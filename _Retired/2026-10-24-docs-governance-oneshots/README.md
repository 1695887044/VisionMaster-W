# 退役：2026-10-24 文档治理 B1-B4 的一次性脚本

## 为什么下线

`tools/oneoff/` 是"一次性脚本"的落点（`AGENTS.md` R166），规则是**用完即删或归档到 `_Retired/`**。
下面这 5 个文件都是 `2026-10-22 ~ 2026-10-24` 文档治理各批次里跑过一次就完成的脚本/数据，
留着只会让下一个人误以为它们还该跑一遍。

| 文件 | 干了什么 | 为什么不再需要 |
|---|---|---|
| `migrate-b3.ps1` + `migrate-b3-plan.json` | B3：把 `docs/` 根级 22 篇参考文档批量 `git mv` 进专题目录，并重写引用 | 已执行完毕，`audit_docs.ps1` 显示 `TOP=0` 证明目标状态达成；重跑会把已经搬走的文件当源路径，直接报错 |
| `migrate-docs-root.ps1` | B3 之前的路径映射草稿版 | 已被 `migrate-b3.ps1` 取代并执行，保留的只是更早一版映射表 |
| `compose-compare.ps1` | 对比两版 `docker-compose` 配置差异 | 一次比对任务的产物，结论已落 `docs/`；脚本本身不含可复用逻辑 |
| `run_gates.ps1` | **2026-10-22 版**的收尾入口（6 个宿主、`*> $out` 重定向、无退出码聚合） | 已被 `tools/run_gates.ps1` 完全取代。旧版的坑写在 `AGENTS.md` R183：`*> $out` 走控制台代码页解码 UTF-8 输出 → 日志成乱码、统计正则永不命中，且**没有聚合退出码**，红步会滚屏消失。**不要拿它当参考实现** |

## 怎么恢复

`_Retired/` 不参与构建、不进 `.sln`，文件本身是完整可读的。需要找回某段逻辑时：

```powershell
# 看旧版收尾入口怎么写的
code _Retired\2026-10-24-docs-governance-oneshots\run_gates.ps1

# 真要重跑 B3（不推荐：目标目录已存在同名文件）
# 先把 migrate-b3-plan.json 里的源路径改回搬迁前的样子
```

## 何时可以删

`migrate-b3*` 与 `migrate-docs-root.ps1` 里记着 B3 的**原始路径映射表**，是"这篇文档原来在哪"的唯一凭据。
`docs/架构文档/交接报告/交接报告-2026-10-24-docs结构治理B3B4与双约束同步.md` 里也写了映射，
两份互相印证；**在确认交接报告内容完整无误、且没有新文档需要回查来源之后**，可以整目录删除。
`run_gates.ps1`（旧版）随时可删 —— R183 已经把教训写进注入层，脚本本身没有保价值。
