# 「图层 / 属性 / 图元工具箱」与「算子工具箱」按场景互斥显示

## 一、先回答你问的 4 个问题

### 1. 「当前处于组态界面设计」的判据

**代码里没有任何 `IsDesignMode` / `ScadaMode` / `EditorMode` 之类的模式状态**——`Scada.Controls\Canvas\ScadaCanvas.cs:212-215` 的注释是明证：作者**刻意不引入**"设计模式"状态机，只用 `IsReadOnly` 一个开关区分设计态/运行态。`SystemAction.UIDesign` 菜单项虽然名字最像，但 `ShellViewModel.OnSystemAction` 里**没有对应 case，点了是空操作**。

按你的裁决，判据取「**组态画面标签在前台**」。但这里有个**必须绕开的陷阱**：

> 不能用 `LayoutHelper.IsPanelActive("Panel_ScadaEditorView")`（它用 `LayoutContent.IsActive`）。
> AvalonDock 里 `IsActive` 表示"**整个 DockingManager 的当前活动内容**"——用户点一下右侧的「属性」或「图层」面板，文档的 `IsActive` 就被抢走 → 判据翻转成"退出组态" → 我们随即把用户刚点的那个面板隐藏掉 → **自毁循环**。
>
> 应当用 **`LayoutDocument.IsSelected`**（"组态画面是中央文档区里被选中的那个标签"）。点右侧停靠面板不会改变文档区的选中标签，所以它是稳定的。
> 依据：现有监听器已经同时监听 `IsActive` 与 `LayoutDocument.IsSelected` 两种属性（`ShellViewModel.cs:277`），说明作者知道文档要用 `IsSelected`。

**实现时需真机确认一次**：点右侧属性/图层面板时，`Panel_ScadaEditorView` 的 `IsSelected` 保持不变。

### 2. 四个面板的布局关系：是「三条列」，不是"四者互斥"

`Shell.xaml` 实际结构（我逐行读过）：

| 容器 | DockWidth | 承载 | 关系 |
|---|---|---|---|
| `LayoutAnchorablePane` | **260** | 属性 `Panel_ScadaPropertyView` | **独占一列** |
| `LayoutAnchorablePane` | **240** | 图层 `Panel_ScadaLayerView` | **独占一列** |
| `LayoutAnchorablePane` | **300** | 工具箱 `Panel_ToolView` + 图元工具箱 `Panel_ScadaToolboxView` | **同一 pane 的两个标签页（互斥）** |

所以不是"四者挤一个 pane 互斥"，而是 **"属性、图层各占一列 + 工具箱/图元工具箱在第三列里互斥换标签"**。

**切换时会不会跳动：会，且宽度会被回收。** 依据（AvalonDock 4.74.1 实际实现，已反编译确认）：
- `LayoutAnchorablePane.GetVisibility()` = 只要有任一子项可见就算可见；
- `LayoutGridControl.UpdateRowColDefinitions()` 给每个子项算列宽：`child.IsVisible ? child.DockWidth : new GridLength(0, Pixel)`；
- 隐藏 anchorable 会把它从原 pane 移到 `LayoutRoot.Hidden`，再 Show 时按 `PreviousContainer` 回到**原 pane 原位置**，`DockWidth` 属性不变。

推论（你已确认接受）：
- 非组态模式隐藏属性+图层 → 两列各收成 **0px**，中央画布**变宽约 500px**；
- 隐藏工具箱或图元工具箱其一 → 同 pane 另一个还在，**300px 列保持不动**（只有两个都隐藏才会收）；
- 再切回组态时列宽恢复 260/240，位置不跑。

### 3. 改动落点与影响面

**能切这四个面板显隐的入口只有两处**（全仓穷举完毕，含断言宿主）：
1. 「视图」菜单 13 个 `commands:ShowPanelCommand` 项（`Shell.xaml:240-356`）→ 只 show/激活，不 hide；
2. 右侧活动栏 3 个 `TogglePanelCommand`（`Shell.xaml:939-961`）→ show/切前台/收起三态。

**没有任何其它 ViewModel、模块或事件去切它们**（`FlowCanvasChecks` / `ScadaChecks` 对 `ShowPanel`/`HidePanel`/`LayoutHelper` **零引用**）。所以影响面是收敛的。

数据链上四个面板互不相干（这是"能安全按场景切"的前提）：

| 面板 | 数据来源 | 隐藏时 |
|---|---|---|
| 图层 | `ScadaEditorViewModel.SelectedPage` / `SelectedElement`（单例） | 视图 `Unloaded` → `Deactivate()` 摘订阅 |
| 属性 | 同一个 `ScadaEditorViewModel`（选中图元→编辑图元；未选→编辑画面属性，**不是空面板**） | 同上 |
| 图元工具箱 | `ElementRegistry.All` + `ScadaTemplateStore.Shared` | `Detach()` 摘模板订阅 |
| 算子工具箱 | `IPluginProvider.ModulePlugins` | 无订阅、构造即静态快照 |

**「算子工具箱」与前三者零共享状态**，只共用右侧布局 pane。

### 4. 边界情况

| 场景 | 期望行为 |
|---|---|
| 首次加载（默认选中「视觉图像」） | 非组态 → 只显示算子工具箱（属性/图层/图元工具箱收起） |
| 切到「组态画面」标签 | 显示属性+图层+图元工具箱，隐藏工具箱 |
| 切到「视觉图像」/「流程画布」 | 反向，回到算子工具箱 |
| 切换中间态 | 先 Show 目标、再 Hide 对方，避免同 pane 出现"两个都不在"的瞬态 |
| 用户手动折叠/展开（活动栏、视图菜单） | **当前模式内有效**；下次模式切换按基线覆盖回去 |
| 方案切换 / 加载布局 / 恢复默认布局 | 走 `LayoutLoaded` → 重新收敛（方案 `.vms` 内嵌布局也会触发） |
| 退出时保存布局 | `Layout.xml` 会记下当时的可见性；**下次启动由模式逻辑立刻纠正**，不冲突 |

新增（放在 `ShowPanel`/`HidePanel` 旁边，复用它们）：

/// <summary>
/// 按"是否处于组态界面设计"收敛右侧面板：
