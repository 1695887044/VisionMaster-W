第一部分 预备知识

第 1 章 边缘与亚像素：卡尺的物理基础

1.1 边缘 = 灰度的"跳变"

拿一条线穿过图像，把线上每个像素的灰度值画成曲线——曲线陡起陡落的地方就是边缘。卡尺的全部工作就是：沿一条线扫描，找"灰度跳变最陡的那个点"。

1.2 亚像素：真实边缘在两个像素之间

相机把连续的世界切成一格一格的像素，真实边缘的位置往往落在两个像素之间（比如 150.6）。卡尺用灰度插值把这个小数位置算出来——这就是亚像素。

精度换算：物理精度 = 亚像素精度 ÷ 像素当量。亚像素能做到 0.2px；视野 100mm ÷ 2448px ≈ 0.04mm/px 时，物理精度约 0.008mm——足够大部分工业测量。

1.3 像素当量：从"像素"到"毫米"

卡尺量出来先是像素值，要变成物理尺寸得乘像素当量（mm/px）。本插件有两条路：手填 PixelSizeMm，或直连「标定」插件的 MmPerPixel 输出（推荐，见 8.1 节）。

1.4 卡尺比喻

真实车间里工人拿游标卡尺卡住零件读数；视觉里的卡尺是一条沿某方向扫描的线，扫过时记下灰度跳变点。本插件更进一步——是阵列式卡尺：一个搜索区内自动均布 N 把（默认 5 把），每把找一个边缘点，最后取平均抗噪。

第 2 章 这个插件是干什么的

2.1 一句话

在图像上"拿尺子量尺寸"，量到亚像素精度，并按规格判定 OK/NG。

2.2 ★ 全插件最关键的几何：L1 与 L2

方向半轴是什么摆错了会怎样
L1（Phi 方向）半长扫描方向——每把卡尺沿此方向扫描，检出的边缘垂直于它扫不到边
L2（垂直 Phi）半宽卡尺阵列排布方向——N 把卡尺沿此方向均布每把扫到不同位置，结果是错的

记忆口诀：矩形要"横跨"被测的边/缝——L1 与边垂直，L2 沿边方向。实测佐证：Phi=0 时把 L1=100/L2=10 放在竖直亮带上能测出宽度；把 L1 缩到 10 或把 Phi 转 90° 都检不到边。

第 3 章 算子卡片集

3.1 ★ 核心中的核心：gen_measure_rectangle2

gen_measure_rectangle2(Row, Column, Phi, Length1, Length2,
                       Width, Height, Interpolation : MeasureHandle)
  • 直觉：把 [中心行, 中心列, 角度, 半长, 半宽] + 图像尺寸 + 插值方式，打包成一个测量句柄——后面所有找边算子都拿着它干活。
  • 易错点 ①：L1 是扫描方向、L2 是排布方向（见 2.2 节，本插件最贵的一条经验）。
  • 易错点 ②：中心在图外会抛 #3022（英文报错说"滤波核尺寸非法"，人话翻译不了）——插件在进 HALCON 前就用中文报"哪个区、中心在哪、图多大"。
  • 源码：CreateMeasureHandle()，CaliperMeasurePlugin.cs:1371（phi 约定经探针实证：画布矩形参数可直接喂给测量算子，无需换算）。

3.2 measure_pos：单边缘找边

measure_pos(Image, MeasureHandle, Sigma, Threshold, Transition, Select :
            RowEdge, ColumnEdge, Amplitude, Distance)
  • 直觉：沿句柄的扫描方向取一条灰度剖面，轻度平滑（Sigma）后，找出所有"跳变幅度超过阈值"的位置——每个位置就是一个亚像素边缘点，Amplitude 是跳变幅度。

  • 参数直觉：Sigma 大=更平滑（抗噪但边缘变糊，不允许 0，会抛 #1302）；Threshold 大=只认明显的边；Transition = 极性（暗→亮/亮→暗/全部）；Select = 多条边时取第一条/最后一条/全部。
  • 源码：MeasurePosWithRetry()，:1387——首跑空结果重试最多 4 次（HALCON 偶发首跑空，同参第二跑正常；真没边时重试后仍空、仍判失败，语义不变）。

3.3 measure_pairs：成对边缘（测宽度的正解）

measure_pairs(Image, MeasureHandle, Sigma, Threshold, Transition, Select :
              Row1, Col1, Amplitude1, Row2, Col2, Amplitude2,
              IntraDistance, InterDistance)
  • 直觉：把扫到的边按"第一条+第二条"配对——IntraDistance（对内间距）就是缝宽，InterDistance 是相邻两对的间距。
  • 与 measure_pos 的分工：pos 找单边（两点距/拟合的点来源）；pairs 找对（宽度/间隙一把卡尺直接出缝宽）。
  • 源码：插件统一取第一条配对的 intra[0]；MeasurePairsWithRetry()，:1401。

3.4 鲁棒拟合：fit_line_contour_xld / fit_circle_contour_xld

  • 直觉：N 把卡尺给出 N 个边缘点，用一条直线/一个圆去"最贴合"它们。毛刺会产生离群点——最小二乘会被一个坏点拽歪整条线，所以默认 Tukey（对残差超限的点大幅降权）。
  • 实测对比：12px 毛刺下 tukey=196.5（真值 196.5）vs regression=191.092。

  • ⚠️ 高频坑（两套值集）：
算子algorithm 合法值
fit_line_contour_xldregression / huber / tukey
fit_circle_contour_xldgeometric / geohuber / geotukey

传错直接 #1301（真实 P1 事故，已按语义映射修复）。

  • 残差判据用中位数不用最大值：按最大值检查，一个毛刺就把 Tukey 已正确拟合的结果判死，鲁棒拟合白做。
  • 源码：TryFitLine() / TryFitCircle()，:1503 / :1610。

3.5 圆直径：径向均布卡尺 + 退化判据

  • 直觉：沿圆周均布 N 把卡尺，每把的扫描方向 = 该点的径向；扫出的点拟合成圆，直径 = 2×半径。
  • 环宽 AnnulusWidth（默认 30px）：每把卡尺沿半径方向扫描的总宽度（±15px 容差）——圆心位置有误差时靠它兜住。
  • 几何陷阱：圆周上角 a 处的点 = (R + r·sin a, C + r·cos a)，径向向量 (sin a, cos a)，而 HALCON 长轴 = (−sinφ, cosφ) → 要 φ = −a（官方文档案例 4）。
  • 退化判据（真实 P1 事故）：3 个共线点配鲁棒算法会不报错地收敛到一个"贴住少数点的小圆"（实测 r≈31px）。插件判据：拟合圆直径 < 点集跨度的 60% → 判退化报错。

  • 源码：CollectCircleEdgePoints()，:1446。

🖼️ HDevelop 截图位：跑官方文档附录 C 案例 4（gen_measure_rectangle2(row, col, -a, ...) 循环 + fit_circle_contour_xld(..., 'geotukey', ...)），贴运行结果。

3.6 三个几何量算子：distance_pp / distance_pl / angle_ll

  • distance_pp：两点距（两点距测量用）。
  • distance_pl：点到线距（垂距；区1 代表点到区2 拟合直线）。
  • angle_ll：两线夹角——返回弧度，代码 ×180/π；且要先把两条线归一化为"交点→远端"射线再求角，否则会把 150° 报成 −30°（补角歧义，已修：实测 30°/90°/150° → 29.91°/90°/150.1°）。
  • 角度不受像素当量影响（量纲无关量，单位是度）——这条区分容易写错。

🖼️ HDevelop 截图位：

angle_ll (100, 100, 200, 100,   100, 100, 200, 200, AngleRad)
AngleDeg := abs(AngleRad) * 180.0 / 3.14159265358979
* AngleDeg 应为 90 —— 直接对 fit 输出求角可能得 -30，先归一化再求

3.7 close_measure：句柄的"还尺子"

  • ⚠️ 算子名是 close_measure，不存在 clear_measure——写错直接编译/运行报错（官方踩坑汇编 #5）。
  • HALCON 的 measure 句柄、XLD、图像都是非托管资源：不释放 = 泄漏。本插件实测教训：gen_*_contour_xld 产出的源对象不释放，500 次约漏 160MB（HALCON .NET 是引用计数语义，包装成 HXLDCont 后要立刻释放源对象）。

第三部分 设计思路

第 4 章 六个设计决策（每条都有真实事故佐证）

卡尺是计量插件，它的设计规矩比别的插件更"死"——因为计量的第一戒律是：宁可报错，不可给一个错误但看起来合理的数。

4.1 阵列取平均：单点噪声带不跑结果

一个搜索区内自动均布 N 把卡尺（默认 5），每把各找一个边缘点取平均。均布数学（源码 DistributeCalipers()，:1316）：

spacing   = 2·L2 / N                     —— 把整段 L2 等分 N 份
halfWidth = max(spacing/2, 0.5)          —— 每把半宽，正好铺满不重叠
第 i 把中心 = 中心 + t·(cosφ, +sinφ)，t = −L2 + spacing·(i+0.5)

4.2 必须全部检出：杜绝"错误但不出错"

只要有一把卡尺找不到边就判失败，不把检到的几把平均出个"看似合理"的数。官方文档原话：把错误结果平均得"看似合理"是计量最危险的失败模式（错误但不出错）。宁可报错让用户调参数。

4.3 静默夹取 + 中文报错：配置坏了不炸流程

所有越界参数进 HALCON 前静默夹取（NormalizedParameters()，:1763）：Sigma 夹到 0.4~100（0 会抛 #1302）、阈值 1~255、卡尺数 1~1000、公差 ±1e9……同时搜索区越界不再抛英文 #3022，而是提前中文报出"哪个搜索区、中心在哪、图多大"。原则：配置坏了最多结果不对，绝不炸流程；报错必须能指导操作。

4.4 零容忍默认：安全侧默认，宁严勿松

StandardValue/UpperTolerance/LowerTolerance 默认全 0——通用平台算子不该假装知道产品规格。用户看到默认即 NG，立刻意识到"该填标准值与公差了"。（与 BlobDetect 的 MaxDefectCount=0 同一风格。）

4.5 配置态守卫：预览只在配置态跑

宿主会给"打开配置界面"和"正式运行"各造一个实例，_isConfigInstance（MarkAsConfigInstance()，:692）把预览限制在配置态。历史 P0：运行实例也跑预览 → ① 产线每帧白烧 CPU（N 把卡尺+拟合+离屏渲染）；② 流程线程与 UI 线程互抢同一扇离屏渲染窗口；③ 每帧 new 一张标注图随即丢弃，内存抖动。

4.6 真实事故：L2 均布向量算错（最隐蔽的几何 bug）

第一批把卡尺排布方向的单位向量写成 (cosφ, −sinφ)——它与真实长轴 (−sinφ, cosφ) 的点积 = −2sinφcosφ ≠ 0，φ≠0 时排布方向根本不垂直于扫描方向。第一批实测全在 Phi=0，暴露不出来；第二批用"非对称位置探针"裁决后改为 (cosφ, +sinφ)。

教训（写进了官方文档）：几何约定不能靠推理，必须写探针实测来裁决，且探针要覆盖 φ≠0 的非对称位置。

4.7 附：标量端口的"镜像 bug"

基类的轮首回收只处理 IDisposable（HImage/HXLD），double/bool 端口的上一轮值会原样留下——本轮失败时下游读到上一轮的 MeasureValue/IsOk。修法：RunAlgorithm 开轮显式重置三个标量端口。极易漏的镜像 bug，写自己的插件时记得这一条。

  │    │    ├─ 两点距: pos×2 → 代表点 → distance_pp
  │    │    ├─ 点线距: 拟合直线 → distance_pl
  │    │    ├─ 圆直径: 径向卡尺 → fit_circle → ×2
  │    │    └─ 角度: 拟合两线 → 归一化 → angle_ll
  │    ├─ 任一卡尺未检出 → 整体失败（必须全部检出）
  │    └─ AnnotationRenderer 出标注图（离屏窗口缓存+加锁）
  └─ finally 统一释放（源对象引用计数）

5.4 端口总表

端口方向类型说明
SrcImage入HImage待测图
MmPerPixel入double像素当量直连口（接标定插件；上游无效 → 明确失败，不静默回退）
MeasureValue出double测量值（已乘当量）
Deviation出double偏差（带符号）
IsOk出bool判定（NG 不算执行失败）
MeasureImage出HImage标注图
FittedGeometry / EdgePoints出HXLD拟合几何 / 边缘点十字

N 把卡尺不生成 N 个端口：合成一个 HXLD 对象集交出去——端口数量恒定，改卡尺数不会弄断下游连线。

第 8 章 应用实例：从需求到验收

8.0 思路框架：先问四个问题

拿到任何测量任务，先别拖卡尺，先回答——答案会自动把你引到正确的算子和配置上：

问题决定什么去哪找依据
① 量什么？测量类型 + 搜索区数量2.3 节五类型
② 多准？公差 ÷ (4~10) = 允许的像素当量 → 镜头/视野/要不要标定9.1 节
③ 动不动？产品位置角度稳不稳 → 要不要先定位（匹配/跟随）9.2 节
④ 判什么？标准值/公差/NG 后干什么 → 判定配置 + 下游接线4.4 节

8.1 实例一：测垫片缝隙宽度（最短路径，先跑通一遍全流程）

任务：缝隙宽 2.00±0.05mm，节拍 200ms/件。

思路链（每一步一个"为什么"）：

  1. 量什么 → 宽度 → measure_pairs 一把卡尺直接出 IntraDistance，连拟合都不用；
  2. 多准 → 公差 ±0.05mm → 当量做到公差的 1/4~1/10 ≈ 0.005~0.012mm/px。查镜头：视野 100mm ÷ 2448px ≈ 0.04mm/px → 不够！ 把视野收窄到 20mm → 2448px → 0.008mm/px ✓（这就是"先算精度预算再选镜头"，反过来先拍完再算当量是新手最贵的返工）；
  3. 动不动 → 工位有定位销、位置稳 → 不做定位，固定搜索区（省掉一整个模板匹配节点——过度设计也是设计错误）；
  4. 判什么 → StandardValue=2.00、公差 ±0.05、当量直连标定插件（9.1 节）；
  5. 摆卡尺 → L1 ⊥ 缝（横跨）、L2 沿缝、N=5；
  6. 打光先想 → 缝底反光会淹没边缘 → 低角度光让"缝=暗线、面=亮背景"，把跳变幅度拉满（阈值才有余量）。

失败模式预演（上线前自己先问一遍）：边缘太弱（Threshold ↓）／极性选反（明确成单向）／毛刺干扰（pairs 不走拟合——靠极性和 Select 过滤）／节拍不够（CaliperCount ↓，但别牺牲"必须全部检出"）。

验收三步（做完才叫"能上线"）：标准件实测对真值 → 重复 20 次看 σ（重复精度）→ 上/下公差边界各测一次看判定翻转。

8.2 实例二：测孔径（圆直径的坑位清单）

思路链：圆环搜索区压在孔边缘上（圆心估计误差必须 ≤ 环宽/2，否则部分卡尺扫不到边）→ 卡尺数 12~16（圆周均布，抗局部脏污）→ 极性按孔的明暗定 → geotukey 拟合 → 直径 = 2R。

专属坑位：

坑现象解法
圆心估计偏出环宽报"某卡尺未检出"环宽加大或圆心摆准——不是关掉"必须全部检出"
点集退化（共线/过扁）拟出一个贴住少数点的小圆插件判据拦截（直径 < 跨度 60%）→ 保证卡尺数、压准圆周
孔口倒角/毛刺一把卡尺扫出两条边Select 选对的那条 + 极性过滤
孔贴近视场边缘报错拖离边缘 / 缩小半径 / 减环宽

验收：标准环规（已知直径）实测 → 换 3 个方位摆圆环看结果一致性。

8.3 实例三 ★：涂胶检测——把"宽度"用成"一条剖面"

任务：胶路三连问——断没断（no bead）？宽窄合格吗（too thin / too thick）？在槽里吗（incorrect position）？

思路推演（本章灵魂，慢慢读）：

  1. 胶路是一条连续曲线——"量一个尺寸"不够用了。换个视角：把它看成一列宽度——沿胶路法线方向、每隔 d mm 摆一把卡尺，得到宽度序列 w₁…w_N；
  2. 断胶 = 序列里某处宽度≈0 或无边缘 → 不但知道"断了"，还知道断在第几毫米（Blob 只能说"有缺陷"，序列能说"断在 37mm 处"）；
  3. 宽窄 = 每个 wᵢ 是否落在 [2.0±0.2]mm → 逐点判定；
  4. 偏移 = 每把卡尺扫出的胶中心点连成线，与槽中心基准线比 → 逐点 distance_pl；
  5. 采样间距 d 由需求倒推：要检出最小 0.8mm 的断胶 → d ≤ 0.4mm → 卡尺数 = 胶长 ÷ d（30mm 胶路要 75 把！）。

推演到这里会撞一堵墙（重要的工程边界，值得停下来体会）：手摆 75 把卡尺不现实，而且两把卡尺之间的断胶根本检不到——这正是仓库另做 Plugin.BeadInspect（胶路检测）的原因：给一条参考路径曲线，让算法沿整条线连续采样，直接输出分段分类（no bead / too thin / too thick / incorrect position）。

直觉模型 → 工程产品：卡尺序列是理解涂胶检测的心智模型，BeadInspect 是它的连续版产品化（HALCON create/apply_bead_inspection_model；极性只能 dark/light 二选一；且要求图像先与参考位姿对齐——对齐是前置职责）。学完思路再读 docs/胶路检测/胶路检测插件方案说明书.md，会发现它的方案论证第一段就是在讲"卡尺范式为什么不够用"——你会全程眼熟。

和 Blob 的分工（涂胶检测的核心区分）：Blob 给"有无/面积/位置"——胶断成两段它能数出 2 个区域，但"细而未断"它看不见；宽度序列逐点量化，能区分"细"和"断"。

8.4 实例四：测量引导（量偏移 → 补偿运动）

任务：来料位置飘 ±2mm，机构要对准产品特征。

思路链：模板匹配 粗定位（Row/Column/Angle）→ 数学计算算偏移 Δ = 实测 − 标准 → 变量赋值 → 轴运动。卡尺的角色：匹配精度不够时的二次精测——对特征边再做一次亚像素测量，把偏移量从"匹配级精度"提到"测量级精度"。接线范式见《工具插件集》附录 A 接线②；位姿从哪来见《模板匹配手册》第 8 章。

8.5 实例篇自检四题

  1. 公差 ±0.02mm，当量该做到多少？（公差的 1/4~1/10 → ≤0.002~0.005mm/px——先算预算再选镜头）
  2. 涂胶检测为什么用"宽度序列"而不用 Blob 面积？（能区分"细"和"断"、能报断点位置）
  3. 最小要检出 0.8mm 的断胶，采样间距怎么定？（≤0.4mm；卡尺数 = 胶长 ÷ 间距）
  4. 圆测量报"某卡尺未检出"，除了调参数还可能是什么？（圆心估计偏出环宽 / 局部脏污——不是关"必须全部检出"）

9.1 像素当量的正解：直连标定

手填 PixelSizeMm 是兜底；正解是把「标定」插件的 MmPerPixel 输出直连本步骤 MmPerPixel 端口——免手抄、随标定自动更新，且标定失败时本步骤明确失败（不拿旧值硬算——又是"错误但不出错"戒律的体现）。衔接：docs/标定插件/。

9.2 先定位再测量

产品位置不固定时：模板匹配.Row/Column/Angle → ROI 跟随 / AlignedImage 归一化图 → 卡尺 SrcImage。两条路线的选型（原始坐标 / 归一化图 / 跟随区域）见《模板匹配插件手册》扩展篇。

9.3 两条找边路线对比

measure 句柄族（本插件）edges_sub_pix 轮廓族

本插件选择✅ 全部走句柄式明确未使用（官方文档 2.5 节列明）
