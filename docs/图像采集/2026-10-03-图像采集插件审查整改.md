## 一、P1：必现的交互与契约问题

### 1. 配置窗口打开后，状态栏被"推送测试已就绪"覆盖

- **现象**：非"网络推送"模式下打开配置窗口，信息栏显示的是绿色的"推送测试已就绪（目标 …）"，而"请选择图像文件""请选择一个相机""相机未连接"等与当前模式相关的提示被盖掉（含 Error 级提示）。
- **根因**：调用顺序是 `Initialize → ValidatePathInputs`（写模式提示）→ `SetConfigContext`（末尾无条件 `SetStatus(推送服务状态)`）。
- **修法**：推送服务状态改为"记在字段里、由模式决定是否进信息栏"——`SetConfigContext` 只写 `PushServiceHint` / `PushServiceLevel` / `_pushServiceMessage(+Level)`；`ValidatePathInputs` 新增 `case Hub`（进入 Hub 模式才把它写进信息栏），其余模式保持各自的路径/相机提示。

### 2. `PublishPreview` 未加"锦上添花"保护

- **现象**：事件总线在无 UI 环境会**就地同步**执行订阅者；推图抛异常会被 `RunAlgorithm` 的大 catch 接住，`ErrorMessage` 被写成异常、日志记"图像采集异常"——而 `Success` 已是 true，运行记录出现"成功带错误信息"的自相矛盾状态。本插件每帧都推图，风险面最大。
- **修法**：新增 `TryPublishPreview(image, viewIndex, context)`，照抄 `PreProcessingPlugin` 的既定约定（失败只 `Logger?.Warn`）。

## 二、P2：健壮性缺口

### 3. 构造期急切 `new HImage()`

- **现象**：字段初始化器 `private HImage _previewImage = new();` 会使 `Activator.CreateInstance` 在无 HALCON 的机器上抛 `DllNotFoundException`；而 `PluginService.InitPlugins` 是**按 DLL 捕获**——整个 `Plugin.ImageAcquisition.dll` 被判"加载失败"，与"无 HALCON 时流程编排照常可用、只降级视觉"的既定口径冲突。
- **修法**：初值改 `null`，`PreviewImage` 标可空；用到时（`LoadPreview`）再建。

### 4. `ToHImage` 的尺寸溢出 / 失败泄漏 / 通道白名单

- **溢出**：`width*height*channels` 用 int 计算，超大尺寸会溢出成负数让"长度不足"校验反面放行，最后以 `AllocHGlobal(负数)` 抛难懂的错。改为 `long` 计算 + `> int.MaxValue` 明确拒绝。
- **泄漏**：`new HImage()` 之后若 `AllocHGlobal` / `GenImageInterleaved` / `GenImage1` 抛异常，对象没有释放。补 catch-dispose（与 `AcquireSingleFile` / `AcquireFromFolder` 同一约定）。
- **通道白名单**：`channels == 2` 原先会静默走 `GenImage1`（把前半段数据当灰度图显示，不报错但图是错的）。改为入口明确拒绝；`1 / 3 / ≥4(BGRA→压 BGR)` 三条合法路径不变。

### 5. 预览侧不认"变量链接"，与 `CheckPath` 语义矛盾

- **现象**：`FolderPath` 被变量链接时，打开配置窗口报橙色"请先选择图像文件夹"（`CheckPath` 明明规定"链接端口直接放行"）；`FileIndex` 被链接时翻页作用在手动值上而运行期用链接值，预览与实跑可能不是同一张图。
- **修法**：`RefreshFolderFiles` 开头判 `FolderPathPort.LinkedSource != null` → 中性提示"文件夹路径来自变量链接，运行期生效；配置态无法预览"并跳过；`LoadPreview` 成功文案在 `FileIndex` 被链接时追加"（文件索引来自变量链接，运行期以链接值为准）"。

### 6. `DisplayViewIndex` 无边界防护

- **现象**：落盘的 `[StepConfig]` int，手改方案可给出 >9；消费端按"ViewIndex == 窗口号(1~9)"等值筛选，越界值不报错、也不显示，最难归因。
- **修法**：setter `Math.Clamp(value, 0, 9)`（写入即归一，方案里不会再留下越界值）。

### 7. `PushServiceHint` 恒挂警告色

- **现象**：服务正常在监听时提示也是橙色（像出了问题）。
- **修法**：新增 `PushServiceLevel`，XAML 用 `DataTrigger` 按级别取 `PluginOkBrush / PluginWarningBrush / PluginErrorBrush`（与信息栏同一套令牌）。

| 项 | 命令 | 结果 |
| --- | --- | --- |
| 插件工程 | `dotnet build Plugins\Plugin.ImageAcquisition\Plugin.ImageAcquisition.csproj --no-dependencies -t:Rebuild` | **0 错误 0 警告**，DLL 已投递 Modules |

**19 项既有失败与本改动无关**，逐个核对后的根因：

- `WireSequenceCheck` 10+3 项：`线序检测.vms` 的图像采集步骤是**相机模式**（VIRTUAL-001），而该检查自建 `ExecutionContext` 时未注入相机仓库（默认 `NullCameraProvider`）→ 首步失败，后续与"预览帧 0 帧"都是连锁结果；另有 `onnxruntime_providers_shared.dll` 元数据加载失败等环境因素。
- `ExecutionChecks` 1 项（`RegisterCamera` 模块表）、`MotionZMotionChecks` 3 项、`YoloChecks` 1 项：均属运动/YOLO/插件注册表，与本次改动无交集。

## 六、已知边界（本次明确不做）

1. **相机模式 `CurrentIndex/TotalFiles` 的重载语义保留**：改成 0 会静默打断已有接线；精确值走新口 `FrameId/ReceivedCount`。
2. **`_cachedFiles` 目录缓存**仍不存在（09-24 文档已记录：每轮重新枚举，几毫秒成本换"拍图落盘"场景正确）。
3. **`LoadPreview` 的 `File.Exists` 仍在 UI 线程**（网络盘可能短暂阻塞，读图本体已异步）。
4. **翻页按钮仍不做 `CanExecute` 门控**（由 `RefreshFolderFiles` 内部 Clamp 兜住）。
5. **线序检测的两个 `.vms` 检查**需在真机环境（虚拟相机客户端在跑）才有意义，属既有环境性欠债，不在本次范围。
