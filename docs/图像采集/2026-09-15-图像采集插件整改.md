# 图像采集插件整改（2026-09-15）

## 一、需求与决策

用户请求："检查下 图像采集插件 有没有什么需要优化补充的，先提方案"。经通读插件全链（主体 `ImageAcquisitionPlugin.cs`、配置视图 `ImageAcquisitionView.xaml`、枚举 `Enum.cs`、基类 `VisionPluginBase.cs`、端口 `InputPort/OutputPort`、预览扩展 `PluginPreviewExtensions`、Halcon 显示基类 `HalconBase`）后，产出按严重度分级的问题方案。用户拍板执行范围：**删掉相机模式 + P0/P1/P2 全做**。

关键决策与安全前提核实：
- **P0 内存修复前置核实**：在 `PreviewImage` setter 里"换图即弃旧"是否安全，取决于配置预览控件 `ImageReadOnly`（继承 `HalconBase`）对传入 `HImage` 是"持引用"还是"复制"。通读 `HalconBase.cs` 确认：`HImage` 为依赖属性（`BindsTwoWayByDefault, HImageChangedCallBack`），回调里 `DisplayImageInfo.Image = newImg` **仅存引用不复制**，`RenderAll` 用 `hWindow.DispObj(HImage)` 绘制当前 DP 值。WPF UI 线程绑定是同步的——`SetProperty` 触发 `OnPropertyChanged`→DP 更新到新值→重绘新图，回到 setter 时旧图已不被 UI 引用，**释放旧图安全**。
- **相机模式**：`AcquireFromCamera` 只生成 640×480 渐变占位图却返回 `Success=true`（误导用户），用户决定整体删除，待真实接 SDK 时重做。
- **OutputImage 所有权**：`OutputPort<T>` 换值不 Dispose 旧值（仅基类 `Dispose` 收尾释放）。跨运行是否弃旧图涉及"所有权是否已移交下游"这一全局架构问题，**不在本次插件整改范围**，保留现状。

## 二、问题清单与修改

### P0-1 预览图非托管内存泄漏
`PreviewImage` 原为 `set => SetProperty(...)`，换图时旧 `HImage` 从不 `Dispose`；每次浏览/翻图/关面板都漏一张非托管图（Halcon 软件最常见崩溃源）。
- 改法：setter 先取旧引用 → `ReferenceEquals` 短路 → `SetProperty` 成功后 `old?.Dispose()`。
- `Dispose()` 去掉重复的 `PreviewImage?.Dispose()`，只留 `PreviewImage = null` 交给 setter 统一释放，避免双重 `Dispose`。
- `RefreshFolderFiles/LoadPreview` 里的 `PreviewImage = null` 现在也能正确弃旧。

### P0-2 DisplayViewIndex 三处语义矛盾
注释说"1~9，0=不显示"，ComboBox 却绑 `SelectedIndex`（首项=0），`RunAlgorithm` 又 `PublishPreview(image, DisplayViewIndex+1)`——导致"0=不显示"选不到、默认反而显示到窗口1，且资源里 `ViewIndexes`(0~9) 定义了没被用（死资源）。
- 统一为"真实窗口号 1~9，0=不显示"，默认 `_displayViewIndex = 1`（保持开箱显示到窗口1）。
- ComboBox 改用 `ItemsSource={StaticResource ViewIndexes}` + `SelectedItem={Binding DisplayViewIndex}` + `ItemTemplate`（`StringFormat=图像窗口{0}`，`DataTrigger Value="0"`→"不显示"），激活死资源。
- `RunAlgorithm` 去掉 `+1`，加 `if (DisplayViewIndex > 0)` 守卫后再 `PublishPreview(result.Image, DisplayViewIndex)`。

### P1 删除相机模式
- `Enum.cs`：删 `AcquisitionMode.Camera`。
- 主体：删 `CameraIndexPort`、`AcquireFromCamera`、`ExecuteCore` 的 `cameraIndex` 参数与 `Camera` 分支、`RunAlgorithm` 调用中的 `CameraIndexPort` 实参、`using System.Runtime.InteropServices`（仅占位图用到 Marshal/IntPtr）。
- 视图：删"相机采集" RadioButton。

### P1 补文件夹配置界面 + 模式按 Mode 显隐
- 复用现成转换器 `UI.Converters.EnumToVisibilityConverter`（`{ui:EnumToVisibilityConverter}`）：
  - "指定图像" GroupBox → 仅 `Mode=SingleFile` 显示；
  - "文件目录" GroupBox（原整块注释掉的死代码）→ 重建为可用面板，仅 `Mode=Folder` 显示。
- 文件夹面板：`FolderPathPort` 的 `LinkableValueEditor`（双击浏览，`BrowseFolderCommand`）+ `FileIndexPort` 的 `LinkableValueEditor`（可手动/变量链接）+"刷新预览"按钮（`RefreshPreviewCommand`）+ "当前文件 / 共 N 张"提示。

### P2 杂项清理
- 扩展名提为常量 `ImageExtensions = ".bmp,.jpg,.jpeg,.png,.tif,.tiff"`，执行核心/文件夹列表/浏览 filter 三处统一由其派生；原 `OpenFileDialog` filter 含 `.gif` 与过滤集不一致，已对齐去掉。
- 死方法 `BrowseFolder`（无人调用）→ 接入 `BrowseFolderCommand`。
- "图像参数"页 10 余个未绑定任何命令的占位 CheckBox/Button → 全部移除，仅保留有实际作用的"显示窗体"。
- 恢复被注释的预览信息栏（左=来源路径 `PreviewImagePath`、右=操作状态 `StatusMessage`），三模式统一反馈；文件夹面板内不再重复显示 `StatusMessage`。

## 三、修改文件清单

- `Plugins/Plugin.ImageAcquisition/Enum.cs`：删 `Camera` 枚举成员。
- `Plugins/Plugin.ImageAcquisition/ImageAcquisitionPlugin.cs`：P0-1 预览弃旧、P0-2 语义与发布守卫、删相机链、新增 `BrowseFolderCommand/RefreshPreviewCommand`、`ImageExtensions` 常量、filter 对齐、`Dispose` 收敛、清理无用 using。
- `Plugins/Plugin.ImageAcquisition/ImageAcquisitionView.xaml`：删相机项、"指定图像/文件目录"按 Mode 显隐、重建文件夹面板、修正显示窗体 ComboBox、移除占位控件、恢复信息栏。

## 四、验证结果

- `dotnet build Plugin.ImageAcquisition.csproj -c Debug -p:SolutionDir=...`：**0 错误**（585 警告均为仓库既有可空性告警，非本次引入）。
- 全仓 grep 确认无外部工程引用被删的 `AcquisitionMode.Camera / CameraIndexPort`；无 `Camera / Marshal / GenImage1 / SelectedIndex` 残留。

## 五、已知边界

1. **软件需重启加载新 DLL**：插件为启动期扫描加载，改后需重启主程序方可见新界面。
2. **历史方案的 DisplayViewIndex 语义迁移**：旧工程把该值当"SelectedIndex(0~8)"持久化，新语义按"真实窗口号(0~9)"解释——旧值 0 会从"显示到窗口1"变成"不显示"。属 bug 修正的必然结果，需要时手动在界面重选窗口号即可。
3. **ComboBox "0=不显示"标签**：依赖 WPF `DataTrigger Value="0"` 对 int 的类型转换显示"不显示"文案；即便个别环境下不转，功能（0 不发布）仍正确，仅文案退化为"图像窗口0"。
4. **OutputImage 跨运行弃旧未处理**：涉及跨节点图像所有权移交的全局策略，未在本次范围内改动。
5. **文件夹预览刷新为手动**：切换"文件索引"后需点"刷新预览"才重载预览图（未做值变更自动刷新，规避 clamp 回写端口的重入风险）。
