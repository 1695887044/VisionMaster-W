# 2026-09-27 变量管理：数组编辑不可用 + 明细表残行 + 样式收编

> 📦 **本文件已归集至 `docs/归档/`（历史留档，不再维护）。**

起因（用户的三个诉求）：
1. "**这个数组的变量编辑方式不能用**"；
2. "UI 需要美化"；
3. "公用样式的抽到 UI 公共层"。

第 1 条查下来是两个独立的缺陷叠在一起，都是"界面上看着正常、实际不能用"那类。

---

## 1. 缺陷一：数组编辑弹窗里根本没有可编辑的控件

原来的入口：数组变量的"编辑集合..." → `EasyDialog.ShowPropertyGridSync` → PropertyGrid 渲染 `VariableArrayEditor`。

```csharp
public class VariableArrayEditor
{
    [DisplayName("元素数")]
    public int Count => Elements?.Count ?? 0;                      // 只读 int
    public ObservableCollection<ArrayItemWrapper> Elements { get; set; } = new();   // 集合
}
```

而 UI 库的 PropertyGrid 是**反射式生成器**体系，它的生成器只有五个：
`BoolStateGenerator` / `EnumGenerator` / `NestedPropertyGridGenerator` / `StructValueGenerator` / `TypeGenerator`。

- `StructValueGenerator.CanProcess` 只认 `string` / 基础类型 / `decimal` → **集合不匹配**；
- `TypeGenerator` 要求属性上挂 `[PropertyItem]` → 没挂。

结论：`Elements` 这个集合**从来不会被渲染**，`Count` 又是只读的 —— 于是那个弹窗里只有一行只读的"元素数"。
更糟的是新建数组时 `Array.CreateInstance(elementType, 0)` 得到**长度 0**，
所以是"打开弹窗 → 什么都没有 → 也没地方加元素"的死路。

### 修法：UI 库新增可复用的 `DialogArrayEditor`

`UI/Controls/CustomControl/DialogArrayEditor.xaml(.cs)`：显式的列表编辑器 ——
每个元素一行（可编辑输入框 + 上移/下移/删除），底部"添加元素"，空列表时给明确引导文案。
`EasyDialog` 本来就有"自定义内容弹窗"重载（`ShowSync(title, FrameworkElement)`），所以不需要新增弹窗注册。

设计上只处理**字符串**：控件在 UI 库，不认识任何业务类型（元素可能是 int/double/string/bool），
"字符串 → 目标类型"的解析留在 VM（`TryBuildArray`），控件就不会因为多一种元素类型而改动。

## 2. 缺陷二：表格里改不了单个元素

数组元素行（`[0]`/`[1]`…）的"初始值"原来是个**只读 TextBlock** —— 想改一个数字，也得打开上面那个用不了的弹窗。

修法两条腿：

1. **元素行就地可编辑**：`VariableNode` 新增 `ElementIndex`（我在父数组里是第几项）与
   `ChildDefaultValueText`（类型安全代理，写回父数组的第 `ElementIndex` 项）。
   写回时 **DefaultValue（初始值）与 Value（当前值）一起改** —— 与"编辑集合"弹窗
   （整体 `gv.Value = newArray.Clone()`）保持同一语义，免得出现"表格里改了、当前值还是旧的"。
2. 元素行创建处（`CreateChildNodes`）补上 `OriginalModel = parentNode.OriginalModel` 与 `ElementIndex = i`
   —— 这是子节点与父数组唯一的对应关系来源，**不能靠 `Name`（"[3]"）反解**：那是把展示格式当数据用。

## 3. 缺陷三：切来源后表里出现"没有名字的 [0]/[1] 残行"

`UpdateFilteredList` 原来是这样：

```csharp
if (node.IsRootNode)          // ← 只对根节点判来源/搜索
{
    if (!matchSource) continue;
}
// ... 子节点不判任何条件，直接加进列表
FilteredDisplayNodes.Add(node);
```

注释写着"子节点跟随父级"，代码却没实现 —— 子节点只是"不判来源"，于是**无条件加入**。
后果：切到"网络变量"（或输入搜索词）时，本地数组变量的 `[0]`/`[1]` 会以
"没有变量名、没有来源、类型还被列宽截断"的残行留在表里（用户截图里那堆 `[0]~[3]` 就是它），
既看不懂也没有任何入口能操作。

修法：把筛选抽成纯函数 `FilterDisplayNodes(displayNodes, sourceKey, query)`，
用一个游标量表达"跟随父级"（`DisplayNodes` 是"根 + 它的子节点紧随其后"的扁平表，见基类 `UpdateFlatList`）。

**为什么抽成纯函数**：VM 的构造函数要通信管理器、桥接器、弹窗服务，在冒烟里凑齐这些依赖不划算；
而这段逻辑恰恰是最容易出错、最该守住的一段。抽出来之后断言可以直接驱动它。

## 4. 样式收编到 UI 公共层

### 新增 `DialogCellInput`（`UI/Controls/Themes/DialogStyles.xaml`）

视觉管理表的"初始值"列原来是视图里自己拼的：

```xml
<Border Height="26" BorderBrush="#DCDFE6" ...>
    <TextBox Style="{x:Null}" Background="Transparent" BorderThickness="0" ... />
</Border>
```

—— 聚焦高亮、悬停、错误红框都要在视图里再写一遍，而且**每写一处都会漏掉一两项**（原来就没有聚焦态）。

改成 UI 库一支 TextBox 样式：常驻白底 + 1px 描边 + 圆角 6 + 悬停/聚焦/校验错误三态 +
校验失败悬停看原因。视图里现在只写一行 `Style="{StaticResource DialogCellInput}"`。

与既有的 `DialogGridInput` 的分工写进了注释：
`DialogGridInput` 是"平时透明、划过才浮出描边"（连接管理的组名/周期列，整表都是输入框但不该喧宾夺主）；
`DialogCellInput` 是"常驻白底描边"（初始值列，这一列本来就是个输入区）。区别是**用户要不要一眼看出这里能输入**。

### 顺带

- "编辑集合..."与"强制覆盖集合..."用的 `LinkButtonStyle` 目前定义在 `App.xaml`（应用级）。
  它算"全局公共"、不是"每个视图各抄一份"，所以本次没动；若将来要统一到 UI 库，可迁成 `DialogLinkButton`。
- `ExpandToggleButtonTemplate` 同样在 `App.xaml`，同上处理。

### 新增断言（`FlowCanvasChecks/GlobalVariableChecks.cs`，18 条全绿）

```
---- [G] 变量管理：明细筛选（来源 / 搜索 / 数组子行跟随父级） ----
  [√] 选中「本地变量」：只剩本地根节点 + 它的数组子行            → Barcode,[0],[1]
  [√] ★选中「网络变量」：数组子行不许漏出来（旧实现在这里漏 2 行无主 [0]/[1]） → Test
  [√] 搜索命中的是网络变量时，本地根与它的子行一起消失            → （空）
  [√] 搜索命中数组根（按描述）时，子行跟着一起留下              → Barcode,[0],[1]
  [√] 搜索按地址命中网络变量                                   → Test
  [√] 选中不存在的连接：什么都不显示（也不许漏子行）             → （空）

---- [G] 数组元素就地编辑：写回父数组 / 类型校验 / 留空用默认值 ----
  [√] 改元素 → 初始值与当前值同步写下标                        → DefaultValue=[A,C] Value=[A,C]
  [√] 节点自身回显同步更新                                     → ChildDefaultValue=C
  [√] 非法值抛异常、且模型保持原值（不污染）                    → 抛异常=True 模型[0]=1
  [√] int 元素留空 → 写入 0
  [√] string 元素留空 → 写入 null（引用类型没有可实例化的默认值）
  [√] ElementIndex 未设（-1）时不写任何东西（防止误改父数组）

---- [G] 数组编辑：文本转数组（留空用默认值 / 非法值明确失败） ----
  [√] int[]：正常值写入、空串按 0 处理                          → 1,2,0
  [√] double[]：按元素类型转换（不是按字符串拼）                 → 1.5,2
  [√] int[]：非法元素整体失败并给出原因（不半途写入）
  [√] 空列表 → 长度 0 的数组（新建数组的初始形态，必须能建成）
  [√] string[]：空串保留为 null 元素（长度必须与界面一致）        → a,<null>,c
  [√] 误传数组类型时明确失败                                    → 元素类型不能是数组（收到 Int32[]，应传元素类型本身）
```

最后那条是**写断言时真踩出来的**：我把"数组类型"当"元素类型"传进 `TryBuildArray`，
`Array.CreateInstance(typeof(int[]), n)` 造出了 `int[][]`，然后 `SetValue` 抛
`InvalidCastException: Invalid cast from 'System.String' to 'System.Int32[]'` ——
这条报错完全指不到"参数传错了"上。已在 `TryBuildArray` 里加显式防御。

## 6. 已知边界

1. **视图未在真实会话里打开过**。探针能证明"BAML 与所有 StaticResource 都能解析、模板能展开、
   增删改与下标重编都正确"，但**数据绑定告警**（属性名写错之类）只在运行时会打到输出窗口，
   建议打开一次变量管理弹窗看一眼输出窗口。
2. **`DialogArrayEditor` 未做超长数组的虚拟化**：它是 `ItemsControl` + `ScrollViewer`，
   几百个元素会一次全部实例化。数组变量在实践中通常是几个到几十个元素，暂未处理；
   若将来要支持上千元素，需要换 `VirtualizingStackPanel`。
3. **元素就地编辑直接改模型数组的两份值**（DefaultValue 与 Value）。
   这是与"编辑集合"弹窗的既有语义对齐的选择；如果将来引入"当前值不允许手改"的规则，
   这里要一起改。
4. **"编辑集合..."按钮仍叫这个名字**（截图里另一处写的是"强制覆盖集合..."），
   文案不统一但指向同一个命令；本次未改以免动到既有截图/文档。
