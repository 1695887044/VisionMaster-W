## 2. UI 库新增的公共件

形状与颜色都收进 `DialogStyles.xaml` / `Colors.xaml`，两个视图**不再定义任何样式、不再出现颜色字面量**。

| 键 | 用途 | 为什么值得进公共层 |
| --- | --- | --- |
| `DialogTagButton` | 软色块小按钮（高 30、圆角 6、强调色浅底） | 条件编辑器里成片排列的"引脚变量 / 逻辑比较 / 数学运算 / 字符串函数"快捷插入，以及"重新绑定 / 选择数据源"；这类"点一下就插进去"的交互在别处也会出现 |
| `DialogChipButton` | 表格行内胶囊动作按钮（高 24） | 行内动作要"看得见但不抢主操作视线"；底色由使用处按语义成对给（信息/危险/中性） |
| `DialogHintText` | 灰色说明文字 | 收编自六个弹窗里逐字相同的写法（11~11.5px + 弱化色 + 换行） |
| `DialogInfoPanel` | 浅底信息块 | 底部说明、口径声明这类成段辅文（Web 里的 alert / callout） |
| `DialogDangerSubtleBrush` | 危险类浅底 `#FEF2F2` | 软色块危险按钮、溢出告警块 |
| `DialogWarningSubtleBrush` | 警示类浅底 `#FFF4E5` | "注意事项"块（如网络相机参数不生效） |

`DialogChipButton` / `DialogTagButton` / `DialogHintText` / `DialogInfoPanel` 都**不设 Margin** ——
间距是布局的事：硬塞 Margin 会让"紧凑排布"和"宽松排布"必须二选一（`DialogHintText` 的注释里写了这条理由）。

## 3. 重写要点：先把"不能碰的东西"列出来

整体重写最容易出的错是**悄悄丢绑定**。所以动手前先把必须原样保留的列清楚（并写进文件头注释）：

- 所有命令与属性名（`AddVariable` / `BindVariable` / `RemoveVariable` / `LinkLoopCount` /
  `UnlinkLoopCount` / `Cancel` / `Save`、`IsForMode`、`Branches`、`SelectedBranch`、
  `SelectedBranchNeedsExpression`、`Variables`、`LoopCountText`、`LoopCountSourceText`、`HasLoopCountLink`、
  `Flows`、`SelectedFlow`、`SearchText`、`EncryptFlowCommand` / `DecryptFlowCommand` / `ToggleEnabledCommand`）；
- **AvalonEdit 的 `x:Name="txtExpression"` 与 `TextChanged="TxtExpression_TextChanged"`** ——
  code-behind 靠它读写表达式，改名等于把输入通道切断；
- 快捷插入按钮的 `Click="QuickInsert_Click"` 与**每个 `Tag` 的精确内容** ——
  Tag 就是要插进表达式的片段（`.Contains()`、`string.IsNullOrEmpty()`、`Math.Abs()`），
  写错一个字符等于插入一段错代码。

### 交互上的两个决定

- **标题栏 × 绑 `CancelCommand` 而不是新加 `CloseCommand`**：本弹窗是"草稿 → 校验 → 写回"事务，
  关闭即丢弃草稿，语义上就是取消；另加一个 CloseCommand 反而让两个入口语义分不清
  （流程管理那边本来就有 CloseCommand，所以它绑 CloseCommand）。
- **`SelectedIndex="-1"` 保留**：进弹窗时不要自动选中第一个分支，否则用户还没操作就被带进某个分支的表达式。

## 5. 断言两次"写偏"的记录

**写严了一次**：`【窗框】每个弹窗都有关闭入口` 第一版要求 XAML 里必须出现 `CloseCommand`，
结果 7 个弹窗报红 —— 它们其实**都有底部「取消 / 确定」按钮**，那也是合法关闭入口。
断言要守的是"关不关得掉"，不是"必须有 × 按钮"，放宽成三者之一。

**误报两次**：`不再有硬编码颜色` 扫源文件时会扫到**注释里写的色值** ——
而注释里提旧色值恰恰是"这处为什么改"的唯一线索（不该禁）。
本轮四个视图全部因此误报。已改成**先剥掉 XML 注释再扫**。
（上一轮 `VariableBindingView` 也栽在同一个地方，当时是把注释里的色值删掉了事 ——
这次改成剥注释，才不会再犯第三次。）
