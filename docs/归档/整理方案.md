# 归档区整理方案

> 本文件是 **工作性方案**（不是归档内容），用于规划 `docs/归档/` 的进一步归类。
> 现状：按"方案1"已把根目录 10 份不再维护的文档/目录搬入 `docs/归档/` 并加 📦 横幅。但归档区目前是**扁平**的，混了三类性质完全不同的内容，建议进一步归类。

> **执行状态：已按"标准版"于 2026-10-04 执行。** `EasyDialog` / `UI组件库` 已提升为 `docs/基础设施/`（去横幅）；5 份整改记录归入 `docs/基础设施/整改记录/`；SCADA 归入 `归档/SCADA/`。坐标变换 / 标定的方案说明书由 owner 迁出归档、现已在 `docs/坐标变换插件/`、`docs/标定插件/`（docs/ 根）。

## 1. 现状盘点（按性质分）

| 性质 | 文件 | 是否被现行文档引用 |
|---|---|---|
| **共享基础设施·使用文档** | `EasyDialog弹窗引擎使用文档.md`、`UI组件库-Fluent设计系统与迁移.md` | 仅被 `code-changes/`（开发日志）引用，现行插件主文档/顶层文档均未引用 |
| **共享基础设施·整改记录** | 5 份 `2026-09-27-*`：弹窗自绘标题栏统一、变量绑定弹窗尺寸与样式收编、变量绑定按类型过滤与判据归一、变量管理数组编辑修复与样式收编、条件编辑器与流程管理整体收编 | 仅 `code-changes/` |

| **未实现插件的方案说明书** | `坐标变换插件/`、`标定插件/` | 仅 `运动控制/运动控制插件.md`、`运动控制/README.md`（已改链到归档） |

### 关键问题
- `EasyDialog弹窗引擎使用文档.md`、`UI组件库-Fluent设计系统与迁移.md` 描述的是**全平台复用的弹窗引擎 / UI 组件库**——所有插件都依赖它们。它们目前是**唯一**的使用文档，却因为"没被插件主文档引用"而被当成历史归档，属于**错归档**。
- 5 份整改记录是基础设施的**演进史**，与"现行有效文档"性质不同，但也不该和 SCADA / 未实现插件混在一起。
- SCADA 与未实现插件是真正的"留底待定"，适合留在归档。

---

## 2. 整理原则

1. **功能性质优先**：现行复用基础设施 vs 纯历史 vs 未实现，分开存放。
2. **可晋升**：若某归档件其实是"现行有效参考"，应从归档**提升为顶层专题目录**并去掉 📦 横幅。
3. **不破坏链接**：任何移动都要同步改链（含 `code-changes/` 内、各插件 README 内）。
4. **最小扰动**：先确认方案，再执行。

│       ├── 弹窗自绘标题栏统一.md
│       ├── 变量绑定弹窗尺寸与样式收编.md
│       ├── 变量绑定按类型过滤与判据归一.md
