# 第 0 章 这是什么

**OCR 文本识别 = 把图上的印刷字符"读"成文字（料号、日期码、批次号、铭牌）。**

> 生活比喻：你看一张标签上的"11240B"，眼睛先要把这些字**一个个分开**（不然就是一坨黑块），再逐个认出来。OCR 也是这两步——先**切字**，后**认字**。

它在流程里的位置（归在 **「图像处理」** 分组）：

```
[图像采集] → [创建 ROI] / [模板匹配] → [图像预处理] → [OCR 文本识别] → [C#脚本] / [CSV记录] / [结果上报]
                                                    ↓
                    Text(文本) / Count(字符数) / Confidence(置信度) / Detail(逐字符明细)
```

**一句话**：模板匹配解决"目标在哪"，码读取解决"码里写的什么"，而 **OCR 解决"印的字是什么"**——它认的是人类可读的字符（0-9 / A-Z）。

## 0.1 与码读取的分工

| | 码读取 `Plugin.CodeReader` | OCR `Plugin.Ocr` |
|---|---|---|
| 认什么 | 条码 / 二维码的**编码** | 印刷出来的**字符** |
| 算法 | HALCON 现成引擎 | 自己切字 + MLP 分类器 |
| 模型 | 运行期现场构造 | **必须带 `.omc` 模型文件** |
| 失败语义 | 没读到码 = 正常工况 | 认不准 = **必须报出来** |

## 0.2 最重要的认知：分割是成败的 90%

OCR 与传统视觉算子有个本质差别——**分割（切字）是成败的 90%，识别只是一行调用**。

- 字切对了 → 识别基本没问题（分类器很成熟）。
- 字切错了（两个字粘一起、一个字断成三截）→ 再好的分类器也认不出。

所以本插件把"分割策略"当一等公民：参数分层、必须有「试算」。

# 第 1 章 设计思想

## 1.1 核心原理：两层架构

```
┌─ 分割层 CharSegmenter ────────────────────────────────┐
│  ROI → 转灰度 → 二值化 → 形态学 → 连通域 → 三档筛选 → 排序  │
└──────────────────────┬──────────────────────────────┘
                       ↓ 排好序的字符区域
┌─ 识别层 OcrEngine ────────────────────────────────────┐
│  模型路径解析 → 句柄缓存 → do_ocr_multi_class_mlp        │
└──────────────────────┬──────────────────────────────┘
                       ↓ 文本 + 逐字符置信度
┌─ 插件壳 OcrPlugin ────────────────────────────────────┐
│  端口 / 配置 / 运行 / 试算 / 释放                        │
└──────────────────────────────────────────────────────┘
```

> 两层严格分工：**分割层负责"把字切开"，识别层负责"认清每个字"**。识别层不做任何阈值/形态学——混进来会让"改哪个参数"变得说不清。

## 1.2 三条设计原则

**原则①：不做 OK/NG 判定**

只输出"认到了什么"（文本 + 逐字符置信度），合格与否交给下游的比较节点。

**原则②：认不准必须看得出来**

> OCR 最危险的失败不是"认错"，而是"给出一串看似正常的错字符却没有任何提示"。

所以本插件有两条 **Warn**（诚实机制）：
- 有字符被拒识 → Warn
- 均值置信度 < 0.9 → Warn（提示"请勿直接用于放行"）

**原则③：试算与运行共用同一条路径**

若试算与运行走两套代码，界面上看着对、跑起来不对，那种问题最难查。

## 1.3 为什么不用 HALCON 的 `SegmentCharacters`

实施时改走**手搓路线**（阈值→形态学→连通域→筛选→排序），理由是：

`SegmentCharacters` 的控制参数（`ThresholdOffset` / `CharWidth` / `Inhibition`）是它自己的内部概念，**现场调参时看不懂**；而手搓路线的参数是"阈值、字符尺寸、形态学"，与脚本原型同构、现场已有使用经验。

## 1.4 模型文件怎么带：两条投递路径（与码读取的关键差别）

| 路径 | 做什么 | 为什么 |
|---|---|---|
| ① `Update + CopyToOutputDirectory` | 让本工程与"编译期引用本工程"的消费者（断言工程）输出目录里都有模型 | 断言才能真的按"内置模型开箱可用"跑一遍 |
| ② `PostBuild` 投到 `$(HostBinDir)` | 投到生产宿主 `VisionMaster` 的目录 | **宿主按 DLL 反射加载插件，拿不到 ① 的传递拷贝**。缺这条，现场运行期找不到模型 |

> ⚠️ 用 `Update` 而不是 `Include`：SDK 风格工程已把非 .cs 文件默认纳为 `None`，再 `Include` 一次会撞成重复项（`NETSDK1022`）。
>
> **对比 `Plugin.CodeReader`**：一维/二维码的模型是 HALCON **运行期按码制名现场构造**的，不依赖外部模型文件——所以码读取既不需要 Assets 目录也不需要 PostBuild 投递，**少一条会出错的链路**。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | OCR 文本识别 |
| `GroupName` | 图像处理 |
| `Description` | 在识别区里切分字符并用内置分类器识别（0-9 / A-Z，带拒识） |
| `ShortName` | 字体图标（FontAwesome `f031`） |

## 2.2 端口完整清单（全部固定端口，无动态端口）

| 端口 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `Image` | 入 | HImage | 待识别图像（`IsRequired = false`） |
| `Text` | 出 | string | 识别出的文本 |
| `Count` | 出 | int | 字符数（含拒识字） |
| `Confidence` | 出 | double | 平均置信度 0~1，**低置信 = 本次结果不可信** |
| `Detail` | 出 | string | 逐字符明细「序号+字符+置信度」，拒识显示 `?` |

另有基类隐式端口 `Success`、`ErrorMessage`。

> ⚠️ **不输出字符框**（未做结果投射）。但分割结果里已带 `Chars`/`Rows`/`Cols`，将来投射机制立起来可直接用。

## 2.3 配置项（常用 6 + 高级 9）

### 常用参数（界面默认展开）

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `RoiParams` | `double[]` | 空 | 识别区形状，HALCON Rectangle 约定 `[中心行, 中心列, 角度(弧度), 半长, 半宽]` |
| `TextIsDark` | bool | **true** | 极性：`true` = 暗字亮底（工业最常见打码），`false` = 亮字暗底 |
| `MinCharHeight` | int | `8` | 字符最小高度(px)，收紧可挡背景纹理与脏点 |
| `MaxCharHeight` | int | `300` | 字符最大高度(px) |
| `MinCharWidth` | int | `4` | 字符最小宽度(px) |
| `MaxCharWidth` | int | `300` | 字符最大宽度(px) |

### 高级参数（界面 Expander 折叠）

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `UseFixedThreshold` | bool | `false` | `true` = 固定阈值，`false` = 自动阈值（Otsu `max_separability`） |
| `FixedThreshold` | int | `128` | 固定阈值：暗字取灰度 `<=T`，亮字取 `>=T` |
| `MinArea` | int | `20` | 字符最小面积(px²) |
| `MaxArea` | int | `5000` | 字符最大面积(px²) |
| `ClosingRadius` | double | `0` | **闭运算半径，点阵字必备**（散点连成笔画且不变胖）。点阵喷印从 1.5 起试 |
| `ErosionRadius` | double | `0` | 腐蚀半径：印刷字粘连时先腐蚀断开 |
| `DilationRadius` | double | `0` | 膨胀半径：笔画过细时加粗（会外扩字形） |
| `ModelPath` | string | 空 | 外部模型路径。留空 = 内置 0-9/A-Z；填了用指定模型（中文/自训练） |
| `ColumnFirst` | bool | `false` | `true` = 按列优先排序（竖排），`false` = 按行优先（横排） |

> ⚠️ **没有**正则约束、字符集约束配置（如"只允许 0-9"）。字符集完全由**模型文件**决定——内置模型只含 0-9 与 A-Z，`:` `/` 空格一律拒识。
>
> `LowConfidenceThreshold = 0.9` 是**常量不是配置项**：它只影响"要不要提醒"，不参与判定（判定归下游），多一个旋钮只会让现场多一处要调的东西。

## 2.4 HALCON 算子清单

### 分割层（`CharSegmenter.TrySegment`，按调用顺序）

| # | 算子 | 作用 |
|---|---|---|
| 1 | `gen_rectangle2` | 由 `RoiParams` 生成旋转矩形 ROI |
| 2 | `reduce_domain` | 把图像裁剪到 ROI 域 |
| 3 | `count_channels` | 判通道数（>1 才转灰） |
| 4 | `rgb1_to_gray` | 彩色图转单通道 |
| 5 | `threshold` | **固定阈值**：暗字 `0..T`，亮字 `T..255` |
| 6 | `binary_threshold`（`max_separability`） | **自动阈值**，极性 `dark`/`light` |
| 7 | `closing_circle` | 闭运算（先扩后缩），点阵字焊合散点 |
| 8 | `erosion_circle` | 腐蚀，粘连字符断开 |
| 9 | `dilation_circle` | 膨胀，细笔画加粗 |
| 10 | `connection` | 连通域拆分 |
| 11 | `select_shape` × 3 | **三档筛选**：`height` → `width` → `area` |
| 12 | `sort_region` | 阅读顺序排序：`"character"`, `"true"`, `"row"`/`"column"` |
| 13 | `area_center` | 取每个字符的中心行列 |

### 识别层（`OcrEngine`）

| 算子 | 作用 |
|---|---|
| `read_ocr_class_mlp` | 按模型路径读 `.omc`，返回分类器句柄 |
| `do_ocr_multi_class_mlp` | 一次性识别多个**已排序**字符区域 → `classes` + `confidences` |
| `clear_ocr_class_mlp` | `Dispose` 时释放句柄 |

> **没用到的算子**：`create_ocr_class_mlp`（不训练）、`create_text_model`/`find_text`（不用 Deep OCR 路线）、`segment_characters`/`select_characters`（刻意不用，见 1.3）。
>
> `sort_region` 是**必需的**：`do_ocr_multi_class_mlp` 返回的 Class 顺序与输入区域顺序一一对应，**没排序就会拼出一串乱序文本，而且不报错**。

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **三档筛选分开做** | 不用 `select_shape` 多特征 | ⭐⭐⭐ 能报出"是哪一档筛光的"，现场直接知道放宽哪个参数 |
| **点阵字用闭运算而非膨胀** | 先扩后缩，外轮廓尺寸基本还原 | ⭐⭐⭐ 避免"胖字"导致 0→A、3→T 的系统性错 |
| **两条 Warn 诚实机制** | 拒识 + 低置信都报 | ⭐⭐⭐ 杜绝"看似正常的错字符被直接放行" |
| **试算与运行同路径** | 共用 `TryRecognize` | ⭐⭐⭐ 界面看着对 = 跑起来对 |
| **句柄按路径缓存 + 锁** | `Dictionary<string, HTuple>` | ⭐⭐ 不重复加载；Dispose 与运行撞车有保险 |
| **四级模型路径回退** | 显式 → AppBase → HALCONROOT → 短名 | ⭐⭐ 装了 HALCON 但资源没投递成功也能跑 |
| **资源所有权铁律** | 中间对象进 `owned` 列表，`finally` 统一释放 | ⭐⭐ 漏一个就是一次缓慢泄漏 |
| **上游图拷一份显示** | 自己管副本 | ⭐⭐ 不会互相 Dispose 坏句柄 |

# 第 3 章 使用方式

## 3.1 安装与启用

1. **需要模型文件**：内置模型 `Assets/ocr/Industrial_0-9A-Z_Rej.omc`（约 208 KB）随插件投递，**两条路径缺一不可**（见 1.4）。
2. 依赖 HALCON 原生库。
3. 首次使用前关掉宿主进程再生成。
4. 重开软件，工具箱里出现「OCR 文本识别」（**图像处理** 分组）。

## 3.2 配置界面总览（两列）

```
┌──────────────────────────┬────────────────────────────┐
│ 左：参数（330px 可滚动）     │ 右：图像编辑器 ImageEdit     │
│  ① 图像输入（可🔗链接上游）  │  ← 右键可新建矩形识别区        │
│  ② 识别区（+ 清空按钮）      │  ← 拖动手柄粗调              │
│  ③ 常用参数                 │                            │
│  ④ 高级参数（Expander 折叠） │                            │
│  ⑤ 试算（按钮 + 结果）       │                            │
└──────────────────────────┴────────────────────────────┘
```

## 3.3 第一次识别（6 步）

**第 1 步｜接图**：左栏「图像输入」点 🔗 绑定上游图像端口/变量（或在画布拖线）。点「执行」试运行后，上游图会自动显示到右侧。

**第 2 步｜框识别区**：右侧图上**右键 → 区域 → 新建矩形**，框住**整行字符**。
> 框太松会带进背景纹理，框太紧会把字切掉一半。

**第 3 步｜选极性**：常用参数里勾「暗字亮底」（`TextIsDark`，默认开）。
> ⚠️ **选错时一个字都切不出来**。

**第 4 步｜试算**：点「试算一下」，结果显示在等宽字体区：
```
文本 11240B    字符数 6    拒识 0
均值置信度 0.98
实际阈值 154（自动）
明细 1:1(0.99) 2:1(0.98) 3:2(0.97) 4:4(0.99) 5:0(0.98) 6:B(0.97)
```

**第 5 步｜按明细调参**：切不出来 / 认不准 → 展开「高级参数」：
| 现象 | 调什么 |
|---|---|
| 点阵字散成小点、切不出整字 | `ClosingRadius`（从 1.5 起试） |
| 两个字粘一起算一个 | `ErosionRadius`（腐蚀断开） |
| 笔画太细 | `DilationRadius` |
| 切出太多脏点 | 收紧 `MinCharHeight` / `MinArea` |

**第 6 步｜看置信度**：`Confidence` < 0.9 或出现 `?`（拒识）→ 日志会 Warn，**不要直接放行**。

## 3.4 参数调节速查表

| 现象 | 调哪里 |
|---|---|
| 一个字都切不出来 | ① 极性选反了（`TextIsDark`）② 阈值不合适（换自动/固定）③ 识别区没框住字 |
| 切出太多碎片 | 调大 `MinCharHeight` / `MinArea`；或 `ClosingRadius` 焊合散点 |
| 两个字粘成一个 | `ErosionRadius` 腐蚀断开 |
| 点阵喷印认成别的字（0→A、3→T） | 用了膨胀导致"胖字" → 改用 `ClosingRadius` |
| 认错但有把握（置信度高） | 模型/字符集不匹配。：`/` 空格不在内置字符集里 |
| 竖排文字 | 勾 `ColumnFirst` |
| 要认中文 | 填 `ModelPath` 指向自训练模型（留空 = 内置 0-9/A-Z） |
| 报错"哪一档掉的" | 按提示放宽对应参数（见 3.6 排障） |

## 3.5 FAQ

**Q1** 为什么必须要有「试算」？
分割的成败取决于"这幅图的直方图与字符尺寸长什么样"，光看参数值想象不出来。能在框完识别区的当下看到"切出几个字、各自认成什么、置信度多少"，才有依据调高级参数。**没有试算的 OCR 插件等于不可用**。

**Q2** 均值置信度低于 0.9 会怎样？
写一条 Warn，提示"请勿直接用于放行"。**不判 NG**（判定归下游）。

**Q3** 拒识字符怎么显示？
明细里显示 `?`（如 `2:?(0.72)`）。字符数**包含**拒识字。

**Q4** 内置模型能认什么？
只含 `0-9` 与 `A-Z`。`:` `/` 空格一律拒识。要认中文或特殊字符，填 `ModelPath` 用自训练模型。

**Q5** 我填了模型路径但认不出来怎么办？
**显式配了却不存在的路径会直接报错**，不会静默退回内置——否则你会以为是"OCR 连中文都认不出来"，而没有任何提示指向真因。

**Q6** 有正则约束吗（比如"只允许数字"）？
**没有**。格式校验归下游比较节点。字符集约束纠正（0/O、1/I 混淆）需受约束重打分，是独立课题，本轮不做。

## 3.6 现场排障

| 现象 / 报错 | 含义与排查 |
|---|---|
| "尚未框选识别区" | 没画矩形。在右侧图上右键 → 新建矩形 |
| "识别区里没有切出任何字符。筛选过程：连通域 N 个 → 过高 … → 再过宽 … → 再过面积 0 个" | **按这一句就知道放宽哪个**：<br>· 第一档（高度）掉光 → 极性选错、或点阵没焊合（调 `ClosingRadius`）<br>· 第三档（面积）掉光 → 面积范围与字符实际大小不匹配 |
| "识别区的半长/半宽必须大于 0" | 框画得太小，重画 |
| 坐标越界报错 | 识别区画到图像外了 |
| "指定的 OCR 模型文件不存在" | `ModelPath` 填错。修正或清空（用内置） |
| 置信度低 / 有拒识 | 看日志 Warn。低对比点阵图（瓶盖曲面、细纹理纸面）常见 |
| 界面显示"先点「载入」把示意图读进来" | **残留文案**。图只有上游端口一个来源，去「图像输入」点 🔗 绑定 |

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与开发文档）。每条给：现象 → 原因 → 修法。

## 4.1 缺陷修复总览

| 级别 | 问题 | 一句话 |
|---|---|---|
| P0 | 拒识判空漏判 | HALCON 返回一个"看不见的字符"，被当成"认出来了" |
| P0 | 点阵字用膨胀导致系统性错认 | 0 认成 A、3 认成 T |
| P1 | 显式模型路径不存在却静默退回内置 | 现场以为是"OCR 不认识中文" |
| P1 | 三档筛选合一导致报错无指向性 | 只说"没切出字符"，现场无从下手 |
| P2 | 宣传/注释口径未同步（膨胀 vs 闭运算） | 提示语仍写"调膨胀半径" |

| P3 | `scale_image_max` 旋钮被删 | 实测没用，删掉 |

## 4.2 P0/P1 级详解

### ① 拒识判空漏判（最隐蔽的 bug）

**现象**：明细里出现 `2:(0.99)` 这种什么都看不见的项，而 `RejectedCount` 却是 0——**拒识被当成"认出了一个字符"混进结果**。

**原因**：HALCON 返回的既不是 `null`、空串、也不是空格，而是一个"看起来什么都没有"的字符。**判空 / 判空白都漏过去了**。

**修法**：换可靠判据——`Industrial_0-9A-Z_Rej` 分类器的输出只可能是 0-9 与 A-Z，**所以"输出里没有字母也没有数字"等价于"它没认出这个区域"**。这个判据不依赖 HALCON 用哪个占位符表示拒识，比猜字符形状稳。

> 配套：拒识在明细里统一显示 `?`，否则拼出来是 `2: (0.98)` 这种看不出所以然的东西——**一个看不见的字符在日志里等于没写**。

### ② 点阵字用膨胀导致系统性错认

**现象**：点阵喷印的字被认成别的（实测 0 认成 A、3 认成 T），而且是**系统性**的。

**原因**：膨胀 = 只扩不缩 → 笔画整体变粗、字形失真。MLP 分类器拿到一个"胖"字就会错认。

**修法**：改用**闭运算**（先扩后缩）——点之间连上了，外轮廓尺寸基本还原。点阵喷印从 `ClosingRadius=1.5` 起试。

> 结论：**"连接"用闭运算，"加粗"才用膨胀，两者不能互相替代。**

### ③ 显式模型路径不存在却静默退回内置

**现象**：用户填了一个中文模型路径、实际却拿内置的 0-9A-Z 分类器在跑，现场只会觉得"这 OCR 连中文都认不出来"，**没有任何提示指向真因**。

**修法**：显式配了却不存在的路径**直接报错**，不许静默退回内置。

### ④ 三档筛选合一导致报错无指向性

**现象**：切不出字符时只报"没切出字符"，现场要从头试所有参数。

**原因**：用 `select_shape` 多特征有两个问题——① 多特征要把特征名拼成元组，而 `HTuple` 的 `operator+` 是**算术加**不是拼接，拼错的表现是 HALCON `#3101 Unknown feature`，一个完全不指向真因的报错；② 合一后报不出"是哪一档筛光的"。

**修法**：三档分开做，并在报错里把每一档的数量都写出来。

## 4.3 代码级踩坑汇编

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | 拒识被当成正常字符 | HALCON 返回"看不见的字符"，判空漏判 | 判"输出里没有字母也没有数字" |
| 2 | 点阵字认错（0→A） | 用膨胀导致字形变胖 | 用闭运算 |
| 3 | `#3101 Unknown feature` | `HTuple` 的 `+` 是算术加不是拼接 | 三档分开做，不拼特征元组 |
| 4 | 认不出中文但没提示 | 显式路径不存在静默退回内置 | 显式配了不存在就报错 |
| 5 | 句柄泄漏 | 基类管不到引擎内部句柄 | 重写 `Dispose` 逐个 `clear_ocr_class_mlp` |
| 6 | 乱序文本 | `do_ocr_multi_class_mlp` 顺序与输入区域一一对应 | 分割层必须 `sort_region` |

## 4.4 HALCON API 踩坑

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `#3101` Unknown feature | 特征名元组拼错 / 特征不被支持 | 分开做，或换等效算法 |
| 2 | 乱序文本 | Class 顺序 = 输入区域顺序 | 先 `sort_region` |
| 3 | 拒识占位符不确定 | HALCON 用"空格"表示拒识 | 判"没有字母数字" |
| 4 | 固定阈值"设了 128 却切在别处" | `binary_threshold` 的 `'fixed'` 模式语义不同（按直方图自适应） | 固定阈值直接用 `threshold`，不借道 |
| 5 | 极性处理多一次全图运算 | 先 `invert_image` 再二值化 | 用 `binary_threshold` 的 `dark`/`light` 参数 |
| 6 | 句柄泄漏 | `read_ocr_class_mlp` 是进程级非托管资源 | 必须 `clear_ocr_class_mlp` |

## 4.5 已知边界与待办

- **字符集只含 0-9 与 A-Z**：`:` `/` 空格一律拒识。中文/自训练需填 `ModelPath`。
- **不做格式校验 / 正则约束**（归下游比较节点）。
- **0/O、1/I 混淆未处理**（需受约束重打分，是独立课题）。
- `LowConfidenceThreshold = 0.9` 是**常量**，不可配。

- `ErosionRadius` / `DilationRadius` 无实测用例（`ClosingRadius` 有点阵实测）。
- 低对比点阵图（瓶盖曲面、细纹理纸面）会大面积拒识——**这是"看得出来"而不是"认错"，属预期行为**。

## 5.3 附录 C：HALCON 实战案例

### 案例 1｜标准印刷字：自动阈值 + 连通域

```hdevelop
* ① 生成 ROI 并裁剪
gen_rectangle2 (Roi, Row, Col, Phi, HalfLen, HalfWidth)
reduce_domain (Image, Roi, ImageReduced)
* ② 转灰度（单通道图不要 rgb1_to_gray，会报错）
count_channels (ImageReduced, Channels)
if (Channels > 1)
    rgb1_to_gray (ImageReduced, Gray)
else
    copy_image (ImageReduced, Gray)
endif
* ③ 自动阈值（Otsu），暗字亮底用 'dark'
binary_threshold (Gray, Region, 'max_separability', 'dark', UsedThreshold)
* ④ 拆连通域 + 按高度筛
connection (Region, Connected)
select_shape (Connected, Chars, 'height', 'and', 8, 300)
* ⑤ 按阅读顺序排序（必需！do_ocr 的顺序 = 输入区域顺序）
sort_region (Chars, Sorted, 'character', 'true', 'row')
```

### 案例 2｜点阵喷印字：必须用闭运算，不能用膨胀

```hdevelop
* 点阵字的笔画是一个个散点，直接 connection 会碎成一地
* ✗ 错：dilation_circle 只扩不缩 → 字形变胖 → 0 被认成 A、3 被认成 T
*   dilation_circle (Region, Fat, 1.5)
* ✓ 对：闭运算先扩后缩 → 点连上了，外轮廓尺寸基本还原
closing_circle (Region, Closed, 1.5)
connection (Closed, Connected)
```

> 经验：点阵喷印从 `ClosingRadius = 1.5` 起试；实心印刷字不需要（默认 0）。

### 案例 3｜识别（必须先排序）

```hdevelop
* 读模型
read_ocr_class_mlp ('Industrial_0-9A-Z_Rej', OCRHandle)
* 识别：Class 的顺序 = 输入区域的顺序，没排序就会拼出乱序文本且不报错
do_ocr_multi_class_mlp (Sorted, Gray, OCRHandle, Class, Confidence)
* 释放（进程级非托管资源）
clear_ocr_class_mlp (OCRHandle)
```

### 案例 4｜拒识的正确判法（别判空）

```hdevelop
* HALCON 对认不出的区域返回的是"空格"之类的占位，不是空串也不是 null。
* 判空 / 判空白都会漏过去，于是拒识被当成"认出了一个字符"。
* 可靠判据：内置分类器只可能输出 0-9 与 A-Z，
* 所以"输出里没有字母也没有数字" 等价于 "它没认出这个区域"。
for i := 0 to |Class| - 1 by 1
    HasAlnum := false
    * 逐字符检查 Class[i] 是否含 0-9 / A-Z
    if (not HasAlnum)
        Rejected := Rejected + 1      * 这一位记为拒识，明细里显示 '?'
    endif
endfor
```

### 案例 5｜固定阈值（别借道 binary_threshold 的 'fixed'）

```hdevelop
* binary_threshold 的 'fixed' 模式语义与 threshold 不同（它按直方图在给定值附近自适应），
* 混用会让"设了 128 却切在别处"这种问题极难查。
* 固定阈值直接用 threshold：
threshold (Gray, Region, 0, 128)        * 暗字（TextIsDark = true）
* threshold (Gray, Region, 128, 255)    * 亮字（TextIsDark = false）
```

### 案例 6｜极性：用算子参数，不要先反相

```hdevelop
* ✗ 多一次全图运算：invert_image (Gray, Inverted) 再二值化
* ✓ 用 binary_threshold 的极性参数，少一次运算且"当前按哪种极性在切"一眼可见
binary_threshold (Gray, Dark,  'max_separability', 'dark',  T1)   * 暗字亮底
binary_threshold (Gray, Light, 'max_separability', 'light', T2)   * 亮字暗底
```
