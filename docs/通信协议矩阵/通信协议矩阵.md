## 2. 关键实现口径

### 2.1 字节序

| 协议 | `ICommunicationConnection.ByteOrder` | 依据 |
|---|---|---|
| Modbus | 由 `ModbusTcpConfig.ByteOrder` 决定（ABCD/DCBA/BADC/CDAB） | 现场设备决定，必须显式配置 |
| S7 | `ABCD` | S7 报文本身大端 |
| 三菱 MC | `DCBA` | **实测**：写 `0x1234` 线序 `34 12`；写 `int 0x12345678` 线序 `78 56 34 12`（小端） |
| 欧姆龙 FINS | `CDAB` | 与 `OmronFinsServer` 的 `DataFormat.CDAB` 同源 |
| 自由协议 | `ABCD` | 文本协议无多寄存器字序概念，保留契约值 |

### 2.2 三菱 MC 的厂商变体

三家都走 QnA 兼容 3E 帧，差异只在**地址解析**：

- `McVendor.Mitsubishi` → `MelsecMcNet` / `MelsecMcAsciiNet`
- `McVendor.Keyence` → `KeyenceMcNet`（`DM100`/`R100`/`MR100`…）
- `McVendor.Panasonic` → `PanasonicMcNet`（`DT100`/`WR100`/`LD0`…）

选错厂商的表现是"地址解析失败"，不是连不上；配置面板的「厂商」就是为这件事存在的。

### 2.3 MC / FINS 的批量轮询

已接入字区批量：

1. `PollProtocol` 增加 `Mc` / `Fins`；
2. `McAddress` / `FinsAddress` 把地址解析成 `GroupKey` / `Start` / `SpanUnits`（**字**单位）；
3. `PollBatchPlanner` 通过 `ISegmentReader.ReadSegment(address, units)` 读段——MC/FINS 的 `units` 是"字"，
   不会像 `ReadBytes` 那样被误当字节；
4. 单请求上限：MC 960 字、FINS 500 字；1000 个连续 D 寄存器 → 2 段、0 兜底；
5. **位区不批量**：MC 的 M/X/Y/L/B/F/S/V、FINS 的 `D100.0` 位地址走单读（位打包解码与字区不同）。

HSL 虚拟 PLC 实测（本机 loopback，仅作相对对比）：

| 协议 | 1000 点 | 段 / 兜底 | 批量 | 单读 | 倍数 |
|---|---|---|---|---|---|
| MC | D0~D999 | 2 / 0 | 1ms | 56ms | 56x |
| FINS | D0~D999 | 2 / 0 | <1ms | 75ms | >75x |

同时写入 `D0/D1/D500/D999` 已知值，批量轮询后按变量读回一致（防"快但错"）。

**当前不要**把 MC/FINS 地址塞进 Modbus/S7 的解析器，那会把"字区批量"变成"错误合并"。

### 2.4 自由协议（FreeProtocol）

定位：**一行文本命令**的设备兜底（条码枪、称重仪、扭矩枪、部分光源控制器）。

- `Read<T>(address)`：发送 `address + 帧结束符`，读到结束符后按 T 解析；
- `Write(address, value)`：address 含 `{0}` 时按模板格式化，否则"address + value"；
- `FrameTerminator` 支持 `\r` `\n` `\t` `\0` `\xNN` 转义；留空 = 读到超时；
- `WriteExpectsResponse=false` 用于"只收不回"的设备，避免每次写白等一个超时；
- **不支持** CRC/长度前缀/二进制帧；这类设备请用脚本插件或后续的帧编辑器，不要硬塞。

## 3. 测试与仿真

### 3.1 契约断言（无设备）

```powershell
dotnet run --project CommChecks
```

覆盖：

- B5-1：MC / FINS / FreeProtocol 配置 `Validate` 与 `Config` 类型；
- B5-2：MC/FINS 地址 `D100` 通过、`@@@` 被拒；
- B5-3：工厂创建 MC/FINS/Free 连接类型正确；
- B5-4：MC UDP 在 `Validate` 阶段被拒；
- B6：FreeProtocol 本地 TCP 回环（`Read<int>("READ")==42`、`Write("SET {0}",7)`、连续读帧边界）。

### 3.2 HSL 虚拟 PLC（真 TCP）

```powershell
# 完整压测（含 S0e MC/FINS 批量性能）
dotnet run --project CommStress

# 只跑 MC/FINS 批量 vs 单读
dotnet run --project CommStress -- mcperf

# 只跑诊断链路
dotnet run --project CommStress -- diag
```

`CommStress` 用 HslCommunication 自带的虚拟服务器：

- `ModbusTcpServer` :1502
- `SiemensS7Server` :1102
- `MelsecMcServer` :1802（二进制 3E）
- `OmronFinsServer` :1960（FINS/TCP）

S0c / S0d 两段会做**真写→真读回环**：

- MC：写 `D100=0x1234`、`D200=0x12345678`，读回必须一致；
- FINS：写 `D100=0x1234`，读回必须一致。

如果这两段出现 `真连真读=False`，先看打印的"读回值/原始字节"：
- MC 读回 `0x3412` = 字节序配错（应为 `DCBA`）；
- FINS 连不上 = 检查 `DNA/DA1/DA2` 与服务器端口。

## 4. 新增一个协议的最小步骤

1. **配置类**：`Core/CommunicationContracts/Config/XxxConfig.cs`，继承 `EthernetConfigBase` 或 `ConnectionConfigBase`，实现 `Clone` / `Validate`。
2. **连接类**：`Communication/Communications/Connection/XxxConnection.cs`，实现 `ICommunicationConnection`；建议同时实现 `ILinkHealthProbe` / `IConnectionFailureDetail`（照 `SiemensS7Connection`）。
3. **工厂**：`ConnectionFactory.cs` 加 `IConnectionFactory` + `ICommunicationDriverFactory`，并在 `RegisterDefaults` 注册。
4. **清单**：`CommunicationConfig.TryCreateConfig` 加 `case`；`CommunicationProtocols.Implemented` 加类型。
5. **地址**：优先复用 HSL 的解析器；不要自己写正则覆盖厂商差异。
6. **测试**：`CommChecks` 加配置/地址/工厂断言；`CommStress` 用 HSL 虚拟服务器做真 TCP 回环。
7. **文档**：更新本矩阵与 `docs/项目全景说明.md` 的协议口径。

## 5. 已知限制 / 后续

| 项 | 状态 | 说明 |
|---|---|---|
| OPC UA | 未实现 | 缺 `Opc.Ua.Client` 依赖；证书/订阅模型未落地 |

| Delta / Inovance / AB / Beckhoff 等 | 未接入 | HslCommunication 已有客户端，按 BOM 逐个加配置/地址/测试 |
| 自由协议二进制帧 | 不支持 | 仅文本 + 结束符；CRC/长度前缀需脚本或帧编辑器 |
