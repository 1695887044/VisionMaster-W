# docs/实施计划

> 实施计划存档。原名 `docs/superpowers/`（ZCode 时代的目录名），2026-10-24 改名：
> 目录里装的是**本项目的实施计划**，不是某个工具的产物。

## 这里的文档是什么

**计划，不是结论。** 记录当时的任务拆解、依赖关系、验收口径。
计划与最终结果的偏差不写回这里，写进 [`docs/code-changes/`](../code-changes/)。

## 与另外两类文档的区别

| 目录 | 回答什么 | 时效 |
|---|---|---|
| [`docs/实施计划/`](README.md)（本目录） | "当时打算怎么做" | 归档后**不改写** |
| [`docs/方案设计/`](../方案设计/README.md) | "为什么选这个方案"（决策留痕） | 变更时**追加新版本**，不覆盖旧版 |
| [`docs/code-changes/`](../code-changes/INDEX.md) | "实际改了什么、怎么验的" | 只追加，不回改 |

## 文件

| 路径 | 内容 |
|---|---|
| [`plans/`](plans/README.md) | 按 `yyyy-MM-dd-<主题>.md` 命名的实施计划，当前 2 篇：`2026-10-24-方案级用户管理实施计划.md`、`2026-10-24-方案级用户管理-交接说明.md` |

## 命名与历史

按日期前缀命名，与 `code-changes/` 同一套习惯，方便按时间线对照"计划 vs 实际"。
