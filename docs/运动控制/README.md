## ⚠️ 最需要记住的四条（都是撞机级）

1. **下发 ≠ 到位**——`Enqueue` 返回只代表"命令被收进队列了"。要等轴真的走到位，**必须再加一个「等待到位」步骤**。把"下发成功"当"运动完成"是运动控制里最经典的错误，会写出看起来并行、实际串行的流程。
2. **`UnitsPerMm`（脉冲当量）必须先标定再上电**——配错等于所有行程按错的倍率走。`SetUnits` 之后 API 一律是 mm，**不要再除当量**。
3. **增量式编码器每次上电/断线重连后必须回零**——否则绝对运动会按错误坐标算行程，**可能直接撞向限位**。
4. **软件急停不能替代硬件安全回路**——真正的急停必须由**硬件回路**（急停按钮直接切伺服使能）保证。

## 维护约定

1. **只改主文档**。`运动控制插件.md` 是唯一事实来源；归档件只作历史留档。
2. **寻址口径已定死**：轴级操作只给**轴名**，卡级操作给**卡名**；**地址不进流程**。
3. **命令是异步的**：不要在 `Enqueue` 后假设已到位；等待一律用独立「等待到位」步骤。
4. **急停必须能插队**，且用**令牌链接**才能打断正在执行的长命令；区分"被急停打断"（预期，不报故障）与"设备断开"两种取消。
5. **先落副作用，再发完成信号**（防"已完成但 IsHomed 仍是 false"的中间态）。
6. **单位换算只在驱动层做一次**：`SetUnits` 之后一律 mm，不再除当量。
7. **回零码只能来自手册**，不猜；回零**不可盲目重试**（`Retryable=false`）。
8. **报警/限位优先于"到位"**——只看 InPosition 会把"撞停"当成"走到位"。
9. **状态查询读轮询快照**，不发起通信；IO 要**批量读**，别逐点问。
10. **点动必须有心跳兜底**——安全不能建立在"事件一定送达"的假设上。
11. **不编造错误码字典 / 不猜未识别机型能力**（报小不报大）。
12. ⚠️ **待确认**：`ZMotionCard.cs` 的 `SupportsAbsoluteEncoder` 代码值与注释不一致（注释说"保守取 false"，代码是 `true`），需人工确认后统一。
