# 第 0 章 这是什么

**运动控制插件 = 让视觉流程能"指挥机器动起来"。**

> 生活比喻：前面所有视觉插件都是"眼睛"（看、测、判）。运动控制是"**手和脚**"——看完之后让轴走过去、回原点、夹爪动作、气缸伸缩。

它分**两半**：

| 半边 | 工程 | 是什么 | 用户看到什么 |
|---|---|---|---|
| **流程步骤**（L4） | `Plugin.Motion.Steps` | 7 个流程节点（轴使能/运动/回零/等待/停止/读状态/IO） | 拖进流程的**节点** |
| **设备驱动**（L1） | `Plugin.Motion.Virtual`<br>`Plugin.Motion.ZMotion` | 虚拟仿真卡 / 正运动真实控制器 | 在系统菜单里配置的**运动卡** |

## 0.1 三个工程一览

| 工程 | 定位 | GroupName |
|---|---|---|
| **`Plugin.Motion.Steps`** | **流程步骤**：用户在流程里拖的 7 个节点。纯托管、net9.0（**不带 -windows**），只调 `Core.Interfaces` 的契约，不知道任何厂商 SDK | 运动控制 |
| **`Plugin.Motion.Virtual`** | **虚拟运动卡（仿真）**：无硬件也能开发与回归，支持**故障注入**（模拟报警/通信失败/增量编码器） | 运动卡 |
| **`Plugin.Motion.ZMotion`** | **正运动（ZMotion）真实控制器驱动**：ECI/ZMC 系列网口控制器 | 运动卡 |

> 计划书里提到的雷赛 `Plugin.Motion.LeadShine` **未实现**（仓库中不存在该目录）。

## 0.2 一条典型链路

```
[视觉定位] ──▶ [轴运动] ──▶ [等待到位] ──▶ [轴卡 IO（夹爪）] ──▶ [继续]
   ↑               ↑              ↑
先算坐标       只下发命令      等它真的走到
```

# 第 1 章 设计思想

## 1.1 核心：运动是"命令模式"，不是"推模式"

相机与运动是**同一范式的兄弟，但执行模型完全不同**（这点必须看清）：

| | 相机 | 运动 |
|---|---|---|
| 模式 | **推模式**：设备持续送帧，流程去"取"。设备是主动方 | **命令模式**：流程下发命令 → 卡执行 → **状态靠主动轮询**回来。流程是主动方 |
| 关键约束 | — | ① **命令是异步的**：`Enqueue` 返回的是"收下了吗"，**不是"动到位了"**<br>② **急停必须能插队**：排队执行的急停不是急停 |

> ⚠️ **把"下发成功"当"运动完成"是运动控制里最经典的错误**，会写出看起来并行、实际串行的流程。

## 1.2 四层架构

```
L4 流程步骤插件   Modules\Plugin.Motion.Steps.dll      用户拖的：轴运动/回零/等待/读状态/IO
L3 设备资源层     MotionProvider + SolutionModel.MotionCards   方案级配置与生命周期
L2 能力抽象层     IMotionDevice + MotionCapabilities + 命令/状态模型
L1 驱动实现插件   Modules\Plugin.Motion.ZMotion.dll / .Virtual.dll   一品牌一个
```

> 📌 计划书里的接口草案名是 `IMotionCard` / `MotionCardDescriptor` / `PulsePerMm`；**落地后实际叫 `IMotionDevice` / `MotionDescriptor` / `UnitsPerMm`**。

## 1.3 寻址口径（定死了，别往回加地址）

> - **轴级操作 → 只给轴名**。轴名全局唯一，注册表按它一次解出"哪张卡 + 哪个轴号"。
> - **卡级操作**（IO 读写端子、停某张卡的全部轴）→ **给卡名**。
> - **地址（IP/槽位）只活在「运动卡设置」里**，是驱动连接用的，**不进流程**。

## 1.4 三条"写错后果很重"的驱动约定（正运动）

> ① `SetUnits` 之后位置/速度 API **一律是用户单位（mm）**，**不要再拿脉冲当量去除**；
> ② 回零的完成判据是 `GetHomeStatus == 1`，**homemode 数字只能来自手册**；
> ③ 位置模式运动是"**下发即返回**"，等到位是上层「等待到位」步骤的事。

## 1.5 虚拟卡刻意"不瞬间到位"

> 虚拟卡模拟真实异步运动：`Move` 命令**立即返回**，位置由轮询线程按速度逐拍推进，走完才置 `InPosition`。
> 这样才测得出"**下发 ≠ 到位**"这条最容易写错的语义——若虚拟卡是瞬间到位，一切流程看起来都对，真机上却会出现"两条轴同时下发、实际串行"。

# 第 2 章 技术特点

## 2.1 七个流程步骤（Plugin.Motion.Steps）

| 步骤 | Name | 图标 | Description |
|---|---|---|---|
| **轴使能** | 轴使能 | `f011` | 给轴上电（使能）或断电（失能）。伺服上电有机械后果，建议按现场的上电顺序显式放置 |
| **轴运动** | 轴运动 | `f0d1` | 让轴走到目标位置（**只下发命令，不等待到位**） |
| **轴回零** | 轴回零 | `f015` | 让轴回原点（**阻塞到回零完成**；增量式编码器每次上电后都应先执行） |
| **等待到位** | 等待到位 | `f017` | 等待轴运动到目标位置（轮询设备状态，带超时与报警检查） |
| **轴停止** | 轴停止 | `f04d` | 停止指定轴（或全部轴）。**急停模式会清空待执行命令并立即停止**，请勿替代硬件安全回路 |
| **读轴状态** | 读轴状态 | `f201` | 读取位置/速度/使能/限位/报警等（**读轮询快照，不额外占用通信**） |
| **轴卡 IO** | 轴卡 IO | `f0e7` | 读写运动卡上的数字输入/输出（气缸、夹爪、传感器等） |

### 端口与配置

**轴使能**

| 端口名 | 方向 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| `Axis` | 入 | string | ✖ | `"X"` | 逻辑轴名 |
| `Enable` | 入 | bool | ✖ | `true` | true=使能 / false=失能 |
| `Timeout` | 入 | int | ✖ | `10000` | 超时 ms |
| `Enabled` | 出 | bool | — | — | **操作后**的使能状态 |

**轴运动**

| 端口名 | 方向 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| `Axis` | 入 | string | ✖ | `"X"` | 逻辑轴名 |
| `Mode` | 入 | 枚举 | ✖ | `Absolute` | 绝对 / 相对 |
| `Target` | 入 | double | ✖ | `0.0` | 目标位置（**mm**） |
| `Velocity` | 入 | double | ✖ | `0.0` | 速度 mm/s（**0 = 用卡级默认**） |
| `Accepted` | 出 | bool | — | — | ⚠️ **不代表已到位** |
| `AxisUsed` | 出 | string | — | — | 供下游「等待到位」直接引用 |

> 目标和速度是**输入端口**而不是配置项，因为它常常来自上游：**视觉定位给出坐标 → 这一步接过去 → 轴走过去**。用配置项就绑不了变量，视觉引导就无从落地。

**轴回零**：`Axis`(入) + `Mode`(`[StepConfig]`，默认 `NegativeLimitIndex`) + `TimeoutMs`(`[StepConfig]`，默认 **120000**) + `Homed`(出)

**等待到位**：`Axis`(入) + `TimeoutMs`(默认 30000) + `PollIntervalMs`(默认 20，Clamp 1~500) + `Position`(出) + `ElapsedMs`(出)

**轴停止**：`Axis`(入，**留空 = 停所有卡的全部轴**) + `Mode`(默认 `Decelerate`) + `UseEmergencyStop`(默认 false) + `Accepted`(出)
> 勾上 `UseEmergencyStop` 后 **Axis 与 Mode 都被忽略**——急停的语义就是"全停下来，别排队"。

**读轴状态**：`Axis`(入) + `FailOnAlarm`(默认 false) + 9 个输出（`Position`/`Velocity`/`Moving`/`InPosition`/`Enabled`/`Alarm`/`PositiveLimit`/`NegativeLimit`/`StatusText`）

**轴卡 IO**：`Card`(入，**按卡名不是 IP**) + `Direction`(`[StepConfig]`) + `IoPort`(入，0 基) + `Value`(入，写值) + `Accepted`(出) + `InputValue`(出)

## 2.2 卡级配置（`MotionDescriptor` / `AxisMapping`）

### 三条硬要求（注释原文）

> 1. **逻辑名是流程唯一引用的东西**。物理轴号可能因接线、换卡而变，逻辑名是机构语义，流程只认它。
> 2. **`UnitsPerMm` 是机械换算（脉冲当量）**。流程里一律用毫米，换算发生在驱动层；**配错这个值等于所有行程都按错的倍率走，必须先标定再上电**。
> 3. **软限位是软件层的最后一道防线**。硬限位在卡上，软限位在这里——**两层都要有**。

| `AxisMapping` 字段 | 默认 | 含义 |
|---|---|---|
| `LogicalName` | — | 逻辑轴名 |
| `PhysicalIndex` | — | 物理轴号（0 基） |
| `Enabled` | — | 是否启用 |
| `UnitsPerMm` | `1000` | 脉冲当量 |
| `SoftLimitMinMm` | `-1e6` | 软限位下限 |
| `SoftLimitMaxMm` | `+1e6` | 软限位上限 |
| `IsSoftLimitDisabled` | — | 是否禁用软限位 |

| `MotionParams` 字段 | 默认 | 含义 |
|---|---|---|
| `DefaultVelocityMmPerS` | `50` | 默认速度 |
| `DefaultAccelMmPerS2` | `500` | 默认加速度 |
| `PollIntervalMs` | `10` | 状态轮询周期（工业常见 5~20ms） |
| `CommandTimeoutMs` | `30000` | 命令超时 |
| `WatchdogTimeoutMs` | `3000` | 看门狗超时 |
| `AutoReconnect` | `true` | 自动重连 |
| `MaxQueueDepth` | `256` | 最大队列深度 |

## 2.3 驱动接口 `IMotionDevice`

成员：`Descriptor` / `State` / `StateDetail` / `Capabilities` / `ModelName` / `LastFault` / `IsHomed` / 计数器 / `StateChanged` / `FaultOccurred` / `Connect` / `Disconnect` / `ClearAlarm` / `NotifyAlive` / `GetAxisStatus` / `ReadInput` / `Enqueue` / `EmergencyStop` / `CancelAll` / `ResetCounters`

> **状态查询一律读轮询缓存**，不发起通信：界面每秒可能查几十次，每次都发一次网口请求会把带宽吃光，而且会让"这一帧界面上的几个字段"来自不同时刻、互相矛盾。

## 2.4 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **命令队列 + 异步** | `Enqueue` 立即返回 | ⭐⭐⭐ 支持"两轴同时运动" |
| **急停专用插队槽** | 不排普通队列 | ⭐⭐⭐ 排队执行的急停不是急停 |
| **急停令牌链接** | 设备令牌 + 急停令牌链接后交给驱动 | ⭐⭐⭐ 能打断正在执行的长命令（如回零） |
| **门禁分层** | 在线门禁 / 软限位门禁 / 报警门禁 / IsHomed 门禁 | ⭐⭐⭐ 防撞机 |
| **看门狗** | 轮询连续失败 → 安全停机 | ⭐⭐⭐ 失联不死等 |
| **状态读快照** | 不发起通信 | ⭐⭐⭐ 省带宽、字段自洽 |
| **虚拟卡故障注入** | 模拟报警/通信失败/增量编码器 | ⭐⭐⭐ 无硬件也能验证安全路径 |
| **点动心跳兜底** | 500ms 没脉冲自动停 | ⭐⭐⭐ **安全不能建立在"事件一定送达"的假设上** |
| **逻辑名寻址** | 流程只认轴名 | ⭐⭐ 换卡/改接线只改映射表 |
| **批量读输入** | 一次读全部输入点 | ⭐⭐ 避免 10ms 周期下 24 次往返打满网口 |

# 第 3 章 使用方式

## 3.1 安装与启用

1. 编译后产物投到 `Modules\`（`Plugin.Motion.Steps.dll` / `Plugin.Motion.Virtual.dll` / `Plugin.Motion.ZMotion.dll`）。
2. **正运动还需 native SDK**：`Sdk\zauxdll.dll` **与** `Sdk\zmotion.dll` **必须同时存在**（缺 `zmotion.dll` 时报错是 `0x8007007E`，看上去像"zauxdll 没放对位置"，极误导）。
3. 重开软件，工具箱出现 7 个运动步骤；**系统菜单**出现「运动卡设置」与「运动卡调试」。

## 3.2 调试面板（4 个页签）

```
系统 → 运动卡设置 / 运动卡调试
┌──────────────────────────────────────────┐
│ [卡设置] [手动调试] [点位列表] [电子凸轮]   │
├──────────────────────────────────────────┤
│ 手动调试：                                │
│   连接/断开  清报警  【急停】（红色独立入口）│
│   使能 / 失能                             │
│   点动 ← / →（按住才动）                   │
│   定位到… / 定位并等待 / 取当前位置 / 回零  │
│   IO 输出列表（点击翻转）                  │
│   一带多：左侧轴列表，右侧该轴的状态        │
└──────────────────────────────────────────┘
```

### 点动的三条安全设计（务必理解）

> 1. **点动「按住才动」**：按下执行、**按住期间每 150ms 重复**、松开/移出/失焦/控件禁用都收尾。
> 2. **点动心跳兜底**：看门狗发现超过 **500ms** 没收到界面脉冲就自动停——即使界面事件全丢（失焦、卡顿、行为失效），设备也不会一直走。**安全不能建立在"事件一定送达"的假设上**，这是点动与普通按钮的根本区别。
> 3. **关窗必停点动**：点动的终点是"松手"，面板都关了就不会再有松手事件。

## 3.3 第一次让轴动起来（6 步）

**第 1 步｜配置卡**：系统 → 运动卡设置 → 选驱动（正运动 / 虚拟仿真）→ 填地址（IP）→ 给卡起个名字 → 配轴映射（逻辑名 ↔ 物理轴号 + `UnitsPerMm`）。

> ⚠️ **`UnitsPerMm` 必须先标定再上电**——配错等于所有行程按错的倍率走。

**第 2 步｜拖「轴使能」**：给轴上电。

**第 3 步｜拖「轴回零」**（增量式编码器必做）：连上不等于位置可信，**每次上电/断线重连后都必须回零**。建议放流程首步。

**第 4 步｜拖「轴运动」**：填目标位置（mm），或连上游定位结果。

**第 5 步｜拖「等待到位」**：⚠️ **这一步不能省**——轴运动只下发命令。

**第 6 步｜（可选）拖「轴卡 IO」**：控制夹爪/气缸。

## 3.4 参数速查表

| 你想做 | 怎么做 |
|---|---|
| 两轴同时动 | 连续拖两个「轴运动」（都不等待）→ 再拖两个「等待到位」 |
| 等轴真的走到 | 必须加「等待到位」步骤 |
| 视觉引导抓取 | 定位坐标 → 轴运动.Target → 等待到位 → IO 夹爪 |
| 换卡/改接线 | 只改轴映射表，**流程不用动** |
| 急停 | 「轴停止」+ 勾 `UseEmergencyStop`（⚠️ **不能替代硬件安全回路**） |
| 读当前位置 | 「读轴状态」读 `Position` |
| 报警了 | 先「清报警」→ 再手动使能（**清报警不会自动使能**） |
| 控制气缸/夹爪 | 「轴卡 IO」，给**卡名**（不是 IP） |
| 停所有轴 | 「轴停止」的 `Axis` 留空 |
| 只跑仿真 | 用「虚拟运动卡」，可开故障注入开关 |

## 3.5 FAQ

**Q1** 为什么"下发成功"不等于"到位"？
运动是异步的。`Enqueue` 返回 `Accepted` 只代表"命令被收进队列了"。要等轴真的走到位，**必须再放一个「等待到位」步骤**——这不是设计缺陷，而是必然：产线上大量场景需要"两轴同时运动"，如果 Move 内部阻塞等到位，两条轴就只能串行跑（而且现场很难看出为什么慢了一倍）。

**Q2** 急停能打断正在执行的长命令吗？
**能**。命令线程是逐条执行的，若正在跑回零（几十秒），普通急停要等它跑完。本插件用**急停专用 CancellationTokenSource** 把"设备令牌"与"急停令牌"**链接**后交给驱动，所以能打断。
而且区分了两种取消语义：**被急停打断 = 预期行为**（不报故障、不进安全停机），**设备断开/流程停止 = 另一种取消**。

**Q3** 每次上电都要回零吗？
**增量式编码器必须**。掉电/断线后位置是"不知道在哪"，此时若允许绝对运动，卡会按错误的当前坐标算行程（**可能直接撞向限位**）。
绝对值编码器（`SupportsAbsoluteEncoder=true`）开箱即可信。

**Q4** 软件急停能替代硬件急停按钮吗？
**绝对不能**。真正的安全急停必须由**硬件回路**（急停按钮直接切伺服使能）保证，软件这条路只是补充。

**Q5** 读状态会占用通信吗？
不会。`GetAxisStatus` / `ReadInput` 一律读**轮询缓存**。而且一次执行里读到的所有字段来自**同一采样时刻**，互相自洽。

**Q6** 读不到状态时会给 0 位置吗？
**不会**。给"未知"而不是编一个 0——把未知当成 0 位置，下游可能据此做出错误判断（且看不出是猜的）。

**Q7** 轮询间隔该设多少？
默认 10ms（工业常见 5~20ms）。太小会占满通信带宽（网口卡尤其明显），太大则安全响应迟钝。

**Q8** 点动松手了会不会一直走？
不会。有**心跳兜底**：超过 500ms 没收到界面脉冲就自动停。关窗/切轴/切卡也会停。

## 3.6 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| `0x8007007E` / "找不到模块" | 缺 native SDK。**`zauxdll.dll` 与 `zmotion.dll` 都要有**；也可能是**位数不符**（32/64 位） |
| 目标超软限位被拒 | 检查 `SoftLimitMinMm/MaxMm`；门禁记为 Notice 级，设备仍可用 |
| 报警态拒绝运动 | 先「清报警」→ 再手动使能（**清报警不会自动使能**） |
| 回零超时 | 回零默认 120s（要先找开关再找 Index，慢是正常的）。超时会**先停轴**再报错 |
| 不支持的回零方式 | 能力协商不通过会**当场拒绝并列出该卡支持哪些** |
| 位置不对/行程差很多倍 | **`UnitsPerMm` 配错**，或驱动里多除了一次脉冲当量 |
| 回零朝反方向撞 | **`homemode` 数字填错**（只能来自手册） |
| 失联后位置不可信 | 看门狗会安全停机并把 `IsHomed` 归 false → **必须重新回零** |
| 界面卡顿/带宽打满 | 轮询间隔太小，或 IO 逐点读（应批量读） |
| 面板打开崩溃 | 曾因资源字典键重复 / `Run.Text` 默认 TwoWay 导致（均已修） |

## 4.2 P0/P1 级详解

### ① 急停打断不了正在执行的命令

**现象**：回零执行期间（几十秒）触发急停，急停**要等回零跑完才轮得到**。

**修法**：加**急停专用 CancellationTokenSource**，把"设备令牌"与"急停令牌"**链接**后交给驱动。同时区分两种取消语义：
- **被急停打断 = 预期行为**（不报故障、不进安全停机）
- **设备断开/流程停止 = 另一种取消**

### ② 完成信号早于副作用（冒烟偶发失败抓到）

**现象**：等待方被唤醒时读到"命令已完成、但 `IsHomed` 仍是 false"的中间态。

**原因**：`CompleteCommand`（置状态 + 发完成信号）先执行，`MarkHomed(true)` 后执行。

**修法**：**先落副作用，再发完成信号**。

### ③ StackOverflowException（改轴参数必崩）

**现象**：在「运动卡设置」里改轴参数**必崩**，且**无法捕获**（写复现测试会把测试进程本身杀掉，拿不到任何输出）。

**根因链**：
```
① 用户改参数 → MarkConfigDirty() → _configDirty = 1
…
⑦ ★ 此时 _configDirty 仍然是 1（RememberSynced 在后面，代码还没走到）→ 再进 SyncFromSolution → 回到 ④
```

**修法**：`Interlocked.CompareExchange(ref _syncing, 1, 0)` 重入守卫 + 把 `RememberSynced` 提到 `DevicesChanged` 之前。
并新增 **4 条静态断言**（因为 StackOverflowException 无法被捕获）。

### ④ `UnitsPerMm` 重复除（最隐蔽）

**现象**："看起来能跑"，只是行程全错——**极难在现场发现**。

**原因**：`SetUnits` 之后 Mpos 已经是用户单位（mm），又除了一次脉冲当量。除一次会让所有位置缩小到 `1/UnitsPerMm`，而且目标位置也会同样缩小。

**修法**（注释原文）：
> ```
> // SetUnits 之后 Mpos 已经是用户单位（mm）——**不要再除脉冲当量**。
> // 除一次会让所有位置缩小到 1/UnitsPerMm，而且目标位置也会同样缩小，
> // 于是"看起来能跑"，只是行程全错——这类错误极难在现场发现。
> ```

### ⑤ 缺 `zmotion.dll` 报 `0x8007007E`（SDK 双层依赖）

**现象**：报错是 `0x8007007E`（"找不到模块"），**看上去就像 `zauxdll.dll` 没放对位置**，极误导。

**原因**：正运动 SDK 是**双层依赖**——`zauxdll.dll` 依赖 `zmotion.dll`，缺后者时 Windows 给出的也是"找不到模块"。

**修法**：驱动自带诊断 `BuildMissingSdkMessage()` **逐个检查 native 文件并点名**；并单独点明**位数不符**（32/64 位同样报 0x7E）。

### ⑥ 资源字典键重复 → 启动即崩

**现象**：`DialogStatusDot` 键重复 → **整个程序启动即崩**。

**教训**：资源字典的键重复是**编译不报、加载即炸**。→ 新增主题键唯一性静态断言。

### ⑦ `Run.Text` 默认 TwoWay → 面板加载失败

**现象**：面板加载抛 `InvalidOperationException`。

**原因**：`Run.Text` 的默认绑定模式是 **TwoWay**（它是 FlowDocument 元素），而 VM 里这些状态属性是**只读**的。

**修法**：显式写 `Mode=OneWay`。新增断言钉死。

## 5.2 附录 B：实战案例（6 个）

### 案例 1｜上电标准顺序（增量式编码器必做）

```
[轴使能] → [轴回零] → [后续所有运动]
```
> 连上**不等于位置可信**。增量式编码器每次上电/断线重连后都必须回零，否则绝对运动会按错误坐标算行程（可能直接撞向限位）。

### 案例 2｜两轴同时运动（关键：都不等待）

```
[轴运动 X] → [轴运动 Y] → [等待到位 X] → [等待到位 Y]
```
> 若写成 `轴运动X → 等待X → 轴运动Y → 等待Y`，两轴就**串行**了，节拍翻倍且现场很难看出原因。

### 案例 3｜视觉引导抓取

```
[采集] → [模板匹配] → [C#脚本：手眼标定换算] → [轴运动.Target] → [等待到位] → [轴卡IO：夹爪]
```
> 目标位置是**输入端口**才能接上游——这是视觉引导能落地的前提。

### 案例 4｜急停（软件层补充，不是安全回路）

```
[轴停止] + UseEmergencyStop = true
→ 清空待执行命令 + 停全部轴 + 立即停
→ Axis 与 Mode 都被忽略
⚠️ 真正的安全急停必须由硬件回路（急停按钮直接切伺服使能）保证
```

### 案例 5｜失联恢复

```
看门狗：轮询连续失败 → 安全停机
→ IsHomed 归 false（增量式）
→ 重连后必须重新回零，才能按绝对坐标运动
```

### 案例 6｜虚拟卡故障注入回归

```
用 Plugin.Motion.Virtual，打开开关：
  SimulateAlarm          → 模拟伺服报警
  SimulatePollException  → 模拟轮询异常（触发看门狗）
  SimulateCommandFailure → 模拟命令失败
→ 无硬件也能验证安全路径（真卡上没法随便制造这些）
```

**`MotionZMotionChecks` 重点**：回零模式码映射（1/2/17/18/19/23/27/37 逐个钉死）；机型→能力（**未识别不猜**）；轴状态位域（Alm=8/Pot=10/Net=20/Inp=800/Emg=1000）；故障分级（**不逐码编造文案**）；部署（**`zauxdll.dll` 与 `zmotion.dll` 同时存在**）；点动端到端 + 心跳兜底（900ms 超时必停）；调试面板契约（**按住才动**、独立急停入口、`Run` 绑定 OneWay）。

## 5.5 附录 E：术语表

| 术语 | 含义 |
|---|---|
| 命令模式 | 运动 = 流程下发命令 → 卡执行 → 状态靠轮询（区别于相机的推模式） |
| **下发 ≠ 到位** | `Enqueue` 返回"收下了吗"，不是"动到位了"——**最经典的语义错误** |
| 逻辑轴名 | 流程唯一引用的轴标识（物理轴号可变，逻辑名不变） |
| `UnitsPerMm` | 脉冲当量（机械换算）。**配错=所有行程按错倍率走，必须先标定再上电** |
| `SetUnits` | 正运动驱动里设定用户单位（之后 API 一律 mm，**不要再除当量**） |
| 软限位 / 硬限位 | 软件层最后防线 / 卡上的硬件限位——**两层都要有** |
| 回零（Home） | 找机械原点。增量式编码器**每次上电/断线重连后必做** |
| `homemode` | 回零方式码——**只能来自手册**，填错会朝反方向撞 |
| 急停插队 | 急停不能排在普通命令后面——排队执行的急停不是急停 |
| 看门狗 | 轮询连续失败 → 安全停机（增量式同时 `IsHomed` 归 false） |
| 轮询快照 | 状态查询读缓存不发起通信——省带宽且字段自洽 |
| 点动心跳 | 500ms 没脉冲自动停——**安全不能建立在"事件一定送达"的假设上** |
| 一带多 | 一张卡带多轴，流程/面板都按逻辑名引用 |
| 故障注入 | 虚拟卡模拟报警/通信失败/增量编码器——**真卡上没法随便制造** |
| 毒记录 | （结果上报）累计失败上限的记录；运动里对应"不支持的回零方式入队即拒" |
