## 四类文档（分工，别混）

| 类 | 回答的问题 | 位置 | 怎么维护 |
|---|---|---|---|
| **参考类** | "现在该怎么用 / 是什么" | 各专题目录（插件、架构、基础设施…） | 人写，改动即更新；目录必须有 `README.md` 做地图 |
| **日志类** | "某天改了什么、为什么" | [`code-changes/`](code-changes/)、[`meetings/`](meetings/)、[`performance/`](performance/) | 只追加、不回改；`INDEX.md` 由脚本生成 |
| **决策类** | "为什么选这个方案" | [`方案设计/`](方案设计/) | 人写；方案变更时**追加新版本**，不覆盖旧版 |
| **归档类** | "历史留档，别再引用" | [`归档/`](归档/) | 只读，不更新 |

判定一个文件该放哪，只问一句：**它会被谁在什么时候读？**
"现在要照着做" → 参考类；"记录某天干了什么" → 日志类。

## 结构守门（不靠自觉，靠脚本）

| 脚本 | 守什么 | 什么时候跑 |
|---|---|---|
| [`tools/audit_docs.ps1`](../tools/audit_docs.ps1) | 顶层目录/根文件白名单、参考目录必须有 `README.md`、参考文档必须被某份 `README.md` 点名（孤儿检测） | 验收前；已接入 `run_gates.ps1` |
| [`tools/gen_docs_index.ps1`](../tools/gen_docs_index.ps1) | 为日志目录生成 `INDEX.md`（幂等，仅在内容变化时重写） | 加了日志条目就跑；`run_gates.ps1` 会**先跑一遍判红**（索引过期即失败） |
| [`tools/audit_root.ps1`](../tools/audit_root.ps1) | 仓库根目录白名单（`R166`） | 收尾入口 `run_gates.ps1` |

白名单唯一事实源：[`tools/docs-layout.json`](../tools/docs-layout.json)。
**新增 `docs/` 顶层目录或根级 `.md` 必须先登记**，否则审计判红。

```powershell
# 只审计出报告
powershell -NoProfile -ExecutionPolicy Bypass -File tools\audit_docs.ps1

# 加完日志条目后刷新索引
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gen_docs_index.ps1
```

## 三条写作约定

1. **频率决定厚度**：常被读的文档写全（主文档 600+ 行是正常的）；一年读一次的写结论即可。
2. **一个是事实源，其余是引用**：插件主文档是事实源，`README.md` 只做目录不抄内容；
   `AGENTS.md` 是判据事实源，`docs/工程纪律/` 只存"为什么"。
3. **新文档必须有入口**：写完在某个 `README.md` 里挂一行，否则 `audit_docs.ps1` 会把它报成孤儿
   —— 孤儿不是"文件不存在"，是"没人能找到它"。
