## 一、什么叫"对标商用组态"

商用组态软件（InTouch / WinCC / iFIX / 组态王）的能力面，剥掉品牌后是这七件事：

| 能力面 | 一句话判据 | 本项目现状 |
|---|---|---|
| 画面建模 | 多画面、多页、图元可分组可分层 | 🟢 多画面/多页/图层/锁定/成组均已落地（图层有独立停靠面板，图元锁定有右键菜单 + 属性面板双入口，成组走右键菜单二态项 + "点中一个组员即选中整组"） |
| 图元库 | 覆盖"操作 + 指示 + 流程符号"三类，可扩展 | 🟡 已 15 个图元（基础 3 + 操作 1 + 指示 3 + 数值 3 + 工艺 4 + 报警 1，按描述符 `Category` 归类）；余下 5 个 = `Hmi.GroupBox` / `Hmi.Frame` / `Hmi.CheckBox` / `Hmi.ComboBox` / `Hmi.CommandButton`——它们原先的依赖（S8 导航、S12 权限）**均已落地**，纯堆量，不阻塞交付 |
| 数据驱动 | 变量值变化 → 图元属性变化，这是组态的命 | 🟢 S6 运行态数据泵已落地（变量 → 图元属性 + 写变量动作；**压力验收已由 S13-b 的 60s 等价负载补上**，真机 8 小时长稳另计） |
| 事件与动作 | 点一下能触发一件事，且可配置 | 🟢 S5 已落地（图元级 Pressed/Released 真触发 + 属性面板事件分组 + 动作内联编辑）；S8 补 `Navigate`；**画面级 `Loaded`/`Unloaded` 的动作表也已可在界面直接编**（抽 `IScadaEventHost` 后与图元侧同一份实现，见[开发记录](code-changes/2026-09-21-SCADA画面级事件动作表.md)） |
| 报警与记录 | 报警产生/确认/恢复/历史/导出 | 🟢 S11 全部收口（a 领域层与引擎 / b 运行时接线含统一节拍源与按天滚动落盘 / c 报警条图元 + 历史面板 + CSV 导出 / d 断言，1115 断言 0 失败）；真机可见性复核归 S13 |
| 权限与审计 | 谁能操作、操作过什么 | 🟢 S12 全部收口（a 角色模型 / b 权限闸门 / c 账号与界面 / d 操作审计 / e 真机）；状态栏身份来自 `ScadaAccessPolicy.LoginStateText`，**写死的"开发者"字面量已移除**（`ScadaUserStore` 落 `ScadaUsers.json`，审计落 `Audit\Audit-yyyy-MM-dd.csv`）；唯一挂账是"系统参数变更不落审计"（见 §六） |
| 工程效率 | 撤销重做、对齐分布、复制粘贴、模板 | 🟢 **四项全齐**（S9 统一写入口 + 撤销重做、S10-b 对齐/分布、S10-d 成组、复制/粘贴/再制 + 模板库；模板落程序目录 `ScadaTemplates.json`，工具箱「我的模板」分组可搜可拖、右键改名/删除）；真机手势复核归 S13 |

**本路线图的第一优先级不是"图元数量"，而是把三件地基（数据驱动 / 统一写入口 / 报警）立起来。**
理由：图元库是线性堆量，地基没立就堆图元，等于在沙上盖楼——每加一个图元都要重写一遍
"变量怎么流进来、事件怎么发出去、改了怎么撤销"。（数据驱动 S6 ✅、统一写入口 S9 ✅、**报警 S11 ✅——三件地基已全部立起**，
后续阶段是在地基上堆量：S7 图元、S12 权限、S13 交付。）

## 二、三条地基纪律（贯穿所有阶段，不许破）

### D1 依赖单向，领域层零 WPF

```
Core（变量/序列化/插件契约）
  ▲
Scada（画面领域层：Document / Page / Element / Binding / Runtime / EventType）
  ▲
Scada.Controls（图元控件库：Descriptor / Canvas / Element 控件）
  ▲
VisionMaster（WPF 应用：ViewModel / View / Service 宿主）
```

**为什么**：产品规则（该显示哪一页、Loaded 该不该发、绑定按 Id 还是按名寻址）必须能被
无界面的检查（`ScadaChecks`）钉住。一旦规则写进 WPF 类，每次改动都得开界面点一遍，
测试成本立刻高一个数量级；将来接报表、无人值守、多屏运行时，同一套规则没法复用。

S4 的 `ScadaRuntime` 就是这条纪律的样板：它只交出"该显示哪一页"这个事实，
"什么时候真画出来了"由 WPF 侧的宿主补（见 `ScadaRuntimeHost` 类注释）。

### D2 元数据驱动，描述符是唯一真相

`ElementDescriptor` 声明一个图元的：类型键、分类、默认尺寸、属性表、支持的变量类型、
**支持的事件清单**。工具箱、属性面板、序列化、画布渲染、事件分发**全部从描述符派生**，
任何一处都不许写 `if (typeKey == "Hmi.Button")`。

**为什么**：写死一处判断，第三方扩展图元就要改主程序源码。属性面板那条
"面板里没有一行属性是写死的"（S3-d）就是这条纪律的成果，必须守住。

### D3 写模型只有一个入口

**当前状态：未落地，只有接缝。** 现在改一个图元的 X 坐标，路径是
`ScadaElement.X` 的属性 setter 直接写。这带来两个已经存在的症状：

- 撤销/重做做不了（没有统一的变更记录点）；
- 脏标记靠 `PropertyChanged` 冒泡拼凑，`ScadaPage.Version` 的语义只能靠约定维持
  （S4 里"绑定内容变了要往上冒"那条注释就是补丁之一）。

S9 专门收这笔债。**在 S9 之前，任何新增的"改模型"代码都必须走 `page.Try*` 家族**，
不许再开新的直接 setter 路径，否则 S9 的改造面会持续扩大。

## 四、各阶段展开

### S5 事件 → 动作分发

**目标**：把"事件钩子"从词表变成通路。点按钮真的能引发一件事。

**交付物**
- 图元控件自己发 `Pressed` / `Released`（按钮、指示灯这类可操作图元）；
  `ValueChanged` 由 S6 的数据泵在属性写入处发。
- 事件配置落盘：`ScadaElement.Actions`（`List<ScadaAction>`），
  每条 = 触发事件 + 动作类型 + 参数。落盘格式沿用 `.vms`，动作类型是新枚举，
  **数值发布后不许改**（与 `ScadaEventType` 同一条规矩）。
- `IScadaActionDispatcher`：领域层定义接口，WPF 侧实现。分发器只认"事件 + 动作"，
  不认是哪个图元发的。
- 本版动作类型三种，**都不接流程引擎**（用户明确要求）：
  `Log`（记一行运行日志）、`WriteVariable`（往变量写值）、`Navigate`（切画面，S8 才实现，先留枚举位）。
- 属性面板"事件"分组：从描述符的 `Events` 清单渲染，不写死。
- 动作**内联编辑**（不弹窗）：勾上事件后原地长出动作表，支持增 / 删 / 选类型 / 改文案 / ↑↓ 调序。
  `WriteVariable` 的变量选择器与 `Navigate` 的目标画面选择器**不在本阶段**，
  这两类动作先显示一行橙色"还没接通"说明（该说明与运行日志共用领域层同一句话）。

**验收**：真机点运行画面的按钮 → 日志出现一行；不勾事件 → 一行都没有。
断言覆盖"事件关闭即不触发""未声明的事件类型配了也不发"。
面板侧另验"勾选内联展开、增删调序真的改到模型、未接通提示与日志逐字一致"。

**明确不做**：脚本动作、条件动作、动作链。

### S6 运行态数据泵 ★ 本路线图最关键的一段

**目标**：变量值变化 → 图元属性变化。没有这一条，做出来的只是"会动的图片"，不是组态。

**现状（必须先认清）**：`ScadaBinding` 有 `VariableId` / `VariableName` / `TargetProperty` /
`Format` / `IsEnabled`，`ScadaElement` 有整套订阅机制——但那些订阅**只服务于脏标记冒泡**。
全仓搜索确认：没有任何一处从 `IVariableRegistry` 取值写回图元属性。

**S5 留给本阶段的欠债（已还清）**：`ScadaActionType.WriteVariable` 已能配置、能落盘，
面板上的**变量选择器**（`IScadaVariablePicker` + `ScadaVariablePickerView`）与执行侧的
`ExecuteWriteVariable` 已一并补齐。选择器与 `IScadaValueSource` 共用同一套寻址知识，
所以「选得到就一定写得到」，两处口径没有分叉。

**交付物**
- `IScadaValueSource`（领域层）：按 `VariableId` 读当前值 + 订阅变化。
  适配到既有 `IVariableRegistry`。**绑定按 Id 寻址、名字只做展示与旧数据兜底**——
  这条是 S0/S1 就定下的，不许回退。
- `ScadaRuntimeBinder`（WPF 侧）：**首帧之后、跑 `Loaded` 动作之前**按
  `page.EnumerateBindings()` 建表（挂在宿主既有的 `OnFirstFrameRendered` 上；控件要到布局
  阶段才被造出来，早于此建表会一条都命中不了），
  `Stop()` 时**必须全量摘干净**（运行态泄漏是现场最难查的一类，因为要跑几小时才看出来）。
- 线程边界：轮询在后台线程，写 `DependencyProperty` 必须回 UI 线程。
  用 `Dispatcher.BeginInvoke` + **合并/节流**（同一帧内多次变化只写最后一次），
  否则 1000 个绑定 × 100ms 轮询会把 UI 打成筛子。
- 值 → 属性的转换：`IConvertible` 路径 + `Format` 串 + 枚举/布尔映射（指示灯的
  "值=1 变绿"这类）；转换失败要**可见**（图元右上角一个红点 + 悬停看原因 + 日志留一行），不许静默。
- 写变量（S6-6）：`IScadaVariablePicker` + `ScadaVariablePickerView`（组态侧选变量）
  → `ScadaActionDispatcher.ExecuteWriteVariable`（运行侧写变量）。四档失败各自交代：
  没选变量 / 找不到变量 / 值转不过 / 写不进。
- 图元属性反向写（输入框改值 → 变量）：**本版不做**，留待 S9 统一写入口。

**验收**
- 断言：绑定命中/未命中、Id 优先于名字、禁用绑定不刷新、摘表后无残留订阅。→ ✅ 全绿（`ScadaChecks` `[Z]` 段）
- 真机（已做，2026-09-18）：注入 5 条绑定（3 好 2 坏）+ 7 条动作，逐行验证建表时机、
  计数口径、诊断四档、动作四档、停止路径。证据见 `docs/code-changes/2026-09-18-SCADA运行态数据泵.md`。
- 真机（**未做，S6 唯一未闭合项**）：1920×1080 画面挂 200 个绑定，接模拟变量以 20ms 周期跳变，
  跑 60s，UI 不卡、内存不涨、停止后句柄与订阅归零。→ 归入 S13 性能基线，或在 S7 之前单独补做。

**明确不做**：历史值、趋势曲线（那是 S11 之后的事）。

### S8 多画面导航与运行中切页

**目标**：运行态能在画面之间走，且走得干净。

- `Navigate` 动作落地（S5 已留枚举位）；`ScadaRuntime` 加 `Navigate(pageId)` / `GoBack()`。
- 切页时 `Unloaded`（旧页）→ `Loaded`（新页）的顺序与幂等：连点两下不能触发两次 Loaded。
- 页栈深度与回退；`Frame` 图元（画面套画面）复用同一套规则。
- 切页时**旧页的绑定必须全摘、新页的绑定再建**（与 S6 的 binder 同一处收口）。

**验收**
- 断言：页栈深度与回退、`Unloaded → Loaded` 顺序、**`Loaded` 只触发一次**（连点两下 / 目标即当前页）、
  切页后旧页绑定摘净、出口接缝（挂上真转发 / 原因原样透传 / 摘掉后「运行已经结束」）。→ ✅ 全绿
  （`ScadaChecks` `[W]`/`[Y]`/`①E`/`[AC]` 段，783 断言 0 失败）。
- 弹窗渲染证据图 `artifacts\scada-page-picker.png` → ✅ 已人眼复核（四列对齐 / 选中态 / 起点徽标）。
- 真机（**未做**）：三页互切 + 返回，日志顺序正确。→ 待用 `Invoke-CimMethod Win32_Process Create`
  脱离终端启动后人工核。
- 证据与决策见 `docs/code-changes/2026-09-19-SCADA运行中切页.md`。

**明确不做**：`Hmi.Frame`（画面套画面）本版未实现；`GoBack` 无 UI 入口（真实工程多靠"返回"图元显式配 `Navigate`）。

### S9 D3 统一写入口 + 撤销/重做

**目标**：把"改模型"收敛成一个入口，然后撤销只是这个入口的副产品。

- `IScadaChangeScope`：所有编辑器写操作走 `using (page.BeginEdit("移动图元")) { ... }`，

  运行时（数据泵）使用**，编辑器路径一律禁止——这条要用断言钉住，不能只靠约定。
- 批量操作（多选拖动、对齐、删除）必须是**一次撤销**，不能十步回退。

**目标**：把 S3-e2 已经做好的领域能力暴露到界面。

  "当前选中的图元"，是动作而不是属性值，右键是它们天然的入口）。本条补的是"图层自己的增删改名/显隐/锁定"

- 图元对齐/分布/成组/锁定；多选框选。
- 顺序与图层的语义要一次讲清：本项目定的是**图层是"分组开关"，不是"深度容器"**
  （见 S3-e2 记录），UI 不能反过来暗示"图层决定叠放次序"。

**落地（三个子轮）**
- **S10-a 图层面板**：右侧新增「图层」停靠面板（240 宽，排在属性栏右侧、工具箱左侧）。行是**不可变快照**
  `ScadaLayerItem`（不是把 `ScadaLayer` 直接绑到行上——`ElementCount`/`CanRemove`/`CanMoveUp`/`ContainsSelection`
  全是画面级算出来的量，图层对象上根本没有）。刷新只订阅 `ScadaPage.Version` 一条；`ItemsEqual` 值比较挡刷
  （拖动会逐帧抬 `Version`，不挡就是每秒几十次重建行容器）。显隐/锁定走 `using (layer.BeginEdit(...))`——
  一次点按 = 一条撤销位，`Label` 就是撤销按钮的提示。底部固定一句「图层顺序不改变图元叠放」防误判。
- **S10-b 多选 / 对齐分布 / 批量删除**：画布多选（Ctrl 加选 + 橡皮筋框选，相交即入选、看不见的不入选）、
  整批拖动、整批删除；右键菜单新增「对齐与分布」八项（`ScadaAlign`：6 对齐 + 2 分布，**不拆两个枚举**——
  对用户是同一件事）。对齐基准是**整组包围盒**；分布是**等间隙**（不是等中心距，图元宽度不一时后者看着仍是乱的）、
  两端原地不动。锁定项**既不参与也不作为基准**（与拖动/删除口径一致）。一次排列 = 一条撤销位。
- **S10-c 图元锁定**：`IsLocked` 是图元的**编辑保护位**（刻意不进描述符、不占属性面板的属性行）。
  唯一写入口 `ScadaPage.TrySetElementLocked`——**刻意不按 `IsElementEditable` 过滤**（解锁的目标恰恰是已锁定的，
  照抄那个过滤会让解锁变成永远的空操作）。VM 侧过滤分两套：`CollectPresent`（锁定用）/ `CollectEditable`
  （删除/对齐用），共用 `CollectTargets(page, editableOnly)` 一个漏斗。入口三处：右键菜单二态项
  （标题/图标跟主选中走，判灰只看"有没有选中"——整批已锁时那一项必须仍亮着，解锁恰是此刻唯一该亮的动作）、
  属性面板顶栏复选框（借 `_editor.SetSelectedLocked` 走同一条已被钉住的路径）、画布选中视觉。
- **S10-d 图元成组**：`GroupId` 是图元的**编辑期分组关系**（`Guid`，`Guid.Empty` = 未分组，**刻意不进描述符**——
  与 `IsLocked` 同一判断：描述符描述的是"图元自己的样子"，不是"它和别人什么关系"）。唯一写入口
  `ScadaPage.TryGroupElements` / `TryUngroupElements`，共用私有漏斗 `FilterPresent`。三条关键取舍：
  **① 不带名字、不嵌套**（两组再组合 = 合并成一个新组，不套一层）；**② 成员删剩一个不做清理**
  （清掉 `GroupId` 会让"撤销删除"回不到原组——宁可留一个只有一员的组，也不要在删除路径上顺手改数据）；
  **③ 与 `LayerId` 正交**（分层管渲染、成组管编辑，**同组图元可跨图层**）。
  交互上最要紧的一条是**"选中即整组"**：点中一个组员 = 选中整组，且**被点中的那个排首位**
  （否则"点的是 B、属性面板显示 A"）。展开点**只做在点选路径上**（`OnSelectedElementChanged` 换整份选中
  + 左键换整份选中 + 左键 Ctrl/Shift 加选，共三处），**`SetSelection` 与 `SelectedElements` setter 都不展开**——
  框选的语义是"框住谁就是谁"，在集合入口里展开会让用户**再也没法用框选只挑出组里的一个**。
  菜单侧与锁定同形：一条 `GroupElementCommand` 管两向（标题/图标跟主选中走，图标跟动作不跟状态），
  插在"锁定/解锁"与"删除"之间（末位留给唯一不可逆的那一项）；`CanToggleSelectedGroup` 与
  `ToggleSelectedGroup` 是**同一个三元表达式**，杜绝"亮着但点了没反应"。

**S10-c 画布视觉（s10c-4）的验收方式说明**
锁定图元的选中视觉定为**整圈换色（金 `#E3A51B`）+ 右上角锁角标**——锁定的直接表现是"拖不动"，
而"拖不动"是一次**没有反馈的失败**，用户会以为软件卡了。换色第一眼可见并天然解释"为什么"
（蓝=可编辑、金=受保护），角标把答案说出口。金色**刻意避开**诊断层的警示橙 `#E88B1A`
（那个橙的意思是"没接变量"，同色会互相冒充）。

`InternalsVisibleTo` 也救不了（角标永远是 `Collapsed`）。**只能真机复核**，清单见记录 §4。

**明确不做 / 已知边界**
- **组没有名字、不支持嵌套**（S10-d）：两组再组合 = 合并成一个新组（组里没被选中的成员留在原组）。
  组名要到"组模板/复用"那一步才有意义，那是另一个功能。
- **成员删剩一个 / 指向不存在的组不做清理**（S10-d）：会留下"只有一员的组"与悬空 `GroupId`。
  这是为了保住"撤销删除能回到原组"——判据侧（`GetGroupMembers`）对此天然免疫。
- **组合不筛锁定图元**（与对齐/分布**反着**）：成组是"改关系"，锁定保护的是"位置/尺寸不被改"，
  不是"不许被组织"。混锁的组被整组拖动时，锁定的成员原地不动、其余照走。
- **单击=选中整组 / 框选=只选中框住的**（S10-d 的刻意不对称）：框选是"只挑出组里一个"的唯一手段，
  故展开只做在点选路径上，不进 `SetSelection`。真机须确认不造成困惑。
- **组不参与运行态**：与 `IsLocked` 同——运行态 `IsReadOnly = true`，点选本来就不给编辑。
- 图层排序只有行内上移/下移，**没有拖拽调序**（领域层 `TryMoveLayer` 已支持任意目标位次，将来加不用改领域层）。
- 删除仅限**空层**（`CanRemoveLayer` 要求空层 + 画面还剩别的层），防误删但"灰着的垃圾桶"对新手是一次解释成本。
- 批量改图层归属**不支持**：多选时「图层」子菜单只有主选中那一个会变（菜单打勾只能表达一个归属）。
- 对齐/分布只作用于可编辑图元，锁定项跳过；全部锁死时返回 false 且**不产撤销记录**。
- **图层锁与图元锁共用一个视觉**（都是金框 + 锁角标），用户无法从视觉上区分是哪一层锁的。刻意合并
  （对用户来说都是"拖不动"），若现场反馈"不知道该去解锁哪一层"再考虑分色。
- 锁角标与 `ScadaDiagnosticOverlay` 的角标**都在右上角**（诊断 `HitSize = 14`），且诊断层压在选中层之上——
  真机须确认是否重叠，重叠需错开。**这是 s10c-4 头号待核项。**

### S12 权限与运行审计

**目标**：操作员只能干操作员该干的事。

- 现状：`Shell.xaml` 里"开发者"是**写死的字面量**，没有任何用户系统。

**"机制断言"这条路的边界（写清楚，免得被当成万能替代）**

- **能证的**：数据通路——写入口、撤销链、守卫（`Strict`）、判灰口径、文案。
- **证不了的**：手势与像素——鼠标拖拽、点击热区、真实热键、字体渲染、DPI 实际换算。
- **判据**：只要"真机要验的行为"与"断言里驱动的命令"**落在同一段代码**上，机制断言就是等价证据；
  一旦某条行为在真机上有**独立代码路径**，机制断言只能算旁证，必须在上表写明残余风险。
