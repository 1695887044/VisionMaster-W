# SCADA 商业级交付路线图（S0 → S13）

> 定稿：2026-09-18。S0～S4 的状态由**断言 + 真机操作**双证支撑，不是"看代码觉得做完了"；
> S5 之后是计划，允许在开工前按现场反馈调整顺序，但**不许调整每阶段的验收口径**。
> 各阶段的实现细节见 `docs/code-changes/` 里同名的开发记录。

---

## 一、什么叫"对标商用组态"

商用组态软件（InTouch / WinCC / iFIX / 组态王）的能力面，剥掉品牌后是这七件事：

| 能力面 | 一句话判据 | 本项目现状 |
|---|---|---|
| 画面建模 | 多画面、多页、图元可分组可分层 | 🟡 单画面多页已有，图层无 UI |
| 图元库 | 覆盖"操作 + 指示 + 流程符号"三类，可扩展 | 🟡 只有 5 个基础图元 |
| 数据驱动 | 变量值变化 → 图元属性变化，这是组态的命 | 🔴 **完全没做** |
| 事件与动作 | 点一下能触发一件事，且可配置 | 🟡 词表立住，只有画面 Loaded 真触发 |
| 报警与记录 | 报警产生/确认/恢复/历史/导出 | 🔴 无 |
| 权限与审计 | 谁能操作、操作过什么 | 🔴 状态栏"开发者"是写死的字面量 |
| 工程效率 | 撤销重做、对齐分布、复制粘贴、模板 | 🔴 无统一写入口，撤销做不了 |

**本路线图的第一优先级不是"图元数量"，而是把 🔴 的三件地基（数据驱动 / 统一写入口 / 报警）立起来。**
理由：图元库是线性堆量，地基没立就堆图元，等于在沙上盖楼——每加一个图元都要重写一遍
"变量怎么流进来、事件怎么发出去、改了怎么撤销"。

## 二、三条地基纪律（贯穿所有阶段，不许破）

### D1 依赖单向，领域层零 WPF

```
Core（变量/序列化/插件契约）
  ▲
Scada（画面领域层：Document / Page / Element / Binding / Runtime / EventType）
  ▲
Scada.Controls（图元控件库：Descriptor / Canvas / Element 控件）
  ▲
VisionMaster（WPF 应用：ViewModel / View / Service 宿主）
```

**为什么**：产品规则（该显示哪一页、Loaded 该不该发、绑定按 Id 还是按名寻址）必须能被
无界面的检查（`ScadaChecks`）钉住。一旦规则写进 WPF 类，每次改动都得开界面点一遍，
测试成本立刻高一个数量级；将来接报表、无人值守、多屏运行时，同一套规则没法复用。

S4 的 `ScadaRuntime` 就是这条纪律的样板：它只交出"该显示哪一页"这个事实，
"什么时候真画出来了"由 WPF 侧的宿主补（见 `ScadaRuntimeHost` 类注释）。

### D2 元数据驱动，描述符是唯一真相

`ElementDescriptor` 声明一个图元的：类型键、分类、默认尺寸、属性表、支持的变量类型、
**支持的事件清单**。工具箱、属性面板、序列化、画布渲染、事件分发**全部从描述符派生**，
任何一处都不许写 `if (typeKey == "Hmi.Button")`。

**为什么**：写死一处判断，第三方扩展图元就要改主程序源码。属性面板那条
"面板里没有一行属性是写死的"（S3-d）就是这条纪律的成果，必须守住。

### D3 写模型只有一个入口

**当前状态：未落地，只有接缝。** 现在改一个图元的 X 坐标，路径是
`ScadaElement.X` 的属性 setter 直接写。这带来两个已经存在的症状：

- 撤销/重做做不了（没有统一的变更记录点）；
- 脏标记靠 `PropertyChanged` 冒泡拼凑，`ScadaPage.Version` 的语义只能靠约定维持
  （S4 里"绑定内容变了要往上冒"那条注释就是补丁之一）。

S9 专门收这笔债。**在 S9 之前，任何新增的"改模型"代码都必须走 `page.Try*` 家族**，
不许再开新的直接 setter 路径，否则 S9 的改造面会持续扩大。

## 四、各阶段展开

### S5 事件 → 动作分发

**目标**：把"事件钩子"从词表变成通路。点按钮真的能引发一件事。

**交付物**
- 图元控件自己发 `Pressed` / `Released`（按钮、指示灯这类可操作图元）；
  `ValueChanged` 由 S6 的数据泵在属性写入处发。
- 事件配置落盘：`ScadaElement.Actions`（`List<ScadaAction>`），
  每条 = 触发事件 + 动作类型 + 参数。落盘格式沿用 `.vms`，动作类型是新枚举，
  **数值发布后不许改**（与 `ScadaEventType` 同一条规矩）。
- `IScadaActionDispatcher`：领域层定义接口，WPF 侧实现。分发器只认"事件 + 动作"，
  不认是哪个图元发的。
- 本版动作类型三种，**都不接流程引擎**（用户明确要求）：
  `Log`（记一行运行日志）、`WriteVariable`（往变量写值）、`Navigate`（切画面，S8 才实现，先留枚举位）。
- 属性面板"事件"分组：从描述符的 `Events` 清单渲染，不写死。
- 动作**内联编辑**（不弹窗）：勾上事件后原地长出动作表，支持增 / 删 / 选类型 / 改文案 / ↑↓ 调序。
  `WriteVariable` 的变量选择器与 `Navigate` 的目标画面选择器**不在本阶段**，
  这两类动作先显示一行橙色"还没接通"说明（该说明与运行日志共用领域层同一句话）。

**验收**：真机点运行画面的按钮 → 日志出现一行；不勾事件 → 一行都没有。
断言覆盖"事件关闭即不触发""未声明的事件类型配了也不发"。
面板侧另验"勾选内联展开、增删调序真的改到模型、未接通提示与日志逐字一致"。

**明确不做**：脚本动作、条件动作、动作链。

---

### S6 运行态数据泵 ★ 本路线图最关键的一段

**目标**：变量值变化 → 图元属性变化。没有这一条，做出来的只是"会动的图片"，不是组态。

**现状（必须先认清）**：`ScadaBinding` 有 `VariableId` / `VariableName` / `TargetProperty` /
`Format` / `IsEnabled`，`ScadaElement` 有整套订阅机制——但那些订阅**只服务于脏标记冒泡**。
全仓搜索确认：没有任何一处从 `IVariableRegistry` 取值写回图元属性。

**S5 留给本阶段的欠债（已还清）**：`ScadaActionType.WriteVariable` 已能配置、能落盘，
面板上的**变量选择器**（`IScadaVariablePicker` + `ScadaVariablePickerView`）与执行侧的
`ExecuteWriteVariable` 已一并补齐。选择器与 `IScadaValueSource` 共用同一套寻址知识，
所以「选得到就一定写得到」，两处口径没有分叉。

**交付物**
- `IScadaValueSource`（领域层）：按 `VariableId` 读当前值 + 订阅变化。
  适配到既有 `IVariableRegistry`。**绑定按 Id 寻址、名字只做展示与旧数据兜底**——
  这条是 S0/S1 就定下的，不许回退。
- `ScadaRuntimeBinder`（WPF 侧）：**首帧之后、跑 `Loaded` 动作之前**按
  `page.EnumerateBindings()` 建表（挂在宿主既有的 `OnFirstFrameRendered` 上；控件要到布局
  阶段才被造出来，早于此建表会一条都命中不了），
  `Stop()` 时**必须全量摘干净**（运行态泄漏是现场最难查的一类，因为要跑几小时才看出来）。
- 线程边界：轮询在后台线程，写 `DependencyProperty` 必须回 UI 线程。
  用 `Dispatcher.BeginInvoke` + **合并/节流**（同一帧内多次变化只写最后一次），
  否则 1000 个绑定 × 100ms 轮询会把 UI 打成筛子。
- 值 → 属性的转换：`IConvertible` 路径 + `Format` 串 + 枚举/布尔映射（指示灯的
  "值=1 变绿"这类）；转换失败要**可见**（图元右上角一个红点 + 悬停看原因 + 日志留一行），不许静默。
- 写变量（S6-6）：`IScadaVariablePicker` + `ScadaVariablePickerView`（组态侧选变量）
  → `ScadaActionDispatcher.ExecuteWriteVariable`（运行侧写变量）。四档失败各自交代：
  没选变量 / 找不到变量 / 值转不过 / 写不进。
- 图元属性反向写（输入框改值 → 变量）：**本版不做**，留待 S9 统一写入口。

**验收**
- 断言：绑定命中/未命中、Id 优先于名字、禁用绑定不刷新、摘表后无残留订阅。→ ✅ 全绿（`ScadaChecks` `[Z]` 段）
- 真机（已做，2026-09-18）：注入 5 条绑定（3 好 2 坏）+ 7 条动作，逐行验证建表时机、
  计数口径、诊断四档、动作四档、停止路径。证据见 `docs/code-changes/2026-09-18-SCADA运行态数据泵.md`。
- 真机（**未做，S6 唯一未闭合项**）：1920×1080 画面挂 200 个绑定，接模拟变量以 20ms 周期跳变，
  跑 60s，UI 不卡、内存不涨、停止后句柄与订阅归零。→ 归入 S13 性能基线，或在 S7 之前单独补做。

**明确不做**：历史值、趋势曲线（那是 S11 之后的事）。

### S7 图元库扩充

**目标**：补齐"操作 / 指示 / 流程符号"三类，让工程师画得出真实产线画面。

| 分类 | 新增图元 |
|---|---|
| 数值 | `Hmi.IOField`（输入/输出框）、`Hmi.ProgressBar`、`Hmi.Gauge`（表盘） |
| 指示 | `Hmi.Lamp`（多态灯）、`Hmi.AlarmBanner`（报警条，依赖 S11）、`Hmi.Clock` |
| 流程符号 | `Hmi.Valve`（开关阀/调节阀）、`Hmi.Pump`、`Hmi.Motor`、`Hmi.Pipe`（带流向） |
| 容器 | `Hmi.GroupBox`、`Hmi.Frame`（画面套画面，依赖 S8） |
| 操作 | `Hmi.CheckBox`、`Hmi.ComboBox`、`Hmi.CommandButton`（带权限，依赖 S12） |

**每个图元必须一次交付完整**：描述符（含属性表 + 事件清单 + 可绑变量类型）、
控件、模板、默认值、`.vms` 往返断言、工具箱分类。**不许出现"先画出来，属性以后补"**——
那会直接破坏 D2。

**验收**：`ElementRegistry` 断言覆盖每一个类型键；新增图元不改主程序一行 `if`。

### S8 多画面导航与运行中切页

**目标**：运行态能在画面之间走，且走得干净。

- `Navigate` 动作落地（S5 已留枚举位）；`ScadaRuntime` 加 `Navigate(pageId)` / `GoBack()`。
- 切页时 `Unloaded`（旧页）→ `Loaded`（新页）的顺序与幂等：连点两下不能触发两次 Loaded。
- 页栈深度与回退；`Frame` 图元（画面套画面）复用同一套规则。
- 切页时**旧页的绑定必须全摘、新页的绑定再建**（与 S6 的 binder 同一处收口）。

**验收**：真机三页互切 + 返回，日志顺序正确；断言覆盖"Loaded 只触发一次"这条承诺。

---

### S9 D3 统一写入口 + 撤销/重做

**目标**：把"改模型"收敛成一个入口，然后撤销只是这个入口的副产品。

- `IScadaChangeScope`：所有编辑器写操作走 `using (page.BeginEdit("移动图元")) { ... }`，
  作用域结束时产出一条变更记录。
- 命令栈（撤销/重做）+ 与 `page.Version` 脏标记打通；直接 setter 在 S9 后**只允许
  运行时（数据泵）使用**，编辑器路径一律禁止——这条要用断言钉住，不能只靠约定。
- 批量操作（多选拖动、对齐、删除）必须是**一次撤销**，不能十步回退。

**验收**：拖 10 个图元 → Ctrl+Z 一次全部回去；撤销后重做，版本号与磁盘内容一致。

---

### S10 图层面板 UI + 编辑效率

**目标**：把 S3-e2 已经做好的领域能力暴露到界面。

- 图层面板：列表 + 显隐（👁）+ 上移/下移 + 新建/重命名/删除，全部接 `ScadaPage.Try*` 家族
  （`TryAssignLayer` 目前除断言外**没有任何 UI 入口**）。
- 图元对齐/分布/成组/锁定；多选框选。
- 顺序与图层的语义要一次讲清：本项目定的是**图层是"分组开关"，不是"深度容器"**
  （见 S3-e2 记录），UI 不能反过来暗示"图层决定叠放次序"。

---

### S11 报警系统

**目标**：组态软件真正的价值出口——出问题要喊人。

- 报警源：变量越限（高/高高/低/低低）、布尔跳变、通信断线。
- 报警态机：正常 → 激活 → 确认 → 恢复，四态与时间戳。
- 实时报警条图元 + 报警历史查询面板 + CSV 导出（可复用既有 Excel 报表插件的导出通路）。
- 报警记录落盘与保留策略（按天滚动，现场要能查三个月前）。

**依赖**：S6（报警本质是"绑定值 → 状态判定"）。

---

### S12 权限与运行审计

**目标**：操作员只能干操作员该干的事。

- 现状：`Shell.xaml` 里"开发者"是**写死的字面量**，没有任何用户系统。
- `IScadaAccessPolicy`：图元级 `RequiredRole`（描述符声明，面板渲染，分发器执行）。
- 登录/登出、超时锁屏、操作记录落盘（谁在什么时候按了哪个按钮、值从多少改到多少）。

**注意**：权限必须在**动作执行处**校验，不能只靠"没权限就不渲染"——
界面隐藏挡不住直接调接口。

---

### S13 性能基线、稳定性与交付

- `ScadaChecks --stress` 基线固化：图元数、绑定数、切页次数、报警数四组规模，
  每次改动跑一遍并留档，**回归时看数字不看感觉**。
- 长稳：运行态 8 小时，句柄/内存/订阅数曲线必须平。
- 多显示器：运行窗口能指定落到哪块屏（现场常见"副屏只给操作员看画面"）。
- 打包：安装、升级、方案文件迁移、异常退出后的现场恢复。

## 五、每阶段的验收口径（不许打折）

一个阶段只有同时满足这四条才算完成：

1. **构建 0 错误**（`VisionMaster` + `ScadaChecks`）。
2. **`ScadaChecks` 全绿**，且本阶段新增的能力**必须有对应断言**；
   渲染类问题一律用像素采样断言（S4 的 `[X]` 组是样板），不接受"我看截图是对的"。
3. **真机验证**：启动 `VisionMaster.exe`，用界面实际操作走一遍本阶段的主路径并留截图。
   注意启动纪律——GUI 必须用 `Invoke-CimMethod Win32_Process Create` 脱离终端启动。
4. **开发记录**落 `docs/code-changes/YYYY-MM-DD-主题.md`：需求与决策、修改文件清单、
   验证结果、**已知边界**（欠债必须写，下一阶段的输入就是上一阶段的欠债清单）。
