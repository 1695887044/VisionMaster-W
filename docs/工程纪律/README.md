## 为什么拆成三层（2026-10-22）

原文 177,585 字节，而工作区指令注入预算是 65,536 字节。实测注入被截断到 65,140 字节，
截断点在 §18 开头——**§18-§37（R58-R174，约 115 条规则）从未进入过任何会话的上下文**。
规则写了、以为生效、实际没生效、且不报错，属本仓库最忌讳的静默故障。

拆分口径：

- **注入层**只回答"我现在这么做对不对"：判据、阈值、守门人（哪条断言会红）、触发条件。
- **分册**回答"这个域还有哪些约束"：单域低频规则，注入层只留"最易踩 + 指针"。
- **归档层**回答"当初为什么这么定"：事故现象、异常栈、反编译证据、复现步骤、逐项台账。

2026-10-22 第二轮：注入层从 61,886 压到 **49,314 字节**（-20%），把 §23/§27/§28/§31/§32/§34/§35 共 7 节下沉成两个分册。**下沉不删判据**——每节的正文一字未改，只是搬了位置；注入层保留该节标题、三条"最易踩"与指针。校验方式：脚本按二级标题字节级切分，切完比对"注入层 + 分册"的规则编号并集 = 182（R1-R174 + R132A + R175-R181），无缺失无多余。

## 怎么用

1. 要改代码/改界面/改配置前，先查 `AGENTS.md` 对应章节，按判据自检。
2. 章节标题带"→ 分册《…》"的，动手前读那份分册。
3. 判据看不懂、或想知道"这条是怎么来的、改坏了会怎样"，查归档同名章节。
4. 归档里的行号、数字快照（如"10 个探针""1458 处引用"）是**当时**的实测值，不可当现状引用。

## 维护约定

- **新增规则加进 `AGENTS.md`**（编号顺延），必须带判据与守门人；确实没有自动闸的写"人工评审"。
- 加完核对字节数：`(Get-Item AGENTS.md).Length` 必须 **< 56000**。
- **满了就下沉，不压缩既有判据**：把低频单域整节搬进 `docs/工程纪律/分册-<域>.md`，注入层留标题 + 三条最易踩 + 指针。切分用脚本按 `^## N.` 字节级搬移，搬完必须校验编号并集不丢。
- 起因、复盘、取证过程写 `docs/code-changes/`，不要写回 `AGENTS.md`。
- 归档文件**只读**：不再更新。口径变更只在 `AGENTS.md` 里改，并在此 README 记一句变更摘要。
