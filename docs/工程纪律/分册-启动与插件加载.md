# 工程纪律分册 · 启动与插件加载

> 本册是 `AGENTS.md` §15 / §17 / §24 / §25 的**完整判据**（R48-R50 自检超时、R57 启动关键路径、R78-R80 启动插桩与提速、R81-R83 插件清单缓存）；注入层只留指针与「最易踩」。
> 触发条件：改 `AppLifetimeService`/启动链/任何 `IStartupCheck` 实现、动启动插桩或插件扫描性能、改插件清单缓存（`PluginCatalog` 一类）。
> 起因与取证见 `2026-10-22-工程纪律全集（原文归档）.md` 的同名章节。
> 读法：启动链的坑全是**时序与级别**的坑——超时被架空中断语义（§15）、全 Warning 项占着关键路径（§17/§24）、缓存指纹松一格整类静默失效（§25）。

## 15. 启动自检超时（R48-R50）

| # | 判据 |
|---|---|
| R48 | 超时走 `IStartupCheck.TimeoutMs`（逐项声明，默认 30s），**不许写死在 `AppLifetimeService`**；级别同样逐项（`TimeoutLevel`，默认 `Error`）。"缺失也不影响主界面"的项必须声明 `Warning`（范例：插件扫描 `120_000` + `Warning`）。`SingleInstanceCheck`/`ConfigCheck` 必须保持 `Error`。`TimeoutMs` 必须为正。文案走 `FormatTimeout`。 |
| R49 | **超时判定不许只看 `Task.WhenAny` 赢家**：取消后实现"以已取消收尾"，赢家仍是 `execTask` 但没跑完，取 `.Result` 抛 `AggregateException`（不是 `OperationCanceledException`）→ 被记成 `Error「检查异常」`，把 `TimeoutLevel` 架空。必须同时判"已取消且没跑完"（写法见 `AppLifetimeService.cs:115-117`）。探针 300 轮命中 98~138 轮。 |
| R50 | 守门：`StartupChainTimeoutIsNotFatal()` 5 条（进常规 gate）：慢项 Warning 不阻断 / 进 `Warnings` / 后续照跑 / 链 < 5s / **反向**：未声明级别仍按 Error 阻断。放宽只在项内声明，别改默认值。 |

## 17. 启动关键路径（R57）

| # | 判据 |
|---|---|
| R57 | **"全部出口都是 Warning"的自检项不许进启动链**——改由 `App.OnInitialized` 后台跑（`RunCommunicationCheckInBackground`）。三条不变形：日志口径不变（`[启动自检] {名称}: …`）、开关留在检测类首行、只挪全 Warning 项。**四件事同时到位**：链里删注册 / `OnInitialized` 补后台调用 / `OnExit` 里 `_postStartupCts.Cancel()` / 其它异常只落一行 Warn。守门：`[E18]` 六条（含反向：`CommunicationCheck` 里 `CheckLevel.Error` 必须 0 次；链上 `RegisterCheck(` 恰好 **4** 次——单实例/配置日志/HALCON/插件扫描，通讯与帮助手册已在 `OnInitialized` 后台）。 |

## 24. 启动插桩与提速（R78-R80）

| # | 判据 |
|---|---|
| R78 | **启动插桩必须落 `ILogService`，不许走 `IUserNotifier`**（弹泡 3 秒就消）。 |
| R79 | **全 Warning 自检项不许站在启动关键路径**（先例 R57）。四条：链上删注册 / `OnInitialized` 补后台调用 / `OnExit` 里 `Cancel()` / 异常只落一行 Warn。**挪动前确认懒构建兜底在位**（`HelpViewModel.OnDialogOpened` 的 `!IsBuilt → Build()`）。守门：`[E19]` 三条，`E18` 第 ⑤ 条计数改 4。 |
| R80 | **扫插件程序集必须带名字过滤 `GetFiles(dir, "Plugin*.dll")`，反射元数据只物化一次**（`GetTypes()` 一次、三处各写过滤器）。 |

## 25. 插件清单缓存（R81-R83）

| # | 判据 |
|---|---|
| R81 | **正确性全押在指纹失效判据上，且必须是断言**。四道全满足才命中（SchemaVersion / 每 DLL 大小+mtime / 无未登记 `Plugin*.dll` / 契约程序集 `Core.Interfaces.dll` 的 size+mtime 文件指纹），任一不满足即**全量重扫并重写**，不做部分缓存；失效原因写日志。守门：`PluginCacheChecks` PC1~PC8（进常规 gate）。 |
| R82 | **缓存跳过实例化的前提是"构造器无副作用"，必须静态扫描钉住**；判据收窄到**构造器体**（运行期 `Process.Start`/`HttpClient` 是合法业务）。守门：PC8。 |
| R83 | **缓存产物与全量扫描必须逐项一致，比对剔除内置节点**；抽查端口表的对象必须是**插件**。 |

守门：`StartupChainTimeoutIsNotFatal()` 5 条、`[E18]` 六条、`[E19]` 三条、`PluginCacheChecks` PC1~PC8（均进常规 gate）。

## 读法

1. 改任何一项自检先回答三个问题：`TimeoutMs`/`TimeoutLevel` 声明了吗？它是不是全 Warning（是 → 不许进链，走 `OnInitialized` 后台）？`AppLifetimeService.cs:115-117` 的"已取消且没跑完"判定还盖得住它吗？
2. 挪动自检项的固定四步（R57/R79）：链里删注册 → `OnInitialized` 补后台调用 → `OnExit` 里 `Cancel()` → 异常只落一行 Warn。**四件事缺一，gate 的计数断言（`RegisterCheck(` 恰好 4 次）会红。**
3. 改缓存前先回答"这次改坏，靠哪条断言能发现"——R81 的前提是**指纹判据本身被断言钉住**，判据松一格就是整类静默失效；新增缓存命中路径前确认被跳过的构造器确实无副作用（R82 只钉构造器体）。
