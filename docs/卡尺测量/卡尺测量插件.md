# 第 0 章 这是什么

**卡尺测量 = 在图像上"拿尺子量尺寸"，量到亚像素精度。**

> 生活比喻：真实车间里，工人拿游标卡尺卡住一个零件读数。视觉里的"卡尺"是同一件事——只不过它是一条**沿某个方向扫描的线**，扫描过程中检测"灰度跳变最陡的那个点"（就是边缘），然后用多个位置的边缘算出宽度/距离/角度。

本插件是**阵列式卡尺**：你拖一个"搜索区矩形"，插件在矩形内**自动均布 N 把卡尺**（默认 5 把），每把各找一个边缘点，最后**取平均**——这样单点噪声不会把结果带跑偏。

它在流程里的位置（归在 **「测量」** 分组）：

```
[图像采集] → [创建 ROI] → [图像预处理] → [卡尺测量] → [CSV记录] / [结果上报] / [C#脚本]
                                        ↓
        MeasureValue(测量值) / Deviation(偏差) / IsOk(判定) / MeasureImage(标注图)
```

**一句话**：模板匹配解决"目标在哪"，Blob 解决"有没有缺陷"，而 **卡尺解决"这个尺寸是多少、合不合格"**——它是尺寸检测（宽度、间距、点到线距离、圆直径、角度）的主力算子。

# 第 1 章 设计思想

## 1.1 核心原理：扫描找边

```
        搜索区矩形（你拖出来的）
   ┌───────────────────────────────┐
   │  ▮ 卡尺1  ▮ 卡尺2  ▮ 卡尺3     │  ← N 把卡尺沿 L2 方向均布
   │  ──▶      ──▶      ──▶        │     每把沿 L1 方向扫描（扫描方向）
   │   ▲        ▲        ▲         │     ▲ = 找到的亚像素边缘点
   └───────────────────────────────┘
              ↓
        5 个边缘点 → 拟合/求距 → 取平均 → 乘像素当量 → 判定 OK/NG
```

**关键几何（务必看懂，这是新手最常搞错的地方）**：

| 方向 | 半轴 | 是什么 | 摆错了会怎样 |
|---|---|---|---|
| **L1（Phi 方向）** | 半长 | **扫描方向**——每把卡尺沿此方向扫描，检出的边缘**垂直于**它 | 扫不到边 |
| **L2（垂直 Phi）** | 半宽 | **卡尺阵列排布方向**——N 把卡尺沿此方向均布 | 每把扫到不同位置，测出来是错的 |

> 记忆口诀：**矩形要"横跨"被测的边/缝**——让 L1 方向与边垂直，卡尺才扫得到边；L2 方向是沿边的方向，用来在多个位置重复取边、取平均抗噪。
>
> 实证：`Phi=0` 时 L1 沿水平方向——把 `L1=100/L2=10` 的矩形放在竖直亮带上能测出宽度；把 L1 缩到 10（扫描线够不到边）或把 Phi 转 90°（扫描方向变竖直）都检不到边。

## 1.2 五种测量类型

| 类型 | 需要几个搜索区 | 算法 | 典型场景 |
|---|---|---|---|
| **宽度/间隙** | 1 个矩形 | `measure_pairs` 直接给双边距离 | 测缝隙、线宽、材料厚度 |
| **两点距** | 2 个矩形 | 各用 `measure_pos` 找一个边缘点 → `distance_pp` | 测两个特征之间的距离 |
| **点到线距** | 2 个矩形 | 区1 出代表点，区2 点集拟合直线 → `distance_pl` | 测点到基准边的距离（垂直度、位置度） |
| **圆直径** | 1 个**圆** + 环宽 | 沿圆周**径向**均布 N 把卡尺 → `fit_circle_contour_xld` → 直径 = 2×半径 | 测孔、轴、圆的外径/内径 |
| **角度** | 2 个矩形 | 各拟合一条直线 → `angle_ll` → 归一化到 0~180° | 测夹角、倒角、V 形槽 |

> **角度不受像素当量影响**（单位是"度"，是量纲无关量）。其余类型 = 像素测量值 × 当量。这条区分容易写错。

## 1.3 `measure_pos` 与 `measure_pairs` 的区别（核心概念）

| 维度 | `measure_pos` | `measure_pairs` |
|---|---|---|
| 找什么 | **单边缘**：沿扫描方向找出所有符合极性/阈值的边 | **成对边缘**：把边按"第一条 + 第二条"配对 |
| 返回 | 每个边的亚像素行列坐标 + 振幅 | 两坐标 + `IntraDistance`（**对内间距**）+ `InterDistance`（相邻对间距） |
| 用在哪 | 两点距、拟合类（点线距/圆直径/角度的点来源） | **宽度/间隙**（一把卡尺横跨缝隙，直接得缝宽） |
| 本插件取值 | 统一取**第一条**（`select='last'` 时它本就是最后一条） | 取第一条配对的 `intra[0]` |

## 1.4 三条设计原则

**原则①：必须全部检出，不"将就平均"**

只要有一把卡尺找不到边就判失败。把检到的几把平均出一个"看似合理"的数是**计量最危险的失败模式**（错误但不出错）。宁可报错让用户调参数。

**原则②：配置坏了最多结果不对，绝不炸流程**

所有越界参数（`Sigma`、阈值、卡尺数、当量、公差、残差、环宽）在进入 HALCON 前**静默夹取**。典型：`Sigma=0` 会直接抛 `#1302`；搜索区中心在图外会抛 `#3022`（滤波核尺寸非法，英文报错对操作员毫无指导意义）→ 插件提前用**中文**说清"哪个搜索区、中心在哪、图多大"。

**原则③：判定规格默认"零容忍"**

`StandardValue/UpperTolerance/LowerTolerance` 默认都是 0。这是**有意的**——通用平台算子不该假装知道产品的规格值。用户看到默认即 NG，会立刻意识到"要去填标准值与公差"。与 BlobDetect 的 `MaxDefectCount=0` 同一风格：**安全侧默认，宁严勿松**。

## 1.5 配置态 / 运行态严格隔离

宿主会为"打开配置界面"和"正式运行"各造一个实例，用 `_isConfigInstance` 守卫把**预览**限制在配置态。放到运行实例上会：① 产线每帧多跑完整测量，CPU 白烧；② 流程线程与 UI 线程并发共用同一扇离屏渲染窗口；③ 每帧 new 一张标注图随即丢弃，纯内存抖动。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | 卡尺测量 |
| `GroupName` | 测量 |
| `Description` | 阵列式卡尺测量：自动均布 N 把卡尺做亚像素找边，支持宽度/间隙、两点距、点到线距、圆直径与角度；输出物理值、偏差与 OK/NG |
| `ShortName` | 图标（FontAwesome `f545`） |

> 与仓库其它插件同一写法：**流程节点 + 配置界面 ViewModel 合一**。

## 2.2 端口完整清单（全部固定端口，无动态端口）

| 端口 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `SrcImage` | 入 | HImage | 待测量图像 |
| `MmPerPixel` | 入 | double | **像素当量直连口（可选）**：接「标定」插件的 `MmPerPixel` 输出（也可链接运行时变量）。**未接线 = 用手填 `PixelSizeMm`**（旧行为不变）；已接线但上游值无效（≤0/NaN，例如标定步骤本轮失败）→ 步骤**明确失败**，不静默回退旧值 |
| `MeasureValue` | 出 | double | 测量值（**已乘像素当量**） |
| `Deviation` | 出 | double | 与标准值的偏差（带符号：测大为正、测小为负） |
| `IsOk` | 出 | bool | 判定结果（true = OK） |
| `MeasureImage` | 出 | HImage | 标注图（卡尺 + 边缘点 + 测量连线/拟合几何 + 判定文字） |
| `FittedGeometry` | 出 | HXLD | 拟合几何（直线/圆/角度两线；宽度与两点距 = 测量连线） |
| `EdgePoints` | 出 | HXLD | 检出的原始边缘点（十字 XLD） |

另有基类隐式端口 `Success`、`ErrorMessage`。

> **N 把卡尺不生成 N 个端口**：所有卡尺矩形合成**一个** `HXLD` 对象集交出去（`gen_rectangle2_contour_xld` 一次出 N 个对象）。这样端口数量恒定，下游连线不会因为改了卡尺数就断。

## 2.3 配置项（按 5 组）

### ① 测量类型

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `MeasureKind` | 枚举 | `Width` | 宽度/间隙、两点距、点到线距、圆直径、角度 |

### ② 搜索区与卡尺

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `CaliperRegions` | 集合 | 空 | 搜索区列表（随方案持久化）。宽度/圆直径用第 1 个，其余用前 2 个 |
| `CaliperCount` | int | **5** | 卡尺数 N：每个搜索区内自动均布的卡尺条数，取平均抗噪 |

### ③ 找边参数

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `Sigma` | double | **1.0** | 平滑系数（轻度平滑，压高频噪声又不糊掉边缘） |
| `EdgeThreshold` | double | **30** | 边缘阈值（相邻像素最小灰度差） |
| `Polarity` | 枚举 | **All（全部）** | 暗→亮 / 亮→暗 / 全部 |
| `Select` | 枚举 | **All（全部）** | 每条卡尺多条边缘时取 第一条 / 最后一条 / 全部 |
| `Interpolation` | 枚举 | **Bilinear** | 亚像素插值（对应 `gen_measure_rectangle2` 的 `Interpolation`） |

> 为什么用"暗→亮/亮→暗"而不是暴露 HALCON 的 `positive/negative`：操作员看图只会判断"灰的变白的还是白的变灰的"，不需要知道算子里叫什么。内部统一映射。

### ④ 拟合参数（仅拟合类显示）

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `FitAlgorithm` | 枚举 | **Tukey** | 最小二乘 / Huber / **Tukey（推荐）** |
| `FitMaxError` | double | **1.0 px** | 边缘点到拟合几何距离的**中位数**上限（不是最大值！） |
| `FitMinPoints` | int | **3** | 参与拟合的最少边缘点数（直线 2 点、圆 3 点，取 3 兼顾） |
| `AnnulusWidth` | double | **30 px** | 环宽（仅圆直径）：每把卡尺沿半径方向扫描的总宽度（±15px 容差） |

> 为什么默认 **Tukey**：卡尺偶尔扫到毛刺会产生离群点，最小二乘会被**一个坏点拽歪整条线/圆**；Tukey 对残差超限的点大幅降权。实测：12px 毛刺下 `tukey=196.5`（真值 196.5）vs `regression=191.092`。
>
> 为什么残差用**中位数**而非最大值：若按最大值检查，一个毛刺离群点就会把 Tukey 已正确拟合的结果判死，鲁棒拟合就失去意义。

### ⑤ 判定与标定

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `StandardValue` | double | **0** | 标准值（名义尺寸） |
| `UpperTolerance` | double | **0** | 上公差（偏差 ≤ 上公差 才 OK） |
| `LowerTolerance` | double | **0** | 下公差（可填负数实现**非对称公差**） |
| `PixelSizeMm` | double | **1.0** | 像素当量 mm/px（默认 1.0 = 直接输出像素值）。**接「标定」后此框为兜底**：已接 `MmPerPixel` 输入端口时运行时以连线为准 |

## 2.4 运行时夹取区间（静默夹取，防炸流程）

| 参数 | 夹取区间 | 说明 |
|---|---|---|
| `Sigma` | 0.4 ~ 100 | 0 会抛 `#1302`，夹到 0.4 |
| `EdgeThreshold` | 1 ~ 255 | |
| `CaliperCount` | 1 ~ 1000 | |
| `PixelSizeMm` | 1e-9 ~ 1e6 | 手填与「已接线的上游值」走同一夹取；上游值无效（≤0/NaN）时不夹取而是**明确失败** |
| 公差 | ±1e9 | |
| `FitMaxError` | 0.05 ~ 1e6 | |
| `FitMinPoints` | 2 ~ 1000 | |
| `AnnulusWidth` | 2.0 ~ 1e5 | |

## 2.5 HALCON 算子与算法链

### 测量链

| 算子 | 作用 |
|---|---|
| `get_image_size` | 取图像宽高（越界检查与建句柄） |
| `gen_measure_rectangle2` | **建测量句柄**：把 `[R,C,Phi,L1,L2]` + 图像尺寸 + 插值方式变成 measure 对象 |
| `measure_pos` | **单边缘**找边（返回亚像素坐标 + 振幅） |
| `measure_pairs` | **成对边缘**找边（返回两坐标 + `IntraDistance`） |
| `close_measure` | 释放测量句柄（⚠️ 算子名是 `close_measure`，**不存在 `clear_measure`**） |
| `distance_pp` | 两点距 |
| `distance_pl` | 点到线距（垂距） |
| `angle_ll` | 两线夹角（返回**弧度**，代码 ×180/π） |
| `fit_line_contour_xld` | 边缘点拟合直线 |
| `fit_circle_contour_xld` | 边缘点拟合圆 |
| `gen_contour_polygon_xld` | 点列连成 XLD 轮廓（供拟合 / 画测量连线） |
| `gen_circle_contour_xld` | 生成整圆/圆弧轮廓 |
| `gen_rectangle2_contour_xld` | 批量生成 N 把卡尺的矩形轮廓 |
| `gen_cross_contour_xld` | 生成边缘点十字（size=12） |
| `concat_obj` / `gen_empty_obj` | 合并轮廓 / 空对象兜底 |
| `count_channels` → `copy_image` / `rgb1_to_gray` | 转灰度（测量只在单通道灰度上做） |
| `get_image_type` → `convert_image_type` | 非 byte 图转 byte（显示用） |

> **明确未使用**：`measure_rectangle1` / `measure_rectangle2`（对象式旧算子）、`measure_throw`、`edges_sub_pix`、`select_shape`。本插件走的是**句柄式** `gen_measure_rectangle2 + measure_pos/measure_pairs`。

### 标注渲染（`AnnotationRenderer.cs`）

`get_image_size` → `set_draw("margin")` → `disp_obj` 底图 → **卡尺矩形（黄，1px）** → **测量连线（青，2px）** → **拟合几何（品红，2px）** → **边缘点十字（绿，2px）** → 左上角 `disp_text` 文字 → `dump_window_image`

## 2.6 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **阵列式多卡尺取平均** | N 把卡尺（默认 5）各找边取平均 | ⭐⭐⭐ 单点噪声带不跑结果 |
| **鲁棒拟合（Tukey）** | 对离群点降权 | ⭐⭐⭐ 一个毛刺拽不歪拟合结果 |
| **必须全部检出** | 任一把找不到边即失败 | ⭐⭐⭐ 杜绝"错误但不出错"的计量灾难 |
| **静默夹取 + 中文越界报错** | 参数夹取；搜索区越界提前中文提示 | ⭐⭐⭐ 不炸流程，报错能指导操作 |
| **配置态守卫** | `_isConfigInstance` | ⭐⭐ 产线不白烧 CPU |
| **measure 首跑空结果重试** | 最多重试 4 次 | ⭐⭐ 兜底 HALCON 偶发首跑空 |
| **离屏窗口缓存 + 加锁** | 按尺寸缓存，防预览/流程线程互抢 | ⭐⭐ 避免 `#9302` 死锁 |
| **源对象释放** | `new HXLDCont(...)` 后释放源对象 | ⭐⭐ 防引用计数泄漏（500 次约 160MB） |
| **角度归一化 0~180°** | 两线归一化为"交点→远端"射线再 `angle_ll` | ⭐⭐ 消灭补角歧义（不会把 150° 报成 -30°） |

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.CaliperMeasure.dll`（由 `Plugins/Directory.Build.targets` 自动投递）。
2. 依赖 HALCON 原生库（随软件分发）。
3. 首次使用前关掉宿主进程再生成。
4. 重开软件，工具箱里出现「卡尺测量」（**测量** 分组）。

## 3.2 配置界面总览（两列）

```
┌──────────────────────┬────────────────────────────────────┐
│ 左：参数（340px 可滚动）│ 右：标注图预览（**同时是拖拽画布**）    │
│  图像输入              │  顶部：标注图预览（可拖拽搜索区）       │
│  ① 测量类型            │                                    │
│  ② 搜索区与卡尺        │  ← 右键可新建矩形/圆形搜索区           │
│  ③ 找边参数            │  ← 拖动手柄粗调                      │
│  ④ 拟合参数            │                                    │
│  ⑤ 判定与标定          │  底部：状态信息栏（三色）              │
└──────────────────────┴────────────────────────────────────┘
```

> 右侧用的是 `ImageEdit`（可拖拽）而不是 `ImageReadOnly`——既要显示标注结果，又要能拖搜索区（与创建 ROI 同一范式）。

## 3.3 第一次测量（7 步）

**第 1 步｜接图**：把前级图像连到 `SrcImage`。

**第 2 步｜选测量类型**：左栏①选类型（宽度/两点距/点到线距/圆直径/角度）。下方灰字会提示需要几个搜索区。

**第 3 步｜摆搜索区**（最关键）：在右侧图上**右键 → 区域 → 新建矩形**（圆直径选圆形）。
> ⚠️ 矩形要**横跨**被测的边/缝：半长 L1 方向 = 扫描方向（与边垂直），半宽 L2 方向 = 卡尺阵列排布方向。

**第 4 步｜调卡尺数**：②区设 `CaliperCount`（默认 5）。想要更稳就调大，想省时间就调小。

**第 5 步｜调找边参数**：③区。一般先用默认（`Sigma=1.0`、`EdgeThreshold=30`、极性=全部）。如果边缘很弱，把 `EdgeThreshold` 调小；噪声大就把 `Sigma` 调大。

**第 6 步｜填规格**：⑤区填 `StandardValue`（标准值）、`UpperTolerance`/`LowerTolerance`（上下公差）、`PixelSizeMm`（像素当量）。
> 有「标定」步骤时优先**直连当量**：把标定的 `MmPerPixel` 连到本步骤 `MmPerPixel` 端口（运行时以标定为准）；手填框作为未接线时的兜底。
> 默认是零容忍（全 0），看到 NG 是正常的——它在提醒你该填规格了。

**第 7 步｜看标注图**：右侧自动刷新。图层含义：
| 颜色 | 是什么 |
|---|---|
| 黄（细） | 卡尺矩形（N 把） |
| 绿（十字） | 找到的边缘点 |
| 青（2px） | 测量连线 |
| 品红（2px） | 拟合几何（直线/圆） |
左上角文字三行：判定 OK/NG、测量值、偏差。

## 3.4 参数调节速查表

| 现象 | 调哪里 |
|---|---|
| 找不到边（报"某卡尺未检出"） | ① 矩形没横跨边（L1 方向错了）② `EdgeThreshold` 太大，调小 ③ 极性选反了 ④ 搜索区在图像外 |
| 测宽度的缝量到的是别的东西 | 把 `Polarity` 明确成"暗→亮"或"亮→暗"，别用"全部" |
| 结果抖动不稳 | 调大 `CaliperCount`（多取平均）；调大 `Sigma` 平滑 |
| 边缘太糊/太锐 | 调 `Sigma`（大=更平滑） |
| 拟合结果被毛刺带歪 | 确认 `FitAlgorithm` 是 **Tukey**；调大 `FitMaxError` 容忍度 |
| 拟合老失败 | `FitMinPoints` 调小；或检查边缘点是否足够 |
| 圆测成奇怪的小圆 | 点集太少/共线（退化）。保证卡尺数够多、圆搜索区压在真实圆周上 |
| 圆贴近图像边缘报错 | 把圆拖离边缘、缩小半径或减小环宽 |
| 角度报成 -30° 之类 | 已修（0~180° 归一化）。如仍异常，确认两搜索区分别压在**两条相交**的边上 |
| 两线接近平行报错 | 让两个搜索区分别压在两条**相交**的特征边上 |
| 结果单位不对 | 检查 `PixelSizeMm`（角度不受影响，单位是度） |

## 3.5 FAQ

**Q1** 为什么默认一上来就 NG？
`StandardValue/UpperTolerance/LowerTolerance` 默认 0 = 零容忍。有意设计：通用算子不该假装知道你产品规格。

**Q2** 判 NG 算执行失败吗？
不算。`Success` 保持 true，只写 `ErrorMessage` 说明原因。NG 是正常结果。

**Q3** 卡尺数越多越好吗？
更多 = 更稳（平均抗噪）但更慢。默认 5 是通用起点；节拍紧就调小。

**Q4** 像素当量怎么定？
两条路：① **推荐——直连「标定」插件**：把标定的 `MmPerPixel` 输出连到本步骤的 `MmPerPixel` 输入端口，运行时自动用标定值（标定失败会直接判失败，不会拿旧值硬算）；② 手填兜底：用已知尺寸的标准件标定 `PixelSizeMm = 实际尺寸(mm) / 像素数`。默认 1.0 表示直接输出像素值。

**Q5** 角度为什么不受像素当量影响？
角度是**量纲无关量**（单位"度"）。当量只作用于长度类测量。

**Q6** 搜索区能是任意形状吗？
**不能**。算法只接受 `Rectangle`（圆直径用 `Circle`）。其它形状是画布右键误建，运行期会明确报错。

**Q7** 删掉搜索区后再切类型会自动补吗？
会"只增不减"地补到所需数量，**绝不删**你已摆好的区域——删区域这种破坏性操作永远由你显式触发。

## 3.6 现场排障

| 现象 | 排查 |
|---|---|
| 报"搜索区中心超出图像范围" | 中心在图外。把搜索区拖到图像内（插件已用中文报出是哪个区、中心在哪、图多大） |
| 报"某把卡尺未检出边缘" | ① L1 方向没横跨边 ② 阈值太大 ③ 极性反了 ④ 该位置真的没边（脏污/遮挡） |

## 4.2 P0 级详解

### ① 卡尺均布方向算错（最隐蔽的几何 bug）

**现象**：`Phi≠0`（旋转矩形）时测出来的值不对。第一批实测全在 `Phi=0`，未暴露。

**原因**：卡尺沿 L2 轴均布时，L2 轴的单位向量第一批写成了 `(cosφ, −sinφ)`，与真实长轴 `(−sinφ, cosφ)` 点积 = `−2sinφcosφ ≠ 0`，**φ≠0 时排布方向不垂直于扫描方向**。

**修法**：改为 `(cosφ, +sinφ)`。φ=0 行为不变。第二批用"非对称位置探针"裁决后确认。

### ② 运行实例跑配置态预览（复盘发现）

**现象**：三重代价——① 产线每帧多跑完整测量（N 把卡尺 + 拟合 + 离屏渲染）；② 流程线程与 UI 线程并发共用同一扇离屏渲染窗口（有锁不崩但互相阻塞）；③ 每帧 new 一张标注图随即丢弃，纯内存抖动。

**修法**：补 `_isConfigInstance` 守卫 + `MarkAsConfigInstance()`（只在此处订阅 `SrcImage.ValueChanged`）+ `SchedulePreview` 纵深防御。

> 参照系：BlobDetect 第一批就有这个守卫，卡尺两批都漏了。这是"跨插件经验没同步"的典型。

### ③ HALCON 源对象泄漏

**现象**：长时间运行内存只增不减。

**原因**：`gen_*_contour_xld` 产出的对象是"源对象"，`new HXLDCont(...)` 是独立句柄，但 HALCON .NET 是**引用计数语义**——不释放源对象会留下一个引用计数。实测 500 次不释放约泄漏 160MB。

**修法**：包装成独立句柄后立刻释放源对象（`temp` 里登记的所有临时对象在 `finally` 里统一 Dispose）。

### ④ 非 `IDisposable` 端口不清零

**现象**：本轮失败时下游读到上一轮的 `MeasureValue`/`Deviation`/`IsOk`。

**原因**：基类 `AutoDisposeRoundOutputs` 只处理 `IDisposable`（HImage/HXLD），`double`/`bool` 端口的上一轮值会原样留下。

**修法**：`RunAlgorithm` 开轮显式重置三个标量端口。这是**极易漏的镜像 bug**。

## 4.3 P1 级详解

### ⑤ `fit_circle` 算法值集传错 → `#1301`

**现象**：拟合圆时传 `regression` 直接报 `#1301`。

**原因**：`fit_line_contour_xld` 与 `fit_circle_contour_xld` 的 **algorithm 值集是两套**：

| 算子 | 合法值 |
|---|---|
| `fit_line_contour_xld` | `regression` / `huber` / `tukey` |
| `fit_circle_contour_xld` | `geometric` / `geohuber` / `geotukey` |

**修法**：按语义一一对应映射（`regression↔geometric`、`huber↔geohuber`、`tukey↔geotukey`）。

> 另：`fit_circle_contour_xld` 的实测签名是 `(contours, algorithm, maxNumPoints, maxClosureDist, clippingEndPoints, iterations, clippingFactor)` —— **没有 PointOrder 输入**（那是输出）。

### ⑥ `measure` 偶发首跑空结果

**现象**：进程内"同一调用首跑可能返回空、第二跑正常"。探针复现：同参连跑 3 遍得到 0/1/1 条边。

**修法**：带一次性重试（最多 4 次）。真正没有边缘时第二次仍为空、仍判失败，**语义不变**——它只兜底"偶发首跑空结果"的误报。

### ⑦ 圆退化几何（共线点拟出小圆）

**现象**：3 个共线点配 geo 系列鲁棒算法时**不报错**，而是收敛到一个"贴住少数点的小圆"（实测 r≈31px）。半径有限、残差中位数也可能因降权而达标，常规检查全拦不住。

**修法**：加几何退化判据——真实圆周上均布点的最大跨度 ≈ 直径（N=3 的 120° 均布也有 `√3·R ≈ 1.73R`）；若**拟合圆直径 < 点集跨度的 60%**，说明这个圆根本包不住点集，必是退化解。另有 `maxSpan < 2.0` 判"点几乎重合，特征可能是直线边"。

### ⑧ phi 约定反复（教训）

**过程**：第一批假定"参数直通"（画布矩形参数可直接喂给测量算子）。中途曾按**相反假设**改成取负，随即被裁决探针推翻并撤销。

**最终实证结论**：本环境 `GenRectangle2`（画布/显示/paint）与 `gen_measure_rectangle2` 的 phi 约定**一致**——长轴单位向量都是 `(−sinφ, cosφ)`。因此画布矩形参数**可直接喂给测量算子，无需换算**。

> 教训：几何约定不能靠推理，必须写**探针实测**来裁决；且探针要覆盖 `φ≠0` 的非对称位置，否则测不出来。

### ⑨ 试运行跨线程异常

**现象**：用户点「卡尺_宽度」试运行 31ms 失败，报 `调用线程无法访问此对象，因为另一个线程拥有该对象。`

**原因**：`PluginTestRunner.BridgeInputs` 在**后台线程**给配置实例端口赋值 → `ValueChanged` 在后台线程触发 → `LinkableValueEditor.OnPortValueChanged` 首行读 DP（`IsLinked`）触发 `VerifyAccess` 抛异常。

**修法**：`LinkableValueEditor.xaml.cs` 非 UI 线程改用 `Dispatcher.BeginInvoke`；补堆栈日志。此修复一处全局受益（卡尺/码读取/OCR/YOLO 共用该控件）。

### ⑩ 方案重开枚举配置静默丢失

**现象**：生成「卡尺测量测试」`.vms` 保存后重开，**所有插件的 `[StepConfig]` 枚举配置都静默还原默认值**。卡尺的极性/选择/插值/拟合算法全受影响。

**修法**：修复枚举值的序列化/反序列化链路。验证：5 个实例的 `MeasureKind` 全部正确还原，5 种测量值 5 PASS / 0 FAIL。

```
标定.MmPerPixel ──▶ 卡尺.MmPerPixel（未接线时用 ⑤区手填 PixelSizeMm 兜底；标定失败 → 卡尺明确失败）
```

> **位置原则**：卡尺是"测量"节点，前面要有干净图（采集/预处理/ROI），后面接记录/上报/补偿。一个步骤测一个尺寸——多个尺寸就摆多个卡尺节点。

## 5.3 附录 C：HALCON 实战案例

### 案例 1｜测宽度：`measure_pairs` 一把卡尺直接得缝宽

```hdevelop
* 建测量句柄：矩形横跨缝隙，L1=100（扫描方向，垂直于缝）、L2=10
gen_measure_rectangle2 (Row, Col, Phi, L1, L2, Width, Height, 'bilinear', Handle)
* 成对找边：返回第一条边、第二条边、以及 IntraDistance（对内间距=缝宽）
measure_pairs (Gray, Handle, 1.0, 30, 'all', 'all',
               Row1, Col1, Amp1, Row2, Col2, Amp2, IntraDist, InterDist)
* 缝宽 = IntraDist[0]（第一个配对）
Width_px := IntraDist[0]
close_measure (Handle)      * ← 释放句柄，算子名是 close_measure
```

### 案例 2｜测两点距：两个搜索区各找一个边点

```hdevelop
* 区1：measure_pos 取第一条边 → 取平均成"代表点" P1
gen_measure_rectangle2 (R1, C1, Phi1, L1a, L2a, W, H, 'bilinear', H1)
measure_pos (Gray, H1, 1.0, 30, 'all', 'first', RowE1, ColE1, Amp, Dist)
* 区2：同理得 P2
gen_measure_rectangle2 (R2, C2, Phi2, L1b, L2b, W, H, 'bilinear', H2)
measure_pos (Gray, H2, 1.0, 30, 'all', 'first', RowE2, ColE2, Amp, Dist)
* 两点距
distance_pp (mean(RowE1), mean(ColE1), mean(RowE2), mean(ColE2), Distance)
close_measure (H1)
close_measure (H2)
```

### 案例 3｜测点到线距：拟合直线后求垂距

```hdevelop
* 区2 的 N 个边点 → 点列 → 拟合直线（Tukey 抗离群）
gen_contour_polygon_xld (PolyXld, Rows, Cols)
fit_line_contour_xld (PolyXld, 'tukey', -1, 0, 5, 2.0, RowBegin, ColBegin, RowEnd, ColEnd, Nr, Nc, Dist)
* 区1 的代表点到该直线的垂距
distance_pl (PRow, PCol, RowBegin, ColBegin, RowEnd, ColEnd, Distance)
```

### 案例 4｜测圆直径：沿圆周径向均布卡尺再拟合

```hdevelop
* 沿圆周均布 N 把卡尺，每把的扫描方向 = 该点的径向
* 圆周上角 a 处的点 = (R + r·sin a, C + r·cos a)，径向单位向量 = (sin a, cos a)
* HALCON 约定下长轴 = (−sinφ, cosφ)，要得到径向 (sin a, cos a) → φ = −a
for a := 0 to 2π by 2π/N
    row := CenterR + Radius * sin(a)
    col := CenterC + Radius * cos(a)
    gen_measure_rectangle2 (row, col, -a, HalfLen, HalfWidth, W, H, 'bilinear', Hnd)
    measure_pos (Gray, Hnd, 1.0, 30, 'all', 'first', RE, CE, Amp, Dist)
    close_measure (Hnd)
endfor
* 拟合圆（值集是 geo 系列！）
gen_contour_polygon_xld (Poly, AllRows, AllCols)
fit_circle_contour_xld (Poly, 'geotukey', -1, 0, 0, 5, 2.0, RowC, ColC, Radius, StartPhi, EndPhi, PointOrder)
Diameter := 2 * Radius
```

### 案例 5｜测角度：归一化到 0~180°（消灭补角歧义）

```hdevelop
* 两条拟合线 → 求交点 → 各归一化为"从交点指向点分布远端"的射线 → angle_ll
* 直接对 fit 输出求角会依赖端点顺序，可能把 150° 报成 -30°
angle_ll (R1a, C1a, R1b, C1b, R2a, C2a, R2b, C2b, AngleRad)
AngleDeg := abs(AngleRad) * 180.0 / 3.14159265358979
* 结果单位"度"，不受像素当量影响
```

### 案例 6｜阵列卡尺沿 L2 轴均布（最关键的正确姿势）

```hdevelop
* N 把卡尺必须沿 L2 轴（垂直于扫描方向）均布，每把保留完整 L1 扫描长度
spacing   := 2.0 * L2 / N                        * 把整段 L2 宽度等分成 N 份
halfWidth := max2(spacing / 2.0, 0.5)            * 每把半宽 = L2/N（正好铺满不重叠）
for i := 0 to N-1 by 1
    t  := -L2 + spacing * (i + 0.5)              * 沿 L2 轴的偏移量
    ri := R + t * cos(Phi)                       * ⚠️ L2 轴单位向量 = (cosφ, +sinφ)
    ci := C + t * sin(Phi)                       *    （写成 (cosφ,−sinφ) 在 φ≠0 时是错的）
    gen_measure_rectangle2 (ri, ci, Phi, L1, halfWidth, W, H, 'bilinear', Hnd)
    ...
    close_measure (Hnd)
endfor
```

## 5.6 附录 F：术语表

**测量基础**

| 术语 | 含义 |
|---|---|
| 卡尺（Caliper） | 沿某方向扫描检测灰度跳变的"尺子" |
| 亚像素 | 比一个像素更细的精度（如 0.2 px），靠灰度插值得到 |
| 搜索区 | 你拖出的矩形/圆，卡尺在此范围内均布 |
| 极性 | 边缘是"暗→亮"还是"亮→暗" |
| 像素当量 | mm/px，把像素值换算成物理尺寸的标定系数 |
| 拟合 | 用一堆边缘点算出最接近的直线/圆 |
| 鲁棒拟合 | 对离群点降权，防一个坏点拽歪结果（Tukey/Huber） |

**插件专属**

| 术语 | 含义 |
|---|---|
| L1（半长） | **扫描方向**，卡尺沿此方向扫描，边缘垂直于它 |
| L2（半宽） | **卡尺阵列排布方向**，N 把卡尺沿此方向均布 |
| Phi | 矩形角度，决定 L1 的朝向 |
| 环宽 `AnnulusWidth` | 圆直径测量时每把卡尺沿半径方向扫描的总宽度 |
| 代表点 | 一个搜索区内所有卡尺边点的平均点（两点距/点线距用） |
| 零容忍默认 | 规格默认 0，看到默认即 NG，提醒用户填规格 |
| 静默夹取 | 越界参数夹回合法区间，保证"配置坏了不炸流程" |
| 配置态 / 运行态 | 打开配置窗的实例 vs 正式运行的实例，预览只在前者跑 |

**HALCON 对象**

| 术语 | 含义 |
|---|---|
| `HImage` / `HXLD` | 图像 / XLD 轮廓（非托管资源，要 Dispose） |
| measure 句柄 | `gen_measure_rectangle2` 建的对象，用完必须 `close_measure` |
| `IntraDistance` | `measure_pairs` 返回的**对内**间距（= 宽度） |
| `InterDistance` | `measure_pairs` 返回的**相邻对**间距 |
