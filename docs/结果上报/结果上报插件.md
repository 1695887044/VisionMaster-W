# 第 0 章 这是什么

**结果上报 = 流程每测完一件，把「条码 + 结果 + 检测值」组一条 JSON，POST 出去。**

> 生活比喻：检测完了，结果不能只留在机器里——要告诉 MES（制造执行系统）"这一件合格不合格"，或者往钉钉/企业微信群里发一条通知。这些事底层都是同一件事：**往一个 URL POST 一段 JSON**。

它在流程里的位置（归在 **「数据处理」** 分组）：

```
[采集] → [检测类插件] → [结果上报] ──POST JSON──▶ MES / 钉钉 / 企微 / 自定义接口
                          ↑ 动态端口（按字段表生成）
```

**一句话**：数据记录负责"记在本地"，**结果上报负责"告诉别人"**——MES 上传、群通知、自定义协议，一套界面全覆盖。

## 0.1 两个最重要的特性

1. **异步队列不占节拍**：流程线程只做"取值 + 组 JSON + 入队"（**微秒级，不碰网络**），HTTP + 重试退避全部交给插件内静态 `UploadQueue` 的后台线程。**MES 挂了、网线拔了都拖不垮检测。**
2. **断网续传**：重试穷尽仍失败的件**落盘**，网络恢复后自动补传（幂等 ID 防 MES 记重）。

## 0.2 出厂就有一条最小可用的报文

默认三字段：`sn`（端口）、`result`（端口）、`time`（内置时间戳）。

# 第 1 章 设计思想

## 1.1 核心原理：五步

```
① 取值   字段表三路取值（端口 / 运行期变量 / 内置）
② 组包   按报文预设生成 JSON
③ 入队   微秒级，塞进 BlockingCollection
④ 发送   后台线程 HTTP POST + 退避重试
⑤ 回写   回调把状态码/响应/是否成功写回端口
```

> 需要拿服务器响应给下游用时，才取消「异步队列」改**同步模式**（代价：超时会拖节拍）。

## 1.2 字段表 = 动态端口（与数据记录同范式）

| 字段的`来源` | 含义 | 是否生成端口 |
|---|---|---|
| **端口**（`Port`） | 取上游连线的值 | ✅ 字段名同时是**动态输入端口名** |
| **变量**（`Variable`） | 取运行期变量（`context.LocalVariables`） | ❌ |
| **内置**（`BuiltIn`） | 时间戳 / 步骤名（**只有 2 种**） | ❌ |

> 动态端口一律 `IsRequired=false`：允许"**先定义、后连线**"。
> 端口类型用 `InputPort<object>`：`FlowCompiler` 连线不做类型静态校验，任何上游输出都接得进来。

## 1.3 类型保真（这条很关键）

> 端口值是 `double` 就写 **`12.3`** 而不是 `"12.3"`——**MES 数值型字段校验靠它**。
> 认不出的类型（如 `HImage`）用字符串占位，好过炸。

## 1.4 失败契约：宁漏报不停线

> 默认**不**阻断（`BlockOnFailure=false`），上报失败只 WARN。需要"MES 没收到就停线"的场合才勾阻断。

## 1.5 四种报文预设，一套界面

| 预设 | 用途 | 载荷 |
|---|---|---|
| **MES字段表**（默认） | 标准 MES 上传 | 字段表本身就是 JSON（类型保真） |
| **钉钉文本** | 钉钉群机器人 | `{msgtype:"text", text:{content:"…"}}` |
| **企业微信文本** | 企微群机器人 | `{msgtype:"text", text:{content:"…"}}` |
| **原始JSON** | 对接奇葩协议的兜底 | 你自己写模板 |

> 通知/原始 JSON 模式下，**字段表是"占位符值池"**——`Source=Port` 的字段照样长动态端口，模板里 `{字段名}` 展开时从这里取值。**界面只有一套心智。**

## 2.2 端口完整清单

### 固定端口

| 端口名 | 属性名 | 方向 | 类型 | 必填 | 说明 |
|---|---|---|---|---|---|
| `上报触发` | `TriggerPort` | 入 | bool | ✖ | 上报时机=**触发端口**时，值为 true 才上报 |
| `响应` | `Response` | 出 | string | — | 服务器响应体（失败时为错误描述；异步模式下是"最近一次"） |
| `状态码` | `StatusCode` | 出 | int | — | HTTP 状态码（超时/网络错误为 **0**） |
| `已上报` | `IsUploaded` | 出 | bool | — | 最近一次是否成功（2xx **且**命中成功关键字） |
| `Success` / `ErrorMessage` | 基类 | 出 | — | — | 基类契约 |

### 动态输入端口

字段表里 `Source == Port` 且 `Enabled == true` 且名字非空 → 每个生成一个同名 `InputPort<object>`（`IsRequired=false`）。

> ⚠️ **只有动态输入，没有动态输出**（未实现 `IDynamicOutputProvider`）。这点与 DataRecord 相同、与脚本类插件不同。

## 2.4 占位符语法

| 写法 | 含义 |
|---|---|
| `{字段名}` | 在文本模板里 → 原样替换；在**原始 JSON** 里 → **JSON 字符串转义注入** |
| `{#字段名}` | 在原始 JSON 里 → **原样注入**（不加引号、不转义，用于塞数值/对象） |
| `{时间}` / `{时间戳}` | 走 `TimestampFormat` + UTC 开关 |
| `{日期}` | `yyyy-MM-dd` |
| `{步骤名}` / `{StepName}` | 本步骤名 |

> 找不到的字段**原样保留**（用户一眼看出写错名）。
> 先处理 `{#名}` 再处理 `{名}`——`{#名}` 不会被 `{名}` 的正则误伤（第二个字符是 `#`）。

## 2.5 工业纪律（后台中枢内置）

| 纪律 | 做法 |
|---|---|
| HttpClient 进程级单例 | 连接池复用，防高频上报耗尽端口 |
| 单次超时用每请求 CTS | 各任务超时可不同；`HttpClient.Timeout` 置 Infinite 不干扰 |
| 队列有界（1000） | 满则拒绝入队，按"阻断/放行"契约处置 |
| 退避重试 | 0.5s / 1s / 1.5s… **封顶 3s**，防 MES 短暂抖动打成风暴 |
| **断网续传** | 落盘 JSONL，空闲自动补传（**实时件永远优先**，补传不插队） |
| **幂等 ID** | 每条一个 GUID，自动注入 `X-Upload-Id` 头，补传重发也不怕 MES 记重 |
| spool 上限 | 100000 行，满则**丢最老 10%**（保新弃旧） |
| 毒记录 | 单条累计失败 50 次作放弃（URL 写错永远发不通，别挡住后面的件） |

## 2.6 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **异步队列** | 流程线程只入队（微秒级） | ⭐⭐⭐ 不占产线节拍 |
| **退避重试** | 递增封顶 3s | ⭐⭐⭐ 防风暴 |
| **断网续传 + 幂等** | JSONL 落盘 + `X-Upload-Id` | ⭐⭐⭐ 数据不丢、不重 |
| **实时优先不插队** | 补传只在空闲 30s 后扫 | ⭐⭐⭐ 重要数据先走 |
| **类型保真** | double 写 12.3 而非 "12.3" | ⭐⭐⭐ MES 数值校验靠它 |
| **中文不转义** | `UnsafeRelaxedJsonEscaping` | ⭐⭐⭐ 钉钉/企微看得懂 |
| **四种预设一套界面** | 一个学习成本 | ⭐⭐ |
| **报文实时预览** | 面板上显示"实际发出 →" | ⭐⭐⭐ 配错当场发现 |
| **测试发送** | 不落 spool，不污染真实账本 | ⭐⭐ |
| **日志回看** | 最近 50 条，级别着色 | ⭐⭐ 排障快 |

## 3.3 第一次上报（5 步）

**第 1 步｜选报文格式**：MES 用「MES字段表」；群通知用「钉钉文本」或「企业微信文本」；奇葩协议用「原始JSON」。

**第 2 步｜填 URL**：MES 接口地址，或钉钉/企微的 webhook。

**第 3 步｜配字段表**：`sn`（条码）和 `result`（结果）默认就在，把它们连到上游（如码读取的 `Text`、Blob 的 `IsOk`）。要加字段点「+ 添加字段」。

**第 4 步｜看报文预览**：卡片底部的"实际发出 →"会显示真实 JSON。**端口没值时显示 `(空)` 占位，一眼看出没连上**。

**第 5 步｜测试发送**：点「立即发送」，看返回 `✔ HTTP 200（业务成功）` 还是 `✘ …`。

> 测试件**不落 spool**——测试失败不该污染真实断网账本。

## 3.5 FAQ

**Q1** 会影响产线节拍吗？
**几乎不会**（默认异步）。流程线程只做"取值 + 组 JSON + 入队"（微秒级），HTTP 在后台线程。要拿响应才用同步模式。

**Q2** MES 挂了会怎样？
后台线程退避重试（0.5s/1s/1.5s…封顶 3s）。重试穷尽 → 落盘（若开 `SpoolEnabled`）→ 网络恢复自动补传。**默认不停线**。

**Q3** 补传会不会让 MES 记重？
不会。每条上报一个 GUID，自动注入 `X-Upload-Id` 头，**补传沿用原 ID**，MES 端可据此去重。

**Q4** 数值为什么不能写成字符串？
MES 数值型字段会校验。本插件**类型保真**：端口是 `double` 就写 `12.3` 而不是 `"12.3"`。

**Q5** 中文变成 `\u4EF6` 怎么办？
已修：`UnsafeRelaxedJsonEscaping`——**中文不转义**（钉钉/企微看得懂，很多 MES 还按原文匹配）。

**Q6** 请求头的值安全吗？
界面用 `PasswordBox` **打码显示**，但**持久化仍是明文**存进 `.vms`。这是"只打码不加密"的刻意取舍。

**Q7** 相对路径/非法路径的图片能上报吗？
上报的是**文本**，不涉及文件。路径只作为字符串上报。

**Q8** 支持数据库/Modbus 吗？
**不支持**。只做 **HTTP POST**。要对接别的协议请用「原始JSON」+ 中转服务，或走 C#脚本。

## 3.6 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| `超时（{N}ms 无响应）`，状态码 0 | 网络不通 / DNS 解析失败 / URL 非法 |
| `✘ HTTP 200，但响应未命中成功关键字` | 业务失败。检查 `SuccessKeyword` |
| 状态码 0 | 超时或网络错误（不是 HTTP 错误码） |
| 队列满 → 上报被拒 | 队列容量 1000；检查 MES 是否长时间不可用 |
| 日志里出现"毒记录" | URL 写错/协议不对永远发不通，累计失败 50 次后放弃该条 |
| 测试发送成功但正式运行失败 | 检查字段连线（预览里显示 `(空)` 就是没连上） |
| 中文在 MES 端乱码 | 检查 `Content-Type: application/json; charset=utf-8`（本插件已设 UTF-8） |
| 时间戳时区不对 | 勾 `TimestampUtc` |
| 面板日志没更新 | 点「刷新」；异步模式下日志由后台线程产生 |
| 上报一直不成功但也不停线 | 默认 `BlockOnFailure=false`（宁漏报不停线）。要停线请勾上 |

## 4.2 P0/P1 级详解

### ① 中文被转义成 `\u4EF6`

**现象**：`件A判定OK` 变成 `件A\u5224\u5B9AOK`，**钉钉/企微看不懂**，很多 MES 还按原文匹配。

**修法**（注释原文）：
> ```
> /// 中文不转义：默认序列化把中文打成 \u4EF6，钉钉/企微看不懂，很多 MES 还按原文匹配。
> /// UnsafeRelaxed 只是"不转义非 ASCII 与 HTML 敏感字符"，字符串内容照样合法转义。
> ```
> `JsonSerializerOptions` 用 `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`。

### ② 内置步骤名报出"未赋值"

**现象**：上报出去的 `StepName` 是"未赋值"。

**原因**：`InstanceName` 由引擎注入，配置期/某些路径下还没注入。

**修法**：`EffectiveStepName`——`InstanceName` 未注入时退回 `StepData.StepName`（与 CSV记录/Excel报表同一套规则）。

### ③ UTC 开关对值池里的 DateTime 无效（冒烟抓出）

**现象**：开了 `TimestampUtc`，内置时间戳变了，但**用户变量里的时间**没变。

**原因**：转换点分散，只转了入口的 `now`。

**修法**（注释原文）：
> ```
> /// 时间戳统一出口，也是 UTC 开关的唯一转换点：
> /// 入口归一化的 now（已转 UTC，再转恒等）与值池里的 DateTime（本地时刻）都从这里过，
> /// 保证"内置时间戳"和"用户变量里的时间"遵循同一个时区纪律。
> ```
> 全部收敛到 `FormatTime`。

### ④ 原始 JSON 模板中文又被转义

**现象**：`{名}` 注入时中文被转义，与 JSON 序列化口径不一致。

**修法**（注释原文）：
> ```
> // 再处理 {名}（JSON 字符串转义注入；encoder 用 UnsafeRelaxed：中文不转 \u，跟 JSON 序列化口径一致）
> ```

### ⑤ XAML `MC3042`

**现象**：编译报错。

**原因**：`ConverterParameter='DingTalkText,WeComText'` 里的**逗号被当标记扩展参数分隔符**。

**修法**：单引号包裹。

### ⑥ 异步模式队列线程改 UI → 跨线程异常

**现象**：异步上报完成后面板崩溃（跨线程访问 UI）。

**原因**：`LastResult` 在**队列线程**被赋值，`PropertyChanged` 处理器跟着跑在后台线程。

**修法**（注释原文）：
> ```
> // 异步模式：LastResult 在队列线程被赋值，本事件处理器跟着跑在后台线程——
> // 摸 UI（Foreground / ItemsSource）必须封送回 UI 线程，否则跨线程异常
> ```
> 用 `Dispatcher.BeginInvoke(...)`。

## 4.4 已知边界与待办

- ⚠️ **`FlowCanvasChecks/` 没有任何 ResultUpload 断言**（21 个检查文件中 0 命中）。历史验证来自已删除的临时冒烟工程（MVP 21/21 + 全量版 25 项）。
- **只做 HTTP POST**——没有 MES 私有协议、没有 Modbus、没有数据库写入。
- **spool 是单文件，不共享**（`AppContext.BaseDirectory/ResultUploadSpool/spool.jsonl`）。
- "启动即扫"依赖消费线程懒启动。
- `SkipCertValidation` 只对 https 有意义。
- 加签遵循**钉钉规范**（`sign = UrlEncode(Base64(HMAC-SHA256(secret, "时间戳\nsecret")))`）。

- 请求头**明文**存进 `.vms`（只打码不加密）。
- 切换报文预设时**模板不迁移**。
- 类型保真依赖上游给出正确类型。
