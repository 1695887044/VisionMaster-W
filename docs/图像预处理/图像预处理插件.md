# 第 0 章 这是什么

**图像预处理 = 在正式"看"图像之前，先把它洗一洗、调一调、修一修。**

> 生活比喻：你拍了张照片要去打印。打印前你会先"调色、去噪、裁掉边角、转成黑白"。这些"打印前的准备动作"就是预处理。视觉软件里一模一样——拿到一张图，先做一堆固定的"洗图"步骤，再交给后面的检测算法，效果会好一大截。

它在流程里的位置（归在 **「图像处理」** 分组）：

```
[图像采集] → [创建 ROI] → [图像预处理] → [Blob 分析] / [模板匹配] / [OCR] / [码读取] → …
                          ↓
           输出：Image（洗好的图）+ StepCount / ActiveCount / ActiveOperators（链状态）
```

**一句话**：模板匹配解决"目标在哪"，Blob 解决"有没有缺陷"，而**预处理解决"图干不干净、好不好认"**——它是几乎所有视觉算法的**前置公共水管**。

**和创建 ROI 的区别**：ROI 是"圈一块区域"（回答"看哪里"）；预处理是"对整张（或框内）图做变换"（回答"怎么把图弄清爽"）。两者常串联：先用 ROI 圈出工位，再把 `Domain_` 丢给预处理洗图，最后交给检测。

# 第 1 章 设计思想

## 1.1 核心原理：算子链（Pipeline）

本插件不是"一个算法"，而是"**一串可勾选、可排序、可各自调参的算法步骤**"，业内叫 pipeline（管线/流水线）。

```
输入图
  → [① 转灰度]   ← 勾选 + 调参
  → [② 中值滤波] ← 勾选 + 调参
  → [③ 二值化]   ← 勾选 + 调参
  → 输出图
```

每一步是一个**算子（Operator）**，目前内置 21 个，分成 6 组（色彩/几何/滤波/形态学/增强/二值化）。你像搭积木一样把它们排进链里，每个都能独立开/关、拖顺序、改参数。

**为什么是"链"而不是"一个大算法"**：真实产线上，不同产品、不同相机需要的"洗图动作"千差万别——有的只要转灰度，有的要"去噪+二值化+形态学填空洞"。把算子拆开、让用户自由组合，一套插件覆盖无数场景。

## 1.2 三条铁律（工程上最关键的约定）

**铁律①：禁用 = 原样透传**

关掉某个算子，它必须**什么都不做、把图原样往下传**。否则会出现"勾掉一个算子、画面却没恢复"的鬼问题（旧参考实现就踩过：禁用时没给输出赋值，下一个算子拿到的是上上级的陈旧图）。本插件在链引擎里统一保证透传语义。

**铁律②：单个算子出错不拖垮整条流程**

某个算子参数填错抛异常 → **记日志、跳过这一步、图继续往下流**。现场调参时，你不能因为链里某一步填错就"整条流程红掉"。

**铁律③：图像所有权 / 生命周期清晰**

HALCON 的图像（`HImage`）是**非托管资源**，用错会崩或泄漏。本插件约定：每一步"改图就返回新图、输入图归调用方管"；链引擎统一处置；预览阶段"换图那一刻才释放旧图"（旧实现是跑之前就释放，导致画布手里攥着已销毁的句柄）。

## 1.3 开闭原则：加算子 = 只写一个类

新增一个预处理算子，**不用改任何既有代码**——只要新建一个类、打上 `[PreprocessOperator(key, 显示名, 分组, Order=…)]` 特性，元数据的 `OperatorRegistry` 会自动反射扫描、把它加进菜单。这是"对扩展开放、对修改关闭"的标准做法。

## 1.4 存盘：弱类型快照（不写死类名）

链要随方案保存。做法不是序列化整个算子对象（会焊死 CLR 类名，方案文件极脆），而是存**"算子 Key + 参数字典"**的弱类型快照（`OperatorStepItem`）。好处：单条参数加载失败只跳过那一项、不会卡死整个方案；不认识的 Key 也能安全跳过并提示。

## 1.5 预览后台化：别让界面卡死

一条链在 UI 线程同步跑会卡死窗口（对比度算子默认 101×101 掩膜，一次 `illuminate` 在大图上就是秒级；而参数框是逐字符触发刷新的）。本插件把预览拆成三段：① UI 线程**拷一份**原图；② 后台线程跑链；③ 回 UI 线程换图（此刻才释放旧图）。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | 图像预处理 |
| `GroupName` | 图像处理 |
| `Description` | 串接色彩/几何/滤波/形态学/增强/二值化算子，支持逐步预览与单步启停 |
| `ShortName` | 齿轮图标（FontAwesome `f085`） |

> 这个类**身兼两职**：① 流程节点（`RunAlgorithm` 正式执行）；② 配置界面的 ViewModel（算子链、逐步预览、增删改命令）。宿主对"配置"和"编译执行"各造一个实例。

## 2.2 端口完整清单（均为固定端口）

| 端口 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `SrcImage` | 入 | HImage | 输入图像（可连上游，也可在界面用变量/路径指定）。**不连线会直接 Fail** |
| `Image` | 出 | HImage | 预处理后的图像（端口名就是 `Image`） |
| `StepCount` | 出 | int | 链上算子总步数 |
| `ActiveCount` | 出 | int | 实际启用的算子步数 |
| `ActiveOperators` | 出 | string | 生效算子名串（按执行顺序用 `→` 连接；全禁用时显示 `(全部禁用)`） |

> 运行末尾统计：`ActiveOperators.Value = active.Count == 0 ? "(全部禁用)" : string.Join(" → ", active)`。下游可用 `StepCount`/`ActiveCount` 判断链是否真的在干活。

## 2.3 配置项（随方案保存）

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `DisplayViewIndex` | int | 1 | 显示窗口：`0=不显示，1~9=主界面视图号` |
| `Chain` | `List<OperatorStepItem>` | 空 | 算子链存盘快照（弱类型：`Key + Enabled + 参数字典`）。界面真正用的是 `Operators`，两者靠 `WriteChain()` / `RebuildOperators()` 双向同步 |

> `Operators`（`ObservableCollection<PreprocessOperator>`）**不贴 `[StepConfig]`**——它带 HImage/事件，序列化进去只会出事。`Chain` 只是它的"落盘影子"。

## 2.4 21 个算子参数速查（6 组）

> 每个算子都能独立**启用/禁用 + 调参**。下文给出每组的算子、关键参数与默认值。

### 组 1 · 色彩与通道
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 彩色空间转换 | `color` | `Mode`(Gray/SplitChannel/HSV/HSI/YUV/CIELAB，默认 Gray)、`Channel`(1/2/3 基，默认 First) | 转灰度（`rgb1_to_gray`）/ 分通道（`decompose3`+Pick）/ 其它（`trans_from_rgb`）。**单通道图直接透传**（旧版会把灰度图转成黑图，已修） |

### 组 2 · 几何调整
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 图像镜像 | `mirror` | `Mode`(水平/垂直/对角，默认水平) | `mirror_image` |
| 图像旋转 | `rotate` | `Angle`(90/180/270，默认 180) | `rotate_image`（**不改画布大小**，超界裁掉） |
| 修改图像尺寸 | `change_format` | `Width`/`Height`(0=沿用原尺寸) | `change_format`；尺寸没变即透传 |
| 按比例缩放 | `zoom_factor` | `RowFactor`/`ColFactor`(默认 1.0，`[RangeValidation(0.01,20)]`)、`Interpolation`(最近邻/双线性/双三次，默认双线性) | `zoom_image_factor` |
| 固定框裁剪 | `crop_box` | 框（Row/Col/Width/Height） | `crop_part`；框盖满整图透传。**链内一步**，可放在去噪后、二值化前 |
| 框外屏蔽 | `mask_box` | `OutsideGray`(0~255，默认 0) | 框内保留、框外填灰，尺寸不变 |

### 组 3 · 滤波
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 均值滤波 | `mean` | `Width`/`Height`(默认 5×5) | `mean_image` |
| 中值滤波 | `median` | `MaskType`(方/圆/菱，默认方)、`Radius`(默认 5，`[1,50]`)、`Margin`(镜像/循环，默认镜像) | `median_image` |
| 高斯滤波 | `gauss` | `Size`(默认 5，必须 ≥3 奇数，自动 +1 收敛) | `gauss_image` |

### 组 4 · 灰度形态学
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 灰度膨胀 | `gray_dilation` | `Width`/`Height`(5×5) | `GrayDilationRect`（先膨胀，亮处扩张） |
| 灰度腐蚀 | `gray_erosion` | 同上 | `GrayErosionRect`（先腐蚀，暗处扩张） |
| 灰度开运算 | `gray_opening` | 同上 | `GrayOpeningRect`（**先腐蚀后膨胀**，去亮噪点） |
| 灰度闭运算 | `gray_closing` | 同上 | `GrayClosingRect`（**先膨胀后腐蚀**，填暗孔洞） |

> ⚠️ 这一族参数顺序是 `(Height, Width)`，**别顺手按 W,H 传**。

### 组 5 · 图像增强
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 锐化 | `emphasize` | `Width`/`Height`(7×7 奇数)、`Factor`(0~50，默认 1.0) | `emphasize` |
| 对比度 | `illuminate` | `Width`/`Height`(101×101 奇数)、`Factor`(0~1，默认 0.7) | `illuminate`（端点会抛异常，自动 `Clamp(0.01,0.99)`） |
| 亮度调节 | `brightness` | `Multiplier`(默认 1.0)、`Addend`(默认 0) | `scale_image`（out = in × Mult + Add） |
| 反色 | `invert` | 无 | `invert_image` |
| 直方图均衡 | `equ_histo` | 无 | `equ_histo_image`（三通道原生支持） |

### 组 6 · 二值化
| 算子 | Key | 关键参数（默认） | 做什么 |
|---|---|---|---|
| 二值化 | `threshold` | `Low`(128)、`High`(255)、`Reverse`(false) | `threshold` + `region_to_bin`（命中=255；反转=0） |
| 均值二值化 | `var_threshold` | `MaskWidth`/`MaskHeight`(15×15)、`StdDevScale`(0.2)、`AbsThreshold`(2)、`Mode`(Light/Dark/Equal/NotEqual，默认 Light) | `var_threshold` + `region_to_bin`（明暗不均图更稳） |

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **预览后台化** | 拷图→后台跑链→回 UI 换图（换图才释放旧图） | ⭐⭐⭐ 大图调参不卡窗口 |
| **禁用透传** | 链引擎统一保证 | ⭐⭐⭐ 关掉算子画面立即恢复，无陈旧图 |
| **单算子失败隔离** | 异常→记日志→跳过→图继续流 | ⭐⭐⭐ 调参不红整条流程 |
| **开闭原则** | 新算子只写一个类 + 特性，注册表反射 | ⭐⭐ 扩展零改动 |
| **弱类型快照** | `Key + 参数字典` 落盘 | ⭐⭐ 单参失败不卡方案、不焊死类名 |
| **生命周期所有权** | 改图返回新图、统一 Dispose | ⭐⭐ 不崩不泄漏 |
| **枚举写死数值** | 所有参数枚举成员写死值 | ⭐ 方案存盘按数值写 JSON，中途插删成员会错位（这是"最难查的事故"，见 4.6） |

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.PreProcessing.dll`。
2. 依赖 HALCON 原生库（随软件分发）。
3. 首次使用前关掉宿主 VisionMaster 进程再生成（运行中的程序锁着 `UI.dll` 和插件 DLL）。
4. 重开软件，工具箱里出现「图像预处理」（**图像处理** 分组）。

## 3.2 配置界面总览（三栏）

```
┌──────────┬─────────────────────────────┬──────────────────────────┐
│ 左 240   │ 中 预览（*MinWidth=300）       │ 右 360                    │
│ 图像输入  │ 原图/输入图/算子输出 三单选     │ 处理链 ListBox            │
│ SrcImage  │ + 导出图片/刷新 按钮           │ 步号+启用+名称+Summary     │
│ 绑定     │ + ImageEdit 画布（带框算子用）  │ 上移/下移/删除/清空        │
│ 显示窗口  │ + 提示行                      │ 复制整链/粘贴到链尾        │
│ 下拉     │                              │ ─────────────────        │
│ 算子库    │                              │ 算子参数 FlatPropertyGrid  │
│ （反射分组）│                             │ （反射生成，插件零参数代码） │
└──────────┴─────────────────────────────┴──────────────────────────┘
```

> 配置窗默认 880×600 装不下三栏，视图 `Loaded` 时**只放大不缩小**地撑到约 1120×620，并以工作区为上限、把位置夹回可视范围（防止确认按钮点不到）。

## 3.3 第一次配链（5 步）

**第 1 步｜接图**：把前级（图像采集 或 创建 ROI 的 `Domain_`/`Crop_`）图像连到 `SrcImage`。或在左栏用变量/路径指定一张本地图作底图。

**第 2 步｜加算子**：在左栏"算子库"点你想要的处理名 → 追加到链尾（如"转灰度""中值滤波""二值化"）。

**第 3 步｜排序/开关**：右栏 ListBox 拖动调整顺序、勾选/取消启用。停用的步整行半透明（0.4）。

**第 4 步｜调参**：选中某步 → 右下 `FlatPropertyGrid` 反射出该算子的参数控件，按需调整（如二值化的 Low/High）。

**第 5 步｜看预览 / 保存**：中栏选"算子输出"看本步结果；确认后点「确定」落盘。把"显示窗口"设 1~9 可把洗好的图发布到主界面。

## 3.4 带框算子（裁框 / 屏蔽框）

`crop_box`（固定框裁剪）和 `mask_box`（框外屏蔽）是**带框算子**：选中后中栏画布自动切到"输入图"态，出现可拖拽矩形，松手即重算。框盖满整图时前者透传；后者把框外统一填成 `OutsideGray`（默认 0=黑）。

> 与创建 ROI 的"动态端口裁剪"不同：这里框是**链内一步**，可以排在"去噪之后、二值化之前"，灵活度更高。

## 3.5 复制 / 粘贴 / 导出

- **复制整链 / 粘贴到链尾**：把当前链（含参数、框）搬到剪贴板，粘到另一个实例链尾（验证过 7→14 步追加正确）。
- **导出图片**：把链上每一步的输出各导一张 PNG + 一份 `.txt`+`.json` 清单（透传/禁用步不出文件；无 `.png.png` 重复后缀）。用于离线排查"到底是哪一步把图洗坏了"。

## 3.6 典型链示例（缺陷检测前置）

```
采集图 → [转灰度] → [中值滤波 5×5] → [二值化 128~255] → 输出
```

更稳的明暗不均场景：

```
采集图 → [转灰度] → [高斯 5] → [均值二值化 15×15, Light] → [灰度闭运算 5×5] → 输出
```

## 3.7 参数调节速查表

| 你想做 | 调哪里 |
|---|---|
| 彩色图送给只认灰度的下游 | 加 `color`（Mode=Gray） |
| 去椒盐噪点 | 加 `median`（中值）或 `mean`（均值） |
| 去高斯噪点/轻微模糊 | 加 `gauss` |
| 把图变黑白、提取目标轮廓 | 加 `threshold`（或明暗不均用 `var_threshold`） |
| 填小孔洞 / 去小亮斑 | 加 `gray_closing`（填空洞）/ `gray_opening`（去亮噪） |
| 图像太暗/太亮 | 加 `brightness` 或 `illuminate` |
| 只保留框内、框外涂黑 | 加 `mask_box` |
| 只取框内一小块 | 加 `crop_box` |
| 倒镜像 / 转正 180° | 加 `mirror` / `rotate` |
| 关掉某步看前后对比 | 取消该步"启用"即可（画面立即恢复） |

## 3.8 FAQ

**Q1** 关掉一个算子，画面为什么没变化？
应该立即恢复成"没这步"的样子（禁用=透传）。若没恢复，是旧参考实现的 bug，已修；如仍异常请检查该步是否真的被取消勾选。

**Q2** 某个算子参数填错，整条流程会红吗？
不会。该步记日志、跳过，图继续往下流（铁律②）。

**Q3** 彩色图转灰度后变全黑？
旧版 bug（把灰度图又当彩色转换），已修：单通道图直接透传。确认用的是新版本。

**Q4** 预览卡顿/窗口僵住？
已后台化；若仍卡，多半是图太大 + 对比度算子默认 101×101 掩膜，调小 `Width/Height` 或先缩小图。

**Q5** `ActiveOperators` 显示 `(全部禁用)`？
链上所有算子都被取消启用了——等于原图直出。下游拿到的就是未处理图。

**Q6** 导出的 PNG 尺寸和预期不一致？
核对越界夹取（见 4.6 节）：`crop_box` 框超出图像边界时，越界处填 0，导出尺寸按你设的框尺寸，不是图像有效区。

## 3.9 现场排障

| 现象 | 排查 |
|---|---|

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与迁移文档）。每条给：现象 → 原因 → 修法。本插件**暂无 FlowCanvasChecks 专属断言文件**（见 5.5），41 项断言在已删除的离线脚手架中。

## 4.1 算法正确性类（最致命）

### ① 灰度膨胀 / 腐蚀接反（经典 bug，已修）

**现象**：选"灰度膨胀"实际跑的是腐蚀、选"灰度腐蚀"跑的是膨胀——图像越处理越反。

**原因**：旧参考实现的 switch 里两个分支的算法整个接反了。

**修法**：改成"一个算子一个类"，膨胀类里只可能调到膨胀、腐蚀类里只可能调到腐蚀——**从结构上消灭这类错误**（开闭原则的副产品）。

### ② 禁用算子不释放 → 陈旧图（已修）

**现象**：勾掉某个算子，画面没恢复，像是"还在生效"。

**原因**：旧实现禁用时**不给输出赋值**，下一个算子拿到的是"上上级"的陈旧图像。

**修法**：链引擎统一保证"禁用 = 原样透传"。

### ③ YUV 映射错（已修）

**现象**：选 YUV 实际跑的是 HSI，颜色空间错乱。

**原因**：旧版 ColorSpaceName 映射错。

**修法**：按 `trans_from_rgb` 真实支持的 ColorSpaceName 逐项映射。

### ④ `median_image` 的 Margin 语义错（已修）

**现象**：中值滤波边缘处理不对。

**原因**：旧版把"模板高度"传给了 `margin`（边缘扩充方式）参数。

**修法**：改回正确语义（镜像/循环边缘处理）。

### ⑤ 前景极性矛盾（已修）

**现象**：`threshold` 与 `var_threshold` 的"命中区域"一个 255 一个 0，下游接到一会儿白一会儿黑。

**修法**：统一"命中区域为白（255）"，`Reverse` 才反转成 0。

### ⑥ 灰度图转彩色变黑（已修）

**现象**：单通道灰度图过 `color` 算子变全黑。

**原因**：旧版对灰度图仍走彩色转换路径。

**修法**：单通道图直接透传（没色彩空间可言）。

## 4.2 生命周期 / 预览类

### ⑦ 预览卡死窗口（已重构）

**现象**：点一个算子或改一个参数，整个窗口僵住一两秒。

**原因**：整条链在 UI 线程同步执行（对比度默认 101×101 掩膜一次就是秒级；参数框逐字符触发刷新）。

**修法**：拆成三段——UI 拷图 → 后台跑链 → 回 UI 换图（**换图那一刻才释放旧图**，旧实现跑之前就释放，画布攥着已销毁句柄）。

### ⑧ 单个算子出错拖垮流程（已修）

**现象**：链里某步参数填错，整条流程红掉。

**修法**：异常 → 记日志 → 跳过该步 → 图继续往下流（铁律②）。

### ⑨ 配置窗初始尺寸不对 / 右侧被裁（上机反馈修复）

**修法**：`Loaded` 时 `EnlargeHostWindowIfNeeded()` 只放大不缩小地撑到 1120×620+壳，以工作区为上限夹回位置。

### ⑩ 流程线程与配置界面共用 `Operators` 无锁（上机反馈修复）

**现象**：运行期并发读写链集合可能崩。

**修法**：`RunAlgorithm` 里先用 `ToArray()` 拍快照再遍历，断开与配置界面的共享引用。

## 4.3 实测细节类

- **参数越界提示要失焦才出现**：越界校验在参数提交时触发，文本框仍聚焦时提示不弹（已知边界）。
- **步号依赖 `AlternationIndex`**：ListBox 的 `AlternationIndex` 在项数 >1000 时有重号风险（理论边界）。
- **框只支持正矩形**：带框算子目前只做轴平行矩形，不支持旋转框。

| 灰度图 | 单通道、0~255 的黑白图 |
| 通道 | 一张图几个数/格。1=灰度、3=RGB |
| 二值化 | 把图变成"0 或 255"的黑白图（提取目标） |
| 形态学 | 用结构元"腐蚀/膨胀"修图像（开=去亮噪，闭=填暗孔） |
| 直方图均衡 | 拉开明暗对比，让暗处也看得清 |

| 术语 | 含义 |
