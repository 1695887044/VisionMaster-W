### 5.2 需要修正的一处（上轮不准确）

**P2「Plugin.Calibration 标定源图接 image 资产」的落地建议不可直接实现。**

`ProjectAssetPathResolver.TryResolve` 的契约只返回**单个文件的 `AbsolutePath`**（ProjectAssetResolver.cs:169-175）。而 `IntrinsicsImageFolder`（CalibrationPlugin.cs:474）是**一个文件夹下 N 张图**、`IntrinsicsImageList`（487）是内嵌多行路径列表。因此：

- 单图情形（`SourceImagePath`，九点 / 透视的点选底图）→ 可以接 image 资产；
- 批量内参标定（文件夹 / 图列表）→ **不能**用一个 image 资产表达，需要新 Kind（图集 / 清单）或维持目录路径。

上轮写成「照抄 ImageAcquisition 范式即可」是不准确的，应按上面两种情形分开决策。

### 5.3 上轮漏掉的一处（新发现，优先级 P1）

**模型资产导入新版本后，进程内已加载的推理会话不会失效。**

- 版本导入是**原地覆盖同一路径**：`TryImportNewVersion` 把新文件 `File.Move(tempPath, activePath, overwrite: true)`（ProjectAssetImporter.cs:266-270），`asset.RelativePath` 不变。
- 四个插件（Yolo / DlClassify / DlSegment / DlAnomaly）的会话缓存**只按路径做键，不校验 mtime / 大小 / 哈希**：`YoloSession.cs:81-90`、`ClassifySession.cs:79-107`、`SegmentSession.cs:174/200`、`AnomalySession.cs:143-147`。
- 后果：在资产页导了 v2，正在跑的进程仍用 v1，直到重启。资产版本库把「同路径换内容」变成常规操作，这条缺口因此从「理论可能」变成「产品内一步可达」。
- 修法：缓存键加 `(mtime, size)` 或内容哈希（本地改动，四个插件同款）。**不要**指望 `AssetVersionEvent` / `ISolutionAssetHistorySink` 做失效通知——它是审计历史（Append/Read，AssetVersionEvent.cs:31-43），不是事件总线，当前无任何插件订阅。
- 对照：模板 / 模型 **JSON** 类资产不受影响（Matching 每轮 `File.ReadAllText` 重读，1863→1788；Deformable 983 同款）。

### 5.4 修正后的优先级

| 优先级 | 插件 | 更新点 |
|---|---|---|
| P1 | Yolo / DlClassify / DlSegment / DlAnomaly | 会话缓存键加 mtime/size（或哈希），否则资产导新版本不生效（§5.3） |
| P1 | Plugin.HandEye | 手眼结果入 `ICalibrationCatalog` + 资产页 TypeLabel 补 HandEye 分支（§二，复核成立） |
| P2 | Plugin.Calibration | 单图情形接 image 资产；**文件夹 / 图列表需新 Kind 或维持目录**（§5.2 修正） |
| P2 | Plugin.Matching / Plugin.DeformableMatching | 条目级 `RefImagePath` 仍是本机绝对路径（库 JSON 作为资产时，跨机器重学会断） |
| 记录 | Plugin.Calibration | `CaltabDescrFile` 全路径形式需新 Kind（自制标定板） |

### 5.5 顺带发现的小瑕疵（不影响行为）

`IAssetIdConfig` 的 XML 注释写「插件配置壳可识别的资产字段（template / model）」（ProjectAssetResolver.cs:38），实际 image / recipe 也在用同一接口——注释陈旧。
