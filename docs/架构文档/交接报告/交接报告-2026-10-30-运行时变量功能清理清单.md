# 交接报告 — 「运行时变量」功能全仓引用清单（为清理做准备）

> 类型：**只读测绘，未改任何产品源码**。
> 触发：用户决定放弃「运行时变量」功能，要求先列出全部使用位置。
> 扫描口径：`rg` 全仓（排除 `bin/obj/_Retired/artifacts`），关键词
> `运行时变量 / 运行期变量 / RuntimeVariable / RuntimeVariableProxyPort / IContextAwareOutputPort /
> RuntimeVariableMarkerGuid / RuntimeVariableRefs / Scope="Runtime" / ScopeRuntime / RuntimeVariableCatalog`。

---

## 0. 先分清五层（决定清理范围）

「运行时变量」不是一个模块，而是横跨五层的同一条数据链。**删除范围不同，工作量差一个数量级**：

| 层 | 内容 | 关键标识 | 与其他功能耦合 |
|---|---|---|---|
| **L1 协议** | 连线类型 `LinkKind.RuntimeVariable` + 哨兵 Guid | `Shard\Core.Interfaces\LinkReference.cs` | 与 `Constant`/`GlobalVariable` 共用 `LinkProtocol` |
| **L2 引擎** | 代理端口 + 上下文注入 | `RuntimeVariableProxyPort`、`ContextAwareBindings` | 独立，仅服务本功能 |
| **L3 候选/入口** | 绑定弹窗左栏「运行时变量 (Runtime)」节点 + 「变量定义」节点识别 | `FlowQueryHelper.GetRuntimeVariableDefinitions / TryGetDefinedVariable` | 与「全局变量」节点同树 |
| **L4 声明表** | `ConditionStep/WaitStep.RuntimeVariableRefs`（条件表达式按名取值的形参表） | `RuntimeVariableRefs` | 与 `LocalVariables` 并列，编译器参数顺序耦合 |
| **L5 数据池** | `IExecutionContext.LocalVariables`（真正的"运行期变量池"） | `LocalVariables` | **被 4 个插件 + 并行分支记账共用，删它=另一个大工程** |

> **重点提示**：L1~L4 是可以整体摘除的"运行时变量功能"主体；**L5 是底层存储，被「变量赋值 Scope=Runtime」「C# 脚本 SetVar/GetVar」「判定表结果输出」「数据记录/结果上报的变量档」共用**。清理前必须先确认是否连 L5 一起放弃。
