### 0.2 关键取舍：公共层为什么是"每页各一份"

**BasePages 走不通**（实测）：`ScadaDocument.EnsureIdentity` 加载期按**引用**清理
`_basePages`（`_pages.Contains(_basePages[i])`），而 .vms 序列化没有 `PreserveReferencesHandling`
→ 同一张基座页在 `Pages` / `BasePages` 里反序列化成两个实例 → 加载后基座被当"幽灵条目"删掉。
实测：手写两份 JSON、加载后 `BasePages=0`（探针 `BasePageProbe` 验证）。

**Hmi.SubPage 也走不通**：内容能渲染（16/16 TargetPageId 全部可解析），但占位层
（"未找到画面"）与内容层同时可见（产品边角缺陷），且首次渲染早于 PageResolver 注入会闪占位。

**结论**：公共层由生成器 `PairChrome()` 在每页各生成一份（每页约 30 个图元）。
图元/事件/绑定全走"本页"通道，零依赖边角机制。代价是改公共层要改生成器重跑。

#### 0.7.1 工位图像显示链路（新增）

```
算法 → 结果显示（烧标注框 + 判定文字）→ AnnotatedImage 端口
     → 「图像赋值」步骤（Plugin.ImageAssign，InputImage + VariableName）
     → 全局图像变量 XXX_Image（HImage）
     → 组态 Hmi.ImageView 绑该变量
```

- **变量类型必须写 HImage 的完整 AssemblyQualifiedName**
  （`HalconDotNet.HImage, halcondotnet, Version=23.5.0.0, Culture=neutral, PublicKeyToken=4973bed59ddbf2b8`）。

- 换算由宿主 `RegistryScadaValueSource` 做（图元库刻意不引用 HalconDotNet）。
- 真机验证：七条流程均输出 `写工位图像_XXX 已把图像写入全局变量 XXX_Image`，
  组态「自动运行」页七张卡全部显示真实标注图（NCC 0.793 / PCB 0.880 / 标签缺陷 21 / 条码 1 / 二维码 1 / 形变 1.000）。

### 0.8 第五轮：画面外黑边（同日再追加）

用户指出「显示区域外怎么还有黑边」。

**根因**（两处叠加）：

1. `ScadaRuntimeWindow.xaml:476` 的画面区是 `<Grid Grid.Row="1" Margin="16">`，那 16px 边距透出窗口底色 `ScadaRunWindowBrush = #FF16191D`；
2. 等比缩放（适配 45%/58%）后画布 1920×1080 缩到视口内，四周 letterbox 同样透出窗口底色。
   页面底色是 `#FF0E1522`（更深更蓝），两个深色一对比就是一圈明显的黑框。

**修法**（1 行，产品 XAML）：给画面区 Grid 加 `Background="{Binding CurrentPage.Background}"`。
留白与画面同色，视觉上是一条连续的画布；颜色走绑定不硬编码（R140）。

**遗留（可选优化）**：页面外没有网格/光晕（背景图只铺 1920×1080），边界处网格会断开。
要彻底无缝需让运行窗口用 `ImageBrush` 延伸背景图，但那需要窗口侧解析方案内相对路径（现有能力在
`ScadaRuntimeHost` 的 `ImageAssetResolver`，窗口拿不到），属独立批次。

**另一个使用注意**：工位卡的图像是**运行态变量**（`XXX_Image`），重启应用后为 null → 显示"无图像"占位。
必须先跑一轮（执行一次/启动连续）才会出图。这是"运行态数据"的正确表现，不是缺陷。

### 0.10 第七轮：两处残留黑框（同日再追加）

用户截图报「界面外面的黑框 列表标题的黑框」。两个缺陷、两条独立根因。

#### 0.10.1 画面四周的黑框（两处叠加）

| # | 根因 | 修法 |
|---|---|---|
| ① | `ScadaRuntimeWindow.xaml` 画面区是 `<Grid Grid.Row="1" Margin="16">`。Margin 区域属于**父容器**（根 Grid，窗口深灰底 `#FF16191D`），于是画面四周一圈深灰缝 | `Margin="0"`（画面自身的内边距由页面内容的 40px 提供） |
| ② | `ScadaCanvas` 的模板是"外层视口底（`HmiCanvasBackgroundBrush #0E1318`）+ 内层页面矩形（`PageBackground`）"。等比缩放后左右/上下 letterbox 露的是**外层**那个 | `ScadaRuntimeWindow.xaml.cs::ApplyPageBackgrounds()` 里除 `PageHost` 外，再刷 `Canvas.Background` 与 `PopupCanvas.Background` |

> 上一轮只改了 ④（XAML 绑定换成 code-behind 的 `BrushConverter`），只刷了 `PageHost` —— 那只盖住 Margin 内侧，盖不住画布自己的外层视口底。**两处必须同时改。**

#### 0.10.2 列表/报表标题的黑框（模板里写死深色令牌）

`Hmi.DataGrid` 与 `Hmi.Report` 的标题条 / 列头 / 工具栏 / 脚注用的是 `HmiSurfaceRaisedBrush #1B242D`，
正文底用 `HmiSurfaceBrush #151C23`，**模板里写死、没有任何属性可覆盖**；DataGrid 更彻底 ——
描述符里刻意**不声明** `Fill`/`Stroke`（原注释："声明了却不生效等于给用户一个假开关"），
所以生成器往属性包里写 `Fill="#FFFFFFFF"` 也是**死配置**，整张表是一块黑。

改法（控件库层面，向后兼容）：

1. `DataGridElement` / `ReportElement` 各加三个可选依赖属性：
   `HeaderBackground` / `HeaderForeground` / `ZebraBackground`，**默认 null → 回落原深色令牌**（零回归）。
   `OnApplyTemplate` + 属性变更回调把值写到命名模板部件（`PART_HeaderBar` / `PART_ColumnHeader` /
   `PART_HistoryToolbar` / `PART_Toolbar` / `PART_FooterBar` / `PART_HeaderText` / `PART_HeaderCount`）。
2. 模板把写死的令牌换成 `TemplateBinding Fill` / `Stroke` / `Foreground` 与
   `{Binding Foreground, RelativeSource={RelativeSource TemplatedParent}}`；正文格子/斑马纹/工具按钮走
   `RelativeSource AncestorType=local:XxxElement`（DataTemplate 里没有 TemplatedParent）。
3. 主题默认值改放 **Style setter**（`Fill=HmiSurfaceBrush` 等），属性包写的是**本地值**、压得住 Style setter，
   于是"浅色主题只改属性、模板零分支"。
4. `BuiltInElements.cs` 给 DataGrid 补 `Fill`/`Stroke`/`Foreground` 三条描述符（不再是死开关），
   两个图元各补三条新描述符。

本方案给的组合：`Fill=#FFFFFFFF`、`Stroke=#FFE5E7EB`、`Foreground=#FF111827`、
`HeaderBackground=#FFF9FAFB`、`HeaderForeground=#FF111827`、`ZebraBackground=#FFF3F4F6`。

#### 0.10.3 生成器改成可重入

`--pair` 原先无条件往循环体末尾追加"判定表 + 4×变量赋值 + 图像赋值 + 200ms 延时"，

#### 0.10.4 探针出图补两条（否则拍出来的是假缺陷）

### 2. `L()` 连线构造器 vs 已存在步骤 ID

`Program.L(seed, ...)` 是「种子 → MD5 → GUID」；我把已存在的真实 `StepID` 当种子传进去，
生成了全新 GUID → 21 条断链。**修法**：新增 `LById(stepId, ...)` 原样使用 StepID。

### 3. 全局变量链接会打红 `FlowCanvasChecks`

`FlowCanvasChecks\CodeReaderChecks.cs:153-157` 等 5 处直接编译本方案流程，
但**只 `SwitchSolution`、不做 `VariablePersistenceService.Restore`** →
任何 `Kind=2` 全局变量链接都被判 `[连线断开] 找不到全局变量` → 整条流程编译失败。

**修法**：参数联动改用手填值（`For.DefaultLoopCount`），不用全局变量链接。
**代价**：参数页变成"参考值看板"（已在页面上写明）。

### 4. 相对目录账本落到 `bin\History`

`RecordingHub.ExpandTemplate` 展开后按**宿主进程 CWD** 解析相对路径，
而运行态的报表/历史表格按 `<方案根>\History` 锚定（`ScadaRuntimeHost.cs:895`）——
两边不一致时账本落 `bin\History`，组态页永远查不到。

**修法**：账本目录用绝对路径（`SolutionRoot` 全局变量 + 脚本拼路径），两边对齐。

### 5. C# 脚本共享变量必须先声明

脚本里 `Context.GetGlobal<string>("SolutionRoot")` 报
`脚本引用了未声明的共享变量`——**共享变量必须在步骤的 `SharedVars` 表里先声明**，
否则编译期就拒（不是运行期返回 null）。

### 6. PowerShell 中文路径的三次复发（R1/R2）

同一轮里踩了三次：`.ps1` 里写中文字面量 → 被 936 解码成乱码 → 路径找不到。
**唯一可靠写法**：中文路径放进单独 UTF-8 清单文件，脚本用
`[IO.File]::ReadAllLines($f, [Text.Encoding]::UTF8)` 读；`.ps1` 本体纯 ASCII。

### 7. `dotnet run --project X -m:1 ... -- --pair` 会把 MSBuild 参数传给程序

`-m:1` 被当成 `args[0]`，`--pair` 不在首位 → 走了默认分支，
**在 `解决方案\` 下生成了六个不该存在的方案文件夹**（已删除恢复）。
**修法**：构建用 `dotnet build`，运行直接 `dotnet <dll> --pair`。

### 8. `run_gates.ps1` 必须带 `-ExecutionPolicy Bypass` 且参数用 `-Command` 调

`-File ... -StepTimeoutSec 900` 会被 bash 传递破坏；用
`powershell -NoProfile -ExecutionPolicy Bypass -Command "& 'path\run_gates.ps1' -StepTimeoutSec 900"`。

### 9. `run_gates` 的 3 项红是既有红灯（非本次引入）

- `HelpProbe` / `FlowCanvasChecks`：`ScadaPropertyViewModel.cs` 编译错误。
  **该文件 mtime = 09:33:18（本次会话进行中）**，且报错行号（3563）与磁盘当前内容
  （3579 行 `element is not MultiTrendElement`）不符 → **另一个会话正在实时编辑该文件**（R9 情形）。
  按 R9 纪律：只报告、不修改。
- `ScadaWebChecks`：`exit=-532462766`（.NET 未处理异常），其 B1~B4c 前置断言全 PASS，
  属该宿主自身问题，与方案无关。
