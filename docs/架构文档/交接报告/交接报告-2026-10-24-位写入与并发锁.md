# 交接报告-2026-10-24-位写入与并发锁

> 问题：触摸屏（SCADA 运行态 / Web 客户端）对 PLC 位地址（如 `D100.0`）写入是怎么走的？用了什么锁？
> 本轮为**代码走读**，未构建、未跑断言宿主、未接真 PLC。

## 一、当前状态

本仓库对「字寄存器内位地址」的支持**按协议分三种，不是统一实现**：

| 协议 | `D100.0` 这类地址 | 写入实现 | 原子性 |
|---|---|---|---|
| 欧姆龙 FINS | 支持（`FinsAddress.MaxBitOffset = 15`） | HSL FINS 原生位命令（`BuildWriteWordCommand(..., isBit: true)`） | 单报文，原子 |
| 三菱 MC | **当前不支持**（D 区是字区，布尔量只能选位区） | 未开启 HSL 的 `EnableWriteBitToWordRegister`，`D100.0` 写会在地址解析阶段失败 | 无（不成立） |
| Modbus | 不支持寄存器区位写（布尔只能走线圈） | 线圈 FC5/15；寄存器区 Boolean 在地址层被禁止 | 线圈单报文 |

并发保护不是一把全局锁，而是四层各管一段：**Web 命令泵（单消费者）→ UI 单线程 → 变量写租约 → 连接 Worker 单线程**。

## 二、已做（代码核实）

### 2.1 触摸屏（Web）到设备的完整写入链

1. WebSocket 命令 → `ScadaWebHost.cs:2364` `pump.Enqueue(...)`。
2. `ScadaWebCommandPump.cs:12-34`：一个全局有界 `Channel`（容量 1024）+ **单消费者**，逐条投到 UI Dispatcher。目的是让「审计顺序 = 执行顺序」；满时回 `E_BUSY`，不静默丢弃。
3. `ScadaWebCommandRouter` → `IScadaActionDispatcher` → `ScadaActionDispatcher.ExecuteWriteVariable`（`VisionMaster/Services/ScadaActionDispatcher.cs:767`）或 `ScadaValueWriter.TryWriteText`（`VisionMaster/Services/ScadaValueWriter.cs:91`，类注释明确「只在 UI 线程被调用，故不加锁」）。
4. `IWritableVariable.TryWrite` → `NetworkVariableModel.TryWriteToValue`（`:381`）→ `TryWriteCore`。
5. `NetworkVariableModel.cs:814-822`：按 `LeaseKey = $"{ConnectionName}.{Name}"`（`:292`）获取写租约；`AllowSharedWrite` 时跳过。
6. `CommunicationManager.WriteVariable` → `AdvancedCommunicationManager.Write`（`:629`）→ `worker.InvokeWrite(...)`（`:647`，写队列，入队最多等 2000ms）。
7. `ConnectionWorker`：每个连接一个专属线程；四条 `BlockingCollection` 车道（插队写 → 插队读 → 常规写 → 常规读，`:640-660`），`SemaphoreSlim(0,1)` 唤醒（`:85`）。类注释（`:9-23`）写明 HSL 设备对象不是线程安全的，所以全部 I/O 必须串行到这一条线程。
8. `MitsubishiMcConnection.Write`（`:135-140`）/ `OmronFinsConnection.Write`（`:116-120`）→ `HslHelper.WriteTyped`（`HslHelper.cs:204-214`）：`bool` 走 `device.Write(address, bool)`。

### 2.2 位地址在协议库里的实际动作

- **FINS `D100.0`**：`OmronFinsNetHelper.cs:548-565` 用 `BitCode` + `AddressStart%16` 组单条位写命令，**不读改写**。
- **MC `D100.0`**：`MelsecMcNet.EnableWriteBitToWordRegister` 默认 `false`（`MelsecMcNet.cs:60`）。开启后 `McHelper.cs:176-179` 才走 `ReadWriteNetHelper.WriteBoolWithWord`：读整字 → 改位 → 写整字（`ReadWriteNetHelper.cs:13-17` 明确写 3~10ms 脏数据风险）。未开启时 `McAnalysisAddress("D100.0", isBit:true)` 在 `ParseMelsecFrom` 里按十六进制解析 `"100.0"` 失败。
- **MC 读写不对称**：`McHelper.ReadBool` 对含 `.` 的地址无条件走 `HslHelper.ReadBool`（读字取位，`HslHelper.cs:620-647`）；写则要开关。所以 `D100.0` 可能「读得到、写不进」。
- **第一方地址模型**：`McAddress.Validate`（`:121-136`）禁止 D/W/R/ZR 区配 Boolean；`McAddress.BuildAddress`（`:88-95`）根本不拼 `BitOffset`。`MitsubishiMcConfig` 也没有对应开关。
- **FINS 第一方地址模型**：`FinsAddress.MaxBitOffset = 15`（`:38`）、`BuildAddress` 拼 `D100.0`（`:45`）、布尔量必须带位偏移（`:75-76`），位地址不批量、走单点读写。

### 2.3 锁清单（按层）

| 层 | 机制 | 保护对象 | 位置 |
|---|---|---|---|
| Web 命令 | `Channel` 单消费者 + UI Dispatcher | 命令全序、审计顺序 | `ScadaWebCommandPump.cs:97-107` |
| 变量 | `WriteLeaseRegistry` 的 `lock (_gate)` | 同一变量同时只有一个 owner（流程 / 手动） | `Core/Services/WriteLeaseRegistry.cs:31,52-89` |
| 连接管理 | `AdvancedCommunicationManager._connectionsListLock` | 连接/Worker 列表增删 | `AdvancedCommunicationManager.cs:103,191,245...` |
| 设备 I/O | 每连接单 Worker 线程 + 四队列 | 同一 socket 不并发两个事务 | `ConnectionWorker.cs:66-85,640-660` |
| 自由协议 | `FreeProtocolConnection._ioLock` | 「发一条收一条」 | `FreeProtocolConnection.cs:186-219` |
| Web 会话 | `ScadaWebLease` / `ScadaWebRateLimiter` / `_stateGate` 的 `lock` | 会话占用、限流、宿主状态 | `ScadaWebLease.cs:49...`、`ScadaWebRateLimiter.cs:116...` |

## 五、踩过的坑

- **HSL 位读写不对称**：`ReadBool("D100.0")` 开箱可用，`Write("D100.0", true)` 在 MC 上要 `EnableWriteBitToWordRegister`，否则报地址解析失败——容易被误判成「地址写错了」。
- **读改写不是事务**：即使开启开关，读与写是两条报文；PLC 自身程序或另一台触摸屏在这 3~10ms 内改同一字的其它位，写回会把对方覆盖。项目内 Worker 串行只能挡住本进程自己的流量，挡不住另一个主站。
- **写租约键是变量名，不是地址**：两个变量对象指向同一 `D100` 不会互斥；绕过 `NetworkVariableModel` 直接 `CommunicationManager.Write` 也不受租约保护。
- **手动写租约不主动释放**：`manual` owner 写入后靠 30 秒超时回收（`2026-10-21-数组写入重构与逐元素换算.md:149,195`）；手动写后 30 秒内流程写同一变量会被拒。同一 owner 重复获取是允许的，所以触摸屏连点不会被自己挡住。
- **不要用一把全局锁替代 Worker**：HSL 设备对象非线程安全是结构性的，单连接单线程才是正确边界；全局锁会把不同连接也串起来，轮询延迟直接放大。
