## 1. 当前状态

底部那块区域实际是**一个** `LayoutAnchorablePane`（`VisionMaster/Shell.xaml:1637-1657`），里面有三个页签：

| 页签 | ContentId | 内容 | 状态 |
|---|---|---|---|
| 日志信息 | `Panel_LogView` | `Views.LogView`，内含 `UI.CustomControl.LogConsole`（搜索 / 等级筛选 / 跟随最新） | 已实现 |
| 监控栏 | `Panel_MonitorView` | `Views.MonitorView` + `MonitorViewModel`（方案 `WatchItems` 的变量/端口实时值，按全局变量/输入/输出三组） | 已实现 |
| 设备状态 | `Panel_DeviceStateView` | **无**（XAML 自闭合空标签；`ContentFactories` 里明确写「占位面板，无内容」） | 空壳 |

「控制台」在全仓**没有第二个窗口或面板**，它是这整块 pane 的容器名，出现在三个地方：

1. 状态栏右下按钮 `>_ 控制台`（`Shell.xaml:2257-2273`）→ `ToggleConsoleCommand` → `LayoutHelper.ToggleConsole`（`LayoutHelper.cs:831-845`）：**只把同一个 pane 的高度在 32 ↔ 240 之间切换**，不动可见性、不切页签。
2. 视图菜单「控制台」（`Shell.xaml:898-907`）→ `ShowPanelCommand` → `ShowPanel("Panel_LogView")`：显示/激活的就是**日志信息**那个页签。
3. 命令面板（`ShellViewModel.cs:783`）→ 同 `ToggleConsole`。

设计基线确认这层命名是**有意**的：`docs/UI设计基线/app-shell/README.md:51` 把底部面板写作「控制台（日志 / 监控 / 设备）」，`:165` 记了术语收口「`日志信息` → `控制台`」。`UIThemeSmokeTest/Program.cs:1722-1728` 还把「控制台」写进了术语收口断言。

## 2. 已做（本轮结论）

**不是四份重复数据，但有三类真冗余 + 一处与基线不符。**

### A. 控制台 vs 日志信息：同一块面板两套叫法、两个入口
- 名称层面：容器叫「控制台」，可见页签叫「日志信息」，界面上没有任何一处把两者连起来。用户看到状态栏「控制台」+ 页签「日志信息」，自然读成两个东西。
- 入口层面：状态栏按钮（32↔240）与页签栏自带的 ▼（AvalonDock 自动隐藏）做的是同一件事的两种做法，且两者不共享状态（一个改高度、一个改可见性），收起后再点另一个会出现「高度是 32 但内容被自动隐藏」这类叠加态。

### B. 监控栏：不冗余
数据源与日志完全无关——`MonitorViewModel` 读的是方案里的 `WatchItems`，订阅端口 `ValueChanged` 实时刷新（`MonitorViewModel.cs:63-67`）。日志是 `ILogService` 的事件流。两者是「看值」与「看事件」的分工，应保留。

### C. 设备状态：空壳，真冗余
- `Shell.xaml:1656` 是自闭合空标签，`LayoutHelper.cs:116` 注释「占位面板，无内容」，`ContentFactories`（`:100-117`）里没有它，全仓也没有 `DeviceStateView` 类 → 点开是白板。
- 设备状态的数据其实已经存在：`CommunicationDeviceStateSource.Snapshot()`（`CommunicationDeviceStateSource.cs:30-77`）把它翻译成系统变量。
- 设计基线把它安排在别处：`app-shell/README.md:109-110` 明确「运行场景只保留控制台页签……设备在线信息已在 KPI 卡里」。而驾驶舱那张 KPI 卡目前也是写死的占位（`RunCockpitView.xaml:281-286`：值 `—`、副标题「待接入设备状态」）。
- 即：设备状态的**正确落点是驾驶舱 KPI 卡**，底部页签是重复落点且没实现。

### D. 顺带发现：视图菜单两个死入口
`Shell.xaml:908-927` 的「数据栏」`Panel_DataView` 与「模块输出」`Panel_ModuleOutView`，这两个 ContentId 在 `Shell.xaml` 里已不存在，只在 `LegacyContentIdMap`（`LayoutHelper.cs:122-126`）里作为**旧布局迁移**映射保留。`ShowPanelCommand`（`Commands/ShowPanelCommand.cs:15-21`）只按 ContentId 在当前树里查，查不到就 `return` → **点了静默无反应**。

### E. 顺带发现：收起态与基线不符
基线 `app-shell/README.md:96-104` 要求：
- 默认 32px 抽屉头（三页签 + 计数 + 最近一条摘要 + `…` + 展开箭头），展开 240；
- 故障自动展开；点页签也展开。

现状：
- 默认高度是 **200**（`Shell.xaml:1637`），不是 32；
- 32px 态只是 AvalonDock 页签条被压扁，**没有计数、没有最近一条摘要、没有展开箭头**；
- **没有故障自动展开**：全仓 `DockHeight` 的写入点只有 `ToggleConsole` / `CollapseLogPane` / `RestoreLogPane` 三处，没有任何 error 级别日志 → 展开的接线；
- 点页签不展开。

## 7. 落地结构决定：抽屉条挂主窗口层（2026-10-26）

**结论：抽屉条的父容器是主窗口（`Shell.xaml` 根 Grid 新增一行），不是视图（LogView / 新的 ConsoleView）。**

**决定性证据（反射 `Dirkster.AvalonDock 4.74.1` 的 `net48` 程序集）**

- `LayoutDocumentPane` 有 `ShowHeader` 属性；`LayoutAnchorablePane` **没有**，`LayoutAnchorablePaneControl` 也没有任何 Header/CanShow 成员（全程序集搜 `Header|CanShow` 只命中 `LayoutContent.CanShowOnHover` 与文档面板的 `ShowHeader`）。
- 即：只要面板还在停靠树里，库就一定画自己的页签条，且没有开关能关掉。抽屉头若放进视图内容，32px 高度里露出来的只有库的页签条，自定义头看不见；要露出来只能改 `LayoutAnchorablePaneControl` 的模板（模板编译在 `AvalonDock.Themes.VS2013` 里，仓库无源），属于改库模板。

**由此确定的结构**

| 状态 | 谁在画 | 高度 |
|---|---|---|
| 收起 | Shell 根 Grid 新增的 32px 行（`ConsoleDrawerBar`：页签 + 计数 + 摘要 + 箭头） | 面板 `DockHeight` 压到 1（复用 `CollapseLogPane` 的 `_savedLogPaneHeight`），抽屉行可见 |
| 展开 | AvalonDock 面板自己的页签条 + 内容 | 面板还原 240，抽屉行隐藏 |

点抽屉行上的页签 = `LayoutHelper.ShowPanel(contentId)` + 展开；点箭头 = `ToggleConsole`。

**必须注意的四点**

1. **状态只有一个事实源**：新增 `ShellViewModel.IsConsoleCollapsed`，由「状态栏按钮 / 抽屉箭头 / 抽屉页签 / 运行场景进入 / 组态隐藏」五条路径共同改写；`LayoutHelper` 只做输出（改 `DockHeight`、藏面板）。**不要再用 `DockHeight > 60` 反推展开态**——用户把分隔条拖到 50px 就会判错，现在的 `ToggleConsole` 正是这么判的。
2. **摘要与计数要复用同一份数据**：`LogViewModel` 订阅的是具体类 `LogService.OnLogReceived`，每个实例各收一份。抽屉若自己 new 一个 `LogViewModel`，计数在达到 `LogPanelMaxRows` 上限后会和日志页的「全部 N」分叉。要么把 `LogViewModel` 注册成容器单例给两处共用，要么抽屉只订阅 `LogService.OnLogReceived` 维护「最后一条 + 错误数」的轻量状态。监控计数直接读 `IWorkspaceManager` 的 `WatchItems`，不要去拿 `MonitorViewModel`。
3. **展开态没有摘要条**（这是本决定的代价）：库页签条接管后，计数可以用 `DockingManager.AnchorableHeaderTemplate` 塞进页签（「控制台 56」），但摘要与箭头没有位置。若一定要"展开也保留摘要条"，就得把控制台整体移出 AvalonDock 由 Shell 托管——代价是布局持久化自建、`ShowPanel` 命令链、R56/R58 面板收敛、`UIThemeSmokeTest` 与 `LayoutVisibilityCheck` 等四个断言宿主、`ShellCopy.xaml` 全部要改，不建议为一条视觉连续性付这个。
4. **闸门影响**：只新增一行非停靠行，停靠树没变 → **不升** `LayoutHelper.CurrentLayoutSchemaVersion`（R43 判据是"旧布局恢复会不会抵消改造"，这里不会）；但 `Shell.xaml` 的根 Grid 行号变了（状态栏 `Grid.Row` 3 → 4），`ShellCopy.xaml` 必须同步（R44/R70），`RunShellLayoutChecks` 里按行号/位置写的判据要复核。

### 7.1 落地结果：上面第 1 条的前提是错的（同日返工）

本节写"面板 `DockHeight` 压到 1"——**真机证明这条路不通**：AvalonDock 的页签条有约 20px 最小高度，
`DockHeight=1` 只压面板框，页签条照旧画在面板外（`ClipToBounds` 默认 false），
屏幕上就是抽屉条上方多一条重复的「控制台 / 监控栏」。

试过并否掉的方案：① 运行时给该 pane 控件设 `ClipToBounds=true`（无效，溢出的是面板自身最小高度）；
② 抽屉条覆盖在停靠区底部 32px 上（停靠区横跨三列，会把流程导航/工具箱底部一起盖住）。

**最终实现：收起 = 把整块 `LayoutAnchorablePane` 从父容器摘下缓存，展开 = 原父容器原索引插回。**
- `SaveToString` 序列化前临时插回、之后恢复原状态（否则收起状态退出会让 `Layout.xml` 丢掉控制台）。
- `ShowPanel` 在控制台收起时先展开再按 ContentId 查（否则视图菜单「控制台/监控栏」点了没反应）。
- 抽屉页签点击 = 先展开，**下一次布局之后再切页**（同步切会被库的选中项回填覆盖，真机实测"点了监控栏还是日志页"）。
- 因此 **布局结构版本升到 7**（本节第 4 条说的"不升"不再成立；升版同时用于淘汰带 `Panel_DeviceStateView` 的旧布局）。

细节与验证见 `docs/code-changes/2026-10-26-底部控制台抽屉条与页签清理.md`。
