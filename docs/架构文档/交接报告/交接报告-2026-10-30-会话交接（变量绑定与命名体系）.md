## 2. 关键认知修正（避免重走弯路）

### 2.1 「取值」vs「写名」是两件事（前版方案在这里搞错了）

| | 取值（读） | 写名（写） |
|---|---|---|
| 数据形态 | 一个**值** | 一个**键**（变量名/Id） |
| 实现路径 | `InputPort.LinkedSource` → `LinkReference` → `LinkedSources` | `TryWrite(name)` / `LocalVariables[name]=` |
| 能否用绑定弹窗 | ✅ 弹窗产物就是 `LinkReference` | ✅ 但**只取 `TargetPortName`/`TargetVariableId`**，绝不写 `LinkedSources` |

**代码依据**：`UploadFieldDef.cs:31` 注释"字段的**取值**来源"；`ResultUploadPlugin.cs:690` 是 `TryResolveVariable` 读值；`RecordColumnDef.cs:12` "从 LocalVariables **按名取值**"。
**单绑定模式不写模型的证据**：`VariableBindingViewModel.cs:793` `if (!IsSingleBindMode && _targetStep != null)`；探针 C27.11 实测 `LinkedSources.Count == 0`。

### 2.2 全仓"变量下拉"盘点结论（9 处，只有 2 处是取值）

| # | 位置 | 语义 | 能否改绑定 |
|---|---|---|---|
| 1 | `DataRecordPlugin` 列「来源=变量」 | **取值** | ✅ 能（方案 B） |
| 2 | `ResultUploadPlugin` 字段「来源=变量」 | **取值** | ✅ 能（方案 B） |
| 3 | `VariableAssignmentPlugin` 行「变量名」 | **写名** | ✅ **已改成弹窗（本次完成）** |
| 4 | `CSharpScriptPlugin` 共享变量声明表 | 声明（按 Id） | ❌ 不能 |
| 5 | `ImageAssignPlugin.TargetVariableName` | 写名 | ❌ 不能 |
| 6 | `Plugin.Comm` 读/写立即的 `VariableName` | 名字类端口（`OptionKind`） | ❌ R33 禁止 |
| 7 | `ConditionEditorView` 的 `JudgeVariableCandidates`/`AlarmVariableCandidates` | 写名 | ❌ 不能 |
| 8 | `FlowResultSourceDialogView.FilteredVariables` | 写名 | ❌ 不能 |
| 9 | SCADA 属性/排程 | SCADA 域（R191 暂停） | ❌ 不动 |

### 2.3 运行时变量：产出方只有 3 个插件，且性质不同

全扫 `LocalVariables` 写入点（判据：`LocalVariables[...]=` 或 `.Add(`，排除注释）：

| 插件 | 写入点 | 性质 |
|---|---|---|
| `JudgeTablePlugin` | `:954`（由 `:845 WriteRuntimeVariable(context, portName, outcome.IsOk)` 调用） | **派生输出**：名字 `表名.规则名.结果` 由 `:398-412` 算出，用户无选择权；**同时已有输出端口**（`:834-842`） |
| `VariableAssignmentPlugin` | `:1220`（覆盖）/ `:1226`（`CreateIfNotExists` 新建） | **用户指定写入** |
| `CSharpScriptPlugin` | `ScriptContext.cs:132 SetVar` | **声明式**：`OutputVars` 是真输出端口（`:497-526`）；`SetVar` 是局内变量 |

**其余 40 个插件都不写 `LocalVariables`。**
**`VariableDefinitionPlugin` 这个类在本仓库不存在**——全仓唯一 `class *VariableDefinition*` 命中是 `DeviceVariableIoService.cs:243` 的 `DeviceVariableDefinition`（设备变量 DTO，无关）。而 `FlowQueryHelper.cs:255` 正按 `PluginTypeName.Contains("VariableDefinitionPlugin")` 扫它 → **运行时候选实际为空**。

**`LocalVariableItem` 不是运行时变量**：它属于 `ConditionStep.LocalVariables` / `WaitStep.LocalVariables`（`ConditionStep.cs:21`、`WaitStep.cs:32`），是条件/等待节点的**判定变量声明表**（键是 Guid，`LinkedSources` 按 Guid 挂）。**不要与 `context.LocalVariables` 混为一谈，不能删。**

### 2.4 下游能不能改端口的值？**不能**

- `OutputPort<T>` 只由插件自己 `Set`（`CreateRoiPlugin.cs:487`）；
- `RuntimeVariableProxyPort.Value` 的 **setter 空实现、静默忽略**（`RuntimeVariableProxyPort.cs:94-98`，注释原文"运行时变量代理是只读的"）；
- 下游写值只有两条合法路径：`IWritableVariable.TryWrite` 或 `GlobalVariableWriter`。

## 5. 踩过的坑（本会话新增，已记 R185 台账）

| ID | 坑 | 判据 |
|---|---|---|
| C-56 | 构建命令接 `findstr` 过滤，**无匹配时退出码 1** → 成功被误判失败 | 判构建成败只看输出文本，不看 findstr 退出码 |
| C-57 | `Get-Process -Id <pid>` 在目标退出后**命中被复用的 PID**（实测变成 `conhost`） | 等进程退出按**进程名**轮询 |
| C-58 | `Select-String -SimpleMatch` 把 `[01]` 当字面量 → 字符类失效 | 要字符类就别加 `-SimpleMatch` |
| E-12 | 探针反射调私有方法，`GetMethod` 返回 null 被 `?.Invoke` 静默跳过 | 必须先断言"方法找到且参数个数对" |
| E-13 | 断言宿主子 STA 线程 `new Application` → `Application.Current` 亲和留在死线程 → 后续检查 `add_Exit` 跨线程崩（`-532462766`） | 宿主刻意不 new Application；已修 `KnobChecks.RunOnSta` |
| C-08 补 | 两个会话各跑一份 `run_gates` 互抢 `obj`/`Modules`/`AppConfig.json`/PNG → 计数漂移、假红 | 判红前先查有无第二个 `run_gates`；**检测命令要 `$PID` 排除自身**（否则自匹配，实测误等 40+ 分钟） |

**另有两条工程教训（未入台账，建议补）**：
- **PowerShell 内联 `-Command` 处理含中文/引号/方括号的匹配极易被转义吞掉**（本会话多次输出为空或参数绑定异常）。**稳定做法：把脚本写到 `artifacts\logs\<日期>\*.ps1` 再 `-File` 执行**，本会话所有可靠扫描都是这么做的。
- **改 XAML 大块内容**：不要用 `Get-Content/Set-Content` 往返（R3）；本会话用的是"片段写文件 + 按行号 splice 的 .ps1"，并在 splice 前 assert 首尾标记行内容，避免行号漂移改错位置。
