## 一、当前状态

### 1. EasyNet 是什么（从参考材料确认的事实）

- 汇川 Easy 系列（Easy521/H5U 等）专用 TCP 协议，默认端口 **12939**，无握手、长连接、一问一答。
- 定界：帧前 2 字节 = 整帧总长（UInt16 LE，含自身）。
- 请求：22 字节固定头 + 写载荷；`[8]`=1 读 / 2 写；`[14..17]` 地址；`[18..20]` 位数（3 字节 LE）。
- 读响应：**整帧回显请求 + 数据**（`[0..1]` 改为总长，`[16]` 类型码被清低 4 位），数据从 `[22]` 开始，按位 LSB-first 打包。
- 写响应：固定 9 字节 `09 00 01 03 01 00 00 00 06`；错误帧 `[8]=0x0F`，错误码 `[10..11]` LE（1=未知区域、2=地址异常、3=拒写）。
- 地址：20 位位地址（字节 0..2 LE）+ 字节 2 高 4 位类型码；X/Y 八进制、Y=+0x80000、M/S 十进制（S=+0x80000）、B=0x2、D=0x4/R=0x5/W=0x6（字地址×16，可 `.bit`）、U/UB/UW 十六进制且 32 位裸地址不做类型码合并。
- 数据字节序：**小端**（原版 `RegularByteTransform` 实测：字节 `12 34` → `0x3412`，与 `BitConverter` 一致）。

### 2. 参考实现可信度

- 协议库 `src/EasyNetProtocol`（地址/命令/定界/客户端/服务器，约 600 行），与原版 DLL 做过双向互通：自测 11/11、原版客户端→还原服务器 10/10、还原客户端→原版服务器 10/12（仅 Y10 写失败，归因为原版服务器自身写路径缺陷）。
- README 已标注 U 区路由怪癖与 Y/S 写缺陷，属于“保留原版行为”的已知边界。

### 3. 本仓现状（决定实现方式的关键事实）

- **仓库内置 `DLL\HslCommunication` 是旧版（net48，LangVersion 8），只有 `InovanceTcpNet`，没有 `InovanceEasyNet`**（全仓 grep 无命中）。→ 不能像 MC/FINS 那样薄封装 HSL，必须自己实现报文层。
- 因此也不能复用 `HslHelper.WriteTyped`（它要求 `IReadWriteNet` 设备对象），EasyNet 连接需要自带类型分发。
- 本仓通讯层的扩展点已具备：`ICommunicationConnection` + 三个可选能力接口（`ILinkHealthProbe` / `ISegmentReader` / `IConnectionFailureDetail`），`FreeProtocolConnection` 就是“不用 HSL、自己开 TCP”的现成范式。

## 二、已做（对照本仓的接入设计）

### 1. 字节序必须映射为 `DCBA`

本仓 `HslHelper` 的 `ByteOrderFormat.ABCD` 语义是“线路序=逻辑大端”，解码时会再反转；而 EasyNet 线路是小端。若声明 ABCD 会把 `12 34` 解成 `0x1234`，与原版（`0x3412`）相反。**EasyNet 应固定 `ByteOrderFormat.DCBA`**，与 MC 同理。

### 2. 批量读的可行性（推荐做，改动面很小）

- 字区（D/R/W）一个“单元”= 1 字 = 2 字节，响应数据就是 `units*2` 字节；位区（M/S/B）一个单元 = 1 位，响应按 LSB-first 打包。
- 现有规划器两条路径正好对上：
  - 字区 → `ISegmentReader.ReadSegment(address, units)` → 按 `BytesPerUnit=2` 切片解码；
  - 位区 → `IsBitArea=true` → `ReadBits(address, count)` → `DecodeBitItem`。
- 需要改的既有代码只有两处（都是 `PollProtocol` 分支）：
  - `Core\CommunicationContracts\PollAddress.cs` 的 `ValueByteLength`（字区 ×2）；
  - `Communication\Communications\Manager\PollBatchPlanner.cs:113-115` 的 `ReadSegment.BytesPerUnit`（字区 ×2）；
  - 外加 `PollAddress.MaxSegmentUnits` 增加 EasyNet 分支。
- **X/Y（八进制）与 U（十六进制）第一阶段不做批量**：段地址是 `SegmentPrefix + 十进制 Start` 拼出来的，八/十六进制区拼回去会二次错位（MC 当年就踩过，靠 `SegmentAddressOverride` 解决）。这两个区先走单读兜底，正确性优先。

### 3. 地址对象设计

- `EasyNetArea { X, Y, M, S, B, D, R, W, U }`，`EasyNetAddress : DeviceAddressBase<EasyNetArea>`。
- 进制：X/Y=8、U=16、其余=10（与 `McAddress` 的 Radix 写法同构）。
- `MaxBitOffset` 覆盖为 15（字内位，D100.15）；但 **`.bit` 只允许 D/R/W**，且位访问一律走单读（规划器 `DecodeBit` 只处理字节内 0-7 位，FINS 位访问也是走单读的先例）。
  > **2026-10-29 已作废**：改为"字区布尔随所属字并段"，`DecodeBit` 的位上限按单元宽度（字节 0~7 / 字 0~15）。
  > 见 `docs/code-changes/2026-10-29-字区位变量并段（第1批）.md`。
- `BuildAddress`：字区 `{Area}{十进制/八进制偏移}` + 可选 `.bit`；位区 `{Area}{偏移}`；U 区 `U{十六进制}`（原版对 U/UB/UW 三种前缀解析完全一致，保留 `U` 即可，需在文档写明）。
- `TryCreatePollAddress`：字区数值 → 批量；位区布尔 → 批量；位访问、U 区、位区数值 → 返回 false 走单读。
  > **2026-10-29 已作废**：字区位访问（`D100.5`）现在也走批量，作为 `SpanUnits=1` 字的段成员。
- `TryCreateElementAddress`：字区按元素大小折算字、位区按位；U 区先不支持。

## 五、踩过的坑（评估阶段已识别）

- **HSL 版本陷阱**：内置 HSL 没有 EasyNet，不能照抄 MC 的 `new MelsecMcNet(...)` 写法；`HslHelper.WriteTyped` 也用不上。
- **字节序陷阱**：`ByteOrderFormat.ABCD` 在本仓是“大端语义”，EasyNet 必须 DCBA，否则所有 16 位以上值全错。
- **段地址进制陷阱**：X/Y 八进制、U 十六进制，`SegmentPrefix + 十进制 Start` 拼回去会二次错位（MC 已有前车之鉴）；第一阶段这两类不批量。
- **位访问切片陷阱**：规划器 `DecodeBit` 只处理字节内 0-7 位；D100.15 若走批量会抛异常，必须让位访问走单读。
  > **2026-10-29 已作废**：位上限已按单元宽度放宽（字节 0~7 / 字 0~15），`D100.15` 随所属字一起读回。
  > 代价是"坐标写错会静默错值"——`SegmentAddressOverride` 必须为 null、`Start` 必须是字号，
  > 三条前提由 `CommChecks` 的字区位并段断言钉住。
- **原版服务器缺陷**：v13.0.2 虚拟服务器写 Y/S 越界（错误码 2），互通测试时不要把它当“我们实现错了”的证据；参考实现已提供 `ReplicateHslYsWriteBug` 开关。
- **U 区怪癖**：U 地址不做类型码合并，只有位地址 20~23 位全 1 才路由进 U 区；Demo 里的 `UW2100010` 按服务器逻辑实际会路由到 M/S 区。此行为保留，需在帮助文档标注。
