## 3. 方案（推荐：插件出口烧录，SCADA 零改动）

### 3.1 数据通路

```
A 类插件（原图 + MeasureAnnotation 列表）
        ↓  AnnotationBaker.Bake(...)   ← 新增重载，复用六条硬纪律
OutputPort<HImage> AnnotatedImage（全新图）
        ↓
「图像赋值」→ 全局 HImage 变量
        ↓
SCADA Hmi.ImageView.Source
```

### 3.2 共享件改造（只改一处）

在 `Services/Core.Halcon/Helpers/AnnotationBaker.cs` 增加：

```csharp
public HImage? Bake(
    HObject baseImage,
    IReadOnlyList<MeasureAnnotation> marks,
    AnnotationBakeStyle style,
    Action<string>? warn = null)
```

内部把 5 种 `MeasureType` 映射到 `BakePlan`，位置口径与 `HalconBase.RenderAnnotations` 对齐：

| MeasureType | BakePlan |
|---|---|
| `Line` | `BakeShape(Line, [r1,c1,r2,c2])` + `BakeText(Text, 中点, HAlign.Left)` |
| `Angle` | 两条 `BakeShape(Line)` + `BakeText(顶点)` |
| `Text` | `BakeText(row, col)` |
| `Polyline` | 逐段 `BakeShape(Line)`；`ShowVertices` 时每顶点 `Cross` + 序号文本（`(r-14, c+6)`） |
| `Point` | `Cross(size=12)` + `Text(r-14, c+6)` |

新增 `AnnotationBakeStyle`：

```csharp
public sealed record AnnotationBakeStyle
{
    public int FontSize { get; init; } = 0;        // 0 = 自动：clamp(min(w,h)/50, 16, 64)
    public int LineWidth { get; init; } = 3;       // 全幅图缩到 SCADA 后 1px 线会消失
    public bool TextBox { get; init; } = false;    // 与现有覆盖层一致；复杂背景可开
    public string FontFamily { get; init; } = "Microsoft YaHei"; // 中文字形
    public int MaxSize { get; init; } = 0;         // >0 先等比缩小再烧（SCADA 专用时可设 1280）
}
```

**不新开窗口**：全部走 `AnnotationBaker` 已有的 buffer 窗口、`SetPart`、`DumpWindowImage`、`SetFont` 还原逻辑。

### 3.3 A 类插件改造（四个）

每个插件加三样东西：

```csharp
[StepConfig, DefaultValue(false)]
public partial bool OutputAnnotatedImage { get; set; }

public OutputPort<HImage> AnnotatedImage { get; } =
    new("AnnotatedImage", "烧录后的标注图（可接图像赋值/数据记录）");

private readonly AnnotationBaker _baker = new();
public override void Dispose() { _baker.Dispose(); base.Dispose(); }
```

在 `ProjectResult` 里：

1. 把 `if (DisplayViewIndex <= 0) return;` 改成
   `if (DisplayViewIndex <= 0 && !OutputAnnotatedImage) return;`（否则关显示时连标注图也不生成）；
2. 构建 `marks` 后：
   ```csharp
   if (OutputAnnotatedImage)
       AnnotatedImage.Value = _baker.Bake(image, marks, AnnotationBakeStyle.Default,
           m => context.Logger?.Warn($"{InstanceName} 标注烧录：{m}"))!;
   ```
3. `DisplayViewIndex > 0` 时照旧 `PublishPreview(image, DisplayViewIndex, marks)`。

**默认关闭**的理由：每轮多一次全幅 `DumpWindowImage`；不用 SCADA/存图的现场不该付这笔开销。与 `MatchingPlugin.OutputAlignedImage` 同一范式（静态端口 + 布尔开关，关闭时端口为 null）。

### 3.4 ImageScript

加固定输出端口：

```csharp
public OutputPort<HImage> AnnotatedImage { get; } =
    new("AnnotatedImage", "脚本自绘效果图（dev_* 绘制后的回读图）");
```

在 `HDevDisplayBackend.Capture()` 之后：

```csharp
if (fx != null)
{
    AnnotatedImage.Value = fx;     // 端口持有；下一轮轮首由基类释放

```

端口名 `AnnotatedImage` 需在动态输出变量表中视为保留名（脚本变量同名时跳过并 Warn）。

### 3.5 CSharpScript

## 6. 踩过的坑

- **不要在 SCADA 端加标注层**：`VM.Scada.Controls` 刻意不引 HALCON，`MeasureAnnotation` 在 `Core.Halcon.Models`；Web 端还要另做一套标注协议；变量链只有 HImage，标注得再开一个变量/类型。烧录是唯一同时覆盖桌面、Web、CSV/导出/报警留存的路径。
- **`ProjectResult` 的早退会连标注图一起挡掉**：`DisplayViewIndex=0` 时 `marks` 根本没建；改造必须先建 marks 再决定发不发预览。
- **文字会被缩放吃掉**：全幅 2448×2048 烧 20px 字，缩到 200px 宽只剩 1.6px；字号必须按图幅自适应（`min(w,h)/50` 下限 16），线宽至少 3。
- **中文字体不是默认能画的**：`AnnotationBaker` 现在硬编码 `Consolas`，中文可能靠字体链接或画成豆腐块；改字体族后必须用像素断言反证「中文有墨迹」。
- **端口所有权**：`AnnotatedImage` 是 `Bake` 出来的新图，端口持有、基类轮首释放；不要接 `src` 原图（透传口会踩上游释放）。`图像赋值` 写入时已做拷贝（2026-10-24 修复），下游安全。

## 推荐落地：每个工位只保留一张「最终展示图」

### 目标口径

- 每个工位**一张**最终展示图；SCADA 每页绑**自己工位**的变量，不再共用 `LastImage`。
- 这张图里必须同时有：底图 + 所有几何（线/圆/区域/轮廓/点）+ 所有文字（判定/数值/编号）。
- 主界面预览的 `ImageInfoRow`（随图信息）不是像素；要上 SCADA 就烧进图，或在 SCADA 用文本图元单独绑变量。
- 判据：主界面预览里看得见的东西，SCADA 的同一张图里必须也看得见。

### 推荐架构：「结果显示」= 唯一合成器

```
各插件原图 ─────────────────────────────┐
各插件几何（GeometryParam / HRegion / HXLD）┼──▶ 结果显示（SrcImage + r1..rN）
各插件文字/数值结果 ─────────────────────┘        DisplayViewIndex = 0
A 类插件 Annotations（List<MeasureAnnotation>）──┘        AnnotatedImage
                                                              └──▶ 图像赋值
                                                                    VariableName = "Img_STn"
                                                                          └──▶ SCADA 工位 n 的 ImageView.Source
```

为什么是它：

- `结果显示` 已经有 `AnnotatedImage`、`DisplayViewIndex=0` 只烧不发布、`GeometryParam/HRegion/HXLD/文本` 四类绘制、以及经过验证的 `AnnotationBaker`；只差 `List<MeasureAnnotation>` 一个分支。
- A 类插件只需要暴露 `Annotations`（托管列表，不开窗、不烧图），不用每个插件各养一个 baker。
- 每工位只烘焙一次；可以把多个插件的标记和文字合成到同一张图，最符合「不丢信息」。
- 桌面、Web、CSV/导出、报警留存全部吃同一张 HImage，不需要改 SCADA。

## 附：性能影响

### 先说结论

**推荐方案（结果显示合成）几乎不新增烘焙开销**：`ResultDisplayPlugin.RunAlgorithm` 在 `DisplayViewIndex=0` 时**仍然每轮无条件烘焙**（`ResultDisplayPlugin.cs:482-503`，`viewIndex <= 0` 只跳过发布，不跳过 `_baker.Bake`）。你现在的六个 `结果显示` 全是 `DisplayViewIndex=0`，也就是说这笔全幅 dump 今天已经在付、产物被丢掉了。把 `图像赋值` 改接 `AnnotatedImage` 只是把已经在算的图用起来。

新增的只有三块：

| 项 | 量级 | 触发条件 |
|---|---|---|
| `图像赋值` 写入的 `CopyImage`（`LocalVariableModel.TryWriteImage`） | 5MP 彩色约 15MB/次，memcpy 量级（本仓未单独实测，估 1~3ms） | 每次写图像变量 |
| 变量保留两代图（当前 + 退役） | 5MP 彩色约 30MB/变量；6 工位约 180MB | 变量存在即占 |
| SCADA 位图转换 `ToBitmapSource` | **实测 5MP 彩色 14.08ms / 分配 28.69MB；1920×1080 灰度 0.86ms**（A2 报告） | 有页面打开且变量变化时；一个变量只转一次（A4），不是每个图元一次 |
| 烘焙本身 | **本仓没有全幅 `DumpWindowImage` 实测**（2026-10-13 结果显示文档明确写“仓库从未测过”）；旁证只有小窗画框写字约 1ms | 每工位每轮一次；推荐方案不新增 |

### 为什么不推荐 per-plugin `AnnotatedImage`

每个 A 类插件各开一扇窗、各做一次全幅 dump；四个插件就是四倍 dump。合成器只在 `结果显示` 里做一次，且能把多个插件的标记画进同一张图。

### 压成本的做法

1. **只给需要上画面的工位接 `AnnotatedImage`**；不显示的工位不接变量，数据泵就不会转换位图。
2. **烧录前先缩图**：`MaxSize=1280`（或 960），5MP 的 dump/转换/内存都降到约 1/9，SCADA 字也更大更清楚。代价是存图/导出不是全分辨率——需要全分辨率存图时另开一条记录路径。
3. **控制 item 数量**：几何/区域/文字几十条以内；`结果显示` 已有 `MaxDrawElements` 上限。
4. **Web 端**：`/img` 是 1fps/元素、在 UI 线程转换；5MP 彩色每个元素约 14ms/s，别在一页上堆很多 5MP ImageView。
5. **可选优化（需改代码）**：给 `结果显示` 加 `BakeAnnotatedImage` 开关（默认 true 保持兼容），不需要存图/上画面的工位关掉，省掉今天这笔被丢弃的烘焙。

### 量化验收（R105/R38）

- 场景：5MP 彩色图，连续 500 轮，记录 `结果显示` 开启前后单轮耗时与私有内存。
- 判据建议：节拍增量 < 10%，内存增量 < 100~200MB（按现场预算定）；若超预算，先上 `MaxSize=1280`，再考虑关掉不需要的工位。
- 注意：`AnnotationBakerChecks B7` 只钉了 500 轮内存增量 < 60MB，没有记时间；时间必须在真机上按真实操作顺序测，不能拿“手动试是好的”当证据。
