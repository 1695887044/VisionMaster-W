## 2. 已存在的语义裂缝（支持删除的直接证据）

`IsDirectlyLoopable`（`FlowModel.cs:300`）= `Role == Main || IsLineStartMember`，
所以主流程在列表里显示「循环」徽标、ToolTip 写「主流程：工具栏「启动整线」可直接启动」；
但 `FlowBatchSelector` 一旦发现**任何**「整线」成员就只返回这些成员，主流程进 `EnabledButExcluded`。

→ 现场只要勾了一条「整线」，主流程的徽标就与按钮实际行为矛盾（说可循环，按了不启动）。
→ 主流程实际不是「另一种可循环」，只是老文件的兼容兜底。

## 3. 删除前必须补的两件事

1. **线级判定来源（唯一需要用户拍板的语义）**
   现状：`ShellViewModel.cs:431` 取 `Role == "主任务"` 的那条流程作为「全部」口径的 OK/NG。
   候选：
   - A（推荐）方案级显式字段「线级判定来源」流程 Id，默认取第一条勾「整线」的流程；
   - B 固定取第一条勾「整线」的流程（无显式配置，改勾选就改口径）；
   - C 各流程求和（否决：与「串联线不跨站求和」冲突，`Shell.xaml:2615`）。
2. **迁移（不迁移会静默丢启动能力）**
   `Role == 2` → `Role = None` + `InvokeType |= LineStart`，落在 `MandatoryFlows.Ensure`
   （与老名 GoHome/MainTask 认领同一处，幂等）。
   ⚠ 直接删 `Role` 属性会**静默丢失唯一信号**：Newtonsoft 默认 `MissingMemberHandling.Ignore`，
   老 `.vms` 里的 `"Role": 2` 被忽略后无法判断「这条曾是老主流程」。必须保留只读垫片
   （`[JsonProperty("Role")]` 的 legacy 字段，迁移后清零）或保留成员只停用。
   数值 2 永久保留不复用（同 `FlowInvokeType` 的落盘纪律）。

## 4. 删掉后的目标模型

- 骨架只剩 Home / End（安全流程，可改名、不可删）。
- 其余流程一律 `Role = None`，能怎么跑完全由 `InvokeType` 位集表达（整线 / 定时 / 变量 / 子程序 / HTTP）。
- 「至少一条流程勾整线」用 `FlowManager` 已有的「未配齐」提示表达（`FlowManagerViewModel.cs:497-503` 同族），**不建流程**。
- 新建方案仍可预置一条名为 `Main` 的流程并**默认勾「整线」**，`Role = None`（可删可改名）——
  这样「新建即可启动整线」的引导不变，但不占骨架名额。

## 6. 建议的最小路径

若只想消除「两套启动语义」的歧义，**先做两件低风险改动**即可，不必删概念：

1. `IsDirectlyLoopable` 去掉 `Role == Main` 分支 → 徽标与 `FlowBatchSelector` 口径一致（纯展示，零行为变更）；
2. `FlowBatchSelector` 兜底分支加日志/提示，暴露「你还在用兼容口径」。

彻底删 `Role.Main` 则按 §3.1 先定线级来源，再按 §5 一次性落迁移 + 断言 + 文档。
