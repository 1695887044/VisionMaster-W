# 交接报告-2026-10-28-运行态页面菜单白条诊断与修复

## 1. 当前状态

**已修复并已实测**（`VisionMaster/Views/ScadaRuntimeWindow.xaml` 的 `PageMenuContextStyle` 补了完整深色
`ControlTemplate`），新增的自动闸在真实 `ScadaChecks` 里**通过**。该宿主整体仍是 exit 1：
3 条失败全在属性面板段落，来自另一会话正在进行的 `ScadaPropertyViewModel` / `ScadaPropertyView`
重构（证据见 §3），与本次改动无关。

缺陷现象：组态运行态窗口顶栏「主页 ▾」下拉菜单左侧一条约 28 DIP 宽的浅色竖条
（截图实测 `#F1F1F1`），中间被悬停项的深色圆角块遮住一段，看起来像"白条只到一半"。

根因：**WPF Aero2 默认 `ContextMenu` 模板自带的"图标栏"矩形**被深色背景暴露。该模板里三个矩形是
硬编码浅色：

```xml
<Rectangle RadiusX="2" RadiusY="2" Fill="#FFF1F1F1" Width="28" Margin="1,2,1,2" HorizontalAlignment="Left" />
<Rectangle Fill="#FFE2E3E3" Width="1" Margin="29,2,0,2" HorizontalAlignment="Left" />
<Rectangle Fill="#FFFFFFFF" Width="1" Margin="30,2,0,2" HorizontalAlignment="Left" />
```

浅色主题下它与菜单底色一致、看不出来；一旦把 `ContextMenu.Background` 改成深色，它就变成一条亮带。

## 5. 踩过的坑

- **显式 `Style` 会整条顶掉隐式样式**：`PageMenuContextStyle` 一旦赋给 `ContextMenu.Style`，
  `UI/Controls/Themes/Controls/Navigation.xaml:73` 的隐式 `ContextMenu` 样式与 Fluent 隐式样式
  **同时失效**，控件回落到 Aero2 主题默认模板。原注释只写了"不用隐式样式是因为会顶掉应用级模板"，
  没意识到"显式只给 Setter"同样会掉进 Aero2。
- **查底色必须把 `Shape.Fill` 算进去**：白带是 `Rectangle`，只查 `Background` 会把它当透明放过
  （第一版探针就漏了，`WHITE CANDIDATES` 只报了两个 0×0 的滚动条按钮）。
- **`Application` 未 `Run()` 时 `Dispatcher.BeginInvoke(..., ApplicationIdle)` 回调根本不执行**，
  探针会静默零输出（与 R183"零输出 = 判红"同源）。
- **截图肉眼判断会错**：中间那段被悬停项背景盖住，必须按像素统计判范围。
- **构建退出码别接在 `&` 后面**：`dotnet build ... > log 2>&1 & echo EXIT=%ERRORLEVEL%` 拿到的是
  重定向的退出码，第一次"构建成功"是假的（日志里其实是 CS7036）。
- **并发会话正在改的文件，不要顺手修**：`ScadaPropertyViewModel.cs` 的错误点从 3404 漂到 3414、
  再变成另一条 CS8121，说明是在跑重构；插一脚只会把两边都搞乱。
