#### 多赋值 UI 方案（推荐 A）

```
左轨 2*（min 320）                          右栏 1*（min 220）
┌────────────────────────────────────┐    ┌──────────────────────┐
│ 赋值设置                 [+ 添加]  │    │ 当前行 · 目标变量    │
│ 作用域 · 变量名 · 值 · 自动创建    │    │ [运行时]  OKCount    │
│ ┌表头─────────────────────────────┐│    │ 候选 12 · Int32      │
│ │作用域  变量名      值      创 删││    └──────────────────────┘
│ ├─────────────────────────────────┤│    ┌──────────────────────┐
│ │[运行时▾][OKCount ▾][21  🔗 ✕][x][✕]││   │ 作用域规则（静态）   │
│ │[全局  ▾][LineName▾][上游…    ][ ][✕]││   │ …                    │
│ └─────────────────────────────────┘│    └──────────────────────┘
│ 空态：还没有赋值行（+ 添加一行）    │
└────────────────────────────────────┘
```

- **行控件选择**：`ItemsControl` + 共享列定义的 `Grid`，**不用** `DataGrid`/`ListView+GridView`。理由：DataGrid 单元格要先进编辑态，内嵌 `LinkableValueEditor` 得双击才能输入；`GridView` 列宽是固定像素、无星号列（`JudgeTableView.xaml` 的列宽范式），640 档无法自适应；`ItemsControl` 与 `DataRecordView.xaml` 同构（表头 + 行模板 + 空态）。若坚持 `ListView+GridView`，R19-R22 三件套（`GridListViewStyle` + `ItemContainerStyle` 带 `GridViewRowPresenter` + 就地合并 `GridView.xaml`）一条不能少。
- **行内控件**：作用域用紧凑分段/下拉；变量名**不要**用 `DialogCombo`（没有 `PART_EditableTextBox`），用「无显式 Style 的 `ComboBox`（回落到框架默认模板，含 `PART_EditableTextBox`，与 `Dialog.ConditionEditor.xaml:25` 同一做法）」或「`TextBox` + 箭头 `Button` + `Popup`」；`Popup.IsOpen` 必须 `Mode=OneWay`（R174）。值用 `LinkableValueEditor`。自动创建用 `DialogCheckBox`，全局作用域下禁用。删除用共享图标按钮 `DialogIconButton`（`UI\Controls\Themes\Fluent\FluentAliases.xaml:55-64`，30×30 方形、`Padding=0`，R68）。
- **行高/间距**：`MinHeight=48`（36 编辑器 + 上下 6）、模板根 `Border Padding="6,2"` + 底边 hairline，禁止「Grid Auto 行 + 子元素 Margin」（R133）；表头 30（DataRecord 先例）。
- **滚动**：只有列表滚，外层不再套 `ScrollViewer`。
- **空状态**：复用 `DialogEmptyStateBadge/Title/Hint`（`Dialog.Text.xaml:33-46,119-130`）+ 零值转可见性（现仅 DataRecord 有局部实现，第二处出现应下沉到 `UI\Controls\Converters`，R141）。
- **上限**：软上限 32 行、硬上限 64 行；到顶禁用「添加」并给一行说明。
- **键盘**：Tab 顺序 作用域→名字→值→自动创建→删除；值里 Enter 提交并下移一行；Delete 仅在焦点不在文本框时删行；Ctrl+D 复制行。
- **批量操作**：添加/复制/上移/下移/删除/清空，命令挂插件实例，`CommandParameter={Binding}` + `RelativeSource AncestorType=UserControl`（`JudgeTableView.xaml` 范式）。
- **右栏取舍**：目标卡改绑「选中行」；规则卡保留但不再占 `*` 行（行列表需要高度），640 档折叠成一行说明。

#### 设计基线 v2 必须写清

- 新增状态：0 行（空态）、1 行（旧配置迁移）、N 行（滚动/表头吸附）、行内错误（空名/未知作用域/类型不匹配/候选为空）、**行被删除但旧连线仍在**（必须定义：删行即 `RemoveLink(rowPort)` + 移除 `InputValue`，否则 `.vms` 留孤儿连线，且 UI 要说明「删除会一并解除」）。

#### 推荐数据模型（A 案）

`AssignmentRow`（`Plugin.Util.Models`，`ObservableObject`，全部存盘字段 JSON 友好）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `RowId` | string（Guid N） | 稳定身份，**端口名唯一锚点**；删行即失效 |
| `VariableName` | string | 名字，不是值（R33）；只从真实输入事件上报（R35） |
| `Scope` | string | `Runtime`/`Global` 白名单（沿用字符串，避免枚举经 `InputValues` 往返抛 `InvalidCastException`） |
| `CreateIfNotExists` | bool | 仅 Runtime 生效 |
| `ValuePortName` | string | `"Value_" + RowId`，**持久化**（编译器/连线键都要读） |
| `Enabled` | bool | 停用仍建端口（`JudgeTablePlugin.cs:222-224`），避免孤儿键 |
| `[JsonIgnore] SourceText / LastResult / LastError` | — | 纯界面态，不落盘 |

**不要** `Order`：集合顺序是唯一真源，双份必漂移。

关键生命周期（骨架）：

```csharp
[StepConfig] public ObservableCollection<AssignmentRow> Rows { get; set; } // 手写属性 + Hook/Unhook

public override void ApplyConfigValues(IStepConfigData d) {
    base.ApplyConfigValues(d);      // Rows 先落地（迁移也在这里做，纯内存）
    MigrateLegacy(d);               // Rows 空且旧键在 → 合成 1 行
    RebuildDynamicInputs();         // 先存旧值 → RemoveDynamicInput + Dispose → 按 RowId 重建
    RefillRowConstants(d);          // 未连线行补灌常量（照 JudgeTable/ResultDisplay）
}

public override void OnConfirm(IStepConfigData d) {
    RebuildDynamicInputs();
    base.OnConfirm(d);              // 端口键 + Rows JSON 深拷贝
    DropOrphanLinks(d);             // 删行 → RemoveLink/RemoveInputValue + 状态提示
    StripNonConstantRowValues(d);   // 试运行桥接值不当常量落盘（照 ResultDisplay）
}
```

要点：

- 端口名 `Value_<RowId>` 只含字母数字下划线；编译器端口名正则只禁 `[`（`FlowCompiler.cs:1069-1072`），能过。
- 重建前保存旧端口值、重建后补回；旧端口 `Dispose`（`InputPort` 实现 `IDisposable`，用于退订上游 `ValueChanged`）。
- `PortsVersion` 通知行内 `MultiBinding` 重取端口（`ResultDisplayPlugin.cs:315-325`、`ResultDisplayView.xaml:644-656`）。
- `[StepConfig]` 集合经 `SnapshotConfigValue` JSON 往返；行类不要放 `InputPort`/`HImage`/事件。

#### 迁移与兼容策略

1. `Rows` 缺失/空 且存在旧键 → 合成 1 行：`VariableName=InputValues["Name"]`、`Scope=InputValues["Scope"]`（非法则 `Runtime`）、`CreateIfNotExists`、`ValuePortName="Value_"+RowId`。
2. 常量：`InputValues["Value"]` **复制**到 `InputValues["Value_<RowId>"]`；旧键保留（旧版本回退仍可读）。
3. 连线：`LinkedSources["Value"]` → `["Value_<RowId>"]`；`LinkedSources["Name"]` **删除并提示**（名字不能来自连线，见 `04-名字与值口径.md`）。编译实例上**不迁移活模型**，改用「兼容端口 `Value`」接住老连线，首次确认时落成新键。
4. 幂等判据：`Rows` 存在即权威，不再迁移；`OnConfirm` 不重写旧键（或只把第 1 行镜像到旧键，供旧版本回退）。
5. 回退旧版本：旧键仍在 → 旧版读到迁移前配置（代价：新版改动不回流），写进差异清单。

#### 执行语义

- 逐行执行，**某行失败不中断其余行**（与 `CompiledPluginNode`「业务失败流程继续」同口径），整节点 `Success=false`。
- `ErrorMessage`：`N/M 行失败：第2行「OKCount」找不到全局变量；第3行「Qty」类型不匹配`（前 3 条 + `等 N 行`）。
- 日志：每成功行一条 `Info`（保留 `{InstanceName}` 前缀），每失败行一条 `Error`，汇总一条 `Error`。
- 无法回滚：前序行已写入的副作用必须写进手册（部分应用）。
- 同一节点内两行写同一变量：建议**编译错误**（几乎必是配错），至少给 `Warn`。
- `[ParallelSafe]` 仍成立：插件无静态可变状态；`LocalVariables` 线程安全由 `BranchVariableRegistry` 保证；**跨节点并行写同名变量仍不安全**，帮助手册的既有承诺保持。
- 运行时新建变量的类型仍由值决定，不新增「声明类型」概念。

#### 输出端口

保持单一 `Success/ErrorMessage`，**不建议**每行一个动态输出：

- 每行输出会引入 N 个 `DynamicPortInfo`、绑定界面与下游连线复杂度；
- 行级结果用配置界面 `LastResult/LastError` + 日志呈现即可；
- 下游若需逐行判定，应使用判定表/独立节点。

#### 备选方案对比

| 方案 | 改动面 | 兼容性 | 用户收益 | 静默故障风险 |
| --- | --- | --- | --- | --- |
| **A 行列表 + 每行动态输入端口（推荐）** | 插件 + 视图 + 编译器冲突检查 + 断言 + 手册 | 迁移可控（见上） | 一节点 N 变量，每行可接上游 | 中：迁移/端口重建/命名空间三处必须做对 |
| B 行列表 + 行内常量 | 最小 | 最好 | 只能填常量，失去「赋上游结果」主用法 | 低 |
| C 另建「批量赋值」插件 | 复制一份实现 + 手册 + 断言 | 旧节点不变 | 工具箱两个近似条目，维护双份 | 中（两套口径漂移） |
| D 流程层展开 N 节点 | 需新的编辑期展开/编译前置 | 破坏「一节点=一步」语义 | 无需新模型 | 高（生成节点与用户编辑冲突） |

**推荐 A。** B 丢掉核心场景；C 违反「同结构第二次出现就下沉」（R141 精神）并让老节点继续带病；D 改动面最大且无收益。

## 5. 踩过的坑

1. **子代理的「不存在」判词必须复核**：前端审查员说 `DialogIconButton` 不存在，实际它在 `FluentAliases.xaml:55-64` 且正好符合 R68。**「全仓没有/唯一」这类断言，必须自己 grep 一遍再写进报告。**
2. **「必填只看连线」是错的**：`FlowCompiler.cs:1343-1352` 同时接受非空常量。这个误判会让人以为 `IsRequired=false` 可以省，实际空值行仍会报「参数缺失」。
3. **DataRecord 的「base → 重建」范式缺补灌**：`DataRecordPlugin.cs:176-181` 没有 `Refill`，照抄会静默丢常量；正解是 `JudgeTablePlugin.cs:140-145` / `ResultDisplayPlugin.cs:252-256` 的「base → 重建 → 补灌」。
4. **行模型命名空间是硬约束**：`ConnectionConfigJsonConverter.cs:98-102` 只放 `Plugin.` / `VisionMaster.Models` / `Communications` / `Scada`；`VisionMaster.Plugins.Util` 不在内，`.vms` 会「存得下、打不开」。
5. **编译器里还有一处单值假设**：`FlowCompiler.cs:1639-1659` 的 `CollectAssignmentWrite` 读 `InputValues["Name"]/["Scope"]`，不在插件工程里，最容易漏改；漏改的后果是并行写冲突门禁静默消失。
6. **陈旧颜色基线会掩盖回归**：`hardcoded-colors.baseline.txt:9` 记 9、实际 0；「存量只减不增」让 9 处 hex 可以静默通过，建议同批清零。
7. **静态扫描断言是「恰好 1 个编辑器」**：多赋值必须重写判据，不能删断言；按 R65 先改坏验证它会红，再还原。
