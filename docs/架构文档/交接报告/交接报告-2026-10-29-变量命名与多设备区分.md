## 2. 需求"存在 / 缺失"逐条核对

需求三句：①导入前什么样导进来什么样；②只在绑定与控件显示绑定值时显示设备前缀；③程序内靠 Guid/Id 链接。

| 需求 | 现状 | 判定 |
|---|---|---|
| ① 名字不改、跨设备同名可导入 | 导入把跨设备同名判成错误行（C4.1）；即便绕过，注册表也只保留一个（C1.1） | **缺失** |
| ②-a 绑定弹窗能分辨设备 | 候选树不去重，两行都在，但**显示名都是 `Alarm[90]`**；设备只在 `Description`（`[网络变量] ... (连接: L2)`） | **部分存在**（信息在，但不在显示名） |
| ②-b 控件显示绑定值带设备 | 绑定显示串 = `{节点名}.{变量名}`（`:746-749`），节点名是 `全局变量 (Global)` | **缺失** |
| ③-a 流程连线按 Id | 写 `TargetVariableId`，解析 Id 优先 + 自愈 | **存在** |
| ③-b 监视项 / SCADA 绑定按 Id | 都是 `Resolve(id, name)` | **存在** |
| ③-c 变量赋值按 Id | 运行期 `TryWrite(name, ...)`，契约只有名字重载 | **缺失** |
| ③-d 数据记录 / 结果上报按 Id | 调的是 Id 版接口但传 `Guid.Empty` | **缺失**（接口就位，数据没存） |
| ③-e SCADA 自由文本模板按 Id | 先按文本名解析 | **缺失**（只能靠文本） |

## 3. 风险与边界

1. **静默错值（最高危）**：名字重复后，任何"空 Id + 名字"的读写都落到第一台设备（C3.1/C3.3），不报错。这是本需求的唯一红线。
2. **加载零诊断**：手改 `.vms` 造出重名，打开方案不报错、不提示，`LastProblems` 也是空（C2.3）。用户只能靠"数值不对"发现。
3. **候选被静默吞掉**：`PluginVariableOptions`（:55-63）与变量赋值 `BuildCandidates`（:447-453）按名字去重，重名的第二台设备**在插件下拉里根本选不到**。只改注册表不改这两处 = 半可用。
4. **模板限定语法会误报**：`L2/Alarm[90]` 现在报"数组根「L2/Alarm」不存在"（C5.2），不是"变量不存在"。若要做限定引用，解析器必须显式先认"设备/名字"，否则用户拿到的错误指错方向。
5. **唯一性口径有三处**：导入（`DeviceVariableIoService.cs:769`）、新建（`GlobalVariableManagerViewModel.cs:1881`）、改名（`VariableRegistry.cs:208`）。三处必须同批改成"同设备内唯一"，漏一处就会出现"建得进、改不进"或反之。
6. **同连接内同名仍会互相覆盖**：轮询层键是 `(连接名, 变量名)`（C7.1、`:951`），所以"同设备内唯一"这条必须保留，不能整体放开。
7. **改名会 re-key 轮询**：`NetworkVariableBridge.cs:159-171` 用旧名注销、新名重注册，行为正确；这是"改名方案"安全的前提。
8. **导出/导入是同一份名字**：导出写 `Name`（`:468`）、导入按名字匹配（`:769`）。一旦允许重名，导出的表里会出现两行同名（分属不同设备，但表里没有设备列），**再导入另一台设备时无法区分**——这是"导入即所得"与"按名匹配"的固有冲突，必须定口径。
9. **老方案零迁移**：现有方案名字本来就唯一，放开唯一性不会改变任何既有解析结果（C1 的 first-wins 在"无重名"时等价于唯一命中）。
10. **未验证项（不得当结论用）**：SCADA 图元运行期"显示绑定值"的具体文本由哪个控件/转换器生成，本轮没有定位；`ICommVariableAccess` 的实际调用方（grep 在 `Plugins\*.cs` 里未命中 `Comms.Read/Write`）未查清，不排除宿主内部使用。

## 4. 建议方案与待确认

### 4.1 建议分四批（每批可独立验收）

**批 1 · 让"重名"安全（不改唯一性口径）**
- `VariableRegistry._byName` 改多值；`FindByName` 歧义时返回 null；新增 `FindAllByName`。
- 5 个调用点处理歧义：`GlobalVariableWriter`（:59、:111）、`CommVariableAccess`（:101）、`ScadaTemplateVariableResolver`（:41、:62）、`MonitorViewModel`（:465 旧项兜底）。
- 验收：探针 C1.1 从"命中 L1"改为"返回 null + 歧义原因"；C3.1 从"读到 111"改为"失败并给出歧义原因"。

**批 2 · 唯一性口径改为"同设备内唯一"**
- 导入 `DeviceVariableIoService.cs:769-777`、新建 `GlobalVariableManagerViewModel.cs:1881`、改名 `VariableRegistry.cs:208` 三处同批改。
- 同连接内同名仍然拒绝（依据：C7.1 与 `AdvancedCommunicationManager.cs:951`）。
- 验收：C4.1 从"错误行"改为"合法新增"；新增断言"同设备内同名仍被拒"。

**批 3 · 三处改存 Id（自愈）**
- `AssignmentRow` / 数据记录列配置 / 结果上报字段各加 `Guid VariableId`；选择时写入（候选已带 Id）。
- 变量赋值改走 `ISharedVariableAccess.TryWrite(id, name, ...)`（契约已存在，`ISharedVariableAccess.cs:32`）。
- `PluginVariableOptions.cs:55-63` 与 `VariableAssignmentPlugin.cs:447-453` 的去重键从"名字"改成"名字+设备/Id"。
- 验收：C3.1/C3.3 在"存了 Id"的路径上命中正确设备。

**批 4 · 显示与护栏**
- `FlowQueryHelper.cs:72` 的 `PortDefinition.Name` 增加设备段（或 `VariableBindingViewModel.cs:746-749` 拼显示串时加），二选一需定。
- 变量管理打开时把歧义/重名上屏（`LastProblems` 补上"用户变量重名"的收集点，见 `VariableRegistry.cs:292-300`）。
- 模板限定语法：`ScadaTemplateVariableResolver` 先认 `设备/名字`，认不出再按 `Base[index]`；错误文案改成"变量在 N 台设备上都有"。

### 4.2 待确认问题清单

1. **导出表要不要加"设备"列**？不加则两台设备的表无法互导（风险 8）；加了则改动导出/导入 schema。
2. **同名变量在变量赋值下拉里怎么显示**？`Alarm[90]` 还是 `L2 · Alarm[90]`？显示口径一旦定，`PluginVariableOptions` 的去重键随之定。
3. **"控件显示绑定值"具体指哪些控件**？需要指名到图元类型（本轮未定位到具体控件）。
4. **SCADA 自由文本模板要不要支持限定写法**？若支持，语法用 `设备/名字` 还是 `设备.名字`（`.` 会与 `RebuildVariableDisplayAddress` 的切分冲突，`IReadOnlyWorkspaceContext.cs:405`）。
5. **歧义时的错误处理**：是"运行期报错并跳过该动作"，还是"加载期就拒绝打开方案"？建议前者。
6. **是否接受"同设备内同名仍然禁止"**？这是保留 `(连接, 名字)` 轮询键的前提。

## 8. 绑定弹窗显示设备（批 4 第一项，2026-10-29）

### 8.1 结论回顾

用户问「A 台 PLC 有 A、B 台 PLC 也有 A，绑定弹窗能选吗」。实测（C20）：
- **能选**：候选树不按名字去重，两条都在；选择按对象；绑定写 `TargetVariableId`。
- **但回显分不清**：显示串只由 `{节点名}.{变量名}` 组成，两台设备算出同一个地址；「已绑定」按名字串比较，绑了 B 的 A，A 的 A 也亮。

### 8.2 已修

| 项 | 改法 |
|---|---|
| 显示串 | 新增纯函数 `VariableBindingViewModel.BuildVariableDisplayAddress`，格式 `{节点名}.{设备}.{变量名}[{下标}]` |
| 候选端口带设备 | `PortDefinition.Device` + `FlowQueryHelper` 填充 + `CloneForCandidate` 拷贝 |
| 「已绑定」判定 | `InputPortUIModel.BoundVariableId` + converter `IsBound` 改 Id 优先（两边都有 Id 才按 Id，否则退回名字串） |

**设备必须放在变量名之前**：改名级联 `RebuildVariableDisplayAddress` 按最后一个点切前缀，设备放在名字后面会在改名时被吃掉（C21.5 端到端钉住）。
