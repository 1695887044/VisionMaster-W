### 2.1 运行态未授权点击弹登录（本轮发现的真实缺口）

B3 定的「运行态点无权按钮 → 弹登录 → 登录后继续原操作」原本**根本没接线**：

- `ScadaRuntime.AccessLoginPrompt` 全仓无任何赋值；
- `AxisPanelElement` 把无权限按钮直接置灰，点击根本进不来。

修法（4 处）：

| 文件 | 改动 |
|---|---|
| `Scada/Models/ScadaRuntime.cs` | 新增 `TryAuthorize(key, out reason)`：缺权限给宿主一次登录机会，登录后重判一次，只重试一次不递归；`RaiseElementEvent` 改走它 |
| `Scada.Controls/Runtime/ScadaRuntimeContext.cs` | 新增 `AccessLoginPrompt` 属性 + `TryAuthorize`，让图元拿到同一条链路 |
| `VisionMaster/Services/ScadaRuntimeHost.cs` | 构造新增 `accessLoginPrompt` 参数，同时透传给 `ScadaRuntime` 会话与 `ScadaRuntimeContext` |
| `VisionMaster/App.xaml.cs` | `ShowRuntimeAccessLoginPrompt`：解析 `IDialogService` 弹 `ScadaLoginView`，用 `Dispatcher.PushFrame` 同步等窗关闭，关窗后按最新权限重判 |

## 五、踩过的坑

1. **启动 exe 会锁 `Modules\` 与 `bin\`**：闸门跑构建期间启动 `VisionMaster.exe`，
   会让 `Plugin.CSharpScript` / `Plugin.ImageScript` 的 `copy ... Modules\` 报 MSB3073。
   本轮踩了两次（16:07、16:29），两次都不是代码问题。**跑闸门前先确认没有实例**。
2. **`gate-<宿主>.log` 可能是上一轮的残留**：`ScadaChecks` 那次报 `NO OUTPUT`，
   但 `gate-ScadaChecks.log` 有 3273 行——查 mtime 才发现那是 16:30:54 的上一轮文件。
   **判「有没有输出」要连时间戳一起看**，别只看文件存在。
3. **`.vms` 里手插字段要写真实换行**：PowerShell 字符串里 `` `r`n `` 若被当成字面量写进
   JSON，`ConvertFrom-Json` 会报「传入的对象无效」。写完必须回读解析一次。
4. **`-Command` 里传中文会被控制台代码页（936）截断**：生成验收账号文件时，
   中文组名被截成半个字，JSON 直接损坏。改用 ASCII 组名绕开（显示名走内置中文）。
5. **`setValue` 连填两个框会叠加**：账号框变成 `ianadmin`（两次输入拼在一起）。
   填之前先 `setValue(el, "")` 清空。
6. **CUA 坐标是相对窗口的**，不是屏幕坐标：窗口在 (260,260) 时，状态栏用户名要点
   `[366, 840]` 而不是屏幕值。
