## 2. 已做

### 2.1 目录重组（方案 A）

原 `docs/` 根级有 23 个插件/算子目录（`图像采集/`、`卡尺测量/`、`模板匹配/`、`运动控制/`……）和 3 个方法论目录平铺，顶层 42 个，读者进去第一屏看不出哪是"功能文档"哪是"工程记录"。

重组为六域：

| 新路径 | 收进来的目录 |
|---|---|
| `docs/代码/采图与显示/` | 图像采集、图像显示、结果显示、结果上报 |
| `docs/代码/视觉算子/` | 创建ROI、卡尺测量、模板匹配、目标检测、缺陷检测、胶路检测、颜色检查、码读取、深度学习、几何工具、坐标变换插件、标定插件、图像脚本、图像赋值、图像预处理、OCR |
| `docs/代码/运动控制/` | 运动控制 |
| `docs/代码/数据与通讯/` | 数据库、通讯相关 |
| `docs/代码/流程与变量/` | 变量管理、流程控制 |
| `docs/代码/界面与框架/` | UI、插件框架 |

用 `git mv` 逐目录搬迁，保留历史。搬迁后统一在每个域目录补 `README.md` 作为域索引。

同时把 38 篇较早的改动记录从 `docs/` 根级移进 `docs/code-changes/`（按 R166 日志落点规则，日志不进业务目录）。

### 2.2 白名单收编

`tools/docs-layout.json` 的 `topDirs` 从 42 项重写为 19 项；`rootFiles` 从 24 项收敛到 **1** 项（只留 `项目全景说明.md` 作为合法根入口）。`docs/` 根级不再允许散落 .md。

### 2.3 文档中心

新建 `docs/README.md` 作为整个 docs 的入口，说明每类目录"是干什么的、什么时候往里写、写什么格式"。它和 `docs/工程纪律/README.md`（三层结构：注入层 `AGENTS.md` → 分册 → 归档）形成两级导航。

### 2.4 断链修复（1200 条相对链接、552 条 file:// 链接）

搬迁会让所有 `../xxx` 相对链接失效。用一次性脚本 `tools/oneoff/docs_linkstats.py` 分类统计后分三轮修：

- **pass1**：机械改写——所有指向旧目录的相对链接按新路径替换；
- **pass2**：`docs/code-changes/` 里指向已迁移代码文件的链接，改为指向新位置或降级为纯文本；
- **pass3**：手工逐条——真死链（目标文件已不存在）。

死链的成因主要有三类，都值得记住：

1. **代码文件改名/合并**：`ScadaSystemParametersViewModel.cs` 并进了 `ScadaSystemSettingsViewModel.cs`，`ScadaRunWindowSettingsViewModel.cs` 同理。这类链接不能机械改路径，得改成"这是旧名，现在在哪"的叙述，否则读者点过去还是 404。
2. **模板文件搬家**：`DefaultStyle.xaml` 里的 ComboBox 模板已下沉到 `Controls/Selection.xaml`，链接要改指向。
3. **历史绝对路径**：552 条 `file:///e:/VM/VisionMaster-W-master/...` 是旧机器路径，全部是历史记录里的引用，处理成纯文本。

### 2.5 LINK 闸门（新增）

`tools/audit_docs.ps1` 新增第 7 项指标 `LINK`：扫描 `docs/` 下所有 .md 的相对 Markdown 链接，目标文件不存在即计数。这样断链不再靠一次性扫描发现。

设计时踩到两个假信号，都做了明确处理：

| 假信号 | 处理 | 理由 |
|---|---|---|
| 代码块里的伪链接写法 | 扫描前先把 ` ``` ` 围栏内容整体抹空 | 那是"教人怎么改链接"的示例，不是链接。`docs/code-changes/2026-10-04-PowerShell中文路径与编码纪律.md` 里就有 |
| 图片链接 `![](images/flow.png)` | 按扩展名豁免（png/jpg/jpeg/gif/svg/webp/bmp/ico） | 本仓 docs 正文基本是纯文本，行内图片引用多为示例；图挂了不影响导航 |

变异反证（AGENTS.md R65③）：往 `docs/README.md` 末尾塞一行指向不存在文件的相对链接 → `LINK=1`；删掉 → `LINK=0`。闸确实会红。

## 5. 踩过的坑

| 坑 | 表现 | 怎么绕过去 |
|---|---|---|
| PowerShell 5.1 按 936 代码页读**无 BOM 的 UTF-8 .ps1** | 中文字面量全变乱码，报 `MissingEqualsInHashLiteral` | 脚本文件**纯 ASCII**，中文（文件名、路径）一律放单独的 UTF-8 JSON，脚本用 `[IO.File]::ReadAllLines($f, [Text.Encoding]::UTF8)` 读。这与 AGENTS.md R1/R2 一致 |
| `git mv` 前目标已存在 | `fatal: destination exists` | 先 `rm -rf` 清目标再 `git mv`。**不要先 `git rm --cached` 动索引**——本轮试过一次，13 个文件瞬间从索引里消失，靠 `git reset HEAD -- .zcode/` 才恢复 |
| `git checkout -- <file>` 恢复不了未跟踪的新文件 | 变异反证后测试行删不掉 | 新文件不在索引里，`checkout` 无版本可回；得直接编辑删行 |
| `pwsh` 在 bash 里不存在 | `bash: pwsh: command not found` | 用 `pwsh` 工具本身；且默认执行策略禁止跑 .ps1，需 `powershell -NoProfile -ExecutionPolicy Bypass -File` |
| bash 里 `mkdir`/写子目录被拒 | `Permission denied` | 那是早先 `workspace-write` 沙箱；改 `danger-full-access` 后正常 |
| 一次性脚本留在 `tools/` | 又变成根目录垃圾 | 全部放 `tools/oneoff/`，收尾时归档或删（R166） |
