### 2. 契约层（新增协议必须理解的部分）

- `ICommunicationConnection`：`Connect/Disconnect/TestConnection/Read<T>/Write/ReadBytes/WriteBytes/ReadBits` + `ByteOrder`。
- 三个**可选能力接口**（按需实现，不实现则上层按“不支持”降级）：
  - `ILinkHealthProbe.HasLinkFault`：段读失败后区分“链路死了”还是“这个地址读不到”，用于立即中断剩余段。
  - `ISegmentReader.ReadSegment`：地址单位不是字节的协议（MC/FINS 按“字”）用它。
  - `IConnectionFailureDetail`：建连失败分类（refused vs 超时）。
- `ICommunicationManager`：连接管理 / 读写 / 变量注册 / 插队读（`ReadVariableNow`）/ 插队写（`WriteVariableNow`、`TryTriggerWriteNow`）/ 两个事件。
- 配置对象：`CommunicationConfig`（连接级：协议、链路配置、扫描组表、周期、自启、坏段隔离、运行时态）→ `ConnectionConfigBase` 子类（链路参数）→ `DeviceAddressBase` 子类（地址参数）。
- 关键封闭点：`CommunicationType` 枚举（`Core\Enums.cs:472`，7 个成员含未实现的 `OpcUa`）+ `CommunicationProtocols.Implemented`（`CommunicationConfig.cs:359`）必须与工厂注册表一致。
- 驱动注册表：`CommunicationDriverRegistry`（字符串 `DriverId` + `ConfigType` + `Create`）已存在，但**当前只有内建 6 个驱动注册，没有任何插件扫描/外部注册入口**（全仓 grep 只有 `ConnectionFactoryManager.RegisterDefaults` 与 CommChecks 的 `FakeDriverFactory`）。

### 3. 收发链路（读）

```
连接配置(方案) → Manager.AddConnection
  → ConnectionFactoryManager.CreateConnection(config)  // 按 CommunicationType 枚举取工厂
  → ConnectionWorker（每连接一条专属线程，状态机 + 4 条命令车道）
  → PollScheduler（扫描组：默认组 + ≤8 自定义组，周期升序=优先级）
  → PollBatchPlanner（按 协议+存储区 分组、贪心合并成“段读”，其余走兜底单读）
  → ICommunicationConnection.ReadBytes / ReadSegment / ReadBits
  → HslHelper 解码（字序）→ CommunicationVariable.UpdateValue
  → MirrorCallback → NetworkVariableModel.UpdateMirrorValue → UI/SCADA；QualityCallback → 质量戳
```

- 判定规则：**本轮所有读都失败 = 通信级故障（LinkFault）→ 断线重连**；个别段失败只按变量级错误消化（`MarkUncertain`），并进旁路健康通道（连续失败 3 轮 = 异常段，可选隔离为 5s 探测一次）。
- 插队让路：轮询在**段与段之间**询问 `HasUrgentPending`，有插队命令即返回 `Yielded`（不 MarkSuccess、不判故障）。

### 4. 收发链路（写）

```
NetworkVariableModel.Value setter（隐式写，数组跳过）
  / TryWriteToValue / TryWriteNowToValue / TryQueueWriteNowToValue（显式写，共用 TryWriteCore）
  → 只读区拦截 → 文本按声明类型解析 → 写租约 → AddressConfig.ConvertToRaw
  → 定长字符串/字符串数组编码 → Manager.WriteVariable / WriteVariableNow / TryTriggerWriteNow
  → Worker 写队列（插队写优先）→ conn.Write → HslHelper.WriteTyped（按协议族分派窄类型）
```

- 车道优先级：插队写 → 插队读 → 常规写 → 常规读；每取一条都重看更高优先级车道（防饿死）。
- 写不重试（避免二次动作）；「立刻读」才有 `RetryCount/RetryIntervalMs` 重试。

### 5. 六个协议实现（`Communication\Communications\Connection\`）

| 协议 | 类 | 实现的能力接口 | 字序 | 批量读 |
|---|---|---|---|---|
| Modbus TCP | `ModbusTcpConnection` | LinkHealth + FailureDetail | 跟随配置（默认 CDAB） | 寄存器段 + 位区 `ReadBits` |
| Modbus RTU | `SerialConnection` | 无（串口无链路错误标志） | 跟随配置（默认 ABCD） | 同上 |
| 西门子 S7 | `SiemensS7Connection` | LinkHealth + FailureDetail | 恒 ABCD | 字节段（位随字节切片） |
| 三菱 MC | `MitsubishiMcConnection` | SegmentReader + LinkHealth + FailureDetail | DCBA | 字段（`ReadSegment`），位区不批量 |
| 欧姆龙 FINS | `OmronFinsConnection` | SegmentReader + LinkHealth + FailureDetail | CDAB | 字段，位区不批量 |
| 自由协议 | `FreeProtocolConnection` | LinkHealth + FailureDetail | ABCD（无意义） | **不可批量**（全走单读兜底） |

- 地址实现：`ModbusAddress`（富地址 `x=fc;addr`，站号 `s=N;` 逐帧）、`S7Address`（`MB/DBn.DBB` + 位后缀）、`McAddress`（按区进制 + `SegmentAddressOverride`）、`FinsAddress`（字/位，`MaxBitOffset=15`）。
- 批量规划器只认 `PollProtocol` 四个家族（S7/Modbus/Mc/Fins）；`PollAddressResolver` 对无结构化配置的旧数据按字符串回退解析。

## 五、踩过的坑（本轮读代码发现的“静默陷阱”）

- `CommunicationConfig` 构造/`CopyFrom` 的顺序不能颠倒：先 `Protocol` 再 `Config`，否则 `Protocol` setter 里的 `OnChanged` 会用默认配置顶掉刚传进来的那份。
- 各 `ConnectionConfigBase` 子类**没有覆写 `Type`**，默认值 0 = `ModbusTcp`；漏赋会被 `Validate` 判“协议类型不匹配”。
- HSL 的 `ByteTransform` 默认 CDAB：不下发配置字序 = 读侧跟随配置、写侧永远 CDAB（16 位看不出来，32 位必错）。
- `PollAddress.GroupKey`/`SegmentPrefix` 漏站号会把不同从站同地址变量合并成一段，静默读到错值。
- MC 十六进制区（X/Y/B/W）必须用 `SegmentAddressOverride`，否则“单读打 256、批读打 598”。
- 变量级周期已删除，周期只挂在扫描组；`ReadCycleMs` 只是默认组周期。
- 驱动注册表（字符串 Id）目前**没有 UI/插件接入路径**，新增“外部驱动”需要补扫描与 UI，不是只写一个类就生效。
