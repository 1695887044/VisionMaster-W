## 五、踩过的坑

### 1. `git mv` 失败时先清目标，不要先动索引

首次 `git mv` 报 `fatal: destination exists`（目标已被之前用 `write` 工具手工复制的副本占用）。当时为了绕开，先执行了 `git rm -q --cached <src>`，结果 `git mv` 变成 `fatal: not under version control`，**13 个文件从 Git 索引中被全部标记删除**。

文件本身没丢，用 `git reset -q HEAD -- .zcode/` 完整恢复。

> **教训**：`git mv` 失败 → 清目标 → 重试。**永远不要"先把索引摘掉再 mv"**。

### 2. PowerShell 控制台代码页 936 会吃掉所有中文

审计脚本第一次跑，输出里所有路径都是 `docs/������ʩ/...`。原因是 PowerShell 控制台默认代码页 936，把它当 UTF-8 解码 `[Console]` 输出流。

修法：脚本开头
```powershell
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding($false)
```

这与 `AGENTS.md` R183① 记录的是**同一类坑**（那里是捕获子进程输出时按 936 解码 UTF-8）。

### 3. PowerShell 按文件顺序执行，函数必须先定义后使用

`Test-JournalDoc` 定义在调用点之后 → `CommandNotFoundException: 无法将"Test-JournalDoc"项识别为 cmdlet`。修法：把函数定义整体上移到白名单加载之后。

### 4. "孤立"这个指标第一次跑出 386，是错的

首次实现把 `code-changes`（392 篇）、`meetings`、`performance` 里的日期记录都算成孤立文件。

**判定：日志式记录不是"孤立"，是"按日期索引"的另一类。** 把它们算进去，指标永远不可能归零 → 永远不可行动 → 还会埋掉真正信号（`docs/项目全景说明.md` 这种真没人找得到的核心文档）。

所以在 `docs-layout.json` 里加了 `orphanPolicy`，把 `code-changes`/`meetings`/`performance`/`归档` 和 `^\d{4}-\d{2}-\d{2}-` 命名的文件排除。**480 篇被跳过**，剩下 23 个是真问题。

### 5. 白名单只能如实登记现状

`docs-layout.json` 里 `topDirs` 39 个、`rootFiles` 24 个，是**当前的真实状态**，不是理想状态。目的：让审计只报告"新增的漂移"，而不是让存量问题淹没它。

`TOP=0` 的意思是"没有新增未登记项"，**不是"docs 结构已经健康"**。随着 B3/B4 推进，这两个列表应该变短——`rootFiles` 最终应归零（基线/总览/交接/方案四类都该搬进子目录）。
