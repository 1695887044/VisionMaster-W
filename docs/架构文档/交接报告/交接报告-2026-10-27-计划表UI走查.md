# 交接报告-2026-10-27-计划表UI走查

> 范围：仅依据用户提供的两张「计划表」对话框截图做视觉与可用性问题走查。
> 图 1 = 默认态（视口 940×724）；图 2 = 「触发」下拉展开态（视口 1160×708）。
> 本轮**未改任何代码**，未核对源码实现，未实机复现。

## 当前状态

「计划表」对话框共整理出 **17 条 UI 问题**（高 7 / 中 7 / 低 3），已按影响程度排序。等待用户裁定其中哪些进入修复范围；未裁定前不动代码。

## 已做

### 高（影响主流程 / 可能造成错误结果）

1. **左栏计划列表整块空白，没有任何空状态**
   位置：对话框左侧「计划（启用的才会执行）」下方的灰色矩形，约 289×380，占对话框宽度约 41%。
   表现：区域内没有列表行、没有列头、没有任何文字，也没有加载中或错误提示；下方只有一个「＋ 新建计划」。用户无法判断是"还没有计划""数据没加载出来"还是"控件坏了"，同时近一半宽度零信息量。

2. **「启用的才会执行」这句话在界面上没有对应开关**
   位置：左栏标签与右侧表单。
   表现：标签明确承诺"启用的才会执行"，但当前界面既没有勾选框，也没有启用/停用开关，也看不出哪一列代表启用状态。计划建出来后无法从界面确认它到底会不会被执行。

3. **右侧表单已预填，左栏却没有任何选中项，编辑态/新建态不可辨**
   位置：左栏（空列表、无高亮行）与右侧已填好的表单（名称「新计划 1」、触发「时间计划」、两行动作）。
   表现：列表里没有任何条目被选中，表单却已有完整默认内容。用户无法判断自己是在编辑一个已存在的计划，还是在填写一个尚未创建的新计划；点「确定」是新建还是覆盖，界面上看不出来。

4. **三套互斥的调度条件同时可编辑，没有依赖关系与必填提示**
   位置：右侧「周期与时刻」区的「每天」下拉、「08:00」、「1,2,3,4,5」、「指定日期」四个控件。
   表现：四个控件外观完全一致、全部可编辑；选「每天」时「每周几」「指定日期」不灰化、不说明、不标必填。用户可同时填三套条件，界面不告诉他哪一套生效——最容易造成"计划在错误时间执行"。

5. **动作行两列没有表头，执行顺序也没有任何表达**
   位置：「动作（按顺序执行；按名字引用变量/画面/流程/配方）」下方两行。
   表现：每行左侧「日志」下拉、右侧「计划触发」输入框，但没有列标题说明左列是动作类型、右列该填什么（变量名？画面名？流程名？）；标题写着"按顺序执行"，行上却没有序号、没有拖拽手柄，两行之间也没有分隔。用户既不知道填什么，也无法确认或调整先后。

6. **动作行右侧有两条无内容的窄条，像被裁掉的控件**
   位置：两行动作行最右端，紧贴「计划触发」输入框，约 10px 宽、25px 高，上下各一。
   表现：白底细边框小矩形，内无图标无文字，右边缘看起来被内容区切断，正好各对齐一行。读起来像"只剩一条缝的按钮"或"只露出一截的滚动条"；整块界面里也找不到任何删除动作的入口。

7. **「触发」下拉展开后，弹层远超控件与对话框边界**
   位置：图 2 的「触发」下拉。
   表现：下拉框本体约 350px 宽，弹层约 625px（约 1.8 倍），右边缘越过对话框右边界约 260px，直接压在对话框外的深色画布上；弹层还把下方「每天 + 08:00」整行完全遮住。弹层像一块脱离对话框的独立白板，窗口再窄就会被裁掉。

### 中（可用性与一致性）

8. **同一张表单出现三种输入框外观**
   位置：名称 / 触发 / 每天 / 时刻 / 每周几 / 指定日期 / 计划触发。
   表现：名称只有一条下划线、无边框；触发、每天、日志是灰底填充框（灰底易被读成禁用/只读）；时刻、每周几、指定日期、计划触发是白底细边框矩形。三种形态混在一屏，用户无法靠外观判断哪些可改。

9. **「周期与时刻」三行的右边缘与标签起点全是参差的**
   位置：右侧「周期与时刻」三行。
   表现：三个输入框右边缘约停在 565 / 565 / 495，而上方「名称」「触发」右边缘在 720；三个右侧标签左起点约在 575 / 585 / 502，互不对齐，也没形成标签列；第一行最左的「每天」还没有标签。整块像随手摆放，扫读时视线来回跳。

10. **垂直间距不一致，且这一组没有被视觉分组**
    位置：同上。
    表现：行间/段间距依次约 19 / 17 / 9 / 15 / 22 / 10px；「周期与时刻」三行同属一组，却没有容器、分隔线或缩进，只靠一行小灰字区分，与上下字段混成一片。

11. **左右两栏几乎贴在一起**
    位置：左栏灰块右边缘（约 365）与右侧表单左边缘（约 375）。
    表现：栏间距约 10px，而对话框左边距约 29px、右边距约 25px。两栏看起来粘在一起，"这是两个区域"的边界读不出来。

12. **右栏下半部大片空白，底部按钮悬空，两栏底部不齐**
    位置：「＋ 添加动作」（约 y=505）到「取消/确定」（约 y=600）之间。
    表现：中间约 85–100px 纯白，无分隔线也无背景区分；左栏灰块底边（约 530）比右栏内容底边低约 25px。整体"上重下空"。

13. **「计划触发」两行文字完全一样，占位提示与真实值不可辨**
    位置：两行动作右侧的输入框。
    表现：两行都显示「计划触发」，颜色字重与真实输入值一致，没有占位符的浅灰样式。用户无法判断这是系统预填的目标名还是让他照着填的示例；直接点「确定」就可能把示例文本当数据保存。

14. **没有必填标记、没有格式引导、没有校验反馈位置**
    位置：整个右侧表单。
    表现：所有字段都没有必填标识；`HH:mm`、`yyyy-MM-dd`、`1=周一…7=周日` 这些格式约束只写在标签括号里，字段本身没有掩码、没有示例灰字、没有日期选择入口；界面上也没有任何校验提示区域，填错时当场得不到反馈。

### 低（观感与一致性）

15. **两个"章节标题"的层级读不出来**
    位置：「周期与时刻」与「动作（按顺序执行；按名字引用变量/画面/流程/配方）」。
    表现：前者是小号浅灰短标签，后者字号更大、颜色更深且塞了一整串括号说明。两者都不像标题——一个像字段说明，一个像帮助文字，读者看不出它们是同级分区。

16. **按钮形态与圆角不统一**
    位置：「＋ 新建计划」「＋ 添加动作」「取消」「确定」。
    表现：前两个是浅灰底 + 边框的方块按钮，取消是无底色的纯文字 + ✕ 字形，确定是蓝色胶囊；同一屏出现三种按钮形态、三种圆角；✕ / ✓ 用字形字符绘制，字重与基线跟旁边中文不完全一致。

17. **小标签偏小偏浅，对比度存疑**
    位置：名称 / 触发 / 周期与时刻 / 时刻 / 每周几 / 指定日期。
    表现：约 12px 的浅灰字压在纯白底上，观感偏淡；这些标签是表单里唯一的字段说明，在深色画布包围的白色对话框里可读性偏弱（未实测数值，仅目测）。
