### 3.5 修法：克隆 + 所有权，四件事缺一不可

**克隆位置：变量写入边界**（`LocalVariableModel.TryWrite` 的 HImage 分支）。两条理由：

1. `Core` 已引 HALCON（`Core\Helpers\HalconImageHelper.cs` 就在），放变量侧能连 SCADA 的写入一起守住；
2. **`GlobalVariableWriter.WriteResolved` 不是真收口**——SCADA 的写走 `ScadaValueSource.VariableHandle.TryWrite`（`Core\Binding\ScadaValueSource.cs:284-294`），**直接调 `IWritableVariable.TryWrite`，绕过写入器**。所以只有变量边界盖得住全部入口。

**一旦克隆，变量就成了 owner，必须同时补齐**（否则每轮泄漏一张全尺寸图，500 万彩图 ≈ 15MB/轮，比现在的 bug 更糟）：

1. **覆盖旧值时释放上一张**：`ReferenceEquals(value, _value)` 跳过。**另外不要释放与 `DefaultValue` 同引用的那张**，但理由要说准：`VariableFactory.cs:25` 对非数组是 `DefaultValue` 与 `Value` **同一个引用**；而"新建变量 + 空初始值"这条路 `TryGetNewInitialValue`（`GlobalVariableManagerViewModel.cs:1609`）走 `Activator.CreateInstance(targetType)`，给的是**空图**不是活图。所以**"恢复初始值拿到已释放的活图"这个后果今天不可达**（我原稿写错了）；真实风险是"首次覆盖把 `DefaultValue` 那个实例 dispose 掉，`ResetToDefault`（`LocalVariableModel.cs:227`）再把已释放对象放回模型"——功能无害，但正是 `PreviewCaptureChecks.cs:16` 明令避免的状态。**严重度是卫生问题，不是 P1 的组成部分。** 补一条：`ResetToDefault` 自身也要释放当前那张，否则 owner 化之后这里漏。
2. **变量删除 / 方案关闭时释放**。注意代价：那句"刻意不放进 `IVariable`，否则所有实现者（含测试桩）被迫实现无关口子"写在 `IValueChangeNotifier` 上（`Core\Models\Variable\IVariable.cs:90`），**不是 `IVariable` 本体**（我原稿引用位置错了，先例仍成立：同文件三个接口同一范式）。所以要走独立接口，并且**必须有调用方**——`VariablePersistenceService.Restore` 的 `workspace.GlobalVariables.Clear()`（`:113`）就是现成入口，覆盖替换 / `ResetToDefault` / 集合移除三处。
3. **释放点收在一处**，不要散在三个插件里。
4. **跨线程：我原判"硬伤"错了，更正如下。** 桌面端那次"像素→位图"转换**跑在写入线程，不是 UI 线程**：`LocalVariableModel.Value` setter 同步 `_valueChanged.Invoke` → `ScadaValueSource.VariableHandle.ValueChanged`（`:277-281`，add/remove 直接转发、无封送）→ `ScadaRuntimeBinder.OnValueChanged`（`:315`，注释原文「值变化回调。**可能在后台线程**」）里读 `subscription.Handle.Value`（`:329`）→ `ToBitmapSource` 就在这一层；UI 线程只在 `Flush()` 里拿已转好的 `BitmapSource` 写控件（`:350`，经 `QueueFlushIfDirty` → `BeginInvoke`）。**所以"写时释放"与"转换"在同一次调用栈里天然串行**，桌面端不会撞车。
   唯一的跨线程读者是 Web `/img`（`RunOnUiAsync` 上 UI 线程，`ScadaWebHost.cs:3610`），而**这个竞态今天就已经存在**——今天上游在轮首 dispose（流程线程）、Web UI 线程正转位图，同样 #4060、同样被吞成 404。修复是把窗口从"上游整段算法耗时"缩到"一次位图转换"，**严格变好**，不是拿偶发换周期。
   口径现成、零锁零封送：**延迟一代释放**（写第 N+1 张时释放第 N-1 张），退役队列按变量实例持有、不用静态。精度上补一句：这不是严格为零——慢读者在写 N+1 时仍可能在转 N-1；要严格零得上引用计数或交 UI 线程释放。**但工程上够，且不再是阻塞项。**

**可观测性**：`ToBitmapSource` 全 catch → 这个故障零日志，现场只会说"图没了"。照 `ImageCollectionService.cs:82` 的 `_deadSourceSkips`（注释："正常应恒为 0；>0 即发布方提前释放了图"）加计数 + Warn，才能事后定位。
