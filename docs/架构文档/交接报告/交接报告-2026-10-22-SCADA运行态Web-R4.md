### 2.2 协议关键字段

- 快照/结构：`{type:"snapshot"|"page", seq, structureSeq, runGeneration, pageId, pageVersion, basePageVersion, page}`。
- 值帧：`{type:"frame", seq, frameSeq, keyframe, runGeneration, pageId, pageVersion, items[]}`。
- 控制：`hello`、`hello.ok`、`pong`、`ack`、`error`、`result`、`bye`、`stopped`、`idle`、`img.token`。
- 重同步：
  ```json
  {"type":"view.resync","id":"...","scope":"structure"|"frames","reason":"...",
   "pageId":"...","pageVersion":42,"runGeneration":7}
  ```
  应答：`ack{kind:"view.resync",ok:true,result:{accepted,scope,coalesced?,idle?}}`；
  限速：`error{kind:"view.resync",code:"E_RATE_LIMITED",retryAfterMs}`。
- 命令：`cmd.element` / `cmd.input` / `cmd.alarm.ack` / `cmd.confirm.request` / `cmd.result` / `lease.*`。
- `cmd.result` 四态：`succeeded/failed/running/unknown`，**不带 `ok`**。

### 2.3 线程与写者纪律（最重要）

- `LastValues` / `FrameSeq` / `DeltaCursor` / `NeedsKeyframe` **只由帧循环线程写**。
  其它线程（WS/UI）只能 `RequestDeltaReset()` 置标志，由 `SendFrame` 开头消费。
- `CurrentPageKey` 目前仍有三个写者（WS 首屏、UI `OnRunStarted/Stopped`、帧循环）：
  字符串引用赋值，内存安全；但与本轮“单写者”裁决不完全一致（见 §8）。
- `structureSeq` 是**每次准备发结构就自增的单调戳**，不是结构身份；失败会烧号、跨会话不连续。
  客户端只接受更大的值。
- `_seq` 是整条消息的诊断序号，构建时自增，**不能**做顺序/缺口判据。
- 控制/数据两条发送循环共用一个 `SemaphoreSlim`：控制消息只等当前一条，不排整批；
  **不是抢占式**（Watson 一条消息发完才能发下一条）。

## 6. 本轮修掉的真实缺陷（交接时不要回退）

1. **ack/bye 排在 256 条值帧后面** → 控制队列 + 发送闸。
2. **`OnRunStopped`/首屏在非帧循环线程清 `LastValues`** → 改成 `RequestDeltaReset` 标志。
3. **15s 发送超时被当正常收尾** → `when (!token.IsCancellationRequested)` + `HandleSendFault`。
4. **`img.token` 入队失败后 15s 图片 401** → 入队成功才更新 current，失败下拍补发。
5. **`caps` 每 2s 全量 200KB** → 稳定哈希，内容不变不发；入队成功才记哈希。
6. **首屏发两份** → `InitialStatePending`，浏览器实测 `structureSeq=1`。
7. **超大页面 1009 无限重连** → 客户端认 close 1009 → `enterFatal`，实测无重连。
8. **跨进程重启 generation 归零导致新快照永久被拒** → hello 带 `runGeneration/structureSeq`，客户端采纳。
9. **`stopped` 与快照跨通道乱序盖住新画面** → `stopped/idle` 加 generation 比较。
10. **resync 跨线程清页键 + 帧循环双发** → WS 线程只置标志，帧循环消费。
11. **`frameSeq` 跳变触发结构 resync 的自激循环** → 删除该触发；只保留组装/首屏/停滞（frames scope）。

## 7. 分片：为什么本批不做（重要裁决）

- R4-1 要求“先量 ack 队头再决定”。S6 实测 ack p95 = **117ms**（目标 200ms 内），帧率/预算不变。
- 分片**不减少字节、不减少一次 `JSON.parse`**；它不是大页面容量方案。
- 架构反编译显示 Watson `MaxMessageSize` 只判**入站**，出站 4MB 上限未被证实；
  `ScadaWebHost.cs` 里“双向”注释与本地 DLL 实现矛盾。
- 当前 3.5MB 硬闸 + 3000 图元 1.5–1.8MB 仍安全。
- **已冻结但未实现**的协议（R4-1 §二-8/9/10）：
  `struct.begin/chunk/end/abort` + `snapshotId` + `structureSeq` + `byte[]` 按 UTF-8 前导字节切
  + `StructureBatch` 单对象入队 + `view.hello{caps:["struct"]}` 能力协商。
  触发条件：页面规模或慢链路实测让 ack/首屏触顶。
