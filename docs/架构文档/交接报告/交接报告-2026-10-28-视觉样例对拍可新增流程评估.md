## 4. 下一步（按性价比排序）

### 4.1 先补一个洞：7 条工位 + Main 都没有判定源

事实链：

- `FlowVerdictResolver.Resolve` 的 `Auto` 回退顺序是 **结果输出步骤 → 配置的结果变量 → 配置的步骤端口 → 约定变量 `<FlowName>_Result`**（`VisionMaster\Services\FlowVerdictResolver.cs:52-63`）。
- 本方案 7 条工位都没有「结果输出」步骤、没有 `ResultSource` 配置；写的是 `Ncc_Result`/`Pcb_Result`…，而约定变量名是 `模板匹配_NCC散焦图_Result` 这种**流程全名 + `_Result`** → **一条都对不上**。
- 结论：L2 的 `FlowRoundResult.Outcome` 在本方案里**每条流程都是 Unknown**，底栏 / `System.Flow.*` 拿不到 OK/NG。
- 附带后果：判定表 NG 会 `Fail()`（`JudgeTablePlugin.cs:773`），而 `FlowInvoker` 在 Unknown 分支仍按"有步骤失败即失败"处理（`Engine\FlowInvoker.cs:165-172`）→ PCB 工位真 NG 时，Main 的「调用工位_Pcb」会报失败。

**最小改法**：每条工位流程末尾（判定表之后）加一个「结果输出」步骤，`IsOk` 接判定表的 `IsOk` 端口，`Reason` 接 `Reason`；Main 末尾接 `allOk`。这样不用改任何代码，`System.Flow.*` 与底栏立刻有数。

### 4.3 流程结构能力还没演练（现在只用了 `For`）

`Core\Models\ProcessStep\` 里已有的容器/控制步骤，本方案一个都没用：

- `ConditionStep`（If / ElseIf / Else，条件可写成 `Score > 0.8` 这类表达式）
- `CaseStep`、`WhileStep`、`BreakStep`、`ContinueStep`
- `ParallelStep`（并行组；纯视觉计算插件带 `[ParallelSafe]`）

最有价值的一条：把某条工位流程改成「匹配失败 → 跳过测量 → 直接判 NG」的 If/Else 结构，这是真实产线最常见的形态，也能顺带压测分支 + 判定表 + 结果输出的组合。

### 4.4 整线启动（LineStart）——把 7 工位从"串在 Main 里"改成"平级会话"

- `FlowInvokeType.LineStart = 128` 已落地，`Core\FlowBatchSelector.cs` 已按"勾了整线就全部启动、各起各的会话"选流程；`ShellViewModel` 两处批量入口都走它。
- 现状：7 工位是 `Subroutine(32)`，由 Main 串行 `调用流程`。任一站技术故障会让 Main 那一步失败。
- 改成整线成员后：7 条流程各自独立会话、互不阻塞，失败只收尾自己（这正是 2026-10-28 的用户裁决）。
- **代价**：7 条流程并发跑，内存与 Halcon 窗口压力上升（仓库有 7 GB 内存事故的历史约束）；PCB 121 张 × 200ms 的延时也会和其它站并行叠加。建议先只把 2~3 条轻站改成整线成员做验证。

## 6. 踩过的坑

1. **`findstr /s` 会连 `obj\` 一起扫**：`Plugins\**\*.cs` 里同名 `AssemblyInfo.cs` 上千份，结果全是噪音。必须用 `Get-ChildItem` + `-notmatch '\\(obj|bin)\\'` 过滤。
2. **`.ps1` 里写中文路径必挂**（R1/R2 又一次验证）：PowerShell 5.1 按 936 读无 BOM 的 UTF-8 脚本，`解决方案\视觉样例对拍\...` 变成 `瑙ｅ喅鏂规...`，报"路径的一部分找不到"。正解：路径放 UTF-8 清单文件，脚本 `[IO.File]::ReadAllLines($f, [Text.Encoding]::UTF8)` 读。
3. **`cmd` 里 `powershell -Command "...\"...\""` 的双引号转义会把正则吃掉**：第一次扫 `[Display(...)]` 得到 0 条命中，不是没有数据，是正则没传进去。落成 `.ps1` 文件再 `-File` 跑才对。
4. **约定变量名不是"工位前缀 + `_Result`"**：`FlowVerdictResolver` 只认 `<FlowName>_Result`（流程全名）。方案里写 `Ncc_Result` 看着像、实际一条都不命中，且**没有任何报错**——判定静默变 Unknown。
