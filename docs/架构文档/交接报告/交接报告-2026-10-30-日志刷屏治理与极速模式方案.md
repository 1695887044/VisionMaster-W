# 交接报告 — 日志刷屏治理与「极速模式」方案（2026-10-30）

## 当前状态

**仅诊断，未改任何代码。** 用户在现场发现运行日志过多，问是否要加「极速模式」只显示有用日志。

结论：**该加，但只按「等级」加开关解决不了问题**——刷屏的 99.9% 是 INFO，而 INFO 里"有用的"和"没用的"混在一起。
另发现两个既有缺陷（见下），它们会直接让任何"按来源过滤"的方案落空。

## 已做：顺带查出的两个既有缺陷

### 缺陷 1：`LogItem.Source` 恒为 null（面板"按来源搜索/来源标签"完全失效）

- `Core\LogService.cs:161` 有 `GetSource([CallerMemberName] ...)`，但**从未被调用**。
- `PublishLog(LogLevel level, string message, string source = null)`（:187）签名带默认 `null`，
  而所有调用点（`Info`/`Warn`/`Error`/`Success`，:135-159）都只传两个实参 → `source` 恒为 `null`，
  且 `new LogItem(level, message, source)` 显式覆盖了 `LogItem` 构造函数里 `source = "System"` 的默认值。
- 后果：`LogConsole.FilterLogic` 的 `log.Source?.IndexOf(...)` 永远为 null → **按来源搜索一条也搜不到**；
  `LogView.xaml` 里的 `SourceChip` 标签永远为空。

### 缺陷 2：面板上限配置不生效

- `VisionMaster\Views\LogView.xaml:489` 硬编码 `MaxItems="2000"`。
- 而 `AppConfigModel.LogPanelMaxRows` 默认 **5000**、且「系统 → 系统参数设置」里可改（:864）。
- `LogViewModel.AppendBatch` 按配置裁到 5000，`LogConsole.TrimToCapacity` 又按 2000 裁一次 → **实际卡 2000，配置改了没用**。

## 下一步：三条路线（待用户裁决）

| 路线 | 做法 | 成本/风险 | 效果 |
|---|---|---|---|
| **A 重复折叠** | `LogService` 内按"同一消息 N 秒内"合并，输出 `…（重复 N 次）` | 小；零契约改动；改的是落盘与面板两条通道，需定"合并窗口" | 当日立减 19%；重载日砍掉绝大部分刷新；每步内容不同的流水仍在 |
| **B 日志分档**（推荐长期）| 加「详细/步骤」档：`ExecutionContext.Logger` 是**步骤执行专用通道**（模块/通讯/系统日志一律走宿主 `ILogService`，不走它）→ 在这一层包一层 `ScopedLogService` 打 `IsStepFlow` 标记即可**准确分类**，不靠前缀猜。面板加 极速/标准/完整 三档，落盘同样按档 | 大：`LogItem` 加字段 + `LogLevel` 或新 `LogChannel` + 约 20 个断言桩 + 落盘过滤；按 R12 走评审 | 一劳永逸：文件 90MB/天 → MB 级，面板只剩人要看的东西 |
| **C 只加面板开关** | `LogConsole` 加 `QuickMode` DP，只显示 WARN/ERR + `[标签]` 类 | 小（1~2 小时）；但按文本前缀分类较脆，且**文件仍 90MB/天** | 面板清爽，磁盘问题不解决 |

### 关键洞察（决定 B 可行且干净）

`ExecutionContext.Logger`（`Core\ExecutionContext.cs:220`）是**运行期唯一递送给插件的日志通道**；
宿主侧的模块日志全部走 `Container.Resolve<ILogService>()`（如 `AdvancedCommunicationManager.LogSink`、`ScadaWeb`、`[启动自检]`）。
两者在**对象身份上就是分开的**——所以"是不是步骤流水"可以在 `ExecutionContext.Create(...)` 一处准确判定，不需要在 57 个插件调用点上做任何改动。

### 建议顺序

1. 先修**缺陷 1、2**（都是明确 bug，改动小、可立即验证）——修完 `Source` 才有真实值，"按来源过滤"才成立。
2. 再做 **B 的显示侧**（面板三档），此时可以先用"来源/标签"兜底。
3. 最后做 **B 的落盘侧**（按档过滤写文件），配合"临时切完整档复现问题"的现场用法。
4. **A 独立做**，与 B 不冲突，可以合并进同一批。

## 踩过的坑

- 本机 `findstr /s` 对中文关键字（如"开始执行延时"）经常**零命中**——`findstr` 按 ANSI/GBK 匹配，源码是无 BOM UTF-8。
  正确做法：PowerShell `[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` 后 `-match`。本次靠这条才定位到 `Plugin.Utility\DelayPlugin.cs`。
- `findstr` 输出中文会变乱码（同理），别拿它读中文源码内容做判断，只用来定位文件名/行号。
- 本机 `git` 不在 PATH，无法用 `git log`/`git diff` 判断 `MaxItems="2000"` 是遗留还是刻意——只能按"与配置矛盾即不一致"处理，不动它。
