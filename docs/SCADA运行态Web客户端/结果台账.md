## 0. 记账规则

1. **只追加、不改写历史行**；更正另起一行并在 `备注` 引用原行。
2. 同一轮的所有行**构建 hash 必须一致**；出现两种 hash = 这一轮混跑了两个版本，整轮作废重跑。
3. `结果` 只能是 `通过` / `失败` / `阻塞`；**不许写"跳过"**（跳过按失败算，R38）。
4. `失败` / `阻塞` 行必须带 `缺陷 ID`（未建缺陷单时用 `U-xx` 引用本文件 §5 的未关闭项）。
5. **构建 hash 口径**：本仓不是 git 仓库，无法给 commit hash，统一用**被测产物 DLL 的 SHA256 前 12 位**（同一轮同一产物）；无法锚定到产物时（例如日志对应的二进制已被重建）**必须写明"只锚定日志 hash"**，不许拿当前 DLL 冒充。
6. 每轮结束由 docs 角色汇总一次；发布前由 reviewer 抽查 ≥20% 的证据路径（X02）。
