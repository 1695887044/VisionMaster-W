## 1. Indicator / Lamp 在非正方形图元上按短边内切圆

| 项 | 内容 |
| --- | --- |
| 现象 | 桌面 `Hmi.Indicator` / `Hmi.Lamp` 的灯体随图元格子拉伸：96×140 的格子渲染成**椭圆**（高大于宽）。web 取 `side = min(宽, 高 - 标签高) - 2`，灯体是**正圆/正方**，标签紧贴灯下方。 |
| 桌面 | WPF 模板里的 `Ellipse` 吃满格子的可用区域，随行高被拉成椭圆。 |
| web | `elements-process.js` 的 `createLampLike`：`face.style.borderRadius = square ? '3px' : '50%'`；`side = Math.max(0, Math.min(size.w, available) - 2)`。 |
| 结论 | **允许偏差**（有意）：工业画面上的"灯"必须是圆/方；把 96×140 拉成椭圆会让操作员误读为"仪表"而不是"指示灯"。WPF 的发光/阴影在 web 用 `box-shadow` 近似，边缘 1–2px 的差异并入本条（B34 的"阴影/发光"判据由本条覆盖）。 |
| 后续处理 | M1.5 视觉对照时把灯体包围盒按"短边正方形"排除；若用户要求与桌面**逐像素**一致，改为 `border-radius:50%` + 宽高各自 100%（会牺牲灯的可读性，需用户书面确认）。 |
| 证据 | `_scada_web_shots\demo-1920x1080.png`；`elements-process.js` `createLampLike`（约 495–506 行）。 |

## 2. Tank 读数 / 位号带深色底带（桌面无）

| 项 | 内容 |
| --- | --- |
| 现象 | web 的 `Hmi.Tank` 在罐体中央给"读数 + 位号"加了一块半透明深色底带（`hmi-tank-text`），桌面模板没有这块底带，文字直接压在液面/空腔上。 |
| 桌面 | 读数/位号是普通 `TextBlock`，背景透明；深色液体与浅色文字靠对比度硬扛。 |
| web | `elements-process.js` 的 `Hmi.Tank`：`textBox` 叠加在 `liquid` 之上，CSS 给 `hmi-tank-text` 深色半透明底。 |
| 结论 | **允许偏差**（可读性优先）：液位在 50% 附近时，桌面文字会同时压在液体与空腔两种底色上，对比度不稳定；web 的底带保证任何液位都可读。 |
| 后续处理 | M1.5 把底带做成 `ShowValueBackdrop`（默认 true）可关；B34 对照时排除该条带，或在"桌面基准"一侧也加同款底带（需用户裁定基准）。 |
| 证据 | `_scada_web_shots\demo-1920x1080.png`；`elements-process.js` `Hmi.Tank`（约 599–613 行）。 |

## 3. 长位号用 ellipsis（对齐桌面）

| 项 | 内容 |
| --- | --- |
| 现象 | 图元名/位号超出宽度时，web 用 `text-overflow: ellipsis` 单行截断；桌面 `TextBlock` 在同样宽度下也是单行省略（`TextTrimming=CharacterEllipsis` 同口径）。 |
| 桌面 | 单行省略号，不换行撑破图元。 |
| web | `elements-process.css` / `styles.css` 多处 `overflow:hidden; white-space:nowrap; text-overflow:ellipsis`。 |
| 结论 | **已对齐**（不算偏差）：曾经担心 web 会换行，实测与桌面同口径。 |
| 后续处理 | 保留；B34 的"文字内容逐字相等"判据对省略号后的文本按**完整原文**比对，不按屏幕可见串比对。 |
| 证据 | `_scada_web_shots\demo-1366x768-final.png`；`elements-process.css`（约 65/123/165/204 行）。 |

## 4. 字体栈：Microsoft YaHei vs Microsoft YaHei UI

| 项 | 内容 |
| --- | --- |
| 现象 | web 的图元字体栈是 `"Microsoft YaHei", "PingFang SC", "Segoe UI", system-ui, sans-serif`；桌面主题用的是 **`Microsoft YaHei UI`**（Fluent 主题默认 UI 字体）。同一字符串的**字宽/行高**有 1–2px 级差异，中文标点的左右留白也不同。 |
| 桌面 | `Microsoft YaHei UI`（WPF 主题资源）。 |
| web | `elements-process.css` 的 `--font-ui` 与图元字体栈；`styles.css` 的顶栏是 `"Segoe UI", "Microsoft YaHei"`。 |
| 结论 | **允许偏差**（≤2px 文字偏移、≤1px 行高差），但**文字内容必须逐字相等**。 |
| 后续处理 | M1.5 若能把 web 字体栈首项改成 `"Microsoft YaHei UI"` 且实测度量一致，则改；否则维持现状并把"允许 ≤2px"写进 B34 判据。**不许**为了像素对齐把中文换成图片。 |
| 证据 | `elements-process.css` 第 22 行；`styles.css` 第 45 行；`demo-1920x1080.png`。 |

## 5. `non-scaling-stroke` 未实现（SVG 线宽随缩放变粗/变细）

| 项 | 内容 |
| --- | --- |
| 现象 | web 的 SVG 描边（Gauge 刻度、Valve 轮廓、Tank 描边等）用 `stroke-width` 固定逻辑像素，**没有** `vector-effect: non-scaling-stroke`；外层 `transform: scale(k)` 会把线宽一起缩放。1920×1080 的自然缩放 `k=0.922`（线略细 8%）；1280×720 用 `MIN_SCALE=0.8`（线细 20%）。 |
| 桌面 | WPF 的 `StrokeThickness` 是设备无关像素，**不随窗口缩放**（除非显式 `LayoutTransform`）。 |
| web | `elements-process.js` 的 SVG 节点未设 `vector-effect`；`styles.css` 无全局补偿。 |
| 结论 | **需复刻（M1.5）**：线宽随缩放漂移会让"1px 描边"在 1280 屏上变成 0.8px（发虚）、在 4K 上变粗。 |
| 后续处理 | M1.5 给所有 SVG 描边加 `vector-effect: non-scaling-stroke`，或按 `1/k` 反算 `stroke-width`；B34 在 `k≠1` 时专测线宽。M1 只在 1920×1080（k≈0.922）做对照，暂按"允许偏差"记录。 |
| 证据 | `elements-process.js` 的 `svgNode`/`arcCircle` 段；`app.js` 的 `MIN_SCALE` 与 `applyScale`。 |

## 6. 1280 宽下启用最小缩放 + 滚动

| 项 | 内容 |
| --- | --- |
| 现象 | 视口小于"设计尺寸 × 0.8"时（1280×720 自然缩放只有 0.589），web **不再继续缩小**，而是按 `MIN_SCALE=0.8` 铺开、把 `#stage` 切成滚动容器（`.is-scroll`）。1920×1080 自然缩放 0.922 > 0.8，不触发。 |
| 桌面 | 运行窗口可以继续缩小（文字变小但仍整页可见）。 |
| web | `app.js`：`var scale = Math.max(natural, MIN_SCALE)`；`MIN_SCALE=0.8`；`dom.stage.classList.toggle('is-scroll', clamped)`。 |
| 结论 | **允许偏差**（设计决策）：13px 文字在 0.589 下只有 7.7px，不可读；滚动比"整页缩小到看不清"更适合现场。 |
| 后续处理 | 保留；B34 的视口固定 1920×1080（不触发）；D30（响应式）单独记录"1280 下有滚动"。若用户要求 1280 整页可见，把 `MIN_SCALE` 降到 0.55 并接受文字变小（需用户裁定）。 |
| 证据 | `app.js` 第 45 行、`applyScale`（约 1400–1435 行）；`_scada_web_shots\demo-1366x768-final.png`。 |

## 7. Tank 用圆角矩形裁剪代替几何求交

| 项 | 内容 |
| --- | --- |
| 现象 | 桌面 `Tank.FillGeometry` 是"罐体轮廓 ∩ 底部矩形"的**几何求交**（圆角处液体边界与罐体轮廓完全贴合）；web 用 `overflow:hidden` 的圆角容器 + 内部矩形液面，**圆角处按容器圆角裁剪**，不是与罐体轮廓求交。 |
| 桌面 | `TankBodyGeometry` / `FillGeometry` 两条 `Path` 几何。 |
| web | `hmi-tank-shell`（`overflow:hidden` + `border-radius`）内放 `hmi-tank-liquid`，液面高度按比例。 |
| 结论 | **允许偏差**（像素级）：在圆角半径 12px 的四个角，液体边界与桌面几何最多差 1–2px；不影响液位读数。 |
| 后续处理 | M1.5 若要 `FillGeometry` 的 DP 对照（B33b），必须改成 SVG `clipPath` 与罐体轮廓同一条 `d`；M1 的 B34 把四个圆角 2px 环带排除。 |
| 证据 | `elements-process.js` `Hmi.Tank`（约 585–680 行）；`_scada_web_shots\demo-1920x1080.png`。 |

## 8. ProgressBar 用百分比宽度代替像素 `FillLength`

| 项 | 内容 |
| --- | --- |
| 现象 | 桌面 `ProgressBar.FillLength` 是**像素长**（`可用宽度 × ratio`，含边框/内边距扣减）；web 的填充是 `width: ratio*100%`，由 CSS 布局算像素。 |
| 桌面 | `FillLength` 是 double，参与 B33 的 DP 对照。 |
| web | `elements-process.js` 的 `Hmi.ProgressBar` 设百分比宽度；没有输出像素 `FillLength`。 |
| 结论 | **允许偏差**（等效）：视觉上同一比例；差异只在 1px 取整与圆角端点。 |
| 后续处理 | M1.5 的 B33b 要补"`FillLength` 像素值"计算（读容器 `clientWidth` × ratio，按桌面同一扣减规则），否则 B33b 不通过；M1 的 B33 只判比例。 |
| 证据 | `elements-process.js` 的 `Hmi.ProgressBar` 段；`demo-1920x1080.png`。 |

## 9. SVG 抗锯齿差异

| 项 | 内容 |
| --- | --- |
| 现象 | 斜线/圆弧（Gauge 刻度、Valve 蝴蝶结、Tank 圆角）在浏览器与 WPF 的**边缘像素**不同：浏览器 Skia 的抗锯齿灰度分布与 WPF `RenderTargetBitmap` 的 `Pbgra32` 不同，边缘 1px 内会出现 ±10 级灰度差。 |
| 桌面 | WPF 抗锯齿 + `RenderTargetBitmap`。 |
| web | Skia/Chromium 抗锯齿；`deviceScaleFactor=1`。 |
| 结论 | **允许偏差**：B34 的颜色判据只看**块内主色 ΔE ≤3**，边缘 1px 不计；几何包围盒仍按 ≤1px 判。 |
| 后续处理 | 保留；若将来做逐像素 diff，必须先做 1px 边缘腐蚀再比，否则永远红（与 R77 的"不许写永远为假的像素断言"同一条纪律）。 |
| 证据 | `demo-1920x1080.png` 与 `docs\UI设计基线\scada-controls\evidence\after-phase1-core.png` 的边缘对照。 |

## 10. 登录卡片与演示标记（web 独有，桌面无对应物）

| 项 | 内容 |
| --- | --- |
| 现象 | ① 无 ticket 打开页面时，web 显示**登录卡片**（用户名 / 密码 / 登录 / "以只读身份查看"），桌面端没有这一屏；② 演示页右上角有 `#demo-chip`"演示数据"标记与半透明水印，桌面运行窗口没有。 |
| 桌面 | 桌面端由本机账号直接进入；演示页不加水印。 |

| 结论 | **允许偏差**（web 独有能力，不是"桌面已有但 web 没复刻"）：登录卡片是 M1c 的登录入口（矩阵 B02/B05）；演示标记只出现在演示数据页，用于区分"真实运行"与"演示/静态数据"。 |

| 证据 | `Web\VisionMaster.ScadaWeb\wwwroot\index.html`、`app.js`、`styles.css`；M1c 浏览器实测（Agent S 报告，未留运行日志）。 |

## 11. 演示页棒图配色（对比度优先）

| 项 | 内容 |
| --- | --- |
| 现象 | 演示页的 `Hmi.ProgressBar` 用 `Fill=#0E7490` + 白字，实测对比度 **5.36:1**（WCAG AA 正文门槛 4.5:1）；桌面默认主题的棒图填充更浅，白字对比度不足。 |
| 桌面 | 棒图填充走主题令牌；浅色填充 + 白字在部分主题下对比度 < 4.5:1。 |
| web | 演示页样式覆盖棒图填充色（`styles.css` / `elements-process.css`）；**仅演示数据**，真实运行仍沿用桌面令牌。 |
| 结论 | **允许偏差**（仅演示页的可读性取舍，不是图元默认行为）。 |
| 后续处理 | B34 用真实页面（不覆盖配色）对照，演示页截图**不作为像素基准**；若用户要求演示页与桌面逐像素一致，改回主题令牌并接受对比度不足（需书面确认）。 |
| 证据 | 演示页样式；M1c 浏览器实测（Agent S 报告，对比度 5.36:1）。 |

## 12. 2026-10-22 A′ 第一批：5 个复杂图元仍无 Web 渲染器 + 轴面板只读

| 项 | 内容 |
| --- | --- |
| 现象 | `Hmi.ChartTrend` / `Hmi.DataGrid` / `Hmi.ImageView` / `Hmi.AxisPanel` / `Hmi.AxisConsole` 在 Web 上仍落占位盒（`app.js` 的 `createRecord` 兜底 + 一次 `console.warn`）。`Hmi.AxisPointTable` 是 `ShowInToolbox=false` 的兼容别名，不在工具箱集合里，但老页面出现时同样落占位盒。 |
| 原因 | 这 5 类不是"再写一个渲染器函数"能补齐的：曲线需要采样数据通道、表格需要行/列数据通道、图像需要 `/img` + `imageToken`、轴面板/轴控台需要 `IScadaAxisSource` 的 Web 投影。当前 Web 值帧只有 text/number/bool/color 四类标量。 |
| 结论 | **已知缺口，显式登记**（不是静默偏差）。`ScadaChecks` [WR0-WR4] 用例外清单钉住：例外只许变短；实现一个就红，要求删例外；新增图元漏渲染器会红。 |
| 后续处理 | 下一批按"先数据通道、再渲染器"做；曲线/表格/轴面板分四段验收；图像先落 `/img` token。 |
| 轴面板只读 | A 范围（2026-10-22）：Web 不做运动/停止；`BuildAllowedSet` 硬排除 `StartFlow/RunFlowOnce/ResumeFlow`，运动九条仍由 `AllowMotionCommands` 默认关闭。轴面板即使将来有渲染器也只显示状态，不提供使能/点动/回零/定位/示教/停止入口。**已封（2026-10-22 追加）**：Web 写流程触发变量回 `E_FLOW_TRIGGER`（`IScadaFlowTriggerQuery`，判据与 `FlowVariableTriggerService` 同源）；guard 未接线时 fail closed（`E_INTERNAL`）。 |
| 证据 | `Web/VisionMaster.ScadaWeb/ScadaWebHost.cs`（SendFrame/结构键）、`wwwroot/app.js`（createRecord 兜底）、`ScadaChecks/WebRendererCoverageChecks.cs`、`Web/ScadaWebChecks` 117/0。 |
