## 3. 关键设计落地（与计划书的对应）

| 计划书要求 | 落地方式 |
| --- | --- |
| 一品牌一个驱动 DLL、扫描识别 | `LoadMotionDrivers` 扫 `IMotionDevice` + `[Display]`，与相机驱动同构；插件工程放 `Plugins\` 即自动投递 `Modules\` |
| 能力协商而非大接口 | `MotionCapabilities`：轴号/输出点/回零方式在**入队时**就校验，不支持当场拒绝 |
| 逻辑轴名寻址 | `AxisMapping.LogicalName`，流程引用名字，物理轴号可随接线变化 |
| 单位统一 | 命令与状态一律 **mm**，脉冲当量在 `AxisMapping.UnitsPerMm`，换算在驱动层 |
| 安全与流程解耦 | 软限位、看门狗、报警侦测全部在 `MotionDeviceBase`，**与流程无关**（流程没跑也生效） |
| 异步语义 | `Move` 只下发；`等待到位` 独立步骤等设备状态 |
| 急停插队 | 紧急槽位 + 清队列 + **专用取消源打断正在执行的命令** |
| 故障分级 | `MotionFault`（Notice / Recoverable / RequiresReset / RequiresService）+ 中文建议 |

## 4. 实现过程中发现并修掉的真实缺陷

写实现时按"边写边验"暴露了三个**设计层面的**问题（都不是编译错，而是行为错）：

### ① 急停打断不了正在执行的命令

最初实现：`EmergencyStop()` 清空队列 + 插一个紧急槽位。看着对，实际不对 ——
命令线程是**逐条**执行的，若正在跑一条耗时命令（回零几十秒），急停要等它跑完才轮得到。
而真实场景里恰恰是"回零卡住/轴在跑"的时候最需要急停。

**修法**：加急停专用 `CancellationTokenSource`，`EmergencyStop()` 时 Cancel 它；
执行命令时把"设备令牌"与"急停令牌"**链接**后交给驱动 ——
驱动只要尊重传入的 ct（等待循环用 `ct.WaitHandle`），就自动获得"急停打断"能力，不必自己区分两种中断。

同时区分了两种取消的语义：**被急停打断 = 预期行为**（不报故障、不进安全停机），
**设备断开/流程停止 = 另一种取消**。否则"人工按了急停"会被记成一次设备故障，现场排查会被带偏。

### ② 完成信号早于副作用

`CompleteCommand`（置状态 + **发完成信号**）先执行，`MarkHomed(true)` 后执行 ——
等待方被唤醒时可能读到"命令已完成、但 `IsHomed` 仍是 false"的中间态。
而"回零完成后位置才可信"恰恰是紧接着就要用的结论。

**修法**：先落副作用，再发完成信号 —— 完成信号的含义应该是"这条命令的一切都结束了"。
（这条是冒烟跑出来的：`回零后 IsHomed=true` 偶发失败，一次 778/16。）

### ③ 端口弱类型入口的语义陷阱

`OutputPort<T>.Value` 是 `object`（弱类型入口，供 WPF 绑定用），`GetTypedValue()`/`ActualValue` 才是强类型生效值。
把它直接用在三元条件里编译不过；另外 `InputPort<bool> Value` 这种属性名会与基类成员撞车、
解析到的不是自己的端口。都已按仓库既有语义改正（取值先落局部变量、端口属性名避开 `Value`）。

### 运动内核断言（`FlowCanvasChecks/MotionChecks.cs`，54 条，**零失败**）

用虚拟卡 + 时间推进 + 故障注入，覆盖 6 组（★ 是其中最关键的一批）：

```
---- [M] 命令门禁与异步语义（下发 ≠ 到位） ----
  [√] 未连接时命令被拒绝  [√] 连接成功  [√] 能力已回填（3 轴/8 DI/8 DO/硬限位）
  [√] 绝对式编码器连接后位置即可信  [√] 轴使能命令完成且设备回报使能
  [√] ★Move 下发成功 ≠ 已到位（命令 Done，但轴仍在途中，位置 2.00mm）
  [√] 轮询推进后轴真的走到目标（20.00mm）  [√] 轴号越界被拒绝

---- [M] 软限位门禁 ----
  [√] 超软限位被拒绝  [√] 记为 Notice 级（业务正常，不当设备故障）  [√] 设备仍可用

---- [M] 急停：清空队列 + 打断正在执行的命令 ----
  [√] 回零执行期间后续命令在排队（待执行=2）  [√] 急停被接受
  [√] ★急停能打断正在执行的命令（回零 → 已取消，"被急停中断"）
  [√] ★急停清空待执行队列（q1/q2 均 Canceled）
  [√] 急停是预期操作：不记故障、不进安全停机

---- [M] 看门狗：轮询失联 → 安全停机 + 位置失效 ----
  [√] 增量式编码器连接后位置不可信  [√] 回零后 IsHomed=true
  [√] ★轮询连续失败后进入安全停机（看门狗）
  [√] 通信类失联记为可恢复级（而不是需人工复位）
  [√] ★增量编码器失联后 IsHomed 归 false（必须重新回零）
  [√] 安全停机后不再接受运动命令

---- [M] 报警：状态门禁 → 清报警恢复 ----
  [√] ★轮询到伺服报警 → 状态转 Alarm
  [√] 报警故障为需人工复位级
  [√] ★报警态拒绝运动命令（不会对着报警轴下发 Move）
  [√] ★清除报警后回到可运动状态（不必重启软件）  [√] 清报警后运动恢复正常

---- [M] 回零 ----
  [√] 回零命令完成  [√] 回零后位置归零
  [√] ★不支持的回零方式在入队时就被拒绝（而不是运行到一半才失败）
```

   契约、门禁、看门狗、急停这些**与板卡无关的部分已经全部就位**，驱动只需填设备差异。
