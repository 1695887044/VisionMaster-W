## 一、需求与决策

### 1. 需求（用户原话）

> 位置尺寸 整栏都不需要绑定  外观也是
> 图元要有图层的概念

> 图层的功能应该是选中控件后点击右键功能栏显示图层功能,不需要放到属性栏

三条诉求：

- **去绑定**：「位置与尺寸」整栏、「外观」整栏都不能绑变量；
- **图层**：图元要有图层（Layer）概念——领域侧 `ScadaPage.TryAssignLayer` / `TryMoveElementZ` 早已就绪，缺的是**界面入口**；
- **入口位置**：入口必须是**选中图元后的右键上下文菜单**，**不放属性栏**（第一版曾落在属性面板的「图层」组，本轮整体撤掉并迁移）。

### 2. 入口为什么从属性栏搬到右键菜单

这不是"换个地方摆"，是**作用域**变了：

- 「所属图层」「置顶/上移/下移/置底」的作用域是**当前选中的那个图元**，是**动作**（动词），不是图元自身的属性值（名词）。属性面板回答的是"这个图元是什么样"，右键菜单回答的是"拿这个图元做点什么"。
- 属性面板的行是**跟着选中项重建**的，把动作塞进去就会出现"面板每换一次选中，动作行跟着重建一遍"的浪费，且和"变量绑定"那一类真属性混在一列里，用户读不出哪行是改值、哪行是触发。
- 右键菜单天然带**目标**（用户指哪儿就是哪儿），不需要额外解释"这里的叠放指的是谁的叠放"。

### 3. 决策清单

| # | 决策 | 依据 |
|---|---|---|
| U-1 | `ElementDescriptor.NonBindableGroups = { "位置与尺寸", "外观" }`，**按组**收口而不是逐条改 `IsBindable` | 口径是"整栏"级别的：逐条改会在下次往这两组里加属性时漏掉一条，而按组收口是"新属性默认进不来" |
| U-2 | 注册期校验：往不可绑组里塞 `IsBindable = true` 的属性直接抛异常 | 让口径在**启动时**就炸，而不是等用户看到一颗不该存在的 ƒx |
| U-3a | 右键菜单顶层两栏：**「图层」子菜单**（候选 = 本画面图层表 + 末位「（未分层）」，当前归属打勾）+ **「叠放次序（n / N）」子菜单**（置顶/上移一层/下移一层/置底） | 归属是有限枚举（用户认名字不认 Guid），做成单选式勾选；叠放是四个方向的动作，各自配一个箭头图标，从上到下就是"从最前到最底" |
| U-3b | **菜单内容由视图模型产出"描述"，视图只做机械翻译**：`BuildElementContextMenu()` 返回 `IReadOnlyList<ScadaMenuItem>`，不产 `MenuItem` | ① 视图模型不该认识 WPF 控件；② 断言工程刻意没有 `Application` / `Dispatcher`，造不了控件——而"有哪些图层、哪项打勾、哪项判灰"恰恰是最该被断言的部分。切成两半后，这半边是纯数据，可以直接验 |
| U-3c | 命令用**闭包**捕获目标，不用 `CommandParameter` | 泛型 `DelegateCommand<T>` 在参数为 null 时 `CanExecute` 一律判假，「（未分层）」这一项要用 `null` 当参数会被整项灰掉。每项 `new DelegateCommand(() => AssignSelectedLayer(target))` 绕开这个坑 |
| U-3d | 右键**按下的那一刻**由画布对齐选中态（`OnPreviewMouseRightButtonDown`），且**刻意不设** `e.Handled`；空白处右键**不清**选中 | `SelectedElement` 记的是上一次**左键**选中的东西，少了这一步会在 B 上点右键却改到 A；不设 `Handled` 是因为菜单由 `ContextMenuService` 在右键抬起时弹出，谁都不该抢它的路；空白处不清选中，否则菜单里原有的目标会凭空消失 |
| U-3e | 菜单**每次弹出即重建**（`menu.Items.Clear()` 后重装）；无选中或运行态（`IsReadOnly`）时 `e.Handled = true` 不弹 | 描述不持有任何会过期的状态，也就没有"菜单还开着、模型被别处改了"这类劈叉；没有目标时弹出来只会是一排灰按钮，不如不弹 |
| U-3f | 位次文案写进**分组标题**：`叠放次序（2 / 5）` | 属性面板撤掉「叠放次序」行之后，这里是用户唯一能读到"我在第几层"的地方 |
| U-3g | 端点判灰的判据与 `ScadaPage.TryMoveElementZ` 的**空操作条件完全同源**（`CanMoveSelectedZ` 复用 `IndexInZOrder` 的稳定排序口径） | 两处各排一次就会出现"按钮亮着但按下去没反应" |
| U-3h | 属性栏的「图层」组**整体撤掉**：`ScadaLayerRow` / `ScadaZOrderRow` / `_layerPage` / `BindLayerPage` / `ZOrderRowBody` 模板 / `IsStandaloneEditor` 分流全部删除 | 同一件事不留两个入口，否则两边口径一旦漂移，用户看到的是"面板里说在第一层、菜单里说在第二层" |

### 4. 口径沉淀

- **不可绑的是"设计期版面语言"，可绑的是"运行期语言"**：位置/尺寸/旋转/填充色/边框/圆角决定"画面长什么样"，改它属于重新设计；文字/文字颜色/状态/数据才是"被变量驱动"的量。SCADA 里"液位越限就变红"绑的是**颜色**，不是宽高。
- **动作进菜单、属性进面板**：判断标准是"这句话是名词还是动词"。这条口径以后加新功能时直接照用（对齐/分布/成组/删除都该进右键菜单）。
- **描述与控件分层**：视图模型交出"是什么"，视图负责"长什么样"。翻译层只有一份，不许在别处再抄一份。

### 3. 图标字体：一条"假绿"堵漏（本轮最值得记的一条）

**现象**：⑪B 的证据图上，菜单图标全成了**豆腐块**（□），而字符串层断言**全绿**。

**根因**：`App.xaml:11` 里的图标字体是**绝对 pack 写法**

```
pack://application:,,,/UI;component/Asserts/FontFamilys/Font Awesome 6 Pro-Solid-900.otf#Font Awesome 6 Pro Solid
```

这写法要靠 `Application.ResourceAssembly` 定位 `application` 那一档。断言宿主里**没有 `Application`**，实测该写法**静默回落成 Arial**（`FamilyNames=Arial`、`TryGetGlyphTypeface=False`），于是字形全部取不到。

**修法**：改用"**包基址 + 相对路径**"这一档（WPF 给无 App 宿主留的写法）：

```csharp
new FontFamily(
    new Uri("pack://application:,,,/UI;component/Asserts/FontFamilys/"),
    "./Font Awesome 6 Pro-Solid-900.otf#Font Awesome 6 Pro Solid")
```

指向同一个 otf、同一个族名，实测 `TryGetGlyphTypeface=True`、码点 `F5FD` 命中、`FamilyNames=Font Awesome 6 Pro Solid`。**不是换了个字体，是换了个能解析出来的地址写法。**

**防回归**：新增一条断言把"图标成豆腐块"钉死——`Typeface.TryGetGlyphTypeface` 成功 + `CharacterToGlyphMap.ContainsKey(0xF5FD)` + 族名等于 `Font Awesome 6 Pro Solid`。否则这种"字符串全绿、图上一排方框"的绿是骗人的。

## 四、已知边界

1. **只有"图元 → 图层归属"，没有"图层面板"**：新建/重命名/删除图层、图层的显隐（👁）与锁定仍无界面入口（模型侧 `TryMoveLayer` / `TryRenameLayer` / `TryRemoveLayer` 已就绪）。归 S10。
2. **图层是"分组开关"，不是"深度容器"**：谁盖住谁只由 `ZIndex` 决定，与图层无关。用户可能直觉以为"归到上层图层就会盖住下层图层的图元"，这条口径需要在 S10 的图层面板上讲给用户看。
3. **无拖拽调序**：叠放只能靠四个方向项，没有"图层面板里拖一下"。归 S10。
4. **右键菜单没有"删除/复制/对齐"**：本轮只承载图层与叠放两件事。对齐/分布/成组/删除后续按同一套 `ScadaMenuItem` 描述机制加项即可（加项不动视图，只动 `BuildElementContextMenu`）。
5. **离屏渲染看不到"用户视角"**：`IsVisible` 恒为 false（没接 `PresentationSource`），"看不看得见"只能沿视觉树往上问 `Visibility`。
6. **图标字体在断言宿主里必须用"包基址 + 相对路径"写法**：宿主 `App.xaml` 里仍是绝对 pack 写法（那里有 `Application`，正常解析）。两处写法不同是环境差异所致，改动字体时**两边都要看**。
7. **SCADA 新代码尚未纳入版本控制**：`Scada/`、`Scada.Controls/`、`ScadaChecks/` 与 `VisionMaster` 下的 SCADA 文件仍是未跟踪状态。这是当前头号风险。
