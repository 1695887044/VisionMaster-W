## 🔴 高危

### H1. RegisterVariable 逐个触发全量重编译 → O(N²)
- 位置：[AdvancedCommunicationManager.cs L578-579](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)（RegisterVariable 末尾 `RequestPollPlanRebuild`）+ [L628-632](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)
- 链路实证：NetworkVariableBridge 订阅 GlobalVariables 集合事件**逐个 Register**（建变量、加载方案 RebindAll、改地址、改名都触发）→ 每次注册末尾 `RequestPollPlanRebuild` → **连接在线时每次都全量 RebuildPollPlan（O(N)）**
- 后果：N 个变量 = N² 次编译。10 个无感；1000 个 = 100 万次段划分操作；几万点 = 分钟级卡死 + GC 风暴。"未连接时推迟编译"的优化只在冷启动有效，**在线批量注册（重载方案/批量改地址）全中招**
- 修法方向：RegisterVariable 只"标脏"不重建；重建收敛到三个既有落点（Connect / RequestConnect / OnWorkerStateChanged(Connected)）+ 新增"Worker 轮询拍开始前检查脏标记"包装层。Plan 对象引用替换本身原子，无并发风险

### H2. RegisterVariable 每变量一条 Info 日志
- 位置：[AdvancedCommunicationManager.cs L549](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)
- 后果：加载几万点方案 = 5 万条"注册变量: ..."刷爆 UI 日志窗口（日志控件自身被 UI 线程打爆）
- 修法：注册期日志降为 Debug 级（配合 L8 修 LogDebug 通道），或批量注册 API 汇总成一条

### H3. RemoveConnection 不清理 _varForwardHandlers → 对象滞留
- 位置：[AdvancedCommunicationManager.cs L204-210](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)（移除了 _connections/_configCache/_registeredVariables，**漏了 _varForwardHandlers**）
- 后果：handler 闭包捕获变量对象 → 删连接后变量对象被转发表钉住不回收；几万点删连接 = 几万对象滞留
- 对照：UnregisterVariable 单变量注销有清理（L594-597），Dispose 有 Clear（L966），唯独整连接移除漏了
- 修法：RemoveConnection 里移除变量字典前，遍历变量 → TryRemove forwardKey → 退订 handler（一行循环）

## 🟡 中危

### M1. UpdateConnection 失败后变量注册记录永久丢失
- 位置：[AdvancedCommunicationManager.cs L234-256](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)
- 场景：Remove 成功 → Add 失败（如改出的参数非法）→ keepVariables 已从 _registeredVariables 删除，恢复循环执行不到 → 变量静默不轮询，直到 RebindAll
- 修法：Add 失败的 catch 里把 keepVariables 的注册记录回填 _registeredVariables（幂等），并向上抛异常让 UI 感知

### M2. ConnectionWorker.Connect(-1) 永久阻塞隐患
- 位置：[ConnectionWorker.cs L126-133 + L382-392](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/ConnectionWorker.cs)
- 场景：默认参数 timeoutMs=-1 → WaitStateAsync deadline=long.MaxValue；若设备离线 + 无限重连 → Task 永不完成，**同步调用 `.GetAwaiter().GetResult()` 的线程永久挂起**
- 现状：Manager 内部调用都传了有限超时，暂无触发路径；但 API 公开，属埋雷
- 修法：默认参数改 30000，或 -1 时封顶 5 分钟

### M3. Worker Dispose 3s Join 超时后的竞态
- 位置：[ConnectionWorker.cs L413-435](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/ConnectionWorker.cs)
- 场景：Worker 线程正卡在长 IO（建连超时 30s）→ Join(3000) 超时 → 主流程继续 `_connection.Dispose()` → 后台线程随后用已释放连接对象。ExecuteItem 有 catch 兜底不会崩循环，但 socket 层竞态可能产生诡异报错
- 修法：Dispose 超时分支放弃释放连接对象（交给后台线程自行了断 / GC 回收），或先等当前 WorkItem 完成再放行

### M4. LogDebug 不进 LogSink
- 位置：[AdvancedCommunicationManager.cs L907-910](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Manager/AdvancedCommunicationManager.cs)
- 与 L896 注释"接入 UI 日志窗口"矛盾：Debug 级日志（读取成功/轮询计划等）在 WPF（无控制台）全部丢失，日志窗口只能看到 Info 以上
- 修法：补一行 `LogSink?.Debug(...)`（若 ILogService 有 Debug 级）
