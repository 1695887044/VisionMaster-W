## 一、需求与决策

### 1. 需求：S9 的真机欠债怎么收

S9（统一写入口 + 撤销重做）在路线图里留了一条真机欠债：

> 真机（**未做**）：拖动 + `Ctrl+Z`/`Ctrl+Y` + 关闭重开。→ 归 S13。

S13 是收口阶段，这条得有个交代。**但本机走不成真机**：屏幕采样纯黑（`CopyFromScreen` 后 400×400 网格采样 `distinctColors=1`，唯一色 `0,0,0`），截不了图；热键又需要真实键盘输入。

于是本轮的问题变成：**这条欠债里，哪一半能用机制证明、哪一半不能？**

### 2. 关键发现：`NudgeCommand` 就是"用键盘做拖动"

`Grep "Nudge" ScadaChecks/Program.cs` → **No matches**。方向键微调（`ScadaEditorViewModel.NudgeCommand`）在断言侧**零覆盖**，而它恰好是"用键盘做拖动"的那条路：

| 维度 | 鼠标拖动 | 方向键微调 |
|---|---|---|
| 写入口 | `ScadaPage.BeginEdit` → 模型侧改 `X`/`Y` | **同一条**（`NudgeSelectedElement` 里就是 `using (page.BeginEdit(...))`） |
| 撤销链 | `ScadaEditHistory` 静态单栈 | **同一条** |
| 锁定口径 | 锁定的图元跳过 | **同一口径**（`CollectEditable`） |
| 差别 | 位移量按像素算 | 位移量按步长算（`NudgeStep = 1` / `NudgeCoarseStep = 10`） |

**结论：拖动与方向键只在"位移量谁算"上分叉，数据通路完全重合。** 所以"拖动 + `Ctrl+Z`/`Ctrl+Y`"里**能被机制证明的那一半，就是方向键的这 19 条断言**。

### 3. 决策清单

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| N-1 | 钉哪个入口 | **`NudgeCommand`**，不钉 View、不钉鼠标事件 | 先例是 `[AD]` 段的右键菜单断言——"菜单内容由 `BuildElementContextMenu` 产出一份与 WPF 无关的描述，切这一刀就是为了让'菜单里有什么'能在没有 Application/Dispatcher 的这里被断言"。方向键同理：命令在 VM 层，无头可驱动 |
| N-2 | 是否实例化 `ScadaEditorView` | **不实例化** | `ScadaEditorView.xaml` 用 `{StaticResource Icon}`（解析自 `VisionMaster/App.xaml:11`），断言宿主没有 `Application` 资源字典 → 解析失败；另有 `DataContextChanged="OnViewDataChanged"` 要真窗口。VM 层已足够 |
| N-3 | 步长是否写死 1 | **不写死**，钉"步长 ∈ {1, 10} 且四次一致" | `OnNudge` 读的是 `Keyboard.Modifiers`（按住 Shift 走粗调 10），那是**进程级真实键盘状态**，断言无法注入。把不确定的那一维留给机器，其余（方向、另一轴不动、四次一致）全部钉死 |
| N-4 | 方向表外的参数 | 断言它**判灰**（`CanExecute == false`），而不是"执行后不动" | `CanNudge` 只认 `Left/Right/Up/Down`；XAML 里写错字时宁可灰着，也不要"静默当成不动"走一遍空作用域。顺带把大小写 `"left"` 也归入不合法 |
| N-5 | 撤销是否按时间合并 | **不合并**，一次按键一条撤销位 | 预测性优先：用户按了 5 次就知道要撤 5 次。这与 `ScadaEditHistory` 里别处的合并口径**刻意不同**，是方向键这个场景的专门决策 |
| N-6 | 多选怎么办 | 整组一起挪，只留**一条**撤销位，文案 `微调 3 个图元位置` | 只挪主选中那一个，用户会以为方向键卡了；产 3 条撤销位则要按 3 次 Ctrl+Z 才回得去 |
| N-7 | 静态状态怎么处理 | 进段 `Clear()` + 备份 `ScadaWriteGuard.Strict`，出段 `finally` 还原 | 照 `[AF]` 段口径：`ScadaEditHistory` 是全局单栈、`Strict` 是线程静态开关，两者都必须在 `finally` 里还原 |
| N-8 | 宿主装配 | 照 `[AE]` 段：`WorkspaceContext` + 空 `SolutionModel` + `SwitchSolution` + `new ScadaEditorVM(workspace, null!)`，`finally` 里 `Deactivate()` | 与既有段落逐字同口径，不另创一种装配方式 |

### 4. 19 条断言的分组

| 组 | 覆盖 | 条数 |
|---|---|---|
| ① 门控 | 空选四向判灰 / 方向表外（含 `""` / `null` / 小写）判灰 | 2 |
| ② 落子 | `AddElement` 放下即选中，四向立刻可执行 | 1 |
| ③ 方向表 | Left / Right / Up / Down 各量一次：方向对 + **另一轴一动不动** + 步长一致（量完立刻撤回原位） | 4 |
| ④ 撤销链 | 连按 5 次 = 位移 5 个步长 / 留下 5 条撤销位 / 文案可读 / **撤 5 次精确回原位** / 重做 5 次回位 | 5 |
| ⑤ 多选 | 三个整组一起挪 / 只留一条撤销位且文案带数量 / 一次 Ctrl+Z 三个一起回 | 3 |
| ⑥ 锁定 | 混选里锁定的跳过（口径与拖动一致）/ 只选中锁定件时判灰 | 2 |
| ⑦ 严格模式 | `ScadaWriteGuard.Strict = true` 下放行 + **恰好一条**记录（= 走 `BeginEdit`，不是裸写 setter） | 1 |
| ⑧ 文案 | `UndoLabel` / `RedoLabel` 里带出 `Ctrl+Z` / `Ctrl+Y` | 1 |

其中 ④ 的"**连按 5 次 → 撤 5 次精确回原位**"就是"拖动之后按 Ctrl+Z"的机制等价——同一条写入口、同一条撤销链、位置逐字还原。

### 5. 为什么"关闭重开"这一半仍留账

`[NU]` 段证的是**内存态的数据通路**。"关闭重开"要证的是**序列化往返 + 宿主生命周期**，那是另一条路：

- 序列化往返：已由 `[AD]` 段的"撤销后 JSON 与操作前逐字节一致"与 `[PI]` 段的"往返文本稳定：读回再序列化与磁盘逐字一致"覆盖；
- 宿主生命周期（真关窗、真重启）：需要真机，本轮走不成。

所以"关闭重开"在核对表里只标注"数据侧已证、宿主侧待真机"，**不**把它算作已闭环。

## 四、已知边界

1. **`[NU]` 证的是数据通路，不是手势**。鼠标拖拽（按下 → 移动 → 落点）、点击热区、真实热键、字体渲染、DPI 实际换算，这五类**机制断言一概证不了**。判据写在路线图 §七：只要"真机要验的行为"与"断言里驱动的命令"落在**同一段代码**上，机制断言就是等价证据；一旦某条行为在真机上有**独立代码路径**，机制断言只能算旁证。
2. **本条的结论有前提**：建立在"拖动与方向键共用写入口"之上。若将来给拖动单开一条写路径（例如加"拖动时的磁吸/约束"直接写模型），**`[NU]` 段的结论立刻失效**，必须回来补真机。这一条已写进路线图 §七 第 1 行的"残余风险"。
3. **步长那一维不确定**：断言只钉"∈ {1, 10} 且四次一致"，因为 `Keyboard.Modifiers` 是进程级真实键盘状态、无法注入。若将来把粗调改成"按 Ctrl"或加第三档，断言需要同步改（它会失败，不会静默通过——这是刻意的）。
4. **撤销不合并是方向键专属口径**。`NudgeSelectedElement` 每次按键产一条记录，与 `ScadaEditHistory` 里别处的"按时间合并"刻意不同。别处若要复用这个思路，需重新判断合并策略。
5. **`[NU]` 不覆盖吸附**。方向键按 `NudgeStep` 直接改坐标，**不过吸附网格**；鼠标拖动过不过吸附是画布的事。两者在这一点上**不重合**，属"独立代码路径"，已在 §七 的边界里归入"证不了的"一类。
6. **"关闭重开"仍未闭环**：数据侧（序列化往返逐字一致）由 `[AD]` / `[PI]` 两段覆盖，**宿主侧（真关窗、真重启、草稿恢复）待真机**。
7. **SCADA 新文件仍未纳入版本控制**：`Core/Lifetime/CrashReportWriter.cs`、`Core/SolutionDraftService.cs`、`pack.ps1`、`baseline.ps1` 等仍是未跟踪状态。**提交需用户明确授权。**
