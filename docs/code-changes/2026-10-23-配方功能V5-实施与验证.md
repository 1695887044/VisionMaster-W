## 一、V5 交付内容

### 1.1 选择器入口（新增）

`VisionMaster/Services/IScadaRecipePicker.cs`
- `void Pick(Guid currentRecipeId, string? currentName, Action<Guid, string?> onPicked)`
- 与 `IScadaFlowPicker` / `IScadaPagePicker` 同构：面板不碰 `IDialogService`，取消不回调。

`VisionMaster/Services/ScadaRecipePicker.cs`
- Prism 弹窗实现；`DialogName = "ScadaRecipePicker"`。
- 入参键 `CurrentRecipeId` / `CurrentRecipeName`；出参键 `PickedRecipeId` / `PickedRecipeName`。
- 只在 `ButtonResult.OK` 且 Id 非空时回调；取消不回写（不把"取消"翻译成"清空原配方"）。

### 1.2 选择器弹窗（新增）

`VisionMaster/ViewModels/DialogViewModels/ScadaRecipePickerViewModel.cs`
- 清单来自 `RecipeService.Recipes`——与运行态 `IRecipeCommandSink` 应用的是同一份。
- 预选顺序：**Id 优先、名字兜底**；旧数据指向已删配方时落回第一条，不留空选。
- 每行显示：名称 / 版本（`vN`）/ 生效中徽标（`ActiveRecipeId`）/ 条数与编码。
- `PickCommand` 无选中时不可用；`CancelCommand` 只关窗。

`VisionMaster/Views/DialogViews/ScadaRecipePickerView.xaml(.cs)`
- 卡片式清单 + 空态提示 + 取消/确定。
- **零硬编码颜色**（R140）：颜色全部引 `Dialog*Brush` / `DialogOptionItem` / `DialogPrimaryButton` 等令牌。
- 可聚焦项挂 `DialogFocusVisual`（R135）。

### 1.3 动作行接线

`VisionMaster/ViewModels/ScadaEventEditorViewModel.cs`
- 新增可选构造参数 `IScadaRecipePicker? recipePicker = null`（追加在最后，旧 8 参构造不变）。
- 新增 `PickRecipeCommand`：没接选择器时 `CanExecute = false`（按钮灰掉，不静默空跑）。
- 新增 `OnPickRecipe`：回填走 `ScadaAction.BindRecipe`，并包一层 `Host.BeginEdit`（可撤销）。
- `ActionDisplayOrder` 增加 `ApplyRecipe => 30`：排在流程/运动之后，不混进设备动作段。

`VisionMaster/Views/Controls/ScadaEventEditor.xaml`
- 新增「应用配方」段：目标配方名 + 「选择配方」按钮 + 未选警告。
- 可见性判据 `Type == ApplyRecipe`；未选时执行侧会跳过，界面提前说明。

`VisionMaster/ViewModels/ScadaPropertyViewModel.cs`
- `ScadaEventRow` 与 `ScadaPropertyViewModel` 各加可选 `recipePicker`，图元事件/画面事件与变量事件三条入口都能配「应用配方」。
- 未接线时行为与 V4 相同（按钮不可用），既有断言不受影响。

`VisionMaster/ViewModels/DialogViewModels/ScadaVariableEventDialogViewModel.cs`
- 新增可选 `recipePicker`，透传给 5 个事件编辑器。

`VisionMaster/App.xaml.cs`
- 注册 `IScadaRecipePicker` 单例 + `ScadaRecipePicker` 弹窗。
- 变量事件弹窗工厂显式传入 `Container.Resolve<IScadaRecipePicker>()`（漏传的表现是按钮灰着，不报错）。

### 1.4 断言

`RecipeChecks/Program.cs` 从 99 条扩到 **111 条**，新增 12 条：

| 断言 | 钉住什么 |
| --- | --- |
| 选择器列出方案内全部配方 | 清单来源 = `RecipeService.Recipes` |
| 按 Id 预选当前配方 | Id 优先 |
| 生效中徽标落在 ActiveRecipeId 那条 | 唯一性 + 指针一致 |
| Id 为空时按名字兜底预选 | 旧数据兜底 |
| 旧数据指向已删配方时落回第一条 | 不留空选 |
| 确认回传 (配方 Id, 配方名) | 出参键与类型 |
| 取消只关窗、不回传目标 | 取消不是破坏性动作 |
| 方案内无配方时不可确认 | 空态 |
| 没接配方选择器时「选择配方」不可用 | 静默空跑防线 |
| 接了配方选择器时「选择配方」可用 | 接线 |
| 选择结果回填到动作（Id + 名字） | `BindRecipe` 链路 |
| 「应用配方」排在运动命令之后 | 下拉分组顺序 |

## 四、并行会话与全量 gate 说明（必须如实记录）

V5 收尾期间检测到**另一个会话正在并行接入 `Plugin.DlAnomaly`**（R9：最近几分钟被改过）：

- 11:38–11:41 写入 `Plugins\Plugin.DlAnomaly\Help\` 8 页（5 用户 + 3 开发）；
- 11:43 在 `FlowCanvasChecks\HelpManualCheck.cs` 登记 `["DlAnomalyPlugin"] = ManualTier.M`；
- 11:44–11:46 新增/修改 `FlowCanvasChecks\Program.cs`、`FlowCanvasChecks.csproj`、`AnomalyChecks.cs`。

因此全量 gate 的状态分两段：

1. **11:37 首跑**：`audit_artifacts` 红（`Modules\Plugin.DlAnomaly.dll` 缺失）→ 已重建该插件补齐（128,000 字节，内嵌 8/8 手册页，R42 已核）；
   `FlowCanvasChecks` 5 红（4 条 DlAnomaly 手册缺失 + 1 条分支胶囊时序断言）。
2. **11:47 二跑**：`audit_root` / `audit_artifacts` / Comm / DataPipeline / Database / Scada / **RecipeChecks 111/0** / UITheme / HelpProbe 全绿；
   `FlowCanvasChecks` **构建失败**，错误全部落在并行会话正在写的 `AnomalyChecks.cs`（`ResizePlan` 未定义、`object` 与 `double` 混用等），与 V5 改动文件无交集。
3. **11:50 三跑**：`FlowCanvasChecks` 已能编译，但运行时**未处理异常**退出（`exit=-532462766`）：
   `AnomalyChecks.FakeMetadata` 对只读属性调用 `PropertyInfo.SetValue`（`AnomalyChecks.cs:360`），
   仍属并行会话的未完成代码；其余 9 步全绿，RecipeChecks 111/0。

**结论**：V5 自身的构建与断言已全部通过；全量 gate 的最后一项红是并行会话的未完成代码（同一文件在两跑之间仍在变），等其收尾后复跑即可。
本条不写成"门禁全绿"，避免把"别人正在写的文件"算进 V5 的验证结论。
