# 枚举下拉显示中文名（2026-10-14）

> 起因是一句真机反馈：**「几何查找的下拉框应该是中文，不要英文」**。
> 一句话的小改动，但根因不在那个插件，而在**框架把已经写好的中文丢掉了**——
> 所以记一条纪律（AGENTS.md **R40**），并把还欠着的枚举清单一起记下来。

---

## 一、现象（真机截图）

「几何查找_0」的参数弹窗（框架给**没有自定义配置视图**的插件自动包的那层，
`VisionMaster\Views\DialogViews\AutoPortConfigView.xaml.cs`）里，两个下拉显示的是：

| 行 | 屏幕上 | 本该显示 |
| --- | --- | --- |
| 查找类型（直线/圆…） | `Circle` | 圆 |
| 拟合鲁棒算法 | `Regression` | 最小二乘 |

## 二、根因：中文本来就写在枚举上，是两处候选生成点没读

`Plugins\Plugin.GeometryFinder\Models\GeometryFinderEnums.cs` 每个成员都标了
`[Display(Name = "圆")]`，宿主扫描插件名/参数名读的也是同一个特性。
但界面上的候选是这样生成的：

```csharp
// Shard\Core.Controls\LinkableValueEditor.xaml.cs:228（改前）
foreach (var name in Enum.GetNames(port.DataType))
    editor.EnumOptions.Add(new StepConfigOption(name));   // ← 只给成员名，Display 退化成成员名
```

同样的写法在**变量绑定窗口**的枚举候选里还有一份（`VariableBindingViewModel.cs:351`）。
ComboBox 侧其实早就配好了 `DisplayMemberPath="Display"` / `SelectedValuePath="Value"`
（值/显示分离，为的是运动卡地址显示「上料轴卡（192.168.0.11）」而写进流程的是地址）——
**管道是通的，只是没人往 Display 里灌中文**。

所以这不是"缺一个本地化功能"，是**两处各写一份候选生成、都漏读了已经存在的特性**。

## 四、口径：显示走中文，值必须是成员名

这是本次唯一需要钉死的设计点，也是 `StepConfigOption` 这个类存在的理由：

- **写进流程 / `.vms` 的永远是成员名**（`Circle`）。枚举写回走 `Enum.Parse` 按名字解析，
  与 JSON 加载路径同一口径。
- **拿显示名当值的后果**：改一次中文名（"圆" → "圆形"）就打断一条已配好的流程 ——
  与 `MotionDescriptor` 那句"引用一律用 Id，不要用显示名"是同一个坑。
- **没标 `[Display]` 的成员回退成员名**，不回退成空白：空白等于下拉里看不出选了什么，
  比英文更糟。

所以断言里除了"显示是中文"，必须同时有一条"**端口值仍是 `Circle`**"（§五第 2 条）。
