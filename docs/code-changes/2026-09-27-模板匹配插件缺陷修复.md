## 2. P0：学习成功却报"创建模板失败"

### 现象

`MatchingPlugin.cs:1054` 的成功文案里取了**迁移字段** `TemplateRect`：

```csharp
+ $"特征区域 {TemplateRect[3] * 2:0}×{TemplateRect[4] * 2:0} px，"
```

`TemplateRect` 的全部使用点只有三处：声明（`:73`，默认 `Array.Empty<double>()`）、
`ParseLibraryAndMigrate` 里读一次、迁移后**立刻清空**（`:693`）。
也就是说在当前主流路径（模板库）下它恒为空数组 → `TemplateRect[3]` 必然越界。

### 后果链

1. 模型**已经学好**（`:1015` `entry.Model` 已写入 base64）；
2. 拼状态栏文字时抛 `IndexOutOfRangeException`；
3. 被 `CreateTemplate` 的 catch 吞掉 → 状态栏显示
   **"创建模板失败：索引超出了数组界限（区域里特征太少？换一块纹理更丰富的区域试试）"**；
4. 并跳过后面的 `TouchModelStaleness()` 与 `UpdateTemplatePreview()` → 徽标不刷新、预览不出现。

即：**每次学习都成功，但界面每次都说失败**。用户会以为没学好而反复点学习。

### 为什么 44 条冒烟断言全绿

- `【模板】学习成功且载荷随方案序列化` 断言的是 `Model.Length > 1000`（载荷在，必然绿）；
- `【模板】学习后参数未变不提示重学` 断言 `IsModelStale`——它是被动计算属性，不依赖被跳过的通知。

**没有任何一条断言看状态栏文字**。

### 修法

改用当前画布区域 `CanvasRect`，并按形状给尺寸（圆只有 3 个参数，取 index 3/4 会显示 0×0）：

```csharp
string sizeNote = CanvasShape == RoiShapeNames.Circle
    ? $"半径 {CanvasRect[2]:0} px"
    : $"{CanvasRect[3] * 2:0}×{CanvasRect[4] * 2:0} px";
```

## 3. P1：标注图轮廓角度双重转换

`find_shape_model` 输出的 `Angle` 单位是**弧度**。原代码：

```csharp
RenderResultAnnotation(src, entry, rows, cols, angles);   // 传的是弧度
...
angles![i].D * Math.PI / 180.0,                            // 内部又当成"度"转弧度
```

结果 0.5 rad（≈28.6°）被转成 0.0087 rad → **轮廓几乎不旋转**。
端口 `Angle`/`Angles`（度）是对的，**只有画出来是错的**，所以"【旋转】整图转 10° 后仍命中"这类断言依然绿。

佐证：仓库自己的脚本模板 `ScriptTemplates.cs:1238` 是
`vector_angle_to_rigid (RefRow, RefCol, 0, MRow, MCol, MAngle, HomMat2D)` —— 直接喂 MAngle，不做转换。

### 修法

统一"度"口径（与端口一致），并把"轮廓放置"抽成 **public 静态**方法，让冒烟能直接断言这条换算：

```csharp
public static HObject? PlaceContoursAtPoses(HObject contours, HTuple rows, HTuple cols, HTuple anglesDeg)
```

调用处改成传度：`RenderResultAnnotation(src, entry, rows, cols, angles * 180.0 / Math.PI);`

> 抽成 public 不是为设计好看：这条换算错的后果"只有画出来才看得见"，
> 不暴露一个可测的入口，冒烟就永远够不着它。

## 4. P2 / P3 逐项

### 4.1 删除条目泄漏模型句柄

`DeleteSelectedEntry` 只做 `Library.Remove(entry)`。条目一旦从库里摘掉，
`Dispose` 遍历 `Library` 再也够不着它 → HALCON shape model 句柄 + 轮廓对象**永久泄漏**。

修法：摘除前先 `ReleaseEntryModel(removed)`。

### 4.2 `Dispose` 未释放参考图

`DisplayImage` 的 setter 是普通 `SetProperty`（不释放旧值），各换图路径靠手动 `Dispose`，
但"最后一次那张"没人管 → 补 `DisplayImage?.Dispose(); DisplayImage = null;`。

### 4.3 运行实例做配置态工作

`ApplyConfigValues → EditingEntry = selected` 会触发 `SeedCanvasFromEntry` + `RefreshPreviewForEntry`
（读参考图文件 → 反序列化模型 → 开离屏 buffer 窗口渲染预览 → 每个条目还要写/读临时 PNG 还原掩膜）。
而 `ApplyConfigValues` 正是 `FlowCompiler` 构造运行实例时调用的那一个。

修法：加 `_isConfigInstance`，**盖在 `Initialize` 上**（不是 `GetConfigView`）：

```csharp
public override void Initialize(IStepConfigData stepData)
{
    MarkAsConfigInstance();     // 先盖章，再 base.Initialize → ApplyConfigValues
    base.Initialize(stepData);
}
```

> 判据：流程编译器构造运行实例时**只调 `ApplyConfigValues`、不经过 `Initialize`**。
> 盖在 `Initialize` 上，既隔离了运行实例，又保住"重新打开方案要恢复画布/预览/掩膜"。
>
> 我第一版盖在 `GetConfigView` 上，结果误伤了 2 条"【重开】"断言（它们用 `Initialize` 模拟重开）。
> 这也是为什么回归段里特意加了一条"编译实例 vs 重开实例"的对照组。

另：`OnImagePortChanged → ShowUpstreamImage` 同样加配置态门禁（运行实例不需要把上游图搬到画布）。

### 4.4 掩膜口径不一致

学习时存的是"与模板区域求交后的"掩膜，换条目时 `WriteBackSmearToEntry` 写回的是"原始"掩膜，
两者 base64 长度不同，而 `EntrySignature` 含 `Mask.Length` → **什么都没改也会提示需重新学习**。

修法：学习时统一存 `BuildRawSmearRegion()`（原始域），与写回路径同口径。

### 4.5 条目区域损坏的报错看不懂

`AlignedImage` 用 `entry.Rect[0]/[1]`，条目被手工改坏（非 5 个值）时越界，
整轮匹配变成"模板匹配失败：索引超出数组界限"。修法：提前校验并给能照着修的中文提示。

### 4.6 缩放范围退化解

`ScaleMin == ScaleMax` 时 HALCON 拒绝创建模型。修法：撑开一个 ±0.005 的最小窗口（不再静默失败）。

### 4.7 `NumberValidationRule` 收编

三份逐字相同的类（Blob / Caliper / Matching）→ 新建 `Shard/Core.Controls/NumberValidationRule.cs`，
Matching 删除本地副本，XAML 里 12 处 `local:NumberValidationRule` → `cv:NumberValidationRule`。
Blob / Caliper 留待各自批次切换（本轮不动，避免踩并行任务）。

（或其它插件统一改成 `Image`）。

## 8. 已知边界 / 后续建议

1. **功能缺口未做**（属新能力，不在"修复"范围）：搜索区域 ROI、NCC/灰度相关匹配与可变形匹配、
   `IsOk` 判定端口、模板导入导出（.shm）、亚像素模式可配、单帧超时保护。
2. **Blob / Caliper 的 `NumberValidationRule` 尚未切换** —— 仍是各一份，下一批随样式收编一起做。
3. **失败口径**：本插件"未找到目标 = Fail"，Blob 是"NG 不算 Fail"。
   两者各有理由（定位失败下游确实拿不到位姿），建议写进平台契约，避免新插件各选各的。
4. **端口命名 `Image` vs `SrcImage`** 待统一（破坏性变更，需单独规划）。
5. **运行实例各自持有一份模型句柄**：20 条模板 × 多流程实例会重复加载同一份模型，
   如需优化应做进程级模型缓存（带引用计数）。
