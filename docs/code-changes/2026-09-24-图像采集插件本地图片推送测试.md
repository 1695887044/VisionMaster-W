# 2026-09-24 图像采集插件 · 本地图片推送测试

## 1. 需求与决策

### 1.1 需求来源

用户提问：

> 请为刚才的插件添加一个本地图片推送测试案例

「刚才的插件」= **图像采集插件**（`Plugin.ImageAcquisition`），
「网络推送」= 采集模式里的 `Mode = Hub`（从宿主 `ImageHub` 网络槽取图）。
需求是在配置窗口的「网络推送」面板里加一个按钮：**选一张本机图片，推给宿主收图服务，用来验证整条收图链路**。

### 1.2 前情：这条需求曾被搁置，以及为什么现在能做

任务线 C 期间用户曾说「这个功能先不考虑了」，当时查清的硬障碍是：

- `ImageHub` 按**流程名**分槽（`_slots: ConcurrentDictionary<string, ...>`），推送地址 `POST /flow/{流程名}` 必须带流程名；
- 但 `IStepConfigData` 里**没有流程名成员**，`StepModel` 也不持有 `Flow` 引用；
- 插件工程**不引用 `Core` 项目**（见 `Plugin.ImageAcquisition.csproj` 的 ProjectReference），
  拿不到 `AppSettingsService` / `AppConfigModel` → 连 Host / Port / Token 都读不到。

本轮用户重新提出，障碍的解法是：**由宿主把运行环境快照主动透传给插件视图**（见 1.4 决策 2）。
这是一次**非破坏性扩展**——不实现该接口的插件完全不受影响。

### 1.3 五项决策（5 轮 `AskUserQuestion`，用户明确答复）

| 轮次 | 问题 | 用户选择 |
| --- | --- | --- |
| Q1 | 推送语义：走真 HTTP 还是直接塞 `ImageHub`？ | **走真 HTTP POST 到本机服务端** |
| Q2 | 连接参数（流程名/主机/端口/令牌）从哪来？ | **宿主透传真实值，面板内可编辑（推荐）** |
| Q3 | 推送前要不要先把界面配置写回步骤？ | **先写回再推送（推荐）** |
| Q4 | 测试结果怎么呈现？ | **面板内结果区 + 信息栏概要（推荐）** |
| Q5 | 「网络推送」面板纵向空间不够，说明文字怎么办？ | **说明折叠 + 整体滚动（推荐）** |

### 1.4 关键设计原则（每条都对应一个易踩的坑）

1. **真发 HTTP，不塞槽**。塞 `ImageHub` 只能验证「插件能取到图」，
   验证不了鉴权、URL 转义、流程触发、回包解析这些**真正容易出错的地方**。
   真发一次请求，走的就是外部相机 / PLC 走的那条路，测通了才算真通。
2. **宿主 → 插件走接口，不走引用**。插件不能反向持有宿主的 `AppSettingsService`
   （会跨程序集耦合，且插件是 `Assembly.LoadFrom` 装进默认 ALC 的）。
   所以定义 `PluginConfigContext`（**纯数据快照**）+ `IPluginConfigContextProvider`，
   由 `PluginConfigShellViewModel` 在 `OnDialogOpened` 末尾填充。
3. **透传必须在 `Initialize` 之后**。插件 `Initialize` 可能写默认值
   （`PushPortText` 默认 `"19000"`），宿主透传的真实值应当**最后落地**，否则会被覆盖。
4. **监听地址 `0.0.0.0` 不等于可连接地址**。`0.0.0.0` 是「听所有网卡」，
   它不是目标地址；本机测试必须连回环地址 `127.0.0.1`，故在 `BuildConfigContext` 里做了一次归一。
5. **推前 `OnConfirm` 保证「所见即所测」**。`OnConfirm(StepData)` → `SetInputValue` →
   `FlowModel.Version++` → 服务端发现会话图纸过期 → 重编译 → 本次跑的是界面上看到的配置。
   只写内存不落盘，方案没保存就不产生文件变更。
6. **客户端超时必须大于服务端等待上限**。`HttpImageServer` 的 `RequestTimeoutMs` 是服务端等流程的上限，
   客户端若用同一数值，会出现「服务端还在跑、客户端先断」→ 用户分不清是流程慢还是网络断。
   故客户端取 `RequestTimeoutMs + 5000`。
7. **流程名由客户端转义**。URL 里直接放中文 / 空格会把请求行切坏；
   `HttpImageServer.HandleFlowPost` 是拿到路由参数后才 `Uri.UnescapeDataString`，
   所以转义是客户端（本测试按钮）的责任。
8. **不用自建 `IsPushing` 守卫**。Prism 9 的 `AsyncDelegateCommand` 默认禁止并行执行
   （`EnableParallelExecution()` 是显式 opt-in）→ 执行期间 `CanExecute=false`，按钮自动置灰。
   再加一个布尔属性就是死代码。

### 1.5 明确不做

- 不做**批量推送**（一次选多张、按帧率循环推）——用户要的是「测试案例」，单张足够。
- 不做**推送历史记录**——结果区只保留最近一次。
- 不改 `HttpImageServer` 的任何既有行为（`Start` / `HandleFlowPost` 一字未动），只新增一个只读快照属性。
- 不改另外 7 个实现 `IPluginCustomViewProvider` 的插件（接口是新增的，不是改签名）。

```csharp
private PluginConfigContext BuildConfigContext()
{
    var cfg = _httpServer?.EffectiveSettings ?? new HttpImageServerSettings();
    var host = string.IsNullOrWhiteSpace(cfg.Host) ? HttpImageServerSettings.DefaultHost : cfg.Host;

    return new PluginConfigContext
    {
        FlowName = _workspace?.CurrentFlow?.FlowName ?? string.Empty,
        HttpEnabled = cfg.Enabled,
        HttpListening = _httpServer?.IsListening ?? false,
        // 监听端写 0.0.0.0 是"听所有网卡"，它不是可连接的目标地址 —— 本机测试要连回环地址

        HttpPort = cfg.Port > 0 && cfg.Port <= 65535 ? cfg.Port : HttpImageServerSettings.DefaultPort,
        HttpToken = cfg.Token ?? string.Empty,
        RequestTimeoutMs = cfg.RequestTimeoutMs
    };
}
```

```csharp
public void SetConfigContext(PluginConfigContext context)
{
    if (context == null) return;

    PushFlowName = context.FlowName ?? string.Empty;
    PushHost = context.HttpHost ?? string.Empty;
    PushPortText = context.HttpPort.ToString();
    PushToken = context.HttpToken ?? string.Empty;
    _pushTimeoutMs = context.RequestTimeoutMs;

    if (context.HttpListening)
    {
        PushServiceHint = $"宿主收图服务正在监听 {context.HttpHost}:{context.HttpPort}";
        SetStatus($"推送测试已就绪（目标 {context.HttpHost}:{context.HttpPort}）", StatusLevel.Info);
    }
    else
    {
        PushServiceHint = context.HttpEnabled
            ? "宿主收图服务配置为启用但未在监听（端口被占用或启动失败），推送会连接失败"
```

推送主流程（`PushLocalImageAsync`，5 步）：

1. **参数校验放在选文件之前**——参数都不对就别让用户白选一次文件；
   流程名空 / 主机空 / 端口非 1~65535 → `RejectPush(...)` 直接返回。
2. **选图**——`OpenFileDialog`，Filter 复用与「指定图像」同一套 `ImageExtensions`；
   取消则只写一条 Info 状态，不动结果区。
3. **写回配置**——`OnConfirm(StepData);`（见 1.4 第 5 条）。
4. **发请求**——`File.ReadAllBytesAsync` → `POST http://{host}:{port}/flow/{Uri.EscapeDataString(flowName)}`，
   头带 `Authorization: Bearer ...` 与 `X-Image-Name: 文件名`，body 是 `application/octet-stream`；
   客户端 `Timeout = RequestTimeoutMs + 5000`。
5. **呈现**——`FormatPushResult` 整理成多行文本写结果区，同时用 `SetStatus` 给信息栏一句概要。

## 4. 已知边界

1. **推送测试只做单张、只做同步等待**：一次一张，等回包或超时。
   没有批量 / 连续推送（做压测请用外部脚本打 `POST /flow/{流程名}`）。
2. **推送目标必须是「非运行中」的流程**：若目标流程正在运行，
   服务端按既有逻辑返回 **409**（`流程「X」正在运行中，本次请求未受理`）。
   本测试不改这个语义——它恰好是一个可验证的负向用例。
3. **推送目标流程必须含一个 `Mode=Hub` 的采集步骤**：否则图片进了槽也没人取，
   会看到「流程跑完了但输出里没有这张图」。面板内不做这种前置检查（跨流程静态分析成本高）。
4. **推送成功 ≠ 方案已保存**：`OnConfirm` 只写内存（`InputValues`），
   关窗口不点「确定」/ 不保存方案，这些值不会落盘。
5. **结果区只保留最近一次**：没有历史记录，点第二次会覆盖第一次。
6. **`PushServiceHint` 是打开对话框那一刻的快照**：对话框开着的时候
   宿主服务被停掉 / 端口被别人抢走，提示不会自动刷新（下次打开才更新）。
7. **`0.0.0.0` → `127.0.0.1` 的归一只在宿主侧做**：用户在面板里手改成 `0.0.0.0`
   不会被纠正，会得到一个连接失败——这是有意保留的（允许用户指向真实远端主机）。
8. **客户端超时固定 `RequestTimeoutMs + 5000`**：不跟随服务端配置热更新
   （值在 `SetConfigContext` 时取一次）。
9. **不支持 `https`**：URL 硬编码 `http://`，与 `HttpImageServer`（Watson，无 TLS）一致。
10. **面板纵向空间仍是紧的**：最小窗口（内容区约 304px）下需要**展开 Expander 看说明**
    就必须滚动，属于 2.5 节已接受的取舍。
11. **解决方案级构建在 VisionMaster 运行期间可能报拷贝错**：见任务线 C 记录，
    环境性（`Modules\` 下 `hdevenginedotnet.dll` 等被占用）。
