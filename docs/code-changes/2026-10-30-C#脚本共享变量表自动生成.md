# C# 脚本共享变量表：从「手动新增」改成「从脚本正文自动生成」

日期：2026-10-30
类型：功能新增（插件内，零契约变化）

---

## 1. 当前状态

已落地并通过全量闸门（`run_gates` 17 steps green）。

**目标形态**：用户在脚本里直接写

```csharp
int g = Context.GetGlobal<int>("imageIndex");
Context.SetGlobal("imageIndex", g + 1);
```

点「校验脚本」或「确认」时，插件扫正文里的**字面量别名**，把没声明过的补进左侧「共享变量」表
（`VariableId` + `Name` + `Alias` + `TypeName` + `IsSystem` + `Access` 一次填好）。

**表必须保留**（已确认结论，本次未重新论证）：

| # | 表挡的事 | 代码依据 |
|---|---|---|
| 1 | 多设备同名消歧 | `Core\Binding\VariableNameAmbiguity.cs` + `VariableRegistry.FindByName` 歧义返回 null；表存 `VariableId`，`ScriptSharedAccessor.cs:52` 走 `TryRead(def.VariableId, def.Name, ...)` |
| 2 | 改名不断链 | `ScriptSharedVarDef.cs:124-130` 注释原文"按 Id 寻址只保住了声明行，保不住脚本正文" |
| 3 | 并行写冲突静态检查 | `Engine\FlowCompiler.cs:1717-1749`（`CollectScriptGlobalWrites`）从 `InputValues["SharedVars"]` 读写集合 |
| 4 | 只读/读写是用户意图 | `ScriptSharedAccessor.cs:117-124` 的 `ValidateWritable` 闸门 |

## 2. 已做

### 2.1 `ScriptSharedUsageValidator`：抽取与校验拆开

`Plugins\Plugin.CSharpScript\ScriptSharedUsageValidator.cs`

- 新增 `public readonly record struct ScriptSharedAliasUse(string Alias, string Method, int Line)`
- 新增 `public static IReadOnlyList<ScriptSharedAliasUse> Extract(string script)`：顺序 = 出现顺序，同一别名可出现多次
- `Validate` 改为复用 `Extract`，**三种原有错误文案与行号格式一字未变**（C32.25a/b/c 逐字断言）
- **新增注释掩码**（`MaskComments`）：`//` 与 `/* */` 逐字符替换成等长空格（保留换行 → 行号不变），
  **字符串字面量区域原样跳过**（否则 `"http://x"` 里的 `//` 会被当成注释起点吞掉后文）。
  理由：默认脚本模板把 `Context.GetGlobal("imageIndex")` 写成**注释示例**，若把注释也算用法，
  任何新建步骤点「校验脚本」都会要求先建一个 imageIndex 变量。C32.11b 钉住这一点。
- 动态拼接的名字（`GetGlobal(name)`）仍扫不到——已声明边界，未尝试解决。

### 2.2 `CSharpScriptPlugin.EnsureSharedVarsFromScript`

`Plugins\Plugin.CSharpScript\CSharpScriptPlugin.cs`

规则（逐条对应实现）：

| 规则 | 实现 |
|---|---|
| 已有别名集合 | `SharedVars.Select(EffectiveAlias)`，`StringComparer.Ordinal`；同时建 `VariableId → 别名` 索引 |
| 按出现顺序遍历 `Extract(ScriptText)`，跳过已有别名 | `seenNew` HashSet 保证同别名只处理一次 |
| 按 `Name` 精确匹配（Ordinal） | `BuildSharedCandidateIndex()` 一次性建 `Dictionary<string, List<VariableOption>>`（不是每个别名遍历 5000 条） |
| 0 条命中 | `第 N 行 第 1 列: 共享变量「X」不存在：请在变量管理里确认变量名，或检查拼写` |
| 1 条命中 | 补行（`Alias` **显式写死**，避免以后变量改名把脚本键带跑） |
| ≥2 条命中 | **报错、绝不猜**：`第 N 行 第 1 列: 共享变量「X」在 2 个变量上重复（设备 A_PLC / 设备 B_PLC），请在左侧「共享变量」表里选择一台后再校验` |
| 系统变量 + 写 | `第 N 行 第 1 列: 「X」是系统变量（只读），不能调用 SetGlobal（系统变量只能读；要写请改用全局变量）` |
| 候选快照为空 | 直接返回 null、不补行（headless 无法判定，交给原 `Validate` 的"未声明"） |
| 幂等 | 第二次调用全部命中 `declared`，不再补 |

**原子性**：先算出 `pending` 列表（任何一步出错直接 return，`SharedVars` 一行都没动），全部通过才 `Add`。
C32.5 / C32.28 钉住"不许半补"。

**多设备文案上限**：最多列 **8 个设备**，超出收敛成「等 N 台」（总数仍写"在 N 个变量上重复"）。
理由写在方法注释里：状态栏不是日志窗，200 台逐条铺开会把可执行动作挤出视野。C32.6 钉住。

**额外加的一条防御（规格没写、实现时发现必须加）**：
同一 `VariableId` 已用**别的别名**声明过（如 `Alias="idx"`、`Name="imageIndex"`，脚本写 `GetGlobal("imageIndex")`）→
报 `变量「imageIndex」已在共享变量表里以别名「idx」声明：请把脚本里的键改成「idx」，或把该行的别名改成「imageIndex」（同一变量不能声明两行）`。
不加这条就会静默落成同一变量的第二行（表里像两个变量，并行写集合重复计一条）。C32.21 钉住。

### 2.3 两个接入点

| 位置 | 调用 |
|---|---|
| `ValidateScript()` | `GetVariableNamesError()` 之后、`ScriptSharedUsageValidator.Validate(...)` **之前**；非 null 直接 return |
| `OnConfirm(stepData)` | `RestoreEmptyNames()` 之后、`GetVariableNamesError()` 之前；非 null `throw new InvalidOperationException(error)` |

`OnConfirm` 里的位置比规格写的"`GetVariableNamesError()` 之前"更细：放在 `RestoreEmptyNames()` 之后。
理由：`RestoreEmptyNames` 只动输入表，与共享变量无关；但两者都必须早于**任何** `base.OnConfirm` 写入。

## 3. 未做

1. **「共享变量」表的「+ 新增」按钮没删**。自动补表只覆盖"脚本里写了的"，用户仍可能需要
   预先声明（例如脚本还没写完、或想先绑一台设备）。删按钮属于产品决策，不在本次范围。
2. **没有做"脚本里删掉某个别名的用法 → 自动删表里那行"**。反向同步风险高（用户可能只是暂时注释掉），
   本次只做"补"，不做"减"。表里多余行仍走原有 `Validate` 提示与人工删除。
3. **GUI 上没有"补了 N 行"的回执**。`EnsureSharedVarsFromScript` 只返回错误、不返回补了几行；
   状态栏只显示成功/失败。要加得给 `ValidateScript` 换返回类型（牵动视图），另批。
4. **没有真机跑 `VisionMaster.exe` 看窗口**。本批全部是断言宿主 + 探针（`run_gates` 的九个宿主全绿），
   视觉验收交给下一轮（R175 允许，因为本改动是纯模型层逻辑，界面只改了一行副标题文本）。
5. **动态别名（`GetGlobal(name)`）没覆盖**——已声明边界，运行期访问器仍会拒绝未声明别名。
6. **`ScriptSharedAccessor.cs` 一字未改**（规格禁止），运行期语义完全不变。

## 4. 下一步

1. 若要"补完给回执"，把 `ValidateScript()` 的返回改成 `(string Error, int Added)` 或加一个
   `LastAutoDeclareSummary` 只读属性，视图在成功行拼一句"已自动补 N 行共享变量"。
2. 若要"减"：在 `EnsureSharedVarsFromScript` 里加"表里有、脚本里没有"的反向扫描，
   **但必须先有用户确认对话框**（自动删行是不可逆的配置变更）。
3. 多设备同名的"在表里选一台"目前要求用户手动点下拉；可考虑错误文案里给出设备名后，
   视图提供"按错误里的设备名一键补行"入口（属于交互优化）。
