# 主流程角色退役：改由「整线」位集表达 + 线级判定来源显式化（2026-10-28）

- 日期：2026-10-28

- 上游：评估记录 `docs/架构文档/交接报告/交接报告-2026-10-28-主流程概念去留评估.md`

## 1. 为什么删

2026-10-28 上午的「整线启动」改造已经让工位与主流程**平级**（各自一条流程、各自一个会话），
`FlowInvokeType.LineStart` 完整表达了"这条流程随整线启动"。此后 `FlowRole.Main` 只剩四处语义，
其中两处是纯展示、两处是历史包袱：

| 原语义 | 处理 |
|---|---|
| 批量启动的兼容兜底（一条整线都没勾时选唯一 Main） | 删除；改为"一条都没勾 → 不启动 + 提示去勾整线" |
| 底栏「全部」的线级 OK/NG 来源 | **改为方案级显式字段** `SolutionModel.LineVerdictFlowId` |
| 删除保护 / 强制骨架 | 骨架收敛为 Home / End 两条 |
| `IsSubroutineOnly` 的排除项 | 已由 `!IsLineStartMember` 覆盖，直接删 |

另外，退役前徽标与选择器**已经互相矛盾**：`IsDirectlyLoopable` 把 Role=Main 也算"可循环"，
但选择器一旦发现任何整线成员就只启动那些 —— 主流程显示"可循环"、按钮却不启动它。删掉即消除。

## 3. 语义

- **骨架**：Home / End 两条，新建即自带、老方案打开即补齐、不许删（`Role != None`）。
- **生产主任务**：任意流程勾「整线」即随工具栏「启动整线 / 整线循环」启动；可多条、平级、各起各的会话。
- **新建方案的 `Main`**：只是一条默认名，`Role=None` + 已勾整线（可删可改名），保证"新建即可启动整线"。
- **老方案**：`Role=2` 在加载时迁移成 `Role=0` + 勾整线 —— 行为逐位不变（原本按整线启动的就是它）；
  `MainTask` 老名同样只勾整线，不再占角色。
- **线级 OK/NG 来源**：`SolutionModel.LineVerdictFlowId` 显式指定（结果源弹窗勾「作为线级汇总来源」）；
  未指定时回落到**第一条勾整线的启用流程**；都没有则底栏显示「—」（不按流程顺序瞎挑一条）。
- **一条整线都没勾**：按「启动整线」不启动任何流程，状态栏提示去「流程管理」勾「整线」。

## 6. 踩过的坑

1. **`cmd` 的 `%ERRORLEVEL%` 在解析期展开**：`dotnet build ... > log 2>&1 & echo EXIT=%ERRORLEVEL%` 打印的是上一行
   命令的退出码（实测 `EXIT=0` 而日志是"2 个错误"）。判构建结果只读日志的「0 个错误」。
2. **断言宿主进程也会锁 `Modules\*.dll`**：不只 VisionMaster。错误文本里"文件被 X 锁定"的 X 才是真正持有者；
   等它自己退出，别杀（杀掉等于毁掉一整轮断言）。已记台账 B-00。
3. **隔离构建（`-p:BaseOutputPath`）之后普通构建报 `MC3074 标记不存在`**：契约工程的 `obj\...\ref\*.dll`
   被搬走导致 XAML 编译读到旧 ref；先 `--no-incremental` 重建 `Core.Controls` 再重试。已记台账 B-00b。
4. **`[JsonIgnore]` 不能贴方法**：`ResolveLineVerdictFlow()` 上加特性直接 CS0592（方法本来也不参与序列化）。
