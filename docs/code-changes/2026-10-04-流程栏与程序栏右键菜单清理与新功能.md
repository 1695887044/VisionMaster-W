## 一、背景：空壳菜单的来历与「禁用」反向缺陷

两个面板的右键菜单是从参考工程 `WPF-Halcon-流程拖拉`（未纳入 `VisionMaster.sln` 的旧教程工程）照抄的：

- **流程栏（ProcessView）**：菜单 15 项里 8 项是空实现（case 里只有 `break;`）；且「禁用」写反——写的是 `IsDisEnable = false`，而 `IsDisEnable == true` 才表示禁用（定义 `Core\Models\ProcessStep\StepModel.cs:54`；消费点 `Engine\FlowCompiler.cs:218` 的 `if (model.IsDisEnable) continue;`）。即：点「禁用」实际把它**启用**。
- **程序栏（FlowListView）**：「加密/解密流程」两项没有对应 switch case，点了没反应。

**不是本仓库删功能删出来的**：参考工程里这些项当年也大多没有处理器——其 `ProcessView.xaml.cs:1329-1335` 的 `miDisable_Click` / `miCopy_Click` / `miPaste_Click` / `miCut_Click` 均为空方法。本轮把「抄来的空壳」与「真缺陷」一次收口，并给程序栏补上真正缺失的启用/禁用与编译入口。

## 三、关键决策与理由

### 3.1 8 个空壳项：删除而非实现

| 菜单项 | 为什么删（不实现） |
| --- | --- |
| 执行选中模块 | 真等价入口是「双击开配置 → 试运行」——那个入口能看到结果图；独立「执行」没有结果展示面 |
| 从此处执行 | 引擎没有「从某节点起跑剩余链」的语义 |
| 剪切 / 复制 / 粘贴 | 步骤剪贴板不存在；该需求应跟画布多选一起做，不适合在旧菜单里单起炉灶 |
| 显示所有 / 启用超级工具 | 参考工程里即为死概念；`IsUseSuperTool` 全工程零消费者（本轮复核：Core / Engine / VisionMaster / Plugins 全仓零命中） |
| 设置断点 | Core / Engine 零插桩；留空壳是最差状态——等引擎立项断点能力后再加回菜单 |

### 3.2 FlowListView「加密/解密」：删入口而非接线

真正的实现在 `FlowManagerViewModel.cs`（弹窗里带完整上下文与 🔒 状态显示）；列表菜单不再留重复入口，避免两处入口各自演化。

### 3.3 编译的运行锁范围：只拦 `Compile`

- `Compile` 必须拦：`RegisterSession` 会**静默停掉同名运行会话**，属「边跑边拆台」。
- `Create / Delete / Rename / EditComment` 维持原有不拦行为（本轮不扩面，见遗留 S4）。

### 3.4 枚举成员删除的安全性

`ModuleCommandAction` / `FlowAction` 均为 UI 命令参数，全仓无存盘 / 序列化引用（reviewer 已核；残留 grep 零命中，见下）。
