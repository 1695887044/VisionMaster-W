# 非全屏下图像区尺寸分析 — 2026-10-26

## 一、当前状态（按截图实测）

截图 1644×1036 物理像素，125% DPI → 窗口约 **1315×829 DIP**。按面板边界换算（DIP）：

| 区域 | 实测 | 说明 |
|---|---|---|
| 左栏（流程导航） | 340 | `Shell.xaml:1574` `DockWidth=340 / DockMinWidth=320` |
| 右栏（工具箱） | 320 | `Shell.xaml:1649` `DockWidth=320 / DockMinWidth=300` |
| 底部控制台 | **200（展开）** | `Shell.xaml:1628` `DockHeight=200`；`LayoutHelper.cs:823` `CurrentConsoleState` 默认 `Expanded` |
| 中央图像区 | 约 **604×464** | 1315 − 340 − 320 − 分隔 8 ≈ 647 宽；高再减顶栏/运行条/工具条/文档标签/控制台/状态栏 |

图像区占窗口面积约 **26%**（604×464 / 1315×829）。

## 二、根因

1. **底部控制台默认展开 200，与设计基线不符**。`docs/UI设计基线/app-shell/README.md:35` 的「调试」场景写的是**底部控制台收起 32**；实现里 `CurrentConsoleState` 默认 `Expanded`，XAML 也是 200，所以启动就是展开态。
2. **右栏 320 用的是 ≥1500px 视口的设计值**。设计稿 `design.html:2169-2172` 在 `max-width:1500px` 时把检查器降到 **300**；当前窗口约 1315，命中窄视口规则。
3. **左栏 340 不能直接降**。2 列 24px 胶囊在 340 宽时名字列约 90px，`ST1_LoadCode`（12 字符 ≈78px）刚好放得下；降到 280 时名字列约 60px，长流程名会被截断。

## 三、可回收的空间（按同一窗口尺寸估算）

| 动作 | 图像区 | 面积变化 | 代价 |
|---|---|---|---|
| 现状 | 604×464 = 280k | — | — |
| 控制台收起 32（设计基线） | 604×632 = 382k | **+36%** | 日志只留抽屉条一行摘要，点箭头可展开 |
| 右栏 320→300 | 624×464 = 290k | +3% | 属性编辑器 205→185px（260 已实测可用） |
| 控制台收起 + 右栏 300 | 624×632 = 394k | **+41%** | 同上两项 |
| 专注图像（隐藏左右栏，保留控制台） | 1264×464 = 586k | **+109%** | 新增一个专注/退出入口；左右栏不可见 |
| 专注 + 控制台收起 | 1264×632 = 799k | +185% | 同上 |

## 四、建议

**P0：把「调试」场景的默认控制台状态改回收起（32），与设计基线一致。**
这是单项收益最大的一步（+36% 高度），而且不是新设计——基线 `app-shell/README.md:35` 已经写明「收起 32」。实现侧需要让启动/新建布局时 `CurrentConsoleState` 落在 `Collapsed`，用户手动展开后仍按用户状态记忆（Layout.xml 优先）。

**P1：右栏默认 320→300。**
命中设计稿自己的窄视口规则；属性面板在 260 已实测无截断，300 安全。

**P2（可选）：加「专注图像」开关。**
在图像文档的工具条上放一个按钮：隐藏左栏 + 右栏（保留控制台），图像区从 604 宽变 1264 宽，面积翻倍。适合"看图/调焦"时用；退出后恢复原布局。这是新增交互，按 R125 需要设计稿升版与用户确认。

**不做：左栏降到 280。** 胶囊名字会截断；用户已确认 340 的 2 列胶囊方案。

## 六、踩过的坑

- 截图里的黑色区域是**图像视口**，中间的白色提示框是空态提示，不是图像本身；判断"图像太小"要看视口尺寸，不要看提示框。
- 125% DPI 下截图是物理像素，面板宽度要除以 1.25 才是 DIP；直接按 445/434 读数会以为左栏 445、右栏 434。
- 控制台"收起"不是把 `DockHeight` 压到 32：AvalonDock 页签条约 20px 最小高度，压到 32 会画出重复页签；实现是整块 pane 摘下来 + Shell 底部 32px 抽屉条（`LayoutHelper.DetachConsolePane`）。所以 P0 不能只改 XAML 的 `DockHeight`。
- 图像视图是"适应视口"的：视口变大，图像按比例放大；不存在固定的图像尺寸上限。
