# 判定表：数据源接线断点与「期望值变量化」诊断（2026-10-28）

> 性质：诊断记录，**本轮未改任何产品代码**。
> 触发：用户提问「结果判定插件数据源怎么获取的？我没看到哪里可以获取；期望值不能是变量吗」。

## 1. 结论（先说答案）

| 问题 | 答案 |
|---|---|
| 数据源从哪来 | 设计上是该步骤的**动态输入端口** `实际_{规则名}`（object），靠「变量绑定」把上游输出接上去；配置弹窗里的「数据源」只是**只读回显**（`JudgeTableView.xaml` 466-487，注释写明"连线在画布/端口列表里配"） |
| 现在能不能在 UI 里接上 | **不能**。「变量绑定」窗口左侧端口表来自 `ToolItemModel.InputDefinitions`，那是 `PluginService.LoadPlugin` 用 `Activator.CreateInstance` 造的**空配置实例**快照 —— 判定表此时 `Rules` 为空，动态输入端口 0 个，所以窗口里一条都列不出来（界面会显示「当前步骤没有可绑定的输入端口」） |
| 截图里前两行为什么有数据源 | 那份方案是 `tools\vms-generator\Program.SamplePair.cs` 生成的，`judgeLinks["实际_" + name] = …` 直接写进 `.vms` 的 `LinkedSources`，绕过了 UI |
| 期望值能不能是变量 | **不能**。`Expected` 是随方案落盘的字符串，`JudgeEngine` 全程按字面量解析（数值/区间/比较符/集合/正则/布尔），没有任何"读变量"的通道 |

## 2. 证据（可复跑）

`PluginService.cs:339` 扫描期实例化 → `JudgeTablePlugin` 构造函数只订阅空的 `Rules` → `EnsurePortsDiscovered` 反射不到任何 `IInputPort` 属性。

临时探针（`%TEMP%\jtprobe`，加载 `Modules\Plugin.JudgeTable.dll`，已删除）输出：

```
[SCAN] Inputs.Count = 0
[SCAN] Outputs.Count = 7
[SCAN] dynamic input '实际_R1' exists = False
[SCAN] declared IInputPort properties = 0
[CONFIGURED] Inputs.Count = 1
[CONFIGURED] dynamic input '实际_R1' exists = True
[SNAPSHOT] InputDefinitions would list 0 port(s)
```

即：**配置态实例有 `实际_R1`，扫描期快照没有**，而 `VariableBindingViewModel.BuildTree`（868-887）只读快照。

对照：输出侧有 `StepModel.OutputPortDefinitions` 动态快照（`ResultSourceDialog` 的注释明确写"静态定义 + 动态端口快照"），**输入侧没有对应物**（全仓 `InputPortDefinitions` 命中 0 处）——这是不对称的根因。

## 3. 为什么别的动态输入插件能用

`AutoPortConfigView`（无自定义视图时的框架参数面板）直接枚举**插件实例**的 `Inputs`，并给每行配 🔗（`AutoPortConfigView.xaml.cs:20-24`）。
判定表实现了 `IPluginCustomViewProvider`，走自己的视图，于是既没有 🔗，也拿不到框架那张端口表。

## 4. 两条修复路线（未实施）

- **A（只动插件，改动小）**：每行「数据源」旁加「绑定…」按钮 → 发 `LinkPathEvent { InputPortName = rule.InputPortName, TargetType = typeof(object), OnBound = link => { StepData.SetLink(name, link); RefreshSourceText(); } }`。
  宿主 `ProcessViewModel.OnLinkPathEvent`（562-588）已支持单绑定模式，C#脚本/结果输出同款通道，**不需要改宿主**。
- **B（改公共契约，收益面大）**：`StepModel` 加 `InputPortDefinitions` 快照（对称 `OutputPortDefinitions`），`RebuildDynamicInputs` 写快照，`VariableBindingViewModel.BuildTree` 与 `pluginInfo.InputDefinitions` 取并集 → 通用「变量绑定」窗口（含流程栏右键「编辑绑定…」）对所有动态输入插件生效。按 R12 需架构评审。

建议先 A 恢复可用，B 单独立项。

## 5. 期望值变量化（未实施，需拍板）

最小方案：每条规则加可选动态输入 `期望_{规则名}`（object）+ 开关 `ExpectedFromInput`；
运行时已连线且有值 → 用 `JudgeEngine.FormatActual(value)` 作为**有效期望文本**，否则回落字面量 `Expected`。

必须同时处理：
1. `SpecText` / `TryParseNumericSpec` 现在直接读 `rule.Expected`，要收口成"先取有效期望"的单一入口，否则界面上写一套、判的是另一套；
2. 开关打开时「期望 / 规格」框置灰并提示"由 `期望_规则名` 提供"，避免用户以为字面量生效；
3. 这是"值"端口，符合 R33；断言补：连线值覆盖字面量 / 未连线回落 / 类型不符要写清原因；
4. 该端口同样受第 1 节接线断点影响 —— 不先修 A，期望变量化在 UI 里也接不上。
