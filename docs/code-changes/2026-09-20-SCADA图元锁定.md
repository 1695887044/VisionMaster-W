## 一、需求与决策

### 1. 需求

S10 的定义原文里有"图元对齐/分布/**成组**/**锁定**"四项。前一轮（S10-a/b）已交对齐/分布/多选，本轮收锁定。

要解决的具体症状：**锁定当时在模型上已经存在，但在界面上几乎不可见**——只有图层面板里图层那一行有个锁图标。图元自己的 `IsLocked`：

- 没有任何写入口（属性面板没有、右键菜单没有），只能在代码里调；
- 锁定之后画布上**毫无变化**：选中框还是蓝的、手柄照样出现、拖上去纹丝不动。

第二条是最要命的。用户按下图元、拖动、画面不动——他的第一反应是**软件卡了**，而不是"这个图元被保护了"。锁定必须自己把这件事说出来。

### 2. 决策清单 —— 写入口（s10c-1 / s10c-2 / s10c-3）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| C-1 | 锁定/解锁的入口 | **一个方法管两向**：`ScadaPage.TrySetElementLocked(elements, locked, out error)` | 锁定与解锁除了那个 bool，前置校验、作用域、记账、文案形态完全一样。拆成 `TryLock`/`TryUnlock` 就是两份复制品，将来"批量 + 撤销一条"的口径改了要改两处 |
| C-2 | 是否按 `IsElementEditable` 过滤 | **刻意不过滤** | 这是本类里**唯一一处反着来**的批量入口。`IsElementEditable` 把"已锁定"判为不可编辑，而**解锁的目标恰恰就是已锁定的那些**——照抄那个过滤，解锁会变成永远的空操作（返回 `true` 但什么都没干） |
| C-3 | 只留"状态确实要变"的 | `targets = present.Where(e => e.IsLocked != locked)` | 整批已经是目标态时，这是一次**空操作**：返回 `true`（不是失败）但**不产撤销记录**——撤销栈里不该堆"什么都没干" |
| C-4 | 操作名（撤销按钮上的文案） | 写**真正变化的个数**：`锁定 3 个图元`；只有一个时写 `锁定图元 [名字]` | 用户按下 Ctrl+Z 时要能读出撤的是哪一步。写"选中 5 个"而实际只动了 2 个，是谎报 |
| C-5 | VM 侧的过滤分两套 | `CollectPresent`（只筛"属本画面 + 去重"）/ `CollectEditable`（再叠一层可编辑）/ 共用 `CollectTargets(page, editableOnly)` | 删除/对齐/分布要的是 `CollectEditable`；锁定要的是 `CollectPresent`。**共用同一个漏斗函数**，只是把"要不要叠可编辑"做成参数——各写一遍迟早出现"删除认锁定、锁定却不认" |
| C-6 | 菜单项的二态判据 | 标题与图标跟**主选中**的当前状态走（`IsMainSelectionLocked`） | 菜单每次弹出即重建，所以"锁上之后菜单自己翻成解锁"是免费得到的 |
| C-7 | 命令判灰 | `CanSetSelectedLocked` 用 `CollectPresent`，**不**复用删除那条"可编辑"判据 | 整批都锁着的时候，那一项**必须仍然亮着**——解锁恰是此刻唯一该亮的动作。抄删除的判据会让它永远灰着，等于锁上之后解不开 |
| C-8 | 图标跟动作不跟状态 | "锁定图元" → `U+F023`（闭锁）；"解锁图元" → `U+F3C1`（开锁） | 标题写"锁定"而图标画"开锁"（暗示当前状态）会自相矛盾。图标与标题都描述"点下去会发生什么" |
| C-9 | 菜单里放哪 | 排在**删除之前** | 与"对齐与分布"同属"改这批图元的属性/摆法"，删除是唯一"不可见地改变画面内容"的一项，仍在末尾 |
| C-10 | 属性面板的写法 | 新增 `IsElementLocked`，**借** `_editor.SetSelectedLocked(value)` | 面板编辑的图元恒等于编辑器的主选中（`Rebuild` 就是从 `SelectedElement` 读来的）。借它走一遍 = 复用同一条已被断言钉住的路径，也省掉面板自己找"这个图元属于哪张画面" |
| C-11 | 面板的回抛通知 | setter 里补 `RaisePropertyChanged(nameof(IsElementLocked))` | 写失败时（图元已不在画面上）模型值没变、也不会有模型通知，而绑定是 TwoWay 的——不补这一句，复选框会停在用户刚点出来的那个**假状态**上 |

### 4. s10c-4 的视觉理由（逐条展开）

**为什么整圈换色，而不是只点一个角标。** 锁定的直接表现是"拖不动"，而"拖不动"是一次**没有反馈的失败**。换色是第一眼就能看见的，而且它天然回答了"为什么"：蓝 = 可编辑，金 = 受保护。角标只是把这个答案说出口。两件事分工：换色负责"看得见"，角标负责"说清楚"。

**为什么是金，以及为什么不是诊断橙。** 诊断层的 `WarningBrush` 是 `#E88B1A`，含义是"**这个图元没接上变量**"。如果锁也用这个橙，同一幅画面上两个角标会互相冒充——用户看到橙色根本分不清是"没接变量"还是"被锁了"。所以往黄侧挪一档（26° → 41°），并排看能分开。也不用灰：灰在默认深色底（`#1E1E1E`）上太沉，一眼扫过去会先被当成图元本身的一部分；金与选中蓝在色轮上近乎互补，最不容易看混。

**为什么角标要垫深色底板，而不是一把裸的金锁。** 图元底色由用户配（浅色按钮、白底文本都常见），金锁压在浅底上会糊成一团。垫一层深色底板，角标在**任意底色**上的对比度都由自己保证，不依赖图元配了什么颜色。

**为什么锁形用矢量 `Geometry` 而不是图标字体。** 控件库不该赌某个字体装没装——断言宿主里连 `Application` 都没有，字体回落成豆腐块在那里是查不出来的。取 Material 的 "lock" 24×24 轮廓，`PathGeometry` 的默认填充规则是 EvenOdd，正好把钥匙孔与锁梁下的空档掏成洞。

**为什么角标整个压在框内、不探出。** 包围盒会跟着图元旋转，而页面左上角的图元其包围盒就在画面原点附近——探出去的那一半正好落在视口外，被外层 Border 的 `ClipToBounds` 裁掉，变成"有的图元有锁、有的只剩半把"。压在里面，任何位置都完整。

**为什么要反旋转。** 角标挂在 `_selectionBox` 里就会跟着一起转，180° 时整个倒过来。另配 `_lockCounterRotation` 反着转回 `_selectionRotation.Angle`，做到"位置跟着转（贴在转过去之后的那个右上角）、字形保持正立"。

**为什么角标排在 4 个手柄之后（压最上层）。** 其实两者不会抢位置——角标只在"拖不动"时出现，而那时 `showThumbs` 必为 `false`（同一个判据的两面）。放最上层只是免得日后判据一变，就冒出一个被手柄压掉一角的角标。

### 5. `OnLayerPropertyChanged` 的语义修订（本轮唯一一处推翻既有前提）

```csharp
// 图层锁定从 s10c 起有可见后果了（选中框与角标转金），必须跟着重画。
// 这里原先写的是"锁定判定是鼠标事件发生时现算的，没什么要重算的"——
// 那个前提被 s10c-4 推翻了：现在"现算"的结论会落成一个颜色，就得有人去重算。
if (e.PropertyName is nameof(ScadaLayer.IsLocked))
    UpdateSelectionVisual();
```

原注释在 S10-c 之前是**正确**的：那时锁定只在鼠标事件里现算一次，算完就丢，没有任何需要持久化的视觉产物。s10c-4 之后，"现算"的结论**落成了一个颜色**——颜色是画上去的，就必须有人在前提变化时去重画。

**为什么不借 `ApplyLayerVisibility` 顺路。** 它开头就 `PruneSelection` 把选中清掉。而"锁一个图层"不该顺手取消用户当前的选中——用户正盯着那个图元看它变金，选中框却消失了，比不重画更糟。

**至此 `IsLocked` 变化的自动重画有两条通路，都在**：① 图元锁 → `OnSelectedElementPropertyChanged → UpdateSelectionVisual`（订阅早已在）；② 图层锁 → 本轮新补的这一条。不需要第三个订阅点。

### 6. 口径沉淀

- **判据只有一份，方向可以相反**：`IsElementEditable` 是"能不能编辑"的唯一判定（删除/对齐/拖动都用它）；而"锁定/解锁"要的是"能不能改这个保护位"，是**另一件事**，所以走 `CollectPresent`。同一个概念（可编辑）在一处用、在另一处必须不用——这不是不一致，是两件事共用了名字。
- **"空操作"要返回成功，但不留痕**：整批已是目标态 → `true` + 不产记录。判失败会让调用方以为"没锁上"；产记录会让撤销栈里堆垃圾。
- **状态变化必须有人负责重画**：把"现算"的结果渲染成持久视觉，就把一次纯计算变成了一个订阅义务。任何"现算所以不用重算"的注释，都要回头确认它算出来的东西有没有落成画面上的像素。

### 3. s10c-4 为何没有断言（结论：只能真机复核）

`ScadaChecks` 的 `[X]` 段**已有**"渲染到位图再采样像素"的完整基础设施（`RenderToBitmap` / `Sample` / `HasColorIn` / `SameColor` / `IsBlue` / `DesignToViewport`），但**选中视觉量不到**。原因写在 `Program.cs` L5165-5167：

> 为什么不验选中框本身：视觉层在 `UpdateSelectionVisual` 里要 `IsLoaded` 才画，而断言宿主没有窗口（`IsLoaded` 恒 false），多选虚线/合并包围盒在无头环境里量不到。

`UpdateSelectionVisual` 的早退链是 `_selectionBox == null || _elementLayer == null` → `!IsLoaded` → `shown.Count == 0`，**第二条在无头宿主里恒成立**，所以整段（含本轮新增的框色与角标）根本不会执行到。给控件库开 `InternalsVisibleTo` 也救不了——`_lockBadge` 永远是 `Collapsed`，能断言的最多只是"字段被创建过"，那是把断言写成同义反复。

**结论：s10c-4 不做断言，改为真机复核清单（见 §4）。** 本轮断言覆盖的是 s10c-1/2/3（写入口与菜单/面板，全在视图模型与领域层，可无头验证）。

| 角标对比度 | 深色底板 `#D8_141414` 让金锁在**任意**图元底色上都有对比度，不依赖用户配了什么颜色 |
| 小图元 | 8×8 指示灯上角标夹到 4.8px（`8 * 0.6`），此时"锁住了"主要靠金色外框传达 |
| 旋转 | 反旋转保证 180° 图元的锁仍正立 |

**须在真机上确认的三点**（静态审图看不出来的）：

1. **锁角标与诊断角标是否重叠**：`ScadaDiagnosticOverlay` 的角标也在**右上角**（`HitSize = 14`、`DotSize = 6`），而锁角标同样贴右上（`Left = boxWidth - badge, Top = 0`）。**这是本轮最可能出问题的一处**——若同址，需错开（锁角标挪左上 / 诊断右移）。另外诊断层在 `PART_SelectionLayer` 之上（`ScadaCanvas.xaml` L57 之后），真重叠时锁角标会被诊断角标压住。
2. **14px 角标在真实图元上是否过大/过小**：默认图元（如 120×40 按钮）上角标占短边 12%，观感需现场确认。
3. **拖动时角标是否闪**：角标每帧改 `Width/Height/CornerRadius/Padding`，若肉眼可见闪烁，改为只在 `locked` 状态翻转时改（缓存上一次的值）。

## 四、已知边界

1. **s10c-4 无自动化兜底**：见 §3.3。这是本轮唯一没有断言覆盖的一环，只能靠真机复核。给 `VM.Scada.Controls` 开 `InternalsVisibleTo("ScadaChecks")` 也解决不了（`IsLoaded` 恒 false 是**宿主**限制，不是可见性限制）。
2. **角标与诊断角标同址未验证**：见 §4 第 1 点，真机复核的头号项。
3. **锁定不进描述符**：`IsLocked` 是模型的**编辑保护位**，不是图元的"属性"，所以它不占属性面板的属性行（描述符是唯一真相，见 D2）。代价是它的变更通知要在两处单独补（`ScadaPropertyViewModel.OnElementPropertyChanged` L936、`ScadaCanvas.OnLayerPropertyChanged` L1090）。
4. **多选时没有整体锁定提示**：多选不给角标（没有"这一个"可言），只在组外框保持蓝色 + 逐元素描边判色。若整组都锁着，用户看到的是"一圈蓝框 + 几个金边"，需在真机上确认这个表达够不够清楚。
5. **锁定不阻止选中与查看**：锁定的语义是"不可编辑"（拖不动、改不了尺寸、不参与对齐/删除），但**仍可选中**——否则用户没法从画布上解锁。解锁入口：右键菜单「解锁图元」或属性面板顶栏复选框。
6. **图层锁与图元锁共用一个视觉**：两者都渲染成金框 + 锁角标，用户无法从视觉上区分"是这个图元锁了"还是"它所在的图层锁了"。当前判断是**刻意合并**（对用户来说都是"拖不动"，原因归属要去图层面板看），但若现场反馈"不知道该去解锁哪一层"，再考虑分色或角标加层数标记。
7. **锁定不影响运行态**：`IsLocked` 只在编辑器里生效。运行态宿主 `IsReadOnly = true`，整块画布本来就不给编辑，锁不锁都一样（这也是 V-8 里 `!IsReadOnly` 那条限制的由来——不排除的话运行态会一片金）。
8. **SCADA 新文件仍未纳入版本控制**：`Scada/Models/ScadaAlign.cs`、`ScadaEditHistory.cs`、`ScadaChangeScope.cs`、`ScadaWriteGuard.cs`、`ScadaChange.cs`、`ScadaModelBase.cs`、`ScadaZMove.cs`、`VisionMaster/ViewModels/ScadaLayerViewModel.cs`、`ScadaMenuItem.cs`、`Views/ScadaLayerView.xaml(.cs)` 等仍是未跟踪状态。**提交需用户明确授权。**
