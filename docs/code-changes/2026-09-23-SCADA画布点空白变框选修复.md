# SCADA 画布「点空白变成框选」修复（框选起点从未赋值 + 缺少拖动门限）

现场报「画布的选择有问题，我点击画布空白处，会变成框选」，附截图：蓝色虚线橡皮筋框的
**左上角钉在页面左上角（设计坐标原点 0,0）**，而不是鼠标按下的位置；框同时框住「按钮」「仪表盘」
「文本框」；右侧属性面板显示「多选」。

两条根因：**框选起点字段从未被赋值**（几何错）+ **按下瞬间即进框选态、没有拖动门限**（手感错）。
两者叠加，才出现「点一下空白，框从原点长出来、圈走一片图元」。

---

## 一、需求与决策

### 1. 需求

用户报障（逐字）：

> 「画布的选择有问题  我点击画布空白处,会变成框选」

期望口径（用户逐字选定）：

> 「**拖动超 4px 才起框（推荐）**」

修法口径（用户逐字选定）：

> 「**补起点 + 4px 门限（推荐）**」

### 2. 根因

#### 根因 A：`_bandStartModel` 全仓库从未被赋值（几何错，更硬）

`ScadaCanvas.Interaction.cs` 里有一个专供框选用的起点字段：

```csharp
/// <summary>框选起点（设计坐标；按下时就换算好，中途缩放/平移取景器也不会让框跑偏）</summary>
private Point _bandStartModel;
```

全仓库 grep 该符号**只有声明、注释与读取，没有一次写入**：

| 性质 | 位置 |
|---|---|
| 声明（无初值 ⇒ 默认 `(0,0)`） | 改动前 L85 |
| 注释提及 | L239 / L567 |
| 读（算框宽高） | L580 / L581 |
| 读（算框左上角） | L585 / L586 |
| 读（松手落账算框） | L614 / L615 / L616 / L617 |

对比 `BeginDrag`：它老老实实写了 `_dragStartViewport` / `_dragStartModel` / `_dragStartBounds` /
`_dragStartRotation` —— **偏偏漏了 `_bandStartModel`**。而 `_dragStartModel` 的值恰好就是框选该用的起点。

⇒ 真实行为：在设计坐标 (300,200) 按下空白后，`_bandStartModel` 仍是 `(0,0)`，鼠标一挪，
框就是「从原点长到鼠标」的巨大矩形，与之相交的图元全被选上。**截图里虚线框左上角钉在页面原点即铁证。**

⇒ 结论：单靠调门限治不好 —— 只要挪过门限，框照样从原点长出来。**必须同时补起点。**

#### 根因 B：按下瞬间即进框选态，无拖动阈值（手感错）

`OnPreviewMouseLeftButtonDown` 的空白分支**按下瞬间**就无条件 `BeginDrag(DragMode.RubberBand, null, point)`，
没有任何拖动阈值。原先唯一的门限 `BandSlopPixels = 3` **只在松手落账时**用（判「框是否退化成一点」）。

副作用：

- 手按在键上挪一两像素，就会真的框出一片图元来；
- 按下即 `e.Handled = true` + `Focus()`；
- `UpdateCursorState` 把光标改成十字准星 —— 真点击也会先闪一下准星。

### 3. 关键决策（已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 是否落修 | 落修（用户逐字选定「补起点 + 4px 门限」） | 两件一起治：几何与手感 |
| 2 | 起点怎么补 | **复用 `BeginDrag` 已算好的 `_dragStartModel`，删掉从未被写的 `_bandStartModel`** | 消除「两套起点字段」的隐患；移动/改尺寸/框选共用同一个起点，语义本来就是一回事 |
| 3 | 门限怎么加 | 空白按下先进**挂起态**（新增 `DragMode.PendingBand`，**追加在枚举末尾**），鼠标移动超过 `SystemParameters.MinimumHorizontalDragDistance`（=4 屏幕像素）才升级为 `RubberBand` | 遵守「枚举数值一旦发布不许改，新增只能往后追加」 |
| 4 | 门限按什么单位 | **屏幕**像素（用视口坐标比），不折算设计坐标 | 拖动是手感问题，与缩放无关；放大 8 倍时若按设计坐标 4px 判，屏幕上要挪 32px 才起框 |
| 5 | 未升级（纯点击）时怎么办 | 走「算出空集」⇒ 取消选中；**光标不闪十字准星**、**不画框** | 点空白取消选中是最常用动作，必须干净利落 |
| 6 | 挂起态是否抢事件 | 保留 `e.Handled = true` 与 `Focus()` | 空白点击本就不该继续往上冒；键盘删除/方向键微调需要画布有焦点（沿用原行为，避免回归） |
| 7 | 是否补断言 | **不补**（沿用上一轮口径） | `ScadaChecks` 对画布拖动内部状态零覆盖，改动不波及现有断言 |

### 3. 行为对照（修复前 → 修复后）

| 操作 | 修复前 | 修复后 |
|---|---|---|
| 空白处轻点一下（位移 ≤ 4px） | 进框选态；光标闪十字准星；框从**原点**长到鼠标，圈走一片图元 | 不进框选态；光标始终箭头；只取消选中 |
| 空白处拖动（位移 > 4px） | 框从**原点**长出（起点错误） | 框从**按下的位置**长出；升级瞬间才变十字准星 |
| 拖到一半滚轮缩放 / 中键平移 | 起点错误，无从谈起 | 起点钉在画面位置上不漂（因为存的是设计坐标） |
| Ctrl/Shift + 点空白 | 走加选分支：基线非空则保留原选中 | 同左（`ApplyBandResult(null)` 的加选分支天然保留原选中） |

## 四、已知边界

1. **画布拖动/框选零回归覆盖**。`ScadaChecks\Program.cs` 对 `ScadaCanvas` 的 18 处引用全部是
   `new ScadaCanvas { … }` 构造 + 样式赋值，**无一处引用 `RubberBand` / `BandSlop` / `DragMode`** ——
   这正是它能一路坏着活到今天没被拦住的原因。本次按用户口径**暂不补断言**；后续若再动这条路径，
   建议优先补：模拟 Down→Move(≤4px)→Up 应清空选中且不出现橡皮筋；Down→Move(>4px)→Up 应按框选中。
2. **`PendingBand` 仍会捕获鼠标**（`BeginDrag` 里统一 `CaptureMouse()`）。纯点击时会先捕获再释放，
   与修复前一致，未引入新副作用；但它意味着「点空白」仍会短暂拿到鼠标捕获。
3. **未升级即移出画布松手**（4px 内移出，实际几乎不可能）：会走 `ApplyBandResult(null)` ⇒ 取消选中。
   行为合理，未额外加分支处理。
4. **枚举新增值的次序**：`PendingBand` 追加在 `Pan` 之后（末尾）。语义上它与 `RubberBand` 相邻更易读，
   但枚举数值纪律要求只能往后追加，故未插队。若将来序列化 `DragMode`（目前**没有**），次序问题才会浮现。
