# 管线几何改为"只读显示"（描述符 ReadOnlyKeys）

日期：2026-10-26　状态：完成；`ScadaChecks` **3087 通过 / 0 失败**

## 为什么不是"删掉几何项"

上一轮试过从描述符里过滤掉 `$X/$Y/$Width/$Height/$Rotation`，结果 **`Hmi.PipeRun` 直接注册失败**：

> `Hmi.PipeRun 缺少几何属性 $X（请用 GeometryProperties.With(...)）`

连锁反应：注册表 50→49，所有依赖注册表的断言全红。**几何属性是注册校验的硬要求**，
框架假定每个图元都有位置与尺寸（路由器也确实要写回外框）。

所以"不能改"正确的表达是**显示但只读**，不是"不存在"。

## 改了三层

| 层 | 改动 |
| --- | --- |
| `ElementDescriptor` | 新增 `ReadOnlyKeys`（默认空）：声明哪些属性键在面板上只读 |
| `BuiltInElements`（`Hmi.PipeRun`） | `ReadOnlyKeys = new[] { "$X", "$Y", "$Width", "$Height", "$Rotation" }` |
| `ScadaPropertyRowBase` | 新增 `IsReadOnly`；面板建行后按 `descriptor.ReadOnlyKeys.Contains(property.Key)` 置位 |
| `ScadaPropertyView.xaml` | 行容器加 `DataTrigger IsReadOnly=True` → `IsEnabled=False` + ToolTip「由系统计算（随两端图元自动重排），不能直接修改」 |

## 效果

选中管线时，属性面板里 X/Y/宽高/旋转**仍然看得见**（能知道当前值是多少），但**灰掉、点不动**，
悬停提示说明为什么。加上上一轮画布侧的 `BeginDrag` 拦截（拖/缩放/旋转都不开始），
"改了又被写回"的误导彻底没有了。

## 断言

`[P1-1]`：描述符的 `ReadOnlyKeys` 必须恰好是那五个键，**且几何项本身仍在**（注册校验要求）。
判据同时钉住两件事——"只读声明在"和"没有为了让面板好看去删注册必需的属性"。

## 教训

**"不能改"有两种实现：删掉入口，或置灰入口。** 前者在注册校验/依赖关系存在时会直接崩；
后者既保住契约，又让用户知道值是什么。以后遇到"这个属性没意义"的诉求，先问
"它是不是框架的必需项"，是就置灰，不是才删。
