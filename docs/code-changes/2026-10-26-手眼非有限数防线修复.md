## 五、踩过的坑

- **只把 `RobotX` 设成 NaN 不会抛异常**：旋转矩阵仍合法，求解会在平移方程里落成
  "堆叠矩阵奇异"——看起来像"点位方向不够"，完全指不到 NaN。真正触发 `Math.Sign(NaN)` 的是
  **旋转** NaN。所以有限性检查必须覆盖 12 个分量，不能只查旋转。
- **`double.TryParse("NaN", NumberStyles.Float, InvariantCulture)` 返回 true**：`"NaN"`/
  `"Infinity"` 都能进来；`"1e400"` 反而返回 false。入表处必须显式 `IsFinite`。
- **`TryRotationLog` 对"部分 NaN"可能返回 true**：只把 `[0,0]` 设 NaN 时，`RotationAngle` 走 NaN
  分支，但 `Math.Sign` 的入参是矩阵元素之差（仍是 0），不会抛；必须让整个矩阵非有限才会命中。
  断言因此用全 NaN 矩阵。
- **`Math.Sign(double.NaN)` 抛 `ArithmeticException`**（.NET 行为）：手眼求解的 π 分支会走到这里，
  而 `RelayCommand` 不捕获异常；配置界面「求解」必须自己兜底。
