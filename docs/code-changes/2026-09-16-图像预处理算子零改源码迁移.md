## 一、需求与决策

### 1. 需求

把参考实现 `WPF-Halcon-流程拖拉/02Plugins/001图像处理/Plugin.PerProcessing`（.NET Framework 4.7.2 旧插件架构，17 个预处理算子）
迁移到本地 VisionMaster-W（.NET 9 + WPF + 插件化流程引擎），并做到：

1. **零改源码**：UI 库、`FlatPropertyGrid`、`Core.Interfaces`、流程引擎一律不动，只经既有公开扩展点接入；
2. **保留"反射属性 → 视图"的展示特点**：算子参数不写一行界面代码，全部由 `[SuperDisplay]` + `FlatPropertyGrid` 反射生成；
3. 界面与交互对齐本地既有插件 `Plugin.CreateRoi`；
4. 顺手修掉参考实现里的逻辑缺陷。

### 2. 接入点选择（都不需要改宿主）

| 能力 | 使用的既有扩展点 |
|---|---|
| 流程节点 | `VisionPluginBase` + `[Display(Name/GroupName/Description/ShortName)]` |
| 自定义配置界面 | `IPluginCustomViewProvider.GetConfigView(IStepConfigData)` |
| 参数存取 | `[StepConfig]` 属性（基类统一读写 `InputValues`） |
| 数据流 | `InputPort<HImage>` / `OutputPort<T>`（基类反射自动发现） |
| 运行结果上图 | `Core.Events.PluginPreviewExtensions.PublishPreview` |
| 参数面板 | `UI` 程序集 `ui:FlatPropertyGrid`（`BindingObject` 依赖属性） |
| 装载 | 产物复制到 `Modules\`，由 `Engine.PluginService` 扫描 `Plugin*.dll` 加载 |

### 3. 关键设计决策

**（1）存盘用"弱类型快照"，不写 CLR 类型名**

- 界面操作的是 `ObservableCollection<PreprocessOperator> Operators`（活对象，带事件）；
- 落盘的是 `[StepConfig] List<OperatorStepItem> Chain`，每项 = `OperatorKey + Enabled + Dictionary<string,string> Params`；
- 两者靠 `WriteChain()`（活链 → 快照）与 `RebuildOperators()`（快照 → 活链）双向同步，`_rebuilding` 标志防自激。

> 为什么不直接序列化算子对象：算子里有 `HImage`、事件、反射缓存；而 `TypeNameHandling` 会把类名/命名空间焊进客户现场的方案文件，以后改名就打不开。
> 基类 `SnapshotConfigValue` 走 JSON 往返、`ValueConverter.Convert` 走 `JToken.ToObject(targetType)` —— 这条通道 `List<RoiItem>` 已在用，`List<OperatorStepItem>` 天然兼容。

**（2）图像所有权三条硬规则**

1. `ExecuteChain` 永不释放入参 `src`（输入图归上游）；
2. 逐步预览的输出留在 `_stepImages`，但**与 `src` 同引用（透传）的不入字典**，否则 `DisposeStepImages` 会释放别人的图；
3. 全链禁用/全透传时最终图就是上游那张，此时 **`Clone` 一份再挂输出端口** —— 因为基类 `Dispose()` 会释放输出端口承载值。
   另外 `DisposeOldOutput()` **先置空再释放**：`OutputPort` 用 `EqualityComparer<T>.Default`（引用类型=引用比较），同引用赋值不发通知。

**（3）"禁用 = 原样透传"，不是"跳过不赋值"**

参考实现禁用算子时不给输出赋值，下一个算子拿到的是"上上级"的陈旧图像，现象是"勾掉某算子画面没恢复"，极难查。
本实现统一由链引擎保证透传。

**（4）单个算子失败不拖垮整条流程**

参考实现一个参数填错，整条流程红掉。现在：算子抛异常 → 记 `Warn`、跳过该步、图像继续流；只有链外的意外才 `Success=false`。

**（5）逐步预览只在配置界面做，正式运行不推中间图**

`GlobalEventBus.PublishOnUIThread` 内部是 `Dispatcher.BeginInvoke`（异步投递）。
配置界面在 UI 线程同步跑整链、把每步结果留下；正式运行只推最终图，中间图用完即弃（`stepResults == null` 分支里逐步 `Dispose`）。

**（6）`DisplayViewIndex` 语义对齐 `Plugin.ImageAcquisition`**

`0 = 不显示，1~9 = 主界面视图号`，用法 `if (DisplayViewIndex > 0) this.PublishPreview(img, DisplayViewIndex);`。
（`CreateRoi` 里的 `DisplayViewIndex + 1` 是历史遗留，不照抄。）

**（7）防抖**

`StructValueGenerator` 生成的参数框是 `UpdateSourceTrigger=PropertyChanged`（逐字符写入），
故参数变化经 `DispatcherTimer`（200ms）合并后再重跑链。

**（8）新增算子 = 只写一个类（开闭原则）**

`[PreprocessOperator(key, 显示名, 分组)]` + 继承 `PreprocessOperator` + 实现 `Process()`；
参数属性贴 `[SuperDisplay]`。注册表反射扫描，算子库菜单、参数面板、存盘读写全部自动生效，不改任何 switch。

### 4. 第二轮追加：链内固定框（可拖拽）

**需求来源**：盘点功能缺口后，明确要求补「固定框裁剪」，理由不是"能裁图"（`Plugin.CreateRoi` 已能做），
而是要在**处理链中间插一刀** —— 先滤波、再框裁、再二值化，ROI 插件作为独立节点做不到这一点。
同时要求框**可以拖拽**，不允许只能手填数字。

**五项已锁定决策**：

| 决策点 | 结论 | 理由 |
|---|---|---|
| 框画在哪张图上 | **当前选中算子的输入图** | 裁剪/缩放会改尺寸，画在输出图上坐标对不上 |
| 支持斜框吗 | **只支持正框**（`phi=0`，中心行/列 + 宽/高） | 预处理场景无需旋转框；参数少一半，`rectangle2` 也够用 |
| 框越界怎么办 | **自动夹取到图内 + 留 Warn**，不报错不断链 | 现场把框拖出图外是常态，报红断流反而难查 |
| 缩放参数怎么表达 | **行因子 + 列因子两个独立参数** | 与 `zoom_image_factor` 原生语义一致，能非等比 |
| 拖框基建从哪来 | **复用 `Core.Halcon` 的 `ImageEdit` + `DrawingObjectInfo`** | `Plugin.CreateRoi` 已验证通路，宿主控件一行不改 |

**新增算子**：`crop_box`（固定框裁剪）、`mask_box`（框外屏蔽，框外填指定灰度、尺寸不变）、
`zoom_factor`（按比例缩放）、`equ_histo`（直方图均衡）。算子总数 17 → **21**。

**带框算子的共同契约** —— `BoxOperatorBase : PreprocessOperator`：

- 四个 `[SuperDisplay]` 参数（中心行 / 中心列 / 框宽度 / 框高度，`GroupPath="编辑框"`）→ 属性面板自动生成，零界面代码；
- `ToBoxTuples()` / `ApplyBoxTuples()` 负责与画布 `rectangle2` 元组互转。注意 **`W = 2×length1`（水平半宽）、`H = 2×length2`（垂直半高）**；
- `ClampBox()` 先夹尺寸再夹位置，并置 `WasBoxClamped`；
- 未框选（宽高为 0）时 **`Process` 直接透传**，摘要显示"未框选（透传）"；
- `WasBoxClamped` 故意**不贴 `[SuperDisplay]`** —— 基类的快照筛选条件是"有 `[SuperDisplay]` 的可读写属性"，运行时标记因此天然不进存盘。

**插件层的三处关键取舍**（与 `CreateRoiPlugin` 的差异）：

1. **画布是算子链的"投影"，不是数据源。** ROI 插件里 `CanvasRois` 集合变更要回写 `RoiList`；这里 `OnCanvasRoisChanged` 只做订阅/退订，外加"用户主动删框 → 把框参数归零"一件事。链才是唯一数据源。
2. **复用同一个 `DrawingObjectInfo` 实例，只换 `HTuples`。** 每次同步都 new 一个的话，控件那边句柄重建，用户在数值框里改数字会掉焦点。
3. **`RefreshPreview()` 里【故意】不调 `RefreshCanvasBox()`。** 跑一遍链不会改框参数，而用户手还按在框上时重建句柄，会把这次拖拽直接打断。

配套的双向同步细节：

- 两条防重入闸：`_syncingCanvas`（VM 往画布写参数时屏蔽一次回写，否则"写进去→又读回来"自激）、
  `_fromCanvas`（拖拽结果写回算子时屏蔽一次回推，否则拖到一半被 `SetParams` 拽住）；
- `SelectedOperator` 一变就 `ApplyPreviewState(..., force: true)` —— 第 0 步与第 1 步的输入图常常是同一张，
  状态"没变"会导致通知全被吞、框还挂着旧算子的位置；
- `IsBoxBaseDisplayed()` 保证只有画面确实是"那一步的输入图"时才显示框；
- 输入态取图用**向前回溯第一张真正产出图的步骤**，而不是简单取 `i-1`：`_stepImages` 里故意不存透传结果，直接取 `i-1` 会让画面跳回上游；
- 预览路径**没有日志通道**（全仓 `ILogService` 只有 DI 注册，配置期 VM 拿不到），所以越界提示双通道落地：
  正式运行走 `logger?.Warn`，配置界面靠算子摘要里的"（越界已夹取）"文本。

### 5. 顺带修掉的算法问题

| 位置 | 原问题 | 修正 |
|---|---|---|
| `Threshold` / `VarThreshold` | 前景极性互相矛盾（一个 255 一个 0） | 统一"命中区域为白（255）"，`RegionToBin(fg:255, bg:0)` |
| `RotateOperator` | 说明与 Halcon 行为不符 | 更正注释与参数语义 |
| `illuminate`（对比度） | `Scale` 可填 0/负数，Halcon 直接报错 | `[RangeValidation(0,1)]` + `Clamp(0.01, 0.99)` |
| `median_image` | MaskType 传了 Halcon 不认的值 | 收敛为 `square/circle/diamond` |
| `ColorSpaceMode` | 与旧枚举对不齐、缺 `YUV` | 对齐旧枚举并补齐 |
| 均值/灰度形态学 | 旧版膨胀↔腐蚀接反 | 抽出 `RectMaskOperator` 共用，方向统一 |
| 参数校验 | "3–11 的奇数"只写在注释里 | 基类 `Normalize()` + `OddAtLeast()` 运行时纠偏 |
| 加载未知算子 | 反序列化失败整份方案打不开 | 按 Key 跳过并汇总进 `LoadWarning` 红字提示 |

### 6. 第三轮追加：整链导出 + 链复制/粘贴

**需求来源**：盘点后确认两个真缺口 —— ①调完参数想把"每一步长什么样"整份拿走去复盘；②同一条链在别的方案/别的机器上要重搭一遍。

**（1）导出整条链 —— `ExportChainCommand` / 「导出图片」按钮**

先说清**为什么不做"另存当前预览图"**：画布用的 `ImageEdit` 右键菜单里本来就有「保存原始图像 / 保存缩略图像」，重复造没意义。
缺口是**一次调完参数后，把每一步的输出图按步命名一把导出**。

实现拆成两半，这是为了能脱离界面单测：

- `ExportChain()`：只管校验有输入图 + 弹一次 `SaveFileDialog`（借"存清单"这个框同时定位目录和起前缀）；
- `internal WriteExport(manifestPath)`：真正干活，转调它即可指定任意路径。

产出三份东西，同一个目录、同一个前缀：

| 产物 | 命名 | 说明 |
|---|---|---|
| 每步输出图 | `前缀_步号_算子名.png` | 步号两位补零且**全程连续**（禁用步照样占号），便于跟清单对照 |
| 参数清单 | `前缀.txt` | 制表符分隔，逐步列出「步号 / 算子 / 参数摘要 / 文件名 / 尺寸」 |
| 链快照 | `前缀.json` | 与剪贴板同一套 `List<OperatorStepItem>` 格式，可直接粘回插件 |

**关键取舍：透传与禁用的步骤不出图，但清单里必须留痕。**
禁用步写 `已禁用，未出图`，透传步写 `透传，未单独出图`。否则现场会以为"文件丢了"，反过来排查半天。

判定"这一步到底有没有产出新图"用的是**引用比对**，不是查字典有没有键：

```csharp
// 用它做引用比对判断"这一步到底有没有产出新图"，比只查 _stepImages 更准 ——
// 中间的透传步（如缩放因子 1.0、框正好盖住整图）在 _stepImages 里存的是上一步那张，
// 不管的话会给同一张图重复写出一个文件。
HImage current = src;
for (int i = 0; i < Operators.Count; i++)
{
    var op = Operators[i];
    string step = $"{i + 1:00}";

    if (!op.Enabled)
    {
        lines.Add($"{step}\t{op.DisplayName}\t{op.Summary}\t已禁用，未出图\t-");
        continue;
    }

    var image = _stepImages.TryGetValue(i, out var shot) && shot != null && shot.IsInitialized() ? shot : null;
    if (image == null || ReferenceEquals(image, current))
    {
        // 透传步在 _stepImages 里通常是故意留空的（不持有所有权），这里如实写清楚，别让人以为丢文件了
        lines.Add($"{step}\t{op.DisplayName}\t{op.Summary}\t透传，未单独出图\t-");
        continue;
    }

    string imagePath = Path.Combine(directory, $"{stem}_{step}_{Sanitize(op.DisplayName)}.png");
    try
    {
        PreprocessHService.SaveImage(image, imagePath);
        saved++;
        current = image;                       // 下一步的输入就是它
        lines.Add($"{step}\t{op.DisplayName}\t{op.Summary}\t{Path.GetFileName(imagePath)}\t{DescribeImage(image)}");
    }
    catch (Exception ex)
    {
        lines.Add($"{step}\t{op.DisplayName}\t{op.Summary}\t写出失败：{ex.Message}\t{DescribeImage(image)}");
    }
}
```

（见 [WriteExport](file:///e:/VM/VisionMaster-W-master/Plugins/Plugin.PreProcessing/PreProcessingPlugin.cs#L805-L886)）

> 为什么不能只查 `_stepImages`：透传步在字典里**可能存着上一步那张对象**（例如链中间的 `zoom_factor` 因子填 1.0）。
> 只查缺项会给同一张图重复写出一个文件，前缀一样、步号不同，看的人根本分不清哪张是真产物。

另外 `PreprocessHService.SaveImage` 内部先剥掉扩展名再传给 `write_image`，否则会写出 `xxx.png.png`。

**（2）链复制/粘贴 —— `CopyChainCommand` / `PasteChainCommand`**

剪贴板里放的是**弱类型 JSON 文本**（`List<OperatorStepItem>`），不是对象、也不含 CLR 类型名：

- 走的就是 `[StepConfig]` 落盘那套哲学 —— 改类名、换版本都不影响已经复制出去的文本；
- 文本形态顺带满足"发微信给同事一份参数"这种现场需求。

三条行为约束：

1. **`CopyChain` 绝不改动 `Chain`**（只读快照），复制动作对存盘配置零副作用；
2. **粘贴 = 追加到链尾，不清空**。要清空先按「清空」按钮 —— 隐式清链是事故制造机；
3. **宽容解析**：`JsonException` 不抛，识别失败就提示"不是处理链"；单个 Key 认不出则**跳过并计数**，
   提示形如 `已粘贴 1 步，跳过 2 步不存在的算子：no_such_op、OLD_NAME`。旧方案里的链拷到新版本不会整份废掉。

粘贴路径上的三个细节：
`_rebuilding` 罩住整批追加（避免逐条回写 `Chain` + 逐条重跑链）→ `WriteChain()` → `SchedulePreview()` →
`SelectedOperator = pasted[0]`（粘完停在第一条新算子上，参数面板直接可改）。

**（3）反馈通道：`ActionHint`**

配置界面拿不到 `ILogService`（全仓只有 DI 注册，VM 里没有容器），所以复制/粘贴/导出的结果统一走
`public string ActionHint`（`SetHint()` 写入并发通知），视图里预览区底部那行绿字绑定它。
`CLIPBRD_E_CANT_OPEN` 这类瞬态故障不弹框，`TrySetClipboardText` 静默重试 5 次（间隔 40ms）后提示"剪贴板被占用"。

### 上机反馈修复 1：配置窗体初始尺寸不对（右侧两栏被裁）

**现象**：打开配置界面，右侧「处理链 / 算子参数」只显示出一半，要手动拖窗口才看得全。

**根因**：`PreProcessingView` 上写死了 `Width="1120" Height="620"`，而承载它的通用外壳
`VisionMaster/Views/DialogViews/PluginConfigShellView.xaml` 把窗口固定成 `Width=880 Height=600`。
用户控件的显式宽度优先，直接溢出外壳给的内容区，右边两栏被裁掉。

**为什么改插件而不是改外壳**：那个外壳是全平台共用的（`CreateRoi`、`DataRecord`、脚本类插件都走它），
改它的固定尺寸会连带影响别的插件窗口。尺寸该由使用者自己决定。

**改法**（`PreProcessingView.xaml` + `.xaml.cs`，宿主零改动）：

- 删掉视图上的 `Width/Height`，只留 `d:DesignWidth/Height` 喂设计器；
- 中列加 `MinWidth="300"`，窗口被缩小先把预览压窄而不是把右栏挤出去；
- `Loaded` 时 `Window.GetWindow(this)` 拿到宿主窗口，**只放大不缩小**地撑到
  `1120+16 × 620+116`（外壳标题栏 50 + 按钮栏 50 + 内容边距 16），并以 `SystemParameters.WorkArea` 为上限，
  最后把 `Left/Top` 夹回工作区 —— 窗口超出屏幕会导致底部「确认」点不到，属于自锁。
  最大化状态直接跳过（那时改 `Width/Height` 只影响"还原尺寸"，改了不生效）。

### 上机反馈修复 2：流程线程与配置界面共用 `Operators`（无锁）

**问题**：`RunAlgorithm` 在流程线程直接遍历 UI 线程持有的 `ObservableCollection`。
原实现用下标循环，侥幸躲开了"集合修改后无法枚举"，但界面若在运行途中删步骤，`Count` 中途变小会
`IndexOutOfRange`，被外层兜成一次"图像预处理失败"。后果可控，语义却模糊。

**改法**：`ExecuteChain` 增加 `IReadOnlyList<PreprocessOperator> steps` 参数，
流程线程入口先 `Operators.ToArray()` 拍快照，整次运行（含端口统计 `StepCount` / `ActiveOperators`）只读快照；
预览路径仍在 UI 线程，直接传活的 `Operators`。所有权语义不变，快照只解决"集合被抽走"，算子实例本身仍归活链。
