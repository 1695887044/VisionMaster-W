# SCADA 图元可写性与权限闸门（文本禁绑 + 数值域两档 + 写前先查）

把「哪些图元能接变量、能接哪些属性」「数值域的可编辑性怎么收口」「谁有权改现场量」
这三件事一次拉直：

- **「文本」图元彻底退出变量绑定**：它是静态标签，内容与文字颜色都不再给 ƒx。
- **「数值域」模式由三档收成两档**：只读 / 读写，「只写」档撤掉。
- **「读写」与位按钮的写入前先查权限**：角色不够，点一下都不进编辑态。

---

## 一、需求与决策

### 1. 需求

用户在组态界面上连提两条：

> 「文本控件 应该不存在可以绑定的对象，IO 文本域，应该在设计阶段可以选择只读或者读写功能以及对应权限」

拆开是三件事：**文本图元不该有绑定入口**、**数值域的模式档位要收口**、
**可写性要跟角色权限挂钩**。另外还发现一个缺口：既有权限闸门只管**事件钩子**，不管**写入本身**。

### 2. 关键决策（逐条已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 「文本」图元的可绑定口径 | 内容（`Text`）+ 文字颜色（`Foreground`）**全禁** | 绑上去只是把一段静态字换成另一段静态字；真正会变的值从来不走这条路 |
| 2 | 「数值域」的模式档位 | 收成两档：`Output`（只读）/ `InputOutput`（读写） | 「只写」档在实机上没有真实用法，留着只会让"能不能点进去"这件事多一种分支 |
| 3 | 「读写」的权限闸门卡在哪一层 | **写前先查**（卡在控件侧） | 写通道只认变量收不收值、不认识角色；领域层那条闸门卡的是事件钩子。两边都不管，就会出现"谁都不许改的域，操作员照样把数写进变量" |
| 4 | 改动范围 | 全做，**位按钮一起加**权限闸门 | 位按钮的 `Write` 与数值域的 `CommitEdit` 是同一类"改现场量"，只补一处等于留半个洞 |

### 3. 设计要点（为什么这么做）

- **可编辑性收敛成「四道门」**：模式允许写 + 宿主给了写通道 + `Value` 真绑了变量 + 当前角色够格。
  少任何一条都点不出输入框——"点了没反应"总好过"敲完才告诉你写不了"。
- **判「是不是读写档」用「不等于 `Output`」，不是「等于 `InputOutput`」**：
  已存盘画面里可能残留 `Mode = "Input"`。按前一种判法它自动归入读写档（最多"多能写"），
  按后一种判法会变成只读——"存盘时能改、打开后改不动"才是真的坑。
- **提交那一刻再查一次权限**：`UpdateEditable` 只在模式 / 上下文 / 模型刷新时重算，
  赶不上登录状态的变化。否则"编辑框开着的时候登出"就能把值写进去。
- **权限出口的兜底语义与领域层逐字一致**：`RequiredRole` 为 null（没配过权限）一律放行；
  未登录按操作员算。旧 `.vms` 里根本没有这个字段，读出来就是 null——"不限制"是它们能照常跑的基础，
  也是本期不需要迁移方案的实现基础。
- **判定规则只有一份**：控件侧走 `RuntimeContext.AccessPolicy.CanOperate`，
  断言里的测试替身复用领域层 `ScadaRoleExtensions.Allows`，不另写一套"高角色含低角色"。
- **依赖单向**：`AccessPolicy` 这个出口挂在 `Scada.Controls` 的 `ScadaRuntimeContext` 上，
  接口 `IScadaAccessPolicy` 在 `Scada`（领域层，零 WPF）；控件不认识会话，只认识这只"手提箱"。

## 四、已知边界

1. **「文本」图元禁绑只影响组态期面板**：`IsBindable` 管的是给不给 ƒx 按钮，
   运行层 `ScadaRuntimeBinder` 并不查它。已存盘画面里绑在「文本」上的变量**仍然生效**，
   只是属性面板不再显示 ƒx——与既有「位置与尺寸 / 外观」两组的处理完全一致。
2. **撤掉「只写」档后没有迁移动作**：残留 `Mode = "Input"` 的画面按"不等于 `Output`"判为读写档，
   最多"多能写"，不会变成只读。
3. **权限闸门只管「改现场量」**：数值域的 `CommitEdit` 与位按钮的 `Write`。
   事件钩子那条闸门仍在领域层 `ScadaRuntime.RaiseElementEvent`，两处口径一致但互不替代。
4. **未登录 = 操作员**：没接线时 `AccessPolicy` 是 `DefaultScadaAccessPolicy.Instance`，
   与领域层同一口径；不会因为"没接权限"而放开一切。
5. **权限判定只有三档**（`Operator < Engineer < Administrator`），不支持自定义角色或按图元单独授权。
6. **属性面板宽度**：截图中右侧面板仅约 110px、取值框被切在窗口外，此项**尚未定位**
   （是否为本次改动引入未确认），不在本期范围内。
7. **环境级抖动**：复跑断言时偶发 `AppSettingsService.Save()` 的 `File.Replace` 抛
   `IOException: 无法删除要被替换的文件`（退出码 `3762504530`），原样重跑一次即通过，与本期改动无关。
8. **构建前必须关掉正在运行的 `VisionMaster.exe`**，否则 `PostBuild` 拷贝 `Modules\*.dll` 会
   `MSB3073` 失败。
