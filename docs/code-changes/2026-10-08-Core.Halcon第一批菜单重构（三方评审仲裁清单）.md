# 2026-10-08 Core.Halcon 第一批菜单重构（三方评审仲裁清单落地）

## 一、起因与决策链

2026-10-08 对 `Services\Core.Halcon` 的改进建议清单做了**三方评审**（ui 角色 + vision 角色独立审查、主会话仲裁）：ui 评审 13 条逐条评级 + 补 7 条遗漏；vision 评审同 + 补 6 条；仲裁 7 个分歧点后产出分批清单。本文记录**第一批**（10 项）的实现。第二批（缩放状态保持 / HistogramPlot 上提 / 标定残差箭头 / 伪彩 LUT）与第三批（Line Profile / ImageCompare / 多选批量平移）见各自主文档（未开工）。

评审中仲裁掉的方案（不做）：BuildContextMenu 拆 protected virtual 虚方法链（`RegisterMouseMethods` 已是 virtual、ContextMenu 可实例级整替，拆链=过度设计）→ 改轻量 `AppendContextMenu`；折线**交互层**上提（单消费者=过早抽象，卡尺不消费折线）→ 只上提几何静态类；Ctrl+Z/Ctrl+S 基类快捷键（BeadInspect 已用 Ctrl+Z，且基类无可撤销操作，不预占键位）。

## 二、改动清单

### 1. 右键菜单整包重构（HalconBase.cs + ImageEdit.cs / ImageDisplay.cs / ImageReadOnly.cs）

旧「信息」一个子菜单混装视图/图像两类操作，其中「适应图片/窗口」一个开关管两条语义（勾=1:1、不勾=铺满，且勾选态不随滚轮缩放更新——双向都坏）。重构为：

- **「视图」子菜单**：适应窗口（铺满）/ 按 1:1 显示（原始像素）/ 图像信息 / 十字线。勾选态由 `ContextMenu.Opened` 时实算刷新（`SyncMenuStateOnOpen`：`_showImageInfo`/`_showCross` 字段 + `IsViewingOneToOne()` 按 GetPart 实算，容差 2%）——不靠点击时翻勾，杜绝"状态与显示脱节"（P0-3 同类病根）。
- **「图像」子菜单**：保存原始图像 / 截取当前视图并保存（旧名「保存缩略图像」名不副实——DumpWindow 截的是整个 HALCON 窗口，与缩略图无关）/ **复制当前视图**（DumpWindowImage → %TEMP% PNG 中转 → BitmapSource → `Clipboard.SetImage`，不落常驻文件）/ **复制像素信息**（从 `DisplayImageInfo` 现算单行文本，不抄 BottomText——后者可能被「图像信息」开关关掉）/ 打开图片。
- **API 真相**（实测）：`HOperatorSet.WriteImage` 托管重载**只认文件路径**（无 Stream 重载）、HImage 无 `ToBitmap`/`EncodedBytes`——复制视图走 %TEMP% 中转 + finally 删除。
- **扩展点**：`AppendContextMenu(MenuItem, separator)`——宿主/派生类可追加菜单项而不必 `ContextMenu = null` 整体接管（BeadInspect 之前的唯一选择）。

### 2. ImageEdit 区域子菜单（ImageEdit.cs 重写）

- 头部实时计数「区域 (N)」（Opened 时刷新）。
- 新增「清空全部区域」→ 基类 `ClearAllRois()`：**带确认弹窗**（DrawObjectList 双向绑定 VM/流程参数且无撤销栈，误清=参数永久丢失；集合 Reset 分支的句柄释放链路是现成的）。无 ROI 时走"没有可清空的区域"瞬时提示分支。
- 「删除选中区域」在 `ActiveRoi == null` 时置灰（旧版静默 no-op，用户以为点坏了）。
- **取点模式收敛**（UI 评审发现的真误操作路径）：`IsPickMode=true` 时「新建 ×」三项置灰 + 基类把「打开图片」置灰（Calibration 取点中途点"新建矩形"会插无关 ROI 且打断取点）。

### 3. 双击切换 + 快捷键（HalconBase.cs）

- **双击画布**在「适应窗口 / 1:1」间切换：400ms + 6px 容差的自实现双击检测（同一位置两次 HMouseDown），**三重模式互斥**（`SmearMode != None || IsPickMode || IsDrawing` 时禁用——涂抹中双击=两次落笔、取点中=取两个点，"双击=两次单击"是这些模式的既有语义，不能吞）。当前 1:1 则切铺满，否则（含任意中间缩放）切 1:1。
- **快捷键 F=适应窗口、1/小键盘1=1:1**：焦点在控件时生效。两个实测坑：
  - 裸字母键的 `KeyGesture` 构造**直接抛** NotSupportedException（"None+F" 非法）——不能走 InputBinding，改 `OnKeyDown` 直接比较（已修，曾有 CreateRoiView 实例化断言连带炸红的教训）。
  - `Control` 默认 `Focusable=false`——`HMouseDownForFocus` 在左键按下时 `Focus()`，否则"按 F 没反应"。
- Ctrl+Z/Ctrl+S **不挂**（仲裁结论，理由见上）。

### 4. MeasureAnnotation 补 Polyline/Point（MeasureAnnotation.cs + RenderAnnotations）

- `Polyline`：N 点连线一次画完（`ShowVertices=true` 时逐点小十字+序号）——此前 BeadInspect 画 14 点参考路径要拼 2(N-1)+2N ≈ 54 个 Line/Text 对象，每次改点整表重建。
- `Point`：小十字标记 + 可选文本（匹配中心/标定点/取点回显）。
- 两者是未来焊缝轮廓/折线交互层（若立项）的前置件。

### 5. PathEditor 上提（BeadPathEditor.cs → Core.Halcon\Geometry\PathEditor.cs）

- 纯静态、零 HALCON 依赖的几何类原样搬迁（namespace `Plugin.BeadInspect` → `Core.Halcon.Geometry`，类名 `BeadPathEditor` → `PathEditor`）。
- 消费方改引用：`BeadInspectPluginConfigView.cs`（using + 全部调用点）、断言 12（`BeadInspectChecks.cs`，改 using 即续守"**断言测的就是界面用的**"——界面和断言仍调同一个类）。
- 旧文件删除。**交互层（拖点/撤销栈/坐标系警告）留 BeadInspect**，等第二个真实消费者（仲裁结论）。
- 迁移中顺带消解一个 using 二义：`Core.Halcon` 命名空间引入后 `HImage.GetImageSize()` 的 0 参扩展方法重载冲突 → BeadInspect 的 `ClampToImage` 改用 `GetImageSize(out, out)` 重载。

### 6. 顺手小修（UI 评审遗漏项）

- 引擎不可用占位提示补 `MaxWidth=460`（MatchingView 模板预览高仅 120px，两三行 Reason 会横向撑破）。
- `HSmart_HMouseMove` 异常分支写 ex.Message 后被正常路径无条件覆盖（死代码路径）→ 异常时清空读数行改写异常文本。

## 三、断言（HalconControlChecks.cs 第三批，15 条新增全绿）

菜单结构 7 条（顶层=视图/图像、双语义开关已拆、勾选态项归位、改名、复制入口、ReadOnly 口径、区域子菜单含清空）+ 行为 4 条（删除置灰、计数头实时、取点模式下打开图片置灰、ClearAllRois 无 ROI 走提示分支）+ 标注 2 条（Polyline/Point 枚举与契约）+ 上提 2 条（PathEditor 在新命名空间可用 + 插点语义保持）。

**断言工程两个实测教训**：① 右键菜单在 `RegisterMouseMethods`（OnApplyTemplate 时才调）里建——断言无模板环境须反射调它先建菜单（`ContextMenu!.Items` 直接读 = NRE）；② 菜单项遍历必须 `OfType<MenuItem>()`——Separator 参与强转 `InvalidCastException`（产品代码 ImageEdit 的取点收敛循环同款坑，一并修掉）。
