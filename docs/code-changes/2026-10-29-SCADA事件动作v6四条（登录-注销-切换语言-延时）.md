     private sealed class AccessPolicyUserSession : IScadaUserSession
     {
         private readonly ScadaAccessPolicy _policy;
         public AccessPolicyUserSession(ScadaAccessPolicy policy) => _policy = policy;

         public bool IsLoggedIn => _policy.IsLoggedIn;

         public bool TryLogout(out string? error)

## 踩过的坑

- **`VisionMaster` 首次构建报了 9 条"成员不存在"的假错误，全是 `_wpftmp` 项目的**：`LanguageManagerView.xaml` 说没有 `OnAddLanguageClick`、`ScadaEditorViewModel` 说没有 `OpenLanguagesCommand`/`ResolveText`——而这三个成员在磁盘上明明都在。`dotnet msbuild -getItem:Compile` 证明文件确实在编译集里。**根因是 `obj\` 里积压的陈旧中间产物**（`obj\Debug\net9.0-windows` 下有几十份历史 `*_wpftmp.*` 残留）：`rmdir /s /q VisionMaster\obj` 后重建即 **0 错误**。以后见到"某成员不存在但代码里明明有"的报错，先清 `obj` 再怀疑源码。
- **`ShowRuntimeAccessLoginPrompt` 对空权限是"直接放行"**：`if (string.IsNullOrWhiteSpace(requiredPermission)) return true;`。把 `loginPrompt: required => ShowRuntimeAccessLoginPrompt(c, required)` 直接接上去，会让「登录」动作**永远不弹窗、永远记"已登录"**（而且不报错）。必须兜一个具体权限 Key（见"下一步"）。
- **`ScadaAccessPolicy` 不是 `IScadaUserSession`**：字段名很像（`IsLoggedIn` / `CurrentUserName` / `Logout`），但语义差两处——未登录时 `CurrentUserName` 给 `"未登录"` 而不是 `null`，注销返回 `void` 而不是 `bool + 原因`。直接强转编译不过，需要适配器。
- **延时临时钩子必须 `Actions.Clear()`**：`ScadaEventHook.Actions` 的 setter/`CollectionChanged` 会给每条动作挂 `PropertyChanged` 订阅；临时钩子派发完不清空，这些动作会一直钉住它（每次延时一条订阅泄漏，长跑现场会慢慢变大）。
- **断言没接进 `Main` 也能先跑**：本轮不许改 `ScadaChecks\Program.cs`，于是用 `artifacts\_v6probe\` 下一个一次性反射探针（`Assembly.LoadFrom` + `GetNestedType("ActionV6Checks", NonPublic)` + `GetMethod("Run")`）把真断言跑了一遍，**pass=14 fail=0**，跑完即删。探针不引用任何仓库工程，只反射已构建的 `ScadaChecks.dll`，不会污染 sln。
