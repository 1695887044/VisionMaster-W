# 变量管理对话框 —— 三栏整体视觉重做

日期：2026-09-17
范围：`VisionMaster/Views/DialogViews/GlobalVariableView.xaml`（纯视图层，未改 ViewModel / 业务逻辑）

---

## 一、需求与决策

用户反馈（附截图）："现在界面不美观"。

经 AskUserQuestion 确认两点：

1. **现象**：「点文字区域无反应（推荐先按这个修）」——三个下拉框只有右侧小箭头能点开。
2. **美化范围**：「**三栏整体视觉重做**」——左栏（变量来源树）、中栏（新建变量表单）、右栏（变量明细表）一起重排，统一栅格间距、卡片层级、字体阶梯、颜色语义。

即：不是"只修刺眼细节"，而是把三栏放到同一套设计规范里重画。

## 二、设计规范（本次落地的四件事）

### 1. 栅格间距统一

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 外层容器 Margin | 6 | **14** |
| 栏间距 | 10 | **12** |
| 左栏宽 | 215 | **216** |
| 中栏宽 | 285 | **296** |
| 卡片圆角 | 8 | **12** |
| 卡片标题栏高 | 无（内联） | **52**（统一） |

三栏统一为 `216 / 12 / 296 / 12 / *`，卡片顶、底、标题栏基线全部对齐，视觉上"长在一起"。

### 2. 卡片层级：投影层与内容层分离（★ 关键坑）

每个卡片由 **两个叠放的 Border** 组成：

```xml
<Grid Grid.Column="0">
    <Border Style="{StaticResource CardShadow}" />   <!-- 只承载投影，空内容 -->
    <Border Style="{StaticResource CardBorder}"> ... </Border>
</Grid>
```

**为什么不直接给 `CardBorder` 加 `Effect`？**

`DropShadowEffect` 会让 WPF 把整棵子树渲染到一张离屏位图（RenderTargetBitmap）再做模糊，**子树内的文字因此失去 ClearType 亚像素抗锯齿，整卡片文字发糊**。

把"投影"和"内容"拆成两层后：投影层是空的、不含任何文字，随便离屏渲染；内容层留在正常渲染路径上，文字保持清晰锐利。**鱼与熊掌兼得。**

### 3. 字体阶梯

| 层级 | 字号 | 字重 | 颜色 |
| --- | --- | --- | --- |
| 卡片标题 `CardTitle` | 14 | SemiBold | `TextPrimaryBrush` #0F172A |
| 分组标题（网络参数） | 12 | SemiBold | `PrimaryTextBrush` #0369A1 |
| 表单标签 `FormLabel` | 12 | SemiBold | `TextSecondaryBrush` #475569 |
| 正文 / 输入 | 12.5~13 | Normal | `TextPrimaryBrush` |
| 表头 | 12 | SemiBold | `TextSecondaryBrush` |
| 表格次要列（类型） | 12 | Normal | `TextMutedBrush` #94A3B8 |
| 底部脚注 | 11 | Normal | `TextMutedBrush` |

**尺寸递减 + 颜色递减**，用户扫一眼就知道"先看标题、再看分组、再看内容"。

### 4. 颜色语义统一

| 语义 | Token | 值 | 用在哪 |
| --- | --- | --- | --- |
| 主色 | `PrimaryBrush` | #0EA5E9 | 图标、聚焦边框、写值按钮 |
| 主色深 | `PrimaryDarkBrush` | #0284C7 | 摘要胶囊内的值 |
| 主色浅底 | `PrimaryLightBrush` | #E0F2FE | 当前值胶囊、选中行、徽标 |
| 主色文字 | `PrimaryTextBrush` | #0369A1 | 浅底上的文字 |
| 成功 | `SuccessBrush` | #22C55E | 在线圆点 |
| 危险 | `DangerBrush` | #EF4444 | 离线圆点、删除按钮 |
| 警告 | `#D97706` | — | 恢复初始值按钮、线圈提示 |

页面背景 `#EEF2F7` 比卡片白稍深，白卡片自然"浮"起来。

## 三、修改文件清单

**A. 资源层（`UserControl.Resources`）**

2. 新增 `CardBorder` / `CardShadow` / `CardHeader` / `CardTitle` / `CardTitleIcon` 五个卡片体系样式。
3. 新增 `InputInGroup`（白底 + `#BAE6FD` 描边，用于浅蓝分组内的输入框）。
4. 新增 `ComboInGroup`（同上，用于浅蓝分组内的下拉框）。
5. 新增 `SegmentRadio`：把原先两段各自内联的 `RadioButton.Template` 抽成一个共享样式（本地/网络分段控件）。

**B. 三栏骨架**

三栏全部改为 `Grid` + 双 `Border` 叠层；标题栏统一换成 `CardHeader` + `CardTitleIcon` + `CardTitle`。

**C. 中栏（新建变量）**

- 浅蓝分组（网络专属配置）重做：`Padding 12 → 14`、圆角 `8 → 10`，新增"网络参数"分组标题图标。
- 地址/协议摘要改为**浅蓝胶囊**（`#E0F2FE` + 圆角 6）。
- 「创建变量」按钮从表单流里移到**底部固定操作栏**，用一条细分割线与表单断开。

**D. 右栏（变量明细）**

## 五、已知边界

1. **运行效果未经用户确认**：本次只做了编译验证，实际观感（投影强度、行高、列宽是否挤压）需要用户实机打开对话框确认后再微调。
2. **投影层代价**：`CardShadow` 用了 `DropShadowEffect`，仍是一次离屏渲染（每卡片一次）。本对话框只有 3 个卡片，开销可忽略；若将来出现"列表里几十个卡片"的场景，应改为预渲染的九宫格阴影图或直接去掉投影。
3. **下拉框整框可点**：属上一次修复内容（见 `2026-09-17-变量管理下拉框整框可点修复.md`），本次未改动 `ModernCombo` 模板结构，仅新增了它的变体 `ComboInGroup`（`BasedOn` 继承，热区逻辑一并继承）。
4. **纯视图改动**：所有 Binding / Command 保持原样，ViewModel 未动，回滚只需还原这一个 XAML 文件。
5. **列宽是硬编码像素**：窗口若被拉得很宽，「当前值」列会变宽，其余列不变。若日后需要"按比例铺满"，需改用 `Width="1*"` 配 `MinWidth`。
