## 一、起因与目标

软件此前没有可用的内置帮助入口：菜单「帮助(H)」里只有既有但未接线的「激活」「建议及反馈」「关于」等项（本次未动，见「六」），而手册全部散在仓库 `docs\` 里——那是开发文档，现场用户看不到。此时插件（含驱动）已到 **38 个**（探针口径），各插件自带文档有无不一。

目标是"**一本目录查全部**"，从「帮助(H) → 帮助文档」打开，形态对齐 CHM：左目录树 / 右 FlowDocument 正文 / 工具栏（隐藏目录、上一步、打印、正文字号）。两条硬要求：

1. 没有写手册的插件也必须在目录里有一页（不能出现空节点）；
2. 不破坏既有投递链——`Modules\` 仍只投 DLL，`pack.ps1`、`Plugins\Directory.Build.targets` 不为本功能改动。

## 三、关键设计与理由

### 3.1 手册走内嵌资源——`Modules\` 投递链一格不动

- 约定：插件程序集里以 `<程序集名>.Help.` 为前缀的内嵌资源，**一个 `.md` 一页**；文件名按字符序排序即页序（`01-`、`02-` 前缀，**多页时文件名要零填充**——页序是字符序，`10-` 会排在 `2-` 前面）；页标题取正文**第一个 `# ` 一级标题**，没有才回退文件名（`HelpCatalogService.cs:367-387`）。宿主手册走同一条路（`VisionMaster.csproj:76`）。
- 图片：`Help\images\` 下的文件随资源内嵌，宿主按 `{程序集}.Help.images.xxx.png` 解析（`:293-297`、`LoadEmbeddedImage :336-364`）；取不到时**降级成文字**，不让整页渲染失败。
- 为什么内嵌：`Modules\` 里仍然只有 DLL——`pack.ps1` 第 3 步整目录拷 `Modules\`（`pack.ps1:137-150`）不需要认识新文件类型，`Plugins\Directory.Build.targets` 的 DLL 投递约定（`:40-43`）也不需要改；插件手册跟着 DLL 走，"升级 = 覆盖同名 DLL、不丢用户数据"这条结构承诺原样成立。
- 代价要记牢：**改手册 = 重建插件工程**。手册编进 DLL，源码改了不重建，`Modules\` 里还是旧 DLL、手册也是旧的——与 AGENTS.md 红线③"改了插件源码必须重建插件工程"同一口径。

### 3.2 插件手册三条来路（按优先级）

1. **内嵌资源**（约定路径，零配置，见 3.1）；
2. **可选接口** `IPluginHelpProvider`（`IPluginHelpProvider.cs:11-19` 的注释即契约）：适合"正文要在运行期按现场环境生成"或"要显式指定章节标题与顺序"的插件。取数失败只留 Warning 日志、回调兜底页（`HelpCatalogService.cs:227-257`）；
3. **兜底自动生成页**（`BuildAutoPageMarkdown :393-424`）：用注册期已有的 `[Display]` 元数据（名称 / 分类 / 描述）+ 端口表生成一页。**参数表刻意不复制**（`:389-392` 注释）：参数以插件自己的配置界面为准，抄一份到手册里必然漂移。

优先级实现即"查到一个就停"（先内嵌、再接口、最后兜底），保证目录里没有空节点。

### 3.3 目录在启动自检链里合并；正文按需读取与渲染

- 自检项 `HelpCatalogCheck`（`Name` = "帮助手册合并"，`HelpCatalogCheck.cs:32`）在 `Task.Run` 里调 `HelpCatalogService.Build()`；**失败仅 Warning、放行**（`:46-50`）——帮助读不出来只影响查手册，不该把人挡在主界面外（与插件扫描、HALCON 自检同口径）。
- 注册顺序 `App.xaml.cs:94-102`：`PluginScanCheck` → `HelpCatalogCheck` → `CommunicationCheck`。必须排在插件扫描之后：分组按插件注册元数据（`ToolItemModel.Category` / `Name`）形成，且**此刻插件程序集已在内存**，读内嵌手册是顺手读几个资源流，不必二次 `LoadFrom`（二次加载同一个 DLL 会多占程序集并锁文件——"产物陈旧"那类坑的老朋友；`HelpCatalogCheck.cs:12-19` 注释）。
- `Build()` 只登记"每页标题 + 取数口"（`HelpPage.LoadMarkdown`，`HelpModels.cs:73`）；正文/图片等用户点开才取（`HelpViewModel.ShowPage :224-240` 才第一次调用 `LoadMarkdown`）。启动只多花"每页读一次拿标题"的小 IO（`HelpCatalogService.cs:33-36`）。
- 服务走工厂显式传依赖注册（`App.xaml.cs:363-368`），弹窗注册名 `"HelpView"`（`:369`）。弹窗打开时目录若未合并（自检项只剩警告的情形）**就地补一次 `Build()`**（`HelpViewModel.OnDialogOpened :360-372`），不给用户看空窗口。

### 3.4 界面（CHM 观感）的几处刻意取舍

- **正文按需渲染 + 逐页缓存**：`Dictionary<HelpPage, (FlowDocument, string)> _renderCache`（`HelpViewModel.cs:47-52`），切回已看页不重新解析；改字号清缓存重渲染（`ApplyFontSize :331-343`——字号进了 `FlowDocument` 的字号属性，不清就是新旧混排）。缓存存的是"**文档 + 该文档对应的 markdown**"这一对，不是只存文档：打印要重新渲染一份、用的必须是当前页正文，正文另存单个字段的话，"看 A → 看 B → 回退到 A（命中缓存）→ 打印"就会打出 B 的正文而标题写 A——**审查发现并按此修掉**，探针补了一条"回退到已看过的页（缓存命中）"断言盯它。
- **"上一步"是页的历史**，不是树的选中历史（`_history :46`、`GoBack :200-222`）：回退时目录选中态同步跟着走。分组/插件节点只展开、不换正文（`OnSelectedNodeChanged :184-198`）。
- **打印"另渲染一份"**（`Print :311-329`）：打印要重设 `PageWidth/PageHeight/ColumnWidth/PagePadding`，直接改屏幕那份会把阅读位置与排版一起弄乱；用 `PrintDialog.PrintDocument` 打临时文档。
- **隐藏目录记住宽度**：目录列宽 `TocColumnWidth` 与 `ColumnDefinition.Width` 双向绑定（`HelpView.xaml:380`、VM `:106-123`）；隐藏时宽度归零但记账 `_lastVisibleTocWidth`，再点回来是用户刚才拉的宽度（`ToggleToc :163-178`）。
- **字号三档**（小 12.5 / 标准 14 / 大 17，`:37-42`）：下拉绑"档位名"而不是数字；忽略 ComboBox 初始化期写回的 `null`（`:142-151` 注释里写明了这个静默坑）。页脚状态栏把合并摘要与快捷键一起写出来（`StatusText :100`）。
- **按插件名打开预留**：`OnDialogOpened` 支持参数 `plugin`（`:383-393`），供将来"流程步骤右键帮助 / 配置窗 ? 按钮"带名打开；当前无调用方（见「六」）。
- 视图不含 ListView/GridView（目录树是 TreeView），不触发 AGENTS.md §6 的 R19~R22 约束；壳层菜单变更由 `UIThemeSmokeTest` 的 Shell 全树实例化覆盖（见「四.3」）。

### 3.5 渲染器自研（Markdown 子集 → FlowDocument），不引第三方包

- 支持子集：标题 / 段落 / 无序·有序列表（可嵌套）/ 表格 / 代码块 / 引用 / 分隔线 / 粗体·斜体·行内代码 / 链接 / 图片 / 反斜杠转义（`MarkdownToFlowDocument.cs:14-17`）。刻意不支持：脚注、HTML 块、引用式链接、任务列表——出现时按普通文字渲染（`:28`），**不会渲染成空白**。
- 三个理由（源注释 `:19-26`）：① 本仓 NuGet 还原受代理限制（`VisionMaster.csproj` 里 Watson 那段注释同源），Markdig / WebView2 这类新包拿不到；② 渲染目标是 `FlowDocument` 而不是 HTML——WPF 打印与分页直接白送（"打印"按钮就是 `PrintDialog` 打这份文档），内嵌浏览器方案还多一层 airspace 问题；③ 手册内容是自己写的 md，按需支持即可。

### 3.6 分组与计数口径

- 分组沿用注册元数据的分类（`HelpCatalogService.cs:171`），与算子工具箱分类逐字一致；四张插件表合并成一棵（模块 / 相机 / 激光 / 运动，`:122-125`）——驱动插件（不实现 `IVisionPlugin`）同样有配置界面，用户在帮助里不该找不到（`:112-114` 注释）。
- **内置流程节点单独计数**：If/While/For/Break/Continue/Return 照常列进目录，但不算插件（`:155-162`），摘要分开表述（`:140-141`），否则摘要会写成"插件 44 个"、与实际对不上。
- 分组显示顺序表驱动（`CategoryOrder :56-61`，表外分组按 zh-CN 排序排后面 `:145-149`）；插件名按 zh-CN 排序（`NameComparer :49-50`）。
- 无手册的插件节点带「自动生成」角标（`:182`），自带手册的不带（探针有断言，见「四.2」）。
