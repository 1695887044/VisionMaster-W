# 2026-09-24 Modbus TCP 字节序可配置化（读写两侧同源跟随配置）

## 一、需求

> 用户原话：「我给 Modbus Tcp 加个一个字节排序 CDAB 或者 ABCD，请更新之后的解析数据方法」

表面是「加个下拉 + 改解析」，实际排查后发现是三件事：

1. `ModbusTcpConfig.ByteoRDER` 是个**死字段**——从没下发到 `ModbusTcpNet`，也从没参与解析，`Clone()` 还漏拷贝（克隆一次配置就丢字序）；
2. 真正的「解析数据方法」是 [HslHelper.ConvertTo<T>](file:///e:/VM/VisionMaster-W-master/Communication/Communications/Core/HslHelper.cs#L103)，它**硬编码 ABCD**；
3. ★ 更关键：**写侧走 HSL 设备的 `ByteTransform`，读侧走 `HslHelper`**，两条链路各认各的字序。HSL 的 `ModbusTcpNet` 构造函数里默认 `new RegularByteTransform(DataFormat.CDAB)`，而读侧是 ABCD → **32/64 位读写不对称**。16 位之所以一直没暴露，是因为 HSL 的 `ByteTransDataFormat2` 把 ABCD/CDAB 归到同一分支（退化等价）。

这正是 [2026-09-15-Modbus字节序颠倒修复.md](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-15-Modbus字节序颠倒修复.md) 的「已知边界 1」。

### 字节序语义（实现依据）

命名含义 = 「逻辑值字节 A(最高)~D(最低) 在**线路上**的排列顺序」，故「线上字节 wire → 逻辑大端字节 V」的换算为：

| 配置 | 换算规则 | 32 位示例（逻辑 0x12345678） |
|---|---|---|
| ABCD | `V = wire` | wire = `12 34 56 78` |
| BADC | 相邻两字节两两交换 | wire = `34 12 78 56` |
| CDAB | 相邻两个 16 位寄存器整体倒排 | wire = `56 78 12 34` |
| DCBA | `V = reverse(wire)` | wire = `78 56 34 12` |

16 位自动退化：ABCD≡CDAB（`V=wire`）、BADC≡DCBA（`V=reverse`）——与 HSL `ByteTransDataFormat2` 的分支一致。8 字节亦逐项比对过 HSL `ByteTransDataFormat8`，全部吻合。

⚠ **两套枚举顺序不同，绝不能强转**：

| 索引 | `ByteOrderFormat`（本项目） | `DataFormat`（HSL） |
|---|---|---|
| 0 | ABCD | ABCD |
| 1 | DCBA | BADC |
| 2 | BADC | CDAB |
| 3 | CDAB | DCBA |

序号强转会静默错位（DCBA ↔ BADC 直接互换），所以 `HslHelper.ToDataFormat` 必须**按枚举名 switch**。

## 五、已知边界

1. **32/64 位读写不对称已消除**：写侧 `ByteTransform` 与读侧 `ConvertTo` 现在同源跟随 `config.ByteOrder`。
2. **`SerialConnection`（Modbus RTU）同样存在读写不对称，本次未修**：HSL 的 `ModbusRtu` 默认 `ByteTransform = CDAB`，而串口读侧沿用 ABCD。待 `SerialConfig` 补字序字段后统一（现已在 `SerialConnection.ByteOrder` 的 XML 注释里标注 ⚠）。
3. **顺带修掉一个既有 bug**：`HslHelper.ConvertTo<T>` 原先没有 `TypeCode.Int64` / `TypeCode.UInt64` 分支，落到 `_ => default`，导致 **long / ulong 类型变量恒解出 0**（`MinByteCount` / `RegisterCount` 都按 8 字节 4 寄存器读，数据读回来了却解不出值）。
4. **落盘键名保留历史拼写 `"ByteoRDER"`**，代码属性名为 `ByteOrder`。Newtonsoft 反序列化默认大小写不敏感，旧文件仍可命中；新文件写出的仍是 `"ByteoRDER"`。
5. **存量连接的默认值变化**：默认值取 CDAB。用户现有连接 `Conn_014013` 在方案文件里显式存 `"ByteoRDER": 0`（= ABCD），不受默认值影响；若某条老连接**没有**存过该键，其 32 位变量读取会由 ABCD 变为 CDAB，需在 UI 手动切回 ABCD。
6. 未做「字节序变更时自动重连/重下发」：`ByteTransform` 在构造时下发，改配置后需重连该连接才生效（与其他连接参数的既有行为一致）。
