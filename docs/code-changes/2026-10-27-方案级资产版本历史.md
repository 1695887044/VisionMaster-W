# 方案级资产版本历史（`<方案目录>\Logs\operations.db`）

## 当前状态

资产版本历史从"只躺在 `.vms` 里"改成**双写 + 并读**：

- 写：每次 `AssetVersionLog.Append` 除了进 `.vms`，同时写 `<方案目录>\Logs\operations.db`；
- 读：`AssetVersionLog.Of` **库优先、`.vms` 兜底**，按 RecordId 去重、时间倒序。

效果：每个资产的历史从 **50 条上限**变成 200 条（库的保留上限），且不再随方案文件膨胀；
老方案（历史只在 `.vms` 里）照样看得到。

## 已做

### 1. 契约（`Core.Interfaces/Operations/AssetVersionEvent.cs`）

- `AssetVersionEvent`：版本事件的传输对象。
  为什么要在契约层再定义一个：版本记录本身是 `VisionMaster.Models.Assets.AssetVersionRecord`（Core 层），
  而 Sqlite Provider 只允许出现在 `Core.Database` 层，两边不能直接引用。
- `ISolutionAssetHistorySink`：`Append` / `Read` / `DatabasePath`。
- `AssetVersionSinkHost`：进程级出口（与 `SoftwareOperationLogHost` 同一手法），`SafeAppend`/`SafeRead` 吞异常。

### 2. 实现（`Services/Core.Database/SqliteAssetHistoryStore.cs`）

- 表 `asset_events`（`record_id` 主键）+ 索引 `(asset_id, ts_utc)`。
- 路径由 `Func<string?>` 惰性取方案根目录——切方案不用重新装配。
- **不用 WAL**：现场方案常放共享盘，SQLite 在 SMB 上 WAL 不可靠。
- 每个资产保留最近 **200 条**（远高于 `.vms` 的 50），超出按时间删。
- **fail-open**：建库/写入/读取失败只 Warn，不影响资产操作；没有方案时静默停用。

### 3. 接线

- `App.CreateShell`：`AssetVersionSinkHost.Current = new SqliteAssetHistoryStore(() => SolutionIdentityHolder.SolutionRoot, ...)`。
- `AssetVersionLog.Append`：加一条双写（**一处改动覆盖全部 8 个调用点**，不用逐个改 `ProjectAssetService`）。
- `AssetVersionLog.Of`：改成合并读。

### 4. 为什么先双写、不切停写

`.vms` 里那份仍是"方案自带的历史"，老方案与 `.vms` 单独拷走的场景要靠它。
真正切读/停写是第三步，前提是界面已改读库；现在停写会让"只拷 `.vms` 走"的方案丢历史。

## 验证

探针新增 `RunSolutionAssetHistoryChecks`，10 条断言全过：

- 写 60 条 → `.vms` 按既有规则截到 **50**，合并读是 **60**（库补齐了被截掉的 10 条）；
- 顺序正确（最新在前，v60 → v1）；
- **重开方案**（`.vms` 只剩 50）后仍是 60 条；
- 库不可用时回落到 `.vms`（老方案照样看得到「导入」那条）；
- 没有方案时写历史**不抛**、对外报告「没有库」。

`tools\run_gates.ps1`：**14 步全绿**（FlowCanvasChecks 4014 / ScadaChecks 3138）。

## 未做 / 已知边界

- **界面仍读合并结果**（`AssetVersionLog.Of`），所以资产页版本页签现在能看到 60 条——但分页/虚拟化没做，
  200 条时列表会很长（`MaxHeight=240` 自己滚动，暂时可接受）。
- `.vms` 仍在写（双写）。彻底停写是第三步，需先确认"只拷 `.vms`"不再是支持的用法。
- 库的清理只按"每资产 200 条"，没有按时间清理（版本历史是长期凭证，不该按天删）。
- 版本文件本体（`Assets/Versions`）的保留口径**已自动对齐**：`PruneVersionFiles` 读的是
  `AssetVersionLog.Of(...)`，而它现在返回合并后的记录（最多 200 条），所以文件保留数跟着变成 200。
  代价是单资产最多 200 份文件本体——这是"能回滚到更早版本"的必然成本，不是 bug。
