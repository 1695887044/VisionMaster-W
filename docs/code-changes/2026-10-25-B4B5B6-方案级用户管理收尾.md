   现象：四次闸门运行里三次红、受害者各不相同（两次 `前置：假设备命令失败后进入安全停机`+`★底层仍报警时清报警不放行`，一次 `★运动中 Home 被拒`），每次空载单跑都是 `3672/0`。
   排查：先把等待从 2s/5s 提到 20s——**无效**（仍红），说明不是"慢"；再把 `Enqueue` 返回值与"命令是否跑完"写进断言明细，下一次红直接打出
   `Enqueue=Rejected_NotConnected 完成=False`。
   **根因**：`MotionDeviceBase.Connect()` 只表示"开始连接"，状态真正到 `Online` 之前 `Enqueue` 一律回 `Rejected_NotConnected`（产品自己的提示原话就是"刚连接时请稍候一拍再下发运动"）。而断言助手 `EnableAxis(card, axis)` **吞掉了 Enqueue 返回值**，于是"连接未就绪"被静默吃掉：Enable 没执行、随后的 Move 也被拒，断言看到的是 `状态=Online`（因为压根没执行），却像是"状态机没走到"。
   **修法**：在 `EnableAxis` 入口 `WaitFor(() => card.State == Online, 5000)` 再下发。一处改动覆盖所有同类调用点；等待上限 5s，条件一满足就返回。
   **验证**：修复后连续两次全量闸门 **14 步全绿**（此前 4 次里 3 次红）。

## 五、踩过的坑

1. **`SolutionSessionChecks.cs` 被批量替换改坏**：上一轮用 `String.Replace` 改 `Issue(...)` 调用，留下了"半行新、半行旧"的悬空语句（`new[] {...}, ScadaRole.Operator, false);`）和未定义变量（`okRedeem`/`general`/`grant`）。教训：**批量替换后必须编译**，而这份文件当时从未编译过。
2. **`Issue` 的命名参数与位置参数混用报 CS1744**：把 `role` 从第 2 位删掉后，`Issue("op1", "G-lineop", …)` 与 `groupId:` 同时出现就冲突。最终统一成"全位置参数 + 尾部可选命名参数"。
3. **`M2-07c2` 一开始假绿**：补上权限后仍走 `E_NOT_OPERABLE`（图元没配动作），断言 `!result.Ok` 也能过。必须给图元加一条 `Pressed` 钩子，否则"权限放行"这件事根本没被验证。
4. **`M2-13c` 被权限闸先拦**：运动动作的兜底 Key 是 `AxisJog`，会话只有 `ViewRuntime` 时在 `E_POLICY` 就结束了，白名单断言等于没跑。给会话补 `AxisJog` 才测到白名单。
5. **`ListOnline` 与 hello/caps 不同源**：一个用签票时冻结的 `session.ReadOnly`，一个用 `IsSessionReadOnly`（现算）。运行期关总闸后两者分叉，表现是"列表说能点、其实不能"。SW5-d 就是钉这个的。
6. **`run_gates.ps1` 的中文计数正则对 `ScadaWebChecks` 永远不命中**：它打印 `RESULT: N PASS / M FAIL`。不单独给正则，闸门会记成 `exit 0 (no summary line)`——**看起来绿、其实没数**。
7. **B5 计划里的"删旧文件"是错的**：`ScadaUserManagerView` 不是旧页面，是新页面的「账号与用户组」页签内容。删之前必须先读 `UserManagementView.xaml` 的引用。
8. **`powershell -Command` 传长中文串会解析炸**（`子表达式中缺少右")"`）。改法：中文放 UTF-8 清单文件，脚本只读文件、按 `@@@` 分隔配对做 `String.Replace`（R2/R3）。
9. **"令牌化"要抵住"顺手改好看"的冲动**：`#909399` 在库里已有更深的 `ScadaSecondaryTextBrush`(#66708A) 和更浅的
   `ScadaFaintTextBrush`(#A8ABB2)，看起来"并进现有档位更干净"——但那是**改颜色**，会让 B0 基线的视觉对照失效。
   正确做法是新加一条 `ScadaPlaceholderTextBrush` 保持原值，并在注释里写清它为什么不是那两档。
10. **闸门里的时间敏感断言不能只看"空载绿"**：运动那两条断言在空载 3672/0、在闸门里 3670/2，两次复现。
    判断"是负载还是竞态"的判据是**同一条 exe 两种条件下结果不同**；只有一种条件能绿，就不能写"这是负载问题"。
    **更关键的教训**：把等待从 2s 加到 20s 是**无效**的——真正的病是"命令压根没进队列"，加时间只会让失败更慢。
    正确的下一步不是调大超时，而是**把中间结果写进断言明细**（`Enqueue` 返回值 + 是否完成）。加了这两项之后，
    下一次红一次就定位到 `Rejected_NotConnected`。
11. **并行会话会锁住 `bin` 与 `Modules`**：`VisionMaster.exe` 在跑时，`dotnet build` 会同时失败在
    `VisionMaster\bin\...\UI.dll` 与 `Modules\Plugin.*.dll` 两处（`Directory.Build.targets` 按目录投递）。
    `-o` 重定向输出也绕不过 `Modules` 那一跳。**只能等它退出**，不要杀别人的实例。
