### 1.2 四板斧（B0-B4 覆盖面）

- **B0 差分对拍**：手写"参考解释器"（纯递归；语义来源 = 编译产物注释——If 首真分支/Else 兜底、For 计次、While 先判后跑、Break/Continue 本层消化、Return 全局终止、Parallel Sequential 平铺），对**随机生成的图**跑真引擎，逐元素比较：执行 trace + 编译判定（这张图该不该编译失败）+ 终值（StressVar）+ 终态（跑过的叶子必须落 Success）。
- **B1 判断（真值表穷举）**：If 两分支 true/false；If/ElseIf/Else 三链 TT/TF/FT/FF（只该走第一条真分支、全假走 Else 兜底）；条件形态（常量 / 变量比较 / 算术）；无兜底全假 → 判断成功、无事可做；嵌套两层（内层无兜底且 false → 内层不跑、外层后续照跑；内层有 Else → 走兜底）；编译门禁——缺条件（If 非兜底分支 / ElseIf / While）必须编译失败且**文案指向具体节点**，Else 不写条件是合法（`RequiresExpression=false`）。
- **B2 循环（表驱动边界）**：For 1 / 3 / 0 圈；`LoopCount` 连线覆盖 `DefaultLoopCount`；`For.Index` 在循环体内可读（0 基递进）；循环后节点只执行一次；While 先判后跑（初值即假 → 0 圈；初值 3 → 3 圈 + 终值 0）；Break 只跳出内层、Continue 只跳本圈剩余；嵌套两层循环 break 组合穷举；Return 在循环体内 → 全程终止（trace 到此为止 + 流程态 Return）；顶层 Break/Continue → Warn「无循环归属」+ 后续照跑；循环套并行 / 并行套循环（保序 + 多重集）。For 负值与超上限沿用既有断言（2026-10-05），本批不复述。
- **B3 并行（等价与压力）**：同一张图 Sequential / Parallel 两模式——**trace 多重集相等 + 分支内子序列保序 + 终态集相同 + 容器 Success**（"并行不改变语义"的核心不等式）；分支数 2 / 4 / 8（8=建议上限）；空分支不报错、单分支平铺退化；压力图 4 分支 × 每分支 3 叶子（含嵌套 If + 每分支写不同名变量）**连跑 50 轮**（`TracePlugin.DelayMs=1` 把四条分支线程真叠在一起）——断言多重集 / 无异常 / 容器 Success / 父域变量终值稳定 / 无"同名写"冲突 Warn；失败聚合边界——分支内嵌套 If 的子分支业务失败被识别为分支业务失败（FailFast 取消兄弟 → Run 快速返回）、无异常上抛、失败步骤如实 Failed。
- **B4 分支/拓扑**：合法取数（分支内引用外层步骤输出）；非法嵌套取数（并行分支 A 的 If 子分支引用分支 B 内步骤）→ 编译失败、文案含「[跨分支取数]」；版本链（分支内增/删步骤、容器新增分支、容器改名 → Version++；**分支名不自动推**——R26 口径）+ 随机图抽样；两种模式的顶层 Break/Continue 对照断言（`:780-803`）。

### 1.3 比较口径（★ 后人别误读 ★）

- 确定性图（全顺序 / Parallel 节点用 Sequential 模式）：trace **逐元素全等**。
- Parallel 模式：只比**排序后的多重集 + 分支内子序列 + 终态集**（跨分支顺序本质不确定；分支内部因各自跑 `RunSequence` 必然保序，用同分支 Tag 前缀分组取子序列）。
- 失败 / 取消的图不做全 trace 对拍，只断集合关系 + 终态 + 日志关键文案。
- B0 随机图的 Parallel 节点**一律 Sequential 模式**（参考模型按声明序平铺 == 引擎一期平铺语义）——由此换来逐元素全等的判定强度；Parallel 模式的等价关系由 B3 单独钉（见 §四.4）。
- 参考模型遇见不认识的条件表达式**响亮抛异常**（生成器与解释器脱节必须立即可见，不让对拍变成自欺）。

### 1.4 看门狗（不许挂死套件）

- 每个 case `Task.Run + Wait(6s)`；到点先用**协作取消**打断（Cancel 令牌——While / For / RunSequence 每个迭代 / 节点都会检查），记 finding 而不是让套件挂死。
- 永久保留一条**看门狗自检**（`:486-493`）：三层 9999 计次循环 → 2 秒内被协作取消打断并如实记超时（安全网自己也有守卫：看门狗坏掉时，随机图一旦生成"长循环"就是挂死整个套件）。
- 处理纪律（写进文件头）：参考模型与引擎不符时**先判性质**——参考模型写错改参考模型（detail 里写依据）；引擎与设计文档不符 → 报 finding + 图 JSON，**不改引擎**；两者都对但口径未定义 → 记"口径未定义"并如实报告。

### 1.5 随机图生成器（两条不变量 + 约 1/4 故意非法）

- ① While 条件恒为 `StressVar > 0`，且循环体首步必是 `Dec`（StressVar 单调递减 ⇒ 必然有界）；② 全图只有 `StressVar` 这一根变量被写（⇒ 不触发同名写冲突）。

## 四、未决口径（别丢）

1. **Sequential 模式下并行分支顶层的 Break/Continue 归属外层求解器**（一期平铺语义，v2 §3.7/§4 已声明）：顶层 → 清状态 + Warn + 后续照跑；Parallel 模式下则是"只终结本分支 + 分支级 Warn"——**同一张图两模式行为不同是设计使然**，B4 已用两条对照断言钉住。
2. **直调 `CompiledFlow.Run`（断言宿主口径）不做轮末容器态上浮**（`EscalateContainerFailures` 在 `FlowEngineService` 轮末，2026-10-05 落地）：B3 只断"FailFast 取消兄弟 + 步骤态如实 + 不上抛"，容器终态留给引擎服务侧既有用例。
3. **Parallel 模式的 trace 顺序本质不确定** → 差分对拍只覆盖顺序图；若将来要"按分支的并行差分"，需引擎侧新增观测钩子（当前不存在，属设计空白而非 bug）。
4. **B0 随机图的 Parallel 一律 Sequential 模式**（参考模型按声明序平铺），换来逐元素全等判定强度；Parallel 模式的等价关系交给 B3 单独钉。
