# 2026-10-23 配方功能 V4 · 实施与验证记录

- 版本：**V4.0**
- 状态：已实现、已构建、已跑断言
- V4 范围：**SCADA 动作表「应用配方」**——组态按钮可走 `RecipeService.Apply`，不绕过配方服务

## 一、V4 交付内容

### 1.1 领域接口

`Scada/Models/IRecipeCommandSink.cs`：
- `bool TryApply(Guid recipeId, string? recipeName, out string? error)`
- 与 `IScadaFlowRunner` / `MotionActionExecutor` 同一分工：领域层只认能力，不认识配方服务实现。

### 1.2 动作类型

`Scada/Models/ScadaActionType.cs`：
- 末尾追加 `ApplyRecipe = 23`（**只许末尾追加**，数值已可能落进 `.vms`）。
- `DisplayName` → 「应用配方」。
- `IsDangerous` → true（换配方会改运动/视觉参数，确认框走红色语气）。
- `PendingReason` → null（已接通；未注入 sink 时由分发器报「未接入配方服务」）。

`Scada/Models/ScadaAction.cs`：
- 新增 `TargetRecipeId`（Guid，空=按名兜底）、`TargetRecipeName`、`HasRecipe`、`BindRecipe(...)`。
- `Detail` / `Describe()` 增加「应用配方 → 名称」；未选配方时给「应用配方（未选配方）」。

### 1.3 分发器

`VisionMaster/Services/ScadaActionDispatcher.cs`：
- 新增可选构造参数 `IRecipeCommandSink? recipes = null`（追加在最后，旧 7 参构造不变）。
- `Execute` 增加 `case ApplyRecipe` → `ExecuteRecipeAction`。
- 三档结果：
  - sink 未接线 → `Skipped`「未接入配方服务」；
  - 未选配方 → `Skipped`「还没选配方」；
  - `TryApply` 返回 false → `Skipped` 并带中文原因；成功 → `Ok`。
- 权限、运行闸、整单预检、回滚、终检、审计全部由 `RecipeService.Apply` 负责。

### 1.4 宿主接线

`VisionMaster/App.xaml.cs`：
- `ScadaActionDispatcher` 构造显式传入 `c.Resolve<RecipeService>()`。
- 不接的后果是 SCADA「应用配方」永远记一行「未接入配方服务」且不报错；所以显式接上。

### 1.5 断言

`RecipeChecks/Program.cs` 从 89 条扩到 **99 条**，新增：
- `ApplyRecipe` 枚举值 = 23 / 显示名 / 危险动作 / 已接通。
- `ScadaAction` 未选配方描述、绑定后 `HasRecipe`、描述含配方名。
- `RecipeService.TryApply` 按 Id 成功、按名成功、未知配方被拒。
