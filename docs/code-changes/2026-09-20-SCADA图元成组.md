## 一、需求与决策

### 1. 需求

S10 的定义原文是"图元对齐/分布/**成组**/锁定；多选框选"。S10-a/b 交了图层面板与多选/对齐/分布，S10-c 交了锁定，**"成组"是 S10 的最后一项**。

要解决的具体症状：**多选是"临时选择集"，不是持久分组**。框选五个图元、把它们挪到画面上别处、再点一下空白——选择没了，下次要动这五个还得重新框一遍（而且很可能框不全）。商用组态软件里这件事的答案是"成组"：这五个从此是一个整体，点中其中任何一个 = 选中整组。

**成组的边界要想清楚**：它**不是**几何约束。组员之间没有相对位置锁定、没有联动缩放——只是"选中时一起被选中"。这一点决定了整个实现只有**一个 Guid 字段**，不需要在画布上维护任何坐标耦合。

### 2. 决策清单 —— 领域层（s10d-1）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| G-1 | `GroupId` 的类型 | **`Guid`**，`Guid.Empty` = 未分组 | 与 `LayerId` 逐字同形（`ScadaLayer` 的归属也是 `Guid`）。领域层里"指向某个对象的关系"已经有了一套成熟写法，照抄不引入新概念 |
| G-2 | 是否落盘 | **落盘** | 组是**配置**，不是编辑器的临时状态。旧 `.vms` 里没有这个字段 → 反序列化后自然得到 `Guid.Empty`，**零迁移代码**（`Guid` 的默认值恰好就是"未分组"这个哨兵） |
| G-3 | 组自己有没有名字 | **不带名字**（本轮只做结构） | 商用软件里组名是为了"组模板/复用"，那是另一个功能（模板），不该塞进这一轮。没有名字就不需要"组对象"，组就退化成"一组共享同一个 Guid 的图元"——**没有组对象就没有生命周期问题** |
| G-4 | 是否允许嵌套 | **不允许，只一层**。两组再组合 = **合并成一个新组** | 嵌套组会让"点中一个成员该选中谁"变成一道递归题，也让删除/撤销的边界膨胀。合并的语义对用户更好理解："这几个和那几个，现在是一拨的" |
| G-5 | 成员删剩一个 / 指向不存在的组 | **不做清理** | 清掉 Guid 会让"撤销删除"回不到原组（撤销时把图元加回来，但它已经忘了自己属于哪一组）。**宁可留一个只有一员的组**，也不要在删除路径上顺手改数据 |
| G-6 | 与 `LayerId` 的关系 | **两把独立关系**：`LayerId` 管**渲染**、`GroupId` 管**编辑**；**同组图元可以跨图层** | 分层是"什么时候画、画在谁上面"，成组是"点一下选中谁"。两者正交。若强行要求"同组必须同层"，就会出现"改图层归属顺手把组拆了"这种用户完全没预期的副作用 |
| G-7 | 组合是否筛掉锁定图元 | **不筛**（与 `TryAlignElements` **反着**） | 对齐/分布是**几何改动**，锁定的图元不该被动；而成组是**改关系**，锁定的图元照样可以被归进一个组（锁定保护的是"位置/尺寸不被改"，不是"不许被组织"）。解锁后就能整组拖走，这正是用户要的 |
| G-8 | 全员已同组时 | **空操作**：返回 `true`，**不产记录** | "点中一个组员就整组选中"，于是"选中一个组、再点一次组合"是最自然的误操作。判失败会让用户以为没组合上；产记录会让撤销栈里堆"什么都没干" |
| G-9 | 少于 2 个目标 | **拒绝**："至少要选中 2 个图元才能组合" | 一个成员的组与未分组**没有任何行为差别**，允许它只会让用户以为自己建了个组。这是本入口唯一的前置校验 |
| G-10 | 取消组合是否要求"选中整组" | **不要求** | 要求整组会把"把 A 从组里拿出来"变成"先选中整组、再取消组合、再重新组合剩下的"——三步操作。不要求则一步到位：选中 A，取消组合 |
| G-11 | 取消组合的数量口径 | 只算**确实有组**的（`GroupId != Guid.Empty`）；全都没组 → 空操作 | 与锁定那一对的端点口径逐字同源（C-3）。递进来 5 个而实际只有 2 个在组里，操作名必须写 2 |
| G-12 | 组 → 成员的索引 | **不建索引，线性扫描** `_elements` | 画面图元数量级是几十到几百，一次 `Where` 是纳秒级；而索引要跟着增删/撤销/反序列化维护，是**确定的复杂度换不确定的收益**。`FindElement` 建索引是因为它被运行态逐帧调用，成组没有那个调用频次 |

### 3. 决策清单 —— 展开点（s10d-2）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| E-1 | 展开点写在哪 | **不写进 `SetSelection` 内部**，只在"点选"三条路上做：① `OnSelectedElementChanged` 的"换掉整份选中"分支；② 左键"换掉整份选中"分支；③ 左键 Ctrl/Shift 加选分支 | 见下 §4 |
| E-2 | 为什么不能写进 `SetSelection` | 框选（`CommitRubberBand`）也走 `SetSelection`，它的语义是"**框住谁就是谁**" | 在内部展开的话，用户**再也没法用框选只挑出组里的一个**。`PruneSelection` 收缩出的结果也不该被重新撑开（那会让"删掉组里一个"变成"删掉整组"） |
| E-3 | 被点中者在集合里的位次 | **排首位** | `SetSelection` 拿首项当主选中。若被点中的 B 排在整组的第三位，就会出现"**点的是 B、属性面板显示 A**" |
| E-4 | UI 隐藏的成员 | **不并进来**（判据 `IsElementShown` / `IsElementVisible`） | 选中集合里不该出现"画面上看不见的东西"——用户看不到它，却会跟着被拖动/删除 |
| E-5 | 锁住的成员 | **照并** | 单击本来就选得中锁住的图元（锁定只挡编辑，不挡选中，见 S10-c 边界 5）。若这里把它滤掉，"组里混锁"就会变成"点一下选中一半"，比不展开更迷惑 |
| E-6 | 视图模型侧是否也展开 | **是** | `SelectedElement` setter 的契约写明"与画布逐字对齐"，且它与画布是双向绑定的。只在一侧展开 → 画布撑成整组、VM 还是单个，属性面板与菜单会显示错的东西 |
| E-7 | 判据从哪来 | 只有 `ScadaPage.GetGroupMembers` **一处**；视图侧**不**自己按 `GroupId` 再筛一遍 | 两处判据 = 迟早不一致（比如将来给组加"暂时挂起"的状态）。这是 D2"描述符是唯一真相"的同一条纪律在关系上的投影 |

### 4. 为什么"展开"必须放在点选路径上，而不是选中集合的入口里

这是本轮**最容易做错的一处**，值得单独说清。

`SetSelection` 是选中集合的**唯一写入口**，看起来很自然："要展开，就在写进去的地方展开"。但 `SetSelection` 有三个调用方，它们的语义**不一样**：

| 调用方 | 语义 | 该不该展开 |
|---|---|---|
| 单击图元 | "我要动这一拨" | **要**——点中一个组员就是选中整组 |
| Ctrl/Shift 加选 | "把这一拨也加进来" | **要** |
| 框选（橡皮筋） | "**框住谁就是谁**" | **不要** |
| `PruneSelection`（图元被隐藏/删除后收缩） | "把已经不在的剔掉" | **不要** |

如果展开写在 `SetSelection` 内部，第三条就被毁了：用户想"只动组里的这一个"，于是小心地框住它——结果整组被撑进选中。**这是一个用户没有任何办法绕过的死角**（框选是他唯一的"只选一个组员"的手段）。

所以本轮的写法是：**把"展开"做成点选路径的一个前置步骤**，在调用 `SetSelection` 之前把集合算好。`SetSelection` 自己保持"给谁就是谁"的纯粹语义。

这也解释了 E-6：VM 侧要在 `SelectedElement` setter 里展开，而不是在 `SelectedElements` setter 里。前者对应"点中一个"，后者对应"程序化给一份集合"（框选、收窄、批量操作）——**两个 setter 恰好就是两种语义的分界**。

### 5. 决策清单 —— 菜单二态项与判灰（s10d-3）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| M-1 | 命令数 | **一条 `GroupElementCommand` 管两向** | 组合与取消组合除了"往哪个方向写"，标题/图标/判灰/落点完全一样。拆两条命令就是两份复制品，将来改一处要改两处（与 C-1 同一理由） |
| M-2 | 标题与图标跟谁 | 跟**主选中**的分组状态（`IsMainSelectionGrouped`） | 菜单每次弹出即重建，"组合之后菜单自己翻成取消组合"是免费得到的 |
| M-3 | 图标跟动作不跟状态 | `GroupIcon = U+F247`（object-group）/ `UngroupIcon = U+F248`（object-ungroup） | 与 C-8 同一条：图标和标题都描述"点下去会发生什么"。标题写"组合"而图标画"拆开"（暗示当前状态）会自相矛盾 |
| M-4 | 菜单排位 | **插在"锁定/解锁"与"删除"之间**（第六栏） | 与锁定同属"改图元之间的关系/保护状态"（上面三栏只换个摆法）。**末位留给唯一不可逆的破坏性动作**（删除） |
| M-5 | 标题里要不要写数量 | **不写** | 数量落在撤销记录的操作名里（`组合 3 个图元`）。菜单标题是"要做什么"，不是"要动几个"——写数量会让标题长短随选中数抖动，观感不稳 |
| M-6 | `CanGroupSelected` 的判据 | `CollectPresent(page).Count >= 2` | 与 G-9 的前置校验**同源**。两边不一致就会出现"亮着但点了没反应" |
| M-7 | `CanUngroupSelected` 的判据 | `CollectPresent(page).Exists(e => e.GroupId != Guid.Empty)` | 与 G-11 的数量口径同源。若按"选中了几个"判灰，全都没组时它也会亮着——点了没反应，用户只会记成"这一项坏了" |
| M-8 | `CanToggleSelectedGroup` 怎么算 | 走哪一边由主选中决定，**可用性就按那一边算**：`IsMainSelectionGrouped ? CanUngroupSelected() : CanGroupSelected()` | 与 `ToggleSelectedGroup` 的分支**逐字同构**。只要这两处的判据是同一个表达式，就永远不会出现"亮着但点了没反应" |
| M-9 | 动作传哪一份集合 | `CollectPresent`（**不筛锁定**，见 G-7）；判据与动作传**同一份** | 见 M-6/M-7 |

### 6. 口径沉淀

- **"关系"和"属性"要分开看**：`GroupId` 与 `LayerId` 都是"指向别处的关系"，两者正交且互不触发。往描述符里塞"组"是错的（D2：描述符描述的是**图元自己的样子**，不是它和别人什么关系）——这与 `IsLocked` 不进描述符是同一个判断。
- **展开只在点选路径上做**：集合写入口要保持"给谁就是谁"的纯粹语义。**一个写入口被多个语义不同的调用方共用时，"聪明的自动补全"必然害死其中一方**。
- **两条命令合并成一条时，判据也必须合并**：`CanToggleSelectedGroup` 与 `ToggleSelectedGroup` 必须是同一个三元表达式，否则就是"亮着但点了没反应"的温床。
- **删数据要留手**：成员删剩一个时不清理 `GroupId`——因为撤销要能回到原组。**为了"看起来干净"而破坏可撤销性，是把用户的信任换成了一行整洁的数据**。

## 四、已知边界

1. **组没有名字**：G-3 的取舍。用户看不到"这个组叫什么"，菜单与属性面板也不显示组信息。当"组"需要被复用时（组模板）才需要名字，那是另一个功能。
2. **不支持嵌套**：G-4。两组再组合 = 合并成一个新组，组里没被选中的成员留在原组（这一点有断言钉住）。
3. **成员删剩一个 / 指向不存在的组不做清理**：G-5。会留下"只有一员的组"与"悬空 GroupId"。代价是数据可能不"干净"，收益是**撤销删除能回到原组**。判据侧（`GetGroupMembers`）对此天然免疫——只有一员的组查回来就是一件，行为与未分组无差别。
4. **组合不筛锁定，取消组合也不筛**：G-7。混锁的组被整组拖动时，**锁定的成员原地不动、其余照走**——这是 s10c-4"多选逐元素判色"的自然结果（可编辑的才动），不是 bug，但真机上要确认用户读得懂（金色外框的那几个没动）。
5. **展开只在点选路径上做，框选不展开**：E-2。这带来一个**用户可见的不对称**：单击一个组员 = 选中整组，框选一个组员 = 只选中它。这是刻意的（框选是"只挑一个"的唯一手段），但需要在真机上确认不造成困惑。
6. **隐藏成员不并进选中**：E-4。于是"组里有一个成员被隐藏了"时，点中另一个成员 → 选中的集合**少于**整组。拖走的是看得见的那些。
7. **`GroupId` 不进描述符**：D2。它是**编辑期关系**，不是图元"自己的样子"。与 `IsLocked` 同一判断。代价：属性面板不显示组信息（本轮也没打算显示）。
8. **组不参与运行态**：与 `IsLocked` 同（S10-c 边界 7）。运行态 `IsReadOnly = true`，点选本来就不给编辑，成组与否无差别。
9. **画布"选中即整组"无自动化兜底**：`ExpandPointSelection` 在 `ScadaCanvas` 与 `ScadaEditorViewModel` 里都是 **private**，且 `VM.Scada.Controls` 未开 `InternalsVisibleTo`。断言只能经 `SelectedElement` / `SelectedElements` 属性**间接观察**（本轮就是这么做的：`SelectedElement = e2` → 观察集合被撑成整组且 `e2` 在首位）。**画布侧那条路径（左键三处）本身没有被直接断言**，靠的是与 VM 侧共用同一份 `GetGroupMembers` 判据。
10. **SCADA 新文件仍未纳入版本控制**：`Scada/Models/ScadaAlign.cs`、`ScadaEditHistory.cs`、`ScadaChangeScope.cs`、`ScadaWriteGuard.cs`、`ScadaChange.cs`、`ScadaModelBase.cs`、`ScadaZMove.cs`、`VisionMaster/ViewModels/ScadaLayerViewModel.cs`、`ScadaMenuItem.cs`、`Views/ScadaLayerView.xaml(.cs)` 等仍是未跟踪状态。**提交需用户明确授权。**
11. **"组员身份"没有常驻视觉（刻意）**：画布上不给"这个图元属于某个组"加角标或虚线。理由是**商用软件也不加**——组是"点一下会带出一整片"的行为，用户只有在选中时才知道自己选中了什么；选中时整组的合并包围盒本来就会出现，反馈已经到位。常驻角标反而会在画面上堆一层与业务无关的标记（对比：锁角标是必要的，因为"拖不动"是一次没有反馈的失败）。若现场反馈"不知道这几个是一组的"，再考虑给整组加一条淡色虚线外框（仅选中态，与合并包围盒同址）。
