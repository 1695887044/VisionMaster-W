# 综合测试台方案与四处联调修复（2026-10-22）

## 背景

用户要求以“测试员”视角，用正运动 VPLC532R 虚拟卡、Modbus TCP 503/504、S7 102 与 `D:\C#\VM\Image` 图片，尽可能覆盖仓库里的算子插件，并设计组态。

产出：

- `解决方案\综合测试台.vms`：8 条流程 / 270 步 / 5 个组态页面 / 44 个变量
- `解决方案\综合测试台-说明.md`：测试矩阵、组态页图、运行方法与证据
- `_ScadaUiProbe --solution <vms>`：按方案里的 Scada 段逐页离屏渲染（本次新增的探针模式）

## 四处修复

| # | 现象 | 根因 | 修改 |
| --- | --- | --- | --- |
| 1 | 方案加载后运动卡一直“未连接”，必须手动点连接 | 宿主只在启动时执行一次 `ConnectAutoStart()`，方案在其后加载 | `VisionMaster\ShellViewModel.cs:850` / `:890` 在方案加载后调用 `ConnectMotionAutoStart()`；内部先 `EnsureSynced()` 再 `ConnectAutoStart()`（`:902`） |
| 2 | 写 `Meter_Value`（Modbus InputRegisters）没有本地拦截，等到 Socket 超时 | `IsReadOnlyArea` 只覆盖离散输入与 S7 输入映像 | `Core\Models\Variable\NetworkVariableModel.cs:330-339` 加入 `ModbusArea.InputRegisters`；两处写入错误文案补“输入寄存器” |
| 3 | Int16 变量写 1/7 后读回 0 | 值以 Int64（8 字节）写进 2 字节地址，低字落到后面的寄存器 | `NetworkVariableModel.TryWriteCore` 写入前按变量声明类型做标量转换（`Convert.ChangeType`，`InvariantCulture`） |
| 4 | 只读区提示与实际拦截范围不一致 | `CommWriteNowPlugin` 与 `NetworkVariableModel` 两处文案不同步 | 两处统一为“离散输入 / 输入寄存器 / S7 输入映像 I” |

## 已知边界

- 测试流程为 HTTP 触发而启用；主界面「循环运行」会并发跑所有启用流程，测试台不要点它。
- 虚拟卡到位后 `InPosition` 位不置位，`MotionWait` 可能超时；位置判据不受影响。
- VPLC532R 被驱动标成总线型，`轴回零` 走 `ZAux_BusCmd_Datum`；轴 0~5 是 Step Encoder，回零可能失败。
- 组态预览图是设计态离屏渲染（关闭编辑网格），运行态数值以绑定为准。
