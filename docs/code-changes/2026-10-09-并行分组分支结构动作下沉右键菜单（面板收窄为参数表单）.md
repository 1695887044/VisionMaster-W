## 一、裁决链与分工（为什么"分开"）

用户三问（这个视图有必要存在吗 / 为什么不可以右键直接添加 / 说下理由）之后，主会话给出的分工，并成为本批的口径：

| 动作种类 | 合适的位置 | 理由 |
| --- | --- | --- |
| **结构动作**：加 / 删 / 重命名分支 | **流程栏右键菜单**（就地、单步） | 产品里早有先例：If 容器的「右键 → 添加 ElseIf 分支 / 添加 Else 分支」在树上直接做（`VisionMaster\Views\ProcessView.xaml:680-692`，`IsIfNodeSelected` 控制可见性）。首版面板把分支名单整块搬进表单，是当初**漏补**这条既有路线 |
| **参数动作**：执行模式 / 失败聚合 / 汇合超时 + 语义解释（「继承全局（当前＝开/关）」、调试运行提示等） | **表单（弹窗）** | 语义属性需要说明文案与三态解释，菜单项放不下 |
| **菜单放不下的唯一项**：汇合超时 | 表单 | 数值输入无法用菜单承载 |

用户裁决「分开吧」→ 本批执行：**分支的增/删/改名从面板下沉到流程栏右键，面板收窄为"参数表单 + 分支只读总览"**。

## 三、最终口径（右键落在哪 → 出什么菜单 → 命令靶 → 选中/焦点）

| 右键位置 | 菜单 | 命令靶 | 选中/焦点 |
| --- | --- | --- | --- |
| 并行分组组头 | 父级 TreeView 菜单（含新增「添加分支」） | 当前选中组头（`SelectStep`） | 选中组头（原逻辑） |
| 并行分组分支胶囊 | 胶囊自带两项（重命名 / 删除本条分支） | **命中的那条 `StepCollection`**（`PlacementTarget.DataContext`） | **不选中、不改焦点** |
| 并行分支行**空白背景** / If·For·While 的分支卡片 | 不出菜单（事件被吃掉，与改动前一致） | — | 不选中 |
| 算子卡片（含分支内算子） | 父级 TreeView 菜单（原逻辑） | 当前选中项 | 选中该算子 |

**分支胶囊三态**（R25 的红线一条不少）：

- **左键** = 仍被拦（不选中 / 不派发双击 / 无弹窗；**箭头仍可点**，`IsBranchCardUnderMouse` 的 ToggleButton 豁免未动）；
- **右键** = 并行分组的分支出两项菜单、其余分支仍拦；
- **双击** = 仍不派发参数窗 / 条件窗。

**版本号纪律（三个结构命令）**：增 / 删分支**不手动 `Version++`**（FlowModel 订阅每个容器的 `Children` 集合，结构变更自己递增）；**只有改名必须手动推进**（`StepCollection.StepName` 不在 FlowModel 的监听面里）。

## 四、已按现实做的偏差（如实记录）

1. **改名命令是同步 `DelegateCommand<StepCollection?>` + `EasyDialog.ShowTextInputSync`**（不是 async + `ShowTextInputAsync().GetAwaiter().GetResult()`）：后者在 UI 线程硬阻塞等不到 `DispatcherPriority.Background` 排队的弹窗创建 → 死锁（`ProcessViewModel.cs:434-441` 注释留档）。
2. **新增可注入 `ShowFeedback`**：`Notifier.Show*` 内部直接取 `Application.Current.Dispatcher`，离屏断言宿主必 NRE——不改就没法断言上限 / 下限 / 空名的提示文案（默认实现另加了一道 `Application.Current == null` 空判）。
3. **分支级菜单只给并行分组的分支**：If/For/While 的分支若也放开，删 If 首分支 / For 唯一循环体会击穿容器不变量（For 的"一个循环体"与 If 的"至少一个 If 分支"是编译期与运行期都依赖的结构）。
4. **右键放行多一个条件"命中元素祖先链里有 ContextMenu"**：否则右键分支行空白背景会漏到父级 TreeView 菜单（正是 R25 要防的错靶）；代价是并行分支行空白区右键"什么都不发生"（与改动前一致）。
5. 取舍：组头「添加分支」到上限**只提示不置灰**（与 If 的「添加 ElseIf」同风格，让用户知道为什么点不动）。
