# 运行条只报当前流程、流程卡不显示运行态

日期：2026-10-20
现象（用户真机截图）：MainTask 与「新建流程」**同时**在循环运行，但
① 运行条只写「循环运行中 MainTask」；
② 流程导航里四张卡（GoHome / MainTask / 新建流程 / End）看不出谁在跑，状态点全是绿的。

两处根因不同，别当成一件事治。

## 一、运行条：绑的是"选中"，不是"在跑"

`Shell.xaml` 的运行条文字直接绑 `Workspace.CurrentFlow.FlowName`：

```xml
Text="{Binding Workspace.CurrentFlow.FlowName, TargetNullValue='未选择流程'}"
```

而本仓**允许同时跑多条流程**（单流程运行 / HTTP 触发 / 定时触发各开各的会话），
`MainRunState` 只反映"界面发起的整体运行"。于是：

- 两条在跑时，条上只写选中的那一条；
- 更糟的是**选中的那条可能根本没在跑**（切到别的流程看一眼，条上就写成它了）。

**修法**：新增 `ShellViewModel.RunBarFlowText`，数据源与 `AnyFlowRunning()` 同一份
（`FlowModel.RunState` 镜像，涵盖界面 / HTTP / 定时所有触发）：

| 在跑的条数 | 文案 |
| --- | --- |
| 0 | 回落到当前流程（与改造前逐字一致） |
| 1 | 报那一条（与当前选中无关） |
| N | `MainTask 等 2 个流程`，完整名单进悬停提示 |

`RunBarFlowToolTip` 在 N > 1 时列全名单。两者都是 `static` 纯函数
（`FormatRunBarFlowText` / `FormatRunBarFlowToolTip`），断言直接调，不必凑一个 Shell。
重算时机：会话状态变化（`OnSessionStateChanged`）+ 选中流程变化（`Workspace.PropertyChanged`）。

### 补记：**有两条运行条**，第二遍才补全

第一版只改了调试场景那条（`Shell.xaml`），真机切到「运行」场景后发现驾驶舱那条**也**错：

```xml
<!-- RunCockpitView.xaml:101（改前） -->
Text="{Binding Workspace.CurrentFlow.FlowName, StringFormat='当前流程 · {0}'}"
```

它比调试条还多一个「当前流程 · 」前缀——多条并跑时这个前缀直接是假话。两处一并改成
`{Binding RunBarFlowText}` + 悬停 `RunBarFlowToolTip`，前缀去掉（左边那行已经是「循环运行中」，
再写一遍"当前"只会让人以为只有这一条在跑）。

守门断言因此改成**同时扫两个文件**（`Shell.xaml` + `RunCockpitView.xaml`），
防止只修一条、另一条再漏。

## 二、流程卡：`RunState` 早就有了，只是没上屏

`FlowModel.RunState`（`[JsonIgnore]`，不落盘）由 `ShellViewModel.SyncFlowRunState` 按会话状态镜像，
注释里写着"方案里 4 处'运行中禁止改配置'的守卫读的都是它"。但 `FlowListView.xaml` 里
状态点只表达**启用 / 禁用**（绿点 / 灰点 + 「禁用」标签 + 删除线），运行态一个字都没用上。

**修法**：在 `DataTemplate.Triggers` 里加两条（顺序在「禁用」之前，禁用态最后赢）：

| RunState | 表现 |
| --- | --- |
| `Running` | 名称加粗 + 右侧绿色「运行中」标记 |
| `Paused` | 名称加粗 + 状态点转主色蓝 + 右侧蓝色「已暂停」标记 |
| `Stopped` | 与改造前一致（绿点 = 启用） |

「运行中」与「禁用」同格（禁用流程不可能在跑）；禁用触发器额外把 `RunningTag` 收掉，
防止模型里留着旧镜像时两枚标签挤在一格里。

**为什么状态点不改成"运行态灯"**：它现在的语义是"这条流程能不能跑"（启用/禁用），
与"它现在是不是在跑"是两件事。把绿点改成"停着就灰"，会让满屏闲置流程看起来像坏了；
所以运行态用**标记 + 加粗**表达，点保持原语义。

## 三、验证

- `VisionMaster`（`--no-incremental`）× `ScadaChecks`：0 错误；
- `ScadaChecks` 全量 **2120 通过 / 0 失败**，新增 `[AJ]` 7 条：

```
[√通过] 运行条：没有流程在跑 → 回落到当前流程  →  MainTask
[√通过] 运行条：没流程在跑且没选中流程 → 「未选择流程」
[√通过] 运行条：1 条在跑 → 报那一条（与当前选中无关）  →  新建流程
[√通过] 运行条：多条并跑 → 「A 等 N 个流程」  →  MainTask 等 2 个流程
[√通过] 运行条悬停：多条时列全名单  →  正在运行：MainTask、新建流程
[√通过] 流程卡片：按 FlowModel.RunState 出「运行中 / 已暂停」标记  →  FlowListView.xaml
[√通过] 运行条：绑的是 RunBarFlowText，不是 Workspace.CurrentFlow  →  Shell.xaml
```

**验证边界（按 R13 口径如实说明）**：文案口径与两处 XAML 接线是断言钉住的；
**卡片上的「运行中」标记与加粗没有出图复核**——流程栏渲染要真 Shell + 真会话，
不在断言宿主的能力范围内。下次真机跑起来时顺眼确认一下即可（预期：在跑的那张卡名字变粗、
右侧出现绿色「运行中」；运行条在多条并跑时显示「MainTask 等 2 个流程」）。

## 四、一个没做但值得记的边界

`FlowModel.RunState` 只在**会话状态事件**里更新。若某个会话被 `ClearAll` 之类直接丢掉、
没发终止事件，卡片可能挂着旧的「运行中」。这与改造前 `AnyFlowRunning()`（菜单互锁）的已知特性一致，
不是本次引入的；真要收口应在"方案切换 / 会话清理"处统一把 `RunState` 归零。
