# 登录框换回自绘密码框：App.xaml 把「输入域」一册提到 Fluent 之后重挂

> 日期：2026-10-23 ｜ 范围：`VisionMaster/App.xaml` 的 MergedDictionaries ｜ 状态：已改，登录视图出图验收通过（眼睛按钮出现），全量 gate 待另一个会话的 `ScadaCanvas.cs` 编译错落地后复跑

## 1. 背景

上一轮修完输入框模板的二次内缩后发现：`UI/Controls/Themes/Controls/Input.xaml` 里那份**带「显示密码」眼睛**的 PasswordBox 模板，在运行期被 .NET 9 Fluent 的隐式样式顶掉（`App.xaml` 合并顺序 `Core.Halcon → UI → Fluent`，后合并者优先）。实测运行期 `Application.Current.Resources[typeof(PasswordBox)]` 拿到的是 Fluent 的 `Padding=10,5,10,6`，UI 声明的 `10,8` 从未生效；登录视图探针也确认模板里 `PlainTextHost` / 眼睛按钮都不存在。

## 2. 决策：不整册翻转，只把「输入域」一册重挂到 Fluent 之后

`UI/Themes/Generic.xaml` 里 `FluentAliases.xaml` 明确要求"最后合并、同名旧键重定向到 Fluent"；整册翻转（UI 在 Fluent 之后）会把 Button / ListView / DataGrid / ToggleButton 等**全套**换回自绘皮肤，而 R19（GridView 让路样式）与 R148（自定义模板里的 ToggleButton 依赖 Fluent 的 `Left/Center`）的前提正是"Fluent 赢"。

所以只在 `App.xaml` 末尾重挂一册：

```xml
<ResourceDictionary Source="/UI;component/Themes/Controls/Input.xaml" />
```

`Input.xaml` 自带 `Colors.xaml` 合并，重挂不会产生跨册断链（R30）。

## 3. 影响面（必须知道）

`Input.xaml` 定义了三个**隐式**样式：`TextBox`、`Slider`、`PasswordBox`。重挂之后：

| 控件 | 数量 | 影响 |
|---|---|---|
| 显式 `Style=` 的 TextBox | 95 处 | 不受影响（显式样式优先） |
| **未写 Style 的 TextBox** | **47 处**（Shell / LogView / MonitorView / ScadaPropertyView 等） | 从 Fluent 皮肤换成自绘皮肤（`#FBFBFB` 底 + 圆角 5 + 聚焦下划线动画） |
| Slider | 1 处 | 同上 |
| PasswordBox | 登录 4 处 + 用户管理 + 数据库页 | 换成自绘模板，**「显示密码」眼睛与明码通道恢复** |

回退成本：删掉 `App.xaml` 里那一条重挂即可（一行）。
