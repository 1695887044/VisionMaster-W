# 修复：报表列编辑器「聚合」下拉文字被切（同类事故第 N 起）

日期：2026-10-25　状态：已修（报表列 + 数据表格列两处）；`VisionMaster` 编译 0 错误

## 症状

「配置报表列」弹窗里，「聚合」下拉的选中文字（"不聚合"）上下被切掉，同一行左边三个 TextBox 正常。

## 根因

`ScadaReportColumnsEditor.xaml` 里那个 ComboBox 写了 `Height="26"`，**没有写 `Padding`**。
而应用级 Fluent 的隐式 ComboBox 样式自带一份很大的内边距（上下合计约 11px）。
26px 总高 − 11px 内边距 = 15px 内容区 < 一行中文的行高（约 16.5px）→ 文字被裁。

同一行的 TextBox 之所以正常，是因为它们走本地 `CellBox` 样式，里面写了 `Padding="6,3"` +
`VerticalContentAlignment="Center"`。

## 为什么"很多起"

1. **两套尺寸系统打架**：弹窗按"26px 行高"手工排版，控件却吃应用级 Fluent 隐式样式自带的
   Padding/MinHeight/模板边距。只要显式 Height 小于"样式要求的内容高度"，就必然裁字。
   这与 R68（图标字符按钮被 Fluent 的 `11,5,11,6` 削掉字形）、R184（TextBox 二次内缩把 38px 压成 12px）
   是**同一族**：显式尺寸 + 继承样式内边距 = 静默裁切。
2. **缺陷靠复制传播**：报表列编辑器是从数据表格列编辑器抄的，那边也是 `Height="26"` 无 Padding。
3. **没有闸**：GB* 只覆盖"图标字符按钮"，R184 只有人工评审；没有任何静态扫描检查
   "固定高度的输入类控件有没有显式内边距"。

## 本轮改动

- `ScadaReportColumnsEditor.xaml`：聚合 ComboBox 补 `Padding="6,0"` + `VerticalContentAlignment="Center"`；
- `ScadaGridColumnsEditor.xaml`：对齐 ComboBox 同样补两行（同一个病，顺手修掉）。

## 静态闸（同日第三轮，已落地）

新增 `ScadaChecks/DialogLayoutChecks.cs` 的 `[DL1]`，扫 `VisionMaster\Views\**\*.xaml`：

- 判据：带**字面量 Height** 的 `ComboBox`/`TextBox`，必须
  ① 有 `Style="{StaticResource …}"`（含子元素 `<ComboBox.Style>` 写法），或
  ② 有 `Padding` 且 `Height − 2×边框 − 上下内边距 ≥ 字号 × 1.4`；
  两者都没有 → 判红（它拿到的内边距是隐式样式的，不是作者想的）。
- 阈值 1.4 的依据：中文行高约等于字号 × 1.35~1.4（13 号字实测约 18px），低于它必然裁字或压顶。
- 报错带**文件名:行号 + 具体算式**，可直接照着改。

**变异反证（R65）**：把 `ScadaReportColumnsEditor.xaml` 里那行 `Style="{StaticResource DialogComboCompact}"`
删掉 → `[DL1]` 红，指名 `ScadaReportColumnsEditor.xaml:82 ComboBox Height=26 既无 Style 也无 Padding`；
还原 → 绿（`扫描 76 个固定高度控件，全部合规`）。

落点说明：放在 `ScadaChecks` 是因为它跑得最快、且已有同类跨域静态检查（`[DSK1]`）；
将来若 `UIThemeSmokeTest` 纳入常规 gate，可把这一条平移过去（判据不变）。
