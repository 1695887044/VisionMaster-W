# 画布注入帧收容开关与缩略图条折叠（2026-10-24）

## 起因

现场按「每条流程各发自己的显示窗口」使用多画面（3×3 下每流程占一格），提出三点：

1. 插件怎么发怎么显示（默认不要收容历史帧）；
2. 收容开关要能关，关掉时优先显示最后一张；
3. 下方缩略图条太占画面，3×3 时大图不够看。

## 现状核查（改前）

- **"最后一张优先"在多窗口配置下本来就成立**：`ImageGallery.Recompute` 按窗口号筛选后
  按 `Sequence` 升序，自动选中取末项。只有当两条流程挤在同一窗口时，
  排序里的 `OrderBy(FlowName)` 才会让字母序靠后的流程长期占屏——本现场不触发。
- **"不进历史"不存在**：注入帧走 `uniqueSlot: true` → 槽位键是随机 GUID
  （`ImageFrame.cs` 的 `SlotKey`），`InsertOrReplace` 的覆盖分支永远撞不上，
  于是每次发布都是新增一条。循环运行时几十秒就顶到单流程上限 50 张。
- **缩略图条是模板写死的一行**：`ImageGallery.xaml` 的第三行固定 112px + 4px 分隔条，
  没有任何开关；3×3 下每格约 390×270，条子吃掉约 44%。

## 改动

### 1. 新增"收容"开关（默认关）

`Core\Models\AppConfigModel.cs` 的 `ImageGallerySettings` 加两项：

| 属性 | 默认 | 含义 |
|---|---|---|
| `KeepInjectedHistory` | `false` | 是否保留插件注入图的历史帧 |
| `ShowThumbnailStrip` | `true` | 缩略图条是否显示（仅收容打开时有意义） |

语义分工（三者互不覆盖）：

- `Enabled` = 采集总闸，关了一帧都不收；
- 本次的 `KeepInjectedHistory` = 收进来之后"留一张还是留一串"；
- 既有的 `KeepFrameHistory` = 只管**兜底采集**的输出端口帧（按步骤/端口占槽那类）。

### 2. 槽位键随开关切换

`ImageCollectionService.BuildFrame`：注入帧在收容关时用 `流程名 + 窗口号` 作槽位键，
收容开时用唯一 GUID。收容关下 `InsertOrReplace` 的既有覆盖分支直接生效，旧图当场 `Dispose`。

内存从"每流程 50 张"降到"窗口数 × 1 张"：三条流程三个窗口 ≈ 45MB（原来是 2.25GB 上限）。

### 3. 开关翻转当场收敛（`ReslotInjectedFrames`）

只改 `BuildFrame` 是不够的：已收下的帧还挂着旧键，会出现"旧键那条 + 新键这条"两张并存。
`ApplySettingsNow` 现在会先调 `ReslotInjectedFrames`：

- 收容关：按「流程+窗口号」分组，每组只留 `Sequence` 最大的一张，其余 `Dispose`；
- 收容开：给每帧补唯一键（绝不退化成按窗口合并）；
- **只动注入帧**（靠 `ImageFrame.IsInjectedPreview` 区分）——兜底帧本来就被端口数封顶，
  跟着收敛等于白扔可见的中间过程图。

`Reslot` 是 public 方法（跨程序集），注释写明"调用方必须同时维护槽位索引"。

### 4. 缩略图条折叠

- `ImageGallery` 加 `ShowThumbnailStrip` 依赖属性；
- 模板给两行 `RowDefinition` 起名（`StripRow` / `StripSplitterRow`），
  触发器把**行高折成 0** 而不只是设 `Visibility`——只藏元素的话固定 112px 的行定义仍然占位，
  界面上"条子不见了"看起来生效了，大图却一点没变大。这是本次最容易踩空的一处；
- `ImageView.ShouldShowStrip`：`Enabled && KeepInjectedHistory && ShowThumbnailStrip`。
  收容关时每格只有一张图，条子必然只有一张缩略图，属于纯占位，直接不显示。

### 5. 兜底采集窗口归属（顺带修的真缺陷）

`Harvest` 原来把**所有**输出端口的图一律塞窗口 1。单流程时看不出来，但
"多流程各占一个窗口 + 打开兜底采集"就会让第 1 格被所有流程轮番刷满、其余各格永远空着。

新增 `ReadDisplayViewIndex(plugin)`，两种声明形态都认：

- `[StepConfig] public int DisplayViewIndex`（普通属性，不进端口表，绝大多数插件是这种）；
- `InputPort<int> DisplayViewIndex`（几何查找/几何计算这类）。

读不到或声明为 0（不显示）才回落窗口 1——兜底的语义是"至少让这图有地方出现"。

### 6. 配置入口

`SystemSettingsDraft` 加 `GalleryKeepInjectedHistory`（Order=3）、`GalleryShowThumbnailStrip`（Order=4），
`ScadaSystemSettingsViewModel` 的 `BuildDraft` / 保存 / 审计改动明细三处同步；
`galleryChanged` 判据加上收容开关——否则翻转它不会触发 `ApplySettingsNow`，收敛就不发生。

### 7. 清掉死代码

`ImageView.xaml` 里那个 `ToggleButton` 从来没显示过：构造函数 `ShowCanvas` 第一件事就是
`grid.Children.Clear()`。删除。

## 踩过的坑

- **一次错误的"优化"**：起初让收容关时不生成缩略图（省一次全尺寸转换），
  结果 `[TH]` / `C3` 两条既有断言立刻红。更根本的问题是行为变更：
  用户事后打开收容，已收下的那批帧永远没有缩略图，条子会全是"无预览"。
  已撤回，`Thumbnail` 保持无条件生成。
- **FlowCanvasChecks 的偶发红**：中途几轮出现 YC3 三条红，一度怀疑是新断言污染。
  用环境变量临时摘掉 `[HW]` 后变绿，但**执行顺序证伪了这个推断**——
  YC3 在 `Program.cs:145`，`[PC]/[HW]` 在 322 行，物理上不可能反向影响。
  随后连跑一轮 0 失败，确认是既有偶发（该宿主本来就有"数据缺失类"红灯在轮次间浮动）。
- 断言里构造的 `FlowSession` 一开始没 `Dispose`（它持有 `CancellationTokenSource` /
  `SemaphoreSlim`），已补 `finally` 收尾。

## 第二批（同日，收尾）

第一批遗留两件事，本批补齐。

### 1. 右键菜单入口：显示缩略图条

`ImageGallery.EnsureContextMenu` 加第四项「显示缩略图条」（可勾选）。

**分层处理**：控件在 `Services\Core.Halcon`，不引用 `VisionMaster`，拿不到 `AppSettingsService`。
所以控件只做两件事——翻自己的 DP（本格立刻生效）+ 发 `ThumbnailStripToggleRequested` 事件；
**落盘与多格同步归宿主**（`ImageView.OnThumbnailStripToggleRequested`）。

写成两步而不是一步，是因为两种单边失效都很难查：
- 只改 DP 不发事件 → 当次有效、重启回弹（每次开机都要再点一遍）；
- 只发事件不改 DP → 等宿主回调才动，宿主没接或抛了就是"点了没反应"。

宿主侧的写盘走 `ContainerLocator`（本仓惯例，见 `FlowQueryHelper`、`StepParameterDialog`），
并且**必须容错**：`ImageView` 会被断言宿主和设计器直接 `new`，那时容器为空，硬解会抛。
写盘失败时回滚到原值并弹窗说明"本次有效、重启后回到旧值"，不让界面停在"点了没动"。

### 2. 锁定跟随 / 对比模式按能力置灰

新增 `ImageGallery.SupportsFrameHistory`（默认 `false`），由 `ImageView` 从配置推下来
（= `Enabled && KeepInjectedHistory`）。

为 false 时「钉住当前帧 / 对比模式 / 锁定跟随 / 显示缩略图条」四项一律置灰，
并在 `ToolTip` 里指出去哪儿打开——只说"不可用"的话用户还得自己再找一遍。

**能力被收回时的连带清理**（`OnSupportsFrameHistoryChanged`）：自动退出对比模式并清空
`PinnedFrame`。不这么做的话，收容一关，左右两张大图显示的是同一张（更糟的是那张可能
已被覆盖释放，`ImageFrame.Dispose` 之后 `HImage` 为 null）。
