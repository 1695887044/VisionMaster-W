## 1. 当前状态

「结果输出」步骤的规则从"多个取最后执行"改为**一条流程只允许一个**，三层同时生效：

| 层 | 行为 |
| --- | --- |
| **轮末解析** | 本轮执行成功的结果输出步骤 > 1 → `Outcome=Unknown`，原因写"流程里有 N 个结果输出步骤（只能保留一个）：名字1、名字2"；不再猜"最后执行" |
| **结果源弹窗** | 检测到多个 → 面板红字点名全部；「结果输出步骤」模式**阻断保存**并给原因；「自动」模式不阻断，但警告"跳过结果步骤、按回退链继续" |
| **插件手册** | 写明"一条流程只允许一个"、分支各一个可以、循环里不要放、要指定端口用「步骤端口」模式 |

**为什么改**：旧规则"取最后执行"在两种真实写法里都是错的——

- 循环里放结果输出：每个对象执行一次，最后一个对象（通常 OK）覆盖掉前面的 NG；
- 顺序放两个（初检/复检）：后一个永远覆盖前一个，用户无从选择。

正确写法是"分支逻辑算出一个布尔 → 接到唯一那个结果输出的 `IsOk` 端口"，这也是插件本来支持的接法。

## 5. 踩过的坑

1. **FRS-7 第一版断言写错了模式**：在 `Auto` 下两个结果步骤 → 结果步骤解析返回 Unknown 后，Auto 继续回退到结果变量，最终是 `Ng / Variable`。歧义只在**显式「结果输出步骤」模式**下可见。测试改为先切模式、清变量名再断言。
2. **`HasResultStep` 与 `AutoUsesResultStep` 不能混用**：自动模式标签原来绑 `HasResultStep`，多步时它仍为 true，会显示"结果输出步骤"而实际已回退；标签必须绑"命中且不歧义"。
3. **改插件 Help 的 `.md` 必须 `--no-incremental` 重建该插件**：本轮只改了 `ResultOutputPlugin/01-overview.md`，`audit_artifacts` 立刻报
   `STALE_DLL Plugin.Util dll=07:49 src=08:25 newest=01-overview.md`（R42）。重建 `Plugin.Util.csproj --no-incremental` 后复跑即绿。
