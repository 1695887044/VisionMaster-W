# 开发记录：插件契约整改（默认成功、显式失败）+ 工具集精简

- 日期：2026-09-15
- 类型：框架契约修复 + 用户手工精简工具集后的体检
- 前置：同日上午《延时插件Success契约修复》发现"不写 Success 就每轮假失败"病根，本次全量收口

---

## 一、背景与盘点

用户手工删除 Plugin.Utility 下 9 个工具（ArrayElement、ArrayStatistics、ConditionalBranch、Counter、FileLogger、RangeCheck、Stopwatch、StringFormat、SystemTime，共 -766 行）。删后全库体检：

- **代码零残留引用**（仅 docs\软件手册.md L513 的"约 18 个插件"描述过时，待更新）；
- 现存方案(.vms)未使用被删工具；
- 剩余工具箱 11 个：图像采集/延时/ROI/随机数 | 数值比较/逻辑运算 | 类型转换/数学计算 | 变量定义/变量赋值 | 图像脚本。

契约体检发现三类病灶（20 个 RunAlgorithm 实现中仅 4 个原本健康）：

| 病灶 | 受害者 | 机理 |
|---|---|---|
| 从不写 Success | Comparison、LogicOperation（及被删的 9 个） | 基类 `Execute` 返回 `Success.Value is true`，bool 默认 false → 正常路径也每轮假失败 |
| 吞异常/静默降级不报失败 | MathCalculation(catch→NaN)、Random(min>=max 降级) | 旧契约偶然报失败；改默认成功后会**误报成功**，需显式补 false |
| **影子端口** | DataConversion(Success)、VariableDefinition/VariableAssignment(Success+ErrorMessage)、FileLogger(IsSuccess 端口名"Success"撞名，已删) | 派生类自声明同名属性：插件代码编译期绑定写**派生端口**，基类 Execute 读**基类端口** → 写了也白写；ErrorMessage 同理 → 引擎日志"执行失败: "空消息 |

## 二、决策

契约从"必须显式写 true"改为 **"默认成功、显式失败"**：`Execute` 进 `RunAlgorithm` 前预置 `Success=true`、清空 `ErrorMessage`。理由：基类注释本就写着"RunAlgorithm 把失败写入 Success"（实现追上文档）；一次修复全部纯计算插件；未来新插件忘写 false 的风险由代码评审兜住，而忘写 true 是天天踩的坑。影子端口一律删除声明、复用基类端口（端口名不变，连线/监控无感知）。

## 六、全量复查（同日追加）

对 11 个插件子类逐一过源码，专查三类模式：失败分支跌落洗状态 / 提前 return 漏标 / 影子残留。

**发现并修复 1 处（VariableAssignmentPlugin）**：
"变量不存在且不自动创建"分支置 `Success=false` + `ErrorMessage` 后**未 return**，直落到方法尾部 `ErrorMessage.Value = string.Empty` 把失败原因洗成空。
- 历史：该 bug 一直存在，但旧代码里 ErrorMessage 是影子端口（引擎读基类），洗的是空气，未暴露；
- 现形：本次拆影子后写值落到基类端口，跌落清洗开始真实伤害引擎日志（"执行失败: "空消息）——**契约修复会让潜伏 bug 现形**，这是"修一处、查全线"的直接案例；
- 修复：else 分支补 `return` 短路，删除尾部冗余清洗行（基类 Execute 已预置清空）。Plugin.Util Release 重编 13:45:54。

**复查通过（无需改动）**：
- ImageScript：三处失败点（编译失败/输入为空/输出类型不符/未赋值）均 `Success=false` + **return**，规范；
- ImageAcquisition：入口清 false、catch 不置 true → 异常路径保持失败，正确；
- CreateRoi：入口校验失败 false+return，尾部 true，正确；
- VariableDefinition：失败分支全部 return 后才写 true+清空，正确；
- Random/MathCalc：本次新补的显式失败带 return/位于 catch 内，无跌落；
- Comparison/LogicOperation/Delay/DataConversion：无新发现。

**遗留观察项（未修，待决策）**：
1. CreateRoi L333 `catch { }` 静默吞单个 ROI 裁剪失败（注释声明"不阻断整体"是设计意图，但连 Warn 日志都没有，坏件可能无痕迹）——建议至少补一条 Warn；
2. 试运行不看 Execute 返回值（同边界表第 2 条）。
