## 二、已做

### 2.1 行为口径

| 场景 | 行为 |
|---|---|
| 两个方案**同账号同密码** | 切方案后保持登录；用户组与权限取**新方案**账号本里的组 |
| 账号不存在 / 密码不同 / 账号本读不出 | 按未登录处理（与旧行为一致），审计 + 运行日志写明原因 |
| 切到未保存的新方案（出厂 `admin/admin123`） | 同账号密码时保持登录 |
| 手动登出 / 空闲超时 / 强制登出 | 凭据立即清零；之后切方案不会把会话复活 |
| 本人改密 | 旧凭据作废；登录弹窗用新密码回填，改完立刻切方案仍保持 |
| 重开当前方案（同 id + 同 root） | 早退：不登出、不重复审计、凭据不动 |
| 关闭方案 / 账号本绑定失败 | 不保持登录（没有可验的账号本，不能凭空登录） |

### 2.2 关键设计

1. **内存凭据仓** `ScadaSessionCredentialVault`：用户名 + 可擦除的 `char[]` 密码。
   `Capture()` 取走即清空仓；`Dispose()` 逐位清零；**不落盘、不进日志与审计**。
   生命周期严格等于"这次登录会话"——不是"记住密码"。
2. **任何登出都清凭据**：`ScadaAccessPolicy` 新增 `LoggedOut` 事件（在状态清空之后广播），
   凭据仓构造时订阅。手动登出 / 空闲超时 / 方案切换 / 强制登出四条路全覆盖。
3. **先取凭据、再登出**：协调器在 `Logout()` **之前** `Capture()`，否则凭据已被
   `LoggedOut` 清掉，表现是"两边密码一样却还是登出"。
4. **在新账号本重验，不搬旧快照**：账号本按方案隔离、每个账号的盐随机，
   同一个密码在两份账号本里的哈希不同；旧权限快照里的组 Id 在新方案可能不存在。
   所以绑定新账号本后调用 `ScadaUserStore.TryValidate`，成功才 `Login`，
   权限永远来自新方案返回的 `ScadaUserInfo`。
5. **验证链路不把明文转回 `string`**：`ScadaUserStore` 新增
   `TryValidate(string?, ReadOnlySpan<char>, ...)` 重载，PBKDF2 直接吃 span；
   `string` 重载委托给它，行为不变。
6. **连续切换**：重验成功后把凭据回填仓里，否则只能保持一次。
7. **改密联动**：账号本的 `PasswordChanged/PasswordReset` 事件会清凭据；
   登录弹窗"本人改密"拿得到新明文，在事件之后立刻回填（顺序反了会留下空仓）。
8. **自定义组显示名**：`ScadaAccessPolicy.Login` 原来只查三档内置模板，
   自定义组（如 `G-lineop`）在状态栏会显示组 Id；本批改为优先用账号本给的
   `GroupName`，断言 `[SL-e1-c]` 钉住。

## 五、踩过的坑

1. **凭据必须在 `Logout` 之前取走**：`Logout` 会经 `LoggedOut` 清空仓；顺序反了就是
   "两边密码一样却还是登出"，而且不报任何错。
2. **不能搬旧权限快照**：盐不同、组 Id 可能不存在；必须在新账号本重验。
   直接搬旧快照 = 在新方案按旧方案权限放行，是权限越界。
3. **`string` 不可擦除**：凭据仓用 `char[]`，验证链路加 `ReadOnlySpan<char>` 重载；
   否则为了重验会把刚擦掉的明文再造一份。
4. **改密事件与回填的顺序**：`TryChangePassword` 同步触发 `UserChanged` → 协调器清仓；
   登录弹窗必须在**事件之后**用新明文回填。反了就是"改完密码，下次切方案登出"。
5. **`run_gates` 的 FlowCanvasChecks 首次红不是代码错**：残留的 `FlowCanvasChecks (PID)`
   锁着 `FlowCanvasChecks\bin\...\Plugin.*.dll`；等实例退出后
   `-Only FlowCanvasChecks` 复跑即绿（已合并进台账 A-01）。
6. **自定义组显示名**：`ScadaAccessPolicy.Login` 原来只查三档模板，自定义组显示组 Id；
   本批改为优先用账号本的 `GroupName`，由 `[SL-e1-c]` 钉住。
