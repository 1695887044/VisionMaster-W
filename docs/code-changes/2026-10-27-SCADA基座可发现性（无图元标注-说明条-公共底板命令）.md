# SCADA 基座可发现性：无图元标注 / 说明条 / 插入公共底板矩形（2026-10-27）

## 一、当前状态

现场反馈「建了基座、主界面也引用了，怎么没反应」的根因是**误解**而不是缺陷：基座只合成**图元**，底色 / 尺寸 / 网格永远取引用页自己的（R90 与 `2026-10-18-组态基座画面（跨页公共层）.md` §五）。排查取证见同目录 `2026-10-27-SCADA基座引用无显示排查（底色不参与合成）.md`（含像素取样证据与 §七 的三方案取舍）。

本轮按用户拍板落地「提示 + 一键公共底板」，**不改**底色自动合成（默认值 `#FF1E1E1E` 会让存量画面静默变暗、多基座叠放谁压谁说不清）。

- 构建：`dotnet build ScadaChecks\ScadaChecks.csproj -m:1 -nodeReuse:false` → **0 个错误**、退出码 0（R179）。

  - `基座说明条`：基座页亮、普通页不亮，且换页时发了通知（否则 `DataTrigger` 要等重开面板）。

## 六、踩过的坑

- **并发编辑把解决方案打红了**：`VisionMaster/ViewModels/LogViewModel.cs` 在 23:14 被另一会话写入**逐字重复**的 `AppendWithCap`（CS0111），整个 `VisionMaster` 编不过。文件静置 2 分钟后按 R9 删掉重复那一份恢复构建（语义零变化）。**判据**：改代码前先看 `LastWriteTime`，构建报"莫名其妙"的重复成员先怀疑并发编辑，别去动自己没碰过的文件。
- **`ScadaChecks.exe` 跑完不退出**：打印完 `通过/失败` 汇总后进程仍驻留（WPF Dispatcher 线程），会锁住 `bin\` 里的 DLL → 下一次构建报 `MSB3021/MSB3027 文件被锁定`。处置：`taskkill /PID <pid> /F` 再构建；批量跑用 `tools\run_gates.ps1`（它有界等待 + 收尾）。
- **cmd 里 `& echo EXITCODE=%ERRORLEVEL%` 是假读数**：`%ERRORLEVEL%` 在整行解析时就展开了，拿到的是**上一条命令**的退出码，不是刚跑的 exe。判退出码要么 `if errorlevel`，要么用 `run_gates.ps1` 的 `exit=` 行（R183 家族）。
- **同一工作区第二个会话在跑断言时，全量闸的结果不可信**：本轮实测三种污染——① `MSB3021/MSB3027`（DLL 被对方正在跑的宿主锁住）；② `CS2012`/`CS0006`（同一 `obj\` 目录被两个 WPF 构建同时写，还见过 `RG1000: An item with the same key has already been added. Key: app.baml`）；③ **断言宿主写同名证据 PNG 时互相 `IOException`**（`ScadaChecks\bin\...\artifacts\scada-editor-toolbar.png` 被对方占用 → 一条"全程未抛异常"直接判红）。判据：看到这三类错误先查 `Get-Process | ? ProcessName -match 'dotnet|*Checks'` 与源码 `LastWriteTime`，**别去改自己没碰过的代码**。
