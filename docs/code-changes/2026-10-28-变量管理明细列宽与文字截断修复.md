### 2.2 列宽契约（`FlowCanvasChecks\GlobalVariableChecks.cs`）

- `expectedWidths`：`{220,104,120,104,88,*,100}` → `{1.6*,Auto,120,104,88,*,100}`；`expectedMinWidths` 不变。
- 合计算法按来源分开建模：
  - 弹性列（`1.6*`）最坏退到 `MinWidth` 计入固定负担；
  - `Auto` 列在本地/系统来源按 `MaxWidth` 计（长类型名只出现在这两档），在网络来源按 `MinWidth` 计（网络类型均为基元/数组）。
  - 结果：本地/系统 220+220+100=540（+160=700 ≤ 924）；网络 220+104+120+104+88+100=736（+160=896 ≤ 924）。
- 新增一条闸：类型列 `Auto` 必须带 `MaxWidth` 且 ≤ 220（没有上限会把当前值挤出视口；220 = `FlowRuntimeSnapshot` 整词宽度）。

## 5. 踩过的坑

- **列宽被断言逐列钉死**：`GlobalVariableChecks` 用 `expectedWidths` / `expectedMinWidths` 做 `SequenceEqual`，改 XAML 列宽必须同步改断言，否则闸红；反过来，断言也是"这次改宽了多少"的唯一记录点。
- **只加列宽不改 chip 上限无效**：类型 chip 自己有 `MaxWidth="92"`，列宽加到 160 也只能渲染 92。
- **160 也不够**：`FlowRuntimeSnapshot` 在 160 列宽下实测渲染成 `FlowRuntimeSnaps…`（chip 可用宽 = 列宽 − 单元格左内边距 12）。按整词宽度给到 220 才完整；不要按"字符数 × 平均字宽"拍脑袋，直接用冒烟夹具渲染验证。
- **固定 `Height` 与基线 `min-height` 不一致**：design.html 是 `min-height:40px`（内容高就长高），WPF 写 `Height` 就是裁。改 `MinHeight` 后冒烟实测仍是 `root=54 child=40`——`DataGrid.MinRowHeight` 不会覆盖行自己的 `MinHeight`（`DataGridRow.cs` 里只在拖拽改高时读它）。
- **真机在跑时构建必挂**：`VisionMaster.exe` 会锁住 `bin\` 与 `Modules\`（插件 `CopyPluginToModules` 目标）。验证构建用 `-p:OutDir=artifacts\verify\smoke\ -p:ModulesDir=artifacts\verify\modules\ -p:HostBinDir=...` 把整套产物重定向，不碰运行中的文件；冒烟的 RepoRoot 向上找 8 级，放在 `artifacts\verify\smoke\` 仍能找到仓库根。
- **Auto 列不能无上限**：`Width="Auto"` 会让长类型名按内容撑开，若不加 `MaxWidth`，1200 窄档下会把星号「当前值」列挤出视口（2026-10-11 事故的同类回归）。
- **星号列判定用精确匹配**：断言里 `Width="\*"` 只匹配 `Width="*"`，弹性列写成 `1.5*` 不会被误当成星号列；但合计算法必须显式处理 `1.5*`（按 MinWidth）与 `Auto`（按 MaxWidth/MinWidth），否则弹性列会从合计里"消失"，闸门形同虚设。
- **名称 ToolTip 不含描述**：`DisplayFullName` 只是 `FullName`，给描述加 ToolTip 不能复用名称那个。
