# 2026-10-20 通讯立刻读/立刻写算子（插队读写车道与两个插件）

> 起因：用户要求「在通讯类下新增『立刻读』『立刻写』两个算子，对通讯变量执行插队读/插队写，
> 优先于常规读写队列立即执行；放在一个类库就行」。
> 结论：插件是一个类库（`Plugin.Comm`，两个插件类）；真正的插队能力在通讯层新增
> **L0 插队写 / L1 插队读** 两条最高优先级车道，并让轮询在段间让路。

---

## 1. 现状核对（先分清"已经有什么"）

| 能力 | 改造前 | 证据 |
| --- | --- | --- |
| 写优先于读 | 有（N1，2026-09-24） | `ConnectionWorker.cs` 读/写双队列；`DrainQueues` 先写后读 |
| 按需读/写（不等下一拍轮询） | 有 | `AdvancedCommunicationManager.Read<T>/Write` 投递到 Worker，Worker 先排空命令队列再轮询 |
| 插队读（越过已排队的读/写） | **没有** | `Read<T>` 走 `_readQueue`，FIFO 且低于写 |
| 插队写（越过已排队的写） | **没有** | `Write` 走 `_writeQueue`，FIFO |
| 轮询段间让路 | **没有** | `PollScheduler.Run` 一次跑完所有到期组；`PollBatchPlanner.Poll` 一次跑完所有段 |

因此本轮新增的是"同类队列之间"的优先级与"轮询让路"，不是重复已有的"写优先于读"。

---

## 2. 车道模型

| 车道 | 内容 | 入队 API | 优先级 |
| --- | --- | --- | --- |
| L0 | 插队写（「立刻写」） | `ConnectionWorker.InvokeUrgentWrite` | 最高 |
| L1 | 插队读（「立刻读」） | `ConnectionWorker.InvokeUrgentRead` | 高 |
| L2 | 常规写 | `InvokeWrite` | 中 |
| L3 | 常规读 | `Invoke` | 低 |
| L4 | 轮询 | `PollScheduler.Run` | 最低，且段间让路 |

- 同车道 FIFO；跨车道严格优先级；一次只执行一条命令。
- **不能抢占正在执行的命令/段**：插队只改变排队位置，不打断 `ReadBytes`/`Write`
  （同一 socket 不能并发两个事务）。
- 插队队列容量 256、入队等待 200ms；满了即失败，**不回退常规队列**
  （回退会静默违反"立刻"语义）。常规队列仍是 4096 / 2000ms。
- `_urgentPending` **先加计数、再入队**：Worker 可能在 `TryAdd` 返回后立刻取走并减计数，
  若先入队后加，计数会被减成负数、后续 `HasUrgentPending` 少算（轮询该让路却没让）。
  入队失败/Dispose 竞态时在对应出口减回去。

## 3. 轮询段间让路

- 新增 `PollCycleOutcome { Completed, Yielded, LinkFault }`。
- `PollBatchPlanner.Poll(connection, yieldRequested)` 在**每段之前**、**每个兜底单读之前**
  询问是否让路；段内不中断。
- `PollScheduler.Run(connection, yieldRequested)` 透传；`Yielded` 时**不 MarkSuccess**，
  本组保持到期，下一拍重跑整组（已读过的段会重读一次，这是让路的代价）。
- 旧 `bool Poll(connection)` / `bool Run(connection)` 保留为兼容重载。

## 4. 调用链

```
插件 RunAlgorithm
  → IExecutionContext.Comms（新增能力）
    → CommVariableAccess（宿主实现，按名解析 NetworkVariableModel）
      → NetworkVariableModel.TryReadNow / TryWriteNowToValue
        → AdvancedCommunicationManager.ReadVariableNow / WriteVariableNow
          → ConnectionWorker.InvokeUrgentRead / InvokeUrgentWrite
            → PollBatchPlanner.TryReadOne（读）/ ICommunicationConnection.Write（写）
```

- `ReadVariableNow` 用**单变量计划**（只读自己的跨度，不合并邻居），
  `isolateFaultedSegments: false`（坏段隔离不能影响立刻读）。
- `TryReadOne` 与常规轮询共用 `DecodeItem` / `DecodeBitItem`，字节序/解码/长度校验只有一份实现。
- `ReadVariableNow` 的 `variable.UpdateValue(工程值)` 单独 try/catch：下游订阅者（UI/组态/报警）
  抛异常不能把"已经读到的值"判成读取失败（与 `PollBatchPlanner.PublishValue` 的隔离口径一致）。
- `WriteVariableNow` 只负责传输：`rawValue` 已是设备原始值；工程值换算、文本解析、写租约、
  只读区判断、镜像同步都在 `NetworkVariableModel.TryWriteCore`（普通写与插队写共用）。
- **不等待分支**：`TryQueueWriteNow` → `NetworkVariableModel.TryQueueWriteNowToValue` →
  `AdvancedCommunicationManager.TryTriggerWriteNow` → `ConnectionWorker.TryEnqueueUrgentWrite`
  （只入队，立即返回）。`Success=true` 只代表"已受理"；设备晚到的失败走日志 +
  `OnCommunicationError`；不更新镜像（命令还没执行）。

## 5. 插件（一个类库，两个类）

| 文件 | 内容 |
| --- | --- |
| `Plugins\Plugin.Comm\Plugin.Comm.csproj` | `net9.0`，只引用 `Core.Interfaces`，`EmbeddedResource Include="Help\**\*"` |
| `CommReadNowPlugin.cs` | 立刻读：1 输入（变量名）+ 5 输出（Value/ValueText/TypeName/ConnectionName/ElapsedMs） |
| `CommWriteNowPlugin.cs` | 立刻写：3 输入（变量名/值/是否等待）+ 5 输出（WrittenValue/Completion/TypeName/ConnectionName/ElapsedMs） |
| `Help\CommReadNowPlugin\` | S 档：3 用户页 + 1 开发页 |
| `Help\CommWriteNowPlugin\` | S 档：3 用户页 + 1 开发页 |

- 工具箱分组 `GroupName = "通讯"`。
- 立刻写有 `WaitForCompletion`（默认 `true`）：`false` 时只入插队写队列立即返回，
  `Success=true` 只代表"已受理"，`Completion=Queued`，设备晚到的失败只进日志/通讯错误事件；
  该模式**不更新镜像**（命令还没执行），等下一拍轮询刷新。
- `WaitForCompletion` 是 `InputPort<bool>` + `IsFunctionalEnum = true` +
  `OptionKind = BooleanChoice`：界面渲染成 **True/False 下拉**，并隐藏 🔗/✕。
  布尔二选一的候选由 `StepConfigOptionSource` 契约层自带（不依赖宿主模块注册），
  避免"手输 true/false 易错 + 还能被上游灌值"。
- 变量名端口 `IsFunctionalEnum = true` + `OptionKind`：`LinkableValueEditor` 渲染成"只能选"下拉
  并隐藏 🔗（R33：名字类端口不接受上游值）。
- 不标 `[ParallelSafe]`：触碰共享设备与写租约，并行分支应由编译器拒绝。
- 全部参数都是端口（无 `[StepConfig]`）：`AutoPortConfigView` 只渲染输入端口。

## 9. 已知边界

1. **不能抢占正在执行的命令/段**：插队只改变排队位置；最坏等待 = 当前事务/连接 I/O 超时。
2. **严格优先级**：插队命令持续洪泛会推迟常规读写与轮询；队列有界（256），满了快速失败。
3. **一个步骤一个变量**：批量读/写是后续扩展。
4. **读-改-写不是事务**：两条独立命令，中间设备可能变化。
5. **名字寻址**：变量改名后步骤报"找不到变量"，需要重选（与「变量赋值」全局作用域一致）。
6. **不标 `[ParallelSafe]`**：并行分支编译期拒绝；租约只解决"不同 owner 写同一个点"的运行期冲突。
7. **无自定义视图**：旧方案里变量名不在候选时，下拉显示空白；运行期报"找不到变量"。
8. **不等待模式是 at-most-once**：只保证入队，不保证执行；进程退出/连接停止时队列里的命令
   会被放弃（`ReleasePendingItems` 触发 `OnAbandon`，晚到失败进日志）；不更新镜像。
