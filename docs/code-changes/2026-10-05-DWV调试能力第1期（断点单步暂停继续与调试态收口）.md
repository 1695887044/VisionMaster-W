## 一、背景与用户决策

流程的「调试能力」此前是空壳：画布右键菜单里的 `SetBreakpoint` 是空实现，现场排障只能靠日志倒推。架构评审给出 3 期路线（第 1 期：断点 / 单步 / 暂停继续；第 2 期：变量监视；第 3 期：跨流程调试与录制）。

用户决策（原话口径）：

1. **单次执行也允许断点**（评审稿原本只给连续运行装调试门——用户决策推翻，验收点随之改写）；
2. 快捷键要上；
3. 断点命中**不用模态对话框**，用「非模态命中窗 + [模块参数] 按钮」——用户要看命中步骤的参数现场，但不愿被模态窗挡住其他操作。

硬约束（评审结论沿用到第 1 期）：**HTTP 触发 / 试运行 / 非调试运行不得被断点卡住**——产线链路（HTTP 收图触发流程）绝不允许被一个遗留断点拦住。

## 二、引擎侧设计：调试门是全引擎唯一插桩点

### 2.1 调试门（`FlowSession.DebugGateBeforeNode`）

所有节点执行前都经过编译产物里的 `CompiledNode.RunSequence` 这一个点。调试门就插在这里：

- **装门条件 = `DebugEnabled`**（不是 `IsContinuousRun`）：所以单次执行同样支持调试（用户决策 1）；`DebugEnabled=false` 时直接 `return`，一步不停——HTTP / 试运行 / 普通运行全走这条路（硬约束靠它守住）；
- **停下顺序**：先合上 `PauseLock` → 再 `raise DebugStopped`（引擎订阅后经 `NotifyStateChanged` 把 State 归到 `Paused`，`Message` 承载"断点命中 / 单步"）→ 再 `PauseLock.Wait(token)`；
- **收尾 `finally Set()` 兜底**：停在中途被 Stop 时，令牌取消会唤醒 `Wait(token)`，锁必回放行态——否则该会话后续所有等待会被莫名按住（[E13] ②⑩ 两条断言专门钉这条）。

### 2.2 三种停下与放行

| 停因 | 触发 | 放行 |
| --- | --- | --- |
| `Breakpoint` | 命中 `step.IsBreakpoint` | `ResumeSession` 或 `StepSession` |
| `Step` | 上一停点执行了一次单步（`DebugStepPending`） | 同上 |
| `User` | 运行中点「暂停」（`PauseSession`） | `ResumeSession` |

- `SessionPauseReason{None, User, Breakpoint, Step}` 落在 `Core\Enums.cs`；
- `PauseSession` 守卫按 `IsContinuousRun || DebugEnabled` 判定（非调试单次执行显式拒绝，不造"UI 显示已暂停、流程照跑"的假象），并对无效请求写 Warn 而不是静默吞掉；
- `IFlowEngine.StepSession`：仅当"运行中且已暂停"有效（与 `ResumeSession` 同口径守卫）——没有等待中的门时置"单步待停"只会遗留给下一轮，下一轮开始会清（`DebugStepPending` 在两种运行的开轮清理里都置 false）。

### 2.3 断点不落盘、不递增 Version

`StepModel.IsBreakpoint` 与 `IsDebugStopped` 都是 `[RuntimeState] + [JsonIgnore]` 双标注：

- 不递增 `FlowModel.Version`——否则每点一下红点就触发一次全量重编译（正是 B2 排除名单要修掉的坑）；
- 不随 `.vms` 落盘——**遗留断点跟方案进产线是安全隐患**（评审结论 4）；
- 收尾时引擎清 `IsDebugStopped` 与 `session.FocusedStep`，避免"停止时机落在置位与清除之间"导致高亮卡死。

## 三、应用层接线

- **运行入口**：`ShellViewModel.RunSessionOnceAsync / RunSessionAsync` 两处，本次运行以 `debugSession: true` 声明为调试会话；

## 四、P2 收口：调试态归引擎独占置位（本记录落盘前同批完成）

**问题**（reviewer 登记 P2）：原实现由调用方（Shell 两入口）在调用前置 `session.DebugEnabled = true`。若这一刻 HTTP 触发抢先拿到会话锁，界面这次调用会被拒（锁被占），`true` 却残留在会话上——那次 **HTTP 运行**就会被断点卡住，静态破坏"HTTP 豁免"硬约束（概率低，但性质是硬约束的漏洞）。

**修复**：置位权收归引擎——

- `IFlowEngine` 两个运行方法新增可选参数 `bool debugSession = false`；
- `FlowEngineService` 在**抢到会话锁之后**执行 `session.DebugEnabled = debugSession;`（赋值而非"仅 true 时置位"：非调试调用顺带把任何残留清干净）；收尾统一清回 false（原有逻辑不变）；
- Shell 两入口删除预置行、改传 `debugSession: true`；
- 断言固化：[E13] ⑪「调试态归引擎置位（预置 true 不生效）」——手工预置 `true` + 带断点图纸 + 非调试调用，必须一次跑完且 `Paused 次数=0`。
