# 2026-10-29 SCADA 模板绑定「结构体」可行性评估

> 需求：后续可能导入其他品牌的变量表（同样带结构体定义）。要评估三件事：
> ① 结构体能否暴露给 SCADA 模板绑定；② 模板能否直接绑定结构体且支持多选；
> ③ 模板界面下的变量能否限定为"只能来自所绑结构体"。
>
> 本文所有结论都有代码依据或探针证据，未验证的写在最后一节。

## 一、结论

| 需求 | 结论 | 一句话依据 |
|---|---|---|
| ① 暴露结构体供模板绑定 | **可行，但需要新增"结构体实体"**（当前不存在） | `IVariable` 没有子变量；唯一先例是系统变量专用的 `ISystemVariableContainer`；结构体根解析不到变量（探针 P5） |
| ② 模板直接绑结构体 + 多选 | **部分可行**：单层成员路径今天已能跑通；"绑结构体本身"和"多选"都不成立 | `Recipes[0].Title` 可参数化并展开（P1/P2）；但 `Recipes[0]` 不是变量（P5），变量选择器是单选（P7） |
| ③ 变量只能来自所绑结构体 | **当前完全没有，但最容易补** | `TemplateStrictRoots` 只在"存/插/刷新"三处出现，**绑定期没有任何消费者**（P6） |

**关键澄清**：上一轮在变量管理里做的"按名称路径折叠成结构体"是**纯展示**——
`VariableNode.IsSyntheticContainer`（`Core\Models\VariableNode.cs:244`），合成容器 `OriginalModel == null`
（`GlobalVariableManagerViewModel.cs:1612-1623`），不进 `Workspace.GlobalVariables`、不落盘。
SCADA 侧看不到它，也拿不到任何"结构体"对象。需求①不是"把已有结构体接出去"，而是"先把结构体造成实体"。

## 二、依据

### 2.1 模型层没有结构体

- `IVariable`（`Core\Models\Variable\IVariable.cs:8`）只有
  `VariableId / VariableType / ConnectionName / AddressConfig / DefaultValue / Description / ResetToDefault`，
  没有 `Children` / `Fields` / `Parent`。
- 全仓唯一"一个变量带多个子变量"的结构是 `ISystemVariableContainer`
  （`Core\Models\Variable\SystemDeviceSnapshots.cs:148-159`，`Fields` 返回 `IReadOnlyList<IVariable>`），
  唯一实现者是系统变量 `SystemVariableModel`（`Core\Models\Variable\SystemVariableModel.cs:28`、`Fields` :75）。
  **网络变量没有任何等价物。**
- 注册表只有精确查找：`VariableRegistry.FindByName`（`Core\Binding\VariableRegistry.cs:126-140`）、
  `Resolve(id, name)`（:142-143）。**没有按前缀批量查询**。

### 2.2 SCADA 绑定只能指向一个真实变量

- `ScadaBinding`（`Scada\Models\ScadaBinding.cs:34-73`）三个寻址字段：
  `VariableId`（权威）、`VariableName`（展示 + 旧数据兜底）、`ArrayIndex`（-1 = 整个变量）。
  **没有成员路径字段。**
- 运行期解析：`VariableRegistry.Resolve(id, name) => FindById(id) ?? FindByName(name)`
  （`Core\Binding\VariableRegistry.cs:142-143`），失败即 `MissCount++` + Warning
  （`Scada.Controls\Runtime\ScadaRuntimeBinder.cs:200-207`）。

### 2.3 模板体系已有一套"参数化 + 多选数组根"机制

- 参数化：`ScadaTemplateParameterizer.TryParameterize`（`Scada\Models\ScadaTemplateParameterizer.cs:40-144`），
  把 `Control[0]` / `Cys[0].HpTime` 改写成含 `{i}` 的形态，并输出"数组根清单"。
- 根提取：`ExtractArrayRoot`（`Scada\Models\ScadaTemplateExpansion.cs:465-476`）取**第一个 `[` 之前**的名字。
- 展开：`ScadaTemplateExpansion.TryPlan`（:119-），按实例序号替换 `{i}` 并重新解析引用。
- 严格替换：`ScadaTemplateExpansionOptions.StrictArrayReplacement / ArrayRoots / SelectedArrayRoots / OriginalIndex`
  （:34-47），`ReferenceNumber`（:442-463）决定每条引用用实例序号还是原始下标。
- 多选 UI 先例：`ScadaTemplateInsertOptionsEditor` 的复选框清单
  （`VisionMaster\Views\Controls\ScadaTemplateInsertOptionsEditor.xaml.cs:57`、`TryApply` :105-108），
  产出 `IReadOnlySet<string> selectedArrayRoots`。
- 严格选择随实例落盘：`ScadaElement.TemplateStrictRoots`（`Scada\Models\ScadaElement.cs:192-220`）。

### 2.4 变量选择器是单选、且无作用域

- 列表 `SelectionMode="Single"`、`SelectedItem="{Binding SelectedVariable}"`
  （`VisionMaster\Views\DialogViews\ScadaVariablePickerView.xaml:209-216`）。
- ViewModel 只有一个 `SelectedVariable`（`ScadaVariablePickerViewModel.cs:75`），
  过滤只有关键字 `Keyword`（:64-72、:171-188）。
- 打开时列出**全部** `GlobalVariables` + `SystemVariables`（:267-289）。
- `IScadaVariablePicker.Pick`（`VisionMaster\Services\IScadaVariablePicker.cs`）没有作用域/过滤参数（探针 P7）。

### 2.5 `TemplateStrictRoots` 不参与绑定期校验

只出现在三处：
- 写入：`ScadaEditorViewModel.InsertTemplateAt`（`VisionMaster\ViewModels\ScadaEditorViewModel.cs:1615-1625`）
- 传递：`ScadaTemplateBatchInserter.cs:104`
- 读回：`ScadaTemplateInstanceRefresher.cs:95-110,182`

**没有任何选择器 / `TrySetBinding` / 运行期消费者。** 探针 P6 已实测：严格根为 `["Recipes"]` 的模板实例，
照样能绑到根外的 `Unrelated`。

## 三、探针证据

探针：`tools\probes\_StructBindingProbe`（已登记进 `tools\probes\probes.json`，名字 `StructBindingProbe`）。
输出 `RESULT: ALL_OK`，退出码 0。日志 `artifacts\logs\20261029\probe-struct.log`。

| 编号 | 结论 | 实测输出 |
|---|---|---|
| P1 | `Recipes[0].Title` 可参数化，根 = `Recipes`（外层名，不含下标） | `Recipes[{i}].Title` / root=`Recipes` |
| P2 | 展开后实例 1 绑到 `Recipes[1].Title`（独立变量名，`ArrayIndex=-1`） | `Recipes[1].Title / idx=-1` |
| P3 | **嵌套下标被一并替换** | `Recipes[0].Ints[0]` → `Recipes[{i}].Ints[{i}]` |
| P4 | **后果：实例 1 静默绑到 `Recipes[1].Ints[1]`（应为 `Ints[0]`），全程不报错** | `Recipes[1].Ints[1]` |
| P5 | 结构体根不是变量 | `Recipes[0]`=null，`Recipes`=null |
| P6 | 严格根不拦绑定 | 绑到 `Unrelated` 成功 |
| P7 | 变量选择器无作用域参数 | `Pick(Guid currentId, String currentName, Action…)` |

## 四、风险点（按严重度）

1. **嵌套下标静默错绑（P3/P4）** —— 最危险，因为**不报错**。本次导入的 `Recipes[0].Ints[0..19]`
   正是嵌套形态：模板批量插入 20 个实例，实例 i 会绑到 `Recipes[i].Ints[i]`，看起来"有值"，
   实际读的是错成员。**这条与本次需求无关也必须修。**
2. **结构体根不可寻址（P5）** —— 任何"绑结构体"的设计，若不在模型/引用层造出可解析的目标，
   运行期就是空值 + Warning，画面上表现为"配了没反应"。
3. **需求③只在选择器过滤不够** —— 还有一条**不经过选择器**的通道：图表数据项
   `ScadaChartItem.Variable`（`Scada\Models\ScadaChartData.cs:18-30`）、数据表格列
   `ScadaGridColumn.Variable`（`Scada\Models\ScadaDataGrid.cs:17-30`）、XY 图 `XVariable/YVariable`
   （`Scada.Controls\Elements\XYChartElement.cs:48-56`）——它们存变量名、运行期按名字解析
   （`ChartPaint.Read` :440-450、`DataGridElement.TryResolve` :809-815、`XYChartElement.TryRead` :247-253），
   不产生 `ScadaBinding`。要真正做到"只能来自结构体"，这条通道得一起管。
4. **成员增删的级联没有规则** —— 引用按 `VariableId` 跟随（`ScadaBinding.Matches`
   `Scada\Models\ScadaBinding.cs:130-137`；改名级联 `IReadOnlyWorkspaceContext.OnVariableRenamed` :299-375）。
   重新导入时结构体成员新增/删除/改名，模板实例该怎样？目前没有任何机制。
5. **多品牌命名语法不同** —— `ExtractArrayRoot` 只认第一个 `[`，`TryParameterizeReference` 用
   `name.Replace("[index]", "[{i}]")` 全量替换（`ScadaTemplateParameterizer.cs:414-425`）。
   `A.B[0]`、`A[0].B[1]` 这类其它品牌的形态都会走"全替换"。

## 五、建议的落地顺序（不是工作量承诺）

1. **先修 P3/P4 的静默错绑**：把"全量 Replace"改成"只替换指定层"，或明确拒绝嵌套下标参数化并报错。
   独立于新需求，属于缺陷修复。
2. **需求③最便宜**：给 `IScadaVariablePicker.Pick` 加作用域参数 + picker 过滤 +
   `ScadaPage.TrySetBinding` 加白名单校验；同时把"属性袋里的变量名字符串"通道纳入校验。
3. **需求①决定形态**：优先做"路径概念"（`ScadaBinding` 增加成员路径，或 picker 把结构体展开成成员），
   不动 Core 的持久化契约；只有确实需要"结构体本身作为一个可监视对象"时才做模型实体。
4. **需求②多选**：`SelectionMode` 改多选 + 回调改成集合，UI 参照
   `ScadaTemplateInsertOptionsEditor` 的复选框清单；注意根粒度目前是外层名（P1），
   要精确到 `Recipes[0]` 需要改 `ExtractArrayRoot`。

## 六、未验证 / 边界
