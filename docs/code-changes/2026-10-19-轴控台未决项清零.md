## 1. 三条运动口径的最终裁定

三条都按「安全动作优先、使能从严」定，**不再保留"流程侧一套、动作表另一套"的分叉**。

| 决策点 | 最终口径 | 落点 |
| --- | --- | --- |
| 报警/安全停机时能不能停 | **能**。停止/失能是安全动作，`Alarm` 与 `SafeStopped` 都放行 | `MotionCommandGate.CheckSafetyAction`、`MotionDeviceBase.CheckGateLocked` |
| 报警/安全停机时能不能失能 | **能**（清报警前往往要先失能） | 同上 |
| 报警时能不能使能 | **不能**。使能给伺服上电、有机械后果，必须先清报警 | `MotionCommandGate.CheckEnable(device, enable: true)` |
| 卡级清报警 vs 单轴清报警 | 动作表/轴控台按 `PhysicalAxis` **只清那一根**；卡级 `ClearAlarm(out error)` 仍清全部（`PhysicalAxis = -1`） | `ZMotionCard` / `VirtualMotionCard` / `MotionActionExecutor` |
| 清报警后什么时候回 Online | 由**轮询**确认"所有轴都没有致命信号"才回 Online，不在命令完成回调里直接置 | `MotionDeviceBase.DetectCriticalSignals` |
| 清完立刻又报同一原因 | 清报警成功时摘掉该轴的报警去重记录，否则新一轮报警会被 `continue` 掉、状态停在 Online | `MotionDeviceBase.ExecuteOne` |

**为什么不在命令完成回调里直接置 Online**：清报警可以按单轴下发；命令线程只认识被清的那一根，
另一根还在报警时直接置 Online 就是"误放行"。只有轮询线程拿得到所有轴的最新状态。

**为什么 `SafeStopped` 也放行停止/失能**：基类在失联时已经 `SafeStopCore` 过一次，但操作员
仍可能想再停一次（比如卡刚恢复通信）；拒绝它只会制造"越危险越不发"。

**未连接 / 正在连接仍拒绝**：这两种状态下命令线程不在跑，收下的命令只会躺在队列里，
反而会制造"已经发了停止"的假象。

## 2. 清报警按轴下发

- `ZMotionCard.ExecuteCommandCore` 的 `ClearAlarm`：
  - `PhysicalAxis >= 0` → 只清 `Descriptor.FindAxis(axis)` 那一根；
  - `PhysicalAxis < 0` → 沿用旧行为清全部启用轴。
- `VirtualMotionCard` 同口径；新增 `SetSimulatedAlarm(axisIndex, value)` 供断言制造
  "两根轴都报警、只清一根"的场景。
- `MotionDeviceBase.ClearAlarm(out error)` 显式写 `PhysicalAxis = -1`，把"卡级清全部"的语义
  从"依赖默认值"变成"写清楚"。

**顺带修掉的真 bug**：旧实现里组态动作表/轴控台走的是 `Enqueue(ClearAlarm)`，不是
`ClearAlarm(out error)` 便捷 API；便捷 API 才会把状态从 `Alarm` 置回 `Online`。
所以面板上点「清报警」会显示成功，卡却一直停在 `Alarm`，后续使能/定位全被门禁拒绝。
现在改由轮询在"所有轴无致命信号"时回 Online。

## 3. 候选轴摘要随轴改名实时刷新

- `MotionAxisRegistry` 新增 `Changed` 事件：轴增删/改名/换卡/换轴号，以及 `EnsureFresh`
  发现外部改动时，在**锁外**广播（订阅方异常被吞掉，不影响索引）。
- `ScadaPropertyViewModel` 注入 `MotionAxisRegistry`，订阅 `Changed`：
  - 重取「轴 Id → 最新轴名」快照；
  - 对每个 `ScadaAxisListRow` 抛 `Summary` 变更通知（后台线程触发时先切回创建 VM 的 Dispatcher）。
- `ScadaAxisListRow.Summary` 不再直接读属性袋里那份落盘 JSON 的名字，而是按 Id 问快照；
  查不到（轴已删除）才回退到落盘名并标注「已移除」。
- 轴选择弹窗写回时仍会写当时的名字；但摘要显示从此只认 Id 对应的最新名。

## 5. 分发器 → 运动执行器整链断言（AX13）

新增 `MotionDispatcherChainChecks`，用真实 `ScadaActionDispatcher` + 真实 `MotionActionExecutor`
+ 假设备/假注册表跑三档：

1. **成功**：`Dispatch` 一条 `MotionMoveAbsolute` → 设备 `LastCommand` 是 `MoveAbsolute`、
   日志里有「已下发（未等到位）」；
2. **未接入**：构造时不注入 executor → 日志如实写「运动模块未接入」，设备没有任何下发；
3. **静默**：点动遇轴忙 → 执行器返回 false + 空 message，分发器一行日志都不写。

这三档覆盖的正是"点了按钮没反应"时现场最需要区分的三种情况。

## 6. 旧轴控件迁移（AX15）

`ScadaDocument.MigrateLegacyAxisElements(out messages)`，在 `SolutionService.LoadAsync`
的 `EnsureIdentity()` 之后调用一次（幂等）：

- **只在"整页只有一块轴面板 + 一张旧点位表"时自动合并**：
  - 候选轴取并集（面板顺序在前、旧表独有在后，按 Id 去重）；
  - 面板写 `ShowPoints=True`、`ShowCommands=True`；
  - 面板尺寸补到至少 320×470（点位区 6 行需要这个高度；只放大不缩小）；
  - 删除旧点位表（先取并集再删，删除失败不留半合并状态）；
  - 迁移走 `ScadaWriteGuard.Suspend` + `ScadaChangeScope.SuspendRecording`，不进撤销栈。
- **其余页面只产出提示、不动版面**：同页还有其它图元、多块面板、多张旧表、旧表锁定，
  都只写一条诊断（`Debug.WriteLine`，前缀 `[SCADA 轴控件迁移]`），让用户自己决定。
- 为什么只在这个条件下自动做：旧画面里轴面板与点位表往往摆在不同位置，无条件合并会
  删掉用户画面上的一块、并在原处留一个洞。整页只有这两个图元时，这一页本来就是
  "一根轴的调试页"，合并不会撞到任何别的图元。

## 7. 视觉复核（离屏渲染 + 人眼）

`ScadaChecks` AX14 在 320×470（轴控台默认）与 280×470（轴面板预设宽）两档真渲染，
产物在 `ScadaChecks/bin/Debug/net9.0-windows/artifacts/`：

- `scada-axis-console-320.png`
- `scada-axis-console-280.png`

本轮从图上抓到并修掉的三件事：

1. **轴选择器是空框**：模板原来绑 `SelectedValue`，模板套上那一刻 `SelectedAxisId` 已有值、
   但 `ItemsSource` 还没到，ComboBox 把选中置空。改为 `SelectedItem` 绑新的
   `SelectedAxisItem` DP（与 `SelectedAxisId` 双向同步），Selector 会在 ItemsSource 到位后
   重新解析。AX14 有一条「轴选择器显示当前轴名」守门。
2. **280 宽下点位行右侧被切**：原行固定列 64+52 + 两颗按钮，窄面板装不下。
   列宽收到 58/46、按钮内边距/边距各收 1px，并给 `ScrollViewer`/`ItemsControl` 加
   `HorizontalContentAlignment=Stretch`、给点位表 Border 加 `MaxWidth` 绑定到父 StackPanel。
   现在 280 宽下「示教/定位」完整可见。
3. **"6 行点位"实际显示 8 行**：`PointsHeight` 原来算成 `18 + rows*22`，但表头在
   ScrollViewer 外面，150px 的视口按 18px 行高能塞 8 行。改为 `rows*22`，行 Grid 加
   `MinHeight=20`（+ 上下各 1px 边距 = 22），现在 6 行就是 6 行。

**仍欠真机**：点动按住/回零长按的手感、真实触摸屏上的滚动惯性，离屏渲染验不出来。

## 7.1 点位表列头与示教/定位二次确认（同日追加）

用户反馈「点位表只有位置没有速度」——实际速度列一直在（第二个数字框，可编辑），
只是标题行只有「点位 + 一句提示」，没有列头。本轮补上列头，并给示教/定位加二次确认开关。

### 7.1.1 列头

点位表的标题行改成与数据行**同列宽**的列头：

| 点位 | 位置(mm) | 速度(mm/s) | 操作 |
| --- | --- | --- | --- |

- 列宽与数据行一致（`* / 58 / 46 / Auto`），左/右边距都是 4，所以列头与数字严格对齐；
- 原来那句「示教 = 写当前位置 · 定位 = 走到该点」挪到「点位」的 ToolTip，不再占一整行；
- 320/280 两档离屏图复核：列头完整、没有把数据行挤下去。

### 7.1.2 二次确认开关

- 新增属性 `ConfirmCommands`（「操作二次确认」，操作组，**默认 True**）。
- 示教/定位的执行顺序固定为：**权限 → 确认 → 出口**：
  1. `CheckCanRun` 先判命令出口、选中轴、`RequiredRole`；没权限的人**根本不会弹确认框**；
  2. `ConfirmCommands=true` 时弹一次确认，文案带轴名、点位名、当前/目标位置与速度；
  3. 用户取消 → 不落出口、不写配置；确认 → 才调 `TryTeach` / `TryMove`。
- 关掉开关 = 一键直接执行，权限仍照常检查（这个开关只控制"多问一句"，不是权限替代品）。
- 开关为 true 但宿主没接确认出口 → **拒绝执行**并提示「二次确认服务未接入，已取消操作」，
  不静默跳过——静默跳过等于把防误触悄悄关掉。
- 出口：`IScadaConfirmationService`（`Scada.Controls`）→ `ScadaRuntimeContext.Confirmations`；
  宿主 `ScadaConfirmationService` 走 `EasyDialog.ShowSync`，无 `Application` 时返回 false。
- 断言（AX10 新增 6 条）：列头文字、默认开启、示教确认文案、定位确认文案（含位置与速度）、
  取消不落出口、关开关不弹窗；权限不足那条同时断言"不弹确认框"。
