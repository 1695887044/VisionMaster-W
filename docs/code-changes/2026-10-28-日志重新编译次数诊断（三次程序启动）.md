# 日志里的「重新编译」为什么出现好几次（2026-10-28）

> 触发：用户看 `解决方案\视觉样例对拍\Logs\2026-10-28.log`，看到「重新编译并注册会话」出现多次，与"程序只在启动时才编译"的印象不符。
> 结论：**这行不是 .NET 构建，是流程编译**；今天出现 3 组共 21 条 = **程序今天启动了 3 次**，每次启动后主流程第一次跑时把 7 个工位子流程各编译一次。一次运行之内没有重复编译。

## 2. 已做（取证过程）

### 2.1 这行日志是谁打的、什么条件下打

`Engine\FlowSessionFactory.cs:70` 调 `compiler.Compile(...)`，`:90` 打这条日志。触发条件是 `TryEnsureSession` 里两个分支：

- `runtime.GetSessionByName(flow.FlowName)` 返回 null —— 当前进程里还没有这条流程的会话（**进程刚启动**）；
- `IsStale(existing, flow)` —— 流程 `Version` 变大（图纸改过）或 `FlowID` 变了（换了方案的同名流程）。

编译产物是内存里的 `FlowSession`（注册进 `IRuntimeManager`），**不落盘**，所以进程一退出就全丢，下次启动第一次跑必然重编译。

调用方共 5 处：`Engine\FlowInvoker.cs:81`（父流程调用子流程）、`Engine\FlowAutoRunner.cs:52`（自动/循环触发）、`VisionMaster\Services\ScadaFlowRunner.cs:91/142`（组态运行态按钮）、`VisionMaster\Services\HttpImageServer.cs:259`（HTTP 触发）、`VisionMaster\ViewModels\FlowListViewModel.cs:502`（流程列表运行）。

本次日志里编译后紧跟 `Main.调用工位_xxx 流程「…」执行完成（xxx ms）`，说明走的是 **Main 流程 → FlowInvoker → 子流程按需编译**这条路径。

### 2.2 怎么证明是"三次进程启动"而不是"一次运行里编译三回"

`[启动自检] 通讯连通性` 这行只在 `VisionMaster\App.xaml.cs:1032` 的 `OnInitialized` 里由 `RunCommunicationCheckInBackground()` 打出，**每个进程一次**（R57：该项被挪出启动自检链、改由主窗口显示后后台跑，日志口径不变）。

今天该行出现 3 次（08:38:04 / 08:44:45 / 08:52:50），且每一组编译都落在对应启动之后，中间没有任何"同一进程内 Version 变大"的重编译。

### 2.3 排除掉的错误判据

`[报警] 引擎已挂载` + `[通讯] 方案通讯配置已装配` + `[系统变量] 通讯设备拓扑变化` 这一串，**进程启动自动加载方案**和**运行期打开另一个方案**都会打，长得一模一样，不能用来数启动次数。能数的只有 `[启动自检] 通讯连通性`。
