# 串口隐藏无效的「超时时间(ms)」（给属性面板补 Visible 开关）

日期：2026-09-21
承接：[2026-09-21-读超时字段落地.md](./2026-09-21-读超时字段落地.md)（该文「已知边界 1」提出：串口界面上同时显示无效的「超时时间(ms)」与有效的「读超时(ms)」，需另行确认是否收口）

---

## 1. 需求与决策

### 1.1 问题

串口配置（`SerialConfig`）会同时显示两个超时输入框：

| 界面字段 | 模型字段 | 在串口上是否生效 | 原因 |
| --- | --- | --- | --- |
| 超时时间(ms) | `ConnectionConfigBase.TimeoutMs` | **不生效** | HSL `ModbusRtu.Open()` 只是打开本地串口句柄，不存在网络建连等待，无「TCP 建连超时」这个量可消费 |
| 读超时(ms) | `ConnectionConfigBase.ReadTimeoutMs` | 生效 | 下发到 HSL `ReceiveTimeOut`（TCP / 串口共用入口） |

「超时时间(ms)」在串口上是一个**改了没有任何反应**的输入框，会让现场用户误以为调它能解决串口通信慢的问题。

### 1.2 关键调研结论（决定了方案选择）

1. **属性面板没有「隐藏字段」的能力**。`SuperDisplayAttribute` 原先只有 `IsReadOnly / GroupPath / Order / GroupOrder / Name / Description / ColSpan / RequireRefresh`；生成器的唯一过滤条件是 `Attribute.IsDefined(p, typeof(SuperDisplayAttribute))`——**有特性就显示，没有就隐藏**。所以想隐藏继承来的字段，绕不开给这套机制加一个「可见性开关」。
2. **不能用 `new` 隐藏**。生成器用 `GetProperties(BindingFlags.Public | BindingFlags.Instance)`，会同时返回基类与子类两个同名 `PropertyInfo`；基类那份仍带 `[SuperDisplay]`，过滤条件依旧命中 → **同一字段渲染两行**。
3. **必须用 `override`**。`GetProperties` 对重写属性会去重，只返回最派生的那一个。这正是本项目既有的约定做法：`EthernetConfigBase.Port` 是 `virtual`，`SiemensS7Config` 用 `override int Port` 覆盖默认值 102。
4. **特性继承方向对我们有利**。子类 override 后重贴 `[SuperDisplay(Visible = false)]`，`GetCustomAttribute<SuperDisplayAttribute>()`（`inherit` 默认 true、`AllowMultiple = false`）返回的是**最派生**的那一份，所以基类的特性会被子类那份覆盖掉。

### 1.3 决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 收口方式 | **彻底隐藏**（用户选定） | 界面上不留误导性输入框，串口只保留真正生效的「读超时(ms)」 |
| 隐藏信号放在哪 | 扩 `SuperDisplayAttribute` 加 `Visible`（默认 `true`） | 与既有 `IsReadOnly / RequireRefresh` 同族，声明式、通用；默认值保证**全项目零行为变化** |
| 怎么让子类表达 | `TimeoutMs` 改 `virtual` + `SerialConfig` `override` 重贴特性 | 复用 `SiemensS7Config.Port` 已验证的 override 约定；无嵌套透传风险 |
| 模型字段是否删除 | **保留**（默认 3000） | 只摘界面显示，删字段会破坏老方案反序列化兼容 |

### 1.4 兼容性与行为变化

- `Visible` 默认 `true` → **所有既有字段的显示行为完全不变**（过滤器由「有特性」变为「有特性且 Visible」，对未声明 Visible 的字段等价）。
- `TimeoutMs` 由 `int` 改 `virtual int` → 源码级兼容，唯一子类 `SerialConfig` 改为 override 后仍可正常读写、`Clone()` 仍成立。
- **界面上唯一可见变化**：串口连接设置弹窗的「高级参数」组里不再出现「超时时间(ms)」，只剩「重试次数 / 重试间隔(ms) / 读超时(ms)」。以太网连接不受影响。

## 2. 修改文件清单

### 2.1 `Core\UiAttributes\SuperDisplayAttribute.cs`

新增可见性开关（插在 `ColSpan` 与 `RequireRefresh` 之间）：

```csharp
/// <summary>
/// <para>该字段是否在属性面板中显示，默认 true（不写就等于显示，老字段行为不变）。</para>
/// <para>用途：子类隐藏"继承来但对自己无意义"的字段。做法是子类用 <c>override</c> 重贴
/// <c>[SuperDisplay(Visible = false)]</c>。</para>
/// <para>⚠️ 必须用 <c>override</c> 而不是 <c>new</c>：<c>GetProperties()</c> 会把基类与子类
/// 两个同名属性都反射出来（基类那份仍带 <see cref="SuperDisplayAttribute"/>），
/// 结果是同一字段被渲染两行。</para>
/// </summary>
public bool Visible { get; set; } = true;
```

### 2.2 `Core\CommunicationContracts\ConnectionConfigBase.cs`

`TimeoutMs` 改虚，让子类可以覆盖其显示特性：

```csharp
public virtual int TimeoutMs { get; set; } = 3000;   // 原为 public int
```

### 2.3 `Core\CommunicationContracts\Config\SerialConfig.cs`

新增 override，把该字段从属性面板摘掉（**不是**从模型里删掉）：

```csharp
/// <summary>
/// <para><b>串口不使用"连接超时"</b>——HSL 的 <c>ModbusRtu.Open()</c> 只是打开本地串口句柄，
/// 不存在网络建连等待，所以基类的 <see cref="ConnectionConfigBase.TimeoutMs"/> 在串口上无处消费。</para>
/// <para>串口真正生效的超时是「读超时(ms)」（<see cref="ConnectionConfigBase.ReadTimeoutMs"/>）。</para>
/// <para>这里用 <c>override</c> 把它从属性面板隐藏（<c>Visible = false</c>），
/// 避免界面上出现一个"改了没有任何反应"的输入框。字段本身仍保留在模型中（默认 3000），
/// 以保证与老方案的序列化兼容。</para>
/// </summary>
[SuperDisplay(Visible = false)]
public override int TimeoutMs { get; set; } = 3000;
```

> `SerialConfig.Clone()` 里原有的 `TimeoutMs = TimeoutMs,` **无需改动**：override 后读写的是同一份属性，克隆行为不变。

### 2.4 `UI\Controls\CustomControl\PropertyGrid\FlatPropertyGrid.cs`（弹窗实际使用的控件）

过滤条件加 `Visible` 判断：

```csharp
// Visible 默认 true，老字段行为不变；子类可用 override 重贴 [SuperDisplay(Visible = false)] 摘掉某个字段
var properties = BindingObject.GetType()
    .GetProperties(BindingFlags.Public | BindingFlags.Instance)
    .Where(p => p.GetCustomAttribute<SuperDisplayAttribute>()?.Visible == true)
    .ToList();
```

> 这一处就够覆盖串口场景：`CommunicationConfig.Config` 贴的是 `[PropertyItem]`，由 `NestedPropertyGridGenerator` 再 new 一个子 `FlatPropertyGrid` 承载 `SerialConfig`，所以子网格走的仍是本方法。

### 2.5 `UI\Controls\CustomControl\PropertyGrid\CardPropertyGrid.cs`

同一处过滤逻辑同步修改，**防止两个控件行为分叉**（该控件虽未被 `EasyDialog` 使用，但属同门兄弟）。

## 4. 已知边界

1. **断言只证明「模型层声明正确」，证明不了「界面上框真的消失」**。C9 读的是特性元数据，不启 WPF 窗体。真正的界面效果需实机点验：打开串口连接 → 编辑参数 → 「高级参数」组里应只见「重试次数 / 重试间隔(ms) / 读超时(ms)」。
2. **`CardPropertyGrid` 已同步但无断言覆盖**。它未被 `EasyDialog` 使用，本次只做代码对齐；若将来启用，其行为应与 `FlatPropertyGrid` 一致。
3. **`Plugins\Plugin.PreProcessing\Models\PreprocessOperator.cs` 的算子属性面板未接入 `Visible`**。它自己另有一份 `GetCustomAttribute<SuperDisplayAttribute>() != null` 过滤，本次未改。当前没有算子属性声明 `Visible = false`，故无实际影响；但若将来算子想隐藏字段，需同步改造那一处。
4. **只做了「隐藏」，没有做「解释」**。串口用户若从老方案带过来一个非默认的 `TimeoutMs`，界面上看不到它、也改不了它。当前判断是：该值在串口上本来就不生效，看不见反而是正确的。
5. **`TimeoutMs` 改 `virtual` 是一个契约松动**。今后任何子类都可以覆盖它的显示与默认值；若某子类覆盖后忘记 `Clone()` 里对应字段，会出现「复制连接后值被重置」。当前只有 `SerialConfig` 覆盖，且其 `Clone()` 已含该字段。
