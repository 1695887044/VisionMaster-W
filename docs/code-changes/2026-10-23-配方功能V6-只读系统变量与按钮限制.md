## 一、怎么新建配方（软件里）

1. 打开方案，把要纳入配方的步骤参数/局部变量调成**目标产品**的值（这是"捕获"的来源）。
2. 点顶栏的配方图标（硬件管理右边），或走「系统 → 配方管理」。
3. 在左侧「从当前已确认参数捕获一份新配方」里填：
   - **配方名称**（必填，方案内唯一）；
   - 产品编码、备注（可空）；
   - 点「捕获当前值」。
4. 左侧清单出现新配方；选中后在右侧表格逐项核对：
   - 表格列：目标 / 参数 / 类型 / 配方值 / 当前值 / 状态；
   - 顶部工具栏可「添加参数」「删除参数」；下方可「重命名」「清除生效」。
5. 需要立即生效：点「应用」（先出差异确认，再整单写入）；要顺带落盘：点「应用并保存」。
6. 导出/导入：左侧底部「导出 / 导入」，文件是 `.vmrecipe`（不含设备字段）。

配方编辑**只在主软件里**；SCADA 组态侧没有配方编辑器，运行态只做"切"和"看"。

## 二、SCADA 只读显示：8 条系统变量

新增 `Core/Binding/RecipeVariableCatalog.cs` + 宿主适配器
`VisionMaster/Services/RecipeVariableSource.cs`，在 `SystemVariableModule` 里接入统一宿主。

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `System.Recipe.Active` | bool | 当前是否有生效配方 |
| `System.Recipe.Name` | string | 当前生效配方名 |
| `System.Recipe.Code` | string | 产品编码 |
| `System.Recipe.Version` | int | 配方内容版本（`vN` 的 N） |
| `System.Recipe.Deviation` | int | 当前参数与配方不一致的项数 |
| `System.Recipe.EntryCount` | int | 配方参数条数 |
| `System.Recipe.Summary` | string | 参数摘要，每行一项，如 `检测.Threshold = 0.75` |
| `System.Recipe.Status` | string | `已生效 / 偏离 N / 未应用 / 未启用 / 配方悬空` |

三条口径：

- **只读**：用 `SystemVariableModel`，不实现 `IWritableVariable`；写路径如实拒绝，
  界面双向绑定误写静默忽略（与运动/通讯系统变量同一语义）。
- **确定性身份**：`SHA1("recipe-var|{字段}")` 前 16 字节；画面绑定重启后仍命中。
- **实例复用**：8 个模型只建一次，之后只更新镜像值；不会让已绑定画面失联。

### 怎么在画面上显示

1. 组态态打开目标画面，从工具箱拖一个「文本」图元。
2. 在属性面板把 `Text` 绑定到 `System.Recipe.Summary`（显示全部参数），
   或分别绑 `System.Recipe.Name` / `.Version` / `.Status` 做标题行。
3. 文本图元会自动换行；`Summary` 每行一项，超过 50 项时末行显示「… 共 N 项」。
4. 变量选择器里来源徽标是「系统」，与用户变量区分；不能编辑/写回。

刷新时机：应用/清除/捕获/增删参数/改名/删除配方、切换方案时立即刷新。
参数被流程画布或属性面板直接改动时，`Deviation` 要等下一次配方状态变化才刷新（v1 已知边界）。

## 三、SCADA 只能通过按钮切配方

`ScadaEventEditorViewModel` 的动作下拉改为**按宿主/事件裁剪**：

- 只有**按钮图元**（`TypeKey` 以 `Button` 结尾：`Hmi.Button` / `Hmi.BitButton` / `Hmi.AckButton`）
  的**按下/释放**事件，下拉里才有「应用配方」；
- 页面加载/卸载、变量事件、普通图元事件一律不出现这一项；
- 已配置的旧数据不受影响（行还在、仍可执行）；这里收的是"以后怎么配"的入口。

配置路径：选中按钮 → 事件「按下」→ 添加动作「应用配方」→「选择配方」→ 选目标 → 运行态点按钮即切换。

## 四、验证结果（2026-10-23 实测）

| 命令 | 结果 |
| --- | --- |
| `dotnet build Core\VM.Core.csproj -m:1 -nodeReuse:false` | 0 错误 |
| `dotnet build VisionMaster\VisionMaster.csproj --no-dependencies` | 0 错误 |
| `dotnet build RecipeChecks\RecipeChecks.csproj --no-dependencies` | 0 错误 |
| `dotnet build VisionMaster.sln -m:1 -nodeReuse:false` | **0 错误** |
| `RecipeChecks.exe` | **通过 138 / 失败 0**（V5 的 111 + V6 新增 27） |
| `tools\run_gates.ps1 -Only RecipeChecks,UIThemeSmokeTest` | **2 steps green** |
| 真实启动 | 日志出现 `[系统变量] 配方 8 条 / 通讯 8 条 / 相机 0 条已接入统一宿主` |

V6 新增断言覆盖：

- 8 条变量、`System.Recipe.` 前缀、全部只读（不实现 `IWritableVariable`）；
- 无配方 → `未启用`；捕获后 → `未应用`；应用后 → `已生效` + Name/Code/Version/EntryCount/Summary；
- 摘要含 `Threshold = 0.75` / `Mode = Circle` / `Setpoint = 10.5`（字符串不带 JSON 引号）；
- 改参数 + 状态刷新后 `Deviation=1`、`Status=偏离 1`；清除生效后回到 `未应用`；
- 直接写 `IPort.Value` 被忽略；
- 两次构造变量 Id 完全相同；
- 按钮按下可配「应用配方」，页面加载/变量事件不可配。
