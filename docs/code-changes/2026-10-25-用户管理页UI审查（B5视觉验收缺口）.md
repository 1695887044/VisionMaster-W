## 二、已做（本轮审查发现）

### P0-1 账号页签内层「关闭」是死按钮

- 证据：`ScadaUserManagerView.xaml:484` 绑 `CloseCommand`；实现是 `ScadaUserManagerViewModel.cs:69` 的 `RequestClose.Invoke(...)`。
- 但 `Account` 是宿主直接 `new` 出来的子 VM（`UserManagementViewModel.cs:38`），全仓没有给它赋 `RequestClose`（grep `Account.RequestClose` / `.RequestClose\s*=` 均无命中）。Prism 只在把 VM 当对话框托管时注入监听器。
- 后果：点这个「关闭」不会关窗（监听器为空时空跑；若 Prism 该版本不判空则抛异常）。**B5 复用旧弹窗时引入的回归**：旧页里它是真关闭。
- 判据：点一次内层「关闭」，窗口应关闭或按钮应不存在——现状两者都不成立。

### P0-2 权限目录「32/32 满额禁用新建」永不生效

- 证据：`ScadaPermissionCatalogView.xaml:48`
  `IsEnabled="{Binding IsFull, Converter={ui:BooleanToVisibilityConverter}, ConverterParameter=Inverse}"`。
- 转换器对 bool 输入**返回 `Visibility`**（`UI\Controls\Converters\BooleanToVisibilityConverter .cs:19-23`），不是 bool；绑到 `IsEnabled` 类型不匹配 → 绑定失败 → 目标保持默认 `true`。
- 后果：基线 v3.1 补充态 2（满额禁用 + 计数转警告色 + 底部上限提示）三条里，禁用这条**静默失效**；另两条（警告色、底部提示）根本没实现。
- 另：`AddCommand` 也无 CanExecute（`ScadaPermissionCatalogViewModel.cs:24`），命令层同样不拦。

### P0-3 审计页丢列、无表头、无筛选、无底部计数

- 证据：`UserManagementView.xaml:167-189` 是 `ItemsControl` 手写 6 列，绑定 `Timestamp / Actor / Subject / ActionText / OutcomeText / DetailRemainder`。
- CSV 是 **7 列**（`ScadaAuditWriter.cs:213-216`：时间/操作者/对象/事件/动作/结果/说明），`EventText` **完全没有绑定** → 事件列丢失。
- 基线 §3.3 要求：筛选行（日期范围 + 操作者 + 结果 + 显示未归属）、7 列表格、底部「显示 X 条 / 共 Y 行 / 已跳过 N 行」。现状三者全无。
- 无表头：6 列裸数据，用户无法知道哪列是对象、哪列是动作。
- 时间列 `{Binding Timestamp}` 直绑 `DateTime`（`ScadaAuditReader.cs:12`），走当前区域性 → 截图是 `10/25/2026 6:54:09 PM`；基线是 `HH:mm:ss`。会话页 `ConnectedAt` 同样直绑（`UserManagementViewModel.cs:148`）。
- 结果列直接显示 CSV 原值：截图出现 `Warning`，而当前枚举只有 成功/未执行/失败/被拒绝（`ScadaAuditWriter.cs:27-54`）→ 历史值未归一，中英混排，且没有基线要求的颜色 chip。
- 行间只有 4px 间距、无分隔线/斑马纹；6 列宽间距下横向跟踪困难。

### P0-4 权限目录缺 4 类信息，且内置行可点删除

- 证据：`ScadaPermissionCatalogView.xaml:51-66` 只有 Key / 名称 / `IsBuiltIn` 三列。
- 基线 §3.5 要求：名称 / Key / **使用组数** / **类型 chip** / **行内操作**。现状缺 3 列；`IsBuiltIn` 是 bool 直绑，屏幕上是 `True`（截图 3），字号硬编码 10。
- `DeleteCommand` 是无 CanExecute 的 `DelegateCommand`（`ScadaPermissionCatalogViewModel.cs:26,117-127`）→ 内置行也能点「删除」，点了才由 store 报错。基线要求内置不可删、被引用不可删，并给出「N 个组 / M 个按钮引用」。
- 删除无二次确认（账号页的删除有，两页不一致）。

### P1-1 账号页 = 旧弹窗复用 → 双标题 / 双关闭 / 居中窄卡 / 两套色

- 证据：`UserManagementView.xaml:92` `<views:ScadaUserManagerView DataContext="{Binding Account}" />`；该视图 `Width="760"`（`:9`）、自带 45px 标题栏（`:144-164`，标题「用户管理」）、自带关闭（`:478-487`）、自带 `DropShadowEffect`（`:131-139`）。
- 现象：截图 1 出现两个「用户管理」、两个「关闭」；卡片仅 736 宽、两侧各留 ~170px、下方再留 ~40px，读起来像"页面上又开了一个弹窗"。
- 基线 §3.1 要求内容区左 300 + 16 + 右表单整页铺满；§8 明确旧页"不复用其视觉"。
- `prism:Dialog.WindowStyle`（`:20-30`）现在是死代码（不再当窗口托管）。

### P1-2 账号页缺基线列出的三块内容

- 搜索框：基线左卡头部「搜索账号名」+ 计数「4 个」+「+ 新建」；实现没有搜索，`新建账号` 在卡片底栏左侧。
- 确认密码：基线「新密码 + 确认密码」两栏；实现只有单个 `PasswordBox`（`ScadaUserManagerView.xaml:329-331`），打错无二次校验。
- 安全策略摘要 +「在系统设置中修改」：基线在右卡底部；实现该位置被「账号文件：ScadaUsers.json」占用（`:252-261`）。
- 按钮文案：基线「重置密码 / 保存用户组」，实现「重置 / 保存」；而「重置」实际执行 `CancelNewCommand`（放弃修改），语义与文案不一致。

### P1-3 同一屏两套调色板（可量化）

- 外层页壳用 `Dialog*`：`DialogAccentBrush = #0EA5E9`、`DialogAccentLightBrush = #E0F2FE`（`UI\Controls\Themes\Colors.xaml:161,163`）。
- 内层账号卡用 `Scada*`：`ScadaPrimaryButtonBrush = #409EFF`、`ScadaSelectedRowBrush = #ECF5FF`（同文件 `:87,93`）。
- 结果：主按钮两种蓝、选中行两种浅蓝、圆角 12 vs 8、内层多一层投影。违反 R114/R117。
- 注意：B4B5B6 文档「未做 #1」说 `ScadaUserManagerView.xaml` 还有 40 处 hex —— **该描述已过时**（现文件 0 处 hex）。问题不在 hex，在 `Scada*` 令牌本身就是旧调色板。

### P1-4 页签视觉与基线不符

- `TabControl` / `TabItem` 无样式（`UserManagementView.xaml:90-91`），渲染为默认 Fluent 方框式选中态（截图 1 那个带边框的块 + 右侧竖线）。
- 基线：44px 页签行、选中 2px 主色下划线、「在线会话」带计数徽标。现状三项都没有。
- 标题栏也缺基线要求的关闭按钮，只能点底栏「关闭」。

### P1-5 权限目录列不对齐（True 粘在名称后）

- 现象：截图 3 每行 `看运行画面True`。
- 根因：`ListBox` 未设 `ItemContainerStyle`，`ListBoxItem` 默认 `HorizontalContentAlignment=Left`，ItemTemplate 里的 `Grid` 拿到的是内容宽而非列表宽 → 第三列（70px）贴在第二列文字后面，选中高亮却是整行宽。
- 修法：`ItemContainerStyle` 设 `HorizontalContentAlignment=Stretch`（同类问题见 R139-B 树行口径）。

### P1-6 在线会话页同类缺项（未截图，代码可见）

- `UserManagementView.xaml:107-143`：6 列无表头、无「刷新」「全部踢下线」、缺基线要求的「会话」与「最近活动」两列。
- 空态是裸 `TextBlock`，不是 `DialogEmptyState*`（基线 §5.1）。

### P2-1 按钮普遍无 Style / 无危险语义

- 「管理用户组…」「刷新」「关闭」「新建」「改名」「删除」直接吃 Fluent 默认样式；基线 §5.1 要求走 `DialogPrimaryButton` / `DialogSecondaryButton` / `DialogDangerButton`。
- 权限目录的「删除」与「改名」同权重并排，无 danger 色、无间距分组。

### P2-2 出厂口令明文上屏

- `UserManagementViewModel.cs:78`：「当前使用出厂账号（admin/admin123）…」。
- 基线 FactoryFallback 文案只写「当前使用出厂管理员…」，没有口令。是否保留需按 R132 由用户裁定并写进已知偏差。

### P2-3 审计「未登录」与顶部横幅并存

- 顶部说当前用出厂 admin，下面 10 条操作者全是「未登录」。实际是运行态未登录操作，但页面上没有任何解释，容易被读成 bug。建议改「运行态未登录」或加脚注。

### P2-4 计数与说明列的细节

- 权限目录计数 `15/32` 是裸文本，基线是「已定义 N/32」+ chip。
- 审计说明列绑 `DetailRemainder`，把 `[sol=…]` 方案标签剥掉了；基线是保留前缀。
- 权限目录把英文 Key 放第一列、中文名放第二列，主次与基线相反。

## 五、踩过的坑（审查方法）

1. **"令牌化"不等于"和页面同色"**：`ScadaUserManagerView.xaml` 已经 0 处 hex，但引用的 `Scada*` 令牌是 #409EFF 旧蓝，外层 `Dialog*` 是 #0EA5E9。只查 hex 会漏掉这种"合规但撞色"。
2. **不能只凭截图判"没对齐"**：权限目录的 `True` 粘名字是 `ListBoxItem.HorizontalContentAlignment` 默认值造成的，肉眼看起来像"少了一个空格"，实际是列根本没铺开。
3. **截图里的「管理用户组…」不是被截断**：XAML 里就是省略号字符，别当宽度 bug 修。
4. **审计的 `Warning` 不是漏翻**：当前枚举只有四个中文值，`Warning` 是 CSV 里的历史/外部写入值，要在读取端归一，不是补一个 `[Display]`。
5. **旧弹窗复用的代价是"看不见的回归"**：`ScadaUserManagerView` 的 `CloseCommand` 在旧页里是真关闭，搬进页签后监听器没人注入，变成死按钮。复用前要按"它现在还被谁托管"重核一遍命令出口。
