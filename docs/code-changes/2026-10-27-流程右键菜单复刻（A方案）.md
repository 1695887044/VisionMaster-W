### 关键口径

1. **命令与绑定不动**：`MyViewModelProxy` + `PlacementTarget.DataContext` 靶点、`FlowCommand` 的 12 个 `CommandParameter`、动态标题 `FlowToggleHeader` 全部保留；新属性只驱动 `IsEnabled` / 徽标 / ToolTip。
2. **禁用态与命令体一致**：`CanCompileFlow` / `CanRunFlow` / `CanStopFlow` / `CanDeleteFlow` / `CanBatchDisplayWindow` 的判断条件逐条对应 `FlowCommandExecute` 里原有的拦截条件（含 `MandatoryFlows`、`StepsEncrypted`、`RunState`、`_runState`）。命令体本身没有改，所以属性漏刷新最多是灰/亮不同步，不会放行非法操作。
3. **暂停中允许批量设置**：`CanBatchDisplayWindow` 只拦 `RunningOnce` / `RunningContinuous`，与 `EditGate.ModuleParameters`（暂停放行参数编辑）同口径。
4. **删除只在骨架流程变灰**：`MandatoryFlows.IsMandatory`；运行中删除仍由命令体提示（未额外变灰，与设计稿 B4 一致）。
5. **徽标只做启用/禁用**：`FlowStateBadge`（当前：已启用 / 已禁用）；停止徽标按 Q4 建议后置（需要额外订阅 `RunState` 才能刷新）。
6. **图标全部已验证在字体里**：13 个码点（含新用的 `f204` / `f205`）在 `Font Awesome 6 Pro-Solid-900.otf` 的 `CharacterToGlyphMap` 里全部命中，不会出豆腐块。

## 五、踩过的坑

- **`ContextMenu` 的 `Style` 不会传给 `MenuItem`**：只给菜单挂 `FlowContextMenuStyle`，12 个项仍然吃系统默认模板。必须逐项挂 `FlowMenuItemStyle`——本轮第一次跑冒烟就是被静态检查当场抓住（`缺：FlowMenuItemStyle`）。
- **`BasedOn` 复用外框最省**：`FlowContextMenuStyle` 只覆盖 `Width=320`，圆角/阴影/页脚/滚动条全部继承 `StepContextMenuStyle`，没有第二份外框模板。
- **分组标题用 `Separator` + `Tag`，不要用 `IsEnabled=False` 的 `MenuItem`**：后者仍会被菜单键盘导航命中，也会吃掉高亮。
- **新图标码点必须在字体里查一遍**：`f204/f205` 是全仓第一次用，只靠"看起来像"会静默出豆腐块；判据是 `GlyphTypeface.CharacterToGlyphMap` 命中。
- **构建被运行中的 `VisionMaster.exe` 锁 `Modules\*.dll`**（`MSB3027/MSB3021`，报"文件被 VisionMaster (PID) 锁定"）：不是代码问题，等程序退出或换只构建宿主工程；**不要**为了过构建去杀用户正在用的进程。
- **并发会话会让"全绿"假红**：本轮遇到三次外部改动——`LogViewModel.cs` 重复方法（23:14:52 出现、23:16:18 自愈）、`DisplayDraw.cs`（23:17:36）、`ScheduleViewChecks.cs`（23:17:59）。判据是"失败项所属文件 + 该文件 mtime"，不是"构建退出码红=我的改动错"。
