# 图像赋值插件（Plugin.ImageAssign：把 HImage 写进全局图像变量）

补上「视觉流程 → 全局图像变量 → 组态图像显示图元」这条链路里**唯一缺失的一环：写**。

上一轮（见 [SCADA 图像显示图元](2026-09-24-SCADA图像显示图元.md)）已经把显示端做完，
但当时的"已知边界"第 1 条就写着：**流程 → 图像变量的回写路径不存在**。
本轮把这条路打通。

---

## 一、需求与决策

### 1. 需求

用户指令（逐字）：

> 「好的，新建图像赋值插件」

即：新增一个流程节点，把上游产出的 `HImage` 写进一个**指定名字的全局图像变量**，
供画面上的「图像显示」图元绑定显示。

### 2. 调研核实的关键事实（决定了"不能只写个插件了事"）

开工前逐条 grep / Read 核实，得到三条硬事实：

| # | 事实 | 出处 |
|---|---|---|
| 1 | **插件层看不见"写全局变量"的接口** —— 全仓 8 个插件 csproj **无一个**引用 `VM.Core.csproj`，写全局变量在代码里**没有正门** | 各 `Plugins/*/*.csproj` 的 ProjectReference 清单 |
| 2 | 现成的「变量赋值」插件写的是 `context.LocalVariables`（**流程运行期内存草稿本**），**不与全局变量同步** | `Plugins/Plugin.Utility/VariableAssignmentPlugin.cs` |
| 3 | 全局变量的读侧能力早已存在（`VariableRegistry.FindByName`、绑定解析器），**写侧能力从未抽象出来** | `Core/Binding/IVariableRegistry.cs`、`Core/IReadOnlyWorkspaceContext.cs` |

**结论**：若照着"应该有个写变量的方法"去写插件，会做出一个
**编译通过、运行静默失败**的插件。所以第一步必须先把写能力抽象成契约，
放到依赖链最底层（Shard），插件才够得到。

### 3. 关键决策（逐条经用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 写入通路怎么给 | **新增写变量能力接口**：`IGlobalVariableWriter` 定义在 Shard 层，实现放 VM.Core，经 `IExecutionContext.GlobalVariables` 递给插件 | 插件只引 `Core.Interfaces`；实现要查注册表、要碰工作区，只能留在 VM.Core。方向仍是"宿主实现、插件依赖契约"，依赖单向不破 |
| 2 | 目标变量不存在时 | **报错，不创建** | 自动建变量会让"名字打错"变成一个悄悄多出来的空变量，现场最难排查的就是这种"看着有、其实不是我想要的那个" |
| 3 | 节点定位 | **图像专用**，新建工程 `Plugins/Plugin.ImageAssign` | 通用"赋值变量"已经存在（写本地变量）；图像是 `HImage` 专有类型，混进去会让那个节点的类型守门变复杂 |
| 4 | 目标变量名怎么给 | **文本输入端口** `InputPort<string>` | 端口既能手填常量，也能上游连线喂进来（例如按工位号拼名字），比写死在属性里灵活 |
| 5 | 类型校验 | **加通用类型守门**（`IsInstanceOfType`） | 写进一个"数值变量"或"字符串变量"必然出事；守门放在实现层一次做掉，任何未来的写方都受益 |
| 6 | 输入图像为空 | **失败报错，不写** | 空图写进变量会让画面显示"无图像"，看着像显示端坏了，实际是上游没出图——错误要停在源头 |
| 7 | 显示名与分组 | `Name=「图像赋值」`、`GroupName=「图像处理」` | 与既有节点命名口径一致；分组不能填「相机」等保留字 |

### 4. 数据通路（本轮的"接线图"）

```
Plugin.ImageAssign.ImageAssignPlugin.RunAlgorithm
      ↓  context.GlobalVariables  ← ★ 本轮新增的入口（IExecutionContext 成员）
IGlobalVariableWriter（契约，Shard 层）
      ↓  实现：VisionMaster.Binding.GlobalVariableWriter
① 查：_workspace.VariableRegistry.FindByName(name)   ← 找不到 → 中文报错
② 守：declared.IsInstanceOfType(value)               ← 类型不符 → 中文报错
③ 写：((IWritableVariable)variable).TryWrite(...)
      ↓
全局图像变量（HImage）
      ↓  VariableHandle.ValueChanged（流程线程）
ScadaValueSource.VariableHandle.Value → BitmapSource(Freeze)   ← 上一轮已做
      ↓
Hmi.ImageView 图元刷新
```

三个要点：

- **懒建**：`ExecutionContext.GlobalVariables` 是 `??=` 惰性构造。绝大多数节点用不到写全局变量，
  不必每次执行都 new 一个出来。
- **工作区可能为空**：容器注册等"简化构造"场景下 `Workspace` 为 null。
  此时写入**必失败并给出中文原因**（"当前执行环境没有绑定工作区"），而不是抛空引用异常。
- **成功/失败都走基类契约**：复用 `VisionPluginBase` 自带的 `Success` / `ErrorMessage` 输出端口与 `Fail(string)`，
  **不另立端口**（曾因重复声明同名端口触发 CS0108）。

## 四、已知边界

1. **类型守门是"严格匹配"，不做隐式数值转换**
   `double` 变量写 `int` 值会被拒（`IsInstanceOfType(3)` 对 `double` 为假）。
   这是刻意的：静默的数值拓宽/收窄在工业现场比"报错"危险得多。
   需要换算时，应由上游节点显式产出正确类型的值。
2. **变量不存在不自动创建**（决策 2）
   必须先在变量管理里建好同名的 `HImage` 变量；否则节点运行即失败并给出中文原因。
3. **简化构造（容器注册等）上下文没有工作区时，写入必失败**
   `GlobalVariableWriter` 的 `_workspace` 为 null，返回"当前执行环境没有绑定工作区，无法写入全局变量"。
   这是设计内的行为（容器注册路径本来就不该写业务变量），不是缺陷。
4. **写入的是引用，不是快照**
   `HImage` 是引用类型，变量持有的是同一个对象引用。
   若上游之后对同一 `HImage` 实例做**原地修改**，变量里看到的值也会变。
   需要"冻结某一帧"时应由上游产出新实例。
5. **图像变量的当前值不落盘**
   承上一轮的边界：`VariableDto.JsonToValue` 走 JSON 往返，`HImage` 无法序列化，
   故图像变量**重启后为空**（画面回落显示"无图像"）。本插件不改变这一点。
6. **不校验目标变量的类型是不是 HImage**
   守门只保证"写入值类型 ⊆ 变量声明类型"。
   若把一个 `HImage` 变量名敲错成某个 `object` 变量，是能写进去的——这类语义错配需要靠命名规范约束。
