## 二、第一派：交互补齐七项

### 2.1 搜索「上一个」

- `SearchLocate(forward)` 抽成公共核，正向/反向共用一套命中遍历。
- **反向口径**：头回绕（已到首个命中再往前 → 回绕到末尾）；当前不在命中列表里时**从末尾开始**。
- `ProcessView.xaml` 搜索行加「上一个」按钮，置于「下一个」左侧。

### 2.2 失败跳转开关 `AutoJumpToFailure`

- 默认 `true`（保持既有自动跳转行为）。
- **关闭时**：200ms 扫描照跑、基线照记，只是**不切选中**——开关只控制"跳"，不控制"发现"。
- **重开后**：从**下一个新失败**恢复自动跳转；**关闭期间的旧失败不补跳**——防"打开开关的一瞬间被整批旧失败来回拽"。

### 2.3 画布多选批量禁用/断点

- `CollectBatchTargets`：选中集 > 1 时，按 `DeleteSelectedNodesCore` 同一口径取目标——`IsSelected && !IsDecorator && Model != null`。
- **禁用**收"有模型的节点"（容器框也算）；**断点**在此之上再过 `Kind == Step` 闸（容器没有断点语义）。
- 无多选时维持既有"右键靶"单节点行为，**逐位不变**。
- 版本口径分叉：禁用走**语义 setter 自动推版本**；断点是 `[RuntimeState]`，**不推**。

### 2.4 DoCompileAll 接编译错误事件

- 批量编译时**每个失败流程各发一次** `CompilationErrorsEvent`（此前只有单流程 `DoCompile` 发布——2026-10-10 记录 §七-3 未决项收口）。
- 画布侧缓存口径从"整体替换"升级为**按 `FlowName` 分组累计**：同 `FlowName` 重发时只替换该组，其它流程的错误保留。

### 2.5 错误列表升级

- 按流程**分组显示**：组头 = 流程名 + 条数，按**首现顺序**排列。
- 组头下加「复制全部」按钮：多行文本进剪贴板；headless 环境剪贴板会抛 `ExternalException`，**静默降级**不弹错。

### 2.6 流程栏执行统计两行

- 流程树底部两行：
  - 规模行：「共 N 步 · 最深 d 层」——**N 含容器**；**顶层第 1 层**，分支内容随嵌套 +1（口径见 §六-3 未决）；
  - 耗时行：「本轮总耗时 X ms · 最慢：步骤名 Y ms」——`Sum` / `Max`（`LastRunTimeMs`），全 0 时显示"尚未运行"。
- 刷新挂在既有 200ms tick 上顺带做，不加定时器。

### 2.7 工具箱搜索补 Category 匹配

- 核实：ToolView **本就有搜索框**，`Name`/`Description` 过滤早于本任务存在——不是"新做搜索"，是补缺口。
- 本批补齐 **Category 匹配**：命中分组名即**整组保留**；同时修正"注释声称按分组名、实现漏了 Category"的注释与实现不符（勘误注释见 `ToolViewModel.cs:56`，判据 `:80`）。

## 三、第二派：画布可视化五项 + 持久化与稳定三项

### 3.8 CodeReader QR flaky 稳定化

- 现象：gate 全量跑时 CodeReader QR 用例偶发超时失败（flaky）。
- **调查**：`--qrprobe 10` 空闲态 **0/10 失败**——flaky 在空闲态**复现不出来**，与"gate 全量跑宿主负载高、`find_data_code_2d` 500ms 超时偶发不足"的假设一致。
- **修法**：用例内**最多 3 次重试**，每次**全新引擎实例**；断言语义"能解出"**不变**，新增 `Attempts` 诊断字段记录实际次数。
- 新增 `--qrprobe [N]` 调查模式（空闲态复现率采样），**不进常规 gate**。
- 边界：若未来重试后**仍稳定失败**，按产品真 bug 另立 finding，不再当 flaky 压。

## 五、本批钉死的口径（守门点）

1. **失败跳转开关只关"跳"不关"发现"**：关闭期间扫描照跑、基线照记；重开后只从下一个**新**失败恢复，**旧失败不补跳**（[G4] 守门）。
2. **多选批量取节点口径单一**：`CollectBatchTargets` 与 `DeleteSelectedNodesCore` 逐字同款（`IsSelected && !IsDecorator && Model != null`）；禁用与断点在此基础上分层过滤（[T3c] 守门）。
3. **编译错误缓存按 FlowName 分组累计**：重发同流程只替换该组——不许退回"整体替换"（[G6] 守门）。
4. **必填叹号与编译期判据逐字同源**：`IsRequired && 无 LinkedSource && 手填值为 null`；解析失败**不亮**角标（[Z4] 守门）。
5. **参考线纯视觉附加**：不参与拖动落点/改序计算；挂/摘必须成对（[Z5] 守门）。
6. **视图态三分**：随流程进 `FlowLayoutStore`、随用户进 `AppConfig.json` 两开关、选中/瞬态/视口/参考线**刻意不存**——新视图态先归栏再动手（口径表在 `FlowLayoutStore.cs` 头注释）。
7. **AppConfigModel 新节必须带 `= new()` 初始化器**：老配置缺节反序列化变 null 的三次坑史（[Z7] 序列化往返断言守门）。
8. **QR 断言语义不变**：重试只是吸收偶发超时，"能解出"口径不动；重试后仍稳定失败 = 产品真 bug，另立 finding。

## 八、补记：画布耗时徽章实时化（2026-10-12 真机反馈）

**反馈**："画布视图中 不会实时更新 插件的运行时间"。

**病根（本批 §3.4 徽章的刻意限制反被打脸）**：画布耗时徽章只绑 `Model.LastRunTimeMs`（**步骤完成后**由引擎冻结写入的终值），而运行中的实时值在 `Model.CurrentRunTimeMs`（由 200ms tick 计算写入，`StepModel` 走 `SetRuntimeState` 发 INPC）——原注释写"运行中的实时值仍由流程栏耗时胶囊承担，卡片不闪数字"，但真机上"流程栏有、画布没有"恰恰是用户感知到的缺陷。

**修法两半**（`FlowCanvasView.xaml` 徽章段 + `FlowCanvasViewModel`）：
1. **徽章双态绑定**（照流程栏耗时胶囊的两触发器模式）：`Model.IsRunningFocus=true` → 显示 `CurrentRunTimeMs` 实时值（加粗、随 tick 跳秒）；否则 `LastRunTimeMs > 0` → 显示冻结终值；两者同时成立时运行态赢（触发器后写者覆盖）。可见性同样双触发器（运行中即使还没终值也亮）。
2. **画布自有 200ms tick**：`FlowCanvasViewModel._runTimeTimer` + `internal void RunTimeTick() => ProcessViewModel.TickRunningTimes(_attachedFlow?.Steps)`；**Attach 启动 / Detach 与"切到无图纸"停止**（`internal bool RunTimeTimerEnabled` 供断言）。此前只有流程栏的 tick 在刷——**关掉流程栏面板，画布就再也不跳秒**；现在画布独立刷新，两处 tick 调同一静态纯函数、重复计算幂等（`SetProperty` 同值不发通知）。
3. 语义澄清（断言时踩到）：切到**另一条有效流程**时 tick 理应继续（有挂接就有刷新），停止只发生在**无挂接图纸**（`SwitchFlow(null)`）。

**断言与验证**：[Z8] 3 条（`CanvasVisualizationChecks.cs`）——挂接后 tick 在跑 / tick 后 `CurrentRunTimeMs` 实时前进（实测 0 → 38 ms）/ 切到无图纸停止、切回恢复。**主会话独立复核**：构建两工程 0 错误；全量 gate **通过 2111 / 失败 0**；`--render` 退出 0，E 场景出图可见运行中步骤右下角实时徽章（`右工位检测_0` 显示 **15230 ms** 粗体）；VisionMaster 已重启。
