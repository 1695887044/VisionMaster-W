# SCADA 模板触发器失效与就地编辑修复（状态切换一律落进控件代码）

现场报「运行态那个白框点不进编辑态、敲不进字」。查下去发现不是一处 UI 小毛病，
而是**本工程 XAML 环境下的一个系统性失效**——`ControlTemplate.Triggers` 里的 `DataTrigger`
**一条都不触发**（静默失效，连绑定报错都不写）。7 个图元控件里凡是靠模板触发器翻显隐/形状/
明暗的，全是死代码。修法按用户拍板口径：**模板里触发器全删，状态切换一律搬进控件代码**。

---

## 一、需求与决策

### 1. 需求

用户报障（逐字）：

> 「还是没办法输入」

附运行态截图：组态运行窗口里数值域的白框，鼠标点上去不进编辑态，键盘也敲不进字。
要求是**运行态真能敲进去**——不能用「文本图元是静态标签」「设计如此」打发。

### 2. 根因（两个病叠加）

| # | 病 | 表现 | 机制 |
|---|---|---|---|
| 1 | `ControlTemplate.Triggers` 里的 `DataTrigger` 本环境**永不触发** | 靠模板触发器翻的显隐 / 形状 / 明暗全死 | 触发器绑定的宿主是「被模板化的那个控件自己」（绑定错误日志：`target element is not this element`），`RelativeSource=TemplatedParent` 解析为 null，条件恒假；**且一条绑定报错都不写**（静默失效） |
| 2 | 模板内写死的初值会**压住**触发器 setter | 就算触发器能响也翻不动 | 模板内属性值优先级 4（`ParentTemplate`）**高过**模板触发器 setter 优先级 7（`TemplateTrigger`） |

**边界（已隔离实验证伪）**：病 1 **不波及 `DataTemplate.Triggers`**。
用 `ContentControl.ContentTemplate` 载体验证，`DataTemplate.Triggers` 里的 `DataTrigger`
**正常触发**（`Background` 变到 `#FF00FF00`）。→ 报警条**行内**那条 `IsAcknowledged` 淡化
（落在 `DataTemplate.Triggers` 上）**不受影响，不用改**。
（注：用 `ItemsControl.ItemTemplate` 做实验取不到模板内 Border，会抓到 ItemsControl 自带的 Border，
必须换 `ContentControl.ContentTemplate` 才拿到正确结果。）

### 3. 关键决策（已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 修法 | **挪到控件代码里**（用户逐字选定） | 模板里触发器全删，在控件 `UpdateXxx` 方法里直接翻 `Visibility`；与现有「模板只负责摆放、颜色/换算在代码里算」的哲学最一致。最确定、最不怕 WPF 脾气，代价是同时改 7 个控件 |
| 2 | 统一入口 | 抽 `ScadaElementBase.SetPartVisible(partName, visible)` | 7 个控件翻显隐的口径只留一份，模板取不到部件时是空操作 |
| 3 | 补摆时机 | 每个控件加 `OnApplyTemplate()` 补一次 `UpdateXxx()` | `ShowValue` / `HasAlarms` 等若在套模板**之前**就落地，那几次 `SetPartVisible` 是空操作（那时还取不到模板部件） |
| 4 | `OnApplyTemplate` 修饰符 | **必须 `public override`** | `FrameworkElement.OnApplyTemplate()` 是 `public virtual`，写 `protected override` 直接 `CS0507` |
| 5 | 模板里还留什么 | 不写 `Visibility` 初值、不写 `ControlTemplate.Triggers` 的 `DataTrigger` | 病 2 决定了初值不能写在模板里；病 1 决定了触发器写了也是死代码 |

### 4. 设计要点（为什么这么做）

- **「模板里的状态切换一律走代码」**：模板可被替换，控件拿不到模板内部元素，
  所以「相位 / 明暗 / 形状」这类状态必须做成**控件的依赖属性**，再由控件代码去改模板部件。
- **`Setter.Value` 里嵌的绑定同样走不通**：ProgressBar 原来在 `Setter.Value` 里嵌 `{Binding FillLength}`，
  这条路也堵死——长度一律在代码里赋。
- **模板套上前的调用是空操作，套上后 `OnApplyTemplate` 兜一次**：这是「属性可能先于模板落地」的
  标准处理姿势，避免"设了值但没生效"的时序坑。
- **属性触发器不受影响**：`ButtonElement` / `BitButtonElement` 用的是属性触发器
  （`IsMouseOver` / `IsPressed` / `IsEnabled`），**照常工作，本次不动**。

### 3. 复测输出（`EditAndShapeChecks()` —— 走真实入口的完整输入链）

```
[√通过] 数值域可编辑前提齐备（模式=输入输出 + 绑了变量 + 有写通道 + 权限放行）  →  mode=InputOutput / editable=True
[√通过] 数值域说明字留空时收起（模板触发器已搬进代码）  →  Collapsed
[√通过] 数值域显示态：数值文本露面、编辑框收起  →  ValueDisplay=Visible / PART_Editor=Collapsed
[√通过] 数值域点一下进编辑态：数值文本收起、编辑框露面（点不进编辑态的根因）  →  editing=True / ValueDisplay=Collapsed / PART_Editor=Visible
[√通过] 数值域点开后编辑框自动拿到键盘焦点（敲不进字的根因）  →  IsKeyboardFocused=True
[√通过] 数值域进编辑态预填的是当前显示值（操作员改的是他看到的那个量纲）  →  edit="10"
[√通过] 数值域敲进去的字进了 EditText（模板里 TextBox.Text ↔ EditText 的 TwoWay 通着）  →  edit="23.5"
[√通过] 数值域提交：写通道收到敲进去的值、退出编辑态（图元自己不改变量）  →  写=23.5 / editing=False / value=10
[√通过] 数值域提交后回到显示态：编辑框收起、数值文本回来  →  ValueDisplay=Visible / PART_Editor=Collapsed
[√通过] 灯默认形状：圆形露面、方形收起  →  LampCircle=Visible / LampSquare=Collapsed
[√通过] 灯换方形后：方形露面、圆形收起（模板触发器已搬进代码）  →  LampCircle=Collapsed / LampSquare=Visible
```

**这段测试的分量在于「入口是真的」**：不是把 `IsEditing` 直接设成 `true` 再断言，
而是**真往控件上抛一个隧道左键按下事件**（`OnPreviewMouseLeftButtonDown`），
再往编辑框里写字、再提交——上一轮失效的正是这一条链，从旁路进就测不出来。

### 4. `EditAndShapeChecks()` 守卫的 12 条

| # | 守卫内容 | 抓的病 |
|---|---|---|
| 1 | 数值域模板里有就地编辑框 | 模板改名 / 部件丢失 |
| 2 | 可编辑前提四件套齐备（模式 / 绑定 / 写通道 / 权限） | 可写性判定被改坏 |
| 3 | 说明字留空时收起 | 模板触发器搬走后漏搬 |
| 4 | 显示态：数值文本露面、编辑框收起 | 初始显隐摆错 |
| 5 | **点一下进编辑态**：文本收起、编辑框露面 | **点不进编辑态（本次现场症状）** |
| 6 | **点开后编辑框自动拿到键盘焦点** | **敲不进字（本次现场症状）** |
| 7 | 进编辑态预填当前显示值 | 量纲口径错（预填变量原值） |
| 8 | 敲进去的字进了 `EditText` | 模板里 TwoWay 绑定断掉 |
| 9 | 提交：写通道收到值、退出编辑态、图元自己不改变量 | 写回链路 / 值归属 |

| 11 | 灯默认形状：圆露面、方收起 | 形状切换初始态 |
| 12 | 灯换方形后：方露面、圆收起 | 形状切换（模板触发器搬走后漏搬） |

## 四、交付纪律（后续新增控件必守）

1. **`ControlTemplate.Triggers` 里禁用 `DataTrigger`**——本环境不触发且静默失效，写了是死代码。
   属性触发器（`Trigger Property=`）与 `Style.Triggers` 里的 `DataTrigger` 可用。
2. **模板里的状态切换一律写进控件代码**——经 `ScadaElementBase.SetPartVisible` 统一翻。
3. **模板子部件不写 `Visibility` 初值**——初值优先级高过模板触发器 setter，会压住状态切换。
4. **`OnApplyTemplate` 补摆一次，且必须 `public override`**——`protected override` 会 `CS0507`。
5. **`Setter.Value` 里不要嵌绑定**——同样走不通，值一律在代码里赋。
6. **`DataTemplate.Triggers` 不受此限**——行内模板的 `DataTrigger` 照常工作，不必迁走。
7. **需要"相位 / 明暗 / 形状"这类状态时，把它做成控件的依赖属性**——模板可被替换，
   控件拿不到模板内部元素，状态必须走属性出口。
