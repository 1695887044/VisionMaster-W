## 1. 当前状态

批 1 让"重名不猜"、批 2 让"同设备内唯一"，批 3 补上最后一环：**绑定侧记住变量身份**。

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| 插件下拉里的同名点位（两台设备） | 只出现一条（被按名字去重吞掉） | 两条都在，Caption 带 `· 设备` |
| 变量赋值写全局变量 | `GlobalVariables.TryWrite(名字)` | `SharedVariables.TryWrite(Id, 名字)`，Id 优先 |
| 数据记录 / 结果上报读变量 | `TryRead(Guid.Empty, 名字)` | `TryRead(Id, 名字)`，Id 优先 |
| 变量在变量管理里改名 | 插件里那条引用失效（按名找不到） | Id 仍指向同一个变量，**不断链** |
| 旧方案（没有 Id 字段） | — | 反序列化为 `Guid.Empty` → 名字兜底，行为与改造前一致 |

## 3. 未做 / 已知限制

- **数据记录 / 结果上报的下拉仍是"名字字符串"**（可编辑 ComboBox，R190 允许手输运行时变量名）。因此这两处**无法为同名点位提供可选的第二条候选**：重名时确认期捕获留空、运行期明确报歧义（字段按空值上报 + 限次 WARN），不会静默取另一台设备。要真正可选，需要把下拉改成对象绑定（`VariableOption` + `SelectedItem`），属批 4 的显示改造。

## 5. 测试范围与结果

### 5.1 功能（C14~C18）

- **候选快照**：两台设备同名 → 2 条候选、各自 Id、Caption 带设备；本地变量不带设备段。
- **变量赋值**：候选两条都在；`FindVariable(行)` 按 Id 命中 L2；名字失效但 Id 有效仍解析到同一变量（改名不断链）；名字查不到补「已失效」项；运行时作用域不补失效项。
- **运行期写入**：带 Id 时 `SharedVariables.TryWrite` 收到的 `Id/名字/值` 与行完全一致；旧配置（无 Id）仍按名字写；空名字+空 Id 明确拒绝且不调用写入；运行时作用域不碰共享变量。
- **运行期读取**：数据记录 / 结果上报带 Id 都读到 L2 的值；无 Id + 重名 → 失败（不取第一个）；只有 Id（名字为空）也能读；局部变量优先语义不变。
- **序列化**：三个模型的 `VariableId` JSON 往返；旧 JSON（无该字段）反序列化为 `Guid.Empty` 且不抛异常。

### 5.2 边界与异常（C19.1~C19.10）

null 快照保留原 Id；Id 可解析时保留（改名场景）；无 Id + 唯一名捕获；无 Id + 重名留空；空名字留空；作用域不匹配留空；Id 失效回退按名；名字前后空白 Trim；大小写不敏感；4000 字符超长名字仍可捕获。

### 5.3 暴力（C14.5 / C19.11 / C19.12）

| 用例 | 规模 | 结果 |
| --- | --- | --- |
| 候选快照高负载 | 200 台设备同名 | 200 条候选，0ms，无吞噬 |
| 捕获正确性（反复执行） | 5000 候选 × 1000 行 × 20 轮 = 20000 次 | 全部正确，1535ms |
| 确认期性能 | 2000 行 × 2000 候选 | 全部捕获，**41ms** |

## 6. 踩过的坑

1. **`ResultUploadPlugin` 根本没有配置上下文**：它原本不实现 `IPluginConfigContextProvider`，变量名是自由文本、没有候选快照，确认期无从捕获 Id。补实现接口后才有 `_configContext`。
2. **`ExecutionContext` 与 `System.Threading.ExecutionContext` 重名**：探针里 `using System.Threading` 后必须写全名。
3. **反射调用私有方法是"会静默失效"的测试**：方法改名/改签名后 `GetMethod` 返回 null，若只写 `?.Invoke` 会静默通过。所以先判签名并单独 Check（C16.0/C17.0）。
4. **`SelectedGlobalCandidate` 的 Id 分支必须判 `VariableId != Guid.Empty`**：运行时变量的候选 Id 全是空，不判就会"按 Id 命中第一条"，把 A 行显示成 B 行的候选。
