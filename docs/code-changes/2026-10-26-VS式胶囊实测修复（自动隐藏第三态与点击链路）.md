## 二、已做

### 2.1 根因一：自动隐藏是第三种状态，`FindPanel` 根本找不到它

AvalonDock 4.74.1 的面板有三种「看不见」：

| 状态 | Parent | IsVisible | IsHidden | IsAutoHidden |
| --- | --- | --- | --- | --- |
| 正常停靠 | LayoutAnchorablePane | true | false | false |
| Hidden 区（关闭/收起） | LayoutRoot | false | true | false |
| 自动隐藏（图钉） | LayoutAnchorGroup | **true** | false | **true** |

`LayoutHelper.EnumerateContents` 只遍历 `RootPanel`、浮动窗口和 `Hidden`，**漏了 `LayoutRoot.{Left,Right,Top,Bottom}Side` 四棵自动隐藏子树**。于是图钉按下后：

- `FindPanel("Panel_ToolView")` 返回 null → `IsPanelVisible` false → 胶囊出现（表面正常）；
- 点胶囊 → `ShowPanel` 里 `EnumerateContents(...).FirstOrDefault(...)` 得到 null → 直接 `return`，**静默无反应**。

修法（`VisionMaster\Services\LayoutHelper.cs`）：

- `EnumerateContents` 追加 `LeftSide/RightSide/TopSide/BottomSide` 的遍历；
- `Walk` 增加 `LayoutAnchorGroup` 与 `LayoutAnchorSide` 两个分支。

### 2.2 根因二：`ShowAnchorable` 不认自动隐藏，且 `IsVisible` 早退会挡住它

旧 `ShowAnchorable` 第一行是 `if (anchorable.IsVisible) return;`，而自动隐藏的 `IsVisible` 仍为 true；即使不早退，后面 `if (!anchorable.IsHidden) return;` 也会把自动隐藏放走。

修法：在 `IsVisible` 早退**之前**处理 `IsAutoHidden`，调用库的 `ToggleAutoHide()`「收回停靠」分支：

```csharp
if (anchorable.IsAutoHidden)
{
    anchorable.ToggleAutoHide();   // 按 group.PreviousContainer 把整组移回原 pane
    if (!anchorable.IsAutoHidden) return;
}
if (anchorable.IsVisible) return;
if (!anchorable.IsHidden) return;
```

为什么不用 `Show()`：`Show()` 对 `Parent=LayoutAnchorGroup` 的状态直接抛 `InvalidOperationException`；`Dock()`/`Show()` 又共用 `PreviousContainerIndex` 缺负索引判据的老路（R58 的 2026-10-16 真机闪退同族）。`ToggleAutoHide()` 的收回分支用的是 `group.PreviousContainer`，并在为空时新建 pane，不碰那条老路。

### 2.3 根因三：`IsPanelVisible` 把自动隐藏算成「可见」

`IsVisible` 对自动隐藏为 true，所以：

- `UpdateInspectorCapsules` 不会给图钉收起的面板生成胶囊；
- `respectUserHidden` 的判据 `FindPanel(...) is LayoutAnchorable { IsVisible: false }` 也永远不成立 → 重启后 `ApplyScadaPanelMode(false, respectUserHidden:true)` 会把用户的图钉收起强行拉回来。

修法：

- `IsPanelVisible` 改为 `a.IsVisible && !a.IsAutoHidden`（与注释「关闭到自动隐藏区均视为不可见」一致）；
- `ApplyScadaPanelMode` / `ApplyShellMode` 的 `respectUserHidden` 判据改为 `!IsPanelVisible(manager, OperatorToolboxPanel)`。

### 2.4 根因四：日志通道选错，导致「点击没反应」被误判

`ShellViewModel.ShowInspectorCapsule` 原来用 `NLog.LogManager.GetCurrentClassLogger()`。本仓 `Logs\yyyy-MM-dd.log` 由 `Core.LogService`（`ILogService`）写；仓库里没有 `NLog.config`，NLog 没有 target → `logger.Warn` 静默丢弃。所以即使点击成功，日志里也永远看不到 `[胶囊]`。

修法：

- `ShowInspectorCapsule` 改用 `TryResolveLogService()`（`ILogService`），并记录点击前/后的 `visible/hidden/autoHidden`；
- `Shell.xaml.cs` 的 `OnInspectorCapsuleClick` 在守卫前先写 `[胶囊] Click 到达 sender/item/shellDc`，守卫不通过再写一条。

### 2.5 根因五：胶囊贴窗口右边缘，点击坐标容易落到非客户区

第一版 `ItemsControl` 贴右边缘，胶囊 20px 几乎压在窗口 resize border 上，真机点击会偏。修法：`ItemsControl Margin="0,6,6,0"`，胶囊整体左移 6px，轨道背景仍铺满右边缘。

### 2.6 断言补齐

`UIThemeSmokeTest` 新增两条：

- 「图钉自动隐藏后点胶囊：ToggleAutoHide 收回原 pane」——先 `ToggleAutoHide()` 进入 `LayoutAnchorGroup`，再 `ShowPanel`，断言 `IsAutoHidden=false` 且 `Parent is LayoutAnchorablePane`；
- 「启动/布局加载尊重图钉收起（respectUserHidden），显式切模式仍恢复工具箱」——`respectUserHidden:true` 时保持自动隐藏，`false` 时恢复。

## 五、踩过的坑

- **`IsVisible` 不是「看得见」**：自动隐藏时 `Parent=LayoutAnchorGroup`，`IsVisible` 仍为 true；判断用户是否收起必须用 `IsPanelVisible`（`IsVisible && !IsAutoHidden`）或 `IsAutoHidden`。
- **`FindPanel` 的遍历面决定一切**：漏掉 `LayoutRoot` 的四个 Side，面板就「查无此人」，`ShowPanel` 会静默 return，表现为「点击没反应」而不是异常。
- **NLog 没有配置 = 静默黑洞**：本仓文件日志只有 `ILogService` 一条通道；排障日志不要用 `LogManager.GetCurrentClassLogger()`。
- **静态扫描的 `MethodBody` 不认字符串**：`FlowCanvasChecks.LayoutVisibilityCheck` 用「第一个 `ShowAnchorable(` 之后的下一个 `{`」取方法体；在 `ShowPanel` 里加一条含 `{contentId}` 的插值日志后，`{` 被当成方法体开头 → LV4/LV5 假红。临时日志已删；后续若要在调用点前加日志，先看这条。
- **并发会话会改同一份源码/同一个实例**：`MatchingChecks.cs` 的 mtime 与构建错误、真机日志里非本次的点击，都要先按 R9 看时间戳再判断，别把别人的改动算到自己头上。
