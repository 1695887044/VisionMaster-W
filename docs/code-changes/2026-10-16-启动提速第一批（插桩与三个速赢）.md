# 启动提速第一批：插桩 + 三个速赢（插件扫描分解 / 反射三合一 / 目录过滤 / 帮助合并挪出启动链）

- 日期：2026-10-16
- 涉及：`Engine\PluginService.cs`、`VisionMaster\App.xaml.cs`、`VisionMaster\Lifetime\Checks\PluginScanCheck.cs`、`FlowCanvasChecks\FlowEngineFixChecks.cs`（E18 计数改 4、新增 E19）、`HelpProbe\Program.cs`（构造点同步）
- 触发：用户问「现在启动的时候加载算子插件速度很慢，有什么提速方案吗」（App.xaml.cs 94 行起），并点了层 0 + 层 2（插桩与速赢）。

---

## 1. 先做的事实盘点

启动链（`App.xaml.cs` 的 `RegisterCheck` 段）串行跑：单实例 → 配置 → HALCON → **插件扫描** → ~~帮助手册合并~~。
耗时大头一直是**插件扫描**（`Engine\PluginService.cs`），日志实测同机波动 1.07~28.83 秒（153 样本），
极值 90 秒是冷缓存/杀软离群——**代码优化救不了离群值，那是运维层的事**（Defender 排除 / SSD / 预读）。

本批只做层 0（插桩）+ 层 2（速赢）：先让"慢在哪"现场可查，再把确定能省的省掉。
层 3（插件清单缓存，把 2~3 秒压到 ~0.2 秒）与层 5（ReadyToRun）留待后续，先量后动。

### 插桩通道的坑（本批抓到并修正）

第一版插桩走 `_notifier.ShowInfo`（右下角弹泡）——弹泡 3 秒消失，启动时根本来不及看，
真机日志里一行都没有。**启动插桩必须落日志文件**（`ILogService`），弹泡只配给"用户要立刻看到"的事。
`PluginService` 构造函数加了可选参数 `ILogService? log = null`（兼容无日志宿主，探针塞 `NullLogService.Instance`）。

### 帮助合并挪动的成立前提（两条都钉死）

1. **懒构建兜底在位**：`HelpViewModel.OnDialogOpened` 已有 `!IsBuilt → Build()`——后台没跑完时
   用户打开帮助会当场构建，行为不降级。这是这条路径能成立的前提，由 E19 第 ③ 条钉住。
2. **时序不变式不破**：它仍排在插件扫描之后（合并要按插件注册元数据分组）——主窗口只能在
   `CreateShell` 返回后出现，那一刻插件扫描早已跑完，所以挪到后台不改变"程序集已在内存里"这个前提。

## 3. 守门人（进常规 gate 基线）

`FlowCanvasChecks\FlowEngineFixChecks.cs`：

- **E18**（既有，通讯检测挪出启动链）第 ⑤ 条计数 **5 → 4**：链上现在剩单实例/配置/HALCON/插件扫描四项。
- **E19**（新增，帮助合并挪出启动链）三条：
  - ① 链上不许有 `RegisterCheck(new HelpCatalogCheck`（加回去 = 启动又慢回去）；
  - ② `OnInitialized` 里必须真的调 `RunHelpCatalogCheckInBackground()`（只删注册不补 = 帮助从此不合并）；
  - ③ 反向钉住前提：`HelpViewModel.OnDialogOpened` 的懒构建兜底必须还在（删了它就该回链上）。

`PluginScanCheck` 的过时记忆一并修正（那句"紧随其后的 HelpCatalogCheck"改成指向新的后台入口）。
