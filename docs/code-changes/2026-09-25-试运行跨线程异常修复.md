# 修复：试运行跨线程异常（"调用线程无法访问此对象"）

## 现象

用户在「卡尺_宽度」配置窗口点「执行」试运行，31ms 即失败：

```
状态: ✗ 失败 - 执行异常: 调用线程无法访问此对象，因为另一个线程拥有该对象。
```

同构的「卡尺_角度」试运行却成功；整流程运行 5 项测量全部正确——问题特定于试运行路径。

## 根因

试运行基建在**后台线程**执行（`PluginConfigShellViewModel.ExecutePlugin` → `Task.Run` →
`PluginTestRunner.Run`）。`PluginTestRunner.BridgeInputs` 把编译实例的上游输出灌进配置实例
输入端口（`configPort.Value = actual`），端口 `ValueChanged` 事件因此在**后台线程**触发。

「图像输入」卡片的 `LinkableValueEditor` 订阅了该事件，而事件处理第一行就读依赖属性：

```csharp
private void OnPortValueChanged(object sender, EventArgs e)
{
    if (IsLinked) return;          // ← 读 DP：DependencyObject.VerifyAccess() 抛异常
    SyncPortValue();               // ← 写 DP：同样会抛
}
```

`DependencyObject.VerifyAccess` 强制 UI 线程——异常沿 BridgeInputs 冒泡，被
`PluginTestRunner` 的 catch 捕获转为失败结果，整个试运行 31ms 内夭折。

## 修复

| 文件 | 改动 |
| --- | --- |
| `Shard\Core.Controls\LinkableValueEditor.xaml.cs` | `OnPortValueChanged` 开头检测线程，非 UI 线程 `Dispatcher.BeginInvoke` 投递后再处理（读 IsLinked / 写 PortValue 均为 DP 操作）。事件来源本就可能来自任意线程（试运行桥接 / 流程运行赋值），投递是标准姿势 |
| `Engine\PluginTestRunner.cs` | 失败 catch 补 `logger?.Error($"[试运行] 执行异常堆栈: {ex}")`——此前只把 `Message` 放状态栏、堆栈丢弃，本次排查正因此多绕一轮 |
| `VisionMaster\ViewModels\DialogViewModels\PluginConfigShellViewModel.cs` | 同上口径：异常路径补堆栈日志 |

## 验证

```
宿主重编译：0 错误
冒烟回归：644 通过 / 15 失败（较基线 +3 通过 / +1 失败；新增失败为并行任务的
"脚本预览帧"断言，与本次三处改动无关；此前基线 641/14 时并行任务已在线改动）
用户实测：重启后「卡尺_宽度」试运行成功，读数与判定符合预期
```

## 已知边界

1. **修复前的方案文件不受影响**：这是运行期线程问题，与数据/方案无关。
2. `LinkableValueEditor` 被多插件共用（卡尺/码读取/OCR/YOLO 的图像输入、各文本端口），
   本修复一处生效全部受益；若插件在后台线程自行触发端口 INPC，事件同样会被安全投递。
3. 试运行的"执行异常"现在日志带堆栈，后续同类问题可直接从日志定位，无需再补埋点。
