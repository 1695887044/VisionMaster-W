# 属性面板下拉框与组头被 Fluent 隐式样式压扁

日期：2026-10-20
现象（用户真机截图）：组态属性面板里
① **Expander 组头**那圈下划线只到标题那么宽（"数据 4 ⌃" 后面就断了），箭头贴着计数徽标而不是靠右；
② **下拉框**（操作权限 / 形状）没有框，只剩一个小箭头，而且箭头跑到文字左边。

## 一、根因（实测，不是猜）

`App.xaml` 把 `.NET 9 Fluent` **最后**合并进应用级资源。Fluent 的隐式 `ToggleButton` 样式（含 `BasedOn` 链）设了：

```
HorizontalAlignment       = Left
VerticalAlignment         = Center
HorizontalContentAlignment= Center
Padding                   = 11,5,11,6
```

（用 `_ResProbe` 新增的「隐式样式 setter 诊断」逐条打出来；`Button` 同样 `Left`，因为它 `BasedOn ButtonBase`。）

我们两个模板里的 `ToggleButton` **都没有挂 Style**——模板本身写在元素上，觉得没必要再给个 Style——
于是吃到这份隐式样式，`HorizontalAlignment=Left` 让外壳只占**内容宽度**：

- Expander 组头：`ToggleButton` 里的 `Border`（下沿 hairline）缩到"标题 + 徽标 + 箭头"那么宽 → 下划线断掉；
- ComboBox：模板根 `ToggleButton` 缩到箭头那么宽 → 框看不见，箭头落在文字左侧。

同一模板里其它元素（TextBox / Border / NumericBox）没受影响，所以**只有这两类控件**出问题。

## 二、为什么现有探针没抓到

`ScadaChecks` 的属性面板渲染探针**不合并 Fluent**（没有 `Application`、只有视图自带的 `Colors.xaml`），
Fluent 的隐式样式压根不在查找链上——它验的是"另一套外观"。这与 R19（ListView 被 Fluent 隐式样式顶掉）、
R30（分册作用域）是同一族：**断言宿主与真机劈叉，绿灯是真的，只是验的不是同一件事**。

## 三、修复（8 处，同一行改动）

给自定义模板里的 `ToggleButton` 显式写 `HorizontalAlignment="Stretch"`（需要撑满高度的再补 `VerticalAlignment`）：

| 文件 | 控件 |
| --- | --- |
| `VisionMaster/Views/ScadaPropertyView.xaml` | Expander 组头、ComboBox 外壳 |
| `VisionMaster/Views/ToolView.xaml` | 工具箱分组组头 |
| `VisionMaster/Views/DialogViews/HelpView.xaml` | 帮助目录展开箭头 |
| `VisionMaster/Views/DialogViews/MotionBoard/MotionBoardTheme.xaml` | 运动板设置下拉 |
| `UI/Controls/Themes/PluginConfigStyles.xaml` | 插件配置壳下拉 |
| `UI/Controls/Themes/Controls/Layout.xaml` | 库里的 Expander 组头 |
| `UI/Controls/Themes/Controls/Selection.xaml` | 库里的 ComboBox 外壳 |

`UI/Controls/Themes/Dialog/Dialog.Input.xaml:121` **早就这么写了**（`HorizontalAlignment="Stretch"`），
说明这个坑此前在对话框那一支被踩过一次、只是没推广开。

## 四、守门（两层，都做了变异反证）

### 1. 静态扫描（`ScadaChecks` 的 `[AI]`）

扫 `VisionMaster/` 与 `UI/` 下全部 XAML：**声明了自己模板**的 `ToggleButton`，必须满足其一——
显式 `Style=`（隐式样式整份不生效）/ 自己写了 `HorizontalAlignment=` / 同时写了 `Width=` 与 `Height=`（自定尺寸，对齐无所谓）。
当前 87 个 XAML 全过。

### 2. 合并 Fluent 再渲染一次（属性面板渲染探针）

另建一份 `ScadaPropertyView`，把 `Fluent.xaml` 塞进它自己的 `MergedDictionaries`（等价于 App 级合并后的查找结果），
布局后量两条：

```
[√通过] 合并 Fluent 之后组头仍铺满整行  →  259×259/259×259/…（7 组）
[√通过] 合并 Fluent 之后下拉框的外壳铺满整格  →  下拉 145 / 外壳 145
```

**变异反证**（把两处 `Stretch` 去掉重跑）：

```
[×失败] 组头…  →  87.9×259/87.9×259/…      ← 外壳只有 87.9，正是截图里"下划线断掉"的那个宽度
[×失败] 下拉框外壳…  →  下拉 145 / 外壳 18.7
[×失败] 静态扫描…  →  缺对齐：ScadaPropertyView.xaml:65；:602
```

恢复后全绿。同时留了证据图 `artifacts/scada-property-panel-fluent.png`（合并 Fluent 后的面板实图）。

## 五、验证

- `VisionMaster`（`--no-incremental`，XAML 改动）× `ScadaChecks`：**0 错误**；
- `ScadaChecks` 全量 **2098 通过 / 0 失败**；
- 合并 Fluent 的实图人眼复核：组头下划线贯穿整行、箭头靠右；两个下拉框都有完整边框、箭头在右。

**未逐个出图复核的部分**：另外 6 处（工具箱 / 帮助 / 运动板 / 插件壳 / UI 库两处）只做了
静态扫描 + 构建确认。它们与属性面板是**逐字相同的一行改动**，且都属"外壳要铺满整格"的同一形态；
但按 R13 的口径，这里只能表述为"静态与构建确认"，不能算视觉已验证。

## 六、构建时的一个坑（记录）

改完 XAML 跑 `dotnet build VisionMaster.sln` 会报几十条 `MSB3021/MSB3027`：
`Modules\*.dll` 被 **正在运行的 VisionMaster.exe** 锁住（`Plugins\Directory.Build.targets` 往 `Modules\` 拷贝）。
解法二选一：关掉应用再全量构建，或只构建宿主与断言工程（`VisionMaster.csproj` + `ScadaChecks.csproj`），
插件工程不参与就不会碰 `Modules\`。
