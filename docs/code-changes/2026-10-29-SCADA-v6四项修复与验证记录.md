## 二、逐项改法与判定标准

### F1 首拍只建立基线（代码，语义变更）

**改法**（`Scada.Controls\Elements\ScadaElementBase.cs`）：

| 位置 | 改动 |
| --- | --- |
| 字段 | `private bool _animationEnabled = true;` → `private bool? _animationEnabled;`（`null` = 本轮还没基线） |
| `ResetAnimationVisuals` | `_animationEnabled = true;` → `= null;`（停运行/换上下文/设计期刷新都清基线） |
| `ApplyAnimationEnable` | 早退之后先判 `bool isBaseline = _animationEnabled is null;`，落状态照旧，**只有非基线**才 `RaiseScadaEvent` |

**为什么用可空而不是加一个 `_animationInitialized` 标志**：只有 4 处引用，改类型天然覆盖两条入口（换上下文、Refresh），不会出现"两处都要记得重置、漏一处就回到旧行为"的静默退化。

**判定标准**：

| 场景 | 判定 |
| --- | --- |
| 首拍值 = 0（启动即禁用） | `IsEnabled == false` 且 **0 条事件** |
| 首拍值 = 1（启动即可用） | 0 条事件 |
| 基线后 0→1 | 恰 1 条 `Activated` |
| 基线后 1→0 | 恰 1 条 `Deactivated` |
| 同值重复推 | 0 条 |
| 换运行上下文后再起一轮 | 新一轮首拍仍 0 条（两轮行为一致） |
| 设计期（无上下文） | 任何值都 0 条 |
| Invert 反向 | 首拍基线 0 条；1→取消激活、0→激活 |

### F2 延时日志后缀幂等（代码）

**改法**（`VisionMaster\Services\ScadaActionDispatcher.cs`）：

```csharp
private const string DelayedMarker = "（延时后）";
...
var delayedSubject = stamp.Subject.EndsWith(DelayedMarker, StringComparison.Ordinal)
    ? stamp.Subject
    : stamp.Subject + DelayedMarker;
```

**判定标准**：链式延时（延时→动作→延时→动作）四条日志全部出现、顺序为"延时/甲/延时/乙"，且第 4 行的对象名里「（延时后）」**恰好出现 1 次**。

### F4 容量整数化（代码 + 兼容）

**改法**：

| 位置 | 改动 |
| --- | --- |
| `XYChartElement.MaxPoints` | `double` → `int`（与 `AlarmTable.MaxRows` 同类型；去掉 `Math.Round` 与 NaN 判断） |
| `ScadaElementBase.ConvertFromString` | 严格转换失败、且目标是 `int`/`long`、且文本是数值时，四舍五入后返回；超范围/NaN/非数值仍照常抛 |

**为什么在 `ConvertFromString` 加宽容而不是在元素里特判**：`ApplyTargetProperty` 转换失败时是"保持现状"（静默），手改文件写 `"300.0"` 会静默停在默认 200——用户以为改成了 300。宽容解析只在**严格转换已经失败**时生效，对合法输入零影响，同时把这一类问题（所有 int 属性）一次解决。

**判定标准**：

| 场景 | 判定 |
| --- | --- |
| 描述符 | `MaxPoints` 的目标属性类型是 `int` |
| `"200.0"` | 转成 200 |
| `"5000.5"` | 转成 5001（AwayFromZero） |
| `"不是数"` | 仍抛（交给调用方保持现状） |
| 旧 `.vms` 里 `"300.0"` | 刷新后 `MaxPoints == 300`（不是默认 200） |

### F3 / F5 文案（只改文本）

- `StateListManagerViewModel.ModeHint` 位号档 → `"「值」列填位号 0~31；该位为 1 时命中（变量为负时按补码看位）"`。
- `ScadaEventEditor.xaml` 延时区说明 → `"只影响本条之后、同一事件里的动作；本条被跳过（没填毫秒 / 非界面线程）时，后面的动作仍会立即执行"`。

**判定标准**：`[V6R-9]` 断言提示含"补码"；F5 走人工评审（XAML 文案不进断言）。

## 五、剩余风险与未做

1. **F1 的多动画边界**：同一图元配了多条「启用对象」时，只有第一条算基线；后一条若与基线不同仍会发一次。语义上"最后一条生效"，属可接受；已在代码注释写明。
2. **F4 的类型变更**：`MaxPoints` 从 `double` 变 `int`，若外部脚本按 double 反射写这个 DP 会失败——仓库内无此类用法（已 grep）。旧 `.vms` 的 `"200.0"` 已兼容。
3. **F5 无自动断言**：XAML 文案靠人工评审（R111/R141 口径）。
4. **未跑真 exe**：四项修复都走的是断言宿主（R175 优先），未启动 `VisionMaster.exe` 做整窗目视；需要目视验收时按 R176 备份布局后单独跑。
