# 状态色令牌迁移收尾 + 图表颜色改调色板

日期：2026-10-26　状态：完成；`ScadaChecks` **3079 通过 / 0 失败**

## 一、迁移了哪些图元（主题 Style 加 Setter，属性声明不动）

| 图元 | 接的令牌 |
| --- | --- |
| `Indicator` | OnColor→Running，OffColor→Stopped |
| `Lamp` | OnColor→Running，WarningColor→Warning，AlarmColor→Fault |
| `Symbol` | AccentColor→Running，StoppedColor→Stopped，FaultColor→Fault |
| `Valve` | OpenColor→Running，ThrottleColor→Warning |
| `ProgressBar` | HighColor→Fault，LowColor→Warning |
| `Gauge` | ProgressColor→Running |

`[ST2]` 保护已迁的 6 个（改回字面量会红）；`[ST3]` 报告剩余：
`TankElement` / `PumpElement` / `MotorElement`。

## 二、剩下三个为什么没迁

不是漏了，是**它们没有"状态色"属性**：

- `Tank`：只有 `TrackColor`（空腔底色），不是状态语义；
- `Pump` / `Motor`：没有 Color 属性，状态靠 `State` + 模板内固定色。

如果将来给它们加状态色属性，加完往 `MigratedThemes` 里补一行即可，`[ST2]` 自动纳入保护。

## 三、图表「颜色」从文本框改成调色板下拉

用户反馈：柱/饼每新增一项都要手打 `#RRGGBB`，太原始。改成下拉：

| 选项 | 写入值 |
| --- | --- |
| 自动 | 空串（图表按调色板顺序取色） |
| 蓝 / 青 / 绿 / 橙 / 紫 / 红 | `#2563EB` / `#38BDF8` / `#22C55E` / `#F59E0B` / `#8B5CF6` / `#E03A2B` |

仍是**可覆盖**语义：选"自动"就不写死，选具体色则写进配置、随 `.vms` 走。

## 四、踩的坑

`ScadaChecks.exe` 被上一个还在跑的实例占着，`MSB3021` 复制失败——但 DLL 已更新、
旧 exe 加载的是新 DLL，所以断言结果有效（3079/0）。这类"构建报错但结论有效"的情况
容易误判成失败，记一笔：**看退出码之前先看是不是只错了 apphost 复制**。

## 五、用户裁定：不做「恢复主题默认」（2026-10-26）

结论：**这个功能不上线**。理由（用户口径）：真需要默认色时，**重建一个图元**就行，
不值得为它动属性面板的取色链路（那份弹窗体由属性行与动画档位颜色槽共用，
加按钮要同时处理 DP 与 read/write 委托两套语义）。

**后续会话不要再实现它**——看到状态色可覆盖但没法一键回默认不算缺陷，
这是有意留白：令牌只管默认值，配歪了重拖一个图元即可。
