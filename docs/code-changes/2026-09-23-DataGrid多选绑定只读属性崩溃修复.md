# 2026-09-23 DataGrid 多选绑定「只读属性 + 默认双向」崩溃修复

## 1. 需求与背景

在上一轮修掉 `DialogStyles.xaml` 模板内 `{StaticResource Icon}` 崩溃后，按用户要求做**实机点验**
（启动 `VisionMaster.exe` → 系统(S) → 通讯设置 → 截图）。

实机结论：

- ✅ `Icon` 崩溃确实已修好（不再出现「无法找到名为 Icon 的资源」）。
- ❌ **通讯设置弹窗仍然打不开**，日志面板报出一条**此前从未见过**的异常。

```
[UI] An unexpected error occurred while resolving 'System.Object',
     with the service name 'CommunicationSettingsView'
  → Prism.Ioc.ResolutionFailedException
  → System.Reflection.TargetInvocationException
  → System.Windows.Markup.XamlParseException:
      设置属性 UI.Behaviors.DataGridSelectionBehavior.BindableSelectedItems 时引发了异常
```

即：`CommunicationSettingsView.xaml` 在解析阶段就炸了，View 根本没构造出来。

## 2. 根因

三个事实叠在一起：

| # | 事实 | 位置 |
| --- | --- | --- |
| 1 | 附加属性声明了 `BindsTwoWayByDefault` | `UI\Controls\Behaviors\DataGridSelectionBehavior.cs` |
| 2 | 调用点写的是 `{Binding SelectedConfigs}`（未指定 `Mode`） | `CommunicationSettingsView.xaml` L115 |
| 3 | `SelectedConfigs` 是**只读属性**（只有 getter） | `CommunicationSettingsViewModel.cs` L91 |

推导：

1. 附加属性带 `BindsTwoWayByDefault` ⇒ `{Binding}` 的默认模式被隐式升成 `TwoWay`。
2. `TwoWay` 要求**源属性可写**，而 `SelectedConfigs { get; } = new()` 没有 setter。
3. WPF 在**绑定期**（不是赋值期）就抛
   `InvalidOperationException: 无法对"…CommunicationSettingsViewModel"类型的只读属性"SelectedConfigs"进行 TwoWay 或 OneWayToSource 绑定。`
4. XAML 解析把它包成 `XamlParseException` ⇒ View 构造失败 ⇒ Prism 报 `ResolutionFailedException` ⇒ 弹窗打不开。

**关键认知**：这是**第三类**「绑定期就抛」的坑（前两类是 `Freezable` 内 `{StaticResource}` 与模板内 `{StaticResource}`）。
它的特点是被包成 `XamlParseException: 设置属性 … 时引发了异常`，光看外层消息**看不出是绑定模式问题**，
必须展开 `InnerException` 才看得到「只读属性」四个字。

## 3. 决策

### 3.1 主修：去掉 `BindsTwoWayByDefault`（治本）

先问「这个行为到底需不需要双向 DP？」

读 `DataGridSelectionBehavior` 的实现：它把 DP 当**入口**用一次 —— 在
`OnBindableSelectedItemsChanged` 里 `e.NewValue` 拿到集合实例后，**就地增删**该集合：

- 「界面 → VM」：`OnDataGridSelectionChanged` 里 `target.Clear()` / `target.Add(item)`；
- 「VM → 界面」：订阅集合自身的 `INotifyCollectionChanged`，回调里推选中行。

**全程从不回写 DP**。也就是说真正的双向是靠**集合实例本身**完成的，DP 只需要单向进来一次。
⇒ `BindsTwoWayByDefault` 是多余声明，还把「源属性必须可写」这个**不必要的约束**强加给调用方。

故去掉它，默认模式回落 `OneWay`，绑定成立。

### 3.2 辅修：调用点显式写 `Mode=OneWay`

在 `CommunicationSettingsView.xaml` 把 `{Binding SelectedConfigs}` 改成
`{Binding SelectedConfigs, Mode=OneWay}` 并加注释。

理由：`Mode` 的隐式推断依赖**库那边不写某个 flag**，这是「看不见的契约」；
显式写死 + 注释，既让调用点自解释，也能在将来有人手滑把 `BindsTwoWayByDefault` 加回来时**依然不炸**。

### 3.3 备选方案（未采用）

| 方案 | 为什么不选 |
| --- | --- |
| 给 VM 的 `SelectedConfigs` 补 setter | 治标不治本；且替换集合实例会让行为里已挂的 `CollectionChanged` 监听失配，需要额外处理 |
| 只改 XAML、不动行为 | 同一颗雷留给下一个调用方；本属性全仓库只有 1 个调用点，改库的爆炸半径已经最小 |

## 6. 已知边界

1. **实机点验未完成**。修复的「弹窗能开」这一条只有静态推理 + 探针同源异常坐实，
   缺一次真实点击「系统(S) → 通讯设置」的截图确认。建议下次开机后补。
2. **`Mode=OneWay` 下 VM 侧替换集合实例**：行为会因 DP 变化重新挂监听，逻辑正确；
   但若将来有人把 `SelectedConfigs` 改成带 setter 的「每次 new 一个新集合」，会出现
   「界面选中项丢失」的观感问题 —— 因为它不是回写 DP，而是就地改集合。**保持 `{ get; }` 单例集合是前提。**
3. **`TreeViewBehavior.BindableSelectedItemProperty` 仍保留 `BindsTwoWayByDefault`**：那是**正确的**
   （单选属性必须回写 DP），本次不动。两个行为长得像但语义不同，勿盲目对齐。
4. **双击启动会撞日志文件**：实机过程中曾同时存在两个 VisionMaster 实例，第二个实例启动即崩：
   `System.IO.IOException: The process cannot access the file '…\Logs\2026-09-23.log' because it is being used by another process.`
   （栈：`LogService.OpenWriter` ← `LogService.FlushLoop`）。**这是既有问题，本次未修**，
   现场文件 `crash_reports\crash-20260923-122310-767.txt`。是否加单实例互斥 / 日志文件共享模式待定。
5. 崩溃弹窗「上次运行的现场」会阻塞启动流程，实机自动化必须先点掉它才能操作主窗口。
