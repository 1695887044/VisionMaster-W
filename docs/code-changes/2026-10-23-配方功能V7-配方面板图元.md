## 一、这个控件是什么

工具箱「数据」分类里的 **配方面板（只读）**，默认 300×200。

一块面板显示四样东西：

```
当前配方                      ← 标题（可关掉，留空整行收起）
产品A · v3              [偏离 2]  ← 主行 + 状态胶囊（绿=已生效，橙=偏离，红=悬空，灰=未应用）
检测.Threshold = 0.75
检测.Mode = Circle
定位.X = 120
…
```

**不需要在设计期一条条绑变量**：它自己按固定名字读 `System.Recipe.*` 六条只读系统变量
（`Active` / `Name` / `Version` / `EntryCount` / `Status` / `Summary`）。

三个可配属性：

| 属性 | 默认 | 说明 |
| --- | --- | --- |
| 标题 | `当前配方` | 留空则整行收起 |
| 显示参数明细 | `True` | 关掉只留铭牌（配方名 · 版本 + 状态） |
| 最多显示行数 | `12` | 超出折成「… 共 N 项」；3~50 收敛 |

**只读**：没有编辑态、不写任何变量。改配方走主软件配方管理器，切配方走按钮上的「应用配方」动作。

## 二、实现分层（一处格式化，两端共用）

| 文件 | 职责 |
| --- | --- |
| `Scada/Models/ScadaRecipePanelData.cs` | **唯一的格式化口径**：读 6 条变量 → 主行 / 状态键 / 明细行 / 空态提示 |
| `Scada.Controls/Elements/RecipePanelElement.cs` | WPF 控件：节拍里调上者，把结果写进依赖属性（同值短路） |
| `Scada.Controls/Themes/RecipePanelElement.xaml` | 模板：标题 / 主行 + 状态胶囊 / 明细列表 / 空态；**零硬编码颜色**（R140） |
| `Scada.Controls/Descriptors/BuiltInElements.cs` | 描述符登记（`Hmi.RecipePanel`，分类「数据」） |
| `Web/VisionMaster.ScadaWeb/ScadaWebHost.cs` | `BuildRecipeJson`：2Hz 下发 `recipe` 消息（与 grid 同频同路） |
| `Web/VisionMaster.ScadaWeb/wwwroot/elements-process.js` | `Hmi.RecipePanel` 的 Web 渲染器 |
| `Web/VisionMaster.ScadaWeb/wwwroot/app.js` | `recipe` 消息分发 + 结构重建后补发最近一份 |

为什么放在 `VM.Scada`（领域层）而不是各写一份：同一状态两边说法不一致是**静默**的——
桌面端显示「偏离 2」、Web 端显示 `Deviated 2`，没人会为此开缺陷单。

状态键只认四个：`ok` / `warn` / `danger` / `muted`。模板与 Web 都按**键**挑色，
不做「文案里有没有『偏离』」这种字符串判断（改一次文案颜色就全灰）。

设计态（无运行上下文）显示「配方数据未接入」，**不显示 0 / 空配方**——与轴面板「未接入运动数据」同一口径。

## 三、断言

### 3.1 ScadaChecks 新增 `[RP]` 16 条

| 断言 | 钉住什么 |
| --- | --- |
| RP1 | 描述符登记（默认尺寸 / 分类 / 工具箱可见） |
| RP2 | 三个属性默认值 |
| RP3 | 可配属性都不可绑（面板自己读数据，挂 ?x 等于允许配一个不起作用的绑定） |
| RP4 | 状态键映射四档 |
| RP5 | 悬空优先于偏离 |
| RP6/RP7/RP8 | 明细拆分、超限截断（末行「… 共 N 项」）、空摘要 0 行 |
| RP9 | 无运行上下文 → 「未接入」 |
| RP10/RP11/RP12 | 运行态主行 + 状态键；关明细留铭牌；悬空改「配方已丢失」 |
| RP13 | 缺变量 → 「未接入」而不是「未应用」 |
| RP14/RP15/RP16 | 工厂建模型；无 Application 宿主里套真主题模板不抛异常；模板里有明细列表 |

> RP15/RP16 第一次是红的：在无 `Application` 的断言宿主里控件拿不到隐式样式，
> 量到的是「没套模板的空白控件」。修法与 `TankKpiChecks` 一致——从 `Generic.xaml` 现取 `Style` 赋给控件。

### 3.2 ScadaWebChecks 新增 `B57` 1 条

假值源喂 6 条 `System.Recipe.*`，断言 `recipe` 消息的
`header=产品A · v3` / `statusKey=warn` / `rows=4` / 末行 `… 共 6 项` 且 `truncated=true`。

> 第一次也是红的：假值源用 `Guid.Empty` 作身份时，按名字兜底的分支没走到。
> 改成每条一个真 Guid（更接近生产形态）后通过。

## 五、一处必须记的 flaky

全量 gate 里 `FlowCanvasChecks` 报 2 条红：

```
前置：假设备命令失败后进入安全停机  →  状态=Online 说明=断言用假运动卡
★底层仍报警时清报警不放行：保持安全停机 + 给出原因  →  清报警=True 状态=Online
```

**单独跑 `-Only FlowCanvasChecks` 是 3501/0 全绿**（连跑两次都是）。
这两条是运动安全停机的断言，与配方面板无任何交集（面板不碰运动、不碰命令链）；
从现象看是跨宿主的进程状态残留（前一个宿主的假运动卡/报警状态带进下一个宿主）。
本次没有改它——修它属于运动域的独立问题，混在配方改动里会掩盖真因。
