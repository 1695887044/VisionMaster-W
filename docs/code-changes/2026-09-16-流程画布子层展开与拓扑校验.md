# 开发记录：流程画布子层展开 + 拓扑校验（M2-1 段1段2）

- 日期：2026-09-16
- 类型：功能实现（画布 M2-1 段1 + 段2 + 断言工程）
- 触发场景：M1 阶段画布只画顶层，连线靠运行期判定，结构层非法（数据依赖倒序、跨分支取数）必须等到流程跑起来或编译失败才暴露。本阶段把结构层校验上收到图纸侧，并把画布从「单一顶层视图」升级为「按容器分层、带泳道与执行序号、双击下钻联动」的组态画布。

## 一、需求与决策

### 段1：结构层拓扑校验先行

M1 期画布拉线只走 `LinkedSources` 的写回路径，**校验全部依赖运行期编译**：连线写到 `LinkedSources` 后，`FlowCompiler` 才在 `LinkPorts` 里检查是否乱序。问题有两类——

1. **「画上去了能编过」的错觉**：执行倒序的连线在编译器里其实只是 warning 级别提示，运行时表现是「拿到 null」或「上一轮陈旧值」，画布上看不出。
2. **「画上去就编不过」的困惑**：跨分支取数会在 `FlowCompiler.LinkPorts` 报致命错，但画布不知道，仍然画成正常实线。

决策：把「执行序号 + 容器嵌套层级」抽成纯数据快照（`FlowTopology`），编译期在 `LinkPorts` 之后追加一次 `CheckLinkOrder` 做结构层告警，画布侧同源调用 `Classify` 把对应连线标记为灰色虚线。**单一事实源**：拓扑关系只算一遍，编译器和画布共用同一份判定结果。

### 段2：子画布一层全展开 + 泳道 + 层根 + 增量重建

段2 交付清单（M2-1 段2）：

| 项 | 实现 | 关键决策 |
|---|---|---|
| 子画布一层全展开 | 同一 `NodifyEditor` 内把当前层主列步骤 + 各分支泳道一起渲染 | 不开多画布实例，避免视口/选中态割裂 |
| 分支泳道 | `CanvasNodeKind.Lane` 装饰节点，外接框由分支内所有步骤坐标算出 | 泳道宽高纯展示，不进 `FlowLayoutStore` |
| 不可拖层根 | `CanvasNodeKind.LayerRoot` 装饰节点，`IsDraggable => Kind==Step` | 层根位置是算出来的（`UpdateLayerRootPositions`），拖了没地方存 |
| 不可拖泳道 | `IsSelectable => Kind != Lane` | 泳道是背景，选中无意义 |
| 安全锚点 | 层根位于主列节点最左 X - `LayerRootGap`，纵向排列间距 `LayerRootRow` | 不写 `SafeAnchor` 字段，几何即可表达 |
| 非法线灰色告警 | `CanvasConnectionViewModel.IsIllegal + WarningText` 由 `LinkLegality` 驱动 | 四类文案对应四种非法：倒序、容器后置、跨分支、未知 |
| 双击下钻 | `DrillDownCommand` → `NavigateToPath` | 路径键用「容器 Id#分支下标」拼接，跨渲染稳定 |
| 面包屑 | `ObservableCollection<CanvasCrumbViewModel>`，`IsCurrent` 标末项 | 切层时重建，不订阅 |
| SwitchStep 联动 | A 方案：画布写 `Workspace.SwitchStep`，`_suppressStepSync` 屏蔽反向回环 | 不新增 `GlobalEventBus` 通道，零基础设施改动 |
| 增量重建 | `RebuildCore(resetViewport, dropLayer)` 三态：`Rebuild`/`RebuildLayer`/`RebuildInPlace` | 切流程全清；切层保视口保层；改集合保视口保层 |
| 执行序号 | `OrderIndex`（1 基）由拓扑按 `IndexInOwner` 算，装饰节点恒 0 | 不在 XAML 用集合下标凑，序号是结构语义不是视觉序 |
| Watch 订阅范围 | `AttachLists` 只 Watch 当前层主列表 + 当前层所有容器分支的 `Steps` | 跨层列表不订阅：下钻后再 Watch，避免无谓重建 |

### 总线方案：A 方案（不新增通道）

画布选中节点时直接调 `_workspace.SwitchStep(step)`，`WorkspaceContext` 同步派发 `PropertyChanged`。`ProcessViewModel`（流程栏/参数面板）原本就订阅它，无需新增 `GlobalEventBus` 通道。

回环防护：`WorkspaceContext.SwitchStep` 派发会触发画布侧的 `OnSelectedStepChanged`，画布在该回调里检查 `_suppressStepSync` 标志——本画布主动发起 `SwitchStep` 时置位、`finally` 清零，进入时即返回。这样画布既不会因为外部切换重建（外部切 = 流程栏切 = 用户在树选步骤，画布要响应），也不会因为自己发起切换而重建（自己切 = 用户在画布选节点，画布不需要再重建自己）。

### Header 陈旧点修复

段2 段1 期 `CanvasNodeViewModel.Header` 是构造时传入的 `_header` 字符串快照，泳道与层根改名后不刷新。改为 getter 直接回读真相源：

```csharp
public string Header
{
    get
    {
        if (Kind == CanvasNodeKind.Lane)
            return Branch?.DisplayName ?? _header;   // 泳道标题回读分支 DisplayName
        if (Kind == CanvasNodeKind.LayerRoot)
            return Model != null ? $"层根 · {Model.StepName}" : _header;
        var name = Model.StepName;
        return Model.IsDisEnable ? $"{name}（已禁用）" : name;   // 步骤名以 Model 为唯一真相源
    }
}
```

显示刷新靠 `RefreshHeader()` 发 `PropertyChanged`，回读与缓存成本完全相同，但少一个陈旧点。

## 三、验证结果

### 编译

```
dotnet build VisionMaster.sln
```

全解决方案 0 错误。过程中修掉的问题：

1. `Harness.Out`/`In` 原为 `static` 但以 `h.Out(...)` 调用 → CS0176，改为实例方法。
