## 1. 背景

手眼标定插件提交（`3a1d41ed`）后按 R182 跑收尾验证，`tools/run_gates.ps1` 连续暴露两个"闸门自己坏了"的问题，而且**两次都是报绿**：

1. **挂死**：18:27 启动后，`audit_root` / `audit_artifacts` 通过、`CommChecks` 构建完成（`raw-build-CommChecks.out` 411KB，尾部 `0 个错误 / 已用时间 00:00:18.91`），然后 **11 分钟没有任何新文件**。实测 gate 进程（PID 49788）活着但 CPU 只有 0.81s，**没有任何子进程**（`Get-CimInstance Win32_Process -Filter 'ParentProcessId=49788'` 为空），`tasklist` 里也没有 `CommChecks.exe`。结论：不是宿主在跑，是 `Start-Process -Wait` 在**等整棵进程树**——PowerShell 5.1 的 `-Wait` 等的是进程树，一个残留后代就能永久阻塞。
2. **报假绿**：改成"去掉 `-Wait`、自己 `WaitForExit`"之后，八步全报 `[OK] xxx exit=0 BUILD FAILED`，末尾 `[run_gates] OK - 8 steps green` —— 构建日志里全是 `0 个错误`，构建其实成功，但 note 说 BUILD FAILED、exit 却显示 0。根因：**`Start-Process -PassThru` 在不加 `-Wait` 时 `ExitCode` 永远是 `$null`**（实测 `raw ExitCode: []` / `WaitForExit=True` / `after wait ExitCode: []` / `after refresh ExitCode: []` / `HasExited=True`）。`$null -ne 0` 为真 → 走进失败分支；`[int]$null` → 0 → 印出 exit=0。**六个宿主一个都没跑，却报了八步全绿。**

第 2 条比第 1 条更坏：挂死至少看得出来，假绿看不出来。

## 3. 关键决策

1. **不再用 `Start-Process`，不是"用法不对"**。它的 `-Wait` 等进程树（会挂死）、不用 `-Wait` 时 `ExitCode` 恒 `$null`（会假绿）——这两条在 PowerShell 5.1 上都无法通过参数绕开，所以直接驱动 `System.Diagnostics.Process`。实测这条路径 `ExitCode` 是真 `Int32`（`cmd /c exit 3` → `exitcode=3 / exitcode_type=Int32`）。
2. **原始字节落盘，解码放在读取侧**。`BaseStream.CopyToAsync` 只搬字节，不经过控制台代码页；回读时严格 UTF-8 优先、失败回落 936（R183 ①）。这样"日志是乱码"和"日志是空的"能分开。
3. **`$null` 退出码判红，不是判绿也不是判跳过**。之前的 `[int]$Exit` 把 `$null` 悄悄变成 0，这正是假绿的来源。未知就是红——和 R183 ② "零输出判红"同一个立场。
4. **超时是红（124），不是无限等**。挂死 11 分钟的代价是"用户以为还在跑"，而 gate 的价值就是给出判决。默认 600 秒，超时杀进程树并写原因。
5. **不把 `Add-Row` 改成"容忍 null"**。容忍 null 等于把"我不知道退出码"当成通过；宁可红着让人看日志。
