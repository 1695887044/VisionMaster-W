# SCADA 图像显示图元（Hmi.ImageView，显示流程输出的 HImage）

补上 SCADA 图元库一直缺的一类：**把视觉流程产出的图像摆到画面上**。
此前图元库 16 类全是"标量"图元（数值、状态、文字），`HImage` 这类**位图**没有任何落脚点。

本轮新增第 17 类图元 `Hmi.ImageView`，并顺手把"HImage 变量"这条路在变量侧放开。

---

## 一、需求与决策

### 1. 需求

用户指令（逐字）：

> 「可以加个控件 用来显示流程输出的图片吗 HImage类型的」

即：画面上的一个框，绑一个 `HImage` 类型的变量，流程每次产出新图就自动刷新。

### 2. 关键决策（已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 图元放哪 | 走既有三处范式：`Elements/` 控件类 + `Themes/` 样式 + `BuiltInElements` 一条描述符 | 领域层、序列化层、编辑器一行不改，`.vms` 里只留一个字符串 `TypeKey` |
| 2 | 转换落在哪 | **宿主侧 `ScadaValueSource.VariableHandle.Value`**（VM.Core），图元只认 `ImageSource` | 图元控件库（VM.Scada.Controls）**刻意不引 HalconDotNet**：画面领域层要保持"不认识视觉库"的干净边界 |
| 3 | 属性袋怎么存 | `Source` 的 `DefaultValue` **留空串** | 属性袋是字符串键值对，位图没法文本化；`ElementDescriptor.Validate()` 只对非空默认值做字符串转换，留空即免转换 |
| 4 | 属性面板给什么编辑器 | 新增 `ElementPropertyKind.Image`，只给**只读状态行 + 绑定按钮**，不给输入框 | 位图不是一段文本，给输入框必然引导用户去手填一个永远填不对的东西 |
| 5 | 变量侧 | `AvailableTypes` 加「图像 (HImage)」；`IsEditableNode` 对 HImage 返回 false | 变量能建、能持有、能写入（`VariableFactory`/`TypeCache` 本无白名单）；但初始值那格必须只读 |
| 6 | 网络模式 | `FilteredTypes` 过滤掉 HImage | 设备侧根本没有"图像点位"，留着只会让人配出一个永远为空的变量 |
| 7 | 写方向 | `VariableValueConverter` 对 HImage 直接给中文错误 | 流程 → 图像变量的回写路径不存在，界面这一侧只能报错（见"已知边界"） |
| 8 | 缩放方式 | 复用 WPF 的 `System.Windows.Media.Stretch` 枚举，不做自定义枚举 | `ConvertFromString` / `ScadaValueConverter` 天然认它，零转换代码 |
| 9 | `None` 的译名 | 全局词汇表里由「不显示」改为「无」 | 见下文"译名冲突" |

### 3. 译名冲突（决策 9 的展开）

`ScadaChoiceNames` 是**全局词汇表**（落盘值 → 面板中文名），口径是"一个值只能有一个词"。
新加的 `Stretch` 候选里 `None` 已被管路「流向」占用，原译名「不显示」在图像上会读成
"图像不显示"，是误导。故取两边都读得通的「无」：

| 属性 | 行标签 | 显示 |
|---|---|---|
| `Hmi.Pipe.Direction` | 流向 | 无（= 无流向 / 不画箭头） |
| `Hmi.ImageView.Stretch` | 缩放方式 | 无（= 不缩放，按原始尺寸居中） |

连带把 `Hmi.Pipe` 描述符的 `Description` 里"正向/反向/不显示"同步改成"正向/反向/无"。

### 4. 数据通路（为什么转换只做一次）

```
流程写入 HImage 变量
      ↓  VariableHandle.ValueChanged（流程线程）
ScadaRuntimeBinder.OnValueChanged  ← 就在这条线程上读 handle.Value
      ↓
ScadaValueSource.VariableHandle.Value   ← ★ 唯一转换落点：HImage → BitmapSource(Freeze)
      ↓  脏值暂存表（存的是已冻结的位图）
Dispatcher.BeginInvoke → ScadaElementBase.TryApplyRuntimeValue
      ↓  ScadaValueConverter.TryConvert：值已是 ImageSource，第②档 IsInstanceOfType 直通
ImageViewElement.Source
```

两个要点：

- **`Freeze()` 是必须项**：转换在流程线程发生，不冻结的位图交给 UI 线程读会直接抛跨线程访问异常。
- **图元库不必认识 HalconDotNet**：转换产物是 `BitmapSource`，它本身就是 `ImageSource`，
  绑定换算链里"值已是目标类型"那一档零改动直通。

## 四、已知边界

1. **流程 → 图像变量的回写路径不存在**（本窗口决定不新建插件）
   `VariableAssignmentPlugin` 按名字字符串寻址，内部走 `Convert.ChangeType`，
   对 `HImage` 必然抛异常。因此目前图像变量**只能由 C# 脚本插件等直接持有变量引用的方式写入**，
   通用"赋值变量"步骤写不了图像。
2. **图像变量的值不落盘**
   `VariablePersistenceService.Capture` 走 `VariableDto.JsonToValue` 的 JSON 往返，
   `HImage` 无法 JSON 序列化 → 图像变量的当前值不入 `.vms`，**重启后为空**（画面回落显示"无图像"）。
3. **支持范围刻意收窄**
   只处理单通道（`byte`/`int2`/`uint2`/`int4`/`real`）与三通道（仅 `byte`）。
   多光谱、方向图、复数图返回 null → 图元显示"无图像"，不抛异常打断整页。
4. **三通道非 byte 图不处理**（少见，避免引入色彩空间换算的复杂度）。
5. **`int4` / `real` 是"按本图自身 min/max 线性拉伸"**：同一台相机前后两帧的灰度
   量程不同，视觉上会看到"亮度整体漂移"，这是显示口径而非数据失真（变量里存的仍是原图）。
6. **`Source` 不参与手填**：属性面板那一行没有输入框，只能通过右侧 ƒx 走变量绑定。
