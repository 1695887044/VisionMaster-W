# 2026-10-09 涂胶（BeadInspect）配置界面设计级重排（设置栏在左、画布称王）

## 一、起因

用户真机截图反馈：「涂胶插件**布局不合适、不现代化、可视化也不行**」。前两轮（4:6 → 2:1）只调了行比例，没解决结构问题。

**真机尺寸定量**（本轮关键事实）：截图 1900×1350 物理像素，按左列卡宽 ~630 物理 ÷ 令牌 330 反推 → **约 200% DPI 缩放**；换算 **窗口 ≈ 950×675、插件视图区 ≈ 914×547 逻辑像素**——比此前验证过的所有尺寸都小。探针在 914×547 复现出与用户截图逐条对上的四个症状：

| # | 症状（before，914×547 实测） | 数字 |
| --- | --- | --- |
| 1 | 画布图片可视区极小 | **97px 高**（按高适配宽仅 121px）——右列 4 件抢 523px：工具条 182 + 画布 192 + 参数卡 72 + 状态/预览 106 |
| 2 | 参数卡只剩两个表头 | 内滚动 viewport=38 |
| 3 | 工具条"适应图片"掉第二行 | 7 按钮需 588 / 可用 518 |
| 4 | 状态/预览行下沿被裁 | y=482..580 > 视口 547 |

## 二、方案（结构重排，不是调比例）

右列从「四行叠卡」改为 **2 行：工作区卡（`*`）+ 状态条（Auto）**：

- **工具条与画布同卡**（省一层卡间距与内边距）；工具条只留 6 个动作按钮，**「适应图片」+ 点数迁进画布标题行**（都描述/作用于画布本身）→ 914 宽下工具条一行放下。
- **画布 hero 占满余高**：`h:ImageEdit` MinHeight=120 兜底；操作提示从两行压成一行（完整口径进 ToolTip）；颜色图例常驻一行（橙=路径 红=点 青=四角）。
- **「配方参数」「路径点列」迁入左列滚动区**，顺序按使用频率：⓪ 输入绑定 → ① 配方库（两张自动提取用图收进折叠 Expander「自动提取输入（可选）」）→ ② 路径点列（DataGrid 固定 168 ≈ 6 行，永不塌）→ ③ 配方参数（含高级 Expander）→ ④ 运行参数 → ⑤ 平面匹配搜索范围 → 预览 → 怎么用。
- **预览卡迁左列 + 无图整卡折叠** + `Height=200`（ImageReadOnly 是填满父容器的画布，不给高度在 Auto 行里自然高=0——这正是它此前一直像"黑缝"的根因）。
- **左/右列之间加 GridSplitter**（6px，悬停变深）：想再给画布让宽可手动拖。
- 三处本视图局部样式（工作区卡内边距 14→8、工具条按钮 12→10/MinHeight 24、分栏条）全部 `BasedOn` 共享件；**共享令牌一个没改**。

**放弃的备选**（写进注释防回退）：预览留右列侧栏会压画布宽 <400；横幅做画布浮层会挡图抢点击；横幅出现时藏提示行（拾取提示恰是刚学完微调点时最需要的）；左列改 Tab（形态变更超本视图权限）；工具条放左列（跨栏操作违反"谁管谁"）。

## 五、未决

1. **横幅出现时画布 300px（验收线 330）**：结论横幅是"点完学习立刻看见结论"的硬要求，出现时画布必然让位约 42px；把成功话术压到一行内可消化（属 hmi 侧文案长度）。
2. **左列在 547 高下是 3.7 屏滚动**（内容 1916 / 视口 523，滚到配方参数需 836px）：滚动可达已达标并出取证图；要"免滚"只能改分页/Tab（形态变更，需拍板）。
3. **共享字典两枚死令牌**：`PluginParamsCardMinHeight/MaxHeight` 已无视图引用（本视图改用局部样式），可在清理轮退役；`PluginCanvasMinHeight` 仍用但注释口径陈旧。
4. `PluginViewMinHeight=360` 对本视图仍不成立（真实下限 ≈620×540，探针承诺区间已按此执行）。
5. 新交互面供 reviewer/hmi 知悉：GridSplitter 可拖窄（用户主动行为）；分栏位置不持久化；「适应图片」移位、两张图路径收进 Expander、卡片重编号——控件与绑定一个不少。
6. 预览卡"有图才出现"：左列长度随学习/试运行状态变化；若要常驻占位可改回固定占位。
