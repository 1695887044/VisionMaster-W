## 一、需求与决策

### 1. 需求

路线图 S13 原文：

> `ScadaChecks --stress` 基线固化：图元数、绑定数、切页次数、报警数四组规模，每次改动跑一遍并留档，**回归时看数字不看感觉**。

要解决的具体症状：**"性能回归"这件事在此之前只有感觉，没有证据**。`[E]/[I]/[Q]` 三段压力测试证明的是"万级不塌"——它们是**布尔断言**（耗时 < 某个上限），只能回答"有没有塌"，回答不了"比上一版慢了多少"。而真正折磨现场的是后者：一次重构把 O(n) 的索引换回线性扫描，从 5ms 变成 500ms，**照样能过 `< 3000ms` 的阈值**，一直到画面真卡了才被发现。

### 2. 决策清单

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| B-1 | 与 `[E]/[I]/[Q]` 的关系 | **另开一段 `[BL]`，不改造那三段** | 那三段各自钉一类对象的**正确性 + 吞吐**，是本阶段的回归网；基线只回答"快慢"。混进去会让"某条断言红了"分不清是**功能坏了**还是**机器抖了** |
| B-2 | 报什么数字 | **单位成本**（µs/图元、µs/绑定、µs/切页、µs/报警轮），而不是总毫秒 | 规模可以不同、机器可以不同，**单位成本是唯一能跨版本、跨机器对比的数字**。总毫秒只在同一台机器上同一规模下才有意义 |
| B-3 | 阈值怎么定 | **取得极宽**，只拦"数量级退化" | 基线断言一旦开始拦机器抖动，就会变成"偶尔红一次"的噪声——而**噪声最后一定会被忽略**，等于白写。精确数字靠打印出来的留档块人工对比 |
| B-4 | 图元数取 20000（`[Q]` 是 10000） | **规模翻一倍** | 基线的意义是"看规模再翻一倍曲线还直不直"。与 `[Q]` 同规模只会得到同一个数字，等于白跑一遍 |
| B-5 | 为什么要补"切页次数" | 运行态唯一**每次操作都走完整条链**的动作（卸旧页 → 换 `CurrentPage` → 载新页 → 压页栈），且页栈是运行态**唯一会随操作时长增长**的集合 | 除了单次成本，必须钉住"栈深有上限、停止后归零"——组态软件连开几个月，一次没清干净的页栈就是一条缓慢泄漏 |
| B-6 | 为什么要补"报警数" | 报警有一条**会随时长增长的历史**（`MaxHistoryRecords = 2000`） | 除单位成本外钉两件事：① 历史被削在上限内；② **退订后订阅数归零**——500 条报警漏一条订阅就是 500 个对象永远回收不掉 |
| B-7 | 报警轮次怎么设计 | **完整走"报 → 全部确认 → 恢复"**，而不是只报不管 | 只报不管的话 `ActiveAlarms` 永远不落（未确认的恢复会停在 `Recovered` 态等确认），既测不到"了结"这条路径，也测不出历史被削的真实节奏 |
| B-8 | 页栈上限断言怎么写 | 写 **`> 0 && <= 32 && < switchCount`**，不写 `== 32` | 上限是 `ScadaRuntime` 的 `private const`。断言它的**性质**（有界、且远小于切页数）而不是**字面值**——将来调上限不该让基线变红，但"页栈不设上限"必须变红。字面值由留档块打印出来 |
| B-9 | 撤销栈怎么处理 | 段首 `Clear()`、段尾 `finally Clear()` | `ScadaEditHistory` 是**全局静态**的单栈双向结构（`MaxDepth = 50`），本段建画面/建报警都会压栈。不清理就会把压栈留给后面的段（`[AH]` 段已有同款纪律） |
| B-10 | 假时钟 | 报警组传定值 `Func<DateTime>` | 本组不测延时/断线，但引擎每个公开入口都从时钟取"现在几点"。传定值是为了与 `[AH]` 段同一写法，不引入 `Thread.Sleep`（那种"偶尔红一次"的断言一定会被当噪声忽略） |

### 3. 四组规模各测什么

| 组 | 规模 | 测什么 | 附带钉住的性质 |
|---|---|---|---|
| ① 图元数 | 20000 个图元 | 构造（`Elements.Add`）+ 按身份查找（`FindElement` × 200000） | 查找命中数 = 探针数（索引没被换回线性扫描） |
| ② 绑定数 | 10000 图元 × 2 = 20000 条绑定 | 跨图元枚举（`EnumerateBindings`）+ 改名级联（`RefreshVariableReferences`） | 枚举条数正确、级联命中数正确 |
| ③ 切页次数 | 8 页 × 200 图元，切 5000 次 | 运行态来回切页（`ScadaRuntime.Navigate`） | 每次**真的**换页（`PageLoaded` 次数 = 切页数 + 1 次启动）；页栈有界；`Stop()` 后当前页与页栈归零 |
| ④ 报警数 | 500 条定义 × 10 轮 | 报 → 全部确认 → 恢复 → `Tick`（含"没有值变化、纯靠节拍"的那条路） | 迁移次数 = 5000 且实时列表归零；历史削到 2000 上限；退订后订阅数归零 |

```
→ 已成功生成。0 错误（警告为既有 CS860x 可空性提示，与本次改动无关）
```

### 2. 断言

```
dotnet run --project ScadaChecks --no-build -- --stress
→ 通过: 1206  失败: 0
→ >>> 全部断言通过 <<<
```

口径：常规（不带 `--stress`）1181 条；`--stress` 叠加 `[E]` 4 + `[I]` 4 + `[Q]` 9 = 17 条；本次新增 `[BL]` 8 条 → **1181 + 17 + 8 = 1206**。

### 3. 基线数字（留档 —— 回归时与这一块对比）

跑于 2026-09-20，开发机（Windows / .NET 9 / Debug 构建）：

```
图元数   | 20000 个                     | 构造 29ms = 1.4µs/图元   | 查找 200000 次 3ms = 0.01µs/次
绑定数   | 20000 条（10000 图元 × 2）    | 级联 3ms  = 0.15µs/绑定  | 命中 10000
切页次数 | 5000 次（8 页 × 200 图元）    | 1ms       = 0.20µs/次    | 页栈峰值 32、Stop 后归零
报警数   | 500 条 × 10 轮               | 循环 25ms = 5.00µs/报警轮 | 历史 2000/2000、退订残留 0
```

**怎么读这张表**（回归时先看这里）：

- 四条单位成本都在 **亚微秒到几微秒** 量级。**任何一条跳一个数量级（比如 µs 变 ms）就是真回归**，先查索引/缓存是不是被绕过了，不要先怀疑机器。
- "图元构造 1.4µs/图元"和"查找 0.01µs/次"之间差两个数量级是**设计使然**：构造要建对象 + 维护 `FindElement` 的索引，查找只是一次字典命中。这两条一旦**接近**了，说明索引退化成了线性扫描。
- "切页 0.20µs/次"是**纯领域层成本**——不含 WPF 渲染。真机的切页体感由渲染主导，这个数字只保证"逻辑侧没有隐藏的 O(n)"。
- "报警 5.00µs/报警轮"是**一整轮**（越限判定 + 事件广播 + 确认 + 恢复 + 历史写入 + 一次节拍），摊到单条报警上是这个量级。它明显高于其他三条是正常的：一轮里有 4 次状态迁移和 3 次事件。
- 断言与数字是**两套口径**：断言只管量级（防"塌"），数字管趋势（防"慢"）。**数字不红不代表没回归**，要人工对比。

### 4. 本次新增的 8 条断言

| # | 断言 | 拦什么 |
|---|---|---|
| 1 | ① 图元数 20000：构造与按身份查找都不随规模退化 | 索引退化、构造路径里藏 O(n²) |
| 2 | ② 绑定数 20000：枚举条数与改名级联命中数都正确、单位成本不退化 | 级联遍历里加了"按图元重建索引" |
| 3 | ③ 切页 5000 次：每次都真的换页（`Loaded` = 切页数 + 1 次启动）且单次成本不退化 | 切页被静默降级成"重复页不换"、或切页成本随页数增长 |
| 4 | ③ 切页：运行中页栈受上限约束 | 页栈被改成无上限（长跑泄漏） |
| 5 | ③ 切页：停止后当前页与页栈全部归零 | `Stop()` 漏清页栈 / 漏清当前页 |
| 6 | ④ 报警数 500 × 10 轮：迁移次数正确、单位成本不退化 | 判定链里藏 O(槽数²)、事件重复广播 |
| 7 | ④ 报警历史被削在上限内（5000 → 2000） | 历史裁剪被拿掉（内存随时长无限增长） |
| 8 | ④ 报警退订后订阅数归零 | 退订漏摘通道（对象永远回收不掉） |

## 四、已知边界

1. **不是真机性能**。四组数字全部是**领域层**成本，不含 WPF 渲染、不含 `Dispatcher` 排队、不含真实 IO。真机体感以 `S6` 的"200 绑定 × 20ms × 60s"验收（S13-b）为准，本段不替代它。
2. **阈值刻意宽，等于放弃了"自动拦住小退化"**。这是 B-3 的自觉取舍：宁可让 10% 的退化靠人眼对比留档块发现，也不让基线变成噪声源。**代价是"留档块必须真被人看"**——目前没有任何机制强制这一点（见欠债 3）。
3. **留档块是打印出来的，不是自动落文件的**。没有把数字写进 `docs/` 的自动化，靠跑的人粘贴。做自动落盘要考虑"写到哪、谁覆盖、CI 上要不要写"，属于打包/交付那一摊（S13-f），本轮不做。
4. **Debug 构建下的数字**。Release 会更快，但本项目断言一直在 Debug 下跑，基线沿用同一配置才可比。**不要跨配置对比数字**。
5. **`④ 报警数` 不测延时与断线**。那两条由 `[AH]` 段用假时钟钉住（推十分钟不靠 `Sleep`）。本组只走"报 → 确认 → 恢复"的稳态轮次。
6. **`③ 切页` 的页栈峰值固定是 32**（上限值），与切 5000 次无关——这是断言 4 要的性质。若将来把上限调大，留档块里的数字会变、断言不会红（B-8 的自觉取舍）。
7. **`--stress` 才跑本段**。常规运行不跑，所以"每次改动跑一遍"这条纪律**靠人**（改 SCADA 相关代码时应带 `--stress`）。加进常规运行会让每次编译验证慢一截，而常规验证的高频场景不需要它。
