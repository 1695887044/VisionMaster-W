## 一、组名对齐

| 常量 | 改前 | 改后 | 设计稿 |
| --- | --- | --- | --- |
| `General` | 常规 | **基本** | 基本 |
| `Text` | 文字 | **文本** | 文本 |
| `Layout` | 位置与尺寸 | **布局** | 布局 |
| `Permission` → `Interaction` | 权限 | **交互** | 交互 |

常量名一并把 `Permission` 改成 `Interaction`：组名变了还叫 Permission，下一个人会以为它只管权限。

**为什么改名只改了 4 行**：批次 A 把全仓 33 个文件的字面量都换成了常量，所以这次只动目录里的值，
描述符、21 个图元类、曲线图元、面板、断言全部自动跟随——这正是 A 批的价值兑现。

**用户可见描述同步**：三处 ToolTip 写着"见属性面板「权限」那一行"（IOField 的模式、文本框的模式、
BuiltInElements 的说明），一并改成「交互」——描述里指错组名，用户会去面板上找不到。

## 二、「类型」只读行

设计稿的「基本」组是 `名称 / 类型 / 图层`。本批只做**类型**（图层按用户裁定不做，见下）。

- **值取 `TypeKey`（如 `Hmi.Button`），不是 CLR 类名**。设计稿画的是 `PumpElement`，但
  `TypeKey` 才是写进 `.vms` 的长期标识、也是"本机未注册该图元"提示与注册表用的键；
  CLR 类名会随重构变，写进面板只会误导。这属**有意偏差**（行标签与只读形态与设计稿一致，取值不同）。
- **新增 `ElementPropertyKind.ReadOnly`**：面板给一块与输入框同尺码的底色（`EditReadOnly`），
  **不给输入框**。不复用"只读的 TextBox"——那仍然能聚焦、能选中、能打字，而打进去的字会被静默丢掉。
- **两道闸**：模板管"不给编辑入口"，`ScadaTypeRow.Commit` 恒 `false` 管"绕过模板也写不进去"。
- **基类补一条**：`ScadaPropertyRowBase.Value` 的 setter 遇到 `ReadOnly` 行时**按模型回填**而不是
  保留用户文本——只读行连输入框都没有，缓冲区里多出一个模型里不存在的值，等于面板在展示假事实
  （其它类型保留文本是为了"让人就地改完"，只读行没有这个场景）。
- **不进描述符**：类型键是"这一行实例"的事实，不是"这一类图元"的声明；塞进描述符只会让
  `ElementValueAccess` 多一条"这个键没有落点"的特例。与权限行同一安排（`ScadaTypeSpec` + `ScadaTypeRow`）。

## 三、图层：不做（有意偏差）

用户 2026-10-20 裁定：**属性面板不加「图层」下拉**。图层归属已经是画布右键菜单里的动作，
再放一份就是"一个东西两个入口"，用户迟早会怀疑两处不同步（与 `ScadaPageProperties` 里
`ShowGrid` / `SnapToGrid` 刻意不进面板同一条口径）。已写进 `app-shell/README.md` 的「已知偏差」。

| 图元 | 改前（组序） | 改后（组序） |

### 断言（`ScadaChecks` 全量 **2089 通过 / 0 失败**）

新增/更新的关键条目：

```
[√通过] 组序取自 ScadaPropertyGroups.Order：基本→外观→文本→布局→交互→动画
        → 基本/外观/文本/布局/交互/动画
[√通过] 组内行数按声明落位：基本 2 条（名称 + 只读类型）、外观 4 条、文本 3 条、布局 5 条
        → 基本:2/外观:4/文本:3/布局:5/交互:1/动画:4
[√通过] 「类型」行只读展示类型键（不是 CLR 类名、也不是显示名），且不给 ƒx
        → ReadOnly / Hmi.Rectangle / ƒx=False
[√通过] 「类型」行写不进去：直接往行上赋值也不改模型，缓冲按模型回填（第二道闸）
        → 模型=Hmi.Rectangle / 行=Hmi.Rectangle
[√通过] 目录显示名快照（改名必须同时改这条断言）
```

`UniversalRows` 从 1 改成 2（权限 + 类型），所有"行数 = 描述符 + 事件 + 动画 + 通用关系"的账本
随之对齐；位按钮/按钮两条断言的文案里的行数与组名同步更新（28→29 行、21→22 行、权限→交互）。

**渲染层已被间接验证**：`ScadaChecks` 里有几条像素级断言会真的实例化并渲染 `ScadaPropertyView`
（变量带底色、绑定按钮的实心/白底对照）。它们全绿说明 `EditReadOnly` 模板与它引用的
`ScadaBadgeBackgroundBrush` 在视图作用域里解析得开——`StaticResource` 缺失会在 XAML 解析期就抛。
