## 8. 追加：左栏分支表达式摘要实时刷新（2026-10-20）

### 结论：**已经是实时的，不需要改代码**

原先记的"编辑当前分支表达式时，左栏摘要要切一次分支才刷新"经实测**不成立**：

- 摘要 `TextBlock` 绑的是 `{Binding Expression}`，`ListBox.ItemsSource` 直接绑 `Branches`（不是快照）；
- `StepCollection.Expression` 的 setter 走 `SetProperty`，会发 `PropertyChanged(nameof(Expression))`；
- 绑定链一通，改值即刷新。

### 新增守门：`FlowCanvasChecks\ConditionEditorSummaryProbe.cs`（9 条，`[CE2-L]`）

**为什么不用真 `ConditionEditorView`**：它的根节点写着 `Background="{StaticResource DialogBackgroundBrush}"`，`StaticResource` 在 **XAML 解析期**就要解析；断言宿主没有 `Application`（R67 禁止在 FlowCanvasChecks 里 `new Application`），把字典塞进 `Window.Resources` 也进不了 `UserControl` 的解析链 → 直接 `XamlParseException`（实测：行 12 位置 5）。所以拆成"绑定出处 + 通知链"两步，合起来等价：

| 组 | 断言 | 判据 |
| --- | --- | --- |
| 静态（3） | S1 | 分支摘要 `TextBlock` 绑 `Expression`（不是 `DisplayName` / `StepName`） |
| | S2 | 摘要红态绑 `IsConditionMissing`（与编译器同一判定） |
| | S3 | 左栏 `ItemsSource` 直接绑 `Branches`（不是快照/投影） |
| 运行时（6） | 容器 | 同形 `ListBox` 已生成容器 |
| | 改值 | 改 `Expression` → 该行摘要立刻变新值（**不切分支**） |
| | 连续改 | 第二次改继续跟随（不是只刷一次） |
| | 非当前行 | 改第二条分支 → 该行摘要同样实时 |
| | 清空 | 清空 `Expression` → 摘要同步为空（真视图由 `IsConditionMissing` 换红字） |
| | 前提反证 | `StepCollection.Expression` 的 setter 确实发 `PropertyChanged`（收到 1 次） |

**变异反证**：把 XAML 的 `Text="{Binding Expression}"` 改成 `{Binding DisplayName}` → S1 立刻变红；把 `ItemsSource` 换成投影副本 → S3 变红。

> 该探针最初写成"实例化真视图"，因上述 `StaticResource` 解析期限制不可行（R67 不允许 `new Application`）；已改为静态 + 同形模板两步，并在文件头写明原因，避免后来者再走一遍。

## 9. 追加：底栏按钮悬停区域与焦点环（2026-10-20 真机反馈）

### 现象

真机截图（用户用橙红圆角框圈出「取消」按钮）：底栏按钮的悬停/焦点区域看起来明显不对。

### 根因（两层）

1. **悬停叠加层被 Padding 缩进**：`FluentButtonStyle` 的按钮模板把 `Padding="{TemplateBinding Padding}"` 放在根 `Border` 上，`HoverOverlay` / `PressedOverlay` 是 `Border` 的子级，于是叠加层跟着 `Padding` 一起缩进。实测 96×32.6 的「取消」按钮，悬停时只有中间 **70×18.6** 的小胶囊变色（`Padding=12,6,12,6`），不是整颗按钮 —— 这正是"悬浮区域怪怪的"的来源。
2. **焦点环是系统默认虚线**：`FluentButtonStyle` 没设 `FocusVisualStyle`，键盘 Tab 到按钮时用的是 WPF 默认的 1px 黑色虚线矩形（`SystemParameters.FocusVisualStyleKey`），既不是圆角、也和按钮形状对不上。`Dialog.Misc.xaml` 里虽然定义了 `DialogFocusVisual`，但全仓没有任何按钮引用它。

### 修法

| 文件 | 改动 |
| --- | --- |
| `UI\Controls\Themes\Fluent\FluentControls.xaml` | 按钮模板：`Padding` 从根 `Border` 挪到 `ContentPresenter.Margin`（内容位置不变），`HoverOverlay` / `PressedOverlay` 与内容同级铺满 `Border` 内容区（`BorderThickness` 内）；新增 `FluentButtonFocusVisual`（外圈 2px `FluentAccentBrush` + 内圈 1px `FluentOnAccentTextBrush` 白线，`FluentRadiusMedium` 圆角、向内收 2px；白线保证 Accent 主按钮上蓝环不消失），并挂到 `FluentButtonStyle.FocusVisualStyle`。 |
| `UI\Controls\Themes\Fluent\FluentAliases.xaml` | 更新 `DialogIconButton` 的过时注释（叠加层已由模板铺满，Padding=0 仅用于方形几何）。 |
| `UI\Controls\Themes\Dialog\Dialog.Misc.xaml` | 更正 `DialogFocusVisual` 注释里的"外扩 2px"为"向内收 2px"（实现一直是 `Margin=2` 内缩）。 |
| `VisionMaster\Views\DialogViews\ConditionEditorView.xaml(.cs)` | 初始焦点改到主输入区：Case→判据 ComboBox、For→循环次数、其余→表达式编辑器；避免弹窗一打开焦点先停在底栏按钮上。 |

### 验证

- 渲染探针（`_FocusProbe --view`，真实 `ConditionEditorView` + 1120×760）：
  - 修复前悬停叠加层 70×18.6（按钮 96×32.6）；修复后 **94×30.6**（铺满 `BorderThickness` 内），出图 `tools\_condition_view_hover.png`；
  - 焦点环出图 `tools\_condition_view_focus.png`（取消，浅底看外圈强调色）与 `tools\_condition_view_focus_save.png`（保存并应用，Accent 底看内圈白线）：两层环在两种底色上都可见，不再是系统虚线/大方框。
- `UIThemeSmokeTest --controls` 新增 3 条按钮规格断言（叠加层铺满 / 焦点环走 `FluentButtonFocusVisual` / 内容位置不变）全部通过；同轮 4 条失败是开关样式断言（实测 54×22 vs 期望 44×24），开关走独立的 `FluentToggleSwitchStyle`，与本次按钮模板改动无交集。
- `FlowCanvasChecks` 全量 gate：首轮 **2797 通过 / 0 失败**（含 `[CE2]` 26 条与 `[CE2-L]` 9 条）；收尾复跑 **2796 / 1**，唯一失败是定时流程"已在运行中"的时序用例（`[定时] 流程「定时真跑流程」正被其它执行占用`），`[CE2]` 36 条仍全绿，与本次 UI 改动无关。

### 影响面

按钮模板是全局 Fluent 按钮共用，所有 `Dialog*Button` / `FluentButton*` 的悬停、按下、键盘焦点环都会变成"整颗按钮"的形态；这是统一修正，不是只改条件编辑器。无布局尺寸变化（`Padding` 只是从 `Border.Padding` 挪到 `ContentPresenter.Margin`，内容盒不变）。
