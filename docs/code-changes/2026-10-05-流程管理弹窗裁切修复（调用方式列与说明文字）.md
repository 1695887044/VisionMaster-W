- 项目：VisionMaster（WPF + Prism 9 + Unity + Halcon）

- 类型：界面缺陷修复（内容被裁 / 控件被挤出可视区）+ 检查断言纠偏
- 起因：用户实机截图——「调用方式（多选）」列只露出「定时/变量」，第三个（子程序）被截断、**第四个（HTTP）完全看不见（勾不到）**；勾选框下方汇总文本被裁成一条线；底部说明第 3 行被弹窗右边界裁断

## 一、两个真根因（不是"列宽不够"这么简单）——由 `ui` 角色用离屏+真实窗口渲染定位

| # | 根因 | 证据 |
| --- | --- | --- |
| 1 | **Fluent 隐式 CheckBox 样式带 `MinWidth=120 / MinHeight=32`**：四个勾选框需要 520px，而该列可视区仅 288px → 「子程序」右边界 552 越过单元格右边界 480、「HTTP」右边界 682 完全在单元格外 | 几何实测（探针日志）；修法=四个框显式挂弹窗自己的 `{StaticResource DialogCheckBox}` 令牌（15px 方框、无最小尺寸），四个合计 242px |
| 2 | **`DialogHintText` 被应用级 Fluent 别名顶掉、丢了 `TextWrapping="Wrap"`**：`UI\Controls\Themes\Fluent\FluentAliases.xaml:276` 覆盖成 `BasedOn FluentTextCaptionStyle` 的版本（无 Wrap），顶掉了 `Dialog\Dialog.Text.xaml` 里带 Wrap 的那份 → 底部说明第 3 行单行自然宽 950px 不回行，还把说明面板顶宽到 978px 越出弹窗右边界 | 令牌叠加顺序（`App.xaml` 最后合并 Fluent 主题）；修法=该视图内显式 `TextWrapping="Wrap"` |

## 二、改动清单

- 弹窗尺寸：`Width 1000→1180`、`MinWidth 820→1060`（1060 是算出来的：客户区 1048 − 表格边距 40 = 1008 ≥ 名称列下限 120 + 四列固定宽 880）；
- 调用方式列：四个 CheckBox 显式挂 `DialogCheckBox` + 改用 `WrapPanel`（列变窄时折行而不是被裁）；列宽 320→300；
- 汇总文本与"待接通"提示加 `TextWrapping="Wrap"`；DataGrid 行高 `MinRowHeight=46` + 行高自适应（原先固定 46 会把汇总行压出单元格）；
- 名称列 `MinWidth=120`（窗口拖到最小时不再把"GoHome"切成"GoHom"）；描述列 160→200、状态列 110→150（"🔒 已锁定（禁止运行）"单行 128px 原会越界）；
- 底部四条说明全部 `TextWrapping="Wrap"`；
- 标题副标题同步为「流程的**锁定、解锁**、启停与调用方式」（与正文口径一致）。

## 四、未决问题

1. **`DialogHintText` 的 Wrap 丢失是公共令牌层的问题**：`FluentAliases.xaml:276` 覆盖后全仓所有用该令牌的弹窗（变量绑定、条件编辑器等）长句都不折行、会被裁。本批按最小改动在该视图内显式覆盖；**根治要动公共令牌**（会影响其它弹窗高度），需确认后再动。
2. **勾选框点击热区**从 Fluent 的 32px 高变成弹窗令牌的约 16px 高（标签本体仍可点，整体热区约 100×16）——绑定的属性/命令一字未动，属外观变化，待你实机确认可接受。
3. **行高随之变化**：本表行高从固定 46 变为内容自适应（实测约 55），比其它弹窗宽松；如要求严格等高需牺牲"待接通"提示行。
4. 剩余 5 条基线失败与本弹窗无关：相机模块注册表、YOLO 测试模型、Motion 属性面板 ×2、**BeadInspect 的 Plugin* 键缺失**（后者是并发会话在改 BeadInspect 的产物/主题所致的漂移）。
5. 用户截图里的流程名是 `GoHome / MainTask / End`——这是**老方案的认领行为**（骨架按角色认领老默认名、保留用户名字），非缺陷；新方案默认名为 Home/Main/End。
