# 系统变量分支（运动轴只读投影）

日期：2026-10-18
目标：让轴状态成为**可连线、可绑定、可报警、可监视**的一等数据源，同时不污染用户变量。

---

## 1. 为什么不做成用户变量

| | 用户变量（Local / Communication） | 系统变量（新分支） |
| --- | --- | --- |
| 归属 | 用户创建 | 从方案里的轴配置派生 |
| 持久化 | 进 `.vms`（`SolutionModel.GlobalVariables`） | **不落盘**，运行期重建 |
| 可写 | 是 | **只读**（不实现 `IWritableVariable`） |
| 身份 | 新建 Guid | **确定性 Guid**（轴 Id + 字段） |
| 生命周期 | 用户增删 | 轴增删/改名联动 |

三条不能做成用户变量的硬理由：

1. **会被落盘**：派生量写进 `GlobalVariables` 后，保存重开就重复生成，还能被用户改名/删除，立刻与轴配置分叉。
2. **身份不稳定**：每次启动新建 Guid，所有连线和 SCADA 绑定重启后全部失联。
3. **可写语义错位**：轴状态是观测值，"写位置 = 改位置"是伪命令。

## 3. 命名与身份

```
System.Motion.{轴名}.{字段}
```

12 个字段：`Position` / `Velocity` / `Moving` / `InPosition` / `Enabled` / `Alarm` / `AlarmMessage` / `PositiveLimit` / `NegativeLimit` / `Origin` / `EmergencyStop` / `StatusText`。

身份：`SHA1("motion-var|{AxisId:N}|{Field}")` 前 16 字节。同一根轴的同一字段在任何机器、任何次启动都得到同一个 Id → 按 Id 寻址的连线与画面绑定重启后仍命中。

## 4. 两条关键实现口径

### 4.1 实例必须复用

`Rebuild` 对"同一轴 + 同一字段"复用已建好的模型实例，只改名字与说明。重建实例会让所有订阅了 `ValueChanged` 的消费方（数据泵、监视项、画面绑定）静默失联——它们手里还攥着旧对象，值永远不会再变。

### 4.2 轴改名必须主动重扫名字索引

这是**本轮修掉的阻断级缺陷**：

- 轴改名时，目录对复用实例只改 `Name`，集合**不增不减** → 一个 `CollectionChanged` 都不发；
- 注册表的名字索引因此永久停在旧名上：**新名查不到、旧名一直命中**；
- 更糟的是下一拍"名字看起来已经一致"会让重建被短路，**陈旧状态不会自愈**。

修法：目录 `Rebuild` 里记账 `renamed`（比对上一次的轴名 + 模型名），改名后调 `IVariableRegistry.RefreshSystemNames()` 重扫系统名表。注册表拿不到时是空操作。

## 5. 线程

- `Rebuild` / `Publish` 跑在发布器定时器线程（100ms）；`TryGet` 由 UI 线程调用。
- 内部"整表构造 + 引用交换"，读方拿到的是完整且此后不再改动的表。
- `Variables` 集合的改写在发布器线程上（只增删移，不 `Clear`，避免"全查不到"窗口）。全仓 XAML 无任何 `SystemVariables` 绑定；选择弹窗每次打开复制快照（带重试）。
- **约束**：将来若要把 `SystemVariables` 直接绑到常驻 UI 列表，必须改成 Dispatcher 投递。

## 6. 验证

- `dotnet build VisionMaster.sln`：**0 error**。
- `dotnet run --project ScadaChecks --no-build`：**通过 1878 / 失败 0**。

AX8（系统变量）11 条，其中三条是**反向断言**：

| # | 断言 |
| --- | --- |
| 1 | 一根轴投影出 12 个变量 |
| 2 | 名字带前缀且能按名查到 |
| 3 | 身份非空 + 保留前缀生效 |
| 4 | **另一个 catalog 实例（模拟重启）投影出同一个 Id** |
| 5 | 重建复用同一模型实例 |
| 6 | 系统变量不进用户变量集合（不落盘） |
| 7 | 不实现 `IWritableVariable` |
| 8 | 值投影落地且同值只通知一次 |
| 9 | 离线保留上次已知位置、状态文本写明原因（不编 0） |
| 10 | **轴改名后新名可查、旧名查不到** |
| 11 | 轴改名后变量 Id 不变 |

第 10 条是阻断级缺陷的守门人：修回"只改 Name 不重扫索引"它必红。

## 7. 未决

1. **`VariableRegistry.Count` 含系统变量**：既有断言"`Count == GlobalVariables.Count`"在接上发布器后会不成立（当前 ScadaChecks 里没有系统变量，所以还是绿的）。
2. **新建变量不校验保留前缀**：只有 `TryRename` 拦 `Motion.` 前缀，"添加变量"两条创建路径仍可能造出 `System.Motion.X.Position` 并与系统变量撞名。`LastProblems` 会记，但它目前只走 `Debug.WriteLine`（生产侧无消费）。
3. **系统变量名里的 `Motion.` 段落在常量 `NamePrefix = "System."` 之后**：实际全名是 `System.Motion.X.Position`，与最初设想的 `Motion.X.Position` 不同；保留前缀判据只看 `System.`。
4. **`AlarmMessage` 取值口径**：`ScadaAxisSample` 没有独立报警文案字段，取"报警时用 `StatusText`，否则空串"。
5. **真机未验证**：发布器 100ms 下的系统变量刷新观感、变量选择弹窗里系统变量列的宽度。
