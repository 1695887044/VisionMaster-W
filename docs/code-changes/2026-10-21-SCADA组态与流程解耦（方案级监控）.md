# SCADA 组态与流程解耦：方案级监控（2026-10-21）

> 需求：报警配置在 SCADA 组态里做，变量事件归流程/自动化；不想 SCADA 组态和流程耦合。
> 本批按“先运行解耦、再搬入口、暂不拆 `.vms` 文件”的路线落地。

## 1. 原来的耦合

| 层 | 原状 | 后果 |
| --- | --- | --- |
| 运行生命周期 | `ScadaEditorViewModel.OnRunPage → IScadaRuntimeHost.Start → StartAlarms/StartVariableEvents` 是唯一启动链 | 只跑流程、不打开 SCADA 运行窗口时，报警不评估、变量事件不触发 |
| 数据所有权 | `ScadaDocument` 同时拥有 `Alarms` 与 `VariableEvents` | 配置入口和运行生命周期混在一起 |
| UI 入口 | 报警配置在「文件」菜单，变量事件在「系统」菜单 | 分类不符合现场心智；组态编辑器里找不到报警配置 |
| 确认框 | 变量事件可配「执行前确认」，headless 时会弹无人点的模态框 | 可能卡住 UI 线程 |

## 2. 改动

### 2.1 方案级监控宿主

新增 `VisionMaster/Services/ScadaMonitoringHost.cs`：

- 持有 `ScadaAlarmEngine` + `ScadaVariableEventEngine` + `ScadaBeatSource` + 报警历史落盘端。
- 生命周期跟**当前方案**走：方案加载即 `EnsureStarted`，切方案/退出即 `Stop`；不再依赖 SCADA 运行窗口。
- 暴露 `ScadaRuntimeContext`，SCADA 运行窗口只消费它，不再自己 new 引擎。
- 变量事件动作仍走 `ScadaActionDispatcher`；`Navigate` 在没有 SCADA 会话时按现有语义失败并记 Warn（不静默）。
- 报警历史仍写方案目录 `Alarms`（CSV + JSON），目录解析复用 `ScadaAlarmHistoryStore`。

### 2.2 ScadaRuntimeHost 只做窗口

- `Start(document)`：创建/复用 `ScadaRuntime` 会话与窗口；`_monitoring.EnsureStarted(document)` 后把 `_monitoring.Context` 交给画布。
- `OnWindowClosed`：只摘数据泵、导航器、会话/窗口；**不再** `TeardownAlarms` / `TeardownVariableEvents`，监控继续跑。
- `Stop()`：只收窗口与会话；监控由 `ScadaMonitoringHost` 按方案生命周期收。
- `IScadaRunHub` 仍按“窗口在 = 运行中”实现（Web 行为不变；这是本批已知边界）。

### 2.3 UI 入口

| 配置 | 新入口 | 旧入口 |
| --- | --- | --- |
| 报警配置 | SCADA 编辑器工具栏「报警配置」（方案级，多页共用） | 删除「文件 → 报警配置」 |
| 变量事件 | 流程栏右键「变量事件（方案级）」 | 删除「系统 → 变量事件」 |

- `ScadaEditorViewModel` 增加可选 `IDialogService` 与 `OpenAlarmConfigCommand`；App 注册显式注入。
- `FlowAction` 末尾追加 `VariableEvents`（不存盘）；`FlowListViewModel` 打开现有 `ScadaVariableEventDialogView`。
- `UIThemeSmokeTest/ShellCopy.xaml` 同步删除两个旧菜单项（R44）。

### 2.4 报警热更新不重复激活

`ScadaAlarmEngine`：

- `Slot` 在挂载时快照“判定口径”（变量/种类/阈值/回差/断线秒数/启用状态）。
- `Reload` 把这些快照带过去；口径没变的旧记录沿用 `RecordId`，只改文案/严重度/报警组不会把当前报警重新激活。
- 口径变了（如阈值 10→25）仍从当前值重新判，旧记录按状态机恢复/清除。

### 2.5 Headless 确认

`ScadaConfirmationService.InteractiveAllowed`：

- `ScadaMonitoringHost.EnsureStarted` 置 `false`（无人值守，确认框按取消处理）；
- SCADA 运行窗口 `Show` 成功后置 `true`，关窗置 `false`；
- 避免变量事件在后台弹一个没人点的模态框卡死 UI 线程。

## 4. 已知边界

- **变量事件现在方案加载即生效**，不再等“运行画面”。这是解耦的必然结果；如果现场有“只在运行时才该触发”的变量事件，请用记录上的「启用」开关或后续增加“监控开关”。
- **Web 的 `IScadaRunHub` 仍按窗口语义**：SCADA 窗口关闭后 Web 显示未运行，虽然后台监控仍在跑。若要 Web 也跟随 headless，需要新增 monitoring hub 契约（下一步）。
- **`Navigate` 在无 SCADA 会话时失败**：后台变量事件可以写变量/启停流程/记日志，但切画面需要窗口会话；失败会记 Warn + 审计 Skipped。
- **报警历史 JSON 仍每次状态迁移全量重写**：高频报警下需要防抖/异步；本批未改。
- **`ScadaRuntimeHost` 里旧的引擎方法/字段暂未删除**（已无调用）；后续可做一次纯清理，避免读者误以为窗口仍持有引擎。
