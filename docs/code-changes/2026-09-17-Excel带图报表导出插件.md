# 2026-09-17 Excel 带图报表导出插件（Plugin.ExcelExport）

## 一、需求与决策

### 需求背景
CSV 记录插件已经把每件结果落成账本（含「图片路径」列），但账本是给机器/程序看的：
一列长路径没法一眼看出哪件是 NG、想看图还得复制路径去资源管理器粘贴。
需要**给人看的报表**——一页里能筛选、能排序、能点开看高清原图。

### 三条已批准共识（施工图依据）
1. **不往实账本里嵌图，改为"事后导出"**。产线上写 xlsx 要整份重写、还得防 Excel 占用，
   代价高且无意义（机器不看报表）；人要看的时候再导出，报表就是"当时那份账"的快照。
2. **工具选 MiniExcel（NuGet 1.46.0）**，新建独立导出插件 `Plugin.ExcelExport`，
   依赖只随插件目录走 `Modules\`（不动宿主、不污染其它插件）。
3. **超链接走"MiniExcel 写数据 + 自写 OOXML 注入"**——MiniExcel 完全不支持写超链接，
   而 xlsx 本质就是 zip + 若干 XML，缺的那点自己补最省事，不必为超链接引入整个 OpenXML SDK。

### 「事后导出」的三段式
```
CSV 账本（机器看）  ──MiniExcel──▶  纯数据 xlsx  ──自写 zip 注入──▶  带图链接的报表（人看）
                                                    ↑
                                    改 sheet1.xml / sheet1.xml.rels / styles.xml 三处
```

### MiniExcel 1.46.0 实测事实（探针真跑，非文档推测）
- ✅ 读 CSV：`MiniExcel.Query(csv, useHeaderRow:true, excelType: ExcelType.CSV)` → `IEnumerable<dynamic>`
  （按 `IDictionary<string,object>` 消费）。**不传 `excelType` 必抛 `InvalidDataException`**（它默认按 xlsx 解析）。
- ✅ 写 xlsx：`SaveAs(path, List<IDictionary<string,object>>, overwriteFile:true, configuration: OpenXmlConfiguration)`；
  **列序 = 字典键插入序 = CSV 表头序**，不需要额外写列映射。
- ✅ 冻结首行/筛选：`OpenXmlConfiguration{ FreezeRowCount=1, AutoFilter=true }`
  → `<x:pane ySplit="1" state="frozen"/>` + `<x:autoFilter ref="A1:F5"/>`。
- ❌ **超链接完全不支持**（这是本插件自写注入的唯一原因）。
- ❌ 公式不支持（落成 `t="str"` 文本）；❌ `EnableAutoWidth` 必抛。
- MiniExcel 默认样式索引：表头 `s="1"`、数据格 `s="2"`；styles 默认 `fonts count=2`、`cellXfs count=6`
  （**末位 cellXfs 是时间格式 numFmtId=21**，所以克隆样式时不能取末位，要克隆"数据格样式"）。

### 落地过程中踩到并修正的坑
1. **超链接 `<Relationships>` 的 `Type` 必须写纯 URI 字符串**：
   若写成 `XName`（Clark 记法 `{http://...}hyperlink`），Excel 打开直接报"需要修复"。冒烟已抽查这一点。
2. **`<hyperlinks>` 段位置有 schema 约束**：必须在 `autoFilter`/`mergeCells` **之后**、
   `printOptions`/`drawing` **之前**，否则 Excel 报包损坏。代码里按名单找"插入锚点"而非硬写下标。
3. **CT_Font 子元素顺序固定**：`u` 必须排在 `sz`/`color`/`name` 之前，否则 Excel 报错。
4. **改完 sheet 必须写回条目表**：漏 `doc[sheetName] = ...` 会退化成"关系有了、单元格没变"。
5. **显示名首次写成 `Path.GetFileNameWithoutExtension`** → 报表里显示 `0001_OK`，
   一眼分不出 png 还是 jpg → 改为 `Path.GetFileName`（保留扩展名）。
6. **配置期拿不到 `InstanceName`**：`InstanceName` 是**引擎在编译流程时注入**的
   （`FlowCompiler.cs`：`plugin.InstanceName = flowName.IsEmpty ? StepName : $"{flowName}.{StepName}"`），
   而配置面板里的实例是界面 `Activator.CreateInstance` 新建的、**没经过引擎命名**，
   值仍是默认 `"未赋值"` → 预览路径算错。**修法**：新增 `EffectiveStepName`：
   运行期用 `InstanceName`（与 CSV 记录插件同一套命名规则，路径才对得上），
   配置期退回 `StepData.StepName`，两条路都能预览。

### 顺带确认的宿主契约（供后续插件复用）
- **`MiniExcel.dll` 放 `Modules\` 是安全的**：`PluginService.LoadPlugin` 只认
  `Name.StartsWith("Plugin") && EndsWith(".dll")` 的文件名，`MiniExcel.dll` 不会被误注册成插件，
  但能被默认 ALC 按 LoadFrom 连续性解析到——正好是我们要的"只当依赖、不当插件"。
- **`LinkableValueEditor.Port` 是 `IInputPort` 型 DP**，可直接 `Port="{Binding TriggerPort}"` 拉线。

## 四、已知边界

- **宿主 UI 实跑未验证**：需在 VisionMaster 里拖一个"Excel报表"步骤、在面板里点「立即导出」实测一次。
- **只支持"外链"不支持"嵌图"**：报表里是短文件名 + 指向磁盘原图的链接。
  **原图被删/挪走，链接就断了**——图片归 CSV 记录插件的 `KeepDays` 清理策略管，两边的保留期要一起考虑。
- 只处理 **sheet1**（MiniExcel 也只写一张表）。
- `OnlyRowsWithImage` 依赖 `LinkColumn` 列存在；列名对不上时会**静默不筛**（结果文本里有说明，但不会报错）。
- 图片路径必须是**绝对路径**：相对路径（如 `img\1.png`）不生成链接、原样留文本。
- 报表是**整份重写**：`ExportPolicy=EachRun` 用在高频循环流程里会反复重写整本报表，**慎用**
  （适合"一个班次只跑一次"的报表流程，或改用"触发端口"由收工信号触发）。
- 导出路径被 Excel 占用 → `IOException`，提示"请先关闭"，**不自动旁路改名**（报表是给人看的，改名只会让人找不到）。
- 超链接样式是**新克隆的 cellXfs 项**，字号固定 11 / 字体 Calibri：若宿主未来改了 MiniExcel 默认样式，
  注入器会自动克隆"该列数据格实际用的样式"，观感仍一致，但字体名写死这点未来可能需要跟随。
