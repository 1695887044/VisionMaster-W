# 配方管理：配方值就地编辑（2026-10-25）

## 一、起因

用户原话：「配方值也无法修改」。

排查后确认这不是"界面没开放"，而是**数据层根本没有这个能力**：

| 位置 | 现象 |
|---|---|
| `VisionMaster/Views/DialogViews/RecipeManagerView.xaml` | 「配方值」列是 `DataGridTemplateColumn` + 裸 `TextBlock Text="{Binding RecipeValue}"`，整个 `DataGrid` 还写着 `IsReadOnly="True"` |
| `RecipeManagerViewModel.RecipeParameterRow` | `RecipeValue` 是 `{ get; init; }`，没有 setter，也不发通知 |
| `VisionMaster/Services/RecipeService.cs` | 公开 API 只有 `AddEntry` / `RemoveEntry` / `Rename` / `Delete` / `Capture` / `Apply`，**没有任何"改某条参数值"的方法** |

所以只改 XAML 是改不动的，必须先把 Service 的口子开出来。

## 二、改动清单

### 1. `VisionMaster/Services/RecipeService.cs`

新增 `UpdateEntryValue`，位于 `RemoveEntry` 之前：

```csharp
public bool UpdateEntryValue(
    Guid recipeId, RecipeTargetKind kind, Guid targetId, string key,
    string? text, out string error)
```

校验顺序（**与 `AddEntry` 同一套口径，不另立一份**）：

1. 方案已打开 → `FindRecipe` → `FindEntry`，任一步找不到就返回具体原因；
2. 声明类型：`RecipeTypeKey.TryResolveType(entry.DeclaredType)`；老数据里 `DeclaredType` 为空的，退回 `ResolveDeclaredTypeAtTarget` 去目标上现查；记了键但已解析不到（插件/步骤没了），按 `typeof(JToken)` 收 JSON 原文，不丢数据；
3. `RecipeTypeKey.IsSupportedType` 拒掉不支持的类型；
4. `TryParseEntryText` 解析文本 → `TryConvertToDeclared` 复验；
5. **值没变就直接成功**，不动 `ContentVersion`——否则"点开框又点掉"也会让配方版本虚涨。

成功路径：`entry.Value = token; entry.ValueIsNull = false; recipe.TouchEntries(ActorName);` → 审计（动作名「修改配方参数」，明细 `目标.参数：旧值 → 新值`）→ `RaiseStateChanged()`。

配套私有方法：`TryParseEntryText`、`TryParseLooseBoolean`、`SimpleTypeName`、`ResolveDeclaredTypeAtTarget`。

**刻意不做的一步（已写进 XML 注释）**：不复验"目标此刻是否已链接 / 已隐藏"。理由是配方存的是**快照**——换型时把另一台机器的值抄过来本来就是刻意的，这里设卡会让"机器 A 链接、机器 B 没链接"根本没法建档。能不能写回目标，由 `Validate` / `Apply` 在应用那一刻判。

### 2. `VisionMaster/ViewModels/DialogViewModels/RecipeManagerViewModel.cs`

- `RecipeParameterRow.RecipeValue` 由 `init` 改 `SetProperty`（绑定的框要能回写）；
- 新增 `CommittedRecipeValue`：服务端确认过的那份值，既是失败时顶回去的基准，也是"有没有真改"的比较基准；
- 新增 `CanEditValue` / `ValueEditBlockedReason`；
- 新增 `ValueEditState()`：未登录 → 「未登录，只能查看」；`!_service.CanEdit` → 服务端原话；`IsRunLocked` → 「流程运行中，配方锁定」；否则可改。**与 `CanEdit` / `CanApplyNow` 同源，不另立口径**；
- `RefreshParameters()` 里取一次 `ValueEditState()` 给所有行赋 `CommittedRecipeValue` / `CanEditValue`；
- 新增 `CommitParameterValue(RecipeParameterRow?)`：不可改 → 报原因 + 顶回；值没变 → 什么都不做；`UpdateEntryValue` 失败 → 报原因 + 顶回；成功 → 状态栏「已修改「X」的配方值」+ `Refresh()`。

### 3. `VisionMaster/Views/DialogViews/RecipeManagerView.xaml`

「配方值」列 `CellTemplate` 换成两个互斥元素，都包在 `Grid Background="Transparent"`（透明底才收得到鼠标）里：

- `TextBlock`：`CanEditValue == false` 时显示（含运行中/未登录）；
- `TextBox`：`CanEditValue == true` 时显示，`UpdateSourceTrigger=LostFocus`。

### 4. `VisionMaster/Views/DialogViews/RecipeManagerView.xaml.cs`

- `OnValueCellClicked`：点格子任意位置都进编辑态（Focus + SelectAll）；
- `OnValueBoxKeyDown`：Enter 提交，Escape 撤销（回 `CommittedRecipeValue`）；
- `OnValueBoxLostFocus`：失焦提交；
- `FindDescendant<T>` / `IsInsideTextBox` 两个小工具。

## 三、验证

主工程：`dotnet build VisionMaster/VisionMaster.csproj -m:1 -nodeReuse:false` → **0 个错误**。

探针 `tools\probes\_RecipeUiProbe` 六跑全绿，`RESULT: OK`、零 FAIL。关键输出：

```
[ValueEdit] 行数=2 可改行=2 首行="AngleTolerance" 类型="double" 原值="3.0"
[ValueEdit] 改成="42.42" 落盘="42.42" 表格显示="42.42" 状态="已修改「AngleTolerance」的配方值"
[ValueEdit] 非法值后 显示="42.42" 提交基准="42.42" 错误态=True
           状态="「这不是一个合法的值!!」不能当作 Double：The input string ... was not in a correct format."
[ValueEdit] 运行中：没有可改行（符合预期，配方锁定生效）      ← design-running 场景
```

覆盖三条：合法值**真正落盘**（不是只改界面）、非法值被拒并**顶回原值**、运行中**整列锁死**。

### 期间修掉的一条假红

探针最初在 `design-running` 场景报 `[FAIL] 一条可改的配方值都没有`。查下来是**断言写错了**：该场景本来就 `IsRunLocked == true`，一行都不该可改，产物行为是对的。已把判定拆成三支（未登录 / 运行中 / 其余），只有"已登录 + 未运行"才要求至少一条可改。

## 四、踩坑

- `edit` 的 `old_string` 必须覆盖到要保留的完整边界（至少含函数签名行）。只匹配注释行的话，`new_string` 漏写签名会把注释和签名拼成一行，编译必炸——本次踩了一次。
- `bool.TryParse(raw, out var v) == false && !TryParseLooseBoolean(raw, out v)` 会 `CS0165 使用了未赋值的局部变量`，要拆成独立 `if` 块。
- 把 build 和 run 串在同一条 `&&` 命令里、又用 `grep` 过滤输出，看不到构建是否真的重生成了 exe。要用 mtime 核对——本次就因为没核对，把"跑了旧 exe"误判成"代码没生效"，白查两轮。
- 探针里 `vm.SelectedRecipe` 是只读派生属性（`=> SelectedItem?.Recipe`），不能赋值；`RecipeListItem` 只有 `Recipe`，没有 `Entries`。
- 合法值测试表要按 `RecipeTypeKey.Normalize` 的**小写别名**（`double` / `int32` / `string`）匹配，不是 .NET 类型名。

## 五、未做

- 「配方值」列的输入没有做类型提示（比如 `double` 行右侧不明显提示可填小数）。本轮没做，属体验增强。
- 批量改值（多行一起改）没做。
