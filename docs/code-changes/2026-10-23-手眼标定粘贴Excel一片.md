# 手眼标定：支持从 Excel 粘贴一片（Ctrl+V）

> 日期：2026-10-23 ｜ 范围：`Plugins/Plugin.HandEye`（插件侧规则 + 视图接线）、`FlowCanvasChecks`、设计基线与手册 ｜ 状态：已落地，`FlowCanvasChecks 3375/0`

## 1. 背景

手眼标定的数据是「一行一组、12 个数值」，现场最常见的来源是机器人控制器导出的表、或者工程师先在 Excel 里算/整理过的一批数。改完这一版之前只有两条录入途径：

- 表格里逐格手填（适合一组一组采，不适合整批搬）；
- 「导入 CSV」（要先把数据落成一个文件，且文件是**整表替换**，不适合"补中间两行"）。

缺的是中间那条：**从 Excel 里选中一片，直接粘进来**。用户在评审设计基线时点名要它（Q6），本次实现。

顺带一个必须一起想清楚的问题：单元格编辑**不会**作废上一次的标定结论——这个已经在 `7db61fd5` 补掉了（行级 `PropertyChanged` 订阅）。粘贴走的是同一条路（`SetRow` 统一发通知），所以粘完结论自动转「未求解」。

## 3. 关键决策

1. **规则放插件侧，视图只做"读剪贴板 + 定位 + 弹错误"**。理由：剪贴板文本的处理规则是**数据规则**，不是界面规则。放在 `HandEyePaste` 里，断言宿主能直接测；留在 `HandEyeView.xaml.cs` 里就只能靠人去点一遍。这条和 `HandEyeCsv` 的分工一致（CSV 也只做文本↔行，选文件/编码归视图）。
2. **单格纯数字不接管**。`IsBlock` 要求文本里有制表符或换行才算"一片"。否则 `Ctrl+V` 会把一个数粘进单元格，绕开单元格编辑器的逐格校验与撤销——用户按 `Ctrl+Z` 期望撤掉刚才那次粘贴，结果撤的是别的东西。
3. **整片先校验、任何一格非法则一个都不写**。一半写进去的表比"什么都没发生"更难收拾：用户会以为粘贴成功，然后拿一半新一半旧的数据去求解。报错文案带**行号 + 列号 + 原始文本**（`第 2 行第 2 列不是数字：「abc」`）。
4. **空单元格保持原值，不写 0**。来自 Excel 的空格子 = "这次没量"，写 0 会变成一条**有效但错误**的样本，而全 0 行还会被 `IsBlank` 判成"还没填"——两个都不对。变异反证专门钉这条（把 `continue` 改成写 0 → 断言 ④ 立刻红）。
5. **超过 12 列的部分丢弃并计数**，不折到下一行。粘贴的列数由用户在 Excel 里框选决定，框多了是常见手误；折行会把后面的行整体错位，比丢弃难查得多。
6. **没选中任何格子时，接在表尾**。注释写在 `CurrentPasteAnchor` 里：**第一行是构造所有相对运动的基准样本**，悄悄把它换掉，症状是"残差突然变大但看不出哪行错"，比"少粘一片"难查。所以宁愿接在末尾让人自己发现少了，也不默认覆盖第一行。
7. **一次 `SetRow` 而不是 12 次 setter**。12 个分量各走 `SetProperty` 会推 12 次"预览作废"，每次都重算指纹；`SetRow` 内部统一改完再逐个发一次通知。
