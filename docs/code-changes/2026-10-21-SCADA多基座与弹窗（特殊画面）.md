# SCADA 多基座与弹窗（特殊画面）

> 日期：2026-10-21 ｜ 范围：P1 弹窗 / 子画面 + 每画布多基座 ｜ 状态：桌面端已实现，专项断言通过，待真机确认

## 1. 背景

两条需求同时落地：

1. **弹窗是特殊画面**：普通页面之外，还要有"浮层盖在当前页上、关闭后回到原页"的弹窗页。
2. **每个画布可以有多个基座**：一个页面经常要同时叠"公共标题栏 + 公共底栏"这类互不相干的两层；
   原来的单基座模型只能把这些内容硬塞进同一只基座。

实现沿用两条既有纪律：

- 弹窗页仍是普通 `ScadaPage`，只多一个 `IsPopup` 标记；图元、绑定、动画、事件钩子全部复用。
- 基座仍是"引用"而不是继承；多基座只是把单个 `BasePageId` 扩成有序列表 `BasePageIds`。

## 3. 关键决策

### 3.1 多基座：列表顺序 = 渲染顺序（靠层偏移，不靠插入顺序）

`ScadaPage.BasePageIds` 是 `List<Guid>`，按页面里的引用顺序叠：第一只压在最下面，最后一只盖在所有基座之上，本页图元再盖在基座之上。`ScadaCanvas.BasePages` 直接按这个列表逐层枚举，不另建合并集合——"哪些图元属于谁"仍只有模型一处真相。

**层序不能只靠"先枚举"**：所有图元共用一个 Canvas，WPF 只按 `Panel.ZIndex` 排序；基座里 ZIndex=5 的图元会盖住本页 ZIndex=0 的图元。所以画布给每只基座分配一个 ZIndex 段（`LayerZStride = 10,000,000`），`ScadaElementBase.ApplyGeometry` 写 `Element.ZIndex + LayerZOffset`；本页占最后一个段。这样"基座A < 基座B < 本页"与各自的模型 ZIndex 无关。

- 单值 `BasePageId` 保留为兼容视图：读第一只，写等于把列表替换成一只。旧代码/旧断言/旧插件不用一次性改完。
- 旧 `.vms` 的 `BasePageId` 由私有 `LegacyBasePageId` 读进列表；新文件只写 `BasePageIds`（`NullValueHandling.Ignore` + getter 恒 null），不会再写出全 0 的旧字段。
- 悬空 Id 不清理：基座被摘除/删除后 Id 留着，渲染侧跳过；撤销或重新注册后自动恢复。
- 一层限制不变：基座页自身不能再引用基座；`TryAddBasePageReference` / `TrySetBasePage` 两条入口都拦。
- 顺序调整走 `TryMoveBasePageReference`（文档层已支持）；本轮顶栏多选菜单只做勾选/取消，顺序暂等于基座注册顺序——拖拽排序是后续 UI 增强，不影响模型与渲染。

### 3.2 弹窗：页面级呈现参数，动作只带目标

设计稿原本把 `Modal/Anchor/Offset` 放在 `OpenPopup` 动作参数上。本轮改为放在弹窗页自己身上（`IsPopup` / `PopupModal` / `PopupAnchor` / `PopupOffsetX/Y`）：

- 同一个弹窗页可能被多个按钮打开，呈现方式（居中/贴右上、模态/非模态）属于"这个页面长什么样"，不属于"哪个按钮打开它"；
- 动作表因此只需要复用已有的 `TargetPageId/TargetPageName`，不新增四组字段，也避免"同一个弹窗从不同入口打开时位置不一致"。

代价：同一页不能在两个入口用不同位置打开。当前没有这种需求；将来需要时再加动作级覆盖字段（页面级仍是默认值）。

### 3.3 弹窗不压页栈、不改 CurrentPage

`OpenPopup` 只设置 `CurrentPopup`，`CurrentPage` 保持不变；关闭后自然回到原页。这样：

- 页栈只表达"整页导航历史"，不会因为开一个参数弹窗就多一层；
- `CanGoBack` 在弹窗打开时为 true，`GoBack` 先关弹窗（返回按钮的语义是"退掉最上面一层"）；
- 切页（`Navigate`）在真正换页前先收弹窗，避免旧弹窗盖在新页上。

### 3.4 事件闸门按"表面"判定

`RaiseElementEvent` 原来只认 `CurrentPage`。弹窗打开后：

- 弹窗页自己的图元命中（按引用比对，与整页同一口径）；
- 模态弹窗：背景页图元一律返回 0（遮罩挡住鼠标，逻辑上也挡住快捷键/脚本派发）；
- 非模态弹窗：背景页图元照常命中；
- 弹窗页的 Loaded/Unloaded 钩子照常发；Loaded 由宿主在弹窗画布布局完成后上报（与整页首帧同一纪律），Unloaded 在 `ClosePopup` 里先于状态清空发。

### 3.5 弹窗数据泵独立一张表

`ScadaRuntimeHost` 在 `PopupOpened` 后等 `DispatcherPriority.Loaded`，用 `PopupCanvasHost` 建第二张 `ScadaRuntimeBinder`；`PopupClosed` 与窗口关闭时摘表。弹窗画布与主页画布共用同一个监控上下文（报警/变量事件/写口），但绑定表不混用——否则关掉弹窗后旧控件还会收变量值。

**重开竞态**：关闭后立刻重开同一弹窗时，上一轮排队的回调会与新一轮同时通过"CurrentPopup 还是它"的引用判据；宿主用 `_popupGeneration` 代次作废旧回调，并在建表前再 `Stop` 一次旧表。

### 3.6 弹窗尺寸与锚点

`PopupFrame` 用 `MaxWidth/MaxHeight` 绑到 `PopupLayer` 的实际尺寸，弹窗画布外套 `Viewbox`（`StretchDirection=DownOnly`）：默认 1920×1080 的页面在 1280×800 窗口里等比缩小，关闭按钮不会被推出屏外；小弹窗不放大。锚点仍按九宫格对齐，偏移用 `TranslateTransform` 平移。

### 3.7 弹窗页不参与普通导航

`FindNavigablePage`、`IsNavigable`、`FindNavigablePageByName`、`ResolveStartupPage` 回落全部排除 `IsPopup`；`Navigate(Guid)` 指向弹窗页时给专属原因（"只能用「打开弹窗」打开"）；页面选择器按动作类型过滤（`Navigate` 只列普通页，`OpenPopup` 只列弹窗页）。弹窗页也不能注册为基座。

### 3.8 关闭弹窗的重入闸

`ClosePopup` 在广播 Unloaded 时置 `_closingPopup`：Unloaded 钩子里的 `ClosePopup`/`GoBack`/`Navigate` 再进来时直接返回 false，不会递归广播同一条 Unloaded（否则栈溢出直接杀进程）。

### 3.9 快照与 Web

- `ScadaPageSnapshot.BasePages` 带全部基座快照，`BasePage` 仍是第一只（旧 web 渲染器不用改）。
- `BasePageVersion` 改为所有基座版本之和：任何一只基座变化都会让 web 的页键变化，不会出现"改了第二只基座、web 不刷新"。
- `ScadaPageSnapshot.Popup` 带当前弹窗层；**本轮只交付桌面端浮层**，web 渲染器尚未消费 `Popup`（边界见 §5）。

## 5. 边界与未做

1. **Web 弹窗未渲染**：`ScadaPageSnapshot` 的 `BasePages` / `IsPopup` / `Popup` 字段已由宿主 `ApplyCaps` 透传，但 web 渲染器仍未画弹窗层；Web 命令层的 `OpenPopup` / `ClosePopup` 已按镜像模式剔除（`IsMirrorOnlyPageAction`），不会出现"网页点了桌面弹窗、网页看不到"的状态错位。
2. **不支持弹窗嵌套**：已有弹窗时 `OpenPopup` 直接拒绝并记 Skipped；层叠弹窗的焦点/Esc 归属/遮罩叠加没有可靠口径，v1 先不做。
3. **多基座顺序暂无拖拽 UI**：顶栏多选按基座注册顺序叠；`TryMoveBasePageReference` 已可用，后续加拖拽/上下移只改 UI。`BasePageVersion` 是各基座版本之和，对"换序"不敏感——加排序 UI 时必须改成顺序敏感的快照键。
4. **没有真机截图**：锚点/遮罩/关闭按钮的最终观感需真机确认；断言已覆盖可见性、对齐方式、偏移与 `Viewbox` 尺寸约束（尺寸约束未做像素级断言）。
5. **只验证 Debug**：打包前需 Debug/Release 都重建（R55 同族）。
6. **全量断言未复跑**：两个并发/监控段本机偶发崩溃，未修；本次专项 2401/0，评审复跑全量时曾到 2424/0（修复前代码），修复后未再跑全量。
