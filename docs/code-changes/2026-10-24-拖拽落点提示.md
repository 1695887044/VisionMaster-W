# 拖拽落点提示（2026-10-24）

## 起因

上一批把 gong 自带的英文浮层（`Copy to`）关掉后，拖拽时**完全没有落点反馈**——比英文更糟。
用户要求出 Web 设计稿；确认 v2 后按基线复刻到 WPF。

用户拍板三件事：动词「添加 / 移动」、路径分隔符 `/`、状态③（落点会展开折叠分组）要做。

## 设计基线

`docs/UI设计基线/drag-drop-hint/`（v2 已确认）：卡片（是什么）+ 提示条（落到哪）两个浮层，
五状态（有效 / 需注意 / 非法 / 锁定 / 无落点），文案公式 `[动词]「名称」→ [路径] · [位置]`。

## 改动

### 1. 新增四个部件

| 文件 | 职责 |
|---|---|
| `VisionMaster/Services/DragHintPresenter.cs` | 进程级单例状态（`Text` / `Kind` / `Owner`）；`Show(owner, text, kind)`、`Hide(owner)`、`Hide()`、`Reset()` |
| `VisionMaster/Services/DragHintText.cs` | 文案公式纯函数（Add / Move / Build / Path / Illegal / WillExpand / InsertBefore、AfterPosition） |
| `VisionMaster/Controls/DragHintPill.xaml(.cs)` | 提示条：高 26 / 圆角 8 / 图标 11 / 文字 11.5 Medium / 四档配色与图标 / Hidden 时 Collapsed |
| `VisionMaster/Controls/DragGhostStack.xaml(.cs)` | 卡片 + 提示条组合；`Loaded` 时 `Reset()`（= 新一轮拖拽开始） |

**为什么需要一个共享状态对象**：gong 4.0.0 的 `DropHintState` 只有 None/Active/Error 三态，
模板 DataContext 只有 `HintText` + `HintState`，表达不了"需注意 / 锁定"两档。要五档就只能自己承载。
提示条与卡片放进同一个 adorner 模板（纵向 StackPanel），视觉与设计稿一致。

**`Owner` 标记是必需的**：gong 的 `DragLeave` 走 `Dispatcher.BeginInvoke` 延迟派发，
从流程栏移到画布时流程栏那条 DragLeave 可能排在画布 DragOver 之后——不带 owner 的 `Hide`
会把画布刚写的提示抹掉。`DragLeave` 只撤自己写的。

### 2. 两处放置端接入（判据必须同源）

- **流程栏**：新增 `ProcessViewModel.ResolveProcessDrop(IDropInfo)`，**同时供 `DragOver` 与 `Drop` 使用**。
  此前 `DragOver` 只看 `TargetItem` 类型，而 gong 在 TreeViewItem 上下 25% 把 `TargetCollection`
  设为父集合（插到容器**旁边**）、中间 50% 设为条目自己的空 `Items`（`TargetItemCenter`），
  两种落点完全不同——只看 `TargetItem` 会撒谎（提示"容器 / 分支 · 末尾"、实际插到主流程末尾）。
  解析结果统一给出：目标集合、插入下标、路径（容器链 + 分支名）、位置（末尾 / 插到「X」之前）。
- **画布**：新增 `FlowCanvasViewModel.DescribeDropTarget(tool, position)`，复用 `ResolveInsertTarget`
  + `AllowsLoopControl`，与 `DropToolAt` 同一份判据；四档各自可达。
- 两处 `DragOver` 都补了 **Break/Continue 落点闸门**（此前只有 `Drop` 里判，提示会说"可以"、松手才被拒）。
- 画布 `DragOver` 的 `Effects` 与提示一致：Illegal / Locked 时设 `None`，不再出现
  "光标说能放、提示说不能放、松手被拒"的三方矛盾。

### 3. 状态③必须兑现

`DescribeDropTarget` 对折叠容器给 Caution「会展开「X」后再放入」，`DropToolAt` 落子后调
新增的 `ExpandIfCollapsed` **真的展开**。只提示不展开 = 新步骤插进去了却看不见（用户以为没加成功），
比不给提示更坏。折叠判定与 `TryGetLayout` 完全一致：`Layout.Collapsed || _sessionCollapsed`，
漏掉后者会漏掉"大流程自动折叠"的容器。

### 4. 成环拦截（DragOver 与 Drop 共用）

`IsDraggingIntoSelf`：拖容器到自己或自己的子孙（含自己的分支卡片）会形成结构环，之后编译/遍历无限递归。
此前只拦 `Data == TargetItem`（自拖），不拦子孙。现在 `DragOver` 给 Illegal「不能放进自己里面」，
`Drop` 同样拒绝——只提示不拦等于把坏图纸放进来。

### 5. 顺带修的两处健壮性

- `DescribeDropTarget` 取名时跳过 `Steps` 里的 null 项（反序列化残留），否则提示这一行抛 NRE 打断拖拽。
- 提示条四档底色/文字色/图标色共 **12 个令牌**全部进 `Colors.xaml`（R140），XAML 内零 `#RRGGBB`。

### 6. 模板接线

`ToolView.xaml`（1 个）与 `ProcessView.xaml`（2 个：步骤 + 分支卡片）的拖拽模板由
`DragGhostCard` 换成 `DragGhostStack`。漏换一处 = 那一路拖拽永远没有提示（有静态扫描钉住）。

## 断言

新增 `FlowCanvasChecks/DragHintChecks.cs`（[DH] 组 37 条）：

- **DH1** 文案公式：动词、分隔符 `/`、≥3 级路径截断、非法原因、运行锁文案与 `EditGate` 同源；
- **DH2** 状态通道：Show/Hide/Reset、同值不发通知、空白文案自动收起、
  **别的放置端 DragLeave 不抹当前提示**；
- **DH3** 画布落点：顶层末尾 / 两兄弟之间 / 容器内 / **折叠容器 Caution + 落子后真展开** /
  展开态反向 / Break 顶层 Illegal + For 内 Valid / 运行锁 Locked / 未挂流程 Hidden / null 步骤不抛；
- **DH4** XAML 接线：精确模板键、`Text` 与 `Kind` 两个绑定都在、12 个令牌在 pill 与 Colors 都齐、
  11.5 Medium + 省略、单层阴影、零硬编码颜色、`Loaded` 复位存在。

**变异反证**（3 条，均判红后还原）：

| 变异 | 结果 |
|---|---|
| 分隔符改回 `›` | DH1 判红 3 条（`并行组 › 分支 2`） |
| 去掉折叠判断（`collapsed = false`） | DH3 判红（`Valid / 添加「落点桩」→ 判断 / If · 末尾`，本该 Caution） |
| 流程栏漏换一个模板 | DH4 判红（`步骤=True 分支=False`） |

**验证**：`FlowCanvasChecks` 3608 通过 / 0 失败；`UIThemeSmokeTest` 108 项 0 失败（颜色令牌零新增硬编码）。

> 期间踩到一个自己的坑：DH3 的 null 步骤断言往仍被 `WorkspaceContext` 订阅的流程里塞了 null，
> 之后 G7 改名触发 `RefreshStepPortDisplayAddresses` 遍历到 null → 整段崩（AV）。
> 修法是断言自己 `finally` 摘干净。顺带暴露一个既有缺陷：`RefreshStepPortDisplayAddresses`
> 对 null 步骤不设防（本批未改，见「未做」）。
