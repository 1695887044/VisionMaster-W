# 停靠面板订阅泄漏修复（sub-leak）

**日期**：2026-09-17
**模块**：UI 面板视图模型生命周期
**缺陷**：`LayoutHelper.LoadFromString` 每次加载方案/恢复布局都会把面板内容重新 `new` 一遍（`FillContents` 按 ContentId 调工厂），Prism 随之解析出新的 ViewModel。旧 ViewModel 的订阅从不摘除，被静态表与单例永久持有。

## 需求与决策

**泄漏清单（修复前）**

| 类 | 泄漏点 | 持有者 |
|---|---|---|
| ProcessViewModel | `GlobalEventBus.Subscribe<LinkPathEvent>` | 静态 `_subscribers` |
| ProcessViewModel | `GlobalEventBus.Subscribe<MainRunState>(lambda)` | 静态 `_subscribers`（lambda 无法反订阅） |
| ProcessViewModel | `Workspace.PropertyChanged +=` | Workspace 单例 |
| ProcessViewModel | `DispatcherTimer` 已 `Start()` | WPF 计时器泵（每 200ms 遍历 Steps） |
| FlowCanvasViewModel | `Workspace.PropertyChanged +=` | Workspace 单例 |
| FlowCanvasViewModel | `flow.Steps.CollectionChanged` + 各泳道列表订阅 | 流程模型 |

**方案选择**：用户选 B（视图卸载时清理）。实施中把「一次性 Dispose」修正为**可逆的 Activate / Deactivate 成对挂摘**，原因：

- AvalonDock 切换标签页、隐藏面板（`IsVisible=false`、自动隐藏）都会让面板内容触发 `Unloaded`，且**不会自动回到 `Loaded`**（要等用户切回来）。
- 若在 `Unloaded` 里做一次性清理，切回来的面板订阅已摘除 → 流程树不再跟随联动、画布不再响应流程变化（功能性回归）。
- 「延迟到下一轮 Dispatcher 检查 `IsLoaded`」也挡不住：标签切换后旧标签的 `IsLoaded` 会一直是 `false`，不是「稍后会变 true」。
- 成对挂摘同时满足两个目标：离树时摘干净 → 旧 VM 不再被任何长生命周期对象引用，可被 GC（泄漏解决）；入树时重新挂上 → 功能不回归。

## 修改文件清单

1. **`VisionMaster/ViewModels/ProcessViewModel.cs`**
   - 新增 `Activate()` / `Deactivate()`（幂等，`_subscribed` 标志）与 `_workspaceChanged` 字段
   - `MainRunState` 订阅由 lambda 改为命名方法 `OnMainRunStateChanged`（lambda 无法反订阅）
   - 计时器 Tick 由 lambda 改为命名方法 `OnRunTimeTimerTick`
   - 构造函数末尾改为调 `Activate()`（构造即视为已入树）
2. **`VisionMaster/ViewModels/FlowCanvasViewModel.cs`**
   - 新增 `Activate()`（挂 Workspace 通知 + `Rebuild()`）/ `Deactivate()`（解绑 + `Detach()`）
   - 构造末尾改调 `Activate()`；`_workspaceChanged` 字段承接 INPC 引用
   - `PendingConnection.PropertyChanged` 保持构造内订阅（自身成员，随 VM 一起 GC，非泄漏源）
3. **`VisionMaster/Views/ProcessView.xaml.cs`**
   - `Loaded` → `Activate()`，`Unloaded` → `Deactivate()`，`DataContextChanged` 里在 `IsLoaded` 时补挂
4. **`VisionMaster/Views/FlowCanvasView.xaml.cs`**
   - 同上；另外 `DataContextChanged` 里对换下来的旧 VM 调 `Deactivate()`（旧视图被替换的路径也不会漏）
5. **`VisionMaster/Services/LayoutHelper.cs`**（同批次的画布入口修复，见另一篇记录）
   - 新增 `CriticalPanelContentIds` + `EnsureCriticalPanelsVisible`；`Shell.xaml` 的流程画布 `CanHide="False"`

## 验证结果

- `dotnet build VisionMaster/VisionMaster.csproj` → **0 错误**
- `dotnet run --project FlowCanvasChecks` → **通过 207 / 失败 0**（画布模型行为未受生命周期改动影响）

## 已知边界

1. **`Unloaded` 会触发的前提**：本修复依赖 AvalonDock 在切换标签/隐藏面板时确实把内容移出可视化树。若某些配置（虚拟化 + 缓存）下不触发，则该面板的旧 VM 仍不会被摘除——但**不会比修复前更差**（修复前从不摘除）
2. **VM 被复用的情况**：`Activate` 幂等且 `Deactivate` 后 `Activate` 会重新 `Rebuild()`，因此「隐藏→显示」链路安全；若将来有代码持有 VM 引用并在 `Deactivate` 后使用，需先 `Activate()`
3. **构造即 Activate**：VM 若被直接 new 出来但从未入树（例如单元测试），订阅是挂着的；测试结束若不 `Deactivate()` 仍会留在静态表里（旧行为一致）
4. **未覆盖的其它面板**：`LogViewModel` / `MonitorViewModel` / `ToolViewModel` / `FlowListViewModel` 是否也有同类订阅，本次未逐一排查（进程内面板数量固定，量级远小于 Process 的计时器）
