| # | 用户原话 | 屏幕上看到的样子 |
| --- | --- | --- |
| ① | 「窗台与容器间隙有点大 **关闭按钮的X 显示不全**」（帮助手册弹窗截图） | 30×30 的关闭钮里，「✕」左右两截被削掉 |

**①③与②是两条完全不同的根因**，一开始被当成同一件事（都叫"显示不全"），分开查才查清：
一条是**几何数据里少一笔**，一条是**格子宽度减内边距的算术**。两条的编译期都是全绿。

## 2. 根因②：主窗口标题栏的 `Path` 几何少一笔

`WindowControlButton` 模板把 `Content` 当 `Path.Data` 用（`UI\Controls\Themes\Controls\Window.xaml:30`）：

```xml
<Path x:Name="Icon" … Data="{Binding Content, RelativeSource={RelativeSource TemplatedParent}}"
      Stroke="{TemplateBinding Foreground}" StrokeThickness="1.2" />
```

Close 那颗的 `Content` 原文（`VisionMaster\Shell.xaml:756` 修复前）：

```
M 0 0 L 10 10   M 0 10 L 0 10
└─ 第一笔：左上→右下 = "\"   └─ 第二笔：起点 (0,10) = 终点 (0,10) = 零长度线段，什么都不画
```

正解是 `M 0 10 L 10 0`（左下→右上 = "/"），两笔合起来才是「✕」。所以屏幕上是一条孤零零的 `\`。

**为什么既有闸全放行**：样式在、模板同源、资源键存在、绑定形状对——错的不是引用关系而是**字符串数据本身**。
R30/R32 那一族"资源断链"闸（按 key 查可达性）与探针的形状检查都看不到它。

**修法**：`Shell.xaml:756` 那一行改一个字（`L 0 10` → `L 10 0`），并按 R44 同步结构副本
`UIThemeSmokeTest\ShellCopy.xaml:714`。

## 3. 根因①③：Fluent 隐式 `Button` 样式的内边距吃掉了紧格子

`VisionMaster\App.xaml:68` 把 .NET 9 Fluent 主题并进**应用级**资源（与第 6 节 GridView 事故同一支主题）：

```xml
<ResourceDictionary Source="pack://application:,,,/PresentationFramework.Fluent;component/Themes/Fluent.xaml" />
```

它带一支隐式 `Button` 样式，`Padding="11,5,11,6"`。于是**不挂样式也不写 Padding** 的按钮：

```
内容区宽 = 格子宽 − 11 − 11 − 边框      内容区高 = 格子高 − 5 − 6 − 边框
```

模板里那圈带 `CornerRadius` 的 Border 会裁子元素，所以内容区比字形窄多少，屏幕上就缺多少。

### 3.1 实测台账（HelpProbe 离屏量具，`Measure/Arrange/UpdateLayout` 真挂载）

字形需求由**不受约束的参照 `TextBlock`** 量（`Measure(infinite)`）：

| 形状 | 生效内边距 | 内容区 | 「✕」需求 | 判定 |
| --- | --- | --- | --- | --- |
| 30×30 裸按钮（Fs14） | 11,5,11,6 | **6.0×17.0** | 11.4×17.8 | **被切** |
| 30×30 + `Padding="0"` | 0,0,0,0 | 28.0×28.0 | 11.4×17.8 | 完整 |
| 30×30 + `DialogIconButton` | 6,4,6,4 | 16.0×22.0 | 11.4×18.6 | 完整 |
| 24×24 + `Padding="0"`（Fs12） | 0,0,0,0 | 22.0×22.0 | 9.8×15.2 | 完整 |
| 24×24 裸按钮（Fs16） | 11,5,11,6 | **0.0×11.0** | 13.1×20.3 | **被切（宽归零）** |
| 不定宽（Fs11） | 11,5,11,6 | 9.0×14.0 | 9.0×14.0 | 完整（自动长开吸收内边距） |

字号→字形需求的实测比例：14→11.4×17.8、12→9.8×15.2、16→13.1×20.3、11→9.0×14.0，
即 **宽≈0.82Fs、高≈1.27Fs**（闸里取 0.85 / 1.30 再 +0.5px 余量）。

### 3.2 像素对照（同一批形状渲染成 PNG 亲眼看的结论）

| 形状 | 屏幕上是什么 |
| --- | --- |
| 30×30 裸按钮 | 一个「**>**」——「✕」只剩右半 |
| 24×24 裸按钮 | 一个**空框**——「×」整根不见 |
| 30×30 `Padding=0` / `DialogIconButton` / 24×24 `Padding=0` / 不定宽 | 完整「✕」 |

### 3.3 量具自己踩的坑（写进 R69）

第一版量具判"被切"用的是**内层 `TextBlock.ActualWidth` 与参照宽比大小**，结果六个形状**全部判成"完整"**，
白跑一轮。原因：**`TextBlock` 被父级挤了也不会改自己的实得宽**（它按 `DesiredSize` 报宽，裁切发生在
父级 Border 的 clip 上，不在子元素的布局里）。正解两条：
① 参照宽必须由一个**无限宽**的 `TextBlock` 单独量（`DesiredSize` 记录的是"上一次**受限** Measure 下要了多少"，
被挤过的那个不能当参照）；② 判据用**算式**"格子 − 生效 Padding − 边框"。
另一条：`Application.Current.Resources[typeof(Button)]` 取到的那支隐式样式**读不到 Padding Setter**
（值在合并链更深处，探针打印出来是 `Padding=(未设)`），所以判据必须从**按钮自己**的生效值 `button.Padding` 取。

## 5. 修法与口径

**统一走 `Padding="0"`**，不改成挂 `DialogIconButton`。理由：这三颗各自带本视图的配色
（`MbTextSecondaryBrush` / `PanelMutedBrush` / `Background=Transparent BorderThickness=0`），
挂样式会把它们的观感换成 Fluent 的按钮皮肤——那是"修一个切字顺手改五处外观"的过度修复。
`Padding="0"` 只把被内边距吃掉的 22px 还给字形，外观一点不动。

**不定宽的点位不纳入判据**（自动长开会吸收内边距，写 `Padding` 反而多余）。
**挂了样式的点位不猜它的内边距**（静态扫拿不到合并链里的值），交给运行时渲染看。

## 6. 守门人（三层）

### 6.1 静态闸：`FlowCanvasChecks\GlyphButtonClipCheck.cs`（GB0~GB5，进常规 gate 基线）

| 条 | 判据 |
| --- | --- |
| GB0 | 定位到仓库根（以 `AGENTS.md` 为锚） |
| GB1 | 扫到第一方 `.xaml` > 80 个（只扫 `Plugins/Services/Shard/Engine/Core/UI/VisionMaster`，排除 `bin\obj`；`VM3.0-main`、`DLL\HslCommunication` 是随仓第三方源码，沿用 R29/扫描④ 口径） |
| GB2 | **反向钉住解析器**：图标按钮命中数 ≥10 且固定格子子集 ≥3——少了它，"0 违规"可能只是"0 命中"的假绿 |
| GB3 | 主判据：写了 `Width`/`Height` 的图标按钮必须挂 `Style` 或显式 `Padding` |
| GB4 | 定量：显式 `Padding` 也要过账（内容区 ≥ 字形需求，需求 = 0.85Fs×1.30Fs+0.5） |
| GB5 | 事故点复查（三颗）：仍在名单里且仍带防护；找不到那颗按钮时报"本条该重审"而不是静默通过 |

解析细节：先 `StripXmlComments`（**保留行数与列偏移**——本轮写的注释里就有「✕」和"30×30 只剩 6×17"，
不去注释就是自己判自己红）；`Width="Auto"`/`*`/绑定表达式一律按"没写死尺寸"处理（`double.TryParse` +
`InvariantCulture`）；数字字符实体 `&#xf00d;` / `&#10005;` 先解码再判图标字符。

### 6.2 运行时前提闸：`HelpProbe.RunGlyphClipChecks`（4 条）

裸 30×30 **必被切** / `Padding=0` **必完整** / 裸 24×24 内容区宽 **必归零** / `DialogIconButton` **必完整**。
这几条红了 = Fluent 换版本或主题不再并进应用级资源 → **GB3/GB4 的算术前提没了，该重审判据而不是继续挂绿灯**（R38）。

### 6.3 数据级闸：`UIThemeSmokeTest\Program.cs` 的 `RunShellLayoutChecks()` 末尾两条

同一道 `CaptionGeometryOffenders()` 判据跑两遍：`Shell.xaml` 与 `ShellCopy.xaml`（R44 的副本不许照抄原件的错）。
判据：`Button[Style*=WindowControlButton]` 的 `Content` 里出现 `M x y L x y` 且起=终 → 报"「关闭」的 M 0 10 L 0 10"。

## 8. 未决 / 交给现场

1. **真机复核**：本轮改动全部经离屏量具与静态闸验过，但「✕」在真机上是否**完全**好看（比如 20×20 那颗
   FA 图标在 `Padding=0` 后是否贴边）需要现场看一眼。
2. **`DialogIconButton` 一档的 30×30 内容区是 16×22**，比 `Padding=0` 的 28×28 紧得多——将来谁把字号从 14
   提到 18，那一档会先切。GB4 只算"显式 Padding"的点位，挂样式的点位不在算术覆盖内（这是刻意的，
   静态扫拿不到样式内边距）。
3. **`ShellCopy.xaml` 与 `Shell.xaml` 的双写**仍靠人守（R44 既有隐患），本轮只是给"照抄原件的错"补了一条闸，
   没有解决副本漂移本身。
