## 1. 欠账清单的准确盘点（先查实，不盲目全补）

R40 记的欠账清单里有三类**不同形态**，修法各不相同：

| 插件 | 枚举 | 上屏路径 | 修法 |
| --- | --- | --- | --- |
| Plugin.Utility 四件套 | `MathOperationType` / `LogicOperationType` / `ComparisonType` / `TargetDataType` | `InputPort<T>` → `LinkableValueEditor` → `StepConfigOption.ForEnum` | 补 `[Display(Name)]` |
| 两个脚本插件 | `ScriptVarType` | **裸 `Enum.GetValues` 数组上屏**（`ComboBox.ItemsSource = Enum.GetValues(...)`，显示成员名） | 补 `[Display]` + 视图改走 `ForEnum` |
| Plugin.DataRecord / ExcelExport / ResultUpload | `ImageSaveMode` / `ExportPolicy` / `PayloadKind` / `SendTiming` / `FieldSource` / `BuiltInField` | 视图里**手写 `LabelConverter` 映射**（`{ BuiltInField.Timestamp, "时间戳" }`） | **已覆盖**，不动 |
| Plugin.PreProcessing | `ColorSpaceMode` / `MirrorMode` / 等 8 个 | `FlatPropertyGrid` 的 `EnumGenerator`（读 `[Description]`） | **已覆盖**，不动 |

**关键区分**：`ForEnum` 读 `[Display(Name)]`，`FlatPropertyGrid.EnumGenerator` 读 `[Description]`——两条路不是同一个特性。PreProcessing 标的是 `[Description]`，所以它在本闸门（ForEnum 路径）之外；DataRecord/ExcelExport/ResultUpload 的枚举根本没走 ForEnum（手写映射），也不在欠账里。

## 3. 守门人

`FlowCanvasChecks\MotionZMotionChecks.cs` 的枚举中文闸门扩容：在"几何+运动 23 个成员"之后追加一条新断言，
盯 **Utility 四件套 + 两个脚本插件的 6 个枚举共 52 个成员**逐个过中文闸门（`ForEnum` 读 `[Display]`，
没标或显示=成员名即红）。

**闸门的两处健壮性修正**（被真机数据教育）：
- 反射解析不到脚本插件类型时，初版把 `null` 混进 `Enum.GetNames` 让闸门自己崩掉——改成**红着说清是哪个类型没找到**，
  不让"闸门坏了"与"缺中文"分不清。
- `FlowCanvasChecks.csproj` 补了两个脚本插件的引用（`Plugin.CSharpScript` / `Plugin.ImageScript`）——
  它们原来不在引用集里，反射解析不到，"生产加载器能打开这份方案"那条断言也因此红了一次（`ScriptVarDef` 的
  `$type` 解析失败）。加上引用后两个都恢复。
