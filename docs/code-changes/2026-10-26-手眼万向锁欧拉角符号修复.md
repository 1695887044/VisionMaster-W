## 二、已做

### 2.1 代码改动

`Plugins\Plugin.HandEye\HandEyeMath.cs:598`：

```diff
-                rz = Math.Atan2(r[0, 1], r[1, 1]);
+                rz = -Math.Atan2(r[0, 1], r[1, 1]);
```

推导：正解 `R = Rz·Ry·Rx`；`ry=+90°`、`rx=0` 时 `r[0,1] = -sin(rz)`、`r[1,1] = cos(rz)`，
所以 `Atan2` 得到的是 `-rz`；`ry=-90°` 同理。加负号后 `rz` 才与正解一致。

### 2.2 断言改动

- 改为 `rz=30°`，并把往返比较抽成局部函数 `GimbalRoundTripDiff(ryDeg)`；
- 新增「欧拉④b」覆盖 `ry=-90°`。

## 五、踩过的坑

- **万向锁断言的 `rz=0` 盲点**：`Atan2(0,1)=0`，符号错在 `rz=0` 时完全不可见。这类"参数取了让缺陷
  不可见的特殊值"的断言比没有断言更危险——它让人以为这一点已经测过（R38 的反证要求）。
- **修复顺序必须是"先改断言、确认红，再改代码"**：如果先改代码，新断言直接绿，无法证明它真的能抓到这个
  缺陷。本次两次日志（before/after）就是反证。
- **`Mat4ToXyzEulerZyxDeg` 当前不在插件主路径**：手眼插件输出的是 4×4、CSV 写的是原始 12 个数，
  所以这条修复不会改变任何现有生产输出；它的价值是把 public helper 的注释承诺兑现，防止未来
  "把 4×4 写回 12 个数"时静默写错。
- **产物判据看 mtime 不看构建退出码**（红线③）：本次额外核了 `Modules\` 与宿主输出目录两份 DLL 的
  mtime，均晚于源码。
