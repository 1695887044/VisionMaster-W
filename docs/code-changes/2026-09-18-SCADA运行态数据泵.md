## 一、需求与决策

### 需求

S4 让画面"能跑起来"，S5 让图元"能发事件、能执行动作"，但整个 SCADA 与商用组态之间最大的一条差距还在：

> **`ScadaBinding` 有模型，没有数据泵。** 变量值变了，图元属性一动不动——做出来的只是"会动的图片"。

S6 就是补这条：**变量值变化 → 图元属性变化**。没有它，组态软件不成立。

### 八条设计决策（逐条）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 一 | **值的落点** | **写控件，不碰模型**。给 `ScadaElementBase` 开运行态写值入口，模型全程只读 | 模型是"设计文档"，运行态改它就是改用户的方案；而且停止时只要重刷一遍模型，设计值自动回来——**不需要任何"恢复现场"的备份表** |
| 二 | **跨线程写入** | **脏值暂存 + 单次排队合并** | 网络变量在后台轮询线程改值，写 `DependencyProperty` 必须回 UI 线程。同一帧内 N 次变化只写最后一次，否则 1000 个绑定 × 100ms 会把 UI 打成筛子 |
| 三 | **订阅粒度** | **按变量订阅一次 + 反向分发** | 表结构是"变量 → 一批目标（控件 + 属性键 + 格式）"。两个图元绑同一个变量只订一次，变量注册表侧的订阅数与绑定数解耦 |
| 四 | **值转换层级** | **标量直转 + 复用既有转换链** | 目标属性是 `string` 就直接 `ToString`；类型本就对就直通；其余走 bool / enum / `IConvertible` / WPF 转换器逐级降级，**不新造一套类型系统** |
| 五 | **失败可见性** | **日志 + 控件上的视觉标记** | 静默失败是现场最难查的一类（"这个值怎么不动"）。两条通道：日志可复盘（角标随窗口消失），角标可当场看见 |
| 五-子 | **标记强度** | **轻量角标 + 悬停看原因**（右上角 6px 圆点，集中叠在画布之上的**诊断层**） | 不做弹窗、不做红框——运行画面是给操作员看的，诊断信息不能挡住工艺画面 |
| 六 | **写变量范围** | **接通动作写变量 + 加显式写契约**（Core 侧 `IWritableVariable`） | 值通道顺带能写，但"写"是命令语义（同值也要下发、必须返回真实结果），与"读"分开成两个契约 |
| 八 | **建表时机** | **首帧后、跑 Loaded 之前** —— 挂在宿主既有 `OnFirstFrameRendered` | 早了（会话 `Start()` 那一刻）画布还是空的，一条都命中不了；晚了则"画面刚打开时那个值没显示，动一下才出来" |

### 建表时机为什么是最难的一条（写下来给下一个人）

三个时刻只有一个是窗口期：

```
会话 Start()  ────►  ContentRendered（首帧）  ────►  Loaded 动作
   画布为空            控件已造好、已布局            可能有"写变量"
   建表 = 空表         ★ 唯一窗口期                  需要表已建好
```

控件是在 `OnApplyTemplate → RebuildElements` 才被造出来的，所以只能卡在首帧之后。
真机日志逐行证明了这个顺序（见第三节）。

### 阈值化日志：为什么"命中 0 / 未命中 0"不记

`数据泵建表：命中 N / 未命中 M / 订阅 K` 这行**只在 `N + M > 0` 时才输出**。
没配绑定的画面是绝大多数页面的常态，无条件记只会把日志淹掉；
而一旦有绑定，这一行是回答"画面怎么不动"的第一现场——它必须出现。

## 四、已知边界

1. **★ 压力验收未做**：路线图的真机验收口径是「1920×1080 画面挂 200 个绑定，模拟变量 20ms 周期跳变，跑 60s，UI 不卡、内存不涨、停止后句柄与订阅归零」。
   本次真机只跑了 **5 条绑定**——它验证的是**正确性**（建表/订阅/诊断/动作四档/停止路径），**不是吞吐与泄漏**。
   200 绑定 × 20ms 的压测与句柄/内存观测**尚未执行**，是 S6 唯一未闭合的验收项。
2. **画面级钩子的动作表仍无法在界面上编辑**：`ScadaPagePropertyRow` 不是 `IsCompositeEditor`，所以画面级 `EventHooks` 的动作只能**手改 `.vms`**（本次验证正是手改的）。
   图元级动作（`ScadaEventRow`）可以正常编辑。这是 s6-6d 未覆盖到的一块。
3. **图元属性反向写变量不做**：输入框改值 → 变量，留待 S9 统一写入口（路线图明确）。
4. **`Navigate`（切换画面）仍未接通**：等 S8，`PendingReason` 照旧出「切换画面要等画面导航（S8）接入」。
5. **`ScadaCanvas` / `ScadaElementBase` 没有 `AutomationPeer`** → UIA 看不见任何图元，「图元是否可见 / 角标是否画上」无法做图形级自动化验收，只能靠运行态日志。
6. **`.vms` JSON 是 PascalCase、无 camelCase 策略**（`SolutionService._jsonSettings` 只有 `Formatting.Indented / NullValueHandling.Ignore / TypeNameHandling.Auto / SafeSerializationBinder`）。
   手工写 `.vms` 必须用 C# 属性原名，小写会**静默丢失**——这条踩过一次，写在这里。
7. **`ScadaAction` 刻意保持扁平类 + 类型字段**（不搞派生类）：派生类会让 `.vms` 写出 `$type`，就要过白名单。
8. **SCADA 新代码与 `tools\*.ps1` 仍未纳入版本控制。**

### 操作纪律（真机验证踩过的坑）

- **改 `.vms` 前必须先杀进程**：软件退出时会把内存中的旧模型写回文件，改好也会被覆盖。
- **单实例保护**（Mutex `Local\VisionMaster-W-SingleInstance`）会拒绝重复启动，表现为"进程秒退、日志无新启动记录"——所以重启前必须先杀旧进程。
- **UIA 的 `InvokePattern.Invoke()` 对按钮类控件可靠可用**，是"无合成桌面"下唯一能驱动真机的手段（合成鼠标 `SetCursorPos` + `mouse_event` 在本机不生效）。
