## 一、结论先说

| 指标 | 现画布（每节点一个元素） | 自绘层（第 1 步） | 倍数 |
| --- | ---: | ---: | ---: |
| 建几何快照（2268 节点 / 2267 线） | — | **25 ms** | — |
| 一帧渲染（视口内 25 个节点） | 7 400 ms（整次重建） | **11~21 ms** | ~500× |
| 一帧渲染（缩到全图，460 节点全画） | 同上 | **24~32 ms** | ~250× |

> 数字口径：`RenderTargetBitmap`（**软件光栅化**，比 GPU 慢），1600×900，Debug 构建。
> 也就是说真机 GPU 下只会更快，这里的 11~32 ms 是**上限**。

**但这是"只读渲染"的数字，不含交互。** 现在还不能替换画布：点选、框选、拖动、拖线、右键菜单、缩放平移都还在 Nodify 那边。

## 二、第 0 步：几何守门断言（`--surface-guards`）

新增 `FlowCanvasChecks\CanvasSurfaceGuards.cs`（22 条，全绿），把自绘层必须满足的三组语义**先钉死**：

| 组 | 钉住什么 | 条数 |
| --- | --- | ---: |
| SURF-1 框选几何 | 矩形命中集合精确、`Rect.Empty` 不命中、`HitTest` 取最高 ZOrder（泳道压容器框）、画布外返回 null | 9 |
| SURF-2 多选批量位移 | 坐标精确偏移、只有 `Kind==Step` 写回 `FlowLayoutStore`、`ContentBounds` 跟随且右缘严格外扩、顶缘只随最顶节点动 | 7 |
| SURF-3 FitToScreen | 视口包含全部四角、zoom 均匀且在 `[minZoom,maxZoom]`、缩 10% 后不再包含（**反证有鉴别力**）、夹取后的代价、空画布返回 `Rect.Empty` | 6 |

每条都有反向或边界对照（R38：不许"永远为真"的断言）。

## 三、第 1 步：只读渲染层（`VisionMaster\Views\FlowCanvasSurface.cs`，约 1100 行）

### 3.1 结构

- `FlowCanvasSurface : FrameworkElement, IFlowCanvasGeometry`：**零子元素**，一切画在 `OnRender`。
- `SetModel(FlowCanvasViewModel)` 时把 `Nodes`/`Links` 压成**冻结快照**（排序、连线 `StreamGeometry` 预建并 Freeze）。
- 公开 `HitTest` / `ContentBounds` / `ComputeFitViewport` / `Zoom` / `Pan` / `LastDrawnNodeCount`。
- 颜色写死为 `Colors.xaml` 的字面量副本（无 `Application` 的断言宿主解析不到资源键），每个字段注释标了键名。

### 3.2 两条让性能成立的关键设计（都是实测逼出来的）

**① 视口裁剪**：`OnRender` 把屏幕矩形反变换回图坐标，只画与它相交的节点/连线（外扩 64px）。

**② LOD：缩放 < 0.4 不画文字**。缩到能看全图时全部节点都在视口内，裁剪帮不上忙，
而文字排版是自绘里最贵的一段。阈值与 Nodify 自己的 `OptimizeRenderingZoomOutPercent(0.3)` 同量级。

**③ 禁用态不用 `PushOpacity`（这条最贵，实测差 100 倍）**：

| 做法 | 460 个禁用节点、适配全图 |
| --- | ---: |
| `dc.PushOpacity(0.45)` 每节点一个 | **3 179 ms/帧** |
| 把 0.45 预乘进画刷（`Fade()`，冻结缓存） | **32 ms/帧** |

`PushOpacity` 在 WPF 里是"开一个合成图层"，元素方案的 `Opacity` 属性是合成属性——**同一个视觉效果，
自绘里用错 API 就是 100 倍代价**。这条已写进代码注释，后续任何自绘控件都适用。

### 3.3 三级 LOD（2026-10-24 追加）

| 缩放 | 画什么 | 典型一帧 |
| --- | --- | --- |
| ≥ 0.4 | 全细节：卡片 + 图标块 + 标题/副标题 + 序号角标 + 容器头带 + 连线标签 | 11~21 ms（视口内 25 节点） |
| 0.15 ~ 0.4 | 卡片 + 边框 + 泳道/容器框，**不画任何文字** | ~20 ms（460 节点） |
| < 0.15 | **只画纯色块**（无边框、无圆角、无图标） | **42 ms（2268 节点、实画 674 个）** |

看全图时一个节点在屏幕上往往不到 2 像素，描边/圆角/文字都不可辨——省掉它们是纯赚。
这也是"全局不要那么细节"的落地方式。

> 注：极端单列布局（高 29 万像素）需要 zoom 0.003 才能装下，而 `ZoomFloor = 0.01`，
> 所以"看全图"在这种图纸上仍然要平移。这是数据形态问题，不是渲染问题。
