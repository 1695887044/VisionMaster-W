## 1. 起因与需求

变量管理原先只有「添加变量」一条录入路径：一条设备挂几十个监控点 / 控制点时，用户只能逐条点开属性网格填
存储区、偏移、类型、扫描组、显示分组。三件事做不了：

1. **整表交付**：现场给一份 Excel 点位表，无法一次落进方案；
2. **整表带走**：`.vms` 是整方案级文件，不能只把"这台设备的变量表"交给别人；
3. **批量改**：换一批地址 / 改扫描组 / 调缩放系数，只能一条条改。

因此本批做的是**单设备（连接）维度**的变量表导入 / 导出，边界写死在入口上：

- **只对网络来源**（某条通信连接）生效，本地 / 系统变量不参与——它们没有设备地址表；
- 导出的是**结构化字段**，不是"把地址串抄一遍"；导入**按变量名匹配**，不靠 Excel 改名；
- 导入是**事务**：要么全落、要么全回滚，且流程运行中禁止导入。

## 2. 方案与口径

### 2.1 入口：变量管理卡片头「导出 / 导入」，仅网络来源

| 项 | 实现 |
| --- | --- |
| 位置 | 卡片头右侧、搜索框之后、「管理分组」之前（`GlobalVariableView.xaml:704-756`） |
| 命名元素 | `ExportButton` / `ImportButton`（冒烟与静态闸按名字取） |
| 显隐 | `Visibility="{Binding IsNetworkSource, …}"`——本地 / 系统来源**整块收起，不置灰** |
| 可执行 | `IsNetworkSource && SelectedConnection != null && _workspace.CurrentSolution != null`（`GlobalVariableManagerViewModel.cs:944-947`） |
| 换来源时 | `IsNetworkSource` / `SelectedConnection` 的 setter 各补一次 `RaiseCanExecuteChanged`（`:594-595`、`:613-614`） |
| 弹窗注册 | `App.xaml.cs:474-479`（`DeviceVariableExportViewModel.DialogName` / `DeviceVariableImportViewModel.DialogName`） |

**为什么收起而不是置灰**（视图注释逐字保留）：置灰会让用户以为"权限不够"，而实际是本地 / 系统变量
根本没有设备地址表这条业务。

**导入的入口先选文件**：`ExecuteImport` 先弹 `OpenFileDialog`（`*.xlsx`），拿到路径后才开预览弹窗
（`GlobalVariableManagerViewModel.cs:1081-1100`）——没有"空弹窗再选文件"这一步。

**关窗回执**：导入是**即时落地**（结果页只是回执），所以 `OnImportClosed` **只在确认时重建**左栏与明细
（含结果页点 × 返回 OK），并统一回到该设备的「全部」分组（`GlobalVariableManagerViewModel.cs:1168-1188`）
——新增变量可能落在任意分组，停在导入前的分组会让用户以为"导进来的没几个"；**未应用过的取消保持原选择**，
不重建左栏。尝试过「应用」（含失败）后关闭也返回 OK，以便刷新已回滚/已落地的界面（§5c P3-g）。

### 2.2 导出

单设备网络变量 → xlsx，两张表：**变量表** + **说明**（可关）。

| 项 | 口径 |
| --- | --- |
| 范围 | **全部变量** / **当前显示分组** 二选一（两张 `RadioButton` 卡片，带实时计数） |
| 当前分组不可用时 | 左栏没选中分组 → 第二张卡禁用并显示"先在左栏选中一个分组" |
| 选项 | 「附带说明页」（默认开）、「附带地址预览列」（默认开） |
| 保存位置 | 默认「我的文档」+ `{连接名}_变量表_{yyyyMMdd_HHmm}.xlsx`；`浏览…` 可改；路径只读文本框 |
| 覆盖确认 | 目标已存在 → `EasyDialog.ShowSync("覆盖文件", …)` 二次确认 |
| 汇总 | 蓝条一句话：`将导出 N 个变量：分组A 3 / 分组B 2`（当前分组档只报该组） |
| 空范围 | 可导出计数为 0 时「导 出」禁用 |
| 窗口 | 620 × 560，最小 580 × 520 |

**范围判据**（`DeviceVariableExportViewModel.cs:291-300`）：按 `ConnectionName` 过滤出该设备的网络变量；
当前分组档再按 `NormalizeGroupId(v.GroupId, groups) == _currentGroupId` 过滤——悬空 `GroupId` 归一成
`Guid.Empty`，与「未分组」一致，不会因为分组被删而"导出 0 个"。

**结构化地址列**（本批的核心决定）：地址拆成
`存储区 / 偏移量 / 位偏移 / 站号 / DB号 / 元素个数 / 每元素字节数 / 地址偏移 / 40001写法` 九列，
`地址预览` 是**只读列**，导入端明确忽略。理由：复合地址串（如 `D100`、`DB7.DBW10`）的格式随协议变化，
拿它当输入等于让导入端再写一套反向解析器；拆成列之后每个字段都能独立校验、独立报错。

**说明页**（`DeviceVariableExportService.BuildGuideRows`，`:496-530`）列出：格式版本、适用范围、匹配规则、
必填列、该连接可用的数据类型 / 存储区 / 扫描组候选、显示分组候选、地址填写说明、每元素字节数、初始值、
删除口径、运行锁、地址预览只读。目的是"导出的文件换台机器也能照着填"。

**写盘**：先写同目录临时文件（`path + ".{guid}.tmp.xlsx"`）再 `File.Move(…, overwrite: true)`
（`:467-483`）——见 §5.7。

### 2.3 导入

流程：**选择文件 → 差异预览 → 事务应用 → 结果页**（窗口 1060 × 800，最小 960 × 700）。

| 阶段 | 界面 |
| --- | --- |
| 文件 | 文件名 + `N 行`；「重新选择」「下载模板」 |
| 步骤条 | `① 选择文件 ── ② 预览与确认 ── ③ 完成` |
| 四类计数 | 新增 / 更新 / 无变化 / 错误（四个描边胶囊，带色点） |
| 差异表 | 行 / 变量名 / 类型 / 地址 / 扫描组 / 显示分组 / 状态 / 说明；按文件顺序；错误行在「说明」列给原因 |
| 选项 | 「跳过错误行」（仅有错误时可用）、「删除文件中没有的变量（N 个）」（默认关）、「自动创建未知显示分组」（默认开） |
| 后果提示 | 删除清单（前 3 个 + 总数）、未知扫描组回落说明、显示分组新建 / 回落说明 |
| 底栏 | `ApplyHint`（将应用 N 项 / 有错误请修正或勾选跳过 / 没有需要应用的变更）+ 取消 + `应用 N 项` |
| 结果页 | 56px 成功圆 + 「导入完成」+ `新增 x · 更新 y · 删除 z · 跳过 n` + 「关闭后变量管理会自动刷新；新增变量已接入轮询。」 |

**按变量名匹配，不支持通过 Excel 改名**：同名 = 更新；文件内重名 = 错误行；与方案内其它变量
（本地 / 系统 / 其它设备）撞名 = 错误行。改名只能在变量管理里做，或"删旧建新"两步。

**默认全有或全无**：存在错误行时「应用」置灰；勾选「跳过错误行」才允许只应用合法行，错误行整行
`Opacity=0.5`。**删除缺失默认关闭**：不勾就保留文件里没出现的变量；勾选后逐条列出将删的名字并提示
"引用这些变量的流程 / 画面可能断链"。

**未知扫描组回落「默认组」且不自动建组**（`PollScheduler.DefaultGroupName = "默认组"`，
`Communication\Communications\Manager\PollScheduler.cs:138`）。扫描组是连接级调度资源（周期 / 请求配额 /
段合并），在导入里凭空建一个只会得到一个"周期取连接默认值"的空壳组，还会让轮询侧多一条无法解释的配置。

**未知显示分组**：选项开（默认）→ 自动建组（复用分组编辑器 `ValidateGroupName`：空名 / 超长 / 保留名 /
重名都拒绝）；选项关 → 回落「未分组」并在提示条列出。显示分组是纯展示分类，自动建组没有副作用，所以默认开。

**流程运行中禁止导入**：互锁落在「应用」这一步（`DeviceVariableImportViewModel.cs:348-358`）——
`RunState == Running` 时弹「互锁」说明并直接返回；`DeviceVariableImportService.Apply` 首部也再守一次
（`:1198-1200`），未来直接调服务同样绕不过。注意这是**应用时拦截**，不是入口禁用：预览（读文件、算差异）
是纯读操作，允许在运行中看。

### 2.4 事务

`DeviceVariableImportService.Apply`（`DeviceVariableIoService.cs:1180-1340`）的顺序固定：

```
① 自动建显示分组
② 逐行：新增 → Add；更新 → 快照 + 赋值 +（必要时）ReRegister
③ 删除缺失（仅勾选时）
任一步抛异常 → Rollback(...) 逐项收集错误 → 抛 DeviceVariableImportException
```

**回滚清单先入、再动集合**（`:1266-1269`、`:1282-1284`、`:1322-1324`）：集合变更会触发桥接器注册，
注册抛异常时对象**可能已经进了集合**；后进清单就等于回滚漏掉它。三类都遵守：新增变量、更新快照、
待删变量。

**更新必须 ReRegister**（`:1276-1313`）：地址（含地址类型 / `DataValueType`）/ 数据类型 / 扫描组 /
区域合并读任一变化就调 `NetworkVariableBridge.ReRegister`。这四项在注册时被抄成 `CommunicationVariable`
快照，只改模型不重注册会出现"导入成功但还在读旧地址"这种最坏的静默故障。**ReRegister 返回 `bool`**：
返回 false（连接不存在 / 地址非法）时抛错并回滚，不再静默报成功。

**数组的「初始值」列按设计忽略**（`:1301-1306`）：Excel 里数组行的初始值是空的，若照写就会把已有
`DefaultValue` 基准清成 `null`——那是「恢复初始值」与数组编辑弹窗的唯一锚点。**更新行的空白初始值
= 保持原值（含 null）**；新增行留空才用类型默认值（`:947-952`）。

**回滚覆盖四类**（`Rollback`，`:1342-1402`）：新增变量移除、更新变量按快照还原（只对"本来就需要
重注册"的变量重注册）、被删变量加回、自动建的分组移除。每个动作单独 `try/catch` 并把错误**收集成列表**
返回；全成功时异常消息是「本次改动已回滚」，有失败时是「回滚未完全成功：…」——VM 不再固定声称已回滚。

### 2.5 协议与空白默认值

| 协议 | 地址结构 | 导出 / 导入往返 |
| --- | --- | --- |
| Modbus Tcp / Rtu | 存储区 + 偏移 + 位偏移 + 站号 + 元素个数 + 每元素字节数 + 地址偏移 + 40001写法 | 全覆盖（`[IO]` 往返断言） |
| 西门子 S7 | 存储区 + 偏移 + 位偏移 + **DB号** + 元素个数 + … | 全覆盖（DB 号单独一条往返） |
| 三菱 MC | 存储区（`[Display]` 中文名，如 `D 数据寄存器`）+ 偏移 + …（**不适用位偏移**） | 全覆盖（`[IO]` Mc 往返；导入兼容成员名 `D`） |
| 欧姆龙 Fins | 存储区（`[Display]` 中文名，如 `D DM 区`）+ 偏移 + 位偏移 + … | 全覆盖（`[IO]` Fins 往返；导入兼容成员名 `D`） |

**空白单元格的默认值必须按列语义给**——这是本批第一个被断言抓到的真 bug（§5.1）：

| 列 | 空白时的值 | 允许范围 / 说明 |
| --- | --- | --- |
| DB号 | **1** | 1 ~ 65535；**仅 S7**，非 S7 填了明确报错 |
| 元素个数 | **1** | ≥ 1；标量（非 string）必须为 1；字符串标量表示**总字节数**（与数组同样受单次读取上限约束） |
| 缩放系数 | **1** | 乘数，0 会把所有读数变成 0；拒绝 NaN / Infinity |
| 位偏移 | **-1** | 0 ~ 15（FINS 到 15；Modbus / S7 上限 7），留空 = 不使用；仅布尔变量；**MC / 线圈 / 离散输入不适用**（填了明确报错） |
| 站号 | **0** | 0 ~ 255；**仅 Modbus**，非 Modbus 填了明确报错 |
| 地址偏移 | **0** | 任意整数（地址单位） |
| 工程偏移 | **0** | 拒绝 NaN / Infinity |
| 区域合并读 | **是** | 是 / 否 |
| 40001写法 | **否** | **仅 Modbus**；S7 / MC / Fins 填"是"明确报错（不再静默忽略） |
| 扫描组 | **默认组** | 未知组名 → 默认组，不自动建组 |
| 显示分组 | **未分组** | 未知组名 → 自动建（默认开）或未分组 |
| 初始值 | 类型默认值 | 仅标量；**新增行留空 = 类型默认值，更新行留空 = 保持原值（含 null）**；数组忽略；拒绝 NaN / Infinity |
| 每元素字节数 | 0 | **仅字符串数组**可填（≥ 1）；其它类型填了明确报错 |

## 5. 本批被断言抓到的真实缺陷

以下七条**都是"编译期全绿、只有真跑才看得见"**的类型，写在这里是为了后来者不要重复踩。

### 5.1 空白单元格被 `TryParseInt` / `TryParseDouble` 当 0

- **症状**：导出的表把「DB号 / 元素个数 / 缩放系数」留空，导回来全是 0——DB 0 直接报错、元素 0 报错、
  缩放 0 把读数全变成 0；位偏移留空被当成"第 0 位"，bool 变量悄悄改成按位读。
- **根因**：两个解析器的契约是"空白返回 `true` 且 `value = 0`"（`DeviceVariableIoService.cs:137-166`），
  调用方如果直接拿 `value` 当结果，就把"没填"和"填了 0"混为一谈。
- **修法**：**每列自己决定默认值**，并在解析后显式补：DB 1（`:740-741`）、元素 1（`:753-754`）、
  缩放 1（`:800-801`）、位偏移 -1（`:710-714`，空白根本不调用解析器）、站号 / 地址偏移 / 工程偏移 0。
  解析器注释里也写清了这条契约，防止下一个人直接复用。
- **守门**：`[IO]` ② 往返（导出留空 → 导回必须"无变化"）与 ⑤/⑥/⑦ 的落库值断言。

### 5.2 `DataGrid.RowHeight="Auto"` 在视图构造期抛异常

- **症状**：导入弹窗一打开就抛 `Auto is not a valid value for Double`，编译期 0 错误。
- **根因**：`DataGrid.RowHeight` 是 `double`，WPF 的 `Auto` 只属于 `RowDefinition.Height` 那种 `GridLength`。
- **修法**：自动行高写 `RowHeight="{x:Static sys:Double.NaN}"` + `MinRowHeight="42"`
  （`DeviceVariableImportView.xaml:329`）。
- **守门**：冒烟静态闸同时断言"不许出现 `RowHeight="Auto"`"且"必须有 `Double.NaN`"（两条一起，防止
  有人把整行删掉也算过）。

### 5.3 `Run.Text` 默认 TwoWay，绑只读计数在构造期抛异常

- **症状**：导入弹窗计数胶囊里的 `新增 3` 让视图构造期抛"无法对只读属性使用 TwoWay 绑定"。
- **根因**：`Run.Text` 是依赖属性且**默认 `TwoWay`**（与 `TextBlock.Text` 的一贯印象相反），
  `NewCount` / `UpdateCount` 等只有 getter。
- **修法**：五处计数 `Run` 全部显式 `Mode=OneWay`（`:227`、`:247`、`:267`、`:286`、`:474`）。
- **守门**：冒烟正则扫这五个属性名，任何一处漏写 `Mode=OneWay` 就红。

### 5.4 自定义 `RadioButton` 卡片内容宽不等宽

- **症状**：导出弹窗两张范围卡首版一张 178px、一张 119px，看起来像"没铺满"。
- **根因**：`RadioButton` 默认 `HorizontalContentAlignment=Left`，模板里的 `Border` / `ContentPresenter`
  也按内容宽收缩；只给外层 `Grid` 写 `*` 列不管用。
- **修法**：`HorizontalAlignment="Stretch"` + `HorizontalContentAlignment="Stretch"`，模板里 `Border` 与
  `ContentPresenter` 也写 `Stretch`（`DeviceVariableExportView.xaml:120-122`、`:135`、`:191-192`、`:204`）。
- **守门**：导出弹窗渲染图（两张卡等宽、计数右对齐）。

### 5.5 数组更新会把基准 `DefaultValue` 清成 null

- **症状**：导入一次（哪怕只改描述）之后，数组变量的「恢复初始值」失效、数组编辑弹窗的基准变成 0 项。
- **根因**：Excel 里数组行的「初始值」按设计是空的，更新路径若照写 `variable.DefaultValue = null`
  就抹掉了基准；而基准是数组编辑 / 恢复的唯一来源（v2 语义）。
- **修法**：更新只在**非数组**时写初始值（`DeviceVariableIoService.cs:1154-1157`）。
- **守门**：`[IO]` ⑥b——先给 `int[]{1,2,3}` 基准，导入后断言仍逐元素相等。

### 5.6 MC / Fins 未导出结构化地址，导致无法回导

- **症状**：三菱 MC 与欧姆龙 Fins 变量导出后「存储区」「偏移量」两列是空的，导回来直接报"存储区不能为空"。
- **根因**：首版只写了 Modbus / S7 两支 `if`，MC / Fins 落到"空字符串"的初值分支。它们的存储区显示名
  与 Modbus/S7 不同（当时是枚举成员名 `D` / `W` / `R`，不是中文），所以不能套同一张 `AreaDisplayNames` 表。
- **修法**：补齐两支，存储区走 `AreaDisplayName(...)`，与 `GetAreaOptions` 的 MC/Fins 分支同口径。
  **后续并发 MC 会话**把 MC / Fins 的显示名接成枚举上的 `[Display]` 中文（`D 数据寄存器` / `D DM 区`），
  `AreaDisplayNames` 改由 `BuildAreaDisplayNames()` 统一构造（`GlobalVariableManagerViewModel.cs:671-709`）；
  导入仍兼容成员名 `D`。
- **守门**：`[IO]` ⑩ / ⑪（导出存储区 == `AreaDisplayNames[McArea.D]` / `[FinsArea.D]`，导出再导入无变化）。

### 5.7 导出先 Delete 再 SaveAs 有丢原文件风险

- **症状（潜在）**：磁盘满 / 目标文件被 Excel 占用时，旧实现"先删目标再写"会让用户**原来那份文件也没了**。
- **修法**：`WriteSheets` 先写同目录临时文件（保留 `.xlsx` 后缀，MiniExcel 按扩展名选格式），
  成功后 `File.Move(…, overwrite: true)`；`finally` 里删临时文件（`:467-483`）。
- **守门**：代码审查 + 说明页的写盘约定；这条没有像素/断言可验（失败注入成本高于收益），
  但写盘路径只有一处，复核面很小。

## 6. 未决 / 边界

1. **不支持通过 Excel 改名**：导入只按变量名匹配；改名请在变量管理里做，或"删旧建新"。这是有意的
   ——按名字匹配 + 允许改名会让"改一行名字"变成"删一个建一个"，引用关系（流程 / 画面）会静默断开。
2. **复合地址串不回读**：`地址预览` 只给人看，导入端明确忽略；导入只认结构化列。若现场表只有
   `D100` / `40001` 这类单列地址，需要先按说明页拆成存储区 + 偏移。
3. **协议专属列**：导出时对不适用协议留空；导入时若非空且协议不适用 → **明确报错**（站号 / 40001 仅
   Modbus、DB 仅 S7、位偏移仅 bool 且 **MC / 线圈 / 离散输入不适用**、每元素字节仅 `string[]`）。
   **不要**为了让表格"看起来整齐"给它们填 0——站号 0 对 Modbus 是合法从站号，语义不同。
4. **结果页没有独立渲染证据**：`--global-variables-render` 只渲染到"预览与确认"这一步；结果页（成功圆 +
   汇总 + 完成）目前只有 XAML 静态闸覆盖，**没有像素级对照**。需要时补一个 `IsResultStep=true` 的渲染档。
5. **模板文件只有表头 + 一行空白**：`ExportTemplate` 给一行全空行当填写示例（空行在导入时会被忽略，
   不算错误行）。没有做"按当前设备预填几行真实变量"的模板。
6. **流程运行中禁止导入是"应用时拦截"**：弹窗可以打开、可以预览差异，点「应用」时才检查 `RunState` 并
   弹互锁说明；服务层 `Apply` 首部再守一次（防直接调用绕过）。**入口按钮不置灰**——预览是纯读操作，
   提前禁用会让用户无法在运行中核对文件。
7. **删除缺失的影响面提示只列名字**：提示条列出前 3 个待删变量 + 总数，并给一句"引用这些变量的流程 /
   画面可能断链"，但**没有做引用扫描**（不检查流程步骤 / 组态画面是否真的引用了它们）。要精确报影响面，
   需要接 `IReferenceScanner` 一类的东西，不在本批。
8. **大文件同步执行会卡 UI**：`ReadRows` / `BuildPlan` / `Apply` 全在 UI 线程同步跑，几万行的表会让弹窗
   "假死"一段。异步化（进度 + 取消）是后续项，本批未做。
9. **导出不覆盖网络不支持的类型**：`HImage` / `byte[]` 等不是网络变量可用的数据类型；导出只覆盖网络变量表，
   把图像 / 二进制塞进 Excel 不在本批。
10. **服务层依赖 VM 静态助手**：`DeviceVariableIoService` 复用 `GlobalVariableManagerViewModel` 的
    `TypesFor` / `TryBuildAddress` / `ResolveType` 等（Services → ViewModels 反向依赖）。这是"同一份规则
    不复制"的取舍；要分层干净应把这些助手下沉到 Core / Communication，属后续项。
11. **导入 / 导出没有日志审计**：不写 `ILogService`，事后无法从日志追溯"谁在什么时候导了哪份表、改了
    多少变量"；目前只有成功弹泡与界面计数。
12. **组编辑器覆盖层刷新**：导入期间覆盖层是关闭的；若将来允许在导入过程中打开，`VariableGroupEditorViewModel.Open`
    会重新 `Reload`（当前靠"导入时覆盖层关闭"规避，未做并发编辑保护）。
13. **不支持在线切换 MC 厂商**：`AddressChanged` 已比较 `McAddress.Vendor`，但导入计划构建时
    `TryBuildAddress` 不带 connection 的厂商，**计划级厂商差异检测不到**；换厂商（三菱 ↔ 基恩士 ↔ 松下）
    请删旧建新。
14. **以下路径代码已改但还没有专属断言**（保留为边界；下次补 gate 优先补前四条）：系统变量撞名、
    缺「变量表」页、删除回滚、双击 Apply；以及服务层流程锁、模板 CanExecute、Reselect 复位、
    MC 厂商切换、真实设备在线轮询（最后一项只能真机验，无头断言替代不了）。
