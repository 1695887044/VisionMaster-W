## 二、已做

### 分流点只有一处

`DeviceVariableImportService.ReadRows(path, connectionCycleMs)` 按后缀分流：

```
if (EasyNetCsvReader.IsCsv(path)) return EasyNetCsvReader.ReadRows(path, connectionCycleMs);
// 否则走原来的 MiniExcel 读「变量表」工作表
```

两个入口的过滤器同时放开（主入口 `GlobalVariableManagerViewModel.ExecuteImport`、
弹窗内重选 `DeviceVariableImportViewModel.ExecuteReselectFile`）：

```
变量表 (*.xlsx;*.csv)|*.xlsx;*.csv|Excel 工作簿 (*.xlsx)|*.xlsx|汇川变量表 (*.csv)|*.csv
```

### 列映射（汇川 → 本仓）

| 汇川列 | 本仓列 | 口径 |
|---|---|---|
| 名称 | 变量名 | 原样（含 `Alarm1[0]` 这类下标名） |
| 注释 | 描述 | 原样 |
| 数据类型 | 数据类型 | Bool/Int16/Int32/Float/Double/String → 本仓显示名；**认不出的回落原文**，由 BuildPlan 报"无法识别"（UInt16/UInt32/WString/DateTime 目前都不支持，宁可报错也不误读） |
| 地址 `UB 2101060` | 存储区 + 偏移量 | 拆成前缀 + 数字；U/UB/UW → U，D/M/S/B/X/Y/R/W → 同名 |
| 数组计数 | 元素个数 | `>1` 或 `[lo,hi]` 才算数组；`1` 是标量 |
| 长度 | 元素个数 | **仅字符串标量**：汇川的长度列 = 总字节数，与导入侧 string 标量同语义 |
| 采集周期 | 扫描组 | 与连接 `ReadCycleMs` 一致时**不写**（= 默认组，本来就按连接周期读）；不一致才写进去，由 BuildPlan 列成"未知扫描组 → 回落默认组" |
| 变量组Id | 显示分组 | `汇川组<Id>`，与既有方案里的组名保持连续 |

### 三条按真实文件踩出来的口径

1. **列位置按表头取**（`ResolveColumns`）：老工程 16 列（A..P，分组 Id 在倒数第 4 列），
   新工程 13 列（A..M，分组 Id 是最后一列）。按 `f[^4]` 硬编码，换个工程就把「下限」当成组 Id，
   **描述与显示分组静默丢失**。
2. **「数组计数」标量有两种写法**：老导出留空、新导出写 `1`。按"非空即数组"判，
   会把 304 个布尔标量全判成"布尔数组"（EasyNet 不支持）→ 整表报错。
3. **编码是无 BOM 的 GB18030**：先按严格 UTF-8 试解，失败回落 GB18030；
   按 UTF-8 硬解会把整表中文读成 U+FFFD。

### 重名不自动改名

一次性转换器当年对重名加 `_2/_3` 后缀"保点不丢"。产品内**不做**这件事：
变量名就是 PLC 里的名字，静默改名会让用户以为导对了。重名交给 BuildPlan 报
"文件内变量名重复（与第 N 行）"，用户在预览里逐条处理。

## 三、未做

- **UInt16 / UInt32 / WString / DateTime 不支持**：本仓 `AllTypes` 里没有对应类型。
  现状是逐行报"数据类型无法识别"，不会误读。要支持得先决定 UInt16 是映射成 int 还是新增类型
  （映射成 int 会按 4 字节读，把邻位值一起读进来）。
- **字符串数组**：汇川导出没有"每元素字节数"列，语义不明，导入会报"必须填每元素字节数"。
- 一次性工具 `tools\oneoff\EasyNetCsvImport` 保留（用于批量出 xlsx 存档），产品已不再依赖它。

## 四、下一步

1. 若产线常用 UInt16，评估是否新增 `无符号短整数 (ushort)` 类型（涉及通信层读长度）。
2. 扫描组若希望按汇川的采集周期自动建组，需要在通讯设置里先有同名组——目前不做自动建组。

## 五、踩过的坑

1. **同一家软件不同版本的导出列数会变**：这类"转换器不报错、导入侧也全绿、只是内容悄悄丢了"
   的坑，只有拿真实文件跑一遍才发现。
2. **`数组计数=1` 不是数组**：EasyNet 不支持布尔数组，误判会让整表 304 行报错。
3. **构建被运行中的 exe 锁死**：`VisionMaster.exe` 运行时会锁 `bin\` 与 `Modules\`，
   所有拷贝步骤报 MSB3021/MSB3027（不是编译错误）。必须先关掉它再构建。
4. **同一时刻别人也在改仓库**：本轮收尾跑 gate 时 `Scada\Models\ScadaStateList.cs`
   在 19:37 被另一处改动写入，留下重复的 `case "BitIndex"` 标签（CS0152），
   连带 5 个断言宿主构建失败。跨进程协作先看 `LastWriteTime`，别把别人的红当成自己的。
