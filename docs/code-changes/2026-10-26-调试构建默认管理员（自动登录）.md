### 2.1 行为口径

| 场景 | 行为 |
|---|---|
| 未上线构建（`DebugModeBuild.IsPreRelease = true`）+ **调试模式面板开关开着** + 第一次拿到已绑定账号本 + 当前无人登录 | 用出厂管理员 `admin/admin123` 自动登录 |

| 手动登出后再切方案 | 不自动登回来（每进程只尝试一次） |
| 自动登录后切到同账号密码的方案 | 凭据已回填，按"保持登录"继续 |
| 发版构建（`IsPreRelease = false`） | 永不自动登录 |
| 自动登录的权限 | admin 所在组的**真实权限快照**，与手动登录 admin 完全一致 |

## 五、踩过的坑

1. **自动登录会掩盖断言夹具的"未登录"路径**：夹具构造后必须显式
   `DebugAutoLoginAllowed = false`；需要测自动登录时再单独打开。
   否则 `[SL-e4]`（未登录切方案不会凭空登录）会被自动登成 admin 而假红/假绿。
2. **必须每进程只尝试一次**：否则手动登出后切个方案又登回来，用户无法保持登出。
   第一次拿到已绑定账号本时就算尝试过（即使失败），行为可预测。
3. **必须走 `TryValidate`，不能合成会话**：合成一个"调试管理员"会绕过密码与账号本，
   改过密码也能进，是后门。现在的实现是"用出厂密码正常登录"，审计能看出来。
4. **开关关着时不要消耗一次性尝试**：`TryAutoLoginDebugAdmin` 在检查
   `debugModeEnabledProvider` 为 false 时直接 return，**不**把 `_debugAutoLoginAttempted`
   置 true；否则开发者打开开关后还得重启才能生效。
5. **发版开关只有一个**：`DebugModeBuild.IsPreRelease`。发版时改 false 并重建，
   自动登录与"调试面板免权限"一起失效；不要用配置项把它翻回来。
6. **本地 `AppConfig.json` 是运行配置**：改 `DebugMode.Enabled=true` 只影响本机；
   源码默认值仍是 `false`（`DebugModeSettings.Enabled`），断言 `[DM1]` 仍然成立。
