# 流程栏选中算子右键删除没反应（删后命令靶被自己的清空抹掉）

- 日期：2026-10-16
- 涉及：`VisionMaster\ViewModels\ProcessViewModel.cs`（`ModuleActionAsync` 的 `Delete` 分支）、`FlowCanvasChecks\ProcessTreeInteractionChecks.cs`（新增 V10 探针）
- 触发：真机反馈「流程栏选中算子右键删除没反应，**尤其只剩下最后一个算子的时候**」。截图里第一行「延时_2」左侧有蓝色选中竖条、右键菜单的「删除」项正常亮着，点下去毫无反应。

---

## 1. 根因

**命令靶（`CurrentSelectedStepModel`）被删除分支自己抹掉了 —— 抹的时机晚了一步。**

`ProcessViewModel.ModuleActionAsync` 的 `Delete` 分支改前逐字是：

```csharp
case ModuleCommandAction.Delete:
    if (CurrentSelectedStepModel == null || Workspace?.CurrentFlow == null)
        break;
    if (RemoveStepRecursively(Workspace.CurrentFlow.Steps, CurrentSelectedStepModel))
    {
        CurrentSelectedStepModel = null;     // ← 无条件清空
    }
    break;
```

删除会从 `FlowModel.Steps` 里摘掉一项，而**流程栏的 `TreeView` 在 `ItemsSource` 变更后会自己改选邻近行**（WPF `Selector` 的保选行为）。那次改选走的是既有双向链：

```
Steps 集合变更 → TreeView 自动改选幸存行 → SelectedItemChanged
  → TreeViewBehavior.BindableSelectedItem 写回 → ProcessViewModel.SelectStep setter
  → CurrentSelectedStepModel = <幸存的那一步>   ← 靶已经指向幸存者了
```

之后才轮到 `CurrentSelectedStepModel = null` 执行 —— 把刚接上的靶又抹成 null。于是：

- 界面上**幸存那行高亮着**（树自己的选中态），`SelectStep` / `Workspace.CurrentStep` 也都指着它；
- 而命令链取参的 `CurrentSelectedStepModel` 是 `null` → 删除/改名/禁用/注释全部静默空跑
  （每个分支开头都是 `if (CurrentSelectedStepModel == null) break;`，连提示都没有）；
- **最阴的是"再点一次那一行"救不回来**：它本来就处于选中态，再点不会触发 `SelectedItemChanged`，
  写回链一次都不跑。用户看到的就是"高亮着、删不掉"。

只剩最后一个算子时必然踩中：删完只剩唯一一行，而它一定被自动选中 —— 症状与用户描述完全吻合。

### 实测证据（真视图 + 真 VM，屏幕外窗口）

删除前：`tree=延时_1，命令靶=延时_1` → 删除后：`Steps=1，tree=变量赋值_2，SelectStep=变量赋值_2，命令靶=null`。
再把同一行点一遍（它已高亮）→ 状态纹丝不动，再调删除 → `Steps` 仍是 1（**静默空跑**）。

## 2. 修法

只在"删除期间没人改过选中项"时才清空靶：

```csharp
case ModuleCommandAction.Delete:
{
    // 删除会用掉"这一次"的命令靶，但靶还要用来判断下面该不该清选中——先记住它。
    var target = CurrentSelectedStepModel;
    if (target == null || Workspace?.CurrentFlow == null)
        break;

    if (!RemoveStepRecursively(Workspace.CurrentFlow.Steps, target))
        break;

    // 树自动改选过（靶已换人）→ 保留它；没人接手 → 清空
    if (ReferenceEquals(CurrentSelectedStepModel, target))
        SelectStep = null;

    break;
}
```

三处口径同时确立：

1. **清空判据是"靶还停在刚被删掉的那一步上吗"**，不是"删完就清"。靶换人了说明树已经把选中交给幸存者，
   这次交接是用户看得见的事实（高亮就在那儿），命令链必须跟上。
2. **清空走 `SelectStep` 而不是只写字段**。旧写法只动私有字段，`SelectStep`（树的绑定源）与
   `Workspace.CurrentStep` 还停在已删除对象上——公开属性与命令靶各说各话，"菜单可见性判定"
   （`IsIfNodeSelected` / `IsCaseNodeSelected` / `IsParallelNodeSelected`）也照旧按孤儿对象算。
   走 `SelectStep` 顺带把 `Workspace.SwitchStep` 与那一批属性通知一起归位。
3. **清空分支必须留着**（反向钉住）：删掉唯一的一步时没人接手选中，靶若不清就留着已移出图纸的
   `StepModel` 当孤儿，后续改名/禁用会打在孤儿对象上（错靶）。V10 第 ④ 条守这一侧。

## 3. 守门：V10 五条

`FlowCanvasChecks\ProcessTreeInteractionChecks.cs` 的 `DeleteKeepsCommandTargetAlive()`（进常规 gate 基线）：

| # | 判据 | 挡的是 |
| --- | --- | --- |
| ① | 选中某行 → 命令靶就是它 | 前置条件（链没接错） |
| ② | 删除后命令靶 = 树自动改选的那一步（不是 null、也不是已删的那一步） | **本次事故本体** |
| ③ | 接着删幸存的那一步 → 真的删掉（`Steps` 到 0） | 用户动作"已高亮，直接再点删除" |
| ④ | 删掉唯一的一步（无人接手选中）→ 命令靶清空，不留孤儿对象 | **反向**：防"一律不清空"的过度修复 |
| ⑤ | 删光后再拖入一步：选中即可删（最后一步不是终点） | 完整走通用户路径 |

### 为什么必须在真 TreeView 上跑

症状的成因是**"树的自动改选回写 VM"**这一环。纯 VM 直调（像既有 V5/V7 那样 `vm.SelectStep = step`）
根本产生不出那次回写 —— 缺了树这一环，断言必是**假绿**（这正是它藏了这么久的原因之一）。

探针环境（照 `RoiInteractionChecks` 的 STA 夹具先例）：

- 独立 STA 线程 + `Dispatcher.PushFrame` 手动泵（断言宿主不是 WPF `Application`）；
- **不 `new Application`**（同 `BlobDetectChecks` / `ParallelContainerChecks` 的纪律：控制台进程里第二个
  `Application` 会卡初始化、退出时挂住）；
- 只做 `Measure` / `Arrange` / `UpdateLayout`，**无需窗口、无需主题资源**——
  实测 `TreeView` 的 `ItemContainerGenerator` 在这套布局后就生成容器了，判据全在数据侧
  （命令靶字段 / 步骤集合 / 树选中项），不依赖任何样式。

### 变异反证（已做）

把修法退回"无条件清空"（`if (…|| true)`）→ **②③④⑤ 准确变红**：

```
[×失败] V10：删除后命令靶 = 树自动改选的那一步  →  树选中=变量赋值_2；命令靶=null
[×失败] V10：再删剩下那一步 → 真的删掉        →  删后=1 步（期望 0）
[×失败] V10：删掉唯一的一步 → 命令靶清空        →  剩=2 步
[×失败] V10：删光后再拖入一步：选中即可删       →  选中生效=False 删后=3 步
```

还原后 5 条全绿。

## 5. 未覆盖 / 已知边界

- **程序栏（流程列表）的删除**不适用本坑：`FlowListViewModel` 的 `Delete` 分支不做"删后清选中"
  （只 `Flows.Remove(SelectFlow)`），没有"靶被自己抹掉"这一步。
- **画布侧删除**（`FlowCanvasViewModel.OnDeleteSelection`）不适用：它的选中态是节点 VM 自己的
  `IsSelected`，删除记录按引用现查现删，不经"命令靶 + 树自动改选"这条链。
- 真机复验（用户在流程栏里连删到最后一步）**未做**——本机只做了离屏 STA 夹具 + 真视图的重放；
  建议真机按"两三个算子连续删到空"走一遍确认手感。
