## 1. 实际修的三个点

### 1.1 默认 `Rules` 集合没有订阅 `CollectionChanged`（根因）

`_rules` 是字段初始化器 `new ObservableCollection<JudgeRule>()` 创建的，只有 `Rules` **setter** 会
`HookRules(_rules)`；构造函数没订阅。配置态直接 `Rules.Add(...)` 时：

- `OnRulesCollectionChanged` 不触发 → `RebuildAll` 不跑；
- 动态输入/输出端口永远为空；
- `JudgeTableChecks` 报 `输入=[] 输出=[]`、`输入端口不存在：实际_外径`。

**修复**：在 `JudgeTablePlugin` 构造函数里 `HookRules(_rules)`。

### 1.2 重名输出端口的 `_2` 后缀位置错

`ComputeNames` 原来对**完整输出名**去重：

```
Unique($"{prefix}.{stem}{ResultSuffix}", usedOutputs)
→ 工位A判定.高度.结果_2
```

验收口径要求后缀落在规则名上、`.结果` 保持在末尾：

```
工位A判定.高度_2.结果
```

**修复**：先去重 `{prefix}.{stem}`，再拼 `ResultSuffix`。

### 1.3 Tiers 登记 + Modules 刷新

- `HelpManualCheck.Tiers` 增加 `["JudgeTablePlugin"] = ManualTier.M`（5 用户 + 3 开发页，最长开发页 169 行 → M 档）；
- 重建 `Plugin.JudgeTable` 并复制到 `Modules\Plugin.JudgeTable.dll`（mtime 17:05、Help 内嵌 8 页）。
  `JudgeTableChecks` 优先加载 `Modules\`，不刷新就会一直测旧 DLL——这是本轮最容易误判的一点。
