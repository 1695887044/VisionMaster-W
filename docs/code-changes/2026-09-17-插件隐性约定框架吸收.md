### N2 的两个关键设计

1. **回收时机与语义对齐现状**：轮首（`RunAlgorithm` 之前）释放上一轮输出值，与 CreateRoi 手写的 `DisposeOldOutputs` 时机完全等价——不引入新的行为风险窗口。
2. **透传防御**：输出端口当前值若与任一输入端口上游链接的当前值**同引用**（"我输出的其实是上游的图"），跳过释放——防止透传型插件轮首误杀上游仍持有的图像。释放权始终归生产者。

## 四、已知边界

1. **默认异常语义变化**：以前"异常穿透→引擎中断当轮"，现在默认"转失败→流程继续走下一步"。需要旧行为的插件 `override bool RethrowOnException => true;`（信息照样先落 ErrorMessage）。**上机回归需关注**：跑一遍含 Halcon 异常的既有方案，确认失败步骤后续行为符合预期。
2. **N2 透传防御是基于"同一轮内引用同一性"的启发式**：若值经 `LinkedSource.Value` 之外的路径间接共享引用（如插件 A 把上游图存进私有字典、B 从别的端口拿到同一引用），仍可能误杀——这种所有权模糊的场景本就有风险，速查页已声明"跨轮持有的私有缓存仍要自己管"。
3. **回收后置空 `port.Value=null`**：下游若在本轮开始前刷缓存会读到 null（`RefreshLinkedCache` 对 null 有兜底 → `default(T)`），不会抛。
4. **84 处存量 `Success/ErrorMessage` 样板只收敛了 CreateRoi/PreProcessing 两示范插件**，其余 11 个插件待各自迭代时顺手替换（`Fail` 与旧写法完全兼容，无强制）。
5. N3 只检测 **public 字段**（private 字段可能是动态端口注册持有者，合法场景，不报）。
6. C6（动态端口快照协议）未动：受众仅 CreateRoi 一家，抽象收益不抵改动风险。
