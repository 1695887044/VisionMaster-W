## 一、需求与决策

### 为什么与 OCR 分开（用户直接问的问题）

四条理由，前三条是硬的：

| # | 理由 | 证据 |
|---|---|---|
| 1 | **算法机制毫无交集** | OCR 是「分割 + MLP 分类器」，读码是「模型驱动解码器」。共享代码量约等于零 —— 连 ROI 都不共用（读码两个算子都不吃 ROI 参数，靠 `reduce_domain`） |
| 2 | **端口契约形状不同** | OCR 一节点认一处、输出单值；读码在 HALCON 里**天然返回全部找到的码**。硬合会造出一堆"这次有值、那次为 null"的端口 |
| 3 | **失败语义正好相反** | 读码"没找到码"是**正常工况**（翻面/未打码）；OCR 认不准是**要报警的**。混在一起日志口径与下游判定必然拧巴 |
| 4 | ROI 必要性不同 | OCR 识别区**必填**（没有它无从分割）；读码**可选**，全图找是常态。一个必填一个可选，参数面板摆一起会互相误导 |

### 用户确认的 5 个决策点

| 决策点 | 结论 |
|---|---|
| 一维 + 二维 | **合在这一个节点里**，用"码制"下拉分派（对外契约完全相同；`PreProcessing` 有同款先例） |
| 一帧多码 | **数组全返回**（`Codes` 为 `string[]`） |
| 未找到码 | **算正常**：`Success=true` + `Count=0` + Info 留痕 |
| 定位 | **不归它管** —— 上级定位后传**裁好的小图**进来，节点零定位参数、无框选、无图像编辑器 |
| 开工范围 | 全套一次做完 |

### 我直接定的项

| 项 | 结论 | 理由 |
|---|---|---|
| 插件标识 | `Plugin.CodeReader`，`GroupName = "图像处理"` | DLL 名须匹配宿主 `Plugin*.dll` 扫描 |
| 端口 | 入 `Image`；出 `Codes`(string[]) / `Count` / `Text`(逗号串) | 见下"双形态" |
| 码制范围 | 内置全表（一维 14 种 + 二维 6 种） | 码制本质只是建模型时传的一个字符串，成本为零；`datacode`/`barcode` 官方样张齐全，逐码制验证 |
| 存盘值 | 存 HALCON 原始名（不是中文标签） | 稳定身份，改中文标签不会让存量图纸失效 |
| 结果寻址 | 两个 Engine 类分开 | 一维按下标、二维按句柄 —— 硬合会写出一堆 `if(是一维)` |
| 模型释放 | `Dispose()` 里 `ClearBarCodeModel` / `ClearDataCode2dModel` | 基类管不到引擎内部句柄 |

**`Text`（逗号串）不是冗余**：查证发现 `ArrayIndexProxyPort` 服务的是**变量**，`VisionMaster/` 里找不到任何生成 `端口名[下标]` 的入口 —— 画布上数组端口只能整体连，而比较/上传/存变量这些既有下游节点都按标量写。所以必须有标量形态。

### 本轮明确不做

`rectangle2` 已知位置直接解码快路径（要求角度准、现场调参贵，且不做定位就没这个前提，`reduce_domain` 已能拿到大部分提速收益）、逐码码制输出（1D `auto` 时有用，但属 YAGNI，记入边界）、质量等级输出、结果投射、判定。

### `EAN 校验位`：本文件唯一的**独立真值**

二维码的**内容**没法人工读图确认（人眼读不出 QR 的比特），所以别处只能断言"解出了点什么"（`Count≥1`）。
但 EAN 的最高位是**按编码规则算出来的校验位**，验算与 HALCON 无关：

```
[√通过] EAN-13 校验位正确（独立于 HALCON 的数学验算）  →  4008535118906 → 加权和 84，校验位期望 6 实际 6
[√通过] EAN-8  校验位正确（独立于 HALCON 的数学验算）  →  40266657   → 加权和 63，校验位期望 7 实际 7
```

**一个"把内容读错"的 bug 会在这里现形，在别处不会。** 所以这两个断言的价值高于同段其余断言之和。

### 反面用例：未找到码的语义

```
[√通过] 码制错配（用 DataMatrix 读 QR 图）→ 解不出且不抛异常  →  Count=0
[√通过] 空白图上读二维码 → 解不出且不抛异常  →  Count=0
[√通过] 空白图上读一维码 → 解不出且不抛异常  →  Count=0
[√通过] 【核心】图上没有码 → 不抛异常、Success=true（不把正常工况当失败）
[√通过] 【核心】图上没有码 → Count=0 且 Codes 为空数组（下游用 Count 判有没有）
[√通过] 未读到码时写 Info，且带上当前码制（便于现场自查是不是码制选错了）
```

### 数组端口真的能承载（用户选的那条设计）

```
[√通过] 【核心】一帧两个码 → Codes 数组真的承载了两个元素（数组端口可用）  →  Codes=R74-2001-010 | 92274A  Count=2
[√通过] Count 与数组长度一致  →  Count=2 数组长=2
[√通过] Text（逗号分隔）与 Codes 内容一致 —— 标量下游就靠它接  →  Text='R74-2001-010,92274A'
```

Code39 那张样张里**真的有两个条码**，所以这不是构造出来的用例。

## 四、实施中被实测推翻/纠正的三处

| # | 原以为 | 实测 | 处置 |
|---|---|---|---|
| 1 | `set_bar_code_param` 接受 `polarity` | **拒绝**（`#3286 Wrong generic parameter name`）。一维读码本身对极性鲁棒，压根没这个旋钮 | 一维引擎去掉极性参数。写临时探针把 13 个候选名逐个试了一遍，**合法名记进引擎注释**；探针用完即删 |
| 2 | 二维 `ResultHandles` / `DecodedDataStrings` 长度应相等 | HALCON 官方文档**自相矛盾**（一个说"只含成功解码的"、一个说"含所有检测到的"） | 不猜：按"字符串非空"收码，两个数量都记出来，不一致时补一条 Warn 诊断 |
| 3 | 一维与二维参数只是名字不同 | `set_data_code_2d_param` 接受 `polarity`，`set_bar_code_param` 不接受 | **配置界面必须按家族分派**（1D 面板不出现极性项）—— 这条是 UI 结构的硬依据 |

探针实测的一维合法参数名（不是猜的）：
```
element_size_min / element_size_max / num_scanlines / orientation / quiet_zone /
start_stop_tolerance / check_char / meas_thresh / min_identical_scanlines /
persistence / timeout / composite_code
```
本插件只用了 `timeout` —— 其余在没有实测需求前不暴露。

## 五、已知边界

| # | 项 | 说明 |
|---|---|---|
| 1 | **解码内容没有独立真值（除 EAN）** | 二维码内容无法人工读图确认，别处只能验"解出了内容 + 多种码制/多张图都稳定"。**要更强的内容真值，需另找独立解码器做交叉验证** —— 那是另一个课题，断言文件里没假装做了 |
| 2 | **一帧多码的顺序由 HALCON 内部决定** | `Codes[0]` 不保证是"某个特定工位"上的码。上级若要对应关系，需自己去核对内容（例如按前缀匹配），不能靠下标 |
| 3 | **未输出逐码码制** | 用一维 `auto` 时"每个码实际是什么码制"看不到（需 `get_bar_code_result(..., 'decoded_types')`）。配置里明确指定码制时无此问题 —— 而明确指定本就更快，所以我建议别用 `auto` |
| 4 | **上级裁剪要留余量** | HALCON 文档明确：图带 `reduce_domain` 时搜索缩到该域，**码没完全落在域内可能找不到**（极少数情况还会在域外找到）。贴边裁会漏读 |
| 5 | **`auto` 会明显变慢** | 一维 `auto` 让 HALCON 在内部逐个码制试。码制固定时应明确指定 —— 这条写进了配置界面的码制提示文字 |
| 6 | **`Polarity` 配置在一维下无意义** | 配置项仍在（属于二维），切到一维时界面会隐藏它，但值会留在存盘配置里不生效。属良性冗余，未做清理 |
| 7 | **未做 `rectangle2` 快路径** | 若将来测出"一维码位置朝向固定 + 节拍不够"，可另开。那时是有数据支撑的优化 |
| 8 | **`Codes[0]` 这种写法在画布上未必给得出** | 编译器支持（`IsLinkable` 对 `ArrayIndexProxyPort` 放行），但没找到生成 `端口名[下标]` 的 UI 入口。所以标量下游请用 `Text`（逗号串） |
| 9 | **`PluginTestRunner.cs` 由并行任务在改** | 我上一批活改过它的 `AddBlueprintsDeep`；并行任务正在给它加 `Run` 重载。**两边都在改同一个文件**，需注意 |
