# 化工装置多画面 Web 运行态夹具（M3 复杂档真实负载）

> 日期：2026-10-21
> 起因：M3 的暴力测试此前只有**合成负载**（`Web\ScadaWebStress` 按参数批量造 N 页 × M 图元 × K 绑定）。
> 合成负载能压到 1000 图元，却压不出"一页里二十种图元、有跨页基座、有真实量纲的模拟量"这类现场形状。
> 本轮补一套**真实画面**的夹具，并顺手补齐了化工画面必需、但 Web 端一直是占位盒的 7 个渲染器。

## 2. 补齐的 7 个 Web 渲染器

**改动前实测**：`BuiltInElements.All` 28 条，Web 端只注册 13 个渲染器。
缺的 15 条里，`Hmi.Pipe` / `Hmi.Pump` / `Hmi.Motor` / `Hmi.Ellipse` 是化工工艺图的**骨架**——
没有它们，"化工界面"就是一屏虚线占位盒，压测也就失去意义。

本轮补齐（全部落在 `elements-process.js`，与既有 5 个工艺渲染器同一文件、同一契约）：

| TypeKey | 与桌面的几何口径 |
| --- | --- |
| `Hmi.Pump` | 泵壳 = 可画区内接圆；叶轮 = 半径 ×0.62 的内接等边三角形，0° 顶点朝右；底下 25% 让给位号 |
| `Hmi.Motor` | 机身圆 + 顶部接线盒（宽 0.5×直径、下沿探入 0.12×直径）+ 折线字母 M（笔画 0.18×半径） |
| `Hmi.Pipe` | 管身圆角矩形（内缩 半线宽+1）；箭头数 = `clamp(round(宽/(短边×1.8)), 1, 6)`；箭头笔画 0.10×短边 |
| `Hmi.Ellipse` | `border-radius:50%`（等价 `EllipseGeometry`），文字居中压圆 |
| `Hmi.Clock` | 纯客户端定时器；`Format` 认 `yyyy/MM/dd/HH/mm/ss`；**切页时 `scada:teardown` 停表** |
| `Hmi.KpiBoard` | 2~4 格网格；`Columns` 夹在 2~4（与桌面 `EffectiveColumns` 同口径）；空槽整格收起 |
| `Hmi.AlarmBanner` | 读 `ctx.getAlarms()`（服务端 2s 一拍的 `alarms` 快照）；**只有"严重且未确认"才闪** |

渲染器覆盖：**13 → 20**（28 条注册项中）。仍缺 5 条，见 §5。

**状态色口径**（三个设备图元共用）：`State` 认 `Stopped/Running/Fault` 与整数 `0/1/2`，
**认不出的值一律收敛到"停止"**（与桌面 `StateVisualElement.PickStateColor` 的 default 分支一致）。

## 3. 三个真实的契约冲突（本轮实测发现）

### 3.1 `Navigate` 在 Web 侧根本不可能生效（镜像模式）

夹具第一版给每页摆了一排「去其它页」按钮（`ScadaActionType.Navigate`）。
实测点击后服务端审计写的是：

```
[审计] admin@127.0.0.1 导航-反应釜 R-1201 Web 操作/Pressed 跳过 全部动作被跳过（Navigate:mirror-mode）
```

`ScadaWebActionFilter.IsMirrorOnlyPageAction` 把 `Navigate` / `NavigateBack` **无条件剔除**——
Web 是"所有人看同一页"的镜像，切页是**现场动作**（桌面运行窗口那一次），不是某个浏览器的视图偏好。
**修法**：夹具不再摆切页按钮，改成"画面 N / 6"的索引文字带；切页由宿主侧
`ScadaRuntime.Navigate` 发起（`--auto-page` 轮播），Web 端在下一拍比较 `PageKey` 后收到整份 `page`。

### 3.2 Web 按钮发**两个**事件，只配 `Pressed` 会弹红条

`elements-interactive.js` 在 `pointerdown` 发 `Pressed`、`pointerup` 发 `Released`（与桌面画布一致）。
夹具只配 `Pressed` 时，每次点击都会收到：

```
[审计] ... 导航-反应釜 R-1201 Web 操作/Released 拒绝 图元「导航-反应釜 R-1201」没有为事件「Released」配置动作
```

屏幕上就是"点一下弹一条红色 toast"。**修法**：夹具里凡可点的按钮，`Pressed` 与 `Released`
配同一串动作（动作本身幂等）。这是**夹具侧**的正确写法，不是框架缺陷。

### 3.3 `SelectorSwitch` 的属性键是 `Value`，不是 `SelectedIndex`

夹具第一版按"下拉框"的习惯把旋钮绑到 `SelectedIndex`，点击档位时得到：

```
图元「回流模式」的「Value」没有启用全量模式，无法写入
```

桌面 `SelectorSwitchElement` 的档位号键是 `Value`（`[ScadaProperty(Key = "Value", DisplayName = "当前档位")]`），
Web 渲染器也按 `Value` 读写；`SelectedIndex` 是 `ComboBox` 的键。**两者不能互抄**。

同时修掉两处**语义错绑**（类型对得上、语义对不上，界面看不出来、跑起来才露）：

| 图元 | 原绑定 | 问题 | 改为 |
| --- | --- | --- | --- |
| 多档旋钮 ×4 | `FV-1103 进料调节阀`（0~100） | 拨档位会把阀门开度写成 0/1/2（几乎全关） | 专用 `MODE-*` 变量（0~2） |
| 操作备注输入域 | `SHIFT-01 班组`（只读展示串） | 输入备注必然失败 | 专用可写 `REMARK-0101 操作备注` |

## 4. 实测证据

### 4.1 逐页视觉验收（1920×1080，真实浏览器）

6 张画面全部渲染，**占位盒 0 个**（改动前工艺图元全是占位盒）：

| 画面 | 图元数 | 验收要点 |
| --- | --- | --- |
| 装置总览 | 38 | 4 罐体 + 4 管段 + 泵/电机 + 5 阀门 + 3 表盘 + KPI + 报警条 |
| 反应釜 R-1201 | 31 | 大罐体 + 搅拌电机 + 6 数值域 + 2 表盘 + 3 阀门 + 8 交互件 |
| 精馏塔 T-1401 | 27 | 三段塔体 + 三段上升蒸汽 + 2 表盘 + 2 阀门 + 回流泵 |
| 换热站 E-1301 | 28 | 3 台换热器 + 4 管段 + 2 阀门 + 2 表盘 + 状态灯 |
| 报警与趋势 | 21 | 报警条 + 4 格 KPI + 5 条限值棒图 + 6 设备状态灯 |
| 配方与联锁 | 26 | 8 数值域 + 2 旋钮 + 输入域 + 4 联锁灯 + 3 按钮 |

### 4.2 交互链路（浏览器点击 → 服务端审计）

```
[审计] admin@127.0.0.1 启动搅拌 Web 操作/Pressed  成功 hooks=1 actions=1 ok=1 skipped=0 failed=0
[审计] admin@127.0.0.1 启动搅拌 Web 操作/Released 成功 hooks=1 actions=1 ok=1 skipped=0 failed=0
[审计] admin@127.0.0.1 控制模式 Web 操作/输入 成功 property=Value 1 → 2
[审计] admin@127.0.0.1 操作备注 Web 操作/输入 成功 property=Value 接班检查完成 → 巡检完毕-1400
[审计] admin@127.0.0.1 报警     Web 操作/确认报警 成功 全部确认 1 条
```

双角色（`HighestRoleOnly`）：管理员 + 操作员同时在线时，操作员的按钮
`aria-disabled="true"` + `is-disabled`，逐图元 caps 正确降级。
顶栏 chip 仍显示"可操作"——那是**会话级**只读，其 title 已写明
"每个图元仍按服务端权限单独判定"，属既定设计而非缺陷。

### 4.3 压测（`--stress`，真实 WS 客户端，镜像切页）

命令突发（每客户端背靠背 10~20 条 `cmd.element`），宿主按 1200ms 轮播 6 页。

| 档位 | 连接 | 命令 | page 帧 | 错误 | p50 / p95 / max | 工作集 | 日志 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 10 × 10 | 10/10 | 100/100 ack | 20 | **0** | 1 / 54 / 56ms | 98MB | `_chem_final_10x10.log` |
| 30 × 10 | 30/30 | 300/300 ack | 60 | **0** | 24 / 81 / 91ms | 120MB | `_chem_final_30x10.log` |
| 50 × 10 | 50/50 | 500/500 ack | 100 | **0** | 15 / 126 / 361ms | 122MB | `_chem_final_50x10.log` |
| 100 × 10 | 100/100 | 1000/1000 ack | 200 | **0** | 34 / **786** / 3125ms | 143MB | `_chem_final_100x10.log` |
| 100 × 20 | 100/100 | 2000/2000 ack | 200 | **0** | 48 / 334 / 4270ms | 143MB | `_chem_final_100x20.log` |

**结论口径**：

- **≤50 客户端稳定达标**（p95 ≤ 126ms，远低于 M8 的 500ms 门槛）；
- **100 客户端不达标且不稳定**：本轮 6 次 100 客户端运行 p95 = 63 / 334 / 432 / 597 / 686 / 786ms，
  只有 2 次低于 500ms。原因与此前复杂档一致——命令泵**按设计单写者串行**（保最终状态一致），
  100 客户端同时突发时队列积压。**不写"M3 达标"**。
- 所有档位 **0 错误、ack 100%**、切页帧数符合预期（每轮切页 1 条 `page`）。
- 快照 21KB/客户端（6 页平均，含基座）；100 客户端合计 2.1MB，与合成档 1000 图元页的 144KB 相比小得多——
  真实画面不是"图元越多越好"，而是**每页几十个图元**就够表达一个工段。

## 5. 仍缺的 5 个渲染器（如实记录）

`Hmi.ImageView` / `Hmi.DataGrid` / `Hmi.AxisPanel` / `Hmi.AxisConsole` / `Hmi.AxisPointTable`
**仍然没有 Web 渲染器**，落到中性占位盒。原因不是遗漏：

| TypeKey | 缺的机制 |
| --- | --- |
| `Hmi.ImageView` | 需要 `/img` 通道 + `imageToken` 轮换 + 带宽/编码策略（矩阵 B32、D31，M1.5 独立 spike） |
| `Hmi.DataGrid` | 需要列定义 JSON 解析 + 1000 行虚拟化（矩阵 D16、W3-02） |
| 轴三件套 | 需要 `IScadaAxisSource` 快照 + 运动命令通道（矩阵 D15、W3-03） |

这三组都是"需要新协议通道"的能力，不是"补一段渲染代码"能解决的。
本轮夹具**刻意不使用**它们——占位盒在化工画面上会显得像渲染 bug，而这几件确实还没交付。

## 6. 复现命令

```powershell
# 编译
dotnet build Web\ScadaWebChemicalDemo\ScadaWebChemicalDemo.csproj -c Release -m:1 -p:UseSharedCompilation=false

# 交互演示（浏览器打开 http://127.0.0.1:8899/，admin/admin123 或 op/op123）
ScadaWebChemicalDemo.exe --port 8899 --auto-page 12000

# 停在指定页（截图/断言用）
ScadaWebChemicalDemo.exe --port 8899 --start-page 精馏塔

# 暴力测试
ScadaWebChemicalDemo.exe --stress --clients 50 --commands 10 --page-ms 1200 --holdMs 4000

# 压测套件（10/30/50/100 × 10，100 × 20）
powershell -ExecutionPolicy Bypass -File tools\_chem_stress_suite.ps1
```
