## 六、踩过的坑

- **"绿块"差点被当成图元**：设计网格画在页面底色之上、元素层之下（`PART_Surface` 里的三层顺序），所以"底色透出网格"只有一种解释——那块绿是页面本身。判据别靠肉眼：取样内部色 + 四周工作台色（`#E9EEF5`）就能一眼定性。
- **PowerShell 5.1 里 `System.Drawing` 可用来裁图/取样**（`Pillow` 装不上、pip 拉 7MB wheel 超时），脚本必须纯 ASCII（R1）；一次性脚本本轮用完即删（R166）。
- 工作区里的 `.vms`（含 Autosave）**没有这次的画面数据**（`Scada.Pages` 与 `Scada.BasePages` 都为空），所以取证只能靠截图取样，不能靠读盘文档——现场未存盘时先看截图，别在磁盘上白找。

## 七、设计取舍（用户提出「加提示 / 让空基座也进图层」后的评估，同日追加）

用户两条提案：① 加提示；② 改成「没图元也进图层、默认覆盖在页面上」。评估如下（**结论：做提示，不做底色自动合成，另加一条"插入公共底板矩形"命令**）。

### 7.1 方案对比

| 方案 | 做法 | 判据 | 结论 |
|---|---|---|---|
| A 提示 | 空基座在候选里标「无图元」；基座页自身常驻一句"只有图元会被合成" | 零行为变更、零存量风险 | **做**（低成本、正好治这次误解） |
| B 底色自动合成 | 基座页的 `Background`/尺寸也进合成，覆盖在引用页上 | 见 7.2 三条硬伤 | **不做** |
| C 一键公共底板 | 命令：在基座上按引用页尺寸插入一个置底的矩形图元 | 它是"内容"，走既有合成路径 | **做**（想要"公共皮肤"时用这个） |

### 7.2 为什么不做 B（三条硬伤）

1. **默认值污染**：`ScadaPage` 的 `_background` 默认就是 `#FF1E1E1E`（`Scada/Models/ScadaPage.cs:25`），且无条件序列化。一旦基座底色参与合成，**所有存量文档里"从没设过底色"的基座都会以深色盖住引用页**——静默全局改外观，且无法区分"用户要的底色"与"默认值"。截图里 `画面_1` 的 `#1E1E1E` 就是这个默认值。
2. **多基座谁压谁**：`BasePages` 已支持 N 只按顺序叠（`ScadaCanvas.EnumerateItems` 产出顺序 + `ResolveLayerZOffset` 分层）。每只都带底色时，最上面那只静默吃掉下面所有基座与本页的底色——正是 `2026-10-18` 设计记录 §五 刻意规避的取舍。
3. **尺寸语义分叉**：基座页尺寸与本页不一致时，"覆盖"要么是"铺满本页"（那基座页尺寸彻底失去意义），要么是"只画基座页那一块"（页面上凭空多一块矩形）。两条都不干净；而"不缩放、按绝对坐标叠"是现行唯一自洽口径。
