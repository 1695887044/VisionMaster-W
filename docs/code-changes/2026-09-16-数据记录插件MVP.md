# 2026-09-16 数据记录插件 MVP（Plugin.DataRecord）

## 一、需求与决策

### 需求背景
流程跑完的结果（时间、序号、检测值、OK/NG）要按行落到 CSV 账本，可选同步保存 NG 图片；
产线节拍敏感，写盘绝不能占用流程执行线程。通信插件不做（通信变量已并入变量表）。

### 六条已批准共识（施工图依据）
1. **不做通信插件**——变量表 + NetworkVariableBridge 覆盖；长尾报文走 C#脚本+白名单。
2. **载体 CSV**：UTF-8 带 BOM（Excel 双击不乱码）、按天滚动 `{yyyy-MM-dd}.csv`、
   目录模板含 `{yyyy-MM}` 跨月自动建新目录；KeepDays 默认 0 = 永不清理（删追溯数据必须显式决定）。
3. **插件内静态 RecordingHub**（不动宿主）：生产者-消费者双队列。
   流程线程只做"组值 + 入队"（微秒级）；CSV 写线程批量落盘、图片写线程逐张低频落盘；
   多步骤实例共享同一静态 Hub（程序集只加载一次）；ProcessExit 尽力冲刷（3 秒预算）。
4. **写失败契约**：默认 Fail 阻断流程（宁停线不丢账），复选框可改为不阻断；
   目标被 Excel 占用 → IOException 退避重试 3 次 → 改写 `xxx_conflictN.csv` 旁路 + WARN（宁旁路不丢账）。
5. **图片双模式**：HImage 端口=存副本（CopyImage 深拷贝后落盘）/ string 端口=只记路径；
   时机默认仅 NG（NG 判定 = 结果列值 == NgValue）；存图失败不回改账本，只 WARN；
   账本靠 **图片路径内置列** 关联相册。
6. **全局序列号**：纯自增、Hub 静态维护、`DataRecord_seq.json` 边车（程序目录）每 50 号步进落盘，
   防重启撞图片名；图片命名模板 `{序号}_{结果}` 可引用任意列占位符。

### 实现期发现并修正的三个问题
- **`HImage.Reference` 属性在当前 halcondotnet 版本不存在**（CS1061，原设计靠引用计数保活）→
  改为仓库既有范式（`PreprocessHService.Clone`）：**CopyImage 深拷贝独立副本**，Hub 落盘后 Dispose。
  副本与上游生命周期彻底解耦——流程末尾基类释放上游端口值不影响落盘（冒烟 T7 专门验证）。
- **`BlockingCollection.Take(500)` 编译报错**：WPF 工程 `ImplicitUsings` 带 `System.Linq`，
  `bc.Take(int)` 无成员重载时被 `Enumerable.Take` 扩展方法截胡（CS0029）；而 `Take(int, CancellationToken)`
  在当前框架也不存在（CS1501）→ 最终用 **`TryTake(out x, 500, CancellationToken.None)`**（超时返回 false，
  队列 CompleteAdding 且空时抛 InvalidOperationException——与原 break 语义一致）。
- **冒烟抓出真 Bug：只取序号不入队的进程退出时边车不落盘**（重启序号回绕 1，图片必撞名）。
  根因：`NextSequence()` 没调 `EnsureStarted()`，ProcessExit 冲刷钩子未注册。
  修复：`NextSequence` 内部先 `EnsureStarted()`。

## 四、已知边界

- **宿主 UI 实跑未验证**：需在 VisionMaster 里拖一个"CSV记录"步骤连线实测（注册依赖 Display 四件套，已按 CSharpScript 范式）。
- 500ms 是**取队首的等待上限**，不是强制攒批窗口：首条到达即写，节拍快时自然合并——延迟只会更低，不会丢行。
- 动态列端口全部 `IsRequired=false`：FlowCompiler 只查连线不查值，**漏连线不报编译错**，执行时该列为空串（契约在运行期由列名提示用户自查）。
- 图片模式为"只记路径"（string 端口）时，路径指向的文件归用户自己管，KeepDays 不清理它。
- 序列号边车在**程序目录**：多开同一程序的多个进程会各自计数（当前宿主单实例，可接受）。
- Hub 日志靠插件执行时 `TakeLogs()` 转交宿主日志；没有任何步骤在执行时，日志暂存（超 2000 条丢最旧）。
- 断电场景：`FlushEveryRow=true` 可逐行落盘（牺牲节拍）；默认批量模式最多丢最后未冲刷的一窗。
- CSV 数值列的文化格式化在插件侧 `FormatCell`（InvariantCulture，冒烟在德语文化下跑模板展开未变形）；
  如需本地化显示，Excel 端自选列格式。

## 五、首次实跑反馈修正（同日）

用户把步骤拖进宿主后反馈两点：① 记录方式选了「每件存图」，却找不到「图片」端口可连；② 配置面板的下拉太丑。

### 「图片」端口看不到的根因（不是插件 Bug，是宿主画布的取端口口径）

画布节点的输入端口来自 `FlowCanvasViewModel.GetInputPorts(StepModel)`，普通算子分支只枚举 **`model.InputValues.Keys`**（图纸快照），而节点端口集合只在画布**整图重绘**时通过 `ConfigurePorts` 全量重挂——画布刻意不订阅步骤属性变更（避免与写回形成回环）。
于是：配置面板里改 `ImageSaveMode` 只动了**活插件实例**的 `Inputs`，`InputValues` 要等点「确认」（`OnConfirm` 把 `Inputs` 写回快照）后才可能有这个键，且能否立刻长出一个连接器还取决于宿主是否重绘。

**决策**：不去改宿主编排（改动面大、影响所有算子），改为**在配置面板内直接提供连线入口**——列定义表本来就能行内连线，图片同理。画布端口留给习惯在图上连线的用户（确认 + 重绘后仍可用）。

| 文件 | 动作 | 说明 |
|---|---|---|
| `Plugins\Plugin.DataRecord\DataRecordPlugin.cs` | 修改 | 新增 `ImagePortNameValue` 实例属性（`const` 不能当绑定路径），供视图 MultiBinding 解析图片端口 |
| `Plugins\Plugin.DataRecord\DataRecordView.xaml` | 修改 | 「图片记录」卡片新增**图片源**连线行：`LinkableValueEditor` + `InputPortConverter(ImagePortNameValue / PortsVersion)`，仅 `ImageSaveMode != Off` 时可见 |
| `Plugins\Plugin.DataRecord\DataRecordView.xaml.cs` | 修改 | 新增 `NotOffToVisibilityConverter`（`SourceToVisibilityConverter` 是等值匹配，语义相反故单开一个） |

### 下拉样式重写

原因：宿主 `UI` 程序集的隐式 `ComboBox` 模板（圆角、自绘箭头）放在本视图**外层**资源作用域时不生效（插件程序集资源与宿主主题合并时机），落回了 WPF 系统默认灰底模板；且宿主样式 `MinHeight=32` 与面板 24 高的行格冲突。

做法：插件视图内完整自绘，不依赖宿主主题。

| 样式键 | 内容 |
|---|---|
| `ModernComboBase` | 自绘 ControlTemplate：圆角 4 边框、悬停/展开变蓝 `#2196F3`、自绘三角箭头、Popup 带阴影 + `Fade` 动画、选中项通过 `SelectionBoxItem` 呈现 |
| `ModernComboItem` | 条目容器模板：圆角 3、悬停 `#F0F4F8`、选中 `#E3F0FB` + 文字 `#1565C0`（替换掉系统蓝色高亮模板） |
| `EnumCombo` | `BasedOn ModernComboBase` + `ItemTemplate`（枚举中文转换器）——来源/内置项/记录方式三处下拉共用 |
| `ModernFormatCombo` | `BasedOn ModernComboBase` + `ItemContainerStyle`，保留裸 `ComboBoxItem`（png/jpg/bmp）与 `SelectedValuePath=Content` |
