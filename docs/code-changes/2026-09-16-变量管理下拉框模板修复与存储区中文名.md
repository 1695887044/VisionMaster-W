# 变量管理下拉框模板修复 + 存储区中文名

日期：2026-09-16
范围：变量管理对话框（GlobalVariableView）UI 缺陷修复

## 一、需求与决策

用户反馈（附截图，红框标注"数据类型"下拉）：

1. "界面太丑了"
2. "这个下拉框数据模板不对，也没办法下拉" —— 框里显示 `VisionMaster.ViewModels.Dialog...`（类名），而不是中文名"整数 (int)"；点击无法展开列表。

排查后与用户确认本轮美化范围：**只修细节问题**（存储区下拉中文化 + 下拉控件本身修复），不重排布局、不做全应用 Design Token 改造。整体美化单独立项。

## 二、根因分析

### 缺陷 1：下拉点不开、选中项显示类名

`ModernCombo` 是本项目手写的 ComboBox 自定义模板（`GlobalVariableView.xaml`），原模板结构只有：

```
Border > Grid > ContentControl(SelectionBoxItem) + Path(箭头)
```

WPF 自定义 ComboBox 模板有三个必备件，原模板缺了两个半：

| 必备件 | 作用 | 原模板 |
| --- | --- | --- |
| 覆盖整框的 `ToggleButton`（ClickMode=Press，IsChecked ↔ IsDropDownOpen） | 点击热区 | **缺失** → 点框子没有任何反应 |
| `Popup` + `ItemsPresenter` | 下拉列表的宿主 | **缺失** → 列表无处渲染 |
| `ContentPresenter` 绑 SelectionBoxItem / SelectionBoxItemTemplate | 显示选中项 | 用了 `ContentControl` → **DisplayMemberPath 失效** |

第三点值得展开（**首轮修复不彻底，以下为复盘后的正确结论**）：`ComboBox.DisplayMemberPath` 的内部实现是在 ComboBox 内部创建一个 `DisplayMemberTemplate`。自定义模板的选中框靠 `SelectionBoxItemTemplate` 渲染，而框架只在 `ItemTemplate` **未被显式设置**时才把 `DisplayMemberTemplate` 赋给它；一旦 ComboBox 走了自定义模板/显式模板路径，`SelectionBoxItemTemplate` 拿到 null，绑定退回无模板渲染 → `ToString()`。因此结论是：

> **自定义 ComboBox 模板 + 需要成员显示名时，必须用显式 `ItemTemplate`（DataTemplate），`DisplayMemberPath` 不足以生效。**
> 附带一条：用 `ContentControl` 更是错上加错（它不参与 ComboBox 的 SelectionBoxItem 模板别名机制）。

### 缺陷 1b：可见外框与箭头画不出来

首版把可见边框画在 `ToggleButton` 的模板里，实际渲染时选中文字压住箭头、边框观感缺失。重构为三层分离：

1. `Border x:Name="Box"` —— 唯一负责可见外观（背景/圆角/边框），hover、展开、禁用态全部作用在它上面；
2. 透明 `ToggleButton` —— 纯点击热区，只画右侧箭头；
3. `ContentPresenter` —— 只显示选中项，`IsHitTestVisible=False` 让点击穿透。

另外修掉一个 Popup 经典坑：Popup 内部 `RelativeSource={RelativeSource TemplatedParent}` 会因 Popup 的视觉树断链而失效，"下拉宽度对齐框宽"改用 `{Binding ActualWidth, ElementName=Box}`。

### 缺陷 2：存储区下拉显示英文枚举名

`AreaOptions` 原本是 `ObservableCollection<Enum>`，直接装_enum 值，ComboBox 无 DisplayMemberPath → 显示 `HoldingRegisters`。对新手不友好，也不带方向/读写语义。

## 三、修改文件清单

### 1. `VisionMaster/Views/DialogViews/GlobalVariableView.xaml`

- 新增 `ComboItemStyle`（ComboBoxItem）：圆角 6、hover 浅蓝、选中加粗、`Padding=10,7`。
- 新增选项 `DataTemplate`：`DisplayNameTemplate`（绑 DisplayName）、`ConnectionOptionTemplate`（连接名 + 灰色小号协议名）。
- 重写 `ModernCombo`（样式为文件内局部资源，共 3 处 ComboBox 使用，改动不外溢）：三层模板（Box 外观 / 透明 ToggleButton 热区 / ContentPresenter 选中项，见缺陷 1b），Popup `Placement=Bottom`、Fade、圆角白底 + `DropShadowEffect(BlurRadius=14, Opacity=0.16)`，`MaxDropDownHeight=300`，禁用态灰底灰字。
- 三处 ComboBox 由 `DisplayMemberPath` 改为显式 `ItemTemplate`。

### 2. `VisionMaster/ViewModels/DialogViewModels/GlobalVariableManagerViewModel.cs`

- 新增 `AreaOption { Enum Value; string DisplayName; }` 包装类型 —— 界面显示与数据取值解耦（显示中文，落库/构造地址仍用原始枚举）。
- `AreaOptions` 类型 `ObservableCollection<Enum>` → `ObservableCollection<AreaOption>`；`SelectedAreaType` 同步改为 `AreaOption?`。
- 新增 `AreaDisplayNames` 静态字典：线圈 (0x, 读写布尔) / 离散输入 (1x, 只读布尔) / 输入寄存器 (3x, 只读字) / 保持寄存器 (4x, 读写字) / 数据块 (DB) / 输入映像区 (I) / 输出映像区 (Q) / 内部标志位 (M) / V 区 (S7-200 Smart)。
- `RefreshAreaOptions()` 填充包装项，默认值改为按枚举查找对应包装项（Modbus→保持寄存器，S7→M）。
- 取值处 3 处适配：`IsCoilOrDiscrete` 用 `SelectedAreaType?.Value is ...`；`AddNetworkVariable` 里 `(ModbusArea)SelectedAreaType.Value`、`(S7Area)SelectedAreaType.Value`。

## 五、已知边界

1. `ModernCombo` / `ComboItemStyle` 是 **XAML 文件内局部资源**，其它对话框若各自有同类模板，仍可能存在同样的三要素缺失问题。若要统一，应把它们提到共享资源字典。
2. 本轮未处理"界面整体观感"：中栏表单布局、配色层次、按钮位置保持原样。存储区中文化的选项文案（如"V 区 (S7-200 Smart)"）待现场核对是否贴合实际机型命名。
3. `DataTypeOption.DisplayName` 仍为可变属性（`{ get; set; }`），未收窄为 `init`；仅影响风格一致性，无功能问题。
