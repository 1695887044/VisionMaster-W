- 日期：2026-09-15

## 一、需求与决策

| # | 需求 | 关键决策 |
|---|------|---------|
| 1 | "启动"与"循环启动"互锁，防误操作 | 扩展为完整互锁矩阵：运行中禁用"编译/启动/循环"，仅"停止"可用；未启动时"停止"置灰 |
| 2 | 实时状态显示（未启动/启动中/循环运行中） | 放底部状态栏左侧：指示灯 + 加粗文字；灰=未启动、橙=启动中、绿=循环运行中 |

| 5 | （追加）运行中禁止编辑流程 | 纳入同一互锁：事件总线广播状态，流程栏 VM 单点拦截编辑动作 |

| 单次运行中 | ❌ | ❌ | ❌ | ✅ |
| 循环运行中 | ❌ | ❌ |  | ✅ |

## 二、架构设计

```
ShellViewModel.RunState（唯一事实来源，MainRunState 枚举）
 ├─► ExecutionCommand.CanExecute ──► RaiseCanExecuteChanged() ──► 按钮自动置灰（互锁）
 ├─► RunStateText / RunStateBrush ──► 底部状态栏绑定（状态显示）
 └─► GlobalEventBus.Publish(MainRunState)
          └─► ProcessViewModel 订阅，镜像 _runState
                   ├─► ModuleActionAsync 入口守卫（双击/右键菜单 编辑拦截）
                   └─► Drop() 入口守卫（拖入/排序 拦截）
```

运行结束如何自动解锁：启动时收集 `RunSession(Once)Async` 返回的 Task，
`Task.WhenAll` 完成（单次跑完 / 循环被停止取消）后把 `RunState` 复位为 `NotStarted`。
`await` 续体自动回 UI 线程，无需 Dispatcher。

## 六、追加：运行中禁止新建/打开/切换方案（同日）

### 需求与决策

原"已知边界"第 2 条闭环。切换/新建/打开方案都会重建 Workspace 并注册**同名新会话**——`RuntimeManager.RegisterSession` 会静默停掉运行中的旧会话，属于"边跑边拆台"，纳入互锁。

**规则**：`Save` 永远可用（只读导出无副作用）；`Create / Open / BrowseList` 运行中禁用。

### 修改（仅 VisionMaster\ShellViewModel.cs，View 零改动）

| 位置 | 改动 |
|---|---|
| `RunState` setter | 追加 `SolutionCommand?.RaiseCanExecuteChanged()`——状态一变，方案菜单/按钮置灰状态自动刷新 |
| 构造函数 | `SolutionCommand = new(ExecuteProjectAction, CanExecuteSolution)` 挂上 CanExecute |
| 新增 `CanExecuteSolution` | `action == Save \|\| RunState == NotStarted` |
| `ExecuteProjectAction` 顶部 | 防御纵深：`!CanExecuteSolution(action)` → 弹警告"流程运行中，禁止新建/打开/切换方案"并返回（兜住快捷键等旁路） |

置灰视觉自动生效：工具栏按钮用 `TitleButton`（第二节已补禁用触发器），`MenuItem` 用 WPF 原生禁用样式。

### 验证与测试

- 编译通过、GetDiagnostics 无错误。
- 实测：循环启动 → 左上"新建/打开/浏览"按钮与文件菜单项全部变灰，"保存"仍可点；点停止 → 恢复；运行中通过任何旁路触发 → 弹警告。
