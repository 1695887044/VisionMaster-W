# 图像变量所有权：写入即拷贝 + 延迟一代释放

- 日期：2026-10-24
- 触发：全插件 GStack 审查（`docs/交接报告-2026-10-24-全插件GStack审查.md` §3.3–§3.6）
- 结论：缺陷成立，定性 P1；本条落地的是**变量侧的收口修法**，不是给某个插件打补丁

## 一、缺陷原貌（修复前）

三条写全局变量的路径都把**上游端口上的 HImage 对象本身**交给变量：

| 写路径 | 关键行 | 行为 |
| --- | --- | --- |
| `Plugin.ImageAssign\ImageAssignPlugin.cs` | `:47` `InputImage.GetTypedValue()` → `:68` `writer.TryWrite(...)` | 拿到上游端口上的那个对象，原样写 |
| `Plugin.Utility\VariableAssignmentPlugin.cs` | `:35` `InputPort<object> Value` → `:347` `writer.TryWrite(...)` | 同上（`CanBindTo` 对 `object` 双向放行，`PortBindChecks` 已钉住 HImage→object 可绑） |
| `Plugin.CSharpScript\ScriptSharedAccessor.cs` | `:75` `Set(alias, value)` → `:86` `_store.TryWrite(...)` | 同上；`_store` 就是 `GlobalVariableWriter` |

三条路都汇到 `GlobalVariableWriter.WriteResolved`（`Core\Binding\GlobalVariableWriter.cs:120`）
→ `IWritableVariable.TryWrite` → `LocalVariableModel.TryWrite`，而旧实现是 `Value = value`（存引用）。

后果：`VisionPluginBase.DisposePreviousRoundOutputs`（`Shard\Core.Interfaces\VisionPluginBase.cs:175`）
在上游下一轮开始时释放那个对象，变量里只剩死句柄：

- Web 运行态 `/img`（`Web\VisionMaster.ScadaWeb\ScadaWebHost.cs:1500` 按需读、1fps/元素）
  → `HalconImageHelper.ToBitmapSource` 吞异常返回 null（`Core\Helpers\HalconImageHelper.cs:54-61`）
  → `404 E_IMG_EMPTY「该图元当前没有图像」`。
- 桌面组态看不到：`ScadaRuntimeBinder` 只在 `ValueChanged` 时读值（`:315-333`），
  而释放动作不发事件，下一轮写入事件一响就读到新图 —— 这解释了它为什么长期没被发现。

**不可见窗口 = 上游从"轮首 dispose"到"算完产出新图"的整段时间**，即上游算法耗时占节拍的比例。

## 二、修法（四件事）

### 1) 写入即拷贝（`Core\Models\Variable\LocalVariableModel.cs`）

`TryWrite` 对 `HImage` 走 `TryWriteImage`：`IsInitialized()` 守门 → `CopyImage()` → 换代。
拷贝失败按写入失败返回（带变量名原因），**不静默退回存引用**。

### 2) 延迟一代释放（同上）

`_retiredImage` 槽：写第 N+1 张时释放第 N-1 张，而不是当场释放。

为什么不当场释放：读图不一定在写入线程上——桌面端 `ScadaRuntimeBinder.OnValueChanged`
是在 `Value` setter 里**同步**触发的，所以"转换"与"释放"天然串行（同一线程）；
但 Web `/img` 经 `RunOnUiAsync` 上 UI 线程按需读，当场 Dispose 会与"正在转换的那张"撞车
（`ImagePreviewCapture.cs:8-15` 记过的 #4060 / 静默丢弃那一类）。
晚一代释放让任何读者抓到的图至少还活一整轮，且**不需要锁、不需要线程封送**。
峰值内存 = 当前副本 + 退役副本 = 2 张。

### 3) 所有权判定只看"是不是我拷的"

新增字段 `_ownedImage` 只记本变量自己拷出来的那份。绕过写入正门直接 `Value = 借用图` 时它是 null，
`ReleaseValues()` 因此**不会误杀别人的图**（断言 `[IV15]` 钉住）。

### 4) 释放口与调用方

- 新接口 `IVariableValueOwner`（`Core\Models\Variable\IVariable.cs`，与 `IWritableVariable` /
  `IValueChangeNotifier` 同一范式——**不加进 `IVariable`**，避免所有实现者（含断言桩）被迫实现）。
- 唯一落点 `VariableValueOwner.Release(IVariable?)`：判型 + 吞异常。
- 调用方（`Core\Binding\VariableRegistry.cs`）：
  - `Remove` → 移出集合的变量当场释放（`[IV12]`/`[IV13]`）；
  - `Reset`（= `Clear()`）→ 释放旧索引里的用户变量（`[IV14]`）；方案重载走
    `VariablePersistenceService.Restore` 的 `GlobalVariables.Clear()`，因此也被覆盖；
  - **集合实例整体替换（`GlobalVariables` setter → `Attach` → `Rebuild`）刻意不释放**：
    那条路上旧变量可能被搬到新集合里继续用。
- `ResetToDefault` 释放自己那份，**绝不碰 `DefaultValue`**（新建 HImage 变量时
  `TryGetNewInitialValue` 会 `Activator.CreateInstance(typeof(HImage))`，`DefaultValue` 与 `Value`
  是同一个空图实例）。

### 为什么不放在插件里、也不放在 `GlobalVariableWriter`

- 插件里拷 → 每轮拷两次（插件一次、变量一次）。
- 放 `WriteResolved` → 盖不住 SCADA 写入：`RegistryScadaValueSource.VariableHandle.TryWrite`
  （`Core\Binding\ScadaValueSource.cs:284-294`）直接调 `IWritableVariable.TryWrite`，**绕过写入器**。
  变量边界才是真收口。

## 三、断言（`FlowCanvasChecks\ImageVariableOwnershipChecks.cs`，18 条）

注册在 `Program.cs` 的 `VariableAssignmentCheck.Run()` 之后。分组：

| 组 | 断言 | 钉住什么 |
| --- | --- | --- |
| 写入即拷贝 | `[IV1]`~`[IV5]` | 存的是副本；源图释放后副本仍可读像素；`ToBitmapSource` 仍出位图 |
| 延迟一代 | `[IV6]`~`[IV8]` | 第二次写入后第一份仍活、第三次写入后才释放、只淘汰一代 |
| 反向 | `[IV9]`、`[IV15]` | 非 HImage 写入保持引用；直接赋值进来的借用图不被释放 |
| 复位 | `[IV10]`、`[IV11]` | `ResetToDefault` 释放自己那份、不释放 `DefaultValue` |
| 释放口有人调 | `[IV12]`~`[IV14]` | 移出集合 / `Clear()` 都释放，且当前值置空 |
| 守门 | `[IV16]` | 空句柄图像拒绝写入并给原因 |
| 端到端 | `[IV17]`、`[IV18]` | 真插件（变量赋值，作用域=全局）写图像变量：存的是副本、源图释放后仍可用 |

## 四、代价与边界

- **每轮一次全图拷贝**：500 万彩色 ≈ 15MB/轮；10fps ≈ 150MB/s。桌面端每轮本就有一份同量级的
  BitmapSource 转换，等于图像带宽翻倍，不是数量级恶化。若现场 ≥20fps 连续采图再谈优化。
- **跨线程**：退役槽的交换有 `_imageGate` 保护；拷贝与事件都在锁外。多线程并发写同一变量时
  以最后写入者为准（与既有 `Value` setter 的并发语义一致，未新增承诺）。
- **订阅方抛异常时**（例如退出途中 Dispatcher 已关、`BeginInvoke` 抛 `InvalidOperationException`）：
  异常照旧从 `Value` setter 冒出（与修复前同一条路径，插件层 `Execute` 会转成失败），
  代价是退役的那一张图这一轮没被释放。属既有异常语义，未为此新增 try/catch。
- **并行流程**同时写同一图像变量：各自克隆、最后写入者赢；退役槽只保留一份，
  不会漏释放，但峰值可能多一张。
- **未跑真机 Web**：断言覆盖到"取值出口能转出位图"，没有起真 `VisionMaster.exe` + 浏览器做
  1fps 取图端到端（需要真机环境，见 R175/R176）。
