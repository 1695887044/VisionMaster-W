## 一、逐项改动（5 件）

### 1. 触发入口"假成功"族收口（P0-1）
| 面 | 改法 |
| --- | --- |
| HTTP 抢不到会话锁被读成"跑完" | `HttpImageServer` 改调 **`TryRunSessionOnceAsync`**；返回 false → **409**（"被其它执行占用，本次请求未受理"），并 `ImageHub.TryRemove(本帧)` 把**自己那一帧精确收回**（不整槽清——槽里可能有别人推的图） |
| 跑挂了也回 200 | 执行后校验 `session.State == SessionState.Faulted` → **500**（原先那条 500 分支其实是死代码：引擎把异常吞进 Faulted 后正常返回） |
| 补编译会杀掉在跑的会话 | `HandleFlowPost` 与 `TryBuildSession` **两处**判"同名会话在跑 → 409，绝不替换"（`RegisterSession` 会先停掉同名运行会话最长 3s） |
| 启动准备期会话被并发释放仍报"跑过" | `TryRunSessionOnceAsync` 增 `catch (ObjectDisposedException)` → Warn + **return false**；连续运行同款 catch（不置 Faulted——这不是流程的错） |
| 界面侧同样丢 bool | `ShellViewModel`（运行全部-单次）改用 Try 并新增 `TrackStartRejectedAsync`（false → 如实提示"未启动"）；连续运行取"调用后 `IsRunning` 快照"判是否真起来；`FlowListViewModel` 的 `TrackSingleRunAsync` 改 Task&lt;bool&gt; 并提示 |
| 陈旧帧被下一轮取走 | `RuntimeManager.RegisterSession`（会话重建）与 `WorkspaceContext.SwitchSolution`（切方案）各补一次 **`ImageHub.Clear/ClearAll`**；`ImageHub` 新增 **`TryRemove(requestId)`**（逐项搬移+命中丢弃，保序不误伤） |

### 2. 绑定弹窗直改字典 → 走会通知的 API（P0-2）
`VariableBindingViewModel` 三处（解绑 `:63`、连线 `DoFinalBind`、常量 `Confirm`）由
`LinkedSources[...] = / .Remove(...)` 改为 **`StepModel.SetLink/RemoveLink`**——
版本递增唯一来自步骤 `PropertyChanged`，直改字典 = 已编译会话继续跑旧连线。

### 3. C# 脚本：原生 DLL 不得进元数据引用集（P1-1，**已重建插件**）
`CSharpScriptEngine.AddAssembly` 增加 `IsManagedAssembly(path)`（`AssemblyName.GetAssemblyName` +
全异常兜底）——宿主目录里的 `onnxruntime*.dll`（Yolo 插件的正常部署产物）此前被当托管元数据引用，
`CreateFromFile` 不抛异常、失败推迟到 Compile 报 **CS0009**，于是"任何构建过 Yolo 的宿主里 C# 脚本必然不可用"。
按红线③重建 `Plugin.CSharpScript` 并投递 `Modules\`。

### 4. 退出链真的可超时 + 相机模块退出序（P1-7）
- `AppLifetimeService`：`Task.Run(task.Execute)`——同步 action 原先在 `await` 前**同步跑完**，
  `CancelAfter(task.TimeoutMs)` 与 30s 看门狗都插不进去；现在卡住的退出任务会被超时跳过（链不再挂死，草稿/日志照常落盘）。
- `CameraModule`：退出注册序对调（先注册"断开相机"、后注册"停止收图服务"），使逆序执行成为
  **先停收图、再断设备**（原先反了：收帧线程会用到已释放的设备句柄）。

### 5. 运行中"改名/删除流程"守卫 + 旧会话回收（P1-11）
`FlowListViewModel`：删除与改名都先判 `RunState != Stopped || 会话在跑` → 拒绝；
改名成功后把**旧名字下的会话**（没在跑）`UnregisterSession` 注销，避免"谁都不是"的孤儿会话常驻插件/HImage。
