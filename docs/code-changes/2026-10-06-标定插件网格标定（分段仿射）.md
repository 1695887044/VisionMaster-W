## 一、背景

仿射与透视都治不了镜头径向畸变（主文档 §1.2 三问）。现场口径是"先看残差形态再选升级路线"：残差呈"中心小、边缘大"时，本轮的 ②是**工程近似**（逐格仿射把畸变局部摊平），③（标定板内参）是正解、仍待实现（设计见另一篇）。

## 二、改动清单

### 2.1 契约

- `CalibrationKind.Mesh = 3`；`MeshNodes`（N·N·4：每节点 `[Row, Col, X, Y]`，行主序）+ `MeshSize`。
- `Matrix` 在网格模式**保持零（故意）**：未升级的消费者走 6 元矩阵（det=0）会明确失败——绝不允许把网格静默当单份仿射用（边缘区域会整体错位）。
- **新增 `CalibrationMesh`（契约程序集内的纯基元静态类）**：`IsUsable`（长度/有限性/两方向三角形非退化）、`TryMapPixelToXY`、`TryMapXYToPixel`、`TryLocalAffine`（局部雅可比）、`TryMeanMmPerPixel`。
  - 为什么放契约：生产端（标定）与消费端（坐标变换）必须用**同一份**三角化与重心插值规则——两处各写一遍迟早分叉，分叉 = 同一份标定算出两套坐标。本类无可变状态，不涉及"两份静态状态"红线。

### 2.2 标定插件

- 新模式「网格标定」（界面单选，与九点/透视共用同一张表；表格显隐含网格）。
- `CollectMeshNodes`：**要求 N×N 每行都填全**（空行/半填/NaN 分别给中文明文；行数与网格不一致时提示用「按网格重建」）；节点组装后走 `CalibrationMesh.IsUsable`（退化三角形在插件侧就点出来，与消费者同一套判据）。
- **质量口径（必须读懂，界面文案已写明）**：网格在节点处**精确通过**，残差恒 0、没有信息量——因此质量区的数字取"同一批点上**全局仿射基线**"的残差（畸变有多大、网格值不值得用的度量），逐行残差同样按基线回写（基线不可用时留空，不假装通过）。
- **不做残差闸门**：畸变场景下基线残差本就超阈值（这正是选网格的理由），闸门会自相矛盾；当量护栏照常生效（`CheckMmPerPixelRange`）。
- `MmPerPixel` = 各三角形 `sqrt(|det J|)`（两轴几何平均）的**中位数**：让"只吃当量"的下游（卡尺/Blob）也能用网格标定。
- 日志与状态栏：`ModeText` / 就绪文案区分网格（节点数 N/N²、口径注记）。

### 2.3 坐标变换插件（消费侧）

- `CheckCalibrationUsable` 增加 Mesh 分支（走 `CalibrationMesh.IsUsable`，失败文案附"请重新运行「标定」步骤"）。
- `TryMapPixelToMechanical` / `TryMapMechanicalToPixel`：网格走分段仿射（机械空间定位 + 重心插值），**网格外明确失败、不外推**；正反严格互逆（同一三角形内是同一个仿射）。
- 角度换算：网格与透视同走"局部雅可比"路径（`TryLocalAffine` 取所在三角形的 J）——仿射等价网格下与九点角度换算逐位一致。
- `CalibrationKindText` 增"网格（分段仿射）"；日志标注类型。

## 四、设计取舍（复查时先看这里）

1. **为什么不做双线性**：分段仿射可**解析求逆**（同一三角形内仿射可逆），反向映射与正向左逆，无需迭代；双线性需要解二次方程且边界处理更绕。现场用"格越密越准"控制误差，N 可调到 10。
2. **为什么残差不做 LOO（留一验证）**：网格是插值模型，去掉一个节点会破坏整格；"全局仿射基线"是**可解释、可复算**的畸变度量，且与"你本来该不该上网格"的判断同源。
3. **为什么网格外失败**：外推会产出"看着正常"的错坐标（与"绝不静默"纪律一致的唯一选择）。
4. **为什么两端共用契约里的实现**：见 2.1 的注释——分叉风险高于"契约只放数据"的洁癖；该类无状态、无 HALCON 依赖。
