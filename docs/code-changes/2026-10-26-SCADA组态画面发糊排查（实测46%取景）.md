# SCADA 组态画面发糊排查（真机实测：46% 取景）

> 日期：2026-10-26　类型：问题排查 + 真机实测（未改代码）
> 证据图：`artifacts\render\20261026\scada-fit46.png`（46%）、`scada-1to1.png`（100%）、`toolbar-zoom-4x.png`
> 本文**取代**同日 v1（`2026-10-26-SCADA组态画面发糊排查（缩放取景与DPI虚拟化）.md`）——v1 的 DPI 判断是错的，见 §5。

## 1. 当前状态

**主因确认：编辑器"适应窗口"把 1920×1080 的设计画面缩到 46%，不是 DPI、不是显卡、不是渲染后端。**

真机实测（`VisionMaster.exe` 06:20:40 启动，方案「智能装配检测线」→ 组态设计 → 画面「产线总览」）：

| 观察项 | 读数 |
|---|---|
| 左下角取景胶囊 | **46%**（1920 × 1080） |
| 点工具栏 `1:1` 后 | **100%**，同屏文字立刻锐利 |
| 窗口 DPI 感知 | `GetWindowDpiAwarenessContext` = **1 (SYSTEM_AWARE)** |
| 窗口 DPI / 屏幕 | `GetDpiForWindow` = **144（150%）**；屏幕 2048×1280 |
| UI 文字（属性面板） | 150% 下清晰，无位图拉伸迹象 |

换算（设计像素 → 屏幕物理像素，本机 150%）：

| 设计字号 | 46% 下 DIP | 46% 下物理 px | 100% 下物理 px |
|---|---|---|---|
| 11 px（多数标签） | 5.06 | 7.6 | 16.5 |
| 12 px | 5.52 | 8.3 | 18.0 |
| 13 px | 5.98 | 9.0 | 19.5 |
| 14 px | 6.44 | 9.7 | 21.0 |
| 1 px 边框/线条 | 0.46 | **0.69** | 1.5 |

中文在这个尺寸必然糊；1px 边框落在 0.69 个物理像素上，抗锯齿摊成两三个半透明像素——整幅画面发灰发虚就是这么来的。

## 2. 已做（实测取证）

1. 按 SOP（台账 §1.2）预检：无宿主在跑、端口 19000/19100/8080 空闲、`Layout.xml`/`DefaultLayout.xml` 备份到 `artifacts\backup\20261026-scada-blur\`。
2. 启动真 exe，关闭"未保存草稿"提示（点「稍后再说」，未打开草稿），切到 **组态设计**。
3. 截图 ①：46%（`scada-fit46.png`）——页面内 11~14px 标签全糊。
4. 点工具栏 `1:1`（先用 4 倍放大裁图量准按钮框，见台账 C-07），截图 ②：100%（`scada-1to1.png`）——同一段文字清晰可读。
5. 运行时 DPI 探测（`GetWindowDpiAwarenessContext` / `GetDpiForWindow` / `GetDpiForMonitor`）：窗口 SYSTEM_AWARE @144 DPI。
6. 静态排除：SCADA 侧无 `BitmapCache` / `BlurEffect` / `ProcessRenderMode`（唯一 `BitmapCache` 在 `FlowCanvasSurface.cs:149`）。
7. 代码链路复核（未变）：`ScadaEditorView.xaml.cs:179-196` 首次进页 `FitToScreen()` → `ScadaCanvas.cs:1047-1059` 算 `min((vw-48)/1920,(vh-48)/1080)` → `ScadaCanvas.cs:1265-1271` 写 `ScaleTransform`（`PART_Surface` 的 `RenderTransform`）。
8. 收工：`Layout.xml` 与备份哈希一致（未改）；`DefaultLayout.xml` 被本次启动重写，已按备份还原。

**顺带发现的独立缺陷（非本次引入）**：运行态每拍抛 2 条
`[ERR] [节拍] … 无法在对象"System.Windows.Media.TranslateTransform"上设置属性，因为它处于只读状态。`
——今天 00:09 用户自己跑运行态时就有，日志刷屏（约 5 条/秒），动画写入静默失败。属运行态动画缺陷，与"糊"无关，需单独修。

## 4. 下一步（若要"变清晰"）

1. **用户侧立即可做**：点 `1:1` 用实际大小编辑；或把画面设计尺寸改成接近编辑区的尺寸（1280×800 及以下），让"适应"倍率落在 80% 以上。
2. **产品侧（按代价排序）**：
   - 低缩放时给提示（`Zoom < 0.8` 时在取景胶囊旁标"文字会发虚"），或默认 1:1 打开；
   - 内置图元字号抬档（11/12 → 13/14）属设计基线变更，走 R125；
   - 运行态 `ScadaRuntimeWindow.xaml:11` 的 `TextFormattingMode="Display"` 改 `Ideal`（Display 只在 100% 整数缩放下锐利，配合缩放会发虚）——本次未验证，属待测。
3. **独立缺陷**：`TranslateTransform` 只读导致运行态动画每拍失败，单独立项修（找到冻结该变换的代码，改成不 Freeze 或改走 `SetCurrentValue`）。

## 5. 踩过的坑（含对 v1 结论的更正）

- **manifest 里没有 `dpiAware` ≠ 进程 DPI-unaware**：v1 只看内嵌 manifest 就判"DPI-unaware、整窗位图拉伸"，**实测推翻**——WPF 运行期把窗口设成 `SYSTEM_AWARE`，150% 下原生渲染、文字清晰。判据必须是 `GetWindowDpiAwarenessContext(hwnd)`，不能只看 manifest。
- **"系统级感知"的剩余风险**：跨到另一块不同 DPI 的显示器时不会重排（Windows 位图拉伸）。单屏 150% 场景不糊。
- **`SnapsToDevicePixels=True` 在缩放变换下失效**：它按变换前的局部坐标对齐像素，祖先挂 `RenderTransform` 后全部无效——这正是 46% 下边框发灰、而代码里"每个图元都设了 Snap"却救不回来的原因。
- **进程消失要区分"崩溃"和"被外部结束"**：崩溃有 WER 事件，优雅退出有 `[退出链]` 日志；两者都没有 + 同时段有构建在跑 = 被 `taskkill`/RestartManager 相关动作结束（台账 A-06）。
- **按截图坐标点按钮会点错邻居**：`适应` 与 `1:1` 在 46% 那张图里只隔约 20 px，第一次点到了 `适应`（倍率不变，看起来"点了没反应"）。正解：裁图 4 倍量准按钮框，或优先用 AX 元素（台账 C-07）。
