# 2026-10-08 Core.Halcon 审查整改第二批（死代码/图集菜单/瞬时提示/过滤器/涂抹性能）

## 一、起因

2026-10-07 对 `Services\Core.Halcon` 的只读审查（三个 P0 已当天修复，见《2026-10-08-Core.Halcon三处P0修复》）留下五组"未决问题"，用户拍板全部整改：死代码与依赖清理、图集默认模板无 UI 入口可达、TopText 提示永不清除且模板颜色不一致、"打开图片"过滤器承诺读不了的格式、涂抹笔画逐盖章全量并集的性能。

## 二、改动清单

### 1. 死代码删除（HalconBase.cs）
- 删 `Display(HObject)`：全仓零调用，且 `SetPart(0,0,-2,-2)` 语义可疑。
- 删 `DrawCheckerboardBackground(HWindow)`（60 行）：唯一调用是注释掉的实验代码（`OnApplyTemplate` 里那行注释一并删）。

### 2. 图集右键菜单补三个入口（ImageGallery.cs `EnsureContextMenu`）
- 新增菜单项：**钉住当前帧（对比基准）**（走 `OnPinClick`，顺手开对比模式）、**对比模式**（IsCheckable → `IsCompareMode`）、**锁定跟随**（IsCheckable → 反写 `AutoSelectNewest`）。
- 背景：默认模板刻意没有工具条（`PART_Pin`/`PART_Compare`/`PART_Lock` 不在模板里），此前 `PinnedFrame`/`IsCompareMode` 整套 API（含模板里的对比视图 + 分隔条布局）**没有任何 UI 入口能触达**。
- 菜单 `Opened` 时同步勾选态与置灰：`pin.IsEnabled = SelectedFrame != null`（无选中帧时"钉住"不可点）。
- `OnPinClick` 由 private 改 public（右键菜单与模板 PART_Pin 同一入口）。

### 3. TopText 瞬时提示（HalconBase.cs）
- 新增 `SetTransientTopText(message, autoClearSeconds=4)` + `DispatcherTimer`：右键菜单路径的全部失败/引导提示（打开图像失败/无图可保存/引擎不可用/请先加载图像）改为**写入后数秒自动清空**。
- **不误伤外部常驻文字**：清空条件是"到点时 TopText 仍是这条文案"（比较当前值），期间被外部改写则不清。
- 6 处提示调用点全部切换（`OpenImage`×2、`SaveImage`、`SaveWindowDump`、`CreateRoi`×2）。
- 模板颜色统一：`ImageEdit.xaml`/`ImageReadOnly.xaml` 的 TopText 前景色 Gray→**Red**（黑底灰字几乎不可见；与 ImageDisplay 一致，错误提示三控件同色）。

### 4. "打开图片"过滤器收缩（HalconBase.cs）
- 新常量 `SupportedImageFilter = bmp/png/jpg/jpeg/tif/tiff/gif/pcx/ico`——旧版把 dxf/cgm/cdr/wmf/eps/emf 也列进去，HALCON ReadImage 读不了，用户选了就报错。

### 5. 涂抹笔画批量并集（HalconBase.cs `ApplySmear`）
- 旧实现：每个盖章圆盘都 `Union2` 进**累计区域**——每次生成覆盖整个累计区域的新 HRegion，长笔画复杂度 O(盖章数×区域面积)，越画越卡。
- 新实现：本批 stamps 先并成一条笔画条带（条带内部并集只涉及这批圆盘），再一次并入工作副本——累计区域每批只拷贝一次。渲染 40ms 节流与收笔移交 DP 的语义不变。

### 6. 警示注释（HObjectExtension.cs）
- `GetImageSize(HObject)` / `ToHimage` 补"仅适用于灰度（单通道）图"注释：内部走 `GetImagePointer1`，对多通道只取通道 1。当前全仓仅 UIThemeSmokeTest 在用（灰度场景）。

### 7. csproj 两处
- `<InternalsVisibleTo Include="FlowCanvasChecks" />`：断言工程驱动 internal 测试辅助（`ImageGallery.EnsureContextMenuForTest` / `RaiseContextMenuOpenedForTest`），比反射稳（改菜单结构不用同步改断言）。注意是 **ItemGroup 里的 Include 元素**，写成 PropertyGroup 的 `<InternalsVisibleTo>` 属性不生效（实测）。
- **`System.Drawing.Common` 包引用保留**（原计划删除）：库内代码零使用，但 XAML 编译器（wpftmp 程序集）解析模板引用闭包时要经它把 halcondotnet 的老式 `System.Drawing v2.0.0.0` 引用解析掉——删掉后三个主题 XAML 全部 MC1000 构建失败（实测，注释已写进 csproj 防后人再清）。

## 三、断言（HalconControlChecks.cs 第二批，13 条新增，全绿）

- `[清理]` ×3：反射确认 `RePaint`/`Display`/`DrawCheckerboardBackground` 已从 HalconBase 删除。
- `[UX] 过滤器`：不含 dxf/cgm/cdr/wmf/eps/emf，含 bmp/png/jpg/tif/gif（读 `SupportedImageFilter` 常量验证）。
- `[UX] 瞬时提示` ×4：写入 TopText；外部常驻文字不误伤；timer 已启动（IsEnabled + Interval）；Tick 订阅在位。
- `[UX] 图集菜单` ×5：含钉住/对比/锁定；保留清空/导出×2；无选中帧时钉住置灰。

**断言工程的一个实测教训（DispatcherTimer 泵不出来）**：想让"到点自动清空"在断言里真跑起来，试了 `Dispatcher.Invoke` 空委托泵、`PushFrame` 循环、隐藏 Window + 消息循环三种驱动方式都失败——断言的 STA 工作线程没有 `Application.Run` 的完整消息循环，`DispatcherTimer` 的 WM_TIMER 派发不出来。这是**断言环境限制，不是产品缺陷**（产品进程的 UI 线程跑着完整消息循环）。断言契约退而锁机制面（timer 启动 + Interval + Tick 挂接）与语义面（文案保护），完整行为留给真机验收。
