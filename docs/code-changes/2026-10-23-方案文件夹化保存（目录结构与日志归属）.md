# 方案文件夹化保存（目录结构与日志归属）

日期：2026-10-23
范围：Core（方案路径约定 / 日志服务）、VisionMaster（保存与打开命令、菜单）、ScadaChecks（新断言组）

## 1. 背景与需求

原先“保存方案”让用户在 `SaveFileDialog` 里挑任意目录、任意文件名，落盘只有一个 `.vms`；
图片与报警历史靠“与 `.vms` 同目录的 `Image\` / `Alarms\`”跟着走。两个后果：

1. 方案 A 与方案 B 存进同一目录时**共用** `Image\` / `Alarms\`（旧文档已把“每个方案一个文件夹”写成约定，但代码不强制）；
2. 日志固定在 `<exe>\Logs`，与当前打开哪份方案无关；把方案目录拷给售后，日志得另外找。

本次把“一个方案 = 一个以方案命名的文件夹”落到代码里：保存时建文件夹，配置、图片、报警、日志都在里面；打开时按 `.vms` 所在目录解析全部资产。

## 2. 目录结构与命名规则

```
<保存位置>\方案A\
    方案A.vms                  ← 配置（既有 JSON 格式与字段完全不变）
    Image\                     ← 方案图片（.vms 内只存相对路径 Image\xxx.png）
    Alarms\                    ← AlarmHistory.json + AlarmHistory-yyyy-MM-dd.csv
    Logs\                      ← 方案级日志 yyyy-MM-dd.log（与全局日志双写）
```

命名规则（`Core\SolutionPaths.SanitizeName`）：

| 输入 | 结果 | 理由 |
|---|---|---|
| 正常方案名 | 原样 | 文件夹名 = 配置文件名 = 方案名 |
| 含 `\ / : * ? " < > \|` | 逐字符换 `_` | 非法文件名会抛异常或静默建出子目录 |
| 结尾的点/空白 | 去掉 | Windows 会静默吞掉结尾的点，界面与磁盘对不上 |
| 空 / 全空白 | `未命名方案` | 不能建一个没有名字的文件夹 |
| `CON` / `PRN` / `COM1` … | 前置 `_` | Windows 保留设备名不能作目录名 |
| 完整路径 > 240 字符 | 保存前拒绝并给中文原因 | 避免写盘阶段抛“路径过长” |

“一个文件夹只放一个方案”：目标文件夹里已有**另一个名字**的 `.vms` 时拒绝保存并说明；同名 `.vms` 是正常覆盖。

## 3. 保存 / 另存为 / 打开

- **保存**（`SolutionAction.Save`）：已符合 `<父>\<方案名>\<方案名>.vms` 的直接写回，不弹位置。
  不符合（从未保存 / 散装老方案 / 用户改过方案名）→ 自动走“另存为”。
- **另存为**（新增 `SolutionAction.SaveAs`，文件菜单）：选的是**父目录**（`OpenFolderDialog`），
  程序在其中建 `<方案名>\<方案名>.vms`；旧目录的 `Image` / `Alarms` / `Logs` 一起复制过去，已存在同名文件不覆盖。
- **打开**：仍选 `.vms`（`OpenFileDialog`），方案根 = `.vms` 所在目录。
  散装老方案照样能打开（读侧不强制文件夹）；第一次保存时会被搬进规范文件夹。
- 落盘顺序：Capture（布局/变量/通讯）→ 原子写 `.vms`（tmp + Replace/Move）→ `EnsureStructure` 建骨架 → 复制资产。
  配置写失败不会留下空方案文件夹；建目录失败只提示、不回滚保存。

## 4. 读取侧如何与文件夹对应

| 内容 | 解析口径 | 代码 |
|---|---|---|
| 方案根 | `Path.GetDirectoryName(SolutionFilePath)` 唯一出口 | `SolutionPaths.GetSolutionRoot` |
| 图片 | 方案根 + `.vms` 里的相对路径；绝对路径与 `..` 越界拒绝 | `SolutionAssetService.TryResolve/TryLoad` |
| 报警历史 | `<方案根>\Alarms\AlarmHistory.json` | `ScadaAlarmHistoryStore.ResolveDirectory` |
| 日志 | `<方案根>\Logs\yyyy-MM-dd.log`，与全局日志**双写** | `LogService.CurrentSolutionLogDirectory` |
| SCADA 运行窗口背景图 | 宿主注入 `SolutionRoot` | `ScadaRuntimeHost` / `ScadaEditorViewModel.SolutionRoot` |

日志双写的理由：全局那份是排障底稿（方案加载前的启动链、退出链、方案切换本身只在这里）；
方案那份随文件夹走（拷给售后不用另找）。两者解析到同一目录时只写一份。

方案根提供口是“现读”的静态钩子（`LogService.SolutionRootProvider`，宿主在 `App.RegisterTypes` 挂接），
不在新建/打开/列表/启动自动加载四个入口逐个推送——漏推一处就会把这份方案的日志写进上一份目录。

## 7. 已知偏差与边界

1. **审计 / 报警抓图 / 数据记录仍在软件目录**：`Audit`（`ScadaAuditWriter.DefaultDirectory`）、
   `AlarmFrames`（`ImageCollectionService`）、`DataRecord` 默认 `D:\Records\`。
   这三类有各自的保留期与清理策略，搬进方案文件夹要连带改清理口径，留给独立批次。
2. **散装老方案**：可打开、可运行；第一次保存会弹“另存为”让用户选位置并搬进文件夹，不静默迁移。
3. **多方案共用同一目录（历史数据）**：打开仍按 `.vms` 所在目录解析，`Image` / `Alarms` 仍是共享的；
   新保存不再产生这种布局。
4. **日志保留期只清全局目录**：方案 `Logs` 属于用户数据，不自动删；需要清理时由用户处理。
5. **另存为复制的是整个资产目录**：从共享目录另存为时，会把同目录其它方案引用的图片一起复制（超集，不丢图）。
