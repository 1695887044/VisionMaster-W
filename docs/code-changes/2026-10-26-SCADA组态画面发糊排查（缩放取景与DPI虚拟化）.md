# SCADA 组态画面"发糊"排查（缩放取景 + DPI 虚拟化）

> **⚠️ 本文 §1 第 2 条（DPI-unaware）已被真机实测推翻，不要再引用。**
> 实测：窗口是 `SYSTEM_AWARE` @144 DPI，DPI 不是主因；主因是"适应窗口"把画面缩到 46%。
> 现行结论见同目录 `2026-10-26-SCADA组态画面发糊排查（实测46%取景）.md`（保留本文仅作排查过程留档）。

> 日期：2026-10-26　类型：问题排查（未改代码）　结论来源：源码阅读 + 产物内嵌 manifest 实测

## 1. 当前状态

用户反馈"SCADA 组态画面很糊"。排查结论：**不是显卡/渲染后端问题，是两件独立的事叠在一起**。

1. **主因（结构性，必然发生）**：组态画布是 1920×1080 的设计画布，编辑器首次进入某一页会自动"适应窗口"，
   把整页按视口等比缩小到约 **50%~70%**，而缩放是给画面层挂 `ScaleTransform`（渲染期缩放，不是重排版），
   于是设计像素下的 11~14px 字号变成 6~10px、1px 边框变成 0.5~0.7 设备像素 → 抗锯齿摊成灰边 = "糊"。
2. **次因（缺陷，可修）**：`VisionMaster.exe` 内嵌 manifest 里**没有任何 dpiAware / dpiAwareness 声明**
   （实测解出 RT_MANIFEST，只有 requestedExecutionLevel）。进程是 DPI-unaware，
   在 125%/150% 显示缩放下整个窗口被 Windows 位图拉伸 → 全界面发虚，组态画面首当其冲。
3. **运行态额外一条**：`ScadaRuntimeWindow.xaml` 窗口级设了 `TextOptions.TextFormattingMode="Display"`，
   Display 只在 100% 整数缩放下锐利，配合 FitToScreen/Viewbox 缩放会明显发糊（编辑器没设，走默认 Ideal）。

## 4. 下一步（若用户要求"变清晰"）

按代价从低到高：

1. **确认归因**：让用户在组态页点顶栏 `1:1`（`ZoomToActualSize`）。立刻锐利 → 主因是缩放取景；
   1:1 仍糊 → 主因是 DPI 虚拟化。
2. **补 DPI 清单**（治次因，全局受益）：加 `app.manifest` 声明 `PerMonitorV2` 并挂到 `VisionMaster.csproj`
   的 `ApplicationManifest`。.NET 9 WPF 原生支持；风险点是 AvalonDock/HALCON 窗口句柄在跨屏 DPI 变化下的重排，
   需真机双屏验证（属 R12 大改动，走架构评审）。
3. **运行态改 `Ideal`**：`ScadaRuntimeWindow.xaml:11` 的 `TextFormattingMode` 从 `Display` 改成 `Ideal`
   （或干脆删掉），配合缩放显示更稳；代价是 100% 下小字略不如 Display 锐。
4. **取景口径**（可选，产品决策）：默认不做 FitToScreen，或对 zoom < 0.8 时提示"当前非 1:1，文字会发虚"；
   或把组态页设计尺寸降到 1280×720、把 11px 字号抬到 13~14px（属设计基线变更，R125 流程）。

## 5. 踩过的坑

- **`SnapsToDevicePixels=True` 不等于缩放后清晰**：它按变换前的局部坐标对齐像素，
  祖先挂了 `RenderTransform` 缩放后全部失效。看到"每个图元都设了 Snap"就以为不会糊，是误判。
- **`UseLayoutRounding` 同理**：它只管布局期取整，管不到渲染期的缩放变换；而且编辑器视图里根本没开。
- **WPF 进程 DPI 感知只看 manifest/API，不看 TFM**：`net9.0-windows` 不会自动给 DPI 声明，
  产物里没有 `<dpiAware>` 就是 unaware。判据必须解 RT_MANIFEST，不能凭"我用的是 .NET 9"推断。
- **`TextFormattingMode="Display"` 与缩放是反组合**：Display 为 96 DPI 整数网格做字形对齐，
  一旦外面套 Viewbox/缩放变换就发糊；可缩放场景应当用 `Ideal`。
