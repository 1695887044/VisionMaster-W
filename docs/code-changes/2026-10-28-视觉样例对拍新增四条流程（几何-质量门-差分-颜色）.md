## 3. 关键设计决定

### 3.0 角色口径：没有"主流程"，四条都勾「整线」

2026-10-28 用户裁决**删除「主流程」概念**（`docs\code-changes\2026-10-28-主流程角色退役（整线成员与线级来源）.md`）：
`FlowRole.Main = 2` 退役为保留位，生产主任务由 `FlowInvokeType.LineStart = 128` 这一个位表达，
骨架只剩 Home / End。按指南 §3.1/§3.2：

| 流程 | Role | InvokeType | 说明 |
|---|---|---|---|
| 七工位 + 四条扩展 | 0 | **160**（子程序 32 + 整线 128） | 点「启动整线」→ **11 条各起各的会话**，一条失败只收尾自己 |
| `Main`（整件串行） | 0 | **0**（手动） | 体内是「调用流程(七工位)」，见下 |
| `Home` / `End` | 1 / 3 | 0 | 骨架 |

**`Main` 为什么不勾整线**：它调用的正是那七条工位。若两者同时被整线启动，工位会话已被自己占住，
`FlowInvoker` 会回「流程「X」正在运行中（被其它执行占用），本次子程序调用未执行」，
统计脚本读到的是上一轮的旧值。所以「整线（11 工位各自跑）」与「整件（Main 串行调七工位 + 统计 + 账本）」
是**互斥的两条入口**；`Main` 现在是普通流程（Role=0）+ 手动，不再是角色。

> 这是本方案对"老文件 `Role: 2`"的处理：生成器显式写 `Role=0`，而不是留给
> `MandatoryFlows.MigrateRetiredRoles` 去迁移——迁移会顺带补上 128 位，正好踩上面那个冲突。

**线级 OK/NG 来源**（`SolutionModel.LineVerdictFlowId`）留空 = 产品默认"第一条勾整线的启用流程"
（当前是 `模板匹配_NCC散焦图`）。串联线不跨站求和，11 条平级工位本来就没有"线级"这一个数，
所以不硬指一条冒充。

### 3.1 几何计算为什么要 ROI

`GeometryFinder` 只拟合**最长轮廓**（`GeometryHService.LongestContour`），不做形状筛选；
同一张图上跑两次必然拟合到同一条轮廓。所以用「ROI」插件切两个矩形（横条 / 竖条），
取它的 **`Domain_xxx` 输出**（带 domain 的原图，**全局坐标不变**）而不是 `Crop_xxx`
（裁剪图原点搬走，下游坐标全变本地坐标）。

`RoiParams`/`RoiList` 是 `[StepConfig]`，`ApplyConfigValues` 走 `ValueConverter` 的
`token.ToObject(targetType)` 分支还原 `ObservableCollection<RoiItem>`；动态端口名
（`Crop_` / `Domain_` / `OffsetRow_` / `OffsetCol_`）按 R18 同步写进 `OutputPortDefinitions`。

### 3.2 几何计算的公差是幅值，不是带符号

`Judge()` 是 `value >= std - lo && value <= std + up`，所以 ±1° 要写
`LowerTolerance = 1`、`UpperTolerance = 1`（写 `-1` 会得到 `[91, 91]` 这个退化区间）。

### 3.3 If 的连线键是局部变量 Id

`ConditionStep.LocalVariables` 里声明 `{Id, Name, DataTypeName}`，
`LinkedSources` 的**键必须是那个 Id 的字符串**（`FlowCompiler.HasLinkedSource` 与
`CompiledIfNode.UpstreamLinks` 都按 Guid 解析），表达式里用的是变量名（本例 `Usable`）。

### 3.4 差分阈值是实测出来的，不是拍的

用 `System.Drawing` 逐像元算 |灰度差|>30 的像元数（与插件同口径）：

| 对比 | 超阈像元 | 占全图 |
|---|---|---|
| 060 vs 061（相邻帧） | **2** | 0.00% |
| 060 vs 001（散焦帧） | **101,047** | 27.99% |

阈值取 2000 px：合格件余量 1000 倍，不合格件超出 50 倍。

### 3.5 质量门的 FocusRef/FocusMin 是按实测梯度定的

`FocusRaw` = sobel_amp('sum_abs') 均值。用同样的 Sobel 核离线测三帧：
060（最清晰）= **65.7**、001 = 21.1、121（最模糊）= **12.3**。
取 `FocusRef=60`、`FocusMin=0.5`（等效阈值 30）：最清晰帧记 1.0，最模糊帧记 0.20。

### 3.6 颜色序列的采样带方向

`RoiParams = [中心行, 中心列, 角度, 半长, 半宽]`，角度 0 时长轴沿列方向（水平），
**短边（半宽）才是跨线束的采样方向**。线束横放 → 长边水平、短边竖直：`[238, 300, 0, 80, 78]`，
覆盖 y 160~316（实测线束在 y 166~310）。

配方按实测像素序列写：`10 芯 = 黑,白,灰,紫,蓝,绿,黄,红,玫红,棕`（与插件文档 §1 的示例一致）。

## 5. 已知边界

1. **四条不进 Main、但勾「整线」**：`Role=0` + `InvokeType=160`，与七工位平级。
   点「启动整线」→ 11 条各起各的会话；`Main`（整件串行 + 统计 + 账本）仍是手动入口，
   不进账本、不参与综合结果（账本 11 列不变）。
2. **不进组态页**：「自动运行」页是 4 列 × 2 行的七工位卡布局，加四张卡要重排版面（R132 验收范围）。
   新流程的 Result / Reason / 数值变量已在变量表里，随时可以绑图元。
3. **图像是绝对路径**：与既有五条文件夹流程同一口径（`ImageAcquisition` 的文件夹/单图模式
   不做方案根锚定，指南 §1.1.1 的 WARN 级边界）。
4. **重跑 `--pair` 会改写调用方式**（幂等自愈，不是覆盖用户改动）：
   - 七工位 + 四条 → `Role=0` + `InvokeType=160`；
   - `Main` → `Role=0` + `InvokeType=0`（原 `Role=2` 是退役值，若留给加载迁移会**自动补 128**，
     与七工位抢会话——见 §3.0）；
   - `Home`/`End` → `Role=1`/`Role=3` 显式写死（不写的话 `MandatoryFlows.Ensure` 会补一条 `Home2`）。

## 6. 踩过的坑

1. **采集插件的图像输出端口叫 `Image`，不叫 `OutputImage`**：`OutputPort<HImage?> OutputImage`
   属性在 ctor 里显式给了名字 `"Image"`。按属性名写 `OutputImage` → 编译期
   `[连线断开] 上游 '...' 不存在输出 'OutputImage'` + `[参数缺失]`。四条流程一开始全红在这。
2. **`P_ROI` 已在 `Program.cs` 定义**：在 `Program.SamplePair.cs` 再写一遍是 `CS0102`。
3. **表达式体 `=>` 后面漏一个 `}`**：`PairIf` 的初始化器闭合后忘了关方法体，
   报的是远处（1364 行）的 `CS0106 static/readonly 对该项无效` + 末尾 `CS1513 应输入 }`——
   **报错行号指向的不是出错处**，靠累计括号深度定位。
4. **`.ps1` 里写中文正则必炸**（R1/R2 第 N 次验证）：`-match '几何计算|前置质量门'`
   被按 936 读成乱码 → `字符串缺少终止符`。清单/模式一律 ASCII，中文只进数据文件。
5. **多下标 PowerShell 数组语法**：`$gray[$x+1, $y-1]` 会被解析成 `$x + (1, $y) - 1`，
   必须写 `$gray[($x+1), ($y-1)]`。
6. **`Role: 2` 留在 .vms 里比"看起来不干净"严重得多**：`MandatoryFlows.MigrateRetiredRoles`
   会把它迁成 `None + LineStart(128)`——于是 `Main`（体内是「调用流程(七工位)」）也会被
   「启动整线」拉起来，和七工位抢会话，`FlowInvoker` 全部回「正在运行中…未执行」。
   生成器必须**显式写 `Role=0` + `InvokeType=0`**，不能指望迁移。
