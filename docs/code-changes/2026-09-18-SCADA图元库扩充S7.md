## 一、需求与决策

### 需求

S6 之后，数据能流到图元上了，但**能接数据的图元太少**：只有矩形、椭圆、文本、按钮、指示灯 5 个基础件。
对照商业组态软件，一个真实的产线画面至少要有"数值看板 + 状态灯 + 时间"，否则工程师画不出画面来。
S7 就是补这条：**把图元库从 5 个基础件扩到能画真实画面**。

路线图把 S7 分成 5 类（数值 / 指示 / 流程符号 / 容器 / 操作）。本批**只做"数值 + 指示"两类中不依赖后续阶段的部分**：

| 图元 | 依赖 | 本批是否做 |
|---|---|---|
| `Hmi.ProgressBar`（棒图） | 无 | ✅ |
| `Hmi.IOField`（数值域） | 无 | ✅ |
| `Hmi.Lamp`（多态灯） | 无 | ✅ |
| `Hmi.Clock`（时钟） | 无 | ✅ |
| `Hmi.Gauge`（表盘） | 无 | ✅（见第四节） |
| `Hmi.Valve`（阀门） | 无 | ✅（见第五节） |
| `Hmi.AlarmBanner`（报警条） | S11 | ⬜ |
| `Hmi.Pump`/`Motor`/`Pipe` | 无 | ⬜ 后续 |
| `Hmi.GroupBox`/`Frame` | S8 | ⬜ |
| `Hmi.CheckBox`/`ComboBox`/`CommandButton` | S12 | ⬜ |

### 决策一：`Hmi.IOField` 做成「只读数值域」，不做「输入写回变量」

路线图原文写的是 `Hmi.IOField`（**输入/输出框**）。做成"用户输入写回变量"的前置条件是
**新增领域层接口**（仿 `IScadaValueSource`）——因为 `VM.Scada.Controls` 只引用 `VM.Scada`，
**不引用 `VM.Core` / `VisionMaster`**（见 [VM.Scada.Controls.csproj](file:///e:/VM/VisionMaster-W-master/Scada.Controls/VM.Scada.Controls.csproj)），
控件拿不到 `IVariableRegistry` / `IWritableVariable`。

调研结论：**当前不存在"控件侧主动写回变量"的契约**。反向写入只被 `VisionMaster` 侧的动作分发器使用
（见 [2026-09-18-SCADA写变量动作接通.md](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-18-SCADA写变量动作接通.md) 的「图元属性反向写变量：本版不做」）。

**结论**：本批按**只读显示 + 可绑变量**（同 `Hmi.Text` / `Hmi.ProgressBar` 口径）落地，
显示名定为**「数值域」**：带边框的方框，左边一行说明字 + 右边「数值 + 单位」，`Value` 可绑变量。

这样**无需新契约、主程序一行不改**，符合"S7 图元库扩充"的边界。
输入写回留待后续阶段（需先设计领域层接口）。

### 决策二：外观由输入推导的图元，"推导"必须写在控件里，模板里不许有换算

棒图的填充长度、多态灯的灯色、数值域的显示串、时钟的时间串——这四类图元的共同点是
**外观不是用户直接设的，而是由输入推导出来的**。

推导逻辑一律落在控件的**只读依赖属性**上（`FillLength` / `LampBrush` / `ValueText` / `DisplayText`），
模板只绑这些只读属性。好处：

- 断言可以**直接读控件属性**验证推导结果（不必数像素）；
- 换算只有一处，模板与代码不会各写一份；
- 将来换皮肤只改模板，换算不动。

### 决策三：坏输入一律"收敛"而不是"抛异常"

四个新图元全部遵守同一条纪律：**一个坏值不该让整页渲染中断**。

| 坏输入 | 处置 |
|---|---|
| 棒图量程下限 ≥ 上限 | `Ratio()` 返回 `0`，画空条（不是 NaN） |
| 数值格式串写错（`"Z"`） | `catch (FormatException)` 退回通用格式 |
| 时钟格式串写错 | 退回默认形状 `yyyy-MM-dd HH:mm:ss` |
| 时钟节拍越界（0 / 负数 / 超大） | 收敛进 `0.1 ~ 60` 秒 |
| 多态灯状态序号越界（9） | `Enum.IsDefined` 挡住，**灯保持原状** |
| 数值非有限（NaN / Infinity） | 归 `0`，不参与布局 |

### 决策四：`ValueChanged` 事件一律不声明

S7 不给任何新图元声明 `ValueChanged`。理由：**缺"值确实变了"的后向回传通道**——
控件写不回模型，就没有权威的"变了吗"的判定点。

`BuiltInElements.cs` 类注释里写死了这条口径：**只声明"已经有人发得出来"的事件**。
清单里有一条发不出来的事件，用户就会配出一个永远不响的钩子，**比少一条更糟**。
所以 `ScadaChecks` 的事件白名单断言保持不动。

### 决策五：新增图元的固定三处改动（写进 `BuiltInElements.cs` 类注释）

```
① Elements/ 下写控件类（继承 ScadaElementBase，自带静态构造换 DefaultStyleKey）；
② Themes/ 下写样式并在 Generic.xaml 里加一行合并；
③ 本清单里加一条描述符。
领域层（VM.Scada）、序列化层、编辑器一行不改——.vms 里只留一个字符串 TypeKey。
```

**TypeKey 命名纪律**：`"Hmi."` 前缀，是写进 `.vms` 的**长期标识，一旦发布就不能再改**。
这条已由断言钉住（见第三节）。

## 四、S7 第二批：`Hmi.Gauge`（表盘）

### 需求与决策

**需求**：棒图看"趋势"，表盘看"指针落在刻度盘哪个位置"——压力、转速、温度这类工程量，
操作员要的是一眼判断"离额定值偏了多少"。这是数值类图元里最后一个无外部依赖的件。

#### 决策一：几何**全部算在代码里**，模板里一个算术都不写

表盘的三个可见部分——内接圆盘面、量程弧 + 刻度线、指针——**都依赖"控件此刻有多大"**，
算不出与尺寸无关的常量。所以与棒图把长度算在 `FillLength` 上同一条纪律：

- 模板只留三个 `Path` 绑只读几何属性（`FaceGeometry` / `ScaleGeometry` / `NeedleGeometry`）
  加一行 `TextBlock` 绑只读 `ValueText`；
- 断言可以**直接读控件属性**（不必数像素）；换算只有一处；将来换皮肤只改模板。

#### 决策二：盘面必须是**内接圆**，不许用 `Ellipse` 形状元素拼

若模板里用 `Ellipse` 形状元素拼盘面，控件被拉成 200×120 时盘面会变成**椭圆**，
而刻度线端点仍按圆周算——两者**当场错位**。所以几何统一用 `EllipseGeometry`，
半径 = `min(w,h)/2 −（半线宽 + 1）`，`RadiusX == RadiusY` 恒成立。

> 断言刻意排成 **200×120 的非正方形**来钉这条（正方形里椭圆与圆看不出区别）。

#### 决策三：WPF 角度约定（易踩）

- **0° 指向右**（3 点钟），角度**顺时针**增加，**90° 指向下**（6 点钟）；
- 默认 `StartAngle=135°`、`SweepAngle=270°` → 缺口落在**正下方**，正好放数值；
- 指针角度 = 起始角 + 扫过角 × 比例；比例已 clamp 在 `0~1`，所以**指针永远落在量程弧内**。

#### 决策四：坏输入一律"收敛"（沿用第一批口径）

| 坏输入 | 处置 |
|---|---|
| 量程下限 ≥ 上限 | `Ratio()` → `0`（不是 NaN） |
| 起始角 / 扫过角非有限（NaN / Infinity） | 归 `0` |
| 扫过角越界（±720） | clamp `±360` |
| 格式串写错（`"Z"`） | `catch (FormatException)` 退回通用格式，单位照拼 |
| 刻度格数 ≤ 0 | 只留量程弧，不画刻度线 |

#### 决策五：扫过角 = ±360 时改画圆环几何

一段 `ArcSegment` **画不出 360°**（起点终点重合，它无从判断走哪边）。
整圈时直接给一个 `EllipseGeometry`，比拆成两段弧少一次边界判断。

```
[√通过] 表盘：扫过角超出 ±360 收敛成整圈（一段 ArcSegment 画不出 360°，改画圆环几何）  →  7 个子项，首项 EllipseGeometry
[√通过] 表盘：刻度格数 0 → 只留量程弧（弧 1 项，不画刻度线）  →  1 个子项
```

> 说明盘面确实按**短边**内接（若按 200 的宽算会得到 98.5）。

### 收口时修掉的两个真问题（都不是断言写错，是控件缺件）

#### ① `GaugeElement` 构造函数是 `protected` → WPF 造不出控件

- **症状**：`[R]` 段 5 条红，注册表里只有 **9** 个图元（`Hmi.Gauge` 没进去），后续 `[S]`/`[X]` 连锁崩。
  报错原文：`Hmi.Gauge 的 ControlType GaugeElement 缺少公开无参构造（WPF 控件样式必须有无参构造）`。
- **根因**：`ElementRegistry` 用公开无参构造造控件，`protected` 不算"公开"。
- **修**：改 `public`（与 `ProgressBarElement` 等兄弟件一致）。

#### ② 缺 `OnElementRefreshed()` 收尾钩子

- **症状**：`[S]` 里盘面 / 刻度几何为空、指针线宽停在默认 `3`。
- **根因两层**：
  1. `Refresh()` **本身不调** `UpdateDial()`——外观重算只经 DP 变更回调触发；
     而 `ScadaElementBase` 的收尾钩子注释**本就写着**「如按角度调整指针、按量程重画刻度」，
     **表盘正是这个钩子的预期用户**，漏实现就是漏了一件。
  2. 半径要扣掉**半线宽**，而 `StrokeThickness` 是在 `RefreshCore` 里才落到控件上的——
     不放在收尾钩子上，改「外圈粗细」不会反映到盘面。
- **修**：`protected override void OnElementRefreshed() => UpdateDial();`
  （与棒图 `OnElementRefreshed => UpdateFill()` 同一个理由）。

#### ③ 断言侧：几何量依赖布局，必须"先布局再 Refresh"

控件刻意**不猜尺寸**：布局没跑时 `ActualWidth == 0`，几何量留空（宁可这一帧不画，
也不拿猜测值画一个会跳的表盘）。所以断言写成三步，并把第一步的结果也钉成断言：

```
Refresh()                       // ① 把模型上的 200×120 落到控件的 Width/Height（此刻几何应为空）
Measure() / Arrange()           // ② 跑布局：ActualWidth/Height 到位
Refresh()                       // ③ 布局已定，几何按真实尺寸算出来
```

> 顺带记一个断言环境的坑：**裸元素上直接 `Measure`/`Arrange` 不一定触发 `SizeChanged`**，
> 所以不能指望"布局一跑几何就自己更新"。挂进真实可视树（`[X]` 段那样）时 `SizeChanged` 正常触发——
> `[X]` 的盘底色采样通过，正是这条的旁证。

## 五、S7 第三批：`Hmi.Valve`（阀门）

### 需求与决策

**需求**：管路画面里最常出现的工艺符号。开关阀（只开 / 只关）与调节阀（开度连续）在
现场是两种设备，但在画面上它们**只差一个数**：0/100 还是 0~100 之间的连续值。

#### 决策一：开关阀与调节阀**合成一个图元**

若拆成两个图元，就得有两份几乎一样的模板、两条描述符、两处要同步修的几何代码——
而它们的差别只有"填充比例会不会停在中间"这一点，那本来就是同一个算式的结果。
所以只留一个数字输入 `Opening`（0~100），其余全部推导：

```
Opening ──┬─▶ ValveState（0=关 / 中间 / 100=全开）
          ├─▶ ValveBrush（关=空腔色、中间=中间位色、全开=全开色）
          ├─▶ OpeningText（"50%"）
          └─▶ FillClipGeometry（填充从左往右推进多少）
```

> 状态色用工业界通用语汇：**灰=没介质、蓝=正在调节、绿=全开**。

#### 决策二：填充用「共用几何 + 矩形裁剪」，不是「会伸缩的条」

蝴蝶结是**尖角朝内**的形状，任何"从边上量一段长度"的条子都塞不进它的轮廓。
做法是：填充与阀体**共用同一份几何** `ValveGeometry`，再拿一个矩形 `FillClipGeometry`
把它裁到"开了多少"的宽度上——无论阀体怎么缩放，填充都严丝合缝地落在轮廓里，比例天然是对的。

**宽度为 0 的裁剪矩形是合法的**，正好等于"一点都没开"，不必为全关单开一条分支。
（注意：`Clip = null` 在 WPF 里等于**不裁剪**，全关时若给 null 反而会被整块填充色盖住，正好画反。）

#### 决策三：图层次序——轮廓必须画在填充**之上**

模板里同一个 `Grid` 从下往上是：**空腔 → 介质填充 → 轮廓 → 位号 → 开度**。

初版把 `Stroke` 挂在 `Cavity` 上、`Flow` 压在其上，结果填充的裁剪矩形其
上 / 下 / 左边缘**正好压在轮廓线上**，会吃掉半个线宽（粗轮廓时左边框看着像断了）。
改成独立的 `Outline` 路径画在最上层，`Cavity`/`Flow` **只填不描边**。

#### 决策四：文字压在上下两个凹口里

蝴蝶结的上下各有一个 V 形空档（靠边最宽、越往中间越窄），那正是 `Text`（位号）与
`OpeningText`（开度）的容身处：**图元不必为文字额外留高度，文字也不会盖住阀体本身**。

#### 决策五：`State` 做成**普通计算属性**，不是依赖属性

没有任何东西绑它（模板要的是颜色，不是枚举），注册成依赖属性只会多一份没人读的表面。
它是给运行态与断言读**语义**用的：`public ValveState State => PickState();`

#### 决策六：不做开启动画（沿用多态灯不闪烁的理由）

动画需要一条全画面统一的节拍源（S11 报警系统一并做）。每个图元各起一个定时器，
同屏几个阀会各走各的，看上去像画面卡了。

#### 决策七：坏输入一律"收敛"（沿用前两批口径）

| 坏输入 | 处置 |
|---|---|
| 开度非有限（NaN / Infinity） | `Ratio()` → `0`；`PickState()` 当 `Closed` |
| 开度越界（150 / −20） | `Math.Clamp(opening/100, 0, 1)`；裁剪不溢出阀体、也不反向 |
| 格式串写错（`"Z"`） | `catch (FormatException)` 退回通用格式，`%` 照拼 |

#### ① 模板描边被填充吃掉半个线宽（落笔时即发现，未走到编译）

见上文「决策三」。改为独立 `Outline` 路径画在最上层。

#### ② 描述符 `Description` 里含未转义双引号（落笔时即发现）

`"…蓝色是"正在调节"的通用语汇"` 会直接编译不过。改用中文书名号 `「正在调节」`。

#### ③ 断言侧：NaN 那条**不能再 `Refresh()`**（跑断言时发现，1 条红）

- **症状**：`阀门：开度是 NaN 时按全关收敛` 报 `比例=0.5，状态=Throttled`。
- **根因**：断言写成 `SetValue(OpeningProperty, NaN)` → `Refresh()`，
  而 `Refresh()` 会把**模型上的 50 原样盖回来**（模型才是权威，与 `[Z]` 段
