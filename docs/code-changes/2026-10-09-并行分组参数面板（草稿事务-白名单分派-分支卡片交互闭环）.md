## 三、面板能力与交互口径

- **入口**：流程栏双击并行分组组头（`ParallelStep` → `ParallelGroupConfig` 白名单第四条出口）。
- **分组名**：可改。
- **分支**：改名 + 添加/删除。上限 8 = `ParallelStep.RecommendedMaxBranches`（到顶按钮禁用并提示「已达上限 8 条分支（模型推荐上限；确需更多请手改 .vms 图纸）」）；下限 1；删有算子的分支先二次确认；**分支名允许重复**（与 If 分支口径一致）；单分支时灰字提示「只有一条分支：等价顺序执行」。**（2026-10-09 同日后续已下沉：分支的增删改名改到流程栏右键——组头 = 添加分支、分支胶囊 = 重命名 / 删除本条分支；面板这一栏改为只读总览，上面这段"改名 + 添加/删除"是当日首版口径，留作历史脉络。见 `docs\code-changes\2026-10-09-并行分组分支结构动作下沉右键菜单（面板收窄为参数表单）.md`）**
- **执行模式**：顺序 / 真并发 二选一 + 常驻说明「调试运行/试运行时并行组会就地退化为顺序执行」。
- **失败聚合**：三态（继承全局 / 强制开 / 强制关），其中「继承全局」**实时显示** `GlobalParallelConfig.FailFastByDefault` 当前值。
- **汇合超时**：留空或 0 = 用默认 15000ms；有效范围 100~600000（超时文案含「存量图纸里更小的值请一并调整」）。
- **总闸警示**：`GlobalParallelConfig.ForceSequential=true` 时顶部警示条。

## 四、关键口径（供后来者）

1. **白名单分派**：`StepParameterDialog.Open` 现共四条出口——`ActionStep → PluginConfigShell`、`ConditionStep/ForStep → ConditionEditor`、`ParallelStep → ParallelGroupConfig`、其余 false 不弹窗；返回值=「是否真弹了窗」，调用方据此决定提示或静默。
2. **为什么保存要手动 `Version++`**：三个语义属性（ExecutionMode/FailFastMode/JoinTimeoutMs）走 setter 会由 FlowModel 版本链自动 +1，分支**增删**也会被其 Children 集合结构变更感知；但分支**改名**（`StepCollection.StepName`）无人订阅。本面板口径 = 保存成功一律手动推进一次（简单优先，多推一次只让下次运行必然重编译，无功能影响）。
3. **事务性**：所有编辑只落草稿；`TryApplyToModel` 校验失败**活模型零改动**（断言 W6/W7 钉住）。
4. **两处生效时机**（审查提示）：三个语义属性是运行期从蓝图读 → 改完下一轮即生效；分支增删要等会话新鲜度判定后的下一次重编译。
5. **分支卡片交互闭环**：视图侧 ToggleButton 豁免（分支箭头可展开/折叠）+ 拦分支卡片本体；VM 侧 `SelectStep` 收到 `StepCollection` 清空选中（不留旧算子当错靶）。
