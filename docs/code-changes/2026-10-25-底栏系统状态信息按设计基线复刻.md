## 5. 踩过的坑

1. **`MEM` 原来绑的是 `PrivateMemoryMB`，ToolTip 却写 Working Set**：两个口径混用，读数比任务管理器小一截。本轮统一到 `WorkingSetMB`；`MemoryUsageStr` 一并改口径，避免 `ShellCopy` 与真机显示两个数。
2. **Popup + `StaysOpen=False` 的「关不掉」**：开着时点 PlacementTarget，Popup 先因失焦关闭，Click 又把它打开。用 `PreviewMouseLeftButtonDown` 先判断「已开着」→ 关掉并 `e.Handled = true`，Click 只负责打开。
3. **`ShellCopy.xaml` 无 code-behind**：直接照抄 `Click=` 会在冒烟宿主里 XAML 解析失败；副本只同步结构，不带事件。另外 `ParseShell()` 会剥掉 `Click`/`PreviewMouseDown`，所以 `Shell.xaml` 里的处理器不会影响冒烟宿主。
4. **进度条不要自己算宽度**：`ProgressBar` 模板里给 `PART_Track` / `PART_Indicator` 命名后，库自己按 `Value/Maximum` 算宽度；内存直接把 `Maximum` 设成 1024 即可，不需要百分比转换器。
5. **`ShellCopy` 的底栏仍是 `Grid.Row="2"` 的老结构**（行数 3 行，没有 KPI / 组态 / 控制台）：它本来就不是逐行副本，本轮只同步「我改到的右区」，没有顺手重写整条底栏。
6. **CPU% 的旧分母把两个时间基准混用了**：`timeDiff = currentTime(墙钟) - _lastTotalProcessorTime(CPU 时间)`，进程跑得越久分母越大，读数一路趋近 0（截图里的 `0.0%` 就是它）。必须单独记 `_lastSampleTime`。
7. **`GC.GetGCMemoryInfo().TotalAvailableMemoryBytes` 不是「系统可用内存」**：它是 GC 的可用上限（容器限额或物理上限），进程用掉多少都不变；要「机器还剩多少」只能走 `GlobalMemoryStatusEx`（或 `PerformanceCounter("Memory","Available MBytes")`）。
8. **性能计数器名写错不会报错，只会一直给 0/同源值**：两条「网络收发」都指向 `Process\IO Other Bytes/sec`，既不是网络也不分收发。既然没人消费，直接删比留着更安全——留着迟早被人拿去画图。
