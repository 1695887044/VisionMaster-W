## 1. 当前状态

引擎把"一轮"升级成一等对象：

- 每轮结束（连续运行每轮、单次运行一次）产出不可变 **`FlowRoundResult`**：FlowId / 轮次号 / 起止 / 节拍 / Outcome / 判定源 / 原因 / 失败步骤 / 步骤数 / IsDebug。
- 写入 **`FlowSession.LastRound`**，并广播 **`FlowEngineService.FlowRoundCompleted`**（订阅者异常隔离）。
- 判定由宿主 **`FlowVerdictResolver`** 解析（结果输出步骤 > 约定变量 `<流程名>_Result` > 未判定）；引擎只依赖 `IFlowVerdictResolver`，不依赖工作区。
- 宿主 `FlowRuntimeVariableSource` 改为**消费引擎记录**：不再自己算节拍、不再自己解析判定；计数/台账/底栏/下钻全部读同一条记录。
- `FlowInvoker`：显式 OK/NG 现在都算"跑完了"（`Success=true`，另带 `Outcome`/`IsOk`）；产品 NG 不再被报成调用故障。未判定保持旧行为（有失败步骤 → 失败）。

### 关键口径

- **一轮 = 一条记录**：底栏、SCADA、上报、报表、子流程调用都读它，不再各算一套。
- **NG ≠ 技术故障**：判定表 NG 时步骤 Failed，但 `FlowRoundResult.Outcome=Ng`；`FlowInvoker.Success=true`。
- **未判定不冒充**：没有结果步骤/变量时 `Outcome=Unknown`；`FlowInvoker` 保留旧行为（有失败步骤才失败）。
- **调试轮**：也产出记录（`IsDebug=true`，`Outcome=Unknown`），宿主统计跳过，不进台账。
- **半轮不记**：被停止/取消的轮次不产出记录，避免"半轮"污染计数。

## 5. 踩过的坑

1. **引擎不能引用 VisionMaster**：`FlowVerdictResolver` 放在 VisionMaster，但 `FlowEngineModule`（Engine 程序集）不能注册它。
   改为在 `App.xaml.cs` 的 `RegisterTypes` 注册——必须早于 `FlowEngineModule.Initialize` 解析引擎。
2. **`FlowInvokeResult` 在 Core.Interfaces，不能引用 Core 的枚举**：把 `FlowRoundOutcome` / `FlowVerdictSource` / `FlowVerdict` 下沉到 `Core.Interfaces`；
   `FlowRoundResult` 留在 Core.Models 引用它们。
3. **`FlowRoundResult.FlowId` 用 Guid 而不是 string**：台账按 Guid 分桶；引擎从 `session.CompiledFlowId` 解析，解析失败回退按流程名。
4. **宿主来源不能自己算节拍/判定**：L2 后只消费引擎记录；否则又出现"引擎一套、宿主一套"。
5. **`FlowInvoker` 的未判定必须保留旧行为**：显式 NG 才改成成功；没有结果步骤的老子流程仍按"有失败步骤 = 失败"走，避免大面积改变既有方案。
6. **调试轮记录**：`session.DebugEnabled` 在 `FlowRoundCompleted` 前仍为 true（引擎收尾才复位），记录里标 `IsDebug`，宿主跳过。
7. **FlowCanvasChecks 两条断点时序**：本轮首跑出现 2 条 `第 2 圈同一断点再次断开住` / `继续后两圈跑完并正常收尾` 失败，单跑复跑 **4272/0**；属既有调试时序抖动。
