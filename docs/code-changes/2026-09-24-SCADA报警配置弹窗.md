# SCADA 报警配置弹窗（方案级平铺表 + 就地编辑 + 顶部工具条）

对标 InoTouchPad 第 7 节「离散量报警」配置表，补上本工程一直缺的一块：
**报警定义没有归属图元、属性面板里也没有落脚点**——`ScadaDocument.Alarms` 这张表
在界面上根本无从编辑（只能靠手改 `.vms`）。

本轮新增一个方案级弹窗，形态照 InoTouchPad 走：**一行一条报警、就地编辑、
左上角工具条，没有"选中 → 右侧属性面板"的分栏**。

## 一、需求与决策

### 1. 需求

用户指令（逐字）：

> 「`e:\VM\VisionMaster-W-master/D:\Program Files (x86)\Inovance Control\InoTouchPad\InoTouchPad软件帮助.chm`参考下第7节的控件 看下现在的功能差异对比,不明白的问我」

附 InoTouchPad「离散量报警」配置表截图（11 列：编号 / 类型 / 触发变量 / 触发位 /
信息文本 / 报警组 / 触发模式 / 报警等级 / 故障原因 / 解决措施 / 附加信息）。
要求按截图形态补出本仓的报警配置界面，**不明白的先问，不许擅自开工**。

### 2. 差异对比结论（已定稿）

| InoTouchPad 列 | 本仓字段 | 结论 |
|---|---|---|
| 编号 | 无 | 行号由 `DataGrid` 自给，**不落盘** |
| 触发变量 | `VariableId` / `VariableName` | 一致，回填走 `IScadaVariablePicker` |
| 触发位 | **不设列** | 位号并进变量自己的地址 |
| 信息文本 | `Message` | 一致 |
| 报警组 | `AlarmGroup` | 一致（**做"历史值下拉"**） |
| 触发模式 0->1 / 1->0 | `Kind = BoolOn / BoolOff` | 一致 |
| 故障原因 / 解决措施 / 附加信息 | `Cause` / `Remedy` / `ExtraInfo` | 一致 |
| （本仓多出） | `High/HighHigh/Low/LowLow` + `Threshold` + `Deadband` + `DelaySeconds` + `StaleSeconds` + `IsEnabled` | 一张表统一 |
| **类型 / 报警等级** | `Severity` | **不拆，只留「报警等级」** |

**★ 关于「类型 / 报警等级」不拆的裁决依据**：InoTouchPad 那两列是"离散量报警 / 模拟量报警"
与"严重度"两个维度；本仓 `ScadaAlarmKind` 已经把"离散（`BoolOn`/`BoolOff`）"与
"模拟量（四限 + `Stale`）"编码进了同一个枚举，`Severity` 又是独立字段。
再引入一个 `ScadaAlarmType` 枚举只会得到"两个枚举互相约束"的冗余状态
（如 `Kind=BoolOn` 却 `Type=模拟量`），**故不新增 `ScadaAlarmType`**。

### 3. 关键决策（已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 入口层级 | **方案级**（用户逐字：「放方案里 这个是跟解决方案来的」） | 报警定义是方案内容，跟着 `.vms` 走、进撤销栈 |
| 2 | 具体落点 | **「文件」菜单加一项**（用户逐字选定） | 与新建/打开/保存同级，用户找得到 |
| 3 | 运行互锁 | **运行中禁用，与新建/打开同级** | `CanExecuteSolution` **一个字不改**（`AlarmConfig` 走 `default` 分支即被拦），只同步改 `ShellViewModel` 的防御提示文案 |
| 4 | 报警组类型 | **自由文本 + 历史值下拉** | 组名随现场工艺划分走，各厂各线不同；枚举一发布不能改（见 `Core\Enums.cs` 的数值稳定性约定），用户想加一个组就得改代码发版本 |
| 5 | 增删改名的写入口 | **调 `ScadaDocument` 那三个自带 `BeginEdit` 的方法**，弹窗**不再外包一层** | 外面再包一层会把"两次撤销"并成一次 |
| 6 | 字段编辑的写入口 | **必须自己 `using (Document.BeginEdit(label))`** | `ScadaAlarmDefinition` 没有 `BeginEdit`，裸写不压栈 |
| 7 | 落值口径 | 弹窗**不自己夹取**，一律交给模型 | 回差负数夹 0、断线判定 < 1 夹 1，口径只由 `ScadaAlarmDefinition` 一处决定 |
| 8 | 长文本清空 | 落 **`null` 而不是空串** | 空串会在导出里变成一列空白，`null` 才是"未填" |
| 9 | 种类与等级 | **改种类不联动等级** | 领域层刻意不联动（`ScadaAlarmDefinition.Kind` setter 无副作用）；用户特意调过的等级不该被静默推翻 |
| 10 | 关窗语义 | 「关闭」以 `OK` 关窗、**不带任何参数** | 每一次编辑都当场写回，关窗不代表"是否采纳" |
| 11 | 历史 CSV 扩列 | 组态补充信息**追加在末尾，不插中** | 插在中间会把既有列下标整体挪位，现场已经有人按列号取数做报表了 |

### 4. 设计要点（为什么这么做）

- **弹窗只做投影，不持有真相**：`ScadaAlarmConfigRow` 的每个 getter 都从
  `Model` 回读，不缓存。行内输入框写回后 `RaisePropertyChanged(null)` 整行刷新，
  避免"看着还在其实已不判"的旧值。
- **一次字段编辑 = 撤销栈一条记录**：标签写成
  `修改报警 [报警_1] 的阈值`，撤销按钮据此显示提示。
- **"点了但没改"不产记录**：等值写被 `SetProperty` 同值短路挡掉，既不入撤销栈也不落审计。
- **"试着改但没改成"要留痕**：填了非数字不写模型、不落审计，只给一句中文原因
  （「「阈值」请填数字，当前填的是「8O」；已恢复成 0。」）——没写进模型的事
  不该在审计里冒充"改过"。
- **下拉选项必须用显式 `ItemTemplate`**（`DialogDisplayNameTemplate`），
  **不能用 `DisplayMemberPath`**——见 `DialogStyles.xaml` 的既有铁律：
  `DisplayMemberPath` 生成的"别名模板"不会同步给选中框，选中框会退化成 `ToString()`。
- **报警组不能用可编辑 `ComboBox`**：全仓 `DialogCombo` 不支持 `IsEditable`
  （grep `PART_EditableTextBox` 零命中），故走 `TextBox + DialogIconButton + ContextMenu`
  的历史值下拉（同 `ScanGroupEditorView` 的"一键预设"手法）。
- **启用开关用裸 `CheckBox`**：全仓没有 `DialogCheckBox`，
  `CheckBox` 只有 `DefaultStyle.xaml` 的全局隐式样式（先例：`ScadaVariableEventDialogView.xaml`）。

## 四、交付纪律（后续新增就地编辑弹窗必守）

1. **`ScadaDocument` 里已自带 `BeginEdit` 的方法（`AddAlarm` / `TryRemoveAlarm` /
   `TryRenameAlarm`），弹窗**不许**在外面再包一层**——会把两次撤销并成一次。
2. **字段编辑没有自带作用域，必须自己 `using (Document.BeginEdit(label))`**，
   否则写进去的值撤销不回去。
3. **落值口径只由模型一处决定**——弹窗不自己夹取（负数、下限），
   免得"界面允许的值"与"模型接受的值"两套口径打架。
4. **长文本清空落 `null` 不落空串**——空串在导出里是一列空白，`null` 才是"未填"。
5. **下拉选项用 `DialogDisplayNameTemplate`，禁用 `DisplayMemberPath`**——
   后者生成的别名模板不会同步给选中框，选中框会退化成 `ToString()`。
6. **`DataGrid` 内控件的命令要往上游找**：
   `{Binding DataContext.XXXCommand, RelativeSource={RelativeSource AncestorType={x:Type DataGrid}}}`；
   `ContextMenu` 里则用 `AncestorType=ContextMenu` 并显式接
   `DataContext="{Binding PlacementTarget.DataContext, RelativeSource={RelativeSource Self}}"`。
7. **`DataGrid` 内联输入的提交口径**：文本用 `UpdateSourceTrigger=PropertyChanged`，
   数值 / 改名用 `UpdateSourceTrigger=LostFocus`；输入框列配
   `CellStyle="{StaticResource DialogDataGridCellFlush}"`。
8. **XML 注释内不得出现连续 `--`**（`MC3000`）；**XML 注释内不要写 Markdown 加粗**（用 `<b>`）；
   **C# 字符串内不要写半角引号**（`CS1003`），一律改用「」。
9. **枚举追加只能往后**（`Core\Enums.cs`）——中间插一个会把后面所有成员的值整体挪一位。

## 五、已知边界

- **`RowDetailsVisibilityMode="VisibleWhenSelected"` 是全仓首次使用**（grep 无先例）。
  已验证"编译通过、断言全绿"，但**展开行的运行时视觉未目视确认**。
- **`ContextMenu.ItemsSource`（字符串集合）+ `ItemContainerStyle` 给 `MenuItem` 设
  `Command` / `CommandParameter` / `Header`** 这套写法**未经真机确认**。
  若不生效，备选写法是改用
  `<ContextMenu.ItemTemplate><DataTemplate><MenuItem Header="{Binding}" Command="..."/></DataTemplate></ContextMenu.ItemTemplate>`。
- **`DataGridTemplateColumn` 内塞 `ComboBox` / `CheckBox`** 的交互（下拉展开、勾选命中）
  同样只过了编译，未目视验证。
- **InoTouchPad 的「类型」列未做**（按裁决不拆，见 §一.2）。
- **「触发位」未设列**（位号并进变量自己的地址）。
- **「编号」不落盘**（行号由 `DataGrid` 自给）。
- **报警组历史值只在本方案内去重**——跨方案不共享，这是刻意的（组名是方案内容）。
- 软键盘输入、BCD 格式、移动小数点等手册对标欠债仍在（见
