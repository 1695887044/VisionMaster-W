# 自动化产线方案（2026-10-22）

## 范围

新增 `解决方案\自动化产线.vms`：

- **14 条流程 / 315 步 / 51 个变量 / 8 页组态 / 95 个图元**
- 9 个工位 + St10_Rework + Recipe + Home/Main/End
- Main 是唯一 `Role=Main`，工位全部 `Role=None + 子程序`
- 工具栏「循环主流程」只跑 Main，不会把工位当顶层流程启动

## Main 调度

```text
读 PLC_Trigger → 空闲/继续
If LineFault → 延时 → Return
CycleCount++
St1 → St2 → St3
For 2 轮:
    St4 → St5 → St6 → St7
    ProductOk = St4_Ok && St5_Ok && St6_Ok && St7_Ok
    If ProductOk → Break
    St10_Rework
FinalOk = ProductOk
St8 → St9
PLC_Result / PLC_Ack / PLC_Alarm / PLC_CycleCount
YieldRate = OKCount/(OKCount+NGCount)*100
CSV → Delay 500ms
```

设备故障与产品 NG 分开：

- `RunFlow.Invoked=false` → 停 X/Y/Z、`LineFault=true`、`PLC_Alarm=true`、`Return`；
- `Invoked=true` 但 `StX_Ok=false` → 产品 NG，继续返修/分拣。

## 验证

- `ValidateSolution`：14 条流程全部 `COMPLEX-FLOW-OK`，`COMPLEX-RESULT: ALL_OK`；Main 127 步。
- `_ScadaUiProbe --solution`：8 页全部 `RESULT: OK`，无 XAML 解析异常。
- `VisionMaster.exe`：HTTP `Main` 返回 **200**；本次运行环境 **502/503/504/102 均未启动**（日志 `PLC_Modbus` 离线、ZMotion 20008），Main 走“读触发失败 → 空闲”分支，**未完成真实 9 工位节拍**。
- 端到端验证需要先启动虚拟卡与三台通讯模拟器，并把 `PLC_Trigger` 写 1。

## 边界

- `RunFlow` 超时仍不停止子流程；产线需要“超时也停”时后续加 `StopOnTimeout`。
- 工位级串行；只有 St5 的视觉分支并行（`RunFlow` 未标 `ParallelSafe`）。
- A/B/C 配方只影响 St4 卡尺标准；St5/St6 阈值共用。
- 每节拍约 9 张图；图像集 300 帧上限约 30 节拍后覆盖。
- 虚拟卡到位用 `Delay` 模拟；接真卡后换「等待到位」。
