# 「系统设置」合并：两个弹窗并成一个、正文交给反射属性面板（2026-10-20）

## 1. 起因与结论

菜单「系统」里并排两项：**运行窗口设置**（依附主窗口 / 独立窗口 + 落在哪块屏）与
**系统参数设置**（空闲自动登出、审计 / 报警历史保留、画布图集）。两者写的是同一份东西
——程序目录 `AppConfig.json`——口径也逐条相同：

- 草稿编辑，只有「确定」才写盘；
- 只把**真变了的项**写进审计；
- 写盘失败**不关窗**，红字条留在屏幕上让人重试；
- 打开时现读配置，不依赖"容器每次新建 VM"。

两个弹窗等于把"读配置 → 编辑 → 算变更 → Save → 失败留窗 → 落审计"这整条链抄了两份
（两个 VM 共 716 行，两个视图共 622 行），而且每加一项设置都要动一次 XAML。

**结论**：合并成一个「系统设置」弹窗，三个页签；正文交给 `CardPropertyGrid`
按草稿类上的 `[SuperDisplay]` 反射生成。**以后新增一项 = 草稿类加一个属性，视图一行都不用改。**

用户对"两张单选卡片换成开关"的裁定：这本来就是一个二选一（是否独立窗口），
草稿里用一个 `bool` 比枚举下拉更贴切；"什么时候用哪个"只需一句话，放进字段说明即可。

## 3. 关键设计（为什么不是"直接 `ShowPropertyGridSync`"）

| 需要的行为 | 属性面板给不了什么 | 本方案怎么补 |
| --- | --- | --- |
| 校验不过不许关窗 | `ValidationProcessor` 只把 `ControlContext.HasValidationError` 置 true，**全仓没有一处读它**；`EasyDialog` 的确定按钮不看这个标志 | 确定/取消由自己的外壳掌握；确认时统一解析，失败写红字条并留在窗上 |
| 留空不能被当成 0 | `NumericBox` 清空写 `NaN`，绑定到 `int` 失败后**属性保持旧值**——界面空着、存下去的是上一次的数 | 五个数值项在草稿里是 `string` + `[RegexValidation(@"^-?\d+$")]`，确认时 `int.TryParse`（不变区域性） |
| 写盘失败留在窗上 | `EasyDialog.ShowPropertyGridSync` 自己建窗口、自己收口成 bool，**没有放错误条的位置** | 只把网格当正文控件，外壳自己管确定/取消与红字条 |
| 字段下方要有说明 | `[SuperDisplay(Description)]` 只落到标签的 **ToolTip** | 数值项的公共约定（"0 或负数 = 不限制"）在壳里写**一行**，不逐项重复 |
| 落盘仍是设备名 | `[ComboSource]` 的候选是纯字符串，值就是显示名本身 | 草稿存下拉文案，确认时反查回 `\\.\DISPLAYn`（映射只在一处） |

审计口径不变：**事件列仍是两个类别名**（`运行窗口` / `系统参数`）。一次确定同时改了两个域就落两条；
一处没动时只落一条（`系统参数 / 修改参数 / 未写盘`）。

## 5. 纪律（给后来者）

1. **属性面板的校验只标红、拦不住确定**。`HasValidationError` 至今无人读，所以"安全策略类"的数值项
   必须在 VM 的确认链里再解析一次——面板的红字是提示，不是闸。
2. **`NumericBox` 清空写 `NaN`**，绑定到 `int` 失败后属性保持旧值。凡是"留空不能猜成 0"的字段，
   草稿里用 `string` 接、确认时解析（与旧 `ScadaSystemParametersViewModel` 的口径一致）。
3. **新增一项设置只需要改草稿类**：加一个带 `[SuperDisplay]` 的属性（数值项再加一行解析）。
   视图里没有字段表，不要去 XAML 里补行——那会把"反射生成"退回"手写表单"。
4. **`Application.Current` 一律 `?.`**。属性面板家族的其它生成器与 `PropertyGridMetrics` 都这么写，
   `BoolStateGenerator` 曾经是唯一例外：在没有 `Application` 的断言宿主里，渲染任何带 bool 的草稿直接 NRE。
5. **`SystemAction` 只许末尾追加**。两个旧值（`RuntimeWindowSettings` / `SystemParameters`）保留并转发，
   删掉会让旧 `Layout.xml` / 脚本里的整数值指向别的动作。
6. **审计的事件类别不随界面合并而合并**。历史流水按「运行窗口 / 系统参数」检索，改名等于断掉追责口径。
