## 2. 骨架规范（摘要）

规范全文在方案说明书，这里只留"守门人要用的那几条"：

1. **页面角色**固定六类：`01` 介绍/快速上手 → `02` 界面与操作 → `03` 端口与参数 → `04` 调参/进阶
   → `05` 常见问题与排障 → `1x-dev-*` 设计思路/架构/不变量。
2. **文件名 = 页序**：`NN-` 前缀，宿主按资源名 Ordinal 排序，所以页序完全由文件名决定（HM6）。
   ⚠ 页名里**不许再出现第二个点**——宿主要用"最后一个点"取页名（§7）。
3. **第一行必须是一级标题**（`# 插件名 · 页角色`），页标题就取它，且只在正文开始前扫描。
4. **开发页标记**：去掉 `NN-` 后以 `dev-` 起头（`HelpCatalogService.DeveloperPageMark`）。
5. **事实来源只有源码**：端口名、默认值、取值范围、错误文案逐条对着代码抄；厂商码这类映射必须
   指着驱动的 `switch` 抄（例：`HomeMode` 的 C# 值是 0~7，正运动 `homemode` 是 1/2/17/18/19/23/27/37，
   表头就得写明"正运动模式码"）。
6. **禁止占位**：`TODO / 待补充 / 待完善 / （略） / TBD` 一律红（HM11）。

## 7. 缺陷一：多插件程序集的开发页标记被宿主吃掉（14 页）

**症状**：界面上一切正常——目录树收到了 86 页里的 72 页开发页，`Plugin.Motion.Steps`（7 个条目）
和 `Plugin.Utility`（5 个条目）的 `10-dev-*.md` **不带「开发」角标**，于是"显示开发章节"关着的时候
它们照样出现在用户目录里。编译期全绿，静态扫描全绿（文件名的确是 `NN-dev-xxx.md`）。

**根因**：`HelpCatalogService.cs:366` 原来这么取页名——

```csharp
var shortName = Path.GetFileNameWithoutExtension(name.Substring(prefix.Length));
```

资源名长这样：`Plugin.Utility.Help.DelayPlugin.10-dev-architecture.md`。MSBuild 把内嵌资源的
**目录分隔符换成点**，于是"分册目录名"（逐字等于插件类名）就粘在页名前面；
`GetFileNameWithoutExtension` 只剥 `.md`，剥不掉 `.DelayPlugin`，交给 `IsDeveloperPage` 的是
`DelayPlugin.10-dev-architecture`——它要求"去掉 `NN-` 后以 `dev-` 起头"，而这里开头是 `DelayPlugin.`，
判不出来。

**为什么以前没暴露**：单插件程序集不分册（页直接放 `Help\` 下），资源名里没有目录段；本轮才第一次
出现"一个程序集里多个条目 + 各自分册 + 开发页"三者同时成立的组合。

**修法**：`HelpCatalogService.cs:408` 新增 `GetPageFileName`——砍前缀、去扩展名后，**再取最后一个点之后**：

```csharp
private static string GetPageFileName(string nameAfterPrefix)
{
    var withoutExtension = Path.GetFileNameWithoutExtension(nameAfterPrefix);
    var lastDot = withoutExtension.LastIndexOf('.');
    return lastDot < 0 ? withoutExtension : withoutExtension.Substring(lastDot + 1);
}
```

`IsDeveloperPage`（`:419`）的注释同步改成"入参必须是 `GetPageFileName` 取出来的纯文件名"。

**这个修法的隐含前提**：页名里不能再有点 → 由 HM6 新增的那半条钉住（§6 表第 1 行）。

**变异反证（R38）**：把 `:366` 还原成旧写法 → 探针第 7 项对照准确变红，报
`开发页标记与资源清单对齐（清单数到 86 页 / 目录树 72 页）`；改回后 69/0 全绿。

## 8. 缺陷二：手册正文里未闭合的 `**` 直接上屏

**症状**：探针渲染整本手册后，屏幕上出现字面两个星号。两处真缺陷：

1. `Plugins\Plugin.PreProcessing\Help\12-dev-invariants.md:160`——原文写的是
   `**B9 透传**必须原样 \`return input\`，异常路径绝不许偷偷返回入参**`，
   **三对星号**（末尾多一个 `**`），第三对没有配对对象。
2. `Plugins\Plugin.ImageScript\Help\05-troubleshooting.md:89-91`——形状完全不同，也更值得记：

   原文（有缺陷）：
   ```
   （"dev_display、dev_set_window 等 `dev_*` 系列是 HDevelop 开发环境专用，粘贴脚本时请删掉这些行"）——
   **当前版本 `dev_*` 是可用的**（宿主注册了显示后端），所以真遇到这条报错时更可能是：
   ```

   `dev_display`、`dev_set_window` 两个算子名**裸写在反引号外面**。渲染器的行内扫描（
   `MarkdownToFlowDocument.cs:563`）把 `_` 也当强调标记，于是正文里起了一个**幻影斜体**，
   把后面那对真 `**` 吞进斜体内部——结果是行内代码 `\`dev_*\`` 的反引号被当字面输出、`**` 剩一个。

   **第一次修错了**：只把第 90 行的 `dev_*` 包进反引号 → 泄漏照旧（因为裸写的是隔壁两个算子名）。
   第二遍才改对：把这一句里所有 HALCON 算子名一律放进反引号，并**去掉与 `dev_*` 相邻的那对 `**`**
   （改成不重叠标记的陈述句）。

**判据为什么是"渲染级"而不是"数原文星号奇偶"**：原文里 `Help\**\*` 这类通配本来就该字面显示，
数奇偶会误报。所以探针的做法是——渲染完取全文（`TextRange(doc.ContentStart, doc.ContentEnd).Text`），
数残留的 `**`，再减去**代码上下文里允许原样出现的额度**（`CountLiteralInsideCode`：fence 与行内反引号
两种来源，遍历口径与 §9 那条共用）。

## 9. 新增第三道渲染闸：代码块里的字有没有字形

**起因**：看 §13 的 YOLO 截图时，代码块里的 `①②③` 在小尺寸下像豆腐块，怀疑等宽字体族
（`MarkdownToFlowDocument.cs:77` 的 `Consolas, Cascadia Mono, Courier New`）盖不住这些字符——
手册里有 **162 行 / 35 个文件**在 fence 内用带圈数字。猜没有意义，加闸量一遍。

**判据**：把每页"代码上下文（fence + 行内反引号）"里出现的非 ASCII 字符去重，逐个用**从渲染结果里
认出来的**代码块字体族渲染成 28×28 位图，与一个**一定没有字形**的私有区字符 `U+E000` 的位图比像素，
一模一样就是走了缺字形兜底。字体族不写死：`FindCodeFont(doc)` 找"第一个改了 `FontFamily` 的块级段落"
（正文族挂在 `FlowDocument` 上，代码块段落是渲染器里唯一改这个属性的块），生产换字体时这条闸跟着走。

**结果**：**1150 个字符全部有字形**，① 与 🔗 都由 WPF 的字体兜底正常显示 → 手册一行没改。

**第一版是假阳性，值得记**：按 `char`（UTF-16 码元）测，报出 `U+D83D U+DD17` 两个"豆腐块"——
那是 YOLO 页里 🔗（U+1F517）的**半个代理对**。改成按 `System.Text.Rune` 走之后归零。
教训：**测字形必须按码点，不能按码元**；这类假阳性的坏处不是红一次，而是让人养成"这条闸常红"的直觉。

**变异反证（R38）**：往字符集里注入 `U+F000` → 准确变红（`豆腐块：U+F000`），删除注入后 69/0。
诊断消息里带 `U+XXXX` 码点——**缺字形字符本身往往是不可见的**，只打字符等于没打。

## 10. 事实来源核对（"手册写的东西源码里有没有"）

两条独立核对，都不依赖写册角色的自述：

1. **端口名反向核对**（`%TEMP%\portcheck2.py`）：把手册里所有反引号包裹的标识符抽出来（**2,299 个不同

   本轮顺手把唯一一个 CRLF 文件 `Plugin.Motion.Steps\Help\MotionEnablePlugin\01-overview.md` 归一成 LF
   （8239→8119 字节），归一后重跑严格解码 + Read 回读中文。

> 为什么单独盯编码：这批页是**多个角色并行**写出来的，混进一份 GBK 或带 BOM 的文件，症状是
> 宿主读出来一片乱码、而构建与闸门全绿（AGENTS.md §1 那三次事故的同一族）。
