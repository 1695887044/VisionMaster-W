# 2026-09-18 SCADA 运行态地基（S4）—— 从"能编辑"走到"能跑起来"

## 一、需求与决策

### 这一阶段要交付什么

S1～S3 把"画面文档、图元控件、编辑器"三件事做完了，但那份文档**从来没有真正跑起来过**——
只能编辑、存盘、看。S4 要补的是商用组态软件最基础的一条闭环：

> 设计完 → 点运行 → 全屏看到那一页 → 点停止回到编辑器。

### 用户在本阶段定下的五条硬契约

| # | 契约 | 落地位置 |
|---|---|---|
| 1 | 事件钩子是**运行态专属**，设计期切页不触发、不订阅 | `ScadaRuntime.Start()` 里发，编辑器路径一条订阅都不挂 |
| 2 | 事件清单**声明在描述符上**（不是散在控件里） | `ElementDescriptor.Events` |
| 3 | 目标口径：图元 Pressed / Released / ValueChanged，画面 Loaded（Unloaded 留 S5） | `ScadaEventType` 五个值，数值发布后不许改 |
| 4 | 本版**动作不接流程引擎**，Loaded 之后只做一件事：往 `LogService` 记一行 | `ScadaRuntimeHost.OnFirstFrameRendered` |
| 5 | 运行态宿主 = **新弹全屏窗口**、读内存里当前方案、`Esc` 不退出、单实例、自动停止 | `ScadaRuntimeHost` + `ScadaRuntimeWindow` |

### 三条关键决策与理由

**决策一：领域层放"会话"，WPF 层放"壳子"，耗时归壳子测。**
`ScadaRuntime`（在 `VM.Scada`，零 WPF 引用）只回答两个产品规则问题：该显示哪一页、
Loaded 该不该发。`ScadaRuntimeHost`（在 `VisionMaster`）负责窗口、计时、日志。
理由：`PageLoaded` 是在 `Start()` 里同步发出的，那一刻**一个像素都还没画**；
现场排查"画面点开是黑的"要看的是首帧，而首帧只有 WPF 的 `ContentRendered` 知道。
两边各管各的事实，谁都不越界。

**决策二：用 `ContentRendered` 而不是 `Loaded` 作为"显示完了"的时刻。**
`Window.Loaded` 只保证逻辑树建完，不保证渲染完成。用 `Stopwatch` 而不是 `DateTime.Now`：
墙上时钟会被 NTP 跳一下，差值变成负数或几百秒，现场看到只会怀疑代码。

**决策三：单实例不是"防呆"，是数据一致性的前提。**
真开出两份会话 = 两份运行态各自往同一批变量上写，出问题时分不清是谁写的。
所以第二次点运行只是 `Activate()` 把已有窗口带到前台。

**决策四（本轮新增）：运行窗口 `Owner = MainWindow`。**
关主界面时运行窗口跟着关，"关编辑器自动停止"这条不用自己写代码，也就不会出现漏摘的订阅。
副作用是最小化主界面会连带最小化运行窗口——对"设计完看一眼效果"这个用途正是想要的行为。

### 顺带修掉的画布渲染缺陷（本阶段最费时间的一件事）

现象：编辑器画布和运行窗口里，**只有左上角一小块有内容，靠右靠下的图元凭空不出现**。
数据一条没少、`RenderSize` 一条没错，就是不出图。详见第三节根因。

## 三、根因分析：画布"只画左上角"

这是本阶段最值得写下来的一条，因为它**在调试器里看起来完全正常**。

### 排查过程

1. 先怀疑缩放：`RenderTransform` 装配在 `ScadaCanvas.cs` L460-463，
   `_surface.RenderTransformOrigin = (0,0)` + `ScaleTransform` + `TranslateTransform`。
2. 再怀疑显式宽高被夹：注释里写着"WPF 会把 `Width=1920` 夹成视口宽"——**这个说法是错的**，
   后面会把注释一起改掉。
3. 写探针：把 `PART_Surface` 单独渲染成 1920×1080 的 PNG，同时打印四行真值。

### 探针实测（800×600 视口、1920×1080 画面、Zoom=0.4）

```
host.RenderSize=800,600  surface.RenderSize=1920,1080  surface.Actual=1920x1080
surface corners in host space: (0,0)->(0,0)  (1920,1080)->(768,432)
painted extent: right=319 bottom=239  (expect 768 x 432)
surface-only png written, size=1920x1080
```

第二行说明**变换完全正确**（1920×1080 精确映射到 768×432）；
第三行说明**实际只画出了 800×600×0.4 那一块**。
单独渲染 `PART_Surface` 得到的 1920×1080 画布里，也只有左上 800×600 有内容。

### 结论：布局槽（layout slot）成了裁剪矩形

`PART_Surface` 直接挂在 Border 下面时，Border 把"视口有多大"当作 arrange 约束传下去，
于是元素被 arrange 进一个 800×600 的**布局槽**，**槽外的像素一律不绘制**。
而 `RenderSize` 仍然是 1920×1080，`TransformToVisual` 也完全正确——
所以断点、监视窗口、日志里一切正常，只有像素不撒谎。

`Canvas` 给子元素的测量与排布约束都是**无限大**，槽位 = 子元素自身尺寸，画面才铺得开。
溢出由外层 Border 的 `ClipToBounds="True"` 收口，不会盖到相邻面板。

### 最终模板

```xml
<Border Background="{TemplateBinding Background}" ClipToBounds="True">
    <!-- 这层 Canvas 是"无限约束"的载体，删掉它画面就会被布局槽裁掉 -->
    <Canvas ClipToBounds="False">
        <Border x:Name="PART_Surface" Canvas.Left="0" Canvas.Top="0"
                Background="{TemplateBinding PageBackground}" SnapsToDevicePixels="True">
            <Grid>
                <Rectangle x:Name="PART_GridLayer" HorizontalAlignment="Left" VerticalAlignment="Top" />
                <Canvas x:Name="PART_ElementLayer" />
                <Canvas x:Name="PART_SelectionLayer" />
            </Grid>
        </Border>
    </Canvas>
</Border>
```

代码侧只靠 `GetTemplateChild("PART_Surface")` 按名字取件，不依赖嵌套层级，
所以加这一层是安全的——这一点在动手前专门读 `ScadaCanvas.cs` L490-529 确认过。

### 方法论收获（写给下一个人）

- **`RenderSize` 正确不代表画得出来。** 必须做像素边界扫描才能暴露布局槽裁剪。
- **单独渲染被怀疑元素**是区分"元素自身没画"与"被祖先截断"的判据。
- **改完即删探针**，不留临时 `Console.WriteLine`；把踩坑原因写进注释，
  写成"删掉它画面就会被布局槽裁掉"这种下一个人能照做的形式。

## 五、已知边界（欠债清单，按优先级）

1. **`ScadaBinding` 只有模型，没有数据泵。** 全仓搜索确认：绑定的订阅机制
   （`ScadaElement.Subscribe/Unsubscribe`）只服务于**脏标记冒泡**，没有任何一处从
   `IVariableRegistry` 取值写回图元属性。也就是说"绑了变量的图元在运行时动起来"这件事
   **完全没做**——这是 S6 的主体，也是当前 SCADA 与商用组态之间最大的一条差距。
2. **图元级事件（Pressed / Released / ValueChanged）词表立住了，但一个都不触发。**
   留给 S5 的事件→动作分发器。
3. **`Unloaded` 不触发。** `ScadaRuntime.Stop()` 里刻意不发（发了也没人接）。
4. **运行态"切方案自动停止"只挂了 `CurrentSolution` 一条属性。** 其他工作区状态变化不管。
5. **重命名方案不改 `.vms` 文件名**（标题栏显示 `解决方案-20260916193845`，
   磁盘文件叫 `解决方案-20260829224154.vms`）。数据自洽，**不是 bug，是产品决策项**：
   要不要同步改文件名、改了会不会破坏"最近打开"列表，等定。
6. **`Hmi.Text` 空文本不可见**——设计期拖一个文本图元不写字就是"凭空消失"。
   商用惯例一般是默认文字=图元名，或空文本画虚线占位框。待决。
7. **图层面板没有 UI。** `ScadaPage` 的 `Try*` 家族（含 `TryAssignLayer`）除断言外无入口。
8. **D3 统一写模型入口未落。** 撤销/重做因此做不了，只留了接缝。
9. **`ScadaRuntimeHost` 不留 `Dispose`。** 三个单例之间的订阅不会互相钉住，
   这是有意为之而非遗漏（注释里写了理由）；但如果将来宿主改成非单例，这条要重新评估。
10. **SCADA 新代码全部未纳入版本控制**（`Scada/`、`Scada.Controls/`、`ScadaChecks/` 等）。

### 操作纪律（踩过两次以上，写死在这里）

- **启动 GUI 做真机验证，必须用 `Invoke-CimMethod -ClassName Win32_Process -MethodName Create`
  脱离终端启动。** `Start-Process` 起的进程会随终端作业对象回收被一起收掉，
  表现为"启动后自行退出"，而日志里**一点异常都没有**——非常误导。
- `click` 与 `get_app_state` 必须用**同一个 `max_depths`**，否则元素 id 对不上。
- 多窗口应用要按 `windowId` 定向查询，否则 tooltip 窗口会抢走"当前截图目标"，
  导致 UI 树被截断成 `(... elements hidden)`。
