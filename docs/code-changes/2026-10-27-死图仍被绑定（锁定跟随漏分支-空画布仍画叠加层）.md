# "死图仍被绑定"（锁定跟随漏分支 / 空画布仍画叠加层）修复（2026-10-27 批 2）

> 姊妹篇：`2026-10-27-视觉图像页滚轮缩放无下界（图像缩到看不见）.md`（批 1 修的是"滚轮缩到亚像素"，
> 本篇修的是"帧已被释放但画布还指着它"——两者症状都是"黑底 + 一行绿字"，成因完全不同）。

## 一、当前状态

**缺陷（三条，都已复现/取证）**：

1. **`ImageGallery.Recompute` 漏一个分支**（`Services\Core.Halcon\Controls\ImageGallery.cs` 原 `:641-648`）：
   `SupportsFrameHistory=true`（保留历史帧）+ `AutoSelectNewest=false`（用户按了"锁定跟随"）
   + 选中的兜底帧被同槽新帧覆盖（`InsertOrReplace` 的 `_frames[i]=新帧` → `existing.Dispose()`）时，
   四个分支全不命中 → `SelectedFrame` **继续指着已 Dispose 的帧**。
   而 `ImageFrame.Image` 是普通 CLR 属性（无 INPC），`Dispose()` 里置 null **不通知绑定**
   → 画布永久停在"黑底 + 标注"，**不自愈**。
2. **`PinnedFrame` 从不校验**：钉住的对比基准被覆盖/淘汰后，右侧对比大图同样永久"黑底 + 标注"。
3. **显示层把叠加层画在空画布上**：`HalconBase.RenderAll` 里只有 `DispObj` 有"图是否有效"的守卫，
   ROI 轮廓 / 涂抹层 / 测量标注 / 十字线**无条件画**——这是"黑底 + 绿字"这个视觉谎言的源头。

**为什么"瞬态"那一帧不是问题**（本轮修正了批 1 记录里的旧结论）：并行会话已把 `HImage`/`Annotations`
两次 DP 变更合并成一次 `ScheduleRender()`（`HalconBase.cs:261-282`，Render 优先级），
flush 时绑定早已是活图 → 换帧窗口期的那一帧已经不会画出来了。**剩下的是上面第 1 条的"永久态"。**

## 二、已做

1. `ImageGallery.Recompute`：
   - `else if (visible.Count == 0)` → **`else`**：锁定跟随下原选中帧被覆盖/淘汰时**清空选中**
     （"锁定"锁的是"新帧不抢焦点"，不是"抱着已释放的帧"；口径与下面 `AutoSelectNewest ? newest : null` 一致）。
   - 末尾新增 `PinnedFrame` 校验：`!all.Contains(PinnedFrame)` → 清空。
     判据刻意**只看"还在不在数据源里"**（`all` = 未按流程筛选的全集）：
     只是被流程下拉挡住的帧仍然活着，切筛选不该丢基准；"图还在但 Image 为空"属显示层问题（见第 3 条）。
2. `HalconBase.RenderAll`：`ClearWindow()` 之后判"有没有活图"，**没有就清屏收尾、直接 return**
   （不画 ROI/涂抹/标注/十字）。收尾要点：`flush_graphic` 由既有 `finally` 还原；
   `SetColor("black")` + `hSmart.InvalidateVisual()` 必须自己补，否则 WPF 侧还显示上一帧的 dump。
3. 断言（全部进常规 gate，`FlowCanvasChecks`）：
   - `HalconControlChecks` 批 7（3 条，纯逻辑不依赖 HALCON）：锁定覆盖→选中清空 /
     钉住帧只是被流程筛选挡住时**不**清空（反向）/ 钉住帧被覆盖→清空。
   - `HalconControlChecks` 批 6 ⑤⑥（真窗口 + 像素尺子）：⑤ 活图 + 粗标注 → 非黑 99.61%（反证尺子量得到）；
     ⑥ 图 Dispose 后强制重画 → **非黑 0.000%**（改前约 0.3%：那条粗绿线 + 一行绿字）。
   - `PixelProbe` 新增 `NonBlackRatio`（3 通道先 `rgb1_to_gray`，**不要只看 R 通道**）。
4. 验证：
   - `FlowCanvasChecks`：**4083 通过 / 11 失败**，本轮新增 7 条全绿；
     11 条红全部来自并行会话新加的 `JudgeTablePlugin`（`[JT1]~[JT8]`+`[JT]`：动态端口 `输入=[] 输出=[]`）

## 五、踩过的坑

1. **"黑底 + 一行绿字"有两个不同成因**：批 1 是"图缩到亚像素"（文字随缩放移动），
   本篇是"帧已被释放"（文字**不随缩放移动**，且缩放救不回来）。判据：动一下滚轮看文字位置变不变。
2. **绿色标注在 R 通道里是 0**：统计"窗口里画了东西没有"必须 `rgb1_to_gray` 后按 >0 判，
   只看 R 通道会把绿字算成"没画"（本轮排查时被这个坑误导过一次，尺子因此写进 `PixelProbe`）。
3. **`UIThemeSmokeTest --gallery` 不在闸门里**（`run_gates` 只跑无参模式）：
   图集断言原本放这里等于"没有闸门"，所以三条断言最终落在 `HalconControlChecks`（在闸门内）。
4. **并发构建会把断言宿主打断**：`Modules\*.dll` 正在被重写时启动宿主，会在"枚举插件"那一步
   直接死掉（本轮实测两次：一次停在 G9 分类映射、一次停在等待节点，日志截断且无异常栈）。
   **跑宿门前先确认 `Modules` 最新 mtime 稳定 ≥ 45s**。
5. **宿主的 exe 会在汇总后仍占着文件**：`FinishAndExit` 之前的那一瞬构建会报 MSB3027 文件锁，
   等几秒重试即可（不要以为是代码错）。
