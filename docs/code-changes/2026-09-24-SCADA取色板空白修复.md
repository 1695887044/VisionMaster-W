# SCADA 取色板空白修复（ContentControl 缺 Content 导致模板子树 DataContext 整棵为 null）

现场报「为什么选择颜色变成这样的了」，附运行态截图：属性面板「填充色 / 边框色」点开取色板，
**「色板」标题下有字无格**（40 个预设色格一个都没渲染）、「透明度」滑块贴最左且右侧读数框空、
「颜色（#AARRGGBB）」输入框空、其右侧预览小色块**连灰色兜底都没出现**，只有字面文字与
「取消 / 确定」按钮、弹窗底板与描边正常。

根因不在颜色值，而在**取色板模板内部的数据源整条断了**。

---

## 一、需求与决策

### 1. 需求

用户报障（逐字）：

> 「为什么选择颜色变成这样的了」

属**诊断性提问**。要求先讲清「为什么」，再谈修法；未批准前不得改仓库代码。

### 2. 根因

`ContentControl` **只给了 `ContentTemplate`，没给 `Content`**。

`ContentControl` 是个「壳」，它的模板里有一个 `ContentPresenter` 负责摆放内容，数据源是顺着
`ContentPresenter` 往下继承的：

| 层 | 给不给 `Content` | `DataContext` |
|---|---|---|
| `Grid`（属性行容器） | — | 行 VM |
| `Popup` | — | 行 VM（照常继承） |
| `ContentControl` | **不给** | 行 VM（自己这层没事） |
| `ContentPresenter` | — | **null ← 断在这里** |
| `StackPanel` → `TextBlock` / `ItemsControl` | — | null（绑定全静默失效） |

于是：

- 字面量文本（「色板」「透明度」「颜色（#AARRGGBB）」「取消」「确定」）不依赖数据，**照常显示**；
- 所有 `{Binding}` 静默失效 → `ItemsControl.ItemsSource = null`（色板 0 格）、
  `Slider.Value` / 读数 `TextBlock.Text` / 十六进制 `TextBox.Text` 全空；
- 预览块绑 `ColorDraftBrush`，该属性**有灰色兜底** `FallbackSwatch`（见 `ScadaPropertyViewModel.cs`），
  **连兜底都不出现** ⇒ 证明绑定根本没执行，而不是「返回了空值」。

### 3. 关键决策（已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 是否落修 | **只落修，暂不补断言**（用户逐字选定） | 先让取色板能用；`ScadaChecks` 对取色板的回归覆盖留待以后 |
| 2 | 修法 | 两处各加 `Content="{Binding}"` | 把宿主自己的 `DataContext` 显式交给 `ContentPresenter`，链条接回；`ContentPresenter Content="{Binding}" ContentTemplate="..."` 是等价写法 |
| 3 | 是否加注释 | 加 | 这类失效**不报错、不写绑定日志**，只靠肉眼极难发现，必须在现场留一段说明 |

## 二、修改文件清单

| 文件 | 位置 | 改动 |
|---|---|---|
| `VisionMaster\Views\ScadaPropertyView.xaml` | L351（属性行弹窗） | `<ContentControl ContentTemplate="{StaticResource ColorPickerBody}" />` → 加 `Content="{Binding}"`；补 3 行说明注释 |

两处**共用同一份 `ColorPickerBody` DataTemplate**，所以两处同时坏、也同时修好：

同文件 [L596-605] 的 `Content="{Binding ForegroundSlot}"` + `ContentTemplate` 是现成的**正确对照**。

## 三、验证结果

### 1. 离屏实证（临时工程，不入仓库）

用与取色弹窗**同构**的 `net9.0-windows` + `UseWPF` 离屏窗口（`Grid(DataContext=VM) > ToggleButton + Popup > ContentControl`），
把弹窗视觉树逐层打出来：

```
① 现状（不给 Content）
  ContentControl      DC=DC
    ContentPresenter  DC=<null>      ← 断在这里
      StackPanel      DC=<null>
        TextBlock     DC=<null> Text=''
        ItemsControl  DC=<null> ItemsSource=<null>

② 修法（Content="{Binding}"）
  ContentControl      DC=DC
    ContentPresenter  DC=DC
      StackPanel      DC=DC
        TextBlock     DC=DC Text='DC'
        ItemsControl  DC=DC ItemsSource=3 项
```

**教训**：验证控件渲染行为必须复刻「宿主容器」。只测孤立的 `ContentControl`（无 `Popup`）
会得出「模板根本不实例化」的错误结论 —— 加上 `Popup` 后模板**会**实例化，只是整棵子树 `DataContext = null`。

## 四、已知边界

1. **取色板目前零回归覆盖**。`ScadaChecks\Program.cs` 里搜 `ColorPalette` / `ColorDraft` / `EditColor` /
   `PaletteCell` / `取色` **均无结果** —— 这正是它能一路空着活到今天没被拦住的原因。
   本次按用户口径**暂不补断言**，后续若再动取色板，建议优先补：打开弹窗后数色格数、读十六进制框文本、
   校验预览块拿到的是真颜色而非空。
2. **同类写法未全仓排查**。本次只核对了 `ContentControl` + `ContentTemplate` 组合：
   全仓仅 L351 / L500 两处漏 `Content`，已修完。若将来新增同类宿主，需注意同一坑。
3. **属性面板宽度疑问（约 110px）** 仍未定位。与本次取色弹窗「228 宽几乎铺满可视区」可能同源
   （弹窗偏移基于偏小的可用宽度），也可能只是窄面板的正常表现 —— **本次未定论**。
4. `Content="{Binding}"` 是「把宿主 DC 显式传给 `ContentPresenter`」。若将来某个宿主需要给模板
   传**别的**对象（而不是宿主自己），要改用具体绑定路径，不能照抄。
