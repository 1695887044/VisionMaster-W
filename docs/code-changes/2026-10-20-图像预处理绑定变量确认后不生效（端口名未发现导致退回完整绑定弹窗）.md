# 2026-10-20 · 图像预处理「选择绑定变量 → 确认」后不立刻生效（端口名未发现 → 退回完整绑定弹窗）

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-10-20 |
| 现象 | 图像预处理配置窗里点「图像路径」行尾的 🔗 → 在变量绑定弹窗里选好上游（图像采集_0.Image）→ 点「确认」，弹窗关掉后**那一行仍显示「需链接变量」**；关掉配置窗重新打开才看到绑定地址 |
| 影响面 | 所有"自带配置视图 + 用 `LinkableValueEditor`"的插件，**前提是步骤还没点过一次「确定」**（`InputValues` 为空） |
| 修法 | `VisionPluginBase.Initialize(IStepConfigData)` 开头补一次 `EnsurePortsDiscovered()` |
| 守门 | `FlowCanvasChecks\VariableBindingCheck.cs` 的 `RunFreshStepPortNameContract()`（2 条，进常规 gate 基线） |

## 一、根因链（每一环都有源码位置）

1. `LinkableValueEditor.LinkBtn_Click`（`Shard\Core.Controls\LinkableValueEditor.xaml.cs:368-385`）发布
   `LinkPathEvent { InputPortName = port.Name, OnBound = … }` —— **端口名是这次回传的唯一钥匙**。
2. `port.Name` 不是插件作者写的：`InputPort<T>` 用 `new()` 声明时 `Name` 为 `null`
   （`DataPort\InputPort.cs:66/:196`），由 `VisionPluginBase.EnsurePortsDiscovered()`
   （`VisionPluginBase.cs:352`）反射按属性名补上（`:357-361`）。
3. 配置会话里唯一可能触发这次发现的路径是 `ApplyConfigValues` 的灌值循环
   （`VisionPluginBase.cs:247-272`，循环体里访问 `Inputs`）。
   **新建步骤的 `InputValues` 是空字典**（`StepFactory` 造 `ActionStep` 时没有种子值），
   循环一次都不跑 → `Name` 一直是 `null`。
4. `ProcessViewModel.OnLinkPathEvent`（`VisionModel\ViewModels\ProcessViewModel.cs:534-541`）拿空端口名走
   兼容分支：`dialogService.ShowDialog("DataBindView")` —— **完整绑定弹窗**，不带 `IsSingleBindMode`。
5. 完整模式下 `VariableBindingViewModel.Confirm()` 直接写活模型（`SetLink`），**没有任何回调**；
   `LinkableValueEditor` 既没收到 `OnBound`，也不监听 `StepData.LinkedSources`，
   于是界面上仍是"需链接变量"。
6. 用户点配置窗「确定」时 `OnConfirm` 遍历 `Inputs` → 这时才补上端口名，并把 `DisplayViewIndex / Chain`
   写进 `InputValues`；**下次打开**配置窗时灌值循环跑起来 → 端口名就绪 → `RestoreLinkState()`
   读得到 `GetLinkedAddress("SrcImage")` → 地址回显。这就是"重开才生效"的由来。

## 二、证据

**截图旁证**：用户截的弹窗副标题是「图像预处理_0 · 1 个输入端口 · 已绑定 1 个」——
这是**完整模式**的文案；单绑定模式的文案是「插件视图请求绑定 · 选定后立即返回」
（`VariableBindingView.xaml.cs:523-526`）。也就是说 🔗 确实发出了空端口名。

**最小复现（`_BindProbe`，仅引用 `Core.Interfaces`）**：

```
before Initialize: Name = <null>
after  Initialize: Name = <null>          ← 修前
Initialize with non-empty InputValues: Name = SrcImage
```

修后同一探针输出 `after Initialize: Name = SrcImage`。

## 三、修法

`VisionPluginBase.Initialize(IStepConfigData)`（`:278-290`）开头补一次 `EnsurePortsDiscovered()`：

- 位置选在**配置会话入口**而不是 `Inputs` getter 里做隐式发现：`Inputs` 是公共面，
  调用方可能在插件还没完成构造时就取；`Initialize` 是"宿主把 stepData 交给插件"的唯一起点，
  所有 15 个重写 `Initialize(IStepConfigData)` 的插件都调了 `base.Initialize`（已逐个核对）。
- 幂等（`_isPortsDiscovered` 布尔短路），且 `AddDynamicInput` 本来就先调它，
  动态端口插件的顺序不变。
- 插件工程**不需要重建**：`VisionPluginBase` 在 `Core.Interfaces.dll`（共享契约），
  由宿主提供，插件 DLL 不内嵌它。

## 四、守门

`FlowCanvasChecks\VariableBindingCheck.cs` 新增 `RunFreshStepPortNameContract()`（`:294`）：

1. 用例前提：`new ActionStep(...)` 的 `InputValues.Count == 0`（否则这条路径根本没被走到）；
2. `PreProcessingPlugin.Initialize(空步骤)` 之后 `SrcImage.Name == "SrcImage"`。

**变异反证已做**：把 `EnsurePortsDiscovered();` 注释掉重建 → 全量 gate 从 `2865/0` 变成
`2864/1`，失败的正是第 2 条（`SrcImage.Name=[<null>]`），其余断言不受影响；恢复后回到 `2865/0`。

## 五、边界与未决

- **只修"端口名为空"这一支**。若某个第三方插件重写 `Initialize(IStepConfigData)` 且不调 `base`，
  仍会落回完整绑定弹窗（本仓无此实例）。
- 完整模式本身仍是合法入口（流程栏/画布发起的绑定），它写模型后**不通知任何插件视图**——
  这是设计使然（完整模式面向"当前步骤"，不面向某个编辑器）。本批没有给它加广播。
- 预览画面不会因为这次绑定立刻出图：配置实例的 `SrcImage.LinkedSource` 只在试运行/正式运行时
  由 `FlowCompiler` / `PluginTestRunner` 接上，与本次修复无关。
- 本轮构建期间仓库有另一进程在改 `IExecutionContext`（新增 `SharedVariables`）与
  `Plugin.CSharpScript\ScriptSharedVarDef.cs`，中途出现过与本次改动无关的编译错误；
  最终以 `Core.Interfaces` 单独构建 0 错误 + 变异前后 gate 结果为准。
