# SCADA 画布取景被推出视口修复（`CenterAxis` 负 Offset）

- 日期：2026-09-18
- 范围：`ScadaCanvas` 取景计算（`FitToScreen` / `ZoomToActualSize` / 首次布局居中）
- 相关：`docs/code-changes/2026-09-18-SCADA运行态地基.md`（同一阶段，但那是**布局槽裁剪**，本条是**取景偏移**，两个不同的 bug）

## 一、需求与决策

### 现象

打开一个 1920×1080 的画面，**画布一片空白、图元一个都看不见**；
但数据一条没少、`ItemsSource` 里 5 个图元都在、`RenderSize` 也对。
编辑区约 1560×800 时**必现**。

### 根因

取景偏移的算式是"画面放不下时也硬居中"：

```
Offset = (视口 - 画面 × Zoom) / 2
```

画面比视口大时这个值是**负数**，等价于把画面左上角推到视口左上角之外。
而组态画面的图元习惯从**左上区**开始摆，于是整幅画面被推出可视区，
只剩贴着视口左边缘的一条窄带——用户看到的就是"画布空白、图元不见了"。

更糟的是：首次布局居中挂在一个**单向闩锁**（`_centeredOnce`）上，写坏一次**永不再纠正**，
所以症状会一直持续到用户手动点"适应"或"实际大小"。

### 决策

**单轴取景：画面放得下就居中，放不下就贴视口左上角（返回 0）。**

```csharp
private static double CenterAxis(double viewport, double page)
{
    double slack = viewport - page;
    return slack > 0 ? slack / 2 : 0;
}
```

理由：放不下时贴左上，是**唯一可预期的取景**——1:1 就该从 (0,0) 开始看，
而不是"从负半屏开始看"。这也与商用组态软件的手感一致（画面大于视口时默认看左上角）。

## 二、修改文件清单

| 文件 | 改动 |
|---|---|
| `Scada.Controls\Canvas\ScadaCanvas.cs` | 新增 `CenterAxis(viewport, page)`；`CenterPage()` 改用它；`FitToScreen()` / `ZoomToActualSize()` 因此一并修好（两者都汇到 `CenterPage`）。注释写明"为什么不能无条件套 (视口-画面)/2" |

## 三、验证结果

```
dotnet run --project ScadaChecks → 通过 554 / 失败 0
```

`[X]` 画布渲染组新增 2 条断言，专门钉这条路：

| 断言 | 口径 |
|---|---|
| 画面比视口大时取景贴左上 | `Offset.X >= 0 && Offset.Y >= 0`（实测 `Offset=(0,0)`） |
| 1:1 取景后左上区图元落在视口内 | 按钮左上角视口坐标落在 `[0, 视口)` 内 |

**断言为什么走"实际大小"这条路而不是只看首次布局**：`OnRenderSizeChanged` 在断言环境里是否触发并不确定，
靠它会让断言在回归时"假装通过"。`ZoomToActualSize()` 是**确定的**、也正是用户复现该症状的那条路。

另有 ①-3 段 2 条断言单独钉**首次布局**这条路（真机启动时用户没点任何按钮，走的就是 `_centeredOnce` 那一次），
用独立的 `NewCanvas()` 工厂——`_centeredOnce` 是单向闩锁，一个实例只能走一次"首次布局"。

## 四、已知边界

1. **"放不下就贴左上"没有留呼吸边**：这是刻意的，与 `FitToScreen()` 的 24px 呼吸边不冲突——
   前者是"画面比视口大"的兜底，后者是"主动适应"的取景。
2. **`_centeredOnce` 仍是单向闩锁**：用户手动平移过之后重排窗口不该把画面弹回去，这是有意为之。
   但如果将来要加"重置视图"，得显式把闩锁清掉，不能指望尺寸变化触发。
3. 本修复只保证"打开就能看见"，**不保证所有图元都在视口内**——画面大于视口时本来就看不全，
   这是取景器的正常语义，用户应点"适应"。
