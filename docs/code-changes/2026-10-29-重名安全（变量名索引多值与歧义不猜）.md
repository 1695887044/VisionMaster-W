## 1. 当前状态

变量名索引从"单值 + 先出现者赢"改为**多值 + 歧义不猜**：

| 入口 | 改前 | 改后 |
| --- | --- | --- |
| `FindByName(name)` | 重名时返回集合里靠前的那个 | 唯一命中才返回；0 个或 >1 个都返回 `null` |
| `FindAllByName(name)` | 不存在 | 新增：返回全部同名（用户表优先，系统表兜底），返回快照数组 |
| `FindById` / `Resolve(带Id)` | 精确 | 不变（探针 C1.5/C1.7/C3.2） |
| `TryRename` 查重 | 单值比对 | 多值列表里"有别人"即拒；唯一性口径**未变**（C6.2/C4.1） |

**为什么改**：名字重复（多设备同名点位、手改 .vms）时，任何"空 Id + 名字"的读写都会落到第一台设备且不报错。批 1 只做"不再猜"——名字重复时**明确失败并说清重复在哪几台设备**，唯一性口径与导入/新建/改名的拦截规则一律不动。

歧义文案统一由 `VariableNameAmbiguity` 生成：
`变量名「Alarm[90]」在 2 个变量上重复（设备 L1 / 设备 L2），无法按名确定目标；请改用变量绑定（按变量身份寻址），或给变量改名区分`

## 5. 踩过的坑

1. **既有断言钉着旧契约**：`ScadaChecks/Program.cs` 里有一组"重名以集合中靠前者为准"的断言，改 `FindByName` 必然打红它。这是**规格变更**（用户明确要求"歧义不猜"），不是"改断言凑绿"——已在断言里写明变更日期与理由，并补了"改走一个后恢复唯一命中"的反向断言。
2. **并行会话造成的假红**：第一次跑 `ScadaChecks` 出现 2 项失败（`[SY12]` 事件数 4≠2、按钮 27 行≠23 行），与本改动无关——同一台机器上另一个会话正在改 SCADA 图元事件（`ProcessSymbolChecks.cs` 于 20:36:18 被改、exe 于 20:37:45 重建），断言源当时还没跟上。重建后复跑 3254/0。**遇到"看起来无关的失败"先看 `LastWriteTime`，别急着改自己的代码。**
3. **`Count` 的语义没动**：它统计 Id 索引数量（`_byId + _systemById`），重名不会让它变；想数"用户变量多少个"要自己遍历集合。
4. **多值索引必须四路一致**：`Rebuild`（全量）、`AddToIndex`（增量 Add）、`NotifyRenamed`（改名）、`AddToSystemIndex`（系统源）任何一路漏了，都会出现"增量能查到、重建查不到"的分裂。四条路径现在共用同一对 `AddNameIndexEntry`/`RemoveNameIndexEntry`，探针 C9.5 专门盯这一点。
5. **移除时不能整键删**：`RemoveNameIndexEntry` 按引用移除、列表空了才删键；否则同名的另一台设备会跟着消失（探针 C2.5/C9.6）。
