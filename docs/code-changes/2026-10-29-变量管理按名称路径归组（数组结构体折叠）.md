## 二、已做

### 为什么不能合成"真数组变量"

原设想是导入时把 `Alarm1[0..99]` 合成一个 `bool[100]`（基址 + 长度），这样轮询还能少读几次。
**实测数据否掉了这条路**——元素地址步长不等于元素大小：

| 组 | 类型 | 元素数 | 实测步长 | 若按连续数组读 |
|---|---|---|---|---|
| `Alarm1` | bool | 100 | 1 | 勉强对 |
| `PlcActTime` | short | 6 | **16** | 读错 |
| `DeviceModeTime` | int | 5 | **32** | 读错 |
| `保存记忆` | float | 30 | **32** | 读错 |
| `RCS=>PLC` | short | 20 | 1（其中一跳是 7） | 读错 |

PLC 侧每个成员按 16 字节边界分配，而现有地址模型只有"基址 + 长度"，没有 stride/packing 概念。
合成真数组 = 读错内存，且要动公共契约（R12 大改动）。所以归组停在展示层。

### 归组口径（写进代码注释的三条边界）

1. **只归网络变量**：本地变量名是用户随手起的；系统变量本来就有 `System.Motion.X` 层级且已由
   `ISystemVariableContainer` 展开，再套一层只会重复。
2. 名字里没有 `[i]` / `.` 的行**原样保留、位置不变**（`PLCVersion`、`下料小车到达RCS` 不受影响）。
3. **单链折叠**：`MessageLog` 只有一个成员 `Show` 时不留只含一行的空壳，直接把原变量行提上来
   （显示名仍是完整名 `MessageLog.Show`）。

另有一条兜底：`Foo` 与 `Foo.Bar` 并存时复用 `Foo` 那一行当容器，表里不出现两行同名。

### 归组成员行仍然可编辑

`IsChildNode` 现在覆盖到第 1 层以下，若继续拿它当"数组元素"用，归组后的普通变量行会
被当成只读元素（当前值变灰、操作列消失）。所以：

- 可编辑 / 数组根 / 元素行的判据统一改成 `ElementIndex >= 0`；
- `ShowRowActions` 改判"背后有没有真变量"，归组成员行保留复制 / 改名 / 删除；
- 复制变量名拿到的仍是完整名（`FullName` 存原名，`Name` 只放最后一段 `[1]`）。

### 搜索

旧实现是"扁平表 + 一个游标"，折叠时子行根本不在表里，搜 `Ints[5]` 一行都匹配不到。
现在按整棵子树判命中，并**自动展开命中路径**；父级已命中时不再剪枝
（搜"条码"命中数组根，它的 `[0]/[1]` 要跟着留下）。

## 五、踩过的坑

1. **`IsChildNode` 不只是"在别人下面"**：它在 XAML 里控制行高/字号/类型图标，在转换器里控制
   "只读元素行"，在 `ShowRowActions` 里控制操作列。改语义必须逐处确认，否则归组一开，
   普通变量行的当前值会静默变成只读。
2. **路径解析漏吃 `]` 后面的 `.`**：`Recipes[0].Ints[5]` 在 `[0]` 之后直接遇到 `.` 被判畸形，
   整个归组静默不生效（表现为"表里一行没变"）。段后分隔符要在**两种段类型**之后统一处理。
3. **搜索剪枝过狠**：一开始"不命中就剪"，搜"条码"命中数组根后子行全被剪掉，
   旧断言立刻抓住（`实际：Barcode`）。剪枝必须带上"祖先是否已命中"。
4. **断言宿主按下标取值**：一条失败后 `grouped[0]` 越界直接抛异常，整个宿主停在半路
   （后面 4000 多条一条没跑）。取下标前必须做安全回落。
