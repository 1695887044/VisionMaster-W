## 1. 需求与决策

按对标商业 SCADA 梳理文档的第一批（P0）开始实施，共 4 项：

| 项 | 问题 | 决策 |
|---|---|---|
| P0-1 | `UpdateValue` 对 `byte[]` 走 `Object.Equals` 引用比较，段读每轮切新数组 → 永不相等 → 每周期必触发 ValueChanged，几万点场景事件风暴 | byte[] 改为按内容逐字节比较 |
| P0-2 | 模拟量微抖动（123.456→123.457）每次都推送 | 引擎层增加变量级死区 `DeadbandPercent`（百分比），基准取"上次上报值"（对齐 OPC UA percent deadband 语义） |
| P0-3 | 值没有"新鲜度"概念：断线/读失败时 UI 仍显示旧值，用户无从分辨 | 引入三档质量戳 Good/Uncertain/Bad（对齐 OPC UA StatusCode 简化版），UI 用色点表达 |
| P0-4 | 转发 handler `OnVarChanged?.Invoke(this, new ...)` 中 `?.` 不阻止 `new` 先执行，零订阅时每秒白分配几万个事件对象 | 先判空订阅者再构造参数；同时确认业务全走变量级 ValueChanged 按点订阅，该能力天然就位 |

关键认知修正（相对梳理文档）：梳理文档写"NaN 永不相等"是**错的**——`Double.Equals(object)` 对 NaN 按 IEEE 语义返回 true。因此 P0-1 的真 Bug 只有 byte[] 引用比较一处，NaN 无需特判。

P0-3 UI 方案：用户取消提问，按推荐方案实施——**色点 + 打灰**（当前值胶囊内 4~5px 小圆点：绿=Good/黄=Uncertain/灰=Bad；Bad 时值文字打灰；保留最后已知值；不增加列宽）。

质量流转逻辑自查：
- 初始注册 → Bad（从未读到）
- 首轮轮询成功 → Good（首次值强制推送逻辑不受影响）
- 个别段读失败/解码失败 → Uncertain（保留旧值）
- 整链失败（Poll 全败）→ Worker 判通信故障断线 → 状态离开 Connected → Manager 批量标 Bad
- 重连成功 → 首轮轮询读到的变量自动翻回 Good
- 幂等保证：重复标记同一质量不触发回调，几万点断线只对"原本非 Bad"的变量发一次通知
