# 2026-10-21 通讯数组写入与字符串支持（数值 / bool / 字符串数组）

> 接续 `2026-10-21-通讯变量数值数组与地址偏移.md` 的第一期（数值数组只读）。
> 本轮把剩下的能力补齐：**数值数组整组写入、bool 数组（Modbus 位区）、字符串标量、字符串数组**，
> 并把变量管理里的网络数组根行从"只读"升级为「写入数组…」入口。
> 仍然不做：超长数组分块、数组逐元素工程量换算、S7 bool 数组、SCADA 图元直接绑数组。

---

## 1. 能力矩阵（本轮完成后）

| 类型 | 读 | 写 | 说明 |
| --- | --- | --- | --- |
| `int[]` / `double[]` / `float[]` | ✅ | ✅ | 整组替换；长度必须等于地址配置的 `Length` |
| `bool[]` | ✅ | ✅ | 仅 Modbus 线圈/离散输入；离散输入只读 |
| `string`（标量） | ✅ | ✅ | `Length` = 总字节数；ASCII + 尾部补 0 |
| `string[]` | ✅ | ✅ | `Length` = 元素个数，`ElementByteLength` = 每元素固定字节数 |
| `byte[]`（原始块） | ✅ | ✅ | 程序化路径支持；变量管理类型下拉未开放 |

---

## 2. 写链路

```
变量管理「写入数组…」 / 流程「立刻写」/ TryWriteToValue
  → NetworkVariableModel.TryWriteCore
      ① 数组：长度校验 + TryNormalizeArray（元素逐个归一到声明类型）
      ② 字符串：TryEncodeFixedString / TryEncodeStringArray（ASCII + 补 0）
      ③ 写租约（并行分支抢同一输出时明确拒绝）
      ④ CommunicationManager.WriteVariable / WriteVariableNow
        → 连接 Write
          → HslHelper.WriteTyped
            → HSL 原生数组重载（int[]/double[]/bool[]…）或 byte[]（字符串定长块）
```

三条硬口径：

1. **长度必须等于地址配置**：`AddressConfig.Length` 是设备点位跨度，短写会留下旧值、长写会覆盖邻居。
2. **元素逐个归一**：外部可能是 `object[]` / 字符串数组；用 `VariableValueConverter` 转成声明类型
   （布尔认 1/0、数值不变文化），与界面单值写入同一份规则。
3. **字符串定长**：写短补 0、写长明确失败；读回按 `TrimEnd('\0')`。ASCII 与既有字符串读写一致。

### 2.1 运行互锁

- 打开「写入数组…」前查一次 `FlowRunState.Running`。
- 弹窗确认时**再查一次**（弹窗是模态的，但定时/变量触发的流程仍可能在打开期间启动）。
- `Value` setter 的隐式写仍跳过数组：避免绑定/镜像赋值在不知情时整块覆盖设备数据。

## 3. 字符串宽度契约

`DeviceAddressBase` 新增 `ElementByteLength`（默认 0）：

| 变量类型 | `Length` 含义 | `ElementByteLength` 含义 |
| --- | --- | --- |
| 数值/布尔标量 | 固定 1 | 0 |
| 数值/bool 数组 | 元素个数 | 0 |
| `string` 标量 | **总字节数** | 0 |
| `string[]` | **元素个数** | **每个元素的固定字节数** |

`TotalBytes` 相应改为：

```text
String + ElementByteLength > 0  →  ElementByteLength × Length
其它                            →  TypeSize × Length
```

- 为什么不能复用 `Length`：String 的历史语义是"总字节数"，数值数组是"元素个数"；
  string[] 同时需要"元素个数"和"每元素宽度"两个数。
- 落盘：`VariableDto.ElementByteLength`，`BuildAddressConfig` 在 `DataType` 之后写回
  （`DataType` setter 会重置 `Length`，顺序反了数组会静默变回标量）。
- 规划器：字符串数组缺 `ElementByteLength` 时**明确跳过并记日志**，不硬解。

## 4. UI

### 4.1 网络数组根行

- 可写区（保持寄存器 / 线圈等）：显示 `ArraySummary` + 「写入数组…」按钮。
- 只读区（离散输入 / S7 输入映像 I）：显示「只读」徽标，不出现写入口。
- 元素行仍然只读：整组写是唯一写语义，单元素写会与"固定跨度"的配置脱节。

### 4.2 数组编辑弹窗（复用 `ArrayEditor`）

- 新增网络模式：`IsNetwork` / `ShowBaselineControls` / `CanEditStructure`。
- 网络模式隐藏「写入范围 / 基准」面板，元素个数固定为 `AddressConfig.Length`，不能增删/移动。
- 当前值还没到（第一拍轮询前）时「确定」禁用（`CanConfirm`）：否则空表直接确认会把整段设备数据写成 0。
  此时取消并等轮询到值后重开即可（不做"值到达自动填行"——那会在用户已经开始输入时覆盖草稿）。
- 确认时直接调用 `TryWriteToValue`；失败（离线、长度、超长字符串）在弹窗内显示原因，不关窗。
- 本地数组编辑的语义完全不变（仍可增删/移动/同时写基准）。

---

## 5. bool 数组

- 仅 Modbus 线圈/离散输入：`Length` = 点数，规划器按位区读 `bool[]`，写走 HSL `Write(address, bool[])`。
- 离散输入是只读区：UI 不出现写入口，`TryWriteCore` 也会拦。
- S7 bool 数组仍不支持：打包位 vs 每字节一个没有唯一语义，创建时明确报错。

## 6. 验证证据

### 6.1 `CommChecks`（292 通过 / 0 失败）

新增 C23（字符串 / bool 数组解码）：

- C23-1 字符串标量按定长 20 字节解码并去掉尾部 `\0`
- C23-2 字符串数组按 2 项 × 8 字节切分（ABC / DEF）
- C23-3 bool 数组按线圈 3 点解码（True / False / True）
- C23-4 字符串数组缺每元素字节数 → 不参与轮询且日志说明原因
- C23-5 方案落盘往返保留 `ElementByteLength`

新增 C24（写入编码）：

- C24-1 `object[] { "1", 2, 3 }` → `int[3]`
- C24-2 长度不一致 → 明确失败（不短写覆盖邻居）
- C24-3 `"1"/"0"/"true"` → `True/False/True`
- C24-5 `"ABC"` → 5 字节 `[65,66,67,0,0]`
- C24-6 字符串超长 → 明确失败
- C24-8 `["A","BC"] × 4 字节` → 8 字节逐项补零

## 7. 已知边界（仍未做）

| 项 | 原因 |
| --- | --- |
| 超长数组分块 | 单请求上限（Modbus 120 寄存器 / S7 110 字节）外仍直接拒绝；分块要处理跨段拼接、坏段隔离与部分失败 |
| 数组逐元素工程量换算 | Scale/Offset 对数组的语义未定；当前数组写入/读取都跳过换算，创建时也拒绝「启用转换」 |
| S7 bool 数组 | 打包位 vs 每字节一个没有唯一语义 |
| 非 ASCII 字符串 | 与既有 string 读写一致用 ASCII；中文/UTF-8 需要新增编码配置 |
| SCADA 图元直接绑数组 | 现有图元以标量为主；数组可通过流程 / `Arr[i]` 取元素 |
| 元素级单点写 | 整组写是唯一写语义；单元素写需要按元素地址 + 读改写互锁，暂不做 |
