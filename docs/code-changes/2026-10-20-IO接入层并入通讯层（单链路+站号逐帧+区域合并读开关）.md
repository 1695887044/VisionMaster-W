# IO 接入层并入通讯层（单链路 + 站号逐帧 + 区域合并读开关）

> 日期：2026-10-20
> 起因：用户提出「如果不加自定义 IO 功能，是不是就不需要 IO 这个功能了；所有 IO 都走标准协议，
> 只需要串口能轮询多从站、变量配置时能选要不要按区域一起读；以后自定义协议只要写驱动实现接口」。
> 项目未落地，可任意修改，故一次性把两层合并。

---

## 1. 为什么合并（不是"IO 改成走变量接口"，而是"只留一层"）

IO 接入层与通讯层各自持有一条物理链路：

| 层 | 链路单位 | 调度单位 |
| --- | --- | --- |
| IO 层 | `IoBusDescriptor` → 一个 `SerialPort` / 一条 TCP | `IoDeviceBase` 每设备一个 Worker 线程 |
| 通讯层 | `CommunicationConfig` → 一条 TCP / 一个 COM | `ConnectionWorker` 每连接一个线程 |

同一个 PLC（或同一台 Modbus 网关）两边各配一次，就是**两条 TCP / 两个 COM 互抢**。
更麻烦的是"通讯正在轮询时 IO 要插队"这个跨层优先级问题——它的根源不是锁不够好，
而是**同一物理链路上跑着两套调度**。

合并成一层后：

- 物理链路只有一条（一个端点 = 一条连接）；
- 轮询调度只有一套（`ConnectionWorker` 的读写分队列，写命令天然优先）——
  **"IO 插队优先"这个需求连同它的问题一起消失**，不需要额外设计。

## 2. 通讯层补了四件事（原 IO 层独有的能力）

### 2.1 站号逐帧生效（一条 COM 挂多从站）

`ModbusAddress` 新增 `Station`（0 = 跟随连接，1~255 = 显式指定）。地址串变成 HSL 富地址
`s=2;x=3;100`，**站号在组帧时写进帧头、应答按本次发出的站号校验**。

关键点：这**不需要改 `ICommunicationConnection` 契约**。交接书曾判断"必须加 `TryExchange(station,…)`"，
实际 HSL 的富地址已经支持逐帧站号：

- `DLL\HslCommunication\Core\Address\ModbusAddress.cs:98-100` —— 解析 `s=` 覆盖 `Station`
- `DLL\HslCommunication\ModBus\ModbusInfo.cs:181` —— 组帧时写 `(byte)mAddress.Station`
- `DLL\HslCommunication\ModBus\ModbusHelper.cs:60-62` —— 应答按**发出帧的站号**校验

**必须同时改 `GroupKey`**：`PollBatchPlanner` 按 `(Protocol, GroupKey)` 分组，
GroupKey 不含站号时两个从站同地址的变量会被合并成一段——一次 FC3 只发给一个站，
另一站**静默读到错值**。故 `GroupKey = "s=2;FC3"`、`SegmentPrefix = "s=2;x=3;"`。

顺带修掉：`ReadBits` 原来用 `address.StartsWith("x=2;")` 判离散输入，带站号后前缀不在开头，
会把 FC2 当 FC1 发。改成 `ModbusRichAddress.IsDiscreteInput`（按 `x=` 段解析）。

### 2.2 逐变量「区域合并读」开关

`CommunicationVariable.MergeAdjacentRead`（默认 true = 行为不变）。

关掉的效果：**只读本变量自己的跨度，不把邻居一起读回来**；仍走段读（自己的跨度一次读完、
按结构化解码），不是退回单点反射读。

实现要点：段归属在合并时**钉死**（`ReadSegment.Owned`），不再事后按"区间包含"反推——
反推在"关合并的变量落在跨多寄存器邻居的跨度内"时会挂错段，留下一个空段每轮白发一次请求。

### 2.3 工程量换算（读写对称）

`DeviceAddressBase` 里的换算管道（`EnableConversion` / `Scale` / `EngineeringOffset` / `DecimalPlaces` /
`ConvertToEngineering` / `ConvertToRaw`）**一直存在，但只有写路径调了 `ConvertToRaw`**，
读路径从没调过——于是"配了缩放系数的变量写进去是工程值、读回来却是原始值"。

现在 `PollBatchPlanner.PublishValue` 走 `variable.ToEngineering(value)`。
默认 `EnableConversion=false`，不配换算的方案行为零变化。

### 2.4 坏段隔离（逐连接开关，默认关）

`CommunicationConfig.IsolateFaultedSegments`（默认 false）。开启后：连续失败达 3 轮的段
移出正常轮询、改为每 5 秒探测一次，探测成功即自愈。

**为什么默认关**：默认"每轮都试"是既有契约——诊断面板的"连续失败 N 轮"靠每轮真读才累加得出来
（C12 组钉住这条）。隔离只给"快周期 + 单个恒坏地址"的病态场景用（50ms 周期下一个坏地址
每轮烧满读超时会把同组其它变量一起拖到 5 秒一拍）。

实现要点：跳过隔离段时**不顺延** `NextProbeTicks`——顺延会让探测时刻一直往后推、永远不到期。

## 3. 驱动注册表：自定义协议只写一个类

改造前新增协议要同时改 6 处（`CommunicationType` 枚举 / `TryCreateConfig` switch /
`CommunicationProtocols.Implemented` 数组 / 配置类 / 连接实现 / `RegisterDefaults`），
且"清单与工厂一致"只靠一条断言手工钉着。

现在：实现 `ICommunicationDriverFactory`（`DriverId` 字符串 + 显示名 + 配置类型 + 造连接）并注册一次。
`ConnectionFactoryManager.Drivers` 是唯一真相源，内建三协议也走同一张表。

## 4. 写租约迁到 Core（与协议无关）

`IoOutputLeaseRegistry` / `IoWriteScope` → `WriteLeaseRegistry` / `WriteScope`（`Core\Services\`）。
键是字符串 `{连接名}.{变量名}`，所以 Modbus / S7 / 自定义驱动共用同一套仲裁。

`NetworkVariableModel` 新增 `AllowSharedWrite` / `LeaseTimeoutMs` / `LeaseRegistry`，
`TryWriteToValue` 在写设备前先取租约：并行分支抢同一个输出时**后者被明确拒绝**，
而不是"最后写入者赢"。

## 5. IO → 通讯的配置折算（两层拆分）

`SolutionModel.IoBuses` / `IoDevices` 保留不删（回退旧版本仍能读到配置），加载方案时一次性折算：

- 一条总线 → 一条连接（TCP → ModbusTcp；串口 → ModbusRtu）
- 一个点位 → 一个网络变量（命名 `{设备Id}.{点位Id}`）
- 站号（`DriverConfigJson.UnitId`）→ `ModbusAddress.Station`
- Scale/Offset/Unit → 换算参数
- AllowSharedWrite / LeaseTimeoutMs → 写租约开关

**为什么分两层**：草稿在 `Core.Interfaces`（`IoMigrationPlanner`）算——那里能看到 IO 描述符；
真实对象在 `VM.Communication`（`IoMigrationApplier`）造——因为 `CommunicationConfig` / `ModbusAddress`
在 Communication 程序集，而 **Core 引用不到它**（依赖方向不允许反过来）。
`SolutionService.IoMigrationHook` 是宿主注入的接缝。

幂等：同名连接已存在则跳过该总线（C27-8/C27-12 钉住）。

## 8. 断言抓出的两个真 bug

1. **存储区索引错位一格**：折算时把"保持寄存器"写成索引 2（那是 `InputRegisters`），
   模拟量会被当输入寄存器读（只读区），**写回必然失败**。C27-4 抓到，改为 3。
2. **隔离永远不到期**：最初在"跳过"分支里顺延 `NextProbeTicks`，导致每轮都往后推、永不探测。
   C25-2/C25-5 抓到，改为只在失败达阈值时设置。

## 9. 已知边界

- **S7 设备折算**：`S7Address` 的结构化解析依赖字符串路径，折算时 `AddressConfig` 留 null、
  由 `PollAddressResolver` 解析西门子语法。IO 侧 S7 的机架/槽位是设备级配置，通讯层是连接级——
  一台 PLC 一条连接，多 PLC 需在方案里配多条连接。
- **IO 与通讯的周期合并**：IO 每设备有 `PollGroups`，合并后只能取一个连接级周期（取最短的那个）。
  需要多节拍时用通讯层的**扫描组**（按变量分组，比设备级更细）。
- **`VariableType.Io` 枚举值保留**：`IoVariableModel` 已删，该值不会再产生；保留是为了不打断
  已落盘的整数值与既有分支判断（枚举只能追加）。
- **并发编辑提醒**：本轮实施期间 `Charts\VM.Charts\ChartView.cs` 与 `VisionMaster\ShellViewModel.cs`
  曾被其它任务并发修改并短暂打破构建，均已等其稳定后重试，未强改对方文件。
