# 报警条默认尺寸改 36 + 状态色令牌落地

日期：2026-10-26　状态：完成；`ScadaChecks` **3070 通过 / 0 失败**

## 一、报警条新实例默认高度 140 → 36

跑马灯是默认形态，单行 36px 就够；140px 是"卡片列表"时代的高度，留着会让新拖进来的报警条空一大块。
**只影响以后拖入的新图元**：老工程 `.vms` 里存着各自的高度，不会被改动。

同步改了那条既有断言（"默认尺寸 320×140：装得下五行"→ `320×36`）。

## 二、状态色令牌落地（HmiState*）

`ScadaTokens.xaml` 新增五个：

| 令牌 | 取值 | 语义 |
| --- | --- | --- |
| `HmiStateRunningBrush` | `#FF22C55E` | 运行 / 使能 |
| `HmiStateStoppedBrush` | `#FF64748B` | 停止 / 失能 |
| `HmiStateWarningBrush` | `#FFFFB020` | 警告 |
| `HmiStateFaultBrush` | `#FFE03A2B` | 故障 / 报警 |
| `HmiStateUnknownBrush` | `#FF4B5563` | 断线 / 未知（新增语义） |

**断言** `[ST1]`（`ScadaChecks/StateTokenChecks.cs`）：直接读 `ScadaTokens.xaml` 文本，
五个键必须在、取值必须等于约定值。用文件判据而不是取资源，因为断言宿主不保证加载了 SCADA 主题字典；
令牌本来就是"唯一事实源"，看文件就够。

## 三、这一版**没有**做的（重要）

**各图元的颜色默认值还没改成引用令牌。** 现状是 `[ScadaProperty(DefaultValue = "#FF34C759")]`
这种**字面量**——特性参数只能写常量，不能引用 XAML 资源。要真正"改令牌全局生效"，需要：

1. 图元颜色属性**不在创建时烤入局部值**（DP 默认值 = 令牌 Brush）；
2. 属性面板加「恢复主题默认」（清掉局部值）；
3. 把 `[ST1]` 从"令牌存在"升级成"**每个图元颜色属性的默认值 = 对应令牌值**"。

第 3 条是关键闸：没有它，令牌改了、图元默认值还是老颜色，界面不会变，也没人会发现。

**当前的实际效果**：令牌表就位、值有断言兜底；但**改令牌不会改变已存在的图元外观**——
它们仍用各自的字面量默认值。这一步是下一步的事，不假装已经生效。

## 四、用户的另一个问题（已回答）

"HmiState* 一处改所有状态色统一，我在组态时还能改状态色吗" → **能**。
令牌只是默认值，图元自己的颜色属性保留，局部覆盖全局、随 `.vms` 走。
评审结论是"默认统一、允许覆盖"，不是"锁死"——不能为了统一去覆盖现场调过的颜色。
