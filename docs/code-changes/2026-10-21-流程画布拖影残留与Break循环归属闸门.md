# 流程画布：工具箱拖影残留 + Break/Continue 落点闸门

> 日期：2026-10-21 ｜ 范围：VisionMaster 流程画布 / 流程栏 / 工具箱拖放 ｜ 状态：已实现，`FlowCanvasChecks` 3183 通过 / 0 失败，两处变异反证通过

## 1. 背景（真机两问）

用户截图反馈两件事：

1. **拖影不消失**：把工具箱条目拖到流程画布、落下之后，那个白底蓝边的胶囊（截图上写着 `Continue`）留在落点，再也不走；之后再拖别的条目，胶囊内容也不跟着变。
2. **Break / Continue 的归属**：「跳过（Continue）/ Break 应该只能放循环容器里吧」——截图里 `Break_0` / `Continue_0` 是主流程顶层的兄弟节点（不在任何 For/While 里）。

## 2. 根因

### 2.1 拖影残留：gong 的预览 Popup 只由它自己的放置端关闭

- 工具箱是 **gong-wpf-dragdrop 4.0.0** 的拖拽源（`ToolView.xaml` 的 `dd:DragDrop.IsDragSource="True"` + `DragAdornerTemplate`）。
- 反编译 `GongSolutions.WPF.DragDrop.dll` 4.0.0 证实：4.x 的拖影**不是 Adorner**，而是 `internal class DragDropPreview : Popup`，由 `DragDrop` 的**私有静态字段** `dragDropPreview` 持有。它只在三处被关闭：
  1. `DropTargetOnDrop`（gong 自己的放置端 `Drop` 处理器）**开头无条件** `DragDropPreview = null`（属性 setter 会 `IsOpen=false` 关掉旧 Popup）；
  2. `DoDragSourceMove` 里 `DoDragDrop` 返回 `DragDropEffects.None`；
  3. 下一次给该静态属性赋新值时先关旧的。
- 画布此前用的是**裸 WPF 拖放**：`AllowDrop="True"` + `DragOver="OnEditorDragOver"` + `Drop="OnEditorDrop"`。它不是 gong 的放置端 → ① 永不执行；而落子成功时 `e.Effects = Copy`，`DoDragDrop` 返回 Copy → ② 也不执行。于是预览 Popup 永远停在落点。
- **附带的第二个症状**：`UpdatePreviewPresenter`（刷新胶囊内容的唯一调用点）在 `DropTargetOnDragOver` 里，同样只在 gong 放置端路径上执行。所以胶囊内容永远停在**第一次**拖的条目上——截图里最后加的是 `Return_0`，胶囊却写着 `Continue`，正是这条。

### 2.2 Break/Continue：运行期是"Warn + 忽略"，编译期不能改成硬错误

- `CompiledNode.RunSequence`（`:255-264`）：`CurrentFlowState != Normal` 且当前层不消费控制流时，记一条 `Warn("…无循环归属…已忽略")` 后清零；`CompiledParallelNode`（`:351-361`）对分支顶层同样处理。
- 这条语义是**有意为之且被断言钉住的**：`LogicBruteforceChecks` 的 B2（顶层 Break/Continue 被忽略 + 后续照跑）、B4（Sequential 并行平铺按顶层孤儿处理）、`ParallelExecutionChecks` P17（并行分支顶层 Break 只终结本分支）。暴力测试的"合法图"口径也允许在嵌套 If 里放 Continue（没有循环）。
- 因此**不改成编译期 `[结构错误]`**（实测会打红 31 条既有断言：P17 + 26 张随机图 + B2/B4 四条语义断言），而是把规则收在**新增落点**上：拖入与粘贴不许把 Break/Continue 放到没有 For/While 包着的位置。

## 4. 关键决策

### 4.1 画布改走 gong 放置端，不用反射关 Popup

gong 4.0.0 **没有公开 API** 关闭预览；预览对象是私有静态字段。两条候选：

- 反射把字段取出来 `Popup.IsOpen=false`：违反 R59「反射只读、绝不写库的私有状态」，且换版本即静默失效；
- **走 gong 自己的放置端**（本次采用）：`IsDropTarget` 一开，`DropTargetOnDrop` 自然会在落子前关掉预览，顺带让 `UpdatePreviewPresenter` 恢复工作（胶囊内容跟着当前条目刷新）。

落点坐标仍由视图换算：gong 的 `IDropInfo.DropPosition` 是**相对放置目标元素**（= 编辑器）的屏幕坐标，换算 `图坐标 = ViewportLocation + 屏幕坐标 / zoom`——与 `NodifyEditor.GetLocationInsideEditor`（`args.GetPosition(ItemsHost)`）以及既有 `OnEditorPointerMoved` 同一条口径。

### 4.2 闸门判据与运行期语义逐字对齐

由近及远看容器链：**先撞到 For/While → 放行**；**先撞到 Parallel → 拒绝**（并行分支不把控制流传给外层循环，`CompiledParallelNode` 会吞掉）；**到顶 → 拒绝**。If/Case 只透传控制流，不算边界。

例：`For → Parallel → Break` 拒绝（外层 For 救不了它）；`Parallel → For → Break` 放行（最近的循环归属是内层 For）。

### 4.3 闸门收在 `StepFactory`，三条入口共用一份文案

画布拖入、流程栏拖入、粘贴三处都调用同一组纯函数，拒绝文案只有一份（`LoopControlPlacementMessage`）。编译期与运行期语义**一点没动**：旧图纸、共享子流程、Sequential 平铺照旧按 Warn + 忽略执行。

## 6. 已知边界（不是缺陷，别回炉）

- **只拦"新增落点"**：工具箱拖入画布、工具箱拖入流程栏、粘贴。把**已有**的 Break 从循环里拖出去（画布改序 / 流程栏移动）**不拦**——拖动已改坐标，回弹需要布局回滚；这类移动造成的无归属状态仍按运行期 Warn + 忽略。
- **旧图纸不受影响**：顶层 Break/Continue 照旧编译、照旧运行（Warn + 忽略），不会因为本次改动变成编译错误。
- **拖影内容刷新**依赖 gong 的 `DragDropPreview` 生命周期；若将来换掉 gong，`ToolView.xaml` 的四件套与画布的 `IsDropTarget` 要一起重审（FLC-23 会先红）。
