# 手眼标定：表尾采集进度条（Q2 落地）

> 日期：2026-10-23 ｜ 范围：`Plugins/Plugin.HandEye`（插件属性 + 视图 + 手册）、`FlowCanvasChecks/HandEyeChecks.cs`、设计基线 `docs/UI设计基线/hand-eye/README.md` ｜ 状态：已完成，`FlowCanvasChecks` 本段断言全绿

## 1. 背景

设计基线 v2 的 `§12` 里有一条待拍板项 **Q2「采集进度怎么显示」**，当时的推荐写法是"只显示「已录入 N 组 · 建议 ≥ 6 组」文字，不做实时进度条"。用户 2026-10-23 明确要求 **采集进度条做**。

顺带在实现过程中发现两个真问题（都不是"要不要加个进度条"层面的）：

1. **"组数"原来数的是行数，不是有效组数**。加了 7 行只填了 3 行时，文字会显示「已录入 7 组 · 建议 ≥ 6 组」，用户以为够了，一点求解却报第 4 行还没填。
2. **改一个数字不会刷新计数**。12 个分量各走 `SetProperty` 发 `PropertyChanged`，而插件原先只订阅了 `CollectionChanged`（增删行），所以"把空白行填上"这条路径既不更新计数、也不作废上次结论（后者已在持久化那轮修过，这轮补计数）。

## 3. 关键决策

1. **进度只认有效组**（12 个分量不全为 0 的行），判据与 `HandEyeSample.IsBlank` 同一份。不这么做，"进度条满了但一求解就报第 N 行还没填"会让用户认为工具在骗人。
2. **刻度固定 `HandEyeMath.RecommendedPairs`（6），刻意不跟 `RequireRecommendedPairs` 开关走**。那个开关问的是"少于 6 组要不要判失败"，进度条说的是"建议采几组"。绑在一起的话，关掉从严后 3 组会显示满格——正是最需要提示"再多采几组"的时候给了绿灯。
3. **空白行单独点名**（「另有 N 行没填」）。只显示"5 / 6"而不说为什么不到 6，用户会去数行数，然后发现行数是 7。
4. **不用默认 `ProgressBar`，也不用 `FluentProgressBarStyle`**。默认模板带 3D 斜面与渐变，与本页扁平卡片不是一路；`FluentProgressBarStyle` 在 `UI/Controls/Themes/Fluent/FluentControls.xaml:762`，但那个文件**不在** `UI/Controls/Themes/Generic.xaml` 的合并链上（链上只有 `Fluent/FluentAliases.xaml`），`StaticResource` 它会在解析期抛"找不到资源"。所以自绘 `ControlTemplate`，颜色全走既有令牌（R140：视图内零十六进制）。
5. **`RaiseSampleStatsChanged()` 一处实现、四处调用**，而不是各调用点各推几条。6 个派生属性分散着推，迟早漏一个——本轮就漏了 `ValidSampleCount` 系列。

- `进度①：空表 → 0 组、进度 0、未达建议，文案说「还没有成对数据」`
- `进度②：3 行填了 + 1 行空着 → 有效 3 / 6（半格），空白行单独点名`
- `进度③：6 组有效 → 满格、HasEnoughSamples=true（进度条由主色转绿）`
- `进度④：关掉「要求 ≥ 6 组」也不改进度刻度（3 组仍是半格）`
- `进度⑤：把空白行填上一个数 → 有效 4 组、进度跟着涨（行级通知生效）`
- `进度⑥：删掉一行有效数据 → 有效 3 组、进度回落`

### 一个被断言抓到的真实事故：栈溢出

第一版实现里，我用 `replace_all` 把 `OnSamplesCollectionChanged` 中成对的 `OnPropertyChanged(HasSamples)` / `OnPropertyChanged(SampleCountHint)` 两行替换成新的 `RaiseSampleStatsChanged()` —— **这一替换同时命中了新方法自己的方法体**（它开头本来就是这两行），于是 `RaiseSampleStatsChanged()` 第一句调自己。表现为断言宿主直接崩：

```
Stack overflow.
Repeated 24074 times:
   at Plugin.HandEye.HandEyePlugin.RaiseSampleStatsChanged()
   at Plugin.HandEye.HandEyePlugin.OnSamplesCollectionChanged(...)
   at ...ObservableCollection`1.add_Item(...)
```

修法是把那两行还原成真实通知，并在方法体里留注释写明"这里不能再写 `RaiseSampleStatsChanged()`，曾经被 `replace_all` 换成了自调用"。**教训：`replace_all` 之前先确认目标串没有被新代码自己也用一份。**

## 5. 边界与未做

- **不做"实时采集进度"**：本插件没有自动采集循环，只有手填 / 粘贴 / 导入 CSV，不存在"进行中"这个状态，进度条的语义是"已采够没有"。
- **进度条没有独立截图证据**：视图探针已随上一轮清理删除，本轮只由 6 条断言覆盖数据侧与 `HasEnoughSamples` 驱动的配色切换；`docs/UI设计基线/hand-eye/evidence/` 里的五张 PNG 仍是持久化那轮渲染的。
- **全量 `tools/run_gates.ps1` 未跑通**：`UIThemeSmokeTest` / `HelpProbe` 构建被另一会话正在编辑的 `VisionMaster/ViewModels/DialogViewModels/PluginConfigShellViewModel.cs`（`CS0234`）挡住，`FlowCanvasChecks` 另有 `Plugin.Database` 手册缺口 4 条。都不是本轮改动。
- 进度条复用了 `SampleCountHint` 作 `ToolTip`，两者文案因此完全一致；若以后要显示"还差几组"，需要拆成两个属性。
