# SCADA 变量选择弹窗空清单修复（`Keyword` setter 的短路）

- 日期：2026-09-18
- 范围：`ScadaVariablePickerViewModel.OnDialogOpened`
- 相关：`docs/code-changes/2026-09-18-SCADA写变量动作接通.md`（s6-6，本弹窗是该阶段新建的）

## 一、需求与决策

### 现象

「写变量」动作里点「选择变量」，弹窗打开后**列表恒为空**，
底部提示「当前方案里还没有变量。请先在「全局变量」里创建，再回来配置这条动作。」——
但方案里**明明有变量**。真机踩到。

### 根因

`OnDialogOpened` 里原本只写了一句"把关键字归零"，指望 setter 顺带刷新清单：

```csharp
Keyword = string.Empty;   // ← 靠副作用刷新，错在这里
```

首次打开时 `_keyword` **本来就是空串**，`SetProperty` 判定"值没变"直接返回，
`ApplyFilter()` **压根不跑**。结果：`_all` 装满了变量快照，而 `Variables`（界面上绑的那个投影）**恒空**。

一句话：**"清单投影"被藏在 setter 的副作用里**，而 setter 会因为"值没变"而短路。

### 决策

**把"清单投影"从 setter 的副作用里解耦出来**：归零关键字之后**无条件**调一次 `ApplyFilter()`。

```csharp
if (_keyword.Length != 0)
{
    _keyword = string.Empty;
    RaisePropertyChanged(nameof(Keyword));
}
ApplyFilter();   // ← 无条件，不依赖 setter 是否真的改了值
```

理由：`OnDialogOpened` 是"打开一次，重建一次"的生命周期钩子，
它**必须自己保证清单是新的**，不能把这件事托付给一个可能短路的属性 setter。

顺带保留了原有的正确行为：每次打开都重新取一份快照（两次打开之间用户可能增删过变量），
缓存跨弹窗复用会给出"清单里没有它，却怎么也选不上"的幽灵条目。

## 四、已知边界

1. **弹窗打开期间用户改了变量清单**（在另一个窗口增删变量）：本弹窗拿的是**打开那一刻的快照**，
   不会自动跟随。确认时若变量已删，执行侧走 `Warn`（找不到变量），不会静默失败。
2. **清单只列 `IWorkspaceManager.GlobalVariables`**：这是刻意口径——清单 == 运行态可寻址口径，
   保证"选得到就一定写得到"。流程内局部端口不在清单里。
3. 这类"setter 短路导致副作用不执行"的坑在本仓不止一处，写在这里当反面教材：
   **凡是要"无条件做一次"的事，不要挂在属性 setter 的副作用上。**
