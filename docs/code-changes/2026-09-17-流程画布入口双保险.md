# 流程画布入口双保险修复

**日期**：2026-09-17
**模块**：UI 布局恢复 + AvalonDock 停靠声明
**根因**：方案文件 `.vms` 的 `DockLayoutXml` 把 FlowCanvas 持久化到 `<Hidden>` 段；`LayoutXmlCoversAllPanels` 用 `Contains("ContentId=\"...\"")` 做覆盖度校验，Hidden 里的条目同样命中 → 校验放行 → 面板以隐藏态恢复，用户找不到任何标签入口。

## 需求与决策

| 选项 | 内容 | 效果 |
|---|---|---|
| A（采纳） | `CanHide=False` + `LoadFromString` 后兜底强制可见 | 双保险：源头禁止后续关闭，已持久化的 Hidden 旧布局也自动救回 |
| B | 仅 `CanHide=False` | 只防后续关闭，旧 vms 里已经 Hidden 的 FlowCanvas 仍不可见 |
| C | 仅加载后强制可见 | 救回一次，但用户之后手动隐藏又会被下次启动强制弹回，剥夺选择权 |

## 修改文件清单

1. **`VisionMaster/Shell.xaml`** L711：`流程画布` 停靠面板的 `CanHide="True"` → `CanHide="False"`
   - 与 `CanClose=False` 对齐：画布是核心工作流入口，和流程栏同 pane 作标签页，不允许关闭到 Hidden 区
2. **`VisionMaster/Services/LayoutHelper.cs`**
   - `LoadFromString`（原 L184）：`FillContents` 之后新增 `EnsureCriticalPanelsVisible(manager)` 调用
   - 新增字段 `CriticalPanelContentIds`：关键面板集合（当前含 `FlowCanvas` + `ProcessView`，工具箱在侧栏自动隐藏区是合法态，不动）
   - 新增私有方法 `EnsureCriticalPanelsVisible`：反序列化后遍历布局，对关键面板若 `IsVisible=false` 则强制 `IsVisible=true`，AvalonDock 会把它们从 Hidden 移回 RootPanel 中原来的 pane

## 验证结果

- `dotnet build VisionMaster/VisionMaster.csproj --no-restore` → **0 错误 / 711 警告（全部为既有 nullable 警告）**
- 静态证据：vms 文件第 6 行 `<Hidden>` 内明确含 `ContentId="Panel_FlowCanvasView"`，覆盖度校验（`string.Contains`）对 Hidden 条目同样放行 → 加载后画布不可见。修复后：
  1. Shell 默认布局的 FlowCanvas `CanHide=False`，AvalonDock UI 上关闭按钮被禁用，无法再关进 Hidden
  2. `EnsureCriticalPanelsVisible` 在 `FillContents` 之后、`LayoutLoaded` 之前执行，把已 Hidden 的关键面板拉回可见

## 已知边界

1. **覆盖度校验未升级**：`LayoutXmlCoversAllPanels` 仍只做 `ContentId` 字符串包含检查。如果未来新增面板被放进 Hidden 而不在 `ContentFactories` 注册，覆盖度同样放行且不会被强制救回——需要时再把 Hidden 判定纳入覆盖度校验逻辑
2. **工具箱（ToolView）不在关键面板集**：它默认在 RightSide 自动隐藏区，用户手动隐藏后下次启动仍保持隐藏，属于合法自定义
3. **兜底日志**：强制恢复时会在控制台输出 `关键面板 {ContentId} 从 Hidden 区强制恢复可见`，便于排查
