# 2026-10-15 · ROI 画布拖拽改大小（冷启动手势补发 + 命中容差放宽）

> 范围：`Services\Core.Halcon\Base\HalconBase.cs` 的 ROI 鼠标交互 —— `HSmart_MouseDownForRoi`（换绑分支补发一次 down）+ 新增 `ReplayMouseDownForFreshHandle` + 常量 `RoiHitToleranceScreenPx`（8.0 → 14.0）。
> 用户原话（2026-10-15）：「**使用 Core.Halcon 创建 ROI 后，拖拽改变已创建 ROI 大小的时候很不方便，改不了大小**」。
> 影响面：`Core.Halcon` 的 `ImageEdit` 是**共享画布控件**，8 个插件把 `DrawObjectList` 绑到它 —— CreateRoi / CaliperMeasure / ColorCheck / ColorRegion / Ocr / Matching / PreProcessing / Calibration（位姿变换等其余插件用只读画布，不受影响）。**改一处，8 个插件同时受益**。

> 两处**最有价值的产出**：① 根因不在"拖拽没实现"，而在 **`HSmartWindowControlWPF` 的鼠标链路顺序**——控件**先**把 down 交给 HALCON 做句柄交互、**之后**才触发 `HMouseDown` 事件，而句柄只在事件处理器里才挂上，于是"冷启动一次手势"天然作废（见 §二-1）；② 交互断言**只能用可见窗口**，`open_window(..., "buffer", ...)` 上角点手柄与拖拽全失效（见 §五-2）——踩过才知道，别再拿 buffer 窗口验交互。

## 二、根因（三条，全部实测）

### 1. 鼠标链路顺序：down 先给 HALCON，句柄后挂 —— 冷启动一次手势作废

`HSmartWindowControlWPF` 的鼠标链路是：

```
控件内部 MouseDown
  ├─ ① SendMouseDownEvent  ← 交给 HALCON 做 drawing object 句柄交互
  └─ ② 触发 HMouseDown 事件 ← HalconBase 在这里才挂句柄（AttachRoi → AttachDrawingObjectToWindow）
```

而 `HalconBase` **只给 `ActiveRoi` 挂 HALCON 句柄**（`AttachRoi`，`:692`）。于是：

- 在**未选中**的 ROI 上"按下 - 拖动"：HALCON 收到 ① 的那一刻，窗口里**还没有任何句柄** → 交互无从开始；
- 等 ② 里 `HSmart_MouseDownForRoi` 把句柄挂上（换绑 `ActiveRoi`），down **早已过去**；
- 其后的 mouse-move（`SendMouseDragEvent`）自然拖不动 → **整段手势作废**。

**用户看到的就是"必须点一次（选中）、再拖一次（才能改大小）"**。

### 2. 未选中的 ROI 连手柄都不显示

HALCON **只给已挂接的 drawing object 画手柄**。未选中的 ROI 在画布上只是一条蓝色轮廓——**没有角点/边中点手柄**，用户**看不出哪里能拖**。（这一条没有代码改动，是 §二-1 修复后自然缓解：一次手势即选中+拖动。）

### 3. 摘除容差与手柄同宽：瞄偏 8px 就丢选中

摘除判定用 `ScreenToleranceToImage(8.0)`（`:992` 旧值），而 HALCON 手柄**约 8px 见方**——两者同宽。已选中后起手点**偏出 8px** 就被判成"点空白"，`SetCurrentValue(ActiveRoiProperty, null)`（`:1008`）**当场摘除句柄**，得重新点选才能再拖。这正是用户"很不方便"的第二半。

## 三、修法（`HalconBase.cs`，两处）

### 1. `HSmart_MouseDownForRoi`：换绑后补发一次 down

命中其它 ROI、换绑 `ActiveRoi` 之后，调用新增的 `ReplayMouseDownForFreshHandle(e)`（`:1005`）——**让当前这一手势直接驱动刚挂上的句柄**：

```csharp
SetCurrentValue(ActiveRoiProperty, hit);   // 换绑（DP 回调摘旧挂新并重绘）
ReplayMouseDownForFreshHandle(e);          // 补发 down：本次手势继续驱动新句柄
```

`ReplayMouseDownForFreshHandle`（`:1024-1037`）：

```csharp
hWindow.SendMouseDownEvent(new HTuple(e.Row), new HTuple(e.Column), 1);
```

三条口径：

| 点 | 说明 |
| --- | --- |
| **button 编码 = `1`** | 与控件内部 `MouseButtonEventToInt` 的 `Left → 1` 一致（本处理器开头已有"只处理左键"守卫 `:980-981`） |
| **只在换绑分支调用** | "命中已选中 ROI"在 `:992-993` 已 `return`，挑选时又排除 `x != ActiveRoi`（`:996`）→ 到这里必然是换绑，**不存在重复补发** |
| **失败静默退化** | `hWindow == null` 或原生调用抛异常时直接吞掉（`:1026-1027` / `:1033-1036`）——退化为旧行为（先选中、再拖一次），不阻断"本次点击已完成选中"这件事 |

### 2. 新增常量 `RoiHitToleranceScreenPx = 14.0`（原 8.0）

`:1049`。**只作用于"是否摘除已选中的 ROI"这一处**（`:992`）；**挑选其它 ROI 的第二段 `HitTest` 保持无容差**（`:996`）——否则相邻 ROI 之间会互相误选。取值依据：手柄约 8px 见方，14px 让"擦着手柄点"仍算命中。

## 四、行为变更（必须写明）

### 1. 冷启动"在未选中 ROI 的内部按下并拖动"从"只选中"变成"**移动该 ROI**"

这是**补发 down 的必然结果**——HALCON 里"内部拖"本来就是移动（不是改大小）。属于**行为改善**，已用断言 ⑧ 钉住，免得日后被当成新缺陷。

### 2. 容差 14px 在活动 ROI 周围形成一条"遮蔽带"

两个 ROI **贴得比 14px 还近**时，想切到相邻那个要**先在空白处点一下结束编辑**，再点它。这是"放宽容差"的代价，且是**有意的取舍**——宁可让用户多点一下，也不要"瞄着手柄点却被判点空白、选中当场被摘"。

## 五、排查过程（分离 HALCON 层与控件层，两个坑值得记）

### 1. HALCON 层本身完全正常（10 组对照全绿）

`rect2(300,400,0,100,60)` 的 **4 角 + 4 边中点都能缩放、中心能移动**；`ClearWindow` / 完整 `RenderAll` 序列 / `flush_graphic=false` / `detach + reattach` / `HMoveContent=true` **都不影响**交互。结论：问题**不在 HALCON**，在控件层的鼠标路由与句柄挂接时机。

### 2. 窗口类型坑：**buffer 窗口不能用来验证交互**

`open_window(..., "buffer", ...)` 的 buffer 窗口上，**只有"点中对象内部"能命中，角点手柄与拖拽全失效**，且"补发 down"在它上面也无效。**必须用可见窗口**——本仓断言用**屏幕外**的真 WPF 窗口（`Left=-4000`）即可，HwndHost 仍创建真窗口、HALCON 手柄照常响应（`RoiInteractionChecks.cs:90-92`）。

### 3. 坐标口径坑：`rectangle2` 的 length1 沿 **column** 轴

`rectangle2(row, col, phi, length1, length2)` 在 `phi=0` 时 **length1 沿 column 轴、length2 沿 row 轴**。第一轮探针按"l1 沿 row"算角点坐标，得出"角点命中失败"的**假结论**。此坑已写进断言类注释（`RoiInteractionChecks.cs:36`）。

### 4. 控件路由：drawing object 优先，`HMoveContent` 不抢手柄

反编译确认 `HWPFWindow_MouseMove` 里 `flag = SendMouseDragEvent(...)` 为 true 时**不走** `HShiftWindowContents`——即"drawing object 优先，未命中才平移内容"。所以 `HMoveContent` **不会**抢手柄。

| R53 | **画布交互断言只能用「可见窗口」**：`open_window(..., "buffer", ...)` 的 buffer 窗口上**只有"点中对象内部"能命中，角点手柄与拖拽全失效**，"补发 down"也无效（实测）。要验手柄交互必须开真窗口——**屏幕外**的 WPF 窗口（`Left=-4000`）即可，HwndHost 仍创建真窗口、手柄照常响应。（⚠ 与 R37-① "烘焙件的窗口 mode 只能 `buffer`" **方向相反**：烘焙=离屏 `buffer`，交互=可见窗口，别记混。）夹具自带 STA 线程 + 手动 `Dispatcher.PushFrame` 泵 + **窗口级**主题字典（`/Core.Halcon;component/Generic.xaml`，断言宿主没有 Application 级资源）。 |
