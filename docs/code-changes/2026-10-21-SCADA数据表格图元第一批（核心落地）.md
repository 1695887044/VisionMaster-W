## 三条口径

1. **图元不认识变量注册表**：列定义写的是变量名，运行期经 `ScadaRuntimeContext.Values` 解析句柄——与轴面板认 `IScadaAxisSource` 同一条边界。
2. **采行是"同一拍"的**：判到上升沿后逐列从同一轮读取里取值再攒行；分两拍会攒出"SN 是上一个、角度是下一个"的脏行。
3. **确认变量写累加计数**：不是脉冲（脉冲要复位，又把"读"变成"写"）；写失败只记脚注、不回滚已入表的行。

## 构建期抓到的三个坑

1. **`ControlTemplate` 里的 `{Binding X}` 走 DataContext，不是控件本身** —— 列头/行数/空态/脚注全部改成 `RelativeSource={RelativeSource TemplatedParent}`。这条是渲染断言当场抓到的（列头一个都没长出来）。
2. **名册断言 27 → 28**：`ElementRegistry` 多了 `Hmi.DataGrid`，仓库自带的"名册条数 = 注册表全量"守门人准确变红。
3. **断言宿主解析不到默认样式**：ScadaChecks 刻意不 `new Application`、断言跑在子 STA 线程，自定义控件的 `DefaultStyleKey` 拿不到主题字典（实测连指示灯也是 `Template=null`）。所以视觉验收改成"模板字典能解析 + 里面确有该样式"，真视觉留给带 Application 的探针。

**两个刻意的取舍**：

1. **弹窗内容不用 ListView/DataGrid**：行内是可编辑输入框，R19-R21 那套表格纪律是为只读列表定的；`ItemsControl + 定宽 Grid` 表头天然对齐，也不吃 Fluent 的隐式样式。
2. **`Monospace` 这一列 v1 没有控件**：弹窗里改不了，但**从模型读出、原样写回**——否则打开一次弹窗就把等宽设置抹掉了（往返断言钉住了这一点）。

**没做**：硬校验（变量名为空的行由 codec 静默丢掉，没有"确定不可用"）；结果列值映射与 NG 行红条；采行信号/确认变量的候选下拉。这三项与设计基线 §03 的"校验错误态"对应，是下一批。
