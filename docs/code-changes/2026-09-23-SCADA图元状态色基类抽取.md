# SCADA 图元「状态色」基类抽取（StateVisualElement）

对标 InoTouchPad 官方帮助手册第 7 章「控件」的一处**内部重构**：把泵 / 电机 / 管道三家逐字重复的
6 个依赖属性与 3 处生命周期接线，上提成一层中间基类 `StateVisualElement`。

> 起因是用户的一句反问：「你现在新建一个控件，要写的依赖属性也太多了吧，有什么推荐的优化项吗」。
> 痛点归属（用户多选确认）：**嫌每次都要重新想一遍「开发一个控件」的代码量太大**。
> 改造范围（用户单选确认）：**只收 Pump / Motor / Pipe**。
> 抽取深度（用户单选确认）：**A 档（深抽）**——6 个 DP 与三处生命周期一起上提。

---

## 一、需求与决策

### 1. 需求

新建一个 SCADA 图元控件时，要铺的样板里有一段是「状态变色」：一个 `State` 枚举输入 + 四个颜色输入 +
一个只读的 `StateBrush` 输出，再加上三处「随尺寸重算」的接线。泵、电机、管道三家**逐字相同**，
每新建一个这类图元都要重抄一遍，而且抄漏了**不报错**。

### 2. 改造前后的重复面（逐字比对源码后的结论）

逐字重复的成员（3 个图元 × 6 个 = 18 个）：

| 图元 | 逐字重复的成员 |
|---|---|
| `PumpElement` | `State` / `TrackColor` / `StoppedColor` / `RunningColor` / `FaultColor` / `StateBrush`（只读） |
| `MotorElement` | 同上 6 个（逐字） |
| `PipeElement` | 同上 6 个（逐字，另有独有的 `Direction`） |

另有两段也逐字重复：

- 4 个 `ScadaBrushes.Frozen(...)` 默认色静态字段（`#FF3A3A3A` / `#FF7A7A7A` / `#FF34C759` / `#FFE03A2B`）；
- `PickColor()` 方法体（`Running → RunningColor`、`Fault → FaultColor`、`_ → StoppedColor`，兜底透明）。

三处「随尺寸重算」的生命周期接线（原本每个图元各写一遍）：

```csharp
public XxxElement()
{
    SizeChanged += (_, _) => UpdateXxx();   // ① 尺寸变 → 重算
    UpdateXxx();                            // ② 构造即算第一帧
}
protected override void OnElementRefreshed() => UpdateXxx();  // ③ 收尾钩子
```

### 3. 关键决策（逐条已与用户确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 改造范围 | 只收 `Pump` / `Motor` / `Pipe` 三家（`Lamp` / `Indicator` / `Valve` / `Gauge` / `ProgressBar` 语义相近但名字与槽位数均不同，**主动排除**） |
| 2 | 抽取深度 | **A 档（深抽）**：6 个 DP + ① ② ③ 三处生命周期一起上提，派生类只实现一个 `RebuildStateVisual()` |
| 3 | 基类命名与落点 | `StateVisualElement`，单独文件落在 `Scada.Controls/Elements/` |
| 4 | 是否挂到 `ScadaElementBase` | **不挂**。否则「文字」「矩形」「按钮」也会凭空长出 `State` 与四个颜色，属性面板多出五行永远用不上的项 |
| 5 | 是否改用 attached property | **不换**。attached 解决的是「把属性挂到别人家的类型上」，而这里收的是「六个属性 + 一段生命周期」；换过去模板要写 `{TemplateBinding local:StateVisualElement.State}`、描述符的 `TargetProperty` 也要改，只换来更绕的写法 |
| 6 | 枚举要不要新建 | **不新建**。三家共用的 `DeviceState`（`Stopped` / `Running` / `Fault`）上一轮已单开文件 |
| 7 | 派生类的 `Direction` 怎么办 | 留在 `PipeElement`（管道独有语义），只把它的回调改挂基类的 `OnVisualInputChanged` |

### 4. 设计要点（为什么这么做）

- **A 档的真正价值在三处生命周期上**：它们属于「隐式契约」型样板——漏订 `SizeChanged`，
  设计期拖大尺寸时图形不跟手；漏掉构造首帧，断言环境（不挂可视树、不跑布局）里读到的是空几何。
  收进基类以后，新建一个状态图元**不可能再漏**。只搬 DP（B 档）是治了一半。
- **构造期调虚方法的契约**：基类构造函数里要调 `RebuildStateVisual()`（构造即算第一帧），
  因此钉死一条契约——**实现里不得读写派生类的实例字段**（那时派生类的字段初始化器还没跑）。
  只读依赖属性、`const` 常量、静态字段都是安全的。三个派生类均满足该契约。
- **默认色必须冻结**：依赖属性默认值被所有实例共享，未冻结的 `Freezable` 被某实例改到会串到别的实例。
  4 个默认色因此在基类里各留一个 `static readonly` 冻结实例。
- **回调链是「先挑色、再重算几何」**：`OnVisualInputChanged` → `RefreshStateVisual()` →
  `SetValue(StateBrushPropertyKey, PickStateColor() ?? Brushes.Transparent)` + `RebuildStateVisual()`。
  基类回调设为 `protected static`，派生类自己的视觉输入（`Direction`）可以直接挂它。
- **描述符合法性**：`ElementDescriptor.IsPropertyOn(dp, controlType)` 首句是
  `dp.OwnerType.IsAssignableFrom(controlType)`，因此 `dp.OwnerType = StateVisualElement`、
  `controlType = PumpElement` 天然通过；`PumpElement.StateProperty` 这种「经派生类名访问继承来的静态成员」
  的写法在 C# 里也合法。
- **`TemplateBinding` 按属性名解析**、不认声明在哪个类，因此模板一行不用改。

## 三、验证结果

命令：

```
dotnet build VisionMaster.sln -v q --nologo
dotnet run --project ScadaChecks\ScadaChecks.csproj --no-build
```

- 编译：**0 错误**（1007 个既有警告，均为历史遗留的 `CS8600/CS8602/CS8604` 等，与本次改动无关）。
- 断言：**通过 1592 / 失败 0**，与改造前**逐条持平、一条不降**。

### 覆盖到的关键口径

| 口径 | 断言 |
|---|---|
| 三家的状态色仍经派生类读到 | `pump.State == DeviceState.Stopped && pump.StateBrush is SolidColorBrush { Color: var pumpStoppedColor }`，`Motor` / `Pipe` 同构（Stopped / Running / Fault 三态各一遍） |
| 描述符仍认得出这三个图元 | 16 条 `TargetProperty` 全部注册成功（注册失败会直接抛） |
| 模板仍绑得上 | `TemplateBinding TrackColor` / `StateBrush` 原样解析 |

原样重跑即 **1592 / 0**，`[AB]` 段全绿。

## 四、已知边界

1. **只收了三家**。`LampElement`（四态 `OffColor/OnColor/WarningColor/AlarmColor`）、
   `IndicatorElement`（两态 `IsOn/OnColor/OffColor`）、`ValveElement`（`Opening/ThrottleColor/OpenColor`）、
   `GaugeElement` / `ProgressBarElement`（各有自己的 `TrackColor`）**未纳入**——它们的槽位数与语义都不同，
   硬并会把基类撑成「什么都收一点」的杂物间。
2. **`RebuildStateVisual()` 不得读写派生类实例字段**。这是构造期调虚方法换来的契约，
   靠注释与代码评审守，编译器不拦。
3. **DP 数量并未因此减少**。属性面板 / 持久化 / 运行态三条链路本来就不看 DP（只走描述符 + 属性字典），
   本次收益是**新建图元时的样板代码量**与「漏订生命周期」这个坑，不是运行时开销。
4. **控件骨架模板仍未做**。新建一个图元要铺的另外几段（DP 字段 + CLR 包装 +
   `DefaultStyleKeyProperty.OverrideMetadata` + `Themes/XXX.xaml` + `Generic.xaml` 资源字典引用 +
   `BuiltInElements.cs` 描述符条目）还没有 snippet / `dotnet new` 模板；源生成器方案暂缓。
