# 2026-10-21 数组写入重构（只写修改项）+ 逐元素工程量换算

> 起因：用户两条反馈——① 网络数组「写入数组」弹窗设计不合理（50 项只能整组覆盖，改一个点要重写全部，且没有“我改了哪几项”的概念）；② 数组工程量换算“共用一个”不合理（一套 Scale/Offset 套所有元素）。
> 范围：`Core`（换算模型 / 变量模型 / DTO）、`VisionMaster`（桥接 / 持久化 / 导入导出 / 数组弹窗 / 添加变量草稿）、断言宿主（`CommChecks` / `FlowCanvasChecks` / `RenderProbe`）。
> **不改插件工程、不改 `Modules\` 产物、不改 `Shard\Core.Interfaces`**。

## 二、网络数组写入语义（v4）

### 2.1 旧实现的问题

旧实现只有“整组替换”一种写语义：

- 弹窗打开时把轮询镜像抄进列表，确认时把 **全部 N 项** 一次写回设备；
- 用户只改 1 项，其余 N-1 项也被重写；
- 弹窗是冻结快照，期间设备/别人改过的值会被静默覆盖；
- 没有“已修改”概念（数组的 `DefaultValue` 为 null，`_baseline` 恒空），底部只显示“共 N 项”；
- 整组写超过单请求上限（Modbus 120 寄存器 / S7 约 110 字节）时，只能在确认后拿到一个协议错误。

旧文档 `2026-10-21-通讯数组写入与字符串支持.md:166` 写“元素级单点写……暂不做”，理由是“需要按元素地址 + 读改写互锁”。但同日的 SCADA 模板参数化已经落地 `TryWriteElement`（按元素地址直接下发，不需要读改写，写租约也走 `LeaseKey`），**该前提已不成立**。本轮按“只写修改项”重构。

### 2.2 新语义

| 维度 | 旧 | 新 |
| --- | --- | --- |
| 默认写范围 | 整组替换 | **只写修改项**（逐项按元素地址下发） |
| 对照值 | 无 | 打开时快照 = 「原值」；行内 ↺ 撤销本行，底部「撤销全部修改」 |
| 未改动的设备值 | 被快照重写 | **不碰** |
| 整组写入 | 唯一方式 | 显式分段选择；确认前查镜像冲突 + 单请求上限 |
| 质量 | 不感知 | `Uncertain`/`Bad` 顶部预警，提示先「刷新」 |
| 写入执行 | 同步阻塞 UI | `Task.Run` + 忙碌态（禁用取消/确定/Esc） |
| 失败 | 整组失败一句错误 | 逐项失败列出下标；成功项推进「原值」，失败项标红可重试 |
| 协议不支持元素写（MC/FINS） | — | 默认落到整组写入，并说明原因 |

### 2.3 三条硬口径

1. **只写修改项 = 逐元素地址写**：`TryWriteElement` 不读改写、不碰邻居；同一 owner（manual）重复获取租约是允许的（`WriteLeaseRegistry` 同名 owner 直接返回 true）。
2. **整组写入前必须查冲突**：当前镜像与打开时快照逐项比较，不一致就拒绝并提示「刷新」或改用只写修改项；镜像不完整但用户把全部项填满时，写入的是用户显式给的一组值（字符串数组例外：空串是合法值，无法区分“没读到”与“故意清空”，必须等镜像完整）。
3. **换算档案的事务性**：确认前把草稿档案落到模型（轮询线程立即可见），全失败回滚；部分成功保留新档案（已写下去的值就是按它换算的），并把成功项的原值推进到解析后的值（`ParseRowValue`，不是原始字符串），失败项保持脏标记可重试。

## 三、数组逐元素工程量换算

### 3.1 为什么不能“共用一个”

`DeviceAddressBase` 上的 `Scale/Offset` 是**整个变量一份**：同型号多通道（50 路温度）能用，但“第 0 项温度、第 1 项压力”或“每路单独标定”表达不了。地址对象回答的是“怎么寻址”，元素档案回答的是“每个元素怎么解释”，两者不能混。

因此：

- 档案挂在变量上：`NetworkVariableModel.ElementConversions`（`ElementConversion?[]`，下标与元素一一对应，null = 该元素不换算）；
- 地址对象上的 `EnableConversion` 对数组仍然**禁用**（避免与逐元素档案双重换算）；
- 旧方案/手工数据里若数组带地址级换算，写路径明确报错、读路径按不换算处理（不静默双重换算）。

### 3.2 读路径（两条读链路同一口径）

```
PollBatchPlanner.PublishValue / AdvancedCommunicationManager.ReadVariableNow
  → CommunicationVariable.ToEngineering(raw)
      → EngineeringConverter（NetworkVariableBridge 注入 nv.ToEngineeringValue）
          → 标量：AddressConfig.ConvertToEngineering
          → 数组：逐元素 ArrayConversion.TryToEngineering → double[]
```

- 换算生效时数组镜像是 `double[]`（工程值），与标量换算返回 double 同一口径；
- 没有生效档案时原样返回（引用不变，零分配）；
- 档案比数组短：缺失项按不换算处理（不整组丢数据）；
- 换算失败：该元素退回原始数值（读链路不能因为一条坏档案丢整组数据），写链路明确报错。

### 3.3 写路径

- `TryWriteCore`（整组）：`TryNormalizeArray`（工程值归一到声明元素类型）→ `TryToRawArray`（逐元素反算）→ 设备写；镜像用 `ToMirrorArray` 保持 `double[]` 表示，避免“写一次变 int[]、下一拍又变 double[]”的类型翻转，以及 `Array.SetValue` 把 int 塞进 double[] 抛 `InvalidCastException`。
- `TryWriteElement`（单元素）：`TryCoerceElement` → `ArrayConversion.TryToRaw` → 元素地址写；镜像元素按 `ToMirrorElement` 转成镜像数组的元素类型。
- `Scale=0` 在草稿、导入、`ArrayConversion.TryToRaw` 三处都明确拒绝（无法反算）。
- `byte[]` 是原始块，不参与换算（即使有人手工塞了档案）。

### 3.4 UI

- 网络数组行第三列 = 「换算」：显示 `×0.1 +5 ℃`（无换算显示 `—`），行内 Σ 编辑该元素；
- 底部 Σ 图标 = 整组换算（同一份档案应用到全部元素；identity 即清除）；
- 输入框里是**工程值**，写入时按该元素的档案反算；
- 添加变量草稿的换算块改为多态子对象：数值标量给四个可编辑字段，数组/字符串/布尔给只读说明——不再出现“填了换算 → 点确定 → 属性网格先关闭 → 才弹不支持 → 整份草稿丢失”。

### 3.5 持久化与导入导出

- `.vms`：`VariableDto.ElementConversions` 随变量落盘；`Restore` 在桥接器接线之前还原；
- 顺带修掉两个既有持久化缺口：`MergeAdjacentRead` 与标量换算四字段（`EnableConversion`/`Scale`/`EngineeringOffset`/`Unit`）此前**没有随方案落盘**，下次打开静默回到默认行为；
- xlsx 设备变量表：新增「逐元素换算」JSON 列（`[{"Scale":..,"Offset":..,"DecimalPlaces":..,"Unit":".."},null,...]`），导入时长度必须等于元素个数、Scale=0 拒绝；计划差异与回滚快照都包含它。

## 六、已知边界（未做 / 有意不做）

| 项 | 原因 |
| --- | --- |
| 整组写入分块 | 单请求上限（Modbus 120 寄存器 / S7 约 110 字节）外仍直接拒绝；现在会在弹窗里预警并建议「只写修改项」，默认路径不受影响 |
| MC/FINS 单元素写 | `TryCreateElementAddress` 未实现；弹窗默认落到整组写入并说明原因 |
| `bool[]` / `string[]` / `byte[]` 的逐元素换算 | 布尔无量程、文本无数值语义、byte[] 是原始块；UI 不给入口，导入也拒绝 |
| 非 ASCII 字符串 | 与既有字符串读写一致用 ASCII（既有边界） |
| 部分成功后的自动重试 | 失败项标红、原值推进到成功项；用户修正后再次确认即可，不自动重试 |
| 弹窗定位/跳转 | 未做“跳到第 N 项”；靠滚动条 + 紧凑行 + 多行粘贴覆盖现场主要用法 |
| 多列 Excel 粘贴 | 只取每行第一个制表符前的单元格（数组是一列值，多列无意义） |
| `AllowSharedWrite` / `LeaseTimeoutMs` 落盘 | 既有缺口（由 IO 迁移在启动时重新施加），本轮未动 |
