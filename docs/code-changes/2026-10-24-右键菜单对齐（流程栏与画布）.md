# 右键菜单对齐（流程栏 / 画布，2026-10-24）

## 起因

用户指出两件事：

1. 「编辑绑定」只有画布右键有，**流程栏没有**——同一个步骤在两个编辑面上能力不一致；
2. 画布右键是浏览器默认观感（白底、无图标、无描述），而流程栏那套菜单有图标底片、
   双行标题+说明、语气色、页脚。希望**画布沿用流程栏的样式和命令菜单**。

盘点后确认的差异（改前）：

| 命令 | 流程栏 | 画布·算子卡 | 画布·容器框 |
|---|:--:|:--:|:--:|
| 编辑绑定 | ❌ | ✅ | ✅ |
| 重命名 / 编辑注释 | ✅ | ❌ | ❌ |
| 复制 | ❌ | ✅ | ✅ |
| 展开全部 / 折叠到第一层 | ✅ | ❌ | ❌（树概念，画布无此对象） |
| 切换断点 | ✅ | ✅ | ❌（容器不能断点） |

## 改动

### 1. 菜单样式下沉到 UI 主题（硬前提）

三个样式（`StepContextMenuStyle` / `StepMenuItemStyle` / `StepMenuSeparatorStyle`）原先**只定义在
`ProcessView.xaml` 里**，画布直接引用会在解析期抛"无法找到名为 StepMenuItemStyle 的资源"
（R30：分册之间互相看不见）。

新增 `UI/Controls/Themes/Controls/StepContextMenu.xaml`（样式原样搬迁，键名不变），并：

- 在 `Generic.xaml` 的 Controls 域合并（应用级可解析）；
- `ProcessView.xaml` / `FlowCanvasView.xaml` **各自就地 merge**（R22 同一手法：无 Application 的断言宿主里也能解析）。

**两个踩过的坑（写在这里免得下次重踩）**：

- 字典里 `xmlns` 必须用 `clr-namespace:UI.AttachedProperties`，**不能**用
  `http://schemas.UI.com/ui`：XmlnsDefinition 是给别的程序集用的，本文件编译在 UI 程序集内部，
  用 URI 前缀会报 `MC4106 无法解析模板属性 Footer`。
- `UserControl.Resources` 里**不能直接写** `<ResourceDictionary.MergedDictionaries>`，必须先套一层
  `<ResourceDictionary>`，否则 `MC3074 XML 命名空间…不存在标记 ResourceDictionary.MergedDictionaries`。
  两个视图的整个资源块因此各多了一层包裹。

### 2. 流程栏补「编辑绑定…」与「复制」

- `ProcessViewModel.OpenBindingCommand`：以当前选中步骤为锚打开 `DataBindView`
  （与画布 `FlowCanvasView.OnModuleLinkRequested` 同一弹窗、同一 `TargetStep` 参数）。
  不做运行锁，与画布入口一致。
- `ProcessViewModel.CopyStepCommand`：`FlowClipboard.Copy(选中步骤)`，与画布共用同一份剪贴板。
  无选中时给回执（不静默空跑）；复制不改图纸、不受运行锁限制（与画布 `OnCopySelected` 同口径）。
- **`Ctrl+C` 接到同一命令**：挂在 `<TreeView.InputBindings>`（与既有 `Delete` 同一层、同一口径）——
  只有焦点在流程树里才抢 `Ctrl+C`，不干扰画布/日志面板的快捷键。菜单与快捷键共用 `CopyStepCommand`
  一个出口，不做第二套实现。

### 3. 画布补「重命名」「编辑注释」

- `CanvasNodeViewModel.RenameCommand` / `EditCommentCommand`（主 VM 注入闭包，与既有命令同一模式）；
- `FlowCanvasViewModel.BeginEditText` → `ApplyTextEditAsync`：同一个 `EasyDialog.ShowTextInputAsync`、
  同一道 `ModuleEditAction.StructuralEdit` 门禁；异常收在方法内落到状态栏（无 Application 的宿主里
  EasyDialog 取不到 Dispatcher，不该让它冒到 UI 线程）；
- 版本推进不手写：`StepName` / `Description` 都在 FlowModel 监听面里，改了就 `Version++`。

### 4. 画布三份菜单套上共享样式

算子卡 / 容器框 / 连线 / 空白四处都改成 `Style="{StaticResource StepContextMenuStyle}"`，
每项带 `Icon`（FA6 连字名）、`ui:MenuItemEx.Description`、`ui:MenuItemEx.Tone`；
分隔线用 `StepMenuSeparatorStyle`。

**页脚各写各的真实语义**（不许照抄）：

| 挂载面 | 页脚 |
|---|---|
| 流程栏树 | 右键菜单 · 仅作用于当前选中步骤 |
| 画布·算子卡 | 右键菜单 · 作用于指针下的算子 |
| 画布·容器框 | 右键菜单 · 作用于指针下的容器 |
| 画布·连线 | 右键菜单 · 作用于这根连线 |
| 画布·空白 | 右键菜单 · 作用于画布空白处 |

### 5. 文案对齐

- 「编辑绑定…」（画布原先多了「（打开变量绑定）」后缀）
- 「步骤参数…」（流程栏原先无省略号）
- 复制项补 `Ctrl+C`、删除项统一 `Del` 手势

### 6. 断点勾选态

画布菜单的「切换断点」加了 `IsChecked="{Binding IsBreakpoint}"`，`CanvasNodeViewModel` 新增
`IsBreakpoint` 并在 `OnModelPropertyChanged` 里转发 `StepModel.IsBreakpoint` 的通知——
菜单是共享实例，不转发的话勾选态会停在上一次打开的节点上。

## 断言

`FlowCanvasChecks/ProcessMenuChecks.cs`（[PM] 组 16 条）：

- **PM1** 流程栏挂「编辑绑定…」且接 `OpenBindingCommand`、用统一样式；
- **PM2** 两处核心命令集覆盖（编辑绑定/重命名/注释/参数/禁用/删除）、共享样式被两边引用、
  **页脚不照抄**；
- **PM3** 流程栏复制：菜单项接 `CopyStepCommand`、**`Ctrl+C` 接同一命令**、画布自己的
  `Ctrl+C` 未被抢、未选中不进剪贴板 / 选中后进共享剪贴板；
- **PM4** 编辑绑定：未选中不弹窗 / 选中弹 `DataBindView` / **参数带 TargetStep 且等于选中步骤** /
  清空选中后不再弹；
- **PM5** 画布注入了重命名/注释命令、断点勾选态与模型一致、**运行中重命名被运行锁拦下**。

**变异反证**（3 处改坏，都判红后还原）：

| 变异 | 结果 |
|---|---|
| 画布的「重命名」项改成绑其它命令 | PM2 判红：`缺=重命名` |
| 画布页脚照抄流程栏文案 | PM2 判红：`画布若照抄流程栏页脚就是在说假话` |
| 删掉流程栏的 `Ctrl+C` KeyBinding（菜单留着） | PM3 判红：`TreeView.InputBindings 里应有 Ctrl+C → CopyStepCommand` |

**验证**：

- `FlowCanvasChecks` **3624 通过 / 0 失败**；
- `UIThemeSmokeTest` **108 项 0 失败**；
- `--switch-perf test-suite.vms 1 tree` 与 `... canvas` 各跑一次（**真实例化** ProcessView / FlowCanvasView），
  exit 0、无异常——覆盖"样式下沉后运行时解析不出错"这一层（常规 gate 只把 ProcessView 当 XML 文本读）。

## 有意保留的差异

- **展开全部 / 折叠到第一层**：树概念，画布是扁平全深度渲染，没有"第一层"这个可操作对象；
- **切换断点只出现在算子卡**：容器不能挂断点（画布已按类型隐藏，流程栏靠选中类型显隐）；
- **流程栏的分支胶囊菜单**（重命名/删除本条分支）：对应"分支"这个对象，画布上没有等价落点；
- **粘贴只在画布空白处**：流程栏没有落点概念。
