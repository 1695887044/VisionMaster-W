## 三、首轮失败的 8 项（全部为**测试期望写错**，非产品缺陷）

首轮跑出 8 红，逐条定位后确认 **7 条是我的期望值算错、1 条根本没走到被测分支**。修正后全部转绿，且把其中两条语义改成了"语义钉"（行为变了会红）。

| # | ID | 复现步骤 | 定位 | 根因 |
| --- | --- | --- | --- | --- |
| 1 | AT08 | 建 3 条报警 → 先 AT06 确认 1 条 → 再断言"全部确认前=3" | 测试期望 | 忘了前面已确认一条，起点应为 2 |
| 2 | EV01 | 新控件（初始启用）→ 直接推 0 → 断言"0→0 不发" | 测试期望 | 首次 0 实际是 1→0，是**真翻转**；已在 EV00 单独钉住该语义 |
| 3 | EV02 | 承接上一步的状态再推 0 | 测试期望 | 同上，事件计数整体偏移 |
| 4 | EV07 | 控件已处于禁用态 → 推 0 → 断言"应发 1 条" | 测试期望 | 同值不翻转，自然不发；改为先启用再禁用 |
| 5 | EV09 | Invert 动画，控件初始启用 → 推 0 → 断言"发 Activated" | 测试期望 | 0 反转后仍是启用，无翻转；改为先推 1（禁用）再推 0 |
| 6 | SL07 | 位号模式，变量 -1 | 测试期望 | -1 是补码全 1，命中位 0；原期望"无命中"错 |
| 7 | CS04 | 登录窗抛异常 | 测试期望 | 实现按 Warn + "按未登录处理"，我按 Error 断言；Warn 更贴切（业务结果非程序故障） |
| 8 | CS11 | 钩子里只放一条延时，从工作线程调用 | **测试未覆盖到分支** | `rest.Count == 0` 先命中"没有后续动作"，根本没走到 Dispatcher 判断；补一条后续动作后才真正测到 |

## 四、真实发现（不是失败，但值得记录/裁定）

`--stress-v6` 是新增开关，**常规闸门（`tools\run_gates.ps1`）不会执行它**——压测含万级循环，放进每次闸门会明显拖慢；需要时手动跑。

## 七、环境备注

- 压测期间同一仓库有另一个会话在并发改 `VisionMaster\Services\DeviceVariableIoService.cs` 与通信模块，导致 `ScadaChecks` 构建一度报 `CS8121`（该文件当时半成品）。等其落盘后重跑即绿；**未改他人文件**。
- `VisionMaster\obj` 里的陈旧 `*_wpftmp.*` 会造成"成员明明存在却报不存在"的假错误（本机既有问题），清 `obj` 后重建即恢复。
