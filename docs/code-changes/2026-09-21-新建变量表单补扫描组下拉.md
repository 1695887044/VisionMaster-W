# 新建变量表单补「扫描组」下拉

## 1. 需求与决策

### 需求

「扫描组」此前只在**变量列表**（右栏 DataGrid）里有下拉列，是**事后改**的入口。中栏「新建变量」表单里没有该字段，导致 `AddNetworkVariable` 建出来的变量 `ScanGroup` 恒为空串 → **一律进默认组**，必须建完再回列表里逐个改。

批量录点位时很别扭：建 50 个 100ms 快组的点，得建完 50 个再下拉 50 次。

### 决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 是否补下拉 | **补** | 建的时候就定好节拍，一步到位 |
| 是否记住上次选择 | **记住** | 连续录同节拍点位时不用每次重选（用户明确要求） |
| 记住的状态是否落盘 | **不落盘** | 纯 UI 便利，不属于方案数据 |
| 下拉放在哪 | 网络专属区内、**「所属连接」之后** | 扫描组与所属连接同为「连接级」属性；存储区/地址是「地址级」，排在后 |
| 本地变量时 | **隐藏** | 整块网络专属区靠 `IsNetworkSource` 的 `DataTrigger` 控制显隐，自动跟随 |
| 落库值口径 | **「默认组」→ 空串** | 与 `PollScheduler` 约定一致（空名 = 默认组，周期取连接 `ReadCycleMs`） |

### 关键设计：换连接时组名怎么办

组名是**连接级资源**（组表挂在 `CommunicationConfig.ScanGroups` 上），不是全局的。所以「记住上次选的组」不能无脑记字符串，否则 A 连接选了「快组」、切到没有「快组」的 B 连接，下拉会留一个失效值。

处理口径：**记住组名 → 切连接时检查新连接组表里还有没有同名组 → 有就继续选中，没有就回落「默认组」**（不留失效值）。

```csharp
string remembered = SelectedNewScanGroup;
SelectedNewScanGroup = !string.IsNullOrWhiteSpace(remembered) && NewScanGroupOptions.Contains(remembered)
    ? remembered
    : PollScheduler.DefaultGroupName;
```

### 关键设计：口径只留一处

「显示值 → 落库值」的转换（「默认组」→ 空串）此前散在 `OnScanGroupChanged` 里。本次抽出 `ToStoredScanGroup`，**新建入口与列表改组入口共用同一个方法**——避免将来一处改口径、另一处忘改。

## 4. 已知边界

1. **下拉选项不随外部改组实时刷新**：`RefreshNewScanGroupOptions` 只在 `SelectedConnection` 变化时触发。若在变量管理弹窗**打开期间**去连接设置里改组表，下拉选项不会自动重算——但两个弹窗都是模态的，实际无法同时打开；重新打开变量管理弹窗会重建 VM、选项重算。故不处理。
2. **连接未缓存配置时下拉只剩「默认组」**：`GetScanGroupNames` 依赖 `_configCache`，未命中时安全兜底只给默认组。用户看不到自定义组，但**不会**选到不存在的组（安全侧）。
3. **记住的是组名，不是组对象**：连接设置里把「快组」改名成「高速组」后，新建表单里记住的「快组」在新组表里不存在 → 回落默认组，需要用户重选。不做「按周期自动匹配同名组」这类启发式猜测。
4. **新建时选的组若随后被删**：变量已在列表里显示为默认组（`CreateRootNode` 的回落逻辑），不会丢点。删组时 `ReassignScanGroup` 会把已注册变量级联回落并落盘。

## 5. 补充：变量管理内补「管理扫描组」入口

### 5.1 需求与根因

用户报障「UI 没办法添加扫描组」，截图显示变量管理弹窗里「扫描组」下拉展开**只有「默认组」**。

逐文件核查后的结论：**扫描组编辑器本身没有坏**，坏的是**入口的可见性**。

| 核查项 | 结论 |
| --- | --- |
| `ScanGroupEditorViewModel.ExecuteAddGroup` 的 canExecute | 未写反（空表时 `0 >= 8` = false，可正常新增） |
| `MaxScanGroups` | 8，额度充足 |
| 图标 `&#xf5fd;`（layer-group） | 字形存在（Shell 的「图层」用同一码位） |
| `ExecuteEditScanGroups` → `ShowDialog` 接线 | 完整 |
| 弹窗注册 | `App.xaml.cs` 已 `RegisterDialog(ScanGroupEditorViewModel.DialogName)` |
| **「新增组」的入口** | **全工程只有一处** —— 通讯设置 → 操作列第 4 个蓝色层叠图标 |

而用户是在**变量管理**里录点位的。那里原本连 `IDialogService` 都没注入，物理上打不开子弹窗，「扫描组」下拉只是个只读清单。用户在下拉里发现只有默认组、想建组时，找不到任何入口 —— 这就是报障的真实原因。

### 5.2 决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 入口放哪 | 变量管理 → 新建表单 → **「扫描组」下拉右侧** | 用户正是在这里发现「只有默认组」的，入口就该在旁边，不必退出去开通讯设置 |
| 复用还是新写 | **复用同一个 `ScanGroupEditor` 弹窗** | 一份组表、一套校验，绝不出现两套改法 |
| 按钮何时可用 | `SelectedConnection != null` | 组表是连接级资源，没有「所属连接」就无所谓组表 |
| 传参传什么 | **只传连接名**，不传对象引用 | 编辑期间这条连接可能已被别处删除；传引用会让编辑器拿着一个「已不在册」的对象改。编辑器自己按名字去 Manager 取活对象，取不到就如实报错并退化为只读空表 |
| 关闭后刷新什么 | ① 新建表单下拉 ② 右栏变量列表（`RefreshTree`） | 新加的组要能立刻选到；组被改名/删除后已有变量的可选项要跟上。变量模型里的组名已由编辑器 `CascadeRename` 级联改好，界面只需重读一遍 |

### 5.5 已知边界

1. **界面改动无法用断言覆盖**：这是 WPF VM + XAML 交互，`CommChecks` / `ScadaChecks` 都是无 UI 的控制台宿主，跑不到。**必须实机点验**：变量管理 → 选「所属连接」→ 新建表单「扫描组」右侧「管理」→ 新增组 → 确定 → 下拉应能选到新组。
2. **未选连接时按钮置灰**：符合预期（组表是连接级资源），但用户若不理解会觉得「按钮怎么点不动」——靠 ToolTip 说明作用对象。
3. **`ScanGroupEditorViewModel` 静默 no-op 已修**：`AddGroupCommand` / `ApplyPresetCommand` 的 canExecute 由 `!IsAtGroupLimit` 改为 `_working != null && !IsAtGroupLimit`。连接不在册时按钮直接置灰，不再「点了没反应」。
   - 成功路径的恢复靠 `OnDialogOpened` → `RebuildRows()` → `AfterStructureChanged()`（内含两个命令的 `RaiseCanExecuteChanged`），无需额外补调用。
   - 失败路径 `_working` 保持 null，构造函数里 canExecute 初评即为 false，天然置灰。
   - `DeleteGroupCommand` / `CopyToConnectionCommand` 无需改：空表时 `SelectedGroup` 为 null、`CopyTarget` 为 null，canExecute 本就为 false。
4. **`ExecuteConfirm` 的静默 return 已修**：`_working == null || _live == null` 时改为 `RequestClose(Cancel)` + `Notifier.ShowWarning("连接 [X] 已不存在，本次未做任何修改")`。
   - 选择「点确定就关闭」而不是「确定按钮置灰」：没活对象可写时这个弹窗已经失去意义，把用户困在里面（只能自己找取消）是更差的体验；确定按钮置灰又会让用户困惑「为什么不能点」。
   - 关闭结果返回 `ButtonResult.Cancel`（而非 OK），调用方 `OnScanGroupsClosed` 见 `!= OK` 便不做任何刷新，语义与「没保存」一致。
