## 1. 服务端

### 1.1 `structureSeq`（陈旧快照闸）

- 每**准备发一份** snapshot/page 自增一次（`Interlocked.Increment(ref _structureSeq)`），
  写进消息的 `structureSeq`；它是“发送单调戳”，不是结构身份（失败会烧号、跨会话不连续）。
- `hello` 也带当前 `structureSeq` 与 `runGeneration`：客户端新连接采纳服务端值，
  不再沿用旧连接（服务端进程重启后 generation 从 1 重来）。
- 客户端只接受更大的 `structureSeq`；同值/更小 = 迟到旧快照，丢弃。

### 1.2 `view.resync`

请求：

```json
{"type":"view.resync","id":"...","scope":"structure"|"frames","reason":"...",
 "pageId":"...","pageVersion":42,"runGeneration":7}
```

- WS 线程受理（不入命令泵）：先 `TryValidateSessionAlive`（撤销 4403 / 过期 4401），
  参数校验、每会话 1 秒限速（`E_RATE_LIMITED` + `retryAfterMs`）。
- `scope=frames`：置 `ForceKeyframe`，下一帧 keyframe；未运行回 `ack{idle:true}` + `idle`。
- `scope=structure`：置 `ResyncRequested`（单飞合并），由**帧循环**在下一拍消费：
  把 `CurrentPageKey` 置空 → 走一次 `previousKey is null` 分支发 snapshot；
  成功才推进页键并 `ResetDeltaForNewStructure()`；失败下一拍自动重试。
- **不跨线程清 `LastValues`/`FrameSeq`**（普通 Dictionary，只有帧循环写）；
  不会与帧循环双发（没有第二个快照发送者）。
- ack/error 统一走 `TrySendControlOrClose`：控制队列满时 Warn + 1011，不静默丢。

### 1.3 首屏只发一份

`ScadaWebSession.InitialStatePending`：WS 入册后为 1，帧循环跳过该会话；
`SendInitialStateAsync` 的 `finally` 放行（成功/失败/异常都放行，失败由帧循环重试）。
浏览器实测 `structureSeq=1`（修复前是 2，首屏被发了两份）。

### 1.4 发送超时不再被当成正常收尾

`SendOneAsync` 的 15 秒超时用独立 linked token；两条发送循环改为：

```csharp
catch (OperationCanceledException) when (!token.IsCancellationRequested)
    => HandleSendFault(new TimeoutException(...));
catch (OperationCanceledException) { /* 停服/Dispose */ }
```

`HandleSendFault` 记日志 + 取消会话 + 2 秒超时关 1011；不再出现“数据循环静默死亡、
控制循环还刷出站时间戳、会话永不被回收”。

### 1.5 其它收口

- `caps` 哈希改用稳定投影（排除每拍变化的 `policyVersion` 与 `remainingSeconds`），
  入队成功后才记哈希；内容不变不再每 2 秒重发 200KB。
- 快照超限置 `StructureTooLarge`，帧循环不再 10Hz 重发 error / 重复发起关闭。
- `E_UNSUPPORTED` 回显 `id`/`kind`，旧服务端不支持 `view.resync` 时客户端能关联。
- `stopped`/`idle` 都带 `runGeneration`；帧循环兜底用 `_lastRunGeneration`（不再用 0）。
- `img.token` 失败下拍补发（第一批已做，本批回归通过）。

## 2. 客户端

- `handleMessage` 不再全局写 `state.runGeneration`；各 handler 先校验后写。
- `applySnapshot` 三道闸：
  1. `structureSeq <= state.structureSeq` → 丢弃；
  2. `generation <= stoppedGeneration` → 丢弃；
  3. `generation < state.runGeneration` → 丢弃。
- `hello` 采纳服务端 `runGeneration`/`structureSeq`，重置 `stoppedGeneration=-1`。
- `idle`/`stopped` 带 generation，旧轮次不覆盖新画面。
- `applyFrame` 在**所有 early return 之前**更新 `lastReceivedFrameSeq`（空帧也算）。
- `view.resync` 客户端：单飞 + 1.5s 限速 + 6s 无进展退避，最多 2 次；
  首屏 5 秒无结构触发 `structure` resync；`E_RATE_LIMITED` 按 `retryAfterMs` 等。
- 1009 / `E_SNAPSHOT_TOO_LARGE` → `enterFatal`：显示“页面过大”遮罩、停止自动重连、
  只留「重试」；`fatal` 只由 hello/手动重试清除（迟到快照不能绕过终态）。
