# 多流程并发（批 2/3）：UI 负载与资源卫生（2026-10-27）

## 一、当前状态

批 2（UI 负载）与批 3（资源卫生）已落地。批 1 解决的是"窗口 2 被 A 清空"（正确性），
本轮解决的是"界面卡住"（负载）与"跑久了越来越慢"（泄漏/全局状态）。

- **帧入 UI 合并**：每个（流程，窗口号）只留最新一张，队列长度被"流程数 × 窗口数"封顶；
  中间帧在进 UI 之前就被顶掉并释放。排空走 `Background` 优先级（低于 Render/Input）。
- **渲染合并**：一次选中帧变化最多刷一次（旧实现 `HImage` 与 `Annotations` 两个 DP 各刷一次，
  清空后旧图已 Dispose 还会再多一次）。
- **同尺寸换图不再重铺**：尺寸判定改用"本控件上次画过的尺寸"，不再靠"旧图是否还活着"推断。
- **不可见画布不渲染**：切到别的文档标签时只标脏，可见后补一次。
- **资源卫生**：`ImageView` / `ImageGallery` 的全局订阅随 `Unloaded` 摘除；`HalconBase` 卸载后
  把 `hWindow`/`hSmart` 置空；`RenderAll` 的进程级 `flush_graphic` 用 `finally` 兜底还原。

## 五、批 3.3（追加）：启动流程的编译挪出 UI 线程

原计划里这条被标为"需要先有编译期禁编辑闸，单独评估"。复查后确认：**定时触发与 HTTP 触发本来
就在后台线程编译**（`FlowAutoRunner.RunOnce` / HTTP 收图都走同一个
`FlowSessionFactory.TryEnsureSession`），手动入口没有理由特殊——竞态口径与它们一致即可。

改动（`VisionMaster\ViewModels\FlowListViewModel.cs`）：

- `RunSingleFlowAsync` 里的 `FlowSessionFactory.TryEnsureSession` 包进 `await Task.Run(...)`：
  这一句里最贵的是 `FlowCompiler.Compile`（大流程几百毫秒到数秒），旧实现同步跑在 UI 线程，
  点"循环运行"那一下界面会顿住。`await` 之后回到 UI 线程再提示/启动。
- 新增 `_starting` 重入闸：编译是异步的，不挡的话双击会排两次编译（命令的 `CanExecute` 不判"正在启动"）。
- 编译期间界面仍可操作，新增两条复核：流程被**删除/禁用**则放弃启动并如实提示。
  （"已被其它触发启动"仍由会话锁裁决，连续运行分支本来就会报"未启动：会话正被其它触发占用"。）

竞态口径（与定时/HTTP 触发一致）：编译期间用户改图纸 → 会话里记的是"编译前版本号"，
下一轮判过期自动重编译；真正互斥仍由会话锁（`TryOccupySession`）保证。

断言（`FlowCanvasChecks\FlowEngineFix2Checks.cs` 的源码纪律段）：方法体内
`TryEnsureSession` 必须出现在 `await Task.Run(` 之后；新增 `--engine` 专项入口便于迭代。
**变异反证**：把实现退回同步调用 → `Task.Run@-1`，该条变红；还原后 14/14 全绿。

未做：显式「编译本流程」命令仍在 UI 线程（那是用户主动等待的动作，语义上可以接受；如需同样处理，
把 `FlowAction.Compile` 分支也包 `Task.Run` 即可，但要注意它同样会 `RegisterSession`）。

## 六、踩过的坑

- **合并队列把"UI 线程上同步执行"这条老行为改掉了**：`RunOnUi` 在 `CheckAccess()` 时是**同步执行**的，
  而我的第一版 `EnqueueFrame` 一律入队 → 断言宿主（`Application.Current != null`、直接在 UI 线程调
  `Capture`）全部读到"还没插进去"的旧状态，`UIThemeSmokeTest --gallery` 一次红 9 条。
  正解：**已在 UI 线程就同步提交**（没有排队的意义），只有跨线程发布才合并。
  断言要测合并时用 `SuspendUiDrainForTest` 强制走队列。
- **事件订阅改成"随 Loaded 挂"会破坏离线断言**：`UIThemeSmokeTest` 的多格布局断言把 `ImageView`
  放进一个没有 Window 的 `Border` 里（`Loaded` 永不触发），只在构造期订阅才收得到布局切换。
  正解：构造期挂 + `Unloaded` 摘 + `Loaded` 补挂——真正泄漏的是"加载过又被丢弃"的实例。
- **`HImage.GetImageSize()` 返回 `int[]`**，不是 `HTuple[]`：写 `newSize[0].I` 直接编译错。
- **另一会话正在同仓库施工**（`ScadaUserStore.cs`、`Plugin.Matching`、`MatchingChecks.cs`）：
  - 一次 gate 因 `MatchingChecks.cs` 引用未定义符号而 BUILD FAILED；
