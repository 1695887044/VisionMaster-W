## 2. 已做

### 2.1 服务本体

`Program.cs` 手写 MCP JSON-RPC over stdio（`initialize` / `tools/list` / `tools/call` / `ping` / `shutdown`），
通知不回包，`ToolException` 与 `AssertionFailed` 都走 `isError`，其中断言失败的报告原样返回、不加前缀，
避免"跑过了"被读成"过了"。

### 2.2 第一批：进程、构建、界面基础（13 个）

`vm_status` `vm_start` `vm_stop` `vm_backup_layout` `vm_build` `vm_run_host` `vm_gates`
`vm_ui_tree` `vm_ui_act` `vm_ui_click` `vm_ui_wait` `vm_shot` `vm_log_tail`

### 2.3 第二批：输入、断言、图像体检（9 个）

- `vm_ui_type`：ValuePattern 优先 + 真实按键回落 + 快捷键 + **读回实际值**；
  描述里明写"SetValue 不产生输入事件，R35 类控件必须用 mode=keys"。
- `vm_ui_drag` / `vm_ui_scroll`：真鼠标按下-移动-抬起、滚轮；坐标模式可不带 pid（此时不做前台比较）。
- `vm_assert`：元素 exists/absent/count/text/enabled + 日志正则（带时间窗），轮询到超时；失败即 `isError`。
- `image_info` / `image_histogram` / `image_diff` / `image_crop` / `dataset_scan`：
  WIC 解码保留原位深（Gray8/Gray16/Bgr24/Bgra32/Rgb48/Rgba64，其余转 Bgra32 并注明），
  统计走内联热循环（121 张 752×480 全扫 < 1s）。

### 2.4 把台账的坑写进代码（不是文档约定）

- 子进程原始字节落盘 + UTF-8 严格解码 → 回落 936（C-01/C-25）；零输出判红（C-03）
- 有界 `WaitForExit(ms)` + 退出码 `null` 判红（C-02/F-02/R183）
- `vm_build` 判据 = 退出码 0 **且** 0 错误 **且** 无失败横幅（R179）
- 主窗口取**面积最大**的顶层窗口（C-20）；最小化时 `SW_RESTORE` 后重试（C-31）
- 缺 UIA 模式时报出可用模式清单（C-21/C-22）
- 点击/拖拽/滚轮前查前台窗口归属（C-26）
- 日志读取 `FileShare.ReadWrite`（C-09）
- 截图返回窗口矩形 / 图像尺寸 / DPI，坐标可换算（C-07）
- 私有区字形转义成 `\uXXXX`（C-32）
- `vm_status` 用命令行区分真构建与常驻 `VBCSCompiler`（A-01 补充）

### 2.5 自测设施

`--selftest-window` 起一个自带 WPF 窗口（按钮 / 文本框 / GroupBox 拖拽面板 / ScrollViewer / 菜单 /
一个故意没有 automation peer 的 `Border`），三套冒烟各自独立：协议层、GUI 层、图像层。
GUI 层不依赖 VisionMaster，也不碰用户开着的程序。

### 2.6 真机试跑暴露的缺陷（本轮修复）

自测全绿不等于真机可用。第一次真跑 VisionMaster 就连撞三个：

1. **`vm_start` 把启动画面当主窗**：启动画面是无标题的 520×360 顶层窗口，1.2s 出现、2.8s 消失；
   旧实现 1.4s 就报"启动成功"并把后续 `vm_shot` / `vm_ui_tree` 全指向它。
   现判据改为"**有标题 + ≥640×480**"，超时会列出进程当前所有顶层窗口。
   实测时间线：t=1.23s 无标题 520×360 → t=2.83s 无窗口 → t=3.26s `VisionMaster` 1280×860。
2. **草稿恢复框阻塞界面**：上一次带未保存改动退出（`vm_stop` 也会触发退出链转存草稿），
   下次启动弹「上次运行的现场 / 稍后再说 / 打开目录」，盖住整个主界面。
   已固化为启动后的固定第一步，并加进 README 与台账 C-37。
3. **按名字过滤后取第一个 ref 拿到 `Text`**：`Text` 没有模式，`invoke` 报
   "Available patterns: (none)"，看起来像按钮不可点。
   `vm_ui_act` 现在支持不带 ref、按名字/id/类型定位，并**自动挑支持该动作的元素**。

新增 `vm_windows`：列出进程全部顶层窗口（标题/类/矩形/是否无标题），
"弹窗卡住"第一步就是看它，而不是猜 `vm_ui_tree` 选中了哪个窗口。

## 5. 踩过的坑（本轮新增，已并入台账）

| 现象 | 根因 | 处理 |
|---|---|---|
| 截图"成功"但菜单没出现 | WPF 菜单/下拉/Tooltip/原生对话框是**独立顶层窗口**，`PrintWindow` 只拍窗口自身表面 | 增加 `mode=screen`；描述与返回值明写 `popup-note`（C-30） |
| `vm_status` 永远显示"构建中" | `VBCSCompiler` 是常驻 Roslyn 服务，被当成 `dotnet` 构建 | 读命令行（`ProcessCommandLineInformation`）过滤，单列 `roslyn-server` 行（A-01 补充） |
| `Start-Process notepad -PassThru` 的 pid 找不到窗口 | Win11 记事本 launcher + 宿主两段式；最小化时 UIA 矩形为空 | `ResolvePid` 明确报"进程已退出"；`MainWindow` 先 `SW_RESTORE` 再重试（C-31） |
| 图标按钮在树里全是 `'?'` | UIA `Name` 是私有区码点（U+E000–U+F8FF） | 树输出转义成 `\uF067`（C-32） |
| 拖拽靶子拿不到元素 | `Border`/`Canvas` 没有 automation peer，**根本不出现在 UIA 树里** | 自测靶子改用 `GroupBox`（C-33） |
| `SetValue` 写完界面"没反应" | ValuePattern 不产生输入事件，`PreviewTextInput` 类逻辑收不到 | 工具描述强制说明，R35 类控件用 `mode=keys`（C-34） |
| `powershell -Command` 里拼 JSON/变量被转义吃掉 | cmd → PowerShell 两层引号 + `\$` | 一次性脚本一律写文件用 `-File`（C-04 补充） |
| `vm_start` 报"成功"但窗口是 520×360 无标题 | 启动画面是真实顶层窗口，且在那个瞬间是唯一/最大 | 判据改"有标题 + 尺寸下限"；新增 `vm_windows`（C-36） |
| 启动后点哪都没反应 | 上次带未保存改动退出 → 草稿恢复框盖住界面 | 启动第一步 `vm_ui_act {nameContains:"稍后再说",controlType:"Button"}`（C-37） |
| `invoke` 报 `available patterns: (none)` | 按名字过滤时 `Text` 子节点先命中，`Text` 没有模式 | `vm_ui_act` 支持按名字定位并自动挑支持该模式的元素（C-38） |
