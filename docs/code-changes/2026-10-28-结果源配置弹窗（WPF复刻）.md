### 候选口径（与基线 v1.1 一致）| 来源 | 规则 |
| --- | --- |
| 变量 | `GlobalVariables` 里 bool / string / int / long / double；排除系统变量；bool 排前；显示类型与当前值 |
| 步骤 | 深表（容器只递归、不列自身），分支内步骤标「分支内」；选中后提示未走到即未判定 |
| 端口 | 静态 `ModulePlugins[type].OutputDefinitions` + 步骤动态端口快照；只列 bool；排除 `Success`/`ErrorMessage` |
| 校验 | 变量模式必须有变量；端口模式必须有步骤 + 端口；只读阻断；其余模式不阻断（Q4） |
| 警告 | 自动无结果步骤 / 结果步骤缺失 / 主流程不参与（Q3）/ 分支步骤（Q5） |

**验收中发现并修复**：首次真机打开时左栏「自动」没有高亮。原因是 `Preselect()` 直接写 `_selectedMode`
字段、没有发 `PropertyChanged`——ListBox 在 `OnDialogOpened` 之前已经绑定过一次 null，之后收不到
`SelectedItem` 变化。补 `RaisePropertyChanged(nameof(SelectedMode))`（连同三个候选选中项）后复验，
高亮正常。**这类"字段直写 + 无通知"的预选逻辑，纯 VM 断言看不出来，只有真机截图能发现。**

## 5. 踩过的坑

1. **XML 注释里不能出现 `--`**：`<!-- ---- 自动 ---- -->` 直接 `MC3000` 构建失败；分隔线改用 `[自动]`。
2. **`DialogCloseListener` 在断言宿主里不可直接伪造**：反射 internal 构造器后 `Invoke` 会在异步续体里抛
   `DialogCloseCallback has not been properly initialized`，把整个宿主带崩（退出码 `-532462766`），
   而每条断言当时都已打印"通过"——**"通过"不等于没崩**。
   正解：把保存核心抽成 `Apply()`（不关窗、可断言），测试不再碰 Prism 关窗回调。
3. **另一会话正在改 `FlowManagerView.xaml`**：`dotnet build` 报 `MC3024 Header 设置两次`（文件 mtime 就在几分钟内）。
   按 C-41 不修别人的文件；用 `-p:BuildProjectReferences=false` 只编断言宿主先验证，全量 gate 等对方收尾。
4. **运行中的宿主锁 `Modules\`**：`Plugin.CSharpScript` / `Plugin.ImageScript` 的复制后步骤报 `MSB3073`；
   先等 VisionMaster 退出再全量构建（A-01/A-04）。
5. **`FlowModel.Steps` 是 `ObservableCollection`**：深表遍历要自己递归 `IContainerStep.Children`，
   容器自身不是候选（它没有可判定的输出端口）。
