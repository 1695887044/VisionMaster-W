# 2026-10-29 读超时体检与默认值分档（第 2 批）

> 来源：通讯体系优化清单第 2 批（A 项）。目标：让"读超时远大于扫描周期"这种配置在**保存时**和**加载时**
> 都能被指出来，并把以太网默认值从"跟随 HSL 的 5000"改成有依据的 2000。
> 前置：`2026-10-29-通讯超时三处错接修复（第0批）.md`、`2026-10-29-字区位变量并段（第1批）.md`。

## 一、当前状态

已落地。`CommChecks` **400 通过 / 0 失败**（新增 8 条）。

## 二、已做

### 2.1 规则：`ReadTimeoutAdvisor`

新增 `Communication\Communications\Manager\ReadTimeoutAdvisor.cs`，单一实现、两个出口共用。

**判据：读超时 > 生效最短扫描周期**（不是"周期的一半"）。
理由：TCP 类默认读超时 2000ms 与常见周期 1000ms 本就同量级，取一半会让大量正常配置 100% 触发告警，
警告立刻退化成背景噪声。取"超过一个整周期"——含义是"一次静默超时至少吞掉一整拍"，这是用户能感知的伤害起点。

**为什么比"最短"而不是默认组**：调度器按各组自己的周期驱动，自定义组可能比默认组快得多；
5s 超时对 100ms 组是 50 拍，对 10s 组只是半拍。取生效最短周期才是最坏情况。

结论里带三样东西：吞掉几拍、代价口径（串口"乘以段数" / TCP"1 次超时 + 重连"）、建议区间。

**边界处理**：周期低于读超时下限（100ms）时，"压到周期/4"根本做不到——直说"两者无法匹配，
请把周期调到 ≥400ms 或接受跨拍读取"，不给夹到下限的假建议（第一版输出过"建议降到 100~100ms"，已修）。

### 2.2 日志出口（方案加载 / 运行时重编译）

`AdvancedCommunicationManager.RebuildPollPlan` 末尾调用 `ReportReadTimeoutAdvisory`。
这是"方案加载 / 改扫描组 / 注册变量"三类动作的公共汇聚点，一处挂上就全覆盖。

**按结论文本去重**：同一份配置反复重编译（2357 个变量注册下来会触发多次）只在结论变化时告警一次；
配置改好后结论变 null、条目被清掉，再改坏会重新告警——不是"一次告警永久静音"。
`RemoveConnection` 同步清条目，避免同名连接删掉再建时被旧结论压住。

### 2.3 提示出口（设置对话框保存）

`CommunicationSettingsViewModel.ExecuteAdd / ExecuteEdit` 成功后调 `ShowReadTimeoutAdvisory`，
弹一次 `Notifier.ShowWarning`（toast，不阻断保存）。规则与日志出口共用同一个 `Describe`。

只提示不改值：读超时的合理取值取决于现场（网关、无线、低速串口差异很大），自动改会把用户明确填过的数字
悄悄换掉。

### 2.4 默认值分档

| 传输 | 默认读超时 | 依据 |
|---|---|---|
| 以太网（`EthernetConfigBase`） | **2000ms** | 帧小、链路快；5000 在 1000ms 周期下等于白等 5 拍 |
| 串口（`SerialConfig`，直接继承基类） | 5000ms（不变） | 2400bps 下单帧 256 字节本身约 1.07s，压不下去 |

放在 `EthernetConfigBase` 构造器而不是工厂里：任何新建的以太网配置（属性面板新建、方案里缺该字段的老文件）
都拿到同一个值，不需要每个协议各写一遍。**没有动** `ConnectionConfigBase` 的初始化器（串口靠它保持 5000）。

**兼容性影响**：已存盘的配置有显式值，行为不变；只有"方案文件里缺 `ReadTimeoutMs` 的以太网连接"
会拿到 2000 而不是 5000——这是本次有意为之（正是要修的"白等 5 拍"）。

### 2.6 断言（8 条）

| 断言 | 钉住什么 |
|---|---|
| C8-1 ModbusTcp 默认 2000 | 以太网分档生效 |
| C8-1b 串口默认仍 5000 | **反向**：分档没有连串口一起降 |
| C8-11 未超过周期 → 不提示 | 不制造噪声 |
| C8-11 5000/1000 → 5 拍 + 带"重连" | 结论内容与 TCP 口径 |
| C8-11 自定义快组 50ms → 100 拍 + "无法匹配" | 按生效最短周期算；低于下限时直说无解 |
| C8-11 串口提示带"段数" | 串口与 TCP 的代价口径必须不同 |
| C8-12 编译计划触发体检，同一结论只告警一次 | 日志出口接线 + 去重 |
| C8-12 改好再改坏 → 重新告警 | 去重按结论，不是按连接永久静音 |

C8-12 用 `RequestConnect`（同步编译轮询计划、非阻塞建连）驱动，不需要设备在线；
`AdvancedCommunicationManager.LogSink` 装一个 `CapturingLogSink` 收 Warn 文本，断言命中次数。

## 三、未做

  OmronFins 同理。字段说明里写清了，但按协议隐藏继承字段要动属性面板（清单 D3）。

## 五、踩过的坑

- **阈值取"周期的一半"会自触发**：新默认 2000ms + 常见周期 1000ms，取一半就是 2000 > 500，
  默认配置 100% 告警。判据必须与默认值一起设计，不能分开拍脑袋。
- **默认值分档不能改基类初始化器**：`ConnectionConfigBase.ReadTimeoutMs = 5000` 是串口的下限依据，
  改它等于把低速串口一起压死。分档的正确落点是传输基类构造器（`EthernetConfigBase`），不是工厂也不是基类。
- **"压到周期/4"在快组上无解**：50ms 周期的 1/4 是 12ms，低于字段下限 100ms；
  第一版夹到下限后输出"建议降到 100~100ms"，是自相矛盾的建议。**给建议值前先判"这个建议在字段约束内是否可达"**。
- **日志出口只在 `State == Connected` 时才重编译**（`ConnectionWorker.Loop` 第 3 步）：
  想测这条接线，必须用同步入口 `RequestConnect`（它自己调 `RebuildPollPlan`），
  靠"注册变量后等一拍"在没设备的环境里永远等不到。
- **去重要按结论文本，不能按连接名**：按连接名做"已告警"集合，会让"改好再改坏"永远静默；
  按结论文本去重才能既防刷屏又保证改坏后重新提醒。
