# 视觉图像页滚轮缩放无下界（图像缩到看不见只剩标注文字）修复（2026-10-27）

## 一、当前状态

**现场**：跑完 `码读取_Code128` 后，在「视觉图像」页手动滚轮放大/缩小，画布变成一片黑，
只剩一行绿色标注文字 `A: Text, B: □□□, C: 347862`（截图 2）。

**根因（已取证，不是猜测）**：滚轮缩放**没有下界**。

- `HSmartWindowControlWPF` 的滚轮每格把显示范围（part）跨度乘 `HZoomFactor`（默认 √2），
  且**不设上下限**（反编译 `halcondotnet.dll`：`HZoomWindowContents` 只做 `HomMat2dScale` + 写 `HImagePart`）。
- 缩 17 格 ≈ 500 倍：771px 的图在 880px 宽的画布上只剩 1px → 画布全黑。
- **几何标注（码框）一起缩没**（它按图像坐标画），但**标注文字不缩**——HALCON 的
  `set_tposition` 只换算位置、不换算字号，字是定长像素画的。于是"图没了、字还在"。

**取证链**（三条独立证据，互相印证）：

1. **截图逐像素测量**（`tools/oneoff/pixscan.ps1`，临时脚本已删）：
   - 截图 2 画布内**除标注文字外没有任何非黑像素**：`green count=1824 bbox=(1321,1051)-(1606,1072)`；
     连码框（截图 1 里绿色 bbox 横跨整幅）都不见了 → 几何元素全部缩到亚像素，不是"没画"。
   - 同一行文字在截图 1 是 `(717,357)-(1012,420)`、截图 2 是 `(1321,1051)-(1606,1072)`，
     **字宽完全一致（≈285px）**、位置大幅移动 → 字号不变（窗口像素定长）、part 变了（确实发生了缩放）。
   - 文字新位置几乎就在缩放锚点（鼠标处）上 —— 大幅缩小时画面元素会向锚点收敛，与该位置吻合。
2. **离屏探针复现**（`tools\probes\_ZoomProbe`，已登记进 `probes.json` + `README`，`run-probe.ps1 -Name ZoomProbe` 可复跑；真窗口 + 真 `ImageDisplay` + 真 `HSmartWindowControlWPF`）：
   - 连续 12 格外缩：part 跨度 766 → 6019，非黑像素 75.5% → 1.2%；
   - 强行把 part 设成 90 万跨度（等价于缩过头）：非黑像素 **0.1%**（只剩标注文字）——
     与现场截图同一形态。
3. **反证**（排除"图像被 Dispose 导致丢图"这条替代解释）：
   - 探针场景 C：把**正在显示**的 HImage `Dispose()` 后滚轮放大，图**照常显示**（非黑 100%）——
     HALCON 的显示栈自己持有对象引用，宿主释放托管包装不影响重放；
   - 探针场景 B：只有当 `HImage` 处于"非 null 但已失效"时 `RenderAll` 才会跳过图像只画标注
     （黑底 + 绿字）。但那种状态下**文字不会随缩放移动**，与现场截图（文字位置大变）不符 → 不是本次成因。

## 二、已做

1. `Services\Core.Halcon\Base\HalconBase.cs` 新增滚轮缩放的上下限（**唯一改动点**）：
   - `OnApplyTemplate` 里挂 `hSmart.PreviewMouseWheel += HSmart_PreviewMouseWheelForZoomLimit`。
     必须在 **Preview（隧道）** 阶段拦：控件自己的 `HWPFWindow_MouseWheel` 挂在 `MouseWheel`（冒泡）上，
     `e.Handled = true` 之后它就不会再缩。
   - 规则三条：
     - **下限 = 整幅铺满**：已到铺满就不再缩小；
     - **已经缩过头**（旧视图缓存 / 外部设过 part）→ 一把 `SetFullImagePart()` 拉回铺满（一个滚轮格即可救回）；
     - **放大上限**：part 行跨度 ≤ 8 图像像素就不再放大（否则 part 退化成一个点，同样什么都看不见）。
   - `FitPartRowSpan()`：按 `set_part(0,0,-1,-1)` 的口径算"铺满"的行跨度
     `max(图高, 图宽 × 窗口高 / 窗口宽) − 1`（探针实测：图 771×767 / 画布 880×660 → 766，与 HALCON 实际 part 完全一致）。
   - `TryRestoreViewPart()` 增加一条校验：缓存里"跨度比铺满还大"的记录**不恢复**（历史脏缓存同样会演一遍黑屏）。
   - 没越界时**一律放行**，行为与改动前完全一致。
2. **顺带修掉一处编译错误**（另一个并行会话 10:08 写进同一文件的）：`newSize[0].I` ——
   `HImage.GetImageSize()` 走的是 `HObjectExtension` 的扩展方法，返回 `int[]`，元素本身就是 `int`，
   没有 `.I`。改成 `newSize[0]` / `newSize[1]`。
3. 探针验证（`tools\probes\_ZoomProbe`，已登记为 `ZoomProbe`，`run-probe.ps1 -Name ZoomProbe` 可复跑）：

   | 场景 | 期望 | 实测 |

   | D1 铺满时滚轮外缩 | 被拦、part 不变 | `Handled=True`，span 766（基线 766） |
   | D2 滚轮内缩 | 放行 | `Handled=False` |
   | D3 外部强设 90 万跨度（复刻现场） | 黑屏 | 非黑 0.1% |
   | D4 该状态下滚轮外缩 | 弹回铺满 | span 900000 → 766，非黑 75.5%（图回来了） |
   | D6 放大到 span 6.2 后再内缩 | 被拦 | `Handled=True`，span 仍 6.2 |

   `Core.Halcon.csproj` 构建 0 错误；`VisionMaster\bin\Debug\net9.0-windows\Core.Halcon.dll`

## 五、踩过的坑

1. **"图没了只剩字"不等于"图没画"**：标注文字按窗口像素定长，几何按图像坐标缩放 ——
   两者对 part 的响应不一样，只看截图很容易误判成"渲染管线丢图"。判据要落到
   "画布内非黑像素的 bbox + 字宽是否随缩放变化"。
2. **`PreviewMouseWheel` 与 `MouseWheel` 是两段路由**：拦第三方控件的滚轮只能在隧道段
   `Handled`，冒泡段拦不住（控件自己的处理器已经在冒泡段跑完了）。
3. **探针量"绿字"不能只看 R 通道**：绿色 `(0,132,0)` 的 R=0，用 R 通道统计会把字算成"没画"。
   本轮第一次统计就被这个坑误导过一次（`nonblack` 改成三通道取最大才对）。
4. **`HImage.GetImageSize()` 有两个同名入口**：HALCON 实例方法是 `GetImageSize(out int, out int)`，
   仓里还有个扩展方法 `int[] GetImageSize(this HImage)`。写成 `x.GetImageSize()[0].I` 编译不过
   （`int` 没有 `.I`）—— 并行会话留的就是这个错误。
5. **并发会话是真的会撞车**：本轮 10:06–10:13 期间另一个会话在改同一批文件，
   编辑工具直接报 `File has been modified since read`。**动手前先看 `LastWriteTime`（R9）**，
   撞上了就只做验证与记录、别再往同一文件里加改动。
