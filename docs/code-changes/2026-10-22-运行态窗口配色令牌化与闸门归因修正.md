## 3. 关键决策

- **17 个令牌单开一节，不复用 `Dialog*`/`Scada*`**。运行态窗口是**深色语境**，和主界面浅色语义不同源；若混用，将来"调面板底色"会顺手把运行窗口也改浅。理由写进了 `Colors.xaml` 注释。
- **底色挪到根 `Grid`，不是改 `DynamicResource`**。首次写成 `<Window Background="{StaticResource ScadaRunWindowBrush}">` → 解析期抛 `XamlParseException: 无法找到名为"ScadaRunWindowBrush"的资源。资源名称区分大小写。`，连带崩掉 5 段断言（RH11/RH16/RH17、运行窗口形态、落屏、Phase 2 UI、多基座弹窗）。根因：**元素自身属性在解析期先于该元素的 `Resources` 求值**。改 `DynamicResource` 能绕过但违反 R31，所以选择挪属性位置。
- **断言改查语义而不是给 XAML 补 `RunningTag`**。补一个没人用的元素名只为迎合过期断言，等于把错误固化；改成"RunState 两个取值各自驱动命名元素显示（元素名不钉）"，以后再改元素名不会误报。
- **`DlClassify` 进 sln 而不是继续靠 `FlowCanvasChecks` 顺带重建**。顺带重建只在"跑断言"这条路上成立，用户日常用 VS 编类库这条路完全不经过它。
- **基线删行而不是把 22 写进基线**。写进基线等于承认"这个文件可以有 22 个硬编码色"，违反 R140 存量只减不增。
