## 一、根因（证据链）

| # | 现象 | 根因 |
| --- | --- | --- |
| ① 界面运行拿不到真并行 | `ShellViewModel` 两个运行入口写死 `debugSession: true`（DWV 第 1 期"界面运行=调试会话"）→ 引擎同时置 `DebugEnabled` + `DebugDegradedParallel`（FlowEngineService）→ `CompiledParallelNode` 退化判定命中 → **并行组就地平铺顺序执行**（日志有"并行组 'X' 在调试/试运行会话中按顺序执行"）。设计注释（FlowSession.DebugDegradedParallel）本预留了"界面普通运行→真并发"入口，但 Shell 从未实现 | 调试不并发是刻意的（单步/断点语义在真并发下没有良定义：DebugStepPending 单次消费、PauseReason 单值、FocusedStep 单指针），错在"界面运行无条件调试" |
| ② 并行分支步骤耗时不刷新 | UI 实时耗时唯一刷新源 = 流程栏 200ms 定时器 `TickRunningTimes`，旧判据 `IsRunningFocus && State==Running`；而并行分支线程走 `UpdateStepRuntimeState` **分支快捷路径**——只写 State+计时、刻意不碰 FocusedStep（并发不变量 1）→ 分支步骤 `IsRunningFocus` 恒 false → 实时耗时停 0、跑完才一次性蹦终值（`LastRunTimeMs` 终值能显示）。XAML 绿色"运行中"高亮触发器同样只认 `IsRunningFocus` | 与①叠加：修好①后分支步骤全程无高亮无实时耗时，必须一起修 |
| ③ 容器与上级算子不居中对齐 | 顺序链端点 = 双方"缘中点"（`EdgeMidpoint`）：容器比算子宽得多，两个中心的 X 必然错开，正交走线被拽成"下-横-下"拐弯 | 端点几何问题，非布局问题 |

## 二、改动与口径

| # | 改动 | 口径 |
| --- | --- | --- |
| 1 | **方案 A**：`RunAllEnabledOnce` / `RunAllEnabledContinuous` 改为 `debugSession: flow.HasBreakpoint()`；自动进调试时 `Notifier.ShowInfo` 说明"断点/单步生效，并行组将按顺序执行" | 界面运行默认**普通运行**（真并发）；断点是"按需调试"的开关——设了断点才装调试门。断点在**运行中**才设置的，本轮不生效、下次启动生效（与 HTTP 运行同款既有语义）。`FlowModel.HasBreakpoint()` 深度递归（容器判定走 `IContainerStep`，与 FlowTopology 同口径） |
| 2 | `TickRunningTimes` 判据放宽为 **`State==Running && LastRunStartTimestamp.HasValue`**（不再要求 IsRunningFocus），改 `internal static` 供断言直调 | 读 State 无并发问题（每分支各自写自己的 StepModel）；终态不满足条件 → 引擎冻结的终值不会被覆盖；`FocusedStep` 单指针机制原样不动 |
| 3 | `ProcessView.xaml` 算子卡新增 **`State==Running`** 触发器（与 IsRunningFocus 触发器 Setter 同款：绿卡 + 实时耗时 + 转圈图标） | 真并行时多条分支同时绿色高亮——这才是并行的真实图景；放在 LastRunTimeMs 触发器之后，上一轮冻结值让位给本轮实时值 |
| 4 | 顺序链**就窄轴拉直**：`SharedVerticalX`——下游中心落在上游跨度内 → 用下游中心（容器→算子，箭头打在算子正中）；否则上游中心落在下游跨度内 → 用上游中心（算子→容器，链贴算子轴垂直下落）；互不在跨度内（并排错位的手摆图）保持中心对中心不硬掰；内缩 12px 避开框角/折叠钮 | 只影响"一方是宽容器"的链；等宽算子间行为逐位不变（旧断言原样绿）。数据线锚点不受影响 |
| 4b | **布局本层居中**（用户追问"延时_2 应该在中间不是左对齐"后追加）：`FlowLayoutStore.PlaceLevel` 按"本层最宽项的设计轴线"派位——叶子 X = 轴线 − 盒宽/2，新容器 X = 轴线 − 设计宽/2；新增纯测量 `MeasureItemWidth/MeasureLevelWidth`（公式与 PlaceExpanded 框宽逐项同源，折叠态判定同规则） | 只影响**本次新落位**的项，已有坐标原样沿用（拖过的位置不冲掉，"只补缺项"纪律不破）；本层外接矩形不变 → 泳道/框体/行推进逐位不变。**存量流程要点一次画布「整理」才会整体重排居中**。分支内子层同样居中（递归同一路径），嵌套容器链沿同一轴线 |
| 5 | `VisionMaster.csproj` +`<InternalsVisibleTo Include="FlowCanvasChecks" />`（照 ScadaChecks 先例） | TickRunningTimes 是纯计算，断言直接调验判据，不再绕反射 |
