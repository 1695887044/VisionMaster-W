# 底部控制台抽屉条（收起态 32px）与页签清理

日期：2026-10-26　状态：已实现并真机验收（见文末「验证」）

## 为什么抽屉条挂在 Shell 根 Grid，而不是放进 LogView

AvalonDock 4.74.1 的 `LayoutAnchorablePane` **没有** `ShowHeader`（反射 `net48` 程序集确认：
只有 `LayoutDocumentPane` 有），`LayoutAnchorablePaneControl` 也没有任何 Header/CanShow 成员。
只要面板还在停靠树里，库就一定画自己的页签条；抽屉头塞进视图内容，32px 里露出来的只有库的页签条，
自定义头根本看不见——要藏只能改库模板（模板编译在 `AvalonDock.Themes.VS2013`，仓库无源）。

所以：**收起 = 把整块底部面板从停靠树摘下缓存 + Shell 根 Grid 多一行 32px 抽屉条；
展开 = 按原父容器、原索引插回 + 抽屉条折叠成 0。**
推论：展开态没有摘要条（由库页签条接管）。

## 收起为什么不是"把 DockHeight 压到 1px"（本轮返工的原因）

第一版按"1px"实现，真机一跑就露馅：**AvalonDock 的页签条有约 20px 最小高度**，
`DockHeight = 1` 只把面板框压到 1px，页签条照旧画在面板外（`Control.ClipToBounds` 默认 false），
屏幕上变成「抽屉条上方多一条重复的控制台 / 监控栏」。

试过三条路，只有第三条成立：

| 尝试 | 结果 |
| --- | --- |
| 压 1px + 运行时给该 pane 控件设 `ClipToBounds=true` | 无效：溢出的是面板**自身最小高度**，不是可以裁掉的子元素 |
| 抽屉条覆盖在停靠区底部 32px 上 | 停靠区横跨左中右三列，覆盖会把流程导航/工具箱的底部也盖住 |
| **把整块 pane 从父容器摘下缓存，展开时原索引插回** | ✅ 屏幕上真的没有它，位置不漂 |

为什么不用 `IsVisible=false`（Hidden 区）：恢复时库按"记忆容器"插回，容器已不在树上时会退化成
"找任意空 pane / 在根末尾新建一列"，控制台可能跑到别的列去。缓存整块 pane 是确定性的。

## 四个实现要点（都是踩过的坑）

1. **状态只有一个事实源**：`LayoutHelper.CurrentConsoleState`，由「状态栏按钮 / 抽屉箭头 / 抽屉页签 /
   运行场景 / 组态隐藏」五条路径共同改写，`ShellViewModel` 只转发给抽屉 VM。
   旧实现用 `DockHeight > 60` 反推——用户把分隔条拖到 50px 就判错，而且组态（隐藏）与用户收起在高度上分不开。
2. **计数必须共用同一份 `LogViewModel`**：它订阅的是具体类 `LogService.OnLogReceived`，每个实例各收一份；
   抽屉自己再造一个会在 `LogPanelMaxRows` 上限处与日志页的「全部 N」分叉。故注册成单例
   （与 `ScadaEditorViewModel` 同一手法：singleton 覆盖 `RegisterForNavigation` 的默认单次构造）。
3. **必须升布局结构版本（6 → 7）**：旧 `Layout.xml` 里存着 `Panel_DeviceStateView`，
   反序列化会把它原样恢复成一个空壳标签——正是这次要删的东西，而 ContentId 覆盖度校验不会报错。
   属于 R43 判据「旧布局恢复会不会抵消改造」：会，所以升版让旧布局作废重建。
4. **"还原收起前那一页"只能用一次**：`AttachConsolePane` 在插回时还原用户看的页，用完立即清掉记忆；
   否则之后每次模式收敛（都会走 Expanded）都会把用户刚切过去的页签拽回旧的。

## 未做 / 已知边界

- **展开态没有摘要条**（库页签条接管）。要保留摘要得把控制台整体移出 AvalonDock，
  代价：布局持久化自建、`ShowPanel` 命令链、R56/R58 面板收敛、四个断言宿主、`ShellCopy.xaml` 全要改。
- 收起状态下无法切页（设计如此）：抽屉上的两个页签按钮点下去是"展开到那一页"。
- 调试模式启动仍是「展开」而不是基线表里的「收起 32」——本次只换了收起态的呈现方式，没改启动默认值。
