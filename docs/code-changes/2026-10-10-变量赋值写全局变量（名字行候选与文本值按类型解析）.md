# 2026-10-10 「变量赋值」写全局变量：名字行不再用通用绑定弹窗，值的文本按声明类型解析

> 真机反馈（用户原话）：
> 「变量赋值的时候，在弹窗上选择全局变量绑定后，**编译不通过**；必须在变量绑定弹窗的**常量处手动输入全局变量名**；
> 21 也**赋值不进去**。」
> 截图里那条状态：`状态: ✕ 失败 - 全局变量「OKCount」的类型是 Int32，无法写入 String`（对话框底部状态栏）。

---

## 1. 两条症状，一个根

「变量赋值」的作用域选 `全局变量` 之后，这个节点要表达的是
**"把 21 写进 OKCount"**，而配置界面上那两行分别是：

| 行 | 要的语义 | 当时的界面给了什么 |
|---|---|---|
| 变量名 | **名字**（文本） | 一个手填框 + 🔗（点开=通用「变量绑定」弹窗） |
| 值 | **值** | 一个手填框 + 🔗 |

通用「变量绑定」弹窗的语义是"**这个端口的值由某个数据源在运行期提供**"——
在它里面选中一个全局变量，落下来的是一条 `LinkKind.GlobalVariable` 连线：**运行期把那个变量的值喂给这个端口**。
把它挂到"变量名"这一行上，等于说"名字 = 那个变量的当前值"，而不是"名字 = 那个变量的名字"。

于是两条症状各自成立（都已在断言里复现，见 §3）：

| # | 用户动作 | 实际发生 | 用户看到的 |
|---|---|---|---|
| ① | 在绑定弹窗里选中全局变量（HImage / 数组这类**塞不进 string** 的类型） | 编译期 `TryValidateLink` 按类型守门拦下这条连线 | `[连线类型不匹配] '变量赋值_0' 的输入端口 'Name' 期望 String，但上游 'Global' 提供的是 HImage` → **编译不通过**（2026-09-25 线序检测文档 §10 已记过同一条） |
| ① b | 选中的是数值型变量（Int32 的 `OKCount`） | 编译能过（`IsLinkable(int,string)` 允许数值→文本），但运行期"名字"变成了该变量的**值** → 值为空时 `变量名称不能为空`；有值时（演示变量 `OKCount` 初值 1485）`找不到全局变量「1485」` | 试运行失败；**这条绑法永远写不到 OKCount** |
| ② | 改在弹窗的**常量框**里手打 `OKCount`（能编译、能跑），值填 `21` | 值端口是 `InputPort<object>`，界面上只能产出**文本** `"21"` → 宿主 `GlobalVariableWriter` 按声明类型**硬守门**、不做任何解析 | `全局变量「OKCount」的类型是 Int32，无法写入 String` → **数字/布尔永远写不进去**（截图那条） |

② 是"给 Int32 变量填 21 根本不可能成功"，属于死路；① 是"选变量"这个最自然的动作把人带进坑里。
两条都不是"用户操作错"，而是**界面在这一行没有表达"名字"的能力**。

## 2. 修法

### 2.1 「变量名」行改成"名字编辑器"（候选来自宿主快照）

| 文件 | 动作 | 说明 |
|---|---|---|
| `Shard\Core.Interfaces\IPluginConfigContextProvider.cs` | 改 | `PluginConfigContext` 加 `Variables`；新增 `VariableOption`（Name / Scope / TypeName / Description）。与既有 `Cameras` 同一范式：**只读快照**，不让插件持有宿主活对象 |
| `VisionMaster\Helpers\PluginVariableOptions.cs` | **新增** | 快照组装：`GlobalVariables`（变量管理那批）+ 目标步骤**上游**「变量定义」节点声明的运行时变量名（走既有 `FlowQueryHelper.TryGetDefinedVariable`，不另写一套判据） |
| `VisionMaster\ViewModels\DialogViewModels\PluginConfigShellViewModel.cs` | 改 | `BuildConfigContext` 里填 `Variables`（宿主本来就在这儿给相机快照） |
| `Plugins\Plugin.Utility\VariableAssignmentPlugin.cs` | 改 | 实现 `IPluginConfigContextProvider`；新增 `NameCandidates`（按作用域过滤的候选）/ `NameHint`（提示，含目标变量的**声明类型**）；`Initialize` 里记住这一行的**旧连线**并订阅作用域/名字变化 |
| `Plugins\Plugin.Utility\VariableAssignmentView.xaml` | 改 | 「变量名」行换成可编辑 `ComboBox`（候选下拉 + 手填）+ 一行 `NameHint`；**通用绑定控件只剩「值」那一行** |

三条纪律写进代码注释与断言：

1. **这一行要的是名字**，所以选出来的名字落成**常量**（`VariableName.Value`），不是连线；
2. **旧连线自愈**：老方案 / 早先在通用弹窗里绑过全局变量的步骤，打开窗口时把地址**写进提示**（"该行原由上游提供（…）—— 在本行选/输一个变量名即可改为手填"），用户一动这一行就 `RemoveLink`。
   不这样做的话运行期是"有连线就以连线为准"，**键盘敲下去那串字不会生效**（界面正常、写的是别的变量，最难查的一类）；
3. **提示里点明声明类型**（"写入全局变量「OKCount」（Int32）——「值」按它的类型解析"），因为值那一行只能填文本，类型不匹配是这条链上最常见的失败。

#### 复核（独立 reviewer 子智能体）改掉的三处

| 问题 | 现象 | 最终做法 |
|---|---|---|
| **P1 换作用域会把名字清空** | 可编辑 `ComboBox` 当前**有选中项**时，`ItemsSource.Clear()` 会把 `Text` 一并置空并沿 TwoWay 绑定**把空串推回端口** → "选中名字 → 切作用域"这个连招静默清名，点确定就落盘成空名（运行期报 `变量名称不能为空`） | `RefreshNameCandidates` 重算前记住端口里的名字、重算后**顶回去**；断言：`【插件】换作用域重算候选后名字还在` |
| **P2 "值变了"≠"用户编辑"** | 试运行 `PluginTestRunner.BridgeInputs` 会把上游实际值灌进配置实例端口；原先订阅 `VariableName.ValueChanged` 判"用户改名"，会在这条路径上**误解除用户没动过的旧连线**（改的是活模型，取消也退不回来；P2 并存于 [A4] 断言之外） | 不再订阅端口事件；改由**视图**上报真实输入事件（`PreviewTextInput`（键入）+ `PreviewKeyDown`（退格/Delete/Ctrl+X）+ `DataObject.Pasting`（粘贴）+ `SelectionChanged`（下拉选）→ `NotifyNameEditedByUser()`）；断言：`【插件】程序灌值不解除旧连线` |
| **P2 跨作用域同名** | 候选去重只按名字（全局先入），上游声明的运行时变量与某个全局变量同名时，`Runtime` 的候选里就没有它；提示还会说成"不在上游的变量定义里"（与事实相反） | 去重键改 **名字+作用域**；提示补一支"该名字是另一个作用域的变量，要写它请改作用域" |

同批复核还提出、本批一并处理的：`IsTextSearchEnabled` 由 `True` 改 **`False`**（可编辑下拉的"输入即补全"会把键到一半的 `OK` 补成 `OKCount` —— 正是本次要消灭的那类静默写错变量；候选照常下拉可选）；
`[A4]` 两条偏弱断言已收紧（第 3 条补"运行确实失败且错误非空"；第 7 条静态扫描改判**精确绑定串** + 视图上报方法名与输入事件挂载串，不再只找 `<ComboBox`）。

#### 二次复核（改了第一批之后）又抓出两处

| 问题 | 现象 | 最终做法 |
|---|---|---|
| **P2 我新加的那条断言是假绿** | "换作用域重算候选后名字还在"在断言宿主里根本**没有 ComboBox**，没有任何东西会把端口写回空串 —— 把插件的"记住—顶回"整段删掉，这条断言照样绿（它守不住它声称守的坑） | 断言里**手动模拟绑定中的 ComboBox**：订阅 `NameCandidates` 的 `CollectionChanged`，遇 `Reset`（=Clear）就把 `VariableName.Value` 置空（=TwoWay 回写），然后再断言名字被顶回来 —— 删补偿必红 |
| **P3 右键菜单「剪切」漏报** | `PreviewKeyDown` 只认 `Ctrl+X`；右键菜单的「剪切/删除」既无按键也不走 `Pasting` → 老方案里那行若有旧连线，剪切后不再有输入 → 连线仍在（框里空名、实际用连线值） | 补 `CommandManager.AddPreviewExecutedHandler`（`ApplicationCommands.Cut/Delete`）+ `DragDrop.DropEvent`（`handledEventsToo: true`）兜住右键菜单与拖拽落文；两者都只在**用户手势**触发命令时发，程序改文本不发 |

### 2.2 值的文本按声明类型解析

`Core\Binding\GlobalVariableWriter.cs`：类型守门遇到**文本**时先按变量声明类型解析一次（`Convert.ChangeType`），
解析不了才报错（错误信息里带上被拒的原值）。口径与运行时变量那条路（`VariableAssignmentPlugin` 的 `Convert.ChangeType`）一致。

两条附加口径（复核提出后收紧）：

- **不变区域性**（`InvariantCulture`）：zh-CN 与不变区域性在小数点上一致（`.`），显式写死才能保证换机器/换区域设置时同一个方案解析出同一个数。
  代价（复核提示）：**日期文本**也跟着收窄 —— `2026-10-10` 能解析，中文习惯的 `2026/10/10` 会被拒（要支持就显式列 `DateTime` 的格式串）；
- **数值文本不许带千分位分隔符**：默认解析会把 `2,5` 读成 `25`（用户想写 2.5）——"应当报错却改了值"的一类，宁可让他改写法。

**只放宽文本**：类型化的值（double 塞进 int 变量）仍按原样报错 —— 那多半是上游接线错了，静默截断会把错因推迟到很远的地方。
数组 / 枚举 / HImage 这类目标 `Convert` 不了，照旧报"类型不匹配"（`docs\图像赋值\图像赋值插件.md` 的消息表已同步）。

## 4. 未决 / 注意

1. **"名字由上游算出来"这类用法**（例如名字取自条码变量）在本视图里**不再提供入口**：本行只能手填/从候选里选。
   通用「变量绑定」窗口（画布右键入口）仍然能给这一行挂连线；那种连线在本视图打开时会以提示形式说明"原由上游提供"，用户一动这一行即改为手填。
   ——这是刻意的取舍：让"选一个变量"落在正确的语义上，比保留一条**看起来能用、实际写错变量**的绑法更值。
2. 运行时候选的来源是上游「变量定义」节点（`FlowQueryHelper.TryGetDefinedVariable` 的既有口径）。
   仓库当前没有该插件的 CLR 类型（`Plugin.Utility` 里只有 6 个工具），所以实际候选通常为空 —— 名字照样可手填；
   等该插件回归，候选自动出现（快照按类型名识别，不依赖 CLR 类型）。
3. `VariableOption.TypeName` 是短名（`Int32` / `String` / `HImage`），只用于**显示与提示**；寻址仍按 **名字**（与本行落常量的语义一致，不引入 Id 引用）。
4. **待真机点一次的四处**（WPF 行为无法在断言宿主里点，断言只钉住了插件侧的可判据部分）：
   ① 打开一个已存名字的节点 → 名字行应显示该名字；② 从下拉选一个候选 → 切作用域 → 名字**不该**变空（断言钉的是"重算后端口值被顶回去"，ComboBox 自身行为仍值得眼过一遍）；
   ③ 名字行键入 `OK` → **不该**被补成 `OKCount`（本批已把 `IsTextSearchEnabled` 关掉，正是防这个）；④ 老方案里该行曾挂连线的节点 → 打开时应看到"原由上游提供"的提示，动一下该行后提示消失。
5. `RefreshNameCandidates` 的"记住—顶回"是针对可编辑 `ComboBox` 在 `ItemsSource.Clear()` 时清空 `Text` 的**补偿**；若将来换控件/换绑定方式，这条补偿可删（`[A4]` 的"换作用域重算候选后名字还在"会立刻发现该不该删）。
6. 值的文本解析现在**拒绝千分位分隔符**（`1,500` 会被拒而不是读成 1500）。这是刻意的取舍：静默把 `2,5` 读成 `25` 比拒一次按键更危险；若现场反馈"想写千分位"，再统一放开（`GlobalVariableWriter.TryCoerceText` 一处改）。
