# 语音播报（TTS）第二步：`语音播报` 动作 + 变量插值

日期：2026-10-25
状态：**已完成并验证**（`ScadaChecks` 3034 通过 / 0 失败）

## 1. 当前状态

第一步（报警自动播报）已上线：报警产生时由 `ScadaAnnouncerService` 串行念出
"级别 + 报警名 + 消息"，带 30 秒去重、队列上限 3、严重度抢占、说话期间压住提示音。

本步补上"**由组态触发的一句话**"：按钮按下、画面事件、计划表到点都能念，
且文本里可以写 `{变量名}` 按运行态当前值替换（例如"一号罐液位 {T101} 毫米"）。

## 2. 已做

| 文件 | 内容 |

**模板口径**（`ScadaTextTemplate`）：

- `{名字}` → 当前值；名字前后空白自动裁掉；
- `{{` / `}}` 转义成字面量 `{` / `}`；
- 未闭合的 `{` 按字面量处理（宁可念出一个花括号，也不吞掉后面的正文）；
- **解析不到的变量从文本里去掉**并记进 `Missing`，不把 `{T101}` 原样念出来。

### 2.2 执行侧（`VisionMaster`）

- `ScadaActionDispatcher`：新增 `Announcer` 可写属性 + `ExecuteSpeakText`。
  四档跳过（未接入 / 已关闭 / 没语音包 / 内容为空）各给一句可直接上屏的中文；
  部分变量找不到时**照念其余部分**，日志点名缺的是谁；整句渲染为空才跳过。
  档位映射与「播放声音」共用 `ToSeverity`（未知档位按 Info）。
- `ScadaAnnouncerService`：实现 `IScadaAnnouncer`，新增 `AnnounceCommand`。
  与报警播报只差一条——**不受 `MinSeverity` 门槛限制**：那道门槛是挡报警洪水的，
  挡掉操作员刚按下去的一句话等于按钮坏了。总开关 `Enabled` 照样生效。
- `ScadaMonitoringHost`：`Start()` 里 `_dispatcher.Announcer = _announcer`（与报警播报**共用同一个队列**，
  否则两套队列抢着说话）；`Stop()` 里先摘引用再 Dispose。

### 2.3 编辑器

- 事件编辑器（`ScadaEventEditor.xaml`）：动作下拉自动出现「语音播报」（候选来自 `Enum.GetValues`）；
  文案输入框与「记录日志」共用（`Type == SpeakText` 也显示），档位面板同样共用。
- 计划表编辑器（`ScadaScheduleManagerView`）：动作下拉新增「语音播报」；
  主输入框 = 播报文本，副输入框 = 档位（默认 Info）。

### 2.4 断言（`ScadaChecks/AnnouncerChecks.cs`）

| 编号 | 钉住什么 |

## 5. 踩过的坑

- **`[JsonIgnore]` 类问题不涉及本步，但插值位置踩了一次**：最初想把 `{变量}` 解析放在编辑器侧，
  那样运行态改值后文本不更新；必须放在**执行时**（`ExecuteSpeakText` 里渲染），
  否则念出来的是"配置那一刻的值"。
- **不要给 `AnnounceCommand` 复用 `Announce` 的 `key` 去重**：同一条动作连点两次应当念两次
  （操作员按了两次），去重只对报警的 `AlarmChanged` 反复上报有意义。
- `IScadaActionDispatcher` 加成员必须给**默认实现**：断言工程里有多个替身分发器，
  否则一次接口扩展会打红一片与本功能无关的断言。
- 枚举追加后有两处"末尾值 / 下拉顺序"断言会红（`[BIT1]`、类型下拉同源），
  这是**预期的**——它们正是防止静默改值的闸，改断言而不是改枚举。
