# 延时算子默认值被判「必填参数未配置」（诊断，2026-10-27）

## 一、当前状态

- 现象：拖「延时」进流程栏后**不打开参数窗、不点「确定」**就编译，报
  `[参数缺失] '延时_0' 的必填参数 'Delay' 未配置！`（`Engine\FlowCompiler.cs:1349-1352`）。
- 运行期其实不缺值：编译实例上 `DelayTimePort` 的值就是构造默认 500
  （`Plugins\Plugin.Utility\DelayPlugin.cs:24`），`RunAlgorithm` 直接
  `DelayTimePort.GetTypedValue()`（同文件 `:48`）。
  **编译期判据与运行期实际取值是两套口径**，这是本次现象的根。
- 根因（三段链）：
  1. `StepModel.InputValues` 新建时是**空字典**（`Core\Models\ProcessStep\StepModel.cs:361`）；
     拖入只造模型不灌值（`VisionMaster\Services\StepFactory.cs:31-81`，
     两个落点 `VisionMaster\ViewModels\ProcessViewModel.cs:1394` /
     `VisionMaster\ViewModels\FlowCanvasViewModel.cs:3580`）。
  2. 默认值只活在**插件实例的端口**上（`Shard\Core.Interfaces\DataPort\InputPort.cs:196-201`）。
     写回 `InputValues` 的唯一常规入口是参数窗「确定」：
     `PluginConfigShellViewModel.Confirm()`（`VisionMaster\ViewModels\DialogViewModels\PluginConfigShellViewModel.cs:569-580`）
     → `VisionPluginBase.OnConfirm`（`Shard\Core.Interfaces\VisionPluginBase.cs:362-381`）。
     取消不写——`AutoPortConfigView.xaml.cs:843-848` 原文：
     "值只在插件实例上……不调 OnConfirm 就不会进步骤的 InputValues"。
  3. 编译期必填判据只看 `InputValues` 里有没有键：
     `input.IsRequired && input.LinkedSource == null && !hasConstant`
     （`Engine\FlowCompiler.cs:1343-1352`），`hasConstant` = `InputValues` 有非 null 值。
     **端口自带的 500 不算数。**
- 所以"点确定就好了"不是巧合：确定那一刻 `OnConfirm` 把全部未链接端口的值写进
  `InputValues`，`hasConstant` 变真。打开窗但不点确定（取消）仍然编不过。

### 影响面（同一判据，不止延时）

`InputPort.IsRequired` **默认就是 `true`**（`InputPort.cs:27`），凡没显式写
`IsRequired = false` 的端口都算必填。按源码静态排查，**带可用默认值却仍被判必填**的有：

| 算子 | 端口（默认值） |
|---|---|
| 延时 | Delay(500) ← 本次现象 |
| 轴运动 | Mode(Absolute)、Target(0.0)、Velocity(0.0) |
| 运动使能 | Enable(true)、Timeout(10000) |
| 运动 IO | Value(true) |
| 数值比较 | A(0.0)、B(0.0)、Type、Tolerance(1e-6) |
| 数学计算 | Operation、A(0.0)、B(0.0) |
| 逻辑运算 | Operation、A(false)、B(false) |
| 类型转换 | Target、Format("yyyy-MM-dd HH:mm:ss") |
| 子流程调用 | TimeoutMs(60000)（FlowName 空串仍应判缺） |

图像类端口（`InputPort<HImage>` 默认 null）与名字类空串端口判"缺"是对的，现有行为符合预期。

> **安全提醒**：轴运动 / 运动 IO 的"必须配置"带安全含义（Target=0 会真走、Value=true 会真输出），
> 不能简单把判据一律放宽。

同一判据还有第二个投影：画布黄叹号 `CanvasNodeViewModel.RefreshMissingRequired`
（`VisionMaster\ViewModels\CanvasNodeViewModel.cs:809-827`），端口名快照来自
`FlowCanvasViewModel.ResolveRequiredPortNames`（`:1654-1681`）。**任何修法必须两处同步**，
否则出现"角标说缺、编译器放行"的分裂。
