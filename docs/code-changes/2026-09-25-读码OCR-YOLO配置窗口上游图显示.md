# 读码 / OCR / YOLO：配置窗口补齐"上游图自动显示"

## 需求与决策

用户打开「码读取」配置窗口后反馈："怎么没有上游图像绑定的地方"。排查结论分两层：

1. **流程级绑定一直存在且正常**——三个插件都有 `InputPort<HImage> Image` 端口，运行期
   `Image.GetTypedValue()` 取图；绑定位置在流程画布上拖线（平台统一机制，配置窗口本无绑定控件）。
2. **真正的缺口在配置窗口**：同类的 RegionColor/ColorCheck 都实现了"试运行桥接进来的上游图
   自动显示到预览"，而这三个插件（并行任务所写）的 `OnViewLoaded()` 只走示意图路径，
   导致配置窗口里永远看不到上游实际会进来的图。

用户确认修复范围：**三个都补**（码读取 + OCR + YOLO，同款缺口同一模板）。

## 实现方案（照 RegionColorPlugin 现成模式，三件套）

以 [RegionColorPlugin.cs L241-278](../../Plugins/Plugin.ColorRegion/RegionColorPlugin.cs) 为模板，每个插件补：

1. **构造函数订阅端口变化**：`Image.PropertyChanged += OnImagePortChanged`。
   试运行时上游图是**通过给端口赋值**桥接进配置实例的（`PluginTestRunner.BridgeInputs`），
   盯端口变化才能在点「执行」后自动刷新预览。
2. **`OnImagePortChanged`**：过滤 `nameof(IInputPort.Value)` → 调 `ShowUpstreamImage()`。
3. **`OnViewLoaded()`** 改为 `if (!ShowUpstreamImage()) LoadPreviewImage();`
   —— 优先上游图，没有才退回示意图路径（处理"视图晚于桥接打开/重开窗口"的情况）。
4. **`ShowUpstreamImage()`**：从端口取上游图，**拷贝一份**到 `DisplayImage`（上游句柄归框架管，
   插件只负责自己的副本——资源所有权铁律），失败只写 Hint 不抛异常。

另外三个视图在「示意图路径」标签上方补了一行发现性提示（沿用 ColorCheck 家族文案）：
"有上游图像时会自动显示（点下面的「执行」把它带进来）；也可以填路径手动载入一张示意图"。

## 已知边界

1. **Yolo 的试算依赖模型**：上游图带入后点「试算一下」需要已选好 .onnx 模型，否则仍提示先选模型。
2. **订阅在构造函数、生命周期与实例一致**：端口 PropertyChanged 订阅不主动退订（实例销毁即随 GC
   走，与 RegionColor/ColorCheck 同策略）；若未来出现"同一实例反复开关配置窗口"的重复显示问题，
   需要补退订逻辑（现架构下每个步骤一个实例，不存在该场景）。
3. **跨线程 PropertyChanged**：桥接发生在试运行任务线程，`DisplayImage` 的 INPC 通知依赖
   WPF 绑定引擎的跨线程封送（与 RegionColor/ColorCheck 现网行为一致，未额外投递 Dispatcher）。
4. 本插件的定位策略不变：码读取仍坚持"上级裁好小图再连进来"，配置窗口的 `ImageReadOnly`
   依旧不提供框选（视图注释写明的刻意设计）。

## 8. 追加：配置窗口内「图像输入」链接卡片（用户二轮反馈）

### 8.1 用户真正想要的

第一轮修复（ShowUpstreamImage 自动带图）交付后，用户贴出 Blob 缺陷检测的截图对比：
"我想要的是图二这种"——**Blob 的「图像输入」卡片里有 `LinkableValueEditor`
（"输入图像 需链接变量 🔗"），在配置窗口内就能直接把输入端口链接到上游**，
不必回画布拖线。码读取/OCR/YOLO 缺的是这一块。

### 8.2 修复内容（每个视图 3 处）

照 [BlobDetectView.xaml L65-89](../../Plugins/Plugin.BlobDetect/BlobDetectView.xaml) 的既有写法：

1. **加 xmlns**：`xmlns:cv="clr-namespace:Core.Controls;assembly=Core.Controls"`（三个视图原本只有 `h:`）；
2. **左列首卡片插入「图像输入」**：

   ```xml
   <Border Margin="0,0,0,8" Style="{StaticResource PluginCard}">
       <StackPanel>
           <TextBlock Style="{StaticResource PluginCardTitle}" Text="图像输入" />
           <cv:LinkableValueEditor
               Margin="{StaticResource PluginFirstRowMargin}"
               HorizontalAlignment="Stretch"
               Label="输入图像"
               Port="{Binding Image}"
               StepData="{Binding StepData}" />
       </StackPanel>
   </Border>
   ```

   （`Port` 绑到各插件公开的 `Image` 输入端口，`StepData` 来自 `VisionPluginBase` 公开属性；
   HImage 属复杂类型，LinkableValueEditor 自动呈现"仅链接"形态，即截图里的 🔗 图标。）
3. **提示文案改写**：原来的"有上游图像时会自动显示…"改为
   "在上方「图像输入」里链接上游后点「执行」，上游图会自动显示进来；不连上游时也可以填路径手动载入一张示意图"。

两轮修复的关系：本节的 LinkableValueEditor 解决"**怎么连**"（配置窗口内直接建立链接），
第 1 节的 ShowUpstreamImage 解决"**连上之后怎么看**"（点执行后上游图自动显示到预览）——互补。
