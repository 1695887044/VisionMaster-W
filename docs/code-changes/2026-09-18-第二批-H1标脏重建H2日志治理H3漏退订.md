## 1. 需求与决策

用户指令："二批（H1 重编译 O(N²)、H2 日志风暴、H3 漏退订）可以开工。你自己绝对要配合商业 Scada 使用的"——三项全做，以商业 SCADA 的采集可靠性/可运维性为准绳。

| 项 | 问题 | 决策 |
|---|---|---|
| H1 | RegisterVariable/UnregisterVariable 每次触发全量 RebuildPollPlan（O(N)），批量注册 N 个变量 = O(N²)；几万点加载方案/RebindAll 分钟级卡死 + GC 风暴 | **标脏 + 三落点重建**：注册/注销只置脏标记（O(1)）；重建收敛到"Connect 建连前 / OnWorkerStateChanged(建连成功) / Worker 轮询拍前消费脏标记" |
| H2 | RegisterVariable/UnregisterVariable 每变量一条 Info 日志，几万点加载 = 几万条日志刷爆 UI 日志窗口 | **删除逐条注册/注销日志**（商业 SCADA 惯例：高频热路径不打 Info），可观测性由"轮询计划已更新"汇总日志 + UI 变量列表承担 |
| H3 | RemoveConnection 清理了 _connections/_configCache/_registeredVariables，**漏了 _varForwardHandlers**——handler 闭包捕获变量对象，几万点删连接 = 几万对象被转发表钉住无法回收 | RemoveConnection 里遍历变量 → 摘除转发 handler 并退订（与 UnregisterVariable/Dispose 对齐） |

### H1 关键设计

- **脏标记放 Worker**（`volatile bool _pollPlanDirty`）：注册发生在任意线程（Bridge 在 UI 线程逐个注册），消费在 Worker 线程，volatile 足够。
- **拍前消费必须独立于轮询分支**：若挂在 `PollAction != null && ShouldPollNow()` 分支内，"在线且从零注册第一个变量"场景（PollAction 为 null）脏标记会被饿死。
- **清脏放在 RebuildPollPlan 末尾**（两个出口都清）：任何重建落点（Connect/建连成功/拍前）完成后计划必新鲜、无残留；重建抛异常时脏标记未清 → Worker 下一拍自动重试，天然自愈。
- **Plan 引用替换原子**：`worker.PollAction = planner.Poll` 单赋值，Worker 下一拍自然用新计划，无并发风险。
- **未连接时标脏无害**：State != Connected 不消费，由 Connect/建连成功两个既有落点统一编译（保持原"冷启动推迟编译"语义）。

### H2 关于 M4 的说明

排查文档建议"注册日志降 Debug + 补 LogSink.Debug（M4）"。核实 `ILogService` 接口（`Shard/Core.Interfaces/ILogService.cs`）**只有 Info/Warn/Error，无 Debug 级**，M4 按原方案行不通；改为直接删除两条逐条日志（更符合商业 SCADA 做法）。若未来需要注册期细粒度追踪，应在 ILogService 增加 Debug 级后按连接汇总输出。

## 4. 已知边界

1. **在线增删变量的生效时机**：标脏后最迟一个轮询周期（默认 1s）后生效（拍前重建）。对采集系统可接受；如需立即生效可后续加"事件信号量唤醒 Worker"。
2. **断线期间标脏的残留**：重连成功由 OnWorkerStateChanged(Connected) 落点重建并清脏；若连接永久停在 Error 终态（AutoReconnect 关闭），脏标记保留但不消费——重新 Connect 时统一编译，无泄漏。
3. **ConfigureWorker 未执行的 Worker**（从未手动 Connect 过）：PollPlanDirtyHandler 为 null，拍前空调用无害——该路径下本就无 PollAction、不轮询。
4. **M4 搁置**：ILogService 无 Debug 级，未补 LogSink.Debug；LogDebug 仍仅 Console（调试器可见）。注册期细粒度追踪待接口扩展。
5. **全量编译仍受外部阻塞**：`Shard/Core.Controls/Editing/`（另一任务）缺 AvalonEdit 引用，本批改动全部位于 VM.Communication 工程，已独立编译验证，不受影响。
6. M1（UpdateConnection 失败回填注册记录）/M2（Connect 超时封顶）/M3（Dispose 竞态）为第三批防御加固项，本批未动。
