# 2026-10-25 生成器统一文件夹：默认六方案 + 压测也走「一个方案一个文件夹」

## 1. 当前状态

`tools\vms-generator` 的**所有**模式现在都写「一个方案一个文件夹」布局：
默认六方案、`--stress`、`--smart-line`、`--ccg-bga/pack/measure`。
旧的平铺落盘 `WriteSolution`（写 `解决方案\<名字>.vms` + 绝对图片路径 + `D:\Records`）已删除。

`解决方案\` 根下只剩文件夹（外加 `Alarms`/`Logs` 两个历史全局目录）与一个断言夹具
`合成颜色验证.vms`（`FlowCanvasChecks.ColorSyntheticChecks` 产出，不属于生成器）。

8 份生成产物全部通过 `VmsCompileProbe` 逐流程编译；文件夹形状与"无外部路径"自检全绿。

## 5. 踩过的坑

| 现象 | 根因 | 修法 |
|---|---|---|
| `WriteFolderSolution` 抛「SolutionName 与落盘名不一致」 | 压测方案名带节点数（`压测方案-3000节点`），调用方另给常量 | 新增 `WriteSolutionInFolder`，文件夹名取方案自己的 `SolutionName` |
| `--giant` 与普通版互相覆盖 | 两者 `SolutionName` 相同，只有旧文件名不同 | giant 追加 `-单流程` 后缀 |
| 外部路径自检把负例也判红 | `Z:\NoSuchDrive\`、`D:\...\Image\test` 本来就是"故意坏的路径" | 改成相对但非法的路径（`bad?path`、`Image`），失败语义不变 |
| 默认六方案里 `综合测试台（测试员版）` 会被覆盖 | 该文件夹是用户保存过的方案，`AppConfig.json` 指向它 | 生成器的样例改名为 `综合测试台` |
| 删掉 `DIR_CALIPER` 后 `Program.EdgeSolution.cs` 编译失败 | 它被 `BuildTestSolution` 引用（不是死代码） | 同步改成 `IMG_CALIPER_1` 等常量 |
| 文件夹采集（`ImgFolder`）无法相对化 | 插件 `FolderPath` 只吃绝对目录，宿主不做方案根解析 | 改成单文件采集；循环仍 5 轮，读同一张样图 |
| 收尾闸 `audit_artifacts` 偶发红：`Plugin.Calibration` 源码 23:52 / DLL 23:19 | 有人正在并行构建该插件（同一时间宿主 23:54 启动），审计恰好落在"源码已写、DLL 未出"的窗口 | 等构建结束后重跑 `audit_artifacts.ps1` 即绿；不是本次改动引入 |
