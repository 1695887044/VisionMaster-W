## 二、已做

### 2.1 口径（三条，缺一条都不是需求原文）

| # | 口径 | 落点 |
|---|---|---|
| 1 | 项目未上线：任何身份都能开关，不需要登录 | `DebugModeBuild.IsPreRelease = true`（当前值） |
| 2 | 项目上线后：开关与面板需要「用户管理」权限（`UserAdministration`） | `DebugModeService.CanUse` → `ScadaAccessPolicy.Can` |
| 3 | 不按时间失效：只有显式关闭才变 false | `DebugModeSettings` 里**没有**到期字段；服务里没有任何时间判据 |

**"是否已上线"的唯一发版开关是构建常量** `DebugModeBuild.IsPreRelease`
（`VisionMaster/Services/DebugModeService.cs`）。发版时改成 `false` 并重建：
之后即使把配置里的 `ProjectReleased` 写成 `false`，也仍按"已上线"判定——
否则改一行配置就能绕过管理员闸门。
配置项 `DebugMode.ProjectReleased` 只用于**开发构建里演练上线后的行为**。

**调试模式不绕过任何权限**：开启后只多出状态栏徽标与诊断附加行；
流程启动 / 硬件配置 / 用户管理仍各走各的权限 Key。这条已写进服务类注释与面板文案。

## 五、踩过的坑

1. **`DialogCloseListener?` 不能实现 `IDialogAware`**：它是值类型，`?` 变成 `Nullable<T>`，
   编译报 `CS0738`。`ProjectAssetsViewModel.cs`（并行会话 07:26 写的）因此挡住整个
   `VisionMaster` 构建；改成非空 + `RequestClose.Invoke(...)` 后通过。
   **与本功能无关，属并行改动**，此处只记录"为了验证本批代码做了什么"。
2. **两个进程同时编同一个 WPF 工程 → `RG1000`「同一 BAML 键重复」**：报的还是别人的文件
   （`GlobalVariableView.baml`）。清 `VisionMaster\obj\Debug\net9.0-windows` 后重建即恢复。
3. **`VisionMaster.exe` 在跑时构建必失败**（`MSB3027` 锁 `bin\Debug\...\VisionMaster.exe`），
   不是代码错。此时用 `-t:Compile` 验证编译与 BAML，不碰 bin。
4. **并行会话会持续改写 `ScadaChecks/Program.cs`**：我加的调用一度被覆盖掉（`[DM]` 一条没输出）。
   判据是"日志里有没有 `[DM` 行"，不是"构建退出码 0"。
5. **断言顺序坑**：DM10 原本先"开"再"关"、最后才检查 `saves==1`，此时已是 2 → 自造假红。
   检查点必须紧跟被检查的那一次动作。
6. **ScadaChecks 写 bin 下 `AppConfig.json.tmp` 会被并发实例锁住**（`IOException`），
   整轮在 `SystemSettingsExtendedChecks` 处崩掉。把 `[DM]` 挪到 `Main` 最前面，
   避免"功能断言被环境问题连带打断"。
7. **`UIThemeSmokeTest` 引用 VisionMaster → 会连带重建插件并写 `Modules\`**，被运行中的
   `VisionMaster.exe` 锁住时报 `MSB3027`。绕法：`-p:BuildProjectReferences=false` 只编冒烟宿主，
   复用已构建好的产品 DLL；这只用于"验证冒烟本身"，不等于 gate 口径。
8. **`UIThemeSmokeTest` 的日志是 GBK（936）**：按 UTF-8 读会把 `[FAIL]`/中文全变乱码，
   看起来像"没有失败项"。回读必须用 `[Text.Encoding]::GetEncoding(936)`。
