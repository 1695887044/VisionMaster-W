## 一、框选只选中一个（先修这个，它挡住了一切多选操作）

### 症状

在组态画布空白处拖出一个框，框罩住 4 个图元，松手后**只选中 1 个**（而且总是叠在最底下的那个）。
单击选一个、Ctrl 加选都正常，所以第一眼像"框选坏了"。

### 复现与定位（`_ScadaEditorProbe --interact`）

探针用真窗口 + Win32 鼠标注入（`SetCursorPos` + `mouse_event`）在空白处拖框，
逐层打印画布状态，得到一条决定性的序列：

```text
[PROBE3] SetSelection(4) before=0
[PROBE4] 主选中 → 罐体/料仓 集合=0 在集合里=False     ← 关键：此刻集合读到的是旧值 0
    [集合变更] 画布=1 视图模型=1
[PROBE3] after=1
```

同时 `[PROBE] band=10,10.09,590,390 hits=4` 证明**命中计算是对的**（框确实罩住 4 个），
手动 `SetSelection(4)` 也能稳定落成 4 —— 所以坏的不是框选，是"落账"这一步。

### 根因

`ScadaCanvas.SetSelection` 按文档约定"先写集合、再写主选中"：

```csharp
SetCurrentValue(SelectedElementsProperty, next);   // 4 个
SetCurrentValue(SelectedElementProperty, next[0]); // 主选中 = 第 1 个
```

第一行写下去之后，`SelectedElements` 是**双向绑定**（`BindsTwoWayByDefault`），
绑定把新的主选中回推到画布，`OnSelectedElementChanged` 被触发；
而此刻 `SelectedElements` 这条依赖属性**读到的还是旧值**（实测写 4 个的过程中 `Count` 仍是 0）。
于是它判定"这个图元不在集合里"，走进那条"把主选中展开成选中集合"的修正分支，
`SetCurrentValue(SelectedElementsProperty, [第1个])` —— **把刚写进去的 4 个覆盖成 1 个**。

为什么单击和 Ctrl 加选没暴露：那两条路上主选中要么本来就等于首项、要么不变，
`SetMainSelection` 是空操作，不会触发回推，也就不会走进修正分支。
框选从"空选中"起步时主选中必然从 null 变人，必踩。

### 修法

给 `SetSelection` 罩一个重入闸 `_settingSelection`，只在这两行之间落下：

```csharp
bool previous = _settingSelection;
_settingSelection = true;
try
{
    SetCurrentValue(SelectedElementsProperty, next);
    SetCurrentValue(SelectedElementProperty, next.Count > 0 ? next[0] : null);
}
finally { _settingSelection = previous; }
```

`OnSelectedElementChanged` 见到闸门开着就只刷视觉、**不做修正**——
这段时间里主选中与集合是同一次写入的两个分量，天然一致。
闸门之外的任何写入（宿主直接赋 `SelectedElement`）照常走修正，行为不变。

### 守门人

`ScadaChecks` 的 `[T]` 段新增两条（进常规 gate 基线）：

| 断言 | 改前 | 改后 |
| --- | --- | --- |
| 框选落账后多选原样保留（不被主选中回推压成单选） | 画布=1 / 视图模型=1（红） | 画布=3 / 视图模型=3（绿） |
| 框选落账后主选中是集合首项（不变式仍成立） | 绿 | 绿 |

**变异反证已做**：把闸门改成 `if (false && ...)` → 第一条准确变红并打印"画布=1（期望 3）"，
第二条仍绿（说明它守的是另一件事，不是重复）。恢复后 2354/0。

## 二、组态编辑器按 V2 重排

### 改前 vs 设计稿（`design.html` 的 `.scada-view`）

| 项 | 设计稿 | 改前实现 |
| --- | --- | --- |
| 顶栏 | 单行 44px | **两行**，实测 78.2 + 33 = 111.2px |
| 格式栏 | v2 隐藏，选中时浮出 34px 上下文条 | 常驻 33px，18 颗按钮 |
| 顶栏按钮 | 28px 高 / r6 / `#E2E8F0` 描边 / 11.5px | **21.2px 高**、渐变描边（Fluent 隐式样式）、13px |
| 格式按钮 | 28×24 透明无边框 | 18 个描边小方块（`FormatToolButton` 没写 Template，落回 Fluent 默认模板） |
| 运行画面 | 实心 `#0EA5E9` 白字主按钮 | 白底 + 绿字 `#1B7F3B` |
| 画布视口 | `#E9EEF5` 浅色工作台 | **`#0E1318` 近黑**（吃了运行态令牌 `HmiCanvasBackgroundBrush`） |
| 页面 | 居中、留白 | 100% 铺满，看不出画面边界 |
| 缩放胶囊 | 左下角浮动 `61% │ 1280×800` | 无 |

### 改法

1. **顶栏合并成一行 44px**（`ScadaEditorView.xaml`）：左组 = 画面/基座 + 新建(▾)/删除 + 撤销/重做；
   右组 = 网格/吸附 + 缩放 + 运行画面 + `…`。
   报警配置 / 批量插入模板两个低频动作收进 `…` 菜单（v2 的减法口径）。
   整行套 `ScrollViewer`，内层 Grid 的 `MinWidth` 绑视口宽：够宽时右组右对齐，拖窄时出滚动条不裁按钮。
2. **新增五态按钮样式** `ScadaToolButton` / `ScadaIconButton` / `ScadaPrimaryButton` /
   `ScadaContextButton`，全部**自带 `Template`**——不带就等于把外观交给应用级隐式样式，
   而 `App.xaml` 最后合并的是 .NET 9 Fluent，实测渲染成 21px 高、渐变描边。
3. **删掉常驻格式栏**，改成选中时浮出的 `SelectionToolbar`：
   对齐三连 + 叠放两连 + `…`（`…` 复用 `BuildElementContextMenu`，与右键菜单同一份命令集）。
   位置由代码后台按"选中集合外接框"经 `ToViewportPoint` 现算，上方放不下就翻到下方并夹进视口。
4. **画布视口改浅色工作台**：`ScadaCanvas.Background` 在编辑器里显式给 `ScadaWorkbenchBrush`（`#E9EEF5`）。
   **注意**：`ScadaCanvas.xaml` 的默认 `Background` 是运行态令牌，没有改它——
   运行窗口还要用那支。
5. **首次进入某页自动 `FitToScreen`**（按页记一次，切标签回来不重置视角），
   于是 1920×1080 的画面按 88% 居中显示，工作台留白与画面边界一眼可见。
6. **左下角浮动缩放胶囊**：`88% │ 1280 × 800`。
7. **令牌化**：`Colors.xaml` 新增 8 个键（`ScadaToolbarBackgroundBrush` / `ScadaWorkbenchBrush` /
   `ScadaToolbarTextBrush` / `ScadaToolbarBorderBrush` / `ScadaToolbarBorderStrongBrush` /
   `ScadaToolbarHoverBrush` / `ScadaToolbarPressedBrush` / `ScadaPrimaryButtonHoverBrush` /
   `ScadaToolbarShadowColor`），视图内不再新增十六进制色值。

## 三、图元工具箱按 V2 重做（2026-10-21 追加）

用户看到面板后指出"图元工具箱没按 Web 的样式设计"。对照 `design.html` 的
`.toolbox-body[data-toolbox-panel=elements]` 逐项核，确实整块没跟上：

| 项 | 设计稿 | 改前 |
| --- | --- | --- |
| 面板标题 | 无内嵌标题（面板头已经有了），总数进搜索行右端 | **内嵌一行"图元工具箱 + 共 28 种"**，与面板头重复 |
| 分组 | 扁平 28px 组头（chevron 在左、计数在右） | Fluent `Expander` 默认模板 → **一叠圆角白卡片**，行被撑高、组间空十几像素 |
| 条目 | 30px：悬停出抓手 + 22×22 分类色图标块 + 名称 + 右端类型键(9px) | 28px 纯文字：名称 + 类型键，**没有图标块、没有分类色** |
| 计数 | `2`（纯数字，右侧） | `(2)`（跟在名称后面） |

### 改法

1. **整支重写 `Expander` 模板**（`ToolSection`）：组头是一个 28px 的 `ToggleButton`，
   chevron + `Header`（名称 + 右侧计数）+ 可折叠内容。不用默认模板的原因与 R68 的按钮同理——
   `App.xaml` 最后合并 .NET 9 Fluent，它自带的 Expander 样式是卡片式。
   chevron 的折叠旋转用 `TextBlock.Style` 里的 `DataTrigger` 换整条 `RenderTransform`：
   模板 Trigger 只能按 `x:Name` 打到元素，打不到 `RenderTransform` 里的子对象（MC4111，编译期就报）。
2. **新增 `VisionMaster/Helpers/ScadaCategoryVisuals.cs`**：组态图元八个分类 →（图标码点, 分类色）。
   **没有复用** `ToolboxCategoryVisuals`——那张表被 `FlowCanvasChecks` 钉成"表内条数 == 插件分类数"，
   塞进去会让那条断言红，而它守的是插件侧的纪律。两张表各守各的域。
   图标码点全部取自**本仓已在用的** FA6 私用区字符（不抄文档：抄错一个码点就是一枚豆腐块，只有真机看得见）。
3. 条目行改为四列：抓手（悬停才显形）/ 分类色图标块（22×22 圆角 6，浅底 + 分类色字形）/ 名称 / 类型键。
   类型键 `MaxWidth=74` + 省略号 + 悬停显示全键——不设上限时 `Hmi.AlarmBanner` 这类长键会把整行顶出可视区。
4. 滚动区右侧留 14px 给 Fluent 的**覆盖式滚动条**：它悬在内容之上，不留沟会把每行最右边的类型键压掉一截
   （实测：不留沟时 `Hmi.AckButton` 被压成 `Hmi.AckButto`）。

### 图标必须按图元类型取，不能只按分类（2026-10-21 追加）

第一版只做了"分类 → 图标"，于是基础组里矩形/椭圆/文本/底板/图像显示**五枚图标长得一模一样**——
用户一眼就看出来"这些图标是假的"。

改法：`ScadaCategoryVisuals` 里加一张 **TypeKey → 图标** 表（27 条），
查表顺序是 `TypeKey → Category → 兜底`。转换器绑的是**整条 `ElementDescriptor`** 而不是 `TypeKey`：
只传 TypeKey 的话回落那一步就丢了分类信息，未登记的新图元会一律变成同一个兜底图标（正是要修的那个毛病）。

**码点先用 `GlyphTypeface.CharacterToGlyphMap` 核过"字库里真有这个字形"**（探针 `--glyphs`，58 个候选逐个打印有/无），
不靠记忆——图标字体里缺码点会渲染成豆腐块，而编译期与静态扫描全绿，只有真机那一眼才看得见（R63 同族）。

现在的对应：矩形=square / 椭圆=circle / 文本=font / 底板=layer-group / 图像显示=image /
按钮=toggle-on / 位按钮=check-square / 多档旋钮=sliders / 指示灯=lightbulb / 多态灯=bolt /
时钟=clock / 棒图=chart-bar / 数值域=pen / 表盘=tachometer / KPI=chart-line / 文本输入=terminal /
下拉=caret-down / 阀门=sitemap / 泵=play / 电机=gear / 管道=arrows-h / 罐体=database /
报警条=bell / 报警确认=check / 轴控台=gamepad / 轴面板=diagram-successor / 数据表格=table。

## 四、没做 / 边界

1. **画面底色仍是深色**（`ScadaPage.Background` 默认 `#FF1E1E1E`）。设计稿里那张白纸是**画面内容**，
   不是 chrome；而图元库目前只有一套深色令牌（`ScadaTokens.xaml`），
   "编辑工作台浅色 + 浅色画面" 需要 `scada-controls` 基线里那条 **D1 画面级主题**（契约扩展，未落地）。
   本批只把**工作台**改成浅色，画面自身颜色仍由页面属性决定。
2. **页面投影未做**。设计稿 `.scada-page` 有 `0 8px 24px rgba(15,23,42,.08)`；
   WPF 侧给 `PART_Surface` 挂 `DropShadowEffect` 会让画面里的文字失去 ClearType，
   代价大于收益，先靠"深色画面 vs 浅色工作台"的对比表达边界。
3. **顶栏在极窄面板下会出横向滚动条**（设计稿同样是 `overflow-x:auto`）。
4. **`_ScadaEditorProbe` 只是探针**，不进构建、不发布；它的 `--interact` 模式是这次定位框选问题的主要工具，
   将来改画布交互可以继续用。
