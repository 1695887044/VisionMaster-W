- 日期：2026-10-19
- 范围：**只动门禁与三处前置缺陷**，不含系统健康面板本体（阶段 1 起另记）

## 1. 为什么先做这一批

系统健康面板要在现有 IO 健康上再加 4 张表（通讯/相机/运动 + 概览）。落地前评审组实测发现**三道门禁已经失真**，不修的话后面所有"新增断言后全绿"都是假的：

| 门禁 | 失真形态 | 后果 |
|---|---|---|
| `FlowCanvasChecks` | clean build 后 2622/8 红 | 新失败会淹没在既有红里，无法判断是不是自己改坏的 |
| `UIThemeSmokeTest` GridView 扫描 | `scanned=12 offenders=6`，6 条全来自 vendored `VM3.0-main`，且只打印 `Take(6)` | 新视图 4 张表坏 3 张，扫描照旧红但看不出是哪张 |
| `IoViewSmoke` | `if (tabs != null) { ... }` 整段包住审计/设备断言 | 页签结构一变，整段被静默跳过 → 假绿 |

## 2. 修复一：容器里加步骤 Version 涨 2（8 条红）

### 现象

```
循环体里新增步骤：Version +1      实际 3 → 5
新增 ElseIf 分支：Version +1      实际 4 → 6
往返后新分支加步骤：Version +1    实际 9 → 11
```

### 根因

一次结构变更触发了**两条**递增：

1. `FlowModel.OnStructureChanged`（订阅了 `Children` 与各分支 `Steps` 的 `CollectionChanged`）→ `Version++`
2. `ContainerStepCountWatcher` 随即 `RaisePropertyChanged(nameof(TotalStepCount))`；
   而 `TotalStepCount` 声明在 `ForStep` / `ConditionStep` / `ParallelStep` 上，
   这些类型本身是被 `FlowModel.OnStepPropertyChanged` 监视的步骤 →
   它不在 `[RuntimeState]` 名单里 → 再 `Version++`

`TotalStepCount` 是**从 Children/Steps 派生的只读计数**，结构变更已经计过一次，派生通知不该再计。

### 修法

给三处 `TotalStepCount` 补 `[RuntimeState]`，并在注释里写明"派生自结构，结构变更已单独计版本"。
没有改成字符串名单——`RuntimeStateAttribute` 的存在理由就是"把知识放在属性旁边，重命名不会漏改"。

### 验证

| 项 | 修前 | 修后 |
|---|---|---|
| `FlowCanvasChecks` clean build + run | 2622 通过 / 8 失败 | **2630 通过 / 0 失败** |

## 3. 修复二：通讯自检的快照没持锁

上一轮把 `CommunicationCheck` 从"直接遍历活动集合"改成了 `ConnectionsList.ToList()`，
但 `ObservableCollection.ToList()` 走 `ICollection.CopyTo`，**不持 `_connectionsListLock`**，
只是绕开了枚举器的版本检查——并发增删时仍可能读到撕裂快照。

改为 `manager.GetAllConnections()`（同一把锁内 `ToList`）。

守门断言同步改：`FlowEngineFixChecks` E18-⑥ 从"含 `ConnectionsList.ToList()`"改成
"含 `GetAllConnections()` 且不含 `ConnectionsList.ToList()`"。

**顺带修了断言本身的一个坑**：说明性注释里必须提到被禁的旧写法（否则后来者不知道为什么不许用），
静态扫描会把注释也扫进去 → 误判"仍残留"。新增 `StripComments()`，判据只扫代码。

## 4. 修复三：`IoVariableCatalog` 的并发读

`_models` 是普通 `Dictionary`，`Rebuild()`（方案切换 / `DevicesChanged`）与
`Snapshot()` / `Variables` / 设备回调 `OnPointsChanged`、`OnStateChanged` 之间无任何同步。
1 秒一次的健康轮询把"读一次"变成常态，竞态窗口被放大。

修法：加 `_modelsGate`，覆盖 `Snapshot` / `Variables` / `Rebuild` 的增删段 / `RemoveAll` /
两处设备回调的读取。**`Publish` 一律放在锁外**——它会触发 `PropertyChanged`/`ValueChanged`，
订阅方回调时持锁很容易滚成死锁。状态变量仍走自己的 `_statusGate`，两把锁不嵌套。

## 5. 修复四：GridView 扫描口径

### 改法

1. **第一方白名单**：只扫 `VisionMaster` / `UI` / `Scada` / `Scada.Controls` /
   `Scada.Controls.Charts` / `Plugins`。`VM3.0-main` 是随仓第三方源码，不是本仓维护的代码。
2. **逐个 `ListView` 判**，不再做文件级子串。文件级判据下"4 张表里 3 张漏挂样式"照样绿。
   正则 `<ListView(?![.\w])[^>]*>` 排除 `<ListView.View>` 这类成员元素。
3. **打印全部违规**，去掉 `Take(6)`；每条带 `文件:行号`。

### 变异反证（R65）

| 步骤 | 结果 |
|---|---|
| 在第一方目录放一个缺三件套的 `_MutationProbe.xaml` | **红**：`扫过 7 个 ... 2 条：_MutationProbe.xaml: 第 5 行的 ListView 未挂 GridListViewStyle \| 行模板缺 GridViewRowPresenter` |
| 删除探针 | **绿**：`扫过 6 个 ... 全部齐全` |

注意：探针只加了文件、没有重新构建，直接跑 `--no-build` —— 扫描读的是文件系统，这条路正好能验"新增文件会不会被抓到"。

## 6. 修复五：`IoViewSmoke` 的静默跳过

| 改动 | 原因 |
|---|---|
| 页签/审计/设备三段不再包在 `if (tabs != null)` 里 | 容器缺失时**逐条判红**，不许整段跳过 |
| 设备表改用 `FindListViewByItemsSource(view, vm.Devices)` | 原来用"第一个 ListView"；页签顺序一变就指到别的表，断言假绿 |
| 页签高度断言在 `tabs == null` 时判红 | 同上 |
