# 2026-10-29 模板参数化只替换最外层下标（P3/P4 静默错绑修复）

> 上一轮可行性评估的探针 P3/P4 暴露：`Recipes[0].Ints[0]` 存模板时被改成
> `Recipes[{i}].Ints[{i}]`，实例 1 展开成 `Recipes[1].Ints[1]` —— 变量存在、解析不报错、
> 画面上有值，**读的却是错成员**。本次集中修这一条。

## 一、当前状态

已修复并全绿：

- `ScadaChecks`（常规）：**3272 条断言 0 失败**（其中新增 12 条 SP 用例）。
- `ScadaChecks --stress`：**3309 通过 / 1 失败**——失败的是**既有**性能断言
  「10000 次属性变更耗时 < 1000ms」（实测 1074ms / 首次负载下 1882ms），
  调用链是 `ScadaElement.X` 属性变更冒泡到 `ScadaPage.Version`，
  **不经过模板参数化**，与本次改动无关（见第六节）。
- `run_gates.ps1`：16 步全绿。
- 探针 `StructBindingProbe` 的 P3/P4 期望值已改为修复后口径，复跑 `RESULT: ALL_OK`。

## 二、修改内容

### 2.1 `Scada\Models\ScadaTemplateParameterizer.cs`（核心）

`TryParameterizeReference` 重写：**只把最外层那一组下标换成 `{i}`**，其余原样。

| 名字 | 实例号 | 旧结果 | 新结果 |
|---|---|---|---|
| `Recipes[0].Title` | 0 | `Recipes[{i}].Title` | 同左（不变） |
| `Recipes[0].Ints[0]` | 0 | `Recipes[{i}].Ints[{i}]` ❌ | `Recipes[{i}].Ints[0]` ✅ |
| `Line[0].Cell[0].Slot[0]` | 0 | 三处全换 ❌ | `Line[{i}].Cell[0].Slot[0]` ✅ |
| `Recipes[2].Ints[0]` | 0 | 内层被换 ❌ | 原样 ✅（外层≠实例号，不动） |
| `Recipes[{i}].Ints[0]` | 0 | 原样 | 原样 ✅（幂等） |

新增私有 `TryReadLeadingIndex`：解析**第一组** `[digits]`。非数字（`{i}` / `[]` / `[abc]`）、
缺右括号、空串一律返回 false —— 认不出就不参数化，绝不猜。

B 形态（纯根名 + `ArrayIndex`）加守卫 `name.IndexOf('[') < 0`：
带下标的名字不再叠一层（旧实现会造出 `Ctl[1][{i}]` 这种废名）。

### 2.2 `Scada\Models\ScadaTemplateTokens.cs`

新增 `CountIndexTokens(string?)`：数一段正文里未转义索引令牌的个数（`{{`/`}}` 不算）。

### 2.3 `Scada\Models\ScadaTemplateExpansion.cs`

展开时收集"一条引用里出现两处以上 `{i}`"的情况，在 `warnings` 里给出可见提示。

**为什么需要**：已经被旧版参数化器存进模板库的模板（`Recipes[{i}].Ints[{i}]`）不会因为
修了参数化器而自动变好——它已经落盘了。不告警的话，这些模板会继续静默错绑。
这里不改模板（改模板是作者的决定），只把问题摆到用户面前。

### 2.4 测试

- 新增 `ScadaChecks\StructIndexParameterizationChecks.cs`（`internal partial class Program` 分部文件）。
- `ScadaChecks\Program.cs` 只加两行调用：`StructIndexParameterizationChecks();` 与
  `if (stress) StressStructIndexParameterization();`。
- `tools\probes\_StructBindingProbe` 的 P3/P4 期望值改为修复后口径（第二道独立回归网）。

## 五、风险 / 未做

- **已落盘的旧模板不会自动修复**：`Recipes[{i}].Ints[{i}]` 需要作者手工把成员下标改回固定值。
  现在至少有告警。是否要做"一键修复旧模板"，需要单独评估（要判断哪一处该固定）。
- **根粒度仍是外层名**（`Recipes`，不是 `Recipes[0]`）：本次没动 `ExtractArrayRoot`。
- **`{i}` 出现在名字非下标位置**（如 `Ctl{i}`）不在本次范围；`TryReplace` 那条文本替换通道没动。
- 未验证真实模板库里的存量模板数量分布（有多少是旧版参数化器产出的）。

## 六、关于那条失败的性能断言

`[×] 10000 次属性变更（逐次冒泡到画面版本号）耗时 < 1000ms → 1074ms`

- 位置：`ScadaChecks\Program.cs:1822`，属于既有 `StressScadaDocument()`。
- 测的是 `elements[i].X += 1` 逐次冒泡到 `page.Version`（WPF 依赖属性变更链路）。
- 该路径**不调用**本次改动的任何代码（`ScadaTemplateParameterizer` / `ScadaTemplateTokens` /
  `ScadaTemplateExpansion` 只在模板存/展开时使用）。
- 两次实测：负载下 1882ms、空闲 1074ms；阈值 1000ms。属于机器性能相关的既有阈值，
  本次不调整（改阈值是另一件事，且需要先定基线）。

## 七、踩过的坑

1. **测试把"畸形"写过头**：一开始把 `A[0]]` 也列进"畸形名"期望原样保留，但它的首组 `[0]`
   是合法下标，尾部多一个 `]` 不影响判定 —— 产品行为是对的，是断言写错了。
   "畸形"只该覆盖**首组解析不出来**的情况。
2. **`name.Replace` 是个陷阱**：替换一段"可能多次出现"的文本时，必须先把位置定死再切，
   不能拿字符串当锚点做全量替换。这次修的是同一类问题的第二次（第一次是变量名路径解析）。
3. **修了源头不等于修了存量**：参数化器修好了，但已存进模板库的旧模板仍是错的，
   所以补了展开期告警 —— 否则用户永远不知道自己的老模板在错绑。
