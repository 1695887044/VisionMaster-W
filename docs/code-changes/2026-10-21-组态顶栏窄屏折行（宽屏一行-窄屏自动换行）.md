# 组态顶栏窄屏折行（宽屏一行 · 窄屏自动换行）

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-10-21 |
| 涉及工程 | `VisionMaster`（`Views/ScadaEditorView.xaml` / `.xaml.cs`）、`ScadaChecks`（两条新断言）、`_ScadaUiProbe`（三个出图场景） |
| 用户原话 | 「这个组态上面的按钮栏 可以在屏幕小的时候 也可以显示全吗」 |
| 证据图 | `docs/UI设计基线/app-shell/evidence/scada-editor-04-narrow.png`（1010）、`-06-toolbar-700.png`、`-07-toolbar-520.png`、`-08-resize-back.png` |

---

## 一、现象

窗口偏窄（或右侧「属性/图层」面板展开）时，组态顶栏右侧的「适应 / 1:1 / 运行画面 / ⋯」整排被推到视口外，
顶栏底部出现一条几乎看不见的横向滚动条。用户看到的是"按钮没了"——**被滚出去等于不存在**。

复现宽度：**1010px 就已经溢出**（`scada-editor-04-narrow.png` 的旧版就是这样）。
顶栏内容的自然宽度实测 **≈1050 DIP**，而窗口最小宽 1120 在两侧面板停靠后，文档区只剩 480~700。

## 二、沿革（为什么改过两次又回来了）

| 日期 | 形态 | 结果 |
| --- | --- | --- |
| 2026-10-19 | **固定拆两行**，每行各套横向 `ScrollViewer` | 任何宽度都占掉两行高度（窄屏更挤），且每行仍可能溢出 |
| 2026-10-21（V2 版式） | **收回一行 44px**（对齐 `design.html` 的 `.scada-top`） | 宽屏好看，窄屏把右侧按钮推出视口 |
| **本次** | **宽屏一行、窄屏折行** | 两种宽度都"看得全"，且不常驻占用第二行 |

## 三、改法

### 1. 行的容器：`44` → `Auto + MinHeight=44`

```xml
<RowDefinition Height="Auto" MinHeight="44" />
```

单行时行高仍是 44（内容 32 居中），折行时按内容长高（实测两行 = 69）。

### 2. 顶栏：`ScrollViewer + Grid(Auto/*/Auto)` → `WrapPanel`

```xml
<WrapPanel x:Name="ToolbarPanel" Margin="10,0" VerticalAlignment="Center"
           SizeChanged="OnToolbarSizeChanged">
    <WrapPanel x:Name="ToolbarLeftGroup" .../>   <!-- 画面/基座 + 新建/删除 + 撤销/重做 -->
    <Border    x:Name="ToolbarSpacer" Width="0" />  <!-- 弹性空白，宽度现算 -->
    <WrapPanel x:Name="ToolbarRightGroup" .../>  <!-- 网格/吸附 + 缩放 + 运行/更多 -->
</WrapPanel>
```

**折行粒度是"组"，不是"按钮"**：逐个按钮折会掉出孤立的一颗（例如只剩一个「⋯」飘在第二行），
读起来像排版事故；整组换行则是可预期的"一行 / 两行"。

**为什么不用 `Grid` 的 `*` 列**：`*` 列只会把两组挤在同一行里互相压，永远不会折行。
左右间距改由 `ToolbarSpacer` 撑开——撑得开时右组贴右边缘（与设计稿一致），撑不开时宽度算成 0，右组自然折行。

### 3. 代码后台 `UpdateToolbarLayout()`

挂在 `ToolbarPanel.SizeChanged` 上，每次宽度变化重算三件事：

| 量 | 取值 | 作用 |
| --- | --- | --- |
| `ToolbarLeftGroup/RightGroup.MaxWidth` | = 顶栏可用宽度 | 连"一组自己都放不下"的极端窄宽度下，组内按钮再各自折行（520px 时实测折成 4 行，任何宽度都不裁切） |
| `ToolbarRightGroup.Margin.Top` | 折行时 8，否则 0 | 两行都是 28px 高的按钮，不补就是两排边框贴在一起 |
| `ToolbarSpacer.Width` | 折行时 0，否则 `可用宽 − 两组自然宽` | 撑开右组 / 让出折行 |

三处赋值**都带"变了才写"的守卫**（`> 0.5`）：它们都会再触发一轮布局，
无条件写就是"改尺寸 → 布局 → 再改尺寸"的死循环，而它跑在 `SizeChanged` 里，一旦循环就是界面卡死。

刻意**没有**用 `WrapPanel.ItemHeight` 做行间距：它会强制每个子项的槽高，
而两组自己也是可折行的 `WrapPanel`，槽高 36 会把组内第二行直接裁掉。

## 四、验证

### 1. 出图（`_ScadaUiProbe --editor`，真窗口 + `RenderTargetBitmap`）

| 场景 | 顶栏量值 | 结果 |
| --- | --- | --- |
| 1500 宽 | 1465.3 × 32（行高 **44**） | 单行，右组贴右边缘（与改前一致） |
| 1010 宽 | 975.3 × 68 | 两行 |
| 700 宽 | 665.3 × 68 | 两行 |
| 520 宽 | 485.3 × 124 | 四行（左组 2 + 右组 2），无裁切 |
| **活尺寸循环** 1500→700→1500→520→1500 | 32 / 68 / 32 / 124 / 32 | 可逆、无抖动、无死循环 |

活尺寸循环单独测，是因为每张出图都新建视图，走不到"`ToolbarSpacer` 已经撑开之后再收窄"这条路径——
而它正是用户拖分隔条时天天走的。

### 2. 断言（`ScadaChecks`，进常规 gate 基线）

新增两条，挂在既有的顶栏断言之后：

1. **顶栏窄到 700 时折行**（`ActualHeight > 44`）——仍是固定单行 44 的话，右侧一整排按钮会被裁掉；
2. **折行后没有任何顶栏元素越过视口右缘**——参照系取**视图**而不是顶栏自己：
   顶栏在横向滚动容器里时它自己的宽度会跟着内容一起涨（内容 1051 就量成 1051），拿它当尺子会漏判。

结果：**2384 通过 / 0 失败**。

### 3. 变异反证（R65）

把顶栏临时塞回"横向滚动"（正是旧设计），两条断言**准确变红**：

```text
[×失败] 顶栏窄到 700 时折行  →  顶栏 1051.8×36
[×失败] 折行后没有任何顶栏元素越过视口右缘  →  最右缘=1061.8 / 视图宽=700
```

还原后 2384/0 全绿。第二版的判据一开始拿"顶栏自身宽度"当尺子，**变异下依然是绿的**（1051.8 ≤ 1051.8），
改成视图宽度后才抓得住——这正是"没有变异反证就不知道闸有没有牙"的又一例。

## 五、边界

- **单行外观未变**：1500 宽时顶栏仍是 44px 高、右组右对齐，与 V2 设计稿一致。
- **折行会占掉画布高度**（两行 69、四行 125）。这是"显示全"的代价；用户要的是按钮可见，而不是省高度。
- **极窄仍有下限**：单个控件本身有宽度（最宽的是「画面」下拉 150），视图窄到 ~160 以下才会真正裁切。
- **未改动**：`Shell.xaml` 的面板归属与停靠语义没变，**不需要**递增 `CurrentLayoutSchemaVersion`（R43 的触发条件是"面板归属/停靠语义变了"）。
