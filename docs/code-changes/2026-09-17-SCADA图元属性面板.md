# 2026-09-17 SCADA 图元属性面板（S3-d）—— 面板里没有一行属性是写死的

## 一、需求与决策

### 背景：S3-d 补齐的是"改"这一环

前面几阶段把"有东西可改"铺完了：

| 阶段 | 交付物 | 用户能做到 |
|---|---|---|
| S1 [SCADA画面领域层](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA画面领域层.md) | `ScadaDocument → ScadaPage → ScadaElement`（`TypeKey` + 属性袋） | 有模型、能落盘 |
| S2 [SCADA图元控件库](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元控件库.md) | `ElementRegistry` / `ElementDescriptor` / 图元控件 / `ScadaCanvas` | 知道"每类图元有哪些可配属性" |
| S3-b / S3-e1 | 画布宿主 + 主程序接线 | 看得见画布 |
| S3-c [图元工具箱与拖放](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元工具箱与拖放.md) | 工具箱面板 + 拖放落画布 | **摆上**图元 |

摆上去之后只能拖位置、改尺寸，颜色、文字、字号、形状、锁定全都没入口 —— 那不叫组态。
本阶段（S3-d）交付：**点选画布上任意图元，右侧面板按它的描述符自动长出可编辑的属性行，改完写回模型。**

用户长需求在本阶段的落点仍然是那三条：商业级可扩展、模块化、**长期可扩展性优先**，并且每阶段配"暴力测试"。

### 决策一：行源只有描述符 —— 整个 S3 最重要的一条性质

```
ElementDescriptor.Properties（S2 声明）
        │  一条声明 = 一行编辑器，次序权威 = 声明次序
        ▼
ScadaPropertyRow（编辑态，生命周期只有一次选中）
        │  Value 读写
        ▼
ElementValueAccess（S2 已有的唯一读写通道）
        │  "$X"/"$Width"… 走强类型字段；其余走属性袋
        ▼
ScadaElement（模型，会落盘进 .vms）
```

面板代码里**没有任何一句 `if (typeKey == "Hmi.Rectangle")`**。收益很直白：
以后加一类图元（阀门、管道、相机画面框），或者给现有图元加一条可配属性（圆角半径、渐变），
**面板的 VM、View、XAML 三个文件一行都不用改**。

这条性质光靠"我觉得代码是通用的"不算数，所以 `[U]` 里专门写了一条遍历断言钉它（见三节 ①）。

### 决策二：不复用描述符当视图模型 —— 它是跨图元共享的

描述符上已经有 `DisplayName / Kind / DefaultValue`，看着"直接绑它就行"。不行：

- 描述符实例在注册表里**全局唯一**，六个几何键甚至共用同一份 `GeometryProperties.Standard`；
- 把"当前值、红框状态"写回它，等于让画面里**所有矩形共用一个填充色** —— 改一个，全变。

所以编辑态另立一份 `ScadaPropertyRow`，它只持有两个引用（目标图元 + 属性声明），
一次选中一套，换选中整份重建。断言 ⑤ 专门验证：改过值之后
`FindProperty("Hmi.Rectangle","Fill").DefaultValue` 仍是 `"#FFFFFFFF"`、
`Hmi.Text/FontSize` 仍是 `"14"` —— 描述符没被污染。

### 决策三：读写只走 `ElementValueAccess` 一条通道

几何键（`$X $Y $Width $Height $Rotation $Name`）落在模型的强类型字段上，其它键落在属性袋上 ——
这个分叉判断 S2 已经写过一遍。面板再写一遍就是**两处规则**，将来注册表加一个保留键必然漏一处
（漏了的症状是"改了不生效"或"生效了但没落盘"，都极难查）。

顺带白得了三条已经过 `[M]/[S]` 验证的语义，面板直接继承：

| 语义 | 来源 | 面板表现（有断言） |
|---|---|---|
| `TryParse` 失败**不写模型** | `ElementValueAccess` 数字键写入 | X 里打 `abc`：模型仍是 10 |
| 宽/高取 `Math.Abs` | 同上 | 宽里打 `-30`：模型存 30 |
| 格式化 `InvariantCulture + "0.######"` | 同上 | `12.5` 往返不变，不会被念成 `125` |

### 决策四：提交时机 = `LostFocus` + 回读规范值，而不是"抑制写回"

面板最容易做成灾难的地方是**"用户输入 → 写模型 → 模型回读 → 又覆盖用户输入"**这个环。
常见解法是加一个 `_suppressWriteback` 标志位，一旦忘记配对，症状是"某些时候改值没反应"。
这里换了一种不需要标志位的做法：

- 文本框用 `UpdateSourceTrigger=LostFocus`（复选框/下拉是即时，它们没有"半个值"的中间态）；
- 写完之后**无条件用模型的规范文本回填输入框**（`RefreshValue()`）。

于是"负数被纠正成 30""空串被填回 12.5"这类事情在用户眼里是**输完那一刻的自然收敛**，
而不是"我打的东西被吞了"。为什么不在 `PropertyChanged` 上做：那样每敲一个字符就规范化一次，
`1.` 会立刻变成 `1`，**用户永远输不进小数**。

### 决策五：越界照样写模型，只标红；非法输入不写模型，也标红

两种"值不对"故意给两种结果：

| 情况 | 写不写模型 | 为什么 |
|---|---|---|
| 旋转打 `400`（`Max=360`）、字号打 `3`（`Min=6`） | **写**，只把框标红 + 悬停说「不能大于 360」 | `Min/Max` 是**编辑提示，不是模型约束**。底图被整组拖出画面就得能存下负坐标；静默夹回边界值会让人以为鼠标或输入框坏了 |
| X 打 `abc`、清空数字框 | **不写**，但把用户文本原样留在框里 + 标红「请输入数字（小数点用 . ，不用千分位）」 | 模型压根没法接这个值。此时把输入框抹回旧值 = 当着他的面擦掉他打的东西；把非法值写进模型 = 污染 .vms |

红框是 DataTrigger 驱动的（`IsValid=False` → 红边 + 浅红底，`ErrorText` 挂 ToolTip），
改回合法值自动消失，不留残留（断言：`-90` 之后 `ErrorText == null`）。

### 决策六：色块与图元控件共用 `BrushConverter` —— 顺便说一件断言抓出来的事

WPF 没有公开的 `Color.TryParse`。要判断 `#FF00FF00` / `Red` / `#RGB` 到底长什么样，
唯一不撒谎的办法就是**用图元控件把字符串变成 `Fill` 时用的那个转换器**（`BrushConverter`）。
另写一份"井号加六个十六进制"的正则，就会出现"面板色块是绿的、画布上是白的"这种
用户认为是软件在骗他的场面。解析失败回落成**灰色**色块而不是留白 —— 留白看着像"当前就是这个颜色"。

而转换器的失败方式是**抛异常，不返回 null**。这里踩到一层：

```csharp
catch (NotSupportedException) { /* 不认识的写法 */ }
catch (FormatException)       { /* "#GGG"：看着像颜色、实际非法 */ }
```

最初只 catch 了 `NotSupportedException`，`[U]` 断言喂进 `#GGG` 之后直接以
`System.FormatException: 令牌无效。` 崩掉整节（`通过: 283 失败: 1`）。
**这是本阶段断言抓出的唯一一处真实产品缺陷**：面板是给人改值的地方，非法输入是常态而不是程序错误，
两类异常都必须接住。（已修，见 [ScadaPropertyViewModel.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/ViewModels/ScadaPropertyViewModel.cs#L177-L185)）

### 决策七：通知口径 —— 改值绝不重建整表

| 事件 | 动作 | `Groups` 通知次数 |
|---|---|---|
| 面板里改一行值 | 写模型 → 本行回读 | **0**（每敲一格就整表重建会把输入焦点顶掉，等于没法连续输入） |
| 模型侧外部写入（画布拖 X、改名） | 遍历所有行 `RefreshValue()` | **0** |
| 换选中 / 换画面 / 换方案 | 整份 `Rebuild()` | **1** |

`Rebuild` 不做"保留行、换个图元"的复用：同一类型两次选中看着一样，但行里钉着上一个图元的实例，
复用等于把**泄漏和错值**一起焊进面板。断言 ④ 把这三个数字钉死（连改两行 `== 0`、换选中 `== 1`）。

### 决策八：与编辑器 VM 共用同一个实例，不引事件总线

"画布点谁、面板就编辑谁"如果靠 `GlobalEventBus` 广播选中变更，就会多出一种
"两边都收到了但次序不同"的劈叉状态。做法很朴素：
[App.xaml.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/App.xaml.cs#L122) 里
`containerRegistry.RegisterSingleton<ScadaEditorViewModel>()`。
Prism 的导航机制默认对每个 View 新建一个同名视图模型，singleton 覆盖这层解析，
于是编辑器面板和属性面板拿到**同一个实例**，面板只需要订阅它的 `PropertyChanged`。

接的是 `SelectedElement / Pages / Document` 三个属性名（外加 `null`）：
换方案时 `SelectedPage` 的 setter 会顺手把 `SelectedElement` 置空，
但那之后可能直接赋新值而不经过 `null`，**少接一条就会编辑到已废弃的图元**。

### 决策九：可逆挂摘 + 幂等（这是"停靠面板订阅泄漏"那课的直接收益）

面板视图 `Loaded → Activate()`、`Unloaded → Deactivate()`，两个方法都幂等（`_subscribed` 标志 +
`Bind()` 里的 `ReferenceEquals` 短路）。再加一层 `DataContextChanged` 补挂：
Prism 的 `AutoWireViewModel` 可能晚于 `Loaded` 才把 VM 塞进 `DataContext`，那时入树事件已经过去。

`Activate()` 里带一次 `Rebuild()`，语义是"把挂接期间错过的选中变更补回来"。
这个行为一度把我自己的断言算错过（见三节踩坑第 4 条），但它本身是对的：
浮窗、切标签、隐藏再显示之后，面板必须立刻跟上当前的选中，不能等用户再点一次。

### 决策十：编辑器模板用"显式 keyed 模板 + `DataTrigger` 挑"

| 候选 | 判定 |
|---|---|
| 隐式 `DataTemplate`（按 `DataType` 自动匹配） | 否。要按 `Kind` 分六种，`DataType` 只能匹配行类型，还得再套一层选择器 |
| `DataTemplateSelector` | 否。得写一个 C# 类，且 XAML 里要认得 `ScadaPropertyRow` 这个自定义类型 |
| **`ContentControl` + `Style.Triggers` 里六个 `DataTrigger` 挑 `ContentTemplate`** | **是**。零额外要求，`Text` 与 `Number` 现在共用 `EditText`（都只是一个文本框），将来给数值加上下调节按钮时再拆 |

`ScadaPropertyRow` 把 `DisplayName / Kind / Choices / IsBindable / Description` 全部转手暴露，
XAML 里因此没有一处 `{Binding Descriptor.xxx}` 的两级路径。
Bool 行的 `bool ↔ bool?` 换算放在行里（`BoolValue`），不为一个复选框引一个 `IValueConverter` 类。
`BoolValue` 是 `bool?`：属性袋里真出现 `"也许"`（手改过的 .vms）时复选框呈**未定态**，
不崩、也不自作主张猜成 `false`（断言 ⑥）。

### 决策十一：面板落位 —— 右栏顶层并列的定宽栏

| 候选 | 判定 |
|---|---|
| 塞进中央那个竖向 `LayoutPanel`（和图像/日志同栏） | 否。竖向面板里的子项只有高度方向说话（`DockHeight`），宽度被整个面板拉平，属性栏会跟着日志栏一起吞掉工作区宽度 |
| 放右侧自动隐藏区（和工具箱同区） | 否。自动隐藏点了才浮出、点一下就收，而属性面板是组态时**全程盯着**的面板 |
| **右栏顶层并列 `LayoutAnchorablePane DockWidth="260"`** | **是**。定像素不用星号：一列"标签 + 输入框"要的是稳定可读宽度，1080 与 2560 下都是 260 最舒服 |

登记仍然照 S3-e1 定下的三处范式一处不落：
[LayoutHelper.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/Services/LayoutHelper.cs#L52) 的
`ContentFactories["Panel_ScadaPropertyView"]` +
[Shell.xaml](file:///e:/VM/VisionMaster-W-master/VisionMaster/Shell.xaml#L805-L813) 的 `ContentId` 与「视图(V)→属性」菜单项 +
[App.xaml.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/App.xaml.cs#L125) 的 `RegisterForNavigation`。
`LayoutXmlCoversAllPanels` 以 `ContentFactories.Keys` 为权威 ⇒ **本机旧 `Layout.xml` 与出厂快照缺这个面板会自动回退默认布局，属预期行为，不需要迁移代码**（代价是自定义过布局的机器会掉回默认布局一次）。

### 决策十二：ƒx 按钮现在只说实话，不弹一个改不动东西的框

`IsBindable` 的行（含六个几何键里的 X/Y/宽/高 —— SCADA 里"液位随变量变化"就是绑 `Height`）
在行尾出现 ƒx。点它**不接任何绑定逻辑**，只弹一条提示：

> 「点亮」的变量绑定要等运行态阶段（S4）接入。

理由：仓库里现成的变量选择框 `DataBindView` 服务的是流程侧的 `LinkReference`，
而组态图元要走 S1 就定好的 `ScadaBinding`（按变量 **Id** 寻址）。
两套语义硬接 = 把两个绑定的参数池搅在一起，将来拆不开。
**宁可少一个功能，也不要一个看着能点、点了没反应的功能。**
S4 接运行态时把 `OnBindVariable` 换成"弹框 → 选变量 → 往 `Element.Bindings` 增删一条"，面板其余代码不动。

按钮可用性用参数化的 `DelegateCommand<ScadaPropertyRow>` 的 `CanExecute(row) => row.IsBindable`，
不挂在面板状态上 —— 行对象换了可用性就得重算，挂参数比挂面板状态准，也便于断言直接调。

### 决策十三：两个"文案即功能"的地方

- **空态**：`SelectedElement = null` 时 0 行 + 标题「未选中图元」+ 一块 `IsHitTestVisible=False` 的说明文字。
  绝不留上一个图元的值在面板上 —— 那是"我以为我在改这个"的头号来源。
- **类型没注册**：`TypeKey` 在注册表里找不到（.vms 带着插件图元跑到没装该插件的机器上，真实场景）时
  显示「`Hmi.NotOnThisMachine`（本机未注册该图元，无法编辑）」+ 0 行。
  必须说清"不是面板坏了，是这台机器不认识它"，否则用户会以为**属性丢了**。

标题条上的「锁定」勾选直绑 `Element.IsLocked`（TwoWay），不经视图模型转发：
它是**模型字段、要落盘**，画布的拖动/改尺寸都认它，多一层转发只是给"改了不生效"留坑。

## 三、验证结果

### 断言工程：`[U]` 节 36 条（9 个小节）

现场与 `[S]/[T]` 同一套建场顺序（`WorkspaceContext` → 清空全局变量 → 空方案 → `SwitchSolution`
→ `new ScadaEditorVM(workspace)` → `AddPageCommand.Execute()` → `new ScadaPropertyVM(editor, notifier)`），
跑在 `SetApartmentState(STA)` 的独立后台线程上（行里有 `Brush`，末了还要真造控件）。
`ScadaChecks` 同时引用 `VisionMaster.csproj` 与 `VM.Scada.Controls.csproj`，所以断言里直接 `new` 面板 VM。

| 小节 | 条数 | 钉住的行为 |
|---|---|---|

### 过程中踩到的事（四条是断言自己的错，一条是产品的）

1. **`SearchReplace` 把紧随其后的方法签名一起吞了。** 往 `[T]` 尾部追加 `[U]` 时锚点带了
   `private static void Section(string title)`，结果留下一个孤儿方法体。
   → 教训：**追加代码时锚点别带下一个方法的签名**；这次用一次全量重写补回。
2. **`CS0128` 局部变量 `green` 撞名**：② 里 `is SolidColorBrush green` 的模式变量与 ⑨ 的
   `var green = Named(...)` 同名（模式变量的作用域比想象中大）。→ 后者改名 `greenRect`。
3. **`CS8625` 不可空上下文不能传 `null` 字面量**：`CanExecute(null)` → `CanExecute(null!)`。
4. **两条"编译过了但会误判/抛"的断言逻辑错**（自己写的断言也要被断言）：
   - ⑧ 漏算 `Activate()` 自带的那一次 `Rebuild()` ⇒ 基线必须在 `Activate()` **之后**重取；
   - ② 里把选中切到 `Hmi.Text`（**文本图元没有 `Fill` 属性**）之后再 `Row("Fill")`，
     `.First()` 直接抛 ⇒ 色块断言前先显式 `editor.SelectedElement = box;`（切回矩形）。
     这一条同时暴露了一个通用陷阱：`ElementRegistry.All` 按 `Category → DisplayName`
     （`StringComparer.CurrentCulture`）排序，**遍历结束时选中的恰好是 `Hmi.Text`**，
     凡是依赖"循环后面板状态"的断言都必须显式重设选中，不能指望"上一个还在"。
5. **产品缺陷：`#GGG` 抛 `FormatException`。** 见决策六 —— 这是 `[U]` 唯一一条真正改进了产品代码的断言。

## 四、已知边界

| 边界 | 说明 / 影响 |
|---|---|
| **运行期未目视验证（P0）** | 断言是 headless 的，证明的是"行按描述符生成、值能写回模型、模型能落到控件依赖属性"。**下一次启动主程序必须肉眼确认**：右栏出现「属性」面板；点画布图元后标题是 `矩形 · 料箱`；分组 `Expander` 正常展开；X 打字母出现红框且悬停有原因；色块跟着颜色变；勾「锁定」后画布上确实拖不动；点 ƒx 弹出提示。这一环 `[U]` 覆盖不到，也最容易在集成时才暴露 |
| **画面级属性不在本面板** | 宽/高/底色/网格/吸附目前由组态编辑器**顶栏**承载（`ScadaEditorViewModel` 的口径是"画面属性不中转，XAML 直绑 `SelectedPage.*`"）。面板里重复一份只会让"改哪个生效"变成谜题。**画面级属性区与「定位」一并推到 S3-e2**（画面/图层管理）统一处理 |
| **ƒx 未真正接通** | 只弹"要等 S4 接入"的提示（决策十二）。届时改为 `ScadaBinding` 增删，面板其余代码不动 |
| **无撤销** | 面板改值即时写模型。撤销应属于 S3-e2 之后的统一命令层 —— 现在补一套只覆盖属性编辑的 Undo，会和拖放那边做成两套语义 |
| **单选** | 画布侧 `SelectedElement` 只有一个，面板因此不做"多选时显示公共属性 + 混合值（`<multiple values>`）"。做的话要先把编辑器的选中态改成集合 |
| **无取色器** | 只有"文本框 + 色块"。仓库里没有可用的取色控件（第三方树里的都不在引用范围内），而 `#AARRGGBB` 本来就是可手输文本，色块只负责回答"这串字符到底长什么样"。专业取色弹层属后续独立需求 |
| **数值无步进/滑杆** | `Text` 与 `Number` 共用一个文本框模板。上下调节按钮、按 `Min/Max` 限制输入范围（而非只标红）留给将来真的需要时再拆模板 |
| **`Description` 只挂行 ToolTip** | 描述符上的说明文字没有"属性说明区"这种地方集中展示；行尾图标/帮助链接未做 |
| **数字口径固定不变文化** | 输入不接受千分位（`1,000` 会被判非法并标红），提示语里也明确写了"小数点用 . ，不用千分位"。这是与 `.vms` 存储格式对齐的刻意选择，不做本地化数字格式 |
| **分组次序依赖声明次序** | `GroupBy(..., StringComparer.Ordinal)` 的组序 = 键的**首现次序**（LINQ to Objects 保证）。想换分组次序要改描述符声明，不在面板里排序 |
| **旧布局回退一次** | 新增面板使既有 `Layout.xml` / 出厂快照校验不过，会自动回退默认布局（用户自定义过的停靠位置丢一次）。这是 `LayoutXmlCoversAllPanels` 的既定策略，不做增量迁移 |
| **断言里的隐式约定** | `[U]` 用 `Row(key)`（`.First()`）取行，一旦描述符改了键名（如 `Fill` → `FillColor`）断言会抛而非误判 —— 这是想要的行为（抛出来比悄悄通过好），但改描述符时要记得断言跟着改 |
