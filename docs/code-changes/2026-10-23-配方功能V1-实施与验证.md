## 一、V1 交付内容

### 1.1 数据模型（Core）

| 文件 | 内容 |
| --- | --- |
| `Core/Models/Recipe/RecipeModels.cs` | `RecipeTargetKind` / `RecipeScope` / `RecipeEntry` / `RecipePoint` / `RecipeDefinition` / `RecipeJson` / `RecipeTypeKey` / `RecipeSolutionExtensions` |
| `Core/Models/SolutionModel.cs` | 追加 `Recipes` / `ActiveRecipeId` / `RecipeSchemaVersion`（Order=100/101/102，全部可空、不兜底 new） |

关键口径：
- `Recipes: null` = 从未启用；`[]` = 已启用但无配方；两者不互相归一化。
- 首次实体化配方时 `Version` 抬到 2.0（旧版覆盖 canary）。
- 值存规范 `JToken`；枚举存成员名；`ValueIsNull` 显式承载 null。
- `DeclaredType` 用程序集无关的规范化类型键；`List<T>` / `ObservableCollection<T>` / `T[]` 视为同形状。
- `RecipeTypeKey.TryResolveType` 支持基元/枚举/数组/List/ObservableCollection/Nullable 反向解析，供兜底 schema 用。

### 1.2 服务层（VisionMaster）

| 文件 | 内容 |
| --- | --- |
| `VisionMaster/Services/RecipeService.cs` | 捕获 / 预检 / 应用 / 逆序回滚 / 终检 / 偏离 / 重命名 / 删除 / 清除生效 / 审计 |
| `VisionMaster/Services/RecipeSaveCoordinator.cs` | 「应用并保存」复用布局/变量/通讯 Capture + 原子写 |
| `VisionMaster/ViewModels/RecipeViewModel.cs` | 标题栏 chip 展示与打开管理器 |
| `VisionMaster/ViewModels/DialogViewModels/RecipeManagerViewModel.cs` | 管理器：列表/参数对照/捕获/应用/应用并保存/删除/重命名/清除生效 |
| `VisionMaster/Views/DialogViews/RecipeManagerView.xaml(.cs)` | 管理器界面（DataGrid 参数表，不用 ListView+GridView） |

关键行为：
- 只接受 `RecipeTargetKind.StepInput`；`LocalVariable` / `MotionPoint` 出现即整单拒绝。
- 只按 `StepID + Key` 寻址；名字仅显示/审计。
- 已链接端口、隐藏端口、路径/模型/模板库/动态列名、不支持类型全部跳过或拒绝。
- 应用：权限（已登录操作员）→ 运行闸（`SnapshotSessions` + `IFlowRunState`）→ 未保存提示 → 封门 → 复判 → 全量预检 → 快照 → `SetInputValue` 写入 → 终检 → 更新 `ActiveRecipeId`/`LastApplied*` → 审计。
- 失败逆序回滚；回滚失败不谎称成功；审计不可用禁止应用。
- 写循环内不 `await`、不 `Serialize`、不弹窗。

### 2.2 断言

`RecipeChecks.exe`：

```text
通过: 62  失败: 0
```

覆盖：
- 老文件零回归：不写 `Recipes` / `ActiveRecipeId` / `RecipeSchemaVersion`；`Recipes: []` 与 null 语义分开。
- 捕获：5 条步骤参数；跳过链接端口/展示索引/路径；枚举存成员名；复杂对象存 JArray。
- 序列化：`Kind` 写成员名；无 `Newtonsoft.Json.Linq` 的 `$type`；无 NaN；往返后值不变。
- 应用：5 条写回；`FlowModel.Version` 推进；`ActiveRecipeId`/`LastAppliedContentVersion` 正确。
- 偏离：应用后 0；改一个值后 1；改回 0。
- 边界：链接端口预检报错且应用拒绝；孤儿条目报错；double→int 收窄拒绝。
- 回滚：注入第 4 条写入失败，已写 3 条逆序回滚，值恢复，指针保持旧值。
- 门闸：在途启动时应用被封门；归零后可应用；释放后 `IsApplying=false`。
- 审计/权限：审计不可用禁止应用；未登录禁止切换。
- 生命周期：生效配方禁止删除；重命名不改内容版本。

## 三、已知缺口 / 未做（V1 边界）

1. **运动点位**：未进 V1；`RecipePoint` 仅预留，`Points` 非空会被整单拒绝。
2. **全局变量**：未进 V1；`LocalVariable` 仅预留，出现即整单拒绝。
3. **导入导出**：未做；`.vmrecipe` 尚未实现。
4. **SCADA**：未做只读显示/切换动作；v1 只保留标题栏 chip。
5. **基线哈希/脏判定**：未做；沿用现有「序列化文本 vs 磁盘」比较，仅作提示。
6. **触发边沿延后**：`RecipeApplyGate` 封门期间被拒的变量/定时触发尚未实现延后重试；当前只保证不启动，边沿可能丢。
7. **UI 端到端**：未登录，未完成「登录 → 捕获 → 应用」全链路；服务层已覆盖。
8. **旧版二进制实测**：未做（需用上一版 exe 打开 2.0 文件验证 canary）。
9. **复杂对象消费端断言**：V1 只验证 `InputValues` 往返；尚未实例化 CreateRoi/Caliper 断言插件属性。
10. **`CompiledVersion` 其余 5 处**：V1 只修了 `FlowSessionFactory`；`FlowListViewModel`/`ShellViewModel` 的 5 处直接赋值仍在（未改，避免扩大 V1 范围）。

## 五、V2 建议入口

1. 局部变量（`LocalVariable`）：捕获/应用/回滚 + 触发源排除 + 保存前回填 + 草稿前 Capture。
2. `.vmrecipe` 导入导出：`TypeNameHandling.None`、禁 `$type`、禁设备字段、导入只建定义不应用。
3. 运动点位（`MotionPoint`）：先补 AxisId 重映射/消费者，再开放。
4. SCADA 只读 + `ApplyRecipe` 动作：新动作追加在枚举末尾 + `IRecipeCommandSink`。
5. 触发边沿延后/重试、`CompiledVersion` 其余 5 处、基线哈希、复杂对象消费端断言。
