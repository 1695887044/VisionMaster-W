# 2026-10-20 · 图像预处理点「执行」后预览不刷新（输入端口灌值没人订阅）

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-10-20 |
| 现象 | 配置窗里已把「图像路径」绑到 图像采集_0.Image，点「执行」→ 状态栏「✅ 成功 - 执行完成 17 ms」，**画布仍是黑的**，还挂着「尚无预览：在左侧添加算子；若上游没有图像…」的提示条 |
| 影响面 | `Plugin.PreProcessing` 的配置预览；同类"配置态预览"插件（BlobDetect / CaliperMeasure / BeadInspect）**没有这个问题**——它们都订阅了输入端口 |
| 修法 | `PreProcessingPlugin` 补 `MarkAsConfigInstance()`（视图就绪时置位 + 订阅 `SrcImage.ValueChanged`），并给 `SchedulePreview` 补配置态守卫与无 `Application` 时的同步分支 |
| 守门 | `FlowCanvasChecks\PreProcessingChecks.cs` 的 `RunPreviewRefreshContract()`（2 条，进常规 gate 基线） |

## 一、根因

试运行取图的链路是（`Engine\PluginTestRunner.cs`）：

1. `ExecuteUpstreams` 在**编译实例**上把上游（图像采集_0）跑出来；
2. `BridgeInputs`（`:223-242`）把上游端口的实际值写进**配置实例**的同名输入端口：
   `configPort.LinkedSource = null; configPort.Value = actual;` —— 走的是 `Value`，
   即 `InputPort<T>.ValueChanged`（`DataPort\InputPort.cs:95-125`）；
3. `configPlugin.Execute(context)` 在配置实例上跑 `RunAlgorithm`，所以状态栏是"成功"。

而 `PreProcessingPlugin` 的预览只在三处取图：`OnViewLoaded`（`:301`）、
`RefreshPreviewCore`（`:356`，由参数变更/链变更的防抖触发）。**`SrcImage.ValueChanged` 没有任何订阅**，
于是第 2 步灌进来的图没人接：`_sourceImage` 一直是 `null`，`DisplayImage` 为 `null`，
`PreProcessingView.xaml:786` 那条 `NullToVisibility` 提示条自然一直亮着。

对照组：`BlobDetectPlugin.cs:706-727`、`CaliperMeasurePlugin.cs:650-670` 都在
`OnViewLoaded` 里 `MarkAsConfigInstance()` 并订阅 `SrcImage.ValueChanged`，注释写的就是
"输入图像变了（换图/接上上游变量）也刷新预览，否则选了图还得再动一下参数才看得到"。
本插件漏了这一步。

## 二、修法（`Plugins\Plugin.PreProcessing\PreProcessingPlugin.cs`）

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 新增 `_isConfigInstance` + `MarkAsConfigInstance()`：视图就绪时置位并订阅 `SrcImage.ValueChanged`（幂等） | `OnViewLoaded` 内 |
| 2 | `OnSrcImageValueChanged` → `SchedulePreview()`（后台线程来源由 `SchedulePreview` 自己投递回 UI） | 同上 |
| 3 | `SchedulePreview` 补 `if (!_isConfigInstance) return;`：运行实例不该被"上游每帧新图"唤醒去重算整条链 | `SchedulePreview` 首行 |
| 4 | `SchedulePreview` 在 `UiDispatcher == null` 时就地 `RefreshPreview()`（离线/断言宿主），与 BlobDetect 同口径 | 同上 |

行为变化：0 个算子时，`RefreshPreviewCore` 在 `steps.Length == 0` 处早退，但 `_sourceImage`
已在方法首行取到新图；`DisplayImage` 的 `Output` 分支查不到 `_stepImages` 时本来就回落原图
（`:266-268` 的注释："该步透传/未产出时退回原图，画面不会空白"），所以画布直接出图、提示条隐藏。

## 三、守门

`FlowCanvasChecks\PreProcessingChecks.cs` 的 `RunPreviewRefreshContract()`：

1. `OnViewLoaded()` 之后、上游还没给图 → `DisplayImage == null`（前提：提示条确实该亮）；
2. 复刻 `BridgeInputs` 的动作 `SrcImage.Value = 一张合成图` → `DisplayImage` **立刻**是这张图
   （`ReferenceEquals`）。

断言宿主没有 `Application`，走的是修法第 4 条同步分支，所以无头环境里结论是确定的
（真机上则是 200ms 防抖）。

**变异反证已做**：注释掉 `SrcImage.ValueChanged += OnSrcImageValueChanged;` 重建 →
全量 gate 从 `2898/0` 变成 `2897/1`，失败的正是第 2 条（明细 `null（没刷新）`）；恢复后回到 `2898/0`。

## 五、边界

- 只解决"输入图到达后预览不刷新"。试运行**结果**（`RunAlgorithm` 产出的 `Image` 端口）
  本来就不进预览字典——预览显示的是"预览链"自己算的那一份，两者同源同参数，画面一致。
- 预览持有的 `_sourceImage` 是**不持所有权**的引用（来自上游编译实例，试运行会话在窗口关闭/
  下次试运行前一直存活），与 BlobDetect / CaliperMeasure 的既有口径相同。
