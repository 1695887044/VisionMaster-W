### 两个必须记住的坑

1. **汇川 CSV 是无 BOM 的 GB18030，不是 UTF-8**（首行字节 `23 B1 E4 C1 BF…` = "#变量…"）。
   按 UTF-8 硬解会把整表中文读成 U+FFFD/错字，且**错字会掩盖重名**：不同中文名塌缩成相同的
   FFFD 串，第一次跑出 19 个假重名；正确解码后真实重名为 0，一个点都不用改名。
   修法：BOM 探测 → 严格 UTF-8 试解 → 失败回落 GB18030；`GB18030` 在 .NET 9 不是内建编码，
   需 `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)`（运行时自带该程序集）。
2. **读 GBK 文件时控制台里的"？？？"是真乱码不是显示问题**——判定方法：把检索串用码点拼出来
   （`[string][char]0x8BBE…`）再 `Contains`，或者解包 xlsx 数 FFFD；靠肉眼看控制台会被误导一整轮。

## 五、踩过的坑（复述给下一次）

- 汇川 CSV = GB18030 无 BOM；`Import-Csv -Encoding UTF8` / `File.ReadAllLines(UTF8)` 都会静默乱码，
  且乱码会**制造假重名、掩盖真数据**——转码类工具的第一件事是确认源文件编码。
- MiniExcel 写 xlsx 用内联字符串，`sharedStrings.xml` 是空的；验证内容要读 `xl/worksheets/sheet1.xml`。
- 手工构造 `EasyNetConfig` 必须显式 `Type = CommunicationType.EasyNet`（默认 0 = ModbusTcp，
  `CommunicationConfig` 构造器会把 Protocol 设错，工厂取错实现抛 InvalidCastException）。
