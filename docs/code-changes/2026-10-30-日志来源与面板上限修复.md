# 日志面板来源与上限：两个静默缺陷的修复（2026-10-30）

## 背景

用户在现场发现运行日志过多，问是否加「极速模式」。量了实际日志后发现两个**与刷屏无关但更基础**的缺陷
（分析见 `交接报告-2026-10-30-日志刷屏治理与极速模式方案.md`）：

1. `LogItem.Source` 恒为 null → 面板的**来源胶囊永不显示**、**按来源搜索一条也搜不到**，且不报任何错。
2. `LogView.xaml` 硬编码 `MaxItems="2000"`，与配置 `LogPanelMaxRows`（默认 5000、设置里可改）**两个上限并存取小**
   → 「日志面板保留条数」这一项**改了永远不生效**。

本次只修这两个，不动日志分档/极速模式（那是下一步）。

### 来源的判定口径（为什么这样取）

`ILogService` 的三个方法是 `params string[]`，全仓 1000+ 调用点、没有一个传 `source`。
而**本仓模块日志本来就是 `[标签] 消息` 的写法**（`[Comm]` / `[启动自检]` / `[退出链]` / `[ScadaWeb]` /
`[组态事件]` / `[系统变量]` / `[HttpImageServer]` …），覆盖率实测 1,774 / 3,234 条（其余就是步骤流水）。

`DeriveSource` 的判定（三条都要满足，防止把索引当标签）：
- 必须 `[` 开头、`]` 在前 24 个字符内；
- 标签内不许有空白；
- `[` 后第一个字符必须是字母或汉字（排除 `[1/121]`、`[0.5s]` 这类）。

步骤流水（`步骤名.插件名 消息`）没有标签 → `Source` 保持 `null` → 面板按既有设计把来源胶囊整块收起
（`UIThemeSmokeTest` 已有断言守这条，未改）。

## 踩过的坑

  手动查看日志时要用 `[Text.Encoding]::GetEncoding(936).GetString(bytes)`，否则中文全是 `?????`，
  会误判成"断言没打印"。
- 断言总数变化容易被忽略：ScadaChecks 从 3330 涨到 3332 正是本次新增的两条，不是回归。
