### 解析优先级（写死在后端）

```
显式 None        → 未判定（不读任何来源）
显式 ResultStep  → 只认结果输出步骤；没有/未执行 → 未判定
显式 Variable    → 只认配置变量（Id 优先、名字兜底）；读不到 → 未判定
显式 StepPort    → 只认配置步骤的 bool 输出端口；步骤未执行 → 未判定
Auto             → 结果输出步骤 > 配置变量 > 配置步骤端口 > 约定变量 <流程名>_Result > 未判定
```

## 5. 踩过的坑

1. **`FlowVerdictResolver` 需要工作区**：配置在 `FlowModel` 上，解析器必须按 `CompiledFlowId`/流程名找到 flow；
   构造从 `(registry)` 改为 `(workspace, registry)`，App 注册同步改。
2. **`StepState` 不在 `VisionMaster.Models`**：它在 `VisionMaster` 命名空间；测试里要 `using VisionMaster;`。
3. **Auto 与显式模式的区别**：显式 Variable/StepPort 配置缺失时**不**回退（避免"配了却没生效"被悄悄掩盖）；
   Auto 才逐级回退。
4. **None 是"不参与"而不是"未配置"**：显式 None 即使结果步骤存在也返回未判定；
   底栏不计数，但轮次仍记录。
5. **配置字段不触发流程重编译**：解析器在轮末读取，改配置下一轮生效；不需要 Version++。
6. **全量 gate 的抖动**：本批复跑中出现过 `FlowCanvasChecks` 计数 4281/1（日志本身 4283/0）与
   `HelpProbe` 退出码异常（日志"全部通过"）；单跑/下一次全量复跑均恢复，属既有宿主抖动。
