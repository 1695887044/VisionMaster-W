### 关键口径

- **节拍**：每轮 `FlowRunStarted → FlowRunCompleted` 的 Stopwatch；底栏显示在跑流程的**瓶颈**（最大值）。
- **OK/NG**：只认业务判定；结果步骤优先，旧方案回退约定变量 `<流程名>_Result`；读不到记「未判定」。
- **NG ≠ 步骤失败**：结果输出步骤 NG 时仍 Success；判定表/卡尺/斑点的步骤状态语义不一致，不能反推。
- **归属**：按 `FlowId` / `SessionId`；不维护"最后开轮的那条流程"。
- **排除**：`Role=Home/End`、子程序流程、调试轮不计入底栏生产 KPI。
- **不落盘**：系统变量是只读派生量，重启/换方案清零。

## 5. 踩过的坑

1. **帮助手册档位闸门**：新增插件类必须在 `HelpManualCheck.Tiers` 登记档位，否则 HM16 红；
   S 档要求 3 用户页 / 1 开发页 / 100 开发行，第一版只有 51 行，HM13/HM17 红。已补到 S 档要求。
2. **运行中的 VisionMaster 锁 `Modules\Plugin.Util.dll`**：插件构建的复制步骤可能报
   `MSB3026 ... 文件被 VisionMaster (22308) 锁定`。本次重试后复制成功（`Modules\Plugin.Util.dll` mtime 13:58:45 > 源码 13:46:07），
   `run_gates` 16 步全绿；若下次遇到 `audit_artifacts` 判红，先关掉运行中的应用再跑。
3. **`OutputPort<T>.Value` 是 object**：断言里 `plugin.Success.Value` 不能直接与 bool 做 `&&`，
   要用 `plugin.Success.TypedValue`（CS0019）。
4. **定时器线程异常会退进程**：`System.Threading.Timer` 回调里任何未捕获异常都会终止进程；
   `Tick` 已整体 try/catch，采集失败保留上一拍。流程线程上的判定读取也包了 try/catch。
5. **`ObservableCollection` 跨线程枚举**：定时器线程枚举 `CurrentSolution.Flows` 时 UI 可能正在增删；
   `Tick` 的 try/catch 会兜住并跳过这一拍（下一拍重试）。更好的做法是订阅集合变更维护快照，留给下一批。
6. **调试轮判定**：`session.DebugEnabled` 在 `FlowRunCompleted` 时仍为 true（引擎收尾才复位）；
   必须在事件里判断，否则调试轮会污染生产 KPI。
