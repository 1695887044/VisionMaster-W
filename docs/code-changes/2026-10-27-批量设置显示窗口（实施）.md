### 关键口径

1. **写的是 `StepModel.InputValues`，不是插件实例**：编译期 `VisionPluginBase.ApplyConfigValues` 才把它灌进实例；`SetInputValue` 发 `PropertyChanged(InputValues)` → `FlowModel.Version++` → 下一轮运行自动重编译。等价于逐个打开参数面板点「确定」。
2. **判型不实例化**：`Type.GetType(PluginTypeName)` 后看 `DisplayViewIndex` 属性类型——`int` = 配置项，`InputPort<int>` = 端口。只有读"当前默认值"时才按类型缓存一个原型实例（`Activator.CreateInstance`，R82 保证构造器无副作用），用完统一 `Dispose`。
3. **当前值口径**：`InputValues` 优先（用户改过的值），缺失时读插件声明默认值（15 个插件都是 1）。弹窗默认值取当前值众数。
4. **越界不写**：`RangeValidation` 只是行内红字，用户仍可能带越界值点确认；VM 侧用 `IsValidValue` 再判一次，`Apply` 自身对越界抛 `ArgumentOutOfRangeException`（双保险）。

## 五、踩过的坑

- **`DisplayViewIndex` 有两种声明形态**：只按"属性是 int"找会漏掉 GeometryFinder/GeometryRelation 的 `InputPort<int>`；只按端口找会漏掉 13 个 `[StepConfig]`。R84 同类坑。
- **`[StepConfig]` 形态不该按链接跳过**：即使 `LinkedSources` 里残留同名键（历史数据），配置属性也不进连线体系，跳过会让它永远改不了。只有端口形态才判 `IsLinked`（[BW8] 反向钉住）。
- **0 是最常用的目标值**（全部关闭显示），任何"空值即跳过"的写法都会把它吞掉——[BW12] 专门钉 `IsValidValue(0)` 与 int 0 落盘。
- **同一窗口只有最后一张可见**：主界面每格默认只保留最新一帧（`KeepInjectedHistory=false`），多个插件投同一格时前面会被覆盖。弹窗说明区已写这句，避免"设了却看不到"的误判。
- **`FlowAction` 的权限 switch 有两处**（`RequiredPermission` 与 `TryRequiredPermission`），漏一处会落到 `UserAdministration` 默认值 → 普通工程师突然没权限。
- **`UIThemeSmokeTest` 有一份 FlowAction 静态清单**（`VisionMaster\Views\FlowListView.xaml` 的 11 项契约）；加枚举不更新它，新菜单项就没有回归守护。
- **`ScadaChecks` 还有一份硬编码的枚举项数**（SL16-a/h/m：四类动作 46、FlowAction 13、Describe 去重 46）：加一个 `FlowAction` 会直接打红 3 条。这不是误报，是"加枚举必须同步权限审计"的守门人——本次已改为 47 / 14 / 47。
- **断言宿主里 `Type.GetType(AssemblyQualifiedName)` 能解析的前提是该程序集已加载**：FlowCanvasChecks 直接引用了 Matching / BlobDetect / ImageAcquisition / GeometryFinder / Util，所以桩步骤能拿到真实插件类型；生产侧靠启动扫描 `LoadFrom`。
