# HALCON 样例流程 ⑤：QR 二维码（9 张）

> 日期：2026-10-26。第五条 HALCON 样例流程：用 `2d_data_codes_default_settings.hdev`
> 的 QR Code 分支（9 张 `qr_workpiece`），对比 HALCON `find_data_code_2d`
> 与 VM `CodeReader` 的解码内容。9/9 张逐字符一致。

## 一、当前状态

- **HALCON 例程**：`examples\hdevelop\Identification\Data-Code\2d_data_codes_default_settings.hdev`
  （只取 `QR Code` 分支）
- **图片**：`examples\images\datacode\qrcode\qr_workpiece_01..09.png`
  （仓库 `Image\images\datacode\qrcode` 有同一份）
- **HALCON 参数**：
  - `create_data_code_2d_model('QR Code', 'default_parameters', 'standard_recognition', Handle)`
  - `find_data_code_2d(Image, SymbolXLDs, Handle, [], [], ResultHandles, DecodedDataStrings)`
- **VM 参数**：`CodeReaderPlugin`，`Symbology="QR Code"`、`Polarity="any"`、`TimeoutMs=500`
  （`DataCodeEngine` 建模型时不传 `default_parameters`，即 HALCON 默认的
  `standard_recognition`；只额外设 `polarity` 与 `timeout`）
- **结果**：9/9 张都解出 `12345678901234567890`，与 HALCON 逐字符一致。
- **落盘流程**：`解决方案\视觉样例对拍\视觉样例对拍.vms` 新增 `二维码读取_QR`，
  步骤 `读取二维码图像 → QR码读取`（全中文命名）。

## 二、已做

### 2.1 对拍结果

临时探针 `HalconQrCompare` 直接调 `CodeReaderPlugin` 的私有 `TryRead`
（运行期与配置期试算共用的路径），与本进程内 HALCON `find_data_code_2d` 比对：

```text
[qr_workpiece_01.png] ref=1 vm=1 OK  ref/vm=[12345678901234567890]
[qr_workpiece_02.png] ref=1 vm=1 OK
...
[qr_workpiece_09.png] ref=1 vm=1 OK
RESULT: ALL_OK
```

- 这 9 张是同一工件的不同姿态/光照，内容相同；`ref=1 vm=1` 说明两边都只报一个码。
- 2D 引擎比一维多两个参数：`polarity`（VM 默认 `any`）与 `timeout`（VM 默认 500ms）。
  两者都不改变这组图的结果；若以后出现差异，先查这两个参数。

### 2.2 落盘流程

```text
视觉样例对拍
├─ 模板匹配_NCC散焦图
├─ 形状匹配_散焦PCB
├─ Blob缺陷检测_标签字符
├─ 码读取_Code128
└─ 二维码读取_QR（For 9 次）
   └─ 循环体
      ├─ 读取二维码图像（文件夹：<方案根>\Image\qrcode，FileIndex←For.Index）
      ├─ QR码读取（码读取，Symbology=QR Code、Polarity=any、TimeoutMs=500）
      │    Image ← 读取二维码图像.Image
      └─ 显示检测结果（结果显示，DisplayViewIndex=1）
           SrcImage ← 读取二维码图像.Image
           OverlayContours ← QR码读取.SymbolContours
           OverlayLabels ← QR码读取.Codes
           r1..r2 ← Count / Text
```

- 工厂批量口径：`For` 遍历整个样例目录（9 张），采集步骤是文件夹模式，`FileIndex` 接 `For.Index`；
  目录用方案内绝对路径（`AcquireFromFolder` 直接 `Directory.Exists`，不解析相对目录）。
- 读码插件只输出 `SymbolContours`（码轮廓）与 `Codes`；结果显示底图接采集原图、
  `OverlayContours` 接 `SymbolContours`、`OverlayLabels` 接 `Codes`（逐码标内容），
  另设 `OverlayPalette=green,red,yellow`、`OverlayLineWidth=2`。
- 步骤配置来自 `CodeReaderPlugin` 的 `[StepConfig]` 属性快照。
- 9 张图全部由 `For` 遍历，不是只跑一张；断言里另有 `CheckBatchFlow` 钉住 For 次数与文件夹模式。

### 2.3 回归断言

`FlowCanvasChecks/CodeReaderChecks.cs` 新增 `RunHalconQrSampleFlow()`：

1. `SolutionService.LoadAsync` 打开 `解决方案\视觉样例对拍\视觉样例对拍.vms`；
2. 按 `FlowName` 找 `二维码读取_QR`，核对采集/算法/结果显示三个步骤与图片路径；
3. `FlowCompiler.Compile` 校验端口名/连线类型；
4. 真 `CodeReaderPlugin.Initialize(step)` + 喂图 + `Execute`；
5. 同一进程内用 `create_data_code_2d_model('QR Code','default_parameters','standard_recognition')`
   + `find_data_code_2d` 现算真值，逐字符比对；
6. 判据：`Success=true && vm.Length==ref.Length && 拼接串相等`。

结果：`FlowCanvasChecks` **3752 通过 / 0 失败**（含前四条样例流程）。

## 五、踩过的坑

1. **`default_parameters` 没暴露成参数**：VM 建模型时不传该 gen 参数，等价于
   `standard_recognition`；例程里的 enhanced/maximum 两档目前无法在 VM 里选。
   对拍时只能拿 standard 档做基准，别把"enhanced 能读、VM 读不出"当成 bug。
2. **`polarity='any'` 是 VM 默认值**：HALCON 例程不设它。这组图两种极性都能读，
   所以结果一致；换反色码时先确认 `polarity` 设置。
3. **超时 500ms**：例程不设超时（默认不限）。这 9 张都在 500ms 内完成；
   若换更难的低对比图，先把 `TimeoutMs` 调大再判定"算法不一致"。
