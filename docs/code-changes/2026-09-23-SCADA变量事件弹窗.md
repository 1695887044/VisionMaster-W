# SCADA 独立「变量事件」弹窗（手册 7.5.2）

对标 InoTouchPad 官方帮助手册第 7 章「控件」，本期落地 7.5.2 的**可组态对象 = 变量**那一类：
把「某个变量的值变化 / 变真 / 变假 / 超上限 / 低于下限」这五类事件，做成一张可组态的表，
并给它一个专门的配置入口——独立弹窗。

> 引擎侧（`ScadaVariableEventEngine` + `ScadaRuntimeHost.StartVariableEvents`）在上一轮 `[VEv]` 已闭合。
> 本期解决的是**「这些配置从哪来」**：引擎只认记录，记录得有人在界面上配出来。

---

## 一、需求与决策

### 1. 需求

- 手册 7.5.2 把可组态对象分成两类：**画面 / 图元**（挂在选中图元上，走属性面板）与**变量**（没有「当前选中的图元」这个落脚点）。
- 变量类事件需要：
  - 一个**独立入口**（属性面板描述不了它，因为落脚点是变量不是图元）；
  - 一张**变量清单**（哪些变量配了、哪些没配、哪些变量的记录已经失效）；
  - 每个变量上挂 **5 类值驱动事件**（更改数值 / 值为真 / 值为假 / 超上限 / 低于下限）；
  - 每条事件下挂**动作表**（与图元事件共用同一套动作模型）；
  - 上下限阈值的编辑（因为「超上限 / 低于下限」这两条事件靠它判定）。

### 2. 关键决策（逐条已与用户确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 弹窗范围 | 整张变量事件表（不是只配当前选中的变量） |
| 2 | 布局 | 左变量清单 + 右事件详情，两栏各自滚动，窗口固定尺寸 |
| 3 | 未配变量怎么进表 | 显式点「新建配置」按钮才建记录（选中即建会让方案凭空多一条空配置、版本号白脏一次） |
| 4 | 右侧排法 | 阈值区置顶 + 下面 5 行事件表 |
| 5 | 写回时机 | 即时写回 + 进撤销栈（本弹窗没有「确定」这一步） |
| 6 | 菜单入口 | 挂「系统」菜单（与运行窗口设置同类：没有「当前选中的图元」这个落脚点） |
| 7 | 左栏分段 | 变量 + 已失效（变量已不存在）两段 |
| 8 | 是否落审计 | 落审计（新建 / 删除 / 改阈值 / 启停监视四类动作） |
| 9 | 事件编辑器怎么复用 | 抽公共控件 `ScadaEventEditor`，属性面板与弹窗共用一份（最彻底） |
| 10 | 控件落点 | 落在 `VisionMaster` 内（`Views/Controls/`），不进 `Scada.Controls` 图元控件库 |
| 11 | 阈值区形态 | 数值框 + 各自启用勾选（清空 = 不判这条限值） |
| 12 | 删除入口 | 详情区顶部按钮（不放右键菜单） |
| 13 | 底部按钮 | 只有「关闭」（写回是即时的，关窗不代表「是否采纳」） |
| 14 | 尺寸 | 固定尺寸 + 两栏各自滚动 |

### 3. 设计要点（为什么这么做）

- **依赖单向不破**：弹窗 ViewModel 落在 `VisionMaster`（WPF 应用层），领域层 `Scada` 一行没动——
  `ScadaVariableEvent` / `ScadaDocument.GetOrAddVariableEvent` 等 API 上一轮就已就位。
- **写模型只有一个入口**：所有改动都走 `ScadaDocument` 的变量事件 API + `ScadaVariableEvent.BeginEdit` 作用域，
  界面层不直接 `Add` / `Remove` 集合。
- **真值不缓存**：`IsConfigured` 每次都从宿主 `FindEventHook(EventType) != null` 回读，
  勾选态与 `Actions` 都是投影，不是副本。
- **框是模型的投影**：阈值文本框与模型双向一致——解析失败回灌原值、清空则模型落 `null` 并把勾一并摘掉、
  取消勾选时框内也一并清空（不留「看着还在其实已不判」的旧值）。
- **失败要看得见**：解析不了给中文原因（含「当前填的是「8O」」这类原文回显），而不是静默当 0 写进模型。
- **左栏状态字实时**：`ScadaVariableEventRow` 订阅记录的 `PropertyChanged`，
  整条监视开关一动，左栏「未配置 / 已配置 / 已停用」立刻跟着翻。

## 三、验证结果

命令：

```
dotnet build VisionMaster.sln -v q --nologo
dotnet run --project ScadaChecks\ScadaChecks.csproj --no-build
```

- 编译：**0 错误**（38 个既有警告，均为历史遗留的 `CS8600/CS8602/CS8604`，与本次改动无关）。
- 断言：**通过 1592 / 失败 0**（较上期 1545 增加 47 条，全部为 `[VEd]` 段）。

### 断言分九段，各钉一类口径

| 段 | 验什么 | 代表断言 |
|---|---|---|
| ① 空工作区 | 左栏真的空、不预选 | `!HasAnyRows`；`SelectedRow == null`；两个命令都置灰 |
| ② 主场景（3 变量 + 3 记录 + 1 条失效） | 分组两段、组序、状态字三态、阈值摘要 | 行数 4；分组串 `变量/已失效（变量已不存在）`；`已配置` / `已停用` / `未配置`；失效行 `Info == null` 且 `Name` 回落记录名快照；`ConditionText == "超上限 80 / 低于下限 5"`，未配为空串 |
| ③ 选中未配置行 → 新建 | 「显式点按钮」这条路真的通 | `ShowCreatePrompt` 真、`Editors.Count == 0`；点新建后记录 +1、`ReferenceEquals` 找回、`Editors.Count == 5`、左栏状态字翻「已配置」 |
| ④ 编辑器五件套 | 顺序 / 显示名 / 悬停 / 空动作表语义 | 顺序串 `ValueChanged/ValueBecameTrue/ValueBecameFalse/ValueOverUpperLimit/ValueUnderLowerLimit`；`DisplayName == DisplayName()`；`Description` 非空；`!IsConfigured && Actions == null` |
| ⑤ 阈值字符串通道 | 解析不了不许静默写模型 | 填 `8O`（字母 O）→ 有错 + 回灌 `80` + 模型仍 80；填 `90` → 模型 90；填空白 → 模型 `null` 且勾摘掉；勾上时框空 → seed `0`；取消下限 → 框内一并清空；重新勾上 → seed `0` |
| ⑥ 整条监视开关 | 左栏状态字跟着翻 | 选停用记录时开关是关的；打开后 `IsEnabled` 为真且状态字从「已停用」翻「已配置」 |
| ⑦ 删除 | 记录没了，选中留在同一个变量上 | 记录 -1；按 `VariableId` 找回的行 `Record == null`；`ShowCreatePrompt` 真、`Editors.Count == 0` |
| ⑧ 关闭 | 以 OK 关窗、不带参数 | `closed.Result == ButtonResult.OK && closed.Parameters.Count == 0` |
| ⑨ 审计 | 四类动作 + 署名 + 同值不落痕 + 失败也落痕 | 新建 / 改阈值（「上限：0 → 88」）/ 启停监视 / 删除各落一条；同值不落；非数字不落；换署名后新行署「李工」；没有打开的方案时失败行署「未登录」 |

## 四、已知边界

1. **左栏只列「工程变量 + 当前方案里已有记录」**。跨方案的变量不列；要配另一个方案的变量，得先切方案。
2. **未配变量不会自动出现在表里**，必须显式点「新建配置」——这是刻意设计，不是缺陷。
3. **阈值只有上、下两个限值**，不支持区间外再套区间，也不支持多档阈值。
4. **阈值是 `double?`**：清空 = 不判这条限值，而不是「判 0」。
5. **取消勾选会清空框内的值**：重新勾上得到的是 `0` 而不是原值。这是「框是模型的投影」这条纪律的必然结果，取舍是「宁可让用户重填，也不留一个看着还在的旧值」。
6. **弹窗固定尺寸**，两栏各自滚动；不支持用户拉伸后记住尺寸。
7. **审计只覆盖四类动作**（新建 / 删除 / 改阈值 / 启停监视）。事件行内「勾选某类事件」与动作表的增删改走的是既有 `[VEv]` 那套审计口径，不在本弹窗另记。
8. **本弹窗不做权限门控**：谁能打开「系统」菜单谁就能配。权限粒度到菜单级为止。
9. **断言只在断言宿主里跑**（STA 线程 + 无消息循环，靠 `CollectionViewSource.GetDefaultView` 造投影分组）；
   真机上的手感（左栏长清单滚动手感、两栏焦点跳转）仍需现场确认。
10. **r5「格式工具栏」仍未开始**——那是用户总指令的第三项，与本弹窗无关。
