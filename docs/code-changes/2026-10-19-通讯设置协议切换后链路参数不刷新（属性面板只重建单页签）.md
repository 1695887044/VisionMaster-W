# 2026-10-19 通讯设置协议切换后链路参数不刷新（属性面板只重建单页签）

- 现象来源：用户反馈「原来我写的是根据用户选择的设备类型，动态反射他的配置属性；用户选择 ModbusRtu 就显示串口，选择 Tcp 就显示网口属性，现在怎么没了」
- 触发位置：`VisionMaster\ViewModels\DialogViewModels\CommunicationSettingsViewModel.cs:385`（`ExecuteAdd`，只是打开属性弹窗，**本身不是缺陷所在**）
- 结论：**模型层的动态反射一直是对的，坏在属性面板的刷新范围**

---

## 一、现象与定位

### 1.1 先排除的三处（都不是原因）

| 检查项 | 结论 |
|---|---|
| `ExecuteAdd` 的代码 | 495 行里只做"造 `CommunicationConfig` → `ShowPropertyGridSync` → `AddConnection`"，没有丢过反射逻辑 |
| `CommunicationConfig.Protocol` 的 setter | `OnChanged()` → `TryCreateConfig()` 仍按协议 `new` 出 `ModbusTcpConfig` / `SerialConfig` / `SiemensS7Config`；探针实测改成 `ModbusRtu` 后模型确实是 `SerialConfig` |
| `Config` 上的 `[PropertyItem(Type = typeof(Control))]` | 仍在；`NestedPropertyGridGenerator` 仍会递归摊开子表单 |

### 1.2 真因

`UI\Controls\CustomControl\PropertyGrid\Core\PropertyGridBase.cs` 里，`RequireRefresh` 的消费点被改成了"只重建该属性所在的页签"：

```csharp
// 改前（错误）
RebuildTabForProperty(e.PropertyName);   // key = GroupSegment(prop, 0)
```

而 `CommunicationConfig` 的两个字段**不在同一个页签**：

| 字段 | 分组 | 作用 |
|---|---|---|
| `Protocol`（标 `RequireRefresh = true`） | 「1. 基本设置」 | 切换开关 |
| `Config`（标 `[PropertyItem]`） | 「2. 链路配置」 | **被换掉的那个对象** |

于是切换协议只重建了「基本设置」，「链路配置」里的嵌套子网格**仍然绑着旧的 `ModbusTcpConfig` 实例**——用户选了 ModbusRtu，屏幕上还是 IP 地址 / 端口号。

### 1.3 为什么"时好时坏"（这是最难查的一点）

页签内容是**懒加载**的（`_builtTabs`）：

| 操作顺序 | 结果 |
|---|---|
| 新建弹窗 → 改协议 → **第一次**点开「链路配置」 | **正常**（懒构建那一刻才创建子网格，取到的是新实例） |
| 新建弹窗 → **先点开**「链路配置」→ 再改协议 | **永远不刷新**；来回切页签也不自愈（旧页签还在 `_builtTabs` 里，懒构建不会重跑） |

用户在实际使用中先看过一眼链路参数再改协议，就必然踩中，表现为"功能没了"。

## 二、修复

`PropertyGridBase.cs`：

1. **`RequireRefresh` 分支恢复整表重建**（与特性注释、使用文档的原始语义一致）：
   ```csharp
   UpdatePropertyGrid(preserveSelectedTab: true);
   ```
2. **`UpdatePropertyGrid` 增加 `preserveSelectedTab` 参数**：整表重建会换掉全部 `TabItem` 实例，
   不保就跳回第一页。实现为"重建前记下选中页签标题 → 重建后按标题找回"，找不到（该分组整体消失）才落回第一页。
3. **删除 `RebuildTabForProperty` 与 `_tabByKey`**：单页签重建这个能力本身就是陷阱，
   留着迟早有人再用一次。

保留的既有行为：普通属性仍不触发重建（走 WPF 绑定），50ms 防抖、异步投递、跨线程封送一律不变。

## 五、已知边界

1. **`preserveSelectedTab` 按页签标题匹配**。若重建后该分组整体消失（属性被动态移除），会落回第一页——这是有意行为，不保留一个已不存在的页签。
2. **整表重建比单页签重建贵**：会重建全部页签头（内容仍懒加载，只重建当前可见那一页的内容）。`RequireRefresh` 只在用户切协议这类低频操作上触发，代价可接受。
3. **没有运行期断言覆盖本次语义**（无头环境里搭真窗口 + Dispatcher 泵可以跑，但成本高于价值）；运行期用临时探针实测过，常规 gate 由 PG0~PG8 的静态扫描守着。
4. **本次未改 `CommunicationConfig` / `ExecuteAdd`**：模型层与入口本来就正确，改它们只会扩大回归面。
