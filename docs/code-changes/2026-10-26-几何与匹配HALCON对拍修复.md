### 2.2 修复一：椭圆 Phi 符号（真实 bug）

`Plugin.GeometryFinder/Services/GeometryHService.cs` 的 `TryFitEllipse` 原先：

```csharp
phi = GeometryParam.NormalizePhi(phiT.D * RadToDeg);
```

HALCON 的 `fit_ellipse_contour_xld` / `gen_ellipse` 用 `Phi` 表示"长轴相对列轴逆时针"，
在行向下的图像系里长轴方向是 **(−sinφ, cosφ)**；本仓 `GeometryParam.Phi` 的方向是
**(sinφ, cosφ)**。两者差一个负号。`Plugin.ResultDisplay` 在绘制椭圆时已经做了 `-g.Phi`，
`GeometryFinder` 却直接透传，导致：

- 拟合出的椭圆标注镜像（φ=0/90 看不出来，φ=45 最明显）；
- `GeometryRelation` 的椭圆残差、`GeometryFinder` 的预览轮廓都跟着错。

修复：

```csharp
phi = GeometryParam.NormalizePhi(-phiT.D * RadToDeg);
```

回归断言：`GeoDemoCheck.RunEllipseSignCheck()` 合成一个 HALCON 30° 椭圆，插件必须输出
**150.18°**（同一长轴、相反符号），半径 120.37×60.25（真值 120×60）。通过。

### 2.3 修复二：NCC 原点与轮廓（真实 bug）

`Plugin.Matching` 的文档承诺 `Row`/`Column` 是"你画的区域中心"，形状模型用
`set_shape_model_origin` 做到了；NCC 没有对应算子，`find_ncc_model` 返回的是模板域重心。
原代码：

```csharp
double dRow = entry.Rect[0] - ModelOriginRow(entry);   // ModelOriginRow 返回 entry.Rect[0]
double dCol = entry.Rect[1] - ModelOriginCol(entry);   // 所以补偿恒为 0
rows = rows + dRow;
cols = cols + dCol;
```

非对称涂抹掩膜会让重心偏离 ROI 中心（本次用例 offset=(-10.864,-10.864)），
输出坐标因此整体偏 13.13 px。另外 NCC 的 `RuntimeContours` 被生成在参考图绝对坐标
`(r[0],r[1])`，而预览/运行时放置都按"相对模板原点"使用，会再平移一次；圆/椭圆 ROI
还被画成矩形。

修复：

- `MatchingTemplateEntry` 新增 `NccOffsetRow` / `NccOffsetCol`（随条目序列化）；
- 学习时 `AreaCenter(domainSource)` 记下 `ROI 中心 − 模板域重心`；
- 匹配时用 `VectorAngleToRigid(0,0,0,row,col,angle)` + `AffineTransPoint2d` 把偏移按
  匹配角旋转后补回（旧方案字段为 0，非对称掩膜的旧 NCC 模板需重新学习一次）；
- NCC 的 `RuntimeContours` 改为以 `(0,0)` 为原点，并按 `Shape` 生成矩形/圆/椭圆轮廓。

回归断言（`MatchingChecks.RunNccOrigin()`）：

```text
【NCC 原点】非对称掩膜确实产生了重心偏移  →  offset=(-10.864,-10.864)
【NCC 原点】同图定位回准 ROI 中心 (150,200 ±0.5)  →  (150.00,200.00) Score=1.000
【NCC 轮廓】轮廓放置回 ROI 中心  →  bbox center=(150.00,200.00)
```

## 五、踩过的坑

- **HALCON 椭圆 Phi 是 `(-sinφ, cosφ)`**：`gen_ellipse_contour_xld` 在 Phi=+30° 时首点是
  `(-50, 86.603)`；`fit_ellipse_contour_xld` 也返回 +30°。本仓 `GeometryParam.Phi` 是
  `(sinφ, cosφ)`，必须取反；`ResultDisplay` 早已这么做，`GeometryFinder` 漏了。
- **`distance_pc` 不是"点到圆心"**：它要一条轮廓，返回点到轮廓的最小/最大距离；
  验圆残差用 `abs(distance_pp(点,圆心) − R)`，验椭圆用 `gen_ellipse_contour_xld + distance_pc`。
- **`intersection_lines` 对平行线返回空元组**，对共线重叠才返回 `IsOverlapping=1`；
  读结果前先判 `Length`，不要直接取 `.D`。
- **6 元仿射矩阵排布不同**：插件 `[a11,a12,a21,a22,tx,ty]`，HALCON `hom_mat2d` 是
  `[a11,a12,tx,a21,a22,ty]`；不重排会得"矩阵不一致"的假结论。
- **透视角度用有限差分对照时，ε 和容差要匹配**：ε=1e-6 时截断误差约 4.6e-5°；
  这不是插件 Jacobian 错，别把容差卡到 1e-9。
- **`line_orientation` 有符号且与行主 Phi 相反**（右下斜线 −45° vs +45°）；
  验"两点构线"应查两点是否在线上 + 方向叉积，不要直接比 `line_orientation`。
- **NCC 的 `find_ncc_model` 原点是模板域重心**：空掩膜的矩形/圆/椭圆 ROI 重心≈中心，
  所以旧实现看起来没问题；一旦涂抹掩膜不对称就暴露。不要用"注释说补偿了"当证据。
- **NCC 的 `RuntimeContours` 必须相对模板原点**：预览按"平移到 ROI 中心"、运行时按
  "旋转平移到命中位姿"使用；生成在参考图绝对坐标会被再平移一次。
- **`FlowCanvasChecks` 构建可能被上一次运行的进程锁住输出 DLL**：构建前
  `Get-Process FlowCanvasChecks`，有就等它退，不要反复重试。
