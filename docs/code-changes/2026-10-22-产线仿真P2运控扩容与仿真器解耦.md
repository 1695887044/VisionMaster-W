### 2.3 修掉的三个真缺陷

1. **限位开关装在行程端点上**（最严重）。上位机 `MotionDeviceBase.DetectCriticalSignals`（`:1359`）把任一轴限位升级成设备级 `Alarm + RequiresReset` → 回零后设备立刻 Alarm，后续所有命令 `Rejected_NotConnected`。
   修法：`Axis` 新增 `LimitSwitchMarginMm = 2.0`，开关位置 = 行程端点 ± 2mm；`CompleteHome()` 走到开关后退回行程端点再定零（`_zeroOffset = _travelMinRaw`，位置 0 = 负端、正端读出行程长度）。
2. **速度/加速度 `<=0` 被当成 0.001 爬**。原来 `Math.Clamp(Math.Abs(speed), 0.001, Max)` 让 `acc=0` 的命令以 0.001mm/s² 加速，5s 只走 0.019mm，现象酷似"下发了没动"。
   修法：`ResolveSpeed`/`ResolveAccel` —— `>0` 才 clamp，`<=0` 取轴级默认（100mm/s、1000mm/s²），契约注释本就写"<=0 用卡级默认值"。
3. **世界开机压在限位上**。`ST1.Z`（-40..0）与 `ST2.Y`（0..900）停 0 时限位位立刻为真 → 一连上就 Alarm。修法：`Axis.ParkAt()` + 构造时把接限位的轴停到行程中点。

## 4. 踩过的坑

1. **`UseWPF=true` 的工程隐式 using 集合里没有 `System.IO`** —— `StreamReader/StreamWriter/IOException` 报 CS0246。本会话第三次命中（`CameraServer.cs`）。凡 WPF 工程里用 `System.IO` 都要显式 `using System.IO;`。
2. **构建失败时旧 exe 还在**，`--selftest` 会照常打印上一次的结果 → 先看构建输出再跑（R65 同族）。
3. **回零是真的走一段**（`HomeSpeedMmPerS` 默认 50mm/s，行程 600mm ≈ 6s），等待给 5s 会假失败。
4. **探针不许吃任意 argv**：`run-probe.ps1` 会传 `--nologo`，探针只认 `--linesim <path>`。
5. **`edit` 的 `old_string` 必须覆盖整行/整块**。本轮以 `---\n\n## 1. 背景与目标` 为锚插入内容时漏把标题写回，把章节标题吃掉了（已修复）。
6. **限位信号在上位机侧是设备级故障源**：仿真器建模时必须把"限位开关位置"与"机械行程端点"分开，否则一接上位机就 Alarm。
