## 一、对象头

**旧版**：一行 `HeaderText`，内容是「类型显示名 · 名字」。而新建图元时 `Name` 默认就等于
`DisplayName`，于是面板顶上长期显示成 **「按钮 · 按钮」**——两段一样的信息各占一半宽度。

**新版**（对齐设计稿的两行结构）：

```
[图标]  料箱
        Hmi.Rectangle                          [锁定 ●]
```

- 第一行 `HeaderTitle` = 图元名 / 画面名 / 状态说明；
- 第二行 `HeaderSubtitle` = **类型键**（`Hmi.Rectangle`）/「画面」；类型没注册时显示
  `Hmi.Xxx（本机未注册该图元）`——与空态同口径，用户一眼知道不是属性丢了；
- 左侧图标块（`HeaderGlyph`）：图元用 Font Awesome `vector-square`，画面用 `file`。

**为什么图标不按图元类型换**：图元库没有图标资产（工具箱那边也只是名字 + 类型键）。
在这里现造一张"类型 → 码点"的映射表，加一类图元就要多记一处，而它的作用只是给对象头一个
视觉锚点，不是"一眼认出是泵还是电机"。

**设计稿的两处没做**（见 `app-shell/README.md` 已知偏差 13/14）：

- 对象头右侧那颗「绑定变量」按钮：本仓的绑定是**按属性**挂的（每行一个 ƒx），没有"整个对象绑一个变量"
  这个概念。硬加一个只会弹出"还没接"；
- 第二行的「· 主画面」图层段：图层按用户裁定不进面板（批次 B 的决定），这里也不放只读展示。

## 二、搜索

- 匹配 **属性名 / 键名 / 分组名**，大小写不敏感、`Contains` 而不是前缀
  （中文属性名多是"填充色"这种复合词，前缀匹配反而找不到）；
- 输入即过滤（`UpdateSourceTrigger=PropertyChanged`），占位文案「搜索属性」，打了字才出现 ✕ 清空按钮；
- **只重算分组，不重建行**（`RebuildGroups` vs `Rebuild`）：行上挂着正在编辑的文本与输入框焦点，
  搜一次就重建等于把用户手里的活抹掉。断言用**引用相等**钉住（`ReferenceEquals(Row("Fill"), fillRow)`）；
- 换选中时**不清空搜索词**：用户正按「温度」找属性时切了个图元，期望的是"在新图元里继续找温度"；
- 空组不占位：过滤后没有行的分组整组消失，不留空组头。

## 三、空态

从"一段长句"改成设计稿的三件套：**图标 + 标题 + 正文**。

- `EmptyTitle`：`未选择对象` / `这个图元本机不认识` / `没有可编辑的属性` / `还没有组态画面` /
  **`没有匹配的属性`**（搜索无结果）；
- `EmptyHint`：正文说"该怎么办"，四类成因分开说；
- `HasRows` 的语义改成**按当前搜索词过滤后**有没有行——搜索无结果时也要出水印，
  否则列表空着、一句提示都没有，用户会以为面板卡住了。

**搜索无结果与"这个对象本来就没属性"必须分开**：混成一句会让用户去怀疑对象，而问题在搜索框。

## 四、上屏变化

| 区域 | 改前 | 改后 |
| --- | --- | --- |
| 顶部 | 一行「按钮 · 按钮」+ 锁定 | 图标 + 两行（名字 / 类型键）+ 锁定 |
| 中部 | 直接是分组列表 | 多一行搜索框 |
| 空态 | 一段长句 | 图标 + 标题 + 正文 |

面板整体高度增加约 **80px**（对象头两行 + 搜索框），渲染探针里的行坐标随之整体下移
（变量带从 y≈716 移到 y≈796），间距断言仍绿。
