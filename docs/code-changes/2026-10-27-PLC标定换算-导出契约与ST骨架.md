# PLC 标定换算：导出契约与 ST 骨架（2026-10-27）

> 前置：`docs\code-changes\2026-10-27-PLC承担像素到机械坐标换算的可行性评估.md`（可行性与风险分析）。
> 本文只写「已确认拓扑下怎么落地」：智能相机直连 PLC、只能发**整像素**、PLC 支持 REAL、
> 机械坐标单位 **0.1mm**。

## 一、三条已确认事实的结论

| 事实 | 结论 |
|---|---|
| 相机只发整像素 | **这是精度天花板，比其它一切因素大 2~3 个数量级。** 决定「0.1mm 能不能做到」 |
| PLC 支持 REAL（可手搓 LREAL） | **REAL 足够，不需要 LREAL。** 手搓 LREAL 省下的误差比整像素量化小 80~800 倍 |
| 机械坐标单位 0.1mm | 系数保持 **mm** 导出，PLC 最后乘 10 —— 保证与上位机/HALCON 的数值 1:1 可比 |

## 二、精度预算（唯一需要先算清的一件事）

整像素的量化误差：每轴 ±0.5px，径向 RMS = √(2/12) ≈ **0.41px**。

设 `p` = 毫米/像素，则运行期量化误差 ≈ **±0.5p**（mm）。

| p (mm/px) | 1280px 相机的视野宽 | ±0.5px 折算 | 对 0.1mm 目标 |
|---|---|---|---|
| 0.05 | 64 mm | ±0.025 mm | 4 倍余量 |
| 0.10 | 128 mm | ±0.05 mm | 2 倍余量，**可用** |
| 0.15 | 192 mm | ±0.075 mm | 余量很小 |
| 0.20 | 256 mm | ±0.10 mm | 吃满，无余量 |
| 0.30 | 384 mm | ±0.15 mm | **超差** |

**判据：视野宽度 ÷ 相机像素数 ≤ 0.1 mm/px。**
1280px 相机视野别超过 128mm；2448px 别超过 245mm。超了就达不到 0.1mm，与 PLC 用什么算术无关。

### 2.1 唯一能大幅改善的动作

**问相机能不能输出「像素 × 10」或「× 100」的整数**（很多智能相机有 scale / unit 设置）。
能的话量化误差从 ±0.5px 降到 ±0.05px，`p` 的允许值放宽 10 倍，上面那张表整体右移一档。
实现上只需把系数除以 10（`a11' = a11/10`），PLC 代码一行不改；**黄金向量要按同一约定生成**。

### 2.2 整像素带来的两个必须做的动作

1. **标定表里的像素值必须与运行期同源**。如果上位机标定时用的是 HALCON 亚像素结果，
   而运行期相机输出的是取整值，就会吃进一个**最多 1px 的常数偏移**（`p`=0.1 时就是 0.1mm）。
   做法：让相机对着标定标记输出一次，把**它给出的整数**填进标定表；
   或者按相机的取整规则（round / floor / truncate 三者不同）把已有亚像素值取整。
   **标定与运行必须用同一种取整方式。**
2. **残差判据要按噪声底重设**。整像素下，即使模型完全正确，`ResidualRmsPx` 也会落在
   **0.3~0.45px**（最小二乘还会再吸收一点噪声）。
   - 0.3~0.5px：已到量化极限，不用再优化；
   - > 0.7px：才是模型问题（相机倾斜 / 畸变 / 点取错）。
   `DiagnoseRadialBands` 的「边缘带 ≥ 2× 中心带」判据仍可用，但绝对门限要从默认 0.5px 抬到 0.8px 以上，
   否则量化噪声会误报「疑似畸变」。

## 三、REAL 够不够：算术

REAL 的相对精度约 6e-8，误差 ≈ |值| × 6e-8。与整像素量化（`p`=0.1mm/px → 0.5 单位）对比：

| 机械坐标绝对值量级 | REAL 舍入误差 | 整像素量化误差 | 倍数 |
|---|---|---|---|
| 10,000 单位（1000mm） | 0.0006 单位（0.06µm） | 0.5 单位（50µm） | **833×** |
| 100,000 单位（10m） | 0.006 单位（0.6µm） | 0.5 单位 | 83× |
| 1,000,000 单位（100m） | 0.06 单位（6µm） | 0.5 单位 | 8× |

即使机械坐标是 100m 量级的绝对坐标，REAL 仍比量化误差好 8 倍。

**结论：这 6/9 个系数的换算不需要 LREAL。** 把省下的工放到第七节的上电自检上，收益高一个量级。

推论：因为用 REAL，**`CalibrationMath` 里的 double 阈值不能照抄**——
`MinProjW = 1e-12`、`MinProjDet = 1e-12`、`BarycentricEps = 1e-9` 在 REAL 里低于可表示精度（eps≈1.2e-7），
照抄等于守卫失效。必须换相对判据（见第六节 ST 里 `wAbs` 那段）。

## 四、模型选型：透视 + 至少 4×4

- **选透视，不选九点**：透视能吸收相机装歪导致的近大远小，只多 3 个系数、2 次除法。
  现场「装不正」比「镜头畸变大」常见得多。
- **点数至少 4×4（16 点），5×5 更好**。透视 8 个自由度，9 点只剩 1 个残差自由度 →
  最小二乘会把量化噪声当成倾斜拟合掉，残差接近 0 是**假信心**。
  标定插件的 `GridSize` 支持 2~10（`CalibrationPlugin.cs:166-168`），4×4/5×5 直接可用。
- **排除网格与内参**：网格的重心容差在 REAL 里不可表示，且定位循环代码长、边界语义易错；
  polynomial 内参只能迭代反解。两者都不该进 PLC。
- **带内参的 `*Undistorted` 三种 Kind 不要用**：矩阵定义在去畸变域，而智能相机不会做
  HALCON 的 `change_radial_distortion_points`，PLC 收到的会是原始像素 → 语义错位
  （kappa=−1500 时视野角点差约 23px）。

## 五、导出契约（写进 PLC 的字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `CalVersion` | DINT | 导出时生成（如 `yyyyMMddHHmm`），HMI 显示，换型/交接班核对 |
| `Kind` | INT | 1=仿射 2=透视（PLC 侧按它分支，未知值 → 故障） |
| `h11..h33` 或 `a11..a32` | REAL | **必须按命名系数写，绝不按数组下标**；单位 mm |
| `UnitScale` | REAL | 输出换算，0.1mm 单位填 `10.0` |
| `ImgW`, `ImgH` | INT | 标定时图像尺寸（惰性数据，HMI 核对 + 像素窗口） |
| `ResidualRmsPx` | REAL | 标定质量（惰性数据，HMI 显示） |
| `Xmin/Xmax/Ymin/Ymax` | REAL | 工作包络（0.1mm 单位） |
| `PtRow[]/PtCol[]/ExpX[]/ExpY[]` | DINT/DINT/REAL/REAL | 自检黄金向量，5~8 点 |

**为什么系数保持 mm 而不预先乘 10**：这样 PLC 里的数能与归档的上位机导出、HALCON 计算结果
逐位比对。乘 10 只放在输出那一行，写清楚「mm → 0.1mm」。把 ×10 折进系数会让
「PLC 里那 6 个数是不是那次标定的」变成一件需要推理的事。

**导出必须按命名系数**：本仓 6 元是 `[a11 a12 a21 a22 a31 a32]`，HALCON 是 `[h11 h12 h13 h21 h22 h23]`，
差一次重排（`CalibrationTransform.cs:176-179`）。按下标导出一旦对错，矩阵看起来完全正常但整幅错位。

## 六、ST 骨架（S7-1200/1500 SCL 风格；Codesys 差异见文末）

```pascal
TYPE ST_CalibCfg :
STRUCT
    CalVersion : DINT;
    Kind       : INT;        // 1=仿射 2=透视
    // 透视系数（Kind=2 用）
    h11, h12, h13 : REAL;
    h21, h22, h23 : REAL;
    h31, h32, h33 : REAL;
    // 仿射系数（Kind=1 用）
    a11, a12, a21, a22, a31, a32 : REAL;
    UnitScale  : REAL;       // 10.0
    ImgW, ImgH : INT;
    Xmin, Xmax, Ymin, Ymax : REAL;
    // 上电自检
    SelfTestCount : INT;
    PtRow  : ARRAY[0..7] OF DINT;
    PtCol  : ARRAY[0..7] OF DINT;
    ExpX   : ARRAY[0..7] OF REAL;   // 0.1mm 单位
    ExpY   : ARRAY[0..7] OF REAL;
    TolX, TolY : REAL;              // 建议 0.1 单位（=0.01mm）
    SelfTestDone : BOOL;
END_STRUCT
END_TYPE


FUNCTION_BLOCK FB_PixelToMachine
VAR_INPUT
    Row      : DINT;         // 整像素
    Col      : DINT;
    CamValid : BOOL;         // 相机「结果有效」位
    Trigger  : BOOL;         // 上升沿执行一次
END_VAR
VAR_IN_OUT
    Cfg      : ST_CalibCfg;
END_VAR
VAR_OUTPUT
    X, Y       : REAL;       // 0.1mm 单位
    PosValid   : BOOL;
    FaultCode  : INT;        // 0=OK 1=相机无效 2=像素越界 3=投影退化 4=包络越界 5=自检失败 6=未知模型
    SelfTestOk : BOOL;
END_VAR
VAR
    r, c     : REAL;
    w, wAbs  : REAL;
    Xmm, Ymm : REAL;
    i        : INT;
    tx, ty   : REAL;
    edg      : BOOL;
END_VAR
BEGIN
    PosValid := FALSE;
    FaultCode := 0;

    // ---- 0. 上电/换版本自检：抓矩阵排布错、单位错、字节序错 ----
    IF NOT Cfg.SelfTestDone THEN
        SelfTestOk := TRUE;
        FOR i := 0 TO Cfg.SelfTestCount - 1 DO
            CalcRaw(Cfg, Cfg.PtRow[i], Cfg.PtCol[i], tx, ty);   // 复用同一段公式，见下方 FC
            IF ABS(tx - Cfg.ExpX[i]) > Cfg.TolX
            OR ABS(ty - Cfg.ExpY[i]) > Cfg.TolY THEN
                SelfTestOk := FALSE;
            END_IF;
        END_FOR;
        Cfg.SelfTestDone := TRUE;
    END_IF;

    IF NOT SelfTestOk THEN
        FaultCode := 5;
        RETURN;
    END_IF;

    edg := Trigger AND NOT EdgeMem;
    EdgeMem := Trigger;
    IF NOT edg THEN RETURN; END_IF;

    // ---- 1. 相机结果有效性（替代上位机 IsUsablePixelPoint）----
    IF NOT CamValid THEN
        FaultCode := 1;
        RETURN;
    END_IF;

    // ---- 2. 像素合法性窗口（替代上位机 (0,0)/NaN 判据）----
    IF Row < 0 OR Row > Cfg.ImgH - 1 OR Col < 0 OR Col > Cfg.ImgW - 1 THEN
        FaultCode := 2;
        RETURN;
    END_IF;

    // ---- 3. 换算 ----
    IF Cfg.Kind = 2 THEN
        r := DINT_TO_REAL(Row);   // DINT ≤ 16.7M 时转 REAL 无损，整像素没有精度损失
        c := DINT_TO_REAL(Col);
        w    := Cfg.h31 * r + Cfg.h32 * c + Cfg.h33;
        // 相对守卫：double 的 1e-12 在 REAL 里不可表示，必须用相对判据
        wAbs := ABS(Cfg.h31 * r) + ABS(Cfg.h32 * c) + ABS(Cfg.h33);
        IF wAbs < 1.0E-20 OR ABS(w) < 1.0E-4 * wAbs THEN
            FaultCode := 3;
            RETURN;
        END_IF;
        Xmm := (Cfg.h11 * r + Cfg.h12 * c + Cfg.h13) / w;
        Ymm := (Cfg.h21 * r + Cfg.h22 * c + Cfg.h23) / w;
    ELSIF Cfg.Kind = 1 THEN
        r := DINT_TO_REAL(Row);
        c := DINT_TO_REAL(Col);
        Xmm := Cfg.a11 * r + Cfg.a12 * c + Cfg.a31;
        Ymm := Cfg.a21 * r + Cfg.a22 * c + Cfg.a32;
    ELSE
        FaultCode := 6;           // 未知模型：绝不静默按仿射跑
        RETURN;
    END_IF;

    // ---- 4. mm → 0.1mm（单位换算只有这一处）----
    X := Xmm * Cfg.UnitScale;
    Y := Ymm * Cfg.UnitScale;

    // ---- 5. 工作包络：抓「系数没加载」「用错工位」「整幅错位」----
    IF X < Cfg.Xmin OR X > Cfg.Xmax OR Y < Cfg.Ymin OR Y > Cfg.Ymax THEN
        FaultCode := 4;
        RETURN;
    END_IF;

    PosValid := TRUE;
END_FUNCTION_BLOCK
```

`CalcRaw` 就是第 3 段那段公式（按 `Cfg.Kind` 分支），抽成 FC 让自检与运行走**同一份代码**——
自检与运行分叉，自检就失去意义。

### 6.1 三个实现注意

1. **REAL 比较一律用容差**，不要用 `=`。自检的 `TolX/TolY` 建议 0.1 单位（0.01mm）：
   同系数同整数输入下 PLC 与上位机的差异只在 REAL vs double 的舍入（≈1e-4 单位），
   0.1 单位既能挡住 10 倍单位错和矩阵重排错（误差是整幅量级），又不会误报。
2. **输出要动轴时再取整**。若运动接口收 0.1mm 的 DINT，`REAL_TO_DINT(ROUND(X))`，
   取整规则（四舍五入 vs 银行家舍入）要与上位机黄金向量一致，否则差 1 个单位。
3. **相机「结果有效」位不可省**。整像素下检测失败常输出 `(0,0)`，
   它与「零件真在像素原点」在数值上不可区分；没有 valid 位就只能靠像素窗口兜底，
   而 `(0,0)` 恰好落在窗口内（合法像素）——**兜不住**。

### 6.2 Codesys / 其它平台差异

- 类型转换：`DINT_TO_REAL` 在 Codesys 里同样可用；Mitsubishi 需用 `FLT`/`INT_TO_REAL` 等价写法。
- 边沿检测：Codesys 用 `R_TRIG`；S7 可手写 `EdgeMem`（上面即手写版）。
- `ROUND` 在 Codesys 是银行家舍入（.5 取偶），S7 是四舍五入。**跨平台迁移要重验黄金向量。**

## 七、上电自检：这是方案 A 下性价比最高的一道闸

把 5~8 个黄金向量烧进 PLC（`PtRow/PtCol/ExpX/ExpY`），系数加载后或每次上电跑一遍。
它能自动抓住**全部三种最致命的错误**，而且不需要上位机在回路里：

| 错误 | 自检能否抓到 |
|---|---|
| 矩阵排布错（按数组下标导出） | ✅ 误差是整幅量级 |
| 单位错（mm 当 0.1mm / 系数预乘了 10） | ✅ 10 倍偏差 |
| 字节序 / 字序错（REAL 翻反） | ✅ 数值完全离谱 |
| 系数没加载 / 用了别的工位 | ✅ |
| 相机取整方式变了（floor→round） | ⚠️ 半像素级，需 `Tol` 收紧到 0.5 单位才抓得到 |
| 标定过期（用了旧标定） | ❌ **抓不到**，只能靠 `CalVersion` 上屏 + 换型确认 |

最后一行要诚实接受：**方案 A 下没有第二份真源可比对，「旧标定」只能靠流程管。**

## 八、验收清单

1. 确认 `p = 视野宽 ÷ 像素数 ≤ 0.1 mm/px`（第 2 节）。超了先改光学，别改代码。
2. 确认相机能否输出 ×10/×100 整数（2.1）。能就按缩放后的约定做，整体精度放宽 10 倍。
3. 标定用 **透视 + ≥4×4 点**，标定表里的像素值用**相机输出的整数**（2.2-1）。
4. 检查 `ResidualRmsPx` 是否落在 0.3~0.45px（2.2-2）。>0.7px 先查倾斜/畸变/点取错。
5. 导出 ≥200 点黄金向量，上位机与 HALCON 双向核对（`affine_trans_point_2d` /
   `projective_trans_point_2d`，注意 6 元重排）。
6. 抽 5~8 点写进 PLC 做上电自检。
7. 全量 200 点在 PLC 上跑一遍比对，最大偏差 ≤ 0.1mm。
8. **每次重新标定：重跑 4~7 全部步骤**，并更新 `CalVersion`。
