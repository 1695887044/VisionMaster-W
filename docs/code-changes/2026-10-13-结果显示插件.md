## 二、目标与背景

平台**没有任何"纯显示"算子**：数值算出来了但不上屏，用户要看结果只能靠各插件自己在图上画——于是仓库里长出了**五份**同源的"离屏窗口烘焙"实现（BlobDetect / CaliperMeasure / BeadInspect / Matching / ImageScript），每份都各自踩（或各自躲过）同一批坑。而几何工具那两个新插件**连显示出口都没有**（几何计算无图像口、连 `Core.Halcon` 都不引用）。

本轮两件事：

1. **给一个通用的「结果显示」算子**——所有算子的输出（结果与数值）都能通过它标注在图上，用户不需要为每个新算子再写一遍画图代码。
2. **把烘焙收成一个共享件**——第六份不可接受。

**为什么走"离屏烧录"而不是"覆盖层"**（§12-①，2026-10-13 用户裁定）：`ImageCollectionService.BuildFrame:451-452` 里**缩略图与 `Image` 是同一份像素**，`ImageExporter.cs:76` 只消费 `frame.Image`。所以**烧进像素的标注自动出现在大图、缩略图、导出 PNG、报警留存图上，宿主零改动**；覆盖层方案这三条全都拿不到，要治就得动宿主。另：覆盖层通道目前**是空跑的**——`PluginPreviewExtensions.cs:37-38` 那个带 `annotations` 的重载**全仓零调用方**，12 个发布者全走 2 参重载，所以改道**不会丢掉一个正在用的通道**。

## 四、实现相对方案的刻意偏离（**以此为准**，详见说明书第 14 章）

| # | 偏离 | 理由 |
| --- | --- | --- |
| 1 | **底图归一化的归属**：方案 §5.1/§7.5 说在 `DisplayDraw`，实际是 `AnnotationBaker.NormalizeForDisplay`（`public static`），由 `Bake` 内部自动调；`DisplayDraw` 完全不碰像素类型 | 迁移四份之后，归一化留在各调用方 = 同一份代码复制五遍，正是共享件要消灭的东西；且"Caliper 那份残缺会死白"的分歧只有收进唯一一处才治得了根 |
| 2 | **迁移集合是四份，不是五份**：`Plugin.ImageScript\HDevDisplayBackend.cs` 是**永久非烘焙件例外** | 它是 HDevEngine 按 `dev_*` 算子**逐条驱动**的显示后端（`[ThreadStatic]` 窗口状态、`HandoutWindow` 把窗口交给脚本），"画什么"在脚本跑完之前根本不存在，`BakePlan`（跑完才攒得出来）表达不了它 |
| 3 | **`Cross` 的 `P` 长度是 2 或 3**（方案 A4 写固定 2） | 3 = `(row,col,size)`；2 = `(row,col)` 用默认 size。`DisplayDraw` 走 3 |
| 4 | **椭圆角度有两处变换，各归各家**：度→弧度在 baker（`p[2] * π/180`），**符号取反在 `DisplayDraw`**（传 `-g.Phi`） | 本仓 `GeometryParam.Phi` 的方向向量是 `(sin φ, cos φ)`（**行主**，`GeometryHService.cs:63-67`），HALCON 的 `Phi` 是"自列轴逆时针"，在行向下的图像系里等价于 `(−sin Phi, cos Phi)`（同口径旁证 `CreateRoiPlugin.cs:881`）。度→弧度是"对接 HALCON"的职责，取反是"对接本仓角度定义"的职责，合到一处就会在下一个调用方身上再错一次 |
| 5 | **结果项表是 6 列**（方案写 5 列，漏了"单位"），且容器是 **`ItemsControl` + 手写表头 `Grid`**，不是 `ListView + GridView` | `DisplayItemDef.Unit` 一直存在，没有输入口就等于永远空着。不用 GridView 是为了避开 AGENTS.md 第 6 节那个 Fluent 隐式样式顶掉列头的坑（R19~R22）；代价是"改列宽要同时改表头与数据行两处 `ColumnDefinitions`" |
| 6 | **用户连进来的 `HRegion`/`HXLD` 不抽稀** | `ThinPoints` 只用于"上游给 `double[]` 点集、本插件自己 `GenContourPolygonXld`"那条通路。改用户的几何对象 = 改检测结果，显示算子没这个权力 |
| 7 | **`box` 之争的结论要修正**：不是"只给 `box_color` 画不出框"，实测 **box 默认就是开的**（18303px vs 3754px，`HDevDisplayBackend.cs:514-518`） | 真正的风险是"把决定权交给默认值"→ `BakeText.Box` 做成 **record struct 的必填位置参数**，编译期就不可能漏。⚠ 名字是**大写 `Box`**，写 `new BakeText(..., box: false)` → **CS1739**（本轮真踩） |
| 8 | **迁移改了一层图层顺序**（BlobDetect）：baker 的绘制顺序固定为 `Shapes → Objects → Texts`（`AnnotationBaker.cs:148-150`），缺陷号因此在黄色高亮框**之上** | 顺序不固定 = 每个调用方自己决定谁压谁，那 §5.2-3 的 `SetPart`、`SetLineWidth`/`SetDraw` 还原这些**窗口级状态纪律**就没法只写一遍。要改层序就改 plan 的入列顺序，**不要改 baker** |

| 12 | **`OutputPort<T>` 一律用 `.TypedValue`，不用 `.Value`** | `.Value` 返回 `object`，于是 `.IsInitialized()` **静默绑定到 Prism 的扩展方法**（CS0411），把 `HImage`/`string`/`int` 当参数传直接 CS1503。`InputPort<T>.ActualValue` 本身就是强类型，没这个问题 |
