# 仓库根目录整理（分区 + 探针登记 + 白名单）

> 日期：2026-10-21
> 范围：仓库根目录与 `tools/`、`_Retired/`；**不改任何生产源码**。
> 结论：根目录文件 841 → 8，目录 75 → 40；全仓 13.44 GB → 9.78 GB（重建后）。
> 约束已写入 `AGENTS.md` §36（R166–R170）。

---

## 1. 起因

用户反馈"方案文件夹太乱了，什么都有"，并要求：
① 给出迁移方案与文件位置约束；② 按推荐执行；③ **把"运行中的任务找不到自己的探针文件"写进约束**。

实测现状（迁移前）：

| 指标 | 数字 |
| --- | --- |
| 根目录文件 | **841**：527 `.log` + 195 `.out` + 69 `.txt` + 5 `.err` + 9 无扩展名垃圾 + 少量脚本/图片 |
| 根目录子目录 | **75**，其中 **31** 个以 `_` 开头 |
| 全仓 | 111,943 文件 / **13.44 GB** |
| `bin` + `obj` | 359 个目录（含嵌套）/ **6.49 GB** |
| `docs/code-changes` | 320 篇 |
| sln 内工程 | 44 个；另有 6 个工程未入 sln |

生产源码其实只占 15 个顶层目录：`VisionMaster`、`Core`、`Engine`、`Communication`、`Services`、`Shard`、`UI`、`Plugins`、`Scada`、`Scada.Controls`、`Scada.Controls.Charts`、`Charts`、`Web`、`Demo`、`DLL`。其余 60 个条目是日志、渲染产物、探针、一次性脚本、构建缓存与垃圾。

---

## 2. 决策：不做"全仓 src/ 大搬家"

四条硬约束决定了源码目录不能搬：

| 目录/文件 | 原因 |
| --- | --- |
| `Plugins\` | `Plugins\Directory.Build.targets` 按目录把 DLL 投递到 `Modules\`，搬走 = 红线① |
| `Modules\` | 宿主只扫 `Modules\Plugin*.dll` |
| `DLL\Halcon` | `pack.ps1` 硬编码路径 |
| `Image\` | `.vms` 里是绝对路径 |
| 9 个验证宿主 | 在 sln 内、被 160 篇文档引用 `dotnet run --project X` |

因此采用 **"分区 + 清理 + 白名单"**：源码原地不动，把非源码内容赶出根目录，并用门禁防回潮。

### 关于 ScadaChecks 的 4 条失败（与本轮迁移无关）

失败项：`Presentation=Text → 下拉框收起`、`Text 呈现标签/值`、`ShowSeparator=false → 底边线收起`、`有写通道 + 绑定 → IsEditable=true`。

证据：

- 这 4 条位于 `ScadaChecks/Phase2UiChecks.cs`（mtime **14:37:45**）与 `ChoiceControlChecks.cs`（14:26:52）；
- 被测控件 `Scada.Controls/Elements/ComboBoxElement.cs`（mtime **14:20:21**）与 `Themes/ComboBoxElement.xaml`（14:20:52）；
- `ScadaChecks/Program.cs` 在 **14:39:07** 仍在被修改（我们的 ScadaChecks 运行期间）；
- 本轮迁移**没有触碰** `Scada.Controls` / `ScadaChecks` 的任何源码。

结论：这是另一个会话正在开发的 SCADA 下拉框 `Presentation=Text` 功能，属于"改了控件、断言还没跟上"的在途状态；本轮迁移只是重建了它，没有改它的行为。

## 7. 回滚方法

本机 `git` 命令不在 PATH，无法用 git 回滚，所以清理一律"移动而非删除"：

| 要恢复什么 | 从哪里 |
| --- | --- |
| 根日志/输出 | `_Retired/2026-10-21-root-logs/` |
| 一次性脚本 | `_Retired/2026-10-21-oneoff-scripts/` |
| 游离文件 | `_Retired/2026-10-21-strays/` |
| 退役探针 | `_Retired/2026-10-21-probes/`（移回根目录即可，csproj 仍是 `..\`） |
| 在用探针 | `tools/probes/<原名>/`（移回根目录后需把 csproj 的 `..\..\..\` 改回 `..\`） |
| 渲染产物 | `artifacts/render/2026-10-21/` |

只有 15 个垃圾文件与 `2000` cookie jar 是直接删除、不可恢复的。
