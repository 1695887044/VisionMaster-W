# 2026-09-25 冒烟命令超时排障与规避（FlowCanvasChecks）

> 记录一次"命令老是超时"的完整排障过程，以及**写死的规避规则**。
> 下次再遇到 `dotnet build` / `dotnet run` 卡住或报 MSB3021/3027，先看这一份，不要再从头猜。

---

## 1. 现象

在本轮（插件配置界面样式收编 UI 库）里连续出现：

- `dotnet run --project FlowCanvasChecks` 迟迟不返回，被环境判定为"长时间运行"丢到后台；
- 后台命令没结束，`FlowCanvasChecks.exe` **常驻进程**（实测同时存在 2 个：PID 99796 / 19376，后来又冒出 66084、2628）；
- 下一次 `dotnet build` 报一大堆错，全是同一类：

```
error MSB3027: 无法将“...\Core.Controls.dll”复制到“bin\Debug\net9.0-windows\Core.Controls.dll”。
               超出了重试计数 10。失败。文件被“FlowCanvasChecks (66084)”锁定。
error MSB3021: 无法将文件“...”复制... The process cannot access the file ... because it is being
               used by another process.
```

- 输出重定向 `Out-File C:\Temp\smoke_style.txt` 报"文件正由另一进程使用"；
- 单次 build 从正常的 2 秒劣化到 **43 秒**（全是锁重试）。

---

## 2. 根因（三条，按贡献排序）

### 根因 A（主因）：在控制台冒烟里 `new Application()`

我为验证"插件视图的 StaticResource 能不能解析"，在 `FlowCanvasChecks` 里起了 STA 线程并
`new Application()`（WPF 资源解析需要 `Application.Current`）。两个实测后果：

1. **污染后续断言**：`Application.Current` 一存在，插件里的预览帧投射逻辑就改走 UI 线程投递分支，
   而在没有消息泵的控制台里永远不落地 → **后续 7 条投射类断言变红**
   （`脚本往视图窗口发过预览帧`、`【投射】只投一帧…`、`【10 芯】结果帧带标注…` 等）；
2. **进程退出时挂住**：STA 线程上的 Application 既没有消息泵也未必走到 Shutdown，
   进程不退出 → 命令不返回 → 被后台化 → 进程残留 → 锁住 exe/DLL。

**结论：冒烟工程（控制台）里禁止 `new Application()`、禁止实例化 WPF 视图。**

### 根因 B：残留进程 → 文件锁 → 重试放大

残留的 exe 与它加载的一批 DLL 全被锁住。MSBuild 复制失败会**重试 10 次**再放弃，
于是 2 秒的活变成 43 秒，并且 26 条"错误"里**没有一条是代码错误**——极易误判成改坏了。

### 根因 C：输出文件固定 + 重复全量运行

- 固定文件名 + 进程残留 → `Out-File` 报占用；
- 冒烟是**全量重活**（HTTP 服务端真监听、OCR/码读取真模型、YOLO、线序端到端真跑），
  单次几十秒~分钟级。我只想看其中一小段却反复全量跑，每次都付全量成本。

## 3. 已落地的修复

| 改动 | 说明 |
| --- | --- |
| `FlowCanvasChecks/BlobDetectChecks.cs` | 视图样式契约改为**纯静态扫描**（读 XAML 源文件比对键名），彻底不再 `new Application` / 实例化视图 |
| `FlowCanvasChecks/Program.cs` | 撤销"把该段放最后"的特殊调用，回到普通注册 |
| 视图能否真的打开 | 改用**仓库外一次性探针**（`C:\Temp\ViewProbe`，自带 `Environment.Exit(0)` 强制退出），验证完即删 |

静态扫描的判据与运行期等价：运行期报的是"无法找到名为 X 的资源"，
静态版报的是"用到但没定义"。实测插件视图共引用 **23 个 Plugin\* 键**，全部有定义。

## 4. 规避规则（写死，后续照做）

1. **冒烟一次跑完落盘，之后 grep 文件，绝不重复运行**
   ```powershell
   $out = "C:\Temp\smoke_" + (Get-Date -f HHmmss) + ".txt"   # 带时间戳，避免占用
   dotnet run --project FlowCanvasChecks\FlowCanvasChecks.csproj -c Debug --no-build 2>&1 | Out-File -Encoding utf8 $out
   Select-String -Path $out -Pattern "关键字" -Context 0,10
   ```
2. **冒烟工程里禁止 `new Application()` / 禁止实例化 WPF 视图**。
   WPF 资源相关的验证一律走静态扫描（读源文件、比对 `x:Key` 与 `StaticResource` 引用）。
   确实需要实例化视图时，用**仓库外的一次性探针**，且末尾 `Environment.Exit(0)`。
3. **看到 MSB3021 / MSB3027 就先杀进程，不要怀疑代码**
   ```powershell
   1..3 | ForEach-Object { Get-Process -Name FlowCanvasChecks -ErrorAction SilentlyContinue | Stop-Process -Force; Start-Sleep 2 }
   ```
   实测：清空后 build 从 43 秒 → **1.89 秒**。
4. **跑长命令前先清残留**，尤其是被"后台化/cancel"过的命令——cancel 不等于进程结束。
5. **只看某一段时先想清楚代价**：冒烟没有 filter，跑就是全量。
   单工程改动优先 `dotnet build <单个 csproj>`（秒级），最后再跑一次全量冒烟收口。
6. HALCON 原生库需注入 PATH：
   `$env:PATH = "E:\VM\VisionMaster-W-master\DLL\Halcon;" + $env:PATH`

## 5. 排障过程中的副产品（两个真实缺陷）

都不是超时本身，但是靠这条链路抓出来的：

1. **`ColumnDefinition.Width` 不能用 `sys:Double` 资源** —— 它的类型是 `GridLength`，
   塞 double 会在 XAML 解析时抛"设置属性 Width 时引发了异常"。列宽令牌必须声明成 `GridLength`。
2. **合并字典内部的 `StaticResource` 不会横向查同级的另一本字典** ——
   `PluginConfigStyles.xaml` 引用 `PluginConfigColors.xaml` 的键时，必须自己再合并一次：
   ```xml
   <ResourceDictionary.MergedDictionaries>
       <ResourceDictionary Source="/UI;component/Themes/PluginConfigColors.xaml" />
   </ResourceDictionary.MergedDictionaries>
   ```
   漏了这行就抛 `无法找到名为“PluginCardShadowBlur”的资源`（独立探针抓到的原文）。
