# 添加变量弹窗按协议 / 类型分块（Modbus 不再显示 DB 块编号与每元素字节数）

> 日期：2026-10-21
> 范围：VisionMaster 变量管理「添加变量」弹窗（`NetworkVariableDraft` / `VariableDraft`）
> 口径：以磁盘代码为准。只改**界面字段的组织方式**，不改地址构造与协议语义。

---

## 0. 一句话结论

把 `NetworkVariableDraft` 上平铺的四套协议字段、两套类型字段拆成两个嵌套子对象：
**「地址参数」按连接协议换实例**（Modbus / S7 / MC / FINS），**「元素参数」按数据类型换实例**
（标量 / 数值数组 / 字符串 / 字符串数组），靠 `RequireRefresh` 整表重建。
Modbus 连接下只剩「站号 / 40001 写法」，S7 下只剩「DB 块编号 / 位偏移」，标量下不再出现「每元素字节数」。

---

## 1. 起因

用户真机反馈：添加 ModbusTcp 设备后，点「添加变量」→「网络参数」页签里出现
**「DB块编号」**与**「每元素字节数」**——前者只对 S7 的 DB 区有效，后者只对 `string[]` 有效，
在 Modbus 点位录入时纯属噪音，而且容易让人以为填了生效。

---

## 2. 根因

1. 弹窗不是手写视图，而是 `EasyDialog.ShowPropertyGridAsync("添加变量", draft)` 渲染的
   `FlatPropertyGrid`（`GlobalVariableManagerViewModel.cs` 的 `AddVariableCore`）。
2. 属性网格的可见性判据只有 `[SuperDisplay].Visible == true`，那是**编译期常量**；
   `RequireRefresh` 只能整表重建、改不了可见性（`PropertyGridDefaults.GetVisibleProperties`）。
3. `NetworkVariableDraft` 把四套协议的字段平铺在一个类上：`DbNumber`（S7）、
   `UseLegacyAddress` / `Station`（Modbus）、`BitOffset`（S7/FINS）、`ElementCount` / `ElementByteLength`
   （数组 / 字符串）——全部带 `[SuperDisplay]`，所以不管选哪条连接都会画出来。
4. 值层面本来就是忽略的：`TryBuildAddress` 的 Modbus 分支根本不传 `dbNumber`，
   `elementByteLength` 只在 `string[]` 时生效。也就是说这是**纯界面噪音**，不是数据错误。

该边界在 `docs\code-changes\2026-10-21-通讯控件审查修复（连接编辑丢类型与MC地址进制）.md`
§7 第 6 条 / §9 第 1 条已登记（当时只加了 `Description` 文案）；本轮按仓库既有范式落地。

---

## 3. 改法

范式照 `.zcode\skills\vm-property-grid\SKILL.md` §5.1.1（互斥字段不要平铺）：

```
NetworkVariableDraft（公共：连接/扫描组/存储区/偏移量/地址偏移/合并读/换算/预览）
├── AddressDraft : ProtocolAddressDraft     ← ConnectionName 变 → 换实例（RequireRefresh）
│   ├── ModbusAddressDraft   站号 / 40001 写法
│   ├── S7AddressDraft       DB 块编号 / 位偏移（0-7）
│   ├── FinsAddressDraft     位偏移（0-15）
│   ├── McAddressDraft       一行只读说明（位访问由存储区表达）
│   └── UnknownAddressDraft  一行只读说明（先选所属连接）
└── Elements : ElementDraft                 ← TypeName 变 → 换实例（RequireRefresh）
    ├── ScalarElementDraft          一行只读说明（标量按 1 个元素读）
    ├── ArrayElementDraft           元素个数
    ├── StringScalarElementDraft    字节长度（默认 20）
    └── StringArrayElementDraft     元素个数 + 每元素字节数（默认 10 × 20）
```

四条实现要点：

1. **外层只留公共字段**，协议/类型专属字段全部搬进子对象；外层用
   `[PropertyItem(Type = typeof(Control))]` 递归展开（`NestedPropertyGridGenerator`）。
2. **换实例而不是原地改字段**：`ConnectionName` / `TypeName` 的 setter 里同步换 `AddressDraft` /
   `Elements`，两个切换字段都带 `RequireRefresh = true`（50ms 后整表重建）。
3. **草稿保留**：每种协议、每种类型形态各缓存一个实例——S7 填完 DB 号切去看 Modbus、
   再切回来 DB 号还在（旧实现是同一个字段被来回改，`string[]` 填的 3 项切去 `string` 会变成 20）。
4. **消费侧零改动**：`ElementCount` / `ElementByteLength` / `BitOffset` / `DbNumber` / `Station` /
   `UseLegacyAddress` 保留为**只读透传属性**，`BuildAddressPreview` 与 `AddNetworkVariable` 的
   `TryBuildAddress(...)` 调用一字未改。非适用协议返回中性值（0 / 1 / false），
   下游协议分支本来就忽略这些参数。

`NetworkVariableDraftContext` 新增两个回调：`ProtocolFor`（连接名 → 协议）与
`TypeResolver`（类型显示名 → CLR 类型），由 VM 注入 `FindConnection(name)?.Protocol` 与 `ResolveType`。

## 6. 已知边界

1. **嵌套块头会显示内部类名**（`地址参数 ModbusAddressDraft`、`元素参数 ArrayElementDraft`）：
   这是 `NestedPropertyGridGenerator.BuildInlineBlock` 的既有行为（连接配置弹窗的
   `底层链路参数 ModbusTcpConfig` 同款），不是本批引入。要隐藏得给属性网格加"隐藏类型名"开关。
2. **MC / 未知协议用一行只读说明占位**：空嵌套块看起来像界面坏了；说明行同时解释了
   "MC 的位访问由存储区表达"与"先选连接"。
3. **`TypeName` 的 `RequireRefresh` 对本地草稿也生效**：本地草稿只有 4 个字段，
   切类型多一次整表重建（无副作用，且保持本地/网络两个草稿的基类语义一致）。
4. **值层面本来就不生效**：本批只改"看不看得见"，`TryBuildAddress` 的协议分支、
   地址串、轮询计划、`.vms` 存量数据全部未动；旧方案打开后的行为不变。
