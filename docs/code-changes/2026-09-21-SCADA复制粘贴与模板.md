## 一、需求与决策

### 1. 需求

路线图"工程效率"那一行还欠两项：**复制粘贴 / 模板**（[路线图](../SCADA商业级交付路线图.md#L21)）。这两件事在用户眼里是两件事，在代码里是**一件事的两种落点**：

| | 复制 / 粘贴 / 再制 | 模板 |
|---|---|---|
| 存哪儿 | 进程内存（剪贴板） | 磁盘（`ScadaTemplates.json`） |
| 活多久 | 关软件即失 | 跨会话、跨工程 |
| 搬什么 | **一模一样**：快照 | **一模一样**：快照 |
| 怎么落地 | `Materialize` | `Materialize` |

所以本轮的骨架是：**一份"不可变快照" + 一个"物化"动作**。剪贴板与模板库都只是这份快照的容器——一个在内存、一个在磁盘。四条落地路径（粘贴 / 再制 / 插模板 / 拖模板）**共用同一个物化函数**，"一次操作 = 一条撤销位""ElementId 一律重生成"这类不变量就只在一处负责。

要解决的具体症状：

1. 现场画一排十个一样的按钮，只能拖十次、每次再改一遍属性（**复制**）。
2. 改完版式要"按刚才那套再来一遍"，得从头拼（**再制**）。
3. 反复出现的一小块（三通阀 + 两根管 + 一个位号）每张画面都要重画一遍（**模板**）。

### 2. 决策清单 —— 领域层：快照载体

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| C-1 | 快照装什么 | **纯数据**（`ScadaElementSnapshot`）：类型键 / 名字 / X Y W H / 旋转 / Z / `LayerName` / `GroupSlot` / `IsLocked` / 属性袋 | 活对象搬不过去：`ScadaElement` 身上挂着 `ElementId`、`LayerId`、`GroupId` 这些**只在源画面里成立**的关系。搬过去等于把源画面的坐标系统带进了目标画面 |
| C-2 | 快照可不可变 | **不可变**（构造后只读；属性袋是拷贝出来的新字典） | 剪贴板与模板库会**长期持有**这份数据。可变的话，"复制一份 → 改原件 → 粘贴"会粘出改过的东西，用户完全无法理解 |
| C-3 | 属性袋怎么搬 | **逐键搬，不走 setter** | 走 `SetProperty` 会把 `X`/`Width` 这些几何键重新解释一遍（`Width` 会取绝对值、非法值会被丢弃）。快照是"原样记下来"，解释留给物化那一步 |
| C-4 | 图层怎么记 | 记**层名**（`LayerName`），不记 `LayerId` | 跨画面粘贴时那个 Guid 在新画面里**必然不存在**，搬过去只会得到一批指向已删除图层的悬空图元——渲染上等同未分层，图层列表里却数不出来 |
| C-5 | 组怎么记 | 记**组槽位**（`GroupSlot`，int），不记 `GroupId` | 同理：`GroupId` 出了源画面就失效。快照要搬的是"**哪几个是一伙的**"这个语义，槽位号正好只表达这个。`NoGroupSlot = -1` = 未分组 |
| C-6 | 只拷组里一个成员怎么办 | 槽位**回落成 `NoGroupSlot`** | 否则粘出来会冒出一个"只有自己的组"，右键菜单跟着显示"取消组合"，用户只会困惑自己什么时候组合过 |
| C-7 | 快照要不要 `$type` | **不要**。序列化出来一个类型标记都不带 | 模板文件读盘就不需要类型白名单，也就没有那道"让人不敢随手放宽"的口子（`SolutionService` 上那一道是刻意留着的，不该为模板再开一张） |

### 3. 决策清单 —— 领域层：物化（`Materialize`）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| M-1 | `ElementId` | **一律重生成** | 活对象只有一个 Id。粘第二遍画面上就有两个同 Id 的图元，而 `FindElement` 按"保留靠前者"解析——第二个从此永远选不中、绑定也刷不到它 |
| M-2 | 名字 | 走 `page.MakeUniqueElementName`，就地查重（`阀门` → `阀门_2`） | 照搬原名会让画面上出现两个同名图元，属性面板标题跟着失去分辨力 |
| M-3 | `GroupId` | 用快照里的槽位**现造新 Guid**；同槽复用同一个新 Guid | 既不与画面里任何现存组串味，又保住"拷一整组、粘出来还是一整组"。`slot < 0` 或同槽成员 < 2 → `Guid.Empty` |
| M-4 | `LayerId` | **按层名回查**目标画面；查不到落默认图层 | 与"新拖出来的图元归默认层"同一条口径，而不是留一个指向已删除图层的悬空 Id |
| M-5 | `ZIndex` | 取目标画面现有**最大 Z**，再按快照里的相对 Z 序**依次 +1** | 直接照搬源 Z 序会让粘出来的东西生在底图下面，用户看到的是"粘了没反应" |
| M-6 | 偏移 | 由调用方给 `offsetX/offsetY`，物化只负责 `X + offset` | 物化**不认识鼠标**，也不该认识。拖模板时鼠标落点换算出来的偏移由视图层算好递进来 |
| M-7 | 撤销 | 整个物化包在一个 `ScadaChangeScope.Detached(...)` 里 | 一次粘贴 / 一次插入 = **一条**撤销位。靠 `ScadaChangeScope` 的嵌套自动合并，不需要在调用方记"这次要不要合并" |
| M-8 | 失败怎么办 | `page.TryAddElement` **成功才进**返回表 | 返回表就是"真的放下去了几件"。调用方拿 `Count > 0` 判成功，不需要另开一个布尔量 |
| M-9 | 空负载 / `null` 画面 | 返回**空表**、不产记录 | 放下是失败，不该崩，也不该在撤销栈里留一条"粘贴 0 个图元" |

### 4. 决策清单 —— 编辑器四条命令

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| V-1 | 复制筛不筛锁定 | **不筛**（走 `CollectPresent`） | "照这张锁住的底图再做一个"是现场真实诉求。被锁挡住只会逼用户先解锁、复制、再锁回去——而这三步里任何一步忘了，画面上就多出一张没锁的底图 |
| V-2 | 删除筛不筛锁定 | **筛**（走 `CollectEditable`） | 与 S10-c 同口径。两条漏斗的分界线就是"**读的不挡、写的不放**" |
| V-3 | 复制要不要产撤销位 | **不产** | 复制是读操作。`Ctrl+Z` 不该把"复制"撤掉——那会让用户以为撤销坏了 |
| V-4 | 粘完之后选中什么 | **整批选中**新粘出来的那些 | 粘完紧接着十有八九是拖到位置上，让他再框选一次是白费一步 |
| V-5 | 连续粘贴怎么摆 | **阶梯式错开**：`PasteStep = 12`，偏移 = 步长 × 次数（12 / 24 / 36…） | 不给偏移的话副本与原件像素级重合，用户看到的是"按了 Ctrl+V 没反应"，直到拖开上面那个才会发现下面还压着一个 |
| V-6 | 什么时候归零 | **重新复制一次就归零** | 不归零的话复制完再粘会莫名其妙跳到 (36,36) |
| V-7 | 再制怎么实现 | 单独一条路：抓快照 → 就地物化，**不写成"先复制再粘贴"** | 写成两步的话，用户在别的画面复制了一批东西，回来按一次 `Ctrl+D` 剪贴板就变成这几个图元了，待会儿切回去想粘贴时粘出来的是错的 |
| V-8 | 四条路的公共落点 | `PlacePayload(payload, offsetX, offsetY, label)` | 粘贴 / 再制 / 插模板 / 拖模板四条路都过它。`label` 就是撤销记录的操作名，四条路各自写人话 |
| V-9 | 三个命令的判据 | 复制 / 再制 / 存模板**共用 `CanCopySelection` 一个判据** | 三者的可用性完全同构（"有没有选中可读的东西"）。一个判据一处刷新，不会出现"亮着但点了没反应" |
| V-10 | 「粘贴」的判据 | **两半**：手上有货 + 当前有画面 | 两半各有一处刷新点（复制时刷"有货"、换画面时刷"有画面"）。缺一处就会留下一个灰错的按钮 |
| V-11 | `Ctrl+C/V/D` 挂哪一层 | `ScadaEditorView` 的 `UserControl.InputBindings`（与 `Ctrl+Z/Y` 同址） | 它们读的是"选中集合"、写的是当前画面，是**编辑器级**语义。刻意不挂窗口级——属性面板里还有一堆文本框，窗口级热键会把它们的文本撤销抢走 |
| V-12 | `Delete` / 方向键挂哪一层 | `ScadaCanvas.InputBindings` | 那是**画布级**语义（要有焦点在画布上才成立）。两个域分开挂，互不抢键 |

### 5. 决策清单 —— 模板库（`ScadaTemplateStore`）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| T-1 | 存哪儿 | 程序目录 `ScadaTemplates.json`（`DefaultFileName`） | 与 `ScadaUserStore`、`AppConfig.json` 同址同款。现场要备份/迁移，一个目录拷走 |
| T-2 | 文件形状 | 文件头（`Version` + `Templates[]`），记录类**私有嵌套** | 外面永远只拿到 `ScadaTemplateInfo` 视图（Id / 名字 / 件数 / 创建时间），不会有人图省事把记录直接绑到界面上。与 `ScadaUserStore.ScadaUserRecord` 同款 |
| T-3 | 写盘方式 | **原子替换**：先写 `.tmp`，再 `File.Replace` | 写到一半断电不会留下半个 JSON——模板是用户一个个攒的，损坏即全失 |
| T-4 | 重名 | **自动避让**（`三通阀` → `三通阀_2`） | 存模板不该因为撞名就失败（用户只是想再存一个差不多的），更不该悄悄覆盖掉原来那一个 |
| T-5 | 改名撞名 | **拒绝**并说明（"已有名为「三通阀_2」的模板"） | 改名不像存新模板那样可以避让：用户明确输入的名字被悄悄改成别的，才是真正糟糕的事 |
| T-6 | 改成同名（Trim 后相同） | 算成功但**空操作**：不写盘、不发通知 | 在改名框里按一下回车、没改字，是最常见的一次误操作，不该换来一次无意义的文件替换 |
| T-7 | 名字校验 | Trim 后为空 → "模板名不能为空"；超 32 字 → "模板名不能超过 32 个字符" | 各给一句人话。长度上限 `MaxNameLength = 32` 是常量，报错文案里带着它，改常量不会让文案撒谎 |
| T-8 | 空负载 | **拒收**："没有可保存的图元" | 存进去在工具箱里是一行点不动的项，用户会当成软件坏了 |
| T-9 | 校验的次序 | **全部排在写盘之前** | 被拒的那几次一个通知都不该发、清单也不该多一条 |
| T-10 | 文件版本比本版高 | 清单照常读得出来，但**三个写操作全拒**并说明"为什么存不进去" | 不说的话用户只会以为模板功能坏了，然后一遍遍重试；允许写则下次本版本一写盘，高版本的字段就永久丢了 |
| T-11 | 残缺记录 | **逐条跳过**，好的照常读进来，留一句"另有 N 条模板记录不可用，已跳过" | 留着它们不会多出什么，但在工具箱里是一行点不动的项 |
| T-12 | 文件读坏 | 按空清单处理，但**允许写入** | 否则用户再也存不进任何模板，而那个坏文件本来也读不出东西。与 `ScadaUserStore` 读坏回落出厂账号同一取舍 |
| T-13 | 首次运行 | 文件不存在 → 空清单、非只读、无错误、**不落盘** | 只是打开过一次软件不该留下一个空文件，与 `ScadaUserStore` 同口径 |
| T-14 | 清单排序 | 按名字（忽略大小写） | 现场没人记得住当初存的是 `Valve` 还是 `valve`。排序口径统一了，找东西就只靠眼睛扫一遍 |
| T-15 | 单例怎么给 | `ScadaTemplateStore.Shared` 静态属性 | 不改 `ScadaToolboxVM` 的构造签名（Prism 的 `AutoWireViewModel` 按无参构造造它） |
| T-16 | 变更怎么广播 | `Changed` 事件 | 存模板的入口在画布右键菜单里、看模板的地方在工具箱面板上，两处谁都不认识谁，中间只搁这一个通知 |

### 7. 口径沉淀

- **"搬运"和"引用"要分开看**：快照搬的是**内容**（类型键 + 几何 + 属性 + 组语义 + 层名），不搬**关系**（`ElementId` / `LayerId` / `GroupId` 这三个 Guid 一律在目标画面现造）。三个 Guid 里，前两个是"身份"，第三个是"关系"，而"关系"要退化成"槽位"这种只在本批快照内成立的相对量。
- **一次操作 = 一条撤销位这条不变量，只在一个函数里负责**：四条落地路径共用 `Materialize`，靠 `ScadaChangeScope.Detached` 的嵌套合并。这样"按一次 `Ctrl+Z` 只回退一个图元"在结构上就不可能发生。
- **读的不挡、写的不放**：`CollectPresent`（复制 / 再制 / 存模板 / 解锁）与 `CollectEditable`（删除 / 对齐 / 拖动）两条漏斗，分界线是"这次动作改不改模型"。
- **静态事件必须可逆挂摘**：`Attach` / `Detach` + 视图 `Loaded` / `Unloaded`，且 `Attach` 幂等。这条是 `ScadaTemplateStore.Changed` 引出来的，也是所有 `Shared` 单例的通用要求。
- **刷新点只有一个**：改名 / 删除成功后**不在调用点刷列表**，一律靠库广播 + 订阅方整份重读。"忘了刷"从缺陷降级成不可能。
- **写盘要原子、校验要在写之前、读坏要能继续用**：这三条是模板库（也是所有落盘服务）的通用底线。

## 四、已知边界

1. **剪贴板是进程内存，关软件即失**：这是 C-1 的取舍。跨会话复用走模板，不走剪贴板。与商用软件一致（也没有哪家的 `Ctrl+C` 能跨重启）。
2. **模板没有"另存为文件 / 从文件导入"**：本轮只做程序目录那一份库。现场要"把模板带给另一台机器"，暂时只能拷 `ScadaTemplates.json`。
3. **模板没有分组 / 分类 / 缩略图**：条目只有名字与件数。攒到几十份之后靠搜索框（U-14）顶着；真到需要分类时，模板记录里加一个 `Category` 字段即可，文件格式已经预留了 `Version`。
4. **模板不进撤销栈**：改名与删除都**不可撤销**（删除前问一次）。理由是模板库不是画面文档，把它接进 `ScadaEditHistory` 会让"撤销"这个概念跨两个存储域。**残余风险**：用户误删模板后找不回来——只能靠"删除前问一次"这一道。
5. **删模板不检查"有没有画面正在用"**：模板是快照、不是引用，画面上已经插进去的内容不受影响。这正是快照方案的好处，但也意味着"删掉模板"不会提示"有 N 处用过它"。
6. **一次粘贴只有一层偏移**：粘的是"一整批"，不是逐件错开。整批里图元之间的相对位置**严格保持**（M-6），只有整批相对原件偏移。
7. **`ElementId` 重生成 = 绑定与事件跟着走**：图元上的变量绑定 / 事件钩子是**随图元一起搬**的（它们是图元自己的字段）。这意味着粘出来的一批图元**绑的是同一个变量**——这是对的（"照它再做九个一样的"），但真机上要确认用户读得懂"粘出来的这批一起动"。
8. **跨画面粘贴按层名回查，同名层即落进去**：源画面与目标画面各有一个叫"设备层"但含义不同的层时，会**静默落进去**。没有更好的判据（`LayerId` 跨画面必然失效），商用软件同此。
9. **模板拖放的光标只有"可放 / 禁止"两态**：没有"拖到画布外"之类的细分反馈。`CanAccept`（U-13）保证"显可放就真放得下"。
10. **`Ctrl+C/V/D` 挂 `UserControl.InputBindings`**：焦点在编辑器内（画布、画面下拉）才生效。焦点在属性面板的文本框里时，`Ctrl+C` 走的是文本框自己的复制——这是刻意的（V-11），但真机上要确认用户在文本框里按 `Ctrl+C` 时不会以为"复制图元失败了"。
11. **真实热键 / 鼠标框选复制 / 模板拖放光标 无真机证据**：本机屏幕采样纯黑（`CopyFromScreen` 400×400 网格 `distinctColors=1`），截不了图；热键需真实键盘输入。断言证的是"命令执行后的数据通路"（`CopySelection` / `PasteClipboard` / `DuplicateSelection` / `PlacePayload` 都被直接调用），**不是"按键真的接到了命令上"**——`InputBindings` 那三行 XAML 本身没有被断言覆盖。见路线图 §七 收口核对表。
12. **SCADA 新文件仍未纳入版本控制**：`Scada/Models/ScadaElementSnapshot.cs`、`Scada/Models/ScadaClipboard.cs`、`VisionMaster/Services/ScadaTemplateStore.cs` 等仍是未跟踪状态。**提交需用户明确授权。**
