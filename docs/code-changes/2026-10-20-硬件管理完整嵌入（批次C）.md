## 1. 本批做了什么

批次 A/B 交付的是「统一入口 + 概览 + 打开既有弹窗」。批次 C 把相机 / 通讯 / 运动三个页面真正嵌入硬件管理外壳，并把权限与通讯保存语义收口到宿主。

### 1.1 生命周期契约

新增 `VisionMaster/Services/Hardware/IEmbeddedDialogPage.cs`：

- `OnEmbeddedOpened`：懒创建时一次，转调原 `OnDialogOpened`。
- `OnEmbeddedActivated` / `OnEmbeddedDeactivated`：切页可多次；只停/启本页 UI 定时器与点动看门狗，不退订全局事件、不 `CancelAll`。
- `OnEmbeddedClosed`：宿主关闭时恰好一次，转调原 `OnDialogClosed`。
- `CanCloseEmbedded`：关闭前确认。

三个域 VM 实现该接口；`IHardwareEditGateAware.ApplyEditGate` 由宿主把门禁结果推给页面。

### 1.2 宿主

`HardwareManagerViewModel` 重写为：

- 懒创建三个页面；`EnsurePage` 优先用 Prism AutoWire 的 `view.DataContext`，取不到再 `IContainerProvider.Resolve` 兜底。
- `EmbeddedMode.SetIsEmbedded(view, true)` 让子视图隐藏自己的标题栏/底部关闭或确定按钮。
- 切页：`OnEmbeddedDeactivated` → 目标页 `OnEmbeddedActivated`；概览页调用 `DeactivateAllPages`。
- 关闭：`CanCloseEmbedded` 全通过 → 通讯页脏时 `await SaveConfigAsync` → `OnEmbeddedClosed` → `RequestClose`。
- 运动急停放在宿主页头（三个页面均可查看、动作各自 gate；急停不随页面 gate 禁用），调用 `MotionBoardViewModel.Debug.EmergencyStopCommand`。
- 概览/健康/异常逻辑保持批次 A 的实现。

### 1.3 权限门禁

新增 `VisionMaster/Services/Hardware/IHardwareEditGate.cs`、`HardwareEditGate.cs`、`FlowRunState.cs`：

- 查看：所有角色。
- 运行操作（连接/断开/测试/点动/使能/回零）：工程师及以上。
- 配置修改（增删设备/改地址/参数/轴映射）：管理员，且 `AnyFlowRunning == false`。
- 运行锁走 `IWorkspaceManager.CurrentSolution.Flows` 现算，不用 `EditGate.IsRunLocked`（后者不覆盖单流程/HTTP 触发）。
- 宿主每 1 秒重算并推给页面；权限提示同时显示运行与配置两个原因。

页面侧：

- 相机：`添加相机`、内联添加表单、`删除相机`、采集参数区绑定 `IsConfigEditable`。
- 通讯：`添加设备`、`编辑`、`扫描组`、`删除` 绑定 `IsConfigEditable`；连接/测试/批量操作保留给运行时。
- 运动：`卡设置/点位列表` 两个配置页签绑定 `IsConfigEditable`（电子凸轮 UI 自 2026-10-21 起不开放）；左栏`添加`按钮绑定 `IsConfigEditable`；手动调试页的操作区绑 `DataContext.IsRuntimeOperable`（操作员可查看页签与状态，动作按钮禁用）。
- 子视图标题栏、相机底栏`关闭`、通讯底栏`确定`在 `EmbeddedMode.IsEmbedded=true` 时折叠；宿主 footer 接管关闭。

### 1.4 通讯保存

`CommunicationSettingsViewModel` 新增 `IsCommunicationDirty`：

- 新增/删除/编辑参数/扫描组确定后置脏；"复制扫描组到其它连接"立即提交，由编辑器 `MarkDirtyKey` 主动上报。
- 宿主关闭时只在通讯页打开且脏时 `await SaveConfigAsync`，成功后按 `DirtyVersion` 清理保存前版本；失败提示并保持宿主不关；保存期间的新编辑保持脏并提示再关一次。
- 未打开通讯页关闭宿主不写 `communications.json`。

### 1.5 菜单深链

`ShellViewModel.ShowHardwareManager(page, tab)`：

- `HardwareSettings` → 概览。
- `CameraSettings` → `page=camera`。
- `CommSettings` / `IoSettings` → `page=comm`。
- `MotionBoard` / `ReturnToZero` → `page=motion`，`ReturnToZero` 带 `tab=debug`。
- 三个独立弹窗仍保留注册，但 UI 不再直接打开；避免旁路权限与保存语义。
- **2026-10-21 补充**：系统菜单已删除「相机设置 / 运动板卡 / 通讯设置」三项，只保留「硬件管理」；顶栏「通讯设置」快捷键改为「硬件管理」。枚举值与深链分支保留，供旧布局/脚本兼容。

## 3. 已知边界

- 子视图的 DataContext 优先用 AutoWire；若 AutoWire 失败才显式 Resolve。正常路径下不会造第二份 VM；极端情况下 AutoWire 生成的未使用实例会被 GC。
- 只读改为“可查看、动作禁用”：宿主不再整页 `IsEnabled=false`；相机动作条、通讯操作列/批量、运动调试页分别 gate，配置区由 `IsConfigEditable` 拦住。通讯/运动的自定义主按钮在禁用时仍偏蓝，页头权限提示是主要说明。
- 独立弹窗路径仍保留注册，供旧布局/脚本兼容；UI 已全部深链到宿主。
- 运动板卡仍使用 `MotionBoardTheme` 的 Mb 令牌；与 Dialog 令牌的完全统一留到后续视觉批次。
- 方案级“已保存/未保存”标记仍未做（全仓无 `SolutionModel.IsDirty`）；宿主只显示“配置随方案保存”。
- 登录忙碌态、上次登录/IP、记住账号仍未做。
