## 已做

1. **防抖（250 / 300）**：`OperationsLogViewModel` 加 `FilterDebounce`（默认 250ms）与 `KeywordDebounce`（默认 300ms）；分类 / 操作者 / 时间走前者、搜索框走后者；翻页 / 刷新 / 清空筛选保持**立即**查询（离散动作不防抖）。防抖用 `DispatcherTimer`（UI 线程），多次改动只留最后一次；`FlushPendingReload()` 给程序化 / 探针场景立即触发。
2. **异步查询 + 加载态骨架（≥300ms 门限）**：
   - `StartReload()` 清空结果 → `Task.Run` 后台查 SQLite（`QueryActors` + `QueryPage` 一起）→ `Dispatcher.BeginInvoke` 回 UI 线程应用；`_loadVersion` 版本号丢弃过期结果（连续改筛选不串行回写）。
   - 骨架门限：只有查询超过 `SkeletonDelay`（默认 300ms）还没回来才 `IsLoading = true`；**快查询不闪**（设计稿 §5 的"避免闪烁"）。骨架 = 三条灰条 + 「正在读取操作记录…」；`IsEmpty` 在加载中不成立（骨架优先于空态）。
3. **打开弹窗焦点 / 选中第一行**：视图 `Loaded` 后（或首屏异步结果到达时）把选中落到 `Rows[0]` 并 `Focus()` + `ScrollIntoView`；每个弹窗实例只做一次。默认态出图现在天然是"首行选中 + 明细"（与设计稿 §10 的 design-normal 同态）。
4. **探针（+4 条断言，364/0）**：慢查询 → `IsLoading = true`（用 SQLite 排他锁造慢查询，见下）；锁释放 → 加载态退出且数据到位；快查询 → `IsLoading = false`（门限反向）；打开弹窗后 `SelectedRow == Rows[0]`。四态出图：`artifacts\render\<yyyyMMdd>\operations-log\wpf-operations-log{,-empty,-denied,-loading}.png`。

## 踩过的坑

- **WAL 下读写不互斥**：想验证"慢查询才显示骨架"时，普通写锁（事务写）**挡不住读**；必须先把夹具库 `PRAGMA journal_mode=DELETE;`（切回 rollback journal，持久化），再由外部连接 `BEGIN EXCLUSIVE;` 持排他锁，`SELECT` 才会按 `DefaultTimeout` 等待——这样才造得出确定性的慢查询。
- **VM 构造时就发起首次查询**：`SkeletonDelay` 等可调参数在对象初始化器里赋值时，首次查询已经用默认值启动了；探针要重发一次（`RefreshCommand.Execute()`）才吃到新门限。
- 异步回写必须带**版本号**（`_loadVersion`）：防抖 + 连续改筛选会让多个查询在途，旧结果直接丢弃，否则表格会"跳回上一次筛选"。
- 视图的 `Loaded` 早于异步结果：焦点落到第一行不能只写 `Loaded`，还要在 `HasRows` / `IsLoading` 变化时再试一次（一次性标志防重复）。
