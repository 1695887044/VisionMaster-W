# 图像预处理补齐顶帽/黑帽与边缘检测算子（2026-10-19）

## 0. 结论

`Plugin.PreProcessing` 在原有 21 个算子之外，补齐了**单图进 / 单图出**的四类经典算子：

| Key | 显示名 | 分组 | Order | 参数 |
| --- | --- | --- | --- | --- |
| `gray_top_hat` | 灰度顶帽 | 灰度形态学 | 115 | 模板宽度 / 高度 |
| `gray_black_hat` | 灰度黑帽 | 灰度形态学 | 116 | 模板宽度 / 高度 |
| `sobel_edge` | Sobel 边缘 | 边缘检测 | 180 | 模板尺寸（3~11 奇数）/ 滤波类型 |
| `laplace_edge` | Laplace 边缘 | 边缘检测 | 181 | 模板尺寸（3~11 奇数）/ 邻域 |

算子总数 21 → **25**，分组 6 → **7**（新增「边缘检测」）。新增断言 `FlowCanvasChecks/PreProcessingChecks.cs`，随常规 gate 运行。

## 1. 背景

用户问"传统算子补全是什么、预处理模块里没有吗"。盘点后确认预处理模块已有 21 个 GUI 算子（色彩/几何/滤波/灰度形态学/图像增强/二值化），主干完整；缺的是几类常用算子：

- **顶帽 / 黑帽**：只有灰度开/闭，没有"把被开/闭清掉的结构单独拿出来"的残差算子；
- **边缘检测**：只有 `GeometryFinder` 内部用 Canny，没有可拖拽的 Sobel/Laplace 算子；
- 图像算术/差分、图像统计、区域运算、通道合并：因为**输出不是 HImage 或需要第二张图**，不适合硬塞进预处理的单图链，本批不做（见 §5）。

`ImageScript` 能写任意 HALCON 算子，但它是给会写脚本的人用的逃生口；现场调试需要带参数面板、帮助手册、断言的 GUI 算子。

### 2.2 服务层

`Plugins/Plugin.PreProcessing/Services/PreprocessHService.cs`：

- `GrayTopHat`：`GrayOpeningRect` → `SubImage(原图, 开运算)`；
- `GrayBlackHat`：`GrayClosingRect` → `SubImage(闭运算, 原图)`；
- `SubImage`：`sub_image(mult=1, add=0)`，byte 负值由 HALCON 截到 0（顶帽/黑帽本身非负）；
- `SobelAmp`：`sobel_amp(filterType, maskSize)`；
- `Laplace`：`laplace("absolute", maskSize, filterMask)`。

**为什么顶帽/黑帽用"开/闭 + 减"而不是 `gray_tophat` / `gray_bothat`**：后者要传一个结构化元素区域（SE），SE 的参考点/形状口径与 `Rect` 族不一致；复用已经实测过的 `GrayOpeningRect` / `GrayClosingRect`，语义等价，且与四个灰度形态学算子的"矩形模板 W×H"参数完全对齐。

## 3. 关键口径

- **顶帽 = 原图 − 开运算**：输出亮残差（比模板小的亮斑/毛刺/亮点），背景为 0；
- **黑帽 = 闭运算 − 原图**：输出暗残差（比模板小的暗点/裂纹/黑斑），背景为 0；
- 两者输出的是**特征图**，不是"洗干净的原图"；典型接法是直接接二值化/Blob，不要再做亮度/对比度调整；
- 模板口径与开/闭相反：**要大于要检的缺陷、小于背景变化尺度**；模板小于缺陷时残差 ≈0，模板过大时背景梯度会产生光晕；
- Sobel/Laplace 的模板尺寸统一收敛为 **3~11 的奇数**（偶数 +1、超界夹取），避免把 HALCON 不接受的尺寸传下去；
- 边缘算子对彩色输入先 `EnsureMono`（`rgb1_to_gray`），输出单通道；临时灰度图用 `ReferenceEquals(mono, input)` 判断是否该释放，避免误释放上游图；
- 枚举存盘沿用 `OperatorEnums.cs` 的"数值即格式"约定：新枚举成员只许追加，不许插删/改值。

## 5. 未做 / 边界

- **图像算术/差分**：需要第二张参考图，预处理只有一个 `SrcImage` 输入；建议单独做 `Plugin.ImageArithmetic`（参考图管理/路径/对齐是独立问题），不要硬塞进单图链。
- **图像统计**：输出是数值不是 `HImage`，硬塞会破坏"算子链只传图"的契约；建议单独做 `Plugin.ImageStats`。
- **区域运算**：输出是 `HRegion`，建议单独做 `Plugin.RegionOps` 或扩展 `CreateRoi`。
- **通道合并**：真正的"合并"需要三张单通道输入，单输入链做不了；本批不做。
- **LoG（Laplace of Gauss）/ 双边滤波**：可作为下一批边缘/滤波算子，本批只补最常用的 Sobel/Laplace。
- **历史 41 项离线断言**：验证的是链的复制/粘贴/导出/降级路径，仍未迁入 `FlowCanvasChecks`；本批新增的 36 条只覆盖新算子，不替代它们。
