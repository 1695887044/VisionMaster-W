### 1.3 范围决策（三轮 `AskUserQuestion`）

| 轮次 | 问题 | 用户选择 |

### 1.4 明确不做（本轮排除）

- **C 组全部**（C1~C5）：都是「重构 / 打磨」性质，不解决实际问题，单独排期。
- **B2**（合并 Tab）：会动交互结构，用户未选。
- **B4 / B5 / B7**：锦上添花。
- **任务线 B（网络推送测试案例）**：用户已明确「这个功能先不考虑了」，**不得擅自恢复**。
  其硬障碍已查清：`ImageHub` 按**流程名**分槽，但 `IStepConfigData` 无流程名成员、
  `StepModel` 无 Flow 引用 → 配置态插件视图拿不到「本流程名」，无法构造推送地址。

### 1.5 体检过程中被推翻的三条自我误判（避免写错报告）

| 初判 | 复核结论 |
| --- | --- |
| `BrowseFile` 用 `.Value` 而别处用 `TypedValue`，可能污染链接值 | 读 `InputPort.cs` 确认 `Value`/`TypedValue` **读写同一个 `_manualValue`** → **不是 bug** |
| 「刷新预览」按钮点了不会重扫目录 | `RefreshFolderFiles` **每次都真调 `ListFolderImages`**；只有运行期 `AcquireFromFolder` 走 `_cachedFiles` → **不是 bug** |
| 预览区缺滚轮缩放 | `HalconBase` 已有 `HZoomContent = WheelForwardZoomsIn` → 改为「缺『适应窗口』按钮」（B7，未入选） |

### 1.6 关键设计原则

1. **状态消息与级别必须成对更新** → 引入唯一写入口 `SetStatus(message, level)`，
   禁止各处直接赋 `StatusMessage`。否则典型症状是「失败变红之后再成功，颜色还停在红」。
2. **插件只管语义，视图只管颜色** → `StatusLevel` 是纯语义枚举（Info/Warning/Error），
   具体色值（绿/橙/红）写在 XAML 的 `DataTrigger` 里，插件不引用任何 `Brush`。
3. **载图是显式动作** → `ValueChanged` 事件里**只做校验、不顺手载图**，
   避免与「浏览 / 刷新 / 翻页」的显式调用重复读盘。
4. **异步读图必须带身份与生命周期守卫** → 轮次号 `_previewLoadId` 丢弃过期结果，
   `_disposed` 拒绝往已关闭的对话框写图。

### 2.1 `Plugins\Plugin.ImageAcquisition\Enum.cs`

**新增** `StatusLevel` 枚举（追加在 `AcquisitionMode` 之后、`#endregion` 之前）：

```csharp
/// <summary>
/// 状态消息级别：驱动配置界面信息栏的颜色（绿 / 橙 / 红）。
/// 只描述"这条消息有多严重"，不参与任何流程逻辑。
/// </summary>
public enum StatusLevel
{
    /// <summary>正常信息（绿）：操作成功、路径有效等</summary>
    Info,

    /// <summary>警告（橙）：还能继续，但需要用户注意（如尚未选择路径）</summary>
    Warning,

    /// <summary>错误（红）：当前配置不可用（如路径不存在、读图失败）</summary>
    Error
}
```

> 语法提示：`StatusLevel.Info` 中 `StatusLevel` 按**类型**解析（属性名与类型名同名时，
> 编译器优先当类型用），`Info` 是它的静态成员，合法。

核心片段：

```csharp
// A1：基类 AutoDisposeRoundOutputs 只处理 IDisposable 端口值（HImage），
// int 端口不管 → 索引/总数必须手动归零，否则本轮失败时下游会读到上一轮残留值
CurrentFileIndex.Value = 0;
TotalFiles.Value = 0;
```

```csharp
// A3：异步载图的守卫逻辑
var loadId = ++_previewLoadId;      // 先占号
if (!File.Exists(path)) { ... return; }   // 快检留在 UI 线程，立即反馈
Task.Run(() => {
    HImage loaded = null; string error = null;
    try { loaded = new HImage(); loaded.ReadImage(path); }
    catch (Exception ex) { loaded?.Dispose(); loaded = null; error = ex.Message; }

    PostToUI(() => {
        if (loadId != _previewLoadId || _disposed) { loaded?.Dispose(); return; }
        if (loaded == null) { PreviewImage = null; SetStatus($"加载预览失败: {error}", StatusLevel.Error); return; }
        PreviewImage = loaded;    // setter 负责释放被换下的旧图
        SetStatus($"预览: {Path.GetFileName(path)}", StatusLevel.Info);
    });
});
```

```csharp
// A4：唯一写入口，消息与级别成对更新
private void SetStatus(string message, StatusLevel level = StatusLevel.Info)
{
    StatusMessage = message;
    StatusLevel = level;
}
```

## 4. 已知边界

1. **运行期目录缓存不失效**：`AcquireFromFolder` 走 `_cachedFiles` 缓存，只在
   「文件夹路径或扩展名变化」时失效 → 运行中往文件夹新增文件，同一插件实例看不见。
   配置态 `RefreshFolderFiles` 每次都真扫目录，**不受影响**。（即清单里的 C3，本轮未处理）
2. **翻页按钮不做 `CanExecute` 门控**：到头再按无反应（由 `RefreshFolderFiles` 内部
   `Clamp` 兜住），不会越界，但按钮不会变灰。
3. **链接状态下不做路径校验**：`CheckPath` 在 `port.LinkedSource != null` 时直接放行
   → 变量链接的路径要运行时才由上游产出，配置态无从校验。
4. **`File.Exists` 仍在 UI 线程**：`LoadPreview` 的存在性检查留在 UI 线程做（为了立即反馈），
   网络盘上该次调用仍可能短暂阻塞 UI；**读图本体已异步**，大图/慢盘的主要开销已移出。
5. **`Initialize` 可能先清一次预览**：`ClearPreview` 由 `Mode` setter 触发，
   `Initialize` 中 `base.Initialize(stepData)` 恢复配置时若 `Mode` 发生变化会先清一次
   （无害，随后 `Initialize` 会重新载入）。
6. **解决方案级构建在 VisionMaster 运行期间报错**：见第 3 节，环境性、与本次改动无关。
7. **任务线 B（网络推送测试案例）保持搁置**：用户已说「这个功能先不考虑了」，
   硬障碍为「配置态拿不到本流程名」，未改任何相关代码。
