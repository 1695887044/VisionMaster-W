# 结果上报插件优化全量版（2026-09-19）

> 承接 MVP（见 `2026-09-19-结果上报插件.md`）。本轮为用户四方向全选 + "全量一次推进"：
> 小组合拳、安全小包、对接能力包、断网续传，一次性落地。

## 需求与决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 补传 vs 实时优先级 | **实时优先** | 检测节拍不能被历史欠账拖累；MES 端靠 X-Upload-Id 幂等去重，补传晚点没关系 |
| 请求头安全 | **只打码不加密** | 界面 PasswordBox 打码显示，持久化仍明文随 .vms 保存（内网场景，DPAPI 跨机迁移反成坑） |
| 批量上报 | **砍掉** | MES 协议千家千面，等真对接协议再定制，避免臆造抽象 |
| 响应输出端口 | MVP 已存在（o1 核实） | 无需重复开发 |

新增能力清单：
1. **小组合拳**：卡片④"最近上报日志"回看 50 条（环形底账，与 TakeLogs 消费型转交双通道）
2. **安全小包**：钉钉加签（可选密钥）、跳过 HTTPS 证书校验（默认关+红字⚠中间人风险）、请求头值打码
3. **对接能力包**：OnlyNG 判定升级比对（double→bool→字符串三段式）、时间戳格式模板、UTC 开关
4. **断网续传**：JSONL spool 落盘（10 万行上限丢最老 10%）、启动即扫 + 30s 空闲扫描 + 实时件清空顺手扫、毒记录 50 次放弃、`X-Upload-Id`(GUID) 幂等头贯穿首发/重试/补传

## 冒烟验证（临时工程 ResultUploadSmoke）

独立控制台项目直接 Compile Include 插件三个纯 BCL 源文件（UploadQueue/HttpPayloadBuilder/UploadFieldDef + ObservableObject 桩），
假 MES 用 TcpListener 手写 HTTP（HttpListener 需 URLACL 管理员权限，TcpListener 无门槛）。**25 项断言全 PASS**：

1. 实时件：X-Upload-Id 注入、自定义头透传、body 逐字节一致
2. 钉钉加签：URL 带 timestamp&sign、sign 与独立复算 HMAC-SHA256("ts\nsecret") 一致
3. **spool 往返**：死端口→落盘（账本含原 Id/报文）→原端口拉起假 MES→空闲触发补传→沿用原 UploadId、body 一致→删行
4. 时间戳：字段表/占位符走模板+UTC；RawJson `{#num}` 数值原样 + 中文不转义
5. 日志：SnapshotRecentLogs 与 TakeLogs 双通道语义（消费型 vs 底账）

冒烟首轮抓到 2 个真 bug（UTC 对值池 DateTime 无效、RawJson 中文转义），修复后全绿。

## 已知边界

1. **spool 是单文件账本**：多机器同目录不共享（设计如此——每台机只补传自己欠的）；账本损坏整文件读失败时只记 ERROR 不自动重建，需人工删 `ResultUploadSpool/spool.jsonl`
2. **"启动即扫"的前提是消费线程已拉起**：线程由首次 `Enqueue`（异步模式上报）懒启动，起来先扫一轮 spool。若方案里所有步骤都配成同步模式，线程永不启动，历史欠账不会被补——同步模式本身就阻塞节拍、失败当场可见，落盘场景极少，可接受
3. **SkipCertValidation 只对 https 有意义**，http URL 勾选无效果也无害
4. **加签算法是钉钉规范**（timestamp\nsecret → HMAC-SHA256 → Base64 → UrlEncode）；企微/飞书签名方案不同，未做（企微 webhook 本身不强制加签）
5. **幂等去重最终靠 MES 端**：插件只保证"同一件永远带同一个 X-Upload-Id"，服务器不认这个头则可能记重
6. "时间戳"占位符旧版固定 `yyyy-MM-dd HH:mm:ss`（无毫秒），本轮与"时间"合并走模板——依赖旧行为的方案需在卡片②把格式改回 `yyyy-MM-dd HH:mm:ss`
