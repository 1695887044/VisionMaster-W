## 一、收敛：三份副本 → 一份实现 + 两个空别名

| 收敛前 | 收敛后 |
| --- | --- |
| `Shard\Core.Controls\NumberValidationRule.cs`（实现） | **唯一实现**（Matching 用的就是它，`cv:` 前缀） |
| `Plugins\Plugin.BlobDetect\NumberValidationRule.cs`（逐字复制的实现） | **空类型别名**：`public class NumberValidationRule : Core.Controls.NumberValidationRule { }` |
| `Plugins\Plugin.CaliperMeasure\NumberValidationRule.cs`（逐字复制的实现） | 同上 |

**为什么用"别名"而不是"删掉 + 改 29 处 XAML"**：BlobDetect 视图有 **19 处**、CaliperMeasure 有 **10 处**写的是 `<local:NumberValidationRule …/>`（CaliperMeasure 那 11 个数值框里，`Value` 那个本来就没有规则）。留着别名，视图一个字都不用动，而"实现只有一份"这件事由基类保证 —— 收益一样、churn 小一个数量级。两个别名文件里都写清了来龙去脉（为什么留别名、为什么不能再复制实现）。

**收敛的直接动因**：今天上午的"全字段变红"事故，本质是**同一段逻辑有三份**：把绑定目标从 `Text` 换成 `Value` 之后，规则必须改成"字符串与已转换数值都认"，我先修了 BlobDetect / CaliperMeasure 两份插件副本，**漏了 Core.Controls 那份**（Matching 用的），于是 Matching 迁完必然重演。三份变一份之后，这类改法只需动一个文件。

## 二、文档：`docs\新插件端口速查.md` 新增 `§8A 数值字段（NumericBox）标准做法`

- 三条用法：① 自带视图直接用（区间抄自 `[RangeValidation]` / 规则里的 Min/Max；整数加 `DecimalPlaces="0"`；只读用 `IsReadOnly`）② 交给属性网格（`NumericGenerator` 自动接管，别在视图里另赌一个控件）③ 样式可复用；
- 三个真踩过的坑：**`PluginNumericBox` 的 TargetType 是 TextBox 基类 → 同一份样式可直接套 NumericBox**；**绑定目标换成 `Value` 后规则必须认数值**（否则整片标红且写不回模型）；**别只看样式名判断是不是数值**（PoseTransform 那处是图片路径、Calibration 那处是设备序列号）；
- 契约：实现只有 `Core.Controls` 一份，插件里的同名类应当是空别名；自管校验的表单用 `RevertOnInvalid="False"`；两条非法反馈接到同一个红色；
- 第 9 节自查清单加一条：数值参数用 `ui:NumericBox`（见 §8A）。
