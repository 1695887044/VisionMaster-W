# 2026-09-19 结果上报插件（Plugin.ResultUpload：MES 上报 + IM 通知）

## 一、需求与决策

### 需求背景
流程跑完，结果只落在 CSV 账本里——账本不会喊人。产线的两类真实诉求：
1. **MES 要数据**：每件产品的判定结果要逐件 POST 给 MES / 客户服务器（字段名、类型往往是对齐死的）；
2. **人要被通知**：NG 了要在钉钉/企业微信群冒一条消息，值班的人手机能收到。

用户拍板：**「把 1 和 2 一起做，都当作结果上传」**——一个插件覆盖，不拆两个。

### 方案共识（施工图依据）
1. **一个插件、四种报文预设、一套界面**（`PayloadKind` 枚举）：
   - `FieldTable`：MES 字段表——字段表本身就是 JSON 载荷（类型保真）；
   - `DingTalkText` / `WeComText`：钉钉/企业微信机器人文本（两家报文同构，共用一段组包代码）；
   - `RawJson`：原始 JSON 模板，对接奇葩协议的兜底。
2. **零第三方依赖**：`HttpClient` + `System.Text.Json` 都是 .NET 自带，不学 ExcelExport 往 `Modules\` 塞私有包。
3. **只做 POST**，不做 GET/PUT；MVP 不做断网续传（本地暂存重传）、不做钉钉加签。
4. **异步队列默认**：组包和发送解耦，网络再慢也拖不垮流程节拍；重试 3 次、退避封顶 3s。
5. **值池统一**：字段表 / 占位符模板共用同一张 `UploadFieldDef` 表——`Source=Port` 的字段长动态端口，
   `Variable` 从运行期变量池取，`BuiltIn` 给时间戳/步骤名。界面只有一套心智。

### 关键设计点（为什么这么写）
- **类型保真**：`ToJsonNode` 按真实类型分派（double→数值、bool→布尔、其余→字符串）。
  MES 校验 `"12.3"` 字符串会打回，`12.3` 数值才收——这不是洁癖，是对接能不能过的问题。
- **占位符双语法**：模板里 `{名}` = 转义字符串注入；`{#名}` = 原样注入（想自己控制引号时用）；
  找不到的字段**原样保留**（让你一眼看出哪个字段名写错了）。
- **HTTP 纪律**：HttpClient 进程级单例（`PooledConnectionLifetime=10min`，防连接池耗尽 + DNS 生效）；
  总超时 `InfiniteTimeSpan`，单次超时用每请求 CTS（全局单例不能设 Timeout，否则永远生效）；
  退避 `Math.Min(500ms*(attempt-1), 3000ms)`——封顶是防第 3 次重试等出天文数字。
- **业务成功判定**：HTTP 2xx **且**响应体命中 `SuccessKeyword`（钉钉回 `errcode:0`、企微回 `errcode:0`，
  MES 各有各的说法）；未配置关键词则 2xx 即成功。
- **四种预设共用一条异步链路**：`SendTiming` 决定"要不要发"（每次/仅NG/触发端口），
  `PayloadKind` 决定"发什么"，队列只管"什么时候发出去"——三件事互不纠缠。

### 落地过程中踩到并修正的坑（冒烟真发 HTTP 才暴露）
1. **中文被转义成 `\u4EF6`**：`JsonNode.ToJsonString()` 默认 encoder 把所有非 ASCII 转成 `\uXXXX`。
   钉钉/企微收到的 content 一片乱码看不懂；很多 MES 还按响应原文匹配。
   **修法**：`JsonSerializerOptions { Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping }`，
   两处 `ToJsonString(JsonOpts)`。（UnsafeRelaxed 只是"不转义非 ASCII 与 HTML 敏感字符"，
   字符串内容照样合法转义，不是不安全。）
2. **内置步骤名上报出去是"未赋值"**：`InstanceName` 是引擎编译流程时才注入的，
   配置期/部分路径下仍是默认值。**修法**：内置字段改用 `EffectiveStepName`
   （运行期用 `InstanceName`，退回 `StepData.StepName`）——与 ExcelExport/DataRecord 同一套契约。
3. **XAML MC3042**：`ConverterParameter=DingTalkText,WeComText` 里的逗号被当标记扩展参数分隔符，
   编译报错。**修法**：单引号包裹 `ConverterParameter='DingTalkText,WeComText'`。

## 三、验证结果

1. **编译**：Debug + Release 均 **0 错误**（警告全部来自宿主 UI 存量工程的 nullable 提示，非本次代码）。
2. **冒烟**（`%TEMP%` 临时工程反射调 internal 类型 + 本地 TcpListener 回显端点 18081，不污染仓库）——**21/21 全过**：
   - **①MES 字段表类型保真**：字符串带引号、数值/布尔不带引号、内置字段齐——
     `{"sn":"SN001","result":"OK","value1":12.3,"pass":true,"time":"2026-09-19 10:30:00.000","step":"上报1"}` ✔
   - **②③钉钉/企微同构**：`{"msgtype":"text","text":{"content":"件SN001判定OK"}}`，中文原样（不转义）✔
   - **④原始 JSON 双语法**：`{名}` 转义注入、`{#名}` 原样注入、未知名保留原样 ✔
   - **⑤同步 SendNow 真发**：本地回显端点收 POST，HTTP 200（169ms），请求头/请求体字节级比对一致 ✔
   - **⑥异步 Enqueue**：入队微秒级返回（不阻塞调用线程）+ 完成回调正常触发 ✔
   - **⑦死端口重试退避**：3 次重试全失败如预期，总耗时 7648ms ≈ 0.5s+1s 退避 + 3 次连接拒绝，节奏符合 `min(500*(n-1),3000)` ✔
3. 冒烟暴露并修复 2 个真缺陷（中文转义 + 内置步骤名），复测通过。

## 四、已知边界

- **宿主 UI 实跑未验证**：需在 VisionMaster 里拖一个"结果上报"步骤、在面板里点「立即测试」对着真实 MES/机器人 webhook 实测一次。
- **只做 POST**：GET/PUT、SOAP、加签（钉钉 sign）都不在 MVP 内；钉钉加签是纯 HMAC-SHA256 拼串，后续要做也简单。
- **断网续传没有**：失败的重试 3 次后即放弃（日志可查），本地不暂存。MES 逐件上报若不允许丢，需要后续加本地落盘重传。
- **仅 NG 时机依赖判定字段值比对**：判定字段若是数值类型，NG 判定值按字符串比对（如 `0` vs `0.0` 不相等）——建议判定字段用字符串/布尔源。
- **PayloadKind 切换时模板内容不迁移**：各预设的配置项（字段表/内容模板/JSON 模板）各自独立，切预设后要重新填。
- **字段的类型保真依赖上游供值类型**：`InputPort<object>` 收到什么就是什么；若上游步骤把数值装箱成了字符串，出来就是字符串。
- **自定义请求头值不脱敏**：Authorization 的值会明文存进 .vms 方案文件——密码类头要注意方案文件的分发范围。
