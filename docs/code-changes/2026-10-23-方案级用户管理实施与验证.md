### 2.10a 真机验收（2026-10-25 15:46–16:04，运行态权限链路）

这一轮补上了 2.10 里“未验”的三项，并在此过程中**发现并修掉一个真实缺口**。

**缺口：运行态未授权点击不会弹登录。** `ScadaRuntime.AccessLoginPrompt` 全仓无任何赋值，
`AxisPanelElement` 又把无权限的按钮直接置灰——两个原因叠加，B3 定的
“运行态点无权按钮 → 弹登录 → 登录后继续原操作”在真机上根本走不到。

修复分三处：

- `ScadaRuntime.TryAuthorize(key, out reason)`：缺权限时给宿主一次登录机会，
  登录后按最新权限重判一次；只重试一次，不递归。`RaiseElementEvent` 改走它。
- `ScadaRuntimeContext.AccessLoginPrompt` + `TryAuthorize`：图元（轴面板等）拿到同一条链路；
  `ScadaRuntimeHost` 构造新增 `accessLoginPrompt` 参数并透传给会话与上下文。
- `App.xaml.cs` 的 `ShowRuntimeAccessLoginPrompt`：解析 `IDialogService` 弹 `ScadaLoginView`，
  用 `Dispatcher.PushFrame` 等弹窗关闭（Prism 的 `ShowDialog` 是异步回调，不同步等会拿着
  未登录的会话立刻重判失败），关窗后按最新权限重判。

**轴面板按钮不再因缺权限置灰**：新增只读 `CanAttemptOperate/CanAttemptStop/CanAttemptJog`
（= 有出口 + 有选中轴 [+ 轴没在动]），模板改绑这三个；权限在命令出口判，点击后走弹登录。
`TryExecuteCommand(..., interactive: false)` 供松手补发的 `JogStop` 用——安全收手不弹登录。

## 五、踩过的坑

1. **计划测试里的 `TryUpdateGroup` 少写 `name` 参数**：`TryUpdateGroup(id, name, permissions, out error)` 四个参数；只传三个会把数组绑到 name、`out` 绑到 permissions，编译报 `CS7036`/`CS0019`。
2. **`GroupChanged` 无参数导致“改别的组也刷当前会话”**：协调器不能无条件 `HandleGroupChanged(current)`；先比较当前组权限快照，只有变了才触发边界。`[SL-d4]` 就是这条的反证。
3. **测试显式调 `HandleGroupChanged` 与 store 自动订阅重复**：`TryUpdateGroup` 已触发 `GroupChanged`，测试再手调一次会让 `SessionBoundaryChanged`/`RevokeGroup` 计 2 次。测试应只依赖自动订阅，或只用手调不触发 store 事件。
4. **`TryAddGroup("G-temp", ...)` 的 `G-temp` 是“组名”不是 Id**：`CreateGroupIdLocked` 会生成 `G-G-temp` 之类；测试要按 `Groups.First(g => g.Name == "G-temp").Id` 取真实 Id。
5. **`DefaultScadaAccessPolicy` 从“操作员放行”改成“未登录无权限”**：旧轴面板断言不传策略会全红；夹具要显式给管理员策略，权限拒绝用例再换工程师策略 + 显式 `RequiredPermission`。
6. **`DataLinkCount` 与“数据线关闭时也建 VM”冲突**：VM 现在总建、靠 `IsScopeHidden` 隐藏；计数必须算“可见线”，否则默认态永远 >0。测试里 `Links.Single(!IsOrderLink)` 也要加 `!IsScopeHidden`。
7. **并行改动会反复锁 `bin`/改 XAML**：`VisionMaster.exe` 运行会锁 `Modules`/`bin`；构建失败先看进程与文件 mtime，不要把它当代码错误。临时可用 `-p:OutputPath=artifacts\tmp\...` 编译验证，但最终验收必须回到默认产物。
