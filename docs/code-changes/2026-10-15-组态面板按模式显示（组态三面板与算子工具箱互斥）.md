## 四、关键技术决策（为什么）

### 1. 判据必须用 `LayoutDocument.IsSelected`，不许用 `IsPanelActive`（本轮核心）

`LayoutContent.IsActive` 在 AvalonDock 里表示"**整个 DockingManager 的当前活动内容**"——用户点一下右侧的「属性」或「图层」面板，文档的 `IsActive` 就被抢走，判据翻转成"退出组态" → **随即隐藏用户刚点的那个面板 = 自毁循环**。`LayoutDocument.IsSelected` 只随"文档区的选中标签"变化，点停靠面板不动它（判据实现 `LayoutHelper.cs:370-383`，注释即本节）。

> **评审独立复核（结论 pass 代码侧）**：反编译 `Dirkster.AvalonDock 4.74.1` 逐路径核实——`IsActive=true → IsSelected=true` 是**单向**联动、`IsActive=false` **不清** `IsSelected`；点停靠面板只设该 anchorable 自己、不碰文档窗格的 `SelectedContentIndex`。据此确认自毁循环已排除、触发点齐全、转发重载与改动前逐字等价。

### 2. 收敛动作必须"先 Show 目标、再 Hide 对方"（`LayoutHelper.cs:404-406` 注释原文）

「工具箱」与「图元工具箱」**同处一个 `LayoutAnchorablePane` 做标签页**——若先 Hide 再 Show，中间会出现"该 pane 两个子项都不可见"的**瞬态**，空 pane 的列宽被置 0，表现为**整列闪一下**。先激活目标就没有这个窗口（实现 `:427-431`：组态分支先 `foreach Show`（三个）再 `Hide(算子工具箱)`；非组态分支反之）。

### 3. 收敛逻辑放 `LayoutHelper` 而不是 `ShellViewModel`（`:408-409` 注释原文）

断言宿主可以对着**它自己那份** `DockingManager` 直接调 `ApplyScadaPanelMode` 验可见性矩阵；写在 VM 里就只能写"源码里有这段"这种弱断言。

### 4. 为什么 `ApplyPanelMode` 不挂在四个面板自己的 `IsVisible` 上

Hide/Show 动作本身就会改 `IsVisible`——挂上去就是"Hide 触发下一轮收敛、下一轮再 Hide"，**来回抖动**。只用"文档区选中标签变化"这一个入口（`:300-302`），状态机是单向的。

### 5. 为什么右侧「工具箱」开关在组态模式下要收起

见 §二-4：那一列此刻显示的是图元工具箱，留着这个开关点一下会把算子工具箱切到前台、正好覆盖掉模式收敛。故 `ShellCopy.xaml:898-906` 用 `DataTrigger`（`Binding IsScadaDesignMode, Value=True → Visibility=Collapsed`）收起它。

### 6. 为什么**不用**升 `CurrentLayoutSchemaVersion`（`R43` 的边界）

3. **补 `ContentFactories` 不会新增拒绝**：旧 `.vms` / 旧 `Layout.xml` 本来就在**版本闸**那一关被拒（`IsLayoutXmlUsable`（`:257-287`）对 `version < 3` 返回 false，判据 `:265-271`），覆盖度校验（`LayoutXmlCoversAllPanels`（`:239-248`））压根没参与。**本记录作者独立核实**：全仓 30 份 `.vms` 中 `LayoutSchemaVersion="3"` 的 **0 份**（21 份 v2 + 9 份无版本属性）；磁盘 `Layout.xml`（`VisionMaster\bin\Debug\net9.0-windows\Layout.xml`，mtime 2026-10-16 00:45:58）是 `LayoutSchemaVersion="3"` 且**已含** `Panel_ScadaLayerView` → 放行。结论：**不构成行为变更，`R43` 不升版本的理由成立**。

### 7. 附带修掉的既有缺陷：`ContentFactories` 漏登记图层面板
