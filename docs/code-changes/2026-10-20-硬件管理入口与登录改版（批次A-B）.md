# 硬件管理入口与登录改版（批次 A-B）

- 日期：2026-10-20
- 范围：`VisionMaster` 宿主（菜单、硬件管理入口、登录弹窗、UI 冒烟断言）
- 状态：批次 A/B 已落地并验证；完整嵌入（批次 C）未开始

## 1. 起因

用户要求按已评审的设计稿落地「用户登录优化 + 相机 / 通讯 / 运动板卡统一收纳进硬件管理」。

评审结论（见上一轮计划）：可以统一，但不能直接把三个 `IDialogAware` 弹窗塞进新页签。
本批先交付**低风险、可见收益**的两块：

1. 系统菜单只留一个「硬件管理」入口，并给出只读概览（哪些设备不正常）。
2. 登录弹窗换用 Dialog 设计令牌，补关闭键、已登录账号卡、出厂密码「立即修改」入口。

三个域窗口仍由硬件管理外壳里的「打开」按钮进入，**本批不改它们的生命周期**。

## 4. 批次 C 前置（本批未做，别当成已完成）

按评审计划，完整嵌入三个域窗口前必须先补：

1. `IEmbeddedDialogPage`：Opened 一次 / Activated/Deactivated 多次 / Closed 恰好一次；懒创建。
2. 子视图 chrome：隐藏标题栏、相机底栏「关闭」、通讯底栏「确定」；宿主 footer 接管关闭，不调用子 VM 的 `RequestClose`。
3. 运动切页只停看门狗 + 停点动，**不调用 `Debug.OnShellClosed`**（它在等待回零/到位时会 `CancelAll`，可能误杀同卡流程命令）。
4. 权限：`IHardwareEditGate` + 整页 `IsEnabled` + 订阅角色变更；运行锁用 `AnyFlowRunning()`，急停/停止例外。
5. 通讯保存：仅通讯页打开且脏时 `await SaveConfigAsync`；失败可见；未打开通讯页关闭宿主不得覆盖 `communications.json`。
6. 方案脏标记：全仓无 `SolutionModel.IsDirty`，宿主暂不承诺“已保存 / 未保存”状态。
7. 登录：忙碌态若要做可见动画，需要把 PBKDF2 验证挪后台并给 `ScadaUserStore` 加锁/快照；本批保持 UI 线程。
8. 登录数据缺口：`ScadaUserRecord` 无上次登录时间/IP，`AppConfig` 无“记住账号”；本批未加，设计稿对应元素先隐藏。
9. 主题：`MotionBoardTheme.xaml` 仍是 Mb 令牌；完整嵌入前需映射到 Dialog 令牌（注意 `MbPrimaryColor` 是 Color 而非 Brush，R30-R32）。

## 5. 风险与注意

- 本批硬件管理是**入口 + 概览 + 打开既有弹窗**，不是设计稿里的完整嵌入外壳；不要按“三个页签已嵌入”去验收。
- 概览使用独立 HealthMonitor 实例；若改为共用 `SystemHealthView` 的单例，帧率/告警会因两次 `Capture` 互相打乱基线。
- 菜单静态闸只认 `Shell.xaml` 里出现的 `SystemAction`；新增菜单项必须同时补 `OnSystemAction` case，否则冒烟会红。
- 登录页的已登录态尚未真机复验，见 §3。
