## 5. 踩过的坑

1. **批 1 的"LastProblems 上屏"到批 4 才做，口径已经变了**：批 1 时"重名"就是缺陷；批 2 之后跨设备重名合法。若照原计划"见到重名就报"，正常多设备方案会天天弹假警报。修法 = 判定共用 `VariableNameScope.Conflicts`，只报同作用域冲突。**跨批次的计划项落上前必须重新对口径。**
2. **`LastProblems` 在接口上不存在**：`GlobalVariableManagerViewModel` 拿到的是 `IVariableRegistry`，编译才发现。补进接口时把"惰性计算"语义写进注释。
3. **诊断改惰性而不是"Rebuild 时存"**：方案加载是 `Clear() + 逐个 Add`，全量 Rebuild 只发生在空集合那一刻——存起来的诊断会永远停在加载前。惰性扫一遍 O(名字数)，只在打开变量管理时读一次。
4. **两条横幅同占 `Grid.Row="1"`（Auto 行）会重叠**：包进 `StackPanel` 才能让"可见几条撑多高"。
5. **`[JsonIgnore]` 了 `IsTextDirty`，但反序列化仍会把它标成 true**：名字 setter 在反序列化时触发（名字从默认值变成 JSON 里的值）。这是**预期**——由插件加载路径 `ApplyConfigValues → MarkTextClean` 复位；探针第一版断言"往返后必须 false"是错的，改成"落盘不含脏标记 + 加载复位后 false"。
6. **`ResolveTarget` 的顺序是口径**：①未改文本+Id 可解析 → 保留（改名不断链）②精确名 → ③名字+设备 → ④原样。**精确名必须在后缀解析之前**，否则真叫 `A_PLC/A` 的变量会被拆成（A_PLC, A）。
7. **限定写法的错误要分三档**：设备不存在 / 设备上没有该变量 / 同设备重名，三种修法各不相同；混成一句"找不到"会把用户引去错方向。
8. **探针夹具：限定写法只对网络变量有意义**，本地数组（`CreateLocal("Samples"…)`) 会被"设备上没有该变量"拦住——第一版红是夹具错，不是产品错。夹具改成带设备的网络数组。
9. **`Net()` 夹具重载**：数组镜像需要 `DataType = mirror.GetType()`，标量 `typeof(int)`——加一个 4 参重载而不是让标量路径跟着变。
