# 2026-10-25 配方参数表：删除前先能全选

## 1. 起因

用户在配方管理里配方「DD」有 1195 条参数，要清掉大部分，发现**勾不快**：
界面上只有「删除选中(2)」，没有任何全选 / 全不选入口，只能一行一行点。

## 2. 根因

`CheckAllCommand` 早就写好了，`RecipeManagerViewModel` 里从构造到 `CanExecute` 一应俱全：

```csharp
CheckAllCommand = new DelegateCommand(ToggleCheckAll, () => Parameters.Count > 0)
```

但**全仓 grep `CheckAllCommand` 在 XAML 里命中 0 次**——命令从接入界面这步就断了，属于"写了没接线"。
所以这不是功能缺失，是一条从未被使用过的死代码。

## 3. 改动清单

### 3.1 `VisionMaster/ViewModels/DialogViewModels/RecipeManagerViewModel.cs`

- `ToggleCheckAll()` 重写为只作用于 `ParametersView`（表格此刻看得见的行）：

  ```csharp
  var rows = ParametersView.Cast<RecipeParameterRow>().ToList();
  if (rows.Count == 0) return;
  bool target = rows.Any(r => !r.IsChecked);
  foreach (var row in rows) row.IsChecked = target;
  ```

  两条理由写进 XML 注释：
  1. **只勾看得见的行**。拿 `Parameters` 全量勾，遇上「仅显示差异」或查找过滤，会把看不见的行也勾上——
     用户以为只勾了 3 行，点删除却删掉 1195 行。
  2. **全选 / 全不选按"可见行是否已全勾"判**，不拿勾选数跟总数比。总数含被过滤掉的行，
     那样的比较会让点一次之后永远停在半选。

- 新增 `public bool? CheckAllState`：可见行全勾 → `true`，全不勾 / 无可见行 → `false`，部分勾 → `null`。
  与 `ToggleCheckAll` 同源，都只认 `ParametersView`。
- 三处 raise `CheckAllState`：`OnParameterRowChanged`（`IsChecked` 变化）、`RaiseParameterCounts()`、
  `SelectedItem` setter（换配方要重置表头框）。

### 3.2 `VisionMaster/Views/DialogViews/RecipeManagerView.xaml`

- 工具栏（`Grid.Row="1"`，7 列 `Auto×4 + * + Auto×2`）在 `Grid.Column="3"` 插入表头全选框：

  ```xml
  <CheckBox Grid.Column="3" Command="{Binding CheckAllCommand}" Content="全选"
            IsChecked="{Binding CheckAllState, Mode=OneWay}"
            Style="{StaticResource DialogCheckBox}"
            ToolTip="全选 / 全不选（只作用于表格里此刻可见的行）" ... />
  ```

  `Mode=OneWay` 是必须的：`CheckAllState` 是三态只读派生属性，TwoWay 会让勾选框自己把 `null` 写回去。
- 参数表 `DataGrid` 挂 `MouseLeftButtonUp="OnParameterRowClicked"`。

### 3.3 `VisionMaster/Views/DialogViews/RecipeManagerView.xaml.cs`

- `OnParameterRowClicked`：命中第 0 列（勾选列）且点的不在 `CheckBox` 本体上时，切换该行勾选，整格可点。
- 配套 `AncestorOf<T>`（`VisualTreeHelper` 上溯找 `DataGridCell`）。

**为什么不是另外两条路**（都试过 / 都写进注释）：

- **不给 `CheckBox` 再挂 `Click`**：它已 TwoWay 绑 `IsChecked`，点自己就翻一次，再挂 Click = 翻两次等于没动。
- **不用 `DataGrid.SelectingCells`**：`DataGrid` 没有这个事件（那是 `DataGridCell` 的），
  写上直接 `error MC3072: XML 命名空间中不存在属性"SelectingCells"`，编译期就红。

## 4. 验证

探针 `tools/probes/_RecipeUiProbe` 新增 `[CheckAll]` 段，**刻意做成反向用例**：
先清空勾选，再打开「仅显示差异」把行过滤掉一部分，然后点全选，断言「可见行全勾」且「隐藏行没被勾」。

实测输出（五个渲染场景逐一跑）：

```
[CheckAll] 过滤前 可见=2 隐藏=0
[CheckAll] 仅显示差异 可见=1 隐藏=1
[CheckAll] 全选后 可见全勾=True 隐藏未动=True 勾选数=1/2 CheckAllState=True
[CheckAll] 再点一次 全不选=True 勾选数=0 CheckAllState=False
```

其中 `design-xxx` 场景恰好无差异行时走退化用例（`可见=0 隐藏=2`），同样有断言。
最终 `RESULT: OK`，0 条 FAIL。

主工程 `dotnet build VisionMaster/VisionMaster.csproj -m:1 -nodeReuse:false` → **0 个错误**（449 个警告均既有）。

## 6. 踩过的坑

- `DataGrid` 没有 `SelectingCells`，只有 `DataGridCell.Selected` / `SelectedCellsChanged`；前者写上 MC3072。
- `CheckAllState` 若用 TwoWay 绑定，三态值会在用户点击时反向写回只读属性，必须 `Mode=OneWay`。
