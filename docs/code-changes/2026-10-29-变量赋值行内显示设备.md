## 1. 当前状态

批 3 已经给候选带上了 `Device`（`VariableOption.Device` → `NameCandidate.Device`），但**界面三处仍绑裸名字**，所以两台设备的 `Alarm1[48]` 在插件里完全一样：

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 候选浮层标题行 | `Alarm1[48]` | `Alarm1[48] · B_PLC` |
| 行内变量名格子 | `Alarm1[48]` | `Alarm1[48] · B_PLC` |
| 右侧标题（`SelectedRow.DisplayName`） | `Alarm1[48]` | `Alarm1[48] · B_PLC` |
| 右侧提示 | `写入全局变量「Alarm1[48]」（Boolean）…` | `写入全局变量「Alarm1[48]」（Boolean · 设备 B_PLC）…` |
| 本地/运行时变量 | 不变 | 不变（无设备段） |

## 2. 用法（怎么选全局变量）

1. 行的「作用域」选 **全局**；
2. 点「变量名」格子（它是 `ToggleButton`，不是可编辑输入框）→ 弹出候选浮层（顶部带搜索框）；
3. 候选来自 `PluginConfigContext.Variables`（变量管理快照，含全局/通讯/系统 + 上游运行时变量）；
4. 点一条候选 → `SelectGlobalCandidateCommand` 同时写 `Row.VariableName` 与 `Row.VariableId`，浮层关闭。

**重名时**：浮层里两行的加粗标题分别是 `Alarm1[48] · A_PLC` 与 `Alarm1[48] · B_PLC`；选中后行内与右侧标题也带设备。运行期按 `VariableId` 写入，不会串到另一台。

## 6. 踩过的坑

1. **数据带了 ≠ 界面显示了**：批 3 把 `Device` 放进了 `NameCandidate`，但 XAML 仍绑 `Name`——不实际跑界面/断言就发现不了。这次是用户截图点出来的。
2. **`DisplayName` 必须按 Id 解析设备**：按名字查的话，变量在变量管理里改名后行内会掉设备段（C22.4 钉住）。
3. **`DisplayName` 每次刷新都会调 `FindVariable`**（O(候选数)）：与既有 `IsInvalidGlobal` / `TypeText` 同一量级，未新增复杂度等级；8000+ 候选下仍在毫秒级。
