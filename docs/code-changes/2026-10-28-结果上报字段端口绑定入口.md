## 1. 问题是什么（三条事实，不是感觉）

1. **画布上没有字段级端口锚点**。`FlowCanvasViewModel.GetOrCreateNode` 给每个节点只加两根脚：
   `__flow_in` / `__flow_out`（流程顺序），画布连线是**模块级数据依赖**，端口选择一律交给绑定弹窗
   （类注释第 41/47 行、`FlowCanvasView.xaml` 的 `Inputs[0]`/`Outputs[0]` 绑定）。所以"在画布上把 sn 连上"
   在当前架构里不存在。
2. **完整绑定弹窗列不出字段端口**。左侧端口表读 `ToolItemModel.InputDefinitions`，那是 `PluginService`
   扫描插件时用**空配置实例**拍的快照（`Engine\PluginService.cs:339-375`）。结果上报的动态端口由 `Fields`
   驱动，快照里最多只有构造器那三行——而构造器里 `Fields.Add` 三次发生在 `HookFields` 之前，
   集合通知一次都不触发，`RebuildDynamicInputs()` 从没跑过 → **连默认的 `sn`/`result` 都不在快照里**。
3. **视图里"来源=端口"只有一句静态文字**"画布上连线供值"，没有任何绑定入口。两头的路都不通，
   用户只能面对一个列不出端口的弹窗。

### 为什么改名迁移只在「确定」时做

字段名是逐字符写进模型的（原绑定 `UpdateSourceTrigger=PropertyChanged`），改 `sn → sn1` 会经过 `s`。
逐字符迁移的后果：第一次把线搬到 `s`，第二次 `s` 已无线可迁，最后**线停在 `s`、字段叫 `sn1`**——
比"根本没迁"更难查。所以：

- 锚点 `_confirmedPortNames` 只在 `Initialize` / `OnConfirm` 拍快照；
- 迁移只在 `OnConfirm` 执行一次，且排在 `base.OnConfirm` **之前**（base 会给"未链接"端口写
  `InputValues` 固定值，迁完新名才算已链接，才不会留脏值）；
- 字段名文本框回到默认的 `LostFocus` 提交——配置期间改的是副本，点「取消」模型一个字节都不变。

## 8. 踩过的坑

- **`Fields.Add` 早于 `HookFields`**：构造器里三次 `Add` 时订阅还没挂，`OnFieldsCollectionChanged` 不触发，
  所以 `RebuildDynamicInputs` 必须显式补一次。这也是"扫描期快照里没有 sn/result"的直接原因。
- **R42 的真实形态**：改 `Help\*.md`（内嵌资源）后 `dotnet build` 增量构建不会重打包，
  `audit_artifacts` 直接报 `STALE_DLL`（本次复现：dll=22:59:44 < src=23:01:41）。必须 `--no-incremental` 重建。
- **`TextBlock` 局部 `Foreground` 会压掉 Style 的 DataTrigger**：先写了 `Foreground="…Success"` 又在
  `TextBlock.Style` 里用 DataTrigger 改色 → 触发器永远不生效。颜色只能走 Style。
- **`GetConfigView` + `PluginConfigShellViewModel.OnDialogOpened` 会各调一次 `Initialize`**（两次），
  第二次会把 `Fields` 换成新反序列化实例；视图绑 `Fields` 会跟着刷新（setter 有 `PropertyChanged`），
  但任何"只改本地字段对象、不写模型"的写法都会在第二次 Initialize 时丢掉。
- PowerShell 里 `ReadAllLines` 读正在被写的日志会抛 `IOException`；用 `[IO.File]::Open(...,'Read','ReadWrite')` 共享读。
