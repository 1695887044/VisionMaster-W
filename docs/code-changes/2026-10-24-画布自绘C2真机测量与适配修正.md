## 五、踩过的坑

- **`Visibility.Collapsed` 不等于"这个编辑器不存在"**：容器在首次布局时已生成，
  折叠只跳过 measure，绑定照跑，451 节点吃掉 ~1000 ms。测量时必须把
  `Editor.ItemsSource`/`Connections` 真正置空，否则测出来的是"两套画布同时在跑"。
- **`ActualWidth == 0` 时算适配**：0 宽 → zoom 撞下限 → 整张图缩成一个点，
  真机表现就是"一片空白"，而且不报错。必须先判尺寸、等布局、再算。
- **长链流程的"适配到全图"是无意义操作**：29406 px 高的链条塞进 349 px 视口，
  比例适配的产物是像素点。适配必须有下限，且撞下限时对齐策略要换（左上角）。
- **同机并发构建会污染测量**：22:46 那次 18093 ms 与同构建的 3294/3968 ms 差一个数量级，
  当时主会话正在同机跑 `dotnet build`。**真机计时必须在机器空闲时连跑三轮取稳定值。**
- `dotnet build` 时 exe 被自己启动的实例锁住 → `MSB3027`。
  测完先 `taskkill` 再构建，别指望增量构建绕过文件锁。
