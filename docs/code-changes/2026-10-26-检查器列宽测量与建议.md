# 检查器（右栏）列宽测量与建议 — 2026-10-26

## 一、当前状态

- 右栏是 **一列四页签**：属性 / 图层 / 工具箱 / 图元工具箱。
- 宽度写在 `VisionMaster/Shell.xaml:1649`：`DockWidth="320" DockMinWidth="300"`。
- 用户反馈：工具箱页签看起来偏宽，希望给一个合适的宽度。

## 二、已做（测量）

### 2.1 设计基线自己的窄视口规则

`docs/UI设计基线/app-shell/design.html:2169-2172`：

```css
@media (max-width: 1500px){
  :root{ --nav-w:280px; --inspector-w:300px; }
}
```

即：视口 ≤1500px 时，检查器设计值就是 **300**。现状顶栏截图 `docs/UI设计基线/flow-nav-shell/evidence/before-topbar.png` 宽 1310px（窗口客户区约 1310），落在该规则内。

> 左侧流程栏没有跟着降到 280：2 列 24px 胶囊的宽度账要求 340（用户已确认），两者是独立决策。

### 2.3 宽度账（图元工具箱，最紧的一页）

一行可用宽 = 列宽 − 滚动条 17 − 滚动区左右边距 18 − 右边框 1。

- 320：可用 284；固定件（内边距 16 + 抓手 10 + 图标 22 + 两处 6 + 类型键 74）= 134；名字列 150。
- 300：可用 264；名字列 130。
- 280：可用 244；名字列 110。
- 最长名字「报警确认按钮」11.5px ≈ 69px，三种宽度都放得下；差别只在名字与类型键之间的留白（320 约 81px / 300 约 61px / 280 约 41px）。

### 2.4 属性面板编辑器宽

属性行固定件 = 左右边距 24 + 标签 64 + 行尾绑定槽 26 = 114。

- 320：编辑器 205px
- 300：编辑器 185px
- 280：编辑器 165px
- 260：编辑器 145px（`scada-property-panel.png` 实测可用）

## 四、建议

**默认宽度取 300**，`DockMinWidth` 可保持 300（若希望用户还能继续拖窄，降到 280）。

理由：

1. 设计基线在 ≤1500px 视口下的检查器值就是 300，当前窗口约 1310px，正好命中。
2. 300 是四页签共用列里“最紧页签”（图元工具箱）刚好舒服的宽度：类型键完整、名字列 61px 余量。
3. 属性面板在 260 已实测无截断，300 比它多 40px，不会挤压编辑器。
4. 从 320 降到 300 只还画布 20px，视觉上刚好是“有点大”这一档；若还嫌宽，280 是下一档（图元工具箱名字列余量降到 41px，仍可用），再低就会让类型键和页签条开始挤。

如果只想让“工具箱”页签自身看起来窄、不想动属性面板：可以在工具箱内容上设 `MaxWidth=280` 左对齐，但面板本身仍是 320、页签条也不变，不推荐——那是把空白留在面板里。

## 五、踩过的坑

- 右栏是四页签共用一列，**不能只给工具箱单独设宽度**；AvalonDock 同一 `LayoutAnchorablePane` 内各页签共享列宽。
- 设计稿的 320 是 ≥1500px 视口的值；直接拿 320 当“设计值”会忽略它自己的窄视口规则。
- 图元工具箱 260 宽时类型键已被 `TextTrimming` 省略，容易误判为“宽度够了”；判据要看名字列余量与类型键是否完整，不看有没有报错。
