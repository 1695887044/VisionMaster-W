## 1. 当前状态

左侧工作列（流程导航，340）与右侧检查器列（属性 / 图层 / 工具箱 / 图元工具箱，300）的**结构定义**
一直是正确的（`Shell.xaml` 与 `RunShellLayoutChecks` 的静态闸都钉着"右侧检查器只有一列"）。
坏的是**运行期归属**：检查器面板一旦被停进左侧工作列，`Layout.xml` 会原样持久化，
下次启动恢复布局后点胶囊（`ToggleAutoHide()` 收回原 pane）又收回同一列 —— 于是「流程导航 / 工具箱」
成了同一个 `LayoutAnchorablePane` 的两个标签，且每启动一次复现一次。

代码里此前只有两类约束：`EnsureInspectorColumnWidth`（列宽）、`ApplyScadaPanelMode`（可见性），
**唯独"落在哪一列"没有任何判据**。`AnchorToHomePane` 的兜底第 ② 档"树上第一个空列"还会主动
把面板塞进左列（流程导航被收起时，左列正好是第一个空 pane）。

本轮补的是"列归属"这一维：加载布局的同一拍把错位面板迁回右侧，显示路径（`ShowPanel`）与
兜底落点（`AnchorToHomePane`）同时加上"检查器面板不许落左列"的判据。

用户现有 `Layout.xml` 不需要手改：下次启动自愈（左列 = 流程导航，右列 = 工具箱），退出时按新归属重写。

## 3. 未做（以及为什么不能"顺手"做）

1. **流程导航被拖到右侧列不纠正**：本轮只钉"检查器面板不许进左列"。反向（流程导航跑到右列）
   属于另一条归属规则，且用户可能有意为之，改动面更大，未纳入。
2. **不升 `CurrentLayoutSchemaVersion`**：升版会整份作废用户布局（面板位置、控制台状态全丢），
   而本缺陷用"加载即纠正"即可修好，代价小得多。R43 的判据是"结构/停靠语义是否变化"——本轮没有。
3. **不给隐藏态面板改记忆容器**：R58 明确"反射只读、绝不写库私有状态"。隐藏面板的记忆若指向左列，
   不预先改写；等它被显示时由 `ShowPanel` 的钩子纠正。
4. **未跑真 `VisionMaster.exe` 验收**：断言宿主已覆盖归属判据（R175 分层）；用户侧验收只需重启一次，
   看"左=流程导航、右=工具箱"。

## 5. 踩过的坑

1. **`run_gates.ps1` 的构建步偶发 `0 个错误 + 退出码 1`**：本轮第一次全量跑，`DataPipelineChecks`
   报 `BUILD FAILED`，但 `build-DataPipelineChecks.log` 末尾是「已成功生成 / 0 个错误」。单步
   `run_gates.ps1 -Only DataPipelineChecks` 复跑即绿（97 pass / 0 fail）。属 R179/B-01 的瞬时失败，
   不要为此改代码或清 `obj`。已并入台账 B-01。
2. **断言宿主里 `processPane` 重名**（CS0136）：`RunPanelModeChecks` 后半段已有同名局部变量，
   新块改用 `leftWorkPane`。新增断言块前先 grep 变量名。
3. **`Get-Content` 读 UTF-8 日志会显示乱码**（PS 5.1 默认 936）：判读一律 `Select-String` 或
   `-Encoding UTF8`，别据此判断"宿主输出坏了"。
