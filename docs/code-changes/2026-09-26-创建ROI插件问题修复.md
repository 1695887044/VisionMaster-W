# 创建ROI插件（Plugin.CreateRoi）问题修复

日期：2026-09-26（评审于 2026-09-25）
范围：`Plugins/Plugin.CreateRoi/`、`FlowCanvasChecks/`（新增 CreateRoiChecks）
测试：全量断言 737 通过 / 15 失败（15 条为相机注册表、线序方案、脚本预览通道的既有基线失败，与本次无关）；CreateRoi 新增 47 条全过；宿主启动冒烟 30 插件加载 0 错误。

## 一、功能 Bug 修复

### 1. 参数微调在"从列表选中"后与画布断链（核心交互失效）
- **根因**：`SelectedRoi` setter 先无条件退订 `ParamEdited` 再判断值是否变化。列表选中会经
  `CanvasActiveRoi` setter 联动回写同一个 RoiItem（同值重入），第二次进入 setter 时订阅被摘走、
  同值路径短路后不再补回 → 参数微调事件无人监听，画布句柄不动、掩膜预览不刷新。
  画布点选路径因 `_canvasActiveRoi` 已同值不触发重入，所以"时好时坏"。
- **修复**：改为先 `SetProperty` 判断真变化再退订旧值/订阅新值；画布活动对象未变时不回写，
  消除 setter 互写回环。

### 2. 显示窗口选"不显示"仍发布到窗口 1
- `RunAlgorithm` 无条件 `PublishPreview(img, DisplayViewIndex + 1)`，而 ComboBox 0 = 不显示。
- **修复**：`if (DisplayViewIndex > 0)` 才发布，与 BlobDetect 的仓库口径一致。

### 3. 重开配置后新建 ROI 必然撞名 → 输出丢失 + 每轮内存泄漏
- **根因**：控件命名序号 `roiSeq` 是控件实例字段，每次打开配置从 0 重新计数；方案里已有
  ROI_0/ROI_1 时再新建必然又叫 ROI_0。后果：动态端口重名被 `AddDynamicOutput` 静默去重 →
  两个 ROI 写同一端口，`OutputPort` 覆盖旧值不释放 → 首个 ROI 的裁剪图每轮泄漏、下游永远拿不到。
- **修复**（三层防御）：
  - 画布 Add 分支：`NextFreeName` 强制唯一名并回写 `info.RoiName`（画布标签同步）；
  - `Initialize` 播种：对历史方案已存在的重名统一去重，有改名时重建端口与快照；
  - `RunAlgorithm`/`RebuildDynamicOutputs`：重名只输出第一个端口，兜底旧数据。

### 4. 涂擦区域重开配置即丢（历史数据丢失 bug，测试期间发现）
- **根因**：`RestoreSmear` 经 `SmearDraw` setter 恢复时，setter 内的 `SyncSmearData` 会把
  `_smearEraseData` 用"尚未恢复的 null"重新编码成空串——擦除区域恢复不了，且下次确认时
  方案里的擦除数据被静默抹掉。原代码即存在。
- **修复**：`RestoreSmear` 直接写字段后一次性 `OnPropertyChanged`，不走 setter 的同步逻辑。

## 二、功能补全（评审 P2 项）

### 5. 涂擦/排除模式此前只影响预览、不影响任何实际输出
- 新增两个固定输出端口（随插件就位，无需配置）：
  - `MaskRegion`（HRegion）：合并有效区域 = (ΣROI ∪ 涂抹) − 擦除，不随排除模式反转；
  - `MaskImage`（HImage）：二值掩膜（有效区 255），排除模式下反转（内 0 外 255）。
- 逐 ROI 裁剪域现在吃掉"擦除涂抹"（`region − 擦除`）：擦掉的地方不再出现在裁剪图里；
  被擦除殆尽的 ROI 跳过并留警告日志。

### 6. 主界面发布改为合并掩膜合成图
- 此前每个 ROI 的裁剪图都发到同一窗口互相覆盖（只见最后一个）；现改为发布"无效区置黑"
  的合成图一帧看清全部 ROI 与涂擦修正，与配置界面掩膜预览同口径。

### 7. RoiCount 语义修正
- 由"配置的 ROI 数"改为"本轮实际成功输出的裁剪图数"，下游按此循环取数不越界。

## 三、健壮性 / 体验

- 裁剪循环补 `try/finally`：端口写入前抛异常不再泄漏 HImage/HRegion（原代码会漏 `croppedImg`）。
- "清空"按钮加二次确认（清空不可恢复），且无 ROI 时禁用。
- 笔刷半径输入框挂数字过滤附加属性（只放行数字与小数点）。
- 视图尺寸改用 `d:DesignWidth/Height` + 既有 `PluginViewMinWidth/MinHeight` 令牌（与 Matching 等
  新插件统一，去掉固定 1000×600）；补 `mc:Ignorable="d"`。
- 涂擦游程序列化超 4KB 自动 GZip+base64（`gz:` 前缀），旧格式照常解析，两代互认；
  大图大范围涂擦不再让方案文件线性膨胀。

## 三·五、实测反馈修复（2026-09-26 凌晨，用户实机验证后）

### 8. ROI 列表被参数面板挤没
- 左列重排：**ROI 列表提为主区**（`*` 行 + MinHeight 150），参数微调挪到列表下方；
- 参数微调改紧凑双列（UniformGrid，5 个参数 3 行），未选中 ROI 时只剩标题一行；
- 数值框右对齐 + 按位数格式化（原样显示 236.8858795… 截断难看）：行/列/半长等 F1、
  角度 Phi 弧度 F4，经 `RoiParamEntry.Text` 双向绑定（不变区域解析，非法输入还原）。

### 9. 擦除"没反应"（视觉反馈缺失）
- `HalconBase.RenderAll` 原来把涂抹(橙)与擦除(红)两层都原样画满，擦除后橙色仍在，看起来像没擦。
- 改为显示**净涂抹**（涂抹 − 擦除）：擦到哪橙色消失到哪，红色只标出被挖除的位置；
  笔画进行中的工作副本同样按净口径实时显示。此改动在共享控件层，Matching 等涂擦使用者同步受益。

### 10. 杂项美化
- ROI 列表形状名中文化（`ROI_0 [矩形]`，原为英文枚举名 `[Rectangle]`）；
- 掩膜预览工具条间距收紧。
- 回归：CreateRoi 组 48 条断言全绿（新增"视图实例化+布局"STA 冒烟断言，防 XAML 运行时炸配置窗口）；
  全量 738 通过 / 15 失败（既有基线不变）。

### 11. 第二轮实测反馈（擦除视觉 / 窗口尺寸）
- **擦除仍像"涂红色"**：第一轮把擦除区显示为红色**填充**，盖在擦除位置上，用户看到的是
  "画了红色"而不是"擦掉了"。改为红色**细轮廓**（margin）标记擦除位置，净涂抹（橙=涂−擦）
  挖空后直接露出底图——擦到哪橙色消失到哪。
- **配置窗口默认尺寸放大**：宿主 `PluginConfigShellView` 全局 880×600 → **960×680**
  （内容区高度 ~490px 时参数多的插件左列底部被裁，880 时代的历史遗留）。
- **CreateRoi 左列再压缩**：删掉底部"操作提示"卡（提示并入 ROI 列表头：右键图像→区域→新建；
  Del 删除选中，悬停有完整说明），默认窗口下三卡完整显示不再裁切。
- 回归：全量 740 通过 / 15 失败（既有基线不变），CreateRoi 组含视图冒烟全绿；
  宿主启动冒烟 0 加载错误。

## 四、测试（FlowCanvasChecks/CreateRoiChecks.cs，47 条断言）

- 三形状区域构建（面积/质心，按栅格化像素口径）+ 非法参数返回 null；
- 掩膜构建：正常/排除模式、单通道/三通道、二值内外灰度；
- 合并区域：多 ROI 并集、涂抹并入、擦除挖除（面积笔算）；
- 动态端口：画布增删联动、快照同步 StepData、MaskRegion/MaskImage 就位；
- 重名防御：画布撞名改名回写、历史重名播种去重、端口无重名；
- 选中联动契约：列表/画布双向选中、参数微调写回画布句柄（旧 bug 回归位）、点空白同步取消；
- 运行端到端：裁剪包围盒/域面积、擦除修正进裁剪域、坏 ROI 跳过且 RoiCount=成功数、
  无输入失败语义、三通道底图全链路、"不显示"不炸；
- 序列化往返：RoiList 快照脱钩、小涂擦纯文本、大涂擦 gz 压缩、新实例恢复、Dispose 幂等。

## 五、遗留 / 后续候选

- ROI 名称仍不可在界面上重命名（本次只保证唯一性）；如需语义命名（如"焊盘1"）可加改名入口，
  改名时同步端口名需处理下游接线迁移。
- `MaskRegion`/`MaskImage` 是新端口，旧方案不会自动接线，需用户在画布上按需连线。
- 15 条既有基线失败（相机注册表、线序方案、脚本预览通道）与本次无关，建议另行排查。
