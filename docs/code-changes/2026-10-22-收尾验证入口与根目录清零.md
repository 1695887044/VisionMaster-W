## 3. 关键决策

**① 入口只有一个，不许各自为政。** 六个宿主 + 两个审计脚本，谁都能手敲，但"手敲"意味着有人漏敲、有人敲了不看退出码。`run_gates.ps1` 把顺序、日志落点、陈旧 exe 检测全部钉死，收尾只有一句话。`-SkipBuild` 保留但写进注释"不是日常用法"——它的唯一用途是刚构建完想重跑一遍判定。

**② 管道里解码是错的，必须让子进程直接写文件。** 第一版用 `& $exe 2>&1 | Out-String`：PowerShell 5.1 按**控制台代码页**（本机 936）解码子进程 stdout，而 .NET 宿主吐的是 UTF-8，于是写出来的日志是"合法 UTF-8 的乱码"；更糟的是**统计正则在这段乱码上永远不命中**，每个宿主都回落打印 `all checks passed`——**汇总行成了没人能验证的断言，比没有汇总行更坏**（R13）。第二版用 `Start-Process -RedirectStandardOutput` 让子进程把原始字节直接写文件，回读时严格 UTF-8 优先、失败回落 936（`powershell.exe` 子进程确实吐 936）。教训记在这里：**跨进程传中文，别在管道里过一遍字符串**。

**③ 根目录违规只"搬"不"删"。** 141 个 `.log` / 15 个 `.out` 全是历史 AI 批次产物，且**全部未跟踪**——删了不可回退。按 R166 搬到 `artifacts\logs\2026-10-22-root-sweep\`，`_help_preview` 搬到渲染落点。只有空目录 `--nologo` 直接删（没有内容可丢）。

**④ 那 2 条红是负载超时，不是产品缺陷——但也不是"重跑就好了"。** 首次全量 gate 里 `FlowCanvasChecks` 报 2 条失败，都在 `MotionChecks` 的 ②反例（可控假设备）：`前置：假设备命令失败后进入安全停机` 拿到 `状态=Online 说明=断言用假运动设备`。空载重跑同一条 exe：**3298 通过 / 0 失败**。根因是 `failing.Completion.Wait(2000)` + `WaitFor(..., 2000)`：六个宿主连着构建+跑，机器在负载下假设备的命令没在 2s 内走完，于是"前置"失败、后面两条断言被连坐（第三条反而"通过"——因为状态本来就是 Online，这是个**假绿**）。改 5s 并在注释里写明原因。**没有改判据、没有加豁免**：等待的是"最终会进入安全停机"，不是"多久进入"。

**⑤ 探针不能一搬了之。** 先确认 `_ScadaUiProbe`（571 行、7 个模式、12:25 还在改、多篇记录在用）**不是** `_ScadaEditorProbe`（531 行、2 个模式）的副本，所以它是活探针，不能进 `_Retired`。按 R167 先在新址 `-BuildOnly` 通过（0 错误 / 949 警告 / 48.61 秒），再改登记表，最后才删旧目录（202M）。

## 5. 边界与未做

- **`run_gates.ps1` 尚未接进任何"自动化"**：它现在是**人工收尾命令**，不是提交钩子。要不要挂 `pre-push` 另议（一次全量约 9 分钟，不适合每次提交）。
- **两个宿主仍不在 sln**（`UIThemeSmokeTest`、`HelpProbe`）。本轮只让 `run_gates.ps1` 绕过这个问题，**没有把它们加进 sln**——加进去会改变用户的"生成解决方案"耗时，属于要用户点头的事。
- **`run_gates.ps1` 对这两个宿主只能判退出码，判不了条数**（它们没有 `通过: N  失败: M` 汇总行）。要补的话得给宿主加汇总行，或让脚本解析各自的明细计数——本轮没做，记在这里免得下次误以为"8 steps green = 条数都核过了"。
- **断言宿主会写仓库里的受跟踪文件**（本轮实测，未修）：`ScadaChecks/Phase1UiChecks.cs:432-491`、`Phase2UiChecks.cs:648-803` 把 7 张证据 PNG 直接渲染进 `docs/UI设计基线/scada-controls/evidence/`；`UIThemeSmokeTest` 的六个 Smoke 也各写自己的 `docs/UI设计基线/*/evidence/`。于是**每次跑 gate 都会弄脏 7 个二进制文件**，而且两次渲染出来的字节不一样（6051→5225），说明它们**不是可复现的证据，是"上一次跑出来的样子"**。本轮已 `git checkout --` 还原，**没改落点**——改到 `artifacts\render\` 会改变"证据随文档走"的既有约定，属于要用户点头的事。
- `docs\产线仿真3D\` 是**未跟踪目录，不是本轮产物**，按 R9 没动。
- 首轮那 2 条红的**根因只到"负载下 2s 不够"**，没有做到"证明假设备完成事件不会丢"。若后续再偶发，下一步应该是查 `FakeAlarmCard` 的完成事件有没有丢，而不是继续加超时。
