## 1. 需求与决策

### 1.4 最终形态

过程名 `script`，接口 3 个端口：

```
Image (HImage, 进)  →  ResultImage (HImage, 出) + Result (String, 出)
```

正文是「数亮斑个数」的可跑骨架：示教参数区（`ThreshMin` / `MinArea`）→ 通道数判断转灰度 → 阈值分割 → 连通域 + 面积筛选 → 计数判 OK/NG → 画布标注 → 输出图像。

### 1.5 三个必须解释的技术约束（都是查证后确定的，不是拍脑袋）

**① 默认过程名不能叫 `main`。** `RunProcedureNameList` 明确排除它：

```csharp
/// <summary>可运行的过程名列表（排除 main）</summary>
public List<string> RunProcedureNameList =>
    Procedures?.Where(p => p.Name != "main").Select(p => p.Name).ToList() ?? new List<string>();
```

叫 `main` 会「运行过程」下拉里看不到、`EnsureCompiled` 里 `FirstOrDefault(p => p.Name == SelectedProcedure)` 也找不到。故取 `script`，与「新建过程」按钮的既有命名（`baseName = "script"`，重名递增）风格一致。

**② 正文不能无条件写 `rgb1_to_gray`。** 它对单通道图直接报 `Wrong number of image channels`（脚本模板库里已踩过并留注：资产库 32 张图只有 1 张是 3 通道）。上游给的图灰度/彩色都可能，所以先判通道：

```
count_channels (Image, Channels)
if (Channels >= 3)
    rgb1_to_gray (Image, GrayImage)
else
    copy_image (Image, GrayImage)
endif
```

**③ 变量类型必须显式声明，不能靠猜。** `GuessType` 对非图形类型是「名字以 i 开头→Int，以 s 开头→String，其余→Double」：

```csharp
if (!iconic)
{
    string l = name.ToLowerInvariant();
    if (l.StartsWith("i")) return ScriptVarType.Int;
    if (l.StartsWith("s")) return ScriptVarType.String;
    return ScriptVarType.Double;
}
```

`Result` 不以 `i`/`s` 开头 → 会被误判成 `Double`，而它要的是 `'OK'`/`'NG'` 文本。所以 `CreateDefaultOutputVars()` 里显式写 `Type = ScriptVarType.String`。

### 1.6 关键设计原则

1. **默认脚本只有一份定义。** 正文、接口、变量表全部放在 `ScriptTemplates` 里（`DefaultProcedureName` / `DefaultBody` / `CreateDefaultProcedure` / `CreateDefaultInputVars` / `CreateDefaultOutputVars`），「首次打开自动预置」和「恢复默认脚本」按钮共用它 → 两个入口行为永远一致，不会各写一套慢慢跑偏。
2. **判据是「从未保存过」而不是「当前没有」。** 前者只送一次（用户删空并保存后不再回来），后者会让删不掉的脚本变幽灵。
3. **不靠下拉的 SelectionChanged 刷编辑器。** 替换后第 0 项**仍是过程**（只是换了实例），`SelectedIndex` 没变 → 事件不触发 → 编辑器会停在旧文本上。所以恢复按钮里显式调 `LoadEditorText`。
4. **破坏性操作必须问。** 「恢复默认脚本」会清掉用户脚本，先弹确认框；文案里明确告诉用户「方案未保存前关闭窗口即可放弃」。

| 成员 | 作用 |
| --- | --- |

| `DefaultBody` | 正文（verbatim 字符串，逐字见附录） |

| `CreateDefaultOutputVars()` | `ResultImage` → `HImage`；`Result` → **显式 `String`** |
| `CreateDefaultProcedure()` | 组装 `EProcedure`，接口三类列表与上面两张表严格对应 |

```csharp
public static EProcedure CreateDefaultProcedure() => new EProcedure
{
    Name = DefaultProcedureName,
    IconicInputList = new List<string> { "Image" },
    IconicOutputList = new List<string> { "ResultImage" },
    CtrlOutputList = new List<string> { "Result" },
    Body = DefaultBody,
};
```

> 为什么接口列表必须与变量表一致：`EnsureCompiled` 每次编译前会 `SyncInterfaceFromTables(proc)`
> **反向**用变量表覆盖过程接口列表，两者不一致就会互相打架（表现为变量找不到、端口对不上）。

### 2.2 `Plugins\Plugin.ImageScript\ImageScriptPlugin.cs`

`GetConfigView` 加一句预置调用 + 新增两个方法：

```csharp
public object GetConfigView(IStepConfigData stepData)
{
    Initialize(stepData);
    EnsureDefaultScriptIfNeverSaved(stepData);   // ← 新增
    EnsureSelectedProcedure();
    return new ImageScriptView { DataContext = this };
}

/// <summary>配置字典里代表"这个步骤配置过脚本"的键名（= [StepConfig] Procedures 的属性名）</summary>
private const string ProceduresConfigKey = "Procedures";

private void EnsureDefaultScriptIfNeverSaved(IStepConfigData stepData)
{
    // 两个条件都要满足：
    // ① 配置字典里没有 Procedures 键 = 这个步骤从没保存过脚本配置
    // ② 内存里也没有过程 = 用户上次点"取消"留下的未保存内容不该被冲掉
    if (stepData?.InputValues != null && stepData.InputValues.ContainsKey(ProceduresConfigKey))
        return;
    if (Procedures != null && Procedures.Count > 0) return;

    ApplyDefaultScript();
}

public void ApplyDefaultScript()
{
    var proc = ScriptTemplates.CreateDefaultProcedure();

    // 先过程、后变量表：变量表决定动态端口的名字与类型，端口随变量表 setter 重建
    Procedures = new List<EProcedure> { proc };
    SelectedProcedure = proc.Name;

    InputVars = new ObservableCollection<ScriptVarDef>(ScriptTemplates.CreateDefaultInputVars());
    OutputVars = new ObservableCollection<ScriptVarDef>(ScriptTemplates.CreateDefaultOutputVars());
}
```

**「保存过就有键」这条假设的核实过程**（不核实就会变成"每次打开都覆盖用户编辑"的 bug）：

- `VisionPluginBase.EnsureConfigPropsDiscovered()`（L207-219）反射扫描带 `[StepConfig]` 的**所有**属性 → `Procedures`（`[StepConfig] public List<EProcedure> Procedures`）在列；
- `VisionPluginBase.OnConfirm`（L290-292）`foreach (var cp in _configProps) stepData.SetInputValue(cp.Name, SnapshotConfigValue(cp.Get()));` **无条件**写入；
- `StepModel.SetInputValue` 只有 `if (string.IsNullOrEmpty(key)) return;` 一个前置判断 → 键一定落进 `InputValues`。

→ 用户点过一次「确定」（或对含该步骤的流程执行过一次），`Procedures` 键就存在了。

## 3. 默认脚本正文（逐字）

```
* ──────────────────────────────────────
* 默认脚本：1 个图像进 → 1 个图像出 + 1 个结论出
*   Image       输入图像（本步骤的输入端口，需要连上游）
*   ResultImage 处理后的图像（可以直接连给下游）
*   Result      判定结论 'OK' / 'NG'（可以接条件分支）
* 下面这段是「数亮斑个数」的示范，把它换成你自己的算子即可
* ──────────────────────────────────────
* ── 示教参数区：换产品只改这一段，下面代码不用动 ──
* 阈值下限：亮于它的像素算目标（0~255，先看灰度直方图再定，别拍脑袋）
ThreshMin := 128
* 目标最小面积（像素）：比它小的当噪点丢掉
MinArea := 50

* 第1步 彩色转灰度：机器视觉大多在灰度图上做，数据量小一半
* 必须先判断通道数——对单通道图调用 rgb1_to_gray 会直接报错
count_channels (Image, Channels)
if (Channels >= 3)
    rgb1_to_gray (Image, GrayImage)
else
    copy_image (Image, GrayImage)
endif

* 第2步 阈值分割：亮于 ThreshMin 的像素连成候选区域
threshold (GrayImage, Region, ThreshMin, 255)

* 第3步 拆分与筛选：粘连的拆成一个个，再按面积甩掉噪点
connection (Region, ConnectedRegions)
select_shape (ConnectedRegions, Targets, 'area', 'and', MinArea, 1e7)
count_obj (Targets, Number)

* 第4步 判定：数出个数就能判 OK/NG
* 换成测量 / 匹配 / OCR 也是同一套路：先算出来，再和规格比，最后给结论
if (Number > 0)
    Result := 'NG'
else
    Result := 'OK'
endif

* 第5步 画在画布上：脚本结束时会自动回读成效果图送到界面窗口1
dev_display (GrayImage)
dev_set_draw ('margin')
dev_set_line_width (2)
dev_set_color ('red')
dev_display (Targets)
dev_disp_text ('Result: ' + Result + '  数量: ' + Number$'.0f', 'window', 12, 12, 'black', ['box','box_color'], ['true','yellow'])

* 第6步 输出图像：ResultImage 就是本步骤的图像输出端口
ResultImage := GrayImage
```

正文里每个算子的用法都能在 `ScriptTemplates.All` 的既有模板中找到同类写法（`dev_disp_text` 七参写法、`1e7` 上限、`Number$'.0f'` 格式化、字符串拼接、`if/else/endif`），本次只新增两个基础算子 `count_channels` / `copy_image`。

## 5. 已知边界

1. **默认脚本正文的 Halcon 语法未经自动验证**：它是手写的 HDevelop 代码，本次只做了
   逐算子人工核对（对照 `ScriptTemplates.All` 里已被验证过的既有用法），没有跑引擎编译。
   冒烟工程虽已具备「真加载插件 + 真编译执行」能力（见 `WireSequenceCheck`），
   但现有断言不覆盖本插件。**建议首次使用先点一次「执行」确认**，或点编辑器右键菜单「编译（校验脚本）」。
2. **新步骤在没打开过配置窗口之前，端口不存在**：动态输入/输出端口是由变量表长出来的，
   而默认脚本的预置发生在**配置态**（`GetConfigView`），不在编译期（`ApplyConfigValues`）。
   所以流程里刚拖入的步骤要先打开一次配置窗口并「确定」，才能连 `Image` / `ResultImage` / `Result`。
3. **`Image` 必须连线，否则运行直接失败**：`RunAlgorithm` 灌入阶段遇到图形输入未链接会
   `Success=false` + `输入变量[Image]未链接或图像为空` 并**直接返回**（脚本一行都不会执行）。
   这是既有行为，本次未改。
4. **「恢复默认脚本」不可撤销**：确认后整表替换，没有 Ctrl+Z 反悔路径；
   逃生通道是「方案未保存前关窗口」。已保存过的方案被替换后，只能自己重新写回来。
5. **默认脚本只在「从未保存过」时自动补一次**：用户手动删空并保存后，再打开不会自己长回来，
   想找回来得点「恢复默认脚本」按钮。
6. **正文的判定语义是"有亮斑即 NG"**：`ThreshMin=128` / `MinArea=50` 是示范值，
   换产品必须改示教参数区；不改就可能全图判 NG（阈值过低）或恒判 OK。
7. **`script` 过程名固定**：恢复按钮不检查重名（因为它整表替换，替换后只会有这一个过程）；
   但如果用户在同一个步骤里手动新建了别的过程，它们会被替换掉。
8. **阈值不做输入端口**：这是用户选定的方案（Q3「写死在脚本里」），
   想让它变成界面可调参数，需要用户自己在变量表里加输入变量并改正文——不是插件行为。
9. **`guessType` 的兜底仍然存在**：默认变量表是显式声明类型的，但用户后续手动「添加变量」时
   仍走名字启发式（不以 `i`/`s` 开头一律 `Double`），非本次改动范围。
