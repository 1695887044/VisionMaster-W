## 一、需求与决策

### 1. 需求（用户原话）

> 变量绑定界面模板不对
> 对于图元的位置 不需要绑定变量 不是所有变量都需要绑定的
> 现在就你一个任务再跑，你自己启动软件 截图 去完善到商业 Scada 的标准

三条诉求对应四处缺陷。前两处是**用户直接指出的**，后两处是**启动真机截图后自己审出来的**（落实"UI 改动后自审是否美观"）。

### 2. 缺陷与决策清单

| # | 缺陷（真机现象） | 根因 | 决策 |
|---|---|---|---|
| A | 「选择变量」弹窗每一行只显示 `VisionMaster.ViewModels.DialogViewModels.ScadaVariableRow`，五列全丢 | 行容器 `ControlTemplate` 把 `GridViewRowPresenter` 换成了裸 `ContentPresenter`。GridView 的列摆位**全靠** `GridViewRowPresenter` 按 `Columns` 排；换成 `ContentPresenter` 后列布局整体丢失，`ListView` 退化成把数据对象丢给 `ToString()` | 行模板改回 `GridViewRowPresenter`（`Columns="{TemplateBinding GridView.ColumnCollection}"`），并**写长注释钉死"不能用 ContentPresenter"**——这类事故改回来太容易 |
| B | 五列中右侧三列被硬裁（`文本 (String) 数组 [ ]` 被切成 `文本 (String) 数`） | ① 右侧三列用 `DisplayMemberBinding`，WPF 生成的是**裸 `TextBlock`，没有 `TextTrimming`**，放不下就硬裁；② 列宽按"内容区净宽"算，没扣行左右留白 | ① 五列全改 `CellTemplate` + `VariableCellTextStyle`（`TextTrimming="CharacterEllipsis"` + `ToolTip` 看全值）；② 列宽按"净宽 651 − 竖滚动条 17.33 − 行留白 20"重排为 `170/140/80/105/150 = 645` |
| C | 表头与数据**整行错位 4px**（表头压在数据上） | `GridViewRowPresenter` 会给**每个单元格容器内置 `Margin="6,0,6,0"`**，而列头那一侧没有这一层 | 行 `Padding` 取 **4**（4 + 单元格内置 6 = 10，与列头 8px 内边距 + 列头元素右移 2px 相抵）。对齐由断言钉住 |
| D | 图元「位置」X/Y 也带 ƒx 绑定入口 | `GeometryProperties.Standard` 里 X/Y 未显式收掉可绑 | **产品口径：设计期版面语言不可绑，运行期动画语言可绑。** X/Y 是"这个图元画在画面哪儿"的设计期事实，交给变量驱动等于让画面每次刷新自己搬家，操作员会以为界面故障。只留 宽/高/旋转 可绑 |
| E | **绑定成功后 ✕（清除绑定）按钮是 `disabled`**（真机 UI 树实锤：`button "✕" (disabled)`） | `ClearBindingCommand` 的 `CanExecute` 谓词读 `row.HasBinding`，绑完自然是 `true`；坏的是 **WPF 的 `ButtonBase` 只在命令抛 `CanExecuteChanged` 那一刻把可用性抄进 `IsEnabledCore`**。`HasBinding` 从 false→true 时没人抛这个事件，按钮就停在模板实例化那一刻的初值 `false` 上 | 在 `OnElementPropertyChanged`（行状态的**唯一**刷新点）补 `ClearBindingCommand.RaiseCanExecuteChanged()`。**行刷新与命令刷新必须成对出现**，口径才不会分叉 |
| F | 变量带贴着上一行输入框（缝只剩 2.4px），"这条变量归哪一行"说不清 | 变量带 `Margin="0,2,0,1"` 上下留白太紧 | 改 `0,5,0,2`。实测缝 5.4px，分组感出来又不把行距撑散 |

### 3. 口径沉淀

- **E 的判据一句话**：命令的 `CanExecute` 谓词读的是**谁的状态**，那个状态一变就得由**持有该命令的对象**抛一次 `CanExecuteChanged`。谓词返回值对不对是另一件事——`ButtonBase` 根本不主动去问。
- **C 的判据一句话**：行这侧多出来的每一层内边距都要在列宽预算里扣掉；只扣竖滚动条会算出**假余量**，真机上表现为三列被硬裁。
- **D 的判据一句话**：`IsBindable` 不是随手填的默认值，是一条产品口径，注释已写进 `ElementPropertyDescriptor.IsBindable`。

### 3. ⑬ 节：✕ 的"能不能点"为什么要真渲染一遍

⑦ 只验到"命令的 `CanExecute` 返回 true"，可真机上看见的是 `button "✕" (disabled)`。差的那一步藏在 WPF 内部：`ButtonBase` 抄的是"命令抛 `CanExecuteChanged`"那一刻的结论。所以 ⑬ 节把**真机那条时间线原样走一遍**：

1. 先让 ✕ 以"这一行还没绑"的样子被实例化出来（此时初值就是禁用）；
2. 再绑上变量；
3. 然后看**同一颗按钮**自己有没有翻过来。

**反向验证（关键）**：把 `OnElementPropertyChanged` 里的 `RaiseCanExecuteChanged()` 临时注释掉重跑 →

```
[×失败] 绑上之后命令主动抛 CanExecuteChanged：✕ 才会从禁用翻成可用（不抛就停在初值上）  →  抛了 0 次
[×失败] 绑上之后同一颗 ✕ 自己翻成可用（不抛 CanExecuteChanged 就停在初值禁用上，真机实锤）  →  IsEnabled=False / 已绑=True / Speed2
通过: 658  失败: 2
```

`IsEnabled=False / 已绑=True` —— 正是真机那条症状。**断言不是假绿**，恢复修复后回到 660/0。

## 四、已知边界

1. **真机交互复验受锁屏阻断**：`LockApp` 在前台时，UIA 的 `Invoke`/`SetFocus` 一类动作仍可用，但**画布点选、菜单点选这类需要真实鼠标（SendInput）的动作无效**。本节 E/F 的最终真机确认待解锁后补做。
2. **离屏渲染看不到"用户视角"**：`IsVisible` 恒为 false（没接 `PresentationSource`），"看不看得见"只能沿视觉树往上问 `Visibility`（断言里的 `IsShown`）。
3. **列宽是写死的常数**：`170/140/80/105/150` 按当前弹窗尺寸算好。弹窗尺寸若改，这五列要跟着重算——断言"列宽和塞得进内容区"会在那时变红，是**有意的护栏**，不是可以顺手调大的阈值。
4. **`DisplayFormat` / 停用开关仍无界面入口**：`ScadaBinding` 上这两个字段模型已通、运行态已认，但属性面板还没有对应的配置入口（换绑时会保留，用户改不了）。
5. **画面级绑定无入口**：面板的画面模式（未选中图元时）`IsBindable` 恒为 false，画面属性还不能绑变量。
6. **SCADA 新代码尚未纳入版本控制**：`Scada/`、`Scada.Controls/`、`ScadaChecks/`、`VisionMaster/Services/IScada*` 等仍是未跟踪状态。这是当前头号风险。
