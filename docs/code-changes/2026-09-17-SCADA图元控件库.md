# 2026-09-17 SCADA 图元控件库（S2）—— 从"画面文档"走到"能画出来的图元"

## 一、需求与决策

### 背景：S2 在整条链上的位置

S1 交付了画面领域层：`ScadaDocument → ScadaPage → ScadaElement`，图元只带一个字符串 `TypeKey`
和一个 `Dictionary<string,string>` 属性袋（见 [SCADA画面领域层](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA画面领域层.md)）。

这样设计的好处是领域层与序列化层完全不认识任何图元类型；代价是**总得有人回答**：

| 问题 | 谁来回答 |
|---|---|
| `"Hmi.Rectangle"` 是什么？ | 本库的注册表 |
| 它有哪些属性、默认值多少、能不能绑变量？ | 本库的 `ElementDescriptor` |
| `"#FF112233"` 怎么变成画面上的画刷？ | 本库的控件基类（`TypeDescriptor` 转换） |
| 它在画布上长什么样？ | 本库的 `Themes/*.xaml` |

**S2 就是这一层**：`Scada.Controls` 图元控件库。

用户长需求里对本阶段的约束：商业级、可扩展控件、模块化、**以长期可扩展性为最高优先级**、
每阶段都要"暴力测试"、与既有数据源无缝对接。

### 决策一：落点与依赖方向

```
Core（领域 + .vms 序列化）
  └─▶ Scada（画面领域层，S1）
        └─▶ Scada.Controls（图元控件库，S2）
              └─▶ （将来）VisionMaster 应用 / 组态编辑器（S3）
```

| 规则 | 理由 |
|---|---|
| 工程目录与 `Scada\` **平级**（`Scada.Controls\`），**不建在 `Scada\` 里面** | SDK 风格工程的编译范围是**工程目录树**，子工程长在父工程目录里会被父工程默认 glob 当成源码吞掉（同一份 .cs 被两个工程编译，还会因 `ThemeInfo` 等特性重复定义而炸） |
| `net9.0-windows` + `UseWPF=true`，**不引用任何 UI 工程** | 本库要能在纯净宿主里单独加载：自带 `Themes/Generic.xaml`，靠 `ThemeInfo(..., SourceAssembly)` 自解析默认样式 |
| `RootNamespace = VisionMaster.Scada.Controls` | 与目录名 `/VisionMaster.Scada.Controls.…;component/…` 的 XAML 资源路径一致 |
| 依赖方向**只向下**：`Scada.Controls → Scada` | 领域层不知道"怎么画"，本层不知道"谁来编辑"；S3 编辑器引用本层，本层永不回头引用编辑器 |

### 决策二：描述符是"单一事实来源"，而不是接口 + 实现类

每个图元一条 `ElementDescriptor`（**数据**），而不是一个 `IElementDescriptor` 实现类（**行为**）：

- 图元之间的差异全在**数据**上（键、默认值、目标依赖属性），行为差异在**控件类**里；
- 做成接口只会得到一个"字段声明比接口方法还多"的类，白白多一层间接；
- 将来第三方扩展图元库时，他们提供的也是同一个类的实例，不需要引用我们的接口程序集。

`ElementDescriptor` 一次声明四件事，四个消费者共用一份：

| 字段 | 消费者 |
|---|---|
| `TypeKey` / `DisplayName` / `Category` / `Description` | 工具箱（S3） |
| `DefaultWidth` / `DefaultHeight` | 放置图元时的初始尺寸 |
| `ControlType` | 注册期校验 + `Activator` 造控件 + 将来的拖放预览 |
| `Properties`（`ElementPropertyDescriptor` 列表） | 属性面板、绑定引擎、**控件自身的默认值回落** |

关键定案：`ElementPropertyDescriptor.TargetProperty` 存的是**真的依赖属性对象**
（`DependencyProperty`，不是字符串名）。存名字要反射解析、拼错只在运行期静默失效；
存对象则注册期就能校验"这个 DP 到底挂不挂得上这个控件类型"。

### 决策三：属性字符串 ↔ 依赖属性，只有一条换算路径

```
模型属性袋 ──Refresh()──▶ 依赖属性
   ▲                          │
   └─（不回写）────────────────┘
```

- **单向**：控件只读模型、不回写。绑定引擎与属性面板是唯一的写入口（S3/S4），
  控件不做"我改了所以模型也改"的猜测——否则拖一下滑块模型就脏了，撤销栈会爆炸。
- **换算集中**：字符串 → 目标类型统一走 `TypeDescriptor.GetConverter(dp.PropertyType).ConvertFromString(InvariantString)`。
  颜色、`FontWeight`、枚举全是同一行代码，不为 Brush 写特例分支。
- **两条刷新路径合一**：直接 `new RectangleElement { Element = model }` 与
  `ElementRegistry.CreateControl(model)` 结果完全一致——后者只做"造 + 绑"，落地逻辑只有一处（断言已覆盖）。
- **脏值不抛异常**：`Fill = "#GGGGGG"` 这类值转不动就保持现状。一个坏值不该让整页渲染中断
  （工业现场宁可看到一个颜色不对的框，也不要整块画面空白）。

### 决策四：`$` 保留键与几何字段

几何（`$Name/$X/$Y/$Width/$Height/$Rotation`）**不进属性袋**，直接读写 `ScadaElement` 的强类型字段：

| 规则 | 理由 |
|---|---|
| 属性袋键不得以 `$` 开头 | 保留前缀给几何；写错的保留键（`$Widht`）直接丢弃，既不生效也不躺在袋子里 |
| 几何写负数取绝对值 | 模型约定宽高恒正；负数只会来自脏数据，取绝对值比"写 0"更接近用户意图 |
| 几何写非法数值保持原值 | 不写 `NaN`（会把整个布局算崩），也不用 0 顶替（图元会消失得莫名其妙） |
| 数值格式用 `"0.######"` + `InvariantCulture` | .vms 要跨机器交换，小数点不能跟着区域设置走 |

### 决策五：控件范式与主题

- 自定义控件范式：`ScadaElementBase : ContentControl` + 静态构造 `DefaultStyleKeyProperty.OverrideMetadata`；
- **`ThemeInfo(ResourceDictionaryLocation.None, ResourceDictionaryLocation.SourceAssembly)`** 必须显式声明，
  否则控件会以"裸 Control"出现且**不报任何错**（最难查的一类问题）；
- 主题 XAML 里的资源引用**必须程序集限定**写法：`/VM.Scada.Controls;component/Themes/….xaml`；
- 形状用 `Rectangle`/`Ellipse` 画，**不用 `Border`**：`Border` 会把 `Thickness` 拖进类型转换链，
  在我们的字符串换算里不值得；
- 边框线宽内缩：`ApplyStrokeInset(半线宽)` → 模板用 `Margin` 内缩，避免"100 宽的框视觉变成 103"；
- 旋转：`RenderTransformOrigin = (0.5, 0.5)`（转轴随尺寸走），角度归零时**摘掉** `RenderTransform`
  （不在可视树上留恒等变换）。

### 决策六：订阅跟随"Element 非空 且 IsLoaded"单一条件

`SyncSubscription()` 只在两个条件**同时**成立时订阅模型、否则退订：

- 未挂可视树的控件不订阅（文档对象不会反过来"钉住"控件，避免内存泄漏）；
- 挂载时 `Loaded` 补一次 `Refresh()` 追上离树期间的模型变化；
- 单一条件而不是分散在多个回调里判断，避免"某条路径忘了解除订阅"。

### 断言抓到并修掉的真 bug（本次最重要的收获）

第一次跑断言时，**5 个内置图元全部注册失败**：

```
[×失败] 内置图元在类型初始化时自注册 → Hmi.Rectangle.Foreground 的目标属性 TextElement.Foreground 不在 RectangleElement 上
[×失败] 5 个内置图元全部注册
```

根因：`ElementDescriptor.Validate()` 原本用

```csharp
if (!dp.OwnerType.IsAssignableFrom(ControlType))   // 错
```

而 WPF 的 `Control.Foreground` / `FontSize` / `FontWeight` **实际是 `TextElement` 的同名属性经
`AddOwner(typeof(Control))` 挂上来的**——`DependencyProperty.OwnerType` 永远停在最初的声明者
`TextElement`，可它们在任意 `Control` 派生类上都完全可用。于是"派生关系"这个判据把合法属性判成了非法。

修复（见 [ElementDescriptor.cs](file:///e:/VM/VisionMaster-W-master/Scada.Controls/Descriptors/ElementDescriptor.cs#L174-L199)）：
先看派生关系，再交给 WPF 本体回答——

```csharp
private static bool IsPropertyOn(DependencyProperty dp, Type controlType)
{
    if (dp.OwnerType.IsAssignableFrom(controlType))
        return true;

    try
    {
        dp.GetMetadata(controlType);   // 天然沿继承链查找，AddOwner 挂上来的也认
        return true;
    }
    catch (ArgumentException)
    {
        return false;
    }
}
```

连带后果：注册全失败后，紧接着的 `CreateElement("Hmi.Rectangle", …)` 抛
`InvalidOperationException` 把断言进程直接打挂（后续 Section 一条都没跑）。修好校验后全部转绿。

**这正是"注册期自检"要挡的那类静默失败**：不修的话程序能启动、能打开画面，
只是所有图元都渲染成模板默认样子，现场只会说"颜色配置没生效"。

## 四、已知边界

| 边界 | 说明 | 归属 |
|---|---|---|
| 图元尚无交互 | 选中、拖拽、缩放手柄、右键菜单一律没有；`Hmi.Button` 不带 Click 语义 | S3（编辑器）/ S4（运行态） |
| 未接绑定引擎 | 本层只做"属性袋 → 外观"，不做"变量值 → 属性袋"；`ScadaBinding` 尚未被消费 | S4 |
| 未接变量→控件驱动 | 没有定时器/事件驱动的刷新，运行态的刷新节流策略未定 | S4 |
| 自定义控件模板较简 | 只有填充/边框/文字/旋转，没有阴影、渐变、位图、动画 | 按需扩 |
| 未接入主程序 | `VisionMaster` 应用尚未引用本库（编辑器面板还不存在，引用了也无处显示） | S3 |
| `ElementRegistry.Register` 不幂等 | 重复注册返回"已注册"失败原因；外部扩展图元需自行保证只注册一次 | 设计如此 |
| 属性面板编辑器类型 | `ElementPropertyKind` 已备好（Color/Number/Bool/Text/Choice/MultilineText…），但**面板控件与范围校验（Min/Max）尚未实现** | S3 |
| 性能 | 断言只覆盖到"1 万图元 + 2 万绑定"的**模型层**吞吐；**万级图元的渲染帧率与虚拟化尚未测** | S3/S5 |

## 五、经验清单（写给下次的自己）

1. **SDK 工程的编译边界 = 工程目录树**。子工程绝不能长在父工程目录里，否则被父工程默认 glob 吞掉，
   两个工程编译同一份 .cs（`ThemeInfo` 等特性会重复定义）。
2. **主题资源引用必须程序集限定**：`/VM.Scada.Controls;component/Themes/….xaml`；
   同时 `ThemeInfo` 不能省——缺了不报错，只是控件变成"裸 Control"。
3. **依赖属性必须"字段 + CLR 包装属性"成对**，只写 `Register` 不写包装属性，同文件里引用就是 `CS0103`。
4. **画形状用 `Rectangle`/`Ellipse`**，别用 `Border`——后者会把 `Thickness` 拖进类型转换链。
5. **不要用 `dp.OwnerType` 判断"属性挂不挂得上某个类型"**：`AddOwner` 只改注册表、
   不改 `OwnerType`，`Foreground/FontSize/FontWeight` 都是这类。判据应当是
   `dp.OwnerType.IsAssignableFrom(t) || dp.GetMetadata(t)`（本次 bug）。
6. **断言宿主 `Main` 不是 STA**，WPF 控件层断言必须另起 `SetApartmentState(ApartmentState.STA)` 线程跑，
   异常经闭包变量回传为失败断言（比把 `Main` 标 `STAThread` 更好：不动既有断言的运行环境）。
7. **类型模式 `is X and not Y` 要求 X 能赋给 Y**，两个无继承关系的类型直接写会 `CS8121`；
   跨类型判断要用 `typeof(Y).IsAssignableFrom(x.GetType())`。
8. **保留前缀约定要"丢弃"而不是"转义"**：写错的 `$Widht` 既不生效、也不该躺进属性袋等以后被读出来。
