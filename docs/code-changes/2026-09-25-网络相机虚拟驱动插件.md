# 网络相机（虚拟）驱动插件 Plugin.Camera.Network

「图像采集插件增加相机采集功能」任务的**驱动层**部分。契约层（`ICameraDevice` / `CameraDeviceBase` /
`CameraDescriptor` / `CameraSettings` / `CameraFrame`）已先行完成，本文件只覆盖驱动的落地。

---

## 一、需求与决策

### 1. 需求

新建独立驱动插件工程 `Plugins\Plugin.Camera.Network\`，实现"网络相机（虚拟）"驱动：
由外部客户端按 HTTP 协议推图，用于**无硬件时验证采集链路**。

### 2. 决策

| 分支 | 结论 | 理由 |
|---|---|---|
| 目标框架 | `net9.0`（不带 `-windows`） | 驱动层不碰 WPF、不碰 Halcon、不碰 Windows 专有 API；框架依赖越窄越好 |
| 依赖 | 只引用 `Shard\Core.Interfaces` | 帧全程以 `byte[]` 流转，`HImage` 生成留给消费者；不引 halcondotnet 就不会被 HALCON 版本绑死 |
| 基类 | 继承 `CameraDeviceBase` | 环形队列 / 状态机 / 心跳看门狗已由基类固化，驱动只写差异点 |
| 投递 | 复用 `Plugins\Directory.Build.targets` | 该文件已统一把插件 DLL 投到仓库根 `Modules\`，无需 PostBuild、无需写进 .sln |
| 包装方法 | **不写** | `PushFrame` / `NotifyAlive` 已在 `ICameraDevice` 接口上 public，宿主可直接经接口调用，包一层是纯冗余 |
| 编译开关 | `ImplicitUsings=enable` + `Nullable=enable` | 与 `Plugin.Util.csproj`、`Core.Interfaces.csproj` 保持一致 |

### 3. 驱动的差异点（= 需要重写的成员）

基类里 `OpenCore` / `CloseCore` 是 `abstract`，必须重写；其余六个差异点都是 `virtual`，本驱动逐一重写并写明理由：

| 成员 | 网络相机取值 | 关键理由 |
|---|---|---|
| `RequiresHeartbeat` | `true` | HTTP 无连接、没有 SDK 掉线回调，只能靠"多久没收到证据"推断；不重写则客户端消失后界面永远停在"在线" |
| `StateAfterOpen` | `Connecting` | Open 只是"收图服务开始接受该序列号的帧"，客户端可能还没来；标成 Online 就无法区分"没接入"与"接入了没触发" |
| `OpenSuccessDetail` | `等待客户端接入（序列号 xxx）` | 客户端按序列号寻址，界面显示它可直接核对接入失败最常见的原因 |
| `OpenCore` | `true` | 无物理句柄可开；返回 true 才能让基类推进到 Connecting 并启动看门狗 |
| `CloseCore` | 空实现 | 驱动侧无句柄/内存/线程可释放；基类在 Close/Dispose 都会调用，抛异常会把正常断开渲染成故障 |
| `ApplySettingsCore` | `true` | 曝光/增益/触发由客户端决定，软件侧无下发通道；返回 false 会让"已保存的配置"报成失败 |
| `StartStreamCore` | `true` | 帧由客户端送来，软件侧无法命令其开始；基类此前已把状态推进到 Streaming |
| `StopStreamCore` | 空实现 | 停止语义由基类的"收帧闸门 + 清空队列"落地，驱动侧无句柄可停 |

> 注：`FrameTimeoutMs` / `BufferCapacity` / `HeartbeatTimeoutMs` 三项对网络相机**真实生效**——
> 它们不由硬件消费，而是基类自己消费（等图超时 / 环形队列容量 / 心跳判活阈值）。

## 四、已知边界

1. **驱动本身不实现 HTTP 收图**。真正"收 HTTP、解像素、调 `PushFrame`"的是宿主的收图服务
   （`NetworkCameraServer`）；本驱动只负责被推、被取、判活。
2. **未登记进 `VisionMaster.sln`**，宿主扫描 `Modules\` 可装载；若需 IDE 内整体构建，仍需后续统一登记。
3. **无真机联调**：验证仅到"编译 + 投递"，尚未跑通"客户端推图 → `WaitNextFrame` 取到帧"的端到端冒烟。
4. **`ApplySettingsCore` / `StartStreamCore` / `StopStreamCore` 的重写行为与基类默认实现完全一致**，
   保留它们只是为了让"网络相机为何无需动作"这条设计说明留在驱动文件里；若后续判定为冗余可整体删除，行为不变。
