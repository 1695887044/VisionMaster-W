# 软件级操作记录（SQLite）

## 当前状态

引入 SQLite 记录**软件级核心操作**（跨方案、跨重启、跟机器走）。方案级（资产历史、生产记录、报警）
**不放进这张表**——它们必须跟方案走，混进来会让库无限增长且方案换机就断链。

## 已做

### 1. 契约（`Core.Interfaces/Operations`）

- `ISoftwareOperationEntry` 的字段：时间 / 机器 / 版本 / 操作者 / 角色 / 分类 / 动作 / 结果 /
  对象 / 对象 Id / 方案 Id / 方案名 / 明细。
- `SoftwareOperationLogHost.Current`：**进程级静态出口**。
  为什么不用构造注入：`AppSettingsService` 在 Core 层、`new ScadaAccessPolicy()` 遍布各处，
  全加一个构造参数改动面远大于收益，而且漏传一处就是"这条永远不记"（静默缺失比没有更坏）。
- `SafeRecord(...)`：填字段 + 记录，**任何异常都吞掉**。

### 2. 实现（`Services/Core.Database/SqliteSoftwareOperationLog.cs`）

- 表 `software_events` + 三个索引（category/ts、actor/ts、solution_id/ts）。
- **fail-open**：建库失败就整体停用并 Warn 一次，之后每次调用直接返回，不反复撞同一个错。
- **WAL + synchronous=NORMAL**：写不挡读（Web 端可能并发读）。仅适用于本地磁盘。
- **保留期复用 `AuditRetentionDays`**（默认 90 天），初始化时清一次。
- `Query(category, actor, solutionId, limit)` 供断言与后续界面共用。
- 放在 `Core.Database` 而不是宿主：**Provider（Microsoft.Data.Sqlite）只允许出现在这一层**
  （仓里的既有约束），宿主只做装配。

### 3. 落库位置

`<程序目录>\Data\operations.db`——与 `AppConfig.json` / `Audit\` / `databases.json` 同一约定。
不为这一个文件单独引 `%ProgramData%`：那会造成"一半配置在程序目录、一半在系统目录"。

### 4. 已接的调用点（5 处）

| 分类 | 动作 | 位置 |
|---|---|---|
| Lifecycle | 启动 / 退出 | `App.OnStartup` / 退出链任务 |
| Lifecycle | 未处理异常 | `App.OnDispatcherUnhandledException` |
| Identity | 登录成功 | `ScadaAccessPolicy.Login(ScadaUserInfo)`（手动/调试自动/切方案重验同一出口） |
| Identity | 登录失败（拒绝） | `ScadaLoginViewModel.OnLogin`（策略看不到密码错误） |
| Identity | 登出 | `ScadaAccessPolicy.Logout()`（手动/超时/切方案/强制同一出口） |
| Solution | 打开 / 关闭方案 | `SolutionSessionCoordinator.HandleSolutionSwitchedCore` |
| Settings | 保存系统参数 | `AppSettingsService.Save` |

登录成功放在策略里、失败放在弹窗里：**策略永远看不到"密码错了"**，
而弹窗也不该重复记成功（否则一次登录两条）。

## 验证

探针新增 `RunSoftwareOperationLogChecks`，12 条断言全部通过：

- 写 → 查：人/结果/动作/方案归属/明细/机器名原样保存；
- 按分类、按操作者、按方案筛选各自准确；不带条件返回全部；
- 保留期：30 天前的行被清掉、未过期的保留；
- **fail-open**：库路径不可建（父路径是个文件）时，记录/查询/清理**都不抛**，
  且有 Warn 可查、`DatabasePath` 报告"没有库"；
- 实现抛异常时 `SafeRecord` 也吞掉；
- **真实调用点**：`ScadaAccessPolicy.Login/Logout` 与 `AppSettingsService.Save`
  确实把「登录成功」「登出」「保存系统参数」写进了库。

## 踩过的坑

1. **命名空间解析**：`Core.Database.X` 写在 `namespace VisionMaster.*` 里会被解析成
   `VisionMaster.Core.Database`，必须靠文件顶部的 `using`（或 `global::`）。
2. **`AppSettingsService.Current` 是实例属性**，启动早期容器还没建好：
   保留期用 `Func<int>` 懒取，取不到就 90 天（不清空任何历史）。
3. **登录成功不能记在弹窗里**：调试自动登录、切方案重验都不走弹窗，
   记在弹窗会漏掉这两条最需要留痕的路径。

## 未做 / 已知边界

- 表里没有"软件卸载/升级"事件（升级流程本身还没有）。
- 权限变更（用户增删改、分组变更）尚未接；`SolutionSessionCoordinator` 已有
  `HandleUserChanged` / `HandleGroupChanged`，接进去是下一步的小改动。
- 安全动作（急停/回零/使能）尚未接——它们走运动服务，需要单独的接入点。
- 没有界面：目前只能用 SQLite 工具或 `Query` 接口看。方案级 DB 做完后再一起做"操作记录"页。
- 软件级库与方案级库是两套；方案级（资产版本历史、生产记录）还没开始。
