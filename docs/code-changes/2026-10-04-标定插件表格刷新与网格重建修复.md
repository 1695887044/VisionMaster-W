## 二、改动清单

### 2.1 ① 表格编辑即时刷新质量区（原 P1-2）

`CalibrationPlugin.cs`：

| 位置 | 改动 |
| --- | --- |
| `PointRows` setter（`:143`） | 改为：摘旧集合订阅 → `SetProperty` → 挂新集合订阅 → `RebindPointRowSubscriptions()` → `RefreshStatus()` |
| `OnPointRowsCollectionChanged`（`:164`，**新增**） | 集合增删时逐行挂/摘 `PropertyChanged` |
| `OnPointRowChanged`（`:180`，**新增**） | 行内数值变化 → `RefreshStatus()`；**只认 `MachineX/MachineY/ImageRow/ImageCol` 四个属性** |
| `RebindPointRowSubscriptions`（`:189`，**新增**） | 先摘后挂，供反序列化进来的行补挂 |
| 构造函数（`:368`） | 补 `_pointRows.CollectionChanged += OnPointRowsCollectionChanged;` |

- **病根**：`PointRows` 只挂了**集合级** `CollectionChanged`，**逐行的 `PropertyChanged` 从未订阅**。拖动标记路径由 `OnMarkerChanged` 显式调 `RefreshStatus()`（`:995`），手工填表没有任何人通知 → 质量区与残差列停在旧值，要切一次模式或点「重建网格」才更新。
- **两个易错点**（都写进了代码注释）：
  1. `OnPointRowChanged` **只认四个坐标属性**——`ApplyRowResiduals`（`:576`）会回写 `ResidualPx`，若把该属性也算进来，就会"重算 → 回写残差 → 再重算"递归；
  2. 构造函数必须补一行——**字段初始化不走 setter**，缺这步在"从未经过 setter 的实例"（如新建步骤）上会静默失效。

### 2.2 ② 网格缩小不再"半途而废"（原 P2-2）

`CalibrationPlugin.cs` `RebuildGrid(bool preserveValues)`（`:745`）：

- 缩表分支改为**先扫描再删**：从 `target` 起逐行检查，遇到第一个非空行就**整表保持原样**并提示（`:755-765`），一行都不删；
- 提示文案同步改为可操作形式（`:761`）：
  `网格缩小会把已有的第 {i+1} 行（{Name}）丢掉：请先清空该行或改回 {oldN}×{oldN}`。

**原缺陷**：边删边判——删到第 k 行发现非空才退出，此时前几行已经删掉，留下一个**既不是旧尺寸也不是新尺寸**的表，而且提示里报的行号（`i+1` 按当前已删短的集合算）与实际要丢的行对不上。

### 2.3 ③ 网格规模下拉覆盖 clamp 全范围（原 P1-1）

`CalibrationPlugin.cs:311`：

```csharp
public int[] GridSizeOptions { get; } = Enumerable.Range(2, 9).ToArray();   // 原 { 3, 4, 5 }
```

- **原缺陷**：`OnGridSizeChanging`（`:108`）允许 clamp 2~10，主文档 §4.3 差异表第 5 条也写了"下拉 3/4/5 + 手填 clamp 2–10"，但该 ComboBox（`CalibrationView.xaml:138-142`）**非 `IsEditable`**，用户**无法手填**——N=2（4 点最小覆盖）与 6~10 实际不可达；且从旧方案载入 `GridSize=6` 时，下拉框因值不在候选项里而显示**空白**。
- 修法即把候选集与允许范围对齐为 2~10（9 个值）。

### 2.4 ④ 预览载入轮次号缺口（原 P2-4）

`CalibrationPlugin.cs` `EnsurePreviewLoaded`（`:661`）空路径分支补 `_previewLoadId++`（`:666`）：

- **原缺陷**：清空路径时未递增轮次号，此前发出的后台读图完成时守卫 `loadId != _previewLoadId`（`:714`）仍成立 → 已清空的预览**"复活"**。
- 与「坐标变换」插件同类问题**同一修法**（`PoseTransformPlugin.cs:835`，该处注释即"丢弃任何在途的预览载入，防止旧图复活"）。

## 六、补记（2026-10-05）：网格缩小建议值向上取整 + 断言口径修正

**起因**：修完 ②（先扫描再删）后，拒绝缩表时给的建议值用 `Round(Sqrt(行数))` 反推 N×N——**粘贴扩容出的"非平方行数"下会给出放不下全部行的假建议**：12 行时 `Round(√12)=3`，提示"改回 3×3"，但 3×3=9 < 12，用户照做仍会被拒（循环）。

**修法**（`CalibrationPlugin.cs` `RebuildGrid` 内）：
- 建议值改为 `Ceiling(Sqrt(行数))`（clamp 2~10），文案改为「请先清空该行，或把网格规模调到 {fitN}×{fitN}」；
- 行数超 10×10 上限（100）时改提示「当前 N 行超过 10×10 网格上限，请先清空多余的行」。

**断言**：
- 原 #27 修订为「拒绝缩小时给出可操作提示（含能容纳全部行的 3×3 建议）」；
- 新增 #57「非平方行数被拒缩时建议向上取整（12 行 → 4×4 而非 3×3）」；`[CAL]` 段 56 → **57 条**（计数口径见主文档 5.5）。

**证据**（实测输出）：
```
[√通过] [CAL] 拒绝缩小时给出可操作提示（含能容纳全部行的 3×3 建议）
        →  网格缩小会把已有的第 5 行（P5）丢掉：请先清空该行，或把网格规模调到 3×3
[√通过] [CAL] 非平方行数被拒缩时建议向上取整（12 行 → 4×4 而非 3×3）
        →  行数=12 文案='网格缩小会把已有的第 5 行（P5）丢掉：请先清空该行，或把网格规模调到 4×4'
```

**连带**：`CalibrationMath.Solve3` 的死守卫注释订正——`Math.Abs(det) < double.Epsilon` 与 `det == 0` 等价（double 最小正值即 epsilon），直白写出避免误读成"近零守卫"；无行为变化。

**验证**：

- `[CAL]` 段 **57/57 通过**（`FlowCanvasChecks` 全量 1112 通过 / 19 失败，19 项仍为未触碰模块的预存环境问题）；
