# 项目资产：文件版本库与回滚 / 胶路配方资产 / 配方内容编辑 / 插件端到端验证

## 当前状态

上一轮列的"还剩"全部做完，并按用户要求补了**源头插件与消费插件的端到端验证**：

1. 文件资产（模板/模型/图像）有版本库，能导入新版本、能真回滚；
2. 胶路（BeadInspect）配方可以作为方案资产，插件按 AssetId 取用；
3. 文本/胶路配方可以在资产页直接编辑；
4. 五个消费插件 + 一个源头插件的契约与运行期行为都有断言（含"归档后被拒""格式不匹配被拒"）。

## 已做

### 1. 文件版本库（`Assets/Versions/{kind}/{assetId}/v{n}{ext}`）

- 每个版本都留一份文件本体：**只存哈希的话"回滚"只能是空话**。
- 导入 v1 时就归档 v1；`TryImportNewVersion` 先归档旧文件再换活动文件（归档失败就不动活动文件，
  避免"旧的没了新的没进来"）。
- 同内容再导被拒（不白占版本号）。
- `TryRestoreStoredVersion`：把版本库里的文件复制回活动路径，版本号 +1（历史只追加），
  回滚结果也进版本库（下次才能再回滚到它）。
- `TryRollback` 按类型分派：标定还原 Transform、文件资产还原文件、配方还原内容。
  文件资产不再"明确拒绝"，而是真的还原；只有"版本库早于该功能、没有文件本体"的旧记录才拒绝，
  并写清原因。

### 2. 胶路配方资产（`RecipeDefinition.ContentFormat = "bead"`）

- 新增 `ContentFormat`（`text` / `bead` / 空=参数配方）。**必须显式给**：
  只靠"能不能解析"猜，会把胶路库当颜色表喂进去，报出与真实原因无关的错。
- `ProjectAssetRef.ContentKind` 直接反映它；`TryResolveContent(..., "bead", ...)` 做形态校验。
- 配方导入：`.json` 且形状是 `[{Name, RefPointsJson}, ...]` → bead；`.txt/.csv/.tbl` → text。
- `BeadInspectPlugin`：`RecipeAssetId`（`IAssetIdConfig`，Kind=recipe），运行期解析覆盖步骤内
  `RecipeLibraryJson`；解析失败直接 Fail（不静默用旧库）。

### 3. 配方内容编辑

- 资产页「概览」里，文本/胶路配方出现「配方内容（可直接编辑）」编辑框 + 「保存配方内容」。
- 保存前校验：非空、内容有变化、胶路必须是合法 JSON 数组；冻结的配方拒绝写入。
- 保存走 `TryRecordVersion`（递增 ContentVersion + 一条版本记录）。

### 4. 端到端验证（探针内）

**契约层**（每个消费插件都要过）：
- `AssetKind` 正确（template / model / image / recipe）；
- `AssetId` 能写回插件自身字段、能清空（退回旧路径）；
- 配置壳下拉能选到这类资产（`PluginConfigShellViewModel.BuildAssetOptionsFor` 抽成静态方法才可断言）。

**运行层**：
- **图像采集全链路**：导入 PNG → 插件按 `ImageAssetId` 解析 → `Success=true`、产出 HImage、
  `CurrentFilePath` 指向资产解析出的真实绝对路径。
- **归档拦截**：同一插件在资产归档后 `Success=false`，`ErrorMessage` 点名「已归档」，**不抛异常**。
- **格式不匹配**：颜色检查拿胶路库 → `内容形态是 bead，这里需要 text`；
  胶路检查拿文本配方 → `内容形态是 text，这里需要 bead`；两者都不抛异常。
- **模板/模型**：插件口径能解析到真实文件；归档后被拒。
- **文件版本**：v1 进版本库 → 导 v2（活动文件换新、v1 仍在）→ 回滚到 v1 后**文件内容真的是 v1**
  （不看版本号自增）→ 回滚结果进版本库 → 冻结时回滚被拒。

### 5. 顺带修的两个并发缺陷

- `AppSettingsService.Save` 的临时文件改成 `AppConfig.json.<pid>.tmp`：
  两个宿主实例同时跑时共用一个 `.tmp` 会互相锁住，症状是"保存配置失败 + 未处理异常"直接崩进程。
- （上一轮已修）`run_gates.ps1` 的 raw 输出带 PID。

## 踩过的坑

1. **`HImage` 没有 6 参构造**：造 RGB 图不能 `new HImage("byte",w,h,0,"rgb",bytes)`，
   直接读真实彩色 PNG 更省事也更真实。
2. **`InputPort.Value` / `OutputPort.Value` 是 object**：断言里要用 `TypedValue`，
   否则 `!port.Value` 与 `port.Value.Contains(...)` 都编不过。
3. **版本记录必须"每次变化立刻写"**：事后再补，两条记录都会拿到当时的版本号（都是 v2），
   "回滚到 v1"就无从选起。
4. **`Run.Text` 默认 TwoWay**（R159）：绑只读属性必须 `Mode=OneWay`，否则 XAML 加载期抛异常。
5. **并行会话的中间态会污染门禁**：`DeformableMatchingChecks` 未落盘、`CodeReader.MeasureImage`
   未实现、`Plugin.CodeReader` DLL 陈旧——这些都不是本轮改动，只能等对方落定后复跑。
