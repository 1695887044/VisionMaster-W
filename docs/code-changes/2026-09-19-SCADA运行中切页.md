# SCADA 多画面导航与运行中切页（S8）

- 日期：2026-09-19
- 路线图：`docs/SCADA商业级交付路线图.md` → S8「多画面导航与运行中切页」
- 前置：S5（事件 → 动作分发，已留 `Navigate` 枚举位）、S6（运行态数据泵 + 写变量动作接通）均已完成并全绿

## 一、需求与决策

### 需求

S5 里「切换画面」这个动作是**能配、能落盘、但执行不了**的：属性面板能选这个类型，但目标画面选不了（没有 UI），
执行侧只会照实警告一句「切换画面要等画面导航（S8）接入，本条未执行」。S8 的任务就是把这笔欠债还掉：

1. 让「切换画面」真能切——运行态能在画面之间走，且走得干净；
2. 切页时**旧页的绑定必须全摘、新页的绑定再建**（与 S6 的 binder 同一处收口）；
3. `Unloaded`（旧页）→ `Loaded`（新页）的顺序与幂等：连点两下不能触发两次 Loaded；
4. 页栈深度与回退（`GoBack`）；
5. 补齐配套的编辑界面（属性面板选目标画面 + 画面选择弹窗）。

### 决策（逐条）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 1 | 导航能力住在哪 | `ScadaRuntime` **兼作** `IScadaNavigator` 的实现者（`class ScadaRuntime : BindableBase, IScadaNavigator`） | 「该显示哪一页」是产品规则不是渲染细节，必须能被无界面的 `ScadaChecks` 钉住；规则只写一份，宿主壳子不复制 |
| 2 | 分发器（长命单例）怎么够到会话（短命对象） | 单设薄适配 `ScadaNavigator`：`Attach(ScadaRuntime?)` 记住"此刻是谁"，`Navigate` 转交 | 分发器是容器单例（只依赖日志与值源），会话每次点"运行"现建、关窗口作废；中间必须有人记住"现在是谁" |
| 3 | 出口的空会话语义 | 没挂会话时 `Navigate` 返回 `false` + `reason = "运行已经结束"`，安静返回不抛 | 与 `RegistryScadaValueSource` 同一个角色（薄适配 + 空实现安静返回）；关窗口的收尾与迟到的动作撞上也不出事 |
| 4 | 出口读会话的时序 | 先取字段快照到局部变量，再判空，才调用 | `Attach(null)` 可能就发生在下一行（关窗口收尾），用字段直接调会炸空引用；快照语义 = "这一次点击归谁处理" |
| 5 | 切页通道 | 单设一条：首帧前走 `ContentRendered`（还要测耗时），首帧后走 `SchedulePageAfterLayout`（`DispatcherPriority.Loaded`） | `ContentRendered` 在窗口生命周期内只来一次；运行中切页必须另找"这一页的布局跑完"这个等价信号 |
| 6 | 连点两下的幂等 | 目标就是当前页时：**返回 `true` 但什么都不做**（不重发 Loaded、不压栈） | 「目标状态」语义：要的状态已成立；"点了两下"和"画面被删了"在日志里必须是两句话，不能都叫失败 |
| 7 | 切页事件顺序 | 旧页 `Unloaded` → 换 `CurrentPage` → 新页 `PageLoaded`，各发一次 | 两条钩子都可能写同一个变量（旧页复位、新页置位），顺序反了最终值就错，且只在配了两条钩子的工程上复现；卸载发在换 `CurrentPage` 之前，卸载钩子还能读到旧页 |
| 8 | 页栈上限 | `MaxPageStackDepth = 32`，超限从**栈底**丢最老的一页 | 运行态可以来回跳（A→B→A→B…），这是唯一随操作时长增长的集合，而组态软件要连开几个月；32 层足够覆盖任何真实层级 |
| 9 | `Stop` 补发 `Unloaded` | 先关运行开关 → 补发当前页 `Unloaded` → 最后清 `CurrentPage` + 清页栈 | 用户在卸载事件上配的收尾动作（写变量、记日志）得在会话还活着时跑完，否则"停止运行"会静默丢掉最后一件事；先关开关顺带挡住"卸载里再切页" |
| 10 | 目标页寻址 | Id 优先、名字兜底，只认**本方案里**的画面；寻址交给 `ScadaDocument.FindPage / FindPageByName` | 与变量寻址同一口径，忽略大小写规则只该有一份实现；运行态不自己遍历画面 |
| 11 | 野生副本 | `Navigate(ScadaPage?)` 按**引用**比对（`ReferenceEquals(_document.FindPage(page.PageId), page)`） | Id 相同但不是文档里那一份对象的，是个野生副本，切过去不会被画布渲染，只会留下"看着像成功了"的假象 |
| 12 | 回退遇到已删页 | `GoBack` 弹到已不在文档里的页就丢掉继续往下找，到底都没有返回 `false` | "回退按钮点了没反应"比"回退到一个已经不存在的画面"好排查得多 |
| 13 | `PendingReason` | `Navigate => null`（保留 switch 分支，让"已接通"在代码里显式可见） | 面板那行橙色提示与运行日志逐字同源，接通了就必须一起消失；三条动作现已全部接通 |
| 14 | 「选画面」抽象 | 新建 `IScadaPagePicker.Pick(currentId, currentName, onPicked)`，**回调式**，与 `IScadaVariablePicker` 分开 | 面板/事件行必须能在无 WPF 宿主下被断言，不能硬接 Prism `IDialogService`；两者清单来源与列都不同，合成一个大接口只会把类型判断从 UI 挪到接口上 |
| 15 | 画面选择弹窗 | 新建组态专用弹窗 `ScadaPagePickerView`，照 `ScadaVariablePickerView` 骨架 | 四列：画面名 / 尺寸 / 图元数 / 说明；双击即确认；「起点」徽标标出起步页 |
| 16 | 取消语义 | 回调**一次都不触发** | 取消是"当我没点过"，不是"清掉原来选的那个"——后者是破坏性动作，不能藏在取消键里 |
| 17 | Id 权威 | 出参拿不到 `Guid` 就整条放弃，绝不退化成按名字猜 | Id 是权威身份，名字只用于显示与兜底寻址；确认后按画面身份（Id）记录，之后改名不会让这条动作断链 |
| 18 | 弹窗清单口径 | 只列 `IWorkspaceManager.CurrentSolution?.Scada.Pages`，打开时现取快照 | 清单口径 == 运行态可寻址口径（「选得到就一定切得到」）；不跨弹窗缓存，免得方案改了还列着旧页 |
| 19 | 过滤首次打开恒空 | `ApplyFilter()` **无条件重建**；打开时若 `_keyword` 非空先清空再广播，再无条件 `ApplyFilter()` | 防 `Keyword = string.Empty` 被 `SetProperty` 短路导致首次打开清单恒空（该坑在变量选择器上已踩过一次，此处复刻防护） |
| 20 | 面板入口 | `ScadaEventRow` 加 `PickPageCommand` / `OnPickPage`，模板加 `Navigate` 分支（目标名 + 「选择画面」按钮 + 未选时的橙色提示） | 与「选择变量」逐字同构；面板只认 `IScadaPagePicker`，弹窗怎么弹是应用层的事 |

## 四、已知边界

1. **`Hmi.Frame`（画面套画面）未做**：路线图 S8 提到「`Frame` 图元复用同一套规则」，本版未实现该图元；套画面的导航规则已由 `ScadaRuntime` 备好，接图元时直接复用即可。
2. **真机三页互切待人工核**：路线图 S8 验收要求"真机三页互切 + 返回，日志顺序正确"；目前靠 `[W]`/`[Y]`/`[X]` 离屏与断言模拟，真机需用 `Invoke-CimMethod Win32_Process Create` 脱离终端启动后人工核对日志顺序。
3. **`GoBack` 无 UI 入口**：领域能力与断言已就绪，但属性面板暂无「返回上一页」按钮（真实工程多靠"返回"图元配 `Navigate` 动作显式指向目标页）。
4. **`Navigate` 目标页在弹窗打开期间被删除**：确认时 `TargetPageId` 仍会回填，执行时走 `Warn`（`方案里没有叫「…」的画面`），不会静默失败。
5. **`ScadaNavigator` 摘除依赖关窗口收尾**：若宿主在某条非常规路径上没走到 `Attach(null)`，迟到的动作会去操作已 `Stop` 的会话，日志上是「运行已经结束」——行为安全，但排查时要知道这一档的出处。
