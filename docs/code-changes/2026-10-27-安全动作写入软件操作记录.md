# 运动安全动作写入软件操作记录（Category = Safety）

## 当前状态

「软件级操作记录」（`ISoftwareOperationLog` / `SqliteSoftwareOperationLog`，表 `software_events`）此前已有
`Lifecycle` / `Identity` / `Solution` / `Settings` / `Permission` 五类调用点，**运动侧一条都没接**
（前一篇 `2026-10-27-软件级操作记录SQLite.md` 的"未做"里明确写着"安全动作（急停/回零/使能）尚未接"）。
本篇把这一格补上：使能 / 失能 / 回零 / 停止 / 清报警 + 急停两个调用点。

分类固定 `Safety`，**成功与被拒绝两条路径都落库**——事后要回答的是两件事：
"谁在什么时候让这根轴失能了"与"那一下为什么没停成"。

## 已做

### 1. `VisionMaster/Services/Motion/MotionActionExecutor.cs`

- 新增 `private const string SafetyCategory = "Safety"`（分类字面量只写一处，查询侧按同一个字面量筛）。
- 新增 `IsSafetyAction(type)`：只认 `MotionEnable` / `MotionDisable` / `MotionHome` /
  `MotionStop` / `MotionClearAlarm` 五条。**定位两条、点动两条刻意不记**：量大（按住点动每秒数条），
  且已有运行记录；全记进去只会把真正该看的安全动作淹掉。
- 新增 `RecordSafetyOperation(...)`：走 `SoftwareOperationLogHost.SafeRecord`（内部吞异常、fail-open），
  填 `Category` / `Action`（`action.Type.DisplayName()`，即「轴使能」「轴回零」这类中文）/
  `Outcome`（成功 → `成功`，门禁拒绝或下发失败 → `拒绝`）/ `Subject`（轴名）/ `SubjectId`（轴稳定 Id）/
  `Detail`（`message`，失败时就是拒绝原因，成功时是"已下发（未等到位）"那行摘要）。
- **`TryExecute` 只把 `return ExecuteXxx(...)` 改成 `executed = ExecuteXxx(...); break;`**，
  在 switch 之后统一 `RecordSafetyOperation(...)` 再 `return executed`：
  - 记录点在"结果已算出、返回还没发出去"那一格，成功与拒绝共用同一条出口，**返回值仍是 `executed` 本身**；
  - 轴解析失败那条早退也记一条（`binding` 为 null，`Subject` 退回动作上配的轴名 / Id）——
    "按钮点了没反应"事后只能靠这条记录说明是"没选轴 / 轴被删 / 卡不在方案里"；
  - `default`（非运动动作）仍在记录之前 `return false`，不会给别的动作类型落 Safety。
- 记录失败不影响动作：`SafeRecord` 已保证，探针另有断言钉住"接不接库，返回值与提示逐字一致"。

### 2. 急停两个调用点

| 位置 | 主体（Subject） | 说明 |
|---|---|---|
| `VisionMaster/ViewModels/DialogViewModels/MotionBoardDebugTabViewModel.EmergencyStop()` | 卡名 | 手动调试页签的急停按钮；`SubjectId` = 卡 `Descriptor.Id` |
| `Plugins/Plugin.Motion.Steps/MotionStopPlugin.RecordEmergencyStop(...)`（`UseEmergencyStop` 分支） | 卡名 | 轴停止步骤的急停模式；配了轴名时把它写进 `Detail` |

两处都是 `Category = "Safety"`、`Action = "急停"`、`Outcome` 按 `MotionCommandResult.Accepted` 判
`成功` / `拒绝`、`Detail` 写结果原因（成功 = "已清空待执行命令并立即停全部轴"；
失败 = `LastFault.Suggestion ?? StateDetail`）。

**Subject 用卡名而不是轴名**：`IMotionDevice.EmergencyStop()` 的语义是"清空待执行命令 + 立即停**全部**轴"，
填一根轴名会让人以为只停了那一根。步骤里配了轴名时把它放进明细，读起来就是"目标是这根轴、实际整卡全停"。

两处都不改原有提示文案与返回值：调试页签的 `reason` 变量同时喂给记录与 `NotifyError`，
插件的 `RecordEmergencyStop` 在"判成败"之前调用（两条路径共用一条出口），
`Fail(...)` 与 `context.Logger.Warn(...)` 原样保留。

### 3. 探针（`tools/probes/_ProjectAssetsUiProbe`）

- `_ProjectAssetsUiProbe.csproj` 新增对 `Plugins/Plugin.Motion.Virtual` 的 `ProjectReference`：
  断言要用**真实**虚拟运动卡，`new` 一个假 `IMotionDevice` 只能断言常量（R38）。
- `Program.cs` 的 `RunSoftwareOperationLogChecks` 末尾追加 ⑦，新增 `RunMotionSafetyLogChecks`
  （**19 条断言**，全部用真实 `MotionActionExecutor` + 真实 `VirtualMotionCard` + 真实 `MotionAxisRegistry`）：
  - 造两张卡：一张连上（`SX`，成功路径），一张始终不连（`SY`，用来造"被门禁拒绝"）；
  - 使能 / 失能 → 断言 `log.Query(category: "Safety")` 里有「轴使能」「轴失能」两条，
    `Outcome="成功"`、`Subject="SX"`、`SubjectId` 非空；
  - 未连接卡上回零 → 断言留下 `Outcome="拒绝"`、`Subject="SY"`、`Detail` 含"未连接"；
  - **反向断言**：先确认定位真的被卡接受（`前置：定位被卡接受`），再断言 Safety 条数没变；
  - **记录不影响动作结果**：同一条回零调用分别在"接库 / 不接库（`NullSoftwareOperationLog`）"下各跑一次，
    断言返回值与 `message` 逐字一致；
  - **条数收口**：最后断言 Safety 恰好 4 条（使能 + 失能 + 回零拒绝 + 第⑤步接库那次），防"多记/少记"。

## 未做

  `IExecutionContext` 桩（`DataPipelineCheckSupport` 在 `FlowCanvasChecks` 里，探针引用不到）。
  这两处目前只有"编译通过 + 代码评审"这一档证据。
- `MotionStop` 的**手动停止**（调试页签 `StopAll`、插件 `UseEmergencyStop=false` 分支）仍不记 Safety：
  本篇按任务口径只覆盖动作表的 `MotionStop` 与急停通道。
- **调试页签自己那几个按钮不记**：`MotionBoardDebugTabViewModel` 的
  `SetEnableAsync` / `ClearAlarm` / `HomeCommand` / `StopAll` 直接调 `device.Enqueue`，
  不经 `MotionActionExecutor`，所以它们的使能/失能/回零/停止/清报警**没有** Safety 记录。
  只有该页签的**急停**记了（本篇第 2 节）。要不要把调试面板也收进同一口径，需要产品裁决
  —— 那会把"调试期手动试车"也写进跟机器走的审计库。
- 没有界面：`Safety` 记录目前只能用 SQLite 工具或 `Query` 接口看（与其余五类同一现状）。

## 踩过的坑

1. **命名空间解析**：`Core.Interfaces.Operations.X` 写在 `namespace VisionMaster.*` 里会被解析成
   `VisionMaster.Core.Interfaces`，报"不存在"。三处（执行器、调试页签 VM、插件）都在文件顶部加
   `using Core.Interfaces.Operations;` 后用裸名。
2. **`out` 参数不能进局部函数**：`message` 是 `out`，不能在 `TryExecute` 里用 local function 捕获
   （CS1628），所以记录逻辑抽成 `private static RecordSafetyOperation(..., string message)` 显式传参。
3. **记录必须放在 switch 之后**：原来九个 case 各自 `return`，若在每个 case 里各插一次记录，
   迟早出现"新加一条运动类型忘了插"（正是 `default` 分支注释警告的那类事）。
   改成统一 `executed = ...; break;` + 出口处一次记录，名单也只剩 `IsSafetyAction` 一份。
4. **反向断言必须能反证**：只断言"Safety 条数没变"是不够的——定位若被门禁拒了，条数同样不会变。
   所以先断言"定位真的被卡接受"，再断言条数不变；探针输出里 `前置：定位被卡接受（…已下发…）`
   与 `定位不产生 Safety 记录` 是两条独立的 PASS。
5. **探针引用插件工程**：`Plugin.Motion.Virtual` 目标框架是 `net9.0`（不带 `-windows`），
   探针是 `net9.0-windows`；引用方向没问题（windows 可引用非 windows），但别反过来。
6. **虚拟卡的点动没有终点**：`Jog` 会把目标设成 ±1,000,000 mm，越过软限位会触发基类安全停机。
   探针因此只跑"定位"这条反向断言，不跑点动——否则会把在线卡打成 `SafeStopped`，后面的断言全跟着歪。
