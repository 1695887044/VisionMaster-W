# 流程画布 v2：海康式一图全展开（扁平化重做）

## 需求与决策

用户要求把"列表能用但分支不直观、画布不可用"的流程画布重做成海康 VM 式：

1. **整棵流程树摊在同一张画布上**——不再"一次看一层 + 双击下钻 + 面包屑"（旧 M2-1 子画布模型整体废弃）；
2. **容器（If/While/For）渲染成框体 + 分支泳道**，可折叠（折叠态沿用 `FlowLayoutStore.Collapsed`，随图纸存盘）；
3. **连线升级为模块级**：一根线 = 两模块存在数据依赖，同一对模块的多条端口绑定聚合成一根线（×N 角标）；
   具体端口绑定在既有 `DataBindView`（变量绑定弹窗）里维护——画布从模块圆点拖线只发
   `ModuleLinkRequested` 事件，端口对由弹窗决定，画布自身**不再写连线**；
4. **全局变量/常量绑定不画线**，折成模块盒上的琥珀色角标（悬停列明细）；
5. **缩放工具条**（＋/−/1:1/适应）+ **右下小地图**（Nodify.Minimap）+ **整理布局**按钮
   （清空散乱坐标按正交重排——旧子画布按"每层各自坐标系"存的布局迁移后散乱，这是迁移出口）；
6. **保留流程栏**（列表视图）不动；画布与流程栏经 `Workspace.CurrentStep` 双向联动
   （画布点选→SwitchStep；外部选中→画布点亮并滚入视野，折叠时给提示不炸）；
7. UI 全部走 `UI/Controls/Themes/Colors.xaml` 新增的 `FlowCanvas*` 令牌，零硬编码色。

## 已知边界

1. **Nodify 默认深色模板残留**：模块盒必须显式置 `HeaderBrush/ContentBrush/FooterBrush = Transparent`，
   否则 Node 默认主题在卡片后垫黑带（踩过一次，已写进 XAML 注释）；
2. **锚点时机缺陷（第二轮修复）**：用户实测"加 If 后连线飞走"。根因是依赖 Connector 控件回报
   Anchor 的时机——加节点触发重排时控件读到旧位置。最终方案：**主 VM 确定性计算锚点**
   （`UpdateLinkAnchors`：源=生产方盒子右缘中点、目标=消费方盒子左缘中点，容器框用框体矩形），
   模块盒改**固定尺寸 210×62**（模板与常量一致），节点拖动（Location 变化）实时重算，连线跟随拖拽；
   连接器（NodeInput/NodeOutput）退化为纯拖拽把手，直接叠放在卡片左右边缘、
   `DataContext="{Binding Inputs[0]}"` 切到连接器 VM，不再包裹 Node 控件（顺带消灭深色模板残留）；
3. **空分支泳道压框头（第二轮修复）**：空分支泳道改锚定到框体内容区
   （全空=框头带下方起点；混合=与有内容泳道的内容顶对齐），EmptyLaneWidth=200 + 提示文本换行；
4. **旧方案首次打开会因散乱的子画布时代坐标而"适应"到很远**——**点「整理」一键归位**，
   初始适应已加 0.6 最小缩放钳制兜底；
5. **UIA 自动化无法合成 OLE 拖放**（工具箱拖步骤进流程是 GongSolutions 拖放链路），
   实机验证用离线工具 `FlowCanvasChecks --inject-if <方案路径>` 向 MainTask 注入
   If 容器（带条件表达式与空分支）后启动软件目验——已注入到
   `解决方案/解决方案-20260829224154.vms` 的 MainTask（改前备份：
   `解决方案-20260829224154.vms.bak-画布测试前`，不需要可直接删 If_自动化测试 步骤或还原备份）；
6. 折叠/展开实机点击验证通过（框体收成头带、泳道隐藏、角标翻转、状态栏留痕，
   折叠态持久化由 [D] 断言覆盖）。

## 第三轮补充：执行顺序链（用户报"画布表现不出顺序"）

- **执行顺序链**：同一集合里相邻两步之间画一条自上而下的**细灰虚线箭头**（`IsOrderLink`），
  容器框参与顶层链（进出走框体上下缘中点），分支内部各自成链；折叠子树不参与；
  与数据依赖线（实线、横向、右缘出左缘入）视觉区分，数据线右键菜单不挂在顺序链上；
- **容器框头带补执行序号角标**（此前只有步骤盒有，折叠后看不到容器是第几步）；
- 锚点机制统一：`UpdateLinkAnchors` 按线型分派（数据线=左右缘中点，顺序链=上下缘中点），
  纯数学、拖拽/重排实时跟随；
- VM 新增公开指标 `DataLinkCount` / `OrderLinkCount`；
- 修一个自伤 bug：`Render` 里集合清单初始化器与 `CollectCollections` 重复种入顶层集合，
  导致顶层顺序链成对重复（断言诊断 "A→判断 | 判断→外层循环 | A→判断 ..." 定位）；
- 断言：[B] 新增顺序链计数/端点/提示/折叠联动 5 条，数据线计数断言全部改走
  `DataLinkCount`（排除顺序链），`Harness.Link` 过滤顺序链；
- 实机：MainTask（图像采集 → 模板匹配 → If 容器）三条顺序链 + 数据线 + 容器序号 3 全部正确渲染。

## 第四轮补充：展开容器层级混乱（用户报"展开后层级顺序乱了"）

两个根因、两个修复：
1. **`FlowLayoutStore.LayoutLevel` 不预留容器分支高度**：容器分支排布完后游标没有推进到
   分支内容底部，后续兄弟直接叠进容器框里。修复：`LayoutLevel` 改为高度感知递归，
   返回本层消耗的底部 Y，容器的游标推进到所有分支内容的最大底部；
2. **展开/折叠不重排**：历史散乱坐标在展开时全部暴露。修复：展开/折叠触发整体重排
   （`TidyLayoutCore`，折叠标记先记后置——重排不能抹掉折叠状态），「整理」按钮共用同一核心；
3. 断言：[C] 新增"AutoLayout 预留容器分支高度：后续兄弟排在分支内容之下"
   （tail=(0,270)、b1=(220,180) 实证）；
4. 实机：展开 If 容器后框内泳道不压头带、兄弟节点不叠进框里、顺序链自上而下可读。

## 第二轮实测证据（用户报"加逻辑分支不行"之后）

- 断言：画布段新增"锚点=边缘中点""节点挪动后锚点实时跟随"两条，[A]–[R] 保持全绿。
