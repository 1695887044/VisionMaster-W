# 2026-09-15 Modbus/S7 字节序系统性颠倒修复（HslHelper 大端化）

## 一、现象与暗号破译

用户网络变量（Int32，40001）联调 Modbus 模拟器发现：

| 方向 | 发出值 | 对端显示 | 十六进制暗号 |
|---|---|---|---|
| 软件写 21 | 0x0015 | 模拟器显示 **5376** | 0x1500 —— 字节颠倒 |
| 模拟器写 1221 | 0x04C5 | 软件当前值 **50436** | 0xC504 —— 字节颠倒 |

两对数字互为字节反转，实锤**端序 bug**：软件读写"自洽"（自己写自己读正确），与标准 Modbus 设备交换数据字节系统性颠倒——接真 PLC 必炸。

## 二、根因

`Communication/Communications/Core/HslHelper.cs`：
- `ConvertTo<T>`：设备返回**大端**字节流，直接 `BitConverter.ToInt16/32...`（x86/x64 **小端**解释）；
- `GetValueArray`：`BitConverter.GetBytes`（小端）直接下发设备。

毒及三个连接实现（ModbusTcpConnection / SiemensS7Connection / SerialConnection 都走 HslHelper）——S7 同为大端协议，同样中招。

**为什么 CommTest 从没抓到**：既有测试全部"软件写→软件读"自洽断言，两次颠倒互相抵消——**自洽测试永远测不出端序 bug**，这是本案例最大的测试学教训。

## 三、修复

1. **HslHelper 大端化**（单点修复，三协议受益）：
   - `ConvertTo<T>`：字节流 `Array.Reverse` 后再 BitConverter（= 大端解释，32/64 位取 ABCD 字序）；
   - `GetValueArray`：BitConverter 结果反转（= 大端编码下发）；
   - string/bool/byte 无端序语义，不反转（反转会乱码/错位）。
2. **CommTest 补两类回归防线**：
   - `[H] 纯单元断言`（反射 HslHelper，不依赖模拟器，程序开头必跑）：short 21 → `[0x00,0x15]`、`[0x04,0xC5]` → 1221、int ABCD 双向；
   - `[G] 端到端交叉验证`（模拟器在线时）：软件链路写值 → **HSL 标准强类型接口**（独立实现）读回比对——第三方视角，专杀自洽盲区。

## 四、验证结果

- Communication / VisionMaster Debug 编译 0 错误；
- CommTest `[H]` **4/4 通过**（旧代码这四项全红）；
- `[G]` 待模拟器在线复跑（本轮 502/108 未启动，连接失败属环境）。

## 五、用户复测指引（重启软件 + 开模拟器后）

1. 网络变量写 21 → **模拟器 40001 应显示 21**（不再是 5376）；
2. 模拟器 int 写 1221 → 软件当前值应显示 **1221**（不再是 50436）；
3. ⚠ **32 位字序对齐**：软件按 **ABCD** 字序（与 HSL 默认一致）。你的模拟器编码下拉当前是 **CDAB**——Int32 交互需把模拟器改成 ABCD，否则 16 位正确而 32 位仍对不上（这是字序约定问题，不是 bug）；
4. "UI 不更新"再观察：50436 本身就是更新过的值（1221 的颠倒形态），修复后数值对得上，若模拟器改值（含改成 0）软件 1 秒内仍不动，再按 `[Comm] 读取变量失败` 日志深挖。

## 六、已知边界

1. 32/64 位字序固定 ABCD，未在连接配置暴露 DataFormat（CDAB/BADC/DCBA）选项——遇到只认其他字序的 PLC 时再加；
2. bool 走寄存器 0/1 语义（HSL 线圈区另论）；
3. `[G]` 交叉验证需要模拟器在线，纳入例行联调清单。
