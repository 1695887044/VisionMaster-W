# 2026-09-17 SCADA 图元工具箱与拖放落画布（S3-c）—— 从"注册表里的一条描述符"到"画布上一个能选中的图元"

## 一、需求与决策

### 背景：S3-c 在整条链上的位置

前两阶段各交付了一半：

| 阶段 | 交付物 | 还欠什么 |
|---|---|---|
| S1 [SCADA画面领域层](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA画面领域层.md) | `ScadaDocument → ScadaPage → ScadaElement`（只有 `TypeKey` 字符串 + 属性袋） | 不知道"怎么画" |
| S2 [SCADA图元控件库](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元控件库.md) | `ElementRegistry` / `ElementDescriptor` / 图元控件 / `ScadaCanvas` | 没人把它们串成"用户能操作的编辑器" |

S3-a/S3-b/S3-e1 已经把**画布宿主**接进主程序（面板登记三处 + `ScadaEditorView` + `ScadaEditorViewModel`）。
本阶段（S3-c）补上用户操作闭环的第一环：**在面板里看到有哪些图元 → 按住拖到画布 → 松手就多出一个图元**。

用户长需求对本阶段的约束照旧：商业级、可扩展、模块化、**长期可扩展性优先**、每阶段"暴力测试"。

### 决策一：拖放链路拆成三段，每段只知道自己该知道的

```
┌── 工具箱（VisionMaster/Views/ScadaToolboxView）──────────────┐
│ 按下条目 → 跨过系统拖拽阈值 → DoDragDrop(负载, Copy)          │
│ 知识范围：哪条描述符被按下了。不算落点、不造模型                │
└──────────────────────────┬───────────────────────────────────┘
                           │  IDataObject：只有一个字符串 TypeKey
                           ▼
┌── 协议（Scada.Controls/Canvas/ScadaDrag）────────────────────┐
│ ElementTypeKeyFormat / CreatePayload / TryGetTypeKey         │
│ 知识范围：负载长什么样。两端都从这里读写，不存在第二份定义       │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
┌── 画布（ScadaCanvas.ToDropOrigin）──────────────────────────┐
│ 视口坐标 → 设计坐标 → 以落点为中心 → 吸网格 → 夹进画面          │
│ 知识范围：只有它知道当前的 Zoom / Offset / GridSize / 页面尺寸  │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
┌── 编辑器 VM（ScadaEditorViewModel.AddElement）──────────────┐
│ 查注册表造模型 → 去重命名 → 抬 ZIndex → Elements.Add → 选中   │
│ 知识范围：文档语义。不碰可视树                                │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
              画布订阅 CollectionChanged，自己长出控件
```

**View 层的 code-behind 一段知识都不持有**：`ScadaEditorView.OnCanvasDrop` 只做"把鼠标位置和数据递过去"
（[ScadaEditorView.xaml.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/Views/ScadaEditorView.xaml.cs)）。
这样拆的收益很直接：将来加"复制粘贴""从模板库拖""脚本批量生成图元"，走的都是
`ToDropOrigin + AddElement` 这两步，不必再复制一份落点算法或建模型代码。

### 决策二：拖的是**意图**（TypeKey 字符串），不是**结果**（图元实例）

| 做法 | 后果 |
|---|---|
| 拖 `ScadaElement` 实例 | 工具箱就得会造模型（命名、默认属性、ZIndex 全在这一层写一遍），与 `AddElement` 形成两条平行通道；跨进程拖拽还会撞上序列化 |
| **拖 TypeKey 字符串（本方案）** | 负载是无版本歧义的纯字符串；"这个键是什么、默认多大、叫什么名"永远由注册表与编辑器 VM 回答，一处定义 |

配套三条纪律（都写在 [ScadaDrag.cs](file:///e:/VM/VisionMaster-W-master/Scada.Controls/Canvas/ScadaDrag.cs)）：

- **只认自己那一种格式**（`VisionMaster.Scada.ElementTypeKey`），不做"纯文本兜底"。
  兜底一旦写了，从记事本拖几个字进画布就会长出图元——而且没人知道自己为什么多了个框。
- **格式名带产品前缀**：`DataFormats.Text` 这类通用格式在跨进程拖拽时必然撞上别人。
- `CreatePayload` 对空白键**直接抛 `ArgumentException`**：这是调用方编程错误，静默返回一个空负载只会把问题推到松手那一刻。

### 决策三：起拖的两个细节（都是"看着像 bug、其实是 WPF 规则"的地方）

1. **按下里不 `DoDragDrop`，只记意。** `DoDragDrop` 是模态的，写在 `MouseLeftButtonDown` 里会让每一次单击都变成拖拽，
   Expander 折叠、列表滚动全废。正确姿势是：按下记 `_pending` + `_mouseDown`，`MouseMove` 里量位移，
   跨过 `SystemParameters.Minimum{Horizontal,Vertical}DragDistance` 才起拖。
2. **移动处理器挂 UserControl 根节点，不挂条目。** 条目只有 28 高，鼠标在跨阈值前就滑出条目区域的话，
   挂在条目上的 `MouseMove` 不再触发 —— 表现就是"有时候拖不出来"。挂根节点则整个面板内都能收到。
3. `DoDragDrop` 返回后**必须清 `_pending`**：模态返回时鼠标多半还按着，不清会在同一次按下里被反复拉起拖拽。

### 决策四：`Copy` 而不是 `Move`

工具箱里的条目是注册表的一部分，不是"可搬走的东西"。而且光标上那个 `+` 本身就是
"放下会新增一个、原来的还在"的即时反馈 —— 工业现场少一个需要读文字才能明白的状态，就少一次误操作。

### 决策五：`DragOver` 要同时看负载和"当前有没有画面可写"

```csharp
private bool CanAccept(IDataObject? data)
    => ScadaDrag.TryGetTypeKey(data, out string typeKey)
       && ElementRegistry.Find(typeKey) != null
       && (DataContext as ScadaEditorViewModel)?.SelectedPage != null;
```

只看负载的话：光标一路显示"可放"，用户松手却什么都不发生 —— 这是最难查的一类反馈缺失
（用户会认为是软件坏了，而不是"我还没新建画面"）。

### 决策六：工具箱面板落位 —— 左侧 13\* 栏的第二个标签

| 候选 | 判定 |
|---|---|
| 新开一条左侧栏 | 否。左栏已经有工程树/变量等，再加一条会把画布挤窄，而工具箱是"偶尔用一下"的面板 |
| 放自动隐藏区（AutoHidden） | 否。自动隐藏要点了才浮出、点一下就收，拖放过程中面板收起 = 拖拽中断 |
| **左侧 pane 加第二个 LayoutContent（标签并列）** | **是**。常驻、可拖宽、和"画布编辑器"同屏共存，正是组态时的使用姿态 |

登记照 S3-e1 定下的三处范式，一处都不能少（[LayoutHelper.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/Services/LayoutHelper.cs)
的 `ContentFactories` + [Shell.xaml](file:///e:/VM/VisionMaster-W-master/VisionMaster/Shell.xaml) 的 `ContentId` 与「视图(V)」菜单项 +
[App.xaml.cs](file:///e:/VM/VisionMaster-W-master/VisionMaster/App.xaml.cs) 的 `RegisterForNavigation<View,VM>()`）。
`LayoutXmlCoversAllPanels` 以 `ContentFactories.Keys` 为权威，旧布局文件缺这个面板会自动回退默认布局，**不需要迁移代码**。

### 决策七：搜索用"四路命中"，不做拼音/模糊

`Matches` 依次试 `DisplayName / TypeKey / Category / Description`（`OrdinalIgnoreCase`）。
理由：现场工程师记住的往往是**说明里的词**（"罐体"）而不是控件名（"椭圆"），也可能是分类名（"操作"）。
纯空白关键字一律视为"不过滤"——否则用户删空搜索框的那一瞬间面板会是空的，看起来像软件出错。
刻意不做拼音/编辑距离模糊匹配：内置图元一共五种，模糊匹配只会带来"它为什么把这个也列出来了"的困惑。

## 三、验证结果

### 断言工程：`[T]` 节（46 条，跑在独立 STA 线程）

沿用 `[S]` 的样板：另起 `Thread` + `SetApartmentState(STA)` + `IsBackground` + `Join`，
捕获异常后统一 `Check`，**不把 `Main` 标成 `STAThread`**（免得改变 S0/S1 那批断言的运行环境）。

| 组 | 条数 | 钉住的行为 |
|---|---|---|
| ① 协议 | 5 | 装载/取回往返相等；空白键抛 `ArgumentException`；null 负载 / 空 `DataObject` 判假；**外部纯文本不兜底**；格式名对但值空白也算不是我们的负载 |
| ② 落点换算 | 10 | 落点是**中心**不是左上角（`(500,300)`+120×60 → `(440,270)`）；差几像素落同一格；关吸附后 `(443,266)`；`GridSize=0.5` 视为无网格（吸附自动失效而不是挤成 0）；`Zoom=2/Offset=(40,20)` 先折算回设计坐标；`ToViewportPoint↔ToModelPoint` 可逆；越界时**中心**被夹进 `800×600`；从负方向进来得到 `(-60,-30)`（夹中心，左上角允许为负）；页面尺寸未绑上时不夹；`Zoom=NaN→1`、`99→8` |
| ③ 放置 | 13 | 新建画面即选中；模板套用后 `PART_*` 齐备；进的是模型集合且返回同一引用；坐标/尺寸/名称（`矩形`）/`ZIndex=1`；放完即选中且 `SelectedElement` 只通知一次；**`RenderedElementCount` 跟着 `Elements` 走**（Add=1、连续放=3、Remove=2、Clear(Reset)=0）—— 宿主没有手工 addChild，不留孤儿控件；连放续号 `矩形/矩形_2/矩形_3`、ZIndex 递增；未注册键静默返回 null；跨画面同名不续号；无画面时放置失败但不崩 |
| ④ 挂摘可逆 | 3 | 换方案后编辑目标跟到新文档（`Pages` 恰好通知 1 次）；`Deactivate()` 后不再跟；`Activate()` 后又跟回 —— AvalonDock 反复装卸不失效 |
| ⑤ 工具箱 VM | 11 | 总数 = 注册表全量 = 各组之和；分组覆盖每个分类且沿用注册表次序；组内分类一致；四路命中各 1（`矩形` / `hmi.ind` / `操作` / `罐体`）；无命中为 0；纯空白=不过滤；清空恢复全量且 7 次改关键字通知 7 次 `Groups` |

### 过程中踩到并修掉的三件事（都记下来，下次直接绕）

1. **`DelegateCommand` 没有 `Execute(null)` 这个重载。**
   非泛型 `DelegateCommand` 的公开方法是 `Execute()`，`Execute(object)` 是显式接口实现。
   写 `AddPageCommand.Execute(null)` 直接 `CS1501`。→ 改 `Execute()`。
2. **控制台断言环境里 WPF 的默认样式自动查找链不通。**
   现象：`host.ApplyTemplate()` 返回 false、`Style` 一直是 null，而 `Generic.xaml` 本身完全正常
   （显式 `new ResourceDictionary{Source="/VM.Scada.Controls;component/Themes/Generic.xaml"}` 加载成功、
   `Contains(typeof(ScadaCanvas))==True`、合并 7 本字典）。**先 `new Application()` 再量一次布局也不通。**
   → 断言里显式把本库那条样式赋给 `host.Style`，被测目标仍是"命名件齐不齐、控件是不是画布自己长的"，
   与样式查找机制无关。**产品代码一行没动**（带窗口的真实宿主里这条链是 WPF 的标准路径）。
3. **`ApplyTemplate()` 的返回值是"这次有没有新套用模板"，不是"模板在不在"。**
   先 `Measure/Arrange` 再去 `ApplyTemplate()` 会拿到 false（模板已经在布局里被应用掉了）。
   → 顺序改成 `Style → ApplyTemplate()（断言 true）→ Measure/Arrange`。

## 四、已知边界

| 边界 | 说明 / 影响 |
|---|---|
| **运行期未验证（P0）** | 断言环境是 headless 的，`generic.xaml → DefaultStyleKey` 这条自动链只在"显式加载字典"这一半得到证明。**下一次启动主程序必须肉眼确认**：左栏出现「图元工具箱」、拖 rectangle 到画布能看见带样式的矩形（不是裸 Control）。这是 `[T]` 覆盖不到、也最容易在集成时才暴露的一环 |
| 拖放只在编辑器面板内发生 | 跨窗口、跨进程（从资源管理器拖文件）、面板浮出成独立窗口后的拖放未处理。`AllowDrop` 只开在画布宿主上 |
| 只支持 `Copy` | 没做 Ctrl/Shift 改效果、没做"从画布拖回工具箱删除"、没做多选批量拖。这些是独立需求，不该顺手加进落点链路 |
| 没有撤销栈 | 放下即写进模型。撤销应属于 S3-d/e2 之后的统一命令层，现在补一套只覆盖拖放的 Undo 会做成两套语义 |
| 条目无预览图 | 面板上只有"显示名 + 类型键 + ToolTip 说明"。图元缩略图要拿 `ScadaElementBase` 离屏渲染，属 S3-e2 的缩略图一起做更合算 |
| 拖放期间不做实时插入指示 | 松手前没有落点框/影子（流程画布那套 `DropIndicator` 经验要重做一遍视口变换）。当前反馈只有光标上的 `+` |
| 属性默认值全走描述符 | 拖出来的图元尺寸/颜色一律是注册表默认值，不支持"上次拖的那个图元的尺寸"这类连续性偏好 —— 那是 S3-d 属性面板之后的话题 |
| 断言里的手动赋样式 | `[T]` 组③为了拿到 `PART_ElementLayer` 显式赋了 `host.Style`。若将来给 `ScadaCanvas` 换 `x:Key` 的样式名，这里要跟着改（改的是断言，不是产品代码） |
