# 2026-09-25 插件配置视图样式统一（第二批，9 视图全迁）

> 需求：把 9 个插件配置视图的本地样式迁移到 UI 层公共样式字典（`PluginConfigStyles.xaml` /
> `PluginConfigColors.xaml`），延续 [Blob 试点](2026-09-25-插件配置界面样式收编UI库（Blob试点）.md)。
> 用户决策：**"9 个全迁"**；已迁移的 6 个（Blob + 并行任务的 Yolo/Ocr/ColorRegion/ColorCheck/CodeReader）一律不动。

---

## 1. 需求与决策

- **抽象动机**（承试点）：CardBorder 在 14 个插件里被抄了 15 份，颜色写死在各家 XAML，
  想统一调一次色得全仓搜一遍。第二批把这 15 份里剩下还在本地抄写的 9 份全部收编。
- **范围决策**：9 个全迁，其中 8 个是机械迁移（本地样式键 → 公共键），
  1 个（ImageAcquisition）没有本地样式键、用的是内联硬编码属性，走"内联 → 资源"路线。
- **铁律**：公共字典**只新增键、不改既有 7 键的语义**——已迁移的 6 个视图正在用它们。
- **ImageAcquisition 的 `#0A7` → `PluginOkBrush(#00AA77)` 归一**：它的默认状态色 `#0A7`
  与字典 `PluginOkBrush #00AA77` 语义相同但值不同（同一份抄写源的两种写法）。
  统一到字典值，换主题只改字典。**CaliperMeasure 的状态栏有同款 `#0A7`，一并归一**（审计时发现的，规格只点名了前者）。
  注意这是**刻意的归一**而非视觉还原：正常状态下状态栏文字绿从 `#0A7` 变为 `#00AA77`。

## 7. 缺陷修复：按钮文字竖向裁切（用户截图反馈）

### 7.1 现象与根因

用户打开 4 个并行视图（码读取/颜色序列检查/区域颜色检查/YOLO）发现按钮文字下缘被硬裁
（"载入 / 浏览 / 清空采样区 / 试算一下"集体缺半截）。根因是两件事相乘：

1. `DefaultStyle.xaml` 的**隐式 Button 样式** `Padding="18,7"` + `FontSize=13` → 按钮内容实际需要约 **34px**；
2. 这些视图把按钮**写死 `Height="24/26"`** → 差 8px，超出部分被裁。

全仓库排查：写死高度的按钮只存在于 5 个并行视图（共 17 处）+ DataRecord 一个 24×24 的"✕"
小按钮（自写 `Padding="0"`，不受隐式 Padding 影响，未裁，未动）；**已迁移的 9 个视图零命中**
——"统一走样式"的路线恰好避开了这个坑。

### 7.2 修复内容

| 文件 | 改动 |
| --- | --- |
| `UI\Controls\Themes\Generic.xaml` | **合并顺序调整**：`PluginConfigStyles.xaml` 移到 `DefaultStyle.xaml` 之后（新样式要 `BasedOn` 隐式 Button 样式，隐式样式未合并前解析会抛异常）；已确认 Styles 只引用 Colors 令牌、无其他字典引用 Plugin 键，重排安全 |
| `UI\Controls\Themes\PluginConfigStyles.xaml` | **新增 `PluginButton`**：BasedOn 隐式样式（显式样式套上后未写明的属性回落 WPF 主题默认，不 BasedOn 会丢自绘模板变灰块）、`Padding=12,4`、`FontSize=12`、`MinHeight=26`、**不写死 Height**。注释写明"给按钮写死 Height 是被禁止的写法" |
| `Plugin.ColorCheck\ColorCheckView.xaml` | 4 个按钮：删 `Height` + 套 `PluginButton` |
| `Plugin.ColorRegion\RegionColorView.xaml` | 4 个按钮同上 |
