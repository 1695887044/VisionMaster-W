## 三、关键决策与理由

### 1. 不包裹条目 view model —— 拖拽链路的硬约束

工具箱是**拖拽源**：gong 的默认拖拽处理器把**条目本身**当 `DataObject` 投放，放置端 `FlowCanvasView.xaml.cs` 的 `FindDraggedTool` **硬认 `ToolItemModel` 类型**。包一层 wrapper 会让放置端拿到 null、**拖拽静默失效**。

所以：`ToolboxGroupViewModel.Children` 的元素**必须是原始 `ToolItemModel` 实例**；"每项可变状态"（收藏态）只能留在 VM 里、靠转换器回查。星标用 `IMultiValueConverter`（item + VM + `FavoritesVersion` 刷新信号）——**第三路版本号是唯一的刷新驱动**，只绑前两路的话切换收藏后星标不会重绘（`IsFavoriteConverter.cs:16`）。这也解释了 `ToolboxGroupViewModel` 为什么**只包分组、不包条目**（`ToolboxGroupViewModel.cs:14-16` 注释）。

### 2. 收藏持久化键 = `ToolItemModel.ModuleTypeName`，不用 `Id`

`Id` 字段在算子构造点**从未赋值、恒为 `Guid.Empty`**（`ToolItemModel.cs:22`），拿它当键会把所有收藏撞成一条。`ModuleTypeName`（程序集限定类型名）才是插件的稳定身份——显示名可改、分类可调，只有类型名稳定（`AppConfigModel.cs:443-444` 注释）。

读取时对**当前已注册键集**做存在性过滤（`ToolViewModel.cs:176-180`）：插件升级（类型名变）或卸载后，老配置里的键会变成拖不动的死条目，丢掉它们 = **配置自愈**。

### 3. 持久化落点 = `AppConfig.json`（"随用户"口径），构造参数设为可选

仿既有 `FlowCanvasSettings` 一节：收藏是"这台机器的操作者习惯"，换方案 / 换流程 / 重启都不该丢，但不属于任何一份 `.vms`，故随软件配置落盘（`AppConfigModel.cs:441-442`）。

构造函数第二参 `AppSettingsService?` **可选**，两个目的：① 保 `FlowCanvasChecks` 的 `new ToolViewModel(new StubPluginProvider())` 不破（断言桩传 null = 纯内存）；② **headless 宿主不写盘**——`AppSettingsService` 构造会在程序目录写 `AppConfig.json`，不能让断言宿主碰它。

### 4. 分类色由 VM 暴露 `Brush`，令牌一律 `...Brush` 结尾

先例 `ShellViewModel.RunStateBrush`。新增颜色令牌**一律 `...Brush` 结尾**——`UIThemeSmokeTest` 禁 `{StaticResource *Color}` 挂 `Brush` 属性。画刷**冻结后按分类缓存**（条目模板每次实例化都取一次，不缓存就是每行一个新画刷对象，`ToolboxCategoryVisuals.cs:80-88`）。

### 5. 网格用 `ItemsControl + UniformGrid Columns=2`，不用 `ListView + GridView`

刻意避开 AGENTS.md §6 的 GridView 隐式样式坑（R19~R22）：应用级 Fluent 主题会顶掉支持 GridView 的那份隐式样式，"凡 GridView 必坏"。网格视图用 `ItemsControl` + `UniformGrid` 就没有这条风险。

### 6. 命令参数类型按 AGENTS.md R27：三个命令均 `DelegateCommand<object?>` + 首行判型

`CommandParameter` 在 XAML 里是**编译期不检查的表达式**（`{Binding}` / 字面量字符串），写成强类型泛型会在拿到别的类型时抛 `InvalidCastException`（2026-10-10 真机崩溃先例）。`ToggleViewModeCommand` / `SetViewModeCommand` / `ToggleFavoriteCommand` 全部 `DelegateCommand<object?>`，处理器首行 `is` 判型（`ToolViewModel.cs:118-120`）。

## 七、事故：点收藏即崩 —— AppConfig.json 被占时 File.Replace 抛 1177（2026-10-14 修复）

**现象**：真机点击工具箱算子星标收藏，抛 `System.IO.IOException`（`HResult=0x80070497`），栈：`AppSettingsService.Save()` → `File.Replace` → `SyncToolboxFavorites` → `ToolViewModel.OnToggleFavorite`。

**根因**：`Save()` 用 `File.Replace(tmp, ConfigPath, null)` 落盘，它走 Win32 `ReplaceFile`，**要求能删除目标文件**。运行中的宿主（或杀软 / 索引器）只要以"允许读、允许写、**不允许删除**"的方式打开着 `AppConfig.json`，`ReplaceFile` 就以 `ERROR_UNABLE_TO_REMOVE_REPLACED(1177)` 失败。证据：bin 目录里残留 `AppConfig.json.tmp`（说明 `WriteAllText(tmp)` 成功、`File.Replace` 失败）；App 未运行时文件未锁定、同样的 `Save()` 在断言宿主里成功。这是**既有共享代码**的隐患，工具箱收藏是第一个真机触发它的入口。

**修法（两层）**：

1. `Core\AppSettingsService.cs` 的 `Save()`：`File.Replace` 抛 `IOException` 时退化到 `File.Copy(tmp, dest, overwrite:true)`（只需写权限、不要求删除目标）+ 删 tmp。抽出为私有 `WriteReplacing(tmp, dest)`，带完整注释。**原子性只在 1177 这条冷路径上略降**（Replace 成功时行为不变）。
2. `VisionMaster\ViewModels\ToolViewModel.cs` 的 `OnToggleFavorite`：落盘调用包 try/catch，失败只记一条 `ILogService.Warn`、内存态照常生效、不把异常抛进 UI 线程——与"方案清单 / 系统参数 / 运行窗口"三个既有 Save 调用方同一条约定（它们也是 catch 后提示，不抛）。构造函数随之加可选参数 `ILogService? log = null`。

**回归断言**：`FlowCanvasChecks\Program.cs` 的 `[G9]` 新增一条——用 `FileShare.ReadWrite`（允许读写、不允许删除）占住 `AppConfig.json`，再调 `SyncToolboxFavorites`，断言不抛且值写入成功（`favs=VM.Stub.Leaf`）。密闭性靠"原本没有 → 用完删掉"还原（同 Z7）。**该断言在修前必红、修后必绿**。

**验证证据**：`dotnet build VisionMaster.sln` 退出码 0；`FlowCanvasChecks` 退出码 0（G9 该条通过）；`ScadaChecks` 退出码 0（通过 1710 / 失败 0，未因 `Save()` 改动回归）；`UIThemeSmokeTest` 退出码 0（唯一 FAIL 仍是第三方 `VM3.0-main` 的 GridView 既有项）。

**可提炼的纪律**：凡"写程序目录下的配置文件"的路径，都不能假设 `File.Replace` 一定成功（目标可能被以无删除共享的方式占用）；要么用覆盖写，要么在调用方 catch——**不要把 `IOException` 抛进 UI 线程**。

## 八、补强：悬停预览的端口补"类型 + 注释"（2026-10-14）

**需求**：悬停算子时，预览浮层里每个输入/输出端口除名称外，再显示**类型**与**注释**。

**数据来源**（都在 `PortDefinition` 上，无需新增采集）：
- 注释 = `PortDefinition.Description`（插件端口来自 `new InputPort<T>(name, description: …)`；内置端口也逐个填了，见 `Engine\PluginService.cs:80-156`）。
- 类型 = `PortDefinition.DataTypeName`，但它存的是 **`Type.AssemblyQualifiedName`**（`Engine\PluginService.cs:248/265`），形如 `HalconDotNet.HImage, halcondotnet, Version=…, PublicKeyToken=…`——**直接上屏是一行程序集清单**。

**实现**：
1. 新增 `VisionMaster\Helpers\TypeNameShortenerConverter.cs`：去程序集限定（首个逗号起）、去泛型实参（首个 `[` 起）、取最后一段、去泛型元数反引号。`System.Double → Double`、`HalconDotNet.HImage, … → HImage`、`List\`1[[…]] → List`；空/空白返回空串，**绝不抛**。`Shorten()` 静态方法与转换器共用同一份实现（避免两处口径不一致）。
2. `ToolView.xaml` 的 `ToolPreviewTemplate`：端口行由单行改成"名称 + 类型（弱灰小字）"一行 + "注释（次要灰小字，`TextWrapping`）"一行；**注释为空/为 null 时整行收起**（内置 `If/While` 之类没注释的端口不留空行）。
3. 浮层高度：先试过"`ToolTip` + `ScrollViewer` + `MaxHeight`"，真机上**滚动条在、点了不动**（见 §九），已改为视图自管的 `Popup`。此处保留记录：**不要用 `ToolTip` 承载需要滚动的浮层**。

**断言**：
- `FlowCanvasChecks` 的 `[G9]` 新增 **4 条**类型短名断言（`System.Double → Double` / 程序集限定名 / 泛型去实参与元数 / 空与空白 → 空串）。
- `_ToolboxProbe` 新增 1 条"预览浮层：端口带类型与注释"，并**出图 `toolbox-preview.png`**（探针取图前会重新量一次——端口容器是 Pump 之后才生成的，按旧 `DesiredSize` 截会把输入/输出整段裁掉）。

**验证证据**：`dotnet build VisionMaster.sln` 退出码 0；`FlowCanvasChecks` 退出码 0（**G9 现 25 条全绿**）；`_ToolboxProbe.exe` **通过 20 / 失败 0**（预览文本实测 `In | HImage | 输入图 | Out | Double | 结果`）；`UIThemeSmokeTest` 退出码 0（仍是第三方 `VM3.0-main` 的 GridView 既有 FAIL）。

## 九、补强 2：悬停预览改"视图自管 Popup"（限高 + 真能滚）＋ 分组默认折叠（2026-10-14）

**需求**：① 悬停预览要"限高 + 真能滚"；② 分类分组默认折叠。

### ① 预览从 `ToolTip` 换成视图自管的 `Popup`

- **现象**：§八 试过"`ToolTip` + `ScrollViewer` + `MaxHeight`"，真机上滚动条在、**点了不动**。根因：`ToolTip` 本身也是 `Popup`，但它的内容**拿不到焦点**，Popup 里的鼠标滚轮路由不到内容那一侧。
- **改法**：`ToolView` 自己开一个 `Popup`（`PreviewPopup`，`Placement="Left"`、`StaysOpen="True"`、`HorizontalOffset="-6"`）：
  - 条目 `MouseEnter` 起 300ms 延时开、`MouseLeave` 起 250ms 延时关（给鼠标跨越"条目 → 浮层"之间那段空隙的时间）；鼠标移进浮层取消关窗、移出重新计时；
  - 鼠标移进浮层时 `Keyboard.Focus(PreviewScroll)` —— **滚轮这才进得来**（这是不用 `ToolTip` 的根因）；关窗时把抢来的焦点还回去；
  - `Border` 限高 `MaxHeight="440"` + `ScrollViewer`；另挂 `PreviewMouseWheel` 手动滚动兜底（不同 WPF 版本/输入源的差异）。
- **代码后台**：`VisionMaster\Views\ToolView.xaml.cs`（原来只有 `InitializeComponent`，现在承载悬停定时器 / 开关窗 / 焦点 / 滚轮兜底）。
- `ToolPreviewTemplate` 现在只放"内容"；卡片外框 / 限高 / 滚动条都在 `PreviewPopup` 上。

### ② 分组默认折叠

- `ToolboxGroupViewModel` 改 `: BindableBase`，加 `IsExpanded`（TwoWay 绑 `Expander.IsExpanded`）+ `ExpandedChanged` 回调；`ToolViewModel` 用 `_expandedState` 字典记住用户的手动展开态（**分组实例每次过滤都重建，状态必须留在 VM 里才不丢**）。
- 默认：分类组**折叠**、「收藏」组**展开**；**搜索时命中分组强制展开**（否则结果全压在折叠头下面）。
