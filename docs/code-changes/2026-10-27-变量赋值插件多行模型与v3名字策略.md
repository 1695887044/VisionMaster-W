### 2.3 本轮真机修复（重要）

真机打开样例方案时发现：一条「全局」行打开后作用域显示「运行」、名字列却还是全局模板，右栏徽标也
显示「全局变量」——半旧状态。根因两条：

1. 作用域 `ComboBox` 在容器生成/回收时把 `SelectedValue` 推成 `null`；
   `AssignmentRow.Scope` 旧 setter 把空值回落成 `Runtime`，把迁移行的「全局」静默改成了「运行时」。
   **修法**：setter 忽略空值（不回落）；非法值由 `EnsureRowShape` 在加载/重建时归一。
2. `AssignmentRowVm` 只通知了 `Row.Scope`，没有通知 `IsGlobal` / `IsRuntime` / `ScopeText` /
   `CanCreate` / `ShowLock`，所以名字单元格/右栏徽标/自动创建列不换模板。
   **修法**：`RefreshHint` 里逐个 `OnPropertyChanged`。

修后真机复测：切全局 → 名字列/徽标/锁/失效提示立即一致；切回运行 → 名字仍在、手填徽标回来、
自动创建勾选框回来（但保持未勾，符合"切全局自动取消、切回不自动恢复"的约定）。

## 5. 踩过的坑

1. **`AssignmentRow.Scope` setter 回落 `Runtime` 是静默故障**：ComboBox 初始化/回收会推 `null`，
   真机表现为"全局行打开变运行时"，且不报错。空值必须忽略，非法值只在加载/重建时归一。
2. **派生投影不通知 = 半旧模板**：只通知 `Row.Scope` 不够；`IsGlobal`/`IsRuntime`/`ScopeText`/
   `CanCreate`/`ShowLock` 都要通知，否则名字列和右栏徽标会各显示一套。
3. **动态端口重建后必须回填常量**：`RebuildDynamicInputs` 先 `Dispose` 旧端口，再按 `ValuePortName`
   把旧常量填回；漏了就是"配置打开后值全没了"。
4. **`OnConfirm` 顺序不能换**：重建端口 → base 写回 → 清孤儿链接 → 去非连线常量 → 解旧名字连线；
   顺序错会留下孤儿链接或脏常量。
5. **真机测试不要直接改用户方案**：本轮把启动方案临时换成含测试节点的草稿，测试完已恢复原文件
   （大小/时间戳核对）；应用退出仍会写 `Autosave\recovered` 草稿，属于应用自动恢复，不是仓库产物。
6. **computer-use 驱动原生文件对话框时索引会漂**：`setValue` 文件名后再用旧索引点「打开」可能点到
   主窗口的其他控件；本轮改用"替换启动方案 + 直接双击节点"绕开文件对话框。另：同一 cell 里
   `setupComputerUseRuntime` 只能调一次，重复调会把 bridge 弄坏。
7. **样例方案的旧配置作用域是 Runtime**：迁移行的初始作用域来自旧 `Scope`，不是固定 Global；
   真机看到"运行"是旧配置本来的值，不是迁移 bug（修复后徽标/模板一致）。
8. **手册必须先于 gate 更新**：手册是嵌入资源，改了 `.md` 不重建 `Plugin.Util`，`audit_artifacts`
   会按 DLL mtime/资源数判红；本轮先改六页手册再重建，gate 才绿。
