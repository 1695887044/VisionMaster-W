# HALCON 手眼数值对拍（eye-in-hand / eye-to-hand）

> 日期：2026-10-26。目的：用 HALCON `calibrate_hand_eye` 独立复核「手眼」插件的
> `SolveAXEqualsXB` / `SolveAXEqualsZB`，回答"同一批观测下两边算出来是不是一样"。
> **不改产品代码**，只跑临时对拍探针。

## 一、当前状态

- **eye-in-hand（`hand_eye_moving_cam`）**：同一批 8 个 `find_calib_object` 观测、
  冻结内参与 `calib_obj_pose`、HALCON 用 `optimization_method='linear'` 时，
  插件 `SolveAXEqualsXB` 与 HALCON `calibrate_hand_eye` 的 4×4 结果差：
  **旋转 1.466e-5 rad（约 0.00084°），平移 1.148e-2 mm**。
- **eye-to-hand（`hand_eye_stationary_cam`）**：同一条件下，
  X（`base_H_cam`）差 **旋转 1.508e-5 rad / 平移 1.171e-2 mm**；
  Z（`obj_in_tool`）差 **旋转 1.549e-5 rad / 平移 6.999e-3 mm**。
- 结论：**手眼求解器与 HALCON 线性法数值一致**，差异在 HALCON 自身数值优化/舍入量级，
  没有发现系统性偏差。两种装法的链式关系（HALCON `tool_in_cam_pose` / `base_in_cam_pose`
  与插件 X 互为逆）也已逐项核对。

## 二、已做

### 2.1 对拍方法

临时探针（`%TEMP%\vm-halcon-handeye-compare`，`net9.0-windows`）：

- `ProjectReference` 到 `Plugins\Plugin.HandEye\Plugin.HandEye.csproj`，直接调
  `HandEyeMath.SolveAXEqualsXB` / `SolveAXEqualsZB`；
- `Reference` 到 `DLL\Halcon\halcondotnet.dll`；
- 用真值 X、板位姿 B 和机器人位姿 A 合成 8 组样本，`sim_caltab` 生成 8 张图，
  `find_calib_object` 得到估计 B（8/8 找到），再把**同一批估计 B 和 A**同时喂给
  插件与 HALCON；
- HALCON 侧 `create_calib_data` → `set_calib_data_cam_param` → `set_calib_data_calib_object`
  → `find_calib_object` + `set_calib_data('tool', …)` → `calibrate_hand_eye`；
- 为做"同一输入"对比，HALCON 侧冻结内参与所有 `calib_obj_pose`：
  `excluded_settings='all'`，并设 `optimization_method='linear'`。

### 2.4 HALCON 默认联合优化的差异

不冻结内参/板位姿、用 HALCON 默认非线性优化时，两边差约 **0.065~0.071 mm**，
但 HALCON 自己与真值也差 0.066~0.072 mm，插件差 0.018~0.020 mm。差异来自 HALCON
同时优化内参与标定板位姿，不是手眼求解器公式不同；冻结后差降到 **0.009~0.012 mm**。

## 五、踩过的坑

- **`create_pose` 的旋转参数是"度"，不是弧度**。按弧度传（0.17/0.35/0.52）会得到
  接近单位阵的旋转，`sim_caltab` 生成的板姿态和 `find_calib_object` 估计的 B 一起错，
  表现为"B 旋转差 10~21°、平移几乎为零"的假象。
- **HALCON `'gba'` 的实际矩阵是 `Rx·Ry·Rz`，不是插件 ZYX 的 `Rz·Ry·Rx`**。
  手工拆欧拉角再 `create_pose` 会得到不同的旋转；正解是把插件的 3×4 矩阵直接交给
  `hom_mat3d_to_pose`，让 HALCON 自己选规范表示，`pose_to_hom_mat3d` 可精确还原
  （往返旋转/平移误差均为 0）。
- **`HPose.RawData` 是 `HTupleMixed`**（带 `"Rp+T"`、`"gba"`、`"point"` 字符串），
  `set_calib_data` / `find_calib_object` 不接受；必须用 `create_pose` /
  `hom_mat3d_to_pose` 产生的规范 `HTuple`。用 mixed 元组设置 `tool_in_base_pose`
  会让 HALCON 认不到工具位姿，`calibrate_hand_eye` 报 **#8480 "Not enough
  calibration object poses"**。
- **`find_calib_object` 在 23.05 没有 `InitialPose` 参数**：第 5 个参数是
  `GenParamName`，传 pose 会报 **#1205 Wrong type of control parameter 5**。
- **`get_calib_data('calib_obj_pose', …)` 在校准前不可读**（#8451 "Model not optimized
  yet"）；校准前取观测位姿要用 `get_calib_data_observ_pose`。
- **`set_calib_data('calib_obj_pose', [CalibObjIdx, CalibObjPoseIdx], 'pose', …)` 的
  ItemIdx 是二元组**；用 mixed `HPose.RawData` 当 DataValue 会报 #1304，改用规范
  pose 元组即可。
- **临时探针必须删**（R134）：本记录保留输出原文，探针目录用完即删。
