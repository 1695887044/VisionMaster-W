## 2. 范围（做什么 / 不做什么）

### 做

1. 新插件 `Plugin.DeformableMatching`，两种算法二选一：
   - `LocalDeformable`：局部非刚性；
   - `PlanarUncalibDeformable`：平面透视（未标定单应）。
2. 单模板（一个步骤一个模板）：参考图 + ROI + 掩膜 + 学习/重学 + 模型 base64 随方案落盘。
3. 输出端口：
   - 公共：`MatchCount / Score / Row / Column / Scores / Rows / Columns`
   - 局部：`DeformedContours`（HALCON 直接返回）、`RectifiedImages`（每个命中的校正图，image array）
   - 平面：`HomMat2D`（每命中 9 个 double，拼接成一个 HTuple）
   - 两种模式都尽量输出 `DeformedContours`：局部用 HALCON 返回值；平面用
     `GetDeformableModelContours` + `ProjectiveTransContourXld` 投影得到。
4. 配置界面：参考图路径、ROI（先用数值：中心行/列、半长/半宽、角度）、掩膜、算法、
   角度/缩放范围、平滑度、学习按钮、状态栏、结果表。
   **UI 部分先走 U0 Web 设计基线（R110/R111/R127）：没有基线不得写 WPF 视图。**
   算法/端口/模型持久化属非可视代码（R109），不受此限，可与 U0 并行。
5. 帮助手册 L 档（用户页 ≥5、开发页 ≥3、开发页行数 ≥300）。
6. 断言：`FlowCanvasChecks/DeformableMatchingChecks.cs`，与本进程内 HALCON 参考实现逐项比对。
7. 两条中文流程加入 `解决方案\视觉样例对拍\视觉样例对拍.vms`。
8. `docs/code-changes/` 实施记录（五段式）。

### 不做（v1 明确排除）

- 不做多模板/配方库（一个步骤一个模板；升级路径见 §9）。
- 不做 `PlanarCalibDeformableModel`（需要相机标定，v1 只做 uncalib）。
- 不做 `max_deformation`（那是现有 shape model 的参数，属于另一条线）。
- 不改 `Plugin.Matching` 的任何行为；不引用 `Plugin.Matching` 程序集（避免插件间依赖）。
- 不做实时性优化/并行调参；只保证结果正确与可用。
- 不覆盖 HALCON 的 `enhanced/maximum` 之类识别档位（deformable 没有这个参数）。

### 2.1 为什么是新插件，而不是并进 `Plugin.Matching`（设计决策，2026-10-26 评审）

> 先澄清：**A 方案本身已经是"一个插件装两种算法"**（Local + Planar 共用一个
> `Plugin.DeformableMatching`）。这里回答的是"为什么不把它并进现有 `Plugin.Matching`，
> 靠属性面板反射生成控件来切换参数"。

**硬边界是端口契约，不是 UI。** 流程里的端口是步骤之间的公开 API，下游按"名字 + 类型"连线：

| 现有 `MatchingPlugin` 端口 | 局部形变 | 平面透视 |
| --- | --- | --- |
| `Angle` / `Angles` | HALCON 不返回 | 透视下角度语义不唯一 |
| `Scales` | HALCON 不返回 | 只能从 HomMat2D 反推 |
| `AlignedImage`（刚性位姿归一化） | 语义不同（局部校正图） | 不适用 |
| — | 需要 `DeformedContours` | 需要 `HomMat2D` |

并进 `Plugin.Matching` 只有两条路：① 让 `Angle/Scales` 在新算法下静默为空/0 —— 下游已连的
步骤会拿到假值，属于本仓最忌讳的"静默错误"；② 改现有端口语义 —— 直接打破存量 `.vms` 与
3752 条断言。两者都不可接受。

**反射属性面板替代不了学习视图。** `FlatPropertyGrid` 能从 `[PropertyItem]`/`[SuperDisplay]`
生成标量控件，R106/R107 也支持"切换字段 + 嵌套子对象 + `RequireRefresh`"做多态配置；但它生成不了：
参考图预览、ROI 画布、涂抹掩膜、学习按钮、结果表。现有 `MatchingPlugin` 走的是
`IPluginCustomViewProvider` + `MatchingView.xaml`，新插件同样需要 `DeformableMatchingView.xaml`。
反射面板最多省掉"参数区"的手写，省不掉学习工作流。

**`RequireRefresh` 是配置模型的多态方案，不是运行期算法切换。** R106/R107 的前提是：
切换字段走 `SetProperty`、被切换对象每次换新实例、整表重建。它适合"通讯驱动/轴配置"这类
互斥配置块；用在"算法切换"上，仍要插件自己处理创建期/查找期参数、模型过期、模型类型校验——
这些逻辑一行都省不掉。

**另外三条工程理由：**

1. **schema 兼容**：`MatchingTemplateEntry` 已经作为 JSON 落在 `.vms` 里，还带着旧单模板迁移字段
   （`TemplateModel`/`TemplateShape`/…）。再加两种模型的字段与算法枚举值，要做迁移与回归；
   新插件是干净 schema，存量方案零风险。
2. **模型生命周期**：`EnsureModelLoaded`/`ReleaseEntryModel` 已按 Shape/NCC 分支；再加
   Local/Planar 是四路分支。新插件用自己的一份缓存更简单。
3. **测试与手册**：`MatchingPlugin` 已有 3752 条基线断言和 L 档手册；并进去等于把新算法的
   回归风险压到存量插件上。独立插件可以单独对拍、单独写手册（L 档），失败也不污染存量。

**什么时候"一个插件"是合理的：** 如果从零设计、且愿意把端口收敛成一个模式无关的
`MatchResult` 对象（或接受"某些端口在某种模式下为空"的显式契约），一个插件装四种算法是可行的。
但那是公共契约重构，不是 v1 的范围；本仓已有 `MatchingPlugin` 的存量契约不允许这么做。

### 4.2 模板条目（单模板）

`DeformableTemplateEntry`（普通类，实现 INPC；**不要**引用 `Plugin.Matching`）：

```csharp
public sealed class DeformableTemplateEntry : INotifyPropertyChanged
{
    public string Name { get; set; } = "模板1";
    public string RefImagePath { get; set; } = "";       // 学习用参考图（绝对路径；只有重学才需要）
    public string Shape { get; set; } = RoiShapeNames.Rectangle; // Rectangle / Circle / Ellipse
    public double[] TemplateRect { get; set; } = [];     // [row, col, phiRad, half1, half2]
    public string TemplateMask { get; set; } = "";       // 掩膜 PNG base64，可空
    public string Model { get; set; } = "";              // 形变模型 base64
    public DeformableAlgorithm Algorithm { get; set; } = DeformableAlgorithm.LocalDeformable;
    public DeformableAlgorithm LearnedAlgorithm { get; set; } = DeformableAlgorithm.LocalDeformable;
    public string LearnedSignature { get; set; } = "";   // 学习时的创建期参数指纹
    public int NumLevels { get; set; } = 0;              // 创建期 0 → 'auto'；查找期 0 合法（默认）
    public double AngleStartDeg { get; set; } = -30;     // 查找期参数（创建期 HALCON 不读）
    public double AngleExtentDeg { get; set; } = 60;     // 查找期参数
    public double ScaleRMin { get; set; } = 1;           // 创建期参数（最小尺度）
    public double ScaleRMax { get; set; } = 1;           // 查找期参数（创建期不读）
    public double ScaleCMin { get; set; } = 1;           // 创建期参数
    public double ScaleCMax { get; set; } = 1;           // 查找期参数（创建期不读）
    public double Smoothness { get; set; } = 11;         // 查找期参数；HALCON 典型 11，最小 3
    public bool UsePolarity { get; set; } = true;        // 创建期参数
    [JsonIgnore] public HTuple? RuntimeModelId;          // 运行期模型句柄（不落盘）
    [JsonIgnore] public string? RuntimeModelSource;      // 句柄对应的 Model 载荷（缓存键）
    [JsonIgnore] public HObject? RuntimeModelContours;   // 平面模式：模型轮廓缓存（随句柄释放）
}
```

- 落盘（**定稿**）：整体序列化成一个 `TemplateJson` 字符串，照 `MatchingPlugin.TemplateLibraryJson`
  的做法——`[StepConfig] public string TemplateJson { get; set; } = "{}";`，
  `OnConfirm` 里 `JsonConvert.SerializeObject(entry)`。**不要**把 14 个字段直接摊成插件级
  `[StepConfig]`：属性面板会出现一堆模型内部字段，而且 v2 升多模板时要改 schema。
  `double[]` 不是问题（Matching 的 `TemplateRect` 已有先例）。
- **创建期 vs 查找期（必须分开写）**：
  - 创建期（改了就重学）：`Algorithm` / `Shape` / `TemplateRect` / `TemplateMask` / `NumLevels` /
    `UsePolarity` / `ScaleRMin` / `ScaleCMin`。
  - 查找期（改了不重学）：`Smoothness` / `MinScore` / `MaxMatches` / `MaxOverlap` / `Greediness` /
    `AngleStartDeg` / `AngleExtentDeg` / `ScaleRMax` / `ScaleCMax`。
  - HALCON 23.05 文档明确：`create_local_deformable_model` 与
    `create_planar_uncalib_deformable_model` 的 `AngleStart` / `AngleExtent` / `ScaleRMax` /
    `ScaleCMax` **not used**，这四个只在 `find_*` 生效；创建时传 `[]`，不要传用户值。
- 模型载荷：`WriteDeformableModel(modelId, tempFile)` → `File.ReadAllBytes` → base64；
  运行期 `EnsureModelLoaded(entry)`：`RuntimeModelId != null && RuntimeModelSource == entry.Model`
  就复用，否则 `File.WriteAllBytes` → `ReadDeformableModel` → 缓存；临时文件用
  `Path.GetTempFileName()`，`finally` 删除。**绝对不要每帧重读模型**（形变模型比 shape model 大得多）。
- 模型类型校验：学习时把 `LearnedAlgorithm = Algorithm` 写进条目；运行期先比
  `LearnedAlgorithm` 与当前 `Algorithm`，不一致就
  `Fail("模板是用「X」学的，当前算法是「Y」：请重新学习")`。**只存一个 `Algorithm` 字段是校验不了的**
  ——用户切换算法时那个字段已经变成新值了。
- 过期判定：`LearnedSignature` 存创建期参数指纹
  （`Algorithm|Shape|Rect|Mask.Length|NumLevels|UsePolarity|ScaleRMin|ScaleCMin`），查找期参数不进指纹。
  `IsModelStale` 只比这个指纹，照 `MatchingPlugin.cs:1265`。
- 学习/重学/`Dispose` 都要 `ClearDeformableModel`；学习时创建的临时模型写完立即清掉；
  平面模式的 `RuntimeModelContours` 随模型句柄一起 Dispose。

### 4.3 端口

```csharp
public InputPort<HImage> Image { get; } =
    new("Image", null!, "待搜索图像") { IsRequired = false };
public InputPort<HRegion> SearchRegion { get; } =
    new("SearchRegion", null!, "搜索区域（可选，未连=全图）") { IsRequired = false };

public OutputPort<int> MatchCount { get; } = new("MatchCount", "命中实例数");
public OutputPort<double> Score { get; } = new("Score", "最高分实例分数（0~1）");
public OutputPort<double> Row { get; } = new("Row", "最高分实例中心行（亚像素）");
public OutputPort<double> Column { get; } = new("Column", "最高分实例中心列（亚像素）");
public OutputPort<HTuple> Scores { get; } = new("Scores", "各实例分数数组");
public OutputPort<HTuple> Rows { get; } = new("Rows", "各实例中心行数组");
public OutputPort<HTuple> Columns { get; } = new("Columns", "各实例中心列数组");
public OutputPort<HXLD> DeformedContours { get; } = new("DeformedContours", "各实例形变后的轮廓");
public OutputPort<HTuple> HomMat2D { get; } = new("HomMat2D", "平面模式：每命中 9 个 double 的单应矩阵；局部模式为空");
public OutputPort<HObject> RectifiedImages { get; } = new("RectifiedImages", "局部模式：每个命中的校正图（image array）；平面模式为空");
public OutputPort<HImage> MeasureImage { get; } = new("MeasureImage", "标注图（轮廓 + 分数 + 判定文字；无命中也要出）");
```

- **不要**声明 `Angle` / `Scales`：局部模式 HALCON 不返回，平面模式要反推且透视下角度语义不唯一。
  帮助文档必须写清"要角度请用现有模板匹配或平面模式自行从 HomMat2D 反推"。
- **`RectifiedImages` 必须是 `HObject`（image array）**：HALCON 的 `ImageRectified` 类型是
  `(multichannel-)image(-array)`，每个命中一张；`OutputPort<HImage>` 装不下多张。若现场只要最佳一张，
  另加 `OutputPort<HImage> RectifiedImage` 并明确"只在 `MaxMatches=1` 时有意义"，不要用一个端口
  含糊两种语义。
- **两个输入端口都要 `IsRequired = false`**：`SearchRegion` 描述写了"可选，未连=全图"，
  但 `InputPort.IsRequired` 默认 `true`（`InputPort.cs:27`），不写就会被流程编译器判成必填；
  `Image` 也一样，否则 §4.6 的"上游无图 → Fail"永远不会执行。
- 无命中语义与现有 `MatchingPlugin` 一致：`Success=false` + 中文原因，`MatchCount=0`，
  标量端口置 0、数组清空；`MeasureImage` 仍输出（原图 + 红字原因），`RectifiedImages` 置空。
- `Score/Row/Column` = 最高分实例：**用 `TupleMax` + `TupleFind` 取索引**，不要假设 HALCON 按分数降序
  （P2 实测 `rows=[349.5,149.5]`，两个分数相同但第二个实例排在前面）。
- `DeformedContours` 赋值用 `new HXLDCont(deformedContours)`（照 `BeadInspectPlugin.cs:487`）；
  端口声明 `OutputPort<HXLD>` 即可。**它是扁平 XLD 数组，每命中多段**（P2 实测 486 段/命中），
  `CountObj` ≠ `MatchCount`；下游不要按命中数分组。
- 补 `[StepConfig] DisplayViewIndex`（1~9，0=不发布）和 `MeasureImage`，照
  `MatchingPlugin.cs:187-192/274`；否则现场只能看端口、主界面看不到结果。

### 4.4 学习（模型创建）

```csharp
// 1) 读参考图 → 灰度
HOperatorSet.ReadImage(out HObject img, entry.RefImagePath);
// 3 通道：Rgb1ToGray；4 通道：取前 3 通道再 Rgb3ToGray（照抄 BlobDetect 的 TryToGrayImage）
// 2) 生成 ROI 区域（按 entry.Shape 选算子）
//    Rectangle: GenRectangle2(row, col, phi, half1, half2)
//    Circle:    GenCircle(row, col, radius)
//    Ellipse:   GenEllipse(row, col, phi, radius1, radius2)
HOperatorSet.ReduceDomain(gray, roi, out HObject reduced);
// 3) 掩膜（可选）：把 TemplateMask 解成 HRegion，Difference(reduced, mask, reduced2)
// 4) 建模型（创建期参数；AngleStart/AngleExtent/ScaleRMax/ScaleCMax 传 []，HALCON 不读）
//    创建期 NumLevels 可传 'auto'；查找期只能传 0..10（见 §4.5），别用同一个变量两处传。
var createNumLevels = entry.NumLevels <= 0 ? new HTuple("auto") : new HTuple(entry.NumLevels);
if (Local)
    HOperatorSet.CreateLocalDeformableModel(reduced, createNumLevels,
        new HTuple(), new HTuple(), "auto",
        entry.ScaleRMin, new HTuple(), "auto",
        entry.ScaleCMin, new HTuple(), "auto",
        "none", entry.UsePolarity ? "use_polarity" : "ignore_local_polarity",
        "auto", "auto", new HTuple(), new HTuple(), out modelId);
else
    HOperatorSet.CreatePlanarUncalibDeformableModel(reduced, /* 同上 17 个输入参数 */, out modelId);
// 5) 原点：set_deformable_model_origin 的参数是"相对域重心的偏移"，不是图像绝对坐标！
//    先取域、算重心，再把"想当原点的点"减掉重心。
//    roiCenterRow/roiCenterCol 来自 entry.TemplateRect[0]/[1]。
HOperatorSet.GetDomain(reduced, out HObject domain);
HOperatorSet.AreaCenter(domain, out HTuple area, out HTuple cogRow, out HTuple cogCol);
double originRow = roiCenterRow - cogRow.D;
double originCol = roiCenterCol - cogCol.D;
HOperatorSet.SetDeformableModelOrigin(modelId, originRow, originCol);
//    矩形/圆这类对称 ROI 的 roiCenter 就是重心 → 传 (0,0)；非对称掩膜必须按上式算。
// 6) 落盘 + 指纹 + 清临时句柄
HOperatorSet.WriteDeformableModel(modelId, tempFile);
entry.Model = Convert.ToBase64String(File.ReadAllBytes(tempFile));
entry.LearnedAlgorithm = entry.Algorithm;
entry.LearnedSignature = EntrySignature(entry);
HOperatorSet.ClearDeformableModel(modelId);
```

参数默认值（创建期）：`numLevels='auto'`、`angleStart=[]`、`angleExtent=[]`、`angleStep='auto'`、
`scaleRMin=1`、`scaleRMax=[]`、`scaleRStep='auto'`、`scaleCMin=1`、`scaleCMax=[]`、
`scaleCStep='auto'`、`optimization='none'`、`metric='use_polarity'`、
`contrast='auto'`、`minContrast='auto'`、`genParamName=[]`、`genParamValue=[]`。
**`angleStart/angleExtent/scaleRMax/scaleCMax` 在创建期不被使用（23.05 文档原文 "not used"），
用户填的角度/缩放上限只在 `find_*` 里传；创建期这四个一律 `[]`。**
弧度 = 度 × π/180，只在 `find_*` 里换算。

C# 侧两个创建算子的参数顺序完全一致（23.05 反射确认；`template` + 16 个 HTuple = 17 个输入，
方案原文的"17 个参数"按这个口径算）：

### 4.5 查找

**局部非刚性**：

```csharp
HOperatorSet.FindLocalDeformableModel(
    gray, out HObject rectified, out HObject vectorField, out HObject deformedContours,
    modelId,
    angleStartRad, angleExtentRad,
    scaleRMin, scaleRMax, scaleCMin, scaleCMax,
    minScore, maxMatches, maxOverlap, entry.NumLevels, greediness,
    new HTuple("deformed_contours", "image_rectified"),
    new HTuple("deformation_smoothness", "expand_border", "subpixel"),
    new HTuple(entry.Smoothness, 0, 1),
    out HTuple score, out HTuple row, out HTuple col);
```

- 查找期 `NumLevels` 是 **int 0..10**（0=默认），不能传创建期的 `'auto'`；这里直接用 `entry.NumLevels`。
- `Score/Row/Column` 直接用 HALCON 返回值；标量端口取最高分实例（`TupleMax` + 索引），
  数组保持 HALCON 顺序。
- `DeformedContours` = `deformedContours`（XLD array，每命中 486 段——P2 实测；
  `new HXLDCont(...)`）；
  `RectifiedImages` = `rectified`（**image array，每个命中一张**；P2 实测 `CountObj=2`；
  `OutputPort<HObject>`）。
- `vectorField` 不需要就 `Dispose`；如果保留，后续可做输出端口（v1 不做）。
- `ImageRectified` 的尺寸是模板域的轴对齐包围盒（`expand_border=0` 时紧贴），不是旋转 ROI。

**平面透视**：

```csharp
HOperatorSet.FindPlanarUncalibDeformableModel(
    gray, modelId,
    angleStartRad, angleExtentRad,
    scaleRMin, scaleRMax, scaleCMin, scaleCMax,
    minScore, maxMatches, maxOverlap, entry.NumLevels, greediness,
    new HTuple(), new HTuple(),          // GenParamName/Value：默认
    out HTuple homMat2D, out HTuple score);
```

- `homMat2D` 长度 = `9 * MatchCount`；原样写入 `HomMat2D` 端口。
- 每个命中取 `hom = homMat2D.TupleSelectRange(i*9, i*9+8)`；
  用模型参考点 `(0,0,1)` 做投影。**优先用 `ProjectiveTransPixel(hom, 0, 0, out row, out col)`**
  （23.05 反射确认存在，内部已做齐次除法），比手写 `ProjectiveTransPoint2d` + 除 `qw` 少一个坑：

  ```csharp
  HOperatorSet.ProjectiveTransPixel(hom, new HTuple(0.0), new HTuple(0.0),
      out HTuple row, out HTuple col);
  ```

  若要手写：`ProjectiveTransPoint2d(hom, 0, 0, 1, out qx, out qy, out qw)`，
  `row=qx/qw`、`col=qy/qw`；`qw` 接近 0 时明确失败，不要除出 `Infinity`。
- **原点语义**：`set_deformable_model_origin` 的参数是相对域重心的偏移（见 §4.4）。
  设成 ROI 中心后，`get_deformable_model_contours` 会把参考点归一到 `(0,0)`，所以投影 `(0,0)`
  得到的就是 ROI 中心。若不设原点，参考点是重心，投影 `(0,0)` 得到的是重心；要 ROI 中心必须投影
  `(roiCenter - cog)`，**不能直接投影绝对 ROI 中心**。
- `DeformedContours`：**模型加载后**（`EnsureModelLoaded` 读到 `RuntimeModelId` 后）调
  `GetDeformableModelContours(out modelContours, modelId, 1)` 并缓存到 `RuntimeModelContours`；
  **不要在学习临时模型上取完就清掉**（`ClearDeformableModel` 后轮廓对象不再可用）。
  （**level 是 1 基**：0 非法 #1302，合法范围 1..num_levels；探针实测 3 层模型 level 1/2/3 都 OK，
  level 0/4 都 #1302。）
  运行期对每个 `hom` 调 `ProjectiveTransContourXld(RuntimeModelContours, out one, hom)`，
  `ConcatObj`，最后 `new HXLDCont(concat)`。
- `RectifiedImages` 置空（v1 不做）；`MeasureImage` 仍画投影轮廓 + 分数。

**搜索域**：`SearchRegion` 已连接且非空 → `ReduceDomain(gray, region, searchGray)`；
为空/未连 → 全图，并写一条 Info（照抄 Matching 的搜索域口径）。

### 4.6 失败语义（必须与现有插件一致）

| 情况 | 行为 |
| --- | --- |
| 上游无图 / 图未初始化 | `Fail("输入图像为空或未初始化")` |
| `RefImagePath` 为空 | `Fail("还没设置参考图：请打开配置界面选择参考图并学习模板")` |
| `Model` 为空 | `Fail("模板还没学习：请打开配置界面点「学习模板」")` |
| 模型损坏 / `ReadDeformableModel` 失败 | `Fail("模板加载失败（载荷损坏？请重新学习）")`，并清掉 `RuntimeModelId` |
| `LearnedAlgorithm` 与当前 `Algorithm` 不符 | `Fail("模板是用「X」学的，当前算法是「Y」：请重新学习")` |
| 学习时 ROI 越界/退化 | 明确失败，点名哪个参数 |
| 学习时 `NumLevels` 填 0 | 创建期映射成 `'auto'`；查找期 0 合法（表示默认），不要混用 |
| 未找到目标 | `Fail("未找到目标：分数 ≥ … 的形变匹配为 0（可降低分数下限/扩大角度缩放范围）")`，`MatchCount=0` |
| HALCON 算子抛异常 | `Fail($"可形变匹配失败：{ex.Message}")`，不让异常穿出 |

无命中时：`MatchCount=0`、`Score/Row/Column=0`、`Scores/Rows/Columns` 空、`HomMat2D` 空、
`DeformedContours` 空、`RectifiedImages` 空；`MeasureImage` 仍输出原图 + 红字原因。

## 6. 样例流程落盘（`.vms`）

### 6.1 两条流程

**方案是文件夹**（2026-10-24 起的硬约束）：`解决方案\视觉样例对拍\视觉样例对拍.vms`
+ `Image\`（平铺一层）+ `Assets\Alarms\History\Logs\Users\`。新图先从
`Image\images\...` 复制进方案自己的 `Image\`。

**`ImageAcquisition` 必须 `FilePath=Image\<文件名>` + `ImageAssetId`**（根级
`ImageAssets` 里登记稳定 GUID + `RelativePath`）：宿主执行时经
`ProjectAssetPathResolver` → `SolutionProjectAssetResolver` 按「方案根 + RelativePath」
解析。只写相对 `FilePath` 不带 `ImageAssetId` 会报「路径不存在」
（`AcquireSingleFile` 只做 `File.Exists(相对路径)`，按进程 cwd 解析）。
注意：`SolutionService.LoadAsync` 不回填 `SolutionFilePath`，宿主加载后要
`solution.SolutionFilePath = 打开路径`，否则资产解析报「方案尚未保存」。

**每条流程都要有「结果显示」步骤**（现场流程：采集 → 算法 → 结果显示）：
`SrcImage` 接算法标注图（形变插件输出 `MeasureImage`），`r1..rN` 接 Score/Row/Column，
`DisplayViewIndex=1` 发布到图像窗口 1。

```text
视觉样例对拍
├─ 模板匹配_NCC散焦图
```

### 6.2 手写 `.vms` 的硬规则（已踩过，务必遵守）

1. 模型真源是插件 `[StepConfig]` 的 `TemplateJson` 字段（内含 `Model` base64），**不是**参考图路径；
   生成流程时用插件实例 `OnConfirm(step)` 捕获完整 `InputValues`，原样写入。
2. `LinkedSources` 的**键** = 下游输入端口名（`Image`）；
   `TargetPortName` = **上游输出端口名**（图像采集的 `Image`）；
   `DisplayAddress` = `读取xxx.Image`。写错会报
   `上游 '…' 不存在输出 '…'` + `必填参数未配置`。
3. `SolutionService.LoadAsync` 会自动补 `Home/Main/End`；找流程按 `FlowName`，不要按索引。
4. 生成后必须走三步验证：`LoadAsync` → `FlowCompiler.Compile` → 真插件 `Execute`。
5. 生成前备份 `.vms`；改完跑 `gen_docs_index.ps1` + `audit_docs.ps1`。
6. **`ImageAcquisition` 用相对 `FilePath` + `ImageAssetId`**：根级 `ImageAssets` 登记
   `AssetId` + `RelativePath=Image\<文件名>`；只写相对路径不带资产 Id 会报「路径不存在」。
   不要写盘符绝对路径（方案搬移会断）。
7. **每条流程末尾必须加「结果显示」步骤**：`SrcImage ← 算法.MeasureImage`，
   `r1..rN ← Score/Row/Column`，`DisplayViewIndex=1`。没有它，图像窗口只显示采集原图，
   不是现场流程。`ResultDisplay` 的动态口键就是 `r1/r2/...`，必须在 `Items` 里先定义。

## 7. 断言设计（数值口径）

### 7.1 局部非刚性

- 参考实现（断言里现算，不写死）：
  ```csharp
  // 创建期：angle/scale 上限传 []；NumLevels 可 'auto'
  // 查找期：NumLevels 只能 0..10（0=默认）
  int findNumLevels = entry.NumLevels <= 0 ? 0 : entry.NumLevels;
  HOperatorSet.CreateLocalDeformableModel(reduced, createNumLevels, new HTuple(), new HTuple(), "auto",
      scaleRMin, new HTuple(), "auto", scaleCMin, new HTuple(), "auto",
      "none", metric, "auto", "auto", new HTuple(), new HTuple(), out HTuple refModel);
  // 原点：相对域重心的偏移，不是绝对坐标
  HOperatorSet.GetDomain(reduced, out HObject refDomain);
  HOperatorSet.AreaCenter(refDomain, out _, out HTuple cogRow, out HTuple cogCol);
  HOperatorSet.SetDeformableModelOrigin(refModel, roiCenterRow - cogRow.D, roiCenterCol - cogCol.D);
  // 查找期：角度/缩放上限在这里传
  HOperatorSet.FindLocalDeformableModel(image, out _, out _, out HObject refContours, refModel,
      angleStartRad, angleExtentRad, scaleRMin, scaleRMax, scaleCMin, scaleCMax,
      minScore, maxMatches, maxOverlap, findNumLevels, greediness,
      new HTuple("deformed_contours"),
      new HTuple("deformation_smoothness", "expand_border", "subpixel"),
      new HTuple(smoothness, 0, 1),
      out HTuple refScore, out HTuple refRow, out HTuple refCol);
  ```
- **参数同源**：`minScore/maxMatches/maxOverlap/numLevels/greediness/smoothness/angle/scale`
  必须和被测插件读同一份配置（或两边显式写同一组常量）；不要在断言里硬编码一套、插件默认另一套。
- 判据：`MatchCount`、`Score`、`Row/Column`、`DeformedContours` 点数/坐标。
- **反向（具体场景，不要写"模板本身有角度"）**：模板用 0° 的 pen 裁剪块，搜索图旋转 30°；
  `find` 角度范围 0/0 → 参考实现和插件都必须 0 命中；角度范围 -180/180 → 两边都必须 ≥1 命中。
  局部模式的创建期角度参数不生效，反向断言只能改 **find** 参数。

### 7.2 平面透视

- 参考实现（参数与插件读同一份配置）：

## 10. 风险与已知坑

1. **模型句柄生命周期**：学习/重学/`Dispose` 都要 `ClearDeformableModel`；
   泄漏会在长时间运行后拖垮 HALCON。
2. **局部模式不返回角度/缩放**：不要为了"端口齐全"伪造 0；帮助里写清"不可用"。
3. **平面模式不直接返回 Row/Column/Angle**：必须从 `HomMat2D` 推；优先
   `ProjectiveTransPixel`，手写 `ProjectiveTransPoint2d` 时注意齐次坐标要除以 `qw`（并防 0）。
4. **`SetDeformableModelOrigin` 是相对域重心的偏移**（不是绝对坐标！）：先用探针 +
   `GetDomain` + `AreaCenter` 验证；矩形/圆对称 ROI 传 `(0,0)`，非对称掩膜传 `roiCenter - cog`。
   写成绝对坐标会让 Row/Column 和 HomMat2D 投影整体偏掉。
5. **`FindLocalDeformableModel` 的 `image_rectified` 是 image array**：每个命中一张
   （文档类型 `(multichannel-)image(-array)`），不是单张最佳匹配；端口用 `HObject`。
6. **`Model` base64 体积**：形变模型比 shape model 大，`.vms` 会明显变大；
   可接受，但不要每个步骤存多份。
7. **`VisionMaster.exe` 在跑**：会锁 `Modules\Plugin.*.dll` 与宿主 `bin`。
   构建失败先看是不是宿主锁；只停自己的测试宿主，**不要杀用户的 `VisionMaster.exe`**。
8. **`FlowCanvasChecks` 进程不退出**：会锁下一次 gate 的 `raw-*.log`；
   重跑前 `Get-Process FlowCanvasChecks | Stop-Process -Force`。
9. **手写 `.vms` 的端口名**：见 §6.2；这是 2026-10-26 刚踩过的坑。
10. **帮助资源**：`<EmbeddedResource Include="Help\**\*" />` 必须在本工程 csproj；
    改完必须重建插件；`audit_artifacts.ps1` 核 DLL 内嵌资源数。
11. **sln 登记**：新插件不登记 `VisionMaster.sln` 时，`dotnet build` 不编它，
    `Modules\` 永久停旧版且无报错（R62）。
12. **构建命令**：一律 `-m:1 -nodeReuse:false`；判据是 `0 个错误` **且**退出码 0。

### 10.1 2026-10-26 评审补充（按优先级）

13. **创建期 `AngleStart/AngleExtent/ScaleRMax/ScaleCMax` 不生效**（23.05 文档 "not used"）；
    只在 `find_*` 传，创建时一律 `[]`。

    （`StepConfigGenerator.cs:267`）；`MinScore=0` 会让所有东西都命中。

20. **HALCON 示例没装、`gen_random_vector_field` 不是算子**：M1 素材按 §5 的路线 A/B 做。
21. **`GetDeformableModelContours` level 是 1 基**：0 非法（#1302），合法范围 1..num_levels；

25. **`[ParallelSafe]` 要配实例级缓存**：`set_deformable_model_origin` 文档要求跨线程访问
    ModelID 同步；有疑问先不加。
26. **帮助每页 ≥70 行、首行 `# 一级标题`**（R41）；L 档总数只是下限。
27. **`NumLevels` 创建期可 `'auto'`、查找期只能 0..10**：不要用同一个变量两处传；

28. **UI 部分没有 Web 基线就写 WPF 视图 = 违反 R110/R127**：算法/端口/模型属非可视代码
