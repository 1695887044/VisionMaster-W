## 一、交付物

| 文件 | 内容 |
| --- | --- |
| `PoseTransformMath.cs` | 纯托管数学（零 HALCON，断言可完整覆盖）：正/反点变换、角度映射（图像 x 轴基准作差）、三类失配判定、位姿/像素点守卫、角度归一化 |
| `PoseTransformHalcon.cs` | HALCON 层（只做区域/图像变换）：`FollowRegion`（`vector_angle_to_rigid` + `affine_trans_region`）、`FollowImageBack`（对齐图，T⁻¹ + `affine_trans_image`）；度↔弧度只在这一层换算 |
| `PoseTransformPlugin.cs` | 两模式（FollowRoi / ToMechanical）/ 端口 / 配置态叠加预览（基准绿 + 跟随橙 + 参考点黄）/ 三个失配语义 |
| `Enum.cs`、`PoseTransformView.xaml(.cs)` | 模式与状态枚举；配置视图（模式页签式显隐 + 可链接参数行 + 标定信息只读块 + 预览图） |
| `FlowCanvasChecks\PoseTransformChecks.cs` | 39 条断言：数学层（手算常量钉方向与符号）+ HALCON 真算子层（姿态敏感/模板态自洽/对齐图方向）+ 插件层（真 `RunAlgorithm`） |

**端口面**（改名即断下游接线，已被断言锁住）：

| 方向 | 端口 | 类型 | 说明 |
| --- | --- | --- | --- |
| 入 | `SrcImage` | HImage（可选） | 尺寸失配校验（ToMechanical）/ 输出对齐图（FollowRoi） |
| 入 | `BaseRegion` | HRegion（FollowRoi 必填） | 接 MarkRegion，**画在模板图上** |
| 入 | `TemplateRefRow` / `TemplateRefCol` | double | 模板参考点（默认由基准 ROI 中心派生） |
| 入 | `PoseRow` / `PoseCol` / `PoseAngle` | double | 当前位姿（接 Matching；角度=度） |
| 入 | `Transform` | `CalibrationTransform?`（ToMechanical 必填） | 接「标定」插件输出（不允许手填矩阵） |
| 入 | `PixelPointRow` / `PixelPointCol` / `PixelAngle` | double | 待换算像素点/角度（角度接了才输出机械角） |
| 出 | `FollowedRegion` | HRegion | 接 BlobDetect.MaskRegion |
| 出 | `FollowedImage` | HImage（可选） | 对齐图（`EmitFollowedImage=true` 时） |
| 出 | `MechanicalX` / `MechanicalY` / `MechanicalAngle` | double | 机械坐标/角度（mm、度） |
| 出 | `PixelEchoRow` / `PixelEchoCol` | double | 反向回显（自校验，偏差 > 1e-6px 即失败） |

**失配三类（强制失败，文案带"下一步"）**：① 未接标定；② 当量标定（PixelScale）当机械坐标用；③ 当前图尺寸 ≠ 标定图尺寸（换分辨率/换相机须重标）。另加位姿 NaN/全零守卫与像素点 (0,0)/NaN 守卫（防匹配失败被静默变换）。

## 二、与方案说明书的差异（刻意 6 处）

| # | 方案原文 | 实现 | 理由 |
| --- | --- | --- | --- |
| 1 | §六 公式块：区域与图像都写 `affine_trans_* (…, HomMat2D, …)`（同一正变换 T） | 区域用 T（模板系→当前系）；**图像用 T⁻¹**（当前系→模板系） | **实现勘误**：两对象所在坐标系不同，"同一变换"对图是互逆的；对图也用 T 会把内容推离参考位姿**两倍**偏差（看着像"跟反了"）。断言「对齐图方向」用合成图亮点 (100,50)→参考点 (60,60) 锁死（写反会到 (140,40)） |
| 2 | 预览区"（有图时）"，未指定图从哪来 | 新增 StepConfig `PreviewImagePath`（浏览载入，运行期不读盘，与 Matching 同模式）；未载路径时若 `SrcImage` 有值直接当底图 | 配置态必须"保存前就有图可看"；运行语义不受影响（方案 §五 的意图落地） |
| 3 | §3.1 SrcImage 行写"像素尺寸失配校验" | 尺寸校验只在 **ToMechanical** 生效（FollowRoi 不消费标定，无"标定图尺寸"可比） | FollowRoi 没有可比对象；§四 的失配表本身就是 `SrcImage` vs `Transform` 的语义 |
| 4 | 决策 6：位姿 NaN/全零必须失败 | 同一口径**对称**加在 ToMechanical 的像素点（(0,0)/NaN 失败） | 匹配失败对两个模式给出的是同一种垃圾（0/NaN），只守一半等于留了个静默口 |
| 5 | 文件清单只有 Math + Plugin | 拆出 `PoseTransformHalcon.cs` | HALCON 只出现在区域/图像变换层（方案 §六·6 的"纯托管边界"）；拆出后断言可直呼该层（姿态敏感/对齐图方向） |
| 6 | 未提视图刷新时机 | 叠加预览只在配置窗口开着时刷新（`OnViewAttached/OnViewDetached`） | 对话框关了还做重采样是白干活（HALCON 对象+内存拷贝）；运行语义不受影响 |

## 三、断言抓出的语义不一致（已修）

- **现象**：断言里"直接调用 `RunAlgorithm`"（不经基类 `Execute`）时，上一轮的 `Success=false` 与 `ErrorMessage` 残留——成功轮被判为失败（4 条断言同时揭示：值都对，`Success` 停在 false、`ErrorMessage` 还是上一轮的"尺寸不符/位姿为0"）。
- **根因**：基类只在 `Execute` 里预置 `Success=true` / 清 `ErrorMessage`；插件自身没在 `RunAlgorithm` 轮首重置。
- **修法**：`RunAlgorithm` 轮首 `Success.Value = true; ErrorMessage.Value = string.Empty;`（与基类预置一致，直调路径语义一致）。
- **证据**：修后 39/39 全绿；成功路径机械坐标 = 手算常量 (405,307)。
