## 二、★ 上量前必修的真 Bug（CommunicationVariable.UpdateValue）

`Core/CommunicationContracts/CommunicationVariable.cs` L78：

```csharp
if (!_hasPublished || !Equals(CurrentValue, newValue))
```

`Equals` 对 `byte[]` 是**引用比较**——段读每次切出新数组 → 永不相等 → 每周期必触发 ValueChanged。同样问题：

- `float.NaN != float.NaN` → NaN 值每周期必触发
- 浮点抖动（123.456→123.457）每次触发

几万浮点变量 @1s = 每秒数万次事件穿过 MirrorCallback → SetProperty → UI 绑定链，UI 线程被打爆。

**修法方向**：数组按内容比较（Span 序列比较）+ 浮点死区（见 P0-1）。

## 三、对标商业 SCADA 的差距清单

### P0：几万点的生死线

1. **死区 Deadband**：浮点/模拟量设死区（绝对值或百分比），越过死区才算变化。现场经验值：模拟量加死区后事件量降 80~95%。
2. **质量戳 Quality**（OPC 灵魂，现状完全没有）：
   - 现状：段读失败 → 变量保持旧值静默；断线 → 全部值静止，UI 看起来"正常"。
   - 差距本质：UI 无法区分"值没变"和"这值是 10 分钟前的尸体"。
   - 方向：值包络 {Value, Quality(GOOD/BAD/UNCERTAIN), Timestamp}，段读失败打 UNCERTAIN，断线打 BAD。
3. **按点订阅**：现状全局 OnVarChanged 广播（画面显示 50 点却每秒收几万次回调）；商业做法按 TagId 订阅，内核先过滤。
4. **多扫描组 Scan Class**（KEPServer 叫 Scan Class / Ignition 叫 Tag Group）：
   - 现状：每连接单周期 ReadCycleMs，几万点同一节奏。
   - 方向：100ms 组（联锁）/ 1s 组（工艺）/ 10s 组（统计）/ 60s 组（累计），**组内照常批量合并**。
   - 与已删"变量级周期"的区别：变量级周期切碎批量段；扫描组整组共享周期，批量化不受影响。

### P1：可观测性与写链路

5. **诊断统计**：每连接扫描周期实测、读写计数、错误率、队列深度（现状运行期只有一条"轮询计划已更新"日志）。
6. **写优先级**：写与轮询同队列 FIFO、容量 256；商业做法写插队 + 写回执超时。
7. **单调时间戳**：`LastUpdateTime = DateTime.Now` 受系统对时回拨影响；改单调钟（TickCount64 基准）。

### P2：广度对标（按项目需要）

8. **浮点字序配置**：Modbus Float 现写死大端 ABCD；国产仪表大量 CDAB，商业驱动器全部可配。
9. **协议广度**：MC 协议（三菱）、Fins（欧姆龙）、EtherNet/IP、OPC UA Client。
10. **冗余/断点续传**：主备 PLC 切换、断线期间数据缓存补采。
