## 二、调用方式：位集取值与老值迁移（落盘纪律）

```csharp
[Flags] public enum FlowInvokeType
{
    Manual = 0,     // 手动：不接受任何自动触发（默认态，界面显示「手动」）
    Timer = 8,      // 定时
    Variable = 16,  // 变量触发
    Subroutine = 32,// 子程序调用
    Http = 64,      // HTTP 外部调用（唯一带门禁的位）
}
```

**为什么位值从 8 起跳、不是 1/2/4**：老文件里这个字段是**单选**枚举（1=定时、2=变量、3=子程序）。
若新位值取 1/2/4，老值 3（子程序）会与"定时|变量"**撞成同一个数**，读回来就变成另一种调用方式
（组态现场最怕的静默错事）。抬到 8/16/32/64 后，1/2/3 全部落在位区间之外，
加载时一眼可辨"这是老值"：`FlowInvokeTypeExtensions.MigrateLegacy`（1→Timer、2→Variable、3→Subroutine、
0→Manual、其它按位集原样保留——高版本位集读进低版本不许被清掉）。

**迁移时机**：`SolutionService.LoadAsync`（读入时换算一次，只改内存不回写；下次保存自然按新格式落盘）。
纪律与 `ScadaActionType` 一致：**数值一旦发布只许末尾追加，不许改、不许回收**。

**"待接通"口径**：`FlowInvokeTypeExtensions.PendingReason(flag)` —— 与 `ScadaActionType.PendingReason` 同款。
本批只接通 `Http`（返回 null）；`Timer/Variable/Subroutine` 各自返回一句话（"定时调度器待接通（下一期）"等），
流程管理列表把这句话显示在勾选框下方——**避免"勾了没反应 = 软件坏了"**，接通一位删一句。

## 四、HTTP 门禁（`HttpImageServer.HandleFlowPost`）

请求进入后按固定顺序判，**门禁放在图片解码之前**（不合规的请求连解码都省了）：

| 判定 | 状态码 | 文案要点 |
| --- | --- | --- |
| 方案里找不到该流程 | **404** | 「当前方案中没有名为「X」的流程」 |
| 流程已禁用（`IsEnabled=false`） | **403** | 「已被禁用，HTTP 触发被拒绝」（禁用优先于调用方式） |
| 调用方式未勾 HTTP（`IsHttpCallable()` 为假） | **403** | 「未开放「HTTP 外部调用」（当前调用方式：…）」+ 指路流程管理 |
| 会话正在运行 | **409** | 原有逻辑不动（抢不到会话锁前先自行判定，避免静默吞单） |

⚠ **行为变更（按需求刻意为之）**：老方案里所有流程的调用方式都是 `Manual`（老单选 0），
因此升级后**默认都不接受 HTTP 触发**——需要在「流程管理」里给对应流程勾上「HTTP」。
这是需求 2 的语义本身（"只有选择了这个的才能被调用"），HttpImageSmoke 里有正反两侧断言钉住。

## 五、强制骨架流程（Home / Main / End）

- `FlowRole { None=0, Home=1, Main=2, End=3 }` + `FlowModel.Role`（**落盘**，非 Flags——一条流程只有一个角色）；
- `MandatoryFlows`（Core，纯模型层）：
  - `Skeleton`：三角色的默认名与说明（Home「回原/回零」、Main「主任务」、End「收尾」）；
  - `Ensure(solution)`：**幂等**补齐，返回本次新建条数。补齐顺序：
    ① **老名字认领**——GoHome→Home、MainTask→Main（老默认名，保住用户已有内容，不重复建）；
    ② 按角色查漏——缺哪个建哪个；默认名被用户占用时**退让后缀**（Main → Main2），不覆盖用户流程；
  - `IsMandatory` / `FindByRole`；**判据是 Role 不是名字**——改名（Home 改叫"回原点"）不丢骨架属性；
- 落点：`SolutionModel.Flows` 初始化器预置三条（新建方案即自带）；`SolutionService.LoadAsync` 调用 `Ensure`
  （老方案打开即补齐）；`FlowListViewModel` 删除前拦截（`IsMandatory` → 提示且不删；改名声明确允许）。

## 六、同批收口

### 6.1 手动单流程运行/停止（`FlowListViewModel`）
右键「运行一次 / 循环运行 / 停止本流程」。会话准备与"编译本流程"同款（复用未过期会话，
缺了或 `Version` 涨了才重编译）；运行任务统一 `await` 到底（吞异常，避免未观察异常把进程打挂）；
非调试路径（不传 `debugSession`）。

### 6.2 `FlowModel.Role` / `InvokeType` 改动不惊动 `Version`
两者都不在 `Steps` 订阅链上，改调用方式/角色不会递增图纸版本 → 不会触发"图纸已修改，是否重新编译"的干扰提示。

### 6.3 骨架流程与会话
骨架流程也是普通流程（默认 `Manual`、启用），不特殊对待运行；"强制"只体现在**存在性**与删除约束上。

### 6.4 `FlowModel.RunState` 同步（救活 4 个死消费点）
`ShellViewModel.SyncFlowRunState`：会话状态事件 → 按流程名（Ordinal）找流程 →
`Running/Paused/→ Running/Paused/Stopped`，`StartRunTime` 只在"由非运行进入运行"时刷新。
消费点：`GlobalVariableManagerViewModel`、`FlowManagerViewModel`、`CommunicationSettingsViewModel`、
`CameraSettingsViewModel` 的"运行中禁止改配置"守卫（此前读的字段从没人赋值 = 守卫形同虚设）。
含 HTTP / 手动运行等一切非界面触发（事件源是引擎）。

**作用域如实说明**（审查 P2-3）：上述守卫读的是**当前选中流程**（`Workspace.CurrentFlow`）且只判 `Running`
（Paused 不拦）——镜像让它们从"永不生效"变成"选中的那条在跑时生效"；是否扩到"任意流程在跑 / 含暂停"待定（见第九节）。

### 6.5 运行锁收口（审查 P1 修复）
单流程运行的引入撕开了一个既有互锁缺口：`MainRunState` 只反映"界面发起的整体运行"，
单流程运行 / HTTP 触发都不写它，于是"运行中禁止编译"从这两个入口溜过去——
而编译走 `RegisterSession`，它会**先停掉同名运行会话（最长 3s）再挂新实例**，等于静默拆台。修复：

- `ShellViewModel.AnyFlowRunning()`：判"是否有任意流程在跑"（读会话级镜像，涵盖单流程 / HTTP / 界面运行）；
- `DoCompileAll` 前置拦截；`CanExecuteSolution`（新建/打开/切换方案）改为
  `RunState == NotStarted && !AnyFlowRunning()`，并在会话状态变更时一并 `RaiseCanExecuteChanged`；
- `FlowListViewModel`：「编译本流程」按"整体运行锁 **或本流程 RunState**"拦截；
  单流程运行把"已在跑"的判定**提到重编译之前**（编译会把老会话换掉，编译后再看 IsRunning 已经晚了）；
- 新建/改名入口加**流程名查重**（流程名是运行标识：会话、状态镜像、HTTP 路由全按名找）。
