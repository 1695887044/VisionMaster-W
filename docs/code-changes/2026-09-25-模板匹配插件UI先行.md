## 三点五、追加：提取参数 / 匹配参数分区（对照商用工具补齐创建态参数）

用户对照商用软件的模板编辑界面指出缺参数：创建模板时就有角度范围、角度步长、缩放范围、
梯度阈值、极性 —— 这些在 HALCON 里确实是**创建态**（角度范围/步长是 create_shape_model 的参数；
缩放范围在 create_scaled_shape_model 里也是创建参数），改成运行期等于模型永远按 ±180° 烤死。

重做后的参数结构：

- **② 提取参数（创建态，改任何一项 → 徽标转橙"参数已改·需重新学习"）**：
  最小/最大角度（-180~180，默认 ±180 与商用工具同口径）、角度步长（0=自动）、
  梯度阈值（0=自动）、使用极性（使用/忽略）、启用缩放 + 最小/最大比例（启用后走
  `create_scaled_shape_model`）、金字塔层数；
- **③ 匹配参数（运行态，改完立即生效）**：分数下限、匹配数上限、最大重叠、搜索激进度；
- **④ 输出**：不变。

配套机制：

- `_modelSignature` 指纹 = 模板区域 + 全部提取参数，`IsModelStale` 驱动徽标三态
  （灰"未创建" / 绿"模板已创建" / 橙"参数已改·需重新学习"）与过期警告；
- CreateTemplate 按 ScaleEnabled 分支调用 create_shape_model / create_scaled_shape_model，
  角度上下限自动排序、缩放上下限自动排序并夹取 [0.5, 2]。

## 三点六、追加：视图窗口首帧不铺满（HalconBase 显示修复）

用户反馈：推图到主界面"视觉图像"视图窗口时，图片缩在角落，要手动右键"适应图片/窗口"才铺满。

根因（HalconBase.HImageChangedCallBack，所有 HALCON 显示控件共用）：

1. 新图尺寸变化时走的是 `HWindow.SetPart(0,0,-2,-2)` —— 窗口级 part 会被
   HSmartWindowControlWPF 的内部缩放状态顶掉，铺满不生效；
2. 图像先于控件 Loaded 到达（流程后台先跑、用户才切到视觉图像页）时 hWindow 还没就绪，
   铺满被 `?.` 静默跳过，Loaded 后直接按默认 part 渲染 = 小图 + 黑边。

修复（对全部 HALCON 显示控件生效：主界面视图窗 / 各插件配置画布）：

- 铺满改走控件层 `hSmart.SetFullImagePart()`（与右键"适应图片/窗口"同一条内部路径，
  同步控件缩放状态）；时序 = 先渲染 → 铺满 → 重绘（在 disp 前调它实测会得到一整帧黑屏）；
- 窗口未就绪时置 `_pendingFitOnLoad`，Loaded 后首次渲染前补铺满。

同尺寸连帧不重铺满（保持既有约定：不抢用户手动缩放状态）。

验证：独立 FitProbe 双路径实测——"先图后加载"内容填充 99%×98%，"先加载后推图"
HALCON 帧缓冲转储 77%×100%（横向留边 = 按窗口比例适配的正确形态）。注意
RenderTargetBitmap 截 HSmartWindowControlWPF 的 D3D 合成面不可靠（会截出全黑），
验证 HALCON 显示必须用 `dump_window_image` 取帧缓冲真值。

## 三点七、执行内核接通（商业化主干完成）

RunAlgorithm 从 fail-fast 桩升级为完整内核：

- **懒加载模型**：运行实例按 TemplateModel（base64）经 temp 文件 `read_shape_model` 反序列化，
  载荷指纹比对 → 变了才重载，句柄与轮廓（`get_shape_model_contours` 最细层）全程缓存；
- **搜索**：`find_shape_model` / `find_scaled_shape_model` 按 ScaleEnabled 分支，搜索范围 =
  创建时烤入的角度/缩放范围，`least_squares` 亚像素，分数/个数/重叠/激进度全部夹取；
- **输出**：标量端口（Score/Row/Column/Angle）= 最高分实例；数组端口
  （Rows/Columns/Angles/Scores/Scales，弧度统一转度、未启用缩放 Scales 恒 1）= 全部实例；
- **AlignedImage 位姿归一化**：`vector_angle_to_rigid(命中位姿 → 模板位姿)` + `affine_trans_image
  (constant, 不自适应画幅)`——目标永远回到标准位姿，下游固定坐标插件零改动；
- **标注图**：原图 + 各命中实例的模型轮廓（绿）+ 白底判定文字；未找到 = 原图 + 红字原因
  （产线看现场），随 DisplayViewIndex 发布主界面；
- **失败语义**：输入空/模板未创建/未找到 = Fail（下游拿不到位姿无法继续），原因全中文。

冒烟（FlowCanvasChecks/MatchingChecks.cs，合成确定性图案，无外部样图）新增 24 条断言：
同图定位（分数 1.000、位置亚像素回准）、平移（(280,360) ±1 回准）、旋转 10°（角度回准 10.001°）、
缩放 1.15×（倍率回准 1.151）、base64 往返无损（新实例直接定位）、未找到失败语义、
多实例（count=2、分数 1.000、数组对齐）、提取参数变更触发重学提示。全套 **668 通过 / 15 失败**
（15 条为既有 [E12]+[W] 基线）。

踩坑记录（写进代码注释）：
1. `HOperatorSet.RotateImage` 的角度实测按**度**解释（传弧度值 0.1745 只转了 0.164°，
   与断言偏差吻合）——旋转测试直接传度数；
2. `AffineTransImage` 参数顺序是 `(HomMat2D, Interpolate, AdaptImageSize)`：
   写成 (hom, "false", "constant") 报 #3147 Wrong interpolation mode；
3. `AffineTransImageSize` 在本版本同样有参数顺序陷阱，已改用 AffineTransImage("constant","false")
   （输出同幅面）替代。

## 三点八、追加：模板区域支持圆形/椭圆 + 模型原点锚定（用户问"为什么不支持圆"）

原第一版把模板区域锁成矩形，是我保守设计，不是 HALCON 限制——create_shape_model 吃的是
"缩减域之后的图像"，域可以任意形状。已放开：

- **模板区域支持 矩形 / 圆形 / 椭圆**（画布右键画什么就是什么），参数约定与区域颜色检查
  完全同口径（圆 [行,列,半径,0,0]），`TemplateShape` 随方案落盘；
- 摘要/播种/签名/预览包围盒全部形状感知；圆形区域创建的模型更小（圆域实测载荷
  39580 字符 vs 矩形 76392 字符）；

配套的**模型原点锚定**（商业化定位精度的关键）：HALCON 默认模型原点取模型内部参考点，
与用户画的区域中心存在 1~2px 系统性偏差（圆域实测 +1.5,+1.5）。创建时在参考图上自匹配
一次量出偏差，`set_shape_model_origin` 锚回画布中心——之后 find 的 Row/Column 输出
= 用户画的区域中心，且随模型序列化、运行期自动一致。实测圆域定位回准 (150.00, 200.00)。
方向踩坑：`found_after = found_default − offset`（与直觉相反，已注释）。

## 三点十一、追加：涂抹笔画连续化（用户实测反馈"一次画一个圆"）

用户实测：涂抹按住拖动只能画出一个孤立的圆。根因有二，都在 HalconBase 的画笔层：

1. **HSmartWindowControlWPF 自带"拖拽平移"（HMoveContent 默认 true）**——按住拖动时
   平移逻辑接管鼠标，笔画只能落下第一个圆。修复：进入涂抹模式自动 `HMoveContent=false`
   （反射探针确认进入后为 False、退出后还原 True）；
2. **只在鼠标事件点盖一个圆**——事件稀疏时笔画断成串。修复：从上一落点到当前点按
   半径×0.6 步进**插值盖章**，单点去重（距上落点不足半个间距不重复盖）。

验证（SmearProbe 反射驱动画笔处理器，模拟稀疏拖动：落点间距 60/120px >> 笔刷直径 20）：
笔画面积 3916px² ≈ 理论连续胶囊面积 3914（旧实现同样事件只有孤立圆）。此修复对
模板匹配与区域颜色检查共用的画笔层同时生效。

## 三点十二、追加：修复"已学习但运行报尚未创建模板"（编译链路灌值口踩坑）

用户实测：配置界面明明已学习（徽标"已学习"），流程运行却报"尚未创建模板"。

根因：流程编译器给运行实例灌参数走的是 **`ApplyConfigValues(model)`，不调 Initialize**
（Engine/FlowCompiler.cs：`pluginBase.ApplyConfigValues(model)`），而模板库的
JSON 解析/迁移/编辑条目选择原来放在 `Initialize` 重载里——编译出的运行实例
`Library` 永远是空的。

修复：解析/迁移/选条目整体挪进 **`ApplyConfigValues` 重载**（base 灌完 [StepConfig]
后立即 ParseLibraryAndMigrate + 选编辑条目）——配置界面（Initialize）与编译器
（ApplyConfigValues）两条路都过这里。回归断言新增"【编译链路】只走 ApplyConfigValues
也能拿到模板库并定位"（MatchCount=1）。

经验教训：**插件的派生状态初始化永远不要只挂在 Initialize 上**——宿主编译运行实例的
统一入口是 ApplyConfigValues，两者必须等价。

用户实测指出"不能绑定上游变量"。修正：

- ① 模板卡顶部新增 `LinkableValueEditor`（与预处理/图像采集同一控件）绑定 `Image` 端口 ——
  HImage 端口不可文本输入，控件呈现"需链接变量 + 绑定按钮"，在对话框里或流程画布上连上游是同一份链接数据；
- 参考图路径降级为"参考图（可选）"并注明**仅配置态使用**（画模板/调参看图用，运行期一律吃上游 Image 端口）
  —— 它是纯配置项，故意不可链接：做成可链接会让用户以为运行期有第二条图像数据路径。

第二个反馈："创建模板后看不到模板特征"。补上**带特征轮廓的模板预览**
（参照商用软件样式）：创建成功后裁出模板矩形区域（轴对齐包围盒 + 6px 边距），
把 `get_shape_model_contours`（level 1 = 最细层）的模型轮廓平移到裁剪坐标系，
在离屏窗口上叠画成绿色，显示在 ① 模板卡内 —— 模型记住了哪些边一眼可辨。
预览失败自动退回纯裁剪显示，不影响模板本身。

实现上踩平了三个坑（都写进了代码注释）：

1. **paint_xld / paint_region 的 Grayval 语义对本版本不适用**：颜色名报 #1401、
   逐通道灰度值静默不上色 —— 改走 buffer 离屏窗口 `disp + dump`（Blob AnnotationRenderer
   同款已验证路径），SetColor 由显示管线处理从没出过问题；
2. **离屏窗口的 part 必须显式 `set_part` 钉住**：不设时 part 会被撑到参考图全幅，
   裁剪图被缩在窗口左上角（内容只占一小块，其余全黑）；
3. **dump_window_image 回读后源对象要立刻释放**（引用计数语义，卡尺插件实测漏 160MB 的同一课）。

预览窗口按尺寸缓存复用（HALCON 反复 open/close 会 #9302 死锁），Dispose 时统一关闭。
