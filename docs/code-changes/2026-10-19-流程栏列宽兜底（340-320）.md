# 流程栏列宽兜底（340 / 最小 320）

日期：2026-10-19
范围：
- `VisionMaster/Shell.xaml`（左侧流程栏列宽）
- `UIThemeSmokeTest/ShellCopy.xaml`（结构副本同步，R44）
- `VisionMaster/Services/LayoutHelper.cs`（恢复布局后夹紧列宽）
- `UIThemeSmokeTest/Program.cs`（新增断言 ⑨）

## 现象

流程栏 v2 上线后，用户把左栏拖窄（`Layout.xml` 里实测 **DockWidth=230.07**），
组头右侧的「N 分支 · M 算子」把实例名挤到只剩两三个字，视觉上像"控件溢出/被裁"。

## 根因

1. `Shell.xaml` 的默认宽度是 `20*`：在 1280 默认窗口下（右侧只留工具箱 300）约 218px，
   在 1920 下约 360px，但用户拖过之后会以**绝对像素**存进 `Layout.xml`（230）。
2. **AvalonDock 恢复布局时用文件里的宽度，会完整覆盖 Shell.xaml 的默认值**——
   只改 XAML 对已有 `Layout.xml` 的用户等于没发生（与 R43"旧布局抵消改造"同族）。
3. v2 组头的固定部分（类型标签 + 统计 + 状态图标）约 200px，加上树内边距与滚动条约 234px；
   低于 320 时实例名只剩两三个字。

## 修法

### 1. 默认宽度：340 / 最小 320

`Shell.xaml`（以及结构副本 `UIThemeSmokeTest/ShellCopy.xaml`）：

```xml
<avalonDock:LayoutPanel Orientation="Vertical" DockWidth="340" DockMinWidth="320">
```

340 是设计基线宽度（`docs/UI设计基线/process-panel/README.md`）：组头默认名称
（如"并行分组_0"）能完整显示；320 是下限，再窄名称开始截断。固定宽度与右侧属性/图层列
同一口径（可预期），中央文档区继续吃剩余宽度。

### 2. 已保存布局的兜底：恢复后夹紧

`LayoutHelper.LoadFromString` 在 `EnsureCriticalPanelsVisible` 之后调用
`EnsureProcessColumnWidth(manager)`：

1. 按 `ContentId="Panel_ProcessView"` 找到流程栏的 `LayoutAnchorable`；
2. 沿 `Parent` 链找到它所在的 `LayoutPanel`；
3. `DockMinWidth = 320`（防止后续再拖到更窄）；
4. 若 `DockWidth` 是绝对像素且 `< 320` → 设为 `340`。

只动这一列，**不升结构版本、不丢用户其它面板的位置与高度**；星号宽度不处理
（交给 AvalonDock 按窗口分配）。失败只记一行日志，不影响启动。

`Reset()` 走 `LoadFromString`，出厂快照同样会被夹紧；若快照过期被拒，则回退 Shell.xaml 的 340。

### 3. 守门人

`UIThemeSmokeTest.RunPanelModeChecks` 新增第 ⑨ 条（变异反证）：
把 ShellCopy 的流程栏列改成 230 → 调 `EnsureProcessColumnWidth` → 必须回到 340、最小 320。
改坏夹紧逻辑或把常量改小，这条会红。

## 验证

- `dotnet build VisionMaster` → **0 错误**。
- `UIThemeSmokeTest` → 新增断言 PASS：`宽度=340（期望 340） 最小=320（期望 320）`；
  日志出现 `流程栏列宽过窄（230），已拉回 340`；其余仅既有 vendored GridView 红灯。
- 宽度预算（340，扣树内边距 16 与滚动条 17 后内容宽 307）：
  - 组头固定部分 ≈ 201（色条 3 + 间距 19 + 类型 67 + 间距 10 + 统计 70 + 状态 20 + 右边距 12），
    实例名可得 ≈ 106（"并行分组_0" 约 78）；
  - 分支固定部分 ≈ 106，名称可得 ≈ 201；
  - 算子行固定部分 ≈ 138，名称可得 ≈ 169；
  - 底部统计：两行文字 + 勾选框（约 90）不换行。

## 备注

- 用户本地已存在的 `Layout.xml` 不需要手工删：下次启动夹紧后，退出时会把 340 写回。
- 若用户把流程栏拖成**浮动窗口**，夹紧不生效（浮动窗口有自己的尺寸），这是预期行为。
- 本改动**不触发** `CurrentLayoutSchemaVersion` 递增：面板归属/停靠语义没变，
  只修一列宽度，不应顺手丢掉用户布局（R43 的触发条件是"面板归属/停靠语义变了"）。
