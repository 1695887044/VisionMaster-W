日期：2026-10-18
范围：`ScadaActionType` 追加 9 条运动动作 + 执行器 + 门禁 + 点动看门狗 + 动作行编辑区。
配套：`docs/code-changes/2026-10-18-SCADA轴面板（轴选择器+单轴视图）.md`（块 A）。

## 1. 为什么这样切

运动动作属于**写方向**，与"读方向"的轴面板是两件事：

| | 读（块 A） | 写（本批） |
| --- | --- | --- |
| 入口 | `IScadaAxisSource` 拉快照 | `ScadaActionType` 动作 + `MotionActionExecutor` |
| 语义 | 持续刷新 | 一次命令 |
| 权限 | 只读，无风险 | 会动机构，必须过门禁 + 点动看门狗 |

所以动作不塞进数据泵、也不做成"图元上的按钮"：按钮点击 → 事件钩子 → 动作表 → 执行器，
这条链与「写变量」「启停流程」完全一致，权限与审计自动继承。

### 2.2 执行器

`VisionMaster/Services/Motion/MotionActionExecutor.cs`（新，约 620 行）：

- 取轴：Id 优先；**有 Id 就只认 Id**（不按名字兜底，防"删旧建新同名"错靶）；只有 Id 为空的旧数据才按名兜底，并当场回填 Id 自愈。
- 门禁：一律问 `MotionCommandGate`；两处刻意例外（清报警允许 Alarm 态、点动结束不过门禁）都在方法注释里写明理由。
- 相对定位的软限位判据是**当前位置 + 增量**投影成绝对终点，不是拿增量本身判。
- 点动看门狗：200ms 扫 `ConcurrentDictionary<Guid, JogLease>`，超过 `MotionJogGuard.PulseTimeoutMs × 2` 未收到「点动结束」就直接下发停止并记 Warn。
- **点动结束只在卡真收下停止后才清租约**——先清后发的话，停止被拒（队列满/参数非法）时看门狗与 `Dispose` 都不会再碰这根轴，而它还在动。
- `Dispose` 把仍在点动的轴补发停止。

## 3. 门禁口径（逐条）

| 动作 | 门禁 | 理由 |
| --- | --- | --- |
| 使能 / 失能 | `CheckDevice` | 未连接/报警/安全停机都不许动 |
| 绝对 / 相对定位 | `CheckMove` | 未连接 → 目标非法 → 软限位 → 未使能 → 未回零 → 忙 |
| 回零 | `CheckHome` | 只挡未连接/未选轴/忙（回零本身就是为了解决"未回零"） |
| 停止 | `CheckDevice` | 与调试面板一致；卡离线时由 `MotionDeviceBase` 的门禁再兜一层 |
| 清报警 | **绕开 `CheckDevice`** | `CheckDevice` 要求 Online，而 Alarm 态正是最需要清报警的时刻 |
| 点动开始 | `CheckJog` | 含"该卡未上报点动能力"；忙时静默 |
| 点动结束 | **不过门禁** | 停是安全动作，门禁里那条"未连接"恰是最该把停止发下去的时候 |

**已知分叉（未改，记账）**：流程侧 `MotionEnablePlugin` 允许报警态使能，动作表用 `CheckDevice` 会拒绝。两处目前口径不同，需要产品裁定后统一。

## 4. 验证

- `dotnet build VisionMaster.sln`：**0 error**。
- `dotnet run --project ScadaChecks --no-build`：**通过 1878 / 失败 0**。

AX7（运动执行器）9 条：
1. 定位按 Id 下发成功（`LastCommand.Kind == MoveAbsolute`）
2. 未使能被拦、不产生下发
3. 超软限位被拦
4. 相对定位按"当前 + 增量"判限位
5. 停用轴被拒并说明去哪儿启用
6. 未选轴给可操作原因
7. 点动遇忙静默（`message` 空串）
8. **反向**：Id 失效时拒绝执行、不按名兜底到另一根轴
9. （配套）`SupportsJog` 未上报时走另一档拒绝

## 5. 未决

1. **`MotionStop` 在卡离线时会被 `CheckDevice` 拒绝**——真机"卡掉线但轴还在走"时停不下。是否改成无条件尝试，需产品裁定。
2. **`MotionClearAlarm` 粒度**：执行器按单轴下发，但 `ZMotionCard` 的实现是遍历所有启用轴逐个清 → 界面上"清 X 轴报警"实际清了整张卡。
3. **`TargetMm` 一个字段承载目标/增量/点动方向**：从"绝对定位 500"切成"点动开始"时方向会静默变成正向；`MotionMoveRelative` 填 0 会下发 0 增量。建议类型切换时清掉不适用字段。
4. **`ScadaChecks` 里 20+ 处 `new ScadaActionDispatcher(...)` 都没注入执行器**，所以"分发器 → 执行器"整链没有端到端断言（执行器本身有 AX7 直测）。
5. **使能口径与流程侧分叉**（见 §3）。
6. **真机未验证**：点动看门狗、回零超时、Virtual 卡上的九条路径。
