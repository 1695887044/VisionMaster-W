# 开发记录：流程画布拖拽改序 + 撤销栈（M2-1 段3）

- 日期：2026-09-16
- 类型：功能实现（画布 M2-1 段3）
- 触发场景：段2 把画布升级成「分层 + 泳道 + 增量重建」后，用户在画布上拖动节点只能改坐标，不能改执行顺序；连线和断线也没有撤销能力，误操作难以挽回。段3 补齐「拖拽即改序 / 跨分支移分支」与「Ctrl+Z / Ctrl+Y 撤销重做」两条主线。

## 一、需求与决策

### 1. 拖拽改序 + 跨分支移分支

| 项 | 实现 | 关键决策 |
|---|---|---|
| 拖拽改序触发 | 自动按几何位置判（抬起时按中心 Y 比对） | 不弹"是否改序"对话框，零打断；改序与改坐标是同一个拖拽动作的两种结果 |
| 改序语义 | `ObservableCollection.Move(from, to)` | 触发 `CollectionChanged` → `FlowModel.Version++` → 运行前版本检查自动重编译 |
| 跨分支范围 | 仅同层跨分支（同一容器的 If/Else 间或同层 For 间） | 不允许跨层级——跨层级会破坏 `FlowTopology` 的祖先链语义 |
| 多选拖动 | 只对"主导节点"（被拖列表第一个 Step 节点）判定改序/移分支 | 其余节点跟随 Nodify 自动保持相对位置 |
| 几何规则 | 项目主列纵向流：Y 方向重排（中心 Y 比对）、X 方向跨分支（中心 X 落在哪条泳道） | 不依赖 `StepModel.SortId`——SortId 全项目只有 `FlowLayoutStore.AutoLayout` 读，编译器不认 |
| 插入指示线 | 水平虚线 + 端点三角 + 泳道边框高亮 | 不写 `DropIndicatorY` 字段到 `FlowLayoutStore`，纯展示 |
| 改序后坐标 | 拖拽过程只写 `FlowLayoutStore`（按 StepID 全局寻址），不触发 `RebuildInPlace`；抬起时若提交 `Move`/`Remove+Insert` 才触发 `CollectionChanged` → 重画 | 拖拽过程重建会导致视口抖动 |

### 2. 撤销栈架构（B 方案）

撤销栈承载方式二选一：
- **A 方案**：引入全局 `IUndoService`，画布、流程栏、参数面板都通过它入栈
- **B 方案**：`FlowCanvasViewModel` 内部维护 `_undoStack + _redoStack`

决策：**B 方案**。理由：
1. 段3 的撤销范围只在画布（改序、移分支、连线、断线），不涉及流程栏/参数面板的属性编辑
2. 全局 `IUndoService` 需要解决"哪个面板发起的、哪个面板能 Undo"的路由问题，超出段3 范围
3. 画布内撤销栈实现简单，零基础设施改动，可后续按需升级到 A 方案

### 3. IUndoCommand 接口

```csharp
internal interface IUndoCommand
{
    void Undo();
    void Redo();
}
```

**关键决策**：`IUndoCommand` 没有 `Execute` 方法——压栈时操作已执行。这与 `ICommand` 的"先压栈再 Execute"模式相反：
- 调用方在 `OnCompleteConnection` / `OnItemsDragCompleted` 等位置已经执行了 `SetLink` / `Move`，再调 `PushUndo(cmd)`
- `cmd.Redo()` 只在 Undo 后用户按 Ctrl+Y 时调用，重复执行同一操作（`SetLink` 重复写同值是幂等的）
- 例外：`OnItemsDragCompleted` 中 `cmd.Redo()` 必须显式调用一次——因为拖拽抬起时 Steps 集合还没动，需要 `cmd.Redo()` 让 `Move` 真正执行

### 4. 单栈双向 + 新操作清空 redo

- `_undoStack` 和 `_redoStack` 两个 `Stack<IUndoCommand>`
- 新操作入 `_undoStack` 时清空 `_redoStack`（标准撤销模型）
- 栈深上限 50：超过后丢最早项（FIFO 淘汰），不报错不阻塞
- **切流程清栈**：避免引用旧图纸的 `StepModel` 阻塞 GC
- **同流程切层不清栈**：栈里 `StepModel` 引用仍属于同一图纸，无需清理
- **Detach 清栈**：画布卸载时清栈，配合切流程清栈双重保险

### 5. 段3 不覆盖范围

- **不覆盖坐标**：拖拽只改 X/Y 不会入栈——坐标变更由 `FlowLayoutStore` 持久化，不属于"图纸结构变更"范畴
- **不快照图纸**：所有 `IUndoCommand` 都是"逆操作"模式（记录 from/to 索引或 oldLink），不是"快照+回滚"模式——节省内存，但要求逆操作必须可逆（`Move` 互逆、`Remove+Insert` 互逆、`SetLink`/`RemoveLink` 互逆）

**Undo/Redo 显式 RebuildInPlace 修复**：

```csharp
private void Undo()
{
    if (_undoStack.Count == 0) return;
    var cmd = _undoStack.Pop();
    _suppressUndoRedo = true;
    try
    {
        cmd.Undo();
        // 设计约束 3：画布只订阅 Steps 集合的增删，不订阅 StepModel 属性变更。
        // 连线/断线类 Undo 只改 LinkedSources（属性变更），不触发 OnFlowStepsChanged →
        // 画布的 Connections 集合不会自动重建。这里显式调一次 RebuildInPlace，
        // 让 BuildConnections 基于 LinkedSources 重新生成 Connections。
        // ReorderCommand/MoveBranchCommand 已通过 Move/Remove+Insert 触发过一次重建，
        // 这里再调一次是冗余但幂等的——RebuildCore 本身可重入安全，二次重建结果与首次一致。
        RebuildInPlace();
    }
    finally { _suppressUndoRedo = false; }
    _redoStack.Push(cmd);
    RaiseUndoRedoCanExecuteChanged();
}
```

`Redo()` 同理。这个修复解决了"Undo 建线后 `Connections` 集合不刷新"的 2 项断言失败。

### 修复过程

段3 实施期间出现的 2 项断言失败及修复：

1. **「Undo 建线后连线清空」失败**：`cv.Connections.Count` 仍为 1，应当为 0；但 `q.LinkedSources` 已移除 `In`
   - 根因：`FlowCanvasViewModel` 设计约束 3「只订阅 Steps 集合的增删，不订阅 StepModel 属性变更」——`Undo` 通过 `SetLink`/`RemoveLink` 修改 `LinkedSources` 时，`PropertyChanged` 触发 `FlowModel.Version++`，但画布的 `Connections` 集合不会自动重建（`BuildConnections` 只在 `Render` 时调用）
   - 修复：在 `Undo()` 和 `Redo()` 方法中，`cmd.Undo()`/`cmd.Redo()` 执行后显式调用 `RebuildInPlace()`，让 `BuildConnections` 重新基于 `LinkedSources` 重建 `Connections` 集合

2. **「换线后 D2 连上、Q 断开」失败**：换线后 `q.LinkedSources` 状态检查失败
   - 根因：测试规格与代码语义不一致。`CreateConnection` 的语义是「一个**输入**端口只允许一条连线」（`RemoveExistingConnection(input)`），**输出**端口可喂多个输入——这是机器视觉流程图的常见设计。测试期望「Q 断开」不符合此语义
   - 修复（与用户确认后）：修订测试断言为「新增 P→D2 后 D2 连上、Q 仍连着 P」，验证 `ConnectCommand` 的 Undo 在 `oldLink == null` 时只 `RemoveLink` 不影响其他线

## 四、已知边界

1. **DropIndicator 视觉未做视口缩放/平移转换**：只在视口原点 (0,0)、Scale=1 时与画布对齐。非段3 验收项，留待 M2-2 真实拖拽联调时一并处理
2. **多选拖动几何未单测覆盖**：单测无 Nodify 实际拖拽事件，多选拖动场景留待 M2-2 联调
3. **撤销栈不覆盖坐标**：拖拽只改 X/Y 不会入栈——坐标变更由 `FlowLayoutStore` 持久化，不属于"图纸结构变更"范畴
4. **撤销栈不快照图纸**：所有 `IUndoCommand` 都是"逆操作"模式（记录 from/to 索引或 `oldLink`），不是"快照+回滚"模式——节省内存，但要求逆操作必须可逆
5. **跨分支范围仅同层**：同一容器内的 If/Else 之间或同层 For 之间，不允许跨层级——跨层级会破坏 `FlowTopology` 的祖先链语义
6. **撤销栈容量 50**：超过后丢最早项（FIFO 淘汰），不报错不阻塞
7. **切流程清栈**：避免引用旧图纸的 `StepModel` 阻塞 GC
8. **同流程切层不清栈**：栈里 `StepModel` 引用仍属于同一图纸，无需清理
9. **输出端口可喂多个输入**：`CreateConnection` 只对 input 端口做 `RemoveExistingConnection`（保证输入端口单一消费者），output 端口可连多个 input——机器视觉流程图的常见设计（一个算子的输出可喂给下游多个算子）
10. **`cmd.Redo()` 在 `OnItemsDragCompleted` 必须显式调用一次**：因为拖拽抬起时 Steps 集合还没动，需要 `cmd.Redo()` 让 `Move` 真正执行触发 `CollectionChanged` → `Version++` → `RebuildInPlace`；而 `OnCompleteConnection`/`OnDisconnectConnector` 不需要先 `Redo`（操作已经发生，`SetLink`/`RemoveLink` 的 Redo 是幂等的）
