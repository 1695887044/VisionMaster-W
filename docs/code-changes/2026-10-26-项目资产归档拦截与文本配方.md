# 项目资产：归档运行期拦截 / 配方生命周期 / 文本配方接 AssetId

## 当前状态

按上一轮列出的缺口，做完了前三条：

1. **归档资产在运行期被拒绝解析**（之前"已归档"只是界面标签，产线照用）；
2. **配方生命周期补齐**（冻结/解冻可用、有版本记录、有快照、能进逐字段差异）；
3. **文本配方接 AssetId**（`ColorCheck` 的配方表可以作为方案资产管理，不再只是步骤里的字符串）。

另外修了一个 gate 基础设施缺陷：两个会话并发跑 `run_gates.ps1` 会抢同名 raw 日志。

## 已做

### 1. 归档 = 退出生产

- `SolutionProjectAssetResolver.TryResolve` 开头查 `AssetLifecycle`：命中"已归档"直接返回 false。
- 错误写清资产名与出路：`资产「X」已归档，不能用于运行；请在项目资产页恢复后再跑`。
- 覆盖面：所有插件都经 `ProjectAssetPathResolver → context.Assets → SolutionProjectAssetResolver`，
  一处拦截即全链路生效（7 个插件调用点已核对）。
- 带旧路径也不放行：`TryResolve(context, assetId, fallbackPath, ...)` 在 AssetId 解析失败时直接返回 false，
  不会悄悄退回旧路径继续跑。
- 恢复后重新可用（归档可逆）。

### 2. 配方生命周期

- `RecipeDefinition.IsFrozen`（与标定 `IsLocked`、文件资产 `IsFrozen` 同语义）。
- `SolutionAssetWriter.FindFreezable` 增加 `RecipeFreezeAdapter`——**之前配方点冻结会报"找不到资产"**。
- `RecipeDefinition.CreateAssetSnapshot()`：配方快照的唯一出处（宿主写版本历史与 diff 都读它）。
  含 Name/Code/Scope/ContentVersion/IsFrozen/TextContent/Entries/Points。
- `RecipeService.Apply` 成功后写一条版本记录（动作「应用」）：
  这是配方内容真正进产线的时刻，也是唯一值得记的里程碑；之前配方版本历史永远是空的。
- 目录读取补 `IsFrozen`（配方徽标之前永远不亮）。

### 3. 文本配方

- `RecipeDefinition.TextContent`：**文本配方形态**。不新开资产类型——参数配方与文本配方
  在"冻结/归档/默认/版本/审计"上的逻辑完全一样，另开一类只会让每个动作多一条分支。
- `ProjectAssetRef.Content` + `ContentKind`（`text`/`json`）：
  配方内容在方案里，插件要读原文；`ContentKind` 必须显式给，否则参数配方会被当成空文本配方，
  报出"配方表里没有这个芯数"这种完全指错方向的错。
- `ProjectAssetPathResolver.TryResolveContent(...)`：读内联内容，可按形态校验。
- `ProjectAssetImporter` 支持 `kind="recipe"`：读 `.txt/.csv/.tbl` → 建 `RecipeDefinition{TextContent}`，
  **不拷文件**（否则同一份配方有两个真相）。同内容重复导入被拒。
- `ProjectAssetExporter` 导出文本配方：`files/recipe/{id}.txt` + manifest 行。
  之前"配方不参与打包"，会把配方悄悄漏掉。
- 资产页：配方页签可「导入资产」（文本配方）；目录预览显示"文本配方 · N 行"。
- `ColorCheckPlugin`：`RecipeAssetId`（`IAssetIdConfig`，Kind=`recipe`），运行期解析文本配方覆盖手填表；
  配置壳下拉只列**文本配方**（参数配方混进去只会选中后报"没有内联内容"）。

### 4. 并发 gate 抢日志（顺带修）

`run_gates.ps1` 的 raw 输出文件名加上本进程 PID。
两个会话同一天并发跑 gate 时会打开同一个 `raw-<host>.out` 并互相截断，
症状是假红（`NO OUTPUT` / `exit=-1`）或更坏的"读到对方那轮的汇总行"。
