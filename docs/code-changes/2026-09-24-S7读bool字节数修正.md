# 2026-09-24 S7 读 bool 字节数修正（Marshal.SizeOf → HslHelper.MinByteCount）

## 一、需求与决策

### 1.1 问题（A1，严重）

`SiemensS7Connection.Read<T>` 用 `Marshal.SizeOf<T>()` 算设备读长度：

```csharp
// 旧代码
// S7 按字节粒度读取：bool/byte=1，short/ushort=2，int/uint/float=4，long/ulong/double=8
var result = _device.Read(address, (ushort)System.Runtime.InteropServices.Marshal.SizeOf<T>());
```

注释自称「bool = 1 字节」，但 **`Marshal.SizeOf<bool>()` 实际返回 4**（.NET 把 `bool` 按 Win32 `BOOL` 封送，4 字节），不是 1。**意图与实现矛盾**。

后果：

| 后果 | 说明 |
| --- | --- |
| 多读相邻字节 | `Read<bool>("M10.0")` 向设备要 4 个字节，白读 3 个相邻字节 |
| 靠近区末越界读失败 | 位地址在区末（如最后一个字节）时请求超出区范围 → 读失败抛异常 |
| 值常常"碰巧对" | `HslHelper.ConvertTo<bool>` 只取首字节 `be[0]`，所以数值看起来正常 → **藏得住的错** |

### 1.2 影响范围（已用 Grep 确认，修正局部化）

- 全项目 `Marshal.SizeOf` 用来算**设备读长度**的只有这一处。
- Modbus 两个连接（TCP/RTU）用的是 `HslHelper.RegisterCount<T>()`（寄存器粒度），**不受影响**。
- S7 **批量轮询**走 `S7Address.TryCreatePollAddress` 的位切片路径（`SpanUnits`/`IsBitAccess`/`BitOffset`），**不受影响**。
- 只有 **S7 单点直读**（`ReadVariable<bool>` / 单读回退路径）踩到。

### 1.3 决策：换用 `HslHelper.MinByteCount`

`MinByteCount(Type)` 是项目自有字节表，且**轮询批量解码（`PollBatchPlanner`）与 `HslHelper.ConvertTo` 用的是同一张表**。单点读改用它之后，单点读与批量读**不可能再对不上**。

未知类型（`decimal`/`DateTime`/自定义 struct）返回 **0**，此时回退 `Marshal.SizeOf<T>()`，保持旧行为不变（读回字节但解不出值，由 `ConvertTo` 返回 default）——**不引入新的抛异常路径**。

### 1.4 备选方案与不采纳的理由

| 方案 | 不采纳理由 |
| --- | --- |
| 改 `MinByteCount` 让 bool 返回 4 | 表是对的，批量解码依赖它；改表会连带改坏轮询路径 |
| 在 `Read<T>` 里对 bool 特判 `byteCount = 1` | 打补丁，只修 bool；short/int 等类型仍与字节表脱钩 |
| 去掉回退、未知类型直接抛 | 会把「读得到但解不出」升级成「读不了」，属行为倒退 |

### 2.1 修正后代码

```csharp
public T Read<T>(string address) where T : struct
{
    if (!_isConnected) throw new InvalidOperationException("设备未连接");
    // S7 按字节粒度读取：bool/byte=1，short/ushort=2，int/uint/float=4，long/ulong/double=8。
    // ⚠ 不能用 Marshal.SizeOf<T>()：它对 bool 返回 4（Win32 BOOL 的尺寸），
    // 会让 bool 读请求从 1 字节变成 4 字节——多读相邻字节，靠近区末还会越界读失败。
    // 值本身常常"碰巧对"（ConvertTo<bool> 只取首字节），属藏得住的错。
    // MinByteCount 与读/写链路的字节表同源；未知类型（decimal/DateTime/自定义 struct）
    // 返回 0，此时回退 Marshal.SizeOf 保持旧行为（读回字节但解不出值，由 ConvertTo 返回 default）
    int byteCount = HslHelper.MinByteCount(typeof(T));
    if (byteCount == 0)
        byteCount = System.Runtime.InteropServices.Marshal.SizeOf<T>();

    var result = _device.Read(address, (ushort)byteCount);
    if (!result.IsSuccess) throw new InvalidOperationException(result.Message);
    return HslHelper.ConvertTo<T>(result.Content, ByteOrderFormat.ABCD);
}
```

### 2.2 断言（C11 组，全部离线可跑）

`HslHelper` 是 `internal` 类，CommChecks 够不着 → 走反射（`typeof(SiemensS7Connection).Assembly.GetType("VisionMaster.Communications.HslHelper")`）取 `MinByteCount`；取不到直接抛，不静默放过。

| 断言 | 内容 | 意图 |
| --- | --- | --- |
| C11-1 | `MinByteCount(bool) == 1` | **核心**：修复目标就是这个值 |
| C11-2 | 10 个定长类型整表核对（byte1/short2/int4/long8/float4/double8） | 任一值错 → 对应类型单点读多读/少读字节 |
| C11-3 | `MinByteCount(decimal) == 0` | 未知类型返回 0，`Read<T>` 靠它走回退 |
| C11-4 | 哨兵 `Marshal.SizeOf<bool>() == 4` | 证明旧写法确实多读 3 字节；哪天 .NET 改了封送尺寸会失败提醒复核 |
| C11-5 | `decimal` 字节表为 0 且 `Marshal.SizeOf<decimal>() > 0` | 证明「0 → 回退」不是死代码 |

## 四、已知边界

1. **`Read<decimal>` / `Read<DateTime>` 仍读回字节但解不出值**：`MinByteCount` 返回 0 → 回退 `Marshal.SizeOf` → 长度对，但 `ConvertTo<T>` 无对应分支，返回 `default`。属既有「读写行为不对称」问题（B5）范围，**本次不动**。
2. **未覆盖实机验证**：C11 断言的是「长度取值正确」，不是「S7 模拟器上 `Read<bool>` 真的只发 1 字节请求」。真机点验需模拟器在线，留待联调。
3. **`Marshal.SizeOf<bool>() == 4` 是平台相关事实**：C11-4 是哨兵，若未来 .NET 改动封送尺寸，该断言会失败——届时需复核 C11-1 的注释是否仍成立（属预期行为，非缺陷）。
