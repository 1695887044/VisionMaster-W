# 画布分支入口 / 刷新 / 落点防重叠 / 连线可读性（2026-10-23）

## 起因

用户提出五个问题（原文口径）：

1. 只能在流程栏右键添加分支，**画布没办法右键添加**；
2. 流程添加分支后**画布没有立刻刷新**，需要手动收缩再展开；
3. 打开数据线后**线交织在一起太乱，文字也不醒目**；
4. 拉一个新算子到画布，**落点是已有算子上时不自动排布**，会在页面上覆盖，
   产生"只有一个算子"的错觉；
5. 拖拽时候的文字（英文 `Copy to`）**能不能修改**。

## 现状核查（改前，逐条定位）

| # | 症状 | 根因 |
|---|---|---|
| 1 | 画布不能加分支 | 画布空白右键只有「粘贴」（`FlowCanvasView.xaml:1459`），节点/容器右键只有 编辑绑定/参数/复制/禁用/删除。分支动作（AddElseIf/AddElse/AddCase/AddParallelBranch）只挂在流程栏 `ProcessView.xaml:1479-1606`。**命令本身都有，画布没接线。** |
| 2 | 加完分支不刷新 | `FlowCanvasViewModel.AttachLists` 只订阅各层 `Steps` 集合，**没订阅容器 `Children`**；而"添加分支"改的正是 `group.Children.Add(...)`（`ProcessViewModel.cs:811`）。`FlowModel` 自己监听 `Children` 并递增 `Version`，但画布不读 `Version` → 通知链断了。折叠/展开会强制 `RebuildInPlace()`，于是"手动收一下就好了"。 |
| 3 | 数据线交织、文字不醒目 | ① 数据线一律"源右缘中点 → 目标左缘中点"直角走线，同列多层依赖必然重叠；② 连线标签只有 `Text="{Binding LinkLabel}"`，**没给 `TextBackground`/`Foreground`/`FontSize`**，吃 Nodify 主题默认值 → 灰白飘字压在点阵背景上。 |
| 4 | 落点重叠 | 落点只决定"插到哪一位"（`ResolveInsertTarget` → `owner.Insert`）；坐标交给 `AutoLayout`，而它**只补缺项、已有坐标一律不动**（`FlowLayoutStore.PlaceLeaf`）。布局推进是"上一项底缘 + 28"，下一项却用自己的旧 Y ——旧布局本来就按同一套间距排的，于是两个 Y 恰好相等，**严丝合缝盖住**。 |
| 5 | `Copy to` 文字 | gong-wpf-dragdrop 的**默认效果浮层**（`EffectCopyAdornerTemplate` 默认文案，DLL 内可读到 `Copy to`/`Move to`/`Link to`）。两个拖拽源都开了 `UseDefaultEffectDataTemplate="True"`。 |

## 改动

### 1. `Services\FlowBranchEditor.cs`（新增）

把四个结构动作抽成静态类，**流程栏与画布共用同一份实现**：

- `AddParallelBranch(ParallelStep?)` —— 上限 8、"分支 N"取未占用最小号；
- `AddElseIfBranch(ConditionStep?)` —— 插在兜底 Else 之前（Else 之后的编译器按"不可达分支"报错）；
- `AddElseBranch(ConditionStep?)` —— 已存在则拒绝，文案"该算子已经包含了 Else 分支！"；
- `AddCaseBranch(CaseStep?)` —— 插在默认分支之前，"Case N"取未占用号。

返回 `Result(Success, Message)`，**不碰 Notifier/弹窗**（反馈出口由调用方给，运行锁也由调用方先判）。
版本号纪律不变：Children 增删由 FlowModel 集合监听自动递增，这里不写 `Version++`。

抽出来的理由：两处各写一份判型/上限/自动命名/插入位置，必然漂移，且症状是"某个入口静默少一条分支"。

### 2. 画布订阅容器 `Children`（修 #2）

`AttachLists` 对每个容器补一行 `Watch(container.Children)`；`Watch` 参数类型从
`ObservableCollection<StepModel>` 放宽为 `INotifyCollectionChanged`。

**顺带修掉一个既有双订阅**：顶层 `Steps` 已由 `RebuildCore` 的 `_stepsChanged` 订阅，
`AttachLists` 又 `Watch` 一次（两个委托 Target+Method 相同但 `+=` 不去重）→
同一次结构变更触发**两遍全量重建**。`Watch` 现在跳过 `_attachedFlow.Steps`，
保留 `RebuildCore` 那一路（它有"切流程换图纸时整份重挂"的语义）。

### 3. 画布右键菜单补分支结构动作（修 #1）

- `CanvasNodeViewModel` 新增只读判据：`IsIfLikeNode`（If 类，含 While）、`IsCaseNode`、
  `IsParallelNode`、`HasBranchMenuItems`（前三者之一），与流程栏
  `IsIfNodeSelected`/`IsCaseNodeSelected`/`IsParallelNodeSelected` 逐条同口径；
- 新增四个 `DelegateCommand?` 注入槽，在 `GetOrCreateNode` 里注入闭包（与既有
  `OpenModuleParametersCommand` 同一模式——菜单 DataContext 是节点 VM，弹层够不到主 VM）；
- `FlowCanvasViewModel.OnAddBranch(node, kind)`：运行锁（`StructuralEdit`）→ `FlowBranchEditor` → `StatusHint` 回执 → `RebuildInPlace`；
- 算子卡片与容器框两个模板的右键菜单各加四项；分隔线由 `HasBranchMenuItems` 控可见性
  （While/For 三项全 Collapsed，不能让菜单以横线开头）。

**CaseStep 的 `IsIfLike` 是 false**（`ConditionStep.IsIfLike` 判名字里有没有 `"If"`，
CaseStep 的 `PluginTypeName` 是 `BuiltIn_Case`）→ Case 容器菜单只出 Case 项。
这条有反向断言钉住（见下）。

### 4. 落点防重叠（修 #4）

`DropToolAt` / `OnPaste` 在 `owner.Insert` 后：

1. `RebuildInPlace()` —— AutoLayout 给新步骤补坐标、容器算出真实框高（**不渲染一帧量不出新容器占了多高**）；
2. `MakeRoomForInserted(owner, insertIndex)` —— 若新节点底缘 + 行距 > 下一个兄弟的顶边，把**后续所有兄弟连同各自子树**整体下移该差值；
3. 有位移再 `RebuildInPlace()`。

三条边界（都有反向断言）：

- 插到末尾 → 后面没人要让位，直接返回（不许无条件顺移）；
- 已有空隙（用户手拖出来的大间距）→ `delta <= 0.01` 直接返回，**尊重手工布局**；
- 被折叠祖先藏起来的**展开容器** → 高度未知，返回 false 放弃腾位（拿假高度算 delta 要么让位不够、要么推开大空档）。

### 5. 连线可读性（修 #3）

`Colors.xaml` 新增四个令牌：

| 键 | 值 | 用途 |
|---|---|---|
| `FlowCanvasLinkOutlineBrush` | `#F7F8FA` | 交叉分离描边（= 画布底色，泳道淡蓝底上也自然） |
| `FlowCanvasLinkLabelBackgroundBrush` | `#F2FFFFFF` | 标签底框 |
| `FlowCanvasLinkLabelTextBrush` | `#1D4ED8` | 数据线标签字色 |
| `FlowCanvasOrderLinkLabelTextBrush` | `#64748B` | 顺序链标签字色（弱化） |

`ModuleLinkTemplate` 的 `StepConnection` 样式新增：

- `OutlineBrush` + `OutlineThickness="1.6"` —— Nodify `BaseConnection.OnRender` 会先用
  `new Pen(OutlineBrush, StrokeThickness + OutlineThickness * 2d)` 画同一几何作描边
  （已核对 Nodify 7.3.0 源码 `BaseConnection.cs:1002`）。所以 `OutlineThickness` 是**每侧加宽量**，
  1.6 表示两侧共 3.2px 宽的一圈画布底色 → 线条互相穿过处出现"断口"，一眼看出谁在上谁在下；
- `TextBackground`/`TextPadding="5,1"`/`TextCornerRadius="4"`/`FontSize="10.5"`/`FontWeight="SemiBold"`/`Foreground`
  —— Nodify 只在 `TextBackground` 非空时才画底框并让 padding/corner 生效；
- `IsOrderLink` 触发器里把标签弱化（灰字 + Normal 字重）：顺序链只是执行次序，不该抢数据线的注意力；
- `IsIllegal` 触发器里标签转红：非法线是要用户去修的错误提示，字色必须与线色同源。

### 6. 拖拽浮层文案（修 #5）

`ToolView.xaml:612`、`ProcessView.xaml:501` 的
`dd:DragDrop.UseDefaultEffectDataTemplate` 由 `True` 改为 `False`。

关掉的是库内置的"图标 + `Copy to` + 目标名"小条；拖拽反馈已由 `DragAdornerTemplate`
的 `DragGhostCard`（设计基线 v2 的卡片）承担，这条浮层纯属重复且是英文。

## 断言

新增 `FlowCanvasChecks\FlowBranchEditChecks.cs`（[YC] 组，23 条），覆盖：

- **YC1**：外部改 `Children` → 画布泳道即时 +1/−1（If 与并行分组都验）；
  **顶层结构变更只触发一次全量重建**（`Reset` 次数 = 1，钉住双订阅不回来）；
- **YC2**：画布四个分支命令的结构结果（上限拒绝 + 回执、Else 去重、ElseIf/Case 插在 Else 之前、
  自动命名不撞、类型靶不对静默空跑不抛、Case 容器 `IsIfLikeNode` 为 false）；
- **YC5**：运行中「添加分支」被拦（Children 不变 + 状态栏给运行锁文案，`GlobalEventBus` 真广播 + finally 复位）；
- **YC3**：落点插到 A/B 之间 → 新算子下标正确、与前后兄弟都不重叠、C 跟随 B 同距下移；
  三条反向（插末尾不动 / 大间距不动 / 容器内插入既有兄弟不动）、粘贴走同一条规则。

**变异反证**（三条都做了，均判红后还原）：

| 变异 | 结果 |
|---|---|
| 注释掉 `Watch(container.Children)` | YC1 判红：`泳道 2 → 2，分支 2 → 3`（正是用户报告的症状） |
| 让 `MakeRoomForInserted` 不腾位 | YC3 判红 3 条：`B.y 86.0 → 86.0 期望 ≥ 172.0`（正是"盖住"） |
| 恢复顶层双订阅 | YC1 判红：`重建轮数=2（期望 1）` |

**验证结果**：`FlowCanvasChecks` 3542 通过 / 0 失败（改动前基线 3501 通过）。
构建命令用隔离输出目录 `-p:OutDir=artifacts\build\debug\vmout\`，因为 `bin\` 被用户正在运行的
VisionMaster 实例（PID 39132）独占——**没有结束用户的进程**。

> 期间观察到的既有偶发：同一 exe 连续跑三次，失败项在 `MotionChecks`（安全停机）与
> `ResultsThumbnail`（缩略图为 null）之间漂移，每次都是 2 条。用"临时禁用 [YC] 组"做对照
> 复跑同样出现 2 条失败 → 证明与本次改动无关（环境相关，非本批引入）。

## 已知偏差

1. **撤销一次拖入/粘贴后，被顺移的兄弟不会回原位**：腾位直接改坐标库，
   `AddStepCommand` 只做 `_owner.Remove(_step)`。Ctrl+Z 后原位留一个空档（不是错误，只是不完美）。
   代价是"撤销多退一份坐标快照"，本批未做。
2. **连线描边在卡片上也会描一圈**：`OutlineBrush` 用的是画布底色，线压在白卡/浅蓝头带上时会有一圈
   浅灰。这是"交叉断口"不可避免的副作用（只有"仅交叉处断开"需要遮罩渲染，成本不值）。
3. **`OutlineThickness=1.6` 未经真机出图确认**：按 Nodify 源码算术是每侧 1.6px（共 3.2px），
   静态看不出效果。若真机觉得断口不够或太粗，只改这一个数值即可（`FlowCanvasView.xaml` 一处）。
