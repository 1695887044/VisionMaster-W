## 一、当前状态

自绘层（`FlowCanvasSurface`）已经**按当前 XAML 模板逐项重写**，不再是"能看懂结构"的草图：
节点卡片、容器框、分支泳道、连线四套图元的尺寸/字号/颜色/徽标/层级全部对齐

## 四之三、数据线"只显示选中算子"（2026-10-25 新增，用户需求）

**行为**：工具条「数据线」**默认不勾**时不再"全部隐藏"，而是**只显示与当前选中算子直接相连的数据线**；
勾上 = 全部显示。非法线（红虚线）永远显示，不受作用域影响。

实现要点：

| 位置 | 改动 |
| --- | --- |
| `CanvasLinkViewModel` | 新增 `IsScopeHidden`（只存结果，判据在主 VM） |
| `FlowCanvasViewModel` | 新增 `_selectedStepForDataLinks` + `RefreshDataLinkScope()`；选中变化（画布点选、流程栏/属性栏外部选择）都刷新；`DataLinkScopeChanged` 事件供自绘层重拍快照 |
| `BuildLinks` | **数据线不再因为开关关闭就不建**——不建就没有线可显（第一版踩了这个坑：勾掉开关后选中节点一片空白）。大流程降级阈值改为独立生效（`aggregated.Count > DataLinkReduceThreshold`），不再依赖开关 |
| `ModuleLinkTemplate` | `DataTrigger IsScopeHidden → Visibility=Collapsed` |
| `FlowCanvasSurface` | 快照期跳过 `IsScopeHidden` 的线；订阅 `DataLinkScopeChanged` 做防抖重拍 |

性能取舍：选择变化只改标记（O(线数)），**不重建集合**——353 步流程重建一遍 Links 是 500ms 量级，
点一下卡半秒不可接受。

| 项 | 状态 | 实现 |

| 框选多选 | 已实现 | 空白处左键拖 → 画选框（屏幕坐标，画在变换之前）→ 落定按图坐标矩形选相交节点；Shift 追加；单击空白清空。泳道不参与 |

**为什么拖动改序要停**：直接把 `Location` 写回模型 → 画布位置是布局器算的，写回后没有重排，

而不是把坐标写回模型再指望它重排。这是独立一轮的事。

**真机验证**：自绘画布默认开启 ✓；框选 ✓（拖框后 2/3/4 号同时选中）；
容器折叠 ✓、工具箱拖入 ✓（2026-10-25 用户确认"没问题"）。

**顺带修**：数据线作用域从"只认最后点中的节点"改成"认全部选中节点"——
框选后多个节点同时选中，只显示其中一个的线会让另外几个看着像没绑定。

## 四之八、拖动改序重做 + 自绘小地图（2026-10-25 晚）

### 拖动改序（第二次实现，换机制）

| | 旧（已废） | 新 |
| --- | --- | --- |
| 拖动期 | 直接写 `node.Location` | **只喂渲染偏移**（`SetDragOffsets`），模型坐标不动 |
| 落定 | `ItemsDragCompletedCommand` | `CompleteSurfaceNodeDrag(dragged, 视觉中心)` |
| 收尾 | 只 `RebuildInPlace` | **整表重排**：`Layout.Nodes.Clear()` → `AutoLayout` → 恢复折叠标记 → `RebuildInPlace` |

为什么必须整表重排：改序之后同组后续节点的位置全变了，只重排被拖的那个会在图里留空洞
（实测：3 号拖走后画布出现 1、2、4、5 的跳号）。`AutoLayout` 只补缺失项，所以要先清空坐标表。

**代价（已知取舍）**：整表重排会清掉该流程里**所有手工摆放的位置**。自绘层不做自由摆放，可接受；
折叠状态已单独保留（`NodeLayout.Collapsed` 重排后回填）。

### 小地图（自绘）

Nodify 的 `Minimap` 在折叠的编辑器上不生成 item，改为自绘层自己画：

- 右下角 180×118、圆角 6、白底 + 描边；内容等比缩放居中；
- 步骤画实心小块、容器画空心框、泳道跳过；
- 当前视口画半透明蓝框；
- **点击 + 按住拖动**都能移动视口（`TryMiniMapJump`，拖动期每帧调用）；
- 跟随工具条「小地图」开关（`SurfacePreview.ShowMiniMap`）；Nodify 的宿主 Border 在自绘模式下收起
  （`MiniMapHost.Visibility = Collapsed`，切回时 `ClearValue` 让 Style 触发器重新接管）。

### 撤销/重做也要重排（同一轮补的）

自绘层的坐标是**从顺序推出来的**，顺序一变就得重排——撤销/重做同样会改顺序。
原来 `Undo()`/`Redo()` 只 `RebuildInPlace()`，结果是"顺序回去了、位置还停在原处"
（图上看着还是旧顺序）。

修法：把整表重排抽成 `ReflowLayout()`，`Undo()`/`Redo()` 里按开关调用
`if (AutoReflowOnStructureChange) ReflowLayout();`。

**为什么用显式开关而不是"看有没有坐标表"这类猜法**：Nodify 路径是自由摆放，坐标是用户
拖出来的，撤销时绝不能跟着顺序重排（会把手摆的布局清掉）。开关由视图在切渲染层时置位
（`FlowCanvasView.SyncSurface` 两个分支各一行），默认 false。

### 断言（进常规 gate）

`FlowCanvasChecks` 新增 `[M3] 自绘层拖拽改序（整表重排）` 15 条，钉住：

1. 改序生效（`Steps` 顺序 / `Version` +1 / 撤销栈 = 1）；
2. **序号连续 1..4**（历史缺陷是 1、2、4、5 的跳号）；
3. **整表重排**：每个节点坐标与"按新顺序重新 `AutoLayout`"逐项相等（±0.5）；
4. 折叠标记在重排后仍在；
5. 拖动偏移不漏进模型（`node.Location` == 坐标表）；
6. 撤销后顺序与坐标都回去（`A.y=0 < B.y=86`）；
7. **反向**：`AutoReflow=false` 时撤销不动坐标（Nodify 自由摆放不被误伤）。

## 五、踩过的坑

- **连线横穿卡片**：数据线的目标锚点在**左缘**，源在右侧时"先竖后横"的走法会让横段落在目标卡中心高度上，
  卡片看起来像穿在线上的珠子。修法：检测到横段会压到卡片就**从卡片上方绕**（出一段→抬到卡顶→横过去→落回→进卡）。
  注意避让判断里**只有源卡片可以跳过**——目标卡片正是要绕的那张（第一版把目标也跳过了，等于没修）。
- **连线标签被卡片切掉半截**：标签原先跟连线一起画，而连线在卡片**下面**。修法：标签单独一趟画在最上层，
  并按"先避卡片、再避已放标签、最后左右挪"的顺序找位置；容器**组头**也算禁区（否则会盖住容器标题）。
- **连线压容器组头**：连线层级在"框/泳道之上、卡片之下"，横穿容器时会把标题/条件胶囊压住。
  修法：连线画完后再把组头**内容**重画一遍（不重画底带，否则穿过组头的顺序链会被切断）。
- **容器没参与走线避让 → 左边凸出一截断头线**：目标锚点在容器左缘时，横段从组头横穿过去，
  只剩末端那 60px 入口段露在容器左边，看起来像"凭空凸出来的一条线"。
  修法：把**容器框**也放进障碍表。判定细节：目标是容器内部的步骤时**不能**绕整框（否则线绕着整个容器跑），
  只有当目标**就是**那个容器（锚点落在它自己的左右缘）时才绕。
- **小地图在自绘模式下失效**：它的 `ItemsSource` 本来就绑 `Nodes`（不依赖编辑器），
  但 `ViewportLocation`/`ViewportSize` 是从 `NodifyEditor` 取的；编辑器一收起就不再更新，
  表现为一个卡住的蓝方块。**最终结论：Nodify 的 `Minimap` 在自绘模式下不生成 item**——
  断开 TwoWay 绑定后视口方块能跟着自绘层动了，但节点点阵始终不渲染。
  按用户决定走 **A 方案：自绘模式下把「小地图」开关置灰收起**，不留假控件。
- **拖动不跟手**：原来 `MouseMove` 每帧改 `Pan` → `InvalidateVisual()` → 整块重绘
  （几十个节点 + 全部文字），鼠标一快就掉帧。修法：拖动期间只改 `RenderTransform`（WPF 直接合成、不触发
  `OnRender`），松手才把位移落到 `Pan` 上一次性重绘。
- **改成 RenderTransform 之后拖动会抖动**（下一轮用户反馈）：因为 `e.GetPosition(SurfacePreview)` 取的是
  **被变换元素自身**的坐标——位移一变、参考系跟着变、鼠标坐标又变，形成正反馈来回震。
  修法：锚点与移动都改取 `e.GetPosition(this)`（UserControl，不受 `RenderTransform` 影响）。
  **凡是在"会自变换的元素上"算拖动增量，都必须换到不变的祖先坐标系。**
- **拖动时画布露白**：底色 + 点阵原本画在自绘层内部，`RenderTransform` 把整块元素一起位移，
  让出来的那块没人画，露出窗口白底。修法：把底色/点阵挪到自绘层**背后的独立 `Border`**
  （`SurfaceBackdrop`），自绘层只画内容；探针出图也改成用同款 Border 做宿主。
  **教训：会整体位移的层不许自己承担背景。**
- **拖窗体明显滞后**：内容没变时 WPF 仍会重走 `OnRender`。修法：给自绘层挂
  `CacheMode = new BitmapCache()`，窗口移动/滚动这类"只是重新呈现"的场景直接复用缓存位图。
- **拖动时"不加载下面的算子"**：上一版为了不重绘，拖动期间只做 `RenderTransform` 位图位移——
  新拖进视口的那部分**根本没画过**，所以是空的。修法：拖动直接改 `Pan`、走真实重绘。
  代价是拖动要重画（掉帧风险回到台面上），但正确性优先——"拖过去是空白"比"稍卡"更糟。
- **单击变多选**：自绘层的点选只把命中节点置 `IsSelected = true`，**没清其它节点**，越点越多。
  修法：先清其它节点再置当前（Shift 才追加）。
- **平移边界夹取两次都没落地（未交付）**：目标行为是"内容不许被拖出视口、只剩空画布"。
  两版实现（视图层算 / 自绘层内部算）在真机上都表现为**不生效**：
  日志实测 `origin=(-43,5560) delta=(115,608)`（合成值应是 `(72,6168)`）→ 落定 `pan=(-954,6168)`，
  说明读到的 `ContentBounds`/`Zoom`/`RenderSize` 与落定时刻不是同一份状态；改成内部算仍未生效。
  **当前状态：已回滚，无边界限制**（能拖出空画布，但不会再甩飞）。要做的下一步：
  把夹取放到 `OnRender` 用的同一份快照上、并在 `RebuildSnapshot` 里同步重算，
  或者干脆在拖动结束时不提交 `Pan` 而是提交"夹取后的视口矩形"。
- **标签仍然压住备注行**：弧长中点会落在两张卡之间的窄缝里，那里正好是备注文字。
  修法：沿折线采样 16 个点，取"离步骤卡片最远"的那个点作标签锚点；容器不参与这个距离计算
  （标签落在容器内部的泳道上完全正常，把容器算进去会把标签赶出框外）。

- **`ViewportLocation` 继承与自动适配会打架**：`SyncSurface(zoomToFit: true)` 会把刚继承的视口
  覆盖成 fit 值。继承成功必须传 `zoomToFit: false`。
- **长链流程 fit 到全图 = 一片空白**：内容 `800×29406` 塞进 `614×349` → zoom 0.0102，节点变 0.6px 点。
  适配必须有下限（现 0.25），撞下限时改左上角对齐。
- **贝塞尔 ≠ StepConnection**：曲线会把"两端都在屏外、只是跨过视口"的线拉成横穿全屏的弧，
  真机一眼就看出不是同一个东西。必须实现直角台阶。
- **静态字段初始化顺序**：`SelectedGlowPen` 若声明在 `SelectedGlow` 之前，Palette 初始化时拿到 null。
  新增令牌一律"先颜色、后画笔"。
- **渐变头带不能像纯色那样分两段画**（圆角矩形 + 补角矩形），两段各自映射渐变会出现接缝；
  要用"只圆上两角"的裁剪几何一次画完。
- **`Fade()` 只处理 SolidColorBrush**：渐变画刷直接原样返回，禁用态的容器头带要退成同色系纯色。
- **并发构建会互相锁**：另一进程在改 `RecipeManagerView.xaml`（XML 一度是坏的）并占着 `Modules\*.dll`，
  `dotnet build` 报 MSB3027/MSB3073。用 `--no-dependencies` 只重建目标工程可以绕开插件拷贝。
- **AvalonDock 的文档页签不吃合成点击**：`click` 落在"流程画布"文字上只出悬停、不切页签，`ctrl+Tab` 也不灵。
  可用的办法是改 `bin\...\Layout.xml`：给目标 `LayoutDocument` 加 `IsSelected="True" IsLastFocusedDocument="True"`
  并刷 `LastActivationTimeStamp`，启动即落在该文档。测完记得从
  `artifacts\logs\20261024\layout-backup\` 还原。
