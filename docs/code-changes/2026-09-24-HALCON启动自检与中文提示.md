# 2026-09-24 HALCON 启动自检 + 中文提示

## 1. 需求与决策

### 1.1 需求来源

用户提问：

> 我现在这个软件如果放到一台新电脑上 可以直接使用吗 如果他没装Halcon的话

查证后的结论是**不能**（见 1.3），于是用户要求：**做启动自检 + 中文提示，但不要禁用视觉入口**。

### 1.2 三项决策（逐轮 `AskUserQuestion`，用户明确答复）

| 轮次 | 问题 | 用户选择 |
| --- | --- | --- |
| Q1 | 需要做点什么吗？ | **启动自检 + 中文提示，不要禁用视觉入口**（用户改写了推荐项，明确否掉"禁用入口"） |
| Q2 | 提示出现在哪里？ | **启动弹窗一次 + 写日志（推荐）** |

### 1.3 查证出来的事实（本次的立论基础）

**① 程序目录里只有"壳"，没有"芯"**

`VisionMaster\bin\Debug\net9.0-windows\` 里有 `halcondotnet.dll`，但**没有** `halcon.dll`、`hcanvas.dll`、license 文件。

原因是 `<Reference>` 只能引入**托管程序集**：

```xml
<!-- VisionMaster.csproj L37-42 -->
<Reference Include="HalconDotNet">
  <HintPath>..\DLL\Halcon\halcondotnet.dll</HintPath>
</Reference>
```

托管程序集默认 CopyLocal → 跟着程序走；而 `DLL\Halcon\halcon.dll` 是原生 DLL，**根本没法用 `<Reference>` 引入，也就永远不会被自动拷贝**。

**② 本机是"借"着系统装的 HALCON 在跑**

```
HALCONROOT = D:\Halcon\HALCON-23.05-Progress            (Machine 作用域)
PATH 含     = D:\Halcon\HALCON-23.05-Progress\bin\x64-win64
该目录      = 41 个 DLL，470.6 MB
```

**③ 崩溃表现很有迷惑性**：.NET 的 P/Invoke 是懒加载，所以程序能启动、界面能出来、方案能打开，
**只有第一次真调算子时**才抛 `DllNotFoundException: 无法加载 DLL"halcon.dll"`。

**④ 改造前代码里没有任何 HALCON 缺失检测**（全仓搜 `HALCONROOT` 零匹配），
用户看到的只会是英文异常堆栈 + `crash_reports\` 里的记录。

### 1.4 关键设计原则

1. **复用既有自检链，不另起一套。** 程序已有 `IStartupCheck` + Splash 进度显示机制，
   且 `CheckLevel.Warning` 的语义逐字就是"失败仅提示，放行进入主界面"——正好是用户要的效果。
2. **判 Warning 不判 Error。** 缺 HALCON 只影响视觉功能，不影响看方案、配流程、调通讯。
   判 Error 会把整个软件挡在门外，代价远大于收益。
3. **不禁用任何入口**（用户明确要求）。把入口灰掉反而挡住了
   "先把流程编好、等 HALCON 装好再跑"这条正常路径。
4. **先查环境、再真调一次。** 只查环境会误判（文件都在、license 过期，照样崩）；
   只真调一次说不清原因（"不可用"三个字对用户毫无帮助）。
   两者合起来才能给出"缺什么、去哪装、怎么验证"的可执行建议。
5. **判定只认真调用，环境信息只用于把建议写准。** 尤其是 license：
   网络许可服务器模式下 `HALCONROOT\license` 里本来就没有文件，拿"文件不存在"当判据会误报。
6. **提示延到主界面出来后再弹。** 自检跑在 Splash 上，而 Splash 在主窗口显示后立刻关闭 ——
   提示写得再清楚也是一闪而过。所以自检只负责"判"，弹窗挂在 `OnInitialized` 的 ApplicationIdle。

### 1.5 超时保护（接口契约要求）

`IStartupCheck` 注释写着"实现应自带超时保护，不无限阻塞启动"。
HALCON 有一个真实的长阻塞源：**许可走网络许可服务器而服务器不可达时，引擎初始化会干等很久**。
所以给探测加了 10 秒上限；超时按不可用报，并把"去查许可配置"这条线索给用户。

## 2. 修改文件清单

### 2.1 `VisionMaster\Lifetime\Checks\HalconCheck.cs`（**新建**）

实现 `IStartupCheck`，`Name = "视觉引擎（HALCON）"`。

| 成员 | 作用 |
| --- | --- |
| `ExecuteAsync(ct)` | 后台线程探测 + 10 秒超时保护 |
| `Probe()` | 环境诊断 → 真调一次 → 判定 |
| `Fail(...)` | **统一失败出口**：组装弹窗文案 + 落日志 + 返回 Warning |
| `FindHalconDllDirectory()` | 在 PATH 里找**真正放着 halcon.dll** 的目录 |
| `FindLicenseFile(root)` | 找候选许可文件（`HALCON_LICENSE_FILE` → `HALCONROOT\license`） |
| `Classify(ex)` | 异常 → 一句人话（Splash 那行要短） |
| `BuildAdvice(...)` | 异常 → 可执行的处置办法 |
| `LooksLikeLicense(ex)` | 消息里认 `license` / `#2106` / `#2009` 关键字 |
| `FailureDetail` | 多行中文详细说明（供弹窗），可用时为 null |

探测主体：

```csharp
// 判定：造一张 8x8 的图再扔掉。
// 这一步会真正加载 halcon.dll 并触发许可检查，最接近"用户点一下图像功能"。
try
{
    HOperatorSet.GenImageConst(out HObject probe, "byte", 8, 8);
    probe.Dispose();
}
catch (Exception ex)
{
    return Fail(Classify(ex), BuildAdvice(ex, root, dllDir, licenseFile), ex, root, dllDir, licenseFile);
}
```

`FindHalconDllDirectory` 的一个刻意选择——**只看 PATH、不看 HALCONROOT**：

```csharp
/// 决定原生库能否被加载的是 PATH（Windows 的 DLL 搜索顺序），HALCONROOT 只影响 license 查找。
/// 把两者混为一谈，给出的修复建议就会指错地方
///（典型症状：用户明明配了 HALCONROOT，却还是加载失败）。
```

失败分类与对应建议（**三种"找不到 halcon.dll"的情况分开说**，因为处置办法完全不同）：

| 情况 | 建议 |
| --- | --- |
| PATH 里已有含 halcon.dll 的目录，但仍加载失败 | 确认 halcon.dll 完整、没被杀毒拦截 |
| `HALCONROOT` 也没设置 | 本机没装 HALCON，请安装 23.05（64 位） |
| 有 `HALCONROOT` 但 PATH 里没有该目录 | 把 `%HALCONROOT%\bin\x64-win64` 加入 PATH |
| `BadImageFormatException` | 装成了 32 位，请改装 64 位 |
| 许可类（有许可文件） | 已过期 / 换机换网卡 / 授权占满，联系供应商 |
| 许可类（无许可文件） | 把 `license_*.dat` 放到 `HALCONROOT\license`，或用 `HALCON_LICENSE_FILE` 指定 |

### 2.2 `VisionMaster\App.xaml.cs`（3 处编辑）

| # | 改动 |
| --- | --- |
| 1 | 新增字段 `private HalconCheck? _halconCheck;` |
| 2 | 自检链注册：插在 `ConfigCheck` 之后、`PluginScanCheck` 之前 |
| 3 | `OnInitialized` 里挂 `ShowHalconNotice`（ApplicationIdle）+ 新增该方法 |

```csharp
// 视觉引擎自检：结果判 Warning —— 缺 HALCON 只影响视觉功能，不该把整个软件挡在门外。
// 详细说明不在这里弹（Splash 转瞬即逝），留到主界面出来后再弹，见 ShowHalconNotice
_halconCheck = new HalconCheck(Container.Resolve<ILogService>());
_lifetime.RegisterCheck(_halconCheck);
```

```csharp
private void ShowHalconNotice()
{
    if (_halconCheck?.FailureDetail == null) return;   // 引擎可用 → 什么都不做
    try
    {
        var owner = Current.MainWindow;
        string text = _halconCheck.FailureDetail;
        if (owner == null) MessageBox.Show(text, "视觉引擎不可用", MessageBoxButton.OK, MessageBoxImage.Warning);
        else MessageBox.Show(owner, text, "视觉引擎不可用", MessageBoxButton.OK, MessageBoxImage.Warning);
    }
    catch (Exception ex)
    {
        // 提示本身失败绝不能影响主界面：记一行日志就够了（与 ShowRecoveryNotice 同口径）
        try { Container.Resolve<ILogService>().Warn($"[启动自检] HALCON 提示显示失败：{ex.Message}"); } catch { }
    }
}
```

## 4. 已知边界

1. **只回答"能不能用"，不回答"功能全不全"**：基础算子通过不代表所有模块可用 ——
   OCR、3D、深度学习等模块可能有各自的 license。本自检只验证"基础视觉链路是否通"。
2. **超时后探测任务仍在后台跑**：HalconDotNet 的原生调用不可中断，10 秒超时只是不再等它；
   该任务最终会自行结束（异常已被 `ContinueWith` 吃掉，不会变成未观察异常）。
3. **按用户要求不禁用任何入口**：用户在 HALCON 不可用时仍可点进图像功能，
   届时看到的仍是 HALCON 原始异常（只是现在他已经被提前告知过原因）。
4. **许可判定靠关键字**：HALCON 没有独立的许可异常类型，只能匹配消息里的
   `license` / `#2106` / `#2009`。若换版本后错误码变了，会落到"引擎调用失败"这个兜底分类
   （提示仍准确，只是不够具体）。
5. **只在启动时自检一次**：程序运行中用户去装了 HALCON，需要**重启**才会认（不提供"重新检测"按钮）。
6. **每次启动弹一次**：引擎不可用时每次启动弹一次窗，不常驻、不重复提醒。
7. **环境诊断里的 license 检查仅供参考**：网络许可服务器模式下，`HALCONROOT\license` 里
   本来就没有文件，这是正常的 —— 所以判定永远以真调用为准，环境信息只用于把建议写准。
8. **未纳入自动冒烟**：`FlowCanvasChecks` 目前不覆盖 `App` 的自检链，
   本次的验证靠"真启动一次程序 + 读日志"完成（见 3.1）。
9. **"输出目录缺 halcon.dll"这条根因未改变**：本自检只是把失败变体面，
   **不解决"没装 HALCON 就用不了视觉功能"**。要真正在干净机器上跑起来，
   仍需目标机安装 HALCON（或取得 MVTec 的运行时分发授权）。
