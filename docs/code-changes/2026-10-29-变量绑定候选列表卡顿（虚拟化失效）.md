# 2026-10-29 变量绑定候选列表卡顿（虚拟化失效）

> ⚠️ **后续修正（同日）**：本文"打开弹窗不再全量实例化"这一结论**不成立**。
> `MaxHeight` 挂在 `LayoutUpdated` 上只能让第二轮收敛，救不了首帧；且"短列表不封顶"分支用
> `Items.Count` 判断，而 `ItemsSource` 是布局期间才落地的 → 首帧仍会把全部候选实例化
> （现场 9000 个变量实测 122 s）。详见 `2026-10-29-变量绑定弹窗打开卡死（首帧全量实例化）.md`，
> 本文第一、三节的"打开弹窗"部分以该文为准；"改搜索词 / 换端口"的结论仍然有效。

> 现象：变量绑定弹窗里把「数据来源」选成「全局变量 (Global)」（现场 **2702** 条），
> 打开弹窗、在候选搜索框里敲字、换目标端口都卡到数秒——用户原话「这里面的变量一多 就会卡顿」。
> 与 2026-10-29《变量管理批量导入卡顿（O(N²) 树重建）》是同一类症状、**相反**的根因：
> 那一次不是虚拟化问题，这一次**正是**虚拟化被外层 `ScrollViewer` 干掉。

## 一、当前状态

已修复并实测（`UIThemeSmokeTest.exe --variable-binding`，1180×760 宿主）：

| 场景 | 改前 | 改后 |
|---|---|---|
| 1501 条候选全量实例化 | **6157 ms** | —（不再发生） |
| 换搜索词（1501 条候选里过滤） | ~390 ms | **25 ms** |
| 清空搜索（→1501 条） | ~390 ms | **40 ms** |
| 实际实例化的行容器 | 1501 个 | **9~10 个** |

`run_gates.ps1` 全量闸门见第五节。

## 二、根因

候选列表 `CandidateList`（`VariableBindingView.xaml`）整块嵌在右栏的 `BindingBodyScroll`
（外层 `ScrollViewer` + `StackPanel`）里，而它自己的竖向滚动被显式关掉了：

```
ScrollViewer.VerticalScrollBarVisibility="Disabled"
```

两个因素叠加 → **量它时可用高度是无穷** → `VirtualizingStackPanel` 退化成逐行实例化、一行都不回收。
2702 条候选 = 2702 个 `ListBoxItem` 全部建出来（列高约 14 万像素）。

行模板本身也重。二分实测（1501 条、纯 UI 重建）：

| 变体 | 100 行耗时 |
|---|---|
| 空 `DataTemplate` | 8 ms |
| 真实行模板 | ~400 ms（≈4 ms/行） |
| 真实模板 − 4 个 `AncestorType=UserControl` MultiBinding | ~200 ms |
| 真实模板 − 4 个 `AncestorType` − 每行 `ToolTip` | ~200 ms（ToolTip 不是主因） |

三个触发点都会把这几千行重造一遍：打开弹窗（默认选中 `TreeNodes[0]` 就是全局变量节点）、
候选搜索框每次 `TextChanged`（`_candidateView.Refresh()` → Reset → 全部容器重建）、
换目标端口（`SelectedInputPort` 变了要重算类型过滤）。

## 三、已做

| 文件 | 改动 |
|---|---|
| `VisionMaster\Views\DialogViews\VariableBindingView.xaml` | `CandidateList` 的 `ScrollViewer.VerticalScrollBarVisibility` 由 `Disabled` 改 `Auto`；就地写清"高度必须有界才能虚拟化"的注释 |
| `VisionMaster\Views\DialogViews\VariableBindingView.xaml.cs` | 新增 `UpdateCandidateMaxHeight()`：按**视口剩余高度**给 `MaxHeight`（视口高 − 列表在滚动内容里的偏移 − 提示行预留，下限 220），但只有**内容高度超过 3 屏**才封顶（十几行以内保持自然高度 = 基线观感）；挂 `LayoutUpdated` + `Loaded` + `OnRenderSizeChanged` 重算，0.5 差值守卫防自激 |
| 同上 | `OnPreviewMouseWheel` / `FindScrollableAncestor`：内层列表滚到顶/底后**继续往外一层**滚（嵌套滚动不吞滚轮） |
| `UIThemeSmokeTest\VariableBindingViewSmoke.cs` | 夹具加 `bulkObjectVariables`（object 类型变量，`CanBindTo` 双向放行，全部进候选）；新增 4 条断言：虚拟化契约（XAML+code）、1501 条只实例化 ≤25 行、滚到底能实例化最后一条、搜索后仍只实例化可见行 |

为什么按"视口剩余高度"算而不是写死一个数：写死会在候选不多时凭空压出一个内层滚动条
（与设计基线不一致）。再叠一道"3 屏"门槛（`CandidateBoundTriggerScreens`）：**十几行以内完全不封顶**，
自然高度、整列滚动、没有内层滚动条——与基线逐像素一致；只有内容超过 3 屏才封顶，
让虚拟化生效（这种长度本来也只能靠搜索挑，不是靠滚）。设计基线里的可见形态没有变。

## 四、验证

```
[PASS] 候选列表保持虚拟化契约（竖向滚动 Auto + 高度上限由代码给）
[PASS] 候选列表：7 条不封顶（普通数量保持基线观感）  (maxHeight=∞ items=7)
[PASS] 候选列表虚拟化：1501 条候选只实例化可见的十来行（不是全量）  (total=1501 items=1501 realized=6 maxHeight=220)
[PASS] 候选列表虚拟化：滚到底能实例化最后一条（没有丢数据）  (last=BulkVar_1499 realized=True)
[PASS] 候选列表虚拟化：搜索后仍只实例化可见行  (items=1 realized=1)
=== 变量绑定视图冒烟：全部通过 ===（39 条）
```

判据取"ListBox 里实际存在几个 `ListBoxItem` 容器"，**不是耗时**：耗时随机器浮动，
而"几千行全被实例化"是这条缺陷唯一可判定、可反证的表征（把 `MaxHeight` 去掉即回到 1501 个容器 → 判红）。

`tools\run_gates.ps1`：**16 步全绿**（CommChecks 400、FlowCanvasChecks 4357、ScadaChecks 3195、
ScadaWebChecks 193、DataPipelineChecks 97、DatabaseChecks 134、RecipeChecks 138，UIThemeSmokeTest /
HelpProbe exit 0，六个审计 + vms_verify clean）。

> ⚠️ 注意 `run_gates` 里的 `UIThemeSmokeTest exit=0` **不含**本视图的 38 条断言：宿主用空参数跑，

## 五、未做 / 残留

- **没在真 `VisionMaster.exe` 上手动点一遍**：断言宿主用的是真实 VM + 真实视图（`--variable-binding`），
  但宿主窗口不是真弹窗。`MaxHeight` 的视口换算只在 1180×760 下量过；窗口拉大/拉小时
  由 `LayoutUpdated` 重算，理论上跟随，但没有多分辨率实测。
- **行模板仍是 ~4 ms/行**：虚拟化后只实例化十来行，已不是瓶颈（25~40 ms/次重建）。
  若以后要再提速，第一步是把 4 个 `AncestorType=UserControl` MultiBinding（实测占一半）
  改成行内预计算属性（`IsBoundHere` / `ShowBindButton`），第二步才轮到胶囊/按钮样式。
- 候选列表**没有截断**：1501 条都能滚到（虚拟化按需实例化）。想快速定位还是走搜索框。

## 六、踩过的坑

- **"分页截断"能治打开卡顿，治不了敲键卡顿**：先按"只显示前 100 行 + 再显示"做了一版，
  打开从 6.2 s 降到 0.7 s，但每次 `TextChanged` 重建 100 行仍是 ~390 ms。
  真正的解法是让列表自己虚拟化（10 行 = 25 ms），而不是少画几行。
- **先二分再动手**：`空模板 8 ms` / `真实模板 400 ms` 一刀就把"VM 过滤慢"排除掉了；
  再摘 `AncestorType` 绑定（400→200）与 `ToolTip`（无变化）就知道钱花在哪。
  没有这一步很容易去优化 `TypeHelper.ResolveType` 之类的错误目标。
- **别写 `CandidateList.SelectedItem = x` 恢复选中**：`SelectedItem` 是双向绑定到
  `VM.SelectedOutputPort` 的，`SetValue` 会把那条绑定整个换成局部值（绑定永久失效）。
- **`MaxHeight` 要按视口算**：第一版只挂 `ScrollViewer.SizeChanged/ScrollChanged`，
  首次布局时视口还是 0，值停在 220 下限且之后没再重算；改挂 `LayoutUpdated` 才稳。
- **封顶本身就改观感**：第一版无条件封顶，7 条候选也被压成 4 行 + 内层滚动条——
  为了治 2702 条的卡，把常见场景的样子改了。加"3 屏门槛"后两头都对：
  十几行以内不封顶（基线），长列表才封顶（虚拟化）。
- **`run_gates.ps1` 不跑参数化冒烟**：它用空参数跑宿主，而本视图的冒烟要
  `--variable-binding` 才会执行——`run_gates` 全绿 ≠ 变量绑定视图被测过。
  本次改动必须另外手跑一次带参数的那条（命令见第四节）。
