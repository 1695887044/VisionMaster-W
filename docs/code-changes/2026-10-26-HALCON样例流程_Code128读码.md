# HALCON 样例流程 ④：Code 128 一维码（3 张）

> 日期：2026-10-26。第四条 HALCON 样例流程：用 `code128.hdev` 的 3 张样张，
> 对比 HALCON `find_bar_code` 与 VM `CodeReader` 的解码内容。
> 3/3 张逐字符一致，含 `code12803` 里的 SOH/TAB/CR 控制字符。

## 一、当前状态

- **HALCON 例程**：`examples\hdevelop\Identification\Bar-Code\code128.hdev`
- **图片**：`examples\images\barcode\code128\code12801..03.png`
  （仓库 `Image\images\barcode\code128` 有同一份）
- **HALCON 参数**：`create_bar_code_model([], [])` + `find_bar_code(Image, …, 'Code 128', …)`
- **VM 参数**：`CodeReaderPlugin`，`Symbology="Code 128"`、`TimeoutMs=500`
  （`BarCodeEngine` 只额外设 `timeout`，不设其它模型参数）
- **结果**：

  | 图片 | HALCON 解码 | VM 解码 |
  | --- | --- | --- |
  | `code12801.png` | `MVTec Software GmbH` | 同左 |
  | `code12802.png` | `234257849713629478135619` | 同左 |
  | `code12803.png` | `A: Text, B: <SOH>\t<CR>, C: 347862` | 同左 |

  3/3 逐字符一致（含控制字符，未被截断或转义）。
- **落盘流程**：`解决方案\视觉样例对拍\视觉样例对拍.vms` 新增 `码读取_Code128`，
  步骤 `读取条码图像 → Code128读码`（全中文命名）。

## 二、已做

### 2.1 对拍结果

临时探针 `HalconCodeCompare` 直接调 `CodeReaderPlugin` 的私有 `TryRead`
（运行期与配置期试算共用的那条路径），与本进程内 HALCON `find_bar_code` 比对：

```text
[code12801.png] ref=1 vm=1 OK
[code12802.png] ref=1 vm=1 OK
[code12803.png] ref=1 vm=1 OK
RESULT: ALL_OK
```

- `CodeReader` 本身是 HALCON 的薄封装（`create_bar_code_model` + `find_bar_code`），
  这一条验的是**码制字符串、超时参数、结果收集与端口输出**这条接线，
  不是重新实现解码算法；因此"一致"是预期结果，出现差异反而说明接线错了。
- `code12803` 的结果里含 `SOH`（0x01）、`TAB`、`CR`，用 `\u0001` 拼接比对，
  能抓住"把控制字符过滤/截断/转义"的问题。

### 2.2 落盘流程

```text
视觉样例对拍
├─ 模板匹配_NCC散焦图
├─ 形状匹配_散焦PCB
├─ Blob缺陷检测_标签字符
├─ 二维码读取_QR
└─ 码读取_Code128（For 3 次）
   └─ 循环体
      ├─ 读取条码图像（文件夹：<方案根>\Image\barcode_code128，FileIndex←For.Index）
      ├─ Code128读码（码读取，Symbology=Code 128、TimeoutMs=500）
      │    Image ← 读取条码图像.Image
      └─ 显示检测结果（结果显示，DisplayViewIndex=1）
           SrcImage ← 读取条码图像.Image
           OverlayContours ← Code128读码.SymbolContours
           OverlayLabels ← Code128读码.Codes
           r1..r2 ← Count / Text
```

- 工厂批量口径：`For` 遍历整个样例目录（3 张），采集步骤是文件夹模式，`FileIndex` 接 `For.Index`；
  目录用方案内绝对路径（`AcquireFromFolder` 直接 `Directory.Exists`，不解析相对目录）。
- 读码插件只输出 `SymbolContours`（码轮廓）与 `Codes`；结果显示底图接采集原图、
  `OverlayContours` 接 `SymbolContours`、`OverlayLabels` 接 `Codes`（逐码标内容），
  另设 `OverlayPalette=green,red,yellow`、`OverlayLineWidth=2`；
  这样图像窗口 1 每圈都能看到“读的是哪张图 + 码框 + 解出什么”。
- 步骤配置来自 `CodeReaderPlugin` 的 `[StepConfig]` 属性快照。
- 3 张图全部由 `For` 遍历，不是只跑一张；断言里另有 `CheckBatchFlow` 钉住 For 次数与文件夹模式。

### 2.3 回归断言

`FlowCanvasChecks/CodeReaderChecks.cs` 新增 `RunHalconSampleFlow()`：

1. `SolutionService.LoadAsync` 打开 `解决方案\视觉样例对拍\视觉样例对拍.vms`；
2. 按 `FlowName` 找 `码读取_Code128`，核对采集/算法/结果显示三个步骤与图片路径；
3. `FlowCompiler.Compile` 校验端口名/连线类型；
4. 真 `CodeReaderPlugin.Initialize(step)` + 喂图 + `Execute`；
5. 同一进程内用 HALCON `find_bar_code` 现算真值，逐字符比对（含控制字符）；
6. 判据：`Success=true && vm.Length==ref.Length && 拼接串相等`。

结果：`FlowCanvasChecks` **3738 通过 / 0 失败**（含前三条样例流程）。

## 五、踩过的坑

1. **控制字符不要经过 `Trim`/正则清洗**：`code12803` 的内容里含 `SOH/TAB/CR`，
   比对必须用原始字符串；探针输出时才转义显示。
2. **流程只覆盖一张图**：`ImageAcquisition` 一次只读一个 `FilePath`，
   多图样例要么建多条流程，要么在断言里直接喂图；本样例选了后者。
3. **连线端口名**：`CodeReader.Image` 与 `ImageAcquisition.Image` 同名，
   `LinkedSources` 键与 `TargetPortName` 都写 `Image`；这与 Blob 样例
   （`SrcImage ← Image`）不同，写之前先查两端端口名。
