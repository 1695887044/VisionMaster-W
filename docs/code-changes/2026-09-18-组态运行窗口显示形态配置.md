## 一、需求与决策

### 1. 需求

> 「你现在的 SCADA 运行窗口把本地视觉图像的界面都覆盖了，你应该加个配置项，让用户选择是新开一个独立窗口和视觉图像窗口一起显示，还是依附在这个主窗口前面。」

改法入口由用户拍板：**系统菜单 → 「运行窗口设置」**（弹小对话框选形态）。

### 2. 根因

不是宿主逻辑写错了，而是窗口形态被**写死在编译期**。[ScadaRuntimeWindow.xaml](../../VisionMaster/Views/ScadaRuntimeWindow.xaml) 里同时钉了三个属性：

```
WindowStyle="None"  WindowState="Maximized"  ResizeMode="NoResize"
```

一开就是无边框满屏 —— 开发调试时必然盖住视觉图像面板。"形态"从一件**策略**（读配置决定）变成了**事实**（改不了）。

### 3. 决策清单

| # | 决策 | 理由 |
|---|---|---|
| D1 | 配置落 **AppConfig.json**（`AppConfigModel.RunWindowMode`），不落 `.vms` | 这是"这台机器怎么用"的偏好，不是"这份方案长什么样"的一部分。同一份方案在开发机上想窗口化、在现场机上要全屏，两边不该互相改 |
| D2 | 默认值 = **依附主窗口**（= 历史行为） | 现场已在产线跑的设备，不能因为一次升级就变成窗口化运行 |
| D3 | 枚举 `ScadaRunWindowMode` **成员加在末尾**（`AttachedToMainWindow=0` / `IndependentWindow=1`） | 整数值会落进 AppConfig.json。中间插一个成员会把后面所有成员的值整体挪一位，读回来就是另一个形态 |
| D4 | 枚举**不加** `StringEnumConverter` | 字符串形式一旦拼错，整份 AppConfig.json 反序列化失败——连带把方案清单一起丢掉。稳定性优先于可读性 |
| D5 | 独立窗口**不挂 `Owner`**；依附窗口**挂 `Owner`** | 挂上 Owner 就永远压在主界面之上、还会跟着一起最小化，"和视觉图像窗口一起显示"直接落空 |
| D6 | 独立窗口落**工作区右下角**，不居中 | 主界面通常最大化，居中弹出的 1280×800 正好压在界面中央——多半就是图像区，等于换个方式复现本来要躲的问题 |
| D7 | 形态在 `Show()` **之前**定死 | `WindowStyle`/`WindowState` 在窗口显示之后再改，WPF 会重建非客户区，表现为闪一下、尺寸跳一格 |
| D8 | 设置弹窗**取消不留痕**，只有确定才写盘 | 改到一半点取消，配置保持原样 |
| D9 | 宿主每次 `Start()` **现读**配置 | 「改完立即生效」不需要重启软件，也不需要在 Shell 里做任何同步动作 |
| D10 | XAML 里**不写**这三个属性 | WPF 默认值本身就是独立窗口形态。万一哪条路径漏调 `ApplyRunWindowMode`，退化的也是一个正常窗口，而不是全屏覆盖 |

## 三、验证结果

### 断言（`dotnet run --project ScadaChecks`）

**622 通过 / 0 失败**（本段新增 15 条，改动前基线 607）。

分三层钉：

**① 枚举与默认值契约**

- 枚举成员顺序冻结（`0=依附` / `1=独立`）
- 新建配置默认是「依附主窗口」

**② 设置弹窗写盘契约**

- 打开弹窗显示的是**当前生效**的形态（不是上次点过的）
- 选独立后两选项互斥
- RadioButton 取消选中写的 `false` 被忽略（否则新旧选项互相覆盖）
- **取消**：关窗返回 `Cancel`，配置保持原值
- **确定**：关窗返回 `OK`，内存配置同步
- 确定后**重新从磁盘加载**读回来仍是独立窗口（证明真写了盘，不是只改内存）
- 再次打开：编辑态从配置现读，无残留

**③ 窗口形态属性组合**

- **回归守卫**：刚构造的窗口必须是普通窗口（`SingleBorderWindow` / `Normal` / 非 `NoResize`）——XAML 里一旦有人把三件套写回去，这条立刻红
- 独立形态：`SingleBorderWindow` + `CanResize` + `Normal` + `ShowInTaskbar`
- 独立形态：落在工作区右下角（实测 `Left=625 Top=261` / 工作区 `1707×1019`）
- 独立形态：尺寸按工作区收过（实测 `1058 × 733`，不铺满）
- 依附形态：`None` + `NoResize` + `Maximized` + 不占任务栏
- 窗口自身不碰 `Owner`

> `MakeCloseListener` 说明：Prism 9 的 `DialogCloseListener` 是**类**不是委托，回调只能经 internal 构造器注入，而断言环境里没有 `DialogService`。这里用反射造一个替身，好在断言里观察"以什么结果关窗"。

## 四、已知边界

1. **视觉复核未做**：两种形态的实际观感（独立窗口是否真的与视觉图像并排、依附形态是否真的铺满）未在运行态截图确认。断言只覆盖属性组合，覆盖不到"用户看着舒不舒服"。
2. **多显示器**：`SystemParameters.WorkArea` 取的是**主屏**工作区。主界面若在副屏，独立运行窗口仍会落在主屏右下角。
3. **已开着的运行窗口不受影响**：配置在 `Start()` 时读取，改配置不会去动正在跑的那个窗口（它已经在跑了）。需先「停止运行」再重开。
4. **`Owner` 的副作用**（依附形态）：最小化主界面会连带最小化运行窗口。对"设计完看一眼效果"正是想要的行为，但未单独做断言（`Start()` 需要消息循环，控制台断言宿主里跑不了）。
5. **`AppConfig.json` 路径写死**在程序目录（`AppDomain.CurrentDomain.BaseDirectory`），`AppSettingsService` 没有可注入的路径，所以断言用的是真实文件 + `finally` 回写原值。这意味着断言会改动 `ScadaChecks/bin/.../AppConfig.json`（构建产物目录，无害）。
6. **`ScadaRuntimeHost` 的 Owner 策略未被断言覆盖**，仅靠代码审查与窗口层断言间接保证。
