## 一、需求与决策

### 1. 需求（用户原话）

> 「你的数值域,没有可读可写的功能」

对标手册后，这一条展开成五个能力点，缺一个都算不上商用：

| # | 手册能力 | 现场含义 |
|---|---|---|
| 1 | **模式**（输入 / 输出 / 输入输出） | 同一个图元，有的位置只许看、有的位置只许改、有的位置两样都要 |
| 2 | **缩放**（增益 / 偏移量） | PLC 里存 `0.1℃` 的整数（235 = 23.5℃），画面上要显示 `23.5` |
| 3 | **限制**（上限 / 下限） | 操作员手滑多敲一位，不许写进设备 |
| 4 | **超限变色** | 不用去翻报警，一列数值里超限的那个自己跳出来 |
| 5 | **格式类型**（十进制 / 十六进制 / 二进制） | 位状态、字状态、设备地址这类要按 16 进制看 |

### 2. 决策清单 —— 依赖方向与落点

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| A-1 | 写通路接口放哪层 | **领域层** `Scada\Models\IScadaValueWriter.cs` | 与 `IScadaValueSource` 逐字同源：输入框在控件库（`VM.Scada.Controls`）里，而它够不着变量注册表与 `VariableValueConverter`。接口下沉、实现上浮，依赖方向不翻（**D1**） |
| A-2 | 接口参数是"文本"还是"已转好的对象" | **文本**（`string? text`） | 输入框交给程序的天然形态就是一串字；变量的类型是可以在变量管理里改的（int ↔ string）。把"转成什么类型"定死在图元里 → "组态时是 double、后来变量改成 int、画面开始报错"这类僵死。目标类型在**真正要写的那一刻**向 `IScadaValueHandle.DataType` 现问，转换规则只认 `VariableValueConverter` 一份——与"写变量"动作、变量管理弹窗写值同一条口径 |
| A-3 | 失败怎么表达 | **返回 false + 中文原因**（`out string? error`），不抛 | 输入框那一下不该让整页运行崩掉。原因串要能**直接展示给操作员**（"没绑变量""「abc」转不成 Int32""设备离线"） |
| A-4 | 写通道怎么进控件 | `ScadaRuntimeContext` 加**可选**第三参 `IScadaValueWriter? writer` | 纯监视画面不该被迫提供一个写通道。可选参意味着既有三处 `new ScadaRuntimeContext(engine, beat)` 构造点**一行不用改** |
| A-5 | 谁判断"能不能改" | 控件自己（`UpdateEditable()`） | 三个条件同时成立才可编辑：`Mode != Output` && `RuntimeContext?.Writer is not null` && `Element.FindBinding("Value") is { IsEnabled: true }`。组态态（无 `RuntimeContext`）恒不可编辑 |

### 3. 决策清单 —— 控件层（`IOFieldElement`）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| B-1 | 显示量从哪来 | **只读 DP**：`DisplayBrush` / `DisplayStroke` / `ValueText` / `IsEditable` | ① 可写属性会有两个来源（程序算一次、模板再设一次）；② 类型上就宣告"这是算出来的"。连带好处：**模板一条 Trigger 都不写**，断言直接读属性而不是数像素 |
| B-2 | 就地编辑怎么摆 | **两块元素叠放**（`ValueDisplay` TextBlock + `PART_Editor` TextBox），靠 `IsEditing` 的 DataTrigger 翻转 `Visibility` | 比"编辑时换一个元素"稳：视觉树不动，焦点、命中测试、尺寸都不重算 |
| B-3 | 点进去的事件走哪个 | **隧道事件** `OnPreviewMouseLeftButtonDown` | 内置 `ButtonBase` / `TextBox` 会吃掉冒泡的 `MouseLeftButtonDown`，隧道阶段才抢得到 |
| B-4 | 提交时写回什么串 | 十进制格式且无缩放时**原样交**（保住 `23.50` 这种写法）；否则交**已算好的十进制串** | 见下方"三、修掉的一个真缺陷" |
| B-5 | 超限了怎么办 | **拒写**，不夹到边界 | 静默改掉操作员敲的数比拒绝更危险。拒写时把中文原因挂到 `ToolTip`（绑 `EditError`） |
| B-6 | 出错怎么提示 | 边框描红（`DisplayStroke` 取 `ErrorBrush`） | 比弹窗轻；与超限变色（文字变色）分工：**红框 = 写不进去，变色 = 值越界** |
| B-7 | "只写"模式收到变量刷新怎么办 | 覆写 `TryApplyRuntimeValue`：**认下刷新但不落值**，提交后用 `SetCurrentValue` 本地承接 | `SetCurrentValue` 改自身 DP 而不破坏既有绑定来源 |
| B-8 | 进制与变量值的关系 | 进制**只是显示与输入的进制**，变量里存的始终是同一个十进制数 | Hex 下敲 `FF` → 写回 `255`；Binary 下敲 `11111` → 写回 `31` |

### 4. 决策清单 —— 描述符（唯一真相，**D2**）

| # | 决策点 | 选择 | 依据 |
|---|---|---|---|
| C-1 | 新属性怎么分组 | `Mode` / `FormatType` / `Gain` / `Offset` 进既有**「数据」**组；上下限六条进**新增「限制」**组 | 面板上"限制"是一整块语义，塞进"数据"会让"数据"变成杂物抽屉 |
| C-2 | 「限制」组要不要进 `NonBindableGroups` | **不进** | 该集合是 `{ "位置与尺寸", "外观" }`。限制值是可绑定的（"这批活的上限跟着配方走"） |
| C-3 | Choice 默认值 | 一律 ∈ `Choices` | 描述符注册的三类失败之一就是"Choice 默认值 ∉ Choices"，会直接让整个图元类型注册失败 |
| C-4 | Number 型要不要给 Min/Max | `Gain` / `Offset` / `Minimum` / `Maximum` **不给** | 另一类注册失败是"Number 型外设 Min/Max"。而且 `Gain` 本来就允许填 0（由逻辑拒写，不由面板拦） |

## 三、修掉的一个真缺陷

写断言时暴露：**十六进制 / 二进制模式下，把输入框原文直接交给变量转换器会写不进去**。

- 现象：Hex 模式敲 `FF`，转换器拿到字符串 `"FF"` 去转 `Double` → 失败，变量纹丝不动。
- 根因：`CommitEdit()` 里"原样交原文"那条捷径只对十进制成立。Hex / Binary 下输入框里的字（`FF`）与变量里的数（`255`）**不是同一个写法**。
- 修复：加 `IsDecimalFormat` 判定，非十进制时一律走**已经算好的十进制串**：

```csharp
private bool IsDecimalFormat
    => !string.Equals(FormatType, FormatHex, StringComparison.OrdinalIgnoreCase)
       && !string.Equals(FormatType, FormatBinary, StringComparison.OrdinalIgnoreCase);
```

```csharp
var raw = (entered - Offset) / Gain;
var writeText = (Gain == 1d && Offset == 0d && IsDecimalFormat)
    ? text
    : raw.ToString("R", CultureInfo.InvariantCulture);
```

`"R"` 是为了十进制下无缩放时也不丢精度地重排一遍（与 `23.50` 这类原文写法互不冲突：无缩放且十进制时仍走原样交）。
