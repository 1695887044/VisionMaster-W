# SCADA 格式工具栏（r5）

在组态编辑器「顶栏」与「画布」之间新开一行格式工具栏，把原本只藏在右键菜单里的
排列类能力全部搬到明面上，并补上手册第 7 章有、本工程没有的三样：
**等尺寸**（等宽 / 等高 / 等大小）、**等间距**（水平 / 垂直）、**对齐网格**。

---

## 一、需求与决策

### 1. 需求

编辑器里「改多个图元的相对形态」这件事，原先只有右键菜单一条路：
对齐与分布 8 项 + 叠放次序 4 项，散在两个分组里，选中多个图元时要先右键、再展开、再点。
需求是把它做成一条常驻工具栏，并且补齐商业组态软件里常见、本工程缺的三样排列能力。

### 2. 关键决策（逐条已与用户确认）

| # | 决策点 | 结论 | 为什么 |
|---|---|---|---|
| 1 | 工具栏落在哪 | 顶栏下方新增一行 | 顶栏已经装了画面选择与取景工具，再塞 18 颗按钮会把「挑画面」这件事挤没 |
| 2 | 等宽 / 等高的基准取谁 | 以选中集合里最大的为准 | 与商业组态软件一致；取最小会让所有图元一起缩小，「统一」看不出效果 |
| 3 | 等间距的锚点取谁 | 第一个（沿轴排序后最靠前的那个） | 「从第一个往后排」比「两端摊匀」更好理解，也不必解方程 |
| 4 | 对齐网格看不看顶栏「吸附」开关 | 无视 | 「吸附」管的是拖动过程；对齐网格是一次显式命令，按下它就是明确要求吸一次 |
| 5 | 间距像素的输入形态 | 内联数值框 + 两个方向按钮 | 数值框在前、方向按钮在后，读起来就是「按这个间距，水平排 / 垂直排」 |
| 6 | 搬运范围 | 只搬排列类（对齐与分布 8 + 等尺寸 3 + 等间距 2 + 对齐网格 1 + 叠放 4） | 剪贴板、锁定、组合、删除这些「改内容」的动作留在右键菜单，工具栏只放「改形态」 |
| 7 | 三个新能力的领域层入口怎么组织 | 新建独立枚举 `ScadaSizeMatch` / `ScadaSpacing` | 等尺寸改 `Width/Height`、等间距改 `X/Y`，两组写入口连参数表都不一样，硬并成一个枚举每处调用点都要再分一次流 |
| 8 | 三个新能力要不要同步进右键菜单 | 同步进 | 工具栏是「快」，右键菜单是「全」；只做一处会让两边的能力清单慢慢分叉 |

### 3. 设计要点（为什么这么做）

- **三条新写入口与 `TryAlignElements` 同一副骨架**：数量下界 → 可编辑过滤 → 一次 `BeginEdit`。
  数量下界写在领域层的 `ScadaSizeMatchExtensions.MinimumCount` / `ScadaSpacingExtensions.MinimumCount` 上，
  **菜单判灰与领域层前置校验读的是同一个常量**——各写一遍就会出现「按钮亮着、点了却返回 false」。
- **等大小恒等于「先等宽再等高」**：`Both` 刻意按两根轴各自取最大，而不是取「面积最大的那个图元」的宽高。
  否则用户点一个按钮和点两个按钮会得到两张不同的画面。
- **一次操作 = 一条撤销记录**：批量改 10 个图元不该要按 10 次 Ctrl+Z。
- **间距值是「参数」不是「状态」**：`SpacingGap` 放在视图模型、不落盘，与 Zoom / Offset 同一条口径；
  存进 .vms 只会让「上次在这儿填了几」变成跨机器复现的隐式配置。默认给 20 而不是 0——
  0 的结果是图元紧贴，看起来像「没生效」。
- **依赖单向**：三个写入口全在 `Scada`（领域层，零 WPF）里，工具栏只是把命令接上去。
- **间距框用 `LostFocus` 而不是 `PropertyChanged`**：点按钮时文本框先失焦、值先写回视图模型，命令才执行，
  所以「改完数字直接点按钮」一定带上新值；若用 `PropertyChanged`，用户想输 20 时敲下 2 那一刻就会按 2 像素排一次。

### 新增（领域层，零 WPF）

| 文件 | 内容 |
|---|---|
| `Scada/Models/ScadaSizeMatch.cs` | 枚举 `Width = 1` / `Height = 2` / `Both = 3`；`ScadaSizeMatchExtensions.MinimumCount = 2` + 中文 `DisplayName()` |

## 三、验证结果

命令：

```
dotnet build VisionMaster.sln -v q --nologo
dotnet run --project ScadaChecks\ScadaChecks.csproj --no-build
```

- 编译：**0 错误 / 365 警告**（均为历史遗留的 `CS8600/CS8602/CS8604`，与本次改动无关）。
- 断言：**通过 1614 / 失败 0**。

### 断言分四段，各钉一类口径

| 段 | 验什么 | 代表断言 |
|---|---|---|
| ① 等尺寸领域层 | 基准取「可编辑里最大者」、锁定者既不改也不当基准、等大小恒等于「先等宽再等高」、一次操作一条撤销记录、null / 越界 / 外来图元各给中文拒绝理由 | 30/80 → 80；`szBothA` 20×90、`szBothB` 70×30 → 两者都成 70×90；`ScadaEditHistory.UndoCount == 1` |
| ② 等间距领域层 | 第一个原地不动、其余按「前一个的右边 + gap」依次落位、垂直档按 Y 轴排序（入参倒着给也认得出谁在头里）、负间距合法（重叠是「排匀」的合法结果） | 0 → 30 → 70；倒序入参仍得 `Y = 0 / 20`；gap = −5 时 `spB.X == 15` |
| ③ 对齐网格领域层 | 网格步长门槛与画布同源（< 1 拒绝、NaN 拒绝且坐标不许被算成 NaN）、无视「吸附」开关 | `GridSize = 0.5` 拒绝且图元不动；`SnapToGrid = false` 时 `13,27 → 10,30`、`46,4 → 50,0` |
| ④ 工具栏与菜单形态 | 菜单 13 栏且次序冻结、前五栏是分组项、后八栏是叶子项、两栏子项数与描述一致、各带图标且同栏内互不相同、图标字体里真有这些码点 | `menu.Count == 13`；`sizeShotItems.Count == 3` / `spacingShotItems.Count == 2`；`menuGlyphs` 逐个 `CharacterToGlyphMap` 命中 |

## 四、已知边界

1. **等尺寸的基准只有「最大者」一种口径**，不能选「最小者 / 第一个 / 最后一个」。
2. **等尺寸的缩放锚点是左上角**（`X / Y` 不动，只改宽高，往右下长），不能选中心或右下。
3. **等间距的锚点只有「第一个」**，不能选「最后一个」或「两端对称摊匀」——两端对称就是既有的「分布」，两者互为反面。
4. **间距值不落盘**：切方案、切标签、重启程序都会回到默认 20。
5. **对齐网格只吸左上角**，不吸中心或某条边；且**无视顶栏「吸附」开关**（这是用户拍板的口径，不是漏做）。
6. **等间距允许负值**（结果是图元重叠），不做校验——与「分布」同一取舍。
7. **本期未给工具栏做图标主题切换**：18 颗按钮的码点是写死在 XAML 里的字面量（`&#xE4BA;` 这种），
   换字形要同时改 XAML 与 `ScadaChecks` 的 `menuGlyphs` 清单。
8. **`Prism.Commands.DelegateCommand<T>` 的泛型参数必须是引用类型或可空类型**。
   本期四处枚举型命令（`AlignCommand` / `MoveZCommand` / `MatchSizeCommand` / `SpaceCommand`）全部写成
   `DelegateCommand<ScadaAlign?>` 这种可空形式——裸枚举能编过、一构造就抛
   `InvalidCastException: T for DelegateCommand<T> is not an object nor Nullable`。
   **以后新增枚举型命令一律照此写 `T?`。**
9. **工具栏横向可滚**：面板被 AvalonDock 拖窄时出现一条滚动条，宁可滚也不要让右边的按钮被裁掉
   （被裁掉的按钮，用户根本不知道它存在过）。
10. **本期断言只在断言宿主里跑**，工具栏在真机上的手感（按钮间距、滚动手感、图标清晰度）仍需现场确认。
11. **环境级抖动**：复跑断言时偶发 `AppSettingsService.Save()` 的 `File.Replace` 抛
    `IOException: 无法删除要被替换的文件`（退出码 `3762504530`）。这是 VS 常驻进程
    （`ServiceHub.Host.dotnet.x64`）持有 `AppConfig.json` 句柄所致，与本期改动无关，原样重跑一次即通过。
