# 2026-09-17 SCADA 图层与画面管理（S3-e2）—— 图层是"分组开关"，不是"深度容器"

## 一、需求与决策

### 背景：这一阶段要回答的是"一批图元怎么一起管"

S3 前几段把"一个图元怎么摆、怎么改"铺完了：

| 阶段 | 交付物 | 用户能做到 |
|---|---|---|
| S1 [SCADA画面领域层](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA画面领域层.md) | `ScadaDocument → ScadaPage → ScadaElement` | 有模型、能落盘 |
| S2 [SCADA图元控件库](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元控件库.md) | 注册表 / 描述符 / 图元控件 / `ScadaCanvas` | 画得出来 |
| S3-c [工具箱与拖放](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元工具箱与拖放.md) | 工具箱 + 拖放落画布 | 摆上图元 |
| S3-d [图元属性面板](file:///e:/VM/VisionMaster-W-master/docs/code-changes/2026-09-17-SCADA图元属性面板.md) | 描述符驱动的属性面板 | 改单个图元 |

但组态画面在工程上从来不是"几十个孤立方块"。真实的一张料线画面长这样：

```
   图层面板                画布（谁盖住谁只看 ZIndex，与图层无关）
 ┌──────────────┐
 │ 👁 🔒 报警层  │   ← 关掉：满屏的报警灯一起消失，用来看清底下的管道
 │ 👁 🔒 标注层  │   ← 锁上：几十条文字一条也挪不动，免得调底图时碰歪
 │ 👁    动态层  │
 │ 👁    底图    │   ← 设备轮廓、管道：画完就该锁死的那一批
 └──────┬───────┘
        │ 一次开关作用在 30~300 个图元上
        ▼
   ScadaElement.LayerId ──► ScadaLayer.LayerId   （归属只有这一条引用）
```

"锁住底图免得误挪"、"临时隐藏标注层看清管道"这类高频操作，逐个点选既慢又必漏。
本阶段交付：**图层模型 + 图层/画面管理 API + 画布侧真正按图层渲染与拦截交互 + 图层随方案落盘**。

用户长需求在本阶段的落点仍是那三条：商业级可扩展、模块化、**长期可扩展性优先**，并配"暴力测试"。

### 决策一：归属只存一条引用 —— 图层类里**没有**图元列表

`ScadaLayer` 只有四个字段：`LayerId / Name / IsVisible / IsLocked`。
图元属于谁，只写在 `ScadaElement.LayerId` 上（见 [ScadaLayer.cs](file:///e:/VM/VisionMaster-W-master/Scada/Models/ScadaLayer.cs#L15-L17) 注释 ①）。

为什么不在图层上再存一个 `Elements` 子集合：那是**双主状态** ——
"图元挂在 A 图层的集合里、`LayerId` 却指向 B"迟早会出现，然后必须写一个"对齐两边"的修补方法，
每次增删改都要记得调它。忘一处的症状是"图层面板里数量对不上、隐藏了却还显示"，极难定位。
"这层上有几个图元"用 `CountElements(layer)` 现算（线性一次，图元是画面级集合，量级完全够）。

### 决策二：图层次序 = 集合次序，不存排序号

`ScadaPage.Layers` 的**列表次序**就是图层面板从上到下的次序（[ScadaLayer.cs](file:///e:/VM/VisionMaster-W-master/Scada/Models/ScadaLayer.cs#L19-L21) 注释 ②）。
再存一份 `Order` 数值，就得维护"数值与集合次序不许矛盾"这条永远没人来测的约束。

### 决策三：图层次序**不参与叠放** —— 最容易被误当成 bug 的一条

画面上谁盖住谁，仍然只由 `ScadaElement.ZIndex` 决定。图层管"一批图元的可见性与可编辑性"，不管深度。

不联动的三条硬理由（[ScadaLayer.cs](file:///e:/VM/VisionMaster-W-master/Scada/Models/ScadaLayer.cs#L23-L30) 注释 ③）：

1. "上移图层"要批量改写几十个图元的 `ZIndex`，会把用户手工调好的**层内次序搅平**（整层加偏移只是勉强能用，层间交错时彻底丢失）；
2. 撤销粒度从"一次图层移动"变成"几十次属性写"；
3. **锁定的图层也会被顺带改掉** —— 那是用户没要求的副作用。

InTouch 一类商业组态软件的 Layer 同样是"分组开关"而非"深度容器"。
真要做按层分深度，正确落点是**渲染侧一次性算复合键**（层序 × 层内序），而不是往模型里塞偏移。

### 决策四：`Guid.Empty` = 未分层；悬空归属一律不动

三种状态必须分清，且**不许悄悄改写**（[ScadaElement.cs](file:///e:/VM/VisionMaster-W-master/Scada/Models/ScadaElement.cs#L78-L86)）：

| 状态 | `LayerId` | `ResolveLayer` | 画布表现 |
|---|---|---|---|
| 正常归属 | 指向存在的图层 | 该图层 | 听图层的话 |
| 未分层 | `Guid.Empty` | `null` | 可见、按自身 ZIndex、只看自身锁 |
| 悬空（图层被手工删掉） | 指向不存在的 Id | `null` | **同上** |

后两种按"未分层"处理，是刻意选择的失败方向：脏数据不该让画面打不开，
也不该被猜成"归属某个图层" —— 那等于把用户的图元塞进他没锁定的层里，看着像丢了东西。

`EnsureIdentity()` 只补两件**不会猜错**的事：图层集合为空时补一个默认图层；
旧文件里从来没写过 `LayerId`（值必然是 `Guid.Empty`）的平铺图元统一归进默认图层。
**指向已删除图层的悬空 Id 一律不动** —— 那种情形只有用户知道图元该去哪。

### 决策五：删除口径两处**刻意不同**

| 操作 | 规则 | 为什么不一样 |
|---|---|---|
| `TryRemoveLayer` | 只许删**空**图层，且画面必须留下至少一个图层 | 用户只想丢掉一个分组开关，图元是他的资产；非空图层被删，图元要么跟着消失要么被悄悄塞进别层，两者都是"用户没要求的改动"。于是宁可拒绝并回传"还剩几个图元" |
| `TryRemovePage` | **只拒"删到没有任何画面"**，非空画面照删 | 删画面意味着"这一整屏我都不要了"，拒绝非空画面等于功能不可用。因此界面侧**务必弹确认框**（工程上没有撤销，误删就是真丢了） |

配套：`CanRemoveLayer` / `CountElements` 供按钮置灰与提示语取数；
`OnRemovePage` 的确认框**报数**而不是只问"确定吗"——空画面一删就过，铺了几十个图元的画面得让人先看一眼损失。

### 决策六：`Try*` 家族统一校验口径（照抄 `VariableRegistry.TryRename`）

四个改名/删除入口（图层 3 个 + 画面 3 个）共用同一套判定：

```
① 对象不在集合里        → false + "××不存在，无法××"
② 空名 / 全空格         → false + "××名不能为空"
③ 与原值 Ordinal 相同   → true，什么都不做（幂等，不刷 Version）
④ 与其他同名(IgnCase)   → false + "已存在同名×× [x]，请更换名称"   ← 查重排除自身
⑤ 通过                 → 写入 + true
```

两条容易写错的地方，都有断言钉住：

- **③ 必须在 ④ 之前**：否则"原样确认改名"会被自己撞成重名，用户看到"已存在同名图层 [底图]"——而那个"别的图层"就是它自己。
- **④ 用 `!ReferenceEquals(l, layer)` 排除自身**：所以 `Alarm → ALARM` 这种"只改大小写"是放行的（`OrdinalIgnoreCase` 查重不排除自身的话，这类改名永远改不动）。
- **② 的"原地放置/原值幂等"是早退型放行**：`return true` 且什么都不动 ⇒ **不刷 `Version`**。断言据此区分"真变更"与"假变更"。

`TryMoveLayer/TryMovePage` 的越界下标按两端 `Math.Clamp` 夹取而非报错：拖到列表末尾之外是常见手势。

### 决策七：可见/可编辑的**唯一口径**在 `ScadaPage`

```csharp
public bool IsElementEditable(ScadaElement? e)
    => e != null && !e.IsLocked && ResolveLayer(e)?.IsLocked != true;   // 或关系
public bool IsElementVisible(ScadaElement? e)
    => e != null && ResolveLayer(e)?.IsVisible != false;
```

画布、属性面板、工具箱落点三处**都调这两个方法**，一处都不自己写 `!element.IsLocked`
（[ScadaCanvas.cs](file:///e:/VM/VisionMaster-W-master/Scada.Controls/Canvas/ScadaCanvas.cs#L871-L875) 里明确写了"判定权整个交给 ScadaPage"）。
两处规则迟早不一致，症状是"面板里显示可编辑、画布上拖不动"。

两条语义要点：图层锁定与图元锁定是**或**关系（任一处锁即不可编辑，两层锁互不覆盖）；
隐藏图层**既挡显示也挡命中**（隐藏是为了看清下面，留一个"看不见但会挡住鼠标"的图层比不隐藏更糟）。

### 决策八：隐藏 = 置 `Collapsed`，**不摘控件**

元素层永远是 `ItemsSource` 的**全量同步视图**（`RenderedElementCount == 数据条数`）。
代价：隐藏层的控件仍占可视树。收益两条：

1. 那套 `Add/Remove/Move/Reset` 的同步逻辑不必长出一个"过滤"例外分支（一有例外就有"数据变了但视图没跟上"的第三种状态）；
2. **"图层一开，图元立刻回来"** —— 万级图元下"隐藏再显示"若走重建，是一次几百毫秒的白等。

配套两个小判断：`IsLocked` / `Name` 变更**不**触发重算（锁定是鼠标事件发生时现算的，改名不影响渲染 ——
"没什么要预备的，就不挂没什么要重算的订阅，少一条通路少一处漏"）；
未知类型的占位框也听图层的话（否则隐藏层上会留下一块谁也不认识的灰框）。

### 决策九：选中项所在的图层一关 → 顺手取消选中

`ApplyLayerVisibility()` 第一件事就是这个。理由很硬：**现在没有撤销**，
一个"看不见、却能被 Delete 掉"的选中项是找不回来的坑。
同时约束住不误伤：关的是别的图层时选中不受牵连（断言分别钉了两头）。

### 决策十：新建画面自带一层；新图元默认归首层

`AddPage` 内部 `page.AddLayer()` **在 `_pages.Add(page)` 之前** —— 让订阅者看到的画面永远是"完整"的
（若先入集合，界面瞬间绑上一个零图层画面，图层面板就得处理畸形状态）。

`ScadaEditorViewModel.AddElement` 里 `element.LayerId = page.DefaultLayer?.LayerId ?? Guid.Empty`：
不给它归属的话它就是个"未分层"图元 —— 图层面板里谁都装不下它，用户关掉唯一的图层却发现画面上的东西一个没少，
只会判定成"开关坏了"。"未分层"这个取值留给脏数据与手工取消分层，**不该是新内容的默认状态**。

### 决策十一：序列化三件套 + 加载期补齐（`CurrentSchemaVersion` 仍是 1）

`Layers` / `Elements` 两个集合属性各自都要凑齐三件，缺一条就有静默失效：

| 措施 | 不做的后果 |
|---|---|
| `[JsonProperty(ObjectCreationHandling = Replace)]` | Newtonsoft 默认往现有集合里 `Add`，setter 里的"摘旧挂新"根本不执行 |
| 带 setter 的**摘干净 + 挂上新**（含 `_subscribedLayers` 登记表） | 反序列化进来的图层开关永远不冒泡 ⇒ **隐藏了一个图层却不提示保存** |
| `[JsonConstructor]` 无参构造里挂初始集合订阅 | 字段初始化器造出来的空集合没人订阅，第一条 `AddLayer` 不脏 |

版本策略不变：**新增字段全靠反序列化默认值 + `EnsureIdentity()` 补齐**，不推进 `SchemaVersion`
（[ScadaDocument.cs](file:///e:/VM/VisionMaster-W-master/Scada/Models/ScadaDocument.cs#L28-L33)）。
所以 `LoadAsync` 里那句早已存在的 `solution.Scada.EnsureIdentity()` 就是本阶段全部的兼容代码 ——
**产品侧没为新字段写过一行迁移逻辑**，旧文件靠补齐路径自然兼容。

### 决策十二：画布的图层订阅按**登记表**摘挂

`_subscribedLayers`（`HashSet`）+ `HookLayer/DetachLayers`，`Reset`（`Clear()`/整体换集合）走全量摘挂。
`Add` 返回 `false` 就是"已订阅过"，一行挡住重复挂。
不做登记表的话，症状是"画布被一份不属于它（甚至已经不属于任何画面）的旧数据钉住"：
图层整表清空后，旧图层的开关还在刷 Version、还在驱动可见性 —— 两头都有断言。

`Layers` 集合实例被整体替换这一条路径上，回调里**拿不到旧集合**（`page.Layers` 已经是新的）；
不纠结：旧集合此刻只被它自己那条挂到本画布的委托引用，两者一起不可达、一起回收。
真要接"原地换集合"的场景，正确做法是让 `ScadaPage` 把旧集合一并告知（自定义事件参数），而不是在这里猜。

## 三、新增 public API

### `ScadaPage`（图层）

| 成员 | 语义 |
|---|---|
| `DefaultLayer` | 列表第一项；一个图层也没有时 `null`（`[JsonIgnore]`） |
| `FindLayer(Guid)` / `ResolveLayer(ScadaElement)` | 按 Id 找 / 解析图元归属；未分层与悬空都返回 `null`（重复身份取靠前者，与 `FindElement` 同口径） |
| `CountElements(ScadaLayer)` / `CanRemoveLayer(ScadaLayer)` | 层上图元数 / 能否删（空且不是最后一层） |
| `AddLayer(string? name = null)` | 追加到末尾；空名按「图层_N」（N 取未占用的最小序号） |
| `TryRenameLayer / TryRemoveLayer / TryMoveLayer / TryAssignLayer` | `bool + out string error`，判定见决策六；`TryAssignLayer(…, null, …)` = 取消分层归属 |
| `IsElementEditable / IsElementVisible` | 图元可否编辑 / 该不该显示（**唯一口径**） |

### `ScadaDocument`（画面）

| 成员 | 语义 |
|---|---|
| `FindPage(Guid)` / `FindPageByName(string)` | 优先按 Id；按名只用于兼容旧数据与用户手输（大小写不敏感） |
| `AddPage(string? name = null)` | 自动命名 + **自带默认图层** |
| `TryRenamePage / TryRemovePage / TryMovePage` | 与图层侧逐条同构（差异见决策五） |

### 运行结果

```
dotnet build ScadaChecks\ScadaChecks.csproj   →  0 个错误（仅剩 1 条与本阶段无关的 HslCommunication 引用告警）
ScadaChecks.exe                               →  通过: 397  失败: 0   >>> 全部断言通过 <<<
ScadaChecks.exe --stress                      →  通过: 414  失败: 0   >>> 全部断言通过 <<<
```

基线演进：`305 → 381`（`[V]` 76 条）`→ 397`（`[O]` 图层落盘 16 条）。

### 过程中踩到的事（五条全是断言自己的错 —— 记下来免得重犯）

1. **`out var` 写在 `&&` 链里，短路时未赋值 ⇒ 6 个 `CS0165`。**
   `Check(expr, $@"…", detail)` 的 detail 实参读了链里 `out var x` 声明的变量，编译器判定"可能没赋值"。
   → 修法统一：**`string a = "", b = "";` 预声明 + 调用处写 `out a`**。这是本项目断言写法的一个固定陷阱。
2. **回归 exe 的 TFM 是 `net9.0-windows`，不是 `net48`。** 按 `bin\Debug\net48\` 跑直接 `CommandNotFoundException`。
3. **`AddPage` 自带 `图层_1`**，再 `AddLayer("底图")/AddLayer("报警")` 是 **3 层**，第一版按 4 层写 ⇒ 断言必红。
   凡"新建对象自带什么"的口径要先看模型，别按直觉数。
4. **断言与自己的 fixture 矛盾**：fixture 只设 `layerBase.IsLocked = true`，断言却写了 `!rBase.IsVisible`。
   detail 打出 `底图 locked=True visible=True` —— **产品行为完全正确，错的是断言**。
   → 凡是"往返后两个开关各自如何"的断言，必须回看 fixture 到底动了哪一个。
5. **手写 legacy JSON 少一个根收尾 `}`** ⇒ `LoadAsync` 报
   `Unexpected end when deserializing object. Path 'Scada'`；紧跟着断言里用 `opage!` 解引用 null，
   把整个回归进程以 `0xC0000005` 崩掉，`[P]`–`[V]` 全没跑、连总数都没输出。
   → 两条纪律：**(a) 断言里凡可能为 null 的对象一律 null-safe，并把失败原因（如 `load.Message`）塞进 detail；
   (b) 手写 JSON 的括号平衡不要靠肉眼，直接 `JObject.Parse` 一次当自检。**
   单条断言把进程打崩，掩盖的是后面所有节的结果 —— 这比它本身报红严重得多。

## 五、已知边界

| 边界 | 说明 / 影响 |
|---|---|
| **图层面板 UI 未做** | 本阶段交付的是**能力**（模型 + 判定 + 画布生效 + 落盘）。界面上还看不到图层列表，`TryAssignLayer` 暂时没有入口。属 S3-e3+ |
| **运行期未目视验证（P0）** | 断言是 headless 的。下次启动主程序必须肉眼确认：画布 `Page` 绑定生效（顶栏改画面时图层规则跟着换）、新建画面后图层下拉/列表不空、拖放新图元后关掉唯一图层东西确实消失、删除画面弹确认框且报数 |
| **无撤销** | 所有 `Try*` 直接改模型。撤销应属统一命令层，现在给图层单独做一套会与拖放/属性面板做成两套语义 |
| **单选** | `SelectedElement` 只有一个，"多选 → 批量换层"未做 |
| **`RenderedElementCount` 含占位框与 `Collapsed`** | 它的定义是"元素层 `Children.Count`"，比 `OfType<ScadaElementBase>()` 多一个选中占位 `Border`。读 detail 数字时别当成对不上 |
| **隐藏层的控件仍在可视树** | 决策八的代价。极端场景（隐藏 90% 的万级图元仍占内存）将来要优化，落点是"隐藏层整体挂一个 `Collapsed` 的容器"而不是逐控件摘除 |
| **悬空 `LayerId` 不清理、不报错** | 决策四。用户手工改过的 .vms 里留悬空 Id，画面照开、图元照显示，只是不受任何图层约束。没有"一键归位"工具 |
| **图层次序不影响渲染深度** | 决策三。若产品侧将来要求"上移图层 = 整层抬到最上"，要改的是渲染侧复合键，不是给 `ScadaLayer` 加 `ZIndex` |
| **`EnsureIdentity` 不给绑定补 `Id`** | 只做身份/归属两件事，绑定自愈仍在 `[M]/[P]` 那条路上。别指望它顺手修别的旧数据 |
| **画面级属性区与「定位」仍在编辑器顶栏** | S3-d 记录里推到本阶段的那条：画面宽/高/底色/网格/吸附由 `SelectedPage.*` 直绑承载，**没有**搬进属性面板。要搬的话得先决定"图层属性面板"长什么样 |
| **旧布局回退一次** | 与 S3-d 同：既有 `Layout.xml` 与出厂快照的面板校验策略不变，本阶段未新增面板，不受影响 |

### 与旧遗留项的关系

- **P3（其它面板 VM 同类订阅泄漏）**：本阶段在 `ScadaCanvas` / `ScadaPage` 两侧都用同一套「登记表 + `Add/Remove` 返回值短路」写法，并各有"清空后不再驱动"的断言。这套样板可以直接搬到 `FlatPropertyGrid` 与旧面板 VM。
- **P4（`FitToScreen` 注释与代码不符）**：仍未修，与本阶段无关。
