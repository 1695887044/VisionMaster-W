# 手眼标定：上次结论持久化（数据指纹 + 过期态）

> 日期：2026-10-23 ｜ 范围：`Plugins/Plugin.HandEye/`（插件 + 视图 + 手册）、`FlowCanvasChecks/HandEyeChecks.cs`、`docs/UI设计基线/hand-eye/` ｜ 状态：已落地，`FlowCanvasChecks` 3362 / 0

## 1. 背景

用户问了两句：

1. 「现在结果重新打开方案会丢失吗」
2. 「值得做,现场不会每次都标定的」

第一句先用探针走过宿主真实路径（`OnConfirm` 快照 → JSON 往返 → `ApplyConfigValues` 灌回新实例），实测：`Samples`（成对数据）、装法、两个门槛、组数门**都会回来**；但**面板上的求解结果不落盘**，重开是「未求解」，要再点一次求解。

现场不会每次都标定（机器人可能一天不动），每次打开方案都要重算一遍没有意义；而"重算"在多机台环境里还得连机器人。所以做**结果持久化**。

关键取舍：**存的不是一串裸结果，而是「数据指纹 + 结果」**。指纹对得上才认这份结论；对不上就转「已过期」，并且**不显示那 16 个数** —— 旧矩阵已经不对应当前数据，摆出来就是在骗人。

## 3. 关键决策

1. **只存「指纹 + 结果」，不存裸结果**。只存结果 → 数据一改就成了假绿（显示"完成"但其实算的是旧数据）；只存指纹不存结果 → 每次重开都要重算，正是要解决的问题。两者必须成对。
2. **指纹用 `R` 格式，不用 `F3`**。`F3` 会把 `0.0004` 与 `0.0001` 认成同一个数 → "改了数据但结论没作废"。`SHA256` 取前 8 字节 = 16 字符，够用且能塞进 JSON 不显眼。
3. **只在 `OnConfirm` 写，非「完成」态一律清空**。求解只是"看一眼"，落盘跟其它配置一样必须走「确定」；失败态点确定会把 `SavedResult` 清空 —— 方案里绝不留与当前数据不匹配的旧矩阵。
4. **过期态 ≠ 未求解**。写「未求解」会让人以为从没标定过，跑去重标一次；写「已过期」明确告知"标过、但作废了"，并给出唯一合法动作（重新求解）。
5. **补掉一个真缺陷：单元格编辑不作废结论**。12 个分量各走 `SetProperty` 发 `PropertyChanged`，但原先只订阅了 `CollectionChanged`（增删行）→ 改一个数字，屏上矩阵仍以「完成」态挂着。现在逐行订阅，`HookAllRows` 在 `Samples` setter 与 `Reset` 时重建。
6. **`ApplyConfigValues` 之后必须克隆集合**（本轮实跑抓到的）：`VisionPluginBase.ApplyConfigValues` 只对**标量**做值拷贝，集合走 `ValueConverter.Convert` 是**原引用** —— 不克隆的话，界面上改一个数字会同时改掉方案 `InputValues` 里存的那份：点「取消」也留下了改动，且下次比对指纹自然对不上。
