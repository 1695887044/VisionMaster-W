# 流程可调用性视觉标识（2026-10-22）

## 背景

多工位连续生产评审确认：工位流程需要“启用 + 子程序”才能被 Main 的「调用流程」拉起，但一旦启用，工具栏「循环运行」也会把它当顶层流程启动。评审建议先按 `Role=Main` 做批量运行过滤，并在界面上把“可直接拉起”和“只能被主流程调用”区分开。

本次先落**视觉层**：不改运行入口，只让流程列表/流程管理一眼看出每条流程的调用关系。

## 视觉口径

| 徽标 | 适用 | 含义 |
| --- | --- | --- |
| 绿色「主」/「主流程 · 可循环」 | `Role=Main` | 主流程；工具栏循环运行的目标（过滤落地后生效） |
| 蓝色「外部」/「外部触发」 | `Role!=Main` 且勾了 定时/变量/HTTP | 可被对应触发源直接拉起 |
| 琥珀「子」/「子程序 · 由主流程调用」 | `Role!=Main`、仅勾子程序、无外部触发 | 只能由其它流程的「调用流程」拉起 |
| 灰色「手动」 | 以上都不满足 | 仅本机界面手动运行 |

优先级：`Main` > `外部触发` > `仅子程序` > `手动`。  
同时勾了 HTTP 和子程序的流程显示「外部」——它确实可以被 HTTP 直接触发，不是“只能被主流程调用”。

## 边界（重要）

**本次只做视觉标识，没有改运行入口。**  
`RunAllEnabledOnce()` / `RunAllEnabledContinuous()` 仍然只判断 `IsEnabled`，会启动所有启用流程。因此：

- 绿色「主」目前表达“主流程 / 循环目标”，不是“点循环只会跑这一条”；
- 要让绿色徽标与实际行为一致，下一步必须落 `Role=Main` 过滤 + 无主流程/多主流程提示；
- 同时还要修 `FlowInvoker` 的停止传播（父流程停止 → 子流程停止），否则多工位急停时工位仍可能在后台收尾。
