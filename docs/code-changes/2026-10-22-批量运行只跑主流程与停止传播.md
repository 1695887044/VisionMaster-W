# 批量运行只跑主流程与停止传播（2026-10-22）

## 背景

多工位连续生产评审确认：工位流程为了能被 Main 的「调用流程」拉起，必须 `IsEnabled=true + 子程序`；而工具栏「循环运行」原先只判断 `IsEnabled`，会把所有启用流程各起一个连续循环。结果就是 Main 与工位并发跑、同一工位可能被跑两遍，严重时回到 7 GB 内存事故。

本次落两件事：

1. 工具栏批量运行只启动 `Role=Main` 的启用流程；
2. 父流程停止/急停时，`FlowInvoker` 停止子流程。

## 改动清单

| 文件 | 改动 |
| --- | --- |
| `Core\FlowBatchSelector.cs` | 新增纯选择器 `FlowBatchSelector.Select(solution)`；只选 `IsEnabled && Role=Main`；0 条/多条主流程返回空选择 + 明确提示；被排除的启用流程单独返回用于提示 |
| `VisionMaster\ShellViewModel.cs` | `RunAllEnabledOnce()` / `RunAllEnabledContinuous()` 改走选择器；0 条主流程拒绝；多条拒绝；被排除的启用流程给一条 Info；连续运行只在 `session.IsRunning` 为真时计数 |
| `VisionMaster\Shell.xaml` | 工具栏文案「运行一次/循环运行」→「运行主流程/循环主流程」；ToolTip 说明工位/子流程不参与批量启动 |
| `Engine\FlowInvoker.cs` | 父流程取消分支：`_engine.StopSession(session)` → `ObserveFault` → 最多等 2 s 收尾 → 返回“已请求停止目标” |
| `FlowCanvasChecks\FlowBatchSelectionChecks.cs` | 新增 E20-1~E20-8：选择器 6 条 + Shell 静态扫描 + FlowInvoker 静态扫描 |
| `FlowCanvasChecks\FlowEngineFixChecks.cs` | 在 `Run()` 末尾注册 `FlowBatchSelectionChecks.Run()` |

## 行为口径

| 场景 | 行为 |
| --- | --- |
| 1 条启用的 Main | 工具栏只启动 Main |
| Main + 启用工位流程 | 只启动 Main；工位流程给 Info 提示“不参与批量运行（非主流程）” |
| Main + Home/End 启用 | 只启动 Main；Home/End 不参与 |
| 没有启用的 Main | 拒绝启动，提示“请启用主流程，或把要运行的流程设为主流程” |
| 多条 Main | 拒绝启动，列出所有主流程名，要求只保留一条 |
| Main 被禁用 | 视为“没有启用的主流程”，拒绝 |
| 工位流程（Role=None + 子程序） | 可继续被 Main 的「调用流程」拉起；工具栏不会启动它 |
| 工位流程同时勾 HTTP/定时/变量 | 仍可被对应外部触发源启动；`Role` 过滤只管工具栏批量，不管这些入口 |
| 流程列表单流程运行 | 不受影响（`FlowListViewModel.RunSingleFlowAsync` 仍按选中流程启动） |
| SCADA `StartFlow` / `RunFlowOnce` | 不受影响（显式指定流程） |
| 父流程停止/急停 | `StopSession` 子流程；最多等 2 s 收尾；返回“已请求停止目标” |
| 子流程超时 | 保持原契约：不打断，目标继续；产线需要“超时也停”时应另加 `StopOnTimeout` |

## 兼容性与迁移

- **老方案 Main 未启用**：工具栏不再“退化成跑所有启用流程”，而是拒绝并提示。这是有意的安全变更，避免静默并发。
- **老方案有多条 Role=Main**：拒绝并列出名字；`MandatoryFlows.Ensure` 只保证“至少一条”，不保证唯一。
- **老方案只有 None 流程在工作**：需要把其中一条设为主流程（或启用 Main），否则工具栏不跑。
- `.vms` 不需要结构迁移；`Role` 字段早已存在。
- `FlowInvoker` 的超时分支没有改：超时仍不打断子流程；本次只改“父流程取消”。

[√通过] E20-4 Home/End 即使启用也不参与批量运行

## 边界

- 本改动解决“工具栏不再误启动工位流程”，**不自动让 Main 调用工位**；Main 里必须显式写「调用流程」步骤。
- 多线并发仍需要 `LineSupervisor`（或后续 `RunInBatch`）；当前只支持一条启用的主流程。
- `RunFlow` 仍未标 `[ParallelSafe]`，不能直接放进 `Parallel` 分支。
- 运动/通讯/相机没有资源锁；顺序 Main 仍是多工位共享硬件时最稳的编排。
