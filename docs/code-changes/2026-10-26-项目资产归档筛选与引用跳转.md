## 已做

### 1. 生命周期筛选

- `ProjectAssetsViewModel.LifecycleFilter`（全部 / 有效 / 待处理 / 已归档）+ `SelectLifecycleCommand`。
- **再点同一个桶 = 取消筛选**（比"必须点全部"少一步）。
- 筛选与计数**共用同一份归桶判据** `LifecycleGroupOf`：
  `有效/派生/内嵌 → 有效`、`待复核/待学习 → 待处理`、`已归档 → 已归档`。
  之前计数用一串内联 `||`，筛选用字符串相等——两边一旦分叉就会出现
  "点『待处理』筛出 0 条、而计数写着 3"。
- `清除筛选` 现在同时复位搜索 / 相机 / 标签 / 生命周期。
- 左侧加一行「当前筛选：X」，避免"列表变少了不知道为什么"。
- 三个按钮改用 `FilterButtonStyle`（与"资产类型"列表同一套）：
  用 `DialogGhostButton` 时内容模板不拉伸，标签和计数会挤在右边。

### 2. 引用跳转

- `AssetReference` 增加 `FlowName` / `StepName`（原始名，不是显示用的友好名）+ `CanNavigate`。
- `GoToReferenceCommand`：
  - 按原始流程名找 `FlowModel`，按步骤名递归找 `StepModel`（**容器分支里的步骤也能找到**，走 `IContainerStep.Children`）；
  - 切流程 + 选中步骤，然后请求关闭弹窗（不关的话用户看不到刚选中的步骤）；
  - 找不到时说清是"流程不存在"还是"流程里没有这个步骤"，不静默。
- VM 只持有 `IReadOnlyWorkspaceContext`（断言宿主也用它），切流程要走 `IWorkspaceManager`；
  运行期用 `is IWorkspaceManager` 判型，没有可写工作区时明确报错。
- 引用卡改成 `Button`（`Command` 走 `AncestorType=ItemsControl` 的 `DataContext.GoToReferenceCommand`），
  `IsEnabled` 绑 `CanNavigate`，非步骤引用（如"方案内静态"）不可点。
- 底部提示从"引用索引当前尚未落地"改成真实说明。

## 踩过的坑

1. **`Run.Text` 默认 TwoWay**（R159）：`<Run Text="{Binding LifecycleFilter}" />` 绑只读属性会在
   XAML 加载期抛 `InvalidOperationException`，整个弹窗起不来。必须显式 `Mode=OneWay`。
2. **`DialogGhostButton` 的模板不拉伸内容**：即使写了 `HorizontalContentAlignment="Stretch"`，
   Grid 的第二列（星号）也会塌成 0，标签与计数挤在右边。改用 `FilterButtonStyle`。
3. **`DialogCloseListener` 不是委托**：它是 Prism 里带 internal 构造的类，断言里只能反射造
   （与 `RecipeChecks.MakeDialogCloseListener` 同一手法）。
4. **用户开着 VisionMaster 时无法构建**：`Modules\*.dll` 被运行中的进程锁住，
   插件工程投递失败（MSB3021/MSB3027）。不杀用户进程，等它关闭；期间可用
   `-p:OutputPath=<临时目录>` 做纯编译检查。
