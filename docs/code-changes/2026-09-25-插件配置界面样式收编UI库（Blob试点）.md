# 2026-09-25 插件配置界面样式收编 UI 库（L1，Blob 试点）

> 需求原文：*"现在我明明有个 UI 库，为什么 Blob 插件的界面还要自己写样式，不能写在 UI 库作为公共调用项目吗"*
> 追加要求：*"要规范化，把所有硬编码都使用资源，后续可以变更主题"*

---

## 1. 为什么要做（现状数据，全部来自全仓检索）

| 事实 | 数据 |
| --- | --- |
| `CardBorder` 定义份数 | **15 份**（14 个插件 + 宿主 `ConditionEditorView.xaml`） |
| `CardTitle/HintText/FieldLabel/NumericBox` | 每个插件 2~4 份，合计约 **70 份重复定义** |
| UI 库已有的对应物 | `Win11Card`（`UI/Controls/Themes/DefaultStyle.xaml:876`） |
| 插件对 UI 库已有资产的引用 | **0**（`Win11Card`/`AccentBrush`/`TextPrimaryBrush`/`ControlBorderBrush` 全零引用） |
| 宿主是否已合并 UI 资源 | **是**，`App.xaml:67` 已全局合并 `UI;component/Themes/Generic.xaml` |

而且**已经漂移**：UI 库的 `Win11Card` 是 圆角 6 / Padding 16 / 阴影 0.04 / `#D1D1D1`，
插件抄的那份是 圆角 8 / Padding 14 / 阴影 0.05 / `#E5E5E5`。同一个"卡片"概念两套参数。
这就是"复制式复用"的代价：想统一调一次色要改 15 个地方，还得先判断哪些"看着像其实不是同一个"。

`Colors.xaml` 里 SCADA 那节已经沉淀了一套**令牌 + 前缀 + 按用途命名**的规范（注释里明确写着
"将来要换肤（深色主题）时，改的是这里的值"），本轮沿用同一套范式做 `Plugin*` 系列。

## 2. 方案：分两本字典，主题可变与结构分离

| 文件 | 职责 |
| --- | --- |
| `UI/Controls/Themes/PluginConfigColors.xaml`（新增） | **主题可变部分**：画笔、颜色、尺寸、间距、列宽、字体。换主题只换这一本 |
| `UI/Controls/Themes/PluginConfigStyles.xaml`（新增） | **结构**：5+2 个 Style，只引用上面的键，不含任何具体数值 |
| `UI/Controls/Themes/Generic.xaml`（修改） | 合并这两本（Colors 在前） |

### 命名规则（沿用 SCADA 那节的三条）

1. **一律带 `Plugin` 前缀** —— 不带前缀会和宿主/组态那边撞名，撞名的后果是"改令牌改不动那一处"
   （局部覆盖优先于全局）；
2. **按"用在哪"命名，不按"是什么颜色"** —— `PluginHintTextBrush` 是"提示文字"，不是"某个灰"；
3. **值全部照抄改造前插件里的原值，不做顺手美化** —— 收编阶段的唯一目标是"行为不变、真相归一"。

### 收录的键

```
容器    PluginSurfaceBrush / PluginCardBorderBrush / PluginSubtleBackgroundBrush / PluginDividerBrush / PluginCardShadowColor
文字    PluginTitleTextBrush / PluginLabelTextBrush / PluginHintTextBrush
语义    PluginOkBrush / PluginWarningBrush / PluginErrorBrush
图表    PluginChart{Fill,Stroke,Band,Marker,Grid,Placeholder}Brush + 两个线宽 + PluginFontFamily
尺寸    PluginCardCornerRadius / PluginCardPadding / 两个小圆角 / 三种 Margin / 三种字号 / 控件高 / 阴影三参数
布局    PluginViewMin{Width,Height} / PluginParamsColumnWidth(GridLength) / PluginEditorColumnWidth(GridLength) /
        PluginParamsColumnMinWidth / PluginPreviewColumnMinWidth / PluginHistogramHeight
样式    PluginCard / PluginCardTitle / PluginFieldLabel / PluginHintText / PluginNumericBox / PluginParamRow / PluginStatusPanel
```

`PluginNumericBox` 含 `Validation.ErrorTemplate` + `Validation.HasError` 的中文 ToolTip 触发器
（校验跑在"字符串写回绑定源"之前，非法输入根本进不了 ViewModel——这条语义一并收编进注释）。

## 3. Blob 插件的改造（试点）

`Plugins/Plugin.BlobDetect/BlobDetectView.xaml`

- **删除**本地 5 个样式定义（`CardBorder`/`CardTitle`/`HintText`/`FieldLabel`/`NumericBox`）；
- **全部硬编码 → 资源**：`#FFFFFF`/`#E5E5E5`/`#1F1F1F`/`#888888`/`#444444`/`#F8F8F8`/`#EEEEEE`/
  `#0A7`/`#E6A23C`/`#F56C6C` 一个不留；圆角、内边距、行距、字号、控件高、列宽、直方图高度全部令牌化；
- 文案里的颜色词也改掉（"橙色区间 = 当前固定阈值" → "标记区间 = 当前固定阈值"，否则换主题后文案说谎）；
- 只保留两个与主题无关的本地转换器（`EnumDisplayNameConverter`、`BooleanToVisibilityConverter`）。

检索确认：改造后 `BlobDetectView.xaml` 里 **`#` 颜色字面量为 0**（只剩 `d:DesignHeight/Width`
这两个设计时元数据，不参与运行时，故保留）。

`Plugins/Plugin.BlobDetect/HistogramPlot.cs`

C# 里自绘的 6 支画笔原本也是硬编码。改为**先查资源、查不到再退回内置值**：

```csharp
// 为什么必须带回退值：本控件可能被实例化在"没有 Application / 没合并 UI 资源"的环境里
// （冒烟断言、离线跑流程）。主题缺失可以丑，但绝不能让直方图渲染不出来。
_fillBrush = LookupBrush("PluginChartFillBrush", FallbackFillBrush);
```

解析结果缓存在实例上（`EnsureResources()` 首次调用时解析一次），避免 `OnRender` 每次查资源树。

## 4. 踩到并修掉的三个 WPF 坑（都是实测，不是推断）

| # | 坑 | 现象 | 修法 |
| --- | --- | --- | --- |
| 1 | **根元素属性用 `StaticResource`** | `XamlParseException`：解析根元素属性那一刻，自身 `Resources` 还没合并进来 | `MinWidth/MinHeight` 改用 `DynamicResource`；子元素照常用 `StaticResource` |
| 2 | **`ColumnDefinition.Width` 要 `GridLength`** | "设置属性 Width 时引发了异常" | 列宽令牌声明成 `GridLength`，不能是 `sys:Double` |
| 3 | **合并字典内部的 `StaticResource` 不横向查找** | `无法找到名为“PluginCardShadowBlur”的资源` | `PluginConfigStyles.xaml` 自己再合并一次 `PluginConfigColors.xaml` |

第 3 条最反直觉：`Generic.xaml` 里虽然同时合并了 Colors 与 Styles，但 Styles 内部的
`StaticResource` 只在"自己 + 自己的 MergedDictionaries"里找，不会去看 Generic 的其它合并项。

### 5.3 固化成冒烟断言（`FlowCanvasChecks/BlobDetectChecks.cs`，纯静态）

```
---- [Blob] 视图样式收编契约（UI 库 Plugin* 令牌） ----
  [√通过] 【收编】插件视图里已无硬编码颜色（颜色一律走令牌）
  [√通过] 【收编】插件视图不再本地定义 CardBorder/CardTitle/HintText/FieldLabel/NumericBox

  [√通过] 【核心】主题令牌（颜色/尺寸）全部在 UI 库里（换主题只改这一本）
  [√通过] 【核心】Plugin* 公共样式全部在 UI 库里
  [√通过] 【核心】插件视图引用的每个 Plugin* 键都有定义（运行期报'找不到资源'就是这条没守住）  →  共引用 23 个键

```

**为什么是静态扫描而不是实例化视图**：`StaticResource` 是运行时查找，编译期查不出键名拼错——
这点必须守护；但实例化要 `Application`，副作用太大。静态比对"用到的键 vs 定义的键"
正好等价于运行期那句"找不到资源"，且快、无副作用。

## 7. 已知边界与后续

1. **`d:DesignHeight/Width` 仍是字面量** —— 设计时元数据，不参与运行时，资源化反而会让设计器解析失败。
2. **`HistogramPlot` 的绘图常量未令牌化** —— 内边距 `pad=1`、占位文字偏移 `8` 属于几何常量不是主题属性。
3. **`AnnotationRenderer` 的 HALCON 颜色名（`"red"/"green"/"white"`）未动** —— 那是 HALCON 调色板名，
   不走 WPF 资源体系；将来真要跟随主题，需要另做"WPF 刷 → HALCON 颜色名"的映射。
4. **`Win11Card` 未动** —— 宿主对话框在用。现在插件卡片（`PluginCard`，8/14/0.05）与它（6/16/0.04）
   仍是两套值，但各自稳定、各自只有一份真相；是否合并成一个，属于独立的视觉统一决策。
5. **其余 13 个插件尚未切换** —— 建议按每批 2~3 个推进，每批跑一次冒烟 + 打开配置界面目视。
   切换时只需把本地 `Style="{StaticResource CardBorder}"` 换成 `PluginCard` 并删掉本地定义。
6. **L2（参数行控件）待立项** —— UI 库的 `BindableParamBox` 与插件在用的 `Core.Controls.LinkableValueEditor`
   职责高度重叠，先确认再收口，别长出第三个。
7. **`ScriptTemplates.cs:238` 的 `'elongation'` 仍是错的**（本版本 HALCON 报 #3101），建议单开一项修。
