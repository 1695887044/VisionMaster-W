# 批量设置流程显示窗口（需求梳理，2026-10-27）

> 影响面为 grep/read 结论，非索引结论（本会话无 CodeGraph 工具，R28）。

## 一、当前状态

需求原话：**"对于单个流程，可以批量设置流程下所有带显示图像窗口属性的插件的值。"**

落成一句话：给"某一条流程"加一个流程级批量操作——把这条流程里**所有带"显示窗口"设置的插件步骤**的窗口号一次性改成同一个值（0 = 不发布，1~9 = 主界面第 N 格画布），不用逐个双击打开参数面板改。

现状是**只能逐个改**：流程栏双击步骤 / 右键「参数设置」→ 插件参数面板 → 找「显示窗口」一行 → 改 → 确定。一条流程里有 5~10 个出图插件时，改一轮窗口分配要点十几次。

## 二、已做（代码取证）

### 1. "流程下所有插件" = 递归遍历整棵树

- `FlowModel.Steps` 是 `ObservableCollection<StepModel>`（`Core/Models/FlowModel.cs:389`）。
- 容器（If/ElseIf/Else、While、For、Case、Parallel）实现 `IContainerStep.Children`（`Core/Models/ProcessStep/IContainerStep.cs:14`），子步骤在 `StepCollection.Steps`（`Core/Models/ProcessStep/StepCollection.cs:39`）。
- 现成的递归口径有多份可参考：`StepFactory.CountStepsDeep`（`VisionMaster/Services/StepFactory.cs:165`）、`FlowModel.CollectSubscriptions`（`Core/Models/FlowModel.cs:500`）、`RecipeService.EnumerateSteps`（`VisionMaster/Services/RecipeService.cs:1701`）。
- **只认 `ActionStep`**：`ConditionStep/ForStep/WhileStep/WaitStep/ParallelStep` 是容器或控制节点，没有插件显示窗口；`BuiltIn_*` 类型（Wait/Break/Continue）也不是插件。

### 2. "显示窗口"在代码里就是 `DisplayViewIndex`（int）

语义统一：**0 = 不发布；1~9 = 主界面第 N 格画布**（`eViewMode` 共 9 档，`Core/Enums.cs:29`）。运行时消费端一律按 `ViewIndex == 窗口号` 等值筛选（`VisionMaster/Views/ImageView.xaml.cs:23`）。

全仓共 **15 个插件**有它，分两种声明形态：

| 形态 | 数量 | 插件 |
|---|---|---|
| `[StepConfig] int` 属性 | 13 | BlobDetect、BeadInspect、ColorCheck、ColorRegion、CreateRoi、DeformableMatching、DlAnomaly、DlSegment、ImageAcquisition、ImageDiff、Matching、PreProcessing、ResultDisplay |
| `InputPort<int>` 端口 | 2 | GeometryFinder、GeometryRelation |

端口形态的两个**可被变量/上游链接**（`DisplayViewIndex` 是"值"类端口，R33 允许挂绑定）；链接后固定值失效，运行时以链接值为准。

另有 **2 个脚本插件是列表形态**，不是单一属性：

- `Plugin.ImageScript`：每个输出变量一行「窗口N」下拉（`Plugins/Plugin.ImageScript/ScriptVarDef.cs:64` 的 `DisplayWindow`，运行时逐变量推送 `ImageScriptPlugin.cs:1106`）；
- `Plugin.CSharpScript`：同上（`Plugins/Plugin.CSharpScript/ScriptVarDef.cs:115`），且脚本里还能 `Context.ShowImage(img, viewIndex)` 直接写死窗口号（`ScriptContext.cs:176`）。

### 3. 参数存在哪、批量写怎么写

- 参数落盘在 `StepModel.InputValues`（键 = 端口名 / `[StepConfig]` 属性名）。
- 编译时 `VisionPluginBase.ApplyConfigValues` 把它灌进插件实例（`Shard/Core.Interfaces/VisionPluginBase.cs:329`，调用点 `Engine/FlowCompiler.cs:883`）；链接端口跳过。
- 所以"批量设置"的正确写法就是给每个目标步骤 `step.SetInputValue("DisplayViewIndex", value)`（`StepModel.cs:380`），**与逐个打开参数窗点「确定」等价**（`OnConfirm` 也是写 `InputValues`，`VisionPluginBase.cs:378`）。
- `SetInputValue` 会发 `PropertyChanged(InputValues)` → `FlowModel.OnStepPropertyChanged` → `Version++`（`FlowModel.cs:588`）→ 下一轮运行自动重编译。**不需要碰运行中的插件实例。**

### 4. 识别"这一步有没有显示窗口"的现成口径

- `ImageCollectionService.ReadDisplayViewIndex(plugin)`（`VisionMaster/Services/ImageCollectionService.cs:714`，私有）已经处理了"两种声明形态"的读取，注释里写明这是 R84 同类坑的统一口径；
- `RecipeService.TryResolveSchema`（`RecipeService.cs:1558`）用 `Activator.CreateInstance` + `plugin.Inputs` + `GetConfigProperties()` 枚举一个步骤的完整参数面（端口 + `[StepConfig]`），是"这个步骤能配哪些参数"的权威口径；
- 更轻的替代：**不实例化**，直接反射 `Type.GetType(step.PluginTypeName)` 上的 `DisplayViewIndex` 属性（int 或 `InputPort<int>`）。插件构造器按 R82 要求无副作用，实例化也是安全的，但反射更省。

### 5. 运行锁与权限

- `EditGate`（`VisionMaster/Services/EditGate.cs`）把编辑动作分三类：结构编辑 / 模块参数 / 断点。**参数编辑归 `ModuleParameters`：运行中拦截、暂停中放行**；新增编辑入口必须先归入 `ModuleEditAction`（文件注释明确要求）。
- 流程级动作统一走 `FlowCommand` + `ScadaPermissionGate.PermissionFor(action)`（`FlowListViewModel.cs:99`）。

### 6. 没有撤销

画布撤销栈（`CanvasUndoCommands.cs`）只覆盖结构/连线/改序，**参数编辑（含逐个参数弹窗）不进撤销栈**。批量改错只能反手再批量改回去。

### 7. 入口位置

流程栏顶部就是流程列表（`VisionMaster/Views/ProcessView.xaml:300` 嵌 `FlowListView`），流程列表右键的「流程」子菜单已有：添加 / 删除 / 重命名 / 编辑注释 / 禁用 / 编译本流程 / 运行一次 / 循环运行 / 停止，另有「流程管理」「变量事件（方案级）」（`FlowListView.xaml:146-204`，命令参数是 `FlowAction` 枚举，`Core/Enums.cs:269`）。**流程级动作都挂这里**，是批量设置最自然的落点。

## 五、踩过的坑

- **不要把"显示窗口"当成一个新概念**：它已经是 `DisplayViewIndex`，两种声明形态（属性 / 端口）+ 两种脚本形态（列表 / 代码）。按名字找属性会漏掉端口形态，按端口找会漏掉 `[StepConfig]`（R84 同类坑）。
- **不要写运行中的插件实例**：批量设置只写 `InputValues`，靠 `Version++` 在下一轮编译时生效。直接改实例既不可靠（实例会被重编译换掉），也会绕过版本链。
- **"同一个窗口"不等于"都能看到"**：默认每格只留最新一帧，多插件投同一窗口时只有最后一张可见。需求侧必须先确认用户要的是"统一关掉/统一收到一格"还是"依次分配"。
- **批量参数编辑不在撤销栈里**：与逐个参数弹窗一致，不要承诺 Ctrl+Z。
