### HALCON 侧事实（23.05，本机实测，不是照抄文档）

| 项 | 实测/文档结论 |
| --- | --- |
| 学习签名 | `create_aniso_shape_model(Template : NumLevels, AngleStart, AngleExtent, AngleStep, ScaleRMin, ScaleRMax, ScaleRStep, ScaleCMin, ScaleCMax, ScaleCStep, Optimization, Metric, Contrast, MinContrast : ModelID)` |
| 查找签名 | `find_aniso_shape_model(Image : ModelID, AngleStart, AngleExtent, ScaleRMin, ScaleRMax, ScaleCMin, ScaleCMax, MinScore, NumMatches, MaxOverlap, SubPixel, NumLevels, Greediness : Row, Column, Angle, ScaleR, ScaleC, Score)` |
| 范围限制 | 文档只要求 `ScaleRMin > 0`、`ScaleRMax ≥ ScaleRMin`（列同理），**默认 0.9/1.1**、建议值 0.5~1.5；**没有**等比档那种 0.5~2.0 的硬区间。实测 `0.1 ~ 10.0` 可创建 |
| `min == max` | **接受**（与等比档不同，实测 `R 1.0/1.0 + C 1.2/1.2` 创建+查找都正常）。本仓仍按需求撑开 ±0.005 的最小窗口，避免尺度搜索退化成单点 |
| Metric | **`ignore_polarity` 不是合法值**：`create_shape_model` #1306 / `create_scaled_shape_model` #1309 / `create_aniso_shape_model` #1312。合法值 `use_polarity` / `ignore_global_polarity` / `ignore_local_polarity` / `ignore_color_polarity` |
| 模型类型不匹配 | **不报错**：各向异性模型 + `find_scaled` → 0 命中；等比模型 + `find_aniso` → 能命中但 `ScaleR == ScaleC`（静默错结果） |
| 查找范围越界 | 传超出创建范围的行/列范围**不抛**（实测 C 1.05~1.35 对 0.9~1.1 的模型也照跑），但语义未定义 → 本仓学习/查找共用同一份夹取函数，不依赖这个宽容度 |
| 范围不含 1.0 | 参考图在最近尺度上只有 ~0.84 分 → 用 minScore 0.8 自匹配**拿不到结果**（原点锚定会静默失效），故各向异性锚定用 0.5 |
| 模型体积 | 默认 `Optimization='auto'` 不预生成变体：同一模板 `360°` 与 `10°` 的 `.shm` 都是 **67.8 KB**（base64 ≈ 90 KB），create 15~18 ms。范围宽只影响**查找耗时**，不影响载荷 |

## 二、已做

### 1. 数据模型（`Plugins\Plugin.Matching\MatchingTemplateEntry.cs`）

### 2. 学习期（`MatchingPlugin.cs`）

- 分叉顺序：`Ncc` → **`AnisoScaleEnabled`** → `ScaleEnabled` → 其余。各向异性**优先**，走到它就不看等比三个字段。
- 新增 `ResolveAnisoRanges(entry)`：**学习与查找唯一口径**，夹 `0.1~10`、上下限填反自动交换、相等撑开 ±0.005。
- 新增 `MetricName(entry)`：`use_polarity` / **`ignore_global_polarity`**（四个 create 算子都认，含 `create_ncc_model`）。
  ⚠ 这条同时**修掉了既有缺陷**：原代码送 `"ignore_polarity"`，HALCON 23.05 直接报错 →
  以前"忽略极性"这一档一学就失败（见第五节）。
- 原点锚定：新增各向异性分支，`find_aniso_shape_model` 自匹配一次（minScore **0.5**、numMatches 1、
  maxOverlap 0.5、greediness 0.9）再 `set_shape_model_origin`，与等比分支同写法。
- `NCC + 各向异性`：学习仍成功（按 NCC 学），但状态栏转 **Warning** 并写
  "NCC 不支持缩放/各向异性（两者都已忽略）…各向异性缩放只对基于形状的算法有效…"。
- `EntrySignature` 追加 `AnisoScaleEnabled` + 四个范围；学习时写 `LearnedAnisoScaleEnabled`。

### 3. 运行期（`MatchingPlugin.cs`）

- 新分支 `entry.AnisoScaleEnabled` → `find_aniso_shape_model`，输出 `ScaleR` / `ScaleC` 两路。
- 端口：`Scales` 语义保持（等比档 = 统一缩放；**各向异性档 = 行缩放**，描述已写明）；
  新增 `ScalesRow` / `ScalesCol`（`OutputPort<HTuple>`）；等比/未缩放档两者 `??= scales` → 与 `Scales` 逐位相同。
- 轮首清零：新增两个数组端口一并清空。
- **模型类型守卫**：`LearnedAnisoScaleEnabled != (形状 && AnisoScaleEnabled)` → `Logger.Warn`
  "学习时各向异性=X，当前=Y：模型与当前参数不一致，结果可能不准…"（**不判失败**）。
- 失败语义/`MatchCount`/`Rows`/`Columns`/`Angles`/`Scores`/`Fail` 文案**一行未改**。

## 五、踩过的坑

- **`ignore_polarity` 是伪值**：HALCON 23.05 三个 create 算子分别报 `#1306` / `#1309` / `#1312`
  （"Wrong value of control parameter"）。原代码一直在送它 → "忽略极性"这一档以前一学就失败。
  现统一 `MetricName()`，新增 create 分支**必须复用它**。
- **模型类型不匹配是静默的**：各向异性模型 + `find_scaled` = 0 命中；等比模型 + `find_aniso` = 行/列恒相等。
  两个方向都不抛异常 —— 只靠"改了开关没重学"这一条就能让产线拿到错结果，所以加了 `LearnedAnisoScaleEnabled`
  快照 + 运行期 Warn。
- **`zoom_image_factor` 的参数顺序是"宽（列）在前"**：`(Image, Zoomed, ScaleWidth, ScaleHeight, Interp)`。
  写反了变成行向拉伸，断言会"看起来像功能坏了"。`RotateImage` 的角度按**度**解释也是同类坑（已记在旧断言里）。
- **90° 对称的测试图案测不出各向异性**：圆盘+十字在列向拉伸 1.2 下，等比模型也能拿 0.8386 分，
  与各向异性模型几乎一样 → 反向判据失效。换成细竖条梳状图案后拉开到 0.9997 vs 0.7665。
- **范围不含 1.0 时原点锚定会静默失效**：自匹配在最近尺度上只有 ~0.84 分，等比分支的 0.8 阈值拿不到结果；
  各向异性锚定改用 0.5，并在 UI ToolTip / 帮助里写明"范围应包含 1.0"。
- **HALCON 接受 `min == max`**（与等比档源码注释里"会拒绝创建"的说法不同，实测两档都接受）。
  仍按需求撑开 ±0.005：否则尺度搜索退化成单点，读数恒等于该值、下游无法判断"是不是真测到了缩放"。
- **本机控制台是 936 码页**：`dotnet build` 输出重定向后中文全是乱码（"0 个错误"读成"0 涓�閿欒�?"）。
  判据只认 **exit code 0 + `error CS|MSB|NETSDK` 命中 0 条**，不看中文行（R183 同族）。
- **`HOperatorSet.GetSystem("version")` 是 out 参数形式**（探针里写成返回值形式直接 CS7036）——
  写一次性探针时踩的，不影响产品代码。
- 临时探针工程放 `%TEMP%`（`anisoprobe`），**不进仓库**；本轮结束已清理，数值结论都记在上面的表里。
