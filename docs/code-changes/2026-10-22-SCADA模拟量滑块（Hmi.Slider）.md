# SCADA 模拟量滑块（Hmi.Slider）

> 日期：2026-10-22 ｜ 范围：P2 模拟量滑块（第二批设计里唯一新增 TypeKey） ｜ 状态：桌面端已实现，专项断言通过，待真机确认

## 1. 背景

连续量需要"拖动即写"的输入方式：棒图只显示比例，数值域要逐个敲数，现场戴手套/小屏时都不如一根滑块。
本轮按设计基线 07 落地 `Hmi.Slider`：

- 横向 / 纵向两种走向；
- 拖动只改显示，**松手写一次**（可选 100ms 节流）；
- 写失败回弹到变量当前值 + 红轨 + 原因；
- 键盘左右/上下按步长调，Home/End 到两端；
- 写入前二次确认可选。

## 3. 关键决策

### 3.1 显示值与模型值分家

`Value` 是绑到工程变量的模型值；拖动期间只改私有 `_displayValue`，**不写 `Value`、不写变量**。
松手（或键盘步进）才通过 `IScadaValueWriter` 写一次。这样一次拖动不会把 PLC 写几百次；
写入成功后由数据泵把变量值读回来追平显示。

### 3.2 写失败必须回弹

写入被拒（设备离线/变量只读/权限不足）时：

- `_displayValue` 退回模型 `Value`（数据泵读回的当前值）；
- 轨道/填充变红，`WriteError` 保留原因为止；
- 绝不把拇指停在"看起来已经改了"的位置。

**二次确认取消是另一条路径**：回弹到模型值、清空错误、不写变量——用户主动取消不该在画面上留一条红色告警（SL8 钉住）。

### 3.3 可编辑四道门 + 二次确认

与数值域/多档旋钮同一口径：`Mode != Output`、有写通道、`Value` 真绑了变量、当前角色过权限。
`ConfirmDanger=true` 时松手写入前走 `ScadaRuntimeContext.Confirmations`；没有确认出口直接拒绝
（不静默放行）。Throttled 模式下 `ConfirmDanger=true` 时不节流（避免一次拖动弹几十次确认）。

**确认期间的回读不能改掉待写值**：确认框是同步模态（内部泵 `DispatcherFrame`），确认期间数据泵会把变量
回读写进 `Value`，`OnValuePropertyChanged` 随即覆盖 `_displayValue`。`WriteCurrent` 在弹确认前先把
"用户要写的值"捕获到 `valueToWrite`，确认文案与真正写入都用它；确认返回后再复核一次 `CanOperate`
（权限/绑定可能在模态期间变化），写成功后把显示恢复到 `valueToWrite`，避免成功后瞬间跳回旧值。
SL9b 用 `FakeConfirmationService.OnConfirm` 在确认框内部改 `Value` 复现这条时序。

**确认期间量程缩小则拒绝重来**：`Minimum/Maximum` 也可能在模态期间被改。若确认值已落到新量程之外，
静默 `Clamp` 会写进一个"没被确认过"的值；所以确认后先 `Clamp(valueToWrite)` 比对，越界就报
"量程已变化，请重新确认"并回弹，不写变量。SL9c 在确认框内把 `Maximum` 改成 50，验证确认值 80
不会被静默夹成 50 写进去。

### 3.4 走向与键盘

- 横向：左→右，0 在左；纵向：下→上，0 在下。
- 纵向时数值文字是覆盖层、TrackHost 跨两行且不留上下边距，保证 48px 高的默认尺寸里轨道仍有足够长度让 20px 拇指走完全程。
- 键盘 Left/Down 减一个 `Step`，Right/Up 加一个；Home/End 到两端；键盘步进立即写一次。
- 拖动不受 `Step` 限制（连续值），与设计基线一致。
- `CaptureMouse()` 失败时不进入拖动态；移动过程中左键已松开也立即结束，避免"没按键划过就改值"。

### 3.5 Web

Web 渲染器与桌面同口径：拖动只改本地显示、松手一次 `cmd.input`、失败回弹。
Web 不做 100ms 节流（浏览器端没有"必须连续跟随"的诉求，少一条写路径更稳）。
**`ConfirmDanger=true` 的滑块在 Web 端明确拒绝写入**（服务端 `HandleInput` 也强制拒绝，不能靠客户端绕过），
并提示"请在桌面操作"——Web 没有桌面那个模态确认出口，静默放行比拒绝危险得多。
Web 的 `ValueFormat` 与桌面同口径覆盖 `F`/`P` 与自定义 `0`/`#`（含单位后缀与 `%`；自定义 `0.0%` 会先乘 100；
`0` 是必选位、`#` 是可选位，`0.0#` 至少保留 1 位小数，`#.##` 的 0 输出空串）。
`N`/`C` 保留小数位与千分位，但 `C` 不显示 InvariantCulture 的货币符号 `¤`（现场上屏无意义）；
桌面 .NET 格式串仍是权威口径，Web 是它的显示子集。该子集用 Node 直接抽取 `formatValue` 实测 10 个代表性格式：
`0.0% @0.5 → 50.0%`、`P1 @50 → 5,000.0 %`、`N2 @5000 → 5,000.00`、`C2 @5000 → 5,000.00`、
`0.0# @50 → 50.0`、`#.## @0 → ""`、`#.## @0.5 → .5`、`#,##0.00 @5000 → 5,000.00`、
`0.0 ℃ @50 → 50.0 ℃`、`F2 @50 → 50.00`。

### 3.6 非有限值与错误可见性

- `Value/Minimum/Maximum` 为 NaN/Infinity 时 `Clamp`/`ComputeRatio`/`ValueFromRatio` 全部回落到有限值，`Thickness` 不会收到 NaN（UI 线程不崩）。
- 写失败时数值文字区直接显示 `WriteError`（红字），ToolTip 同步；`ShowValue=false` 时错误仍显示——操作员必须看得到"为什么没写进去"。
- `CornerRadius` 真的落到轨道/填充的 `Border.CornerRadius`，不是模板写死的 4。

## 5. 边界与未做

1. **动态量程 `MinVariable/MaxVariable` 未做**：设计表里的"上下限取自寄存器"需要运行期解析变量并订阅刷新；本轮只做常数 `Minimum/Maximum`。
2. **刻度文字未做**：设计图里的主刻度（0/25/50/75/100）没有画；数值文字已显示。
3. **运动专用门禁未细分**：速度/压力/温度类"三档 + 硬上限 + Engineer"没有做成滑块专属规则；当前用基类 `RequiredRole` + `ConfirmDanger` 兜底，运动位置类仍应走 `TryMove`。
4. **Web 不支持 Throttled/ConfirmDanger 写入**：Web 固定松手写一次；`ConfirmDanger=true` 的滑块 Web 端明确拒绝（服务端强制），请在桌面操作。
5. **没有真机截图**：拖动观感、拇指尺寸、纵向排版需真机确认。
6. **Release 已重建**：`Scada.Controls` / `VisionMaster` / Web Release 均 0 错误，Web Release 产物与源码逐字节一致。
7. **全量结果依赖交互桌面**：本机 2490 通过 / 1 失败（唯一失败是 `FlowListView.xaml` 流程卡片断言）；非交互桌面复跑时另有若干焦点/计时类断言失败（两次环境分别表现为 3 条数值域焦点/鼠标与 4 条报警历史面板断言），滑块段 34/34 不受影响。真机验收以交互桌面为准。
8. **Web 未执行真实交互**：`ScadaWebChecks` 146/0 覆盖静态文件/HTTP/命令通道与渲染器注册，`formatValue` 用 Node 抽取实测，但没有在浏览器里真拖一次；焦点、指针丢失、触摸手感仍需真机确认。
9. **Web 的 `N`/`C` 格式不显示货币符号**：`N`/`C` 保留小数位与千分位，`C` 省略 InvariantCulture 的 `¤`；桌面 .NET 格式串仍是权威口径。
