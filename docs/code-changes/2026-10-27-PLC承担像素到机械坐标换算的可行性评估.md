# PLC 承担「像素 → 机械坐标」换算的可行性评估（2026-10-27）

## 一、当前状态

需求：本项目标定算法已与 HALCON 交叉验证，希望把「像素坐标 → 机械坐标」的换算下沉到 PLC，
相机侧只发像素坐标，PLC 完成位置转换。

**结论：可行，但要拆成两半看——「拟合求解」必须留在上位机，「应用变换」可以搬到 PLC；
能不能搬取决于现场用的是哪种 `CalibrationKind`。**

- 九点（6 元仿射）与透视（3×3 投影）：搬过去只是十几行 ST，**数学上没有风险，风险全在工程接线**。
- 网格标定、polynomial 内参去畸变、手眼 4×4：**不建议搬**。

本轮为代码取证评估，**未在真 PLC 上跑过任何换算代码，未做 ST 与 C# 的逐点比对**；
影响面为 grep/read 结论，非索引结论。

**拓扑已确认（2026-10-27 追加）：现场为智能相机直连 PLC，相机只能发像素值，上位机不在运行期回路**
= 2.5 表的方案 A。A 版专项要求见第八节。

## 二、已做（证据链）

### 2.1 必须先把「拟合」和「应用」分开

| | 拟合（求解系数） | 应用（每件换算） |
|---|---|---|
| 位置 | `Plugins\Plugin.Calibration\CalibrationMath.cs` | `Plugins\Plugin.PoseTransform\PoseTransformMath.cs` |
| 内容 | 质心/尺度归一化 + 3×3 克莱姆；Hartley 归一化 + 9×9 Jacobi 特征分解（DLT）；共线/退化/折返守卫 | 6 乘 6 加（仿射）；9 乘 6 加 + 2 除（透视） |
| 频次 | **离线、一次性**（重新标定时） | 每件一次 |
| 是否已被 HALCON 交叉验证 | **是，验证的就是这一段** | 否（这一段没被 HALCON 验证过，但公式极简） |

所以「把标定算法落地到 PLC」这个说法要拆开：**PLC 不需要、也不应该做拟合**，
它只需要「系数 + 求值公式」。真正要搬的是第二行那 10~20 行算术。

### 2.2 八种 `CalibrationKind` 的求值复杂度

判据来源：`Shard\Core.Interfaces\Calibration\CalibrationTransform.cs`、`CalibrationMesh.cs`。

| Kind | 每件算术量 | ST 实现难度 | 建议 |
|---|---|---|---|
| `PixelScale` | 1 乘 | 极低 | 可搬（但通常没必要单列） |
| `NinePoint` | 6 乘 6 加 | 极低 | **推荐搬** |
| `Perspective` | 9 乘 6 加 2 除 + w 守卫 | 低 | 可搬 |
| `Mesh` | 定位三角形（最多 2(N-1)² 次重心测试）+ 3 次除法 | 中高（代码长、边界语义易错） | **不推荐** |
| `NinePointUndistorted` | 去畸变 + 仿射 | 取决于畸变模型 | 视情况（见 2.3） |
| `PerspectiveUndistorted` | 去畸变 + 透视 | 同上 | 视情况 |
| `MeshUndistorted` | 去畸变 + 网格 | 高 | **不推荐** |
| `HandEye` | 4×4 刚体 + 机器人位姿 | 高（语义风险大于算术风险） | **不推荐** |

仿射公式（`CalibrationTransform.cs:173-175`，全仓统一口径）：

```
X = a11·Row + a12·Col + a31
Y = a21·Row + a22·Col + a32
```

透视公式（同文件 `:216-220`）：

```
w = h31·Row + h32·Col + h33
X = (h11·Row + h12·Col + h13) / w
Y = (h21·Row + h22·Col + h23) / w
```

### 2.3 三个必须单独说的模型

**① 网格标定（`Mesh`）**——`CalibrationMesh.cs:88-108`：N×N 节点三角化为 2(N-1)² 个三角形，
点落在哪个三角形就用该三角形的仿射（重心插值），**凸包外明确失败、绝不外推**。
算力不是问题（N=5 时 32 个三角形，几百次乘加），问题是：
- 定位循环要写 30~100 行 ST，且必须保留「找不到就报错」的语义；
- `BarycentricEps = 1e-9` 在 float32 里**不可表示**（REAL 的 eps≈1.2e-7），边界点会被两个相邻三角形同时拒绝 →
  误报「不在覆盖范围」。这条阈值必须重新设计，不能照抄。

**② 带内参的三个 `*Undistorted`**——矩阵定义在**去畸变后**的像素域，
去畸变由 HALCON `change_radial_distortion_points` 完成（`CalibrationTransform.cs:44-51`）。
如果 PLC 做换算，去畸变必须**先**在上位机/相机侧做完，PLC 收到的是「去畸变域像素」——
**这是一个与原始图像像素不同的量**。混用的代价：kappa=-1500 时视野角点去畸变位移实测约 23px
（`CalibrationTransform.cs:186`）。单系数 division 模型可解析求逆、能搬；
polynomial 五系数只能迭代反解（`CameraIntrinsics.cs:43-47`），**不要搬**。

**③ 手眼（`HandEye`）**——4×4 刚体、6-DOF，还要机器人位姿；且「眼在手上 / 眼在手外」两种装法的
同一个 4×4 物理含义不同（`CalibrationTransform.cs:87-96`）。`PoseTransform` 自己就明确拒绝它
（`PoseTransformMath.cs:158-162`）。不要搬。

### 2.4 现有数据通路已经具备

- 连接驱动：`Communication\Communications\Connection\` 下有 ModbusTcp / SiemensS7 / MitsubishiMc /
  OmronFins / FreeProtocol / Serial。
- 写能力：`Plugins\Plugin.Comm\CommWriteNowPlugin.cs` 已有「写任意值到 PLC 变量」（含排队写、不等待）。
- 类型宽度：`PollAddressResolver.cs:172-174`，Single=4 字节、Double=8 字节。

**也就是说「上位机算好 mm 再下发」这条路今天就能走，不需要新增任何能力。**

### 2.5 谁在回路里，风险差一个量级

| | 运行期回路 | 风险 |
|---|---|---|
| A：智能相机/相机脚本直接发像素给 PLC | 上位机只在标定时出现 | **高**。上位机现有的全部运行期守卫消失（见 4.1），必须在 PLC 侧重建 |
| B：上位机（VM）发像素给 PLC | 上位机每件都在 | 中。守卫可以留在上位机，PLC 只做纯算术 |

方案 A 下，「标定」和「运行」之间没有任何人核对尺寸、相机身份、结果有效性——
这正是本仓反复立规要杜绝的「看起来正常的错坐标」。若走 A，4.1 的三件事从「建议」变成「必须」。

## 四、下一步

### 4.1 三项必须同时建（否则等于把仓库的静默失败防线全拆了）

1. **标定版本号握手**。上位机重新标定后，PLC 若还在用旧系数 → 静默偏移，单站调试看不出来。
   把 `(Kind, 系数, SourceImageWidth/Height, CameraSerial)` 算一个版本号/哈希，随系数一起写进 PLC；
   PLC 侧不匹配 → 报警并拒绝动作。这替代了 `PoseTransformMath.CheckCalibrationUsable`
   与 `CheckImageSizeMatch` 在运行期提供的自证能力。
2. **结果有效位 + 序列号**。检测失败时上游常给 `(0,0)` 或保持旧值；仓库明确把 `(0,0)`/NaN 判为无效
   （`PoseTransformMath.cs:205-246`）。PLC 收到 `(0,0)` 会算出一个「看起来合理」的坐标然后真去动——这是安全问题。
   必须「坐标 + Valid + Seq」同帧下发，PLC 只在 Seq 变化且 Valid 时消费。
   Modbus TCP 下 Row/Col 是两个寄存器，分开写会读到「新的 Row + 旧的 Col」，只有 Seq 挡得住。
3. **上位机影子算 + 回读比对**。PLC 算完把 X/Y 回写，上位机用同一份系数自己再算一遍比对，超差报警。
   这是把「已 HALCON 交叉验证」重新建立到运行路径上的唯一办法——**拟合被验证过，不代表 PLC 里的求值实现是对的**。

### 4.2 验收：黄金向量集

- 导出系数时同时导出 N（建议 ≥200）个覆盖视野的像素点及其在上位机算出的 mm 值（含四角、中心、边界附近）。
- 三方比对：**上位机 ↔ HALCON ↔ PLC**。HALCON 侧用 `affine_trans_point_2d` / `projective_trans_point_2d`。
- **注意 HALCON 的 6 元排布要重排**：`[h11 h12 h13 h21 h22 h23] = [a11 a12 a31 a21 a22 a32]`
  （`CalibrationTransform.cs:176-179`）——本仓的 6 元与 HALCON 差一次重排，不存在「直喂」。
- 判据：最大偏差 ≤ 允许定位精度（建议先按 1µm / 0.001mm 起，按现场定）。
- 每次重新标定都重跑一遍——这就是回归。

## 五、踩过的坑（已知的与必然遇到的）

1. **矩阵排布**：本仓 6 元是 `[a11 a12 a21 a22 a31 a32]`，HALCON 是 `[h11 h12 h13 h21 h22 h23]`。
   按数组下标导出一旦对错，矩阵「看起来完全正常」但整幅错位。**导出必须按命名系数，不按下标。**
2. **float32 精度**：REAL 相对精度约 6e-8，误差 ≈ |值| × 6e-8。
   机械坐标量级 1000mm → 6e-5mm，够用；量级 1e6 → 0.06 单位，若单位是 mm 就是 60µm，不够。
   **判据：要求分辨率 ÷ 坐标绝对值量级 < 1e-7 时必须上 LREAL**；或把机械坐标改成相对基准点的偏移，
   把量级压到视场大小。
3. **double 的阈值不能照抄**：`MinProjW = 1e-12`、`MinProjDet = 1e-12`、`BarycentricEps = 1e-9`
   在 float32 里都低于可表示精度。照抄 = 守卫形同虚设。要换相对判据
   （如 `|w| < 1e-6 × (|h31·Row| + |h32·Col| + |h33|)`），或者干脆用 LREAL。
4. **除零不抛异常**：ST 里 REAL 除零多数是产出 inf/NaN 或置状态位后继续跑，不像 C# 抛异常。
   必须显式判 w 并给故障位，否则 NaN 会一路进运动指令。
5. **单位与字节序**：仓库有过 Modbus 字节序颠倒的前科
   （`docs\code-changes\2026-09-15-Modbus字节序颠倒修复.md`，「接真 PLC 必炸」）。
   REAL 走 Modbus 要定 word/byte 顺序；单位要定 mm / µm / 0.001mm，且必须与标定时录入的机械坐标单位一致。
6. **角度不是矩阵乘法**：若 PLC 还要算纠偏角，配方是两向量 atan2 相减（`PoseTransformMath.cs:389-497`）：
   ```
   φ0   = atan2(a22, a12)
   φ(θ) = atan2(a21·sinθ + a22·cosθ, a11·sinθ + a12·cosθ)
   机械角 = normalize(φ(θ) − φ0)      // (−180, 180]
   ```
   **透视/网格下角度与位置相关**（要该点的局部雅可比），只有九点是全局常量。
   镜像/轴交换会让转角自然取反——这是矩阵的自然结果，不要再「校正一次」。
7. **图像尺寸/ROI/降采样校验被绕过**：`CheckImageSizeMatch` 只在上位机跑。换分辨率、加 ROI 偏移、
   做 2×2 降采样，像素坐标语义就变了，PLC 毫不知情。这些必须进版本号，或由上位机在下发前拦。

## 六、建议

- **只是为了「减少 PC 负载 / 降低延迟」→ 不值得。** 一次仿射 12 次浮点运算，省不出东西，
  却把三套防线拆了。
- **为了「上位机掉线时 PLC 仍能继续定位」→ 值得**，但 4.1 三项必须一起建。
- **现场用的是网格标定或 polynomial 内参 → 别搬**，留在上位机算 mm 下发（`CommWriteNowPlugin` 现成）。
- **中间路线（推荐）**：PLC 算 + 上位机影子算比对。PLC 有自主性，上位机保留单一真源与漂移检测。

## 八、2026-10-27 追加：拓扑确认为方案 A（智能相机直连 PLC）

### 8.1 结论不变，但重心换了

方案 A 下上位机**不是运行期参与者**，而是「量具工厂」：拟合 → 导出系数 + 版本 → PLC 长期持有。
于是本仓所有运行期守卫——`CheckCalibrationUsable`（类型/内参/相机身份交叉核对）、
`CheckImageSizeMatch`（图像尺寸失配）、`IsUsablePixelPoint`（`(0,0)`/NaN 判无效）、
网格越界拒绝——**在运行期全部不存在**，必须换到两处重建：
① 相机→PLC 的接口约定（8.3）；② PLC 内部的合理性检查（8.4）。

### 8.2 模型选型现在就要定死：默认选透视，不是九点

排除网格（2.3-①）与内参（2.3-②）之后，剩下的只有仿射与透视。两者差别是假设：

- 仿射假设「相机光轴严格垂直于标定平面 + 无畸变」；
- 透视能吸收相机倾斜导致的「近大远小」。

现场「装不正」比「镜头畸变大」常见得多，而透视只比仿射多 3 个系数、2 次除法（约 5 行 ST）。
**所以默认选透视。**

若坚持九点，必须用 `ResidualByRadiusBands` 验收：边缘带残差 ≫ 中心带（2 倍以上，且边缘带 ≥ 允许精度）
就说明模型不够。此时只剩三条路——换低畸变镜头、缩小视野、把网格/内参留在上位机算 mm；
**方案 A 下第三条不存在**，所以实际只剩前两条。这条判据必须在导出前跑一次并写进交接记录。

### 8.3 相机→PLC 这一段比 PLC 里的 ST 重要得多（四个必须确认）

1. **亚像素还是整像素**。若智能相机只能输出整数像素，量化误差 ±0.5px；按 0.05mm/px 即 ±25µm。
   这个量级远大于 float32 的精度损失——**那么 8.7 的 REAL/LREAL 讨论就没有意义了**。
   这条决定整个精度预算，要最先确认。
2. **有没有「结果有效」位**。相机若连一个 valid / strobe 都没有，PLC 无法区分
   「检测失败输出 (0,0)」与「零件真的在像素原点」——后者会被算成一个合法坐标，轴真的动过去。
   这是**安全问题**，不是精度问题。至少要 strobe 或 ready 位；真没有的话，PLC 必须做像素合法性窗口。
3. **半更新**。Row/Col 是两个寄存器：相机分两次写、PLC 分两次读，就会拿到
   「新的 Row + 旧的 Col」，算出的坐标完全合法但错。必须靠 strobe / 序号 / "写完后置位" 做栅栏。
4. **字序与单位**。REAL 走 Modbus 有 word swap / byte swap 两种翻法，仓库有前科
   （`docs\code-changes\2026-09-15-Modbus字节序颠倒修复.md`）。
   单位要定 mm / µm / 0.001mm，且必须与标定时录入的机械坐标单位一致。

### 8.4 PLC 侧必须补的三样（替代被绕过的守卫）

1. **上电自检：把 5~8 个黄金向量烧进 PLC 程序**。系数加载后（或每次上电）用它们跑一遍，
   与烧进去的期望值比对，超差就置故障位、禁止动作。
   这一条能自动抓住**全部三种最致命的错误**——矩阵排布错（2.5/五-1）、单位错、字节序错，
   而且**不需要上位机在回路里**。这是方案 A 下性价比最高的一道闸，强烈建议做。
2. **输出合理性窗口**。算出的 X/Y 落在配置的工作包络外 → 拒绝并报警。
   抓得住「整幅错位」「系数没加载」「用了别的工位的标定」这类粗错，抓不住小漂移。
3. **版本号 + 质量指标上 HMI**。把标定创建时间、`ResidualRmsPx`、图像尺寸、相机序列号作为
   **惰性数据**一起写进 PLC，在 HMI 上显示，换型/交接班确认。
   诚实说：**方案 A 下「用了旧标定」这件事代码管不了**——没有第二份真源可比对，
   只能靠「版本号上屏 + 换型确认」的流程管。不要指望自动检测。

### 8.5 别手工把系数敲进 PLC

6 个（或 9 个）浮点数手工录入 PLC 数据块，是最容易错、也最难查的一步。
上位机已有 Modbus / S7 / MC / FINS 驱动与 `CommWriteNowPlugin`，
**写一个小工具一次性把系数块 + 版本号 + 自检期望值写进去**，比手工敲安全一个数量级。

### 8.6 角度：如果需要纠偏角，九点反而更省事

透视下机械角随位置变化（要该点局部雅可比，先算 w 再算 J）；仿射下是全局常量公式：

```
φ0   = atan2(a22, a12)
φ(θ) = atan2(a21·sinθ + a22·cosθ, a11·sinθ + a12·cosθ)
机械角 = normalize(φ(θ) − φ0)      // (−180, 180]
```

若 PLC 只要位置不要角度，这条忽略，透视仍是首选。

### 8.7 精度判据（前提：相机确实给亚像素）

REAL 误差 ≈ |值| × 6e-8。机械坐标 1000mm 量级 → 6e-5mm，够；
1e6 量级 → 0.06 单位，单位若是 mm 就是 60µm，不够。
**判据：要求分辨率 ÷ 坐标绝对值量级 < 1e-7 → 必须 LREAL**（或改成相对基准点的偏移）。
另：double 的守卫阈值（`1e-12` / `1e-9`）在 float32 里不可表示，必须换相对判据（五-3）。

### 8.8 验收（方案 A 版）

1. 导出时生成 ≥200 点黄金向量，上位机与 HALCON 双向核对（4.2）。
2. 抽 5~8 点烧进 PLC 做上电自检（8.4-1）。
3. 全量 200 点在 PLC 上跑一遍（PLC 把结果批量回读到上位机比对，或用在线监视）。
4. 判据：最大偏差 ≤ 允许定位精度（建议先按 1µm / 0.001mm 起，按现场定）。
5. 每次重新标定：重跑全量 + 重烧自检点。
