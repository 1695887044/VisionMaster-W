## 已做

### 1. 反向引用索引

`SolutionProjectAssetCatalog.FindReferences`：扫**每个步骤的每个输入值**，命中以下任一即算引用——

- 资产 Id（Guid 字符串）
- 绝对路径
- 相对路径（规范化分隔符后包含）
- 文件名

与原有"插件 + 已知键名"的强匹配**取并集**：强匹配抓语义引用（按名字），反向索引抓漏网（换了插件、用路径引用）。引用卡上标出匹配依据（`读取 · 相对路径`）。

旧实现只认"已知插件 + 已知键名"，新插件或换键名就显示"未引用"——而它其实正在产线上被用着。

### 2. 配方内容形态冲突

- `RecipeDefinition.HasConflictingContent` / `ValidateContent()`：文本内容与参数条目/点位同时有 → 报错；声明了形态却没内容 → 也报。
- 保存配方内容时校验，冲突则**回滚内存改动**并提示。
- 回滚配方后也校验，冲突直接拒绝（不做"半还原"）。
- 目录把冲突配方标成 `配置冲突`，并归入左侧「待处理」桶（不再是"有效"）。

### 3. 回滚还原元数据

- 文件资产快照新增 `Name` / `Status`；回滚时 `TryRestoreStoredMetadata` 还原它们。
- 配方回滚还原 `Name` / `Code`。
- **AssetId 一律不动**——它是身份，改了等于把引用全部打断。

### 4. 版本库清理

`ProjectAssetImporter.PruneVersionFiles(solution, kind, assetId, currentVersion)`：
保留「版本记录引用到的版本」+「当前版本」，其余文件删除；`TryRecordVersion` 与回滚路径都自动调用。

以记录为准而不是"最近 N 个文件"：能回滚的前提是"有记录且有文件"，按文件数删会把仍可回滚的记录变成"点回滚才报没有文件本体"。记录本身有 50 条上限，文件增长随之被钉住。

### 5. 其余插件断言

`Yolo` / `DlAnomaly` / `DlClassify` / `DlSegment` 各 4 条契约断言（AssetKind=model、AssetId 回写、配置下拉能选到、能清空）。至此**九个**消费插件全部有断言。

### 6. 探针去掉硬编码方案路径

`解决方案\智能装配检测线` 已不存在（被换成了 `视觉样例对拍`）。改动：

- 方案路径改为 `解决方案\**\*.vms` 里最新的一份；找不到才判红。
- 断言从"标定恰好 1 个 / 图像恰好 14 个"改成"总数 > 0 且等于各页签之和"。
- 筛选/排序、引用跳转两组断言改为**自带夹具**（造方案 + 造流程步骤），不再依赖当前那个方案的内容。
- 夹具图片从已删除的方案目录改为仓库稳定的 `Image\board\board_01.png`。

## 踩过的坑

1. **`StepModel` 是抽象类**：断言里造步骤要用具体类型（`WaitStep(icon, pluginName, pluginTypeName, stepName)`）。
2. **`CameraSerial` 在 `CalibrationTransform` 上**，不在 `CalibrationAsset` 上。
3. **doc 注释与声明写在同一行**会把声明吞进注释，报出 "不能同时提供程序块主体与表达式主体" 这种看不出根因的错。
4. **并行会话反复打断门禁**：这次依次遇到 `DeformableMatching` DLL 陈旧、`HalconBase.GetLineWidth` 半成品、两个 `FlowCanvasChecks` 抢 `Modules\*.dll`。都不是本轮改动，只能等对方落定后复跑。

## 未做 / 已知边界

- 反向索引按**子串**匹配：资产文件名很短时（如 `a.png`）可能误命中别的路径。目前靠"必须包含完整文件名"兜底，没有做路径级精确比对。
- 清理只在"记版本/回滚"时触发；纯浏览不会清理。
- 回滚不还原 `RelativePath`（活动文件路径本身），只还原内容与名称/状态。
- 冲突配方只标状态、不阻止插件运行（插件按 `ContentFormat` 取一份，另一份被忽略）。
