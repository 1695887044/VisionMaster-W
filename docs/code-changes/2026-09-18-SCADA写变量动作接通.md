# SCADA 写变量动作接通（S6-6）

- 日期：2026-09-18
- 路线图：`docs/SCADA商业级交付路线图.md` → S6「运行态数据泵」的欠债清偿段（s6-6）
- 前置：S6 数据泵主体（s6-1 ~ s6-5、s6-7）已完成并全绿

## 一、需求与决策

### 需求

S5 里「写变量」这个动作是**能配、能落盘、但执行不了**的：属性面板可以选这个类型，
但变量选不了（没有 UI），执行侧只会照实警告一句「写变量要等数据泵（S6）接入，本条未执行」。
s6-6 的任务就是把这笔欠债还掉：**让「写变量」真能写**，并补齐配套的编辑界面。

### 决策（逐条）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 1 | 变量清单来源 | 走 `IScadaValueSource.TryResolve`，不直接查 `IVariableRegistry` | 与数据泵同一条寻址通道，「Id 优先、名字兜底」的口径不分叉；写能力收在 `IWritableVariable` 后面 |
| 2 | Dispatcher 注入 | 构造注入 `IScadaValueSource`：`ScadaActionDispatcher(ILogService log, IScadaValueSource values)` | 值源已是 DI 单例；执行侧因此不认变量注册表，只认句柄 |
| 3 | 写失败分档 | ①没选变量→`Warn` ②找不到变量→`Warn`（带变量名）③值转不过→`Error` ④写不进→`Error`（原因原样带上） | 四档对现场是四件事：配置漏了 / 改名删了 / 值写错了 / 设备侧的事。合成一句「写变量失败」，用户得把四条路各试一遍 |
| 4 | 成功日志 | `_log.Info($"{head} → {action.Describe()}")` | 与属性面板上那条动作的摘要同一出处，日志与配置界面对得上号 |
| 5 | 值转换时机 | 执行那一刻从字符串现转，不在配置时转好存下来 | 变量类型可以改（int→string），配置时转好的值会僵死；`.vms` 手工可改，规则只认 `VariableValueConverter` 一份 |
| 6 | `PendingReason` | `WriteVariable => null`（保留 switch 分支，让「已接通」在代码里显式可见） | 面板那行橙色提示与运行日志逐字同源，接通了就必须一起消失 |
| 7 | 「选变量」抽象 | 新建 `IScadaVariablePicker.Pick(currentId, currentName, onPicked)`，**回调式** | 面板/事件行必须能在无 WPF 宿主下被断言，不能硬接 Prism `IDialogService` |
| 8 | 弹窗 | 新建**组态专用**弹窗 `ScadaVariablePickerView`，不复用 `DataBindView` | 语义不同：后者是流程端口绑定的多列树；前者只列工程变量 |
| 9 | 清单口径 | 只列 `IWorkspaceManager.GlobalVariables` | 这正是运行态变量注册表镜像的那一份 →「选得到就一定写得到」 |
| 10 | 取消语义 | 回调**一次都不触发** | 取消不该被翻译成「清空原绑定」这种破坏性动作 |
| 11 | Id 权威 | 出参拿不到 `Guid` 就整条放弃，绝不退化成按名字猜 | Id 是权威身份，名字只用于显示与兜底寻址 |
| 12 | 预选顺序 | Id 优先、名字兜底（与 `IVariableRegistry.Resolve` 同序） | 打开弹窗要停在用户上次选的那一行 |

## 三、验证结果

```
dotnet build VisionMaster.sln        → 0 个错误
ScadaChecks.exe                      → 通过 543 / 失败 0（「全部断言通过」）
```

关键断言实况：

- `写变量 启动 := 1` 成功日志 + 变量值变成 `1`（int，非字符串）
- 四档失败措辞：`写变量：还没选变量，本条未执行` / `找不到变量「已改名的变量」，本条未执行` / `「abc」无法转换为 Int32：...` / `写入失败：设备未连接`
- 面板「选择变量」→ 回填 `VariableId` + `VariableName`；取消后原绑定原样留着
- S6 数据泵段（`[Z]`）30 条断言全部照旧通过，未被本次改动影响

## 四、已知边界

1. **图元属性反向写变量**：本版不做（路线图 S6 明确不做历史值/趋势曲线，反向写同理留待后续）。
2. **`IWritableVariable` 覆盖范围**：本地变量与网络变量都已实现；未实现该契约的变量 `TryWrite` 会明确报「不支持写入（未实现可写契约）」，落在第 ④ 档 `Error`。
3. **`Navigate`（切换画面）仍未接通**：等 S8 画面导航，`PendingReason` 照旧出「切换画面要等画面导航（S8）接入」。
4. **弹窗清单不含流程内局部端口**：只列 `GlobalVariables`。这是刻意的——清单口径 == 运行态可寻址口径。
5. **变量在弹窗打开期间被删除**：确认时 `VariableId` 仍会回填，执行时走第 ② 档 `Warn`（找不到变量），不会静默失败。
