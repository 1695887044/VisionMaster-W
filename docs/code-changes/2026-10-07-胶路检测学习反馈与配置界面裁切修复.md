# 2026-10-07 胶路检测：学习反馈可见化与配置界面裁切修复

> 起因：用户实测两条反馈——① 点「学习」**没有任何反应**；② 配置界面布局不合理（「配方参数/路径点列」卡在下沿被裁断）。
> 影响范围：**仅配置界面**——`Plugins\Plugin.BeadInspect\BeadInspectView.xaml`、`BeadInspectView.xaml.cs`、`BeadInspectPluginConfigView.cs`，
> 外加共享主题**只增不改**的 3 个尺寸令牌（`UI\Controls\Themes\PluginConfigColors.xaml:175-177`）。
> 运行内核、端口契约、算法层（`BeadInspectHalcon.cs` / `BeadInspectPlugin.cs`）未动。

## 一、根因

### 根因 1（"点学习没反应"的真因）：学习结论**全部渲染在用户视口之外**

点击链路本身是通的（读码定位，不是猜测）：

`BeadInspectView.xaml:453`（「学习」按钮 `Click="OnLearnClick"`）→ `BeadInspectView.xaml.cs:148`（`OnLearnClick` 转发）→
`BeadInspectPluginConfigView.cs:861`（`LearnRecipe()`）。

但 `LearnRecipe()` 的**每一条**返回路径（配方条目为空 / 平面可变形缺参考图 / 点列为空或格式无效 / 点数 < 2 /
bead 模型失败 / planar 失败 / 成功）原先只写三处：

| # | 原先写在哪 | 今天的坐标 |
| --- | --- | --- |
| a | 底部**状态栏** | 右列第 3 行，`BeadInspectView.xaml:821` 起的 `PluginStatusPanel` |
| b | **学习预览** `PreviewImage` | 同行的预览卡（`BeadInspectView.xaml:867` 的 `h:ImageReadOnly`） |
| c | 左侧**配方库行** | 左列列表（`RefreshRecipeRows`），首屏要滚动才看得见 |

三处都在用户当前视口之外（左列需滚动、右列第 3 行整行被裁），画布（第 1 行）学习前后不变——
**用户能看见的地方一个字都没变**，于是"点了没反应"。

用户现场的形态最可能是「平面可变形 + 未设参考图路径」：走 `BeadInspectPluginConfigView.cs:870-882` 提前返回，
只写当时还不存在的状态栏提示，连预览与配方库行都不动。

### 根因 2（配置界面下沿被裁）：右列第 2/3 行是 `Auto`（WPF 中 `Auto` 行**不参与压缩**）

旧行模型 `Auto（工具条）/ * MinHeight220（画布）/ Auto（参数卡）/ Auto（状态+预览）`。
`Grid` 自身**不滚动**：只要「工具条 + 画布 220 + 参数卡自然高 298 + 状态行」> 可用高，
后两行就被排到 Grid 边界之外（内容还在，只是被推到视口下面点不到）。

- 复现条件：视图可用高 < ~745px。用户窗口（125% 缩放）视图 ≈1000×664；外壳默认 960×680 也命中。
- **1490×880 下旧版并不裁**（`run_layout_before.txt` 该尺寸各行 `在右列内=True`）→ 属于"矮窗口触发"，与宽度无关的主因是高度。
- before 对照截图（复现用户症状）：`_BeadViewProbe\before_layout_shell_1192x824_learn_ok.png`、`before_layout_620x640_learn_ok.png`。

### 根因 3（独立缺陷）：「③ 平面匹配搜索范围」卡的长提示不是换行，而是被**硬裁**

- 表象：`BeadInspectView.xaml` 的 ③ 卡提示原先带 `MaxWidth="250"`，在 `TextWrapping=NoWrap` 下
  `MaxWidth` **只压窄控件框、文字照样画到框外**：实测框 250 / 渲染 **988×16 一行**，在卡片右缘被切断
  （用户截图"…工件在视"断掉即此；`run_layout_before.txt`：`③卡提示 实际=988x16 … MaxWidth=250 上级可用宽=271 被裁=True`）。
- **仓库级根因（本轮未修，留作决策）**：`UI\Controls\Themes\Generic.xaml:71` 把 `Fluent/FluentAliases.xaml`
  **最后合并**（资源字典后合并者优先），而 `FluentAliases.xaml:305-308` 的同名 `PluginHintText`
  只 `BasedOn FluentTextCaptionStyle`，**没带上** `PluginConfigStyles.xaml:67-71` 的 `TextWrapping=Wrap`
  → 凡合并 `Themes\Generic.xaml` 的插件视图，`PluginHintText` 实际是 **NoWrap**，长提示静默溢出被裁。
- 建议补丁（1 行）：给 `FluentAliases.xaml` 的 `PluginHintText` 加 `<Setter Property="TextWrapping" Value="Wrap" />`。
- **影响面**：全仓 **14 个插件视图**引用该键（CodeReader / ColorCheck / ColorRegion / Ocr / PreProcessing / Yolo 等还有 `BasedOn` 派生）。
  修好后这些视图的提示会开始换行、卡片变高，可能把各自底部推出视口 → **需单独排期评审**；
  本轮只在胶路视图里**就地**写 `TextWrapping="Wrap"`（与字典合并顺序无关的写法）。

### B. 布局压缩与裁切修复

| 位置 | 改动 |
| --- | --- |
| `BeadInspectView.xaml:426-436` | 右列行模型 `Auto / * MinHeight220 / Auto / Auto` → `Auto / 4* MinHeight150 / 6* MinHeight130 MaxHeight320 / Auto` |
| `BeadInspectView.xaml:612-613`（闭合 `:807`） | 参数卡内容加**叶子级** `ScrollViewer`（宽度方向禁滚：`HorizontalScrollBarVisibility="Disabled"`）——压到自然高以下时**卡片自身可滚动**，不再被窗口裁掉 |
| `PluginConfigColors.xaml:175-177` | 新增 3 个 `Plugin*` 尺寸令牌：`PluginCanvasMinHeight=150` / `PluginParamsCardMinHeight=130` / `PluginParamsCardMaxHeight=320`（既有键一个未改） |
| `BeadInspectView.xaml:314-318` | ③ 卡提示**删无效的 `MaxWidth="250"`** + 就地 `TextWrapping="Wrap"` |
| `BeadInspectView.xaml:394-407`、`:449`、`:578-584`、`:805` | 同类**就地 Wrap** 另 4 处：「怎么用」两段、点数提示、画布两行提示、参数卡末行提示 |

**为什么改成两根 `*`**：`Auto` 行不参与压缩，只要「工具条 + 220 + 参数卡 + 状态栏」> 可用高，Grid 就把内容排到边界外
（Grid 自身不滚动）。比例 4:6 不是拍脑袋：参数卡自然高 298（DataGrid 150 + 左列表单 242），高位窗口下封顶 320 把余量全留给画布。

**交互链未被引入滚动容器**：**没有**给右列加 `ScrollViewer`——画布交互链（左键加点 / 拖动 / `Ctrl+Z` / 滚轮缩放）无新增滚动容器，
只有参数卡内部这一层叶子级滚动。

**工具条结论（实测）**：7 个按钮单行**实际占宽 588px**（预算 630px）；1000×664 时右列可用 604px 仍为 1 行、960×680 外壳为 2 行、620 宽为 3 行，
**任何宽度下按钮文字完整（裁切 0 处）** →「适应图片」保留在 `WrapPanel` 内，不做挪出/折叠。
「怎么用」卡不做折叠（左列自带 `ScrollViewer`，内容可达）。

## 四、未决（照实记录，含"本轮明确没修"的）

1. **620×640 + 学习横幅仍溢出**：合计 744 > 可用 616，溢出 116px 落在第 4 行（探针明确标 `[LIMIT]`）。
   比旧版（990 > 616）严格改善但**未修好** → 属"提高最小尺寸"的决策问题。
2. **`PluginViewMinHeight=360`（`PluginConfigColors.xaml:180-181`）对本视图不成立**：右列固定体量使实际下限约 **900×700**
   → 需给本视图单列最小尺寸，或提高外壳/全局最小高（跨 14 插件的公共契约，需评审）。
3. **`PluginHintText` 别名顶掉 `Wrap`**（见根因 3）：1 行补丁建议 + 影响面 14 个视图，需单独排期。
4. **横幅是"最近一次动作的结论"**，不随参数指纹变化自动失效——"参数已变·需重学"仍由配方库行承担。
5. **既有语义缺口（本轮未扩大范围）**：改了「参考图路径」但没点「载入」、同时上游换图触发底图重铺时，
   底图仍是旧参考图缓存（`LoadRefImage` 按路径缓存、`ShowRawBase` 只看 `_rawRefImage` 非空），
   此时拾取坐标为**旧参考图坐标系** → 建议在 `RefImagePath` 变更时作废 `_rawRefImage`。
6. **真机鼠标未走**：证据是同一份视图的**离屏实渲染 + 外壳几何仿真**（72 头 + 56 脚 + 20/16 边距）；
   画布鼠标交互（左键加点 / 拖动 / `Ctrl+Z` / 滚轮）只做结构论证（该控件链未改、无新增滚动容器）。`UIThemeSmokeTest` 本轮未跑。
