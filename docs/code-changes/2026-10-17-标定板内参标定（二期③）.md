## 1. 做了什么（一句话）

给「标定」插件加了**标定板内参标定**能力：用 ≥6 张标定板照片解出相机内参 + 畸变系数，
并提供「取点前先去畸变」开关——打开后平面标定（九点/透视/网格）在**去畸变域**求解，
产出的 `CalibrationTransform` 带新 Kind 与内参，下游「坐标变换」据此**先去畸变再映射**。

## 2. 为什么是这条接线（architect 裁决）

设计稿 §五 原本把"去畸变对图还是对点"列为未决项、要求走 R12 评审。裁决结论：

| 备选 | 结论 |
|---|---|
| **不动 `CalibrationTransform` 语义**，让内参只在标定插件内部生效、下游永远拿"畸变像素→机械"的矩阵 | **数学上不可行**。仿射/单应都是保直线变换，而径向畸变把直线映成曲线；分段仿射确实能逼近，但那**就是网格标定本身**，且丢掉内参的核心优势（可外推——网格明写"覆盖范围外必须明确失败"） |
| **对点**（本期采用） | 标定点先经 `change_radial_distortion_points` 去畸变再求解 → 矩阵定义在理想针孔坐标系；消费端先去畸变再喂矩阵。**只需一个像素帧**，与既有尺寸自证自洽 |
| **对图**（本期不做） | 会把一串帧语义拖进来（`"fixed"` 裁掉四角、`"preserve_resolution"` 改帧尺寸），且"用户忘了插去畸变步骤"变成**无自证**的静默错误。留 v2，届时须同时定死"用哪个 mode + 尺寸怎么记" |

**语义载体为什么是新增 `CalibrationKind` 成员，而不只是加个字段**：透视与网格当年就是靠"`Matrix` 保持零 → 未升级的消费者明确失败"来防静默近似的。内参场景下 `Matrix` 必须**有效**（它确实是可用仿射），所以唯一等价的响亮信号就是 Kind 本身——不知道新 Kind 的消费者会落到自己的 `default:` → 明确失败。

> **口径偏离设计稿 §3.1（记为实现勘误）**：设计稿按 OpenCV 口径写 `CameraMatrix[9]` + `Distortion[5/8/12]`。实现改按 **HALCON 原生 CamPar 形状**（`[type, focus, kappa, sx, sy, cx, cy, w, h]` / polynomial 13 元）逐字段存——HALCON 没有 OpenCV 那种 3×3 矩阵（焦距与像元尺寸是分开的两个量），按原生口径存才能**无损直译**给 `change_radial_distortion_*`。

### 共享件（`Services\Core.Halcon\Helpers\CameraDistortion.cs`，新建）

`TryBuildCamPar` / `TryBuildUndistortedCamPar` / `TryUndistortPoints` / `TryDistortPoints`（+ 单点重载）。
**为什么放共享件而不是各插件各写一份**：与 `CalibrationMesh` 同一理由——生产端与消费端必须是同一份实现，分叉 = 同一份标定算出两套坐标。

两条硬约束（都实测过）：
- `change_radial_distortion_cam_par` 的 mode **必须 `"fixed"`**：`fullsize`/`adaptive`/`preserve_resolution` 会改 `sx/sy/cx/cy`（实测 `fullsize` 把 sx=5.2e-6 改成 5.3458e-6、主点也挪走），去畸变后的像素就落到**另一个像素坐标系**，标定矩阵与 `SourceImageWidth` 全部对不上；
- `DistortionCoeffs` 的个数**必须随模型**：division 只收 1 元、polynomial 只收 5 元，给错个数一律 **#1403**（实测四组对照：div+1 成功 / div+5 失败 / poly+1 失败 / poly+5 成功）。

### 4.2 合成自验证实测（`calplate_320mm.cpd` @1.2m，12 张倾斜位姿）

| 项 | 恢复值 | 真值 | 误差 | 设计判据 |
|---|---|---|---|---|
| 焦距 | 0.0520009 | 0.052 | **0.0018%** | < 0.5% |
| 主点 | (640.0001, 512.0001) | (640, 512) | **0.0001 px** | < 1 px |
| 重投影 RMS | 0.0039 px | — | — | < 0.3 px |
| kappa | −1499.97 | −1500 | **0.002%** | （相对）< 5% |

> **kappa 口径订正**：设计稿 §四a 写"k1 绝对误差 < 5e-3"，那是 **polynomial 的 k1 量纲**；division 的 `kappa` 量级是 **1e3**，只能按**相对**误差判。断言里已按相对口径钉住。

### 4.3 去畸变往返（45 点采样，1280×1024、kappa=−1500）

| 模型 | 往返最大误差 | 说明 |
|---|---|---|
| `area_scan_division` | **2.27e-13 px** | 可解析求逆 |
| `area_scan_polynomial` | **2.56e-7 px** | 只能迭代反解（最坏 1.1e-4） |

**因此回显自校验阈值必须按模型分档**（division 1e-6 / polynomial 1e-3）——拿 1e-6 去判 polynomial 会**假红 100 倍以上**，而且失败文案会说"标定矩阵可能已损坏，请重新标定"，现场重标定解决不了。

### 4.4 变异反证（R65：新闸必须能准确变红）

把插件里"采用去畸变结果"那两行换成 `_ = uRows; _ = uCols;`（即**只算不用**）：

```
[×失败] [IC] 插件级②a：开关开 → Kind=NinePointUndistorted 且带上内参
[×失败] [IC] 插件级②b【反证】：开关开 vs 关 的矩阵必须不同
[×失败] [IC] 插件级②c：开关开 → 残差 ≈ 0 且比开关关小两个数量级以上
[×失败] [IC] 插件级②d：开关开 → 矩阵精确还原去畸变域仿射
→ 通过: 2529  失败: 5
```

还原后 **2534/0**、源码与备份**逐字节一致**。这证明"插件真的用了去畸变"是被断言覆盖的，不是顺带绿。

### 4.5 关键量化事实（现场可复算）

- **去畸变位移量级**：kappa=−1500、1280×1024 下四角 **~22.9px**、中心 **0**（主点是畸变不动点，这是模型正确的天然自证）；四角极差 < 1px（径向对称）。
- **"忘了去畸变"的代价**：边缘点 15.4px 位移 → 机械坐标偏 **0.31mm**（当量 0.02mm/px）。
- **板文件必须与灰度极性配对**（合成自验证配方，配错码不同）：`calplate_*.cpd` → 标记亮/板暗（128/80/224）；`caltab_*.descr` → 标记暗/板亮（128/200/20）。
- **初始猜测容差窗口** = [1/64, 4] × 真焦距（给 8× 会收敛到错误焦距，误差 686%）。

## 6. 已知边界（诚实清单）

| 边界 | 说明 |
|---|---|
| **只做"对点"，不做"对图"** | 见 §2。实时流程若想"整图去畸变一次、下游全见无畸变图"，需 v2 加图像域步骤 |
| **`MmPerPixel` 的适用范围** | 带内参的标定，其当量是**去畸变域**的当量。只吃 `MmPerPixel`（double 端口）的下游（卡尺/Blob/几何计算）**拿不到本对象、结构上无法自证**——它们拿原始像素乘这个当量，视野边缘会有百分之几的静默误差。这类流程要么改用不带内参的标定，要么先在图像域去畸变。**这条没有自动防护，只能靠文案** |
| **内参不进导入导出文件** | v1 边界（见 §5） |
| **真实相机照片未验** | 设计稿 §四d 的现场验收（真实相机 ≥15 张、覆盖四角+中心、与网格横向对比）**未做**——本机无实物相机与标定板照片。已做的是合成自验证（判据 a）。现场可用界面上的「合成自验证」按钮先自证环境可用 |
| **UI 自动化未走查** | `UIThemeSmokeTest --calibration` 的 12 条没加内参卡片的用例；XAML 只做了可解析性 + `StaticResource` 键清单比对（14 个键全为既有键） |
| **像元尺寸是"报告单位"而非精度参数** | `calibrate_cameras` 把 sx/sy 当**已知量固定**（不是自由参数）：单相机下 focus 与 sx 只以**比值**出现、物理上不可分。但去畸变结果对这套重参数化**精确不变**（实测 sx 差 2×/8× 时逐点最大差 **0 px**） |
