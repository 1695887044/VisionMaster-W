# 视觉图像页「多图叠加」诊断（2026-10-27）

## 一、当前状态

用户现场反馈：跑「视觉样例对拍」的样例流程后，视觉图像页看起来像"多个图像叠在一起"。

结论：**同一张图没有被画多遍**。看到的是两件事叠出来的观感，两件都有代码证据：

1. **页面本身是六格布局**，每格只收"显示窗口号 = 格号"的图；样例流程被分散投到不同窗口号，
   于是一屏同时出现 5 张来自 5 条不同流程的图（第 3 格空着并显示"本窗收的是…窗口号 = 3"提示）。
2. **每一格里的那张图自带两套结果文字**：算法插件先把自己的结果烧进输出图（`MeasureImage` /
   `DefectImage`），样例流程又把这张**已经带字的图**接给「结果显示」，后者把同一批数值再烧一遍。
   两套文字的锚点只差几像素，白底框互相覆盖，缝隙里露出上一层的字 —— 这才是字面意义上的"叠加"。

- 形状匹配_散焦PCB → 窗口 2 / 4（17:01:55、22:23:20）

多流程并发时每格各收自己窗口的那条流程，所以一屏出现多张图是"多流程 + 多窗口"的正常结果。

### 2.3 清空口径：别的流程的图不会自己消失

`VisionMaster\bin\Debug\net9.0-windows\AppConfig.json` → `ImageGallery.RunStartMode = 2` = `ClearView`。

- `Core\Models\AppConfigModel.cs:191-195`：只清"本轮要显示的那个窗口"，其它窗口一律不动；
- `VisionMaster\Services\ImageCollectionService.cs:409-433`：`ApplyPendingClearFor` 按（流程，窗口）记账。

后果：某条流程跑过一次之后，它那一格的最后一张图会一直留在页面上（除非该窗口再来新帧或用户显式
「清空画布」）。所以"跑过几条流程 → 页面固定成一张拼图"是可复现的。

## 四、下一步（三选一或组合，按用户想要的效果）

1. **只想消掉重影**：样例流程里把「显示检测结果」的 `SrcImage` 改接**原始图像**
   （`读取XX图像.Image`），或在「结果显示」里关掉 `ShowTextOnImage`（只保留端口/记录），
   或让算法插件不再烧判定文字。三者选一即可，重复的根源是"同一批数字被烧了两遍"。
2. **只想看一条流程**：把方案里的 `ImageViewMode` 改回单画面（`One`），或把不看的流程用
   「批量设置显示窗口」设成 0（不发布）。此时其余格子自然空着。
3. **确认"多流程各占一格"就是要的效果**：保留现状，但需要补一条交互约定 —— 例如「停止运行」
   或「切换流程」时显式清一次画布，或在每格角上标出"属于哪条流程 / 多久以前"。
   ⚠ 不能改回"任一流程开轮就清全画布"：那正是 2026-10-27 修掉的"窗口2 被 A 反复清空"
   （见 `2026-10-27-多流程并发帧归属与清空范围（批1）.md`）。

## 五、踩过的坑

1. **别把"六格"当成渲染缺陷**：`ImageViewMode` 是方案里的持久值（本次 = Six），先看方案再怀疑控件。
2. **`eViewMode` 的数值不是字面量**：`Five` 的枚举值是 4，`Six` 才是 5 —— 直接按名字读 JSON 会判错一格。
3. **"叠加"要先分清是图像层还是文字层**：`HalconBase.RenderAll`（`Services\Core.Halcon\Base\HalconBase.cs:1237-1359`）
   每帧 `ClearWindow` + `DispObj`，图像层不会累积；真正叠的是**已经烧进图里的文字**。
4. **`AddTextBlock` 的行距是 `max(字号+4, 字号×1.3)`**（`AnnotationBaker.cs:628`），
   而 `DisplayDraw` 的行距是 `max(字号+4, max(20, 图高×0.035))` —— 两套排版规则算出来的行距
   不是一回事，靠"字号差不多"猜位置一定会错。
5. **定位用 UTF-8 清单 + `-File`**：本机 `findstr` 在 cmd 里传中文会按 936 编码，匹配不到 UTF-8 源码
   （R2 同类坑）；`.vms` 是 UTF-8 JSON，用 `[IO.File]::ReadAllText(path, UTF8)` 读。
