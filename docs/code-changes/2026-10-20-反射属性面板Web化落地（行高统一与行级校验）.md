## 1. 起因

用户要求按 `docs\UI设计基线\property-grid\design.html` 把反射属性面板的样式与功能落地并做好测试。

改造前该控件的六处问题（基线 README「现状审查」逐条对应实读源码）：

1. **行高在同一条表单里跳变**：开关 24px、文本框 32px、数值框 **44px**。根因是
   `Themes\NumericBox.xaml` 的 `MinHeight=32` 又叠了 `Padding="10,6"`，而
   `StructValueGenerator` 只给了 32 的裸文本框。
2. **颜色体系分裂**：`PropertyGrid.xaml` 头部注释写着"全部指向 FluentTokens"，但生成器层没跟上 ——
   `StructValueGenerator` 写死 `#DCDFE6/#606266/#F5F7FA/#909399`，`BoolStateGenerator` 兜底写死
   `#409EFF`（正是那段注释抱怨的第四份强调色），`FlatPropertyGrid` 外框写死 `229,229,229`。
3. **校验只覆盖文本框**：`ValidationProcessor` 首行 `if (context.Control is not TextBox tb) return;`，
   下拉、开关、数值框一律不校验；且只在 `LostFocus` 触发；错误文案 `FontSize = 10` + `Brushes.Red`。
4. **嵌套对象长出第二层页签**：`NestedPropertyGridGenerator` 直接 `new CardPropertyGrid()`，
   子网格自带 `TabControl`，层级关系读不出来。
5. **扁平式标签列留白不均**：标签侧 `Padding 16,12,32,12`、控件侧 `16,8,16,8`，上下差 4px。
6. **只读与权限不足都只是变灰 + 一个红色 emoji 锁**。

## 3. 复刻中抓到的四个真问题

全部由断言抓到，肉眼复核时都不明显：

1. **行高 48/49 混排**（`[失败] 行高统一 48 -> 各行高度=48/49/244`）。
   `BorderThickness` 是占布局的，值列 `Padding` 写 6 会让内容区 48、加 1px 底边线后整行 49。
   改成 `5.5`。同时把"内含子网格的嵌套行"从行高断言里排除（它承载的是一个块，不是一行字段）。
2. **嵌套块双层卡片**（出图可见）。子网格自带外框 + 父级内联块又一层。加 `IsNested`，子网格不画外框。
3. **卡片式块内第二条导航**（出图可见）。嵌套子网格继承卡片形态后，块里又长出 176px 的"链路参数 3"导航栏。
   改为**嵌套一律用扁平式** —— 嵌套块的层级已由强调条 + 块头表达，内部只需干净字段表。
4. **命令按钮被拉成满宽主色横杠**（出图可见）。`HorizontalAlignment` 原先只对 `ToggleButton` 特判，
   `Button` 被 `Stretch`。改为 Button 也贴左。

另有两条是**断言写法**问题（不是产品缺陷），一并记录：

- 校验断言初次失败：`RangeValidation(0,255)` 配 `int` 属性，值 300 被 `NumericBox` 的
  `CoerceValueCallback` 提前夹回 255 → 界面上的值本就合法，测不到"校验器触发"。改用字符串 + 正则。
- 空态收高断言初次失败（实际高 0）：`MeasureOverride` 里读 `DesiredSize` 读到的是**上一轮**的值，
  必须用 `base.MeasureOverride()` 的返回值。

## 5. 有意偏离设计稿的一处（需用户裁定）

**开关轨道保持黑色，未改成设计稿的蓝色。**

`FluentTokens.xaml` 的 `FluentToggleTrackOnColor = #FF1B1B1F` 是**全应用级**令牌，其注释明确写着
"定成单色黑轨道 + 白滑块而不是系统蓝：蓝色在浅灰界面上太抢，和真正的操作按钮（也是蓝）摆在一起，
状态和动作就分不清了"。属性面板单独改蓝会与相机设置、插件配置、系统设置里所有其它开关不一致。
若裁定要蓝，应改 `FluentTokens.xaml` 一处、全局生效。
