## 三、按建议落地的六条口径

| # | 口径 | 落地方式 |
| --- | --- | --- |
| 1 | 多条动作失败继续 | 直接复用分发器（它本来就是逐条执行、失败记审计继续） |
| 2 | 持续 = 连续不累计 | 条件一断就清计时（[SC11] 钉住） |
| 3 | 错过不补 | 到点窗口 1 分钟，超出即放弃（[SC4] 钉住） |
| 4 | 入口 | SCADA 组态工具栏（用户指定） |
| 5 | 不做导入导出 | 随 `.vms` 走 |
| 6 | 权限 | 入口在组态里，能进组态就能改；运行态不提供改计划的入口 |

## 四、未做 / 偏差（v1 明确）

| 项 | 说明 |
| --- | --- |
| 动作编辑器是**按名字引用**的 7 种 | 跳页 / 写变量 / 启停流程 / 应用配方 / 播放声音 / 日志。完整 27 种动作编辑器要变量/画面/轴/配方选择器，搬进弹窗代价太大；按名字引用走的正是 `ScadaAction` 已有的 `VariableName`/`TargetPageName`/`FlowName` 兜底字段 |
| 事件计划的变量是**手填名字** | 不做变量选择器；引擎按"Id 优先、名字兜底"解析，与变量事件同一口径 |
| 无"开机补跑"开关 | 错过不补是唯一行为 |
| 无"上次执行/触发次数"落盘 | 运行态内存记账，重启清零（要留痕走日志/审计） |
| Web 端 | 不做（Web 运行态是只读视图，计划表是组态配置） |
| 安全联锁 | 明确不做——急停/超压泄放留在 PLC |

## 五、踩过的坑

| 坑 | 现象 | 处置 |
| --- | --- | --- |
| 只读便利属性被 Json.NET 填充 | 序列化前 1 条动作，读回来 **2 条**，不报任何错 | `ScadaSchedule.Actions` 加 `[JsonIgnore]`——只读集合属性默认会被当成"可填充集合"再灌一遍（[SC6] 抓到的） |
| `DayOfWeek` 索引差一位 | "每周一、三"显示成"每周二、四" | `names[ToIsoDay(d) - 1]`；ISO 口径（1=周一）只在一处换算 |
| 断言用 `&` 串两条命令 | 构建成功但跑的是旧 exe，日志时间戳没变，看着像"改了没生效" | 构建与运行分两次调用；判据看 exe mtime 与日志 mtime |
