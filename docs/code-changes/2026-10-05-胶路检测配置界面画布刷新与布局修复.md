# 2026-10-05 胶路检测配置界面：画布不刷新与布局修复

> 起因：用户实测反馈「插件长这个样子，布局不合理，而且我引入图片后界面没刷新」（附宿主配置界面截图）。
> 影响范围：**仅配置界面（`Plugin.BeadInspect` 的视图与配置态 partial）**，运行内核、端口契约、算法层未动。

---

## 一、两个问题及其根因

### 问题 1：绑定输入图后画布不刷新（始终黑屏）

**现象**：`⓪ 输入绑定` 里「输入图像 SrcImage」已绑定上游 `图像采集_0.Image`（链接态可见），画布依旧全黑。
黑屏上点击还能产生点（截图里点列有一条 `177.35, 356.37`），等于在"没有坐标系"的地方记点。

**根因（读码定位，非推测）**：

1. **配置态从未订阅上游图**。同类插件都在 `MarkAsConfigInstance()` 里订阅 `SrcImage.ValueChanged`
   （`Plugin.BlobDetect` :714-726、`Plugin.CaliperMeasure` :655-660、`Plugin.CreateRoi.OnViewLoaded()` :368-373），
   胶路漏了这一步；
2. **画布底图来源单一**：`DisplayImage` 只由 `LoadRefImage()` 从 `EditingEntry.RefImagePath` 载入——
   参考图路径为空就永远黑屏，**用户绑的输入图根本没参与铺底**；
3. **无底图仍允许拾取**：`AddPoint` / `DeleteNearestPoint` / `BeginPointDrag` 没有前置守卫，
   黑屏点击会写入无意义坐标。

第 1、3 条是缺陷；第 2 条是设计缺口——原设计只把画布当"参考图拾取板"，
没考虑"用户绑了输入图就想在图上直接拾取"这条最自然的用法（固定相机场景下它本来就是正确用法）。

## 二、改动清单

### A. 画布与刷新（`BeadInspectPluginConfigView.cs`）

| 位置 | 改动 | 依据 |
| --- | --- | --- |
| `MarkAsConfigInstance()` | 改幂等 + 订阅 `SrcImage.ValueChanged` | 对齐 Blob/卡尺范式；幂等防止 `Initialize`+`GetConfigView` 重复订阅 |
| `OnConfigSrcImageChanged`（新增） | 非 UI 线程 `UiDispatcher.BeginInvoke` 投递回 UI | 上游在流程线程发通知，直接动 `HImage`/绑定会跨线程 |
| `ShowPathBase()` | 改**四级优先**底图：①矫正后参考图 ②原始参考图 ③**输入图** ④空态 | 参考图是路径坐标系基准必须优先；无参考图时用输入图兜底 |
| `ShowInputOrEmptyBase()`（新增） | 上游图**只读复制**（`new HImage(src)`）后交给 `DisplayImage` | 上游图生命周期归流程轮次，**绝不 Dispose 它** |
| `SetBaseImage` / `IsCanvasEmpty` / `BaseImageHint`（新增） | 底图、空态、来源文案三处同时更新 | 避免"画布有图但状态栏写尚未载入"的自相矛盾 |
| `EnsureBaseImageForPick()`（新增） | 无底图时拒绝拾取 + 红字「请先载入图像（绑定输入图或填参考图路径）再拾取点」 | 黑屏拾取是本轮实测暴露的真问题 |
| `AddPoint` / `DeleteNearestPoint` / `BeginPointDrag` | 前置调用该守卫 | 同上 |
| `LoadRefImage` | 路径为空/文件不存在时**清 `_rawRefImage` 缓存**并重铺底图 | 否则切到"没填参考图"的配方时画布还糊着上一个配方 |
| `LearnRecipe` | 参考图检查加 `AlignMode == PlanarDeformable &&` 守卫 | 固定相机/匹配位姿本不需要参考图；此前"绑输入图→拾取→学习"这条流被堵死 |
| `DisposeConfigState` | 退订 `SrcImage.ValueChanged` | 订阅/退订成对 |

## 五、遗留

1. **`_BeadViewProbe\` 脚手架目录**（截图 + 行为自检探针，未加入任何 sln）：验证已完成，确认后可整目录删除；
2. **长提示换行是布局体系级问题**：某些 11pt `TextBlock` 首次测量在宽约束下会按整句渲染、越出窄列
   （⓪/③ 卡与"怎么用"卡都有潜质）。本轮按"会露出来的地方"逐处处理（拆句 / `MaxWidth`），
   彻底修需统一给长提示加宽度钳制，建议单开一轮；
3. **620×640（最小宽×最矮高）纵向仍溢出**：工具条折行 + 画布 + 参数卡 + 底行 ≈ 875px > 640。
   这是**改前就有**的问题（改前该列被撑到 1944px，现降到 875px）；宿主实际高度足够时无影响。
4. **未接真实相机流验证**：绑定场景用真样图赋给 `SrcImage.Value` 验证；每帧会多一次 `new HImage(src)` 复制，
   高频流下的开销未测。
