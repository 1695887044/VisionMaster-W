# SCADA 属性面板「所需权限」同步（2026-10-26）

## 一、当前状态

**结论：之前只在运行态/Web 同步了权限 Key，组态属性面板没有同步。**

- 运行态事件判权、Web 命令判权、页面级判权早已走 `RequiredPermission`（旧 `RequiredRole` 按 `LegacyRolePermission` 折算）。
- 组态属性面板仍只有旧的三档角色下拉：图元侧 `ScadaRolePropertyRow` 写 `RequiredRole`，画面侧 `ScadaPageProperties` 的 `RequiredRole` 行写 `page.RequiredRole`。
- 所以用户在「用户管理」里建的 15 条内置权限 + 自定义权限，在组态面板里**一条都选不到**；面板显示的仍是「无/操作员/工程师/管理员」。

本轮把面板迁到权限目录，并补掉一个同族缺口：旧 `.vms` 的元素 `RequiredRole` 在**运行态事件路径**上没有折算，老方案会被静默放权。

## 二、已做

### 1. 权限目录出口（`IScadaPermissionCatalog`）

新增 `Scada/Models/IScadaPermissionCatalog.cs`：只读 `PermissionCatalog` + `CatalogChanged` 事件。
`ScadaUserStore` 实现该接口，`CatalogChanged` 显式转发到 `BookChanged` / `GroupChanged`；
`App.xaml.cs` 把接口注册到同一个 `ScadaUserStore` 单例（不能另建一份，否则收不到目录变化）。

### 2. 领域层写入口（`ScadaPage`）

新增两个 `TrySetRequiredPermission`：

- `TrySetRequiredPermission(ScadaElement?, string?, out string)`：写 `element.RequiredPermission`，同时清空 `element.RequiredRole`。
- `TrySetRequiredPermission(string?, out string)`：页面级，写 `page.RequiredPermission`，同时清空 `page.RequiredRole`。

口径：

- 空/纯空白 = 不限制（`null`）。
- 有效权限没变是空操作（不刷 `Version`、不进撤销栈）；判据用 `RequiredPermissionOf()` 折算后的有效值。
- 撤销栈里的操作名：`设置所需权限 [名称] → 显示名` / `取消权限限制 [名称]`。
- 领域层**不校验 Key 是否在目录里**：目录属于宿主（用户管理），自定义权限、已删除权限的悬空 Key 都要能原样读出来。

### 3. 图元属性面板：角色行 → 权限行

- 删除 `ScadaRoleSpec` / `ScadaRolePropertyRow`。
- 新增 `ScadaPermissionSpec`（Key=`RequiredPermission`、显示名「所需权限」、组「交互」）。
- 新增 `ScadaPermissionPropertyRow`：候选来自权限目录（内置 + 自定义），第一项「不限制」用哨兵 `ScadaPermissionKeys.NotLimitedValue`（`__none__`，不落盘）。
- 当前值是旧 `RequiredRole` 时，面板显示 `LegacyRolePermission` 折算后的 Key（例如 Engineer → 运行控制），不再显示「工程师」。
- 当前值不在目录里（已删除权限/高版本 Key）时，候选末尾临时补一项「未知权限(Key)」，不会显示成空白。
- 目录变化时 `RefreshChoices()` 只重算候选，不重建行（不打断正在编辑的输入框）。

### 4. 画面属性面板：角色行 → 权限行

`ScadaPageProperties.All` 中原来的 `RequiredRole` 声明替换为 `RequiredPermission`：

- 显示名「所需权限」，组仍是「运行」，行数不变（原有 `Total(panel)` / 分组计数断言不需要改）。
- `ScadaPagePropertyRow` 对 `Spec.Key == "RequiredPermission"` 特判：候选同样来自权限目录，写回走 `Page.TrySetRequiredPermission`。
- 旧页面 `RequiredRole` 通过 `RequiredPermissionOf()` 折算显示；用户改选后写新字段并清空旧角色。

### 5. 运行态旧值兜底（同族缺口）

`ScadaRuntime.RequiredPermissionFor` 在显式 `RequiredPermission` 之后、运动/停止兜底之前，增加：

```csharp
if (element.RequiredRole is { } legacyRole)
    return ScadaPermissionKeys.LegacyRolePermission(legacyRole);
```

否则旧 `.vms` 里「工程师才能按」的按钮在桌面事件路径和 Web 命令路径上会对所有组敞开——面板读得出旧值、运行态却不认。

### 6. 断言

`ScadaChecks/Program.cs` 的 S12 段整体改写为权限行断言（共新增 18 条），覆盖：

- 候选来自目录（内置 15 + 自定义）、显示名来自目录、不给 ƒx；
- 默认「不限制」= `null`；选 Key 写 `RequiredPermission` 且清空 `RequiredRole`；撤销操作名；
- 同值空操作；外来图元拒绝；领域层接受自定义/悬空 Key；
- 旧角色 Engineer → 面板显示 `ControlRun`；运行态 `RequiredPermissionFor` 同样折算；
- 面板写下的 Key 就是运行态判权读的那一个；
- 悬空 Key 临时补项、改走后收回；空文案不当作「不限制」；
- 权限目录变化后下拉当场刷新；
- 页面级权限行：默认、写回、撤销操作名、旧页面角色折算、选「不限制」清旧角色。

## 六、踩过的坑

1. **删旧角色行时不要只按类名搜**：`ScadaRolePropertyRow` 还被基类注释 `<see cref="...">` 引用，删类后注释里的 cref 会变成编译警告/断链；本轮一并改成了 `ScadaPermissionPropertyRow`。
2. **插入领域方法时切掉了相邻文档注释**：`TrySetRequiredPermission` 插在 `TrySetRequiredRole` 与 `TryGroupElements` 之间，第一次替换把 `TryGroupElements` 的 `<summary>` 头吃掉了；靠回读源码发现并补回。同类问题还发生在 `ScadaEventSpec` 的类头。**大段 Edit 后必须回读插入点前后 20 行。**
3. **「不限制」不能用空串当值**：属性面板模板在 `Value == ""` 时会显示「未选择」占位，盖住下拉；改用 `__none__` 哨兵（不落盘，写回前折成 `null`）。空文案仍按「候选失配」标红，不静默放权。
4. **旧值折算必须在写新字段时清旧字段**：只写 `RequiredPermission = null` 而不清 `RequiredRole`，`RequiredPermissionOf()` 会回落到旧角色，表现成「明明选了不限制，却还要工程师」。
5. **`RequiredPermissionFor` 与 `RequiredPermissionOf` 是两条路径**：前者用于事件，后者用于写值/确认；只改后者会让旧 `.vms` 在事件路径上静默放权。本轮把两条都补上。
6. **构建 `BG1002`（找不到 .baml）是并行构建/陈旧 obj 的瞬态**：`-m:1` 重试一次即恢复；不要因此清整个 `UI\Controls\obj`（会拖慢并行会话）。
