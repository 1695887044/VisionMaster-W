## 1. 交付内容

### 1.1 新增插件工程

`Plugins\Plugin.ImageQuality\`：

| 文件 | 作用 |
| --- | --- |
| `Plugin.ImageQuality.csproj` | net9.0-windows / UseWPF / 四引用 / HALCON / `Help\**\*` 内嵌 |
| `ImageQualityService.cs` | 纯 HALCON 算法层（`internal static`，无状态）：对焦/曝光/对比度/饱和度 |
| `ImageQualityPlugin.cs` | 步骤类：2 输入端口 + 12 输出端口 + 14 个 `[StepConfig]` |
| `Help\01..05,10..12` | 8 页手册（5 用户 + 3 开发） |

**v1 范围**（按评审 D1 裁剪）：

- 做：对焦、曝光、对比度、饱和度四类指标 + 原始值 + 0~1 归一化分 + 明细；
- 不做：脏污（与 BlobDetect / DlAnomaly / DlSegment / DlClassify / ImageDiff 五条路重复，移 v1.1）；
- 不做：图像修改、烘焙、开窗、写全局变量、自定义视图；
- 默认 metrics-only：不配阈值只出数；配了阈值也只写 `IsUsable`，**不调 `Fail`**。

### 1.2 端口与参数

输入：`Image`（HImage，必填）、`Roi`（HRegion，可选）。

输出：

- 原始值：`FocusRaw`、`ExposureRaw`（%）、`ContrastRaw`（0~255）、`SaturationRaw`（0~255 / NaN）
- 分数：`FocusScore`、`ExposureScore`、`ContrastScore`、`SaturationScore`（0~1）
- 状态：`HasColor`、`IsUsable`、`Reason`、`Details`（string[]）

参数（14）：`FocusRef=200`、`ContrastRef=128`、`SaturationRef=128`、`MaxTruncationPercent=5`、`MinRoiPixels=16`、
`EnableThreshold=false`、四组 `Min/Max`（默认 0/1）。

### 1.3 算法口径

| 指标 | 口径 |
| --- | --- |
| 对焦 | `sobel_amp(gray→real, 'sum_abs', 3)` 均值；uint2 按 `255/65535` 归一化到 8bit 等效梯度 |
| 曝光 | `gray_histo_range(0..满量程, 精确箱数)` 的 0 箱 + 满量程箱占比（%）；不数平均灰度 |
| 对比度 | 同一灰度直方图的 P95 − P5（0~255 尺度） |
| 饱和度 | 彩色图 `decompose3 + trans_from_rgb('hsv')` 的 S 均值；灰度图 NaN/0 并写“跳过” |

## 3. 关键决策与踩坑

1. **`variance_image` 不存在**（HALCON 23.05）：对焦改用 `sobel_amp('sum_abs')`，对比度用 P5/P95，不用 `variance_image`。
2. **`gray_histo` 对 1 通道 uint2 的箱数与预期不符**：服务层原按 65536 箱检查，uint2 图直接失败；
   改用 `gray_histo_range(0, 满量程, 精确箱数)`，byte 256 / uint2 65536，截断与分位都精确。
3. **`scale_image` 在 byte 上会截顶**（输出仍是 byte）：造 uint2 夹具不能直接 `scale×257`；
   正确做法是 byte→uint2 换类型（0/255），再在 uint2 上 `scale×257`（0/65535）。
4. **`pcb_focus` 是过焦点扫描，不是单调散焦**：本插件 FocusRaw 峰值在 057（Tenengrad 峰值在 061），
   近焦平顶使“全序列 vs |i−61|”的 Spearman 只有 −0.822；断言改为
   “散焦段 061→121 ≤ −0.95 + 接近段 001→061 ≥ +0.90 + 峰值 ±5 帧”，既钉住方向又不误判。
5. **`IsUsable` 不改 `Success`**：质量不达标是测量结论，不是执行失败；拦截交给下游逻辑/判定表。
6. **灰度图饱和度输出 NaN/0 并写跳过**：不静默给 0 分；`HasColor` 供下游区分。
7. **并发构建锁**：本批期间遇到 `RG1000 calibrationview.baml` / `CS2012 Plugin.PoseTransform.dll` /
   `FlowCanvasChecks.exe` 残留锁，均为既有 C-12/C-13/C-27 同类；处理方式是 `dotnet build-server shutdown`
   + 结束自己的残留断言宿主后重试，不杀用户进程。
