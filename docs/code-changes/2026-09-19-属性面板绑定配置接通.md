## 一、需求与决策

### 1. 需求

对标商业组态软件时发现的**断链**：

- 运行侧（S6 数据泵）已经扎实——变量一变，图元属性就跟着变，坏绑定还打角标；
- 但配置侧是空的：属性面板上那颗 `ƒx` 按钮点下去只弹一句"未接入"的提示，**`VisionMaster` 里 `.Bindings` 一处都没被用过**。

也就是：机器能跑，但没人能给它配绑定。数据泵的入口喂不进东西。

本次把这条链从界面一直通到模型：**点 ƒx → 选变量 → 绑定落进图元的 `Bindings` → 运行态数据泵自然认得**。

### 2. 决策清单

| # | 决策 | 理由 |
|---|---|---|
| D1 | 改模型一律走 `ScadaPage.TrySetBinding` / `TryRemoveBinding`（D3 统一写入口） | "谁能改模型"只能有一个答案。将来加撤销/校验/权限时才有**一处**可改。面板、将来的脚本、导入向导都当它的调用方 |
| D2 | 一个属性**至多一条**绑定，换变量 = 复用原条目 | 一个属性被两个变量驱动时运行态只有后到者生效，而用户在界面上完全看不出这件事。复用还顺带保住了已配的停用/格式串——"换变量"不是"删了重配" |
| D3 | `TrySetBinding` 拒绝**空变量 Id** | 空 Id 是"只能按名字找"的旧数据形态（`ScadaBinding.IsLegacyByName`）。它是为读旧方案而存在的兜底，不该由设计器**现场制造**出来——一旦落盘，这条绑定永远走不上"改名不断"的正轨 |
| D4 | 属性键**是不是这个图元类型声明的键**，领域层不判 | 描述符在 `Scada.Controls`，而领域层刻意不引用它（见 `VM.Scada.csproj` 注释）。这层校验由调用方用 `ElementRegistry.FindProperty` 先做，运行态建表时再兜一次 |
| D5 | 属性键比较用 `Ordinal`（大小写敏感） | 这些键（`$X` / `Value` …）是描述符声明的**标识符**，不是给人看的文本。与 `ElementRegistry.FindProperty` 同一口径 |
| D6 | `HasBinding` **直接问图元**，面板不另存一份状态 | 面板永远是模型的一个视图。另存一份就是两个真相，迟早对不上 |
| D7 | `RemoveBinding` 返回 `bool` | 属性面板上"清除绑定"在本来就没绑的时候**不该把画面版本号刷高**（不然点一下空按钮就提示未保存）。调用方靠返回值区分"删了"与"没得删" |
| D8 | 成功**静默**，失败必说 | 绑上了是预期结果，弹窗道贺是噪音；失败（图元已被删等）不说，用户会以为点漏了 |
| D9 | 取消 **≠** 清空，另给显式清除入口 | `IScadaVariablePicker` 取消时**不触发回调**。把"清空绑定"藏在取消键里，等于让用户没法"只是想看看有哪些变量" |
| D10 | `Bindings` 的集合变更**转译**成属性变更往上冒 | 上层只对每个图元挂了一个 `PropertyChanged` 处理器来累计版本号，没再往子集合上挂第二层。转译掉就不用维护嵌套两级订阅——**漏摘一次就是泄漏** |
| D11 | 变量带占**值列**（与属性值同列对齐），不占整行 | 绑定是"这个属性的值被变量接管了"，缩进到值列才读得出这层从属关系；整行横铺会切断"属性—值"的对应 |

## 二、修改文件清单

### 领域层（2 个）

| 文件 | 改动 |
|---|---|
| `Scada/Models/ScadaPage.cs` | 新增 `#region 绑定：统一写入口（D3）`：`FindBinding(element, key)`（图元不属于本画面 → null）、`TrySetBinding(element, key, id, name, out error)`（三条拒绝：图元不属于本画面 / 属性键为空 / 变量 Id 为空；落点 `element.GetOrAddBinding(key).Bind(id, name)`）、`TryRemoveBinding(element, key, out error)`（本来没绑也算成立） |
| `Scada/Models/ScadaElement.cs` | 新增 `#region 绑定：查询与管理`：`FindBinding(key)`（`Ordinal`，同属性多条返回靠前者）、`GetOrAddBinding(key)`（复用而非再添一条）、`AddBinding(key)`、`RemoveBinding(key)`（返回是否真删）；新增 `OnBindingsChanged` / `Subscribe` / `Unsubscribe` / `OnBindingPropertyChanged`（把集合变更与单条绑定的属性变更都转译成 `Bindings` 的属性变更） |

### 视图模型（1 个）

| 文件 | 改动 |
|---|---|
| `VisionMaster/ViewModels/ScadaPropertyViewModel.cs` | ① `ScadaPropertyRowBase` 增两个虚属性 `HasBinding`(默认 false) / `BindingVariableName`(默认 null)——**放在基类**是为了让行模板只认"行"这个身份，不必认识 `ScadaPropertyRow` 具体类型（与编辑器按 `Kind` 分流同一手法）。② `ScadaPropertyRow` 覆写两者（直接问图元），并在 `RefreshValue()` 里补 `RaisePropertyChanged` 两个名字。③ 命令 `BindVariableCommand`（`CanExecute` = 行非空且 `IsBindable`）/ `ClearBindingCommand`（`CanExecute` = 行非空且 `HasBinding`）。④ `OnBindVariable`：取编辑器**当前画面**（图元模式下 `_page` 是 null），预选当前已绑变量，回调里走 `page.TrySetBinding`。⑤ `OnClearBinding`：走 `page.TryRemoveBinding`，**不动属性值本身** |

## 三、验证结果

### 断言（`dotnet run --project ScadaChecks`）

**647 通过 / 0 失败**（本轮新增 25 条：⑦/⑦B 16 条 + ⑪ 9 条；上一轮基线 622）。

**⑦ ƒx：选完变量即落模型**（8 条）

- 刚放下的图元没绑过：不显示变量带（绑没绑只问图元）
- 点 ƒx 选完变量：绑定真落到图元上（Id 是权威键、名字只作展示）
- 成功路径静默：不弹任何提示框
- 行自己回读绑定状态：变量带长出变量名、清除入口随之可用
- 再点 ƒx 换变量：**复用同一条绑定**，旧变量被顶掉
- 换绑复用原条目：用户已配的停用与格式串一并保住
- 换绑时弹窗**预选当前变量**（换绑是改一处，不是重新找一遍）
- 弹窗里点取消：原绑定原样留着；点清除：绑定摘掉、变量带收起、清除入口转灰
- `null` 参数与不可绑行（形状、字号）都不给 ƒx 亮着

**⑦B 领域层写入口自己也得站得住**（8 条）

- `TrySetBinding` 加一条真绑定 → 画面版本号涨起来
- 换变量：仍是同一条条目（不新增），版本号照样涨
- 拒绝空 Id / 拒绝不属于本画面的图元 / 拒绝空属性键（空格也不算键）
- 属性键比较大小写敏感：`IsOn` 与 `ison` 是两条不同的键
- `TryRemoveBinding` 真删 → 版本号 +1；幂等（本来没绑也算成立）且版本号不平白刷高

**⑪ 绑定态的"长相"：真渲染一遍，像素与视觉树双复核**（9 条）

把真 `ScadaPropertyView` 装起来**离屏渲染**成 PNG，再在像素与视觉树上双复核：

- 面板整体渲染成图：有实打实的高度、底色 `#FFF7F8FA` 真被刷出来、`DataContext` 未被换掉
- **整幅面板里只有绑过的那一行真的显示变量带**（对照组另一行未绑）
- 变量带里写的就是变量名，带底 `#FFEAF3FF` / 带边 `#FFC6DDF5`、有 ✕
- 变量带的底色真的落在画面上（带内采到 `#FFEAF3FF`）
- 绑过那行的 ƒx = 蓝 `#FF2A6BB5` + `SemiBold`；没绑那行 = 灰 `#FF909399` + 非 `SemiBold`
- 蓝 ƒx 在画面上真画出来了；灰 ƒx 那一格里**采不到蓝**（对照组成立，否则上一条可能只是别处漏过来的颜色）

> 用**真 View** 而不是照 XAML 另搭一份 Grid：只有真 View 才能证明"面板确实长这样"，重搭一份验的只是重搭的那份（XAML 改坏了断言照样绿）。

## 四、已知边界

1. **属性键合法性未在落库前把关**：`TrySetBinding` 只判"键非空"，判不了"这个键是不是该图元类型声明的"。面板上 ƒx 只在 `IsBindable` 的行出现，实际挡住了误配；但脚本/导入向导这类新调用方必须自己先查 `ElementRegistry.FindProperty`（D4）。
2. **`ScadaBinding` 缺 `输出反向` / `写模式` 字段**：对标软件在绑定上还有这两个开关，本链未做。运行态数据泵目前是单向"变量 → 图元"。
3. **`ValueChanged` 事件仍未在任何描述符上声明**：绑定值变化触发的钩子暂时配不出来。
4. **画面级绑定无入口**：面板的画面模式（未选中图元时）`IsBindable` 恒为 false，画面属性还不能绑变量。
5. **离屏渲染的 `IsVisible` 恒为 false**：没接 `PresentationSource`，所以"用户看不看得见"只能自己沿视觉树往上问 `Visibility`（断言里的 `IsShown`）。这条约束对将来任何离屏渲染断言都成立。
6. **`DataTemplate` 会给每一行都造一份变量带**：未绑的行只是被 `Collapsed` 收掉（元素仍在视觉树里、尺寸为零）。按"树里有没有"去数会把它们全数进来——⑪ 节第一次跑就撞上（数到 15 条），已用 `IsShown` 过滤。**将来数行数一律要带这一层过滤**。
7. **断言宿主渲染带 `AutoWireViewModel` 的 View 需要先喂工厂**：Prism 9 在 `InitializeComponent` 里**立刻**解析 VM，宿主没有 Prism 容器时回落到 `Activator`，而 `ScadaPropertyViewModel` 无无参构造 → 炸在 XAML 解析期。解法是 `ViewModelLocationProvider.Register<ScadaPropertyView>(() => panel)`，**生产代码一字未改**。
8. **SCADA 新代码尚未纳入版本控制**：`Scada/`、`Scada.Controls/`、`ScadaChecks/`、`VisionMaster/Services/IScada*` 等仍是未跟踪状态（见 `git status`）。这是当前头号风险。
