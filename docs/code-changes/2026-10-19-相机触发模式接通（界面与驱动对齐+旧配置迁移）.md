# 相机触发模式接通（界面与驱动对齐 + 旧配置迁移）（2026-10-19）

## 0. 结论

修掉了 P1「相机触发模式：界面有、驱动没接」：

- 海康驱动现在**读取并下发** `CameraSettings.TriggerMode`，支持 **连续采图 / 软触发 / 上升沿 / 下降沿** 四档；
- 软触发由「图像采集」步骤在每次取图前下发 `TriggerSoftware`，不再依赖 MVS 手动触发；
- 触发源线号（Line0~Line3）与触发延时（μs）可配；
- 驱动下发后**回读 `TriggerMode`**，不一致会阻断打开/应用，不再出现"界面说上升沿、相机连续出图"；
- 旧方案（没有 `TriggerSchemaVersion`）自动迁移成 `Continuous`，保持升级前的真实行为，旧流程不会因为没人下发软触发而全部超时。

## 1. 背景

改动前：

- 契约/界面有 `CameraSettings.TriggerMode`（`Software/RisingEdge/FallingEdge`），相机设置界面可下拉、可保存、可回显；
- 海康驱动 `OpenCore` 无条件写 `MV_CC_SetEnumValue_NET("TriggerMode", 0u)`（连续采图），`ApplySettingsCore` 只写曝光/增益；
- 结果是"界面选上升沿 → 应用成功 → 相机仍连续出图"，无异常、无 Warn、无超时；海康插件手册虽然写明了这个限制，但相机设置界面没有提示（网络相机有提示，海康没有）。

## 2. 改动清单

### 2.1 契约层

| 文件 | 改动 |
| --- | --- |
| `Shard/Core.Interfaces/Camera/CameraTypes.cs` | `CameraTriggerMode` 追加 `Continuous = 3`（旧值 0/1/2 不变）；补"本仓枚举值 ≠ GenICam 节点值"的注释 |
| `Shard/Core.Interfaces/Camera/CameraSettings.cs` | 新增 `TriggerSchemaVersion`（默认 1，旧配置缺省 0）、`TriggerSourceLine`（0~3）、`TriggerDelayUs`；`Clone` 复制；`Normalized` 做旧配置迁移与夹取 |
| `Shard/Core.Interfaces/Camera/ICameraDevice.cs` | 新增 `SupportsSoftwareTrigger` / `SupportsHardwareTrigger` / `TriggerSoftware()`（默认实现 false，向后兼容） |
| `Shard/Core.Interfaces/Camera/CameraDeviceBase.cs` | 新增三个 virtual 成员（默认不支持，Hikvision 覆盖） |

**迁移口径**：`TriggerSchemaVersion < 1` 时 `Normalized()` 把 `TriggerMode` 改成 `Continuous` 并把版本置 1。原因：旧驱动实际一直连续采图，旧值不生效；若升级后把旧值当软触发执行，旧流程会因为没人下发 `TriggerSoftware` 而全部等图超时。

**迁移实现的一个坑（已由断言钉住）**：`TriggerSchemaVersion` 的属性初始值必须是 **0**，不能是 1——Newtonsoft 反序列化缺失字段时会保留属性初始值，初始值写 1 就永远识别不出"旧 JSON 没这个字段"，迁移会静默失效。新建配置统一走 `CameraSettings.CreateNew()` 显式置 1；`CameraDescriptor.Settings`、`CameraProvider`、相机设置界面都已改用工厂。`CameraTriggerChecks` 里有一条**真实 JSON 反序列化**用例专门守这一点。

### 2.2 海康驱动

| 文件 | 改动 |
| --- | --- |
| `Plugins/Plugin.Camera.Hikvision/HikvisionTriggerPlan.cs` | 新增纯映射：`CameraTriggerMode` → `TriggerMode(0/1)` + `TriggerSource` + `TriggerActivation` + `TriggerDelay`；线号/延时夹取；空配置回落连续采图 |
| `Plugins/Plugin.Camera.Hikvision/HikvisionCameraDevice.cs` | 删除写死 `TriggerMode=0`；`OpenCore` 先 `ApplyTriggerSettingsCore`（失败阻断打开并 `CloseCore`），再应用曝光/增益（失败只 Warn）；`ApplySettingsCore` 在采流中先停流再改触发；新增 `TriggerSoftware()`（`MV_CC_SetCommandValue_NET("TriggerSoftware")`）与能力位 |
| `Plugins/Plugin.Camera.Hikvision/MvsRuntime.cs` | 新增 `EnumValue(typeName, memberName)`，供老版本 SDK 没有 `MV_CC_SetEnumValueByString_NET` 时按枚举数值兜底 |

**下发顺序**：`TriggerMode=0` → `TriggerSource` → `TriggerActivation` → `TriggerDelay` → `TriggerMode=目标值`；随后回读 `TriggerMode`，不一致抛"触发模式回读不一致"。

**码值口径**：本仓 `CameraTriggerMode.Software = 0` 与 GenICam 节点 `TriggerMode=0`（关闭）数值相同、语义相反；映射只走 `HikvisionTriggerPlan`，禁止按数值直接透传。

### 2.3 采集步骤

`Plugins/Plugin.ImageAcquisition/ImageAcquisitionPlugin.cs`：

- 取图前读 `device.ReadSettings()`；
- `TriggerMode == Software`：
  - 驱动支持软触发 → 先 `TriggerSoftware()`，失败返回"软触发失败"（不再退化成等图超时）；
  - 驱动不支持软触发但支持硬触发 → 明确报"驱动不支持软触发，请改连续采图或上升沿/下降沿"；
  - 两个能力都不支持（网络相机）→ 触发由外部客户端决定，跳过软触发直接等帧；
- 等图超时文案追加触发模式与排查提示（上升沿/下降沿会提示检查 PLC/光电/编码器与相机 IO 线）。

### 2.5 断言

新增 `FlowCanvasChecks/CameraTriggerChecks.cs`（27 条，注册在 `HikvisionChecks.Run()` 之后）：

1. **映射**：连续→0；软触发→1 + `Software`（明确不是 0）；上升/下降沿→1 + `LineN` + 对应边沿；线号/延时夹取；空配置→连续；枚举数值追加式（0/1/2/3）；
2. **迁移**：旧配置（无版本）Software/RisingEdge → Continuous；新配置保留 Software；Clone 复制触发字段；
3. **采集步骤**（假 `ICameraDevice`）：
   - 软触发：`TriggerSoftware` 在 `WaitNextFrame` 之前，且只调一次；
   - 上升沿/连续：不调 `TriggerSoftware`；
   - 驱动不支持软触发：明确失败，不进入 `WaitNextFrame`；
   - 软触发命令被拒：明确报"软触发失败"，不再等帧；
   - 外部驱动（网络相机）：不调软触发，直接等帧；
   - 超时文案带触发模式（上升沿含 PLC/光电提示，连续含"连续采图"）。

## 4. 未做 / 边界

- **真机节点名/回读需现场探针确认**：`TriggerSource` / `TriggerActivation` 优先用 `MV_CC_SetEnumValueByString_NET`，老版本 SDK 用 `MV_CAM_TRIGGER_SOURCE` / `MV_CAM_TRIGGER_ACTIVATION` 枚举数值兜底；不同 MVS 版本若节点名/枚举名不同，会以"缺少方法/类型/回读不一致"明确失败，不会静默。上线前建议用一台真相机验证：软触发"不触发不来帧、每触发一次恰好一帧"，硬触发"每来一个脉冲恰好一帧"。
- **多相机同步**未解决：每台相机各自按自己的触发设置出图；需要同一时刻曝光时，仍要 PLC/同步盒给所有相机同一触发信号（或后续做同步采集步骤）。
- **网络相机触发**仍由客户端决定，界面警告不变；采集步骤检测到驱动两个能力都不支持时直接等帧，不会误报软触发失败。
- **旧配置迁移**只做一次：`TriggerSchemaVersion` 落盘后不再重复迁移；用户重新选触发模式并应用即可。
