## 1. 最终做法

「数据源」那一行 = `Core.Controls.LinkableValueEditor`，按 R189 的强制范式接线：

```xml
<ContentControl Content="{Binding}" ContentTemplate="{StaticResource RulePortEditorTemplate}" />
<!-- RulePortEditorTemplate -->
<cc:LinkableValueEditor LinkAddress="{Binding LinkAddress, Mode=TwoWay}"
                         StepData="{Binding DataContext.StepData, RelativeSource=...}">
  <cc:LinkableValueEditor.Port>
    <MultiBinding Converter="{StaticResource InputPortConv}">
      <Binding Path="InputPortName" />
      <Binding Path="DataContext" RelativeSource="{RelativeSource AncestorType=UserControl}" />
      <Binding Path="DataContext.PortsVersion" RelativeSource="{RelativeSource AncestorType=UserControl}" />
    </MultiBinding>
  </cc:LinkableValueEditor.Port>
</cc:LinkableValueEditor>
```

| 交互 | 行为 |
|---|---|
| 未连线 | 框内**手填常量**（`InputPort<object>`，控件 `IsTextEditableType` 含 `object`）；确定时由 `VisionPluginBase.OnConfirm` 写进 `InputValues` |
| 🔗 | 控件内部发 `LinkPathEvent`（单绑定模式，`InputPortName = 实际_{规则名}`），自己 `StepData.SetLink` |
| ✕ | 控件自己 `RemoveLink` + 清回显 |

配套三处（少一处就静默坏）：

| 位置 | 改动 | 漏了会怎样 |
|---|---|---|
| `JudgeTableView.xaml.cs` | 新增 `InputPortConverter`（端口名 + 插件 + `PortsVersion` 三路） | 端口每次重建换新对象，编辑器会一直指着已 Dispose 的旧端口 |
| `JudgeTablePlugin.GetInputPort` | 按端口名现取当前对象（转换器落点） | 同上 |
| `JudgeRule.LinkAddress` | `[JsonIgnore] string?`，**null = 未连线**；`SourceText` 由它派生 | 绑"未连线"这类非空文案 → 控件按"非空即已链接"渲染，地址框显示"未连线"、输入框被折叠 |

## 2. 三代实现与为什么只剩这一版

| 版本 | 做法 | 结局 |
|---|---|---|
| 一 | 自建 `BindSourceCommand` +「绑定…」按钮，自己 `Publish(LinkPathEvent)` | 撤。与 `LinkableValueEditor.LinkBtn_Click` 逐字重复，白丢 ✕ 解绑与手填常量；且 R189 明令禁止手搓 |
| 二 | 控件 + `JudgeRule.InputPort` 属性（插件重建后重赋） | 撤。R189 判据②要求动态端口必须走 `MultiBinding` + `PortsVersion`；单属性缓存等于把"重取"责任放在插件时序上 |
| 三（现行） | 控件 + `InputPortConverter` + `ContentControl`/`DataTemplate` 按需实例化 | 符合 R189 判据①②，`JudgeRule.InputPort` 已删除（不留第二套机制） |

R189 原文曾把「`Plugin.JudgeTable` 的规则折叠行」举为"允许手写 `LinkPathEvent`"的例外；本版迁移完成后该例外已不存在，规则正文同步改成「当前**无此类例外**」并把 `Plugin.JudgeTable`（`RulePortEditorTemplate`）补进范式清单。

## 5. 踩过的坑

- **并发会话同时改同一批文件**：本轮期间另一会话在同一批文件上落 R188/R189、迁移 `Plugin.ResultUpload`、给判定表补 `OnCancel` 连线回滚。编辑工具会报 `File has been modified since read` —— 必须重读再改，不能凭上下文里的旧内容替换；`AGENTS.md` 字节数也会在你读完之后变化（本次 46,910 → 50,385）。
- **跑闸门时用户启动宿主**：`run_gates.ps1` 的 3 个构建步（DatabaseChecks / FlowCanvasChecks / ScadaWebChecks）报 `MSB3027/MSB3021 文件被 VisionMaster (PID) 锁定`。判据：多个不相干构建步同时红 + 日志含"文件被 VisionMaster 锁定" = 环境，不是代码；等宿主退再原样复跑（本次两次复现，第二次即 16/16）。
- `Modules\` 里没有契约程序集（红线②），临时探针解析依赖要回落到 `VisionMaster\bin\Debug\net9.0-windows`。
- 用 `-p:ModulesDir=<临时目录>` 可以**只验证编译不碰 Modules**（宿主开着时的正确做法）。
- `dotnet build` 输出经管道按 936 解码成乱码（R183）：判绿只看 `0 个错误` 与退出码。
