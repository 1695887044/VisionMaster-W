# 弹窗「白框」收口（透明窗口 + 投影分层）

- 日期：2026-10-22
- 范围：`VisionMaster\Views\DialogViews\` 下 8 个弹窗视图（清单见 §2）
- 起因：用户截图反馈系统设置弹窗四周有一圈白边（"把这个白色边框去掉"）；修完第一个后用户要求
  "一起修复了"，于是把同一套旧壳的其余弹窗一并收口。

## 1. 根因：不是描边，是窗口底色露出来了

这批弹窗共用一个"无系统边框 + 卡片 + 投影"的旧壳，三件事叠在一起就出白框：

1. `prism:Dialog.WindowStyle` 只设了 `WindowStyle=None` / `ResizeMode` / `SizeToContent`，**没设 `Background`**
   → 窗口底色是默认白；
2. 根布局 `Grid Margin="15"`（`HelpView` 是 `6`），卡片内缩，这圈留白露出窗口白底；
3. 卡片自带 `DropShadowEffect`，阴影只压暗**内圈**，最外圈仍是纯白。

以系统设置弹窗的截图逐像素取证（760×628 原图，沿 y=300 横扫）：

| x | 颜色 | 是什么 |
| --- | --- | --- |
| 0–3 | `#FFFFFF` | 窗口白底（阴影没够到的外圈） |
| 4–13 | `#FEFEFE` → `#F0F0F0` | 投影渐变 |
| 14 | `#EDEDED` | 投影最深一圈 |
| 15–34 | `#FFFFFF` | 卡片左内边距 |
| 35–209 | `#F8FAFC` | `CardPropertyGrid` 左导航栏 |
| 210 | `#E2E8F0` | 导航栏右分隔线 |

卡片自身没有任何 `BorderBrush`——白框 100% 来自窗口背景 + 那圈留白。

同一问题 2026-10-21 在 `ScadaLoginView` 上已经治过一次（用户当时的原话也是"白框"），
口径见 `docs\code-changes\2026-10-21-用户登录双栏改版与系统菜单去重.md` §1。

## 2. 改法（每个文件两处，逐字同形）

1. `WindowStyle` 补两条：`AllowsTransparency=True` + `Background=Transparent`。
   卡片外那圈留白变成纯投影区，阴影直接落在主界面上，白底窗口边消失；
   透明像素在分层窗口里不参与命中测试，点击会穿过去（不会挡住背后界面）。
2. **投影层与内容层分离**：把 `DropShadowEffect` 从承载文字的卡片 `Border` 挪到同尺寸的空 `Border` 上，
   内容层再叠在上面。这是仓里 `DialogCardShadow` / `DialogCardBorder` 的既有口径
   （`docs\code-changes\2026-09-22-UI青蓝风统一.md`）：投影不挂在有内容的元素上，避免整棵内容树
   先栅格化再合成。
   注意：`AllowsTransparency=True` 的分层窗口本身只能走灰度抗锯齿（ClearType 需要不透明底），
   所以这一条的收益主要是"投影不作用在内容树上"（少一层中间位图），不是"文字变清晰"；
   真要 ClearType 就得放弃透明窗口，那白框会回来——与 `ScadaLoginView` 的取舍一致。

**没有引入任何 `{StaticResource}`**：断言宿主 `ScadaChecks` 直连 `new 视图()`（没有 Application，
应用级资源取不到），引 App 级键会在 XAML 解析期抛（R22）。`HelpView` 原有的
`{StaticResource DialogShadowColor}` 是既有写法，未新增依赖。

### 2.2 HelpView 的留白从 6px 加到 12px

`HelpView` 的投影是 `BlurRadius=10 / ShadowDepth=2`。实测扩散规律（系统设置弹窗那一组：
`BlurRadius=15` 的横向扩散约 11px，≈ 0.73×R），`BlurRadius=10` 约 7px 扩散。
原来留 6px 是**白底窗口**，阴影被窗口边界裁掉也看不出来；窗口一透明，那道裁切线就变成
一条可见的硬边。所以留白取 12px，让阴影在窗口内自然衰减到 0。
2026-10-16 真机反馈的"窗台与容器之间一道空缝"指的是白底那圈，透明后已不存在，故原注释一并改写。

## 3. 没动的（不是同一个病）

- `PluginConfigShellView.xaml`：根布局是 `Grid Margin="0"`，卡片铺满窗口，**没有白框**。
  它的 `DropShadowEffect` 本来就被窗口边界裁掉（等于没有投影），属于另一件事，本次不碰。
- `ScadaLoginView.xaml`：2026-10-21 已是透明窗口 + `DialogCardShadow` 分层，本次无需改。
- `CommunicationSettingsView` / `GlobalVariableView` / `HardwareManagerView` 等：窗口由
  `DialogBackgroundBrush` 铺满（不是"卡片浮在留白上"），不存在白框。

## 4. 验证

- `dotnet build VisionMaster\VisionMaster.csproj`：**0 错误**（退出码 0；只有既有的
  `PluginConfigShellViewModel.cs` CS8604 可空性警告）。
- `dotnet run --project ScadaChecks`：**2437 通过 / 1 失败**，与改动前同一结果。
  通过的里面含最相关的那条：「弹窗视图能真造出来并完成一次布局」→ `760×600`
  （XAML 解析、资源键、布局都正常）。唯一失败项是 `FlowListView.xaml` 的
  「流程卡片按 RunState 出运行中/已暂停标记」静态扫描，扫的文件与本次改动无关。
- `dotnet run --project HelpProbe`：**全部通过**（1388 行输出，末行 `=== HelpProbe: 全部通过 ===`）。
  5 张手册页截图落在 `_help_preview\`，卡片圆角、目录树、正文表格渲染均正常（留白 12px 后无裁切）。
  ⚠ 调用坑：别给 `dotnet run` 加 `--nologo`——它会被当成**程序参数**转发给 HelpProbe
  （HelpProbe 把 `args[0]` 当输出目录），现象是渲染阶段 `DirectoryNotFoundException`，
  看起来像"改动把渲染搞崩了"，实际是命令行用错。
- **真机未验**：需要重启软件逐个打开弹窗看一圈——投影应直接落在主界面上，
  卡片外不再有白色矩形边。透明窗口是分层窗口，**首次打开时若窗口尺寸有跳变属于 WPF 已知现象**，
  本次 8 个弹窗都是固定尺寸或 `SizeToContent`，无动态改尺寸路径。
