# 组态基座画面：跨页公共层（2026-10-18）

> 用户原话：「我当前的底板实现不符合预期。我期望的底板是一个可复用的通用基础布局/容器，
> 能够作为所有界面的统一基座，被每个页面继承或包裹使用，而非仅服务于单个页面。」
>
> 追问后定下两条语义：**基座走实时引用（改一次全部页面生效）**；**基座在下、本页在上**。
>
> 本轮**不改**已有的 `Hmi.Panel`（底板）——它是"单页内的区域框"，基座是"跨页的公共层"，
> 两者互补：底板管"这一页里的一块区域"，基座管"所有页面共用的那一层"。

---

## 一、现有实现为什么不符合预期

| # | 现状 | 为什么不够 |
| --- | --- | --- |
| 1 | `Hmi.Panel`（`PanelElement`）是**图元**，挂在某一页的 `Elements` 里 | 它只属于那一页。想在 20 个页面里都有同一条报警栏，只能复制 20 份；改一处要改 20 处，且**没有任何机制保证 20 份保持一致** |
| 2 | 图元的父子关系（`ParentId`）是**页内**关系 | `ParentId` 指向的是同一页里的图元（`ScadaPage.GetChildElements`），跨页没有承载物 |
| 3 | 画面之间只有"导航"关系 | 导航是"切到另一页"，不是"叠在这一页下面"。导航过去的页面**没有本页内容**，天然不能当基座 |
| 4 | 复制/粘贴是唯一的"复用"手段 | 复制出来的是**快照**，不是引用——改一处不会传导到其它份 |

一句话：缺的是**"文档级的母版层"**，而现有的一切复用机制都是"页内"或"快照"。

---

## 二、设计取舍：组合 + 实时引用（不做页面继承）

**不做"基类页面"（`class 产线A : 公共基座`）**，三条理由：

1. 基座是**运行时数据**（用户在编辑器里画出来的），不是编译期类型。把数据变成类型继承树，
   序列化要写 `$type`、改名要改类型名、撤销要能回退"类型"——复杂度直接跳一个量级。
2. 一个页面将来可能需要**换基座**（同一套布局，不同产线皮肤）。继承关系改不了，
   引用关系一句话就改了。
3. 继承会把"基座的图元"和"本页的图元"揉进同一个 `Elements` 集合，之后每一次
   复制/删除/撤销都要重新回答"这个图元到底是谁的"——两份真相。

**采用的模型**：

```
ScadaDocument
├─ Pages       : 全部画面（含"被注册成基座"的那些——它们也要落盘、也要能进编辑器）
├─ BasePages   : 其中"可作为基座"的子集（引用它的画面从这一份里挑）
└─ 每个 ScadaPage
   ├─ Elements      : 本页图元（绝对坐标，与以前完全一致）
   └─ BasePageId    : 引用哪只基座（Guid.Empty = 不引用）
```

- 基座本身**就是一份普通的 `ScadaPage`**：能进画面列表、能被选中、能画、能存。
- 页面只多一个 `BasePageId`。渲染时把"基座图元 + 本页图元"合成一棵树，基座先画。
- **实时引用**：基座只有一份数据。改基座的图元/属性，所有引用它的页面**下一次渲染就是新的**
  （画布订阅了基座的 `PropertyChanged`，见 §四）。
- **悬空不清理**：基座被删/被摘除时，`BasePageId` 留着不清（撤销能找回来），
  渲染侧 `ResolveBase` 返回 null → 按"无基座"降级，本页内容一条不丢。

## 四、各页面如何接入（操作路径）

### 顶栏布局（2026-10-18 第二轮：按"现代 UI"重排）

```
画面 [画面_1 ▼]   基座 [基座_1 ▼]   ＋新建 ▾  🗑   |   ↶撤销 ↷重做   ……   ▶运行画面
```

| 改动 | 为什么 |
| --- | --- |
| 基座下拉补上独立标签「基座」 | 两个并排的无标签下拉框看起来像"两个画面选择器"，用户分不清哪个是基座 |
| 「新建」+ 右侧 ▾ 下拉（分裂按钮） | 原先 `新建` 与 `新建基座` 两个并排文字按钮读起来像"同一件事的两个说法"；而新建基座是低频动作，不该占常驻按钮位。主按钮一次点击 = 新建画面（最常用），▾ 里是「新建画面 / 新建基座（跨页公共层）」 |
| 「删除」改成图标按钮（trash）+ 悬停说明 | 三个文字按钮并列时，最容易误点的恰是删除；图标把它从视觉重心上降下来 |
| 编辑基座自己那一页时基座下拉置灰 | 一层限制在模型里本来就会拒，但"选一个注定被拒的值、再弹回原值"是最像"软件坏了"的交互；置灰 + ToolTip 让规则自解释（`CanSelectBasePage`） |

> 顶栏的视觉验收不再靠人眼碰运气：`ScadaChecks` 的 `[T]` 段把整个视图真装一遍并出图
> （`artifacts/scada-editor-toolbar.png`），同时断言两个标签都在、▾ 菜单是两项且都绑了命令、
> 基座下拉在引用页可用 / 在基座页置灰。

### 编辑态：三步

1. **新建基座**：顶栏「新建基座」按钮（`AddBasePageCommand`）——建一份画面、立刻注册成基座、
   并切过去编辑。名字按「基座_1」「基座_2」自动取未被占用的最小号。
2. **在基座自己的页面里画公共内容**：边框、报警栏、公共指示灯、公司 Logo。
   基座图元**只有**在这一页里能选中/拖动/改属性。
3. **让页面引用它**：顶栏「基座」下拉选它（或属性面板「基座」行）→ `TrySetBasePage(当前页, 基座)`。
   新建页面时会**自动沿用当前页的基座**（`AddPage(name, basePageId)`），
   所以"建一批长得一样的页面"不需要每页再选一次。

> 为什么是"新建基座"而不是"把当前页注册为基座"：基座是一份**独立的公共层**，
> 它的内容不该和某一页的业务图元混在一起。"把画好的一页提升为基座"会让那页的业务内容
> 突然变成所有页面共享的东西——一次误操作影响面是整个方案。

### 运行态：零配置

画布绑定 `BasePage="{Binding CurrentBasePage}"`，切页时基座跟着换。基座上的图元照常参与绑定
（曲线、报警条、公共指示灯都能活）——因为 `EnumerateControls()` 把它们和本页图元一起交出去了，
`ScadaRuntimeBinder` 建表时看到的就是"全量渲染的图元"。

### 基座图元在引用页上只读（三个闸门）

| 闸门 | 位置 | 挡住的行为 |
| --- | --- | --- |
| 选中集合 Coerce | `ScadaCanvas.CoerceSelectedElements` → `TrimForeignBaseElements` | 框选、宿主赋值、绑定回写把基座图元塞进选中集合 |
| 主选中 Coerce | `ScadaCanvas.CoerceSelectedElement` | 点选/右键把基座图元设成主选中（属性面板就没有可改的目标） |
| 编辑能力 + 命中 | `CanEditElement`（拖动/改尺寸手柄/"锁住"样式都读它）+ 左右键命中判据 | 拖动、改尺寸、右键图元菜单 |

判据只有一处：`IsForeignBaseElement(element)` = 属于 `BasePage.Elements` 且不属于 `Page.Elements`。
基座自己的编辑器 `BasePage == null`，所以那边照常可编辑——不需要另开"是否基座编辑态"的开关。

## 五、叠放与坐标语义

| 项 | 口径 | 为什么 |
| --- | --- | --- |
| 叠放 | 基座先画（在下），本页后画（在上） | 用户裁定；由 `EnumerateItems()` 的产出顺序表达，不靠 ZIndex 全局重排 |
| 坐标 | 基座图元与本页图元**都用画面绝对坐标** | 两页尺寸一致时，"公共层画在哪"与本页坐标是同一套账；不引入"相对基座"的二次换算 |
| 尺寸不一致 | 各画各的（基座按自己的坐标画，超出本页视口的部分自然看不见） | 不做缩放适配：那会让"设计坐标 = 运行坐标"这条基本盘失效 |
| 底色 | **画布底色始终取本页的 `Background`**；基座的 `Background` 不参与合成 | 两页各有背景时，谁压谁都会静默吃掉对方的设置。基座要底色就放一个铺满画面的矩形图元——它是内容，会正常叠进合成里 |
| 选中 | 基座图元在本页**不可选中**（只渲染，不参与本页的选中/拖动/删除） | 否则"在本页删了它"会删到别页共用的公共层，语义灾难 |

> 最后一条是画布的现状口径：`_containerIndex` 里基座图元也在，但本页的选中集合来自
> `SelectedElements`（本页模型），基座图元不在其中。若要支持"在本页也能点选基座图元"，
> 必须同时定义"点了之后改的是谁"——本轮刻意不做（见 §九）。

## 六、导航口径：基座是公共层，不是终点

基座画面**同时也在 `Pages` 里**（要落盘、要能进编辑器），所以按 Id 一定找得到它。
但它是"叠在本页下面的公共层"，单独显示它 = 一张没有本页内容的空画面。

判据只在 `ScadaDocument` 一处实现：

```
FindNavigablePage(id)      = Pages 里、且 !IsBasePage(p)
FindNavigablePageByName(n) = 同上，按名
IsNavigable(page)          = 在本方案 Pages 里、且 !IsBasePage(page)
```

四个消费点全部改走它：

| 消费点 | 改前 | 改后 |
| --- | --- | --- |
| `ScadaRuntime.Navigate(Guid…)` | `FindPage` | `FindNavigablePage`；目标是基座时给专属原因 |
| `ScadaRuntime.Navigate(page)` | `FindPage(id)` 引用比对 | `IsNavigable` |
| `ScadaRuntime.GoBack()` | `FindPage(id)` 引用比对 | `IsNavigable`（运行中改方案也能跳过） |
| `ScadaDocument.ResolveStartupPage()` | `FindPage` + 回落第一页 | `FindNavigablePage` + 回落第一个非基座页 |
| `SetStartupPage(page)` | `Pages.Contains` | `IsNavigable`（基座不能当启动画面） |
| `ScadaPagePickerViewModel` | 遍历 `Pages` 全量 | 跳过基座 |

`FindPage` / `FindPageByName` **保持全量**（编辑、属性面板、持久化都要能找到基座）——
"可寻址"与"可导航"是两件事，混成一个方法的后果是其中一边必然错。

## 七、一层限制与加载期规范化

**一层**（基座不能再引用基座）：渲染侧只合成两层（基座压底 + 本页），
链上第二层会被**静默丢掉**——现场看到的是"基座改了没反应"，比报错难查得多。
所以这个不变量在**两个入口**都拦：

- `TryAddBasePage`：该页自己已引用别的基座 → 拒绝；
- `TrySetBasePage`：引用方本身是基座 → 拒绝。

外加 `CreatesCycle` 作为防御（正常编辑路径到不了，但手改过的 `.vms` 可能带着链）。

**加载期规范化**（`EnsureIdentity`，与旧数据迁移同一个作用域：不进撤销栈、不过写守卫）：

1. `BasePages` 里不在 `Pages` 里的**幽灵条目**直接摘掉（页面被删时集合可能还留着它）；
2. 基座画面上的 `BasePageId` 一律清成 `Guid.Empty`（把链拆成一层）。

两条都返回在"修复处数"里，加载流程照旧统计。

### 8.1 断言（`ScadaChecks`）

`[B] 基座画面` 段（模型层 + 运行态）与 `[X] 画布渲染` 段的基座合成小节：

| 组 | 钉住的事实 |
| --- | --- |
| 注册/引用 | 注册为基座、出现在 `BasePages`、重复注册幂等；两页指向同一只基座 |
| 实时传导 | 改基座的 `Background`，两页 `ResolveBase` 都看到新值 |
| 一层限制 | 基座再引用基座被拒（且 `BasePageId` 未被污染）；已引用基座的画面不能再注册为基座 |
| 环/自引用 | 两页互引被拒；基座引用自己被拒 |
| 降级 | 摘除基座后引用字段不清理；`ResolveBase` 返回 null；重新注册 + 重新引用后画面又看到基座 |
| 启动画面 | 基座不能当启动画面（设了等于没设）；未指定时回落**跳过**基座 |
| 导航 | 按 Id / 按名都找不到基座；跳基座被拒且原因是专属文案；按对象跳同样被拒 |
| 运行态投影 | `CurrentBasePage` 跟着当前页走；切页时发通知 |
| 画面钩子 | 基座的 `Loaded` 命中 0 次；本页 `Loaded` 命中 1 次（**正反对照**，防止"钩子机制没跑"伪装成通过） |
| 回退 | 运行中某页被改成基座 → `GoBack` 跳过它 |
| 注册/删除可撤销 | 注册基座可撤销；删除基座画面时**同时**从 `BasePages` 摘除（否则被删的画面仍能被引用）；一次撤销把"画面 + 基座登记"一起恢复 |

| 只读口径 | 引用页上 `SelectedElement = 基座图元` → 被强制为 null；`SelectedElements = [基座图元]` → 剔空；本页图元照常可选；基座自己的编辑界面里基座图元照常可选（正反对照） |

## 十一、纪律条目（已并入 `AGENTS.md` §27）

- **R87**：基座 = 组合 + 实时引用，不做页面继承；`BasePageId` 是唯一引用字段，
  `BasePages` 与 `Pages` 分离；悬空不清理、渲染降级。
- **R88**：一层限制在两个入口都拦 + 加载期拆链；渲染只合成两层。
- **R89**：导航/启动画面/画面选择器一律走 `FindNavigablePage` / `IsNavigable`，
  `FindPage` 只给"编辑与持久化"用。
- **R90**：基座图元必须进 `EnumerateItems()`（数据泵免改的前提），基座先于本页；
  画面级钩子只对 `CurrentPage` 触发。
- **R91**：WPF `SelectedItem` 绑定的候选项类型必须与选中项一致；禁止用
  `CompositeCollection` + `ComboBoxItem` 占位去清空强类型属性（转换失败且不报错）。
- **R92**：基座图元在引用页上只读——三个闸门（选中集合 Coerce / 主选中 Coerce /
  `CanEditElement` + 左右键命中），判据只在 `IsForeignBaseElement` 一处。
- **R93**：「新建基座」= 新建一份空白公共层并立刻选中它，不是"把当前页提升为基座"。
- **R94**：视图渲染探针三条纪律（`Activate()` 的静态订阅必须 `Deactivate()` 摘干净 /
  菜单命令断言先给 `PlacementTarget` 再泵 Dispatcher / 视图不许依赖 App.xaml 的内联资源）。
