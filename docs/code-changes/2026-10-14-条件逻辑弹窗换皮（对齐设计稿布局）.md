## 四、关键约束与决策理由

### 1. 本视图在「已收编弹窗」静态扫描名单里 → 不得新增本地样式、不得写十六进制色值

`FlowCanvasChecks\VariableBindingCheck.cs:382-388` 的 `CollectedDialogViews` 名单**含 `ConditionEditorView.xaml`**，`RunCollectedViewStyleContract`（`:401-457`）对它做两条硬扫描：

- **注释外任何十六进制色值**（`:433`，白名单仅 `GlobalVariableView.xaml` 的采集质量色点）；
- **任何本地 `<Style x:Key="...">`**（`:441`）。

→ 本次**不得新增视图本地样式**，只能复用现成 `Dialog*` 样式 + 内联属性。空态框的 `Visibility` 切换也因此**不能用本地 `Style` 包一层**，而是内联 `<Style>`（无 `x:Key`）挂在 `DataGrid` / `Grid` 各自的 `.Style` 上——**注意**：`RunCollectedViewStyleContract` 的正则只匹配**带 `x:Key`** 的 `<Style>`，内联无名 `<Style>` 不触红线（视图里两处内联 `<Style>` 均为无名）。

### 2. 其余四道契约（都必须继续过）

| 契约 | 要求 | 本视图的守点 |
| --- | --- | --- |
| `UIThemeSmokeTest` | `*Color` 令牌不得接 Brush 属性 | 一律用 `Dialog*Brush` |
| `RunDialogChromeContract`（`:469-518`） | 带 `prism:Dialog.WindowStyle` 的弹窗须 `WindowStyle=None` + `IsWindowDraggable` + 有 `CancelCommand`/`ConfirmCommand`/`CloseCommand` | `:26` `WindowStyle=None`、`:76` `IsWindowDraggable`、`:899` `CancelCommand` 全在 |
| `RunWindowStyleSetterContract` | 禁 `WindowStartupLocation` | 未引入 |
| `RunMissingResourceKeyContract` | 禁 `{StaticResource BooleanToVisibilityConverter}` | 未引入（`Visibility` 切换走 `DataTrigger` + `ui:BooleanToVisibilityConverter`） |

### 3. 为什么"只抄视觉"是硬约束，不是偷懒

这个弹窗是**草稿 → 校验 → 写回**事务（`取消或关闭即丢弃`，`:109` 文案）。保存校验逻辑、`IDataErrorInfo`（`:266` 别名列打字即红框）、`LinkLoopCount` 连线语义都在 VM/code-behind 里；XAML 只是它的投影面。**任何"顺手改绑定"都会踩到上一批 `R33~R35` 的坑**（名字类端口误挂绑定弹窗、从"值变了"倒推用户意图）。所以本次的验收线是"改前改后命令/属性/事件/Tag 逐字等价"，见 §五。
