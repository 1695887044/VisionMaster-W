## 一、需求与决策

### 1.1 问题现象 / 背景

「系统 → 相机设置」菜单项此前是空的（`ShellViewModel.OnSystemAction` 里只有一句
`// TODO: 弹出相机配置 Dialog`）。相机功能的契约层（`Shard\Core.Interfaces\Camera\*`）、
宿主服务层（`CameraProvider` / `NetworkCameraServer`）、驱动插件（`Plugin.Camera.Network`）、
采集步骤侧都已完成并通过编译，唯独缺这最后一块可操作的界面：

- 用户没有任何入口去"添加 / 删除相机、连接 / 采流 / 看状态 / 改参数"；
- 相机侧最要紧的语义——**溢出丢帧必须可见、丢帧 = 漏检工件**——在 UI 上无处呈现；
- 网络相机的接入方式（往哪个地址推帧、心跳怎么发）没有可读的提示，现场只能翻协议文档。

### 1.2 修改原因（为什么改 / 不改的风险）

- 没有界面 = 相机功能对用户不存在：即便底层全部写对，现场也只会得到"相机配不上、连不上"。
- 若不把"溢出丢帧 / 其它丢弃"分开显示，运维会把它当成一个笼统的"性能指标"，
  而它实际是**质量事故**（每一帧对应一个未检测工件）。
- 若不给出网络相机的可读接入地址（尤其把监听用的 `0.0.0.0` 换成本机 IP 的说法），
  用户会拿 `0.0.0.0` 去填客户端，连不上却查不出原因。

### 1.3 修改思路（采用的方案 / 被否决的备选）

**采用：照搬「通讯设置」的既有范式，做一个方案级硬件资源对话框。**

- 目录位置、Prism `IDialogAware` 写法、`DialogParameters` / `Dialog.WindowStyle`、
  XAML 主题引用（`DialogStyles.xaml` 的 `Dialog*` 令牌）全部对齐
  `CommunicationSettingsViewModel` + `CommunicationSettingsView`。
- 左侧相机列表 + 右侧选中相机详情与操作，一屏放下。
- 相机**配置**直接改 `SolutionModel.CameraConfigs`（不走任何 Manager）；
  增删改统一走「`MarkConfigDirty()` → `SyncFromSolution()` → 重建列表行」，
  即运行态设备表的对齐**只在 `CameraProvider` 一处发生**，界面从不自己 `new / Dispose` 设备。

被否决的备选：

1. **用 `EasyDialog.ShowPropertyGrid` 编辑相机**：序列号需要"非空 + 全局唯一"的校验，
   属性面板做不到"校验不过就阻止提交并给中文原因"，故改为内联小表单。
2. **界面自己 `device.Close()/Dispose()` 再改集合**：会与 `CameraProvider` 内部那份设备引用打架
   （"界面已释放，provider 还在用"），且绕过统一的"按需对齐"判据。删除一律交给 `SyncFromSolution`。
3. **预览用 `WaitNextFrame`**：那会**消费**生产帧，一开本窗口就偶发漏检。改用
   `TryGetLatest`（Peek 不 Dequeue，只读不消费）。

{
    _reloading = true;
    try
    {
        _provider.MarkConfigDirty();
        var errors = _provider.SyncFromSolution();     // 设备的新建 / 重建 / Dispose 全由它负责

### 3.4 预览：只读不消费 + 像素布局

```csharp
// 必须用 TryGetLatest（只读，Peek 不 Dequeue）：预览绝不能吃掉生产帧
if (device.TryGetLatest(out var frame) && frame != null)
    PreviewImage = ToBitmapSource(frame);

private static BitmapSource? ToBitmapSource(CameraFrame frame)
{
    if (frame == null || !frame.IsValid) return null;
    var channels = frame.Channels < 1 ? 1 : frame.Channels;
    var isColor = channels >= 3;
    var format = isColor ? PixelFormats.Bgr24 : PixelFormats.Gray8;  // 彩色 BGR 交错 3B/px；灰度 1B/px
    var stride = frame.Width * (isColor ? 3 : 1);
    var source = BitmapSource.Create(frame.Width, frame.Height, 96, 96, format, null, frame.PixelData, stride);
    source.Freeze();
    return source;
}
```

## 五、方案"标脏 / 未保存改动"用的是哪个机制

**结论：仓库里没有"方案级脏标记（IsDirty）"这类需要在每次编辑后调用的 API；因此本次没有、也不应新造一个。**

- 真正管"未保存改动"的是 [SolutionDraftService.cs](file:///e:/VM/VisionMaster-W-master/Core/SolutionDraftService.cs)：
  它在退出链上把**内存中的方案按落盘口径序列化一次，与磁盘文件逐字比较**，不一致就转存草稿。
  注释里明确写了"刻意不用脏标记（IsDirty）"，因为脏标记要在每个写模型入口埋点、漏一处就是"改了但退出不存草稿"。
- 相机配置是 `SolutionModel.CameraConfigs`（随 `.vms` 落盘）的一部分，
  **只要改了就会自然被上面的逐字比较发现**，不需要任何显式"标脏"调用。
- 我实际调用的 `CameraProvider.MarkConfigDirty()` **不是方案脏标记**，它只是
  "运行态设备表需要重新对齐"的脏位（见 `CameraProvider` 类注释），语义完全不同。

因此：相机增删改后，我调用的是 `_provider.MarkConfigDirty()` + `SyncFromSolution()`（运行态对齐），
并对用户提示"如需长期生效请保存方案"。**没有**自创方案级脏标记。
仓库现状的局限：Shell 里没有实时"* 未保存"指示，用户仍需手动 Ctrl+S / 文件→保存；
这是既有设计（保存走 `SaveFileDialog`），不在本次范围内。

## 六、已知边界 / 需要你确认的地方（未擅自改你的文件）

1. **数值输入框的健壮性**：曝光 / 增益 / 超时 / 容量目前直接 `double/int` 双向绑定。
   用户输入非法字符（如 "8O"）时绑定会静默失败、保留旧值，界面无提示。
   仓库其它弹窗（如 `ScadaVariableEventDialogViewModel`）用的是"字符串接收 + 失焦解析 + 回灌原值 + 中文原因"的做法。
   本次为控制改动体量先用直接绑定。**如需要，我可以按那套范式补齐**——请确认是否要做。

2. **网络相机参数"设了不生效"的范围**：按你的要求，参数区对网络相机显式说明
   "曝光 / 增益 / 触发模式由客户端决定"，并点明 `FrameTimeoutMs / BufferCapacity / HeartbeatTimeoutMs` 真实生效。
   这与 `NetworkCameraDevice.ApplySettingsCore`（返回 true 但无硬件动作）一致。

3. **URL 里的序列号未做 URL 转义**：网络相机的序列号按现场惯例是字母数字，
   `NetworkCameraServer` 侧是拿到路由参数后才 `Uri.UnescapeDataString`。
   若你的序列号可能出现空格 / 中文，需要在这里补转义——目前按"字母数字"处理。

4. **`DevicesChanged` 回声抑制**：`CameraProvider.SyncFromSolution()` 会触发 `DevicesChanged`，
   而本窗口自己也会同步。我用 `RowsMatchProvider()`（比对 Id 与设备引用）判定"这是自己同步后的回声"，
   是回声就不重建列表，避免每加一台相机重建两遍、选中项闪一下。若你后续改动 `DevicesChanged` 的语义，这里需要同步检查。

5. **`CameraProvider` 是具体类型注入**：因为 `MarkConfigDirty / SyncFromSolution / AvailableDrivers / IsSerialAvailable`
   都不在 `ICameraProvider` 接口上（接口只服务插件），所以 `CameraSettingsViewModel` 注入的是具体类型 `CameraProvider`——
   这与 `CameraModule` 的注释（"宿主内部拿具体类型用 MarkConfigDirty"）一致，属于预期用法，特此标明。

## 七、学到的知识点

- **XML 注释不能包含 `--`**：XAML 里写 `<!-- ---------- 标题 ---------- -->` 会直接导致
  `error MC3000: An XML comment cannot contain '--'`。装饰性分隔线改用 `====` 或不写。
- **运行态对齐收敛到一处**：设备实例的新建 / 重建 / `Dispose` 只在 `CameraProvider.SyncFromSolution()` 发生，
  界面只负责"改配置 + 标脏 + 请求对齐"，避免出现"界面上两台、实际三台"的错位。
- **预览 vs 生产消费的语义必须分开**：`TryGetLatest`（Peek，只读）用于界面预览，
  `WaitNextFrame`（Dequeue，消费）用于流程取图。用错就会"一开监视窗口就偶发漏检"。
- **事件封送**：`ICameraDevice.StateChanged` 在设备线程（收图回调 / 看门狗）触发，UI 绑定属性必须先
  `SafeDispatch.BeginInvoke` 回 UI 线程；且窗口关闭时务必停定时器 + 退订，否则会"窗口关了还在刷界面"。
- **监听地址 ≠ 可连接地址**：`0.0.0.0` / `[::]` 表示"听所有网卡"，不能作为客户端连接目标，界面展示时应转成本机 IP。
