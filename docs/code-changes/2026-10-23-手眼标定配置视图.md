## 3. 关键决策

1. **数据住列表，CSV 只是搬运**（用户拍板）。`Samples` 是唯一真源，保存/加载走既有 `[StepConfig]` JSON 快照（`VisionPluginBase.SnapshotConfigValue` 对非基元类型做 JSON 往返拷贝），`IsBlank` 因为标了 `[JsonIgnore]` 不入库。
2. **命令用 `Core.Commands.RelayCommand`，不引 Prism**。本仓 `RelayCommand` 的 `CanExecuteChanged` 接 `CommandManager.RequerySuggested`，不需要手写刷新；为三条命令加一个 Prism 依赖不划算。
3. **预览结论只写 `Preview*` 只读属性，绝不动输出端口**。`SolveForPreview` 是"让我先看一眼解出什么"，端口只在 `RunAlgorithm` 写——否则用户在界面上点一下预览，流程里下游节点就拿到了一个"没跑过流程的解"。
4. **`TrySolve` 的返回值与 `qualityError` 是两个维度**。`false` = 压根没解出（数据没填完/组数不够/退化）；`true` 但 `qualityError` 非空 = **解出来了但不达标**（此时 `quality` 与残差有效，端口照写、流程判失败）。这个区分让"失败"能给出正确下一步：前者改数据，后者可能只是门槛设紧了。
5. **三态用布尔投影驱动 `DataTrigger`**（`IsPreviewOk`/`IsPreviewFailed`），不拿嵌套枚举直接绑：XAML 里字符串→枚举转换猜不中时**不报错，只是永不触发**。
6. **矩阵 16 格用 `string[] PreviewMatrixCells` 索引绑定**，不用 `IMultiValueConverter`/`ConverterParameter`——同理，`ConverterParameter` 写错也是静默。
7. **视图必须用探针验证**。离屏 `Window`（`Left=-4000`）+ `Dispatcher.PushFrame` + 渲染后判 `IsVisible`（祖先 Collapsed 时为 false），另挂 `PresentationTraceSources` 的 `DataBindingSource` 监听器收绑定错误——绑定路径拼错是静默不显示，这是唯一能抓到它的手段。
8. **数值列 `StringFormat="{}{0:F3}"` + `NumCellHostStyle`**。`DialogDataGridCell` 自带 `Padding="12,0,0,0"`，不减掉会把 `-511.280` 的负号裁掉——**一个负号消失的错误数字比截断的文字危险得多**。

## 5. 边界与未做

1. **眼在手外（`AX = ZB`）求解器未实现**。界面能选这个装法，选了求解会明确失败（`CalibrationKind.HandEye` 契约字段与结果文案已就位）。这是独立批次，需要另一套方程与验证数据。
2. **表格不支持粘贴 Excel 一片区域**（设计基线 §12 Q6 未决）。当前只能逐格输入或整表 CSV 导入。
3. **行尾 ✕ 在 948 宽下要横向滚一点才完全露出**（12×72 + 行号列 ≈ 900 > 可视区）。下一步选项是把 ✕ 挪进行头（需改 `RowHeaderTemplate`）。
4. **两级表头（`机器人位姿` / `相机位姿` 分组行）未复刻**。`DataGrid` 无原生双层表头，叠假表头必然与真实列头缩放错位；改为列名自带前缀，分组语义不丢。
5. **求解中不禁用按钮**。求解是同步的 SVD，毫秒级；不先造无用的禁用逻辑。
6. **插件未标 `[ParallelSafe]`**（沿用上一批结论）：求解器是纯函数可以并行，但"一次标定"本身是单步操作，标了会让流程调度器把它丢进并行批。
7. **真机数据未验**：所有断言都用合成数据；欧拉 ZYX 各轴的符号只按数学自洽验证过，接新品牌机器人必须先用"只绕单轴转 90°"的实测数据核对（符号错的表现是"残差正常、抓取点整体镜像"）。
