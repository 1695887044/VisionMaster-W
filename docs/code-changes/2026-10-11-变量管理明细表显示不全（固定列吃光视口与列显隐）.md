# 变量管理明细表显示不全（固定列吃光视口与列显隐）＋ 当前值就地编辑收敛

- 日期：2026-10-11
- 涉及：`VisionMaster\Views\DialogViews\GlobalVariableView.xaml`（含同名 `.xaml.cs`）、`Core\Models\VariableNode.cs`、`VisionMaster\Helpers\CellValueEditBehavior.cs`、`VisionMaster\ViewModels\DialogViewModels\GlobalVariableManagerViewModel.cs`、`FlowCanvasChecks\GlobalVariableChecks.cs`
- 触发：用户真机截图——「变量管理」弹窗右侧"变量明细"表：**"当前值"列整列消失**；"类型"列被裁成 `St/In/Do/Bo`（表头只剩"类"）；变量名 `ScoreThreshold`/`Exposure_Time`、初始值 `Product_Name`/`QR2023100…` 全部被硬裁半个字，无省略号。

---

## 1. 根因（算账）

右栏视口宽度是硬约束，固定列合计却比它大：

| 项 | 数值 |
| --- | --- |
| 默认窗口宽 | 1240 |
| 三栏结构占宽 | 216 + 12 + 296 + 12 = 536 |
| 外边距 | 14 × 2 = 28 |
| **右栏视口** | **~660** |
| 固定列合计（改前） | 146 + 56 + 104 + 96 + 74 + 112 + 162 = **750** |

- 固定列 750 > 视口 660 ⇒ 星号"当前值"列被压成 **0 宽**，剩余 90px 溢出直接把最右的"操作"列裁进卡片边缘。
- `HorizontalScrollBarVisibility="Disabled"`：超宽部分**静默裁剪**，连滚动兜底都没有。
- `Dialog.DataGrid.xaml` 的单元格 Padding 左 12、表头 Padding 12：56px 的"类型"列再被各吃 12px，`String/Boolean` 只剩两三个字符的可见宽度。
- 窗口 `MinWidth=1120` 时视口仅 ~540，问题必然化。

> 附注：用户截图里的列位其实对应**旧 exe**（列宽约为现源码的 0.75 倍，且当晚 21:12 刚重建过、宿主未重启）；但**当前源码自身同样超宽**（750 > 660），重建也救不了，本修复针对源码账目本身。

## 2. 修法

1. **本地来源收起三列**：`来源 / 扫描组 / 地址` 对本地变量恒为「本地」徽标或空白，是纯占地。代码后置挂 `GlobalVariableManagerViewModel.IsNetworkSource`（`SelectedSource` setter 与本地/网络胶囊两条路径都会推进它），本地来源时 `DataGridColumn.Visibility = Collapsed` 整列收起。
2. **窗口 1240 → 1300（MinWidth 1200）**，`Loaded` 时 `ClampToWorkArea()` 收敛到工作区宽（1920@150% 的小逻辑桌面兜底）。
3. **"当前值"列 `MinWidth=80`**：视口再挤也宁可出滚动条，不许星号列变 0——列宽事故的守门位。
4. **横向滚动条 Disabled → Auto**：网络来源下列更多（固定列合计 764），小窗口下滚动可达，不再静默裁剪。
5. **列宽微调**：类型 56→64（装下 `Boolean`/`String[]`）、初始值 112→126（多显两三个字符）。
6. **变量名列模板 StackPanel → Grid**：横向 StackPanel 给 TextBlock 的是无限宽，`TextTrimming` 永不生效、只能硬裁半个字；换成 Grid 让名称列拿 `*`，超长名走省略号 + ToolTip 全名。
7. 类型列 ElementStyle 补 `TextTrimming`。

修后账目：本地来源固定列合计 = 146+64+126+162 = **498**，最小窗口（1200）视口 = 636，"当前值"列起步 80、默认 1300 下 ~210。

## 3. 守门

`GlobalVariableChecks.RunDetailColumnWidthContract()`（进常规 gate 基线，静态扫 XAML、剥注释）：

- ① `HorizontalScrollBarVisibility` 必须是 `Auto`；
- ② 星号列必须存在且 `MinWidth ≥ 80`；
- ③ 本地来源固定列合计 + 星号下限 ≤ 最小窗口右栏视口（宽 −564）；
- ④ 代码后置仍含 `IsNetworkSource` + 三个列名（防收放线被静默删除）。

## 4. 验证证据

- `dotnet build VisionMaster`：0 error，DLL 与 `GlobalVariableView.g.cs` 刷新。
- `dotnet build FlowCanvasChecks` + 运行常规 gate：**1981 项断言 0 失败**，其中新增【列宽】4 条全过：
  `固定列=[146,64,126,162] 合计=498 + 星号下限=80 ≤ 视口(MinWidth=1200−564)=636`。

## 5. 二次修复：列收放从未执行（DataContext 时序）

第一轮修完真机复验：新构建已生效（"当前值"列出现、省略号生效、窗口被钳到 ~1280），**但"来源/扫描组/地址"三列在本地来源下没有收起**，固定列仍溢出，各列被按比例压窄（`S...`/`BarcodeR...`）。

根因是**DataContext 时序**：Prism 的 `ViewModelLocator.AutoWireViewModel` 附加属性在 `InitializeComponent()` 解析期间就把 DataContext 设好了——早于构造器里订阅 `DataContextChanged` 的那一行；DataContext 之后不再变化，事件永远不补发，`HookViewModel` 一次都没跑过。

修法：构造器在订阅之后**直接补调一次 `HookViewModel()`**（幂等，重复订阅有防重）。守门断言同步强化：`HookViewModel();` 在代码后置中出现 ≥2 次（订阅体之外必须有一次直调）。

## 6. 第三轮：交互收敛——当前值就地编辑 + "恢复初始值"收进单元格

用户裁决（项目未上线、不考虑兼容）：**写值直接在当前值格子里做；"恢复初始值"不再占操作列**。

### 6.1 语义（三条红线）

1. **就地编辑绝不触碰 DefaultValue**——提交走 `IWritableVariable.TryWrite`（本地=内存赋值恒成功，网络=下发设备），基准值是"恢复"的锚点，被就地编辑悄悄改掉它，"恢复"就恢复不到用户认定的基准。文本转换统一走 `VariableValueConverter.TryConvert`（布尔认 1/0/是/否/on/off、不变文化、数组/图像明确拒绝），与组态动作 WriteVariable 共享一份规则；
2. **编辑中（`VariableNode.IsEditingValue`）值推送暂停**——轮询镜像更新不许冲掉输入中的草稿；
3. **网络写入失败必须如实留痕**——提交失败红框 + 中文原因（`Validation.MarkInvalid`），模型未被污染；未绑管理器/离线/未配地址各有明确文案（沿用 `TryWriteToValue` 的既有纪律，写值弹窗"吞错报成功"的教训见其注释）。

### 6.2 实现

- `VariableNode`（Core）：新增 `CurrentValueText` / `IsValueDeviated` / `IsValueReadOnly`（Modbus 离散输入 1x、S7 输入映像 I 等只读存储区转只读展示）与 `BeginEditValue / CommitEditValue / CancelEditValue / RefreshValueDisplay`；`DefaultValueText` setter 顺带推 `IsValueDeviated`（改基准也会翻 ↺ 的显隐）。
- `CellValueEditBehavior`（VisionMaster\Helpers，新文件）：获得键盘焦点→进入编辑态；回车/失焦→提交（失败红框保持编辑态）；Esc→放弃回读。不用 TwoWay 绑定提交——网络写入是设备 I/O，"每键击下发"不可接受，且 LostFocus 触发器与"暂停推送"复位存在焦点让渡顺序竞态。
- VM：**值变化改为就地刷新**（`NodesOf(gv)` 逐节点 `RefreshValueDisplay`，SafeDispatch 封送），撤掉 C4 的"脏标记 + 800ms 全树重建"定时器——节点对象稳定后，编辑中的单元格不再有被重建吞掉的窗口期（C4 注释里记过这个事故），轮询推送也不再引发整树 Clear+重建；数组元素行快照（ChildValue）由 `RefreshValueDisplay` 就地跟进。`WriteValueCommand / ExecuteWriteValue / VariableValueEditor` 死代码清干净。
- XAML：当前值列 = 质量点 + 编辑框（`CellValueEditBehavior.Active`）+ ↺（`IsValueDeviated` 才显示，命令仍是 `ResetCommand`）；数组根仍走"强制覆盖集合"，元素行只读快照；操作列删"写值到设备/恢复初始值"两钮（162→126），只剩 复制/重命名/删除。

### 6.3 守门（GlobalVariableChecks.RunCurrentValueEditContract，进常规 gate）

- ★提交写入 Value、DefaultValue 分毫不动；非法文本失败报因、模型干净；
- 布尔 PLC 约定（1=真 / off=假）；恢复初始值后偏离标记消失；
- 网络未绑定管理器 → 写入失败如实报错、镜像不变；
- 编辑中推送暂停（0 次 CurrentValueText 通知）、Esc 退出并回读；
- 结构扫描：视图挂 `CellValueEditBehavior.Active` + `IsValueDeviated`、`WriteValueCommand` 在视图与 VM 中零残留。

### 6.4 第四轮：撤掉"初始值"列 + 数组元素行就地编辑

用户反馈两点：① 初始值不该显示出来占视图；② 数组类型没法用文本框改数值。

- **明细表撤掉"初始值"列**——表只剩 变量名 / 类型 / 当前值 / 操作，固定列合计降到 336。"初始值"作为基准（DefaultValue）的设定入口挪进**新建变量表单**（「初始值 (选填)」，标量类型显示，留空=类型默认值，`TryGetNewInitialValue` 走同一份 `VariableValueConverter` 校验，本地/网络创建路径都落 `DefaultValue = Value = 初始值`）。↺ 的 tooltip 同步改为"恢复为创建时设定的初始值"。
  - 为什么不能只删不给入口：基准是 ↺ 的锚点，没有设定入口时新建变量的基准永远是 0/空串——对 Exposure_Time 这类变量，↺ 会把它恢复成 0，危险。
  - 数组的基准仍由「强制覆盖集合...」整体维护（DefaultValue 与 Value 一起换），图像由流程写入，建表单对这两类隐藏初始值项。
- **数组元素行就地编辑**：`VariableNode.CurrentValueText` 变为根行/元素行多态（元素行读父数组当前值对应下标，数值走不变文化格式化），`CommitEditValue` 自动分派——元素行走 `CommitChildElementEdit`：**只写 Value[i]，不碰 DefaultValue**（增删元素仍走父行「强制覆盖集合...」，那里基准与当前值一起换）。同一个 `CellValueEditBehavior` 同时服务根行与元素行（提交式：回车/失焦提交、Esc 放弃、失败红框）。
- 守门新增：元素行提交只写 `Value[i]`、基准数组零改动；视图「初始值」列零残留（`DefaultValueText/ChildDefaultValueText` 不再被绑定）；行为挂载 ≥2 处；建表单含「初始值」项。
- **提交成功即回读取模式**：行为在提交成功后 `Keyboard.ClearFocus()` 交回焦点（失败保持编辑态等修正）；UI 库新增 `DialogCellInputQuiet`（Dialog.Input.xaml，BasedOn DialogCellInput）——读取态透明无框长得像普通文本，悬停/聚焦才显出输入框边（悬停与聚焦的高亮由 DialogCellInput 模板触发器接管）。守门：两格样式走 Quiet、行为含 ClearFocus。

- 常规 gate：**1994 项断言 0 失败**——【当前值】16 条（含元素行提交只写 Value[i]）、【列宽】4 条（固定列合计随"初始值"列撤出自动更新为 [146,64,126]=336+80 ≤ 636）。

## 8. 未决问题

- 网络来源下固定列合计 736：默认 1300 窗口仍会出横向滚动条（约 70px）。若嫌滚动，后续可做"扫描组/地址列宽随内容 Auto"。
- 编辑态只挡"值推送"，不挡结构重建：编辑单元格时若同时增删/改名变量，该格草稿会被结构刷新重置（可接受：结构变化是低频人工操作）。
- 观测补充（第二轮）：固定列溢出时 .NET 9 DataGrid 的实际行为是**按比例压缩各固定列**（非裁剪），溢出表整体变窄而不是丢列；就地编辑落地后本地来源不再进入溢出状态。
- 真机复验待用户重启宿主确认。
