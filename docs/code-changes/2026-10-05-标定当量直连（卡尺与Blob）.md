# 2026-10-05 标定当量直连（卡尺 / Blob）：像素当量从「手抄」到「接线」

- 项目：VisionMaster（WPF + Prism 9 + Halcon）
- 范围：**8 个代码/工程文件 + 3 份文档** —— 卡尺插件 2（`Plugins\Plugin.CaliperMeasure\CaliperMeasurePlugin.cs` / `CaliperMeasureView.xaml`）、Blob 插件 2（`Plugins\Plugin.BlobDetect\BlobDetectPlugin.cs` / `BlobDetectView.xaml`）、断言 4（新增 `FlowCanvasChecks\CaliperMeasureChecks.cs`；`FlowCanvasChecks\BlobDetectChecks.cs` 追加；`FlowCanvasChecks.csproj` / `Program.cs` 注册）、文档 3（`docs\卡尺测量\卡尺测量插件.md`、`docs\缺陷检测\Blob缺陷检测插件.md`、`docs\标定插件\标定插件.md` 接线表同步）
- 依据：`docs\标定插件\标定插件.md` §1（现库里"当量是每个插件各自手填的参数"的现状描述）；方案 §九 二期路线「当量直连卡尺/Blob」
- 类型：跨插件功能（加法接线；未接线时行为与旧版**完全一致**）

## 一、背景

「标定」插件产出的 `MmPerPixel` 此前只能**人工抄录**到卡尺 / Blob 的配置框：抄错一个数量级 = 所有测量值整体缩放错且难以察觉——这正是"错误但不出错"的计量灾难。卡尺视图里甚至留了"将来有标定模块可改为连线取值"的字样，本次兑现。

## 二、改动清单

### 2.1 卡尺插件（`CaliperMeasurePlugin.cs`）

- 新增可选输入端口 **`MmPerPixel`**（double，`IsRequired=false`）：接「标定」插件的 `MmPerPixel` 输出，或链接运行时变量。
- 新增 `GetEffectivePixelSizeMm(out string error)`（public，供断言与界面查询）：
  - 未接上游且端口值 ≤ 0 → 手填的 `PixelSizeMm`（旧行为不变）；
  - 已接上游 → 上游值（须有限且 > 0；照常走同一安全夹取 1e-9~1e6）；
  - 未接上游但端口值 > 0 → 用端口值（覆盖"配置界面试运行"桥接：`PluginTestRunner` 把上游实际值灌进端口手动值并清掉链接，此时与运行期同口径，"试运行所见 = 运行所得"）；
  - 已接但无效（≤0 / NaN / Inf）→ 返回兜底值并输出错误说明。
- `NormalizedParameters()` 改用生效值；上游无效时以 `p.ValidationError` **前置失败**（走既有失败通道，预览/运行同一份）。

### 2.2 Blob 插件（`BlobDetectPlugin.cs`）

- 同款 `MmPerPixel` 端口 + `GetEffectivePixelSizeMm`；`BlobParams` 增加 `PixelSizeError` 字段；`RunAlgorithm` 在参数归一化后**明确失败**（不改判定语义——当量只影响 mm² 输出，这条原则保持）。

### 2.3 两处视图（提示）

- 像素当量输入框的 ToolTip 更新；下方增加一行接线提示："把「标定」插件的 MmPerPixel 输出连到本步骤的输入端口「MmPerPixel」，运行时自动以标定当量为准（本框数值作为未接线时的兜底；上游标定失败会直接判失败，不会拿旧值硬算）。"

### 2.4 断言（`[CALM]` 段 + Blob 追加）

- 新增 `CaliperMeasureChecks.cs`（**14 条**，注册进 `Program.cs`）：
  - 端口面：卡尺 `MmPerPixel` 存在/可选/类型 double；标定 `MmPerPixel` 输出类型 double（两端类型吻合）；
  - 语义：未接→手填 0.03 / 已接→0.02 / **试运行桥接（无链接但端口值>0）→以端口值为准** / 上游 0 与 NaN → 报错并指「标定」；
  - **真实测量链路**（合成图 640×480、竖直亮带列 200~440）：未接手填 0.5 → 120.5mm；接上游 2.0 → 482mm（4 倍）；上游 0 → 步骤失败且输出端口清零（无脏值）；**真标定插件产出 0.02 → 直连 → 4.82mm（≈241px × 0.02）**；标定失败（半填行）→ 当量口归 0 → 卡尺明确失败。
- `BlobDetectChecks` 追加 2 条：已接上游以连线为准（0.5²=0.25，手填 2.0 被忽略）；上游无效 → 明确失败。

### 2.5 语义总表（四态）

| 接线状态 | 生效当量 | 行为 |
|---|---|---|
| 未接 `MmPerPixel`（端口值 ≤ 0，从未接过） | 手填 `PixelSizeMm` | 与旧版完全一致 |
| 未接但端口值 > 0（**试运行桥接的快照**） | 端口值（安全夹取） | "试运行所见 = 运行所得"（`PluginTestRunner.BridgeInputs` 灌快照并清链接） |
| 已接且上游有效（> 0） | 上游值（安全夹取） | 以连线为准；标定每轮重算的值自动传导 |
| 已接但上游无效（≤0/NaN） | —（明确失败） | 文案："像素当量来自上游连线但无效（X）：请检查上游（「标定」步骤本轮是否成功 / 链接的变量是否有值），或改用手填像素当量并断开该连线" |

> 为什么"无效就失败"而不是回退手填：拿错当量 = 全部测量值整体缩放错；与「标定」插件"失配必须报"的纪律一致——**绝不静默**。

## 四、边界与下一步

- **未做**：标定文件导入/导出（多设备共享，二期）；`CalibrationView` 配置视图的窗口化冒烟（UIThemeSmokeTest 模式，备选）。
- 端口为**加法**：老方案（未接该端口）+ 新 DLL 行为不变；下游按名接线，无改名。
- 若现场把标定当量接到别的 double 端口（阈值等）属误接——编译期类型检查只保证 double↔double，语义正确性靠本记录的接线说明。
- **变量链接注意**：`InputPort` 的通用机制是"仅在写方发出变更时刷新缓存"——若用运行时变量链接本端口，需确保写方（如变量赋值步骤）**每轮都写值**；标定直连链路无此问题（标定每轮先归零、成功才写值）。
- 试运行口径：上游失败时桥接值=0、链接已被清掉，无法与"从未接线"区分——此时回退手填值（不报错）。运行期（真链接）才是严格口径（失效即失败）。
