## 三、关键设计决定（改代码前先读）

### 3.1 生成器只生成"图元私有属性"；通用外观走打包助手

`Fill` / `Stroke` / `FontSize` / `Text` 这类**基类已有**的依赖属性，**不许**再用 `[ScadaProperty]` 声明一遍：
那会在子类生成第二个同名依赖属性，遮蔽基类那份，`{TemplateBinding Fill}` 绑到新的、基类的永远不动
（表现是"属性面板改了没反应"）。**生成器现在会报 SPG0006 拦住它**（这是本轮新增的一条诊断，
起因是我自己先在 `PanelElement` 上踩了这个坑）。

通用外观的复用走 `AppearanceProperties.Fill("#FF1E2530")` 这种打包助手——它产出的是
**指向基类依赖属性**的描述符条目，零新增依赖属性。

### 3.2 坐标保持画面绝对坐标；"父带动子"由模型层联动

- 子图元的 `X/Y` **仍是画面绝对坐标**（不是相对底板）。这条决定让对齐/分布/等尺寸/等间距/吸附/微调
  六条既有路径**一行都不用改**。
- 渲染时减掉底板位置与子图元区原点（`ScadaElementBase.ApplyPositionToParent`，设计期/运行态/动画三处共用）。
- **底板移动带着子图元走**由 `ScadaPage.CascadeContainerMove` 做：底板挪多少、子图元挪多少。
  它覆盖**所有**写 X/Y 的路径（拖动、对齐、微调、属性面板），不必逐条改。
- **撤销回放时跳过联动**（`ScadaChangeScope.IsReplaying`）：回放时父与子各自有自己的记录要写回，
  再联动一次就是同一段位移推两遍。
- **选中簇不展开子图元**：分组管"选中谁"，底板管"谁跟着谁走"。两者一起生效会双重位移。

### 3.3 容器的挂载时机：模板没就绪就先排队

画布重建时子控件刚造出来、还没进可视树，容器模板尚未套用 → `ChildrenHost` 为 null。
此时**不能**判"装不进去"（那会把子图元当顶层铺开：模型里 `ParentId` 全对、屏幕上却没嵌套），
**也不能**先放进元素层再搬出来（容器模板是在布局过程中就绪的，那一刻元素层的 Canvas 正在枚举子级，
摘孩子会抛"集合已更改，枚举器无效"）。
正解：直接交给容器，容器把还没就绪的子图元**排队**，等 `OnApplyTemplate` 一到就挂进自己的画布。

### 3.4 曲线图元的视口由自己推

库里的"跟随模式"（`AutoScroll`）只认**定采样率的信号系列**，散点系列不参与。
趋势图走的是散点语义（X 是每个值真实到达的时刻），靠它画面会永远停在默认轴范围上
——**数据全在视野外，看起来就是"一条曲线都没画"**。所以 `ChartTrendElement` 关掉 `AutoScroll`，
在追加样本时自己按时间窗与可见值域推视口（带 2% 位移节流）。

### 3.5 曲线绘制面的验证边界（重要）

曲线底层是 ScottPlot → SkiaSharp 的 `WpfPlot`。**SkiaSharp 的绘制面在没有真实渲染目标的进程里画不出内容**
——离屏 `RenderTargetBitmap` 里整幅图只有底色，连坐标轴与网格都没有（实测）。
所以断言只钉到"数据进了缓冲 + 描述符与绑定通道齐备"，**不钉像素**：
一条在无头环境永远为假的像素断言比没有断言更糟（它会让人习惯性忽略红条）。
曲线的视觉验证交给 ① `_ChartProbe5` 探针工程已有的渲染证据；② 真机运行。

## 七、存量 17 个图元的迁移（同日第二批）

上一轮未决 #1 的落地。**全部 17 个图元控件类迁到 `[ScadaProperty]` 写法**，`BuiltInElements.cs` 从 1540 行降到约 440 行。

### 7.1 迁移形态分三类

| 类别 | 图元 | 做法 |
| --- | --- | --- |
| 纯打包（无私有 DP） | Rectangle / Ellipse / Text / Button | 控件类**零改动**，描述符全由 `AppearanceProperties` / `TextProperties` 产出 |
| 私有属性生成 | Indicator / Lamp / Clock / Gauge / Valve / BitButton / ProgressBar / IOField / AlarmBanner / ImageView / Pipe / StateVisual（中间基类） | 删手写 DP + CLR 包装 + 静态回调，换 `[ScadaProperty]` 声明 + `partial void On…PropertyChanged` 钩子；描述符换 `ScadaPropertyCatalog.Collect(typeof(X))` |
| 继承即可 | Pump / Motor | 属性全在已迁移的 `StateVisualElement` 上，只补 `partial` 声明 |

**刻意保留手写的**：IOField 的 `IsEditing` / `EditText` / `EditError`（运行态内部状态——不落描述符、不进属性面板、不落 .vms），以及各图元的只读推导 DP（`LampBrush` / `StateBrush` / `ValueText` / 几何族）。生成器报 SPG0003 拦"只读属性"，这是它该拦的。

### 7.2 迁移中顺手修的

- `ScadaPropertyDefaults` 接管了默认值解析后，原先各图元手写的 `private static readonly Brush DefaultXxx = ScadaBrushes.Frozen(...)` 静态字段全部删除（解析期统一冻结）。只留 `AlarmBannerElement.DefaultNormalColor` 一个——它同时是 `AccentBrush` 只读依赖属性的默认值。
- `StateVisualElement` 的五输入共用回调拆成五条钩子——多两行转调，换来"每个属性各自可挂不同副作用"，不再需要手写静态回调签名。原来那条 `OnVisualInputChanged` 静态回调随之删除，换成 `protected RefreshStateVisual()` 供派生类（管道的 `Direction` 钩子）直接转调。
- **打包助手补了两个可选参数**（向后兼容，只加在参数表末尾）：`Fill` / `Stroke` / `StrokeThickness` 支持 `displayName`，`Foreground` / `FontSize` 支持 `description`。原先表盘叫「外圈色/外圈粗细」、阀门叫「轮廓色/轮廓粗细」、管道叫「管壁色/管壁粗细」，照搬打包助手的固定标签会把这三处的语义抹平成"边框色"。
- **新增 `AppearanceProperties.Rename(...)`**：按 Key 把描述符的 `DisplayName` / `Description` 换掉、返回新数组。用于 `StateVisualElement` 这类"基类一处声明、多个图元各叫各的"：泵叫「泵壳色」、电机叫「机身色」、管道叫「管身色」，管道连状态都叫「流动状态」（0=停流 1=流动 2=异常）。**只换标签与说明，Key / 默认值 / TargetProperty 仍只有基类一处事实来源**；返回新数组是因为 `ScadaPropertyCatalog` 的结果是按类型缓存的实例，就地改会污染缓存。
- `ScadaChecks` 的 `[CP]` 段修掉一处**空引用**：`TrySave` 第二次（重名避让）失败时 `savedBInfo` 为 null，后面 `savedBInfo!.TemplateId` 直接抛 NRE，把整段 [CP] 断言连坐成一条失败。改为把两次保存的 Id 落成 `Guid`（`?? Guid.Empty`）并给第二次保存补上失败原因，失败时以可读断言收场而不是 NRE。

### 7.3 行序与默认值的回归锚点

迁移最大的静默风险是**面板行序漂移**（描述符顺序就是面板行序；打包助手换个传参次序、特性声明换个位置都会改它）与**默认值漂移**（旧画面没配过的图元会跟着变样）。为此在 `ScadaChecks` 的 [R] 段维护**描述符快照断言**：把「Key 顺序 + DisplayName + DefaultValue」三元组钉成字面快照，任何变化必须走"有意改快照"这一步。

覆盖 **18 个内置图元全部**（矩形/椭圆/文本/按钮/位按钮/指示灯/多态灯/棒图/数值域/时钟/表盘/阀门/泵/电机/管道/报警条/底板/图像显示）。本轮迁移后 18 条快照全绿——这同时是"迁移没有改 Key / 默认值 / 行序"的机器证据，比人工逐条对照可靠。
