# 2026-09-27 Git 仓库产物清理与 NuGet 镜像源

## 一、需求与决策

### 现象
项目推送到 Git 后，其他设备 clone/pull 下来：
1. 运行时抛出大量异常（类型加载、方法缺失、文件加载类）；
2. 部分 NuGet 包需要手动重新安装/还原。

### 根因分析
1. **`Modules/` 目录（编译产物）被提交到了仓库**：该目录全部文件均为构建时自动投递——
   - 插件 DLL 由 `Plugins/Directory.Build.targets` 的 `CopyPluginToModules` 目标投递；
   - `Microsoft.CodeAnalysis*.dll` 由 `Plugin.CSharpScript` 生成后拷贝；
   - `MiniExcel.dll` 由 `Plugin.ExcelExport` 拷贝；
   - `hdevenginedotnet.dll` 由 `Plugin.ImageScript` 拷贝。

   其他设备在首次完整编译前（或编译不完整时）运行，`PluginService` 扫描加载的是仓库中的**旧插件**，与新编译的主程序/核心库版本错配，引发 `TypeLoadException` / `MissingMethodException` / `FileLoadException` 等。
2. **仓库根目录没有 `NuGet.config`**：默认仅走 nuget.org（国外源），网络超时时还原失败，表现为"包要重装"。
3. `dist/`（发布成品，含 zip）、`WPF-Halcon-流程拖拉/00Exe/`（旧参考项目成品目录）同样作为成品入库，易被误运行。

### 决策（已经用户确认：全部执行）
- Git 仓库只放"源码 + 公网不可获得的第三方 DLL"，所有编译/发布产物一律不入库；
- `Modules/`、`dist/`、`00Exe/` 取消 Git 跟踪（`git rm --cached`，**本地文件全部保留**）并加入 .gitignore；
- 新增 `NuGet.config`，用 `<clear/>` 清空继承源后，显式锁定"华为云镜像 + nuget.org 官方兜底"，保证任何设备还原行为一致。

## 三、验证结果

| 项 | 结果 |
| --- | --- |
| `dotnet restore --force` | 成功，镜像源可用，无错误/警告 |
| `dotnet build VisionMaster.sln` | **0 个错误**（1027 个警告均为 HSL 全量源码等既有警告，非本次引入） |
| Modules 自动生成 | 编译后自动生成 28 个文件，证明"clone → 编译即得完整 Modules"契约成立 |
| `git check-ignore` | Modules / dist / 00Exe 三个路径均被正确忽略 |
| CommChecks 回归 | **通过 152 / 失败 0** |

> 验证过程中首次编译曾报 6 个 MSB3021/MSB3027（文件被锁），根因是 Visual Studio 2022 正开着解决方案、其 MSBuild 节点占用 bin 目录；关闭 VS 后命令行编译即通过。非代码问题。

## 四、换机标准动作（给新设备）

1. 安装 **.NET 9 SDK**（不是仅运行时）+ Visual Studio 2022 17.12+，勾选".NET 桌面开发"工作负载；
2. `git clone` 仓库；
3. `dotnet restore`（自动走 NuGet.config 的镜像源）；
4. `dotnet build VisionMaster.sln` —— Modules 在编译时自动生成；
5. 运行 `VisionMaster`。

> 注意：主解决方案是仓库根 `VisionMaster.sln`（net9）。`WPF-Halcon-流程拖拉/VM.sln` 是 net framework 旧参考项目，不参与主构建。

## 五、已知边界

1. **历史提交里的 DLL 仍在 `.git` 历史中**，本次只清理当前跟踪，仓库体积未缩小。如需彻底瘦身需用 `git filter-repo` 重写历史（破坏性：所有协作者必须重新 clone），本次不做。
2. **本次变更提交推送后，其他设备 `git pull` 时，其工作区里原被跟踪的 `Modules/`、`dist/`、`00Exe/` 文件会被 Git 删除**：Modules 重新编译即可恢复；若有人需要 dist/00Exe 中的成品，请在 pull 前自行备份。
3. **Halcon license 不随仓库 DLL 解决**：目标设备若需 HDevelop 设计器或运行授权，仍需自行安装 Halcon/配置 license；仓内 DLL 仅解决程序集引用。
4. 华为云镜像对 NuGet 最新发布的包可能存在同步延迟，配置中已保留 nuget.org 兜底。
5. 本变更需经 `git commit` 并推送后才对其他设备生效（本次未代为提交）。
