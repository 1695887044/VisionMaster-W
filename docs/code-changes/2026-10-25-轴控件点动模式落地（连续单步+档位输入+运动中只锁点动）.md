# 轴控件「点动模式」落地（连续 / 单步 + 档位输入 0~50mm + 运动中只锁点动两键）

> 日期：2026-10-25　批次：SCADA 轴控件单步点动　对应设计基线：`docs/UI设计基线/hmi-console/` v6（`V6-01`）

## 一、当前状态

`Hmi.AxisConsole` / `Hmi.AxisPanel` / `Hmi.AxisPointTable`（同一个 `AxisPanelElement` 控件类的三个预设）
现在自带「点动模式」：**连续点动**（按住动、松手停，沿用原口径）与 **单步点动**（点一下走一个档位）。
档位是**可输入数值**（0~50 mm，0.1 mm 粒度），不是若干颗固定档位按钮。
**运动指令执行中点动一律禁止**，但只锁两个点动键——`停止` / `清报警` / `失能` / `回零` 照常可点。

设计稿与实现在这一版是对齐的：`docs/UI设计基线/hmi-console/design.html` 的 `V6-01` 就是按这套口径画的。

## 二、已做

### 2.1 `Scada/Models/IScadaAxisCommandSink.cs`

新增枚举，紧挨 `ScadaAxisCommandKind`：

```csharp
public enum ScadaJogMode
{
    Continuous = 0,
    Step = 1
}
```

**没有**给 `ScadaAxisCommandKind` 加新成员：单步点动复用现成的 `TryMove(axisId, targetMm, velocity, out error)`，
它本来就是"定位到某个绝对位置"的出口，与点位表的「定位」按钮走同一条路。

### 2.2 `Scada.Controls/Elements/AxisPanelElement.cs`

| 类别 | 新增 |
|---|---|
| 可配属性 | `JogMode`（Key `JogMode`，Choice，默认 `Continuous`）、`JogStepMm`（Key `JogStepMm`，Number，默认 1，Min 0，Max 50） |
| 常量 | `JogStepMaxMm = 50d`、`JogStepQuantumMm = 0.1d` |
| 静态工具 | `NormalizeJogStep(double)`：NaN/Inf → 0；夹到 0~50；按 0.1 量化（`AwayFromZero`） |
| 只读 DP | `CanJog`、`IsStepJog`、`IsContinuousJog`、`JogStepText`、`IsStepFieldEditable`、`JogStepValid`、`MovingBannerVisibility` |
| 方法 | `StepJog(int direction)`、`TryParsePositionMm(out double)`、`RefreshJogAvailability()` |

行为改动三处：

1. `StartJog(int direction)`：`IsMoving` 时直接拒绝并写 `CommandMessage = "轴正在运动，点动已锁定（到位或停止后自动放开）"`；`IsStepJog` 时转 `StepJog`；其余仍走 `TryExecuteCommand(JogStart, Math.Sign(direction) * JogVelocityMmPerS)`。
2. `StepJog`：`target = 当前位置 + Math.Sign(direction) * NormalizeJogStep(JogStepMm)`，调 `AxisCommands.TryMove(...)`。**单步不发 `JogStop`**——它本身就是一条完整定位指令，再补一个停会让执行器把它当成被打断。
3. `RefreshCanOperate()` 末尾补 `SetValue(CanJogPropertyKey, can && !IsMoving)`；`ApplySnapshot` 末尾调 `RefreshJogAvailability()`。

> **为什么这些属性必须是只读 DP**：`ScadaElementBase` 继承 `ContentControl`，不是 `BindableBase`，没有 `RaisePropertyChanged`。
> 普通 CLR 属性变了模板也看不见。上一版写成普通属性 + 通知，编译能过但界面永远不刷新；改成只读 DP 才和 `CommandsVisibility` / `PointsVisibility` 一致。

### 2.3 `Scada.Controls/Themes/AxisPanelElement.xaml`

`RootGrid` 由 6 行变 7 行，在**第 3 行（速度行）与第 4 行（操作按钮区）之间**插入点动条：

- 模式胶囊：`连续` / `单步` 两段，选中段用 `AccentColor` 描边；
- 档位输入框：单步时可编辑，连续时置灰并显示 `—`；越界（0 或 >50）时描边转 `AlarmColor`；

三条纪律照旧：不写 `ControlTemplate.Triggers` 里的 DataTrigger（本环境不触发）、颜色与字号走 `TemplateBinding`、不依赖 Application 级资源。

## 三、验证

| 项 | 命令 | 结果 |
|---|---|---|
| 控件工程构建 | `dotnet build Scada.Controls\VM.Scada.Controls.csproj -m:1 -nodeReuse:false` | 0 个错误；`AxisPanelElement.cs` 0 告警 |
| 断言工程构建 | `dotnet build ScadaChecks\ScadaChecks.csproj -m:1 -nodeReuse:false` | 0 个错误 |
| 全量断言 | `ScadaChecks.exe` | 见下 |

`[AX12]` 覆盖的口径：

1. 默认是连续点动模式，档位框只读；
2. 连续模式点动发 `JogStart`，速度取 `JogVelocity`（与档位无关），松手发 `JogStop`；
3. 切到单步后档位框可编辑、文本形如 `3.00`；
4. 单步走定位出口，正向目标 = 当前位置 + 档位、反向 = 当前位置 − 档位；
5. 单步**不产生** `JogStart` / `JogStop`；
6. 档位 0 拒绝、62.5 拒绝（不静默按 50 走）、50 是合法上界；
7. 运动中点动被锁且**零命令**，`CanJog=false` 而 `CanOperate=true`，橙色提示条可见；
8. **反向**：运动中「停止」「清报警」仍然可发；
9. 档位归一化：负数 → 0、超限 → 50、3.14159 → 3.1。

## 六、踩过的坑

1. **`ScadaElementBase` 不是 `BindableBase`**：第一版给 `JogMode` / `JogStepMm` 加了普通属性的通知逻辑，编译过得去，但模板永远不刷新。凡随状态变化的属性一律做成只读 DP。
2. **`ResultDisplay` 一类的图输入端口叫 `SrcImage` 而不是 `Image`**，`RunFlow` 的输出叫 `Invoked` 而不是 `Ok` —— 端口名都是各插件源码里的字面量，抄辅助函数前必须回源码确认。
3. **单步不要补 `JogStop`**：`TryMove` 是完整定位，多补一个停会被执行器当成打断，表现为"点了走一点就停"。
4. **`CanOperate` 不能直接拿来锁点动键**：它是"整块操作区可否操作"，运动中把它关掉会把停止键一起关掉，这是安全上的反向错误。所以单独开 `CanJog = CanOperate && !IsMoving`，只绑两个点动键。
5. **`edit` 工具要求先用 `read` 工具读过文件**，用 pwsh 打印过不算，否则报 `file has not been read`。
6. 构建必须带 `-m:1 -nodeReuse:false`，本机不加这两个开关会静默失败（报"生成失败 / 0 个错误"、退出码 1）。
7. **`OnElementRefreshed()` 只刷权限、不刷数据快照，是本次最隐蔽的一处**。`panel.Refresh()` 走基类 `ScadaElementBase.RefreshCore → OnElementRefreshed`，而运动锁 `CanJog = CanOperate && !IsMoving` 是从快照推导的；只补 `RefreshCanOperate()` 会让 `IsMoving` 停在旧值，于是**轴其实在动、点动键还亮着**。这类错误不会报错、不会崩，只会让机构去抢一根正在走的轴。凡"由快照派生的可操作状态"，`OnElementRefreshed` 里必须连快照一起重取。
8. **断言里 `Contains` 的文案要回控件源码抄**。控件原文是「轴正在**运动**，点动已锁定（到位或停止后自动放开）」，断言写的是 `Contains("运动中")` —— 永远为假，而且失败信息只显示 `ok=False calls=0`，看起来像功能坏了，实际是断言自己写错。写字符串匹配前先 `grep` 一遍控件里的字面量。
9. **反向断言必须放在段尾**。把"清掉 `moving` 后同一个键必须能发出去"插在段中间，它会把状态清掉，后面「`CanJog` 关闭」「橙色提示条」两条读到清除后的值，变假红。反向断言的职责是证明"锁的是运动而不是别的门禁"，它自己会改状态，所以只能收尾。
10. **增量构建会留假红**。`ScadaChecks.exe` 比源码新不代表产物新：`obj` 里的旧 `_wpftmp` 会让 `Choice` 英文译名、`WR1` 缺 `Hmi.StateView`/`Hmi.SubPage`、`SV19`/`SP4`/`SP11`/`BIT15` 这些早已修好的项重新变红。判据是 `RG1000 BAML 键重复` —— 看到它就删 `VisionMaster\obj` 与 `ScadaChecks\obj` 全量重建，不要逐条去查那些"红灯"。
11. **`MSB3021/MSB3027` 文件被 `VisionMaster.exe` 锁定**，多半是自己上一轮构建顺手起的宿主进程（本次是 PID 1660），`Stop-Process -Force` 后重试即可，不用改代码。
