# 纠偏：轴控动作不再允许从事件动作表下发

日期：2026-10-25　状态：完成；`ScadaChecks` **3051 通过 / 0 失败**

## 起因

用户指出：按钮事件里能配轴控动作是前期评估错误——**不允许**。事件动作表没有轴面板那套闸门
（权限在按下前判、使能/回零/软限位、忙判定），一条误配的按钮就能让轴动起来。

## 改了什么

1. **候选里移除**（`ScadaEventEditorViewModel.TypeChoices`）：按 `ScadaActionTaxonomy.IsMotion`
   过滤掉轴控九条。按钮事件、画面事件、图元事件三种宿主共用同一份候选，一处过滤三处生效。
2. **执行侧兜底拒绝**（`ScadaActionDispatcher.Execute` 开头）：老 `.vms` 里已经配上的运动动作
   仍然存在，必须在运行态**如实拒绝并说明去哪做**，不能静默执行、也不能静默消失。
   日志与审计文案：「轴控动作不允许从事件动作表下发（请在轴面板或流程的轴步骤里操作），本条未执行」。
   原 `case Motion*` 分支删除（不再可达）。
3. **枚举值不删**：`MotionEnable..MotionJogStop`（7~15）保留。落盘值是长期标识，回收会让老工程里的
   动作变成另一件事。`MotionActionExecutor` 也保留——流程里的轴步骤仍在用它。

## 断言

- `[AX13]` 由「分发器把运动动作送到执行器」改写为**反向**：
  ① 事件里的绝对定位不再下发（设备零命令）且日志有「不允许从事件动作表下发」；
  ② 运动族整体生效（点动同样被拒，每次都留一行说明）。
- 「类型下拉与枚举显示名同源」：候选数改为「枚举全量 − 运动族」，并新增
  `ActionTypeChoices.All(o => !IsMotion(o.Type))` 的正向断言。

## 已知缺口

- 属性面板里**已经配好的**运动动作不会显示"已停用"提示（`PendingReason` 仍为 null）。
  要补的话得同时改 `PendingReason` 与"全部动作都已接通"那条断言，本轮未做。
- 轴面板（`Hmi.AxisPanel` / `AxisConsole`）与流程里的轴步骤不受影响，仍可正常操作轴。
