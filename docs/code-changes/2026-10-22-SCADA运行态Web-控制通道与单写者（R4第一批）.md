## 1. 控制通道（解决 ack/bye 排在 256 条值帧后面）

### 结构

| 通道 | 容量 | 内容 |
| --- | --- | --- |
| `_control` | 64 | `ack/error/result/bye/stopped/idle/img.token/pong/hello.ok` |
| `_outbound` | 256 | `snapshot/page/frame/axis/grid/presence/alarms/caps` |

- 两条发送循环（控制/数据）共用一个 `SemaphoreSlim` 发送闸：
  控制消息**只等当前正在发的那一条**，不排整批数据；不是抢占式（Watson 一条消息发完才能发下一条）。
- 任一条循环异常：`HandleSendFault` 记日志 + 取消会话 + 关 1011；
  旧写法 `catch { }` 会让死掉的发送循环完全静默（连接还在、结构永远发不出去）。
- 每会话 `_lifetimeCts`：`Dispose` 取消正在 `await SendTextAsync` 的发送；`CloseAsync` 最多等 2 秒。
- 每条消息 15 秒发送超时：慢消费者不能把发送循环永久挂住。
- 控制队列满：`ack/error/bye/stopped` 的调用方记日志并关 1011/1013；`img.token` 下拍重发；`pong` 可丢。

### 分类调整

- `stopped`（运行结束，两处）、`idle`、`pong`、`hello.ok`、`img.token`、`cmd.result`、lease ack、所有命令 ack/error 改为 `TrySendControl`。
- `snapshot/page/frame/axis/grid/presence/alarms/caps` 仍走数据通道。

## 2. `LastValues` 单写者（修既有跨线程 `Dictionary` 风险）

- `ResetPageKey()` 不再直接 `LastValues.Clear()` / `FrameSeq=0`，只置 `RequestDeltaReset` 标志。
- `SendInitialStateAsync`（WS 线程）与 `OnRunStopped`（UI 线程）都改为 `RequestDeltaReset()`。
- 真正的 `ResetDeltaForNewStructure()` 只在帧循环线程执行：`SendFrame` 开头消费标志。
- 这条修的是**既有**隐患（`OnRunStopped` 一直在 UI 线程清 `LastValues`），不是本批新引入。

## 3. 顺带修掉的两个静默缺陷

### `img.token` 入队失败留下 15 秒 401 窗口

旧 `RotateImageTokens` 先更新 `_currentImageToken` 再 `TrySend`；失败后下一拍看到新 token 剩余 >15s 就跳过，
不会补发，旧 token 到期后图片 401。
现在：`IssueImageToken(..., makeCurrent:false)` → `TrySendControl` 成功才更新 `_currentImageToken`，失败下拍重签重发。

### `caps` 每 2 秒全量重发

3000 图元全量 deny/allow 约 200KB/会话/2s，本身就是队头问题。
现在：按 JSON 的 FNV 哈希比对，内容没变就跳过。

### ping/hello 洪泛

`pong` 每会话 100ms 最多一条、`hello.ok` 每秒最多一条；防止恶意/异常客户端刷满 64 槽控制队列，
把 ack/bye 挤掉。

## 4. 验证

- `ScadaWebChecks`：**135 PASS / 0 FAIL**（新增 `M2-17`：控制队列 64 条满、数据队列仍可写、Dispose 后拒绝）。
- `M2-17` 与既有 `M2-14/M2-15/M2-16` 不重号（首次实现误用了已有编号，已改）。
- `ScadaWebChecks` 原有 B 系列全绿：hello/snapshot/值帧/命令/图像/轴/表格/准入/目录均未受控制通道影响。
