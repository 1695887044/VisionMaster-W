# 2026-10-21 通讯变量数值数组与地址偏移

> 起因：用户提出两件事——「连续 10 个 int 可以添加成数组吧」；
> 「通讯地址要有偏移的功能，比如我现在地址是 40001，我可以修改偏移来实现寻址」。
> 裁定：第一期只做**数值数组只读**（`int[]` / `double[]` / `float[]`）；
> 地址偏移对**所有按地址寻址的通讯变量**生效、默认 0（不是数组专属）；
> Modbus 增加「40001 写法」开关，默认关闭，旧方案零影响。
> 字符串数组、bool 数组、数组写入留到后续（原因见 §6）。

---

## 1. 改造前现状（为什么不是"加一个类型"）

| 能力 | 改造前 | 证据 |
| --- | --- | --- |
| 网络变量类型候选 | 仅 `int` / `double` / `bool` 标量 | `GlobalVariableManagerViewModel.TypesFor(isNetwork)` 过滤 string/数组/图像 |
| 数组解码 | 数值数组在规划器里被 `MinByteCount(valueType)==0` 跳过 | `PollBatchPlanner.Build` |
| 数值解码长度 | 只取目标类型所需头部字节（Int32 只取 4 字节） | `HslHelper.ConvertTo<T>` |
| 数组变更检测 | 只有 `byte[]` 按内容比较；其它数组按引用比较 → 每轮都推 `ValueChanged` | `CommunicationVariable.ValueReallyChanged` |
| 方案落盘 | `VariableDto` 没有 `Length` 字段 | `VariableDto.BuildAddressConfig` |
| 地址偏移 | `Offset` 本身就是地址，没有"基地址 + 偏移"两段 | `DeviceAddressBase.Offset` |
| Modbus 40001 写法 | 旧字符串地址解析支持，新结构化地址路径不支持 | `PollAddressResolver.ParseLegacy` vs `ModbusAddress.BuildAddress` |

因此本轮不是"在类型下拉里加一行"，而是把**解码、内容比较、跨度上限、方案落盘、只读 UI** 五条链路一起补齐。

## 2. 设计口径

### 2.1 数组

- 变量的 `DataType` 是**数组类型**（`int[]` / `double[]` / `float[]`），
  地址配置的 `DataType` 是**元素类型**（`Int32` / `Double` / `Float`），
  `Length` 是**元素个数**（标量固定 1）。
- `CommunicationVariable.ValueType` 传数组的 `AssemblyQualifiedName`；
  规划器按元素大小循环解码，字序仍用连接配置的 `ByteOrder`（与标量同一份 `HslHelper.ConvertToByType`）。
- 第一期**只读**：
  - `NetworkVariableModel.TryWriteCore` 对数组直接返回中文原因；
  - `Value` setter 的隐式写、`ResetToDefault` 同样跳过；
  - 变量管理里网络数组根显示摘要 + 「只读」徽标，元素行显示只读文本，不出现编辑框。
- 变更检测按内容逐元素比较（`byte[]` 保留逐字节快路径），避免每拍都推 `ValueChanged`。

### 2.2 地址偏移（所有按地址寻址的通讯变量）

- 新增 `DeviceAddressBase.AddressOffset`（默认 0）：
  **有效起始地址 = 基地址（`Offset`）+ AddressOffset**。
- 单位是**地址单位**，不是元素个数：
  - Modbus 寄存器区 = 寄存器数；Modbus 位区 = 位数；
  - S7 = 字节数。
- `Address` 预览、`TryCreatePollAddress`、`BuildAddress` 全部使用有效起始地址；
  `AddressOffset` 随方案落盘（`VariableDto.AddressOffset`）。
- 默认 0 = 不偏移，旧数据行为不变。

### 2.3 Modbus「40001 写法」开关

- 新增 `ModbusAddress.UseLegacyAddress`（默认 false），随变量落盘。
- 打开后按存储区区间换算成 0 基地址：
  - 线圈 `00001~09999` → `n - 1`
  - 离散输入 `10001~19999` → `n - 10001`
  - 输入寄存器 `30001~39999` → `n - 30001`
  - 保持寄存器 `40001~49999` → `n - 40001`
- 区间与当前存储区不匹配时 `Validate` 明确失败，**不静默按字面值读**。
- 关闭时保持旧口径：`Offset` 就是 0 基地址（40001 表示第 40001 个寄存器）。
- S7 没有 5 位写法：勾选后创建路径明确报错，不静默忽略。

### 2.4 单次读取上限

第一期不做分块。数组跨度超过单请求上限时，**创建时就拒绝**并提示减少元素个数：

| 协议 | 单段上限 | Int32 数组上限 | Double 数组上限 |
| --- | --- | --- | --- |
| Modbus 寄存器区 | 120 寄存器 | 60 个 | 30 个 |
| S7 | 110 字节 | 27 个 | 13 个 |

规划器侧也有同样的兜底（`poll.SpanUnits > poll.MaxSegmentUnits` → 记日志并跳过），
防止手工改方案或旧数据绕过 UI。

## 4. 关键实现点

### 4.1 解码（`PollBatchPlanner.DecodeValue`）

```text
byteLength = SpanUnits × BytesPerUnit
for i in 0..ElementCount-1:
    slice = data[i × elementSize .. (i+1) × elementSize]
    array[i] = HslHelper.ConvertToByType(slice, elementType, order)
```

- `ElementCount` 来自地址配置的 `Length`（编译期抄进 `SegmentItem`，运行期零解析）。
- 位区 `bool[]` 走 `DecodeBitItem` 的数组分支（本期 UI 不开放 bool[]，规划器已支持）。
- `string[]` 明确跳过并记日志：元素宽度/编码没有统一契约。

### 4.2 内容比较（`CommunicationVariable.ValueReallyChanged`）

数组每拍都会切出新实例，按引用比较会让 `ValueChanged` 每拍都触发（几万点场景的事件风暴源）。
现在任意数组按长度 + 逐元素比较；`byte[]` 不装箱、逐字节比较。

### 4.3 方案落盘

- `VariableDto.Length` 必须落盘：不落盘则重开方案后 `Length` 回到默认 1，数组静默变回标量。
- `VariableDto.AddressOffset` / `UseLegacyAddress` 同样落盘；`UseLegacyAddress` 只对 `ModbusAddress` 生效（反射设置，Core 不反向引用通信程序集）。
- 旧方案没有这三个字段 → 反序列化为 0/false → `BuildAddressConfig` 保留类型默认长度，行为不变。

### 4.4 UI 只读边界

- `GlobalVariableValueModeConverter` 新增两支：
  - 网络数组根 → `NetworkArrayRoot`（`ArraySummary` + 「只读」徽标，无「编辑数组…」）；
  - 网络数组元素行 → `ReadOnlyChild`（只读文本，无编辑框、无元素 ↺）。
- 判定顺序放在 `isReadOnly` 之前：只读存储区里的网络数组不会落到 `ReadOnlyRoot` 把 `System.Int32[]` 上屏。
- 即使绕过界面直接调模型：`VariableNode.CommitChildElementEdit` / `ResetElementValue` 与 `NetworkVariableModel.TryWriteCore` 都有第二道拒绝。

## 7. 操作说明（现场）

1. 变量管理 → 选中某条连接 → 「＋ 添加变量」。
2. 数据类型选「整数数组 (int[])」/「小数数组 (double[])」/「单精度数组 (float[])」。
3. 「元素个数」填要读的元素个数（如 10）。
4. 地址：
   - 默认按 **0 基偏移**填（保持寄存器 40001 对应 0）；
   - 或勾选「40001 写法」，直接填 `40001`；
   - 需要从基地址再挪 N 个寄存器/字节时填「地址偏移」（默认 0）。
5. 「地址预览」会显示最终下发的地址（如 `x=3;2`）；非法写法会直接显示原因。
6. 创建后变量表根行显示数组摘要与「只读」徽标，展开可看每个元素；流程里可用 `变量名[下标]` 取元素。
