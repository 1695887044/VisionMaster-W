# 流程栏视觉改版（v2 设计基线复刻）

日期：2026-10-19
范围：
- `VisionMaster/Views/ProcessView.xaml`（整体重写视觉层）
- `Core/Models/ProcessStep/ContainerStepCountWatcher.cs`（新增）
- `Core/Models/ProcessStep/ParallelStep.cs`、`ConditionStep.cs`、`ForStep.cs`（新增 `TotalStepCount`）

设计依据：`docs/UI设计基线/process-panel/design.html`（v2）+ `README.md`。

## 为什么改

v1 只修了"画错/看不清"（失败态不统一、名字被 × 顶偏、计数 2.2:1 对比度、分支无悬停反馈），
整体仍是旧观感。用户要求"再美化一点、现代一点"后出 v2 基线：**更平、更轻、层级更清楚**。

## 改了什么

### 1. 行容器：从"内容宽度"改为"整行"

`ModernStepContainerStyle` 的 `ContentPresenter` 去掉 `HorizontalAlignment="Left"`（默认 Stretch），
分组头 / 分支 / 算子行都铺满整行，状态底色与 section bar 才能横贯。

分组与分支的色条要延伸到展开箭头下方：模板里给 `Expander` 设 `Panel.ZIndex="2"`，
数据模板用 `Margin="-22,…"` 把条左移；内容再用 `19`（分组）/ `22`（分支/算子）的左内边距
拉回 30px 竖线，三种行的文字/图标仍然对齐。

### 2. 分组头：整行 section bar

- 3px 身份色条（`ContainerAccentBarStyle`，上下内缩 9px、右端圆角），按容器类型取色：
  并行蓝 / If 灰 / While 橙 / For 绿 / Case 青蓝。
- 类型标签（图标 + 文字，11px SemiBold，无 chip 底色）+ 实例名（13px SemiBold，补 ToolTip）。
- 右侧统计：`Children.Count`（「N 分支」）+ `TotalStepCount`（「M 算子」）；循环体显示「循环体 · M 算子」。
- 右侧状态位（运行转圈 / 成功勾 / 失败感叹号）。
- 状态底色：运行 `DialogSuccessSubtleBrush`、失败 `DialogDangerSubtleBrush`、选中 `DialogAccentLightBrush`。

### 3. 分支：整行子标题

浅蓝底 + 1px 发丝边 + 右对齐计数；悬停用一层 `HoverLayer`（保住身份色）+ 描边提亮；
空分支用叠加 `Rectangle` 画虚线框（WPF `Border` 不支持虚线）。

### 4. 算子行：柔和状态底色，去掉硬描边

- 失败：`DialogDangerSubtleBrush` 整行底 + 白底图标块 + 红字（名字/类型/耗时/图标）+ 状态列感叹号；
  **不再有 1px 红边、不再有名字前的 ×**（× 会顶偏名字，且读作关闭）。
- 运行：`DialogSuccessSubtleBrush` 整行底 + 白底图标块 + 绿字 + 状态点脉冲。
- 图标块 24→26px、圆角 6→7；耗时去掉灰底胶囊，改纯文字 + 小钟表、右对齐。
- 等待节点与算子行同构：第二行「等待 · 条件」，去掉重复图标与单独 chip。

### 5. 模型：`TotalStepCount`

`Children.Count` 由 `ObservableCollection` 自带通知；「M 算子」是各分支 `Steps.Count` 之和，
集合不会替容器发通知，所以新增 `ContainerStepCountWatcher`：订阅 `Children` 增删 + 每个分支
`Steps` 增删，任一变化回调 `RaisePropertyChanged(nameof(TotalStepCount))`。
`Children` 被反序列化整体替换（`ObjectCreationHandling.Replace`）时由 `Rebind` 摘挂旧集合。

## 已知偏差 / 注意事项

1. **渲染探针里的图标是豆腐块**：`RenderProbe` 把 `app.Resources["Icon"]` 直接设成
   `Segoe MDL2 Assets`（line 70），它优先于场景 F 后合并的 App.xaml 内联资源（FA 字体），
   所以探针图里 `&#xf06a;` 与算子图标显示为空框。**这是探针环境现象，不是产品缺陷**；
   真机走 App.xaml 的 `Icon`（Font Awesome 6 Pro Solid），原截图里组头的红色感叹号即 f06a。
2. **分组条左边界**：从展开箭头之后（30px 竖线）开始向右；箭头由 `ZIndex` 压在色条上。
   若将来调整 TreeViewItem 模板的 `Padding`/箭头列宽，`-22` 与 `19/22` 两组数字要同步。
3. **分支悬停**用叠层而不是换底色：Else/循环的身份色不会被悬停冲掉；叠层透明度 0.6。
4. **脉冲只在 `State=Running` 启动**：`IsRunningFocus` 只保留视觉 setter，不重复起动画，
   避免两个触发器抢同一组 `ScaleTransform/Opacity` 动画。
5. **R23/R25 未动**：所有 `DataType` 模板与分支卡片的命令链/右键靶机制保持原样，
   只改视觉；`ProcessTreeTemplateChecks` 与 `RenderProbe` 的点击拦截判据全部通过。
