## 3. 问题清单（comm 报告 + reviewer 复核裁决后）

### 3.1 架构性瓶颈

#### P-A1【高】单连接单 Worker 线程串行化上限 ~1700req/s

`ConnectionWorker.cs` 单线程串行模型；S2 实测 167 段 × ~1ms ≈ 167ms > 100ms 周期，达成率封顶 82%。**结构性上限，非 bug**（HSL 设备对象非线程安全，并发访问同一连接对象会乱序）。

修复方向（按 reviewer 风险排序，由小到大）：

1. **文档明示**"单连接吞吐 ≈ 1000 / 段耗时 段/s"，引导高频大点数**拆多连接**（诊断面板 `ScanGroupStats.AchieveRate` 现成）；
2. 段解码零分配化（见 P-A3）；
3. 事件派发挪出 Worker 线程（**风险最大**：`CommunicationVariable.UpdateValue` 在 Worker 线程同步 `Invoke ValueChanged`，下游订阅者异常会被误判连接断裂；挪走可拆弹但引入事件乱序，需单独评估立项）。

#### P-A2【中】PollScheduler 周期基准漂移

`PollScheduler.Run`（`PollScheduler.cs:266-288`）无预算截断 + 周期基准漂移。reviewer 补强根因：`PollGroup` 的 `MsUntilDue` / `IsDue` 以 `_lastSuccessTicks` 为基准（`PollGroup.cs:75,102`），**执行耗时永久计入周期且无追平机制**——是 **drift** 不是单次顶住。S5 快组实测 109ms vs 目标 100ms 即此现象。

**正解**：把 `MarkSuccess` 基准改为"对齐时刻表"（如 `Math.Min(now, lastSuccess + interval)`），**不是加预算截断**。功能上不丢轮次不饿死，维持中级。

#### P-A3【中】热路径堆分配 27MB/s 量级

comm 原指 `PollBatchPlanner.DecodeValue`（`:558-559`）`new byte[]`；reviewer 修正归因大头：

- `HslHelper.ConvertTo<T>` 的 `new byte[need]` + `ToLogicalBigEndian` 的 `(byte[])wire.Clone()`（`HslHelper.cs:69,111-113`，**每个数值变量每轮 2 次堆分配**）；
- HSL 内部每帧中间缓冲。

**正解**：`HslHelper.ConvertTo` 出 **Span-based 零分配重载**（.NET 9 `BitConverter.ToInt16(ReadOnlySpan<byte>)`，`ToLogicalBigEndian` 可原地换序）。Gen0 频繁但 Gen2=0，是 CPU/功耗开销不是故障。

### 3.2 线程安全

#### P-T1【低】`ConnectionWorker.cs:67` `_reconnectAttempt` 非 volatile

写点三处（`:207` Connect 任意线程 / `:390` RunPollCycle / `:470` ScheduleReconnect），读点 `:403` / `:408`（Worker）。comm 的"`_nextConnectTick` 屏障"说法只对 `:207`→Worker 一跳成立（`:209` `Volatile.Write` 与 Loop `:319` `Volatile.Read` 配对）；反向无屏障，但当前无跨线程读者 = 良性竞争。**哑弹**：将来诊断面板加"重连次数"列即踩中。修法一行 `volatile`。

#### P-T2【低】`AdvancedCommunicationManager.cs:48` `IsRunning` 非 volatile

仅 UI 提示位，风险近零。

#### F2【中，reviewer 新发现】值/时间戳发布配对撕裂

`CommunicationVariable.UpdateValue` / `MarkBad` 多线程写读无发布配对（`CommunicationVariable.cs:114-118,128,131-136`）：UI 线程读 `CurrentValue` + `LastUpdateTime` 可能读到**不属同一轮的撕裂组合**（`DateTime` 8 字节 struct，非原子读写）。**几万点高频下必现**。

修法：赋值后 `Volatile.Write` 版本号，或 `LastUpdateTime` 改 `long` ticks + `Interlocked.Exchange`。

### 3.3 代码质量

#### P-Q1【低】建连段逐字重复

`ModbusTcpConnection.cs:93-129` 与 `SiemensS7Connection.cs:80-112` 建连段逐字重复，建议抽 `EthernetConnectionBase`。**不急**：`SerialConnection` 形态不同，强行归一会扭曲串口语义。

#### P-Q2【提示】KeepAlive 语义名不副实

HSL `SetKeepAlive(SocketKeepAliveTime, SocketKeepAliveTime)`（`NetworkDoubleBase.cs:412-414`）两参数同值——配置名 `KeepAliveIntervalMs` 实际同时当了"**首次探测前空闲时长**"（Win32 `keepalivetime`）。默认 30000ms 意味着**空闲 30s 才开始探**，对半开检测贡献比名字暗示的弱。契约文档 / UI 提示应写清。

#### P-Q3【提示】DeviceSimulator 字节序宣传名不副实

`ModbusSimServer`（`tools\DeviceSimulator\Program.cs:343-355`）**从未把 `Order` 下发给 HSL 服务端**；HSL `ModbusTcpServer.DataFormat` setter（`ModbusTcpServer.cs:56-66`）只改 `base.ByteTransform`，请求帧解析全走私有 `byteTransformSelf`（`:53` 构造恒 CDAB）。**10 台全部 CDAB**，CommPerf 按端口字节序 3/10 通过是靶子特性（ABCD/CDAB 16 位退化等价碰巧对两台 + CDAB 恒真一台），**非产品缺陷**。建议在 DeviceSimulator 源码注释标注。

#### F1【中，reviewer 新发现】轮询事件异常污染质量戳

`PollBatchPlanner.ApplyBytes` / `ApplyBits`（`:511-523,:544`）把"解码"与"`UpdateValue` 事件派发"包在**同一个 try** 里——下游订阅者（`NetworkVariableModel` `PropertyChanged` 链、`ScadaRuntimeBinder` Halcon 转换、报警引擎）抛异常时，**值明明已读到已更新**，变量却被 `MarkUncertain()`（UI 黄点"读取失败"）+ 记一条误导性"解码失败"日志，且 `failed` 不计数。

修法：`UpdateValue` 挪出解码 try 单独 catch，异常只记日志不降质量戳。

#### F4【低，reviewer 新发现】写设备失败静默

`NetworkVariableModel.WriteToDevice`（`:179-199`）失败只 `Debug.WriteLine`、不更新镜像、离线时直接 `return` 无任何痕迹——"**看着写进去了其实没有**"，与 R33/R34 静默不生效同族。建议失败走 `ILogService.Warn`（需 Bridge 注入日志通道）。

#### F5【低，reviewer 新发现】串口无 ILinkHealthProbe

`SerialConnection` 无 `ILinkHealthProbe`：串口半开时 early-abort 问不到链路状态，退化为段数 × `ReadTimeoutMs`（167 段 × 3s ≈ 8 分钟才判掉线）。**能力缺口非 bug**（串口无 socket 错误标志），建议文档明示 + 串口 `ReadTimeoutMs` 默认收窄或加"连续 N 段超时判链路故障"启发式。

#### F7【提示，reviewer 新发现】$type 白名单 binder 放行面偏宽

`ConnectionConfigJsonConverter.cs:98-116` 对 `Plugin.` 前缀放行面比注释宣称宽：`assemblyName` 解析失败时退化到全 AppDomain 按全名搜索。白名单确实在拦（非裸奔），攻击面需先有配置文件写权限。建议将来收窄为"已加载插件程序集 ∩ `Plugin.` 前缀"。

#### F3【中危欠账，主会话裁决】连接改名路径幽灵转发

Manager 侧 `_registeredVariables` / `_varForwardHandlers` 键是**旧连接名**，Bridge 侧 `Unregister` 用**新名**查不到旧键 → 旧转发 handler 永久挂 `CommunicationVariable`（**幽灵轮询**）。若 UI 允许运行中改连接名则是活的泄漏（中危）；若只读则是防御性欠账（低）。

**主会话裁决：按中危欠账记录**——短期先**禁止运行中改连接名**（UI 锁定或文档明示），长期做 `RenameConnection` 原子迁移键。

## 4. 压测方法学备注（reviewer 指出，4 处失真点，不推翻结论方向）

1. **S9 "最差达成 94%"偏乐观**：达成率来自 `PollGroup` EMA（α=0.25），对周期性尖峰有平滑；诊断面板只有 EMA 无 max/p99。
2. **S9 GC 口径是全进程计数**："Gen0 54 次"不能全归因于解码分配（还含 20 条 Worker 的日志/事件分配）。
3. **S10 "洪峰中同步写 p99 156ms"是三段之和**（入队等待 + 排队 + 写），缺"入队时队列深度"旁证，无法分离背压占比。
4. **S9 建连等待 10s 上限截断风险**：未全就绪时仍带病跑稳态窗口，"2 万点"口径可能名不副实；建议改为未全就绪则跳过场景。
