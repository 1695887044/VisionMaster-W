# SCADA 属性分组目录与注册期校验（批次 A）

日期：2026-10-20
起因：用户问「Scada 图元的属性是不是还没做，怎么和设计稿不一样」，探查后确认面板功能完整，
但**分组名是一串散落的字面量 + 分组顺序取"声明里首次出现的次序"**，与设计基线不一致；
更关键的是「哪些组不许绑变量」按字符串精确匹配，改一个组名就会静默失效。本批先立约束，不动上屏文案。

范围：

- `Scada.Controls/Descriptors/ScadaPropertyGroups.cs`（**新增**：组名目录 + 顺序表 + 绑定口径）
- `Scada.Controls/Descriptors/ElementDescriptor.cs`（删 `NonBindableGroups`，加注册期分组校验）
- `Scada.Controls/Descriptors/ElementValueAccess.cs` / `PropertyPacks.cs` / `BuiltInElements.cs` /
  `ElementPropertyDescriptor.cs` / `ScadaPropertyAttribute.cs` / `ScadaPageProperties.cs` / `ScadaPageEvents.cs`
- `Scada.Controls/Elements/*.cs`（21 个图元类的 `[ScadaProperty(Group = …)]`）
- `Scada.Controls.Charts/Elements/ChartTrendElement.cs`
- `VisionMaster/ViewModels/ScadaPropertyViewModel.cs`（分组排序）
- `ScadaChecks/Program.cs`（新增 `[AH]` 10 条；4 条既有组序断言对齐到目录顺序）

## 一、问题（三条静默失败）

| # | 现象 | 为什么危险 |
| --- | --- | --- |
| 1 | `ElementDescriptor.NonBindableGroups = { "位置与尺寸", "外观" }` 按**字符串精确匹配** | 把「位置与尺寸」改名成设计稿的「布局」，编译期全绿、注册照常通过，那条"几何属性不许绑变量"的校验**当场失效**，面板上凭空多出一个 ƒx |
| 2 | 面板分组顺序 = `GroupBy` 的首现次序（`ScadaPropertyViewModel.Rebuild`） | 同一个「外观」组在按钮面板排第 4、在灯面板可能排第 2；用户每换一个图元都要重新找 |
| 3 | 14 个图元组名散在 5 个描述符文件 + 21 个图元类 + 曲线工程 + 面板视图模型里 | 新加图元顺手写「文本」而不是「文字」，两段看起来一样的分组并存，谁都不会发现 |

另有一个隐形默认值：`ScadaPagePropertySpec.Group` 原先默认 `"画面"`——这个组名**不在任何目录里**，
一旦有声明忘了写 `Group`，面板上就多出一段谁也没见过的分组。

## 二、改动

### 1. 新增 `ScadaPropertyGroups`（唯一出处）

- 19 个常量（14 个图元组 + 5 个画面组），**常量值就是上屏文字**；
- `Order`：面板上的分组顺序（先图元后画面）；
- `NonBindable = { Layout, Appearance }`：接管原 `NonBindableGroups` 的职责；
- `IsKnown` / `OrderOf` / `AllowsVariableBinding` 三个查询。

排序口径（为什么是现在这样）：前四组对齐设计基线的「基本 / 外观 / 文本 / 布局」；
中间是图元自己的功能数据（状态 / 数据 / 图像 / 刻度 / 点位 / 操作 / 限制）；
末尾是配置类（权限 / 事件 / 动画）。画面组排在最后——它与图元属性**互斥出现**，
相对位置不影响观感，合在一张表里只是让"查一个组在第几位"只有一份实现。

### 2. 全仓字面量 → 常量

按 AGENTS.md R1–R5 的口径做批量替换（中文映射放 UTF-8 清单、脚本纯 ASCII、
写回用 `UTF8Encoding($false)` 且保留 BOM 状态），共 **33 个文件**。
替换后自检：严格 UTF-8 解码全部通过、无残留 `Group = "…"`（唯一的 5 处命中是
`AlarmGroup = "冷却水"` 这类无关字段与一行注释）。

### 3. 注册期校验（`ElementDescriptor.Validate`）

```csharp
if (!ScadaPropertyGroups.IsKnown(property.Group))
    return $"{TypeKey}.{property.Key} 的分组「{property.Group}」不在 ScadaPropertyGroups 目录里" +
           "（新增分组要先登记到目录，否则面板排序与「不可绑定」口径都会漏）";

if (property.IsBindable && !ScadaPropertyGroups.AllowsVariableBinding(property.Group))
    return $"{TypeKey}.{property.Key} 位于「{property.Group}」组，该组属性一律不可绑变量";
```

写错组名 = **注册失败**（图元进不了工具箱，原因进 `ElementRegistry.BuiltInErrors`），
与"目标依赖属性不在控件上""默认值转不过去"同一待遇。

### 4. 面板按目录排序

```csharp
Groups = _rows
    .GroupBy(row => row.Group, StringComparer.Ordinal)
    .OrderBy(g => ScadaPropertyGroups.OrderOf(g.Key))   // 未知组 int.MaxValue，稳定排序保持首现次序
    .Select(g => new ScadaPropertyGroup(g.Key, g.ToArray()))
    .ToArray();
```

### 5. 顺手收紧的两处

- `ScadaPagePropertySpec.Group` 改成 `required`，删掉那个不在目录里的 `"画面"` 默认值——漏写现在**编译不过**；
- 修正 5 处 `<see cref="ElementDescriptor.NonBindableGroups"/>` 与 3 处"按首现次序排"的过期注释。

## 三、上屏变化（升级必读）

- **组名一个都没改**（仍是「常规 / 位置与尺寸 / 文字 / 外观 / 权限…」），改名留给批次 B；
- **分组顺序变了**，每个图元都受影响。例：
  - 矩形：`常规/位置与尺寸/外观/文字/动画/权限` → `常规/外观/文字/位置与尺寸/权限/动画`
  - 按钮：`常规/位置与尺寸/文字/外观/事件/动画/权限` → `常规/外观/文字/位置与尺寸/权限/事件/动画`
  - 指示灯：`常规/位置与尺寸/状态/外观/文字/动画/权限` → `常规/外观/文字/位置与尺寸/状态/权限/动画`
- 顺序只在选中图元时体现，`.vms` 文件格式**零变化**（组名是界面语义，不落盘）。

### 断言（`ScadaChecks`，全量 **2087 通过 / 0 失败**）

新增 `[AH]` 10 条：

```
[√通过] 目录顺序表非空、没有重名  →  共 19 组
[√通过] OrderOf 与顺序表下标一一对应（IsKnown 认的是同一份表）  →  19 组
[√通过] 未知组一律判「不在目录里」且排到最后（int.MaxValue）  →  OrderOf=2147483647
[√通过] 「位置与尺寸」「外观」两组不许绑变量，其余组可绑  →  位置与尺寸、外观
[√通过] 目录显示名快照（改名必须同时改这条断言）
[√通过] 每个已注册图元的每个属性组都在目录里  →  图元 28 个
[√通过] 每条画面属性的分组都在目录里  →  8 条
[√通过] 画面事件的分组在目录里（与「启动画面」同处「运行」组）  →  运行
[√通过] 反证：属性声明了目录外的组 → 注册被拒（不是静默放行）
[√通过] 反证：「外观」组里声明 IsBindable=true → 注册被拒（改组名不会再让这条失效）
```

**反证有效性**：改代码前先跑了一遍全量——4 条既有断言**准确变红**（它们钉的正是旧的首现次序）：

```
[×失败] 组序取自描述符里的首现次序：常规→位置与尺寸→外观→文字→动画→权限
[×失败] 位按钮：…（组序按声明首现，状态组排在几何之后、文字之前…）
[×失败] 按钮：…（组序是声明出来的…）
[×失败] 指示灯：…多出来的是一个状态组
```

把期望值对齐到目录顺序后 4 条全部转绿——说明这批断言确实在跑，不是"绿灯是真的，只是少了一条"（R65）。

## 五、未做（后续批次）

## 六、遗留说明

源生成器 `Shard/Core.ScadaGenerators/ScadaPropertyGenerator.cs` 里还有一处
`public string? Group = "外观";`（属性没写 Group 时的兜底）。生成器是 netstandard2.0 的
analyzer 工程，**不能引用** `VM.Scada.Controls`（R17 同族：分析器不该加载目标程序集），
所以这处字面量保留，由 `[AH]` 的"显示名快照"间接钉住——快照红了就说明两处对不上了。
