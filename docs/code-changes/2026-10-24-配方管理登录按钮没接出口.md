# 2026-10-24 配方管理「登录」按钮没接出口

## 现象

配方管理对话框未登录时的橙色权限条，右下「登录」按钮点了没有任何反应
（用户 2026-10-24 截图报告："配方管理这个登录按钮是不是没做好"）。

## 根因

`VisionMaster/Views/DialogViews/RecipeManagerView.xaml:550` 绑的是
`Command="{Binding LoginCommand}"`，而 `RecipeManagerViewModel.LoginCommand`
构造时是 `new DelegateCommand(() => RequestLogin?.Invoke())` —— `RequestLogin`
**从来没人赋过值**：宿主 `RecipeViewModel.OpenManager()` 打开对话框时没传出口，
VM 也没有 `OnDialogOpened` 接收点。于是按钮常驻可见、`CanExecute` 恒真、
点了空跑 —— 典型的"死键"，而且是静默的（无异常、无日志）。

## 改动

| 文件 | 改动 |
|---|---|
| `VisionMaster/ViewModels/DialogViewModels/RecipeManagerViewModel.cs` | ① 新增 `RequestLogin` 出口属性（setter 里连带 `RaisePropertyChanged(nameof(ShowLoginEntry))`）；② 新增 `ShowLoginEntry => !IsLoggedIn && RequestLogin != null` —— **没有出口就把按钮藏起来**，不再留死键；③ `LoginCommand` 改指 `ShowLoginByHost`（弹窗回来后再 `Refresh()` 一次，权限条才会消失）；④ `OnDialogOpened` 读参数键 `RequestLoginParameter = "RequestLogin"` 注册出口；⑤ **重入闸** `_loginEntryActive`（见下）。 |
| `VisionMaster/ViewModels/RecipeViewModel.cs` | `OpenManager()` 经 `DialogParameters` 把 `RegisterLoginEntry` 交给对话框；新增 `ShowLoginDialog()` 弹 `ScadaLoginView` 并 `Refresh()`；对话框关闭后再 `Refresh()` 一次，让顶部 chip 同步。 |
| `VisionMaster/Views/DialogViews/RecipeManagerView.xaml` | 登录按钮补 `Visibility="{Binding ShowLoginEntry, Converter={StaticResource BoolToVisibility}}"`。 |
| `tools/probes/_RecipeUiProbe/Program.cs` | 新增 `[LoginEntry]` 三条断言 + 未登录出图 `design-readonly.png`。 |

## 踩到的坑（都真跑出来过）

1. **出口接成"再调回来"就是无限递归**。探针第一版把 `Action<Action>` 的回调错绑成
   `vm.LoginCommand.Execute`，实测 `Stack overflow. Repeated 10706 times`，
   栈里全是 `ShowLoginByHost → b__2 → ShowLoginByHost`。真实宿主给的是 `Refresh`，
   但这条路径**必须自己防住**（VM 不能假设宿主接得对），故加 `_loginEntryActive` 重入闸。
2. **构建报 0 错误不等于探针跑的是新代码**。中间一轮先 `dotnet build` 探针工程时报
   `CS2001: 未能找到源文件 …obj\Debug\net9.0-windows\Views\*.g.cs`（obj 残缺），
   探针 exe 仍是旧的，于是"改了重入闸还是栈溢出"。正确顺序是**先完整重建主工程，
   再建探针**（`VisionMaster.csproj` 是 ProjectReference），且**只看构建退出码会误判**。
3. 探针控制台是 GBK，`grep` 中文前要 `iconv -f GBK -t UTF-8`，否则断言行匹配不上。

## 未做 / 已知边界

- **没有在真 `VisionMaster.exe` 里点过**（R175：断言宿主优先，真 exe 用来证渲染/启动链）。
  无头探针证明的是"点击 → 宿主出口 → 收尾刷新"这条链，以及"无出口不出死键"，
  真机的一次点击仍建议人眼确认一次。
- 顶部 `未登录` chip（`Shell.xaml` 一带）是**另一条独立入口**，本次未接。
- `RecipeViewModel.ShowLoginDialog` 现在是实际被调用的那条路；若日后要复用
  「登录后弹回原对话框」，需要在此处改为 `ShowDialog` 后重开，属独立批次。

## 守门

本轮**没有新增自动闸**：`[LoginEntry]` 三行写在既有探针 `_RecipeUiProbe` 里，
不归属 `run_gates.ps1` 的六个断言宿主。要变成守门，需把这三条搬进
`ScadaChecks`/`UIThemeSmokeTest` 并在 `run_gates.ps1` 里可见 —— 记为待办（R177）。
