# 「系统设置」第二批：日志 / 服务与启动 / 并行执行 / 账号策略（2026-10-21）

## 1. 起因

用户看完合并后的「系统设置」问："是不是少了关于日志的功能——保留时间、记录地址等等"。

查下来**不是这次合并弄丢的**：`Core\LogService.cs` 里保留天数是 `private const int RetentionDays = 30`、
目录是 `Path.Combine(AppContext.BaseDirectory, "Logs")`，从来就没有配置项，也从来没有界面。

顺手把 `AppConfig.json` 的全部配置节过了一遍，发现更扎眼的是一批**"已经在配置文件里、界面上一个入口都没有"**
的开关——现场只能手改 JSON：

| 配置节 | 字段 | 现状 |
| --- | --- | --- |
| `ParallelExecution` | `FailFastByDefault`、`ForceSequential` | 只有代码读，没有任何地方写。并行分组弹窗的说明区还写着"⚠ 全局已开启强制顺序"，却找不到开关 |
| `HttpImageServer` | `Enabled` / `Host` / `Port` / `Token` / `RequestTimeoutMs` | 手改 JSON；代码自己打 Warn 说"请修改 AppConfig.json 的 Token" |
| `NetworkCameraServer` | `Enabled` / `Host` / `Port` / `Token` | 同上 |
| `EnableCommunicationStartupCheck` | 开关 | 手改 JSON |

另外 `AlarmFrames`（报警图集）目录**只写不删**——每次报警把整个图集落盘，每张 ~15MB 量级，
是全仓唯一一个没有上限的磁盘增长点。

用户裁定："全部做掉"。

## 2. 改动清单

### 2.1 配置模型（`Core\Models\AppConfigModel.cs`）

新增六个字段 + 一个枚举：

| 字段 | 默认 | 语义 |
| --- | --- | --- |
| `LogRetentionDays` | 30 | 0 / 负数 = 永不清理（与审计 / 报警同口径） |
| `LogDirectory` | `""` | 空串 = 程序目录 `Logs`（= 历史行为） |
| `LogFileLevel` | `Info` | 落盘最小级别（面板不受影响） |
| `LogPanelMaxRows` | 5000 | 面板内存条数上限，0 / 负数 = 不限制 |
| `AlarmFrameRetentionDays` | 90 | 0 / 负数 = 永不清理 |
| `MinPasswordLength` | 4 | 0 / 负数按默认 4 处理（不是"允许空密码"的后门） |

`LogFileLevel` 的三个成员带 `[Description]`——属性面板的 `EnumGenerator` 读的是它（R84）。

### 2.3 设置弹窗

草稿新增 18 个字段、三个新页签（日志 / 服务与启动 / 并行执行），账号策略挂在「安全与留档」下：

| 页签 | 字段 |
| --- | --- |
| 运行窗口（2） | 独立运行窗口、落在哪块屏 |
| 安全与留档（4） | 空闲自动登出；操作审计保留、报警历史保留；密码最小长度 |
| 画布（9） | 6 个开关 + 总张数上限、单流程上限、**报警图集保留天数** |
| 日志（5） | 保留天数、目录、落盘最小级别、面板保留条数、**打开日志目录**（`[Command]` 按钮） |
| 服务与启动（10） | HTTP 收图服务 5 项、网络相机收图服务 4 项、启动时通讯自检 |
| 并行执行（2） | 失败聚合默认、强制顺序总闸 |

VM 侧新增三道**保存前**的闸 + 一道保存后的生效链：

1. 端口必须 1~65535（`TryParsePort`）；
2. 启用状态下访问令牌不许为空（空令牌 = `Authenticate` 里 `token.Length > 0` 永远不成立 = 谁都连不上）；
3. 日志目录**改了才试写**（建目录 + 写探针文件 + 删掉）——不试写的话，指到不可写目录的表现是
   "日志面板照常、文件一条没有"，是最阴的一类静默故障；没改的时候不试，免得"网络盘刚好断线"
   把无关的保存也拦下来；
4. 保存后按变更分派生效动作：日志（`RequestReopen` + `CleanupNow`）、图集裁剪/清理、收图服务 `Restart`。
   生效动作抛异常时**配置已落盘、弹窗不关**，红字说明"已保存但没生效"，让用户改端口后重试。

## 3. 几个刻意的取舍

**令牌绝不进审计**：审计"说明"列只写「HTTP 访问令牌：已修改」，不写值。历史流水是长期留存的文件，
把凭据写进去等于把密钥摊在磁盘上。

**密码最小长度填 0 按默认值处理**：这条配置的语义是"至少几位"，配成 0 就成了一条悄悄关掉校验的后门。

**报警图集只删认得出的目录**：`AlarmFrames` 下只处理名字能按 `yyyy-MM-dd` 解析的子目录，
其它目录一律不动——那里可能有现场自己放的东西。判据用**目录名**而不是文件 mtime（拷来拷去会改 mtime）。

**日志目录为空 = 历史行为**：`LogDirectory` 空串时 `LogService` 和「打开日志目录」按钮都用
`程序目录\Logs`，两处口径逐字相同（按钮打开一个和真正落盘位置不同的目录，比没有按钮更糟）。

**并行两个开关不需要重启**：`AppSettingsService.Save()` 里本来就有 `SyncParallelConfig()`，
把配置灌进 `GlobalParallelConfig` 静态桥——写进配置再 `Save()` 就生效。

## 5. 纪律

1. **"改完立即生效"必须由使用方现读配置保证**，不是在保存时把新值推给谁。本次三个落点：
   `LogService` 每次开文件读目录、每次清理读保留期、每行入队读级别；`ScadaUserStore` 每次校验读最小长度；
   `ImageCollectionService` 每次清理读保留期。凡是做不到现读的（收图服务的 Host/Port 是绑定期决定的），
   就老老实实"保存后重启服务"，并在界面提示里写明。
2. **给"路径类"配置做保存前试写**。目录不可写的表现是"文件通道静默降级"，用户看不到任何错误——
   这类配置的校验不是"格式对不对"，而是"能不能真的写进去"。
3. **凭据不进审计、不进日志**。只记"改过"。
4. **"0 / 负数"的语义要逐项写清**：保留期类 = 永不清理，上限类 = 不限制，密码长度 = 用默认值
   （不是关掉校验）。三者的默认值都放在 `AppConfigModel` 的常量上，别在服务里再写一个数。
5. **`[Command]` 是按名字绑定的**：属性名拼错不报错，只会渲染出一个永远点不动的按钮。
   用到它就要有一条"名字对得上 + 点了真执行"的断言。
6. **并发编辑的代价**：本轮开工时 `CameraSettingsViewModel.cs` 缺 `#endregion`、
   `HardwareManagerViewModel.cs` 调 `DelegateCommand.Execute(null)`、`ScadaChecks\Program.cs` 出现重复类——
   都是同一时间另一个会话在改同一批文件留下的。构建红了先看"是不是别人的半成品"，
   改完自己的部分再确认对方的改动没有被自己覆盖。
