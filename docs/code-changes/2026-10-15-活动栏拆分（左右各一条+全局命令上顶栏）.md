## 四、关键技术决策（为什么）

### 1. 为什么选 A（镜像双活动栏）而不是 B / C

- **B（单条瘦身）**：删掉 3 个错配图标能让"指示器不再说谎"，但代价是右侧三个面板**失去一键开关入口**（只能走「视图」菜单找），而且它并没有回答用户的真问题——用户问的是"放哪儿更好"，B 是"干脆不放"。**A 的额外成本只有一条 48px 竖条**（左侧那条本来就占 48px，所以净增 48px），换来"图标 = 落点"这条语义完整。
- **C（全部并入顶栏）**：顶栏已经是三段式（运行控制 / 居中方案名 / 窗口控制），再塞 5 个面板开关会明显变挤（窄窗尤甚，见 §七-2）；更关键的是**语义不对**——活动栏项是"常驻竖向 + 状态高亮"（`IsChecked` 绑 `IsXxxActive`），顶栏 `TitleButton` 是无状态的瞬时命令按钮，面板开关放进顶栏就没有"这个面板现在是开着还是关着"的视觉反馈了。
- **A**：图标贴在它所管面板的那一侧（VS Code 惯例），零命令语义改动，只挪位置——**改动面最小、语义最正**。

### 2. 为什么两个命令上顶栏（而不是留在左条）

它们是**命令**（点了弹窗），**没有面板落点**。活动栏项的第一语义是"面板开关 + 高亮状态"，命令塞进竖条既没有高亮状态、也混了语义（"这条竖条里哪些是开关、哪些是按钮"）。顶栏本就是**全局命令区**（`TitleButton` + `TitleSeparator` 是既有范式，运行控制组就在那儿）——`SystemAction` 里的 `UserLogin` / `CameraSettings` / `SystemParameters` 等其它系统命令也走的是顶栏 / 菜单，本轮只是把这两个归位。

### 3. 为什么「属性」面板不加活动栏项

它是**上下文面板**（没有选中图元时是空的），历史上就没有活动栏项。给它加图标会误导用户"点开就有东西"，且右侧条已经有 3 个图标、再加会变长。**本轮沿用既有设计，不新增**（用户若希望也能一键收起，见 §七-6）。

### 4. 为什么**不用**升 `CurrentLayoutSchemaVersion`（与 R43 的边界说明）

这是本轮最容易被误判的一点：**改了 `Shell.xaml`，但按 R43 的口径不触发结构版本递增**。理由是：

1. **活动栏与顶栏在 `LayoutRoot` 之外**——它们是主体 Grid 的**第 0 列 / 第 2 列**与**第 0 行**；`LayoutRoot`（`Shell.xaml:805-952`）整个包在 `DockingManager`（`:798`）里。R43 的机制（`LayoutHelper.IsLayoutXmlUsable` / `LoadFromString` / `Reset`）只管 `LayoutRoot` 的序列化与恢复，**根本不看活动栏与顶栏**。
2. **面板归属与停靠语义一字未变**——没有增删面板、没有换 pane、没有 `anchorable ↔ document` 转换、没有改标签页分组（本轮 `DockingManager` 子树 `:798-953` 完全没动）。
3. 结论：**磁盘上的 `Layout.xml` 仍然有效，用户自拖的布局不会被作废**（对比上一轮 v2→v3 的"升级后老布局静默作废"，本轮没有这个后果）。

> **R43 的触发条件是"面板归属 / 停靠语义变了"，不是"`Shell.xaml` 变了"。** 判断口径：问"这份旧 `Layout.xml` 恢复出来会不会把改造抵消掉？"——本轮不会（活动栏根本不在 `Layout.xml` 的覆盖范围里），所以不升。这条边界已写进 `AGENTS.md` §14 的 `R47`。

### 5. 为什么刻意保留 `ActivityAction`（本轮后变成零引用）

`ActivityAction`（`Shell.xaml:124` / `ShellCopy.xaml:123`，`TargetType="Button"`）的原用途就是左条底部那两个命令按钮；它们上移顶栏后这个 `Style` **零引用**（实测：两个文件里只有定义行本身命中，无任何 `{StaticResource ActivityAction}`）。

**仍然保留**，两个理由：① **最小改动**——本轮是"挪图标"不是"清样式"，顺手删会让 diff 混入无关变更；② **它是 `Shell.xaml` 自身 `Window.Resources` 里的样式**，`{StaticResource}` 在视图侧是**运行期解析**，静态扫描未必覆盖所有引用点，删它有踩到未预期引用的风险（对照 R30-R32 那类"资源断链"事故的教训：**能不动资源字典就不动**）。列为**后续清理候选**（见 §七-3）。
