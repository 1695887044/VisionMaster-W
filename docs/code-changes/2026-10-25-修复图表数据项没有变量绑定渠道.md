# 修复：柱状图 / 饼图的「数据项」没有变量绑定渠道

日期：2026-10-25　状态：已修；`ScadaChecks` **3056 通过 / 0 失败**

## 用户反馈

> 饼图和柱图没有绑定变量的渠道，只靠文本约束，太粗糙了。

## 根因（两层，缺一不可）

1. **属性面板给的是裸文本框**：两个图元的「数据项」属性 Kind 写的是 `MultilineText`。
   属性视图按 Kind 选 `ContentTemplate`（`ScadaPropertyView.xaml` 的 DataTrigger），
   `MultilineText` 落进默认模板 = 一个多行输入框。虽然我已经写了 `ScadaChartSeriesRow`（摘要 + 按钮）
   和 `ScadaChartSeriesEditor`，**行对象建出来了、却没有对应模板 → 界面上仍然只有一个文本框**。
2. **编辑器里变量也只能手打**：`ScadaChartSeriesEditor` 的变量列是纯 `TextBox`，
   没有接 `IScadaVariablePicker`——与事件编辑器"选变量…"弹窗不是同一条渠道。

## 改了什么

1. 新增 `ElementPropertyKind.ChartSeries`（与 `ReportColumnList` 分开：那个绑账本列名，这个绑工程变量）。
2. `ChartElements.cs`：柱/饼的「数据项」Kind 改为 `ChartSeries`。
3. `ScadaPropertyView.xaml`：新增 `EditChartSeries` 模板（摘要 + 「配置数据项…」按钮），
   并加 `DataTrigger Kind=ChartSeries` 的映射。
4. `ScadaChartSeriesEditor`：每行变量列改成「输入框 + 「…」按钮」，
   按钮走 `IScadaVariablePicker.Pick(...)`（注入自 `ScadaPropertyViewModel._picker`），
   选中后写回变量名。图表项只存名字（与报表列同口径），所以丢弃选择器给的 Id 是有意的。
5. 断言 `[CH10]`：柱/饼的「数据项」Kind 必须是 `ChartSeries`——
   把"面板给按钮 + 选择器"这件事钉住，谁改回 `MultilineText` 就红。

## 验证

- `VisionMaster` / `VM.Scada.Controls` 编译 0 错误（除运行中 exe 的文件锁）。
- `ScadaChecks` **3056 / 0**（`artifacts\logs\20261025\checks-chartpicker.log`），`[CH10]` 显示 `bar=ChartSeries / pie=ChartSeries`。

## 教训

**"行了对象"不等于"界面能看到入口"**：属性面板的模板是按 `Kind` 的 DataTrigger 选的，
新行类若没有自己的 Kind 与模板，就会被默认模板吞掉——症状恰好是"看起来什么都没实现"。
新属性行必须同时交付三件：Kind 枚举值、视图模板、VM 的 switch 分支。
