# DataPort 端口链接订阅退订与转换口径统一（2026-10-17）

> 范围：`Shard\Core.Interfaces\DataPort\` 目录的"链接（Link/Connection）变量的作用域、生命周期、并发安全性、资源释放"专项分析与修复。
> 复核：两轮独立 reviewer 复核；第二轮落地实现核验总评 PASS。

---

## 1. 起因与背景

本轮对 `Shard\Core.Interfaces\DataPort\` 做了一轮**链接（Link/Connection）变量的作用域、生命周期、并发安全性、资源释放**专项分析，发现的核心问题是：

**输入端口对上游 `ValueChanged` 事件的订阅永不退订。**

- `InputPort<T>` 没有 `Dispose`，链接建立后订阅路径是 `LinkedSource setter → LinkedSource.ValueChanged += UpstreamValueChanged`。
- `VisionPluginBase.Dispose()` 只释放输出端口的值，**不退订**输入端口的链接。
- 只要上游 `OutputPort` 被**长生命周期根**（典型：跨 session 的 `RuntimeVariableProxyPort`，挂在 `CompiledNode.ContextAwareBindings` 上）持有，事件委托就**反向钉住**下游插件实例。
- 而 `FlowCompiler` 每轮编译都 `Activator.CreateInstance` 一整套新实例（`FlowCompiler.cs:748`），旧实例被钉住即构成**逐轮累积的托管泄漏**。

另外顺带治理两类相关缺陷：
- **`LinkedSource` setter 的半链接态**：订阅已建立但缓存刷新失败时，异常穿透回 `FlowCompiler.cs:1066`，订阅泄漏。
- **`OutputPort.Value` setter 的 JToken 行为分歧**：内联转换不认 JSON 反序列化的 `JToken`（`JToken` 不实现 `IConvertible`），会抛 `InvalidCastException`。

## 2. 改动清单（逐项：文件:行号 + 动机）

### 2.1 `InputPort<T>` 实现 `IDisposable`（治"永不退订"）

- 文件：`Shard\Core.Interfaces\DataPort\InputPort.cs`
- 改动：
  - 类声明追加 `IDisposable`。
  - 新增幂等 `Dispose()`：`_disposed` 闸门 + `LinkedSource = null` **复用 setter 的退订路径**（不写第二条退订路径，防止两处口径漂移）。
  - 配套：`Shard\Core.Interfaces\VisionPluginBase.cs` 的 `Dispose()` 末尾遍历 `_inputs.Values`，对 `IDisposable` 调 `Dispose()`（try-catch 包裹，单个端口失败不影响其余端口）。
- 时序安全性：`EnsurePortsDiscovered()` 幂等，且一次反射同时填 `_inputs` / `_outputs`，不存在"只填了一半"的中间态。

### 2.2 `LinkedSource` setter 失败回滚（治"半链接态"）

- 文件：`Shard\Core.Interfaces\DataPort\InputPort.cs`
- 改动：`RefreshLinkedCache()` 包 try-catch，失败时**回滚**——
  - `-= UpstreamValueChanged`（摘掉刚建立的订阅）；
  - `_linkedSource = null`；
  - `_cachedLinkedValue = default(T)`；
  - 补两条 `OnPropertyChanged`（`LinkedSource` / `Value`，让界面看到已回退到未链接态）；
  - 然后 `throw`。
- 动机：不修的话，"`RefreshLinkedCache` 抛异常 → 订阅已加上、缓存没刷新" 的半链接态会让异常穿透回 `FlowCompiler.cs:1066`，订阅泄漏且界面显示错值。

### 2.3 `OutputPort.Value` setter 走 `ValueConverter.Convert`（治 JToken 分歧）

- 文件：`Shard\Core.Interfaces\DataPort\OutputPort.cs`
- 改动：删掉 `Value` setter 内联的 null / 枚举 / `Convert.ChangeType` 那一串，改走 `ValueConverter.Convert`。
- 动机**不是**"代码重复"，是 **JToken 行为分歧**：
  - `ValueConverter.cs:25-51` 会**拆** JSON 反序列化的 `JToken`（`JValue` →  underlying value）；
  - 原内联不认 `JToken`（`JToken` 不实现 `IConvertible`），`Convert.ChangeType` 会抛 `InvalidCastException`。
- 等价性确认：非 JToken 路径（string→枚举 `Enum.Parse`、数值→枚举 `Enum.ToObject`、标量 `Convert.ChangeType`、可空拆箱）与原内联实现**等价**，无回归。

### 2.4 删死代码

- 删除 `Shard\Core.Interfaces\DataPort\Port.cs`——`Port<T>` 全仓 0 实例化、0 继承，与 `InputPort` / `OutputPort` 是**平行继承链**（不是基类）。
- 删除 `Shard\Core.Interfaces\DataPort\PortData.cs`——整份 ~180 行**注释掉的旧实现**。
- csproj 是 SDK 风格 glob 包含，**无需改**。

### 2.5 `CompiledParallelNode` 补并发不变量注释

- 文件：`Core\Models\Compileds\CompiledParallelNode.cs:146` 区域
- 改动：补"**并发不变量·端口层**"注释——并行期间上游端口只读：
  - 上游在父序列先写完；
  - `RuntimeVariableProxyPort` 每节点一个实例；
  - 变量写走各分支影子字典 `ParallelBranchExecutionContext.LocalVariables` / `BranchVariableRegistry`。
- 动机：这是**端口层不加锁的前提**，必须把这条不变量写在它该在的地方，免得日后有人给并行分支加写入路径时忘了端口层假设。

## 4. 遗留技术债（记录但不修）

- **本工程存在两份同名 `ObservableObject`**：
  - `Core.Interfaces.ObservableObject`；
  - `Core.Interfaces.Core.ObservableObject`（后者多了数组逐元素比较 / 枚举 / 字符串特判）。
- **现状**：端口类用的是**功能更全的 Core 版**（行为正确）；`VisionPluginBase` 用的是较弱版但恰好只用**引用比较**语义（**无 bug**）。
- 建议择期合并，本轮不动。

## 5. 影响面与后续动作

- **运行时行为变化**：`FlowSession` 销毁 / 配置壳关闭时，下游插件实例的链接订阅会**主动退订**；这意味着一旦被长生命周期根持有的上游端口，不再钉住下游实例。**没有**"Dispose 后复用"的调用路径，所以不会出现"链接断开后还指望它推送"的静默故障。
- **编译期行为变化**：`OutputPort.Value = jtoken` 从抛 `InvalidCastException` 变为正确拆 `JValue`——这是一处**行为修正**，不是行为保持。
- **不影响**：XAML 层、源生成器、SCADA、通信、插件手册打包路径均未触及。

## 6. 附：ObservableObject 双份合并（2026-10-17 补）

**背景**：本工程曾有两份同名 `ObservableObject`——`Core\ObservableObject.cs`（namespace `Core.Interfaces.Core`，功能全：`SetProperty` 走 `ValuesAreEqual`，数组逐元素比 / 枚举 `Enum.Equals` / 字符串 Ordinal）与根目录 `ObservableObject.cs`（namespace `Core.Interfaces`，弱版：仅 `EqualityComparer<T>.Default.Equals`）。这是上一轮 DataPort 审查遗留的技术债（见 §4），本轮合并。

**合并方式（统一到功能全的 Core 版）**：

1. `Core\ObservableObject.cs` 的 namespace 从 `Core.Interfaces.Core` 改为 `Core.Interfaces`，功能全版成为唯一版。
2. 删除根目录弱版 `ObservableObject.cs`。
3. `DataPort\InputPort.cs` / `OutputPort.cs` 删 `using Core.Interfaces.Core;`（namespace 本就是 `Core.Interfaces`，合并后直接解析）。
4. 8 个插件 Models（CalibPointRow / CaliperRegion / RoiItem / ScriptVarDef×2(CSharpScript+ImageScript) / RecordColumnDef / DisplayItemDef / UploadFieldDef）把 `using Core.Interfaces.Core;` 改为 `using Core.Interfaces;`（它们原先只靠 .Core using 拿 ObservableObject）。
5. 未动：`VisionPluginBase.cs`、`PreprocessOperator.cs`（原落根版，合并后自动落到功能全版）；`tools\VirtualCameraClient\ObservableObject.cs`（独立工程第三份，无关）。

**行为切换前提与核验**（reviewer 复核确认无回归）：`VisionPluginBase` 唯一 `SetProperty` 站点是 `IStepConfigData`（接口类型），`PreprocessOperator` 及其 30 个算子的 `SetParam` 参数全是数值/枚举、无数组字段进 `SetProperty`；`CaliperRegion`/`RoiItem` 的 `double[] Params` setter 直写字段 + 显式通知、不经 `SetProperty`。故"引用比→内容比"的切换对这两支语义等价或更优。已知语义差：数组类型输出端口写"内容相同的新数组"会被判相等不再触发 `ValueChanged`——但端口类合并前就在功能全版下运行，行为无变化，全仓 5 处数组端口实例无依赖此旧行为的用法。

**验证**：`Core.Interfaces` 与全仓 `VisionMaster.sln` 的 Debug + Release 均 0 编译错误；全仓扫 `Core.Interfaces.Core` 零代码残留（仅注释自述）。

**遗留待办（记录不修）**：① `UI\Controls\Core\ObservableObject.cs`（namespace `UI.Core`）是第三份独立副本，与本次无关，可择期评估归并；② `Shard\Core.Interfaces\Core\` 子目录现在名不符实（里面唯一类型的 namespace 已不再是 `.Core`），下次整理可挪到根目录。
