# 2026-09-25 卡尺测量插件 第一批（Plugin.CaliperMeasure）

## 1. 需求与决策

### 1.1 需求来源

这是「补齐视觉核心工具链」的又一步：仓库已有图像采集、预处理、ROI、脚本、Blob 缺陷检测、OCR、读码等能力，
但**缺少最基础也最常用的尺寸测量能力**。用户选定「测量」方向，规格在开工前已逐条确认完毕，
本次任务只负责按规格实现**第一批**，不改变设计。

### 1.2 已确认的设计决策（照录规格，不得更改）

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | **交付范围** | 完整形态要支持 5 种测量（宽度/间隙、两点距、点线距、圆直径、角度），**分两批**；本批只做前两种（均不涉及拟合） |
| 2 | **工程/命名** | 工程名 `Plugin.CaliperMeasure`，插件名 `卡尺测量`，分组 `测量` |
| 3 | **卡尺建模** | **阵列式**：用户不逐个摆卡尺，而是给一个"搜索区"形状 + 卡尺数 N，插件内部自动均布 N 个卡尺 |
| 4 | **输出端口 6 个** | `MeasureValue`(double) / `Deviation`(double) / `IsOk`(bool) / `MeasureImage`(HImage) / `FittedGeometry`(HXLD) / `EdgePoints`(HXLD) |
| 5 | **判定规格** | 标准值 + 上公差 + 下公差（上下分开填，支持非对称公差，如 +0.05/-0.02） |
| 6 | **像素当量** | 插件内自带参数（mm/pixel，默认 1.0），输出物理值；项目目前没有标定模块，将来有了可改成连线取值 |
| 7 | **一个步骤测一个尺寸** | 要测多个尺寸就放多个步骤 |

**为什么分两批**：后三种（点线距/圆直径/角度）都要先做**几何拟合**（`fit_line_contour_xld` / `fit_circle_contour_xld` /
角度计算），与"直接找边取距离"是两类算法；且拟合还引入一组拟合参数（迭代数、ClippingFactor 等），
界面上要新增"拟合参数"分区。一次性交付会把风险摊薄、验证量翻倍。因此第一批先把"阵列卡尺 + 找边 + 判定 + 标注"
这条主干打通并实测，第二批在同一骨架上加拟合分支即可（枚举加成员、界面下拉自动多两项，XAML 结构不动）。

### 1.3 参数分区（5 区）

① 测量类型　② 搜索区与卡尺（画布矩形 + 卡尺数 N）　③ 找边参数（Sigma / 边缘阈值 / 极性 / 选择 / 插值）
④ 拟合参数（**本批不涉及拟合，界面不显示；不写用不到的空壳参数**）　⑤ 判定与标定（标准值 / 上公差 / 下公差 / 像素当量）

### 1.4 默认值（通用起点，逐条注明依据；**绝不针对任何样图调**）

| 参数 | 默认 | 依据 |
| --- | --- | --- |
| 卡尺数 N | 5 | 工业常用起步值，兼顾抗噪（多点平均）与速度 |
| Sigma | 1.0 | HALCON 测量例程常用的轻度平滑 |
| 边缘阈值 | 30 | HALCON 测量例程（含仓库脚本模板库）的常用对比度门限 |
| 极性 | 全部 | 不预设明暗方向，最宽容的起点 |
| 选择 | 全部 | 不预设取哪条边 |
| 插值 | bilinear | 亚像素精度与速度的通用折中 |
| 像素当量 | 1.0 | 等于直接输出像素值，不假设任何标定 |
| 标准值/上公差/下公差 | 0 / 0 / 0 | **有意的零容忍**：通用平台算子不该假装知道产品规格；用户看到默认即 NG 会立刻去填规格。与 BlobDetect 的 `MaxDefectCount=0` 同一风格（安全侧默认，宁严勿松） |

### 1.5 本次实现中查证/发现的关键事实（决定了算法怎么写）

1. **扫描方向 = L1(Phi) 轴**（用真实 HALCON 实证，见 3.4 探针）：`gen_measure_rectangle2` 沿矩形**主轴 L1** 扫描，
   检出的边缘**垂直于** L1 轴；`Phi=0` 时 L1 轴为水平方向。
   - 由此推出：**N 把卡尺必须沿"垂直于 Phi"的方向（L2 轴）均布**，每把保留完整 L1 扫描长度。
   - 插件目录里 `Models\CaliperRegion.cs` 原有的几何注释把扫描/均布方向**写反了**，本次已修正并在注释里记录实证过程。
2. **画布形状参数与测量算子参数顺序一致**（规格点名的基石）：`DrawShapeType.Rectangle` 的参数是
   `(中心行 R, 中心列 C, 角度 Phi, 半长 L1, 半宽 L2)`，与 `gen_measure_rectangle2` 完全一致，
   **无需换算层**，搜索区参数可直接喂给算子。
3. **HALCON .NET 是引用计数语义**（用真实 HALCON 实证）：
   - `new HImage(obj)` / `new HXLDCont(obj)` 是**独立句柄**（源对象释放后包装对象仍可用，非所有权转移）；
   - 但**只释放源对象、不释放包装对象会泄漏**：500 次不释放包装泄漏约 160MB。
   - 推论：交给端口的包装对象由基类回收，中间"源对象"必须进 `temp` 释放——两者都要释放，缺一不可。
   - 顺带发现：`dump_window_image` 回读出的 `shot` 也是源对象，包装后必须显式释放（本插件已做；BlobDetect 未做，属其既有问题，本次未改它）。
4. **Sigma 有下限**：`measure_pairs` 传 `Sigma=0` 会抛 `#1302 Wrong value of control parameter`。
   本插件把 Sigma 夹取下限设为 0.4（HALCON 要求），界面校验也改为 `≥0.4`。
5. **搜索区中心在图外时**，算子抛 `#3022 Wrong size of filter for Gauss`——英文错误对操作员无指导意义，
   本插件改为**提前用中文报错**（见 1.6）。

### 1.6 规格之外的实现决策（诚实标注：这些是我做的工程判断，非规格明文）

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| **均布规则** | 把搜索区整段 L2 宽度等分成 N 份，每把卡尺半宽 = L2/N（正好铺满、不重叠） | "均布 N 个卡尺填满搜索区"的自然解释；每把取独立的一段做灰度平均，互不干扰 |
| **必须全部检出** | 只要有 1 把卡尺找不到边，就判**失败**（而非跳过取平均） | 把检到的几把平均出一个"看似合理"的数是计量最危险的失败模式（错误但不出错）；宁可报错让用户调参数 |
| **宽度取值口径** | 每把卡尺取**第一条配对**的 `IntraDistance`，再对 N 把取平均 | 多条成对边缘时取扫描方向第一条；跨卡尺平均是抗噪主手段 |
| **两点距取值口径** | 每个搜索区：每把卡尺 `measure_pos` 取**第一条边点**，N 把的点取**平均**成该区"一个代表点"，再 `distance_pp` | 规格要求"各出一个边点"；平均是"多点抗噪"下的稳健代表点。`Select=最后一条` 时 `measure_pos` 本就只返回最后一条 |
| **越界提前报错** | 搜索区中心超出图像范围 → 中文 Fail（指出哪个区、中心坐标、图尺寸） | 替代算子那条 #3022 英文错误 |
| **默认搜索区播种** | 首次打开视图/换图时，若搜索区不足则按类型补默认区（宽度=1、两点距=2），把图按所需数量切成等宽竖条，每区取本条中间、覆盖 35%×25%，Phi=0 | 给一个"能立刻拖动"的通用起手姿态，不针对任何样图；只增不减，绝不删用户已摆好的区域 |
| **标注底图** | 用**原图**（彩色输入保留彩色） | 与 BlobDetect 同口径，标注图是给人看的 |

**关键片段（a）画布形状 → 测量算子 参数直通 + 阵列均布**：

```csharp
/// 扫描方向 = L1(Phi) 轴（已实证）；所以 N 把卡尺沿"垂直于 Phi"的 L2 轴均布，每把保留完整 L1 扫描长度
private static List<double[]> DistributeCalipers(double[] rect, int n)
{
    double r = rect[0], c = rect[1], phi = rect[2], l1 = rect[3], l2 = rect[4];
    if (n <= 1) return new List<double[]> { new[] { r, c, phi, l1, l2 } };

    double spacing = 2.0 * l2 / n;                       // 整段 L2 宽度等分 N 份
    double halfWidth = Math.Max(spacing / 2.0, MinCaliperHalfWidth);
    double cosPhi = Math.Cos(phi), sinPhi = Math.Sin(phi);
    var list = new List<double[]>(n);
    for (int i = 0; i < n; i++)
    {
        double t = -l2 + spacing * (i + 0.5);            // 沿 L2 轴的偏移量
        list.Add(new[] { r + t * cosPhi, c - t * sinPhi, phi, l1, halfWidth });  // L2 轴单位向量=(cosPhi,-sinPhi)
    }
    return list;
}

// 搜索区参数顺序与 gen_measure_rectangle2 完全一致，直接喂进去（无需换算层）
HOperatorSet.GenMeasureRectangle2(c[0], c[1], c[2], c[3], c[4], imgW, imgH, p.Interpolation, out HTuple handle);
measureHandles.Add(handle);
```

## 4. 已知边界

1. **本批只支持 宽度/间隙 与 两点距**：点线距、圆直径、角度三种**未实现**（枚举里也没有成员，避免死选项）。
   第二批补齐拟合算法后加入枚举即可。
2. **像素当量是手填常量**：默认 1.0，无标定模块联动（项目暂无标定模块）。当量=1.0 时数值上等于像素值，
   但界面与标注仍按参数语义显示单位 `mm`——**未标定时把"像素数"当 mm 看是使用者的责任**，建议在方案里把当量填成实测值。
3. **未做斜边/曲面补偿**：卡尺是直线扫描，被测边若明显倾斜、曲面或存在锥度，测量的是"扫描线方向的投影距离"，
   需要用户把搜索区摆正或改用拟合类算法（第二批）。
4. **标注图渲染依赖离屏窗口**：`open_window('buffer')` 在无显示环境（纯服务/无桌面会话）下理论上有失败可能；
   一旦失败只丢 `MeasureImage`（记一条 Warn），测量结果（值/偏差/判定/几何 XLD）不受影响。
5. **"必须全部卡尺检出"是刻意从严**：任一把卡尺找不到边即判失败（不用"部分平均"）。副作用是搜索区里
   只要有一小段落在无特征区就会失败——这是计量安全的取舍，现场需把搜索区摆到都有边的地方。
6. **均布规则固定为"等分铺满 L2、每把半宽=L2/N"**：规格只说了"均布 N 个卡尺"，具体铺法由本插件定。
   若以后想改成"等间距中心 + 固定半宽（允许重叠）"，只需改 `DistributeCalipers` 一处。
7. **两点距的"一个代表点"取 N 把卡尺边点的平均**：`Select=全部` 时每把取第一条边。若被测边本身弯曲，
   平均点会落在中点附近，与"取某一把的点"口径不同——已在 1.6 记录。
8. **`FittedGeometry` 本批承载的是"测量连线"**（宽度=各卡尺两边缘连线、两点距=两点连线），不是拟合几何；
   第二批的点线距/圆直径/角度会在这里放拟合出的直线/圆/角度几何（端口名与类型不变）。
9. **未纳入自动冒烟**：`FlowCanvasChecks` 不覆盖本插件（冒烟输出里 `Caliper/卡尺` 零匹配）。
   本次算法验证靠"仓库外临时控制台真跑 + 目视标注图"完成，该控制台已删除、不可复现；
   后续若要长期守护，建议把「40px 亮带测出 40.0 / 220px 两点距测出 220.0」固化成正式断言。
10. **`dump_window_image` 源对象必须显式释放**：这是本次实测发现的 HALCON .NET 引用计数陷阱
    （不释放会每轮泄漏）。本插件已规避；同仓库 `Plugin.BlobDetect` 存在同样写法（未释放 `shot`），
    按"不改动其他插件"的约束本次未动它，**建议后续单独排查**。

## 5. 学到的知识点（本次）

1. **HALCON 测量的几何语义必须实证**：`gen_measure_rectangle2` 沿 **L1(Phi) 轴扫描**，边缘垂直于 L1 轴；
   均布阵列要沿**垂直方向（L2 轴）**排。不要凭"半长/半宽"的字面猜，用一张合成图 3 分钟就能定死。
2. **HALCON .NET 是引用计数，包装 ≠ 转移所有权**：`new HImage(obj)`/`new HXLDCont(obj)` 生成独立句柄，
   源对象与包装对象**都要释放**；只释放一边会漏（实测 500 次漏 160MB）。这条同样适用于 `dump_window_image` 的产出。
3. **`disp_text` 的白底框要 `'box','true'`**：只给 `'box_color'` 不会画框——`box` 是独立开关。
4. **`intensity` 算的是均值+偏差，不是 min/max**：取极值要用 `min_max_gray`（本次诊断时踩过，一度误判标注没画上）。
5. **算子有参数下限**：`measure_*` 的 `Sigma` 不能为 0（抛 #1302），夹取下限设 0.4；这类"算子级约束"必须在
   归一化里体现，否则非法配置会炸流程。
6. **越界要靠自己提前报中文错**：算子对"搜索区在图外"抛的是 #3022 英文错误，对操作员没有指导意义；
   提前用"哪个区、中心在哪、图多大"说清楚，才算满足"非法值不能炸 + 中文说明"。
7. **计量工具宁可报错也不要用"部分平均"**：检到 3/5 把卡尺就平均出一个数是"错误但不出错"的最危险失败模式。
