## 四、关键技术决策（为什么）

### 1. 为什么必须有草稿类（`VariableDraft.cs`）

`FlatPropertyGrid` 是**就地编辑**：TextBox / ComboBox 双向写回传进去的实例，点"取消"**不会回滚**；而且它**只渲染带 `[SuperDisplay]` 的属性**（`PropertyGridDefaults.GetVisibleProperties` 的契约边界）。所以录入必须走"草稿 + 确认才落地、取消 = 整份丢弃"的事务范式——范式照 `VisionMaster\Models\ParallelGroupEditModel.cs`（并行分组参数）与 `VisionMaster\ViewModels\DialogViewModels\MotionCardIdentityEdit.cs`（运动卡身份）。

草稿的**候选列表由调用方（VM）构造时注入**：`TypeOptions` / `ConnectionOptions` / `ScanGroupOptions` / `AreaOptions` 都是运行期数据（组名跟着连接走、存储区跟着协议走），草稿自己够不到通信管理器，也不该够到。

### 2. 为什么要新增 `ComboSourceGenerator`（而不是复用既有生成器）

原有生成器里**没有**"候选来自草稿自己的某个属性"的通用能力：

- `EnumGenerator` 只认**编译期枚举**；
- `OptionSourceGenerator` 只认 `StepConfigOptionKind`（仅运动卡名 / 轴名两种**静态 kind**），表达不了"候选挂在当前这个对象上、随这个对象的其它字段而变"。

而「所属连接 / 扫描组 / 存储区」三个下拉**都是运行期候选**（组名跟着连接走、存储区跟着协议走），静态 kind 表达不了。所以新增 `ComboSourceAttribute`（标在 string 属性上，`SourceProperty` 指向同一个绑定对象上的候选属性）+ `ComboSourceGenerator`。

**`Priority = 105` 必须高于 `StructValueGenerator` 的 100**——后者用文本框渲染一切 string，抢在它前面才有下拉可言（低于 `NumericGenerator` 的 110 无妨：本特性只对 string 有意义，数值属性不会同时命中两者）。

### 3. 候选列表属性刻意不贴 `[SuperDisplay]`

`TypeOptions` / `ConnectionOptions` / `ScanGroupOptions` / `AreaOptions` **只当 `ComboSourceAttribute` 的候选来源**，贴了会自己占一行只读文本——属性网格只渲染带 `[SuperDisplay]` 的属性，这个"不贴"是有意的。

### 4. 弹窗里不再有"本地 / 网络"选择

种类由左栏选中项决定（`SelectedSource?.IsNetwork`，VM :731）：选中「本地变量」→ `LocalVariableDraft`；选中某条连接 → `NetworkVariableDraft`（「所属连接」默认就是它）。原中栏顶部的分段胶囊（`DialogSegmentHost` + 两个 `RadioButton`）随中栏一起撤掉，`IsLocalSource` 反值属性也一并删除。

## 六、本轮抓到并修掉的两个问题

### 1. 「管理扫描组」入口一度成为孤儿（换皮顺手弄丢功能入口）

**问题**：`ManageScanGroupsCommand` 的按钮原本在中栏「扫描组」下拉旁；中栏删除后**视图里再无任何绑定** → 用户在「添加变量」弹窗里发现只有默认组时，**没有任何直达组表编辑器的路**（要退出去开通讯设置）。命令本身是活的（VM 侧一行没动），坏的是"界面入口"，构建 / 断言 / 出图全绿。

**修法**：在右栏卡片头补一颗图标按钮（`:272-284`），`Visibility` 绑 `IsNetworkSource`（本地来源下收起），作用对象 = 左栏选中的连接（VM 侧 `SelectedConnection`），与选中项天然一致。

**同类事故互指**：2026-10-14 流程栏换皮时，「失败自动跳转」开关随搜索行删除后一度无 UI 可关（`docs\code-changes\2026-10-14-流程栏换皮（ProcessView 对齐设计稿）.md` §四）——**同一类事故：换皮/删栏顺手弄丢功能入口**。两次的处置也一样：补一个常驻入口 + 加一条静态钉（那次是 `ProcessTreeTemplateChecks` 的 U6，这次见 §七 的「添加变量入口在位」）。

### 2. reviewer 判 FAIL 的一条断言（"改坏了也不红"的静默放行口，已修）

**问题**：新增的「初始值（基准）入口没丢」断言最初写成**整文件两个 `Contains`**：

```csharp
draftText.Contains("InitialValue") && draftText.Contains("[SuperDisplay")
```

两个关键词**各自被别的属性满足**（`VariableName` / `Description` 等也带 `[SuperDisplay]`），**把 `[SuperDisplay]` 从 `InitialValue` 上摘掉它照样绿**——典型的"改坏了也不红"（R38 那类静默放行口）。

**修法**：改成**按属性粒度反射**——问 `PropertyGridDefaults.GetVisibleProperties(draft)` 的返回里有没有 `InitialValue`（范式照 `FlowCanvasChecks\ParallelGroupConfigChecks.cs:230-248` 的 W5）。`GetVisibleProperties` 只认 `[SuperDisplay]` 且 `Visible == true`，所以"`InitialValue` 在可见集里" = "弹窗里真有这一行"。同时顺带加了一条"网络草稿的设备侧字段全部可见"的同类断言（`:443-460`）。

**反向验证已做**：把 `[SuperDisplay]` 从 `InitialValue` 上临时摘掉 → 断言**准确变红**（可见行从 4 个掉到 3 个，`InitialValue` 消失），还原后复绿。
