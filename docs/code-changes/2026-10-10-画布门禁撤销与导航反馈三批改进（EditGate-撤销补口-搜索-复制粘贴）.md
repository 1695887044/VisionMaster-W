| 批次 | 主题 | 条目 |
| --- | --- | --- |
| 第一批 | 正确性收口 | ① 画布编辑门禁 EditGate（三视角一致第一优先）② 撤销补口 ③ 端口点随数据线熄灭 ④ 删死代码 |

## 二、第一批：正确性收口

### 2.1 画布编辑门禁 EditGate（三视角一致第一优先）

- 新建 `VisionMaster\Services\EditGate.cs`：订阅既有 `GlobalEventBus<MainRunState>`，对外暴露 `IsRunLocked` / `IsEditable(ModuleEditAction)`。
- **豁免表从 `ProcessViewModel.IsRunLockExempt` 逐字搬迁**，`ProcessViewModel` 删私有副本改为调它——运行锁判据从此单一出口。
- 豁免表口径（与流程栏既有判据逐字一致）：

  | 编辑动作 | 运行中 | 已暂停 |
  | --- | --- | --- |
  | ToggleBreakpoint（断点） | 放行 | 放行（三态全放行） |
  | ModuleParameters（模块参数） | **拦** | 放行 |
  | 其余（StructuralEdit 等） | **拦** | **拦** |

- 画布六个编辑路径接门禁：`DropToolAt`（拖入）/ `OnDeleteSelection`（删除）/ 禁用 / 解绑 / 改序 `OnItemsDragCompleted` / `OpenModuleParameters`；**不拦**断点 / 折叠 / 缩放 / 显隐开关。
- 运行中画布顶部显示常驻横幅：「流程运行中：编辑已锁定（断点与暂停中的参数除外）」。
- 背景链：2026-10-10《画布编辑化》记录 §九-3 曾如实登记"画布侧编辑入口不查运行态、口径不对称"——本条即该未决项的收口（统一属跨角色口径决策，本轮由三视角评审定案后落地）。

### 2.2 撤销补口：引用型 Add/Delete 命令

- `CanvasUndoCommands.cs` 新增**引用型**命令：
  - `AddStepCommand`（owner + step + 下标）；
  - `DeleteStepCommand`（条目列表，**容器子树整批一个撤销单元**）。
- 与既有"下标型"命令（Reorder / MoveBranch）的差别：引用型按引用增删，owner 被外部动过时按 `Contains`/`IndexOf` **静默降级**（不抛、不误插）。
- 接线：
  - `DropToolAt` 插入后 `PushUndo`（撤掉 2026-10-10《画布编辑化》"拖入不撤销"的口径，见该记录 §八-6——两边口径自此对齐）；
  - `OnDeleteSelection` **删掉 `ClearUndoStacks()`** 改压删除命令；外部非命令路径的结构变化照旧清栈（`_internalWriteback` 闸门未动）；
  - 工具条加撤销/重做按钮（命令早已存在，纯补 UI）。

### 2.3 端口点随数据线熄灭

- `FlowConnectorStyle`（`Views\FlowCanvasView.xaml`）的 `IsConnected` 常显改 **MultiDataTrigger 联合 `ShowDataLinks`**——数据线隐藏时，已连线端口回退"悬停浮现"态。
- 缘由：上一批把数据线默认隐藏后，"满屏亮蓝点却没有线"语义自相矛盾（2026-10-10《画布编辑化》§九-4 未决项的兑现；修法落在样式层而非该记录预估的 VM 层 `BuildLinks` 赋值点）。

## 四、第三批：大件

### 4.1 复制/粘贴（单个节点：叶子或容器）

- 新建 `VisionMaster\Services\FlowClipboard.cs`（照 `ScadaClipboard` 先例）。
- **序列化**：settings 复用 **`SolutionService.SerializationSettings`**（`Core\SolutionService.cs` 新增只读出口），与 .vms 落盘同一条管线——含 `TypeNameHandling.Auto` + 白名单 Binder。
  - **坑（钉死）**：`SerializeObject(object)` 按运行时类型作根契约、**根上不写 `$type`**，反序列化拿抽象 `StepModel` 无法实例化——必须 `SerializeObject(source, typeof(StepModel), settings)`。
- **重映射口径**（粘贴件与原件互不串线）：
  1. 子树全节点重生成 StepID（旧→新映射表）；
  2. `LinkedSources` 仅 `Kind==StepPort` 做"内部改写（TargetStepId 重映射 + DisplayAddress 重算）/ 外部整条删除"——全局变量/常量与运行时变量绑定**不参与内外判定**，防误删；
  3. `ConditionStep.LocalVariables` / `RuntimeVariableRefs` 的变量 Guid 子树内换新；
  4. 根节点 `StepFactory.NextStepName` 重命名（**内层保持原名**——一期口径）；
  5. 运行期字段复位（State / 耗时 / 断点 / DebugStopped）。
- **粘贴链**：`Take` → `ResolveInsertTarget`（与拖入**共用同一落点规则**，从 `DropToolAt` 抽出）→ `PushUndo(new AddStepCommand)` → `Version++` + `RebuildInPlace` + 状态栏回执。
- **入口**：节点右键「复制」、画布空白右键「粘贴」（Editor 级菜单，命中节点/连线时由模板菜单接管）、Ctrl+C/V InputBindings。
- 运行锁拦（2.1 门禁现成）；**多选复制给提示不进剪贴板**（二期）。

### 4.2 性能量化（只量化不优化）

- 渲染探针新增 300/600 节点压力场景：12 条并行分支 × 5/10 层嵌套 If + 顶层算子，**全展开态**。
- 实测（3 次取中位数，**Debug 口径**）：

  | N | RebuildInPlace | 全帧（WPF 可视树生成） |
  | --- | --- | --- |
  | 300 | 343ms | 1274ms |
  | 600 | 289ms | 2857ms |

- perf 行原文（`--render` stdout）：`N=300 RebuildInPlace=343ms 全帧=1274ms；N=600 RebuildInPlace=289ms 全帧=2857ms`。
- **结论**：RebuildInPlace 成本被编译/拓扑/连线等固定项托底、节点数不是主项；**全帧随节点数线性**才是大头。
- **建议**：当前真实图纸几十节点的规模**先放着不优化**；若真机出现几百节点图纸，第一刀落在**全帧侧**（默认折叠 + 局部容器刷新，`FlowLayoutStore.LayoutChanged.AffectedSteps` 只重排命中子树）而非 RebuildInPlace 本身。

### 4.3 `StepCollection.Expression` 双语义契约注释

- XML 注释写死：「If/ElseIf/WhileLoop = 布尔表达式经 FlowCompiler 解析；Case = 匹配值文本；Else/Default = 恒真不消费」，并附**消费方名单**：FlowCompiler / 条件编辑器 / R24 胶囊文案 / B0 参考解释器（`LogicBruteforceChecks`）。
- 约束：任何新消费方必须先确认分支类型语义——防 Case 会话之后的双语义静默错。

## 六、本批钉死的口径（守门点）

1. **运行锁判据单一出口**：豁免表只在 `EditGate` 一处（`ProcessViewModel` 私有副本已删）；画布六编辑路径必接，断点/折叠/缩放/显隐四类必不拦（[G1] 守门）。
2. **删除不再清撤销栈**：`OnDeleteSelection` 压 `DeleteStepCommand`；外部非命令路径的结构变化照旧清栈（`_internalWriteback` 闸门未动）——"外部动过 = 撤不动"与"用户删的 = 撤得回"两条线分明（[G2] 守门）。
3. **端口点与数据线同开关**：`FlowConnectorStyle` 用 MultiDataTrigger 联合 `ShowDataLinks`，不许回到常显。
4. **剪贴板根契约必须是 `typeof(StepModel)`**：`SerializeObject(object)` 根上不写 `$type`，抽象类型反序列化必炸——换任何"简化写法"都是退回这个坑。
5. **重映射五条一个不少**：StepID 全重生成 / StepPort 连线内外判定（非 StepPort 不参与判定防误删）/ 变量 Guid 换新 / 根改名内层原名 / 运行期复位（[G7] 守门）。
6. **粘贴落点与拖入共用 `ResolveInsertTarget`**：不许复制粘贴另造一套落点规则。
7. **`StepCollection.Expression` 双语义契约**：新消费方必须先确认分支类型语义（消费方名单写死在 XML 注释里）。
8. **性能结论先记账不动手**：优化第一刀在全帧侧（默认折叠 + 局部容器刷新），不在 RebuildInPlace。

## 七、未决与已知限制（如实登记）

1. **真机未验**：拖入撤销手感、运行锁横幅真实观感、树右键展开/折叠、复制粘贴的真实点击与 Ctrl+C/V 路由、指针图坐标换算精度（视图侧按 `ViewportLocation + 屏幕坐标/ViewportZoom` 自算，Nodify 的 MouseEventArgs 重载未取证）——headless 合成不了 OLE 拖放与真实双击（与 2026-10-10《画布编辑化》§九-1 同族边界）。
2. **多选批量不做**：画布拖入/粘贴只做撤销之外的**单个节点**复制粘贴；多选复制给提示不进剪贴板（二期）。
3. **`DoCompileAll`（批量编译）未发布编译错误事件**：只覆盖单流程 `DoCompile`——要接需动 `ShellViewModel` 更多处，未擅自扩面。
4. **失败自动跳转无开关**（每轮只跳第一个新失败）；搜索只有「下一个」无「上一个」。
5. **perf 为 Debug 口径**：Release 复测会因 `Modules\` 投递不分配置覆盖调试产物，未做（红线③同族约束）。
6. **`SolutionService.SerializationSettings` 公开出出口属 Core 目录增量**：建议下轮架构评审确认归属。
7. **并发提示**：Case 分支会话同期活跃（`StepFactory` / `ProcessView.xaml` 等文件被其修改），本批开工前后均核对 LastWriteTime 无撞车；`StepFactory` 现含其 `BuiltIn_Case` 分派（该线见 `docs\code-changes\2026-10-10-分支匹配Case（判据+匹配值内置算子）.md` 等 Case 系列记录）。
