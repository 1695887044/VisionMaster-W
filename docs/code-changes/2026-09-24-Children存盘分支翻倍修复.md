### 复查新发现的 2 个问题

**问题 1（轻微）**：`IsIfLike` 缺 `[JsonIgnore]` → 会往 `.vm` 多写一行 `"IsIfLike": true`。与项目惯例（模型的运行时/计算属性一律 `[JsonIgnore]`）不符。

**问题 2（严重，既有缺陷，非本轮引入）**：容器步骤 `Children` **存盘往返后分支翻倍**。

实证（真实路径 `SolutionService.Serialize` + 复刻设置往返）：

```
[×失败] If 图纸存盘往返后分支不重复且条件保留    →  实际 4（If,Else,If,Else）Expr0=''
[×失败] For 图纸存盘往返后循环体不重复（应为 1）  →  实际 2
[×失败] While 图纸存盘往返后循环体不重复（应为 1） →  实际 2
```

病根链条：

```
构造函数预建 [If, Else]
        ↓ 存盘（JSON 里 2 个分支）
反序列化：new ConditionStep(...) → Children 已有 [If, Else]
        ↓ Children 是 { get; } 只读集合 → Newtonsoft 默认 ObjectCreationHandling.Auto = Populate(Add)
最终 [If(空), Else, If(1==1), Else]  ← 首分支表达式为空 → 编译报「表达式为空」
```

**后果**：任何含 If / For / While 的图纸，**存盘后重新打开就编译不过**。历史文档从未登记过。

**漏网原因**：[Program.cs](file:///e:/VM/VisionMaster-W-master/FlowCanvasChecks/Program.cs#L1301-L1303) 的 R4 往返断言只验了 `LinkedSources`，没验 `Children.Count`——存盘往返这条链上「连线对了」掩盖了「分支翻倍了」。

### 关键实证：修法必须「setter + Replace」两件套

用一个只读集合的对照探针把 Newtonsoft 的三种行为跑了一遍：

| 组合 | 结果 | 判定 |
|---|---|---|
| 只读集合 + 无标注 | `Count=2` 首元素='预建' | 追加重复 |
| 只读集合 + `Replace` | `Count=1` 首元素='预建' | **文件数据被整体丢弃（更危险）** |
| 有 setter + `Replace` | `Count=1` 首元素='文件值' | 正确 |

**结论**：只加 `Replace` 却不给 setter 不仅无效、而且更危险——新建的集合无法赋回只读属性，文件里的分支会被整段丢弃，而 `Count` 看起来还「正常」。两件必须同时具备。探针本身用完后已撤除，结论以注释 + 往返断言的形式固化。

## 四、已知边界

| # | 项 | 说明 |
|---|---|---|
| 1 | **`Children` 的 `Replace` 只加了这两个模型** | `StepCollection.Steps` 与 `VariableNode.Children` 同样是 `{ get; } = new()` 只读集合，但**均无构造函数预建内容**，Populate 往空集合里 Add 与 Replace 结果一致，当前无害。未加标注是「没必要」，不是「漏了」；若将来给它们加预建内容，必须同步补 setter + `Replace` |
| 2 | **对照探针已撤除，行为靠断言钉住** | 探针（三个 `*Probe` 类）只在定位期用，留仓库会污染生产断言。撤除后「只读 + Replace = 数据丢弃」这一条结论仅以注释形式存在——**若日后有人改回只读，断言仍会失败**（`Expr0` 那条会报错），保护力不依赖注释 |
| 3 | **`IsIfLike` 的 `[JsonIgnore]` 对存量 `.vm` 无迁移动作** | 老文件里多写的 `"IsIfLike": true` 会被 Newtonsoft 直接忽略（无对应可写属性），不会报错。无需写迁移脚本 |
| 4 | **`.vm` 里 `"Children": null` 由 setter 兜底** | setter 写成 `value ?? new()`：手工编辑导致 `Children` 为 null 时，属性退化为空集合而非 null 引用，避免流程直接打不开。但**空集合会让该容器步骤在编译期报「缺分支」**——这是期望行为（显式报错优于静默） |
| 5 | **`DefaultLoopCount` / `LocalVariables` / `RuntimeVariableRefs` 未做同口径改造** | 前两者是标量/无预建内容的集合；`LocalVariables` / `RuntimeVariableRefs` 虽为 `{ get; set; } = new()`（有 setter），默认 Auto 下 Newtonsoft 会走 Populate，但同样无构造函数预建内容 → 无害。本轮严格按「有预建内容才需要 Replace」的判据收敛范围 |
| 6 | **未做真实 `.vm` 文件的端到端存盘回归** | 断言用的是 `SolutionService._jsonSettings` 的复刻设置 + 同一 `SafeSerializationBinder`，与真实路径等价；但没有跑「真存文件 → 真读文件」的磁盘往返。差异仅在于文件 IO 层，不涉及序列化语义 |
