## 一、背景与设计基线

设计基线把变量绑定弹窗从"三列列表"改造成"目标端口 → 数据来源 → 绑定设置"的工作区：

- 三栏 280 / 300 / 自适应（右栏 ≥ 360），顶部 44px 上下文条（当前步骤 + 类型 + 输入端口 N · 已绑定 M + 进度条），底部 56px 状态条。
- 左栏输入端口搜索 / 全部·未绑定·已绑定筛选；中栏按「变量来源 / 上游算子」分组并带页签；右栏"连线预览英雄区 + 绑定方式二选一 + 候选端口列表（类型过滤 / 显示全部 / 隐藏数量提示）"。
- 枚举预设卡片（中文名 + 写入值分离）；数组 → 标量走行内索引面板；空态 / 单绑定 / 底部状态条分治。

设计稿与审查清单见 `docs\UI设计基线\variable-binding\README.md`；本记录只记 WPF 落地事实、关键决策、验证与回滚。

### 2.2 视图侧实现要点（`VariableBindingView.xaml.cs`）

- **搜索 / 筛选**：`FilterTarget`（`:218`）同时看「全部 / 未绑定 / 已绑定」与搜索词；`FilterSource`（`:240`）看页签与来源搜索；`FilterCandidate`（`:261`）看候选搜索。三处都用 `OrdinalIgnoreCase` 的包含匹配。
- **分组**：`SourceCategoryGroupDescription`（`:642-670`）按 `SourceCategory` 分组；`GetSourceCategory`（`:274-277`）在字段为空时回退 `"Step"`，避免分组头整体消失。
- **计数 / 空态**：`UpdateCounts`（`:438`）、`UpdateFooter`（`:486`）、`UpdateTargetEmptyState`（`:520`）、`UpdateSourceEmptyState`（`:547`）、`UpdateCandidateCount`（`:564`）、`UpdateCandidateEmptyState`（`:571`）分别处理左栏 / 中栏 / 右栏的计数与空态，三者互不覆盖。
- **响应式列宽**：`OnRenderSizeChanged` → `ApplyResponsiveColumns`（`:602-619`），宽度 < 1100 时左栏 264 / 中栏 280，否则 280 / 300；右栏仍由 `MinWidth=360` 守住。`ClampToWorkArea`（`:625-636`）在打开时把 1180×760 收敛到当前工作区，避免 150% 缩放的小逻辑桌面放不下。
- **数组类型**：`BindingTypeText.IsArray`（`:678-688`）先 `TypeHelper.ResolveType(typeName)?.IsArray`，解析不出再退回字符串包含 `"[]"`；原因是 `DataTypeName` 是 AssemblyQualifiedName（如 `System.Double[], System.Private.CoreLib, Version=...`），`EndsWith("[]")` 永远不成立。
- **英雄区文案**：`BindingHeroNameConverter` / `BindingHeroHintConverter` / `BindingHeroMetaConverter` 等按「已绑定 / 常量 / 功能预设 / 未绑定」切换主文案、提示与元信息；不改变 VM 的绑定语义。

## 三、关键决策

### 3.1 ConditionStep 的绑定键口径：按 `LocalVariables` 铺端口，`Description` 承载变量 Guid

改造前 `ConditionStep` 会落到 `pluginProvider.ModulePlugins` 的 `BuiltIn_If` 插件端口（虚拟变量 / 中间变量），而 `ResolveBindKey` 写的是端口 `Description`（变量 Guid）。结果是"值写进去了、重开不回显、解绑也清不掉"，界面上看不出异常。

现在 `BuildTree` 对 `ConditionStep` 与 `WaitStep` 统一调用 `AddLocalVariablePorts`（`VariableBindingViewModel.cs:797-808`、`:904-931`）：

- 端口 `Name` = 变量名（仅显示）；
- `DataTypeName` = 变量声明类型；
- `Description` = 变量 Guid 字符串（绑定键）；
- `ResolveBindKey`（`:464-465`）对两类节点返回 `Definition.Description`；`DoFinalBind`（`:708-715`）与 `Confirm`（`:736`）同口径。

守门：`UIThemeSmokeTest --variable-binding` 的三条条件节点契约（按 `LocalVariables` 列端口、双击绑定写 Guid 键、清除绑定删 Guid 键）。

### 3.2 数组类型判断：AssemblyQualifiedName 不能用 `EndsWith("[]")`

`PortDefinition.DataTypeName` 存的是 AssemblyQualifiedName，例如 `System.Double[], System.Private.CoreLib, Version=...`。字符串末尾是程序集信息，不是 `[]`，所以 `EndsWith("[]")` 永远为 false，数组徽标 / 索引按钮会整片消失。

`BindingTypeText.IsArray`（`VariableBindingView.xaml.cs:678-688`）改为：

1. 先 `TypeHelper.ResolveType(typeName)?.IsArray == true`；
2. 解析不出再退回 `typeName.IndexOf("[]", StringComparison.Ordinal) >= 0`。

这样既覆盖正常类型名，也不会因为未知类型名把数组徽标 / 按钮藏掉。

### 3.3 常量 / 上游模式：显式二选一，切换不写模型

`IsConstantMode`（`:124-152`）与 `IsUpstreamMode`（`:155-159`）只驱动右栏编辑区，点「确定」才写模型：

- 切到上游模式立即清空 `ConstantValue`。`Confirm` 的规则是"常量框非空就写常量"，不清空会让"上游模式下点确定"把残留常量写进去，静默拆掉上游连线。
- 切到常量模式只在 `GetExistingConstantLink()` 真有 Constant 连线时回显，不无条件回填。无条件回填会把 `UpdatePresetOptions` 刚填的枚举首项冲掉，用户看到的就不是实际生效值。
- `Confirm` 回传常量时 `DataTypeName` 取目标端口声明类型（`:745-751`），不再固定 `System.String`，否则 Int32 条件变量会被声明成字符串。

### 3.4 单绑定无 TargetStep：先建 mock 端口，不提前 return

插件视图发起绑定（`ProcessViewModel.OnLinkPathEvent` / `ConditionEditorViewModel.OnBindVariable`）可能只传 `IsSingleBindMode`，此时 `Workspace.CurrentStep` 也可能为空。`BuildTree` 只在 `_targetStep == null && !IsSingleBindMode` 时 return（`:779-780`）；单绑定分支（`:831-863`）用 `TargetPortName` / `TargetTypeName` 建一个 mock `InputPortUIModel`，默认「目标变量」/`System.Object`。

无 TargetStep 时 `allSteps` 取空（`:872-876`），只给全局变量候选；这既符合"没有上游就没有上游候选"的语义，也避免 `FlowQueryHelper` 在无 Prism 容器的测试宿主里解析插件。`TargetStepName` 在单绑定固定为「插件视图绑定请求」（`:970-972`）。

### 3.5 Unbind 必须同时清连线与 `InputValues`

`UnbindCommand`（`:187-206`）的顺序是：

1. `ResolveBindKey(port.Definition)` 取键（条件 / 等待节点是 Guid，其余是端口名）；
2. `_targetStep.RemoveLink(bindKey)`（内部 `RaisePropertyChanged(LinkedSources)`，保证 FlowModel 版本递增）；
3. `_targetStep.RemoveInputValue(bindKey)`；
4. `port.LinkedAddress = null`；
5. 清 `_lastBoundLink` / `_lastBoundPort` / `ConstantValue`。

只删连线不删 `InputValues` 会留下"界面未绑定、运行期却回落到旧手填值"的幽灵值；只改字典不走 `RemoveLink` 则版本不递增，已编译会话会继续用旧连线跑。

### 3.6 数组 → object：整数组绑定，不强制取下标

`DoublockClickBind`（`:566-635`）的 `isIndexing` 判据是：

```text
outputType.IsArray && !targetType.IsArray && targetType != typeof(object)
```

`object` 端口是"整值装箱"语义，`TypeHelper.CanBindTo` 对 object 双向放行。如果强制走索引，`double[]` 到 object 只能取一个元素，整数组永远绑不进去。数组 → 标量才展开行内索引面板；数组 → object 直接 `DoFinalBind`。

### 3.7 枚举端口已有非常量连线时不自动填首项

`UpdatePresetOptions`（`:512-522`）在端口已有非常量连线时不再执行 `ConstantValue = items[0].Value`。否则用户只是打开弹窗、点确定，就会用一个"用户没选过"的预设把原上游连线静默覆盖。`SelectedPresetDisplay`（`:180-181`）优先显示选中预设的 `Display`，没有选中时回退 `ConstantValue`。

### 3.8 隐藏计数与「显示全部」解耦

`HiddenByTypeCount`（`:77-84`）统计的是"默认视图看不到的那批"不兼容端口，与 `ShowAllPorts` 无关。勾选「显示全部」后这些端口以置灰形式出现，但计数仍表示"被类型隐藏"的事实；否则提示条会随勾选忽隐忽现，用户无法判断当前列表到底有没有被过滤。

### 3.9 鼠标滚轮不依赖键盘焦点（2026-10-20 真机反馈）

真机反馈"鼠标悬停在变量弹窗上滚轮没反应，必须先点一下"。根因有两层：

1. 候选 `ListBox` 的 `ScrollViewer.VerticalScrollBarVisibility="Disabled"` 后仍会处理 `MouseWheel` 并标记 `Handled`，外层右栏 `ScrollViewer` 收不到；
2. WPF `ListBox` 在未获得键盘焦点时对滚轮的响应不稳定。

修法：视图根挂 `PreviewMouseWheel="OnPreviewMouseWheel"`，在预览阶段从 `OriginalSource` 向上找**最近一个 `ScrollableHeight > 0` 的 `ScrollViewer`**，直接 `LineUp/LineDown`（一格 3 行）并标记 `Handled`。这样：
- 鼠标在左/中列表上 → 滚对应列表；
- 鼠标在候选列表/英雄区/常量面板上 → 候选列表自身不可滚时向上找到右栏 `ScrollViewer`，滚整栏；
- 不依赖点击/焦点，也不会出现内外两层同时滚的"双倍滚动"。
- `OriginalSource` 可能是 `TextBlock` 里的 `Run`（`ContentElement`，不是 `Visual`），`FindScrollableAncestor` 对非 `Visual` 走 `LogicalTreeHelper`，避免 `VisualTreeHelper.GetParent` 抛 `InvalidOperationException`。

守门：`UIThemeSmokeTest --variable-binding` 的静态检查"滚轮就近滚动接线（PreviewMouseWheel + FindScrollableAncestor）"。

### 6.1 与设计稿的已知偏差

| # | 设计稿 | WPF 实现 | 原因 |
| --- | --- | --- | --- |
| 1 | Lucide 描边 SVG 图标 | Font Awesome 6 Pro Solid（`DialogIconFont`） | 形状不同、语义一致 |
| 2 | Web 字体度量 | Segoe UI / Microsoft YaHei UI | 同字号字宽、行高略有差异，不按 px 硬套 |
| 3 | 滚动条约 8px | WPF 滚动条约 17px | 1000 窄档右栏可用宽度少约 17px，候选行仍守 360 下限 |
| 4 | 目标行 54px | `DialogOptionItem` 自带 Padding/Margin，视觉约 55-56px | 以不裁切两行文字为准 |
| 5 | 类型 chip 无描边 + 圆角 6 | `DialogTag` 1px 描边 + 圆角 4 | 统一走共享 Tag 键，不另造一套 |

| 9 | 固定两组来源 | `CollectionViewSource` 在无变量 / 无上游时不生成空组头 | WPF 分组视图的正常行为 |
| 10 | 单绑定左栏只 1 个目标端口 | 保留三栏；左栏只 1 个目标，搜索 / 筛选收起 | 不隐藏目标端口上下文，避免空间不足时丢信息 |
| 11 | Web 基线只演示 Esc | 仅 `Escape` → `CancelCommand`；Enter 绑定未加 `InputBindings` | 完整键盘导航列入后续（基线 D6） |
