# 视觉图像多格布局「双击放大本格 / 再双击还原」（2026-10-28）

## 一、当前状态

多格布局（2/3/4/5/6/7/8/9 格）下每格画面偏小，看单张图要来回切布局。本次落地：

- **双击某一格的大图 → 该格占满整个图像面板**（跨满当前 Grid 的全部行列，其余格折叠）；
- **再双击一次 → 还原平铺**（各回原槽位，图/列表/选中项都还在，不白屏）；
- 大图右键菜单多一项「最大化本格（双击大图）」/「还原布局（双击大图）」，多格布局才出现；
- **单画面（1 格）不接管双击**：双击仍是既有的「适应窗口 / 1:1」切换，F/1 与右键菜单的缩放能力不受影响；
- 切换画布布局（菜单/方案恢复）会自动退出放大态。

验证：`UIThemeSmokeTest` 的「多格布局」段新增 5 条断言，全部 PASS（可放大 4/4、跨满 2×2、其余三格折叠、还原后四格 1×1、单画面不接管）。

## 三、设计取舍（为什么不是"双击=全屏"）

- **与既有双击语义的冲突**：`HalconBase` 的双击早已是「适应窗口/1:1」切换（2026-10-08 评审过的行为）。直接改成放大等于悄悄废掉它。采用"按布局分派"：多格 → 放大；单格 → 保持缩放，且多格下 F/1 与右键菜单仍能缩放。
- **放大范围 = 图像面板，不是整个显示器**：面板内放大不动 AvalonDock（不触发 R43/R56 的布局版本与面板收敛问题）。真·全屏（F11 盖住整屏）可作下一步，见"未做"。
- **其余格用 `Collapsed` 而不是 ZIndex 垫底**：HALCON 画布是 `HwndHost`（独立 HWND），WPF 的 `Panel.ZIndex` 压不住它，叠放会露出邻居窗口。

## 四、未做

- **真·全屏（覆盖整个显示器）**：需要独立无边框窗口或临时收起停靠区，涉及 R43/R56 的布局语义，另立批次。
- **Esc 还原**：焦点在 HALCON 的 `HwndHost` 上，Esc 路由不可靠（`HalconBase` 已有意不在按下时抢焦点）；目前靠"再双击"与右键菜单还原。
- **放大状态不落盘**：切方案/重启回到平铺（刻意：放大是临时观察动作，不是布局配置）。

## 六、踩过的坑

1. **运行中的 `VisionMaster.exe` 会锁住 `Modules\*.dll` 与 `VisionMaster\bin`**：Debug/Release 构建都会报 `MSB3021/MSB3027`（不是编译错误）。用 `-p:ModulesDir=<临时目录>` 重定向能绕过拷贝，但依赖 `Modules\` 的插件加载断言会**假红**（本次 FlowCanvasChecks 因此出现 8 条"找不到插件"，非回归）。正确做法：关掉被测实例再跑 `tools\run_gates.ps1`。
2. **断言宿主日志编码不统一**：`UIThemeSmokeTest` 重定向到文件是 936，`FlowCanvasChecks` 是 UTF-8。按 R183 严格 UTF-8 优先、失败回落 936，否则统计行读不出来。
3. **`--no-dependencies` 不是"用旧 DLL 跑绿"的捷径**：它仍会拷贝引用工程的产物，只是跳过构建——判断依据要看拷贝来源的 mtime，不能只看命令成功。
4. **收尾闸门撞上另一会话的在途编辑（2026-10-28 21:00 实测）**：`run_gates.ps1` 跑到后半段时，`VisionMaster\Services\FlowConfigAccess.cs`、`FlowResultSourceDialogView.xaml(.cs)`、`App.xaml.cs`、`ScadaPermissionGate.cs` 正被另一会话改写，导致
   - `UIThemeSmokeTest`/`HelpProbe` 构建失败（`FlowResultSourceDialogView.xaml:223` 注释里出现 `--`，MC3000；`IFlowConfigAccess` 在 wpftmp 工程里"找不到"——文件刚出现）；
   - `FlowCanvasChecks` 在 HTTP 收图冒烟处崩（`AppConfig.json` 被并发进程占用）。
   这三条红都**不是**本次改动引入。判据：`Get-ChildItem -Recurse -Include *.cs,*.xaml | ? LastWriteTime -gt <开工时刻>` 能直接列出别人的在途文件（R9）。**多会话同仓作业时，收尾闸门必须串行，且看到红先查 mtime 再查自己的 diff。**
