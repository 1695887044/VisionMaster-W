# 主界面结构合并（流程导航 + 单列检查器 + 运行条）

- 日期：2026-10-20
- 范围：`VisionMaster/Shell.xaml`、`VisionMaster/Shell.xaml.cs`、`VisionMaster/ShellViewModel.cs`、`VisionMaster/Services/LayoutHelper.cs`、`VisionMaster/Views/ProcessView.xaml`、`UIThemeSmokeTest/ShellCopy.xaml`、`UIThemeSmokeTest/Program.cs`
- 设计依据：`docs/UI设计基线/app-shell/design.html`、`docs/UI设计基线/app-shell/README.md`
- 前提：项目尚未发布，用户明确“不要考虑迁移成本”，因此本轮允许改变 AvalonDock 面板归属并递增布局结构版本。

## 1. 结构改动

### 1.1 程序面板并入流程导航

- `ProcessView.xaml` 顶部新增 `<local:FlowListView Height="112" />`（`Grid.Row=0`），流程树下移为 `Grid.Row=1`，底部统计为 `Grid.Row=2`。
- `Shell.xaml` / `ShellCopy.xaml` 删除独立的 `Panel_FlowListView` 窗格；左栏只保留一个 `LayoutAnchorablePane`（`DockWidth=340`、`DockMinWidth=320`），标题改为“流程导航”。
- `LayoutHelper.LeftWorkPanels` 只保留 `Panel_ProcessView`；`ContentFactories` 删除 `Panel_FlowListView`；`EnsureProcessColumnWidth` 改为校正 `LayoutAnchorablePane` 的宽度（v6 不再有外层竖向 `LayoutPanel`）。
- `ShellViewModel` 的停靠监听清单删除 `Panel_FlowListView`；视图菜单只保留一个“流程导航”入口（指向 `Panel_ProcessView`）。

### 1.2 右侧单列检查器

- 原来“属性/图层”一列（260）与“工具箱/图元工具箱”一列（260）合并为**一列** `LayoutAnchorablePane`（`DockWidth=320`、`DockMinWidth=300`），四个 `LayoutAnchorable` 作为标签页：属性 / 图层 / 工具箱 / 图元工具箱。
- 模式收敛仍只改可见性：
  - 调试：工具箱；
  - 组态：属性 / 图层 / 图元工具箱；
  - 运行：全部隐藏；
  - 自由：四项全显示，属性作为主标签最后显示。
- `ApplyScadaPanelMode` 在组态模式显式把属性设为当前标签、其余组态标签 `IsSelected=false`——同 pane 内 AvalonDock 的 `IsSelected` 不是互斥位，只靠 Show 顺序会出现多个 `true`。

### 1.3 独立运行条

- `Shell.xaml` 根 Grid 增加 48px 行：`运行状态 + 当前流程`、`编译 / 运行一次 / 循环运行 / 暂停 / 继续 / 单步 / 停止`、快捷键提示。
- 顶栏删除原来的 7 个运行图标，只保留模式切换、搜索、全局变量/通讯设置与窗口按钮。
- 运行条在 `Config` / `Run` 模式下折叠（组态/驾驶舱有自己的上下文），调试/自由显示。

### 1.4 布局结构版本

- `LayoutHelper.CurrentLayoutSchemaVersion` 从 **5 升到 6**。
- 旧 `Layout.xml` / `.vms` 内嵌布局会被版本闸拒绝并回退默认布局；这是本轮结构改动的预期后果（项目未发布，不做迁移）。

### 1.5 空文档窗格修复（截图“明明打开了方案却空白”）

- 根因：`Layout.xml` 历史保存时缺少 `Panel_ScadaEditorView`（以及 `Panel_RunCockpitView`）。AvalonDock 只还原文件里声明过的文档，不会按 ContentId 补出缺项；于是组态模式只剩一个空 `LayoutDocumentPane`，`ScadaEditorView` 未装载，属性面板的 `ScadaEditorViewModel` 也拿不到画面，最终显示“未打开方案”。
- 修复：
  - `LayoutHelper.EnsureCoreDocuments(manager)`：按 `CoreDocuments`（视觉图像 / 流程画布 / 组态画面 / 运行驾驶舱）检查，缺哪个就用 `ContentFactories` 新建并挂到文档窗格；`ApplyDocumentMode` 和 `SaveToString` 都先调用它，避免缺项被再次写回 `Layout.xml`。
  - `ScadaEditorViewModel` 新增 `HasSolution` / `HasPage`；`ScadaPropertyViewModel` 区分“未打开方案”和“当前方案没有组态画面”，不再把有方案但无画面的情况说成未打开方案。
  - `ScadaEditorView` 增加空态：当前方案没有组态画面时显示“当前方案还没有组态画面 + 新建画面”按钮，而不是一张纯白画布。
- 守门：`UIThemeSmokeTest` 新增“布局缺组态文档时能按核心清单补回（不再出现空文档窗格）”。

### 1.5 流程栏条件摘要

- `StepModel` 新增只读 `ContainerSummary` / `ContainerSummaryVisibility`（`[JsonIgnore]`），与 `CanvasNodeViewModel.ContainerSummary` 共用同一份投影，避免两套 switch 漂移。
- `ProcessView` 的 If / While / For / 并行 / Case 五类容器组头均已绑定该摘要（`MaxWidth=150`、省略号 + ToolTip）。
- **实时通知链**：`StepModel` 自己订阅自身属性（Case 判据 / 并行模式与超时 / For 次数 / Wait 条件），`ContainerStepCountWatcher` 额外订阅每个分支的 `PropertyChanged`（`Expression` / `BranchType`），统一调用 `RaiseContainerSummary()`；`CanvasNodeViewModel` 只转发 `StepModel.ContainerSummary*` 通知，不再维护第二套分支订阅。条件编辑后流程栏组头与画布容器头同步刷新。
