# 2026-09-15 网络变量当前值排障 + 通信层诊断黑洞打通 + 类型下拉显示修复

## 一、现象与需求

用户截图：变量管理中网络变量"测"（Int32、Conn_100401 在线、地址 40001、轮询 1000ms）**当前值恒空**；同时数据类型下拉框显示 `VisionMaster.ViewModels.Dialog...` 乱码。

## 二、排查过程（静态链路核验）

"轮询→镜像→UI"链路逐环核验，结构均完好：
- UI 绑定 `OriginalModel.Value`（INPC）✔
- `UpdateMirrorValue → SetProperty` 通知 ✔
- 桥接器 DI 单例、集合 Add 即注册 ✔
- `manager.Connect`（唯一轮询启动点 L252）覆盖手动连接与 `ConnectAll` 启动自连 ✔

**结论：静态无法定位断点，因为诊断链路是黑洞**——发现真凶级缺陷：

> `AdvancedCommunicationManager` 的 LogInfo/LogWarning/LogError 全部只写 `Console.WriteLine`。WPF 应用没有控制台，**"变量注册/轮询启动/读取失败"所有诊断蒸发**，任何通信故障都无从排查。

## 三、修改内容

| 文件 | 修改 |
|---|---|
| `Communication/Communications/Manager/AdvancedCommunicationManager.cs` | 新增静态 `LogSink`（ILogService），LogInfo/LogWarning/LogError 双通道（Console 保留给调试器 + `[Comm]` 前缀进 UI 日志窗口/文件）；LogDebug 维持 Console（避免刷屏） |
| `VisionMaster/App.xaml.cs` | 启动自检链注册后挂接 `AdvancedCommunicationManager.LogSink = Container.Resolve<ILogService>()` |
| `VisionMaster/Services/NetworkVariableBridge.cs` | 构造注入 ILogService；Register 前置条件不满足（缺地址/连接名）与注册异常从 `Debug.WriteLine`/静默 return 改为 `[NetVar]` Warn——"变量存在但永不刷新"必须出声 |
| `VisionMaster/Views/DialogViews/GlobalVariableView.xaml` | **ModernCombo 模板修复**：`Content={TemplateBinding SelectedItem}` + `ContentTemplate={TemplateBinding ItemTemplate}` 改为 `SelectionBoxItem/SelectionBoxItemTemplate`——`DisplayMemberPath` 生成的模板放在 `SelectionBoxBoxItemTemplate` 而非 `ItemTemplate`，旧写法选中项回退 `ToString()`（下拉列表本身正常，纯显示 bug，选择值一直是对的） |

编译：Communication ✔ VisionMaster ✔ 0 错误。中途一次命名空间解析坑：`Core.Interfaces` 在 `VisionMaster.*` 命名空间下优先解析成 `VisionMaster.Core.Interfaces`（CS0234），`global::` 前缀修复。

## 四、重启后诊断决策表（当前值为什么空）

打开日志窗口，搜关键字，对号入座：

| 日志现象 | 断点 | 处置 |
|---|---|---|
| 无 `[Comm] 注册变量: Conn_100401.测`，且有 `[NetVar] ...未接入轮询` | 桥接注册被前置条件挡掉 | 按 Warn 文案补配置 |
| 无 `[Comm] 启动变量轮询定时器: Conn_100401` | **连接不是经"连接"按钮建立的**（如只点过"测试连接"——它裸调 `connection.Connect()` 且测完断开，不启动轮询） | 在通信设置里点正式"连接" |
| 有 `[Comm] 读取变量失败: Conn_100401.测 ...` 每秒刷 | 设备侧问题（模拟器无 40001 寄存器/站号/功能码不符） | 核对模拟器寄存器表 |
| 有 `[Comm] 轮询周期无效` | 连接配置 ReadCycleMs=0 | 改连接参数 |
| 一切正常但值仍空 | 读回的原始值经镜像链丢失（新场景） | 带日志反馈 |

## 五、已知边界

1. "测试连接"按钮裸调 `connection.Connect()` 绕过 manager（不启动轮询、状态事件不走 manager 通道）——属遗留设计（测试即连即断），若决策表第 2 条命中，建议后续把测试连接也收进 manager 统一入口；
2. LogSink 为静态挂接（通信层多处 new manager 的历史风险点），当前 DI 单例下安全；
3. 通信层其余类（连接实现、驱动）的 Console 日志未接——先覆盖排障主链（manager+bridge），后续按需要再扩。
