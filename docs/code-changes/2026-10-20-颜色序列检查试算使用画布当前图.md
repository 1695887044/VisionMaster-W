# 2026-10-20 颜色序列检查：试算使用画布当前图（右键「打开图片」也能直接试算）

## 1. 症状与根因

用户诉求：画布上**右键 → 打开图片**后，点「试算一下」应当用**这张图**算，而不是"换了图结果还是老的那一套"。

根因是两份图像状态分叉：

| 状态 | 谁写它 | 触发路径 |
| --- | --- | --- |
| `ImageEdit.HImage` | 共享控件 `HalconBase.OpenImage()`（`Services\Core.Halcon\Base\HalconBase.cs:1804`，直接 `this.HImage = image`） | 画布右键 → 打开图片 |
| `ColorCheckPlugin.DisplayImage` | 插件自己 `new HImage(upstream)` 的副本（`ShowUpstreamImage()`） | `Image` 端口 `Value` 变化 / `OnViewLoaded()` |

右键换图**不经过**插件，而旧视图的 `TryAnalyzeCommand` 调的是无参 `TryPreviewAnalyze()` → 内部只用 `DisplayImage`。
于是画布上是新图、算法算的是旧图，且**没有任何提示**。

## 2. 修法（最小改动，不动所有权）

### 2.1 `Plugins\Plugin.ColorCheck\ColorCheckPlugin.cs`

```csharp
public void TryPreviewAnalyze() => TryPreviewAnalyze(null);

internal void TryPreviewAnalyze(HImage? image)
{
    var source = image != null && image.IsInitialized() ? image : DisplayImage;
    ...
}
```

- **图源优先级**：传入图（已初始化）优先，否则回退 `DisplayImage` —— 旧行为（无参入口）逐字保留。
- **只读**：不持有、不 `Dispose`、不把 `image` 赋给 `DisplayImage`。`TryAnalyze(source, …)` 本身只读。
  所以 `DisplayImage` 的所有权、上游端口语义、`OnConfirm` 落盘内容全部不变。
- **为什么 `internal`**：`FlowCanvasChecks` 等宿主用 `Type.GetMethod("TryPreviewAnalyze")` 按名字取无参入口；
  两个 `public` 同名重载会让它抛 `AmbiguousMatchException`（断言宿主当场炸）。`internal` 不在默认绑定标志里。
- **空图提示**追加一句"也可以在画面上右键 → 打开图片，再试算（只影响试算，不改上游图像来源）"。
  原「载入」二字保留，`ColorCheckSequenceCheck` 既有的 `summary.Contains("载入")` 断言不失效。

### 2.2 `Plugins\Plugin.ColorCheck\ColorCheckView.xaml.cs`

```csharp
TryAnalyzeCommand = new RelayCommand(_ => Plugin?.TryPreviewAnalyze(ImageEditor?.HImage));
```

`ImageEditor` 是 XAML 里 `h:ImageEdit` 的 `x:Name`；`HImage` 是 `HalconBase` 的依赖属性，读它就是画布当前显示的那张
（含右键打开的）。命令执行时取一次，不缓存引用。

### 2.3 `Plugins\Plugin.ColorCheck\ColorCheckView.xaml`（文案）

- 「试算一下」ToolTip → "用画布当前这张图跑一遍（含右键 → 打开图片临时换的图），看几根、什么颜色、哪几根是补出来的；只试算，不改上游图像来源"。
- 画布空态补第二行："只想先看效果：在画面上右键 → 打开图片，再点「试算一下」（仅试算，不改上游图像来源）。"

## 3. 断言（`FlowCanvasChecks\ColorCheckSequenceCheck.cs` 新增 `[CC4]` 段，7 条）

| ID | 判据 | 对应的故障形状 |
| --- | --- | --- |
| P6a | `Type.GetMethod("TryPreviewAnalyze")` 能取到、0 参数、不抛 | public 重载 → `AmbiguousMatchException`，断言宿主与反射调用方全炸 |
| P6b | 带图重载存在且 `IsAssembly && !IsPublic` | 被改成 public = 上面的二义性回来 |
| **P2** | 传 cable2（10 芯）而 `DisplayImage` 是 cable1（5 芯）→ 结果必须是 10 芯 | 传入图不生效（等于没接上） |
| **P4** | 试算后 `DisplayImage` **同一引用**、尺寸不变、仍 `IsInitialized` | 试算顺手把画布图写回 `DisplayImage` = 所有权/上游语义被污染 |
| **P3** | 无参调用 → 结果仍是 `DisplayImage` 的 5 芯 | 回退路径被删（旧调用方静默失效） |
| P5 | 两图皆空时提示含「打开图片」且仍含「载入」 | 新入口没写进提示 / 旧断言被文案改动搞红 |
| **P6c** | 视图源码去注释后必须含 `TryPreviewAnalyze(ImageEditor?.HImage)` 且**不含**无参调用 | 改回无参 → 右键换的图永远不参与试算（本条是唯一能拦住它的闸） |

图像用现有样图 `Image\颜色\cable1.png`（5 芯）/ `cable2.png`（10 芯），与既有黄金参照一致。

## 6. 未验证 / 遗留

1. **真机未验收**：需在 VisionMaster 里打开配置 → 右键打开一张本地图 → 框采样区 → 试算，确认结果来自这张图；
   再点「执行」确认 `DisplayImage` 仍是上游图（画布会被上游图覆盖，这是 `ShowUpstreamImage` 的既有行为）。
2. **画布换图后的清空语义**：右键打开新图不会清空 `CanvasRois`（ROI 是配置态、不随图变），若两张图尺寸差很多，
   框可能落到图外 —— 此时试算报"采样区超出图像范围"，提示语已含处置办法。
3. **未做**：把右键打开的图持久化成"示意图路径"（会改上游语义与落盘键，属功能变更，需另行立项）。
