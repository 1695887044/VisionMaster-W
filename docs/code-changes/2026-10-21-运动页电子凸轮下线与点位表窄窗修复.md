# 运动页：电子凸轮 UI 下线 + 点位表窄窗修复

- 日期：2026-10-21
- 范围：`VisionMaster` 运动板卡页（页签、点位列表布局）
- 起因：真机截图里运动页「点位列表」右表的标题与「当前位置」重叠、表头 7 列被压到裁切；用户同时裁定「电子凸轮功能先放弃，不要开放在 UI 上」。

## 1. 电子凸轮 UI 下线

只下线 UI，不删数据/模型：

- `MotionBoardViewModel.TabLabels` 从 4 项改为 3 项（卡设置 / 手动调试 / 点位列表）。
- `MotionBoardView.xaml` 删除 `MotionBoardCamView` 的挂载；页签索引 3 不再有任何内容。
- `SelectedTabIndex` 夹到 `0..2`：旧深链/持久化值若还是 3，不会让 ListBox 选中不存在的项。
- `OnDialogOpened` 的 `tab` 映射删除 `"cam" => 3`；`debug` / `points` 保持不变。
- `MotionBoardCamTabViewModel` 与 `MotionBoardCamView` 文件保留，`CamTables` 数据、轴改名级联、`Cam.LoadTables()` 也保留——已落盘的凸轮表不会被这次 UI 下线破坏，将来重新开放时不用做数据迁移。

## 2. 点位表窄窗修复

宿主最小宽度 1100 时，点位页右表原来只有约 366px（左轴栏 220 + 间距 14 吃掉一半）：

- **轴选择栏改到顶部**：`轴 · 各持一张点位表` 变成横向胶囊条（每项 190px，横向滚动），表格拿到工作区整列宽度。
- **标题行**：原来左右两块放在同一个 `Grid` 单元里，窄窗下互相覆盖。改为两列（`*` + `Auto`），左侧图标与文字用内层 Grid 约束，长文案加 `TextTrimming` + ToolTip；右侧「当前位置」独立列。
- **表格**：`MinWidth="560"`，7 列按比例铺满，不再需要横向滚动；表头文案收紧为「位置 / 速度 / 加减速 / 曲线」，单位放 ToolTip；补第 7 列「操作」。
- **图例**：第二行改成独立 `TextBlock` + `TextWrapping`，窄窗换行而不是被右边缘裁掉。

## 3. 验证

- `dotnet build VisionMaster.sln`：**0 错误**（警告均为既有）。
- `UIThemeSmokeTest`：构建/运行均 0 退出码；运行时布局闸「运动点位表窄窗：标题与当前位置不重叠，表格铺满可用宽度」——在 660×600 下真实 `Measure/Arrange`，实测 `重叠=False；表宽=626；横向滚动=0`，通过。
- `FlowCanvasChecks`：**3024 通过 / 0 失败**；新增 **HW20** 钉住「TabLabels 不含电子凸轮、XAML 不再挂 MotionBoardCamView、没有 cam 深链」。
- 真机（直接运行 `VisionMaster\bin\Debug\net9.0-windows\VisionMaster.exe`，不重新构建）：硬件管理 → 运动控制 → 点位列表，实测三个页签（无电子凸轮）、7 列表头全部可见、标题与「当前位置」不重叠、图例两行完整、无横向滚动条。

## 4. 已知边界

- 电子凸轮只是不在 UI 上开放；底层 `CamTables`、轴标签级联与 VM 仍在，旧方案文件里的凸轮数据不会丢。
- 轴很多时顶部轴条横向滚动（每个 190px），不再挤压表格。
- 表格最小宽度 560px；宿主最小宽度 1100 时实际可用约 626px，仍有约 66px 余量。
