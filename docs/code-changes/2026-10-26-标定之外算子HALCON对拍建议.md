#### P0-4 的疑点展开（已实测并修复）

`MatchingPlugin.cs:1253-1266` 的注释说：NCC 没有 `set_ncc_model_origin`，
所以"直接取 `Rect[0]/Rect[1]` 作为用户期望的原点，实际偏移量为 0"。
`MatchingPlugin.cs:1718-1724` 又写"这里在输出侧补同一份偏移"，但：
`dRow = entry.Rect[0] - ModelOriginRow(entry)`，而 `ModelOriginRow` 返回 `entry.Rect[0]`，
所以 `dRow = 0`。形状匹配那边用 `set_shape_model_origin` 把原点搬到了区域中心；
NCC 的 `find_ncc_model` 返回的是模型域重心。**模板掩膜不对称时，两者原点会差一个重心偏移。**
实测：非对称掩膜 offset=(-10.864,-10.864)，NCC 距 ROI 中心 13.13 px。已按"学习时记偏移、
匹配时按角度旋转补回"修复；回归断言见 `MatchingChecks.RunNccOrigin()`。

### 2.4 不建议现在做（P2）

- **DL 插件**（`Plugin.Yolo`、`Plugin.DlClassify`、`Plugin.DlSegment`、`Plugin.DlAnomaly`）：
  ONNX 推理，与 HALCON DL 不是同一模型/同一预处理，算法级对拍没有意义；
  只建议对预处理（resize/归一化/NMS）做单元测试。
- **`Plugin.ColorCheck` / `Plugin.ColorRegion`**：颜色词表与阈值是自定义的；
  可对拍 `trans_from_rgb`/`decompose3` 的颜色空间转换与中位色，但判定结果不应要求与 HALCON 一致。
- **`Plugin.Utility/MathCalculation`**：标量加减乘除，无 HALCON 对应必要。
- **运动/通讯/数据库/Excel/上传/记录/采集/图像赋值/结果渲染/流程控制/脚本**：
  不含 HALCON 视觉数学，不做算法级对拍。

## 五、踩过的坑（对拍前先看）

- **`distance_pc` 不是"点到圆心"**：它要一条圆轮廓，返回点到轮廓的最小/最大距离；
  验"点到圆残差"要么 `gen_circle_contour_xld` + `distance_pc`，要么 `abs(distance_pp(点,圆心) − R)`。
- **`angle_ll` 有符号**，插件 `AngleBetweenLines` 返回 [0,90]；比较时取绝对值并折到 [0,90]，
  否则会把 150° 与 30° 混为一谈。
- **`line_orientation` 返回弧度**，插件 Phi 是度且 [0,180)；比较时先转度、再按 180° 取模。
- **`intersection_line_circle` / `intersection_circles` 要 `StartPhi`/`EndPhi`/`PointOrder`**；
  全圆用 0..2π + `"positive"`，否则只返回圆弧段上的交点。
- **6 元仿射矩阵排布不同**：插件 `[a11,a12,a21,a22,tx,ty]`，
  HALCON `hom_mat2d` 是 `[a11,a12,tx,a21,a22,ty]`；不重排直接比会得"矩阵不一致"的假结论。
- **透视矩阵先按 h33 归一**再逐元比；HALCON 可能整体差一个尺度。
- **网格（Mesh）没有单一 HALCON 算子**：按三角形用 `vector_to_hom_mat2d` + `affine_trans_point_2d` 对照；
  网格外推行为要单独写断言（插件明确失败，HALCON 仿射会外推）。
- **`Matching` 的 NCC 原点不要按注释想当然**：先做非对称掩膜实测，确认 `dRow=0` 是否真的等价于区域中心。
