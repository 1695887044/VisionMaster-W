### 关键设计说明

1. **SafeDispatch 下沉 Core**（`Core/Helpers/SafeDispatch.cs`，namespace `VisionMaster.Helpers`）：
   引擎侧 `WatchPortWrapper`（Core 工程）也要用它，UI 层的版本 Core 引用不到。UI 版删除，全部 6 个调用点改指新位置。
2. **"写设备"与"更新镜像"必须分开建模**（C1 核心教训）：
   `Value` setter 的 `SetProperty` 短路对 UI 是美德（无变化不通知）、对设备是灾难（同值重发是产线刚需——设备侧可能被手动改回，"再写一次"是**命令**不是状态设置）。新增 `TryWriteToValue(value, out error)`：无条件下发、返回真实结果（离线/未配置地址/驱动异常各有明确文案）、成功后才同步镜像。`ExecuteWriteValue` 按结果反馈，`ResetToDefault` 也改走显式写。
3. **A1 类型安全代理**：`VariableNode.DefaultValueText`（string）在 setter 里按节点 `DataType` 做 `Convert.ChangeType`，失败抛异常——XAML 开 `ValidatesOnExceptions=True`，红框提示且模型零污染（`IVariable.DefaultValue` 接口因此补了 setter）。数组类型不走文本入口（保留"编辑集合"）。
4. **断桥修复取"绑引脚"路线**：`ContextAwareBindings` 从 `CompiledPluginNode` 上移 `CompiledNode` 基类 + `BindContextAwarePorts` 助手；FlowCompiler 的 RuntimeMarker 分支放行 If/While/For 三类节点（条件节点期望类型查 `LocalVariables` 声明、For 固定 int）；三个节点 Run 入口注入 context。公共赋值段（`UpstreamLinks[varId]` / `LoopCountLink`）原样复用，改动最小。`RuntimeVariableRefs`（无 UI 写入方的死机制）本次保留不启用。
5. **E1 修白名单不修 DTO**：数组无参数化构造攻击面，但元素类型仍收敛到基元/值类型白名单；比把 Value/DefaultValue 改字符串存储的方案改动面小一个数量级。
6. **B2 用"跟踪集"而非"当前集合"退订**：`Clear()` 触发 Reset 且 `OldItems=null`——凡靠事件参数清理的地方在 Reset 时都拿不到旧清单（弹窗 VM 的 `_trackedVariables`、桥接器的 `_registered` 同一治法）。`Dispose` 也改用跟踪集，被 Clear 掉的变量不再漏退订。
7. **A2/A3 契约"默认成功、显式失败"的延伸**：数据被悄悄篡改（`catch→默认值`、类型静默转换失败后条件集体不走）比当场失败更难排查。赋值插件对既有变量做类型对齐：可 `Convert.ChangeType` 则转（记 Warn），不可转显式失败。

## 四、重启后回归清单（变量部分）

1. **E1 实测（最高优先）**：建 `int[]` 变量（或给默认数组变量填非空值）→ 保存 → 重新打开——修复前整方案报"加载方案失败"，修复后应正常；
2. **C1**：网络变量在连接**离线**时写值 → 应弹"连接离线，未写入"（旧版：绿色"已写入"）；在线时对**同值**再点一次写 → 设备应真收到（旧版被短路跳过）；
3. **B1**：开变量弹窗 + 拔 PLC 网线（或停 Modbus 模拟器）→ 不崩、状态徽标变灰；
4. **A1**：int 变量初始值填 `abc` → 红框拒写、模型保持旧值；填合法数字 → 正常；
5. **② 断桥**：`变量定义(Score,double)` → `If` 弹窗加引脚变量 Score 并绑定到"运行时变量(Score)" → 保存 → 运行：条件按 Score 实际值走分支（旧版编译报"仅普通算子节点支持"）；For 的 LoopCount 端口同样可绑 Runtime 变量；
6. **A4**：运行中删变量 → 互锁弹窗拒绝；
7. **A3**：`变量定义(x,int)` 初始值填 `abc` → 步骤卡红 + 日志给出转换失败原因（旧版：静默变 0 还报成功）；
8. **A2**：double 变量被赋值 `"OK"` → 显式失败；赋 `"3.5"` → 自动转 3.5 + Warn 日志；
9. **B2**：方案 A↔B 来回切 3 次（带网络变量）→ 日志/流量中不应有旧方案变量仍在轮询；
10. **E2**：删掉连接后保存方案 → 该连接的网络变量仍在列表（显示未配置地址），不再蒸发；
11. **C4**：高频改变量值时表格不再逐次闪重建，编辑中的单元格不被吞。

## 五、已知边界（有意留下的）

1. `ConditionStep.RuntimeVariableRefs` 机制保留但仍无 UI 写入方（断桥修复选了"绑引脚"路线，该字段属死重，未来可连同 `CompileRuntimeVarRefs` 一并清）；
2. 变量**无改名功能**未新增（改名会牵连 `GlobalVariables.FirstOrDefault(s => s.Name == ...)` 这类编译期名字引用，A4 的 stale 问题在改名场景更严重，需独立设计）；
3. 监视栏对 `Runtime.*` 变量不可见（两池隔阂的另一半，文案已说实话，功能未接）；
4. `NetworkVariableModel` 写值成功才同步镜像，**离线时 `Value` setter 仍乐观更新镜像**（Restore 赋值、画布 HMI 写值等旧调用路径的行为保持——只有弹窗写值/恢复初始值走了显式正门）；
5. For 无迭代硬上限（While 有 9999），靠弹窗校验 1~99999 + 运行期负数钳 0 兜底；
6. E1 若实测仍现新形态（如 List<T> 嵌套自定义类型），binder 数组分支已留 `IsAllowedFullName(element)` 递归口子。
