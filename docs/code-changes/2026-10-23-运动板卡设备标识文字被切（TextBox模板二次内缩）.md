# 运动板卡「设备标识」输入框文字被上下切（TextBox 模板二次内缩）

> 日期：2026-10-23 ｜ 范围：`VisionMaster/Views/DialogViews/MotionBoard/MotionBoardTheme.xaml` 的 `MbTextBox` 模板 ｜ 状态：已修，探针实测复核 + Debug/Release 重建 + gate 实跑

## 1. 症状

硬件管理 → 运动控制 → 卡设置 → 「设备标识」输入框，值 `正运动虚拟控制器（127.0.0.1:502）` 的汉字上下各被削掉一截（顶部横画看起来被抹平、括号底部缺口）；同屏「运动参数」的数字框看着正常。

数字"看着正常"是巧合：数字墨迹只有 9~10px，正好落在被压扁后剩下的 10px 可见带里；13px 中文的墨迹有 13px，就露馅了。

## 2. 根因

`MbTextBox` 模板把 `Padding` 又做成了 `PART_ContentHost` 的 `Margin`：

```xml
<ScrollViewer Margin="{TemplateBinding Padding}" x:Name="PART_ContentHost" />
```

`TextBoxBase` 自己已经按 `Padding` 给文本内缩一次，模板再套一层 `Margin` 等于内缩两遍：

```
Height 38 − 边框 2 − Margin(6+6) = 24（ScrollViewer 实高）
24 − 内部 Padding(6+6) = 12px（viewportH）
13px 微软雅黑行高 = 16.51px  →  只剩 12px 能显示，上下各被裁
```

`viewportH(12) < extentH(16.51)`、`scrollableH=4.51` —— 文字在一个自己都装不下的滚动视口里。

## 3. 实测（临时探针：net9.0-windows，实例化真 `MotionBoardSettingsView` + stub DataContext）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `PART_ContentHost` 实高 | 24 | 36 |
| `viewportH` | **12** | **24** |
| `extentH`（行高） | 16.51 | 16.51 |
| `scrollableH` | 4.51 | **0** |
| 墨迹行数（RenderTargetBitmap 数暗行） | 10 | **13**（完整） |
| 文字左起 x | 23（双重内缩） | 13（= 边框 1 + Padding 10） |

模板写法对照（同一控件、同一字号，只改模板）：

| 变体 | `Margin` 绑 Padding | `VerticalContentAlignment` 绑到宿主 | viewportH | 墨迹行 |
|---|---|---|---|---|
| V1（原样） | 有 | 有 | 12 | 10 |
| V2 | 有 | 无 | 12 | 10 |
| V3（修复后） | 无 | 有 | 24 | 13 |
| V4 | 无 | 无 | 24 | 13 |
| V5/V6（加 `VerticalAlignment=Center`） | 有 | — | 12 | 10 |

结论：**病根是 Margin，不是对齐绑定**；`VerticalContentAlignment` 绑不绑都行（保留）。

## 4. 改动

| 文件 | 改动 |
|---|---|
| `VisionMaster/Views/DialogViews/MotionBoard/MotionBoardTheme.xaml` | `MbTextBox` 模板的 `PART_ContentHost` 去掉 `Margin` 绑定，留注释说明为什么不能再加 |

`MbCellTextBox` / `MbCellInput` 都 `BasedOn="{StaticResource MbTextBox}"` → 一并修好（它们 `Height=28`、`BorderThickness=0`，修复前同样只剩 16px 视口）。

## 5. 副作用（有意为之，属修正）

`MbTextBox` 的使用者（卡设置 / 手动调试 / 相机页）文字水平内缩从 20px 回到设计值 10px（`Padding=10,6`），垂直不再被切。已逐个确认这些位置没有依赖旧偏移的叠层：都是独立的固定宽输入框（`Width=90/100/120`），没有"贴在输入框左侧的图标/后缀"。

## 8. 踩坑

1. **看截图判断"有没有被切"不可靠**：禁用态 `Opacity=0.5` 会让抗锯齿的顶行变淡，看起来也像被切。判据必须落在 `viewportH vs extentH` 和"数出来的墨迹行数"上。
2. 探针里 `Border` 没有 `FontFamily`（`Decorator` 不是 `Control`），要 `TextElement.SetFontFamily(host, …)` 才能复刻 `MotionBoardView` 的继承环境（`FontFamily="Microsoft YaHei UI"`）。
3. `TextOptions.TextFormattingMode` 默认就是 `Ideal`；切到 `Display` 行高变 19，切得更狠（只剩 8 行墨迹）。
4. `TextBox` 模板里 `PART_ContentHost` **只能由控件自己内缩**；模板侧再吃一次 `Padding` 就会把固定高度的小框压扁。
