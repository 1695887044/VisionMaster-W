v2 关键改动
01
单条 → 行列表一个节点写多个变量；每行一个作用域、一个变量名、一个值。行顺序即执行顺序，失败行不阻断后续行。
02
每行独立「值」端口行内 LinkableValueEditor 绑各自的 Value_<RowId>；两行可以分别接不同上游，互不串线。
03
作用域按行选择同名变量在两个作用域各有一份；强制整组一致会堵死「运行时 + 全局」混写，所以作用域放在行内。
04
旧配置迁移旧版单条配置首次打开时合成第 1 行，并打「原配置」标记；旧「值」连线保留，旧「名字」连线解除并提示。
05
行内反馈分两级空名 = 红色错误；找不到变量 / 跨作用域 = 琥珀警告；全局行的「自动创建」显示锁图标，不静默失效。
06
批量操作与键盘添加 / 复制 / 上移下移 / 删除 + 撤销；Enter 下移、↑↓ 选行、Delete 删行、Ctrl+D 复制。
契约保留（WPF 复刻时不能改）
C1
DataContext = 插件实例宿主靠 viewObj.DataContext as IPluginConfigView 取 OnConfirm；行列表不引入独立 VM。
C2
每行一个 InputPort<object>端口名用稳定 RowId（Value_<RowId>），改名不断线；IsRequired=false。
C3
变量名是「名字」不是「值」名字行不接通用绑定弹窗；候选来自宿主快照，选中落成常量。只有「值」行可以连线。
C4
用户编辑只认真实输入事件键入 / 删除 / 剪切 / 粘贴 / 选择 / 拖放才解除旧名字连线；程序灌值不算用户编辑。
C5
确认时一次回写Rows JSON 快照 + 各 Value_<RowId> 常量一起写入；未连线行才写常量，链接行以链接为准。
设计决策
D1
为什么用 ItemsControl 而不是 DataGridDataGrid 单元格要先进编辑态，内嵌 LinkableValueEditor 得双击才能输入；GridView 列宽是固定像素、无星号列，640 档无法自适应。
D2
为什么删除链接行要二次确认删行会一并 RemoveLink；不提示就点确定，用户会以为只是删了一行文字。非链接行删除给「撤销」。
D3
为什么 640 改两行式窄档左栏约 364：作用域 68 + 名字 + 操作 66 已贴边；第二行放「值 + 自动创建」，避免把输入框压到不可用。
D4
为什么保留 32 行上限每行一个动态端口，32 行约 100+ 控件；软上限防止误建，到顶禁用「添加」并给出说明。
D5
为什么错误不阻断「确认」保持现有语义：空名在运行期明确失败；界面用红色行内提示 + 底部状态提醒，不静默吞掉，也不阻止用户先保存草稿。
明确延后（需新增功能或契约）
L1
拖拽排序本轮用上移/下移；拖拽涉及 gong-wpf-dragdrop 与 R171，单独立项。
L2
配置态类型预览 / 转换器当前写入侧在运行期按声明类型解析；配置态没有目标变量类型元数据可绑定。
L3
变量管理入口 / 变量浏览器需要新的宿主导航契约；本稿只保留候选下拉与提示。
L4
每行独立 Success/ErrorMessage 输出端口本轮只保留节点级输出；行级结果在配置界面与日志里呈现，避免画布端口爆炸。
