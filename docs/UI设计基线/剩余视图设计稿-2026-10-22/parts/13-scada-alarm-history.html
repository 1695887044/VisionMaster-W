报警历史 · 空态 EmptyHint 两种原因分开说

没有符合当前筛选条件的报警。

一条记录都没有时是另一句：「本次运行还没有报警记录。」——两种原因必须分开说，否则用户会去怀疑筛选坏了。此时「全部确认」由命令自动置灰

覆盖与要点

  • 覆盖：ScadaAlarmHistoryView.xaml（标题条 38 + 筛选区 + 8 列 GridView + 提示行 + 底条 40）、ScadaAlarmHistoryViewModel.cs（SummaryText / EmptyHint / 两组筛选）、ScadaAlarmHistoryRow.cs（TimeText / StateText / DurationText）
  • 改动要点 1：29 处 hex 全部收进令牌——面板 #1B1F24 / 条 #22262C / 线 #33383F / 正文 #D6DAE0 / 次要 #8A929E，再加行 hover #252A31、行选中 #2A3442、确认钮 #2B6CB0 三支。运行窗口是深色语境，本稿按浅色令牌出（见下条偏差）
  • 改动要点 2：筛选筹码由 ListBox + WrapPanel 保留，但 Chip 的圆角/内边距改成令牌档（现为 Padding 10,2 + CornerRadius 9，与 8pt 栅格不合）；选中档位只留一个视觉信号（底色 + 边框），现在底色和边框同时换两套色
  • 改动要点 3：列宽预算固定 632（96/46/120/70/116/78/56/50），行内「确认」按钮 20 高 + Padding 8,0 保留；已确认整行 Opacity 0.6 改成次要色文本，避免半透明把等宽时间列糊掉
  • 改动要点 4：级别列是「3px 色条 + 同色文字」双通道，色条与文字都取同一个语义令牌（严重 / 警告 / 提示），不能只留色条——色觉差异的人会丢整列信息
  • 改动要点 5：底部两个批量动作是中性块（FooterButton）、行内「确认」是强调块，两者必须保持不同视觉重量；「全部确认」的可用性由命令判，不写第二处 IsEnabled
  • 需要新增的接口：无。已知偏差：现网面板是深色（PanelBrush 系），共享 CSS 只有 Dialog* 浅色令牌；若运行窗口保持深色，需在 Colors.xaml 补一组 RunWindow 深色令牌后本页重出
