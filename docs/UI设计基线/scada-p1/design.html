00 代码评审结论

先看代码再画图：四项的成本、复用面与建议批次。

StateView复用高

复用 ScadaStateList / StateListResolver / StateListMissing。列表条目要追加 Image、Color、DefaultImage；一个 TypeKey + 三个预设。

SubPage成本最高

主数据泵只扫主画布控件，嵌套画布不会自动建表。建议 P1a 固定页 + 只读 + 活数据，P1b 再做变量切页与交互。

报警事件引擎已有

AlarmRaised / AlarmChanged / AlarmCleared 已在；补三条页面事件、来源过滤与 UI 线程路由。

位操作最小改动

BitButtonElement 已有置位/复位/取反/按下 ON/按下 OFF。动作表补 SetBit / ResetBit / ToggleBit + BitIndex。

建议顺序：StateView（M）→ 位操作（S）→ 报警事件（S/M）→ SubPage P1a（M）。 SubPage 不排第一批，因为它会引入“嵌套画布 + 第二份数据泵 + 事件宿主判断”三件新东西。 详细代码引用见 docs/方案设计/2026-10-24-SCADA-P1代码评审与设计切分.md。

06 待拍板

这些会改变实现范围，确认后再进 WPF 复刻。

  1. StateView 一个 TypeKey 还是三个？本稿建议一个 Hmi.StateView + 三个预设；拆三个 TypeKey 会让列表/面板/Web/断言各写三份。
  2. 列表条目要不要 Color？字指示灯需要状态色；如果只做 Text + Image，字指示灯只能用统一文字色。
  3. SubPage P1 是否接受只读？接受 = M；不接受 = L（要加活跃子页事件宿主与交互）。
  4. 报警事件只做页面级吗？图元级（AlarmBanner 自己）是否需要单独事件？
  5. 位号范围按 0~31 固定，还是按变量类型动态？本稿建议先 0~31，执行侧按实际类型校验。
  6. Web 运行态本批同步到哪一步？StateView 建议同步；SubPage 视快照递归成本再定。
