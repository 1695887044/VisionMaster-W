## 定位

按 `AGENTS.md` 的四步流程，本目录是**第 ① 步（Web 设计基线）**的产物：

```text
① 设计基线（本目录） → ② 设计定稿与令牌映射 → ③ WPF 复刻 → ④ 截图验收
```

- Web 只是**设计媒介**，不进入构建、不部署、不作为第二个客户端维护。
- 三套模板是**页面结构参考**，不是固定页面规格：复用公共壳与信息层级，主工作区按现场替换。
- 本轮**不决定**技术选型、数据契约、导航逻辑与实现顺序。

## 公共壳（A~E）

三套模板共用同一副外壳，只替换 C 区：

```text
┌──────────────────────────────────────────────┐
│ A  TOP BAR   site / mode / alarm / user / clock│
├────────┬───────────────────────────┬─────────┤
│ B NAV  │ C WORKSPACE               │ D RAIL  │
│        │ industry-specific         │ alarm   │
│        │                           │ KPI     │
│        │                           │ detail  │
├────────┴───────────────────────────┴─────────┤
│ E  STATUS BAR   connection / cycle / version  │
└──────────────────────────────────────────────┘
```

| 区 | 内容 | 约束 |
| --- | --- | --- |
| A 顶栏 | 站点/单元名、运行模式、关键状态、报警入口、操作员、时钟 | 只放 L1 状态，不放操作按钮；报警入口始终可见 |
| B 左导航 | 总览、主工作页、报警、配方/参数、统计、设置 | 当前页高亮；底部固定连接状态；导航项不超过 8 个 |
| C 主工作区 | 行业核心工作面（流程图 / 轴卡 / 图像） | 占最大面积；只放“当前页要做的判断与操作” |
| D 右信息栏 | 报警、KPI、设备/点位/配方、维护/触发 | 顺序固定：先报警，再指标，再明细；不随页面随意重排 |
| E 底栏 | 连接、周期/帧率、轴数/模型版本、方案与版本 | 只读状态，不放操作按钮 |

## 信息层级

三套模板统一按四层组织，保证操作员视线路径一致：

| 层 | 回答的问题 | SCADA 监控 | 自动化设备运控 | 视觉行业 |
| --- | --- | --- | --- | --- |
| L1 | 现在正不正常？ | 顶栏运行状态 + 未确认报警数 | 顶栏自动/手动 + 报警 + 当前步 | 顶栏在线/模型 + 报警 |
| L2 | 哪里不正常？ | 工艺流程图上的设备状态与测点 | 三轴卡（使能/报警/限位）+ 当前步 | 图像上的 OK/NG 框 + 结果徽标 |
| L3 | 是偶发还是趋势？ | 关键趋势 + KPI | 节拍/产量/良率 + 点位摘要 | 最近检测 + 班次统计 + 通过率趋势 |
| L4 | 怎么处置？ | 报警列表、批次、配方入口 | I/O 联锁、点位表、维护提醒 | 配方/阈值、相机/光源、触发 |

## 视觉口径

| # | 口径 |
| --- | --- |
| 1 | 运行画面深色：画面底 `#0E1318`、表面 `#151C23`、浮起 `#1B242D`、描边 `#2A3745` |
| 2 | 状态色只表达状态：绿=运行/OK、黄=警告、红=故障/NG、灰=停机/未启用；青蓝只做交互/选中 |
| 3 | 数字等宽：位置、节拍、产量、良率、耗时、坐标一律 mono，避免跳动 |
| 4 | 报警始终可见：顶栏报警入口 + 右栏报警卡；严重度用色条与徽标，不靠文字颜色单独表达 |
| 5 | 主工作区不做“第二套状态”：设备状态直接落在流程图上，轴状态直接落在轴卡上，检测结果直接落在图像框上 |
| 6 | 按钮只放在需要操作的位置：轴卡、结果卡、顶栏启动/暂停；底栏与卡片标题不放操作按钮 |
| 7 | 公共壳一致：三套模板的顶栏、左导航、右栏、底栏结构一致，只替换 C 区内容 |

## 复用约束

1. **公共壳原样复用**：A/B/D/E 四区不改结构；只替换 C 区。
2. **右栏顺序固定**：报警 → KPI/状态 → 明细/维护；不要把报警压到最下面。
3. **顶栏只放 L1 状态**：站点、模式、报警、用户、时钟；启动/暂停等操作留在主工作区或轴卡。
4. **底栏只放只读状态**：连接、周期/帧率、版本；不放按钮。
5. **候选图元不当作已实现**：需要 `SequenceStep` / `InterlockMatrix` / `DataTable` / `ChartBar` 的页面，先在设计中标注，落地时优先用现有图元组合。
6. **`Hmi.Picture` 属性面板口径**：只保留「加载图片 / 替换 / 清除」与缩略图，**不显示、不暴露文件路径**；不新增 `FilePath` 属性类型。图片作为方案资产复制到方案根目录 `Image\`，`.vms` 内部只存相对路径。
7. **不引入新技术决策**：本轮不定义数据源、通信、流程触发、权限与部署方式。

## 与 `scada-controls` 基线的关系

- 令牌、字号、圆角、状态色沿用 `docs/UI设计基线/scada-controls/README.md` 的令牌映射。
- 图元名称与 TypeKey 以 `Scada.Controls/Descriptors/BuiltInElements.cs` 与 `Scada.Controls.Charts/ChartElements.cs` 为准。
- `Hmi.Picture` 的“只加载图片、不暴露路径”口径见 `scada-controls/README.md` 的「方案资产约定」与「属性面板口径」。
