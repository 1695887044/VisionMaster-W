## 定位

按 `AGENTS.md` §30.1 的四步流程，本文件是**第 ① 步（Web 设计基线）**的产物。
Web 只作设计媒介，**不进入构建、不部署**（R126）。确认后按本基线做第 ③ 步（WPF 复刻），
第 ④ 步以「同一屏、同一状态」的截图对照验收（R129/R132）。

v2 是**结构性改版**，不是换肤：按“调试 / 运行 / 组态”三种工作场景重排工作区，
把右栏三列收成一个上下文检查器，把底部日志改成可收起控制台，把运行控制从顶栏拆成独立运行条。
v1 的六区停靠布局保留在 `design-v1.html`，并作为 v2 的“自由布局”逃生口。

## 一句话结论

v1 的问题是 **chrome 占面积、信息按面板组织**：1920 下左栏 300 + 右栏 800 + 分隔 12，
画布只剩约 808；底部再固定 200，实际画布约 808×730。
v2 在调试场景把右栏收成 320、底部收成 32，画布约 **1292×852**（面积约 2.2 倍）；
运行场景左右栏全收，画布占满 1920。

## 与 v1 的主要差异

### 1. 运行控制从顶栏拆成独立运行条

- v1：14 个同权重图标挤在 36px 顶栏，运行/停止是最高风险动作却最小。
- v2：画布上方 48px 运行条：状态 + 编译 + 运行 split（运行一次 / 循环 / 从当前步骤）+ 暂停 + 单步 + 停止 + 快捷键提示。
- 停止在运行态是实心红；运行中禁用“编译/运行/循环”，故障时只保留“停止”可用。
- 顶栏因此腾出位置给场景切换与命令面板入口。

**理由**：把“编辑”和“执行”分成两个区域，降低误触；运行/停止有文字标签，不再靠猜图标。

### 2. 程序 + 流程栏合并为“流程导航”

- v1：程序列表固定 188 高，流程栏在下面；两者表达同一棵 `Solution → Flow → Steps`。
- v2：顶部 **2×2 流程胶囊条**（状态点 + 名称 + 步数），所有流程同屏；下面直接是当前流程的步骤树。
- 点击胶囊切换树、元信息与底部统计；禁用流程胶囊半透明/删除线，选中后树顶部显示“该流程已禁用”提示。
- 新建/流程管理收进导航面板的 `…` 菜单；188px 还给树。

**理由**：同一件事不再占两个面板头；树获得更多高度，长流程少滚动。

### 3. 右栏三列收成一个上下文检查器

- v1：属性 260 + 图层 240 + 工具箱 300，合计 800 常驻；流程编辑时属性还显示组态图元。
- v2：单列 320（组态 340），顶部页签 `属性 / 图层 / 工具箱 / 图元`，按场景收敛：
  - 调试：`步骤 / 工具箱`；
  - 组态：`属性 / 图层 / 图元`；
  - 自由：全部四项。
- `属性` 是上下文相关的：
  - 调试：选中步骤的参数（运行 / 输入 / 输出 / 参数 + 变量绑定 / 步骤参数）；
  - 组态：选中图元的外观 / 文本 / 布局 / 交互 / 事件。
- 未选中时显示“未选择对象”空态，而不是继续显示上一次的对象。

**理由**：检查器回答“我现在选中的东西是什么”，不是“系统里有哪些面板”；
收成一列后画布面积回来，且不会再出现“流程编辑时属性显示 SCADA 图元”的错位。

### 4. 底部日志改成可收起控制台

- v1：固定 200 高，画布永久损失约 20%。
- v2：默认 32px 抽屉头：三个页签 + 计数 + 最近一条摘要 + `…` + 展开箭头；展开 240。
- 故障自动展开；运行场景默认展开；点击页签也会展开。
- 日志“清空”后显示空态；监控“清空”后显示空态。

**理由**：日志大部分时间是空的；画布是主工作区。摘要让收起时仍能看到最后一条，
故障自动展开保证“出问题不用手动找日志”。

#### 4.1 增补提案：抽屉头三方案（2026-10-26，未确认）

本节 §4 在 WPF 落地时只做成了 `DockHeight` 的 32 ↔ 240 切换（`LayoutHelper.ToggleConsole`）：
没有计数、没有最近一条摘要、没有展开箭头，也没有故障自动展开；底部页签里「设备状态」是空壳
（`Panel_DeviceStateView` 无内容、未登记 `ContentFactories`），而「日志信息」与状态栏「控制台」
本就是同一块面板的两个名字。

提案稿 `design-bottom-console.html`（自包含，浏览器直接打开；顶部可切换方案）给出现状对照 + 三个方案：

| 方案 | 收起态（32px） | 故障时 | 适用 |
| --- | --- | --- | --- |
| 现状对照 | 只有页签条（日志信息 / 监控栏 / 设备状态） | 无反应 | 仅作对照，不复刻 |
| **摘要头（推荐）** | 页签 + 计数 + 最近一条摘要 + 展开箭头 | 自动展开到 240，页签栏出红色计数徽标 | 默认 |
| 双栏常驻 | 展开后日志与监控同屏（日志为主 + 监控 236 右侧栏），不再切页签 | 自动展开 | 调试时要同时看“值”和“事件” |
| 静默提示 | 同摘要头 | 只加红色计数徽标与页签栏左侧红边，不抢画面 | 运行 / 演示时不希望被打断 |

三个方案共同的三处清理：

1. 页签「日志信息」改名「控制台」，与状态栏按钮、视图菜单统一（`UIThemeSmokeTest` 已有“控制台必须出现在菜单 Header”的断言）。
2. 删「设备状态」页签与对应菜单项；设备在线信息按 §5 归运行驾驶舱 KPI 卡。
3. 删视图菜单里 `Panel_DataView` / `Panel_ModuleOutView` 两个死入口（这两个 ContentId 已不在 `Shell.xaml`，点击静默无反应，只保留在 `LegacyContentIdMap` 供旧布局迁移）。

确认前不得改 WPF（R127）；选定方案后按 §30.1 第 ③ 步复刻，并把本文件升版本、同步映射表。

### 5. 运行驾驶舱

- 全宽深色：顶条 `运行中 + 节拍 + OK/NG + 停止运行`；图像区；底部 4 张 KPI 卡（节拍 / 良率 / 设备在线 / 未确认报警）。
- 底部控制台和状态栏在运行场景同步转深色，形成完整驾驶舱；运行场景只保留“控制台”页签，
  监控/设备页签回到调试/自由场景查看（设备在线信息已在 KPI 卡里）。
- 故障态：`运行中` 变红、告警卡变 1、右上角通知、日志错误行红色。

**理由**：车间暗光环境与“操作员视角”需要更高的对比和更少的分心；
深色只覆盖运行场景，不影响编辑场景的浅色工作区。

### 6. 流程画布：选择语法与焦点

- 选中节点：2px 外框 + 8 个手柄（与组态图元同一套选择语法）。
- 节点左侧 3px 状态条：运行蓝 / 成功绿 / 失败红，不再只靠 1.5px 边框。
- 工具条新增“焦点”：当前路径高亮，非当前节点降到 30% 透明度。
- 画布内容按 1.18 放大，填满 v2 更宽的中央区。
- 逻辑判断容器：靛蓝 IF 徽标 + 条件表达式 pill（`Score ≥ 0.85`）+ 两条分支卡
  （OK / Else 徽标、算子数、状态点）；分支内的算子与流程树一致
  （分支 1 `变量赋值_0` / 分支 2 `报警输出_0`）。
- 项目真实逻辑算子（逻辑运算 6 种、数值比较 6 种、If / 分支匹配 / While / For / 并行分组 / 等待等）
  的流程栏 + 画布设计见 `../flow-logic/`；本页只展示流程画布中的一处 IF 容器。
  通用门电路参考库在 `../logic-operators/`（安全回路备用，不是本期基线）。

**理由**：20 个节点时边框色很难扫；调试时用户只关心“现在走到哪”。
焦点是开关，默认关，不会丢上下文。

### 7. 组态：格式工具跟着选中对象走

- v1：主格式栏 20+ 个按钮常驻，没选中时全是灰的。
- v2：主格式栏隐藏；选中图元时在选中框上方浮出 34px 上下文工具条（左/中/右对齐、置顶/上移、`…`）。
- `…` 打开完整排列菜单（分布 / 等尺寸 / 等间距 / 对齐网格 / 叠放次序）。
- 点击页面空白：取消选中，工具条收起，检查器显示“未选择对象”；点击泵恢复。

**理由**：工具和对象在同一视线内；没选中时不再占一排视觉噪音。

### 8. 命令面板（Ctrl+K）

- 顶栏搜索入口 + `Ctrl+K`；分组：最近使用 / 流程 / 视图与命令。
- 输入过滤；上下键移动、Enter 执行、Esc 关闭；没有结果时显示空态；空分组自动隐藏。
- 可执行：切换场景、切换流程、打开工具箱、展开/收起控制台、打开图层。
- 算子项会把名称填入检查器搜索框，完成“搜索即定位”。

**理由**：42 个算子还会继续增长，右侧长列表不适合熟练用户；
命令面板同时覆盖“找算子 / 找流程 / 找命令”，比三层菜单快。

### 9. 字体、行高与状态栏

- 字体刻度统一为 **11 / 12 / 13 / 15 / 20**，最小 11；不再出现 9.5/10.5 的中文小字。
- 行高：日志/监视 28、图层/工具箱 32、属性行 32、树算子 40。
- 状态栏从“CPU/内存/线程/句柄”改为健康条：
  `运行状态 | 节拍 | OK | NG | 告警 | 方案 | 当前用户`；
  系统资源收进右侧“系统”悬浮卡。
- 运行场景状态栏与驾驶舱同深色。

**理由**：操作员先看生产健康，工程师才看资源；资源不是消失，只是降级到 hover。

### 10. 菜单与术语

- 术语统一：`程序 / 流程栏` → `流程导航`；`流程设计器` → `流程画布`；`模块参数` → `步骤参数`；
  `日志信息` → `控制台`；`属性` → `检查器`（菜单入口）。
- 占位菜单项（截屏 / 报表查询 / 数据栏 / 模块输出 / 激活 / 建议及反馈 / 关于）标为
  `未实现` 并禁用，不再让用户点了没反应。
- 面板头的 3 个 22px 小图标收成一个 `…` 菜单（24px），减少微小点击目标。

**理由**：同一个概念只留一个词；菜单里长期挂着死项会消耗信任。

### 11. 空 / 加载 / 错误态

- 图像空态（已有）。
- 控制台清空空态、监控清空空态、工具箱搜索无结果、命令面板无结果、检查器未选中。
- 错误：故障态通知 + 日志错误行 + 组态/流程的红色状态。
- 加载：组件附录保留骨架屏样例；运行驾驶舱的连接中状态留给下一批（需要真实设备状态源）。

### 12. 流程导航与画布视觉（按 `../flow-logic/` 整合）

- 去掉重复的“程序”面板：流程胶囊条 + 当前流程树占满左栏，和 `flow-logic` 的流程导航一致。
- 流程树：容器组头用**类型色 + 类型徽标（IF / PAR）+ 名称 + 分支/算子计数 + 状态点**；分支行改成浅色胶囊 + 左侧 2px 类型色条；算子行用分类色图标块 + 两行名称；分支内部步骤默认收起，点击分支行展开。
- 画布节点：左侧 3px 分类色身份条 + 分类色图标块；分类色取 `ToolboxCategoryVisuals`（图像采集灰、模板匹配橙、卡尺琥珀、变量赋值青、结果上报灰蓝、等待靛蓝）。
- 画布容器：IF 组头用靛蓝类型色 + 条件胶囊 + 分支计数；泳道用浅靛蓝底；数据线改蓝实线、顺序链改灰虚线。
- 参考页：`../flow-logic/design.html`；本页只保留 Shell 的布局、模式隔离与停靠逻辑，流程/画布视觉以 flow-logic 为准。

## 实现取舍

1. **场景化 vs 自由停靠**：默认三场景是“布局预设 + 自动收敛”，不是另造一套布局系统；
   `自由` 保留 v1 式左/中/右三栏与全部检查器页签，作为逃生口。
   代价是用户不能再“同时看到属性、图层、工具箱”三列——需要时用自由布局或页签切换。
2. **单列检查器**：320/340 宽；属性行标签列 58。WPF 侧若坚持 260 最小宽度，需要把
   输入框/单位排成两行；本基线按 320 设计，复刻时不要为了 260 把标签列压到 48。
3. **控制台抽屉**：32/240 两档，故障自动展开；WPF 的 AvalonDock 底栏需要保存“展开/收起”状态，
   但不要把它写进 `Layout.xml` 的结构版本（R43 的触发条件是面板归属，不是高度）。
4. **运行驾驶舱**：用同一份 `ImageView` 加顶条/KPI 条，不新造一个图像控件；
   WPF 可做一个“运行文档”承载同样的布局，图像仍是 `ImageGallery`。
5. **命令面板**：Web 用固定遮罩 + 640 卡片；WPF 需要新弹窗或 OverlayHost 面板，
   `Ctrl+K` 必须与现有快捷键（F5/F9/F10）不冲突。搜索只做“定位/切换”，不做参数编辑。
6. **组态上下文工具条**：Web 用绝对定位在选中框上方；WPF 可用 `Popup` / `Adorner`。
   主格式栏隐藏后，完整命令进 `…` 菜单；如果现场更习惯常驻格式栏，可保留主栏但默认折叠
   （需要另一次设计决策，不在本版）。
7. **流程画布 1.18 放大**：这是为了填满 v2 更宽的中央区，不是固定缩放值；
   WPF 的 `NodifyEditor` 有真实缩放/平移，复刻时以“节点可读、画布不空”为准，不写死 1.18。
8. **深色只覆盖运行场景**：完整 Shell 深色主题不在本版；运行驾驶舱的深色令牌独立，
   不与浅色 `Dialog*` 混用。下一步若做全局深色，应复用 `RunCockpit*` 还是另起 `Dark*`，需单独评审。
9. **菜单死项**：选择“标未实现 + 禁用”，而不是删除；保留信息架构，同时让用户知道边界。
10. **演示条与状态附录**：右下角“演示控制”和页面下方“Shell 组件与状态”不属于设计稿，
    不进入 WPF 复刻范围。

## 已知偏差（复刻时按 R130 记录）

1. **字体度量**：Web 用 Segoe UI Variable / Microsoft YaHei UI；WPF 用 Microsoft YaHei。
   字号刻度已统一到 11/12/13/15/20，但同字号字宽/行高仍有差异。
2. **滚动条**：Web 10px 覆盖式；WPF 约 17px 占位。检查器 320 宽在 WPF 下可用宽度会少约 17px。
3. **布局断点**：Web 在视口 ≤1500 时把导航/检查器收窄到 280/300；WPF 需要按窗口宽度做同样的
   收敛，否则 1280 窗口下三栏会挤。
4. **阴影**：Web 应用外框/弹层有两层柔和阴影；WPF 面板无窗口级阴影，保留 1px 描边。
5. **动效**：Web 120–180ms `ease`；WPF 150ms `CubicEase`；运行脉冲实现不同。
6. **图标**：Web 是 1.6–1.8px 描边 SVG；WPF 是 Font Awesome Solid，视觉重量不同。
7. **焦点态**：Web `:focus-visible` 2px 主色环；WPF 显式模板必须补 `DialogFocusVisual`（R135）。
8. **表格列宽**：Web 可伸缩；WPF `GridView` 无星号列宽，需按基线固定值分配。
9. **组态上下文工具条**：Web 绝对定位；WPF `Popup` 在缩放/平移画布上需要换算到屏幕坐标，
   并处理画布裁剪；这是复刻时的主要技术风险。
10. **命令面板**：Web 的 `Ctrl+K` 与浏览器地址栏/搜索可能冲突；WPF 里要确认不与现有
    `Ctrl+1..4`、F5/F9/F10 冲突。Web 侧 `Ctrl+1..4` 也可能被浏览器标签切换拦截，
    所以顶栏分段按钮是主入口，快捷键是增强。
11. **运行场景深色**：仅驾驶舱/控制台/状态栏；主窗口标题栏仍是浅色。这是刻意的“壳浅、舱深”，
    不是漏改。
12. **流程导航**：v1 的程序右键菜单在 v2 原型里没有完整复刻（流程胶囊条 + 面板 `…` 菜单替代）；
    WPF 复刻时若保留右键菜单，应挂在流程胶囊条/导航面板上，不要恢复独立的程序面板。
13. **组态检查器不做「图层」下拉**：设计稿的「基本」组是 `名称 / 类型 / 图层`，WPF 只做前两项
    （2026-10-20 用户裁定）。图层归属已经是画布右键菜单里的动作，再在面板放一份就是"一个东西两个入口"，
    用户迟早会怀疑两处不同步（与 `ShowGrid`/`SnapToGrid` 不进面板同一条口径）。
    另外「类型」行的取值用 `TypeKey`（如 `Hmi.Button`）而不是设计稿里的 CLR 类名 `PumpElement`——
    `TypeKey` 才是写进 `.vms` 的长期标识，CLR 类名会随重构变。落地记录见
    `docs/code-changes/2026-10-20-SCADA属性面板对齐设计基线（组名与类型只读行）.md`。
14. **组态检查器对象头**：设计稿是「图标 + 名称 + 类型·图层 + 绑定按钮」，WPF 做成「图标 + 名称 + 类型键 + 锁定」。
    三处偏差各有原因：① **没有图层段**——与第 13 条同一个决定；② **没有对象级绑定按钮**——本仓的绑定是
    按属性挂的（每行一个 ƒx），没有"整个对象绑一个变量"这个概念，硬加只会弹"还没接"；
    ③ **图标不按图元类型换**——图元库没有图标资产（工具箱也只有名字 + 类型键），现造"类型→码点"映射表
    加一类图元就要多记一处，而图标在这里只是对象头的视觉锚点。落地记录见
    `docs/code-changes/2026-10-20-SCADA属性面板对象头与搜索（批次C）.md`。
