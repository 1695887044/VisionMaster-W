## 1. 现状

`app-shell` v2 已定义驾驶舱的**结构**（全宽深色 + 顶条 + 图像 + 4 张 KPI 卡），且 `RunCockpitView.xaml` 已实现（209 行、`hex=0`）。缺的是**状态设计**：当前四个 KPI 卡全是 `—` + "待接入 XX"，没有任何"有数据时长什么样"的定义。

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | KPI 四卡永远是 `—` | `RunCockpitView.xaml:150-214`（`Text="—"` 硬编码） | 现场看不到任何生产数字，驾驶舱价值为零 |
| 2 | 顶条只有"状态 + 流程名 + 停止" | `:81-118` | 车间最关心的节拍/OK/NG 要低头看 KPI 卡，视线动线不合理 |
| 3 | 图像区无空态 | `:123-137`（直接塞 `ImageView`） | 无图时是一块纯深色方块，用户不知道是"没图"还是"坏了" |
| 4 | 无故障态 | — | 出故障时只有日志变红，驾驶舱本身毫无变化 |
| 5 | KPI 卡无语义色 | 四张卡长得一样 | 良率/报警与节拍/设备在线视觉同权 |
| 6 | 无帧信息 | — | 看不到帧号、分辨率、耗时，无法判断"这张图是哪一轮" |

## 2. 设计要点

### 2.1 三个场景必须都定义

| 场景 | 何时出现 | 关键差异 |
| --- | --- | --- |
| **运行中（有数据）** | 统计源已接入 | KPI 显示真实数字 + 左侧语义色条；图像区显示画面 + OK/NG 结果章 + 帧信息 |
| **待接入（现状）** | 统计源未接入 | KPI 显示 `—` + 一行说明；图像区显示空态引导 |
| **故障** | 流程异常/设备离线 | 状态灯变红并闪烁；顶条下方浮出告警条；相关 KPI 降级为 `—` 并说明原因 |

**"待接入"必须是显式状态，不能靠 `—` 蒙混。** 现状四个 `—` 没有任何解释，现场无法判断是"没接"还是"接坏了"。设计稿给每张卡一行 `待接入 XX` 说明，与故障态的 `故障中无统计` 区分开。

### 2.2 顶条（56px）：把生产健康提到最上面

```text
● 循环运行中   [主检测]      节拍 1.28s   OK 1485   NG 12          [■ 停止运行]
```

- **状态**：10px 圆点 + 18px 粗体状态字。运行中=绿、故障=红（闪烁）、待机=灰。
- **在跑流程**：蓝底蓝字小胶囊，最多 150px 省略号；多条并跑时并排。
- **中段三指标**（**本版新增**）：节拍 / OK / NG，10px 标签 + 15px 等宽数字。
  - 理由：这三个是车间抬头就看的数，放顶条比放 KPI 卡更符合视线动线；KPI 卡留给"需要看趋势"的指标。
  - OK 绿、NG 红，节拍白。
- **停止按钮**：38px 高、132px 最小宽、14px 粗体、红实底。与现状一致（`CockpitStopButton`）。

### 2.3 图像区

| 元素 | 位置 | 说明 |
| --- | --- | --- |
| 画面 | 铺满 | `ImageView`（`ImageGallery` 宿主），不复制渲染链路 |
| **OK/NG 结果章** | 右上角 | 13px 粗体 + 语义色底 + 1px 描边；绿=OK、红=NG |
| **帧信息** | 左下角 | 等宽 10.5px：`帧 #014985 · 2448×2048 · 128 ms` |
| 空态 | 居中 | 40px 图标 + "等待图像" + 一句引导 |

结果章与帧信息都是**覆盖层**，不挤占图像面积。

### 2.4 KPI 条（96px，4 卡）

每张卡：`3px 左侧语义色条 | 11px 标签 / 24px 等宽数值 / 10.5px 说明`。

| 卡 | 语义色 | 有数据示例 | 说明行 |
| --- | --- | --- | --- |
| 节拍 | 蓝 `--run-blue` | `1.28 s` | 最近 100 帧均值 |
| 良率 | 绿 `--run-green` | `99.2 %` | 1485 OK / 12 NG |
| 设备在线 | 蓝 | `3 / 3` | 相机 2 · PLC 1 |
| 未确认报警 | 琥珀 `--run-amber` | `1` | 最早 19:02:47 |

- **左侧 3px 色条只在有真实数据时出现**；待接入态用 `--run-border` 灰条。
- **说明行是必需项**：它同时承担"这个数怎么算的"与"为什么是 —"两种解释。
- 数值 24px 等宽 `tabular-nums`，四卡纵向对齐。

### 2.5 故障态

1. 状态灯：绿 → **红**，加 4px 18% 红色外环，`1s steps(2)` 闪烁。
2. 状态字：`循环运行中` → **`运行故障`**（红色）。
3. **顶条下方浮出告警条**：`⚠ 相机 camera-02 取图超时（500 ms），流程已暂停` + 右侧时间戳（等宽 10.5px 灰）。
4. KPI 降级：节拍 → `—` + `故障中无统计`；设备在线 → `2 / 3` + `（camera-02 离线）`。
5. 停止按钮**保持可用**（故障时最需要的动作）。

告警条只显示**最新一条**；完整历史在控制台。多条并发故障时显示最新一条 + 右侧 `+2` 计数。

## 4. 复刻约束

1. **不改 `ImageView`**：图像区继续用 `<views:ImageView />`，不复制图像渲染链路（`app-shell` README 已明确此取舍）。
2. **不改命令**：停止按钮继续绑 `ExecutionCommand` + `CommandParameter="{x:Static local:ExecutionAction.Stop}"`。
3. **不改状态源**：`RunStateBrush` / `RunStateText` / `RunBarFlowText` / `RunBarFlowToolTip` 四个绑定保留。**新增的节拍/OK/NG 需要新数据源**——见 §6。
4. **深色只覆盖驾驶舱**：不扩散到其它场景（`app-shell` 已裁定"壳浅、舱深"）。
5. **`hex=0` 保持**：现状已是 0，改版后必须仍为 0（R140）。
6. **图标按钮 `Padding="0"`**（R68）：停止按钮有文字标签不是图标按钮，但若加"设置"齿轮按钮需注意。
7. **不造死按钮**：不新增"暂停""单步""复位计数"等需要新命令的按钮。

## 5. 已知偏差（Web vs WPF，预判）

1. **字体度量**：18px 状态字在 WPF 微软雅黑下比 Web 略宽；顶条 56px 在 1280 宽下需确认三个指标 + 流程胶囊不挤压。
2. **闪烁动画**：Web 用 `steps(2, start)`；WPF 用 `Storyboard` + `DoubleAnimation`（`AutoReverse`），或 `DiscreteObjectKeyFrame` 精确复刻台阶感。
3. **网格底纹**：Web 用两层 `repeating-linear-gradient`；WPF 用 `DrawingBrush` + `TileMode="Tile"`，40px 网格。
4. **ROI 标注框**：Web 是绝对定位 `div`；WPF 是 HALCON 画布上的 drawing object，**`RenderTargetBitmap` 捕获不到 `HwndHost`**——证据图里图像区会是空的，这是已知边界。
5. **结果章描边**：Web `border` 在圆角处会有抗锯齿差异；WPF `Border` 1px 描边需 `SnapsToDevicePixels`。
6. **阴影**：Web 驾驶舱外框有 `0 18px 48px` 大阴影（设计稿外壳，不进产品）；WPF 无窗口阴影。

## 6. 未纳入本版 / 待确认

| 项 | 原因 |
| --- | --- |
| **节拍 / OK / NG / 良率 / 设备在线 / 未确认报警的数据源** | 这是本设计的**最大前置条件**：现状 `RunCockpitView.xaml:139` 注释明确"当前没有运行统计源，先显示待接入，不伪造生产数字"。设计稿定义了"有数据时长什么样"，但**不新增任何统计契约**——需要单独决策：统计在 `IRuntimeManager` 里累计？还是新增 `IProductionStatistics` 服务？ |
| 帧信息（帧号/分辨率/耗时） | 需要 `ImageView` 或运行会话暴露当前帧元数据 |
| OK/NG 结果章 | 需要流程输出 `Result` 的汇总口径 |
| 告警条 | 需要"最新一条报警"的订阅通道 |
| 历史帧回看 / 暂停画面 | 需要图像缓冲与新命令 |
| 驾驶舱深色扩展到全应用 | `app-shell` 已裁定本版不做 |

> **建议的实施顺序**：先做**纯视觉部分**（顶条中段三指标的占位、图像空态、结果章、帧信息的占位、故障态告警条样式、KPI 语义色条），这些不依赖新数据源，可以把"待接入"从一个裸 `—` 变成一句有解释的状态；统计源接入作为独立批次，届时只换绑定不改布局。
