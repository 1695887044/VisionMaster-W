WPF 复刻

全部落在现有 `ProcessView.xaml` / `FlowCanvasView.xaml` 上，不新造一套画布系统。

设计元素现有实现建议改动约束
流程栏容器组头 ProcessView.xaml 的 ConditionStep / WhileStep / ForStep / ParallelStep / CaseStep 模板 统一为“类型色条 + 类型徽标 + 名称 + 条件胶囊 + 分支/算子计数 + 状态点”的一行结构；If 从灰色改为靛蓝。 R23：新增 StepModel 子类必须补 DataType 模板
分支行 StepCollection 模板；DisplayName 已拼好“分支名 + 条件” 分支行做成带浅色底的胶囊；左侧分支徽标、右侧计数；缺条件统一红边红字。 R24：分支文案只认 DisplayName，不要再挂 Expression
流程栏选中 / 运行态 ModernStepContainerStyle + 行模板 DataTrigger 选中用 3px 蓝条 + 淡蓝底；运行中的分支用蓝点脉冲；失败/跳过/禁用沿用现有语义色。 R25：分支卡片不进“按选中项执行”的命令链
画布节点 FlowCanvasView.xaml 的 StepNodeTemplate（210×62） 保持尺寸与端口锚点；把图标块、标题、插件名、操作徽标、耗时/状态点做成统一槽位；分类色取 ToolboxCategoryVisuals。 不要改 NodeWidth/NodeHeight，否则连线锚点要重算
逻辑运算 / 数值比较节点 同一个插件类 + InputPort<枚举> 选择操作 不要为 AND/OR/XOR 各建 StepModel；用节点右上角的 node-op 徽标显示当前操作模式。 枚举显示名走 R40；值仍是成员名
容器框 ContainerNodeTemplate（LaneWidth/LaneHeight 由子孙外接框算出） 组头 46px：类型色条 + 徽标 + 名称 + 条件胶囊 + 计数 + 状态；框体用类型色淡底，不刷大面积高饱和色。 容器框仍由几何计算，不要改成固定尺寸
泳道 LaneNodeTemplate（CanvasNodeKind.Lane） 泳道头 28px：分支徽标 + 分支名 + 计数；If/Else 用不同底色；并行运行中的泳道单独蓝边。 R76：子图元坐标不改成相对坐标
连线 ModuleLinkTemplate 的 StepConnection；数据线 / 顺序链 / 非法线 数据线蓝实线、顺序链灰虚线、非法线红虚线；正交折线；箭头用 Fill 填充。 右键菜单不能改成共享资源，否则样式触发器被本地值压掉
状态与动画 DataTrigger + Storyboard（流程栏/画布已有运行脉冲） 统一“绿=成功、蓝=运行、红=失败、灰=跳过/待机”；容器运行脉冲只给状态点，不给整框。 不要用 CSS 式滤镜/混合模式；只用 WPF 原生 Brush/Effect
检查器 现有属性面板 / FlatPropertyGrid 并行分组用草稿类 + FlatPropertyGrid：执行模式、失败聚合、汇合超时；分支列表只读展示，结构动作留在流程栏右键。 R26：参数动作与结构动作分工
分类色 ToolboxCategoryVisuals.cs 的 13 条分类色 直接复用：逻辑控制 #6366F1、逻辑判断 #8B5CF6、变量操作 #14B8A6、图像处理 #3B82F6、缺陷 #EF4444、测量 #F59E0B、定位 #F97316、运动 #65A30D、数据处理 #64748B。 不要在每个插件模板里硬编码颜色
容器类型色 现有 If 灰 / While 橙 / For 绿 / Parallel 蓝 / Case 青 收敛为：If 靛蓝、Case 紫、While 琥珀、For 翠绿、Parallel 天蓝；只用于容器组头与边框，不覆盖叶子的分类色。 类型色与分类色是两个维度，别混用

复刻边界：真实算子是 ActionStep + 插件；逻辑运算 / 数值比较的“操作模式”是插件端口枚举，不是不同节点类。 逻辑容器是 ConditionStep / WhileStep / ForStep / CaseStep / ParallelStep，分支是 StepCollection。 因此这套设计不需要新增 StepModel 子类，也不需要把 AND/OR/XOR 拆成三种节点。
