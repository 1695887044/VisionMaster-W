0 · 结论

能用的地方：悬停提亮用的是"叠一层白"而不是改填充色，这个思路是对的——填充色可能是用户配的、也可能来自变量绑定，不该被样式覆盖。

主要缺口：没有按下反馈、没有键盘焦点环、禁用态仍是手型且整体半透明、没有危险动作变体。 前两条在触摸屏 + 戴手套的场景是"操作员不确定点没点到"，后两条关系到误操作与可读性。

全部改动都落在主题模板内，不动模型、不动属性契约、不改落盘格式。

2 · 审查发现

级别问题为什么是问题 / Web 惯例建议
P1 没有按下反馈（模板注释写明"IsPressed 用不了"） Web 里 :active 是硬要求：按下瞬间位移 1px 或变暗 8%。触摸屏上如果没有反馈，操作员会连点两三次 按下：下移 1px + 底色再暗一档（不改用户填充色，用叠加层）
P1 没有键盘焦点环（Focusable=True 但模板无 IsKeyboardFocused 触发器） Tab 到按钮上完全看不出来，等于键盘导航不可用；与 R135"焦点必须可见"同一条纪律 2px 外环（品牌青）+ 1px 内描边，只在键盘聚焦时显示（鼠标点击不显示）
P1 没有危险动作变体 急停、复位、清报警与"启动"长得一模一样；Web 里 danger 按钮是独立变体 加 Danger 属性（红底/红边），由属性面板勾选；只影响外观
P1 没有最小可点尺寸 按钮尺寸由用户拉，可能只有 20px 高；触摸屏推荐 ≥ 44px 命中区（Web 无障碍 44×44） MinHeight=36（触摸场景由属性面板给 44），不影响已配好的大按钮
P2 禁用态仍是手型光标，且整体 50% 透明 手型 = "能点"的承诺；50% 透明会让深色底上的文字几乎不可读。Web 用 cursor:not-allowed + 降饱和但保文字对比 禁用：Cursor=Arrow、填充降饱和、文字保持 ~70% 对比度
P2 悬停反馈强度取决于用户配色（白色 12% 叠加） 浅色填充上几乎看不出，深色填充上很明显——同一套样式在不同工程里表现不一致 悬停同时提亮边框（固定色），叠加层保持 8~10%
P2 没有忙碌/进行中态 启动流程要几秒，期间按钮无反馈，操作员会反复点（Web 用 disabled + spinner） 运行态执行动作期间显示 12px 圆环并吞掉点击
P2 文字贴边、无行高 Padding 由用户配，长文案换行时上下贴边（与 R184 同族）；Web 用 padding + line-height 保证呼吸 模板给 TextBlock 加 LineHeight 与 2px 上下余量
P3 圆角 6 与全局卡片 8 不一致 同一屏上按钮与面板圆角不同，观感"没对齐" 圆角走令牌（默认 8），已有工程保持原值
P3 无 ToolTip 兜底 长按钮名被截断时没有提示 运行态若文字被裁剪，自动挂 ToolTip（只读提示，不改文案）

5 · 只改主题，不动契约

改动落点不影响
按下 / 悬停 / 禁用 / 焦点 四态ButtonElement.xaml 模板触发器模型、属性袋、落盘
Danger 属性新增 [ScadaProperty] 布尔项（默认 false）老工程读不到该键 → 默认普通样式
忙碌态运行态分发器执行动作期间置位（只读 DP）动作语义、审计
最小尺寸样式 MinHeight/MinWidth已配好的大按钮尺寸
不做：渐变动画、阴影扩散、圆角动画。工业触摸屏上一律 150ms 以内、只做位移/明暗， 长时间运行的动画会烧 GPU 且在现场显得"软件卡了"。

6 · 待裁定（4 条）

Q1 Danger 是否要做成"自动"——动作类型是危险动作（启停流程/轴运动/应用配方）时自动红？还是只由人工勾选？

Q2 最小高度取 36（本稿）还是 44（触摸标准）？

Q3 忙碌态是否显示"执行中…"文字（会改掉按钮文案），还是只加圆环？

Q4 焦点环颜色用品牌青 #38BDF8 还是与报警区分度更高的琥珀？
