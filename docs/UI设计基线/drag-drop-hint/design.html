01问题：卡片说了"是什么"，没说"落到哪"

现有 v2 拖拽卡片回答的是身份——拖的是什么算子、属于哪一类。但用户在画布上真正拿不准的是落点：

  • 画布是扁平全深度渲染，一个并行分组里有几条分支、分支里还有容器，肉眼看到的"空白处"未必是顶层空白；
  • 落点规则不直观：容器框内 → 落到该容器第一条分支末尾；其余 → 按节点中心 Y 插进顶层序列；
  • 落到容器框边缘时，用户无法预判是"进容器"还是"插在容器旁边"。

当前实现把库自带的英文浮层（Copy to）关掉了，于是完全没有落点反馈——比英文更糟。 本稿补的就是这一层。

目标用一行字回答"落到哪"；非法落点说清为什么；不遮挡卡片、不挡鼠标。
非目标不改落点规则本身，不改卡片视觉（v2 基线冻结），不新增第二套配色。

02模型：两个浮层，各答一个问题

卡片（v2，已实现）跟着光标走，回答是什么；提示条（本稿新增）跟在卡片正下方，回答落到哪。 两者左缘对齐、纵向间隔 6px，视觉上是一组，语义上互不覆盖。

为什么不做成"卡片里加第三行"：卡片由拖拽源驱动（只知道拖的是什么），落点由放置端决定。 塞进卡片就必须在两个 VM 之间共享一份"当前落点"状态，多一处同步面； 而 gong 本来就有 EffectText / DestinationText 与独立的 EffectAdornerTranslation，提示条是它天然的位置（见 §07）。

04文案规则

一条公式：[动词] 「名称」→ [路径] · [位置]。动词由拖拽效果决定，不由拖拽源写死。

场景模板示例
工具箱 → 顶层 添加「{名称}」→ 主流程 · 末尾 添加「图像采集」→ 主流程 · 末尾
工具箱 → 容器内 添加「{名称}」→ {容器} / {分支} · 末尾 添加「图像采集」→ 并行组 / 分支 2 · 末尾
画布内移动 移动「{名称}」→ {路径} · 末尾 移动「模板匹配」→ 判断 / 成功分支 · 末尾
插到两步之间 {动词}「{名称}」→ {路径} · 插到「{目标}」之前 添加「图像采集」→ 主流程 · 插到「模板匹配」之前
深层嵌套（≥3 级） 保留末两级，前缀省略为 … / 移动「模板匹配」→ … / 并行组 / 分支 2 · 末尾
非法落点 不能放这里：{原因} 不能放这里：Break 只能放在循环里
落点是自己/自己的子孙 不能放这里：不能放进自己里面 不能放这里：不能放进自己里面
运行中 运行中不能编辑 运行中不能编辑

文案纪律

  • 动词只认拖拽效果：Copy → 添加；Move → 移动。画布内拖动一律 Move，即使只是同层换位。
  • 「主流程」是顶层的位置名，不是流程名。流程名在标签栏上已经有了，这里重复一遍只会挤掉真正需要的信息。
  • 非法原因必须可执行：「不能放这里」后面必须跟"怎么才能放"，不能只写"不支持"。
  • 不写英文、不写枚举名：ParallelStep / BranchType.Else 这类一律不上屏。
  • 名称超长：截断名称，不截断路径尾部（叶子信息优先）。

06交互细节

  • 跟随：提示条与卡片同帧跟随光标；两者用同一份指针偏移的纵向累加，不各自插值，避免"卡片到了、提示条还在路上"。
  • 落点切换：只换文字与状态色，不做位移/缩放。快速划过多个容器时，位移会让人误判落点。
  • 出现 / 消失：出现 120ms 淡入 + 2px 下移；消失 90ms 淡出。无落点时整条收起，不留一条空底色。
  • 文本变化：不淡入淡出，直接替换。切换动画会让"落点已变"这件事显得比实际慢半拍。
  • 不做脉冲/呼吸：拖拽过程中光标附近已经有卡片 + 提示条两个物体，再加动效会干扰对落点的判断。
  • 禁止光标遮挡：提示条左缘与光标保持 16px，箭头不压文字。
  • 高 DPI：全部用 DIP；26 高在 125% 下是 32.5 物理像素，不做像素对齐修正（与卡片一致）。

08已确认事项与已知偏差

用户已拍板（2026-10-24）

  • 动词：「添加 / 移动」。
  • 路径分隔符：/。
  • 状态 ③（会展开折叠分组）：做。

已知偏差（R130）

  • WPF 无"下移"动效：本稿 120ms 淡入 + 2px 下移；WPF 只复刻 Fade（与 v2 卡片同一处理）。
  • 字体度量：本稿用系统 UI 字体，WPF 用应用默认字体，340px 上限的截断点可能差 1~2 字符。
  • 两个浮层合成一个 adorner 承载：gong 4.0.0 没有 5 态的可定制浮层钩子 （内置 DropHintState 只有 None/Active/Error 三态，且模板 DataContext 只有 HintText + HintState），要表达"需注意/锁定"两档就得自己写 adorner。 故复刻时把提示条与卡片放进同一个拖拽 adorner 模板里（纵向 StackPanel）， 视觉与位置和本稿完全一致，只是不再由两个独立 adorner 承载。 代价：落点状态要经一个单写者的临时状态对象传给模板（见 README「实现形态」）。
  • 画布内部拖节点不在覆盖范围：那条路径用的是视图自己的 Popup，不是 gong adorner； 本稿只覆盖"工具箱 → 流程栏 / 画布"。
