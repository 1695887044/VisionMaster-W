01运行态演示

三个典型场景：设备状态（纯文本）、OK/NG（图片+文本）、工位模式（位号 + 图文）。

HMI 运行画面 · 状态视图

拖动滑杆 / 改值，立即匹配
匹配口径： 位 = 0/1 精确匹配；位号 = 变量值必须恰好一位为 1（value == 1 << bit），两位同时置位按“未匹配”走回退； 范围 = 包含起止值的第一个区间。匹配不到一律显示 DefaultText，不猜、不显示空白。

口径

实现前必须定死
  • 方案级共享：状态列表存在 ScadaDocument.StateLists，控件只存稳定 StateListId；名字只做显示与旧数据兜底。
  • 一个 TypeKey：Hmi.StateView。不新建图形开关/图形 IO 域/字指示灯三个类——它们只是“呈现方式 + 列表模式”的不同组合。
  • 三种模式：位（2 条）、位号（0~31 位）、范围（起止值）。
  • 三种呈现：文本 / 图片 / 图文；图片走方案 Image\ 相对路径。
  • 回退可见：列表缺失、无匹配、图片缺失、绑定丢失各有明确状态，不静默显示空白。
  • 绑定丢失保留末值：与 IOField/ComboBox 同一口径，右上角橙点 + ToolTip 原因。

左边是方案里的列表，右边编辑条目；改动实时反映到上面的运行态预览。

状态列表

列表
管理器边界（v1）：只做列表增删改、模式切换、条目增删、文本/图片路径；不做导入导出、不做多语言分列、不做条目拖拽排序。 按钮/标签的静态标题不进列表；列表只服务于“同一个变量的一组状态”。 切换模式会按新模式重置条目（实现时先确认再重置）。图片选择复用属性面板的 ImageFile 选择器（复制进方案 Image\ + SHA-256 查重）。

04已定 / 待确认

已定

按这些实现
  • 方案级，不是页面级：同一套“设备状态”被多页引用，页面级会逼用户复制。
  • 稳定 ID + 名字兜底：控件存 StateListId；列表改名不打断引用，旧数据按名字找回。
  • 一个 TypeKey：Hmi.StateView；不新增图形开关/图形 IO/字指示灯三个类。
  • 图片走方案资产：只存相对路径，复用 SolutionAssetService 的复制/查重/缺失回退。
  • 回退文案可配：DefaultText 默认 —，不强制中文。
  • 绑定丢失保留末值：与现有 IOField/ComboBox 一致，不闪空。

待确认

实现前拍板
  • Q1 状态列表管理器放哪：SCADA 编辑器顶部“资源”菜单，还是属性面板行内“管理…”？
  • Q2 条目文本是否要支持多语言列（现在只一列）？若近期有出口需求，建议条目按语言存字典。
  • Q3 图片缺失时是否允许“保留上一次有效图”？本稿选择“不保留”，避免把旧状态当新状态。
  • Q4 范围重叠：只提示，还是拒绝保存？本稿选择提示。
  • Q5 是否允许一个 StateView 同时绑“文本列表”和“图形列表”两个不同列表？本稿不允许，保持一份列表一种模式。
