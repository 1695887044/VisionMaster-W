流程运行统计 · 底栏 KPI 与轮次记录 v1 草案

多流程 / 多工位同时运行时，节拍 / OK / NG 是每流程一份，一条全局数没有定义。 本稿演示三件事：① 底栏按「当前流程」显示，点「N 条在跑」看工位浮窗；② 每轮产出一条 FlowRoundResult，OK/NG 可下钻到步骤与原因；③ 复用现有系统变量底座， 把同一份统计开放给 SCADA / 上报 / 报表。设计媒介，不是交付物（R126）。

OK：业务判定通过 NG：业务判定不通过（不是技术故障） 未判定：没拿到判定 / 调试 / 跳过 线级：主流程汇总，不跨站求和 不计入：Home / End / 调试轮

每流程一行：状态 / 节拍 / OK / NG / 未判定 / 判定源 / 最近一轮；右侧是口径说明

口径（现场能解释）

  • 节拍：上一轮 FlowRunStarted → FlowRunCompleted；「全部」范围取瓶颈（在跑流程的最大值），不取平均。
  • OK / NG：只认业务判定；NG 不是步骤失败。判定表 NG 时步骤 Failed，卡尺/斑点 NG 时 Success 仍为 true。
  • 未判定：判定步骤没执行 / 没配置判定源 / 类型不符。单独一桶，不混进 NG。
  • 线级：串联线取主流程汇总（样例 CurrentResult），不把各站相加；并联独立工位才允许求和。
  • 不计入：Role=Home/End、调试轮、单次手动调试；子程序按工位计入（线级 OK/NG 仍只取主流程）。
同一件产品过多个工位时，跨站相加会重复计数；没有产品身份（SN/工单）时，只能做工位统计，不能算线级良率。

System.Flow.<流程名>.* 只读系统变量：从 FlowRoundResult 投影，供 SCADA / 脚本绑定；不落盘、确定性 Id、改名不丢。

① 复用现有系统变量底座

SystemVariableModel 只读派生、确定性 Guid、不落盘；SystemVariableHost 合并多提供方。已有 RecipeVariableCatalog 先例，不用另造一套。

② 复用引擎每轮事件

FlowRunStarted / FlowRunCompleted 每轮各一次，连续/单次都触发；SessionStateChanged 管运行/暂停/停止/故障。

③ SCADA 直接绑定

每个工位在 HMI 上绑 System.Flow.<工位>.CycleTimeMs / .OkCount，不用写插件、不用改画面逻辑。

④ 修掉一个现存问题

FlowInvoker 现在把“有步骤 Failed”当调用失败；判定表 NG 恰好 Fail，产品不良被报成调用故障。L2 用 Outcome 分开。

⑤ NG 与故障分离

判定表 NG 时步骤 Failed；卡尺/斑点 NG 时 Success=true。步骤状态语义不一致，所以判定必须显式声明，不能靠 Failed 猜。

⑥ KPI 可下钻

点 OK/NG 看到最近 N 轮的步骤、原因、图像、日志；没有记录的数字不可解释，也没法验收。

为什么不能把各工位 OK/NG 相加

拓扑线级结果底栏「全部」
串联（同一产品过站）主流程汇总 / 末站判定显示线级，不求和
并联（各自独立产品）各站求和有效可求和，需方案声明
无产品身份（SN/工单）只能做工位统计显示「N 条在跑」，OK/NG 分流程看

本轮设计边界（不做什么）

不自动插入结果输出步骤静默改用户流程图是红线级行为；旧方案 → Unknown + 编译警告
不跨站求和串联线线级取主流程汇总；并联求和需方案级声明
不把调试/骨架计入Home / End / 调试轮排除；子程序按工位计入
不把步骤 Failed 当 NG技术故障与产品不良分开；未判定单独一桶
v1 不改引擎契约先做系统变量 + 结果输出步骤；L2 再上 FlowRoundResult
L1 · 现在可做

系统变量 + 结果输出步骤

底栏有数、工位可绑 SCADA；不动引擎契约。旧方案用结果变量兼容；缺步骤 → 未判定。

L2 · 推荐

FlowRoundResult + 判定解析器

单一事实源；修 FlowInvoker 的 NG 当失败；底栏/SCADA/上报/报表共用；支持下钻。引擎契约增量，需 R12 评审。

L3 · 按需

Ledger + 线级拓扑 + 班次

追溯、良率、OEE、班次/工单报表。线级良率需要产品身份；写入必须异步，不能拖慢流程轮。

评审结论：结果输出步骤只是「判定来源之一」，不是统计核心；真正的完美方案是把「一轮」变成引擎一等对象（L2）。 底栏只做摘要 + 下钻；统计口径写进同一条记录，不再让底栏、SCADA、上报各算一套。
