1优化清单（逐条：现状 → 改法 → 为什么）来源：VisionMaster/Shell.xaml 实际结构

行号指向当前 VisionMaster/Shell.xaml。P0 = 会误导判断或浪费空间，建议本轮就改。

优先级位置现状改法理由
P0 状态栏方案路径
:1722-1730		 显示完整路径，MaxWidth=400 后截断成 …综合测试台（测试员版…（截图即如此） 左侧只显方案名，悬浮显示全路径 路径是"我在哪"的答案，但被截断后两头都没信息；100+ 字符挤在 26px 高的底栏里
P0 KPI 无数据
:1613-1680		 数据源未接入时绑 "—"，和真实值混排，看不出"是真的 0 还是没接入" 未接入用浅色 未接入 文案 + 虚线占位，不占读数位 节拍/OK/NG/告警是产线判断依据，"没有数"和"0"必须一眼分开
P0 底栏折叠按钮
:1770-1784		 只有一个 F0120 图标按钮，无文字、无状态 带文字的 ▁ 控制台，展开时箭头向上 底栏最重要的操作是"把控制台拉出来"，现在要靠猜图标
P1 竖线分隔符
:1613-1686		 每组之间用 TextBlock "|" 当分隔，9 条竖线，间距 4/6/8/10 混用 统一 1px 分隔块（14px 高），KPI 用 8px 内距的气泡 竖线本身是文字，会跟着字体基线漂移，且挤压 26px 高度里的横向空间
P1 底栏高度
:302		 26px，字号 12px，元素无内边距，鼠标命中区只有文字本身 28px + 24px 可点区域（.sb-item） 底栏里可点的东西不少（用户、方案、控制台），26px 下点哪都是"差一点"
P1 系统资源
:1785-1851		 CPU / MEM / THD / HND 四组常驻，占底栏近 1/3 宽，其中线程数、句柄数几乎没人看 常驻只留 CPU + MEM；THD/HND/GC 收进点击浮窗 诊断信息按需展开即可，常驻只留"会不会卡"的那两个数
P1 顶栏文件操作
:1194-1211		 新建/打开/保存三个纯图标按钮，紧挨着菜单，与"全局命令区"同权重 收进 ☰ 文件 菜单按钮（带文字）；顶栏只留模式 + 全局命令 + 身份 文件操作是低频，三者并排占了 100px+；菜单里本来就有这些命令
P1 顶栏模式切换
:1216-1244		 四个按钮只有选中色（LogicIf/For/While 三套色），没有快捷键提示 分段控件（灰底白块）+ 快捷键角标 ^1…^4 + 选中态右侧一行说明 模式是全局上下文，用户不知道 Ctrl+1..4 存在；三套颜色轮流亮反而像状态灯
P1 顶栏中央
:1278-1301		 居中只有"文件夹图标 + 方案名"，保存状态、路径无处安放 身份胶囊：方案名 + 保存态 ● 已保存/未保存 + 目录尾段，点击弹方案菜单 顶栏中央是视线落点，应该回答"我现在在编辑什么、存了没"
P2 问题清单
（新增）		 只在控制台日志里翻，编译错误/告警没有聚合入口 底栏右侧 2 错误 · 1 警告 胶囊，点开列表可定位 把"哪里坏了"从翻日志变成一眼可见；无错误时显示灰色"无问题"
P2 运行条右端
:1322-1436		 48px 运行条左端是操作按钮，右端空着 右端显示当前步骤进度（第 3 / 8 步 · 定位）+ 实时节拍 运行时最常问"跑到哪了"，现在要去流程树里找高亮
P2 图标可读性
:1251-1274		 四个 FontAwesome 图标按钮，只有 ToolTip 保留图标 + ToolTip，但命令面板（Ctrl+K）里补全文字入口 图标节省空间的前提是"有第二条带文字的路径"

7待用户拍板（复刻前必须定）

Q1 顶栏高度40px（+4）还是保持 36px？40 能让模式分段更稳，但会改 CaptionHeight 与双击标题栏最大化的命中区。建议 40。 Q2 底栏高度28px（+2）是否可接受？画布只损失 2px。建议 28。 Q3 文件操作新建/打开/保存收进「☰ 文件」菜单，还说保留三个图标？建议收进菜单（菜单里已有同样命令）。 Q4 资源显示CPU/MEM 常驻 + 浮窗；还是继续四项常驻？建议常驻两项。 Q5 问题清单是否本轮就要（新增聚合逻辑，非纯视觉）？可先只做视觉占位。 Q6 未接入 KPI未接入显示"未接入"还是继续保持 "—"？建议"未接入"（区分"没数"与"0"）。
