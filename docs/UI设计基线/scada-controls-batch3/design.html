设计原则 PRINCIPLES

沿用 v1/v2 的八条

  • 双上下文一套结构：运行深色 / 编辑浅色，只换令牌。
  • 五态是底线：Normal / Hover / Pressed / Focus / Disabled；过程控件再加 Current / Dragging / Loading。
  • 状态色只表达状态：灰停、绿运行、黄警告、红故障；accent 只做交互与当前项。
  • 数字等宽；触摸命中 ≥44。
  • 不造死属性：每个可配属性运行态必须有可见效果。
  • 失败可见：写入失败、变量丢失、无权限、越限都要就地反馈。
  • 只读不伪装：没有写通道 / 没有权限时不给“能点但报错”的假按钮。

本批新增三条

  • 禁用要能说出原因：禁用外观 + 原因角标，鼠标悬停给一句话；不是简单变灰。
  • 历史与实时必须视觉可分：实时带 LIVE 徽标与滚动；历史带查询条、时间范围与分页，不伪装成实时。
  • 编码类图元先保真再美化：二维码/条码优先保证可扫描（静区、对比度、最小模块），不为了好看加圆角或反色。

页面背景图 + Hmi.Picture · 本地图片 P0

现场绝大多数本地图片是整页背景（工艺图、设备布置、厂区平面），不是可拖动的图元。所以拆成两条路径：页面背景是页面属性（铺满、压底、不参与框选/命中），Hmi.Picture 只负责内容图片（logo、产品图、操作指引）。

为什么背景不做成图元

  • 页面背景归属于页面：不参与框选、复制粘贴、图层排序、Z 序调整，也不会被 Ctrl+A 选中。做成图元后，用户一框选就把背景带走，锁图层也挡不住全选。
  • 永远在最底层：在所有图元、所有图层、所有基座元素之下；运行态 IsHitTestVisible=false，不会挡住上面的按钮。
  • 铺满页面矩形：跟随页面宽高，不单独设 X/Y/宽高；窗口缩放时一起缩放。
  • 基座继承：页面自己没设背景时用第一只基座的背景；自己设了就覆盖，不叠加（两张整页背景叠起来从来不是意图）。一张基座背景可以服务所有引用它的页面。
  • 默认“适应”：工程图被裁掉一块是功能错误，所以默认不裁切、留边用背景色；要铺满选“填充”。
  • 不透明度：10~100，做水印底图（蓝图 20~40%），保证上面的数值仍然可读。
  • 资产同一套：复制进方案根 Image\，.vms 只记相对路径；方案本身就是一个文件夹，迁移/备份复制整个文件夹即可（见下一节）。

目录契约

  • 方案 = 一个文件夹：Line1\Line1.vms + Image\ + Alarms\。现有 SolutionAssetFolders 已经按这个约定实现，本批不改结构。
  • 图片只进 Image\：拖入即复制，.vms 只记 Image\xxx.png；绝不写绝对路径、绝不引用方案目录之外的文件。
  • 另存为带走资产：SolutionAssetFolders.CopyAlongside 已实现；目标目录已有同名文件不覆盖（静默盖掉对方的资产比不复制更危险），失败只提示、不回滚保存。
  • 迁移/备份 = 复制整个文件夹：不需要“导出资源包”这一步；要单文件分发就压缩整个方案文件夹。
  • 多方案不共享文件：同一张图拖进两个方案就是两份副本；一个方案删图不会影响另一个。

拖入流程

步骤行为
1 选文件png / jpg / bmp / svg；先校验可解码
2 算哈希内容哈希（SHA-256 前 16 位）用于查重
3 查重同名同内容 → 复用已有文件，不产生副本
4 命名同名不同内容 → name (2).ext，不覆盖
5 复制临时文件写入后 File.Move，避免半写
6 写引用.vms 写相对路径；失败则回滚新文件

边界与失败

  • 文件被占用：明确报“被其他程序占用”，不半写、不改引用。
  • 资源缺失：页面背景回退背景色；内容图显示占位；编辑器给一行警告，运行态不弹窗。
  • 孤儿文件：删除图元/换图不自动删文件（避免误删被别的页面引用的图）；后续可做“清理未引用资源”。
  • 大小：单文件 >20MB 警告，不自动压缩；SVG 栅格化后缓存。
  • Web：宿主按方案路由提供 Image\ 下的位图，浏览器拿不到磁盘路径。
与全局资源库的区别：不做“软件级图片库”。现场交接的是方案文件夹，不是一台机器；全局库会让“拷到另一台机器”缺图，而且多方案互相覆盖。确有跨方案复用需求时，走“另存为 + 替换”，不引入共享引用。

Hmi.Line · 线 / 折线 / 箭头 P0

工艺图连线、分区框、标注、流向箭头。现在只能用细矩形或管道凑，拐弯接缝对不齐、不能带箭头。

设计期演示（可拖端点）—
选中：2px accent + 7px 手柄 锁定：金色 + 手柄消失 禁用：50% + 不响应

口径

  • 一个 TypeKey 三种形态：Mode = Line / Polyline / Arrow。折线就是多端点，箭头就是端点装饰；不拆三个类，否则属性面板与命中测试要写三份。
  • 端点吸附：拖到图元边缘 10px 内吸附到最近的边中点/角点；吸附后跟随图元移动（记录锚点而不是绝对坐标）。
  • 箭头随线宽缩放：marker 大小 = 线宽 × 3.5，避免细线箭头过大。
  • 正交路由是后置项：本批只做直线/折线，不做自动拐弯（自动路由需要避障，成本翻倍且现场更爱手拖）。
  • 命中测试：线宽 < 6 时按 6px 容差命中，否则细线点不中。

Hmi.DataGrid · 历史源模式 P1

视觉机的核心价值是追溯。现有 DataGrid 只有 Live 源（采集信号），历史查询、分页、三态、导出都没有。

口径

  • 只换数据源，不新建图元：Source = Live / History，列定义、行模型、空态、斑马纹、最大行数全部复用。
  • 查询三态必须齐：Loading（骨架行，不用转圈遮罩）、Empty（“该范围没有记录”+ 改范围建议）、Unavailable（原因 + 重试，不清空上一次结果）。
  • 分页而不是全量：默认 50 条/页，上限 500；查询带超时与取消，切页/关窗取消在飞请求。
  • 时间范围用 DateTimeOffset，按行时间过滤；跨午夜文件枚举 ±1 天，旁路文件显式警告。
  • 自动刷新默认关；打开时最小 10s，且只在第一页生效（翻页后暂停，避免跳行）。
  • 导出 CSV 走既有导出通路，文件名带范围与条数；导出失败给原因。

口径

  • 两个 TypeKey：Hmi.QRCode 与 Hmi.Barcode。不合并：条码的长宽比、静区、可读字符集与二维码完全不同。

  • 超长拒绝：QR 上限按字节（默认 2953 字节，UTF-8），条码按码制字符集；超长显示错误态并保留上一次有效图形，不画半个码。

  • 不反色、不圆角、不加装饰：编码表面固定白底黑码，深色主题下也不反色（扫描器要求）。
  • 打印尺寸：属性里给“最小模块宽度”，低于 0.25mm 警告；Web 端按 CSS 像素渲染，不承诺打印精度。

口径

  • 一条动画、三种来源：ScadaAnimationType.Enable，驱动变量为 0 时禁用、非 0 启用；原因文案由 DisableReason 配（联锁/权限/无数据各配一句）。
  • 禁用是交互闸门：不仅变灰，点击/键盘/拖拽全部不响应；不弹错误对话框（避免误以为程序坏了）。
  • 原因必须可见：禁用时在控件右上角挂一个小角标，悬停显示整句原因；没有原因文案时用“当前不可用”。
  • 与权限闸门的关系：元素级 RequiredRole 是“登录身份”，启用动画是“过程条件”。两者都满足才可交互；视觉上不区分来源，文案区分。
  • 不做透明度动画：禁用用固定 58% 遮罩 + 去饱和，避免和“可见性/外观变化”的透明度语义混淆。

属性默认说明
Variable空0 = 禁用，非 0 = 启用
Invertfalse反转语义（1 = 禁用）
DisableReason“当前不可用”联锁/权限/无数据各配一句

状态优先级：可见性 > 启用 > 外观。隐藏时不再渲染禁用态；禁用时外观动画仍可改颜色（例如红色故障），但不接受交互。

对象更改 / 开关打开关闭事件 P1

操作记录与联锁都靠“对象状态变了”这件事。现有事件只有按下/释放/输入完成，对象状态变化只能靠变量值变化间接推。

口径

  • 三个新事件：ObjectChanged（对象状态改变）、Opened、Closed。手册 7.5.2 明确它们挂在图形开关 / 文本开关 / 滚动条 / 量表上。
  • 与变量事件分工：变量事件是“值变了”，对象事件是“控件状态变了”。两者可能同时发生，但动作链只跑一次——由控件在提交成功后发对象事件，变量事件由值源判边沿，互不代发。
  • 只发“用户造成的改变”：程序灌值、初始化、ApplyConfigValues 不发对象事件（R35 同一口径）。
  • 动作失败不改行状态：先写变量，成功后才记“已切换”；失败保留原状态 + 原因，不乐观更新。
  • 防抖：同一控件 100ms 内的重复切换合并为一次事件（避免拖动滑块刷爆日志）。

Hmi.MultiTrend · 多曲线趋势 P1

PV/SP/OP、温度/压力/转速对比。现有 Hmi.ChartTrend 只有一根曲线、一个时间窗，并排放多个会各画各的坐标轴。

  • 2~8 条曲线，每条独立量程与颜色；图例可点选隐藏，隐藏不销毁数据。
  • 两种量程模式：共享量程（同一单位，如三路温度）/ 独立量程（不同单位，归一化后叠画，图例显示真实值）。默认独立，因为混单位是常态。

口径

  • 一个 TypeKey、两种模式：Mode = RunTime / Counter。运行计时按“运行信号为真”累计；计数器按“计数脉冲上升沿”加一。

  • 节拍判定：本次节拍 ≤ 目标为达标（绿），超出 20% 为警告（黄），超出 50% 为超时（红）；只做视觉，不自动报警。

边界与不做 BOUNDARIES

本批不做

  • 配方：单独一批（存储/权限/审计/下载握手）。
  • 报表、PDF/浏览器/数据库视图、文件浏览、I/O 监视：属宿主能力，不是控件。
  • 多语言 / 状态列表：横切能力，等出口需求明确后单独做。
  • 多边形 / 贝塞尔 / 动态画线：场景窄，线/折线先覆盖 90%。
  • 圆形进度条 / 旋钮 / 跑马灯 / XY / 3D 饼图：能用现有控件拼或场景窄，P2。
  • GIF / 增强图片：多帧动画需要独立解码与性能预算，P3。
  • 正交自动路由：线只做手拖折线。

平台差异（必须写进复刻清单）

  • Web 运行态：10 项里 6 个新 TypeKey 都要补渲染器；历史查询、声音、本地图片在 Web 端按“镜像”处理（桌面端决定，浏览器只显示）。
  • 声音：浏览器自动播放限制，Web 端默认静音，需用户手势后才能响。
  • 二维码：两端必须用同一份编码结果，不能让浏览器自己编码。
  • 本地图片：Web 端由宿主下发已栅格化的位图，不暴露文件路径。
  • 触摸：增量按钮长按重复在触摸屏上要 `CaptureMouse`/`CaptureTouch`，滑出即停。
  • DPI：线宽与箭头按 DIP，不按物理像素；二维码最小模块按物理尺寸校验。
