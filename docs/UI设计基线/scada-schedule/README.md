## 定位

按 `AGENTS.md` §30.1 的四步流程，本目录是**第 ① 步（Web 设计基线）**的产物：

```text
① 设计基线（本目录） → ② 设计定稿与令牌映射 → ③ WPF 复刻 → ④ 同屏同状态截图验收
```

- Web 只是**设计媒介**，不进构建、不部署、不作为第二个客户端维护（R126）；
- 基线确认后只读，调整需升版本（v1 → v2）并同步令牌映射（R128）；
- 本版**只审设计**，不改任何 WPF/XAML 代码。

## 需求（要解决的现场问题）

把"什么时间 / 什么条件下，自动做一件事"配成一张表，运行态由宿主按节拍检查并执行——不用人点，也不用下装 PLC。

两类触发：

| 类型 | 触发 | 典型用法 |
| --- | --- | --- |
| 时间计划 | 每天 / 每周 / 指定日期的固定时刻 | 08:00 开班切白班画面、清零班产；19:55 交接班提醒；23:00 夜间停线 |
| 事件计划 | 某变量条件成立**并持续**一段时间 | 液位高持续 10 分钟 → 停泵；通信断线 30 秒 → 切离线画面；工位 5 分钟无结果 → 卡料提示 |

**不做安全联锁**：急停、超压泄放必须留在 PLC / 安全回路；计划表只做提示、记录、画面切换与非安全启停，也不承担毫秒级时序。

## 布局（v1 定稿口径）

| 区域 | 规格 |
| --- | --- |
| 对话框 | 980 × 自适应（列表 3 条时 568 高）；圆角 8；`#151C23` + 1px `#2A3745` |
| 标题条 | 高 46；标题 15；右侧"3 条 · 2 条启用" 11 号灰 |
| 只读提示条 | 仅在只读态出现：琥珀底 10% + 文字 `#FFB020` |
| 左列（计划清单） | 固定 **300**；每条两行（名称 13 / 触发摘要 11）+ 右侧"启用/停用"；选中态 accent 底 14% + accent 边 |
| 左列底部 | 「＋ 新建计划」通栏 |
| 右列（编辑区） | 自适应；内边距 16；区块间距 24；区块内行间距 8 |
| 触发区 | 分段控件（时间计划 / 事件计划）；时间侧再分 每天 / 每周 / 指定日期；事件侧是"变量 + 条件 + 持续 + 单位"一行 |
| 下次触发预览 | 时间侧同一行右侧的灰字（`下次：明天 08:00`），改周期/时刻即时刷新 |
| 动作表 | 每行 `序号 · 动作下拉(150) · 参数(自适应) · ↑↓✕`；行底 `#1B2430` + 1px 边；最多不限，空表时整块描红 |
| 运行态信息条 | 虚线框，三格：上次执行 / 下次触发 / 触发次数（只读，灰色） |
| 底部 | 左：校验错误（红，11 号，可多条用「；」连）；右：删除 / 取消 / 确定（确定是实心 accent） |

## 五态

| 态 | 表现 | 触发条件 |
| --- | --- | --- |
| 空列表 | 右列居中一句"还没有计划。点左下「＋ 新建计划」开始。" | 一条计划都没有 |
| 列表 | 左列 N 条 + 右列第一条的表单 | 默认 |
| 编辑中 | 字段可改、左列摘要随输入实时更新 | 用户输入 |
| 校验失败 | 名称空 → 输入框描红；动作空 → 动作块描红；底部一行红字列出全部问题 | 点「确定」 |
| 只读 | 顶部琥珀提示条 + 全部可编辑区降透明度并禁用指针；只剩关闭 | 当前角色 < 工程师（权限在按下前判定） |

## 交互细节（验收清单）

1. 点左列任一条 → 右列换成该条表单，错误提示清空。
2. 切「时间计划 / 事件计划」→ 只显示该类型字段；切到事件时若没有变量，自动填第一个候选（避免空表单）。
3. 切「每天 / 每周 / 指定日期」→ 星期多选 / 日期输入随之显隐；「下次触发」预览同步刷新。
4. 星期多选：点一下切换；全不选时点「确定」报"每周至少要选一天"。
5. 动作行：↑↓ 调序（首行 ↑、末行 ↓ 置灰）、✕ 删除、＋ 添加；动作类型切换后参数占位提示跟着换。
6. 「启用」勾选框在右列表单上；左列状态字（启用/停用）实时跟随。
7. 「＋ 新建计划」→ 插入一条空名称、默认"每天 08:00"的计划并选中；名称为空时点「确定」报错。
8. 「删除」→ 删当前条并选中下一条；删空后进入空列表态。
9. 右上角开关可切"操作员只读态"预览（真实界面由角色决定，不是开关）。

## 待确认（影响 WPF 复刻范围）

| # | 问题 | 建议 |
| --- | --- | --- |
| 1 | 动作表要不要支持"多条动作 + 每条失败继续" | 建议：**继续并记审计**（与现有动作表口径一致），不做"失败即停" |
| 2 | 事件计划的"持续"是否要支持"累计时长" | 建议：v1 **只做连续**（条件消失即重新计时），累计是另一个语义 |
| 3 | 错过时间点要不要补跑 | 建议：**不补**，只记日志；开机补跑做成属性（默认关） |
| 4 | 计划表入口放哪 | 建议：顶部横条「计划表」按钮（与全局变量/通讯设置同级），不新增面板 |
| 5 | 是否需要"导入/导出计划表" | 建议：v1 不做，随 `.vms` 走 |
| 6 | 只读门槛 | 建议：修改需 **工程师**，查看需 **操作员**；删除另判（工程师） |
