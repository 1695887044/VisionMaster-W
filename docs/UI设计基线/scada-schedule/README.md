## 为什么有 v2

两件事叠在一起：

1. **v1 的域选错了**。v1（2026-10-25 13:04）用的是 SCADA **运行态深色**令牌（`#151C23` / `#38BDF8`），而当天 14:45 落地的 `ScadaScheduleManagerView.xaml` 走的是**浅色 Dialog 域**（`Colors.xaml` 的 `Dialog*` 族，主色 `#0EA5E9`）——设计稿和实现不是一套视觉，v1 从未被复刻。
2. **2026-10-27 对实际界面做了截图走查，列出 17 条 UI 问题**（左栏空态缺失、启用开关不可见、三套互斥条件同开、动作表无表头无删除、下拉弹层越界等）。

v2 把基线拉回**实际落地域**，并逐条回答那 17 条（见 §17 条问题 → 设计回答）。v1 原文保留在 `design-v1.html`，不再维护。

## 需求（要解决的现场问题）

把"什么时间 / 什么条件下，自动做一件事"配成一张表，运行态由宿主按节拍检查并执行——不用人点，也不用下装 PLC。

| 类型 | 触发 | 典型用法 |
| --- | --- | --- |
| 时间计划 | 每天 / 每周 / 指定日期的固定时刻 | 08:00 开班切白班画面、清零班产；19:55 交接班提醒；23:00 夜间停线 |
| 事件计划 | 某变量条件成立**并持续**一段时间 | 液位高持续 10 分钟 → 停泵；通信断线 30 秒 → 切离线画面；工位 5 分钟无结果 → 卡料提示 |

**不做安全联锁**：急停、超压泄放必须留在 PLC / 安全回路；计划表只做提示、记录、画面切换与非安全启停，也不承担毫秒级时序。

## 交互细节（验收清单）

1. 点左列任一条 → 右列换成该条表单，错误提示清空；选中行浅蓝底 + 左侧色条。
2. 「启用」开关在名称标签行右侧；列表行内开关与它双向同步，顶部计数「N 条 · M 启用」实时跟随。
3. 切「时间计划 / 事件计划」→ **只显示该类型字段**（时间块整体隐藏，不保留空壳）。
4. 切「每天 / 每周 / 指定日期」→ 星期芯片 / 日期输入随之显隐；「下次触发」预览同步刷新。
5. 星期芯片点一下切换；全不选时点「确定」报"每周至少要选一天"。
6. 上限 / 下限只在条件为「高于上限 / 低于下限」时出现。
7. 动作行：↑↓ 调序（首行 ↑、末行 ↓ 置灰）、✕ 删除、＋ 添加；动作类型切换后「参数」列按类型显示输入框或「—」。
8. 「＋ 新建计划」→ 插入一条默认「每天 08:00」的空名称计划并选中；名称为空时点「确定」报错。
9. 「删除这条」→ 删当前条并选中下一条；删空后进入空列表态。位置在视图底部最左，与宿主的「确定」隔开。
10. 只读态由角色决定；门槛沿用 v1 建议：查看 ≥ 操作员，修改 ≥ 工程师，删除单独判工程师。

## 复刻结果（2026-10-27）

### 实现期发现并修掉的 5 个问题

1. **宿主卡片 `MaxWidth=700`**：980 宽的视图被压到 652，动作表「操作」列被裁成一条缝（走查第 6 条的真正根因）。放宽到 1040（MaxWidth 只是上限，窄弹窗不受影响）。
2. **`ValidateAndShow()` 没有任何调用方**：EasyDialog 的「确定」直接把结果设成 Primary 并关窗，校验永远不跑。新增 `IDialogValidator` 契约，宿主在设结果前调用；返回 false 就留在弹窗里。
3. **内嵌单位后缀把内容区挤到 12px**：`Padding="8,0,46,0"` 下 R184 实测 `viewport=12 < extent=32.3`，「08:00」只显示「08」。改成「输入框 + 独立后缀列」后 `viewport=65.7`。
4. **折叠的事件块仍会触发 `SelectionChanged`**：条件下拉在布局期完成一次绑定，`OnConditionChanged` 里的 `ClearErrors()` 把刚校验出来的红框全抹掉（R35：不能从"值变了"倒推用户改过）。改为只刷新上下限显隐。
5. **`"8:0"` 被 `TimeSpan.TryParse` 读成 00:08**：想填 08:00 的人会得到 00:08 且不报错。`TryParseTimeOfDay` 先按 `h:mm` / `hh:mm(:ss)` 卡格式，`"8:0"`/`"8:5"` 直接判非法（[SC1] 已钉住）。

## 已知偏差（复刻后实测）

1. **控件高 30**：取自 `DialogGridInput` / `DialogGridSelect` 紧凑档；`DialogInput` 标准档 38 会让整屏超出屏幕预算。
2. **开关**：视图内自绘 `CheckBox` 模板（30×17），未用 Fluent `ToggleSwitch`——断言宿主没有 `Application`，Fluent 隐式样式不可靠。
3. **星期芯片**：视图内 `ScheduleChip`（ToggleButton 模板）。按 R141「同一视觉结构第二次出现再下沉」，首次留在视图内；第二次复用时下沉为 `DialogChipToggle`。
4. **单位后缀外置**（设计稿在框内）：内嵌后缀 R184 实测 `viewport=12 < extent=32.3`，会把「08:00」裁成「08」。
5. **日期**：只有文本框，没有日历弹层（设计稿的日历按钮未实现）。
6. **变量**：纯文本框，没有候选下拉——需要把变量表注入视图（R33 名字类字段口径），当前 `ScadaEditorViewModel` 没有这条通道。
7. **只读态**：视图已实现（`IsReadOnly` → 提示条 + 禁用 + 隐藏删除），**角色未接线**：`ScadaEditorViewModel` 不持有 `IScadaAccessPolicy`，接线是下一步。
8. **标题条**：「N 条 · M 启用」在 EasyDialog 的标题条上放不了（宿主不支持副标题），只在列表头显示。
9. **页脚**：取消 / 确定由 EasyDialog 提供（视图不可改）；「删除这条」放在视图底部最左，与「确定」隔开。
10. **正文高度 540~560**（设计 540~620）：按 1366×768 的屏幕预算收窄；事件计划态内容约 590，会出现纵向滚动条。
11. **下拉弹层**：本稿用原生 `<select>`，WPF 用 `ComboBox` 默认弹层——宽度都跟随控件，但弹层高度/滚动条无法逐像素对齐。
12. **字体度量**：Web 与 WPF 都用 Microsoft YaHei UI；行高与字符宽度允许 1~2px 差异。
