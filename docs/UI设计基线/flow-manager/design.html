改了什么（一句话版）

  • 调用方式：5 个复选框 → 5 个可点 chip，单排 265px；未选是空心灰、已选是实心浅底加粗。绑定不变（仍是 IsTimerInvoke … IsLineStartInvoke 五个 bool）。
  • 删「调用关系」列：它的 4 种取值（循环 / 外部 / 子 / 手动）本来就完全由 InvokeType 位集派生。绿色 整线 chip 表达"可整线启动"，蓝色 chip 表达"外部触发"，名称旁角色徽标表达主流程；只有"仅子程序"与"手动"两种情况在 chips 下补一行小字。
  • 状态列 4 态：运行中 / 已启用 / 已禁用 / 已锁定，只有异常态（运行中、已锁定）给底色，正常态只用圆点。
  • 操作列按状态收敛：启用/禁用是文字键，锁定/解锁合并成一个图标键（锁 ↔ 开锁），不再并排出现两个互斥按钮。
  • 说明折叠：默认 32px 一行目录，点「展开」变两列分组（128px，仍比现状 160px 少）。
  • 空态：搜索无结果时给图标 + 关键词 + 「清除搜索」。
  • 选中态：整行浅蓝 → 3px 左侧强调条 + 更浅的 DialogAccentSoftBrush，与语义色不再打架。
  • 未配齐提示（新增）：勾了「定时」但间隔为 0、勾了「变量」但触发源为空 → 琥珀加粗一行「定时未设间隔 · 变量未选触发源，不会触发」。这两种组合现在静默不触发，见右栏 Q6。

新增 Q6：定时 / 变量 勾了也不会触发

  1. 「定时」的时间没有配置入口。TimerIntervalMs 只在 FlowModel.cs:386，全仓 XAML 无任何绑定，流程右键菜单 11 项里也没有「定时设置」（FlowListViewModel.cs:292-453）。真实方案 10 条流程该值全是 0。
  2. 而 ShouldFire 把 0 判成"没配间隔"（FlowTimerScheduler.cs:173：if (flow.TimerIntervalMs <= 0) return false;）——0 = 永不触发，不是"每 100ms 跑"。
  3. 「变量」同理。TriggerVariable（:377）无 UI，全仓只有 FlowVariableTriggerService 与 RecipeService 读它，没有生产代码写它；真实方案全为空串，EvaluateCore:160 的空串永不匹配变量名。
  4. PendingReason 帮不上忙。它回答的是"这一位有没有接通运行侧"（5 位全返回 null = 都接通了），不回答"这一条流程有没有配齐参数"。所以界面现在既不触发、也不提示——正是这套机制想防的"勾了没反应 = 软件坏了"。

本稿取法（第 4 行「点胶检测_工位」即证据行）：新增一个派生属性（暂名 InvokeConfigNote）， 勾了定时且间隔 ≤0 →「定时未设间隔」；勾了变量且触发源为空 →「变量未选触发源」；两行都缺则合并成一句， 以琥珀加粗挂在 chips 下方。不改 PendingReason 语义（它管"接通"，这个管"配齐"）。

仍待你选的是配置入口：A 点 chip 旁的齿轮开小窗就地配（改动最小）；B 整行双击开「流程属性」把 5 位 + 两个参数 + 描述一起改；C 本版只做提示、配置入口另开一期。
