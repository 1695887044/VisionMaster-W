**另加的两项**（评审里的 P1，成本低）：
- **IOField 禁用态**：`IsEnabled=False` → 光标回箭头、底色收起、字降亮（原来禁用与只读同形）；
- **Slider 量程标注**：轨道下方左右两端显示 `Minimum` / `Maximum` 小字（原来不知道量程是 0~100 还是 0~250）；
- **Slider 禁用态**：轨道/填充/拇指一起降饱和（三个新令牌进 `ScadaTokens.xaml`，无 hex）。

**评审勘误**：评审稿写"拇指尺寸无下限、可能只有几像素"是错的——`SliderElement` 里
`private const double ThumbSize = 20d`，拇指固定 20px。那条 P1 的依据是 CSS 复刻，不是代码。
真实问题只是"命中区 = 控件本身"，所以按 Q4 补 `MinHeight=44`。

**断言同步**：`[SL11]` / `[SL18d]` 原来把填充高度写死成 12 / 24 像素；加了量程标注行后轨道变矮，
两条按预期红。改成"按实际轨道高度 × 比例"计算——判据仍是"填充比例正确"，不再绑定模板像素。

## 第二轮（同日）：跟手气泡 + 单位分列

**Q3 跟手气泡**（`SliderElement`）：
- 模板把数值包进 `PART_ValuePlate`（圆角气泡），`UpdateVisuals` 按拇指中心算水平位置并夹在控件内；
- 横向跟手、纵向退回右上角（纵向时轨道跨两行，没有"拇指上方"可跟）；
- 断言 `[SL12b]`：值 10 与 40 两档比较气泡左偏移（0 vs 46.5），并验证不越界。
  **判据取两个比例之间的相对关系，不写死像素。**

**单位分列**（`IOFieldElement`）：
- 新增只读 `ValueOnlyText`（纯数值），`ValueText`（数值 + 单位）**语义保持不变**——老调用方与断言不受影响；
- 模板改成三列：标签 / 数值（右对齐）/ 单位（固定宽、左对齐、次要色），单位为空时该列宽 0；
- 断言 `[IP1]` `[IP2]`：拆列后两条串各自正确，单位清空时数值串不变。

**踩的坑**：`[SL12b]` 第一版在纵向状态下测量，两个偏移都是 0（纵向本来就不跟手）；
断言里必须先 `Orientation = Horizontal` 再布局。图元控件必须在 STA 线程上构造，
`TouchPolishChecks` 第一版直接 new 就抛了——加了 STA 包装。



## 结论

**IOField 的设计底子比多数商业组态好**：四态（只读/可写/编辑/失败）、编辑框与显示块同格叠放（进编辑字不跳）、
铅笔只做提示不抢命中、错误走 `DisplayStroke` 且 ToolTip 显示 `EditError`。缺的是**触摸与可访问性**。

**Slider 模板干净、令牌齐全**，但拇指尺寸由代码算且**无下限**，没有禁用态、没有拖动反馈、没有量程标注。

## 发现（IOField 9 条 / Slider 8 条，节选）

| 级别 | 控件 | 发现 |
| --- | --- | --- |
| P1 | IOField | 可写提示只在 `IsMouseOver` 出现——触摸屏没有 hover，看不出能改 |
| P1 | IOField | 没有禁用态视觉（`IsEditable=false` 只改光标/边框），"只读"与"无权限"同形 |
| P1 | IOField | 越限/失败只变颜色（色觉差异用户不可辨） |
| P1 | Slider | 拇指尺寸无下限（控件拉小就抓不住），命中区未按 44px |
| P1 | Slider | 无禁用态；写失败无任何反馈（设备拒写时值回弹、界面无解释） |
| P2 | IOField | 单位跟数字拼串 → 小数点不对齐；值变化无瞬时高亮；长标签截断后 ToolTip 被错误信息占用 |
| P2 | Slider | 数值固定右上角（视线远离拇指）；无量程标注；无拖动反馈 |
| P3 | 两者 | 键盘可达性/步进未表达；编辑环 `Margin=-4` 固定不随尺寸 |

## 两条共性根因

1. **按"鼠标 + 桌面"设计，现场是触摸屏**：hover 才是可写提示、拇指按像素算、命中区无下限。
2. **状态只画"看得见"的**：两个控件都没有禁用态；越限只靠颜色；写失败没有出口。

建议把这两条写成判据（触摸优先：可写性常显、命中区 ≥ 44px、拖动/按下必须有可见反馈；
状态三件套：颜色 + 图标/加粗 + ToolTip/文案），否则同类问题会继续按控件逐个复发。
