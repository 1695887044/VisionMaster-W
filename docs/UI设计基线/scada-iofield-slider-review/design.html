抽查评审：数值域（IOField）与 滑块（Slider）

两个都是"操作员要动手"的控件，也都在触摸屏上用得最多。下面「现状」按各自模板逐项复刻， 「改版」是同尺寸建议；末尾给出两条共性根因——它们解释了为什么同类问题会反复出现。

0 · 抽查结论

Hmi.IOField（数值域）

四态（只读/可写/编辑/失败）做得比大多数商业组态细：编辑框与显示块同格叠放、字不跳， 铅笔只做提示不抢命中。缺的是触摸场景与可访问性：无禁用态、可写性靠 hover 才看得见、 越限只变颜色、单位跟着数字跑。

Hmi.Slider（滑块）

模板干净、令牌齐全，但拇指尺寸与命中区由代码算、没有下限约束； 没有禁用态、没有拖动反馈、没有量程标注。触摸屏上"手指盖住拇指"是常态。

2 · 数值域：发现

级别问题为什么是问题 / Web 惯例
P1触摸屏上看不出可写：铅笔只在 IsMouseOver 时出现 触摸屏没有 hover 状态，手指按下就已经进编辑了——"能不能改"这条信息在触摸设备上完全丢失。Web 移动端做法：可编辑控件常显编辑图标或用输入框外形
P1没有禁用态视觉：IsEditable=false 只改光标与边框 只读与"无权限/无写通道"长得一样。操作员点了没反应会反复点。Web 用 disabled 的灰底 + not-allowed
P1越限/失败只靠颜色 红/绿对色觉差异用户不可辨（约 8% 男性）。Web 惯例：颜色 + 图标/加粗/文字（三重编码）
P2单位跟着数字跑：ValueText 是"值+单位"拼串 右对齐时 62.4 % 与 7.2 % 的小数点不对齐，一列域上下扫读很费劲。Web/表格惯例：数值列右对齐、单位独立列固定宽
P2值变化没有瞬时反馈 一屏十几个域同时刷新，操作员看不出哪个刚跳。Web 常用 150ms 背景闪一下（工业 HMI 同样惯例）
P2进编辑是否全选现有值未表达 点进去在 85.0 后面追加会得到 85.012。Web 惯例：focus 时 select()，并给出"输入后回车确认"的提示
P2长标签被截断后看不到全名：ToolTip 被 EditError 占用 标签 TextTrimming=CharacterEllipsis，但唯一的 ToolTip 位置给了错误信息——没错时悬停无提示
P3键盘可达性未验证：样式里 Focusable=False 可编辑时能否 Tab 进入、Enter/Esc 是否提交取消，模板里看不到；Web 里输入控件必须键盘可达
P3编辑环与外框间距 Margin=-4 固定 控件被放大时环相对变小；Web 用 outline-offset 跟字号/尺寸走

5 · 滑块：发现

级别问题为什么是问题 / Web 惯例
P1拇指尺寸与命中区无下限（尺寸由 UpdateVisuals 按走向算） 控件被拉小时拇指只有几像素，触摸屏根本抓不住。Web 的 range thumb 固定 20px、命中区可外扩到 44px
P1没有禁用态（模板无 IsEnabled 触发器） 禁用时看起来仍可拖，拖了没反应。Web：disabled 轨道/填充/拇指全套降饱和
P1写失败无任何反馈 与数值域不同，滑块没有错误通道：设备拒写时值回弹、界面无解释。Web 至少给一条 inline 错误或边框闪红
P2拖动时无数值跟随：数值固定在右上角 视线在拇指、数字在远处；手指还会盖住拇指。Web/工业惯例：数值气泡跟着拇指走
P2无量程标注 看不出 0~100 还是 0~250。Web 在两端标 min/max 小字
P2无"正在拖动"反馈 拇指没有放大/阴影；触摸屏上手指按下后完全看不出状态变化
P3键盘步进不可见 IsTabStop=True 但没有步长提示（方向键 ±Step、Home/End 到端点）；Web 对应 aria-valuenow
P3轨道/填充同色系，边界弱 填充与轨道对比不足时读不出比例；建议填充用渐变或提高对比

7 · 两条共性根因

① 这些控件是按"鼠标 + 桌面"设计的，现场却是触摸屏。 hover 才是可写提示、拇指按像素算、命中区没下限——三条都只在"有精确指针"时成立。 建议把"触摸优先"写成判据：可写性常显、命中区 ≥ 44px、拖动/按下必须有可见反馈。

② 状态只画"能看见"的，不画"看不见"的。 两个控件都没有禁用态；越限只靠颜色；写失败没有出口。 Web 的做法是把状态拆成"视觉 + 语义 + 提示"三件套（颜色 + 图标/加粗 + ToolTip/文案）， 任何一件缺失，现场就会用"多点几次"来补偿。
