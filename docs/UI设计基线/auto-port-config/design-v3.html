v3

Web 设计基线 v3：推翻 v2.1 的「空候选 → 可手填」思路。判据来自一条事实—— 轴名、运动卡名、通讯变量名这些是框架权威清单里的「名字」，不是用户臆造的值： 清单取不到时，用户手填一个不存在的轴名，只会在运行期才炸，且炸得离故障点很远。 v3 因此改成：名字类字段只能从候选里选；候选取不到就禁用控件 + 红字说明原因与下一步； 如果是框架自己没登记候选来源（代码缺陷，不是环境问题），按 bug 红着脸报错，并给出「重新配置」入口。 样例数据仍是真实插件 MotionHomePlugin（Axis = InputPort<string> + IsFunctionalEnum=true + OptionKind=MotionAxisName；Mode 枚举、TimeoutMs 整数）。 颜色只经令牌变量引用，令牌定义只有本文件 #ap-root 一处。

设计要点（v2.1 → v3 的增量）
01
名字类字段不再有可编辑框 轴名 / 卡名 / 通讯变量名一律渲染成下拉（或空候选时的禁用占位）。LinkableValueEditor.xaml.cs:379 的 IsHandFillFallback 对「有 OptionKind 的封闭集合端口」恒为 false； XAML 里 PART_NoOptionHint 的「无候选，可手填」整句删除（LinkableValueEditor.xaml:150）。
02
「来源未登记」是缺陷，不是空态 现在没有任何 API 能区分「没登记来源」和「登记了但返回空」——只能靠 GetOptionItems().Count == 0 反推。 v3 要求 StepConfigOptionSource 提供判据（新增 HasProvider(kind) 或让 GetOptionItems 返回「空 + 原因」结果类型）， 否则界面只能一律当空态处理，缺陷永远静默。
03
「按 bug 直接红着脸报错」的落地口径 红框 + 红字 「这是程序缺陷，不是配置问题」 + 具体原因 + 「复制诊断」按钮（剪贴板文本含 kind/插件类/宿主版本，供开发者复现）。 同一处缺陷在一批任务里可跳过（确认按钮仍可用，因为不改这个字段也能跑），但页脚状态胶囊必须转红并计入缺陷数，不允许静默通过。
04
「重新配置」是一个入口，不是一句文案 空候选态给「去运动卡设置 →」按钮：走既有的设置对话框命令（不新增面板落点，R47 不违反）； 用户配完卡回来，本面板重新取一次候选（GetOptionItems 本来每次现取，不取快照），下拉自动恢复可选。
05
已选值失效 = 红 + 保留原值 流程里存的轴名在当前清单里找不到（改名/删轴/换卡）：不自动清空、不偷偷改成第一个候选， 而是红框 + 原值 + 「该轴当前不存在，请重新选择」。这属于流程数据过期，比缺陷更常见，文案必须分开。
06
只读项与「非运控插件」不复用缺陷样式 [StepConfig] 集合 / 自定义类仍是虚线只读框 + 灰字；没有 OptionKind 的普通字符串仍是可手填输入框 （那是用户自己的文本参数，不是框架清单）。只有「声明了 OptionKind 却取不到候选」才报红。
