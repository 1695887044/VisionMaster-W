两枚新属性的分工：JogMode 是模式（连续/单步），JogStepMm 是档位数值（0~50，0.1）。连续模式下档位框变灰不可编辑、也不参与任何计算；单步模式下才可改。存盘只存枚举名与数值，旧方案缺键时按 Continuous + 1.0 兜底，行为与现在一致。
行为口径（含运动锁）什么时候能动、什么时候不能
条件结果
连续 · 静止按下 JogStart(±JogVelocity)，松手 JogStop（三路：松键/移出/失去捕获）
单步 · 静止按一次 → 目标 = 当前位置 ± 档位，走完即停；不按则不动
运动中只锁两个点动键（连续与单步都锁）：点动键灰、档位框只读、顶部橙字「运动中 · 点动已锁」；停止 / 清报警 / 失能 / 回零照常可点
档位 0 / >50单步按钮灰，给出「档位须在 0~50 mm」；越界立即红框，不等发命令
未使能 / 未回零 / 有报警沿用动作表同一套门禁，原因直接上屏，不静默
为什么运动中也禁止「连续点动」：连续点动本质是「按住就一直走」，与正在执行的定位/回零是两条命令抢同一根轴——谁后到谁改写速度，先到的可能永远到不了位，日志还会显示两条都"成功"。所以在 CheckCanRun 里加一条运动锁（读轴快照的 Moving），比让操作员记"这轴正忙着别按"可靠。

档位输入可输入数值，0.0 ~ 50.0 mm，步进 0.1；▲▼ 单次 ±0.1；失焦提交按你的口径；0.1 与位置大字的三位小数不冲突
越界处理立即红框 + 红字，并回滚到上一个有效值；不发命令把错误停在"输入那一刻"，而不是按下去才发现
单步目标target = 当前位置 ± JogStepMm，走 TryMove（与点位「定位」同一路径）软限位/使能/回零/忙 判据只有一份
连点累计每次都以最新位置为基准（不排队、不预叠），点到哪算哪轴在动就不是「点一下走一格」了，排队的语义会让操作员算不清
运动锁只作用两个点动键：CanJog = CanOperate && !IsMoving（点位「示教/定位」按钮同样绑它）；CanOperate 继续绑外层容器；停止 / 清报警 / 失能 / 回零不绑 CanJog运动中两条点动命令会抢同一根轴；而停与清报警是安全/显示动作，回零不参与点动参数
停止优先级停止成功后立刻解锁；EndJogForAxis（切轴停旧轴）保持不过权限门禁沿用 v3 已有的安全语义
按钮角标单步时两键角标显示 −1.0 / +1.0（随档位变）；连续不显示不用低头看输入框也知道走多少

断言（ScadaChecks）5 条可测
① 连续模式：按下 → 收到 JogStart(value=+10)，松手 → JogStop（反面：档位填 5 不影响速度）
② 单步 +1.0：按一次 → 恰好一次 TryMove，target = 当前位置+1.0；不松手也不重复发
③ 运动中（快照 Moving=true）：两个点动键禁用、零命令，顶部橙字给原因；CanJog=false 而 CanOperate=true
④ 档位 0 / 62.5：只灰点动两键、零命令；填入 50.0 边界值可发
⑤ 运动中「停止」「清报警」「失能」「回零」仍为 enabled，且「停止」点击必须发出 Stop（反向钉住"别把安全动作锁掉"）
