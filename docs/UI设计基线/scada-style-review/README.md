# UI 样式优化清单（剩余控件）· 前端视角

| 项 | 内容 |
| --- | --- |
| 版本 | **v1** |
| 日期 | 2026-10-26 |
| 定位 | 上一轮全量审查（`scada-full-review`）偏**功能与交互**；这一份只谈**样式**：状态色、排版、形状、线宽、动效、令牌 |
| 阅读版 | [review.html](review.html)（页签：状态色 / 排版与密度 / 形状与边框 / 图形与线宽 / 动效 / 令牌清单） |
| 结论 | 需要优化，而且问题的根子是**同一语义有多套视觉取值**，不是单个控件"不好看" |

## 六个方面的问题（按影响排序）

| # | 问题 | 现状 | 建议 |
| --- | --- | --- | --- |
| 1 | **状态色不统一** | "运行"至少有 4 个绿/蓝（`#34C759` / `#22C55E` / `#2D7DD2` / `#0EA5E9`），分别来自 Symbol / Tank / 按钮填充 / 进度条 | 收敛成 `HmiStateRunning/Stopped/Warning/Fault/Unknown` 五个令牌；品牌蓝只做"可交互/选中"，不当状态色 |
| 2 | **缺断线态视觉** | 通讯中断时指示类沿用上一次的值（假状态） | `HmiStateUnknown` = 灰 + 斜纹（形状与亮度双重编码，不只靠颜色） |
| 3 | **字号七档** | 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 同屏出现 | 四档：10 辅助 / 11.5 正文小 / 13 正文 / 20 读数 |
| 4 | **行高四套** | 报警卡片 44、表格 28、位表 18、点位表 22 | 三档：44 触摸主操作 / 32 列表 / 24 密集表 |
| 5 | **圆角三套、线宽四套** | 3/4/6/8/10/12；0.5/1/1.5/2 | 圆角 4/8/12；线宽 1 / 1.5 / 2.5 |
| 6 | **细线不可见且点不中** | 1px 线在缩放画布上会消失，命中区也只有 1px | 视觉 1px、命中区 8px（透明扩边）；50% 缩放下做对比度检查 |

## 一条额外发现

**选中框与"运行蓝"撞色**：选中框用品牌蓝，而多个图元的运行态也用蓝——选中一个正在运行的设备时，
两层蓝叠在一起，看不出是"选中"还是"状态"。建议选中框改双色描边（外青内深）或加四角标。

## 令牌清单（建议新增）

`HmiState*`（5 个）、`HmiFontAux/Small/Body/Readout`（4 个）、`HmiRowTouch/List/Dense`（3 个）、
`HmiRadiusS/M/L`（3 个）、`HmiStrokeThin/Base/Strong`（3 个）、`HmiTouchTarget`（44）。

## 落地顺序

1. **`HmiState*`** —— 一处改、所有状态色统一，且有 R140 硬编码颜色闸兜底；
2. **`HmiTouchTarget` + 三档行高**；
3. 字号四档；
4. 圆角三档；
5. 线宽与符号墨迹归一化（30 种符号按墨迹盒等比填充到 92% 再居中）。

前两条做完，"界面看起来是一套东西"这件事就成立了一半；后三条属于精修，可分批。

## 边界

- 本清单**没有**要求改任何交互逻辑或数据契约，全部落在主题令牌与模板；
- 颜色令牌新增必须走 `ScadaTokens.xaml`（R140 只允许那五个文件里出现 hex）；
- 改完后需要重出四态截图做像素级复核（`_ScadaUiProbe --elements`）。
