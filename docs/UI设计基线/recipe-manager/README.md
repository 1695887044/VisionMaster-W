## 1. 为什么出这份基线

现有界面是在"v1 功能跑通"的目标下长出来的，视觉上没有经过设计阶段。截图（`evidence/before.png`）暴露的核心问题不是"不好看"，而是**界面上有很多东西在说同一件事、或者说不清任何事**：

- 左栏主任务是"选配方"，但列表分到零高度，创建表单占了约 400px。
- 右侧在"未选择配方"时仍然渲染出候选下拉、添加/删除、空表格、重命名框、"清除生效"——6 个当前不可用的控件。
- 权限和运行锁都只在 Service 里晚判，按钮仍然可点；用户得到一条橙色错误，而不是一条出路。

本稿按 R110/R111 补齐设计基线：布局、间距、配色令牌、字号字重、五态、交互细节六项在 §4~§7 逐项落纸。

## 3. 设计目标

1. **一眼看出"现在跑的是哪一份、有多久没换过"**——配方名 + 生效标记 + 最后应用时间常驻详情头部。
2. **把"会改什么"摆到最前面**——`当前值 → 配方值` 左到右读成一次变化，差异行有标线，顶部有计数。
3. **不能做的动作，先说清为什么**——权限条在顶、运行锁在按钮旁，禁用项带 `title` 理由，不靠点完再报错。

│ 配方管理 · SampleLine.vms          [停止·可应用] [工程师] [×] │

├───────────────┬──────────────────────────────────────────────┤

│ [搜索…]       │ 编码 · N 条参数 · 最后应用 …                 │
│ ───────────── │ [+ 添加参数] 12 个可添加 [删除选中(1)] …     │
│ ▸ 配方 A      │ ┌──────────────────────────────────────────┐ │
│   配方 B      │ │ □ 目标 参数 类型 当前值 → 配方值 状态    │ │
│   配方 C      │ │ …（差异行左侧 2px 标线）                 │ │
│               │ └──────────────────────────────────────────┘ │
│               │ 共 10 条 · 修改 4 · 不变 5 · 目标缺失 1       │ 36
├───────────────┴──────────────────────────────────────────────┤ 64
│ 删除配方            hint        [关闭] [应用并保存] [应用配方]│
└──────────────────────────────────────────────────────────────┘

- 左栏固定 300；右栏自适应，表格吃满剩余高度。
- 左右不再各套一张卡片：用一条 1px 分隔线 + 左栏浅底区分区域，少一层描边就少一层噪声。
- 新建/导入/导出从"常驻表单"降级为左栏底部两个入口；新建走弹层（本稿只画入口，弹层另行出稿）。

## 5. 间距与字号（R111 ②⑤）

| 用途 | 值 |
| --- | --- |
| 间距梯度 | 4 / 8 / 12 / 16 / 20 / 24 |
| 圆角 | 4（chip 内小件）/ 6（按钮、输入、列表项）/ 10（空态图标块、确认框）/ 12（弹窗） |
| 字号 | 11（表格类型、角标）/ 11.5（元信息、状态文案）/ 12.5（正文、按钮、表格）/ 13（面板标题）/ 14（窗口标题）/ 16（配方名、确认框标题） |
| 字重 | 400 正文 / 500 强调值、按钮 / 600 标题、表头 |
| 行高 | 正文 1.5；表格行固定 36px；表头 34px |
| 数字 | 所有数值列 `font-variant-numeric: tabular-nums` |

层级只有三档：14/600（窗口）→ 16/600（当前对象）→ 13/600（区域）。面板副标题一律 12/400。

## 7. 交互状态（R111 ④⑥，R115）

配色决策已在 §6，下面是"什么时候出现什么"。

### 7.1 八个业务态（设计文档 §9 要求）

| 态 | 画面 | 关键判据 |
| --- | --- | --- |
| 空 | 右栏空态块（说明 + 从当前值新建 + 导入），左栏"共 0 份"且隐藏搜索 | 主 CTA 只出现一处 |
| 未选中 | 右栏"选择一份配方" + ↑↓ 提示；左栏**不得**保留选中高亮 | 两处状态不许互相打脸 |
| 无参数 | 表格内空态行（"这份配方还没有参数" + 添加入口），不再整表渲染表头 | 空表格 = 未完成 |
| 有差异 | 差异行左侧 2px 琥珀标线 + 状态 chip + 汇总条计数 | 扫表即知会改哪几行 |
| 只读（未登录） | 顶部琥珀权限条 + 登录按钮；编辑类按 `needs-edit` 降透明，应用按 `needs-operator` | 权限在按下前判（R136①） |
| 运行中 | 标题栏红色 chip「运行中 · 应用锁定」；应用类禁用；底部提示换成琥珀 | 运行锁必须真的进门控 |
| 预检失败 | 确认层：红色计数 + 具名错误块 + 「确认应用」禁用 + 焦点在「取消」 | 整单拒绝，一条都不写 |
| 回滚锁定 | 复用只读条，文案换成"上次回滚失败，应用已锁定"，无登录按钮 | v1.1 补齐 |

`孤儿 / 悬空` 两态按设计文档并入"目标缺失"行状态 + 全局横幅，本稿未单独画。

## 10. 已知偏差（R129/R130）

1. **主按钮白字对比度 2.77:1**，未达 WCAG AA 小字 4.5:1。这是既有 `DialogPrimaryButton` 的令牌问题，不是本页引入；改主色是全局批次，需单独评审，本稿沿用现令牌。
2. 字体：Web 稿用 Noto Sans SC，WPF 走系统微软雅黑，字宽有 2~5% 差异，复刻时按实际渲染微调列宽。
3. 图标：稿内为 16px 线性 SVG 占位，WPF 走 Font Awesome 6 Pro Solid，形态会有差异，尺寸按 14/16 对齐。
4. 滚动条：浏览器 8px 悬浮条，WPF 默认 17px 常驻条，右栏可用宽度会少约 9px。
5. 桌面端不做 44px 触摸目标（无触摸场景），按钮高度统一 30/34。
6. 无深色模式：App 当前无运行时主题切换（R140 边界），本稿只覆盖浅色。

## v2.1 为什么改

用户在 2026-10-24 报了两件事，指向同一个设计缺陷：

1. 点「从当前值新建」**看起来没反应**——因为 `CanCapture()` 要求 `NewRecipeName` 非空，而名称输入框在左栏被列表挤到几乎没有提示；未登录时更直接是灰的，连点击都进不来。
2. 更根本的是语义：原实现是**全量捕获**（`RecipeService.Capture` 把流程里所有可捕获的步骤参数与本地变量一次性存进配方）。用户原话：「正常配方哪里所有参数，导入后还要一个一个地删除」。

所以 v2 把"新建配方"从"就地卡片 + 一键全抓"改成**显式弹层 + 手动勾选**：先命名，再逐条勾要跟着产品切换的参数。**默认一个都不勾**（2026-10-24 用户拍板：「默认全不勾、必须自己点」），全量只是"全选"按钮的功能，不再是默认，也不预勾差异项——差异只作为「只看差异」筛选条件与行标线，不替用户做决定。

## v2.4 与 v1 的行为差异（需评审确认）

| # | v1 / 现状 | v2 | 理由 |
| --- | --- | --- | --- |
| 1 | 左栏就地展开创建表单，占约 400px | 改成弹层，左栏整块还给列表 | 弹层能一次容纳"表单 + 候选表"，左栏放不下 |
| 2 | 一键全量捕获 | 手动勾选，**默认一个都不勾** | 用户明确否决全量；且 2026-10-24 追加拍板「默认全不勾、必须自己点」，不预勾差异项 |
| 3 | 未登录时创建/导入/导出整体降透明、点了没反应 | **不降透明，点了先弹登录**，登录后自动续上刚才的动作 | 用户："点不了应该直接弹登录" |
| 4 | 名称空白时按钮仍可点，点后弹错误 | 按钮按勾选数联动文案，名称空白时就地红字 | 把失败前移到输入时 |
