01现状 vs 提案

现状（v0）BEFORE

  图像二值化

① “⋮” 没有功能含义，看起来像可拖动的把手，实际只是装饰；
② 图标固定蓝色，丢失分类身份（工具箱条目是分类色）；
③ 名称不截断，长名字会把浮层拉得很宽；
④ 指针偏移 (-4,-4)，箭头压住浮层左上角。

提案（v1）AFTER

 图像二值化

① 去掉 “⋮”，换成与工具箱条目同源的分类色图标块（浅底 + 描边 + 强调色字形）；
② 名称加粗、限宽 170px、超出省略；
③ 指针偏移 (14,10)，箭头落在浮层外；
④ 尺寸/圆角/阴影微调，观感更接近“拿起来的一张小卡片”。

05交互与边界

  • 跟手：跟随指针移动，不参与命中测试（IsHitTestVisible=false，库内固定），不会挡住放置目标。
  • 落子即消失：拖放成功/取消/按 Esc 都由 gong 的放置端关闭（本轮已修：画布改为 IsDropTarget）。
  • 不表达“能不能放”：浮层只表示“正在拖什么”。能不能落由指针处的光标效果与落点闸门决定（例如 Break 只能进 For/While，被拒时状态栏给文案）。
  • 屏幕边缘：Popup 不自动翻转，靠近右/下边缘时可能被裁切——库行为，本次不改。
  • 长名字：省略号截断；完整名字可在工具箱条目上悬停查看（现有预览浮层）。

06已知偏差（R130 预判）

  • 阴影：WPF Popup 的尺寸等于内容 DesiredSize，不含 Effect 外扩；真机上阴影可能比本稿少一圈。属允许偏差。
  • 字体度量：本稿用系统 UI 字体，WPF 用应用默认字体；同一名称的截断点可能差 1~2 个字符。属允许偏差。
  • 图标字形：本稿用仓库内 FA 6 Pro Solid 的码点，与 WPF 同一字体；但浏览器与 WPF 的字形 hinting 不同，像素级会有差异。
  • 动效：本稿只写 120ms 淡入；WPF 侧时长由库固定，不做自定义动画。
  • DPI：本稿按 100% 出图；125%/150% 下 1px 描边与 38 高按 DIP 缩放，不做像素级承诺。
