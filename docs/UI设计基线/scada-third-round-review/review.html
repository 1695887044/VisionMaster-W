数据表格 · 轴面板 · 报警条 —— 四个角色（应用工程师 / 前端设计 / 运动安全 / 实现）的证据与裁定

轴面板 Hmi.AxisPanel

唯一会动设备的图元。证据最充分：未配置态下状态区、命令区、点动模式全都可见。

禁用
轴控台（含点位区）

A1
裁定：不改八个状态点只靠灰/亮区分
用户裁定：保持现状。状态点是"一眼扫过"的辅助信息，主操作区才是判断依据；改成每点带文字会把 280px 宽的轴面板撑满。
A2
裁定：不是问题「失能」没有独立按钮
用户澄清：轴使能本来就是切换开关——使能态绿色、失能态灰色，点同一个控件切换。不存在"缺一个失能按钮"。

画面右上角写着"未配置轴"，但按钮是正常态。这是"点了没反应"与"点了动错轴"之间最危险的一档。
A4

A5

"设计预览（运行后显示实时值）"这句运行期消失，设计期与运行期差异没有其它提示。

新版：自动滚动（2026-10-25 已实现）

原来的问题不只是"不滚"：OnBeat 第一句是 if (!_isFlashing) return;， 只有需要闪烁的报警才走节拍——一条不闪的报警条永远停在第一屏，连刷新都不做。 现在改成按固定节奏逐行下移、到底回顶：

实时报警未确认 2 / 共 3
严重一号罐液位高14:32
警告B 工位节拍超时14:28
警告相机 2 丢帧14:21
提示配方已切换14:05

↑ 示意（每行停留 2.5 秒、到底回顶）。条数不足一屏时不滚——否则"滚了个寂寞"，还让人以为漏了报警。

新增属性默认说明
AutoScrollTrue条数超过一屏时自动逐行下移、到底回顶；关掉则停在原处手动滚
SecondsPerRow2.5每行停留秒数（0.5~30）。太小看不清、太大像没在动

实现细节：位置按累计时长取模算（与闪烁相位同一理由），漏拍/卡顿不会越走越偏； 可见行数按 ViewportHeight ÷ 47px 算；断言 [AB-S1]~[AB-S3] 已钉住。

没做的两件：① 横向跑马灯（会丢掉时间与状态两列，与"三重编码"的结论冲突）； ② 用户手动拖动后暂停自动滚动（现在会被下一拍拽回）——建议与"新报警插入是否打断阅读"一起在下一批处理。

改为横向跑马灯（同日，按用户裁定 · 已实现）

用户反馈：要的是从右往左滚、不带确认、只要触发条件为 ON 就在队列里， 而且纵向卡片太占空间。所以形态改成两种，默认跑马灯：

一号罐液位高：液位 91.2%（上限 85%）· B 工位节拍超时：14.6 s· 相机 2 丢帧：2.3%· 配方已切换

↑ 示意：单行 34px、从右往左、按严重度上色、条间用「·」隔开。 不带确认状态——确认是报警汇总表的事；这里只回答"现在有哪些报警在响"。

悬浮暂停（2026-10-26）：鼠标停在条上立刻停住，移开继续走。 恢复时扣掉暂停时长而不是清零重来——清零会让文字瞬间跳回起点，正在读的人直接跟丢。

属性默认说明
ScrollModeTickerTicker = 单行跑马灯（默认）；List = 卡片列表（带时间与状态，占地方）
ScrollSpeed60跑马灯速度（像素/秒，10~300）
AutoScroll / SecondsPerRowTrue / 2.5只在 List 形态生效：逐行下移、到底回顶

实现要点：位移 = 视口宽 − (累计秒 × 速度) mod (文本宽 + 视口宽)， 按累计时长取模，漏拍/卡顿不会越走越偏；文字用 Run 按严重度上色； 断言 [AB-T1]（从右缘出发、走完一圈回起点）与 [AB-T2]（空文本不滚、拼接跳过空项）已钉住。

纵向自动滚动保留为 List 形态的能力（老工程配了 List 也不会变样）； 新拖入的报警条默认走跑马灯，高度建议 34~40px。
