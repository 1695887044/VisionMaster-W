01

需求与设计判断

先定"它到底是什么"，再谈长什么样。

这个需求本质是一张滚动历史表（一个产品一行，逐件追加），不是"把某个对象的结构画出来"。 所以设计上把两件事拆开：列是设计期的数据（用户自己配），行是运行期的数据（宿主按列取值、按信号采一行）。

方案本版理由
列定义 + 信号采行 做 直接命中"历史 SN / 角度 / 结果 / MES"；不碰变量系统与插件契约，纯 Scada.Controls + 宿主一个供数服务。
绑定一个集合变量 阶段 2 绑定管线只在"值变了"时推送；算子往同一个 List 里 Add 时引用没变，表格不会刷新（R138 同族）。要做得先定"集合变更通知"的口径。
反射任意用户自定义类 不做 要在 .vms 里存类型（本仓刻意用字符串 TypeKey、不用 $type）、设计期定义字段、运行期反射取列、还要兼容旧版本。代价远超"四列、每件一行"。
这一版要回答的四个问题
  • 设计态：这个图元在画布上长什么样、选中时给出什么反馈？
  • 配置：列怎么加、怎么排、每列绑哪个变量？
  • 运行：一行什么时候产生？满了怎么办？
  • 异常：没数据 / 断连 / 变量找不到，用户看到什么？
不做的事：不做排序、不做筛选、不做单元格编辑、不做导出——那是「报警历史」那种独立页面的活。 图元只负责"把最近 N 条摆出来给人看"。

三条硬口径：① 数字列（角度）用等宽字体 + tabular-nums，列与列之间数字对齐才扫得动； ② 状态色只表达状态（OK 绿 / NG 红），不做装饰；③ 新行插入时**不滚动、不抢焦点**——现场正在看历史时被拽走是最烦的， 所以默认"新行在上"，最新一条永远在第一行。

复刻要点（踩过的坑，别重犯）
点要求来源
表格控件 用 ListView + GridView，不要用 WPF DataGrid：它自带编辑/排序/虚拟化一整套，样式在 Fluent 下更难压，而且我们要的只是"只读展示"。 取舍
隐式样式 必须挂 GridListViewStyle（否则 Fluent 的隐式 ListView 样式会让**列头整体消失**）、行模板里必须是 GridViewRowPresenter（否则整行显示成类型全名）、就地合并 GridView.xaml。 R19–R22
ToggleButton 若标题条上有展开/折叠开关，自定义模板里的 ToggleButton 必须显式 HorizontalAlignment="Stretch"。 R148
数字列 等宽字体 + 右对齐；格式化走不变文化（F2），否则中文系统上小数点是逗号。 R34
列定义落盘 一条规范 JSON 进属性袋（新 ElementPropertyKind.ColumnList + codec），与轴候选同构；不存 CLR 类型。 照抄
行数据来源 图元不认识变量：宿主侧新增 IScadaGridSource 每拍按列取值，图元只接 Rows 快照（与 IScadaAxisSource 同构）。 照抄
收录确认 采行成功之后，经 IScadaValueWriter 把确认变量 +1；写失败只记诊断、不回滚已入表的行（边沿判定保证不会重复采）。配置期就校验目标可写，别等运行期。 复用
07

待确认

这几条定下来，第 ③ 步就能直接开工。

#问题我的建议备选
1采行触发已定：信号上升沿（false→true 采一行），默认不复位——采行信号由 PLC / 流程自己落，图元只读可选「采行后复位」（图元写回变量，需目标可写，且顺序必须"取值→落行→复位"）；手动命令（多一个状态机）
2缓存行数上限默认 100，可配到 500；超过就丢最旧的一行不设上限——内存与渲染都会失控，不建议
3行序默认新行在上（最新一条永远第一行，不用滚动）老行在上 + 自动滚到底（现场看历史时会被拽走）
4要不要导出 CSV第一版不做，只做展示要的话做成事件动作「导出当前表格」，别塞进图元模板
5结果列的值映射列上配 1=OK / 0=NG，映射后按状态色显示不配就显示原值；第一版只做"文本 + 可选状态色"
6列宽单位像素（与属性面板其它尺寸一致），最后一列可填「余量」百分比——缩放时表现更好，但与其它属性不统一
7「已收录」怎么让流程知道已定（方案 A）：加可选的「收录确认变量」，每采一行 +1；采行信号本身不动，图元对它是只读的B：流程自己置采行信号；C：图元复位采行信号（不推荐）
