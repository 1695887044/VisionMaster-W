## 定位

按 `AGENTS.md` §30.1 的四步流程，本目录是**第 ① 步（Web 设计基线）**的产物：

```text
① 设计基线（本目录） → ② 设计定稿与令牌映射 → ③ WPF 复刻 → ④ 同屏同状态截图验收
```

- Web 只是**设计媒介**，不进入构建、不部署、不作为第二个客户端维护（R126）；
- 基线确认后只读，调整需升版本（v1 → v2）并同步令牌映射（R128）；
- 本版**只审设计**，不改任何 WPF/XAML 代码。

## 需求

现场：测一个产品的角度，同时要看到**历史记录**——产品 SN、角度、结果，以及 MES 回传的信息。

它的本质是**一张滚动历史表**（一个产品一行、逐件追加），不是"把某个对象的结构画出来"。

## 记录与确认的边界（2026-10-21 定）

**默认口径：采行 = 信号上升沿，图元只读，不复位信号。**

- 上升沿本身就保证不重复采（信号保持高不会再触发），复位的唯一作用是"让下一个产品能产生新边沿"；
  这件事默认由 PLC / 流程自己落。
- **图元不承担"记录系统"的角色**：它是**显示缓冲**（最近 N 行、切页重建、断电即失）。
  需要留痕的，用现成的「CSV 记录」插件（`Plugin.DataRecord`：每执行一次追加一行、可存 NG 图、异步写盘不占节拍）。
- **所以"流程怎么知道被记录了"——默认不需要知道**：表格记录失败不影响产品质量判定，流程该干嘛干嘛。
  表格负责"看得见"，CSV 记录负责"留得住"。

**如果现场确实要一个"已收录"信号**（要给 PLC 或流程一个确认）——**已定用方案 A**：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A（已定）** | 属性面板加可选的「**收录确认变量**」：宿主每采一行把它 **+1**，**采行信号本身不动**（图元对它是只读的） | 走现成 `IScadaValueWriter`，不改引擎；目标变量必须可写 |
| B | 让流程当触发器：流程末尾用「变量赋值」把采行信号置 1，图元采行 | 流程天然知道自己做过这一步，但采行不再是"外部事件" |
| C（不推荐） | 图元采行后写回采行信号本身（复位） | 把"读"变成"写"，还要跟 PLC 抢这一位的语义 |

**方案 A 的三条实现口径**：

1. **写"累加计数"而不是脉冲**——脉冲总得有人复位，那就又回到 C 的坑里；计数是自洽的，PLC 判"变了"即可，人也能看出"一共记了多少行"。
2. **先落行、再写确认**；写失败只记诊断，**不回滚已入表的行**（边沿判定保证不会重复采，下次上升沿照常采）。
3. **配置期校验可写性**（IO 输入变量只读、通讯变量要有写通道），不可写就当场标红，别等运行期。

**三条不可省的纪律（若改走 C）**：① 顺序固定"取值 → 落行 → 复位"；② 复位失败只记诊断、不回滚已采到的行
（边沿判定保证不会重复采）；③ 目标变量不可写在**配置期**就标红，别等运行期。
另：**四列必须取自同一拍快照**，否则复位后 PLC 立刻换数据会攒出"SN 是上一个、角度是下一个"的脏行。

## 三个设计决策（本版的核心）

| # | 决策 | 为什么 |
| --- | --- | --- |
| 1 | **列是设计期的数据，行是运行期的数据** | 列（表头/宽度/对齐/格式/绑哪个变量）由用户在设计态配好、存进图元属性；行由宿主按列取值、按信号采一行。两件事分开，图元就不需要认识任何 CLR 类型。 |
| 2 | **不做"反射任意用户自定义类"** | 要在 `.vms` 里存类型（本仓刻意用字符串 TypeKey、不用 `$type`）、设计期定义字段、运行期反射取列、还要兼容旧版本——代价远超"四列、每件一行"。 |
| 3 | **行来源分两阶段** | 阶段 1 只做"信号上升沿采一行"；阶段 2 才做"绑定一个集合变量"。原因是绑定管线只在**值变化**时推送，算子往同一个 `List` 里 `Add` 时引用没变，表格不会刷新（R138 同族）。 |

## 复刻要点（踩过的坑，别重犯）

1. **用 `ListView + GridView`，不用 WPF `DataGrid`**：DataGrid 自带编辑/排序/虚拟化一整套，样式在 Fluent 下更难压；本图元只要只读展示。
2. **必须挂 `GridListViewStyle`**（R19）：否则 Fluent 的隐式 `ListView` 样式会让**列头整体消失**。
3. **行模板必须是 `GridViewRowPresenter`**（R20）：否则整行显示成 `VisionMaster.Models.Xxx` 类型全名。
4. **就地合并 `UI\Controls\Themes\Controls\GridView.xaml`**（R22）：断言宿主没有 Application，只挂 `{StaticResource}` 会在 XAML 解析期抛"找不到资源"。
5. **自定义模板里的 `ToggleButton` 必须显式 `HorizontalAlignment="Stretch"`**（R148）：Fluent 的隐式样式把它压成 `Left`。
6. **列定义落盘**：一条规范 JSON 进属性袋（新 `ElementPropertyKind.ColumnList` + codec），与轴候选 `ScadaAxisOptionsCodec` 同构；**不存 CLR 类型**。
7. **行数据来源**：图元不认识变量——宿主侧新增 `IScadaGridSource`，每拍按列取值攒行，图元只接 `Rows` 快照（与 `IScadaAxisSource` 同构）。

## 待确认（7 条，第 1、7 条已定）

| # | 问题 | 建议 | 备选 |
| --- | --- | --- | --- |
| 1 | 采行触发 | **已定**：信号上升沿，**默认不复位**（PLC / 流程自己落） | 可选「采行后复位」（需目标可写）；手动命令（多一个状态机） |
| 2 | 缓存行数上限 | 默认 100，可配到 500，超过丢最旧 | 不设上限（内存与渲染都会失控） |
| 3 | 行序 | 默认新行在上 | 老行在上 + 自动滚到底（会拽走正在看历史的人） |
| 4 | 导出 CSV | 第一版不做 | 要做就做成事件动作，别塞进图元模板 |
| 5 | 结果列值映射 | 列上配 `1=OK / 0=NG`，映射后按状态色显示 | 不配就显示原值 |
| 6 | 列宽单位 | 像素，最后一列可填「余量」 | 百分比（与其它属性不统一） |
| 7 | 「已收录」怎么让流程知道 | **已定（方案 A）**：可选的「收录确认变量」，每采一行 +1；采行信号不动 | B：流程自己置采行信号；C：图元复位（不推荐） |

## 验收口径（第 ④ 步）

同一屏、同一状态截图对照，逐项核对：

- [ ] 深色画面上表格底 / 标题条 / 列头 / 分隔线与本页一致；
- [ ] 数字列等宽右对齐，小数点不随区域设置变化；
- [ ] NG 行左侧 2px 红条 + 结果胶囊为红；
- [ ] 空态 / 未配置 / 断连 / 列变量丢失四种文案与截图一致；
- [ ] 断连时保留最后一屏且灰化，不清空；
- [ ] 行数达到缓存上限后，最旧一行被挤掉、滚动位置不跳；
- [ ] `ScadaChecks` 的静态扫描（`[AI]`）与表格契约断言全绿。
