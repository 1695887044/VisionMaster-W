分类模型（.onnx）客户资产

支持相对路径（相对宿主程序目录），换机器部署时不用改配置。

ok-ng-classify.onnx
input: 1×3×224×224　output: 1×2
task=classify　2 个类别名（OK,NG）

只支持「图像分类」模型。检测 / 分割模型的输出格式不同，会被明确拒绝（不会拿错格式硬算）。

分类参数预处理

Letterbox = 等比缩放 + 补边（默认，不改变长宽比，最稳）；Stretch = 直接拉成方形。按训练该模型时的预处理来选，选错会让精度静默下降。

试算结果与 TopKText 里列出前 K 个类别。K 会被夹到 [1, 类别数]。

高级参数（多数场景不用动）

模型元数据里有静态尺寸时留 0 即可；模型是动态形状才需要手填（分类模型常见 224）。

关键改动（V1）
01
两栏固定分工左 356px 配置轨（输入 → 模型 → 参数 → 试算），右侧预览工作区自适应；窗口窄档左栏 300px，左栏内部滚动。
02
图像输入保持 LinkableValueEditorPort=Image / StepData 原样；只把内部 Label 置空、外置标签，🔗/✕ 仍由控件自带。
03
模型信息卡ModelSummary 原绑定；输入 / 输出形状、task、类别名在卡内等宽显示。加载失败时整卡切红（仅由既有摘要文本触发，不新增状态属性）。
04
参数表单三件套标签 12px / 控件 36px / 帮助 11.5px；ResizeMode 仍是枚举，TopK / InputSize 仍是 int；高级参数收进折叠区。
05
试算结果独立成卡Hint 与 ResultSummary 原绑定；结果卡等宽显示 TopK 概率，不做假进度条、不新增加载态。
06
预览按需创建ContentControl PreviewHost 绑 DisplayImage，模板内 ImageReadOnly HImage="{Binding Mode=OneWay}"；有图才创建，避免折叠后不重绘。空态/错误态是纯 WPF 覆盖层。
07
颜色全部令牌化映射 Colors.xaml / PluginConfigColors.xaml；视图 XAML 零十六进制；图标按钮 30×30 + Padding=0，焦点环走 DialogFocusVisual。
V1 契约保留（一个都不能改）
C1
DataContext = 插件实例 + IPluginConfigView宿主靠 viewObj.DataContext as IPluginConfigView 取 OnConfirm；不引入独立 VM。
C2
LinkableValueEditor（Image）Port / StepData 原样；端口持久化、类型转换、变量链接与解除链接都在控件里。
C3
ImageReadOnly.HImage = DisplayImage保留 HALCON 显示 / 缩放 / 右键菜单；控件类型与 DisplayImage 的释放语义不变。
C4
ModelPath / ResizeMode / TopK / InputSize四个 [StepConfig] 属性绑定与类型不变：string / 枚举 / int / int；UpdateSourceTrigger=PropertyChanged 不变。
C5
浏览 / 试算 / Hint / ResultSummary「浏览」仍写 ModelPath 并刷新摘要；「试算一下」仍走 TryPreviewClassify()；Hint / ResultSummary 原样消费。
V1 明确延后（需新增功能或契约）
D1
加载骨架 / 推理进度需要 VM 新增 IsPreviewLoading 或 PreviewState；当前只有 Hint / ResultSummary 文本。
D2
图像尺寸 / 文件大小需要 VM 新增只读属性（HImage.GetImageSize）；预览头只显示「只读 · 整幅图」。
D3
放大 / 缩小按钮HalconBase 只有 FitToWindow() / FitToImage()，没有公开 zoom 方法；只做「适应窗口 / 1:1」。
D4
打开所在文件夹需要新增 Process.Start("explorer.exe", ...) 行为；V1 不做。
D5
模型库 / 系统导航 / ROI 画框模型仍是外部文件路径；相机、系统设置等导航不进入本插件；分类整幅图，不吃 ROI。
