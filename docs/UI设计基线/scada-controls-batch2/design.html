01

设计原则

沿用 v1 的 11 条，只把与本批控件直接相关的 8 条落到可检查的判据上。

01

双上下文，一套结构

运行画面深色 #0E1318，编辑工作台浅色 #F4F7FB；控件结构、尺寸、状态完全一致，只换令牌。

02

五态是底线

Normal / Hover / Pressed / Focus / Disabled；过程控件再加 Current / Dragging / Loading。缺态即视为未完成。

03

状态色只表达状态

灰=停、绿=运行、黄=警告、红=故障/报警；accent 青蓝只做交互、焦点、当前项，不占用语义色。

04

数字等宽

时间、数值、坐标、计数一律 tabular-nums；小数点在列里排成一条线。

05

触摸命中 ≥44

运行态按键 / 菜单项 / 滑块拇指最小命中 44×44；桌面鼠标档不低于 36×36。

06

不造死属性

每个可配属性必须在运行态有可见效果；只接现有属性 / 命令，不新增“主题 / 皮肤”类空开关。

07

失败可见

写入失败、变量丢失、无权限、越限都要就地反馈；不许静默回弹或假装成功。

08

只读不伪装

没有写通道时输入控件必须是只读外观；没有权限时不给“能点但点了报错”的假按钮。

Hmi.ComboBox · 只读显示 P0

它已经是状态文本的 80%：Mode=Output 只读、Options 做值→文字映射、SelectedText 已把值翻成文字。缺的只是“别长得像禁用下拉框”。

结论：不新增 Hmi.StateText。现有 ComboBoxElement 已有 Mode=Output（只读）、Options（映射）、SelectedText（显示文本）；新建控件会把这三样再写一遍。需要补的是呈现方式，不是数据能力。

04

运行窗口顶栏 · 页面菜单 P0

运行窗口已经有顶栏（页名 / 报警 / 停止）；把页名换成下拉，就是全局页面菜单。它不需要每页放一个图元，也不会被画布裁剪。

结论：不新增 Hmi.PageMenu。页面导航是运行窗口的 chrome，不是画布内容；放在顶栏一处，所有页面共享，也不用担心被图层/裁剪/缩放影响。画布内需要导航时，用现有 Hmi.Panel + Hmi.Button + Navigate 组合即可。

验收与待裁定

设计稿确认后才进入令牌映射与 WPF 复刻；复刻前先冻结下面 6 个裁定项。

复用优先：每个建议都能回答“现有控件是什么、改了什么、为什么不能只改属性”。

只新增 1 个 TypeKey：Slider；其余是 ComboBox/AlarmBanner/DataGrid 的扩展或运行时设施。

向后兼容：ComboBox 默认 Presentation=Field、AlarmBanner 默认 ShowRowAck=false，老方案外观不变。

失败可见：越限、写入被拒、变量丢失、无权限、确认失败都有就地反馈。

Web：每个控件标注 M1 / M1.5 / M2 / M3 / 非目标；页面菜单在 web 隐藏。

不重复：与 v1 的 16+7 候选逐项对账；StateText / PageMenu / HistoryTable 已删除，RecordList 已降级。

Q1

ComboBox 未命中值：保留 #999 还是加一个 UnknownText？ 建议 保留 #值：现有实现刻意“难看但诚实”，不编造一个假的“待机”；真要友好文案就把映射表补全。

Q2

页面菜单放顶栏还是画布？ 建议 顶栏：全局导航一处维护，不受画布缩放/裁剪/图层影响；画布内需要时用 Panel + Button 组合。

Q3

AlarmBanner 行内确认默认开还是关？ 建议 默认关（保持现有外观），新项目在属性面板打开；确认回写变量留空 = 不写。

Q4

DataGrid 历史源现在做还是等契约？ 建议 等 IScadaHistorySource 定稿后再排期；本稿只冻结视觉与列定义。

Q5

Slider 写入时机：松手一次还是 100ms 节流？ 建议 松手一次；只有“必须连续跟随”的场合才开节流，并配危险确认。

Q6

软键盘是否必做？ 建议 看部署形态：触摸屏/无物理键盘必做；纯鼠标键盘工控机可降到 P2。弹窗则是 P1 结构件。
