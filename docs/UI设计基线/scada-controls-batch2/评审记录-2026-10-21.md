## 二、运动安全（motion）

| # | 风险 | 结论 |
| --- | --- | --- |
| M1 | Slider 直接写“目标位置/速度”变量，绕过 `MotionCommandGate` | 位置/速度类目标**不许**由 Slider 直接写变量；只能“编辑目标值 + 显式执行”，执行走 `IScadaAxisCommandSink.TryMove` |
| M2 | 门禁不判速度上限 | Slider 增加独立硬上限（常数，不被 `MinVariable/MaxVariable` 覆盖）；写入前 clamp 并提示 |
| M3 | 默认权限 = 任何人 | 运动量预设 `RequiredRole` 默认 Engineer；与轴控台 `CanOperate` 同口径 |
| M4 | `ConfirmDanger` 默认 false、`Throttled` 100ms | 运动量强制 `Release` + `ConfirmDanger=true`（不可关）；Throttled 只允许非运动量 |
| M5 | 弹窗遮罩可能盖住“停止运行” | 弹窗层只覆盖画布区；顶栏/底条永远可点；含运动参数的弹窗禁止点遮罩关闭 |
| M6 | “确认”被当成“复位” | 行状态区分“已确认（条件仍成立）”与“已恢复”；`AckVariable` 明示“不得接运动复位/清警”；清运动报警只走 `MotionClearAlarm` |
| M7 | web 侧 `cmd.input` 不过运动闸 | Slider 在 web 默认只读；运动量写入需要独立闸；Throttled 与 2/s 限速不兼容 |

## 三、通信 / PLC（comm）

| # | 风险 | 结论 |
| --- | --- | --- |
| C1 | `AckVariable` 的 0→1/累加未定；`long` 直写会覆盖相邻寄存器 | 默认 `Counter`（当前值 + changed，按声明类型归一），可选 `Latch`（Bool，PLC 消费后清 0）；不做 Pulse；只在 `changed>0` 时写 |
| C2 | 确认写与引擎确认同步阻塞 UI | 引擎 ack 与 PLC 回写拆两段；回写后台/插队；UI 显示“确认已生效，握手发送中/失败可重试” |
| C3 | 重复确认/断线重连导致多计 | 同一 AlarmId 飞行中禁用按钮；counter 不自动重试；latch 重试幂等；失败原因原样上屏 |
| C4 | 历史查询时间错位/文件跨午夜/旁路文件 | 按行时间过滤、枚举 ±1 天、契约用 `DateTimeOffset` 并声明 TimeBase；旁路文件纳入或显式警告 |
| C5 | web 镜像被新动作旁路 | `NavigateBack/OpenPopup/ClosePopup` 加入 mirror-mode 排除清单；`cmd.input` 的上下限/确认校验要下沉到共享写入口 |
| C6 | 确认人缺口 | `ScadaAlarmRecord` 只有 `AcknowledgedAtUtc`，没有确认人；设计里的“张三 14:29 已确认”需要新增字段（公共契约，待决） |

## 四、视觉 / 现场（ui / vision）

**ui 的关键结论**：

- 只读字段底线必须与 IOField 同色（`#7A7A7A`，约 3.96:1），不能用 `HmiBorder`（1.42:1）。
- 标签复用基类 `Text`，字号 14、Auto 宽、gap 8；不要固定 56px、不要 11.5px。
- 内边距 0/8、高度 32，不要 3/7/10；`is-dense` 用 12.5，不用 13。
- 状态矩阵固定深色导致浅色证据缺失；README 的验收表要写明“浅色在 WPF 阶段补”，或补浅色对照。
- 顶栏设计 48/52 与现有 chrome（约 26px、页名 14px SemiBold）不一致；这是“重做 chrome”，不是“把页名换成下拉”。
- AlarmBanner 行 58px vs 现有 44px；行内按钮 24-26px 违反 44px 触摸命中；现有严重度是胶囊，不是 3px 色条；已确认 0.72 vs 现有 0.5；`ShowRowAck=false` 必须与当前模板逐像素同构。
- DataGrid 历史模式缺 30px 标题条/24px 脚注；OK/NG 胶囊不是现有 cell 模型能力；行高 33 vs 28；默认 720×300 不是 320。
- 组合示例的状态卡没用新的只读字段；18/13px 不在七档；“3 条未确认”与“未确认 2 / 共 3”矛盾；趋势线硬编码 `#38BDF8`，浅色下几乎消失。

**vision 的关键结论**：

- 控件层够用，但视觉设备的主线（OK/NG 大屏、计数、型号、相机/光源健康、图回看）没有一项成为可验收项。
- 状态文本要补两条口径：数值状态用 `Hmi.Text` + `DisplayFormat`；字符串状态（SN/型号）也用 `Hmi.Text`，不要拿可写 IOField 显示。
- 报警行必须保留 Detail（条件/触发值）与 Help（原因/措施），不能为了塞确认按钮挤掉。
- 历史数据应升 P1（追溯是视觉核心），补 SN 搜索、结果筛选、型号/配方列、`ImagePath` 留位；`AutoRefreshSeconds` 默认 0。
- 滑块对视觉设备是 P2：曝光/亮度是相机 SDK 参数，滑块只写变量≠改相机；适合阈值/补偿，不适合运行屏拖曝光。
- 旋转/缩放动画对视觉设备是 P3/不做。
- 弹窗不要用于 NG 复判（遮罩挡图）；复判走普通页面。
- 软键盘：视觉站多为键鼠工控机；数字键盘 P1、字符键盘 P2，纯键鼠部署整体 P2。

## 五、评审后的优先级修正

| 项 | 原 | 修正 | 理由 |
| --- | --- | --- | --- |
| 返回上一页 | P0 | **P0**（含 `IScadaNavigator.GoBack` + `CanGoBack` 通知） | 成本低，但接口/通知是前置 |
| ComboBox 只读呈现 | P0 | **P0**（复用基类 `Text`/`TextAlignment`，删 `Label`） | 状态文本载体；结果色另做预设 |
| 顶栏页面菜单 | P0 | **P0**（自动列表 + `CanGoBack` 通知；手动配置后置） | 全局导航；页面角色闸门放领域层 |
| 软键盘 | P0 | **P1 数字 / P2 字符**；触摸部署才升 P0 | 视觉站多为键鼠工控机 |
| 弹窗 | P1 | **P1**（模型 + 动作契约 + 当前表面闸门） | 不是纯浮层；NG 复判走普通页 |
| 滑块 | P1 | **P2**（运动安全三档 + 硬上限 + Engineer + Release/Confirm） | 视觉运行屏不拖曝光；位置类走 `TryMove` |
| 报警逐条确认 | P1 | **P1**（统一确认服务 + 审计 + AckWriteMode；确认人字段待决） | 桌面审计缺口是硬缺口 |
| 历史数据 | P2 | **P1**（先定 `IScadaHistorySource`；补 SN 搜索/型号列） | 视觉核心是追溯，数据已在 CSV |
| 旋转/缩放动画 | P2 | **P3/不做** | 视觉现场无用；模型改造大 |

## 六、评审后已改的设计

1. ComboBox 只读字段：底线改 `#7A7A7A`（与 IOField 同色）、标签 14/Auto、gap 8、内边距 0/8、高度 32；`is-dense` 12.5。
2. 删除“空值 → —”；“绑定丢失”改为“保留最后一次有效值 + 橙点”；新增“值 0 有映射”状态。
3. 属性表删除 `Label`/`TextAlignment` 的“新增”口径，改为复用基类；`ShowSeparator` 在 Field 模式下隐藏/置灰。
4. 本记录 + README 增加“专家评审”段落与修正后的优先级。

## 七、仍未决

- `AckWriteMode` 默认 Counter 还是 Latch（建议 Counter）。
- 确认人字段是否本批加（建议下批，公共契约变更）。
- 页面菜单手动排序/改名的存储（`.vms` vs `AppConfig.json`；建议本批只做自动列表）。
- 弹窗“当前表面”闸门的具体形状（建议 `CurrentPage + PopupPage`，由宿主统一）。
- `IScadaHistorySource` 的最小接口（建议按 comm 的草案：Sources + QueryAsync + 错误码 + 取消）。
- 运动量 Slider 是否本批做（建议 P2，先做非运动连续量）。
