目标与现状实证

先把「为什么改」钉在证据上：以下四处都来自本次提供的真机截图与源码，不是口味问题。

实证 1 · 工具提示

系统黄底 ToolTip 盖住动作卡

截图 4 中「按下」事件的长描述以 11px 黄底浮层出现，宽度超过面板、遮住动作卡与「添加动作」。根因是行级 ToolTip 未挂样式，吃了系统默认模板。

实证 2 · 标签截断

64px 标签列装不下 6 个字

截图 1 的「背景不透明…」、截图 3 的「曲线 1…」都被省略号截断；完整名称只能悬停才知道，而悬停又触发实证 1 的大浮层。

实证 3 · 空值占位

背景图空值显示孤立的「..」

截图 1 的背景图行在缩略图与「选择…」之间只剩两个点；「清除」按钮在空值时仍常驻，看起来像可点。

实证 4 · 折叠无摘要

事件 / 动画勾选后看不出配了什么

「加载完成」折叠时只有一个勾；「外观变化」折叠时只有一个勾。要确认配了几条动作、几档、绑了哪个变量，必须逐条展开。

设计原则 1

信息架构不动

组名、组序、行、落盘键、显示名、可绑语义全部沿用 ScadaPropertyGroups / 描述符；本稿只改「怎么画、怎么给反馈」。复刻时不需要动模型与 .vms。

设计原则 2

一屏能扫，状态在行上

绑定、非法、只读、未完成、搜索命中都在行内直接表达；不靠悬停猜、不靠展开确认。折叠状态用摘要与错误点兜住。

!
不做什么：不新增属性、不改分组、不改落盘值、不做运行时主题切换、不把面板改成卡片流。WPF 复刻只允许使用 Border / Path / TextBlock / Grid / ScrollViewer / Popup / DropShadowEffect 能表达的效果。

尺寸与排版

  • 面板宽 300px（Shell.xaml 的 DockWidth=300）；左描边 1px。
  • 组头 32px；行 32px（26px 控件 + 上下 3px）；组间只靠 hairline 与 2px 间距。
  • 列：80px 标签 + 1fr 编辑器 + 26px 槽；槽位恒定，不可绑行也占位。
  • 字体：Microsoft YaHei UI 12px；组头 12.5 SemiBold；辅助 11px；计数 10.5px；十六进制等宽 11px。
  • 控件圆角 6px；色块 4px；动作卡 6px；取色板 8px。
  • 动效：组展开 / 箭头 150ms ease-out；不做位移动画（高频操作）。

复刻与断言

  • 只改 ScadaPropertyView.xaml / ScadaEventEditor.xaml 与两个行 VM；不动模型与 .vms。
  • 颜色全部走 StaticResource Scada*；新增文件不得出现 #RRGGBB（R140）。
  • Tooltip 用 keyed 样式，避免影响其他面板（R30-R32 / R135）。
  • 标签列 / 槽位宽度的断言：现有 ScadaChecks 若钉了 64，需要同步改快照（R65：改断言必须重建再跑）。
  • 新增 7 组断言：标签列 80、颜色 hex 可见、事件摘要、动画摘要、组错误点、搜索计数、曲线卡（若选 B）。
