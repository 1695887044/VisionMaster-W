00

v1 复审结论与 v2 设计原则

v1 是「忠实复刻现有 WPF」的保守稿；本轮按「现代化、简洁、层次感」重新评审，允许推翻。

复审 1 · 层次扁平

全面板一个节奏，扫不到重点

组头 32px + 行 32px 完全均匀，分隔只有一条发丝线；长面板（趋势 34 行）滚到哪里、哪组有错，全靠记忆。

复审 2 · 标签列是根矛盾

固定左标签在窄面板必截断

64px 截断、80px 勉强；而成对数值（X/Y、宽/高）、布尔行、事件行根本不需要左标签——一半行在为不需要的标签付宽度。

复审 3 · 行数虚高

成对数值各占一行

X/Y、宽/高、偏移、值域全部单行单列，天然成对的字段被拆散，面板长度翻倍，滚动距离长。

复审 4 · 绑定态占行

绑定带挂在行下，越绑越长

每绑一个变量面板长 20px；绑定多时「值输入 + 绑定带」双份信息，视觉权重还颠倒了（该突出的是绑定来源）。

复审 5 · 复合行无容器感

事件/动画只是文字行加勾选

「勾选=存在」与「展开=编辑」语义耦合，展开区与普通行无视觉边界，动作卡悬浮在面板底色上。

复审 6 · 输入是框中框

灰底上画白框，视觉噪音大

白底描边输入铺满灰底面板，几十个描边框抢视线；现代工具用「底色差」表达输入区，聚焦才给描边。

v2 五条设计原则

① 三层深度：雾白面板底 → 纯白卡片（淡蓝灰描边 + 极浅投影）→ 浅灰 filled 输入（无边框，聚焦才亮描边）。层次靠底色差，不靠三层描边。

② 混合标签：长文本字段用上标签；成对数值一行两列；其余左标签 72px。规则三条，消灭截断。

③ 复合配置卡片化：事件/动画是折叠卡——勾选管「配没配」，箭头管展开，摘要常显；动作/档位卡有序号与状态条。

④ 绑定即状态：绑定后输入框本体变成变量 chip（ƒ + 变量名 + ✕），不另占一行；ƒx 按钮实心。

⑤ 语义色收敛：晴空蓝=可交互/焦点/选中；琥珀=待完成；赤红=错误/危险；苔绿=成功。四色各管一件事。

信息架构：一处结构变化，其余不动

唯一结构变化：多曲线趋势的 4 条曲线收成「曲线卡」（颜色点 + 名称 + 值 + ƒx 同行），4 个曲线颜色从「外观」组移入「数据」组卡——外观组 8 → 4，数据组 11 → 7。落盘键全部不变。

其余不动：组名与组序沿用 ScadaPropertyGroups；行、显示名、Choices、可绑语义、事件/动画/权限的模型全部不动；面板宽仍是 300px。

呈现升级（不影响模型）：卡片化分组、折叠记忆、搜索强制展开、组头错误点、折叠全部按钮、对象头内联标题、底部 dock 页签。

v1 → v2 差异清单

v1 已归档为 design-v1.html；本表是重构的全部决策点。

#v1（已归档）v2（本稿）理由成本
1分组 = 组头 + 发丝线，直接铺在面板底色上卡片化分组：纯白卡 + 淡蓝灰描边 + 极浅投影，卡间距 8px；折叠即收成一条卡头三层深度；长面板的位置感与折叠目标明确S
2全部行共用「左标签 80 + 编辑器 + 槽」混合标签：左标签 72（颜色/下拉/单数值）+ 上标签（名称/文字/说明）+ 成对网格（X/Y、宽/高、粗细/圆角、字号/字重）消灭截断；成对行数减半M
3输入 = 白底 + 描边（框中框）filled 输入：浅灰底无边框，聚焦白底 + 主色描边 + 柔光；高 26 → 28降噪；聚焦态更明确S
4绑定 = 行下 20px 绑定带绑定 chip 替换输入框（ƒ + 变量名 + ✕），行高不变；曲线卡内为行下小 chip（列窄）绑定态是「值被谁驱动」，应替换值而非追加M
5事件/动画 = 文字行勾选 + 内联展开折叠卡：头部 = 勾选 + 名称 + 摘要 + 箭头；配置中的卡头晨雾蓝底；展开区有边界存在/展开解耦；容器感M
6趋势数据组 11 行平铺（方案 A/B 待定）曲线卡定稿：4 行「色点+名称+值+ƒx」+ 3 行设置；4 个曲线颜色自「外观」移入数据组（外观 8→4，数据 11→7）每条曲线一行闭合；落盘键不变L
7对象头 = 图标块 + 名称 + 类型键 + 锁定保留结构；图标块晨雾蓝底 + 主色线性图标；类型键等宽字体；页面模式显示尺寸 chip身份更清晰S
8工具行只有搜索搜索 + 「折叠全部/展开全部」图标按钮（状态切换）长面板一键收纳S
9搜索时折叠组可能藏住命中搜索期间命中卡强制展开，计数「命中/总数」，清除后恢复折叠搜索永不漏M
10组错误聚合、动画摘要等 Q1~Q8 未定全部按 v2 默认实现：组头错误点、动画摘要、颜色 hex、单位、图片空值占位、只读锁图标评审遗留项一次收口M
11面板底灰 + 白描边输入，6px 圆角体系卡片 10px 圆角、控件 7px、chip 6px；阴影只有卡与弹出层两层现代视觉基线S
12底部 dock 页签默认样式34px；选中项主色 + 2px 下划线；hover 石板灰加深与卡片语言一致S

Q1卡片化分组是否接受

v1 是「去卡片化」（省宽度），v2 反转为卡片化（要层次）。300px 下卡体编辑器约 187px，仍可用。

建议：接受。层次感与折叠收益大于 11px 宽度损失。

Q2混合标签布局是否接受

上标签 + 成对网格会改变行节奏；WPF 复刻是三种 DataTemplate，不是一种。

建议：接受。截断与行数问题一次解决。

Q3绑定 chip 替换输入是否接受

绑定后看不到当前值（值由变量驱动）；解绑后回到输入框。曲线卡内为行下小 chip。

建议：接受；若现场要看值，可在 chip 后附只读小字当前值（备选）。

Q4曲线卡定稿（外观组 8→4）

4 个曲线颜色移入数据组卡；分组计数与 ScadaChecks 快照需同步。

建议：定稿；这是 v2 唯一的结构变化。

Q5事件卡「勾选=存在」与箭头解耦

未配置的事件没有展开区；配置了的事件折叠时显示「N 个动作」。

建议：接受；语义与现有模型一致，只改呈现。

Q6控件高 26 → 28

行高从 32 变 34；面板更长但更透气。紧凑档（24px）可留给表格类面板。

建议：接受 28；如需回 26 只改一个变量。
