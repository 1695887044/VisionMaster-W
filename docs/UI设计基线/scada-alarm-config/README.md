## 1. 为什么出这份基线

报警配置是现场唯一"运行中也会打开"的配置弹窗：温度超限了，操作工第一反应是点开它把阈值调高两度。它现在的界面能跑，但有四个结构性问题：

1. **判定值藏起来了**：断线报警的判定秒数只在展开区里，表格「阈值」列给它一个「—」；而四限报警的恢复条件（阈值 − 回差）在任何地方都没写出来。用户要改一个数，得先知道这个数在哪个角落、是不是真的会生效。
2. **能编辑的地方不可信**：断线的「延时（秒）」可以填，填了引擎不采信（`ScadaAlarmEngine.cs:572` 明确跳过 Stale）。界面允许输入而语义上无效，是最坏的一种"能点"。
3. **反馈离现场太远**：重名失败只在弹窗顶部出一条红条（`ScadaAlarmConfigDialogView.xaml:201-219`），而犯错的输入框在表格里；「关闭」是整屏唯一的深色主按钮，视觉上像"确认提交"，实际什么也不提交。
4. **新建出来的报警是"半成品"，界面不说**：`AddAlarm()` 的默认值是「自动命名 `报警_N` / 高限 / 阈值 0 / 未选变量 / 启用」（`ScadaDocument.cs:817-831`）。引擎对未绑变量的槽直接空转（`ScadaAlarmEngine.cs:555-558`），这条"已启用"的报警在运行态永远不会报；而阈值 0 又意味着一旦选上变量、任何正值都会立即触发。两件事在现有界面上都看不出来——v2 补了「新增行」画面专门说这两句。

本稿按 R110/R111 补齐六项设计基线（布局/间距/配色令牌/字号字重/五态/交互细节），**不改扁平表格这个既定结构**——源码头注释给出的理由是现场最常见的动作是"把这一列的数值挨个调一遍"，这个理由成立，本稿保留并把它做扎实。

## 3. 设计目标

1. **一眼看出"哪几条在跑、哪几条被停用、哪几条还没配完"**——标题栏给 共 / 启用 / 严重 三个数，出现半成品时再补一个琥珀色「缺变量 N」；停用行文字降一级、勾选框空着。
2. **判定值必须出现在表格里**——四限给阈值，断线给 `5 s`，布尔给「—」；展开区只放"这一条特有的东西"。
3. **不生效的东西不出现**——断线不显示回差与延时，并用一句话说明为什么；不能用的动作给可见理由，不给"点了才知道"。
4. **"配了但不生效"必须自己举手**——未绑变量的行、停用的行、阈值还是默认 0 的新行，都要在扫表时就能看出来，而不是等运行态"怎么没报"再回头查。

## 4. 布局（R111 ①）

```
920 × 640（WPF 现尺寸；列宽按"压到 860 仍不横向滚动"预留）
┌──────────────────────────────────────────────────────────────┐ 44 标题栏
│ 🔔 报警配置                             共7·启用6·严重2       │
├──────────────────────────────────────────────────────────────┤ 48 工具栏
│ [+ 新增报警] [🗑 删除] │ [组 全部 ▾]  显示 2/7 清除  [搜索……] │
├──────────────────────────────────────────────────────────────┤
│ 名称      监视变量    种类    阈值  报警等级  启用 报警组      │ 34 表头
│ ─────────────────────────────────────────────────────────────│
│ 通讯-触发变量断线 PLC_Trigger▾ 通信断线▾  5 s 严重▾ ☑  通讯▾  │ 46 行
│ ▸ 详情块（选中行正下方）：规则句 / 种类相关数值 / 四个长文本   │
│ …                                                            │
├──────────────────────────────────────────────────────────────┤ 56 底栏
│ [↶ 撤销「…」]  hint                                [关闭]     │
└──────────────────────────────────────────────────────────────┘
```

- 表格吃满标题栏与底栏之间的高度；详情块是**选中行的下一行**，不是表格末尾（现状是 `RowDetailsTemplate`，本来就跟着行走；Web 稿把详情块紧贴在各自行后面）。
- 表格外层保留滚动条（现状 `HorizontalScrollBarVisibility="Disabled"`，本稿改为按需出现——列宽已经收得住 860，禁用横滚不再必要）。
- 「选择变量」从工具栏撤掉，副操作只剩「删除」；变量列自己就是选择器。
- 底栏只放全局动作：撤销、状态提示、关闭。没有「确定」——这是既定的即时写回语义，本稿不引入提交按钮。
- 标题栏计数默认是 `共 / 启用 / 严重` 三个数；**只有存在"已启用但没绑变量"的行**才追加琥珀色「缺变量 N」（见 §7.1 新增行）；**只有运行中**才在计数左侧出现绿色「运行中」chip（第 9 态）。
- 报警组列限宽 **138 = 输入 112（可伸缩）+ 历史箭头 24 + 间隙 2**；箭头贴着文字，不再吃满整列剩余宽度（D13）。
- 阈值格右侧预留 20px 给单位，与表头 `padding-right` 同一条竖线（D15）。

### 7.3 功能介绍栏（设计批注）

每个画面的右侧固定一栏「功能说明」：一句本屏用途 + 3~5 条按区域编号的说明。它解决的是"设计稿离开作者就没人看得懂"的问题——评审不必先读源码，就能知道每块在做什么、为什么这样排。

- **只用于评审**：不属于 WPF 界面，不参与复刻；「隐藏说明」或 `?notes=0` 可去掉。
- **九个画面各有自己的文案**：同一个区域在不同画面里讲的不是同一句话（表格在默认态讲编辑、在筛选态讲口径、在错误态讲"只标一格"）。
- **事实来源**：阈值 / 回差 / 断线的语义按引擎口径写，新增行按 `AddAlarm()` 的真实默认值写（与 F16/F17 一致），不是营销文案。
- **布局**：920 弹窗 + 24 间距 + 360 批注栏；批注栏最大高 640，超出滚动，不改变弹窗尺寸。

## 10. 已知偏差（R129/R130）

1. **主按钮白字对比度 2.77:1**，未达 WCAG AA 小字 4.5:1。既有 `DialogPrimaryButton` 令牌问题，不是本页引入；改主色是全局批次，本稿沿用现令牌。
2. **字体**：Web 稿用 Noto Sans SC，WPF 走系统微软雅黑，字宽有 2~5% 差异；列宽按实际渲染微调。
3. **图标**：稿内为 16px 线性 SVG 占位，WPF 走 Font Awesome 6 Pro Solid，形态有差异，尺寸按 14/16 对齐。
4. **滚动条**：浏览器 8px 悬浮条，WPF 17px 常驻条，表格可用宽度少约 9px；`920` 下最后一列需再留 12px 余量。
5. **展开行**：Web 稿用 `display:table-row` 瞬时展开；WPF `RowDetails` 不做高度动画（避免每帧重排），直接出现。
6. **严重度配色**：配置用 Dialog 令牌（`#EF4444`/`#F59E0B`/`#0EA5E9`），运行态用 `#FFE03A2B`/`#FFFFB020`/`#FF3B82F6`；本稿不混用，也不改运行态。
7. **无深色模式**：App 当前无运行时主题切换（R140 边界），本稿只覆盖浅色。
8. **新增行提示是瞬时态**：稿里静态展示"刚新增"的一屏；真实实现中「缺变量 N」是派生计数（持续到绑上变量），而详情块里的琥珀提示只在新建后尚未离开该行时出现（P5）。**稿面不能证明它何时消失**，复刻后要按 P5 定的生命周期单独验。
9. **筛选 / 回执 / 错误画面不画详情块**：这是稿面的取景约定，不是"这些态禁止展开"。真实 WPF 选中即展开（`VisibleWhenSelected`），复刻截图会与稿面存在这一处结构差，属于预期差异。

| P5 | **新增行提示的生命周期** | **现状没有"刚新增"信号**：`OnAdd` 只做「追加行 + `SelectedRow = row`」（`ScadaAlarmConfigDialogViewModel.cs:216-237`），行对象上没有任何瞬态标记 | 详情块提示只在"刚新增、尚未离开该行"时出现；「缺变量 N」计数则持续到绑上变量或取消启用 | 需要在行上新增一个瞬态标记（不入模型、不进撤销栈）；若改判"一直提示到绑定"，更吵但更难漏，需在 §9 增一条差异 |

实现备注（不改语义、但必须一起做）：

- 撤销/重做会增删 `Alarms` 集合 → 弹窗要订阅 `ScadaEditHistory.Changed` 与 `Alarms.CollectionChanged`，重建行并保留选中与滚动位置，否则撤销一次添加会留下幽灵行。
- 阈值单元格与展开区不能同时可写同一个字段（D2）：约定**主表负责 `Threshold` / `StaleSeconds`，展开区只负责回差、延时（四限）与长文本**。
- `ReportError` 需升级为"行 + 列"定位，才能做 D6 的行内错误；文案仍由 VM 出（"已存在同名报警 [X]，请更换名称（已恢复为原名）"）。
- 计数 共/启用/严重/**缺变量** 全部从行集合派生（缺变量 = `IsEnabled && 变量未绑定`），写回与勾选变更后重算；不要另存一份状态。
- 停用行样式必须走 `DataTrigger`（`IsEnabled=False`），且不能与单元格自己的 hover/focus 样式打架——行级只改前景色，**不要**给整行设 `Opacity`（会连错误红一起淡掉，且低对比度不可读）。
- 「空方案」与「搜索无结果」是两个分支：`Alarms.Count == 0` vs `Alarms.Count > 0 && 过滤后 == 0`，不能共用一个 `Visibility`。
- 新增后滚动到底并聚焦名称格（`ScrollIntoView` + `FocusManager`）；失败不要静默，至少落一条日志——这条是 D17 的动作，不是纯视觉。
