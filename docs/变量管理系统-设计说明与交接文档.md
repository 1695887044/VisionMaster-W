## 一、这套系统是什么

**一句话**：给上位机软件（VisionMaster）提供一个"变量中心"，让用户既能创建**本地变量**（软件内存里存值），也能创建**网络变量**（和 PLC 等设备实时读写），并随方案文件保存/加载，为将来画布组态（HMI）预留了绑定接口。

**通俗比喻**：
- 本地变量 = 你自己 notebook 上记的数字，想改就改；
- 网络变量 = 贴在 PLC 上的"便利贴"：软件上看着的是**复印件**（镜像值），改写时才真正通知 PLC 本人。

**为什么要有它**：视觉检测流程中，算子需要输入输出数据（检测结果、判定阈值、PLC 交互信号），这些数据需要一个统一、可监控、可持久化的"仓库"，并且仓库里的东西能和现场设备实时同步。

## 二、核心概念扫盲

| 概念 | 通俗解释 |
|------|---------|
| **本地变量** `LocalVariableModel` | 只活在软件内存里。默认值/当前值都在本机，读写零延迟。 |
| **网络变量** `NetworkVariableModel` | 挂在某个通信连接（如 Modbus TCP、西门子 S7）上的变量，值来自设备。 |
| **轮询（Polling）** | 通信管理器每隔一段时间自动去设备"读一眼"，不需要用户手动刷新。 |
| **镜像值（Mirror）** | 轮询读回来的值存在软件内存里，UI 绑定读的是这个"复印件"，**不会**每次刷新都去问设备（那样会把 UI 卡死）。 |
| **INPC 通知** | `BindableBase` 的属性变化通知机制。值一变，绑定的 UI 自动跟着变，无需手写刷新代码。 |
| **桥接器** `NetworkVariableBridge` | 变量和通信管理器之间的"管家"：变量一创建它就自动接线，一删除就自动注销。 |
| **DTO 快照** `VariableDto` | 保存方案时，把变量的"户口信息"（名字、类型、地址、轮询周期）拍成一张平面快照存进文件。加载时按快照"复活"变量。 |
| **反射** | 程序运行时按名字找类、造对象的能力。这里用于解决"Core 层不能引用 Communication 层"的架构限制。 |
| **DependencyProperty / 数据绑定** | WPF 的 UI ↔ 数据自动同步机制，本文不赘述，只需知道"绑定了就会自动更新"。 |

**分层规则（重要）**：
- `Core`：变量模型、DTO、接口 —— 不知道"通信"具体怎么实现；
- `Communication`：具体协议连接、通信管理器；
- `VisionMaster`（主程序）：UI、桥接器、持久化服务 —— 把两者粘起来。

Core 层**不允许**反向引用 Communication 层（否则架构会打结），这正是后面"反射重建地址"出现的原因。

## 五、核心代码逐个讲解

### 5.1 NetworkVariableModel — 网络变量（最核心）

位置：`Core/Models/Variable/NetworkVariableModel.cs`

**三个关键成员**：

```csharp
// ① 绑定通信管理器：变量创建后必须调用，否则不认识设备
public void Bind(ICommunicationManager manager) => CommunicationManager = manager;

// ② 轮询镜像更新：通信管理器轮询到新值后调这里
public void UpdateMirrorValue(object? newValue)
{
    if (SetProperty(ref _value, newValue))          // 触发 INPC → UI 自动刷新
        _valueChanged?.Invoke(this, EventArgs.Empty);
}

// ③ 读：纯镜像（不碰设备！）；写：直通设备
public object? Value
{
    get => _value;                        // getter 只读内存 → UI 绑定绝不卡顿
    set
    {
        if (SetProperty(ref _value, value))
            WriteToDevice(value);         // setter 写设备 → 一次赋值即下发
    }
}
```

**为什么要这样设计（重点理解）**：

| 设计 | 原因 |
|------|------|
| getter 只读内存 | WPF 界面可能有几十个地方绑定同一个变量，每次界面刷新都会调 getter。如果 getter 里去读设备（网络 IO 毫秒级），界面必然卡死。 |
| 写放 setter | 代码写起来最自然：`netVar.Value = 100;` 一句话就下发到 PLC。 |
| `UpdateMirrorValue` 不走 setter | 轮询回来的值如果走 setter，会又写回设备，造成"读→写→读"死循环（自激）。所以镜像更新必须绕过 WriteToDevice。 |

`WriteToDevice` 内部：取连接 → 转原始值（工程值→原始值）→ `connection.Write(地址, 值)`。注意**当前实现失败时静默吞异常**（见[改善点](#九已知问题与可改善点)）。

### 5.2 CommunicationVariable — 通信层数据点

位置：`Core/CommunicationContracts/CommunicationVariable.cs`

这是通信管理器轮询体系里的"登记卡"。关键点：

```csharp
[JsonIgnore]
public Action<object?>? MirrorCallback { get; set; }   // 桥接器接上的回调线

public void UpdateValue(object? newValue)
{
    if (!Equals(CurrentValue, newValue))   // 用 Equals 而不是 !=（装箱值类型引用比较恒不等）
    {
        CurrentValue = newValue;
        LastUpdateTime = DateTime.Now;
        MirrorCallback?.Invoke(newValue);  // 通知 NetworkVariableModel 更新镜像
        ValueChanged?.Invoke(this, newValue);
    }
}
```

数据接力：**轮询线程读到新值 → CommunicationVariable.UpdateValue → MirrorCallback → NetworkVariableModel.UpdateMirrorValue → INPC → 界面自动刷新**。

### 5.3 NetworkVariableBridge — 桥接器（管家）

位置：`VisionMaster/Services/NetworkVariableBridge.cs`

注册为**单例**（App.xaml.cs）。生命周期：

```csharp
// 构造时：订阅变量集合变化 + 对已有变量全量接线
public NetworkVariableBridge(IWorkspaceManager workspace, AdvancedCommunicationManager manager)
{
    workspace.GlobalVariables.CollectionChanged += (s, e) =>
    {
        if (e.NewItems != null) foreach (NetworkVariableModel nv in e.NewItems) Register(nv);
        if (e.OldItems != null) foreach (NetworkVariableModel nv in e.OldItems) Unregister(nv);
    };
    RebindAll();
}

// 接线 = 两件事：
private void Register(NetworkVariableModel nv)
{
    nv.Bind(_manager);                       // ① 告诉变量"你的通信管理器是谁"
    var cv = new CommunicationVariable {
        Name = nv.Name, ConnectionName = nv.ConnectionName,
        Address = nv.AddressConfig.Address, ...
        MirrorCallback = v => nv.UpdateMirrorValue(v),   // ② 接上镜像回调线
    };
    _manager.RegisterVariable(cv);           // 进入轮询体系
}
```

**使用效果**：在变量管理 UI 里新建网络变量，只需 `_workspace.GlobalVariables.Add(netVar);` —— 桥接器监听到集合变化，**自动完成 Bind + 注册轮询 + 接镜像回调**，无需任何手工接线。删除同理自动注销。

`RebindAll()`：方案加载后变量集合被整体重建，桥接器把旧注册清掉、对新变量全部重新接线。

### 5.4 VariableDto + VariablePersistenceService — 持久化

**为什么不用变量对象直接序列化？** `IVariable` 是接口、地址是多态对象，`System.Text.Json` 反序列化时不知道该 new 哪个类；且具体地址类在 Communication 程序集，Core 不能引用。所以保存的是**扁平快照**（只有 string/int 字段），加载时再"复活"。

```
保存方案（ShellViewModel.SaveSolutionAsync）：
  CaptureLayoutToConfig()                                   // 布局快照
  VariablePersistenceService.Capture(方案, workspace)        // 变量快照 ← 本系统
      → 遍历 GlobalVariables：
          本地变量 → VariableDto { VarType="Local", 名称/类型/默认值/当前值 }
          网络变量 → VariableDto { VarType="Network", +连接名/协议/存储区/偏移/位偏移/轮询 }
      → solution.VariableSnapshots = 快照列表（随 .vms 落盘）

加载方案（AutoLoadStartupSolutionAsync / OpenSolutionAsync）：
  Workspace.SwitchSolution(方案)
  VariablePersistenceService.Restore(方案, workspace)        // 清空集合，按快照重建变量对象
  _variableBridge.RebindAll()                                // 桥接器为新变量重新接线
```

**Restore 时网络变量地址怎么"复活"**（`VariableDto.BuildAddressConfig`）——这里是全文最容易迷惑的点，讲清楚：

1. 快照里存的是 `Protocol = "ModbusTcp"` 这样的**字符串**；
2. Core 层不能 `new ModbusAddress()`（那是 Communication 层的类）；
3. 运行时 Communication 程序集**必然已经加载**（主窗口依赖通信管理器）；
4. 所以用反射按全名 `VisionMaster.Communications.ModbusAddress` 在已加载程序集中找类型 → `Activator.CreateInstance` 造对象 → 反射设置 Area/DbNumber/Offset/BitOffset/DataType。

> 一句话：**编译时不能引用，就运行时按名字找人。** 代价是类改名后反射会静默失败（见改善点）。

`JsonToValue`：方案文件里数字/字符串/数组都是 JSON 原生格式，加载时按目标 Type 还原（含数组逐元素还原）。

`ServiceLocator.CommunicationManager`：Capture 时需要查连接的协议，Core 层服务拿不到 DI 容器，于是由 ShellViewModel 启动时把管理器塞进这个静态属性 —— **最小桥**，仅此一处，不要扩散使用。

### 5.5 GlobalVariableManagerViewModel — 对话框逻辑

位置：`VisionMaster/ViewModels/DialogViewModels/GlobalVariableManagerViewModel.cs`

UI 分四块逻辑：

**① 来源树（左栏）**：`SourceNodes` = 全部/本地/每条通信连接一个节点，带 Count（变量数）和 IsOnline（连接在线）。`SelectedSource` 切换 → `UpdateFilteredList` 过滤右侧明细。连接状态变化事件（`ConnectionStateChanged`）→ `RefreshSourceStates` 徽标联动变色。

**② 双模式新建（中栏）**：

### 5.7 通信层读粒度（历史 bug 修复，勿回退）

**Modbus**（`ModbusTcpConnection.Read<T>`）：一次读的**寄存器数**按类型定 —— short/bool=1，int/float=2，long/double=4（每寄存器 2 字节）。早期固定读 1 导致 int/float 只读到半截。
注意 `RegisterCount` 里写的是 `System.Type.GetTypeCode`，因为本类有个实例属性 `Type` 遮蔽了系统类型。

**S7**（`SiemensS7Connection.Read<T>`）：一次读的**字节数**按类型定 —— bool/byte=1，short=2，int/float=4，long/double=8，取自 `HslHelper.MinByteCount`（与轮询批量解码同一张字节表）。
⚠ 勿回退成 `Marshal.SizeOf<T>()`：它对 `bool` 返回 **4**（Win32 `BOOL` 尺寸），会让 `Read<bool>` 多要 3 个字节，靠近区末还会越界读失败；值常"碰巧对"（`ConvertTo<bool>` 只取首字节）所以藏得住。未知类型（decimal/DateTime）`MinByteCount` 返回 0，此时才回退 `Marshal.SizeOf`。断言见 CommChecks C11 组。

**S7 位地址**（`S7Address.BuildAddress`）：位访问独立分支，无类型前缀 —— `M0.0`、`DB1.DBX0.0`，而不是错误的 `MX0.0`。

### 5.8 IVariableDisplaySource — HMI 预留接口

位置：`Core/Models/Variable/IVariableDisplaySource.cs`

```csharp
public interface IVariableDisplaySource : INotifyPropertyChanged
{
    string BindingKey { get; }      // 绑定键 = 变量名（画布控件序列化只存名字）
    string DisplayLabel { get; }    // 显示标签
    Type DataType { get; }          // 控件据此选编辑器
    object? Value { get; }          // 当前值（INPC 自动刷新控件）
    string SourceLabel { get; }     // "本地" 或 连接名
    bool IsReadOnly { get; }        // 只读来源输入控件禁用
    void WriteValue(object? newValue);  // 控件写回入口
}
```

`LocalVariableModel` 和 `NetworkVariableModel` 都已**显式实现**该接口（显式 = 不污染模型自身的公开 API，必须转成接口才能访问）。只读规则：Modbus 离散输入区、S7 输入映像区（I）只读。

**将来画布用法预览**：控件序列化时只存 `"BindingKey": "温度设定"`；运行时按变量名在 `GlobalVariables` 里解析出对象 → `(control.DataContext as IVariableDisplaySource)` 绑定 `Value`/调用 `WriteValue`。**零适配成本**。

## 六、五条数据链路（时序）

**链路 1：轮询读（自动，最重要）**

```
通信管理器轮询定时器（按连接 ReadCycleMs 调度）
  → 连接.Read<T>(地址)            （Modbus 按寄存器数 / S7 按字节数）
  → CommunicationVariable.UpdateValue(新值)     （Equals 判断有变化才走）
  → MirrorCallback(新值)
  → NetworkVariableModel.UpdateMirrorValue(新值) （SetProperty → INPC）
  → 界面上所有绑定该变量的控件自动刷新
```

**链路 2：写设备（用户触发）**

```
UI 点"写值" → WriteValueCommand → 弹窗输入 → Convert.ChangeType 转型
  → netVar.Value = 新值
  → setter → WriteToDevice → connection.Write(地址, 原始值)
  → （稍后）轮询读回新值 → 镜像更新 → UI 显示设备真实值
```

**链路 3：创建网络变量**

```
UI 填表 → AddCommand → 构造地址对象 → Validate → VariableFactory.CreateNetwork
  → GlobalVariables.Add(netVar)
  → 桥接器监听到 → nv.Bind(manager) + RegisterVariable(带 MirrorCallback)
  → 立即进入轮询体系（创建即上线）
```

**链路 4：保存方案**

```
Ctrl+S → CaptureLayoutToConfig → VariablePersistenceService.Capture
  → 遍历变量生成 VariableDto 快照（网络变量从连接配置查协议）
  → 存入 solution.VariableSnapshots → 序列化 .vms 文件
```

**链路 5：加载方案**

```
启动自动加载 / 手动打开 → LoadAsync 反序列化
  → SwitchSolution → VariablePersistenceService.Restore（清空重建变量，网络变量反射重建地址）
  → bridge.RebindAll()（旧注册清掉，新变量全部重新接线）
  → 轮询恢复，镜像值开始刷新
```

## 七、使用手册（手把手操作）

### 步骤 1：确保有通信连接

先在通信管理界面建好连接（如 `PLC_Modbus`，127.0.0.1:502，Modbus TCP）。没有连接也能建本地变量，网络变量必须选连接。

### 步骤 2：打开变量管理

菜单打开"变量管理"对话框（1180×660 三栏窗口）。

### 步骤 3：建变量

- **建本地变量**：中栏选"本地变量"（绿胶囊）→ 填变量名 → 选数据类型（支持 int/double/string/bool 及其数组）→ 可填描述 → 点"＋ 创建变量"。
- **建网络变量**：选"网络变量"（蓝胶囊）→ 出现网络专属区 → 选所属连接 → 存储区自动按协议填充（Modbus: 线圈/离散输入/输入寄存器/保持寄存器；S7: DB/I/Q/M/V）→ 填偏移量（如 `100`）→ bool 类型可填位偏移（0~7）→ 轮询周期默认 1000ms → 点"＋ 创建变量"。

创建成功即自动进入轮询，右栏"当前值"列会随设备实时刷新。

### 步骤 4：监控与写值

- 左栏点某个连接，右栏只显示该连接下的变量；搜索框支持按名称/描述/地址过滤。
- **写值**：网络变量行点"上传"图标（✈）→ 弹窗输入新值 → 确定后直写设备，随后镜像回读刷新。
- **数组**：本地数组变量点初始值/当前值列的"编辑集合..."展开逐元素编辑，行下可展开 [0][1][2] 子行实时看每个元素。
- **状态徽标**：来源列圆点绿=连接在线，红=掉线（打开对话框期间自动联动）。

### 步骤 5：保存 / 加载方案

- 保存方案：变量快照自动随方案写入 `.vms`，无需额外操作。
- 打开方案 / 启动自动加载：变量自动重建并恢复轮询，打开变量管理即可看到全部变量。

### 步骤 6：变量名被谁引用

流程/算子绑定变量用的是**变量名**。点操作列"复制"图标可快速复制变量名到剪贴板。

## 八、设计优势

1. **UI 绝不卡顿**：网络变量 getter 纯读内存镜像，网络 IO 全部隔离在轮询线程，绑定界面几十个控件也不怕。
2. **创建即上线，零手工接线**：桥接器自动完成 Bind/注册/镜像回调/注销，业务代码只需 `GlobalVariables.Add(...)` 一行。
3. **持久化闭环对称**：Capture/Restore 成对出现，挂接点只有 ShellViewModel 三处（保存 + 两个加载），职责清晰。
4. **架构边界干净**：Core 不知道具体协议；地址对象靠反射重建，协议可扩展（新增协议只需：地址类 + DTO 协议分支 + 连接类）。
5. **写值语义自然**：`netVar.Value = x` 一行直通设备，符合"变量"的直觉。
6. **HMI 预留零成本**：`IVariableDisplaySource` 已被两类变量实现，将来画布控件按名绑定即可，不用改现有模型。
7. **UI 状态自解释**：来源/在线/地址徽标一眼看清变量健康状况，联调现场问题定位快。

## 九、已知问题与可改善点

> 交接必读：以下是当前实现的**真实短板**，按优先级排列，接手者可从此入手。

### P1（建议尽快处理）

1. ~~**网络变量不支持 string 类型（隐患）**~~
   ✅ **已修复**：网络模式下数据类型下拉改绑 `FilteredTypes`（过滤文本与所有数组，仅留 int/double/bool 标量）；切换胶囊时非法类型自动回落；`AddNetworkVariable` 入口保留兜底校验弹窗。

2. **写设备失败静默吞异常**
   `NetworkVariableModel.WriteToDevice` 里 `catch { }`。连接掉线时写值"看起来成功、实际没写进去"，UI 还会弹"已写入"提示。
   **建议**：失败时通过 `Notifier.ShowError` 或日志上报，并考虑给 `IVariable` 加写入结果回调。

3. **反射重建地址依赖"类名 + 程序集已加载"**
   `VariableDto.FindCommunicationType` 按字符串全名找类。谁重命名 `ModbusAddress`，旧方案加载时**静默丢变量**（`Restore` 里 `continue` 跳过）。
   **建议**：重建失败时收集清单，加载完弹提示"以下变量因协议不支持未能恢复：xxx"。

### P2（体验/健壮性）

4. **写后回读延迟窗口**：写设备后到下一次轮询回来之间，UI 显示的是 setter 写入的值而非设备真实值。若写失败或被 PLC 覆盖，短时间 UI 与设备不一致。可考虑写后立即触发一次单点读。
5. **变量级 `PollIntervalMs` 未生效**：字段已持久化，但当前轮询节奏由**连接级** `ReadCycleMs` 统一调度。要么实现变量级粒度，要么 UI 隐藏该输入避免误导。
6. **Connections 列表只在构造时填充**：对话框打开期间用户新建的连接不会出现在"所属连接"下拉（重开对话框才行）。可在 `OnDialogOpened` 里刷新。
7. **位偏移输入无 0-7 即时校验提示**：超出范围时 `DeviceAddressBase` setter 会静默夹取，用户无感知。可加输入提示。
8. ~~**网络数组变量不支持**~~ ✅ **已随 P1-2 修复**：网络模式下数组类型已一并从下拉中过滤。

### P3（架构演进）

9. **镜像回调在轮询线程触发**：`UpdateMirrorValue` → INPC。WPF 标量属性绑定会自动跨线程封送所以现在没事，但将来若有人订阅 `ValueChanged` 后直接改 UI 集合（ObservableCollection）会炸。建议回调统一 `Dispatcher.BeginInvoke`。
10. **本地变量值变化触发整树重建**：`OnVariableValueChanged` 里 LocalVariableModel 走 `RefreshTree()` 全量重建，数组元素多时略浪费。可细化到单节点更新。
11. **HMI 绑定解析器未建**：`IVariableDisplaySource` 只是契约，"按名解析对象"的注册表/服务还没写（画布组态阶段的第一件事）。
12. **搜索不联动来源树计数徽标**：计数始终是全量数字，未随搜索过滤（影响很小）。

## 十、常见问题排错 FAQ

**Q1：网络变量当前值一直不动？**
按顺序查：① 左栏该连接圆点是否绿色（红=掉线）；② 连接的 ReadCycleMs 是否 > 0（轮询才会跑）；③ 地址对不对（Modbus 保持寄存器偏移 100 → 实际读 40101；S7 M 区偏移 0 → MW0）；④ 用设备模拟器（ModbusSlave / Snap7 Server）确认设备端值真的在变。

**Q2：写了值设备没收到？**
已知问题 P1-1：写失败被静默吞掉。先确认连接在线，再抓通信报文（Wireshark）验证。

**Q3：保存方案后重开，网络变量不见了？**
大概率是反射重建地址失败（P1-3），检查快照里 Protocol/DataValueType 字符串与枚举名是否一致（协议类是否被重命名）。

**Q4：int/float 读出来是怪数？**
确认 `Read<T>` 粒度修复还在（Modbus 按寄存器数、S7 按字节数）。如果有人改回固定读 1，int/float 只会读到半截数据。

**Q5：S7 布尔地址报错？**
S7 位访问格式必须是 `M0.0` / `DB1.DBX0.0`（无 X 前缀 + 位偏移）。位偏移默认 0，线圈区布尔不要填位偏移。

**Q6：新建变量后 UI 没自动接线？**
确认 `NetworkVariableBridge` 已注册单例（App.xaml.cs）、ShellViewModel 构造已注入、方案加载后有调 `RebindAll()`。

**Q7：想在画布上绑定变量，从哪开始？**
先做 P3-11 的解析服务：遍历 `GlobalVariables`，把实现 `IVariableDisplaySource` 的对象按 `BindingKey` 建字典，控件拿到字典按名绑定即可。
