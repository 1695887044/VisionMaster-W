> 5. 契约命名空间为 `Core.Interfaces`（非 `Core.Interfaces.Geometry`，与 `CalibrationTransform` 同口径）、有 `public` 无参构造供 JSON 反序列化（属性 init-only，仍不可变）。

## 约定（与配套插件共用，先读）

| 约定 | 内容 |
| --- | --- |
| 像素坐标 | `(Row, Col)`：Row 向下、Col 向右（与 HALCON 一致） |
| 角度单位 | **度**；线/椭圆主轴 `Phi` 归一化到 **0~180°**（与卡尺 `Angle` 同口径，消灭补角歧义） |

| 失败纪律 | 找不到/参数非法 → **明确失败**并给出"下一步"，绝不静默返回陈旧或"将就平均"的结果（同卡尺原则①） |
| 工程位置 | 插件工程**必须放 `Plugins\` 下**（红线①） |

## 一、背景与目标

### 1.1 现状（代码自述，不是判断）

| 事实 | 证据 |
| --- | --- |
| 卡尺**已输出**几何基元（`FittedGeometry` HXLD、`EdgePoints` HXLD），但**全仓没有任何插件有 `InputPort<HXLD>`**——基元是死胡同 | `Plugins\Plugin.CaliperMeasure\CaliperMeasurePlugin.cs:186,189`；grep `InputPort<HXLD>` 零命中 |
| 胶路检测同样只"出"HXLD，无人消费 | `Plugins\Plugin.BeadInspect\BeadInspectPlugin.cs:211,213` |
| 没有"查找型"几何算子：卡尺必须先选测量类型 + 填标准值/公差才能用 | `Plugins\Plugin.CaliperMeasure\CaliperEnums.cs:8` |
| 几何关系只以卡尺某个 `MeasureKind` 存在，无法在任意两个上游几何之间算 | `CaliperEnums.cs:14-37` |
| `PoseTransform` 只吃 `HImage`/`HRegion`/点，**不吃几何基元** | `Plugins\Plugin.PoseTransform\PoseTransformPlugin.cs:44-141` |

**结论**：平台有"出几何"的半边，缺"**吃几何 + 算几何**"的另半边。

### 1.2 目标（一期）

1. **查找型算子**：在 ROI 内亚像素找边/找轮廓并拟合，输出**类型化几何基元**；
2. **关系型算子**：对上游基元求交/取点/距离/夹角/关系判定/位置度/构造，输出数值或新基元；
3. **契约先行**：新增 `GeometryParam` 公共契约，使"基元 → 基元"的连线**编译期类型合法**（同类型端口 `IsAssignableFrom` 恒过），**运行期按 `Kind` 校验语义**（线/圆不匹配 → 明确失败）；
4. **不重造**：把卡尺的找边/拟合逻辑**抽成共享服务**供两处复用（见决策 4），不复制、不漂移。

### 1.3 非目标（一期不做，见 §十）

3D 点云、手眼标定、XLD 高级处理（分割/连接/多边形逼近）、基元自动乘当量、多相机基元统一。

## 二、关键设计决策

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 插件个数 | **2 个**（查找 / 计算） | `PreProcessing` 算子都是"图→图"同形状才能串一条链；"查找(图→基元)"与"计算(基元→数值)"输入类型不同，硬并成异构管道。细拆 5 个只多出 5 份样板 |
| 2 | 内部架构 | 查找仿 PreProcessing（注册表 + 链 + 弱类型快照）；计算仿 CaliperMeasure（单算子多模式，枚举分派） | 查找的"边缘提取→筛选→拟合"本身就是链；计算是"一次计算" |
| 3 | 基元契约形态 | **单一具体类 `GeometryParam`**（`Kind` 枚举 + 通用字段），不做继承体系；字段**不可变**（只读 + 工厂构造），输出即新对象 | ① 端口要 JSON 安全；② 继承体系要处理多态序列化，得不偿失；③ 代价（线端口可连圆输入）由运行期 `Kind` 校验兜住；④ **不可变**防下游 `Construct` 就地改字段污染上游同一对象（评审建议 b）。**注**：本契约**不进全局变量**（全局变量类型是宿主白名单 `GlobalVariableManagerViewModel.cs:489-504`，无自定义 DTO 通路） |
| 4 | 找边/拟合从哪来 | **抽取共享服务**：把卡尺的"阵列卡尺分布 + 边缘点收集 + 直线/圆拟合"抽到 `Services\Core.Halcon\Geometry\MeasureFitService.cs`，卡尺与新查找插件**同引用** | 评审阻塞项：卡尺的 `DistributeCalipers`/`CollectRegionEdgePoints`/`TryFitLine`/`TryFitCircle` 等**全是 private**、与私有 `MeasureParams`/`MeasureResult`、VM `CaliperRegions` 深度耦合，**无法原样复用**；复制会违背"消灭逐字副本"纪律。抽取触发 R12 闭环（reviewer + `docs/code-changes/` + **卡尺回归断言**） |
| 5 | 基元是否乘像素当量 | **不乘**；`MmPerPixel` 只在"数值输出"口乘 | 基元是"位置"的载体，乘当量破坏可组合性（求交/旋转要求同一坐标系）；长度类数值乘当量才有物理意义 |
| 6 | 角度口径 | **度**、`Phi` 归一化 0~180° | 与卡尺 `Angle` 完全一致 |
| 7 | 找不到时的语义 | 默认业务失败，提供 `IsFound` 输出；由 `FailOnNotFound` 决定 | 计量场景"找不到=失败"是安全侧默认；探测场景要能配 |
| 8 | 工程位置 | `Plugins\Plugin.GeometryFinder`、`Plugins\Plugin.GeometryRelation` | 红线① |
| 9 | 分组名 | 新建「**几何工具**」 | 与现有 15 个 GroupName 均不重叠，查找与计算同族独立成组；**待用户最终确认**（评审建议 d：也可并入「测量」/「定位」） |
| 10 | 并行安全 | 两插件类均标 `[ParallelSafe]`（纯视觉/纯托管计算，不写全局变量） | 评审问题五；未标注进并行分支会被 `FlowCompiler` 报 `[并行不安全]` |

### 3.1 新增契约：`Shard\Core.Interfaces\Geometry\GeometryParam.cs`

```csharp
namespace Core.Interfaces.Geometry
{
    public enum GeometryKind { Point = 0, Line = 1, Circle = 2, Ellipse = 3, Contour = 4 }

    /// <summary>
    /// 几何基元（跨插件传递的一等数据）。单类 + Kind 分派：JSON 往返安全、端口连线类型检查只认一个类型。
    /// **不可变**：字段只读，用工厂方法构造新对象；下游变换一律产新对象，不就地改（防别名污染上游）。
    /// 放 Core.Interfaces：契约层零 HALCON 依赖（同 CalibrationTransform）。
    /// </summary>
    public sealed class GeometryParam
    {
        public GeometryKind Kind { get; }
        public double Row { get; }        // 基准点：点/圆心/线中点/椭圆中心
        public double Col { get; }
        public double Phi { get; }        // 度，0~180 归一化（线法线 / 椭圆长轴）
        public double Radius { get; }     // 圆半径 / 椭圆长半轴
        public double Radius2 { get; }    // 椭圆短半轴
        public double[]? Points { get; }  // 轮廓/多点（[r0,c0,r1,c1,...]）

        private GeometryParam(...) { ... }   // 私有构造，只经工厂

        public static GeometryParam Point(double row, double col);
        public static GeometryParam Line(double row, double col, double phi);
        public static GeometryParam Circle(double row, double col, double radius);
        public static GeometryParam Ellipse(double row, double col, double phi, double r1, double r2);
        public static GeometryParam Contour(double[] points, double row, double col);

        public override string ToString() => ...;
    }
}
```

### 3.4 `[StepConfig]`（纯配置项）

**两个插件都没有 `[StepConfig]` 属性**——见 §3.2 / §3.3 的校正说明：所有可调项都是输入端口。
下表保留"像素当量取值优先级"这条口径（它是行为契约，不是配置项清单）。

**像素当量取值优先级**（与卡尺 `GetEffectivePixelSizeMm` 同口径，实现见 `GeometryRelationPlugin.cs:307-328` `TryResolveScale`）：
1. `MmPerPixel` 端口**已连线**且值有效（>0 且非 NaN/Inf）→ 用它（夹进 `[1e-9, 1e6]` 防极端值）；
2. `MmPerPixel` 端口已连线但值无效 → **明确失败**（不静默回退，因为上游标定本轮失败了）；
3. 端口未连线 → 用**该端口自己的常量值**（界面上手填的那个数）；≤0 或 NaN → `scale=1`，
   即输出**像素**值（不假装是 mm）。
   ★ 校正：几何计算**没有**独立的 `PixelSizeMm` 配置项（那是卡尺的写法）——手填值就存在 `MmPerPixel` 端口里。

## 四、算子 / 模式清单

### 4.0 链的载体与类型规则（**与 PreProcessing 唯一的差异**）

> **★ 实现口径校正（2026-10-13）**：本节与 §4.1 描述的"异构算子链"**没有实现**。
> 落地的 `Plugin.GeometryFinder` 是**单发**结构：`Kind`（直线/圆/椭圆）选一种拟合，
> 内部固定走 `GeometryHService.EdgeContours → LongestContour → TryFitLine/TryFitCircle/TryFitEllipse`
> （`GeometryFinderPlugin.cs:133-204`），没有 `GeometryChainValue` 载体、没有 `Operators/` 目录、
> 没有 `GeometryStepItem` 链快照，也没有逐步预览/禁用透传/单算子跳过这些链语义。
> 下文保留原设计供后续演进参考；**要看当前真实行为，以 §3.2 的端口表 + 代码为准**。
> §4.2（几何计算的 `Op` 多模式）则是**按设计落地了的**。

PreProcessing 的链是单类型流水线（`HImage → HImage`，`PreprocessOperator.cs:104-115`）。几何查找的链是**异构**的，必须显式定义载体：

```csharp
enum GeometryChainValue { Image, Contour, Primitive }   // 链上流动的三种载体
```

| 规则 | 定义 |
| --- | --- |
| 每算子声明 `InputKind`/`OutputKind` | 见 §4.1 表；链的合法性 = 前一步 `OutputKind` 与后一步 `InputKind` 相容 |
| **禁用=透传** | 该步不执行，载体**原样**流到下一步（透传的是"入参载体"，非图） |
| **单算子失败不拖垮链** | 记日志、跳过该步、载体原样透传（同 PreProcessing 铁律②） |
| **链末取基元** | 链末算子的 `OutputKind` 决定 `Geometry` 端口的 `Kind`；若链末是 `Contour` → `Geometry.Kind=Contour`（`Contours` 端口同步有值） |

### 4.1 几何查找 · 算子（`Operators/` 一个类一个算子，打 `[GeometryOperator(key,显示名,分组,Order)]`）

| 分组 | 算子 | Key | 链载体（入→出） | 实现来源 |
| --- | --- | --- | --- | --- |
| 查找 | 直线查找 | `line` | Image → Primitive | **共享服务**（阵列卡尺 `measure_pos` → `fit_line_contour_xld`，Tukey） |
| 查找 | 圆查找 | `circle` | Image → Primitive | **共享服务**（径向卡尺 → `fit_circle_contour_xld`） |
| 查找 | 椭圆查找 | `ellipse` | Image → Primitive | `fit_ellipse_contour_xld` |
| 轮廓 | 边缘/轮廓提取 | `edge` | Image → Contour | `edges_sub_pix`（canny/sobel） |
| 轮廓 | 轮廓筛选 | `contour_filter` | Contour → Contour | `select_contours_xld`（长度/方向/闭合） |
| 轮廓 | 轮廓拟合 | `contour_fit` | Contour → Primitive | 共享服务（线/圆/椭圆拟合） |
| 区域 | 区域转基元 | `region_to_geom` | Image → Primitive | `smallest_rectangle2`/`area_center`/`orientation_region`（源区域=链首 `MaskRegion` 或全图域） |

> 链语义：禁用透传、单算子失败跳过、逐步预览、复制/粘贴链、导出逐步图（全部照搬 PreProcessing）。

### 4.2 几何计算 · 模式（单算子多模式，仿 `CaliperMeasure.MeasureKind`）

| 分组 | 模式 | 枚举 | 输入 → 输出 | 单位/说明 |
| --- | --- | --- | --- | --- |
| 求点 | 求交 | `Intersect` | 线-线 / 线-圆 / 圆-圆 → 点 | 多解取第一（近平行/无交 → 明确失败） |
| 求点 | 取点 | `PointFrom` | 基元 → 点 | 中点 / 端点 / 垂足 |
| 求值 | 距离 | `Distance` | 点-点 / 点-线 / 平行线距 | `Value`：像素（乘当量后 mm） |
| 求值 | 夹角 | `Angle` | 两线 | `Value`：度（0~180 归一化） |
| 求值 | 关系判定 | `Relation` | 两线 + 容差 | `IsOk`：平行 / 垂直 |
| 圆 | 圆关系 | `CircleRelation` | 圆-圆 | `Value`：圆心距/同心度；`IsOk`：相切/包含 |
| 位置 | 位置度 | `Position` | 基元 + 基准 | `Value`：真位置偏差（mm） |
| 构造 | 构造 | `Construct` | 基元 + 参数 | `Geometry`：平移/旋转/过两点构线/三点构圆（**产新对象**） |

> 几何计算为**纯托管数学**（`Services\GeometryMath.cs`，不调 HALCON），可被断言完整覆盖（同标定决策 5）。

## 五、运行语义

| 分支 | 行为 |
| --- | --- |
| **每轮开头** | **显式重置所有非 `IDisposable` 输出**：`Geometry=null`、`IsFound/IsOk=false`、`Row/Col/Phi/Radius=0`、`Value=0`（HImage/HXLD 由基类轮首自动回收）。**必须**——非托管输出不会自动清零，否则失败轮下游读到**上一轮脏值**（卡尺 `CaliperMeasurePlugin.cs:796-803` 同款显式重置范式） |
| 查找成功 | `Geometry`=链末基元；`Row/Col/Phi/Radius`=对应字段；`Contours`=轮廓；`IsFound=true` |
| 查找失败 + `FailOnNotFound=true` | `Fail("几何查找：<算子名> 未找到 <基元>；请检查 ROI/极性/阈值")` |
| 查找失败 + `FailOnNotFound=false` | `IsFound=false`，其余输出保持（本轮已重置的）空值，流程继续 |
| `SrcImage` 未连线 | `Fail("几何查找：未接入图像")` |
| 计算模式输入 `Kind` 不匹配 | `Fail("几何计算：<模式> 需要 <线/圆>，实际收到 <Kind>")` |
| 计算数值类 | 按 §3.4 当量优先级：未接且 `PixelSizeMm=0` → 输出像素 |
| 计算判定类 | 带规格时 `IsOk`=落在公差内；未填规格（默认 0）→ 默认 NG（提示去填，同卡尺原则③） |
