# 第 0 章 这是什么

**区域颜色检查 = "这块区域是什么颜色？是不是我要的那个颜色？纯不纯？"**

> 生活比喻：产线上有个指示灯，你要判断"它现在是红灯还是绿灯"。人眼一看就知道；视觉里的做法是——在这块区域里**采一堆像素点，每个点判成颜色词（红/绿/…），然后投票**：票数最多的那个词就是"主色"，它占的比例就是"纯度"。两者都达标才合格。

它在流程里的位置（归在 **「图像处理」** 分组）：

```
[图像采集] → [创建 ROI] → [图像预处理] → [区域颜色检查] → [C#脚本] / [CSV记录] / [结果上报]
                                        ↓
        Color(主色) / Share(占比) / Rgb(中位色) / Table(明细) / Result(判定) / Verdict(结论)
```

**一句话**：Blob 解决"有没有缺陷"，卡尺解决"尺寸多少"，而 **区域颜色检查解决"它是什么颜色、纯不纯"**——典型场景：指示灯颜色、色标对不对、区域颜色纯不纯、某颜色占比够不够。

## 0.1 与「颜色序列检查」的分工

| | 区域颜色检查（本插件） | 颜色序列检查 |
|---|---|---|
| 认什么 | **一块区域**（ROI 内逐点投票取主色 + 占比） | **一个顺序**（沿一条线取一串颜色词，逐位比） |
| 典型场景 | 指示灯什么颜色、色标对不对、颜色纯不纯 | 线序、排线、色带 |
| 不看 | 不看顺序 | 不看占比 |

## 0.2 ⚠️ 三条最容易被误解的地方（务必先读）

1. **没有 RGB/HSV/Lab 颜色空间切换**。颜色空间是**固定的 HSV 式判据**（内部算 `s=(max−min)/max`、`v=max`、色相角度），不是可配项。
2. **不算颜色距离、没有 ΔE/容差半径**。判定是「逐点分类成颜色词 → 投票 → 主色 + 占比」，再比对「主色在不在期望词表里」+「占比 ≥ 阈值」。
3. **采样区不接上游 ROI**。采样区是插件内部画的 ROI 参数（`RoiShape` + `RoiParams`），上游只进 `Image`。

# 第 1 章 设计思想

## 1.1 核心原理：逐点分类 → 投票 → 主色 + 占比

```
采样区 ROI（矩形/圆/椭圆）
   ↓  展开成逐像素点集（点太多按步长抽稀）
逐点取 RGB（一次取回整批）
   ↓  每个点判成一个"颜色词"
{ 灰: 63, 蓝: 22, 白: 10, 绿: 5 }
   ↓  投票，票数降序
主色 = 灰，占比 = 63%
   ↓  判定：主色在期望词表里？占比 ≥ MinShare？
合格 / 不合格（并给出结论全文）
```

## 1.2 为什么是"逐点分类再投票"，而不是"取中位色分类一次"

> 区域里若一半红一半蓝，中位色可能是个"谁都不像"的颜色，却还是会被报出一个词——**现场看不出它其实没把握**。逐点投票会直接告诉你"主色红只占 41%"，这是"不纯"，不是"红"。

## 1.3 为什么用 HALCON 区域当掩膜（本插件最核心的卖点）

> **用方框去框圆形指示灯时，方框四个角是背景**。不作掩膜的话，背景像素会参与颜色投票，主色可能直接变成"背景色"，而且因为背景占比高，它还会"看起来很有把握"。用圆形区域就只剩灯上的像素。

## 1.4 颜色怎么分类（11 个颜色词）

判据层次（先判"有没有颜色"，再按色相分色系）：

```
无彩（饱和度 < 0.45）：
  明度 < 80            → 黑
  饱和度 < 0.15 且 明度 > 195 → 白
  偏暖（R 比 G/B 都高 ≥12）且 明度 < 175 → 棕
  其余                → 灰

有彩（按色相角）：
  [330,350) → 玫红    ≥350 或 <20 → 红
  [20,45)  → 橙      [45,70)  → 黄
  [70,160) → 绿      [160,230) → 蓝
  [230,330) → 紫
```

> 红与玫红只差十几度，分界取 350 度。
> 词表：**黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫**，外加通配符 `*`（只报不判）。

## 1.5 为什么每个算子各带一份阈值（而不是全局一份）

> 不同工位、不同产品的打光与材质不一样，"玫红从哪里算起"本来就可能不同；全局一份色卡会变成束缚（要么大家互相迁就，要么再支持多份、复杂度又上一层）。所以内核只提供**默认值**，各算子在界面上放一份可覆盖的副本，随方案落盘。

## 1.6 判定口径

| 情况 | 行为 |
|---|---|
| 主色在期望词表里 **且** 占比 ≥ `MinShare` | ✅ 合格 |
| 主色对但占比不足 | ❌ "颜色不纯：主色 X 只占 N%（要求 ≥ M%）" |
| 主色不在期望词表 | ❌ "颜色错误：实测 X（占 N%），期望 Y" |
| **期望为空** | ⚠️ **运行期报错**（不是默认通过） |
| 期望里写 `*` | ✅ 只报颜色不判定（用户显式写的"我要不检"） |

> 期望为空报错的理由：没配期望是**工程配置问题**，不该静默通过、也不该判成产品不良。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | 区域颜色检查 |
| `GroupName` | 图像处理 |
| `Description` | 在采样区里逐点分类投票，取主色与占比，与期望颜色比对（指示灯 / 色标 / 颜色纯度 / 占比） |
| `ShortName` | 滴管图标（FontAwesome `f043`） |

## 2.2 端口完整清单（全部固定端口，无动态端口）

| 端口 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `Image` | 入 | HImage | 待检查图像（`IsRequired = false`） |
| `Color` | 出 | string | **主色**（票数最多的颜色词，如「灰」「红」） |
| `Share` | 出 | double | 主色占比（0~1） |
| `Rgb` | 出 | string | 区域**中位色** `R,G,B`（如 `"140, 137, 140"`），排查与示教用 |
| `Table` | 出 | string | 各颜色词的占比明细（如 `灰:100%`） |
| `Result` | 出 | bool | 判定结论（true = 合格） |
| `Verdict` | 出 | string | 结论全文（写给人看的那一句） |

另有基类隐式端口 `Success`、`ErrorMessage`。

> ⚠️ **没有标注图输出端口**——结果画面走 `PublishPreview` 事件总线投到视图窗口，不是端口。

## 2.3 配置项

### 基础配置

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `RoiShape` | **string** | `"Rectangle"` | 采样区形状：`Rectangle` / `Circle` / `Ellipse` |
| `RoiParams` | `double[]` | 空 | 采样区参数，**固定 5 槽** |
| `ExpectedColors` | string | 空 | 期望颜色（多个用逗号/顿号分隔，命中任一即可）；`*` = 只报不判；**空 = 运行期报错** |
| `MinShare` | double | `0.60` | 主色最少要占多少才算合格（0~1） |
| `SamplePoints` | int | `400` | 区域内最多取多少个采样点（点太多按步长抽稀） |
| `DisplayViewIndex` | int | `1` | 结果投射到哪个视图窗口（1~9；**0 = 不投射**） |

### `RoiParams` 的 5 槽约定

| 形状 | 参数 |
|---|---|
| 矩形 | `[中心行, 中心列, 角度, 半长, 半宽]` |
| 圆 | `[中心行, 中心列, 半径, 0, 0]` |
| 椭圆 | `[中心行, 中心列, 角度, 半径1, 半径2]` |

> 统一 5 个是为了让存取、回填、断言都只有一条路径（圆的第 4/5 个占位不用）。

### 颜色判据阈值（13 项，界面「高级参数」里可覆盖）

| 阈值 | 默认 | 含义 |
|---|---|---|
| `ColorlessSaturation` | `0.45` | 无彩/有彩分界（饱和度） |
| `BlackValue` | `80` | 无彩且明度低于它 → 黑 |
| `WhiteSaturation` | `0.15` | 白要求饱和度低于它 |
| `WhiteValue` | `195` | 无彩且明度高于它 → 白 |
| `BrownWarmth` | `12` | 偏暖（R 比 G/B 都高出这么多）→ 棕 |
| `BrownValue` | `175` | 棕的明度上限 |
| `RoseHueFrom` | `330` | 玫红起点（色相度） |
| `RedHueFrom` | `350` | 红起点 |
| `RedHueTo` | `20` | 红止点 |
| `OrangeHueTo` | `45` | 橙止点 |
| `YellowHueTo` | `70` | 黄止点 |
| `GreenHueTo` | `160` | 绿止点 |
| `BlueHueTo` | `230` | 蓝止点（比它高就是紫） |

> ⚠️ **13 个属性名不能改**——共用控件 `ColorThresholdEditor` 靠 **DataContext 继承 + 按属性名绑定**，而 **WPF 绑定失败是静默的**（改名 = 绑不上，且没有任何报错）。

## 2.4 HALCON 算子清单

| 算子 | 作用 |
|---|---|
| `image.CountChannels()` | 判通道数（<3 直接报"要彩色图"） |
| `image.GetImageSize()` | 取宽高（越界判定、裁剪、文本夹取） |
| `gen_rectangle2` / `gen_circle` / `gen_ellipse` | ROI → 区域 |
| `gen_rectangle1` | 造整幅图矩形，用于裁剪 |
| `intersection` | **把 ROI 裁到图像内**（超出部分静默裁掉，不报错） |
| `area_center` | 取裁剪后区域面积（≤0 → 报"采样区与图像没有交集"） |
| `get_region_points` | 把区域展开成逐像素点集（这就是"网格采样"） |
| `access_channel` | 逐通道取单通道对象 |
| `get_grayval`（**元组版**） | 一次取回整批点的灰阶 |

> **为什么走元组版 `get_grayval`**：一次调用拿回整批点，比逐点调用快两个数量级；也不必把通道包成 HImage 去管句柄（那条路上踩过 HALCON `#4056 object-ID is NULL`）。
>
> **明确没用到**：`reduce_domain`、`rgb1_to_gray`、`trans_from_rgb`、`decompose3`、`intensity`、`select_shape`、`count_obj`。

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **区域掩膜采样** | 用 HALCON 区域而非方框 | ⭐⭐⭐ 圆框指示灯不会把背景投进来 |
| **逐点分类投票** | 不是取中位色分类一次 | ⭐⭐⭐ 直接暴露"不纯"，而不是给个看似有把握的错词 |
| **元组版 `get_grayval`** | 一次取回整批点 | ⭐⭐⭐ 快两个数量级，且避开 `#4056` |
| **均匀步长抽稀** | `stride = max(1, total/maxPoints)` | ⭐⭐ 点太多时抽稀，投票不偏 |
| **高位深归一** | >255 时等比压回 8 位 | ⭐⭐⭐ 12/16 位相机不会"黑永远判不出、白满天飞" |
| **一键示教** | 试算 → 把主色填成期望色 | ⭐⭐ 手打颜色词打错是常见坑，一键填从根上避开 |
| **越界静默裁剪** | ROI 超出图像部分裁掉不报错 | ⭐ 框得松一点是常事 |
| **推图失败不影响判定** | `catch {}` | ⭐⭐ 投递只是锦上添花 |

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.ColorRegion.dll`。
2. 依赖 HALCON 原生库。
3. 重开软件，工具箱里出现「区域颜色检查」（**图像处理** 分组）。

## 3.2 配置界面总览（两列）

```
┌──────────────────────────┬────────────────────────────┐
│ 左：参数（330px 可滚动）     │ 右：图像编辑器 ImageEdit     │
│  ① 图像输入（🔗链接上游）    │  ← 右键：新建矩形/圆形/椭圆   │
│  ② 采样区（+ 清空按钮）      │  ← 拖动手柄调整              │
│  ③ 检查参数                 │                            │
│     期望颜色 / 最小占比      │                            │
│     「试算一下」              │                            │
│     「把主色填成期望颜色」     │                            │
│     结果框                  │                            │
│     高级参数（Expander）     │                            │
│  ④ 怎么用 / ⑤ 分工说明       │                            │
└──────────────────────────┴────────────────────────────┘
```

## 3.3 第一次检查（4 步）

**第 1 步｜接图**：左栏「图像输入」点 🔗 绑定上游端口/变量（或画布拖线）。点「执行」试运行后，上游图会自动上屏。

> ⚠️ 图**只有上游端口一个来源**，界面上没有"载入本地图"入口。第一次点「执行」会报「尚未框选采样区」——那是对的。

**第 2 步｜画采样区**：右侧图上**右键 → 区域 → 新建矩形 / 新建圆形 / 新建椭圆**。

> 💡 **圆形指示灯请用「新建圆形」**——否则方框四角的背景会参与投票。

**第 3 步｜试算**：点「试算一下」，结果框显示：
```
主色：灰    占比：100%
中位色：140, 137, 140
明细：灰:100%
判定：颜色正确：灰（占 100%，期望 灰）
```

**第 4 步｜设期望颜色**（**推荐用一键示教**）：
- 点「把主色填成期望颜色」→ 自动把试算出的主色填进「期望颜色」。
- 也可手打：`红,玫红`（多候选命中任一即可）或 `*`（只报不判）。
- ⚠️ **手打必须正好落在 11 个词里**——写"深红"永远匹配不上。

## 3.4 参数调节速查表

| 现象 | 调哪里 |
|---|---|
| 主色判成背景色 | 采样区太大 / 形状不对 → 改用**圆形**贴合指示灯 |
| "颜色不纯：主色只占 N%" | ① 采样区框到了背景或多种颜色 ② `MinShare` 要求太高 |
| 12/16 位相机判色全错 | 已自动等比归一（日志会留说明）；中位色 R,G,B 是归一后的值 |
| 黑白灰棕大面积误判 | 同上（高位深未归一才会这样，现在已自动处理） |
| 玫红/红分不清 | 调 `RoseHueFrom` / `RedHueFrom`（默认 330 / 350） |
| 采样区与图像没交集 | 框到图外了，拖回图像内 |
| 只要看颜色不要判定 | 期望颜色填 `*` |
| 结果图不想投到主界面 | `DisplayViewIndex` 设 0 |

## 3.5 FAQ

**Q1** 期望颜色为空会怎样？
**运行期报错**（不是默认通过）。没配期望是工程配置问题。要"只报不判"请显式写 `*`。

**Q2** 为什么手打"深红"匹配不上？
颜色词只有 **黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫** 十一个。比对是按字面做的，词表外的词永远匹配不上。**用「把主色填成期望颜色」一键填**，从根上避开。

**Q3** 能接上游 ROI 吗？
**不能**。采样区是插件内画的 5 槽参数，上游只进 `Image`。

**Q4** 有 RGB/HSV 颜色空间切换吗？
**没有**。判据固定用 HSV 式（`s=(max−min)/max`、`v=max`、色相角度）。要微调的是 13 个色卡阈值，不是空间。

**Q5** 怎么判断"颜色距离"？
**没有距离度量**。判定 = 主色命中期望词表 **且** 占比 ≥ `MinShare`。

**Q6** 试算和正式运行一样吗？
试算**只做颜色分析、不做判定**——现场通常是先试算出主色、再一键填成期望颜色；若试算就要求"必须先填期望"，那个一手入口就永远用不上（顺序死锁）。**判定在运行期做，且必须做**。

**Q7** 结果图投到哪？
`DisplayViewIndex`（1~9）。合格绿字 / 不合格红字。推图失败不影响判定。

## 3.6 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| "尚未框选采样区" | 没画 ROI。右键 → 区域 → 新建矩形/圆形/椭圆 |
| "尚未配置期望颜色" | 期望为空。填词或填 `*` |
| "期望颜色里有认不出的词：…" | 手打词不在 11 个词里（如"深红"）。报错会列出可用词 |
| "采样区与图像没有交集" | 框整个画在图外了 |
| "采样点超出图像范围" | 框部分超出（越界点被检出），把框拖回图像内 |
| "要彩色图" | 输入是灰度图（通道 < 3） |
| 主色是背景色 | 形状不对（方框框圆灯）→ 用圆形 |
| 高位深判色异常 | 看日志里是否有"已等比压到 8 位"的说明 |

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与开发文档）。每条给：现象 → 原因 → 修法。

## 4.1 缺陷修复总览

| 级别 | 问题 | 一句话 |
|---|---|---|
| P0 | 枚举经 `InputValues` 往返抛异常 | `RoiShape` 改用 string |

## 4.2 P0/P1 级详解

### ① `RoiShape` 用枚举会抛 `InvalidCastException`

**现象**：枚举值经步骤的 `InputValues` 往返会抛 `InvalidCastException`。

**原因**：`InputPort` 的 setter 对枚举**只做硬转换**，不从数字/文本解析。

**修法**：`RoiShape` 用 **string** 而不是枚举。内核侧 `RoiShapeNames` 同样处理（这个坑在"变量赋值·作用域"上踩过一次）。

### ② 圆采样区回填被误挡

**现象**：圆形的采样区打开配置时不回填。

**原因**：回填的前提是"参数真的画过一个框"——矩形/椭圆看**半长**，圆看**半径**。但圆的第 4 个参数本来就是占位 0，**用半长判会把圆误挡掉**。

**修法**：按形状分别判断——圆看半径（第 3 槽），矩形/椭圆看半长。

### ③ 高位深相机判色全错

**现象**：12/16 位相机图上，"黑"永远判不出、"白"满天飞、灰/棕大面积误判。

**原因**：颜色判据的明度阈值（黑 80 / 白 195 / 棕 175）**按 8 位标定**，高位深图不压回去就全错。

**修法**：实测全通道最大值 `max`，`max > 255` 时 `k = 255.0/max` **等比缩放**。等比缩放不动色相与饱和度（它们是比值量），**颜色词的答案不变**。归一发生过就把说明带进 `warnings`（日志里能查到 R,G,B 为什么变小了）。

### ④ WPF 绑定失败是静默的

**现象**：改了阈值属性名后，界面上的阈值编辑器不生效，但**没有任何报错**。

**原因**：共用控件 `ColorThresholdEditor` 靠 **DataContext 继承 + 按属性名绑定**，没有接口也没有泛型。

**修法**：13 个属性名**不能改**（改名 = 静默绑不上）。这条代价写在代码注释里。

### ⑤ 视图被宿主外壳硬裁

**现象**：配置窗口显示不全（右侧被裁）。

**原因**：宿主 `PluginConfigShellView` 内容区只有 **864 × 484**，而视图写死 `Width="1000" Height="620"`。

**修法**：改 `MinWidth="700" MinHeight="360"` + `d:DesignHeight="484" d:DesignWidth="864"`。

### ⑥ 图像绑不上上游（两轮修复）

**现象（用户反馈）**：配置窗口里没有上游图像绑定的地方。

**修法（两轮）**：
- 第一轮：`ShowUpstreamImage` 把上游图自动搬到画布（构造函数订阅 `Image.PropertyChanged`）。
- 第二轮：配置窗口内加「图像输入」`LinkableValueEditor` 卡片。

> 两轮关系：`LinkableValueEditor` 解决"**怎么连**"，`ShowUpstreamImage` 解决"**连上之后怎么看**"。

### 案例 2｜一次取回整批点的 RGB（快两个数量级）

* 逐点调用 get_grayval 的开销会远超必要；元组版一次拿回整批

### 案例 3｜逐点分类 → 投票 → 主色（本插件的核心逻辑）

```hdevelop
* 每个点判成一个颜色词，然后投票
* 排序：票数降序；票数相同时按词表顺序定序（保证每次结果一致）
* 词表：黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫
Tally := dict{}
for i := 0 to |Rows| - 1 by 1
    Name := Classify(R[i], G[i], B[i])     * 见案例 4
    Tally[Name] := Tally[Name] + 1
endfor
Dominant := argmax(Tally)
Share    := Tally[Dominant] / |Rows|
```

### 案例 4｜颜色分类判据（HSV 式，纯算法）

```hdevelop
* 明度 V = max(R,G,B)；饱和度 S = (max - min) / max
mx := max2(R, max2(G, B))
mn := min2(R, min2(G, B))
d  := mx - mn
S  := (mx <= 0) ? 0 : d / mx
V  := mx

if (S < 0.45)                                  * 无彩分支
    if (V < 80)                      → 黑
    if (S < 0.15 and V > 195)        → 白
    if (R-G >= 12 and R-B >= 12 and V < 175) → 棕
    else                             → 灰
else                                            * 有彩分支：算色相
    if (d == 0)      H := 0
    elif (mx == R)   H := 60 * (((G-B)/d) mod 6)
    elif (mx == G)   H := 60 * (((B-R)/d) + 2)
    else             H := 60 * (((R-G)/d) + 4)
    if (H < 0) H := H + 360
    * [330,350)=玫红  >=350或<20=红  <45=橙  <70=黄  <160=绿  <230=蓝  其余=紫
endif
```

### 案例 5｜高位深归一（12/16 位相机必做）

```hdevelop
* 明度阈值黑80/白195/棕175 是按 8 位标定的。
* 12/16 位图不压回去：黑永远判不出、白满天飞、灰/棕大面积误判。
* 等比缩放不动色相与饱和度（比值量），颜色词的答案不变。
MaxVal := max over all channels and pixels
if (MaxVal > 255)
    k := 255.0 / MaxVal
    R := round(R * k)   G := round(G * k)   B := round(B * k)
    * 记一条 warning：中位色 R,G,B 是归一后的值
endif
```

### 案例 6｜圆/椭圆轮廓按折线画（别画成方框）

```hdevelop
* 投射时圆/椭圆不能只画一个方框，否则现场看不出到底采的是哪一块
* 圆/椭圆按 32 段折线近似
for a := 0 to 31 by 1
    ang  := 2 * 3.14159 * a / 32
    row  := CenterRow + Radius1 * cos(ang) * ...   * 椭圆需按 phi 旋转
    col  := CenterCol + Radius2 * sin(ang) * ...
    * 收集折线点，首尾相接
endfor
* 矩形：四个角（HALCON 的 phi=0 时长轴沿列方向）
```
