# 新插件端口速查

> 面向插件开发者的一页速查：声明端口、读写值、连线规则。
> 对应代码：`Shard/Core.Interfaces/DataPort/`（InputPort / OutputPort / PortExtensions）
> 与 `Engine/FlowCompiler.cs`（编译期连线类型检查）。

---

## 1. 三句话记住端口系统

```
上游算子：  RunAlgorithm 里  输出端口.Set(值)      ──数据──▶  下游算子：  RunAlgorithm 里  输入端口.ActualValue
```

1. **声明**：端口必须是 `public` **属性**（写成字段反射发现不了，端口会"凭空消失"）。
2. **上游写值**：用 `TypedValue` 或免强转扩展 `Set(...)`。
3. **下游读值**：用 `ActualValue` 或免强转扩展 `Get<T>()`。

---

## 2. 声明端口（照抄即可）

```csharp
public class MyPlugin : VisionPluginBase
{
    // 输入端口：不填名字时基类自动用属性名命名
    public InputPort<HImage> SrcImage { get; } = new(description: "待处理图像");

    // 输入端口带默认值（用户不连线时生效）
    public InputPort<double> Threshold { get; } = new(defaultValue: 0.5);

    // 输出端口
    public OutputPort<HImage> Result { get; } = new(description: "处理结果");

    public override void RunAlgorithm(IExecutionContext context)
    {
        var img = SrcImage.ActualValue;   // ① 读：链接优先，零强转零拷贝
        Result.Set(img);                  // ② 写：免强转扩展
        // ③ Success 基类已预置 true（"默认成功、显式失败"），纯计算插件无需再写；
        //    失败路径才需要：Success.Set(false); ErrorMessage.Set("原因");
    }
}
```

必填性：`InputPort` 默认 `IsRequired = true`，不连线编译直接报"[参数缺失]"。可选输入显式关掉：

```csharp
public InputPort<double> Bias { get; } = new(defaultValue: 0) { IsRequired = false };
```

## 3. 读写入口对照表（★核心）

| 入口 | 输入端口（下游读） | 输出端口（上游写） |
|---|---|---|
| `ActualValue` (T) | ★ **推荐读值入口**：链接值优先，其次手动值 | 无此属性 |
| `Get<T>()` 扩展 | ★ 推荐（经 `IInputPort` 接口/动态端口时免强转） | — |
| `TypedValue` (T) | ⚠ **陷阱：只是"手动值"**！连线后读它得到的是没生效的旧值 | ★ 推荐写值入口：强类型、免装箱 |
| `Set(...)` 扩展 | — | ★ 推荐（经 `IOutputPort` 接口/动态端口时免强转） |
| `Value` (object) | 读写**手动值**，配置灌值/界面绑定用，业务代码别碰 | 可写，走跨类型智能转换；类型不符会抛异常，优先用 `TypedValue`/`Set` |
| `GetActualValue()` | 弱类型取实际值（接口场景兜底），一般被 `Get<T>()` 替代 | — |

**一句话背下来**：

> 输入端三兄弟里只有 `ActualValue` 是"真实生效值"；`TypedValue` 和 `Value` 在输入端读写的都只是手动值，
> 在输出端才是真实值——**同名反义**，这是新手最常踩的坑。

## 4. 数据是怎么流过来的（拉取式 + 引用传递）

```
上游 RunAlgorithm                下游（同一轮或下一轮 RunAlgorithm）
Result.TypedValue = img   ──▶   ValueChanged 事件同步推送   ──▶   下游 RefreshLinkedCache 缓存引用
                                                                下游读 SrcImage.ActualValue → 命中缓存，零转换零拷贝
```

- HImage 等引用类型全程传引用，**不发生像素拷贝**；管线单节点开销约百纳秒，对 Halcon 毫秒级算子可忽略。
- 上游值没变（引用相等）时下游缓存不刷新、事件不传播。

## 5. 连线类型规则（编译期检查，报错归下游节点）

编译器在连线时按下面规则放行（与运行时转换能力严格一致）：

| 上游 → 下游 | 结果 | 说明 |
|---|---|---|
| 同类型 / 派生→基类 / 实现接口 | ✅ | 引用赋值 |
| 任意数值 ↔ 数值（int/double/float…） | ✅ | `Convert.ChangeType` |
| string → 数值 / bool | ✅ | 运行时转换 |
| 数值 / bool → string | ✅ | 运行时转换 |
| string → 枚举 | ✅ | `Enum.Parse` 按名字 |
| **bool ↔ 数值** | ❌ | `Convert.ChangeType` 不支持，直接报编译错 |
| HImage → int 等无关类型 | ❌ | `[连线类型不匹配]` 错误显示在**下游**节点上 |
| 任一方是 `object` 或类型未知 | ✅ 放行 | 交给运行时兜底 |

报错样例（画布上下游节点红框定位）：

```
[连线类型不匹配] 'Blob分析' 的输入端口 'SrcImage' 期望 HImage，但上游 '读码器' 提供的是 String。
请在变量绑定处改选类型兼容的输出，或调整上游算子的输出类型。
```

## 6. 动态端口（数量随配置变化的输出）

参照 `Plugin.CreateRoi`：基类提供 `AddDynamicOutput` / `ClearDynamicOutputs`，写值用 `Set` 免强转：

```csharp
// 重建：先清后加
ClearDynamicOutputs();
AddDynamicOutput(new OutputPort<HImage>($"Crop_{roi.Name}"));

// 填值：经 Outputs 字典拿到的是 IOutputPort 接口，Set 扩展免去 (OutputPort<HImage>) 强转
if (Outputs.TryGetValue(portName, out var port))
    port.Set(croppedImg);
```

## 7. 框架自动做的事（这些约定你不用背了）

| 以前要背的约定 | 现在框架的行为 | 想自定义时 |
|---|---|---|
| 失败要写 `Success=false` + `ErrorMessage` 再早退 | 一行 `Fail("原因")` 搞定两端口；不写也**默认成功** | — |
| 异常不许穿透 `RunAlgorithm`（否则归因错乱） | 基类统一兜底：任何未捕获异常自动转成**本节点失败**（ErrorMessage=异常类型+消息，日志留痕），流程继续 | `override bool RethrowOnException => true;` 恢复"异常中断当轮" |
| 上一轮输出的 HImage 要开轮手写 Dispose | 基类轮首自动回收所有输出端口的 `IDisposable` 旧值（透传上游同引用的值自动跳过，不会误杀） | `override bool AutoDisposeRoundOutputs => false;` 自行管理 |
| 端口写成 public 属性（字段静默失效最难查） | 编译期逮住直接报 `[端口声明错误]`，附改法示例 | — |
| 动态端口写值要 `((OutputPort<T>)port).Value = x` 强转 | 免强转扩展 `port.Set(x)` / `port.Get<T>()`（见第 6 节） | — |
| 连线类型不匹配运行时才炸 | 编译期报 `[连线类型不匹配]` 并红框定位下游（见第 5 节） | — |

## 8. 新插件自查清单

- [ ] 端口全部是 `public` **属性**（写成字段编译会直接报 `[端口声明错误]`）
- [ ] `RunAlgorithm` 读输入一律 `ActualValue` / `Get<T>()`，**不读输入端 `TypedValue`**
- [ ] 写输出一律 `TypedValue` / `Set(...)`
- [ ] 可选输入显式 `IsRequired = false` 并给 `defaultValue`
- [ ] 业务失败路径用 `Fail("原因"); return;`（无需写 `Success=true`，异常也不用自己包 try/catch——基类自动转失败）
- [ ] 输出的 HImage 无需手写释放（基类轮首自动回收；跨轮持有的私有缓存仍要自己管）
