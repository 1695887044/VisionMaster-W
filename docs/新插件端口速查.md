# 新插件端口速查

> 面向插件开发者的一页速查：声明端口、读写值、连线规则。
> 对应代码：`Shard/Core.Interfaces/DataPort/`（InputPort / OutputPort / PortExtensions）
> 与 `Engine/FlowCompiler.cs`（编译期连线类型检查）。

---

## 1. 三句话记住端口系统

```
上游算子：  RunAlgorithm 里  输出端口.Set(值)      ──数据──▶  下游算子：  RunAlgorithm 里  输入端口.ActualValue
```

1. **声明**：端口必须是 `public` **属性**（写成字段反射发现不了，端口会"凭空消失"）。
2. **上游写值**：用 `TypedValue` 或免强转扩展 `Set(...)`。
3. **下游读值**：用 `ActualValue` 或免强转扩展 `Get<T>()`。

## 2. 声明端口（照抄即可）

```csharp
public class MyPlugin : VisionPluginBase
{
    // 输入端口：不填名字时基类自动用属性名命名
    public InputPort<HImage> SrcImage { get; } = new(description: "待处理图像");

    // 输入端口带默认值（用户不连线时生效）
    public InputPort<double> Threshold { get; } = new(defaultValue: 0.5);

    // 输出端口
    public OutputPort<HImage> Result { get; } = new(description: "处理结果");

    public override void RunAlgorithm(IExecutionContext context)
    {
        var img = SrcImage.ActualValue;   // ① 读：链接优先，零强转零拷贝
        Result.Set(img);                  // ② 写：免强转扩展
        // ③ Success 基类已预置 true（"默认成功、显式失败"），纯计算插件无需再写；
        //    失败路径才需要：Success.Set(false); ErrorMessage.Set("原因");
    }
}
```

必填性：`InputPort` 默认 `IsRequired = true`，不连线编译直接报"[参数缺失]"。可选输入显式关掉：

```csharp
public InputPort<double> Bias { get; } = new(defaultValue: 0) { IsRequired = false };
```

## 3. 读写入口对照表（★核心）

| 入口 | 输入端口（下游读） | 输出端口（上游写） |
|---|---|---|
| `ActualValue` (T) | ★ **推荐读值入口**：链接值优先，其次手动值 | 无此属性 |
| `Get<T>()` 扩展 | ★ 推荐（经 `IInputPort` 接口/动态端口时免强转） | — |
| `TypedValue` (T) | ⚠ **陷阱：只是"手动值"**！连线后读它得到的是没生效的旧值 | ★ 推荐写值入口：强类型、免装箱 |
| `Set(...)` 扩展 | — | ★ 推荐（经 `IOutputPort` 接口/动态端口时免强转） |
| `Value` (object) | 读写**手动值**，配置灌值/界面绑定用，业务代码别碰 | 可写，走跨类型智能转换；类型不符会抛异常，优先用 `TypedValue`/`Set` |
| `GetActualValue()` | 弱类型取实际值（接口场景兜底），一般被 `Get<T>()` 替代 | — |

**一句话背下来**：

> 输入端三兄弟里只有 `ActualValue` 是"真实生效值"；`TypedValue` 和 `Value` 在输入端读写的都只是手动值，
> 在输出端才是真实值——**同名反义**，这是新手最常踩的坑。

## 4. 数据是怎么流过来的（拉取式 + 引用传递）

```
上游 RunAlgorithm                下游（同一轮或下一轮 RunAlgorithm）
Result.TypedValue = img   ──▶   ValueChanged 事件同步推送   ──▶   下游 RefreshLinkedCache 缓存引用
                                                                下游读 SrcImage.ActualValue → 命中缓存，零转换零拷贝
```

- HImage 等引用类型全程传引用，**不发生像素拷贝**；管线单节点开销约百纳秒，对 Halcon 毫秒级算子可忽略。
- 上游值没变（引用相等）时下游缓存不刷新、事件不传播。

## 5. 连线类型规则（编译期检查，报错归下游节点）

编译器在连线时按下面规则放行（与运行时转换能力严格一致）：

| 上游 → 下游 | 结果 | 说明 |
|---|---|---|
| 同类型 / 派生→基类 / 实现接口 | ✅ | 引用赋值 |
| 任意数值 ↔ 数值（int/double/float…） | ✅ | `Convert.ChangeType` |
| string → 数值 / bool | ✅ | 运行时转换 |
| 数值 / bool → string | ✅ | 运行时转换 |
| string → 枚举 | ✅ | `Enum.Parse` 按名字 |
| **bool ↔ 数值** | ❌ | `Convert.ChangeType` 不支持，直接报编译错 |
| HImage → int 等无关类型 | ❌ | `[连线类型不匹配]` 错误显示在**下游**节点上 |
| 任一方是 `object` 或类型未知 | ✅ 放行 | 交给运行时兜底 |

报错样例（画布上下游节点红框定位）：

```
[连线类型不匹配] 'Blob分析' 的输入端口 'SrcImage' 期望 HImage，但上游 '读码器' 提供的是 String。
请在变量绑定处改选类型兼容的输出，或调整上游算子的输出类型。
```

## 6. 动态端口（数量随配置变化的输出）

参照 `Plugin.CreateRoi`：基类提供 `AddDynamicOutput` / `ClearDynamicOutputs`，写值用 `Set` 免强转：

```csharp
// 重建：先清后加
ClearDynamicOutputs();
AddDynamicOutput(new OutputPort<HImage>($"Crop_{roi.Name}"));

// 填值：经 Outputs 字典拿到的是 IOutputPort 接口，Set 扩展免去 (OutputPort<HImage>) 强转
if (Outputs.TryGetValue(portName, out var port))
    port.Set(croppedImg);
```

## 7. 框架自动做的事（这些约定你不用背了）

| 以前要背的约定 | 现在框架的行为 | 想自定义时 |
|---|---|---|
| 失败要写 `Success=false` + `ErrorMessage` 再早退 | 一行 `Fail("原因")` 搞定两端口；不写也**默认成功** | — |
| 异常不许穿透 `RunAlgorithm`（否则归因错乱） | 基类统一兜底：任何未捕获异常自动转成**本节点失败**（ErrorMessage=异常类型+消息，日志留痕），流程继续 | `override bool RethrowOnException => true;` 恢复"异常中断当轮" |
| 上一轮输出的 HImage 要开轮手写 Dispose | 基类轮首自动回收所有输出端口的 `IDisposable` 旧值（透传上游同引用的值自动跳过，不会误杀） | `override bool AutoDisposeRoundOutputs => false;` 自行管理 |
| 端口写成 public 属性（字段静默失效最难查） | 编译期逮住直接报 `[端口声明错误]`，附改法示例 | — |
| 动态端口写值要 `((OutputPort<T>)port).Value = x` 强转 | 免强转扩展 `port.Set(x)` / `port.Get<T>()`（见第 6 节） | — |
| 连线类型不匹配运行时才炸 | 编译期报 `[连线类型不匹配]` 并红框定位下游（见第 5 节） | — |

## 7A. 插件自带帮助手册（可选）

> 宿主启动时把"软件自带手册 + 各插件自带手册"合并成一本，从「帮助(H) → 帮助文档」打开（2026-10-07 起）。
> 本节讲怎么写插件自己的那几页；**不写也不受影响**——目录里会给未提供手册的插件自动生成一页
> （用 `[Display]` 元数据 + 注册期端口表，节点上带「自动生成」角标）。
> 实现与验证见 `docs/code-changes/2026-10-07-软件内置帮助手册（宿主手册+插件手册合并）.md`。

**做法①：约定目录（零配置，推荐）**

1. 在插件工程下建 `Help\` 目录，**一页一个 `.md`**。样板：`Plugins\Plugin.BeadInspect\Help\01-overview.md`、`02-usage.md`；`Plugins\Plugin.Matching\Help\01-overview.md`。
2. csproj 加一行（照抄样板工程，图片也一起内嵌）：

```xml
<EmbeddedResource Include="Help\**\*" />
```

3. 三条约定（写在文件名与正文里的）：
   - **文件名顺序即页序**（按字符序排序，用 `01-`、`02-` 前缀；页数可能上两位数时**零填充**——`10-` 会排在 `2-` 前面）；
   - **页标题取正文第一个 `# ` 一级标题**，没有才退回文件名；
   - **图片放 `Help\images\`**，正文按相对路径引用（如 `![](images/flow.png)`）——宿主按 `{程序集}.Help.images.xxx.png` 解析内嵌资源；取不到时该图**降级成文字**，不会让整页渲染失败。
4. 正文是 Markdown 子集：标题 / 段落 / 列表（可嵌套）/ 表格 / 代码块 / 引用 / 分隔线 / 粗体·斜体 / 行内代码 / 链接 / 图片 / 反斜杠转义。不支持的语法（脚注、HTML 块、引用式链接、任务列表）按普通文字显示。
5. 宿主认的内嵌资源前缀是 `{程序集名}.Help.`——别把无关资源塞进这个前缀。

**做法②：`IPluginHelpProvider`（可选接口，按需才实现）**

```csharp
public sealed class MyPlugin : VisionPluginBase, IPluginHelpProvider
{
    public IReadOnlyList<PluginHelpSection> GetHelpSections() => new[]
    {
        new PluginHelpSection { Title = "我的插件", Markdown = "# 我的插件\n\n……" },
    };
}
```

- 签名：`IReadOnlyList<PluginHelpSection> GetHelpSections()`，`PluginHelpSection { string Title; string Markdown; }`；定义在 `Shard\Core.Interfaces\IPluginHelpProvider.cs`（非破坏性新增：不实现不受影响，`IVisionPlugin` 不用改）。返回空集合 = 未提供，宿主转兜底自动页。
- **适用场景**：正文要在**运行期按现场环境生成**，或要显式指定章节标题与顺序。只有静态 md 就放 `Help\`——**内嵌资源优先级更高**，存在时不再调接口（宿主顺序：内嵌资源 → 本接口 → 自动生成页）。
- **调用时机**：宿主启动自检链里"帮助手册合并"一步，**每个插件至多调用一次**；实现里只做取数——不要读现场设备、不要起线程。
- 取数抛异常只影响该插件：宿主记 Warning 后改用自动生成页，不挡启动。

**改手册要重建插件工程**

- 手册是**内嵌资源**（编进插件 DLL 里），改了 `.md` 不重建，`Modules\` 里跑的仍是旧 DLL、手册也是旧的——与 AGENTS.md 红线③"**改了插件源码必须重建插件工程**"同一口径。
- 因此 `Modules\` 仍只投 DLL：`pack.ps1`（整目录拷 `Modules\`）与 `Plugins\Directory.Build.targets`（DLL 投递约定）都不需要为本功能改动；交付升级 = 覆盖同名 DLL。
- 目录里的分组沿用插件注册元数据的分类（与算子工具箱一致）；自动生成页只抄 `[Display]` 名称/描述与端口表，**参数不抄**（以插件自己的配置界面为准）。

## 8. `[StepConfig]` 配置属性三选一（源生成器）

> `[StepConfig]` 属性随 .vms 方案经 `InputValues` 落盘（**键 = 属性名**，改名 = 静默丢配置），不暴露为端口。
> 写法按需求三选一；② 的实现由源生成器在编译期补齐（运行期零痕迹），旧写法与新写法可同文件共存、逐属性迁移。

**① 纯落盘、无 INPC / 无 setter 副作用 → 自动属性**

```csharp
[StepConfig]
public double Threshold { get; set; } = 0.5;
```

**② 需要 INPC 或 setter 副作用 → partial 属性 + 钩子（源生成器接管）**

```csharp
[StepConfig, DefaultValue(3)]
public partial int RetryCount { get; set; }

// 钩子：只写"实现"、不写声明（声明由生成器产出；不写则钩子与调用被编译器整对消除）
partial void OnRetryCountChanging(ref int value) => value = Math.Clamp(value, 0, 10); // 归一化入参（赋值前调用）
partial void OnRetryCountChanged(int value) { /* 变更后副作用：仅值真的变化时触发 */ }
```

生成物（同一 partial class 内）：`_retryCount` 后备字段 + `SetProperty`（INPC）+ 钩子声明与调用。

**③ 保持手写（生成器不接管）**

| 形态 | 例（迁移中的实际跳过项） |
| --- | --- |
| 集合 `new()` 默认值 | Calibration `PointRows`、ResultUpload `Headers`（setter 内联 `?? new()`） |
| 默认值非常量（特性实参必须编译期常量） | CodeReader `Symbology`（默认值 `CodeSymbologyTable.Default.HalconName`） |
| Unhook/Hook 成对替换 setter | ResultUpload `Fields`、DataRecord `Columns` |
| 需要读旧值的 setter | BlobDetect `DetectTarget` |
| 不使用 SetProperty 的结构型 setter | CaliperMeasure `CaliperRegions`、DataRecord `ImageSaveMode`（setter 里重建动态端口） |
| 手写赋值 + 无条件通知型（非 `SetProperty`） | CreateRoi `SmearDrawData` / `SmearEraseData`、ImageScript `SelectedProcedure` |

**契约（不满足会报编译错误 CPG0001~CPG0005，不静默）**

- 钩子**只写实现、不写声明**；钩子名 = `On` + 属性名 + `Changing` / `Changed`。
- 生成的后备字段 = `_` + 属性名首字母小写（`RetryCount` → `_retryCount`）。
- partial 属性所在**类声明必须加 `partial`**。
- `DefaultValue` 用 `System.ComponentModel.DefaultValueAttribute`（文件需 `using System.ComponentModel;`）；`string.Empty` 要写成 `""`；非编译期常量不能用。
- `DefaultValue` 的表达式必须能在**插件类作用域直接解析**（类内 const、字面量、同命名空间枚举成员都行）——生成文件不带 using，引用"靠 using 才可见"的外部类型请写全限定名，或该属性保持手写。

**工程与纪律**

- 生成器在 `Shard/Core.PluginGenerators`，以 **Analyzer 方式**挂接（见 `Plugins/Directory.Build.props`）。
- **改生成器后必须重建全部插件工程**（AGENTS.md R16）——只重建单个插件，用的仍是旧生成实现。
- 参考样板：`Plugins/Plugin.ResultUpload/ResultUploadPlugin.cs`。

## 8A. 数值字段（NumericBox）标准做法

> 插件的数值参数**不要再手写 `TextBox`**，统一用 `ui:NumericBox`。它不是"更花哨的文本框"，而是补上三件裸文本框做不到的事：
> **越界钳制**、**上下键 / 滚轮步进**、**与区域设置无关的解析**（裸文本框走绑定引擎按当前区域转换，
> 小数点分隔符不是 `.` 的机器上，用户按习惯敲 `1.5` 会静默失败 —— 值不变、也没有任何提示）。

**① 自带视图里直接用**

```xml
<ui:NumericBox
    Width="200"
    Minimum="1"
    Maximum="50"
    Style="{StaticResource PluginNumericBox}"
    Value="{Binding BrushSize, UpdateSourceTrigger=PropertyChanged}" />
```

- 区间两端取自**属性上已有的 `[RangeValidation(min, max)]` 或本视图校验规则里的 Min/Max**（抄成 `Minimum`/`Maximum`，越界由控件钳到端点）。
- 整数参数加 `DecimalPlaces="0"`；只读参数用 `IsReadOnly="True"`（不是 `IsEnabled`）。
- 全仓范式：`Plugin.BlobDetect\BlobDetectView.xaml`（19 处）、`Plugin.CaliperMeasure`（11 处）、`Plugin.Matching`、`Plugin.Calibration`。

**② 交给属性网格（`[SuperDisplay]` 反射渲染）**

不用做任何事：`NumericGenerator`（Priority 110）自动把 int / double / … 渲染成 NumericBox，并读 `[RangeValidation]` 当上下限。**别在视图里再赌一个数值控件**，否则与网格里的观感/行为不一致。

**③ 样式可复用，但有两个坑（都真踩过）**

- `PluginNumericBox` 的 `TargetType` 是 **TextBox（基类）**，而 `NumericBox` 继承自 TextBox —— **同一份样式可以直接套在 NumericBox 上**，不需要复制一份"数值专用样式"。
- 绑定目标从 `Text`（字符串）换成 `Value`（double）时，**校验规则必须同时认"字符串"与"已转换的数值"**。只认字符串的规则会把每个数值目标判成"不能为空"，表现是**整片字段标红、而且输入被校验拒绝、写不回模型**（2026-10-10 的真实事故）。
- **别只看样式名判断是不是数值**：`PoseTransformView` 里套着 `PluginNumericBox` 的其实是**图片路径**，`CalibrationView` 里是**设备序列号** —— 迁移/替换前先看绑定路径。

**契约**

- 数值校验规则**只有一份实现**：`Shard/Core.Controls/NumberValidationRule.cs`，视图里统一写 **`cv:NumberValidationRule`**（`xmlns:cv="clr-namespace:Core.Controls;assembly=Core.Controls"`）。全仓 41 处引用都在这个前缀上（BlobDetect 19 + CaliperMeasure 10 + Matching 12），**插件里不再保留同名类** —— 历史上是"三份逐字副本"，修一处漏两处（2026-10-10 的"全字段变红"就是漏了共享那份），**新插件直接引用共享实现、不要复制**。
- 校验由上层 VM 负责的表单（如 SCADA 属性面板），把控件设成 `RevertOnInvalid="False"`：非法文本**保留**、只标红，退回与否交给面板（面板要留住用户输入，好让人在原处改）。
- 数值字段的"非法"反馈有两条来源：控件自己的 `IsInvalid` 与上层 VM 的校验 —— 样式里两条都要接到**同一个红色**上。

## 9. 新插件自查清单

- [ ] 端口全部是 `public` **属性**（写成字段编译会直接报 `[端口声明错误]`）
- [ ] `RunAlgorithm` 读输入一律 `ActualValue` / `Get<T>()`，**不读输入端 `TypedValue`**
- [ ] 写输出一律 `TypedValue` / `Set(...)`
- [ ] 可选输入显式 `IsRequired = false` 并给 `defaultValue`
- [ ] 业务失败路径用 `Fail("原因"); return;`（无需写 `Success=true`，异常也不用自己包 try/catch——基类自动转失败）
- [ ] 输出的 HImage 无需手写释放（基类轮首自动回收；跨轮持有的私有缓存仍要自己管）
- [ ] 数值参数用 `ui:NumericBox`（不要手写 `TextBox`；区间抄自 `[RangeValidation]` / 规则里的 Min/Max；整数加 `DecimalPlaces="0"`）—— 见 §8A
