# 报表图元 与 工艺符号库：方案评审

日期：2026-10-25
背景：中控 InPlant SCADA 对标（见 `2026-10-25-SCADA第三次对标-中控InPlantSCADA（能力级）.md`）确认两项真缺口——**报表**（我们只有 DataGrid 的 N 行缓冲）与**工艺符号库**（我们只有 阀门/泵/电机/管道/罐体 5 个）。
本文只回答"怎么做、要不要交互、工作量多大"，不写代码。

# 第一部分：报表

## 1.1 结论先行

**做，但不是"再做一个 DataGrid"。** 报表的价值在**按时间范围聚合**（班次/日/小时）+ **可打印可导出**；这两件事 DataGrid 都不做，也不该塞给它。

四条设计判断：

| 判断 | 结论 | 理由 |
| --- | --- | --- |
| 聚合放哪 | **宿主侧**（新契约 `IScadaReportSource`），不在图元里 | 现有 `IScadaHistorySource.QueryAsync` 只返回**当前页的字符串行**（`ScadaHistoryResult.Rows` 是 `string`），既不能求和也不给全量；在元素里翻页拉全量会撞 500 行/页上限与 20 万行扫描上限 |
| 明细 vs 汇总 | **同一个图元两种模式**（`Mode=Detail/Summary`） | 明细 = 带打印导出的历史表；汇总 = 按班次/日分组。两者共用请求 DTO 与五态，拆两个图元会复制一遍状态机 |
| 数据从哪来 | 复用现有 CSV 账本（`<方案根>\History\*.csv`，`Plugin.DataRecord` 写的） | 记录与查看必须同一批文件，否则迟早"账本里有、报表里没有" |
| 导出/打印 | xlsx 用 **MiniExcel**（宿主已有 1.46.0）；打印用 **WPF PrintDialog + FlowDocument** | 不引新依赖；PDF 走 Windows 自带"Microsoft Print to PDF"，不引 PDF 库 |

## 1.2 现状盘点（能复用的东西）

| 已有 | 位置 | 怎么用 |
| --- | --- | --- |
| CSV 历史源（时间列识别、倒序、分页、坏文件跳过、5s 超时、20 万行上限） | `VisionMaster\Services\CsvFolderHistorySource.cs` | 抽出"逐行读 CSV"的共用读取器，报表复用它做流式聚合 |
| 五态结果（Ok/Empty/Unavailable/InvalidRange/Timeout/Cancelled） | `Scada\Models\ScadaHistory.cs` | 报表结果**直接复用**这套状态，文案口径不分叉 |
| 图元的异步查询范式（CTS + 取消 + 查询中态） | `Scada.Controls\Elements\DataGridElement.cs` | 报表照抄：切页/改范围/关窗要能取消旧查询 |
| 列定义走属性袋 JSON | `ScadaGridColumnsCodec` | 报表列定义同样做一个 Codec（`ScadaReportCodec`），落盘稳定、可校验 |
| xlsx 导出（临时文件 + `File.Move(overwrite)`） | `VisionMaster\Services\DeviceVariableIoService.cs:554-563` | 照抄这条落盘纪律（R161：写一半失败不能毁掉用户原文件） |
| 审计出口 | `Scada\Models\IScadaAuditSink.cs` | 导出/打印必须记审计（谁、什么范围、多少行、写到哪） |
| 权限出口 | `ScadaRuntimeContext.AccessPolicy` | 导出/打印按角色判；在**按下前**判（`IsEnabled`），不是按完再报错 |

## 1.3 契约设计（新增，放 `Scada\Models\ScadaReport.cs`）

```csharp
public enum ScadaReportMode { Detail = 0, Summary = 1 }
public enum ScadaReportAggregate { None, Sum, Average, Min, Max, Count, First, Last }
public enum ScadaReportGrouping { None = 0, Shift = 1, Day = 2, Hour = 3 }

public sealed class ScadaReportColumn
{
    public string Source { get; init; } = "";      // CSV 表头列名
    public string Title  { get; init; } = "";      // 报表列名（空 = 用 Source）
    public string Format { get; init; } = "";      // 数值格式，如 0.00 / 0
    public ScadaReportAggregate Aggregate { get; init; }
    public double Width { get; init; }             // 0 = 自适应
}

public sealed class ScadaReportRequest
{
    public ScadaReportMode Mode { get; init; }
    public DateTime FromLocal { get; init; }
    public DateTime ToLocal { get; init; }
    public IReadOnlyList<ScadaReportColumn> Columns { get; init; } = Array.Empty<ScadaReportColumn>();
    public string? TimestampColumn { get; init; }  // 空 = 自动识别
    public string? Keyword { get; init; }
    public ScadaReportGrouping Grouping { get; init; }
    public IReadOnlyList<string> ShiftStarts { get; init; } = Array.Empty<string>(); // "08:00","20:00"
    public int MaxRows { get; init; } = 5000;      // 明细模式上限（超了截断并在 Message 里说明）
}

public sealed class ScadaReportResult
{
    public ScadaHistoryStatus Status { get; init; }   // 复用历史五态
    public string? Message { get; init; }
    public IReadOnlyList<string> Columns { get; init; } = Array.Empty<string>();
    public IReadOnlyList<IReadOnlyList<string>> Rows { get; init; } = Array.Empty<IReadOnlyList<string>>();
    public int RowCount { get; init; }               // 聚合后行数（不是扫描行数）
    public int ScannedRows { get; init; }            // 扫描了多少行（页脚"扫描 12,340 行"）
    public string? SourceName { get; init; }
    public DateTime GeneratedAt { get; init; }
}

public interface IScadaReportSource
{
    string Name { get; }
    bool IsAvailable { get; }
    string? UnavailableReason { get; }
    Task<ScadaReportResult> BuildAsync(ScadaReportRequest request, CancellationToken cancellationToken);
}
```

**为什么不用 `Func<...>` 委托注入**：与 `IScadaValueSource` / `IScadaHistorySource` / `IScadaAxisSource` 保持一致，宿主实现、图元只认接口；委托注入会让"报表源可选"这件事在签名上消失。

**聚合语义（必须写死，否则两边算不一样）**：
- 数值列按不变文化解析；解析失败的行**整行跳过**并计数，结果 `Message` 里报"跳过 N 行（列 X 非数值）"。
- `Count` 对任意列有效（计数非空）；`Sum/Average/Min/Max` 只对可解析为数值的列有效。
- 空范围 → `Status=Empty`（不是 Ok + 0 行）：界面文案不同（"该范围没有记录" vs "查询成功"）。
- 班次分桶：按 `ShiftStarts` 里"最后一个 ≤ 记录时间的起点"归桶，跨零点回绕到前一天；桶标签 `2026-10-25 早班(08:00-20:00)`。
- 明细模式超过 `MaxRows` → 截断 + `Message` 说明（不静默丢）。

## 1.4 图元设计（`Hmi.Report`，工具箱分类「数据」）

**属性**（按 `ScadaPropertyGroups` 分组，全部走生成器）：

| 组 | 属性 | 说明 |
| --- | --- | --- |
| 基本 | `Text`（标题） | 报表标题，页眉/打印都用它 |
| 数据 | `Mode`（Detail/Summary）、`From`/`To`（默认 `-1d`/`now` 相对写法或绝对时间文本）、`Grouping`、`ShiftStarts`、`Keyword`、`AutoQuery`、`MaxRows` | 时间用文本键（`2026-10-25 08:00` / `-8h` / `now`），运行态求值 |
| 数据 | `ColumnsJson`（`ElementPropertyKind.MultilineText`，由 Codec 解析） | 列定义：来源列/标题/格式/聚合/宽度 |
| 文本 | `Foreground`/`FontSize`/`HeaderBackground`/`RowAlternateBackground` | 表头/斑马纹 |
| 交互 | `RequiredRole`（继承自基类）、`AllowExport`、`AllowPrint` | 导出与打印分开授权（有的客户只允许看） |
| 外观 | `Fill`/`Stroke`/`StrokeThickness`/`CornerRadius` | 外框 |

**运行态界面**：标题行（标题 + 范围 + 行数）+ 表格区 + 底部工具条（`查询` / `上一页` `下一页`（仅明细）/ `导出 xlsx` / `导出 csv` / `打印`）+ 页脚（来源、扫描行数、生成时间、操作者）。
**五态**：查询中（转圈 + 可取消）/ 有数据 / 该范围无记录 / 数据源不可用 / 范围非法 —— 文案与 DataGrid 同一套词汇，不许出现"查询失败"这种混装说法。
**设计期**：不查数据，按配置列画一张空表 + 一行提示"运行态显示报表"（与 DataGrid 设计期同款）。设计期**不出工具条按钮**（避免点出一个空文件对话框）。

## 1.5 导出与打印

- **xlsx**：MiniExcel `SaveAs` 到 `path + "." + guid + ".tmp.xlsx"` → `File.Move(temp, path, overwrite: true)`；导出内容 = 标题行 + 表头 + 数据 + 页脚（来源/生成时间/操作者）。落盘目录由用户在 `SaveFileDialog` 里选（默认 `<方案根>\Reports\`）。
- **csv**：UTF-8 **带 BOM**（Excel 直接打开不乱码），同样的临时文件纪律。
- **打印**：把结果表构造成 `FlowDocument`（`Table` + `TableRowGroup`），页眉（标题/范围）、页脚（页码/生成时间/操作者）用 `BlockUIContainer` 或 `Paragraph`；`PrintDialog.PrintDocument(doc.DocumentPaginator, 标题)`。纸张 A4、方向按属性（`Portrait/Landscape`）。**不做**打印预览窗口（v1）；要预览就走"打印到 PDF"。
- **权限与审计**：`AllowExport`/`AllowPrint` + `AccessPolicy.CanOperate(RequiredRole)` 双闸；按下前判；成功后 `IScadaAuditSink.Append(actor, …, subject: 报表标题, action: "导出报表"/"打印报表", result: "成功", detail: "范围 08:00~20:00，123 行 → D:\…\x.xlsx")`。失败也记（result="失败"，detail 带原因）。

## 1.6 分期与工作量

| 期 | 内容 | 估时 |
| --- | --- | --- |
| R1 | 契约 + DTO + Codec + 宿主 `CsvReportSource`（流式聚合、班次分桶、五态）+ 断言（聚合数学/跨零点/空范围/非数值列/取消） | 1.5 天 |
| R2 | `Hmi.Report` 图元 + 模板（表头/斑马纹/五态/工具条）+ 描述符 + 断言（行账本、五态、设计期） | 1.5 天 |
| R3 | 导出 xlsx/csv + 打印 + 权限/审计 + 断言（临时文件纪律、审计调用、分页数） | 1 天 |
| R4 | Web 渲染器（只读表格 + 导出走服务端）+ `[WR]` 清单 | 1 天（可与 Web 批次合并） |

**合计 4~5 天**（不含 Web 批次）。

## 1.7 明确不做（v1）

- 报表模板设计器（拖列/合并单元格/公式）——那是独立产品，先用手填列定义。
- 定时自动生成报表文件（"每天 8 点导出到共享盘"）——属计划表能力，见第二部分之后的路线。
- 图表型报表（柱状/饼图）——先把表格做对。
- 跨方案/跨库聚合。

## 1.8 测试清单（`ScadaChecks\ReportChecks.cs`）

1. Codec 往返：列定义 JSON → 对象 → JSON 逐字相等；坏 JSON 返回空表不抛。
2. 聚合数学：Sum/Avg/Min/Max/Count/First/Last 各一条；空列、全非数值、混合列。
3. 班次分桶：08:00/20:00 两班；23:59 与 00:01 落在同一班；跨月边界。
4. 范围校验：起点晚于终点、跨度 > 上限 → `InvalidRange`。
5. 明细截断：`MaxRows` 命中时 `RowCount==MaxRows` 且 `Message` 非空。
6. 取消：查询中取消 → `Cancelled`，不抛。
7. 导出：写出的 xlsx 能被 MiniExcel 读回、行数/列数一致；目标被占用时不破坏原文件。
8. 打印：`FlowDocument` 分页数随行数增长；页脚页码正确（无打印机也能算 `ComputePageCount`）。
9. 权限/审计：无权限时按钮禁用且不落审计；有权限时审计被调用一次、detail 含范围与行数。

# 第二部分：工艺符号库

## 2.1 结论先行

**一个 TypeKey（`Hmi.Symbol`）+ 一个 `SymbolKind` 枚举 + 一张几何表**，不做 30 个 TypeKey。

理由（三条都是硬账）：
1. **工具箱**：30 个近义图元会把「工艺」分类撑成一面墙，用户找不到东西。
2. **属性面板**：30 份描述符里 90% 是同一批属性（主色/线宽/位号/状态），复制 30 遍就是 30 个改漏点。
3. **Web 渲染器**：每个 TypeKey 都要一条渲染器，`[WR]` 例外清单会被迫从 9 涨到 39。

代价（要认）：属性面板里选符号是下拉框，不能像工具箱那样看图选。**v1 接受**；若现场强烈要缩略图选择器，那是一个独立的"符号选择弹窗"，不影响模型（改的只是属性编辑器）。

## 2.3 几何表结构

每个符号 = 一组**归一化图元**（0~1 坐标），在控件里按实际尺寸缩放：

```csharp
internal readonly record struct SymbolPrimitive(
    SymbolShape Shape,        // Polyline / Polygon / Rect / Ellipse / Arc
    double[] Points,          // 归一化坐标（成对）
    SymbolRole Role,          // Outline / Accent（主色/副色）
    bool Filled,
    double ThicknessScale);   // 相对线宽的倍数（细部线可 0.6）
```

- 表本体放 `Scada.Controls\Elements\ProcessSymbols.cs`：`static IReadOnlyDictionary<SymbolKind, SymbolPrimitive[]>`。
- 生成几何走现成范式：`GeometryGroup` 现算 → 写一个只读 DP → 模板 `TemplateBinding`（与批次 C 的多边形/贝塞尔同一套，已验证）。
- **单一事实源**：Web 渲染器将来要用同一张表 → 由 C# 表导出一份 JSON 给 `wwwroot`，并在断言里比"符号数 + 种类集合"，防两边漂移。

## 2.4 属性集（全部通用，不做每符号专属面板）

| 组 | 属性 | 说明 |
| --- | --- | --- |
| 数据 | `SymbolKind`（Choice，30 项，值用 `Device.Tower` 这种稳定 ASCII，显示名走 `ScadaChoiceNames` 译成中文） | 换符号 |
| 状态 | `State`（None/Running/Stopped/Fault，**可绑变量**）、`AccentColor`、`StoppedColor`、`FaultColor` | 泵在转、阀开/关、设备故障——符号库最有价值的运行态能力 |
| 状态 | `BlinkOnFault`（bool，默认 false） | 故障时闪（读 `ScadaBeatSource` 相位，与报警条同源） |
| 外观 | `Fill`、`Stroke`、`StrokeThickness` | 主色/线宽 |
| 文本 | `Text`（位号，**可绑**）、`Foreground`、`FontSize`、`TagPlacement`（Above/Below/Inside/None） | 设备位号 P-101 |
| 数据 | `DetailCount`（int，1~20，默认按符号给） | 塔板数 / 叶片数 / 管程数——一个属性覆盖所有"重复细部" |
| 数据 | `ShowValue` + `ValueFormat` + `Unit` | 可选：在符号内显示一个数值（绑变量），等价于"符号 + 数值域"合体 |

**设计期（全部免费获得，不用新写）**

| 符号内部子件可编辑（单独选中塔板） | **不做** | 那是图元编辑器，不是符号库 |

| 期 | 内容 | 估时 |
| --- | --- | --- |
| S1 | `SymbolPrimitive` + 几何表骨架 + `Hmi.Symbol` 控件/模板/描述符 + 前 12 个符号 + `ScadaChoiceNames` 30 条译名 | 2.5 天 |
| S2 | 第二期 10 个 + 第三期 8 个 | 2 天 |

**测试**（`ScadaChecks\ProcessSymbolChecks.cs`）：
1. 每个 `SymbolKind` 都有几何条目（遍历枚举，缺一个就红）；每个条目 ≥1 个 Outline 图元、点数为偶数、坐标都在 0~1。
2. 换符号后几何变化且尺寸/位号/颜色保留。
3. `DetailCount` 改变后细部图元数随之变（塔板/叶片）。
4. `State` 三态的颜色落点（Outline 用主色、Accent 用状态色）。
5. 故障闪烁在节拍推进时 Opacity 交替（用假节拍源，不启真定时器）。
6. `Interactive=false` 时点击不发事件、`true` 时发（与 SubPage 的 [SP15] 同款）。
7. 位号 `TagPlacement` 四种落点的文字位置。
8. 工具箱/描述符：`SymbolKind` 的每个 ASCII 候选都有中文译名（复用现有 Choice 译名闸）。

# 三、需要拍板的四件事（都有推荐值）

| 1 | 报表要不要**打印**，还是只要导出 | 要打印（现场验收常要纸质签字）；v1 不做预览，走"打印到 PDF" |
| 2 | 报表**班次**怎么定义 | 属性里配 `ShiftStarts`（默认 `08:00,20:00` 两班），不写死在代码里 |
| 3 | 导出/打印的**权限** | 默认"工程师及以上"；`AllowExport`/`AllowPrint` 可关；全部记审计 |
| 4 | 符号库是否要**管道自动吸附** | v1 不做（独立 3~5 天且风险高），先用手画线 |

# 四、建议的落地顺序

1. **报表 R1~R3**（4 天）：这是现场验收项，且不与任何现有批次冲突。
2. **符号库 S1~S3**（5 天）：纯增量，不动现有图元。
3. 之后回到 **Web 统一批次**（把报表与符号的渲染器一起补，`[WR]` 清单一次清零）。
