## 0. 结论（先看这段）

七轮评审的最终建议不是「把所有参数都做成配方」，而是：

1. **v1 只做步骤参数**：`StepModel.InputValues` 里的端口/`[StepConfig]` 参数（含 ROI、卡尺搜索区等复杂对象）。
   这覆盖了视觉阈值、ROI、模板条目名、运动步骤 `Target` 等绝大多数换产品要改的值。
2. **配方内嵌 `.vms`**，不另建独立文件作运行时权威；独立文件只作 v1.1 的交换格式。
3. **显式白名单 + 快照 + 显式保存**：不按现有键推断，不实时写穿；没有配方时老文件行为逐字不变。
4. **仅停止态、整单应用、整单拒绝**：预检不过一条都不写；失败逆序回滚；回滚失败锁定后续应用。
5. **v1 砍掉运动点位与全局变量**：
   - 点位：8 份样例方案 `Points` 全为空（0/8），全仓没有「按点位号运动」的步骤，配方装点位是「配了没人读」；
     产品位置需求用步骤 `Target`（它本身就是 `InputValues` 里的端口值）覆盖。
   - 变量：写变量会同步触发 `FlowVariableTriggerService`；首件后保存会把运行值烘进 `VariableSnapshots`；
     草稿不捕获变量值。三条暗线未闭环，放 v1.1。
6. **先把两个 P0 修掉再开工**：方案打开链统一（`ApplyLoadedSolution`）、`CompiledVersion` 六处编译前快照。
   这两条不是配方引入的，但配方正确性依赖它们。

> 如果现场确实用点位表跑机、或必须切全局变量，请明确告知；那会把 v1 扩成 v1.1 的范围，工期与风险相应增加。

## 1. 需求边界

1. **配方是方案内的东西**：同一份 `.vms`（同一套流程/画面/变量/设备映射）下，按产品切换参数值。
2. **切换可解释、可回退、可审计**：操作员知道现在跑哪个配方；工程师知道这次改了哪些值；审计能追到人/时间/前后值。
3. **不改变现有语义**：没有配方时，`.vms` 行为与今天逐字一致；老文件打开不报错、不静默改值。
4. **不引入第二套参数模型**：配方值落到现有 `InputValues`，由现有 `ApplyConfigValues`/`ValueConverter` 消费。
5. **安全优先**：停止态、整单、拒绝要写清原因；不许半应用、不许静默跳过。

## 2. 为什么不选其他路线

| 路线 | 否决理由 |
| --- | --- |
| 每个产品一份 `.vms` | 相机/运动卡/通讯配置/画面/布局全量复制；换一次相机改 N 份，漏一份该产品跑不了。 |
| 独立 `.vmrecipe` 作运行时权威 | 草稿判定、另存、方案清单都不带它；两份真值谁对谁错靠人记。只能作交换格式。 |
| 运行时参数覆盖层 | 引擎编译/插件实例/HImage 都按编译期取值；覆盖层会让「界面显示新值、运行用旧值」，且无法整单回滚。 |
| 全部 `InputValues` 快照 | 链接端口、模型 base64、路径、动态列名、触发源变量全卷进来；`ApplyConfigValues` 对未知键/类型错误静默跳过。 |
| 实时写穿 | 调试随手改的阈值静默变成产品配方；无 diff、审计只剩「参数变更」。 |
| 运行中排队到周期末 | 没有可靠节拍边界；会话不会重建；运动/PLC 有机械风险。 |

## 4. 数据模型

### 4.1 `SolutionModel` 新增（追加在 `Scada` 之后）

| 属性 | 声明 | 落盘 |
| --- | --- | --- |
| `Recipes` | `List<RecipeDefinition>?`，`[JsonProperty(Order=100, ObjectCreationHandling=Replace)]` | null = 从未启用，不写；`[]` = 已启用但无配方，写 `[]` |
| `ActiveRecipeId` | `Guid?`，`[JsonProperty(Order=101)]` | null = 未应用；`Guid.Empty` 读入归一为 null |
| `RecipeSchemaVersion` | `int?`，`[JsonProperty(Order=102)]` | null = 无配方；有配方写 `1` |

- setter 不兜底 `new()`；读取侧统一 `Recipes ?? 空`。
- `Order=100+` 保证新字段排在所有未标 Order 的既有属性之后；不要给既有属性补 Order。
- 所有配方 DTO 放 `Core/Models/Recipe/`，命名空间必须是 `VisionMaster.Models`
  （binder 白名单只放行 `VisionMaster.Models`/`Communications`/`Scada`/`Plugin.*`）。
- `Version` 2.0：`Recipes` 由 null 变非 null 时置 2.0，之后不降；不变式 `Recipes != null ⇒ Version >= 2.0`。

### 4.2 `RecipeDefinition`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `RecipeId` | `Guid` | 身份；改名不变；复制换新；非空唯一 |
| `Name` | `string` | 必填；Trim 后 OrdinalIgnoreCase 唯一 |
| `Code` | `string` | 产品编码/工单，可空 |
| `Scope` | `RecipeScope` | v1 只有 `Solution` |
| `ContentVersion` | `int` | 条目实质变化 +1；改名/备注/应用不 +1 |
| `CreatedAtUtc` / `CreatedBy` | `DateTime` / `string` | 创建 |
| `UpdatedAtUtc` / `UpdatedBy` | `DateTime?` / `string` | 条目最后一次变化 |
| `LastAppliedAtUtc` / `LastAppliedBy` | `DateTime?` / `string` | 最后一次成功应用 |
| `LastAppliedContentVersion` | `int?` | 应用时的内容版本 |
| `Notes` | `string` | 备注 |
| `Entries` | `List<RecipeEntry>` | 步骤参数（v1 唯一启用的 Kind） |
| `Points` | `List<RecipePoint>` | 预留；v1 必须为空，非空 → 整单拒绝 |

### 4.3 `RecipeEntry`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Kind` | `RecipeTargetKind`（StringEnumConverter） | v1 只接受 `StepInput`；`LocalVariable`/`MotionPoint` 预留，出现即整单拒绝 |
| `TargetId` | `Guid` | `StepID` |
| `Key` | `string` | 端口名 / `[StepConfig]` 属性名 |
| `TargetName` | `string` | 捕获时步骤名；仅显示/审计，不作寻址 |
| `PluginTypeName` | `string` | 规范化、程序集无关的插件类型键 |
| `DeclaredType` | `string` | 规范化类型键（见 §5） |
| `Value` | `JToken?` | 规范 JSON 值 |
| `ValueIsNull` | `bool` | 显式 null 位 |

- 唯一键 `(Kind, TargetId, Key)`；重复 = 整份配方无效、整单拒绝。
- 寻址只按 Id；名字只作显示/导入匹配，禁止名字兜底。
- `PluginTypeName` 不用 AQN（现 `.vms` 存 AQN，插件升版即孤儿）；用规范化键。

## 5. 值 codec

### 5.1 存储

- 一律存**规范 JToken**：捕获时 `JToken.FromObject(value, TypeNameHandling.None)`；枚举显式转成员名。
- `JArray`/`JObject` 在 `TypeNameHandling.Auto` 下不写 `$type`（R1 §4.1 实测），不会被 binder 拦。
- `double[]` 会写 `$type: System.Double[], mscorlib`，binder 对数组有放行分支；配方值本身是 JToken，不受影响。
- `DeclaredType` 规范化：程序集无关、泛型递归展开、无 Version/PublicKeyToken。例：
  - `System.Double`
  - `System.Double[]`
  - `System.Collections.ObjectModel.ObservableCollection\`1[Plugin.CreateRoi.Models.RoiItem]`
  - `System.Nullable\`1[Plugin.CaliperMeasure.MeasureKind]`

### 5.2 复杂对象（v1 启用）

ROI/卡尺搜索区是 `[StepConfig] ObservableCollection<T>`，在 `.vms` 里落成普通 JSON 数组，
加载后由 `ValueConverter` 的 `JTokenType.Array/Object` 分支还原。排除它们等于砍掉核心换型场景。

准入（全部满足）：
1. **封闭类型图**：基元/string/enum/decimal/DateTime/Guid、`System.Collections*`、
   `VisionMaster.Models/Communications/Scada`、`Plugin.*`；出现 `IDisposable`/`IntPtr`/`HalconDotNet.*`/
   接口/抽象/`object` → 拒。**枚举叶子例外**：允许任意已加载程序集的枚举，但必须存成员名 + `Enum.IsDefined`。
2. **JSON 往返恒等**：`FromObject → ToObject(DeclaredType) → FromObject` 逐字段相等；NaN/±Inf 拒。
3. **大小上限**：单条 ≤64 KiB，整配方 ≤2 MiB；超限报「疑似模型/图像资产」。
4. **属性名兼容**：JToken 属性名必须在目标类型上存在；新增属性取默认 + 警告；改名/删除 → 整单拒绝。
5. **集合种类**：`List<T>` ↔ `ObservableCollection<T>` ↔ `T[]` 视为同形状，允许 + 警告
   （CreateRoi 已做过 `List→ObservableCollection` 重构，判拒绝会作废存量 ROI 配方）。

### 5.3 安全放宽矩阵

| 情形 | 判定 |
| --- | --- |
| 同类型异值 | 允许 |
| int/long → double/float；float ↔ double | 允许 |
| 枚举成员仍在（按成员名） | 允许 |
| null → 可空/引用 | 允许（`ValueIsNull`） |
| 数组长度变 / 集合种类变 | 允许 + 警告 |
| double → int；decimal ↔ double | 拒绝 |
| 枚举成员删/改名/换枚举；未定义数值 | 拒绝 |
| string ↔ number/bool | 拒绝 |
| 数组 ↔ 标量；元素类型变；对象类型变 | 拒绝 |
| null → 非可空值类型/必填端口 | 拒绝 |

### 5.4 捕获与应用

- **捕获**：取 `InputValues` 当前值（不取 `ActualValue`）；链接/隐藏端口跳过；必填 + null 不收；
  先 `ValueConverter.Convert` 到 `DeclaredType` 验证，再存规范 JToken。
- **应用**：先 `ValueConverter.Convert(entry.Value, declaredType)` 验证（不能依赖 `ApplyConfigValues`
  的空 catch）；验证通过后 **把 JToken 写回 `InputValues`**（与 `.vms` 重载同一路径），
  通过 `StepModel.SetInputValue` 写，禁止直写字典。
- **比较**：两侧同一规范化（按 `DeclaredType` 解包、整数→decimal、枚举按成员名、`-0.0→0.0`），
  逐字段比较，不比 JSON 文本；字符串不 Trim、不忽略大小写；double 不加 epsilon。

## 6. 捕获/应用/比较语义

### 6.1 捕获

- 前提：无运行会话；方案已落盘（未落盘先另存）；`AxisIdentityState` 只影响点位，v1 不涉及。
- 从当前值生成/更新选中配方的 `Entries`；`ContentVersion++`；`UpdatedAt/By`。
- 捕获不自动应用、不自动保存；保存走显式动作。

### 6.2 应用（v1 步骤参数）

| # | 步骤 | 失败 |
| --- | --- | --- |
| 1 | 权限：工程师编辑；切换需已登录操作员；审计可用 | 拒绝 + 审计 Denied |
| 2 | 运行闸：`SnapshotSessions().Any(IsRunning)` + `IFlowRunState.AnyFlowRunning` | 拒绝，列在跑流程 |
| 3 | 未保存闸：现有比较作**提示**（先保存/仅应用/取消），默认取消；不硬拦 | 取消 |
| 4 | 封门：`TryBeginApply`（seal + 等在途启动归零 ≤3s） | 超时→解封拒绝 |
| 5 | 封门后复判运行态 | 有在跑→解封拒绝 |
| 6 | 全量预检：目标存在、`PluginTypeName` 未变、键存在、未链接、类型可转、值有限、Kind 只允许 StepInput | 零写入、`ActiveRecipeId` 不变、审计 Failed |
| 7 | 快照：旧值 + `FlowModel.Version` | — |
| 8 | 写入：逐条 `SetInputValue`（JToken）；每条按差异写，不写同值 | 逆序回滚 |
| 9 | 终检：逐条回读 `InputValues`，按 `DeclaredType` 规范化比较；含 `Version > 应用前` canary | 逆序回滚 |
| 10 | 更新 `ActiveRecipeId`/`LastApplied*`；首次含配方置 `Version=2.0` | 回滚 |
| 11 | 解封（finally） | — |
| 12 | 可选保存（显式「应用并保存」） | 保留内存值，见 §8 |
| 13 | 审计：应用结果一行；保存结果一行 | 写失败只提示 |

- 状态机：`Idle → Sealing → Prechecking → Applying → Verifying → Committed`；
  旁支 `Rejected`/`Cancelled`/`RollingBack → RolledBack | RollbackFailed`。
- 写入期间不处理消息循环、不弹窗；`Applying` 期间 `CanCancel=false`。

### 6.3 比较/偏离

- 逐条比较当前 `InputValues` 与活动配方条目；得 `Equal/ValueDiff/TargetMissing/TypeChanged/LinkedNow`。
- `ContentVersion` 只解释原因：`LastAppliedContentVersion != ContentVersion` → 「配方已修改」；
  相等但值不等 → 「参数被手工改」。
- 偏离只按值判，不按版本号；比较先归一化，避免 JToken/CLR 文本不等造成假偏离。

## 7. 运行期门闸与 P0 前置

### 7.1 门闸

- `TryBeginStart()`：未封则 `_inFlight++`；已封返回 false。
- `TryBeginApply()`：置 `_sealed=true`，等在途归零 ≤3s；超时撤封返回 false。
- 封门后**复判** `SnapshotSessions`；有在跑 → 撤封拒绝。
- 覆盖 6 个启动入口：UI 主运行/单次、流程列表、HTTP、SCADA、定时/变量、子程序；
  另加 `FlowEngineService.TryOccupySession` 的运行中守卫。
- **触发不丢**：封门期间被拒的变量/定时触发必须**延后重试或显式记 Missed**，
  不许「先记 `_lastTruthy=true` 再拒绝」——否则边沿永久丢失。这是 v1 的 P0 修复项。

### 7.2 `CompiledVersion` 六处编译前快照

`CompiledVersion = flow.Version` 现有 6 处：
`FlowSessionFactory.cs:68`、`FlowListViewModel.cs:236`、`ShellViewModel.cs:1365/1418/1515/1610`。
全部改成**编译前**取值：`var versionBefore = flow.Version; Compile(...); CompiledVersion = versionBefore;`。
否则编译期间 `Version++` 会把混合图纸判成新鲜。

### 7.3 方案打开链统一（P0）

`SolutionListViewModel.OnOpen` 只做 `SwitchSolution` + 布局，缺 `ClearAll` / `VariablePersistenceService.Restore` /
`RebindAll` / `CommunicationBinder.Apply` / `ConnectMotionAutoStart`（对照 `ShellViewModel.cs:841-850`）。
抽 `ApplyLoadedSolution(solution, restoreLayout)`，4 个打开入口共用。
不修这条，配方按 `VariableId` 找不到、偏离用旧方案变量算，且下次保存会把旧变量写进新方案。

## 8. 回滚、保存、审计

- 回滚逆序（v1 只有步骤参数，即逆序 `SetInputValue` 旧值）；逐条记、遇错继续。
- 全成 → `RolledBack`；任一失败 → `RollbackFailed`：
  `ActiveRecipeId` 保持应用前值；常驻红条 + 未恢复项；只留「从磁盘重载」；锁定后续 apply 直到确认。
- 保存失败：保留内存值、不回滚；`ActiveRecipeId` 保持新值；状态 `CommittedUnsaved`；
  界面「已应用（未保存）」+ 错误原文；审计第二行记失败。
- 退出草稿：`Autosave` 会捕获内存值；v1 只含步骤参数，不涉及变量快照。
- 审计：一次应用一行（操作者/配方/`ContentVersion`/目标/成功/回滚/回滚失败/终检不符/结果/原因）；
  回滚失败逐项补行；审计写失败不阻断，但**审计不可用时禁止应用**。
- `.bak`：保存 2.0 文件时 `File.Replace(tmp, filePath, backup)` 保留上一版；R180 双 catch
  `IOException` + `UnauthorizedAccessException`。

## 10. 兼容与迁移

- **零回归用基线差分**，不用「逐字相等」（`LoadAsync` 有多项内存迁移，逐字相等本来就是伪判据）：
  改造前记录 `解决方案\*.vms` 的「Load→Serialize 与磁盘是否逐字相等」清单，改造后逐项不变。
- `Recipes:null` 不写键；`[]` 写回 `[]`；`ActiveRecipeId: Guid.Empty` 读入归一 null（进基线差分）。
- `Version` 2.0 canary：`Version>=2 && Recipes==null` → 横幅「疑似被旧版保存覆盖」+ 指向 `Autosave`；
  不阻断打开、不自动还原。旧版实测是人工硬项。
- `.bak` 在方案文件旁；不使用 `AppContext.BaseDirectory\Recipes\<SolutionId>`（副本共用/Program Files 只读）。
- `RecipeSchemaVersion > 当前支持` → 拒绝应用并提示升级；旧版丢字段无法检测，只能靠 canary。
- 方案另存/复制：`SolutionId`/`RecipeId`/`ActiveRecipeId` 保留；审计行带 `SolutionId+文件路径+RecipeId`。
- `CommittedUnsaved` 时切方案/新建/打开：三选一「先保存/放弃并切换/取消」；回滚未完成时禁止切换。

## 14. 已知限制（必须进手册）

1. 不写 PLC：网络变量不在配方内；PLC 设定值走「按配方号自取」或流程「写变量」步骤。
2. 仅停止态；暂停算运行；无排队、无热切换。
3. v1 不含运动点位与全局变量（v1.1）；点位配方只改配置，流程仍按步骤 `Target`。
4. 无撤销栈：撤销=前向切回上一配方（新审计行）；保存后同样。
5. 白名单外不随配方走：通讯地址、卡/轴映射、软限位、曝光增益、模型/模板/路径、HImage、动态列名、触发源变量。
6. 跨机台 v1 只能整份 `.vms` 复制（带走地址与布局）；单条导入导出 v1.1。
7. 旧版打开新 `.vms` 保存会丢配方；只有 `Version` canary 告警 + `Autosave`/`.bak` 恢复，不承诺前向兼容。
8. 复杂对象依赖 JSON 形状兼容；属性改名/删除整单拒绝；集合种类变化允许。
9. 审计不可用时不能应用；`CommittedUnsaved` 时换班/关机可能丢内存值（依赖 `Autosave`）。
10. 应用期间被拒的定时/变量触发必须延后重试；未实现前不得宣称「不影响触发」。

## 16. 反模式（实现时禁止）

- 禁止按 `InputValues` 现有键自动推断 schema。
- 禁止名字当持久化外键（步骤名/变量名/轴名）。
- 禁止直写 `InputValues` 字典（必须 `SetInputValue`）。
- 禁止实时写穿、运行时覆盖层、旁挂文件作权威。
- 禁止半应用/部分成功/静默跳过；禁止把「跳过」写成成功。
- 禁止用 `EditGate.IsRunLocked` 或 `FlowModel.RunState` 单判当运行闸。
- 禁止在 `CompiledVersion` 编译后取值。
- 禁止审计不可用时仍「应用并保存」。
- 禁止在应用期间 `DoEvents`/弹窗/`Serialize`。
