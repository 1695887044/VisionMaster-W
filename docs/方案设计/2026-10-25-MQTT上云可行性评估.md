# MQTT 上云可行性评估（2026-10-25）

> 性质：评估与决策留痕，**本轮未改任何代码**。结论以磁盘代码为准；引用行号是 2026-10-25 的快照。
> 范围：把检测结果 / 设备数据 / 运行状态通过 MQTT 上云；同时评估"MQTT 作为通讯协议"是否可行。

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 能不能做 | 能。仓库已有可用的 MQTT 客户端源码（HslCommunication），不需要从零写协议。 |
| 推荐落点 | **独立"云通道"服务（发布为主）+ 结果发布步骤**；一期**不要**把 MQTT 做成第 7 种轮询协议。 |
| 最小闭环 | 本地 broker + 每件结果发布 + 断线重连 + 断网补传 + 测试发送，约 **4–6 人日**。 |

## 1. 现状盘点

### 1.1 设备通讯层是"请求-响应 + 轮询"

- `ICommunicationConnection` 的语义是 `Read<T>(address)` / `Write(address,value)` / `ReadBytes` / `ReadBits`（`Core/CommunicationContracts/ICommunicationConnection.cs:31-43`）。
- `ConnectionWorker` 每连接一条专属线程；`PollScheduler` 多扫描组；`PollBatchPlanner` 把连续地址合并成段读（`Communication/Communications/Manager/`）。
- 地址模型 `DeviceAddressBase` 围绕寄存器 / 字节 / 位偏移（`Core/CommunicationContracts/DeviceAddressBase.cs`）。`FreeProtocol` 已经证明"地址 = 命令文本"可以存在，但仍然是**一问一答**（`Core/CommunicationContracts/Config/FreeProtocolConfig.cs`）。
- 协议清单是**四处手工同步**：`CommunicationType` 枚举（`Core/Enums.cs:454-470`）、`TryCreateConfig`（`CommunicationConfig.cs:230-243`）、`CommunicationProtocols.Implemented`（`:359-367`）、`ConnectionFactoryManager.RegisterDefaults`（`ConnectionFactory.cs:247-264`）；`CommChecks` 的 B3 断言钉住一致性。
- 枚举按整数落盘（`_configJsonSettings` 没有 `StringEnumConverter`，`AdvancedCommunicationManager.cs:1137-1143`）。**新增协议只能追加在枚举末尾**，插在中间会让旧 JSON 的数字整体错位。

### 1.2 轮询层对"读不到"的判定是致命的

`PollBatchPlanner` 的结论是"全失败 ⇒ 通信级故障"：

```csharp
// Communication/Communications/Manager/PollBatchPlanner.cs:667-671
if (attempted == 0) return PollCycleOutcome.Completed;
if (linkFault) return PollCycleOutcome.LinkFault;
return failed < attempted ? PollCycleOutcome.Completed : PollCycleOutcome.LinkFault;
```

`ConnectionWorker` 收到 `LinkFault` 立刻 `OnConnectionBroken` 并进入重连（`ConnectionWorker.cs:506-510`）。

MQTT 的语义是"订阅后等消息"。一个主题在第一条消息（或 retained 消息）到达前**没有值可读**：

- 如果 `Read<T>` 在无消息时抛异常 → 轮询层判"全失败"→ 断线重连 → 重连后又读不到 → **无限重连**；
- 如果返回 `default(T)` → 把"没有数据"发布成"值 = 0/空"并标 Good，这是更坏的静默错误。

**结论**：MQTT 不能直接套现有轮询协议，除非先给轮询层加"推送型连接"能力（跳过轮询、由连接主动推值、质量由消息到达驱动）。这是一次通讯层契约改造，不是加一个类。

### 1.3 结果上报已有成熟范式

`Plugin.ResultUpload` 已经解决"流程线程不碰网络"的问题：

- 有界队列 `BlockingCollection<UploadJob>(1000)`；
- 后台单消费线程；失败退避 0.5s / 1s / 1.5s 封顶 3s；
- 断网 spool（JSONL，10 万行上限）+ 幂等 `UploadId`；
- 异步 / 同步两种模式；`BlockOnFailure` 决定是否阻断流程；
- 字段表 / 原始 JSON / 通知模板四套报文预设（`UploadQueue.cs:72-90`、`ResultUploadPlugin.cs`）。

这套"入队即返回 + 后台发送 + 补传"的骨架可以直接复用到 MQTT 发布；但 `UploadQueue` 与 `HttpClient` 绑定，不能直接当 MQTT 队列用，需要抽一层传输接口，或在新插件里重写队列（约 300 行）。

### 1.4 可选模块与安全默认已有模板

`ScadaWeb` 是现成的"可选模块"范式：

- `AppConfig.ScadaWeb.Enabled` 默认 false（`Core/Models/AppConfigModel.cs:280-307`）；
- 独立 `Web\` 目录 + `ScadaWebModuleLoader`，不放进 `Modules\`（`VisionMaster/Services/ScadaWebModuleLoader.cs:31-44`）；
- 默认只读、命令面关闭、运动命令禁用；
- `pack.ps1` 有 Web\ 拷贝与"启用了但缺 DLL 就打包失败"的检查（`pack.ps1:152-190`）。

云通道可以照这个模板做，也可以做成宿主的一等 `IAppModule`（像 `CommunicationModule` / `HttpImageServerModule`）。两者的取舍见 §3.2。

### 1.5 HslCommunication 已带 MQTT 客户端（零新增依赖）

`DLL/HslCommunication/MQTT/` 下有 `MqttClient`、`MqttServer`、`MqttSyncClient`，且已编进现有工程。能力：

- MQTT 3.1.1（CONNECT 协议级别字节 = 4，`MqttHelper.cs:228-233`）；
- QoS 0/1/2 + Retain（`MqttApplicationMessage.cs:18-49`）；
- 用户名 / 密码（`MqttCredential`）、遗嘱（`WillMessage`）、KeepAlive、CleanSession（`MqttConnectionOptions.cs:54-134`）；
- TLS：`UseSSL`、`CertificateFile`、`SSLSecure`（`:70-82`）；
- 断线自动重连（10 秒间隔，`MqttClient.cs:708-766`）；
- `OnMqttMessageReceived` / `OnClientConnected` 事件。

**但有三个坑**：

1. `MqttConnectionOptions.IpAddress` 的 setter **同步做 DNS 解析**（`HslHelper.GetIpAddressFromInput` → `Dns.GetHostEntry`，`HslHelper.cs:286-302`）。如果在 UI 线程构造配置（属性面板 / 方案加载）就会卡住甚至抛 `SocketException`。
2. 解析结果被**缓存成 IP**；重连不会重新解析。云厂商的域名做多 A 记录 / 故障转移时，会一直打旧 IP。
3. 未发现 WebSocket 支持；如果现场只放行 443 / WebSocket，HSL 走不通。客户端证书分支的 TLS 版本也偏旧（固定 `Tls | Tls11 | Tls12`，`MqttClient.cs:945-950`）。

**规避方式**：把 `MqttConnectionOptions` / `MqttClient` 的创建放在后台连接线程；每次重连**重建** client/options（强制重新解析 DNS）；用 `IMqttTransport` 薄接口隔离，后续可换 MQTTnet。

### 1.6 其他相关事实

- 变量有 `ValueChanged`（`NetworkVariableModel.cs:1156`，由轮询线程 `UpdateMirrorValue` 触发），云通道可以订阅；但要注意线程封送。
- 系统健康面板的 `CommunicationHealthMonitor.DescribeEndpoint` 只认 `EthernetConfigBase` / `SerialConfig`（`CommunicationHealthMonitor.cs:165-170`）；云连接要单独加健康行。
- 启动自检 `CommunicationCheck` 是全 Warning 的后台项（`CommunicationCheck.cs:23-33`），云连接不应进启动关键路径。
- 插件能力面的注入范式是 `IExecutionContext` 上的默认属性（`Comms` / `Database`，`Shard/Core.Interfaces/IExecutionContext.cs:84-101`）。新增能力要同步 `ExecutionContext.RuntimeCapabilities` 与 `ExecutionContextCapabilitySource.ResolveCapabilities`（`Core/ExecutionContext.cs:144-151`、`Core/ExecutionContextCapabilitySource.cs:48-59`），否则装配第一跳就抛。
- 凭据保护范式：`DbCredentialProtector` 用 DPAPI `LocalMachine` + entropy，密文只进机器级 `databases.json`，`.vms` 永不出现（`Services/Core.Database/DbCredentialProtector.cs:9-16`）。
- 图片不要走 MQTT：仓库只有"HTTP 收图"（`HttpImageServerModule`），没有云图片上传；建议图片走对象存储 / HTTP，MQTT 只发 URL / ID。

## 2. 四种落点对比

| 方案 | 适合什么 | 复用 | 主要问题 | 估算 |
|---|---|---|---|---|
| A. 第 7 种通讯协议 `CommunicationType.Mqtt` | 云端变量要像 PLC 一样进 SCADA / 流程，能读能写 | 变量、流程步骤、SCADA、健康、写租约 | 轮询语义不匹配；无消息 → LinkFault → 无限重连；主题地址 / 批量规划 / 质量戳都要改 | 5–8 人日（含轮询层改造） |
| B. 独立云通道服务（推荐） | 结果 / 遥测 / 状态上云；发布为主 | 变量事件、队列 / spool 范式、健康面板、模块生命周期 | 新模块 + 新 UI + 新持久化；下行命令要另做安全闸 | 12–18 人日（MVP） |
| C. 结果发布插件 `Plugin.CloudPublish` | 每件结果发一条；不想动宿主 | ResultUpload 的字段表 / 队列 / spool / 测试按钮 | 无持续遥测 / 心跳 / 下行；多步骤会多客户端；凭据容易进 `.vms` | 4–6 人日 |
| D. 组合 B + C（+ A 二期） | 既要每件结果，又要遥测 / 状态；以后可能要云端变量 | 上述全部 | 需要一次契约 / 能力面设计 | 12–18 + 5–8（下行）+ 3–5（平台预设） |

**推荐 D**：一期 B + C，A 只在客户明确要求"云端变量进 SCADA / 流程"时再做。

> 如果将来做 A：不要继承 `EthernetConfigBase`——它的 `IpAddress` 带 IPv4-only `RegexValidation`（`EthernetConfigBase.cs:16-20`），云域名会被属性面板拒绝。应新建 `MqttConfig : ConnectionConfigBase`，用 `Host` 字段；健康面板的 `DescribeEndpoint` 也要补分支。

## 3. 推荐方案（B 为主，C 为入口）

### 3.1 总体数据流

```
流程步骤（CloudPublish）──┐
变量 ValueChanged/周期快照 ─┼─→ CloudOutbox（有界队列 + JSONL spool）
报警/状态/心跳 ───────────┘        │
                                   ▼
                          CloudUplinkService（单发布线程/状态机）
                                   │
                                   ▼
                          IMqttTransport（HSL 或 MQTTnet）
                                   │
                                   ▼
                              MQTT Broker / 云平台
```

- 流程线程只做"组报文 + 入队"（微秒级），网络与重连全在云通道线程。
- 入队失败按"阻断 / 放行"契约处理（照 ResultUpload 的 `BlockOnFailure`）。
- 下行命令是**另一条独立链路**，默认关闭（§3.6）。

### 3.2 组件与落点

| 组件 | 落点 | 职责 |
|---|---|---|
| `ICloudPublisher` / `NullCloudPublisher` | `Shard/Core.Interfaces` | 插件可见的发布契约（默认空实现，未启用时给出中文原因） |
| `CloudUplinkService` | 新工程 `Services/Core.Cloud`（net9.0-windows，引用 HSL + VM.Core） | 连接状态机、发布队列、spool、主题解析、报文组装、健康快照 |
| `CloudModule : IAppModule` | 宿主 `VisionMaster/Modules/` | 注册服务、按 `AppConfig.CloudUplink.Enabled` 启动、注册退出任务 |
| `CloudSettingsView/ViewModel` | 宿主 `VisionMaster/Views|ViewModels/DialogViews/` | broker 配置、主题映射、测试发送、日志回看 |
| `Plugin.CloudPublish` | `Plugins/Plugin.CloudPublish/` | 每件结果发布（字段表 / 原始 JSON / 发送时机），调用 `context.Cloud` |
| `MqttChecks` | 根目录断言宿主 | 本地 broker 回环、重连、QoS / retain、spool、报文契约 |

> 为什么 `ICloudPublisher` 放 `Core.Interfaces`：插件物理上够不到宿主服务，`IExecutionContext` 的 `Comms` / `Database` 就是同一范式（`IExecutionContext.cs:84-101`）。新增能力要同步 `RuntimeCapabilities` / `CapabilitySource` 两处（见 §1.6），否则装配第一跳就抛。

> 工程落点也可以放进 `Communication/VM.Communication`（它已引用 HSL + Core），代价是把"设备协议"和"云通道"混在一个程序集；`Services/Core.Database` 的先例说明独立服务库更清晰。两者都能做，推荐独立工程。

### 3.3 配置与密钥

- **方案级**（`SolutionModel`，随 `.vms` 走）：broker 地址 / 端口 / TLS 开关 / 主题前缀 / 发布规则 / 变量映射。理由与 `CommunicationConfigs`、相机配置一致：这些是"这条产线怎么上云"。结果字段表仍随步骤配置（`Plugin.CloudPublish` 的 `[StepConfig]`）走，不放进方案根。
- **机器级**（`AppConfig.json`）：`CloudUplink.Enabled`（默认 false）、队列上限、spool 上限、日志级别、是否允许下行。理由与 `ScadaWebSettings` 一致：这些是"这台机器怎么对外"。
- **密钥**：用户名 / 密码 / 设备密钥 / 客户端私钥**不进 `.vms`**；照 `DbCredentialProtector` 做 DPAPI `LocalMachine` + 独立 entropy，密文存机器级 `cloud-credentials.json`，方案里只存 profile 名。日志与异常消息必须脱敏。
- **ClientId**：`vm-{installId}-{solutionShortId}`；`installId` 是首次运行生成并持久化在机器级的 GUID（不要只用 SolutionId——同一方案在测试机和产线机各跑一份会互相踢下线）。
- **兼容性**：老版本打开含云配置的 `.vms` 时，`$type` 白名单需要包含新命名空间（`ConnectionConfigSerializationBinder` 只放行 `VisionMaster.Models / Communications / Plugin. / VisionMaster.Scada`，`ConnectionConfigJsonConverter.cs:98-102`）。云配置要么放在 `VisionMaster.Communications` 命名空间下，要么把新命名空间加进白名单——**后者是安全边界变更，必须评审**。

### 3.4 主题与报文契约（这是"上云"的真正工作量）

MQTT 只是传输；云平台真正验收的是主题与报文。建议先定一份 v1 契约：

```
{prefix}/{site}/{line}/{device}/{kind}
例：vm/site01/lineA/vm01/result
    vm/site01/lineA/vm01/telemetry
    vm/site01/lineA/vm01/status
    vm/site01/lineA/vm01/alarm
```

报文（JSON，UTF-8，UTC ISO8601）：

```json
{
  "schemaVersion": 1,
  "messageId": "guid",
  "deviceId": "vm01",
  "solutionId": "…",
  "timestamp": "2026-10-25T08:00:00.000Z",
  "kind": "result",
  "data": { "sn": "SN001", "result": "OK", "values": { } }
}
```

- `messageId` 是幂等键（spool 重发、QoS1 重投都用它）。
- `schemaVersion` 用于演进；新增字段只加不删。
- 时间统一 UTC；本机时区另给 `tzOffsetMinutes`（可选）。
- 图片只发 `imageUrl` / `imageId`，不发字节。
- 主题与字段名要可配置（不同云平台 / 客户 MES 的命名不同），但**模板要有校验**（非法字符、空段、通配符）。
- 阿里云 / 华为云 / AWS 的鉴权与 topic 权限不同，需要 `ICloudAuthProvider` 预设（§3.7）。

### 3.5 可靠性

- **QoS 1**（至少一次）+ 应用层幂等键；QoS 2 代价高，一期不用。
- **Retain** 只用于 `status` / `heartbeat`（让新订阅者立刻拿到当前状态），业务结果不 retain。
- **CleanSession**：一期 true（简单）；如果要 broker 侧排队，再评估 false + 持久会话（但客户端离线时的 publish 不会被 broker 排队，仍要应用层 spool）。
- **断网 spool**：照 ResultUpload 的 JSONL + 上限 + 毒记录上限；恢复后按时间顺序补发，实时件优先。
- **背压**：有界队列；满时按 `BlockOnFailure` 决定"丢 / 阻断 / 降级为仅记录"；健康面板暴露队列深度与丢弃计数。
- **重连**：指数退避 + 抖动；每次重连重建 client/options（解决 HSL 的 DNS 缓存）；记录 `reconnectCount` / `lastError`。
- **LWT**：`status` 主题的离线遗嘱，broker 侧能立刻看到掉线。

### 3.6 安全与下行

- TLS 默认开；`UseSSL=true`、`SSLSecure=true`；自签证书只在显式勾选"跳过校验"时允许，并在 UI 上标红。
- 禁止明文公网 1883；如果 broker 在内网 / 本机，允许显式降级并写审计日志。
- 下行命令**默认关闭**（`AllowCommands=false`），与 `ScadaWebSettings` 的安全默认一致（`AppConfigModel.cs:280-307`）。
- 打开后也只允许**白名单动作**：topic → 动作映射（如 `cmd/start`、`cmd/stop`、`cmd/writeVar`），不提供"任意地址写"。
- 每条命令过：权限（`ScadaAccessPolicy` / 用户组 Key）→ 租约（`OperationLease`）→ 审计（`ScadaAuditWriter` 风格）→ 执行器（与 SCADA Web 同一 `ScadaActionDispatcher`）。
- 运动命令默认禁用（R132A 的口径）；急停 / 停止类命令可以单独授权。
- 命令幂等 / 防重放：`messageId` + 时间窗 + 可选 HMAC；拒绝过期 / 重复命令。

### 3.7 云平台预设

| 平台 | 鉴权 | 备注 |
|---|---|---|
| 通用 MQTT（EMQX / Mosquitto） | 用户名 / 密码 + TLS | 一期默认 |
| 阿里云 IoT | ClientId / Username / Password 由 ProductKey / DeviceName / DeviceSecret 派生（HMAC-SHA256） | 需要预设生成器；topic 受产品模型限制 |
| 华为云 IoTDA | deviceId + secret + 时间戳（HMAC-SHA256） | 同上 |
| AWS IoT Core | 双向 TLS（客户端证书 + 私钥） | 需要证书文件管理；支持 8883 / 443 |

建议 `ICloudAuthProvider` 接口 + 四个实现；平台差异只在"连接参数生成"和"topic 校验"，不要散落到服务里。

### 3.8 可观测性

- 健康行：状态（未启用 / 连接中 / 在线 / 退避）、broker、最后发布时刻、队列深度、spool 行数、重连次数、发布速率、最后错误。
- 日志：连接 / 断开 / 重连 / 发布失败 / 队列满 / 证书错误，全部走 `ILogService`（R78），限流防刷。
- 测试发送按钮：按当前配置真发一条，显示 broker 返回 / 错误；不落 spool（照 ResultUpload 的 `allowSpool:false`）。
- 断言：`MqttChecks` 输出 `PASS/FAIL` 计数，接 `tools/run_gates.ps1`（R182；host 清单在 `run_gates.ps1:251-263`）。

### 3.9 分阶段与工作量

| 阶段 | 内容 | 估算 | 验收 |
|---|---|---|---|
| P0 PoC | 本地 broker + HSL 客户端 + 发布 JSON + 重连 + 最小 spool | 3–5 人日 | 断网 / 重启 broker 后能补发；无重复 ID |

## 5. 验证方案

1. **契约断言（无 broker）**：配置 Validate、主题模板、报文 schema、spool、幂等 ID、队列背压。
2. **本地 broker 回环**：用 HSL `MqttServer`（已在仓库）或 MQTTnet.Server 起 `127.0.0.1` 随机端口；测 QoS1 / retain / 订阅 / 重连。
3. **故障注入**：broker 重启、端口拒绝、DNS 失败、TLS 证书不匹配、断网 30s、队列满、时钟偏移、重复 messageId。
4. **真实云沙箱**：目标平台（阿里云 / 华为云 / AWS）各连一次；核对 topic 权限、鉴权、报文。
5. **性能**：1000 件 / 分钟持续 10 分钟；观察队列深度、内存、发布延迟、CPU；确认流程节拍不受影响。
6. **门禁**：`tools/run_gates.ps1` 加 `MqttChecks`；`pack.ps1` 加 Cloud 产物检查；R42 手册资源数核对。

## 6. 不建议的做法

- 不要把 MQTT 直接塞进 `CommunicationType` 当第 7 种协议（至少一期）。
- 不要把用户名 / 密码 / 设备密钥写进 `.vms`。
- 不要默认开放下行"任意地址写"。
- 不要在 UI 线程构造 HSL MQTT options（DNS）。
- 不要把图片塞进 MQTT payload。
- 不要用 QoS2 作为一期默认（代价高、broker 支持差异）。
- 不要新增 NuGet 却不锁版本 / 不验证 `pack.ps1`。

## 7. 需要拍板的三件事

1. **只发还是发 + 收？** 只发 → 一期不做 P2；发 + 收 → 先定白名单动作与权限模型。
2. **通用 broker 还是指定云平台？** 通用 → 一期用户名 / 密码 + TLS；指定平台 → 先做该平台的鉴权预设与 topic 权限。
3. **每件结果还是持续遥测？** 每件 → C 为主；持续 → B 为主；两者都要 → B + C。
