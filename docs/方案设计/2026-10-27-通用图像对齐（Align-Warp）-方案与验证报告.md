# 通用图像对齐（Align & Warp）· 方案与验证报告

- 日期：2026-10-27
- 状态：可行性报告（未改代码）
- 建议落点：新增 `Plugin.ImageAlign`（通用图像对齐），放在预处理之后、差分/Blob/颜色/读码之前
- 一句话结论：**把“找基准 → 求变换 → 搬图 → 给有效区”做成一个可复用步骤**，不要每个下游插件自己写一遍；v1 做模板/基准点 + 刚性/仿射/透视，v2 再评估局部可变形。

## 1. 为什么做

### 1.1 下游插件已经明确要求“先对齐”，但没有人负责

- `Plugin.ImageDiff` 的帮助写得很直白：**“不做图像对齐。两张图错位时它只会告诉你整幅都不一样——那是模板匹配的活”**（`Plugins\Plugin.ImageDiff\Help\01-quickstart.md:115`），并建议在前面插模板匹配做仿射。
- `Matching` 确实有 `AlignedImage`（位姿归一化图，`Help\03-ports-and-parameters.md:35`），但它是**刚性位姿归一化**、绑定某个模板，且不输出逆变换/有效区；它解决“目标转正”，不解决“透视/局部形变/多基准点”。
- `BeadInspect` 内部有“平面可变形对齐”（`Help\01-quickstart.md:27`），但它是胶路检测的内部实现，别的插件用不到。
- `Blob`/`Color`/`Ocr`/`CodeReader` 都默认工件在固定位姿；批量流程里工件一偏，误判直接上升。

### 1.2 批量流程把这个问题放大了

- `pcb_focus` 121 张、`smd` 11 张、`label` 10 张这类批量流程，只要夹具/上料有 1~2mm 偏移或轻微透视，差分/Blob 就会整片报差异。
- 现场常见做法是“把阈值调大”或“每个产品单独调 ROI”；前者放过真缺陷，后者维护成本高。
- 通用对齐把“位置”从检测里剥离：**先搬回基准位姿，再让下游按固定坐标检测**。

### 1.3 为什么不是“再用一次匹配”

- 匹配输出的是位姿（Row/Column/Angle/Scale），不是“基准图 ↔ 当前图”的完整变换；透视/四点基准/逆变换/有效区都没有。
- 匹配的 `AlignedImage` 只做刚性归一化，不还原透视/非等比形变；对印刷、柔性件、倾斜拍摄不够。
- 通用对齐可以复用匹配做“找基准”，但输出的是**图像 + 变换 + 逆变换 + 有效区**，下游零改动。

## 2. 现状与缺口

| 现有能力 | 能做什么 | 缺什么 |
| --- | --- | --- |
| `Matching.AlignedImage` | 刚性位姿归一化（转正/平移/等比缩放） | 透视、非等比、四点基准、逆变换、有效区、残差 |
| `BeadInspect` 内部对齐 | 平面可变形（投影）对齐 | 不可复用、与胶路检测耦合 |
| `Calibration`/`HandEye` | 像素↔机械坐标变换 | 不做图像重采样 |
| `ImageDiff` | 逐像元差分 | 明确不做对齐 |
| `PoseTransform` | 位姿/坐标变换 | 不做图像 warp |

## 3. 方案（v1）

### 3.1 模式

| 模式 | 找基准的方式 | 变换 | 典型场景 |
| --- | --- | --- | --- |
| 模板位姿 | 复用 `Matching`（形状/NCC）找模板 | 刚性/相似（平移+旋转+等比） | 工件平移/旋转，模板稳定 |
| 基准点（2~4 点） | 用户给参考图上的 2~4 个基准点，运行期在图像里找对应点（模板/角点/卡尺） | 仿射（3 点）/ 透视（4 点） | 印刷、标签、PCB 标记点 |
| 手动四点 | 参考图/当前图各给 4 点 | 透视 | 调试、离线标定 |
| 参考图（v2） | 局部可变形/密集匹配 | 可变形 | 柔性件、拉伸薄膜 |

v1 只做前三种；v2 再评估局部可变形（可参考 `BeadInspect` 的 `prepare_alignment` 思路，但抽成通用步骤）。

### 3.2 端口（建议）

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Image` | `HImage` | 当前图（必填） |
| `ReferenceImage` | `HImage` | 基准图（模板/基准点模式） |
| `RefPoints` / `CurPoints` | `HTuple` | 手动四点/基准点（可选） |
| `AlignedImage` | `HImage` | 搬回基准位姿的图（同尺寸；边界填 0） |
| `HomMat2D` | `HTuple` | 3×3 透视矩阵（9 个数） |
| `InverseHomMat2D` | `HTuple` | 逆矩阵（下游把结果坐标搬回去） |
| `ValidRegion` | `HRegion` | 有效像素区（黑边之外） |
| `Score` | `double` | 匹配/拟合分数（0~1） |
| `Residual` | `double` | 基准点重投影残差（像素） |
| `IsOk` | `bool` | 可选：只有配了阈值才写；默认不判定 |

### 3.3 口径与边界

- **坐标**：图像像素系 (Row, Col)；矩阵按 HALCON `proj_hom_mat2d` 口径（3×3，行主序），`projective_trans_point_2d` 可直接验证。
- **重采样**：`projective_trans_image` / `affine_trans_image`，双线性；输出同尺寸，边界填 0；有效区由 `projective_trans_region`/`affine_trans_region` 把全图区域搬过去得到。
- **逆变换**：必须输出，下游把检测结果从对齐图坐标搬回原图坐标（否则结果显示/机械手会拿错坐标）。
- **不做判定**：只输出 `Score`/`Residual`；是否 OK 由「判定表」按阈值判。
- **不写全局变量**；结果只走端口/运行时变量（与判定表同一原则）。
- **镜头畸变**：先由 `Intrinsics` 去畸变，再做对齐；不要在透视矩阵里混畸变。

## 4. 怎么验证（核心）

### 4.1 合成真值（已知变换）

用 `checkerboard_400.png`、`smd`、`pcb_focus` 的清晰图，生成已知的：

- 平移 (dx,dy)、旋转 θ、等比缩放 s、非等比 (sx,sy)；
- 透视：4 个角点任意位移（已知单应矩阵）；
- 组合变换。

对每组：

1. 用参考图/基准点求 `HomMat2D`；
2. 与真值矩阵逐元素比（或比 4 个角点的重投影误差）；
3. 用 `projective_trans_image` 把当前图搬回，与真值对齐图逐像素比（平均绝对差）；
4. 用 `InverseHomMat2D` 把对齐图上的点搬回原图，往返误差 ≤0.1px。

**反向判据**：不做对齐（单位矩阵）时，对齐图与真值差必须明显（否则测试图本身没位移，用例无效）。

### 4.2 基准点模式

- 参考图给 4 个已知点，当前图用同样的 4 点（可加噪声/遮挡）；
- 期望：4 点重投影残差 ≤0.3px（合成）、≤1px（真图）；
- 反向：把其中 1 点挪 5px → 残差必须上升/判失败；遮挡 1 点 → 明确失败，不静默用 3 点硬算透视。

### 4.3 下游收益（最有说服力的验证）

- 取同一工件的两张图，人为制造 2~5px 平移/1~3° 旋转/轻微透视；
- 直接用 `ImageDiff`：差异面积很大（重影）；
- 先对齐再 `ImageDiff`：差异面积应下降 **≥80%**（目标 ≥90%）；
- 同样验证 `Blob` 的缺陷数/面积、`Ocr` 的识别率、`CodeReader` 的读码率在“对齐前/后”的差异；
- 反向：把对齐矩阵故意错 2px，下游差异面积应明显回升（证明对齐真的在起作用）。

### 4.4 与 HALCON 参考实现对拍

- 在断言宿主内用 HALCON 现算：
  - `proj_match_points_ransac` + `vector_to_proj_hom_mat2d` 求单应；
  - `projective_trans_image` 搬图；
  - `projective_trans_point_2d` 算角点误差。
- 与插件输出比：
  - 4 角点重投影误差差 ≤0.2px；
  - 对齐图平均绝对差 ≤1 灰度级；
  - `HomMat2D` 元素差 ≤1e-3（归一化后）。
- 必须用**同一组点/同一参考图**；点不同直接判失败，不比较。

### 4.5 真图验证

- `smd` 11 张：取一张做基准，其余做平移/旋转/透视变换（已知），验证恢复；
- `pcb_focus` 121 张：清晰段做基准，散焦段只验证“能对齐/分数下降”，不把散焦当几何误差；
- `label` 10 张：标签倾斜/透视，验证四点模式；
- 人工标注 4 个基准点作为真值，抽检 10 张。

### 4.6 验收标准（建议）

1. 合成：角点重投影 ≤0.3px；对齐图平均绝对差 ≤2 灰度级；逆变换往返 ≤0.1px。
2. 真图：基准点残差 ≤1px；对清晰 SMD/PCB 图，对齐后 `ImageDiff` 面积下降 ≥80%。
3. 对拍：与 HALCON 参考的角点误差差 ≤0.2px、对齐图差 ≤1 灰度级。
4. 反向：单位矩阵/错 2px/遮挡基准点/无纹理图四类必须红或明确失败。
5. 有效区：`ValidRegion` 覆盖图像内有效像素，黑边不进有效区；下游只在该区域内检测。
6. 性能：5MP 单次对齐目标 ≤100ms（待实测；模板匹配占大头）。
7. 坐标：`HomMat2D`/`InverseHomMat2D` 与 `projective_trans_point_2d` 自洽；下游结果搬回原图误差 ≤0.5px。

## 5. 风险与边界

- **弱纹理/重复纹理**：模板匹配可能误匹配；需要基准点/多模板/分数阈值兜底。
- **遮挡/缺基准点**：四点缺一不能硬算透视；明确失败，不退化成三点仿射。
- **镜头畸变**：必须先 `Intrinsics` 去畸变；否则透视矩阵吸收不了畸变。
- **非平面/大形变**：v1 不处理；v2 局部可变形再评估。
- **重采样模糊**：双线性会轻微模糊；下游阈值要按对齐后图重标。
- **有效区/黑边**：下游必须用 `ValidRegion` 限制检测区，否则黑边会被当缺陷。
- **坐标回搬**：只给 `AlignedImage` 不给逆变换，结果坐标会错；逆变换是必出项。

| --- | --- | --- |
