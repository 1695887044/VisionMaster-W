# SCADA P1 代码评审与实施切分

日期：2026-10-24
范围：P1 剩余四项——`Hmi.StateView`（图形开关 / 图形 IO 域 / 字指示灯）、`Hmi.SubPage`（画中画）、报警生命周期事件、位操作动作。
前置：P1-1（方案级文本列表 + ComboBox 接入）已落地并验证（`ScadaChecks` 2710/0，见 `docs/code-changes/2026-10-24-SCADA文本列表与ComboBox接入（P1-1）.md`）。
结论先行：四项都能在现有架构上做，但**成本差异很大**；建议按 StateView → 位操作 → 报警事件 → SubPage 的顺序施工，SubPage 先做“固定页 + 只读 + 活数据”的 P1a，不把变量切页和交互事件塞进第一批。

## 二、逐项评审

### 2.1 `Hmi.StateView`（图形开关 / 图形 IO 域 / 字指示灯）

**建议形态：一个 TypeKey + 两个正交属性**，不新增 `GraphicSwitch` / `GraphicIO` / `WordLamp` 三个 TypeKey。

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| `Value` | int，可绑定 | 与 ComboBox 同一条数据语义 |
| `StateListId` | 字符串，可空 | 空 = 回退旧 `Options`（兼容 P1-1 之前的工程） |
| `Presentation` | `Text` / `Image` / `TextAndImage` | 字指示灯 = Text；图形 IO = Image；图文 = TextAndImage（落盘值不用 `Both`，避免与 Line 的 `Both=双向` 在全局译名表里撞车） |
| `Interaction` | `None` / `Toggle` / `WriteValue` | 图形开关 = Toggle；图形 IO / 字指示灯 = None |
| `ClickValue` | int | `WriteValue` 时写这个值 |
| `ImageStretch` | `Uniform` / `UniformToFill` / `Fill` | 图片呈现 |
| `TextAlignment` | 继承文字属性 | 文字呈现 |
| `StateListMissing` | 只读 bool | 列表删除/坏 Id/解析器未注入 |

**列表条目要扩三个可选字段**：

- `Image`：方案内相对路径（与 `Hmi.Picture` 的 `SourcePath` 同口径，走 `ImageAssetResolver`）。
- `Color`：状态色（文字/边框/指示点用；图形态可不用）。
- `DefaultImage`（列表级）：值无匹配时的占位图；没有就显示虚线占位，不拿别人的图顶上。

**为什么只做一个 TypeKey**：三个场景的差异只在“呈现方式 + 是否可点”，用属性表达即可；拆三个 TypeKey 会让文本列表、属性面板、Web 渲染器、断言各写三份。代价是工具箱可发现性差，建议在描述符 `Description` 里写清“图形开关 = Image + Toggle；图形 IO = Image + None；字指示灯 = Text + None”，并在属性面板给“预设”下拉（只改默认值，不新增 TypeKey）。

**复用**：`ScadaStateList`、`StateListResolver`、`StateListMissing` 口径、`IScadaValueWriter` 写入、`RaiseScadaEvent(ObjectChanged/Opened/Closed)`、`ImageAssetResolver`。
**新增**：控件类 + 模板 + 描述符 + 条目字段 + 快照字段 + 管理器列 + Web 渲染器 + 断言。
**风险**：列表条目从“值→文字”扩成“值→文字/图片/颜色”，要保证旧 `.vms` 反序列化后 `Image`/`Color` 为空时行为与 P1-1 完全一致；管理器删除列表仍要显示引用数（ComboBox + StateView 都算引用）。
**结论**：成本 M，收益最高，先做。

### 2.2 `Hmi.SubPage`（画中画）

**现有架构不能直接复用弹窗**：弹窗是运行窗口的浮层，SubPage 是画布里的一个矩形；两者生命周期、命中测试、页面栈语义都不同。现有基座页是“叠在下面的公共层”，也不是“嵌进矩形里的页”。

**建议属性**：

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| `TargetPageId` / `TargetPageName` | 画面选择 | 固定页 |
| `PageSource` | `Fixed` / `FollowVariable` | 跟随变量切页 |
| `PageNameVariable` | 变量选择（字符串） | `FollowVariable` 时读它，按画面名解析；不做“页面 Id 变量” |
| `Fit` | `Uniform` / `UniformToFill` / `Fill` / `Original` | 嵌入页缩放 |
| `ShowBackground` | bool | 是否画目标页背景 |
| `Interactive` | bool，P1 固定 false | P1 只读；交互事件 P2 |
| `MissingBehavior` | `Placeholder` / `KeepLast` | 目标页删除/变量指向不存在页时 |

**代码评审结论（关键）**：

1. **数据泵是最大成本**。`ScadaRuntimeBinder` 只扫主画布的 `EnumerateControls()`（`ScadaRuntimeBinder.cs:121`），嵌套画布里的控件不在主画布 `_containerIndex`，绑定不会自动生效。两条可行路线：
   - A. `SubPageElement` 自己持有嵌套 `ScadaCanvas`，在 `Loaded` 后用自己的 `ScadaRuntimeBinder` 建表（需要 `RuntimeContext.Values`，可为 null）；生命周期跟着图元卸载。
   - B. 主画布递归枚举嵌套控件，主 binder 统一建表；需要新接口 + 诊断归属，改动面更大。
   - 建议 A：边界清楚，SubPage 自己负责自己的数据泵；代价是每个 SubPage 一份订阅表，页面多时要注意释放。
2. **事件路由默认关闭**。`ScadaRuntime.RaiseElementEvent` 只认当前页/弹窗成员（`ScadaRuntime.cs:253-269`），SubPage 内的按钮事件会被拒。P1 设计成只读，正好绕开；如果 P1 就要可交互，必须把“活跃子页”纳入事件宿主判断，成本上一个台阶。
3. **快照要递归**。`ScadaPageSnapshot` 目前只有 `BasePages` + `Popup`，没有“嵌入页”字段。Web 端要显示 SubPage，快照必须带目标页快照（建议 `SubPageSnapshot` 或 `Dictionary<Guid, ScadaPageSnapshot>`），并防止 A 嵌 B、B 嵌 A 的循环。
4. **目标页校验**：建议只允许普通页（`FindNavigablePage` 口径），禁止弹窗页、禁止自引用、禁止循环；基座页是否允许要单独拍板（基座是公共层，嵌进矩形语义上可行，但编辑体验容易混）。
5. **权限**：目标页 `RequiredRole` 不满足时显示“无权查看此画面”，不要渲染半页内容。

**建议切分**：
- **P1a**：固定页 + 只读 + 活数据 + 缺页/无权/未选三态。成本 M。
- **P1b**：`FollowVariable` 变量切页 + 可交互事件。成本 L，等 P1a 稳定后再做。

**结论**：P1a 可做，但排在最后；不要和 StateView 同一批。

### 2.3 报警生命周期事件

**现有能力**：`ScadaAlarmEngine` 已有 `AlarmRaised` / `AlarmChanged` / `AlarmCleared`（`ScadaAlarmEngine.cs:201-207`），宿主已经订阅并落 CSV/JSON（`ScadaRuntimeHost.cs:856-859`）。缺的是“组态侧能配的三条事件”。

**建议语义**：

| 事件 | 触发点 | 说明 |
| --- | --- | --- |
| 报警激活 | `AlarmRaised` | 条件从正常进入激活 |
| 报警取消 | 条件恢复（`Recovered` 或直接 `Normal`） | 只发一次；确认与否不影响“取消激活” |
| 报警确认 | `AcknowledgeCore` 成功 | 操作员确认那一刻 |

**代码评审结论**：

- 不建议在运行态靠 `AlarmChanged` 的 `State` 反推三条事件：`Active → Acknowledged → Normal` 与 `Active → Recovered → Acknowledged` 两条路径的“取消激活”时点不同，反推容易漏/重。建议在引擎里补 `AlarmDeactivated` / `AlarmAcknowledged` 两个事件（或在 `AlarmChanged` 上带 old/new state），由引擎保证“每条报警每个生命周期只发一次”。
- 事件是**页面级**：`ScadaPageEvents.All` 追加三条；`ScadaRuntime` 增加 `RaiseAlarmEvent(record, type)`，只向当前页/弹窗页广播。图元级报警事件 P1 不做（现有报警对象是定义，不是图元）。
- `ScadaEventHook` 需要“报警来源”过滤：`AlarmId` + `AlarmName`（Id 权威、名字兜底），空 = 全部报警。否则页面上三条事件只能对全部报警触发，无法做“温度报警才切页”。
- 属性面板：页面事件行勾选后显示“报警来源”选择器（全部 / 指定报警）；指定报警被删除时显示“报警已删除”，不静默变成“全部”。
- 动作表复用现有动作；不需要新的“报警动作”。
- 线程：引擎事件可能在变量轮询线程上抛（`ScadaAlarmEngine` 注释），`RaiseAlarmEvent` 必须切回 UI Dispatcher 再执行页面钩子（现有 `ScadaRuntimeHost.OnAlarmRaised` 只写日志，没切 UI；页面钩子会执行动作，必须切）。

**结论**：成本 S/M，价值高（报警联动是商业 HMI 的硬需求），排在 StateView 与位操作之后。

### 2.4 位操作动作

**先纠正一个评审结论**：位操作不是“完全没有”。`BitButtonElement` 已经支持置位/复位/取反/按下 ON/按下 OFF 五种模式（`BitButtonElement.cs:52-65`），并且写入走 `IScadaValueWriter`、发 `ObjectChanged/Opened/Closed`。缺的是**事件动作表里没有位操作**——所以“报警确认后置位某个复位位”“页面加载时取反某个标志”这类跨对象联动做不了。

**建议新增**：

- `ScadaActionType.SetBit = 24` / `ResetBit = 25` / `ToggleBit = 26`（末尾追加，不动 1~23）。
- `ScadaAction.BitIndex`：`int?`；`null` = 布尔变量整体置位/复位/取反；`0..31` = 整型变量的位号。
- 执行侧：`ExecuteBitAction` 复用 `_values.TryResolve` + `handle.Value` + `handle.TryWrite`；整型做读-改-写，位号越界/变量非整型/非布尔直接拒绝并写清原因。
- 属性面板：动作类型选“置位/复位/取反”后显示变量选择 + 位号输入；布尔变量可留空，整型变量必须填 0~31（按变量类型给上界更准，但当前动作行拿不到变量类型，先按 0~31，执行侧再按实际类型校验）。
- 审计/日志：`Describe()` 给 `变量.位号 ← 1/0/取反`，与现有 `WriteVariable`/`Increment` 同一句式。
- 危险动作：与 `WriteVariable` 同级，不额外标红；如果现场要求“写 PLC 位必须确认”，再单独加 `IsDangerous` 规则。

**复用**：变量寻址、写租约、失败原因、审计格式全部走现有 `ScadaActionDispatcher` 通道，不新开写口。
**结论**：成本 S，最小、最稳，建议紧跟 StateView 之后做。

## 四、建议施工顺序与验收

1. **StateView（M）**：列表字段 → 控件/模板 → 描述符 → 属性面板 → 快照/Web → `ScadaChecks`。验收：文本/图片/图文三态；列表缺失；无匹配；只读/点击切换；权限拒绝；图片缺失占位；旧 `Options` 回退；管理器引用数。
2. **位操作（S）**：枚举 + 字段 → dispatcher → 动作编辑区 → 断言。验收：布尔置位/复位/取反；整型位 0/31/越界；变量缺失；写失败；审计文案。
3. **报警事件（S/M）**：引擎事件 → 事件枚举/过滤 → 运行态路由（切 UI）→ 属性面板 → 断言。验收：激活/取消/确认各一次；全部 vs 指定报警；报警删除；非当前页不响；动作执行顺序；确认后取消不重复。
4. **SubPage P1a（M）**：控件/嵌套画布 → 自有 binder → 缺页/无权/未选 → 快照/Web → 断言。验收：固定页、活数据、只读、缺页占位、循环引用拒绝、卸载无订阅残留。
5. **SubPage P1b（L，后续）**：变量切页 + 交互事件 + 活跃子页路由。

## 五、未决问题（需要拍板）

1. StateView 是一个 TypeKey + 预设，还是三个 TypeKey？本评审建议一个 TypeKey。
2. 列表条目是否要 `Color`，还是只做 `Image` + `Text`？如果字指示灯需要状态色，建议要。
3. SubPage P1 是否接受“只读、不可交互”？如果不接受，成本从 M 升到 L。
4. 报警事件是否只做页面级？图元级（如 AlarmBanner 自己的事件）是否需要？
5. 位号范围按 0~31 固定，还是按变量类型（byte/word/dword）动态给上界？本评审建议先 0~31，执行侧按类型校验。
6. Web 运行态是否要在本批同步支持 StateView/SubPage，还是先桌面端、Web 下一批？P1-1 已同步 Web 文本态；建议 StateView 同步，SubPage 视快照成本再定。
