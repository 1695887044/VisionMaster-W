# 数据库通讯 · 架构评审与第一版方案

- 日期：2026-10-22
- 状态：评审完成 · 第一版方案待用户拍板后实施
- 评审方式：四角色并行 R1（通信 / 上位机 / 视觉 / 审查）+ 审查员 R2 交叉裁决
- 口径：只读评审，未构建、未改代码；结论以当前磁盘代码为准

---

## 一、一句话结论

**“数据库通讯”不是新通信协议，也不是纯插件直连；第一版应做成“插件形态的数据库步骤 + 宿主数据库服务”。**

- 现场看到的是：`Plugins\Plugin.Database` 的三个流程步骤 + 硬件管理里的“数据库”页。
- 连接池、事务、参数化、凭据、健康、审计放在宿主 `Services\Core.Database`。
- 插件通过 `Core.Interfaces.IDatabaseAccess` 调用，不引用任何 Provider，不持有连接/事务。
- **不新增 `CommunicationType.Database`**，不把 SQL 塞进变量地址，不做数据库变量轮询。

---

## 二、评审过程与结论

### R1 四角色

| 角色 | 结论 | 核心理由 |
| --- | --- | --- |
| 通信 | 选 C；B 否决 | `ICommunicationConnection.Read<T>` 限定 `struct`，只有 `ReadBytes/ReadBits`；`PollBatchPlanner` 按 `AddressConfig` 分段。SQL 的结果集/事务/参数没有表达，硬塞会把数据库退化成“字符串拼 SQL 的寄存器” |
| 上位机 | 选 C | 插件只引用 `Core.Interfaces`；Provider/凭据/权限/审计若压进插件，会重复且散落。宿主服务可集中做 DPAPI、只读档、审计与退出释放 |
| 视觉 | 倾向 A（先纯插件），C 作为后续 | 首版三个步骤 + 静态写 Hub 最省；但承认 Provider 私有部署与凭据散落是风险 |
| 审查 | 选 C（加权 4.3 / A 2.8 / B 1.5 / D 3.2） | A 的插件实例生命周期不适合持有连接/事务；B 语义不匹配；C 在安全、部署、维护、测试上全面占优 |

### R2 裁决

- **A vs C：选 C。** 用户可见形态仍是插件；C 只是把 Provider/凭据/池/事务放进宿主。A→C 不是无痛替换：A 的每个数据访问点都要改、凭据要迁移、测试要重写；若 A 把 Provider/凭据放宿主，它实质已经是 C。
- **命名语句 vs 内联 SQL：v1 只做命名语句。** SQL 编辑器放硬件管理“数据库”页，保存到宿主 profile；步骤只选语句名 + 参数。内联 SQL 会随 `.vms` 明文落盘，且流程编辑没有权限闸，无法做参数化/审计硬闸。
- **Provider：v1 一个产品 Provider + SQLite 仅测试。** SQL Server → `Microsoft.Data.SqlClient`；MySQL/MariaDB → `MySqlConnector`；PostgreSQL → `Npgsql`。没有首客户信息时默认 SQL Server（MES 最常见）；零 native 资产硬要求则选 MySQL。
- **凭据：v1 就做，不能明文。** Windows 集成认证优先；SQL 认证密码用 DPAPI 存宿主 `databases.json`，`.vms` 只存 CredentialId/profile 名。排期不足则 v1 只发集成认证，不接受“明文 + 掩码”交付。
- **首版核心用例：写结果行。** 读配方/工单降为“查询 → 写全局变量/端口”；v1 不承诺改其他插件 `[StepConfig]` 阈值。
- **失败语义：写默认 `FailFast=true`（抛→Faulted 停线），读默认 `false`（步骤 Failed，流程继续），每步可配。** 不要复用 `BlockOnFailure` 名字——它只置 `Success=false`，不会停流程。
- **批量：v1 单行同步写，或一次 `TryExecuteBatch` 多参数集（一个事务）；不做静态写 Hub/后台攒批线程。**

## 四、第一版架构

```text
流程步骤（Plugin.Database）
  Query / Execute / WriteRow
        │  只引用 Core.Interfaces
        ▼
IDatabaseAccess（Core.Interfaces，默认 NullDatabaseAccess）
  TryTest / TryQuery / TryExecute / TryExecuteBatch
  参数化 DTO；不暴露 DbConnection / DbTransaction / DbDataReader
        │  宿主实现
        ▼
Services\Core.Database（宿主单例）
  DbProviderFactory / 一个 Provider / Provider 自带连接池
  profile 存储 / DPAPI 或 Windows 集成认证
  超时 + CancellationToken / 错误分类 / 事务 / 健康 / 审计日志
        │
        ▼
数据库（SQL Server / MySQL / PostgreSQL）
```

配置面：

```text
硬件管理 → 数据库页（IEmbeddedDialogPage + IHardwareEditGateAware）
  连接 profile：Provider / 连接串 / 超时 / 只读 / 凭据
  命名语句：语句名 + SQL + 参数定义
  .vms 只存：profile 名 + 语句名 + 参数值（不存密码/连接串）
```

注入四处（漏一处试运行会报“没有接入数据库”）：
`FlowEngineService`、`PluginConfigShellViewModel`、`PluginTestRunner`、`ExecutionContext`。

## 五、第一版范围

### 做

1. `Core.Interfaces`：`IDatabaseAccess` + DTO + `NullDatabaseAccess`。
2. `Services\Core.Database`：一个 Provider、Provider 自带 Pooling、profile、DPAPI/集成认证、超时/取消、错误分类、事务、健康、日志。
3. `Plugins\Plugin.Database`：
   - `Query`：`Scalar` / `RowsJson` / `RowCount` / `Columns` / `ElapsedMs`；
   - `Execute`：`AffectedRows` / `ElapsedMs`；
   - `WriteRow`：语句名 + 类型化参数表；单行或一次批量参数集。
4. 硬件管理“数据库”页：连接增删改、测试、只读开关、凭据录入、命名语句编辑。
5. `DatabaseModule`：单例注册 + 退出任务 + 四处能力注入。
6. `DatabaseChecks`：假 `IDatabaseAccess` 测插件；假 Provider 测事务/超时/错误分类；SQLite 测参数/事务管道；真实 Provider 用 env-gated。
7. `run_gates.ps1` 登记；`pack.ps1` 增加 Provider/native/Modules 归属检查。

### 不做

- `CommunicationType.Database`、`DatabaseConnection`、`DatabaseAddress`、数据库变量轮询。
- 跨步骤长事务、游标/多结果集、DDL/BulkCopy、存储过程输出参数、动态表名/列名。
- 写自动重试/spool、静态 `DatabaseWriteHub`、后台攒批线程。
- 插件私有 Provider、HSL `SoftSqlOperate`（net48 + `System.Data.SqlClient`，未接入）。
- 内联 SQL 进 `.vms`、SQL 高亮、多 Provider 同发。
- 承诺“读配方能改所有插件阈值”（多数阈值是 `[StepConfig]`，不可连线）。

## 六、契约草案

```csharp
public interface IDatabaseAccess
{
    IReadOnlyList<DbProfileInfo> ListProfiles();

    bool TryTest(string profileName, out DbProfileInfo info, out string? error);

    bool TryQuery(
        string profileName, string statementName,
        IReadOnlyList<DbParameterValue> parameters,
        DbCommandOptions options,
        out DbQueryResult result, out string? error);

    bool TryExecute(
        string profileName, string statementName,
        IReadOnlyList<DbParameterValue> parameters,
        DbCommandOptions options,
        out DbExecutionResult result, out string? error);

    bool TryExecuteBatch(
        string profileName, string statementName,
        IReadOnlyList<IReadOnlyList<DbParameterValue>> rows,
        DbBatchOptions options,
        out DbBatchResult result, out string? error);
}
```

DTO 要点：

- `DbParameterValue { Name, DbType, Value }`；
- `DbCommandOptions { TimeoutSeconds, MaxRows, CancellationToken }`；
- `DbQueryResult { Columns, Rows, RowCount, Truncated, ElapsedMs }`；
- `DbExecutionResult { AffectedRows, ElapsedMs }`；
- `DbBatchResult { SucceededRows, FailedRowIndex?, ElapsedMs }`；
- `DbErrorKind { Transient, Deadlock, Timeout, Constraint, Syntax, Permission, Unknown }`。

**不暴露** `DbConnection`/`DbTransaction`/`DbDataReader`；连接/事务由宿主释放；一次调用 = 一个事务。

## 七、必须定死的硬闸

| # | 硬闸 | 判据 |
| --- | --- | --- |
| 1 | 凭据/语句边界 | `.vms` 只存 profile/语句名/CredentialId；密码在宿主 DPAPI 或环境变量；日志/spool 无密码/参数值；profile 与 SQL 编辑仅管理员 |
| 2 | 参数化 | 只允许语句名 + 类型化参数表；插件源码静态扫描 `SqlCommand/DbCommand` 与 SQL 字符串拼接；无 format 入口 |
| 3 | 事务所有权 | 连接/事务由宿主释放；一次调用=一个事务；不暴露连接/事务/reader；禁止跨步骤环境事务 |
| 4 | 资源上限 | 每次调用必须有 timeout、CancellationToken、maxRows/maxAffectedRows；无上限查询直接拒绝 |
| 5 | 失败语义 | 写默认 `FailFast=true`（抛→Faulted），读默认步骤 Failed；禁止静默成功；Transient/Deadlock/Timeout 可重试，其余不重试 |
| 6 | 幂等/重试 | 至少一次；不自动重试非幂等语句；幂等键由业务提供；批量一事务全有全无 |
| 7 | 并发/部署 | 服务线程安全、per-call 连接；`[ParallelSafe]` 仅在无共享可变状态时标；Provider 只在宿主，`Modules` 无 Provider/契约拷贝 |
| 8 | 审计 | 记 profile、语句名、行数、耗时、错误类别、操作者；不记密码/参数值；日志硬闸 v1 必须有 |

## 八、为什么不是纯插件 / 不是通信协议

### 不是纯插件（A）

- 插件工程只投递自身 DLL（`Plugins\Directory.Build.targets` 的 `CopyPluginToModules`），私有 Provider/原生库要各插件自己 `Exec copy`；仓库无统一 `AssemblyResolve`，缺依赖在首次使用才炸。
- 插件实例是“每次编译 new 一份、会话 Dispose 释放”（`Engine\FlowCompiler.cs:847`、`Core\Models\FlowSession.cs:394-407`），扫描期实例不 Dispose（`Engine\PluginService.cs:324`），`Initialize()` 从未被调用（`Shard\Core.Interfaces\VisionPluginBase.cs:215`）。连接/事务放插件实例不稳。
- 连接串会随 `[StepConfig]` 进 `.vms` 明文（`Core\Models\ProcessStep\StepModel.cs:355`、`Core\SolutionService.cs:25-31`），与 `ResultUpload.SignSecret` 同风险。

### 不是通信协议（B）

- `ICommunicationConnection.Read<T>` 限定 `where T : struct`，另有 `ReadBytes/ReadBits`（`Core\CommunicationContracts\ICommunicationConnection.cs:31-43`）；结果集/多行/事务/参数没有表达。
- `PollBatchPlanner` 必须按 `AddressConfig` 解析段并 `ReadBytes`（`PollBatchPlanner.cs:271-299`）；SQL 塞进 Address 就是字符串拼 SQL。
- `NetworkVariableModel.Value` setter 直接写设备（`NetworkVariableModel.cs:294-303`），只读区只认 Modbus/S7；数据库列映射/主键/WHERE 没有位置。
- `ConnectionWorker` 四车道插队会在 WorkItem 之间插入（`ConnectionWorker.cs:640-660`）；若 BEGIN/COMMIT 拆成多个步骤，别的写会插进事务中间。

### 与现有数据出口的分工

| 出口 | 职责 | 不改 |
| --- | --- | --- |
| DataRecord | 本地 CSV 账本（append-only） | 不改 |
| ExcelExport | 人看报表 | 不改 |
| ResultUpload | HTTP/MES 上报（spool/幂等） | 不改 |
| **Plugin.Database** | 中央库结果行、查询/配方/工单、事务 | 新增 |

## 十二、风险与未验证项

1. **Provider 包可获取性/许可/传递闭包未验证**：`Microsoft.Data.SqlClient` 带 SNI/native；`MySqlConnector` 纯托管最轻；需出第三方声明。
2. **DPAPI 是净新增**：全仓无 `ProtectedData|DPAPI|DataProtection`；需 0.5~1 天 spike 验证包可用性。
3. **SQLite 不证明真实方言**：只证明参数/事务管道；真实 SQL Server/MySQL 需 env-gated 集成测试。
4. **“读配方能改所有阈值”是伪需求**：多数阈值是 `[StepConfig]`，不可连线；v1 只承诺写全局变量/端口。
5. **批量失败归因**：一批回滚后 Provider 通常不告诉第几行；需要逐行校验/幂等键/死信队列（v1.5）。
6. **审计接入**：`AuditLogger` 通用但全仓无调用点；v1 先保证日志硬闸，审计 sink 可 P1。
7. **未构建、未跑 gate**：本文所有代码结论来自只读阅读，不是运行结果。

## 十三、下一步建议

1. **先做 0.5~1 天 spike**：在一个临时工程里验证目标 Provider 的 NuGet 还原、native 资产、DPAPI 可用性。
2. **用户拍板 6 条**（尤其是数据库厂商、MES 是否允许直连、凭据方案）。
3. 按第一版范围实施：`Core.Interfaces` → `Core.Database` → `Plugin.Database` → 硬件页 → 断言 → 帮助/打包。
4. 若首版只想“每件结果落库”，可先走 D：给 `DataRecord`/`ResultUpload` 加 DB sink；有查询/配方/工单/事务需求再升级到 C。
