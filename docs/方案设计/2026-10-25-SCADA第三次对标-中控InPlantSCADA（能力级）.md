## 二、我们现在的家底（源码事实）

- **图元 46 个 TypeKey**：内置 45（`Scada.Controls\Descriptors\BuiltInElements.cs`）+ 曲线 1（`Hmi.ChartTrend`，独立程序集）。
- **动作 27 条**：日志 / 写变量 / 跳页 / 返回 / 开弹窗 / 关弹窗 / 启停流程 / 跑一次 / 暂停 / 继续 / 运动九条 / 增量 / 减量 / 应用配方 / 置位 / 复位 / 取反 / 播放声音。
- **事件 13 条**：加载 / 卸载 / 按下 / 释放 / 值改变 / 变真 / 变假 / 超上限 / 低下限 / 输入完成 / 对象改变 / 打开 / 关闭。
- **动画 7 种**：外观 / 启用对象 / 水平移动 / 垂直移动 / 可见性 / 对角线移动 / 比例移动。
- **运行形态**：桌面全屏运行窗口（自动适配、中键平移、滚轮不缩放、底条一键适配）+ Web 只读运行态（9 个渲染器缺口，`[WR]` 例外清单在案）。
- **数据面**：报警引擎（激活/变化/恢复三事件、落盘 JSON、历史抽屉）+ 审计出口 `IScadaAuditSink`（操作者/会话/IP/对象/动作/结果/明细）+ 历史数据源（DataGrid `Source=History`）+ 实时趋势（4 曲线）+ 配方面板（只读）+ `ApplyRecipe`（预检/回滚/审计）。
- **画面结构**：底板（一层容器）、嵌入画面（画中画，支持跟变量切页与交互子页）、状态图元（文本列表驱动）、位表/IO 监视/变量监视。

## 四、对比结论：差的不是"图元数量"，是四类系统能力

### 4.1 能力级差距（有据）

| 能力 | 中控 | 我们 | 差距性质 |
| --- | --- | --- | --- |
| 报表（班次/日汇总、打印、Web 报表） | 有完整报表引擎 + 独立手册 | 只有 DataGrid（最近 N 行缓冲）与 CSV 记录插件 | **真缺**，且是现场验收项 |
| SPC / OEE | 两个独立插件 + 手册 | 无 | 属分析平台，**不建议做进画面模型** |
| 电子签名（签名含义 + 复核） | 有插件 | 有审计出口，无签名流程 | 合规客户才需要 |
| 3D 组态 | 有 3D-Editor | 无 | 不在同一产品形态，**不做** |
| 视频监控接入 | 有 Smart Video 插件 | 宿主有相机采集，画面里无视频图元 | **可选**，做一路预览即可 |
| 移动端 | APP 插件 | Web 只读运行态 | 移动端不做；Web 补齐 9 个渲染器即可 |
| 脚本二次开发 | VBS + 系统函数库 | 流程侧有 CSharpScript 插件；画面侧无脚本 | **可接受**：画面脚本会破坏"画面模型可静态校验"，建议继续用"事件 → 跑流程" |
| 时间/事件计划表 | 有 | 无 | **真缺**（班次动作、定时联锁） |
| 数据库归档 | 直连 MySQL/SQL Server/Oracle 建表绑点 | 有历史源接口 + 数据库通讯模块 | 能力已有，接线方式不同 |
| 审计追踪 | 有（电子签名前提） | 有 `IScadaAuditSink`（操作者/会话/IP/动作/结果/明细） | **基本对齐** |
| 配方上传/下载 | 有 | 有只读面板 + 应用（预检/回滚/审计），无保存/上传 | **真缺**（对标评审 P2 也记着） |

### 4.2 图元级：工艺符号库（推断，需用他们的素材库确认）

DCS 系 SCADA 的流程图组态标配一套**工艺设备符号**；我们现在只有 5 个工艺图元（阀门 / 泵 / 电机 / 管道 / 罐体）。按行业惯例，缺的是：

- **设备**：换热器（管壳/板式）、精馏塔/填料塔、反应釜（带搅拌）、压缩机、风机、过滤器、分离器、储罐（立式/卧式/球罐）、燃烧器、烟囱、传送带/皮带机。
- **阀门细分**：闸阀、球阀、蝶阀、调节阀（带执行机构）、安全阀、止回阀、三通阀。
- **管道连接件**：三通/四通、法兰、盲板、异径管、流向箭头、管道断点。
- **仪表**：变送器、流量计、液位计、就地压力表、控制回路（PID）标记框。

**实现建议（重要）**：不要做成 30 个 TypeKey——工具箱会爆、属性面板 30 份近义属性、Web 渲染器 30 个缺口。建议**一个 `Hmi.Symbol` 图元 + `SymbolKind` 枚举 + 一张几何表**（枚举上屏走 `StepConfigOption.ForEnum`，R40），属性只有"符号种类 / 线宽 / 主色 / 填充 / 是否显示位号"，位号复用 `Text`。

### 4.3 我们比中控强的部分（不要为了对标丢掉）

- 与视觉检测流程引擎同屏：`StartFlow` / `RunFlowOnce` / 轴控台 / 图像显示 / 结果图元，中控没有这一层。
- 画面模型强类型 + 源生成器：每个图元的属性都有 `TargetProperty` 与注册期校验，中控那套是脚本驱动，静态可查性差。
- 运行态取景与操作纪律（滚轮不缩放、权限先判、写路径唯一）已成型。

## 五、建议的下一步（按对本项目的价值排序）

1. **报表对象**（P1，工作量 M）：新增 `Hmi.Report`——表头/列定义/数据源（历史源或变量快照）/汇总行（班次/日/月）+ 导出 CSV/Excel + 打印。这是现场验收最常问的一项，也是我们目前唯一"完全没有"的类别。
2. **工艺符号库**（P1，工作量 M）：按 4.2 的单 TypeKey + 枚举方案做 20~30 个符号，先覆盖换热器/塔/反应釜/压缩机/风机/过滤器/阀门细分/管道连接件。
3. **历史趋势回放**（P2，S/M）：MultiTrend 现在只有实时滚动；补时间范围、游标读数、导出。
4. **时间/事件计划表**（P2，M）：画面侧"到点做什么"，与动作表复用同一个执行器。
5. **配方保存/上传**（P2，M）：把只读面板补成可编辑 + 下发/回读，复用 `IRecipeCommandSink` 的预检/回滚。
6. **视频监控图元**（P3，S）：宿主已有相机采集，画面里嵌一路预览即可，不做多路矩阵。
7. **Web 渲染器 9 项**（P2，M）：与上面任何一项并行，`[WR]` 例外清单必须清零。
8. **不做**：3D 组态、SPC、OEE、移动端 APP、画面内 VBS 脚本。
