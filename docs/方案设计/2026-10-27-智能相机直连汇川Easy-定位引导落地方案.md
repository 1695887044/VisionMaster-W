## 一、方案边界与结论

**能做到的**：标定、示教、运行全部在 PLC 内完成，全程不需要 PC。
相机发整像素（+角度），PLC 解析、换算、输出偏差量给轴/机器人。

**代价（必须写进交接）**：
1. **只能仿射**。相机必须装正、镜头畸变小。相机歪着装或畸变大时，仿射吸收不了，
   表现为残差偏大——这时要么改安装/换镜头，要么叫工程师带电脑来一次（10.2）。
2. 标定质量诊断比上位机弱：只有 RMS 与各向异性，没有径向带诊断、没有退化原因细分。
3. **PLC 内做不了透视拟合**：需要 9×9 对称矩阵的 Jacobi 特征分解 + 双侧 Hartley 归一化，
   约 200 行 SCL，写错了没有第二份实现可对照。明确不做。

**关键前提**：标定点的机械坐标可以直接从 PLC 自己的轴位置读。
这是"无上位机也能标定"成立的支点——见 4.1。

## 二、三条路，按推荐排序

| # | 做法 | 前提 | 评价 |
|---|---|---|---|
| 1 | **让智能相机自己输出 mm** | 相机内置标定/坐标转换工具 | **最省事、精度最好**。PLC 只做偏差加法。**先查相机手册，别跳过这一条** |
| 2 | **PLC 内九点仿射标定** | 相机只能出像素 | **本方案采用**。全自主，客户可自己重标 |
| 3 | 上位机标定一次 + 手工填系数 | 现场能借到电脑 | 次选。9 个浮点手工录入 + 自检兜底，但客户不能自己重标 |

第 1 条值得花十分钟确认：绝大多数工业智能相机（基恩士 / 康耐视 / 海康机器人 / 奥普特）
都有九点标定或"标定 + 位置修正"工具，能直接输出毫米坐标。如果有，**整个像素换算问题消失**，
本方案第 4~7 节全部作废，PLC 只留"读 mm → 算偏差 → 加示教位姿"。

## 四、标定（PLC 内完成，HMI 引导）

### 4.1 为什么机械坐标可以自动获得（这是方案成立的关键）

标定的做法是**让轴/机器人带着标记物走 N 个位置**，每个位置：
- 机械坐标 = **PLC 自己的轴当前位置**（现成反馈，不用人填）；
- 像素坐标 = **相机对该标记物的整数输出**（现成，不用人填）。

于是标定过程**零人工录入**——这比"上位机标定后手工把 9 个数敲进 PLC"可靠一个量级，
因为人工录入恰恰是最容易错、最难查的一环。

标记物不必在 TCP 上：它与真实夹爪之间的一切**常数**偏移都会被仿射的平移项吸收，
而运行期用偏差量（第五节）又把这层常数偏差再抵消一次。

### 4.2 采集流程（HMI 引导，N = 9）

```
FOR i := 1 TO 9 DO
   HMI 提示「把标记物移到第 i 个位置」           // 3×3 覆盖视野四角+中心
   操作工点动到位后按「记录」
   ├─ PLC 触发相机
   ├─ 读 (Row_i, Col_i)；Status.OK 必须为真，否则重来
   └─ 读当前轴位置 (X_i, Y_i)   // 0.1mm 单位，PLC 自己的坐标
   存入数组
END_FOR
按「计算」→ 4.3 求解 → 4.4 验收 → 通过才写入系数区
```

**N 取 9（3×3）就够**：仿射 6 个未知数，9 点有 3 个残差自由度。
轴能方便走到 4×4 的话取 16 更好（参数估计更稳），代码只需把数组开大。

**采集的三条纪律**：
1. **轴必须停稳再记录**。运动中读轴位置与相机像素不同步，会得到系统性错点。
   判据：连续两次读轴位置差值 < 1 个单位。
2. **每次记录都要 Status.OK**。NG 时相机可能输出 `(0,0)`，那是合法像素，混进去会毁掉整次标定。
3. **允许「重录第 i 点」**。现场标定经常有个点手滑，不能要求从头来。

### 4.3 求解：归一化 + 3×3 克莱姆（照抄上位机口径）

**归一化不是可选优化，是必须做的**。直接对 `Row≈几千` 的法方程求解，条件数很差
（量纲跨度大且原点远离点集中心），REAL 只有 7 位有效数字，不归一化会算出一个"看起来正常"的错矩阵。
上位机 `CalibrationMath.TrySolveAffine` 做的就是这件事，PLC 逐行照抄即可。

```pascal
// ===== 输入：N、PtR[]/PtC[]（DINT 整像素）、PtX[]/PtY[]（REAL，0.1mm）=====
// ===== 输出：a11..a32、RmsPx、MaxPx、MmPerPx、Aniso、ErrCode =====
ErrCode := 0;
IF N < 3 THEN ErrCode := 1; RETURN; END_IF;

// ---- 1. 质心与尺度 ----
cr := 0; cc := 0;
FOR i := 0 TO N-1 DO
    cr := cr + DINT_TO_REAL(PtR[i]);
    cc := cc + DINT_TO_REAL(PtC[i]);
END_FOR;
cr := cr / INT_TO_REAL(N);  cc := cc / INT_TO_REAL(N);

scale := 0;
FOR i := 0 TO N-1 DO
    d := SQRT( SQR(DINT_TO_REAL(PtR[i]) - cr) + SQR(DINT_TO_REAL(PtC[i]) - cc) );
    IF d > scale THEN scale := d; END_IF;
END_FOR;
IF scale < 1.0 THEN ErrCode := 2; RETURN; END_IF;    // 点全重合

// ---- 2. 归一化累加（u,v 落在单位圆内）----
Suu:=0; Suv:=0; Svv:=0; Su:=0; Sv:=0;
Sux:=0; Svx:=0; Sx:=0; Suy:=0; Svy:=0; Sy:=0;
FOR i := 0 TO N-1 DO
    u := (DINT_TO_REAL(PtR[i]) - cr) / scale;
    v := (DINT_TO_REAL(PtC[i]) - cc) / scale;
    Suu := Suu + u*u;   Suv := Suv + u*v;   Svv := Svv + v*v;
    Su  := Su  + u;     Sv  := Sv  + v;
    Sux := Sux + u*PtX[i];  Svx := Svx + v*PtX[i];  Sx := Sx + PtX[i];
    Suy := Suy + u*PtY[i];  Svy := Svy + v*PtY[i];  Sy := Sy + PtY[i];
END_FOR;

// ---- 3. 3×3 对称正规方程 ----
m00:=Suu; m01:=Suv; m02:=Su;  m11:=Svv; m12:=Sv;  m22:=INT_TO_REAL(N);

det   := m00*(m11*m22 - m12*m12) - m01*(m01*m22 - m12*m02) + m02*(m01*m12 - m11*m02);
trace := m00 + m11 + m22;
// 共线判据：与上位机同一口径（无量纲，REAL 下同样成立）
IF det <= 1.0E-4 * trace*trace*trace THEN ErrCode := 3; RETURN; END_IF;

// 伴随矩阵（对称矩阵的伴随仍对称）
c00 := m11*m22 - m12*m12;
c01 := -(m01*m22 - m12*m02);
c02 := m01*m12 - m11*m02;
c11 := m00*m22 - m02*m02;
c12 := -(m00*m12 - m01*m02);
c22 := m00*m11 - m01*m01;

a1 := (c00*Sux + c01*Svx + c02*Sx) / det;
b1 := (c01*Sux + c11*Svx + c12*Sx) / det;
c1 := (c02*Sux + c12*Svx + c22*Sx) / det;
a2 := (c00*Suy + c01*Svy + c02*Sy) / det;
b2 := (c01*Suy + c11*Svy + c12*Sy) / det;
c2 := (c02*Suy + c12*Svy + c22*Sy) / det;

// ---- 4. 还原到原坐标 ----
a11 := a1 / scale;
a12 := b1 / scale;
a21 := a2 / scale;
a22 := b2 / scale;
a31 := c1 - a1*cr/scale - b1*cc/scale;
a32 := c2 - a2*cr/scale - b2*cc/scale;

// ---- 5. 当量、各向异性、残差 ----
lenRow := SQRT(a11*a11 + a21*a21);      // 沿 Row 走 1px 是多少 0.1mm
lenCol := SQRT(a12*a12 + a22*a22);
MmPerPx := (lenRow + lenCol) / 2.0;
IF MmPerPx <= 0.0 THEN ErrCode := 4; RETURN; END_IF;
Aniso := ABS(lenRow - lenCol) / MmPerPx * 100.0;

sumSq := 0;  maxD := 0;
FOR i := 0 TO N-1 DO
    r := DINT_TO_REAL(PtR[i]);  c := DINT_TO_REAL(PtC[i]);
    ex := a11*r + a12*c + a31;
    ey := a21*r + a22*c + a32;
    d  := SQRT( SQR(ex - PtX[i]) + SQR(ey - PtY[i]) ) / MmPerPx;   // 换算成 px
    sumSq := sumSq + d*d;
    IF d > maxD THEN maxD := d; END_IF;
END_FOR;
RmsPx := SQRT(sumSq / INT_TO_REAL(N));
MaxPx := maxD;
```

**注意 `MmPerPx` 的单位是 0.1mm/px**（因为机械坐标用的是 PLC 的 0.1mm 单位）。
这带来一个好处：**全程只有一种单位，没有任何换算步骤**——v1 里那个 `UnitScale = 10` 可以删掉。
代价是系数与上位机/HALCON 不可逐位比对，但本方案没有上位机参与，这个代价不存在。

### 4.4 验收判据

| 指标 | 通过 | 不通过说明 |
|---|---|---|
| `RmsPx` | **≤ 0.6 px** | 9 点 + 整像素的期望值约 0.33px（0.41×√(1−6/18)）。>0.6 说明模型不够：相机装歪 / 镜头畸大 / 有点取错 / 轴没停稳 |
| `MaxPx` | ≤ 1.5 px | 单点离谱 = 那个点手滑，重录它 |
| `Aniso` | < 5% | 略大是正常的（非方像素）；>5% 且 `RmsPx` 也大，查相机是否被非等比缩放 |
| `MmPerPx` | 与"视野宽 ÷ 像素数"相符 | 明显不符 = 轴位置读错单位、或相机做了降采样 |
| `det` 判据 | 通过 | 点近似共线（别把 9 个点摆成一条线） |

**`RmsPx > 0.6` 的处理顺序**（不要一上来就怀疑算法）：
1. 查轴是否停稳（4.2-1）；
2. 查是否有 NG 点混入（4.2-2）；
3. 重录最离谱的那个点；
4. 仍然大 → 相机装歪或畸变大，仿射救不了，走 10.2。

### 4.5 求解器自检（**没有上位机时，这一步是唯一的质量证据**）

在 PLC 里做一个「求解器自检」按钮：**用已知系数造一组无噪声的合成点，跑一遍求解，比对还原结果**。
不需要相机、不需要轴、不需要动设备，几秒钟出结果。

```pascal
// 造点：取 a11=2.0 a12=0.1 a21=-0.1 a22=2.0 a31=-500 a32=-300（0.1mm 单位）
FOR i := 0 TO 8 DO
    PtR[i] := 100 + (i MOD 3) * 800;
    PtC[i] := 100 + (i / 3) * 800;
    PtX[i] := 2.0*PtR[i] + 0.1*PtC[i] - 500.0;
    PtY[i] := -0.1*PtR[i] + 2.0*PtC[i] - 300.0;
END_FOR;
Solve();          // 与正式标定同一段代码

SolveTestOk := TRUE;
IF ABS(a11 - 2.0)   > 0.01 THEN SolveTestOk := FALSE; END_IF;
IF ABS(a12 - 0.1)   > 0.01 THEN SolveTestOk := FALSE; END_IF;
IF ABS(a21 + 0.1)   > 0.01 THEN SolveTestOk := FALSE; END_IF;
IF ABS(a22 - 2.0)   > 0.01 THEN SolveTestOk := FALSE; END_IF;
IF ABS(a31 + 500.0) > 0.5  THEN SolveTestOk := FALSE; END_IF;
IF ABS(a32 + 300.0) > 0.5  THEN SolveTestOk := FALSE; END_IF;
IF RmsPx > 0.001 THEN SolveTestOk := FALSE; END_IF;   // 无噪声数据必须完美拟合
```

**两项都要查**：系数还原验证「反归一化公式」（`a31 = c1 − a1·cr/scale − …` 这段最容易抄错），
`RmsPx ≈ 0` 验证「求解闭合」。只查残差会被同一处 bug 两边抵消骗过去。

自检不通过就**禁止保存标定结果**，HMI 直接报「求解器异常」。

## 五、示教（换型时）

标准件放标准位置，记录：

| 记录项 | 来源 | 说明 |
|---|---|---|
| `R0, C0` | 相机输出 | 参考像素（整数） |
| `θ0` | 相机输出 | 参考角度（0.01° 单位存 INT32） |
| `X0, Y0` | 轴/机器人示教器 | 参考机械位姿（0.1mm 单位） |
| `θr0` | 轴/机器人示教器 | 参考转角 |

**运行期不做**：`Xm0 = a11·R0 + a12·C0 + a31`、`Ym0 = a21·R0 + a22·C0 + a32` 在 PLC 里两行算完，
不需要上位机预先算好。

## 六、运行期：寄存器表与时序

### 6.1 相机侧寄存器（PLC 读取，地址以相机手册为准）

| 偏移 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 0 | `Seq` | UINT16 | 每次检测完成 +1（自然回绕）。PLC 靠它判断"是不是新结果" |
| 1 | `Status` | UINT16 | bit0=OK(找到) bit1=NG(未找到) bit2=Busy bit3=参数就绪 |
| 2-3 | `Row` | INT32 | 整像素 |
| 4-5 | `Col` | INT32 | 整像素 |
| 6-7 | `Angle` | INT32 | 0.01°（1234 = 12.34°）；不做纠偏可省略 |
| 8 | `TrigAck` | UINT16 | 相机已接收触发 |

PLC → 相机：写 `Trigger`（地址按相机手册），或走硬线 I/O。

**INT32 字序必须实测**：让相机输出 `Row = 1000`，看 PLC 读到的是 `(0,1000)` 还是 `(1000,0)`。
Modbus 惯例高字在前，但设备实现两极分化。**这与字节序一样是"接真设备必炸"的经典位置**
（仓库前科：`docs\code-changes\2026-09-15-Modbus字节序颠倒修复.md`）。

### 6.2 时序

```
PLC                                  相机
 │ 工件到位                            │
 ├── 写 Trigger=1 ───────────────────►│
 │                                    │ 采集 + 检测
 │                                    ├─ 写 Row/Col/Angle
 │                                    ├─ Status := OK/NG
 │                                    ├─ Seq := Seq+1
 │◄── 每 10ms 读 (Seq,Status,Row,Col,Angle) ─┤
 │ Seq 变了 且 Status.OK=1             │
 ├─ 锁存 → 换算 → 输出 Δ + Valid        │
 │ 写 Trigger=0                        │
 │ 200ms 内没等到新 Seq → 报警，不动作   │
```

**三条纪律**：
1. **一次触发只消费一次**（`LastConsumedSeq` 存断电保持区）。
2. **超时必须报警**。超时后沿用上一次坐标 = "同一个零件被抓两次"的经典事故。
3. **整块读**。一个 Modbus 请求读连续 9 个寄存器，避免读到"新的 Row + 旧的 Col"。

## 七、运行期：换算（仿射 + 角度 + 偏差量）

```pascal
r := DINT_TO_REAL(Row);
c := DINT_TO_REAL(Col);

// ---- 位置（0.1mm 单位，全程无换算）----
Xm := a11*r + a12*c + a31;
Ym := a21*r + a22*c + a32;

Xm0 := a11*R0f + a12*C0f + a31;      // R0f/C0f 是示教时存的 REAL 化参考像素
Ym0 := a21*R0f + a22*C0f + a32;

dX := Xm - Xm0;
dY := Ym - Ym0;

// ---- 角度（仿射：与位置无关，两次 ATAN2 即可）----
sinT  := SIN(Theta);        cosT  := COS(Theta);
sinT0 := SIN(Theta0);       cosT0 := COS(Theta0);

dx  := a21*sinT  + a22*cosT;      dy  := a11*sinT  + a12*cosT;
dx0 := a21*sinT0 + a22*cosT0;     dy0 := a11*sinT0 + a12*cosT0;

dTheta := ATAN2(dy, dx) - ATAN2(dy0, dx0);   // 基准 φ0 在相减时抵消，不用单独存
dTheta := 归一化到 (-180, 180]
```

> 注意这里 `dy` 用 `a11·sinθ + a12·cosθ`、`dx` 用 `a21·sinθ + a22·cosθ`——
> 与 `PoseTransformMath.cs:466-475` 的写法逐字对应（`dx` 是机械 X 分量、`dy` 是机械 Y 分量，
> 不要按变量名想当然）。镜像标定（`det<0`）会让转角自然取反，这是矩阵的正确结果，不要再"校正一次"。

**输出给运动**：目标位姿 = `(X0 + dX, Y0 + dY, θr0 + dTheta)`。
若机器人转角正方向与机械系相反，`dTheta` 取反——**由验收第 6 步确定，不要猜**。

## 八、故障位与兜底

| FaultCode | 含义 | 动作 |
|---|---|---|
| 0 | OK | 输出 Δ + Valid |
| 1 | 相机 NG / 无有效位 | 不动作，报警 |
| 2 | 像素越界（<0 或 ≥ ImgW/H） | 不动作，报警 |
| 3 | 偏差超包络（`|dX|`/`|dY|` > 上限） | 不动作，报警 |
| 4 | 通信超时（200ms 无新 Seq） | 不动作，报警 |
| 5 | 未标定 / 标定无效 | 禁止动作 |
| 6 | 求解器自检失败 | 禁止保存标定 |

**Δ 包络是这套方案最有效的运行期闸**：轴位置读错单位、系数被写坏、用错工位的标定，
全都会让 Δ 冲出包络立刻报警。建议设成 **1.2 × 半个视野**。

**相机没有 OK 位时**：整像素下检测失败常输出 `(0,0)`，而 `(0,0)` 是合法像素，像素窗口兜不住。
这种情况只能加"连续 N 次坐标完全相同就报警"的弱兜底——**但那只是猜测，不能替代 valid 位**。
建议把"相机必须有 OK/NG 输出"列为选型硬要求。

## 九、验收步骤（按顺序，每步有判据）

| # | 步骤 | 判据 |
|---|---|---|
| 1 | 求解器自检（4.5） | 6 个系数全部还原、`RmsPx < 0.001`。**先做这个，它不依赖任何硬件** |
| 2 | 通信连通 | Seq 随触发递增，Status 正确翻转 |
| 3 | **INT32 字序** | 相机显示 1000，PLC 读到的也是 1000 |
| 4 | 九点标定 | `RmsPx ≤ 0.6px`、`MaxPx ≤ 1.5px`、`MmPerPx` 与视野相符 |
| 5 | 回到第 5 点复测 | 用标定结果算出的 (X,Y) 与该点实际轴位置偏差 ≤ 0.1mm |
| 6 | **平移验证** | 标准件沿机械 X 移 10mm → `dX ≈ 100` 单位、`dY ≈ 0` |
| 7 | **角度方向验证** | 标准件转 +10° → `dTheta = +10°`（或 −10°，与机器人转角正方向一致）；不转时 `dTheta ≈ 0` |
| 8 | NG 路径 | 拿走零件 → 相机 NG → PLC 不动作并报警；**不能沿用上一次坐标** |
| 9 | 超时路径 | 拔网线/串口 → 200ms 内报警 |
| 10 | 重复性 | 同一零件连续测 30 次，`dX/dY/dTheta` 极差 ≤ 精度目标 |

第 6、7 步是**唯一可靠的约定验证**。角度零点/正方向错了，X/Y 完全正常，只有这两步能抓出来。

## 十、风险与边界

### 10.1 风险表

| 风险 | 后果 | 兜底 |
|---|---|---|
| 相机装歪 / 畸变大 | 仿射拟合不了，`RmsPx` 大 | 4.4 的处理顺序；实在不行走 10.2 |
| 相机没有 OK 位 | `(0,0)` 被当合法坐标 | 选型硬要求；弱兜底见第八节 |
| 相机角度约定与公式不同 | X/Y 对、角度偏 90° 或取反 | 验收第 7 步 |
| Easy 无四象限 `ATAN2` | 角度在 ±90° 附近翻 180° | 手写象限修正 + 单测 8 个方向 |
| 标定数据被覆盖 / 程序被改 | 静默错位 | 标定结果存断电保持区 + HMI 显示标定日期与 `RmsPx` + Δ 包络 |
| 轴位置单位与想象不符 | 整体偏 10 倍 | `MmPerPx` 与"视野÷像素数"比对（4.4）+ Δ 包络 |
| 通信丢帧 | 用旧坐标 | Seq 去重 + 超时报警 |

### 10.2 仿射不够时的救援路径（保留 v1）

如果 `RmsPx` 反复 > 0.6px，且确认不是取点/停稳/NG 的问题，说明相机倾斜或镜头畸变超出仿射能力。
这时**借一台电脑**，用上位机做一次透视或网格标定，导出系数后手工填进 PLC，
再用 4.5 的合成自检 + 第九节的 5~10 步验证。

这条路径的代价：客户以后不能自己重标，必须叫工程师。所以只在确实必要时才用，
并且要在交接文件里写明"本机标定依赖上位机一次性完成"。

## 十四、相机型号确认后的影响（华睿 R4013MG-07M-RGG01）

数据来源：厂商单页 PDF（`R4013MG_07M_RGG01_单页_2026-10-25`），页面渲染存
`artifacts\render\20261027\camera_spec\`。

### 14.1 最重要的发现：这是**智能读码器**，不是通用视觉相机

功能列表逐条只有：集成光源、电动对焦、读码（一维/二维码）、码质量评价、深度学习读码、多码轮询。
**没有模板匹配、没有 Blob、没有边缘/测量工具。**

对"定位引导"的直接后果：**只能靠"码的位置"定位零件**——即码印在零件上的固定位置，
把码的中心与角度当作零件的位姿。这条路成立的前提是：

- 零件上确实有码，且码相对零件的印刷/贴装位置稳定；
- 只需要 2D 平面位姿（X, Y, θ），不需要 3D 或形变；
- 码本身足够大（决定定位精度，见 14.3）。

**如果原计划是"找零件轮廓/特征做定位"，这台相机做不到，需要换视觉相机（带匹配工具）。**
这一条必须先和工艺确认，它比精度和通信都关键——其余全部讨论都建立在"用码定位"这个前提上。

### 14.2 精度算账

关键参数：分辨率 **1280×1024**，视野 **116×92mm @ 工作距离 150mm**，7mm 焦距，M12 电动对焦。

当量 `p = 116 / 1280 = 0.0906 mm/px`（横向）、`92/1024 = 0.0898`（纵向），取 **p ≈ 0.09 mm/px**。

| 工作距离 | 视野（宽×高） | p (mm/px) | 整像素量化 ±0.5px | 对 0.1mm 公差 |
|---|---|---|---|---|
| 50 mm | 39×31 | 0.030 | ±0.015 mm | 很宽裕 |
| 100 mm | 77×62 | 0.060 | ±0.030 mm | 宽裕 |
| **150 mm** | **116×92** | **0.091** | **±0.045 mm** | **够，2 倍余量** |
| 180 mm | 139×111 | 0.109 | ±0.054 mm | 偏紧 |
| 250 mm | 193×154 | 0.151 | ±0.076 mm | 基本吃满 |
| 300 mm | 232×185 | 0.181 | ±0.091 mm | 超差 |

**判据**：`p ≤ 0.1 mm/px` 对应**工作距离 ≤ 165mm**（视野 ≤128×101mm）。
需要更大视野就得接受精度下降——这不是算法能补的。

**可用的杠杆**：这台相机 50~500mm 都能对焦，**装得越近精度越好**。
如果零件小，把工作距离压到 100mm 以内，量化误差直接降到 ±0.03mm。

### 14.3 三个额外的误差源（都不在上面的量化里）

1. **码中心定位误差**。读码器是从码的边界/finder pattern 反算中心，**码越小误差越大**。
   经验判据：码边长 ≥ 50px（0.09mm/px 下约 4.5mm）时中心定位通常在 ±0.5px 内；
   码小于 20px 时可能到 ±1~2px，直接把公差吃光。
   **验收第 11 步的"30 次重复性"就是量这一项**，不要跳过。
2. **输出单位取整**。若机械坐标单位是 0.1mm 且运动接口只收整数，取整本身 ±0.05mm。
   与量化（±0.045mm）叠加约 0.067mm（RMS）——勉强在 0.1mm 内，**没有余量**。
   如果轴的接口能收 0.01mm，建议直接用 0.01mm 做单位。
3. **自动对焦会改视野**。这台相机支持电动对焦/一键自动对焦。
   **标定前必须把焦距锁死，运行中禁止自动对焦**——焦距一变视野就变，整份标定立即失效，
   而且症状是"慢慢漂"，最难查。

### 14.4 通信：Modbus TCP 是唯一现实路径

相机支持的协议：SDK、TCP Client、TCP Server、FTP、RS232、**Profinet、Modbus、EtherNet/IP、
MC(SLMP)、FINS/UDP、FINS/TCP**。

与 Easy521 的交集：

| 相机协议 | Easy521 | 结论 |
|---|---|---|
| **Modbus**（需确认是 TCP 还是 RTU） | 待确认 | **唯一现实路径** |
| Profinet / EtherNet/IP | 小型机基本不支持主站 | 不可用 |
| MC(SLMP) / FINS | 三菱/欧姆龙专用协议 | 不可用 |
| RS232（相机侧） | Easy521 是 RS485 | 需 RS232↔RS485 转换器，走 Modbus RTU |
| TCP Client/Server（裸 socket） | 小型机一般不支持 | 不可用 |

**必须确认两件事**：① 相机的 "Modbus" 是 Modbus TCP 还是 Modbus RTU；
② Easy521 能否做 Modbus TCP **客户端**。两者只要有一边不成立，就退回
"RS232 + 转换器 + Modbus RTU"，速率降到 115200 下每帧几十 ms——1~2 Hz 够用，
但对这台相机标称的 60 个/s 完全用不上。

### 14.5 好消息：3 路隔离输出可以做硬件握手

GPIO 连接器（12 芯）实测定义：**2 路光耦隔离输入**（OPT_IN0/1）、**3 路光耦隔离输出**（OPT_OUT0/1/2）、
RS232 TXD/RXD、电源。

这直接解决了第八节"相机有没有 OK 位"的顾虑，而且**硬线比寄存器状态位可靠**：

| 方向 | 信号 | 用途 |
|---|---|---|
| PLC → 相机 | OPT_IN0 | 触发 |
| 相机 → PLC | OPT_OUT0 | 读码 OK |
| 相机 → PLC | OPT_OUT1 | 结果就绪（数据已写入寄存器） |
| 相机 → PLC | OPT_OUT2 | NG / 无码 |

建议：**坐标走 Modbus，有效位走硬线**。这样即使 Modbus 状态字不可靠，也不会拿旧坐标去动轴。

### 14.6 需要在 EasyID 里确认的五条

| # | 确认项 | 不确认的后果 |
|---|---|---|
| 1 | 输出字段里**有没有码中心坐标与角度** | 没有 → 整个方案不成立 |
| 2 | 坐标是**整像素还是带小数/可缩放** | 能 ×10 输出 → 精度放宽一档（14.2） |
| 3 | Modbus 是 **TCP 还是 RTU** | 决定通信路径（14.4） |
| 4 | 触发与结果的**握手时序**（软触发/硬触发、结果就绪） | 决定会不会读到半更新数据 |
| 5 | **自动对焦能否锁定/关闭** | 不锁 → 标定会慢慢漂（14.3-3） |

### 14.8 功能全清单（R4013MG-07M-RGG01）

**定性：这是一台「产线高速读码 / 追溯」设备，不是通用视觉相机。**
它的设计目标是"出结果不出图"——百兆以太网，1280×1024×8bit×60fps ≈ 78MB/s，
远超百兆带宽，所以图像流式输出本就受限，结果输出才是主路径。

#### ① 读码（唯一的"视觉功能"类）
