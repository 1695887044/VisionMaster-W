## 0. 先给审核人看的五条结论

1. **用户管理不是“没有”**。它有账号文件、PBKDF2 密码、三档角色、管理员专属弹窗；问题在于账号本挂在**软件目录**（`ScadaUserStore.cs:195`），且唯一可见入口在登录弹窗里（`ScadaLoginView.xaml:601-607`），主界面「系统」菜单没有入口（`Shell.xaml:1068-1138`）。
2. **改造核心不是重写密码学**。PBKDF2-SHA256 / 十万次 / 每账号随机盐 / 定时比较 / 原子写全部保留（`ScadaUserStore.cs:40-100`、`:909-970`）。要改的是**账号本归属**、**切换方案时的会话边界**、**所有能绕过按钮直接调命令的入口**。
3. **最大的风险不在界面**。五处高风险：另存为不会复制根文件（`SolutionAssetFolders.cs:30-36`），Web 的 8 小时会话令牌没有方案身份（`ScadaWebTicketService.cs:105-147`），Shell 的执行/系统命令只判运行状态不判角色（`ShellViewModel.cs:675`、`:1127`、`:509`），**流程栏 13 个 `FlowAction` 分支零角色判断**（`FlowListViewModel.cs:125-260`），**运行画面上的运动类图元在未配 `RequiredRole` 时任何人都能点动伺服**（`ScadaRuntime.cs:275-288`、`AxisPanelElement.cs:440/544`）。
4. **账号不写进 `.vms`**。账号本含哈希、会被 Capture/撤销栈/序列化路径碰到；必须独立文件、独立原子写。方案级 ≠ 配置级。
5. **“按需登录”不变**。未登录仍按 `Operator` 判定（`IScadaAccessPolicy.cs:29+`、`ScadaAccessPolicy.cs:129`）；密码保护的是改参数、改配置、改权限这些高权限动作。**运动类图元是唯一收紧的例外**：未配 `RequiredRole` 时按 Engineer 兜底（§3.6-G），因为点动伺服不是“普通按钮”。**但停止永不收紧**：轴面板的 `Stop`/`JogStop` 不读 `RequiredRole`、恒放行；点动过程中被降权或登出时还会在下一拍自动补发 `JogStop`（§3.6-G 位置④）——停得下来优先于权限一致。

## 1. 需求边界

### 1.1 本次要做（In Scope）

| # | 内容 | 验收口径 |
|---|---|---|
| S1 | 账号本归属从「软件目录」改为「方案目录」 | 两个方案可有同名不同角色/不同密码的账号，互不影响 |
| S2 | 账号字段固定为「账号 + 密码 + 角色」 | 界面不出现邮箱、手机、显示名、备注等本次未要求的字段 |
| S3 | 打开方案自动加载该方案账号；切换方案自动登出 | 切方案后 `IsLoggedIn=false`、`CurrentRole=Operator` |
| S4 | 新建方案有出厂管理员；首次保存才落盘 | 保存前磁盘不产生账号文件 |
| S5 | 另存为把**当前内存账号**写到新方案目录 | 新目录有 `Users\ScadaUsers.json`，内容与当前账号本一致 |
| S6 | 旧机器级账号本可迁移（导入一次） | 老用户升级后仍可用原账号登录；旧文件不删除 |
| S7 | 固定三档角色 + 逐入口权限矩阵 | 每个菜单/命令/快捷键/命令面板/**流程栏 13 个 `FlowAction`**/**运行画面运动类图元**都有唯一判据 |
| S8 | Web 运行态登录/会话绑定到当前方案 | 切方案后旧会话失效；跨方案重放 ticket 被拒 |
| S9 | 审计记录带方案标签，可按方案筛选 | 仍是 7 列 CSV，不加列、不改老行 |
| S10 | 独立用户管理大页（账号/会话/审计） | Web 设计基线先审，再复刻 WPF |
| S11 | 断言与 gate 覆盖以上行为 | 新增 `[SL]`、Web 检查、UI 冒烟；`run_gates.ps1` 绿色 |
| S12 | 文档同步（方案说明、Web 方案、测试矩阵、UI 基线） | 不留下“文档说机器级、代码是方案级”的错位 |

### 1.2 本次不做（Out of Scope）及理由

| 不做项 | 理由（决定，不是待定） |
|---|---|
| 方案级密码策略 / 失败锁定 | 需求只给了「账号 密码 角色」；密码最短长度与空闲超时继续由机器级 `AppConfig.json` 管（`AppConfigModel.cs:740/781`、`:639`）。Web 已有取票限速与默认密码闸门。新增每方案策略会多一个文件、多一套界面，本批不做 |
| 机器级“安装管理员” | 与“方案级账号”冲突，且会引入第二套账号体系。桌面文件系统信任边界在 §8 明示，本批接受 |
| 账号文件加密 / 防篡改签名 | 本批只做 PBKDF2 哈希；能改文件的人本来就能替换整个账号本，加密不能改变这条边界（`ScadaUserStore.cs:54-56` 已有同样的判断） |
| 每用户 ACL | SCADA 已有页面级 `RequiredRole` 与图元级 `RequiredRole`（`ScadaRuntime.cs:110/277-280`），按“角色”而非“具体人”授权；本批不引入“具体某个人”的授权。**例外（本批做）**：未配 `RequiredRole` 的**运动类**图元由“不限制”改为 Engineer 兜底（§3.6-G），这是补一个真实的越权口子，不是新增 ACL 体系 |
| 审计拆分方案文件 | 审计是“事后唯一作证的那份”，按方案拆文件会碎片化证据并改变保留策略；用标签归属。**审计目录仍在程序目录**（§3.8），本批不搬迁 |
| 审计 CSV 加列 | 代码注释明确禁止：外部脚本按 7 列读取（`ScadaAuditWriter.cs:365-366`）。改用说明列前缀 |
| 浏览器端编辑组态 | 违反 R132A（Web 只做运行态查看/操作） |
| 域账号 / SSO / LDAP | 无需求，且会改变离线工业现场的可启动性 |
| 账号批量导入导出 / 密码找回邮件 | 无需求；现场重置密码由管理员在桌面端完成 |
| 插件内部测试运行按钮的权限改造 | 已核对：本仓库没有插件视图直接调引擎运行；`FlowVariableTriggerService.cs:168` 与 `FlowTimerScheduler.cs:157` 是系统驱动的自动运行，不属于“用户操作”。若后续新增插件直调，按同一 gate 接入 |

## 3. 目标设计

### 3.1 账号记录（文件格式不变）

```json
[
  {
    "Name": "admin",
    "Salt": "Base64…",
    "Hash": "Base64…",
    "Iterations": 100000,
    "Role": 3
  }
]
```

| 字段 | 规则 |
|---|---|
| `Name` | 1–64 字符；忽略大小写唯一（`ScadaUserStore.cs:148`）；界面不提供改名，改 = 删+建 |
| `Salt` / `Hash` | PBKDF2-SHA256 100,000 次、16 字节盐；只存 Base64 |
| `Iterations` | 随记录保存，便于以后调高迭代次数时老账号仍可登录（`ScadaUserStore.cs:998`） |
| `Role` | 存数值：`Operator=1`、`Engineer=2`、`Administrator=3`；`Undefined=0` 与未知值一律拒绝 |

**为什么账号不写进 `.vms`**：`.vms` 会被 `SolutionService.Serialize` 序列化、被撤销栈/草稿/另存为路径反复搬运；哈希与密码元数据进去，等于把凭据散进每一个方案副本和临时文件。独立文件 + 独立原子写，是现有存储层已经验证过的路径。

**密码规则不变**：最短长度仍取机器级 `AppConfigModel.MinPasswordLength`（默认 4）；管理员重置密码不要求旧密码；本人改密仍走登录弹窗的「改密」页。

### 3.2 文件布局

```text
<方案根>\
├─ <方案名>.vms
├─ Image\
├─ Alarms\
├─ History\
├─ Logs\
└─ Users\
   └─ ScadaUsers.json
```

| 决定 | 理由 |
|---|---|
| 子目录 `Users\`，不是根文件 `Users.json` | 另存为只复制目录；手工在资源管理器里整目录复制方案时，账号一起走 |
| 加入 `SolutionPaths.StructureFolderNames`（`SolutionPaths.cs:57`） | 保存时 `EnsureStructure` 自动建目录；SF10 同步加一条 |
| **不**加入 `SolutionAssetFolders.AssetFolderNames`（`SolutionAssetFolders.cs:30`） | 账号必须由存储层按“当前内存态”写，不能盲目复制旧文件；SF18/SF19 保持原样 |
| 文件名保留 `ScadaUsers.json` | 与旧文件格式逐字一致，迁移成本最低；`pack.ps1` 的旧路径保护继续有效 |
| 每方案一个账号本 | 满足“不同方案的用户可以不一样” |

> **注 1：`Audit\` 不在此列表中。** 审计 CSV 一直在**程序目录** `<程序目录>\Audit\Audit-yyyy-MM-dd.csv`（`ScadaAuditWriter.DefaultDirectory`，`:290`），本批只给它加方案标签，**不搬迁、不按方案分目录**；方案根下永远没有 `Audit\`（§3.8）。
>
> **注 2：`Users` 目录由两条路径双重保证。** 保存时 `EnsureStructure` 按 `StructureFolderNames` 建（下次保存自动补齐），`AttachSolutionFolder` 写入前也会 `CreateDirectory` 一次。打开路径**不调用** `EnsureStructure`，所以“打开后 `Users` 不存在”仍然成立（SL4）；实现者不要以为账号文件靠资产复制产生。

### 3.3 账号本状态机

| 状态 | 何时进入 | 内存账号从哪来 | 能登录 | 能改账号 | 会写盘 |
|---|---|---|---|---|---|
| `NoSolution` | 启动后尚未打开方案；关闭方案 | 空 | 否（提示“尚未打开方案”） | 否 | 否 |
| `UnsavedSolution` | 新建方案后、首次保存前 | 出厂管理员 `admin/admin123` | 是 | **否**（按钮禁用，提示“请先保存方案”） | 否 |
| `PersistedSolution` | 打开已保存方案 / 保存成功 / 另存为成功 | 方案文件；缺失则导入旧账号本；再缺失则出厂管理员 | 是 | 是（原子写 + 失败回滚） | 是 |

“能改账号”指**全部**五个写方法：`TryAddUser`、`TryRemoveUser`、`TrySetRole`、`TryResetPassword`、`TryChangePassword`。未保存方案时五个一律拒绝并给出同一句原因；登录弹窗的「改密」页同样禁用，否则会从另一条路绕过状态机。已保存方案的登录验证路径不变：登录弹窗仍调 `TryValidate` 再 `policy.Login`，只是账号本已经换成当前方案的这一份。

**转换规则**：

| 动作 | 转换 | 细节 |
|---|---|---|
| 新建方案 | `NoSolution → UnsavedSolution` | `SolutionService.Create` 不建文件（`SolutionService.cs:64-71`），账号只在内存 |
| 打开方案 | `→ PersistedSolution` | **打开不写盘**：没有 `Users` 文件就不创建（保留 `[US]`“只是打开过一次软件不留文件”的语义） |
| 保存成功 | `UnsavedSolution → PersistedSolution` 或保持 | `.vms` 写成功、`EnsureStructure` 建目录后，`AttachSolutionFolder` 把当前内存账号写进 `Users\ScadaUsers.json` |
| 另存为 | `UnsavedSolution / PersistedSolution → PersistedSolution`，换根 | 同上，但写的是**当前内存账号**，不是旧文件拷贝 |
| 切换方案 | 先登出，再重绑 | 见 §3.5 |
| 关闭软件 | 无动作 | 已经即时落盘；未保存方案本来就没有可写的根 |

**保存顺序（决定）**：

1. `CaptureLayoutToConfig` / 变量 / 通信快照（现状不变）
2. `SolutionService.SaveAsync` 写 `.vms`（原子写，现状不变）
3. `SolutionPaths.EnsureStructure` 建 `Image/Alarms/History/Logs/Users`
4. `ScadaUserStore.AttachSolutionFolder(root)` 写账号本
5. `SolutionAssetFolders.CopyAlongside` 复制资产（仅另存为）

第 4 步失败时：**不回滚已写好的 `.vms`**，弹 `Warning`“方案已保存，但账号文件写入失败：…”。分两种情况收尾：

- 账号文件**原本存在**（普通保存 / 覆盖另存）→ 内存回滚到磁盘那版，状态保持 `PersistedSolution`，避免“界面是新账号、磁盘是旧账号”的分叉；
- 账号文件**原本不存在**（首次保存 / 新根）→ 没有可回滚的提交点，状态回 `UnsavedSolution`，账号只保留在内存，页面横幅提示“账号文件未写入，请重新保存方案”，下一次保存重试。

两种情况都不报“保存失败”，因为 `.vms` 已经原子落盘；这与现有资产复制失败只提示的口径一致（`ShellViewModel.cs:1068-1074`）。

**为什么未保存方案禁止改账号**：账号写不进去，改成功就是“界面成功、重启丢失”，正是 `ScadaUserStore.Persist` 明确要避免的假成功（`ScadaUserStore.cs:962-980`）。禁用比假成功好；出厂管理员足够先把方案保存下来。

### 3.4 存储层改造

新增/变更成员（实现仍在 `ScadaUserStore`，接口 `IScadaUserAuthenticator` 签名不变）：

| 成员 | 语义 |
|---|---|
| `ScadaAccountBookState BookState` | `NoSolution / UnsavedSolution / PersistedSolution` |
| `Guid? BoundSolutionId` | 当前绑定的方案 id |
| `string? BoundSolutionRoot` | 当前方案根；`null` = 未保存方案 |
| `event Action? BookChanged` | 账号本整体换过（切方案/重新加载）时触发；账号增删改仍走现有 `UserChanged` |
| `bool BindSolution(Guid id, string name, string? root, bool importLegacy, out string? error)` | 切方案时重绑。`root == null` → `UnsavedSolution`；有根且文件存在 → 加载；有根无文件 → 可选导入旧机器级账号本，否则出厂管理员。**不写盘**。失败时 `error` 必须含**完整路径 + 异常类型 + 异常消息**（复用 `LastLoadError` 格式，`ScadaUserStore.cs:241/885`），让现场能区分“网络盘断开 / 权限不足 / 文件损坏” |
| `bool AttachSolutionFolder(string root, out string? error)` | 保存/另存为时调用：把当前内存账号写到 `root\Users\ScadaUsers.json`，成功后转 `PersistedSolution` |
| `void Unbind()` | 清空账号本 → `NoSolution`；用于没有当前方案的场合 |

**锁与事件**：继续遵守 `_writeGate → _gate` 的锁序（`ScadaUserStore.cs:64-100`）；PBKDF2 与文件 I/O 在锁外；`BookChanged` / `UserChanged` 在释放锁后触发，避免把会话线程拖进账号锁。

**旧账号本导入**（决定）：

- 仅当：方案根存在、`Users\ScadaUsers.json` 不存在、旧机器级 `ScadaUsers.json` 存在。
- 导入到内存，**不删除旧文件、不立即写新文件**；首次保存时随 `AttachSolutionFolder` 落到方案目录。
- 每个方案各自导入一次：同一台机器上有多个老方案时，每个方案第一次打开都从旧账号本起步，之后各自演化。
- 账号文件损坏时：回退到出厂管理员，`LastLoadError` 非空，页面显示错误；**绝不**悄悄改用旧账号本或上一个方案的账号本。
- 账号文件为空数组或全部记录非法：按损坏处理，回退出厂管理员。坏文件**不在打开时改名**（打开不写盘）；下一次真正要写盘前，先把坏文件改名为 `ScadaUsers.json.bad-<yyyyMMddHHmmss>` 保留证据，再写新文件。
- **绑定失败的口径（fail-closed）**：方案根目录不存在/不可访问，或账号文件存在但读取抛异常（权限、共享断开、被独占）→ `BindSolution` 返回 false，协调器执行 `Unbind()`，状态 `NoSolution`，**不拿出厂管理员兜底**，登录与 Web 都不可用，界面显示具体错误。理由：网络盘断开时若回落到 `admin/admin123`，等于给“拔网线”开了一个管理员后门；只有“目录可访问且文件确实不存在”才是合法的首次打开/迁移场景。
- 损坏但**可读**的 JSON 仍回退出厂管理员（与现有行为一致）；能改文件的人本来就能替换账号本，这条不增加攻击面（§8 R1）。
- **缺账号文件时的横幅（R7 的廉价补救）**：有根、`Users\ScadaUsers.json` 不存在、且旧机器级账号本也不存在（或已导入过）→ 绑定成功但 `BookSource = Factory`。协调器在状态栏与用户管理页显示一次性提示“本方案没有账号文件，当前使用出厂管理员；若这是从另一份方案复制来的，请手动复制其 `Users` 目录”。不自动扫描其它方案（成本高且会误配），但避免“静默降权成 `admin/admin123`”。`BookSource` 取值：`Solution / LegacyImport / Factory / Unbound`，供界面与断言读取。

**账号不变式**（沿用现有）：

- 至少保留一个管理员；删除/降级最后一个管理员被拒。
- 不能删除当前登录的账号（新增界面闸；存储层再加一道，防止脚本路径）。
- 角色变更/删除当前登录账号后，桌面会话强制登出（§3.5）。
- 写失败回滚内存到磁盘状态（`ScadaUserStore.cs:962-980`）。

### 3.5 方案身份与切换协调

新增领域接口（`Scada` 项目，Web 与 VisionMaster 都引用）：

```csharp
public readonly record struct ScadaSolutionChange(
    Guid? OldId, long OldEpoch, Guid? NewId, long NewEpoch);

public interface IScadaSolutionContext
{
    Guid? SolutionId { get; }
    string SolutionName { get; }
    string? SolutionRoot { get; }
    bool IdentityPersisted { get; }  // id 是否来自磁盘（老方案首次加载会被赋新 Guid，但没落盘）
    long Epoch { get; }              // 每次真正切换 +1；会话/票据的有效期边界
    string AuditTag { get; }         // 落盘 id： "[sol=<id12> <sanitized name>]"；未落盘： "[sol=unsaved <sanitized name>]"
    event Action<ScadaSolutionChange>? SolutionChanged;
}
```

**为什么审计标签要区分“id 是否落盘”**：老方案的 `SolutionId` 为空时，`SolutionService.LoadAsync` 每次加载都会生成一个新 Guid（`SolutionService.cs:151-152`）。如果标签直接用 id，同一个未保存的老方案每次启动都换一个标签，审计记录再也对不上。所以 `IdentityPersisted=false` 时标签写 `[sol=unsaved <name>]`，首次保存成功后（`NotifySolutionSaved`）转为 id 标签。**打开仍然不写盘**，不为了稳定标签去改 `.vms`。

`IScadaWebSessionAdmin` 的 DTO 只出对外安全字段：

```csharp
public sealed record ScadaWebSessionInfo(
    string SessionRef, string? UserName, ScadaRole Role,
    string? RemoteIp, DateTime ConnectedAtUtc, DateTime LastSeenUtc,
    bool ReadOnly, bool CanOperate);

public interface IScadaWebSessionAdmin
{
    bool IsAvailable { get; }
    IReadOnlyList<ScadaWebSessionInfo> ListOnline();
    bool TryKick(string sessionRef);
    int KickAll();
}
```

`WorkspaceContext.SwitchSolution`（`IReadOnlyWorkspaceContext.cs:192-200`）末尾追加 `SolutionSwitched` 事件。新增 `SolutionSessionCoordinator` 订阅该事件，按固定顺序执行：

1. 取旧方案 id/root/name 与**旧登录用户名**（必须在 Logout 之前取，否则审计署名会被回落成“未登录”）。
2. 若新旧 id 与 root 都相同 → 只确保账号本绑定，不登出、不撤销 Web 会话（幂等）。
3. 否则在 UI Dispatcher 上执行：`ScadaAccessPolicy.Logout()`，用第 1 步捕获的用户名作 actor 写一条审计（事件“方案切换自动登出”，说明带新旧方案名）。
4. `ScadaUserStore.BindSolution(newId, newName, newRoot, importLegacy: true)`。绑定失败 → `Unbind()` 并记录 Error，**绝不保留上一个方案的账号本**。
5. `SolutionIdentityHolder.Set(...)`：更新 id/name/root，`Epoch++`，生成审计标签。
6. 撤销**全部** Web 会话（见 §3.7 的理由），触发 `BookChanged`。
7. 整个过程 `try/catch`：切方案不能因为账号/Web 故障而抛回 `WorkspaceContext`；异常只落日志与状态栏。
8. 事件在后台线程触发时，用 `Application.Current.Dispatcher.BeginInvoke` 排队；同一优先级的 FIFO 保证连续切换不反序。`Application.Current == null`（断言/探针宿主）时直接同步执行，与 Web 模块处理 UI Dispatcher 的口径一致。

`SolutionIdentityHolder` 用一把私有锁保护 `(id, name, root, epoch, tag)` 元组并在锁内复制事件委托，避免切方案与读身份并发时读到半新半旧的状态。

**保存/另存为后的根更新**：首次保存（`root: null → 路径`）与另存为（`root: 旧 → 新`）成功后，协调器调用 `SolutionIdentityHolder.UpdateRoot(newRoot)`。只更新根字符串，**不升 epoch、不触发 `SolutionChanged`、不撤销 Web 会话**——方案身份没变，只是落点变了。审计标签用 id + name，不随根变化。`SolutionSessionCoordinator` 为此暴露 `NotifySolutionSaved(SolutionModel, string filePath)`，由 `PersistSolutionAsync` 在 `AttachSolutionFolder` 成功后调用。

**为什么切方案撤销全部 Web 会话，而不是只撤旧方案的**：另存为保留同一个 `SolutionId`（`SolutionModel.cs:119` 是稳定 Guid），磁盘上可能存在两份同 id 的方案；只按 id 撤销会漏掉“从副本切换到原件”的场景。`Epoch` 是唯一不会重复的边界，撤销全部最简单也最安全。代价是切方案时所有浏览器都要重新登录，这与“切方案是重大操作”的现场语义一致。

**角色/账号变更对桌面会话的影响**：

| 变更 | 桌面当前会话 | Web |
|---|---|---|
| 改自己密码 | 保持登录（身份未变） | 现有 `UserChanged` 撤销该账号全部会话（`ScadaWebModule.cs:230-259`） |
| 改自己角色 | 强制登出（提示“权限已变更，请重新登录”） | 撤销 |
| 删除自己（需另有管理员） | 强制登出 | 撤销 |
| 改别人的密码/角色/删除 | 不影响当前会话（除非当前用户就是目标） | 撤销目标账号 |

**“降权强制登出”的唯一实现者（补 SL11 的落点）**：`SolutionSessionCoordinator` 订阅 `ScadaUserStore.UserChanged`。事件带 `(userName, changeKind)`；当 `userName == accessPolicy.CurrentUserName` 且 `changeKind ∈ {RoleChanged, Removed}` 时，协调器在 UI 线程执行 `Logout()`、写一条审计（事件“权限变更自动登出”），并刷新三个命令的 `CanExecute`。存储层只管拒绝“删/降最后一个管理员”，**不做**登出——它不该认识会话。两条路径（用户管理页 / 脚本直调存储层）因此都覆盖。

### 3.6 固定权限矩阵

判据口径：`CurrentRole` 达到或高于要求即放行；`Undefined`/未知值拒绝；未登录 = `Operator`（`IScadaAccessPolicy` 契约）。**界面变灰只是第一道；handler 出口必须再判一次**（这是 `IScadaAccessPolicy` 类注释里已经写死的口径）。

#### G. 运行画面运动类图元（默认收紧，Stop 恒放行）

现状：`ScadaRuntime.RaiseElementEvent` 只在 `element.RequiredRole is { } required` 时才问策略（`ScadaRuntime.cs:275-288`），**为 null 直接放行**；轴面板按钮走另一条路（`AxisPanelElement.TryExecuteCommand → CheckCanRun → IScadaAxisCommandSink`，`AxisPanelElement.cs:475-497`），判的也是 `Element?.RequiredRole`（`:527`），**同样 null 放行**。也就是说：把运动板卡设成 Engineer 只挡住了窗口，**挡不住运行画面上的点动/回零/使能按钮**；而六个按钮又共享一个 `CanOperate` 容器（`Themes/AxisPanelElement.xaml:468`），一刀切收紧会把停止按钮一起灰掉。

| 决定 | 内容 |
|---|---|
| 判据 | 图元在**当前事件**下的钩子动作含非 Stop 的运动命令（运动族 `MotionEnable=7 … MotionJogStop=15`，**排除两个停止动作 `MotionStop=12`、`MotionJogStop=15`**）且 `RequiredRole==null` → 按 `Engineer` 兜底；`RequiredRole` 显式配过则**以配置为准**（可用 `Operator` 明确放开，也可用 `Administrator` 收紧）。**Stop/JogStop 不参与兜底**：`RequiredRole==null` 的 stop-only 钩子保持不限制；若组态者显式配了角色，仍按配置判（见“边界”）。轴面板的停止按钮不读 `RequiredRole`，恒放行。**点动过程中权限被收回/登出时，必须在下一拍自动补发 `JogStop`（位置④），不等看门狗** |
| 位置 ①（事件钩子） | `ScadaRuntime` 的元素事件闸门把 `element.RequiredRole` 换成纯函数 `EffectiveRequiredRole(element, eventType)`：只看**当前事件**的钩子动作，stop-only 钩子返回 null；显式 `RequiredRole` 优先 |
| 位置 ②（轴面板按钮） | `AxisPanelElement.CheckCanRun` 增加命令感知重载：`Stop`/`JogStop` 在“有出口 + 有选中轴”之后**跳过权限判**；点动/使能/回零/清报警仍判 `Element?.RequiredRole ?? | 位置 ③（轴面板 XAML） | **必须把 `BtnStop` 移出 `CanOperate` 容器**：容器 `Grid` 去掉 `IsEnabled` 绑定；`BtnEnable`/`BtnJogReverse`/`BtnJogForward`/`BtnHome`/`BtnClearAlarm` 各自绑 `CanOperate`；`BtnStop` 绑新属性 `HasAxisAndSink`（有出口 + 有选中轴，不含权限）。**不能只给 `BtnStop` 设 `IsEnabled=true`**——父级 `Grid` 为 false 时子级无法翻回（WPF `IsEnabled` 继承语义） |
| 位置 ④（自动收手） | `RefreshCanOperate`（`:540-552`）在算出 `can == false && _jogHeld` 时，**先**调 `EndJogForAxis(SelectedAxisId)`（`:924-940`：直呼 `IScadaAxisCommandSink`，不判权限、不判按钮可用性），**再**更新 `CanOperate`/`HasAxisAndSink`。覆盖降权、手工登出、空闲超时登出；`OnBeat` 每拍调 `RefreshCanOperate`（`:1055`），最迟一拍内发出 `JogStop`。前提：`OnBeat` 未在 `:1039-1041` 早退（`AxisSource` 已接）；宿主两处构造都把 `AxisSource` 与 `AxisCommands` 成对传入（`ScadaMonitoringHost.cs:187-197`、`ScadaRuntimeHost.cs:882-886`）。不写 `CommandMessage`（自动收手不是用户操作）；无出口时 `EndJogForAxis` 先清 `_jogHeld` 再返回；摘上下文/关窗不依赖本条——执行器 `Dispose`（`:770-800`）会把仍在点动的轴停掉。**本条不改变看门狗锚点**（长按点动 >~1.2s 被停是既有缺陷，见 C32/R21，默认另批处理） |
| 覆盖范围 | `Hmi.AxisConsole` / `Hmi.AxisPanel` / `Hmi.AxisPointTable` 三个 TypeKey 都指向 `AxisPanelElement`（`BuiltInElements.cs:586/623/661`），改类即全覆盖；`MotionBoardView` 桌面调试窗走 `IScadaAxisCommandSink` 直调，已由 §3.6-D 归 Engineer，不重复处理 |
| 普通图元 | **不动**。按钮/输入框的 `RequiredRole` 保持“null = 不限制”，否则每个现场按钮都要重新配权限 |
| 代价 | 未配权限的轴面板，操作员与未登录用户会看到点动/使能/回零/清报警**以及点位表的示教/定位/行内改速度**变灰，**停止始终可用**。需要放开的现场在图元属性里显式配 `Operator`；`ShowCommands=false` 整块收起是组态的显式选择，不属于权限收紧 |
| 边界 | 事件钩子里**同时**配点动与停止的图元，停止钩子仍按显式配置判（不做“钩子内按动作种类放行”）；急停请用轴面板停止按钮（恒放行）或独立的 stop-only 图元。Web 端命令仍按 `AllowCommands` + 会话角色（§3.6-H），不套本例外 |

> **与 R108 的关系**：R108 要求“权限在按下前判、`CanOperate` 绑 `IsEnabled`、每拍重算”。本批只对**停止按钮**把绑定源从 `CanOperate` 改为 `HasAxisAndSink`（仍每拍重算），其余按钮不变；权限判据仍在 `CheckCanRun`/`EffectiveRequiredRole` 内。这是 R108 的唯一有意例外，理由见上表“边界”。
>

### 3.8 审计

- **位置不变**：审计仍在**程序目录** `<程序目录>\Audit\`（`ScadaAuditWriter.DefaultDirectory`，`:290`；`App.xaml.cs:425-426` 注册的就是它），**不在方案根下**，本批不搬迁、不按方案分目录。方案根下只有 `Image/Alarms/History/Logs/Users`。
- **列不变**：仍为 `时间,操作者,对象,事件,动作,结果,说明` 7 列（`ScadaAuditWriter.cs:213-216`）。
- **文件名格式只有一个事实源**：`Audit-{0:yyyy-MM-dd}.csv`（`:199`，实际文件名 `Audit-2026-10-24.csv`）。本批把 `FileNameFormat` / `FileNamePrefix` / `FileNameSuffix` / `FileNameDateFormat` 由 `private` 改为 `internal`（或公开只读属性）供 reader 复用；**禁止 reader 自带一份 `yyyyMMdd.csv` 之类的字符串**——那会读空目录而 UI 把“空”当合法空态，断言全绿、功能全废（R38）。
- **方案标签**：`[sol=<id12> <name>] ` 前缀加到「说明」列；未落盘方案用 `[sol=unsaved <name>]`（§3.5）。`name` 中的 `[` `]` `\r` `\n` 替换为 `_`。
- **唯一落盘点**：`Append(ScadaAuditEntry, DateTime)`（`:303`）是唯一**落盘**点；`Append(entry)`（`:299`）与 Web 重载（`:375-390`）都转发到它。
- **前缀加在 `BuildRow` 内**（`:549`，对 `entry.Detail` 加），不放在任何一个 `Append` 重载里——放重载里会出现“两个重载各加一次 → 前缀重复”，放 `BuildRow` 里则所有调用方（含未来新增）自动生效，调用方一行不改。
- **读取**：新增 `ScadaAuditReader`，用 writer 的 `DefaultDirectory` + `FileNameFormat` 枚举文件，严格 UTF-8（失败回落 936），解析带引号字段；只读、不写、不清理（清理只在 `PurgeIfNewDay` 的写路径）。
- **非法行**：跳过并**计数**（`SkippedLines`）。审计页签底部固定显示“已跳过 N 行（格式异常）”仅在 N>0 时出现；N 由 reader 返回、由 SL20 断言，不做没人看的隐形计数。
- **UI 筛选**：默认只显示当前方案标签的行；“显示未归属（历史记录）”开关可看没有标签的老行。
- **不新增列的理由**：外部脚本按 7 列读取（`ScadaAuditWriter.cs:365-366` 类注释），加列等于静默打断现场已有的报表/采集脚本。
- **不拆方案文件的理由**：审计要能回答“三个月前谁动过”，拆文件会碎片化证据、改变 90 天保留与清理逻辑。

### 3.9 界面（Web 基线先行）

#### 形态

- **独立模态大窗，1100×820，最小 980×700**。**直接复用 `HardwareManagerView` 的大窗壳**（`WindowStyle=None` + 自绘标题栏 + 同尺寸/最小尺寸，`HardwareManagerView.xaml:193-203`）：仓里已有同形态窗口，另造一套 1180×760 属于无理由分叉（R120/R141）。三页签在 1100 宽下每页都有 ≥ 1000px 内容区，够放 7 列 GridView。
- 不做成停靠文档页：避免卷进 `Layout.xml` 的恢复/版本升级（R43/R56），也不让用户把管理页拖成永久布局。
- 入口三处：`系统 → 用户管理`（新增）；**状态栏当前用户文字右键菜单**（左键保持现有“开登录弹窗”不变，见 `Shell.xaml:1694-1718`）；登录弹窗里的「用户管理」按钮（保留，改为打开新页）。右键菜单两项：`用户登录` / `用户管理`（后者仅管理员可见）。

#### 三个页签（决定）

| 页签 | 内容 |
|---|---|
| 账号与角色 | 左清单 + 搜索；右侧账号名（只读）、角色、新密码/确认、保存角色/重置密码/删除 |
| 在线会话 | GridView：会话/用户/角色/来源 IP/建立时间/最近活动/只读/操作（踢下线）；工具栏刷新、全部踢下线 |
| 审计记录 | 日期范围 + 操作者 + 结果筛选；GridView 7 列；只读；“显示未归属”开关 |

**为什么没有「登录策略」页签**：密码最短长度、空闲超时、审计保留天数都归机器级 `AppConfig.json`（`AppConfigModel.cs:639/740/781`），已有「系统设置 → 安全与留档」编辑入口。再在本页做一套编辑器会产生两个事实源，违反 R141 的“复用优先”。本页只在账号页签底部显示一行只读摘要 + “在系统设置中修改”的跳转。

#### 状态

| 状态 | 表现 |
|---|---|
| 无方案 | 整页空态“尚未打开方案”；所有操作禁用 |
| 未保存方案 | 顶部横幅“方案尚未保存，账号修改将在保存后可用”；列表只读 |
| 非管理员 | 页面不可打开；若打开后角色被降，立即提示并关闭 |
| 加载中 / 加载失败 | 骨架/进度条；失败横幅显示 `LastLoadError`（含路径与异常类型）+ “重新加载” |
| 账号本为空 | 理论不可达（出厂管理员兜底）；仍设计空态，不白屏 |
| Web 不可用 | 在线会话页签空态，不影响账号与审计 |
| 只读介质 / 写失败 | 错误横幅 + 操作回滚；不显示“保存成功” |
| 出厂管理员兜底（`BookSource=Factory`） | 账号页签顶部一次性提示“本方案没有账号文件，当前使用出厂管理员；若这是从另一份方案复制来的，请手动复制其 `Users` 目录”；改密后提示消失 |

（共 8 种；UM5 按名字逐条断言，不用计数。）

#### 视觉与控件纪律

- 0 处 `#RRGGBB`（R140）；颜色/间距/圆角全走 `Colors.xaml` 与 `Dialog*` 资源。
- 列表必须 `GridListViewStyle` + `GridViewRowPresenter` + 就地合并 `GridView.xaml`（AGENTS.md R19/R20/R22）；行容器内边距取 4（AGENTS.md R21）。
- 可复用结构优先用 `DialogColumnCard` / `DialogEmptyState` / `DialogIconButton` 等（R141）。
- 页签高度按 R133：`MinHeight ≥ 36`，模板根 `Border.Padding` 表达留白，**不许**用“Grid Auto 行 + 子元素 Margin”。
- 图标按钮必须带 `Style` 或显式 `Padding`（R68）；焦点可见（R135：`DialogFocusVisual` / `DialogToolTipStyle` / `FocusManager.FocusedElement`）。
- `DataTemplate` 里用到的 `{StaticResource}` 必须定义在同一字典中该模板**之前**（R173）；任何 `Popup.IsOpen` 绑定显式 `Mode=OneWay`（R174）。
- 密码框按 R184：`PART_ContentHost` 不许再吃一层 `Padding` 换算的 `Margin`；高度按“`ViewportHeight ≥ ExtentHeight`”验收，不看截图。
- 密码框只显示掩码，不提供“显示密码”；不显示哈希/盐/迭代次数。
- 审计页签底部固定一行元信息：显示条数 / 总行数 / （N>0 时）“已跳过 N 行（格式异常）”。
