## 0. 结论摘要

| 提案 | 判定 | 必须调整 | 校准工作量 | 建议顺序 |
|---|---|---|---|---|
| `Plugin.ImageQuality` | **做**，价值在"统一口径 + 配方基线 + 帮助 + 断言"，不在"能算指标" | ① 脏污移出 v1 验收（或改为"有参考图才做差分"）；② 饱和度只对彩色图，灰度明确跳过；③ HALCON 对拍去掉 `variance_image`；④ 不依赖判定表 | 5~7 人天（提案 3~4 天未计 8 页手册/断言/变异反证） | 第一 |

## 1. 提案前提核查（哪些说法要改）

### 1.1 事实错误（4 处，建议在提案里更正）

| # | 提案说法 | 实际情况 | 证据 |
|---|---|---|---|
| 1 | Align 提案 §2：「`PoseTransform` 位姿/坐标变换，**不做图像 warp**」 | **错**。`PoseTransform` 输出 `FollowedImage`（`affine_trans_image`，bilinear），帮助里明确写"有了 `Matching.AlignedImage` 就不必再开对齐图——两者等价" | `Plugins\Plugin.PoseTransform\PoseTransformHalcon.cs:44-58`；`Help\01-quickstart.md:50-55` |
| 2 | Align 提案 §2：「`Matching.AlignedImage` 刚性位姿归一化（转正/平移/**等比缩放**）」 | **错**。`VectorAngleToRigid` 只有平移 + 旋转，**不含缩放**；帮助自证"归一化是刚性的（平移 + 旋转）"，各向异性拉伸不还原 | `Plugins\Plugin.Matching\MatchingPlugin.cs:2121-2136`；`Help\04-匹配口径.md:181-183` |
| 3 | Align 提案 §1：「`BeadInspect` 内部有平面可变形对齐……**别的插件用不到**」 | **半错**。`BeadInspect` 已公开输出 `AlignedImage`；真正不外露的是 `HomMat2D` | `Plugins\Plugin.BeadInspect\BeadInspectPlugin.cs:232-233`、`:530-531` |
| 4 | Quality 提案 §1.2：「`PreProcessing` **只有滤波/阈值/形态学**等处理算子」 | **不完整**。还有锐化、对比度、亮度、反色、直方图均衡、Sobel、Laplace、FFT、几何调整 | `Plugins\Plugin.PreProcessing\Operators\EnhanceOperators.cs:9,58,108,146,162`；`EdgeOperators.cs:37,66`；`FrequencyOperators.cs:19` |

### 1.3 `pcb_focus` 数据体检（本轮实测）

| 帧 | 001 | 021 | 041 | 051 | 061 | 071 | 091 | 111 | 121 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Tenengrad（Sobel 梯度能量均值） | 30.9 | 48.7 | 117.2 | 296.5 | **391.7** | 96.3 | 28.0 | 14.3 | 11.2 |
| Laplacian 方差 | 31.4 | 30.1 | 31.4 | 70.0 | **160.3** | 28.9 | 26.6 | 26.0 | 25.8 |
| 平均灰度 | 95.7 | 90.5 | 86.7 | 85.1 | 83.9 | 82.9 | 81.7 | 80.7 | 80.4 |

结论：

1. **最佳焦点在 061 附近**；两侧都散焦。任何"全序列单调下降"的断言都会红，且不是算法错。
2. **Tenengrad 比 Laplacian 方差平滑得多**：Laplacian 在 001~041 几乎不动，容易把"接近焦点的散焦"判成同一档。建议 v1 对焦指标以 `sobel_amp` 的 `sum_abs` 均值为主，`laplace` 方差只作辅助/对拍项。
3. **平均灰度随焦点位置单调漂移 95.7 → 80.4**：这套图的"对焦"和"曝光"是耦合的，**不能拿它验证曝光指标**；曝光/对比度用 `label`/`smd` + 合成图。
4. 分辨率：`pcb_focus` 752×480；`label` 640×482；`smd` 640×512；`checkerboard_400.png` 400×400。全部 8-bit 灰度。

## 2. 能力重叠：什么是真正的新增价值

### 2.1 ImageQuality

| 能力点 | 现有覆盖 | 判定 |
|---|---|---|
| 对焦 / 曝光 / 对比度 / 饱和度的**标准化指标 + 配方基线 + 帮助 + 断言** | `ImageScript`/`CSharpScript` 能算任意指标，但没有统一口径、没有基线、没有 ROI 语义封装、没有断言 | **真新增**（卖点应写成"口径可复用"，不是"以前算不出来"） |
| 脏污检测 | `BlobDetect`、`DlAnomaly`、`DlSegment`、`DlClassify`、`ImageDiff` **五条路已覆盖** | **重复建设**。v1 若保留，只能定位成"有 `ReferenceImage` 时的差分前置分"，不能宣称"能检脏污" |
| 曝光/对比度的"测量" | `PreProcessing` 有增强算子（锐化/对比度/亮度/直方图均衡），但**只出图不出数**；`BlobDetect` 的直方图只在配置界面显示 | **真新增**（数值指标 + 运行时端口） |

建议 v1 范围：**对焦、曝光、对比度、饱和度 + 原始值 + 明细 + 可选阈值布尔**；脏污移到 v1.1（带 `ReferenceImage` 差分），v1 验收不计脏污检出率。

### 2.2 ImageAlign

| 能力点 | 现有覆盖 | 判定 |
|---|---|---|
| 模板位姿 → 刚性对齐图 | `Matching.AlignedImage`（`MatchingPlugin.cs:2109-2138`）+ `PoseTransform.FollowedImage`（`PoseTransformHalcon.cs:44-58`），**已实现两遍** | **重复建设**。v1 只做"消费上游 `Row/Column/Angle` 或 `HomMat2D`"，不自己跑匹配 |
| 2~4 点基准 → 像素域变换 | `Calibration` 的取点产物是"像素→机械 mm"，不是像素→像素；`ImageScript` 只有教学模板；无原生插件 | **真新增** |
| 手动四点 → 透视搬图 | `BeadInspect` 的四点矫正只服务自己的参考图；`DeformableMatching` 只给矩阵不搬图 | **真新增** |
| 透视/仿射重采样作为可复用步骤 | 无原生消费者；`DeformableMatching.HomMat2D` 目前只能喂脚本 | **真新增** |
| `InverseHomMat2D` | 全仓零实现（`BeadInspect`/`PoseTransform` 只在内部临时求逆） | **真新增** |
| `ValidRegion` | 全仓零实现；现有做法是文档里让用户"避开画幅边缘"（`Matching\Help\04:178`） | **真新增** |

补充边界：

- **有效区的下游消费者只有 6 个**：`ImageDiff`（`MaskRegion`）、`BlobDetect`（`MaskRegion`/`ExcludeRegion`）、`Matching`（`SearchRegion`）、`BeadInspect`（`RoiRegion`）、`DeformableMatching`（`SearchRegion`）、`GeometryFinder`（`MaskRegion`）。`ColorCheck`/`ColorRegion`/`Ocr`/`CodeReader`/`CaliperMeasure`/`DlAnomaly` **不吃上游 ROI**，要用有效区得先裁图或改造。帮助里必须写清这一点。
- **全仓没有原生 `HomMat2D` 输入口**。所以 ImageAlign 必须同时输出 `AlignedImage`（它确实输出了），否则矩阵没人接。
- **有效区必须几何生成**：用全图区域做 `projective_trans_region`/`affine_trans_region` 再与目标域求交；**不能**用"像素值是否为 0"判断黑边——黑色工件本身也可能是 0。

## 3. 验证方案逐条评审

### 3.1 ImageQuality

| 提案用例 | 可执行性 | 要改什么 |
|---|---|---|
| Gaussian blur 扫描 + Spearman ≤ -0.95 | 可执行（HALCON `gauss_filter`） | 明确 σ 序列与核大小；合成图真值可笔算。真图部分改为"以 061 为锚"的分段单调或与 `|i-i_best|` 的 Spearman（见 §1.3） |
| 亮度/γ 扫描，截断比例误差 ≤0.5pp | 可执行（`pow_image`/`scale_image`） | 解析真值必须算上 8-bit 量化与四舍五入；明确"截断"定义（=0 与 =255 的像素占比）；γ 扫描要覆盖 <1 和 >1 两侧 |
| 对比度拉伸单调 | 可执行 | 只在**不削顶**的区间断言单调；削顶后 P95-P5 会饱和，不能继续要求上升 |
| 饱和度：彩色上升、灰度 NaN/0 | 合成可执行；**真图不可执行** | 三套真图全灰度（§1.2 #7），只能合成彩色图；灰度必须显式跳过并输出原因，不能静默给 0 分 |
| 脏污：检出 ≥90%、干净图 ≤1/100 | 合成可执行；真图无真值 | 明确"检出"判据（已知斑块中心距 + 面积容差），否则 90% 无法复核；真图盲测不算 gate |
| 噪声：`estimate_noise` 上升、Focus 不同步上升 | 可执行 | 仓内测试工程零使用，需新写参考；注意噪声与对焦的耦合，断言要双向 |
| HALCON 对拍：`sobel_amp`/`laplace`/`variance`/`min_max_gray`/`gray_histo`/`decompose3`+`trans_from_rgb` | 可执行，但清单要改 | **`variance_image` 不存在** → 用 `deviation_image` 或 `intensity` 的 `Deviation²`；`min_max_gray` 第一个参数是 Region 不是 Image；`decompose3` 对单通道图会抛异常，先判通道数 |
| 反向 6 条"改坏必红" | 可执行 | 分两类：① 代码内反向输入（自动跑）；② R65 变异反证（手工改坏→重建→跑→还原→复绿），必须留记录；两者不能混为一谈 |
| 集成：良品误拦 ≤1%、坏图拦截 ≥95% | **缺前提** | 仓内没有 OK/NG 标签；要么先产一批标注（人工/合成），要么按 R38 明确写"本轮不可验证及原因"，不许写"通过" |
| 5MP ≤50ms | **缺基线** | 先新增 perf 模式/探针实测，分指标报（对焦/直方图/脏污）；不直接进常规 gate |

## 4. 工程约束与落地风险

1. **工程契约（缺一不可）**：插件工程必须在 `Plugins\`；csproj 四引用 + HALCON 引用 + `<EmbeddedResource Include="Help\**\*" />`；登记 `VisionMaster.sln`（R62）；`Help\` 8 页（5 用户 + 3 开发，M 档；Align 带画布建议按 L 档：5 用户 + 3 开发 + 开发页 ≥300 行）；在 `FlowCanvasChecks\HelpManualCheck.cs` 的 `Tiers` 登记（HM16 未登记直接红）；构建后由 `Plugins\Directory.Build.targets` 投递 `Modules\`（红线③：改了源码必须重建该插件工程）。
2. **判定表依赖**：`Plugin.JudgeTable` 半成品（见 §1.2 #8）。v1 不接判定表；阈值先用 `ComparisonPlugin` + `LogicOperationPlugin` 组合，等判定表落地再联调。
3. **共享文件冲突**：`VisionMaster.sln`、`FlowCanvasChecks.csproj`、`FlowCanvasChecks\Program.cs`、`HelpManualCheck.cs` 的 `Tiers` 都是热点。判定表施工方也在碰这些文件；C-15 记录过"另一会话整文件重写 `Program.cs`，把自己加的断言调用覆盖掉"。**两个插件必须串行接线，接线后立刻单跑一次 `FlowCanvasChecks` 留日志。**
4. **ImageAlign 的视图成本**：`AutoPortConfigView` 只支持 bool/枚举/数值/字符串；`ObservableCollection`、`HRegion`、`HTuple` 一律只读。基准点点选必须写自定义视图（范式 `CreateRoiView.xaml` 的 `h:ImageEdit`）。这会踩 R19-R22（GridView）、R30-R32（资源作用域）、R141（可复用 UI 下沉）、R173（模板内 `StaticResource` 顺序）等坑。
5. **HALCON 对象所有权**：输出端口上的 `HImage` 由基类 `AutoDisposeRoundOutputs` 轮首统一回收；插件自己 `Dispose` 已交给端口的对象会变野指针。中间对象 try/finally 释放，返回 `new HImage(result)`。
6. **并行安全**：新插件只调 `HOperatorSet`、无未加锁 static 状态 → 应标 `[ParallelSafe]`；若复用 `ImageScript` 跑脚本则**不能**（未标 `[ParallelSafe]`，编译器在并行分支直接报错，且 `HDevEngine` 是 static 单例）。
7. **HALCON 授权可移植性**：本机 `HALCONROOT` 有安装，仓库内没有 `license_*.dat`。换机器/CI 需单独安装 + 授权；断言宿主应沿用 `ImageDiffCheck.ProbeHalconUsable` 的"可用性前置 + 明确跳过/判红"模式，不许静默全绿。
8. **证据边界**：本评审的影响面是 grep/Read 结论，不是 CodeGraph 索引结论；实现前按 R28 重建索引复核。

## 7. 修订后的验收口径（建议直接抄进实现单）

### 7.1 ImageQuality v1

1. **对焦**：合成 Gaussian blur 序列单调下降；`pcb_focus` 以 061 为锚，`FocusScore` 与 `|i-61|` 的 Spearman ≤ -0.95（或 061→121 段单调下降、001→061 段单调上升，各 ≤ -0.95 / ≥ +0.95）。主指标用 `sobel_amp` 的 `sum_abs` 均值，`laplace` 方差作辅助。
2. **曝光**：合成 γ/增益扫描，0/255 截断比例与解析值误差 ≤0.5pp；`label`/`smd` 只验证方向与重复性（无绝对真值）。
3. **对比度**：不削顶区间内随拉伸单调上升；削顶后允许饱和并输出说明。
4. **饱和度**：仅合成彩色图；灰度图输出 NaN/0 + `Skipped=true` + 原因；灰度强算必须红。
5. **脏污（v1.1）**：合成暗斑检出率 ≥90%、干净图误报 ≤1/100；真图盲测不计 gate。
6. **对拍**：`sobel_amp`/`laplace`/`deviation_image`/`min_max_gray`/`gray_histo`/`decompose3`+`trans_from_rgb`，原始指标相对误差 ≤1%、截断比例 ≤0.5pp。
7. **反向**：代码内 6 条反向输入 + R65 手工变异反证记录（至少 6 条"改坏必红"）。
8. **性能**：5MP 分指标实测并落档；目标 ≤50ms（ROI 内），不直接进常规 gate。
9. **集成**：有标注批次才做误拦/拦截率；没有就按 R38 写"本轮不可验证及原因"。

### 7.2 ImageAlign v1

1. **合成**：平移/旋转/缩放/非等比/透视，4 角点重投影 ≤0.3px、对齐图平均绝对差 ≤2 灰度、逆变换往返 ≤0.1px。
2. **基准点**：4 点残差 ≤0.3px（合成）/≤1px（真图）；**透视模式 <4 个有效点 → 显式 `Fail`**，不回落仿射；单点挪 5px → 残差/分数超阈值判失败。
3. **下游收益**：同一工件人为平移/旋转/透视，直接 ImageDiff 面积大；先对齐再差分，面积下降 ≥80%（目标 ≥90%）；矩阵故意错 2px → 面积回升。
4. **对拍**：`proj_match_points_ransac` + `vector_to_proj_hom_mat2d` + `projective_trans_image` + `projective_trans_point_2d`；角点误差差 ≤0.2px、对齐图差 ≤1 灰度、`HomMat2D` 元素差 ≤1e-3（归一化后）。
5. **有效区**：几何生成 + 与目标域求交；黑边不进有效区；下游只在有效区内检测；帮助里列清 6 个可消费 ROI 的下游。
6. **坐标**：`HomMat2D`/`InverseHomMat2D` 自洽；下游结果搬回原图误差 ≤0.5px。
7. **性能**：5MP 单次对齐实测；砍掉自跑模板匹配后目标 ≤100ms，不直接进常规 gate。
