# 第 0 章 这是什么

**工具插件集 = 一盒"螺丝刀"**——不是做视觉算法的，而是把流程里那些"零碎但必须有"的动作做出来：给变量赋值、暂停一下、比个大小、做个逻辑运算、转个类型、算个数学。

> 生活比喻：检测插件是"主力机器"，工具集是旁边的**工具箱**——钉子、螺丝刀、尺子。单个不起眼，缺了就干不了活。

## 0.1 内含 6 个插件（不是 8 个！）

| # | 名称 | 分组 | 图标 | 一句话 |
|---|---|---|---|---|
| 1 | **变量赋值** | 变量操作 | `f044` | 给变量赋值（**运行时 / 全局**两种作用域） |
| 2 | **延时** | 常用工具 | `f017` | 暂停指定毫秒，**支持急停中断** |
| 3 | **数值比较** | 逻辑判断 | `f047` | 比较两个数值（支持浮点容差） |
| 4 | **逻辑运算** | 逻辑判断 | `f1b2` | AND / OR / NOT / XOR / NAND / NOR |
| 5 | **类型转换** | 数据处理 | `f044` | 转成 Int32 / Double / Boolean / String / DateTime |
| 6 | **数学计算** | 数据处理 | `f1ec` | 17 种运算（加减乘除、幂、开方、三角、对数、取整…） |

> ⚠️ **纠偏**：`docs/软件手册.md:514` 写"内含 8 个"，其中**随机数（Random）**和**变量定义（VariableDefinition）**已被删除——**实际是 6 个**。

## 0.2 一个工程装多个插件

- 命名空间统一 `VisionMaster.Plugins.Util`
- 工程文件 `Plugin.Util.csproj`，产物 `Modules\Plugin.Util.dll`
- 只有**变量赋值**有自定义配置视图；其余 5 个走框架自动生成的参数面板

# 第 1 章 设计思想

## 1.1 全工程没有 `[StepConfig]`（重要）

> **本工程没有任何 `[StepConfig]` 属性**——所有配置一律走 **`InputPort`**。

为什么？注释原文：

> ```
> /// 【为什么是输入端口】本插件没有自定义配置视图，宿主对这类插件统一打开
> /// 「变量绑定」窗口，而那个窗口只列输入端口 —— 写成 [StepConfig] 就没有编辑入口。
> /// 布尔型端口在窗口里用常量框填 true / false（窗口下方有提示），
> /// 也可以由上游变量决定（例如按配方切换"是否带使能"）。
> ```

## 1.2 两条必须遵守的端口纪律

**纪律①：`IsRequired = false` 必须显式写**

> `InputPort.IsRequired` 默认就是 `true`，而（旧版）编译期的必填检查只看**有没有连线**，不看有没有填值。于是默认值下，只要用户没用连线喂参数（也就是正常用法），编译必然报 `[参数缺失]`，这个节点等于用不了。

**纪律②：枚举不能经 `InputValues` 往返 → 用 string**

> 枚举会序列化成 int，读回来赋给端口时直接抛 `InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'`，**方案一打开就炸**。string 两端都能无损往返。

## 1.3 基类契约：默认成功、显式失败

> `VisionPluginBase.Execute` **进入 `RunAlgorithm` 前预置 `Success=true` 并清空 `ErrorMessage`**。
> 所以：成功不用写；**失败必须显式写**（`Fail()` 或置 `Success=false`）。吞异常而不报失败 = 被误放行。

## 1.4 不要重复声明 `Success` / `ErrorMessage`

> 基类已声明同名输出端口。派生类重复声明会**影子隐藏**基类成员——插件写派生端口、引擎读基类端口，表现为**永远报失败且错误日志为空**（CS0108 教训）。

# 第 2 章 工具逐个说明

## 2.1 变量赋值 `VariableAssignmentPlugin`

**做什么**：给变量赋值。**运行时**（本轮有效，跑完即弃）或**全局**（变量管理里那些，跨流程、随方案存盘）。

| 端口名 | 属性名 | 方向 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|---|
| `Name` | `VariableName` | 入 | string | **false** | `""` | 目标变量名 |
| `Value` | `Value` | 入 | object | **false** | `null` | 要赋的值 |
| `CreateIfNotExists` | `CreateIfNotExists` | 入 | bool | **false** | `false` | 不存在时自动创建（**仅运行时有效**） |
| `Scope` | `Scope` | 入 | **string** | **false** | `"Runtime"` | `Runtime` / `Global` |
| `Success` / `ErrorMessage` | 基类 | 出 | — | — | — | 复用基类 |

**作用域为什么必须显式选**（注释原文）：
> 同名时"运行时变量"与"全局变量"是两个不同的东西，自动路由要么产生歧义、要么用户看不出到底写去了哪。**显式选一次，语义就定死了。**

**为什么不"不是 Global 就当 Runtime"**（注释原文）：
> 那样拼错一个字母会把结果**静默写到另一个变量池**里，用户看到的是"赋值成功了但值不对"，比直接报错难查得多。→ 认不出来就明确报错。

**A2 类型守门**（注释原文）：
> 变量池的类型是条件表达式的"契约"——double 变量被塞 string 后，If/While 每次求值都抛异常、所有分支集体不走且流程照常往下跑，是**最难排查的静默故障形态**。这里对齐既有类型：**可转换则转（记 Warn），不可转换显式失败**。

**全局写入**：走 `context.GlobalVariables`（`IGlobalVariableWriter`）——插件物理上够不到"变量管理"所在的程序集。

## 2.2 延时 `DelayPlugin`

**做什么**：让流程暂停指定毫秒（默认 500ms），**支持急停中断**。

| 端口名 | 属性名 | 方向 | 类型 | 必填 | 默认 |
|---|---|---|---|---|---|
| `Delay` | `DelayTimePort` | 入 | int | **true** | `500` |
| `ET` | `ElapsedTime` | 出 | int | — | — |
| `State` | `State` | 出 | bool | — | — |

> 这是本工程**唯一 `IsRequired = true`** 的端口（界面填常量也算配置）。

实现要点：
- **50ms 分片轮询**（`const int step = 50`），每片检查 `context.CancellationToken.IsCancellationRequested` → **急停立即中断**并 Warn + `Success=false`
- 正常完成：`State=true` **且 `Success=true`**（注释：框架契约以 `Success` 判定业务成功，**不置 true 会被每轮标记"执行失败"**）
- catch → `State=false`、`Success=false`、Error 日志，然后**重新抛出**交给基类转 Fail

## 2.3 数值比较 `ComparisonPlugin`

**做什么**：比较两个数值的大小关系，**支持浮点容差**。

| 端口名 | 方向 | 类型 | 默认 |
|---|---|---|---|
| `A` | 入 | double | `0.0` |
| `B` | 入 | double | `0.0` |
| `Type` | 入 | `ComparisonType`（枚举） | `Equal` |
| `Tolerance` | 入 | double | `1e-6` |
| `Result` | 出 | bool | — |

六种比较：`Equal` / `NotEqual` / `GreaterThan` / `LessThan` / `GreaterThanOrEqual` / `LessThanOrEqual`

> 全部带容差：`Equal => Math.Abs(a-b) <= tolerance`；`LessThanOrEqual => a <= b + tolerance`
> **不写 Success** → 依赖基类"默认成功"。

## 2.4 逻辑运算 `LogicOperationPlugin`

**做什么**：布尔逻辑运算，六路。

| 端口名 | 方向 | 类型 | 默认 |
|---|---|---|---|
| `Operation` | 入 | `LogicOperationType` | `And` |
| `A` | 入 | bool | `false` |
| `B` | 入 | bool | `false` |
| `Result` | 出 | bool | — |

六种：`And` / `Or` / `Not` / `Xor` / `Nand` / `Nor`

## 2.5 类型转换 `DataConversionPlugin`

**做什么**：在不同数据类型之间转换。

| 端口名 | 方向 | 类型 | 默认 |
|---|---|---|---|
| `Input` | 入 | object | `null` |
| `Target` | 入 | `TargetDataType` | `Double` |
| `Format` | 入 | string | `yyyy-MM-dd HH:mm:ss` |
| `Result` | 出 | object | — |

五种目标：`Int32` / `Double` / `Boolean` / `String` / `DateTime`

> **输入 null → `Result=null` 且 `Success=true`**（null 算成功）
> DateTime 走 `DateTime.ParseExact(input.ToString(), format, null)`
> 转换失败 → Error 日志 + `Result=null` + `Success=false`

## 2.6 数学计算 `MathCalculationPlugin`

**做什么**：17 种数学运算。

| 端口名 | 方向 | 类型 | 默认 |
|---|---|---|---|
| `Operation` | 入 | `MathOperationType` | `Add` |
| `A` | 入 | double | `0.0` |
| `B` | 入 | double | `0.0` |
| `Result` | 出 | double | — |

17 种：`Add` `Subtract` `Multiply` `Divide` `Power` `Sqrt` `Abs` `Sin` `Cos` `Tan` `Atan` `Log` `Log10` `Exp` `Round` `Floor` `Ceiling`

> **`Divide` 除零 → `double.NaN`**（仍算成功，由下游判断）
> catch → NaN + `Success=false`（注释：**契约"默认成功、显式失败"，吞异常路径必须显式报失败**）

# 第 3 章 使用方式

## 3.1 安装与启用

1. 编译后产物 `Modules\Plugin.Util.dll`。
2. 重开软件，工具箱里出现 6 个工具（分属**变量操作 / 常用工具 / 逻辑判断 / 数据处理**四组）。

## 3.2 配置界面

只有**变量赋值**有自定义视图（三行表单）：

```
┌──────────────────────────────────────────┐
│ 给一个运行时变量赋值                        │
│ 运行时变量只在本轮执行内有效、跑完即弃；      │
│ 全局变量就是变量管理里那些，可跨流程、随方案  │
│ 存盘。                                    │
├──────────────────────────────────────────┤
│ 作用域    [运行时变量 ▾]                    │
│ 变量名    [             ] 🔗              │
│ 值        [             ] 🔗              │
│ ☑ 变量不存在时自动创建（仅运行时变量）        │
├──────────────────────────────────────────┤
│ 「值」填常量文本，要引用上游步骤的结果就点    │
│ 该行尾部的链接图标。作用域选「全局变量」时，  │
│ 该变量必须先在变量管理里建好（类型要与写入的  │
│ 值匹配）——运行期找不到会明确报错，不会静默   │
│ 新建。                                    │
└──────────────────────────────────────────┘
```

> 为什么不用通用的「变量绑定」窗口（注释原文）：
> 那个窗口是"给任意端口绑任意数据源"的通用工具，而本节点只有"给一个变量赋一个值"这么简单的事。用通用工具表达简单意图，用户不得不先消化「输入端口 / 绑定 / 常量 / 上游输出端口」一整套概念。

**其余 5 个工具**没有自定义视图 → 宿主自动生成参数面板（自动列出输入端口）。

## 3.3 第一次使用（以"变量赋值 + 延时"为例）

**变量赋值（4 步）**：
1. 选作用域（运行时 / 全局）
2. 填变量名
3. 填值——**常量直接敲，要引上游结果就点行尾 🔗**
4. 勾选"自动创建"（可选）

**延时（2 步）**：
1. 拖节点
2. 填毫秒数（默认 500）

**数值比较 / 逻辑运算 / 类型转换 / 数学计算**：拖节点 → 在自动参数面板里选运算类型 → 连上游或填常量。

## 3.5 FAQ

**Q1** 变量赋值和图像赋值有什么区别？
| | 变量赋值（本工程） | 图像赋值 |
|---|---|---|
| 写什么 | 任意值（数值/文本等） | 只写图像 `HImage` |
| 作用域 | 可选 Runtime / Global | 天生只写全局 |
| 自动建变量 | 支持（仅运行时） | 不支持 |

**Q2** 为什么填了值还报"必填参数未配置"？
历史问题：**旧版**编译期判据只看"有没有连线"。现已修正——`FlowCompiler` 加了 `hasConstant` 判据，**手填常量也算配置**。但 `IsRequired = false` 依然是正确且必要的写法。

**Q3** 延时能被急停打断吗？
**能**。延时按 50ms 分片轮询，每片检查取消信号。

**Q4** 延时失败会报吗？
会。急停 → Warn + `Success=false`；异常 → `Success=false` + 重新抛出交给基类。

**Q5** 类型转换输入 null 会失败吗？
**不会**。`Result=null` 且 `Success=true`（null 算成功）。

**Q6** 数学计算除零会怎样？
返回 `double.NaN`，**仍算成功**（由下游判断）。

**Q7** 数值比较为什么要容差？
浮点数有精度误差。`1.0/3*3 == 1.0` 未必成立，默认容差 `1e-6`。

**Q8** 能给全局变量赋值吗？
能。作用域选 `Global`，但**该变量必须先在变量管理里建好**——运行期找不到会明确报错，**不会静默新建**。

## 3.6 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| `变量名称不能为空` | 变量名没填 |
| `作用域取值无法识别：「xxx」` | 作用域拼写错（应为 `Runtime` / `Global`，大小写不敏感） |
| `本地变量 X 不存在` | 运行时变量不存在且没勾"自动创建" |
| `当前执行环境不支持写全局变量` | 简化构造（如单元测试容器）没有工作区绑定 |
| 全局变量类型不匹配报错 | 变量声明类型与写入值不符（对齐既有类型；可转换会自动转并 Warn） |
| 每轮都报"执行失败"但看着正常 | 曾经是延时插件只写 `State` 不写 `Success`——**已修** |
| 类型转换失败 | 检查 `Format`（DateTime）或值本身可否转换 |
| 数学计算得 NaN | 除零或运算异常；异常路径会 `Success=false` |
| 打开方案就炸 `InvalidCastException` | 枚举端口经 InputValues 往返——**已改为 string** |
| 永远报失败且错误信息为空 | 重复声明了基类 `Success`/`ErrorMessage`（CS0108 影子隐藏） |

## 4.2 P0/P1 级详解

### ① `IsRequired = false` 必须显式写（本工程最硬的一条）

**现象**：正常用法（界面手填参数、不连线）下，编译必然报 `[参数缺失] … 必填参数 Name/Value/CreateIfNotExists 未配置`，**这个节点等于用不了**。

**原因**：`InputPort.IsRequired` **默认就是 `true`**；而（旧版）编译期必填检查是「`IsRequired` 且没有连线来源」——**只看有没有连线，不看有没有填值**。

**修法**：三个端口显式写 `IsRequired = false`。

> 📌 **现状补充**：`FlowCompiler` 现已加 `hasConstant` 判据（**手填常量也算配置**），但 `IsRequired = false` 仍是正确写法。

### ② 枚举不能经 `InputValues` 往返

**现象**：方案一打开就炸——`InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'`。

**原因**：`InputPort<T>.Value` 的 setter 对枚举**只做硬转换**，不做"从数字/文本解析"。而本参数要经 `InputValues` 存盘（**枚举会序列化成 int**）。

**修法**：作用域用 **string** + 运行期白名单校验。

> 同一个坑在 `Plugin.ColorRegion` 的 `RoiShape` 上也踩过一次——那里同样改用 string。

### ③ CS0108：不要重复声明基类端口

**现象**：**永远报失败且错误信息为空**。

**原因**：基类已声明 `Success` / `ErrorMessage`，派生类重复声明会**影子隐藏**基类成员——插件写派生端口、引擎读基类端口。

**修法**：复用基类端口，不重复声明。

### ④ HALCON `#4056`：图像变量不能存值

**现象**：含图像变量的方案**保存时直接抛 `#4056 object-ID is NULL`，整个方案存不下来**。

**原因**：旧实现把 HImage 塞进 `VariableDto`，Newtonsoft 走 `serialize_image` → 句柄为空。

**修法**：图像变量**只存定义、不存值**——`Value`/`DefaultValue` 落 null，只保留名字/类型/稳定身份。代价：重启后画面无图。

### ⑤ 失败分支未 return → ErrorMessage 被洗空

**现象**：引擎日志里丢失失败原因。

**原因**：失败后没有 `return`，继续往下走把 `ErrorMessage` 清空了。

**修法**（注释原文）：
> ```
> return; // 必须短路：不 short-circuit 会在下一行把 ErrorMessage 洗成空
> ```

### ⑥ 延时从不写 `Success` → 每轮"真失败"

**现象**：延时节点每轮被标记为执行失败。

**原因**：只写了自家 `State.Value = true`，**从不写 `Success.Value`**。

**修法**（注释原文）：
> ```
> State.Value = true;
> // 框架契约：VisionPluginBase.Execute 以 Success.Value is true 判定业务成功，
> // 不置 true 会被引擎每轮标记"执行失败"（此前只写了自家 State 输出端口）
> Success.Value = true;
> ```

### ⑦ 变量池类型被污染（最难排查的静默故障）

**现象**：double 变量被塞进 string 后，**If/While 每次求值都抛异常、所有分支集体不走，但流程照常往下跑**。

**修法**：A2 类型守门——对齐既有类型：**可转换则转（记 Warn），不可转换显式失败**。
