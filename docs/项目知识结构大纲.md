## 二、模块关系大纲

### 2.1 依赖主干

```
Shard/Core.Interfaces
   ▲        ▲          ▲
   │        │          │
Core.Halcon  Core.Controls  Plugins
   ▲             ▲
   └── Core.Controls
          ▲
        VM.Core ──────► VM.Scada
          ▲
   ┌──────┴───────────────┐
Engine              Communication
   ▲                     ▲
   └────── VisionMaster ─┘
              ▲
        UI / Scada.Controls / Scada.Controls.Charts
```

> 注意：`VM.Core` 依赖 `VM.Scada` 与 `Core.Controls`；真正的最底层是 `Shard/Core.Interfaces`，不是 `VM.Core`。

### 2.2 运行时装配

| 顺序 | 模块 | 关键动作 |
|---|---|---|
| 1 | CommunicationModule | 加载 `communications.json`、启动连接 |
| 2 | FlowEngineModule | 注入 FlowInvoker、启动定时/变量触发 |
| 3 | HttpImageServerModule | 启动 HTTP 收图 |
| 4 | CameraModule | 自动连接相机、启动网络收图 |
| 5 | MotionModule | 轴解析、自动连接、状态发布 |
| 6 | IoModule | 应用 IO 配置、变量投影、健康监控 |

**顺序即启动/退出顺序**；退出任务逆序执行。

### 2.3 一条数据的路径

```
工具箱 → StepFactory → StepModel → FlowCompiler → CompiledNode
   → FlowSession → FlowEngineService → 插件 Execute
   → OutputPort → 下游 InputPort / 全局变量 / 网络变量
   → UI（INPC） / PLC（通信轮询） / SCADA（绑定）
```

## 三、关键概念地图

### 3.1 五个核心对象

| 对象 | 一句话 | 关键文件 |
|---|---|---|
| 方案 Solution | 一个完整工程，落盘 `.vms` | `Core/Models/SolutionModel.cs` |
| 流程 Flow | 运行最小单元，Home/Main/End 强制 | `Core/Models/FlowModel.cs` |
| 步骤 Step | 流程树节点 | `Core/Models/ProcessStep/StepModel.cs` |
| 插件 Plugin | 实现 `IVisionPlugin` 的算子 | `Shard/Core.Interfaces/IVisionPlugin.cs` |
| 变量 Variable | 本地/网络/系统/IO 数据 | `Core/Models/Variable/*` |

### 3.2 四个“容易混”的概念

| 概念 | 不是什么 | 是什么 |
|---|---|---|
| `StepCollection` | 不是算子 | 分支容器（If/Else/Case/循环体/并行分支），持有 `Steps` |
| `LinkKind` | 不是“显示名” | 连线语义：StepPort/GlobalVariable/RuntimeVariable/Constant |
| `FlowModel.Version` | 不是软件版本 | 流程语义版本，运行前触发重编译 |
| `LayoutSchemaVersion` | 不是布局文件版本号随便加 | 停靠结构指纹；面板归属/停靠语义变化才递增 |

### 3.3 三条“不要违反”的契约

1. **插件只依赖 `Core.Interfaces`**：不要引用 `VisionMaster`/`VM.Core`；需要宿主能力走 `IExecutionContext`。
2. **端口即字段**：参与数据流的参数用 `InputPort<T>`/`OutputPort<T>`；配置项用 `[StepConfig]`。
3. **方案是设备配置的唯一事实源**：通信/相机/运动/IO 配置随 `.vms` 走；机器级 `communications.json` 会被方案覆盖。

## 四、学习路径

### 阶段 0：跑起来（1～2 天）

**目标**：能构建、能运行、能打开示例方案。

- 读：`docs/项目全景说明.md` 第 1～4、10 章。
- 做：`dotnet build VisionMaster.sln` → 运行 → 打开 `解决方案/解决方案-20260829224154.vms` → 跑 MainTask。
- 验收：能指出工具箱/流程栏/画布/属性/日志/图像/变量面板；能说出方案/流程/步骤/插件/变量。

### 阶段 1：插件与流程（1 周）

**目标**：理解插件契约，写一个最小插件。

- 读：`IVisionPlugin`、`VisionPluginBase`、`InputPort/OutputPort`、`StepModel/StepCollection`、`docs/新插件端口速查.md`。
- 做：写 `HelloPlugin`（一个输入、一个输出、一个 `[StepConfig]` 参数），构建到 `Modules/`，拖出来跑通。
- 验收：解释 `ActualValue` vs `TypedValue`；解释 `[StepConfig]` 生成器；解释插件为什么不能引用宿主。

### 阶段 2：编译与执行（1～2 周）

**目标**：理解从步骤树到运行时的完整链路。

- 读：`FlowCompiler`、`CompiledFlow`、`CompiledNode`、`CompiledIfNode/While/For/Parallel`、`FlowEngineService`、`FlowSessionFactory`。
- 做：在 `FlowCanvasChecks` 加一条 If 流程断言；用调试器跟一遍 `RunSessionOnceAsync`。
- 验收：画出 `StepModel → CompileSteps → LinkPorts → CompiledFlow → RunSequence`；解释 `CurrentFlowState`/`Version`/`FlowSession`。

### 阶段 3：变量、通信、设备（1 周）

**目标**：理解变量镜像、通信轮询、相机/IO/运动装配。

- 读：`Core/Binding/*`、`Core/Models/Variable/*`、`Communication/Manager/*`、`NetworkVariableBridge`、`Modules/*`、`Core.Interfaces/{Camera,Io,Motion}/*`。
- 做：用 `tools/DeviceSimulator` 起 Modbus/S7 模拟器，配连接与网络变量；用 `CommChecks` 验证；用 `tools/VirtualCameraClient` 推图。
- 验收：解释“读镜像/写设备”；说出通信层与 IO 层边界；定位“变量不刷新”的三段链路。

### 阶段 4：UI 与 SCADA（1 周）

**目标**：理解 WPF/Prism/AvalonDock/Nodify/主题体系与 SCADA 运行态。

- 读：`Shell.xaml`、`ShellViewModel`、`LayoutHelper`、`ProcessViewModel`、`FlowCanvasViewModel`、`ScadaEditorViewModel`、`ScadaCanvas`、`UI/Controls/Themes/*`。
- 做：改一个主题令牌并跑 `UIThemeSmokeTest`；加一个 SCADA 图元并跑 `ScadaChecks`；用 `--render` 截图对照 UI 基线。
- 验收：解释停靠布局与 `CurrentLayoutSchemaVersion`；解释组态/非组态面板收敛；说出资源字典分册作用域规则。

### 阶段 5：工程化与交付（1 周）

**目标**：能独立构建、验证、打包、排障。

- 读：`pack.ps1`、`docs/code-changes/` 最近 10 篇、`AGENTS.md` 全部红线、`docs/软件手册.md` FAQ。
- 做：`pack.ps1 -Zip -Smoke` 打交付包；在干净目录启动；模拟“插件缺失/布局旧版/通信失败”排障。
- 验收：按 `docs/项目全景说明.md` 第 10.8 检查清单交付；说出启动/退出链顺序；解释“产物陈旧”类问题判据。

## 六、常见误区与检查清单

### 6.1 常见误区

| 误区 | 纠正 |
|---|---|
| “Core 是最底层” | 真正的最底层是 `Shard/Core.Interfaces`；`VM.Core` 依赖 `VM.Scada` 与 `Core.Controls`。 |
| “插件可以引用主程序” | 插件只引用 `Core.Interfaces`（UI 插件可加 `Core.Halcon/Core.Controls/UI`），不能引用 `VisionMaster`。 |
| “改了代码就生效” | 插件必须重建并投递 `Modules/`；生成器改动要重建全部插件；帮助 md 改动要 `--no-incremental`。 |
| “布局只是 UI 偏好” | `Layout.xml` 有结构版本；面板归属变化必须递增 `CurrentLayoutSchemaVersion`。 |
| “变量 Value 就是设备值” | 网络变量 `Value` 是轮询镜像；写设备用 `TryWriteToValue`。 |
| “通信层管所有设备” | 通信层管 PLC 地址/网络变量；IO 层管 DI/DO/AI/AO，走 `IIoDevice`。 |
| “并行就是 Task.WhenAll” | 并行分支有影子变量、FailFast、Join 超时、`[ParallelSafe]` 检查、调试退化。 |
| “断言绿了就全覆盖” | 断言宿主是自定义 gate；新闸要做变异反证，跳过型断言要能反证。 |

### 6.2 每次改动后的检查清单

- [ ] 构建通过（sln + 受影响插件单独构建）。
- [ ] 产物真的更新（DLL 时间戳/资源名；不能只看构建退出码）。
- [ ] 跑对应断言宿主（FlowCanvasChecks / ScadaChecks / CommChecks / IoChecks / UIThemeSmokeTest / HelpProbe）。
- [ ] 大改动补 `docs/code-changes/` 记录（背景/改动/证据/未决）。
- [ ] 公共契约/多模块改动走 architect→实现→reviewer→docs 闭环。
- [ ] 打包用 `pack.ps1 -Smoke` 验证交付目录。
