# 2026-09-27 变量绑定：按类型过滤候选 + 绑定判据归一

起因："插件端口绑定的时候会显示上游所有的变量，正常是不是应该只显示可以绑定 + 数据类型满足要求的变量列表"。

---

## 1. 改动前的样子

`VariableBindingViewModel` 里：

- `BuildTree()` 一次性把整棵候选树塞进 `TreeNodes`（不过滤）；
- `SelectedNode` setter 把该节点**所有**输出端口铺进 `DisplayPorts`（不过滤）；
- 类型检查**只在 `DoublockClickBind` 里**——也就是用户双击那一刻才弹"类型不匹配"。

即：**看得见、能点到、点下去才告诉你不行**。错误发现得太晚。

## 2. 为什么不是"完全隐藏不兼容项"

三点，都有依据：

1. **"类型满足"的口径比直觉宽**。`TypeHelper.IsTypeCompatible` 里 `target == string` 恒 true、
   数值互转恒 true、`object` 恒 true。所以过滤砍不掉几项；更要紧的是**必须复用这一个函数**，
   另写一套"类型相等"的判断会把 `int→double`、任意→`string` 这些合法绑定误杀。
2. **数组取索引是合法场景**。`DoublockClickBind` 里有 `outputType.IsArray && !targetType.IsArray` 分支——
   数组输出可以带索引绑到标量端口。只按 `IsTypeCompatible(double[], double)` 过滤会把
   `double[]→double` 这种**合法**绑定误杀。
3. **完全隐藏会造成"找不到"的困惑**。用户明明记得上游有个变量却看不到，第一反应是插件没暴露或流程没跑；
   而且单绑模式默认端口是 `System.Object`，几乎全兼容，会出现"有时过滤有时不过滤"的不一致感。

## 3. 落地的四条

### ① 判据归一：`TypeHelper.CanBindTo`

`Core/Helpers/TypeHelper.cs` 新增：

```csharp
public static bool CanBindTo(Type source, Type target)
{
    if (source == null || target == null) return false;
    // 数组 → 标量：允许"按下标取一个元素"（绑定时会弹索引输入框）
    if (source.IsArray && !target.IsArray)
        return source.GetElementType() is { } e && IsTypeCompatible(e, target);
    return IsTypeCompatible(source, target);
}
```

**UI 过滤与双击校验现在用的是同一个函数**——否则会出现"列表里放着、双击又说不匹配"的自相矛盾。
配套加了 `GetBindableElementType`（数组给元素类型、非数组给自身）。

### ② 默认只列可绑定项，且随端口联动

`RefreshDisplayPorts()` 按"当前选中输入端口的类型"过滤，触发点有两个：

- 换上游节点（`SelectedNode` setter）
- **换左侧输入端口**（`SelectedInputPort` setter）

第二个是必须的：只在换节点时算的话，会把"A 端口的过滤结果"残留到 B 端口上。

另外两点防御：
- `Type.GetType(DataTypeName)` 解析失败时退回 `typeof(object)`，此时一律放行——
  **绝不因为类型名解析不出而误杀本来能绑的项**；
- 判据写在**副本**上（`CloneForCandidate`），不写回节点持有的 `OutputDefinitions` 共享实例，
  否则换端口/换节点后会残留上一次的判定。

### ③ 不兼容项置灰 + 悬停看原因

`PortDefinition` 加两个展示字段（`IsBindable` 默认 true、`IncompatibleReason`），
视图里：

```xml
<Grid IsEnabled="{Binding IsBindable}"
      ToolTipService.ShowOnDisabled="True"
      ToolTipService.ToolTip="{Binding IncompatibleReason}">
    <Grid.Style>  <!-- IsBindable=false → Opacity 0.45 -->  </Grid.Style>
```

`IsEnabled=false` 会连带禁掉 `InputBindings`（双击不生效），
但也会让 ToolTip 不显示——所以必须开 `ShowOnDisabled`。

### ④ "显示全部"开关

`ShowAllPorts`（默认 false）。勾上后把不兼容项也列出来（灰着），
给高级用法留口子：object 端口、故意把任意类型塞进 string 端口做上报/显示。

## 4. 顺带修的一处口径不一致

`Confirm()` 的常量分支原先直接取 `SelectedInputPort.Definition.Name`，
而 `ResolveBindKey` / `DoFinalBind` 对**条件节点**用的是端口的 `Description`。
结果：条件节点填常量会落到错误的键上——表现为"填了值但读不回来"，且界面上看不出异常。

已统一走 `ResolveBindKey(...)`。

## 6. 已知边界

1. **视图未做实例化验证**。改动涉及 XAML（`IsEnabled` / `ToolTipService` / 新增 CheckBox），
   XAML 编译（BAML）能校验属性名与类型，但**运行期数据绑定未做自动验证**——
   冒烟是控制台，在里面 `new Application()` 会让进程退出时挂住（见 `2026-09-25-冒烟命令超时排障与规避.md`）。
   建议在宿主里手动打开一次变量绑定弹窗，确认：默认只剩能绑的项、勾选"显示全部"后不兼容项灰着且悬停有原因、双击灰项无反应。
2. **"类型满足"仍以 `IsTypeCompatible` 为准**，其中 `target == string` 恒 true 是有意放开（字符串化）。
   如果将来希望收紧这条，要连带评估依赖它的既有方案。
3. **过滤只作用于右侧端口列表**，左侧"输入端口"列表与上游节点树未做过滤（节点树按"能不能取到变量"组织，不是按类型）。
