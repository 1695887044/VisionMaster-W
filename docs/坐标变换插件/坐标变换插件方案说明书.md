## 约定（与配套插件共用，先读）

| 约定 | 内容 |
| --- | --- |
| 像素坐标 | `(Row, Col)`：Row 向下、Col 向右（与 HALCON 一致） |
| 机械坐标 | `(X, Y)`：单位毫米；轴方向/镜像/旋转由**九点标定的矩阵自然吸收**，插件不做任何额外假设 |
| 角度单位 | **度**（与模板匹配输出一致）；仅在调用 HALCON 算子时换算为弧度（×π/180） |
| 数组排布 | 多点数组一律 `[x0, y0, x1, y1, ...]`（x 在前、y 在后，成对） |
| 矩阵语义 | `CalibrationTransform.Matrix`（6 元）= 映射 **(Row, Col) → (X, Y)**，HALCON 6 元排布（`X=a11·Row+a12·Col+a31`） |
| 失败纪律 | 沿用仓库纪律：能报的错必须报出"下一步"；失配（尺寸/类型/缺失）必须**明确失败**，绝不静默用旧标定 |

> **配套插件** ← [标定插件方案说明书](../标定插件/标定插件方案说明书.md)：本插件的 `Transform` 输入端口接它的输出。实施顺序：**先落它定义的 `CalibrationTransform` 契约，再做本插件**。

## 一、背景与目标

**现状（证据）**

- 上游位姿**已就绪**：模板匹配输出 `Row`/`Column`/`Angle`（double，**单位：度**，`MatchingPlugin.cs:204`）与多目标 `Rows`/`Columns`/`Angles`（HTuple，`:220`）；
- 但**没有一等算子**把位姿作用到 ROI / 坐标上：全仓 `affine_trans_* / vector_angle_to_rigid / hom_mat2d_*` 只出现在**脚本算子文档**（`OperatorDoc.cs:692-747`）与**脚本模板**（`ScriptTemplates.cs:195/420`）里——即"能做，但用户得自己写代码"；
- 脚本模板还在教用户"Row/Column 是像素，发给机器人前**必须过手眼标定矩阵换算**"——这句话说明：**像素→机械的换算今天是靠脚本手写的**；
- 消费侧就绪：BlobDetect 有 `MaskRegion`(HRegion) 输入（可被"跟随后的区域"驱动）、CreateRoi 有 `MaskRegion`(HRegion) 输出（可作为"基准 ROI"）。

**目标（一期）**

1. **位姿跟随**：`基准 ROI × 当前位姿 → 当前 ROI`（输出 HRegion；可选输出按位姿对齐的图像）；
2. **像素 → 机械坐标**：接上标定，把匹配的 Row/Col（+角度）换成机械 X/Y/θ（**引导/纠偏的最后一公里**）；
3. **机械 → 像素**：反向回显（HMI 校验、把机械坐标画回图上）；
4. **失配检测**：标定缺失/类型不对/图像尺寸不符 → **明确失败**，绝不用旧标定默默算错。

**非目标（一期）**：多目标（HTuple）批量换算、把卡尺/颜色/OCR 的"内部 ROI"改成可被位姿驱动（跨插件改造，二期单独立项）、透视/畸变类变换（属标定二期）。

## 二、关键设计决策

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 与 `Matching.AlignedImage` 的分工 | **两者并存、各管一段**：`AlignedImage` = 把目标**重采样**成标准位姿的新图（适合"内部 ROI 固定"的算子：卡尺/颜色/OCR）；**本插件跟随** = 保留原图坐标，只变换 ROI/点（适合 BlobDetect.MaskRegion、机器人引导、多特征测量）。文档与界面都要写明，避免"两个都能用却选错" | 重采样有插值损失、且丢失原坐标映射；引导场景必须拿**原始坐标**下的位姿 |
| 2 | 端口类型必须与上游**严格一致** | 一期只做单目标 `double`（`Row/Column/Angle`）；多目标 `HTuple` 二期 | 端口赋值走 `ValueConverter`，`double` 与 `HTuple` 不能互转——类型不对就是"接不上"，硬凑会导致运行期静默拿不到值 |
| 3 | 标定从哪来 | 只能**接标定插件的输出端口**（`CalibrationTransform`），不允许手填矩阵 | 单一事实源：手填矩阵等于绕开标定与其质量校验 |
| 4 | 跟随要不要图 | 跟随**只需要区域**；"输出对齐图"是**可选开关**（默认关） | 少一次重采样、少一次内存拷贝；需要时才付代价 |
| 5 | 机械坐标的方向/镜像 | **不做任何假设**：轴交换、镜像、旋转全部由九点标定矩阵吸收 | 各现场机械轴定义不同；插件里再"校正"一次必然出现"负负得正"的错 |
| 6 | 位姿无效（NaN/全零） | 明确失败："位姿无效——匹配是否成功？" | 匹配失败时下游常拿到 0/NaN；静默变换会产出"看起来正常"的错坐标 |
| 7 | 工程位置 | 插件工程放 `Plugins\` 下 | 同标定方案：`Directory.Build.targets` 靠目录投递 `Modules\` |

## 三、契约与端口

**模式（`[StepConfig] Mode`）**：`FollowRoi`（位姿跟随） / `ToMechanical`（像素↔机械）。

### 3.1 FollowRoi 模式

| 方向 | 端口 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| IN | `SrcImage` | HImage | 否 | 用于①像素尺寸失配校验（可选）②输出对齐图 |
| IN | `BaseRegion` | HRegion | ✅ | 基准 ROI（接 `CreateRoi.MaskRegion`）——**在模板图上画的那个 ROI** |
| IN | `TemplateRefRow` / `TemplateRefCol` | double | ✅ | 模板参考点（模板坐标系里"位姿原点"对应的像素位置）；配置页可「取基准 ROI 中心」一键填 |
| IN | `PoseRow` / `PoseCol` / `PoseAngle` | double | ✅ | 当前位姿（接 `Matching.Row/Column/Angle`；**角度单位=度**） |
| OUT | `FollowedRegion` | HRegion | — | 当前坐标系下的 ROI（接 `BlobDetect.MaskRegion`） |
| OUT | `FollowedImage` | HImage | — | 可选：按同一变换重采样后的图（`EmitFollowedImage=true` 时输出；未接 `SrcImage` 时输出 null 并记 Info 日志） |

### 3.2 ToMechanical 模式

| 方向 | 端口 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| IN | `Transform` | `CalibrationTransform` | ✅ | 接标定插件输出 |
| IN | `PixelPointRow` / `PixelPointCol` | double | ✅ | 待换算的像素点（接 `Matching.Row/Column`，即"目标中心"） |
| IN | `PixelAngle` | double | 否 | 像素系角度（度）；接了才输出 `MechanicalAngle` |
| OUT | `MechanicalX` / `MechanicalY` | double | — | 机械坐标（mm）——接运动节点/数据记录/结果上报 |
| OUT | `MechanicalAngle` | double | — | 机械系角度（度）——抓取/贴合要有它 |
| OUT | `PixelEchoRow` / `PixelEchoCol` | double | — | 反向回显：把机械坐标再算回像素（自校验；偏差应 < 1e-9） |

**`[StepConfig]`**：`Mode`、`EmitFollowedImage`(bool，默认 false)、`TemplateRefFromRegionCenter`(bool，默认 true：打开时 `TemplateRef*` 由基准 ROI 中心派生，避免手填两张数)。

## 四、运行语义（含三类失配的强制失败）

| 条件 | 结果 |
| --- | --- |
| `Transform == null`（未接线） | ❌ "未接标定：请把「标定」插件的 `Transform` 输出接到本步骤" |
| `Transform.Kind == PixelScale` 却要机械坐标 | ❌ "当前标定只有像素当量、不含机械坐标；引导类场景请用**九点标定**" |
| `SrcImage.Width/Height != Transform.SourceImageWidth/Height` | ❌ "标定与当前图像尺寸不符（标定时 2448×2048，当前 1280×1024）——换分辨率/换相机后需**重新标定**" |
| `Transform.CreatedAtUtc` 早于方案里相机的"最后修改"？ | ⚠ 一期：只把时间打在日志里（不判失败）；三期可做"相机参数变了提醒重标" |
| `BaseRegion` 为空/未初始化 | ❌ "基准 ROI 为空：请把 ROI 插件的 `MaskRegion` 接过来（并在模板图上画好基准）" |
| 位姿为 NaN/Inf | ❌ "位姿无效（NaN）——请检查模板匹配是否成功" |
| 成功 | 输出上述端口 + Info 日志（跟随：面积变化% / 换算：机械坐标） |

沿用仓库纪律：**能报的错必须报出"下一步"**；失败时输出端口保持开轮清零值（下游不会读到上一轮残留）。

## 五、配置界面（`PoseTransformView`）

单页，上下两块：

- **模式选择**（FollowRoi / ToMechanical）+ 各自的可链接参数行（端口绑定用现成 `LinkableValueEditor`）；
- **预览区**（有图时）：叠加显示 **基准 ROI（绿）** 与 **跟随 ROI（橙）**，并画 `TemplateRef` 点（十字标记）——一眼看出"基准在哪、跟到哪"；预览复用图像采集插件的状态栏约定（`StatusLevel` 分级文案）；
- **标定信息只读块**（`ToMechanical` 模式）：来源标签 / 创建时间 / 残差 / 标定图尺寸——**失配时红字提示**（"当前图 1280×1024 ≠ 标定图 2448×2048"）；
- 「执行」试运行：走的就是正式运行同一段代码（沿用宿主既有基建）。

## 六、实现要点

1. **跟随（唯一公式，直接复用仓库既有范式）**
   ```
   vector_angle_to_rigid(TemplateRefRow, TemplateRefCol, 0,
                         PoseRow, PoseCol, PoseAngle * π/180,
                         out HomMat2D)          // 角度：插件侧是度，HALCON 侧是弧度
   affine_trans_region(BaseRegion, out FollowedRegion, HomMat2D, "nearest")
   affine_trans_image (SrcImage,   out FollowedImage,  HomMat2D, "bilinear", false)   // 可选
   ```
   这条公式在 `Plugins\Plugin.ImageScript\ScriptTemplates.cs:420` 已有**脚本版范式**（`vector_angle_to_rigid(RefRow, RefCol, 0, Row1, Col1, Angle, HomMat2D)`），本方案只是把它提升为一等算子。
2. **自检（写进验收）**：当位姿=模板态（`PoseRow/Col = TemplateRefRow/Col` 且 `PoseAngle = 0`）时，`FollowedRegion` 必须与 `BaseRegion` **完全重合**（面积相对差 < 1e-6）——这是最直观的"公式没写反"的证明。
3. **应用标定（点变换）**：矩阵语义已在契约里写死（`X = a11·Row + a12·Col + a31`）。实现两种等价方式：纯托管展开（推荐，可断言）或 HALCON `affine_trans_point_2d(HomMat2D, Row, Col, out X, out Y)`——**注意入参是 (Row, Col)**：写成 (Col, Row) 会静默产出离谱坐标（转置错），断言第 1 条就是为抓它。
4. **角度换算**：不要手推三角函数。取图像 x 轴单位向量 `(Row=0, Col=1)` 经同一变换求方向角，与基准方向作差得 Δθ（或参照 `hom_mat2d_to_affine_par` 的 `phi` 分量，见 `OperatorDoc.cs:744`）。验收用"合成旋转 30°"断言锁死。
5. **反向回显**：2×2 线性部分求逆再减平移；行列式近零 → 明确失败（复用标定的共线文案）。
6. **纯托管边界**：`PoseTransformMath.cs`（正向/反向点变换、角度、失配判定）只吃 `double[]`/基元 → 断言可完整覆盖；HALCON 只出现在"区域/图像变换"这一步。

## 七、验证计划

**单元/断言（新增 `FlowCanvasChecks\PoseTransformChecks.cs`）**

| # | 断言 | 判据 |
| --- | --- | --- |
| 1 | 合成标定下的正变换与手算一致 | 造"旋转+缩放+平移+轴交换"矩阵 → 任取点 → 与手算误差 < 1e-6 |
| 2 | 反向互逆 | `T⁻¹(T(p))` 误差 < 1e-9（也即 `PixelEcho*` 回显自校验） |
| 3 | 角度换算正确 | 合成"旋转 30°" → `MechanicalAngle ≈ 30°`（±1e-3） |
| 4 | 三类失配全部失败 | 未接标定 / 当量标定当九点用 / 图尺寸不符 → 均失败且文案含"下一步" |
| 5 | 跟随：姿态敏感 | 正方形基准 ROI + `PoseAngle=90°` → 外接框宽高互换（相对误差 < 1e-6） |
| 6 | 跟随：模板态自洽 | 位姿=模板态 → 与基准 ROI 重合（面积相对差 < 1e-6） |
| 7 | 空 ROI / NaN 位姿必须失败 | 不是静默输出空区域/零坐标 |
| 8 | 端口类型面 | `Transform` 端口 DataType = `CalibrationTransform`（换名字要断链，断言锁住） |

**端到端（组合验收，交付时执行）**：`图像采集 → 模板匹配 → 坐标变换(ToMechanical) → 数据记录`，输出机械坐标与示教器/手算一致（±0.5mm 或 ±1 像素当量，取大者）。

## 十、风险与边界

- **只服务"能吃 HRegion / 点位"的下游**：卡尺、颜色、OCR 的 ROI 是插件内部配置，一期**不受本插件影响**——它们的跟随场景继续走 `Matching.AlignedImage`（文档要把这条写进界面说明，否则用户会问"为什么我的卡尺不跟着走"）。
- **机械轴方向不做假设**：轴交换/镜像/旋转由九点标定矩阵吸收；本插件只做"矩阵作用 + 失配检测"（画蛇添足的"方向校正"是历史上最常见的一类静默错误）。
- **基准 ROI 必须画在"模板图"上**：画在别的图上 → 跟随结果系统性偏移；验收第 6 条（模板态自洽）就是这条约束的守卫。
- **一期单目标**：多目标、多相机等按需进二期；不预埋复杂端口（端口面越简单，"接错"的机会越少）。
