# 第 0 章 这是什么

**坐标变换 = 定位模块的"翻译官"与"跟随器"：把"目标在图上哪、转了多少度"变成下游真正能用的两样东西——跟着目标走的 ROI，和机床坐标系里的 X/Y/θ。**

> 生活比喻：向导只说"敌人在我左前方 30°"没用，炮手需要的是"坐标 (X, Y) 与射向角"。翻译这一步不做，信息就永远是"图上的信息"；做了，下游（机器人抓取、纠偏、测量）才能直接用。

**上游其实早就把"位姿"算出来了**——模板匹配输出 `Row` / `Column` / `Angle`（度）——但仓库里**没有一等算子**把它作用到任何东西上：

| 现状 | 出处 |
|---|---|
| `affine_trans_*` / `vector_angle_to_rigid` / `hom_mat2d_*` 只出现在**脚本算子文档**与**脚本模板**里 | `OperatorDoc.cs:692-747`、`ScriptTemplates.cs:195/420` |
| 脚本模板教用户"Row/Column 是像素，发给机器人前必须过手眼标定矩阵换算" | 即：换算靠**手写脚本** |
| 消费侧已就绪：BlobDetect 有 `MaskRegion`(HRegion) 输入；CreateRoi 有 `MaskRegion` 输出 | 本插件把两边接起来 |

本插件补的就是这座桥：**定位位姿 → 跟随 ROI / 机械坐标**。

它在流程里的位置（分组「定位」）：

```
[创建 ROI]（模板图上画基准 ROI）──MaskRegion──┐
[Matching] ──Row/Column/Angle───────────────┼──→ [坐标变换] ──FollowedRegion──→ [BlobDetect].MaskRegion
[标定] ──Transform（CalibrationTransform）──┘         ├──MechanicalX/Y/θ──→ [运动控制]/[数据记录]/[结果上报]
                                                      └──PixelEchoRow/Col─→（自校验）
```

**两个模式，一句话区分**：

| 模式 | 输入 | 产出 | 典型场景 |
|---|---|---|---|
| **位姿跟随** | 基准 ROI + 当前位姿（+可选参考图） | `FollowedRegion`（当前坐标系 ROI，可选对齐图） | 目标会转/会挪，但 Blob 检测区要跟着走 |
| **像素→机械** | 标定 + 像素点（+可选角度） | `MechanicalX/Y`（+`MechanicalAngle`） | 机器人抓取、纠偏、把测量结果落到机床坐标系 |

> 本插件同时是「标定」插件的**验收工具**：标定好不好，用它回算机械坐标就知道（见 3.4 第 5 步）。

# 第 1 章 设计思想

## 1.1 核心原理：刚体变换作用在"区域"或"点"上

位姿跟随的公式只有一条（与仓库脚本范式 `ScriptTemplates.cs:420` 完全一致）：

```
vector_angle_to_rigid(模板参考点, 0°, 当前位姿) → HomMat2D     // 模板坐标系 → 当前坐标系
affine_trans_region(基准 ROI, HomMat2D)        → 当前坐标系下的 ROI
```

含义：基准 ROI 是**在模板图上**画的（模板坐标系）；`HomMat2D` 是"从模板参考位姿出发、转到当前位姿"的刚体变换；把它作用到基准 ROI，就得到"目标现在在哪、ROI 就该在哪"。

**自检（写进验收）**：当位姿 = 模板参考点且角度 0（即"目标就在学习时的位置"）时，`HomMat2D` 是恒等变换——`FollowedRegion` 必须与 `BaseRegion` **完全重合**（回归断言：面积相对差 0）。

## 1.2 与「模板匹配」输出对齐图的分工（最重要的选型表）

Matching 插件也有一个"位姿相关"的输出 `AlignedImage`，与本插件的跟随**两者并存、各管一段**——选错会绕远路：

| 维度 | Matching.`AlignedImage` | 本插件「位姿跟随」 |
|---|---|---|
| 做什么 | 把目标**重采样**成标准位姿的**新图** | **保留原图坐标**，只变换 ROI/点 |
| 代价 | 每帧一次图像重采样（插值损失 + 内存拷贝） | 只变换区域（轻） |
| 适合 | "内部 ROI 固定"的算子：卡尺/颜色/OCR（它们的 ROI 在你自己的配置里，只能吃对齐后的图） | `BlobDetect.MaskRegion`、机器人引导、多特征测量 |
| 不适合 | 引导场景（重采样丢原坐标映射） | 卡尺/颜色/OCR（它们的内部 ROI 一期不可被位姿驱动） |

> **FAQ 见 3.7 Q1**："为什么我的卡尺不跟着走？"——一期就该走 AlignedImage；把卡尺改成可被位姿驱动是跨插件改造，单独立项（二期）。

## 1.3 三条设计原则

**原则①：失配必须明确失败，绝不用旧标定默默算错**

三类失配（未接标定 / 当量标定当九点用 / 图尺寸不符）+ 位姿守卫（NaN/全零）都会**失败并给出下一步**。标定是"设备属性"，换了相机/镜头/分辨率而流程还在用旧标定，是这个领域最典型的静默错。

**原则②：不做任何"方向校正"**

机械轴方向、镜像、旋转**全部由九点标定矩阵吸收**；本插件只做"矩阵作用 + 失配检测"。在插件里再"校正"一次，必然出现"负负得正"的错——这类错误在历史上是最难查的一族。

**原则③：分层——数学纯托管、HALCON 只管区域/图像**

`PoseTransformMath` 只吃基元类型（可被断言完整覆盖：手算常量钉方向）；HALCON 只出现在 `PoseTransformHalcon` 的两个函数里（区域/图像变换）。角度换算只在这一层做：**插件侧一律"度"，HALCON 侧要"弧度"**。

## 1.4 角度配方（图像角度 → 机械角度）

不手推三角函数，用"方向向量作差"（方案 §六·4）：

```
① 图像 x 轴方向 (Row=0, Col=1) 经矩阵线性部分映射 → 基准方向角 φ0
② 目标在图像里转 θ：方向向量 (Row=sinθ, Col=cosθ) 同样映射 → φ(θ)
③ 机械角 = φ(θ) − φ0（归一化到 (−180, 180]）——目标没转时严格为 0
```

**镜像/轴交换的标定会让转角取反**：这是矩阵的自然结果（手性翻转），**不再额外校正**。回归断言把两类都钉死（保向 30°→30°；轴交换 30°→−30°）。

## 1.5 配置态 / 运行态与"叠加预览只在窗口开着时刷新"

- 位姿跟随的配置态叠加预览（基准绿 / 跟随橙 / 参考点黄）由视图挂接驱动：`OnViewAttached` 时刷新、`OnViewDetached`（对话框关闭）后不再刷新——不给"没人看的图"做重采样；
- 运行实例执行的永远是正式代码路径（`RunAlgorithm`），预览只是它的可视化。

## 1.6 配置项写法：源生成器（新约定）

`[StepConfig]` 属性采用**源生成器**写法（同「标定」插件；约定与红线见 `AGENTS.md` R18）：

```csharp
[StepConfig, DefaultValue(TransformMode.FollowRoi)]
public partial TransformMode Mode { get; set; }

partial void OnModeChanged(TransformMode value) => RefreshConfigState();
```

## 2.2 端口完整清单（11 入 7 出，全部固定端口，无动态端口）

### 输入（11 个）

| 端口 | 类型 | 何时必填 | 说明 |
|---|---|---|---|
| `SrcImage` | HImage | 否 | 参考图：①ToMechanical 的**图像尺寸失配校验** ②FollowRoi 的**输出对齐图**；不接也能工作 |
| `BaseRegion` | HRegion | FollowRoi | 基准 ROI（接 CreateRoi 的 `MaskRegion`）——**画在模板图上的那个 ROI** |
| `TemplateRefRow` / `TemplateRefCol` | double | FollowRoi* | 模板参考点（模板坐标系里的"位姿原点"）；*默认由基准 ROI 中心派生，无需手填 |
| `PoseRow` / `PoseCol` | double | FollowRoi | 当前位姿（接 Matching 的 `Row`/`Column`） |
| `PoseAngle` | double | FollowRoi | 当前位姿角度（**度**，接 Matching 的 `Angle`） |
| `Transform` | `CalibrationTransform?` | ToMechanical | 标定（接「标定」插件的输出；**不允许手填矩阵**——单一事实源） |
| `PixelPointRow` / `PixelPointCol` | double | ToMechanical | 待换算的像素点（接 Matching 的 `Row`/`Column`，即目标中心） |
| `PixelAngle` | double | 否 | 像素系角度（度）：**接了（或有非零值）才输出 `MechanicalAngle`** |

### 输出（7 个）

| 端口 | 类型 | 说明 |
|---|---|---|
| `FollowedRegion` | HRegion | 位姿跟随后的 ROI（接 BlobDetect 的 `MaskRegion`） |
| `FollowedImage` | HImage | 可选：按位姿**反向重采样回模板参考位姿**的"对齐图"（`EmitFollowedImage=true` 时输出；未接 SrcImage 时输出 null 并记 Info 日志） |
| `MechanicalX` / `MechanicalY` | double | 机械坐标（mm）——接运动节点 / 数据记录 / 结果上报 |
| `MechanicalAngle` | double | 机械系角度（度）——抓取/贴合要有它 |
| `PixelEchoRow` / `PixelEchoCol` | double | **反向回显**（自校验）：把机械坐标再算回像素；偏差 > 1e-6px 即失败 |

## 2.4 运行语义与失败文案总表

**位姿跟随（FollowRoi）**：

| 条件 | 结果 |
|---|---|
| 基准 ROI 未接/未初始化 | 失败：基准 ROI 为空：请把 ROI 插件的 MaskRegion 接过来（并在模板图上画好基准） |
| 基准 ROI 是空区域（面积 0） | 失败：基准 ROI 是空区域（面积为 0）：请检查基准 ROI 的绘制（要画在模板图上） |
| 位姿 NaN/Inf | 失败：位姿无效（NaN/Inf）——请检查模板匹配是否成功（或上游位姿来源） |
| 位姿全 0 | 失败：位姿为 (0,0,0)：多半是模板匹配失败或位姿未接——请检查上游位姿来源 |
| 手填参考点为 (0,0)（关闭派生时） | 失败：模板参考点为 (0,0)：请点「取基准 ROI 中心」或手工填写实际参考点 |
| 成功 | 输出 `FollowedRegion`；勾了 `EmitFollowedImage` 且接了 SrcImage 时再输出 `FollowedImage`；Info 日志带**面积变化 %**（跟随 ROI 相对基准的面积；正视平面应为 ~0%，明显偏离提示位姿可疑） |

**像素→机械（ToMechanical）**：

| 条件 | 结果 |
|---|---|
| 未接标定 | 失败：未接标定：请把「标定」插件的 Transform 输出接到本步骤 |
| 标定是 PixelScale | 失败：当前标定只有像素当量、不含机械坐标：坐标换算请用九点标定（像素当量模式只给 mm/px） |
| 标定矩阵缺失/退化 | 失败：标定数据损坏（矩阵缺失或退化）：请重新运行「标定」步骤 |
| （接了 SrcImage 时）图尺寸 ≠ 标定尺寸 | 失败：标定与当前图像尺寸不符（标定时 2448×2048，当前 1280×1024）——换分辨率/换相机后需重新标定 |
| 像素点 NaN/Inf | 失败：待换算的像素坐标无效（NaN/Inf）——请检查上游（模板匹配是否成功） |
| 像素点为 (0,0) | 失败：待换算的像素点为 (0,0)：多半是模板匹配失败或未接——请检查上游位姿来源 |
| 回显偏差 > 1e-6px | 失败：反向回显不一致（偏差 X px）：标定矩阵可能已损坏，请重新标定 |
| 角度接了但为 NaN/Inf | 失败：像素角度无效（NaN/Inf）——请检查上游角度来源 |
| 成功 | 输出 `MechanicalX` / `MechanicalY`（+接了角度的 `MechanicalAngle`）与 `PixelEchoRow/Col`；Info 日志：`像素 (r,c) → 机械 (x,y)mm，机械角 θ°` |

**其它语义**：无阻塞操作（无取消分支）；失败时输出端口保持**开轮清零值**（下游读不到上一轮残留）；幂等（同一输入同一输出）。

## 2.5 算法与算子链

### 数学层（`PoseTransformMath.cs`，纯托管）

| 函数 | 行 | 要点 |
|---|---|---|
| `CheckCalibrationUsable` | 35 | 三类失配①②（null / PixelScale / 矩阵损坏），文案常量固定 |
| `CheckImageSizeMatch` | 64 | 失配③；标定未记录尺寸（0）时放行（无从比对，不误报） |
| `IsValidPose` | 82 | NaN/Inf 与全零两类守卫 |
| `IsUsablePixelPoint` | 102 | 同口径的像素点守卫（(0,0)/NaN） |
| `TryMapPixelToMechanical` | 126 | `X=a11·Row+a12·Col+a31`、`Y=a21·Row+a22·Col+a32` |
| `TryMapMechanicalToPixel` | 148 | 2×2 线性部分求逆；det 近零 → 明确失败 |
| `TryPixelAngleToMechanical` | 193 | 方向向量作差配方（1.4） |
| `NormalizeDegrees` | 233 | 归一化到 (−180, 180] |

### HALCON 层（`PoseTransformHalcon.cs`）

| 函数 | 行 | 算子链 |
|---|---|---|
| `FollowRegion` | 21 | `vector_angle_to_rigid(参考点,0 → 位姿,θ)` + `affine_trans_region(…, "nearest_neighbor")` |
| `FollowImageBack` | 44 | `vector_angle_to_rigid(位姿,θ → 参考点,0)`（**逆变换**）+ `affine_trans_image(…, "bilinear", "false")` |

> **参数顺序踩坑（实测，`MatchingPlugin.cs:1577` 有记录）**：`affine_trans_image` 的参数是 `(HomMat2D, Interpolate, AdaptImageSize)`；写成 `(hom, "false", "constant")` 会报 `#3147 Wrong interpolation mode`。"false" = 输出与输入同幅面（目标回参考位姿、画幅不变），出界部分填黑。

### 回显自校验

成功路径自动把机械坐标**反算回像素**并与输入比较（偏差 > 1e-6px 失败）。这样"矩阵损坏/实现写错"当场露馅，而不是等到机器人抓偏了才发现。

## 2.6 对齐图方向：T vs T⁻¹（实现勘误，务必看懂）

**区域在模板坐标系，图在当前坐标系**——"同一变换"对两者的作用方向是**互逆**的：

| 对象 | 用哪个方向 | 为什么 |
|---|---|---|
| `BaseRegion`（画在模板图上） | **T**（模板 → 当前） | 区域坐标本来就是模板坐标系，正变换把它"搬到"当前 |
| `SrcImage`（当前拍到的图） | **T⁻¹**（当前 → 模板） | 要"对齐回参考位姿"，就是把当前图反向搬回去 |

**写反的后果**：对图也用 T，内容会被推离参考位姿**两倍偏差**——"看着像跟反了"。回归断言用合成图锁死：亮点在 (100,50)、参考点 (60,60)，对齐后亮点必须回 (60,60)（写反会到 (140,40)）。

## 2.7 资源所有权与生命周期

- `FollowedRegion` / `FollowedImage` 的 HRegion/HImage 所有权**移交端口**，基类每轮开头/Dispose 回收；
- double 输出（`MechanicalX/Y`、`MechanicalAngle`、`PixelEchoRow/Col`）**每轮开头清零**（基类只管 IDisposable，不清标量）；
- 配置态预览底图由插件持有（`SetPreviewImage` 释放旧的）；异步读图有轮次号守卫；
- 重叠预览的中间 HALCON 对象统一登记后集中释放（`PaintXldOn` 模式）。

## 3.3 第一次「位姿跟随」（8 步）

1. **在模板图上画基准 ROI**：用「创建 ROI」在**模板图/学习图**上框好检测区域（这一步最容易错——画在别的图上会系统性偏移）；
2. 「坐标变换」模式选**位姿跟随**；
3. 接输入：`BaseRegion` ← CreateRoi 的 `MaskRegion`；`PoseRow/Col/Angle` ← Matching 的 `Row`/`Column`/`Angle`；
4. （可选）载入预览图：⑥ 卡片「浏览」选一张模板图——画布上出现**绿色基准轮廓**与**黄色参考点十字**；
5. 试运行（或跑整条流程）给一组有效位姿——画布上出现**橙色跟随轮廓**；位姿=模板态时与绿框重合（自检）；
6. 看信息栏：`跟随面积 …（相对基准 ±X%）`——正视平面应接近 0%，明显偏离提示位姿可疑；
7. 下游接线：`FollowedRegion` → BlobDetect 的 `MaskRegion`；
8. 需要"标准位姿图"给内部 ROI 固定型算子时：勾**输出对齐图**、把 `SrcImage` 接上图像源（否则输出 null 并记日志）。

## 3.4 第一次「像素→机械」（7 步）

1. 模式选**像素→机械**；
2. `Transform` ← 「标定」插件的 `Transform` 输出（**只能这样来**——不允许手填矩阵）；
3. `PixelPointRow/Col` ← Matching 的 `Row`/`Column`；角度需要时 `PixelAngle` ← Matching 的 `Angle`；
4. （建议）`SrcImage` 接图像源——让"换分辨率忘重标"当场失败而不是算错；
5. 看⑤标定信息块：来源/相机/尺寸/残差是否对得上当前相机（红字=已失配）；
6. 试运行：看 `MechanicalX/Y`（+`MechanicalAngle`）与 `PixelEchoRow/Col`——**回显必须回到原点**（自校验）；
7. 下游接线：`MechanicalX/Y/θ` → 运动控制 / 数据记录 / 结果上报。

> **回算验收（「标定」的现场三步第 3 步）**：拿 3 个已知机械位置的特征点，经本插件换出 X/Y，与示教器读数比对（±0.5mm 或 ±1 像素当量，取大者）。

## 3.6 FAQ

**Q1：为什么我的卡尺/颜色/OCR 不跟着走？**
它们的一期 ROI 是插件内部配置、不可被位姿驱动。这类"内部 ROI 固定"的算子请用 **Matching.AlignedImage**（重采样成标准位姿的图）；本插件的跟随服务的是能吃 `HRegion`/点位的下游（BlobDetect、机器人引导、多特征测量）。把卡尺等改成可被位姿驱动是二期跨插件改造。

**Q2："基准 ROI 必须画在模板图上"是什么意思？**
基准 ROI 的坐标是**模板坐标系**里的坐标（跟随公式从"模板参考位姿"出发）。画在别的图上 → 基准本身就偏了 → 跟随结果系统性偏移。回归断言"模板态自洽"就是这条约束的守卫。

**Q3：为什么位姿 (0,0,0) 会直接失败？**
匹配失败时下游常拿到 0/NaN。静默变换会产出"看起来正常"的错 ROI/错坐标；坐标 (0,0) 又在图像角上，正常目标不可能在那——所以全零与 NaN 一样按"无效"处理（附处置提示）。

**Q4：机械角怎么可能是负的？像素角 30° 怎么机械角变成 −30°了？**
标定含镜像/轴交换（手性翻转）时，转角符号会翻转——这是数学事实，由矩阵自然吸收。**不要**在配置里"校正"它；要验证就用回算比对示教器。

**Q5：多目标（HTuple）怎么办？**
一期只做单目标 `double`（端口类型与上游严格一致，硬凑 HTuple 会运行期静默拿不到值）。多目标是二期（输出数组 `[x0,y0,x1,y1,…]`）。

**Q6：对齐图和对齐前原图的关系？**
`FollowedImage` 是把**当前图**反向重采样回模板参考位姿：目标回到"学习时的位置"、画幅不变、出界填黑。它等价于"自己算一遍 AlignedImage"——已有 Matching.AlignedImage 时**不必**在这里再开。

## 3.7 现场排障

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 运行失败"未接标定…" | `Transform` 没接 | 按提示接「标定」输出 |
| 运行失败"当前标定只有像素当量…" | 用了 PixelScale 标定做机械换算 | 重标一份九点标定 |
| 运行失败"标定与当前图像尺寸不符" | 换分辨率/换相机没重标 | 重新标定（这正是它该失败的时候） |
| 运行失败"位姿为 (0,0,0)/位姿无效" | 匹配失败 / 位姿没接 | 查上游匹配（分数太低？模板没学？） |
| 画布上只有绿框没有橙框 | 位姿未就绪 | 给位姿一个有效值或试运行一次 |
| 跟随后 ROI 明显偏 | ① 基准 ROI 画在非模板图上 ② 参考点不对 ③ 位姿来源不是同一坐标系 | 看 3.3 第 1/5 步；用"模板态自洽"自检 |
| Blob 检测区尺寸对但位置不对 | 基准 ROI 与模板学习坐标不一致 | 在模板图上重画基准再跟随 |

## 4.2 断言抓到：直调路径的 `Success/ErrorMessage` 残留

**现象**：断言逐条揭示——值都对（机械坐标 (405,307)、机械角 30°），但 `Success` 停在上一轮的 `false`、`ErrorMessage` 还是上一轮的"尺寸不符/位姿为 0"。

**根因**：基类只在 `Execute` 里预置 `Success=true` / 清 `ErrorMessage`；插件自身没在 `RunAlgorithm` 轮首重置。走 `Execute` 的生产路径不受影响，但**直调路径**（断言、框架类调用）语义不一致——错误信息会张冠李戴。

**修法**：`RunAlgorithm` 轮首 `Success.Value = true; ErrorMessage.Value = string.Empty;`（与基类预置一致）。

**证据**：修后 `[PT]` 39/39 全绿。

## 4.3 实现勘误：对齐图方向（T⁻¹）

方案 §六 的公式块对区域与图像都写了正变换 T。实现时判定：**区域在模板坐标系（正变换对）；图在当前坐标系（必须 T⁻¹）**，否则内容被推离参考位姿两倍偏差。已按正确方向实现，并用合成图断言锁死（亮点 (100,50) → 参考点 (60,60)；写反会到 (140,40)）。详见 2.6。

## 4.4 与方案说明书的实现差异（6 处，刻意）

| # | 方案原文 | 实现 | 理由 |
|---|---|---|---|
| 1 | 公式块对图用正变换 | 图用 **T⁻¹** | 见 4.3 |
| 2 | 预览区"（有图时）"未指定图来源 | 新增 `PreviewImagePath` 配置；未载路径时若 `SrcImage` 有值直接当底图 | 配置态必须"保存前有图可看" |
| 3 | SrcImage 行写"像素尺寸失配校验" | 尺寸校验只在 **ToMechanical** 生效 | FollowRoi 不消费标定，无"标定图尺寸"可比 |

| 6 | 未提视图刷新时机 | 叠加预览只在配置窗口开着时刷新（`OnViewAttached/Detached`） | 关了窗口不做无谓重采样 |

## 4.5 代码级/HALCON 踩坑汇编

1. **`Success`/`ErrorMessage` 直调语义**：见 4.2——插件 `RunAlgorithm` 轮首重置是通用防护。
2. **`affine_trans_image` 参数顺序**：`(HomMat2D, Interpolate, AdaptImageSize)`，插值用 `"constant"/"bilinear"`、末参 `"false"`（同幅面）；写反报 `#3147`。
3. **`affine_trans_region` 插值字符串**：仓库既有用法一律 `"nearest_neighbor"`；按 HALCON 值集，`"nearest"` 不是合法插值名（方案文档里是简写，实现照值集与仓库用法）。
4. **`HObject` 所有权**：`new HRegion(hobj)` / `new HImage(hobj)` 与 `hobj` 各自持有引用计数，`hobj.Dispose()` 不会破坏包装对象（反之亦然）；但**显示图与来源图要分开**（本插件先拷贝再画，绝不在用户图上涂改）。
5. **`InputPort.Value = null` 会触发 CS8625**：弱类型入口的参数标注为非空 `object`；需要清空时用 `null!`（断言代码同）。

| 基准 ROI | 在**模板图上**画的检测区域（模板坐标系） |
| 跟随 ROI | 基准 ROI 经当前位姿变换后的区域（当前图像坐标系） |
| 对齐图 | 把当前图反向重采样回模板参考位姿的图（`AlignedImage` 的通用版） |
| 刚体变换 | 只有旋转+平移（无缩放/斜切）的变换；`vector_angle_to_rigid` 生成 |
| T / T⁻¹ | 模板→当前的变换 / 它的逆（当前→模板） |
| 反向回显 | 机械坐标反算回像素的自校验 |
| 手性翻转 | 标定含镜像/轴交换时转角符号翻转（数学事实，不做校正） |
| 失配 | 标定与当前使用条件不符（未接/类型不对/尺寸不符）——必须失败 |
