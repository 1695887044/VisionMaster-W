## ⚠️ 最需要记住的三条

> 1. **基准 ROI 必须画在模板图上**——画在别的图上，跟随结果会系统性偏移（"模板态自洽"自检就是这条的守卫）。
> 2. **位姿 (0,0,0) 一定是没接好**——匹配失败的典型输出；插件会明确失败而不是静默变换。
> 3. **卡尺/颜色/OCR 一期不跟着走**——它们用 `Matching.AlignedImage`；本插件服务的是能吃 `HRegion`/点位的下游（主文档 1.2 / FAQ Q1）。

## 维护约定

1. **只改主文档**。行为、失败文案、参数默认值以 `坐标变换插件.md` 为准；方案说明书只作设计依据，不再随实现更新。
2. **改行为/修 bug 必须同时补回归断言**（`FlowCanvasChecks\PoseTransformChecks.cs`），并在主文档第 4 章记录「现象 → 原因 → 修法 → 证据」。
3. **方向语义（T / T⁻¹）是高压线**：区域用 T、图用 T⁻¹——动这块先看主文档 2.6 与断言 17~20。
4. **不做"方向校正"**：轴交换/镜像/旋转由标定矩阵吸收；任何"再校正一次"的想法先回主文档 1.3 原则②。
5. **端口名 = 接线契约**：改名等于断下游接线（断言锁住了端口面）；`Transform` 端口类型必须保持 `CalibrationTransform`。
6. **多目标/内部 ROI 跟随属二期**：不预埋复杂端口（端口面越简单，接错的机会越少）——见主文档 4.6。
