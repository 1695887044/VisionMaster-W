# 第 0 章 这是什么

**数据记录（CSV）= 流程每跑一次，就在账本里追加一行——把每件产品的检测结果记下来。**

> 生活比喻：产线上每件产品检完，质检员在表格里记一行：时间、序号、合格/不合格、尺寸多少……这就是"账本"。本插件自动干这件事，而且**不占产线节拍**（写磁盘交给后台线程）。

它在流程里的位置（归在 **「数据处理」** 分组）：

```
[采集] → [检测类插件] → [数据记录]  ← 动态输入端口（各列名 + 图片）
                            ↓
              D:\Records\步骤名\2026-09\2026-09-16.csv（UTF-8 带 BOM）
```

**一句话**：检测类插件负责"判"，**数据记录负责"记"**——它是追溯（SPC、质量分析、客户审计）的数据源头。

## 0.1 两个最重要的特性

1. **异步写入不占节拍**：流程线程只做"取值 + 格式化 + 入队"（**微秒级**），磁盘 IO 全部交给插件内静态 `RecordingHub` 的后台写线程（生产者-消费者）。
2. **多个步骤共享同一个 Hub**：多个「CSV记录」步骤实例各归各账，互不干扰。

## 0.2 出厂就有一本最小可用的账

新建步骤默认三列：**时间**（内置时间戳）、**序号**（内置序列号）、**结果**（端口，需连线）。

# 第 1 章 设计思想

## 1.1 核心原理：三遍走 + 后台写

```
流程线程（微秒级）
  ├─ 第一遍：逐列取原始值并格式化（图片路径列先占位）
  ├─ 第二遍：图片处置（存副本 / 记路径），得到 ImagePath 列的值
  └─ 第三遍：行入队（失败按契约处置）
                    ↓ BlockingCollection
后台写线程（RecordingHub）
  ├─ CSV 写线程：500ms 攒批 → 开→写→关 → 关前冲刷
  └─ 图片写线程：HImage → WriteImage 落盘
```

> **为什么 500ms 攒批**：节拍快时合并写入、空闲时不空转。要断电保真可开 `FlushEveryRow`（牺牲节拍）。

## 1.2 列定义 = 动态端口（本插件最重要的概念）

| 列的`来源` | 含义 | 是否生成端口 |
|---|---|---|
| **端口**（`Port`） | 取上游连线的值 | ✅ 列名同时是**动态输入端口名** |
| **变量**（`Variable`） | 取运行期变量（`context.LocalVariables`） | ❌ |
| **内置**（`BuiltIn`） | 时间戳 / 序列号 / 步骤名 / 本轮耗时 / 图片路径 | ❌ |

> 动态端口一律 `IsRequired = false`：列允许"**先定义、后连线**"，未连线走手填值或空值。否则 `FlowCompiler` 编译期会报 `[参数缺失]`。

## 1.3 为什么端口类型用 `InputPort<object>`

> `FlowCompiler` 连线**不做类型静态校验**，赋值经 `ValueConverter` 兜底，任何上游输出都接得进来。

## 1.4 失败契约：宁停线不丢账

写入被拒（队列满 / 关停中）且勾选「写入失败阻断流程」→ **显式 `Success=false`**。

> 理由：追溯数据丢失比停线更严重。不勾则只 WARN 继续跑。

## 1.5 编码与格式（固定，不可配）

| 项 | 值 | 理由 |
|---|---|---|
| 编码 | **UTF-8 带 BOM** | Excel 双击不乱码 |
| 分隔符 | 逗号 | 按 RFC 4180 转义 |
| 打开方式 | `FileMode.Append` | 只追加，不覆盖 |
| 数值格式化 | `InvariantCulture` | 防德语区逗号当小数点毁掉列对齐 |

> ⚠️ **没有**编码配置项、**没有**分隔符配置项、**没有**覆盖选项、**没有**行数上限（滚动靠"目录按月 + 文件按天"）。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | CSV记录 |
| `GroupName` | 数据处理 |
| `Description` | 把每次流程执行的结果按行记录到 CSV 账本，可选同步保存 NG 图片，异步写入不占节拍 |
| `ShortName` | 文件图标（FontAwesome `f1c0`） |

> `[Display]` 来自 BCL 的 `System.ComponentModel.DataAnnotations.DisplayAttribute`。

## 2.2 端口完整清单

### 固定端口

只有基类的 `Success` / `ErrorMessage` 两个输出。**插件自身不声明任何固定端口**。

### 动态输入端口（核心）

| 端口名 | 类型 | 生成条件 | 说明 |
|---|---|---|---|
| `<列名>`（如 `结果`、`宽度`、`OKNG`） | `InputPort<object>`，`IsRequired=false` | 列定义中 `Enabled=true` 且 `Source=Port` 且列名非空 | 一个启用列 = 一个输入端口。未连线时为手填值或 null（写空串） |
| `图片` | `InputPort<object>`，`IsRequired=false` | `ImageSaveMode != Off` | 接 `HImage` → **存副本**；接 `string` → **只记路径** |

> ⚠️ 重名列只建一个端口。
>
> **没有动态输出端口**（未实现 `IDynamicOutputProvider`）。

**重建触发点（5 处）**：`ApplyConfigValues`、`Columns` setter、`ImageSaveMode` setter、列名/来源/启用三项变化、增删列。
**UI 同步**：`PortsVersion` 计数器（与脚本类插件同一范式）。

## 2.3 配置项（13 个）

### 账本文件

| 配置 | 默认 | 说明 |
|---|---|---|
| `DirectoryTemplate` | `D:\Records\{StepName}\{yyyy-MM}\` | 记录目录模板（占位符：`{StepName}` `{yyyy}` `{yyyy-MM}` `{yyyy-MM-dd}`） |
| `FileNamePattern` | `{yyyy-MM-dd}.csv` | 文件名模板（默认按天滚动） |
| `WriteHeader` | `true` | 新建文件时是否写表头行 |
| `KeepDays` | `0` | 保留天数（**0 = 永不清理**——追溯数据的删除必须显式决定） |
| `BlockOnFailure` | `true` | 写入被拒时是否让本步骤失败阻断流程（**宁停线不丢账**） |
| `FlushEveryRow` | `false` | 每行立即落盘（断电保真，牺牲节拍；默认 500ms 批量） |

### 列定义

| 配置 | 默认 | 说明 |
|---|---|---|
| `Columns` | 出厂三列（时间/序号/结果） | 列定义（**顺序即 CSV 列顺序**） |

## 2.4 HALCON 算子：只有两个

| 算子 | 位置 | 用途 |
|---|---|---|
| `copy_image` | `DataRecordPlugin.cs:436` | 上游图**深拷贝**成独立副本，解耦生命周期 |
| `HImage.WriteImage` | `RecordingHub.cs:391` | 后台线程落盘图片 |

> ⚠️ **除此之外没有任何 HALCON 算子**——本插件不做图像处理，只做"取值 + 写文本 + 存图"。

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **异步后台写** | 流程线程只入队（微秒级） | ⭐⭐⭐ 不占产线节拍 |
| **500ms 攒批** | 节拍快时合并、空闲不空转 | ⭐⭐⭐ |
| **开→写→关** | 每批开→写→关，句柄只持有几毫秒 | ⭐⭐⭐ 最大限度给 Excel 让路 |
| **占用重试 + 旁路** | IOException 重试 3 次（递增退避）→ 旁路 `_conflictN.csv` | ⭐⭐⭐ **宁旁路不丢账** |
| **图片深拷贝** | `CopyImage` 独立副本 | ⭐⭐⭐ 与上游生命周期彻底解耦 |
| **UTF-8 带 BOM** | Excel 双击不乱码 | ⭐⭐ |
| **RFC 4180 转义** | 逗号/引号翻倍 | ⭐⭐ 列不错位 |
| **InvariantCulture** | 防德语区逗号当小数点 | ⭐⭐ |
| **磁盘水位** | 剩余 < 500MB 打 ERROR | ⭐⭐ 提前预警 |
| **序列号边车** | `DataRecord_seq.json` 每 50 号落盘 | ⭐⭐ 跨重启续号 |
| **背压非阻塞** | `TryAdd(..., 0)` 满即拒 | ⭐⭐ 不拖住流程 |

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.DataRecord.dll`。
2. 重开软件，工具箱里出现「CSV记录」（**数据处理** 分组）。

## 3.2 配置界面总览（4 张卡片）

```
┌────────────────────────────────────────────────────┐
│ ① 账本文件                                          │
│    记录目录 / 文件名 / 保留天数 / 三个勾选框           │
│ ② 列定义（一行 = 一次执行）                          │
│    表头：用 | 列名 | 来源 | 取值 | 格式 | 删除        │
│    「+ 添加列」                                     │
│ ③ 图片记录（可选）                                   │
│    记录方式 / 图片源连线 / 结果列·NG值 / 命名·格式    │
│ ④ 试写一行验证配置                                   │
│    「测试写一行」+ 结果                              │
└────────────────────────────────────────────────────┘
```

## 3.3 第一次记录（5 步）

**第 1 步｜拖节点**：新建就有出厂三列（时间/序号/结果）。

**第 2 步｜设目录和文件名**：默认 `D:\Records\{StepName}\{yyyy-MM}\` + `{yyyy-MM-dd}.csv`（每月一个目录、每天一个文件）。

**第 3 步｜加列**：点「+ 添加列」，填列名、选来源：
- **端口** → 行内点 🔗 连上游（如 Blob 的 `IsOk`、卡尺的 `MeasureValue`）
- **变量** → 填变量名
- **内置** → 选时间戳/序号/步骤名/耗时/图片路径

**第 4 步｜（可选）存图**：「记录方式」选 `仅NG存图`（推荐，省磁盘省节拍）或 `每件存图`，然后把图像连到「图片」端口。

> ⚠️ 改了记录方式后，「图片」端口的**连线入口在配置面板内**——宿主画布不会立刻长出连接器（见 4.2 节⑤）。

**第 5 步｜验证**：点「测试写一行」→ 立即向当前目标文件追加一行样例，绿字显示 `✔ 已写入一行：{路径}`。

## 3.4 参数速查表

| 你想做 | 调哪里 |
|---|---|
| 只记 NG 件的图 | `ImageSaveMode = 仅NG` + 填对 `ResultColumn` 与 `NgValue` |
| 每件都存图 | `ImageSaveMode = 每件`（省磁盘请选仅NG） |
| 上游已把图存好了，只想记路径 | 「图片」端口接 **string**（路径），不落盘 |
| 断电也要保住最后一行 | 勾 `FlushEveryRow`（牺牲节拍） |
| 写失败要停线 | 勾 `BlockOnFailure`（默认开） |
| 自动清理旧账 | 填 `KeepDays`（0 = 永不清理） |
| 临时停用某列 | 取消该列的「用」勾选（不必删除） |
| 改时间格式 | 该列的「格式」填 .NET 格式串（如 `HH:mm`） |
| 数值保留 2 位小数 | 该列的「格式」填 `F2` |
| 让 Excel 双击不乱码 | 已默认 UTF-8 带 BOM，无需配置 |

## 3.5 FAQ

**Q1** 会影响产线节拍吗？
**几乎不会**。流程线程只做"取值 + 格式化 + 入队"（微秒级），写磁盘在后台线程。默认 500ms 攒批写入。

**Q2** 能改编码/分隔符吗？
**不能**，固定 UTF-8 带 BOM + 逗号（按 RFC 4180 转义）。这是刻意的——保证 Excel 双击不乱码、列不错位。

**Q3** 图片怎么关联到账本？
账本里记的是**图片路径**（靠 `ImagePath` 内置列），不是把图嵌进 CSV。两边靠这列关联。

**Q4** 上游的图被释放了，存的图还在吗？
在。存图前做了 `CopyImage` **深拷贝**成独立副本，与上游生命周期彻底解耦。

**Q5** 序列号会重复吗？
不会。全局单调自增，**跨重启续号**（每 50 号落一次边车 `DataRecord_seq.json`）。边车写不了会从 0 重来并警告。

**Q6** 为什么改了记录方式后画布上看不到「图片」端口？
宿主画布只枚举 `model.InputValues.Keys`，改 `ImageSaveMode` 不会立刻长出连接器。**决策是不改宿主，改为在配置面板内提供连线入口**（见 4.2 节⑤）。

**Q7** 图片存失败会改账本吗？
**不会**。共识：图片失败不回改已写出的账本，只留 WARN 供人工补账。

**Q8** Excel 打开着会怎样？
写不进去时会重试 3 次，仍失败则改写入旁路文件 `xxx_conflict1.csv` 并 WARN 提示你关闭 Excel。

## 3.6 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| `CSV记录：未配置任何启用的列` | 列全被取消勾选了 |
| `CSV记录：写入队列已满，记录被拒（检查磁盘/文件占用）` | 队列满（数据 20 万行 / 图片 2000 张）。检查磁盘/文件占用 |
| `CSV记录：记录中枢正在关停，不再接收` | 进程即将退出 |
| 日志：`目标被占用，N 行已改写入旁路 …` | Excel 独占打开了目标文件 → 关闭它 |
| 日志：`磁盘 X 剩余 … MB，低于 500MB 水位` | 立即清理或更换记录目录 |
| 日志：`序列号边车 … 无法写入` | 程序目录无写权限 → 重启后序号从 0 重来，图片可能撞名 |
| 日志：`存图失败（账本路径已写出，需人工留意）` | 图片落盘失败，账本路径已写出，需人工补账 |
| 序号从 1 重来 | 边车没落盘（见上）；或首次运行 |
| 图片撞名 | 同上，序号回绕导致 |

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与开发文档）。每条给：现象 → 原因 → 修法。

## 4.1 缺陷修复总览

| 级别 | 问题 | 一句话 |
|---|---|---|
| P0 | `HImage.Reference` 属性不存在（CS1061） | 原设计靠引用计数保活 → 改 `CopyImage` 深拷贝 |
| P0 | 只取序号不入队的进程退出时边车不落盘 | 重启序号回绕 → 图片必撞名 |
| P1 | `BlockingCollection.Take(500)` 编译报错（CS0029） | 被 LINQ 的 `Enumerable.Take` 扩展方法截胡 |
| P1 | 「图片」端口在画布上看不到 | 宿主只枚举 `InputValues.Keys` |
| P2 | 长列名占位符被短列名截胡 | `{结果2}` 被 `{结果}` 截胡 |
| P2 | 下拉样式重写 | 收编成 `ModernComboBase` 四键 |
| P3 | 构建期偶发 `CS2001` | WPF 临时工程并行编译瞬时竞态，重跑即消失 |

## 4.2 P0/P1 级详解

### ① `HImage.Reference` 不存在（CS1061）

**现象**：编译报错。原设计想靠引用计数给图片"保活"。

**原因**：当前 `halcondotnet` 版本**没有** `HImage.Reference` 这个属性。

**修法**：改为仓库既有范式—— **`CopyImage` 深拷贝独立副本**，Hub 落盘后负责 `Dispose`。

### ② 只取序号不入队 → 边车不落盘（冒烟抓出的真 Bug）

**现象**：只取了序号但没入队的进程退出时，边车不落盘 → 重启序号回绕成 1 → **图片必撞名**。

**原因**：`NextSequence()` 没调 `EnsureStarted()`，`ProcessExit` 冲刷钩子未注册。

**修法**：在 `NextSequence()` 里调 `EnsureStarted()`。注释原文：

> ```
> EnsureStarted(); // 取过号就必须挂好退出冲刷钩子：防止"只取号未入队"的进程退出时边车不落盘，重启序号回绕撞名
> ```

### ③ `BlockingCollection.Take(500)` 编译报错（CS0029）

**现象**：`bc.Take(500)` 编译不过。

**原因**：WPF 工程 `ImplicitUsings` 带 `System.Linq`，`bc.Take(int)` 无成员重载时被 **`Enumerable.Take` 扩展方法截胡**。

**修法**：改用 **`TryTake(out x, 500, CancellationToken.None)`**（自带超时语义，且队列关死时会抛 `InvalidOperationException`）。

### ④ 长列名占位符被截胡

**现象**：`{结果2}` 被 `{结果}` 抢先替换。

**修法**：**长 token 优先替换**。注释原文：`// 长列名优先替换，避免 "{结果2}" 被 "{结果}" 截胡`

### ⑤ 「图片」端口在画布上看不到（首次实跑反馈）

**现象**：用户反馈"图片端口看不到"。

**原因**：宿主画布只枚举 `model.InputValues.Keys`——改 `ImageSaveMode` 不会立刻长出连接器。

**修法**：**决策是不去改宿主，改为在配置面板内提供连线入口**。理由：改宿主影响面大，面板内连线已经够用。

## 4.3 代码级踩坑汇编

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `CS1061` | `HImage.Reference` 不存在 | `CopyImage` 深拷贝 |
| 2 | 序号回绕、图片撞名 | `NextSequence` 没调 `EnsureStarted` | 取号即挂冲刷钩子 |
| 3 | `CS0029` | `Take(500)` 被 LINQ 截胡 | 用 `TryTake(out, 500, token)` |
| 4 | 占位符截胡 | 短名先替换 | 长 token 优先 |
| 5 | Excel 占用写不进 | 文件被独占 | 重试 3 次 → 旁路 `_conflictN.csv` |
| 6 | 图片存失败 | 磁盘/格式问题 | 只 WARN，不回改账本 |
| 7 | 清理误删 | 文件名无日期 | 只认"文件名带日期"的 csv，其余一律不动 |
| 8 | 端口看不到 | 宿主只枚举 InputValues.Keys | 在配置面板内连线 |
| 9 | 列错位 | 文化差异（德语逗号当小数点） | 一律 `InvariantCulture` |
| 10 | 图被上游释放 | 只存引用 | 深拷贝独立副本 |

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `CS1061` | `HImage.Reference` 不存在 | 用 `CopyImage` |

## 4.5 已知边界与待办

- ⚠️ **`FlowCanvasChecks/` 没有任何 DataRecord / 数据记录 / CSV 相关断言**（全目录检索 0 命中）。历史验证来自 MVP 期临时冒烟工程（跑完已删）。
- **宿主 UI 实跑未验证**（MVP 期遗留）。
- **500ms 攒批**是默认语义，要断电保真需开 `FlushEveryRow`。
- **动态端口一律 `IsRequired=false`**（允许先定义后连线）。
- **只记路径模式（接 string）不受 `KeepDays` 管**——插件不管你那个路径下的文件。
- **序列号边车在程序目录**（`DataRecord_seq.json`），需写权限。
- **日志暂存机制**：静态 Hub 拿不到 `IExecutionContext`，日志暂存后首次执行时取走（上限 2000 条）。
- **`ImagePath` 列的下标写法**有一处可收敛的边界写法（`imagePathIndex < colValues.Count`），不影响功能。
- 构建期偶发 `CS2001`（`Plugin.DataRecord` 的 `obj\*.g.cs`）= WPF 临时工程并行编译瞬时竞态，**重跑即消失**。
