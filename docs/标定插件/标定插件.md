# 第 0 章 这是什么

**标定 = 给相机发一把"带刻度的尺子"，把"图上的像素"翻译成"车间的毫米/机械坐标"，并告诉你这个翻译能不能信。**

> 生活比喻：地图上的距离是"手指几厘米"，实际是"几公里"——两者之间要有一个**比例尺**；如果还要让机械手去地图上某个点抓东西，还得知道地图的"北"对着车间的哪个方向、地图的原点对应机床的哪个坐标。标定就是测这个比例尺（像素当量）与这层对应关系（九点标定）。

**为什么需要它（仓库现状，不是空谈）**：

| 现状 | 出处 |
|---|---|
| Blob 的"像素当量"是**手填参数**，默认 1.0 = 不标定 | `BlobDetectPlugin.cs:140`「1.0 = 输出即像素值，不假设标定」 |
| 卡尺的当量同样是手填，注释直言"项目暂无标定模块" | `CaliperMeasurePlugin.cs:81`、`BlobDetectPlugin.cs:476` |
| 脚本模板教用户"发给机器人前必须过手眼标定矩阵换算"——即换算靠**手写脚本** | `ScriptTemplates.cs`（"E 精密测量"模板） |

本插件补的就是这个洞：把"像素 → 毫米 / 机械坐标"做成**可配置、可复用、可溯源、可校验**的一等算子。

它在流程里的位置（分组「标定」）：

```
[图像采集] ─┬─→ [标定] ──Transform（契约）──→ [坐标变换] ──→ 机械坐标 / 跟随 ROI
            │        │                                        ↓
            │        └─MmPerPixel ──→ Blob / 卡尺的 `MmPerPixel` 输入端口（直连；未接=手填兜底）
            └─ 标定图（配置态取点用）
```

**两种模式，一句话区分**：

| 模式 | 你要准备什么 | 得到什么 | 典型场景 |
|---|---|---|---|
| **像素当量** | 一张图 + 一段已知长度 | `mm/px`（一个数） | 卡尺/Blob 测毫米尺寸；不需要机械坐标 |
| **九点标定** | N×N 组「机械坐标 ↔ 图像点」 | 2D 仿射矩阵（含当量/方向/平移） | 机器人引导、纠偏、需要机械坐标系的一切场景 |

> **教训先记住**：`PixelScale` 的产出**没有机械坐标系**（矩阵是"沿图像轴的毫米"，不是"沿机床轴的毫米"）。拿它当九点用会在下游被明确拒绝（见 3.8 排障表第 1 条）。

# 第 1 章 设计思想

## 1.1 核心原理：最小二乘求 2D 仿射

仿射变换的公式（本仓统一口径，HALCON `hom_mat2d` 同排布）：

```
X = a11·Row + a12·Col + a31
Y = a21·Row + a22·Col + a32
```

它有 **6 个自由度**：2 个缩放 + 1 个旋转 + 2 个平移 + 1 个"斜切/轴交换"。公式里能表达的东西（轴交换、镜像、旋转、缩放）**全部由矩阵自然吸收**——现场机械的 X 轴对着图像的哪一边、是否需要镜像，都不用手动"校正"，标定出来是什么就是什么。

求解=对 N 组点做**最小二乘**：

```
设计矩阵 A 的每行 = [Row, Col, 1]，两列目标 [X], [Y] 各解一次
法方程：(AᵀA)θ = Aᵀb   →  3×3 方程组，克莱姆法则求解
```

实现上做了两件让数值更稳的事（见 2.5）：**质心 + 尺度归一化**（把像素坐标缩放到 ~[-1,1] 再解法方程）与**共线守卫**（法方程行列式近零 = 点全在一条直线上 → 直接失败，不去解一个病态方程）。

## 1.2 点数 = 采样密度，不是模型（9 点 / 12 点 / 畸变 三个高频疑问）

这是现场最常被问、也最容易误解的一点，直接给结论：

| 疑问 | 答复 |
|---|---|
| 为什么默认 9 点？ | 9 点不是"方法名"，而是**采样密度**：仿射只有 6 个自由度，**3 个非共线点即唯一解**；用 3×3 是为了覆盖视野四角+中心、把测量噪声平均掉 |
| 换成 12 点能治畸变吗？ | **不能。12 点仍然是仿射**——多出来的点只提高抗噪余量，模型能力没有任何变化。畸变是"位置相关的非线性误差"（径向/切向），仿射里没有能表达它的项，加多少点都吃不进去，只会把它摊进残差 |
| 那畸变怎么治？ | **先看残差形态，再选升级路线**（下表） |

| 残差形态（看质量区的径向带提示） | 结论 | 走哪条路 |
|---|---|---|
| 随机小残差（无位置规律） | 正常噪声 | 维持仿射（可把 GridSize 调到 4 / 5 加密采样） |
| **中心小、边缘大**（径向规律） | 镜头径向畸变 | ② 网格标定（工程近似）或 ③ 标定板内参标定（正解）——均未实现，列二期 |
| 单向偏差 / 梯形 | 相机倾斜（透视） | ① 透视标定（`vector_to_proj_hom_mat2d`，≥4 点）——未实现，列二期 |

> 所以本插件的选择是：**点数可配（默认 3×3，界面下拉 2~10）**，并把"该不该升级"交给数据说话（残差与诊断提示），而不是预先上 12 点。

## 1.3 三条设计原则（读懂了少踩 80% 的坑）

**原则①：超阈值 = 业务失败，绝不静默放行**

残差 RMS 超过 `ResidualThresholdPx`（默认 1px）时，步骤**失败**而不是打个警告继续。理由：错标定会污染整条产线的判定——"错误但不出错"是计量最危险的失败模式。现场确有需要（画幅大、镜头弱）就把阈值**显式调大**，可解释、可追溯。

**原则②：唯一一份计算（配置态所见 = 运行期所得）**

配置界面上的质量数字与运行期输出的矩阵走的是**同一个函数** `ComputeCalibration`（`CalibrationPlugin.cs:613`）。不存在"界面说能跑、一跑就失败"的裂缝——这是把"预览"做成"另一套代码"的插件常有的暗病。超阈值时界面**照常显示残差数字**（红字提示差多少）、运行期照旧失败（见 4.4.3 ④）。

**原则③：契约零 HALCON，算法纯托管**

`CalibrationMath` 只吃 `double[]`、不引用任何 HALCON 类型：① 断言可以完整覆盖（合成已知仿射 → 精确还原，误差可控到 1e-13）；② 没有 HALCON 的机器上插件加载不受影响（"构造期 new HImage"的历史教训）。HALCON 只出现在配置态**读图预览**一处。

## 1.4 矩阵语义与坐标/角度约定（全仓统一，写死避免静默错位）

| 约定 | 内容 |
|---|---|
| 像素坐标 | `(Row, Col)`：Row 向下、Col 向右（与 HALCON 一致） |
| 机械坐标 | `(X, Y)`：单位毫米；轴方向/镜像/旋转由**矩阵自然吸收**，插件不做任何额外假设 |
| 角度单位 | **度**（与模板匹配输出一致）；仅在调用 HALCON 算子时换算为弧度 |
| 数组排布 | 多点数组一律 `[x0, y0, x1, y1, ...]`（x 在前、y 在后，成对） |
| 矩阵语义 | `CalibrationTransform.Matrix`（6 元）= 映射 **(Row, Col) → (X, Y)**，HALCON 6 元排布（`X=a11·Row+a12·Col+a31`） |

为什么把语义写死：**转置 / 轴交换 / 正负号**是这一族代码的"静默错误家族"——数值看着合理、结果全错。把语义写进契约注释 + 用合成数据断言锁死（正变换手算常量、正反互逆 < 1e-9），是唯一可靠的防法。

## 1.5 配置态取点范式（画布交互不用自造 API）

九点的"图上取点"走的是仓库既有的**画布标记范式**：

- 图上放 `DrawingObjectInfo` 标记（圆点），拖动时通过 `HTuples` 通道自动回写表格（`CalibrationPlugin.cs:1348`）；
- 拖拽/回写只用到控件既有的 `ActiveRoi` / `DrawObjectList` / `HImage` 三个通道；**唯一的例外**是「取点」按钮的一次性点击通道（`HalconBase.IsPickMode` + `ImagePicked`，**opt-in、默认关**，仅取点待命时开启，见 4.4.3 ⑦）；
- 表格改值 → 画布标记跟随（`SyncMarkerFromRow` / `SyncScaleMarker`），与"拖标记→回写表格"构成**双向同步**；
- 换图清标记（旧坐标已无意义）；网格重建时清标记（行结构变了）。

## 1.6 配置项写法：源生成器（新约定）

`[StepConfig]` 属性自 2026-10-04 起采用**源生成器**写法（`Shard\Core.PluginGenerators`）：

```csharp
[StepConfig, DefaultValue(1.0)]
public partial double ResidualThresholdPx { get; set; }

partial void OnResidualThresholdPxChanged(double value) => RefreshStatus();   // 只在有副作用时需要
```

- 实现体（后备字段 / `SetProperty` / 通知）由生成器产出；**属性名 = 持久化键**，改名 = 静默丢配置（红线）；
- 副作用挪到 `On<属性名>Changed` / `On<属性名>Changing` 钩子（`GridSize` 就是用它做 2–10 夹取）；
- 约定与诊断：`AGENTS.md` R18、`docs\新插件端口速查.md`、变更记录 `../code-changes/2026-10-04-插件配置属性源生成器（StepConfig-partial）.md`。

## 2.4 运行语义与失败文案总表

**成功分支**：

| 分支 | 行为 |
|---|---|
| PixelScale 成功 | `MmPerPixel = KnownLengthMm / 两点像素距离`；`Transform.Kind=PixelScale`，矩阵按当量构造（a11=a22=当量，其余 0）；残差记 0 |
| NinePoint 成功 | 最小二乘求 6 元矩阵 → 输出；`MmPerPixel` 由矩阵两基向量长度反解均值；`ResidualRmsPx/MaxResidualPx/ResidualByRadiusBands/ResidualBandCounts` 一并输出；表格残差列同步回写（**像素口径**，见 2.5 ⑩） |

**失败文案（原文，均在运行期与配置态共用）**：

| 触发条件 | 文案（节选） |
|---|---|
| 两点含 NaN/Inf | 两点坐标含非法数值（NaN/Inf）——请检查表格或画布标记 |
| **A/B 未取全**（像素当量） | 像素当量：A / B 两点尚未取全——请点「取点」在图上各点一下，或直接填表格里的 Row/Col（也点「把点画到图上」后拖动 A / B 标记） |
| **NaN/Inf 按行指名**（九点；插件侧先报行，数学层兜底） | 标定表第「P2」行含非法数值（NaN/Inf）——请检查该行的填写（兜底文案：参与求解的第 N 组点含非法数值……） |
| 已知长度为非正 | 已知长度必须为正数（当前 X） |
| 两点重合 | 两点像素距离为 0：请在画布上把 A/B 两个标记拖到标定物的两端（或手工填写表格里的 Row/Col） |
| 当量为非正 | 像素当量 X 非法（必须为正） |
| 当量越界 | 当量 X mm/px 超出合理范围 [0.001, 1]：① 单位是否把 µm 当 mm 填了？② 标定物长度/网格点是否填错一个数量级？ |
| 有效点不足 | 有效标定点不足：至少需要 3 组，当前 N 组（表里共 M 行；默认 3×3=9 点，覆盖视野四角+中心） |
| **半填行**（防"漏填一格"被静默忽略） | 标定表第「P3」行只填了一部分：机械X / 机械Y / 图像Row / 图像Col 必须四值齐全（整行不填 = 空行，不参与计算；**0 是合法坐标值**，不会被判成没填） |
| 点全部重合 | 标定点在图像上全部重合（尺度为 0）——请把点铺开成 N×N 网格 |
| 近似共线 | 标定点近似共线（无法定出平面方向）：请把点铺开成 N×N 网格，覆盖视野四角与中心，别让点落在一条直线上 |
| 残差超阈值 | 标定残差 7.86px 超过阈值 1px（最大偏差 22.22px）。请检查：① 机械坐标与图像点是否一一对应 ② 特征点是否取在同一物理位置 ③ 若残差呈「中心小、边缘大」→ 疑似镜头畸变（仿射模型无法吸收，见方案 §十一）。**超阈值时质量区照常显示残差数字**（红字，看得到差多少），运行期照旧失败不输出 |
| 粘贴解析失败 | 剪贴板第 N 行有 M 列，应为 4 列（机械X、机械Y、图像Row、图像Col）或 5 列（带序号） / 剪贴板第 N 行「xxx」不是数字 / 剪贴板里没有可解析的数据行 |

**其它语义**：无阻塞操作（无取消分支）；同一组输入永远得到同一矩阵（幂等）。

## 2.5 算法链（`CalibrationMath.cs`，纯托管）

| 步骤 | 函数 | 要点 |
|---|---|---|
| ① 两点当量 | `TryPixelScale`（:46） | 距离=像素欧氏距离；失败文案见 2.4 |
| ② 归一化 | `TrySolveAffine`（:94） | 质心 `(cr,cc)` + 尺度（最大半径）归一化到 ~[-1,1]，数值稳定 |
| ③ 共线守卫 | 同上 | 法方程 `det ≤ 1e-4 · trace³` → 判共线失败（**不去解病态方程**） |
| ④ 求解 | 同上 | 克莱姆法则解两条独立 3 元方程（X 与 Y 共用系数矩阵）；系数还原到原坐标系 |
| ⑤ **残差（mm→px）** | 同上 | 先算机械系偏差（mm），**按当量除一次换算成像素**再统计——这一步 2026-10-04 曾漏掉，见第 4 章（同一换算也用于表格残差列回写，见 ⑩） |
| ⑥ 径向带统计 | 同上 | 按归一化半径分 3 带（≤0.4 / 0.4~0.7 / >0.7）取平均；**同时输出各带点数 `bandCounts`**；无点的带记 **0**（原 NaN）——"有没有点"由计数表达 |
| ⑦ 当量反解 | `DeriveMmPerPixel`（:244） | 两基向量长度 `√(a11²+a21²)`、`√(a12²+a22²)` 的均值；相对差 = 各向异性 % |
| ⑧ 畸变诊断 | `DiagnoseRadialBands`（:271） | 边缘带 ≥ 2×中心带 **且** ≥ 门限 → 提示"疑似镜头畸变"；**给了带计数时，中心带/边缘带任一无点就不判形态**（空带的 0 不会被误读成"中心很小"）；门限 = `max(0.5px, 残差阈值×0.5)`（随阈值放宽） |
| ⑨ 正/反变换 | `TryMapPixelToXY`（:301）/ `TryMapXYToPixel`（:314） | 反向 = 2×2 线性部分求逆；退化 → false |
| ⑩ 表格残差列回写 | `ApplyRowResiduals`（插件侧，`CalibrationPlugin.cs:843`） | 把每行反算偏差按当量 **mm→px** 写回"残差px"列（与残差闸门同口径）；配置态每次计算都回写，不跑流程也能看到 |

## 2.6 质量指标怎么看（现场口诀）

| 指标 | 位置 | 含义 | 建议阈值 |
|---|---|---|---|
| 残差 RMS | 质量区 / `ResidualRmsPx` | 所有点"实测 - 拟合"距离的均方根（像素） | ≤ 1px 合格（可配）；0.2px 以内很漂亮 |
| 最大偏差 | 质量区 / `ResidualMaxPx` | 单点最差——**哪个点没取好，看它**（表格残差列直接指到行） | 比 RMS 大 2–3 倍属正常 |
| 各向异性 | 质量区（橙字 > 1%） | 横向/纵向当量差 %；通常=标定物没有正对镜头 | > 1% 提示而非失败 |
| 径向带 | 质量区提示行 | 残差随半径的形态 → 畸变判据（**无点带记 0：先看计数再看均值**，计数为 0 的带不参与形态判读） | 边缘 ≫ 中心 → 畸变（升级路线见 1.2） |

## 2.7 资源所有权与生命周期

- 预览 `HImage` 归插件持有：`DisplayImage` 的 setter 释放被换下的旧图（`CalibrationPlugin.cs:302`）；Dispose 时置空释放；
- 异步读图用**轮次号**（`_previewLoadId`）丢弃过期结果、`_disposed` 拒绝写已关闭窗口——与「图像采集」插件同一守卫模式；清空路径也会推进轮次号（`CalibrationPlugin.cs:988`），防止在途读图把已清空的预览写回来；
- 画布标记被移除时必须 Dispose 原生句柄（`OnMarkerChanged` / 集合变更处理）；
- **表格行的事件订阅**：`PointRows` 集合变更时逐行挂/摘 `PropertyChanged`（`OnPointRowsCollectionChanged`），但 **`Dispose` 未摘除逐行订阅**（只 `_disposed = true` 让 `RefreshStatus` 早退，`CalibrationPlugin.cs:890`）。属已知边界：行对象不持有 HALCON 句柄，插件实例被回收后订阅随宿主与行对象一同被 GC 回收，无泄漏路径；若后续出现"插件已 Dispose 但行仍被外部引用"的场景，需在 `Dispose` 里补摘除（见 4.5 待办）；
- 运行期输出（`Transform` 等）由基类 `AutoDisposeRoundOutputs` 每轮开头回收；`double` 输出由插件自己每轮清零（失败时下游不读上一轮脏值）。

## 2.8 性能与独特实现

- **运行期重算而不是"只存不算"**：每轮用存下的标定点重算矩阵（微秒级）。好处是"改了表格但忘了重新标定"这种不一致在结构上不可能发生；
- **配置态与运行期同一份计算**（原则②），界面上看到的质量就是运行时的质量；
- 求解全程无 HALCON 调用（原则③）。

## 3.3 第一次标定①：像素当量（6 步）

1. **准备标定物**：一段已知准确长度的东西（量块 / 打印的标尺 / 圆点靶的两点距），长度尽量**跨越视野的 1/3 以上**——短线相对误差大；
2. 「标定图」选一张拍下该标定物的图（或链接变量）；
3. 填**已知长度(mm)**（① 卡片「像素当量」区）；
4. 点「取A点」→ 在图上点标定物一端（Row/Col 自动填入）；「取B点」→ 点另一端；也可点「把点画到图上」后**拖动 A / B 标记**，或手工填 A/B 的 Row/Col（三种方式等效，改完即时重算）；
5. 看质量区与**跨度提示**：`像素当量 ≈ 0.02… mm/px`（超出 [0.001, 1] 会直接报越界——先查单位）；跨度提示显示"标定线占视野对角 X%"，**< 1/3 时橙字"偏短"**——换更长的标定物重取（短基线相对误差大）；
6. 需要机械坐标的场景**不要停在这里**——改用九点标定。

> **防误改（可选）**：核验无误后勾 ③ 卡片的「锁定标定（防误改）」——表格 / A、B 点 / 粘贴 / 重建 / 取点全部禁改；运行输出不受影响，解锁后才能继续编辑。

## 3.4 第一次标定②：九点标定（9 步）

**准备**：把标定物/靶点固定在机械末端（或工作台上），确定 9 个位置：**覆盖视野四角 + 中心**（3×3）。两种常见工作流：

- **工作流 A（单图九靶点）**：一张图里能同时看到 9 个特征点（标定板）；
- **工作流 B（多图走位）**：相机固定、机械带着标定物走 9 个位置，每到一处采一张图——图像点用「模板匹配/Blob」或人工读，机械坐标从示教器读。插件的画布主要服务工作流 A 和核对。

**步骤**：

1. 模式切到「九点标定（N×N）」；网格规模默认 3×3（下拉 2~10，加密到 4×4 / 5×5 可提高抗噪余量）；
2. 「标定图」载入一张图（工作流 A 直接载那张九点图；工作流 B 载任意一张用于核对）；
3. 点「把点画到图上」→ 画布上出现 9 个标记；
4. **逐行点「取点」在图上定位**（点一下特征点中心，Row/Col 自动填入该行）；也可拖动标记（拖完自动回写）或直接在表格里填 像Row/像Col——**三种方式改完都即时重算质量区**（表格里敲完一格，残差/最大/各向异性当场更新，不用切模式或点「重建网格」）；
5. **填/粘贴机械坐标**：点「粘贴 N 行」，从示教器/Excel 复制 9 行（每行 4 列：机械X、机械Y、图像Row、图像Col；带序号 5 列也行）。工作流 B 直接把每点的机械+图像坐标一起粘进来；
6. 看质量区：残差 RMS / 最大偏差 / 各向异性；橙字诊断（畸变提示）出现时**别急着重取点**——看残差是否"中心小、边缘大"（1.2 的路线表）；
7. 残差超阈值会红字失败：按提示三查（一一对应 / 同一物理位置 / 畸变）；
8. 试运行（走正式运行同一段代码）确认 `Success=true`；核验无误可勾「锁定标定（防误改）」（锁定后编辑入口全部禁用，运行不受影响）；
9. 下游接线：把「坐标变换」插件的 `Transform` 输入接到本插件的 `Transform` 输出。

> **现场三步验收（交付时执行）**：① 放已知尺寸（如 100mm 标定尺）→ 当量读数与实物一致（±0.5%）；② 九点标定后**回算**：9 个点的机械坐标经矩阵反算图像点，误差 < 1 像素当量；③ 用「坐标变换」把匹配得到的 Row/Col 换成机械坐标，与示教器读数比对。

## 3.6 多相机怎么配

**一期设计天然支持多相机**：每台相机一份标定、一个标定步骤，流程里各自接线。要点：

1. **一次移动、N 台取点**：九点表"一行 = 一个机械位置"，多台相机各建一个标定步骤（各自的图像点列）；机械只需走 N 次；
2. **统一坐标系**：每台相机**各自与机械做九点标定**，就天然统一到同一个机械坐标系（多相机融合在机械系里完成）；只有需要拼图/相机间互相换算时才需要相机间标定（二期）；
3. **失配按相机判**：填好 `CameraSerial`（+ 自动记录的图尺寸），换相机/换镜头后能人工核对（二期做自动校验需要采集插件输出序列号）。

## 3.7 FAQ

**Q1：为什么运行期还要重算矩阵？直接存矩阵不行吗？**
可以但不划算：① 下游要接端口，运行期必须有产物；② 求解微秒级；③ 存点+重算让"改了表格忘重标"的不一致**结构上不可能**发生。

**Q2：为什么标定图路径是"输入端口"？为什么不直接收 HImage？**
配置态取点必须"保存前就能预览"，走路径→HImage 最直接；运行期**不读盘**（图尺寸等元信息在取点时已记录）。直接吃 HImage 的在线复算二期再做——新增输入端口是加法，不破现有接线。

**Q3：残差多大算合格？**
默认阈值 1px。经验：≤0.2px 很漂亮，0.2–1px 正常（点取在有噪声的边上），>1px 先查点、再考虑畸变，最后才考虑调阈值。

**Q4：各向异性 2% 要不要紧？**
通常是标定物没有正对镜头（或镜头非方形像素）。**是提示不是失败**；如果测量方向恰好是当量大的那一向，误差会放大——介意就重新摆正标定物再标一次。

**Q5：粘贴支持什么格式？**
每行 4 列（机械X、机械Y、图像Row、图像Col）或 5 列（带序号）；分隔符支持 Tab/空格/逗号/分号（含中文逗号分号）。Tab 分隔（Excel 原生）时**空格子 = 未填**（行首空列也按未填；行尾空列裁掉）；整行留空跳过。

**Q6：为什么整行留空算空行、半填行直接报错？0 到底算不算"没填"？**
**0 是合法坐标**（机械回零位、工件原点、图像边缘都可能取到 0）——"没填"用**留空**表达，不是写 0。四格全留空 = 空行（不参与计算）；**半填 = 漏填**——静默忽略会把"漏填的某一行"变成"标定悄悄算歪"，所以必须报错并指到行名。旧方案里"四值全 0"的行载入时自动还原为空行（迁移，不丢点）。

## 4.2 P0 详解：残差单位 mm 当 px（最阴的一条）

**现象**：断言「给 1 个点加 0.5mm（当量 0.02mm/px ≈ 25px）→ 必须超 1px 阈值失败」**未通过**——插件静默放行了错标定。

**根因**：`TrySolveAffine` 的残差在机械坐标系里算（**mm**），但对外字段/闸门/诊断全是像素口径（`ResidualRmsPx`、默认阈值 1px、带诊断 0.5px）。0.5 被当成 0.5"像素"混过闸门。

**修法**：矩阵解出后按当量**除一次**（mm → px）再进统计；矩阵尺度为 0 视为退化失败。

**证据**：修后同一断言给出 `标定残差 7.86px 超过阈值 1px（最大偏差 22.22px）`，与手算吻合（中心点杠杆 1/9 → 最大残差 0.5×8/9≈0.444mm≈22px；RMS≈7.9px）。

**教训**：单位/坐标系这类"数值看着合理"的错，只有**反证式断言**（故意注入超差量、要求必须失败）能抓到。已入回归（`[CAL] 残差超阈值` 一条同时守着这条）。

**① P1｜表格里手工填坐标，质量区不刷新**

| 项 | 内容 |
|---|---|
| 现象 | 在九点表格里直接敲 机械X/Y、像Row/像Col，质量区（残差 RMS / 最大 / 各向异性）与残差列停在旧值——要切一次模式或点「重建网格」才更新；而拖动画布标记却有刷新，两条路径体验不一致 |

| 修法 | ① `PointRows` setter 改为「摘旧集合订阅 → `SetProperty` → 挂新集合订阅 → `RebindPointRowSubscriptions()` → `RefreshStatus()`」；② 新增 `OnPointRowsCollectionChanged`（集合增删时逐行挂/摘）；③ 新增 `OnPointRowChanged`——**只认 `MachineX/MachineY/ImageRow/ImageCol` 四个属性**，避免残差回写 `ResidualPx` 再触发一轮重算（递归）；④ 新增 `RebindPointRowSubscriptions()`（先摘后挂，供反序列化进来的行补挂）；⑤ 构造函数补 `_pointRows.CollectionChanged += OnPointRowsCollectionChanged;`——**字段初始化不走 setter**，缺这步在从未经过 setter 的实例上会静默失效 |

**② P2｜网格缩小时"半途而废"**

### 4.4.2 既有踩坑汇编

1. **输出 `OutputPort<T>` 写 nullable 值**：`port.TypedValue = null` 对引用类型会触发 CS8625；用 `port.Value = null`（弱类型入口）或把端口声明成 `OutputPort<T?>`（本插件 `Transform` 即如此）。
2. **`Value` 是 `object`**：断言/代码里比较 `port.Value - 405` 编译不过；业务取端口值一律 `TypedValue`（输出）/ `ActualValue`（输入）。
3. **构造期不碰 HALCON**：插件构造函数里不要 `new HImage()` / 调算子——无 HALCON 的机器上宿主扫描插件类型时也要能实例化（回归断言锁住：构造后 `DisplayImage == null`）。
4. **HALCON 调用参数顺序**（与显示/变换相关，跨插件通用）：`affine_trans_image` 参数是 `(HomMat2D, Interpolate, AdaptImageSize)`——写反报 `#3147 Wrong interpolation mode`（`MatchingPlugin.cs:1577` 有记录）。
5. **图片路径不读盘原则**：`SourceImagePath` 只在配置态读；运行期读盘会把"方案搬到别的机器"变成运行失败点。

## 5.3 附录 C：实战案例

**案例 1｜量块标当量（5 分钟）**：100mm 量块平放在视野中央偏对角 → 载图 → 拖 A/B 到量块两端 → 读数 0.0198 mm/px。若"跨视野比例"太小（<1/3），重复性会明显变差——换更长的标定物。

**案例 2｜九点 + 示教器（产线常规）**：机械走 3×3 九个位置，每处拍图并把特征点用匹配拿到 Row/Col，示教器读 X/Y → 一次性 9 行粘贴 → 残差 0.31px 通过 → 「坐标变换」接上后与示教器比对 3 个随机点，偏差 ≤0.3mm。

**案例 3｜"残差 2.7px"排障**：表格残差列显示 P1/P3/P7/P9（四角）残差大、中心小，径向带提示"边缘带 2.9px ≈ 中心带 0.4px 的 7 倍" → 判为镜头畸变 → 当前仿射无法吸收；短期把 `ResidualThresholdPx` 调到 3px 并接受四角误差（显式、可解释），长期按 1.2 路线升级标定方式。

## 5.6 附录 F：术语表

| 术语 | 一句话 |
|---|---|
| 像素当量（mm/px） | 一个像素代表多少毫米 |
| 仿射 / 6 元矩阵 | 平面上的"线性 + 平移"变换（缩放/旋转/斜切/轴交换都能表达） |
| 残差 | 每个标定点"拟合值 - 实测值"的距离；RMS=均方根 |
| 各向异性（%） | 横/纵两方向当量差的相对值 |
| 径向带 | 按"离视野中心多远"分的三段（中心/中环/边缘），用来看残差形态 |
| 共线 | 所有点落在一条直线上——方向自由度丢失，无法求仿射 |
| 半填行 | 四值只填了一部分的行（必须报错，防漏填） |
