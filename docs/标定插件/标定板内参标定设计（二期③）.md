## 一、为什么它是"正解"，而网格只是工程近似

| | 网格标定（已实现） | 标定板内参标定（本文） |
|---|---|---|
| 模型 | 分段仿射（逐格插值） | 相机模型（内参矩阵 + 畸变系数） |
| 畸变 | **局部摊平**（格越密越准，仍是近似） | **显式建模**（径向/切向系数，物理可解释） |
| 超出网格范围 | 明确失败（不外推） | 可外推（模型覆盖全图，只要参数靠谱） |
| 换镜头/改焦距 | 重新取点 | 重新拍板（换镜头必须重标） |
| 资产 | 节点表（随方案落盘） | 相机参数（可跨产品/跨方案复用） |

结论：网格解决"今天就想要准一点"，内参解决"要一套可解释、可外推、可复用的相机模型"。两者**互补**，不互相替代；现场按下表选：

| 场景 | 建议 |
|---|---|
| 畸变明显、只关心视野内测量 | 网格（已可用） |
| 需要外推/多工序共用相机模型/要解释畸变 | 内参（本文） |
| 相机倾斜（近大远小） | 透视标定（已实现） |

## 三、设计（两阶段管线）

内参标定**单独不给出 mm**（它给的是相机几何）；必须与平面标定串联使用：

```
① 内参标定（离线，一次）        ② 去畸变                     ③ 平面标定（现有）
拍板 ≥12 张 → find_calib_object → calibrate_cameras
        → CamParam（内参 + 畸变） ──→ 点：change_radial_distortion_points
                                        或 图：change_radial_distortion_image
                                                    ↓
                                       九点/透视/网格（用去畸变后的点/图取点）
```

要点：
1. **去畸变发生在取点之前**（对图）或**映射之前**（对点）——两种接入点都保留，由使用场景选（实时流程倾向对图，离线数据倾向对点）；
2. 内参标定的产物是**相机资产**（跨方案复用），落盘形态与锁定语义要与现有"标定数据"区分开；
3. 畸变模型选择（`area_scan_division` 单系数 vs `area_scan_polynomial` 多系数）取决于镜头：广角/低畸变用 division，强畸变用 polynomial——**现场按重投影 RMS 与去畸变后的平面残差选型，不预设**。

### 3.1 计划新增的契约（`Shard\Core.Interfaces`）


## 四、验收条件（实现时逐条断言，量化）

| # | 条件 | 判据 |
|---|---|---|
| a | 合成自验证（内参） | `sim_caltab` 用已知 CamParam（如 f=2500、主点 (640,512)、k1=-0.05、1280×1024）生成 ≥12 张不同位姿 → 标定恢复：f 相对误差 < 0.5%、主点偏差 < 1px、k1 绝对误差 < 5e-3、重投影 RMS < 0.3px |
| b | 合成自验证（去畸变+仿射 优于 网格） | 同一畸变数据：先去畸变再九点标定 的残差 < 直接网格插值残差的一半 |
| c | 失败面 | 图数 < 6 / 找不到板标记 / 板描述与图像尺寸不符 / 板厚填错 → 全部**明确失败**并给下一步 |
| d | 现场验收 | 真实相机拍 ≥15 张（覆盖四角+中心，含倾斜）→ 重投影 RMS 与去畸变后平面残差都进质量区；与网格方案横向对比一次 |

## 五、为什么现在只交付设计（不交代码）

1. **无验证不交付**：内参代码会改变相机模型与**所有**测量值；本仓库的纪律是"未验证的计量相关代码不落地"（比"没有"更危险）。本机虽可用 `sim_caltab` 自验证，但：
2. **现场信息缺口**：初始相机猜测与畸变模型选择取决于实际镜头（焦距/畸变强度/是否远心），现在写死等于替现场做错决定；
3. **接线设计未定**：去畸变发生在"对图"还是"对点"，会影响下游所有插件（Blob/卡尺/匹配）的输入语义——这是**流程语义级**变更，需按 R12 走 architect 评审后再实现；
4. 本期范围（A 批 + 网格）已闭环，内参作为下一个独立增量最清晰。
