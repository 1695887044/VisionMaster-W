# 第 0 章 这是什么

**图像赋值 = 把流程图里的一张图，"写进"一个全局变量，让组态画面能显示它。**

> 生活比喻：视觉流程在后台跑，算出一张"检测效果图"。但操作员看的是组态画面（SCADA），流程里的图画面看不到。图像赋值就是那根"数据线"——把流程里的图搬到一个全局变量里，画面上的图像显示图元绑定这个变量，就能实时看到流程在拍什么。

它在流程里的位置（归在 **「图像处理」** 分组）：

```
[图像采集] → [预处理/检测/…] → [图像赋值] →（写入全局变量）
                                            ↓
                                  组态画面「图像显示」图元（绑定该变量）
```

**一句话**：本插件**不做任何图像处理**（零算子），它是"视觉流程 → 全局变量 → 组态画面"这条链路里**唯一的写入口**。

## 0.1 为什么必须要有它

> 在此之前，写全局变量在代码里**根本没有通路**——连线方向只有"读全局变量"，插件拿不到任何写入正门。照着注释写的插件会"**编译通过、运行静默失败**"。

所以本插件的价值不在算法，而在**打通写回通路**。

## 0.2 与「变量赋值」插件的区别

| | 图像赋值（本插件） | 变量赋值 `Plugin.Utility/VariableAssignmentPlugin` |
|---|---|---|
| 写什么 | 只写**图像**（`HImage`） | 写任意值（数值/文本等） |
| 作用域 | 天生只写**全局** | 可选 `Runtime` / `Global` |
| 输入 | `InputImage` + `VariableName` 两个端口 | `Name` / `Value` / `Scope` / `CreateIfNotExists` |
| 自动建变量 | 不支持（必须先建好） | 支持 `CreateIfNotExists`（运行时作用域） |

# 第 1 章 设计思想

## 1.1 核心原理：一次搬运，三步守门

```
流程线程：取图 → 取变量名 → 交给 IGlobalVariableWriter
                                   ↓
                    ① 查名（大小写不敏感，同名以靠前者为准）
                    ② 类型守门（写入值类型必须 ⊆ 变量声明类型）
                    ③ 落值（IWritableVariable.TryWrite）
```

## 1.2 三条设计原则

**原则①：失败必须说话**

空图、空变量名、环境不支持、变量不存在、类型不符——**每一种都要给出可以直接展示给操作员的中文原因**，禁止静默失败。写入结果按 `TryWrite` 的真实返回值如实反馈，**不做"无条件报成功"**。

**原则②：变量是设计期资产，运行期只能写、不能增**

> 为什么不做"变量不存在就自动创建"：插件在运行期悄悄改变量表，会让方案结构随运行结果漂移（跑一次多一个变量），而组态画面绑定的又是设计期那批名字，问题极难复现。

**原则③：类型守门是严格匹配，不做隐式数值转换**

`double` 变量写 `int` 会被拒。理由：**静默的数值拓宽/收窄在工业现场比"报错"危险得多**。

## 1.3 能力契约下沉（架构约束）

插件工程只引用 `Core.Interfaces`，**物理上够不到"变量管理"所在的程序集**。所以：
- 契约 `IGlobalVariableWriter` 放在 `Shard/Core.Interfaces/`；
- 实现 `GlobalVariableWriter` 放在主程序 `Core/Binding/`；
- 通过 `IExecutionContext.GlobalVariables` 暴露给插件（懒建 `??=`）。

依赖方向单向：**插件 → 接口 ← 宿主实现**。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | 图像赋值 |
| `GroupName` | 图像处理 |
| `Description` | 把输入图像写入指定的全局图像变量（配合组态图像显示图元使用） |
| `ShortName` | 图片图标（FontAwesome `f03e`） |

> `[Display]` 特性来自 BCL 的 `System.ComponentModel.DataAnnotations.DisplayAttribute`，仓库内没有自定义 `DisplayAttribute`。

## 2.2 端口完整清单（全部固定端口，无动态端口）

| 端口名 | 属性名 | 方向 | 类型 | 必填 | 说明 |
|---|---|---|---|---|---|
| `InputImage` | `InputImage` | 入 | HImage | ✔ | 要写入的图像。**未连上游则为空 → 运行 Fail** |
| `VariableName` | `TargetVariableName` | 入 | string | ✔ | 目标全局图像变量名 |
| `Success` | — | 出 | bool | — | 基类自带（默认预置 true） |
| `ErrorMessage` | — | 出 | string | — | 基类自带（中文失败原因） |

> ⚠️ **端口名与属性名不一致**：属性叫 `TargetVariableName`，但端口名（连线和落盘用的键）是 **`VariableName`**。按属性名去找会对不上。
>
> ⚠️ **本插件没有任何图像输出端口**——它不"从一个口搬到另一个口"，也不转发图像。

**为什么变量名用文本端口而不是枚举下拉**：
> 既能手填，也能被上游连线驱动（例如由上游节点决定"这一轮写哪个变量"），与"变量赋值"插件保持同一手感。

## 2.3 配置项

**本插件没有任何 `[StepConfig]` 配置属性。** 所谓"配置"就是两个输入端口的手填常量，由基类默认生命周期存进 `StepModel.InputValues`：

| 配置项 | 类型 | 默认 | 存储键 |
|---|---|---|---|
| 目标变量名 | string | `""` | `VariableName` |
| 输入图像 | HImage | `null`（只能连上游） | `InputImage` |

**必填校验的真实判据**（`FlowCompiler.cs:878-887`）：来源有两种——**上游链接** 或 **面板手填常量**。所以：
- `VariableName` 手填后即可通过编译；
- `InputImage` 因为没法手填 HImage，**必须连上游**，否则编译期报 `[参数缺失] … 必填参数 'InputImage' 未配置`。

## 2.4 HALCON 算子：零

> **本插件不调用任何 HALCON 算子。** 全文件对 HalconDotNet 的使用只有两处：`using HalconDotNet;` 与 `image.IsInitialized()`（判空判初始化，不是算子）。
>
> **没有** `copy_image`、**没有** `gen_empty_obj`、**没有**任何 `HOperatorSet.*` 调用。

真正"Halcon 像素 → WPF 位图"的转换发生在**下游显示那一步**：`ScadaValueSource.cs:60-67` 的 `value is HImage image ? HalconImageHelper.ToBitmapSource(image) : value`（注释原文：*"取值出口，也是'Halcon 像素 → WPF 位图'唯一的转换落点"*）。

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **不拷贝、不新建** | 只把 `InputImage` 的引用交给写入器 | ⭐⭐⭐ 零开销、零额外显存 |
| **不 Dispose 任何图** | 所有权仍归生产者 | ⭐⭐ 不会出现双 Dispose / 图被提前释放 |
| **纯文本端口** | 变量名可手填也可连线 | ⭐⭐ 支持"上游决定写哪个变量" |
| **失败必说中文原因** | 五类失败文案齐全 | ⭐⭐⭐ 现场能自查，不用翻日志 |
| **配置界面零代码** | 不实现 `IPluginCustomViewProvider`，走宿主自动端口面板 | ⭐⭐ 整个工程只有 2 个文件、83 行 |

> 本插件工程只有 **`ImageAssignPlugin.cs`（83 行）** + **`Plugin.ImageAssign.csproj`** 两个文件。

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.ImageAssign.dll`（由 `Plugins/Directory.Build.targets` 统一投递，宿主只扫 `Modules\Plugin*.dll`——所以插件 csproj 不需要写 PostBuild）。
2. 重开软件，工具箱里出现「图像赋值」（**图像处理** 分组）。

## 3.2 配置界面

**本插件没有自定义视图**，宿主回退到**自动端口面板**（`AutoPortConfigView`），把所有输入端口列成清单：

```
┌──────────────────────────────────────────────┐
│ ℹ 该步骤没有自定义配置界面，参数如下：          │
│   没有绑定需求时直接填入常量，需要连上游变量     │
│   就点右侧的链接图标。                         │
├──────────────────────────────────────────────┤
│ 要写入的图像          [        ] 🔗 ✕         │
│ 目标全局图像变量名     [        ] 🔗 ✕         │
└──────────────────────────────────────────────┘
```

> 界面上显示的是**端口的 Description**（"要写入的图像" / "目标全局图像变量名"），不是端口名 `InputImage` / `VariableName`。

## 3.3 第一次使用（6 步）

**第 1 步｜先建变量**：在「变量管理」里新建一个**类型为 HImage 的全局变量**（例如 `Img`）。
> ⚠️ 不建则运行必失败（插件不自动创建）。

**第 2 步｜拖节点**：画布拖入「图像处理 → 图像赋值」。

**第 3 步｜连图**：双击打开参数面板，第 1 行「要写入的图像」点 🔗 连上游节点的图像输出。
> 图像**只能连上游**，界面上没有"手填一张图"这回事——这是设计使然：图像只能由视觉流程产生。

**第 4 步｜填变量名**：第 2 行「目标全局图像变量名」**直接手打变量名文本**（如 `Img`），或点 🔗 由上游字符串喂进来。

**第 5 步｜确定**：走 `OnConfirm` 存进 `InputValues`。

**第 6 步｜画面绑图元**：组态画面放「图像显示」图元，绑定该变量。
> 流程每跑一帧，画面就刷新一次。

## 3.4 FAQ

**Q1** 会不会把图复制一份（占内存）？
**不会**。变量持有的是**同一个 HImage 对象引用**，零拷贝。副作用：若上游之后对同一 HImage 实例做**原地修改**，变量里看到的值也会变。需要"冻结某一帧"时应由上游产出新实例。

**Q2** 为什么图像赋值节点后面，上游的图还能继续用？
因为本插件**不 new、不 copy、不 Dispose 任何 HImage**。上游图的所有权仍归生产者，基类的"轮首自动回收"只针对输出端口，而且对"与上游链接同引用"的值会跳过释放。

**Q3** 重启后画面还有图吗？
**没有**。`HImage` 无法 JSON 序列化，**图像变量的当前值不落盘**，重启后为空（画面回落"无图像"）。

**Q4** 变量不存在会自动建吗？
**不会**，必须先在变量管理里建好同名 HImage 变量。这是设计：运行期只能写，不能增。

**Q5** 能把名字写成某个 `object` 变量吗？
技术上可以写进去——本插件**不校验目标变量是不是 HImage**，守门只保证"写入值类型 ⊆ 变量声明类型"。把名字敲错会写进不该写的变量，请注意。

**Q6** 为什么变量名不能用下拉选？
用文本端口既能手填、也能被上游连线驱动（由上游决定这一轮写哪个变量）。

## 3.5 现场排障

| 报错 | 原因与处理 |
|---|---|
| `输入图像为空或未初始化` | 上游没连图，或上游产出的图是空的。**必须连上游** |
| `目标变量名不能为空` | 变量名那格没填 |
| `当前执行环境不支持写入全局变量` | 简化构造（如单元测试容器）没有工作区绑定。**这是设计内行为，不是缺陷** |
| `找不到全局变量「X」，请先在变量管理里新建同名变量` | 变量没建。去变量管理建一个 HImage 类型的 X |
| `全局变量「X」的类型是 Y，无法写入 HImage（值 […]）` | 类型不符。变量声明类型必须是 HImage（或 `object`）。<br>**注**：写入器自 2026-10-10 起会把**文本**值按变量声明类型解析一次（"变量赋值"那类手填界面只能产出文本，`21` 填不进 Int32 就是它），消息里因此带上了被拒的原值；图像这类值不是文本，照旧直接报错 |
| `全局变量「X」不支持写入（该变量类型未实现可写契约）` | 该变量类型不可写 |
| `[参数缺失] … 必填参数 'InputImage' 未配置` | 编译期报错：`InputImage` 没连上游（它没法手填） |

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与开发文档）。每条给：现象 → 原因 → 修法。

## 4.1 缺陷修复总览

| 级别 | 问题 | 一句话 |
|---|---|---|
| P0 | 重复声明 `Success`/`ErrorMessage` 会影子隐藏基类成员 | 表现为"永远报失败且错误信息为空"（CS0108） |
| P0 | 枚举端口经 `InputValues` 往返抛异常 | 变量名改用 string（对照插件踩过） |
| P0 | HALCON `#4056`（图像变量落盘） | 旧实现存 `Value` 会抛，改为只存定义不存值 |
| P1 | 「变量赋值」`IsRequired` 默认值导致节点不可用 | 旧注释口径 vs 当前实现（手填常量也算配置） |
| P2 | 表达式短路缺失 | 不 short-circuit 会把 ErrorMessage 洗成空 |
| P2 | 跨线程写 `ObservableCollection` | `GlobalVariables` 是 UI 绑定的，后台线程插会踩 WPF 跨线程 |

## 4.2 P0/P1 级详解

### ① CS0108：不要重复声明基类已有的端口（本插件最硬的一条注释）

**现象**：**永远报失败且错误信息为空**。

**原因**：基类 `VisionPluginBase` 已声明 `Success` / `ErrorMessage` 同名输出端口并提供 `Fail()` 失败契约。派生类重复声明会**影子隐藏**基类成员——插件写派生端口、引擎读基类端口，两边对不上。

**修法**：本插件**复用基类端口**，不重复声明。注释原文：

> ```
> // Success / ErrorMessage 复用基类端口（基类已声明同名输出端口，并提供 Fail() 失败契约），
> // 本类不要重复声明：重复声明会影子隐藏基类成员，插件写派生端口、引擎读基类端口，
> // 表现为"永远报失败且错误信息为空"（CS0108 教训）
> ```

### ② 枚举端口不能经 `InputValues` 往返（对照插件踩过）

**现象**：方案一打开就炸——`InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'`。

**原因**：`InputPort<T>.Value` 的 setter 对枚举**只做硬转换**，从 `InputValues` 读回来赋给端口时直接抛。

**修法**：端口用 **string** 而不是枚举（本插件的 `VariableName` 就是 string）。string 两端都能无损往返。

### ③ HALCON `#4056`：图像变量不能存值

**现象**：方案保存时抛 HALCON `#4056`。

**原因**：旧实现把图像变量的 `Value` / `DefaultValue` 也序列化了，而 `HImage` 无法 JSON 序列化。

**修法**：图像变量**只存定义、不存值**——落盘时 `Value`/`DefaultValue` 写 null，只保留类型名 `HImage` 与 `VariableId`。代价：重启后画面无图（见 FAQ Q3）。

### ④ `IsRequired` 默认值导致节点不可用（对照插件的历史坑）

**现象**：「变量赋值」插件只要用户没用连线喂参数（也就是正常用法），编译必然报 `[参数缺失] … 必填参数 Name/Value/CreateIfNotExists 未配置`，**这个节点等于用不了**。

**原因**：`InputPort.IsRequired` 默认就是 `true`，而**旧版**编译期检查只看"有没有连线"，不看有没有填值。

**当前实现**：`FlowCompiler.cs:878-882` 已加 `hasConstant` 判据——**手填常量也算配置**。所以现在手填即可通过编译（旧注释口径已过时）。

## 4.3 代码级踩坑汇编

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | 永远报失败且错误为空 | 重复声明基类端口（CS0108 影子隐藏） | 复用基类 `Success`/`ErrorMessage` |
| 2 | 打开方案就炸 `InvalidCastException` | 枚举端口经 InputValues 往返 | 端口用 string |
| 3 | 存盘抛 `#4056` | 序列化了 HImage 的值 | 只存定义不存值 |
| 4 | ErrorMessage 被洗成空 | 没短路 | `return;` 必须紧跟 Fail |
| 5 | 跨线程异常 | `GlobalVariables` 是 UI 绑定的集合 | 明确报错并给中文原因（不做跨线程插入） |
| 6 | 编译报"必填参数未配置" | 旧版只看连线不看手填 | 手填常量也算配置（已修） |
| 7 | 变量悄悄变多 | 运行期自动创建 | 运行期只能写不能增 |

## 4.4 已知边界与待办

- **类型守门严格匹配**，不做隐式数值转换（`double` 变量写 `int` 会被拒）。
- **变量不存在不自动创建**，必须先在变量管理里建好同名 HImage 变量。
- **简化构造无工作区时写入必失败**（设计内行为，不是缺陷）。
- **写入的是引用，不是快照**：上游原地修改同一 HImage 会影响变量。需要冻结某一帧应由上游产出新实例。
- **图像变量的当前值不落盘**，重启后为空。
- **不校验目标变量是不是 HImage**：守门只保证"写入值类型 ⊆ 变量声明类型"。
- **跨线程**：`GlobalVariables` 是 UI 绑定的 `ObservableCollection`，流程跑在后台线程上，从插件路径往里插会踩 WPF 跨线程。当前行为是明确报错并给中文原因。
- **`FlowCanvasChecks/` 没有本插件专属断言文件**（见 5.5）。
