# 桌面端测试双身份契约（planner / runner）

> **适用**：VisionMaster 桌面端（WPF / net9.0-windows）的功能测绘与测试执行。
> **上位规则**：`AGENTS.md`（R175/R176/R177/R179/R182/R183/R185）与 `docs/AI操作计划/README.md`（§5 计划格式、§9 已知坑、附录 B 豁免）。
> **角色定义位置**：`.zcode/agents/vm-test-planner.md`、`.zcode/agents/vm-test-runner.md`。角色定义归客户端；本文件只留**交接契约**，DSH 等其他客户端可直接复用。
> **版本**：1.0 · 2026-10-26。

---

## 1. 两个身份

| 身份 | 一句话职责 | 交付物 |
|---|---|---|
| **planner**（功能测绘 + 计划下达） | 查清软件有哪些功能、哪些没被覆盖，把缺口排成一轮可执行的测试 | `plans/*.json`、`ui-map.json`、`TASKS.md`、批次单 |
| **runner**（测试执行） | 按批次单机械执行、逐步断言、留证据、报状态 | 日志/截图/UIA dump、批次汇总、交接报告、台账更新 |

一句话分界：**planner 决定"测什么、怎么判"，runner 只回答"这一条跑成了没有"。**

```text
功能测绘（源码/帮助/计划库）
        │
        ▼
   planner ──► 批次单 + vm-plan/1 + ui-map + TASKS
        │
        ▼
   runner ──► 断言宿主 / 探针 / UIA 真 exe
        │            │
        │            ├─ 选择器缺失 ──► MISSING_SELECTOR ──► planner
        │            ├─ 计划本身错 ──► PLAN_DEFECT ───────► planner
        │            ├─ 环境不满足 ──► BLOCKED ───────────► 用户/主会话
        │            └─ 需真实手势 ──► BLOCKED_NEEDS_MAIN ► 主会话
        ▼
  证据（artifacts）+ 交接报告（docs/架构文档/交接报告/）+ 台账更新
```

## 2. 职责矩阵与文件所有权

| 文件 / 目录 | planner | runner | 说明 |
|---|---|---|---|
| `docs/AI操作计划/plans/*.json` | **写** | 只读 | runner 发现错误只报告，不就地改 |
| `docs/AI操作计划/ui-map.json` | **写** | 只读 | 新增选择器必须有 dump 或源码来源 |
| `docs/AI操作计划/TASKS.md` | **写** | 只读 | 说法 → 计划 ID → 参数 |
| `docs/AI操作计划/README.md` §3/附录 | **写** | 只读 | 功能清单与豁免清单 |
| `docs/AI操作计划/batches/*.md` | **写**（新版本） | 只读 | 批次单不可被 runner 改写；有错出新版本 |
| `artifacts/logs/**`、`artifacts/render/**` | 只读 | **写** | 执行证据 |
| `docs/工程纪律/分册-AI操作与exe测试踩坑.md` | 只读 | **写** | runner 收工必须更新（R185） |
| `docs/架构文档/交接报告/**` | 只读 | **写** | runner 收工必须写（R177） |
| 产品源码（`VisionMaster/`、`Core/`、`Plugins/` 等） | 不写 | 不写 | 产品缺陷只报告 |

**为什么批次单不可改**：执行期改计划会让"这条到底按哪版跑的"无法追溯。计划有错就出 `v2` 批次单，旧版保留。

## 3. 交接物一：批次单

位置：`docs/AI操作计划/batches/<yyyyMMdd>-<主题>.md`，索引在 `batches/README.md`。

```markdown
# 批次单 <batch-id>（v1）

## 1. 目标
<一句话：本轮要证明什么>

## 2. 范围
| 功能 ID | 功能 | 覆盖现状 | 本轮动作 |
|---|---|---|---|
| A-01 | 新建方案 | L3 `solution-new` | 执行 |
| D-07 | 修改变量当前值 | L4 无判据 | 补计划（或：不测，理由…） |

## 3. 执行项（按顺序）
| 顺序 | 计划 ID | 参数 | 风险 | 证据要求 | 中止条件 |
|---|---|---|---|---|---|
| 1 | `solution-new` | `solution_name=Test_20261026` | low | 顶栏方案名 + toast | 顶栏未变 |

## 4. 不测项及理由
| 功能 ID | 理由分类 | 替代验证 |
|---|---|---|
| I-05 | 运动会驱动真实机械 | 人在现场点动 |
| J-01 | 密码只走运行时输入 | 人工登录 |

理由分类只用四类（对齐 README 附录 B）：
`运动会驱动真实机械` / `凭据与身份` / `没有稳定可观察判据` / `结果落在外部对象上`。

## 5. 选择器缺口
- `missing_selector`: <界面> / <控件描述> / <建议来源：dump 或源码 AutomationId>

## 6. 环境与前置
- VisionMaster 已启动且只有一个实例；无流程在跑
- 端口 19000/19100/8080 空闲
- 方案：<路径>；账号权限：<不需要 / 现场输入>

## 7. 退出条件
- 每个执行项都有状态（PASS/FAIL/BLOCKED/UNVERIFIED/SKIPPED/NOT RUN），不允许空白
- 失败项有失败步号、期望、实际、证据路径
- 台账与交接报告已更新
```

**批次单自检**：每个功能 ID 都能在 README §3 找到；新增 ID 已补表；没有"看情况""适当""必要时"。

## 4. 交接物二：单条计划的可执行性

runner 拿到一条计划，只允许依赖计划文件本身 + `ui-map.json` + 批次单。planner 必须保证：

- [ ] `schema=vm-plan/1`；`id` = 文件名；`n` 连续；`version` 为 `x.y.z`
- [ ] 所有 `${var}` 已在 `params` 声明（或内置三变量）
- [ ] 每个 `target` 都在 `ui-map.json`；未校准的 `confidence=low` 并写来源
- [ ] 每个动作步有可观察 `expect`（`key/note/screenshot` 除外）
- [ ] `risk=high` 有计划内二次确认；`on_fail=stop_and_report`
- [ ] 无密码/令牌/坐标/硬编码用户目录
- [ ] 组合任务用 `call`，不复制子计划步骤

任一不满足，runner 直接报 `PLAN_DEFECT`，不执行。

## 5. 状态词汇（唯一口径）

| 状态 | 判据 | 能否算完成 |
|---|---|---|
| `PASS` | 所有步骤 `expect` + 后置断言成立，证据齐全 | 是 |
| `FAIL` | 某步 `expect` 不成立，有失败步号与证据 | 否 |
| `BLOCKED` | 前置不满足（进程/端口/方案/设备/权限/选择器） | 否 |
| `UNVERIFIED` | 执行了但无可观察证据 | **否**，不得折算成 PASS |
| `SKIPPED` | `skip_if` 成立，且理由可反证（R38） | 否，但可接受 |
| `NOT RUN` | 没执行 | **否**，必须与 PASS 分开统计（R183） |

汇总行必须写六类计数；只写"全部通过"视为无效汇报。

## 6. 升级路径

| 情况 | 标记 | 接手方 | 处理 |
|---|---|---|---|
| 选择器找不到/失配 | `MISSING_SELECTOR` | planner | 补 `ui-map`（dump 或源码来源），出新批次单 |
| 计划步骤错/缺参数 | `PLAN_DEFECT` | planner | 升 `version`，出新批次单 |
| 进程/端口/设备/权限/方案不满足 | `BLOCKED` | 用户或主会话 | 恢复环境后重跑 |
| 需要真实鼠标手势/视觉验收 | `BLOCKED_NEEDS_MAIN` | 主会话 | 主会话用 computer-use 执行该段 |
| 产品行为与计划/文档不符 | `PRODUCT_DEFECT` | 用户 | 只报告，不自行改码 |

**computer-use 仅主会话可用**，所以 runner 不得声称自己完成了拖拽、长按、画布双击、框选这类步骤。

## 7. 证据与落点

| 证据 | 路径 |
|---|---|
| 计划执行日志 | `artifacts\logs\<yyyyMMdd>\plan-<id>.log`（原始字节落盘，UTF-8 无 BOM） |
| 批次汇总 | `artifacts\logs\<yyyyMMdd>\batch-<batch>-summary.md` |
| 失败截图 | `artifacts\render\<yyyyMMdd>\<batch>\<id>-step-<n>.png` |
| UIA dump | `artifacts\logs\<yyyyMMdd>\uia-<id>-step-<n>.txt` |
| 布局/配置备份 | `artifacts\backup\<yyyyMMdd>-<主题>\` |
| 交接报告 | `docs\架构文档\交接报告\交接报告-<yyyyMMdd>-<主题>.md` |
| 踩坑台账 | `docs\工程纪律\分册-AI操作与exe测试踩坑.md` |

**禁止**：在仓库根写日志（R166）；用 `Start-Process` 跑被测进程（R183③）；管道捕获子进程输出（R183①）；零输出判绿（R183②）。

## 9. 维护口径

- 本契约只写**两身份之间不变的东西**：所有权、交接格式、状态词汇、升级路径。具体命令与坑位放各自角色文件与台账，避免三处各写一份。
- 批次单是**日志式产物**：只追加新版本，不改旧版本；`batches/README.md` 负责索引。
- 角色文件改动不需要动本契约；契约改动必须同时检查两个角色文件是否仍一致。
- 本文件被 `docs/AI操作计划/README.md` 引用；新增批次单后同步 `batches/README.md`，否则 `tools\audit_docs.ps1` 会报 ORPHAN。
