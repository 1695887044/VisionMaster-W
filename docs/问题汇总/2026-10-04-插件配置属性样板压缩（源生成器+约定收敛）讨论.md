## 1. 背景与术语澄清

需求方提出：插件类内 `[StepConfig]` 配置属性与 `InputPort<T>` / `OutputPort<T>` 端口声明占据大量行，希望优化。主会话派 architect / vision / hmi / Explore 四个角色只读分析后，需求方已拍板路线：**源生成器（partial property 写法）+ 约定收敛**。

用户口语与仓库准确术语的对照：

| 用户口语 | 仓库准确术语 | 说明 |
|---|---|---|
| "保持型变量 / 跟随进方案" | `[StepConfig]` 配置属性 | 随 .vms 方案文件经 `InputValues` 落盘，**键 = 属性名**；不暴露为端口、不进数据流 |
| "输入输出变量" | `InputPort<T>` / `OutputPort<T>` | 数据流端口，参与连线与编译期类型检查 |

> 注：仓库既有术语中**没有"保持型"这个说法**；全仓唯一命中是第三方库的 Modbus"保持寄存器"（与本议题无关）。

## 3. 候选方案与裁决

| # | 方案 | 裁决 | 理由 |
|---|---|---|---|
| 1A | 生成器·字段标记式（`[StepConfig] private double _x = 默认;`） | ❌ | 需改 `AttributeUsage`（放开字段）；字段 → 属性名映射有风险；生成器失效时**静默坏**（无编译错误，危害最大） |
| 1B | 生成器·partial property 式（`public partial double X { get; set; }` + 默认值特性） | ✅ **推荐** | 零契约改动；缺失实现是**编译期硬错误**（fail-fast） |
| 2 | 契约层 helper（`In<T>()` / `Out<T>()`） | ❌ | 收益 ≈ 0（端口声明已是 1.39 行/个） |
| 3 | 声明式集中注册 | ❌ | 破坏四处契约：反射发现 / 动态端口 / public 字段防呆 / AutoPortConfigView；且总行数不减（只是搬家） |
| 4 | 纯约定收敛：45 条无副作用 setter → 自动属性 | ✅ 作为配套 | 仅限**无绑定 / 无程序化写入依赖**者；~100–150 行 |

## 4. 推荐方案设计

### 4.1 目标写法与生成物示意

目标写法（插件源码侧只写声明）：

```csharp
[StepConfig, DefaultValue(DefaultMinScore)]
public partial double MinScore { get; set; }

// 可选钩子（需要副作用时手写；不写则被编译器消除）
partial void OnMinScoreChanging(ref double value);
partial void OnMinScoreChanged(double value);
```

生成物（示意，由源生成器发射，与手写声明同在同一个 partial class 内）：

```csharp
private double _minScore = DefaultMinScore;

public double MinScore
{
    get => _minScore;
    set
    {
        OnMinScoreChanging(ref value);
        SetProperty(ref _minScore, value);   // INPC 由基类 ObservableObject 提供（ObservableObject.cs:34）
        OnMinScoreChanged(value);
    }
}
```

> 钩子调用时序、OnChanged 是否仅在值变化时触发等细节属完整版设计，随拍板定稿；上例为**形态示意**。
> 旧写法与新写法**可同文件共存、逐属性迁移**（不需要一次性全量切换）。

### 4.2 生成器规模与"是否重写"（用户核心问题）

- 是**全新小工程、从零写**（仓库无任何生成器 / analyzer 先例）。
- **不改现有任何代码**（`VisionPluginBase` 反射逻辑、宿主、契约全部不动）。
- 生成器只在**编译期**运行；插件 DLL 里产出的是普通属性实现，**运行期零痕迹**。

文件与行数**估算**：

| 组成 | 估算行数 |
|---|---|
| csproj | ~25 |
| 增量管线 / 谓词 | ~80 |
| 语义提取模型 | ~100 |
| 发射器（字段 / 属性 / 钩子 / 可空处理） | ~180 |
| 诊断（缺 partial、命名冲突报 Error 等） | ~70 |
| **合计** | **~450（粗估区间 350–500，含注释）** |
| 另有：`Plugins\Directory.Build.props` 一次性接线 | ~10 |
| 可选：契约反射 diff 检查工具 | ~100–200（M1 可先用一次性检查替代） |

形态取舍（**留待拍板**）：

| 形态 | 生成器规模（估算） | 首批净收益（估算） | 说明 |
|---|---|---|---|
| 完整版（含钩子） | ~450 行 | 净省 ~400–650 行 | 可覆盖自定义 setter 的迁移 |
| 精简版（无钩子） | ~250–300 行 | 净省 ~100–150 行 | 仅覆盖 45 条纯 SetProperty + 未来新代码 |

**诚实备注**：一次性成本与首批收益量级相当（~450 行 vs ~400–500 行）；长期收益在"插件代码结构持续变薄 + 新代码永久受益 + 写法统一"。

### 4.3 技术要点与探针结论（来源与局限）

| 项 | 结论 | 来源与局限 |
|---|---|---|
| C# 13 partial property 可行性 | 跨部分声明、`[StepConfig]` 反射可见、`SetProperty` / INPC 触发、未实现钩子被编译器消除 | 架构角色在 %TEMP% 隔离探针得出（**仓库外**） |
| partial 定义声明不能带初始化器 | CS8050 → 默认值必须用特性承载 | 同上（**仓库外**） |
| 默认值载体 | 复用 BCL `System.ComponentModel.DefaultValueAttribute`：本会话用 `dotnet fsi` 实测 net9.0，Double/Int32/Int64/Boolean/String/SByte…UInt64/Decimal 构造齐全；**无 DateTime 构造** → DateTime 类默认值保持手写；枚举走整型构造 + 生成时强转；`string.Empty` → `""`；集合 `new()` 默认值（12 处）保持手写 | 本会话 fsi 实测（**仓库外**） |
| 生成器在 WPF `UseWPF` 双编译下的行为 | 主编译 + wpftmp 两次编译下均执行；Analyzer 引用不把生成器 DLL 带进输出 | %TEMP% 探针（**仓库外**） |
| 约定不符的处置 | 缺 partial、命名冲突 → 报编译 **Error**（fail-fast，不静默跳过） | 方案设计约定 |
| **局限** | 以上探针均来自**仓库外 %TEMP% 隔离工程**；**仓库内尚未构建验证**（列入 M1 验收） | — |

### 4.4 插件侧迁移形态

两个"旧 → 新"对照（**形态示意，非仓库现成迁移样例**）：

纯 SetProperty 型：

```csharp
// 旧写法（多行）
private double _threshold = 0.5;
[StepConfig]
public double Threshold
{
    get => _threshold;
    set => SetProperty(ref _threshold, value);
}

// 新写法（单行声明，实现由生成器产出）
[StepConfig, DefaultValue(DefaultThreshold)]
public partial double Threshold { get; set; }
```

带副作用型（副作用挪到 OnChanged 钩子）：

```csharp
// 旧写法
private bool _enabled = true;
[StepConfig]
public bool Enabled
{
    get => _enabled;
    set
    {
        if (!SetProperty(ref _enabled, value)) return;
        OnPropertyChanged(nameof(ShowHint));
        SchedulePreview();
    }
}

// 新写法
[StepConfig, DefaultValue(true)]
public partial bool Enabled { get; set; }

partial void OnEnabledChanged(bool value)
{
    OnPropertyChanged(nameof(ShowHint));
    SchedulePreview();
}
```

强调：迁移以**"删行"为主**；属性名 / 端口名 / XAML 绑定名 / .vms 键名**全部不变**。
不在本次迁移范围（见 §5 手写边界）：需读取旧值、成对替换 setter、集合默认值等形态。
