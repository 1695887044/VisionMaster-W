## 3. 问题清单

### P1 · CSV 写盘失败不阻断、错误日志延迟（高）

**现象**：`Test_DataEdge` 把 `DirectoryTemplate` 设为 `Z:\NoSuchDrive\{StepName}\`、`BlockOnFailure=true`，步骤仍返回 `Success=true`；`Z:` 盘不存在，实际没有写出文件。

**根因**：
- `BlockOnFailure` 只覆盖 `RecordingHub.Enqueue` 的“队列满/关停”两种入队失败（`DataRecordPlugin.cs:416`）；
- 实际写盘在后台写线程，`RecordingHub.ProcessBatch` 的异常被 `Log("ERROR", ...)` 收进静态队列；
- `RecordingHub.Logs` 只在**下一次** `DataRecordPlugin.RunAlgorithm` 开头被 `TakeLogs()` 排空（`DataRecordPlugin.cs:340`）。

**证据**：
```
02:29:58.185 [ERR] [数据记录] 批量写入异常: Could not find a part of the path 'Z:\NoSuchDrive\Test_DataEdge.CSV坏路径(应失败)'.
```
这条错误在 **02:32:12** 的 `Test_Report` CSV 步骤执行时才被转交到应用日志——如果之后没有 CSV 步骤，它就只留在静态队列里。

**影响**：勾了“写入失败阻断流程”的用户会以为账已记上，实际丢行且当场看不到错误。

**建议**：给 `RecordingHub` 一个宿主日志 sink（或写盘结果回执），至少让异步错误在发生时就落应用日志；文档明确“`BlockOnFailure` 不覆盖异步写盘”。

### P2 · CSV 的 `Variable` 列读不到全局变量（中）

**现象**：`Test_Report` 第一版直接引用 `EdgeCommOk` 等**全局**变量，CSV 行除时间外全空；改成先用 `变量赋值` 复制到 `Rpt_*` 运行期变量后才有值。

**根因**：`RecordColumnDef` 的 `Source=Variable` 从 `context.LocalVariables` 取值，不是全局变量池。

**影响**：用户在列定义里选全局变量时不会报错，只会得到空列。

**建议**：列编辑器只列运行期变量并给提示，或让 `Variable` 来源同时支持全局变量；文档补一句。

### P3 · 错误令牌间歇性无 HTTP 响应（中）

**现象**：错误令牌连续 5 次，得到 `401, 000, 401, 000, 000`；`000` 表示 curl 没有收到 HTTP 响应。正确令牌随后仍 200。

**影响**：客户端若只按 401 判断鉴权失败，会把“连接被关闭”当成网络故障；重试策略可能误判。

**建议**：统一鉴权失败出口为 401（带 JSON body）；客户端同时处理 401 与连接失败。当前 `HttpImageServer.Authenticate` 返回 `AuthenticationResultEnum.NotFound`，建议核实 Watson 对该枚举的连接处理。

### P4 · 无效轴提示截断，隐藏有效轴（低，已修）

**现象**：32 轴卡上输入无效轴 `Q`，提示“现有轴：A10…A31 等 32 个”，完全看不到 X/Y/Z；用户会误判“X/Y/Z 没配置”。

**根因**：`MotionAxisRegistry.HintNames()` 用 `Take(12)` 截断，逻辑轴排在物理轴名之后。

**修法**：上限改为 64；实测提示已包含 `…、X、Y、Z`。修改文件：`Shard\Core.Interfaces\Motion\MotionAxisRegistry.cs`。

### P5 · 启动方案加载失败无诊断（中，待确认）

**现象**：`StartupSolutionPath` 指向损坏 `.vms` 或不存在的 `.vms`，进程均存活（未崩溃），但 02:37 启动段日志中没有该路径的加载记录，工作区以空方案启动。

**影响**：现场只看到“方案没打开”，无法从日志判断是路径错、文件损坏还是被跳过。

**建议**：启动加载失败至少写一条 `[方案] 启动方案加载失败：{path} / {reason}`，并在 Splash/主界面提示；补一条断言宿主。

### P6 · 重复运行内存缓慢上升（低，观察）

**现象**：40 次 `Test_Vision`：577.8 → 685.2（5 次）→ 682.9（10）→ 687.4（15）→ 694.3（20）→ 695.8（25）→ 738.7（30）→ 748.4（35）→ 751.6 MB（40）。另一轮 20 次从 924.4 → 1122.3 MB。

**判断**：图像集上限 300 帧，内存大部分时间平台化；末段有台阶，可能与 HALCON 缓冲/UI 缓存/GC 有关。未触发 2 GB 守卫。

**建议**：做 100+ 次长跑并记录 `GC.GetTotalMemory`、HALCON 句柄数、图像集当前帧数；当前不判定为泄漏。

### P7 · 已知边界（非本轮新发现）

| 项 | 说明 |
| --- | --- |
| `MotionWait` | 虚拟卡到位后 `InPosition` 不置位，等待步骤超时；位置判据不受影响 |
| VPLC532R 回零 | 驱动标成总线型，`轴回零` 走 `ZAux_BusCmd_Datum`；轴 0~5 是 Step Encoder，回零可能失败 |
| 循环运行 | `RunAllEnabledContinuous()` 会并发跑所有启用流程；测试台不要点主界面「循环运行」 |
| 多流程共享变量 | 所有测试共用全局变量与 `TestSummary`；只能逐条运行 |
| 测试并发 | 同一流程并发：200 + 409；不同流程可同时跑，但共享变量会互相覆盖 |

## 6. 结论

- **功能面**：原有 5 条测试流程全部回归通过；新增 5 条边界流程中 4 条全通过，`Test_DataEdge` 的 CSV 坏路径暴露了 P1。

- **最值得先处理的三件事**：① P1 CSV 写盘失败不可见；② P3 鉴权失败偶发无响应；③ P5 启动方案加载失败无日志。P4 已修并验证。
