- 日期：2026-10-05
- 范围：流程引擎全域（`Core\Models\*`、`Core\IFlowEngine.cs`、`Core\ExecutionContext.cs`、`Engine\*`）+ 与引擎交界的宿主面（`VisionMaster` 的运行入口 / HTTP / 图像集 / 流程管理 / 退出链）+ 契约与落盘面（`Shard\Core.Interfaces`、`SolutionService`、插件面）
- 方法：**6 个只读子智能体 / 两轮**
  - 第一轮（并行 4 视角）：A 并发与生命周期、B 编译与执行语义、C 架构/性能/宿主交界、D 契约/落盘/插件面；
  - 第二轮：E 对 7 条最高影响发现**逐条取证与反驳**；F **对抗性补盲**（审第一轮未覆盖的面 + 试图推翻第一轮的"没问题"结论）。

## 一、总体结论

**引擎的"骨架质量"高，但"触发入口的收口"欠账明显；另有一批静默错结果的缺陷，其中一条把既有断言的 14 条失败从"环境缺件"重新归因为产品缺陷。**

1. **骨架可信**：会话锁（抢锁即原子、最外层 finally 归还）、订阅者异常隔离、通知不递增版本（`[RuntimeState]` + 判等 + 批处理）、调试门（停点先合锁再通知、离开门兜底放行）——四项都有断言现场做过"捣乱实验"（[E4]/[E9]/[E5]/[E13]），两轮复审**都没找到"锁永久泄漏"或"状态赋值不唯一"的反例**（C2 未推翻）。
2. **主要风险集中在"谁把流程跑起来"这条链**：五种触发入口（界面/HTTP/定时/变量/子程序）里，"会话准备 + 门禁 + 成功/失败口径"有 **9 份复制**，已经产生真实漂移：HTTP 与界面两处仍把"没跑上/跑挂了"报成成功（3 个智能体独立命中，复审升级：HTTP 的成功是**无条件**的，500 分支是死代码）。
3. **静默错结果类缺陷仍有一批**：绑定不涨版本跑旧图纸、未连线条件取默认值、上游失败下游读陈旧值、数组下标丢失、跨方案同名流程复用旧引擎、C# 脚本必然编译失败。
4. **重大纠偏**：`_dwv_fail_lines_baseline.txt` 的 19 条基线里，线序组 14 条的主因**不是环境缺件**——是 `Plugin.CSharpScript` 把宿主目录里的原生 DLL（onnxruntime）当托管元数据引用 → `CS0009` 必然失败（F1，已用探测工程复现）。**基线必须按"含产品缺陷"对待。**

## 二、P0 级（会对外输出错数据 / 静默跑错图纸）

### P0-1 「假成功」族：触发入口把"没跑上 / 跑挂了"报成成功
- **面 1（HTTP，3 票 + 复审升级）**：`VisionMaster\Services\HttpImageServer.cs:240` 只做非原子预检 `if (session.IsRunning) 409` → `:246` 调 `RunSessionOnceAsync`（`Engine\FlowEngineService.cs:428-429` 丢弃 `TryRunSessionOnceAsync` 的 bool）→ `:270` 无条件收集输出并回 `success=true`。复审补充两条更可达的面：① 引擎异常在 `:503-511` 被就地吞掉后仍 `return true`，`:264-268` 的 500 分支**是死代码**（跑挂了也回 200）；② `TryBuildSession`（`:304-371`）在"同名旧会话在跑"时 `RegisterSession` 会 `StopSessionGracefully` **杀掉正在跑的会话**（`Engine\IRuntimeManager.cs:149-182`），窗口是"编译时长"量级（毫秒~百毫秒），比微秒级 TOCTOU 可达得多。
- **面 2（启动窗口，F4）**：抢到锁（`:448`）与置 `IsRunning=true`（`:468`）之间，`RemoveAndDispose` 可 Dispose 会话 → `session.PauseLock.Set()`（`:463`，**无 ODE 防护**，而收尾处的同类调用有）抛 `ObjectDisposedException` → 被 catch 吞 → 仍 `return true`。
- **面 3（界面，复审补）**：`ShellViewModel.cs:1026`、`ViewModels\FlowListViewModel.cs:298` 同样丢弃 bool → 界面"提示已启动、实际没跑"。
- **理由（为什么是 P0）**：本仓库自己的判词——"绿着走错分支比红着崩溃危险"。HTTP 是对外接口，错数据直接进上位机/PLC。
- **最小修法**：HTTP 改调 `TryRunSessionOnceAsync`（false→409）+ 收集前校验 `session.State == Faulted`→500 + 补编译前判"旧会话在跑就拒绝替换" + 启动准备段整体 ODE 防护（被替换时返回 false）+ `ImageHub` 在注册/切方案/退出时清槽。

### P0-2 绑定弹窗直写 `LinkedSources` 不递增 `FlowModel.Version` → 已编译会话继续跑旧连线
- 证据：`ViewModels\DialogViewModels\VariableBindingViewModel.cs:63/458/479` 三处裸写字典；只有 `StepModel.SetLink/RemoveLink`（`Core\Models\ProcessStep\StepModel.cs:322-339`）发通知，而 `FlowModel` 的版本递增**唯一**来自步骤 `PropertyChanged`（`Core\Models\FlowModel.cs:479-485`）；五个运行入口的判据都是 `Version > CompiledVersion`。
- 复审限定：仅当该流程**已有旧会话**时才跑旧图纸（无会话会现编译）；画布解绑与条件编辑器保存都已各自补了通知/版本，**唯独这个弹窗漏了**（属遗漏而非设计）。
- 理由：用户"刚绑的线不生效"且界面看起来是好的——静默错结果。
- 最小修法：三处改走 `SetLink/RemoveLink`（约 10 行）+ 一条断言（绑定写回后 `Version +1`）。

## 四、P2 级（按主题归并）

**并发细节**：`FlowTimerScheduler._lastFireUtc` 无锁（计时器线程写 vs UI 线程 `Clear`）且遍历 UI 可变集合未快照（变量触发服务已修，口径不一）；`ResourceLockService` 条目永不回收、`ReleaseAllLocks` 无调用者且并发时漏放；`StopSessionGracefully` 超时后"摘会话但不 Dispose（无日志）"导致新旧循环短暂并存；`FlowVariableTriggerService` 在门锁内做编译/注册（写变量的第三方线程可能被卡数百 ms~3s）；`StopSession` 与启动之间"停止请求可能丢失"的微窗口（H8，命中需并发踩点）。

**性能与日志**：每节点每轮约 2-4 次运行态通知（量级已量过，判"不值得改结构"）；`ImageGallery.Recompute` 每帧全量重建（值得做增量，先测量）；日志**无节流/无级别过滤**、每行一次 flush、UI 侧无上限集合，`_droppedCount` 声明后从未自增（"丢日志计数告警"没实现）；`PerformanceMonitor` 是只写不读的死设施且语义矛盾（`TotalDurationMs` 被覆盖）。

**可观测性**：手动运行无日志、HTTP 无来源 IP、**鉴权失败完全不记日志**、`StopSessionGracefully` 全程静默 → "谁触发的、为什么没跑"在这几条链上查不到（定时/变量/子程序三链已达标）。

**编译执行细节**：For 无运行期迭代上限（While 有 9999）；Break/Continue 不回报状态、`StepState.Warning/Cancel` 从未被赋值；容器状态不聚合子步骤失败；While/For 只编译 `Children.FirstOrDefault()`（多余分支静默丢弃，与 `FlowTopology` 口径不一）；常量类型不匹配会"炸穿编译"成无定位错误；插件灌值 `catch` 静默吞；`LocalVariables` 的作用域语义（每轮一份/无隔离/子流程隔离）无注释。

**死代码与契约**：`PreRunCheck`/`DoCompile` 死代码（"图纸改了是否重编译"只剩死实现）；`RunSessionOnceAsync` 与 `TryRunSessionOnceAsync` 并存（丢 bool 的新调用点仍有 3 处）；`UnregisterSession`/`ReleaseAllLocks`/`RuntimeVariableRefs`/`FlowModel.TriggerMode` 均无生产消费方；`ExecutionContext.Logger` 是唯一没有非空兜底的能力；`FlowTopology`/`CompileSteps` 等递归无环标记（当前无"从文件造环"入口）；插件无版本声明（新插件 + 旧宿主会在首次调用新成员时 `MissingMethodException`，扫描期不报）。

**迁移与草稿**：加载时的迁移改写（位集换算/骨架补齐/补 Id/分支归一化）让"内存 vs 磁盘逐字比较"**必然判脏** → 老方案每次启动弹恢复提示、退出多一份草稿；草稿**不含**「变量管理」里未保存的改动。

**插件面**：`PluginService` 单个类型实例化失败会拖垮同一 DLL 的其余类型，且 `ReflectionTypeLoadException` 只报通用 Message（缺 `LoaderExceptions`）；`Plugin.RunFlow` 无流程名候选下拉（端口是纯文本）。

## 五、复审对第一轮的修正与反驳结果

## 六、建议路线（按收益/代价比，理由附后）

**第一批——现在做（半天内，全部是小改 + 有现成断言可扩）**
1. **触发入口"假成功"族收口**：HTTP 改 `Try*` + 409/500 如实返回 + 会话替换守卫（旧会话在跑就拒绝）+ 启动准备段 ODE 防护 + `ImageHub` 清槽。*理由：唯一对外输出错数据的缺陷；修法与 `FlowInvoker`/`FlowAutoRunner` 既有正确写法同形。*
2. **绑定弹窗改走 `SetLink/RemoveLink`** + 一条断言。*理由：一行级改动堵住"跑旧图纸"，且能顺手把"写模型一律走会通知的 API"这条纪律钉进断言。*
3. **C# 脚本原生 DLL 过滤**（`PEReader.HasMetadata` 判托管；10-20 行）+ 重建插件。*理由：一次恢复 C# 脚本可用性、把基线 19 条降到约 7 条，并纠正"环境缺件"的错误归因。*
4. **退出链 `Task.Run` 包一层**（1 行）+ 修正相机模块注册序（先停服务再断设备）。*理由：一个卡住的 Dispose = 关不掉软件 + 丢草稿/日志，而现在超时是纸面上的。*
5. **运行中守卫扩展到改名/删除流程**（几行）。*理由：消灭"停止够不着"的孤儿会话。*

**第二批——下一期（一批语义修复 + 一次结构收口）**
6. **`FlowRunCoordinator` 收口 9 份会话准备**（统一门禁矩阵/失败口径/触发来源），并把 `RunSessionOnceAsync` 标 `[Obsolete]`。*理由：本轮所有"入口漂移"结构性根因；收口后新触发源/新门禁只动一处。*
7. **跨方案会话治理**：陈旧判据并入 `FlowID`（或方案身份），切方案时 `UnregisterSession`/`ClearAll`。*理由：堵住"静默跑别的方案的图纸"这类最危险静默故障。*
8. **三件语义修复**：未连线条件变量（先警告、老工程兼容）、上游失败/未执行的输出失效、数组下标写入 `TargetPortName`。*理由：都是"绿着用错数据"，与仓库自己的判词同源；每条都便宜且有断言位。*
9. **加密语义定死**：真加密，或改名"锁定/防误改" + 加密时强制清 `Http` 位 + HTTP 补 403 + 文档写明非机密性保护。*理由：对用户信任伤害最大的口径缺口，二选一即可闭环。*

**第三批——以后做（条件触发）**
10. 试运行容器分支体（复用 `RunSequence` 语义）、`MainRunState` 并入"是否有活动会话"以点亮停止键、日志节流 + 丢日志计数、性能监控"删或接"、`ImageCollectionService` 归属改按会话、迁移基线快照消除草稿误判 + 退出前 `Capture` 变量、`ImageGallery` 增量重建（先测量）。

**明确不做（并给理由）**
- 消息队列 / 工作流引擎 / actor 模型：单机几十条流程，引入要付序列化、跨进程停止语义、部署排障三重成本，无现场收益。
- 编译产物增量缓存：全量编译是毫秒级且只在版本变化时发生；增量要处理端口重链与插件实例复用，复杂度远大于收益。
- 每流程一个计时器：现行"单节拍源 + 时间戳判定"既好收尾又好测，别回退。
- HTTP 改排队等会话：与"错过不补跑"口径冲突，会让产线节拍雪崩。
- 每步状态 60fps 节流/拉取式 UI：牺牲"看见跑到哪"的调试价值；先量 UI 线程耗时再谈。
- 运行态/配置态彻底分离（`StepRuntimeTable`）：收益真实（一次性消掉"忘打 `[RuntimeState]`"这类坑），但改动画布与流程栏绑定链，风险中高——**等运行期属性还要再加或流程量上来时再做**。
