## 0. 一句话结论

**值得做且时机合适**：引擎侧暂停基建齐备——`PauseLock`、`PauseSession / ResumeSession / StopSession`、`CancellationToken`、会话状态机与 UI 互锁都在位；**断点不需要动编译器、不需要动插件、不需要动 `Core.Interfaces`**。建议分三期，第 1 期做「断点标记 + 命中暂停 + 继续 / 暂停 / 停止打断」。

## 1. 可行性与时机（评审结论 1）

基建盘点（均在位）：

| 件 | 位置 / 说明 |
| --- | --- |
| `PauseLock` | `Core\Models\FlowSession.cs:170`，`ManualResetEventSlim` 语义（初值放行；`Reset`=暂停、`Set`=恢复、`Wait(token)`=等待点） |
| `PauseSession / ResumeSession / StopSession` | `Core\IFlowEngine.cs`（VM.Core 程序集；`Engine\FlowEngineService.cs` 实现）。`PauseSession` 已按 `IsContinuousRun` 分流，对单次执行显式拒绝并 Warn |
| `CancellationToken` + 停止链路 | 已有「令牌取消可唤醒 `PauseLock.Wait(token)` 等待」的既有模式（引擎收尾路径同一套） |
| 会话状态机与 UI 互锁 | `SessionState`（含 `Paused`）+ Shell 侧运行控制互锁均在位 |

**参考工程不可照抄**：`WPF-Halcon-流程拖拉` 的 `AutoResetEvent + 标志位` 做法（`01Main\VM.Start\Services\Project.cs:552-558`：`Breakpoint.WaitOne()`）**阻塞且不可取消**——没有令牌，「停止」打不断等待；本仓库同模式的等待由 `PauseLock.Wait(token)` 承担（带取消令牌）。

## 2. 三期划分（评审结论 2）

| 期 | 内容 | 体量 |
| --- | --- | --- |
| 第 1 期 | 断点标记 + 命中暂停 + 继续 / 暂停 / 停止打断 | 中 |
| 第 2 期 | 单步 | 小 |
| 第 3 期 | 断点面板 / 命中计数 / 条件断点 + 可选：单次执行支持调试 | 中 |

## 3. 关键语义结论：断点只对连续运行生效（评审结论 3）

- 第 1 期**不为断点开 `IsContinuousRun=false` 的口子**——断点只对**连续运行（`RunSessionAsync`）**生效；**单次执行（`RunSessionOnceAsync`）与试运行（`PluginTestRunner`）不装调试门**。
- 「有断点却单次执行」时**显式 Warn 留痕**（不静默吞掉）。
- 与 2026-09-24 的 D 组决策一致（见「相关记录」）；与既有 `[E11]` 断言一致——`FlowCanvasChecks\ExecutionChecks.cs:917-921`：单次执行 `IsContinuousRun=false`、`PauseSession` 不生效且拒绝留痕。
- 若将来要「单次执行也能断」：走该文档预留的**功能补全**路线（在引擎节点遍历处（`RunSequence` / `RunAndGetNext`）插 `PauseLock` 检查；删 `IsContinuousRun`、重写 `[E11]`），**列第 3 期（可选）**。

## 4. 数据模型（评审结论 4）

- **断点标记放 `StepModel`，`[RuntimeState] + [JsonIgnore]` 双标注**：
  - `[RuntimeState]` → **不递增 `Version`**（切换断点不触发重编译，自动落入 `FlowModel` 的运行时闸门名单）；
  - `[JsonIgnore]` → **不随 `.vms` 落盘**（断点跟方案进产线是安全隐患）。
- **命中状态复用 `SessionState.Paused`**，**不新增 `SessionState` 值**；会话上以 `PauseReason { None, User, Breakpoint, Step }` 区分暂停原因（UI / 日志按原因显示）。
- `SessionStateChangedEventArgs.Message` 目前无消费者，正好首次启用（承载暂停原因等附加语义）。

## 5. 插桩点与单步定义（评审结论 5–6）

- **插桩点**：`Core\Models\Compileds\CompiledNode.cs` 的 `RunSequence` 循环体内、`RunAndGetNext` 之前——**全引擎唯一的节点级执行点**（顶层 / If 分支 / While / For 全走它），一处覆盖。
- 门内用 `PauseLock.Wait(token)` 等待（**停止 / 会话替换可立即打断**）；收尾 `PauseLock.Set()` 兜底。
- **单步定义**：执行一个节点边界后再次断住；**容器算一步**（天然「步入」语义，无需单独处理）；循环体每次到达同一断点都断（命中计数 / 条件断点放第 3 期）。

## 6. 接口（评审结论 7）

- `Core\IFlowEngine.cs`（VM.Core，非 `Core.Interfaces`）追加：`void StepSession(FlowSession session);`
- `PauseSession / ResumeSession` 已存在——第 1 期**首次获得真实 UI 消费者**（此前暂停能力无 UI 入口）。

## 8. 多流程语义（评审结论 9，待决）

建议：**暂停 / 继续 = 全部运行中会话**（与 `StopAll` 同口径）；**单步仅当恰好一个会话暂停时可用**。

## 9. 影响面与三红线（评审结论 10）

- **约 14 个文件**：Core×4（StepModel / FlowSession / CompiledNode / Enums + IFlowEngine）；Engine×1；VisionMaster×7；FlowCanvasChecks×1；文档×2。
- **三红线均不触发**：零插件改动；已核实**无插件引用 VM.Core**（落盘复核：`Plugins\*.csproj` 全量扫描无 `VM.Core` 引用，仅见 `Core.Interfaces`）；`Core.Interfaces` 不动。

## 10. 风险（评审结论 11）

1. 「停在断点时点停止 / 会话被替换」必须可靠打断——须用断言实测钉死（`PauseLock.Wait(token)` 同模式推断可行）；
2. CTS 被 Dispose 后令牌唤醒的边界；
3. WPF 绑定路径未实机验证。

## 11. 验收标准（第 1 期，评审结论 12）

新增 `[E13]` 断言组，至少覆盖：

- 断点命中（`State=Paused`、`PauseReason=Breakpoint`、前序已执行 / 命中未执行）；
- 继续后执行；
- 停在断点时 `StopSession` 干净收尾；
- 试运行豁免；
- 单次执行豁免 + Warn；
- 切换 `IsBreakpoint` 不递增 `Version`；
- 序列化文本不含 `IsBreakpoint`；
- **`[E11]` 既有 15 条断言保持全绿**。
