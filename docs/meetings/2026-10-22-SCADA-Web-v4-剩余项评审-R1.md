## 一、协议收口

### 已形成的技术共识

1. **`cmd.result` 走 WS、在 `HandleTextFrame` 直答、不入泵**：请求 `{type:"cmd.result",id:"q1",targetRequestId:"c7"}`；响应新类型 `result`，带 `id`（查询自身）、`targetRequestId`、`state`、`code/message/result/ageMs`，**不带 `ok`**（否则被前端当 ack）。不能走 `Router.Handle`（会吃版本闸/审计 fail-closed/撤销闸）。
2. **`Dedup.TryPeek` 必须只读**：不得像 `Check` 那样删过期项；读到未完成条目回 `running`；30 分钟窗口内都要能查到结果。现有 `Complete` 是 write-once（`if (_entries.ContainsKey) return`），要支持 running→done 的状态迁移，否则占位会吞掉真回执。
3. **分片必须按 Rune 边界或 base64**：按 UTF-16 码元切会把 emoji 的代理对切成两个孤立代理，逐片 UTF-8 编码后变 U+FFFD，且 JSON.parse 不报错。R1 实测 `"A"+U+1F600+"B"` 在代理对中间切 → `"A??B"`。
4. **分片必须配 resync**：没有 resync，分片失败只能重连；10s keyframe 救不了“结构没收到”。分片期间暂停该会话 frame；全部片入队成功才推进 `CurrentPageKey`；失败整笔作废、下一拍换新 `snapshotId` 重发。
5. **24 槽 = 16 活跃 + 8 握手**：`MaxSessions` 语义仍是活跃上限（16），握手槽单独计数；在 ticket 核销处预留、WS 入册转活跃、所有失败出口幂等释放、5s TTL（取 `min(5s, 票剩余)`）；第 17 个活跃回 **WS 1013 + bye**，不是 HTTP 503（503 会被前端渲染成“登录失败”）；容量拒绝**不得撤销刚签的 token**。
6. **控制帧优先**：分片/大消息会挤占 256 槽 FIFO；ack 排在 1.5MB 快照后必超 5s。需要控制通道或至少给 ack/pong/error/bye 预留槽。

### 争议

- **cmd.result 本批做不做**：comm/hmi 认为可做（服务端 + 客户端查询）；reviewer 认为没有客户端 requestId 保留/在飞状态时它是死代码 + 去重污染，建议砍或补齐。R2 裁决。
- **分片本批做不做**：reviewer 认为没有 resync/控制通道的分片不许上；comm/hmi 认为按 Rune 切 + resync + 暂停 frame 可做。R2 裁决。
- **接管优先**：comm 建议保留 handoff 优先、不新增驱逐；reviewer 指出 `RevokeSession` 会连新连接一起踢。R2 裁决。

## 二、复杂图元数据通道

### 已形成的技术共识

1. **不能靠遍历可视树按 ElementId 找控件**：编辑器与运行窗口各有一份控件；容器子控件可能不在可视树；`RebuildElements` 会重建控件；窗口关闭/未布局时读不到。R1 红队明确反对“可视树反射 + 控件引用缓存”。
2. **正确方向是领域层只读数据 Hub**：`VM.Scada` 加窄接口（TrendSnapshot/GridSnapshot/AxisSnapshot/ImageFrame，各带单调版本），控件在 UI 线程 append，单写者 + 不可变快照整表交换；Web 后台只读，零锁、零 WPF 访问。
3. **图像先修隐藏开销**：`ScadaWebValueResolver` 现在每 10Hz 对每个图像绑定做一次全尺寸 HImage→BitmapSource 转换，再把类型名当 text 发；必须先跳过 `Hmi.ImageView/Source`，否则图像通道上线前 UI 线程已被打满。
4. **`/img` 必须直接吐字节**：Watson 的 `server.Get` 会把 `byte[]` 当对象 JSON 序列化（变 base64）；要用静态路由/`Response.Send(bytes)`。token 按会话、45s、最多 3 个、只放 query；校验会话+元素在当前快照+版本；`sessionToken` 绝不进 URL。
5. **默认值一致性不能用 `factory.defaults` 第二份事实源**：R1 红队指出“声明了但渲染器不读”必然假绿。正解是 catalog 子集随 hello 下发 + 渲染器统一 `ctx.default(typeKey,key)`；或构建期生成 `renderer-defaults.js` 并加“生成物过期”检查。

### 争议

- **数据 Hub 的落点**：hmi 建议宿主实现 `IScadaRuntimeDataProvider`（读运行窗口画布）；reviewer 认为控件私有数据仍不可靠，建议领域层 sink（控件 append）。R2 裁决。
- **DataGrid/ChartTrend 本批做到哪一档**：全量实时数据（hub + 消息 + 渲染器）vs 先做空态/结构渲染、数据通道下一批。R2 裁决。
- **默认值闸**：23 个现有渲染器迁移成本高；是“新渲染器强制 + 旧渲染器例外清单只许变短”，还是全量迁移。R2 裁决。

## 三、压测与性能报告

### 已形成的技术共识

1. **现有 ScadaWebStress 是冒烟级**：值从不变化（只发 cmd.element，FakeWriter 不写值），首帧 keyframe 后全是空帧；`MaxSessions=Math.Max(64, clients+8)` 让“第 17 连接”永不发生；字符数当字节；无慢消费者、无重连、无停服、无浏览器。
2. **必须改造夹具**：`--variables`、`--boundElements`（勿用 `--bindings 1000`）、`--changePct 10/30/100`、`--cmdIntervalMs`、`--stats`、`--slowClient`、`--reconnectStorm`、`--maxSessions`（生产值 16）、`--warmupMs/--durationMs`、`--outDir`。
3. **统计口径**：收包原始 UTF-8 字节（`result.Count`，不用 `.Length`）；逐帧 p50/p95/p99（nearest-rank）；1s 滑窗 Mbps（均值+峰值）；帧率 `(n-1)/(末-首)`；ack `t_send→t_ack`；队列深度、Sent/Dropped、GC、WorkingSet/PrivateBytes。
4. **场景矩阵**：S1 满载（16×3000×1000×10Hz，10/30/100% 变化）、S2 首屏、S3 慢消费者、S4 重连风暴、S5 第 17 连接、S6 握手风暴、S7 64KB 入站、S8 非法 JSON、S9 分片（实现后）、S10 停服中压测。
5. **证据格式**：`docs/performance/evidence/<日期>-<场景>-<runId>/` 下 `meta.json`、`raw.jsonl`、`stats.csv`、`server.log`、`summary.json`、`README.md`；复算脚本从 raw 重算 summary 必须逐字段一致。
6. **报告必须写未覆盖**：真实网卡/交换机/WiFi、浏览器 DOM/布局/绘制、1.5MB 单消息 parse、重连风暴、24 槽、分片、17 端拒绝、生产限速、长稳、三端一致。

### 争议

- **同进程 vs 两进程**：reviewer 认为 16 客户端与宿主同进程会抢核，建议两进程/绑核；comm 认为夹具可先同进程但必须记 CPU 余量。R2 裁决。
- **回环能否证明 70/100Mbps**：双方都认为不能直接证明现场带宽，只能用字节率/发送耗时/队列深度做协议层结论；报告必须写明边界。R2 确认。
- **浏览器覆盖**：无 Playwright/jsdom 时是否接受“协议层 + 静态扫描”作为本批结论；R2 裁决是否引入 headless Edge。
