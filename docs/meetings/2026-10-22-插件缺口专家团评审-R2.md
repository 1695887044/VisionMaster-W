## 三、优先级公式裁决

**现场反馈不能直接排序，只能作为 F 的一个输入；必须先去重到根因，再用路径使用量给静默项补频次。**

`P = S × F × I`

- S（严重度）：S 级 = 4 / A 级 = 3 / B 级 = 2 / C 级 = 1
- F（频次）：罕见 0.5 / 偶发 1.0 / 常用 1.5 / 每日多次 2.0
- I（不可发现性）：完全不可见 1.0 / 半可见 0.6 / 可见 0.2
- 有文档化绕行可乘 0.8 折扣；数据丢失/安全项设 P0 下限。

按此公式的代表性结果：

| 项 | 计算 | 结果 |
| --- | --- | --- |
| S11 CSV 异步写盘失败 | 4 × 1.5 × 1.0 | 6.0 → P0 |
| 空候选陷阱 | 3~4 × 1.5 × 1.0 | 4.5~6.0 → P0/P1 |
| S8 8 参数无 UI | 3 × 1.5 × 1.0 × 0.8（有文档绕行） | 3.6 → P0（硬件误动作下限） |
| N2/P2 全局变量空列 | 3 × 1.5 × 1.0 × 0.8 | 3.6 → P1 |
| S3 预处理算子失败 | 3 × 1.5 × 1.0 × 0.8 | 3.6 → P1 |
| S4/S5/S6 运动安全 | 4 × 0.5 × 1.0 | 2.0 → P1（撞机下限 P0） |
| S1 标定限制 | 2 × 1.0 × 0.6 | 1.2 → P3（若判错则 S=3→1.8 P2） |
| N1 画布端口 | 1 × 1.0 × 0.6 | 0.6 → P3 |
| A3 数组红字 | 2 × 1.0 × 0.6 | 1.2 → P3（可见且有绕行） |
| T1–T8 已修项 | — | 0 |

> 口径提醒：对静默项，“现场反馈密度”会接近 0，必须用“路径日调用量”代替；同一根因的多条反馈只计一次。

## 四、需用户拍板 vs 工程可定

**需用户拍板（产品/安全/契约取舍）**

1. 动态端口是否必须上画布（还是维持“面板内连线”设计）。
2. CSV `Variable` 列是否支持全局变量。
3. 启动方案失败是否阻断启动（还是只提示）。
4. 8 个运控参数做专属视图还是通用只读配置面板。
5. 空候选是否允许手填。
6. 结果显示是否支持数组。
7. 标定是否要求消费端支持旋转/透视。
8. 是否改画布为逐端口连接器。

**工程可直接定（实现/证据/文档）**

- 启动失败落日志与提示。
- 用 `SharedVariables.TryRead` 读全局变量。
- 空候选时显示“无候选”并允许手填（或明确报错）。
- 给 `AutoPortConfigView` 补 `[StepConfig]` 只读清单。
- 补断言（P1/P2/P5/空候选/S8）。
- 修正陈旧文档（`docs/数据记录/数据记录插件.md:363/378`）。
