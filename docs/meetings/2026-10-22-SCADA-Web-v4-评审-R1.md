## 一、R1 共识（无争议）

1. **A 范围仍然成立，但理由要改**：设备层并非没有急停。`IMotionDevice.EmergencyStop()` 在 `MotionDeviceBase.cs:497-536` 有真实实现（停本卡全部轴、清普通队列、打断当前命令）；缺的是 SCADA/Web 入口、停止完成确认、每轴位置有效性。交接文档“设备缺急停”的前提与代码冲突。
2. **当前 Web 运动/停止路径不安全**：`ScadaActionType.MotionStop` 是单轴减速停（`MotionActionExecutor.cs:527-539`），不是急停；`EmergencyStop` 返回 `Accepted` 只证明“收下了”，不证明“已停”。
3. **每轴位置有效性确实缺失**：`AxisStatus` 无有效位/回零位；`ScadaAxisSample.IsValid` 只表示“有轮询快照”；`IMotionDevice.IsHomed` 是卡级单布尔（`MotionDeviceBase.cs:64/109/296/836-837`），任一轴回零成功即整卡 true。
4. **数据面是真正的 go/no-go**：当前每 100ms 在 UI 线程重建整页快照并全量发值帧；`SnapshotMaxBytes` / `FrameBudgetBytes` 全仓无消费点。按当前 JSON 形状，1000 条绑定 ≈ 100KB/帧，16 端 ≈ 128Mbps，已越过 70/100Mbps。
5. **`TrySend` 失败被忽略**：值帧丢一帧在全量模式下无害，在增量模式下会永久漂移，直到下一次 keyframe。
6. **快照缓存只能缓存“无 caps 的原始结构”**：caps、未确认报警数、在线列表、租约必须逐会话/逐拍重算；带 caps 的快照不能按页键缓存。
7. **多基座存在既有缺陷**：`ScadaWebValueResolver.cs:135-138` 只解析 `BasePage`，不解析 `BasePages`；客户端也只渲染第一只基座。该缺陷与规模无关，缓存会把它固化，必须先修。
8. **弹窗结构变化当前推不出去**：`OpenPopup` 不动 `CurrentPage.Version`，`PageKey` 也不含弹窗；缓存后会更严重。
9. **控制帧与值帧共用一条 256 槽 FIFO**：ack/pong/error/caps 会被值帧挤掉，慢消费者下命令超时或直接断开。

## 二、R1 争议点

### 争议 1：A 范围如何真正封住“Web 运动”

- **reviewer**：`AllowMotionCommands=false` 只摘掉 9 个 `Motion*` 动作（`ScadaWebCommandRouter.cs:846-860`）；Web 仍可经 `StartFlow/RunFlowOnce/ResumeFlow` 启动含运动步骤的流程（`ScadaActionType.cs:143-147`、`ScadaActionDispatcher.cs:624-631`、`MotionMovePlugin.cs:105`），这是 P0 旁路。建议 A 范围同时排除流程启动类动作，或在流程/运动命令上增加 WebOrigin 标记并在 `MotionActionExecutor`/各 Motion 插件拒绝。
- **hmi**：唯一生产收口是 `BuildAllowedSet`（`ScadaWebCommandRouter.cs:833-853`）；`cmd.element` 钩子副本只消费 `_allowed`（`:275`），轴面板 `IScadaAxisCommandSink` 是另一条通道、Web 未接。只改 allowlist 没有 `cmd.element` 旁路，但流程动作确实是旁路。
- **architect**：A 是今晚唯一合理范围；但“Web 不能运动”必须定义为“Web 不能启动任何可能运动的流程”。只关 9 条 Motion 不够。建议 A 范围先排除 `StartFlow/RunFlowOnce/ResumeFlow`，保留 `StopFlow/PauseFlow`（安全方向），并把“流程里含运动步骤”的精确拦截列为二期。
- **motion**：如果保留流程启动，就必须把执行来源传到流程引擎与运动插件；否则只能在 Web 侧按动作类型一刀切。今晚不建议做跨层 origin 传播（流程引擎线程模型未核实），一刀切更稳。
- **待裁决**：A 范围是否排除流程启动类动作？排除哪几条？是否保留 `StopFlow/PauseFlow`？

### 争议 2：幂等键与结果查询

- **reviewer**：token 键对断线重发够用，对“同账号独立登录的多标签页”不够；`clientInstanceId` 不是防 UUID 碰撞必需，但应进确认令牌绑定与结果查询。真正漏洞是“队列中”无 in-flight 占位，同 requestId 可执行两次（`ScadaWebCommandRouter.cs:184-197` 先 Check、`:226-227` 执行后才 Complete）。撤销检查在去重前（`:143-158`），撤销后重试查不到结果。
- **comm**：去重键保持 `sessionToken+requestId` 即可跨重连稳定；ack 丢失必须靠“同 id 重发 + 结果查询”闭环；查询建议 WS `cmd.result`，不做 HTTP GET（避免新增鉴权面）。同账号多标签若共用 token，需要 `clientInstanceId` 隔离。
- **hmi**：结果查询用 HTTP GET 更合适，可复用 `TryResolveSession`；WS `cmd.result` 与现有 `id` 字段（回执配对键）冲突，目标 requestId 需要另一个字段。
- **architect**：无论 WS/HTTP，必须解决三件事：① 入队前写 in-flight（Reserved），防并发重复；② 结果保留 running/succeeded/failed/expired/unknown；③ 查询不受撤销闸拦截，否则“踢下线后查不到已执行结果”。
- **待裁决**：`cmd.result`（WS）还是 `GET /api/command/result`（HTTP）？去重键是否加 `clientInstanceId`？in-flight 状态放在 Dedup 还是 Pump？

### 争议 3：24 槽与 45 秒检测

- **reviewer**：24 槽不能按 `_sessions.Count` 算（先查后加非原子、不含握手），应在一个准入闸按“8 握手预留 + 16 活跃”计数；30s 票 TTL 与 handoff 同刻过期有竞态；每 IP 4/每令牌 1/45s 检测当前都不存在，且前两者与反代、多标签页冲突。
- **hmi**：24 槽要新增“含握手的单一槽计数”（或 20 活跃+4 握手）；45s 检测放 `RunPresenceLoopAsync`，判据 `UtcNow-LastSeenUtc`，先 `TryRemove` 认领再关；要跳过 `IsRevoked`，否则 B43 拿不到 4403。
- **comm**：活跃=已入 `_sessions` 且 hello/首屏已发；握手=ticket 已核销到入册之间；24 槽在 Authenticate 预留、入册/失败释放；第 17 个活跃只能回 WS 1013+bye；45s 判据必须叠加“出站无进展”，否则后台标签页会被误杀、能发不能收的僵尸又杀不掉。
- **待裁决**：24 = 16 活跃 + 8 握手，还是 20+4？握手计数在 ticket 核销还是 WS handler？45s 判据是否同时看入站与出站？

### 争议 4：快照缓存键

- **reviewer**：可按页键缓存“无 caps 的原始结构快照”，但现键漏 popup/runGeneration/页面标量/基座身份；带 caps 的快照不能按页键缓存。缓存键必须覆盖 `PageVersion/BasePageVersion/runGeneration/基座/弹窗/图层/AckButton 未确认数/caps`；`ApplyCaps` 逐会话复制与缓存共存。
- **hmi**：缓存未加 caps 的 `ScadaPageSnapshot`，跨会话共享；caps、未确认报警数、在线最高角色、租约逐拍或按 caps 指纹重算；`PageKey` 漏弹窗与基座身份、顺序，缓存前必须补齐。
- **ui**：`PageKey` 只有 `pageId@pageVersion@basePageVersion`（`ScadaWebHost.cs:2403-2406`）；弹窗、页面标量（Name/Width/Background/IsPopup/PopupAnchor）不升版本，缓存会永久陈旧。建议键扩为 `pageId@pageVersion@有序baseIds@各base版本@popupId@popupVersion@popupBaseSum@pageScalarsHash`。
- **待裁决**：缓存键的精确组成；页面标量用哈希还是逐字段；缓存失效是否还要订阅 `PopupChanged`。

### 争议 5：增量帧与关键帧

- **reviewer**：客户端渲染器已是合并语义（`elements-process.js:251-263`、`elements-interactive.js:251-263`），但必须“快照/page 后立刻关键帧 + frameSeq 缺口检测/resync”，否则丢一帧即永久陈旧。`seq` 是宿主级、结构帧按会话递增（`ScadaWebHost.cs:2239/2250/2384`），不能当 delta base。
- **ui**：`lastSeq` 只赋值不比较（`app.js:2506`），`runGeneration` 在闸门之前写（`:2509/2718`）；渲染器无 reset 钩子。增量会饿死拉取式渲染器（AlarmBanner/AckButton）。建议 frame 增 `frameSeq` 与 `keyframe:true`，`createRecord` 增 `reset()`，`applyFrame` 先过三道闸。
- **hmi**：last-values 放 `ScadaWebSession`（连接级）；结构帧入队成功、`ResetPageKey`、generation 变化时清空；首帧及每次清空后首帧发 keyframe，另加周期 keyframe；baseline 只在 `TrySend` 成功时推进。
- **待裁决**：keyframe 用 `frame{full:true}` 还是新 `keyframe` 类型？周期多少？是否需要客户端 `reset()` 全量改造？

### 争议 6：预算与分片

- **comm**：预算必须按字节，且是“每帧每会话”；70Mbps/16/10 ≈ 54.7KB/帧（扣 15% 余量≈46KB），默认 120KB 若真生效等于 153.6Mbps。慢消费者 256 槽×100KB=25.6MB/会话；控制帧必须独立优先道。快照 3000 图元≈1.5–1.8MB，64KB 分片≈24 片，同一 TCP 有 HOL。
- **reviewer**：预算须按 UTF-8 字节、整条 item、超限留到下一帧并轮转；控制帧需独立优先通道；分片按结构定界、逐片 caps、客户端原子重组。
- **hmi**：预算在选 items、流式写 JSON 时裁，不是先序列化整帧再截；未发出的项留 latest-wins 脏表，不会永远追不上；分片在 DTO/`BuildSnapshotMessage` 层做，不在 `TrySend`；分片会挤控制帧。
- **ui**：重组放 `handleRawMessage`（socket 唯一入口）；分片期间丢弃 frame；乱序/超时整笔作废并重同步；客户端无 resync 报文，需新增或退 manualReconnect。
- **待裁决**：预算按“每帧每会话”还是“全局出口”；分片是字符串切片还是结构分片；分片期间是否暂停 frame；是否需要压缩。

### 争议 7：新控件守门人

- **ui**：28 个内置 TypeKey 对 23 个渲染器，已缺 5 个（ImageView/AxisConsole/AxisPanel/AxisPointTable/DataGrid；ChartTrend 在另一程序集）；占位盒只 `warnOnce`，无人守门。默认值全是渲染器内字面量；`/api/catalog` 已暴露 `DefaultValue`，客户端完全没用。
- **reviewer**：渲染器覆盖度静态断言应放在 `ScadaChecks`（与 `RenderCatalogChecks` 同处），先调 `ScadaChartElements.Register()`；默认值一致性可以用 `/api/catalog` 做运行时诊断，但静态闸需要额外机制。
- **待裁决**：覆盖度闸的扫描口径（是否含 `ShowInToolbox=false` 别名）；默认值一致性今晚是否落地，还是只做运行时诊断。

## 三、R1 初步结论（待 R2/R3 确认）

1. A 范围：保留轴只读；**必须额外封住流程启动旁路**；具体排除哪几条待裁决。
2. 幂等：加 `clientInstanceId` + in-flight 占位 + 结果查询；查询通道待裁决。
3. 容量：24 槽准入闸 + 握手 TTL + 45s 双条件检测；比例待裁决。
4. 数据面：先修多基座与弹窗结构推送，再做快照缓存；缓存只缓存 raw structure；键必须含弹窗/基座身份/页面标量。
5. 增量：delta + 周期 keyframe + baseline-on-success；`seq` 不能当 delta base，新增 `frameSeq`。
6. 预算：按 UTF-8 字节；控制帧独立优先；分片在结构层做，客户端原子重组。
7. 守门人：先落渲染器覆盖度静态闸；默认值一致性今晚至少落运行时诊断。
