## 一、两个 P0（已修）

### P0-1 客户端不认 close 1009 → 超大页面无限重连

- 服务端路径：`SendStructure` 先 `TrySendControl(error)`，紧接着 `CloseAsync(1009)`（`ScadaWebHost.cs`）；
  error 帧可能被 close 抢在前面丢掉。
- 客户端原来只认 `E_SNAPSHOT_TOO_LARGE` 这条 error（`app.js` 的 error 分支），
  close 1009 没有任何分支 → `scheduleReconnect` → 重连后再超限，形成风暴。
- **修法**：`handleSocketClosed` 在 4403/4401 之前判
  `code === 1009 || /snapshot-too-large/i.test(closeReason)` → `enterFatal(...)` 并 return。
- **实测**：`ScadaWebStress --serve --elements 20000`（快照 5,096,456 字节 > 2,097,152）：
  浏览器显示「页面过大，无法显示」+「重试」，状态条「页面过大，已停止自动重连」，
  `fatal=true`、`attempt=0`、`reconnectTimer=null`、`wsOpen=false`，**没有重连**。

### P0-2 跨进程重启后 `runGeneration` 不归零 → 新快照被永久拒绝

- 旧客户端在 `hello` 时保留 `state.runGeneration`（用旧连接的值兜底）；
  服务端进程重启后 generation 从 1 重新计数，`idle` 又把旧值抬进 `stoppedGeneration`
  → 新快照 `generation <= stoppedGeneration` 被 `applySnapshot` 永久拒绝，只有 F5 能救。
- **修法**：
  1. 服务端 `BuildHello` 带 `runGeneration` 与 `structureSeq`（`RunSnapshot` 增加 `Generation`）；
  2. 客户端 `hello` **采纳**服务端值（缺省 0），不再沿用旧连接；
  3. `idle`/`stopped` 带 `runGeneration`；帧循环兜底用 `_lastRunGeneration`（不再用 0）；
  4. `idle`/`stopped` 加“旧轮次不覆盖新画面”的判据。
- **断言**：`B65` 验证首帧是 hello 且带 `runGeneration`/`structureSeq`。

## 三、P2（已修/已收口）

- `E_UNSUPPORTED` 回显 `id`/`kind`：新客户端能把“旧服务端不支持 view.resync”关联到请求。
- `view.resync` 的 `pageId/pageVersion/runGeneration` 进日志（不再是死字段）。
- `structureSeq` 注释改为“每次发送的单调戳，不是结构身份；失败会烧号、跨会话不连续”。
- 删除未使用的 `ResyncRequestId`。
- `clearResync` 重置 `resyncLastAt`（否则首屏超时会被上一次 1s 窗口静默吞掉）。
- `handleResyncError` 对“有 id 但与当前请求不符”的迟到错误一律吞掉。
- `applySnapshot` 不再 `clearFatal()`（1009 前排在队列里的快照不能绕过终态）。
- `scope=frames` 在未运行时回 `ack{idle:true}` + `idle`（不再让客户端空等）。
- 首屏竞态：`InitialStatePending` 让帧循环等 `SendInitialStateAsync` 完成，首屏只发一份
  （浏览器实测 `structureSeq=1`）。
