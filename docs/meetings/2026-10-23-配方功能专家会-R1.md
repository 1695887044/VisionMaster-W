## 二、共识（七票一致，R2 不再重开）

| 分叉 | 结论 | 共同理由（去重后） |
| --- | --- | --- |
| F1 载体 | **`.vms` 内嵌**；独立文件只作交换/迁移格式 | 保存已是原子写；旁挂文件不随另存、不参与草稿逐字比较，会造出第二份真值。 |
| F2 范围 | **schema-first 显式参数表** | `InputValues` 是无类型键值袋；`ApplyConfigValues` 对未知键/链接端口/类型不符全是静默跳过，不白名单必然「显示成功、实际没进去」。 |
| F3 语义 | **快照 + 显式「保存当前值到配方」** | 写穿让调试误改永久污染产品配方，无上一版可退，审计只剩「参数变更」。 |
| F4 时机 | **仅停止态** | 暂停态已放行参数编辑，再放行批量切换会与在跑会话打架；运行中排队到周期末没有可靠节拍边界。 |
| F5 入口 | **顶栏选择器 + 独立管理器**（SCADA 程度待定） | 操作员必须随时看到当前配方；管理器与切换是两个权限面。 |
| 键 | 步骤用 `StepID`，变量用 `VariableId`，点位用 `(AxisId, Index)` | 名字会改、会重名；复制/粘贴会重编 `StepID`，所以孤儿必须显式报出，不能猜。 |
| 失败策略 | **整单校验、整单应用、整单拒绝** | 半应用在换型场景等于「相机已换产品、轴还是旧产品」。 |
| 审计 | 每次切换一行：操作者/配方/前值→后值/结果 | 审计写失败不阻断，但必须可见。 |
| 旧文件 | 无配方字段 = 功能休眠，不自动造「默认配方」 | 零回归；不因保存一次就多出字段。 |

## 四、本轮实测（把争议钉死）

### 4.1 `JToken` 在 `.vms` 里安全吗？——安全

用仓库自带的 `packages\Newtonsoft.Json.13.0.4\lib\net45\Newtonsoft.Json.dll` 实测：

```text
Dictionary<string,object> { arr = JArray[1,2,3], dbl = double[]{1.5,2.5}, str = "abc" }
TypeNameHandling.Auto 序列化结果：
{"arr":[1,2,3],"dbl":{"$type":"System.Double[], mscorlib","$values":[1.5,2.5]},"str":"abc"}
```

- **`JArray`/`JObject` 不写 `$type`**，按普通 JSON 落盘 → 不会被 `SafeSerializationBinder` 拦。
- `double[]` 会写 `$type: System.Double[], mscorlib`；binder 对数组有显式放行分支（`ConnectionConfigJsonConverter.cs:60-83`），且元素类型限定在基元集合内。
- 结论：配方条目可以直接持有 `JToken`/原生值，**不需要**「JSON 字符串 + 类型名」的绕行；但**不能**把 `JArray` 包进 `Dictionary<string,object>` 之外的奇怪多态槽位。

### 4.2 轴稳定 Id 可用吗？——可用

- `AxisMapping.AxisId` 一经创建永不改变，历史轴由 `EnsureAxisIds` 按 `(卡 Id, 物理轴号)` **确定性补齐**（`MotionDescriptor.cs` 的 `AxisMapping` 注释）。
- `MotionPoint` 本身只有 `AxisLogical` 字符串外键（`MotionPoint.cs:34-38`），所以配方点位**不能**直接复用 `MotionPoint` 当存储类型；需独立 `RecipePoint { AxisId, Index, ... }`，应用时经 `MotionAxisRegistry` 解析回当前逻辑轴名。

### 4.3 运行锁的两个候选

- `IFlowRunState.AnyFlowRunning`：遍历 `CurrentSolution.Flows` 看 `RunState != Stopped`，注释声称覆盖单流程/HTTP（`VisionMaster/Services/Hardware/FlowRunState.cs:6-40`）。
- `IRuntimeManager.SnapshotSessions().Any(IsRunning)`：会话级真相，覆盖所有已注册会话（`Engine/IRuntimeManager.cs:29-35`）。
- 两者不是互斥：建议**双判**（`AnyFlowRunning || 任一 Session.IsRunning`），并在 R4 解决「预检通过到写入完成之间 HTTP 新起会话」的竞态。

## 五、R2 的合并稿 v0.1（供质询，不是定稿）

```text
SolutionModel
  Recipes: List<RecipeDefinition>?        // null = 功能未启用（旧文件零回归）
  ActiveRecipeId: Guid?                   // 当前生效配方；null = 未应用
  RecipeSchemaVersion: int                // 结构演进用

RecipeDefinition
  RecipeId: Guid
  Name: string
  Code: string                            // 产品编码/工单号（可空）
  ContentVersion: int                     // 每次保存 +1
  UpdatedAtUtc / UpdatedBy
  Notes
  Entries: List<RecipeEntry>

RecipeEntry
  Kind: StepInput | LocalVariable | MotionPoint
  TargetId: Guid                          // StepID / VariableId / AxisId
  Key: string                             // 端口名/属性名；变量与点位为空
  Index: int                              // 点位号 0..15
  Value: JToken                           // 原生 JSON
  DeclaredType: string                    // 捕获时的目标类型，仅用于校验与诊断

应用链
  权限(CanOperate) → 运行闸(双判) → 未保存改动闸 → 全量预检
  → 内存快照 → 按差异写入 → 更新 ActiveRecipeId → 原子保存 → 审计
  → 失败则整单回滚（内存值顶回）并保持旧 ActiveRecipeId

v1 范围（待 R2 裁决）
  步骤非链接 InputValues（含 [StepConfig]）
  本地全局变量
  运动点位（D2）
  不含：网络变量、连接/地址、卡/轴映射、软限位、模型资产、路径、动态列名
```
