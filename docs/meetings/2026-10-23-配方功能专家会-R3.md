# 2026-10-23 配方功能专家会 · R3（数据模型与寻址定稿）

- 输入：R2 裁决 + 四份数据模型提案（hmi / vision / motion / reviewer）
- 性质：只读评审；未构建、未改代码
- 结论：**数据模型定稿**。三处改判：① 复杂 `[StepConfig]` 对象**进 v1**（ROI/卡尺搜索区是产品参数，不收等于砍掉核心场景）；
  ② 运动点位用**独立强类型 `Points` 集合**，不塞进统一 `Entries`；③ `Recipes: []` **不归一化为 null**（否则「删光配方」会被误判成「旧版覆盖」）。

## 一、`SolutionModel` 新增字段（最终签名）

追加在 `Core/Models/SolutionModel.cs` 的 `Scada` 之后，按以下顺序，全部可空、默认 null、setter 不兜底：

| 属性 | 声明 | 落盘语义 |
| --- | --- | --- |
| `Recipes` | `List<RecipeDefinition>?`，`[JsonProperty(Order=100, ObjectCreationHandling=Replace)]` | null = 从未启用配方，不写；`[]` = 已启用但无配方，写 `[]` |
| `ActiveRecipeId` | `Guid?`，`[JsonProperty(Order=101)]` | null = 未应用；`Guid.Empty` 读入归一化为 null |
| `RecipeSchemaVersion` | `int?`，`[JsonProperty(Order=102)]` | null = 无配方；有配方写 `1` |

**零回归判据**：三个属性全 null 时 `NullValueHandling.Ignore`（`SolutionService.cs:28`）不写出任何新键；
`Order=100+` 保证它们排在所有未标 Order 的既有属性之后（Newtonsoft 按 Order 升序、默认 -1 在前），
老 `.vms` 读入→保存文本逐字不变。**不要**给既有属性补 Order。

**null vs 空集合**：`null` = 功能从未启用；`[]` = 用户删光了配方但功能已启用。二者不互相归一化。
`Version` canary 判据只在 `Version >= 2.0 && Recipes == null` 时告警「疑似被旧版保存覆盖」；
`Version >= 2.0 && Recipes != null`（含空集合）不告警。

**`Version` 2.0**：首次创建配方/首次捕获时置 2.0，之后不降。语义 = 「本文件含配方，需 ≥2.0 打开」。
加载不自动升；删光配方不回退。属性面板显示文案改为「方案格式版本」（R5）。
它是旧版覆盖的唯一可用 canary（旧版会原样保留 `Version`，但会丢掉未知的 `Recipes`）。
副作用：用户手改 `Version` 会误报，只告警 + 指向 `Autosave` 草稿，不自动还原。

**命名空间**：所有配方 DTO 放 `Core/Models/Recipe/`，命名空间必须是 `VisionMaster.Models`
（binder 白名单只放行 `VisionMaster.Models` / `Communications` / `Scada` / `Plugin.*`，见
`ConnectionConfigJsonConverter.cs:21-31`）。放 `Core.Interfaces` 会「存得下、打不开」。

## 二、`RecipeDefinition`（最终字段集）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `RecipeId` | `Guid` | 身份；改名不变；复制换新；非空且定义内唯一 |

| `CreatedAtUtc` / `CreatedBy` | `DateTime` / `string` | 创建 |
| `UpdatedAtUtc` / `UpdatedBy` | `DateTime?` / `string` | 条目最后一次变化 |

## 三、`RecipeEntry`（步骤参数 + 本地变量）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Kind` | `RecipeTargetKind`（`StepInput` / `LocalVariable`，`[JsonConverter(typeof(StringEnumConverter))]`） | 落盘写成员名，不写 0/1 |
| `TargetId` | `Guid` | StepInput = `StepID`；LocalVariable = `VariableId` |
| `Key` | `string` | StepInput = 端口名/`[StepConfig]` 属性名；LocalVariable = `""` |
| `TargetName` | `string` | 捕获时的步骤名/变量名；仅显示、审计、导入匹配，**不作寻址** |
| `PluginTypeName` | `string` | StepInput 必填，插件类型全名；用于检测「步骤被换成别的插件」 |
| `DeclaredType` | `string` | 规范化、程序集无关的类型键（见 §四）；来自 schema，不来自运行时值 |
| `Value` | `JToken?` | 规范 JSON 值 |
| `ValueIsNull` | `bool` | 显式 null 位（`NullValueHandling.Ignore` 会抹掉 `Value:null`） |

唯一约束：`(Kind, TargetId, Key)` 序数比较。重复 = 整份配方无效、整单拒绝，报两处下标，禁止后者覆盖。
形状约束：StepInput 的 `Key` 非空、`PluginTypeName` 非空；LocalVariable 的 `Key` 必须为空。

**寻址只按 Id，禁止名字兜底。** 这与 `GlobalVariableWriter` 的「Id 优先、名字兜底」不同：
猜错目标比报孤儿更坏；导入/跨机匹配时才用 `TargetName`，且必须显式确认。

## 四、值 codec（最终规则）

### 4.1 存储

- 一律存 **规范 JToken**：捕获时 `JToken.FromObject(value, TypeNameHandling.None)`，枚举存成员名。
- `DeclaredType` 用**规范化类型键**：程序集无关、泛型递归展开、无 Version/PublicKeyToken。
  例：`System.Double`、`System.Double[]`、`System.Collections.Generic.List\`1[Plugin.CreateRoi.RoiItem]`。
  **不要**用 `AssemblyQualifiedName`（升版即失配）或裸 `FullName`（泛型内嵌 AQN）。
- `ValueIsNull` 与 `Value` 必须一致：`true` 时 `Value` 必须为 null/JValue.Null；`false` 时 `Value` 不得缺失。
  不一致 = 条目损坏，整单拒绝。

### 4.2 复杂对象：进 v1（改判）

证据：`RoiList`（`Plugins/Plugin.CreateRoi/CreateRoiPlugin.cs:45-50`）与 `CaliperRegions`
（`Plugins/Plugin.CaliperMeasure/CaliperMeasurePlugin.cs:247-258`）都是 `[StepConfig] ObservableCollection<T>`，
在 `.vms` 里落成普通 JSON 数组（`解决方案\柔性装配线.vms` 的 `"RoiList": [...]`），
加载后是 `JArray`，由 `ValueConverter.Convert` 的 `JTokenType.Array/Object` 分支还原（`ValueConverter.cs:44-47`）。
排除复杂对象 = 换产品时 ROI/搜索区不能进配方，核心场景直接缺失。

准入判据（全部满足才可进 schema）：
1. **封闭类型图**：类型及其成员只允许基元/string/enum/decimal/DateTime/Guid、`System.Collections*`、`VisionMaster.Models/Communications/Scada`、`Plugin.*`；
   出现 `IDisposable`、`IntPtr`、`HalconDotNet.*`、接口/抽象/`object` → 拒。
2. **JSON 往返恒等**：`JToken.FromObject` → `ToObject(DeclaredType)` → 再 `FromObject`，逐字段相等；NaN/±Inf 直接拒。
3. **大小上限**：单条 ≤ 64 KiB，整配方 ≤ 2 MiB；超限报「疑似模型/图像资产，请拆出配方」。
4. **属性名兼容**：JToken 里出现的属性名必须在目标类型上存在；目标类型新增属性允许（取默认）并警告；
   属性被改名/删除 → 整单拒绝（否则静默回默认值）。
5. **路径/名字类**：`Path.IsPathRooted` 为真的字符串、`TemplateLibraryJson`、`DefaultTemplateName`、动态列名 → 不进 schema。

### 4.3 安全放宽矩阵

| 情形 | 判定 |
| --- | --- |
| 同类型异值 | 允许 |
| int/long → double/float；float ↔ double | 允许 |
| 枚举成员仍在（按成员名） | 允许 |
| null → 可空/引用类型 | 允许（`ValueIsNull`） |
| 数组仅长度变化 | 允许 + 警告 |
| double → int；decimal ↔ double | 拒绝 |
| 枚举成员删除/改名/换枚举；未定义数值 | 拒绝 |
| string ↔ number/bool | 拒绝 |
| 数组 ↔ 标量；数组元素类型变；对象类型变 | 拒绝 |
| null → 非可空值类型 / 必填端口 | 拒绝 |

拒绝 = 整单拒绝并列出条目，不做部分应用。

### 4.4 捕获与应用

- **捕获**：取 `InputValues` 的当前值（不取 `ActualValue`）；链接端口跳过；必填 + null 不收；
  先 `ValueConverter.Convert` 到 `DeclaredType` 验证，再存规范 JToken。
- **应用**：先 `ValueConverter.Convert(entry.Value, declaredType)` 验证（必须自己调，不能依赖
  `ApplyConfigValues` 的空 catch，`VisionPluginBase.cs:326-335`）；验证通过后，
  StepInput **写 JToken 回 `InputValues`**（与 `.vms` 重载同一路径，复杂对象才不会在
  `ChangeType` 上炸）；LocalVariable 写转换后的 CLR 值（`IGlobalVariableWriter` 的类型守门）；
  MotionPoint 写三个 double。
- **比较**：两侧同一规范化（按 `DeclaredType` 解包、整数→decimal、枚举按成员名、`-0.0→0.0`），
  逐字段比较，不比 JSON 文本；字符串不 Trim、不忽略大小写；double 不加 epsilon。

## 五、`RecipePoint`（运动点位，独立强类型集合）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `AxisId` | `Guid` | 稳定轴身份；非空 |
| `Index` | `int` | 0..15（`MotionPointExtensions.PointsPerAxis`） |
| `PositionMm` | `double` | 必填，有限 |
| `SpeedMmPerS` | `double` | 0 = 不下发、沿用控制器当前值（不是「卡默认」） |
| `AccelMmPerS2` | `double` | 同上 |
| `AxisNameSnapshot` | `string` | 诊断；不参与寻址 |
| `CardNameSnapshot` | `string` | 诊断 |
| `PhysicalIndexSnapshot` | `int` | 诊断 |

唯一约束：`(AxisId, Index)`。`Curve`/`Name` 不进 v1（`Curve` 无生产消费者；`Name` 是标签且会被
`FillDefaultNames` 顶掉）。翻案条件见 R3-motion 提案：现场有「同机构不同产品必须不同曲线」的证据、
先有「按点位号运动」的生产消费者。

**为什么独立集合**：点位是固定三 double + 有界 Index，套 `DeclaredType`/`ValueIsNull`/放宽矩阵
只会造出无意义规则；独立集合让点位差异/回滚/软限位校验天然按点聚合。代价是应用/差异引擎有
两段（`Entries` + `Points`），由 `RecipeApplyPlan` 合并，不引入第三套存储。

**AxisId 稳定性**：捕获前必须 `EnsureAxisIds()`；返回 >0（本次刚在内存补出）→ 拒绝捕获，
提示「轴身份刚建立，请先保存方案并重新打开」。捕获要求方案**无未保存改动**，从而保证
卡 `Id` 与轴 `AxisId` 已在磁盘。`AxisId == Guid.Empty` 的轴不进 schema，界面标
「该轴身份未建立，暂不可配方化」。应用时条目 `AxisId` 解析不到 → 整单拒绝，禁止按轴名兜底。

**与步骤参数的重叠**：`MotionMovePlugin` 只读 `Target`/`Velocity` 端口，全仓没有「按点位号运动」的步骤。
配方同时含点位与 `Target` 时，两者都写；确认页必须提示「流程仍按步骤 Target 走，点位只被
『走此点』/SCADA 轴面板消费」。v1 不做「步骤引用点位」。

## 六、schema、差异与生命周期

### 6.1 schema = 条目集合

不建第二张 schema 表：勾选一个候选 = 生成一条带当前值的 `RecipeEntry`/`RecipePoint`；取消 = 删条目。
候选派生：插件实例 `Inputs`（排除 `IsHidden`、已链接、类型图不封闭）+ `GetConfigProperties()`
（排除无 setter、`[RuntimeState]`、不封闭）；默认全不选。落盘即条目集合。

### 6.2 五类差异（应用前预检）

| 类 | 情形 | 处理 |
| --- | --- | --- |
| A 目标消失 | `StepID`/`VariableId`/`AxisId` 不存在，或步骤 `PluginTypeName` 变了 | 整单拒绝，列孤儿；另给显式「清理孤儿」 |
| B 键消失 | 端口/配置名不在当前元数据 | 整单拒绝；例外：端口转 `IsHidden` → 应用 + 警告 |
| C 类型不符 | 按 §4.3 矩阵 | 允许/拒绝/警告 |
| D 端口已链接 | `LinkedSources` 含该键 | 整单拒绝（写入也会被 `OnConfirm` 删掉，静默空跑） |
| E 纯值差异 | 仅值不同 | 正常写，标「偏离」 |

### 6.3 生命周期

- **悬空 `ActiveRecipeId`**：加载保留原值，标 Dangling，不自动清、不自动选第一个；只允许显式「清除指针」。
- **删除当前配方**：确认后置 null，值保持现状，不自动切换。
- **改名**：Id 不变，指针不动，`ContentVersion` 不变。
- **复制/另存**：新 `RecipeId`、`ContentVersion=1`、`LastApplied*=null`；`ActiveRecipeId` 跟随文件复制。
- **旧版覆盖**：`Version>=2 && Recipes==null` → 横幅告警 + 指向 `Autosave`；不自动重建。
- **方案重开**：按文件恢复；立即按值算偏离，显示「已偏离」而非静默应用；未保存的应用不跨会话。

## 七、数据层断言（`RecipeChecks`，至少 18 条，★反向）

1. 老 `.vms` 载入→序列化与磁盘逐字相同（反证：新字段污染草稿判等）。
2. `Recipes:null` 读入仍 null，写回无该键。
3. `Recipes:[]` 读入仍空集合，写回 `[]`（★反证：被归一化成 null 后误报旧版覆盖）。
4. ★ 把新字段插到 `Scada` 之前（变异）→ 必须红。
5. `ValueIsNull=false` 且 `Value` 缺失 → 条目损坏、整单拒绝。
6. ★ `ValueIsNull=true` 且 `Value` 有值 → 拒绝。
7. 条目键重复 → 报错列键，不是后者覆盖。
8. `RecipeId` 重复/Empty、`Name` 大小写重名 → 拒绝。
9. 悬空 `ActiveRecipeId` → 保留 + Dangling，不自动选。
10. 孤儿 StepID/VariableId/AxisId → 整单拒绝，前后全量 `InputValues`/点位逐字段相等。
11. ★ 目标端口已链接 → 拒绝，不是写入后被删。
12. ★ 两张卡 `Id=Empty` 或同 Id → 其轴捕获期拒绝进 schema。
13. NaN/Infinity/含 `$type` 的值捕获期拒绝；序列化文本配方段无 `$type`、无 `NaN`。
14. 捕获→存→读→应用，三类条目逐字段相等（含枚举成员名、数组顺序、ROI 列表）。
15. 第 N 条失败 → 已写值全部回滚、`ActiveRecipeId` 不变。
16. ★ 应用后改一个点位值 → 偏离=1；只把 `ContentVersion+1` 而值不变 → 偏离=0。
17. ★ `Version=2.0 + Recipes=null` → 警告；`Version=1.0 + Recipes=null` → 无警告。
18. ★ 只含点位条目的配方应用后，所有 `MotionMovePlugin.InputValues["Target"]` 逐字不变。
19. ★ 轴改名后配方仍命中（AxisId）；删轴后新建同名轴仍判孤儿（禁按名兜底）。
20. 应用前后 `MotionPoint` 引用同一、集合元素数不变；`Speed=0` 写入后仍为 0。

## 八、R3 遗留到 R4/R6 的问题

1. **R4**：应用门闸的具体机制（在途计数 vs 读写锁）、6 个启动入口的改造面、回滚顺序与终检。
2. **R4**：`ContentVersion++` 的精确触发点（点位改动算不算；算，因为值集变了）。
3. **R6**：`Version` canary 需用真实上一版二进制实测；未实测前只能作为「告警」不能作为「阻断」。
4. **R6**：复杂对象的属性名兼容检查需要一份「类型图遍历」工具；放 `RecipeChecks` 还是 `Core` 待定。
5. **R6**：`.vmrecipe` 导入的跨机匹配（逻辑轴名映射）在 v1.1 的格式里必须现在就留字段。
