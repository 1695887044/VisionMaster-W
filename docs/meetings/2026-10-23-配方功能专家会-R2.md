# 2026-10-23 配方功能专家会 · R2（交叉质询）

- 输入：R1 纪要 + 合并稿 v0.1
- 参与：hmi / vision / motion / comm / ui / reviewer / docs
- 性质：只读评审；未构建、未改代码
- 审查结论：**合并稿 v0.1 判 fail**——D5/D6/D8 与四条生命周期未定；旧版覆盖检测缺可行手段。
- 本轮出现三次公开改口：comm 撤回「网络变量进 v1」、ui 撤回「SCADA 运行态切换」、docs 改判「点位必须进 v1」。

---

## 一、七份质询的净结论

| 角色 | 改口/坚持 | 最关键的一条 |
| --- | --- | --- |
| hmi | 撤回「默认应用并保存」 | 运行锁主判必须是 `SnapshotSessions`（`FlowModel.RunState` 是 UI 异步镜像，会陈旧）；预检到写入的竞态要用「切换屏障+在途计数」收口。 |
| vision | 撤回「禁止 JToken」 | `DeclaredType` 必须是硬闸，不是诊断字段；schema 由宿主从 `Inputs`+`GetConfigProperties()` 派生、用户勾选，零契约改动。 |
| motion | 坚持点位进 v1 | 点位是纯配置写，风险在「走此点」而非「写点位」；排除点位只会把修改赶回无审计的手工示教。`AxisId` 可能为 `Guid.Empty`，必须先补齐。 |
| comm | 撤回「网络变量进 v1」 | 写 PLC 没有事务、没有回滚；v1 只切上位机内存，PLC 参数由 PLC 自取或流程下发。 |
| ui | 撤回「SCADA 给切换」 | `ScadaRuntimeHost.IsRunning => _window != null`——运行窗口开着就等于在运行，停止即回编辑器；v1 只读显示。 |
| reviewer | 判 fail | 应用与保存必须同批（先判未保存改动）；运行门闸要动 Engine；导入导出必须有严格校验器，否则后置。 |
| docs | 改判点位进 v1 | 排除点位后「整单生效」是假象：相机换了产品、轴还停在旧位；导出导入进 v1，否则 5 台机只能整份 `.vms` 覆盖。 |

## 二、主会话初步裁决（R3–R6 在此基础上细化，不再重开）

### D1 值落盘形式：`JToken` + 硬 `DeclaredType`

- R1 §4.1 已实测 `JArray`/`JObject` 不写 `$type`；`double[]` 写 `$type: System.Double[], mscorlib` 且 binder 放行。
- 配方条目：`Value: JToken`、`DeclaredType: string`、`ValueIsNull: bool`。
- `DeclaredType` 不一致：按「安全放宽」矩阵处理（int→double 允许；double→int、枚举成员消失、对象类型变化 → 整单拒绝）。矩阵由 R3 定稿。
- 禁止：`NaN`/`Infinity`（捕获时拒绝）、不可 JSON 往返的值（HImage、句柄、闭包）、`$type` 键。

### D2 运动点位：进 v1，但「可配方化」有前置

- 键：`(AxisId, Index)`；值：`PositionMm`、`SpeedMmPerS`、`AccelMmPerS2`；`Curve`/`Name` v1 不进。
- 捕获前必须 `EnsureAxisIds`；`AxisId == Guid.Empty` 的轴**不进 schema**，界面标「该轴身份未建立，暂不可配方化」。
- 应用时条目 `AxisId` 解析不到 → **整单拒绝**（不是跳过）。
- 前置：无运行会话 + 全轴静止 + 非报警/安全停机/连接中；离线放行；未回零/未使能放行；软限位越界**警告不夹取**；Index 越界/NaN/轴不存在拒绝。
- 写入顺序：变量 → 点位 → 步骤参数；回滚逆序；`MotionPoint` 就地改字段，不换实例。

### D3 网络变量：v1 排除

- 配方不写 PLC；PLC 设定值由「PLC 按配方号自取」或「流程写变量步骤」承接。
- 配方条目出现网络变量 → **整单拒绝**（不是静默忽略），并说明「网络变量写 PLC 不在本功能保证范围」。
- 切换时**不暂停扫描、不清缓存、不重连**（应用只写内存）。

### D4 SCADA 运行态：v1 只读

- 底条显示「配方：X + 偏离点」；不提供切换控件。
- 换型入口：停止运行 → 回编辑器顶栏切换。手册写清「换型必须停机」。

### D5 应用与保存：默认只应用，保存是独立显式动作

- 应用 = 内存写入 + 更新 `ActiveRecipeId`（内存）+ 审计；不自动写盘。
- 有未保存改动：三选一「先保存再应用 / 仅应用（不保存）/ 取消」；若改动落在本次目标集，逐条列出「将被覆盖」，默认取消。
- 「应用并保存」作为显式次按钮，必须复用现有保存链（布局 Capture + 变量 Capture + 通讯 Capture + `SaveAsync`），禁止静默 `SaveAsync`。
- 撤销 = **前向切回上一配方**（新审计行），不做文件回滚、不做第二套历史；保存后仍可切回，但不是「撤销」。
- 界面必须区分「已应用（未保存）」与「已保存」。

### D6 运行锁：双判 + 应用门闸

- 主判：`IRuntimeManager.SnapshotSessions().Any(s => s.IsRunning)`（会话级真相）。
- 副判：`IFlowRunState.AnyFlowRunning`（流程镜像，覆盖 UI 运行态）。
- 二者任一为真 → 拒绝。
- 预检→写入的竞态：R4 定稿「切换屏障」机制（在途计数或读写锁），要求覆盖全部流程启动入口（`FlowAutoRunner`、`FlowInvoker`、`HttpImageServer`、`ScadaFlowRunner`、`FlowListViewModel`、UI 运行命令）。这是 Engine 改动，按 R12 走架构评审 + 独立审查 + `docs/code-changes/`。

### D7 schema：宿主派生 + 用户勾选

- 候选来源：插件实例的 `Inputs` 端口表 + `GetConfigProperties()`；不新增 `[RecipeParameter]`，不改 `Core.Interfaces`，不触发全插件重建。
- 默认排除：HImage/句柄、模型 base64、绝对路径、动态列名、卡/轴映射、软限位、通讯地址、相机 Settings、`TemplateLibraryJson`。
- schema 落盘为条目快照；插件升级后按「目标消失/键消失/类型不符/端口已链接/纯值差异」五类报告。

### D8 导入导出：v1.1（先定格式，不阻塞 v1）

- v1 只做内嵌配方 + 应用/捕获 + 点位 + 本地变量 + 步骤参数 + 界面 + 审计 + 断言。
- v1.1 做单条 `.vmrecipe` 导出/导入：独立 DTO、`TypeNameHandling.None`、禁 `$type`、禁设备字段、导入只建定义不应用、名称路径匹配 + 歧义拒绝。
- v1 期间跨机台临时流程：整份 `.vms` 复制（必须显式警告会带走通讯地址/布局）；手册写明这是临时手段。

### D9 作用域：方案级单一生效配方

- 一份 `.vms` 同一时刻只有一个 `ActiveRecipeId`；配方条目可覆盖任意流程的步骤。
- 不做「每流程一份配方」——现场没有「两条流程同时产不同产品」的真实场景，且会破坏「整单生效」。

### D10 相机曝光/增益：v1 不进

- 它们在 `CameraDescriptor.Settings`，不在三个落点；写入走 `ApplyExposureGainCore`，无 `Version++`、无回读、无整单回滚。
- 若某插件把曝光做成 `[StepConfig]`，它自然落入步骤参数白名单，由用户显式勾选。

## 三、R2 新发现（必须进 R3/R4/R6）

| # | 发现 | 后果 | 归属 |
| --- | --- | --- | --- |
| N1 | `AxisId` 可能为 `Guid.Empty`：`EnsureAxisIds` 只在注册表构建路径调用；卡 `MotionDescriptor.Id` 无迁移补齐 | 旧方案点位配方跨保存不稳定 | R3/R4 |
| N2 | 旧版打开新 `.vms` 会静默丢 `Recipes`；`RecipeSchemaVersion` 也会被旧版丢掉 | 无法用新字段检测覆盖 | R6（建议借 `Version` 2.0 标记） |
| N3 | `NullValueHandling.Ignore` 会抹掉 `Value:null` | 需要 `ValueIsNull` 显式位或 v1 禁止 null | R3 |
| N4 | `ApplyConfigValues` 对 `[StepConfig]` 转换异常是空 catch | 不能依赖运行期灌值做校验，必须应用前自己 Convert | R3 |
| N5 | `SolutionDraftService` 用整份序列化文本逐字比较判脏 | 新属性默认值/字段顺序必须保证老文件零回归；应用后会被判「有未保存改动」 | R3/R6 |
| N6 | `ScadaRuntimeHost.IsRunning => _window != null` | SCADA 运行态没有独立写路径，v1 只读是对的 | R5 |
| N7 | `MotionMovePlugin.Target` 是端口，不是点位；全仓没有「按点位号运动」的步骤 | 若方案不用点位表，配方该装步骤 `Target` 而不是点位 | R3/R4 |
| N8 | `MotionPoint` 无 `INotifyPropertyChanged`，UI 行持活引用 | 必须就地改、逐字段回滚；换实例会留孤儿行 | R4 |
| N9 | 审计 `ScadaAuditWriter` 写失败不阻断 | 应用成功但审计丢失必须界面可见 | R4 |
| N10 | `SolutionService.SaveAsync` 用 `File.Replace`，受限环境可能抛 `UnauthorizedAccessException`（R180） | 导入/导出/保存都要 catch 两类异常 | R6 |
