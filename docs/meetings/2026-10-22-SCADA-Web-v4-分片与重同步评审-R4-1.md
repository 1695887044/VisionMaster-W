# SCADA Web v4 · 分片/重同步/控制通道评审（R4-1）

- 日期：2026-10-22
- 分支：`feature/scada-web-v4-a-prime`
- 参与：架构（general-purpose）、协议（comm）、独立审查（reviewer）
- 输入提案：快照 >512KB 分片（`snapshot.begin/chunk/end`）、控制帧独立队列+发送闸、`view.resync`、≤512KB 保持单条
- 结论：**方向成立，但提案不能原样落地**。评审抓到 9 个 P0；裁决为“先控制通道 + resync + 陈旧快照闸，分片单独一批”，并把分片的立项理由改写。

---

## 一、三份评审的共识（逐条）

1. **`frameSeq` 跳变不能作为 resync 触发条件**（架构 P0-1、协议 P1-1、审查 P0-8）。
   - `ResetDeltaForNewStructure()` 在每次结构发送后把 `FrameSeq` 归零（`ScadaWebSession.cs:175`）；
     客户端 `renderSnapshot` 也把 `state.frameSeq=0`（`app.js:1621`）。两者互相触发 = 每次切页白烧两份全量结构。
   - 更根本：`SendFrame` 只在 `TrySend` 成功后推进 `FrameSeq`（`ScadaWebHost.cs:3166-3173`），
     失败下一拍复用同号，**前向缺口在现有实现里不存在**；慢消费者跳号是正常背压。
   - 客户端空帧提前 return（`app.js:3020-3024`）还会让基线停在最后一次有值的帧，下一次值变化必“跳变”。
   - **裁决**：结构 resync 只由“组装缺口/超时/end 校验失败/首屏超时”触发；值帧只允许 `scope:"frames"`（置下一帧 keyframe），不得整份重发。

2. **resync 不能在 WS 线程清 `CurrentPageKey` / `LastValues`**（架构 P0-2/P0-3、协议 P0-9、审查 P0-2）。
   - `ResetPageKey()` 会 `LastValues.Clear()`（`ScadaWebSession.cs:172-179`），而 `SendFrame` 在帧循环线程写它（`ScadaWebHost.cs:3170`）——跨线程 `Dictionary` 写会损坏/死循环。
   - 清页键后帧循环下一拍必然再发一份 snapshot（`ScadaWebHost.cs:2614-2631`），与 resync 自己的快照**双发**。
   - **裁决**：WS 线程只置 `ResyncRequested` 标志（带 requestId/scope/时间）；由帧循环在下一拍消费，
     用 `ForceStructure` 让 `previousKey is null` 分支走一次；成功后才推进页键、才 `ResetDeltaForNewStructure()`。
     结构状态只有一个写者（帧循环）。

3. **控制优先要“两条循环 + 发送闸”，但不是抢占式**（架构 B、协议 P0-5、审查 P1-3）。
   - Watson `SendTextAsync` 内部有 `_SendLock`；控制消息最多插到“当前这一条之后”，
     不会插进一条消息中间。这正好是我们要的：不排 1.5MB 的队，但要等当前 128KB 块发完。
   - 两条循环各自 `catch` 后必须**记日志并关连接**，不能像今天一样静默吞（`ScadaWebSession.cs:225-229`）。
   - 每会话需要自己的 linked CTS + 每条消息发送超时（默认 15s）；否则关闭/撤销会卡在阻塞发送后。
   - **裁决**：控制队列 64、数据队列 256、共享 `SemaphoreSlim`；控制消息只等当前一条；
     `ack/error/result/bye/stopped/idle/img.token/pong/hello.ok/resync` 走控制；
     `snapshot/page/frame/axis/grid/presence/alarms/caps` 走数据。
     控制队列满：`ack/error/bye/stopped` → 1011/1013 关闭；`img.token` → 下拍重试；`pong` 可丢。

4. **`E_SNAPSHOT_TOO_LARGE` + 1009 会造成无限重连**（协议 P0-6、审查 P2-11）。
   - 客户端 `handleSocketClosed` 只对 4403/4401 特判，其余一律重连（`app.js:2557-2584`）；
     页面过大时每次重连都超限再断，16 个标签页就是小型 DoS。
   - **裁决**：客户端把 `E_SNAPSHOT_TOO_LARGE`/close 1009 当终态：显示“页面过大”遮罩，停止自动重连，只留手动重试。

5. **`img.token` 入队失败会留下 15 秒 401 窗口**（协议 P1-5）。
   - `RotateImageTokens` 先更新 `_currentImageToken` 再 `TrySend`（`ScadaWebHost.cs:3358-3381`）；
     下一次 tick 看到新 token 剩余 >15s 就 `continue`，不会补发。
   - **裁决**：`img.token` 走控制；每会话记 `PendingImageToken`，成功入队后才更新 `_currentImageToken`；失败下拍重发。

6. **旧快照会覆盖新页 / `runGeneration` 闸是死代码**（审查 P0-3/P0-4）。
   - `handleMessage` 在 switch 之前无条件用消息里的 `runGeneration` 写 `state.runGeneration`（`app.js:2718-2720`），
     `applyFrame` 再比较时永远相等；`applySnapshot` 不比较版本/轮次，迟到快照直接 `renderSnapshot` + `running=true`。
   - **裁决**：新增宿主级 `structureSeq`（只在结构键变化时分配），`snapshot/page/hello` 都带；
     客户端 `state.structureSeq` 只接受更大的；`stopped` 带 `runGeneration`，`applySnapshot` 拒绝 `<= stoppedGeneration`；
     `handleMessage` 不再全局写 `runGeneration`，各 handler 先校验后写。

7. **分片的立项理由要改写**（架构 P0-4、协议 P1-16、审查未验证项）。
   - 架构反编译本地 Watson 7.2.0：`MaxMessageSize` 只判**入站**（`ReceiveInternalAsync`），
     出站 `SendTextAsync` 不判；`ScadaWebHost.cs:434` 的“双向”注释与实现矛盾。
   - **裁决**：在探针证明前，不把“避免 4MB 出站上限”写进方案。分片的真实收益只有三条：
     ① 控制消息队头从“整份快照”降到“一块”；② 单次分配从 1.5MB 降到 128KB（LOH 抖动）；
     ③ 切页时可在块边界放弃在飞传输。**它不减少字节、不减少一次 `JSON.parse`，不是大页面容量方案。**

8. **分片协议必须按码点边界切，不能 `Substring`**（协议 P0-3、审查 P0-1）。
   - C# 字符串索引是 UTF-16 码元，128KB 是 UTF-8 字节；中文 3 字节、emoji 4 字节，切中间会产出 U+FFFD。
   - **裁决（若做分片）**：先 `Encoding.UTF8.GetBytes(json)` 一次，只在 UTF-8 前导字节处落刀
     （`(b & 0xC0) != 0x80`），每块 `GetString`；客户端 `end` 校验 `Σ bytes == begin.bytes`
     与 `TextEncoder(joined).length == totalBytes`；断言必须含中文/emoji 与 128KB 边界。

9. **分片的结构批次必须原子入队、整批接受才推进页键**（审查 P0-5、协议 P1-6）。
   - 若 begin/chunk/end 各自入队，队列满会留半截；`TrySend` 成功即推进页键会永久冻结。
   - **裁决（若做分片）**：`StructureBatch` 作为**一个对象**入 `Channel<StructureBatch>(1)`；
     发送循环按块发，每块前检查 `batch.Id == currentBatchId`/撤销/取消；
     最后一块发完才 `CurrentPageKey = batch.PageKey` + `ResetDeltaForNewStructure()`；
     新结构替换 pending（latest wins），旧批在块边界 abort 并发 `snapshot.abort`。

10. **能力协商**（协议 P1-14、审查 P1-6）。
    - 旧标签页的 `app.js` 收到 `snapshot.begin` 会落 `default` 静默忽略，永久停在“等待画面”。
    - **裁决**：客户端连接后发 `{"type":"view.hello","caps":["struct","resync"]}`；
      服务端只在会话声明 `struct` 时发分片，否则保持单条（≤硬上限时）；同时 bump `ProtocolVersion`。

11. **`caps` 每 2 秒全量 deny/allow 本身就是队头问题**（审查 P0-7/P1-12）。
    - 3000 图元约 200KB/2s/会话；若放进控制通道会饿死数据。
    - **裁决**：`caps` 走数据通道；只在 `policyVersion` 变化时发（或发 diff），本批先做“变化才发”。

12. **现有 `ScadaWebChecks` 只认单条 snapshot**（审查 P1-7）。
    - 分片落地时必须加 `ReceiveSnapshotAsync` 状态机；小页面用例保留验证单条路径。

## 二、实施顺序（裁决）

按“每一步独立可测、可回滚”拆成三批：

### 第一批：控制通道 + 会话级取消 + 发送超时（不改协议）
- `ScadaWebSession`：控制队列 64、数据队列 256、共享发送闸、每会话 linked CTS、每条消息 15s 超时；
  两条循环的异常都记日志并关连接（不再静默）。
- 控制/数据分类按 §一-3；`img.token` 改为“成功入队才更新”。
- `stopped`/`idle`/`pong`/`hello.ok` 走控制。
- 断言：`B58` 控制插队（慢读时 ack 先于大消息）、`B59` 控制队列满 1011、`B60` 会话关闭 2s 内退出。

### 第二批：`view.resync` + 陈旧快照闸 + 1009 终态
- 宿主级 `structureSeq`（结构键变化时分配），`snapshot/page/hello` 带；客户端只接受更大值。
- `view.resync{id,scope:"structure"|"frames",reason}`：
  - WS 线程过 `TryValidateSessionAlive`、1s 限速、单飞；`structure` 只置 `ResyncRequested`，`frames` 只置 `ForceKeyframe`；
  - 帧循环消费：`structure` 走一次 `previousKey is null` 分支（不跨线程清 `LastValues`）；
  - 未运行回 `idle`；撤销 4403、过期 4401。
- 客户端：`stopped` 带 generation 并清“等待结构”状态；`applySnapshot` 校验 `structureSeq`/`stoppedGeneration`；
  `handleMessage` 不再全局写 `runGeneration`；空帧也推进 `lastReceivedFrameSeq`；
  `E_SNAPSHOT_TOO_LARGE`/1009 终态、停止自动重连。
- 断言：`B61` resync 单飞/限速、`B62` 未运行 idle、`B63` 撤销 4403、`B64` 旧快照被拒、`B65` 1009 不重连（客户端静态）。

### 第三批：分片（仅在前两批绿后）
- 按 §一-8/9/10 的协议：`struct.begin/chunk/end/abort`、`snapshotId`、`structureSeq`、
  `byte[]` JIT 切块、`StructureBatch` 单对象入队、能力协商、客户端组装状态机。
- 先做 4MB 出站探针定案 Watson 行为；若探针证明无出站上限，方案文档必须写“分片解决的是 HOL/LOH/可中断，不是容量”。
- 断言：`B66` 分片重组逐字节、`B67` 码点边界、`B68` 缺口/重块/乱序、`B69` 控制插队不扰动组装、
  `B70` 切页 supersede、`B71` 慢读不误判、`B72` 旧客户端单条兼容。

## 三、会议摘要

| 议题 | 裁决 | 反对/保留 |
| --- | --- | --- |
| frameSeq 触发 resync | **否决**，自激且抓不到真实故障 | 无 |
| resync 清页键 | **否决**，WS 线程跨线程写 `LastValues` + 帧循环双发 | 无 |
| 控制优先 | 两条循环 + 发送闸；控制只等当前一条；异常必须记日志并关连接 | 架构建议单循环优先级取队；本批先用两条循环，复杂度低、可测 |
| 分片理由 | 改为 HOL/LOH/可中断；容量问题另解 | 协议主张默认上限提到 3.5MB；本批不改默认值 |
| 分片协议 | `struct.*` + snapshotId + structureSeq + byte[] JIT + 原子批次 + 能力协商 | 协议建议 CRC32；裁决先只做字节和校验，CRC 留待探针 |
| 1009 | 客户端终态，停止自动重连 | 协议建议服务端只回 error 不关；裁决先客户端兜住，服务端行为不变 |
| caps | 走数据；变化才发 | 审查建议 diff/位图；本批先“变化才发” |

**签字**：架构（同意，保留“先量 ack 队头再决定分片”）、协议（同意，保留 CRC/默认上限意见）、
审查（同意，要求每批先补断言再改代码）。
