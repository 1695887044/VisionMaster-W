# 2026-10-23 配方功能专家会 · R4（运行期切换与安全定稿）

- 输入：R3 数据模型 + 四份运行期提案（hmi / motion / comm / reviewer）
- 性质：只读评审；未构建、未改代码
- 结论：**运行期定稿**。三处关键修正：
  ① 变量写入会同步触发 `FlowVariableTriggerService`（`Engine/FlowVariableTriggerService.cs` 的 `Evaluate → FlowAutoRunner.RunOnce`），
     **触发源变量 v1 不进 schema**；否则应用中途会起流程或永久丢上升沿。
  ② `FlowSessionFactory.CompiledVersion` 在 `Compile` **之后**取值（`FlowSessionFactory.cs:57-70`），
     并发版本变化会把「混合图纸」判成新鲜；必须改成**编译前快照**。
  ③ 运行门闸用「封门 + 在途计数 + 封门后复判」，不用读写锁；覆盖 6 个启动入口。

## 一、最终应用链（UI 线程、同步、写循环内不 await）

| # | 步骤 | 失败处理 |
| --- | --- | --- |
| 1 | 权限：`ScadaAccessPolicy.CanOperate(Engineer)`；未登录=操作员 | 拒绝 + 审计 Denied；按下前 `CanExecute`、执行前各判一次 |
| 2 | 运行闸 A：`SnapshotSessions().Any(IsRunning)`（主判）+ `IFlowRunState.AnyFlowRunning`（副判） | 任一为真即拒绝，列出在跑流程名 |
| 3 | 未保存闸：`SolutionService.Serialize` 与磁盘逐字比较 | 三选一「先保存再应用 / 仅应用 / 取消」，默认取消；目标集有重叠改动时逐条列出 |
| 4 | 封门：`RecipeApplyGate.TryBeginApply`（seal + 等在途启动归零 ≤3s） | 超时→解封 + 拒绝「有流程正在启动」 |
| 5 | **封门后复判**：再查一次 `SnapshotSessions` | 有在跑→解封 + 拒绝（防止「检查→封门」之间起跑） |
| 6 | 全量预检：目标存在、未链接、类型可转、点位前置、软限位、网络变量/触发源变量拒绝 | 零写入、`ActiveRecipeId` 不变、审计 Failed |
| 7 | 快照：将被写目标的旧值 + 引用 + `FlowModel.Version` | — |
| 8 | 写入：本地变量 → 点位（Speed→Accel→Position）→ 步骤参数（`SetInputValue`） | 进入逆序回滚 |
| 9 | 终检：逐字段回读，不一致=失败 | 进入逆序回滚 |
| 10 | 更新 `ActiveRecipeId` / `LastAppliedAt` / `LastAppliedContentVersion`；首次应用置 `Version=2.0` | 异常→回滚 |
| 11 | 解封（`finally` 无条件） | — |
| 12 | 可选保存（显式「应用并保存」） | 保留内存值，见 §五 |
| 13 | 审计：应用结果一行；保存结果一行 | 写失败只提示，不回滚 |

**状态机**：`Idle → Sealing → Prechecking → Applying → Verifying → Committed`；
旁支 `Rejected` / `Cancelled` / `RollingBack → RolledBack | RollbackFailed`。
`Applying` 期间 `CanCancel=false`（取消会让回滚边界不可定义）。
保存独立成 `SaveState`（NotRequested/Saving/Saved/Failed），不与应用态混。

## 二、运行门闸（封门 + 在途计数）

### 2.1 语义

- `TryBeginStart()`：锁内判 `_sealed`；未封则 `_inFlight++`，返回租约；已封返回 false。
- `EndStart()`：锁内 `_inFlight--`，唤醒等待者。
- `TryBeginApply()`：锁内判 `_sealed`；置 `_sealed=true`，等待 `_inFlight==0`（≤3s）；
  超时则撤封返回 false；成功返回租约，`Dispose` 时撤封。
- **封门后必须复判运行态**：在途启动可能在等待期间把会话置为 `IsRunning=true`；
  复判发现有在跑 → 撤封、拒绝、零写入。
- 为什么不用读写锁：run 的 `finally` 在 `await` 之后由线程池执行，`ReaderWriterLockSlim` 要求同线程释放；
  写锁阻塞会把 UI 冻住整轮连续运行；在途计数语义正好是「没有任何启动能穿过应用窗口」。

### 2.2 入口清单（6 个）

| # | 入口 | 文件 | 封门后的行为 |
| --- | --- | --- | --- |
| 1 | UI 主运行/单次 | `ShellViewModel.cs:1499-1521, 1594-1616` | 拒绝 + 状态栏提示 |
| 2 | 流程列表运行 | `FlowListViewModel.cs:300-321` | 同上 |
| 3 | HTTP 触发 | `HttpImageServer.cs:251-303` | 409 + 不 Push 图 |
| 4 | SCADA 运行 | `ScadaFlowRunner.cs:91-158` | false + reason |
| 5 | 定时/变量触发 | `FlowAutoRunner.cs:23-72` | 跳过本拍，Warn 不 Error |
| 6 | 子程序调用 | `FlowInvoker.cs:81-84` | Fail，父流程步骤失败 |

另两处必须一起改（否则门闸有洞）：
- `FlowEngineService.TryOccupySession`（`FlowEngineService.cs:221-235`）是引擎原子启动点，
  UI/SCADA 两条批量路径内联编译后直接调它，必须补「运行中守卫 + 封门检查」。
- `FlowSessionFactory.CompiledVersion` 改为**编译前快照**：
  `var versionBefore = flow.Version; var compiled = compiler.Compile(...); session.CompiledVersion = versionBefore;`
  否则编译期间 `Version++` 会把混合图纸判成新鲜。

**放 Engine**：门闸是会话生命周期的横切关注点，两个入口本身在 Engine；
放宿主必漏 HTTP/定时的编译窗口。接口放 Engine 程序集，**不动 `Core.Interfaces`**。
按 R12 属大改动（跨 Engine + 宿主 8 文件、改启动语义）→ 架构评审 + 独立审查 + `docs/code-changes/`。

### 2.3 测试钩子

门闸暴露三个确定性 hook：`AfterSeal`、`AfterInFlightAdded`、`BeforeEachWrite`。
用例：
1. `AfterSeal` 阻塞时起流程 → 拒且未编译（变异：删 sealed 判断 → 红）。
2. 在途启动阻塞时 apply → 等待后失败、零写入。
3. apply 窗口内 6 入口全拒，且 `IsRunning` 全 false（证明置位在门内）。
4. apply 抛异常 → `finally` 撤封，随后起流程成功（变异：删 finally → 红）。
5. 子程序遇封门快速失败、不阻塞（超时判红）。
6. `gate=null` 时 6 入口行为逐字不变（录 golden：日志序列、返回值、状态事件）。

## 三、写入、回滚、终检

### 3.1 顺序

**本地变量 → 点位 → 步骤参数**。

- 变量最可能失败（类型/只读/系统变量），放最前；失败时未动其它两类。
- 点位纯配置写、不触发运动；放在步骤前。
- 步骤参数 `SetInputValue` 会 `Version++` 并使已注册会话陈旧，放最后，避免前面失败留下「图纸版本已变」。
- **点位内部顺序：Speed → Accel → Position**。Position 是唯一有机械后果的字段；
  中断时中间态应是「旧目标 + 新速度」，不能是「新目标 + 旧速度」。
- **变量触发源排除**：`FlowModel.TriggerVariable` 指向的变量 v1 不进 schema；
  捕获时直接不列，应用时若条目指向它 → 整单拒绝并说明「触发源变量写入会起流程」。

### 3.2 回滚

- 逆序（步骤 → 点位 Position/Accel/Speed → 变量），逐条记、遇错继续（不在首个失败处停）。
- 每条记 `RestoreOk` / `RestoreFailed(目标名, 原因, 当前实际值)`。
- 全成 → `RolledBack`；任一失败 → `RollbackFailed`：
  - `ActiveRecipeId` **保持应用前的值**（不置 null、不置新值）；
  - 常驻红色横幅「回滚未完成：N 项未恢复 / 当前值与任何配方都不一致」+ 目标清单；
  - 只给两个显式出口「重新应用上一配方」「从磁盘重载」；**锁定后续 apply 直到用户确认**；
  - 审计 Failed 并列未恢复项。
- 回滚快照对数组/引用类型做 JToken 往返深拷贝，避免订阅方就地改污染快照。
- 应用期间不处理消息循环、不弹窗（snapshot→rollback 之间无 `DoEvents`/`MessageBox`）。

### 3.3 终检（不一致=失败，不降级为警告）

| 目标 | 检查 |
| --- | --- |
| StepInput | `StepID` 存在、`PluginTypeName` 未变、键存在、按 `DeclaredType` 规范化后逐字段相等、端口未变成已链接 |
| LocalVariable | `VariableId` 存在、仍是本地变量、值相等（数组逐元素、double 不加 epsilon） |
| MotionPoint | 集合实例与元素数不变、该点同一引用、三 double 精确相等、全表指纹不变 |

- 含 StepInput 时附 `FlowModel.Version > 应用前` 作 canary（证明确实走了通知路径）。
- 读回≠写入说明被静默丢弃或并发覆盖；继续宣布成功就是假成功。

## 四、变量写入（通讯域定稿）

- 入口：`ISharedVariableAccess.TryWrite(variableId, fallbackName: "", value, out error)`。
  **不要**用 `IGlobalVariableWriter`（只有按名重载，`Shard/Core.Interfaces/IGlobalVariableWriter.cs`）；
  **不要**直接 `Value=` 或 `LocalVariableModel.TryWrite`（不校验类型，`LocalVariableModel.cs:119-124`）。
- `fallbackName` 必须为空：writer 是「Id 优先、名字兜底」，变量删了而同名新变量存在时会写错目标。
- 宽化（int→double）writer 不放行（只放宽文本）；配方自己按 R3 §4.3 转成变量**当前** `DataType` 再写。
- 回读 `TryRead(id, "")`：不一致=失败→回滚。回读==旧值→「写入未生效」；回读==第三值→「并发写」。
- 网络变量：捕获不进候选、应用整单拒绝、零写入。文案：
  「条目「X」指向网络变量：本功能只写上位机内存，不写 PLC。请改用『PLC 按配方号自取』或流程『写变量』步骤。」
- 通讯线程：**不暂停、不清缓存、不重连**（应用只改本地变量私有字段；重连会丢质量戳与一拍）。
- PLC 配方号：v1 只定变量契约 + 只读监视，不做内置状态机。

## 五、保存、草稿、ImageHub

- 默认只应用不保存；「应用并保存」是显式次按钮。
- 保存必须复用现有链：布局 Capture + `VariablePersistenceService.Capture` + 通讯 Capture + `SaveAsync`
  （`ShellViewModel.cs:954-997`）；Capture 必须在 apply 之后。现状 `SaveSolutionAsync` 无条件弹 `SaveFileDialog`，
  需抽 `SaveToPathAsync(path)`；方案从未落盘时，「应用并保存」必须强制另存。
- 保存失败：**保留内存值、不回滚**；`ActiveRecipeId` 保持新值；状态 `CommittedUnsaved`；
  界面「已应用（未保存）」+ 错误原文；审计第二行记失败。
- 退出时 `SolutionDraftService.Capture` 会因「内存序列化≠磁盘文本」写出 `Autosave\`，下次启动提示。
- **不清 ImageHub**：配方不换方案；既有纪律是 `TryRemove(RequestId)` 精确回收、禁整槽清
  （`HttpImageServer.cs:298-300`）。`Version++` 使会话陈旧，下次运行 `RegisterSession` 自然清该流程槽。
- SCADA 运行窗口开着：**警告**（「建议先停止运行态」），不硬拒；真正的闸是流程会话。

## 六、运动点位前置（定稿）

| 项 | 判定 | 依据 |
| --- | --- | --- |
| 运行会话 | 拒绝 | `SnapshotSessions` / `AnyFlowRunning`；Paused 也算 |
| 全轴静止 | 拒绝 | 目标卡 `State==Online/Alarm`；`PendingCommandCount==0`；全卡所有轴 `Moving==false` 连续两拍（间隔 ≥1 个轮询周期）；`Timestamp` 新鲜（age ≤ max(2×PollInterval, 300ms)） |
| 报警 | 警告 + 放行 | 应用不动轴；若轴在走会被上一行拒 |
| 安全停机 / 连接中 | 拒绝 | 轮询不跑/缓存清空，静止不可判 |
| 离线 | 放行 + 警告 | 无命令线程；审计注明「未做快照校验」 |
| 未回零 / 未使能 | 放行 + 警告 | 点位是绝对坐标配置；执行期门禁照旧判 |
| 软限位越界 | 逐点警告，不夹取 | `CheckMove` 在「走此点」时硬拦；整单拒绝会让「一行未用点位越界」永久锁死换型 |
| Index 越界 / NaN / 轴不存在 | 拒绝整单 | 结构性非法 |
| 轴停用 | 警告 + 放行 | 写入不可见，确认页必须列明 |

- 判据计算两次：预检一次、写入前一次；状态变化→「状态已变化，请重新确认」。
- `PendingCommandCount` 不含正在执行的那条（`TakeNextLocked` 先出队再执行）；
  v1 用「`Moving` 两拍 + `PendingCommandCount==0` + 操作员确认」近似；
  v2 再给 `MotionDeviceBase` 加在途命令计数（契约改动，单独评审）。
- 不要求回零、不强制 Home；应用后横幅提示「轴 X 未回零/位置不可信」，首次走点前门禁照旧判。
- 确认页提示「流程按步骤 Target 走，点位只被『走此点』/SCADA 轴面板消费」；
  同轴既有 Target 又有配方点位时并列两侧值，不自动改任何一侧。

## 七、审计与可观测

- 一次应用一行：批次 Id、时间、操作者、配方 Id/名/`ContentVersion`、目标/成功/回滚/回滚失败/终检不符计数、结果、原因。
- 回滚失败逐项补行。值文本不变文化、单值 ≤256 字符；数组记长度+前 3 项+指纹。
- 审计写失败不阻断（`ScadaAuditWriter` 返回 bool 不抛），但 `IsFaulted`/`LastError` 必须上常驻横幅；
  **审计不可用时禁止「应用并保存」**（可仅应用 + 明示无审计）。
- 界面必须显示：配方名+`ContentVersion`、目标/成功/回滚/回滚失败/终检不符、
  `ActiveRecipeId` 前后值、「已应用未保存」、拒绝原因（哪个流程、running/paused）、
  `HasRollbackFailure` + 未恢复项。

## 八、运行期断言（`RecipeChecks`，至少 20 条，★反向）

1. 正常链逐字段相等 + 审计 Success 一行。
2. ★ 写入轨迹证明全走 `SetInputValue` 且 `Version` 严格增大（直写字典即红）。
3. ★ 应用后 `IsStale` 为真（不推进=跑旧值）。
4. 第 N 项失败 → 全量回滚、指针不变。
5. ★ 回滚中再抛 → 结果=回滚失败并列出未恢复项。
6. ★ 终检不符却报成功 → 红。
7. ★ apply 中 6 入口全拒、`IsRunning` 全 false。
8. ★ 运行中（含 Paused）apply 被拒且值逐字段不变。
9. 交错：封门内阻塞时 apply 被拒。
10. ★ 收尾注入异常后计数归 0、apply 仍可进。
11. ★ 编译后注册前 bump `Version` → 会话必须判 stale（CompiledVersion 快照）。
12. ★ 触发源变量被写 → 必须显式拒绝或明示未触发；静默丢边沿即红。
13. 指向网络变量 → 整单拒绝且 PLC 写次数 0。
14. ★ 审计写失败 → 应用仍成功但横幅为真且「应用并保存」被禁。
15. 点位引用同一、元素数不变、`Speed=0` 仍为 0。
16. ★ 软限位越界 → 应用成功、警告逐点、值不夹取。
17. ★ 全轴 Moving 时 apply 被拒且点位逐字段不变。
18. ★ 保存失败 → 值仍为新、指针=新、状态=CommittedUnsaved、退出草稿被写出。
19. ★ 应用前后 ImageHub RequestId 集合不变（不清槽）。
20. ★ `gate=null` 时 6 入口 golden 逐字不变。
