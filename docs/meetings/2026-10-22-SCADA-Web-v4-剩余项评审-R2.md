## 一、协议收口

### 收敛结论

1. **`cmd.result` 本批做**（comm/hmi/architect 同意；reviewer 反对“服务端先行”）。
   - 服务端：`Dedup` 升级为 `Reserved → Running → Done` 三态；`Begin` 在入队前占位，`Complete` 只对 Done 保持 write-once，`TryPeek` **只读不删**（30 分钟内都能查）；`cmd.result` 在 `HandleTextFrame` 直答、不入泵、不过版本闸/审计 fail-closed/撤销闸；响应 `type:"result"`、`id`（查询自身）、`targetRequestId`、`state`，**不带 `ok`**。
   - 客户端：超时不立即 reject；把 `{id,kind,sentAt}` 存一份（上限 32），先发 `cmd.result`；`done` 直接 resolve、`running` 退避再查、`unknown` 才 `E_TIMEOUT`；重试复用同一 requestId；重连后只查不自动重发。
   - 反对意见（reviewer）：没有客户端持久化/在飞状态时，服务端先做就是死代码 + 占位污染幂等表；必须在同一批完成客户端查询，否则不做。
2. **分片本批不做**（hmi/architect/reviewer 同意；comm 主张做）。
   - 理由：字符串分片不降低 `JSON.parse` 成本（最终仍要拼回整串解析一次）；只降低 HOL，不解决 ack 队头；半套分片（无 resync/控制通道）比不做更糟。
   - 替代：`SnapshotMaxBytes` 接成**发送前硬闸**（>3.5MB 不发、不推进页键、回 `E_SNAPSHOT_TOO_LARGE` + bye）；4MB WS 上限已能承载 3000 图元 1.5–1.8MB 快照。
   - 下一批入口：控制通道 → `view.resync` → 分片，三者一个单位。
3. **24 槽本批做**（comm/hmi/architect 同意；reviewer 反对）。
   - 新类 `ScadaWebAdmissionGate`：`active ≤ MaxSessions(16)` + `handshake ≤ 8` 一把锁；在 ticket 核销处预留握手、WS 入册转活跃、所有失败出口幂等释放、5s TTL（`min(5s, 票剩余)`）；presence 2s 循环先清握手 TTL 再清 45s 死连接。
   - 第 17 个活跃：**WS 1013 + bye**（不是 HTTP 503；503 会被前端渲染成“登录失败”）；容量拒绝**不得撤销复用令牌**，新签令牌才回收。
   - 反对意见（reviewer）：准入闸容易双减/漏减；建议用同 token 接管替代第二本账。R3 裁决。
4. **控制通道**：本批不做独立通道；`cmd.result`/24 槽不改出站通道，风险可控。分片/大消息的 ack 队头问题记入“未覆盖”，下一批与控制通道一起做。

### 争议

- cmd.result 的 `Begin` 是否会让“排队中重复请求”被误拒；reviewer 给出“占位吞命令”的反例。R3 裁决实现细节（`Begin` 只占位、不改变 Check 的 Cached 分支；Running 重复回 `E_IN_FLIGHT`）。
- 24 槽是否值得做；reviewer 主张用同 token 接管。R3 裁决。

## 二、复杂图元数据通道

### 收敛结论

1. **Hub 放 `VM.Scada`**：新增 `IScadaRuntimeDataHub`（读）与 `IScadaRuntimeDataSink`（写）；每条数据带 `(runGeneration,pageId,elementId,version)`；整表不可变快照、单写者（UI 线程）、Web 只读。控件在 `ChartTrendElement`/`DataGridElement`/`AxisPanelElement`/`ImageViewElement` 的现成钩子 append；`BeginRun/EndRun` 清表。
2. **不能靠遍历可视树按 ElementId 找控件**：编辑器/运行窗口各一份、容器子控件可能不在可视树、`RebuildElements` 会重建、窗口关闭读不到。R1/R2 红队一致反对。
3. **图像**：先让 `ScadaWebValueResolver` 跳过 `Hmi.ImageView/Source`（现在每 10Hz 做全尺寸 HImage→BitmapSource，且把类型名当 text 发）；`/img` 必须直接 `Response.Send(bytes)`（`server.Get` 会把 byte[] 变 base64）；token 按会话/元素/版本，45s、最多 3 个、只放 query。
4. **ChartTrend 不必等 Hub**：`Value` 是普通绑定，frame 已在送；客户端按帧本地攒点 + Canvas，keyframe 不 reset。
5. **AxisPanel/AxisConsole**：`IScadaAxisSource` 在 VM.Scada 可直接解析；候选轴在 `Properties["AxisOptions"]`；`SelectedAxisId` 是控件私有 DP、不在快照里 → Web 只能默认首轴 + 客户端下拉；A 范围下不画命令按钮。
6. **DataGrid**：行是控件私有“触发时刻抓取”的缓冲，Web 不能从值帧推导；本批只做结构/空态，数据通道下一批。
7. **默认值一致性**：不建 `factory.defaults` 第二份事实源；`/api/catalog` 已有 `DefaultValue`，客户端首屏拉一次、渲染前把缺键补进 `el.Properties`；补键后 134 处字面量回退不可达。闸 = 静态扫读键 + 断言 catalog 有该键 + 断言归一化在首帧前执行。
   - 红队反对：catalog 的 `DefaultValue=""` 同时表示“没默认”和合法空串；现有 JS 已与描述符漂移（Clock Format/Text）。必须用 `ctx.default(typeKey,key)` 或“首帧归一化 + 静态读键扫描”，并接受“视觉未验”。

### 争议

- DataGrid 是否必须等 Hub：hmi 说必须（采行是控件私有边沿+写确认变量）；reviewer 说只能 Hub；architect 说本批仅结构/空态。R3 裁决。
- 默认值闸：ui 主张“catalog 首帧归一化 + 134 处读键扫描”；reviewer 主张“运行时哨兵测试 + 只留 catalog”。R3 裁决。
- Axis 是否本批做：hmi 说可做；architect 说结构+只读首轴；reviewer 说轴写/选中态不做。R3 裁决。

## 三、压测与性能报告

### 收敛结论

1. **现有 ScadaWebStress 是冒烟级**：值从不变化、`MaxSessions=Math.Max(64, clients+8)` 把预算夹成 11.6KB、字符数当字节、无慢消费者/重连/停服、同进程抢核、`--no-build` 会跑旧 DLL。
2. **必须两进程**：`--mode host|client` / `--endpoint`；host 打印 `PORT=`；客户端所需 pageId/pageVersion/runGeneration 从 hello/snapshot 取；CPU 可按进程归因。
3. **夹具最小集**：`--variables`、`--boundElements`（勿用 `--bindings 1000`）、`--changePct 10/30/100`、`--changeHz`、`--cmdIntervalMs`、`--slowClient`、`--reconnectStorm`、`--maxSessions 16`、`--warmupMs/--durationMs`、`--outDir/--runId`、`--stats`。
4. **统计**：收包原始 UTF-8 字节（`result.Count`）；逐帧 p50/p95/p99（nearest-rank）；1s 滑窗 Mbps（均值+峰值）；帧率；ack send→match；Dropped/队列深度/GC/WorkingSet；keyframe 与 delta 分桶。
5. **场景**：S1 满载 16×3000×1000×10Hz（10/30/100% 变化，≥60s）、S2 首屏、S3 慢消费者、S4 重连风暴、S5 第 17 连接；S6-S12（握手风暴、64KB、坏 JSON、分片、停服、浏览器、真实网卡、长稳）按能力做或写“未覆盖”。
6. **阈值**：delta p95 ≤ `EffectiveFrameBudgetBytes`（代码实测 46,484B）；聚合 1s 均值 ≤70Mbps、峰值 ≤100Mbps；ack p95 ≤200ms；首屏 ≤3s；重连 ≤15s；errors=0、正常端 dropped=0、帧率 ≥9.5Hz。
7. **证据**：`docs/performance/evidence/<日期>-<S#>-<runId>/` 下 `meta.json`、`raw.jsonl`、`stats.csv`、`server.log`、`summary.json`、`README.md`；复算脚本从 raw 重算 summary 逐字段一致。
8. **报告必须写未覆盖**：真实网卡/交换机/WiFi、浏览器 DOM/布局/绘制、1.5MB parse、分片、24 槽（若未做）、17 端（若被夹具掩盖）、长稳、三端一致。

### 争议

- 两进程 vs 同进程：双方同意两进程；同进程只作为“上界”对照。
- 浏览器：本批不引 headless（环境/时间），报告只写协议层；reviewer 要求每条“未覆盖”写清影响哪个结论。
- 70Mbps 与 46KB 的关系：46,484B 是 `70Mbps×0.85/16/10` 的推导上限，聚合上限约 59.5Mbps；“达到 70Mbps”设计上不可能，报告必须写“预算合规”而不是“跑满 70Mbps”。
