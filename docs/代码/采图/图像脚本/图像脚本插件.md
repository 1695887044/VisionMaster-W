# 第 0 章 这是什么

**图像脚本 = 让你直接写 HALCON 脚本（HDevelop 语言），当成一个流程节点来跑。**

> 生活比喻：其它插件是"成品工具"（Blob、卡尺、OCR 各有各的面板）。图像脚本是"**万能工具箱**"——你直接写代码，想做什么就做什么，输入输出还能像普通插件一样连线。

它在流程里的位置（归在 **「图像处理」** 分组）：

```
[图像采集] → [创建 ROI] → [预处理] → [图像脚本] → [后续节点]
                                    ↑ 动态端口（按声明的变量生成）
```

**一句话**：当内置插件覆盖不到你的需求时（特殊算法、多步组合、临时验证），用图像脚本——**你写的 HALCON 代码就是算子**。

## 0.1 它的三个超能力

1. **全部 HALCON 算子可用**（数千个，含 3D/标定/分类/OCR/码/形态学/`tuple_*` 全族）。
2. **输入输出是动态端口**——你在配置界面声明什么变量，画布上就长出什么端口，能正常连线。
3. **内置 54 个示例模板**（11 大类），从"划痕检测"到"手眼标定+抓取"，可一键插入改改就用。

## 0.2 与 C#脚本的区别

| | 图像脚本（本插件） | C#脚本 |
|---|---|---|
| 语言 | **HDevelop 脚本**（类 Pascal） | **C#**（Roslyn） |
| 引擎 | HALCON `HDevEngine` | Roslyn Scripting |
| 强项 | 图像处理、HALCON 算子 | 逻辑、LINQ、变量、流程控制 |
| 分组 | 图像处理 | 逻辑控制 |

# 第 1 章 设计思想

## 1.1 核心原理：动态端口（本插件最重要的概念）

**端口不是写死的，而是由你在配置界面声明的变量表生成的。**

```
你在「输入变量」表加一行：名称=Image，类型=HImage
        ↓ 自动重建
画布上长出输入端口 Image（HImage）
        ↓
脚本里可以直接用变量 Image
        ↓
你在「输出变量」表加一行：名称=Result，类型=String
        ↓ 自动重建
画布上长出输出端口 Result（String）
        ↓
脚本里写 Result := 'OK'  就能输出到端口
```

> 变量表里的**名字 = 端口名 = 脚本里的变量名**，三者是同一个字符串。

### 为什么必须在 `ApplyConfigValues` 里重建

> 动态输入端口必须在 `ApplyConfigValues`（编译器的 `LinkPorts` 之前）重建，否则按名连线失败。

## 1.2 四条设计要点（类注释原文）

```
- 动态输入端口必须在 ApplyConfigValues（编译器的 LinkPorts 之前）重建，否则按名连线失败；
- 动态输出端口沿用 IDynamicOutputProvider.RebuildDynamicOutputs 范式，并写 StepData 快照
  （编译期 StepData 为 null，用 if 守卫）；
- HDevEngine 静态单例 + 脚本内容指纹缓存，内容不变则复用已编译的 HDevProcedureCall；
- 试运行由主程序外壳（PluginConfigShell + PluginTestRunner）提供，本视图不含"执行"按钮。
```

## 1.3 脚本怎么存

脚本**不是独立文件**，而是 `EProcedure`（过程名 + 四类接口 + 正文 `Body`）随 `[StepConfig]` 内嵌进 `.vms` 方案。

需要编译/导出时才由 `EProcedure.SaveToFile()` 生成 HDevelop 的 `.hdev` XML。

## 1.4 默认脚本：开箱即用

首次打开会自动预置一个默认脚本（1 图进 → 1 图出 + OK/NG 结论）。

> **判据取的是「从未保存过脚本配置」而不是「当前没有脚本」**：前者只送一次（用户手动删空并保存后不再回来），后者会让删不掉的脚本变幽灵。

默认过程名是 **`script`**——**不能叫 `main`**（运行过程下拉明确排除 `main`，否则看不到也执行不到）。

## 1.5 显示：脚本里的图怎么显示出来

脚本里的 `dev_display` / `dev_disp_text` 不是画到真实窗口，而是**回调到 C# 的显示后端**，画进一张离屏 buffer 窗口，最后回读成"效果图"发到预览窗口 1。

> ⚠️ **注册后端后，原生 `open_window` / `set_color` / `disp_text` 照样编译通过、也不报错**，但它们画的是另一个窗口——**效果图会静默变空白**（实测 `Capture()` 直接返回 null）。所以那些老写法由 `LegacyDisplayShim` 在编译前自动改写成 `dev_*`。

# 第 2 章 技术特点

## 2.1 元数据

| 特性 | 值 |
|---|---|
| `Name` | 图像脚本 |
| `GroupName` | 图像处理 |
| `Description` | 导入/编写 Halcon 过程脚本并执行，输入输出变量可显式声明类型并连线 |
| `ShortName` | 代码图标（FontAwesome `f121`） |

实现 `IPluginCustomViewProvider`（自带配置视图）+ **`IDynamicOutputProvider`**（动态输出端口）。

## 2.2 端口完整清单

### 固定端口

只有基类的 `Success` / `ErrorMessage` 两个输出。

> **没有声明式固定输入端口**——全部由变量表动态生成。

### 动态端口（核心）

| 类型 | 生成规则 |
|---|---|
| **动态输入** | `InputVars` 表里每一项 → 一个 `InputPort<T>`，端口名 = 变量名 |
| **动态输出** | `OutputVars` 表里每一项 → 一个 `OutputPort<T>`，端口名 = 变量名 |

**声明类型 → CLR 类型映射**：

| `ScriptVarType` | 端口类型 |
|---|---|
| `Int` | `InputPort<int>` / `OutputPort<int>` |
| `Double` | `double` |
| `String` | `string` |
| `HTuple` | `HTuple` |
| `HObject` | `HObject` |
| `HImage` | `HImage` |
| `HRegion` | `HRegion` |
| `HXld` | **`HXLDCont`**（注意大小写不同） |
| 其它 | `object` |

**重建触发点**（6 处）：构造函数、`ApplyConfigValues`、变量表整体替换、增删改行（`CollectionChanged`）、**改"类型"下拉**、视图主动 `NotifyVariablesChanged()`。

**UI 怎么跟上**：`PortsVersion` 计数器——端口重建后发属性通知，让行内 `MultiBinding` 自动重取新端口对象（替代 `Items.Refresh`）。

## 2.3 配置项（4 个）

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `Procedures` | `List<EProcedure>` | 空 | **脚本本体**：全部过程（接口四类 + 正文） |
| `SelectedProcedure` | string | `""` | 当前要运行的过程名 |
| `InputVars` | `ObservableCollection<ScriptVarDef>` | 空 | 输入变量定义 → 动态输入端口 |
| `OutputVars` | `ObservableCollection<ScriptVarDef>` | 空 | 输出变量定义 → 动态输出端口 |

### `ScriptVarDef` 字段

| 字段 | 说明 |
|---|---|
| `Name` | 变量名 = 端口名 = 脚本里的变量名 |
| `Type` | 声明类型（改了端口按新类型重建） |
| `ManualValue` | 手填值（仅 int/double/string 有意义；**图形类必须连线，不能手填**） |
| `Remark` | 备注 → 用作随图信息名 + 端口 Description |
| `DisplayWindow` | `0=不显示，1~9=窗口1~9`（**仅图形类有效**） |
| `IsIconic` | `HObject/HImage/HRegion/HXld` 为 true（必须连线，不能手填） |

## 2.4 脚本引擎：HALCON HDevEngine

| 项 | 说明 |
|---|---|
| 引擎 | `hdevenginedotnet`（**不是 Roslyn，不是自研**） |
| 语言 | HDevelop 脚本语言（类 Pascal） |
| 过程路径 | 固定指向临时目录 + 自定义算子目录 `ScriptAssets/procedures` |
| JIT | `execute_procedures_jit_compiled = true`（脚本含大量循环时提速明显） |
| 显示后端 | `SetHDevOperators(new HDevDisplayBackend())` |
| 编译缓存 | `Dictionary<string, HDevProcedureCall>`，键 = SHA256 指纹；>64 条整表清空 |
| 预热 | 构造时后台线程编译执行一个 `return ()` 空过程，消除首次加载原生库的数秒卡顿 |

> **为什么自定义算子要走 `.hdvp` 文件**：`.NET 版 HDevelop Engine 根本没有注册外部算子的 API**（反射确认 `hdevenginedotnet`/`halcondotnet` 里没有任何 `*External*` 类型，也没有 `RegisterProcedure`）。教程里那套 `HExternalProcedure` 是 C++/CLI 的。

## 2.5 性能与独特实现

| 手段 / 设计 | 做法 | 收益 |
|---|---|---|
| **SHA256 指纹缓存** | 脚本内容不变 → 复用已编译 `HDevProcedureCall` | ⭐⭐⭐ 零成本复用 |
| **引擎预热** | 启动期后台编一个空过程 | ⭐⭐⭐ 消除首开/首运行卡顿 |
| **JIT 编译** | `execute_procedures_jit_compiled` | ⭐⭐ 大量循环提速明显 |
| **54 个示例模板** | 11 大类，一键插入 | ⭐⭐⭐ 不用从零写 |
| **资源短名** | `read_image(X,'marks')` 自动指向 `ScriptAssets/images/marks.png` | ⭐⭐ 脚本里免路径 |
| **老算子自动垫片** | 编译前把 `open_window`/`disp_obj` 等改写成 `dev_*` | ⭐⭐⭐ 老脚本拿来就能跑 |
| **指针/合成用纯算子** | `paint_region`/`paint_xld` 合成，不开窗口 | ⭐⭐ 线程安全、无 GUI 依赖（旧方案会抛 #1305） |
| **122 个精编中文算子文档** | 补全时优先展示 | ⭐⭐ 智能提示好用 |

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.ImageScript.dll`，`ScriptAssets` 由 PostBuild 投递。
2. 重开软件，工具箱里出现「图像脚本」（**图像处理** 分组）。

## 3.2 配置界面总览（两列）

```
┌────────────────────────────┬──────────────────────────────┐
│ 左：380px 可滚动             │ 右：AvalonEdit 脚本编辑器        │
│  ① 脚本过程                  │  签名行（过程签名，灰字）         │
│     编辑目标 / 运行过程 下拉  │  代码区（行号 + 语法高亮）        │
│     6 个按钮：               │  校验结果（绿 ✔ / 红 ✘）         │
│     新建/删除/导入/导出/      │                              │
│     同步接口变量/恢复默认     │                              │
│  ② 输入变量（名称/类型/连线） │                              │

└────────────────────────────┴──────────────────────────────┘

**编辑器能力（全都有）**：语法高亮、智能补全、参数提示、悬浮文档、Tab 参数步进、撤销/缩进/括号配对/注释切换/缩放/当前行高亮/查找替换。

**右键菜单**：编译（校验）/ 注释 / 取消注释 / **插入示例代码（54 个模板按分类分组）**。

## 3.3 第一次写脚本（5 步）

**第 1 步｜拖节点**：新建就有默认脚本（1 图进 → 1 图出 + OK/NG），可以直接跑。

**第 2 步｜接输入**：「输入变量」表里有 `Image`（HImage），在行内点 🔗 连上游图像输出。
> 图形类（HImage/HRegion/HObject/HXld）**必须连线，不能手填**。

**第 3 步｜写脚本**：右侧编辑器写代码。默认脚本骨架：
```hdevelop
* 计数通道判断转灰度
count_channels (Image, Channels)
if (Channels == 3)
    rgb1_to_gray (Image, GrayImage)
else
    copy_image (Image, GrayImage)
endif
* 阈值 + 连通域
threshold (GrayImage, Region, ThreshMin, 255)
connection (Region, ConnectedRegions)
select_shape (ConnectedRegions, Defects, 'area', 'and', MinArea, 9999999)
* 判定
count_obj (Defects, Number)
if (Number > 0)
    Result := 'NG'
else
    Result := 'OK'
endif
* 标注
dev_display (GrayImage)
dev_set_color ('red')
dev_display (Defects)
dev_disp_text ('判定: ' + Result, 'image', 12, 12, 'green', [], [])
* 输出
ResultImage := GrayImage
```

**第 4 步｜校验**：编辑器右键 → 编译（或「校验脚本」按钮）。绿 ✔ 通过；红 ✘ 会标出**真实行号**并跳转。

**第 5 步｜设输出显示**：「输出变量」表里图形行的「显示到窗口」选 1~9，该图会推到主界面对应窗口。

## 3.4 类型选择速查

| 你想接/出什么 | 选什么类型 |
|---|---|
| 图像 | `HImage` |
| 区域（阈值/连通域结果） | `HRegion` |
| 轮廓/XLD（亚像素边缘、拟合线圆） | `HXld` |
| 不确定是图像还是区域还是轮廓 | `HObject` |
| 整数 | `Int` |
| 小数 | `Double` |
| 文本 | `String` |
| HALCON 元组（数组） | `HTuple` |

> ⚠️ **类型选错是常见坑**：`threshold` 出区域、`edges_sub_pix` 出轮廓。若输出表类型选错，插件会把 HALCON 的天书报错翻译成"改哪个下拉"的可操作指引。

## 3.5 参数调节速查表

| 现象 | 处理 |
|---|---|
| 端口没出现 | 在变量表里加行；改了类型/名字会自动重建端口 |
| 编译报 `invalid program line: N` | 插件已把"第 N 个**非空行**"换算成编辑器真实行号，看红字提示 |
| 脚本报"引用了接口里没有的变量" | 变量名没加到输入/输出表 → 点「同步接口变量」 |
| 效果图空白 | 用了原生 `open_window`/`set_color`/`disp_text`（不报错但画到别的窗口）→ 改用 `dev_*` |
| 想送图到主界面窗口 | 用 `publish_preview (Image, 3)`（**只能送图像**，区域/轮廓会被静默丢掉） |
| 想标注矩形/圆/线 | HALCON 没有 `disp_rectangle1` 之类 → 先 `gen_rectangle1` 再 `dev_display` |
| 字号串台 | 脚本半路抛异常会漏掉字体还原，把大字号串给后面所有脚本 |

## 3.6 FAQ

**Q1** 脚本里能用什么？
全部 HALCON 算子（数千个）+ 你声明的接口变量 + 17 个 `dev_*` 显示回调 + `publish_preview`。

**Q2** 能写注释吗？
能，但**注释必须独占一行**（`*` 或 `'` 开头）。**行尾拖注释是非法的**（`threshold(...) * 注释` 会报 `invalid program line`）。

**Q3** 为什么默认过程叫 `script` 不叫 `main`？
运行过程下拉明确排除 `main`——叫 main 会导致下拉里看不到它、执行时也找不到过程。

**Q4** 能导入现成的 `.hdev` 吗？
能。点「导入.hdev」。导入优先指向 `main` 但运行列表排除它，所以要在运行下拉里另选过程。

**Q5** `publish_preview` 和"显示到窗口"下拉有什么区别？
- `publish_preview (Image, N)`：脚本里主动推送（绕过效果图画布），**只能送图像**。
- 「显示到窗口」下拉：把输出变量（图形类）推到指定窗口，支持区域/轮廓。

**Q6** 输出表声明了但脚本没赋值会怎样？
报 `$"输出参数[{v.Name}]在脚本中未被赋值（接口声明了它，但脚本没有写入）"`——避免 HALCON 裸报 "Index out of range"。

**Q7** 有超时/沙箱吗？
没有超时配置。脚本是本地代码，不做沙箱限制。

## 3.7 现场排障

| 报错 / 现象 | 排查 |
|---|---|
| `未选择要运行的脚本过程` | 运行过程下拉没选 |
| `输入变量[X]未链接或图像为空` | 图形输入没连上游，或上游图是空的。**脚本一行都不执行** |
| `invalid program line: N` | 三类原因：① 行尾拖注释 ② 全角标点 `，＇（）、“”` ③ 算子拆行（引擎不支持续行） |
| `unresolved procedure call` | 用了不支持的老窗口算子 → 看提示改用 `dev_*` 或 `gen_* + dev_display` |
| `Output object type mismatch (excepted image, got region)` | 输出表类型选错（插件会翻译成"改哪个下拉"的指引） |
| `输出参数[X]在脚本中未被赋值` | 脚本忘了给该输出变量赋值 |
| 效果图空白但不报错 | 用了原生 `open_window`/`set_color`/`disp_text` → 改 `dev_*` |
| `HImage could not be found` 之类 | 那是 **C#脚本**的问题（Roslyn 引用集），不是本插件 |
| `elongation` 特征不支持 | 本仓库 HALCON 23.05 不认识该特征名（`select_shape` 报 #3101）。⚠️ **模板库里有教写 `'elongation'` 的地方是错的**，改用 `smallest_rectangle1` 自算 |

# 第 4 章 异常与修复记录

> 本章记录**真实发生过的问题**（来自代码注释与开发文档）。每条给：现象 → 原因 → 修法。

## 4.1 缺陷修复总览

| 级别 | 问题 | 一句话 |
|---|---|---|
| P0 | `Area := Width * Height` 被误判成行尾注释 | **悄悄变成 `Area := Width`**——"不报错但算错"是最危险的失效模式 |
| P0 | 窗口句柄交给引擎后被搬空 | 之后所有绘制算子报 `#2453: HALCON handle is NULL` |
| P0 | 老式 `.hdev` 换行只按 `\r\n` 拆 | 整个脚本坍缩成一行 → `invalid program line: 1` |
| P0 | XML 声明 utf-16 但字节 utf-8 | HDevelop 解析报 "labelled UTF-16 but has UTF-8 content" |
| P1 | 注册显示后端后原生窗口算子静默空白 | 不报错但效果图空白 |
| P1 | `open_window` mode 只接受 `'buffer'` | `'invisible'/'visible'/'pixmap'` 一律报 `#1305` |
| P1 | `dev_disp_text` 必须 7 参 | 5 参简写编译不过 |
| P1 | xshd `Span` 下放 `Rule` 抛异常 | `HighlightingDefinitionInvalidException` |

| P2 | 反复 open/close 窗口 `#9302` 死锁 | 刻意不关窗口 |

## 4.2 P0/P1 级详解

### ① `Area := Width * Height` 被误判成行尾注释（最危险的一类）

**现象**：脚本悄悄变成 `Area := Width`，**不报错但算错**。

**原因**：清理行尾注释的逻辑把 `*` 一律当注释起始符，误伤乘号。

**修法**（注释原文）：
> ```
> 实测教训：Area := Width * Height 曾被误判成行尾注释、悄悄变成 Area := Width，
> 工业程序里这种「不报错但算错」是最危险的失效模式，宁可放行让引擎报错也不能改值。
> ```
> 现行判据：字符串外出现 `:=` 即赋值行，`*` 一律当乘号；需要清理时用**空格替换**保持列位与行号。

### ② 窗口句柄三条铁律（`#2453`）

**现象**：把内部持有的 `_win` 交给引擎后，之后所有绘制算子报 `HALCON error #2453: HALCON handle is NULL`。

**原因**：封送过程会把 `_win` 内部的 handle **搬空**。

**修法**（注释原文）：
> ```
> ★ 交给 HDevelop 引擎的窗口句柄必须是"新容器"，绝不能直接把内部持有的 _win 实例 out 出去。
> 另两条铁律：HTuple.Clone() 对句柄型抛 #2455；Append() 会偷走源 tuple 的句柄。
> 唯一可用的复制方式是 new HTuple(_win.H)。
> ```

### ③ 换行归一（脚本坍缩成一行）

**现象**：`invalid program line: 1`（HDevelop 视为"一行塞多个算子"）。

**原因**：编辑器手敲/粘贴的脚本常是 LF(`\n`) 或 CR(`\r`)，只按 `\r\n` 拆会让整个脚本坍缩成一个 `<l>` 节点。

**修法**：**先归一行尾再拆**。

### ④ XML 声明与字节编码不一致

**现象**：HDevelop 解析报 `labelled UTF-16 but has UTF-8 content`。

**原因**：先转 string 再 `File.WriteAllText` 时，`XmlWriterSettings.Encoding` 对 `TextWriter` 无效——声明恒为 utf-16 而字节是 utf-8。

**修法**：**必须用 `XmlWriter` 直接写文件**，声明与字节编码由 writer 统一生成、天然一致。

### ⑤ 注册显示后端后原生窗口算子静默空白

**现象**：原生 `open_window` / `set_color` / `disp_text` **照样编译通过、也不报错**，但效果图空白（实测 `Capture()` 直接返回 null）。

**原因**：它们画的是另一个窗口/句柄。

**修法**：`LegacyDisplayShim` 在编译前把老写法自动改写成 `dev_*`（见 5.2）。

### ⑥ xshd 两个坑（编辑器）

| 坑 | 现象 | 修法 |
|---|---|---|
| `Span` 下不能直接放 `Rule` | 抛 `HighlightingDefinitionInvalidException` | Rule 只能放 `RuleSet` 下 |
| `#` 未转义 | `<Rule>文本</Rule>` 会被强制加 `IgnorePatternWhitespace`，`#` 起行注释把后面全注释掉 → 规则退化成零长度匹配 → **只有行号、内容空白、无法编辑** | 必须写成 `\#` |

### ⑦ `MergeVars` 遇重名闪退

**现象**：点「同步接口变量」闪退。

**原因**：`ToDictionary` 遇到重复键抛 `ArgumentException`。

**修法**：用索引器逐个写入，容忍重名（后者覆盖前者）。

## 4.5 已知边界与待办

- ⚠️ **`FlowCanvasChecks/` 没有图像脚本专属断言**——默认脚本正文的 HALCON 语法**没有经过自动验证**。建议后续补断言（宿主已具备"真加载插件 + 真编译执行"能力）。
- **新步骤未开配置窗口前端口不存在**（端口由变量表驱动）。
- **`Image` 未连线直接失败**（脚本一行都不执行）。
- **「恢复默认脚本」不可撤销**（但方案未保存前关闭窗口即可放弃）。
- **默认脚本只补一次**（判据是"从未保存过"）。
- 默认脚本里的 `ThreshMin=128` / `MinArea=50` 是**示范值**，不是通用最优。
- 过程名 `script` 固定。
- 阈值不做成输入端口（写死在脚本里，自己改）。
- `GuessType` 名称启发式仍在（非图形 `i`→Int / `s`→String / 其余→Double）——**所以输出 `Result` 必须显式写 String**，否则会被猜成 Double。
- ⚠️ 模板库 `ScriptTemplates.cs:238` 教用户写 `select_shape (..., 'elongation', ...)` 是**错的**（本仓库 HALCON 23.05 不支持）。
- 字体三条实测：`Size=-1` **不是**还原默认（=16）；`dev_disp_text` 的 `['shadow']` 无效、`['font']/['size']` 会让算子失败。
- `publish_preview` **只能送图像**，区域/轮廓会被静默丢弃。
- HDevEngine 是**进程内 static 单例**，多个脚本节点会并发回调同一个后端实例 → 所有可变状态一律 `[ThreadStatic]`（且 `[ThreadStatic]` 字段不能依赖初始化器）。

## 5.7 附录 G：术语表

| 术语 | 含义 |
|---|---|
| HDevelop | HALCON 自带的脚本开发环境与语言（类 Pascal） |
| `HDevEngine` | HALCON 提供的脚本引擎（本插件用它执行脚本） |
| 过程（Procedure） | 一段带接口（io/oo/ic/oc）和正文的脚本单元 |
| 接口四类 | `io` 图形输入、`oo` 图形输出、`ic` 控制输入、`oc` 控制输出 |

| `IDynamicOutputProvider` | 框架接口，编译前调用 `RebuildDynamicOutputs()` |
| `PortsVersion` | 端口重建计数器，UI 用它自动重取新端口对象 |
| `dev_*` | HALCON 的显示算子族（本插件把它们回调到 C#） |
| `publish_preview` | 插件自定义外部过程，送图到主界面窗口 |
| `LegacyDisplayShim` | 编译前把老式窗口算子改写成 `dev_*` 的垫片 |
| 指纹缓存 | SHA256(脚本内容) → 已编译过程调用，内容不变零成本复用 |
| xshd | AvalonEdit 的语法高亮定义格式 |
| `.hdvp` | HALCON 外部过程文件格式（本插件用它扩展算子） |
