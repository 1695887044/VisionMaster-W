# 第 0 章 这是什么

**模板匹配 = 让计算机"记住"一个物体的样子，然后在一张新图片里把它找出来，并告诉你它在哪里、转了多少度、有多大把握。**

生活化的例子：

> 你给机器人看一张螺丝刀的照片（这就是"模板"），然后随便递给它一张桌面照片，它能在照片里把那把螺丝刀圈出来，告诉你："找到了，中心在 (512.3, 340.7)，转了 23.5°，把握 92%"。就算螺丝刀被旋转过、甚至稍微缩小放大了一点，它也能找到。

这在工业视觉里叫**定位**，是几乎所有视觉方案的第一步 —— 先找到产品在哪，后续的测量、缺陷检查、机器人抓取才有坐标可用。

它在流程里的位置：

```
[图像采集] → [图像预处理] → [模板匹配] → [Blob 检测] / [卡尺测量] / [码读取] → [数据记录/上报]
                            ↓
        输出位姿 Row / Column / Angle（亚像素）
        输出 AlignedImage（目标已摆回标准位姿的图）
```

界面里它归在 **「定位」** 分组。

# 第 1 章 设计思想

## 1.1 核心原理：比"形状"，不是比"像素"

很多人以为"模板匹配"就是把一张图存下来、后面逐像素对比。**本插件用的不是这种笨办法**，而是业界标准的**形状匹配（Shape-Based Matching）**。

| | 逐像素比对（老办法） | 形状匹配（本插件） |
|---|---|---|
| 存什么 | 原图的一堆像素 | 从框内提取的**边缘特征**：哪里有明暗边界、边界朝哪个方向 |
| 怎么比 | 逐点相减求差 | 找**同样的边缘特征组合** |
| 光照变亮 | 全部像素变了 → 失败 | 边缘位置大体不变 → **照样找到** |
| 目标旋转 | 失败 | 找旋转过的特征变体 → **找到** |
| 速度 | 慢 | 快（且有金字塔加速） |

一句话记忆：**它把照片描成"线稿"，两张照片只要线稿能对上，就认为找到了同一个东西。**

> 好处：光照稍微变亮变暗、对比度变化、目标稍微转个角度 —— 都不影响。前提是你框住的区域**特征足够独特**（这也是 3.3 节反复强调"要框纹理丰富处"的原因）。

## 1.2 预备知识：五个必须懂的概念

零基础先看这五条，看懂后面就不费劲了。

**① 像素与灰度**
图像就是一堆格子。彩色图每个格子存 3 个数（红绿蓝），灰度图每格只存 1 个数（0=全黑，255=全白）。本插件**内部一律转成灰度**再学习、再查找（因为形状特征本质是"明暗边界"），彩色信息它不用。要判颜色请用 5.2 节表格里的「区域颜色检查」「颜色序列检查」。

**② 梯度（边缘）**
相邻两个格子亮暗差得越狠，说明这里有条"边"。算法把所有"边"找出来，就是特征。`梯度阈值` 就是"多明显才算一条边"：调低（10）→ 特征多、模型啰嗦、噪声容易混进来；调高（60）→ 模型精炼抗干扰，但特征太少会不稳。**设 0 = 让算法自己定**（推荐先保持 0）。

**③ 极性（黑白方向）**
一条边是"左暗右亮"还是"左亮右暗"，这就是极性。勾「使用极性」= 必须黑白方向一致才算命中（更快更准）；光照可能反相的场合取消勾选（会慢一点）。

**④ 金字塔（层数）**
把图缩小 1/2、1/4、1/8……叠成一座"金字塔"。查找时先在最粗那层粗找（快），再逐层放大细找（准）。`金字塔层数` 就是层数：模板很小（几十像素）用 6~8 层；模板巨大用 3~4 层。**层数越多越快，但太粗会漏掉小目标。**

**⑤ 亚像素**
真实位置在两个像素之间（比如 150.3），算法能给出小数而不是整数。配合"像素当量"可以换算成物理精度：

> 像素当量 = 视野宽度 ÷ 图像宽度。例：视野 100mm、图像 2448 像素 → 1 像素 ≈ 0.04mm。
> **要求 ±0.05mm 精度 → 像素当量必须 ≤ 0.02mm**（亚像素精度 ÷ 像素当量 = 物理精度）。

## 1.3 两阶段：学习（create）与查找（find）

这是整个插件最核心的心智模型，**只有两步**：

### 第一步：学习（`CreateTemplate`，界面按钮「创建模板」）

1. 你在图上框一块区域（矩形/圆形/椭圆）——"这就是我要找的东西"；
2. 图像只保留框内部分（在 HALCON 里叫**缩减域** `reduce_domain`）；
3. 统一转成灰度；
4. 算梯度、按阈值筛出特征边、记下极性；
5. 建金字塔；
6. **预先算好各个旋转（和缩放）变体** —— 这是"创建态参数"必须参与学习的原因：模型里存的是"这些角度下的样子"，角度范围填 180° 就意味着模型大、搜索慢；
7. **原点锚定**（见 2.5 节）：让以后输出的坐标 = 你画框的中心；
8. 模型序列化成 base64 存进方案文件（随方案走，换电脑不丢）。

### 第二步：查找（`RunAlgorithm`，流程每跑一帧执行一次）

1. 取上游来的图，转灰度；
2. 选模板（按配方名，见 1.5 节）；
3. 在图上搜：先粗后细找"特征组合"，按分数从高到低排序；
4. 命中数量 ≥ 分数下限的，按 `MaxOverlap` 去重后输出；
5. 端口赋值：最高分那个给标量端口，全部实例给数组端口；
6. 可选：算一张"归一化图"；
7. 画标注图（绿轮廓 + 文字）发到主界面；
8. **一个都没找到 → 步骤判 Fail，但标注图照样输出**（原图 + 红字原因），产线能当场看到现场。

> **关键认知：改"学习阶段"的参数（角度/缩放/步长/梯度/极性/金字塔）必须重新点「创建模板」；改"查找阶段"的参数（分数下限/匹配数/重叠/激进度）改完立即生效。**
> 界面上用一个橙色徽标「参数已改·需重新学习」提醒你 —— 看到它就去点「创建模板」。

## 1.4 目标：位姿 + 归一化图

插件最终给你两样东西：

**① 位姿（位置 + 角度）** —— 下游抓取、测量、裁剪要用。

| 输出 | 含义 |
|---|---|
| `Row` / `Column` | 中心行 / 列，**亚像素**（小数） |
| `Angle` | 角度，**单位是度** |
| `Score` | 分数 0~1，越接近 1 越像 |
| `MatchCount` | 命中几个 |
| `Rows`/`Columns`/`Angles`/`Scores`/`Scales` | 全部实例的数组，**按分数从高到低，逐项对齐**（`Rows[i]` 与 `Columns[i]` 指同一个命中） |

**② 位姿归一化图（`AlignedImage`，可选，默认开启）**

把目标"掰"回**学习时的标准位置和 0°** 再输出。这样下游那些"按固定坐标配置"的工具（画框裁剪、Blob、卡尺、码读取…）**一个都不用改**就能直接用 —— 产品哪怕歪着来、位置飘了也不怕。

> 这就是 `AlignedImage` 存在的全部意义：**把"产品在哪"这个问题，压缩成"产品永远在原点"**。
> 副作用：图像尺寸不变（画幅不变），目标摆回原位后原画面边缘会露黑边，这是正常的（见 3.8 节 Q5）。

## 1.5 架构思路：积木式流水线

**① 插件化**
插件遵循平台统一的插件规范，可以从工具箱拖到**流程画布**上，和其他步骤串成一条自动线。插件本身是一个独立 DLL（`Plugin.Matching.dll`）。

**② 端口（Port）= 插头**
左边是输入（"上游图像""配方名"），右边是输出（"分数/位置/角度/标注图"）。编译器在**编译期**就按名字和类型接线，连错类型会直接报错。用线连、或用变量连都行。

**③ 配置态 vs 运行态分离（很重要）**
你在配置界面里"教"它模板（学习），保存进方案；运行时它只负责"找"，不弹界面、不能点。
插件内部用 `_isConfigInstance` 标记区分"给人看的实例"和"跑的实例"。**不隔离的后果**：流程每次编译都会读一次参考图、反序列化一次模型、开一次离屏渲染窗口 —— 白白变慢（这是历史上真实修过的一个缺陷，见 4.3 节 P2-③）。

**④ 模板库 + 配方驱动（一个实例 = 一个模板库）**
一条产品一个"配方"（模板条目）。换产品时给一个"配方名"，它自动换对应模板去匹配。**最多 20 条**（方案文件体积保护）。

**⑤ 界面零业务逻辑**
`MatchingView.xaml.cs` 只有 35 行，全是"按钮点击 → 转发给插件"的转发行；画布能力全部来自 `Core.Halcon` 的 `ImageEdit` 控件；画布与参数的双向同步全部在 `MatchingPlugin.cs` 里。这样界面好改、逻辑好测。

# 第 2 章 技术特点

## 2.1 算法

底层是 **HALCON 的形状匹配**（Shape-Based Matching），核心算子两个：

| 算子 | 用途 | 本插件何时用 |
|---|---|---|
| `create_shape_model` | 学习模板（目标大小不变，只位置/角度变） | `ScaleEnabled = false`（默认） |
| `create_scaled_shape_model` | 学习模板（目标远近会变，模型带缩放变体） | 勾了「启用缩放匹配」 |
| `find_shape_model` | 在新图里找 | 每帧执行（不缩放） |
| `find_scaled_shape_model` | 在新图里找（带缩放） | 每帧执行（缩放） |

> 完整 HALCON 算子清单见 [5.2 附录](#52-附录-bhalcon-算子速查)。

**几个必须知道的算法特性：**

- **查找角度范围必须 ⊆ 学习时的角度范围**。模型里没生成过的角度变体，找也找不到。所以学习时角度范围填得越宽，模型越大、搜索越慢 —— 产线偏转小就填 ±15°，别偷懒填 ±180°。
- **查找结果天然按分数从高到低排序**，所以"最高分那个"就是第 0 个。
- **亚像素模式固定用 `least_squares`**（最小二乘拟合）。
- **特征多不等于好**：一个区域里有 4 条特征边，匹配错 1 条分数就掉到 75%；有 40 条边，错 1 条还剩 97.5%。**所以宁可框大一点、特征多一点，但要保证独特。**

## 2.2 数据结构

### 一个模板条目长什么样（`MatchingTemplateEntry`）

数据分四组，这是理解整个插件的关键：

**组一：身份与区域**

| 字段 | 类型 | 含义 | 默认 |
|---|---|---|---|
| `Name` | string | **配方键**，`RecipeName` 端口按它选条目 | `"模板1"` |
| `Shape` | string | 区域形状：`Rectangle` / `Circle` / `Ellipse` | `Rectangle` |
| `Rect` | `double[5]` | 区域参数，**固定 5 个** | 空数组 |
| `Mask` | string | 涂抹排除域（PNG 的 base64，255=挖掉） | 空 |
| `RefImagePath` | string | 该条目自己的参考图路径（重学时载入） | 空 |
| `Model` | string | **模型载荷**（`write_shape_model` 的 base64）；空 = 未学习 | 空 |

`Rect` 的 5 参数约定（与「区域颜色检查」统一）：

| 形状 | [0] | [1] | [2] | [3] | [4] |
|---|---|---|---|---|---|
| 矩形 | 中心行 | 中心列 | 角度（**弧度**） | 半长 | 半宽 |
| 圆 | 中心行 | 中心列 | **半径** | 0（占位） | 0（占位） |
| 椭圆 | 中心行 | 中心列 | 角度 | 半径1 | 半径2 |

> **为什么统一成 5 个？** 存取只有一条路径。否则每处读代码都要 if-else，序列化、比较、克隆各写一份。代价是圆形区域取 index 3/4 会得到 0 —— 代码里所有读尺寸的地方都必须**按形状分支**（这也是一个历史缺陷的成因，见 4.1 节 P0）。

**组二：提取参数（创建态，改任一必须重学）**

| 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `NumLevels` | **5** | 1~10 | 金字塔层数 |
| `MinAngleDeg` | **-180** | -180~180 | 角度下限（度） |
| `MaxAngleDeg` | **180** | -180~180 | 角度上限（度） |
| `AngleStepDeg` | **0** | 0~30 | 角度步长；**0 = 自动** |
| `GradientThreshold` | **0** | 0~255 | 梯度阈值；**0 = 自动** |
| `UsePolarity` | **true** | — | 勾=使用极性（更快） |
| `ScaleEnabled` | **false** | — | 是否启用缩放（明显更慢，非必要不开） |
| `ScaleMin` | **0.8** | 0.5~2 | 缩放下限 |
| `ScaleMax` | **1.2** | 0.5~2 | 缩放上限 |

**组三：参数指纹 `LearnedSignature`**
学习成功时把"区域 + 全部提取参数 + 掩膜长度"拼成一个字符串存下来。以后你动了任何一项，比对不一致 → 徽标变橙「参数已改·需重新学习」。

```
"Rectangle|200.5,300.2,0,80,60|5|0|-180|180|0|True|False|0.8|1.2|1234"
   形状     区域(3位小数)      层 梯度 角范围 步长 极性 缩放 比例  掩膜长度
```

**组四：运行期句柄（不落盘，按条目懒加载）**
`RuntimeModelId`（HALCON 模型句柄）、`RuntimeModelSource`（这份额载从哪来的，用于缓存校验）、`RuntimeContours`（模型特征轮廓，画绿线用）。放在条目而不是插件里，是因为 20 个条目各存各的、懒加载互不干扰。

## 2.3 配置项与端口完整清单

### 配置项（`[StepConfig]`，随方案保存）

| 配置项 | 类型 | 默认 | 有效范围 | 说明 |
|---|---|---|---|---|
| `TemplateLibraryJson` | string | `"[]"` | — | **整个模板库**（JSON 数组字符串） |
| `DefaultTemplateName` | string | 空 | 必须是库中某个 Name | 默认模板名 |
| `MinScore` | double | **0.5** | 0.01 ~ 1 | 分数下限，低于不算命中 |
| `MaxMatches` | int | **1** | 1 ~ 100 | 最多输出几个实例（1=单目标） |
| `MaxOverlap` | double | **0.3** | 0 ~ 1 | 两个命中的最大重叠比例（去重） |
| `Greediness` | double | **0.8** | 0.1 ~ 0.9 | 搜索激进度：越大越快越易漏 |
| `DisplayViewIndex` | int | **1** | 0 = 不发布；界面选 1~9 | 标注图发布到主界面几号窗口 |
| `OutputAlignedImage` | bool | **true** | — | 是否输出位姿归一化图 |

> 模板库为什么用 string 存而不是对象数组？因为字符串经框架的 `InputValues` 往返最稳，不受序列化器类型推断影响。

### 输入端口（2 个）

| 端口 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `Image` | `HImage` | 实际必填 | 待定位图像。源码标注 `IsRequired=false`，但**运行时不给图会直接 Fail** |
| `RecipeName` | string | 可选 | 配方名/产品型号。可连上游变量或上位机；留空/纯空格 = "没给" |

### 输出端口（13 个）

| 端口 | 类型 | 说明 |
|---|---|---|
| `Score` | double | 最高分实例的分数 0~1 |
| `Row` | double | 最高分实例中心行（亚像素） |
| `Column` | double | 最高分实例中心列（亚像素） |
| `Angle` | double | 最高分实例角度（**度**） |
| `MatchCount` | int | 命中实例数（去重后） |
| `MatchedTemplate` | string | 本帧实际用的模板名（**追溯用**） |
| `Rows` | HTuple | 全部实例行数组 |
| `Columns` | HTuple | 全部实例列数组 |
| `Angles` | HTuple | 全部实例角度数组（度） |
| `Scores` | HTuple | 全部实例分数数组 |
| `Scales` | HTuple | 全部实例缩放倍率（未启用缩放时恒为 1，**保证五个数组对齐**） |
| `MeasureImage` | HImage | 标注图（绿轮廓 + 判定文字）；**没找到也有**（原图+红字） |
| `AlignedImage` | HImage | 位姿归一化图；`OutputAlignedImage=false` 时不输出 |

> **约定：标量端口 = 最高分实例；数组端口逐项对齐**（`Rows[i]`/`Columns[i]`/`Angles[i]`/`Scores[i]`/`Scales[i]` 指同一个命中）。
> 每轮开始时非图像端口会被**全部归零**（避免下游读到上一帧的"幽灵结果"导致不良品放行）；`HImage` 端口由基类统一回收。

### 配方选择优先级（三级）

```
① RecipeName 端口有值 → 按名字精确匹配库里的条目
   └─ 找不到 → Fail，并列出库里现有的名字（方便照着改）
② 没给名字 → 用「设为默认」的那条
③ 默认也没有 → 用库里第一条
```

## 2.4 性能优化手段

按"性价比"从高到低排：

| 手段 | 怎么做 | 收益 |
|---|---|---|
| **限制搜索区域** | 用「ROI」插件的 `Domain_` 输出接匹配 `Image` | ⭐⭐⭐ 最有效：域外直接不搜，还避免相似背景误匹配 |
| **收窄角度范围** | 学习时把 ±180° 改成实际的 ±15° | ⭐⭐⭐ 模型小一大截，搜索快数倍 |
| **不启用缩放** | 目标远近不变就别勾 | ⭐⭐⭐ 缩放模型明显更大更慢 |
| **提高激进度** | `Greediness` 0.8 → 0.9 | ⭐⭐ 快，但偶尔漏 |
| **金字塔层数** | 小模板 6~8 层，巨模板 3~4 层 | ⭐⭐ 快，但太粗会漏小目标 |
| **多目标时关掉归一化图** | 取消 `OutputAlignedImage` | ⭐ 省一次图像仿射变换 |

> **反过来，什么最伤性能**：角度范围 ±180° + 启用缩放 + 金字塔层数很低 + 大图高分辨率 —— 这四个一起上，帧时间会很难看。

## 2.5 独特实现（工程上的关键设计）

这一节是本插件技术上真正值得学的地方，每一条都是踩过坑换来的。

### ① 原点锚定：让输出坐标 = 你画的框中心

**问题**：HALCON 默认把模型原点放在**模型内部参考点**，不是用户画的区域中心。实测**差 1~2 像素**（圆形区域 +1.5,+1.5）。

**解法**：学习完立刻在参考图上**自匹配一次**（自己找自己，必然满分），量出"默认落点"与"画布中心"的差，用 `set_shape_model_origin` 补偿。补偿量**随模型一起序列化**，运行期自动一致。

**关键细节（容易改错）**：
```
found_after = found_default − offset
所以：补偿量 = 默认落点 − 画布中心
```
**这个方向与直觉相反**（直觉会写成减法），代码里专门注释了"别'修'回减法"。

### ② 涂抹排除：让反光面/变化区不参与学习

反光面、每次会变的图案，会把模型学歪。插件提供"**涂抹编辑**"：

- 「绘制涂抹」涂掉的区域 **∩ 模板区域**，从模型域里**差集掉**；
- 「擦除涂抹」找回涂多的；
- 画布上**橙色 = 排除域，红色 = 擦除笔画**；
- 掩膜随方案落盘，重开配置界面会恢复成橙色、可以继续编辑。

**持久化的一个绕路**：掩膜走"**排除域 → 掩膜图 PNG → base64**"，而不是 HALCON 的区域序列化。原因是**本机 HALCON 的 .NET 包装缺 `write_serialized_item` 入口**。PNG 方案无损、版本稳；还原时一行阈值运算就回来了。

**一个曾经踩过的一致性坑**：早先"学习时存的是与框求交后的掩膜"，而"换条目时写回的是原始掩膜"，两者 base64 长度不同，而指纹里含掩膜长度 → **什么都没改也天天提示"需重新学习"**。修法是全系统统一存**原始涂抹域**。教训：**同一个数据只能有一个存储口径**。

### ③ 离屏渲染的三个防坑（写标注图 / 模板预览共用）

1. **窗口必须缓存复用**：反复 `open_window`/`close_window` 会触发 HALCON **#9302 死锁**。所以尺寸不变就复用，变了才关旧开新，`Dispose` 统一关。渲染全程加锁（HALCON 窗口操作非线程安全）。
2. **必须显式 `set_part` 钉住显示范围**：不设的话 part 会被撑到参考图全幅，**底图缩在左上角一小块、其余全黑**。
3. **`dump_window_image` 回读后源对象立刻释放**：`new HImage(shot)` 拿到独立句柄后马上 `Dispose` 原件（引用计数语义）。**教训来源：卡尺插件实测不释放 500 次约漏 160MB。**

### ④ 失败也要出标注图

找不到目标 → 步骤 **Fail**（下游拿不到位姿确实没法继续），但**照样输出 `MeasureImage`**（原图 + 红字写明原因）并发布到主界面。

**理由：产线要能当场看到现场。** 黑屏等于让人跑到机台前瞎猜。

### ⑤ 角度单位：一律对外"度"，对内才转弧度

- 端口 `Angle`/`Angles` **永远是度**；
- 喂给 HALCON 前再转弧度；
- 度↔弧度的换算**抽成 public 静态方法**，好让自动化测试能直接断言它。

> **为什么这么较劲**：历史上出过"弧度当度又乘一次 π/180"的双重转换 —— **端口数值全对，只有画出来的轮廓不转**。44 条断言全绿，因为它"只有画出来才看得见"。抽成 public 之后，测试能直接用一根已知 30° 的轮廓去断言。

### ⑥ 编译链路：派生状态初始化不能只挂在 `Initialize`

宿主构造运行实例走的是 `ApplyConfigValues(model)`，**不调 `Initialize`**。所以模板库的解析/迁移/选条目必须放在**两条路都会经过**的方法里。

> **教训**：插件的派生状态初始化如果只挂在 `Initialize` 上，会出现"配置界面明明学会了，流程运行却报'尚未创建模板'"。详见 4.3 节。

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：插件是源码内工程，正常编译解决方案即可产出 `Modules/Plugin.Matching.dll`。
2. 依赖 HALCON 原生库（随软件一起分发）。
3. 首次使用前**把宿主的 VisionMaster 进程关掉**再重新生成 —— 运行中的程序锁着 `UI.dll` 和插件 DLL。
4. 重开软件，工具箱里会出现「模板匹配」（**定位** 分组）。若没出现，说明宿主载的是旧 DLL，按"关程序 → 构建 → 启动"刷新。

## 3.2 配置界面总览

界面是**左参数、右画布**两栏。左栏从上到下四张卡片：

| 卡片 | 内容 | 改动后果 |
|---|---|---|
| **① 模板** | 状态徽标 / 模板库列表（新增·删除·设为默认）/ 配方名 / 上游图像绑定 / 参考图路径 / 当前模板区域 / **创建模板**·清除 / 模板预览 / 涂抹编辑（折叠） | 框、涂抹改完要**重新创建模板** |
| **② 提取参数** | 最小·最大角度、角度步长、梯度阈值、使用极性、启用缩放 + 最小·最大比例、金字塔层数 | **改任何一项 → 必须重新创建模板**（徽标转橙提醒） |
| **③ 匹配参数** | 分数下限、匹配数上限、最大重叠、搜索激进度 | **改完立即生效**，不用重建 |
| **④ 输出** | 配方名端口、运行显示窗口、输出归一化图开关 | 立即生效 |

最下方还有「怎么用」提示卡。左上角**状态徽标三态**：

| 徽标 | 含义 | 该做什么 |
|---|---|---|
| 灰「未创建」 | 还没学 | 框区域 → 点「创建模板」 |
| 绿「已学习」 | 模型可用 | 正常运行 |
| 橙「参数已改·需重新学习」 | 你改了②区参数或框/涂抹 | **重新点「创建模板」** |

右侧画布：**右键 → 新建矩形 / 圆形 / 椭圆**框选模板；涂抹模式下可画/擦；下方信息栏（绿=正常、橙=提示、红=错误）。

## 3.3 第一次学模板（7 步）

> 总思路：**先接图 → 把一张"标准样品"的图弄进来 → 框住特征 → 学习 → 以后自动找。**

**第 1 步｜搭流程**
放一个「图像采集」和一个「模板匹配」，把前者的图像输出连到后者的 `Image` 端口。

**第 2 步｜打开配置，把图弄进来**
双击步骤打开配置窗口。两种方式：
- **推荐**：在流程里**试运行一次**，上游图会自动显示在右侧画布（订阅了 `Image` 端口的变化，图到即显示）；
- 没连线时：在「参考图」框填一张本地图片路径，点「载入」。

**第 3 步｜框选模板区域（最关键的一步）**
在右侧图上**右键 → 新建矩形**，框住产品上**稳定、独特、会跟着产品一起动**的特征。

> **画框要领**（决定成败）：
> - ✅ 框**纹理丰富**的地方：丝印字符、边角组合、安装孔位、螺栓阵列
> - ❌ 别框**大平面**（没特征，模型等于白学）
> - ❌ 别框**反光面**（每批亮度都变）
> - ❌ 别框**会变的区域**（活动件、遮挡物）
> - 宁可**框大一点**（特征多更稳），只要保证独特
>
> 拿不准就先框一块试，看左下角**模板预览里绿线多不多** —— 绿线稀少就是特征太少，换地方。

**第 4 步｜（可选）涂抹**
如果框里有反光面或会变的地方：展开「涂抹编辑」→ 模式选「绘制涂抹」→ 在画布上涂橙（不想学的区域）→ 涂错选「擦除涂抹」找回 → 彻底重来点「清除涂抹」。

**第 5 步｜调提取参数（一般默认就行）**
默认是：角度 -180°~180°、步长自动、梯度阈值自动、使用极性、不缩放、5 层金字塔。
**产线偏转小就改成 ±15°** —— 模型小、搜索快。目标远近会变才勾缩放。

**第 6 步｜点「创建模板」**
信息栏变绿，显示：
```
模板「模板1」已学习：金字塔 5 层，角度 -180~180°，特征区域 160×160 px，载荷 55 KB。左下角为模板预览
```
左下角同时出现**带绿色特征轮廓的模板预览**（绿色 = 模型记住的特征边）。

**第 7 步｜保存**
点「确定」关闭配置，模板库序列化进方案文件。

**学完做个压力测试再上线**：目标故意转 ±最大角度、平移到视野四角、光线调暗 20%，每次都能找到才算学好了。

## 3.4 多产品配方（4 步）

1. **新增**：模板库区点「新增」→ 出现「模板2」（重名会自动规避，上限 20 条）
2. **各自学**：每条各自改名字（如"型号A"/"型号B"）→ 载各自参考图 → 框区域 → 点「创建模板」
3. **设默认**：把最常用那条选中，点「设为默认」
4. **接配方名**：把上位机或变量连到 `RecipeName` 端口；`MatchedTemplate` 输出可接回数据记录，**追溯每帧实际用了哪条模板**

> 换产品时不用改配置 —— 运行期给个配方名就自动切过去了。
> 提示：大批量多产品场景建议**拆成多个流程**，避免单方案文件过大。

## 3.5 旋转与缩放配置

**目标会转：**
在②区填实际角度区间。产线偏转小就填 `-30 ~ 30` —— **范围越小搜索越快**，不必每次都 ±180。

**目标远近/大小会变：**
勾「启用缩放匹配」，填实际倍率区间（如 `0.9 ~ 1.1`）。
**不需要就别勾** —— 缩放模型明显更大、搜索更慢。

> 用了缩放就有"缩放范围退化为零"的风险（上下限填成一样时 HALCON 会拒绝创建），插件会自动撑开一个最小窗口兜住（见 4.2 节 P3）。

## 3.6 下游怎么用位姿

**方法 A：直接用坐标（灵活）**
`Row` / `Column` / `Angle`（都是 double）连给「数学计算」「轴运动」「变量赋值」—— 算偏心量、算下一工位位姿、驱动运动卡补偿。

**方法 B：用归一化图（推荐，最省事）**
保持「输出位姿归一化图像」开启（默认开），`AlignedImage` 连给：

| 下游插件 | 接哪个输入端口 |
|---|---|
| Blob 缺陷检测 | `SrcImage` |
| 卡尺测量 | `SrcImage` |
| 码读取 | `Image` |
| OCR 文本识别 | `Image` |
| 区域颜色检查 / 颜色序列检查 | `Image` |
| YOLO 目标检测 | `Image` |
| ROI（裁剪） | `SrcImage` |

这些插件全按固定坐标配置，目标永远回到学习位姿 —— **一个都不用改**。

> **多目标场景**：用数组端口 `Rows`/`Columns`/`Angles`（HTuple），与卡尺、Blob 的 HTuple 输出**逐项对齐**，可以做"第 N 个命中 → 第 N 把卡尺"的配对测量。

## 3.7 参数调节速查表

**匹配参数（③区，随时改，不用重学）**

| 症状 | 调哪个 | 往哪调 |
|---|---|---|
| 找不到目标（分数不够） | `MinScore` 分数下限 | ↓ 调低到 **0.3~0.5**（太低易误匹配） |
| 同一个目标报了好几个 | `MaxOverlap` 重叠上限 | ↓ 调低到 **0.1~0.3** |
| 图里很多个目标只报一个 | `MaxMatches` 匹配数 | ↑ 调大 |
| 匹配太慢 | `Greediness` 激进度 | ↑ 0.8→0.9；或收窄角度范围 |
| 偶尔漏掉该找到的 | `Greediness` | ↓ 0.8→0.6~0.7 |

**提取参数（②区，改了必须重新创建模板）**

| 想要 | 调哪个 |
|---|---|
| 光照变化大、对比度不稳 | `GradientThreshold` 保持 **0**（自动），或按实际梯度手填 |
| 目标黑白可能反转（正反面） | 取消 `UsePolarity`（会慢一点） |
| 模板小、搜索慢 | `NumLevels` ↑（小模板层数多了快） |
| 模板巨大且要精度 | `NumLevels` ↓ |
| 角度精度不够 | `AngleStepDeg` ↓（越小越精，学习越慢），或保持 0 让它自动 |

**学习质量自查**

| 现象 | 原因与对策 |
|---|---|
| 预览里绿轮廓很少/几乎没线 | 区域特征太少 → 换纹理丰富部位，或降低梯度阈值 |
| 匹配位置系统性偏 1~2px | 正常已被原点锚定消除；仍偏就重学一次 |
| 每次打开都提示"需重新学习" | 检查是否动过②区参数；或掩膜口径问题（已修，见 4.1 节 P2-④） |

## 3.8 FAQ

**Q1** 报「未知产品：XXX 没有对应模板（库里有：模板1，模板2）」怎么办？
配方名与模板名没对上，**必须逐字符一致**（大小写、空格都算）。用 `MatchedTemplate` 输出确认实际选中的是哪条。

**Q2** 配置里明明已学习，运行却报"尚未创建模板"？
历史缺陷（解析只挂在 `Initialize`，运行实例不走它），**当前版本已修**。若仍出现，确认点过「确定」保存、方案文件真的存盘了。

**Q3** 改了参数没重学会怎样？
徽标变橙「参数已改·需重新学习」，**运行仍用旧模型**（因为那些是"创建态"参数）。

**Q4** 匹配分数高但标注图上轮廓画歪/不跟着转？
历史上出过"角度双重转换"事故（**端口数值是对的，只有画出来是错的**），已修。若数值也偏，检查模板区域是不是框进了会动的部分。

**Q5** `AlignedImage` 边缘有黑边？
**正常现象**。归一化用"输出与输入同幅面"模式（画幅不变），目标转回标准位姿后原画面边缘部分出界，出界填黑。下游检测区域避开画幅边缘即可。

**Q6** 换电脑模板还在吗？
**在**。模型以 base64 存方案 JSON。但**参考图路径是本机路径**，只影响"重开配置时的画布显示/重学"，**不影响运行匹配**。

**Q7** 能放多少模板？
**上限 20 条**（方案文件体积防护），满了会有明确提示。多产品大批量建议拆流程。

**Q8** 图像是彩色的，要用彩色特征吗？
形状匹配本质用**灰度梯度**，学习/运行都统一转灰（含 4 通道 RGBA/BGRA），黑白特征才稳定。要颜色信息请用「区域颜色检查」「颜色序列检查」。

**Q9** 失败时下游拿不到结果？
步骤 Fail，下游按流程失败策略（停止/跳过）。但 **`MeasureImage` 仍然有值**（原图 + 红字原因），可以在记录环节存下来。

**Q10** 为什么流程每次编译都很慢？
历史缺陷：配置态没隔离，编译一次就读图/建模/开离屏窗口。当前版本用 `_isConfigInstance` 隔离，编译期只灌参数。

## 3.9 打光与现场排障

**打光三条原则**
1. **稳而不亮** —— 亮度稳定比亮度高重要得多（曝光固定住，别让自动增益漂）；
2. **漫射光** —— 避免点光源造成高光和阴影；
3. **看直方图** —— 理想是**双峰**（暗背景 + 亮目标，中间分得开）。单峰或糊在一起 = 光没打好。

**学习时**
- 尽量在**和产品实际来料一致**的光照下学；

## 4.2 P0：学习成功，却报"创建模板失败"

**现象**
状态栏显示：`创建模板失败：索引超出了数组界限（区域里特征太少？换一块纹理更丰富的区域试试）`
同时**徽标不刷新、模板预览不出现**。
→ **每次学习都成功，但界面每次都说失败**，用户会以为没学好而反复点。

**原因（后果链）**
1. 模型**已经学好**（`entry.Model` 已写入 base64）；
2. 拼成功文案时取了一个**迁移字段** `TemplateRect[3]`：
   ```csharp
   + $"特征区域 {TemplateRect[3] * 2:0}×{TemplateRect[4] * 2:0} px，"
   ```
3. `TemplateRect` 是"单模板时代"的遗留字段，迁移后**立刻被清空** → 当前主流路径（模板库）下它**恒为空数组** → 必然越界；
4. 抛出的 `IndexOutOfRangeException` 被 `CreateTemplate` 外层过宽的 `catch` 吞掉，伪装成"创建模板失败"；
5. 跳过了后面的 `TouchModelStaleness()` 与 `UpdateTemplatePreview()` → 徽标不刷新、预览不出现。

**为什么 44 条冒烟断言全绿？**
- 「学习成功且载荷随方案序列化」断言的是 `Model.Length > 1000`（载荷在，必然绿）；
- 「学习后参数未变不提示重学」断言 `IsModelStale`（被动计算属性，不依赖被跳过的通知）；
- **没有任何一条断言看状态栏文字。**

**修法**
改用**当前画布区域** `CanvasRect`，并**按形状给尺寸**（圆只有 3 个参数，取 index 3/4 会显示 0×0）：

```csharp
string sizeNote = CanvasShape == RoiShapeNames.Circle
    ? $"半径 {CanvasRect[2]:0} px"
    : $"{CanvasRect[3] * 2:0}×{CanvasRect[4] * 2:0} px";
```

**回归断言**
- `【回归·P0】学习成功后状态栏不是失败` → 判据 `StatusLevel != StatusLevel.Error`
- `【回归·P0】成功文案给出特征区域尺寸（不是 0×0、也不是空）`

**教训**：**过宽的 `catch` 会把真错误伪装成假错误**；迁移字段用完必须清空；测试要断言**用户能看到的那个字符串**。

## 4.3 P1：标注图轮廓角度双重转换

**现象**
`find_shape_model` 输出的 `Angle` 是**弧度**，内部又当成"度"再转一次弧度。
量化：`0.5 rad（≈28.6°）` 被转成 `0.0087 rad` → **轮廓几乎不旋转**。

> 关键：**端口 `Angle`/`Angles`（度）是对的，只有画出来是错的**。所以「整图转 10° 后仍命中」这类断言依然绿。

**原因**
```csharp
RenderResultAnnotation(src, entry, rows, cols, angles);   // 传的是弧度
...
angles[i].D * Math.PI / 180.0,                            // 内部又当"度"转弧度
```

**修法**
统一"度"口径，并把轮廓放置**抽成 public 静态方法**：

```csharp
/// 【角度单位一律是度】—— 与 Row/Column/Angle 端口、Angles 数组端口同一口径，
/// 内部再统一转成弧度喂给 vector_angle_to_rigid。
/// 为什么不写成 private：早期这里拿 find 输出的【弧度】又乘了一次 π/180（双重转换），
/// 结果标注图上的轮廓几乎不跟着目标转，而端口数值完全正确 —— 冒烟里 44 条断言全都看不见它。
/// 抽成 public 静态以后，冒烟可以直接用一根已知角度的 XLD 断言『度→弧度』这条换算。
public static HObject? PlaceContoursAtPoses(HObject contours, HTuple rows, HTuple cols, HTuple anglesDeg)
```

调用处改传度：`RenderResultAnnotation(src, entry, rows, cols, angles * 180.0 / Math.PI);`

**回归断言**
- `【回归·P1】轮廓放置按【度】换算：给 0° 就是 0°` → 实测 `Phi=0°`
- `【回归·P1】轮廓放置按【度】换算：给 30° 就转 30°（早先被双重转成 ≈0.5°）` → 实测 `Phi=30°`

**测试手法**：用一根已知 30° 的细长矩形轮廓（`gen_rectangle2_contour_xld`）直接测换算：给 30° 就必须真转 30°。

**教训**：**"只有画出来才看得见"的错误，测试够不着**。必须给它造一个可测入口。

## 4.4 P2/P3 其余七条

### P2-① 删除条目泄漏模型句柄

**现象**：`DeleteSelectedEntry` 只做 `Library.Remove(entry)`。条目从库里摘掉后，`Dispose` 遍历 `Library` 再也够不着它 → HALCON shape model 句柄 + 轮廓对象**永久泄漏**（模型占几百 KB~几 MB）。

**修法**：摘除前先释放。
```csharp
Library.Remove(removed);
// 必须先释放模型句柄：条目已从 Library 摘掉，Dispose 遍历 Library 再也够不着它，
// 不在这里释放就是永久泄漏
ReleaseEntryModel(removed);
```
**回归**：`【回归·P2】删除条目时释放了模型句柄` → 判据 `doomed.RuntimeModelId == null && doomed.RuntimeContours == null`

### P2-② `Dispose` 未释放参考图

**现象**：`DisplayImage` 的 setter 是普通 `SetProperty`（不释放旧值），各换图路径靠手动 `Dispose`。但**"最后一次那张"没人管**。

**修法**：`Dispose` 里补 `DisplayImage?.Dispose(); DisplayImage = null;`

### P2-③ 运行实例做配置态工作（编译变慢）

**现象**：`ApplyConfigValues → EditingEntry = selected` 会触发"播种画布 + 渲染预览"（读参考图文件 → 反序列化模型 → 开离屏 buffer 窗口 → 写读临时 PNG 还原掩膜）。而 `ApplyConfigValues` **正是流程编译器构造运行实例时调用的那一个**。后果：**流程每次编译都白干一遍这些活**。

**修法**：加配置态标记，**盖在 `Initialize` 上**：
```csharp
public override void Initialize(IStepConfigData stepData)
{
    MarkAsConfigInstance();     // 先盖章，再 base.Initialize → ApplyConfigValues
    base.Initialize(stepData);
}
```
`OnImagePortChanged → ShowUpstreamImage` 同样加门禁（运行实例不需要把上游图搬进画布，那只是给操作员看的）。

> **判据与踩坑**：流程编译器构造运行实例时**只调 `ApplyConfigValues`、不经过 `Initialize`**。盖在 `Initialize` 上既隔离了运行实例，又保住"重开方案要恢复画布/预览/掩膜"。
> **第一版盖在 `GetConfigView` 上，结果误伤了 2 条「重开」断言**（它们用 `Initialize` 模拟重开）—— 所以回归段特意加了一条"编译实例 vs 重开实例"的对照组。

**回归**（3 条）：
- `【回归·P2】编译实例不持有显示用参考图` → `DisplayImage == null`
- `【回归·P2】编译实例仍然拿得到模板库（隔离不能把功能也隔掉）` → 库 ≥ 1 条
- `【回归·P2】对照：配置态走 Initialize 时预览照常恢复（隔离没矫枉过正）` → 库 ≥ 1 条且 `EditingEntry != null`

### P2-④ 掩膜口径不一致 → 凭空提示"需重新学习"

**现象**：学习时存的是"与模板区域**求交后**的掩膜"，换条目时 `WriteBackSmearToEntry` 写回的是"**原始**掩膜"。两者 base64 **长度不同**，而指纹含 `Mask.Length` → **什么都没改也提示需重新学习**。

**修法**：学习时统一存原始涂抹域。
```csharp
// 掩膜统一存『原始涂抹域』（不与模板区域求交）：与 WriteBackSmearToEntry 同口径。
// 早先这里存的是求交后的 exclusion，与换条目时写回的 raw domain 长度不同，
// 而 EntrySignature 含 Mask.Length —— 于是『什么都没改』也会提示需重新学习。
using (var rawSmear = BuildRawSmearRegion())
    entry.Mask = MaskRegionToBase64(rawSmear, refW.I, refH.I) ?? string.Empty;
```

**回归**：`【回归·P2】换条目再切回，不误报需重新学习`（动作：加模板2 → 切到模板2 → 切回模板1 → 判据 `!IsModelStale`）

**教训**：**一个数据只能有一个存储口径**，否则指纹类机制会自己咬自己。

### P3-① 条目区域参数损坏，报错看不懂

**现象**：`AlignedImage` 用 `entry.Rect[0]/[1]`，条目被手工改坏（`Rect` 不是 5 个值）时越界，整轮匹配变成 `模板匹配失败：索引超出数组界限`。

**修法**：提前校验 + 给能照着修的中文提示。

```csharp
if (entry.Rect == null || entry.Rect.Length != 5)
{
    Fail($"模板「{entry.Name}」的区域参数损坏（应为 5 个值，实际 {entry.Rect?.Length ?? 0} 个）：请打开配置界面重新框选并学习");
    return;
}
```

### P3-② 缩放范围退化解

**现象**：`ScaleMin == ScaleMax` 时 **HALCON 会拒绝创建模型**（范围退化），用户只看到一条看不懂的算子错误。

**修法**：调用前撑开一个最小窗口。
```csharp
// 退化解：上下限相等时 HALCON 会拒绝创建（缩放范围退化），
// 这里撑开一个最小窗口而不是让它变成一条看不懂的算子错误
if (scaleHi - scaleLo < 1e-6)
{
    scaleLo = Math.Max(0.5, scaleLo - 0.005);
    scaleHi = Math.Min(2.0, scaleHi + 0.005);
}
```

## 4.5 编译链路与生命周期类（UI 先行期补齐）

### 「已学习但运行报尚未创建模板」

**现象**：配置界面明明已学习（徽标绿），流程运行却报「尚未创建模板」。

**原因**：流程编译器灌参数走的是 `ApplyConfigValues(model)`，**不调 `Initialize`**（`Engine/FlowCompiler.cs`：`pluginBase.ApplyConfigValues(model)`）。而模板库的 JSON 解析/迁移/编辑条目选择原来放在 `Initialize` 重载里 → 编译出的运行实例 `Library` **永远是空的**。

**修法**：解析/迁移/选条目整体挪进 `ApplyConfigValues` 重载（base 灌完 `[StepConfig]` 后立即执行）—— 配置界面和编译器两条路都过这里。

**回归**：`【编译链路】只走 ApplyConfigValues 也能拿到模板库并定位` → `MatchCount=1`

> **教训（重要）**：**插件的派生状态初始化永远不要只挂在 `Initialize` 上**。宿主构造运行实例的统一入口是 `ApplyConfigValues`，两者必须等价。

### 首帧不铺满（HALCON 显示通用修复）

**现象**：标注图推到主界面视图窗口时，图片缩在角落，要手动右键"适应图片/窗口"才铺满。

**原因**（`HalconBase.HImageChangedCallBack`，所有 HALCON 显示控件共用）：
1. 新图尺寸变化时走 `SetPart(0,0,-2,-2)` —— **窗口级 part 会被 `HSmartWindowControlWPF` 的内部缩放状态顶掉**；
2. 图像先于控件 `Loaded` 到达时 hWindow 还没就绪，铺满被静默跳过 → 小图 + 黑边。

**修法**：铺满改走控件层 `hSmart.SetFullImagePart()`；**时序 = 先渲染 → 铺满 → 重绘**（在 `disp` 前调会得到一整帧黑屏）；窗口未就绪时置 `_pendingFitOnLoad`；同尺寸连帧不重铺满（不抢用户手动缩放状态）。

> **验证提醒**：`RenderTargetBitmap` 截 `HSmartWindowControlWPF` 的 D3D 合成面不可靠（会截出全黑）。**验证 HALCON 显示必须用 `dump_window_image` 取帧缓冲真值。**

### 涂抹笔画断成串（"一次画一个圆"）

**现象**：涂抹时拖动鼠标，笔画变成一串孤立的圆，不是连续一笔。

**原因**（两条，都在画笔层）：
1. `HSmartWindowControlWPF` 自带"拖拽平移"（`HMoveContent` 默认 true）—— 按住拖动时平移逻辑接管鼠标，笔画只能落下第一个圆；
2. 只在鼠标事件点盖一个圆 —— 事件稀疏时笔画自然断成串。

**修法**：
1. 进入涂抹模式自动 `HMoveContent = false`（退出还原）；
2. 从上一落点到当前点按"半径×0.6"步进**插值盖章**，单点去重。

**验证**：模拟稀疏拖动（落点间距 60/120px >> 笔刷直径 20）→ 笔画面积 3916px² ≈ 理论连续胶囊面积 3914。

> 该修复对**模板匹配与区域颜色检查共用的画笔层**同时生效。

### 预览相关的三个坑

1. `paint_xld` / `paint_region` 的 `Grayval` 语义对本 HALCON 版本不适用：颜色名报 **#1401**、逐通道灰度值**静默不上色** → 改走 buffer 离屏窗口 `disp + dump`。
2. 离屏窗口必须显式 `set_part`（否则裁剪图缩在左上角，其余全黑）。
3. `dump_window_image` 回读后源对象要立刻释放（引用计数语义）。

- 单帧超时保护

**架构层面的已知边界**
- **端口命名 `Image` vs 其它插件的 `SrcImage` 待统一** —— 但**不能改**：端口名写进了方案文件的连线，改名是**破坏性变更**（老方案连线会断）。要改必须统一规划。
- **失败口径不统一**：本插件「未找到目标 = Fail」；Blob 是「NG 不算 Fail」。两者各有理由（定位失败下游确实拿不到位姿），**建议写进平台契约**。
- **运行实例各自持有一份模型句柄**：20 条模板 × 多流程实例会重复加载同一份模型。需要优化应做**进程级模型缓存（带引用计数）**。
- `Region_{名}`(HRegion) 输出未做（需要显式区域对象的场景还拿不到）。

### A.2 典型接线（按流程顺序）

**① 图像准备（喂图）**
```
图像采集.OutputImage(HImage)
   └─▶ 图像预处理.SrcImage ── Image(HImage) ──┐
                                              ├──▶ 模板匹配.Image(HImage)
图像采集.OutputImage ─────────────────────────┘
```
预处理把灰度/去噪/增强收敛掉，**模板分数才稳定**。图源本身已标准时也可直连。

**② 限制搜索区域（降耗时、提分数）**
```
图像采集.OutputImage ─▶ ROI.SrcImage
                          ├─ MaskRegion(HRegion)  ──▶ BlobDetect.MaskRegion（限制检测区）
                          └─ Domain_<名>(HImage)  ──▶ 模板匹配.Image（限制搜索范围）
```

> **为什么 `Domain_` 是限制搜索范围的正解**（实测结论）：HALCON 在 domain 图上搜索时，**命中返回的仍是全局坐标**，domain 外的目标直接不命中。
> 实测四组对照（目标真实位置 300,300）：
>
> | 搜索图 | 结果 |
> |---|---|
> | ① 原图（无 domain） | 找到 **(300,300)** |
> | ② 带 domain(200~400)，目标在内 | 找到 **(300,300)** ← 坐标仍是**全局** |
> | ③ 带 domain(0~150)，目标在外 | **未找到** ← 只在 domain 内搜 |
> | ④ 裁剪图（201×200，原点被搬走） | 找到 **(100,100)** ← 局部坐标 |
>
> 结论：**domain 既限制搜索范围（提速 + 避免相似背景误匹配），又不改变坐标系**。
> 必须用裁剪图时，走 `OffsetRow_x`/`OffsetCol_x` 做 `global = local + offset`（`crop_domain` 只平移不旋转，所以两个标量就够，不需要完整矩阵）。

**③ 位姿消费（吃位姿）**
- **归一化图（最省事）**：`Matching.AlignedImage` → `BlobDetect.SrcImage` / `CaliperMeasure.SrcImage` / `CodeReader.Image` / `Ocr.Image` / `ColorCheck.Image` / `ColorRegion.Image` / `Yolo.Image` —— **下游固定坐标插件零改动**。
- **需要原始全局坐标**：`Matching.Row/Column/Angle` → `数学计算` / `轴运动.Target` / `变量赋值`。
- **多目标**：`Rows/Columns/Angles`（HTuple）与卡尺/Blob 的 HTuple 输出逐项对齐，做"第 N 个命中 → 第 N 把卡尺"。

**④ 判定与记录**
```
BlobDetect.IsOk / CaliperMeasure.IsOk / CodeReader.Count
   ├─▶ 逻辑运算 / 数值比较 ── Result(bool) ──▶ CSV记录 ──▶ Excel报表
   └─▶ 结果上报.上报触发
```
CSV 记录的列名是**动态输入端口**，把 `IsOk`/`Row`/`Text` 连上去即成列；`图片` 端口接 `Matching.MeasureImage` 存 NG 图。

**⑤ 运动闭环（可选）**
```
模板匹配.Row/Column ─▶ 数学计算 ─▶ 轴运动.Target
读轴状态.Position ───▶ 数值比较 ─▶ 轴卡 IO.Value（夹爪）
```
注意「轴运动」只下发命令不等到位，闭环必须补「等待到位」。

### 案例 1｜最小闭环：学一个模板 + 找到它

```hdevelop
* ---- 学习：框一块 120x120 的区域，存成模型 ----
read_image (Image, 'board-01.png')
gen_rectangle1 (Region, 200, 300, 320, 420)      * 行列各一对角点
reduce_domain (Image, Region, ImageTpl)          * 只保留框内（不复制像素）
create_shape_model (ImageTpl, 5, 0, rad(360), 'auto', 'auto',
                    'use_polarity', 'auto', 'auto', ShapeModelID)
* 参数依次：图像, 金字塔层数, 起始角, 角度跨度, 步长, 优化, 度量, 对比度, 最小对比度, 输出句柄

* ---- 查找：在另一张图里找 ----
read_image (Image2, 'board-02.png')
find_shape_model (Image2, ShapeModelID, 0, rad(360), 0.5,   * 最低分
                  1,                                            * 最多几个
                  0.3,                                          * 最大重叠
                  'least_squares', 5, 0.8,                      * 亚像素, 层数, 激进度
                  Row, Column, Angle, Score)
* 结果按分数从高到低：Row[0]/Column[0]/Angle[0]/Score[0] 就是最高分那个
```

**要点**：`angleStart=0, angleExtent=rad(360)` = 全角度 360°。若目标只转 ±15°，改成 `rad(-15), rad(30)` 更快。

### 案例 2｜让输出坐标 = 你画的框中心（原点锚定）

HALCON 默认原点不在框中心，**差 1~2 像素**。自己找自己来量偏差：

```hdevelop
* 学完模型后，在【同一张图】上自匹配一次（自己找自己，必然满分）
find_shape_model (ImageTpl, ShapeModelID, 0, rad(360), 0.8, 1, 0.5,
                  'least_squares', 5, 0.9, Row0, Column0, _, _)
* 找出"默认落点"与"我想要的原点(=框中心 200,300)"的差
set_shape_model_origin (ShapeModelID, Row0 - 200, Column0 - 300)
* 之后 find 的 Row/Column 输出就 = 框中心 (200,300)
```

> ⚠️ **方向别搞反**：`found_after = found_default − offset`，所以补偿量 = **默认落点 − 期望原点**。写成减法就反了。

### 案例 3｜排除反光面/变化区（涂抹）

```hdevelop

gen_rectangle1 (Bad2, 210, 310, 290, 390)
union2 (Bad1, Bad2, Bad)                       * 合并所有排除区

* → 转 base64 存进方案；还原时 threshold 一行就回来了
```

### 案例 5｜位姿归一化图（AlignedImage 的原理）

把目标从"当前位姿"搬回"学习时位姿"，下游固定坐标工具就零改动：

```hdevelop
* 命中位姿 → 模板位姿（区域中心、角度 0）
vector_angle_to_rigid (Row[0], Column[0], Angle[0],   200,   300,   0, HomMat2D)
*                        源：当前位姿                目标：标准位姿(度→弧度)

* 搬图：("false" = 输出与输入同幅面，"constant" = 出界填黑)
affine_trans_image (Image2, AlignedImage, HomMat2D, 'constant', 'false')
*            ⚠️ 顺序是 (图像, out, 矩阵, 插值, 自适应幅面) —— 写成 ('false','constant') 报 #3147
```

> **效果**：不管产品怎么歪、怎么飘，这张图里目标永远在 (200,300)、角度 0°。下游按固定坐标配好的 Blob/卡尺/码读取直接吃。

### 案例 6｜用 domain 限制搜索范围（提速 + 避免误匹配）

```hdevelop
* 1) 只在 ROI 内搜索（提速，同时避免 ROI 外的相似背景误匹配）
gen_rectangle1 (SearchArea, 100, 100, 500, 500)
reduce_domain (Image, SearchArea, ImageSearch)     * 幅面不变、坐标系不变！

* 2) 在 domain 图上匹配 —— 命中的 Row/Column 【仍是原图全局坐标】
find_shape_model (ImageSearch, ShapeModelID, 0, rad(360), 0.5, 1, 0.3,
                  'least_squares', 5, 0.8, Row, Column, Angle, Score)
* → Row/Column 就是全局坐标，下游插件零改动，也不需要回变换
```

**对比一下裁剪路线**（不推荐）：
```hdevelop
crop_domain (Image, SearchArea, CroppedImg)        * 原点被搬走
find_shape_model (CroppedImg, ...)                  * 得到的是局部坐标 (100,100)
* 要还原成全局：global = local + 小estRectangle1 的 (row1, col1)
```

| 路线 | 坐标系 | 下游要改吗 | 什么时候用 |
|---|---|---|---|
| `reduce_domain`（domain 图） | **全局** | **零改动** | ✅ 首选 |
| `crop_domain`（裁剪图） | 局部 | 自己加偏移量回变换 | 只在真要省内存/省传输时 |

### E.3 ROI 输出形态断言（`FlowCanvasChecks/CreateRoiChecks.cs`，跨插件端到端 6 条）

| 断言名 | 验证内容 |
|---|---|
| `【输出形态】Domain_{名} 存在且幅面与原图一致` | 没裁剪、坐标系没动 |
| `【输出形态】Domain_{名} 只有 ROI 内有像素` | domain 面积 = ROI 面积 |
| `【输出形态】OffsetRow/Col = 裁剪图左上角在原图中的位置` | (70,120) |
| `【核心】domain 图上做模板匹配 → 得到的就是全局坐标` | **跨插件端到端** |

## 5.6 附录 F：术语表

**图像基础**

| 术语 | 含义 |
|---|---|
| 像素 / 灰度 | 图像的格子；灰度图每格 0~255 |
| 通道 | 一张图有几个数/格。1=灰度、3=RGB、4=RGBA/BGRA |
| 幅面 | 图像的尺寸（宽×高） |
| Domain（域） | "哪些像素有效"。`reduce_domain` 只改域、不动像素、**不省内存** |
| 像素当量 | 视野宽度 ÷ 图像宽度，把像素换算成物理毫米 |
| 直方图 | 亮度分布图。双峰 = 暗背景 + 亮目标，光照合格 |

**特征与匹配**

| 术语 | 含义 |
|---|---|
| 梯度 / 边缘 | 相邻像素的亮暗差，表示"这里有条边" |
| 梯度阈值 | 多明显的边才算特征（0 = 自动） |
| 极性 | 边是"左暗右亮"还是"左亮右暗" |
| 金字塔 | 图像的层层缩小版本，用于"先粗后细"加速 |
| 亚像素 | 小数像素位置（如 150.3） |
| 位姿 | 位置（行/列）+ 角度 |
| 形状匹配 | 基于边缘特征的模式匹配（**本插件采用**） |
| 分数（Score） | 匹配相似度 0~1 |
| 激进度（Greediness） | 搜索时的"贪心程度"，越大越快越易漏 |
| 域限制搜索 | 在指定区域里搜（提速 + 避免相似背景误匹配） |
