## ⚠️ 最需要记住的三条

1. **letterbox 必须填 114 灰，不能用黑边**。黑边会让模型把边界当成强边缘，**贴边目标的框会系统性偏移**。
2. **坐标必须反算**：`原图坐标 = (letterbox坐标 − 补边) ÷ 缩放系数`，再夹进图像范围。框整体偏移时**先看试算里的 letterbox 缩放与补边**。
3. **只做目标检测**。分割 / 姿态 / OBB / 分类会被明确拒绝（`task` 守卫）——**按检测解读会得到错误结果却不报错**。

## 维护约定

1. **只改主文档**。`YOLO检测插件.md` 是唯一事实来源；归档件只作历史留档，不再更新。
2. ⚠️ **最优先待办：用真实 v8/v11 模型验证解码逻辑**。当前受控张量只能证明公式自洽，不能证明对 v8 语义的理解正确——拿到真实模型后必须补验（框是否落在目标上、类别是否对得上、数量是否合理）。
3. **会话生命周期不许改回"实例字段缓存"**——进程级共享 + 引用计数是硬要求（同模型 5 个流程会加载 5 份，GPU 时代会吃光显存）。
4. **`System.Numerics.Tensors` 必须随插件带**（不在 .NET 9 共享框架里，漏带 = 运行期 `FileNotFoundException`）。
5. **修 bug 必须同时补回归断言**（`FlowCanvasChecks/YoloChecks.cs`），并在主文档第 4 章记录「现象 → 原因 → 修法」。
6. **不做判定、不做结果投射**这条边界不要越界——判定交下游，结果通过端口（`Count`/`BoxesText`/`BestCrop`）输出。
7. **HALCON 相关新坑**统一追加到主文档 4.4 节的踩坑表；特别注意 `crop_part` **越界不报错**，必须自己夹取。
