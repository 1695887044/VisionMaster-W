## ⚠️ 最需要记住的两条

1. **分割是成败的 90%，识别只是一行调用**。字切对了识别基本没问题；字切错了再好的分类器也认不出。所以参数分层、必须有「试算」。
2. **认不准必须看得出来**。OCR 最危险的失败不是"认错"，而是"给出一串看似正常的错字符却没有任何提示"——所以本插件有两条 Warn（拒识 + 低置信）。**看到 Warn 不要直接放行**。

## 维护约定

1. **只改主文档**。`OCR文本识别插件.md` 是唯一事实来源；归档件只作历史留档，不再更新。
2. **模型投递两条路径都不能删**（`Update + CopyToOutputDirectory` 供断言工程；`PostBuild` 供生产宿主）。缺第二条，现场运行期找不到模型。
3. **修 bug 必须同时补回归断言**（`FlowCanvasChecks/OcrChecks.cs`），并在主文档第 4 章记录「现象 → 原因 → 修法」。
4. **深度学习的"诚实机制"不能弱化**：任何"认不准"的路径都要能被看出来（Warn 或拒识），不许静默给出看似正常的结果。
5. **拒识判据不许改回"判空"**——HALCON 返回的是"看不见的字符"，判空会漏判（见主文档 4.2 节①）。
6. **HALCON 相关新坑**统一追加到主文档 4.4 节的踩坑表。
