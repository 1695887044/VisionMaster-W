# 第 0 章 这是什么

**创建 ROI = 在图像上画一个或几个"框"，告诉后续步骤"只看框里的，框外的别管"。**

> 生活比喻：你拿到一张全班合影，但只关心第三排的三个同学。你用手指把那块区域圈出来——这就是 ROI（Region of Interest，感兴趣区域）。之后所有分析（认脸、数人数）都只在这个圈里进行，圈外的背景、路人、黑板统统忽略。

它在流程里的位置（归在 **「常用工具」** 分组）：

```
[图像采集] → [创建 ROI] → [Blob 分析] / [模板匹配] / [颜色检查] / [卡尺] → …
                  ↓
      输出：裁剪图（Crop_xxx）+ 带域原图（Domain_xxx）+ 合并区域（MaskRegion）+ 二值掩膜（MaskImage）
```

**与模板匹配的分工**（两者常配合使用）：

| | 创建 ROI | 模板匹配 |
|---|---|---|
| 回答的问题 | "看哪里？" | "目标在哪？" |
| 框怎么来 | **人画的**（配置时画好，固定） | 算法**找出来的**（每帧都变） |
| 有无"学习" | 无 | 有（`create_shape_model`） |
| 典型用途 | 圈定检测区、裁小图分头处理 | 定位、给下游提供坐标 |

一句话：**ROI 是静态的框（配置期确定），模板匹配是动态的框（运行期确定）。** 产线上常配合：先用 ROI 圈出工位区域，再在区域内做模板匹配（搜索更快更稳）。

# 第 1 章 设计思想

## 1.1 核心原理：一切从"区域"开始

复习一个概念：**区域（HRegion）是"剪纸"**——只有形状没有像素值，标记"哪些位置被选中"。本插件的一切都围绕区域展开：

```
画布上画的框（矩形/圆/椭圆）
      ↓ 参数化保存（RoiItem.Params，见第 4 章）
运行时按参数重新生成区域（gen_rectangle2 / gen_circle / gen_ellipse）
      ↓ 多个区域合并（union）、涂擦修正（∪涂抹 −擦除）
合并有效区域（MaskRegion 端口）
      ↓ 两条应用路径
路径A：按 ROI 逐个裁图  →  Crop_xxx 端口
路径B：整图做掩膜抠图   →  MaskImage 端口
```

**为什么不直接存区域对象？** `RoiItem.Params` 存的是**一串数字**（矩形存 5 个数），而不是 HALCON 的 HRegion 对象：

- HRegion 是内存对象，**没法直接进 JSON**；
- 数字数组天然可序列化、跨电脑一致；
- 运行时 3 行代码就能按参数重建区域——**存"配方"，不存"成品"**。

这是整个视觉软件行业的通用做法（模板匹配 `Rect` 5 参数也是同一思想）。

## 1.2 裁剪的两种姿势：Crop vs Domain（最精妙的设计）

本插件给下游提供**两种**"看 ROI"的方式，这是它最核心的设计：

**姿势一：真裁剪（`Crop_xxx` 端口）**

- 图变小了，下游处理快；
- **但坐标系变了**：裁剪图的 (0,0) 不是原图的 (0,0)！所以插件同时输出 `OffsetRow_xxx` / `OffsetCol_xxx`（裁剪原点），下游换算：`全局坐标 = 本地坐标 + 偏移`；
- 换算麻烦——漏加一次偏移，结果就静默错一个"框左上角"的距离。

**姿势二：带 domain 的原图（`Domain_xxx` 端口）**

- 图的大小不变（内存不省），但 HALCON 算子**只在 domain 圈内干活**；
- **坐标系没变**——模板匹配在它上面搜索，返回的还是全局坐标；
- **下游插件一个都不用改**就能吃到 ROI（源码注释实测验证过）。

**怎么选？**

| 场景 | 用哪个 |
|---|---|
| 下游是"智能"插件（自己认 domain）：模板匹配、Blob、卡尺 | **Domain_xxx**（零换算） |
| 下游是"傻"处理（只管手里这张图）：脚本、导出、发送 | `Crop_xxx` + Offset 换算 |
| 只是想省算力缩小图 | `Crop_xxx` |

> 插件把三类端口全给了（Crop + Domain + Offset），下游按需选——**不替用户做选择题，但把每条路的路标都立好**。

## 1.3 掩膜与排除模式

`MaskImage` 是一张 0/255 的二值图（有效区 255，其余 0）。"抠图"就是**原图 × 掩膜 ÷ 255**：

```
原图像素   182    掩膜 255   182 × 255 ÷ 255 = 182   ← 保留
原图像素    90    掩膜   0    90 × 0 ÷ 255    =  0    ← 变黑
```

**排除模式（`MaskInvert`）**：把掩膜黑白反转——ROI 圈的反而变黑，**圈外保留**。用途："这个区域是坏的，检测除它以外的所有地方"。

**合并区域的一条铁律**（源码 62 行注释写死）：

```
合并有效区域 = (ΣROI ∪ 涂抹) − 擦除     （不随排除模式反转）
```

- `MaskRegion` 永远是"**哪里有效**"（正语义）；
- 反转只发生在 `MaskImage`（二值图）那一层；
- **一个概念只在一处反转**——如果区域也跟着反转，下游拿到"排除后的区域"再乘一次反转，语义就乱套了。这是"单一事实来源"原则的区域版：正语义只有一份，反转是**视图**不是**数据**。

## 1.4 架构思路：积木式 + 动态端口

**① 插件化**：遵循平台统一插件规范，从工具箱拖到流程画布，与上下游串成自动线，独立 DLL（`Plugin.CreateRoi.dll`）。

**② 配置态 / 运行态分离**：配置界面里"画框"、保存进方案；运行时只负责"裁剪"，不弹界面、不能点。

**③ 动态端口（本插件最特别的机制）**：模板匹配的输出端口编译期就定死（`Score`/`Row`…），但本插件 ROI 是用户配置时画的——画 3 个框就该 3 个裁剪输出，画 10 个就该 10 个。**端口数量运行期才知道**。`RebuildDynamicOutputs()` 在 `RoiList` 变化或编译器 `ApplyConfigValues` 之后调用，把端口定义快照交给 `StepData.OutputPortDefinitions`，编译运行实例靠快照重建端口。

**④ 单一数据源（MVVM）**：画布、拖拽句柄、数值框三个方向**全部经由 `RoiList`** 互相不直接对话——改画布→写 RoiList→数值框刷新；改数值框→写 RoiList→画布重绘。

# 第 2 章 技术特点

## 2.1 算法（HALCON 算子）

本插件是"区域的搬运工"，核心算子按用途分三类：

| 类别 | 算子 | 用途 |
|---|---|---|
| 生成区域 | `gen_rectangle2` / `gen_circle` / `gen_ellipse` | 按参数重建 ROI 区域 |
| 合并/修正 | `union2` / `difference` / `area_center` / `smallest_rectangle1` / `get_domain` / `gen_empty_region` | 合并、挖除、算面积/质心/外接矩形、防爆 |
| 应用 | `reduce_domain` / `crop_domain` / `region_to_bin` / `mult_image` / `count_channels` / `compose3` / `access_channel` | 域图 / 裁剪 / 二值掩膜 / 抠图 / 通道处理 |

> 完整算子清单见 [5.2 附录](#52-附录-bhalcon-算子速查)。

## 2.2 数据结构（`RoiItem.cs`）

**`RoiItem`：一个框的档案卡**

| 属性 | 类型 | 说明 |
|---|---|---|
| `Name` | string | ROI 名字（默认 "ROI"）。**下游按名引用端口**（Crop_名字），也是唯一键 |
| `ShapeType` | DrawShapeType | 矩形 / 圆形 / 椭圆 |
| `Params` | double[] | 形状参数（见下） |

**Params 参数约定**（与 HALCON 算子一一对应，所以存实际个数，不补位）：

| 形状 | [0] | [1] | [2] | [3] | [4] |
|---|---|---|---|---|---|
| 矩形 | 中心行 | 中心列 | 角度（弧度）| 半长 | 半宽 |
| 圆 | 圆心行 | 圆心列 | 半径 | — | — |
| 椭圆 | 圆心行 | 圆心列 | 旋转角 | 长半轴 | 短半轴 |

> 圆 3 个参数、矩形/椭圆 5 个——和模板匹配"统一 5 参数"不同。原因是这份参数要**直接喂给 `Gen*` 算子**，不需要补位。

**`RoiParamEntry`：参数微调的"翻译层"**（本文件最精彩的设计）

界面要给每个参数一个数值框。难点：`Params` 是 `double[]`——**数组元素没法做 INPC 通知**。解决办法是包一层"行对象"，每个 entry 的 `Value` setter 读写 `Params[index]` 并上抛 `NotifyParamEdited()`，触发画布句柄同步。

- **`Format`**：角度参数是弧度小量（如 0.5236），用 4 位小数（`F4`）；其余 `F1`；
- **`Text` 层**：非法输入按当前值还原显示（不崩、不静默）；`InvariantCulture` 保证小数点永远是 `.`；
- **拖拽高频优化**：长度没变时不重建集合，只对 entry `RaiseWithValue()` 刷新——数值框跟着拖拽实时跳动；
- **`[JsonIgnore]` 必须**：RoiParamEntry 无无参构造且持有 owner 引用，不加此特性加载方案时直接崩。

## 2.3 配置项与端口完整清单

### 配置项（`[StepConfig]`，随方案保存）

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `DisplayViewIndex` | int | 1 | 掩膜合成图发布到主界面窗口（**0 = 不发布**） |
| `MaskInvert` | bool | false | 排除模式：ROI 内变黑、圈外保留。改了立刻刷预览 |
| `RoiList` | ObservableCollection\<RoiItem\> | 空 | **整个 ROI 列表随方案序列化**（比模板匹配"整库序列化成 JSON 字符串"更直接） |
| `SmearDrawData` | string | 空 | 涂抹区域持久化快照（游程编码文本） |
| `SmearEraseData` | string | 空 | 擦除区域持久化快照（同上） |

### 固定端口

| 端口 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `SrcImage` | 入 | HImage | 待处理图像。**不填图会直接 Fail** |
| `RoiCount` | 出 | int | **本轮实际成功输出的裁剪图数**（≠配置数！） |
| `MaskRegion` | 出 | HRegion | 合并有效区域（正语义，见 1.3 铁律） |
| `MaskImage` | 出 | HImage | 二值掩膜图（排除模式下反转） |

### 动态端口（每个 ROI 自动生成 4 个）

| 端口名 | 类型 | 内容 |
|---|---|---|
| `Crop_{名字}` | HImage | 裁剪图（只含 ROI 内容，原点已搬走） |
| `Domain_{名字}` | HImage | 带 domain 的原图（全幅，只在 ROI 内有效，**全局坐标**） |
| `OffsetRow_{名字}` | double | 裁剪图原点在原图的行（`global_row = local_row + 本值`） |
| `OffsetCol_{名字}` | double | 列同上 |

> **为什么 Offset 拆成两个 double 而不是一个 HTuple**：下游（脚本/变量/计算）可直接当标量连线，也保住端口的编译期类型检查（不引入 `object` 多态端口）。

## 2.4 性能优化手段

| 手段 | 做法 | 收益 |
|---|---|---|
| **用 Domain 而非 Crop 喂智能插件** | 把 `Domain_` 接给模板匹配/Blob/卡尺 | ⭐⭐⭐ 零坐标换算，下游不改 |
| **掩膜预览防抖** | 拖拽时 200ms 防抖，只重算最后一次 | ⭐⭐⭐ 全图像素运算防卡顿 |
| **边算边释放** | 合并/擦除每步 `Union2`/`Difference` 产生新对象，旧的立刻 `Dispose` | ⭐⭐ 长列表×每帧执行不锯齿飙升 |
| **所有权移交模式** | `SetImagePort` 返回"是否接管"，调用方据此决定是否释放 | ⭐⭐ 每条路径都不泄漏 |
| **空区域显式 `GenEmptyRegion`** | 一个 ROI 都没画时返回已初始化的空区域 | ⭐ 防爆（见 4.5 节） |

## 2.5 独特实现（工程上的关键设计）

### ① 动态端口 + 快照（`RebuildDynamicOutputs`）

`RoiList` 变化时（画布增删→`OnRoiListChanged`）或编译器 `ApplyConfigValues` 之后调用。每个 ROI 生成 4 个端口，把定义（`DynamicPortInfo`）快照写入 `StepData.OutputPortDefinitions`——**编译的运行实例靠这个快照重建端口，接线面板才有东西可连**。不写快照，编译后的流程就接不上线。

### ② 名字防重（`NextFreeName`）

控件命名序号每次开配置从 0 计数，重开配置再画必然撞上历史名字。重名 = **端口冲突 = 输出互相覆盖 + 内存泄漏 + 按名查找歧义**。三层防御：

- 画布 Add 分支：`NextFreeName` 强制唯一名并回写 `info.RoiName`；
- `Initialize` 播种：对历史方案已存在的重名统一去重，有改名时重建端口与快照；
- 运行期：`RunAlgorithm`/`RebuildDynamicOutputs` 重名只输出第一个端口，兜底旧数据。

### ③ 选中联动的"双向环"断环（`SelectedRoi` ↔ `CanvasActiveRoi`）

列表选中 ROI ↔ 画布激活 ROI 要双向同步，但两个 setter 互相写对方会**无限循环**。解法：两边 setter 都**先判"值真的变了吗"**。还有一个重入陷阱：必须先判同值短路、再做退订/订阅——否则"无条件先退订"遇到同值重入短路后，**订阅被摘走却永远没机会补回**，参数微调就此断链（这是最早的致命 bug，见 4.2 节）。

### ④ 涂擦持久化：游程编码（RLE）

区域要随方案保存。选 RLE 而非序列化 HRegion（HALCON 私有格式不稳）或 PNG（大、要 base64）：

```
区域内容（第 100 行，列 10~20 被选中…）
↓ get_region_runs
"100,10,20;101,10,25;102,10,25;..."     ← 每行只需 3 个数，无损、可读、无需编解码
```

超 4KB 自动 `GZipCompress` + base64（`gz:` 前缀），旧格式照常解析，两代互认——大范围涂擦不让方案文件膨胀。

### ⑤ 恢复顺序的深坑（`RestoreSmear`）

必须**直接写字段后一次性通知**，不能逐个走 `SmearDraw`/`SmearErase` setter——setter 内的 `SyncSmearData` 会把另一边的持久化快照用"尚未恢复的 null"覆盖成空，表现为**擦除区域重开配置即丢、下次确认时方案数据被静默抹掉**。教训：批量初始化走字段、通知走批量（`_seedingCanvas` 哨兵是同一思想的另一实现）。

### ⑥ 掩膜抠图"1/255.0 截断白屏"坑

`mult_image` 的缩放因子必须写 `1/255.0`（一步浮点乘），不能先 `÷255` 再乘（两步整数运算）。否则掩膜中间灰度 128 ÷ 255 = **0**（int 截断）→ 半透明区域全变黑。

### ⑦ 合并区域防爆（`GenEmptyRegion`）

`new HRegion()` 是"未初始化"状态，后面 `RegionToBin` 遇到它会抛异常。"空区域"和"没对象"是两回事——一个 ROI 都没画时显式 `GenEmptyRegion()`。这是 HALCON 新手最常踩的坑之一。

# 第 3 章 使用方式

## 3.1 安装与启用

1. **无需单独安装**：正常编译解决方案即产出 `Modules/Plugin.CreateRoi.dll`。
2. 依赖 HALCON 原生库（随软件分发）。
3. 首次使用前**关掉宿主 VisionMaster 进程**再生成（运行中的程序锁着 `UI.dll` 和插件 DLL）。
4. 重开软件，工具箱里出现「ROI」（**常用工具** 分组）。

## 3.2 配置界面总览

```
┌──────────────────────────────────────────────────┐
│ [原图预览 ○] [掩膜预览 ○]     ← IsMaskPreview 单选  │
├──────────┬───────────────────────────┬───────────┤
│ ROI 列表  │   ImageEdit 画布           │ 参数微调    │
│ (ListBox)│   右键：新建矩形/圆/椭圆      │ (ParamEntries│
│ 选中联动  │   拖拽句柄改大小角度          │  数值框列表) │
│          │   Del 删选中 / 清空按钮       │            │
│          │   涂抹/擦除/清除 + 笔刷半径    │            │
├──────────┴───────────────────────────┴───────────┤
│ 显示窗口选择（0=不显示，1~9=主界面窗口号）              │
└──────────────────────────────────────────────────┘
```

> 左列是主区（ROI 列表 + 参数微调），参数微调在列表下方，未选中 ROI 时只剩标题一行。配置窗口默认 960×680。

## 3.3 第一次画 ROI（6 步）

> 思路：**先接图 → 把一张图弄进配置界面 → 画框 → 选下游要的输出 → 运行**。

**第 1 步｜搭流程**：放一个「图像采集」和一个「创建 ROI」，把前者的图像输出连到「ROI」的 `SrcImage` 端口。

**第 2 步｜把图弄进界面**：在流程里**试运行一次**，上游图会自动显示在右侧画布（订阅了 `SrcImage` 变化）；或者填一张本地图片路径载入。

**第 3 步｜画框**：在右侧图上**右键 → 新建矩形 / 圆形 / 椭圆**。框住你要分析的区域（如"焊盘区""标签位置"）。框多了在左侧列表逐个选中管理。

**第 4 步｜微调（可选）**：选中 ROI 后，右侧参数微调面板用数值框精调"中心行/列、角度、半长/半宽"。拖拽画布句柄或改数值框，**两边实时同步**。

**第 5 步｜决定下游怎么用**（关键）：
- 下游是模板匹配/Blob/卡尺 → 连 `Domain_名字`（**零坐标换算**）；
- 下游是脚本/导出/发送 → 连 `Crop_名字` + `OffsetRow/Col_名字`（自己换算）；
- 只要合并区域/掩膜 → 连 `MaskRegion` / `MaskImage`。

**第 6 步｜显示与保存**：把"显示窗口"设成 1~9（0=不发布），点「确定」保存。`MaskRegion`/`MaskImage` 是新端口，旧方案不会自动接线，需手动连。

## 3.4 多 ROI 与命名

- 想画几个画几个，每个独立名字、列表管理；
- 重开配置再画**不会撞名**（自动改名回写控件，如 `ROI_0`→`ROI_2`），无需担心输出互相覆盖；
- 注意：**当前界面还不能手动改名**（保证唯一性即可），语义命名（如"焊盘1"）是后续候选。

## 3.5 涂抹与排除模式

**涂抹（补充区域）**：切到涂抹模式，画笔涂橙——不规则形状全靠它（比拖句柄自由）。**涂到的地方也算有效区**。

**擦除（挖掉区域）**：切到擦除模式，涂红——把涂错或要排除的地方挖掉。**擦掉的地方不再出现在裁剪图里，也不算有效区**。擦除后橙色（净涂抹=涂−擦）消失到哪，露出底图。

> 显示规则：净涂抹（橙=涂−擦）挖空后露出底图；擦除位置用**红色细轮廓**标出（不是红填充，免得以为"又涂了一笔红的"）。

**排除模式（`MaskInvert`）**：勾选后，掩膜反转——ROI 圈的反而变黑，**圈外保留**。适合"检测除某区以外的所有地方"。

**清除涂抹**：一键置空（`SmearDraw = SmearErase = null`），触发控件同步清除。

## 3.6 下游怎么用输出（接线方案）

**方案 A：零换算（首选）** —— 把 `Domain_名字` 接给下游吃 HImage 的插件：

| 下游插件 | 接哪个输入端口 |
|---|---|
| 模板匹配 | `Image` |
| Blob 缺陷检测 | `SrcImage` / `MaskRegion`（限制检测区） |
| 卡尺测量 | `SrcImage` |
| 码读取 / OCR / 颜色检查 / YOLO | `Image` |

> **实测**：`find_shape_model` 在 domain 图上搜索，命中返回仍是**全局坐标**，domain 外的目标直接不命中。所以下游插件一个都不用改。

**方案 B：必须回变换（用裁剪图时）** —— 连 `Crop_名字` + `OffsetRow/Col_名字`，换算：`全局 = 本地 + 偏移`：

```
global_row = local_row + OffsetRow_名字
global_col = local_col + OffsetCol_名字
```

> ⚠️ **`Offset` 是可选端口**：若下游连了裁剪图却没连 Offset，坐标就是错的**且不报错**。这是 domain 路线存在的理由之一。

## 3.8 FAQ

**Q1** 下游拿到的坐标是局部的还是全局的？
看用哪个输出：`Domain_` 是**全局**；`Crop_` 是**局部**，必须加 `Offset` 才变全局。

**Q2** 为什么 `RoiCount` 比配置的 ROI 数少？
`RoiCount` = **本轮实际成功输出的裁剪图数**。参数无效的 ROI 会被跳过（留警告日志），所以配置 5 个、成功 4 个时 `RoiCount=4`。下游按这个循环取数才不越界。

**Q3** 重开方案后我画的 ROI 还在吗？
在。`RoiList` 随方案序列化；涂擦区域用游程编码或 gz 压缩也一并保存。

**Q4** 擦除/排除模式以前"只影响预览"，现在呢？
历史 bug，已修：现在 `MaskRegion`/`MaskImage` 两个固定端口就位，逐 ROI 裁剪域也吃掉"擦除涂抹"，擦掉的地方不再出现在裁剪图里。

**Q5** 显示窗口选"不显示"还会发布吗？
以前会误发到窗口1，已修：现在 `DisplayViewIndex=0` 真正不发。

**Q6** 带 domain 的图显示时外面是黑的，图坏了吗？
**不是**。domain 外本来就不参与运算，显示为黑是 ROI 的直观表达（仅观感）。

**Q7** 用了裁剪图但没连偏移，会报错吗？
**不会**，坐标静默错。务必一起连 `OffsetRow/Col`。

## 3.9 现场排障

| 现象 | 排查 |
|---|---|
| 下游坐标整体偏一个 ROI 左上角 | 多半是用了 `Crop_` 却没连 `Offset`（或换到 domain 图后模型原点变了，模板匹配需**重新学习**） |
| 掩膜预览空白/异常 | 确认"掩膜预览"开关打开；确认 ROI 参数合法（圆≥3 参数、矩形/椭圆≥5 参数） |

## 4.2 功能 Bug 修复（4 条）

### ① 参数微调选中后断链（核心交互失效）

**现象**：列表选中 ROI 后，在数值框改参数，画布句柄不动、掩膜预览不刷新（"时好时坏"）。

**原因**：`SelectedRoi` setter 先无条件退订 `ParamEdited` 再判断值是否变化。列表选中会经 `CanvasActiveRoi` setter 联动回写同一个 RoiItem（同值重入），第二次进入 setter 时订阅被摘走、同值路径短路后不再补回 → 事件无人监听。画布点选路径因已同值不触发重入，所以时好时坏。

**修法**：先 `SetProperty` 判断真变化再退订旧值/订阅新值；画布活动对象未变时不回写，消除 setter 互写回环。

**回归断言**：`【联动】列表选中 → 画布挂接同一对象` / `【联动】参数微调写回画布句柄（回归：旧 bug 在列表选中路径断链）` / `【联动】重选后参数微调恢复生效`。

> **教训（重要）**：事件订阅/退订必须成对出现在"确认要换"之后，不能出现在"可能短路"之前。

### ② 显示窗口"不显示"仍发布到窗口1

**原因**：`RunAlgorithm` 无条件 `PublishPreview(img, DisplayViewIndex + 1)`，而 ComboBox 0 = 不显示；且 `+1` 是照抄扩展方法过期示例，选"窗口1"会投进第 2 格、选"窗口9"则哪格都不显示。

**修法**：`if (DisplayViewIndex > 0)` 才发布，窗口号**直传**（事件消费端按 `ViewIndex == 窗口号` 等值筛选）。

### ③ 重开配置撞名 → 输出丢失 + 内存泄漏

**现象**：重开配置再画，新建 ROI 必叫 `ROI_0`（控件序号归零），与方案里已有的 `ROI_0` 重名。

**后果**：动态端口重名被 `AddDynamicOutput` 静默去重 → 两个 ROI 写同一端口，`OutputPort` 覆盖旧值不释放 → 首个 ROI 的裁剪图每轮泄漏、下游永远拿不到。

**修法**（三层防御）：画布 Add 分支 `NextFreeName` 强制唯一名并回写控件标签；`Initialize` 播种对历史重名统一去重（有改名时重建端口与快照）；运行期重名只输出第一个端口兜底。

**回归断言**：`【重名防御】画布撞名后 RoiList 全局唯一` / `【重名防御】唯一名回写控件标签` / `【重名防御】端口无重名` / `【重名防御】历史重名方案播种时去重改名`。

### ④ 涂擦区域重开配置即丢（历史数据丢失 bug）

**原因**：`RestoreSmear` 经 `SmearDraw` setter 恢复时，setter 内的 `SyncSmearData` 会把 `_smearEraseData` 用"尚未恢复的 null"重新编码成空串——擦除区域恢复不了，下次确认时方案里的擦除数据被静默抹掉。

**修法**：`RestoreSmear` 直接写字段后一次性 `OnPropertyChanged`，不走 setter 的同步逻辑。

**回归断言**：`【往返】涂抹区从纯文本恢复` / `【往返】擦除区从 gz 压缩恢复`。

## 4.3 功能补全（评审 P2 项）

### ⑤ 涂擦/排除模式只影响预览 → 新增固定输出端口 + 逐 ROI 吃擦除

新增两个固定输出端口（随插件就位，无需配置）：`MaskRegion`（合并有效区域，正语义）、`MaskImage`（二值掩膜，排除模式反转）。逐 ROI 裁剪域现在吃掉"擦除涂抹"（`region − 擦除`）；被擦除殆尽的 ROI 跳过并留警告日志。

### ⑥ 主界面发布改为合并掩膜合成图

以前每个 ROI 的裁剪图都发到同一窗口互相覆盖（只见最后一个）。现改为发布"无效区置黑"的合成图，一帧看清全部 ROI 与涂擦修正，与配置界面掩膜预览同口径。

### ⑦ `RoiCount` 语义修正

由"配置的 ROI 数"改为"本轮实际成功输出的裁剪图数"，下游按此循环取数不越界。

| `union2` | 区域并集（合并多个 ROI） |
| `difference` | 区域差集（挖除擦除区） |
| `area_center` | 面积/质心；**判空利器**（`area<=0`） |
| `smallest_rectangle1` | 轴平行外接矩形左上角——裁剪原点的依据 |
| `get_domain` | 取图像的 domain（验证 Domain 图面积） |
| `gen_empty_region` | 显式初始化空区域（防爆） |

**C 组 · 应用**

| 算子 | 用途 | 注意 |
|---|---|---|
| `reduce_domain` | 大图只处理一小块，**不复制像素、不省内存** | 不改坐标系 |
| `crop_domain` | 真裁出外接矩形，**不旋转图像** | 原点被搬走，回变换只需平移 |
| `region_to_bin` | 区域 → 二值图（剪纸印白纸） | 新区域必须已初始化 |
| `mult_image` | 抠图：`src × mask × (1/255) + 0` | **缩放因子写 `1/255.0`，勿拆两步** |
| `count_channels` | 问图通道数 | 3 通道要把单通道掩膜 `compose3` 成 3 份 |
| `compose3` | 拼成 3 通道图 | 彩色图抠图用 |
| `access_channel` | 取第 N 通道 | **1 基，填 0 报错** |

**D 组 · 涂擦持久化（游程编码）**

| 算子 | 用途 |
|---|---|
| `get_region_runs` | 区域 → 每行起止列（RLE 现成的，无需自写） |
| `gen_region_runs` | 起止列 → 区域（加载方案时重建） |

## 5.3 附录 C：HALCON 实战案例

> 下面 6 个案例按"从简到繁"，可直接照改（HDevelop 风格）。

### 案例 1｜定义三种 ROI 形状

```hdevelop
* 矩形（可旋转，半长半宽不是全长）
gen_rectangle2 (Rect, 200, 300, 0.0, 80, 40)      * Row, Col, Phi(弧度), Length1, Length2
* 圆
gen_circle (Circ, 30, 40, 15)
* 椭圆（斜的）
gen_ellipse (Ell, 100, 120, 0.0, 60, 30)
```

> 矩形的 Length1/Length2 是**半长/半宽**，面积 = 4·L1·L2。角度 **Phi 是弧度**（不是度）。

### 案例 2｜两种"看 ROI"的方式（Crop vs Domain）

```hdevelop
* ① 带 domain 的原图：坐标系不变，下游零回变换（首选）
reduce_domain (Image, Rect, ImageDomain)           * 幅面不变、坐标不变

* ② 真裁剪：原点被搬走，需配合 Offset 回变换
crop_domain (Image, ImageCrop)                     * 裁到外接矩形，不旋转
smallest_rectangle1 (Rect, Row1, Col1, _, _)       * 裁剪原点 = 外接矩形左上角
* 回变换：global_row = local_row + Row1 ;  global_col = local_col + Col1
```

### 案例 3｜游程编码持久化（区域存成文本）

```hdevelop
* 区域 → "行,起列,止列;..." 文本（get_region_runs 直接给每行起止列）
get_region_runs (Region, Rows, ColStart, ColEnd)
* 逐行拼成字符串保存（超 4KB 再 GZip 压缩 + base64，前缀 "gz:"）
* ...
* 加载时反向还原：
gen_region_runs (Region2, Rows, ColStart, ColEnd)  * 注意行号是真实像素行（1 基）
```

> 为什么用 RLE 不用 PNG：区域是"纯形状"，RLE 是原生紧凑表示（每行 3 个数），无损、可读、无需图像编解码。

### 案例 4｜掩膜抠图（防截断白屏）

```hdevelop
* 二值掩膜：内 255 外 0（排除模式：内 0 外 255）
region_to_bin (Region, Mask, 255, 0, Width, Height)

* 彩色图：单通道掩膜没法直接乘 → 复制 3 份
count_channels (Image, Channels)
if (Channels == 3)
    compose3 (Mask, Mask, Mask, MaskColor)
    mult_image (Image, MaskColor, Masked, 1.0/255.0, 0.0)   * ★ 一步浮点乘，别拆 ÷255 再乘
else
    mult_image (Image, Mask, Masked, 1.0/255.0, 0.0)
```

### 案例 5｜合并多个区域 + 涂擦修正

```hdevelop
* 合并：A ∪ B
union2 (A, B, Merged)
* 挖除擦除区：Merged − Erase
difference (Merged, Erase, Final)
* 一个 ROI 都没有时防爆：
if (Final == uninitialized)
    gen_empty_region (Final)        * 不是 new HRegion()（那是未初始化，会炸）
```

### 案例 6｜domain 图坐标系不变（跨插件验证）

```hdevelop
* 在同一张图上：用 domain 限制搜索范围后做模板匹配
reduce_domain (Image, SearchArea, ImageSearch)     * 幅面不变、坐标系不变
find_shape_model (ImageSearch, ModelID, 0, rad(360), 0.5, 1, 0.3, 'least_squares', 5, 0.8, Row, Col, Angle, Score)
* → Row/Col 就是【全局坐标】，下游插件零回变换
* 对比：crop_domain 后匹配得到的是局部坐标，要 global = local + (Row1,Col1) 才能还原
```

> **用法结论**：要让下游零改动吃到 ROI，把 `Domain_` 接给吃 HImage 的插件即可；只有必须用裁剪图（省内存/传输）时，才用 `Crop_` + `Offset_` 并自己回变换。

## 5.6 附录 F：术语表

**图像基础**

| 术语 | 含义 |
|---|---|
| ROI | Region of Interest，感兴趣区域——"圈出来只分析这一块" |
| 区域（HRegion） | HALCON 的"剪纸"：只有形状、没有像素值，标记哪些位置被选中 |
| Domain（域） | 图像的"有效像素标记"。`reduce_domain` 只改域、不动像素、不省内存 |
| 裁剪 | 真把图像切小（`crop_domain`），原点会变 |
| 通道 | 一张图几个数/格。1=灰度、3=RGB |
| 像素当量 | 视野宽度 ÷ 图像宽度，像素换算物理毫米 |

**ROI 专属**

| 术语 | 含义 |
|---|---|
| 动态端口 | 端口数量运行期由画了几个 ROI 决定，`IDynamicOutputProvider` 机制 |
| `Crop_` 端口 | 裁剪图（局部坐标，需配 Offset） |
| `Domain_` 端口 | 带域原图（全局坐标，下游零改动） |
| `Offset_` 端口 | 裁剪原点（局部→全局的平移量） |
| 涂抹/擦除 | 画笔在图上"手涂"补充区 / "挖掉"区，比拖句柄自由 |
| 排除模式 | 掩膜反转：圈内变黑、圈外保留 |
| 掩膜（MaskImage） | 0/255 二值图，乘以原图即"抠图" |
| 游程编码（RLE） | 区域存成"行,起列,止列"文本，无损紧凑、可读 |
| `RoiCount` | 本轮实际成功输出的裁剪图数（≠配置数） |

**HALCON 对象**

| 术语 | 含义 |
|---|---|
| HImage / HRegion / HObject | 图像 / 区域 / 通用对象 |
| HTuple | HALCON 的通用多值容器 |
| 未初始化 vs 空区域 | `new HRegion()` 会炸 `RegionToBin`；`GenEmptyRegion()` 才是安全的空 |
