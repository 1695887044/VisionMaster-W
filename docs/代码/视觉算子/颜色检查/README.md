# 颜色检查插件 · 文档索引

本目录是**两个颜色算子**的专题文档目录。它们**共用 `Core.Halcon.Color` 内核的同一套颜色词与判据**——所以"玫红"在哪个算子里答案都一样。

原先分散在 `docs/code-changes/` 的颜色内核抽取记录、线序检测开发记录与脚本版前史已汇集到这里（**保留，未删除**）。

## 两个插件，先分清用哪个

| | 📘 [区域颜色检查插件](区域颜色检查插件.md) | 📘 [颜色序列检查插件](颜色序列检查插件.md) |
|---|---|---|
| **认什么** | **一块区域**（ROI 内逐点投票取主色 + 占比） | **一个顺序**（沿采样带取一串颜色词，逐位比） |
| **不看** | 不看顺序 | 不看占比 |
| **典型场景** | 指示灯什么颜色、色标对不对、颜色纯不纯、某色占比够不够 | 线序、排线、色带、色块标签 |
| **采样区形状** | 矩形 / **圆** / **椭圆**（圆很关键） | 只有**矩形** |
| **工程目录** | `Plugin.ColorRegion` | `Plugin.ColorCheck` |
| **输出** | `Color` / `Share` / `Rgb` / `Table` / `Result` / `Verdict` | `Result` / `BadIndex` / `Verdict` / `Expected` / `Count` / `Sequence` / `Detail` / `Rows` |

> 两者也常**并列使用**：同一张图上，一个判指示灯颜色、一个检线序。

## ⚠️ 两个插件共有的三条"最容易被误解"

1. **没有 RGB/HSV/Lab 颜色空间切换**。判据固定用 HSV 式（`s=(max−min)/max`、`v=max`、色相角度），不是可配项。要微调的是 **13 项色卡阈值**。
2. **不算颜色距离、没有 ΔE/容差半径**。判定 = 颜色词分类 + 投票（或逐位比对）。
3. **采样区不接上游 ROI**。采样区是插件内部画的 ROI 参数，上游只进 `Image`。

**颜色词只有 11 个**：`黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫`（外加通配符 `*`）。手打"深红"永远匹配不上——**用「一键示教」填**。

## 维护约定

1. **只改主文档**。两篇主文档各是各自插件的唯一事实来源；归档件只作历史留档。
2. **13 个阈值属性名不能改**——共用控件 `ColorThresholdEditor` 靠属性名绑定，而 **WPF 绑定失败是静默的**（改名 = 绑不上且无报错）。
3. **改颜色判据要同时改内核 `ColorVocabulary`**，并同步两个算子的默认值副本（它们各带一份，随方案落盘）。
4. **修 bug 必须同时补回归断言**，并在对应主文档第 4 章记录「现象 → 原因 → 修法」。
5. **几何约定必须写探针实测裁决**，不能靠推理（颜色序列的采样线摊开、自相关找峰都曾因推理出错被推翻）。
6. **配方缺失 = 报错停流程，不判 NG**（工程配置问题 ≠ 产品不良）——这条口径不要改回去。
7. **HALCON 相关新坑**统一追加到对应主文档 4.4 节的踩坑表。
