### 0.2 依赖的底层（已核对）

- `MotionProvider`（设备仓库）：`TryGetDevice(Id)` / `TryGetByKey(Address)` / `AvailableDrivers`（**每次访问都新建 `MotionDriverInfo` 实例**）/ `IsAddressAvailable` / `MarkConfigDirty` + `EnsureSynced`；`DevicesChanged` 在**非 UI 线程**触发。
- `IMotionDevice`：命令模式异步执行，`GetAxisStatus`/`ReadInput` 读轮询快照；**只有 `ReadInput`，没有 `ReadOutput`**。
- `MotionDescriptor`：`Axes`（含 `UnitsPerMm` / 软限位 `SoftLimitMin/MaxMm` / `IsWithinSoftLimit`）、`Points`（扁平、以 `AxisLogical` 字符串为外键）。
- `MotionCamTable`：`MasterAxis`/`SlaveAxis` 存「卡名 · 轴名」**标签字符串**；`MotionCamMath.InterpAt` 每次调用都 `OrderBy` 重新排序。

## 1. 问题清单

### P0 — 安全 / 数据正确性（必修）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| P0-1 | **定位/走此点完全不校验软限位**。`AxisMapping` 已带 `SoftLimitMinMm/MaxMm` 与 `IsWithinSoftLimit()`，但新版调试页只校验"是不是有效数字"，点位页连这个都没校验 | `MotionBoardDebugTabViewModel.cs:735-739`；`MotionBoardPointsTabViewModel.cs:229-241` | 软限位是"软件层最后一道防线"，配了却不拦 = 形同虚设；配置页能填、运动时不生效 |
| P0-2 | **轴映射行内编辑零校验**：逻辑名可空/可重复/可含空白，物理轴号可为负/可重复 | `MotionBoardSettingsTabViewModel.cs:32-99`（`LogicalName`/`PhysicalIndex` 直接写 `Mapping`） | `MotionDescriptor.ResolveAxisIndex` 用 `FirstOrDefault` → 重名时**随机命中**；`RemoveAxisPoints(LogicalName)` 重名会**误删**另一轴的点位 |
| P0-3 | **改轴名不级联**：点位以 `AxisLogical` 字符串为外键，改名后旧点位变孤儿，新名重新 seed 出 16 行空表 | `MotionPoint.cs:119-137`；`MotionBoardSettingsTabViewModel.cs:303` 只发"名字变了"通知 | 用户改个轴名，教好的 16 个点位**静默消失** |
| P0-4 | **旧版 `OnDevicesChanged` 未调度回 UI 线程**（新版做了，旧版没做） | `MotionSettingsViewModel.cs:516-519` 直接遍历 `Cards` 并 `RaisePropertyChanged` | 非 UI 线程改 `ObservableCollection` / 发属性通知 → WPF 抛异常或随机 UI 崩溃 |
| P0-5 | **点位页用地址寻址设备**，而地址在 `MotionProvider` 里被明确定性为"重复时只命中先注册的那张" | `MotionBoardPointsTabViewModel.cs:197` 用 `TryGetByKey(descriptor.Address)`；`MotionProvider.cs:500-508` 有重复告警 | 地址撞车时"命令发给 A 卡、动的是 B 卡" —— 最难查的现场事故 |
| P0-6 | **`async void` 命令处理器**：旧版 `SetEnable` 是 `async void`，`GoToCommand`/`GoToAndWaitCommand`/`HomeCommand` 是 `async` lambda；新版靠手写的 `RunGuardedAsync` 逐个兜 | `MotionDebugViewModel.cs:626/227/228`；`MotionBoardDebugTabViewModel.cs:174-184` | 只要有一个命令忘了包 `RunGuardedAsync`，异常就没接收者 → **进程直接消失** |
| P0-7 | **关窗不取消未完成的运动命令**：外壳关闭只停点动与凸轮，回零（最长 120s）/ 等到位循环仍在跑 | `MotionBoardViewModel.cs:178-188`；`MotionBoardDebugTabViewModel.cs:897` `await Task.Run(() => command.Completion.Wait(120_000))` | 关了窗口轴还在走；`IsWaitingHome` 复位后 UI 与设备状态脱节 |
| P0-8 | **切轴时目标位置沿用上一根轴的值**：`TakeCurrentPosition` 在 `status == null`（未连接）时静默不改 | `MotionBoardDebugTabViewModel.cs:262-263` → `840-845` | 未连接时切轴再点"定位"，目标值是别的轴的上一次目标 —— 一旦连上就是误动作 |

## 2. 优化方案

### 阶段一 · 止血（P0，风险最高、改动最小）

1. **抽 `MotionCommandGate`（闸门单一实现）**
   把"未连接 / 目标非法 / 未使能 / 未回零 / 忙 / 超软限位"六道闸收成一个**静态纯函数**，`MotionBoardDebugTabViewModel`、`MotionBoardPointsTabViewModel`、`AxisPointsViewModel` 三处共用，拒绝文案统一。

   ```csharp
   public static class MotionCommandGate
   {
       public static GateResult CheckMove(IMotionDevice? device, AxisMapping axis,
                                          AxisStatus? status, double targetMm);
       // GateResult { bool Passed; string Reason; }  —— 可直接被单元测试断言
   }
   ```
   顺带把点动心跳判断从 `MotionDebugViewModel` 移到 `MotionJogGuard`（消除 P2-1 的反向依赖）。

2. **`AxisMapping` 校验器 + 改名级联**
   - 新增 `MotionAxisValidator`：逻辑名必填/去空白/全卡唯一（大小写不敏感）；物理轴号 ≥0 且全卡唯一。
   - 行内编辑走校验，失败时挂错误态（不写回 `Mapping`）。
   - 轴名变更走 `MotionDescriptor.RenameAxis(oldName, newName)`：**级联改 `Points[].AxisLogical` + 改凸轮表标签**，而不是现在的"改名 + 重新 seed"。

3. **统一寻址键为 `Id`**：点位页 `TryGetByKey(Address)` → `TryGetDevice(descriptor.Id)`。

4. **旧版 `OnDevicesChanged` 加 UI 线程调度**（与新版一致，建议抽 `UiDispatcher.Post()` 共用）。

5. **消灭 `async void`**：统一 `AsyncDelegateCommand`（内部 try/catch + `IsBusy`），替换 `MotionDebugViewModel` 的 `async void SetEnable` 与所有 `async` lambda。

6. **关窗收尾**：外壳 `OnDialogClosed` 增加 `device.CancelAll("窗口关闭")`；`CanCloseDialog()` 在"回零中/等到位中/凸轮同步中"时改为弹确认。

7. **切轴清目标**：`TakeCurrentPosition` 拿不到状态时把 `TargetText` 置空并给出"未连接，请输入目标"提示。

---

### 阶段二 · 功能补齐（P1）

8. **卡设置页签补齐编辑能力**：地址（改前校验唯一 + 提示"将重建设备并断开连接"）、驱动、机型可编辑；"设备名"回归 `DisplayName`，不再占用 `Remarks`。

9. **移植旧版轴铺底逻辑**：`ReloadAxisRows` 前先 `EnsureAxes(max(能力轴数, 已配轴数, 4))`，连接后按 `Capabilities.AxisCount` 补齐 —— 一次修掉 P1-1 + P1-2。

10. **IO 输出回流**：契约 `IMotionDevice` 增加 `bool? ReadOutput(int port)`（快照，与 `ReadInput` 同口径）；`RefreshRuntime` 增加刷 Outputs；`ToggleOutput` 改为"下发 → 下一拍由设备状态收敛"，失败回滚。

11. **订阅设备事件**：外壳订阅 `FaultOccurred` / `StateChanged`，调度到 UI 线程后走 `NotifyError`（带 `MotionFault.Suggestion`）。

12. **凸轮轴引用结构化**：
    ```csharp
    public sealed class MotionCamAxisRef { public Guid CardId; public Guid AxisId; }
    ```
    `MotionCamTable.MasterAxis/SlaveAxis` 改为该结构（旧方案反序列化时按标签反解并尽力匹配）；`StartSync` 增加"轴/卡是否仍存在且启用"校验；`RefreshAxisOptions` 提供 `AxisOption { CardId, AxisId, Label }`，显示层拼标签、存储层存 Id。

13. **凸轮运行态闸门**：`IsRunning` 时禁用增删拐点、禁用切表（或切表弹确认）。

14. **导入/导出**：点位表（CSV/JSON）与凸轮表（JSON）导入导出，走 `IWorkspaceManager` 的文件对话框。

15. **审计日志**：所有运动命令经 `IMotionOperationLog` 落 `ILogService`，字段 = 时间 / 卡 / 轴 / 动作 / 参数 / 结果；调试页下方增加可折叠"本次会话操作记录"。

16. **默认值统一**：抽 `MotionDefaults`（地址、速度、加速度、超时、最少轴行），外壳 seed 与添加卡共用。

---

### 阶段三 · 架构收敛（P2 / P3）

17. **下线旧弹窗**：`MotionSettingsView` / `MotionDebugView` / `AxisPointsView` 三个注册点改为转发到 `MotionBoardView` 并带 `tab` 参数（外壳已支持 `tab=debug/points/cam`）；删除 `MotionSettingsViewModel`、`MotionDebugViewModel`、`AxisPointsViewModel` 及其行模型，保留 `MotionJogGuard` / `MotionEnumDisplay` / `MotionCamMath` 等纯逻辑。

18. **行模型统一**：一套 `MotionCardRow`（配置+运行态）、一套 `MotionAxisRow`（包装 `AxisMapping`）、一套 `MotionIoRow`，供四个页签复用。

19. **按需刷新**：外壳 `RefreshRuntime` 按 `SelectedTabIndex` 只刷新当前页签 + 左栏在线态 + 统计；三个计时器合并为一个 `MotionUiClock`（200ms），凸轮 50ms 单独保留但仅在运行中启动。

20. **属性通知去字面量化**：引入 `[AlsoNotifyFor]` 特性或 `RaiseAllRuntimeChanged()` 单一出口，杜绝改属性名后静默失效。

21. **凸轮数学性能**：`MotionCamMath` 增加 `SortStable(points)` 缓存与 `InterpSorted(sorted, m)`；`RefreshPreview` 只对排序后数组做一次采样；`SyncTick` 复用同一份排序结果。

22. **数值输入控件化**：`NumberFieldViewModel`（`Text` + `Value` + `Error` + `IsValid`），替换 `JogSpeedText` / `TargetText` / `MoveSpeedText` / `WaitTimeoutText` / `CamSpeedText`；调试页补"加速度"输入（默认取 `Params.DefaultAccelMmPerS2`）。

23. **统计补全**：外壳统计增加 `PendingCommandCount` 合计，超过阈值时顶部挂"命令积压"警告 chip。

## 5. 明确不做

- 不改驱动层（`ZMotionCard` / `VirtualMotionCard`）的下发语义，只补 `ReadOutput` 契约。
- 不引入 SQLite 存点位（保持方案 JSON 落盘，数据量小）。
- 凸轮同步保持"纯软件仿真"定位，但**必须在 UI 上显式标注**（当前只在类注释里写了，用户看不见）—— 这条归入阶段二第 15 项一并处理。

### 设计要点

- **派生索引，不开第二份存档**：真身仍是各卡的 `MotionDescriptor.Axes`（随 .vms 落盘）。两份真身必然在某次保存/加载后分叉。
- **自刷新**：注册表内维护"卡 Id + 每根轴（名字, 轴号）"的精确指纹，每个公开方法进来先比对，变了就重建 —— 调用方不必记得先 `Reload`。
- **默认绝不抢占**：同名 / 同卡同轴号一律返回 `MotionAxisResult`，且报错指向"谁占着"。
- **历史脏数据**：重复时先到者胜、后来者被影子化（解析不到），并把问题作为 `MotionAxisProblem` 报出，由 `MotionModule.Initialize` 写进日志 —— 只报告，不自动改名。

## 8. 插件侧"只按轴名调用"落地记录

| 文件 | 作用 |

### 兼容规则（关键，不可改）

| `Card` 端口 | 走哪条路 | 理由 |
|---|---|---|
| **填了地址** | 老路径：按地址取卡 → 卡内找轴名 | 已保存流程里存着卡地址，且历史方案可能存在跨卡重名。那时"按名字全局解析"会命中**错误的那根轴** —— 老流程必须按老规则跑，一个字节都不能变 |
| **留空** | 全局路径：注册表按轴名解析 → 按卡 Id 取设备 | 新流程只填轴名，彻底不再出现"选哪张卡" |
