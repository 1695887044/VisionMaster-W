# 工位知识地图（理解稿 · 待确认）

> 日期：2026-10-24｜状态：**理解稿，不是最终工位任务书**
> 目的：先对齐"多工位教学线"的站点划分与知识点，再逐站展开动作流程 / 时序 / 异常 / 验收。

---

## 1. 我理解你的意思（先复述，确认没跑偏）

1. **不是单工位**。上一版把工艺收成一台飞剪，方向错了。你要的是**多个工位串成一条线**，工件从上一站流到下一站。
2. **每站都要有"轴 + 相机"**。每个工位至少 2 根轴、至少 1 台相机；不能有"只有相机没有轴"或"只有轴没有相机"的站。
3. **每站讲一个不同的知识点**，而且知识点必须是**轴运动 + 视觉的耦合**，不是"这站检测、那站搬运"这种泛分类。每站要有自己的动作流程、关键时序、异常与可量化验收。

补充理解：

- 工位数量不是越多越好，但**不能少到只够演示一个工艺**；目标是覆盖一张"运动 + 视觉"的课程表。
- 难度来自**工艺耦合与异常**，不是重复机台。
- 工件要带"数字履历"：上一站的视觉/测量结果要影响下一站的动作，否则只是 N 个孤立 demo。

---

## 2. 先纠正一个事实：现有世界并不缺机台

现有 LineSim 世界：**13 工位 / 45 轴 / 14 相机**，而且每个工位都有轴（ST11 只有 1 根，其余 2–5 根），每个工位也都有相机（ST10 有 CAM10/CAM11 两台）。

所以真正的问题不是"机台太少"，而是：

| 问题 | 证据 |
|---|---|
| **知识点重复** | ST3 / ST5 / ST7 都是"视觉检测"，只是工位号不同 |
| **部分站太简单** | ST9 贴标只有 2 根轴；ST11 老化只有 1 根轴 |
| **相机与工位不是一一对应** | ST10 两台相机、ST11 一台相机但工位只有 1 轴 |
| **没有贯穿数据链** | 上游的测量/缺陷结果不驱动下游动作，站与站之间只靠皮带传料 |

结论：**不用再堆机台；要把现有 13 个工位重新切成 8–10 个"教学站"，每站一个唯一知识点。**

|---|---|---|---|---|---|---|---|---|

## 5. 全线数据链（让工位不是孤岛）

工件数字履历（示意）：

```json
{
  "id": 1001,
  "poseAtS1": { "x": 12.3, "y": -4.5, "r": 1.2, "confidence": 0.98 },
  "cutAtS2": { "markOffsetMm": 0.4, "cutLengthMm": 500.2, "cutErrorMm": 0.2 },
  "glueAtS3": { "pathDeviationMm": 0.12, "widthMm": 1.98, "ok": true },
  "pressAtS4": { "measuredHeightMm": 20.04, "pressDepthMm": 7.98, "ok": true },
  "inspectAtS5": { "defects": ["none"], "views": 3, "ok": true },
  "assemblyAtS6": { "holeOffsetMm": 0.08, "forcePeakN": 420, "ok": true },
  "sortAtS7": { "decision": "OK", "rejectTick": 0 },
  "codeAtS8": { "code": "SN202610240001", "read": true }
}
```

联动规则（示例）：

- S1 的位姿 → S4 的压装基准；S1 低置信度 → S4 前重新测量。
- S2 的切长 → S4 的压装深度补偿（切短了，压装基准要跟着挪）。
- S5 的多视缺陷 → S7 的剔除决策；S6 装配失败 → S7 必剔。
- S8 读码失败 → S7 提前分流（不等 S8）；读码成功 → 写追溯库。
- 上游判 NG → 下游站"空跑跳过"（不占节拍、不误判）。

## 7. 需要你确认的 4 件事

1. **站点数**：8 个核心（S1–S8）够不够？要不要把 S9 锁螺丝、S10 打磨作为选修？
2. **串 / 并联**：一条线串到底（工件流过 8 站，上游结果驱动下游），还是每站独立教学单元（可单独练）？我建议**串联 + 单站可独立启动**。
3. **复用还是新建**：在现有 13 工位世界上重切（保留已有轴/相机/IO，改站点职责），还是新开一条"教学线"世界（不动现有演示线）？我建议**重切现有世界**。
4. **任务书深度**：每站一页（知识点+流程+时序+异常+验收），还是每站一份可开发规格（含状态机、IO 表、参数、测试用例）？我建议先出 8 份一页版，确认后再展开 2–3 个重点站。

## 8. 确认后我按站输出什么

每份《工位工艺任务书》固定七段：

1. 设备 / 轴 / 相机 / IO 表（地址、量程、速度、精度）
2. 动作流程（状态机：Idle → Ready → Cycle → Verify → Done/Fault）
3. 关键时序（视觉延迟、轴到位、执行器动作、节拍预算）
4. 联动与数据传递（上游结果如何改本站参数）
5. 异常处理与安全约束（故障矩阵、恢复条件）
6. 可量化验收（测试用例表：输入、期望、判据、证据）
7. 与 LineSim 现有实现的映射（改哪个类 / 加哪根轴 / 哪台相机）
