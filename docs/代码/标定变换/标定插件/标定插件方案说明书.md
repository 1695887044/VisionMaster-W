## 约定（与配套插件共用，先读）

| 约定 | 内容 |
| --- | --- |
| 像素坐标 | `(Row, Col)`：Row 向下、Col 向右（与 HALCON 一致） |
| 机械坐标 | `(X, Y)`：单位毫米；轴方向/镜像/旋转由**九点标定的矩阵自然吸收**，插件不做任何额外假设 |
| 角度单位 | **度**（与模板匹配输出一致）；仅在调用 HALCON 算子时换算为弧度（×π/180） |
| 数组排布 | 多点数组一律 `[x0, y0, x1, y1, ...]`（x 在前、y 在后，成对） |
| 矩阵语义 | `CalibrationTransform.Matrix`（6 元）= 映射 **(Row, Col) → (X, Y)**，HALCON 6 元排布（`X=a11·Row+a12·Col+a31`） |
| 失败纪律 | 沿用仓库纪律：能报的错必须报出"下一步"；失配（尺寸/类型/缺失）必须**明确失败**，绝不静默用旧标定 |

> **配套插件** → [坐标变换插件方案说明书](../坐标变换插件/坐标变换插件方案说明书.md)：本插件产出的 `CalibrationTransform` 由它消费（同时它也是本插件的**验收工具**——标定好不好，用它回算机械坐标就知道）。实施顺序：**先本插件（含契约），后坐标变换**。

## 一、背景与目标

**现状（代码自述，不是我的判断）**

- `Plugins\Plugin.BlobDetect\BlobDetectPlugin.cs:140`：`DefaultPixelSizeMm = 1.0 // 1.0 = 输出即像素值，不假设标定`
- `BlobDetectPlugin.cs:476`：`与仓库 Plugin.CaliperMeasure 的 PixelSizeMm 同一口径（那边注释写明"项目暂无标定模块"）`
- `Plugins\Plugin.CaliperMeasure\CaliperMeasurePlugin.cs:81`：`像素当量默认 1.0 mm/pixel：等于直接输出像素值，不假设任何标定（项目暂无标定模块）`
- `Plugins\Plugin.ImageScript\ScriptTemplates.cs`（"E 精密测量"模板）：`坑：Row/Column是像素，发给机器人前必须过「手眼标定」矩阵换算！`；（"完整标定"模板）：`用 HDevelop 标定助手配 calib_data_* 算子族`

**结论**：像素当量现在是**每个插件各自手填的一个参数**（默认 1.0 = 不标定），没有统一来源、没有标定工具、没有质量校验；"像素 → 机械坐标"这件事被引导到**外部工具（HDevelop）**去解决。这就是本插件要补的洞。

**目标（一期）**

1. **像素当量标定**：用已知长度（量块/标定尺/圆点靶）算出 `mm/px`；
2. **九点标定**：9 组 (机械坐标 ↔ 图像点) 求 2D 仿射矩阵，支持两个方向的坐标换算；
3. **质量可见**：残差 RMS / 最大偏差 / 当量一致性，达标才算成功；
4. **结果可交付**：标定结果随方案存储，输出 `CalibrationTransform` 供下游直接接线。

**非目标（一期不做，见 §十 二期路线）**：标定板全标定与畸变校正、运行期自动示教、标定文件导入/导出、多相机管理、把当量自动下发到卡尺/Blob（那需要改那些插件）。

## 二、关键设计决策

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 标定结果存哪 | **作为 `[StepConfig]` JSON 快照存进步骤**（不引入外部标定文件） | ① 随方案交付、零附加文件（现场最容易丢的就是附加文件）；② 插件物理上拿不到方案目录（只认契约），外部文件路径会引入"换台机器就失效"的绝对路径；③ 与 CreateRoi 的 `RoiList`/涂擦快照同一模式 |
| 2 | 换算职责归谁 | **本插件只"产出标定 + 质量指标"；运行期坐标换算归「坐标变换」插件** | 单一职责 + 单一事实源：两个插件都能换算，早晚出现两套行为不一致 |
| 3 | 运行期要不要重算 | **要**：每轮用存下的标定点重算矩阵并输出 | ① 下游要接它的输出端口，运行期必须有产物；② 求解是微秒级；③ 避免"改了表格但忘了重新标定"的不一致（存储点与输出矩阵永不脱节） |
| 4 | 质量不合格怎么办 | **超阈值 = 业务失败**，错误信息带残差/最大偏差/建议；阈值是显式参数 | 绝不静默：错标定会污染整条产线的判定；要放行就把阈值调大（显式、可解释） |
| 5 | 数学实现 | **纯托管最小二乘**（不调 HALCON 算子）；HALCON 只用于配置态画布取点 | ① 纯函数可被断言完整覆盖（不依赖引擎）；② 无 HALCON 的机器上插件加载不受影响（历史的"构造期 new HImage"教训） |
| 6 | 坐标/角度约定 | 像素 `(Row,Col)`、机械 `(X,Y)`、角度**度**；矩阵语义 `X=a11·Row+a12·Col+a31`（HALCON 6 元排布） | 与模板匹配输出（`Angle` 单位"度"，`MatchingPlugin.cs:204`）和 HALCON `vector_to_hom_mat2d(Px=Row,Py=Col,Qx=X,Qy=Y)` 同语义，避免转置/符号这类静默错 |
| 7 | 失配自证 | `CalibrationTransform` 带 `SourceImageWidth/Height`、创建时间、来源标签 | 换分辨率/换相机后旧标定必须能**自证失效**（下游据此报错），而不是默默算错 |
| 8 | 工程位置 | 插件工程**必须放 `Plugins\` 下** | `Plugins\Directory.Build.targets` 按目录生效，负责把 DLL 投递到 `Modules\`；放别处加载不到（这是部署红线） |
| 9 | 点数与模型 | **点数可配（默认 3×3=9 点，支持 4×4 / 5×5…）；模型固定为仿射** | 点数只是"采样密度/抗噪余量"，**不改变模型能力**——12 点仍是仿射，治不了畸变；畸变的处置见 §十一 |
| 10 | 相机身份 | DTO 带**结构化** `CameraSerial`（不是自由文本标签） | 多相机下"这份标定属于哪台相机"必须机器可读；一期用于日志/人工核对，二期配合采集插件的身份输出做**自动**校验（见 §十一·三） |

## 三、契约与端口

### 3.1 新增 DTO：`Shard\Core.Interfaces\Calibration\CalibrationTransform.cs`

```csharp
public enum CalibrationKind { PixelScale = 0, NinePoint = 1 }

public sealed class CalibrationTransform
{
    public CalibrationKind Kind { get; set; }
    /// <summary>像素当量（mm/px）。PixelScale 模式=直接算出；NinePoint 模式=由矩阵反解的均值</summary>
    public double MmPerPixel { get; set; }
    /// <summary>NinePoint：映射 (Row,Col)->(X,Y) 的仿射 6 元 [a11 a12 a21 a22 a31 a32]（HALCON hom_mat2d 同排布）；
    /// PixelScale：a11=mmPerPx, a12=0, a21=0, a22=mmPerPx, a31=a32=0</summary>
    public double[] Matrix { get; set; } = new double[6];
    public int SourceImageWidth { get; set; }
    public int SourceImageHeight { get; set; }
    /// <summary>来源标签（标定图文件名等，人工核对用）</summary>
    public string SourceTag { get; set; } = "";
    /// <summary>相机序列号（多相机的"这份标定属于哪台"；一期日志/人工核对，二期做自动失配校验）</summary>
    public string CameraSerial { get; set; } = "";
    public DateTime CreatedAtUtc { get; set; }
    public double ResidualRmsPx { get; set; }
    public double MaxResidualPx { get; set; }
    /// <summary>按点位分区的残差（中心/边缘/四角），供"畸变 or 噪声"的诊断（见 §十一·二）</summary>
    public double[] ResidualByZone { get; set; } = new double[5];
}
```

> 放 `Core.Interfaces` 的理由：跨插件传递 + **契约层零 HALCON 依赖**（本 DTO 全是基元类型，JSON 往返安全，也能进全局变量）。

| 方向 | 端口 | 类型 | 说明 |
| --- | --- | --- | --- |
| 输入 | `SourceImage` | HImage | **可选**：仅"图上取点"的配置态预览/在线复算用；纯运行期不接也能工作 |

## 四、运行语义

| 分支 | 行为 |
| --- | --- |
| **PixelScale 成功** | `MmPerPixel = KnownLengthMm / 两点像素距离`；`Transform.Kind=PixelScale`，矩阵按当量构造；残差记 0 |
| **NinePoint 成功** | 最小二乘求 6 元矩阵 → 输出；`MmPerPixel` 由矩阵两基向量长度反解均值；`ResidualRmsPx/MaxResidualPx` 一并输出 |
| 失败：点不足 | PixelScale：两点未取全；NinePoint：有效点 < 3 → "至少需要 3 组点（默认 3×3=9 点，覆盖视野四角+中心；可按需扩到 4×4/5×5）" |
| 失败：点共线 | 法方程行列式近零 → "标定点近似共线，无法求解仿射矩阵，请把点铺开成 N×N 网格" |
| 失败：残差超阈值 | ``` "标定残差 2.31px 超过阈值 1.00px（最大偏差 3.8px）；请检查：① 机械坐标与图像点是否一一对应 ② 特征点是否取在同一物理位置 ③ 残差若呈『中心小、边缘大』→ 疑似镜头畸变，见方案 §十一·二" ``` |
| 失败：当量越界 | "当量 0.00002 mm/px 超出合理范围 [0.001, 1]：单位是否把 µm 当 mm 填了？" |
| 取消 | 无阻塞操作，无取消分支（与采集类插件不同） |
| 幂等 | 同一组输入永远得到同一矩阵（纯函数），重复运行不改变结果 |

## 五、配置界面（`CalibrationView`）

两个页签 + 一个常驻质量区：

**① 像素当量页**
- 「标定图」：浏览/链接变量（与图像采集同一套 `LinkableValueEditor`）；右侧画布显示该图；
- 画布上**画一条线**（两点）：复用 CreateRoi/Matching 的配置态画布交互范式（`ImageEdit` + 取点）；
- 「已知长度(mm)」输入框；
- 实时显示：**像素长度**、**当量 mm/px**、并给"这条线跨越视野的百分比"（提示标定线别太短——短线的相对误差大）。

**② 标定页（网格）**
- **网格规模可切 3×3（默认）/ 4×4 / 5×5**：点数=采样密度，不改模型；点越多抗噪越好、也越能暴露畸变（残差里看得出来）；
- 表格列：`序号 | 机械X | 机械Y | 图像Row | 图像Col | 残差px`；
- 每行「图上取点」：在画布上点一下填 Row/Col（点完即算该行残差并刷新整表）；
- 「粘贴 N 行」：支持从 Excel 直接粘贴（现场常用"示教器读 N 个坐标 → 粘进来"）；
- 「按 ROI 中心预填」：可选便利（若标定点是某个圆形/角点，用匹配/圆查找先定位）；
- **多相机时**：表格扩展为"**一行 = 一个机械位置，N 列 = 各相机的图像点**"——机械只需走 N 次，一次移动把各相机都取上（见 §十一·三）。

**③ 质量区（常驻）**
- 残差 RMS / 最大偏差 / 当量一致性（X 向与 Y 向当量差 > 1% 给橙字提示）/ 结论（绿=通过、橙=勉强、红=不合格）；
- **分区残差**（中心 / 四边 / 四角）+ **诊断提示**：残差"中心小、边缘大"→ 橙字"疑似镜头畸变：当前仿射模型无法吸收，建议改用标定板内参标定或网格标定（§十一）"；整体呈单向/梯形 → "疑似相机倾斜：可用透视标定"；
- 「标定信息」只读展示：**相机序列号**、来源标签、创建时间、标定图尺寸（前三个与尺寸字段在下游失配检测/人工核对时要用）。

## 六、实现要点

1. **最小二乘仿射（纯托管）**：对每组点解两条独立方程
   `X = a11·Row + a12·Col + a31`、`Y = a21·Row + a22·Col + a32`；
   设计矩阵 `A = [Row, Col, 1]`，法方程 `(AᵀA)θ = Aᵀb`，3×3 用克莱姆法则解；`det(AᵀA) ≈ 0` 判共线。
2. **矩阵语义与排布**：输出 6 元 `[a11 a12 a21 a22 a31 a32]`，与 HALCON `hom_mat2d` 完全同排布（`x'=a11x+a12y+a31`），这样未来用它直接喂 `affine_trans_point_2d` 不需要任何转换（§三 已把语义写死）。
3. **当量与一致性反解**：`|∂(X,Y)/∂Row| = √(a11²+a21²)`、`|∂(X,Y)/∂Col| = √(a12²+a22²)`；两者均值记 `MmPerPixel`，相对差 > 1% 时质量区给橙字（各向异性通常是标定物不正对镜头，提示而非失败）。
4. **正/反变换**：反向 = 2×2 线性部分求逆再减平移（求逆失败=行列式近零 → 复用共线分支的文案）。
5. **纯托管边界**：`CalibrationMath.cs` 只吃 `double[]`，不引用 HALCON 类型 → 断言可以直接 new 出来跑（本仓库的测试风格：纯函数优先）。
6. **配置态取点**：画布交互参考 `Plugin.CreateRoi`（`DrawingObjectInfo`/画布 ROI）与 `Plugin.Matching`（`DrawShapeType`）；预览与信息栏沿用图像采集插件的 `StatusLevel` 状态栏约定。

## 七、验证计划

**单元/断言（新增 `FlowCanvasChecks\CalibrationChecks.cs`）**

| # | 断言 | 判据 |
| --- | --- | --- |
| 1 | 已知仿射可精确还原 | 造"旋转 30° + 当量 0.02mm/px + 平移 + 轴交换（X↔Y 反向）"的 9 组点 → 求解 → 任取新点正算，误差 < 1e-6 |
| 2 | 正反变换互逆 | `T⁻¹(T(p))` 与原 p 误差 < 1e-9 |
| 3 | 3 点恰好可解 | 3 个非共线点 → 成功且残差 ≈ 0 |
| 4 | 共线点必须失败 | 9 点全在一条直线 → 失败，文案含"共线" |
| 5 | 残差阈值生效 | 人为给 1 个点加 10px 噪声 → 残差超阈值 → 失败且文案带残差数字 |
| 6 | 当量护栏生效 | 把 mm 当 µm 填（当量 0.00002）→ 失败且文案提示单位 |
| 7 | DTO JSON 往返 | 序列化再反序列化，字段逐项相等（它要随方案落盘） |
| 8 | 构造期不碰 HALCON | 插件可实例化且 `PreviewImage == null`（沿用 [IA] 的断言范式） |

**现场验收（写进说明书，交付时执行）**

1. 打印/放置已知尺寸（如 100mm 标定尺）→ 当量读数与实物一致（±0.5%）；
2. 九点标定后**回算**：把 9 个点的机械坐标经矩阵反算图像点，误差应 < 1 像素当量；
3. 用「坐标变换」插件把匹配得到的 Row/Col 换成机械坐标，与示教器读数比对（这是端到端真验收）。

## 九、二期路线（本期不做，接口先留位）

| 项 | 依赖 / 说明 |
| --- | --- |
| **① 透视标定**（低成本先做） | `vector_to_proj_hom_mat2d`（投影变换 8 自由度，≥4 点、实布 9~16 点）：治"相机倾斜拍平面"；对残差呈单向/梯形规律的现场最有效 |
| **② 网格标定**（畸变的工程近似） | M×N 采样 + **分段仿射 / 双线性插值**（不建物理模型，也能把平面内映射精度提一个量级）；适合"不上标定板但要更准"的现场，数据形态沿用本方案的网格表 |
| **③ 标定板内参标定**（畸变正解） | 多姿态拍标定板 → `find_calib_object` + `calibrate_cameras` 解内参与径向/切向畸变 → `map_image` 校正图 / `change_radial_distortion_points` 校正点；`CalibrationKind` 已留位 |
| 多相机**自动**身份校验 | 采集插件输出 `SourceSerial`(string) → 标定/坐标变换据此自动比对 `CameraSerial`（一期只能日志+人工核对） |
| 相机间标定（cam-to-cam） | 仅在需要"拼图 / 相机间互相换算"时做；**各自与机械做九点标定**已能把多相机统一到同一机械系（多数场景不需要） |
| 运行期示教（自动走点） | 流程里配运动节点走 **N 点（默认 3×3）** + 匹配提供图像点，本插件**累积点对**（新增输入端口 `PixelPoints`/`MechanicalPoints`），凑满 N 组即求解输出——运行期能读轴坐标（`IExecutionContext.Motions`），配置态拿不到设备所以只能手填 |
| 标定文件导入/导出 | 现场多台设备共享同一份标定（同为"设备属性"的场景） |
| 当量直连卡尺/Blob | 需要给那些插件加"当量输入端口"（一期它们只能手填，本期不改，避免多插件连锁改动） |

## 十、风险与边界

- **标定质量取决于取点的物理一致性**：本插件能报出残差，但"点取错位置"这类人为错误只能靠残差与现场验收暴露（所以 §七 的现场三步是交付必做）。
- **九点只覆盖标定平面**：工件不在标定平面（有高度差）时会出现透视误差；一期不处理（二期透视/多平面）。
- **不做 ROI 跟随**（那是「坐标变换」插件的职责）；本插件只出"变换本身"。
- **不替代 HDevelop**：需要内参加畸变模型的高精度场景，二期方案才覆盖；一期解决的是"平面内 mm 与机械坐标"这 80% 的现场需求。

## 十一、追问与答复（点数 / 畸变 / 多相机）

### 11.1 为什么默认 9 点？12 点能治畸变吗？

- 9 点不是"方法名"，而是**仿射模型的采样密度**：仿射只有 6 个自由度，**3 个非共线点即唯一解**；用 9 点是覆盖视野四角+中心、把测量噪声平均掉。
- **12 点仍然是仿射**——多加的点只提高抗噪余量，**模型能力没有任何变化**。畸变是"位置相关的非线性误差"（径向/切向），仿射模型里没有能表达它的项：加多少点都吃不进去，只会把它摊进残差。
- 业界的"12 点 / 16 点 / 25 点标定"通常指两件事：① **透视标定**的多点采样（投影变换 8 自由度，≥4 点，点多更稳）；② **网格标定**（分段仿射/双线性插值）。二者都**不是畸变模型**，而是工程近似。
- 所以本方案的选择是：**点数可配（决策 9）**——默认 3×3，随时可切 4×4 / 5×5；预期收益是"残差更可信、覆盖更充分"，而不是"畸变被治好"。

### 11.2 畸变该怎么治：先看残差形态，再选升级路线

| 残差形态 | 结论 | 走哪条路 |
| --- | --- | --- |
| 随机小残差（无位置规律） | 正常噪声 | 维持仿射（可加密点数） |
| **中心小、边缘大**（径向规律） | 镜头径向畸变 | ② 网格标定（工程近似，不改模型也能提精度）或 ③ 标定板内参标定（正解，有物理模型） |
| 单向偏差 / 梯形 | 相机倾斜（透视） | ① 透视标定（`vector_to_proj_hom_mat2d`，≥4 点，低成本先做） |

分区残差（DTO 的 `ResidualByZone`：中心/四边/四角）与上述诊断提示**一期就做进质量区**——"该不该升级"由数据说话，而不是预先上 12 点。

### 11.3 多相机怎么办

**一期设计天然支持多相机**（每台相机一份标定、一个标定步骤、流程里各自接线），要补的是"顺手 + 不会错"：

1. **身份机器可读**：DTO 带 `CameraSerial`（决策 10）；一期用于日志与人工核对——**自动**核对需要采集插件输出 `SourceSerial`（二期增补，因要改采集插件）；
2. **一次移动、N 台取点**：标定表扩展为"**一行 = 一个机械位置，N 列 = 各相机的图像点**"——机械只需走 N 次（否则是 N×相机数 次）；
3. **统一坐标系**：每台相机**各自与机械做九点**，就天然统一到同一个机械坐标系（多相机融合在机械系里完成）；**只有需要拼图 / 相机间互相换算时**才需要相机间标定（二期，多数场景不需要）；
4. **失配按相机判**：换相机/换镜头后，对应那份标定失效——`CameraSerial + SourceImageWidth/Height` 共同支撑这条（一期人工核对，二期自动）。
