## 第一章 启动层与主程序（App / Shell）

### 1.1 设计思想

启动层是系统的「上帝对象」，统领一切。设计上遵循三个原则：

1. **依赖装配集中化**：所有服务、模块、视图的注册都收敛在 `App.RegisterTypes`，用 Prism 的 `IContainerRegistry` 统一管理依赖注入。
2. **模块化自装配（IAppModule）**：通讯、引擎等子系统各自实现 `IAppModule`，由 `App` 收集模块并调用其 `Register`/`Initialize`，遵守**开闭原则**——新增子系统不改启动类，只加一个模块对象。
3. **启动不假死**：主窗口创建（CreateShell）必须同步返回，但启动自检是异步的。用 **Dispatcher 帧泵（RunWithPump）** 在等待时持续泵消息，保证 Splash 窗渲染/输入照常响应。

### 1.2 核心代码

**依赖注册（顺序即依赖关系）：**

**启动自检链与帧泵（防启动假死）：**

```csharp
protected override Window CreateShell()
{
    _lifetime = Container.Resolve<AppLifetimeService>();
    _lifetime.RegisterGlobalExceptionHandlers();
    // 退出链：最先注册 → 最后运行（逆序），保证日志最后落盘
    _lifetime.RegisterExitTask(ExitTask.Of("日志落盘收尾", () => {
        if (Container.Resolve<ILogService>() is IDisposable d) d.Dispose();
    }));

    foreach (var module in _modules)
        module.Initialize(Container, _lifetime); // 模块注册自检项/退出任务

    // 启动自检链：单例 → 配置 → 插件扫描 → 通信
    _lifetime.RegisterCheck(new SingleInstanceCheck());
    _lifetime.RegisterCheck(new ConfigCheck(...));
    _lifetime.RegisterCheck(new PluginScanCheck(...));
    _lifetime.RegisterCheck(new CommunicationCheck(...));

    _splash.Show();
    var result = RunWithPump(() => _lifetime.RunStartupChecksAsync());
    if (!result.Success) { _splash.ShowBlockingFailure(...); Environment.Exit(2); }
    return Container.Resolve<Shell>();
}

// 帧泵：CreateShell 必须同步返回，但自检是异步的——泵消息使 Splash 不假死
private static T RunWithPump<T>(Func<Task<T>> work)
{
    var frame = new DispatcherFrame();
    var tcs = new TaskCompletionSource<T>(TaskCreationOptions.RunContinuationsAsynchronously);
    _ = work().ContinueWith(t => {
        if (t.IsFaulted) tcs.TrySetException(t.Exception!.GetBaseException());
        else tcs.TrySetResult(t.Result);
        frame.Continue = false;
    }, TaskScheduler.FromCurrentSynchronizationContext());
    Dispatcher.PushFrame(frame);
    return tcs.Task.GetAwaiter().GetResult();
}
```

### 1.3 数据流转

```
进程启动
  → RegisterTypes（注册基础服务/模块/视图）
  → CreateShell：
      注册异常处理器 → 注册退出任务 → 模块 Initialize → 注册自检链
      → 显示 Splash → RunWithPump 执行自检（帧泵保响应）
         ├─ 失败(Error级) → 展示阻塞原因 → Exit(2)
         └─ 成功 → 关闭 Splash → 返回 Shell 主窗口
  → OnInitialized：主窗口显示后关闭 Splash
  → OnExit：ExecuteExitChainBlocking（逆序执行退出任务）
```

### 1.4 关键取舍

- **关闭 Aggressive GC**：注释指出 30s 深清理会冻结主线程 2~3s，WPF+Halcon 常驻>300MB，表现为「空闲双击也卡」。信任 .NET 默认 GC。
- **Splash 在主窗口显示后才关**：避免「零窗口」触发意外 Shutdown。
- **退出链逆序**：日志落盘最先注册、最后运行，保证其他退出任务日志都写全。

## 第二章 通信子系统

### 2.1 设计思想

通信子系统是「抽象连接 + 工厂创建 + 三套定时器」的总管：

1. **工厂模式**：`ConnectionFactoryManager` 根据 `ConnectionConfig.Protocol` 创建对应连接实例，新增协议只需加一个 Config 子类和一个实现类。
2. **线程安全**：连接、配置、定时器、变量全部用 `ConcurrentDictionary`，UI 集合用专用锁，读取方法用 `ConcurrentDictionary<Type,MethodInfo>` 做反射缓存。
3. **三套定时器分工**：
   - **重连定时器**（掉线后按 `RetryIntervalMs` 重试，可设最大次数）；
   - **心跳定时器**（周期性检测，发现掉线启动重连）；
   - **变量轮询定时器**（按 `ReadCycleMs` 周期反射读设备、刷新镜像值）。

### 2.2 核心代码

**变量轮询：反射按类型读 + 更新镜像：**

```csharp
private void PollVariables(string connectionName, ICommunicationConnection connection)
{
    foreach (var variable in variables.Values)
    {
        if (variable.AccessMode == VariableAccessMode.WriteOnly) continue;
        Type valueType = Type.GetType(variable.ValueType);
        if (valueType == null) continue;
        object? rawValue = ReadValueByType(connection, variable.Address, valueType);
        variable.UpdateValue(rawValue); // 触发 ValueChanged
    }
}

private object? ReadValueByType(ICommunicationConnection connection, string address, Type valueType)
{
    Type underlyingType = Nullable.GetUnderlyingType(valueType) ?? valueType;
    if (!_readMethodCache.TryGetValue(underlyingType, out var readMethod))
    {
        readMethod = typeof(ICommunicationConnection)
            .GetMethod(nameof(ICommunicationConnection.Read))!
            .MakeGenericMethod(underlyingType);
        _readMethodCache[underlyingType] = readMethod;
    }
    return readMethod.Invoke(connection, new object[] { address });
}
```

### 2.3 数据流转

```
AddConnection(config)
  → 工厂 CreateConnection(config) → _connections[name] = 连接
  → _connectionsList.Add(config)
  → 状态置 Disconnected → 发 ConnectionStateChanged

Connect(name)
  → connection.Connect()
     ├─ 成功 → Connected → StartHeartbeatTimer + StartVariablePollingTimer(ReadCycleMs)
     └─ 失败 → Error → StartReconnectTimer(RetryIntervalMs)

变量轮询链路：
Timer(ReadCycleMs)
  → PollVariables → ReadValueByType(反射 Read<T>)
  → variable.UpdateValue(rawValue) → 触发 ValueChanged
  → 网络变量镜像更新
```

### 2.4 关键取舍

- **重连计数独立存储**：注释强调「勿复用 ReadCycleMs」——它驱动的是变量轮询周期，混用会导致重连逻辑被轮询周期带偏。
- **反射读方法缓存**：避免每轮询一次都 `GetMethod+MakeGenericMethod`，显著降低高频轮询开销。
- **ReadCycleMs<=0 则跳过轮询**：防止无效周期空转。

## 第三章 流程引擎（编译 + 执行）

### 3.1 设计思想

流程引擎把「可视化图纸」编译成「可执行节点树」，再逐帧执行：

1. **编译/执行分离**：`FlowCompiler.Compile` 把 `StepModel` 蓝图编译成 `CompiledNode` 树（`CompiledIfNode`/`CompiledWhileNode`/`CompiledForNode`/`CompiledPluginNode` 等），运行期不再碰图纸。
2. **内置控制流节点**：`If`/`While`/`For`/`Break`/`Continue`/`Return` 是内置节点，无需插件 DLL，编译期单独识别（`BuiltIn_*` 类型名）。
3. **条件用 DynamicExpresso 解析**：条件表达式（如 `x > 100`）用 DynamicExpresso 编译成 `Lambda`，**每次解析新建 Interpreter**（因为它非线程安全）。
4. **四类数据源绑定**：`LinkPorts` 支持上游算子输出、全局变量、运行时局部变量、常量四类源，通过 `LinkReference` 描述。

### 3.2 核心代码

**运行时变量引用标记（避免与真实 StepID 冲突）：**


**编译主流程：**

```csharp
public CompilationResult Compile(IEnumerable<StepModel> blueprints, string? flowName = null)
{
    var result = new CompilationResult();
    var pluginLookup = new Dictionary<Guid, IVisionPlugin>();
    var nodeLookup = new Dictionary<Guid, CompiledNode>();
    var dependencyMap = new Dictionary<Guid, List<Guid>>();

    var rootNodes = CompileSteps(blueprints, flowName, pluginLookup, nodeLookup, result.Errors);
    LinkPorts(blueprints, nodeLookup, pluginLookup, dependencyMap, result.Errors);

    result.Success = result.Errors.Count == 0;
    if (result.Success)
        result.Data = new CompiledFlow(rootNodes, pluginLookup, nodeLookup, dependencyMap);
    return result;
}
```

**步骤类型分派（内置节点优先于普通算子）：**

```csharp

else if (model is ConditionStep conditionModel) { /* 编译多分支 + 条件 */ }
else if (model is ForStep forModel) { /* 编译循环体 */ }
else if (model.PluginTypeName == "BuiltIn_Break") { new CompiledBreakNode... }
else if (model.PluginTypeName == "BuiltIn_Continue") { new CompiledContinueNode... }
else if (model.PluginTypeName == "BuiltIn_Return") { new CompiledReturnNode... }
```


**执行引擎（连续 / 单次 / 暂停 / 停止）：**

```csharp
public async Task RunSessionAsync(FlowSession session)
{
    session.PauseLock.Set();
    session.CancellationTokenSource = new CancellationTokenSource();
    var token = session.CancellationTokenSource.Token;

    await Task.Run(() =>
    {
        while (!token.IsCancellationRequested)
        {
            session.PauseLock.Wait(token); // 暂停门闩
            if (token.IsCancellationRequested) break;
            foreach (var step in session.Blueprints) step.ResetState();
            var context = new ExecutionContext(_logService, session, _workspaceManager, token);
            session.ExecutionEngine.Run(context); // 执行一轮
            Thread.Sleep(10);
        }
    }, token);
}

public void PauseSession(FlowSession session) => session.PauseLock.Reset(); // 门闩关闭
public void ResumeSession(FlowSession session) => session.PauseLock.Set();  // 门闩打开
public void StopSession(FlowSession session) => session.CancellationTokenSource?.Cancel();
```

### 3.3 数据流转

```
编译：StepModel 蓝图
  → CompileSteps（递归：容器节点先建，再递归子分支）
  → LinkPorts（绑定四类数据源 + 必填项检查 + 记录依赖图）
  → CompiledFlow（节点树 + 依赖图）

执行：CompiledFlow
  → FlowEngineService.RunSessionAsync（后台 Task.Run）
     → 每轮：ResetState → new ExecutionContext → ExecutionEngine.Run(context)
     → 运行焦点在步骤上高亮；暂停时 PauseLock 阻塞
```

### 3.4 关键取舍

- **每次编译 new Interpreter**：DynamicExpresso 非线程安全，new 一个开销极低，从根本上消除并发隐患。
- **运行后清运行焦点**：停止时机可能落在「置 Running 后、置 Success 前」，不清理会让高亮永久卡住。

## 第四章 插件系统

### 4.1 设计思想

插件系统是「反射驱动端口发现」的开闭扩展点：

1. **端口即数据成员**：插件子类把参与数据流的参数声明为 `InputPort` 属性，配置界面直接绑定 `TypedValue`，无需草稿属性镜像。
2. **反射发现端口**：`EnsurePortsDiscovered` 扫描属性自动生成输入/输出端口字典（`Inputs`/`Outputs`），声明时可省略端口名（自动以属性名命名）。
3. **动态端口**：实现 `IDynamicOutputProvider` 的插件（如 CreateRoi）可动态加/减输出端口，编译前框架调 `RebuildDynamicOutputs()` 重建集合。
4. **默认配置生命周期**：`ApplyConfigValues`/`Initialize`/`OnConfirm`/`OnCancel` 统一处理配置灌值、确认写回、快照深拷贝。

### 4.2 核心代码

**插件基类：端口发现 + 执行：**

```csharp
public abstract class VisionPluginBase : ObservableObject, IVisionPlugin, IPluginConfigView
{
    public OutputPort<bool> Success { get; } = new("Success", "成功");
    public OutputPort<string> ErrorMessage { get; } = new("ErrorMessage", "错误信息");

    public IReadOnlyDictionary<string, IInputPort> Inputs
    { get { EnsurePortsDiscovered(); return _inputs; } }
    public IReadOnlyDictionary<string, IOutputPort> Outputs
    { get { EnsurePortsDiscovered(); return _outputs; } }

    public bool Execute(IExecutionContext context)
    {
        RunAlgorithm(context);
        return Success.Value is true; // 业务失败写入 Success，不抛异常
    }
    public abstract void RunAlgorithm(IExecutionContext context);
}
```

**反射端口发现（属性扫描 + 自动命名）：**

```csharp
private void EnsurePortsDiscovered()
{
    if (_isPortsDiscovered) return;
    var properties = this.GetType().GetProperties(BindingFlags.Public | BindingFlags.Instance);
    foreach (var prop in properties)
    {
        if (typeof(IInputPort).IsAssignableFrom(prop.PropertyType))
        {
            var inputPort = (IInputPort)prop.GetValue(this);
            if (string.IsNullOrEmpty(inputPort.Name) && inputPort is IPortNameSettable settable)
                settable.Name = prop.Name; // 自动以属性名命名
            _inputs.TryAdd(inputPort.Name, inputPort);
        }
        else if (typeof(IOutputPort).IsAssignableFrom(prop.PropertyType))
        { /* 同上处理输出端口 */ }
    }
    _isPortsDiscovered = true;
}
```

**配置生命周期（JSON 往返快照，深拷贝防污染）：**

```csharp
public virtual void OnConfirm(IStepConfigData stepData)
{
    foreach (var input in Inputs.Values)
    {
        if (stepData.IsLinked(input.Name)) { stepData.RemoveInputValue(input.Name); continue; }
        stepData.SetInputValue(input.Name, input.Value);
    }
    foreach (var cp in _configProps)
        stepData.SetInputValue(cp.Name, SnapshotConfigValue(cp.Get())); // 快照深拷贝
}

private static object SnapshotConfigValue(object value)
{
    // 原始类型直接返回；复杂类型 JSON 往返拷贝，避免界面后续改动污染已确认数据
    var json = JsonConvert.SerializeObject(value, type, SnapshotSettings);
    return JsonConvert.DeserializeObject(json, type, SnapshotSettings);
}
```


### 4.4 关键取舍

- **[Display] 特性分组**：`GroupName` 决定进哪个仓库（相机/激光/轴卡），框架按该分支调用 `RegisterCamera` 等。
- **动态端口 with 反射固定端口协调**：`ClearDynamicOutputs` 用属性集合判定哪些是固定端口，只清动态部分，避免误删。
- **快照深拷贝**：复杂配置（如 `List<RoiItem>`）确认时 JSON 往返拷贝，不再与界面活对象共享引用。

## 第五章 变量系统（本地 + 网络）

### 5.1 设计思想

变量系统区分两类：

1. **本地变量（`LocalVariableModel`）**：只活在软件内存，读写零延迟，可被流程引用，`ValueChanged` 事件触发。
2. **网络变量（`NetworkVariableModel`）**：挂在某条通信连接上，值来自设备（PLC），由通信管理器轮询刷新。

核心设计在于 **网络变量的「镜像值 + 直通写」**：
- **getter 读镜像（`_value`）**，不直接读设备——避免 UI 绑定触发高频同步 IO 卡顿；
- **setter 直通写**：setter 把新值 `WriteToDevice`，写设备后由轮询「读回」刷新镜像，保证 UI 看到的是设备真实状态。

### 5.2 核心代码

**网络变量：镜像读 + 直通写：**

```csharp
public class NetworkVariableModel : BindableBase, IVariable, IVariableDisplaySource
{
    public void Bind(ICommunicationManager manager) => CommunicationManager = manager;

    // 轮询镜像更新：仅更新本地镜像并通知，不走 setter（避免回写设备造成读写自激）
    public void UpdateMirrorValue(object? newValue)
    {
        if (SetProperty(ref _value, newValue))
            _valueChanged?.Invoke(this, EventArgs.Empty);
    }

    public object? Value
    {
        get => _value; // getter 不直读设备（避免绑定高频同步 IO）
        set
        {
            if (SetProperty(ref _value, value))
                WriteToDevice(value); // setter 直通写设备
        }
    }

    private void WriteToDevice(object? value)
    {
        var connection = CommunicationManager.GetConnection(ConnectionName);
        if (connection != null && connection.IsConnected)
        {
            var rawValue = AddressConfig.ConvertToRaw(value);
            connection.Write(AddressConfig.Address, rawValue);
        }
    }

    // HMI 画布组态预留：显式实现 IVariableDisplaySource
    bool IVariableDisplaySource.IsReadOnly
    {
        get
        {
            if (AddressConfig is DeviceAddressBase<ModbusArea> ma)
                return ma.Area == ModbusArea.DiscreteInputs; // Modbus 离散输入只读
            if (AddressConfig is DeviceAddressBase<S7Area> sa)
                return sa.Area == S7Area.I; // S7 输入映像只读
            return false;
        }
    }
}
```

**本地变量：内存读写 + 事件：**

```csharp
public class LocalVariableModel : BindableBase, IVariable, IVariableDisplaySource
{
    public object? Value
    {
        get => _value;
        set
        {
            if (SetProperty(ref _value, value))
                if (VariableType == VariableType.Local)
                    _valueChanged?.Invoke(this, EventArgs.Empty);
        }
    }

    public void ResetToDefault()
    {
        Value = DefaultValue is Array arr ? arr.Clone() : DefaultValue; // 数组克隆
    }
}
```

### 5.3 数据流转

```
创建网络变量（GlobalVariable 窗口）
  → Bind(manager) 绑定通信管理器
  → 注册到通信管理器轮询体系
  → 通信管理器按 ReadCycleMs 轮询 → ReadValueByType → UpdateValue
  → 网络变量 UpdateMirrorValue（仅更新镜像，不触发写）
  → UI 绑定镜像值自动刷新

写网络变量：
UI 设 Value → setter → WriteToDevice（直写设备）
  → 通信轮询下次读回 → UpdateMirrorValue 刷新镜像
```

### 5.4 关键取舍

- **显式实现 IVariableDisplaySource**：避免与模型自身接口冲突，同时为 HMI 画布组态预留统一的 `BindingKey`/`DisplayLabel`/`WriteValue`。
- **`IsReadOnly` 区分存储区**：Modbus 离散输入/S7 输入映像不可写，UI 据此禁用写值。
- **数组克隆**：`ResetToDefault` 用 `Clone()` 避免共享引用。

## 第六章 方案持久化与序列化安全

### 6.1 设计思想

方案以 `.vms` JSON 文件持久化。核心挑战是 **多态类型与安全**：

1. **`TypeNameHandling.Auto` + `SerializationBinder` 白名单**：抽象/接口位置（如 `ConnectionConfigBase.Config`）自动写 `$type`，反序列化按 `$type` 重建具体子类（`ModbusTcpConfig`/`SiemensS7Config`）。这使新增协议**零维护**，但也引入 `$type` 注入风险，故用 `SafeSerializationBinder` 白名单限定可实例化类型。
2. **方案模型根**：`SolutionModel` 承载方案名、版本、所有流程、通信配置、全局变量、快照、监视项。

### 6.2 核心代码

```csharp
public class SolutionService : BindableBase
{
    private static readonly JsonSerializerSettings _jsonSettings = new()
    {
        Formatting = Formatting.Indented,
        NullValueHandling = NullValueHandling.Ignore,
        TypeNameHandling = TypeNameHandling.Auto,
        SerializationBinder = new SafeSerializationBinder()
    };

    // $type 白名单：只允许本项目的 Models / CommunicationContracts 类型被反序列化
    private class SafeSerializationBinder : ConnectionConfigSerializationBinder { }

    public async Task<Result<bool>> SaveAsync(SolutionModel targetSolution, string filePath)
    {
        var json = JsonConvert.SerializeObject(targetSolution, _jsonSettings);
        await File.WriteAllTextAsync(filePath, json);
        return Result<bool>.Ok(true);
    }

    public async Task<Result<SolutionModel>> LoadAsync(string filePath)
    {
        var json = await File.ReadAllTextAsync(filePath);
        var solution = JsonConvert.DeserializeObject<SolutionModel>(json, _jsonSettings);
        if (!_solutionModels.Contains(solution)) _solutionModels.Add(solution);
        return Result<SolutionModel>.Ok(solution);
    }
}
```

### 6.3 数据流转

```
保存：SolutionModel → JsonConvert.SerializeObject(TypeNameHandling.Auto) → .vms
加载：.vms → DeserializeObject → $type 重建具体子类 → SolutionModel
  → 变量按快照重建并重新接线轮询
  → 通信配置恢复
```

### 6.4 关键取舍

- **白名单继承通信包的 binder**：复用 `ConnectionConfigSerializationBinder` 并直接继承，统一白名单逻辑，一处改动全局生效。
- **`ObjectCreationHandling.Replace`**（SolutionModel 的 JsonProperty）：重载方案时替换集合而非追加，避免重复。

## 第七章 MVVM 基础设施（ObservableObject / 模型基类）

### 7.1 设计思想

自定义 `ObservableObject` 实现 `INotifyPropertyChanged`，完美复刻 Prism 的 `SetProperty` 并扩展了「数组内容比较、可空类型、枚举比较」等特殊情况，为所有 ViewModel 和模型提供统一通知基座。

### 7.2 核心代码

```csharp
public abstract class ObservableObject : INotifyPropertyChanged
{
    protected virtual void OnPropertyChanged([CallerMemberName] string propertyName = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));

    // 复刻 Prism 的 SetProperty，支持数组内容比较、可空、枚举
    protected virtual bool SetProperty<T>(ref T storage, T value, [CallerMemberName] string propertyName = null)
    {
        if (ValuesAreEqual(storage, value)) return false; // 值没变就不通知，提升性能
        storage = value;
        OnPropertyChanged(propertyName);
        return true;
    }

    private bool ValuesAreEqual<T>(T oldValue, T newValue)
    {
        if (oldValue == null && newValue == null) return true;
        if (oldValue == null || newValue == null) return false;
        Type type = typeof(T);
        if (type.IsArray) return ArraysAreEqual(oldValue as Array, newValue as Array);
        if (type.IsEnum) return Enum.Equals(oldValue, newValue);
        if (typeof(string).IsAssignableFrom(type)) return string.Equals(oldValue as string, newValue as string);
        return EqualityComparer<T>.Default.Equals(oldValue, newValue);
    }
}
```

### 7.3 数据流转

```
模型/VM 属性 set：SetProperty -> 值比较 -> 赋值 -> OnPropertyChanged
  -> WPF 绑定刷新 UI
数组/枚举/可空特殊类型：ValuesAreEqual 分派比较，避免引用相等误判
```

### 7.4 关键取舍

- **用 [CallerMemberName]**：编译期自动填属性名，极大减少硬编码字符串错误。
- **数组内容比较**：数组是引用类型，默认 EqualityComparer 比引用会误判（同一个数组对象改内容不通知），故逐元素比较。

## 十一、流程搭建

### 4.1 流程本身

- 每条流程有名称、描述、是否启用（`IsEnabled`）。**禁用的流程不参与批量编译/运行**。
- 内置两条初始流程：`GoHome`（回原）、`MainTask`（主任务），可自行增删改。

### 4.2 添加步骤

从**工具箱**把算子拖到流程画布。算子分为两类：

- **视觉算子**（外部插件 DLL）：如 CreateRoi、ImageAcquisition（相机）、ImageScript（脚本）、Utility 下的数学/数组/比较/字符串等；
- **逻辑控制节点**（内置）：`If`、`While`、`For`、`Break`、`Continue`、`Return`，用于构造分支和循环。

### 4.3 连线（数据流）

每个算子的**输入端口**可以连到上游算子的**输出端口**、某个**变量**、或**常量**。

- **端口即数据成员**：参数是端口，配置界面直接绑定端口的 TypedValue；
- 输入端口的 `LinkedSource`（链接源）确定数据来源；
- 带数据类型的端口会做类型匹配，不匹配的连线会报错。

### 4.4 If / While / For 分支

- **If**：条件成立走 Then 分支，否则走 Else/Default 分支；条件用表达式（如 `x > 100`）。
- **While**：条件成立持续执行循环体内步骤。
- **For**：按固定次数循环（默认次数可配），循环体会输出当前 `Index` 索引供下游使用。
- 条件表达式支持引用**局部变量** / **运行时变量**，允许使用数学函数（`Math` 已引用）。

### 4.5 禁用步骤

每个步骤可勾选 `IsDisEnable`，禁用的步骤编译时被跳过。

## 十四、编译与运行

### 7.1 编译

`流程 → 编译`（或对单个流程）。把可视化图纸编译成可执行节点树。

- 编译会检查：找不到插件、必填参数缺失、表达式语法错误、连线断开等；
- 失败会把错误逐条弹出提示。

### 7.2 脏检查（版本校验）

运行前系统会比较**流程图版本**与**已编译版本**：若图纸已被修改，会提示"配置已更改，运行逻辑已过期，是否重新编译？"。**务必重新编译再运行**，否则改动不生效。

### 7.3 单次运行

执行一次即停。适用于**试运行**单张图片、验证逻辑。

### 7.4 连续运行

在后台循环执行：暂停可继续，停止即中断。流程中每个步骤高亮显示当前运行焦点。

### 7.5 批量运行

对方案里**所有启用的流程**批量「单次」或「连续」运行——适合多流程同时在线检测。

### 7.6 停止

`流程 → 停止`，终止所有运行中的流程。

> **运行顺序**：单次运行 / 运行前会对每个流程做脏检查并按需重编译；连续运行/单次运行基于已编译的会话实例，修改流程需先重新编译。

## 十五、监视与状态查看

- **系统监视**：Shell 状态栏实时显示 CPU%、内存 MB、线程数、句柄数、时间（1 秒刷新）。
- **流程状态**：监视面板/流程列表可见各流程的 Running / Paused / Stopped / Faulted 状态。
- **插件结果**：每个插件输出 `Success`（成功）与 `ErrorMessage`（错误信息），流程节点据此标记状态并写日志。
- **图像视图**：插件输出的 HImage 实时显示，支持多分屏（1\~9 路，顶部切换）。

## 十六、常见问题 FAQ

**Q1：网络变量当前值一直不动？**
按序查：① 左栏该连接圆点是否绿（红=掉线）；② 该连接 ReadCycleMs 是否 >0（轮询才跑）；③ 地址对不对（Modbus 保持寄存器偏移 100 → 实际读 40101；S7 M 偏移 0 → MW0）；④ 用设备模拟器（ModbusSlave/Snap7）确认设备值真的在变。

**Q2：写了值设备没收到？**
先确认连接在线，再抓报文（Wireshark）验证。已知缺陷：网络变量写失败当前被静默吞异常，UI 可能假显示"已写入"。

**Q3：保存方案后重开，网络变量不见了？**
大概率是反射重建地址失败（协议类被改名）。检查快照里 `Protocol`/`DataValueType` 字符串与枚举名是否一致。

**Q4：int/float 读出来是怪数？**
确认 `Read<T>` 粒度未回退：Modbus 按寄存器数（short/bool=1，int/float=2，long/double=4），S7 按字节数。若被改成固定读 1，int/float 只会读到半截。

**Q5：S7 布尔地址报错？**
S7 位访问必须是 `M0.0` / `DB1.DBX0.0` 格式（无 X 前缀 + 位偏移），位偏移默认 0，线圈区布尔不要填位偏移。

**Q6：改动参数后运行没生效？**
先重新编译（脏检查会拦截）。若未提示，说明版本号未递增，检查是否用 `SetInputValue` 写参数（它会触发版本递增）。

**Q7：新建网络变量后 UI 没自动接线？**
确认 `NetworkVariableBridge` 已注册单例、ShellViewModel 构造已注入、方案加载后调了 `RebindAll()`。

**Q8：工具箱里没有算子？**
检查 `Modules/` 目录下是否有 `Plugin*.dll`，且插件类带 `[Display]` 特性、实现了 `IVisionPlugin`。启动自检的「插件扫描检查」会提示加载失败项。
