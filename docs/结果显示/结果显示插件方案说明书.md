## 2. 目标与非目标

### 目标
- G1 一个通用显示算子：接一张底图 + N 个"结果项"（任意上游输出），把数值/文本/判定/几何/区域统一**烧进图像像素**，发到主界面视图窗口。
- G2 现场零门槛：不写脚本、不懂 HALCON、不为每个新算子单独做显示；结果项**加一行 = 长一个端口**，行内直接连线。
- G3 **标注随图走**：缩略图、导出 PNG、报警留存图都带标注（§1.1），用户不需要理解"覆盖层 vs 烧录"的区别。
- G4 成为仓库**唯一**的离屏烘焙实现（收敛点，不许出现第六份）。
- G5 显示失败绝不停线（宁缺显示不阻断生产）。

### 非目标（本轮明确不做）
- N1 **不迁移五份既有烘焙件**（§12-③，单开一轮）。本轮只落地共享件 + 让「结果显示」用它。
- N2 不改宿主：不动 `ImageDisplayEvent` / `ImageFrame` / `ImageGallery` / `ImageExporter` / `HalconBase`（宿主侧的洞单开一轮，见 §12-②）。
- N3 不支持 `HImage` 作为结果项（底图只有 `SrcImage` 一个入口）。
- N4 不做可编辑 ROI（那属 `HalconBase.DrawObjectList:176` 体系，不是随帧烧录）。
- N5 不做集合端口 `InputPort<List<T>>`（全仓零先例；`AutoPortConfigView`/JSON 快照/连线检查三条路都未验证）。
- N6 不撤既有 12 个发布者的 `DisplayViewIndex`（见 D6）。
- N7 **不废弃覆盖层链路**（`ImageFrame.Annotations` / `RenderAnnotations` / `ImageGallery.xaml:77,120`）——本插件不再用它，但它是宿主域，处置属 §12-②。
- N8<br>（★ 10-14） **不给单个结果项配坐标**、**不做几何标签的偏移可调**。文字位置只做"算子级三项"（九宫格锚点 + 边距 + 字号倍率，§5.5）。用户在 AskUserQuestion 里点的就是这一档，"逐项归一化坐标"与"标签偏移可调"是**明确落选**的方案，不要当"顺手补齐"来做：逐项坐标换分辨率/改 ROI 后**静默错位**（`TextAnchorKind.cs` 里记着这个理由），而"某一行单独放"的正解是再接一个结果显示算子。

## 5. 渲染规则（烧录管线）

**总流程**（`RunAlgorithm` 内，全程在流程线程）：
```
SrcImage → ① 底图归一化 → ② 建 BakePlan（结果项 → 图形/文字）→ ③ Baker.Bake（离屏窗口 disp + dump）
        → ④ AnnotatedImage = 产物 → ⑤ PublishPreview(产物, viewIndex, "结果显示", infoRows, null)
任何一步失败 → Warn + 降级（§6.3），Success 保持 true
```

### 5.1 底图归一化（**照 BlobDetect 那份，别照 Caliper 那份**）

烧录前必须把底图变成"HALCON 能 `disp_obj` 的 byte 图"。两份既有实现质量不等，**以完整的为准**：

| 步骤 | 做法 | 证据 |
| --- | --- | --- |
| 通道数 | `CountChannels`；**4 通道先丢 alpha**（`AccessChannel`×3 + `AppendChannel`×2） | `BlobDetectPlugin.cs:1877,1882-1886,1929-1943`。注释 `:1879-1880`：`disp_obj` 只稳妥支持 1/3 通道，4 通道直接画会报"通道数不对"，**整张标注图就没了** |
| 已是 `byte` | 直接用 | `:1888` |
| 多通道非 byte | `ConvertImageType(...,"byte")` | `:1894` |
| **单通道非 byte** | `GetDomain` + `MinMaxGray` + `ScaleImage` **线性拉伸后**再转 | `:1902-1921`。注释 `:1899-1901` 是硬坑：**`convert_image_type(...,'byte')` 是截断不是缩放**，实测 uint2 灰度 1632 转出来就是 255 → **12/16 位相机的底图整片死白**。Caliper 那份（`CaliperMeasurePlugin.cs:1710-1718`）只有一行 `ConvertImageType`，**没修这个坑，不要抄** |

### 5.3 类型分派（`object` 口收到的值 → BakePlan）

判型顺序必须 **`HImage` → `HRegion` → `HXLD` → `HObject`**（`HRegion`/`HXLD` 都派生自 `HObject`，顺序错了会走错分支；范式 `Plugin.ImageScript\ImageScriptPlugin.cs:1101-1103`）。

| 值类型 | 处理 | 烧进图里 | infoRows |
| --- | --- | --- | --- |
| `null` | 跳过（未连线/上游失败） | — | `标签: (空)` |
| `double`/`float`/`decimal`/`int`/`long`/`short`/`byte` | 格式化（`Format` 非空 → `ToString(Format, InvariantCulture)`；空 → `ToString("0.####", InvariantCulture)`）+ `Unit` | `DispText`：`标签: 值单位` | 同文本 |
| `bool` | `true`→`OK`、`false`→`NG`（参与判定配色） | `DispText` | 同 |
| `string` / `enum` / `DateTime` | 原样（`DateTime` 用 `Format` 或 `HH:mm:ss.fff`） | `DispText` | 同 |
| `GeometryParam` | 见 §5.4 | `DispLine`/`DispCircle`/`DispEllipse`/`DispCross` + 摘要 `DispText` | `标签: g.ToString()` |

### 5.4 `GeometryParam` → 图形（**行主口径，最容易静默错的一处**）

`GeometryParam.Phi` 的定义是 `atan2(dr, dc)`（`Plugin.GeometryFinder\Services\GeometryHService.cs:63-67`），所以**方向向量 = (dr, dc) = (sin φ, cos φ)**：

```csharp
double rad = g.Phi * Math.PI / 180.0;
double dr = Math.Sin(rad), dc = Math.Cos(rad);          // ★ 不是 (cos, sin)
double half = Math.Clamp(Math.Min(width, height) / 3.0, 40, 4000);
// Line: DispLine(win, Row - half*dr, Col - half*dc, Row + half*dr, Col + half*dc)
```
套数学的 `cos/sin` 会把水平线画成竖线（45° 镜像）——图形看着"差不多直"，量全错。这条必须有**两层**断言钉死（§8.2 A3 查 plan 里的坐标、§8.2 C2 采样像素）。

| Kind | 烧录用算子 |
| --- | --- |
| `Point` | `DispCross(win, row, col, size, 0)`（size 取 `Math.Max(6, height*0.01)`）+ `DispText` 标签在点右上 |
| `Line` | `DispLine`（上式两端点）+ 中点 `DispText`：`标签 φ=xx.x°` |
| `Circle` | `DispCircle(win, row, col, radius)` + `DispCross` 圆心 + `DispText`：`标签 r=xx.x` |
| `Ellipse` | `DispEllipse(win, row, col, phi, ra, rb)`；长轴 `(dr,dc)=(sinφ,cosφ)`、短轴 `(pr,pc)=(cosφ,−sinφ)`（照 `GeometryHService.cs:90-105`）。**`disp_ellipse` 的参数序要按 halcondotnet 实际签名核对一次**，别照数学惯例猜 |
| `Contour` | 点数 ≤2000：`GenContourPolygonXld` 生成一次 → `DispObj` → **立刻 Dispose**；或退化成逐段 `DispLine`（点很多时更慢但零对象） |

### 5.5 文字排版与字号（锚点/边距/字号可配，**逐项坐标不给配**）

★ 2026-10-14：本节原文是"起点固定左上角、全自动不给配"，现落地为**"算子级三项可配（`TextAnchor`/`TextMargin`/`TextScale`，§4.2）、逐行坐标仍不给配"**。默认值 = 老行为（左上、自动边距、1.0 倍）。

**自动基准**（`DisplayDraw.Ctx` 构造，全部按图高缩放，通用算子必须自适应）：
- 自动边距 `margin = Math.Max(12, height * 0.02)`；`TextMargin > 0` 时**用用户填的**，`0` 才走这条自动值；
- 自动字号 `autoFontSize = Math.Clamp((int)(height * 0.028), 14, 64)`（既有实现硬编码 20（#1#2）/ 16（#3#4），因为它们的图尺寸已知），再乘倍率 `FontSize = Math.Clamp((int)Math.Round(autoFontSize * TextScale), 6, 200)`；
- 行距 `LineHeight = Math.Max(FontSize + 4, Math.Max(20, height * 0.035) * TextScale)`——取大者是为了**倍率放大时字与字不粘连**（只按 `FontSize+4` 在 3.0 倍下会挤）；
- 字体 `-Consolas-{size}-*-0-*-*-1-`，`SetFont` 失败要吞掉（`TrySetFont`，`BlobDetect\AnnotationRenderer.cs:172-178`：字号是锦上添花，**绝不能因为它让整张图渲染不出来**）。

**九宫格落位**（`(int)TextAnchor` 行主序：0~2 上带、3~5 中带、6~8 下带；列 = 0/3/6 左、1/4/7 中、2/5/8 右）：
- **垂直分量归 `DisplayDraw`**（它才知道行数）：堆叠文本先攒进列表，`Build` 末尾 `ctx.EmitStack()` 一次性落位；`blockHeight = 行数 × LineHeight`，上带 `top = margin`、中带 `(height - blockHeight)/2`、下带 `height - margin - blockHeight`，最后 `top = Math.Max(0, top)`；
- **水平分量归 `AnnotationBaker`**（它才有窗口）：`BakeText` 新增可选 `HAlign`（`Left`/`Center`/`Right`，**默认 `Left` = 历史行为**），`Col` 的含义随之变成"左边缘 / 中心 / 右边缘"，baker 在 `TrySetFont` 之后用 `GetStringExtents` 量**真实像素宽**再换算并夹回 `[0, w-1]`。为什么必须这样分：文字宽度取决于**窗口当前字体**，而静态扫描 ④c 明令插件自己零 `OpenWindow`/`SetPart`——调用方根本拿不到窗口，凭字符数估宽必歪（等宽字体也有上下标与小数点差异），量不到就只能贴左。**对齐是烘焙件的能力，不是调用方的**（AGENTS.md R39）；
- 几何标签（点右上 / 线中点 / 圆圆心旁）**仍跟随图元、不受锚点影响**，只有字号同比放大——用户裁决明确不要"几何标签偏移可调"；
- 下带保留一个 `margin` 的余量（不是贴到 `height-1`），行带溢出时 `top` 钳回 0，**最坏是首行贴顶，绝不把整块推出画布**。

**三条边界（断言已钉，见 §8.2 U1~U9）**：
1. `ShowTextOnImage = false` 时**一个文字都不进 `Texts`**，锚点配成右下也不会漏出几何标签之外的字；
2. 默认参数与迁移前的老实现**产出完全相同的 `Texts`**（逐条比 `Row`/`Col`/`Text`/`Color`/`FontSize`/`Box`/`HAlign`，U1）——这是"四项已迁插件零行为变化"的机器证明；
3. 三新参默认值可选，既有 `DisplayDraw.Build` 的唯一调用点与四个已迁插件的 `Bake` 调用点**不改动也照样编过、行为不变**。

行/列坐标钳进 `[0, height-1]`、`[0, width-1]`（坐标系是 `"window"`，单位 = 像素；纪律 4/5 归 `AnnotationBaker` 本类）。

### 5.6 颜色
封闭白名单，**只允许** `green` / `red` / `orange` / `yellow` / `cyan` / `magenta` / `white`（HALCON 色名，直接进 `SetColor`）。
- 未配判定项 → 全 `green`；
- 配了判定项：该项值 == `NgValue`（智能比对，照 `ResultUploadPlugin.cs:592-628` 的 `TryAsDouble`/`TryAsBool`/字符串三路，`InvariantCulture`）→ 判定项与所有文本项 `red`，否则 `green`；
- 几何项固定 `cyan`（与"判定色"区分开，避免满屏红绿看不出哪个是判定）；分层配色可照 Caliper 的既成语言：卡尺框 `yellow`、测量线 `cyan`、拟合几何 `magenta`、边缘点 `green`（`CaliperMeasure\AnnotationRenderer.cs:57-87`）；
- 非法/未知色名 → 回落 `green`（**绝不把用户字符串直接当色名传下去**）。全仓画面语言见 `Services\Core.Halcon\Color\ColorMarks.cs:9-22`（`Pass=green / Fail=red / Inferred=orange`）。

### 5.7 钳制与元素上限（不做就是"整张图没了"或"节拍没了"）
1. 所有坐标 `double.IsFinite` 校验，非 finite → **丢这一条**（不是丢整张）+ Warn；
2. 坐标钳进图幅（§5.5）；半径/线宽钳正数（`radius<=0` 直接丢这条）；
3. 色名走 §5.6 白名单；
4. 轮廓/区域点数抽稀上限 **2000**；
5. **烧录元素总数上限 `MaxDrawElements`（默认 300）**：超出只画前 N 个（按结果项顺序），并在图上追加一行「（仅绘制前 N 项）」；**端口数据永远全量**（照 `BlobDetectPlugin.cs:1775-1784,1812`）；
6. 烧录本体抛错 → `Bake` 返回 `null` → 降级发布**原底图**（§6.3）。⚠ 覆盖层方案里那条"`RenderAnnotations` 抛错 → `flush_graphic` 停在 false（`HalconBase.cs:1087` 置、`:1160` 复位）→ 该帧整幅空白且反复空白"的失败面**在烧录路线下不存在**（不走 `RenderAnnotations`），取而代之的失败面是"dump 不出来 → 整张标注图丢"。

### 6.2 线程与并行（烧录把这一节的风险抬高了一档）
- `[ParallelSafe]` **仍可标**（判据 `Shard\Core.Interfaces\ParallelSafeAttribute.cs:8-21`：无 static 可变字段、不写全局变量；`FlowCompiler.cs:1391` 的冲突检查只盯 `VariableAssignmentPlugin` 的写）。烘焙件的窗口是**实例字段**不是 static。

- **禁止**从全局变量取底图（并行下读全局无任何护栏）。

### 6.3 失败口径（宁缺显示不停线）
- 取不到底图 / 认不出的类型 / 烧录抛错 / 发布抛异常 → **一律不 `Fail`**：`context?.Logger?.Warn(...)` + `Success` 保持 true。理由：显示算子失败会拖垮整轮（`Engine\FlowInvoker.cs:132-133`）。既有五份的契约注释都是这个口径（`BlobDetectPlugin.cs:1760`、`CaliperMeasurePlugin.cs:1236`：渲染只是"给人看"，失败最多丢标注图，**绝不能把一次成功的测量判成失败**）。
- **降级梯度**（一级比一级差，但都不停线）：单个结果项画不出来 → 丢这一项 + 红字说明；烧录整体失败 → `AnnotatedImage=null` + **发布原底图**（用户至少看得到图）；连底图都没有 → 不发布 + 一条 infoRow。
- **无桌面会话**（纯服务/无显示环境）下 `open_window('buffer')` 理论上可能失败（`docs\卡尺测量\2026-09-25-卡尺测量插件第一批.md:342-343`）→ 归入"烧录整体失败"降级，Help FAQ 写明。
- 全部结果项未连线 → 仍发布底图 + 一条 `ImageInfoRow("结果","未接入结果项")`（`ImageInfoRow.cs:15-29`），**不 Fail**。
- 发布/烧录的 `try/catch` 里**必须 Warn，不许空 catch**（对照 `ImageCollectionService.cs:360` 的"绝不能静默"；`Plugin.GeometryFinder\GeometryFinderPlugin.cs:247` 那个空 catch 是反面教材，本轮顺手修，见 §7.10-1）。
- 报错文案按 R34「宽进严出」：能转就转，转不了把**被拒的原类型与原值**写进消息。

### 6.4 配置生命周期（三个必须照抄的顺序，与 v3 相同）
1. `ApplyConfigValues`：**先 `base.ApplyConfigValues(stepData)` 再 `RebuildDynamicInputs()`**（编译期必须先于 `LinkPorts`，`Engine\FlowCompiler.cs:784,852-854`；范式 `ResultUploadPlugin.cs:209-214`）。
2. **动态口手填常量会丢**：`VisionPluginBase.cs:239-249` 遍历 `InputValues` 时动态口尚未创建 → 键既不命中端口也不命中 `_configProps`，直接 `continue`。所以 `RebuildDynamicInputs()` 之后**必须补一遍定向灌值**（只灌"未连线"的动态口，从 `StepData.InputValues` 按 Id 取值）。这是先例里已经存在的坑，断言 A6 钉它。

## 14. 实现口径校正（**落地后与本文的差别，逐条记账**）

> R8：本文是**现行设计文档**，必须与实现一致。凡实现与上文不一致的，**就地改上文**（§4.4 / §8.2-C5 / §8.3 / §8.4 / §8.5 / §11-10 / §12-③ 已改），改不动或需要展开讲理由的记在本章。
> 本章的读法：每条 = 「上文怎么说 → 实现怎么做 → 为什么」。

### 14.1 底图归一化的**归属**变了（§5.1 / §7.5 说在 `DisplayDraw`，实际在共享件）

- **上文**：§5.1 把归一化写成"本插件的第①步"，§7.5 让 `Services\DisplayDraw.cs` 负责"底图归一化 + 类型分派 + 行主口径 + 排版 + 钳制"。
- **实现**：归一化是 **`AnnotationBaker.NormalizeForDisplay(HObject src, List<HObject> temp)`**（`AnnotationBaker.cs:192`，`public static`），由 `Bake` 内部在铺底图前自动调用（`:134`）。`DisplayDraw` **完全不碰像素类型**，只负责建 `BakePlan`。
- **为什么**：迁移四份既有烘焙件之后，如果归一化留在各调用方，同一份"4 通道去 alpha / 单通道非 byte 先线性拉伸"就要复制五遍——**这正是共享件要消灭的东西**。而且 §5.1 那张表里"Caliper 那份残缺会死白"的分歧，只有把归一化收进唯一一处才治得了根（见 §14.7）。

### 14.2 `Cross` 的 `P` 长度是 **2 或 3**，不是 §8.2-A4 写的固定 2

`AnnotationBaker.cs:305-318`：`P.Length==3` → `(row,col,size)`；`==2` → `(row,col)` 用默认 size；其它长度 → Warn「Cross 参数个数非法（N，应为 2 或 3），已跳过」。`DisplayDraw.cs:236,264` 走的是 **3**（带 `crossSize`）。A4 断言按"2 或 3 都合法"判。

### 14.3 `Ellipse` 的角度有**两处**变换，各归各家，不许合并

1. **度 → 弧度**：`BakeShape.P[2]` 的口径是**度**，`AnnotationBaker.cs:301-302` 内部 `p[2] * Math.PI / 180.0` 后才交给 `DispEllipse`。
2. **符号取反**：`DisplayDraw.cs:282-283` 传的是 **`-g.Phi`**。

**为什么第 2 条必须存在**：本仓 `GeometryParam.Phi` 的定义是 `atan2(dr, dc)`（`GeometryHService.cs:63-67`），方向向量 `(sin φ, cos φ)`（**行主**）；HALCON 的 `gen_ellipse` / `disp_ellipse` 的 `Phi` 是"自列轴逆时针"，在"行向下"的图像系里等价于方向向量 `(−sin Phi, cos Phi)`。同口径也用于 `Plugin.CreateRoi\CreateRoiPlugin.cs:881`（直接把 phi 交给 `GenEllipse`）。
**分工**：度→弧度是**烘焙件**的职责（它对接 HALCON），取反是**上游角度定义**的职责（它对接本仓的 `GeometryParam`）。合到一处就会在下一个调用方身上再错一次。

### 14.4 §4.4 是 **6 列**、且容器是 `ItemsControl` 不是 `GridView`

已就地改上文。补一条纪律：本视图**不要"顺手统一"成 `ListView + GridView`**——那会立刻掉进 AGENTS.md 第 6 节那个 Fluent 隐式样式顶掉列头的坑（R19~R22）。手写表头的代价是"改列宽要同时改 `:85-92`（表头）与 `:123-130`（数据行）两处 `ColumnDefinitions`"，收益是零资源依赖、断言宿主里直接 `new` 就能渲染。

### 14.5 用户连进来的 `HRegion` / `HXLD` **不抽稀**（§5.7 的元素上限只管点集）

- `ThinPoints`（`DisplayDraw.cs:340`）只用于**一条**通路：上游给的是 `double[]` 点集、本插件自己 `GenContourPolygonXld` 造 XLD（`:323`，首末点必留，否则轮廓开口）。
- 用户直接连过来的 `HRegion` / `HXLD` 走 `DrawHalconObject`，**原样**进 `plan.Objects`，不抽稀、不简化、不裁剪。
- **为什么**：改用户的几何对象 = 改检测结果。显示算子没这个权力；点数太多导致的节拍问题由 `MaxDrawElements`（元素**条数**上限）与 §1.2 的 dump 成本一起兜，不在几何层面动刀。

### 14.6 `box` 参数之争由 **B2 实测终结**，结论要修正

- **上文 §5.2-5**：「只给 `box_color` **画不出底色框**」（照 `Caliper\AnnotationRenderer.cs:94-95` 的注释）。
- **实测**：`ImageScript\HDevDisplayBackend.cs:514-518` 的量化数据是「**box 默认就是开的**（18303px vs 3754px）」。B2 又把两头钉死：显式 `Box:true` → `band min=0 max=255`（有白框）；显式 `Box:false` → `band min=0 max=100`（只有黑字与灰底）。
- **修正后的口径**：Blob 那份的问题**不是"画不出框"，而是"把决定权交给了默认值"**——`box` 不给就是随 HALCON 版本/窗口类型而变。所以 `BakeText` 把 `Box` 做成 **record struct 的位置参数（必填）**，不是可选参数：编译期就不可能漏。
- ⚠ **命名坑**：位置参数是 **`Box`（大写 B）**，而 `BakePlan.AddTextBlock(..., bool box)` 的方法参数是 `box`（小写）。写 `new BakeText(..., box: false)` → **CS1739**「`BakeText` 的最佳重载没有名为 `box` 的参数」（本轮真踩，`Plugin.BlobDetect\AnnotationRenderer.cs:84`）。

### 14.7 底图归一化的分歧（Blob 完整 / Caliper 残缺）已裁定并**删除重复实现**

以 Blob 的完整版为准，落在 `NormalizeForDisplay`。因此删掉了两个方法（它们是 baker 那份的逐字重复）：
- `Plugin.CaliperMeasure\CaliperMeasurePlugin.cs` 的 `private static HObject BuildDisplayBase(HImage src, List<HObject> temp)`（原 `:1710`）——就是"只有一行 `ConvertImageType`、12/16 位死白"那份；
- `Plugin.BlobDetect\BlobDetectPlugin.cs` 的 `private HObject BuildDisplayBase(...)`（原 `:1875`）与 `private static HObject DropAlphaChannel(...)`（原 `:1929`）。

两处调用点改为**直接把 `src` 交给 `Render`**（`CaliperMeasurePlugin.cs:1242`、`BlobDetectPlugin.cs:1785` 各留一行注释指明归一化是烘焙件的职责）。

### 14.8 迁移**改了一层图层顺序**（BlobDetect）——这是行为变更，不是 bug

`AnnotationBaker.Bake` 的绘制顺序是**固定的**：`DrawShapes → DrawObjects → DrawTexts`（`AnnotationBaker.cs:148-150`）。Blob 原来是"先画缺陷号、再画黄色高亮框"，迁移后**缺陷号在高亮框之上**（数字更清楚）。已记在新的 `Plugin.BlobDetect\AnnotationRenderer.cs` 注释里。
**为什么顺序要固定**：不固定就等于"每个调用方自己决定谁压谁"，那 §5.2-3 的 `SetPart`、`SetLineWidth`/`SetDraw` 还原这些**窗口级状态纪律**就没法只写一遍。要改层序就改 plan 里的入列顺序，不要改 baker。

### 14.10 `JudgeItemLabels` 的实现口径（§4.4 只说"候选 = 启用项的 Label"）

`ResultDisplayPlugin.cs:341` 返回 **`IReadOnlyList<string>`**，内容 = **前导 `""`（= 不判定）** + 启用项的 `Label` + **当前判定值**（若它已不在启用项里——否则下拉框会显示空白，用户以为设置丢了）。刷新走 `RefreshJudgeItemLabels()`（`:364`）→ `OnPropertyChanged(nameof(JudgeItemLabels))`；**每次 `RebuildDynamicInputs()` 之后都要跟着调一次**（`:119-120`、`:308-309`、`:319-320`）。
⚠ **R35 适用**：这是可编辑 `ComboBox` 的候选集合，重填前必须先记住端口里的值、重填后顶回去，否则 `ItemsSource.Clear()` 会沿 TwoWay 把空串推回端口（"选个判定项→加一行结果项"就静默清了判定）。

### 14.11 `IsNg` 的口径（§6.3 只说"报错带被拒原值"）

`DisplayDraw.cs:422-480`：
- `bool` 值接受 **`NG` / `OK` / `1` / `0`** 四种写法（现场习惯不统一，硬要一种写法就是逼用户改配置）；
- 数值一律 **`NumberStyles.Float` + `CultureInfo.InvariantCulture`**。
- ⚠ **不能用 `NumberStyles.Any`**：`Any` 含 `AllowThousands`，`"1,5"` 会被读成 **15**——这正是 R34 明令拒绝的那条（默认解析会把 `2,5` 读成 `25`）。
- 所有格式化（`:358-394`）一律 `InvariantCulture`：别让机器的区域设置改显示结果。数值默认 `0.####`（最多 4 位小数、不留末尾 0）。

### 14.12 `OnConfirm` 的污染清理**遍历端口面**，不是配置面

```csharp
foreach (var port in Inputs.Values)                      // ← 端口面
{
    if (!stepData.InputValues.TryGetValue(port.Name, out var v)) continue;
```

### 14.17 ★ 2026-10-14「文字位置」落地记：一次**分工**决定的实现，不是"加三个配置项"

起因是用户一句"你的显示插件 没办法控制文字的位置吗"。AskUserQuestion 给了四档，用户**只点**了"九宫格锚点 + 边距 + 字号"，明确落选"几何标签偏移可调""逐项归一化坐标""先不做"（→ 已写进 §2 N8 与 D7 校正）。真正的实现难点不在"加三个 `[StepConfig]`"，在下面五条：

1. **水平对齐必须下沉到烘焙件**（这是本节的核心结论）。文字像素宽度取决于**窗口当前字体**，而只有 `AnnotationBaker` 持有窗口（静态扫描 ④c 明令插件零 `OpenWindow`/`SetPart`）。调用方要么"估宽"（等宽字体也有小数点/负号/中文的差异，估必歪），要么"只能贴左"。所以能力做在 baker：`BakeText` 加 `HAlign`（`Left`/`Center`/`Right`），**`Col` 的含义随它变成"左边缘/中心/右边缘"**，baker 在 `TrySetFont(win, size)` **之后**调 `HOperatorSet.GetStringExtents(win, text, out _, out _, out width, out _)` 量宽再换算，并夹回 `[0, w-1]`（量不到就退回左对齐 + 一条 warn，宁可贴边也不许整行出画布）。已升格为 AGENTS.md **R39**。
   ⚠ 本仓**没有** `GetTextExtents`，能用的名字是 `GetStringExtents`（反射核对过签名）。
2. **垂直锚点必须留在 `DisplayDraw`**：九宫格那"一行三列"里的**行**要的是"整块文字多高"，而块高 = 行数 × 行距，行数要到类型分派 + 元素预算 `Take()` 走完才知道。于是排版改成**两遍**：堆叠文字先攒进 `Ctx._stack`，`Build` 末尾 `ctx.EmitStack()` 一次性按锚点落位。
   **为什么这样安全**：烘焙件按**类别**画（`Shapes → Objects → Texts`，`AnnotationBaker.cs:148-150`，R37 定死的层序），所以"文字晚一点进 `Texts`"不会改变图形与文字的先后。**副作用记在这里**：堆叠文字现在排在**几何标签之后**进 `Texts`，也就是文字块会压在几何标签上面（原先两者按插入顺序混排）。要改层序只能改 plan 的入列顺序，**不要去改 baker**。
3. **兼容做法：`init` 属性而不是新增位置参数**。`public readonly record struct BakeText(...) { public BakeHAlign HAlign { get; init; } = BakeHAlign.Left; }`——四个已迁插件的 `new BakeText(...)` 一处都不改就得到 `Left`（= 历史行为）。`DisplayDraw.Build` 的三个新参同理**全部可选**。这个"默认即老行为"不是口头保证，是两条断言：U1（plan 层，`SameTexts` 逐条比七个字段）+ B8（像素层，"默认"与"显式 Left"墨迹盒同位 ±4px）。
4. **枚举成员顺序是承重的**：`EmitStack` 用 `(int)Anchor / 3` 取带、`% 3` 取列，所以 `TextAnchorKind` 必须**行主序**且显式赋值 0~8；`TextAnchorKind.cs` 顶部写着这句警告，守门人是静态扫描 **⑦**（正则抽 `[Display(Name="…")] 成员 = 值`，比顺序、比值、比九个中文名）与 **⑦b**（确认 `/3`、`%3` 还在用）。这类"改了顺序照样编过、照样跑，只是画面全错位"的静默回归，类型系统和运行期都不报错，只有静态扫描抓得到。
5. **`[StepConfig]` 三项全走 partial + 钩子**（R18）：`OnTextAnchorChanging` 夹非枚举值回落 `TopLeft`、`OnTextMarginChanging` 夹 `0~4096`（**0 是语义值**"用自动边距"，不是笔误）、`OnTextScaleChanging` 夹 `0.5~3.0` 且非 finite 回落 1.0。`.vms` 是可手改的 JSON，运行期收到的数可以毫无道理（U9 实测灌 `(TextAnchorKind)99 / 99999 / NaN` → `anchor=TopLeft margin=4096 scale=1`）。

**两条本轮自己的踩坑（写出来防复发）**：
- **XAML 属性值里不许出现 ASCII 双引号**：提示文案写成 `Text="只搬"数值/文本"那一块…"` 直接把属性截断、`XamlParseException`。中文提示里要用**全角 “ ”**。
- **断言 bug 也会长得像产品 bug**：U5 第一版拿 `MiddleCenter` 的 `Col`（= `W/2` = 200）去和"自动边距"（12）比，报"margin=0 与自动同值 → 0→200，自动→12"。当时差点去改 `EmitStack`。正解是**在同一片坐标系里比**：`SameTexts(TopLeft, margin=0)` vs `SameTexts(TopLeft, margin=autoMargin)`。**先怀疑尺子，再怀疑产品**。

**演示方案为什么仍留在默认 `TopLeft`**：两条像素断言把采样带**写死在左上角**——`ResultDisplayCheck.cs:395`（白底框 `BandMax(8..40, 8..200) ≥240`）与 C5 的 `DiffAreaInBand(产物, 底图, 8,8 → 120,400)`（`:1501`）。把演示方案的锚点改成右下，这两条会立刻变红——那**不是回归，是断言写死了位置**。本轮选择"不动这两条、演示方案保持默认"，新能力另由 B8（像素层对齐）+ U1~U9（plan 层锚点，含 U8 真执行右下带）覆盖。**下次真要演示九宫格，就把这两条的采样带跟着锚点挪**，不要新加一条像素断言了事（两条断言互打就是假绿源）。
