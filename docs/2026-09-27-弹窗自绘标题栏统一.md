# 2026-09-27 弹窗标题栏统一：去掉系统窗框，改自绘

起因：用户发来"变量管理"弹窗的截图说"**这种窗口栏太古老了 不美观**"。
截图里是一条 Windows 经典样式的系统标题栏（灰蓝底 + 最小化/最大化/关闭），
而仓库里其它弹窗早已是自绘标题栏 —— 两者同屏切换像两个软件。

---

## 1. 盘点：17 个弹窗里漏了 5 个

对 `VisionMaster/Views/DialogViews/*.xaml` 全量扫一遍"有没有 `WindowStyle="None"`"：

| 状态 | 弹窗 |
| --- | --- |
| 已自绘（12 个） | PluginConfigShellView、ScanGroupEditorView、VariableBindingView、Scada 系列 8 个 |
| **仍是系统窗框（5 个）** | **GlobalVariableView（变量管理）**、**CameraSettingsView（相机设置）**、**CommunicationSettingsView（通讯设置）**、ConditionEditorView（条件逻辑配置中心）、FlowManagerView（流程管理） |

其中 `SolutionListView` 虽然在这个目录里，但它是嵌在 Shell 中的普通视图（没有 `prism:Dialog.WindowStyle`），
所以不在"弹窗"范围内 —— 断言里也据此排除。

### 有一处是"有意的选择"，不是漏网

`CommunicationSettingsView.xaml` 原来写着：

> （与 PluginConfigShellView 同一范式；**区别是这里保留系统标题栏，不设 WindowStyle=None**）

这是当初的取舍。本次按用户诉求改掉，并把那句注释一并更新 ——
**留着它就会和改后的实现自相矛盾**，后来人看到"这里保留系统标题栏"却找不到系统标题栏。

## 2. 改了什么

对三个弹窗（变量管理 / 相机设置 / 通讯设置）做同一套改造：

1. `WindowStyle="None"` —— 去掉系统窗框；
2. 视图顶部加一条**自绘标题栏**（52 高）：栏图标 + `{Binding Title}` + 一句功能说明 + 右侧 ×；
3. 标题栏整条挂 `ui:WindowDragBehavior.IsWindowDraggable="True"`；
4. 右侧 × 绑 VM 的 `CloseCommand`。

### 两个要点

**标题文字绑 `Title` 而不是写死**：系统标题栏去掉之后，视图里这一处就是唯一的标题来源，
写死等于把标题抄成两份（`ScadaUserManagerViewModel` 的注释里也写着"视图标题栏绑它，免得同一个字符串写两遍"）。

**无边框窗口必须自己补两件事**：
- **拖动** —— 系统标题栏没了，就没有任何地方能拖窗口，必须给标题栏挂行为；
- **关闭** —— 系统 × 也一起没了。本弹窗改的是活对象（增删改变量/连接即时生效），
  所以 × 直接走 `CloseCommand`，不做二次确认。

### 顺带发现：三个 VM 早已有 `CloseCommand`

`CameraSettingsViewModel`（line 582）、`CommunicationSettingsViewModel`（line 160）
本来就实现了 `CloseCommand`，只是视图在用系统标题栏、没地方用得上它。
所以这次**一行 VM 代码都没改**（只有 `GlobalVariableManagerViewModel` 需要补，它原来没有）。

## 3. 新增断言：窗框契约（3 条）

写在 `FlowCanvasChecks/VariableBindingCheck.cs` 的视图契约族里，扫 `DialogViews/*.xaml`：

```
[√] 【窗框】所有弹窗都已去掉系统标题栏（改自绘，与青蓝界面统一）→ 共找到 14 个带窗口样式的弹窗；全部自绘
[√] 【窗框】每个弹窗的自绘标题栏都可拖动（无边框窗口没有系统拖动区）
[√] 【窗框】每个弹窗都有关闭入口（标题栏 × 或底部取消/确定，二选一）
```

只检查**带 `prism:Dialog.WindowStyle` 的文件**：目录里还放着嵌在 Shell 中的普通视图（如 `SolutionListView`），
它们没有窗口样式、也不该有标题栏。

### 第三条断言写严了一次

第一版要求"XAML 里必须出现 `CloseCommand`"，结果 7 个弹窗报红 ——
它们其实**都有底部「取消 / 确定」按钮**（`VariableBindingView`、`ScanGroupEditorView`、
`ScadaVariablePickerView` 等），那也是合法的关闭入口。
放宽成"`CloseCommand` 或 `CancelCommand` 或 `ConfirmCommand` 任一"才符合实情：
这条断言要守的是"**关不关得掉**"，不是"必须有 × 按钮"。

## 5. 遗留：还有两个弹窗"不只是标题栏旧"

`ConditionEditorView`（条件逻辑配置中心）与 `FlowManagerView`（流程管理）
**没有 `WindowStyle` 段**，属于更早的一代写法：

- 尺寸写在 UserControl 上（`Width="950" Height="700"`），窗口拉大不会重排；
- 本地定义一堆样式（`PrimaryButton` / `TagButton` / `ActionButtonStyle` / `EncryptButtonStyle`）；
- 颜色是硬编码的 Element 蓝（`#409EFF` / `#66B1FF` / `#3498db` / `#27ae60`）。

也就是说，它们**整个弹窗**都需要收编（不只是窗框）。
本次没有动，理由：只换标题栏会造成"新标题栏 + 旧内容"的新旧混搭，比现在更难看；
而整体收编涉及内容布局重排（`ConditionEditorView` 还嵌着 AvalonEdit 表达式编辑器），要单独排期。
