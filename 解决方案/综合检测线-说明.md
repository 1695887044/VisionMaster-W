# 综合检测线演示方案（综合检测线.vms）

> 方案文件：`解决方案\综合检测线.vms`（3 条流程 / 81 个步骤 / 33 类算子插件）
> 目标：用仓库现有算子把「PLC 触发 → 板卡视觉检测 → 判定 → 分拣 → 计数 → 上报/记账 → 多工位演示」串成一条可运行的完整线体。
> 本版按 2026-10-22 真机运行反馈重构：**只保留 Main 为启用流程**，颜色/卡尺/胶路/码读取四段直接内联，避免“连续运行”把子流程当顶层流程并发跑。

## 2. 流程总览（重要：只有 Main 默认启用）

| 流程 | 角色 | 默认启用 | 调用方式 | 步骤数 | 作用 |
| --- | --- | --- | --- | --- | --- |
| Home | 回原/回零 | **否** | 手动 | 11 | 轴使能 → 回零 → 读轴状态 → 待机位 → IO/PLC 就绪 |
| Main | 主任务 | **是** | HTTP 外部触发（位 64） | 81 | 触发判断 → 2 轮板卡检测 → 颜色/卡尺/胶路/码读取 → 计数 → 并行上报/记账 → 报表 |
| End | 收尾 | **否** | 手动 | 6 | 停轴 → IO 复位 → 清 S7 心跳 → 清就绪 → 延时 |

> **为什么 Home/End 默认禁用**：主界面工具栏的「循环运行」= `RunAllEnabledContinuous()`，它会**并发启动所有启用流程**。Home/End 在运动卡未连接时每轮都报错；禁用后「循环运行」只跑 Main，日志与内存都稳定。
> 需要回零/收尾时：到「流程管理」把 Home/End 勾选启用，先到「系统 → 硬件设置 → 运动卡」手动连接 `ZMotion_Virtual`，再运行（详见 §6）。

## 3. Main 主流程（计划表）

```
读PLC触发 (HoldingRegisters[0], Int16)
└─ 触发判断 (If: Trigger >= 1)
   ├─ If
   │  ├─ 循环检测 (For ×2, Index → 图像采集.FileIndex)
   │  │  ├─ 采集板卡图          (Folder=D:\C#\VM\Image\board)
   │  │  ├─ 图像预处理          (高斯5 + 灰度闭运算5×5 + 锐化7×7/1.2)
   │  │  ├─ ROI圆区域 / ROI小圆区
   │  │  ├─ 找圆 / 找小圆        (几何查找：Circle, Tukey)
   │  │  ├─ 两圆心距            (几何计算：CircleRelation, mm/px=0.05)
   │  │  ├─ 跟随ROI             (坐标变换：FollowRoi)
   │  │  ├─ 表面缺陷检测        (Blob：暗目标, MinArea=10, MaxSingle=1000, 缺陷数≤10 判 OK)
   │  │  ├─ 采集批号图 → OCR识别 (工业 0-9A-Z, 实测 11240B)
   │  │  ├─ 缺陷数比较 + OCR文本比较 → 综合判定 (And)
   │  │  ├─ 写当前结果/OCR文本/缺陷数 (运行期变量, 不存在则创建)
   │  │  ├─ 结果显示            (缺陷数 / OCR / 判定 / 两圆心距)
   │  │  ├─ 写PLC结果           (线圈 Coils[2])
   │  │  ├─ 分拣判断 (If: Ok)    ← 两个分支的轴动作默认禁用（未接卡时不报错）
   │  │  │  ├─ If  → X到取料位 → 等待到位 → X回检测位 → 等待到位
   │  │  │  └─ Else→ NG停止 + NG报警灯
   │  │  ├─ 读PLC确认           (HoldingRegisters[1], Int16)
   │  │  └─ 等待PLC确认 (Wait: Ack == 1, 1s, 超时继续)
   │  ├─ 颜色检查段 (7 步)       ← 原「颜色检查」子流程内联
   │  ├─ 卡尺测量段 (15 步)      ← 原「卡尺测量」子流程内联
   │  ├─ 胶路检测段 (3 步)       ← 原「胶路检测」子流程内联
   │  ├─ 码读取段 (4 步)         ← 原「码读取」子流程内联
   │  ├─ 码有内容 / 工位与1 / 工位与2 / 工位综合判定
   │  ├─ 写工位结果 (全局变量 StationOk)
   │  ├─ 工位完成脚本 (C# 脚本，默认禁用)
   │  ├─ 工位结果显示 (5 行)
   │  ├─ 结果计数 (Case: CurrentResult)
   │  │  ├─ True  → OKCount+1 → 转 Int32 → 写 OKCount
   │  │  └─ False → NGCount+1 → 转 Int32 → 写 NGCount
   │  ├─ 写配方到运行时 (RecipeName，供上报 sn 字段)
   │  ├─ 并行收尾 (Parallel, 真并发, 15s 汇合)
   │  │  ├─ 上报MES (OnTrigger，触发=false，默认不发)
   │  │  └─ CSV记录 (D:\Records\{StepName}\{yyyy-MM}\)
   │  ├─ 导出Excel报表 (Manual)
   │  └─ 循环节拍 (Delay 500ms)
   └─ Else → 空闲延时 200ms
```

### 3.1 判定口径

| 项 | 口径 |
| --- | --- |
| 缺陷数 | `DefectCount <= 10`（板卡样例实测 7~8 个） |
| OCR | `Count > 0`（实测 `11240B`，6 字符，置信 0.95） |
| 综合 | 缺陷 OK **且** OCR 有文本 |
| 分拣 | 综合为真 → X 轴取料位/回位；为假 → 减速停 + NG 报警灯（**轴动作默认禁用**） |

## 5. 通讯 / 变量 / 运动

### 5.1 通讯连接

| 连接 | 协议 | 地址 | 字序/CPU |
| --- | --- | --- | --- |
| PLC_Modbus | Modbus TCP | 127.0.0.1:503 | ABCD（`ByteoRDER=0`） |
| Meter_Modbus | Modbus TCP | 127.0.0.1:504 | CDAB（`ByteoRDER=3`） |
| PLC_S7 | Siemens S7 | 127.0.0.1:102 | S7-1200, Rack=0, Slot=0 |

### 5.2 网络变量

| 变量 | 连接 | 区域/地址 | 类型 | 用途 |
| --- | --- | --- | --- | --- |
| PLC_Trigger | PLC_Modbus | HoldingRegisters `x=3;0` | Int16 | 触发计数（写 1 才进检测分支） |
| PLC_Ack | PLC_Modbus | HoldingRegisters `x=3;1` | Int16 | 完成确认（写 1 让 Wait 通过） |
| PLC_Result | PLC_Modbus | **Coils `x=1;2`** | Boolean | 判定结果（线圈） |
| PLC_OKCount | PLC_Modbus | HoldingRegisters `x=3;4` | Int32 | PLC 良品计数（预留） |
| Meter_Value | Meter_Modbus | InputRegisters `x=4;0` | Float | 仪表读数（CDAB） |
| S7_Heartbeat | PLC_S7 | `M0.0` | Boolean | 心跳 |
| S7_Result | PLC_S7 | `DB1.DBW0` | Int16 | 判定字（预留） |
| S7_Ready | PLC_S7 | `M1.0` | Boolean | 就绪（预留） |

> **为什么 PLC_Result 用线圈而不是保持寄存器**：真机实测写 Int32/Int16 到保持寄存器时，通讯层回读镜像会报「读取长度超过最大值」（地址跨度与值长度口径不一致）；改写成 1 位线圈后一次通过，且 Bool 语义最直接。

### 5.3 本地变量（13 个）

`RecipeName`、`CurrentResult`、`OcrText`、`DefectCount`、`StationOk`、`OKCount`、`NGCount`、`TotalCount`、`SystemReady`、`CycleIndex`、`MeasureWidth`、`BarcodeText`、`YieldRate`

- `CurrentResult` / `OcrText` / `DefectCount`：**运行期变量**（`变量赋值` Scope=Runtime，勾选“不存在则创建”），供 Case/CSV/上报读取。
- `OKCount` / `NGCount` / `StationOk` / `BarcodeText` / `SystemReady`：**方案变量**（Scope=Global）。
- 计数写入前先过「类型转换」：`数学计算` 输出 Double，直接写 Int32 变量会报类型不匹配。

### 5.4 运动卡

- 名称 `ZMotion_Virtual`，地址 `127.0.0.1`，驱动 `Plugin.Motion.ZMotion.ZMotionCard`，机型显式写 `VPLC532R`
- 轴：`X`(0) / `Y`(1) / `Z`(2)，脉冲当量 100（1mm = 100 脉冲），软限位 ±500mm（= ±50,000 脉冲）
- 卡参数：默认速度 10mm/s、加速度 100mm/s²、轮询 10ms、命令超时 30s、看门狗 3s
- **注意 1**：宿主只在启动时执行一次 `ConnectAutoStart()`，而方案是在启动之后才加载的，所以 `AutoConnect=true` 不会自动连上；打开方案后需要到「系统 → 硬件设置 → 运动卡」手动点「连接」。
- **注意 2（回零）**：驱动把 `VPLC532R` 标成总线型，`轴回零` 会走 `ZAux_BusCmd_Datum`；你的轴 0~5 上报的是 `Step Encoder`（脉冲型），如果回零失败/超时，改用脉冲回零（需要驱动侧把该机型的 `IsBusType` 改成 false，或给回零加“总线失败回退脉冲”的一行代码）。移动/IO/读状态不受影响。

## 6. 运行前准备

1. **打开方案**：主程序 → 文件 → 打开 → `解决方案\综合检测线.vms`。
2. **让 Main 走检测分支**：把 `PLC_Modbus` 的保持寄存器 0（`PLC_Trigger`）写成 `1`；若为 0 会走 Else 只延时 200ms。
3. **让 Wait 通过**：把保持寄存器 1（`PLC_Ack`）写成 `1`；否则「等待PLC确认」会 1 秒超时（按设计继续执行并留 ERR 日志）。
4. **运动卡**：需要 Home/End 或分拣轴动作时，先手动连接 `ZMotion_Virtual`，再到流程管理启用 Home/End、并启用 Main 里「分拣判断」两个分支的轴步骤（它们默认 `IsDisEnable=true`）。
5. **MES 地址**：`上报MES` 的 URL 是占位 `http://127.0.0.1:19001/api/inspect`，且 `SendTiming=OnTrigger` + 触发=false，默认不发；要启用时改 URL、把「上报触发」置 true。
6. **Excel**：`导出Excel报表` 是 `Manual`，需要时在配置面板点「立即导出」；CSV 已由 `CSV记录` 每轮写入 `D:\Records\{流程.步骤}\{yyyy-MM}\{yyyy-MM-dd}.csv`。
7. **C# 脚本**：`工位完成脚本` 默认 `IsDisEnable=true`。Roslyn 每次运行都会编译脚本，连续运行下是内存增长源；需要时再启用。
8. **图片路径**：方案里全部是绝对路径 `D:\C#\VM\Image\...`；换机器时改各「图像采集」步骤的路径。

## 8. 本次真机问题的根因与修法

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 内存涨到 7 GB、日志 20 MB、循环像卡死 | 主界面「循环运行」= `RunAllEnabledContinuous()`，会并发跑**所有启用流程**；8 条流程全启用 → 4 个子流程既被顶层跑、又被 Main 的「调用流程」调用 → “正在运行中”风暴 + 图像集/日志暴涨 | 子流程内联进 Main；删除 4 条子流程；Home/End 默认禁用；Main 末尾加 500ms 循环节拍 |
| `本地变量 SystemReady/StationOk/BarcodeText 不存在` | `变量赋值` Scope=Runtime 写的是运行期变量池，而方案变量在 Workspace.GlobalVariables | 方案变量改 Scope=Global；CurrentResult/OcrText/DefectCount 用 Runtime + “不存在则创建” |
| `NGCount 类型是 Int32，无法写入 Double` | 数学计算输出 Double，直接写 Int32 变量 | 计数后加「类型转换」到 Int32 |
| `PLC_Result 写入失败：读取长度超过最大值` | 保持寄存器地址跨度与 Int32/Int16 值长度口径不一致 | `PLC_Result` 改成 **Boolean 线圈 Coils[2]**，直接写 Bool |
| `PLC_Ack` 读到 0 / 类型警告 | `PLC_Ack` 声明 Int32 但地址是 Int16（2 字节），通讯层改用单读 | 变量类型改 `System.Int16`，与 `DataValueType=Int16` 对齐 |
| 运动卡一直“未连接” | 宿主只在启动时 `ConnectAutoStart()`，方案加载在其后 | 打开方案后手动连接；Home/End 与分拣轴步骤默认禁用，避免刷错 |
