# 自动化产线（自动化产线.vms）

> 方案文件：`解决方案\自动化产线.vms`
> 规模：**14 条流程 / 315 步 / 51 个变量 / 8 页组态 / 95 个图元**
> 定位：9 工位自动化线；Main 单流程调度，工位全部是子程序；支持 A/B/C 产品路由、返修、故障停线。

---

## 1. 产线拓扑

```text
PLC 触发
  └─ Main（Role=Main，唯一被工具栏循环的流程）
       ├─ St1_Load        上料 / 夹紧 / 载具二维码
       ├─ St2_Align       视觉定位 / 坐标补偿
       ├─ St3_Assemble    Z 压装 / 拧紧 / 扭矩
       ├─ St4_Dimension   5 种卡尺 + 圆关系，A/B/C 配方
       ├─ St5_Surface     Blob + 颜色线序 + 区域颜色（工位内并行）
       ├─ St6_Trace       OCR + 二维码 + 胶路
       ├─ St7_Function    仪表阈值 + S7 回读
       ├─ St8_Sort        OK / NG 分拣
       ├─ St9_Unload      下料 / 贴标 / 夹具复位
       └─ St10_Rework     返修机械复位（最多 2 轮）
```

工位全部 `Role=None + 子程序`；工具栏「循环主流程」只启动 Main，不会误启动工位。

## 4. Main 节拍

```text
读 PLC_Trigger
If Trigger != 1 → 空闲延时 200ms → Return
If LineFault → 延时 500ms → Return

CycleCount++
St1 → St2 → St3
For 2 轮：
    St4 → St5 → St6 → St7
    ProductOk = St4_Ok && St5_Ok && St6_Ok && St7_Ok
    If ProductOk → Break
    St10_Rework
FinalOk = ProductOk
St8_Sort → St9_Unload
写 PLC_Result / PLC_Ack / PLC_Alarm / PLC_CycleCount
CSV 记录 → 节拍延时 500ms
```

设备故障与产品 NG 分开：

- `RunFlow.Invoked=false` → 设备故障：停 X/Y/Z、写 `PLC_Alarm`、`LineFault=true`、`Return`；
- `Invoked=true` 但 `StX_Ok=false` → 产品 NG：继续返修/分拣，不停线。

## 5. 工位设计

### St1 上料
- X/Y/Z 到 0；夹紧 IO0、真空 IO1。
- 读载具 QR → `CarrierId`；`St1_Ok = Count>0`。

### St2 定位
- `board-01.png` → 预处理 → ROI → 找圆 → 跟随 ROI。
- 找到圆：`St2_Ok=true`，X/Y 补偿 5mm；否则 `St2_Ok=false`。

### St3 装配
- Z→5mm，拧紧 IO2 保持 300ms，Z→0。
- 读 `Meter_Value` 作为扭矩，≤80 → `St3_Ok=true`。

### St4 尺寸
- A：40/240/200/200/90°；B：41/241/201/201/90.5°；C：宽度+圆直径。
- `CaseStep` 按 `ProductTypeCode` 分支；每支跑对应卡尺并写 `St4_Ok`/`St4_Message`。

### St5 表面/颜色（工位内并行）
- 先顺序采集板卡图、颜色图。
- `Parallel` 三分支：Blob 缺陷 / 颜色线序 / 区域颜色；只用 `[ParallelSafe]` 插件。
- 汇合后 `DefectCount<=10 && ColorSeqOk && ColorRegionOk` → `St5_Ok`。

### St6 追溯
- OCR `lot_number_01.png` → 期望 `11240B`。
- QR `qr_workpiece_01.png` → 期望 `12345678901234567890`。
- 胶路 `adhesive_bead_01.png`，31 点中心线，错误段=0。
- `St6_Ok = OCR有文本 && QR有内容 && 胶路IsOk`。

### St7 功能
- 读仪表 ≤80；写 `S7_Result=7` 回读；`St7_Ok` 由仪表阈值决定。

### St8 分拣
- `FinalOk=true`：X200/Y10、真空释放、OKCount++、`SortBin=OK`。
- `FinalOk=false`：X200/Y-10、IO3 剔除、NGCount++、`SortBin=NG`。

### St9 下料
- X220/Y0/Z0；贴标 IO4 脉冲；松开夹具/真空；`St9_Ok=true`。

### St10 返修
- 松夹具 → X150/Y0 → 重新夹紧；`ReworkDone=true`。

## 7. 验证

- **编译**：14 条流程全部 `COMPLEX-FLOW-OK`，`COMPLEX-RESULT: ALL_OK`。
- **组态**：8 页 `_ScadaUiProbe --solution` 全部 `RESULT: OK`，无 XAML 解析异常。
- **真机 exe**：加载方案后 HTTP `Main` 返回 **200**；但本次运行时 **PLC 503/504、S7 102、ZMotion 502 均未启动**（日志：`PLC_Modbus` 离线、ZMotion 20008），因此 Main 走了“读触发失败 → 空闲”的分支，**没有完成一次真实 9 工位节拍**。
- 端到端验证需要在设备模拟器/虚拟卡启动后，把 `PLC_Trigger` 写 1 再触发 Main。

## 8. 运行前准备

1. 启动 ZMotion 虚拟卡（127.0.0.1:502）、Modbus 503/504、S7 102。
2. 打开 `自动化产线.vms`，确认三张通讯连接在线、运动卡在线。
3. 写 `PLC_Trigger=1`（Holding `x=3;0`）。
4. 组态「产线总览」点「运行整线」，或 HTTP：

```powershell
curl.exe -s -o NUL -w "%{http_code}" --max-time 180 `
  -X POST -H "Authorization: Bearer visionmaster" `
  -H "X-Image-Name: board-01.png" `
  --data-binary "@D:\C#\VM\Image\board\board-01.png" `
  http://127.0.0.1:19000/flow/Main
```

5. 产品类型由 `ProductTypeCode` 控制：1=A 全检、2=B 全检、3=C 简化尺寸；可在「尺寸检测」页查看。
6. 故障后到「报警与统计」点「复位」（写 `LineFault=false`、`LineReset=true`）。

## 9. 已知边界

| 项 | 说明 |
| --- | --- |
| 设备离线 | 本次运行环境未启动 502/503/504/102，端到端节拍未验证 |
| 虚拟卡到位 | 工位用 `Delay` 模拟到位；接真卡后可换「等待到位」 |
| 返修 | `For` 最多 2 轮；超过 2 轮直接按 NG 分拣，不再返修 |
| 超时 | `RunFlow` 超时不会停止子流程；产线需要“超时也停”时后续加 `StopOnTimeout` |
| 并行 | 只有 St5 的视觉分支并行；工位级串行，`RunFlow` 未标 `ParallelSafe` |
| 配方 | A/B/C 只影响 St4 的卡尺标准；St5/St6 阈值共用 |
| 图像集 | 每节拍约 9 张图；图像集 300 帧上限约 30 节拍后开始覆盖 |
| 良率 | 按 `OKCount/(OKCount+NGCount)*100` 计算；总数为 0 时由数学插件处理 |
