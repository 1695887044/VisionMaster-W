# 立刻读

> 分类：通讯 ｜ 来源：插件 Plugin.Comm

对通讯变量执行**插队读**：跳过常规读写队列与轮询，立即从设备读取当前值。
本页讲定位与上手；端口字典看「端口与参数」，按现象找原因看「排障」。

## 什么时候用它

普通读（变量连线、变量管理里的当前值、组态画面绑定）拿的是**最近一次轮询到**的值。
轮询周期可能是 100ms，也可能是 10s；如果流程在这一拍之间需要"设备此刻到底是多少"，
普通读给不了答案。

「立刻读」就是为这一瞬间准备的：

- 上料前确认安全门/急停位是否真的为 ON；
- 写了一个设定值之后，立刻回读确认设备确实收到了；
- 流程分支要根据某个联锁点的**当前**状态做判断，不能等下一拍；
- 设备被外部改动后，需要马上刷新变量镜像。

**不该用它的事**：

- 高频连续读同一个变量（那是在用插队队列替代轮询，会把通讯层打满；该调快扫描组）；
- 读一个本来就在当前拍里读到的变量（普通连线更便宜）；
- 需要"读-改-写"原子性（读和写是两条独立命令，中间设备可能变化）。

## 原理一句话

它走通讯层的**最高优先级车道之一**，并在轮询的段与段之间让路：

```
常规写 → 常规读 → 轮询段 ...        ← 插队读到达
常规写 → 常规读 → 轮询段（让路）→ 插队读 → 轮询段继续
```

它不会打断正在执行的设备事务（半包读会让协议解析错位），
但也不用等完整一轮轮询，更不用排在普通读/写后面。

## 三步上手

```
① 工具箱（分组「通讯」）拖出「立刻读」，放在需要"当前值"的位置。
② 双击节点 → 面板上只有一行「通讯变量名（插队读）」。
   点右侧下拉，从当前方案的通讯变量里选一个（显示为「名字（类型 · 连接名）」）。
③ 把 Value / ValueText 接到下游：Value 是工程值（类型 = 变量声明类型），
   ValueText 是给人看的文本（byte[] 为十六进制）。
```

变量名下拉只列**能真正读**的变量：缺连接名/地址的变量不会出现。
如果下拉是空的，先去「变量管理」里建好网络变量并配好连接与地址。

## 端口分工

| 端口 | 方向 | 类型 | 默认 | 一句话 |
| --- | --- | --- | --- | --- |
| `VariableName` | 输入 | `string` | 空 | 要读的通讯变量名，只能从方案候选里选 |
| `Value` | 输出 | `object` | 空 | 读到的工程值（已按地址配置做缩放/偏移） |
| `ValueText` | 输出 | `string` | 空 | 值的文本表示；`byte[]` 为十六进制 |
| `TypeName` | 输出 | `string` | 空 | 变量声明类型短名（`Int32` / `Boolean` / `String`…） |
| `ConnectionName` | 输出 | `string` | 空 | 变量所属连接名 |
| `ElapsedMs` | 输出 | `double` | 0 | 从发起到设备返回的耗时（含插队排队） |
| `Success` | 输出 | `bool` | — | 是否读到（基类端口） |
| `ErrorMessage` | 输出 | `string` | 空 | 失败原因（基类端口） |

本插件没有自定义配置视图，走宿主自动生成的参数面板（只列输入端口）。

## 结果怎么读

- **成功**：`Success=true`，`Value` 有值，`ElapsedMs` 是真实往返耗时；
  日志一条 `实例名 立刻读 变量 = 值（x.x ms）`。
- **失败**：`Success=false`，`ErrorMessage` 是可读的中文原因（变量不存在、连接离线、
  队列已满、设备读失败等）；日志一条错误。
- **读到的值与上次轮询一样**：正常。变量镜像不会因此变化，但 `Value` 仍是这次读到的值。
- **设备侧值在两次读之间变化**：以本次 `Value` 为准；它是发出命令之后设备返回的那一帧。

## 与普通读的区别

| | 普通读（连线/轮询镜像） | 立刻读 |
| --- | --- | --- |
| 数据来源 | 最近一次轮询结果 | 本次设备往返 |
| 延迟 | 取决于扫描组周期 | 一个设备往返 + 插队排队 |
| 是否占用通讯 | 不额外占用（已在轮询里） | 占用一次插队事务 |
| 典型用途 | 常规判断、显示、记录 | 联锁确认、写后回读、外部改动后刷新 |
