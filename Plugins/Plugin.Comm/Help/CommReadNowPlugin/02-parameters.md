# 立刻读 · 端口与参数

> 分类：通讯 ｜ 来源：插件 Plugin.Comm

本页是「立刻读」的端口字典：每个端口的方向、类型、默认值、必填口径与候选来源。
参数只有输入端口，没有 `[StepConfig]` 配置属性——原因见文末。

## 输入端口

### `VariableName`（通讯变量名）

| 项 | 值 |
| --- | --- |
| 方向 | 输入 |
| 类型 | `string` |
| 默认值 | 空字符串 |
| 必填 | 否（`IsRequired=false`） |
| 候选 | 当前方案的通讯变量（`StepConfigOptionKind.CommunicationVariableName`） |
| 写法 | 只能从下拉里选；不提供 🔗（名字类端口不接受上游值） |

下拉项的显示文本是 `变量名（类型 · 连接名）`，例如 `OKCount（Int32 · PLC_1）`。
写进流程的**值仍然是变量名本体**，不是显示文本——显示文本可以改，流程不会因此断链。

候选只包含：

- 在「变量管理」里存在的网络变量；
- 有连接名；
- 有设备地址（`AddressConfig`）。

缺任何一项的变量不会出现在下拉里：选它必然在运行期失败，列出来只会诱导误选。
如果变量刚建好但下拉里没有，检查它的连接名与地址是否已经配好。

### 为什么 `IsRequired=false`

宿主的编译期必填检查只看"这个端口有没有连线"，不看"手填槽位里有没有值"。
`InputPort.IsRequired` 默认是 `true`，若不显式写 `false`，正常用法（手选变量名）
会在编译期报「必填参数 VariableName 未配置」。运行期由插件自己校验空值并给出中文原因。

## 输出端口

### `Value`（工程值）

| 项 | 值 |
| --- | --- |
| 类型 | `object` |
| 含义 | 本次从设备读到的工程值 |

类型是 `object` 而不是某个具体类型，因为变量声明类型是运行期属性（同一个步骤可以读 `Int32`、
`Boolean`、`String`、`byte[]`）。下游的数值比较、条件判断、变量赋值都能直接消费 `object` 端口；
需要显示时优先用 `ValueText`。

工程值换算：如果变量地址配置里启用了缩放/偏移（`EnableConversion=true`），
`Value` 是换算后的工程值，不是设备原始寄存器值。换算规则与轮询读路径完全一致。

### `ValueText`（文本表示）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 含义 | `Value` 的文本形式 |

格式口径：

- `byte[]` → 十六进制，字节之间用空格分隔；
- `bool` → `True` / `False`；
- 数值 → 不变区域性转换（不会因机器区域设置变成逗号小数点）；
- `null` → 空字符串。

它只用于显示/日志/报表，不参与类型判断。下游要做数值运算请用 `Value`。

### `TypeName`（变量声明类型）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 含义 | 变量声明类型短名 |

来自变量管理里的声明类型（`Int32` / `UInt16` / `Boolean` / `String` / `Byte[]` 等）。
读成功但 `Value` 为 `null` 时，`TypeName` 仍会给出声明类型，便于排查"为什么没有值"。

### `ConnectionName`（所属连接）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 含义 | 变量所属连接名 |

用于日志与下游记录。变量被改名/换连接后，这里显示的是**本次解析到**的连接名。

### `ElapsedMs`（耗时）

| 项 | 值 |
| --- | --- |
| 类型 | `double` |
| 单位 | 毫秒 |
| 含义 | 从发起到设备返回的耗时，含插队排队 |

它包含：

1. 在插队队列里的等待；
2. 当前正在执行的设备事务结束；
3. 本次读的往返。

不包含步骤框架的调度开销。现场判断"设备慢不慢"看它；判断"插队有没有生效"也看它
（与普通读对比，插队读应该明显更短）。

## 基类端口

| 端口 | 类型 | 含义 |
| --- | --- | --- |
| `Success` | `bool` | 本次是否读成功 |
| `ErrorMessage` | `string` | 失败原因；成功时为空 |

失败时 `ErrorMessage` 一定有可读内容，禁止静默失败。常见文案见「排障」。

## 没有 `[StepConfig]` 参数

本插件不实现自定义配置视图，宿主会用 `AutoPortConfigView` 渲染参数。
那个面板**只列输入端口**，不渲染 `[StepConfig]` 常量——所以本插件的全部参数都必须是端口。
这不是遗漏，是"没有自定义视图的插件"的硬约束。

## 参数组合示例

| 场景 | 变量 | 下游怎么用 |
| --- | --- | --- |
| 安全门确认 | `SafetyDoorClosed`（`Boolean`） | `Value` 接条件分支；`ValueText` 接日志 |
| 写后回读 | `SpeedSetpoint`（`Int32`） | `Value` 与期望值比较；`ElapsedMs` 记入报表 |
| 外部改动刷新 | `RecipeId`（`String`） | `ValueText` 接显示；`Value` 接变量赋值 |
| 字节串读取 | `BarcodeRaw`（`Byte[]`） | `ValueText` 接日志；`Value` 交脚本解析 |
