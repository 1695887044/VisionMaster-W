# 立刻写

> 分类：通讯 ｜ 来源：插件 Plugin.Comm

对通讯变量执行**插队写**：跳过常规读写队列与轮询，立即把值写入设备。
本页讲定位与上手；端口字典看「端口与参数」，按现象找原因看「排障」。

## 什么时候用它

普通写（变量赋值、变量管理的写值、组态画面写值）走的是**常规写队列**：
它优先于普通读，但要排在已经入队的写命令后面，也要等当前正在执行的设备事务结束。
在多数场景这已经够快；但下面这些场景需要"现在必须下发"：

- 联锁/复位/急停复位这类命令，晚一个轮询周期都可能影响节拍或安全；
- 视觉判定后立刻给 PLC 一个剔除/分拣信号，不能等常规队列；
- 工艺要求"先写设定值，再在同一轮里读回确认"；
- 人工在流程里触发的单点动作，操作员期望"点了就动"。

**不该用它的事**：

- 高频连续写同一个点（用插队队列替代轮询/状态同步会把通讯层打满）；
- 需要"写后一定成功"的确认（本步骤等的是设备回执；若设备只是收下命令、执行失败，
  需要再加「立刻读」回读或看设备报警）；
- 写只读区（离散输入 / S7 输入映像 I）——插件会在发起前拒绝。

## 原理一句话

它走通讯层的**最高优先级车道**（插队写 > 插队读 > 常规写 > 常规读 > 轮询），
并在轮询段与段之间让路：

```
常规写 → 常规读 → 轮询段 ...        ← 插队写到达
常规写 → 常规读 → 轮询段（让路）→ 插队写 → 轮询段继续
```

它不会打断正在执行的设备事务（半包写会让协议解析错位），
但不用等完整一轮轮询，也不用排在普通写后面。

## 三步上手

```
① 工具箱（分组「通讯」）拖出「立刻写」，放在需要"立即下发"的位置。
② 双击节点：
   · 「通讯变量名（插队写）」从下拉里选（只列可写变量，只读区不会出现）；
   · 「值」可以手填常量文本，也可以点 🔗 链接上游结果。
③ 需要确认实际写下去的值，就把 WrittenValue 接到日志/记录节点。
```

## 端口分工

| 端口 | 方向 | 类型 | 默认 | 一句话 |
| --- | --- | --- | --- | --- |
| `VariableName` | 输入 | `string` | 空 | 要写的通讯变量名，只能从可写候选里选 |
| `Value` | 输入 | `object` | 空 | 要写入的值；常量文本或上游链接 |
| `WaitForCompletion` | 输入 | `bool` | `true` | 是否等设备返回；`false` = 只入插队队列立即返回 |
| `WrittenValue` | 输出 | `object` | 空 | 实际写入（或已入队）的工程值 |
| `Completion` | 输出 | `string` | 空 | `Completed`=已等设备返回；`Queued`=只入队未等待 |
| `TypeName` | 输出 | `string` | 空 | 变量声明类型短名 |
| `ConnectionName` | 输出 | `string` | 空 | 变量所属连接名 |
| `ElapsedMs` | 输出 | `double` | 0 | 等待模式=设备往返；入队模式=入队耗时 |
| `Success` | 输出 | `bool` | — | 等待模式=写成功；入队模式=已受理 |
| `ErrorMessage` | 输出 | `string` | 空 | 失败原因（基类端口） |

## 值的解析口径

界面手填的常量永远是**文本**。宿主按目标变量的声明类型解析一次：

| 变量类型 | 填 `21` | 填 `true` | 填 `abc` |
| --- | --- | --- | --- |
| `Int32` | 21 | 失败 | 失败 |
| `Boolean` | 失败 | `true` | 失败 |
| `String` | `"21"` | `"true"` | `"abc"` |

两条硬口径：

- **不变区域性**：换机器/换区域设置，同一个数解析结果一致；
- **数值不许带千分位**：`1,500` 会被拒绝，不会静默读成 1500 以外的值。

如果变量地址配置启用了缩放/偏移（`EnableConversion=true`），
你填的是**工程值**，宿主按 `ConvertToRaw` 换算成设备原始值再下发。

## 同值也写

工业写是**命令**，不是状态赋值：

- 设备侧可能被外部改回同值，"再写一次"有意义；
- 写成功后镜像值同步更新；
- 不自动重试（重试可能重复下发命令）。

## 要不要等设备返回

「是否等待设备返回」默认 `true`：等设备返回成功才算成功，失败会落在本步骤的 `ErrorMessage`。
现场大多数写需要这个确认，不要为了快把默认值改成 `false`。

填 `false` 时：

- 命令只进入**插队写队列**，步骤立即返回；
- `Success=true` 只代表"已受理"，**不代表设备已写入**；
- `Completion=Queued`，`ElapsedMs` 是入队耗时；
- 设备晚到的失败只进日志与通讯错误事件，**无法再改变本步骤结果**；
- 镜像值不会更新（命令还没执行），等下一拍轮询读到设备新值再刷新。

什么时候适合 `false`：复位/置位/分拣脉冲这类"下发即可"的命令，且流程节拍不能被设备往返拖住。
什么时候必须 `true`：写配方/设定值后要立刻回读确认、联锁动作需要知道设备是否接受。

## 结果怎么读

- **成功**：`Success=true`，`WrittenValue` 是实际写入的工程值，`ElapsedMs` 是真实往返耗时；
  日志一条 `实例名 立刻写 变量 = 值（x.x ms）`。
- **失败**：`Success=false`，`ErrorMessage` 是可读中文原因（变量不存在、只读区、离线、
  队列已满、租约冲突、设备写失败等）；日志一条错误。
- **写成功但设备没动**：检查设备是否要求额外的使能/允许位，或该点是否被设备程序覆盖；
  本插件只保证"命令已下发且设备返回成功"。

## 与普通写的区别

| | 普通写（变量赋值/写值） | 立刻写 |
| --- | --- | --- |
| 排队位置 | 常规写队列（写优先于读） | 最高优先级插队写车道 |
| 等待 | 前面已入队的写 + 当前事务 | 当前事务（不能抢占） |
| 轮询让路 | 不参与 | 段间让路 |
| 典型用途 | 常规配方/状态下发 | 联锁、分拣、复位、写后回读 |
