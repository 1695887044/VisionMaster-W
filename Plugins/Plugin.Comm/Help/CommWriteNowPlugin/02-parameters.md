# 立刻写 · 端口与参数

> 分类：通讯 ｜ 来源：插件 Plugin.Comm

本页是「立刻写」的端口字典：方向、类型、默认值、必填口径、候选来源与值的解析规则。
参数只有输入端口，没有 `[StepConfig]` 配置属性——原因见文末。

## 输入端口

### `VariableName`（通讯变量名）

| 项 | 值 |
| --- | --- |
| 方向 | 输入 |
| 类型 | `string` |
| 默认值 | 空字符串 |
| 必填 | 否（`IsRequired=false`） |
| 候选 | 当前方案的**可写**通讯变量（`StepConfigOptionKind.CommunicationWritableVariableName`） |
| 写法 | 只能从下拉里选；不提供 🔗（名字类端口不接受上游值） |

显示文本是 `变量名（类型 · 连接名）`，例如 `SpeedSetpoint（Int32 · PLC_1）`。
写进流程的值仍然是变量名本体。

候选只包含：

- 变量管理里的网络变量；
- 有连接名；
- 有设备地址；
- **不在只读区**（Modbus 离散输入 / S7 输入映像 I 会被排除）。

只读区被排除是刻意的：把它列出来等于递给用户一个"选了必然失败"的选项。
如果某个点确实要写，检查它是否被配到了只读区。

### `Value`（要写入的值）

| 项 | 值 |
| --- | --- |
| 方向 | 输入 |
| 类型 | `object` |
| 默认值 | `null` |
| 必填 | 否（`IsRequired=false`） |
| 来源 | 手填常量文本，或上游链接 |

手填时界面产出的是 `string`，宿主按变量声明类型解析（见下文「值的解析」）。
链接上游时，值可以是数值/布尔/字符串等；类型不兼容会在写入前明确报错。

`null` 不允许写入：插件会报「要写入的值不能为空」。要写空字符串请填 `""`（在界面上
清空输入框通常得到空串，不是 `null`，两者语义不同）。

### `WaitForCompletion`（是否等待设备返回）

| 项 | 值 |
| --- | --- |
| 方向 | 输入 |
| 类型 | `bool` |
| 默认值 | `true` |
| 必填 | 否（`IsRequired=false`） |

- `true`：命令下发后等设备返回；成功才算 `Success=true`，设备失败落 `ErrorMessage`。
- `false`：只进入插队写队列，步骤立即返回；`Success=true` 只代表"已受理"。

这一行在界面上是 **True / False 下拉**（显示为「是（True）」「否（False）」），
**不提供 🔗 链接、也不提供 ✕ 清除**：布尔值不该由上游运行时决定，手输 `true/false`
也容易拼错。默认值必须是 `true`：现场大多数写需要确认，不能让用户因为默认值而失去失败感知。

### 为什么三个输入都是 `IsRequired=false`

宿主的编译期必填检查只看"端口有没有连线"，不看"手填槽位有没有值"。
若保留默认的 `true`，正常用法（手选变量名 + 手填值）会在编译期报
「必填参数 VariableName / Value 未配置」。运行期由插件自己校验并给出中文原因。

## 输出端口

### `WrittenValue`（实际写入的工程值）

| 项 | 值 |
| --- | --- |
| 类型 | `object` |
| 含义 | 真正下发的工程值 |

它与 `Value` 可能不同：手填 `"21"` 而变量是 `Int32` 时，`Value` 是字符串 `"21"`，
`WrittenValue` 是整数 `21`。下游做比较/记录时用 `WrittenValue`。

如果地址配置启用了缩放/偏移，`WrittenValue` 仍是**工程值**（未换算成原始寄存器值）；
换算发生在宿主写链路内部。

### `Completion`（完成方式）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 取值 | `Completed` / `Queued` |

- `Completed`：等待模式，设备已返回成功；
- `Queued`：不等待模式，命令已进入插队写队列，**设备尚未确认**。

下游若要根据"是否真的写进设备"做判断，必须看 `Completion`，不能只看 `Success`：
不等待模式下 `Success=true` 只代表"已受理"。

### `TypeName`（变量声明类型）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 含义 | 变量声明类型短名 |

用于确认"我填的值该按什么类型解析"。变量类型在建变量时确定；改类型后步骤不用改，
但值需要能按新类型解析。

### `ConnectionName`（所属连接）

| 项 | 值 |
| --- | --- |
| 类型 | `string` |
| 含义 | 变量所属连接名 |

用于日志与下游记录。

### `ElapsedMs`（耗时）

| 项 | 值 |
| --- | --- |
| 类型 | `double` |
| 单位 | 毫秒 |
| 含义 | 从发起到设备返回的耗时，含插队排队 |

包含：插队队列等待 + 当前设备事务结束 + 本次写往返。不包含步骤调度开销。

## 基类端口

| 端口 | 类型 | 含义 |
| --- | --- | --- |
| `Success` | `bool` | 本次是否写入成功 |
| `ErrorMessage` | `string` | 失败原因；成功时为空 |

## 值的解析

宿主按目标变量的声明类型解析文本：

| 变量类型 | 能接受的文本 | 例子 |
| --- | --- | --- |
| `Int16` / `Int32` / `Int64` | 十进制整数（可带负号） | `-12`、`21` |
| `UInt16` / `UInt32` / `UInt64` | 非负十进制整数 | `0`、`65535` |
| `Byte` / `SByte` | 对应范围的整数 | `255` |
| `Single` / `Double` / `Decimal` | 小数点用 `.` | `12.5` |
| `Boolean` | `true` / `false`（不区分大小写） | `true` |
| `String` | 任意文本 | `AUTO` |
| `Byte[]` | 不支持文本，请用上游字节数组 | — |

被拒绝的值会原样出现在错误消息里，例如：
`变量 [SpeedSetpoint] 的类型是 Int32，值 [abc] 无法按该类型解析`。

## 写租约

如果变量启用了写租约（默认启用），并行分支同时写同一个输出时，**后写的会被明确拒绝**，
错误消息里带当前持有者（例如 `目标 PLC_1.SpeedSetpoint 正被「flow:Main/...」占用`）。
这是"最后写入者赢"的替代方案：宁可让流程知道冲突，也不让设备偶尔动作错。

- 同一流程/同一 owner 重复写：允许；
- 不同 owner：拒绝；
- 变量上勾了「允许共享写」：不互斥，最后写入者赢。

## 只读区

以下存储区在协议层就是只读的，插件会在发起前拒绝：

- Modbus：离散输入（Discrete Inputs）；
- S7：输入映像 `I`。

错误文案：`变量「X」位于只读存储区（离散输入 / S7 输入映像 I），不能写入`。

## 没有 `[StepConfig]` 参数

本插件不实现自定义配置视图，宿主用 `AutoPortConfigView` 渲染参数。
该面板只列输入端口，不渲染 `[StepConfig]` 常量——所以全部参数都必须是端口。

## 参数组合示例

| 场景 | 变量 | 值来源 |
| --- | --- | --- |
| 视觉分拣信号 | `RejectPulse`（`Boolean`） | 常量 `true` |
| 配方下发 | `RecipeId`（`Int32`） | 上游计算结果 |
| 速度设定 | `SpeedSetpoint`（`Int32`） | 常量 `1500`（工程值） |
| 复位 | `ResetBit`（`Boolean`） | 常量 `true`，下一拍再写 `false` |
