# 可形变模板匹配 · 故障排查

## 1. 快速定位

先看三处：

1. 状态栏文字（`StatusMessage`）；
2. 结果区胶囊（未学习 / 已学习 / 参数已改 / 参考图不存在）；
3. 步骤的 `ErrorMessage` 输出端口。

## 2. 症状 → 原因 → 处理

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 输入图像为空或未初始化 | 上游没图/图未初始化 | 检查上游采集/读取步骤 |
| 模板还没学习 | `TemplateJson` 里 `Model` 为空 | 打开配置界面学习 |
| 模板加载失败（载荷损坏？） | base64 损坏、模型版本不兼容 | 重新学习；必要时换 HALCON 版本重学 |
| 模板是用「X」学的，当前算法是「Y」 | 换算法没重学 | 重新学习，或把算法切回模板对应的算法 |
| 资产「X」的类型是 model，这里需要 template | 资产下拉选错了类型 | 改选模板资产（不是模型资产） |
| 模板资产文件不存在 | 资产文件被移走/未导入 | 在项目资产页重新导入或检查相对路径 |
| 资产「X」已归档，不能用于运行 | 资产被归档 | 在项目资产页恢复后再跑 |
| 读取模板资产失败 | 资产 JSON 损坏/不是形变模板 | 重新导出/导入模板 JSON |
| 模板里没有模型载荷（Model 为空） | 选到了空模板/元数据 JSON | 选学习过的模板，或重新学习 |
| 本地模板文件不存在 | 路径错误；相对路径按宿主程序目录解析 | 改用绝对路径，或把文件放到宿主程序目录下 |
| 未找到目标 | 分数太高/角度缩放范围太窄/ROI 不对 | 降分数、扩范围、检查 ROI |
| ROI 不在参考图内或面积为 0 | 中心/半长填错，或 ROI 在图像外 | 重新填 ROI |
| 学习失败：半长/半宽必须大于 0 | 数值为 0/负 | 填正数 |
| 学习失败：圆半径必须大于 0 | 半径填错 | 填正数 |
| 参考图不存在 | 路径错误/文件被移走 | 检查绝对路径 |
| 参考图载入失败 | 文件损坏/格式不支持 | 换 BMP/JPG/PNG/TIF |
| 平面模式 Row/Column 看起来偏了 | 原点不是 ROI 中心 | 检查掩膜是否非对称；重新学习 |
| `DeformedContours` 数量比命中数大很多 | 它是扁平 XLD 数组，每命中多段 | 不要用 `CountObj` 当 `MatchCount` |
| `RectifiedImages` 为空 | 当前是平面模式，或没有命中 | 切局部模式/检查命中 |
| `HomMat2D` 为空 | 当前是局部模式，或没有命中 | 切平面模式/检查命中 |
| 模型很大、`.vms` 明显变大 | 内嵌模型 base64 仍在方案里 | 选方案资产/本地文件，再点「清除内嵌」 |
| 构建失败、DLL 被占用 | `VisionMaster.exe`/断言宿主在跑 | 只停自己的测试宿主，不要杀用户进程 |
| 改了代码但运行仍旧逻辑 | 没重建插件工程 | 重建插件；`Modules\` 不由宿主带出 |
| 帮助页找不到 | 没重建/没内嵌 | 重建插件；`audit_artifacts.ps1` 核资源数 |

## 3. 学习失败怎么查

按顺序：

1. 参考图能否 `read_image`；
2. 通道数是否 1/3/4（其他通道数不支持）；
3. ROI 是否在图像内、面积 >0；
4. 掩膜 base64 是否能解成区域；
5. `create_*_deformable_model` 的参数是否合法（层数、极性、ScaleRMin/CMin）；
6. `write_deformable_model` 临时文件是否可写；
7. `read_deformable_model` 回读是否成功。

## 4. 运行失败怎么查

1. `Image` 是否连了、是否空图；
2. `Entry.Model` 是否非空；
3. `LearnedAlgorithm` 与 `Algorithm` 是否一致；
4. `read_deformable_model` 是否成功；
5. 查找范围是否合理；
6. HALCON 是否抛异常（看 `ErrorMessage`）。

## 4.1 外部模板来源怎么查

按优先级从高到低查：

1. 状态胶囊显示「方案资产」/「本地模板」时，运行期用的是外部来源，不是内嵌 `TemplateJson`；
2. 方案资产：顶部下拉是否选对；项目资产页里类型是否为模板、状态是否「有效」、文件是否存在；
3. 本地文件：路径是否为绝对路径，或相对宿主程序目录；文件是否为「导出模板 JSON」导出的 `DeformableTemplateEntry`；
4. 资产/文件里的 `LearnedAlgorithm` 是否与上方算法卡片一致；
5. 资产升版或本地文件改动后 `ModelLoadCount` 应增加；同一版本连续帧不应增加。

外部来源读取失败时插件**不会**回退到内嵌模板，避免“看着用的是新资产、实际跑的是旧模型”。

## 5. 分数对不上/位置偏

- 确认插件与参考实现用同一模板、同一 ROI、同一原点；
- 确认 `SetDeformableModelOrigin` 用的是相对重心偏移；
- 平面模式确认 `ProjectiveTransPixel(hom,0,0)` 是参考点，不是绝对 ROI 中心；
- 确认角度单位：界面度、HALCON 弧度；
- 确认没有重复转换（度→弧度只做一次）。

## 6. 轮廓数量对不上

- `DeformedContours` 是扁平 XLD 数组；
- 一个命中可能由几百段组成；
- `MatchCount` 是命中数，`CountObj` 是轮廓段数；
- 如果要按命中分组，需要额外的对应关系；v1 不做。

## 7. 平面模式反推 Row/Column 为 NaN/Inf

- `qw` 接近 0（点在相机后方）；
- 检查 `HomMat2D` 是否为空/长度不足 9；
- 本插件用 `ProjectiveTransPixel`，内部做齐次除法；
- 若自行用 `ProjectiveTransPoint2d`，必须判 `qw` 接近 0 并失败。

## 8. 模型缓存没生效

- 检查 `RuntimeModelSource` 是否等于当前 `Model`；
- 每次重学都会生成新载荷，缓存键变化是正常的；
- 同一载荷连续运行，`ModelLoadCount` 不应增加；
- 换算法会重学，缓存键变化是正常的；
- 方案资产缓存键含 `ContentHash + Version`；资产升版/回滚后应重新加载；
- 本地文件缓存键含路径、文件大小、最后写入时间；文件被覆盖后应重新加载。

## 9. 配置界面不刷新

- 状态胶囊依赖 `IsTemplateCreated` / `IsModelStale`；
- 改创建期参数后应立即变「参数已改」；
- 改查找期参数不应变「参数已改」；
- 如果状态不刷新，先确认改的是 `Entry` 上的属性，而不是视图里的临时副本。

## 10. 帮助与产物

- 帮助文件必须在插件工程 `Help\` 下；
- csproj 必须有 `<EmbeddedResource Include="Help\**\*" />`；
- 改完帮助必须重建插件；
- `audit_artifacts.ps1` 会核 DLL 内嵌资源数 = 磁盘 `.md` 数；
- `HelpProbe` 会核渲染/标题/厚度。

## 11. 断言宿主

- 改断言源码后必须重建再跑，不许 `--no-build`；
- “全部通过”不等于覆盖，要看条数与明细；
- 新断言要做变异反证：改坏→红→还原→绿；
- 对拍失败先看是插件还是参考实现，不要只调容差。
