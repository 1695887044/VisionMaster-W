# 模板匹配

> 分类：定位 ｜ 来源：插件 Plugin.Matching

多模板库 + 配方驱动的形状匹配定位：一个实例 = 一个模板库（上限 20 条），运行时按 `RecipeName` 端口换产品型号，输出**亚像素位姿**与**位姿归一化的图像**，支持旋转 / 缩放搜索与涂抹掩膜编辑。换型号不用改流程、不用改配置——给个配方名就自动切过去。

## 这个算子做什么

- **学习**（界面按钮「创建模板」，方法名 `CreateTemplate`）：在一张良品图上框住"要认的特征"，插件把框内的**边缘特征**（哪里有明暗边界、边界朝哪个方向）做成形状模型，序列化成 base64 随方案存盘；
- **查找**（每帧执行一次）：取上游图、转灰度，在图里找这组特征的组合，给出**中心行/列（亚像素）+ 角度（度）+ 分数（0~1）**，一次可以报多个实例；
- **两样附带产物**：`MeasureImage` 标注图（命中轮廓 + 判定文字，**失败也有**）、`AlignedImage` 位姿归一化图（把目标搬回学习时的位置与 0°，下游固定坐标的算子零改动直接吃）。

## 它比的是"形状"，不是"像素"

| 维度 | 形状匹配（本插件唯一的一条路） | 灰度 / 相关匹配 |
| --- | --- | --- |
| 记的东西 | 框内像素的**梯度**（边缘的位置与方向） | 框内每个像素的**灰度值** |
| 光照变化 | 整体变亮变暗、对比度漂移**照样找得到**（边的相对关系没变） | 亮一点分数就掉，必须重学或补光 |
| 旋转 / 缩放 | 学习时按角度（和缩放）区间**预先烤入变体**，查找即取 | 得自己逐级转，代价高 |
| 适合 | 有清晰边界的工件：丝印、孔位、边角组合、螺栓阵列 | 没有边界、只有明暗斑块的纹理（毛毡、雾面印刷） |

**本插件不提供"灰度/相关匹配"的开关**（没有 `create_ncc_model` 那条链路）。目标几乎没有边时，正确做法是在上游用「图像预处理」把边造出来（直方图均衡 → 二值化，把一块灰度差变成一条硬边界），再交给本算子学；要判**颜色**本身请接「区域颜色检查」`Image` / 「颜色序列检查」`Image`——形状匹配把彩色图一律转灰度后用，彩色信息它不用。

## 原理：只有两阶段，参数也分两半

1. **学习阶段**（创建态）：缩减域 `reduce_domain` → 统一转灰度 → 按梯度阈值筛特征边 → 建金字塔 → **预先算好各旋转（和缩放）变体** → **原点锚定**（在参考图上自己找自己一次，把模型原点补偿到你画的区域中心）→ 存 base64 进条目；
2. **查找阶段**（运行态）：取图转灰度 → 按配方名选条目 → 在条目烤入的角度/缩放区间里搜 → 结果**天然按分数从高到低排序** → 按 `MaxOverlap` 去重 → 端口赋值 → 可选归一化图 → 标注图 → 发布视图。

> **这条分界决定了怎么用**：② 提取参数（角度、角度步长、缩放、梯度阈值、极性、金字塔层数）是**创建态**，改任何一项都必须**重新点「创建模板」**，界面上橙色徽标「参数已改·需重新学习」就是在提醒你；③ 匹配参数（分数下限、匹配数上限、最大重叠、搜索激进度）是**运行态**，改完立即生效、不用重学。

两个决定了"输出坐标怎么读"的设计：**原点锚定在你框的中心**——`Row` / `Column` 就是"你画的那个区域的中心"，矩形 / 圆 / 椭圆三种区域口径一致（HALCON 默认原点与区域中心有 1~2px 系统性偏差，学习时已补偿掉）；**`AlignedImage` 只按最高分那个实例**做刚性变换把目标搬回学习位姿，画幅不变（同幅面输出）、出界填黑，下游按固定坐标画框的算子不用改任何参数。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | 实际必填 | 待定位的图像。源码里标的是可选（配置态可能还没接图），但**运行拿不到图直接判失败**："输入图像为空或未初始化"。1 通道灰度 / 3 通道彩色 / 4 通道 RGBA、BGRA 都吃（内部统一转灰），其它通道数明确报错 |
| `RecipeName` | 否 | 配方名 / 产品型号（字符串）。可接上游变量或上位机写入，也可手填固定名字。**留空或纯空格 = 没给**，此时用「设为默认」的条目；给了名字但库里没有 → 步骤失败并把库里现有的名字列出来 |

`Image` 端口吃**带 domain 的图**：上游接「ROI」插件的 `Domain_ROI名` 输出，HALCON 只在域内搜、域外直接不命中，而**返回的坐标仍是全局坐标**（下游一个都不用换算）——这是最划算的一次提速。

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Score` | double | **最高分实例**的匹配分数（0~1） |
| `Row` / `Column` | double | 最高分实例的中心行 / 列（亚像素，= 你画的区域中心） |
| `Angle` | double | 最高分实例的角度（**度**，不是弧度） |
| `MatchCount` | int | 命中实例数（已按 `MaxOverlap` 去重） |
| `MatchedTemplate` | string | 本帧实际使用的模板名（配方追溯用）。**"未找到目标"这种失败轮它也已经写好**，只有"未知产品 / 模板库为空"时是空串 |
| `Rows` / `Columns` / `Angles` / `Scores` / `Scales` | HTuple | **全部实例**的数组，按分数从高到低、**逐项对齐**（`Rows[i]` 与 `Columns[i]` 指同一个命中）。未启用缩放时 `Scales` 恒为 1，只为保住五个数组一一对应 |
| `MeasureImage` | HImage | 标注图：原图 + 各命中位姿上的模型轮廓（绿）+ 左上角判定文字（白底）。找到 = 绿字两行"匹配 N 个实例，最高分 …" / "位置 … 角度 …"；**没找到也有**：原图 + 红字"未找到目标（要求分数 ≥ …）" |
| `AlignedImage` | HImage | 位姿归一化图像（目标在标准位姿、画幅不变、出界填黑）。`OutputAlignedImage` 关闭、或本轮没找到目标 → 输出空 |

> **口径**：标量端口 = 最高分那一个实例，数组端口 = 全部实例；只定位单目标时用标量端口最省事。**每轮开头非图像端口一律归零**（`Score`/`Row`/`Column`/`Angle`/`MatchCount` = 0、`MatchedTemplate` 空串、五个数组为空），失败轮下游读不到上一帧的"幽灵结果"；图像端口由框架在轮首统一回收。

## 关键参数

取值范围以流程中该步骤的「模块参数」界面为准，下面是含义与默认值。

**③ 匹配参数（插件级，改完立即生效）**

| 参数 | 默认 | 取值 | 说明 |
| --- | --- | --- | --- |
| `MinScore` | 0.5 | 0.01~1 | 分数下限，低于它的命中不算找到（shape matching 的工业常用起点） |
| `MaxMatches` | 1 | 1~100 | 最多输出几个实例（1 = 单目标，绝对多数场景） |
| `MaxOverlap` | 0.3 | 0~1 | 两个命中区域允许的最大重叠比例（去重用）——同一目标别报两次 |
| `Greediness` | 0.8 | 0.1~0.9 | 搜索激进度：越大越快、越容易漏（0.9 = 只搜明显更优的方向） |
| `DisplayViewIndex` | 1 | 0~9 | 标注图发布到主界面几号视图窗口，0（界面显示"不显示"）= 不发布，不影响端口输出 |
| `OutputAlignedImage` | true | — | 是否输出 `AlignedImage`（关掉省一次整图重采样） |

**② 提取参数（跟随每个模板条目，改任一必须重学）**：金字塔层数 `NumLevels`（默认 5，可填 1~10，学习与查找取同一个值）、最小 / 最大角度 `MinAngleDeg` / `MaxAngleDeg`（默认 -180 / 180，填反了自动交换）、角度步长 `AngleStepDeg`（默认 0 = 按模板尺寸自动，可填 0~30 度）、梯度阈值 `GradientThreshold`（默认 0 = 自动，可填 0~255）、使用极性 `UsePolarity`（默认勾选：黑白方向必须一致才算命中，更快）、启用缩放 `ScaleEnabled` / `ScaleMin` / `ScaleMax`（默认关 / 0.8 / 1.2，可填 0.5~2）。逐项调大调小的后果见第二页第四节。

**库与配方（由配置界面维护，不建议手改）**

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `TemplateLibraryJson` | `[]` | 整个模板库（名字/形状/区域/掩膜/模型/提取参数的 JSON 数组）。**JSON 损坏时按空库处理**（界面提示重学），不会把整份方案卡死 |
| `DefaultTemplateName` | 空 | 「设为默认」按钮写入；`RecipeName` 未连接/为空时使用 |
| `TemplateModel` / `TemplateShape` / `TemplateRect` / `TemplateMask` / `PreviewImagePath` | — | 单模板时代的**迁移字段**，首次加载自动迁成库里第一条（名字取默认名，否则"模板1"）后清空，新代码不再使用 |

## 配方怎么选（三级，不静默、不猜）

```
① RecipeName 端口有值 ─▶ 按名字在库里精确找（逐字符一致，大小写与空格都算）
   └─ 没找到 ─▶ 失败：未知产品：XXX 没有对应模板（库里有：A型，B型）
② 没给名字 ───────────▶ 用「设为默认」的那条
③ 默认也没有 ─────────▶ 用库里第一条；库是空的 → 失败：尚未创建模板
```

## 口径与失败策略

- **四种情况判失败**（下游拿不到位姿无法继续）：输入图像为空 / 未知产品名 / 条目未学习或载荷损坏 / 未找到目标。其中**只有"未找到目标"记 Warn**，其余记 Error；四种情况 `ErrorMessage` 都写明原因与处置。
- **失败也要出标注图**：未找到时是"原图 + 红字原因"，产线当场能看到现场；标注图渲染失败**只丢 `MeasureImage`**，端口数据照常输出（一次成功的定位不会因为画不出图而判失败）。
- **界面填坏的离谱数值不会崩流程**：所有送进 HALCON 的量都先夹进合法区间（NaN/Inf 按最小值处理），最多让结果不对，不该冒出 `#1302`/`#9302` 这类算子报错。
- **判定与上报不在这里**：本算子只定位，不判 OK/NG；用 `Score` / `MatchCount` 自己接「结果上报」或条件步骤。
- **可以进并行分支**（标记了并行安全）：纯视觉计算，不碰界面、不共享跨实例状态。
- **配置态与运行态隔离**：读参考图、反序列化模型、渲染预览只在"打开配置界面"的那个实例上做，流程编译出来的运行实例只灌参数——不会每次编译都读一遍图、开一次离屏窗口。

## 典型用法 / 接线

```
── 引导链路（要原图坐标：抓取、贴装、机械坐标）
图像采集.Image ─────────────▶ 模板匹配.Image
变量/上位机（产品型号）─────▶ 模板匹配.RecipeName
模板匹配.Row / Column / Angle ▶ 坐标变换.PoseRow / PoseCol / PoseAngle  （位姿跟随 ROI）
模板匹配.Row / Column ──────▶ 坐标变换.PixelPointRow / PixelPointCol    （像素→机械）
模板匹配.Angle ─────────────▶ 坐标变换.PixelAngle（要机械角才接）
坐标变换.MechanicalX / MechanicalY ▶ 轴运动 / CSV记录 / 结果上报

── 固定坐标检测链路（要标准位姿图，最省事）
ROI.Domain_定位区 ──────────▶ 模板匹配.Image（只在 ROI 内搜，坐标仍是全局）
模板匹配.AlignedImage ──────▶ 卡尺测量.SrcImage / BlobDetect.SrcImage / Ocr.Image / CodeReader.Image
模板匹配.MeasureImage ──────▶ 结果显示.SrcImage（要再叠别的结果时；它已自带标注）

── 留数据、盯趋势
模板匹配.Score / MatchedTemplate ▶ CSV记录（分数格式 0.000，模板名看每帧实际用哪条）
模板匹配.MatchCount ────────▶ 条件步骤（≥1 才继续）
```

> 选型口诀：**要原图坐标 / 引导 → 接 `Row`/`Column`/`Angle` 给「坐标变换」；内部 ROI 固定的算子（卡尺 / Blob / OCR / 读码）→ 接 `AlignedImage`。** 两条别混用——归一化图已经把目标搬走了，再拿 `Row`/`Column` 去对原图坐标就对不上。

## 现象先查什么（速查，细节在后面两页）

| 现场现象 | 先查这一项 | 详见 |
| --- | --- | --- |
| 失败："未找到目标" | 分数下限是否被抬太高 → 真实偏转/远近是否超出条目学的角度、缩放区间 | 第二页第四、五节；第三页第一节 |
| 找得到但位置跳到隔壁 | 模板区域独不独特、梯度阈值是否太低把噪声当特征 | 第二页第二节 |
| 改了角度/极性/层数没变化 | ② 是创建态，**不重学仍是旧模型**（看橙色徽标） | 第二页第四节 |
| 下游用坐标对不上图 | 链路选错：原图坐标走 `Row`/`Column`/`Angle`，固定 ROI 走 `AlignedImage` | 上面口诀；第三页第四节 |
