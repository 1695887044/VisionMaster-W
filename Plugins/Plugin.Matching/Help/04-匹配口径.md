# 模板匹配 · 匹配口径

> 分类：定位 ｜ 来源：插件 Plugin.Matching

这一页回答四个"到底怎么算"的问题：**金字塔与灰度/形状**、**分数与排序**、**耗时与超时**、**多输出口径**。
参数清单在第三页，调法在第二页，症状在第五页。
## 一、三条口径先分清：金字塔、灰度、形状

### 1. 两条路：形状（默认）与灰度相关（NCC）

每个模板条目自带一个 `Algorithm`：

| 算法 | HALCON 算子 | 比对的是 | 该用它的时候 | 代价 |
| --- | --- | --- | --- | --- |
| **基于形状**（默认） | `create_shape_model` / `find_shape_model`；缩放档 `create_scaled_shape_model` / `find_scaled_shape_model`；各向异性档 `create_aniso_shape_model` / `find_aniso_shape_model` | 边缘位置 + 朝向（梯度） | 有清晰轮廓的工件；光照会变、需要抗对比度漂移；需要缩放匹配 | 目标本身没有边时无能为力 |
| **基于灰度相关（NCC）** | `create_ncc_model` / `find_ncc_model` | 灰度值本身的相关度 | 边缘弱但**纹理稳定**：丝印、喷码底纹、织物、低对比度塑料件、同色异材质 | **不支持缩放（也没有各向异性）**；光照整体变化会直接掉分；**极性/梯度阈值不生效** |

两条路的共同点：彩色图一律转灰度后用，颜色不参与比对；都没有"颜色匹配"。

**形状算法内部还有三档，互斥**（同一时刻只有一档生效，优先级从高到低）：

| 档 | 开关 | 送 HALCON 的算子 | 输出 |
| --- | --- | --- | --- |
| 各向异性 | `AnisoScaleEnabled` | `create_aniso_shape_model` / `find_aniso_shape_model` | `Scales` = 行缩放，`ScalesRow` = 行缩放，`ScalesCol` = 列缩放 |
| 等比缩放 | `ScaleEnabled` | `create_scaled_shape_model` / `find_scaled_shape_model` | `Scales` = `ScalesRow` = `ScalesCol` = 统一缩放 |
| 不缩放 | 两个都关 | `create_shape_model` / `find_shape_model` | 三路都恒为 1 |

**各向异性优先**：勾着 `AnisoScaleEnabled` 时等比那三个字段被忽略（界面把等比那组灰掉、数值保留）。

**换算法 = 换模型类型**（`.shm` ⇄ `.ncm`，两者不是同一种文件），必须**重新学习**。
界面上换完算法徽标会立刻转橙"参数已改·需重新学习"，这不是误报。

NCC 下界面上**极性下拉、梯度阈值、缩放匹配三块会灰掉**——不是坏了，是这三项对 NCC 没有意义。
存量方案（升级前保存的）没有 `Algorithm` 字段，一律按"基于形状"解释，行为与升级前完全一致。

### 2. 金字塔：粗层筛、细层定

```
学习侧：NumLevels 请求 1~10（默认 5），送 HALCON 的层数参数走 "auto" 之外的显式值；
查找侧：用同一条目的 NumLevels（同一个夹取区间），粗层先排除、细层再定位。
```

两件事必须知道：

- **信息栏报的是模型实际生成的层数**，不是你填的那个数。模板/图像撑不出那么多层时会自动减层——
  这不是 bug，是提示你"模板太小，用不了这么多层"；
- 层数**是创建态**：改了层数不重学，查找用的仍是旧模型的层结构。

方向：模板只有几十像素见方 → 减到 3~4；模板很大、要找的是小特征 → 5~6。
加层数（5 → 6~7）能提速（粗筛更快），但**太粗会漏掉小目标**（细层还没走到就被粗层的低分否掉了）。

- **散焦/高噪声场景**：HALCON 例程常用 `find_shape_model(..., NumLevels=[0,-1], ...)`，
  第二个值 -1 表示**不跟踪到最低层**。VM 的 `TrackingLevel` 对应这个值：默认 1（旧行为），
  需要时改 -1。本仓 `matching_defocused_pcb` 对拍里，121 张散焦图只有 -1 能全部找到；
  单值层数 1~6 只能找到 25 张（对焦清楚的 25 张）。

### 3. 灰度：形状下是"边的来源"，NCC 下才是"比对对象"

灰度值本身不参与比对，但**梯度阈值**决定"多陡的跳变才算一条边"：

- 填 0 = 让算法按这张图的对比度自动定（推荐）；
- 手动填就夹在 1~255，调高 = 只留最陡的边（特征数骤减、模型小、抗干扰强，太高则分数上不去、位置漂）；
  调低 = 特征变多而啰嗦，噪声/纹理也被当特征，误匹配率上涨；
- 判据在预览图上：**绿线糊成一片毛刺 = 太低；绿线只剩一两条 = 太高**。

亚像素定位在算子内部是最小二乘口径（代码里送的是这个字面量），
所以你看到的 `Row`/`Column` 可以在两个像素之间；同一件产品每帧差 1~2px 时，先怀疑打光与相机振动而不是参数。

### 4. 各向异性：行/列各自一个缩放区间

各向异性档不是"两个缩放参数"这么简单，有三条口径必须先明确：

1. **HALCON 内部顺序是"先缩放、后旋转"**（`create_aniso_shape_model` 参考手册原文）——
   所以模板在参考图里应当**尽量摆正（水平/垂直）**。斜着框的模板，各向异性缩放会先沿
   "模型自身的行/列"拉，再转过去，与"图上看起来的上下/左右"不是一回事；
2. **行/列范围是两个独立区间**，不是"行×列"的组合上限。HALCON 只要求
   `ScaleRMin > 0`、`ScaleRMax ≥ ScaleRMin`（列同理），本仓夹 **0.1~10**、默认 0.9/1.1。
   区间**应包含 1.0**：整段偏离 1.0 时参考图自匹配可能失败，学习期的原点锚定会静默退回
   默认原点（位置差 1~2px，不报错）；
3. **代价在查找侧，不在模型体积**：默认 `Optimization='auto'` 不做变体预生成，
   模型载荷与角度/缩放范围基本无关（本机实测：同一模板 360° 与 10° 的 `.shm` 都是 68 KB）；
   但 `find_aniso_shape_model` 要遍历"角度 × 行尺度 × 列尺度"的组合，
   耗时大致按两段范围宽度之积涨。先按实测波动收窄（±0.1 通常够），别一上来就 0.5~2。

**它到底值不值**（本机实测，同一张列向拉伸 20% 的合成图、同一套角度/分数参数）：

| 档位 | 最高分 | 读出的缩放 |
| --- | --- | --- |
| 各向异性（行 0.9~1.1 / 列 1.0~1.35） | **0.9997** | 行 ×0.999、列 ×1.200 |
| 等比（0.9~1.35，覆盖了 1.2） | 0.7665 | ×1.199（只能给一个数） |

等比档并不是"找不到"，而是**分数明显下降**——20% 的列向拉伸用统一缩放去凑，
边缘会逐条错位。这就是"该开各向异性"的量化判据：分数从 0.99 掉到 0.77，
而把 `MinScore` 抬到 0.9 时等比档直接 0 命中。

**模型类型与查找算子必须配对**（这条最容易静默出事）：HALCON 对"各向异性模型 + `find_scaled`"
（一个都找不到）和"等比模型 + `find_aniso`"（行/列恒相等）**都不报错**。
所以改了开关**必须重新学习**（徽标会转橙）；真忘了重学，运行期会落一行 Warn：
`模板「X」学习时各向异性=关，当前=开：模型与当前参数不一致，结果可能不准…`。

## 二、分数与排序

- **分数 ≈ "对上了几成特征"**。4 条特征边错 1 条掉到 75%，40 条错 1 条还剩 97.5%——
  所以"宁可框大一点"的前提是仍然独特；
- **结果天然按分数从高到低排序**：`Rows[0]` 就是标量端口 `Row` 那一个，`Score` = `Scores[0]`；
- **`MinScore` 是闸门不是期望值**：低于它的命中直接不算找到（`MatchCount=0`，步骤失败）。
  有常态遮挡就按最大遮挡率设（常态遮住三成 → 上限在 0.7 附近，定 0.6 而不是 0.5）；
  找不到时**先降到 0.3 看一眼**：能出结果、分数 0.4 左右 = 光照或模板退化了，去修光或重学，
  而不是把 0.3 定下来长期用；
- **`MatchedTemplate` 在"未找到目标"这种失败轮也已经写好**（条目已经选出来了才去找），
  只有"未知产品 / 模板库为空"时是空串——用它做配方追溯时不用担心失败轮丢名字；
- **分数下限 0.01~1、越界静默夹取**，`NaN` 按最小值处理。

## 三、耗时：没有超时参数，只有搜索空间

**本算子没有"超时"参数**，别指望设个超时兜节拍。一次查找的耗时近似：

```
耗时 ≈ 搜索域大小 × 角度区间宽度 × 缩放区间宽度 × 用到的金字塔层数 × (1 − 激进度)
```

（NCC 的式子去掉"缩放区间宽度"这一项——它不支持缩放；其余同形。
各向异性档把"缩放区间宽度"换成**行区间宽度 × 列区间宽度**——两段范围都在扩张变体数，最贵的档。）

**搜索域是第一项，也是最容易被忘掉的一项。** 打开 `UseSearchRegion` 并把上游区域接到
`SearchRegion` 端口后，插件先 `reduce_domain` 再查找，耗时按**面积比**下降：
全图 2448×2048 上找一个 40×40 的模板，与在 600×400 的工位窗口里找，差距是 20 倍量级。

- 开关打开但区域没连 → **回落全图**（不是缩到零面积），日志里会写"搜索域开关已开但未连区域 → 回落全图"；
- 区域要**留足余量**：目标一旦跑出窗口就永远找不到，这是拿"漏检风险"换速度，实测过边界再定；
- 多模板库共用同一个 `SearchRegion`，不会按条目分区域。

所以节拍顶不住时按这个顺序砍（前面的收益大一个数量级）：

1. **限制搜索域**：上游接「ROI」的 `Domain_` 输出到 `Image`——域外一个像素都不搜，
   还顺手挡掉相似背景的误匹配，而返回坐标仍是全局坐标（下游零换算）；
2. **收窄角度区间**：±180° → 实际偏转 ±15°，模型和耗时一起降（最划算的一次提速）；
3. **关掉缩放**：目标大小不变就别开（`Scales` 就是为此而存在的数组，未启用时恒为 1）；
4. **提高激进度** `Greediness` 0.8 → 0.9：只往明显更优的方向搜，**先确认没有漏检再加**，
   这是拿检出率换时间；偶尔漏检就退回 0.6~0.7；
5. **加金字塔层数** 5 → 6~7：粗筛更快（模板本来就小就别加，减层反而更准）。

反过来"老是找不到 / 位置乱跳"时的顺序是：
**先看分数下限是不是被抬太高 → 再看角度/缩放区间是不是太窄 → 最后才看激进度是不是太凶**。
这三项调错了会互相伪装成对方的症状：激进度太凶造成的漏检看起来和分数下限太高一模一样（都是 `MatchCount=0`）。
所以**一次只改一项，改完连跑 10 帧**再决定下一项。

## 四、多输出口径：标量、数组、去重

### 1. 两套端口是同一批命中的两种视图

| 端口族 | 内容 | 用途 |
| --- | --- | --- |
| 标量族 `Score` / `Row` / `Column` / `Angle` | **最高分那一个实例** | 只定位单目标时最省事 |
| 数组族 `Rows` / `Columns` / `Angles` / `Scores` / `Scales`（+ 各向异性档的 `ScalesRow` / `ScalesCol`） | **全部实例**，按分数从高到低、**逐项对齐**（`Rows[i]` 与 `Columns[i]` 指同一个命中） | "第 N 个命中 → 第 N 把卡尺"这类配对 |

数组族永远一起给：未启用缩放时 `Scales` 恒为 1，只为保住一一对应，别把它当"检测到缩放"。
`ScalesRow`/`ScalesCol` 在等比/未缩放档**与 `Scales` 逐位相同**（不是空数组），
所以"只想拿缩放"的老流程继续读 `Scales` 即可，不需要改连线。

### 2. `MaxMatches` 与 `MaxOverlap` 是两件事

- `MaxMatches`（1~100，默认 1）= **最多输出几个**；想"图里有几个数几个"就调大；
- `MaxOverlap`（0~1，默认 0.3）= **两个命中允许重叠多少**，用来去重。

实测口径（可以直接当数量级用）：模型框 160×160、两个真实目标相距 90px（框重叠约 44%）——
填 0.9 报 2 个、填 0.05 只剩 1 个。**工件实际间距 ÷ 框宽**就是该填的数量级。

| 症状 | 是哪个 | 往哪调 |
| --- | --- | --- |
| 同一个目标被报两三次（数组里位置几乎一样） | `MaxOverlap` 太宽 | 降到 0.05~0.2 |
| 两个紧挨着的相同工件只数出一个 | `MaxOverlap` 太严 + `MaxMatches` 不够 | 放宽重叠、同时确认匹配数上限够大 |

### 3. `AlignedImage` 只对最高分那个负责

归一化图用"输出与输入同幅面"的刚性变换：把**最高分实例**搬回学习时的位置与 0°，画幅不变、出界填黑。

- 边缘那一圈黑是正常的（目标搬回标准位姿后原画面边缘出界）——下游固定检测区域**避开画幅边缘**就行；
- `MaxMatches > 1` 时**第 2、3…个实例不会各自对齐**，要各自对齐就放多个匹配步骤；
- 真的避不开边缘，就改用 `Row`/`Column`/`Angle` 接「坐标变换」做位姿跟随；
- **各向异性档的对齐只搬位姿、不还原拉伸**：归一化是刚性的（平移 + 旋转），
  行/列缩放差异不会被"拉回去"。下游若要求"目标恢复到模板尺寸"，得自己按
  `ScalesRow`/`ScalesCol` 再做一次非等比变换（例如 `affine_trans_image` 的 `hom_mat2d_scale`）。

条目区域参数损坏（应为 5 个值）时，只有开 `OutputAlignedImage` 这条分支会抓到并报"区域参数损坏"，
关掉它不会报——排查时别把这条当成"只有开对齐才有的毛病"。

## 五、配方怎么选（三级，不静默、不猜）

```
① RecipeName 端口有值 ─▶ 按名字在库里精确找（逐字符一致，大小写与空格都算）
   └─ 没找到 ─▶ 失败：未知产品：XXX 没有对应模板（库里有：A型，B型）
② 没给名字 ───────────▶ 用「设为默认」的那条
③ 默认也没有 ─────────▶ 用库里第一条；库是空的 → 失败：尚未创建模板
```

三条推论：**配方选择与场景内容无关**（选了 B 型就用 B 型，找不到就如实报失败，不会"退而求其次"用 A 型）；
`RecipeName` 清空 = 回落默认模板而不是失败；名字不在库里时文案会把库里现有的名字列出来，照着抄最省事。

## 六、位姿的四条口径

1. **原点锚定在你框的中心**：学习时插件会在参考图上"自己找自己"一次，把模型原点补偿到你画的区域中心
   （HALCON 默认原点与区域中心有 1~2px 系统性偏差，实测圆形区域约 +1.5px）。
   这一步失败时**静默回退**到默认原点——表现是"位置差 1~2px"，而不是报错。
   **各向异性档的自匹配用 minScore 0.5**（等比档是 0.8）：行/列范围整段偏离 1.0 时，
   参考图在最近尺度上只有 ~0.84 分，卡 0.8 会拿不到结果、锚定直接失效；
2. **角度是度**：`Angle` / `Angles` 输出前已从弧度换算成度（平台约定全仓库统一用度），
   下游「坐标变换」的角度端口也是度，**直接接，不要自己乘 π**；
3. **轮廓跟着位姿走**：标注图上的模型轮廓是按每个命中的 `(row, col, angle)` 刚性搬运的
   （历史缺陷：角度被双重转换，导致数值对、画出来的轮廓不转）。
   **各向异性档的轮廓同样是刚性的、不按行/列缩放拉伸**：拉伸目标上的绿框会比实际特征略窄或略宽。
   要看真实缩放读 `ScalesRow`/`ScalesCol`，**别拿标注图量尺寸**。
4. **角度步长决定 `Angle` 读数的插值回差**：② 区的角度步长（`AngleStepDeg`）是学习时烤进模型的变体间隔，
   真实角度落在两个变体之间时靠插值补——步长越大回差越大。要拿 `Angle` 做旋转补偿（抓取、贴合）
   就收窄到 0.5~1° 重学；只要位置、不看角度就放宽换速度。填 0 = 送 `"auto"` 由算法按模板尺寸自动定
   （非 0 时夹 0.1~30 度）；**自动值在界面上看不到**——信息栏只报金字塔层数、角度区间与载荷，
   想知道实际步长只能从学习耗时与模型大小间接判断。

## 七、可以进并行分支

插件标了并行安全：纯视觉计算、不碰界面、不共享跨实例状态。
"确保模型已加载"这个动作虽然写法是静态方法，但改写的都是**本实例的条目**，不构成跨实例共享。
