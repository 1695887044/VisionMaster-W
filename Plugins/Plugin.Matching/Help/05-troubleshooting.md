# 模板匹配 · 排错与文案字典

> 分类：定位 ｜ 来源：插件 Plugin.Matching

这一页全是"从症状倒着查"：先看第一节定方向，再按第二节/第三节的**原文**查那一条，最后照第五节核对上线。
配置信息栏那批文案的对照表在第二页第六节，这里不重复。

## 一、症状 → 按这个顺序查

| 现场现象 | 按这个顺序查 |
| --- | --- |
| 步骤失败："未找到目标"（`MatchCount=0`） | ① 分数下限 `MinScore` 是不是被抬太高（先降到 0.3 试一帧）；② 工件实际偏转/远近是否超出条目学的角度、缩放区间（超出就得改区间**并重学**）；③ 光照（直方图还是不是双峰）；④ 遮挡是不是超过常态；⑤ 激进度 `Greediness` 是不是填到 0.9 了（退回 0.7 再试） |
| 找得到了，但位置跳到隔壁/背景上 | ① 模板区域**不独特**（图里还有第二处长这样的）→ 换特征，或用 `MaxMatches=1` + 限制搜索域；② `MinScore` 太低；③ 梯度阈值太小把噪声当特征（预览绿线糊成一片就是它）；④ 用了"忽略极性"导致明暗反了也算命中 |
| 同一个目标被报两三次（数组里位置几乎一样） | `MaxOverlap` 太宽（默认 0.3，降到 0.05~0.2），实测数量级见第四页第四节 |
| 两个紧挨着的相同工件只数出一个 | 反过来：`MaxOverlap` 太严，放大到接近"实际间距对应的重叠率"；同时确认 `MaxMatches` 够大 |
| 偶发漏检（一百帧里丢一两帧） | ① `Greediness` 降到 0.6~0.7；② `Score` 是不是常年在 `MinScore` 附近晃（模板本身弱，重选区域）；③ 光源老化/曝光自动增益在漂——盯 `Score` 趋势，别只盯有没有失败 |
| 数值抖（同一件产品每帧位置差 1~2px） | ① 角度步长是不是填得很大（自动值偏粗）→ 手动收窄到 0.5~1° 重学；② 金字塔层数太少；③ 特征边太少（框太小）；④ 亚像素定位本身就是最小二乘，再抖就是**打光/相机振动**的问题，不是参数的 |
| 改了角度/缩放/极性/层数，跑起来没变化 | **没重学**。看到橙色徽标「参数已改·需重新学习」就再点一次 `创建模板`；不重学不会报错，用的仍是旧模型 |
| 改了分数下限/匹配数/重叠/激进度，跑起来没变化 | 这几个是运行态、立即生效——没变化多半是**没点「确定」落盘**，或流程跑的是另一步骤实例 |
| 标注图上轮廓不跟着目标转 | 端口数值是对的、只有画出来是错的 → 历史缺陷（角度双重转换）已修；若数值也偏，检查模板区域里是不是框进了会动的部分 |
| 打开配置界面右侧是黑的/没有图 | ① `Image` 没连或上游本轮没出图 → 试运行一次；② 没连线就填「参考图」路径点 `载入`；③ 路径存在但读失败会有红字"参考图载入失败：…" |
| 换相机 / 换分辨率后突然匹配不上 | 模板是**按像素尺寸**学的：同样的工件在新分辨率下像素尺寸变了，等价于超出缩放范围。要么开缩放匹配并重学，要么按新图重学一遍（这是最常见的"什么都没改突然不行"） |
| 打开方案就提示"需重新学习" | 动过 ② 区参数就是正常的；若什么都没动还天天提示，多半是方案被手工编辑过（区域参数被改成不是 5 个值、掩膜长度变了） |
| 信息栏红字"模板已学习，但预览生成失败：…" | **模型已经学好了**，只是左下角那张预览图没画出来。可以照常运行；要排查就核对参考图是否还在、区域是否落在图内 |
| 节拍顶不住 | 按第四页第三节的顺序砍：限制搜索域 → 收窄角度 → 关缩放 → 提激进度 → 加层数。**没有超时参数可设** |

## 二、运行失败文案对照（原文照抄源码，`{…}` 是运行时填进去的值）

| 文案 | 含义 | 处置 |
| --- | --- | --- |
| `输入图像为空或未初始化` | `Image` 端口没值（空对象或未初始化的图） | 检查上游步骤本轮是否成功、连线是否被删；本步骤在流程失败策略里是停止还是跳过也要核对 |
| `不支持的图像通道数：N（仅支持 1 通道灰度、3 通道彩色或 4 通道 RGBA/BGRA）` | 上游给了奇怪通道数的图（如 2 通道、多光谱） | 前面接「图像预处理」转成单通道，或确认相机输出格式 |
| `未知产品：XXX 没有对应模板（库里有：A型，B型）` | `RecipeName` 的值在库里没有 | 名字**逐字符一致**（大小写、前后空格、全角半角都算）。看库里列出的名字照着改；长期方案是让上位机传变量而不是手打 |
| `未知产品：XXX 没有对应模板（模板库为空，请先学习模板）` | 给了名字但连条目都没有 | 打开配置界面新增条目并学习；或确认方案是否被手工改坏 |
| `尚未创建模板：请打开配置界面学习至少一个模板` | 没给配方名、库又是空的 | 同上 |
| `模板「X」尚未学习：请打开配置界面完成学习` | 条目在库里，但模型载荷为空（新加没学 / 只画了框没点创建） | 选中该条目 → 画区域 → 点 `创建模板` → 点「确定」 |
| `模板「X」加载失败（载荷损坏？请重新学习）` | base64 载荷读不回模型（方案被手改、跨大版本、存盘中途损坏） | 重新学习这条模板；别再手改方案 JSON 里的 `TemplateLibraryJson` |
| `未找到目标：模板「X」没有满足分数 ≥ 0.50 的匹配（光照/遮挡变化？可降低分数下限重试）` | 没有任何实例达到分数下限（**日志级别是 Warn，不是 Error**） | 按第一节第一行走；注意标注图此时仍然输出（原图 + 红字），可以先看现场再判 |
| `模板「X」的区域参数损坏（应为 5 个值，实际 N 个）：请打开配置界面重新框选并学习` | 只在开 `OutputAlignedImage` 时会被抓到：条目区域被改坏 | 打开配置界面重新框选该条 → 重学 → 确定 |
| `模板匹配失败：…` | HALCON 抛出的兜底分支，后面是算子原始信息 | 先看后面那段是否含 `#` 错误号；若出现过"角度范围超出模型范围"类提示，就是改了提取参数没重学 |

## 三、常见问题

**Q：配置里明明已学习，运行却报"尚未创建模板"？**
历史缺陷（模板库解析只挂在"打开配置界面"那条路上，流程编译走的是另一条），当前版本已修。
若仍出现，只可能是：没点「确定」保存、方案文件没真的存盘、或步骤被复制成了另一个实例（库不共享）。

**Q：`AlignedImage` 边缘为什么有一圈黑？**
正常。归一化用"输出与输入同幅面"的模式（画幅不变），目标被搬回标准位姿后原画面边缘出界、出界填黑。
下游的固定检测区域**避开画幅边缘**就行；真的避不开，就改用 `Row`/`Column`/`Angle` 接「坐标变换」做位姿跟随。

**Q：换电脑 / 拷给同事，模板还在吗？**
在。模型和掩膜都以 base64 存在方案里。**只有「参考图」路径是本机绝对路径**，
它只影响重开配置界面时画布上显示什么、以及重学时用哪张图，**不影响运行匹配**。

**Q：本步骤失败，下游是不是什么都拿不到？**
位姿端口（`Score`/`Row`/`Column`/`Angle`）在失败轮是清零值 0，数组端口为空，`AlignedImage` 为空；
但 **`MeasureImage` 仍然有值**（未找到时是原图 + 红字原因），可以接记录/存图留证。
流程按失败策略停止或跳过本分支——**别拿"读到 0"当"没找到"**，要判就用 `MatchCount` 和步骤 `Success`。

**Q：多目标怎么和卡尺、Blob 配对？**
用数组端口：`Rows[i]` / `Columns[i]` / `Angles[i]` / `Scores[i]` / `Scales[i]` 指同一个命中，
且天然按分数从高到低排序（`Rows[0]` 就是标量端口 `Row` 那一个）。

**Q：为什么流程每次编译都很慢？**
历史缺陷（运行实例也去读参考图、反序列化模型、开离屏渲染窗口），当前版本按"配置态/运行态"隔离，
编译期只灌参数。若最近变慢，想想是不是有人把界面操作（载入参考图、频繁切换条目）搬进了编译路径。

**Q：极性什么时候该从「使用极性」切成「忽略极性」？**
「忽略极性」是亮暗反相也算命中——只有**光照会整片反相**（不同工位补光不一致、正反面拍摄）的场合才需要，
代价是**更慢、更容易误匹配**（黑白颠倒的相似花纹也会被它认下）。现场表现"白天好、傍晚光变了就丢"，
**先查曝光锁定**，再考虑切忽略极性。极性属于 ② 创建态参数，**切了必须重新点 `创建模板`**。

**Q：涂抹掩膜存的是我看到的那块橙色吗？**
存的是**原始涂抹形状**（绘制/擦除两笔都会写回条目），不是"与模板区域求交后的有效排除域"。
学习时才求交。所以"在区域外面涂了一圈"不该让模板长期报"需重新学习"——
早先版本因为把求交结果存进签名而天天误报，现在已按原始长度判定。

## 四、打光与运行习惯

**打光三条原则**：① **稳而不亮**（亮度稳定远比亮度高重要，曝光与增益锁死）；
② **漫射光**（点光源造高光与阴影，高光区就是每批都变的特征）；
③ **看直方图**——理想是双峰（暗背景 + 亮目标，中间分得开），单峰或糊在一起 = 光没打好；
先修光能解决八成的匹配问题，比调参数管用。

**运行时三条习惯**：**盯 `Score` 趋势**——0.95 慢慢滑到 0.75 是光源老化、镜头松动、玻璃脏了的
**领先指标**，等跌破 `MinScore` 才报警就晚了，把 `Score` 接进 CSV 按班看曲线；
**失败先看标注图**——红字直接写明原因，轮廓画在什么位置一眼就知道是"找错了"还是"没找到"；
**改参数单变量**——一次只改一项，改完连跑 10 帧看稳定性（尤其别把"降分数下限"和"提激进度"一起改，
症状会互相伪装）。

## 五、学完必做的压力测试 + 上线前核对

**压力测试**（学完不做这几步，上线必翻车）：

- 目标平移到视野**四个角**，每次 `Row`/`Column` 都回准；
- 转到角度区间的**两个端点**（例如 ±15°），`Angle` 回差在允许范围内；
- 光源**调暗 20%、调亮 20%** 各跑一轮，`Score` 不跌破 `MinScore`；
- 拿**另一件同款**跑一遍（特征不该是"这一件的划痕"）；
- 连跑 50 帧记 `Score` 的均值与最低值，**最低值离 `MinScore` 不到 0.05 就是埋了个雷**（迟早跌破）；
- 开了缩放的话把工件抬高/压低到实际极限，看 `Scales` 是否落在设定区间内。

**上线前核对**：

- [ ] 上面六项压力测试全过；
- [ ] `Score` 最低值与 `MinScore` 之间留有余量（低于 0.05 的余量就是雷）；
- [ ] 每条模板的**配方名**与上位机下发的字符串**实测对过一次**（不是看着一样，是跑过一帧看 `MatchedTemplate`）；
- [ ] 徽标没有停在橙色「参数已改·需重新学习」的条目；③ 匹配参数与产品一致
      （多产品共线时这几项是**整步共用**的，A 产品能容忍的分数下限未必适合 B）；
- [ ] `DisplayViewIndex` 与主界面实际窗口号对上（填 0 只是不占窗口，不影响端口与存图）；
- [ ] 下游选型确定：要原图坐标走 `Row`/`Column`/`Angle` →「坐标变换」；固定 ROI 的算子走 `AlignedImage`；
- [ ] 断一次线、再故意喂一个错误配方名各试一次：确认是**明确失败**而不是给出上一帧的旧值，
      且失败文案里列出的库名与现场一致，再把这个信号接给报警。
