# 模板匹配 · 开发：不变量与守门断言

> 分类：定位 ｜ 来源：插件 Plugin.Matching ｜ 读者：开发

判据只有一条：**每条不变量都能指到一个真实存在的断言名，或指到一段源码**。
断言全在 `FlowCanvasChecks\MatchingChecks.cs`（68 条，`Check("…")` 的名字逐字照抄）；
标了"无断言，靠人工核对"的就是真没有，别照着编。

- **A 组：违反会当场红（断言失败）或抛**——改这些方向前先想清楚怎么改断言。
- **B 组：违反后静默出错**——编译绿、断言可能也绿，现场才露馅。**这一组才是本页的价值**。

## A 组（有断言钉着）

**A1 库解析必须在 `ApplyConfigValues`，不能只挂在 `Initialize`**
症状：配置里明明已学习，运行报"尚未创建模板"。
机理：编译器建运行实例只调 `ApplyConfigValues`，`Initialize` 是配置界面那条路。
守门：`【编译链路】只走 ApplyConfigValues 也能拿到模板库并定位`。

**A2 学习成功必须给出特征区域尺寸，且状态栏不是失败**
症状：每次学习都报"创建模板失败"，或成功文案里区域是 `0×0`。
机理：`GenTemplateRegion` 与灰度/域处理链某步被改坏，`GetShapeModelParams` 取不到实际层数。
守门：`【回归·P0】学习成功后状态栏不是失败（早先每次学习都报创建模板失败）`、
`【回归·P0】成功文案给出特征区域尺寸（不是 0×0、也不是空）`。

**A3 轮廓搬运的角度入参是【度】**
症状：端口数值对、画出来的模型轮廓不跟着目标转（早先被双重转成 ≈0.5°）。
机理：`PlaceContoursAtPoses` 内部自己 `deg * π/180`，调用方又换算了一次。
守门：`【回归·P1】轮廓放置按【度】换算：给 0° 就是 0°`、
`【回归·P1】轮廓放置按【度】换算：给 30° 就转 30°（早先被双重转成 ≈0.5°）`。

**A4 删除条目时必须先释放模型句柄**
症状：句柄泄漏；极端情况新条目拿到已失效的 `RuntimeModelId`。
机理：条目已从 `Library` 摘掉，`Dispose()` 遍历库时够不着它。
守门：`【回归·P2】删除条目时释放了模型句柄（条目已从库里摘掉，Dispose 够不着它）`。

**A5 掩膜存原始、签名用原始长度**
症状：什么都没动，打开方案就提示"需重新学习"；换条目再切回尤其明显。
机理：签名里放的是"与区域求交后的掩膜"长度，而学习会重写它，两端不对称。
守门：`【回归·P2】换条目再切回，不误报需重新学习`。

**A6 配置态/运行态隔离不能把功能隔掉**
症状：运行实例拿不到库（矫枉过正），或编译期去读参考图、开渲染窗口（隔离没做）。
机理：`_isConfigInstance` 只该管"给人看的那部分"（画布播种、预览、参考图）。
守门：`【回归·P2】编译实例不持有显示用参考图（只读该读的，不渲染预览）`、
`【回归·P2】编译实例仍然拿得到模板库（隔离不能把功能也隔掉）`、
`【回归·P2】对照：配置态走 Initialize 时预览照常恢复（隔离没矫枉过正）`。

**A7 条目区域参数必须能被运行期抓到损坏**
症状：开对齐图时抛 `IndexOutOfRange`（早先读的是迁移字段 `TemplateRect`）。
机理：`AlignedImage` 分支要 `entry.Rect[0..1]`，长度不是 5 时必须明确失败而不是硬取。
守门：`【回归·P3】条目区域参数损坏 → 失败原因写明区域参数损坏`。

**A8 缩放上下限相等时不许报错**
症状：填 1.0/1.0 学习直接失败（HALCON 拒绝退化的缩放范围）。
机理：学习侧撑开 ±0.005 的最小窗口（并限制在 0.5~2 内）。
守门：`【回归·P3】缩放上下限相等时仍能学习（撑开最小窗口而不是报错）`。

**A9 定位内核：同图必须命中、位置与角度回准**
症状：换了实现/参数口径后找不到、或坐标偏。
机理：`find_shape_model` 的角度入参、`numLevels`、`greediness` 与学习侧不一致。
守门：`【内核】同图定位命中 1 个实例`、`【内核】同图定位分数 ≥ 0.9`、
`【内核】位置亚像素级回准（150,200 ±0.5）`、`【内核】同图角度 ≈ 0（±0.5°）`。

**A10 平移 / 旋转 / 缩放三条真实形变**
症状：目标搬走、转过、变大后就丢。
机理：角度区间与缩放区间是**学习时烤进去的**，查找区间超出模型范围即 0 命中。
守门：`【平移】图案搬到 (280,360) 后位置回准（±1）`、`【旋转】整图转 10° 后仍命中`、
`【旋转】角度回准 10°（±0.5°）`、`【缩放】启用缩放模型后 1.15× 目标仍命中`、`【缩放】缩放倍率回准 1.15（±0.05）`。

**A11 输出端口面与逐项对齐**
症状：数组端口比实例数多/少一位；未开缩放时 `Scales` 是空数组。
机理：数组端口必须与命中数一一对应，未启用缩放也要填 1。
守门：`【数组】数组端口与实例数逐项对齐`、`【数组】未启用缩放时 Scales 恒为 1`、
`【输出】MatchedTemplate 回传配方名`、`【输出】位姿归一化图像已生成`、`【输出】标注图已生成`。

**A12 标注底图不许被"缩进左上角"**
症状：标注图整体缩在角落、四周黑边；或底图内容整体错位。
机理：离屏窗口没做无条件 `set_part`（R37 那条纪律），四角像素会塌成同一个常数。
守门：`【输出】标注底图逐点保真（两下角 == 场景背景 180，底图没被缩进左上角）`（两条同名，分别跑命中轮与未命中轮）。

**A13 未找到目标 = 失败，但标注图仍要出**
症状：`MatchCount=0` 时 `MeasureImage` 也空了，现场什么都看不见。
机理：失败分支里照样调 `RenderResultAnnotation` + `PublishIfConfigured` 再 `return`。
守门：`【未找到】空白背景判失败（Success=false）`、
`【未找到】失败原因写明「未找到目标」并带上分数阈值`、`【未找到】MatchCount=0 且标注图仍生成（产线看现场）`。

**A14 多实例、上限与去重三条口径**
症状：`MaxMatches=1` 却报两个；重叠去重方向反了。
机理：`num_matches` / `max_overlap` 直接送算子，越界前先夹取。
守门：`【多实例】两个相同图案全部找回（count=2）`、`【多实例】数组端口逐项对齐且分数都 ≥ 0.9`、
`【MaxMatches】上限 1 → 只报最高分实例（不越限）`、`【MaxOverlap】阈值放宽（0.9）→ 两个重叠实例都报出`、
`【MaxOverlap】阈值收紧（0.05）→ 重叠实例被去重成一个`、`【AlignedImage】成功匹配后位姿归一化图非空`。

**A15 涂抹的三条时序**
症状：点「确定」后涂抹丢了；涂完徽标不转橙；清空涂抹换条目再切回又"复活"。
机理：`SmearMask` setter 要写回条目，`TouchModelStaleness` 要即时算签名，清空要真清两层。
守门：`【涂抹时序·即写即存】涂抹后条目掩膜已写回（点「确定」不会丢）`、
`【涂抹时序·过期及时】涂抹后立即提示需重新学习（不必等换条目）`、
`【涂抹时序·清除生效】清空涂抹后条目掩膜真正清空（换条目再切回不会复活）`。

**A16 重学提示只该在创建态参数上出现**
症状：改了分数下限也提示重学（烦人），或改了角度却不提示（危险）。
机理：`EntrySignature` 只包含形状/区域/层数/梯度/角度/步长/极性/缩放/掩膜长度。
守门：`【重学提示】改匹配参数（运行期）不触发重学`、`【重学提示】改提取参数（创建态）触发重学提示`、
`【重学提示】徽标文字对运行实例同样成立（载荷未变时不误报）`。

**A17 圆形区域可学可定位**
症状：圆形区域报"只有矩形支持"，或定位回来的圆心偏。
机理：`HasTemplateRegion` 与 `GenTemplateRegion` 都要按形状分支（圆看半径，不看第 4 个数）。
守门：`【圆形模板】圆形区域可学习模板（域任意形状，无矩形硬限制）`、`【圆形模板】同图定位回准圆心 (150,200 ±0.5)`。

**A18 涂抹真的挖掉了特征**
症状：涂了一大块，模型载荷字节数没变（说明没生效）。
机理：排除域要 `(绘制 − 擦除) ∩ 区域` 再 `Difference` + `reduce_domain`。
守门：`【涂抹】无涂抹时掩膜为空`、`【涂抹】涂抹后重新学习：掩膜随条目落盘`、
`【涂抹】挖掉中心后模型载荷变小（特征点减少）`、`【涂抹】挖掉中心后定位仍回准 (150,200 ±1)`。

**A19 重开方案的状态恢复**
症状：重开配置界面要重画重学；或恢复后的模板跑不起来。
机理：`Initialize` 从方案反序列化库、按 `entry.Mask` 还原涂抹、按条目恢复轮廓与预览。
守门：`【重开】选中条目自动恢复特征预览（参考图 + 绿色轮廓）`、
`【重开】Initialize 从方案恢复涂抹掩膜（橙色显示、可继续编辑）`、
`【重开】模板模型一并恢复（不用重画重学）`、`【重开】恢复后的模板直接可定位`。

**A20 配方选路（八条）**
症状：没给配方名时用了错的条目；未知名字静默回落默认；改名后不生效。
机理：三级顺序是"端口值 → `DefaultTemplateName` → 首条"，且匹配是逐字符。
守门：`【配方】条目 A型 学习成功`、`【配方】条目 B型 学习成功（库 2 条）`、`【配方】运行实例加载到 2 条模板`、
`【配方】RecipeName 为空 → 用默认模板 A型 且回准`、`【配方】RecipeName=B型 → 用 B型模板且回准 (280,360)`、
`【配方】未知配方判失败且列出库里现有的名字`、`【配方】RecipeName 清空 → 回落默认模板 A型`、
`【配方】配方选择与场景内容无关（选 B 就用 B 并如实报告）`。

**A21 老方案迁移必须一次性、可重入**
症状：每次加载都重复迁移（库里长出两条）；迁移出的模板不能定位；迁移字段没清导致重复导入。
守门：`【迁移】老方案单模板字段自动迁入模板库第一条`、`【迁移】迁移后遗留字段清空（防重复导入）`、
`【迁移】迁移出的模板可直接定位`、`【迁移】迁移后的方案再加载不再重复迁移（仍 1 条）`。

**A22 载荷必须能过方案往返**
症状：确认后重开方案"载荷损坏"。
机理：模型与掩膜都是 base64 字符串，走 `InputValues` 的 JSON 快照。
守门：`【序列化】base64 载荷经确认/加载往返无损`。

## B 组（违反后静默出错）

**B1 角度弧度↔度只在一处换算**
症状：`Angle` 差 57.3 倍；或轮廓与数值一起偏（一起偏更难发现）。
机理：端口侧统一"度"，`Angles.Value = angles * 180.0 / Math.PI`；HALCON 侧要弧度。
守门：`【内核】同图角度 ≈ 0（±0.5°）` + `【旋转】角度回准 10°（±0.5°）`（能抓整体错标度，
但"两处都换算错了"这种自洽错**只能靠人工核对**）。

**B2 标量端口是第 0 个实例，不是最后一个**
症状：多目标时界面显示的位置与数组首位对不上；下游抓错件。
机理：排序由算子给出（分数从高到低），插件取 `[0]` 填标量端口。
守门：`【MaxMatches】上限 1 → 只报最高分实例（不越限）`、`【数组】数组端口与实例数逐项对齐`。

**B3 `affine_trans_image` 的参数顺序**
症状：对齐图整体糊掉、或报 `#3147`（插值模式位吃了第三个参数）。
机理：签名是 `(Image, out Result, HomMat2D, Interpolate, AdaptImageSize)`，本处用 `"constant", "false"`。
守门：`【输出】位姿归一化图像已生成`、`【AlignedImage】成功匹配后位姿归一化图非空`
（只验"有没有出图"，**插值质量与幅面要靠人工核对**）。

**B4 原点锚定失败是静默回退**
症状：`Row`/`Column` 与框中心差 1~2px（圆形区域实测约 +1.5,+1.5），不报错。
机理：自匹配（minScore 0.8、单实例、greediness 0.9）拿不到结果就不调 `SetShapeModelOrigin`。
守门：无断言，靠人工核对（`【内核】位置亚像素级回准（150,200 ±0.5）` 能兜住最常见的一次整体偏，
但 ±0.5 的容差恰好盖不住这条，所以改动锚定逻辑时要自己量一次）。

**B5 查找区间不得超出学习时烤入的区间**
症状：改了 `MinAngleDeg` 不重学 → "转过了就丢"，看起来像分数下限太高。
机理：`find_*` 传的是 `minAngle, angleExtent`，超出模型角度集的部分不存在。
守门：`【重学提示】改提取参数（创建态）触发重学提示`（提示层有断言，**行为层没有**，靠界面徽标）。

**B6 界面中文与存盘成员名两条链**
症状：手改方案填了中文形状名 → 区域解析回落默认，模板"莫名"变成矩形。
机理：`Shape` 存 `Rectangle`/`Circle`/`Ellipse` 成员名（R40：候选走 `StepConfigOption.ForEnum`，界面显中文）。
守门：`【圆形模板】圆形区域可学习模板（域任意形状，无矩形硬限制）` 覆盖了 Circle 分支，
成员名字符串本身**无断言，靠人工核对**。

**B7 一个条目只认最后一个句柄**
症状：画了第二个框后，第一个框还看得见但参数不再生效；重开界面只剩一条。
机理：`OnCanvasRoisChanged` 的写回路径只看 `CanvasRois` 最后一项。
守门：无断言，靠人工核对（设计决定，改动时同步改界面提示）。

**B8 `_seedingCanvas` 刹车漏一处**
症状：重开配置框区域翻倍、或条目参数被播种值覆盖。
机理：播种走的是同一个 `CollectionChanged`，靠标志位区分"回填"与"用户操作"。
守门：`【重开】模板模型一并恢复（不用重画重学）`（能抓"数量变了"这一族，
但**成对出现的回环**要看画布条目数，人工核对）。

**B9 `DisplayImage` 的 setter 不释放旧图**
症状：反复载入参考图后内存涨；最后一次那张要等 `Dispose` 才回收。
机理：该属性用普通 `SetProperty`（不释放），换图路径靠各调用点手动 `Dispose`。
守门：无断言，靠人工核对（改载入路径时确认每条都有"释放被替换的旧值"）。

**B10 标注渲染异常被吞**
症状：某轮 `MeasureImage` 为空，但步骤是绿的。
机理：`RenderResultAnnotation` 外层 `catch` 不改成败——"显示层不能把成功的定位判成失败"。
守门：`【未找到】MatchCount=0 且标注图仍生成（产线看现场）` 覆盖了正常路径；
"渲染失败但端口正常"这条分工**无断言，靠人工核对**。

**B11 `PublishPreview` 第二参是窗口号本身**
症状：填 0 也发布、或"窗口9"哪格都不显示。
机理：消费端按 `ViewIndex == 窗口号` 等值筛选，写 `+1` 就整体错一格。
守门：无断言，靠人工核对（断言侧不接视图事件总线；改动时手工投一次图看几号格）。

**B12 并行安全声明的依据**
`[ParallelSafe]` 成立的前提是三条：① 不碰界面（`_isConfigInstance` 拦住所有配置态动作）；
② 不写任何 `static` 可变字段（`EnsureModelLoaded` / `MaskRegionToBase64` 等静态方法只操作入参与临时文件）；
③ 输出的 `HImage` 每轮新建、由基类回收。
违反其中任一条，多分支并行时症状是"偶发错结果而不报错"，**断言抓不到**（现有套件都是单实例跑）。
临时 `.shm` 文件路径要带唯一性，否则并行实例互相读写同一份载荷。
