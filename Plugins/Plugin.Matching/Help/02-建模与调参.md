# 模板匹配 · 建模与调参

这一页讲**怎么把模板学稳**、每个参数**调大调小分别会怎样**、以及"什么现象说明它调错了"。端口与参数清单见第一页，症状与错误文案对照见第三页。

## 一、先把图弄上屏（没图没法画框）

两种方式任选其一。**推荐**：在流程里把上游图像接到 `Image` 端口，然后**试运行一次**——配置界面的画布会自动显示上游那张图（插件盯的是端口的值变化，试运行桥接进来的图也算）。流程还没搭：在「参考图」框里填一张本地图片的完整路径，点「载入」；路径为空会说"还没有参考图路径：填一个图像路径后再点「载入」"，文件不存在会说"参考图不存在：…"。

> **参考图路径只在配置态用**（画框、重学、预览），运行期一律吃 `Image` 端口的图。它是**本机绝对路径**：换电脑后路径失效不影响已学好的模板定位，只影响"重开界面时画布上有没有图"。

## 二、框选模板区域：这一步决定 80% 的成功率

在右侧画布**右键 → 新建矩形 / 圆形 / 椭圆**，框住目标上"**稳定、独特、跟着产品一起动**"的特征。

| 要求 | 为什么 | 现场怎么验 |
| --- | --- | --- |
| **有边界、纹理丰富** | 形状匹配比的是边缘：丝印字符、边角组合、安装孔位、螺栓阵列都是好特征 | 看左下角**模板预览的绿线密度**——绿线就是模型记住的特征边，稀稀拉拉几根就是选错了地方 |
| **独特**（别处不长这样） | 相似的特征会在图的别处也命中，表现成"位置跳到隔壁工件/跳到背景花纹" | 拉远看整幅图：这个模样还有第二处吗？ |
| **稳定**（每批都一样） | 会变的区域（活动件、遮挡物、反光面、换代的丝印版本）把分数拖成随机数 | 连跑 20 帧看 `Score` 的分散度，而不是看一帧 |
| **跟着产品一起动** | 框住了背景 = 定位到背景上，产品偏了看不出来 | 手动把工件挪一点，`Row`/`Column` 必须跟着走 |
| **宁可框大一点** | 分数≈"对上了几成特征"。4 条特征边错 1 条就掉到 75%，40 条错 1 条还剩 97.5%；框大特征多，单条被噪声吃掉不致命 | 前提是**仍然独特**——框大 = 大到把别的花纹也罩进去，反而是坏事 |

三条容易踩的界面口径：**一个条目只认一个区域**，画了第二个框插件以**最新画的那个**为准（前一个作废），想套两个特征就建两条条目；**「清除」只清画布**，清掉的是画布上的框，条目里已学的模型和区域参数不变、运行照旧，真要撤掉这条模板请在模板列表里选中它点「删除」；**三种形状的定位口径一致**——矩形看半长/半宽、圆看半径、椭圆看两个半径，输出的 `Row`/`Column` 都是**你框的中心**（圆形区域只填 3 个数，第 4、5 个是占位 0，看方案 JSON 时别把 0 当成"半径 0"）。

## 三、涂抹编辑：把"会变的部分"从学习里挖掉

框里有反光面、会随批次变的丝印、旁边粘的标签时，别重画框——展开「涂抹编辑」：

1. 模式选**绘制涂抹**，用笔刷（半径 1~50 px，默认 10）把不想学的部分涂成橙色；
2. 涂多了切**擦除涂抹**找回来（红色），彻底重来点「清除涂抹」；
3. **涂完必须重新点「创建模板」**才生效——掩膜只是"下次学习要挖掉哪里"，改它徽标就会转橙；
4. 重开后掩膜会以橙色显示在画布上（随方案存盘，可继续编辑）。

三条判据：**有效排除域 =（绘制 − 擦除）∩ 模板区域**，涂在模板区域**外面**的部分不参与学习（也不报错），别指望"涂一大圈把整个工件圈掉"；**掩膜坐标是参考图的绝对坐标**，换参考图 / 上游换分辨率之前插件会先把当前涂抹按**旧图**坐标系写回条目，换图之后同样的数字含义就变了——**换图后要重新涂**，别看它还显示着就以为对；**验证有没有真挖掉**看重学后信息栏的"载荷 … KB"和预览绿线，挖掉一大块反光面载荷会明显变小、那块绿线会消失，载荷没变说明涂的位置压根没落在模板区域里。

## 四、② 提取参数（创建态）：调大调小的后果

> 改这一区任何一项 → 徽标转橙「参数已改·需重新学习」，**不重学就还是旧模型**；不重学也不会报错，所以这是最容易被忽略的一类"我明明改了角度，怎么还是找不到"。

| 参数 | 调大 | 调小 | 填错的表现 / 建议 |
| --- | --- | --- | --- |
| **金字塔层数**（默认 5，1~10） | 粗找更快、总耗时降；但**太粗会漏掉小目标**（细层还没走到就被粗层的低分否掉了） | 每层都要算，明显变慢；换来的是小特征更稳 | 模板只有几十像素见方 → 层数减到 3~4；模板很大、目标是小特征 → 靠 5~6。**信息栏写的"金字塔 N 层"是模型实际生成的层数**，请求 8 层而模板/图像撑不出那么多时会自动减层——这不是 bug，是提示你"模板太小，用不了这么多层" |
| **最小 / 最大角度**（默认 ±180，可填 -180~180） | 变体数线性上涨：模型明显变大、学习更慢、搜索更慢 | 模型小一大截、搜索快数倍 | **产线偏转小就填 ±15°~±30°，别偷懒留 ±180°**（最划算的一次提速）。填反了（如 30 ~ -30）自动交换。**真实偏转超出这个区间 → 直接找不到**，表现成"转过了就丢"，判据：把工件转到最大角度跑一帧，`MatchCount=0` 就是区间太窄。这个区间是**学习时烤进模型的**，查找只能用烤进去的部分——改了字段不重学，新角度照样找不到 |
| **角度步长**（默认 0 = 自动，0~30 度） | 变体少了、模型小了、快了；但两个变体之间的真实角度靠插值补，**角度回差变大** | 精度更高（`Angle` 更贴真值），模型和耗时一起涨 | 只要位置不要角度 → 放宽；要拿 `Angle` 做旋转补偿（抓取、贴合）→ 收窄到 0.5~1°，或保持 0 让插件按模板尺寸自动定。**自动值在界面上看不到**，想知道实际步长就只能看学习后的耗时与模型载荷 |
| **梯度阈值**（默认 0 = 自动，0~255） | 只留最陡的边：特征数骤减、模型小、抗干扰强；**调太高特征太少 → 分数上不去、位置漂** | 特征变多变啰嗦，**噪声/纹理也被当成特征**，误匹配率上涨 | 先保持 0（让算法按图的对比度自动定）；要手动就小步试（10、20、40…）。判据：预览里绿线糊成一片毛刺 = 太低；绿线只剩一两条 = 太高 |
| **使用极性 / 忽略极性**（默认使用） | 忽略极性：亮暗反相也能命中（光照会整片反相、正反面拍摄的场合才需要），代价是**更慢、更容易误匹配** | 使用极性：黑白方向必须一致才算命中，**又快又准** | 现场表现"白天好、傍晚光变了就丢"→ 先查曝光锁定，再考虑切忽略极性。**切了必须重学**（极性是创建参数） |
| **启用缩放匹配**（默认关，0.5~2） | 开了：远近、批次尺寸差异都能吸收，`Scales` 给出实际倍率；代价是**模型明显更大、学习更慢、搜索更慢** | 关了：只认原尺寸——产品远近会变时表现成"靠得近的镜头那侧找不到" | **非必要不开**（第一提速手段就是关掉它）。上下限填成一样时插件会自动撑开一个极小窗口（HALCON 拒绝退化范围），别以为填 1.0/1.0 就等价于"不开" |

## 五、③ 匹配参数（运行态）：改完立即生效，不用重学

| 参数 | 调大 | 调小 | 判据 |
| --- | --- | --- | --- |
| **分数下限** `MinScore`（默认 0.5，0.01~1） | 更严：误匹配少了，但**遮挡/光照一变就报"未找到目标"** | 更宽容：找得到，但**可能匹配到长得像的别的东西**（更危险，位置是错的却判成功） | 分数本质上就是"对上了几成特征"：**有常态遮挡就按最大遮挡率设**（常态遮住三成 → 上限就在 0.7 附近，定 0.6 而不是 0.5）。找不到时**先降到 0.3 看一眼**：能出结果、分数 0.4 左右 = 光照或模板退化了，去修光或重学，而不是把 0.3 定下来长期用 |
| **匹配数上限** `MaxMatches`（默认 1，1~100） | 多目标计数/抓取场景才调大；数组端口才有第 2、3…个 | 1 = 只报最高分那个 | 想"图里有几个数几个"就调大；**注意 `AlignedImage` 只按最高分那个摆正**，多目标要各自对齐就放多个匹配步骤 |
| **最大重叠** `MaxOverlap`（默认 0.3，0~1） | 允许两个命中的框大面积重叠 → **同一个目标被报两次**（数组里两个位置几乎一样，下游抓两遍） | 去重更狠 → **两个紧挨着的相同工件会被并成一个**（漏数） | 实测口径：模型框 160×160、两个真实目标相距 90px（框重叠约 44%）——填 0.9 报 2 个、填 0.05 只剩 1 个。工件实际间距 ÷ 框宽 就是该填的数量级 |
| **搜索激进度** `Greediness`（默认 0.8，0.1~0.9） | 越快；0.9 = 只往明显更优的方向搜，**边缘情况直接漏** | 越稳（把没希望的方向也扫一遍），越慢 | 节拍紧先试 0.9，**产线偶尔漏检就退回 0.6~0.7**。它是"快 vs 漏"的唯一旋钮 |

## 六、金字塔 / 分数下限 / 激进度这三者怎么配合

一次查找的耗时 ≈ **搜索域大小 × 角度区间宽度 × 缩放区间宽度 × 用到的金字塔层数 × (1 − 激进度)**。**本算子没有"超时"参数**，别指望设个超时兜节拍，只能按下面的顺序砍：① **限制搜索域**（上游接「ROI」的 `Domain_` 输出）——最有效，域外一个像素都不搜，还顺手挡掉相似背景的误匹配；② **收窄角度区间**（±180° → 实际偏转 ±15°），模型和耗时一起降；③ **关掉缩放**（目标大小不变就别开）；④ **提高激进度** 0.8 → 0.9（**先确认没有漏检**再加，这是拿检出率换时间）；⑤ **加金字塔层数**（5 → 6~7，粗筛更快；模板本来就小就别加，减层反而更准）。

反过来"老是找不到 / 位置乱跳"时的顺序是：**先看分数下限是不是被抬太高 → 再看角度/缩放区间是不是太窄 → 最后才看激进度是不是太凶**。这三项调错了会互相伪装成对方的症状：激进度太凶造成的漏检，看起来和分数下限太高一模一样（都是 `MatchCount=0`）；区间太窄看起来像模板学坏了。所以**一次只改一项，改完连跑 10 帧**再决定下一项。

## 七、模板库与配方的管理口径

- **上限 20 条**（方案体积防护：模型和掩膜都是 base64，整库随方案文件走）。满了点「新增」会提示"模板库已满（上限 20 个）——多产品大批量建议拆流程"，**这是建议拆流程，不是让你去改上限**；
- 「新增」自动起名"模板N"并规避重名；名字就是**配方键**（`RecipeName` 按它**逐字符**匹配，大小写与空格都算），改名立刻生效但上游给的名字要跟着改；长期方案是让上位机传字符串变量而不是手打；
- **每条模板各学各的**：提取参数（角度/缩放/步长/梯度/极性/金字塔）跟着条目走，产品 A 要 ±180°、产品 B 只要 ±5° 完全可以共存；分数下限/匹配数/重叠/激进度是**整个步骤共用一套**（运行行为，不分产品）；
- 「设为默认」= 给没接 `RecipeName` 时兜底；**删掉当前条目时默认名自动顺延到库里第一条**（库空了就变空）。改条目名不影响已连的线（连线锚在端口上，条目名只是被查的键）；
- 徽标三态：灰「未学习」→ 框区域、点「创建模板」；绿「已学习」→ 可用；橙「参数已改·需重新学习」→ 再点一次「创建模板」。**橙色时跑流程用的仍是旧模型**（不报错，所以容易被忽略）。

## 八、建模七步（照着做）与上线前压力测试

**七步**：① 接好 `Image`，试运行把上游图带进画布（或填参考图路径点「载入」）；② 模板列表点「新增」，把名字改成产品型号（配方键）；③ 右键新建矩形/圆/椭圆，按第二节框住特征，先看预览绿线密不密；④ 有干扰就展开「涂抹编辑」挖掉，**挖完再点创建**；⑤ 按第四节定提取参数（默认值通常就够，**唯一强烈建议改的是角度区间**）；⑥ 点「创建模板」，看信息栏的金字塔实际层数 / 角度区间 / 特征区域尺寸 / 载荷 KB；⑦ 想长期用就点「确定」落盘（涂抹与库序列化都在这一步写进方案文件）。

**压力测试**（学完不做这几步，上线必翻车）：目标平移到视野**四个角**，每次 `Row`/`Column` 都回准；转到角度区间的**两个端点**（例如 ±15°），`Angle` 回差在允许范围内；光源**调暗 20%、调亮 20%** 各跑一轮，`Score` 不跌破 `MinScore`；拿**另一件同款**跑一遍（特征不该是"这一件的划痕"）；连跑 50 帧记 `Score` 的均值与最低值，**最低值离 `MinScore` 不到 0.05 就是埋了个雷**（迟早跌破）；开了缩放的话把工件抬高/压低到实际极限，看 `Scales` 是否落在设定区间内。
