# 图像预处理 · 端口与参数

> 分类：图像处理 ｜ 来源：插件 Plugin.PreProcessing

本页讲**端口怎么绑、节点级参数填什么、界面上填的值为什么会被改**，以及链是怎么存进方案的。
单个算子自己的参数口径见 `04-算子口径与调参.md`。

---

## 1. 输入端口

| 端口 | 必填 | 可接 | 说明 |
| --- | --- | --- | --- |
| `SrcImage` | 是 | 上游输出图像端口、图像变量、固定图像（界面里的「图像路径」） | 彩色/单通道都能进，但多数算子面向灰度图——链上第一步常放「彩色空间转换」 |

- 端口为空或图像未初始化时，本步骤**直接失败**，原因写 `输入图像为空或未初始化`（三种硬失败之一，另两种见 `05-troubleshooting.md` §1）。
- 已连线的端口不会把固定值写进方案（避免残留脏数据），运行时**以连线为准**。
- 未连线的输入端口会按你填的固定值/变量地址取值。

## 2. 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Image` | 图像 | 预处理后的图像 = 链上**最后一步**的输出（不是当前选中那一步的）。尺寸可能被几何族算子改变，下游做像素级对齐时要留意 |
| `StepCount` | 整数 | 算子总步数，**含被禁用的步骤** |
| `ActiveCount` | 整数 | 启用的算子个数 |
| `ActiveOperators` | 文本 | 启用的算子名按执行顺序用 ` → ` 连接；一个都没启用时输出 `(全部禁用)` |
| `FailedCount` | 整数 | 本轮执行失败的算子个数。0 = 全部跑通；非 0 时**本步骤默认仍算成功**，详见 §3 的「算子失败即失败」 |
| `FailedOperators` | 文本 | 失败摘要 `序号:算子名: 错误消息`（序号是链上的步号，1 基），多条用 `；` 分隔；无失败为空串 |
| `Success` | 布尔 | 本步骤是否跑成（框架自带） |
| `ErrorMessage` | 文本 | 失败原因（框架自带）。勾了「算子失败即失败」时，这里会列出全部失败算子 |

`ActiveOperators` 是上线前最有用的一条：**临时调试关掉又忘了勾回来的步骤，只有在这里能一眼看出来**。
`FailedCount` / `FailedOperators` 是第二条：**默认口径下单个算子失败不会把 `Success` 拉成 false**，
"图看着不对但流程没红"时要靠它们（或配置界面的黄色信息条）确认链里到底跳过了几步、分别是什么原因。
`Success` / `ErrorMessage` 只表达"这一步跑没跑成"，本节点不承担判定与结果上报——那请接各自的专用节点。

## 3. 节点级参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 界面显示 | 说明 |
| --- | --- | --- | --- |
| `DisplayViewIndex` | 1 | 显示窗口：`不显示` / `窗口1~9` | 运行时把预处理结果发布到主界面几号视图。`不显示` = 0，「窗口 N」= N（1~9），与采集插件同一套语义。填 0 不影响 `Image` 输出，只是不占窗口 |
| `FailOnOperatorError` | 不勾选（false） | 左栏「失败处理」区的「算子失败即失败」勾选框 | **默认 false = 跳过失败步继续**，本步骤仍成功（失败记在 `FailedOperators` / `FailedCount`）。勾选 = 任一算子失败 → 链跑完记录全部失败后本步骤判失败，`ErrorMessage` 写 `预处理算子失败：…`。输出端口（`Image` 与统计）在两种口径下都照常赋值 |
| `Chain` | 空链 | 由「处理链」区维护 | 处理链快照：步骤顺序 + 算子标识 + 每步参数 + 每步启用状态。不建议手改 |
| 每步的「启用」 | 勾选 | 处理链行首勾选框 | 算子公共参数。取消勾选 = 图像原样流向下一个算子 |

新建节点即"显示窗口 1"，所以拖进来就能在主界面看到图，不用先设置。

## 4. 界面上填的值为什么会被改

插件在把参数交给底层算子之前会做一轮**收敛**，绝不把非法值丢给图像库（丢进去轻则报错、重则出垃圾数据）。
看到"我填的和你显示的不一样"，先在参数摘要里核对收敛后的值——**以摘要为准**。

| 你填了 | 会变成 | 涉及算子 |
| --- | --- | --- |
| 偶数的模板尺寸 | 自动 +1 成奇数（3~101 / 3~201 范围内） | 高斯滤波、锐化 |
| 0 或负数的模板宽高 | 抬到 1 | 均值滤波、灰度膨胀/腐蚀/开运算/闭运算 |
| 小于 3 的模板宽高 | 抬到 3 | 中值滤波、对比度、均值二值化 |
| 缩放因子超出 0.01~20 | 夹到边界 | 按比例缩放 |
| 增强因子 0 或 1（端点） | 夹到 0.01~0.99 | 对比度 |
| 二值化上下限填反 | 自动交换 | 二值化 |
| 灰度值超出 0~255 | 夹到边界 | 二值化、框外屏蔽、均值二值化 |
| 框宽或高 ≤ 0 | 视为"未框选"，该步透传 | 固定框裁剪、框外屏蔽 |
| 框超出图像范围 | 先夹尺寸再夹位置，把框夹进图内执行，摘要挂"（越界已夹取）" | 固定框裁剪、框外屏蔽 |
| 目标宽高与原图相同（或都填 0） | 透传，不白造一张图 | 修改图像尺寸 |
| 缩放行列因子都是 1 | 透传 | 按比例缩放 |
| 彩色图进二值化 | 自动先转灰度再判决 | 二值化、均值二值化 |
| 灰度图进彩色空间转换 | 原样透传 | 彩色空间转换 |

## 5. 链是怎么存进方案的

- 存盘用**"算子标识 + 参数字典"的弱类型快照**，不写 CLR 类型名：
  改类名、换命名空间、升级版本后，现场已保存的方案仍然打得开。
- **算子的中文显示名不是身份**：改名不影响存量链；能认出旧步骤靠的是内部标识（Key）。
- 参数一律按文本存：枚举存**成员对应的数字**、开关存 `1`/`0`、小数按可完整还原的写法存，
  并且不受系统区域设置影响（小数点不会因为语言环境变成逗号）。
  手工编辑导出的链快照 `.json` 时，枚举也可以直接写成员名——读的时候两种都认。
- 读盘容错：某个参数解析失败就退回该算子的默认值；认不出的算子被跳过并在界面顶部提示，
  **不会让一个脏字段把整份方案卡死**。
- 旧版本里写死或偷偷换算的个别系数（例如均值二值化曾把偏移量除以 100、绝对阈值写死 30）
  已经改成**参数对应底层取值，填多少就是多少**。

## 6. 常见问答

**Q：为什么下拉框里显示的是中文，而导出的 `.json` 里是数字？**
下拉的中文文字是枚举成员随附的说明文本，界面上取它来显示；存盘取的是成员序号（数字）。
两者是同一个成员的不同写法，数字更稳（改中文说明不会破坏存量方案）。

**Q：我在别的地方见过下拉显示英文成员名，这个插件会不会也有？**
本插件界面上**全部**是中文——色彩/通道、镜像方式、旋转角度、模板形状、边缘扩充、插值方式、比较方式
这些候选项都带中文说明，走的是本插件自己的参数面板。
唯一会退回英文成员名的场景：把这些算子参数枚举搬进宿主的**自动参数面板**时（那条路径读另一种显示特性，
而这些枚举目前还没补它）。也就是说，只要你看到的是这个节点自带的配置界面，就不会出现英文下拉。

**Q：均值二值化的「比较方式」在流程里存的是什么？**
成员对应的数字。链快照 `.json` 里手写成员名（例如按大小比较的那种写法）也认，但界面保存后仍是数字。

**Q：`StepCount` 和 `ActiveCount` 不一样说明什么？**
差额就是被取消勾选（禁用）的步骤数。链很长但 `ActiveCount` 很小，说明很多步在透传。

**Q：下游需要区域而不是图像，本节点能给吗？**
不能。本节点只有图像与统计类输出，没有区域端口。要区域请在下游用二值化后的图接 Blob 检测/区域类算子。

**Q：`Image` 出来的图和预览看到的不一样？**
先确认预览停在哪一态：只有"算子输出"是某一步的结果，且它跟着**选中那一步**变；
`Image` 给的永远是**最后一步**。再看是否改完参数没点「确认」。

**Q：`Success` 是 true，`FailedCount` 却不是 0，哪个算数？**
两个都算数，它们回答不同的问题：`Success` 回答"本步骤能不能继续往下走"，
`FailedCount` 回答"链里有没有算子没干活"。默认口径下单个算子失败只跳过那一步，
所以 `Success=true` + `FailedCount>0` 是**预期组合**——下游若不能接受"少跑几步"，
要么把 `FailedCount` 接进判定，要么勾上「算子失败即失败」让 `Success` 直接变 false。

**Q：`FailedOperators` 里的序号是几基？**
1 基，与配置界面处理链左侧的步号一致；格式固定为 `序号:算子名: 错误消息`，
多条之间用全角分号 `；` 分隔。想按算子名过滤时直接 `Contains("算子名")` 即可。
