# 图像预处理 · 排错与提示对照

> 分类：图像处理 ｜ 来源：插件 Plugin.PreProcessing

本页把界面上、日志里、导出时会遇到的**原话**逐条列出来，并说明它意味着什么、该做什么。
文字与源码一致，可以直接对照搜索。

---

## 1. 失败策略：三种情况判失败

- **没有输入图**（端口为空或图像未初始化）→ 本步骤失败，`ErrorMessage` 写
  `输入图像为空或未初始化`。
- **整链跑不起来**（快照或执行本身抛异常）→ 本步骤失败，`ErrorMessage` 写
  `图像预处理失败：…`（后面跟异常原因）。
- **勾了「算子失败即失败」且链上有算子报错** → 本步骤失败，`ErrorMessage` 写
  `预处理算子失败：…`（后面跟全部失败算子的 `序号:算子名: 原因`，用 `；` 分隔）。

除此之外一律**降级**：链上单个算子抛异常只跳过那一步并写一条 Warn（含算子名与原因），
图像继续往后流，**整个流程步骤默认仍算成功**。失败不会丢：
它会同时写进 `FailedOperators` / `FailedCount` 两个输出端口，配置界面的黄色信息条也会列出来。

所以：

- 默认口径下预处理节点不是报警来源。判定与结果上报请接各自的专用节点，
  `Success` / `ErrorMessage` 只表达"这一步跑没跑成"；"链里跳过了几步"看 `FailedCount`。
- 要"错一步就停线"：在配置界面左栏「失败处理」区勾上「算子失败即失败」（存为 `FailOnOperatorError=true`）。
  默认不勾是**刻意**的——既有方案升级后不会因为某个算子偶发失败而突然红掉。
- "画面看着不对但流程没红"先看 `FailedCount` 与界面黄色信息条，
  再去日志里核对"执行失败，已跳过"的原文，而不是等报警。
- 整链全禁用/全透传时本节点会输出一张**复制图**，而不是把上游那张图直接挂到自己的输出端口上
  （否则框架回收图像时会把上游的图一起释放掉）。画面行为一样，内存归属不一样。

## 2. 逐字文案对照表

### 步骤失败（`ErrorMessage`，节点上能看到）

| 原文 | 含义 | 该做什么 |
| --- | --- | --- |
| `输入图像为空或未初始化` | `SrcImage` 没连、连的端口没出图、或那张图已被释放 | 确认下游接的是采集/上一节点的真实输出端口；试运行前先把流程整体跑一遍 |
| `图像预处理失败：…` | 整链跑不起来（取快照、克隆、写端口等环节抛了） | 看后面的原因；内存紧张、上游图已销毁是常见来源 |
| `预处理算子失败：…` | 勾了「算子失败即失败」，且链上有算子报错；后面跟全部失败算子的 `序号:算子名: 原因` | 按原因逐个改参数；只想跳过不想红掉就把「算子失败即失败」取消勾选 |

日志里紧跟一条同样内容的 Error（前缀是该节点的实例名），未捕获异常被框架兜住时另有
`[实例名] 未捕获异常已转为步骤失败：…`，原因文字会是 `异常类型: 消息` 这种格式。

### 运行日志（Warn）

配置期不写流程日志，同样的 Warn 会被预览的黄色信息条收进悬停详情里。

| 原文 | 含义 | 该做什么 |
| --- | --- | --- |
| `实例名 算子[算子名] 执行失败，已跳过：原因` | 这一步被跳过，图像原样往后流 | 按原因改参数；连续多轮出现说明该算子的输入形态和它假设的不一致 |
| `实例名 算子[算子名] 编辑框超出图像范围，已自动夹取到图内执行` | 框越界，插件把框夹进图内再执行 | 把框画回图内。实际生效的框比你填的小，裁出来自然偏 |
| `实例名 预览推送失败：原因` | 推图到主界面视图失败 | **不影响 `Image` 输出**，属"锦上添花"失败。检查视图号是否与主界面窗口对得上 |

### 界面提示

| 原文 | 出现处 | 含义 |
| --- | --- | --- |
| `N 个算子执行失败：序号:算子名: 原因；…` | 配置界面预览区顶部的黄色信息条 | 当前这条链这一轮有几个算子没跑成。悬停可看本轮全部 Warn 原文（含"越界已夹取"）。改完参数重算后自动更新 |
| `有 N 个算子在当前版本中不存在，已跳过：算子标识列表` | 配置界面顶部 | 读盘时认不出的算子被跳过（换版本、换机台常见）。其余步骤照常还原，**按提示把那几步手工补回来** |
| `（越界已夹取）` | 框类算子的参数摘要末尾 | 该步的框超出过图像范围，已夹进图内执行。预览路径的这条 Warn 记在黄色信息条的悬停详情里 |
| `(全部禁用)` | `ActiveOperators` 端口的值 | 链上所有步骤都被取消勾选，`Image` 就是输入的复制图 |

### 输出端口（`FailedCount` / `FailedOperators`）

| 值 | 含义 |
| --- | --- |
| `FailedCount = 0`，`FailedOperators = ""` | 这一轮所有启用的算子都跑通了 |
| `FailedCount = N`，`FailedOperators = 序号:算子名: 原因；…` | N 个算子失败。序号是链上的步号（1 基），多条用全角分号 `；` 分隔。**默认口径下本步骤仍算成功**，这两个端口就是"少跑了几步"的机器可读信号 |

### 复制 / 粘贴 / 导出（底部提示行）

| 原文 | 含义 |
| --- | --- |
| `已复制 N 步到剪贴板（文本格式，可粘到其它方案的本节点）` | 复制成功 |
| `复制失败：剪贴板被其它程序占用，关掉剪贴板工具后重试` | 剪贴板被别的进程（典型是剪贴板管理器、远程桌面）占用，插件已自动重试多次仍失败 |
| `剪贴板里没有文本，先用「复制整链」` | 剪贴板无文本 |
| `剪贴板里的文本不是处理链，需由本插件的「复制整链」得到` | 贴的是别处复制的文本，不是本插件的链格式 |
| `读取剪贴板失败：原因` | 剪贴板读取异常 |
| `已粘贴 N 步到链尾` | 粘贴成功（原有步骤保留） |
| `已粘贴 N 步，跳过 M 步不存在的算子：列表` | 部分粘贴成功，认不出的算子被跳过 |
| `剪贴板里的 N 步在当前版本中都不存在：列表` | 一条都没粘上 |
| `没有输入图像，无法导出：先让上游节点出一张图，或在界面里指定图像变量` | 导出需要底图，当前没有 |
| `已导出 N/M 步图片 + 清单到 目录` | 导出成功 |
| `没有一张图可导出（N 步全是透传或禁用），清单见 文件名` | 链上没有一步真正产出新图 |
| `图片已导出 N 张，但清单写入失败：原因` | 目标目录不可写或文件被占用 |
| `写出失败：原因` | 导出清单里某一步的 PNG 写入失败（该行仍会保留参数摘要） |
| `不支持的导出格式：扩展名` | 导出时给了本插件不认的扩展名（无扩展名也照样报错，写作 `(无扩展名)`） |

导出清单（`.txt`）里每一步还会写：`已禁用，未出图` 或 `透传，未单独出图`——
**禁用与透传的步骤不产 PNG**，这是预期行为，不是漏导出。

## 3. 症状总表：按顺序查

| 现象 | 按顺序查 |
| --- | --- |
| 处理后的图尺寸变了，下游测量全歪 | 链里有没有「固定框裁剪」「修改图像尺寸」「按比例缩放」「图像镜像（对角）」「图像旋转（90/270 度）」——这几种都会改宽高。要保坐标系就换「框外屏蔽」 |
| 某一步勾掉了，画面却没变化 | ① 该算子本来就透传（对灰度图做「彩色空间转换」、框还没拖的「固定框裁剪」、尺寸没变的「修改图像尺寸」、因子都是 1 的「按比例缩放」）；② 该算子这一轮执行失败，按"跳过该步"处理，效果等同禁用——看 `FailedCount` / 黄色信息条，或去日志找"执行失败，已跳过" |
| 图上一个报错都没有，结果却偏了/是空的 | 看参数摘要里有没有「（越界已夹取）」。框超出图像范围时插件**不报错**，而是先夹尺寸再夹位置把框夹进图内执行，实际生效范围比你以为的小 |
| 预览明明好好的、跑起来不对 | ① 改完参数没点「确认」——预览即时重算，运行用的是确认时落盘的链；② 预览停在「输入图」或「原图」态，而 `Image` 给的是**最后一步**的输出 |
| 链越长越慢，节拍顶不住 | 裁剪往前放、必要时先降采样；正式运行跑一步扔一张中间图，慢是**像素量**问题不是内存问题。界面重算慢是**逐步预览**要留住每一步的图，与流程运行无关 |
| 换了台机/升了版本，链少了几步 | 读盘时认不出的算子会被跳过并在顶部提示"有 N 个算子在当前版本中不存在，已跳过：…"——设计行为：不让一个脏字段把整份方案卡死。按提示把那几步补回来 |
| 阈值怎么调都不干净 | 多半不是阈值的问题：先加「直方图均衡」把灰度差摊开，或直接改用「均值二值化」（局部阈值） |
| 二值化之后下游找不到目标，但肉眼看图是对的 | 先看二值化的「反转」有没有勾。约定是**不反转时命中像素为白（255）、背景为黑**，反转后命中变黑。目标显示成黑块还是白块取决于这一位，不取决于原图 |
| 画布上拖了框，参数里中心/宽高还是 0 | 拖框时预览没在「输入图」态，框的坐标基准对不上；切过去重拖 |
| 参数填的和显示的不一样 | 是收敛，不是丢失：偶数模板 → 奇数、越界灰度 → 夹到 0~255、上下限填反 → 交换、缩放因子 → 夹到 0.01~20。以摘要为准 |
| 输入框里的下拉是英文 | 本节点自带界面里**全部**是中文（候选项文字来自枚举成员随附的说明）。若看到英文成员名，说明这一项被搬到了别的面板，见 `03-ports-and-parameters.md` 第 6 节 |
| 导出目录里只有清单没有图 | 全是透传或禁用步骤（见 §2 最后一条），先让链上至少有一步真正出图 |
| 粘贴过去算子顺序不对 | 「粘贴到链尾」是**追加**，原有步骤保留；要整链替换先按「清空」再粘贴 |

## 4. 日志怎么查

- 跳过某步、越界夹取、预览推送失败都是 **Warn** 级别，**不会**在节点上标红。
  排查"没报错但结果不对"时，按实例名过滤流程日志，数一数 Warn 条数；
  配置期不写流程日志，对应的失败与 Warn 在界面黄色信息条（及其悬停详情）里，两边口径一致。
- 上线前的核对项里就有一条：**连续跑 20~50 轮，确认没有偶发的"跳过该步"**。
  偶发说明是**特定那张图**触发的（尺寸/通道/极端灰度），不是参数填错——把触发的那一轮导出来看。
- 导出清单（`.txt`）里的"参数摘要"列就是**执行时真正生效的参数**（含"（越界已夹取）"标记），
  比回忆界面上填过什么可靠。

## 5. 还是解决不了

1. 「导出图片」跑一次，把 PNG + 清单 + 链快照一起留下；
2. 「复制整链」把链文本另存一份；
3. 记录节点实例名、`ErrorMessage` 原话、流程日志里对应的 Warn 原文；
4. 连同上游那张原始图一起反馈给算法同事——**只看最终二值图反推中间步骤，是最慢的路径**。

开发向的实现原因（为什么会出这些现象、代码在哪、改了要动哪）见 `10-dev-architecture.md`、
`11-dev-host-contracts.md`、`12-dev-invariants.md`。
