# 图像预处理

> 分类：图像处理 ｜ 来源：插件 Plugin.PreProcessing

把**色彩与通道、几何调整、滤波、灰度形态学、图像增强、二值化**六族共 21 个算子串成一条处理链，
在同一个节点里逐步预览、单步启停、整链复制与逐步导出，产出一张干净的图给下游的匹配、测量、识别节点。

链的顺序 = 执行顺序：上游的图进第 1 步，第 1 步的输出进第 2 步，最后一步的输出从 `Image` 端口流出。
本插件只做"图像进、图像出"：**不定位、不判定、不输出几何量**，这些请接各自的专用节点。

各算子的参数与调法按族分页说明，见左侧「色彩与通道算子 / 几何调整算子 / 滤波算子 /
灰度形态学算子 / 图像增强算子 / 二值化算子 / 调参与排错」。

## 为什么需要它

传统做法是每种处理各放一个流程节点：一次调参要在五六个节点间来回跳，节点之间连线一断就得重接，
而且"这一步到底把图改成了什么样"只能靠逐个节点跑一遍去看。本插件把这些算子收进**一个节点内部的一条链**：

- **逐步预览**：选中链上任意一步，可以直接看"这一步的输入"和"这一步的输出"，效果差在哪一眼定位；
- **单步启停**：某一算子的"启用"取消勾选，图像原样流过去（透传），不用删步骤就能排除它的干扰；
- **失败隔离**：某个算子这一轮报错，只跳过它这一步，图像继续往后流，整条流程不会因此中断；
- **整链搬运**：「复制整链」把当前所有步骤（含参数与启用状态）拷成文本，「粘贴到链尾」可以并到另一条链上，
  换机台、给同事复现时不用重新调一遍。

## 处理链的三条铁律

这三条决定了"看到的现象"和"参数"之间的关系，先记住再调参：

1. **禁用 = 透传**，不是"这一步没有输出"。取消勾选后图像原样流向下一个算子，
   所以关掉一个算子，画面会立刻回到"没有它"的样子——不会出现"勾掉了但画面没恢复"。
2. **单个算子出错只跳过那一步**。算子抛异常时插件写一条 Warn（含算子名与原因），把当前这张图交给下一步，
   本步骤整体仍然算成功。所以"画面看着不对但没有报警"是设计行为，要查日志里的"执行失败，已跳过"。
3. **图像所有权归插件**。输出端口上的图由框架统一回收，链中间的临时图跑一步扔一张，
   正式运行不会把每步的图攒进内存（只有配置界面的预览会保留中间图）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 是 | 待处理的图像。彩色/单通道都可以，但多数算子面向灰度图——链上第一步常放「彩色空间转换」 |

端口为空或图像未初始化时，本步骤直接失败，原因写 `输入图像为空或未初始化`。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Image` | 预处理后的图像（链上最后一步的输出）。尺寸可能被几何族算子改变，下游做像素级对齐时要留意 |
| `StepCount` | 算子总步数（含被禁用的步骤） |
| `ActiveCount` | 启用的算子个数 |
| `ActiveOperators` | 启用的算子名，按执行顺序用 ` → ` 连接；一个都没启用时输出 `(全部禁用)` |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `DisplayViewIndex` | 1 | 显示窗口：预处理结果运行时发布到主界面几号视图窗口。界面下拉「不显示」= 0，「窗口1~9」= 1~9。填 0 不影响 `Image` 输出，只是不占窗口 |
| `Chain` | 空链 | 处理链快照（步骤顺序、算子标识、每步参数与启用状态），由配置界面「处理链」区维护，不建议手改 |
| 每步的「启用」 | 勾选 | 算子公共参数。取消勾选 = 图像原样流向下一个算子 |

链的存盘用"算子标识 + 参数字典"的弱类型快照，不写 CLR 类型名：改类名、换命名空间、升版本后，
现场已保存的方案仍然打得开。反过来说，**算子的中文显示名不是身份**，改名不影响存量链。

## 配置界面各块做什么

- **图像输入 / 图像路径**：`SrcImage` 端口的绑定入口。点链接按钮选上游端口或变量；
  流程没跑起来时也能手动指定一张图，让预览先动起来。
- **算子库**：按六族分组的算子按钮，**点击即追加到处理链末尾**，按钮的悬停提示就是该算子的用途说明。
- **处理链**：显示"共 N 步"，每行是"步号 + 算子名 + 参数摘要"。可上移/下移/删除/清空，
  行首的勾选框是该步的「启用」。参数摘要里出现"（越界已夹取）"表示该步的框超出过图像范围。
- **预览**：三选一——「原图」= 链的输入那张图；「输入图」= 当前选中那一步的输入；
  「算子输出」= 当前选中那一步的输出（默认态）。
  **带框的算子（固定框裁剪、框外屏蔽）要在「输入图」这一态下拖框**，框的坐标基准就是那张输入图。
- **算子参数**：选中算子的参数面板，改完参数约半秒后自动重算预览；「刷新」是手动兜底。
- **导出图片**：按 `前缀_步号_算子名.png` 一次导出每一步的输出，同目录再生成参数清单（`.txt`）和链快照（`.json`）。
  禁用和透传的步骤不产文件，清单里会写明"已禁用，未出图"或"透传，未单独出图"。
  只想存当前这一张，在画布上右键用「保存原始图像」更快。

## 口径与失败策略

- **只有"没有输入图"和"整链跑不起来"才判失败**。链上单个算子失败一律降级为跳过该步 + Warn 日志。
- **越界不报错，自动夹取**。带框算子的框超出图像范围时，先夹尺寸再夹位置，把框夹进图内执行并写 Warn；
  预览路径没有日志通道，所以提示挂在参数摘要的"（越界已夹取）"上。
  之所以不交给 HALCON 兜底：实测裁剪算子越界不报错，照样返回一张请求尺寸的图，多出来的是垃圾数据。
- **改坏的值会被收敛回合法区间**，不会把非法值喂给 HALCON：填偶数的模板尺寸自动进一位成奇数，
  缩放因子夹到 0.01~20，二值化的上下限填反了自动交换。
- **整链全禁用/全透传时输出一张复制图**，不会把上游那张图直接挂到自己端口上（否则框架回收时会把上游的图一起释放）。
- **读盘时认不出的算子被跳过**，界面顶部提示"有 N 个算子在当前版本中不存在，已跳过：…"，
  其余步骤照常还原，不会让一个脏字段把整份方案卡死。
- 判定与结果上报不在本节点：`Success` / `ErrorMessage` 只表达"这一步跑没跑成"。

## 典型用法 / 接线

```
图像采集.OutputImage ──▶ 图像预处理.SrcImage
图像预处理.Image ─────▶ 模板匹配.SrcImage      （先去噪再匹配）
图像预处理.Image ─────▶ OCR 文本识别.Image      （先裁好、补掉干扰再切字）
图像预处理.Image ─────▶ 结果显示.SrcImage       （底图用处理后的，标注看得清）
```

一条工业上常见的链（顺序即建议顺序）：

```
彩色空间转换(转灰度) → 固定框裁剪 → 均值滤波 → 直方图均衡 → 二值化
```

先转灰度让后续算子面对单通道图；先裁剪把像素量降下来（后面每一步都只算框内）；
再平滑压噪声；灰度差被挤在窄区间时才均衡；最后二值化交给下游。

## 常见问题

**Q：预览画面和运行时输出的图不一样？**
先看预览单选停在哪一态：「原图」是链的输入、「输入图」是选中那一步的输入、「算子输出」才是那一步的结果。
再看选中算子之后的步骤：`Image` 端口给的是**最后一步**的输出，不是选中那一步的。
预览跟随当前参数即时重算，运行时用的是「确认」时落盘的链，改完参数没确认就运行，跑的仍是旧链。

**Q：某个算子勾掉了，画面却没什么变化？**
两种可能：① 该算子本来就透传（例如对灰度图做「彩色空间转换」、框还没拖的「固定框裁剪」，
尺寸没变的「修改图像尺寸」），它有没有都一样；② 该算子这一轮执行失败了，插件按"跳过该步"处理，
效果等同于禁用——去日志里找"算子[…] 执行失败，已跳过"。

**Q：图上一个步骤都没报错，但结果明显偏了/是空的？**
优先查带框算子的参数摘要有没有"（越界已夹取）"。框拖出图外时插件不报错而是夹回来，
实际生效的框比你以为的小，裁出来自然是偏的。另外确认拖框时预览处在「输入图」态——
在别的态下拖的框，坐标基准对不上。

**Q：处理后的图尺寸变了，下游测量结果全错？**
「固定框裁剪」「修改图像尺寸」「按比例缩放」「对角镜像」「图像旋转（90/270 度）」都会改宽高。
下游若拿坐标和原图对齐，必须在改尺寸之前做，或者在下游自己换算。只想"不让下游看见框外"而保持坐标系不变，
用「框外屏蔽」而不是裁剪。

**Q：链越长越慢，节拍顶不住？**
把裁剪尽量往前放（减少后续每一步的像素量），或用「按比例缩放」先降采样提速。
正式运行跑一步扔一张中间图，不攒内存；但配置界面的**逐步预览**要把每一步都留住，
链很长、图很大时界面会重算得慢，这是预览的代价，与流程运行无关。

**Q：想把 A 机台调好的链搬到 B 机台？**
A 上点「复制整链」（含参数与启用状态进剪贴板），B 上在「处理链」区点「粘贴到链尾」，
原有步骤保留。认不出的算子会跳过并提示。要拿去复盘或给算法同事看，用「导出图片」，
它按步号命名出每一步的 PNG + 参数清单 + 链快照。

**Q：二值化之后下游找不到目标，但肉眼看图是对的？**
先看二值化的「反转」有没有勾。本算子约定：**不反转时命中的像素是白（255）、背景是黑**，
反转后命中变黑。目标在图上是黑块还是白块，取决于这一位，不取决于原图。
