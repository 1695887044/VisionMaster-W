# 图像预处理 · 调参与排错

> 分类：图像处理 ｜ 来源：插件 Plugin.PreProcessing

这一页不讲单个算子的参数（那些按族分页写着），讲的是**一条链怎么调**、
以及"画面看着不对但没有报警"时该按什么顺序查。

## 一、先定顺序，再调参数

链的顺序就是执行顺序，顺序错了参数调到死也没用。工业上通用的排布：

```
转灰度 → 裁剪/屏蔽 → 滤波 → 增强 → 形态学 → 二值化
```

- **转灰度放最前**：绝大多数后续算子面向单通道图，彩色图每多走一步就多一倍像素量。
- **裁剪放很前**：后面每一步只算框内，这是最便宜的一次提速（也是最容易忽略的一次提速）。
  只想"别让下游看见框外"但保持坐标系不变，用「框外屏蔽」而不是裁剪——裁剪会改宽高，
  下游拿坐标和原图对齐就全歪了。
- **滤波在增强之前**：锐化会连同噪声一起放大，先压噪声再拉反差。
- **二值化放最后**：它是链的出口。二值化之后一切都变成 0/255，再滤波只会把边缘糊软。

## 二、用「逐步预览」定位问题，不要靠猜

预览三态各回答一个问题：

| 预览态 | 看到的是 | 用它回答 |
| --- | --- | --- |
| 原图 | 链的输入 | "进来的图本来长什么样"——判断是不是上游/光源的问题 |
| 输入图 | **选中这一步**的输入 | "前面几步合起来已经弄成了什么"——也是**拖框类算子的坐标基准** |
| 算子输出 | 选中这一步的结果 | "这一步单独做了什么" |

三条实用纪律：

1. **带框的算子（固定框裁剪、框外屏蔽）必须在「输入图」态下拖框**。在别的态下拖的框，
   坐标基准对不上，实际生效的框比你以为的小。
2. **一步一步往后点，不要只看最后一步**。链上任何一步坏了，最终图都只会表现成"结果不对"，
   看不出是谁干的。选中第 N 步看它的输出，与上一层比对，坏的那一步当场现形。
3. **改完参数要点「确认」再运行**。预览跟着参数即时重算，运行时用的是确认时落盘的那条链——
   这是"预览明明好好的、跑起来不对"的头号原因。

## 三、症状总表

| 现象 | 按顺序查 |
| --- | --- |
| 处理后的图尺寸变了，下游测量全歪 | 链里有没有「固定框裁剪」「修改图像尺寸」「按比例缩放」「图像镜像」「图像旋转（90/270 度）」——这几种都会改宽高。要保坐标系就换「框外屏蔽」 |
| 某一步勾掉了，画面却没变化 | ① 该算子本来就透传（对灰度图做「彩色空间转换」、框还没拖的「固定框裁剪」、尺寸没变的「修改图像尺寸」）；② 该算子这一轮执行失败，插件按"跳过该步"处理，效果等同禁用——去日志找"执行失败，已跳过" |
| 图上一个报错都没有，结果却偏了/是空的 | 看参数摘要里有没有「（越界已夹取）」。框超出图像范围时插件**不报错**，而是先夹尺寸再夹位置把框夹进图内执行，实际生效范围比你以为的小 |
| 链越长越慢，节拍顶不住 | 裁剪往前放、必要时先降采样；正式运行跑一步扔一张中间图，不攒内存，慢是像素量的问题不是内存问题。界面重算慢是**逐步预览**要留住每一步的图，与流程运行无关 |
| 换了台机/升了版本，链少了几步 | 读盘时认不出的算子会被跳过并在界面顶部提示"有 N 个算子在当前版本中不存在，已跳过：…"——这是设计行为：不让一个脏字段把整份方案卡死。按提示把那几步补回来 |
| 阈值怎么调都不干净 | 多半不是阈值的问题：先加「直方图均衡」把灰度差摊开，或直接改用「均值二值化」（局部阈值） |

## 四、失败策略：只有两种情况判失败

- **没有输入图**（端口为空或图像未初始化）→ 本步骤失败，原因写"输入图像为空或未初始化"。
- **整链跑不起来** → 本步骤失败。

除此之外一律降级：链上单个算子抛异常只跳过那一步并写一条 Warn（含算子名与原因），图像继续往后流，
**整个流程步骤仍算成功**。所以预处理节点不是报警来源——判定与结果上报请接各自的专用节点，
`Success` / `ErrorMessage` 只表达"这一步跑没跑成"。

还有一条容易踩的：**整链全禁用/全透传时输出一张复制图**，而不是把上游那张图直接挂到自己的输出端口上
（否则框架回收图像时会把上游的图一起释放掉）。行为一样，内存归属不一样。

## 五、复盘与搬运

- **导出图片**：按 `前缀_步号_算子名.png` 一次导出每一步的输出，同目录再生成参数清单（`.txt`）和链快照（`.json`）。
  禁用和透传的步骤不产文件，清单里写明"已禁用，未出图"或"透传，未单独出图"。
  要给算法同事复盘、或要留下"当时那张图到底被弄成了什么"的证据，用这个。只想存当前一张，画布右键「保存原始图像」更快。
- **复制整链 / 粘贴到链尾**：把当前所有步骤（含参数与启用状态）拷成文本，贴到另一条链的末尾，原有步骤保留。
  换机台、给同事复现同一套预处理，不用重新调一遍。
- 链的存盘用"算子标识 + 参数字典"的弱类型快照，不写 CLR 类型名：改类名、换命名空间、升版本后，
  现场已保存的方案仍然打得开。**算子的中文显示名不是身份**，改名不影响存量链。

## 六、上线前核对

- [ ] 连续跑 20~50 轮，逐轮看 `Image` 输出与最终判定，确认**没有偶发的"跳过该步"**（有就去日志里数 Warn）；
- [ ] 确认下游接的是本节点的 `Image`，不是原始采集图的端口；
- [ ] 看一遍 `ActiveOperators`（启用的算子按执行顺序串起来），确认与你在界面上排的顺序一致——
      临时调试关掉又忘了勾回来的步骤，只有在这里能一眼看出来；
- [ ] 链改过尺寸类算子的，重新核对下游所有坐标（ROI、卡尺位置、显示框）还落在目标上；
- [ ] `DisplayViewIndex` 与主界面的实际窗口号对上（填 0 只是不占窗口，不影响 `Image` 输出）；
- [ ] 把调好的链「复制整链」存一份到别处留底，链快照（导出里的 `.json`）一并归档。
