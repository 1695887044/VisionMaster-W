# Blob 缺陷检测 · 排错

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BlobDetect

按**原文**查：下面每一条都是界面上真会出现的文字（步骤失败原因、信息栏、日志、输入校验），逐字抄自代码。
先分清三件事：**步骤失败**（执行没做成）、**判定 NG**（做成了但判不合格）、**不报错但结果不对**（口径或参数问题）。

## 一、步骤失败（`Success` = false，流程走失败分支）

```
输入图像为空或未初始化
Blob 缺陷检测失败：{异常消息}
Blob 缺陷检测失败：不支持的图像通道数：2（仅支持 1 通道灰度、3 通道彩色或 4 通道 RGBA/BGRA）
像素当量来自上游连线但无效（0）：请检查上游（「标定」步骤本轮是否成功 / 链接的变量是否有值），或改用手填像素当量并断开该连线
```

| 原文 | 为什么会出 | 怎么办 |
| --- | --- | --- |
| `输入图像为空或未初始化` | 上游没连、上游那一步本轮失败（失败步骤的输出端口通常是空的），或端口值为 null / 已被释放 | 先确认上游步骤本轮成功；配置界面里可直接给`输入图像`指定一张图 |
| `Blob 缺陷检测失败：…` | 检测段（转灰度、二值化、形态学、连通域、筛选）抛了 HALCON 或 .NET 异常，前缀告诉你"是在检测这一步炸的" | 看冒号后面那截原文消息；若是通道数问题，上游先转成灰度或 RGB |
| `不支持的图像通道数：N（…）` | 只处理 1（灰度）、3（彩色）、4（RGBA/BGRA，丢 alpha 后转灰度）通道；N 是实际读到的通道数 | 上游加一步通道归一，或改接灰度输出 |
| `像素当量来自上游连线但无效（…）` | `MmPerPixel` 端口已连线，但上游给的值 ≤0 / NaN / Infinity（典型是标定本轮失配） | 这是**故意的**：拿错当量 = mm² 输出整体缩放错，比报错更可怕。让标定先成功，或断开该连线改手填`像素当量` |

> 参数填得离谱**不会**让步骤失败：所有数值进 HALCON 前都会静默夹取（03 页有每一项的区间），
> 所以"配置坏了"最多表现为"结果不对"，不会把整条流程带崩。

## 二、判定 NG（`Success` = true，`IsOk` = false）

`ErrorMessage` 里写的是下面四条之一（按这个顺序检查，只写先命中的那条）：

```
缺陷个数 5 超过上限 3
缺陷个数 0 少于下限 1（目标特征未检到）
最大缺陷面积 1024.5 超过上限 100
缺陷总面积 5300.2 超过上限 2000
```

- NG **不是失败**：流程不会走异常分支，分流请用 `IsOk`，别用执行状态。
- NG 时标注图**照样发布到视图窗口**（默认 1 号窗口）——恰恰是判 NG 时操作员最需要立刻看到缺陷在哪。
- 默认`缺陷个数上限 = 0`（零容忍），一接上就 NG 是正常的，它在提醒"该填规格了"。

## 三、配置界面信息栏原文

| 原文 | 级别 | 含义 |
| --- | --- | --- |
| `输入图像为空：请为上方"输入图像"指定图片，或连接上游图像端口` | 橙 | 还没接图，配置态预览跑不了；不影响流程运行 |
| `正在分析…` | 绿 | 后台线程正在跑全图检测（大图时停一会儿是正常的） |
| `OK：缺陷数 5，最大缺陷面积 201.1 px（在规格内）` | 绿 | 预览判定 OK |
| `NG：最大缺陷面积 1024.5 超过上限 100` | 红 | 预览判定 NG，后面就是第二节那四条原因之一 |
| `已按当前图像（byte / 640×480）适配默认参数：灰度 0~63，面积下限 30、单缺陷上限 100` | 绿 | 自适应做过一次的说明（只在"适配那一次"的刷新里出现） |
| `输入图像取副本失败：…` | 红 | 端口里的图已被释放/未初始化，预览拿不到像素 |
| `预览失败：…` | 红 | 预览这一轮算法或渲染抛异常（只在配置态出现，运行期是第二节那两类） |
| `没有可用的输入图像，无法适配：请先指定图片或连接上游图像端口` | 橙 | 按了「按当前图像重新适配」但没图 |
| `适配失败：灰度范围为无效值（图可能为空）` | 红 | 图上取不到有效灰度范围（域为空或像素值 NaN） |
| `高亮失败：…` | 橙 | 点缺陷清单行时重渲染失败；清单本身不受影响 |
| `无法计算直方图：…` | 红 | 只有直方图这一块降级，检测照常（原因会并进信息栏那条 OK/NG 文案后面） |
| `共 12 个` / `共 480 个（仅列前 200 行）` | 灰 | 缺陷清单行数说明；截断的只是画面与表格，端口永远全量 |

## 四、运行日志原文

```
{InstanceName} 缺陷数=5 最大面积=201.1px 总面积=812.4px 判定=OK
{InstanceName} 缺陷数=9 最大面积=350.0px 总面积=1200.6px 判定=NG（缺陷个数 9 超过上限 3）
{InstanceName} Blob 缺陷检测失败：HALCON error #1304 ...
{InstanceName} 标注图渲染失败，DefectImage 将为空：...
{InstanceName} 逐缺陷特征计算失败（圆度/长宽比/方向角输出为空）：...
```

| 原文片段 | 含义 | 要不要处理 |
| --- | --- | --- |
| `标注图渲染失败，DefectImage 将为空` | 离屏渲染这一层失败（告警级）。**判定与数值端口完全不受影响**，只是没有给人看的图 | 需要证据图时排查；否则可忽略 |
| `逐缺陷特征计算失败（圆度/长宽比/方向角输出为空）` | 补算那三列特征时抛异常，只让那三个端口变空数组 | 下游若依赖这三列要加空数组保护 |
| `Blob 缺陷检测失败：…`（Error 级） | 与第二节同一条原因，同时写进 `ErrorMessage` | 按第二节处理 |

## 五、不报错、但结果不对

| 现象 | 真实原因 | 先查哪里 |
| --- | --- | --- |
| 明明一大片脏污却报 OK | `面积上限`被人填小了——筛选把整片背景"看不见"了（不计数也不判定） | 把`面积上限`归 0（= 不限，自动取图像像素总数） |
| 阈值/面积参数"自己变了" | 只有**配置界面**在所有参数仍为出厂默认值时才自动适配一次；改过就不再覆盖 | 确认是不是配置态实例；若仍出现，确认 `Modules\` 下加载的是本版本 DLL（旧副本残留会让人误以为改动没生效） |
| 改了`检测目标`（暗↔亮）但阈值还停在暗侧 | 守卫逻辑把"改过 DetectTarget"判成"用户调过参数"，于是不再自动适配 | 点「按当前图像重新适配」；阈值若仍等于上次适配出来的值，切目标时会自动补做一次适配 |
| 预览/参数改了不刷新 | 参数改动有 200ms 防抖；预览只在配置界面跑 | 等一下再看；确认不是运行实例 |
| 标注图没有编号/文字 | 缺陷数超过 300 时画面只画前 300 个并写明"（仅绘制前 300 个缺陷）"；渲染整体失败时 `DefectImage` 为空 | 看编号先看`输出排序`，端口与判定仍是全量 |
| 第 3 号缺陷在图上找不到 | 默认`输出排序 = 不排序（区域顺序）`是 HALCON 内部顺序，不保证跨版本一致 | 选`面积从大到小`或`从上到下、从左到右`；编号 1 = 数组第 0 项 |
| 接了 `MaskRegion` 后边界缺陷面积偏小 | 检测区域是推域（`reduce_domain`），压在边界上的缺陷按裁剪后的面积计 | 边界要紧就把 ROI 往外扩一点，或改用`排除区域`做减法 |
| mm² 输出对不上现场尺寸 | 像素当量没接标定，或手填值仍是默认 1.0（此时 mm² 数值 = 像素数值） | 接`MmPerPixel`端口或填准`像素当量`；注意判定永远按像素 |
| 12/16 位相机切不出东西 | `上限灰度`默认 128 隐含 8 位图假设，在 `uint2` 图里落在极暗处 | 按位深换算（12 位约取 2048），或直接点「按当前图像重新适配」 |
| 标注图整片死白、看不出层次 | 16 位图的底图渲染口径问题：按实际灰度范围线性拉伸才是对的，`convert_image_type` 那种"直接转 8 位"是**截断不是缩放**（本算子现行实现已按实际范围拉伸） | 先看数值端口对不对：`DefectCount`/`MaxArea` 正常而只有图发白，就是显示口径，去核对 02 页"标注图的底图口径"；数值也不对才回到上一行 |
| 彩色图检出来的和灰度图不一样 / 怀疑彩色被丢弃 | 检测用的那一路过灰度，底图（标注图）保持彩色，两者不是同一份像素 | 属正常口径（01 页第 ① 步）；要按通道判定就先在「图像预处理」里分离通道，再各接一路 Blob |

## 六、五个输入校验提示（数字框标红时的原文）

```
面积下限不能为空
面积下限必须是数字，当前输入：abc
面积下限不是有效数值
缺陷个数上限必须是整数
面积下限应在 0~1000000000 之间，当前：2000000000
```

界面校验拦下来的是"根本没法解释的输入"；能通过界面但区间仍不合理的值（比如面积填到 1e9）
由算法侧的静默夹取接管，所以现场看到"参数没报错但结果被截"是正常现象，对照 03 页的夹取列即可。

## 七、卡不卡、会不会内存泄漏

- 改参数有 200ms 防抖；全图检测、直方图、标注渲染都在**后台线程**跑，界面不会冻。
- 检测参数（阈值、形态学、筛选等）和源图都没变时，预览只重跑排序与渲染（毫秒级）；
  改`长宽比上限`/`排除触边`/`输出排序`这类"只影响排序筛选"的参数不会重跑全图算法。
- 画面上的编号最多 300 个、清单最多 200 行，防止噪声图上几千个 blob 把渲染拖垮；输出端口永远全量。
- 每轮开头把个数、面积、判定与全部数组端口清零，本轮失败时下游读到的是空值而不是上一轮的脏数据；
  关闭配置窗口时预览图、直方图、清单、离屏渲染窗口一并释放。
