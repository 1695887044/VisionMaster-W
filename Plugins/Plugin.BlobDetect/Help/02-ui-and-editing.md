# Blob 缺陷检测 · 界面与操作

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BlobDetect

配置界面是左右两栏：**左边一列参数卡（从上到下就是检测链路的顺序）**，**右边是预览区 + 信息栏**。
界面里的字段就是插件的参数，名字与 03 页的端口/参数表一一对应；改任何一项都会自动重算预览。

## 六张参数卡

| 卡 | 里面的字段 | 这一卡在管什么 |
| --- | --- | --- |
| 图像输入 | `输入图像`、`检测区域`、`排除区域`、「按当前图像重新适配」按钮 | 图从哪来、只在哪检、哪里一律不报 |
| ① 二值化 | `二值化方式`、`下限灰度`/`上限灰度`、`局部窗口宽`/`高`、`标准差权重`、`绝对灰度偏移`、`检测目标`、`亮暗同检` | 把"可疑像素"切出来 |
| ② 特征筛选 | `面积下限`、`面积上限`、`圆度下限`、`长宽比上限`、`排除触边(px)` | 这东西算不算缺陷 |
| ③ 形态学 | `开运算半径`、`闭运算半径`、`合并半径`、`填孔` | 候选区形状对不对 |
| ④ 判定规格 | `缺陷个数上限`、`缺陷个数下限`、`单个缺陷面积上限`、`缺陷总面积上限` | 这个结果合不合格 |
| ⑤ 输出 | `运行显示窗口`、`像素当量(mm/px)`、`输出排序` | 给下游什么、按什么顺序 |

## 卡内字段的显隐规则

| 条件 | 界面变化 | 为什么 |
| --- | --- | --- |
| `二值化方式 = 固定阈值` | 只显示`下限灰度`/`上限灰度`；**隐藏**`检测目标`与`亮暗同检` | 灰度区间本身已经表达了"要暗的还是亮的"，再摆一个不生效的开关只会让人困惑 |
| `二值化方式 = 自动阈值` | 只显示`检测目标`（+`亮暗同检`），隐藏灰度区间与局部窗口参数 | 分割点由最大类间方差法自己求，没有额外参数可调 |
| `二值化方式 = 动态阈值` | 显示`局部窗口宽`/`高`、`标准差权重`、`绝对灰度偏移`、`检测目标` | 这四个是 `var_threshold` 的入参 |
| 勾上`亮暗同检` | `检测目标`隐藏 | 两种极性都要了，选"亮/暗"就没意义 |

`检测目标`与`亮暗同检`在自动/动态下都有，但**固定阈值下这两项不出现**——这是刻意设计，不是漏显示。

## 右侧预览区

顶部两个页签：**图像视图** / **数据输出**；底部信息栏常显（两个页签共用）。

```
图像视图   标注图：原图 + 缺陷红边 + 每个缺陷中心的红色编号 + 左上角判定横幅
           （横幅内容：判定：OK 或 NG、缺陷数、最大面积；只在总面积规格生效时才加"总面积"行，
             只在像素当量不等于 1.0 时才加 mm² 行。OK 绿字、NG 红字，白底框）
数据输出   缺陷清单（逐缺陷数值） + 灰度直方图（矢量绘制，随窗口缩放）
改参数后   自动刷新：200ms 防抖，全图算法在后台线程跑，界面不冻结
```

**标注图的底图口径**（这几条决定了"图上看到的和实际是不是同一张图"）：

- 彩色图**保持彩色**（只有检测用的那一路过灰度，给人看的底图不动颜色），1 / 3 / 4 通道都能出图；
- **16 位图按实际灰度范围线性拉伸**。这一条别照"直接转成 8 位"理解：`convert_image_type` 是**截断不是缩放**，
  早期版本 12 位相机（0~4095）的标注图会整片死白、看不出任何层次，现在按图的实际灰度范围归一后再落图；
- 缺陷**只画红色描边、不填充**——把可疑区涂实会把产品本身盖住，反而看不出缺陷长什么样；
- 编号写在**外接矩形中心**而不是质心：细长或 L 形缺陷的质心可能漂到区域外面去。

**缺陷清单**的列是：`#`、`面积(px)`、`圆度`、`长宽比`、`宽`、`高`、`行`、`列`。
`#` 就是标注图上写的编号（1 基），顺序与输出数组端口完全一致。
点某一行 → 自动切回「图像视图」，并给那个缺陷套**黄色粗框**（外扩 5 像素的包围盒）——黄框不重跑检测，直接用缓存重渲染。
清单最多列 200 行，超出时表头右侧写明"共 N 个（仅列前 200 行）"；**输出端口永远是全量**。

**灰度直方图**在`固定阈值`方式下会叠两条竖线标记，右上角写着"标记区间 = 当前固定阈值"。

```
按住标记线左右拖   拖动即改 下限灰度 / 上限灰度，实时重算预览
命中判定           离竖线 7 像素以内算抓到；两条线很近时抓更近的那条
拖过另一条线       顶在那条线上，不会交换角色（不会出现"上限变成下限"的跳变）
悬停光标           靠近标记线变成左右调整箭头，提示这里可以拖
下方两行文字       灰度范围：min ~ max      图像类型：byte（8 位）
```

只有在`固定阈值`方式下标记线才可拖（`自动阈值`/`动态阈值`没有可拖的区间）。直方图取不到时只在图上显示原因文字，不影响检测本身。

## 按钮与操作

| 元素 | 做什么 | 注意 |
| --- | --- | --- |
| 「按当前图像重新适配」 | 按当前输入图像的实际灰度范围与分辨率，换算固定阈值上下限与面积规格 | 只改`下限灰度`/`上限灰度`/`面积下限`/`单个缺陷面积上限`这四值；不动二值化方式、检测目标、形态学参数。手动按下任何时候都生效 |
| 页签「图像视图」/「数据输出」 | 切换右侧内容 | 点清单行会自动切回图像视图，否则黄框看不见 |
| 数字框输入非法值 | 输入框标红并给出原因（如"面积下限应在 0~1000000000 之间"） | 这是界面校验；算法侧还有一层静默夹取，见 05 页 |

## 界面原文（照抄，便于对照）

```
首次加载图像时，若参数仍是出厂默认值会自动适配一次；一旦改过参数就不再自动覆盖（避免软件静默改掉你调好的值）。
检测/排除区域可不接：接了就只在区域内检测/把区域内的一律丢弃。

上下限填反了会按区间自动排序，不会报错。
自动求分割点（最大类间方差法），适合来料灰度整体漂移、不方便固定阈值的场合，无需额外参数。
筛选掉的不计数也不判定；判定规格在下面第 ④ 区，两者是两回事。
开/闭运算填 0 表示跳过该步（默认两步都跳过）。
判定：个数超出上/下限、单个面积或总面积超出上限，任一命中即 NG。
接线取值：把「标定」插件的 MmPerPixel 输出连到本步骤的输入端口「MmPerPixel」，运行时自动以标定当量为准
（本框数值作为未接线时的兜底；上游标定失败会直接判失败，不会拿旧值硬算）。
```

## 常见疑问

**为什么下拉框里是"固定阈值/暗缺陷/面积从大到小"这些中文，而不是 `Fixed`/`Dark`/`AreaDescending`？**
这些名字来自枚举成员上的 `[Display(Name = "…")]`，界面用同一个转换器读特性显示，
所以中文名只有一份真相；新增一个枚举值，界面自动多一项，不需要改界面代码。
03 页表格里同时给出中文标签与英文属性名，连线、写下游脚本时以英文名为准。

**为什么直方图下面那行写的是 `byte（8 位）` / `uint2（16 位）`，"byte" 没翻译？**
`byte` / `uint2` 是 HALCON 自己的像素类型名（`get_image_type` 的返回值），界面对它是照抄不译，
括号里的位深才是给操作员看的换算。调 12/16 位相机时这个字段很关键：`上限灰度` 是绝对灰度值，
`uint2` 图的可用区间比 8 位图宽两个数量级，别照搬 8 位图的数值。

**「运行显示窗口」里为什么有"图像窗口1…图像窗口9"和"不显示"？**
它对应参数 `DisplayViewIndex`（0~9）：1~9 = 正式运行时把标注图发布到主界面第几号视图窗口，
0（显示为"不显示"）= 不发布。**只影响正式运行**，配置界面里的预览始终显示；填 0 时 `DefectImage` 端口照样给下游存图。

**为什么我把参数改乱了，想让软件按这张图重来一次？**
点「按当前图像重新适配」。注意自动适配那条路只在**所有参数都还是出厂默认值**时才走，
改过任何一项就不再自动覆盖（这是工业软件的硬要求：绝不静默改掉你调好的值），所以"重来"必须手动按下。
