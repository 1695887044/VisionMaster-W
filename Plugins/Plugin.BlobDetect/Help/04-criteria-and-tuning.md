# Blob 缺陷检测 · 检测口径与调参

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BlobDetect

这一页讲**怎么把它调到能用**：先建立三条口径（判定怎么算、筛选与判定的分界、三种二值化怎么选），
再沿"二值化 → 形态学 → 连通域与筛选 → 判定"这条链路逐段判读标注图，最后按现象查参数。
所有取值与文案都对应界面上的实际字段（字段名见 03 页）。

## 一、判定口径：四条规格，任一命中即 NG

```
缺陷个数 >  缺陷个数上限            → 缺陷个数 N 超过上限 M
缺陷个数 <  缺陷个数下限            → 缺陷个数 N 少于下限 M（目标特征未检到）
最大单缺陷面积 > 单个缺陷面积上限    → 最大缺陷面积 X 超过上限 Y
缺陷总面积  > 缺陷总面积上限        → 缺陷总面积 X 超过上限 Y
```

- 四条按上面这个顺序检查，`ErrorMessage` 里只写**先命中的那一条**，措辞与界面字段名一致，方便现场对照。
- 三项"上限"和"下限"里的 `0` 语义：`缺陷个数上限 = 0` 是**零容忍**（有缺陷就 NG）；
  `缺陷个数下限`、`单个缺陷面积上限`、`缺陷总面积上限`的 0 都是**不做这项判定**。
- **NG 不是失败**：判 NG 时步骤 `Success` 仍为 true，流程照走，只是 `IsOk` = false 且原因写进 `ErrorMessage`。
  分流请用 `IsOk`，别拿执行状态当判定。

## 二、筛选 ≠ 判定（读懂这条少踩 80% 的坑）

| 概念 | 问的问题 | 涉及参数 | 超了会怎样 |
| --- | --- | --- | --- |
| **筛选** | 这个东西**算不算缺陷** | `面积下限` `面积上限` `圆度下限` `长宽比上限` `排除触边(px)` | **不计数**，等于根本没看见：既不报数也不判 NG |
| **判定** | 这个缺陷**合不合格** | `缺陷个数上限` `缺陷个数下限` `单个缺陷面积上限` `缺陷总面积上限` | **判 NG**（但仍算执行成功） |

> 这两套参数早期版本是合一的，筛选上限写死在一个常量（1e7）上，结果**大画幅相机（>1000 万像素）上整块背景被静默滤掉——漏检还报 OK**。
> 现在筛选上限默认自动取"图像像素总数"，与判定彻底分开。现场若出现"明明一大片脏污却报 OK"，先查`面积上限`是不是被人填小了。

## 三、三种二值化怎么选（新手最容易卡的地方）

| 方式 | 底层做法 | 什么时候用 | 要调的参数 |
| --- | --- | --- | --- |
| `固定阈值` | 灰度落在 `[下限灰度, 上限灰度]` 区间的像素全要 | 背景干净、打光稳定、缺陷与背景灰度差明确 | 下限/上限灰度 |
| `自动阈值` | 最大类间方差法（Otsu）自动找"最能分开两类"的分割点 | 来料灰度整体漂移、换型不想重调阈值 | 只选亮/暗极性，无需额外参数 |
| `动态阈值` | 拿每个像素跟它**周围一小块**的局部统计量比，比局部背景暗/亮多少就提出来 | **打光不匀、曲面、有渐变**——固定阈值在这种图上一头判死一头漏检 | 局部窗口宽/高、标准差权重、绝对灰度偏移 |

- `检测目标`（`亮缺陷` / `暗缺陷`）是"缺陷比背景亮还是暗"的统一开关，自动/动态下靠它决定取亮侧还是暗侧；固定阈值下这一项不显示。
- `亮暗同检`只在自动/动态下生效：两种极性各做一次二值化再取并集，一次把"暗划痕 + 亮亮点"都检出，代价是要多跑一遍分割。
- 勾上`亮暗同检`后`检测目标`自动隐藏（两种都要了，它就没意义了）。

## 四、沿链路定位问题：四段判读法

出问题时先判断"是哪一段把缺陷弄丢了"，别一上来就改判定阈值。

### 第 1 段｜二值化（可疑像素切出来了吗）

| 现象 | 判读 | 处理 |
| --- | --- | --- |
| 标注图上整片都红 | 阈值太宽，背景被整片切进来 | 收窄灰度区间；动态阈值则调大`标准差权重`/`绝对灰度偏移` |
| 缺陷区域只有薄薄一圈边 | 固定阈值下缺陷灰度不均，只切到了边缘 | 换`动态阈值`；或把区间放宽后靠`面积下限`兜 |
| 打光不匀：左边全红、右边全空 | 全局阈值处理不了局部光照差 | 换`动态阈值`，`局部窗口宽/高`取**缺陷尺寸的 2~3 倍**（窗口比缺陷小，缺陷本身会被当成本地背景而消失） |
| 检出一堆比头发丝还细的毛刺 | 噪声像素连成片 | `开运算半径`从 1 起加；或调大`面积下限` |

### 第 2 段｜形态学（候选区域形状对不对）

| 现象 | 处理 |
| --- | --- |
| 一条划痕被断成三四段、个数虚高 | `合并半径`：从缺陷段间宽度的**一半**往上取（它按"间距 < 2×半径"合并）；先试 1~2 倍噪声间距 |
| 缺陷内部有亮点、面积偏小或被拆成两个 | 勾`填孔`（按外轮廓算面积）；或`闭运算半径`补内孔 |
| 两个相邻的小麻点被合成一个大缺陷、误判面积超标 | `合并半径`调小或归 0，`闭运算半径`调小 |
| 缺陷旁边挂着毛刺导致长宽比失真 | `开运算半径`磨掉毛刺，再看`长宽比上限` |

> `合并半径`这一步内部是"先 `union1` → 闭运算 → 再 `connection`"，所以它是**跨连通域**的合并；
> 而`闭运算半径`只在候选区上连断口。直接对区域数组做形态学，HALCON 是逐对象处理，合不到一起。

### 第 3 段｜连通域与特征筛选（这个算不算缺陷）

| 现象 | 处理 |
| --- | --- |
| 小缺陷被当成噪点丢了 | `面积下限`调小。**注意单位是像素**：换相机/改 ROI 后同一物理缺陷的像素面积会变 |
| 整片背景脏污既不计数也不 NG | `面积上限`被人填小了。0 = 不限，此时上限自动取图像像素总数 |
| 想只报气泡、不报划痕 | `圆度下限`（气泡高、划痕约 0.02~0.1）或`长宽比上限`（划痕比值大，滤长条就填 3） |
| 想只报划痕、不报圆点 | `长宽比上限`没有"下限"语义——把`圆度下限`填低配合其它筛选更别扭；下游取`DefectCircularities`/`DefectAspectRatios`数组分流才是干净做法 |
| 画面边缘（右缘/底缘）稳定误报 | `排除触边(px)`设边界带宽。ROI 只能整体裁形状、没法"往里缩一圈"，所以这条必须在插件里做 |
| 固定位置（螺丝孔/二维码）总误报 | 接`排除区域`端口，触边参数管不到画面中间 |

### 第 4 段｜判定（合不合格）

| 现象 | 处理 |
| --- | --- |
| 良率明明很高却大批 NG | 先分清是**筛选没滤干净**还是**规格太严**：看`DefectCount`与`MaxArea`，再对照 NG 原因文案（个数超标 / 个数不足 / 单缺陷面积 / 总面积） |
| "每个都合格、整片却像发霉"照样 OK | 填`缺陷总面积上限` |
| "这个标记怎么没了"没报警 | 填`缺陷个数下限`（存在性检测专用，0 = 不判定） |
| 想表达"任何缺陷都不允许" | `缺陷个数上限 = 0`（零容忍），不要靠把`单个缺陷面积上限`填 0——0 的语义是"不做这项判定" |

## 五、按现象查参数（速查表）

| 现象 | 调哪里 |
| --- | --- |
| 漏检（缺陷没检出来） | 看直方图重设`下限/上限灰度`；或`面积下限`太大；或极性选反 |
| 误检（背景当缺陷） | 阈值收窄；`面积下限`调大；`标准差权重`/`绝对灰度偏移`调大 |
| 打光不匀、一头漏一头死 | 换`动态阈值`，`局部窗口宽/高`取缺陷尺寸的 2~3 倍 |
| 缺陷个数虚高（一条划痕算多个） | `合并半径`；或`闭运算半径`连断口 |
| 边缘总有假缺陷 | `排除触边(px)` |
| 只想看某一块区域 | 接`检测区域`（`MaskRegion`） |
| 缺陷有孔洞导致面积偏小 | 勾`填孔` |
| 大画幅相机（>1000 万像素） | 面积类规格按面积比例放大；`面积上限`保持 0 |
| 报表要"最大缺陷排第一" | `输出排序 = 面积从大到小` |
| mm² 输出对不上现场尺寸 | 接`MmPerPixel`或填准`像素当量`；注意判定仍按像素，不会因当量改变 |

## 六、四个常用配方

**案例 1｜固定阈值检暗斑（最常用）**
`二值化方式 = 固定阈值`、`检测目标`不显示（区间自己表达）；直方图把`上限灰度`拖到背景主峰的左肩
（例：背景 180~200，缺陷 90~140 → 区间 0~150）；`面积下限 = 30`；`缺陷个数上限`按规格。

**案例 2｜动态阈值（打光不匀的救命稻草）**
`二值化方式 = 动态阈值`、`检测目标 = 暗缺陷`；缺陷约 5 像素宽 → `局部窗口宽/高 = 15`；
`标准差权重 = 0.4` 起步，误报多就加到 0.8~1.2；低对比区域漏检就适当加大`绝对灰度偏移`（太严则减小）。

**案例 3｜合并断裂的划痕**
一条 60 像素长的划痕被打光切成 3 段、段间空隙约 4 像素 → `合并半径 = 3`（空隙 < 2×3），个数从 3 变 1，面积也合并成真实值。

**案例 4｜排除触边 + 排除区域**
透明膜卷边缘反光稳定误报，宽度约 12 像素 → `排除触边(px) = 15`；画面中间的二维码用`排除区域`端口接它的 ROI。

## 七、上线前检查清单

- [ ] 用**良品 + 已知 NG 样**各跑一批，确认 `IsOk` 与人工判定一致；
- [ ] NG 原因文案能在现场说清楚（个数超标 / 个数不足 / 单缺陷面积 / 总面积）；
- [ ] `运行显示窗口`设好（1~9），操作员能立刻看到缺陷在哪；不需要发窗口就填 0，`DefectImage` 照样给下游存图；
- [ ] `输出排序`与报表口径一致（默认"不排序"的顺序不可预期）；
- [ ] 像素当量与标定连线口径确认（接了标定就以标定为准）；
- [ ] 面积/个数规格是**像素**口径，换相机分辨率后必须重算；
- [ ] 若用了`检测区域`，确认边界上的缺陷按裁剪后面积计是可接受口径（压在 ROI 边上的缺陷面积会偏小）。
