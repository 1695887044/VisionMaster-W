# Blob 缺陷检测

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BlobDetect

把图里"比背景暗（或亮）的可疑像素"切成二值区域 → 拆成一个个连通域 → 按面积/圆度/长宽比/触边筛掉噪声 → 数个数、量面积 → 与规格比对给出 **OK/NG**，同时叠一张**红圈 + 逐缺陷编号 + 判定文字**的标注图。
它解决的是"**有没有缺陷、有几个、最大多大、合不合格**"——划痕、暗斑、脏污、气泡、麻点、异物这类检测的主力算子。

## 为什么需要它 / 原理

模板匹配解决"目标在哪"，预处理解决"图干不干净"，**Blob 解决"有没有异常"**。它靠**规则**（灰度、面积、形状）判定，不需要训练样本；缺陷种类说不清规则、只能"靠经验认"的场合，改用「YOLO 目标检测」或「深度学习分类」。

### 五步流水线

```
① 转灰度   → 彩色/多通道图归一成单通道（1 通道直接用，3 通道彩色转灰度，4 通道丢 alpha 再转）
② 二值化   → 按阈值把"可疑像素"切出来（固定 / 自动 / 动态三种方式）
③ 形态学   → 开运算去毛刺、闭运算补孔连断口、合并半径把断成几段的划痕接回去
④ 拆连通域 → connection 把一片片区域拆开，每片 = 一个候选缺陷
⑤ 筛选+判定 → 按面积 / 圆度 / 长宽比 / 触边筛掉噪声，再与规格比对给 OK/NG，并叠标注图
```

### 三种二值化方式怎么选（新手最容易卡的地方）

| 方式 | 底层做法 | 什么时候用 | 要调的参数 |
| --- | --- | --- | --- |
| `固定阈值`（Fixed） | 灰度落在 `[下限灰度, 上限灰度]` 区间的像素全要 | 背景干净、打光稳定、缺陷与背景灰度差明确 | `MinGray` / `MaxGray` |
| `自动阈值`（Auto） | 最大类间方差法（Otsu）自动找"最能分开两类"的那个分割点 | 来料灰度整体漂移、换型不想重调阈值 | 只选亮/暗极性，无需额外参数 |
| `动态阈值`（Dynamic） | 拿每个像素跟它**周围一小块**的局部统计量比，比背景暗/亮多少就提出来 | **打光不匀、曲面、有渐变**——固定阈值在这种图上一头判死一头漏检 | `VarMaskWidth/Height`、`VarStdDevScale`、`VarAbsThreshold` |

- `检测目标`（`亮缺陷` / `暗缺陷`）是"缺陷比背景亮还是暗"这一件事的统一开关，自动/动态阈值下都靠它决定取亮侧还是暗侧。**固定阈值下这一项不显示**——灰度区间本身已经表达了极性。
- `亮暗同检`（`DetectBrightAndDark`）只在**自动/动态**下生效：两种极性各做一次二值化再取并集，一次把"暗划痕 + 亮亮点"都检出。勾上后`检测目标`也会隐藏（两种都要了，它就没意义了）。

### 筛选 ≠ 判定（读懂这条少踩 80% 的坑）

| 概念 | 问的问题 | 涉及参数 | 超了会怎样 |
| --- | --- | --- | --- |
| **筛选** | 这个东西**算不算缺陷** | `MinArea` `MaxBlobArea` `MinCircularity` `MaxAspectRatio` `ExcludeBorderPx` | **不计数**，等于根本没看见（既不报数也不判 NG） |
| **判定** | 这个缺陷**合不合格** | `MaxDefectCount` `MinDefectCount` `MaxSingleArea` `MaxTotalArea` | **判 NG**（但仍算执行成功） |

> 这两套参数早期版本是合一的，把筛选上限写死在一个常量上，结果**大画幅相机（>1000 万像素）上整块背景被静默滤掉——漏检还报 OK**。现在筛选上限默认自动取"图像像素总数"，与判定彻底分开。现场若出现"明明一大片脏污却报 OK"，先查`面积上限`是不是被人填小了。

### 标注图

原图（彩色保持彩色，16 位图按实际灰度范围线性拉伸）上画：缺陷**红色描边**（只画轮廓、不遮挡产品）、每个缺陷中心写**红色编号**（1 基，顺序 = 输出数组顺序 = 配置界面缺陷清单的行号）、左上角**判定横幅**（`判定：OK/NG`、缺陷数、最大面积，OK 绿字 / NG 红字，白底框）。
配置界面里点缺陷清单的某一行，图上会额外给那个缺陷套**黄色粗框**联动高亮。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 是 | 待检测的输入图像（`HImage`）。为空或未初始化 → 本步骤**失败** |
| `MaskRegion` | 否 | **检测区域**：只在该区域内找缺陷（接「创建 ROI」的 `MaskRegion`）。语义与 `reduce_domain` 一致——候选区先与它取交集再走后续处理，**压在区域边界上的缺陷按裁剪后的面积计**。不连 = 整图检测 |
| `ExcludeRegion` | 否 | **排除区域**：区域内的候选一律丢弃。用在校固定位置的误检源——螺丝孔、二维码、标记载体（`排除触边`只能处理图像边缘，处理不了画面中间的干扰） |
| `MmPerPixel` | 否 | **像素当量直连口**（mm/px）：接「标定」插件的 `MmPerPixel` 输出，也可链接运行时变量。**未接线**时用配置项`像素当量`（默认 1.0，即旧行为）；**已接线但上游值无效**（≤0 / NaN，典型是标定步骤本轮失败）→ 本步骤**明确失败**，绝不静默回退旧值 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `DefectImage` | 标注图（原图 + 缺陷红圈 + 编号 + 判定文字）。渲染失败时为空，见"口径与失败策略" |
| `Defects` | 缺陷区域对象集合（`HRegion`），可直接给下游做进一步分析或存图 |
| `DefectCount` | 缺陷个数（已按筛选条件过滤） |
| `MaxArea` | 最大单缺陷面积（**像素**） |
| `TotalArea` | 缺陷总面积（**像素**）——"每个都合格但整片脏污"只有它能兜住 |
| `IsOk` | 判定结果（true = OK 合格） |
| `CenterRows` / `CenterCols` | 各缺陷中心行/列坐标数组（图像像素系） |
| `DefectAreas` | 各缺陷面积数组（像素） |
| `DefectWidths` / `DefectHeights` | 各缺陷外接矩形宽/高数组（像素，= 边界差 + 1） |
| `DefectCircularities` | 各缺陷圆度数组（0~1，1 = 正圆，细长划痕约 0.02~0.1，方块约 0.67） |
| `DefectAspectRatios` | 各缺陷长宽比数组（外接矩形 长边/短边，正方形 = 1，越大越细长） |
| `DefectPhis` | 各缺陷方向角数组（**度**，-90~90，等效椭圆主轴与水平方向夹角）。圆形缺陷的方向无意义，只对细长缺陷有参考价值 |
| `MaxAreaMm2` / `TotalAreaMm2` | 最大/总面积的毫米平方口径 = 像素面积 × 像素当量² |

> **顺序契约**：上面 8 个数组端口（`CenterRows` `CenterCols` `DefectAreas` `DefectWidths` `DefectHeights` `DefectCircularities` `DefectAspectRatios` `DefectPhis`）与 `Defects` 集合**逐项对齐**，下游按同一个索引取就能对上号，编号 1 对应数组第 0 项。HALCON 的区域数组本身**没有顺序约定**，顺序一律由配置项`输出排序`定死。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

### ① 二值化

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ThresholdMode`（二值化方式） | 固定阈值 | 固定 / 自动 / 动态，切换后界面只显示该方式自己的参数 |
| `DetectTarget`（检测目标） | 暗缺陷 | 亮缺陷 / 暗缺陷；固定阈值下不显示（区间自己表达极性） |
| `DetectBrightAndDark`（亮暗同检） | false | 仅自动/动态生效：两种极性各切一次取并集 |
| `MinGray`（下限灰度） | 0 | 固定阈值区间下界（含） |
| `MaxGray`（上限灰度） | 128 | 固定阈值区间上界（含）。**128 是 8 位灰度图的中位**，是"不针对任何产品"的通用起点。⚠ 这是**绝对灰度值**、隐含 8 位图假设：12/16 位图（uint2）要按位深换算（12 位约取 2048） |
| `VarMaskWidth`（局部窗口宽） | 15 | 动态阈值的邻域宽度（像素）。要**略大于缺陷尺寸**（现场经验取缺陷宽度的 2~3 倍），否则缺陷本身会被当成本地背景而检不出 |
| `VarMaskHeight`（局部窗口高） | 15 | 同上，邻域高度 |
| `VarStdDevScale`（标准差权重） | 0.4 | 局部标准差乘的系数：**越大越严格、检出越少** |
| `VarAbsThreshold`（绝对灰度偏移） | 2 | 相对局部均值的固定灰度偏移量，兜底对比度很低的区域；调大 → 只报反差明显的 |

### ② 特征筛选

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `MinArea`（面积下限） | 30 | 小于它（**像素**，不是毫米）的连通域当噪点丢弃。噪声多就调大 |
| `MaxBlobArea`（面积上限） | 0 | 超过它的连通域**直接不算缺陷**（不计数也不判定）。0 = 不限，此时自动取"图像像素总数" |
| `MinCircularity`（圆度下限） | 0 | 0~1，1 = 正圆；只保留圆度不低于它的候选，用来把"圆形斑点"与"细长划痕"分开。0 = 不按圆度筛 |
| `MaxAspectRatio`（长宽比上限） | 0 | 外接矩形 长边/短边（正方形 = 1，越大越细长）；只保留不超过它的候选。**想滤掉长条划痕**就填小（如 3），**想只留长条**就把它调大配合圆度用。0 = 不按长宽比筛 |
| `ExcludeBorderPx`（排除触边） | 0 | 边界带宽（像素）：缺陷外接矩形碰到图像（或 ROI 外接矩形）最外 N 像素就丢弃——打光/裁切边缘效应是固定误检源。0 = 不排除 |

> 长宽比不用 HALCON 的 `elongation` 特征：本仓 HALCON 版本不认识该特征名（报 `#3101`），插件改用外接矩形自己算，语义一致且跨版本成立。

### ③ 形态学

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `OpenRadius`（开运算半径） | 0 | 先腐蚀后膨胀：磨掉细小毛刺、断开粘连细桥。0 = 不做 |
| `CloseRadius`（闭运算半径） | 0 | 先膨胀后腐蚀：补上缺陷内部小孔、连接断裂的划痕。0 = 不做 |
| `FillHoles`（填孔） | false | 缺陷内部有亮斑/反光时会把一个缺陷"挖成环形"（面积偏小、甚至拆成多个）。勾选后按外轮廓算面积 |
| `MergeRadius`（合并半径） | 0 | 把间距小于 **2×半径** 的几段连成一个缺陷。一条划痕常被噪声断成三四段、个数虚高好几倍，用它合回去。0 = 不合并 |

> 顺序是固定的：**开 → 闭 → 拆连通域 → 合并 → 填孔 → 特征筛选**。合并必须"先 `union1` 再闭运算再 `connection`"——直接对区域数组做形态学，HALCON 是逐对象处理，合不到一起。

### ④ 判定规格

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `MaxDefectCount`（缺陷个数上限） | 0 | 缺陷个数超过它即 NG。**0 = 零容忍**（一个都不允许） |
| `MinDefectCount`（缺陷个数下限） | 0 | 缺陷个数少于它即 NG。用在**存在性检测**（"这个标记在不在"）——一个都没检到恰恰是坏消息。0 = 不做这项判定 |
| `MaxSingleArea`（单个缺陷面积上限） | 100 | 最大单缺陷面积（**像素**）超过它即 NG。0 = 不做这项判定 |
| `MaxTotalArea`（缺陷总面积上限） | 0 | 所有缺陷面积之和超过它即 NG。每根单独看都合格、但整片脏污/麻点密布时只有它能兜住。0 = 不做这项判定 |

> 默认 `MaxDefectCount = 0` 是**有意的**——通用平台算子不该假装知道你产品的规格。一上手就看到 NG 是正常的，它在提醒"该填规格了"。

### ⑤ 输出

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `PixelSizeMm`（像素当量） | 1.0 | mm/px。1.0 = 输出的 mm² 数值等于像素值（不假设标定）。标定后填真实值，`MaxAreaMm2`/`TotalAreaMm2` 即为物理量。**已接 `MmPerPixel` 端口时以连线值为准，本框只作未接线时的兜底** |
| `SortMode`（输出排序） | 不排序（区域顺序） | 不排序（区域顺序） / 面积从大到小 / 从上到下、从左到右。决定 8 个数组端口与 `Defects` 的输出顺序，标注图编号也跟着走 |
| `DisplayViewIndex`（运行显示窗口） | 1 | 正式运行时把标注图发布到主界面几号视图窗口（1~9）；选"不显示"（0）则不发布。**NG 也会发布**——判 NG 时操作员最需要立刻看到缺陷在哪。只影响正式运行，配置界面里的预览始终显示 |

## 口径与失败策略

- **NG 不是执行失败**：判定 NG 是**正常结果**（`Success` 仍为 true），只把原因写进 `ErrorMessage`（形如"缺陷个数 5 超过上限 3"）。只有输入为空、像素当量非法、算法抛异常才判失败。
- **执行失败**：`SrcImage` 为空/未初始化；`MmPerPixel` 已接线但上游值 ≤0 或 NaN；HALCON 算法异常（如不支持的通道数）。
- **空输入**：本步骤失败并给中文提示"输入图像为空或未初始化"。
- **脏配置不炸流程**：所有参数在进 HALCON 前做**静默夹取**（灰度 0~65535、局部窗口 1~1000、半径 0~1000、个数 0~1000000、面积 0~1e12、当量 0~1000），`MinArea` 超过筛选上限时也会夹到不超过上限——配置坏了最多是结果不对，绝不会把整条流程带崩。NaN / Infinity 一律按 0 处理。
- **面积/尺寸单位**：`DefectAreas` `MaxArea` `TotalArea` `DefectWidths` `DefectHeights` 与所有筛选、判定阈值**都是像素**；只有 `MaxAreaMm2`/`TotalAreaMm2` 是物理量。**像素当量不参与判定**（避免"改了当量就改判定结果"的隐式耦合）——想要按毫米判定，就把毫米规格换算成像素填进判定项，或在下游取 mm² 端口自己比。
- **坐标系**：图像像素系 (Row, Col)，`CenterRows`/`CenterCols` 是质心；`DefectPhis` 为度。接了 `MaskRegion` **不会改变坐标口径**（仍是整图坐标），只是不再检测区域外。
- **渲染上限**：标注图最多画 300 个缺陷（超出时图上写"仅绘制前 300 个"）、配置界面缺陷清单最多 200 行；**输出端口与判定永远是全量**，不受画面截断影响。逐缺陷形状特征（圆度/长宽比/方向角）算不出来时只让那三列变空并写告警，不会把一次成功的检测判成失败。
- **配置态/运行态隔离**：预览、灰度直方图、"按当前图像自适应"只在配置界面里的那份实例上跑；产线运行不会白烧 CPU，也**不会静默改写你调好的参数**。
- **每轮清零**：个数、面积、判定与全部数组端口在每轮开头重置为空/0，本轮失败时下游读到的是空值而不是上一轮的脏数据。

## 典型用法 / 接线

```
① 最常用：固定阈值检暗斑
图像采集.OutputImage ──▶ Blob检测.SrcImage
创建ROI.MaskRegion ────▶ Blob检测.MaskRegion      （可选：只在产品区域内找）
创建ROI.MaskRegion ────▶ Blob检测.ExcludeRegion    （可选：螺丝孔/二维码一律不报）
标定.MmPerPixel ───────▶ Blob检测.MmPerPixel       （可选：让 mm² 输出成真值）
Blob检测.IsOk ─────────▶ 条件分支 / 结果上报        （NG 报警、OK 放行）
Blob检测.DefectImage ──▶ 数据记录.图片              （留证据图）
Blob检测.DefectAreas ──▶ C#脚本                     （分拣：气泡 vs 划痕）

② 打光不匀：换动态阈值
预处理.Image ──▶ Blob检测.SrcImage   （二值化方式 = 动态阈值，局部窗口取缺陷尺寸的 2~3 倍）

③ 存在性检测（有没有这个标记）
Blob检测.缺陷个数下限 = 1，缺陷个数上限 = 0 不用管 → 检不到就 NG

④ 先定位再检测
模板匹配.AlignedImage ──▶ Blob检测.SrcImage         （工件位置飘，先对齐再检缺陷）
```

## 常见问题

**Q1：一接上就报 NG，是不是坏了？**
不是。默认`缺陷个数上限 = 0`（零容忍），图上只要出现一个可疑区域就 NG。按产品规格填`缺陷个数上限`、`单个缺陷面积上限`，这是"该配规格了"的提示。

**Q2：一个缺陷都没检出来，查哪几项？**
按顺序查：① 阈值区间没覆盖缺陷灰度（看右侧**灰度直方图**，把标记线拖到背景峰与缺陷峰之间的谷底）；② `面积下限`太大（小缺陷被当噪点丢了）；③ 极性选反了（暗缺陷选成了`亮缺陷`）；④ 接了`排除区域`却画大了、或`排除触边`带宽过大；⑤ `面积上限`被人填了个很小的值（整片都被筛掉）。

**Q3：把背景整片当缺陷（全是红圈）？**
阈值太宽 → 收窄灰度区间或调大`标准差权重`；`面积下限`太小 → 调大；打光不匀 → 换**动态阈值**。

**Q4：缺陷个数虚高（一条划痕算成 3~4 个）？**
调`合并半径`（把间距小于 2×半径 的段接起来）或`闭运算半径`（连断口），必要时加`开运算半径`去毛刺。

**Q5：图像边缘总有假缺陷？**
调`排除触边`（如 10~20 像素）。画面**中间**的固定干扰（螺丝孔、二维码）用`排除区域`端口，触边参数管不到它。

**Q6：12/16 位相机（uint2）为什么切不出来 / 标注图看不清？**
`上限灰度`默认 128 隐含 8 位图假设，12 位图（0~4095）里 128 落在极暗处 → 按位深换算（12 位约取 2048），或直接点"按当前图像重新适配"。标注图底图现在按**实际灰度范围**线性拉伸（`convert_image_type` 是截断不是缩放，早期版本 uint2 会整片死白，已修）。

**Q7：数组端口取到的顺序稳定吗？第 3 号缺陷到底是哪个？**
由`输出排序`定死。默认`不排序（区域顺序）`是 HALCON 内部顺序、不保证跨版本一致；报表要对号入座就选`面积从大到小`或`从上到下、从左到右`，标注图上的编号与数组索引**始终一致**（编号 1 = 数组第 0 项）。

**Q8：改了`像素当量`，判定结果变了？**
不会。当量只影响 `MaxAreaMm2` / `TotalAreaMm2` 两个输出，判定永远按像素。想按毫米判定：把毫米规格换算成像素填进判定项，或下游取 mm² 端口自己比。

**Q9：接了标定的 `MmPerPixel`，为什么这一步直接失败了？**
这是**故意的**：连线值 ≤0 或 NaN（多半是标定步骤本轮失配/失败）时插件明确报错，而不是拿旧当量静默硬算——mm² 输出整体缩放错比报错更可怕。要么让标定那一步先成功，要么断开该连线改用手填`像素当量`。

**Q10：缺陷很多时会不会卡？**
画面上的编号最多 300 个、清单最多 200 行（超出会写明"仅列前 N 行"），输出端口与判定仍是全量。配置界面改参数有 200ms 防抖，全图检测在后台线程跑，界面不会冻。
