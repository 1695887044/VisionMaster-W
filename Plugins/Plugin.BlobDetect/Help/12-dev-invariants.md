## 一、A 组：违反就红

### 1. 执行状态与判定不能混（最重要的一条）

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 检出缺陷就报步骤失败 | `RunAlgorithm` 里把 NG 误写成 `Fail(...)`，下游会用执行状态当分流条件、把 NG 当异常走 | 报成功（检出缺陷是正常工况，不是失败）；默认零容忍 → 判 NG，但 `Success` 仍为 true（NG 是正常结果） |
| 运行不抛异常但流程炸了 | 异常没被 `Fail` 收口 | 运行不抛异常（`RethrowOnException` 保持 false 才有这条绿） |

### 2. 端口语义与顺序契约

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 下游按索引取不到对应缺陷 | 八个数组端口与 `Defects` 不是同一次遍历的产物 | 【核心】五个数组端口逐项对齐（下游按同一索引取就能对上号）——名字里的"五个"是初版遗留，夹具现在核的是全部数组列 |
| 检出数目不对还看不出来 | 噪点没被面积下限滤掉 | 【核心】检出 5 个缺陷（4px 的噪点被面积下限滤掉） |
| `MaxArea` / `TotalArea` 与数组不自洽 | 汇总量单独算了一份、没有走 keep 后的集合 | MaxArea 等于逐项面积的最大值；TotalArea 等于逐项面积之和 |
| 排序选了却没生效 | 排序发生在阶段二但端口赋值取了阶段一顺序 | 【排序】面积从大到小：输出确实单调不增；【排序】排序后第一个就是 MaxArea |
| 标注图编号与数组错位 | 编号不是 1 基、或用了另一份顺序 | 【编号】缺陷旁写有 1 基编号（与输出端口顺序逐项对应） |

### 3. 每一项筛选参数的语义

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 触边排除把不贴边的也丢了 | 边界带按外接矩形而不是像素判定 | 【触边排除】ExcludeBorderPx=1 → 恰好少一个（贴右边缘那个被丢掉）；【触边排除】剩下的都不压到最外 1 像素 |
| 长宽比滤不掉长条 | 自己算的比值取了 短边/长边 | 【长宽比】MaxAspectRatio=5 → 细长条被排除（5 个剩 4 个）；【长宽比】剩下的每个都 ≤ 设定的长宽比 |
| 圆度筛反了方向 | `select_shape` 的 `circularity` 下界写成上界 | 【圆度】MinCircularity=0.5 → 细长条被排除（圆斑保留） |
| 断裂划痕仍算多个 | 合并写成逐对象形态学（HALCON 对区域数组是逐对象处理） | 【合并】断裂两段：不合并是 2 个；【合并】MergeRadius=2.5 → 合并成 1 个（划痕断裂不再虚高计数） |
| 环形缺陷面积仍偏小 | `FillUp` 加在了筛选之后 | 【填孔】环形缺陷填孔后面积变大（孔不再被漏算） |

### 4. 判定四条与单位

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 存在性检测（个数下限）不报警 | `MinDefectCount` 的 0 被当成"零容忍" | 【存在性】个数少于下限 → 判 NG 且原因写明「少于下限」 |
| 总面积超标却报 OK | 四条判定漏了总面积项 | 【总面积】单缺陷都合格但总面积超标 → 判 NG 且原因写明「总面积」 |
| mm² 算错 | 当量被平方/没平方写反 | 【像素当量】mm² = 像素面积 × 当量²（当量 2 → ×4） |
| 接了标定却不生效 | 手填值优先于连线值 | 【当量直连】已接上游 → 以连线为准（当量 0.5 → ×0.25；手填 2.0 被忽略） |
| 上游标定失败还硬算旧值 | 静默回退到手填 `PixelSizeMm` | 【当量直连】上游当量无效 → 明确失败且指「标定」（绝不静默回退） |

### 5. 轮次边界

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 本轮失败、下游读到上一轮的缺陷数 | 基类 `AutoDisposeRoundOutputs` 只回收 `IDisposable` 端口值，`int`/`double`/`bool`/`HTuple` 不管 | 【开轮重置】失败轮把上一轮的脏数据清零（下游不会读到旧结果）；失败原因写明是图像为空 |

### 6. 标注图与位深（这一组就是"迁移到 `AnnotationBaker` 时抓出真 bug"的那组）

| 症状 | 机理 | 守门断言 |
| --- | --- | --- |
| 标注底图整片塌成窗口底色（黑） | 渲染器漏 `SetPart`，常驻窗口还带着上一轮的 part 设置 | 【底图保真】标注图逐点等于原图（左半 100 / 右半 200，底图没被缩进左上角）——**这条就是当年漏 `SetPart` 那条真 bug 的现行守门人**；共享件侧对应 B1【纪律3 SetPart】四角像素 == 底图灰度 100（不是窗口黑底、底图没缩进左上角）与 B1 底图右下角指纹块仍在原位（灰度 ≈180） |
| 16 位图标注整片死白 | `convert_image_type` 是**截断不是缩放**，`uint2` 的 0~4095 全被顶到 255 | 【位深】uint2 图标注底图按实际灰度范围拉伸（底部条带灰度跨度 > 50，不是一片死白）；【位深·对照】byte 两档图的标注底图保留了层次（渲染链路本身可用） |
| 3/4 通道输入行为不一致 | 通道归一写在渲染层而非检测层 | 【多通道】3 通道输入检出与 1 通道一致；【多通道】4 通道输入检出与 1 通道一致（alpha 被忽略）；【多通道】4 通道输入的标注图照样生成（底图已丢 alpha，渲染不报错） |
| 插件自己又开了一个离屏窗口 | 复制出第六份烘焙件（AGENTS.md R36） | 扫描④【D9】全仓 OpenWindow 只出现在 AnnotationBaker.cs + N 份豁免里（清单只许变短）；扫描④b 豁免清单没有过期项（迁完的文件必须从清单里删掉）。本插件的 `AnnotationRenderer` 只许攒 `BakePlan` |
| 给文字加对齐时把老插件的编号画歪了 | `BakeText.HAlign` 默认值变了 | B8【零行为变化】不写 HAlign 与显式 Left 的墨迹包围盒一致（±4px）——四份已迁插件不受影响（BlobDetect 是这四份之一） |

## 二、B 组：违反静默（什么都不红）

### B1 契约与存盘

| 症状（现场表现） | 机理 | 兜法 |
| --- | --- | --- |
| 老方案打开后某项配置"回到默认" | `.vms` 的键就是 CLR 属性名/端口名（`OnConfirm` 用 `cp.Name`，`ApplyConfigValues` 按名字匹配、**匹配不上直接 `continue`**）。改名 = 键读不回来 | 无断言，靠人工核对：改名前先想"老方案要不要读回来"；需要兼容就在 `ApplyConfigValues` 之前做一次性迁移。**不许"为了过编译把老键删掉"** |

| 已链接端口上残留一个固定值 | `OnConfirm` 对链接端口是 `RemoveInputValue`（`:281-285`）。若将来 override 成"照样写值"，运行期会以连线为准、用户看着框里有值却不生效 | 无断言。参考 AGENTS.md R33 的同族事故 |

### B2 参数语义

| 症状 | 机理 | 兜法 |
| --- | --- | --- |
| 接了**去畸变标定**的 `Transform` 还照常出数，边角件面积系统性偏 | 几何量全在原始像素上算，消费不了矩阵；`ValidateCalibrationGuard(src)` 是唯一落点。判据 ① `Intrinsics != null \|\| CalibrationKinds.IsUndistorted(Kind)` ② `SourceImageWidth/Height` 都 >0 且与当前图不符 → 失败 | **无断言**（P1-B S1 未配断言宿主）。人工核对：`Transform` 为空时必须逐字等于升级前行为 |

### B3 两阶段与缓存

## 四、"跳过"型断言的旧账（别再写回去）

`BlobDetectChecks` 里曾经有一道**误判的环境闸门**：底部条带灰度跨度 ≤50 就把【位深】那条记成
"跳过：本环境离屏窗口不渲染底图层次"。而 `AnnotationBakerChecks` 的 B1 早就实测过 buffer 窗口能正常铺满底图
（四角像素 == 底图灰度 100）——**这道闸门把一个真 bug（漏 `SetPart`）伪装成了"环境不支持"**，
让 BlobDetect 与 CaliperMeasure 两份渲染器的底图全黑存活了很久。现在【位深】与【底图保真】都是**硬断言**。

写 `Check(name, true, "跳过：本环境不支持 X")` 之前必须先回答"**谁证明了是环境不支持、而不是代码有 bug**"
（AGENTS.md R38）。本插件现在只剩两类合法"跳过"：`Check("插件视图样式收编（静态扫描）", true, "跳过：定位不到 BlobDetectView.xaml")`
一类是"文件定位不到"的前置，宿主里都写明了原因，不是"结果判不了"。
