# 图像采集 · 快速上手

> 分类：常用工具 ｜ 来源：插件 Plugin.ImageAcquisition

流程的**入口算子**：把图从四种来源——单个文件、文件夹、网络推送、相机——取成一张 `HImage` 交给下游视觉步骤，
并把最新图按需投到主界面的视图窗口。除 `Image` 之外它还报出"这张图是从哪来、第几张/第几帧、这台相机是谁"，
供下游做批次追溯与标定身份核对。

## 为什么需要它 / 原理

**一个算子、四条链路**。四种采集模式共用同一个执行核心，"试运行"与"正式运行"跑的是同一段代码——
所以配置窗口底部的「执行」按钮就是最可信的验证手段。

**数据分三层存，各走各的口径**：
- **可被变量链接的数据流参数**做成输入端口（路径、索引、取图超时）：值随流程数据流灌入，可接上游；
- **纯配置项**（采集模式、显示窗体、相机序列号）不落端口、永不连线，随步骤配置持久化；
- **纯界面状态**（预览图、信息栏、文件计数、推送测试表单）只在配置窗口存活，不进流程。

**取图语义按来源分成两种世界**，这是本算子最容易混的地方：
- **文件 / 文件夹**：拉模式——本轮要哪张，按路径或索引读哪张；
- **网络推送（Hub）**：外力驱动——外部程序"推一张 → 触发流程跑一次"，本步骤只是把那张图从本流程的图像槽里取走；
- **相机采集**：推模式——相机持续出图进帧队列，本步骤按自己的节奏**消费**一帧，**每帧只会被取到一次**。

**像素 → HImage 全仓只有一处转换核心**。网络推送与相机采集的像素约定必须逐字节一致
（灰度 = 1 字节/像素；彩色 = 3 字节/像素交错，HALCON 通道 1/2/3 = R/G/B），各写一份早晚出现
"相机采的彩色图颜色是反的、网络推送却是对的"——而灰度图上完全看不出来，只表现为判别类算子莫名不对。
入队/入槽前已有尺寸与字节数自洽校验，≥4 通道（BGRA/RGBA）先抽掉 alpha 压成三通道，2 通道直接拒绝。

**显示是"锦上添花"，不参与成败判定**：采集成功后把图投递到「显示窗体」指定的窗口；投递失败只记一条告警，
绝不把一次成功的采集判成异常。视觉图像页的图像集另有开关（见「常见问题与排错」）。

## 四种模式怎么选

| 模式（界面卡片） | 什么时候用 | 要不要在「系统 → 相机设置」添加相机 | 一帧怎么来 |
| --- | --- | --- | --- |
| 指定图像 `SingleFile` | 调一张静态图、复现现场某一张图 | 不用 | 按 `FilePath` 读盘 |
| 文件目录 `Folder` | 跑一批已有图（离线复现、批量回归、序列回放） | 不用 | 按 `FolderPath` + `FileIndex`（0 基）取自然序第几张 |
| 网络推送 `Hub` | 外力（PLC / 别的软件 / 客户端）"给一张图就跑一次流程并把结果回给对方" | **不用**（图走 HTTP 进本流程的图像槽） | 从本流程图像槽取刚推进来的那一帧；槽空则阻塞等待 |
| 相机采集 `Camera` | 相机持续出图、流程按自己节奏取帧 | **必须**先添加、连接并开始采流 | 从这台相机的帧队列消费一帧 |

## 第一次跑通（指定图像，5 步）

1. 流程里拖入「图像采集」→ 双击（或右键「模块参数」）打开配置窗口。
2. 「基本参数 → 采集模式」选 **指定图像**，「图像路径」浏览选中一张图（扩展名白名单 `.bmp .jpg .jpeg .png .tif .tiff`）。
3. 「图像参数 → 显示窗体」选目标窗口（`图像窗口1~9` / `不显示`，默认窗口 1）。
4. 点窗口底部**「执行」试运行**——跑的就是正式运行的同一段代码，信息栏那句 `已加载图像: {路径} ({宽}x{高})` 就是自检结果。
5. 把 `Image` 连给下游（如「图像预处理」的 `SrcImage`），点「确定」写回步骤（只写内存；方案要长期生效仍需保存）。

## 接线速览（最常见的一条）

```
图像采集.指定图像（浏览选一张良品图）
图像采集.Image ──▶ 图像预处理.SrcImage ─▶ 下游算子
```

其余三种模式的接法与"什么算失败"见「四种模式的操作口径」；产线连续采图务必把 `SourceSerial`
接到下游「标定」/「坐标变换」的同名输入，让"换了相机却沿用旧标定"变成**明确失败**而不是静默算错。
