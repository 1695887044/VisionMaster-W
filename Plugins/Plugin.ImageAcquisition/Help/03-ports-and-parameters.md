# 图像采集 · 端口与参数

> 分类：常用工具 ｜ 来源：插件 Plugin.ImageAcquisition

本页是字典：端口名、类型、默认值、必填口径、取值范围逐条对源码。
**端口名是连线和落盘用的键**，与 C# 属性名不同处已注明；改名会打断既有接线。

## 输入端口

| 端口 | 类型 | 默认 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `FilePath` | string | 空串 | 否 | **指定图像**模式：单个图像文件完整路径。可手填、可浏览选择、可 🔗 链接上游变量 |
| `FolderPath` | string | 空串 | 否 | **文件目录**模式：图像文件夹路径。同样可链接变量（链接时配置态无法预览，运行期才生效） |
| `FileIndex` | int | `0` | 否 | **文件目录**模式：文件夹内第几张，**0 基**；可链接变量（批量回放时由上游计数给） |
| `FrameTimeoutMs` | int | `0` | 否 | **相机采集**模式：等一帧的超时（毫秒）。`0` = **使用相机自身配置的超时**（默认 3000 ms）；可被上游变量控制（不同产品节拍不一样） |

> 四个口都标为"非必填"：四种模式各用各的，用不到的口留空是合法状态，不会被编译拦下。
> 属性名与端口名的对应关系：`FilePathPort` → `FilePath`、`FolderPathPort` → `FolderPath`、
> `FileIndexPort` → `FileIndex`、`FrameTimeoutPort` → `FrameTimeoutMs`。

## 配置项（随步骤落盘，不可连线）

| 项（C# 名） | 界面 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `Mode` | 采集模式 | `AcquisitionMode` | `SingleFile` | 四选一：`SingleFile`「指定图像」/ `Folder`「文件目录」/ `Hub`「网络推送」/ `Camera`「相机采集」。枚举落盘为数字，坏档会被踢回默认值。**换模式会清空预览并重新校验** |
| `DisplayViewIndex` | 显示窗体 | int | `1` | 采集图发布到主界面几号视图窗口：`图像窗口1~9`；`不显示` = 0（不抢占窗口，图照样给下游）。**写入即夹取到 0~9**——手改方案文件塞进 10 或负数不会报错，但表现为"配了显示哪格都不显示"，所以必须在写入时就夹住 |
| `CameraSerial` | 相机下拉 | string | 空串 | 目标相机的**序列号**（不是显示名、不是内部 Id），相机模式必填。候选列表由宿主在打开配置窗口时下发；序列号对应的相机被删掉时，下拉诚实显示为空、信息栏报红 |

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Image` | `HImage` | 采集到的图像。失败轮为空——本轮开轮即清零 |
| `CurrentPath` | string | 当前来源：文件模式 = 完整路径；网络推送 = 客户端声明的图片名（缺省 `hub://{流程名}`）；相机 = 来源名（缺省 `camera://{序列号}`） |
| `CurrentIndex` | int | 文件目录模式 = 当前索引；**相机模式重载为"第几帧"**（兼容既有接线）。要精确帧号用 `FrameId` |
| `TotalFiles` | int | 文件夹内符合条件的总数；**相机模式重载为"累计收帧数"**。要精确值用 `ReceivedCount` |
| `FrameId` | long | **相机帧序号（从 1 开始）**，无任何语义重载；非相机模式为 0。日志对账、结果归档一律用它 |
| `ReceivedCount` | long | 该相机**累计收到的帧数**（含溢出被丢弃的）；非相机模式为 0 |
| `SourceSerial` | string | **相机身份**：相机模式 = 本步骤配置的序列号，其余模式为空。接「标定」/「坐标变换」的 `SourceSerial` 输入做自动核对——换相机（换镜头/换工位）后旧标定自证失效，而不是静默用错标定 |
| `Success` / `ErrorMessage` | bool / string | 基类统一提供：本步是否成功 + 一句话原因（失败原因本身就是排查指引） |

## 关键参数口径

| 项 | 值 | 说明 |
| --- | --- | --- |
| 支持的图像扩展名 | `.bmp .jpg .jpeg .png .tif .tiff` | 白名单一处定义：执行核心、目录列表、浏览框都由此派生；不在名单内的文件不进目录列表、不参与索引 |
| 目录排序 | 自然序 | `img2` 排在 `img10` 之前（与资源管理器一致）——文件索引直接对应工件顺序，**排序错 = 顺序错** |
| 子目录 | 不递归 | 需要分目录跑就把索引做成变量，或一个目录配一个采集步骤 |
| 索引越界 | **夹取**到有效区间 | 不失败，但结果文案写明"（索引 X 超出 0~N，已夹取）"。静默吞掉的旧表现已修：留痕是因为批处理场景里上游算错索引若被吞掉，表现为"同一张产品被反复检测"，现场极难归因 |
| 目录枚举时机 | **每轮重新枚举** | "拍图落盘"式工作目录里新增的文件当轮就能读到，删掉的不再占索引 |
| 超时口径 | `FrameTimeoutMs` 端口值；填 0 取相机配置里的超时 | 两者都被保证为有限值。这个口存在的意义就是**绝不能没有超时**：无超时的等图会让流程线程永久卡死、现场只能杀进程 |
| 网络推送的等待 | 没有"超时"这一说 | 只有"等到图"或"用户停止流程"两个退出条件；等待上限由流程是否被停止决定 |

## 必填与校验口径（编译期 / 配置态 / 运行期）

| 层 | 判据 | 表现 |
| --- | --- | --- |
| 编译期 | 四个输入端口全部非必填 | 不会因为"没用到的口留空"报 `[参数缺失]` |
| 配置态 | 信息栏即时校验（空 = 橙、路径不存在 = 红、已链接 = 中性说明） | 边改边提示，不弹窗 |
| 运行期 | 各模式各自的失败口径（见「四种模式的操作口径」） | `Success=false` + 一句"下一步该做什么"的中文原因 |
