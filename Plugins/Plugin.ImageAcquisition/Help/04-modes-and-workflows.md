# 图像采集 · 四种模式的操作口径

> 分类：常用工具 ｜ 来源：插件 Plugin.ImageAcquisition

这一页回答两件事：**每种模式怎么操作**，以及**每种模式什么算成功、什么算失败**。
端口与参数取值查「端口与参数」，界面格子查「界面与编辑」。

## 一、统一的收尾规则（四种模式都适用）

- 每一轮**开轮清零**：`Image` / `CurrentPath` / `CurrentIndex` / `TotalFiles` / `FrameId` / `ReceivedCount` / `SourceSerial`
  全部先归零再执行。失败轮不会留上一轮的残留值（下游按"当前索引/总数"判断的步骤尤其依赖这条）。
- 业务失败 → `Success=false` + `ErrorMessage` + 一条 Error 日志；`ErrorMessage` 一律写成"下一步该做什么"。
- 取消（用户点了"停止流程"）→ 本步没产出，`Success=false`、`ErrorMessage` 写"已停止等待图像"一类文案，
  但这**不是业务故障**：流程去向由引擎的取消语义决定，本算子绝不试图终止流程。
- 读盘/解码失败时先把已创建的 HALCON 对象释放再上抛，避免连续失败持续吃非托管内存。

## 二、指定图像（调试 / 单图复现）

1. 「图像路径」浏览选图或 🔗 链接上游变量。
2. 右侧预览立刻显示该图；「执行」后信息栏形如 `已加载图像: {路径} ({宽}x{高})`。
3. 输出口关注：`Image`、`CurrentPath`（就是这条路径）、`TotalFiles` 恒为 1、`CurrentIndex` 恒为 0。

**成败口径**：路径为空（"文件路径不能为空"）/ 文件不存在（"文件不存在: {路径}"）/ HALCON 读不了该文件
（扩展名在名单内但内容损坏）——都会明确失败，**不会退回旧图**。

## 三、文件目录（离线批处理 / 序列回放）

1. 「文件夹路径」浏览选择；「文件索引」填 0 基索引（或 🔗 链接上游计数变量）。
2. `◀ ▶` 翻页、`刷新预览` 重扫目录；"当前文件：xxx（共 N 张）"随索引更新。
3. 排序是**自然序**（`img2` 在 `img10` 之前）。实现刻意不做区域/文化敏感比较——同一台设备上排序必须永远稳定。
4. 运行期**每轮重新枚举**：新增的文件当轮就能读到、删掉的不再占索引。
5. 索引越界会**夹取**并在结果文案里留痕：`已加载图像 [i/N]: {路径}（索引 X 超出 0~N-1，已夹取）`。

**成败口径**：目录为空（"文件夹路径不能为空"）/ 目录不存在（"文件夹不存在: {路径}"）= 失败；
目录内没有匹配扩展名的文件 = 失败并写"文件夹内未找到符合条件的图像文件: {路径}"（`TotalFiles` 报 0）。
子目录**不递归**——需要分目录跑就把索引做成变量、或一个目录配一个采集步骤。

## 四、网络推送（外力推一张、流程跑一次）

**这个模式不需要添加任何相机**，图由外部程序推给宿主收图服务，本步骤从**本流程的图像槽**里取走那张图。
操作步骤与推送测试区见「界面与编辑」。

**接口速查（Hub 通道）**

| 项 | 值 |
| --- | --- |
| 地址 | `POST http://{Host}:{Port}/flow/{流程名}?outputs=步骤名.端口名`（`outputs` 省略 = 回传全部步骤的全部输出端口） |
| 鉴权 | `Authorization: Bearer {Token}`；默认占位令牌 `visionmaster`，投用前必须改 |
| 请求体 | **图片文件原始字节**（非 multipart、非 base64）；可选头 `X-Image-Name: 文件名`（回传为 `CurrentPath`，缺省为 `hub://{流程名}`） |
| 成功回包 | JSON：`success / requestId / flow / elapsedMs / image{width,height,channels} / outputs`；失败 `{success:false, message}`（**原因在 message**） |
| 错误码 | 401 无/错令牌；404 未知流程；400 空 body；409 流程正在运行（同一流程串行）；504 等待结果超时（**不打断流程**，后台继续跑完） |
| 语义约束 | 一次 POST = 推一帧 + 单次执行；图像槽**只留最新一帧**，每槽上限 8 帧、满则丢最旧 |
| 配置位置 | `AppConfig.json → HttpImageServer`：`Enabled` / `Host`（`0.0.0.0` = 所有网卡，客户端要填实际 IP）/ `Port`（默认 19000）/ `Token` / `RequestTimeoutMs`（默认 30000，一般取现场流程最长耗时的 2~3 倍；本期无配置 UI） |
| 客户端超时 | 必须**大于**服务端等待上限（本插件的推送测试按 `RequestTimeoutMs + 5000` 设），否则服务端还在跑、客户端先断，"超时"分不清是流程慢还是网络断 |

**成败口径**：图像槽里没有图是**正常工作状态**，于是**阻塞等待**而不是报失败（旧实现报失败会让本步失败、
下游每个吃图的步骤再各报一次"输入图像为空"，真正的根因被噪音盖住）。
正常 HTTP 链路是"先推图再触发流程"，命中快路径、不产生等待；连续运行或手动单跑时槽空等待是常态。
唯一的退出方式是等到图或用户停止流程；**绝不回退旧图**（回退会产出"长得像成功"的错结果）。
等待期间被打断 → "已停止等待网络图像"（取消，不是故障）。

## 五、相机采集（产线连续采图）

1. **先配相机**：「系统 → 相机设置」→ 选驱动类型（如「海康相机」「网络相机（虚拟）」）→ 填**序列号** → 连接 → 开始采流。
   真机与虚拟相机的接入差别、参数哪些生效，见各自驱动插件的手册（分类「相机驱动」/「相机」）。
2. 回到本页：下拉选这台（同时显示名字与当前状态）；`当前状态：` 那行按红/橙提示"现在能不能跑"。
3. 「取图超时(ms)」：默认 0 = 用相机自身配置的超时；可手填或 🔗 链接变量。
4. 「执行」试运行：成功文案 `已从相机取图: {宽}x{高}x{通道}（第 {帧号} 帧，来源 {来源名}）`。
5. 语义要点：**每帧只被消费一次**（同一帧不会被两个采集步骤各取一次——需要同一帧多处使用，
   取一次再把 `Image` 传给下游）；帧队列有上限，处理不过来会丢最旧并计溢出（**丢帧 = 一个未检测的工件**）。

**四类失败分开报**（文案就是排查指引，照抄搜索）：
① 没选相机 → `尚未选择相机，请在「相机采集」页选择一个已配置的相机`；
② 方案里没这台 → `找不到序列号为「X」的相机。请到「系统 → 相机设置」添加该相机，或回到本步骤的「相机采集」页重新选择`；
③ 相机未连接 → `相机「X」未连接（…）。请到「系统 → 相机设置」连接该相机后再运行`；
④ 等图超时 → `等待相机「X」出图超时（N ms）；相机状态：…，待消费 N 帧，累计收帧 N，溢出丢帧 N`。
另外帧不自洽会被拦下（"相机返回的帧数据无效（宽高与像素字节数不自洽）"）。

**不做"重试等下一帧"**：这一帧没等到就是没等到，继续等只会让流程越来越滞后于生产；
产线上"这一件没检出"必须被明确记录，而不是靠等待掩盖过去。

## 六、两条 HTTP 通道不要混

| | 网络推送（本算子 Hub 模式） | 相机推帧（网络相机驱动） |
| --- | --- | --- |
| 配置节 / 默认端口 | `AppConfig.json → HttpImageServer` / **19000** | `AppConfig.json → NetworkCameraServer` / **19100** |
| URL | `POST /flow/{流程名}` | `POST /camera/{序列号}/frame`，心跳 `POST /camera/{序列号}/heartbeat` |
| 是否等流程结果 | **等**（同步回包，含 outputs） | **不等**（入队即回，流程自己按节奏取） |
| 帧留存语义 | 图像槽只留最新一帧 | 环形队列消费，每帧只取一次，溢出丢最旧并计数 |
| 要不要添加相机 | 不用 | 要在「系统 → 相机设置」添加并连接 |
| 现成客户端 | 配置窗口的「推送测试」按钮 | `Tools\VirtualCameraClient`（独立"假相机"工具） |

## 七、典型用法 / 接线

```
① 离线调试（最常见）
   图像采集.指定图像（浏览选一张良品图）
   图像采集.Image ──▶ 图像预处理.SrcImage ─▶ 下游算子

② 序列回放 / 批处理
   上游计数.变量 ──▶ 图像采集.FileIndex        （0 基，越界自动夹取）
   图像采集.Image ──▶ 下游算子.SrcImage
   图像采集.CurrentPath ──▶ 数据记录（存的记录能反查是目录里哪张图）

③ 外力触发（相机/PLC/上位机推一张跑一次）
   外部程序 ──POST /flow/{流程名}──▶ 本步骤（网络推送，取到刚推进来的那一帧）
   图像采集.Image ──▶ 下游算子；判定结果由同一次 HTTP 请求同步回传

④ 产线连续采图（推模式）
   系统 → 相机设置：添加并连接相机、开始采流；触发模式选 连续采图 / 软触发 / 上升沿 / 下降沿
   图像采集.相机采集（CameraSerial = 那台的序列号；取图超时端口 0 = 用相机配置）
   图像采集.Image ─────────▶ 下游算子.SrcImage
   图像采集.FrameId ───────▶ 数据记录.备注 / 结果上报（帧溯源）
   图像采集.SourceSerial ──▶ 标定.SourceSerial ─▶ 坐标变换（换相机后旧标定明确失败）
   （本算子只出原图，不带标注；要往图上烧结果请接「结果显示」算子）
   （软触发由本步骤每次取图前自动下发，不需要在流程里额外加触发节点）
```
