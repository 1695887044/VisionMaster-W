# 图像采集 · 界面与编辑

> 分类：常用工具 ｜ 来源：插件 Plugin.ImageAcquisition

配置窗口长什么样、每一格改完会发生什么、信息栏那句话是什么口径。
端口名/默认值/取值范围请查「端口与参数」，各模式的成败判定请查「四种模式的操作口径」。

## 窗口布局

| 区域 | 内容 |
| --- | --- |
| 左侧表单 | 两个标签页：**基本参数**（采集模式四张卡片 + 当前模式对应的那一个分组）、**图像参数**（显示窗体） |
| 右侧 | 图像预览区（含 `◀ ▶` 翻页、`刷新预览`、"当前文件：xxx（共 N 张）"）+ 底部「状态信息」与图像路径回显 |
| 窗口底部 | 宿主的「执行」（试运行）、「确定」、「取消」——**试运行跑的就是正式运行同一段代码** |

四个分组按采集模式切换显隐：`指定图像` / `文件目录` / `网络推送` / `相机采集`。
**换模式会清空预览并重新校验**——旧模式的数据源在新模式下对不上号，留着只会让界面自相矛盾。

## 「基本参数」页

**采集模式**（四张卡片，落盘为 `Mode`）：选一后下方只显示对应的分组。

**指定图像**分组：`图像路径` 一行，双击下划线区域浏览选图（浏览框只放开白名单扩展名），
行尾 🔗 可链接上游变量。链接后配置态无法预览（值要运行期才由上游产出）。

**文件目录**分组：`文件夹路径`（同样可浏览、可 🔗）+ `文件索引`（0 基，可 🔗 由上游计数变量驱动）。
右侧预览的 `◀ ▶` 就是改这个索引，`刷新预览` 重扫目录。
"当前文件：xxx（共 N 张）"随索引更新。

**网络推送**分组会当场告诉你三件事：
- **服务状态**（`PushServiceHint`）：绿 = "宿主收图服务正在监听 {主机}:{端口}"；橙 = 未监听并给原因
  （`AppConfig.json → HttpImageServer.Enabled=false`，或配置为启用但端口被占用/启动失败）。
- **接口说明**（「接口说明（点击展开）」四行）：URL 形态、鉴权头与请求体、配置位置、并发约束。
- **推送测试**：`流程名`（预填当前流程名，可故意改成不存在的名字验 404）、`主机`、`端口`、
  `令牌`（可故意填错验 401）→ 点「选择本地图片并推送测试」= **真发一次 HTTP 请求**
  （走的就是外部相机/PLC 那条路，测通了才算真通）。
  推送前会先把界面上改过的配置写回步骤，所以本次跑的就是你看到的配置。
  结果区（"推送结果（可选中复制）"）给出：HTTP 状态码 + 客户端耗时、流程名、图像 `宽x高x通道`、
  服务端耗时、输出摘要或错误原因。

**相机采集**分组：
- 下拉候选来自宿主下发的方案相机快照，显示文本是 `显示名（序列号）`，后面另起一行给出该相机当前状态文字；
  选没配置过相机时列表为空。
- `当前状态：` 那行说清"现在能不能跑"——**未连接 = 红；已连接但未采流 / 等待客户端接入 = 橙；采流中 = 无提示**。
- `取图超时(ms)` 输入框（对应 `FrameTimeoutMs` 端口，0 = 用相机自身配置的超时）。
- 「说明（点击展开）」三行：本步骤是**消费**一帧（每帧只被取到一次）；填 0 用相机配置、超时永远是有限值；
  相机图像预览在「系统 → 相机设置」看，验证本步骤能否取到图就点「执行」。

## 「图像参数」页

`显示窗体`：`图像窗口1~9` 或 `不显示`（0）。默认 1。选"不显示"不抢占窗口，图照样给下游。
写成 0~9 以外的值（手改方案文件）会被**写入即夹取**到 0~9，理由见「端口与参数」。

## 信息栏的即时校验口径（边改边提示）

| 界面表现 | 含义 |
| --- | --- |
| 橙字"请选择…" | 该项为空且未被链接（运行期会明确失败） |
| 红字（路径类） | 路径填了但文件/文件夹不存在 |
| 中性说明（不报红） | 该项**已被变量链接**：值运行期才产出，配置态无法校验，于是给"来自变量链接，运行期生效；配置态无法预览" |
| 相机行红/橙 | 见「相机采集」分组的状态色口径：红 = 运行必失败；橙 = 能连但可能等图超时 |

> 链接端口时不报"请先选择…"是刻意的：报红会让人误以为链接失效了。

## 「确定」与「取消」

- **确定**：把界面上的输入端口值与 `[StepConfig]` 配置写回步骤（`InputValues` + 配置快照），
  集合类值写回前先做深拷贝，之后继续在界面上改不会污染已确认数据。
- 只写内存：**方案要长期生效仍需保存方案**。
- **取消**：不落盘，界面状态随窗口销毁。试运行读的是**已保存**的配置，所以改完想验证请点「确定」再「执行」。

## 为什么配置窗口里没有相机实时预览

刻意不提供。预览要拿到设备对象，而设备只存在于宿主的相机仓库里（配置窗口拿到的只是候选快照），
硬要预览就得让插件持有宿主对象，破坏"插件只认契约"。相机图像预览在「系统 → 相机设置」
（那里本来就有 Live 预览，也是更该检查相机的地方）；要验证"这一步能不能取到图"，
点配置窗口的「执行」试运行即可——它跑的就是正式运行的同一段代码。
