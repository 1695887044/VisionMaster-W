# ROI

> 分类：常用工具 ｜ 来源：插件 Plugin.CreateRoi

在图像上画一个或几个"**框**"（矩形 / 圆 / 椭圆，还可以用画笔涂抹与擦除修正），
告诉后续步骤"**只看框里的，框外的别管**"。
每个框自动生成 4 个输出端口：裁剪图 `Crop_名字`、带 domain 的原图 `Domain_名字`、
裁剪原点 `OffsetRow_名字` / `OffsetCol_名字`；另有全算子共用的合并有效区域 `MaskRegion`、
二值掩膜图 `MaskImage`、本轮实际成功输出的裁剪图数 `RoiCount`，
并把合并掩膜合成图投到主界面的视图窗口。

**它回答"看哪里"（配置期人画的、固定的框）；模板匹配回答"目标在哪"（运行期算法找出来的框）。**
产线上常配合：先用 ROI 圈出工位区域，再在区域内做模板匹配——搜索更快也更稳。

## 为什么需要它 / 原理

**一切从"区域"开始**。区域（`HRegion`）是"剪纸"：只有形状、没有像素值，标记"哪些位置被选中"。

```
画布上画的框（矩形 / 圆 / 椭圆，外加画笔涂抹与擦除）
      ↓ 参数化保存（RoiItem.Params 是"一串数字"，不是 HALCON 对象）
运行时按参数重建区域（gen_rectangle2 / gen_circle / gen_ellipse）
      ↓ 多个区域合并 + 涂擦修正：合并有效区域 = (ΣROI ∪ 涂抹) − 擦除
      ↓ 两条应用路径
路径 A：按 ROI 逐个裁图 / 取域图  →  Crop_名字、Domain_名字、OffsetRow/Col_名字
路径 B：整图做二值掩膜与抠图      →  MaskRegion、MaskImage（+ 发布到主窗口的合成图）
```

- **为什么存参数而不是存区域对象**：`HRegion` 是内存对象、进不了 JSON；
  数字数组天然可序列化、跨电脑一致，运行时几行代码就能重建——**存"配方"，不存"成品"**。
- **裁剪的两种姿势**（本算子最核心的设计，两条都给你）：
  - **真裁剪 `Crop_名字`**：图变小了，下游处理更快；**但坐标系变了**——
    裁剪图（外接矩形左上角）成了新的 (0,0)，所以同时输出 `OffsetRow_名字` / `OffsetCol_名字`，
    下游换算 `全局坐标 = 本地坐标 + 偏移`。漏加一次偏移，结果就**静默错一个框左上角的距离**（不报错）。
  - **带 domain 的原图 `Domain_名字`**：图的大小不变（内存不省），但 HALCON 算子**只在 domain 圈内干活**；
    **坐标系没动**——实测 `find_shape_model` 在 domain 图上搜索，命中返回的仍是全局坐标，
    domain 外的目标直接不命中。**下游插件一个都不用改**就能吃到 ROI。
- **掩膜与抠图**：`MaskImage` 是 0/255 的二值图（有效区 255、其余 0），抠图就是 `原图 × 掩膜 ÷ 255`
  （彩色图先把掩膜 `compose3` 成三通道再乘；缩放因子固定 1/255，避免截断把有效区刷成白屏）。
- **排除模式（`MaskInvert`）**：勾选后掩膜黑白反转——**ROI 圈的反而变黑、圈外保留**。
  用途："这块是坏的/不要的，检测除它以外的所有地方"。
- **一条铁律**：`合并有效区域 = (ΣROI ∪ 涂抹) − 擦除`，**不随排除模式反转**。
  `MaskRegion` 永远表示"哪里有效"（正语义），反转只发生在 `MaskImage` 那一层——
  一个概念只在一处反转，否则下游拿到"已排除的区域"再乘一次反转，语义就乱套了。
- **动态端口**：输出端口数量取决于你画了几个框，是配置期才确定的。
  `RoiList` 一变就重建端口并把"名字 + 类型"的快照写进步骤数据，编译器据此恢复端口供接线。
  **改名/删框会断开对应的连线**，接好的线要跟着重连。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 是 | 待处理的图像（`HImage`）。空或未初始化直接失败：`输入图像为空或未初始化`。单通道/三通道都吃（掩膜抠图时三通道会自动合成三通道掩膜） |

## 输出端口

**固定端口**

| 端口 | 说明 |
| --- | --- |
| `RoiCount` | **本轮实际成功输出的裁剪图数**（不等于配置的 ROI 个数！参数无效或被擦除殆尽的框会被跳过） |
| `MaskRegion` | 合并有效区域（`HRegion`）：`(ΣROI ∪ 涂抹) − 擦除`，恒为正语义 |
| `MaskImage` | 二值掩膜图（`HImage`）：有效区 255、其余 0；**排除模式下反转** |
| `Success` / `ErrorMessage` | 基类自带：本步骤是否跑通、失败时的中文原因 |

**动态端口：每个 ROI 自动生成 4 个**（名字里的"名字"就是列表里那个 ROI 名）

| 端口 | 类型 | 内容 |
| --- | --- | --- |
| `Crop_名字` | `HImage` | 裁剪图，只含 ROI 内容；**坐标系已搬走**（原点是有效域外接矩形的左上角） |
| `Domain_名字` | `HImage` | 带 domain 的原图：只在 ROI 内有像素，**坐标仍是全局坐标**，下游零回变换 |
| `OffsetRow_名字` | `double` | 裁剪图原点在原图中的**行**：`global_row = local_row + 本值` |
| `OffsetCol_名字` | `double` | 裁剪图原点在原图中的**列**：`global_col = local_col + 本值` |

> **不旋转图像**：裁剪裁的是外接矩形，所以回变换永远只是**平移**，没有旋转项。
> 擦除涂抹同样作用于每个 ROI 的有效域——擦掉的地方不会出现在 `Crop_` / `Domain_` 里。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `DisplayViewIndex` | `1` | 合并掩膜合成图发布到主界面第几个视图窗口（1~9）；`0` = 不发布 |
| `MaskInvert` | `false` | 排除模式：ROI 内变黑、圈外保留。改了立刻刷新掩膜预览 |
| `RoiList` | 空 | ROI 列表（整表随方案序列化）。每一项含：`Name`（名字，下游按它引用端口，也是唯一键）、`ShapeType`（矩形 / 圆形 / 椭圆）、`Params`（形状参数，见下表） |
| `SmearDrawData` | 空 | 涂抹区域的持久化快照（游程编码文本 `行,起列,止列;…`；超过 4KB 自动 GZip+base64 加 `gz:` 前缀） |
| `SmearEraseData` | 空 | 擦除区域的持久化快照（同上） |

**`Params` 的形状参数约定**（与 HALCON 的 `Gen*` 算子一一对应；界面上的中文名如下）

| 形状 | 参数（界面上的名字） | 重建用的算子 |
| --- | --- | --- |
| 矩形 | 中心行(R)、中心列(C)、角度(Phi，**弧度**)、半长(L1)、半宽(L2) | `gen_rectangle2`（可旋转矩形） |
| 圆形 | 圆心行(R)、圆心列(C)、半径(Radius) | `gen_circle`（只要 3 个数，不补位） |
| 椭圆 | 圆心行(R)、圆心列(C)、旋转角(Phi，弧度)、长半轴(Ra)、短半轴(Rb) | `gen_ellipse` |

## 口径与失败策略

- **只有"没有图像"会让本步骤失败**（`输入图像为空或未初始化`）。
  **单个 ROI 裁剪失败不阻断整体**，只写一条 Warn 日志留痕：
  - `ROI[Crop_名字] 形状参数无效，跳过裁剪`（圆少于 3 个参数、矩形/椭圆少于 5 个、参数为 0 或非法）；
  - `ROI[Crop_名字] 有效区域为空（被擦除殆尽），跳过裁剪`；
  - `ROI[Crop_名字] 裁剪失败：异常信息`。
- **本轮清零机制**：每个 ROI 的 `OffsetRow_/OffsetCol_` 在裁剪前先写 `0`，
  任一失败分支下游读到的都是 0，**不是上一轮的残留值**（`double` 端口基类不回收，脏值会一直挂着）。
- **`RoiCount` 是"成功数"不是"配置数"**：配置 5 个、成功 4 个时它给 4。下游按它循环取数才不会越界。
- **重名防御**：ROI 名强制唯一（撞名时自动取同词干的最大序号 +1，例如 `ROI_0`→`ROI_2`→`ROI_3`）。
  极端兜底：万一历史方案里有重名，`Crop_` 端口只输出第一个。
- **投图是锦上添花**：`DisplayViewIndex=0` 或合成图无效就不发布；窗口号**直传**（它本身就是 1~9）。
  发布的是**合并掩膜合成图**（一帧看清全部 ROI 与涂擦修正），不再逐 ROI 发到同一窗口互相覆盖。
- **内存口径**：上一轮输出的 `HImage` 由基类在轮首自动回收；发布到主窗口的合成图不走端口，
  由本算子自管生命周期（轮首 + 配置实例 `Dispose` 释放）。
- **配置界面是"设计期"**：画框、拖拽、涂擦都只在配置窗口里发生，运行期只裁剪、不弹界面。
- **坐标系**：全部**图像像素系 `(Row, Col)`**，角度**弧度**存盘；`Domain_` 全局坐标、`Crop_` 本地坐标（加 Offset 才变全局）。

## 典型用法 / 接线

```
图像采集.OutputImage ──▶ ROI.SrcImage

【首选：零坐标换算】
ROI.Domain_焊盘区 ──▶ 模板匹配.Image        （返回仍是全局坐标）
ROI.Domain_检测区 ──▶ Blob缺陷检测.SrcImage
ROI.Domain_标签区 ──▶ 卡尺测量.SrcImage
ROI.Domain_读数区 ──▶ 码读取 / OCR / 颜色检查.Image

【必须用裁剪图时：三条线一起连】
ROI.Crop_小图      ──▶ C#脚本 / 结果上报（只管手里这张图的下游）
ROI.OffsetRow_小图 ──▶ 下游（global_row = local_row + 本值）
ROI.OffsetCol_小图 ──▶ 下游（global_col = local_col + 本值）

【整图抠掩膜】
ROI.MaskRegion ──▶ Blob缺陷检测.MaskRegion   （限制检测区）
ROI.MaskImage  ──▶ 需要二值掩膜参与运算的下游
ROI.RoiCount   ──▶ 循环/计数的上界
```

**第一次画 ROI（6 步）**：
① 把上游图像输出连到 `SrcImage`；
② **试运行一次**，上游图会自动显示在配置界面的画布上；
③ 图上**右键 → 新建矩形 / 圆形 / 椭圆**，圈出要分析的区域；
④ 选中后在"参数微调"里用数值框精调（与画布句柄实时双向同步）；
⑤ 决定下游怎么用：智能插件连 `Domain_名字`；脚本/导出连 `Crop_名字` + 两个 Offset；
   只要区域/掩膜就连 `MaskRegion` / `MaskImage`；
⑥ 设"显示窗口"（1~9，0 = 不发布），点确定保存。

## 常见问题

**Q：下游拿到的坐标是局部的还是全局的？**
看用了哪个输出：`Domain_名字` 是**全局**（坐标系没动）；`Crop_名字` 是**本地**，
必须再加 `OffsetRow_/OffsetCol_` 才是全局。

**Q：用了裁剪图但没连 Offset，会报错吗？**
**不会**，坐标**静默错**（整体偏一个框左上角的距离）。这正是 `Domain_` 路线存在的理由。

**Q：为什么 `RoiCount` 比我配置的 ROI 个数少？**
`RoiCount` = 本轮**实际成功输出**的裁剪图数。参数无效或被擦除涂光的框会被跳过（日志里有 Warn）。
下游按 `RoiCount` 循环取数才不会越界。

**Q：重开方案后画的 ROI 还在吗？涂擦修正呢？**
在。`RoiList` 整表随方案序列化；涂抹与擦除用游程编码文本一并保存
（超过 4KB 自动 GZip 压缩，`gz:` 前缀标识，旧格式照常解析）。

**Q：改了 ROI 的名字或删了框，下游的线断了？**
正常——动态端口是**按名字**建的。改完要把断掉的连线重新接到新的端口名上。
（当前配置界面**不能手动改** ROI 名，唯一性由自动改名保证。）

**Q：带 domain 的图显示出来框外是黑的，图坏了吗？**
**不是**。domain 外本来就不参与运算，显示成黑是 ROI 的直观表达，只是观感。

**Q：勾选排除模式后 `MaskRegion` 也跟着反了吗？**
没有，这是有意的。`MaskRegion` 恒为"哪里有效"（正语义），反转只发生在 `MaskImage` 那一层。

**Q：主界面选"不显示"却还是弹图？**
已修：`DisplayViewIndex = 0` 现在真的不发布。窗口号是 1~9 直传，选窗口 1 就进第 1 格。

**Q：模板匹配换了 domain 路线后老是找不到目标？**
换到 `Domain_` 图后**模型需要重新学习**——搜索范围与参考坐标系的口径变了，
旧模板的坐标基准对不上（现象是"下游坐标整体偏一个 ROI 左上角"或直接不命中）。
