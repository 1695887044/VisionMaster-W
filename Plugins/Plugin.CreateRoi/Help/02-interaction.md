# ROI · 交互与坐标系

> 分类：常用工具 ｜ 来源：插件 Plugin.CreateRoi

这一页讲**怎么把框画对、怎么把坐标算对**：三种编辑入口（画布右键 / 拖拽句柄 / 参数微调数值框）、
画笔涂抹与擦除、掩膜预览与排除模式，以及**每个输出端口用的是哪一套坐标系**——
现场大部分"结果整体偏移"的问题都出在最后这一节。

## 一、界面布局

```
┌───────────────────────────────────────────────────────────┐
│ 图像输入：图像路径 [🔗 链接上游的 SrcImage]   显示窗口 [不显示/窗口1…9] │
├──────────────┬────────────────────────────────┬───────────┤
│ ROI 列表      │  画布（ImageEdit）              │ 参数微调   │
│ 名字  [形状]  │  右键 → 区域 → 新建矩形/圆/椭圆   │ (选中后可编辑)│
│ 选中即联动    │  拖拽句柄粗调大小与角度           │ 每参数一个数值框│
│ 删除 / 清空   │  涂抹 / 擦除 + 笔刷半径 + 清除涂抹 │ 中心行列/角度 │
│              │  原图 ○ 掩膜预览 ○  排除模式 □    │ 半长半宽…    │
└──────────────┴────────────────────────────────┴───────────┘
```

- **底图**：「图像输入」那一行（界面上标签写的是"图像路径"）绑的就是 `SrcImage` 端口；
  在流程里**试运行一次**，上游图会自动显示到画布上（`OnViewLoaded` 回填当前值）。
- **显示窗口**：下拉的第 0 项是"不显示"（对应 `DisplayViewIndex = 0`），往后 1~9 就是主界面的视图窗口号。
- 左列是主区（ROI 列表 + 参数微调在列表下方）；**未选中 ROI 时参数微调只剩标题一行**，这是正常的。

## 二、画框与编辑：三个入口，一个数据源

三种改框的动作**全部经由同一份 `RoiList`**，互相不直接对话，所以永远同步：

| 入口 | 怎么用 | 适合什么 |
| --- | --- | --- |
| 画布右键 → 区域 → 新建 | 新建矩形 / 圆形 / 椭圆；新建即进列表并自动取唯一名 | 首次画框 |
| 拖拽句柄 | 选中框后拖动角/边/中心句柄 | **粗调**（实时跳动，参数框跟着变） |
| 参数微调数值框 | 选中 ROI 后逐个数值框精调 | **精调**（亚像素、固定角度） |

- **删除选中**：列表里选中后按 `Del`，或点「删除」按钮。
  焦点在文本框里时 `Del` 不触发（那是文本编辑键），此时请用按钮。
- **清空**：点「清空」会弹**二次确认**（"该操作不可撤销"）。
- **列表 ↔ 画布双向选中联动**：列表里点一项 → 画布把句柄挂到对应的框上；
  画布点某个框 → 列表定位到那一项；画布点空白 → 列表取消选中。
- **数值框的口径**：角度类参数按 4 位小数（`F4`，弧度是小量），其余 1 位（`F1`）；
  写值按**不变区域性**解析（小数点永远是 `.`），**非法输入直接按当前值还原显示**，不崩也不静默改值。
- **改了就在掩膜预览模式下会延迟约 200 毫秒重算**（防抖）——拖拽时看到预览"慢半拍"是正常的。

## 三、涂抹与擦除：画笔修正 ROI

拖句柄只能改"规则形状"，不规则的边界靠画笔。工具条三选一：**正常 / 绘制涂抹 / 擦除涂抹**，
外加「笔刷」半径（像素，正数）与「清除涂抹」按钮。

| 动作 | 效果 | 显示 |
| --- | --- | --- |
| 绘制涂抹 | 涂到的地方**也算有效区**（并入 ROI） | 净涂抹（涂 − 擦）显示为橙色 |
| 擦除涂抹 | 涂掉的地方**从有效区里挖走**，且**不会出现在裁剪图里** | 用**红色细轮廓**标出（不是红填充，免得以为又涂了一笔红的）；被挖空处露出底图 |
| 清除涂抹 | 一键置空两类涂擦，画布同步清除 | — |

**合并口径（铁律）**：

```
合并有效区域 = (ΣROI ∪ 涂抹) − 擦除        （恒为正语义，不随排除模式反转）
```

- 这条区域给 `MaskRegion` 端口；擦除同样作用于**每一个 ROI 的裁剪域**
  （历史 bug：涂擦以前"只影响预览"，现在真的会改变输出）。
- **涂擦会随方案保存**：区域被编码成游程文本 `行,起列,止列;…`（超过 4KB 自动 GZip + base64，带 `gz:` 前缀）。
  数据损坏时按"无涂擦"降级处理，不会打断编辑。

## 四、掩膜预览与排除模式

- **「原图」/「掩膜预览」单选**：预览模式看到的和运行期产出的同口径（合并区域 → 掩膜 → 抠图）。
- **排除模式（`MaskInvert`，界面上"排除模式（ROI 外有效）"）**：勾选后 `MaskImage` 黑白反转——
  ROI 圈的反而变黑、圈外保留。适合"这块是坏的/不要的，检测除它以外的所有地方"。
  **注意 `MaskRegion` 不会跟着反转**（正语义只有一份，反转是"视图"不是"数据"）。
- 抠图算法是 `原图 × 掩膜 ÷ 255`（彩色先把掩膜合成三通道），缩放因子固定 1/255 以免截断把有效区刷成白屏。

## 五、坐标系：每个端口到底在哪套坐标里

**存盘口径**：ROI 全部是**图像像素系 `(Row, Col)`**；角度是**弧度**（界面上按度显示、存进方案的是弧度）。

| 形状 | `Params` 的含义（界面名字） | 重建算子 |
| --- | --- | --- |
| 矩形 | `[中心行, 中心列, 角度(弧度), 半长, 半宽]` | `gen_rectangle2`（可旋转矩形） |
| 圆形 | `[圆心行, 圆心列, 半径]`（只有 3 个，不补位） | `gen_circle` |
| 椭圆 | `[圆心行, 圆心列, 旋转角(弧度), 长半轴, 短半轴]` | `gen_ellipse` |

| 输出 | 坐标系 | 换算 |
| --- | --- | --- |
| `Domain_名字` | **全局**（原图坐标系，一点没动） | **不用换算**，下游插件直接吃 |
| `Crop_名字` | **本地**（裁剪图自己的坐标系） | `global_row = local_row + OffsetRow_名字`；`global_col = local_col + OffsetCol_名字` |
| `OffsetRow_名字` / `OffsetCol_名字` | 全局（原点在原图里的位置） | 裁剪原点 = **有效域外接矩形的左上角**（`smallest_rectangle1`） |
| `MaskRegion` / `MaskImage` | 全局（与原图同尺寸） | 不用换算 |

**三个必须记住的点**：

1. **不旋转图像**。即使画的是斜矩形，裁剪也只是取它的**外接矩形**，所以回变换永远只是**平移**，没有旋转项。
   表现："裁剪图比预期大一点/歪一点"是正常的——它框的是外接矩形，不是斜边贴齐。
2. **Offset 是可选端口，不连不报错**，坐标静默错。要么老老实实连上，要么改用 `Domain_` 路线。
3. **本轮失败的 ROI，Offset 会被写成 0**（不会留上一轮的脏值）。
   所以"偏移突然变成 0"通常意味着那个框本轮被跳过了，去日志找 `跳过裁剪`。

## 六、ROI 传给下游：三条路线怎么选

| 路线 | 连什么 | 用在什么下游 | 代价 |
| --- | --- | --- | --- |
| **A. 零换算（首选）** | `Domain_名字` → 下游的图像输入 | 自己认 domain 的"智能"插件：模板匹配 `Image`、Blob 缺陷检测 `SrcImage`、卡尺测量 `SrcImage`、码读取 / OCR / 颜色检查 / YOLO `Image` | 内存不省（图还是整幅大），但**下游一个都不用改** |
| **B. 真裁剪 + 回变换** | `Crop_名字` + `OffsetRow_名字` + `OffsetCol_名字` | 只管手里这张图的"傻"处理：C#脚本、结果上报；或纯粹为了省算力缩小图 | 必须**三条线一起连**，漏一条就静默偏移 |
| **C. 区域 / 掩膜** | `MaskRegion`（`HRegion`）、`MaskImage`（二值图） | 需要"区域"或"掩膜"参与运算的下游（如 Blob 缺陷检测的 `MaskRegion` 限制检测区） | 反转只发生在 `MaskImage`，别指望 `MaskRegion` 反 |

```
图像采集.OutputImage ──▶ ROI.SrcImage
ROI.Domain_焊盘区 ─────▶ 模板匹配.Image            （返回全局坐标）
ROI.MaskRegion ────────▶ Blob缺陷检测.MaskRegion   （限制检测区）
ROI.Crop_小图 ─────────▶ C#脚本.Image
ROI.OffsetRow_小图 ────▶ C#脚本.rowOffset
ROI.OffsetCol_小图 ────▶ C#脚本.colOffset
ROI.RoiCount ──────────▶ 下游循环的上界
```

> **注意**：颜色类算子（区域颜色检查 / 颜色序列检查）**不接上游 ROI**——它们有自己的采样区。
> 但可以把 `Domain_名字` 接到它们的 `Image`，等于"先圈定再看"。

## 七、命名与重名规则

- 列表里显示的是 `名字  [矩形/圆形/椭圆]`（形状用中文名）。
- **名字是端口的键**：`Crop_名字` / `Domain_名字` / `OffsetRow_名字` / `OffsetCol_名字`，下游按名引用。
- **重开配置再画不会撞名**：控件的命名序号每次打开配置都归零，所以强制唯一名——
  撞名时取同词干现有最大序号 +1（`ROI_0`/`ROI_2` 在场 → 新框叫 `ROI_3`；无序号名"缺陷区" → "缺陷区_1"），并回写画布标签。
- **当前界面不能手改 ROI 名**（保证唯一性即可），语义命名是后续候选。
- **改名或删框会断开对应的连线**（动态端口按名字重建），改完记得重接。

## 八、常见问题与现场排障

**Q：下游坐标整体偏一个 ROI 左上角的距离？**
用了 `Crop_` 却没连 `Offset`（不报错，静默错）。改连 `Domain_`，或把两个 Offset 一起连上。

**Q：画布点选后数值框不动？**
选中联动是双向的，正常路径下数值框会实时跟着拖拽跳动。
若真出现"点选无效"，检查是不是焦点还在文本框里（`Del`/选中逻辑会被文本编辑键拦住）。

**Q：涂擦完预览没变化？**
确认切到了「掩膜预览」模式（实时刷新只在预览模式下做，且带 200ms 防抖）。

**Q：掩膜预览空白或不对？**
① 确认底图已经在画布上（上游已连并试运行过）；② 确认 ROI 参数合法——圆要 3 个数、矩形/椭圆要 5 个数；
③ 排除模式下"框内变黑"正是预期效果，不是坏了。

**Q：`RoiCount` 比列表里的项数少？**
它是**本轮实际成功输出的裁剪图数**。去日志找 `跳过裁剪` / `裁剪失败`，
常见原因是那个框的形状参数无效，或被擦除涂得一点不剩（"有效区域为空（被擦除殆尽）"）。

**Q：重开方案后涂擦没了？**
旧 bug 已修（恢复顺序问题）。若仍丢，先确认方案确实保存过；涂擦是随方案序列化的游程文本。

**Q：为什么发布到主界面的是"整幅带黑边"的合成图，而不是每个 ROI 的小图？**
有意为之：以前逐 ROI 发到同一窗口会互相覆盖、只能看到最后一个。
现在一帧发布**合并掩膜合成图**，全部 ROI 与涂擦修正在同一张图上看清；要小图请用 `Crop_名字` 端口。

**Q：想画多边形/任意形状？**
当前版本只支持**矩形 / 圆 / 椭圆**三种参数化形状，任意边界请用「绘制涂抹」补、用「擦除涂抹」挖。
