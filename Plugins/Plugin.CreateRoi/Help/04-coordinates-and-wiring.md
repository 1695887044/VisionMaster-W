# ROI · 坐标系与下游接线

> 分类：常用工具 ｜ 来源：插件 Plugin.CreateRoi

现场大部分"结果整体偏移""找不到目标"的问题都出自这一页：**你连的是哪个输出，它就在那套坐标系里说话**。

## 一、两套坐标系，一张图看懂

```
原图（全局坐标，行 Row / 列 Col）
┌────────────────────────────────────────────┐
│                                            │
│        ┌───────────────┐                   │
│        │  ROI "焊盘区"  │                   │
│   (r1,c1) ← 有效域外接矩形的左上角           │
│        │               │                   │
│        └───────────────┘                   │
└────────────────────────────────────────────┘

Domain_焊盘区 = 整幅原图，只是把 ROI 外设为 domain → 坐标仍是 (Row, Col)
Crop_焊盘区   = 从 (r1,c1) 裁出的一块小图 → 它自己的左上角是 (0,0)
OffsetRow_焊盘区 = r1      OffsetCol_焊盘区 = c1
```

**存盘口径**：ROI 全部是图像像素系 `(Row, Col)`；角度是**弧度**。

## 二、每个输出端口用的是哪套坐标

| 输出 | 坐标系 | 换算 |
| --- | --- | --- |
| `Domain_名字` | **全局**（原图坐标系，一点没动） | **不用换算**，下游插件直接吃 |
| `Crop_名字` | **本地**（裁剪图自己的坐标系） | `global_row = local_row + OffsetRow_名字`；`global_col = local_col + OffsetCol_名字` |
| `OffsetRow_名字` / `OffsetCol_名字` | 全局（原点在原图里的位置） | 裁剪原点 = **有效域外接矩形的左上角**（`smallest_rectangle1`） |
| `MaskRegion` / `MaskImage` | 全局（与原图同尺寸） | 不用换算 |

**三个必须记住的点**

1. **不旋转图像**。即使画的是斜矩形，裁剪也只取它的**外接矩形**，所以回变换永远只是**平移**，没有旋转项。
   表现："裁剪图比预期大一点/歪一点"是正常的——它框的是外接矩形，不是斜边贴齐。
2. **Offset 不连不报错**，坐标**静默**整体偏一个框左上角的距离。要么三条线一起连，要么改用 `Domain_` 路线。
3. **本轮失败的 ROI，Offset 会被写成 0**（不留上一轮脏值）。
   所以"偏移突然变 0"通常意味着那个框本轮被跳过，去日志找 `跳过裁剪`。

## 三、三条路线怎么选

| 路线 | 连什么 | 用在什么下游 | 代价 |
| --- | --- | --- | --- |
| **A. 零换算（首选）** | `Domain_名字` → 下游的图像输入 | 自己认 domain 的"智能"插件：模板匹配 `Image`、Blob 缺陷检测 `SrcImage`、卡尺测量 `SrcImage`、码读取 / OCR / 颜色检查 / YOLO `Image` | 内存不省（图还是整幅大），但**下游一个都不用改** |
| **B. 真裁剪 + 回变换** | `Crop_名字` + `OffsetRow_名字` + `OffsetCol_名字` | 只管手里这张图的"傻"处理：C#脚本、结果上报；或纯粹为省算力把图缩小 | 必须**三条线一起连**，漏一条就静默偏移 |
| **C. 区域 / 掩膜** | `MaskRegion`（`HRegion`）、`MaskImage`（二值图） | 需要"区域"或"掩膜"参与运算的下游（如 Blob 缺陷检测的 `MaskRegion` 限制检测区） | 反转只发生在 `MaskImage`，别指望 `MaskRegion` 反 |

为什么 `Domain_` 能"下游零改动"：HALCON 的算子**只在 domain 圈内干活**。
实测 `find_shape_model` 在 domain 图上搜索，命中返回的仍是**全局坐标**，domain 外的目标直接不命中。
所以"限制搜索区"这件事由图像自己带着，不需要每个插件各写一遍坐标回加。

## 四、接线示范

```
图像采集.OutputImage ──▶ ROI.SrcImage

ROI.Domain_焊盘区 ─────▶ 模板匹配.Image            （返回全局坐标）
ROI.MaskRegion ────────▶ Blob缺陷检测.MaskRegion   （限制检测区）
ROI.Crop_小图 ─────────▶ C#脚本.Image
ROI.OffsetRow_小图 ────▶ C#脚本.rowOffset          （global_row = local_row + 本值）
ROI.OffsetCol_小图 ────▶ C#脚本.colOffset          （global_col = local_col + 本值）
ROI.RoiCount ──────────▶ 下游循环的上界
ROI.MaskImage ─────────▶ 需要二值掩膜参与运算的下游
```

**多 ROI 批量**：想在脚本/循环里逐个取图，端口名是固定的 `Crop_{名字}` 形式，
按 `RoiList` 的名字拼端口名即可；循环上界用 `RoiCount`（成功数），**不要用配置数**，否则越界。

## 五、坐标换算写在哪里

| 你的下游是 | 该在哪做换算 |
| --- | --- |
| 认 domain 的检测类插件 | **不用做**，连 `Domain_名字` 就完事 |
| C#脚本 / 数学计算 | 在脚本里 `全局 = 本地 + Offset`，把两个 Offset 当输入参数连进来 |
| 结果上报 / 画回原图 | 必须换回全局再上报，否则标注框会整体偏到左上角 |
| 又送回另一个视觉插件 | 优先改连 `Domain_`；非要用裁剪图就把 Offset 一起送过去 |

## 六、几个容易误解的边界

- **`Crop_` 的图不是 ROI 的最小包围形状**，而是有效域的**外接矩形**；`crop_domain` 会把 **domain 一起平移保留**，
  所以斜矩形/圆的四角像素虽在图里、却**不在 domain 内**。认 domain 的算子不受影响；
  把图当整幅读像素的下游（存图、上报、脚本直接取某点灰度）会读到四角——这是外接矩形的固有代价。
  要"整幅原图 + 只圈内有效"，用 `Domain_名字`。
- **`Domain_` 图框外显示成黑**是正常的，不是图坏了——domain 外本来就不参与运算，黑只是 ROI 的直观表达。
- **擦除涂抹同样作用于每个 ROI 的有效域**：擦掉的地方既不进 `Crop_`，也不进 `Domain_`。
- **排除模式不改坐标**，只改 `MaskImage` 的黑白；`MaskRegion` 永远是"哪里有效"。
- **颜色类算子（区域颜色检查 / 颜色序列检查）不吃上游 ROI**——它们有自己的采样区。
  但可以把 `Domain_名字` 接到它们的 `Image`，等于"先圈定再看"。
- **模板匹配换到 `Domain_` 路线后模型要重新学习**：搜索范围与参考坐标系的口径变了，
  旧模板的坐标基准对不上（现象是"下游坐标整体偏一个 ROI 左上角"或直接不命中）。
