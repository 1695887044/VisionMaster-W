# 调用流程 · 端口与参数

> 分类：流程控制 ｜ 来源：插件 Plugin.RunFlow

本页给全：两个输入端口与三个输出端口的类型、必填性、默认值、"接不上/没填会怎样"，
以及参数面为什么只有这两行、另一半配置为什么在被调用流程身上。

## 输入端口

| 端口 | 类型 | 必填 | 默认 | 面板标签 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `FlowName` | `string` | 是 | 空串 | 目标流程名 | 要当子程序跑的流程名。界面是**封闭候选下拉**（只列勾了「子程序」的流程）；先 `Trim()` 再判空；**按名精确查找**（`Ordinal`，区分大小写） |
| `TimeoutMs` | `int` | 是 | `60000` | 等待超时(ms) | 父流程愿意等多久（毫秒）。生效值有 `1000` ms 下限；**超时只报错，不打断目标** |

> **端口名与代码里的属性名不一致**（连线与存档都用端口名，按属性名去找会对不上）：
> `FlowName` 那一行的属性是 `TargetFlowPort`、`Message` 那一行的属性是 `InvokeMessage`；
> `Invoked` 与 `ElapsedMs` 两侧同名。

两个端口都声明为必填（`IsRequired` 默认 `true`，本插件没关）：
只要打开参数面板点过一次「确定」，两行的值（空串 / 60000）就会被写进步骤常量，编译期不再报缺失；
从没确认过面板的步骤，编译期会对未配置的必填端口报
`[参数缺失] '<步骤名>' 的必填参数 'FlowName' 未配置！`（`TimeoutMs` 同理）。
于是 `FlowName` 空名的失败**推迟到运行期**，表现为 `目标流程名不能为空`。

## `FlowName` 这一行的语义是"名字"

- 填的是**名字本身**，例如 `回原`、`工位2检测`。不要写成 `流程:回原`、`{回原}`、带引号、带路径。
- 界面是**封闭候选下拉**：候选由宿主按当前方案现取，只列「调用方式」勾了「子程序」的流程。
  下拉里没有某条流程 = 它没勾「子程序」，回「流程管理」补勾即可（不是下拉坏了）。
- 候选文本可能带状态后缀：`（已禁用）` / `（步序已加密）` / `（当前流程，不能调用自己）`。
  这些项**仍可选**，但运行到本步骤必然按门禁失败——后缀就是失败原因，先按后缀去处置。
- **不提供 🔗 链接**：流程名是"名字"不是"值"，新配置不能由上游文本输出提供（R33）。
  要按配方 / 工单决定跑哪条，用「分支匹配」或「条件判断」把不同的「调用流程」分到各分支里。
- **老工程已有的上游连线**：升级前连过的步骤，连线仍生效；下拉照常显示，选一项即拆线改成固定值
  （不选则保持原行为）。绑定弹窗对这类端口也不会再放开"上游端口"选项。
- 方案里一条子程序都没有时，这一行退化成可手填的文本框并提示"无候选，可手填"；
  此时手填的名字过得了界面，但运行期一定被门禁拦下。
- **改名连锁**：被调流程改名 = 所有调用它的步骤失配（下拉里显示为空，存档值仍是旧名）。
  改名前先全局搜一遍旧名，改完把调用点重新选一遍。

## `TimeoutMs` 的取值范围与后果

| 情形 | 生效值 | 后果 |
| --- | --- | --- |
| 不填（默认） | `60000` ms | 按一分钟等 |
| 填 `0` / 负数 / `500` | `1000` ms | **不是"不等"，也不是"无限等"，是等 1 秒** |
| 填得比子流程最坏耗时小 | 你填的值 | 超时返回，但**子流程还在后台跑到自然结束**：父子同时动 |
| 上游连一个整数输出 | 该值 | 常用来把超时做成配方参数 |

- 等待实现是 20 ms 一拍的轮询，同时盯「父流程被取消」与「超时」两件事，不是 `Wait(timeout)` 一次性阻塞。
- 填大了的代价：把"子流程没跑上"这种问题拖成一整段无谓等待，直接体现在父流程 CT 上。
- 数值转换不过去时报框架消息（原文形态）：
  `端口 TimeoutMs 无法将上游输出值转换为类型 System.Int32。上游值类型：…，上游端口：…`

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Invoked` | `bool` | 子流程**整体**是否成功。跑完了但有 N 个步骤失败 → 这里也是 `false`。每次执行开头先清成 `false` |
| `ElapsedMs` | `int` | 从开始调用到返回的毫秒数，**包含等待全程**；门禁早期失败也带真实耗时（通常个位数）。开头清 `0` |
| `Message` | `string` | 调用结果说明。成功是简述，失败是**可直接展示给操作工的中文原因**（19 条原文全表见《字段与排错》）。开头清空串 |
| `Success` | 基类自带 | 本步骤是否成功。本插件**照实**把 `Invoked` 的结果写进 `Success`：调用失败就是步骤失败 |
| `ErrorMessage` | 基类自带 | 失败原因。**注意**：「目标流程名为空」这一条分支只写了 `Message`，见《排错》第三节 |

**没有"容错开关"**：需要"调不通也继续走"，请把本步骤放进 `If` 容器或用 `Invoked` 做分支判断，
而不是让插件偷偷吞掉失败。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

本插件**没有模块级参数**（一个 `[StepConfig]` 都不写），参数面全部由输入端口表达；
也**没有自定义界面**，宿主发现没有自定义视图接口时会自动包一层通用参数面板
（每行 = 标签 + 值 + 链接 + 清除；`FlowName` 那一行是封闭候选下拉，没有链接与清除）。

另一半配置在**被调用流程的属性**上：那条流程的「调用方式」是**多选位集**，
五个位分别是 手动 / 定时 / 变量 / **子程序** / HTTP外部调用，本算子的门禁只看「子程序」这一位。
勾了"定时"或"HTTP外部调用"**不放行**子程序调用；位集全表与老值迁移口径见《字段与排错》。

## 改了会影响什么

| 改动 | 连锁 |
| --- | --- |
| `FlowName` 的值 | 只决定"调哪条"；写成一个不存在/未勾子程序的名字 = 当场失败，不会产生半跑状态 |
| `TimeoutMs` | 决定父流程最多等多久；不改变子流程本身的执行内容与时长 |
| 子流程被禁用 / 加密 / 改名 | 本步骤立刻按门禁失败，**父流程侧不需要重新编译**，但建议重跑一遍确认 |
| 子流程步骤增删 | 宿主会在会话需要重建时重新编译并注册（图纸改过/换过方案），失败会以编译错误原文回到 `Message` |
