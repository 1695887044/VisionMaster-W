# 调用流程 · 排错

> 分类：流程控制 ｜ 来源：插件 Plugin.RunFlow

本页按**现象**给排查路径与判定树；19 条门禁/失败消息的**原文逐字对照表**、超时口径的具体数值、
日志原文全表在《字段与排错》那一页，这里不重复抄，只说"先查什么、为什么、怎么改"。

## 一、三十秒判定树

```
本步骤红
 ├─ Message 说"没有名为「X」的流程"        → 名字失配（大小写 / 中间空格 / 在别的方案里 / 上游值不是纯流程名）
 ├─ Message 说"未开放「子程序调用」"        → 调用方式没勾「子程序」位（括号里给的就是当前值）
 ├─ Message 说"已被禁用"                   → 那条流程在「流程管理」里被停用
 ├─ Message 说"步序已加密"                 → 加密流程不能当子程序（把要复用的段单独建一条不加密的）
 ├─ Message 说"正在运行中…未执行"          → 目标此刻在跑：上一轮超时没打断 / 定时或 HTTP 也在唤起 / 自己调自己
 ├─ Message 说"被其它执行占用"             → 并发抢不到会话锁（并行分支或两条父流程调同一条）
 ├─ Message 说"编译失败：…"                → 子流程自己有编译错误，先去把那条流程单独跑通
 ├─ Message 说"跑完但有 N 个步骤失败"      → 子流程跑完了但内部有红步骤，去运行日志找那条流程
 ├─ Message 说"执行超时（>Xms），目标仍在后台继续" → 超时设小了；目标没被打断，见第四节
 └─ Message 说"当前执行环境没有绑定流程引擎" → 执行环境没装配调用器（检查夹具/简化上下文），正式界面出现即报修
```

## 二、步骤绿，但父流程拿不到子流程算出来的值

按这个顺序查（命中率从高到低）：

1. **作用域混用**：子流程写的是 `Global` 全局变量，父流程却去读同名的**运行时变量**（或反过来）。
   两者是两个东西，框架刻意不做"先找运行时再找全局"的自动路由——同名时自动路由就是歧义。
2. **读得比写得早**：本步骤返回后父流程才该读子流程写的量；若写那一值的那一步在子流程里被禁用/失败，
   父流程读到的就是空或旧值（配合 `Invoked=false` 一起看）。
3. **靠了局部变量**：流程内的局部变量每轮执行新建一份，跨流程、跨轮传值都不能靠它。
4. **变量名拼错**：这类"名字"行取不到时通常**静默为空**、不报错，所以查不到就先怀疑名字与作用域。
5. 上面都对，再确认子流程那一步**真的执行到了**（`Message` 成功 = 子流程整条真的跑过，副作用是真的）。

> 不存在"子流程的输出端口映射到父流程"这种用法：`Invoked` / `ElapsedMs` / `Message` 是调用结果，不是业务数据。

## 三、"没填目标流程名"这一条为什么界面上没原因

这一条分支由**插件自己**拦住（不会走到宿主调用器），它把原因写进 `Message` 端口并记一条错误日志，
**没有**写 `ErrorMessage`——`ErrorMessage` 保持空串。

后果与处置：现场若把报警/记录接在 `ErrorMessage` 上，这条路径会收到空消息。
**报警链路请把 `Message` 一并连出去**（其余所有失败分支 `ErrorMessage` 与 `Message` 同源）。

## 四、第一次能调、第二次报"正在运行中"

说明上一次的子流程**还没跑完**。两种成因：

- 上一次**超时**返回了：超时不打断目标，它还在后台跑，父流程这一轮再来就撞上；
- 有别的触发源也在跑同一条（定时 / 变量 / HTTP外部调用，或另一条父流程）。

处置三选一：① 把 `TimeoutMs` 调到子流程最坏耗时之上（含等机构、重试拍照）；
② 给子流程加互斥的全局变量条件；③ 把触发收口到一处。

**"调不通"不会排队、不会补跑**：这是成环保护（自己调自己、A 调 B 又调 A 都在第二次进入正在运行的那条时被拦下）。
真需要重复执行，请用 `While` 容器在一条流程里循环，或用定时调用方式让那条流程自己周期跑。

## 五、并行分组里放本步骤

门禁失败时本步骤是**一支普通业务失败**：不抛异常、不升级成故障源、不影响并行容器的其它分支判定口径。
但两条纪律要记住：

- **不要让多个并行分支调用同一条子流程**——后到的那一单会撞上"正在运行 / 被其它执行占用"，
  而且结果取决于调度顺序，看起来像偶发。
- 并行分支里**避免写同一个全局变量**（宿主有并行写冲突检查，编译期就会提示）。
  传值靠全局变量 + 子程序调用，本身就是串行设计，别叠并行。

## 六、节拍 / CT 异常

| 现象 | 查 |
| --- | --- |
| 父流程整轮变慢 | `ElapsedMs` 是不是接近子流程整条耗时——排产要按"父子相加"算 CT，别按单步算 |
| 偶发长时间等待后才失败 | `TimeoutMs` 是否设得过大，把"没跑上"拖成整段等待 |
| 超时后机构动作"打架" | 超时不打断目标：加大超时，或在子流程末尾加互斥的全局变量条件 |
| 急停后子流程还在动 | 设计口径：本步骤只结束**等待**，取消令牌归子流程自己的引擎管，会如实报"目标仍在后台收尾" |

## 七、编译期就红

`[参数缺失] '<步骤名>' 的必填参数 'FlowName' 未配置！`：该步骤的参数面板从没确认过值。
打开面板、填上流程名（超时可以先留默认 `60000`）、点「确定」。
两个端口都是必填，`TimeoutMs` 同理——它自带默认值，所以点过一次确定就不会再报。

## 八、上线前自检

1. 每条被调流程：启用、未加密、调用方式含「子程序」，且**单独跑一遍能跑通**；
2. 所有调用点的流程名与「流程管理」逐字一致（把名字当字符串常量管，改名前先全局搜）；
3. `TimeoutMs` 按"子流程最坏耗时 + 余量"填；不要用 0 或小值表达"不等待"；
4. 传值清单落纸：哪些全局变量是入参、哪些是出参、谁写谁读、作用域一律 `Global`；
5. 并行分支里不出现"多个分支调同一条子流程 / 写同一个全局变量"；
6. 带机构工位：试运行/调试前确认子流程的动作处于安全状态（点「执行」会真跑）；
7. 失败处置口径写进工艺文档：停线，还是用 `Invoked` 走兜底分支（本算子没有"失败不阻断"开关）。
