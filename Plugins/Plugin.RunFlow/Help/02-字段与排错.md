# 调用流程 · 字段与排错

> 分类：流程控制 ｜ 来源：插件 Plugin.RunFlow
> 本页给全：门禁与失败消息原文、流程名这一行到底怎么填、超时口径的具体数值、
> 父子流程之间传值的作用域细则、现象→查哪一项。

## 「目标流程名」这一行怎么填（本仓 R33/R34：语义是"名字"，不是"值"）

| 要点 | 说明 |
| --- | --- |
| 填的是**名字本身** | 下拉里选中的就是流程名，例如 `回原`、`工位2检测`。**不要**改成 `流程:回原`、`{回原}`、带引号、带路径 |
| 候选下拉只列子程序 | 候选由宿主按**当前方案**现取：只列「调用方式」勾了「子程序」的流程。下拉里没有某条流程 = 它没勾「子程序」（不是下拉坏了） |
| 状态后缀 | 下拉里的 `回原（已禁用）`、`回原（步序已加密）`、`回原（当前流程，不能调用自己）` 仍可选中，但运行到本步骤必然按门禁失败；后缀就是失败原因。正常流程显示纯名字 |
| 没有链接按钮 | 流程名是"名字"不是"值"：这一行**不提供 🔗**，新配置不能由上游文本输出提供（R33）。要按配方选流程，用「分支匹配」/「条件判断」把不同的「调用流程」分开 |
| 老工程的上游连线 | 升级前已经连了上游的步骤：连线仍生效，但面板里的下拉**照常显示**（带提示"选择一项会改为固定值并清除旧连线"）。选一项即拆线；不选则保持原行为 |
| 匹配口径 | `StringComparison.Ordinal` **精确匹配**：区分大小写、区分中间的空格；两端空白会被 `Trim` 掉 |
| 必填判定 | 两个端口（`FlowName`、`TimeoutMs`）都按**必填**声明。参数面板从没点过「确定」时，编译期会报 `[参数缺失] '<步骤名>' 的必填参数 'FlowName' 未配置！`（`TimeoutMs` 同理）；点过确定后两行的值（空串 / 60000）写进步骤常量，编译就过了 —— 于是 `FlowName` 没选的失败**推迟到运行期**，表现为"目标流程名不能为空" |
| 改名连锁 | 被调流程**改名 = 所有调用它的步骤都失配**（下拉里显示为空，值还是旧名）。改名前先全局搜一遍旧名 |
| 候选取不到 | 方案里一条勾了「子程序」的流程都没有时，这一行退化成可手填的文本框并提示"无候选，可手填"——此时手填仍会过界面，但运行期一定被门禁拦下（先回「流程管理」勾子程序） |
| 类型不符 | `TimeoutMs` 是整数端口。上游给的类型转不过去时，抛的是框架消息：`端口 TimeoutMs 无法将上游输出值转换为类型 System.Int32。上游值类型：…，上游端口：…` |

## 被调用流程需要勾什么（调用方式位集）

一条流程的「调用方式」是**多选位集**，不是单选：

| 位 | 界面文本 | 含义 |
| --- | --- | --- |
| `Manual` | 手动 | 只由本机界面的运行入口触发（新建流程的默认态，不占位） |
| `Timer` | 定时 | 按该流程的定时间隔自动跑（间隔下限 100ms） |
| `Variable` | 变量 | 指定的触发变量**由假变真**（上升沿）时跑一次 |
| `Subroutine` | **子程序** | **允许被「调用流程」步骤调用**——本算子的门禁只看这一位 |
| `Http` | HTTP外部调用 | 允许经 `/flow/{流程名}` 接口触发 |

勾了"定时 / HTTP外部调用"**不放行**子程序调用。失败消息会把当前调用方式原样打出来，
组合用 ` / ` 连接（例：`当前调用方式：定时 / HTTP外部调用`），照它去「流程管理」补勾「子程序」即可。
认不出来的损坏值显示成 `未知(<整数>)` 而不是回落"手动"——就是为了让"勾了却没生效"这种问题一眼可见。

## 门禁与结果消息原文（`Message` 端口 / 运行日志）

判定顺序固定，任一不过 → 子流程**一步都不跑**，当场失败返回。

| # | 消息原文（`X` = 目标流程名） | 触发条件 | 现场处置 |
| --- | --- | --- | --- |
| 1 | `目标流程名不能为空` | 端口值为空/纯空格（插件层拦住，不会走到宿主） | 打开面板从下拉里选一条流程名并确认 |
| 2 | `目标流程名不能为空（在「调用流程」步骤里选择或填写流程名）` | 名字空但进到调用器（如其它调用方） | 同上 |
| 3 | `调用前父流程已被取消（急停 / 停止）` | 还没开始跑，父流程的取消令牌已置位 | 正常收尾行为，急停后重现 |
| 4 | `当前方案中没有名为「X」的流程` | 名字不匹配（流程刚改过名/大小写/中间空格/另一方案） | 在面板下拉里重新选一条 |
| 5 | `流程「X」已被禁用，不能作为子程序调用` | 该流程在流程管理里被停用 | 启用它，或换成启用的那条 |
| 6 | `流程「X」未开放「子程序调用」（当前调用方式：<文本>）。请在「流程管理」里勾选「子程序」后重试` | 调用方式没勾「子程序」位 | 按括号里的当前值补勾 |
| 7 | `流程「X」步序已加密，无法编译调用` | 该流程步序加密 | 解密，或把要复用的段单独建一条不加密的流程 |
| 8 | `流程「X」正在运行中，本次子程序调用未执行（避免成环等待）` | 目标此刻 `IsRunning`（含自己调自己、A↔B 互调、上一轮超时后仍在后台跑、被定时/变量/HTTP 同时唤起） | **不排队不补跑**。见下节"超时后"的竞态 |
| 9 | `流程「X」正在运行中，不能在此时重建会话` | 图纸改过需要重编译，但目标正在跑 | 停下那条流程的触发源再改流程 |
| 10 | `流程「X」编译失败：<逐条编译错误，用；分隔>` | 该流程本身有编译错误（必填参数缺、连线断、条件变量未绑定等） | 先去把那条流程单独跑通 |
| 11 | `等待流程「X」执行超时（><毫秒>ms），目标仍在后台继续` | 等待超过生效超时（下限 1000ms） | 加大 `TimeoutMs`；**注意目标没被打断**，见下节 |
| 12 | `流程「X」执行中父流程被取消（急停），目标仍在后台收尾` | 等待期间按了急停/停止 | 正常口径；确认子流程的机构/IO 收尾安全 |
| 13 | `流程「X」执行被取消（急停 / 停止）` | 子流程自己被打断 | 查是谁停了它 |
| 14 | `流程「X」执行异常：<异常消息>` | 子流程引擎抛异常 | 按消息内容报修 |
| 15 | `流程「X」正在运行中（被其它执行占用），本次子程序调用未执行` | 检查通过但**抢会话锁失败**（并发窗口） | 如实失败，**不会假成功**。同一子流程被并发调用时后到的那一单会走这条 |
| 16 | `流程「X」跑完但有 <N> 个步骤失败（详见运行日志）` | 跑完了，但本次有失败步骤（`Invoked=false`） | 去运行日志看那条流程哪几步红了 |
| 17 | `流程「X」执行完成` | 成功 | — |
| 18 | `当前执行环境没有绑定流程引擎，无法调用流程（「调用流程」步骤不可用）` | 执行环境没装配调用器（检查夹具/简化上下文） | 正式界面不应出现；出现说明启动链不完整，按此报修 |
| 19 | `会话准备缺少运行管理器或编译器` / `流程为空` | 宿主内部装配缺失 | 报修 |

## 超时口径（具体数值与最坏情况）

| 项目 | 数值 / 行为 |
| --- | --- |
| 默认超时 | `60000` ms（`TimeoutMs` 端口的默认手动值） |
| 生效下限 | `Math.Max(1000, 填写值)`：**填 0 / 负数 / 500 都按 1000ms**。填 0 **不等于**"不等"或"无限等" |
| 等待方式 | 20ms 一拍的轮询，同时盯取消令牌与超时；不是 `Wait(timeout)` 一次性阻塞 |
| 超时后果 | **只报错，不打断目标**：子流程继续跑到自然结束（取消令牌归引擎自己管，调用侧去掐会污染会话状态） |
| 由此产生的竞态 | 超时返回后父流程已经往下走，而子流程还在写全局变量/驱动机构 → **父子同时动**。唯一可靠处置：`TimeoutMs` > 子流程最坏耗时（含等机构、重试拍照） |
| 超时后的第二次调用 | 子流程还在跑 → 本步骤命中"正在运行中"直接失败（第 8 条），不排队 |
| `ElapsedMs` 口径 | 从开始调用到返回，**包含等待全程**。门禁早期失败也带真实耗时（通常个位数 ms） |
| 对父流程节拍的影响 | 父流程这一步的耗时 ≈ 子流程整条流程的耗时。排产时按"父子相加"算 CT，别按单步算 |

## 父子之间怎么传值（作用域细则）

**只有一条通道：全局变量。** 父流程与子流程之间**没有端口映射**，
`Invoked`/`ElapsedMs`/`Message` 是调用结果，不是业务数据。

| 方向 | 做法 |
| --- | --- |
| 父 → 子 | 父流程在本步骤**之前**用「变量赋值」把值写进**全局变量**（那一行的作用域选 `Global`）；子流程内在需要它的步骤上绑到该全局变量 |
| 子 → 父 | 子流程内部用「变量赋值」（作用域 `Global`）写；本步骤**返回之后**，父流程后续步骤绑到同一全局变量读 |

必须知道的四个坑：

1. **运行时变量与全局变量是两个东西**，同名也不算同一个。「变量赋值」的作用域必须显式选对：
   子流程写了 `Global` 的 `实测高度`，父流程却去读同名的**运行时变量** → 拿到空/旧值，反之亦然。
   （框架刻意不做"先找运行时再找全局"的自动路由——同名时自动路由就是歧义。）
2. **局部变量每轮执行新建一份**：跨流程、跨轮传值都不能靠它。
3. **并行分支里避免写全局变量**；确需写时，同一轮只允许一个分支写同一个全局变量
   （编译期有并行写冲突检查，图纸纪律见宿主）。所以"并行调同一条子流程"不是好画法。
4. **`变量名` 这类"名字"行的填法同 R33**：手填/从候选下拉选，填的是名字不是值；
   取不到时通常**静默为空**，不会报错——查不到就先怀疑名字与作用域。

## 日志长什么样（便于对着日志查）

| 来源 | 原文 |
| --- | --- |
| 本步骤成功 | `<InstanceName> 流程「X」执行完成（<ms>ms）` |
| 本步骤失败 | `<InstanceName> 调用流程「X」失败：<Message 端口同款中文原因>` |
| 本步骤没填名字 | `<InstanceName> 未指定目标流程名（请在「目标流程名」里选择或填写）` |
| 宿主调用器（成功） | `[调用流程] 流程「X」执行完成，耗时 <ms>ms` |
| 宿主调用器（有失败步骤） | `[调用流程] 流程「X」跑完但有 <N> 个步骤失败（详见运行日志）` |
| 会话重建时 | `[会话准备] 已为流程「X」重新编译并注册会话（Version=…，…）` |

`<InstanceName>` 是编译时注入的 **`流程名.步骤名`**（不是步骤名本身）。
所以日志里看到的是 `主流程.调用流程_0 …` 这种两级形式；配置面板单独试运行该步骤时可能是默认值。

## 现象 → 查哪一项

| 现象 | 先查 |
| --- | --- |
| 下拉里没有我要的流程 | 「流程管理」里那条流程的「调用方式」有没有勾「子程序」；方案是不是切错了 |
| 下拉里那条流程带着后缀 | `（已禁用）` / `（步序已加密）` / `（当前流程，不能调用自己）`——后缀就是运行期会失败的原因 |
| 一执行就红，`Message` 说没有该流程 | 流程是否刚改过名（下拉里会显示为空，值还是旧名）；大小写 / 中间空格；是不是在别的方案里 |
| 说未开放子程序调用 | 「流程管理」→ 选中那条流程 → 调用方式勾「子程序」；括号里给的就是当前值 |
| 说步序已加密 | 那条流程的步序加密状态（加密流程不能当子程序） |
| 第一次好、第二次"正在运行" | 上一轮是否**超时返回**过（目标还在后台跑）；是否有定时/变量/HTTP 也在唤起同一条 |
| 偶发"被其它执行占用" | 同一条子流程被并发调用（并行分支 / 两条父流程）。收口成一处调用，或拆成两条流程 |
| 子流程明明跑完了却 `Invoked=false` | 看 `Message` 里的失败步骤数 → 去运行日志找那条流程红了哪几步 |
| 父流程拿不到子流程算出来的值 | 作用域选错（Global/运行时混用）> 变量名大小写 > 子流程那一步其实没写成功 > 读得比写早（子流程步骤被禁用） |
| 节拍变慢/整线 CT 变大 | `ElapsedMs` 是不是接近子流程整条耗时；`TimeoutMs` 是否设得过大把问题拖成等待 |
| 超时之后机构动作"打架" | 超时不打断目标：加大超时，或在子流程末尾加互斥的全局变量条件 |
| 面板点「执行」没反应 / 直接失败 | 试运行同样会真调子流程；若报"没有绑定流程引擎"属环境未装配，正式运行不受影响 |
| 编译期 `[参数缺失] … 'FlowName' 未配置` | 该步骤的参数面板从没确认过值：打开填上流程名并确认 |

## 上线前自检

1. 每条被调流程：启用、未加密、调用方式含「子程序」，且**单独跑一遍能跑通**（编译错误会以第 10 条消息整串抛回父流程）。
2. 所有调用点在面板里**从下拉重选一遍**确认没有状态后缀；改过名的流程要重新选（存档里仍是旧名，下拉会显示为空）。
3. `TimeoutMs` 按"子流程最坏耗时 + 余量"填；不要用 0/小值表达"不等待"。
4. 传值清单落纸：哪些全局变量是入参、哪些是出参、谁写谁读、作用域一律 `Global`。
5. 并行分支里不要让多个分支调用同一条子流程，也不要让多个分支写同一个全局变量（宿主有并行写冲突检查）。
6. 带机构工位：试运行/调试时确认子流程的动作在安全状态下才点「执行」。
7. 失败处置：确认"调不通要停线"还是"用 `Invoked` 走兜底分支"，并把选定的那条写进工艺文档
   （本算子没有"失败不阻断"开关，容错要靠容器或分支表达）。
