# 调用流程

> 分类：流程控制 ｜ 来源：插件 Plugin.RunFlow

把**当前方案里的另一条流程**当子程序跑一遍：本步骤停下来等它跑完，再把"跑没跑成、跑了多久、
为什么没跑成"带回父流程。用来把换型、回原、复测、某个工位的通用检测段抽成一条独立流程多处复用，
而不是把同样的二十个步骤在每条流程里复制一遍。

产出三件事：`Invoked`（是否成功执行）、`ElapsedMs`（耗时）、`Message`（可直接展示的中文结果说明）。

## 定位：这个插件做的事很薄

父流程与子流程之间**没有端口映射**，所以本步骤只有三个动作：
读「名字 + 超时」→ 交给宿主调用器 → 把结果原样转成端口值。

**所有门禁都在宿主侧一处判定**（本插件不做二次判定，避免"两处各判一半"的口径漂移）：
存在 → 启用 → 勾了「子程序」→ 步序未加密 → 目标当前不在运行。任一不过就当场失败，子流程一步都不跑。

**"等待"是默认且唯一的模式，没有"发出后不管"**：引擎按节点顺序执行，父流程在等的时候本来就没法往下走；
真做"不等待"开关，就会出现"子流程还在往回收数据里写、父流程已经往下跑"的竞态。
要并行请用两条独立流程各自的调用方式（定时 / 变量 / HTTP外部调用），而不是一个不等待的调用开关。

**能力怎么送到插件手里**：插件物理上够不到宿主引擎，调用能力由执行上下文递送
（`IExecutionContext.FlowInvoker`，与全局变量写入口、相机仓库同一范式）。
没装配时拿到的是"调用即失败并说明原因"的空实现，所以插件不必判空——
现场表现为 `Message` 直接告诉你"当前执行环境没有绑定流程引擎"。

## 快速上手（6 步跑通第一次）

① 「流程管理」里新建（或选中）要当子程序的那条流程，例如 `回原`；
② 在该流程的**调用方式**里勾上「子程序」（这是一位多选位集，勾"定时"或"HTTP外部调用"都不放行）；
③ 确认那条流程**启用**、**步序未加密**，并且**单独跑一遍能跑通**（它的编译错误会整串抛回父流程）；
④ 回父流程，工具箱「流程控制」里拖入「调用流程」，双击打开参数面板；
⑤ 「目标流程名」从**下拉**里选 `回原`（候选只列勾了「子程序」的流程；下拉里没有它，说明第 ② 步还没勾），
   「等待超时(ms)」按子流程最坏耗时 + 余量填（默认 `60000`）；
⑥ 点「确定」保存，跑父流程；看 `Invoked` / `ElapsedMs` / `Message` 三个输出确认结果。

> 带机构的工位：配置面板的「执行」（试运行）会**真的把子流程跑一遍**（运动、写文件、上报都执行），
> 请先脱机或置维修状态，或临时把子流程换成一条只读的空流程。

## 跑通之后该看到什么

- 步骤 `Success` = `true`、`Invoked` = `true`、`Message` = `流程「回原」执行完成`；
- `ElapsedMs` ≈ 子流程整条流程的耗时（包含等待全程）；
- 运行日志两行：本步骤一行 `<实例名> 流程「回原」执行完成（<ms>ms）`，宿主调用器一行 `[调用流程] …`。

## 典型接线

```
① 固定名字的复用段（回原、换型清理）
   调用流程.FlowName  = 下拉选 回原      调用流程.TimeoutMs = 手填 30000

② 按配方 / 工单决定跑哪条（用分支，不用动态名字）
   分支匹配(判据=配方名) ─┬─ 回原    ──▶ 调用流程(选 回原)
                          ├─ 换型清理 ──▶ 调用流程(选 换型清理)
                          └─ 默认     ──▶ 结果显示(配方未配置)
   配方参数.超时 ──▶ 调用流程.TimeoutMs（超时仍可由上游给）
   调用流程.Invoked ──▶ 分支判定.条件      调用流程.Message ──▶ 结果显示

③ 传参进去 / 结果拿回来（唯一通道：全局变量）
   变量赋值(写全局 目标高度) ──▶ 调用流程(测高子流程) ──▶ 后续步骤读全局 实测高度
        └── 父流程先写                       └── 子流程内写

④ 调不通也要继续（显式兜底，本算子没有"失败不阻断"开关）
   调用流程.Invoked ──▶ If(为假) ──▶ 结果显示 / 结果上报
```

> **流程名不能由上游给**：它是"名字"不是"值"，配置界面是封闭下拉、没有链接按钮（R33）。
> 要按配方选流程，就用 ② 的分支画法 —— 每条分支编译期可见，走哪条在日志里也一目了然。
> 老工程里升级前已经连了上游的步骤：连线仍生效，打开面板选一项即拆线改成固定值。

**位置原则**：放在需要它的那一刻**之前**（换型后先调「回原」再继续检测）。
子流程里不要再放"调用流程"回指父流程——会被"正在运行"拦下，但那属于误配，别靠门禁当保护。

## 三条必须先记住的口径

- **传值只有全局变量一条路**：父流程调用前写、子流程内读；子流程内写、本步骤返回后父流程读。
  运行时变量与全局变量是两个东西，同名也不算同一个；局部变量每轮执行新建一份，跨流程不能靠它。
- **超时只报错、不打断目标**：超时返回后子流程**还在后台继续跑**（仍会写全局变量、驱动机构、拍照），
  父流程这时已经往下走了。唯一可靠处置是把 `TimeoutMs` 设到子流程最坏耗时之上。
- **"跑完但有 N 个步骤失败"算失败**：`Invoked=false`、`Message` 给出失败步骤数；
  具体哪几步红了要到运行日志里看那条流程自己的记录。
