# 调用流程

> 分类：流程控制 ｜ 来源：插件 Plugin.RunFlow

把**当前方案里的另一条流程**当子程序跑一遍：本步骤停下来等它跑完，再把"跑没跑成、跑了多久、
为什么没跑成"带回父流程。用来把换型、回原、复测、某个工位的通用检测段抽成一条独立流程，
多处复用，而不是把同样的二十个步骤在每条流程里复制一遍。

产出三个东西：`Invoked`（是否成功执行）、`ElapsedMs`（耗时）、`Message`（可直接展示的中文结果说明）。

## 为什么需要它 / 原理

父流程和子流程之间**没有端口映射**，所以这个插件做的事很薄：把"名字 + 超时"交给宿主引擎，等结果。

```
父流程.调用流程
   │ ① 读 FlowName（Trim 后判空）、TimeoutMs
   ▼
② 门禁（全部在宿主侧一处判定，本插件不做二次判定）
   存在 → 启用 → 勾了「子程序」→ 未加密 → 目标不在运行
   ▼
③ 会话准备：查会话；图纸改过/换过方案 → 重新编译并注册
   ▼
④ 单次执行（非调试）：开跑前把步骤状态整树复位，抢不到会话锁就如实报失败
   ▼
⑤ 等待（轮询，20ms 一拍）：同时盯「父流程被取消」与「超时」两件事
   ▼
⑥ 回收：失败步骤数 > 0 → 失败；否则成功。带真实耗时
   ▼
父流程.调用流程.Invoked / ElapsedMs / Message
```

**"等待"是唯一模式，没有"发出后不管"**：引擎按节点顺序执行，父流程在等的时候本来就没法往下走；
真做"不等待"开关，就会出现"子流程还在往回收数据里写、父流程已经往下跑"的竞态。
要并行请用两条独立流程各自的调用方式（定时 / 变量 / HTTP外部调用），而不是一个不等待的调用。

**能力怎么送到插件手里**：插件物理上够不到宿主引擎，调用能力由执行上下文递送
（`IExecutionContext.FlowInvoker`，与全局变量写入口、相机仓库同一范式）。
没装配时拿到的是"调用即失败并说明原因"的空实现，所以插件不必判空——
现场表现为 `Message` 直接告诉你"当前执行环境没有绑定流程引擎"。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `FlowName` | **是** | 目标流程名（文本）。面板标签显示为「目标流程名」。会先 `Trim()` 再判空；**按名精确查找**（区分大小写，见"口径"节） |
| `TimeoutMs` | **是**（自带默认值 `60000`） | 等待超时（毫秒）。面板标签显示为「等待超时(ms)」。**生效下限 1000ms**：填 0 或负数不是"不等"，而是"等 1 秒" |

两个端口都声明为必填（`IsRequired` 默认为 `true`，本插件没关）：**只要打开参数面板点过一次「确定」**，
两行的值（空串 / 60000）就会被写进步骤常量，编译期不再报 `[参数缺失]`；
从没确认过面板的步骤，编译期会对未配置的必填端口报 `[参数缺失] '<步骤名>' 的必填参数 'FlowName' 未配置！`。
`FlowName` 一旦为空，运行期由本步骤直接判失败。

两个端口都可以**手填常量**，也可以**连上游输出**（流程名来自码读/变量、超时来自配方，都可行）。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Invoked` | 子流程**整体**是否成功。注意：跑完了但有 N 个步骤失败 → 这里也是 `false` |
| `ElapsedMs` | 从开始调用到返回的耗时（毫秒），包含等待全程。门禁早期失败也带真实耗时（通常为个位数） |
| `Message` | 调用结果说明。成功是 `流程「X」执行完成`；失败是**可直接展示给操作工的中文原因**（见 `02-字段与排错`） |
| `Success` / `ErrorMessage` | 基类契约。本步骤**照实**把 `Invoked` 的结果写进 `Success`——调用失败就是步骤失败，**没有"不阻断"开关** |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

本插件**没有模块级参数**（不写 `[StepConfig]`），参数面全部由输入端口表达；
没有自定义界面，宿主用通用参数清单渲染这两行（每行 = 标签 + 值 + 链接 + 清除）。

| 参数（=端口） | 默认 | 说明 |
| --- | --- | --- |
| 目标流程名 `FlowName` | 空 | 要当子程序跑的流程名。**必填**，空/纯空格即失败 |
| 等待超时 `TimeoutMs` | `60000` | 父流程愿意等多久（毫秒）。下限 `1000`；**超时只报错，不打断目标**——子流程仍在后台继续跑 |

真正"配置另一半"在**被调用流程的属性**上：「流程管理 / 属性面板」里那条流程的**调用方式**
必须勾上「子程序」。没勾 = 你把它当私有块，不允许被别的流程顺手拖起来。

## 口径与失败策略

- **流程名怎么匹配**：`Ordinal` 精确比较（区分大小写、不折叠空格），名字两端会 `Trim`。
  和 HTTP 路由、运行状态镜像同一个口径——不会出现"面板里找到了流程、引擎找不到会话"这种自己跟自己打架。
- **门禁五连，顺序固定**：存在 → 启用 → 勾了「子程序」→ 步序未加密 → 目标当前不在运行。
  任一不过就**当场失败**，子流程一步都不会跑，`ElapsedMs` 就是判定的耗时。
- **"目标正在运行"直接失败，不排队、不补跑**：排队会把"A 等 B、B 又在等 A"这种成环误配变成挂死现场。
  **自己调自己**也被这一条拦住；**A 调 B、B 又调 A** 同样在第二次进入 A 时失败（此时 A 正在运行）。
- **抢不到会话锁不假装成功**：并发调用同一子流程时，后到的那一单如实报失败
  （历史上这里会只记一条警告就正常返回，父流程会把"我没跑上"读成"跑完了"，带着未落地的数据继续走）。
- **超时不打断目标**：取消令牌归引擎自己管，调用侧去掐它会污染会话状态。
  所以超时返回后，**子流程还在后台继续跑**：它仍会写全局变量、驱动机构、拍照。
  父流程这时已经往下走了——这是本算子最需要警惕的一条，处置办法是把超时设到子流程最坏耗时之上。
- **急停/停止**：父流程被取消时本步骤立刻失败并说明"目标仍在后台收尾"，不会把子流程一起掐掉。
- **"跑完但有 N 个步骤失败"算失败**：`Invoked=false`，`Message` 给出失败步骤数。
  数的是**这一次**的失败（单次执行开跑前整树复位过状态，不会吃上一轮连续运行的历史状态）。
- **子步骤失败如何影响子流程本身**：由子流程自己的失败处置口径决定（它照常往下走或中止），
  本插件不干预，只负责如实报告最终结果。
- **参数与结果怎么在父子之间传**：**只能经全局变量**（见"典型用法"）。
  父流程 → 子流程：调用前由父流程的某个步骤（如变量赋值/脚本）写全局变量，子流程内部读它；
  子流程 → 父流程：子流程内部写全局变量，本步骤返回后父流程的后续步骤读它。
  除此之外**没有任何通道**——不存在"子流程的输出端口映射到父流程"这种用法。
- **副作用是真的**：`Message` 成功不代表只是"检查通过了"，子流程里的运动、IO 输出、上报都真实发生过。
  配置面板的「执行」（试运行）会**真的把子流程跑一遍**，带机构的工位请先脱机/置维修。
- **本步骤失败 = 步骤失败**：不设"容错开关"。需要"调不通也继续走"，请把本步骤放进 `If` 容器或
  用 `Invoked` 端口做分支判断，而不是让插件偷偷吞掉失败。

## 典型用法 / 接线

```
① 最常用：固定名字的复用段（回原、换型清理）
   流程管理里把「回原」的调用方式勾上「子程序」
   调用流程.FlowName   = 手填  回原
   调用流程.TimeoutMs  = 手填  30000
   上游.判定结果 ──▶（可选）If 容器，容器内放本步骤

② 名字由上游给（配方/工单决定跑哪条）
   码读取.Text ──▶ 调用流程.FlowName        （文本：值必须正好是流程名）
   配方参数.超时 ──▶ 调用流程.TimeoutMs
   调用流程.Invoked ──▶ 分支判定.条件        调用流程.Message ──▶ 结果显示

③ 传参进去 / 结果拿回来（唯一通道：全局变量）
   变量赋值(写全局 目标高度=12.5) ──▶ 调用流程(测高子流程) ──▶ 变量赋值(读全局 实测高度)
                     └── 子流程内读「目标高度」                     └── 子流程内写「实测高度」

④ 调不通就停线（默认行为，无需额外配置）
   调用流程.Success=false ──▶ 本步骤失败，日志给出中文原因

⑤ 调不通也要继续（显式兜底）
   调用流程.Invoked ──▶ If(为假) ──▶ 结果显示 / 结果上报（提示操作员手工确认）
```

**位置原则**：放在需要它的那一刻**之前**（比如换型后先调「回原」再继续检测）。
子流程不要放"调用流程"回指父流程——会被"正在运行"拦下，但那属于误配，别靠门禁当保护。

## 常见问题

**Q：明明流程就在方案里，为什么报"没有名为「X」的流程"？**
按这个顺序查：① 大小写（`Ordinal` 精确匹配，`MainTask` 与 `maintask` 是两个名字）；
② 名字里的空格（两端会 Trim，**中间**的空格是名字的一部分）；③ 是不是在**另一个方案**里
（查找范围只有当前方案的流程）；④ 端口连的是不是别的字符串（比如带前缀的条码）。

**Q：报"未开放「子程序调用」"——我已经在流程上勾过东西了。**
勾的是**哪一位**：`Message` 会把当前调用方式打出来（如"当前调用方式：定时 / HTTP外部调用"）。
必须是「子程序」这一位，其它位（定时/变量/HTTP外部调用）都不放行。
去「流程管理」选中那条流程，在调用方式里勾上「子程序」再保存。

**Q：第一次能调、第二次报"正在运行中，本次子程序调用未执行"。**
说明上一次的子流程**还没跑完**。两种成因：
① 上一次**超时**了——超时不打断目标，它还在后台跑，父流程这一轮再来就撞上；
② 有另一条流程（或定时/变量/HTTP 触发）也在跑同一条。
处置：把 `TimeoutMs` 调到子流程最坏耗时之上；给子流程加互斥的全局变量判定；或把触发收口到一处。

**Q：子流程里有一步失败，父流程这边看到什么？**
`Invoked=false`、`Success=false`、`Message=流程「X」跑完但有 1 个步骤失败（详见运行日志）`。
具体是哪一步、为什么失败，要到**运行日志**里看那条流程自己的记录（本步骤不逐个列出来）。

**Q：怎么把数据传进子流程 / 把结果拿回来？**
只有全局变量一条路：父流程调用前写、子流程内读；子流程内写、本步骤返回后父流程读。
**不要指望端口**——父流程的端口和子流程的端口之间没有映射关系。
另注意"读的是哪一份"：流程内的局部变量每轮执行新建，跨流程传值必须用**全局变量**。

**Q：超时设多少合适？**
先量出来：跑一遍子流程，看 `ElapsedMs`（或那条流程自己的耗时记录），
按最坏工件（含等待机构、重试拍照的时间）乘一个余量填。
填小了不会让子流程停，只会让父流程"提前以为它跑完了"继续走——比卡住更危险。

**Q：`TimeoutMs` 填 0 是不是表示不等待？**
不是。生效值有下限 `1000` 毫秒，填 0 / 负数都按 1 秒等。要"发出后不管"请用定时/变量/HTTP 触发，
本算子刻意不做这个分支。

**Q：配置面板点「执行」验证会不会有副作用？**
会。试运行同样注入真调用器，会**真的把子流程完整跑一遍**（运动、写文件、上报都执行）。
带机构的工位请在脱机/维修状态下验证，或者先临时把子流程换成一条只读的空流程。

**Q：能不能让子流程调用父流程，形成循环？**
不能，也不该。第二次进入"正在运行"的那条流程时会被直接拦下（`正在运行中`/`被其它执行占用`），
这是**成环保护**，不是 bug。真需要重复执行，请用 `While` 容器在一条流程里循环，
或用定时调用方式让那条流程自己周期跑。

**Q：报"当前执行环境没有绑定流程引擎，无法调用流程（「调用流程」步骤不可用）"。**
说明这一步跑在没有流程引擎的执行环境里（检查夹具/容器简化构造那类）。
在正式界面里跑正常流程不会看到这句；看到就是启动链没装配完整，按这条消息报修。
