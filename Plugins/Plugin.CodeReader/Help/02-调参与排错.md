# 码读取 · 调参与排错

这一页讲**现场怎么把码读稳**：先选对码制，再按"分辨率 → 光照 → 静区 → 清晰度 → 超时"这条链排查读不出的原因，
最后说清多码同框与中文乱码这两件常年踩的事。
本插件刻意只开放三个参数（码制 / 搜索超时 / 极性，极性仅二维码），**其余 HALCON 旋钮都要靠上游图像来解决**——所以下游调不动时，改动基本都发生在 ROI 与预处理里。

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

## 一、码制怎么选（符号体系 → 适用场景）

| 码制 | 符号体系 | 典型场景 | 现场要点 |
| --- | --- | --- | --- |
| Data Matrix ECC 200 | 方形点阵，两条实心"L"边 + 两条虚线时钟边 | **金属件激光 DPM、元件本体追溯**（本插件默认） | 尺寸能做得极小；模块数少（码版本低）时对分辨率要求最高。方向靠 L 边判定，**90° 整数倍旋转不影响识别** |
| QR Code | 方形点阵，三角位置探测图形 + 定时图案 | 消费端扫码（手机扫码看说明书/报修）、铭牌 | 容量大、有纠错；三角探测图形对**模糊和残缺**比 Data Matrix 更宽容，但占面积也大得多 |
| Micro QR Code | QR 的缩小版（1~2 个探测角） | 极小零件、容量需求很低 | 探测角少 → 定位能力弱，光照与分辨率要求比 QR 高，能用 QR 就别用 Micro QR |
| PDF417 | 行排式（多行一维条堆叠） | 证件、托盘标签、要写大段文本 | 高度方向行数多，**裁图别把上下行切掉**；行高与最窄单元宽的比通常约 3:1，打码或成像把行压扁就读不出来 |
| Aztec Code | 以中心"定位靶"向外扩展的同心方块 | 票据、瓶盖/圆管等边缘受限处 | **规范上不要求外围静区**，所以印在边上也能读；反过来"没白边读不出"时先怀疑它被选成了别的码制 |
| DotCode | 点阵，无固定起始位置、单行高度 | 饮料/医药高速线逐件打码 | 为高速打印设计，常见于**传送带上的短曝光抓拍** |
| Code 128 | 变长高密度一维条，含起始/停止符与校验符 | **工业零部件标签的主力** | 全字符集；优先选它而不是 `auto` |
| Code 39 | 宽窄型条空（每字符 5 条 4 空，其中 3 个宽单元），字符集窄：数字 / 大写字母 / `- . 空格 $ / + %` | 老系统、内部料号 | 密度低、条宽，读起来容易；**内容首尾可能带起止符 `*`**（见第四节） |
| Code 93 | 条空型，密度比 Code 39 高，靠两个校验符查错，字符集可用移位扩到全 ASCII | 内部标识、字母数字条码化 | 用得少；与 39 混淆时按内容长度与校验结果判，读不出就两个码制各试一次 |
| GS1-128 | Code 128 的 GS1 数据规范版（带应用标识符 AI） | 物流外箱、批次/效期/序列号组合 | **模型与 Code 128 同族**，但内容是 `01…10…` 这类 AI 串；本插件不解 AI，拆解在下游做 |
| EAN-13 / EAN-8 | 定长纯数字、有校验位，条空模式带两侧护栏条 | 零售商品包装 | **校验位是唯一能人工验算的独立真值**（权重交替 3/1 加权和取模），可用来确认"读对没读对" |
| UPC-A / UPC-E | EAN 的北美子集（UPC-E 为零压缩版） | 北美零售包装 | 选错 EAN/UPC 时读不出，靠码位数与首字判断 |
| 2/5 Interleaved（交插二五码） | 条与空都载信息，**必须偶数位纯数字** | 仓储、瓦楞箱、内部周转 | 位数是奇数就打不出合法码；读到奇数位串说明读糊了 |
| Codabar | 定宽、四个字符作起止符 | 血库、图书馆、内部周转 | 起止符会出现在内容首尾，同 Code 39 处理 |
| Code 32（意大利医药码） | Codabar 变体，固定 9 位、首字 A | 意大利制药追溯 | 极少见；只在明确供应链里用 |
| MSI | 纯数字一维，自检位可选 | 库存/仓储内部标签 | 非公开标准化，各家打码规则不同，内容与打码端逐字对 |
| PharmaCode | 由不同宽度竖条组成的码，专为高速喷码 | 药品小盒 | 打印常见断续，读不出时优先查清晰度而不是码制 |
| 一维·自动识别码制（较慢） | 逐个码制试 | **仅调试用** | 节拍明显更慢，码制混杂时可能给出意外匹配。产线请选具体码制 |

## 二、第一次配读码（五步）

1. **先确定码制**：拿一张实际工件图，按上表对号；分不清就把码制逐一在配置界面点「试算一下」——试算与正式运行是同一条读码路径，看到的就是跑起来的。
2. **上游裁图并留余量**：用「ROI（创建ROI）」的 `Crop_ROI名` 输出，**裁剪框 = 码的外接矩形向外扩 5~10 像素**（经验值）。
   传入图带 `reduce_domain` 时搜索范围缩到该域，**码没完全落在域内就可能找不到**——贴边裁是"图上有码却 `Count = 0`"的第一号原因。
3. **连图**：配置窗口左栏「图像输入」卡片里链接上游（或画布上把上级输出连到 `Image` 端口）。
4. **设超时**：默认 `500` ms。它是"没找到时的止损线"，不是"提高命中率"的旋钮——图里真有好码时，几十毫秒就出来了。
5. **（仅二维码）定极性**：默认「自动（两种都试）」。金属 DPM 常是亮码暗底，让 HALCON 两种都试更稳；确定极性后明确指定能省一截节拍。

## 三、读不出来：按这条链往下走

**别一上来就调超时。** 现场命中率几乎全部由"图够不够清楚"决定，所以按顺序判：

| 顺序 | 查什么 | 判据与处理 |
| --- | --- | --- |
| 1 码制 | 日志里那行"本帧未读到码（当前码制 …）"对不对 | 标签纸上的黑条 ≠ Data Matrix；把码制改成实际那一种。这是最高频原因，**日志已把当前码制写出来**就是为了让你一眼自查 |
| 2 裁剪 | 上级图是否把码**完整包住**并留余量 | 半截码 / 切掉 PDF417 上下行 / 切掉 EAN 两侧护栏条 → 都会读不出。回 ROI 把框放大 |
| 3 分辨率（模块尺寸） | 最窄单元（一维的最细条、二维的单个模块）宽够不够 **2~3 像素**（经验：按 3~4 像素起配） | 估算：`需要的像素当量 ≤ 模块尺寸(mm) ÷ 想要的每模块像素数`。例：模块 0.25 mm、要 4 像素/模块 → 当量需 ≤ 0.06 mm/px。不够就**缩短工作距离 / 加远心镜头 / 上游「按比例缩放」放大** |
| 4 光照与反色 | 过曝（模块连成一片）、镜面反光、阴影斜射 | 金属刻印码换**低角度环形光或同轴光**；反光标签换漫射光。**整片亮暗反了**：二维码改「极性」；一维没有极性旋钮（实测不接受该参数），必须在**上游「图像预处理 → 反色」**解决 |
| 5 静区 quiet zone | 码四周的空白带够不够 | 一维按规范留 **≥10 倍最窄单元宽**的左右白边；Data Matrix 规范只要求 1 模块宽的浅色边（现场按 ≥2 模块更稳）。标签贴到边、码印在拐角、背景是深色 → 都会栽在这条。**Aztec 不要求静区**，别用它的经验去判别的码制 |
| 6 清晰度 | 运动模糊、失焦、镜头畸变 | 模糊：缩短曝光（先提光量/增益）或提高线扫行频，与运动速度匹配。失焦：**工作距离**跑出厂景深（远心镜头看铭牌深度差异尤其明显）。畸变：广角镜头下画面四角的码被拉歪 → 让码落在视野中心区，或先做标定/换镜头 |
| 7 超时 | 上面的都对、只是"勉强能读" | 调大超时只影响"愿意花多久试"。节拍够就给到 1000~2000 试探，若确认能读出来再决定是保留还是回去改善图像 |
| 8 码本身坏了 | 脏污、打码过浅、边缘崩缺 | 二维码有纠错余量，但损伤超过纠错能力就**无解**，只能重打码。此判据靠"同一工位别的件能读、这件读不出 + 日志有候选数提示"得出 |

**关键提示行**：日志出现 `二维候选 N 个（句柄 M 个），其中成功解出 K 个` 时，说明**码找到了、内容解不出来**——这是码脏/对比度低/局部损伤的典型指纹，直接去查上表的第 4、6、8 条，不要再折腾码制与超时。

## 四、多码同框与内容取用

- 一帧里所有解出的码都进 `Codes`（只收**解出内容**的，空文本候选被丢弃），`Count` 是它的个数，`Text` 是逗号拼接。
- **多码顺序由 HALCON 决定，不保证稳定**：不要按"第一个是序列号、第二个是批次"这种约定来用。要稳定归属，就**一码一路**——上游 ROI 给每个码各裁一个区域、各接一个码读取步骤。
- **一次运行只按一种码制找**（一个二维模型只绑一种码制，一维的 `auto` 只是逐个试）。同框既有条码又有二维码时，用两个码读取步骤并联，各自接各自的裁剪图。
- **内容里的起止符**：Code 39、Codabar 这类码的起止符可能随内容一起返回（例如首尾多出 `*` 或字母起止符）。本插件**原样透传**，不裁起止符、不校验字符集——统一在下游「C#脚本」里修剪，别在多个下游各剪一遍。
- **GS1 串（GS1-128 / GS1 DataMatrix）**：本插件不解应用标识符（AI），给的是整串原文；拆解（`01` 物料号 / `10` 批次 / `21` 序列号）请在下游做，且**校验位规则也在那边验**。
- **画布上想取"第一个码"**：数组下标写法未必给得出，用 `Text`（`Count = 1` 时它就是那一个码）。

## 五、中文内容与乱码（常年问题）

先立一条口径：**本插件把 HALCON 解出的字符串原样吐出，不做任何编码转换，也不做任何修剪。**
所以乱码的原因只可能在下面三处之一，按顺序查：

| 现象 | 查哪 | 处理 |
| --- | --- | --- |
| 读到的是 `??`、方块、或与打码内容长度都对不上的怪字符 | **打码端写入的字节编码**：GBK/GB18030 写的中文，读取端按单字节解，就必然错位 | **首选把打码端统一改成 UTF-8**（一劳永逸，跨品牌读码器都认）；改不了打码端，就在下游用 `Encoding` 按原编码把字节重新解一次（注意：.NET 里 GB2312/GBK 需先注册 `CodePagesEncodingProvider` 才拿得到该编码） |
| 同样的码，本软件读出来和手持枪读出来不一样 | **码内的编码声明**：QR 有 ECI/数据模式（汉字模式），Data Matrix 只有字节 | 这不是视觉问题。先确认打码时用了什么模式，再看手持枪的编码设置——两边都要按同一编码解释 |
| 日志/CSV 里正常，界面显示乱码（或反过来） | **显示与落盘的编码**：解码结果已经是对的，下游写文件/上报时换了编码 | 落盘用 UTF-8；要发给只认 GBK 的旧 MES，就在上报侧显式转换，不要指望算子帮你转 |

另外两条与编码无关但常被当成乱码的情况：

- **读到空串/短串**：内容真的为空或被截半（码破损）——看有没有"候选 N 个、解出 K 个"的告警行。
- **首尾多了看不见的空白/控制字符**：打码端把控制字符写进了码。`Text` 是逗号拼接，多余字符会让下游比对始终不相等——比对前先归一化（`Trim`），并把它当作**打码规范问题**上报，而不是在读码端补偿。

## 六、ROI 与预处理怎么配（本插件没有增强参数的替代方案）

可用的上游算子（「图像预处理」的算子名照界面）与对应症状：

| 症状 | 加哪个算子 | 要点 |
| --- | --- | --- |
| 模块/条太细，像素不够 | **按比例缩放** 或 **修改图像尺寸** | 放大后模块边缘仍偏硬时，接一个**中值滤波**（模板尺寸 3）把插值锯齿磨掉 |
| 对比度低（DPM 浅刻、热影响区淡） | **对比度** / **直方图均衡** | 先均衡再看极性；均衡过头会把背景噪声拉起来 |
| 亮暗整体反了（亮底黑码 ↔ 暗底亮码） | **反色** | **一维唯一的解法**（一维没有极性参数）；二维码优先用极性、别用反色绕 |
| 边缘发虚、印糊的一维条 | **锐化** | 锐化过头会起毛刺，配合**中值滤波**收边 |
| 噪点、麻点、划痕搭在码上 | **中值滤波** | 模板尺寸从 3 起加；超过 5 会把细条切掉，一维尤其敏感 |
| 背景花、码区之外全是干扰 | **固定框裁剪** / **框外屏蔽**，或 ROI 的裁剪输出 | 干扰区留在框外比在框内"洗掉"更省时间，也少一类误判 |
| 打光不匀（一头亮一头暗） | **均值二值化**（局部阈值） | 慎用全局**二值化**：阈值失手会把整段细条一起切没，比不处理更糟 |
| 来图是彩色图、步骤报找码阶段的类型错误 | 上游加「彩色空间转换」（取一个通道） | 本插件把手上的图**原样**交给 HALCON 的找码算子，自己不做通道转换；找码按单通道灰度图设计，彩色图请先在预处理里转灰度 |

**顺序经验**：先解决"码完整且够大"（裁剪 + 缩放），再解决"看得清"（对比度/锐化/中值），最后才考虑二值化。二值化放在最前会一次性毁掉后面所有补救余地。

## 七、按现象查参数（速查）

| 现象 | 调哪里 |
| --- | --- |
| 读不到码 | ① 码制对不对（看日志里的当前码制）② 上级是否把码完整包住 ③ 分辨率够不够 ④ 超时太短 |
| 读得慢 | ① 别用 `auto`，选具体码制 ② 二维已知极性就明确指定（别用 `any`）③ 超时给小一点 |
| 亮码暗底 / 暗码亮底 | 仅二维码：设极性的两项之一；一维走上游反色 |
| 一帧多个码 | 取 `Codes` 数组或 `Text` 逗号串；顺序不可预期，要定序就一码一路 |
| 想把码内容存变量/参与比较 | 用 `Text`（标量） |
| 拖慢整条流程 | 调小超时；别用 `auto`；二维明确指定极性；上级先把 ROI 裁小 |
| 步骤失败"上游没有图像" | 上级没连图，或上级本轮失败（失败步骤的输出端口通常是空的） |
| 步骤失败"不在支持的码制表里" | 码制名被手改坏了。**不会静默退回默认码制**，错误信息里会把可选值逐个列出来 |

## 八、上线前检查清单

- [ ] 用**已知内容的实物样件**各码制至少跑 20 帧，确认 `Text` 逐字一致（不是"能读出来就行"）；
- [ ] 零售/EAN 类码用**校验位规则**独立验算一次，防止"稳定读错"；
- [ ] `Count = 0` 的分支在流程里有明确去向（放行 / 报警 / 重拍），别让"没码"静默变成 OK；
- [ ] 超时值是按**节拍**定的，不是按"能不能读出来"定的；
- [ ] 上游裁剪框留了余量（不是贴边裁）；
- [ ] 中文内容已确认打码端编码，且下游比对做过归一化；
- [ ] 需要逐码归属的场合改成了"一码一路"，没有依赖多码返回顺序。
