# 码读取 · 界面、端口与参数

> 分类：图像处理 ｜ 来源：插件 Plugin.CodeReader

## 配置界面长什么样

打开步骤（双击或右键「模块参数」）后是左右两栏（窗口约 900×560）：

| 位置 | 卡片 | 里面有什么 |
| --- | --- | --- |
| 左 1 | **图像输入** | 一行「输入图像」编辑器：值输入框 + 🔗（链接上游端口或变量）+ ✕（清除连线）。**在这里就能连上游，不用回画布拖线** |
| 左 2 | **码制** | 下拉（显示中文/通用名）+ 一行当前码制说明（随码制变化，见下） |
| 左 3 | **二维码参数** | 「极性」下拉。**这一整块只在选了二维码时才出现**；一维码制下它是隐藏的 |
| 左 4 | **通用参数** | 「搜索超时(ms，0 = 不限)」文本框 + 一句说明（没有码时引擎会在候选区域反复尝试，没有止损线会拖住整条流程） |
| 左 5 | **试算** | 「试算一下」按钮 + 一行提示 + 一块等宽字体的结果区 + 一句"上级传进来的图要把码完整包住、留点余量"的提醒 |
| 右 | 图像显示 | **只读**图像控件：只能看，不能画、不能框选 |

**为什么右侧故意不给画图控件**：本节点按设计不做定位，没有"识别区"这个概念，
给个能画框的编辑器只会让人以为能在这里框码——要框码的位置就去上游加「ROI（创建ROI）」。

### 界面上的两句提示原文

码制卡片下面那行说明跟着码制走：

- 二维码：`二维码：可调极性。一个模型只能是一种码制，切码制会重建模型。`
- 一维码：`一维码：无极性参数（一维读码本身对极性鲁棒）。选具体码制比用「自动」快得多。`
- 存盘值被手改坏、表里查不到时：`码制「X」不在支持的码制表里，请重新选择`

试算区第一行提示刚打开时是：
`先在「图像输入」里点 🔗 手动绑定图像来源（选上游端口或变量），然后点「试算一下」看这张图能不能读出码`；
上游图进来后变成：`已显示上游图像（点「执行」试运行带进来的）：可直接点「试算一下」看读码结果`。

结果区平时写 `尚未试算`，试算后是四段：`码制：X` / `读到 N 个码` / 逐行列出的码内容（没读到写 `（未读到码）`）/
（有候选数差异时补一行诊断）。
**若右侧还是空白（没有图）就点试算**，会得到提示 `先在「图像输入」绑定上游图像，或点宿主「执行」带图进来再试算；本节点没有「载入」按钮，图像只来自上游`——
界面上**没有**「载入」按钮，图只有一个来源：上面的「图像输入」端口（点 🔗 绑上游，或点「执行」试运行带进来）。
看到这句就按这条走，别去找不存在的按钮。

## 输入端口

| 端口 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `Image` | `HImage` | 编译期不强制（`IsRequired = false`），**运行期必须有图** | 待读码的图像，应由上级**定位后裁好**并把码完整包住；建议单通道灰度图（彩色请先在上游转灰度）。空图/未初始化 → 本步骤失败，原因写"上游没有图像" |

编译期不强制是为了让"先摆好节点、后接上游"的方案能编译通过；运行期没图仍然明确失败，不会静默跳过。

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Codes` | `string[]` | 这一帧里所有**成功解出内容**的码文本（一帧可能有多个，实测 Code 39 样张就是两个） |
| `Count` | `int` | 码的个数。**下游判"有没有码"用它**（0 = 本帧没有码，属正常工况） |
| `Text` | `string` | 所有码文本的逗号分隔形式，给按标量工作的既有下游（比较 / 存变量 / CSV记录 / 结果上报）用 |
| `SymbolContours` | `HXLD` | 识别到的码轮廓。接「结果显示」的 `OverlayContours`，由图像窗口统一画框；插件自己不烧图 |
| `Codes` | `string[]` | 逐码内容；接「结果显示」的 `OverlayLabels` 可逐框标出内容（顺序与 `SymbolContours` 对应） |
| `Success` / `ErrorMessage` | `bool` / `string` | 基类隐式端口：本步骤执行状态与失败原因 |

**位置怎么给**：没有单独的 `Row/Column` 端口，但 `SymbolContours` 已经给出码轮廓，
接「结果显示」的 `OverlayContours` 就能在图像窗口看到框；要拿数值位置请用上游定位节点或 HALCON 脚本。
逐码的码制、质量等级/置信度仍不输出。

`Codes` 与 `Text` 的取舍：下游是**标量**口径就用 `Text`——画布上数组端口只能整体连，
`Codes[0]` 这种下标写法未必给得出；要逐个处理多个码才取 `Codes`（配合 `Count` 判空）。

## 三个参数（就这么多）

| 参数 | 默认 | 存盘值 | 说明 |
| --- | --- | --- | --- |
| 码制 `Symbology` | `Data Matrix ECC 200` | HALCON 原始名（如 `Data Matrix ECC 200` / `Code 128` / `auto`） | 一帧只按**一种**码制找。界面显示中文/通用名，**流程里存的是原始名**（稳定身份，改中文标签不会让存量图纸失效）。表里没有的名字报明确错误，**不静默退回默认码制**（静默退回的表现只是"读不到码"，无从排查） |
| 搜索超时 `TimeoutMs` | `500` | 整数毫秒 | `0` = 不限。默认给值是因为**图里没有码时引擎会在候选区域反复尝试**，没有止损线会拖住整条流程。调大只影响"找不到时肯花多久试" |
| 极性 `Polarity` | 自动（两种都试） | `any` / `dark_on_light` / `light_on_dark` | **仅二维码有效**（一维模型不接受这个参数）。激光 DPM 打码在金属上常是亮码暗底或低对比，两种都试更稳；已知极性时明确指定可提速 |

码制与极性的下拉都是"显示中文、存盘原始值"这一套做法。20 条码制的完整清单与符号体系在「码制清单」页。

## 改了参数好像没生效？

先确认改的是**运行实例**还是配置界面（改完要保存并重新编译流程），再确认加载的是最新插件 DLL。
本插件的机制本身不会"吞参数"：参数在**每次查找前都会重设一遍**，
二维只在码制变化时才重建模型句柄（码制没变就复用），所以"参数动了结果不变"这条链在插件里是堵掉的。
