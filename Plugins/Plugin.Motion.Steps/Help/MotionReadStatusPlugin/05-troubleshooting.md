# 读轴状态：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面上真会出现的原文**（从源码逐字抄），按"现象 → 为什么 → 怎么改"排。
本步骤的失败出口一共四类：轴名解析、卡服务、快照读不到、`FailOnAlarm` 命中——先看分流表。

## 一、先看挂在哪一环

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 轴名解析 | `没有指定轴名：…` / `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 还没碰卡，纯配置问题 |
| ② 卡服务 | `运动卡服务尚未就绪：…` / `找不到运动卡「…」的运行态设备：…` | 宿主没注入服务 / 配置改了没同步 |
| ③ 快照读不到 | `读不到轴「…」的状态快照：运动卡「…」当前为 …` | 还没轮询到第一轮，或已断开/安全停机 |
| ④ 报警即失败 | `轴「…」状态异常：…（建议：…）` | 仅 `FailOnAlarm=true` 时出现，是"读到坏消息"被你配置成了失败 |

## 二、逐条

**`没有指定轴名：请在「Axis」端口填轴名（或用下拉选一个），也可由上游变量给出`**
为什么：`Axis` 实际生效值为空白（手填被清空，或上游变量给了空串）。
怎么改：重新选一个轴；这一行挂着链接时先查上游变量本轮的值——链接值优先级高于手填。

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是**全局唯一**标识，注册表查不到就是配置里没有（改名、删卡、换方案都会）。
怎么改：核对轴名；大小写不敏感但字面必须一致（`Al` 与 `A1`、多一个空格都算两个）。

**`轴「X」在卡「…」上处于停用状态：请到「运动卡设置」把它启用，或换一个轴名`**
为什么：轴映射 `Enabled=false`。怎么改：确认接了驱动器再启用，或换成实际接线对应的轴名。

**`运动卡服务尚未就绪：请在主程序内运行流程`**
为什么：只在没注入运动卡服务的宿主里出现（设计器/离线跑流程）。怎么改：在主程序里运行。

**`读不到轴「X」的状态快照：运动卡「运动卡1」当前为 SafeStopped（状态说明原文）`**
为什么：`GetAxisStatus` 返回空。只有两个来源：① 卡刚点上连接、还没轮询到第一轮（等一拍再跑就好）；
② 已断开/安全停机（冒号后附的是卡的当前状态与说明原文——`当前为` 后面是状态**成员名**，
如 `Closed`（未连接）、`Alarm`（报警）、`SafeStopped`（已安全停机），不是中文）。
怎么改：去「运动卡设置」或调试面板看卡状态；反复出现查通信（网线/供电/网段）与卡级看门狗参数。
注意本步骤**不设"必须在线"门禁**：卡进「报警」时快照通常还在，能正常读到报警位——
读不到的是断连之后的快照。

**`轴「X」状态异常：报警：伺服报警（建议：检查伺服侧故障码…）`**
为什么：`FailOnAlarm=true` 且快照有硬信号（急停输入/正限位/负限位/报警任一）。
冒号后是 `Status` 同一句话，括号里（如有）是故障记录附带的处置建议。
怎么改：这不是"读取坏了"，是"读到了坏消息且你要求它失败"。要么按建议处置报警（清报警不会自动使能，
清完补一步「轴使能」），要么把 `FailOnAlarm` 改回 `false`、由流程条件分支去分流——
后者更常见，因为不同分支处置不一样（重试 / 报警 / 停线）。

## 三、"步骤成功了，但数对不上"这一类

**`Velocity` 一直是 0，但 `Moving` 是 true**
`Moving` 对。正运动驱动的轮询不读速度寄存器，`Velocity` 恒为 `0`（缺数据，不是"静止"）；
仿真驱动会填当前推进速度。判"动没动"一律用 `Moving`；要真实速度反馈得扩展驱动，不要在本步骤里凑。

**明明撞了限位，`Alarm` 却是 false**
限位与报警是独立位：看 `PositiveLimit` / `NegativeLimit`。反过来 `Status` 显示"报警：…"时
限位信息藏在其余端口里，需逐个读——`Status` 是按优先级取**一条**，不是全量罗列。

**步骤成功、位置明显不对（差一个当量倍数）**
单位口径问题：位置应是 mm。读数像脉冲数，说明该轴 `UnitsPerMm` 配错，
或正运动侧设置当量下发失败（日志会警告"位置与目标将按控制器原单位解释"）。
核对「运动卡设置」里该轴当量与驱动器电子齿轮比，两处口径必须一致。

**命令刚完成，`Enabled` 还是 false（「轴使能」明明成功了）**
以设备回报为准是刻意的：使能命令完成的那一拍，轴状态快照可能还没刷到（快照由轮询按卡级间隔刷新）。
守门断言 `轴使能命令完成，且设备回报已使能`（`FlowCanvasChecks\MotionChecks.cs`）钉的就是
"命令完成与快照刷新是两件事，断言要分别等"。再走一圈或等一拍再读即可。

**读到 `已到位` 但位置是上一轮的？**
本步骤每次执行开头清零九个输出、然后按**同一份快照**一次写回，不存在"新位置配旧到位位"。
若现象如此，看到的其实是**卡侧快照本身没刷新**（轮询线程停了 = 卡已失联），
对照下一步：`Success` 是否仍为 true、`Status` 是否还是旧值——再查卡状态与看门狗。

**用日志比反复点运行快**
本步骤成功时把 `Status` 原文写进行日志（`轴「X」：已到位（20.000 mm）`），
连跑几轮就能从日志里看出位置推进与状态翻转的顺序，不用逐端口接线。
