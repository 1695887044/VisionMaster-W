# 读轴状态：端口与参数

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

这一页只回答三件事：**每个口怎么填、每个输出字段的口径、这些值最后存在哪儿**。
为什么读快照不直读硬件、"读到坏消息"为什么不失败，见《读轴状态》首页，本页不重复。

## 一、参数面板长什么样

本步骤**没有自定义配置界面**，参数清单**只列输入端口**：

| 界面元素 | 本步骤看到的内容 |
| --- | --- |
| 行 | 只有一个输入端口一行：`Axis` |
| 值框 | `Axis` 呈现为**下拉**（候选 = 当前方案里已启用的轴） |
| 🔗 图标 | 改成"由上游变量给出"（推荐链上游动作步骤的 `Axis` 输出） |
| ✕ 图标 | 清除链接（也清掉常量），回落到默认值 `X` |

面板顶部提示条原文：**「该步骤没有自定义配置界面，参数如下：没有绑定需求时直接填入常量，
需要连上游变量就点右侧的链接图标。」**

**取值优先级**：上游链接值 ＞ 界面手填常量 ＞ 步骤声明的默认值。

## 二、输入端口与配置项逐个

| 名称（也是存档键） | 类别 | 类型 | 默认 | 口径 |
| --- | --- | --- | --- | --- |
| `Axis` | 输入端口（可链接，`IsRequired=false`） | 字符串（逻辑轴名） | `X` | 解析不出轴 → 步骤失败，原因由解析器给出（见排障页） |
| `FailOnAlarm` | 配置项 `[StepConfig]` | 布尔 | `false` | `true` = 快照里有**硬信号**（急停输入 / 正限位 / 负限位 / 报警，任一为真）就判本步骤失败，并在有故障记录时拼上建议 |

**`FailOnAlarm` 为什么界面上改不了**：本插件没有自定义视图，参数面板只渲染输入端口，
`[StepConfig]` 在这张面板上没有渲染形态 = 没有编辑入口。实际生效的是默认值/流程存档值；
要打开它需在流程存档里改该步骤的属性值（按属性名 `FailOnAlarm` 保存）。
这是当前界面欠账，不是设计意图。

**硬信号的判断口径**是 `AxisStatus` 上的统一属性（急停输入 / 正限位 / 负限位 / 报警任一为真），
与「等待到位」里"报警优先于到位"用的是同一套判断——两处不会出现宽严不一致。

## 三、输出端口逐个（九个 + 通用两个）

| 端口 | 类型 | 口径 / 坑 |
| --- | --- | --- |
| `Position` | 浮点（mm） | **指令位置**（控制器内部的 Mpos，驱动已按脉冲当量换算成 mm），不是编码器实际位置；带跟随误差、丢步、被外力推动时两者分叉，本步骤不报这个差 |
| `Velocity` | 浮点（mm/s） | **可信度按卡而定**：仿真驱动会给（运动中=当前推进速度、静止=0）；正运动驱动当前轮询不读速度寄存器，恒为 `0`。判"动没动"一律用 `Moving`，不要用 `Velocity=0` |
| `Moving` | 布尔 | 卡侧忙碌位（正运动取空闲判断，空闲=0 即视为运动中），不是软件自己比距离 |
| `InPosition` | 布尔 | 卡侧到位信号（到位判断参数在控制器/驱动器侧，如跟随误差窗口、到位带宽） |
| `Enabled` | 布尔 | 伺服是否上电（以设备回报为准——命令完成的那一拍快照可能还没刷到，见排障页） |
| `Alarm` | 布尔 | 卡侧报警状态位的汇总（伺服报警、跟随误差超限等）；与限位位**互相独立** |
| `PositiveLimit` | 布尔 | 正限位是否触发 |
| `NegativeLimit` | 布尔 | 负限位是否触发 |
| `Status` | 字符串 | 同一份快照按优先级取**一条**互斥描述：报警 → 急停输入 → 正限位 → 负限位 → 运动中 → 未使能 → 已到位/裸位置。例：`报警：伺服报警`、`急停输入被触发`、`运动中（12.345 mm）`、`已到位（12.345 mm）`、`12.345 mm` |
| `Success` / `ErrorMessage` | 布尔 / 字符串 | 每个步骤都有 |

注意两处名字口径：属性名 `StatusText`，**端口名是 `Status`**——下游引用与界面以端口名为准；
属性名 `Position`/`Velocity` 等与端口名一致。

## 四、写入时序：开头全清、成功全写

每次执行**先把九个输出全部重置**（数值 0、布尔 false、文本空），再读快照、一次性按同一份快照写回。
后果：① 上一轮的旧值不会伪装成本轮读数；② 失败路径（解析失败 / 快照读不到）下输出保持全零——
下游看到 `Success=false` 时应忽略全部数值输出，那不代表"轴在 0 位、一切正常"。

## 五、这些值最后存在哪儿

- `Axis` 的常量落在步骤的 `InputValues`（`.vms`），键名 = 端口名；链接后确认时移除常量键。
  存的是**轴名本身**，不存卡地址、不存物理轴号——换卡/改接线只动「运动卡设置」。
- `FailOnAlarm` 按属性名落在该步骤的配置段中（界面无编辑入口，一般只有手工改存档才会出现非默认值）。
- 九个输出端口**不落盘**：它们是本轮执行的产物，交给连线下游与变量系统。

## 六、口径速查

- **单位**：mm / mm/s / ms 一律公制；脉冲当量换算发生在驱动层（正运动连接时逐轴下发 `SetUnits`，
  当量取轴映射 `UnitsPerMm`，默认 1000），软件**不再除当量**。读数像脉冲数（大一个数量级）就是当量配错。
- **坐标系基准**：与「轴运动」的绝对坐标同一套（「轴回零」建立的零点）。
  未回零时读到的是上电瞬间的原始读数——数值照样返回，但**不要当可信坐标用**。
- **同一轮自洽**：九个字段来自同一份快照（同一采样时刻），不会出现"位置是新的、报警位是旧的"。
- **刷新节奏**：由**卡级** `PollIntervalMs`（「运动卡设置」，默认 10 ms）决定；本步骤没有"轮询间隔"参数，
  它就是单点读一次。
