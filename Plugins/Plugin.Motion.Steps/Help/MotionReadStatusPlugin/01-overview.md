# 读轴状态

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

读取一根轴的位置 / 速度 / 使能 / 限位 / 报警等运行状态，是运动链路的**反馈入口**。
产出九个输出端口，其中最常上屏的是 `Status`（一句话描述）。

它在链路里跟在"动作"之后，用于确认动作真的发生了：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 本步骤 / 轴卡 IO / 轴停止`

## 为什么需要它 / 原理

- **读的是轮询快照，不发起通信**。一次执行里读到的九个字段来自**同一采样时刻**，互相自洽；
  也不会因为流程跑得比通信快而把网口打满。快照由这张卡的轮询线程按卡级 `PollIntervalMs`（默认 10 ms）刷新。
- **快照可能还没有**：刚连接、还没轮询到第一轮，或者已经断开时，快照是空的。
  这时本步骤**判失败**，而不是给一版全 0 的状态 ——
  把"未知"当成"位置 0、未报警"是最坏的做法：下游会拿一个猜测值做判断，而且看不出是猜的。
- **读到坏消息 ≠ 读取失败**。默认 `FailOnAlarm=false`：读到一个报警，这一步仍然是"成功读到"，
  由流程显式判断要不要因此中断。把"读取失败"与"读到坏消息"混在一起，异常处理就没法写了。
- **同时给结构化字段和人话**。`Position`/`Moving`/`Alarm` 这些供流程做条件判断与变量绑定；
  `Status` 供直接上屏、写日志、进报表 —— 现场排查时最需要的是一句人话。
- **开头全部清零**：每次执行先把九个输出重置（数值 0、布尔 false、文本空），
  所以上一轮的旧值不会伪装成本轮的读数。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Axis` | 否 | 逻辑轴名，默认 `X`。下拉候选来自「运动卡设置」里已启用的轴；可由上游变量给出。建议链上游「轴运动」的 `Axis` 输出 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Position` | 当前位置，**mm**（指令位置，已按脉冲当量换算） |
| `Velocity` | 当前速度，**mm/s**。注意：正运动卡的轮询不读速度，该字段在正运动上恒为 `0`（不是"轴静止"的意思） |
| `Moving` | 是否运动中（卡侧忙碌位；正运动取 `GetIfIdle`，idle=0 即为运动中） |
| `InPosition` | 是否已到位（卡侧到位信号，非软件自己比距离） |
| `Enabled` | 是否已使能（伺服上电） |
| `Alarm` | 是否报警（伺服报警 / 跟随误差超限等，卡侧状态位的汇总） |
| `PositiveLimit` | 正限位是否触发 |
| `NegativeLimit` | 负限位是否触发 |
| `Status` | 一句话描述（同一份快照的优先级摘要：报警 → 急停 → 正限位 → 负限位 → 运动中 → 未使能 → 已到位/位置） |
| `Success` / `ErrorMessage` | 每个步骤都有的成败与原因 |

`Status` 的取值就是这几句（互斥，按优先级取第一条命中）：
`报警：伺服报警` / `急停输入被触发` / `正限位被触发` / `负限位被触发` / `运动中（12.345 mm）` /
`未使能` / `已到位（12.345 mm）` / `12.345 mm`（既未到位也无异常时只报位置）。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Axis` | `X` | 逻辑轴名（**输入端口**，界面上可改、可被上游链接） |
| `FailOnAlarm` | `false` | true=只要快照里有硬信号（报警 / 正限位 / 负限位 / 急停输入）就判本步骤失败。当前是步骤的**配置属性**，本插件没有自定义配置界面、参数面板只列输入端口，所以界面上暂无编辑入口，实际以默认值/存档值为准 |

> 硬信号的判断口径是一个统一属性（急停输入 / 正限位 / 负限位 / 报警 任一为真），
> 与「等待到位」里"报警优先于到位"用的是同一套判断，两处不会出现宽严不一致。

## 口径与失败策略

- **位置是 mm 不是脉冲**。正运动卡在连接时对每个启用轴下发 `SetUnits`（当量取轴映射 `UnitsPerMm`，默认 `1000`），
  之后 `GetMpos` 读回来直接就是 mm，软件**不再除当量**。换卡/改当量只影响「运动卡设置」，不影响本步骤。
- **指令位置 vs 实际位置**：读的是控制器内部的指令位置（Mpos），不是编码器反馈位置。
  带跟随误差、丢步或外力推动时两者会分叉 —— 本步骤不报这个差。
- **坐标系基准**：与「轴运动」的绝对坐标同一套（由「轴回零」建立的零点）。未回零时读到的是上电瞬间的原始读数，
  数值本身仍会返回，但**不要把它当可信坐标使用**。
- **速度字段的可信度按卡而定**：虚拟卡会给（运动中为当前速度、停止为 0）；正运动卡当前不采速度，恒为 `0`。
  不要用 `Velocity` 判断"是不是停了"，用 `Moving`。
- **算不算流程失败**：
  ① 轴名解析失败 → 失败；② 快照读不到 → 失败（`读不到轴「X」的状态快照：运动卡「…」当前为 Alarm（…）`）；
  ③ `FailOnAlarm=true` 且快照有硬信号 → 失败（并在有故障记录时拼上建议）；其余情况**成功**，
  哪怕读到的是"报警 + 未使能 + 压在负限位上"。
- **卡未连接也能读**：本步骤不设"必须在线"的门禁，只要快照还在（或能拿到）就返回。
  断开后第一轮读不到就报"状态快照读不到"，这是它区别于「轴运动」的地方 —— 后者会先挡状态。

## 典型用法 / 接线

```
动作后确认（推荐紧跟等待）：
  轴运动(X) ──▶ 等待到位(X) ──▶ 本步骤(X) ──▶ 数据记录（Position / Status）

报警巡检分支（不阻断流程，交给条件判断）：
  本步骤(X) ──┬─ Alarm ──▶ 条件判断 ──▶ 轴停止 / 报警输出
              ├─ PositiveLimit / NegativeLimit ──▶ 条件判断
              └─ Status ──▶ 界面显示 / 日志 / 报表

收尾停稳确认（「轴停止」之后）：
  轴停止(X) ──▶ 本步骤(X)   判据用 Moving=false（不要用 Velocity=0，正运动不回报速度）

链路上下游关系：本步骤读的是**别的步骤造成的结果**，它自己不动任何机构，
所以可以放心插在流程任何位置做采样，也可以反复读。
```

## 常见问题

**Q：`读不到轴「X」的状态快照：运动卡「…」当前为 …`？**
快照为空只有两个来源：卡还没轮询到第一轮（刚点连接，等一下再跑），或者已经断开/安全停机。
去「运动卡设置」或调试面板看卡状态与说明；反复出现就查通信（网线/供电/网段）与卡级看门狗参数。

**Q：`Velocity` 一直是 0，但 `Moving` 是 true，谁对？**
`Moving` 对。正运动卡的轮询不读速度寄存器，`Velocity` 在正运动上恒为 `0`（缺数据，不是"静止"）。
判断动没动请用 `Moving`；要真实速度反馈需要扩展驱动读取，不要在本步骤里凑。

**Q：明明撞了限位，`Alarm` 却是 false？**
限位与报警是两个独立位，分别由 `PositiveLimit`/`NegativeLimit` 与 `Alarm` 报告，不要只看 `Alarm`。
反过来也一样：报警时 `Status` 会优先显示"报警：…"，限位信息就藏在其余端口里，需逐个读。

**Q：步骤成功、位置却明显不对（比如差一个当量倍数）。**
这是**单位口径**问题：位置应当是 mm。若读数像脉冲数，说明该轴的 `UnitsPerMm` 配错、
或正运动侧 `SetUnits` 下发失败（日志里会有"设置脉冲当量失败——位置与目标将按控制器原单位解释"）。
核对「运动卡设置」里该轴的当量与驱动器电子齿轮比，两处必须口径一致。

**Q：我想让它"报警就中断流程"。**
把 `FailOnAlarm` 设为 `true`（当前界面没有编辑入口，需在流程存档里改该步骤属性），
或者保持默认、在后面的条件判断里用 `Alarm` / `PositiveLimit` / `NegativeLimit` / `Status` 分流。
后者更常见，因为不同分支的处置不一样（重试、报警、还是停线）。

**Q：能不能用它代替「等待到位」？**
不建议。本步骤是**单点采样**：读完就返回，不等"停下来"。
需要"直到停下为止"的语义请用「等待到位」（有超时、有硬信号优先判断、有耗时统计）。
反过来，需要看一堆字段的全貌时，本步骤是「等待到位」给不了的。

**Q：多轴设备要每个轴都放一步吗？**
要。本步骤一次只读一根轴（`Axis` 是轴级）。常见写法是各轴并排放，或只读关键轴、其余靠卡级报警显示。

**Q：能不能读到"回没回零"？**
读不到。轴状态快照里没有"已回零"这一位，本步骤也不输出它。
"是否回过零"目前不作为运动门禁（门禁只查卡状态、能力、轴号、软限位），
所以请按现场要求在流程首步显式放「轴回零」，不要指望软件替你保证。
