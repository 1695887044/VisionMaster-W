# 读轴状态

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

读取一根轴的位置 / 速度 / 使能 / 限位 / 报警等运行状态，是运动链路的**反馈入口**。
产出九个输出端口（外加每个步骤都有的 `Success` / `ErrorMessage`），最常上屏的是 `Status`（一句话描述）。
它跟在"动作"之后，用于确认动作真的发生了：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 本步骤 / 轴卡 IO / 轴停止`

## 跑通第一次：4 步

1. 在前面放任意动作步骤（或就放在流程开头做巡检）。
2. 放本步骤，`Axis` 填要读的轴名（推荐直接链上游步骤的 `Axis` 输出，避免手抄）。
3. 跑一次，看九个输出口都有数：`Position` 应是机构当前位置（mm），`Status` 是一句人话。
4. 把要判断的位（`Alarm` / `Moving` / `PositiveLimit` …）连进条件分支，把 `Status` 连上屏或进「数据记录」。

## 跑通后该看到什么

- 成功日志一行：`轴「X」：已到位（20.000 mm）`（冒号后就是 `Status` 端口的内容；行首是步骤实例名）。
- 九个输出全部按快照刷新（步骤开头先全部清零，所以上一轮的旧值不会伪装成本轮读数）。
- **默认"读到报警也算成功"**——`Alarm=true` 但 `Success=true` 是正常组合，处置交给流程；
  要"报警即失败"见《端口与参数》页的 `FailOnAlarm`。

## 原理（每条一句话）

- **读的是轮询快照，不发起通信**。一次执行里九个字段来自**同一采样时刻**，互相自洽；
  也不会因为流程跑得比通信快而把网口打满。快照由卡级轮询（默认 10 ms）刷新。
- **快照可能还没有**：刚连接还没轮询到第一轮、或已断开时快照为空——这时本步骤**判失败**，
  而不是给一版全 0 的状态。把"未知"当成"位置 0、未报警"是最坏的做法：下游拿猜测值做判断，还看不出是猜的。
- **读到坏消息 ≠ 读取失败**。默认 `FailOnAlarm=false`：报警也算"成功读到"，由流程显式分流。
  把两件事混在一起，异常处理就没法写了。
- **同时给结构化字段和人话**：`Position`/`Moving`/`Alarm` 等供条件判断与变量绑定；
  `Status` 供直接上屏、写日志、进报表——现场排查时最需要的是一句人话。

## 端口速览（逐个口径见《端口与参数》页）

| 端口 | 类型 | 一句话含义 |
| --- | --- | --- |
| `Axis` | 输入（可链接） | 逻辑轴名，默认 `X`，下拉候选 = 「运动卡设置」里已启用的轴 |
| `Position` | 输出 | 当前位置，**mm**（指令位置，已按脉冲当量换算） |
| `Velocity` | 输出 | 当前速度，**mm/s**。正运动卡上恒为 `0`（卡侧不回报速度），判"动没动"用 `Moving` |
| `Moving` | 输出 | 是否运动中（卡侧忙碌位） |
| `InPosition` | 输出 | 是否已到位（卡侧到位信号，非软件比距离） |
| `Enabled` | 输出 | 是否已使能（伺服上电） |
| `Alarm` | 输出 | 是否报警（伺服报警/跟随误差超限等卡侧状态位的汇总） |
| `PositiveLimit` / `NegativeLimit` | 输出 | 正/负限位是否触发（与 `Alarm` 是独立位，别只看报警） |
| `Status` | 输出 | 一句话描述（同一份快照按优先级取一条）：`报警：…` / `急停输入被触发` / `正限位被触发` / `负限位被触发` / `运动中（12.345 mm）` / `未使能` / `已到位（12.345 mm）` / `12.345 mm` |
| `Success` / `ErrorMessage` | 输出 | 每个步骤都有 |

## 典型接线

```
动作后确认（推荐紧跟等待）：
  轴运动(X) ──▶ 等待到位(X) ──▶ 本步骤(X) ──▶ 数据记录（Position / Status）

报警巡检分支（不阻断流程，交给条件判断）：
  本步骤(X) ──┬─ Alarm ──▶ 条件判断 ──▶ 轴停止 / 报警输出
              ├─ PositiveLimit / NegativeLimit ──▶ 条件判断
              └─ Status ──▶ 界面显示 / 日志 / 报表

收尾停稳确认（「轴停止」之后）：
  轴停止(X) ──▶ 本步骤(X)   判据用 Moving=false（不要用 Velocity=0，正运动不回报速度）
```

本步骤读的是**别的步骤造成的结果**，自己不动任何机构，可以放心插在流程任何位置采样，也可以反复读。

## 常见问题（速答）

**Q：`Velocity` 一直是 0，但 `Moving` 是 true，谁对？**
`Moving` 对。正运动卡的轮询不读速度寄存器，`Velocity` 在那种卡上恒为 `0`（缺数据，不是"静止"）。

**Q：明明撞了限位，`Alarm` 却是 false？**
限位与报警是独立位，分别由 `PositiveLimit`/`NegativeLimit` 与 `Alarm` 报告。
反过来报警时 `Status` 优先显示"报警：…"，限位信息藏在其余端口里，需逐个读。

**Q：我想让它"报警就中断流程"。**
把 `FailOnAlarm` 设 `true`（当前界面无编辑入口，需在流程存档里改该步骤属性），
或者保持默认、在后面用 `Alarm` / `PositiveLimit` / `NegativeLimit` / `Status` 分流——后者更常见，
因为不同分支的处置不一样（重试、报警、还是停线）。

**Q：能不能用它代替「等待到位」？**
不能。本步骤是**单点采样**：读完就返回，不等"停下来"。要"直到停下"的语义用「等待到位」；
要看一堆字段的全貌，「等待到位」给不了。

**Q：能不能读到"回没回零"？**
读不到。轴状态快照里没有"已回零"这一位（"已回零"是卡级标记，不是轴位），
本步骤也不输出它。按现场要求在流程首步显式放「轴回零」，不要指望软件替你保证。

**Q：卡没连接也能读吗？**
只要快照还在就能读（本步骤不设"必须在线"门禁——这是它和「轴运动」的区别）；
断开后第一轮起读不到，报"状态快照读不到"。
