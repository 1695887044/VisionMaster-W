# 轴回零：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面/日志里真会出现的原文**（从源码逐字抄，`{…}` 处是实际值），按"现象 → 为什么 → 怎么改"排。

## 一、先看挂在哪一环节

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 轴名解析 | `没有指定轴名：…` / `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 还没碰卡，纯配置问题 |
| ② 卡状态门禁 | `运动卡「…」当前不可运动：…` | 步骤自己的前置判断：本步骤只放「在线」 |
| ③ 能力协商 | `回零命令被拒绝（Rejected_NotSupported）：该卡不支持回零方式「…」，它支持的是：…` | 设备门禁按能力表拦下，配置与卡不匹配，不是运行时故障 |
| ④ 命令入队 | `回零命令被拒绝（Rejected_…）：…` | 设备门禁拦下（状态 / 能力 / 轴号 / 正在运动），括号里是命令结果成员名 |
| ⑤ 执行与等待 | `轴「…」回零超时（>… ms）：…` / `轴「…」回零失败（…）：…` / `轴「…」回零被取消：…` | 命令进了队列，卡那边没成 |

两条超时不会同时出现，先到者胜：步骤侧等的是 `TimeoutMs + 1000 ms`，驱动侧到点会**先停轴再报**，
所以正常看到的是⑤里 `TimedOut` 那条。

## 二、逐条

**`没有指定轴名：请在「Axis」端口填轴名（或用下拉选一个），也可由上游变量给出`**
为什么：`Axis` 的实际生效值是空白（下拉没选、手填框被清空）。
怎么改：在参数面板把 `Axis` 选一个（下拉里只有**已启用**的轴）。这一行是"只能选"型下拉、没有链接按钮，
所以空白只可能是没选或选了之后被清掉。

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是全局唯一标识，注册表里查不到就是配置里没这个名字（改名、删卡、换方案都会造成这个结果）。
怎么改：去「系统 → 运动卡设置」核对轴名。大小写不敏感但**字面必须一致**：`Al`（字母 L）与 `A1`、
`上料轴` 与 `上料 轴`（多一个空格）都算两个名字。

**`轴「X」在卡「…」上处于停用状态：请到「运动卡设置」把它启用，或换一个轴名`**
为什么：轴映射里 `Enabled = false`（未接电机的轴可以关掉，就是为了让流程误用不了）。
怎么改：确认这根轴确实接了驱动器再启用，否则换成实际接线对应的那根轴名。

**`找不到运动卡「…」的运行态设备：请确认该卡已在「运动卡设置」里配置并保存到方案`**
为什么：注册表里有这根轴的绑定，但运行态设备表里没有对应卡 Id 的设备 —— 配置改了没同步，或换了方案没重开流程。
怎么改：保存方案后回流程重开一次参数面板；仍不行就重连该卡（运行期会把配置变化同步进设备表）。

**`运动卡服务尚未就绪：请在主程序内运行流程`**
为什么：只在**没有注入运动卡服务**的宿主里出现 —— 从设计器/离线宿主单独跑流程时是空实现。
怎么改：在主程序里运行（试运行与正式运行注入的是同一个服务）。

**`轴注册表尚未注入（宿主未完成初始化）：请重启主程序`**
为什么：宿主启动阶段的注入没完成（启动自检被跳过或初始化异常）。怎么改：重启主程序；
若反复出现，看启动日志里运动模块的初始化有没有报错。

**`运动卡「{卡名}」当前不可运动：{状态说明}`**
为什么：卡的当前状态不是「在线」。本步骤的入口只放「在线」，所以**报警态、已安全停机、未连接、连接中**
都会落在这条上（冒号后面是卡自己的状态说明原文，报警时通常是「轴名：报警原因」）。
怎么改：未连接 → 去「运动卡设置」点连接，或勾「随方案启动自动连接」；
报警 → 先在调试面板清报警（**清报警不会自动回零**，之后还得让流程重跑这一步）；
已安全停机 → 状态机不会自己回 online，**先断开再连接**（安全停机意味着通信连续失败或命令执行失败，
原因还没排除，人工确认那一步不能省）；连接中 → 等一轮或重试。

**`回零命令被拒绝（Rejected_NotSupported）：该卡不支持回零方式「PositiveLimit」，它支持的是：NegativeLimitIndex、Origin、PresetZero`**
为什么：设备门禁的能力协商挡下的配置问题，不是运行时故障。后半句已经把这张卡支持的方式**列成成员名**了。
支持的集合由驱动上报：正运动总线型 8 种全支持、脉冲型只有 `NegativeLimitIndex` / `PositiveLimitIndex` / `Origin`、
虚拟卡只有 `NegativeLimitIndex` / `Origin` / `PresetZero`。
怎么改：照后半句换一种；机构确实需要限位类回零而卡是脉冲型/虚拟卡，就得换总线型或改用 `Origin`。

**`回零命令被拒绝（Rejected_NotSupported）：该卡不支持回零方式「{Mode}」，它支持的是：（该卡尚未上报能力，请确认已连接）`**
为什么：能力表是**连接成功时才建立**的，没连上就没有支持清单（这条文案就是空清单时的兜底）。
怎么改：先连接该卡；连接失败的原因看该卡说明（正运动常见是 native DLL 缺失或 IP/网段不通）。

**`回零命令被拒绝（Rejected_NotConnected）：轴「X」正在运动，不能同时回零：请先停止该轴（或在当前运动结束后再回零）`**
为什么：Home 的运动前置条件只有"未在运动中"这一条。轴还在走时发回零会让两个目标互相覆盖。
怎么改：先发「轴停止」，或在前一条运动后加「等待到位」，等轴停稳再回零。这条拒绝记为 Notice 级，不是设备故障。

**`回零命令被拒绝（Rejected_NotSupported）：该卡不支持回零方式「Origin」，它支持的是：…`**
为什么：设备门禁的能力校验（P1-A 起能力协商只在这里做，步骤侧不再重复一套）。
走到这条说明入队时卡的能力表与配置不匹配 —— 典型是排队期间重连了另一张卡。
怎么改：核对卡名与轴映射指向的是不是同一张卡，再重跑。

**`回零命令被拒绝（Rejected_InvalidArgument）：轴号 3 超出范围（本卡 4 轴）`**
为什么：轴映射里配的**物理轴号**超出这张卡上报的轴数（机型给小了，或未识别机型走了兜底 4 轴）。
怎么改：核对「运动卡设置」的机型栏与物理轴号。换 8 轴的卡（`ECI3828`）而机型留空时，以控制器上报的型号为准；
日志里若出现过 `未识别机型「…」，本次按 4 轴 …`，先把机型填准。

**`回零命令被拒绝（Rejected_QueueFull）：命令队列已满（上限 256 条）`**
为什么：这一轮往这张卡堆了太多命令，或前面的命令卡住了队列（此时队列不消费）。
怎么改：先看有没有轴在报警/通信受阻，再考虑加等待、降低循环频率或拆分流程。上限是卡级参数 `MaxQueueDepth`。

**`轴「X」回零超时（>120000 ms）：请检查原点/限位开关接线、回零速度与回零方式是否正确`**
为什么：命令进了队列，但 `TimeoutMs + 1000 ms` 内没等到完成信号（这条是**步骤侧**的等待上限）。
怎么改：查①原点/限位开关接线与电平（调试面板的 IO 页能看同一帧原始电平）；②回零高速/低速是否设得过小
（控制器内参数，本步骤不改它）；③方式与机构是否匹配（需要 Index 的方式在没接 Z 相的编码器上永远等不到）。
真正确认需要更久的场合把 `TimeoutMs` 加大，不要减小。

**`轴「X」回零失败（TimedOut）：回零超时（>120s）：请检查原点/限位开关、回零方式与回零速度`**
为什么：这是**驱动侧**自己判的超时（正运动总线型；脉冲型的文案是 `回零超时（>120s）` 没有后半句）。
驱动在报这条之前**已经先给这根轴下了减速停**，不会把一个还在寻零的轴丢给下一条命令。
虚拟卡的对应文案是 `回零超时（>{毫秒}ms）`。
怎么改：同上一条；先离开限位开关再重跑，反复出现就按方式与开关是否匹配来查。

**`轴「X」回零被取消：执行前校验未通过：运动卡处于报警状态，请先清除报警`**
为什么：命令**在队列里排着**的时候卡状态变差了，执行前的二次校验把它拦下（后半句是当时的门禁原因，
可能是 `运动卡未连接` / `运动卡正在连接/断开，请稍候` / `运动卡已安全停机，请重新连接后再操作` /
`轴号 … 超出范围（本卡 … 轴）` / `轴「X」正在运动，不能同时回零…`）。
怎么改：处理卡的状态，再重跑这一步；回零不可重试是刻意的，所以必须人工确认后再发起。

**`轴「X」回零被取消：被急停中断`** / **`轴「X」回零被取消：已取消（设备断开或流程中断）`**
为什么：前者是有人按了急停，后者是设备断开或流程被中止。
这两种**都不记成设备故障、也不进安全停机** —— 人工急停是预期行为。
怎么改：确认安全后重新连接/重启流程，再回零。

**`轴「X」回零失败（Failed）：回零失败（轴 X，正运动错误码 12）。检查原点/限位开关是否被触发、回零方式与回零速度是否与机构匹配；排除后重新回零（建议：…）`**
为什么：驱动启动寻零就吃了厂商返回码。冒号前括号里的 `Failed` 是**命令状态成员名（英文）**，
冒号后面是驱动拼好的"操作 + 轴名 + 原始码 + 建议"整段；末尾若还有 `（建议：…）`，那是设备最近一次故障的建议字段，
可能与前半句重复（同一句被说了两遍，不是两个不同的问题）。错误码是厂商原始码，**没有被翻译成"好听的话"**——
SDK 没有码→文案的接口，凭记忆编对照表只会把人引错方向。
怎么改：拿那个数字对正运动手册；这条故障的分级是"需人工复位"，所以**先排除机械原因**（开关被触发、方向不对）
再重跑，不要直接循环重试。

## 三、"步骤成功了但结果不对"这一类

**`Homed = true`，但轴看起来没在零点**
虚拟卡会把位置直接写 0；真机上"停在哪儿算 0"由控制器的**回零偏移**决定。
机构要求"零点 = 夹爪闭合位"时，用回零偏移或对好位后改用 `PresetZero`。

**回零这一步绿了，后面的「轴运动」还是撞限位**
回零建立的零点只对**这根轴**有效。核对两个步骤的 `Axis` 是不是同一个轴名；
以及后面那条用的是不是**别的卡上的同名轴**（轴名必须全局唯一，重名时解析不到的一律不进下拉）。

**用日志定位比反复点运行快**
本步骤成功时打印 `{步骤实例名} 轴「X」回零完成（方式 NegativeLimitIndex）`，失败时卡的执行线程也会打
`[{卡名}] X 回零（NegativeLimitIndex） → Failed：…`。两行对照就能分清"步骤没等到"与"卡说它失败了"。
