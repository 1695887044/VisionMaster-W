# 轴回零：快速上手

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

让一根轴**回到机械原点**，把这根轴的坐标零点建立起来。产出只有一个业务端口 `Homed`（回零是否完成），
外加每个步骤都有的 `Success` / `ErrorMessage`。

它在运动链路的**第二环**：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态 / 轴卡 IO / 轴停止`

为什么必须有这一步：增量式编码器掉电后"轴在哪"是不知道的，此时按绝对坐标运动，
控制器会拿一个错误的当前位置去算行程 —— **可能直接撞向限位**。所以建议把它放在流程首步（使能之后、任何运动之前）。

## 一、跑通第一次（5 步）

1. 先把卡配好：「系统 → 运动卡设置」里添加运动卡、填机型、连上，并在轴映射里给这根轴一个**逻辑轴名**（如 `X`）且勾选启用。
2. 流程里「轴使能」之后放一个**轴回零**步骤。
3. 双击该步骤打开参数面板，把 `Axis` 那一行的下拉选成第 1 步里的轴名（下拉里只有**已启用**的轴）。
4. 回零方式**先用默认**（`NegativeLimitIndex`，即"负限位 + Index"），它适配绝大多数机台；
   这一项当前是步骤的配置属性，界面上没有编辑入口（见本页第五节的 Q&A），要换方式请对照第二节的表改存档值。
5. 运行一次。看得到成功日志：`{步骤实例名} 轴「X」回零完成（方式 NegativeLimitIndex）`，
   同时 `Homed = true`、`Success = true`、`ErrorMessage` 为空。

跑通后应该看到的现象：这根轴的位置读数变成 0（虚拟卡直接写 0；真机上由控制器的回零偏移决定停在哪儿算 0），
后续「轴运动」的绝对目标都以这个零点为基准。

## 二、回零方式怎么选

左列 `HomeMode` 成员名是**流程存档与报错里用的名字**（契约枚举，C# 值 0~7）；
"正运动模式码"那一列是**正运动控制器的 `homemode` 参数**（由驱动 `ZMotionHomeModes.ToSdk` 一对一映射），
两套数字**互不相等**，别把它们混为一谈。中文说法来自契约层的显示字典，出现在「运动卡设置 → 板卡调试」的回零下拉里。

| 成员名（存档 / 报错） | C# 值 | 正运动 `homemode` | 中文说法 | 什么时候用 |
| --- | --- | --- | --- | --- |
| `NegativeLimitIndex` | 0 | 1 | 负限位 + Index | 撞到负限位后找第一个 Index 脉冲，**精度最高、机台最常见**（本步骤默认值） |
| `PositiveLimitIndex` | 1 | 2 | 正限位 + Index | 机台只装了正限位开关时 |
| `Origin` | 2 | 19 | 原点开关 | 只有原点开关、没有 Z 相（Index）信号 |
| `NegativeLimitOrigin` | 3 | 27 | 负限位 + 原点 | 先撞负限位、再回原点开关定位 |
| `PositiveLimitOrigin` | 4 | 23 | 正限位 + 原点 | 先撞正限位、再回原点开关定位 |
| `NegativeLimit` | 6 | 17 | 负限位（不回原点） | 撞到负限位即停；零点随开关重复性变化，精度最差 |
| `PositiveLimit` | 7 | 18 | 正限位（不回原点） | 同上，方向相反 |
| `PresetZero` | 5 | 37 | 零位置预设（不找开关） | **把当前位置直接置为 0**：绝对值编码器、或轴已经停在对接位 |

各卡实际支持哪些（入队前会做能力协商，不支持当场报错）：

| 卡 | 支持的回零方式（成员名） |
| --- | --- |
| 正运动 总线型（ECI3428 / ECI3828 / ZMC408SCAN / VPLC532R） | 上表**全部 8 种** |
| 正运动 脉冲型 | `NegativeLimitIndex`、`PositiveLimitIndex`、`Origin`（寻零参数在控制器内设定） |
| 虚拟运动卡（仿真） | `NegativeLimitIndex`、`Origin`、`PresetZero` |

## 三、典型用法 / 接线

```
轴使能(X) ──▶ 本步骤(Axis=X) ──▶ 轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=ON 夹紧)
                   │
                   └── Homed ──▶ 条件判断（false 就走报警分支，别让后面的运动继续跑）

每台一次（上电标准顺序）：
  轴使能 X → 轴回零 X → 轴使能 Y → 轴回零 Y → [后续所有运动]
```

多轴要不要串行回零，按机构干涉区定：两条轴空间上会撞就一根回完再回另一根；互不干涉可以并排放，
但同属一张卡时命令是**排队执行**的（并不会真的并行）。

## 四、口径与失败策略

- **本步骤会等待**（与「轴运动」相反）。回零是有明确终点的过程动作，后面必须站在零点上才能继续，
  所以天然阻塞：入队后等驱动报"回零结束"，步骤侧最多等 `TimeoutMs + 1000 ms`。
- **超时默认 120000 ms**，下限 1000 ms（填更小按 1000 跑）。回零要先撞开关再找 Index，慢是正常的。
- **绝不盲目重试**：命令上标了"不可重试"。中途失败时轴可能正卡在原点开关上，再来一次可能撞机械原点，
  失败就是失败，交给人确认。
- **回零速度、回零偏移由控制器决定**，本步骤与驱动都不覆盖 —— 现场通常已用厂商调试软件调好，
  软件擅自改动会破坏已经调好的机构行为。
- **卡状态要求比别的步骤严**：只有「在线」才发起回零，「报警」「已安全停机」「未连接」都在步骤入口就被拦下
  （使能/失能那一步反而允许报警态，这是刻意的差别）。
- **超时之后驱动先停轴**（正运动 `Single_Cancel` 减速停）再报超时，不会把一个还在寻零的轴丢给下一条命令。
- **被打断**：急停或流程停止打断回零，报"被取消"，软件**刻意不记成设备故障**、也不因此进安全停机
  —— 人工按急停是预期行为。
- **回零成功后位置是不是 0**：是这根轴的坐标 0。虚拟卡直接写 0；真机由控制器的回零偏移决定，
  若机构要求"零点 = 夹爪闭合位"，用回零偏移或干脆用 `PresetZero` 在对好位之后建零点。

## 五、常见问题

**Q：为什么参数面板里只有「轴」一行，找不到"回零方式"和"超时"？**
本步骤没有自定义配置界面，宿主的自动参数面板**只渲染输入端口**，而 `Mode`（回零方式）与 `TimeoutMs`
是 `[StepConfig]` 配置属性 —— 它们会正常存盘、正常生效，只是在这张面板上没有可渲染的形态。
要改这两个值，眼下只有两条路：直接改方案存档里该步骤的值，或先用默认方式（`NegativeLimitIndex`）跑通再说。
默认值本身就是最通用的一种，多数机台不需要动。

**Q：报错里为什么是 `NegativeLimitIndex` 这种英文，而不是中文？**
`HomeMode` 是契约层的枚举，成员上**没有** `[Display]` 中文名（这是契约层的设计：中文说法统一由一份
显示字典给出，避免同一概念在不同界面变成不同中文）。而**报错文案拼的是成员名**，所以日志与 `ErrorMessage`
里看到的是英文成员名；中文说法只在「运动卡设置 → 板卡调试」的回零下拉里出现。
对照关系就是本页第二节那张表，两边一一对应，不会串位。

**Q：轴朝**反方向**撞过去了？**
九成是回零方式与接线不匹配（限位开关装在正方向、却选了负限位系）。核对三件事：
① 卡上的正/负限位输入点是哪一个；② 电机转向与坐标正方向是否一致（驱动器侧的定义）；
③ 本步骤的方式。**正运动模式码只能来自手册**，不要靠试。

**Q：回零一开始就不动？**
① 未使能（回零要求轴已上电，虚拟卡会明确报 `轴未使能（回零前需先使能）`，真机由控制器固件返回）；
② 卡不在「在线」状态（报警/安全停机都要先处理）；
③ 轴已经压在限位开关上 —— 很多机台要求先离开开关再回零，用调试面板手动移开。

**Q：每次都超时，但轴其实已经回到原点了？**
看方式：`NegativeLimitIndex` / `PositiveLimitIndex` 需要 Z 相（Index）信号，编码器没接 Z 相就永远等不到，
只能改用 `Origin` 或不依赖 Index 的限位类方式。另外确认低速段速度没设得过小（控制器内参数，去厂商软件看）。

**Q：每次上电都要回零吗？**
增量式编码器**必须**（掉电、断线重连后位置都不可信）。绝对式可以省，但别指望软件强制：
**命令门禁不检查"是否已回零"**，它只查卡状态、能力、轴号、软限位。"未回零"只在调试面板上作为提示显示，
流程里该不该回零由你放不放这一步决定。
