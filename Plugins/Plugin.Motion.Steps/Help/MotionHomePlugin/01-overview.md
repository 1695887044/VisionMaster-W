# 轴回零

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

让一根轴**回到机械原点**，把"轴坐标系的零点"建立起来。产出是 `Homed`（回零是否完成）。
它在运动链路的**第二环**：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态 / 轴卡 IO / 轴停止`

为什么必须有这一步：增量式编码器掉电后"轴在哪"是不知道的，此时按绝对坐标运动，
控制器会拿一个错误的当前位置去算行程 —— **可能直接撞向限位**。所以建议把本步骤放在流程首步
（使能之后、任何运动之前）。

## 为什么需要它 / 原理

- **它会等待**（与「轴运动」相反）。回零是一个有明确终点的过程动作，后面必须站在零点上才能继续，
  所以这一步天然阻塞：入队后等驱动报"回零结束"，最多等 `超时 + 1000 ms`。
- **超时给得很大**（默认 `120000` ms）。回零要先撞开关、再找 Index 脉冲，慢是正常的；
  用点位运动那种几十秒的超时会频繁误判。
- **绝不盲目重试**（命令上标了不可重试）：中途失败时轴可能正卡在原点开关上，
  再来一次可能撞机械原点。失败就是失败，交给人确认。
- **能力协商前置**：各卡支持的回零方式不一样，本步骤在入队前就先问这张卡"支不支持这种"，
  不支持时当场报错并**列出它支持哪些**，而不是让用户在界面上一个个试。
- **完成后零点即成立**：回零成功时驱动先把"已回零"标记落下，再发完成信号
  —— 顺序是刻意的，否则紧跟着读到的会是"命令已完成、但还没回零"的中间态。
- **先使能再回零**：本步骤自己不检查"是否已使能"，这件事交给卡去拒。
  虚拟卡会明确报 `轴未使能（回零前需先使能）`；真机上这句话由控制器固件返回，措辞以其为准。

## 回零方式一览

界面显示中文，**流程存档的是成员名**，改显示名不会断连线；报错里出现的同样是成员名（例如
`不支持回零方式「NegativeLimitIndex」`），对照本表左列即可，两句是一一对应的。
正运动一侧的模式码（`homemode`）
只能来自厂商手册，填错一个数字轴会按完全不同的寻零路径走（把"负限位 + Index"填成"正限位 + Index"，
轴就朝反方向撞）：

| 成员名（存档） | 界面显示 | 说明 | 正运动模式码 |
| --- | --- | --- | --- |
| `NegativeLimitIndex` | 负限位 + Index | 撞到负限位后找第一个 Index 脉冲，**精度最高、机台最常见**（默认值） | 1 |
| `PositiveLimitIndex` | 正限位 + Index | 撞到正限位后找第一个 Index 脉冲 | 2 |
| `Origin` | 原点开关 | 只找原点开关，不看限位 | 19 |
| `NegativeLimitOrigin` | 负限位 + 原点 | 先找负限位再回原点开关 | 27 |
| `PositiveLimitOrigin` | 正限位 + 原点 | 先找正限位再回原点开关 | 23 |
| `NegativeLimit` | 负限位（不回原点） | 撞到负限位即停，位置随开关重复性变化 | 17 |
| `PositiveLimit` | 正限位（不回原点） | 撞到正限位即停 | 18 |
| `PresetZero` | 零位置预设（不找开关） | **直接把当前位置置为 0** —— 用于绝对值编码器、或轴已经停在对接位 | 37 |

各卡实际支持哪些（能力协商的口径）：

| 卡 | 支持的回零方式 |
| --- | --- |
| 正运动 总线型（ECI3428 / ECI3828 / ZMC408SCAN / VPLC532R） | 上表**全部 8 种** |
| 正运动 脉冲型 | `NegativeLimitIndex` / `PositiveLimitIndex` / `Origin`（寻零参数在控制器内设定） |
| 虚拟运动卡（仿真） | `NegativeLimitIndex` / `Origin` / `PresetZero` |

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Axis` | 否 | 逻辑轴名，默认 `X`。下拉候选来自「运动卡设置」里已启用的轴；可由上游变量给出 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Homed` | 回零是否完成（本轮开头先清 `false`，只有驱动报"完成"才置 true） |
| `Success` / `ErrorMessage` | 每个步骤都有的成败与原因 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Axis` | `X` | 逻辑轴名（**输入端口**，可在面板改、可被链接） |
| `Mode` | `NegativeLimitIndex` | 回零方式（见上表）。当前是步骤的**配置属性**，本步骤没有自定义界面、面板只列输入端口，所以界面上暂无编辑入口 —— 实际以存档值/默认值为准 |
| `TimeoutMs` | `120000` | 回零超时 ms（下限 `1000`，填更小按 1000 算）。同上，当前是配置属性 |

> 需要改回零方式时先用默认方式跑一遍：默认「负限位 + Index」适配绝大多数机台；
> 机构只有原点开关没有 Index 的，用「原点开关」；轴已经停在对接位、只想建零点，用「零位置预设」。

## 口径与失败策略

- **单位**：只有 `TimeoutMs`（毫秒）。回零过程的速度与回零偏移**由控制器决定**，
  本步骤和驱动都不覆盖 —— 现场通常已用厂商调试软件把回零高速/低速/偏移调好，
  软件擅自改掉会破坏已经调好的机构行为（要按方案配置就得先扩卡级参数并显式暴露到界面）。
- **坐标系**：回零成功后，这根轴的坐标零点就是本次寻到的机械原点；后续「轴运动」的绝对目标都以此为基准。
- **算不算流程失败**：算。命令被拒绝、超时、执行失败、被取消，四种都判 `Success=false`。
- **超时后卡怎么收尾**：正运动在报超时**之前先停轴**（`Single_Cancel` 减速停），
  不会把一个还在寻零的轴丢在那里让下一条命令接着使。
- **被打断**：急停或流程停止打断回零，报的是"被取消"，
  软件**刻意不把它记成设备故障**，也不因此进安全停机 —— 人工按急停是预期行为。

## 报错原文对照

`{…}` 处是实际值；排查时先按这句话定位环节，再决定动哪儿。两条超时不会同时出现，先到者胜：
步骤侧的等待上限是 `超时 + 1000 ms`，驱动侧到点会先停轴再报，所以正常看到的是 `TimedOut` 那条。

| 现象 | 步骤报出的原文 |
| --- | --- |
| 卡不在「在线」状态 | `运动卡「{卡名}」当前不可运动：{状态说明}` |
| 这张卡不支持这种回零方式 | `运动卡「{卡名}」不支持回零方式「{Mode}」，它支持的是：{支持列表}` |
| 命令入队被拒 | `回零命令被拒绝（{Rejected_xxx}）：{故障建议}` |
| 步骤侧等不到命令结束 | `轴「{轴名}」回零超时（>{超时} ms）：请检查原点/限位开关接线、回零速度与回零方式是否正确` |
| 驱动侧自己判超时 | `轴「{轴名}」回零失败（TimedOut）：回零超时（>{秒}s）：请检查原点/限位开关、回零方式与回零速度` |
| 排队期间卡状态变差 | `轴「{轴名}」回零被取消：执行前校验未通过：{门禁原因}` |
| 被急停打断 | `轴「{轴名}」回零被取消：被急停中断` |
| 设备断开 / 流程中断 | `轴「{轴名}」回零被取消：已取消（设备断开或流程中断）` |
| 执行中控制器返回故障 | `轴「{轴名}」回零失败（Failed）：{执行侧错误原文}` |

> 执行侧错误原文由卡给出（正运动是"故障描述。厂商建议"两句拼起来的，末尾还可能再补一次建议），
> 后半句里的 `TimedOut` / `Failed` 是**英文成员名**，不是界面上的中文。

## 典型用法 / 接线

```
轴使能(X) ──▶ 本步骤（Axis=X）──▶ 轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO（夹紧）
                  │
                  └── Homed ──▶ 条件判断（false 就走报警分支，不要让后面的运动继续跑）

每台一次（上电标准顺序）：
  轴使能 X → 轴回零 X → 轴使能 Y → 轴回零 Y → [后续所有运动]
```

多轴要不要串行回零，按机构的干涉区来定：两条轴空间上会撞，就一根回完再回另一根；
互不干涉可以并排放（各自一步），但要注意它们同属一张卡时命令是排队执行的。

## 常见问题

**Q：`运动卡「…」不支持回零方式「XXX」，它支持的是：…`？**
能力协商挡下的配置问题，不是运行时故障。报错后半句已经把这张卡支持的方式列出来了，照着换一种即可。
如果它说的是"该卡尚未上报能力，请确认已连接"，说明卡还没连上 —— 先回「运动卡设置」连接。

**Q：轴朝**反方向**撞过去了？**
九成是回零方式与接线不匹配（限位开关接在正方向、却选了负限位系）。
核对三件事：① 卡上的正/负限位输入点是哪一个；② 电机转向与坐标正方向是否一致
（驱动器侧的旋转方向定义）；③ 本步骤的方式。**模式码只能来自手册**，不要靠试。

**Q：回零一开始就不动？**
① 未使能（回零要求轴已上电）；② 卡不在「在线」状态（报警/安全停机都要先处理）；
③ 轴已经压在限位开关上 —— 很多机台要求先离开开关再回零，用调试面板手动把轴移开。

**Q：每次都超时，但轴其实已经回到原点了？**
先看回零方式：`负限位 + Index` 需要有 Z 相（Index）信号，编码器没接 Z 相或驱动器没给
就永远等不到，只能选"原点开关"或"负限位（不回原点）"这类不依赖 Index 的方式。
另外确认低速段速度别设得过小（这是控制器内参数，去厂商软件里看）。

**Q：每次上电都要回零吗？**
增量式编码器**必须**（掉电、断线重连后位置都不可信）。绝对式可以省，
但别把"能不能省"寄托在软件强制上：**命令门禁不检查"是否已回零"**，它只查卡状态、能力、轴号、软限位。
"未回零"只在调试面板上作为提示显示，流程里该不该回零由你放不放这一步决定。

**Q：回零成功后位置就是 0 吗？**
是这根轴的坐标 0。虚拟卡会直接把位置写 0；真机上"回零停在哪儿算 0"由控制器的回零偏移决定，
若机构要求"零点=夹爪闭合位"，请用回零偏移（控制器内参数）或干脆用「零位置预设」在对好位之后建零点。
