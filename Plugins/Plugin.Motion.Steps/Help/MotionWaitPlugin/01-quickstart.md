# 等待到位

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

等一根轴**真的走到位置**。默认判据是设备状态快照里的 `InPosition` 与 `Moving` 两个位同时成立
（已到位、且不在运动中）；也可以显式给 `Target` + `Tolerance`，改按"位置落在容差内且已停下"判。
产出 `Position`（到位位置，mm）与 `Elapsed`（等待耗时，ms）。
它是运动链路的第四环，也是「轴运动」的必配搭档：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 本步骤 ──▶ 读轴状态 / 轴卡 IO / 轴停止`

## 跑通第一次：5 步

1. 前面放一步「轴运动」（目标与速度都在那里给）。**不要**指望运动步骤自己等 —— 运动是异步下发的。
2. 放本步骤，`Axis` 填与上游**同一个轴名**；推荐直接把「轴运动」的 `Axis` 输出链过来，避免手抄错字。
   `Target` 默认是 `NaN`（沿用设备到位信号），**老流程不用动它**；只有卡不报 `InPosition` 时才填目标位置，
   并把 `Tolerance` 设成机构能接受的位置误差（默认 0.05 mm）。
3. 按"行程(mm) ÷ 速度(mm/s)"估这段行程的正常耗时，超时给"最长合理耗时 × 2 + 1000 ms"。
   默认 `TimeoutMs` = 30000，短行程小机构一般不用动。
4. 跑一次：正常应看到本步骤成功，`Position` 等于（或极接近）目标值，`Elapsed` 与你的估算同量级。
5. 下游要用到位位置或耗时的，接 `Position` / `Elapsed` 去「变量赋值」或「数据记录」，别再补一步「读轴状态」。

## 跑通后该看到什么

- 成功日志一行：`轴「X」已到位：20.000 mm（耗时 138 ms）`（行首是步骤实例名）。
  显式目标模式会多出目标与偏差：`轴「X」已到位：20.000 mm（目标 20.000 mm ±0.050 mm，偏差 0.000 mm，耗时 138 ms）`。
- `Success = true`、`Position` = 到位位置（mm）、`Elapsed` = 实际耗时（ms）。
- 六种非正常出口（目标非法 / 超时 / 期间硬信号 / 卡进报警或安全停机 / 快照读不到 / 流程被停止）都是 `Success = false`，
  `ErrorMessage` 给出原因原文——每条报错原文的含义与处置见《排障》页。

## 为什么它是独立步骤（而不是让「轴运动」自己等）

产线上大量场景要"两轴同时运动"。如果运动步骤内部阻塞等到位，两条轴就只能串行——
现场会发现"节拍莫名慢了一倍"，却极难看出原因。把"下发"与"等待"拆开，
用户才能显式表达自己的意图：先都下发、再各自等待。

## 原理（每条一句话）

- **等的是设备状态，不是"某条命令的完成信号"**。命令对象不跨步骤传递（那会让流程依赖对象身份、
  无法保存与重放），而"这根轴现在到没到位"是设备上随时可查的事实。
- **两种判据，默认行为与升级前一致**：`Target` 默认 `NaN` → 只认 `InPosition && !Moving`；
  `Target` 填了有限数值 → 只认 `!Moving && |PositionMm - Target| <= Tolerance`（**不要求** `InPosition`，
  有些卡/仿真器的到位位没有驱动）。旧流程存档里没有 `Target` 键，端口保持默认 `NaN`，行为一个字都不变。
- **读的是轮询快照，不发起通信**。轴状态由这张卡的轮询线程按卡级轮询间隔（默认 10 ms）统一刷新，
  本步骤只是"隔一会儿去看一眼最新那份"。所以它不占用通信带宽。
- **报警/限位优先于"到位"**。轴在报警或撞限位时，位置可能恰好停在目标附近，
  只看 `InPosition` 会把"撞停"当成"走到位"。每轮先查硬信号（急停输入 / 正限位 / 负限位 / 报警），任一命中直接判失败。
- **卡状态快检**：每轮先看 `device.State`，一旦变成报警 / 安全停机 / 断开 / 连接中，立即失败并给出卡的状态说明，
  不会继续等到超时。
- **超时是失败，不算"走完了"**：`走不到` 与 `走得慢` 必须能区分开。
- **流程停止能立刻退出**：取消判断优先于一切，等待间隔本身也是可中断的，不会傻等满超时。

## 端口与参数速览（细节见《端口与参数》页）

| 端口 / 参数 | 方向 | 默认 | 一句话含义 |
| --- | --- | --- | --- |
| `Axis` | 输入（可链接） | `X` | 逻辑轴名，下拉候选来自「运动卡设置」里已启用的轴 |
| `Target` | 输入（可链接） | `NaN` | 目标位置 mm；**默认 NaN = 沿用设备 InPosition 语义**，填有限数值才启用位置判据 |
| `Tolerance` | 输入（可链接） | `0.05` | 到位容差 mm，只在 Target 有值时生效；负数按绝对值，NaN/∞ 回退 0.05 |
| `TimeoutMs` | 配置项 | `30000` | 等待超时 ms（≤0 的值按 1 处理）。当前界面上没有它的编辑入口，见端口页说明 |
| `PollIntervalMs` | 配置项 | `20` | 每轮查看快照的间隔 ms，实际取值被夹到 `1~500` |
| `Position` | 输出 | — | 结束时刻轴位置（mm，指令位置）；正常到位与超时都写；步骤开头先清 `0` |
| `Elapsed` | 输出 | — | 进入等待到结束的耗时（ms），超时时写实际等了多久 |
| `Success` / `ErrorMessage` | 输出 | — | 每个步骤都有的成败与原因原文 |

## 典型接线

```
标准四步（最常见）：
  轴使能(X) ──▶ 轴回零(X) ──▶ 轴运动(X) ──▶ 本步骤(X) ──▶ 轴卡 IO(OUT0=ON)
                                                  │
                                    Axis ◀────────┘（直接链「轴运动」的 Axis 输出）

两轴同时运动 + 各自等待：
  轴运动(X) ──┐
              ├──▶ 本步骤(X) ──┐
  轴运动(Y) ──┘   本步骤(Y) ──┴──▶ 读轴状态 / 下一步

收尾确认（「轴停止」之后）：
  轴停止(X) ──▶ 本步骤(X)（超时给小一点）或 读轴状态(X) 看 Moving=false
```

## 常见问题（速答）

**Q：本步骤秒过（`Elapsed` 只有几 ms），但轴明明还在路上？**
判据是设备状态，不是"这条命令的结果"。要么轴本来就已经停在目标附近（这一轮目标位置没变），
要么前面的「轴运动」其实失败了、根本没下发。先回看上游运动步骤本轮的 `Success`，
再看 `Position` 是不是你以为的目标值。详见《排障》页。

**Q：真机等得到了，仿真里却总是立刻返回？**
虚拟运动卡按每拍匀速推进模拟异步运动，目标与当前位置相同时直接判到位。
仿真的节拍不等于真机节拍——用仿真验**逻辑顺序**（有没有少放等待），不要用它定超时数值。

**Q：卡不报 `InPosition`（例如正运动 0x800 位没驱动），旧语义永远等不到怎么办？**
把 `Target` 填成本次的目标位置（mm）、`Tolerance` 按机构精度填（默认 0.05 mm）。
此时判据变成"轴停下且位置落在容差内"，**不再依赖** `InPosition`。
注意 `Target` 必须填**这一轮真正要到的位置**：填错目标会表现为"到了也一直等到超时"。

**Q：超时了，位置显示差一点点。**
先分清"没走完"还是"走完了但卡没报到位"：差得远是速度过低/行程过长/被中途停止；
差一点点却是到位信号没起来，通常是到位判断条件（跟随误差窗口、到位带宽）在控制器/驱动器侧设得太严，
去厂商软件里调该轴的到位参数，而不是把流程超时加大。
如果是显式目标模式，报错里会直接给出"目标 / 容差 / 偏差"三个数：偏差 > 容差就是真的没到，
偏差 <= 容差却仍超时，说明轴还在 `Moving`（没停稳）或卡状态已经变了。

**Q：等待期间报异常信号——明明刚才是好的。**
等待过程中卡持续采样，急停按钮被按下、限位被压到、伺服报警都会在这一步暴露。
这是它**该有的表现**：报警优先于到位，宁可报错也不把撞停当到位传给下一步。

**Q：`PollIntervalMs` 改大有没有副作用？**
有，但不是通信：它决定"最快多快能发现到位"。给到 500 ms 时，最坏多等半秒才发现到位，
短行程高精节拍下这半秒就是产能。卡级轮询不受它影响。

**Q：多条轴各放一步等待，会不会互相拖累？**
不会互相"等"，但同一张卡上的**命令**是排队执行的（下发快、执行逐条）。
本步骤只是观察结果，不占用命令队列；两个轴的动作要真并行，请放到不同卡。
