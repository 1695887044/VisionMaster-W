# 等待到位：端口与参数

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

这一页只回答三件事：**每个口怎么填、填错/接不上会怎样、这些值最后存在哪儿**。
为什么要有这一步、和「轴运动」怎么配对，见《等待到位》首页，本页不重复。

## 一、参数面板长什么样

本步骤**没有自定义配置界面**，双击步骤后由框架自动生成参数清单，清单**只列输入端口**：

| 界面元素 | 本步骤看到的内容 |
| --- | --- |
| 行 | 只有一个输入端口一行：`Axis` |
| 值框 | `Axis` 呈现为**下拉**（候选 = 当前方案里已启用的轴） |
| 🔗 图标 | 把这一行的值改成"由上游变量给出"（推荐：直接链「轴运动」的 `Axis` 输出） |
| ✕ 图标 | 清除链接（也清掉常量），回落到步骤声明的默认值 `X` |

面板顶部提示条原文：**「该步骤没有自定义配置界面，参数如下：没有绑定需求时直接填入常量，
需要连上游变量就点右侧的链接图标。」**

**取值优先级**：上游链接值 ＞ 界面手填常量 ＞ 步骤声明的默认值。
一次执行内取值只在开头做一次，整步用同一个值，避免中途改常量框导致前后判断标准不一致。

## 二、输入端口逐个

| 端口（也是存档键） | 类型 | 必填 | 默认值 | 合法取值 / 填法 | 接不上或填错会怎样 |
| --- | --- | --- | --- | --- | --- |
| `Axis` | 字符串（逻辑轴名） | 否 | `X` | 下拉候选来自「系统 → 运动卡设置」里**已启用**的轴，也可直接手填；可由上游变量给出 | 解析不出轴 → 步骤失败，原因文本由轴名解析器给出（见排障页），**不会**自己去猜别的卡 |

`Axis` 标了 `IsRequired = false`：**没连上游也不会被判编译失败**（老流程只填常量照样能跑）。

## 三、配置项（`[StepConfig]`）逐个

| 属性 | 默认 | 代码里的处理 | 说明 |
| --- | --- | --- | --- |
| `TimeoutMs` | `30000` | `Math.Max(1, TimeoutMs)`：填 0 或负数按 **1 ms** 跑，基本上一轮就报超时 | 等待超时（ms）。超时即判失败——"走不到"与"走得慢"必须能区分 |
| `PollIntervalMs` | `20` | `Math.Clamp(PollIntervalMs, 1, 500)`：填 1000 也只按 **500** 跑，填 0 按 1 | 每轮查看快照的间隔（ms）。**不改变通信量**（读的是快照），只决定"最快多快能发现变化" |

**为什么这两项界面上改不了**：本插件没有自定义视图，参数面板只渲染输入端口，
标成 `[StepConfig]` 的配置项在这张面板上**没有渲染形态 = 界面上没有编辑入口**。
实际生效的是默认值/流程存档值；要调超时或轮询频率，需在流程存档里改该步骤的属性值
（按属性名 `TimeoutMs` / `PollIntervalMs` 保存）。这是当前界面欠账，不是设计意图——
补了自定义视图或面板形态之后，本页与排障页的相关说法要同步更新。

## 四、输出端口与下游怎么用

| 端口 | 类型 | 什么时候被写 | 典型消费方 |
| --- | --- | --- | --- |
| `Position` | 浮点（mm） | 步骤开头先清 `0`；**正常到位**与**超时**两种结束都写；硬信号失败 / 快照读不到 / 被流程停止**不写**（保持 0） | 「变量赋值」「数据记录」、条件判断（比对目标位置） |
| `Elapsed` | 整数（ms） | 同上（超时时写实际已等的时长） | 「数据记录」——单件耗时，用于发现节拍漂移 |
| `Success` | 布尔 | 每个步骤都有：除正常到位外全为 `false` | 条件分支（If / While） |
| `ErrorMessage` | 字符串 | 每个步骤都有：失败原因原文 | 接「数据记录」或报警上报 |

注意两处名字口径：
- 耗时输出的**属性名是 `ElapsedMs`，端口名是 `Elapsed`**——下游引用与界面都以端口名为准，别按属性名找。
- `Position` 写的是**指令位置**（驱动侧已按脉冲当量换算成 mm），不是编码器实际位置；
  两者在跟随误差、丢步、被外力推动时会分叉。

## 五、这些值最后存在哪儿

- `Axis` 的常量落在**步骤**的配置里（`.vms` 中该步骤的 `InputValues`），**键名 = 端口名** `Axis`；
  链接成 🔗 后确认时**移除**该键的常量值，运行时以链接为准。轴名存**名字本身**，不存卡地址、不存物理轴号。
- `TimeoutMs` / `PollIntervalMs` 按属性名落在该步骤的配置段中（界面无编辑入口，一般只有手工改存档才会出现非默认值）。
- 换卡、改接线只动「运动卡设置」里的轴映射，本步骤存档的轴名不用改。

## 六、口径速查

- **单位**：`Position` 是 **mm**，`TimeoutMs` / `Elapsed` / `PollIntervalMs` 是毫秒。不涉及速度。
- **坐标系基准**：绝对运动的基准是「轴回零」建立的零点；本步骤只读回来，不做任何换算。
- **卡级轮询 vs 本步骤轮询**：快照由卡的轮询线程按卡级 `PollIntervalMs`（「运动卡设置」里配，默认 10 ms）刷新；
  本步骤的配置项 `PollIntervalMs` 只管"多久去看一眼"。两者独立，把它设得比卡级还小只是空转。
- **每种结束情形的表现**：
  | 结束情形 | `Success` | `Position` / `Elapsed` |
  | --- | --- | --- |
  | 正常到位（`InPosition` 且非 `Moving`） | true | 到位位置 / 实际耗时 |
  | 超时 | false | 超时瞬间的位置 / 已等时长（报错原文带当前位置） |
  | 期间出现硬信号（急停/正限位/负限位/报警） | false | 不写（保持开头的 0） |
  | 快照读不到（卡断开或还没轮询到） | false | 不写 |
  | 流程被停止 | false | 不写 |
- **它不等"别人"**：只等 `Axis` 指定的那一根轴，多轴各放一步。
