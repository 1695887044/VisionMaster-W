# 等待到位：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面上真会出现的原文**（从源码逐字抄），按"现象 → 为什么 → 怎么改"排。
本步骤有八种失败出口，先看分流表，再按行往下查。

## 一、先看挂在哪一环

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ⓪ 参数 | `目标位置 … 不是有效数字：…` | `Target` 填了 ±∞（`NaN` 是合法的"沿用旧语义"，不算错误） |
| ① 轴名解析 | `没有指定轴名：…` / `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 还没碰卡，纯配置问题 |
| ② 服务与设备 | `运动卡服务尚未就绪：…` / `找不到运动卡「…」的运行态设备：…` | 宿主没注入服务 / 配置改了没同步 |
| ③ 卡状态 | `等待轴「…」期间运动卡不可用（…）：…` | 等待期间卡进报警 / 安全停机 / 断开 / 连接中 |
| ④ 快照读不到 | `读不到轴「…」的状态：运动卡「…」可能已断开（…）` | 卡断开、或还没轮询到第一轮 |
| ⑤ 硬信号 | `等待轴「…」期间出现异常信号：…` | 等待期间报警 / 限位 / 急停被采样到 |
| ⑥ 超时 | `等待轴「…」到位超时（>… ms，…当前位置 … mm）：…` | 到点没等到"到位且静止"（显式模式还会带目标/容差/偏差） |
| ⑦ 流程停止 | `等待轴「…」到位时被中断（流程已停止）` | 预期行为，不是故障 |

## 二、逐条

**`目标位置 Infinity 不是有效数字：请填有限数值，或填 NaN 沿用设备到位信号`**
为什么：`Target` 被填成 `±∞`。`NaN` 是**合法**的（表示"沿用设备 InPosition 语义"），
但无穷大不是坐标，无法算偏差。
怎么改：填一个有限的目标位置；要回到旧语义就把 `Target` 填成 `NaN`（或保持端口默认值）。

**`没有指定轴名：请在「Axis」端口填轴名（或用下拉选一个），也可由上游变量给出`**
为什么：`Axis` 的实际生效值是空白（手填框被清空，或上游变量给出空串）。
怎么改：在参数面板重新选一个轴；这一行挂着链接时，先查上游变量本轮到底是什么值——
链接值优先级高于手填值，手填再对也不生效。

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是**全局唯一**的对外标识，注册表里查不到就是配置里没这个名字（改名、删卡、换方案都会）。
怎么改：核对「系统 → 运动卡设置」里的轴名；大小写不敏感但**字面必须一致**——
`Al`（字母 L）与 `A1`、`上料轴` 与 `上料 轴`（多一个空格）都算两个名字。

**`轴「X」在卡「…」上处于停用状态：请到「运动卡设置」把它启用，或换一个轴名`**
为什么：轴映射里 `Enabled = false`（未接电机的轴可以关掉，就是为了让流程误用不了）。
怎么改：确认这根轴确实接了驱动器再启用，否则换成实际接线对应的那根轴名。

**`运动卡服务尚未就绪：请在主程序内运行流程`**
为什么：这条只在**没有注入运动卡服务**的宿主里出现（设计器/离线宿主单独跑流程）。
怎么改：在主程序里运行（试运行与正式运行都注入同一个服务）。

**`等待轴「X」期间运动卡不可用（SafeStopped）：命令失败：…`**
为什么：等待期间卡进了报警 / 安全停机 / 断开 / 连接中。括号里是卡状态成员名
（`Alarm` / `SafeStopped` / `Closed` / `Connecting`），冒号后面是卡的 `StateDetail`。
本步骤每轮先看卡状态，命中就**立刻失败**，不会继续等到超时——轴已经不可信了，再等只是浪费节拍。
怎么改：按冒号后面的说明处理（清报警、排查通信/看门狗、重新连接）；恢复后重跑这一步。
不要靠加大超时"等它自己好"。

**`读不到轴「X」的状态：运动卡「运动卡1」可能已断开（括号内是卡的状态说明原文）`**
为什么：`GetAxisStatus` 返回空——这张卡连快照都拿不到（还没轮询到第一轮，或已断开/安全停机）。
怎么改：去「运动卡设置」或调试面板看卡状态与说明；反复出现就查通信（网线/供电/网段）
与卡级看门狗参数。括号里附的就是卡的 `StateDetail`，先按那句话定位。

**`等待轴「X」期间出现异常信号：报警：伺服报警（建议：…）`**
为什么：等待期间卡持续采样，急停按钮被按下、限位被压到、伺服报警都会命中这一条。
冒号后面是状态快照的一句话描述，括号里（如有）是故障记录附带的建议。
**这是它该有的表现**：硬信号优先于"到位"——宁可报错，也不把"撞停"当成"走到位"传给下一步。
怎么改：按建议处理（清报警、检查急停回路、核对是否压在限位上），恢复后再跑。
不要试图给本步骤加"忽略报警"的开关——没有这个开关，也不该有。

**`等待轴「X」到位超时（>30000 ms，当前位置 12.345 mm）：请检查目标是否超出行程、速度是否过低，或该轴是否被限位/报警阻挡`**
**`等待轴「X」到位超时（>30000 ms，目标 30.000 mm ±0.050 mm，偏差 10.000 mm，当前位置 20.000 mm）：…`**
为什么：到点没等到"到位且静止"。第一条是旧语义（`Target=NaN`），第二条是显式目标模式
（`Target` 有值，报错里直接给出目标 / 容差 / 偏差）。报错里带了超时瞬间的位置，先拿它和目标比：
① 差得远——速度过低、行程过长、或运动中途被停止过（回看「轴运动」本轮的 `Success`）；
② 只差一点点——到位信号没起来，通常是到位判断条件（跟随误差窗口、到位带宽）在控制器/驱动器侧设得太严，
去厂商软件调该轴的到位参数，**而不是**把流程超时加大；
③ 显式模式下偏差 <= 容差却仍超时——轴还在 `Moving`（没停稳），或卡状态已经变了（看上一条）。
怎么改：超时按"行程 ÷ 速度 × 2 + 1000 ms"重估。注意配置项被代码夹过下限（0/负数按 1 ms），
改存档时别把它改成 0——那等于"每轮必超时"。

**`等待轴「X」到位时被中断（流程已停止）`**
为什么：用户停止/流程取消，本步骤第一优先退出，不等满超时。预期行为，不是故障。

## 三、"现象对不上"这一类

**本步骤秒过（`Elapsed` 只有几 ms），但轴明明还在路上**
判据是设备状态，不是"这条命令的结果"。两种可能：
① 轴本来就停在目标附近（这一轮目标位置没变），`InPosition` 一直为真；
② 前面的「轴运动」其实失败了、根本没下发，这里读到的是"静止且到位"。
先回看上游运动步骤本轮的 `Success`，再看 `Position` 是不是你以为的目标值。
（守门断言「★Move 下发成功 ≠ 已到位（命令已 Done，但轴仍在途中）」钉的就是"下发与到位是两件事"，
本步骤存在的意义就是等第二件事。）

**真机等到了，仿真里总是立刻返回**
虚拟运动卡按每拍匀速推进，目标与当前位置相同直接判到位；仿真推进是 200 ms 量级的。
用仿真验**逻辑顺序**（有没有少放这一步），不要用它定超时数值。

**超时那次 `Position` 是 0**
看结束情形表：超时**会**写当前位置；写 0 的是"硬信号失败 / 卡状态失败 / 快照读不到 / 被流程停止"这四种
（步骤开头清零后没来得及写）。也就是说：`Position=0` 且报的是超时以外的错误，说明根本没读到有效位置。

**用「读轴状态」定位，比反复点运行快**
在等待前后各插一步「读轴状态」，把 `Moving` / `InPosition` / `Status` 连去「数据记录」，
一次运行就能看出是"轴没在动"还是"一直在动没等到信号"。
