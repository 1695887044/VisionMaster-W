# 轴停止

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

中止一次运动：可以只停一根轴，也可以**留空轴名停掉所有卡的全部轴**；
还可以走"急停"通道（清空待执行命令 + 打断当前命令 + 立即停）。产出是 `Accepted`。

它在链路里是**安全出口**，出现在两个位置 —— 异常分支和中止分支：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态`
                    `异常/条件判断 ──▶ 本步骤 ──▶ 轴卡 IO（松开）/ 报警输出`

## 为什么需要它 / 原理

- **两种停止必须分清（安全相关，不是口味问题）**：
  | 模式 | 存档成员名 | 界面显示 | 行为 | 用在什么场合 |
  | --- | --- | --- | --- | --- |
  | 减速停（默认） | `Decelerate` | 减速停 | 按减速曲线停下来，对机械冲击小 | 正常中断一次运动、换型、到位后收尾 |
  | 立即停 | `Immediate` | 立即停（急停/限位） | 直接取消当前运动，不走完减速段 | 已经出事、需要最短停止距离 |

  界面显示中文，**流程存档的是成员名**，改显示名不会断连线。这两个数字与正运动 SDK 的取消模式一致
  （`2`=减速停、`3`=立即停），落到卡上就是 `Single_Cancel(轴, 模式)`。
- **本步骤不等待停止完成**。停止本身要尽快返回；"等它停稳"是下一步的事
  —— 需要确认就在后面跟「读轴状态」（看 `Moving=false`）或「等待到位」。
- **普通停止是"打断当前那一条"，不是排队等**。命令线程逐条执行，而回零这类命令要跑几十秒；
  如果"停止"老老实实排在它后面，等轮到它时轴早就自己走完了，那样的停止毫无意义。
  所以停止/失能属于**打断性命令**：入队即打断正在执行的那条（但不清队列，其它命令照旧排队）。
- **急停是更重的路径**，勾上 `UseEmergencyStop` 后走设备的急停通道：
  ① 清空待执行队列（急停之后还去执行之前排队的运动是危险的），② 插队一条"停全部轴 + 立即停"，
  ③ 打断当前正在执行的命令。**此时 `Axis` 与 `Mode` 都被忽略** —— 急停的语义就是"全停下来，别排队"。
- **软件急停不是安全回路**。真正的安全急停必须由硬件回路（急停按钮直接切伺服使能）保证，
  这条软件路径只是补充。描述里就把这句话写在了插件名旁边。
- **被打断的命令不算设备故障**：急停打断导致的"命令被取消"是预期行为，
  软件刻意不把它记成故障、也不因此把卡打进安全停机。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Axis` | 否 | 逻辑轴名，默认**空**。填了 → 只停这一根轴（按名解析出卡+轴号）；**留空 → 停所有卡的全部轴**（下拉候选来自「运动卡设置」里已启用的轴，可被上游变量给出） |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Accepted` | 停止命令是否被接受（开头先清 `false`）。急停模式下只要每张目标卡的急停通道都放行才置 true |
| `Success` | 本步骤是否成功（每个步骤都有） |
| `ErrorMessage` | 失败原因原文（每个步骤都有） |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Axis` | 空（= 停全部轴） | **输入端口**：界面上可改、可被上游链接。这是最常用的开关 —— 一个端口决定"单轴停"还是"全停" |
| `Mode` | `Decelerate`（减速停） | 停止方式，枚举见上表。当前是步骤的**配置属性**，本插件没有自定义配置界面、参数面板只列输入端口，所以界面上暂无编辑入口，实际以默认值/存档值为准；勾了急停时它被忽略 |
| `UseEmergencyStop` | `false` | 是否走急停通道。同为配置属性（同上，暂无界面入口）。true 时 `Axis` 与 `Mode` 都被忽略 |

> 停全部轴**不需要**指定卡：设备集合是从"确实被流程解析到过"的卡推出来的，
> 不会出现"配置里有但设备没建起来"的空引用；当前一张可用卡都没有时报
> `当前没有任何可用的运动卡：请到「运动卡设置」配置并连接至少一张卡`。

## 口径与失败策略

- **单位**：本步骤没有位置/速度参数，只有模式选择；命令超时取该卡的 `CommandTimeoutMs`（卡级默认 30000 ms），
  但因为 `WaitsForCompletion=false`，本步骤不会用它去等停稳。
- **停全部轴的口径**：向每张卡下发一条"物理轴号 = -1"的停止命令（契约约定 -1 表示全部轴）。
  正运动卡没有"停所有轴"的单一调用，驱动会**逐个已启用的轴**下取消；
  只要有一个轴下发失败，这条命令就报 `部分轴停止命令下发失败：X(码 …)` 并判失败。
  注意只遍历"已启用"的轴 —— 用户在映射里明确关掉的轴不会被操作。
- **卡状态门禁（现场最容易踩的一条）**：
  普通停止走命令队列，**要求卡「在线」**。报警态下会被拒：`运动卡处于报警状态，请先清除报警`；
  未连接/连接中/已安全停机分别给出对应原因。
  急停通道更宽：**「在线」与「报警」两种状态都放行**（出事时正是需要它的时候），
  其余状态返回 `Rejected_NotConnected`（括号里就是这个名字，冒号后面是状态说明原文）。
  所以"报警了想停轴"请勾急停，或者先清报警 —— 普通停在报警态是发不进去的。
- **算不算流程失败**：算。轴名填了但解析不到（报错会补一句 `（若要停全部轴，请把轴名留空）`）、
  没有任何可用卡、命令被拒绝、急停被拒绝，都会 `Success=false`。
- **Accepted=true 不等于已经停住**：它只代表命令进了通道/队列。停稳与否要用「读轴状态」确认，
  尤其是急停后想接着做别的事时。
- **停止之后不会自动重新使能**：轴停在原地但使能状态不变；急停打断的运动要重新运动需再下一次命令，
  若中途做过失能则要先「轴使能」。

## 典型用法 / 接线

```
正常收尾（走完一段动作后停住，保持使能）：
  轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=OFF 松开) ──▶ 本步骤(X，减速停)

异常分支（等待超时/读到报警时立刻停）：
  等待到位(X) ── Success=false ──▶ 本步骤(X) ──▶ 报警输出 ──▶ 流程结束
  读轴状态(X) ── Alarm=true ──────▶ 本步骤(X)

换型 / 全线安全停（轴名留空 = 停所有卡的全部轴）：
  条件判断(换型信号) ──▶ 本步骤（Axis=空）──▶ 读轴状态(X) 确认 Moving=false

班末下电顺序：
  本步骤（Axis=空，先停）──▶ 轴使能(X, Enable=false) ──▶ 轴使能(Y, Enable=false)
```

选择口径：**中断一根轴** → 填轴名 + 减速停；**出事** → 勾急停（全停、清队、立即停）；
**只断某根轴的电** → 用「轴使能」的 `Enable=false`（它内部会先补一次减速停），别用本步骤代替。

## 常见问题

**Q：流程里放了本步骤，但轴好像还在走？**
① 本步骤不等停稳，`Accepted=true` 只代表命令被接受 —— 停稳要另外确认（「读轴状态」看 `Moving`）；
② 检查是否只停了 A 轴而 B 轴还在动（`Axis` 只作用一根轴，要全停请把轴名留空）；
③ 卡是否已进「报警」——软件发现报警/限位/急停输入时**已经自动做过一次急停**（队列清空、全部轴立即停），
   此时普通停止会被拒（`运动卡处于报警状态，请先清除报警`），要停就只能勾急停。

**Q：`对运动卡「…」的急停命令被拒绝（被拒绝：该卡未连接…）：…`？**
急停通道虽然允许「在线」与「报警」，但「未连接」「连接中」「已安全停机」仍然拒绝。
卡真断连时软件发不出任何东西 —— 这正是硬件急停回路必须存在的原因，软件路径不能替代它。

**Q：报警态下想停轴，为什么普通停止被拒？**
门禁对命令队列一律要求「在线」，只有清报警和急停两条通道在报警态放行。
报警态要停 → 勾 `UseEmergencyStop`；报警态要恢复 → 先清报警（正运动清报警**不会自动使能**，
清完还要补一步「轴使能」）。

**Q：减速停和立即停怎么选？**
减速停用于"计划内的中断"（工艺要求提前结束本段运动），对机械与联轴器冲击小；
立即停用于"必须最短距离停下"（撞到人/件、位置已经明显不对）。
带竖直轴或搬运中的夹具时谨慎用立即停：不减速的停止可能让重物继续下行或工件滑出。

**Q：停完之后要不要重新回零？**
不一定：停止不会破坏零点（软件记录的"已回零"标记不变）。
但如果这次停止是**撞限位、报警、失能、断电**造成的，位置的可信度已经下降，
建议把这根轴重新走一次「轴回零」再按绝对坐标运动。

**Q：`停止命令被拒绝（被拒绝：参数无效）：轴号 4 超出范围（本卡 4 轴）`这类报错？**
这是映射与卡能力不一致：轴映射里填的物理轴号（**0 基**）超出了这张卡上报的轴数。
去「运动卡设置」核对机型与轴号；如果机型不认识（日志会警告"未识别机型"），能力是按兜底值给的，
先把机型栏填成准确型号（如 `ECI3428` / `ECI3828` / `ZMC408SCAN` / `VPLC532R`）。

**Q：能不能把本步骤当流程的"总停"按钮绑到界面上？**
可以，写法是：`Axis` 留空 + 勾急停。但请不要把它当安全件：
它依赖软件在跑、卡还在通信；硬件急停回路该断的电必须自己断。
