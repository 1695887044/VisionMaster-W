# 轴停止

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

中止一次运动。三种形态由**一个端口 + 两个配置项**决定：
填轴名 = 停这一根轴；轴名留空 = **停所有卡的全部轴**；勾急停 = 清空待执行命令 + 打断当前命令 + 立即停。
产出是 `Accepted`（命令是否被接受）。它在链路里是**安全出口**，出现在异常分支和中止分支：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态`
`异常/条件判断 ──▶ 本步骤 ──▶ 轴卡 IO（松开）/ 报警输出`

## 跑通第一次：4 步

1. 在需要"叫停"的分支后面放本步骤（比如「等待到位」`Success=false` 的分支）。
2. `Axis` 填要停的那根轴的轴名；要做"全线停"就**留空**（留空不需要选卡，它停的是所有已接入的卡）。
3. 想要最短停止距离就勾急停（`UseEmergencyStop`）；计划内的中断保持默认 `Decelerate`（减速停）。
   注意：这两个配置项当前在参数面板上**没有编辑入口**（本步骤无自定义视图），改法见《端口与参数》页。
4. 跑一次，看 `Accepted=true`。然后补一步「读轴状态」确认 `Moving=false`——本步骤**不等停稳**。

## 跑通后该看到什么

- 成功日志：`已下发：…`（命令的一行描述）；勾了急停则是 Warn 级
  `已对运动卡「…」下发急停（清空待执行命令 + 立即停全部轴）`。
- `Success=true`、`Accepted=true`。**`Accepted=true` 不等于已经停住**——它只代表命令进了通道/队列。

## 两种"普通停止"必须分清（安全相关，不是口味问题）

| 模式 | 存档成员名 | 显示名 | 行为 | 用在什么场合 |
| --- | --- | --- | --- | --- |
| 减速停（默认） | `Decelerate` | 减速停 | 按减速曲线停下来，对机械冲击小 | 正常中断一次运动、换型、到位后收尾 |
| 立即停 | `Immediate` | 立即停（急停/限位） | 直接取消当前运动，不走完减速段 | 已经出事、需要最短停止距离 |

存档与流程里认的是**成员名**，改显示名不会断连线。两个模式的数值（2 与 3）与正运动 SDK 的取消模式一致，
落到真卡上就是 `Single_Cancel(轴, 模式)`；映射写在驱动侧，流程层只见成员名。

## 原理（每条一句话）

- **本步骤不等待停止完成**。停止要尽快返回；"等它停稳"是下一步的事（后面跟「读轴状态」或「等待到位」）。
- **普通停止是"打断当前那一条"，不是排队等**。命令线程逐条执行，回零这类要跑几十秒；
  若"停止"老实排在它后面，轮到它时轴早走完了。所以停止属于**打断性命令**：入队即打断正在执行的那条（但不清队列）。
- **急停是更重的路径**：清空待执行队列 + 插队一条"停全部轴 + 立即停" + 打断当前命令。
  勾上后 `Mode` 被忽略；`Axis` 不再决定"停哪根轴"（急停总是停掉目标卡上的全部轴），
  但仍决定**打哪几张卡**——填了轴名只急停该轴所在的卡，留空则所有卡逐张急停。
- **软件急停不是安全回路**。真正的安全急停必须由硬件回路（急停按钮直接切伺服使能）保证，
  插件描述里就把这句话写在名字旁边。
- **被打断的命令不算设备故障**：急停造成的"命令被取消"是预期行为，软件刻意不记故障、也不因此把卡打进安全停机。

## 端口与参数速览（细节见《端口与参数》页）

| 端口 / 参数 | 方向 | 默认 | 一句话含义 |
| --- | --- | --- | --- |
| `Axis` | 输入（可链接） | **空（= 停全部轴）** | 填=停这一根轴；空=停所有卡的全部轴。这是最常用的开关 |
| `Mode` | 配置项 | `Decelerate` | 减速停 / 立即停；勾急停时被忽略 |
| `UseEmergencyStop` | 配置项 | `false` | 是否走急停通道（清队 + 打断 + 立即停全部轴） |
| `Accepted` | 输出 | — | 停止命令是否被接受（开头先清 `false`；急停模式下每张目标卡都放行才置 `true`） |
| `Success` / `ErrorMessage` | 输出 | — | 每个步骤都有 |

## 典型接线

```
正常收尾（走完一段动作后停住，保持使能）：
  轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=OFF 松开) ──▶ 本步骤(X，减速停)

异常分支（等待超时/读到报警时立刻停）：
  等待到位(X) ── Success=false ──▶ 本步骤(X) ──▶ 报警输出 ──▶ 流程结束
  读轴状态(X) ── Alarm=true ──────▶ 本步骤(X)

换型 / 全线安全停（轴名留空 = 停所有卡的全部轴）：
  条件判断(换型信号) ──▶ 本步骤（Axis=空）──▶ 读轴状态(X) 确认 Moving=false

班末下电顺序：
  本步骤（Axis=空，先停）──▶ 轴使能(X, Enable=false) ──▶ 轴使能(Y, Enable=false)
```

选择口径：**中断一根轴** → 填轴名 + 减速停；**出事** → 勾急停；**只断某根轴的电** →
用「轴使能」的 `Enable=false`（它内部先补一次减速停），别用本步骤代替。

## 常见问题（速答）

**Q：放了本步骤，但轴好像还在走？**
① 本步骤不等停稳，`Accepted=true` 只代表命令被接受，停稳要用「读轴状态」确认；
② 是不是只停了 A 轴而 B 轴还在动（要全停请把轴名留空）；
③ 卡是否已进「报警」——软件发现硬信号时**已经自动做过一次急停**，此时普通停止会被拒
（`运动卡处于报警状态，请先清除报警`），要停只能勾急停。

**Q：报警态下想停轴，为什么普通停止被拒？**
命令队列一律要求卡「在线」，只有清报警和急停两条通道在报警态放行。
报警态要停 → 勾 `UseEmergencyStop`；报警态要恢复 → 先清报警（清报警**不会自动使能**，清完还要补一步「轴使能」）。

**Q：停完之后要不要重新回零？**
不一定：停止不破坏零点。但如果这次停止是**撞限位、报警、失能、断电**造成的，位置可信度已下降，
建议把这根轴重新走一次「轴回零」再按绝对坐标运动。

**Q：带竖直轴能用立即停吗？**
谨慎：不减速的停止可能让重物继续下行或工件滑出。计划内的中断一律减速停。
