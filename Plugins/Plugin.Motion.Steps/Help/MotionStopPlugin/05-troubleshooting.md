# 轴停止：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面上真会出现的原文**（从源码逐字抄），按"现象 → 为什么 → 怎么改"排。
括号里是命令结果的枚举**成员名**（如 `Rejected_NotConnected`），冒号后面才是真正的原因。

## 一、先看挂在哪一环

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 轴名解析 | `没有指定轴名…（若要停全部轴，请把轴名留空）` 之外的 `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 填了名字但解析不到 |
| ② 服务与卡集合 | `运动卡服务尚未就绪：…` / `当前没有任何可用的运动卡：…` | 宿主没注入服务 / 一张可解析的卡都没有 |
| ③ 急停通道 | `对运动卡「…」的急停命令被拒绝（Rejected_NotConnected）：…` | 卡状态不允许急停（非在线且非报警） |
| ④ 停止入队 | `停止命令被拒绝（Rejected_…）：…` | 基类闸门拦下（报警态、未连接、轴号越界等） |

## 二、逐条

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是**全局唯一**的对外标识，注册表查不到就是配置里没这个名字（改名、删卡、换方案都会）。
怎么改：核对轴名；大小写不敏感但字面必须一致（`Al` 与 `A1`、多一个空格都算两个名字）。
若本轮想做的就是"全停"——把 `Axis` **留空**，不要填通配符。

**`当前没有任何可用的运动卡：请到「运动卡设置」配置并连接至少一张卡`**
为什么：`Axis` 留空（全停形态），但设备集合是空的——方案里没有已接入的运动卡，
或配置改了还没同步到运行态。怎么改：先按《轴使能》排障页同步配置；确认卡存在后重试。

**`停止命令被拒绝（Rejected_NotConnected）：运动卡处于报警状态，请先清除报警`**
为什么：普通停止走命令队列，闸门对**除清报警外的所有命令**一律要求卡「在线」；报警态被拒。
冒号后面是闸门给出的原因原文。**这是现场最容易踩的一条**。
怎么改：报警了想停 → 勾 `UseEmergencyStop`（急停通道允许「在线」与「报警」）；
报警了想恢复 → 先清报警（清报警不会自动使能，清完还要补一步「轴使能」）。

**`停止命令被拒绝（Rejected_NotConnected）：运动卡未连接`（或 `运动卡已安全停机，请重新连接后再操作`）**
为什么：「未连接」「已安全停机」状态下软件发不出任何东西。
怎么改：未连接 → 去「运动卡设置」连接或勾「随方案启动自动连接」；
已安全停机 → 状态机不会自己回在线，**先断开再连接**（人工确认那一步不能省——安全停机意味着
通信连续失败或命令执行失败，原因还没排除）。这正是硬件急停回路必须存在的原因。

**`停止命令被拒绝（Rejected_InvalidArgument）：轴号 4 超出范围（本卡 4 轴）`**
为什么：轴映射里配的**物理轴号**（0 基）超出这张卡上报的轴数——机型给小了，或未识别机型走了兜底值。
怎么改：核对「运动卡设置」的机型栏（如 `ECI3428` / `ECI3828` / `ZMC408SCAN` / `VPLC532R`）与轴映射的物理轴号。

**`对运动卡「运动卡1」的急停命令被拒绝（Rejected_NotConnected）：（括号后是卡的状态说明原文）`**
为什么：急停通道虽然宽（放行「在线」与「报警」），但「未连接」「连接中」「已安全停机」仍然拒绝。
怎么改：卡真断连时软件发不出任何东西——这条报错的意义是告诉你"这一步没停住"，
后续动作（报警输出、记录）照常走，硬件回路该断的电由回路自己断。多张卡时逐张执行，
**第一张被拒就整步失败**，后面的卡不再发——所以混装环境要检查每张卡的状态。

**`等待轴「X」到位时被中断（流程已停止）`（出现在「等待到位」，与本步骤相邻的常见困惑）**
这是流程停止的预期文案，不是停止命令失败。若你想"停住继续跑"，用本步骤而不是停止流程。

## 三、"现象对不上"这一类

**放了本步骤，但轴好像还在走**
① `Accepted=true` 只代表命令被接受，本步骤**不等停稳**——用「读轴状态」看 `Moving=false`；
② 只停了 A 轴、B 轴还在动——要全停请把 `Axis` 留空（勾急停时同理，留空才会急停所有卡）；
③ 卡已进「报警」——软件发现硬信号（报警/限位/急停输入）时会自动做一次急停，
此时普通停止会被拒（见上面第一条被拒文案），流程里"异常分支 → 轴停止"要改勾急停或先清报警。

**减速停看起来"停得很远"**
减速停按当前加减速曲线走完剩余减速段，这是设计（保护机械）。要最短停止距离用 `Immediate`
（立即停）或勾急停；带竖直轴/夹具时用立即停前先确认重力风险。

**"停全部轴"在某张卡上报"部分轴停止命令下发失败"**
正运动没有"停所有轴"的单一调用，驱动逐轴下发取消，任何一根失败整条判失败；
失败的那根轴大概率是映射与卡能力不一致（见上面 `Rejected_InvalidArgument` 那条）。

**勾了急停但之前排队的运动还在排**
不会——急停第一步就是清空待执行队列（排队的命令全部转"已取消"）。
守门断言 `★急停清空待执行队列（排队的 Move 全部被取消）`、
`★急停能打断正在执行的命令（回零立刻结束，而不是等它跑完）`（`FlowCanvasChecks\MotionChecks.cs`）
钉的就是这两件事。若观察到"急停之后还有运动被发起"，那是**急停之后新入队**的命令，
检查流程分支——急停不锁死队列，后续步骤照样能发新运动（这是编排自由，也是责任）。

**急停之后要不要重新使能？**
急停只停运动、不动使能；轴停在原地但仍带电。若中途做过失能或报警，要先「轴使能」再运动。
撞限位/报警造成的停止，建议补一次「轴回零」再按绝对坐标走。
