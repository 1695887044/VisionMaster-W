# 轴运动：快速上手

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

让一根轴走到目标位置。产出是 `Accepted`（命令有没有被收进队列）和 `Axis`（本次实际用到的轴名，
供下游步骤直接引用），外加每个步骤都有的 `Success` / `ErrorMessage`。

它在运动链路的**第三环**：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态 / 轴卡 IO / 轴停止`

**本步骤最关键的一条语义：它只下发，不等到位。**
`Accepted = true` 只代表"这条命令被这张卡收下了"，不代表轴已经开始动，更不代表已经到位。
这不是缺陷，而是必然：产线上大量场景要"两轴同时运动"，如果运动内部阻塞等到位，两条轴就只能串行跑 ——
现场只会发现"节拍莫名慢了一倍"，而且很难看出原因。把"下发"和"等待"分开表达，用户才能显式写出自己的意图。

## 一、跑通第一次（5 步）

1. 上游先走完「轴使能」和「轴回零」（没回零时当前位置是上电瞬间的读数，按绝对坐标走可能直接撞限位）。
2. 流程里放一个**轴运动**步骤，双击打开参数面板。
3. `Axis` 下拉选轴（下拉里只有**已启用**的轴）；`Mode` 下拉选"绝对（走到坐标点）"或"相对（再走一段）"。
4. `Target` 填目标位置（mm）。绝对 = 目标点坐标；相对 = 增量，**负号就是方向**。`Velocity` 填一个非零速度（mm/s）。
5. 在它后面**再放一个「等待到位」**，轴名直接链本步骤输出的 `Axis`。运行一次，成功日志形如：
   `{步骤实例名} 已下发：X 绝对运动 → 12.000 mm @ 50.0 mm/s（未等到位；如需等待请在其后加「等待到位」步骤）`，
   随后「等待到位」报到位、`读轴状态` 的 `Position` 接近 12.000 mm。

## 二、原理与口径

- **命令走卡内队列**：入队后由该卡的执行线程按先进先出逐条执行，所以"先动轴、再夹紧"这类顺序关系天然成立
  （「轴卡 IO」的写输出走同一条队伍）。队列有深度上限（卡级默认 `256` 条），满了直接拒。
- **目标与速度是输入端口，不是配置项**：因为它常常来自上游 —— 视觉定位给出坐标 → 这一步接过去 → 轴走过去。
  做成配置项就绑不了变量，视觉引导无从落地。
- **取值优先级**：一律"上游链接值 > 界面手填值 > 端口默认值"。`Axis` 空白时不猜默认坐标，
  让校验给出"没有指定轴名"—— 把未知当成一个坐标是最危险的做法。
- **单位是 mm，不是脉冲**：流程侧一律 mm / mm/s，脉冲当量换算发生在驱动层。
  正运动卡在连接时对每个启用轴下发 `SetUnits`（当量取自轴映射 `UnitsPerMm`，默认 1000），
  之后厂商 API 收发的就是 mm，软件**不再二次除当量** —— 所以"改当量"只需改「运动卡设置」里的映射。
- **绝对运动的基准点** = 这根轴的坐标零点，也就是「轴回零」建立出来的那个原点。
- **相对运动的基准点** = 下命令时刻的当前位置（指令位置，不是编码器实际位置）。
  **相对运动同样受软限位约束**：闸门按"当前位置 + 增量"算出目标点，再与 `SoftLimitMinMm` / `SoftLimitMaxMm` 比，
  越界直接拒绝（提示里同时给出当前值、增量与算出的目标值）。读不到当前位置时**拒绝**而不是放行 ——
  "不知道现在在哪"却允许相对运动，等于把越界判断交给运气。
- **速度填 0 的真实行为**（现场最容易踩的差异）：正运动卡"命令速度 ≤ 0 就不覆盖"，即沿用**控制器内该轴当前的 SPEED**
  （可能是厂商调试软件里设的值）；虚拟运动卡则回落到卡级默认 `DefaultVelocityMmPerS`（默认 50 mm/s）。
  两者不一致。要确定性的速度，请在流程里显式给非零速度。
- **加速度与曲线本步骤不下发**：命令里的加速度取 `0`、曲线取梯形。落到正运动卡上就是
  "加速度沿用控制器内既有值（不覆盖）、S 平滑时间每次定位前被写回 0"（所以上一条命令设过的 S 曲线也会被清掉）。
  要按方案指定加减速或走 S 曲线，走「运动卡设置」/调试面板那条路，不要指望这一步。
- **不做点位表绑定**：本步骤只认 `Target` 端口里的数值，不会去读「运动卡设置」里的点位表
  （P0~P15 是给调试面板点位运动用的）。要在流程里用点位，把点位坐标作为变量喂给 `Target`。
- **超时用的是卡级值**：本步骤的命令超时取该卡的 `CommandTimeoutMs`（卡级默认 `30000` ms），
  它只用于"把命令写进卡"这一步；**真正的到位超时由「等待到位」步骤负责**，两者不要混。

## 三、典型用法 / 接线

```
单轴一次定位：
  轴使能(X) ──▶ 轴回零(X) ──▶ 本步骤(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=ON 夹紧)
                                   ▲
                                   └ Target ◀── 视觉定位.X坐标      Velocity ◀── 变量定义.速度

视觉引导（最常见）：
  图像采集 ──▶ 视觉定位 ──▶ 本步骤（Target ◀── 定位结果.X，Mode=绝对）──▶ 等待到位 ──▶ 拍照确认

两轴同时运动（下发/等待拆开的全部意义）：
  本步骤(X) ──┐
              ├──▶ 等待到位(X) ──▶ 下一步
  本步骤(Y) ──┘   等待到位(Y) ──▶ 下一步
  说明：两个运动步骤背靠背放，两条命令进同一队列先后下发，然后各自等待；
        物理上两轴几乎同时起动。若把等待夹在中间，就退化成串行。

收尾：… ──▶ 轴停止（需要中断时）──▶ 读轴状态（确认停下来）
```

`Mode` 用绝对还是相对：定位到"某个位置"用绝对；"再走一段"（退料、微探、补走）用相对。
相对运动的方向靠 `Target` 的正负号表达，`Mode` 里没有方向选项。

## 四、算不算流程失败

只覆盖"下发"这一段，四种情况 `Success = false` 并把原因写进 `ErrorMessage`：
① 轴名解析失败；② 卡不在「在线」状态（报警 / 安全停机 / 未连接 / 连接中都算）；
③ 命令被拒绝（软限位越界、轴号无效、队列满、不支持）；④ 步骤内抛出未捕获异常。
**下发成功之后的运动失败（撞限位、跟随误差报警、中途掉线）不由本步骤报告**，
必须由后面的「等待到位」或「读轴状态」去发现。

## 五、常见问题

**Q：步骤绿色成功，轴却好像没到位置 / 后面的动作扑空？**
正常现象 —— 本步骤不等到位。在它后面补一个「等待到位」（`Axis` 直接链本步骤的 `Axis` 输出），
或者在要求不严的场合用「读轴状态」确认 `InPosition` 与 `Moving`。

**Q：速度填 0 到底跑多快？**
真机上沿用控制器内该轴当前的 SPEED（不是软件里的"卡级默认速度"），仿真卡用卡级默认 50 mm/s。
节拍敏感的流程请把速度显式写成非零值。

**Q：`Mode` 那一行为什么没有链接图标？**
枚举端口在编辑器里按"只能选"处理：**不提供链接、也不提供清除**（上游值未必是合法枚举，
绑上去等于把非法值塞进封闭集合；也没有"空枚举"可以表示清除后的状态）。
需要"由上游决定走绝对还是相对"时，用流程分支判断，而不是给这一行接变量。

**Q：想要 S 曲线 / 指定加速度，这一步里没有？**
确实没有，是刻意的：流程步骤只负责"去哪、多快"，加减速与平滑形状属于卡的运动参数配置面。

**Q：换了一张卡、或者重新接了线，流程要改吗？**
不用。改「运动卡设置」里的卡配置与轴映射（`PhysicalIndex` 物理轴号 0 基、`UnitsPerMm` 当量）即可，
流程里引用的还是那个轴名。唯一要重做的是：确认新卡的行程软限位、以及重新回零建立零点。

**Q：为什么 `Axis` 既是输入又是输出？**
输入是"我要动哪根轴"，输出是"本步骤实际用到的轴名"（把生效值定稿下来）。
下游「等待到位」「读轴状态」直接链这个输出，就不存在手抄轴名抄错的问题。
