# 轴运动：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面/日志里真会出现的原文**（从源码逐字抄，`{…}` 处是实际值），按"现象 → 为什么 → 怎么改"排。
本步骤只覆盖"下发"这一段，所以排障也要先分清：是**没下发成功**（本步骤报错）还是**下发了但没走到**（要靠后面的步骤发现）。

## 一、先看挂在哪一环节

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 轴名解析 | `没有指定轴名：…` / `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 还没碰卡，纯配置问题 |
| ② 卡状态门禁 | `运动卡「…」当前不可运动：…` | 步骤入口只放「在线」 |
| ③ 命令入队 | `运动命令被拒绝（Rejected_…）：…` | 基类四道闸拦下，括号里是命令结果**成员名**（英文） |
| ④ 下发之后 | 本步骤**不报错**（`Success = true`、`Accepted = true`） | 撞限位、跟随误差报警、掉线都由「等待到位」/「读轴状态」或卡状态体现 |

## 二、逐条

**`没有指定轴名：请在「Axis」端口填轴名（或用下拉选一个），也可由上游变量给出`**
为什么：`Axis` 的生效值是空白（下拉没选，或手填被清空）。代码刻意不兜默认值，就是为了让这句话被说出来。
怎么改：在参数面板重选一个轴名。

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是全局唯一标识，注册表里查不到（改名、删卡、换方案都会造成这个结果）。
怎么改：核对轴名。大小写不敏感但**字面必须一致** —— `Al`（字母 L）与 `A1`、`上料轴` 与 `上料 轴` 都算两个名字。

**`轴「X」在卡「…」上处于停用状态：请到「运动卡设置」把它启用，或换一个轴名`**
为什么：轴映射里 `Enabled = false`（未接电机的轴关掉，就是为了让流程误用不了）。
怎么改：确认这根轴确实接了驱动器再启用，否则换成实际接线对应的轴名。

**`找不到运动卡「…」的运行态设备：请确认该卡已在「运动卡设置」里配置并保存到方案`**
为什么：注册表有绑定，运行态设备表里没有对应卡 Id 的设备 —— 配置改了没同步或换了方案没重开流程。
怎么改：保存方案后回流程重开一次参数面板；仍不行就重连该卡。

**`运动卡服务尚未就绪：请在主程序内运行流程`** / **`轴注册表尚未注入（宿主未完成初始化）：请重启主程序`**
为什么：宿主侧的运动服务/注册表没注入（离线宿主、设计器里单独跑流程，或启动初始化没走完）。
怎么改：在主程序里运行；反复出现就查启动日志里运动模块的初始化。

**`运动卡「{卡名}」当前不可运动：{状态说明}`**
为什么：卡状态不是「在线」。冒号后面是卡自己的说明，常见四种：`运动卡未连接`、
`运动卡正在连接/断开，请稍候`、`运动卡处于报警状态，请先清除报警`、`运动卡已安全停机，请重新连接后再操作`；
报警时通常是「轴名：报警原因」。
怎么改：未连接 → 连接或勾「随方案启动自动连接」；报警 → 调试面板清报警（**清报警不会自动使能**，
使能得回来补一步）；已安全停机 → 先排除停机原因（命令失败/看门狗/失联），
再清一次报警：底层确实没报警且位置可信时，状态会从「已安全停机」回到「在线」
（位置不可信——增量编码器未回零——则仍要求重新连接并回零）；连接中 → 等一轮。

**`运动命令被拒绝（Rejected_InvalidArgument）：目标 1200.000 mm 超出软限位 [-1000.0, 1000.0] mm`**
为什么：**绝对运动**查的是目标点本身，这是软件层的最后一道防线。九成是目标超出行程，
或轴名指向了另一张卡的同名轴、`Target` 被上游给了一个离谱值（视觉像素当量没换算、坐标系没平移）。
怎么改：核对「运动卡设置」里该轴的 `SoftLimitMinMm` / `SoftLimitMaxMm`（默认 ±1000000 mm，即"实际不限制"）；
再核对上游坐标。这条被记为**提示级**故障（业务上正常），设备仍可用，不会进报警或安全停机。

**`运动命令被拒绝（Rejected_InvalidArgument）：相对运动目标 240.000 mm（当前 190.000 + 增量 50.000）超出软限位 [-100.0, 200.0] mm`**
为什么：**相对运动也受软限位约束**，判据是"当前位置 + 增量"。括号里把三样都写出来了：
算出来的目标、当前位置、你给的增量 —— 一眼能看出是"增量给大了"还是"起点已经在边上了"。
怎么改：核对增量与方向（`Target` 的符号就是方向）；确实要走这么远，就调整该轴的软限位
（前提是机械行程允许）。这条同样是提示级，设备仍可用。

**`运动命令被拒绝（Rejected_NotConnected）：无法读取轴「X」的当前位置，禁止相对运动（…）`**
为什么：相对运动的目标 = 当前位置 + 增量，而快照里还没有这根轴的位置
（刚连接还没轮到第一拍轮询，或状态轮询异常）。**这种情况一律拒绝，不放行** ——
"不知道现在在哪"时允许相对运动，越界判断就形同虚设。
怎么改：确认卡在线且状态轮询正常（看「读轴状态」能不能读到 `Position`），稍后重试；或改用绝对运动。

**`运动命令被拒绝（Rejected_InvalidArgument）：轴号 3 超出范围（本卡 4 轴）`**
为什么：轴映射里的**物理轴号**超出这张卡上报的轴数（机型给小了，或未识别机型走了兜底 4 轴）。
怎么改：核对机型栏与物理轴号；换 8 轴卡（`ECI3828`）而机型留空时以控制器上报型号为准。
日志里若有 `未识别机型「…」，本次按 4 轴 …`，先把机型填准。

**`运动命令被拒绝（Rejected_QueueFull）：命令队列已满（上限 256 条）`**
为什么：这一轮往这张卡堆了太多命令，或卡侧执行被卡住（队列不消费）。通常是运动步骤放在循环/并行组里跑得过密。
怎么改：先查有没有轴在报警或通信受阻，再加等待、降低循环频率或拆分流程。上限是卡级参数 `MaxQueueDepth`。

**`运动命令被拒绝（Rejected_NotConnected）：{原因原文}`**
为什么：卡不在线（四类原因见上面那条）。括号里的 `Rejected_NotConnected` 是命令结果**成员名**，
冒号后面才是可直接照做的原因。
怎么改：照冒号后面的话处理；这一步**不会**替你把命令暂存等卡恢复。

**`运动命令被拒绝（Rejected_NotSupported）：{原因原文}`**
为什么：这张卡/这个动作不支持（回零方式那一类能力协商走这条）。点位运动本身各家都支持，
出现它多半是命令被别的门禁改道了。怎么改：看后半句原文，并按「轴回零」的排障页对照能力清单。

## 三、"下发成功但没走到"这一类（本步骤不报错）

**`Accepted = true`、`Success = true`，轴没动 / 没到位置**
按顺序查：① 后面**有没有**「等待到位」—— 本步骤不等，绿色只代表收下了命令；
② 这根轴有没有使能（虚拟卡会明确报 `轴未使能（请先执行「轴使能」步骤）`，真机由控制器处理，
   通常体现为卡随后进入报警）；③ `Target` 是不是被上游给了 0（绝对运动走到 0 就是"看起来没动"）；
④ 速度是不是 0（正运动沿用控制器内 SPEED，厂商软件里若设得很小，就是"极慢"而不是"没动"）。

**卡突然进「报警」，流程里没有任何一步报错**
这是**下发之后**的失败（伺服报警、跟随误差超限、撞硬限位）。本步骤早就成功了，原因在卡的状态里：
看日志行 `[{卡名}] {命令描述} → Failed：…` 或状态栏的报警说明，用「读轴状态」把 `Alarm` / `Position` 连到记录里定位。

**运动方向反了**
① `Mode = Relative` 时方向靠 `Target` 的正负号；② 绝对运动方向不对通常是**零点没建对**（回零方式选错、
或根本没回零）；③ 驱动器侧的电机转向定义与坐标正方向不一致。
方向搞反 + 相对运动会一路走到软限位才被拦下（现在会拦：按"当前位置 + 增量"判，越界直接拒），
所以"方向反了"更容易表现为**一开始就被拒绝**，而不是闷头冲到硬限位。

**"节拍莫名慢了一倍"**
把「等待到位」夹在两个「轴运动」中间了。两条下发背靠背放、等待各自放后面，
两条命令进同一队列先后下发、物理上几乎同时起动。

**用日志定位比反复点运行快**
成功时的固定一行：`{步骤实例名} 已下发：X 绝对运动 → 12.000 mm @ 50.0 mm/s（未等到位；如需等待请在其后加「等待到位」步骤）`。
相对运动那行是 `X 相对运动 +12 mm @ 50.0 mm/s`（带符号、不带尾零）。
排查"为什么没等""到底下发到哪根轴"先看这行；卡的执行线程另有
`[{卡名}] X 绝对运动 → 12.000 mm @ 50.0 mm/s → 完成` 一条，两行对照就能分清"步骤没等到"与"卡说它失败了"。
