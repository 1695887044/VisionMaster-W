# 轴运动：端口与参数

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

这一页只回答三件事：**每个口怎么填、填错/接不上会怎样、这些值最后存在哪儿**。
"只下发不等到位"这条语义本身见《轴运动：快速上手》，本页不重复。

## 一、参数面板长什么样

本步骤**没有自定义配置界面**，也没有任何 `[StepConfig]` 配置属性：四个可调项**全部是输入端口**，
由宿主 `AutoPortConfigView` 自动生成清单，所以四项在界面上都能改。

| 界面元素 | 本步骤看到的内容 |
| --- | --- |
| 行 | 四个输入端口各一行（顺序 = 端口名按字母序：`Axis`、`Mode`、`Target`、`Velocity`） |
| 行标签 | 取端口的**描述**（如"目标位置(mm)"、"速度(mm/s，0=用卡级默认)"） |
| 值框 | `Axis` 与 `Mode` 是**「只能选」下拉**；`Target`、`Velocity` 是数值常量输入框 |
| 🔗 图标 | **只有 `Target` 与 `Velocity` 有**。`Axis`（声明了 `IsFunctionalEnum`）与 `Mode`（枚举）都按"只能选"渲染，链接与清除按钮不出现 |
| ✕ 图标 | 同上，只在可链接的两行上出现（清除链接与常量，回落到端口默认值） |
| 窗口尺寸 | 宽 560、按内容定高 |

面板顶部提示条原文：**「该步骤没有自定义配置界面，参数如下：没有绑定需求时直接填入常量，
需要连上游变量就点右侧的链接图标。」**

**取值优先级**：上游链接值 ＞ 界面手填常量 ＞ 端口声明的默认值。挂着链接时，常量框里填什么都没作用。

## 二、输入端口逐个

| 端口（也是存档键） | 类型 | 必填 | 默认值 | 合法取值 / 填法 | 填错会怎样 |
| --- | --- | --- | --- | --- | --- |
| `Axis` | 字符串（逻辑轴名） | 否（`IsRequired = false`） | `X` | 下拉候选来自「运动卡设置」里**已启用且能解析**的轴（全局唯一名，如 `A0` / `X` / `上料轴`） | 解析不出轴 → 步骤失败，原因文本由轴解析器给出（见排障页），不会去猜别的卡 |
| `Mode` | `MotionMoveMode`（枚举） | 否 | `Absolute` | 下拉两项：`绝对（走到坐标点）` / `相对（再走一段）`；**只能选、不可链接** | 只能二选一，不存在"空值"；存档与报错用**成员名** `Absolute` / `Relative` |
| `Target` | 双精度（mm） | 否（默认值即可运行） | `0` | 绝对 = 目标点坐标；相对 = 增量，**可为负**（负号即方向）。可链上游（视觉定位结果、配方变量） | 类型不符的上游值在灌值时宽容跳过，仍用上一生效值 —— 改完确认这一行显示的确实是你要的那个 |
| `Velocity` | 双精度（mm/s） | 否 | `0` | `0` 表示"不覆盖"：正运动沿用控制器内该轴当前 SPEED，虚拟卡回落到卡级 `DefaultVelocityMmPerS`（默认 50）。可链上游 | 填负数按"未给速度"处理（驱动侧判据是 `≤ 0` 就不设速度），不会产生反向运动 —— 反向靠 `Target` 的符号 |

四个口都刻意保持"不连上游也能跑"：`IsRequired = false` 或有默认值，老流程只填常量不会被判编译失败。

## 三、配置项（`[StepConfig]`）

**本步骤没有任何配置属性**，所以「模块参数」里没有第二张表要填；
速度上限、加减速、曲线形状**不在本步骤的参数面上**（属于「运动卡设置」/调试面板的卡与轴参数）。

## 四、输出端口与下游怎么用

| 端口 | 类型 | 什么时候被写 | 典型消费方 |
| --- | --- | --- | --- |
| `Accepted` | 布尔 | 步骤开头先清 `false`；只有 `Enqueue` 返回"已接收"才置 `true`。**不代表已到位，也不代表已起动** | 条件分支、报警 |
| `Axis`（由属性 `AxisUsed` 提供） | 字符串 | 步骤一开始就把生效轴名原样回填，**失败时也写** | 「等待到位」「读轴状态」的 `Axis` 直接链它，避免手抄轴名抄错 |
| `Success` | 布尔 | 每个步骤都有：四条失败出口都置 `false` | 条件分支（If / While） |
| `ErrorMessage` | 字符串 | 每个步骤都有：失败原因原文 | 接「数据记录」或报警上报 |

注意输出端口的**名字**是 `Axis`（属性名 `AxisUsed` 只是代码里为了不与输入端口同名）。
在绑定界面里挑选时看到的是 `Axis`，别以为是同一个口 —— 一个是入、一个是出。

## 五、这些值最后存在哪儿

- 落在**该步骤**的 `InputValues`（`.vms` 里），**键名 = 端口名**：`Axis`、`Mode`、`Target`、`Velocity`。
- `Mode` 存的是**成员名**（`Absolute` / `Relative`），不是界面上的中文。改中文显示名不断流程；
  改枚举成员名会打断已配好的流程。
- `Target` / `Velocity` 存数值（mm、mm/s，不带单位字符串）。
- 某一行的值改成链接（🔗）后确认，会**移除**该键的常量值，避免残留脏数据；运行时以链接为准。
- 轴名存**轴名本身**：不存卡地址、不存 IP、不存物理轴号。换卡/改接线只动「运动卡设置」。

## 六、口径速查

- **单位**：位置 mm、速度 mm/s；脉冲当量换算在驱动层（`UnitsPerMm` 默认 1000）。
- **0 基**：物理轴号 0 基，但流程里看不到它。
- **运动前置门禁（设备层，P1-A）**：Move 必须满足三条 —— **已使能、已回零（或该轴 `HasAbsoluteEncoder=true`）、未在运动中**。
  缺一条就拒绝（`Rejected_NotConnected`，具体原因在 `LastFault.Suggestion` 里，步骤会拼进报错）。
  这三条不写在本步骤里，UI / SCADA / 流程共用同一道设备门禁，避免三处口径漂移。
  使能命令刚完成、轮询快照还没刷新的一拍内，门禁会以命令结果为准（不会误报"未使能"）。
  `IsHomed` 是**卡级**标志（既有契约）：同卡任意轴回零成功即视为整卡已回零；
  多轴机台请对每根参与运动的轴各放一步「轴回零」。
- **软限位**：绝对运动比**目标点**；相对运动按"**当前位置 + 增量**"算出目标点再比
  （`SoftLimitMinMm` / `SoftLimitMaxMm`，默认 ±1000000 mm）。
  默认值等于"这道防线是空的"，界面上会提示"实际不限制"。
  相对运动取不到当前位置时直接拒绝（`无法读取当前位置，禁止相对运动`），不放行。
- **相对运动算两次**：入队时按当时的当前位置算一次，**执行前再算一次**（命令在队列里等待期间轴可能已经动了）。
  执行前那次越界会以"执行前校验未通过"取消这条命令 —— 这是有意的：宁可这一条不走，也不硬冲行程。
- **不等待**：`Enqueue` 返回即结束，命令超时取卡级 `CommandTimeoutMs`（默认 30000 ms），只约束"写命令"这一段。
- **重试**：命令默认可重试（`Retryable` 未显式关闭），重试与否由设备侧的队列/门禁决定；
  点位运动本身没有机械危险，这一点与「轴回零」（刻意禁止重试）不同。
