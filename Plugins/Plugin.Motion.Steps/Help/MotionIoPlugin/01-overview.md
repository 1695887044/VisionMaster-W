# 轴卡 IO

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

读写**运动卡上的数字输入/输出端子**：气缸、夹爪、真空反馈、到位传感器、报警灯这些点位。
一次执行只做一件事 —— 要么写一个输出点（`Accepted`），要么读一个输入点（`InputValue`）。

它在链路里与轴动作穿插使用（夹紧/松开/吹气这些动作必须和轴在同一条时序里）：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 本步骤（夹紧）──▶ 本步骤（读夹紧反馈）──▶ 轴停止`

## 为什么需要它 / 原理

- **为什么归在"运动控制"而不是"通讯"**：这些点位是运动卡上的 IO，与轴的动作在同一个时序里、
  走同一条卡通信。拆到通讯侧会出现"同一台设备的状态被两条链路读写"的麻烦（顺序没法保证，状态还可能互相打脸）。
- **写输出走命令队列，与轴命令同一条队伍**：所以"轴到位 → 夹紧"这类顺序关系天然成立，
  不需要额外同步。读输入走轮询快照，不发起通信。
- **IO 是卡级操作，必须指定卡**：读写的是卡上的端子，不属于任何一根轴，没有轴名可借。
  给的是**卡名**而不是 IP：地址是物理接线（换网段/换卡就失效），卡名是用户在「运动卡设置」里给的身份，与接线无关。
- **点号是 0 基**，与卡上的接线标号一致（正运动手册里的 `IN0` / `OUT0` 就是点号 0 / 1 基写法的分界点：
  本步骤填 `0` 对应 `IN0`，填 `3` 对应 `OUT3`）。这是现场最容易搞错的一项 —— 按"第 1 点=1"去填会整体错一位。
- **能力先行校验**：点号超范围在入队前就被挡下，并告诉用户这张卡有几个点
  （读：`输入点 5 无效（本卡输入点范围 0~3）`；写：`输出点 9 超出范围（本卡 8 点）`）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Card` | 写操作/读操作都要 | 运动卡**卡名**，默认空。空值直接报 `这是卡级操作（IO / 急停），请在「运动卡」端口选择一张运动卡`；下拉候选来自「运动卡设置」里的卡，可被上游变量给出 |
| `IoPort` | 否 | 点号（**0 基**），默认 `0`，与卡接线对应。整数端口：可由上游变量给出（例如"第 N 个工位的气缸"） |
| `Value` | 否 | 写入值，默认 `true`（ON），**仅"写输出"用**。布尔端口，可被变量驱动（如"夹紧=真"） |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Accepted` | 写入命令是否被收进队列（开头先清 `false`）。仅"写输出"有意义 |
| `InputValue` | 读到的输入状态（开头先清 `false`）。仅"读输入"有意义 |
| `Success` / `ErrorMessage` | 每个步骤都有的成败与原因 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Card` | 空 | 卡名（**输入端口**，界面上可改、可被链接） |
| `Direction` | `WriteOutput`（写输出） | 操作方向，界面显示中文、存档成员名（`WriteOutput` / `ReadInput`），改显示名不会断连线。当前是步骤的**配置属性**，本插件没有自定义配置界面、参数面板只列输入端口，所以界面上暂无编辑入口，实际以默认值/存档值为准 |
| `IoPort` | `0` | 点号，0 基（**输入端口**） |
| `Value` | `true` | 写入值（**输入端口**，端口名 `Value`；属性名刻意不叫 `Value`，否则会撞上基类同名成员、解析到的不是这个端口） |

## 口径与失败策略

- **读写两条完全不同的路径**：
  | 方向 | 走哪里 | 是否等执行 | 状态要求 | 产出 |
  | --- | --- | --- | --- | --- |
  | 写输出 | 命令队列（与轴命令同队） | **不等**（`WaitsForCompletion=false`） | 步骤自己允许「在线」与「报警」两种状态发起，但**底层命令门禁只放行「在线」** | `Accepted` |
  | 读输入 | 轮询快照 | 立即返回 | 无状态门禁；但点号必须在能力表范围内 | `InputValue` |

  也就是说：报警态下写输出**发得出去、但会被队列门禁挡回**，报错是
  `写输出命令被拒绝（Rejected_NotConnected）：运动卡处于报警状态，请先清除报警`
  （括号里是命令返回的成员名，冒号后面才是原因原文）。
  要"报警后先松夹"，得先清报警（或把松夹做进硬件回路 / 用失电松开的气路设计）。
- **点号口径**：0 基。范围提示直接来自卡上报的能力（读 `0~DigitalInputCount-1`，写按 `DigitalOutputCount`）。
  正运动卡的 IO 点数由**机型**决定（如 ECI3428 = 24 入 / 16 出，ECI3828 = 24 入 / 20 出，虚拟卡 = 8 入 / 8 出）；
  部分机型上报的是显示上限，界面会标注"点数未核实"，此时以实物接线为准。
- **读输入的"未采到"与"OFF"不可区分**：快照缓存里没有这个点时返回 `false`。
  刚连接、还没跑完第一轮批量读，或者点号超出这张卡实际上报的范围，都会读成 OFF。
  要区分，先确认卡已连接、卡级轮询在跑（`PollIntervalMs` 默认 10 ms），日志里这条会打
  `读输入 3 = OFF` —— 它只说明"读到 OFF"，不说明"传感器坏了"。
- **`Accepted=true` 不代表端子已经动作**：命令只是进了队列，还没轮到执行；
  气缸是否真的到位要用输入点反馈去读（读输入），或用「读轴状态」以外的传感器步骤确认。
- **算不算流程失败**：算。① 卡名为空/找不到该卡；② 读：点号无效或能力未知（`该卡尚未上报能力，请确认已连接`）；
  ③ 写：卡状态既不是「在线」也不是「报警」（`运动卡「…」当前不可下发输出：…`）、命令被拒绝（点号超范围、队列满）。
  读输入只要读到值（含 OFF）就算成功 —— 读到坏消息不是读取失败。
- **超时**：写命令的超时取该卡 `CommandTimeoutMs`（卡级默认 30000 ms），但本步骤不等执行，所以不会因它挂住。

## 典型用法 / 接线

```
夹紧（写输出）：
  等待到位(X) ──▶ 本步骤（Card=运动卡1, Direction=写输出, IoPort=0, Value=true）──▶ 下一步

夹紧 + 反馈双确认（写→读，最常见也最稳）：
  轴运动(X) ──▶ 等待到位(X) ──▶ 本步骤(写 OUT0=ON 夹紧)
                                    └──▶ 本步骤(读 IN4 夹紧到位) ──▶ 条件判断 ──▶ 报警/继续

按配方给点号：
  变量定义.工位 ──▶ 本步骤.IoPort      变量定义.动作 ──▶ 本步骤.Value

收尾断气 / 松开：
  轴停止(X) ──▶ 本步骤（写 OUT0=OFF）──▶ 轴使能(X, Enable=false)

链路关系：本步骤与「轴运动」共用同一条命令队列，
所以"先运动、后夹紧"只要把两个步骤前后放好即可，不需要额外同步节点。
```

## 常见问题

**Q：写了输出，`Accepted=true`，气缸却不动作？**
按顺序查：① `IoPort` 是不是**按 0 基**填的（填 1 打的是 `OUT1`，不是"第 1 个点"）；
② 端子实际接的是不是这张卡的这一路（`Card` 选对没有 —— 多卡设备最容易选错卡）；
③ `Value` 是不是被上游变量给了 `false`；
④ 命令还在队列里排着（前面有长命令，比如一个还在跑的回零）—— 本步骤不等执行。
最后确认驱动器侧：正运动写输出是 `SetOp(点号, 1/0)`，可在厂商调试软件里看点位状态。

**Q：`输入点 5 无效（本卡输入点范围 0~3）`？**
点号超出这张卡上报的输入点数。虚拟卡只有 8 入 8 出；正运动按机型给点数，
如果日志里出现过"未识别机型……按兜底值处理"，先去「运动卡设置」把机型填准（`ECI3428` / `ECI3828` / `ZMC408SCAN` / `VPLC532R`）。

**Q：`该卡尚未上报能力，请确认已连接`？**
能力表是连接成功时才建立的，没连上就无从判断点号范围。去「运动卡设置」/调试面板连接；
连接失败的原因看该卡的说明（正运动常见是 native DLL 缺失或 IP/网段不通）。

**Q：传感器明明是通的，读出来一直 OFF。**
① 点号 0 基错位（最常见）；② 卡还没轮询到该点（刚连接，读的是空缓存，结果就是 OFF）；
③ 输入是源型/漏型接法不匹配，卡上读到的电平与实物相反；④ 读的是另一张卡（`Card` 选错）。
先用调试面板的 IO 页看同一帧的原始电平，再回流程比对。

**Q：想在报警/急停后立刻松夹，但写输出被拒。**
写输出允许「在线」与「报警」两种状态；被拒的多半是「已安全停机」（通信看门狗跳闸后需要人工重连）
或「未连接」。安全相关的松开动作请同时做进硬件回路（失电即松开的气路设计），不要只靠这一步。

**Q：能不能一次写多个点？**
不能，一个步骤一个点号。多点同写就并排放多个本步骤（它们进同一队列，先后几乎连着执行）。
需要真正的同步输出（例如两路气阀必须同一拍）应走卡上的插补/联动配置，不要在流程层凑。

**Q：读写能不能放在同一个步骤里？**
不能，`Direction` 二选一。典型写法是"写输出 → 读输入反馈"两个步骤前后放，
读到的 `InputValue` 交给条件判断，这样失败原因也分得开（没写进去 vs 没夹到位）。
