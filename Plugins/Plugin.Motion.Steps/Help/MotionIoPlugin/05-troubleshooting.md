# 轴卡 IO：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面/日志里真会出现的原文**（从源码逐字抄，`{…}` 处是实际值），按"现象 → 为什么 → 怎么改"排。
本步骤读写两条路，失败出口不共用，所以先按方向分流再往下看。

## 一、先看挂在哪一环节

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 卡名解析（读写都过） | `这是卡级操作（IO / 急停），请在「运动卡」端口选择一张运动卡` / `找不到名为「…」的运动卡：…` | 还没碰设备，纯配置问题 |
| ② 读：点号能力校验 | `输入点 {N} 无效（…）` | 步骤自己查 `IsInputValid`，**不看卡状态** |
| ③ 写：卡状态门禁 | `运动卡「…」当前不可下发输出：…` | 步骤只放「在线」与「报警」两种状态进入 |
| ④ 写：命令入队 | `写输出命令被拒绝（Rejected_…）：…` | 基类闸门拦下，括号里是命令结果**成员名**（英文） |
| ⑤ 执行侧（写） | 本步骤**不报错**（`Accepted = true`） | 写是"不等执行"的命令，失败只在卡的执行线程日志里 |

## 二、逐条

**`这是卡级操作（IO / 急停），请在「运动卡」端口选择一张运动卡`**
为什么：`Card` 的生效值是空白。IO 读写的是卡上的端子，不属于任何一根轴，没有轴名可借，必须给卡。
怎么改：在参数面板的 `Card` 下拉里选一张卡。这一行是"只能选"型下拉、没有链接按钮，所以空白只可能是没选或被清掉。

**`找不到名为「{卡名}」的运动卡：请到「运动卡设置」确认卡名，或换一张卡`**
为什么：卡名是用户在「运动卡设置」里给的身份（**不是 IP、不是设备型号**），按卡名查运行态设备查不到。
改名、删卡、换方案都会造成这个结果；大小写不敏感但**字面必须一致**（多一个空格就是另一个名字）。
怎么改：核对卡名。两张卡同名时下拉只列一项，解析结果取决于遍历顺序 —— 把卡名改成互不相同才是正解
（启动体检也会把"卡名重复"报出来）。

**`运动卡服务尚未就绪：请在主程序内运行流程`**
为什么：宿主没注入运动卡服务（离线宿主 / 设计器里单独跑流程）。
怎么改：在主程序里运行，试运行与正式运行注入的是同一个服务。

**`输入点 5 无效（本卡输入点范围 0~3）`**
为什么：点号超出这张卡上报的数字输入点数（判据是 `0 <= 点号 < DigitalInputCount`）。
后半句直接给出范围，就是为了让"0 基错位"一眼看出来。
怎么改：① 先确认不是按"第 1 点 = 1"填的；② 核对 `Card` 选的是不是真正接了传感器的哪张卡；
③ 虚拟卡只有 8 入 8 出（0~7），仿真时用超出范围的点号必然报这条。

**`输入点 5 无效（该卡尚未上报能力，请确认已连接）`**
为什么：能力表（含 IO 点数）是**连接成功时**才建立的，`DigitalInputCount` 还是 0，范围无从判断。
注意读输入这一支**不检查卡状态**，所以没连接也能走到这里，然后被能力挡住。
怎么改：去「运动卡设置」/调试面板连接该卡；连接失败的原因看该卡说明（正运动常见是 native DLL 缺失或 IP/网段不通）。

**`运动卡「{卡名}」当前不可下发输出：{状态说明}`**
为什么：写输出时卡状态既不是「在线」也不是「报警」，也就是**未连接 / 连接中 / 已安全停机**三种之一
（冒号后面是卡自己的说明）。步骤刻意放过报警态，是为了让"报警后先松夹"这类写法有机会发起 ——
能不能真下去由下一道闸门决定。
怎么改：未连接 → 连接或勾「随方案启动自动连接」；连接中 → 等一轮；
已安全停机 → 状态机不会自己回 online，**先断开再连接**（安全停机意味着通信连续失败或命令执行失败，原因还没排除）。

**`写输出命令被拒绝（Rejected_NotConnected）：运动卡处于报警状态，请先清除报警`**
为什么：③ 放开了报警态，但**闸门只放行「在线」** —— 这就是"看着像两个地方各说一半"的原因，不是矛盾。
括号里是命令结果成员名，冒号后面才是真原因。
怎么改：先在调试面板清报警（**清报警不会自动使能、也不会把这条被拒的输出命令补发**），
再让流程重跑这一步。安全相关的松开动作请同时做进硬件回路（失电即松开的气路设计），不要只靠软件。

**`写输出命令被拒绝（Rejected_NotConnected）：运动卡已安全停机，请重新连接后再操作`**
同上原因（另一种状态）；也可能是 `运动卡未连接` 或 `运动卡正在连接/断开，请稍候`。
怎么改：按冒号后面的话处理，安全停机需人工重连。

**`写输出命令被拒绝（Rejected_InvalidArgument）：输出点 9 超出范围（本卡 8 点）`**
为什么：点号超出这张卡上报的数字输出点数（闸门里查 `IsOutputValid`）。
范围来自**机型**：ECI3428 = 16 出、ECI3828 = 20 出、ZMC408SCAN = 20 出、虚拟卡 = 8 出、
未识别机型走兜底（4 轴 / 24 入 / 16 出）。
怎么改：① 核对 0 基；② 若日志里出现过 `未识别机型「…」，本次按 4 轴 …`，
去「运动卡设置」把机型栏填准（`ECI3428` / `ECI3828` / `ZMC408SCAN` / `VPLC532R`）；
③ 虚拟 PLC（VPLC532R）这类上报的是"常见上限"，界面会标注点数未核实，以实物接线为准。

**`写输出命令被拒绝（Rejected_InvalidArgument）：输出点 0 无法校验（能力未知）`**
为什么：能力表还没建立（没连上就走到写）—— 与读那支的区别是写还会被"必须在线"的门禁先拦一道，
所以这条通常出现在刚断开、状态还没落到"未连接"的窗口期。
怎么改：重连该卡再跑。

**`写输出命令被拒绝（Rejected_QueueFull）：命令队列已满（上限 256 条）`**
为什么：这一轮往这张卡堆了太多命令，或前面有长命令卡住队列（此时队列不消费）。
怎么改：先查有没有轴在报警/通信受阻，再加等待、降低循环频率或拆分流程。上限是卡级参数 `MaxQueueDepth`。

**`写输出命令被拒绝（Rejected_NotConnected）：{该卡最近一次故障的建议原文}`**
为什么：拒绝时的文案是 `LastFault?.Suggestion ?? StateDetail` —— 设备最近一次故障留了建议就用建议，
否则用卡的状态说明。所以后半句的措辞可能不完全一样，**看的是"卡现在到底怎么了"**。
怎么改：照后半句处理；没有可操作信息时去调试面板看卡状态与最近故障。

## 三、执行侧失败与"成功但没动作"（写不等执行，所以本步骤不报错）

**`Accepted = true`，端子却没动**
① `IoPort` 0 基错位；② 端子接的是另一张卡（`Card` 选错）；③ `Value` 被上游给了 `false`；
④ 命令还在队列里排着（前面有一条还在跑的回零）；⑤ 下发之后厂商 API 返回非 0 —— 这一种**不会回到本步骤**，
只能在卡日志里看到：`[正运动错误码 N]` 形状的那条来自驱动（文案是
`写输出失败（正运动错误码 {N}）。查看控制器状态与该轴是否有报警/限位；如持续出现请记录错误码联系厂商`），
以及基类的执行线程日志行 `[{卡名}] 输出 0 ← ON → Failed：…`。
排查时先看有没有这两行，再决定动接线还是动流程。

**传感器明明通着，`InputValue` 一直 false**
① 点号错位；② 卡刚连接、还没跑完第一轮批量读（快照空 → 与 OFF 不可区分）；
③ 源型/漏型接法不匹配；④ 读的是另一张卡。
卡级轮询周期默认 `PollIntervalMs = 10 ms`，正常连接后一轮就应有值；
日志里这条步骤打的是 `读输入 {N} = ON` / `读输入 {N} = OFF`，它只说明"读到什么"，不说明"传感器坏没坏"。

**"步骤成功，但流程后面读反馈读到 ON 而夹爪其实没夹"**
`Accepted` 与 `Success` 都只说"命令进队了"。夹紧到位的唯一凭据是**反馈输入点**：
写输出 → 读输入两步前后放，把 `InputValue` 交给条件判断，别拿 `Accepted` 当到位信号。
