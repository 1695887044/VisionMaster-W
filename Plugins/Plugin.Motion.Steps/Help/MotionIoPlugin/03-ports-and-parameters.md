# 轴卡 IO：端口与参数

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

这一页只回答三件事：**每个口怎么填、填错/接不上会怎样、这些值最后存在哪儿**。
为什么归运动控制、点号 0 基、读写两条路径，见《轴卡 IO：快速上手》，本页不重复。

## 一、参数面板长什么样

本步骤**没有自定义配置界面**，由宿主 `AutoPortConfigView` 自动生成清单；
该面板**只渲染输入端口**，所以配置属性 `Direction` 不会出现在界面上。

| 界面元素 | 本步骤看到的内容 |
| --- | --- |
| 行 | 三个输入端口各一行（顺序 = 端口名按字母序：`Card`、`IoPort`、`Value`） |
| 行标签 | 取端口的**描述**："运动卡（IO 是卡级操作，必须指定）"、"点号（0 基，与卡接线对应）"、"写入值（仅写输出用）" |
| 值框 | `Card` 是**「只能选」下拉**（候选 = 方案里的卡名）；`IoPort` 是整数常量框；`Value` 是布尔常量框（填 `true` / `false`） |
| 🔗 图标 | **只有 `IoPort` 与 `Value` 有**。`Card` 因为声明了 `IsFunctionalEnum = true`（候选来自方案）按"只能选"渲染，链接与清除按钮都不出现 |
| 窗口尺寸 | 宽 560、按内容定高 |

面板顶部提示条原文：**「该步骤没有自定义配置界面，参数如下：没有绑定需求时直接填入常量，
需要连上游变量就点右侧的链接图标。」**

**取值优先级**：上游链接值 ＞ 界面手填常量 ＞ 端口声明的默认值。

## 二、输入端口逐个

| 端口（也是存档键） | 类型 | 必填 | 默认值 | 合法取值 / 填法 | 填错会怎样 |
| --- | --- | --- | --- | --- | --- |
| `Card` | 字符串（**卡名**，不是 IP） | 否（`IsRequired = false`） | 空字符串 | 下拉候选来自「运动卡设置」里填过显示名的卡（同名卡只列一项，重名由启动体检报出来） | 空白 → 步骤失败：`这是卡级操作（IO / 急停），请在「运动卡」端口选择一张运动卡`；名字对不上 → `找不到名为「…」的运动卡：…` |
| `IoPort` | 整数（点号，**0 基**） | 否 | `0` | 读：`0 ~ DigitalInputCount-1`；写：`0 ~ DigitalOutputCount-1`。可链上游（例如"第 N 个工位的气缸"） | 超范围当场失败，并把这张卡的点数一起报出来（见排障页两条"无效/超出范围"） |
| `Value` | 布尔 | 否 | `true`（ON） | 仅"写输出"用。常量框填 `true` / `false`，也可由变量驱动（"夹紧=真"） | 类型不符的上游值在灌值时宽容跳过，仍用上一生效值 —— 改完确认这一行显示的确实是你要的那个 |

三个口都不连上游也能跑（`IsRequired = false` 或有默认值），老流程不会被判编译失败。

**端口名 ≠ 属性名**：写入值那个端口的 C# 属性叫 `WriteValue`，但端口名显式写成 `Value`。
属性名刻意不叫 `Value`，是因为那个名字会撞上基类上的成员、反射解析到的就不是这个端口。
**存档键取的是端口名 `Value`**，别按属性名去方案里找。

## 三、配置项（`[StepConfig]`）

| 参数 | 类型 | 默认值 | 取值 | 界面入口 |
| --- | --- | --- | --- | --- |
| `Direction` | `MotionIoDirection`（枚举） | `WriteOutput` | `WriteOutput`（写输出，中文显示名"写输出"）/ `ReadInput`（读输入，中文显示名"读输入"） | **没有**。它是配置属性，而本插件没有自定义配置界面、自动面板只列输入端口 —— 会正常存盘、正常生效，改它要动方案存档 |

枚举成员都带 `[Display(Name = "中文")]`，所以凡是走枚举候选的界面（例如变量绑定窗口里把它当端口候选时、
或将来给它补上编辑入口时）显示的是中文，**存档与报错用的仍是成员名**。

## 四、输出端口与下游怎么用

| 端口 | 类型 | 什么时候被写 | 典型消费方 |
| --- | --- | --- | --- |
| `Accepted` | 布尔 | 步骤开头先清 `false`；仅"写输出"且命令进队列后置 `true`。**不代表端子已动作** | 条件分支、报警 |
| `InputValue` | 布尔 | 步骤开头先清 `false`；仅"读输入"时写读到的电平（未采到与 OFF 不可区分） | 条件判断（夹紧到位 / 真空反馈）、「数据记录」 |
| `Success` | 布尔 | 每个步骤都有：四条失败出口置 `false` | 条件分支（If / While） |
| `ErrorMessage` | 字符串 | 每个步骤都有：失败原因原文 | 接报警上报，便于事后追溯 |

## 五、这些值最后存在哪儿

- 落在**该步骤**的 `InputValues`（`.vms` 里），**键名 = 端口名或属性名**：
  `Card`（端口名）、`IoPort`（端口名）、`Value`（端口名，**不是属性名 `WriteValue`**）、`Direction`（属性名）。
- `Direction` 存**成员名**（`WriteOutput` / `ReadInput`），不是中文显示名；读回按名字解析。
- 卡名存**卡名本身**：不存 IP、不存地址、不存端口号。换网段、换卡只动「运动卡设置」的地址栏。
- 点号存整数（0 基）；写入值存布尔。
- 某一行的值改成链接（🔗）后确认会**移除**该键的常量值，运行时以链接为准。

## 六、口径速查

- **单位**：本步骤只有点号（整数）与电平（布尔），没有长度/速度单位问题。
- **0 基**：点号 0 基，物理轴号 0 基，但流程里看不到轴号。
- **等待语义**：写输出**不等**执行（`WaitsForCompletion = false`）；读输入**立即返回**（读的是轮询快照）。
- **超时**：本步骤没有超时端口/属性；写命令的超时取该卡 `CommandTimeoutMs`（卡级默认 30000 ms），
  只约束"把命令写进卡"那一步，流程不会因为它挂住。
- **能力先行**：读输入的点号范围在步骤里就校验（`IsInputValid`）；写输出的范围在**闸门**里校验
  （`IsOutputValid`），所以两者的报错文案形状不同 —— 一个是"输入点 N 无效（…）"，
  一个是"写输出命令被拒绝（Rejected_InvalidArgument）：输出点 N 超出范围（…）"。
