# 轴使能

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

给一根轴**上电（使能）**或**断电（失能）**。产出是操作之后卡上真正回报的使能状态 `Enabled`，
以及每个步骤都有的 `Success` / `ErrorMessage`。

它是运动链路的**第一环**：

`轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 读轴状态 / 轴卡 IO / 轴停止`

伺服上电是有机械后果的动作（力矩一下加上去、制动器打开），工业现场的上电顺序通常有讲究，
所以软件**不会在「轴运动」里替用户自动使能** —— 把上电时序交给用户在流程里显式表达。
忘了放这一步的表现不是"轴静默不动"，而是运动步骤直接报
`轴未使能（请先执行「轴使能」步骤）`，一眼能看出缺哪一步。

## 为什么需要它 / 原理

- **本步骤会等待**（与「轴运动」相反）。命令带 `WaitsForCompletion`，入队后要等驱动把它执行完，
  最多等 `超时 + 500 ms`。理由是：使能失败必须当场知道，否则后面每一步都以"轴未使能"失败，
  真正的原因（供电、急停回路、驱动器报警）会被淹没在后面一堆同类报错里。
- **结果以设备回报为准**，不是"我发了使能所以它就该是使能"。命令执行完成后，
  本步骤再去读轴状态快照里的 `Enabled` 位填进输出端口 —— 卡可能拒绝或延迟生效。
- **报警态也允许发起**。卡处于「报警」时使能/失能的请求照样发（现场常常要先失能再清报警），
  但底层命令门禁只放行**在线**的卡，所以报警态下使能会得到一句明确拒绝：
  `运动卡处于报警状态，请先清除报警`。**失能**是安全动作，报警态与安全停机态都放行。
  「未连接」一律在步骤入口被拦下；「已安全停机」在**使能**时被拦下 ——
  要恢复就把 `ClearAlarmFirst` 填 `true`（见下一条）。
- **安全停机后可以先清报警再使能**：把 `ClearAlarmFirst` 填 `true`，本步骤会先清一次报警，
  成功后再走原来的使能逻辑（清报警在门禁之前做，否则"安全停机"会先把这一步挡掉）。
  清报警**不会自动使能**（上电有机械后果），所以两步仍然分开；
  底层报警没清干净时这一步如实失败（不会带着报警上电）。
  位置不可信（增量编码器未回零）时，清报警成功也不会放回在线 —— 那要先重新连接并回零。
- **失能即停**：断电前驱动先给这根轴下发一次减速停（正运动 `Single_Cancel` 模式 2），
  避免"失能瞬间还带着速度"。也就是说本步骤的 `Enable=false` 自带一次软停止，
  但它**不是急停**，需要清空待执行队列请改用「轴停止」的急停模式。
- **取值优先级**：所有端口都是「上游链接值 > 界面手填值 > 端口默认值」。
  一次执行内取值只在开头做一次，整步用同一个值，避免中途有人改常量框导致前半句使能、后半句失能。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Axis` | 否 | 逻辑轴名，默认 `X`。下拉候选来自「运动卡设置」里**已启用**的轴（全局唯一名，如 `A0`/`X`/`上料轴`）；可由上游变量给出 |
| `Enable` | 否 | `true`=使能（上电，默认值），`false`=失能（断电）。布尔端口在参数面板的常量框里直接填 `true` / `false`，也可由上游变量决定（例如按配方切换"是否带使能"） |
| `ClearAlarmFirst` | 否 | `true`=使能前先清一次报警（默认 `false`）。用于「已安全停机」后的恢复：清报警成功才继续使能，失败则本步骤失败。**只在使能时生效**（失能是安全动作，不需要清报警） |
| `Timeout` | 否 | 等待超时，默认 `10000` ms（下限 `500` ms，填得比它小按 500 算）。到点没等到结果就判失败 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Enabled` | 操作之后**卡上报**的使能状态（步骤开头先清成 `false`） |
| `Success` | 本步骤是否成功（每个步骤都有） |
| `ErrorMessage` | 失败原因原文（每个步骤都有），可直接连去报警/记录 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

本步骤没有配置属性，四个可调项**全部是输入端口**（步骤的参数面板只列输入端口）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Axis` | `X` | 逻辑轴名。物理轴号与"是哪张卡"由轴名一次解出，流程里不存在选卡/填 IP |
| `Enable` | `true` | true=使能 / false=失能 |
| `ClearAlarmFirst` | `false` | 使能前先清报警（安全停机后的恢复路径）；仅在使能时生效 |
| `Timeout` | `10000` | 等待超时 ms，最小按 500 计 |

## 口径与失败策略

- **单位**：本步骤不涉及位置与速度，没有单位问题；`Timeout` 是毫秒。
- **算不算流程失败**：算。命令被拒绝、等待超时、执行结果不是"完成"、以及
  `ClearAlarmFirst=true` 时清报警失败，都走 `Fail(原因)`
  —— 本步骤 `Success=false`、`ErrorMessage` 给出原因，`Enabled` 保持 `false`（本轮开头已清零）。
- **卡住了怎么表现**：最多等 `Timeout + 500 ms` 就返回失败，不会无限挂着；
  报错文案是 `轴「X」使能超时（>10000 ms）：请检查伺服供电与急停回路`。
- **换卡/改接线不影响流程**：只需改「运动卡设置」里的轴映射，流程里的轴名不用动。

## 典型用法 / 接线

```
（流程首步，上电时序）
本步骤.Axis      ◀── 手填轴名，或 变量定义.AxisName
本步骤.Enable    ◀── 手填 true / false，或上游变量
本步骤.Enabled   ──▶ 轴回零.Axis（同一根轴，用输出端口把轴名带下去，避免手抄错）

链路：轴使能 ──▶ 轴回零 ──▶ 轴运动 ──▶ 等待到位 ──▶ 轴卡 IO（夹紧）
收尾：… ──▶ 轴停止 ──▶ 轴使能（Enable=false，失能下电）
```

`Enable=false` 的那一步通常放在流程末尾或换型分支里；产线上要不要在每班结尾断电，按现场机构要求定。

## 常见问题

**Q：后面「轴运动」报 `轴未使能（请先执行「轴使能」步骤）`，但我明明放了这一步？**
按顺序查三项：① 两个步骤的 `Axis` 是不是**同一个轴名**（大小写不敏感，但抄错字就会打在不同轴上）；
② 使能那一步本轮的 `Success` 是不是真为 true（它失败时后面照样会跑）；
③ 中间有没有「轴停止」勾了急停或「轴使能 Enable=false」把电断了 —— 急停与失能都不会自动重新使能。

**Q：`使能命令被拒绝（Rejected_NotConnected）：…`？**
括号里是命令返回的成员名，冒号后面才是真正的原因（**清报警之外的所有命令都只放行「在线」的卡**）：
`运动卡未连接` → 去「运动卡设置」连接或勾「随方案启动自动连接」；
`运动卡处于报警状态，请先清除报警` → 先清报警再使能（**清报警不会自动使能**，还得回来放一步使能），
把本步骤的 `ClearAlarmFirst` 填 `true` 可以一次做完这两件事；
`运动卡已安全停机，请重新连接后再操作` → 排除停机原因后清报警即可回在线（同样可填 `ClearAlarmFirst=true`）；
若这张卡是增量编码器且还没回零，清报警**不会**放回在线 —— 先重新连接并回零。
另外「未连接」「正在连接」以及**使能时的**「已安全停机」在本步骤入口就被拦下，报的是
`运动卡「…」：{原因}`（没有"被拒绝"那一截；失能不受这条限制，它是安全动作）。

**Q：步骤成功了，但 `Enabled` 却是 false？**
这不是矛盾：本步骤以**设备回报的快照**为准，而快照由卡的状态轮询刷新（卡级默认 10 ms 一轮）。
命令刚完成的那一拍，轴状态可能还是使能前的旧值。要确认真实状态，在后面补一步「读轴状态」读 `Enabled`，
或让流程再走一圈。

**Q：超时给多少合适？**
默认 10000 ms 覆盖绝大多数伺服上电（含制动器打开）。如果现场驱动器上电动作确实慢
（例如带大惯量轴、需要搜到使能延时），把 `Timeout` 加到 20000~30000 ms，不要减小 ——
使能超时后卡的状态不明确，后面接着运动会更危险。

**Q：能不能靠「轴运动」自动帮我使能？**
不能，是刻意做的。上电顺序属于机构语义（先确认安全、先回零、再使能这类要求各家不同），
软件替用户决定就等于替所有现场决定；代价只是流程里多一个节点。

**Q：失能和停止怎么选？**
`失能` = 断伺服的电（轴不再有力矩，竖直轴会掉！），正运动内部会先补一次减速停；
`停止` = 保持使能、只把这次运动中止（「轴停止」步骤，可选减速停/立即停）。
Z 轴、夹具这类"停了不能掉"的场合，正常中断一律用「轴停止」而不是失能。

**Q：多张卡、多根轴要不要每根都放一步使能？**
要。本步骤是**轴级**操作（只动 `Axis` 指定的那一根）。多轴设备常见写法是把各轴的
使能并排放（或用并行分组），再各走各的回零。
