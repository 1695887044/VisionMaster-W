# 轴使能：排障

> 分类：运动控制 ｜ 来源：插件 Plugin.Motion.Steps

下面每条都是**界面上真会出现的原文**（从源码里逐字抄），按"现象 → 为什么 → 怎么改"排。
先看这张分流表，再按行往下查。

## 一、先看这一步在哪一环节挂的

| 环节 | 报错原文的开头特征 | 说明 |
| --- | --- | --- |
| ① 轴名解析 | `没有指定轴名：…` / `没有名为「…」的轴：…` / `轴「…」在卡「…」上处于停用状态：…` | 还没碰卡，纯配置问题 |
| ② 卡状态门禁 | `运动卡「…」：…` | 步骤自己的前置判断（使能只放「在线」；失能放「报警/安全停机」） |
| ②b 使能前清报警 | `轴「…」使能前清除报警失败：…` | 只在你把 `ClearAlarmFirst` 填 `true` 时出现；冒号后面是清报警的失败原因 |
| ③ 命令入队 | `使能命令被拒绝（Rejected_…）：…` / `失能命令被拒绝（…）` | 基类四道闸拦下，括号里是命令结果成员名 |
| ④ 执行与等待 | `轴「…」使能超时（>… ms）：…` / `轴「…」使能失败（…）：…` | 命令进了队列，驱动那边没成 |

## 二、逐条

**`没有指定轴名：请在「Axis」端口填轴名（或用下拉选一个），也可由上游变量给出`**
为什么：`Axis` 的实际生效值是空白（手填框被清空，或上游变量给出空串）。
怎么改：在参数面板把 `Axis` 重新选一个（下拉里只有**已启用**的轴）；如果这一行挂着链接，
先查上游那个变量本轮到底是什么值——链接值优先级高于手填值，手填再对也不会生效。

**`没有名为「A1」的轴：请到「运动卡设置」确认轴名已配置并启用`**
为什么：轴名是**全局唯一**的对外标识，注册表里查不到就是配置里没这个名字（改名、删卡、换方案都会造成这个结果）。
怎么改：去「系统 → 运动卡设置」核对轴名；注意大小写不敏感但**字面必须一致**，
`Al`（字母 L）与 `A1`、`上料轴` 与 `上料 轴`（多一个空格）都算两个名字。

**`轴「X」在卡「…上处于停用状态：请到「运动卡设置」把它启用，或换一个轴名`**
为什么：轴映射里 `Enabled = false`（未接电机的轴可以关掉，就是为了让流程误用不了）。
怎么改：确认这根轴确实接了驱动器再启用；否则换成实际接线对应的那根轴名。

**`找不到运动卡「…」的运行态设备：请确认该卡已在「运动卡设置」里配置并保存到方案`**
为什么：注册表里有这根轴的绑定，但运行态设备表里没有对应卡 Id 的设备——配置改了但没同步，
或方案换了却没重开流程。怎么改：保存方案后回流程重开一次参数面板；仍不行就重连该卡
（运行期 `EnsureSynced()` 会把配置变化同步进设备表）。

**`运动卡服务尚未就绪：请在主程序内运行流程`**
为什么：这条只在**没有注入运动卡服务**的宿主里出现——典型是从设计器/离线宿主单独跑流程，
或流程执行上下文没拿到 `IMotionProvider`（此时是 `NullMotionProvider`）。
怎么改：在主程序里运行（试运行与正式运行都注入同一个服务，见断言
「★正式运行的执行上下文注入了 IMotionProvider（此前永远是 NullMotionProvider）」）。

**`运动卡「…」：运动卡已安全停机，请重新连接后再使能`**
为什么：卡的当前状态是 `SafeStopped`（已安全停机）——命令失败、看门狗超时、失联都会落到这里。
**使能**要求「在线」，所以本步骤在入口就拦下（失能是安全动作，不受这条限制）。
怎么改：先排除停机原因（通信、伺服、机械），再**清一次报警**：底层确实没报警、且位置可信时，
状态会从「已安全停机」回到「在线」。流程里可以把本步骤的 `ClearAlarmFirst` 填 `true`，
让它自己先清报警再使能；也可以先在调试面板手动清一次。
**增量编码器且未回零时清报警不会放回在线** —— 那要先重新连接并执行「轴回零」（位置不可信，不能按绝对坐标运动）。

**`运动卡「…」：运动卡未连接` / `运动卡「…」：运动卡正在连接/断开，请稍候`**
为什么：卡的当前状态是 `Closed`（未连接）或 `Connecting`，这两种状态连"使能/失能"都不允许下发，
所以本步骤在入口就拦下（冒号后面是卡的状态说明原文）。
怎么改：未连接 → 去「运动卡设置」点连接，或勾上「随方案启动自动连接」；连接中 → 等一轮。

**`使能命令被拒绝（Rejected_NotConnected）：运动卡处于报警状态，请先清除报警`**
为什么：括号里是命令结果成员名，冒号后面才是真原因（**除清报警外的所有命令都只放行「在线」的卡**）。
报警态在②这里不会被拦（清报警前往往需要先失能，所以使能/失能允许报警态进入），
但基类闸门会拒绝——这就是"看着像两个地方各说一半"的原因。
怎么改：先清报警再使能（**清报警不会自动重新使能**，使能有机械后果，要人明确点一次）。
把本步骤的 `ClearAlarmFirst` 填 `true` 可以一次做完这两件事：先清报警、成功后再使能。

**`轴「X」使能前清除报警失败：底层仍在报警/限位/急停（…），保持安全停机。请先排除触发原因并复位伺服，再清一次报警`**
为什么：`ClearAlarmFirst=true` 时，清报警不只是"发一条命令"，还会**复核底层报警位**（现读一次轴状态）。
报警位没落下就返回失败——带着报警上电是真机上最不该发生的事。
怎么改：照冒号后面点名的轴与原因处理（限位/急停/伺服报警），复位伺服后再跑一次。
另一种同类原因：`报警已清除，但本卡为增量编码器且尚未回零：位置不可信，保持安全停机` ——
这时要重新连接并执行「轴回零」，清报警本身不会让位置变可信。

**`使能命令被拒绝（Rejected_InvalidArgument）：轴号 3 超出范围（本卡 4 轴）`**
为什么：轴映射里配的**物理轴号**超出这张卡上报的轴数（机型给小了或未识别机型走了兜底值）。
怎么改：核对「运动卡设置」里的机型栏与轴映射的物理轴号；
换了 8 轴的卡（ECI3828）而机型留空时，以控制器上报的型号为准。

**`轴「X」使能超时（>10000 ms）：请检查伺服供电与急停回路`**
为什么：命令进了队列，但 `Timeout + 500 ms` 内没等到完成信号。
本步骤**会等待**——使能失败必须当场知道，否则后面每一步都会以"轴未使能"失败，原因被淹没。
怎么改：现场驱动器上电确实慢（大惯量轴、制动器释放延时）就把 `Timeout` 调到 20000~30000 ms，
**不要往小调**；超时之后卡的状态不明确，接着运动比多等十秒危险得多。
同时要查急停回路：急停按钮按下时伺服不带载，命令会一直等不到回报。

**`轴「X」使能失败（Failed）：轴使能失败（轴 X，正运动错误码 12）。检查伺服供电与急停回路是否闭合；确认轴号与驱动器映射正确`**
为什么：驱动报了失败，括号里是命令状态成员名，冒号后面是驱动给出的"操作 + 轴名 + 原始码 + 建议"整段
（错误码是厂商原始码，**没有**被翻译成"好听的话"——SDK 没有码→文案的接口，凭记忆编对照表只会把人引错方向）。
怎么改：拿那个数字去对正运动手册；文案里带了"轴使能"这个上下文，
因为同一个码在不同操作下含义不同，只看数字容易查错章节。

## 三、"步骤成功了但状态不对"这一类

**步骤 `Success = true`，`Enabled` 却是 `false`**
以设备回报为准是刻意的：命令完成的那一拍，轴状态快照可能还是使能前的旧值（快照由轮询刷新）。
要确认真实状态，在后面补一步「读轴状态」读 `Enabled`，或让流程再走一圈。

**后面「轴运动」报"轴未使能"，但明明放了这一步**
按顺序查三项：① 两个步骤的 `Axis` 是不是同一个轴名；② 使能这一步本轮 `Success` 是否真为 `true`
（它失败时后续步骤照样跑）；③ 中间有没有失能或急停把电断了——**急停与清报警都不会自动重新使能**。

**用「读轴状态」定位，比反复点运行快**
在使能前后各插一步「读轴状态」，把 `Enabled`、`Status`（一句话描述）连去「数据记录」，
一次运行就能看出是"命令没下去"还是"下去了但伺服没应答"。
