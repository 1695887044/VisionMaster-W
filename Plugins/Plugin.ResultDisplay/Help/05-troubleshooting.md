# 结果显示 · 排障

> 分类：常用工具 ｜ 来源：插件 Plugin.ResultDisplay

下面的**告警文案逐字抄自源码**（`ResultDisplayPlugin.cs` 与 `Services\DisplayDraw.cs`），
界面上/日志里看到的句子可以直接在这里查。

**先记住一条总原则**：本算子几乎不会把步骤判失败——"宁缺显示不停线"。
所以**现象多半体现在日志 Warn + 图上看不到东西**，而不是弹错误。排查请从日志开始。

## 图上看不到字

按顺序查这四条：
1. 「显示窗口」是不是填了 `0` —— `0` = **只烧录不发布**（不抢占窗口，但窗口里当然看不到）。
2. 「图上叠字」是不是被取消了 —— 取消后**只画几何/区域/轮廓，文字不画**（文字仍进缩略图信息栏，
   鼠标悬停还能追溯）。
3. 结果项那一行是不是**没连线也没手填值** —— 空值只显示 `(空)`，且**不计入 `DisplayedCount`**。
   日志里对应的写法是 `未接入结果项` / `(无法取值)`。
4. 上游算子本轮是不是失败了 —— 失败步骤的输出端口通常是空的，本算子拿到的就是空值。

## 日志里的告警（不中断本步骤）

| 日志文案 | 为什么 | 怎么改 |
| --- | --- | --- |
| `底图（SrcImage）为空，本轮不发布显示` | `SrcImage` 没接、或上游本轮没出图 | 接底图；确认上游成功。此时 `IsDisplayed=false`、`AnnotatedImage` 为空 |
| `读取底图尺寸失败，本轮不发布显示：…` | 底图句柄异常（`GetImageSize` 抛了） | 换一张图验证；多半是上游给的句柄已被释放 |
| `组装标注内容失败，本轮不发布显示：…` | 攒绘制计划时整体抛异常（类型分派之外的意外） | 看后面的异常类型名；先移除可疑的结果项定位是哪一行 |
| `烧录失败，降级为发布原底图（不带标注）` | 离屏烘焙返回空。**这是降级，不是失败**：用户至少看得到图 | 检查底图类型（见下方"多通道/高位深"一条）；本轮 `AnnotatedImage` 为空 |
| `结果项「X」处理失败（已跳过该项）：…` | 单个元素炸了只丢那一个，不带走整张图 | 看异常类型名定位值类型；把该项停用以确认 |
| `结果项「X」不支持图像值（底图请用 SrcImage）` | 有人把一张 `HImage` 接到了结果项上 | 图像只能进 `SrcImage`；图上会给一行红字提示，同样是为了现场看得见 |
| `结果项「X」不支持的类型 类型名 = 值摘要` | 分派表之外的类型 | 在上游先用脚本/转换算子变成数值或文本 |
| `{种类} 的第 i 个参数非有限值（值），已跳过该元素` | 坐标是 NaN / ±Inf（上游算子发疯） | 该项**整个不进绘制计划且不占预算**；先查上游为什么出非有限值 |
| `…（仅绘制前 N 个元素）`（图上那行截断说明） | 元素数超过「绘制上限」`MaxDrawElements` | **端口数据仍是全量**，只是没画完。想画完就调大上限（夹取 10~2000），但先想清楚几千个元素画上去给谁看 |

## 颜色不对 / 判定项没变红

- **文字全绿、判定项根本没生效**：`JudgeItemLabel` 是**按名字匹配**的（找不到再按 `Id` 找一次）。
  刚刚改过那个结果项的名字 → 判定项里填的还是老名字。重新填一次即可（它是可编辑下拉，允许手填任意名字）。
- **"图上那行字写着 NG、整幅标注却是绿色"**：`NgValue` 的语义比对没命中。
  NG 值认 `NG` / `OK` / `true` / `false` / `1` / `0`，`false` 与 `NG` **同义**（就是为了让这种自相矛盾不出现）。
  两边都能当数字时按数字比（`21` 等于 `21.0`），否则按真假比，再否则忽略大小写按文本比。
- **几何项一直是青色**：这是设计——几何恒青色，**不参与判定换色**（判定只影响文本项）。
- **提示类文字是橙色 / 不该出现的红字**：色名是插件内部的白名单常量（`cyan` / `green` / `red` / `orange`），
  用户字符串不会被当成 HALCON 色名传下去；非法色名一律回落并留告警。

## 导出/存图里为什么没有标注

标注是烧进 `AnnotatedImage` **像素**的，所以「显示窗口」填 `0` 也不影响存图。
检查存图算子接的是不是 `AnnotatedImage`，**而不是原始 `OutputImage`**（那是没烧过的底图）。
导出图目前只支持 **PNG**（无损，字不会被压糊）。

## SCADA 上看不到标注

SCADA 的「图像显示」图元只认 **HImage 像素**，没有覆盖层通道。按顺序查：

1. 「图像赋值」的 `InputImage` 接的是不是本算子的 `AnnotatedImage`——不是原始图。
2. 全局图像变量是不是**每个工位一个**（`Img_ST1`…）；四个页面共用一个 `LastImage` 会互相覆盖。
3. 组态页面的 `Hmi.ImageView.Source` 绑的是不是该工位变量。
4. 如果本算子 `DisplayViewIndex=0` 且 `BakeWhenNotDisplayed=false`，`AnnotatedImage` 是空的——要上 SCADA 就保持 `BakeWhenNotDisplayed=true`。
5. A 类插件（颜色检查/颜色区域/几何查找/几何计算/C# 脚本）的彩色标记：把它们的 `Annotations` 接到本算子的结果项，本算子会把标记一起烧进 `AnnotatedImage`。

图元太小也会让字"看起来没有"：默认 200×160 的框缩 5MP 图约 12 倍，20px 字只剩 1.6px。把图元放大到至少 640×480，或按最终显示尺寸调 `TextScale`。

## 位置与大小

**文字压住要看的工件了** → 把「文字位置」九宫格换成不挡的角落（例如右下）。
只有**数值/文本那一块**会动，几何标签本来就贴着图元、不会跟着跑。
边距想再留宽一点就把「边距」从 `0` 改成具体像素（`0` = 自动：画布高×2% 与 12 像素取较大）。

**字太小看不清 / 想整块放大** → 「字号」填 1.5~2，行距自动跟着放大，几何标签也一起放大
（放大是为了看清，只放大角上的字等于没解决"看不清"）。填 9 会被夹到 3.0、填 0.1 夹到 0.5。

**右对齐的几行没对齐 / 整行被推出画布** → 先确认选的是右列或中列（每一行各自右对齐/居中，
宽度由 HALCON 实测）。若日志里出现量宽失败的告警，那是**退回左对齐**的降级：宁可贴边也不丢字。

**想让某一行单独放到别的位置** → 本算子刻意**不给逐行坐标**：像素坐标在换相机分辨率或改 ROI 之后会
**静默错位**（图上看着正常、位置其实全偏），比"压住工件"更难发现。
正解是再接一个「结果显示」算子，各自选一个角落。

**行太多、块比画布还高** → 首行不会被推到画布外（首行通常是判定项，宁可下面的行看不见）。
真塞不下就调小字号或减少结果项。

## 连线与配置

**编译期报「没有名为 X 的输入端口」** → 动态端口名是**内部 Id**（`r1`/`r2`…），
连线锚在它上面。老方案里那行如果被删掉或停用，口就不存在了，连线自然失败。
改「名字」（`Label`）**不会**触发这件事——它只影响显示文字，不动端口名。

**判定项选了名字、改了一下别的结果项名字，判定项就空了** → 已修：候选列表重填前会记住当前值、重填后顶回去
（可编辑下拉在候选被整体替换的瞬间会清空文本、并把空串推回配置）。若仍遇到，直接把名字重新填进「判定项」框即可。

**想同时在两个窗口显示** → 一个本算子只能发布到一个窗口。要多窗口就放多个本算子
（各自接同一批上游输出），其中一个把「显示窗口」设为 `0` 只出标注图给存图用。

**`>9` 的窗口号** → 会被夹到 `9`：大于 9 的号收得进图集但界面上没有格子显示，夹住比放行好。

## 图像本身

**多通道 / 高位深图** → 产物会按显示口径归一（非 8 位单通道要拉伸，否则整片死白看不出层次）；
4 通道图能烘、不算降级。若日志出现烘焙相关的告警就按文案处理，本算子不会因此停线。

**上游区域/轮廓接进来后画得对，但担心句柄** → 上游给的 `HRegion` / `HXLD` 进的是"对象"层、
用的是**同一个句柄**，插件**不接管所有权**（不会替上游释放）；只有本算子为自己新生成的轮廓才登记待释放、
用完立刻回收。看到"区域画出来了但形状变了"先怀疑上游，不要怀疑这里。
