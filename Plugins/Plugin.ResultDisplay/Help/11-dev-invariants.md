# 结果显示 · 不变量与移植清单

> 分类：常用工具 ｜ 来源：插件 Plugin.ResultDisplay ｜ 读者：开发

每条一律 **症状 → 机理 → 守门断言名**。断言名逐字取自 `FlowCanvasChecks\ResultDisplayCheck.cs`
与 `FlowCanvasChecks\AnnotationBakerChecks.cs`，改代码前先按名字把那条断言找出来。

## A 组：违反就编译期/闸门红

**1. 在插件里自己开离屏窗口**
症状：编译不报错、跑起来也"看起来正常"，但从此有**两份**离屏渲染实现；后来改 baker 时这份不会跟着改，
表现为"同一个标注在别的插件里画歪了"。
机理：AGENTS.md R36——全仓 `OpenWindow` **只许出现在 `Services\Core.Halcon\Helpers\AnnotationBaker.cs`**，
外加一份永久豁免 `Plugins\Plugin.ImageScript\HDevDisplayBackend.cs`（它不是烘焙件，是 HDevEngine 逐条驱动的显示后端）。
豁免清单**只许变短、不许变长**。
守门：`静态扫描④【D9】全仓 OpenWindow 只出现在 AnnotationBaker.cs + N 份豁免里（清单只许变短）`、
`静态扫描④b 豁免清单没有过期项（迁完的文件必须从清单里删掉）`、
`静态扫描④c Plugin.ResultDisplay 自己**零**开窗/dump/SetPart（那属于共享件的职责）`。

**2. `OpenWindow` 的 mode 写成 `'invisible'` / `'visible'` / `'pixmap'`**
症状：HALCON 报 **#1305**，整轮烘焙返回 null（表现为"图上什么标注都没有"）。
机理：离屏烘焙件的窗口 mode **只能 `'buffer'`**。这条纪律只在 baker 里实现一遍，调用方永远不该看到它。
守门：`B1 烘焙产出非 null 且尺寸 == 底图尺寸（200x100）` 起步的那组 B1 断言（mode 写错时 B1 直接红）。
⚠ 与 ROI 交互断言**方向相反**：画布交互只能用**可见窗口**（R53），烘焙才是离屏 `buffer`，别记混。

**3. 反复 open/close 窗口，或想改窗口尺寸**
症状：跑到某一轮**死锁**（#9302），HALCON 不支持改窗口尺寸。
机理：窗口**按尺寸常驻复用**，只在尺寸变化或 `Dispose()` 时才关。
守门：`B3【纪律2 窗口复用】同尺寸连烘 3 轮都成功（没有反复开关窗口）` +
`B7 {N} 轮烘焙全部成功（窗口常驻复用，没有反复开关）`。

**4. 每轮忘了无条件 `SetPart(win, 0, 0, h-1, w-1)`**
症状：**底图缩在左上角、其余全黑**（或整片塌成窗口底色）。
这条在仓库里**真实存活过**：BlobDetect 与 CaliperMeasure 那两份同源实现都漏了 `SetPart`，
实测 `(150,20)=0 (150,180)=0`（期望 100/200）、`(470,320)=0`（期望 255）。
更阴的是它曾被一道**误判的"环境闸门"**伪装成"本环境离屏窗口不渲染底图层次"而长期免检（R38）。
机理：常驻窗口复用时**历史 `dev_set_part` 还会串轮污染**，所以必须每轮**无条件**重设，不能"只在变化时设"。
守门：`B1【纪律3 SetPart】四角像素 == 底图灰度 100（不是窗口黑底、底图没缩进左上角）` +
`B3【纪律3 串轮污染】第 1 轮的线没有残留（行20 附近 max ≤130）`、`第 2 轮的线没有残留（行50 附近…）`。

**5. 文字坐标系用 `"image"`**
症状：整段文字**一个都不画**（不抛、不告警，图上就是没字）。
机理：无显示会话下 `disp_text` 的坐标系**只能用 `"window"`**。
守门：`B2 两次烘焙（带框 / 不带框）都产出非 null` 与 `B2 黑字确实落墨（不带框时 band 最小值 <60）`——
字没画出来时这两条红。

**6. `DispText` 不显式给 `box`**
症状：几何标签被白框盖住被测特征（本该只给文字行加框），或反过来文字没有底框看不清。
**不抛异常、纯静默**——所以必须靠"必填"而不是靠自觉。
机理：实测 **`box` 默认就是开的**（同一行文字 18303px vs 3754px 的墨迹差），
所以真正的风险不是"画不出框"，而是**把决定权交给默认值**。
`BakeText.Box` 因此是 **record struct 的必填位置参数**；
⚠ 参数名是**大写 `Box`**，写成 `box:` 编译报 **CS1739**。字号只能走窗口级 `SetFont`，不能逐条给。
守门：`B2【纪律5 box】显式 Box:true → 文字周围采到接近白的底色框像素（max ≥240）`、
`B2【纪律5 box】显式 Box:false → 同一带内没有白框（max ≤130，只有黑字与灰底）`、
插件侧对应 `文字项带白底框（左上角第一行采到接近白的像素，max ≥240）` + `没写字的地方仍是黑底（右下角 max ≤40）`。

**7. `DumpWindowImage` 的源对象没有立刻 `Dispose`**
症状：跑几百轮之后内存涨到几百 MB（实测 500 次不释放 ≈ **漏 160MB**）。
机理：`new HImage(shot)` 拿到的是独立句柄，但 **`shot` 是源对象**，不释放它就是一直占。
守门：`扫描⑤【160MB 泄漏】每个 DumpWindowImage 的源对象在 5 行内 Dispose`（静态） +
`B7【纪律6 160MB 泄漏】{N} 轮后私有内存增量 <60MB`（运行时，实测 500 轮增量 −4.4MB）。

**8. 改绘制层序 / 在 baker 里塞"结果项"语义**
症状：窗口级状态纪律（`SetLineWidth` 用完还原 1、`SetDraw` 还原 `"margin"`、整段 `lock` 罩住
"改窗口状态 → 画 → 回读"）没法只写一遍，两路绘制互相串色。
机理：层序**固定 `Shapes → Objects → Texts`**，要改就改 `BakePlan` 的入列顺序、**不要改 baker**；
baker 只认识 `BakePlan`，不认识"结果项/判定项/L"。
守门：`A4 HRegion → 进 **Objects**（不是 Shapes；判型顺序 HImage→GeometryParam→HRegion→HXLD→HObject）`、
`A4 HXLD → 进 **Objects**（不是 Shapes）`、`A4 Line → BakeShapeKind.Line 且 P 长 4` 等一整组分派断言。

## B 组：违反不报错，只出诡异现象

**9. 调用方自己估文字像素宽度来做右对齐/居中**
症状：贴边对不上、极端时**整行推出画布**；换字体或换中文就歪。
机理（R39）：文字宽度取决于**窗口当前字体**，而窗口只存在于 baker——插件根本量不到（扫描 ④c 禁止它开窗）。
正解是 `BakeText.HAlign`：`Col` 的含义随对齐变成左边缘/中心/右边缘，换算在 baker 内做并**夹回 `[0, w-1]`**，
量不到就**退回左对齐 + 一条 Warn**（宁可贴边也不许丢字）。
守门：`B8【Right】墨迹右缘 == 给定列 380（±10px，实测宽度才可能这么近）`、`B8【Center】墨迹中心 == 给定列 200（±10px）`、
`B8 三种对齐墨迹同宽（换的是锚点含义，不是内容或字号）`、`B8 垂直不受对齐影响（三种对齐墨迹上缘同行带，±6px）`。
**反过来，垂直分量必须留给调用方**：块高 = 行数 × 行距，行数只有攒完 plan 才知道——
这条边界（"水平归 baker、垂直归调用方"）不许来回搬。

**10. `GetStringExtents` 排在 `TrySetFont` 之前**
症状：对齐偏半个字宽，字号一改就更偏。
机理：字号是**窗口级状态**，没设就量，量到的是上一号字体的宽。
⚠ 本仓 HALCON **没有 `GetTextExtents`**，能用的名字只有 `GetStringExtents`。
守门：`B8 墨迹可测（四种对齐都阈值出非空包围盒）` + `B8【零行为变化】不写 HAlign 与显式 Left 的墨迹包围盒一致（±4px）——四份已迁插件不受影响`
（这条同时是"新增 `init` 属性不能改默认行为"的反证）。

**11. `TextAnchorKind` 的成员顺序被打乱**
症状：选"右下"却画在左上、中带算不出行带。
机理：`DisplayDraw` 用 `(int)Anchor / 3` 取水平带、`% 3` 取列带——**成员顺序即布局**，必须保持"自上而下、每行左中右"、值 0..8。
守门：`静态扫描⑦ 锚点枚举九宫格行主序（Top*→Middle*→Bottom*，值 0..8，中文名与位置一致）` +
`静态扫描⑦b DisplayDraw 确实按 (int)Anchor/3 取水平带、%3 取列带（顺序即布局，所以 ⑦ 值得守）`。

**12. 把 viewIndex `+1` 再发布**
症状："选窗口 1、图进第 2 格"（历史上示例代码写过 `+1`，被部分插件照抄）。
机理：viewIndex **就是界面上的窗口号，直传**。
守门：`A1 事件里的 ViewIndex == 配置值 3（**不加不减**；写过 +1 导致'选窗口1图进第2格'）` +
静态扫描⑥（名字原文是 "PublishPreview 的第 2 个实参没有 +1（viewIndex 直传，防'选窗口1图进第2格'）"）+
`静态扫描⑥b 本插件的 PublishPreview 第 2 实参就是 viewIndex 语义的变量`。

**13. 同一批标注既烧像素又走覆盖层**
症状：图上每个标注**画两遍**（重影、发虚）。
机理（D10）：本算子**只烧录不双发**，发布事件里的 annotations 一律为空。
守门：`A1【D10 只烧录不双发】annotations 一律为空（同一批标注既烧像素又走覆盖层 = 画上两遍）`。

**14. 把底图句柄透传出去，或顺手释放它**
症状：下游拿到的"标注图"其实是底图（不刷新），或底图在别人手里变成空句柄。
机理：`AnnotatedImage` **必须是烧录产出的全新图**；底图句柄归上游，插件不接管。
守门：`C1 产物与底图**不是同一句柄**，且两者都 IsInitialized（D12：烧录产出的是全新图）`、
`C1 发布的就是产物本身（event.Image 与 AnnotatedImage.Value 同句柄）`、
`C1【禁透传口】底图句柄在烧录后仍然可用（没有被插件顺手释放）` + `静态扫描①【禁透传口】Plugin.ResultDisplay 里没有把 SrcImage 的值赋给任何端口`。

**15. 把上游的 `HRegion` / `HXLD` 登记进本轮 `TempObjects`**
症状：本轮结束后上游的区域变成已释放句柄，别的算子下一轮画不出来（跨算子踩脚，最难查）。
机理：`TempObjects` 只收"**本轮为自己新生成**的 XLD"；上游给的对象进 plan 时用的是**同一个句柄**、所有权不接管。
守门：`A4 上游区域的所有权不被接管：不进 TempObjects，plan 里是**同一句柄**` +
`A4 Contour → 生成一条 XLD 进 Objects，且登记进 TempObjects（用完必须释放）`。

**16. 拿用户字符串当 HALCON 色名传下去**
症状：`SetColor` 抛 → **整张标注图丢失**（不是丢一个元素）。
机理：色名必须是白名单常量（`cyan` / `green` / `red` / `orange`），非法一律回落。
守门：`静态扫描③-a 色名常量的字面值全在白名单内`、`③-b 调用点的色名/画法实参全合法（非法色名会让 SetColor 抛 → 整张标注图丢失）`、
`③-c 色名变量/属性的赋值面只由白名单字面量与已验常量拼成`；运行时侧 `A5 判定项命中 NG 值 → 文本转 red；不命中 → 全不是 red；几何恒 cyan（不参与判定换色）` +
`B6 非法色名有告警且明确回落 green（绝不把用户字符串当色名传下去）`。

**17. 非有限坐标"钳一下照样画"**
症状：坐标 NaN 时画出乱窜的笔画；更糟的是被钳制的元素**占用了预算**，导致良品元素被截掉。
机理：NaN / ±Inf 的项**整个不进 plan、不占预算**并留告警；只有**坐标分量**钳进图幅，
**半径原样保留**（钳半径是篡改数据不是保护）。
守门：`A5 NaN 坐标 → 一个图形都不进 plan（**不占预算**），且有告警留痕`、`A5 +Inf 坐标 → 同样不进 plan`、
`A5 超大坐标 → **坐标分量**钳进图幅，半径原样保留（钳半径是篡改数据不是保护）`、
`B6 非法色名 / NaN / 负半径 / 参数个数错 / 空对象 全都不抛异常`、`B6 仍然产出标注图（坏元素只丢自己，不丢整张）`。

**18. 截断说明那一行也占元素预算**
症状：图上一个元素都画不出来（预算全被说明行吃掉），或者"画了一部分"这件事**说不出来**。
机理：超上限时 plan 里只有预算内的图形；标签行 + 1 条截断说明，**说明行不占预算**。
`DisplayedCount` 只数**真画进去**的项。
守门：`A5 元素数超上限 → plan 里只有预算内的图形（5 个 Cross）`、`A5 超上限 → 5 行标签 + 1 条截断说明（说明行**不占**预算，否则这件事本身说不出来）`、
`A5 DisplayedCount 只数**真画进去**的项（5，不是 20）`、`A5 关掉图上叠字 → plan 里零文字，但图形照画、infoRows 照给`。

**19. 配置项没有 Changing 钩子（越界值直接进模型）**
症状：`MaxDrawElements` 填 0 或 99999 时行为不可预期；界面上"填了但不生效"却看不出为什么。
机理：三个排版配置项（`TextAnchor` / `TextMargin` / `TextScale`）必须有 `[StepConfig]` partial 属性 + `…Changing` 钩子，
**越界值在入口就夹住**（夹到 `0~4096` / `0.5~3.0` / 非法枚举回 `TopLeft`）。
守门：`静态扫描⑧ 三个配置项都有 [StepConfig] partial 属性与 Changing 钩子（越界值在入口就夹住）`、
`静态扫描⑧b 本插件的 DisplayDraw.Build 调用把三个配置项透传进去（第 8/9/10 实参）`、
`静态扫描⑧c 视图把三项都绑上了（锚点下拉的数据源也一起查，漏了就是空下拉）`；
运行时侧 `U9 非法锚点夹回左上、边距夹到 4096、NaN 倍率夹回 1.0（钩子在入口挡弹）`。

**20. 加配置项时只改插件、没改视图**
症状：界面上根本没有那一项（或锚点下拉是空的），用户改不到、只能改 `.vms` 文本。
守门：`静态扫描⑧c 视图把三项都绑上了（锚点下拉的数据源也一起查，漏了就是空下拉）`。

**21. 动态端口重建晚于连线编译，或忘了补灌手填常量**
症状：方案打开后连线全断（`[连线错误] 没有名为 X 的输入端口`），或"往返后手填的值丢了"。
机理：`ApplyConfigValues` 三段顺序承重——① base 灌 `[StepConfig]` → ② 按 `Items` 重建动态口
（**必须先于** `FlowCompiler.LinkPorts`）→ ③ 补灌动态口的手填常量（基类遍历 `InputValues` 时动态口还没建）。
守门：`A6 往返后动态端口存在（r1 出厂项 + r2 新增项）`、`A6【§6.4-2 那个坑】往返后**手填常量不丢**（基类遍历 InputValues 时动态口还没建 → 必须补灌一遍）`。

**22. 把"值变了"当成"用户编辑"**
症状：用户什么都没动，判定项连线却自己被解掉；点"取消"也退不回来（改的是活模型）。
机理（R35）：可编辑 `ComboBox` 在 `ItemsSource` 被整体替换的瞬间会清空 `Text` 并沿 TwoWay 把空串**推回绑定源**。
所以 `RefreshJudgeItemLabels()` 必须**只在真的变了才通知**，且**先记住、通知后顶回去**。
守门：`A6 OnConfirm 把结果项表写进了 InputValues（[StepConfig] 快照）` 这一组往返断言；
行为口径本身靠代码评审（`R33`~`R35`），改动时**不要简化成无条件通知**。

**23. 空 catch 吞告警**
症状：显示没出来，但日志一行都没有——现场只能猜。
机理：该吼的必须吼。插件与 baker 两侧**零空 catch**。
守门：`静态扫描② Plugin.ResultDisplay 与 AnnotationBaker 里**零**空 catch（该吼的必须吼）`。

**24. 用"跳过"型断言放过环境差异**
症状：某条像素断言长期显示"跳过：本环境不支持 X"，而真 bug 就藏在那条里。
机理（R38）：`Check(name, true, "跳过…")` 必须先回答"谁证明了是本环境不支持、而不是代码有 bug"。
本轮的先例是 `B1` 已反证 buffer 窗口能铺满底图，于是把 BlobDetect 那道误判闸门删成硬断言，
**当场抓出两条漏 `SetPart` 的真 bug**。
守门：`B1 底图右下角指纹块仍在原位（灰度 ≈180）`、`B4【死白陷阱】产物有灰度层次（全图 range >100，不是整片 255）`
（uint2 不拉伸就是死白）、`B5 4 通道没有触发任何降级告警`。

## 移植 / 扩展清单（要把这套烧图能力接到别的插件时）

1. **只攒 `BakePlan`，不要复制渲染器**：`new AnnotationBaker()` + `Shapes`/`Objects`/`Texts` + `Bake(底图, plan)`。
   历史四份同源实现（BlobDetect / CaliperMeasure / BeadInspect / Matching）已迁完，
   迁完的文件**必须从豁免清单删掉**（否则 ④b 红）。
2. **色名走白名单常量**，画法走 `'margin'` 等已验字面量；SDK 字面量只留在注释与代码块、不进界面承诺（R40-③）。
3. **对齐用 `HAlign`，不要估宽度**；垂直布局（块高、行数、行距）留在调用方。
4. **层序 `Shapes → Objects → Texts` 不改**；要盖住文字就改入列顺序，别改 baker。
5. **上游 HALCON 对象一律不接管所有权**；为自己新生成的对象才登记待释放。
6. **改完必须重建插件工程并核 DLL**：`Modules\Plugin.ResultDisplay.dll` 里 `.Help.` 资源名数要等于 `Help\` 下的 `.md` 数
