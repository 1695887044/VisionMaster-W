# 胶路检测 · 开发：不变量与陷阱清单

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BeadInspect ｜ 读者：开发

**改这个插件前逐条对照**：每条都是"症状 → 机理 → 守门断言名"。
分两类：**A 类违反后当场红或抛**（好查），**B 类违反后不报错、只出诡异现象**（难查）。

守门断言在 `FlowCanvasChecks\BeadInspectChecks.cs`（真样图 `Image\bead` 01..07 + 参考图，
P4 真值表 = 探针实测的错误段总数与四类分布）。断言号 1~17 分段：
几何与建模型（1/2）、检测语义与输出（3~7）、端口面（8）、模型缓存（9）、自动提取（10/13/15）、
毫米口径（11）、拾取几何（12）、夹紧（14）、搜索范围（16）、界面契约与横幅（UI、UI·绑定、17）。
**下面每条引的都是该文件里真实存在的断言名**；没有对应断言的条目明确写"无断言，靠人工核对"。

## A 组：违反会当场红或抛

**A1 端口面是固定契约：输入 5 个、输出 16 个，名字与类型都不许动**
症状：改名/改类型后接线断掉、下游变量引用失效，或输出端口少一个导致 `Outputs.TryGetValue` 拿不到。
机理：端口名一经发布即契约（`InputValues` 的键就是端口名，无映射层）。
守门：`8a 输入端口面：SrcImage/RecipeName/AlignedImage/RoiRegion/Transform（名字+类型锁定）`、
`8b 输出端口面：16 个端口全部就位（名字+类型锁定）`。

**A2 参考路径至少 2 个点，且不许近似重合**
症状：`TryBuildContour` 返回 false → 该轮直接失败；如果新加的形状入口忘了校验，就会在算子层抛英文错误。
机理：折线 XLD 由 `gen_contour_polygon_xld` 生成，点数 < 2 不成线、点几乎重合是退化曲线。
守门：`1a 14 控制点生成非空折线 XLD（P1 折线口径）`、`1b 点数 < 2 → 中文错误（含「至少需要 2 个点」）`、
`1c 点列近似重合 → 中文错误（含「退化」）`、`12d 删点后仍可建模型（13 点 → 折线 XLD + bead 模型构建成功）`。

**A3 `TargetWidth` 必须 ≥ 6**
症状：直接传 4 会抛 HALCON #3716（英文错误，现场读不懂）。
机理：`create_bead_inspection_model` 的 `target_thickness` 合法下界是 6；本插件在 `[StepConfig]` 的
`OnTargetWidthChanging` 里夹到 `6~10000`，算子层再抛一条中文 `ArgumentException` 兜第二道。
守门：`14a TargetWidth 传 4/2/1 都被钩子夹到 6，传 15 原样使用`、
`14b 用夹到 6 的胶宽实际建模型成功（不抛 #3716）`、
`14c 对照：绕过保护直接传 4 确实报 #3716（证明夹取的必要性）`。

**A4 毫米口径不许静默降级**
症状：`UnitOutput=Mm` 却拿不到当量时，若"回退按像素输出"，下游阈值判断会差一个数量级且**没有任何提示**。
机理：`ResolveMmPerPixel` 三条失败路径全部 `Fail`——无来源、`MmPerPixel ≤ 0`、标定图幅与当前图不符。
守门：`11a UnitOutput=Mm 无任何来源 → Fail（中文话术）`、
`11b 标定图像尺寸与当前图不符 → Fail（中文话术）`、
`11c PixelScale 标定只取 MmPerPixel（矩阵全零不影响长度换算）`、
`7 mm 输出 == 像素值 × 当量（容差 1e-9）`。

**A5 NG 是正常结果：`Success` 必须保持 true**
症状：把 NG 写成 `Fail` → 整条流程中断、下游拿不到标注图与明细，产线一个坏品停一台机。
机理：判定只写 `IsOk` / `NgReason` / 数值端口，不碰 `Success`；失败出口只留给"没法算"。
守门：`5-{i:00} NG 语义（Success 仍为 true、NgReason 非空）`、
`4-{i:00} 良品零误报（IsOk=true、NgReason 空、AnnotatedImage 就绪）`。

**A6 对齐参数必须真的传进 find 算子**
症状：界面能改但行为不变 → 现场以为放宽了搜索窗口，实际还是默认 ±0.39rad。
机理：`FindAngleStartDeg * DegToRad` 等在调用处换算后传入 `find_planar_uncalib_deformable_model`。
守门：`16a 默认搜索范围：对齐成功、检出 OK`、
`16b 搜索窗口挪到 90°~100°：对齐失败（证明参数真的传进 find 算子）`、`16c 恢复默认：检出恢复 OK`、
`16d 搜索范围 6 个参数在配置界面可编辑（XAML 绑定齐全）`。

**A7 标注图必须每轮无条件设视区**
症状：底图整片塌成窗口底色，或"上一轮的 `dev_set_part` 串到这一轮"，把黑边烙进像素。
机理：这条纪律不在本插件里，而在共享烘焙件 `AnnotationBaker`；**本插件不许自己开窗**。
守门：`3-01 标注底图逐点保真（两下角与 AlignedImage 一致，底图没被缩进左上角）`。

## B 组：违反后**静默**出错

**B1 配方库的 JSON 解析必须在 `ApplyConfigValues`，不能在 `Initialize`**
流程编译器对运行实例**只调 `ApplyConfigValues`**。解析放 `Initialize` 的话，配置界面看着有配方、
运行内核拿到的是空库 → 报 `未找到可用配方`（这条还算响的）；更坏的是有人为了让"界面显示"而在运行实例上懒加载，
于是库内容随实例而异。
守门：间接——`9a 首轮：bead 与 planar 各重建 1 次`（空库根本走不到重建）。
**另有专门一条断言吗？无断言，靠人工核对**（改动这两个方法时先看 `Matching` 的同款注释）。

**B2 点列变更后必须走 `AfterPathChanged()` 这一个出口**
它一次做四件事：写回 `entry.RefPointsJson`、原位刷新表格行、重画叠加层、更新计数与按钮可用性。
漏掉任何一件 → 画布看着对但**学习用的是旧点列**，或表格与画布分叉（下一次提交表格把画布改动覆盖掉）。
守门：`17e 前置：画布拾取 5 点（点列缓存与点列表格同步、按钮可用）`。

**B3 bead 指纹只能有一个出处（`BeadRecipeEntry.BuildBeadSignature`）**
配置界面的「已学习」用 `LearnedSignature` 与当前指纹比对，运行期缓存键用同一个串。
两处各自手写 → 「参数已变·需重学」永远不消失或永远不出现，且**模型静默用旧参数**跑。
守门：`17e 学习指纹已写入条目（配置态「已学习」与运行态缓存键同口径）`、
`9c 改容差后：bead 重建 1 次、planar 仍复用`。

**B4 句柄必须按指纹缓存，命中时一个都不重建**
症状：每轮重建 planar（实测 100~360ms）→ 节拍被吃掉一大截，但结果是对的，**性能回归不会变红**。
机理：`Ensure…Model` 首行比对 `Runtime…Source`，命中即 `return true`；重建计数器是给断言看的诊断面。
守门：`9a 首轮：bead 与 planar 各重建 1 次`、`9b 第二轮（同参数）：不重建（指纹缓存生效）`。

**B5 删除配方条目必须就地释放句柄**
条目从 `Library` 摘出去之后，`Dispose()` 的遍历再也够不着它 → 非托管句柄泄漏到进程结束。
守门：**无断言，靠人工核对**（`DeleteSelectedEntry` 里那两行 `ReleaseBeadModel` / `ReleasePlanarModel` 不许删）。

**B6 轮首必须手动重置 12 个标量/数组端口**
基类 `AutoDisposeRoundOutputs` 只回收 `IDisposable` 的端口值，`int` / `double` / `string` / `HTuple` 不归它管。
症状：本轮某段逻辑提前 `return`，下游读到**上一轮**的 `ErrorCount` / `NgReason`——
"时对时错"里最难查的一类。
守门：`4-{i:00} 良品零误报（IsOk=true、NgReason 空、AnnotatedImage 就绪）`（残值会让这条直接红）。

**B7 碎段过滤要"计数与轮廓一起丢"**
`MinErrorLength` 只过滤数组不过滤 `ErrorSegments`（或反过来）→ 四类计数与总长口径互相矛盾。
机理：过滤发生在 `length_xld` 之后、累积之前，被丢的段当场 `Dispose`。
守门：`6-{i:00} 四类计数之和 == ErrorCount`、`3-{i:00} 四类计数与真值一致（缺胶/太细/太粗/偏移）`、
`3-07 类型明细 = 偏移3 + 缺胶1（顺序与数组端口逐项对齐）`。

**B8 四个数组端口必须逐项对齐**
`ErrorTypes` / `ErrorLengths` / `ErrorRows` / `ErrorCols` 任一个少拼/多拼一位，下游按下标取数就串行。
机理：都在同一个循环里累积，`SelectObj` 与 `errType[i-1]` 的下标口径不同（**对象序号是第 3 参且 1 起**）。
守门：`3-07 类型明细 = 偏移3 + 缺胶1（顺序与数组端口逐项对齐）`、`3-07 ErrorSegments / BeadContours 输出就绪`。

**B9 `None` 模式下 `aligned` 与 `src` 是同一个引用**
所以给输出端口时写的是 `new HImage(aligned)`（独立句柄）。症状：若把 `src` 原样塞进 `AlignedImage` 端口，
基类轮首回收就会去释放**上游那份图**，下游下一轮拿到已释放句柄。
守门：**无断言，靠人工核对**（`PoseFromMatching` 模式则用 `CopyImage` 复制，同样不许把上游引用直接交出去）。

**B10 角度单位是"度"，弧度换算只发生在调算子处**
症状：界面填 44.69、算子收到 44.69 弧度 → 搜索窗口大到离谱，表现为"什么都能匹配上、误对齐"。
守门：`16b 搜索窗口挪到 90°~100°：对齐失败（证明参数真的传进 find 算子）`。

**B11 自动提取的链路顺序不许换（差分优先、black-hat 回退）**
症状：没填「无胶参考图路径」时若直接抛，用户以为功能坏了；若把两种口径混着用，提取线时好时坏无从解释。
机理：差分 σ=0.96px（贴合最紧），black-hat 只覆盖部分胶条；两者都失败时给**中文原因且不写空点列**。
守门：`10a 自动提取（参考图差分口径）出非空点列`、
`10c black-hat 回退不崩（成功给点列 / 失败给中文原因）`。

**B12 骨架必须做"树直径合并"，不能只取最长一条**
症状：分叉场景下只取最长一条，覆盖率 68.9%（实测）→ 路径少一截，检出静默偏。
守门：`13a 提取成功且骨架段数 > 1（分叉场景成立）`、`13b 树直径合并覆盖率 ≥ 95%（P6 实测 98.2%）`、
`13c 只取最长一条的覆盖率 < 70%（P6 实测 68.9%，证明必须合并）`、`13d 抽稀点数在 40~80 区间（§6.4 ⑧）`、
`15 提取中心线到范例 ContourRef 平均偏离 < 3px（P11 实测 1.98 全点 / 2.18 @40 点）`。

**B13 拾取几何："插到最近线段之间"而不是追加到末尾**
症状：在路径中间补一个点却加到了末端 → 折线折返，模型跟着错，界面看上去还"点了就有色块"。
守门：`12b 直线中段插点：点数+1、插到最近段、走向不变（不折返）`、
`12c 范例路径中段插点：原点列保序、最大转角不变（走向不变）、局部转角<90°、总长偏差<0.1%`。

**B14 `RecipeName` 给了名字就不许回退默认配方**
症状：型号切换失效时**静默用另一款产品的模型**跑——判定结果看着"合理"但完全不可信。
机理：`ResolveEntry` 对"名字非空且库里没有"直接返回 null 并把库里的名单写进错误串。
守门：**无断言，靠人工核对**（改这段逻辑时保持"不静默、不猜"）。

**B15 底图、空态提示、来源文案三者必须同时更新**
`SetBaseImage` 是唯一出口；症状：画布有图但状态栏还写着"尚未载入图像"，或反过来让人不敢拾点。
另附联动：底图不再是"输入图兜底"时要**折叠**坐标系警告横幅，否则横幅与画布自相矛盾。
守门：`17f 平面可变形 + 输入图兜底 → 拾取后横幅警告坐标系风险（「可拾取」的设计不变）`、
`17f 底图切回参考图 → 坐标系警告横幅自动折叠`。

**B16 「学习」的每条返回路径（含成功）都必须写横幅**
症状：点了按钮没反应（历史上真收到过"载入是不是没效果"的反馈）——结论只写在状态栏那行小字里，
在 200% 缩放下落在视口之外。
守门：`17a 配置视图有常驻结果横幅（文字/可见性/级别三个绑定齐全）`、
`17b 平面可变形缺参考图 → 横幅从拾取警告换成「学习失败」/ 红级 / 点名参考图 + 两条对策`、
`17c 点数不足（1 点）→ 横幅说明「至少需要 2 个点」`、`17c 点列为空 → 横幅给出「先拾取至少 2 个点」的去处`、
`17e 可学：成功横幅 + 配方库行「已学习」+ 学习预览非空`、
`17b 现场形态：在输入图兜底上拾取 3 点 → 「学习」按钮可用（IsEnabled 绑的就是 HasEnoughPoints）`。

**B17 矫正四点拾取期间不许被上游图换掉底图**
`RefreshBaseFromInput` 首行判 `QuadPicking`。症状：四点拾到一半底图变成输入图，
记录下来的源点坐标与画布显示不同坐标系，矫正矩阵跟着错，而且**不报错**。
守门：**无断言，靠人工核对**。

**B18 表格回写要等 Binding 提交、且要有行数相等守卫**
`CellEditEnding` 里用 `Dispatcher.BeginInvoke` 再提交；`CommitTableToCache` 判 `_syncingTable` 与行数不等就放弃。
症状：画布批量刷新期间表格提交，会把**别人的点列**写进来（或读到还没提交的旧值）。
守门：间接 `17e 前置：画布拾取 5 点（点列缓存与点列表格同步、按钮可用）`；
**提交时序本身无断言，靠人工核对**。

**B19 配置实例的两个 `ValueChanged` 订阅必须在 `DisposeConfigState` 里成对退订**
症状：配置窗口关了之后仍有回调打进来，访问已释放的 `HImage` → 偶发抛或访问已回收句柄。
守门：**无断言，靠人工核对**（`SrcImage` 与 `AnnotatedImage` 各一对）。

**B20 极性只能是 `dark` / `light` 二选一**
HALCON 建模型只收这两个字面量，不支持同检两种。症状：加第三种取值 → 建模型抛英文错或静默按 dark。
守门：间接 `2a bead 模型构建成功且句柄非空`、`2b 模型参数回读一致（target=15 / tol=8 / pos=30）`；
**"第三种极性"本身无断言，靠人工核对**。

**B21 planar 句柄的释放入口是 `clear_deformable_model`（本机 23.05 无专用入口）**
症状：有人"顺手改成"不存在的 `ClearPlanarUncalibDeformableModel` → 编译期还好，运行期反射/签名问题晚爆。
释放失败**必须留痕**（有 `log` 走 `Error`，否则 `Debug.WriteLine`），静默 `catch` 会让句柄泄漏查不到。
守门：**无断言，靠人工核对**。

**B22 `planar` 指纹要带文件长度 + 写入时间戳**
只带路径 → 同路径覆盖参考图但字节数碰巧不变时缓存不失效，**继续用旧模板**跑（结果稳定地错）。
守门：间接 `9a/9b/9c` 三条；**覆盖文件的场景无断言，靠人工核对**。

**B23 无底图时必须拒绝一切拾取（含删点与拖动）**
"没有图就没有坐标系"。症状：黑屏上点了几个"点"，坐标是 `NaN` 或窗口号，学出来的路径无从解释。
守门：间接 `1b/1c`；**拒绝拾取本身无断言，靠人工核对**。
（另注：`EnsureBaseImageForPick` 里那句 `SetStatus` 的缩进看着像在 `if` 体内、实际是 else 路径——
**读代码时别被缩进骗**，行为是对的。）

**B24 烘焙失败不许把检测判成失败**
`Bake` 返回 null 时只跳过 `AnnotatedImage`，数值端口完好。症状：有人"顺手"给渲染失败加 `Fail`，
一个字体/显示环境问题把整线打停。
守门：间接 `4-{i:00} 良品零误报（IsOk=true、NgReason 空、AnnotatedImage 就绪）`（它要求**正常路径**有标注图）。

## 并行安全声明的依据（`[ParallelSafe]`）

纯视觉计算、无 static 可变字段、不碰进程级独占资源、不写全局共享状态；实例之间不共享配方条目。
`RunAlgorithm` 内没有长阻塞（建模型最贵的一条是 planar 重建 100~360ms，属可接受的一次性成本），
无需分段检查取消令牌。匹配口径提醒：`FlowCompiler` 按类型 **FullName 字符串**匹配该特性，
别把特性写在自己的命名空间副本上。
