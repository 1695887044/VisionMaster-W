# 胶路检测 · 检测口径与调参

> 分类：缺陷检测 ｜ 来源：插件 Plugin.BeadInspect

这一页讲**判定是怎么算出来的**：四类错误段的口径、碎段过滤发生在哪一步、
配方值与插件值谁赢、毫米从哪里来、以及各模式下的坐标系。调参前先看清口径，否则容易拿"真实尺寸"去补误报。

## 一、四类错误段

`apply_bead_inspection_model` 沿参考路径输出左右胶路轮廓与错误段，每段带一个类型字面量（本插件按它分类计数）：

```
no bead              → NoBeadCount       「缺胶」：这一段没检出胶
too thin             → TooThinCount      「太细」：宽度低于目标胶宽一个容差幅度（WidthTolerance）
too thick            → TooThickCount     「太粗」：宽度高于目标胶宽一个容差幅度
incorrect position   → MispositionCount  「位置偏移」：检出位置偏离参考路径超过 PositionTolerance
```

`ErrorTypes` / `ErrorLengths` / `ErrorRows` / `ErrorCols` 里的类型就是这四个字符串原样，
`NgReason` 则把四类按「缺胶 / 太细 / 太粗 / 位置偏移」的固定顺序拼成中文串，段数只列非零的类，
中间用顿号相连（例：`NG：缺胶 2 段、太细 1 段`）。

## 二、一条错误段要经过的三道关

| 关卡 | 判据 | 影响哪些输出 |
| --- | --- | --- |
| ① 类型识别 | 算法给的类型字符串命中四类之一 | 四类计数；命中不了的类型仍计入 `ErrorCount` 但不进任何一类计数 |
| ② 碎段过滤 | `length_xld` 量出的段长 < `MinErrorLength` → **整段丢弃**（不进数组、不进 `ErrorSegments`、不计数） | `ErrorCount`、四个计数、`TotalErrorLength`、`NgReason`、标注图上的红标 |
| ③ 合格判定 | 过滤后**剩余段数为 0** 才 `IsOk = true` | `IsOk` / `NgReason` |

所以"界面上 `ErrorCount` 比算法明细少"不是 bug：碎段在第 ② 关就被扔了，日志里也只有过滤后的总数。

## 三、有效参数的折算（配方优先）

```
目标胶宽   = 配方.TargetWidth   > 0 ? 配方值 : 插件级 TargetWidth（赋值处已夹到 ≥ 6）
胶宽容差   = 配方.WidthTolerance > 0 ? 配方值 : 插件级 WidthTolerance
位置容差   = 配方.PositionTolerance > 0 ? 配方值 : 插件级 PositionTolerance
极性       = 配方.Polarity 非空白 ? 配方值(trim) : (插件级 Light ? "light" : "dark")
```

- 填 0（或留空极性）就是"这条配方跟随全局"；**每个产品单独调**就把配方行填上实际值。
- 这四个有效值连同点列一起构成学习指纹：改了其中任何一个，列表显示「参数已变·需重学」，
  运行期也会按新指纹重建模型（重建的是句柄，不是你的点列）。

## 四、三种对齐模式的口径

| 模式（界面显示） | 谁把图搬回参考位姿 | 需要参考图吗 | 什么时候选它 |
| --- | --- | --- | --- |
| 固定相机（不对齐） | 没人搬，输入图即检测图（不复制、不浪费内存） | 不需要 | 相机与工件位置固定、来料姿态稳定 |
| 匹配位姿 | 上游匹配插件已完成位姿归一化，本算子接它的 `AlignedImage` 并复制一份使用 | 不需要（对齐图由上游给） | 产线已有匹配定位时**首选**：复用它的对齐结果最快也最稳 |
| 平面可变形（投影）（默认） | 内置平面模型 find + 投影变换搬图 | **需要**（模板 + 坐标系基准） | 印刷、柔性件这类有轻微形变/透视的工件 |

「平面可变形」的搜索窗口由 `MinScore` / `PlanarNumLevels` / 起始角与角度范围 / 行列缩放上下限决定。
工件旋转超出默认窗口时，失败文案是 `图像对齐失败：平面匹配未找到匹配实例`——这时才需要动第 ⑤ 张卡，
默认值来自范例实测（起始角 -22.35°、范围 44.69° ≈ 范例的 ±0.39rad），不改也能跑。

第 ⑤ 张卡里两个「分数/层数」参数的口径（配置界面直接可改）：

| 参数 | 默认 | 调大的后果 | 调小的后果 |
| --- | --- | --- | --- |
| 最低分数 `MinScore` | 0.4 | 更严：弱纹理/遮挡多时会把**能用的对齐**也拒掉（报「平面匹配未找到匹配实例」） | 更宽容：可能接受**错位**的对齐，之后表现为整条路径「位置偏移」 |
| 金字塔层数 `PlanarNumLevels` | 5 | 更快，但工件小/模糊时**容易漏匹配** | 更稳但更慢；层数 1 = 全分辨率匹配 |

两者都只在「平面可变形」模式生效；「固定相机」与「匹配位姿」不跑 find，改它们没有效果。

## 五、坐标口径

```
参考路径点列         矫正后参考图坐标系（设了矫正四点时；没设则是原始参考图坐标系）
ErrorRows/ErrorCols  对齐后的参考位姿坐标系
ErrorSegments        对齐图上的轮廓
AnnotatedImage       对齐图打底 + 各层标注（不是原始输入图）
RoiRegion            只缩小处理域，不改变以上任何坐标
```

**底图与点列必须同坐标系**：配置界面画布按四级优先选底图（见界面页），
当底图是"输入图兜底"而模式是「平面可变形」时，拾取的点落在输入图坐标系上，学习会被拒绝——
界面会当场用横幅点名这个风险。

## 六、毫米换算（只发生在输出层）

`UnitOutput` 选「毫米」时，只有 `TotalErrorLength` 会乘上像素当量，判定与逐段长度口径仍是像素：

```
优先级：Transform 端口（标定插件） → PixelSizeMm 参数 → 两者皆无 = 执行失败（绝不静默按像素输出）
Transform 校验：MmPerPixel ≤ 0 → 失败；标定图尺寸 ≠ 当前图尺寸 → 失败（换分辨率/换相机后需重新标定）
Transform 校验（P1-B S1）：去畸变标定（*Undistorted 或带 Intrinsics）→ 失败
PixelScale 型标定只取 MmPerPixel，不用它的矩阵（该模式矩阵除对角线外为 0，无机械坐标含义）
```

**为什么去畸变标定要判失败**：本插件量的是**原始像素**上的胶路长度，乘的是 `MmPerPixel`。
去畸变标定给的当量属于**去畸变之后的图**——两张图在视野边缘差百分之几（kappa=-1500 时角点位移实测约 23px），
直接乘会在边角件上系统性偏，而中间没有任何一步会报错（P1-B S1 的核心诉求就是堵这类静默错数）。
处置：改用不带内参的标定（像素当量 / 九点 / 透视 / 网格），或把去畸变放到采图侧做完再检。
判据单一真源是 `Core.Interfaces` 的 `CalibrationKinds.IsUndistorted`，插件里不复制枚举判断。

`PixelSizeMm` 在配置界面「④ 运行参数」的「像素当量(mm/px)」，界面限 0~1000、填 0 = 视为未填。
它是**兜底**：只要 `Transform` 接了，就轮不到它（标定值优先，且带图像尺寸校验）。

## 六之二、输出对齐图开关

`OutputAlignedImage`（配置界面 ④ 卡勾选框，默认勾选）只控制 `AlignedImage` **输出端口**要不要给图：

```
勾选 → AlignedImage 输出对齐后的图（下游复用可省一次对齐）
取消 → 该端口输出为空；对齐本身照做，AnnotatedImage / 判定 / 各错误段端口完全不受影响
```

所以「取消勾选」不是关对齐，只是不再把对齐结果往外给。

## 七、调参顺序（照现象走，不要反过来）

| 现象 | 先看 | 再调 |
| --- | --- | --- |
| 轮廓贴不上胶沿 | 参考路径是否画在胶中线上；工件姿态变化是否超出对齐能力 | 路径重画；改「匹配位姿」模式并上游接匹配；必要时拾取矫正四点 |
| 整条都判「缺胶」 | 极性是否选反（暗胶/亮胶）；路径是否落在胶上 | 换极性；重画路径 |
| 到处零零碎碎的「太细 / 太粗」 | 是否只是抖动造成的短段 | 先把 `MinErrorLength` 调大滤碎段，再放大 `WidthTolerance` |
| 判定整体偏严 / 偏松 | `WidthTolerance`、`PositionTolerance` | 调这两个容差，**不要先动 `TargetWidth`**（那是真实胶宽） |
| 报「位置偏移」偏多 | 良品样本的偏移分布 | 用 3~5 张确认良品重测偏移上界，留余量后设 `PositionTolerance` |
| 自动提取的线略偏 | 有没有无胶参考图 | 补「无胶参考图路径」走差分口径；没有就回退 black-hat 后手工微调点列 |
| 报「平面匹配未找到匹配实例」 | 工件姿态是否超出搜索窗口；`MinScore` 是否被调高；`PlanarNumLevels` 是否调得太大 | 先放宽起始角/角度范围，再把 `MinScore` 降回 0.4 附近、`PlanarNumLevels` 降到 4~5 |
| 自动提取后点太密 / 太疏 | 「抽稀目标点数」 | 调它（10~500，默认 40）；**只影响本次会话**，重开配置界面回到 40 |

## 八、上线前自检

1. 用几组**已知 NG** 样本回放，确认 `NgReason` 报的类型与现场看到的缺陷一致，再接报警；
2. 需要毫米口径时确认标定链路在线（`Transform` 已连、图像尺寸对得上），否则这一步会直接失败；
3. `DisplayViewIndex` 决定标注图发到主界面几号窗口（0 = 不发，不影响判定与输出）；
4. 想让下游拿到对齐图复用（省一次对齐计算）就保持 `OutputAlignedImage` 为 true，不需要可关（**不影响判定**）；
5. 配方库是"输入 + 指纹"的落盘，模型句柄不随方案存：换机器或路径失效后第一次运行会重建，属正常现象；
6. 「抽稀目标点数」只对本次配置会话有效——**别把它当产线参数**，重开配置界面会回到 40。
