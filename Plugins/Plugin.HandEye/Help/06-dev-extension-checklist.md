# 开发页：移植、扩展与上线清单

本页给"要把这套东西接到新机器人/新相机上"或"要给本插件加功能"的开发者。
按小节顺序做，每一步都有可验证的判据，不要跳。

---

## 一、接到新品牌机器人

### 1.1 先确认三件事

| 事项 | 怎么确认 | 不确认的后果 |
|---|---|---|
| 位姿读数是基座系还是工具系 | 看控制器文档 / 移动一个轴观察哪个数变了 | 整批数据作废 |
| 欧拉角顺序 | 按下面 1.2 的四步核对 | 残差正常但抓取镜像 |
| 角度单位 | 看数值范围：-180~180 是度，-3.14~3.14 是弧度 | 残差虚高或直接失败 |

### 1.2 欧拉约定的四步核对

本插件只支持 **ZYX**（R = Rz · Ry · Rx）。换品牌时按这个做：

1. 机器人摆到 `RX=RY=RZ=0`，记读数；
2. 只把"绕 X 转"那个字段改成 90°，另两个保持 0，记读数；
3. 拿这两个位姿 + 任意相机位姿凑两行数据，跑一次求解；
4. 若报"旋转激励不足"，说明第 2 步动的不是绕 X 那一轴 → 换字段重试，
   直到找到控制器里哪个字段对应"绕 X 转"。

找到映射之后，若控制器用的是别的顺序（例如 XYZ），
**在导出 CSV 前换算成 ZYX**，不要改本插件的求解器——
求解器只认一个约定，多认几种会让"到底按哪个约定算的"变成不可判定问题。

### 1.3 需要改代码的情况

只有当**控制器给的不是欧拉角**（例如直接给四元数或旋转矩阵）时才需要改代码：

- 四元数 → 加一个 `QuaternionToMat3`，在 `TryLoadSamples` 里换掉
  `PoseFromXyzEulerZyxDeg` 的调用；
- 旋转矩阵 → 直接 `Mat3` 逐格赋值，跳过欧拉转换。

两种情况都**不要动 `SolveAXEqualsXB`**：求解器与"位姿怎么表示"无关，
它只吃 4×4。把表示转换放在读取层，是这一层唯一该做的事。

## 二、接到新相机 / 新标定板

相机侧要给出的是**靶标在相机坐标系里的 4×4**，不是像素坐标。

- 内参没标 → 先用「标定」插件的相机内参模式标一次；
- 标定板换了尺寸 → 位姿解算里的板参数要同步，否则 B_i 整体差一个尺度；
- 单位是米 → 乘 1000 换成毫米再写 CSV。

## 三、加断言（必做，不是可选）

本插件上线前必须有断言覆盖。断言放在 `FlowCanvasChecks`，形态是
"引 `HandEyeMath.cs` 源码 + 跑合成数据"。最少要有这五条：

| # | 断言 | 判据 |
|---|---|---|
| 1 | 合成往返 | 已知 X 造数据 → 求解 → 旋转误差 < 1e-9 rad、平移误差 < 1e-6 mm |
| 2 | 无姿态变化必须失败 | 全部位姿相同 → 报"旋转激励不足" |
| 3 | 旋转轴共线必须失败 | 全部绕同一轴转 → 报"共线" |
| 4 | 样本不足必须失败 | 只给 2 组 → 报"样本不足" |
| 5 | 噪声下的质量指标 | 加 0.05 mm 噪声 → 平移 RMS 非零且量级正确 |

第 5 条的意义：如果 RMS 恒为 0，说明质量指标根本没在算，是假绿。

**变异反证**（R65）：改坏一处 → 必须变红 → 还原 → 必须变绿。
只跑绿不做反证的断言，无法区分"真的在查"和"恒真"。

## 四、加 UI 之前必须完成的六件事

这一节回答"新建 UI 前要干嘛"。UI 是最后一步，不是第一步。

### 4.1 数据契约定稿

`CalibrationTransform` 里手眼相关的五个字段必须已经稳定：

| 字段 | 类型 | 含义 |
|---|---|---|
| `HandEyeMatrix` | `double[]?` | 16 元 4×4 **行主序** |
| `HandEyePose` | `HandEyePoseKind` | 眼在手上 / 眼在手外 |
| `HandEyeRotationRmsRad` | `double` | 旋转残差 RMS（弧度） |
| `HandEyeTranslationRmsMm` | `double` | 平移残差 RMS（毫米） |
| `HandEyeSampleCount` | `int` | 参与组数 |

判据：**UI 要显示的每一个数，都必须已经在契约里**。
UI 阶段不允许"先在界面里算一下再显示"——那会让界面成为第二个计算源。

### 4.2 枚举的中文名已就位

`HandEyePoseKind` 的两个成员必须带 `[Display(Name="眼在手上")]` / `[Display(Name="眼在手外")]`。
理由见 AGENTS.md R40/R84：`InputPort<T>` 走 `ForEnum` 读 `[Display]`，
`FlatPropertyGrid` 的 `EnumGenerator` 读 `[Description]`，**两者读的不是同一个特性**。
如果这个枚举既要出现在端口候选里、又要出现在属性面板里，两个特性都要补。

### 4.3 失败原因已经是给人看的句子

`Fail(...)` 的文案就是 UI 上要显示的那句话。所以：

- 不要写"参数错误"这种；要写"旋转激励不足：所有样本的相机侧旋转跨度只有 0°（要求 ≥ 5°）……"；
- 文案里要带**具体数值**与**下一步动作**。

判据：把 `Fail` 的文案直接贴到界面上，操作员能照着做。

### 4.4 设计基线已存在（R127/R128）

按 AGENTS.md §30：**没有设计基线不得改桌面端样式**。
手眼标定的 UI 基线放在 `docs/UI设计基线/手眼标定/`，至少要有：

- `README.md`：版本、确认日期、确认人、覆盖范围；
- 界面结构图（分区/层级/控件形态/文案位置/状态语义）；
- 令牌映射表（颜色/间距/圆角/字号 → `Colors.xaml` 的键）。

判据：基线里能查到界面用到的每一个颜色令牌的键名。
没有这一条，UI 阶段会写出硬编码 hex，被 `UIThemeSmokeTest` 判红。

### 4.5 交互路径已定

手眼标定的 UI 至少要回答这些问题（在基线里写清楚，不要在 XAML 里现想）：

1. 成对数据怎么进？手填路径 / 从上游端口 / 内置表格编辑？
2. 采集中怎么显示"已采几组、还差几组"？
3. 残差超限时是拦住不让保存，还是只提示？
4. 标定结果怎么给下游？只走端口，还是也要落盘一份？
5. 换装法（眼在手上/眼在手外）时，界面哪些字段要跟着变？

第 5 条对应 AGENTS.md R106/R107：**互斥字段集必须"切换字段 + 嵌套子对象"**，
不许把两套装法的字段平铺在同一个类上。

### 4.6 复用件已盘点

按 R141，同一视觉结构第二次出现就要下沉到 `UI\Controls\Themes\Dialog\`。
先查有没有现成的：`DialogColumnCard`、`DialogColumnHeader`、`DialogOptionItem`、
`DialogTag`、`DialogEmptyState`、`DialogIconButton`、`DialogInput`、`DialogCheckBox`。
手眼标定的"成对数据表格"很可能可以直接用现有 `Dialog` 件拼出来，不需要新控件。

## 六、已知边界（写清楚，免得后来人当成 bug）

1. **不做运行期坐标换算**：把相机系点换成机器人系点是 `Plugin.PoseTransform` 的职责，
   本插件只输出矩阵。
2. **不自动剔除离群点**：残差超限就失败，让人看数据。
   自动剔除会在"整批都脏"时悄悄给出一个看起来正常的解。
3. **不支持非刚体**：不做尺度、不做剪切。需要的话先确认物理上是否合理。
4. **断言宿主不连真机**：所有断言都用合成数据，真机验收按「快速开始」第六节做。
5. **CSV 只认 12 列**：不要偷偷支持 7 列（四元数）或 16 列（矩阵），
   多格式会让"这份文件到底是哪种"变成不可判定问题；要支持就换扩展名。
