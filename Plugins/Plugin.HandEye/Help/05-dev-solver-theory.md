# 开发页：AX = XB 的求解原理

本页给开发者：为什么这样解、每一步的数学依据、哪些地方踩过坑。
只关心"怎么用"的读者看前四页即可。

---

## 一、问题的物理来源

设：

- `A_i` = 第 i 个位姿下，机器人法兰在基座坐标系里的位姿（4×4，机器人读数）；
- `B_i` = 第 i 个位姿下，靶标在相机坐标系里的位姿（4×4，视觉解算）；
- `X` = 要求的固定变换（4×4）。

**眼在手上**：相机随法兰动，靶标固定。

```
靶标在基座里的位姿 = A_i · X · B_i     （与 i 无关，因为靶标不动）
```

于是对任意 i, j：`A_i · X · B_i = A_j · X · B_j`，即

```
(A_j⁻¹ · A_i) · X = X · (B_j · B_i⁻¹)
```

记 `α = A_j⁻¹ · A_i`、`β = B_j · B_i⁻¹`，就得到经典的

```
α · X = X · β
```

**眼在手外**：相机固定，靶标随法兰动。同样因为"相机不动"，
`A_i · X · B_i` 恒等于常数，方程形式完全一样，只是 `X` 的物理含义变成
"相机在基座里的位姿"。所以**一套求解器服务两种装法**，区别只在输出的语义标注。

---

## 二、一个必须记住的取逆方向

上面写的是 `β = B_j · B_i⁻¹`——**后一项取逆**。

本插件最初的实现写成了 `B_i · B_0⁻¹`，结果：

- 解出的 X 与真值相差 **1 弧度**；
- 但残差只有 **3.6e-8 弧度**。

原因：错的那一侧在数学上也是自洽的（它对应另一个物理问题），
所以残差检验**根本抓不到**。这个教训写进了源码注释，也决定了验收方式：

> **验收必须是"已知 X 的合成往返"，不能只看残差。**

推论：造测试数据时，生成模型必须与求解器的物理假设**同源**。
早期用 `A = X · B · X⁻¹` 造数据（对应绝对式 A·X = X·B），
与相对式 `α·X = X·β` 不同源，会得到"自洽但错误"的方程组。

正确的造法是：固定靶标 `C`（靶标在基座里的位姿），随机机器人位姿 `A_i`，则

```
B_i = X⁻¹ · A_i⁻¹ · C
```

此时 `A_i · X · B_i ≡ C` 严格成立，任意 X 都能被验出来。

---

## 三、解 α = X 与 β 的旋转

以第 0 组为基准构造相对运动（`α_i = A_0⁻¹·A_i`、`β_i = B_0·B_i⁻¹`），
取旋转部分 `R_αi`、`R_βi`，方程变成 `R_αi · R_X = R_X · R_βi`。

两边取旋转角（对数映射，模长即转角），得

```
log(R_αi) = R_X · log(R_βi)
```

记 `α_vec = log(R_αi)`、`β_vec = log(R_βi)`，就是线性方程

```
α_vec = R_X · β_vec
```

对 n-1 组数据堆起来，用最小二乘求 `R_X`：

```
M = Σ β_vec · α_vecᵀ
R_X = V · Uᵀ    （M = U · Σ · Vᵀ 的 SVD）
```

若 `det(R_X) < 0`，说明得到的是反射而不是旋转，把 `V` 的最后一列取反再乘。

这就是 Park–Martin 方法。它比四元数法更容易看清"为什么需要姿态散开"：
`M` 的秩完全取决于 `β_vec` 张成的方向数。

---

## 四、解平移

旋转已知后，把平移分量单独列出来。对每一组：

```
R_αi · t_X + t_αi = R_X · t_βi + t_X
```

整理得

```
(R_αi − I) · t_X = R_X · t_βi − t_αi
```

堆成 3(n-1) 行的超定方程，用正规方程 `AᵀA t = Aᵀb` 求 3×3 线性系统。
`AᵀA` 的条件数同样受姿态影响：全部相对旋转为零时 `R_αi − I = 0`，方程直接退化。

---

## 五、退化判据（为什么必须有）

| 判据 | 阈值 | 失败原因 |
|---|---|---|
| 组数 | ≥ 3（建议 ≥ 6） | 未知数比方程多 |
| 相机侧旋转跨度 | ≥ 5° | 没有旋转信息，`M` 秩亏 |
| 旋转信息矩阵奇异值比 | ≥ 1e-3 | 所有旋转轴共线，秩只有 1 |
| 旋转矩阵行列式 | > 0 | 得到反射，不是刚体变换 |

阈值的选择依据：

- **5°**：低于这个量级，旋转信号与编码器/解算噪声同阶，解出的 X 会被噪声主导。
  这不是保守取值，是"再低就没有信息"的边界。
- **1e-3**：`σ_min / σ_max`。共线时 `σ_min` 是数值零（实测 1e-17 量级），
  正常数据在 0.1 以上，1e-3 留了三个数量级的余量。

## 六、自研而不是调 HALCON

HALCON 有 `calibrate_hand_eye`，为什么不用：

1. 它要的是 **camera setup model + 标定板观测位姿**的完整链路，
   而本插件拿到的已经是"算好的成对 4×4"。中间再套一层模型，
   等于把"相机内参标定"和"手眼标定"耦合成一个黑盒，现场分不清是哪一步错了。
2. 自研版可以**用合成数据做往返反证**（已知 X → 造数据 → 求解 → 比对），
   HALCON 版本只能看它自己报的误差，没有独立真值。
3. 本模块是纯 `System` 实现，不引 HALCON、不引 NuGet，
   可以直接在断言宿主里跑，不需要 `halcondotnet.dll` 与原生库。

代价是自己维护 SVD 与 Jacobi 特征分解（见下）。

## 七、自研的数值组件

| 组件 | 用途 | 精度实测 |
|---|---|---|
| `JacobiEigenSymmetric` | 3×3 对称阵特征分解 | `|Av − λv| ≤ 8.9e-16` |
| `Svd3` | 3×3 矩阵 SVD | 正交性偏差 = 0，σ 对 90° 旋转得 1,1,1 |
| `TrySolve3x3` | 高斯消元求 3×3 线性系统 | 病态时返回 false，不返回垃圾 |

Jacobi 用循环旋转把非对角元素逐个消到零，3×3 时 10 次扫描足够。
SVD 走 `AᵀA` 的特征分解：`AᵀA = V Σ² Vᵀ`，`U = A V Σ⁻¹`（σ 太小时跳过该列）。

**注意**：`V·Uᵀ` 在正交输入下等于 `Mᵀ` 是**正确的**（最大化 `tr(R·M)` 时 `R = Mᵀ`），
不要误以为是转置写错了。这个坑我在写诊断用例时踩过一次。

## 八、质量指标怎么算

解出 X 之后回代：

```
残差旋转 = angle( R_αi · R_X − R_X · R_βi 对应的旋转角 )
残差平移 = | (R_αi · t_X + t_αi) − (R_X · t_βi + t_X) |
```

取 RMS 与最大值。RMS 反映整体噪声水平，最大值用来发现单点错点
（本插件只上端口 RMS，最大值在 `Quality` 结构里，供断言使用）。

## 九、实现清单

| 文件 | 内容 |
|---|---|
| `HandEyeMath.cs` | 纯数学：`SolveAXEqualsXB`、`EulerZyxDegToMat3`、`PoseFromXyzEulerZyxDeg`、`Svd3`、`JacobiEigenSymmetric`、`Vec3`/`Mat3`/`Mat4` |
| `HandEyePlugin.cs` | 配置（含成对数据表 `Samples`）、表格 → 数学样本、残差门、组装 `CalibrationTransform` |
| `Models/HandEyeSample.cs` | 表格一行的模型（12 个 double + `IsBlank` + `ToMathSample`）；`ToMathSample` 是全仓唯一的「一行 → 数学样本」入口 |
| `HandEyeCsv.cs` | CSV 文本 ↔ 行集合，**不碰文件**（选文件、编码、覆盖确认归视图层） |

`HandEyeMath.cs` **不引任何外部依赖**，可以直接被断言工程 `Compile Include` 进去跑，
这是它刻意保持独立的原因。

`Mat3` 是 `sealed class` 且只有无参构造——构造一个旋转矩阵要逐格赋值，
不要试图写 9 参构造（会与已有的 `FromRows` 之类的辅助方法冲突）。
