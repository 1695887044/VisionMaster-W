# 手眼标定：残差、失败原因与排查

本页教你看懂"为什么失败了"，以及"没失败但结果不对"该怎么办。
先记住一句：**残差小不代表解对**。残差只说明"这批数据自洽"，不说明"这个方程是对的"。

---

## 一、四个输出各说明什么

| 输出 | 说明 | 什么时候看它 |
|---|---|---|
| `RotationRmsDeg` | 旋转残差 RMS（度） | 判姿态数据干不干净 |
| `TranslationRmsMm` | 平移残差 RMS（毫米） | 判点位数据干不干净 |
| `UsedPairs` | 参与求解的组数 | 判样本够不够 |
| `Transform` | 4×4 + 残差 + 装法 | 给下游用；失败时为空 |

残差的算法：把解出的 X 代回每一组 `A_i · X` 与 `X · B_i`，
比较两者的旋转差与平移差，取均方根。所以它是"这批数据自己跟自己的差"，
**不包含任何外部真值**。

## 二、失败原因逐条对照

### 2.1 还没有成对数据

```
还没有成对数据：在表格里加一行，或点「导入 CSV」
```

表格是空的。手采就在表格里逐行加，成批就从 CSV 导进来。

### 2.1b 某一行还没填

```
成对数据第 3 行还没填（12 个值全为 0）：填完或删掉这一行再求解
```

加了一行但没填数。这条单独报出来是有原因的：全 0 的行会让求解结果崩掉，
如果不拦住，用户看到的会是「旋转残差 15° 超过上限」——然后跑去怀疑机器人姿态、
去查欧拉约定、去问是不是单位错了，其实只是忘填了一行。

### 2.1c CSV 解析失败

```
第 2 行有 11 列，应为 12 列
第 4 行第 7 列不是数字：「abc」
```

导入 CSV 时的格式错，文案带行号与列号（行号按文件行数，含表头）。

### 2.3 格式错

```
成对数据第 7 行有 11 列，应为 12 列：512.3,120.8,...
```

```
成对数据第 9 行第 5 列不是数字：「-3.1度」
```

按提示改那一行。列数不对通常是末尾多/少一个逗号；
某格不是数字通常是粘了单位，或者用了千分位。

### 2.4 组数不足

```
成对数据只有 4 组，少于建议的 6 组：3 组能解但不可靠，请补到 6 组以上（或关掉「要求建议组数」自担风险）
```

数学下限是 3 组，但 3~5 组解出来的结果对噪声极其敏感。补数据，或者
明确接受风险后关掉「要求建议组数」。

### 2.5 旋转激励不足（最需要理解的失败）

```
旋转激励不足：所有样本的相机侧旋转跨度只有 0°（要求 ≥ 5°）。
请让机器人以不同姿态取点（只平移或每次都回到同一姿态无法解出旋转）
```

这条不是"数据脏"，而是**数据里根本没有旋转信息**。机器人只平移、或者每次都回到
同一个姿态时，方程退化，旋转分量不可观。此时任何"解"都是噪声放大后的垃圾。

修法：重新采，让机器人在 RX/RY/RZ 三个方向上都有明显变化（各方向 15° 以上比较稳）。

### 2.6 旋转轴共线

```
旋转求解失败：旋转信息矩阵奇异（最小奇异值为 0），所有样本的相对旋转共线
```

所有姿态都绕着**同一根轴**转（例如只在一个平面内倾斜）。几何上无法唯一确定 3 个旋转自由度。
修法：让旋转轴换方向，例如既绕 X 倾、又绕 Z 转。

### 2.7 残差超限

```
旋转残差 31.146° 超过上限 0.5°（按「眼在手上」求解）：姿态数据可能含错点/角度单位不对/
欧拉约定不符；也可能是装法选错了——先核对「眼在手上 / 眼在手外」
```

```
平移残差 3.5 mm 超过上限 1.0 mm（按「眼在手外」求解）：点位数据可能含错点、机器人未回零，
或装法选错了
```

求解成功但质量不过关。括号里的「按某装法求解」不是装饰：**同一批数据换个装法算出
来的残差能差一个量级**，看不到按哪种算的就没法判断下一步该查什么。
按下面的排查表走。

---

### 2.8 结果已过期（琥珀色，不是失败）

```
结果已过期    上次标定 2026-10-23 01:02。成对数据或门槛在那之后改过，所以旧矩阵不显示。
```

这不是求解失败，是**方案里存着一份上次确认过的标定结果，但它已经不对应当前数据了**。

- 触发：打开方案后改了任意一个数字、加了/删了一行、换了装法、动了两个上限或组数门。
- **16 个数故意不显示**（全显示 `—`）。旧矩阵拿出来看就是在骗人——数据变了，矩阵也该跟着变。
- 想恢复：点右边的「重新求解」按当前数据重算，看到「完成」后再点「确定」把新结论存进方案。
- 为什么不是「未求解」：那样会让人以为从没标定过，跑去重采一遍。过期态明确告诉你"标过、但作废了"。

结果与数据同生共死：方案里存的不是一串裸数字，而是**数据指纹 + 结果**；指纹对得上才认。

## 三、残差偏大的排查顺序

按"最容易错、最容易查"的顺序排，不要跳步：

0. **装法**：先看报错括号里写的是哪种装法，和现场实际对不对。把「装法」切一下再点求解，
   如果残差从几十度掉到零点几度，那就是装法选错了，数据本身没问题。
   （这一步排在最前，因为它只要点一下；而下面几条都要回去翻控制器或重新采集。）
1. **角度单位**：CSV 里有没有一半写弧度？把每一行的角度值看一眼，
   正常应在 -180~180 之间，出现 0.78 / 1.57 这种小数多半是弧度。
2. **欧拉约定**：控制器给的顺序是不是 ZYX？按「装法与坐标系」第五节核对三个符号。
3. **错点**：把每一组的残差单独看一遍（本插件只给 RMS，逐组残差需要自己用矩阵回代），
   通常只有一两组明显偏大，删掉重跑就正常了。
4. **靶标动过**：采集中途靶标被碰过。这种情况残差会**整批**偏大，删单点没用，只能重采。
5. **机器人未回零**：开机没回零，位姿读数带偏移。
6. **相机内参没标或标错**：相机位姿本身就不准，误差会被吸收进矩阵。

## 四、残差正常但结果不对

这是最麻烦的一类，因为它不报错。可能的原因：

| 现象 | 原因 | 怎么确认 |
|---|---|---|
| 抓取点整体差一个臂长量级 | 装法选反了 | 换另一种装法重跑，比较两次的输出量级 |
| 抓取点整体镜像 | 欧拉角某个轴的符号错 | 按「装法与坐标系」第五节核对 |
| 换位姿误差就变 | A/B 不是同一时刻的数据 | 检查采集流程是否"停稳再拍" |
| 只在某一片区域偏 | 数据集中在一小块工作空间 | 把采样点铺开到实际工作区域 |

**唯一的可靠验收方式**是「快速开始」第六节那个已知点核对：拿一个能同时被相机看到、
又能被机器人尖端点到的特征点，走一遍矩阵，比较计算值与实测值。
要求小于工艺公差（抓取类通常 0.5~1 mm）。

## 五、这次求解用了哪些防护

本插件在求解前后做了这些检查，任何一条不过就明确失败，不会"给个大概的数"：

1. 组数下限（默认 6，可放宽到数学下限 3）；
2. 相机侧旋转跨度 ≥ 5°（否则判"旋转激励不足"）；
3. 旋转信息矩阵的最小奇异值 / 最大奇异值 ≥ 1e-3（否则判"共线"）；
4. 旋转矩阵行列式必须为正（否则判"反射，不是刚体变换"）；
5. 求解后残差与上限比对。

**它不会做的**：不会自动剔除离群点，不会在失败时返回上一次的解，
不会把 6-DOF 悄悄降级成平面仿射。失败就是失败，下游必须自己判空。
