# CSV记录 · 开发不变量

> 分类：数据处理 ｜ 来源：插件 Plugin.DataRecord ｜ 读者：开发

每条按 **症状 → 机理 → 守门断言名** 三段写。
先说清一件事：**`FlowCanvasChecks\` 里没有针对本插件的专属断言文件**（既没有 `DataRecordChecks.cs`，也没有等价于
「结果显示」那种按插件立项的闸）。能在 CI 里挡住本插件改坏的，只有**手册闸门 HM 系列**（`HelpManualCheck.cs`）、
**产物守门 P31**（`ParallelExecutionChecks.cs`）以及**一条跨插件的 A2**（`ResultDisplayCheck.cs`）。
其余条目一律标注"无断言，靠人工核对"，**不要假装有更硬的闸**。

## A 组：确实有闸的

**A1｜手册改了但没进 DLL**
症状：宿主帮助窗口还是旧页，或该插件的分组是空的。
机理：`Help\*.md` 靠工程文件里的 `EmbeddedResource` 打进 DLL，宿主按插件类型收窄读取。
守门断言名：`HM4 有 Help/*.md 的工程都带 EmbeddedResource（手册进得了 DLL）`、`HM10 宿主按插件类型收窄内嵌手册（分册机制在位）`。

**A2｜开发页文件名没带 `dev-` 段**
症状：开发章节不出现，或用户页里混进实现细节。
机理：宿主靠文件名里的 `dev-` 标记识别开发页并裁树。
守门断言名：`HM12 开发页文件名是 NN-dev-xxx.md（宿主认得出这是开发章节）`、`HM14 开发章节显隐链路四处齐全（标记→节点→裁树→开关→配置）`。

**A3｜在 `Help\` 下建了子目录**
症状：用户页被挤掉，只剩开发页；或分册认不出来。
机理：本程序集只有一个插件类（`DataRecordPlugin`），扁平 `Help\` 是合法形态；建子目录是分册形态（`Help\某插件类名\`），名字必须逐字等于类名。
守门断言名：`HM12b 手册最多一层目录（开发页另立子目录会挤掉用户页）`、`HM2 多插件程序集不许放扁平手册（防串页）`、`HM3 Help 子目录名逐字等于插件类名（分册能被认出）`。

**A4｜页首行不是 H1，或页序前缀乱了**
症状：宿主页名取不到、导航顺序漂移、同序号两页互相覆盖。
机理：页名取第一行 H1，页序只由 `NN-` 前缀决定。
守门断言名：`HM5 每页第一行内容就是 # 一级标题（页名取得到）`、`HM6 手册文件名是 NN-xxx.md（页序确定）`、`HM6b 同一分册内 NN- 前缀不重复（页序唯一）`。

**A5｜编码坏掉（BOM / CRLF / 非法 UTF-8 / 整页无中文）**
症状：宿主读到乱码，或闸门红。
机理：仓内纪律要求无 BOM 合法 UTF-8。
守门断言名：`HM7 手册都是无 BOM 的合法 UTF-8 且含中文（编码纪律）`。

**A6｜留了占位标记，或册子太薄**
症状：交付的其实是随笔页。
机理：M 档下限是用户 4 页、开发 2 页、开发合计 150 行；每个插件正文另有 70 行地板。
守门断言名：`HM9 手册里不许出现占位标记（这条闸门的名字原文自带那五个禁用词，此处刻意不照抄——照抄会让 HM9 自己变红）`、`HM8 每个插件的手册正文 ≥ 70 行（不是占位页）`、`HM13 已交的开发章节达到所在档位的行数下限（L300/M150/S100，交了就不是随笔）`。

**A7｜档位表与本插件脱钩**
症状：`HelpManualCheck` 报未登记或过期条目，台账失真。
机理：`["DataRecordPlugin"] = ManualTier.M` 必须与插件类一一对应。
守门断言名：`HM16 档位表与插件类一一对应（无未登记、无过期条目）`、`HM17 骨架完整度台账（按档位，欠账不判红）`、`HM1 每个插件类都有自带手册（无兜底自动生成页）`。

**A8｜改了源码没重建 DLL（本插件标了 `[ParallelSafe]`）**
症状：宿主并行编译把「CSV记录」报成"并行不安全"，明明源码有标注。
机理：门禁在 DLL 字节里找 `ParallelSafeAttribute`；漏重建就是陈旧产物。
守门断言名：`标注 [ParallelSafe] 的 18 个插件 DLL 全部含特性元数据（漏重建=门禁误报）`（P31），另见 `P12：未标注算子进 Parallel 分支 → 编译错误含[并行不安全]`。

**A9｜上游"显示"算子改了，导致记账拿不到带标注的图**
症状：`仅NG存图` 存出来的是原图而不是标注图，或反过来账本有路径但图没了。
机理：`DisplayViewIndex=0` 时 `IsDisplayed=false`，但 `AnnotatedImage` 仍要照算，下游「CSV记录」正是那个消费方。
守门断言名：`A2 DisplayViewIndex=0 → IsDisplayed=false，但 AnnotatedImage 照算（下游 CSV记录 仍能存带标注的图）`。
说明：这条闸守在「结果显示」侧，本插件改动不会触发它——**接线口径变了要回那边确认**。

## B 组：无断言，靠人工核对

**B1｜连线编译期找不到端口**
症状：方案加载后连线丢失，或编译报 `[参数缺失]`。
机理：`ApplyConfigValues` 必须"先基类灌 `[StepConfig]`，再 `RebuildDynamicInputs()`"，且动态端口 `IsRequired = false`。顺序写反或忘了非必填，就分别导致"端口还没建就来连线"和"未连线的列被判参数缺失"。
守门：无断言，靠人工核对（改这段后手工加载一份含连线的老 `.vms` 看连线是否健在）。

**B2｜列名带首尾空格 → 端口名与表头一起脏**
症状：账本表头某列名字怪、重连不上。
机理：`RebuildDynamicInputs` 用**未 Trim** 的 `col.Name` 建端口（与「结果上报」字段表不同）。
守门：无断言，靠人工核对。

**B3｜`PortsVersion` 通知丢失**
症状：改完列定义，行内连线控件还指着已被移除的端口对象，连上也不生效。
机理：端口对象是新实例，绑定只能靠计数器通知重建。
守门：无断言，靠人工核对。

**B4｜序号被空耗 / `{序号}` 没被替换**
症状：日志里序号一直涨但账本没有序号列；或图片文件名里出现字面 `{序号}`。
机理：`needSeq` 只看内置序号列与图片模板里的 `{序号}`/`{Sequence}` 两种情形，判定漏了就残留字面量；反向漏了则白耗全局号。
守门：无断言，靠人工核对。

**B5｜图片副本泄漏或双重释放**
症状：长跑内存涨，或 HALCON 句柄异常。
机理：副本有三条归宿（Hub 落盘后 Dispose / 入队被拒 Hub Dispose / 行阻断时插件 Dispose），漏一条就坏。
守门：无断言，靠人工核对。

**B6｜`ImagePath` 列写成空**
症状：记录方式已开、图也存了，账本"图片路径"列还是空。
机理：三遍式的顺序是硬约束——第一遍先给 `ImagePath` 占位并记下下标，第二遍算出路径，之后**回填**。把回填挪到入队之后就丢了值。
守门：无断言，靠人工核对。

**B7｜"仅NG存图"一张都不存**
症状：`ShouldSaveImage` 恒假。
机理：比的是**格式化之后**的文本，且列名匹配区分大小写、NG 值比较不区分大小写——两种大小写口径同时存在，改动时极易统一错方向。
守门：无断言，靠人工核对（把布尔判定列接进来时先确认落笔是 `True`/`False`）。

**B8｜表头重复写或老文件被改结构**
症状：同一个 CSV 中间又冒出一行表头。
机理：写表头的判据是 `!File.Exists(path) || new FileInfo(path).Length == 0`；`FileMode.Append` + `FileShare.ReadWrite` 也不能换成 `Create`（那是覆盖，账本会被洗）。
守门：无断言，靠人工核对。

**B9｜行交织成半行**
症状：CSV 出现字段错位的破损行。
机理：安全性来自"只有**一条** CSV 写线程串行落盘"。把写线程改成多实例并行、或按 target 分线程，同一文件就会被两个写者撕裂。
守门：无断言，靠人工核对（这条也是 `[ParallelSafe]` 标注成立的前提）。

**B10｜中枢日志永远看不见**
症状：出问题只见到步骤失败文案，没有 `[数据记录]` 系列。
机理：静态中枢没有 `context`，日志暂存在 `Logs`（上限 2000，溢出丢最旧），只能在下一次执行该步骤时投递。新增静态日志就要确认它落在投递路径之后。
守门：无断言，靠人工核对。

**B11｜重启后序号回绕、图片撞名**
症状：`DataRecord_seq.json` 里数字比实际小。
机理：边车每前进 50 号才写一次，退出/关停强刷；`NextSequence()` 里 `EnsureStarted()` 保证"只取号未入队"也挂了退出钩子。去掉这个钩子就会回绕。
守门：无断言，靠人工核对。

**B12｜小数点变逗号、列错位**
症状：某些机器上账本列全部右移。
机理：`FormatCell` 与日期展开一律 `CultureInfo.InvariantCulture`。新增分支时顺手用 `ToString()` 就引入当前区域性。
守门：无断言，靠人工核对。

**B13｜占位符被短 token 截胡**
症状：`{yyyy-MM}` 展开成 `2026-MM` 这种半截值。
机理：`ExpandTemplate` 靠**长 token 先替换**的固定顺序（`{StepName}` → `{yyyy-MM-dd HH-mm-ss}` → `{yyyy-MM-dd}` → `{yyyy-MM}` → `{yyyy}` → `{MM}` → `{dd}`）；一旦短 token 先跑，长占位符里重合的前缀就被吃掉。新增占位符必须插在可能截胡它的短 token 之前。
守门：无断言，靠人工核对。

**B14｜清理把客户账删了**
症状：`已删除 N 个过期文件` 数目离谱。
机理：`RunCleanup` 只在 `KeepDays > 0` 时按 target 每天一次；CSV 只认文件名里 `\d{4}-\d{2}-\d{2}` 的日期，图片目录按 `LastWriteTime` 判旧并顺带删空子目录（`AllDirectories` 扫描）。放宽任何一条判据都会扩大删除半径。
守门：无断言，靠人工核对。

**B15｜枚举加了成员但界面显示英文**
症状：下拉里出现 `ImagePath`、`Every` 这种本名。
机理：`ColumnSource` / `BuiltInField` / `ImageSaveMode` 都**没有** `[Display(Name)]`，中文全部来自视图里的 `CnEnumLabelConverter` 字典；加成员必须同时补字典。用户册里也不许声称"已中文"。
守门：无断言，靠人工核对（补 `[Display]` 属全仓 R40 欠账，另议）。

## 改这个插件之后的必做动作

| 动作 | 怎么做 |
| --- | --- |
| 重建 DLL（含 Help 资源） | 改过 `*.cs` 或 `Help\*.md` 都必须重建，P31 与 HM4 都在查产物字节 |
| 跑手册闸门 | 跑一次常规 gate 基线（`FlowCanvasChecks` 全量运行里没有独立开关，`HelpManualCheck.Run()` 随基线执行），HM0~HM17 全绿 |
| 手工回归一次落盘 | 新建流程 → 三列出账 → 连一个布尔判定列 → 记录方式改"仅NG存图"且 NG值改成 `False` → 跑一轮 → 看 csv 与 img 目录 |
| 手工回归一次旁路 | 用 Excel 独占打开当天账本再跑一轮，确认 `_conflict1.csv` 与那条 WARN 文案 |
| 同步用户册 | 参数、口径、日志原文三张表逐字对齐（见架构页第八节） |
