# OCR 文本识别

> 分类：图像处理 ｜ 来源：插件 Plugin.Ocr

在框选的识别区里把一行字符**逐个切开**，再用内置分类器**认字**，产出识别文本、字符数、平均置信度与逐字符明细。
它认的是**人类可读的印刷字符**（内置模型：数字 0-9 与大写字母 A-Z），用于读料号、日期码、批次号、铭牌。
判定（合格与否）**不由本插件做**——它只报告"认到了什么"，比对与放行交给下游的比较节点或脚本。

## 为什么需要它 / 原理

机器视觉里三件事各有分工：模板匹配解决"目标在哪"，码读取解决"码里编码了什么"，而 **OCR 解决"印出来的字是什么"**。

OCR 的关键认知是：**切字（分割）决定成败的九成，认字只是一行调用**。
- 字切对了 → 分类器很成熟，基本认得准；
- 字切错了（两字粘成一块、一字断成三截、把背景纹理当字）→ 再好的分类器也只能给出一串看似正常的错字符。

所以插件分两层，且所有"能拧的螺丝"都集中在切字这一层：
1. **分割层**——把识别区裁剪出来，转灰度，按极性二值化（暗字/亮字），可选做闭运算/腐蚀/膨胀把散点焊合或把粘连断开，再走连通域拆字、按"高度→宽度→面积"三档筛选，最后按阅读顺序排序；
2. **识别层**——把排好序的字符区域喂给 MLP 分类器，一次性拿到每个字符及其置信度。

排序这步是必需的：分类器返回的字符顺序与喂进去的区域顺序一一对应，**没排序就会拼出一串乱序文本、而且不报错**。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | 否（端口层标记非必填） | 待识别的图像（`HImage`）。运行期由上游连入；**没有图会直接失败**，报"上游没有图像"。彩色图也允许直接连进来，内部会自动转灰度 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Text` | 逐字符拼出的识别文本；**被拒识的字符在原串里不可见**，要看清每一位用 `Detail` |
| `Count` | 字符数（**含**被拒识的字符） |
| `Confidence` | 平均置信度（0~1），各位字符置信度的算术平均。低置信 = 本次结果不可信 |
| `Detail` | 逐字符明细，格式 `序号:字符(置信度)`，用空格分隔；**被拒识的字符显示为 `?`** |

> 本插件**不输出字符框 / 标注图**（未做位置投射）。要看"切在哪、认成什么"，靠 `Detail` 逐字定位；配置界面里的「试算」会直接把明细显示出来。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `RoiParams` | 空 | 识别区形状，按 HALCON 矩形约定 `[中心行, 中心列, 角度(弧度), 半长, 半宽]`。在配置界面的图上右键 → 新建矩形即可回写，不建议手填。角度非 0 就是给歪着的字行用的 |
| `TextIsDark` | `true` | 极性：`true` = 暗字亮底（工业最常见的打码方式），`false` = 亮字暗底。**选反了一个字都切不出来** |
| `MinCharHeight` | `8` | 字符最小高度（像素）。按实际字符尺寸收紧，能挡掉背景纹理与脏点 |
| `MaxCharHeight` | `300` | 字符最大高度（像素） |
| `MinCharWidth` | `4` | 字符最小宽度（像素） |
| `MaxCharWidth` | `300` | 字符最大宽度（像素） |
| `UseFixedThreshold` | `false` | `false` = 自动阈值（按直方图双峰找分界），`true` = 用下面的固定阈值。光照均匀时自动即可，光照不匀时再切固定 |
| `FixedThreshold` | `128` | 固定阈值：暗字时取灰度 ≤ 本值，亮字时取 ≥ 本值。仅在 `UseFixedThreshold = true` 时生效 |
| `MinArea` | `20` | 字符最小面积（像素²），三档筛选的最后一道 |
| `MaxArea` | `5000` | 字符最大面积（像素²） |
| `ClosingRadius` | `0` | 闭运算半径（像素）——**点阵 / 喷印字焊合散点的首选**。先扩后缩，点连上了、字形尺寸基本还原。实心印刷字留 0；点阵喷印从 1.5 起试 |
| `ErosionRadius` | `0` | 腐蚀半径（像素）：印刷字粘连时先腐蚀断开 |
| `DilationRadius` | `0` | 膨胀半径（像素）：笔画过细时加粗。**注意它会外扩字形**，点阵字要的是"连接"不是"加粗"，请优先用 `ClosingRadius` |
| `ModelPath` | 空 | 外部模型文件（`.omc`）路径。**留空 = 用内置模型（0-9 / A-Z，带拒识）**；填了就改用指定模型（如中文 / 自训练模型） |
| `ColumnFirst` | `false` | `true` = 按列优先排序（竖排文本），`false` = 按行优先（横排，默认） |

> 界面上的开关（暗字亮底 / 固定阈值 / 竖排）是勾选框，`.vms` 流程里存的是对应布尔成员名；这里给的是参数含义，不是要手打的文本。

## 口径与失败策略

- **不判 OK/NG**：本插件只报"认到了什么"，合格与否由下游比较节点 / 脚本决定（与颜色检查同一规矩）。
- **拿不到输入图 → 失败**：上游没连图或图为空，本步报失败"上游没有图像"。
- **切不出字符 → 失败并指明该放宽哪一档**：报错里会把三档筛选逐级写出来（连通域 N 个 → 过高/过宽/过面积各剩几个），据此就知道该调极性以及调尺寸范围。
- **没框识别区 → 失败**，提示去配置界面右键新建矩形。
- **认不准 ≠ 流程失败**：只要跑出了结果，本步仍算成功；但插件有两条 **Warn 诚实机制**：出现拒识字、或平均置信度低于 0.9 时主动写告警。因为 OCR 最危险的失败不是"认错"，而是"给出一串看着正常的错字符却毫无提示"——那会被下游当成功直接放行。
- **0.9 是常量、不是配置项**：它只决定"要不要提醒"，不参与判定。
- **字符集只由模型文件决定**：内置模型只含 0-9 与 A-Z，冒号 `:`、斜杠 `/`、空格一律会被判为拒识；界面没有"只允许数字"这类正则约束（格式校验归下游）。

## 典型用法 / 接线

```
① 固定位置字符
图像采集.OutputImage ──▶ OCR.Image
OCR.Text ─────────────▶ C#脚本（比对料号 / 判 OK-NG）

② 位置不固定（先定位再读字）
模板匹配.AlignedImage ─▶ OCR.Image

③ 置信度把关（宁缺勿错）
OCR.Confidence ────────▶ 比较节点（低于阈值不放行 / 转人工）
OCR.Detail ────────────▶ 结果上报（留每位的置信度做追溯）
```

## 常见问题

**Q：图上明明有字，却报"识别区里没有切出任何字符"？**
看报错里的"筛选过程"三档：**第一档（高度）就掉光**，多半是极性选反了（把 `TextIsDark` 改一下试试），或点阵字没焊合（把 `ClosingRadius` 调到 1.5 左右）；**第三档（面积）掉光**，多半是面积/尺寸范围跟字符实际大小对不上，按报错提示放宽对应区间。

**Q：认出来是乱码、或多字少字？**
先看 `Detail` 有没有 `?`（拒识）和整串置信度是否偏低，再看是不是识别区没框住整行（框太紧切掉字头、框太松带进背景纹理都会被切成多余区域）。

**Q：点阵 / 喷印的字被认成别的（0 认成 A、3 认成 T），而且成批错？**
这是用**膨胀**把字弄"胖"了的典型系统性错。改用**闭运算**（`ClosingRadius`，从 1.5 起试）：它先扩后缩，把散点连上又还原外轮廓尺寸；膨胀只扩不缩才会致字形失真。

**Q：带冒号的日期码、或中文认不出来？**
内置模型的字符集只有 0-9 与 A-Z，`:` `/` 空格都会被判拒识。要认中文或特殊字符，把 `ModelPath` 指向自训练 / 中文模型文件（详见另一页《训练与排错》）。

**Q：填了模型路径却"什么中文都认不出"，也没什么提示？**
如果 `ModelPath` 填了但文件不存在，插件会**直接报错**（"指定的 OCR 模型文件不存在"），不会静默退回内置模型——避免你以为是"OCR 不认中文"而真因是路径写错。清空 `ModelPath` 就用内置。

**Q：竖排文字顺序乱了？**
勾上 `ColumnFirst`（按列优先排序）。横排保持默认 `false`。

**Q：置信度多少才能放行？**
低于 0.9 插件会写 Warn 提示"不可信"。**别把它当放行判据**：在下游用比较节点，把"文本匹配 + 置信度闸门"两道一起上——任一不满足就转人工复判或判 NG（宁缺勿错）。

**Q：想要图上标出每个字框在哪？**
本插件不输出标注图/字符框（未做位置投射）。排错请读 `Detail` 逐位定位；要单独看切分效果，就先用上游「创建 ROI / 裁剪」把整行裁出来，再在配置界面点「试算」看"切出几个字、各认成什么、置信度多少"。
