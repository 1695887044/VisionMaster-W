# OCR 文本识别 · 快速上手

> 分类：图像处理 ｜ 来源：插件 Plugin.Ocr

在框选的识别区里把一行字符**逐个切开**，再用内置分类器**认字**，产出识别文本、字符数、平均置信度、逐字符明细，以及**逐字符结构化数据**（类别名 / 置信度 / 外接框 / 拒识数）。
它认的是**人类可读的印刷字符**（内置模型：数字 0-9 与大写字母 A-Z），用于读料号、日期码、批次号、铭牌。
判定（合格与否）**不由本插件做**——它只报告"认到了什么"，比对与放行交给下游的比较节点或脚本。

## 为什么需要它 / 原理

机器视觉里三件事各有分工：模板匹配解决"目标在哪"，码读取解决"码里编码了什么"，而 **OCR 解决"印出来的字是什么"**。

OCR 的关键认知是：**切字（分割）决定成败的九成，认字只是一行调用**。
- 字切对了 → 分类器很成熟，基本认得准；
- 字切错了（两字粘成一块、一字断成三截、把背景纹理当字）→ 再好的分类器也只能给出一串看似正常的错字符。

所以插件分两层，且所有"能拧的螺丝"都集中在切字这一层：
1. **分割层**——把识别区裁剪出来，转灰度，按极性二值化（暗字/亮字），可选做闭运算/腐蚀/膨胀把散点焊合或把粘连断开，再走连通域拆字、按"高度→宽度→面积"三档筛选，最后按阅读顺序排序；
2. **识别层**——把排好序的字符区域喂给 MLP 分类器，一次性拿到每个字符及其置信度。

排序这步是必需的：分类器返回的字符顺序与喂进去的区域顺序一一对应，**没排序就会拼出一串乱序文本、而且不报错**。

## 典型用法 / 接线

```
① 固定位置字符
图像采集.OutputImage ──▶ OCR.Image
OCR.Text ─────────────▶ C#脚本（比对料号 / 判 OK-NG）

② 位置不固定（先定位再读字）
模板匹配.AlignedImage ─▶ OCR.Image

③ 置信度把关（宁缺勿错）
OCR.Confidence ────────▶ 比较节点（低于阈值不放行 / 转人工）
OCR.Detail ────────────▶ 结果上报（留每位的置信度做追溯）

④ 按位判定 / 定位（判定仍在下游做）
OCR.Classes ───────────▶ C#脚本（第 3 位必须是 B；拒识位是 U+001A）
OCR.CharBoxes ─────────▶ 报表 / 自绘标注（stride 4：row1,col1,width,height）
OCR.RejectedCount ─────▶ 比较节点（> 0 就转人工复判）
```

## 常见问题

**Q：图上明明有字，却报"识别区里没有切出任何字符"？**
看报错里的"筛选过程"三档：**第一档（高度）就掉光**，多半是极性选反了（把 `TextIsDark` 改一下试试），或点阵字没焊合（把 `ClosingRadius` 调到 1.5 左右）；**第三档（面积）掉光**，多半是面积/尺寸范围跟字符实际大小对不上，按报错提示放宽对应区间。

**Q：认出来是乱码、或多字少字？**
先看 `Detail` 有没有 `?`（拒识）和整串置信度是否偏低，再看是不是识别区没框住整行（框太紧切掉字头、框太松带进背景纹理都会被切成多余区域）。

**Q：点阵 / 喷印的字被认成别的（0 认成 A、3 认成 T），而且成批错？**
这是用**膨胀**把字弄"胖"了的典型系统性错。改用**闭运算**（`ClosingRadius`，从 1.5 起试）：它先扩后缩，把散点连上又还原外轮廓尺寸；膨胀只扩不缩才会致字形失真。

**Q：带冒号的日期码、或中文认不出来？**
内置模型的字符集只有 0-9 与 A-Z，`:` `/` 空格都会被判拒识。要认中文或特殊字符，把 `ModelPath` 指向自训练 / 中文模型文件（怎么训、字符集怎么定见《训练与字符集》，一步步排查见《排错》）。

**Q：填了模型路径却"什么中文都认不出"，也没什么提示？**
如果 `ModelPath` 填了但文件不存在，插件会**直接报错**（"指定的 OCR 模型文件不存在"），不会静默退回内置模型——避免你以为是"OCR 不认中文"而真因是路径写错。清空 `ModelPath` 就用内置。

**Q：竖排文字顺序乱了？**
勾上 `ColumnFirst`（按列优先排序）。横排保持默认 `false`。

**Q：置信度多少才能放行？**
低于 0.9 插件会写 Warn 提示"不可信"。**别把它当放行判据**：在下游用比较节点，把"文本匹配 + 置信度闸门"两道一起上——任一不满足就转人工复判或判 NG（宁缺勿错）。

**Q：想要图上标出每个字框在哪？**
本插件不输出**标注图**（不在图上画框），但每个字的位置以数据形式给在 `CharBoxes` 里（扁平 stride 4：`row1,col1,width,height`，图像绝对坐标，宽高含端点），下游可以据此自己画。排错请读 `Detail` 逐位定位；要直接看切分效果，先用上游「创建 ROI / 裁剪」把整行裁出来，再在配置界面点「试算」看"切出几个字、各认成什么、置信度多少"。
