# OCR 文本识别 · 开发章节：不变量与守门断言

> 分类：图像处理 ｜ 来源：插件 Plugin.Ocr ｜ 读者：开发

守门文件：`FlowCanvasChecks\OcrChecks.cs`（29 条）。逐条"症状 → 机理 → 断言名"。

## A 组：违反就报错或结果明显不对

1. **症状** 内置模型换机器后找不到。
   **机理** 四级解析顺序：显式配置 → `Assets\ocr` → `%HALCONROOT%\ocr` → 短名交回 HALCON。
   **守门断言名** `内置 OCR 模型按默认路径可解析`。
2. **症状** 填了自定义模型却静默跑内置，中文样本"认不出来"。
   **守门断言名** `显式配了不存在的模型 → 报错而不是静默退回内置`、`模型路径配错 → 插件报失败且原因可读（不静默退回内置）`。
3. **症状** 切分数量不对：多切把噪声当字符，少切把一个字切成两半。
   **机理** 阈值、形态学、尺寸与面积筛选共同决定；这条用"恰好几个字符且零拒识"卡住。
   **守门断言名** `lot_number_04.png 恰好切出 6 个字符且零拒识（多切=噪声，少切=字符被切断）`、`dot_print_02.png 切出 9 个字符（041023/A5 共 9 个）`。
4. **症状** 识别结果整体错。
   **守门断言名** `lot_number_04.png 识别出 09240A`、`插件按默认配置走内置模型并识别出 11240B`、`插件报成功且字符数为 6`。
5. **症状** 低对比图"全都认出来了"，其实是错的。
   **机理** 拒识判据是"输出既无字母也无数字"（不是判空、不是猜占位符）。
   **守门断言名** `【核心】低对比点阵图必须出现拒识，而不是清一色'认出来了'`、`【核心】低对比点阵图认不准时给出低置信度（现场据此判不可信）`。
6. **症状** 错字符串被当成功结果放行。
   **机理** 出现拒识、均值置信偏低两条 Warn 必须写出来。
   **守门断言名** `【核心】出现拒识字时写 Warn（否则错字符串会被当成功结果放行）`、`【核心】均值置信度偏低时写 Warn 提示结果不可信`。
7. **症状** 没框识别区时空报错或抛异常。
   **守门断言名** `没框识别区 → 报失败且提示指向右键新建矩形`；插件层不抛异常的口径由 `插件运行不抛异常（Execute 的失败契约兜住了）`、`低对比图走插件路径也不抛异常` 钉住。
8. **症状** 分类器句柄泄漏或退出时崩。
   **守门断言名** `Dispose 释放分类器句柄不抛异常`。

## B 组：违反不报错，只是识别率或可信度静默下降

9. **症状** 亮底暗字时切出一整块背景。
   **机理** `TextIsDark` 极性搞反。
   **守门断言名** 无断言，靠人工核对（同一张图勾与不勾各跑一次）。
10. **症状** 竖排文本读出来顺序乱。
    **机理** `ColumnFirst` 决定按列还是按行排序。
    **守门断言名** 无断言，靠人工核对。
11. **症状** 换图纸后识别区位置不对但没提示。
    **机理** `Initialize` 在 `_seedingCanvas` 保护下还原 `RoiParams`；`OnRoiTuplesChanged` 只在"改动的是最后一项"时写回，
    `WriteBackRoi()` 也只取 `LastOrDefault`——多个识别区只认最新。保护标志若被去掉，打开界面就会把配置改写一次。
    **守门断言名** 无断言，靠人工核对（开界面、不改任何东西、直接保存，比对 `.vms` 里 `RoiParams` 有没有变）。
12. **症状** 固定阈值与自动阈值结果差很多，却看不出用的哪个。
    **机理** `SegmentResult.UsedThreshold` 回读实际阈值，试算文本里带"实际阈值 N"。
    **守门断言名** 无断言，靠人工核对（勾上"用固定阈值"跑一次，看提示里的阈值是否等于配置值）。
13. **症状** 字符被切断后 `MinArea` 调大反而更差。
    **机理** 闭运算、腐蚀、膨胀与面积筛选互相耦合，一次只动一个。
    **守门断言名** 无断言，靠人工核对。
14. **症状** 打开一张异常图就抛。
    **机理** 兜底 catch 把原因写进错误文本（`字符分割失败：… （若为坐标越界，请把识别区画在图像范围内）`）。
    **守门断言名** `dot_print_01.png 不抛异常并给出结果或可读原因…`。

## C 组：结构化输出端口（`Classes` / `Confidences` / `RejectedCount` / `CharBoxes`）

这组端口只给数据、不判 OK/NG；下面钉的是"交给下游的数据自不自洽"。

15. **症状** 下游按 `HTuple` 取值，插件却把类型改成了 `double[]`（或反之），编译期全绿、运行期取值抛。
    **机理** 端口类型就是下游的取值契约：类别名用 `string[]`（同 `CodeReader.Codes`），数值数组用 `HTuple`（同 `BlobDetect`）。
    **守门断言名** `端口契约：Classes=string[] / Confidences=HTuple / RejectedCount=int / CharBoxes=HTuple`。
16. **症状** 四个端口长度各说各话（`CharBoxes` 少一组、`Confidences` 比 `Classes` 短），下游按下标取越界或错位。
    **机理** 三者由同一次 `do_ocr_multi_class_mlp` 与同一份 `segment.Chars` 产出，长度必须 `Count` / `Count` / `Count×4`。
    **守门断言名** `结构化端口与 Count 对齐：Classes/Confidences 长度 = Count，CharBoxes 长度 = Count×4`、`Confidences 逐项落在 0~1（长度由对齐那条钉住）`。
17. **症状** `Text` 与 `Classes` 不同源（有人给 `Text` 单独拼一遍），下游按位比对与整串比对得出不同结论。
    **机理** `Text` 就是 `Classes` 直接拼接，不另算一遍。
    **守门断言名** `Classes 直接拼接 == Text（逐字符与整串同源，不是两份数据）`、`11240B 零拒识：RejectedCount = 0 且 Classes 里没有 U+001A`。
18. **症状** 字符框宽或高为 0（单像素宽的字被下游当"没有框"丢掉）、框跑到图像外、框顺序与 `Classes` 不一致。
    **机理** 宽高按像素**含端点**（`col2-col1+1`）；坐标是图像绝对坐标；顺序 = 阅读顺序。
    **守门断言名** `每个字符框宽高 > 0 且落在图像范围内（像素含端点，单像素宽的字也是 1）`、`字符框按阅读顺序排列（横排：框中心列严格递增）`。
19. **症状** `RejectedCount` 与 `Classes` 里的拒识位对不上（漏算、把空白当拒识），或 `Detail` 的 `?` 出现在非拒识位。
    **机理** 拒识位 = `Classes` 里含 U+001A 的项；`Detail` 的 `?` 必须与它逐位一致（反向：非拒识位不许是 `?`）。
    **守门断言名** `【核心】拒识数 == Classes 里 U+001A 的个数（低对比点阵图确有拒识）`、`拒识位在 Detail 里是 '?'，非拒识位不是 '?'（逐位对照 Classes）`。
20. **症状** 失败轮下游读到上一帧的字符（比"没有值"更危险）。
    **机理** 基类 `AutoDisposeRoundOutputs` 只回收 `IDisposable`（`HImage`/`HRegion`），`string`/`int`/`double`/`HTuple` 端口会原样留下 → 必须在 `RunAlgorithm` 开轮显式清零。
    **守门断言名** `【反向】失败轮四个新端口全空、Count = 0（下游读不到上一轮残留）`。

## 并行安全声明

带 `[ParallelSafe]`，注释理由是"纯视觉计算"。成立前提是**切分与识别都不写画布状态**：
`CanvasRois`、`RoiSummary`、`DisplayImage` 只属于配置界面那一侧。
若以后让运行路径也写这些属性（例如运行后自动刷新界面），必须同时摘掉 `[ParallelSafe]`。
