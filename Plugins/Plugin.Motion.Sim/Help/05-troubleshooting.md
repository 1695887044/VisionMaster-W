# 故障排查

先看**卡状态说明**（`StateDetail`）与**最近故障**（`LastFault`），90% 的问题在这一行里就写清了。
下面按"症状 → 多半是什么 → 怎么办"排列。

## 一、卡建不出来 / 列表里没有这个驱动

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| 「运动卡」下拉里没有"产线仿真运动卡" | `Modules\Plugin.Motion.Sim.dll` 不在，或插件扫描没扫到 | 重建插件工程（红线③：`Modules\` 不由宿主带出），确认 `Modules\Plugin.Motion.Sim.dll` 的修改时间 ≥ 源码 |
| 有驱动但建卡报"驱动不可用（插件未加载或被删除）" | `MotionDescriptor.DriverTypeKey` 里存的是旧 `AssemblyQualifiedName` | 删掉这张卡重加（类型键随程序集版本变化，不会自动迁移） |

## 二、连不上

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| `连接仿真器超时（127.0.0.1:19510）` | 仿真器没启动 / 端口不是 19510 | 先 `LineSim.exe --serve`；确认没改过 `--motion-port` |
| `连接被拒绝`（`Connection refused`） | 端口没人监听 | 同上；再看仿真器控制台有没有 `[motion] 监听失败` |
| `仿真器协议版本不符（仿真器 X / 本驱动 1）` | 两边版本不配套 | 同步重建：仿真器与驱动必须同一批 |
| `仿真器没有回应握手` | 连上了但对方不说话（多半是连到了别的服务） | 用 `curl` 或 `telnet` 确认 19510 上跑的确实是 LineSim |

## 三、命令被拒绝（`accepted=false`）

拒绝理由原样来自仿真器，与上位机基类门禁**同一口径**：

| 理由 | 含义 | 处理 |
|---|---|---|
| `轴未使能，请先在流程中加入「轴使能」步骤` | 轴没使能 | 流程里把「轴使能」放在运动步骤之前 |
| `轴未回零，位置不可信` | 增量编码器未回零 | 先跑「轴回零」；仿真器自报增量式，连上后必然要回零 |
| `轴正在运动中` | 上一条运动还没到位 | 用「轴等待」步骤等到位，别用固定延时 |
| `设备处于安全停机状态，先复位急停` | 仿真器侧被 `estop` 过 | 复位急停（上位机侧「清报警」/重新连接）后再动 |
| `轴号 N 超出范围 0..M` | 轴号对不上（配置里的轴表与仿真器规模不一致） | 重新连接让 `hello` 刷新能力位，或改仿真器规模 |
| `不支持的回零方式：Xxx` | 回零方式名对不上 | 选八种标准方式之一（`NegativeLimitIndex` 等） |
| `不支持的命令类型：Xxx` | 驱动发了仿真器没实现的命令 | 看 `10-dev-architecture.md` 的命令映射表 |

## 四、跑着跑着停了

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| 卡状态变 `SafeStopped`，说明写"安全停机" | 限位被点亮 / 急停被触发 / 连续轮询失败触发看门狗 | 先看轴状态里哪个位亮的；排除后清报警、必要时重新回零 |
| `LastFault` 写"仿真器无响应（poll 超时或连接已断）" | 仿真器进程被杀或卡死 | 重启仿真器；重连后增量编码器要求重新回零 |
| 位置长时间不变化，但 `Moving=true` | 仿真器 tick 停了（断点/被挂起） | 看仿真器控制台是否在推进 tick |
| 位置跳变（一帧内跨很大距离） | 有人改过仿真器 `--speed`，或 tick 补跑 | 仿真器落后 >200ms 会**丢 tick 不补跑**；确认没有把 `--speed` 调得离谱 |

## 五、行为与预期不符

| 现象 | 说明 | 是否缺陷 |
|---|---|---|
| Move 命令瞬间"完成" | 正常：`Move` 是"下发即完成"，等到位要用「轴等待」步骤 | 否 |
| 回零要等一会儿 | 正常：仿真器按回零方式与行程真算，不是瞬间 0 | 否 |
| 点动一直走不停 | 正常：点动没有终点，直到 `Stop`/`Disable` 或撞限位 | 否 |
| 数字输入会自己变 | 正常：输入由轴位置与工位状态推导 | 否 |
| 两条轴"同时"下发却一前一后动 | 正常：基类命令线程是单条的，命令串行执行；真机也常如此 | 否 |
| 连上后第一件事就是被拒"未回零" | 正常：增量式编码器 | 否 |

## 六、需要带日志找人的情况

准备三样东西再提问，能省一轮往返：

1. 卡状态说明原文 + `LastFault.Message` / `Suggestion`；
2. 仿真器控制台输出（含 `hello` 与拒绝行）；
3. 触发问题的流程片段（哪几步、什么顺序、有没有「轴等待」）。
