# 端口、端点与参数

## 端点从哪来

本驱动**不读宿主配置里的地址**（插件程序集是 `net9.0`、只引 `Shard/Core.Interfaces`，
拿不到宿主 `AppConfigModel` 里的设置对象）。端点按下面顺序确定，只有两级：

| 优先级 | 来源 | 取值 |
|---|---|---|
| 1 | 环境变量 `VM_LINESIM_CAM` | `host:port`，例如 `127.0.0.1:19501` |
| 2 | 编译期常量 | `127.0.0.1:19500` |

设计文档 §8.1 的端口表是**唯一登记处**，断言 S29 会核对"常量 == 端口表 == 仿真器场景文件"三者一致。
改端口必须三处同改，否则 S29 判红。

### 为什么要环境变量这一级

单机部署时端点写死没问题；一旦仿真器跑在另一台机器（或同机换端口做多实例），
改代码显然不现实。用环境变量是**最小代价**：不进配置模型、不需要改契约、不触碰插件配置通道
（那条通道按设计只服务配置视图，不传运行期连接信息）。

设置方式（当前用户，重开宿主生效）：

```
setx VM_LINESIM_CAM 192.168.1.20:19500
```

## 端口规划

| 端口 | 用途 | 谁监听 |
|---|---|---|
| 19500 | 相机流（HTTP 长连接） | LineSim |
| 19510 | 运控（TCP JSON-lines） | LineSim |
| 19520 | Modbus TCP unit 1..6 | LineSim |
| 19530–19532 | 西门子 S7 | LineSim |
| 19540–19541 | 三菱 MC | LineSim |
| 19550–19551 | 欧姆龙 FINS | LineSim |
| 19560–19561 | 自由协议 | LineSim |
| 19000 | 宿主收图服务 | VisionMaster |
| 19100 | 宿主网络相机服务 | VisionMaster |
| 8080 | SCADA Web | VisionMaster |

**仿真器不许占用宿主的三个端口**（19000 / 19100 / 8080）。`LineSim --check-ports` 会把两段都列出来，
并把宿主占用标成"正常"、仿真器段占用标成"异常"。

## 参数逐项

| 参数 | 默认 | 生效时机 | 说明 |
|---|---|---|---|
| 序列号 `SerialNo` | 空 | 连接时 | **必须**等于仿真器相机名（`CAM1`/`CAM2`…）；空或不存在都会被拒 |
| 触发模式 | 软件触发 | 每次采集 | 只有软件触发能出图，见 `01-overview.md` |
| 曝光 `ExposureTimeUs` | 10000 | 点确定后下发 | 夹在 100–100000us；仿真器侧线性缩放亮度 |
| 增益 `Gain` | 0 | 点确定后下发 | 夹在 0–24 |
| 帧超时 `FrameTimeoutMs` | 3000 | 每次取帧 | 超时未取到帧即报"取帧超时" |
| 缓冲容量 `BufferCapacity` | 8 | 连接时 | 与仿真器侧队列容量**同值**，改一边要改两边 |
| 心跳超时 `HeartbeatTimeoutMs` | 3000 | 连接时 | 超过它没收到任何证据（帧或 `/health`）即判掉线 |

### 曝光/增益的生效路径

设置对话框点"确定" → 宿主调 `ApplySettings` → 基类调 `ApplySettingsCore` → 本驱动
`POST /camera/{serial}/config`。**未连接时只记住参数不报错**，连接后由第一次下发生效——
这样"先配参数再连接"的常见操作顺序不会被卡住。

## 帧格式（客户端视角）

长连接上连续写帧，每帧：

```
int32 LE headerLen | headerJson (UTF-8) | int32 LE pixelLen | pixels
```

`headerJson` 字段**只有成像参数**，白名单：`tick` / `cam` / `w` / `h` / `ch` / `bits` /
`exposureUs` / `gain` / `seq` / `ts`。多一个字段就说明真值外泄了（断言 S15 会扫）。

像素布局：行优先、**无行填充**，灰度 1 字节/像素，彩色 BGR 交错 3 字节/像素。
这与契约 `CameraFrame.PixelData` 的约定完全一致，所以驱动侧不需要任何转换。

## 端点不通时的排查顺序

1. `LineSim.exe --serve` 是否在跑（控制台应打印 `相机流 HTTP 19500`）
2. `LineSim.exe --check-ports` 看 19500 是否被别的进程占了
3. `curl http://127.0.0.1:19500/health` 是否返回 `cameras` 数组
4. 序列号是否与 `/health` 里列出的相机名逐字一致（大小写不敏感，但不做模糊匹配）
