# 产线仿真相机（Plugin.Camera.Sim）

## 这是什么

产线仿真相机驱动把 **LineSim 产线仿真器**的图像接进 VisionMaster 的采集链路。它与「网络相机（虚拟）」
的区别只有一个，但很关键：**取图方向相反**。

- 网络相机：外部客户端把图**推**给宿主（HTTP POST），宿主收图服务解码后送进设备；
- 产线仿真相机：宿主**拉**仿真器（HTTP 长连接），触发那一刻仿真器才按当前世界状态渲染。

因为"触发才渲染"，图像与轴位置严格落在同一个 tick 上——这就是本方案第一条不可让步约束
（"触发时刻与图像严格对应"）的可执行形态。

## 什么时候用它

| 场景 | 适用 |
|---|---|
| 没有真相机，想跑通"触发 → 取图 → 算法 → 判定"整条链路 | 适用 |
| 想验证编码器触发、多相机并行、曝光/增益下发 | 适用 |
| 想复现"图像与轴位置对不上"这类时序缺陷 | 适用 |
| 想验证真实相机的 SDK 行为（增益非线性、坏帧、丢包） | 不适用，请用真机 |
| 想测 HALCON 算法在真实光学下的极限精度 | 不适用，仿真图像是解析合成的 |

## 前置条件

1. 本机已构建并启动仿真器：`tools\LineSim\bin\Debug\net9.0-windows\LineSim.exe --serve`
2. 相机序列号必须等于仿真器里的相机名（默认 `CAM1` / `CAM2`）
3. 仿真器端口未被占用（默认 `19500`，可用 `LineSim --check-ports` 检查）

## 五步上手

1. **启动仿真器**：`LineSim.exe --serve`，看到 `相机流 HTTP 19500（CAM1 / CAM2，proto 1）`。
2. **新建相机**：系统 → 相机设置 → 新增，驱动类型选「产线仿真相机」。
3. **填序列号**：`CAM1`。**这一栏不是装饰**——它就是仿真器里的相机名，填错会在连接时被明确拒绝
   （提示"仿真器里没有相机 XXX"）。
4. **连接**：状态应变为「在线」，说明文字显示 `已连接 LineSim 127.0.0.1:19500 / CAM1`。
5. **采集**：流程里放「图像采集」步骤，触发模式选**软件触发**，运行一次应取到图。

## 触发模式怎么选

| 触发模式 | 本驱动的行为 |
|---|---|
| 软件触发 | **推荐**。每次采集前向仿真器要一帧，图像与当时的轴位置同 tick |
| 连续 | 仿真器不会自己出图（它是"拉"模型），连续模式下会等到帧超时 |
| 上升沿 / 下降沿 | 契约里的硬件触发线在仿真器侧没有对应物，请改用软件触发 |

一句话：**只有软件触发能出图**。这是设计取舍，不是缺陷——"谁来触发"必须有一个确定的答案，
仿真器把答案钉在"上位机说触发的那一刻"。

## 与真机的差异

| 维度 | 真机 | 本驱动 |
|---|---|---|
| 触发延迟 | 几十微秒到几毫秒，随曝光与传输变化 | 一次 HTTP 往返，默认按 1ms 建模（`--camera-latency`） |
| 图像内容 | 真实光学、噪声、缺陷 | 解析合成：背景渐变 + 工件矩形 + 高斯噪声，同 tick 可复现 |
| 曝光/增益 | 相机内部模拟增益，非线性 | 线性缩放，只影响亮度不影响几何 |
| 丢帧 | 环形队列满时丢帧，计数可查 | 仿真器队列容量 8，满了丢最旧并计入 `/health` 的 `dropped` |
| 掉线 | SDK 回调 | 心跳超时（`HeartbeatTimeoutMs`，默认 3000ms） |
