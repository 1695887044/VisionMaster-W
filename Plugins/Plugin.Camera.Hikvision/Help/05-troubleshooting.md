# 海康相机 · 排错

> 分类：相机驱动 ｜ 来源：插件 Plugin.Camera.Hikvision

本页的错误文案与插件/基类源码**逐字一致**，照抄搜索最快。概念与口径见《取流与触发口径》，
参数含义见《端口与参数》。

## 一、现象 → 机理 → 处置

| 现象（屏幕/日志上的原话） | 直接原因 | 处置 |
| --- | --- | --- |
| 「尚未配置相机序列号：请在「系统 → 相机设置」为本步骤选择一台海康相机」 | 相机配置里序列号为空 | 填 MVS 设备属性里的 `SerialNumber` |
| 「未找到海康 MVS 运行时（MvCameraControl.Net.dll）。请安装海康 MVS 客户端…（探测记录：…）」 | SDK 包装器不在探测路径上 | 按括号里的探测记录逐条补：复制进 `Modules\` 或设 `MVCAM_SDK_PATH` 指向 MVS 安装根目录 |
| 「MVS SDK 缺少常量 X —— MvCameraControl.Net.dll 版本不匹配」 | 放进 `Modules\` 的那份包装器里没有该传输层常量 | 换成与相机固件配套的 MVS 版本；进程里只认先加载的那一份，别混两份 |
| 「MVS SDK 缺少类型 MyCamera.X —— MvCameraControl.Net.dll 版本不匹配」 | 包装器里没有该结构体（版本差异） | 同上 |

| 「MVS SDK 缺少字段 类型.字段 —— MvCameraControl.Net.dll 版本不匹配」 | 结构体成员名变了 | 同上 |
| 「枚举海康相机失败（错误码 0x…）」 | SDK 原生运行库不全，或枚举通道被别的进程占着 | 确认 MVS 自身能枚举；关掉其它相机软件 |

| 「打开海康设备失败（错误码 0x…）」 | 该相机已被别的程序独占（MVS 客户端、采集卡软件） | 关掉占用者再连；本驱动此时已把设备销毁，状态干净回到 `Closed` |

| 界面显示"采流中"，但累计收帧不涨 | 掉线未被感知：真机不启心跳、当前版本未订阅 SDK 掉线回调 | 停止采流 → 断开 → 重连 |

## 二、超时文案怎么读（现场最常用的一张表）

| 计数表现 | 结论 | 下一步 |
| --- | --- | --- |
| 累计收帧不涨 | 相机根本没出图 | 查状态是否 `Streaming`、触发是否等外部信号、网线/供电、是否被别的程序抢走 |
| 累计收帧涨、待消费长期为 0 | 图来了但立刻被取走，只是本轮没赶上 | 流程节奏问题：看单步耗时，或放宽取图超时 |
| 待消费长期等于队列上限、溢出在涨 | **产能不匹配** | 先解决处理速度，别靠加大 `BufferCapacity` 掩盖 |
| 显示采流中但累计不涨 | 掉线未被感知 | 停止采流 → 断开 → 重连 |

## 三、逐项专题

**Q：「系统 → 相机设置」的驱动下拉里没有「海康相机」？**
① `Modules\` 里有没有 `Plugin.Camera.Hikvision.dll`——插件工程必须在 `Plugins\` 下构建，构建约定才会把 DLL 投递到 `Modules\`；
② 有 DLL 但时间戳旧 = 改了源码没重建插件工程（只重建宿主跑的仍是旧 DLL）；
③ 看日志里宿主扫描该 DLL 是否失败（缺依赖会整份 DLL 被判加载失败）；
④ 类上若没有 `[Display]`，宿主会**静默跳过**它——列表里没有却不报错。
**不要把 `Core.Interfaces.dll` / `Core.Controls.dll` 等公共契约程序集拷进 `Modules\`**（会出现两份静态状态）。

**Q：MVS 客户端能看到相机，本软件却说枚举 0 台？**
本软件只加载托管包装器；MVS 客户端自带原生运行库。检查是否只复制了 `MvCameraControl.Net.dll` 而没装完整 MVS，
以及是否有别的进程独占枚举通道；重启软件（必要时重启网卡）后重试。

**Q：改了曝光，图上亮度没变？**
① 单位是**微秒**（填 10 只等于 10 μs；10 ms 要填 10000）；
② 日志里有没有"打开后应用参数失败"或"设置曝光失败（ExposureTime，错误码 0x…）"——有就是相机拒绝了该值；
③ 相机开了自动曝光时手动值会被盖掉，先在相机侧关掉 AE；
④ 参数在**连接时/点应用时**下发，改完要在相机设置里确认生效，而不是等流程跑起来。

**Q：想要硬触发（光电 / 编码器 / PLC）？**
本软件不下发触发参数：打开设备时把 GenICam 节点 `TriggerMode` 写 0（连续采图）。
正解是在相机/MVS 侧配好触发并接线，帧照样进队列，采集步骤按自己节奏消费。
顺序要点：连上本软件**之后**再改相机侧的触发，或改完重连一次——否则驱动那次写入会盖掉你的配置。

**Q：多台相机出现"A 相机的图被 B 流程检测了"？**
两台配了**相同序列号**（按序列号取图只命中先注册那台，宿主日志会告警）；
或者两个采集步骤选了同一台（帧不广播，每帧只被取一次，会互相分抢）。
前者要序列号逐字唯一、改名不算；后者要在一处取图后把 `Image` 往下游传。

**Q：预览窗口会抢走生产的图吗？**
不会。预览走只读通道（`Peek`），采集步骤走消费通道（`Dequeue`）。
但**不要**为了"多一路看"再挂一个采集步骤——那是消费语义，真的会吃帧。

## 四、产物与部署红线（"改了没生效"永远先查这三条）

1. 插件工程必须在 `Plugins\` 下（构建约定按目录把 DLL 投到 `Modules\`，放别处加载不到）。
2. 改了插件源码必须**重建插件工程**：`Modules\` 不由宿主工程带出，只重建宿主跑的还是旧 DLL。
3. `Modules\` 只放插件 DLL 与厂商 SDK 的托管包装器（`MvCameraControl.Net.dll`）；
   **公共契约程序集一律不许拷进去**（`Core.Interfaces.dll` / `Core.Controls.dll` 等），否则静态状态出现两份。

## 五、一分钟自检顺序

1. `Modules\Plugin.Camera.Hikvision.dll` 在不在、时间戳新不新；
2. `Modules\MvCameraControl.Net.dll` 在不在（没它就只能到"打开"那一步才报错）；
3. MVS 客户端能不能枚举并打开这台相机；
4. 相机设置里状态是不是 `Streaming`、预览有没有图；
5. 采集步骤「相机采集」页 `当前状态：` 那行颜色（红=未连接 / 橙=未采流或等待接入 / 空=正常）；
6. 点「执行」试运行，把信息栏那一句完整读一遍——本驱动的失败文案都带"下一步该做什么"。
