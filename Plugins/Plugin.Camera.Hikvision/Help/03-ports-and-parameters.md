# 海康相机 · 端口与参数

> 分类：相机驱动 ｜ 来源：插件 Plugin.Camera.Hikvision

海康相机是**设备驱动**，不是流程算子：它没有 `InputPort` / `OutputPort`，界面上也不出现在工具箱里。
它对外的"面"分三处——契约成员（宿主与采集步骤调用）、方案里的配置字段、采集参数。本页逐条给实名与真实默认值。

## 一、契约成员（宿主侧看到的"端口"）

真源在 `Shard\Core.Interfaces\Camera\CameraDeviceBase.cs`（本驱动只重写其中的差异点）。

| 成员 | 谁调它 | 语义与注意点 |
| --- | --- | --- |
| `Open()` | 相机设置「连接」/ 自动连接 | 幂等：非 `Closed` 时直接返回 true。失败时状态干净回到 `Closed`，说明写"打开失败：异常类型: 消息" |
| `Close()` | 「断开」/ 方案关闭 / `Dispose` | 先收状态与闸门，**再**关设备，最后清队列（顺序刻意：反过来会在关闭期间再吃进一帧） |
| `StartStream()` | 「开始采流」 | `Closed` 状态下直接拒绝并把说明写成"尚未连接：请先连接相机再开始采流" |
| `StopStream()` | 「停止采流」 | 关收帧闸门 → 停 SDK 采流 → 清空队列（残留旧帧已无意义） |
| `ApplySettings(CameraSettings)` | 参数面板确定 / 打开设备后自动下发 | 先归一化再下发；成功后把归一化值同步回 `Descriptor.Settings`（界面显示与方案落盘同一份） |
| `ReadSettings()` | 界面回显 | 返回拷贝，调用方改了不影响设备 |
| `PushFrame(frame, out error)` | **本驱动的取图线程**（真机不走 HTTP） | 入队前校验 `frame.IsValid`、回填 `CameraId` / `SerialNo` / `FrameId`，并推进状态到 `Streaming` |
| `WaitNextFrame(out frame, timeoutMs, ct)` | 「图像采集 · 相机采集」 | **消费**语义：出队，一帧只被取一次。`timeoutMs` 填 0 或负数 = 用相机配置里的 `FrameTimeoutMs` |
| `TryGetLatest(out frame)` | 相机设置的预览 | **只读**语义：`Peek` 不 `Dequeue`，所以开着预览窗口不会吃掉生产帧 |
| `NotifyAlive()` | 心跳证据（网络相机用；海康用不到） | 只把 `Connecting` 往前推；海康不启心跳，真机的"活着"由取图线程持续出图体现 |
| `ResetCounters()` | 界面清零 | 只清**溢出**与**丢弃**并重新武装首次告警；`ReceivedFrameCount` 与帧号序列**不重置** |
| `State` / `StateDetail` | 界面与采集步骤的失败文案 | 锁内读，跨线程安全 |
| `ReceivedFrameCount` / `PendingFrameCount` / `OverflowCount` / `DroppedFrameCount` | 计数展示与超时文案 | 前两项是"进过队列多少"与"还压着多少"；后两项**分开计数**（溢出=处理不过来，丢弃=掉线/停止/不自洽） |
| `StateChanged` | 界面订阅 | 在锁外触发；订阅方抛异常会被吞掉，不会带垮设备 |
| `Log` | 宿主 `CameraProvider` 创建后注入 | 没注入则本驱动所有日志静默 |
| `Dispose()` | 方案关闭 / 退出 | 幂等（二次释放不抛）；释放路径上的异常不再上抛 |

## 二、方案里的配置字段（`CameraDescriptor`）

| 字段 | 界面叫什么 | 落盘与寻址 |
| --- | --- | --- |
| `SerialNo` | 序列号 | **唯一寻址键**。比较时忽略首尾空格与大小写，其余一位都不能差；留空则 `Open` 直接失败 |
| `DisplayName` | 显示名 | 不参与寻址。缺失时界面回落到序列号（`Caption`：显示名 → 序列号 → "(未命名相机)"） |
| `DriverTypeKey` | 驱动类型 | 决定宿主用哪个驱动类实例化这台相机（本驱动对应「海康相机」） |
| `Remarks` | 备注 | 纯展示 |
| `AutoConnect` | 自动连接 | 方案加载/启动时执行"连接 + 开始采流"；一台失败不影响其它相机 |
| `Id` | —（不展示） | 内部 `Guid`，**不要**用它当引用键：方案里存的是序列号 |
| `Settings` | 采集参数 | 见第三节 |

## 三、采集参数（`CameraSettings`，随方案落盘）

| 参数 | 默认 | 对海康 | 下发到哪 / 说明 |
| --- | --- | --- | --- |
| `ExposureTimeUs` | 10000 | **生效** | GenICam 节点 `ExposureTime`（float）。**单位是微秒**：10000 = 10 ms。相机拒绝该值时报"设置曝光失败（ExposureTime，错误码 0x…）" |
| `Gain` | 0 | **生效** | 节点 `Gain`（float）。**单位由相机自行解释**（多数机型 dB，也有机型是原始码值），与 MVS 客户端对不上时先确认那一侧显示的物理量 |
| `TriggerMode` | `Software` | **不生效** | 本驱动不读它：打开设备时把节点 `TriggerMode` 写 0（连续采图）。见《取流与触发口径》 |
| `FrameTimeoutMs` | 3000 | **生效**（由基类消费，不是硬件消费） | 消费端"等一帧最多等多久"。**永远必须有限**：无超时的等图会让流程线程永久卡死、现场只能杀进程 |
| `BufferCapacity` | 8 | **生效**（基类消费） | 环形队列容量，满则丢最旧并计溢出 |
| `HeartbeatTimeoutMs` | 3000 | **不生效** | 真机这一侧 `RequiresHeartbeat` 为 false，看门狗根本不创建。这一项只对网络相机有意义 |

**归一化规则**（`CameraSettings.Normalized()`，配置可被人工编辑必须有兜底）：

| 条件 | 归一化结果 |
| --- | --- |
| `BufferCapacity` 小于 1 | 置 1 |
| `BufferCapacity` 大于 1024 | 置 1024 |
| `FrameTimeoutMs` 小于 1 | 置 3000 |
| `HeartbeatTimeoutMs` 小于 200 | 置 3000 |

曝光与增益**不做归一化**：本驱动不把非法值夹成"看着合理"的值，而是原值下发、由相机决定接受或拒绝，
拒绝就把 SDK 错误码原样报出来——静默夹值会把"相机其实拒绝了"这件事推迟到某个说不清的亮度问题上。

## 四、下发时机（改完什么时候生效）

| 时机 | 动作 |
| --- | --- |
| 打开设备成功后 | 驱动立刻把方案里存的曝光/增益下发一次。这一步失败**只记日志、不阻断连接**，日志文案"打开后应用参数失败：…" |
| 参数面板点确定 | 走 `ApplySettings`：失败时状态说明写成"应用参数失败：…"并记日志，成功的值会同步回配置并落盘 |
| 采流过程中改曝光 | 同样走 `ApplySettings`，对海康是即时生效的（不需要重连），但自动曝光开着时手动值会被相机盖掉 |

## 五、常见问题

**Q：为什么这个插件在工具箱里找不到？**
它是相机驱动（工具箱条目分组为「相机驱动」），入口在「系统 → 相机设置」的驱动类型列表；
流程里要用它，靠「图像采集」的**相机采集**模式按序列号引用。

**Q：采集步骤那边的口在哪？**
在「图像采集」插件里：相机标识按**序列号**引用这台，`FrameTimeoutMs` 可被采集步骤的取图超时端口覆盖
（端口填 0/负值即回落到相机配置），输出侧与本驱动相关的有 `FrameId` / `ReceivedCount` / `SourceSerial`。
完整端口表见「图像采集」手册，本页不重复。

**Q：只想预览、不想影响生产？**
用相机设置里的预览（它走 `TryGetLatest`，只 `Peek`）。**不要**为了让预览出图而再挂一个采集步骤——
采集步骤是消费语义，会把帧从队列里取走。

**Q：改了 `BufferCapacity` 会立刻改变已经积压的帧吗？**
不会立刻删，但下一帧入队后会按新上限裁剪最旧的（裁剪量计入溢出）。
