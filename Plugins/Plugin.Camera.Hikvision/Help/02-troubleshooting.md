# 海康相机 · 接入与排错

按顺序走一遍就能上线；每步都写明"对了是什么表现、不对先看哪一条"。
本页的错误文案与插件源码逐字一致，照抄搜索最快。

## 一、上线六步

1. **装 SDK 运行库**：装海康 MVS 客户端（版本要与相机固件配套）。
2. **放托管包装器**：把 MVS 安装目录 `Development\DotNet\MvCameraControl.Net.dll` 复制到本程序目录下的 `Modules\`，然后重启软件。
   （也可以设环境变量 `MVCAM_SDK_PATH` 指向 MVS 安装根目录，驱动会去它的 `Development\DotNet\` 找。）
3. **确认驱动 DLL 在位**：`Modules\Plugin.Camera.Hikvision.dll` 必须存在且时间戳是最近一次构建的。
   插件工程只有在 `Plugins\` 目录下构建，构建约定才会把 DLL 投递到 `Modules\`；改了源码只重建宿主、不重建插件工程 = 跑的还是旧 DLL。
   **不要把 `Core.Interfaces.dll` / `Core.Controls.dll` 等公共契约程序集拷进 `Modules\`**（会出现两份静态状态）。
4. **接一台相机并核对序列号**：在 MVS 客户端里能看到这台相机、并能打开它——**MVS 看不到，本驱动必然也看不到**。
   记下设备属性里的 `SerialNumber`（不是用户名、不是 IP）。
5. **加进方案**：「系统 → 相机设置」→ 驱动类型选「海康相机」→ 填序列号 → 建议勾「自动连接」→ 点「连接」，状态从
   `Online`（已连接未采流）变到 `Streaming`（采流中）；再点「开始采流」（若未自动开始）。
   预览用只读通道（不消费生产帧），所以开着相机设置窗口不会让流程漏检。
6. **流程里消费**：「图像采集」→「相机采集」页下拉选这台 → 用窗口底部「执行」试运行（跑的就是正式运行同一段代码），
   成功后信息栏给出 `已从相机取图: 宽x高x通道（第 N 帧，来源 hikvision://序列号）`。

## 二、现象 → 查哪一项

| 现象（屏幕/日志上的原话） | 直接原因 | 处置 |
| --- | --- | --- |
| 「尚未配置相机序列号：请在「系统 → 相机设置」为本步骤选择一台海康相机」 | 相机配置里序列号为空 | 填 MVS 的 `SerialNumber` |
| 「未找到海康 MVS 运行时（MvCameraControl.Net.dll）…（探测记录：…）」 | SDK 包装器不在探测路径上 | 按括号里的探测记录逐条补：复制进 `Modules\` 或设 `MVCAM_SDK_PATH` |
| 「MVS SDK 缺少常量/类型/方法/字段 …—— MvCameraControl.Net.dll 版本不匹配」 | `Modules\` 里那份包装器与相机固件/MVS 版本不配套 | 换成与 MVS 配套的那一份；别在进程里混两份 |
| 「枚举海康相机失败（错误码 0x…）」 | SDK 原生运行库不全或被别的进程占着枚举通道 | 确认 MVS 自身能枚举；关掉其它相机软件 |
| 「未找到序列号为「X」的海康相机（本次枚举 0 台）」 | 一台都没枚举到：网段不通 / 供电 / 网线 / 交换机 / 相机被独占 | 先让 MVS 客户端看到它，再回来 |
| 「未找到序列号为「X」的海康相机（本次枚举 3 台）」 | 枚举通了、序列号对不上（抄错、抄成用户名、方案来自另一台设备） | 逐字核对；比较会忽略首尾空格与大小写，其余一位都不能差 |
| 「创建海康设备失败（错误码 0x…）」/「打开海康设备失败（错误码 0x…）」 | 该相机已被其它程序（MVS 客户端、采集软件）独占，或权限/驱动异常 | 关掉其它占用者；重启软件重连；必要时重启网卡 |
| 「启动采流失败（错误码 0x…）」（状态退回 Online） | 相机在线但采流起不来（带宽/触发设置/上一轮未干净释放） | 先「停止采流」再「开始采流」；GigE 检查链路与包长设置 |
| 「设置曝光失败（ExposureTime，错误码 0x…）」/「设置增益失败（Gain，错误码 0x…）」 | 相机拒绝该值（超范围，或该机型节点名/单位不同） | 用 MVS 里能设成功的数值口径回填；注意曝光单位是**微秒** |
| 状态说明「打开失败：ExceptionType: 消息」 | 基类收尾会覆盖为这一句 | 冒号后面的原文才是根因，按上面几行对号 |
| 日志「…暂不支持的像素格式 X，该帧被丢弃」 | 相机输出了驱动不认识的格式 | 在相机侧改回 `Mono8` / `Bayer…8` / `RGB8` 一类标准输出 |
| 日志「…像素格式转换失败（X，错误码 0x…），该帧被丢弃」 | SDK 转换被拒（缓冲/参数与机型不合） | 换 8 bit 标准输出；确认包装器版本 |
| 日志「…取图解算异常：…」 | 单帧解算抛异常（已兜住，不影响线程） | 看紧跟的上下文与版本变更 |
| 「等待相机「X」出图超时（N ms）；相机状态：…，待消费 N 帧，累计收帧 N，溢出丢帧 N」 | 见下面「三、超时文案怎么读」 | — |
| 「找不到序列号为「X」的相机。请到「系统 → 相机设置」添加该相机，或回到本步骤的「相机采集」页重新选择」 | 采集步骤引用的相机不在当前方案里（被删/改名/换方案） | 重新添加或重新选 |
| 「相机「X」未连接（…）。请到「系统 → 相机设置」连接该相机后再运行」 | 状态 `Closed` | 连接 + 开始采流 |
| 「尚未选择相机，请在「相机采集」页选择一个已配置的相机」 | 采集步骤没选相机 | 下拉选一台 |
| 「相机返回的帧数据无效（宽高与像素字节数不自洽）」 | 帧进队列前的自洽校验拦下 | 看该帧的来源与尺寸，多为格式/位深异常 |
| 「帧队列溢出：处理速度跟不上相机出图速度，已丢弃 N 帧最旧图像（队列上限 C）…」 | 流程节拍慢于相机出图 | 缩短处理链 / 降帧率 / 只在需要时消费；**丢帧 = 漏检工件，必须查** |

## 三、超时文案怎么读（现场最常用的一张表）

| 计数表现 | 结论 | 下一步 |
| --- | --- | --- |
| 累计收帧不涨 | 相机根本没出图 | 查状态是否 `Streaming`、触发是否等外部信号、网线/供电、是否被别的程序抢走 |
| 累计收帧涨、待消费长期为 0 | 图来了但立刻被取走，只是本轮没赶上 | 是流程节奏问题：看单步耗时，或把超时放宽 |
| 待消费长期等于队列上限、溢出丢帧在涨 | **产能不匹配**（处理太慢） | 先解决处理速度，再谈超时值；不要靠加大 `BufferCapacity` 掩盖 |
| 相机设置显示采流中，但累计不涨 | 掉线未被感知（真机不启心跳、当前版本未订阅 SDK 掉线回调） | 停止采流 → 断开 → 重连 |

## 四、部署与产物红线（"改了没生效"永远先查这三条）

1. 插件工程必须在 `Plugins\` 下（构建约定按目录把 DLL 投到 `Modules\`，放别处加载不到）。
2. 改了插件源码必须**重建插件工程**：`Modules\` 不由宿主工程带出，只重建宿主跑的还是旧 DLL。
3. `Modules\` 只放插件 DLL 与厂商 SDK 的托管包装器（如 `MvCameraControl.Net.dll`）；
   **公共契约程序集一律不许拷进去**（`Core.Interfaces.dll` / `Core.Controls.dll` 等），否则静态状态出现两份。

## 五、一分钟自检顺序

1. `Modules\Plugin.Camera.Hikvision.dll` 在不在、时间戳新不新；
2. `Modules\MvCameraControl.Net.dll` 在不在（没它就只能到"打开"那一步才报错）；
3. MVS 客户端能不能枚举并打开这台相机；
4. 相机设置里状态是不是 `Streaming`、预览有没有图；
5. 采集步骤「相机采集」页 `当前状态：` 那行颜色（红=未连接 / 橙=未采流或等待接入 / 空=正常）；
6. 点「执行」试运行，把信息栏那一句完整读一遍——本驱动的失败文案都带"下一步该做什么"。
