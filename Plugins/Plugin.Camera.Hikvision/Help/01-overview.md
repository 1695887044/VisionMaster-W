# 海康相机

> 分类：相机驱动 ｜ 来源：插件 Plugin.Camera.Hikvision

海康威视 **GigE / USB3 相机的真机驱动**：自己打开 SDK 设备句柄、启动采流，并在自己的取图线程上把 SDK 帧解成
原始像素，送进这台相机的**帧队列**。它不是流程里的算子——它出现在「系统 → 相机设置」的驱动列表里，
产出的图由流程中的「图像采集 · 相机采集」步骤按节奏消费（每帧只会被取到一次）。

本册共四页：本页（定位与上手）·《端口与参数》·《取流与触发口径》·《排错》。

## 一、它负责什么、不负责什么

| 它负责 | 它不负责 |
| --- | --- |
| 枚举 GigE + USB3 设备、按**序列号**对上方案里那台、创建并打开设备句柄 | 相机侧的触发接线、包长、心跳时间（这些在 MVS / 相机里配，本驱动不改） |
| 启动/停止采流，维持一条自己的取图线程 | 生成 `HImage`（原始像素 `byte[]` 交给消费者「图像采集」建图） |
| 把 SDK 帧转成 `Mono8` / `RGB8_Packed` 后入队 | 决定"什么时候要一帧"（那是流程节拍，见《取流与触发口径》） |
| 下发曝光与增益到 GenICam 节点 | 自动感知掉线（当前版本未订阅 SDK 掉线回调，也不启心跳，见《排错》） |

**骨架不重写一遍**：环形帧队列 + 溢出丢旧计数、连接状态机、心跳看门狗、取图口（消费 / 只读）都在契约层的
驱动基类 `CameraDeviceBase`（`Shard\Core.Interfaces\Camera\`）里；本驱动只写"海康与别家不一样的地方"。
「网络相机（虚拟）」用的是同一副骨架，所以两者的界面操作、计数口径、采集步骤用法完全同形。

**SDK 是运行时探测的，编译期不引用海康 DLL**。带来的效果是**没装 MVS 的机器上本驱动照样随插件加载**，
直到点「连接」时才给出"去哪装、放哪"的中文指引，其余（状态机 / 队列 / 计数）照常可用。

## 二、六步上线

1. **装 SDK 运行库**：装海康 MVS 客户端（版本要与相机固件配套）。
2. **放托管包装器**：把 MVS 安装目录 `Development\DotNet\MvCameraControl.Net.dll` 复制到本程序目录下的
   `Modules\`，重启软件。备选：设环境变量 `MVCAM_SDK_PATH` 指向 MVS 安装根目录。
3. **确认驱动 DLL 在位**：`Modules\Plugin.Camera.Hikvision.dll` 存在且时间戳是最近一次构建的。
4. **接一台相机并核对序列号**：先在 MVS 客户端里能看到并打开它——**MVS 看不到，本驱动必然也看不到**；
   记下设备属性里的 `SerialNumber`（不是用户名、不是 IP）。
5. **加进方案**：「系统 → 相机设置」→ 驱动类型选「海康相机」→ 填序列号 → 建议勾「自动连接」→「连接」→
   「开始采流」，状态走到 `Streaming`。
6. **流程里消费**：「图像采集」→「相机采集」页下拉选这台 → 点窗口底部「执行」试运行。

跑通后应看到：相机设置里状态说明形如"采流中（已收 N 帧）"，试运行信息栏给出
`已从相机取图: 宽x高x通道（第 N 帧，来源 hikvision://序列号）`。
任何一步不对，直接翻《排错》的"现象 → 机理 → 处置"表。

## 三、配置面速览（系统 → 相机设置）

| 项 | 必填 | 一句话 |
| --- | --- | --- |
| 驱动类型 | 是 | 选「海康相机」。列表来自宿主扫描 `Modules\` 里实现 `ICameraDevice` 且带 `[Display]` 的类型 |
| 序列号 | **是** | **唯一的寻址键**：枚举后按序列号（忽略首尾空格与大小写）挑中那一台。留空直接报"尚未配置相机序列号" |
| 显示名 | 否 | 只给人看，**不参与寻址**；改它不会断客户端、不会断采集步骤 |
| 备注 | 否 | 界面展示 |
| 自动连接 | 否 | 宿主在方案加载/启动时对本机执行"连接 + 开始采流"，一台失败不影响其它相机 |
| 采集参数 | 否 | 曝光 / 增益 / 取图超时 / 队列容量 / 心跳超时——**逐项含义、默认值、归一化规则、对海康是否生效见《端口与参数》** |

方案里存的是**序列号**，不是显示名、也不是内部 Id：换一台相机只要改序列号，采集步骤那边的下拉候选由宿主
按序列号下发快照，`当前状态：` 那行会当场说清"现在能不能跑"。

## 四、产出：这台相机的帧队列

| 项 | 说明 |
| --- | --- |
| 帧（`CameraFrame`） | `PixelData`（行优先、**无行填充**；灰度 1 字节/像素，彩色 3 字节/像素交错）、`Width` / `Height` / `Channels`、`FrameId`（本机从 1 自增）、`Timestamp`（收帧时刻）、`SourceName`（固定为 `hikvision://{序列号}`） |
| 连接状态 | `Closed` / `Connecting` / `Online`（已连接未采流）/ `Streaming`（采流中），外加一句话状态说明 |
| 累计收帧 | 进过队列的帧数（含后来被溢出丢掉的）——采集步骤的 `ReceivedCount` 输出就是它 |
| 待消费帧数 | 队列里当前还有几帧等着被取 |
| 溢出丢帧 | 队列满丢最旧的累计数：**每丢一帧就是一个未被检测的工件**，界面单独红块告警 |
| 其它丢弃 | 掉线 / 停止采流 / 帧不自洽被拦下的累计数，与溢出**分开计数**（原因与处置完全不同） |

## 五、三条与直觉相反的口径

1. **界面上的「触发模式」对海康不生效**：打开设备时驱动统一把 GenICam 节点 `TriggerMode` 写 0（连续采图），
   节拍由流程消费节奏决定。要硬触发（光电 / 编码器 / PLC）见《取流与触发口径》。
2. **网线被拔时界面不会自己变红**：真机这一侧不启心跳看门狗，且当前版本未订阅 SDK 掉线回调。
   现场判据是"累计收帧不再增长 + 采集步骤等图超时"。
3. **多台相机的序列号必须逐字唯一**：重复时按序列号取图只命中先注册的那一台，
   表现是"A 相机的图跑到 B 流程里"（宿主会记一条告警，但状态照常显示正常）。

## 六、接线形态

```
① 系统 → 相机设置：驱动 = 海康相机，序列号 = T-0512xxxxxx，勾自动连接 → 连接 → 开始采流
② 流程：图像采集.Mode = 相机采集，CameraSerial = 同一序列号

海康相机.帧队列 ──▶ 图像采集.相机采集（取图超时端口 0 = 用相机配置）
图像采集.Image ─────▶ 下游算子.SrcImage
图像采集.FrameId / ReceivedCount ──▶ 数据记录 / 结果上报（帧溯源对账）
图像采集.SourceSerial ──▶ 标定 / 坐标变换.SourceSerial（换相机后旧标定自证失效）
```

一帧只被消费一次：两个采集步骤选同一台相机会互相**分抢**帧，需要同一帧多处使用请在下游传 `Image`。

## 七、与另外两条"收图"通道的区别

| 通道 | 端口 | 语义 |
| --- | --- | --- |
| **海康相机**（本页） | 无（走 SDK 与相机直连） | 驱动自己开窗取图入队，流程按节奏消费 |
| 网络相机（虚拟） | `19100`（`AppConfig.json → NetworkCameraServer`） | 客户端按 HTTP 持续推帧入队，同一副骨架 |
| 网络推送采集 | `19000`（`AppConfig.json → HttpImageServer`） | 推一张图 → 立刻跑一次流程 → 同步回结果，与相机无关 |

排障前先确认自己走的是哪一条：`Modules\` 里有没有 `MvCameraControl.Net.dll` 只影响海康；
`19100` 通不通只影响网络相机；`19000` 是第三条链路的端口。
