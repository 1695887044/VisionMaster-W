# 延时

> 分类：常用工具 ｜ 来源：插件 Plugin.Utility

让当前流程暂停指定毫秒数，期间**每 50ms 检查一次急停信号**，可被强制中断。
本页只讲**定位**和**三步上手**；端口字典查「端口与参数」，按现象找原因查「排障」。

## 什么时候用它

视觉流程不是纯计算：光源要点亮、气缸要动作、相机要曝光完、机械手要到位。
这些"等一等"如果靠反复轮询上游信号实现，会白烧 CPU、也让流程难读；
但如果用一个死的 `Sleep(N)`，急停时程序会卡在这一整段里出不来。

**不该用它的事**：精确计时（它是"等够"，不是"等准"）、到位判定（有反馈信号就用信号或条件分支）、
超时保护（超时要有"到点怎么办"的分支，本节点只等不判）。

## 原理一句话

**分片睡**：

```
elapsed = 0
while elapsed < Delay:
    若已请求取消 → 记警告、抛取消（步骤记「跳过」，不算失败）
    本轮睡 min(50, Delay − elapsed)     ← 最后一片按余量截短
    elapsed += 本片长度，并把 elapsed 写进 ET 输出
```

于是急停最多 50ms 就能脱出，而 `ET` 一路跟着真实流逝时间走。
它标了 `[ParallelSafe]`（协作取消范式），可以出现在并行分支里。

## 三步上手

```
① 工具箱（分组「常用工具」）拖出「延时」，放在"要等的那个人"之后。
② 双击节点 → 面板上只有一行「延时时间(ms)」。填数（例如 800），
   或点右侧链接图标把配方里的稳定时间连进来。
   注意：这行是必填的，光有默认值 500 不算"已配置"——必须亲手填过或连上。
③ 需要知道本轮实际等了多久，就从 ET 输出端口连线给记录/上报节点。
```

## 三个端口的分工

| 端口 | 方向 | 类型 | 默认 | 一句话 |
| --- | --- | --- | --- | --- |
| `Delay` | 输入 | `int` | `500` | 要等多少毫秒。**必填** |
| `ET` | 输出 | `int` | — | 已流逝毫秒数，每片更新一次；正常跑满约等于设定值 |
| `State` | 输出 | `bool` | — | 执行状态：跑满 `true`，被急停打断或异常 `false` |

本插件没有自定义配置视图，走宿主自动生成的参数面板（只有输入端口那一行）。

## 结果怎么读

- **正常跑满**：`State=true`、`Success=true`，日志两条
  （`实例名 开始执行延时...` → `实例名 延时 800ms 完成。`）。
- **被急停打断（取消）**：**步骤记「跳过」，不是失败**（框架口径：取消是"被叫停"，不是"算错了"）。
  `State=false`、`ET` 停在已流逝的毫秒数，日志一条警告 `实例名 收到急停信号，已强制中断！`。
  `ErrorMessage` 为空；`Success` 停在方法开头预置的 `false`（本轮确实没等满），
  但**节点不会据此判失败**——取消以取消异常收口，节点记「跳过」。
  本轮后续步骤也不再执行（序列按取消令牌退栈）。
- **异常**：`State=false`、`Success=false`，日志 `实例名 发生异常: …`（Error）随后异常上抛，
  由框架统一转成步骤失败并另记一条**带完整堆栈**的日志——本节点不吞异常。
- **`Delay` 填 0 或负数**：循环一次都不进，直接判完成（`State=true`、`ET=0`、`Success=true`）。

## 常见取值口径

| 场景 | 怎么定 |
| --- | --- |
| 等气缸 / 真空到位 | 实测动作时间 + 20% 余量（实测 600ms → 填 800）。有到位反馈就别用延时 |
| 光源点亮后拍照 | 留 50~100ms 让亮度稳定 |
| 相机软触发后 | 按曝光时间留量，再叠加读出时间 |

节拍紧的产线别在同一条串行链上串多个大延时——那是线性拉长周期。
