# 延时 · 排障

> 分类：常用工具 ｜ 来源：插件 Plugin.Utility

按"看到什么现象"查。文案原文逐字取自 `DelayPlugin.cs` 的日志语句与 `FlowCompiler` 的报错，
括号里标的是它的级别（Info / Warn / Error）。

## 一、编译/启动前就被拦的

| 现象原文 | 为什么 | 怎么改 |
| --- | --- | --- |
| `[参数缺失] '步骤名' 的必填参数 'Delay' 未配置！` | 既没连线、存盘字典里也没有该键的非空值。**默认值 500 不算"已配置"** | 在面板「延时时间(ms)」里填一个数并确认保存，或从上游连一个整数进来 |
| 节点上亮黄色叹号角标，悬停显示 `必填参数未配置（编译会报参数缺失）：` + `· Delay` | 同一条判据的画布投影 | 同上 |
| `[连线类型不匹配] '步骤名' 的输入端口 'Delay' 期望 Int32，但上游 '…' 提供的是 Boolean。请在变量绑定处改选类型兼容的输出，或调整上游算子的输出类型。` | `bool` 不属于数值族 | 上游先出数值（例如「类型转换」转 `Int32`），或用「数值比较」的反向判据 |
| `[并行不安全] 分支内步骤 '步骤名'（算子 DelayPlugin）未声明 [ParallelSafe]，…` | 本插件**已标** `[ParallelSafe]`；出现这条说明 `Modules\` 下是旧 DLL | 重建插件工程（插件 DLL 不由宿主工程带出） |

## 二、等待时长不对

**现象：设 1000ms，实际过了 1020ms 左右。**
正常现象。`Thread.Sleep` 不保证毫秒级准时，加上按 50ms 分片的粒度与最后一片的截断，
实际耗时会**略多于**设定值。本节点是"等够"用的，不是"精确计时"用的。
时序严格的场合请改用到位反馈 / 触发信号 / 条件分支轮询。

**现象：填了 0（或负数），节点直接绿了。**
设计如此：`while (elapsed < targetDelayMs)` 一次都不进，
于是 `State=true`、`Success=true`、`ET=0`，日志仍会打
`实例名 开始执行延时...` 和 `实例名 延时 0ms 完成。`（Info）。
**这是"等 0ms 也算完成"，不是"参数没生效"**——想强制下限请上游自己夹。

**现象：明明只填了 100，却等了几秒。**
先看是不是**上游连线**给的值（连线值优先于面板手填值，面板里那个 100 根本不参与生效）。
再确认不是别的步骤在挡（通讯超时、相机取图等待都长这样）。
`ET` 输出端口能告诉你真实流逝了多少。

**现象：`ET` 比 `Delay` 小。**
只有一种正常来源：**被急停中断**，`ET` 停在已流逝的毫秒数（最后一片没睡完就退了）。
没中断的话，`ET` 是各片之和 = 设定值。

## 三、急停与取消

**现象：按了急停，流程卡在这一秒多才退出来。**
本节点每片醒来一次检查取消令牌，**最多 50ms 就该脱出**。
真慢了要查别的地方：正在跑的其它算子是不是没有分步检查取消（这是它们的问题，不是延时的）。
延时被中断时日志一定留一行 Warn：`实例名 收到急停信号，已强制中断！`
——**有这行就证明脱出是快的**，卡住的是别的步骤。

**现象：急停之后这一步算失败还是算成功？**
**失败**（`Success=false`、`State=false`）。下游若依赖它，分支按失败走。
但**错误信息是空的**——这条中断路径不写 `ErrorMessage`，原因只在日志那一行 Warn 里。
排查请打开流程日志按实例名过滤，别在界面上等一句话。

**现象：并行分组里一条分支被急停打断，另一条跑完了。**
两条分支各自在自己的线程里睡，取消令牌是共享的：中断的那条如实判失败，
跑完的那条照常 `Success=true`。容器的聚合结果按并行分组的"失败聚合"口径来，
不归本插件决定。

## 四、异常路径

**现象：日志里 `实例名 发生异常: …`（Error），随后步骤被引擎记成执行异常。**
本节点**不吞异常**：写完 `State=false`、`Success=false` 和那行 Error 日志之后 `throw;` 原样上抛。
所以同一次故障可能有两条记录（自家的一行 Error + 引擎按执行异常处理时的一条），
以带实例名的那行为准。

**现象：找不到"发生异常"的日志，但节点是红的。**
两种可能：① 被急停中断（找那行 Warn）；② 异常发生在进入 `RunAlgorithm` 之前
（取值阶段的类型转换问题），那类错误文案不带"发生异常"字样，也不由本插件写。

## 五、改了没反应

**现象：改了源码，界面上行为一点没变。**
`Modules\` 下的插件 DLL 不由宿主工程带出，只重建宿主跑的还是旧 DLL。
必须重建插件工程；增量构建还可能静默漏打包（内嵌手册资源同理），
收尾那次全量重建用 `--no-incremental`。

**现象：手册改了页序，界面上顺序没变。**
页序只由文件名的 `NN-` 前缀决定（Ordinal 序），改完必须重建插件工程才会进 DLL。

**现象：想让延时期间界面能操作。**
本节点不提供回调，也不让出线程——它就是睡住自己那条执行线程。
要"等待 + 轮询"请用 While 容器 + 判定算子组合，或在脚本节点里自己写带取消检查的循环。

## 六、快速自查清单

```
① 节点红 → 先看日志有没有"收到急停信号，已强制中断！"（有 = 被中断，不是 bug）
② 时长不对 → 看 Delay 是连线值还是手填值（连线优先）
③ 想拿"实际等了多久" → 连 ET，不要靠外部计时
④ 想做"等完了才走"的分支 → 连 State（跑满才 true），别拿 ET 当判据
⑤ 改了源码没效果 → 重建插件工程，核 Modules\ 下 DLL 的时间戳
```
