# 延时 · 端口与参数

> 分类：常用工具 ｜ 来源：插件 Plugin.Utility

本页是字典：一个输入、两个输出，逐个写清**端口名、声明类型、默认值、必填性、
界面上这一行长什么样、不配置的后果**。内容逐字取自 `DelayPlugin.cs`。

## 端口声明对照

| C# 成员 | 端口名 | 声明类型 | 默认值 | 端口描述 | 必填 |
| --- | --- | --- | --- | --- | --- |
| `DelayTimePort` | `Delay` | `InputPort` 装 `int` | `500` | 延时时间(ms) | 是（源码显式写了 `IsRequired = true`） |
| `ElapsedTime` | `ET` | `OutputPort` 装 `int` | — | 已流逝时间(ms) | 输出端口无此项 |
| `State` | `State` | `OutputPort` 装 `bool` | — | 执行状态 | 输出端口无此项 |

两点要留意：

- **C# 成员名与端口名不一致**：成员叫 `DelayTimePort`、端口名是 `Delay`。
  存盘字典里的键、编译报错里出现的参数名，用的都是**端口名** `Delay`。
- 输出端口属性名（`ElapsedTime` / `State`）与端口名（`ET` / `State`）也不一致，
  `ET` 这个短名是端口名，文档与界面都按它写。

`IsRequired = true` 在源码里是**显式重复**了一遍——`InputPort` 的基类初值本来就是 `true`。
所以这行写不写都一样；反过来，其它三个工具插件（数学计算/类型转换/逻辑运算）没写，
但它们的输入端口**同样是必填**，别把"源码里没写"读成"可以不填"。

## 本插件没有 `[StepConfig]` 配置属性

唯一参数 `Delay` 是输入端口（源码里没有任何 `[StepConfig]` 标注）。后果：

- 它**可以连线**——把配方里的"动作时间"、上游计算出的等待量直接接进来；
- 存盘时和其它参数共用同一个 `InputValues` 字典，不另开一套键；
- 界面回退到宿主自动生成的参数面板，本插件不实现自定义视图接口。

## 参数面板上这一行

宿主自动生成的参数面板只列输入端口，本插件正好一行：

- **行标签用端口描述**，界面上看到的是「延时时间(ms)」，不是 `Delay`——
  文档和报错里出现的是端口名，界面上出现的是描述，同一行的两张脸。
- 控件形态：可编辑文本框 + 🔗 链接图标 + ✕ 清除。类型是 `int`（数值族），
  不是枚举，所以**没有被"封闭集合"那套下拉限制锁住**，能连线也能清除。
- 连线之后手填框里的值不参与生效（生效值以连线为准）。

## 必填判据（三条同时成立才报错）

编译期（`Engine\FlowCompiler.cs`）的判据是：

```
IsRequired == true  且  该端口没有上游连线  且  存盘字典里没有该键的非空常量
```

三条全成立时报：

```
[参数缺失] '步骤名' 的必填参数 'Delay' 未配置！
```

**关键：默认值 `500` 不算"已配置"。** 判据读的是"界面里有没有亲手填过"（存盘字典），
不是端口槽位里的初值。所以：

| 情况 | 结果 |
| --- | --- |
| 从工具箱拖出来、什么都没动，直接编译 | **报参数缺失**（没连线、字典里也没有键） |
| 在面板里填了 `500` 并确认 | 通过（值落进字典，`hasConstant` 成立） |
| 从上游连了一个整数过来 | 通过（连线算来源；此时字典里的键会被 `OnConfirm` 移除） |
| 填过之后又点 ✕ 清除、也没连线 | 报参数缺失 |

画布上还有同一判据的投影：节点角标（黄色叹号）+ 悬停提示
`必填参数未配置（编译会报参数缺失）：` 后面逐行列端口名。

## 两个输出端口的语义细节

**`ET`（已流逝时间(ms)，`int`）**
不是"结束才算一次"的统计量——**每睡完一片就写一次**。
所以急停中断时它是"已经等了多久"的诚实读数，可以被下游取走记录。
正常跑满时它约等于 `Delay`（最后一片按余量截短，不会超过设定值）。

**`State`（执行状态，`bool`）**
方法一进入就被写成 `false`，只有**跑满**那一条路径写 `true`：
急停中断 → 保持 `false`；异常 → 显式写 `false`。
它是"这一轮有没有等完"的信号，**不等同于步骤成功**（虽然本插件里两者恰好同步），
下游要用它做分支请显式连线，别靠节点颜色推断。

## 类型与连线

`Delay` 期望 `int`，编译期连线检查（`FlowCompiler.IsLinkable`）放行：

| 上游输出类型 | 能否连进 `Delay` |
| --- | --- |
| `int` / 数值族（`double`/`float`/`short`…） | 可（数值互转） |
| `string` | 可（运行期 `Convert` 解析文本） |
| `object`（全局变量默认类型） | 可（类型待定，交给运行期校验） |
| `bool` | **否**——`bool` 不属于数值族，报错文案是
`[连线类型不匹配] '步骤名' 的输入端口 'Delay' 期望 Int32，但上游 '…' 提供的是 Boolean。` |

**`double` 连进来会怎样**：连线判据放行，运行期按端口类型取值时做转换——
小数被截断成整数（不是四舍五入语义，按框架转换器的路径处理）。
需要"精确到毫秒"的场合请上游就出整数。

**`ET` / `State` 能给谁**：`ET` 是 `int`，下游数值端口都能接；
`State` 是 `bool`，只能连 `bool` 或 `string` 端口（`bool → double` 会被拦）。

## 改端口名 / 改默认值的代价

- 改端口名 `Delay` = 改存盘键，老方案里那个键查不到 → 端口静默回落到默认 `500`，
  并且**立刻撞上必填检查**（该键在字典里不存在）。
- 改默认值 `500` 影响不了历史方案的行为（历史方案要么连了线、要么字典里有值），
  真正的影响面是"拖出新节点后确认前的那一次"。
- 改分片步长 `50`（`const int step`）会同时改变"急停响应上限"与 `ET` 的更新粒度，
  见开发页与「排障」。
