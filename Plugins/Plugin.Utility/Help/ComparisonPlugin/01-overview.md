# 数值比较

> 分类：逻辑判断 ｜ 来源：插件 Plugin.Utility（工程 `Plugin.Util.csproj`，C# 类 `ComparisonPlugin`）

比较两个 `double` 的大小关系，输出一个布尔判定，并带**浮点容差**——
这是它区别于"直接写 `a > b`"的关键。

## 为什么需要它 / 原理

视觉测量出的尺寸是浮点数，反复跑同一个零件，`12.0000001` 与 `12.0` 是同一个值。
如果用严格相等判定，`Equal` 会随机翻转、分支时好时坏。本节点的六个比较**全部按容差写**：

```
Equal               |a − b| ≤ tolerance
NotEqual            |a − b| > tolerance
GreaterThan         a > b + tolerance          （明显大于）
LessThan            a < b − tolerance          （明显小于）
GreaterThanOrEqual  a ≥ b − tolerance          （大于，或落在容差带内也算）
LessThanOrEqual     a ≤ b + tolerance
```

所以把 `Tolerance` 理解成**判定死区/带宽**：`|a−b|` 不超过它的差值一律视为"相等"，
不影响判定。纯计算、无外部依赖，标了 `[ParallelSafe]`；**没有动态端口**，端口固定五个。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `A` | 否 | 第一个数值（`double`，默认 `0.0`），通常是实测值 |
| `B` | 否 | 第二个数值（`double`，默认 `0.0`），通常是名义值/限值 |
| `Type` | 否 | 比较类型（枚举 `ComparisonType`，默认 `Equal`） |
| `Tolerance` | 否 | 浮点比较容差（`double`，默认 `1E-06`） |

本插件没有自定义配置视图，走宿主自动生成的参数面板：四行按端口名排序显示，
每行填常量或点链接图标连上游输出。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Result` | 比较结果（`bool`，"比较结果"） |

## 关键参数

| 参数（端口名） | 默认 | 说明 |

| `Tolerance` | `1E-06`（0.000001） | 容差/死区宽度，非负数才有意义 |

| `B` | `0.0` | 第二个数值 |

| `Type` 成员名 | 中文含义 | 判据（含容差） |
| --- | --- | --- |
| `Equal` | 等于（容差内视为相等） | `|a−b| ≤ tol` |
| `NotEqual` | 不等于 | `|a−b| > tol` |
| `GreaterThan` | 大于（要超过容差才算） | `a > b + tol` |
| `LessThan` | 小于 | `a < b − tol` |
| `GreaterThanOrEqual` | 大于等于 | `a ≥ b − tol` |
| `LessThanOrEqual` | 小于等于 | `a ≤ b + tol` |

## 口径与失败策略

- **恒判成功**：只做一次比较，没有异常路径也不显式置失败；跑完就是绿的。
  **"超限"不是失败**，它只是 `Result=false`——要按 NG 处理请把 `Result` 接到条件分支或判定步骤。
- **`NaN` 输入**（典型来源：上游「数学计算」除零）时，**六个比较全部返回 `false`，且不报错**。
  表现为"既不等于、也不不等于；既不大、也不小"，这是最容易被误认为节点坏了的现象。
- **没连线就用默认 `0.0`**：只连了 `A` 而 `B` 留空，等于在跟 0 比。
- **容差填 0** 退化成严格比较（`Equal` 就再也不会命中浮点数，慎用）。
- **容差填负数**：`|a−b| ≤ 负数` 恒假 → `Equal` 恒 `false`、`NotEqual` 恒 `true`；
  `GreaterThan` 反而变松（`a > b − |tol|`）。容差请填非负数。

## 典型用法 / 接线

```
Blob 分析.Area ──▶ 数值比较.A
配方参数.名义面积 ──▶ 数值比较.B
                    数值比较.Type = GreaterThanOrEqual
                    数值比较.Tolerance = 0.5      （按测量重复性给，不是越小越好）
                    数值比较.Result ──▶ 条件分支（If）
```

判"NG 个数 > 0"：`A` = 上游 `DefectCount`、`Type` = `GreaterThan`、`B` = 0、`Tolerance` 可以留 0（计数是整数）。
判"尺寸在公差带内"：两个本节点串联（`GreaterThanOrEqual` 下限 + `LessThanOrEqual` 上限），
结果再送「逻辑运算」的 `And`。

## 常见问题

**Q：明明两个值一样，`Equal` 却是 `false`？**
A：看 `Tolerance`。默认 `1E-06` 对**像素级/毫米级**的测量往往太严
（浮点累加误差可以到 1e-5 量级）。按测量重复性放宽，比如 `0.001`。

**Q：`Tolerance` 到底该填多大？**
A：填"你不打算区分的差值"。经验口径：取同件重复测量标准差的 2~3 倍，
或直接按工艺公差的 1/10。它是**判定死区**，不是精度指标。

**Q：`GreaterThanOrEqual` 和 `GreaterThan` 差一个等号，为什么结果差很多？**
A：带容差后它们的边界是**互不重合的两条线**（`b − tol` 与 `b + tol`），
中间那段 `tol×2` 宽的区间里，前者为真、后者为假。上下限判定建议分别用
`GreaterThanOrEqual` / `LessThanOrEqual`，别混用 `GreaterThan`。

**Q：全部比较都返回 false，是不是坏了？**
A：先怀疑 `A` 或 `B` 是 `NaN`（上游除零/负数开方）。
把上游 `Result` 直接接一个显示或记录看一眼值，比在这里猜快。

**Q：想判"整数相等"要不要设容差？**
A：可以留默认。整数（来自计数、序号）做 `double` 比较是精确的，`1E-06` 不会误放行。

**Q：能不能比字符串/日期？**
A：不能，端口类型是 `double`。文本比较需要走脚本类节点；日期先用「类型转换」转成
`DateTime` 再比较（本节点也不吃 `DateTime`，只能先转成数值/时间戳）。

**Q：界面下拉为什么是英文？**
A：这四个工具插件的运算类型枚举还没配中文 `[Display]`（已知待办），
显示的就是成员名（`Equal`/`GreaterThan`/…），含义见上表。
