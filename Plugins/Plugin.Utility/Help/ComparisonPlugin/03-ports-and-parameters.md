# 数值比较 · 端口与参数

> 分类：逻辑判断 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `ComparisonPlugin`）

本页是字典：四个输入、一个输出，逐个写清**声明类型、默认值、必填性、不接线的后果**，
以及界面按什么规则把这一行长出来。含义层面的解释在「概览」，取值边界在「参数与取值边界」，
按现象找原因在「排障」。

## 端口声明对照（逐字取自源码）

| C# 成员 | 端口名（界面上看到的） | 声明类型 | 默认值 | 端口描述 | 必填 |
| --- | --- | --- | --- | --- | --- |
| `ValueA` | `A` | `InputPort` 装 `double` | `0.0` | 第一个数值 | 是 |
| `ValueB` | `B` | `InputPort` 装 `double` | `0.0` | 第二个数值 | 是 |
| `Type` | `Type` | `InputPort` 装 `ComparisonType` | `Equal` | 比较类型 | 是 |
| `Tolerance` | `Tolerance` | `InputPort` 装 `double` | `1E-06` | 浮点比较容差 | 是 |
| `Result` | `Result` | `OutputPort` 装 `bool` | — | 比较结果 | 输出端口无此项 |

`A` / `B` / `Tolerance` 三行的**必填性来自基类默认**：`InputPort` 的 `IsRequired` 初值就是 `true`，
源码里没有写 `{ IsRequired = false }`。别把"必填"理解成"必须接上游连线"，见下节。

## "必填"到底怎么判（三方同一口径）

判据是三条同时成立，不是"有没有连线"一条：

```
IsRequired 为 true   且   该端口没有上游连线   且   手填值为空
```

- **画布上**：满足时该节点亮黄色叹号角标，悬停列出缺失的端口名。
- **编译时**：同一判据报 `[参数缺失] '步骤名' 的必填参数 'A' 未配置！`。
- 角标和编译器各判一套必然出现"角标说缺、编译器放行"的分裂，所以这个判据在两处是逐字对齐的。

也就是说：`A` 里手打了 `12.5`、不接线，完全合法。反过来 `A` 既没连线又留空，编译直接被拦。
`double` 端口的"空"由宿主参数面板判定（清空数字框），不是 `0.0`——`0.0` 是算得出结果的合法值。

## 一个端口的值从哪来（优先级）

```
上游连线值  >  手填（常量）值
```

- 取值走 `GetTypedValue()`：已连线时读的是**缓存的上游值**，不是手填值。
- 连线后你在参数面板里改的那个数**不参与生效**（它仍是"手填值"槽位），
  这也是"改了参数没反应"的标准解释。
- `ApplyConfigValues`（试运行 / 正式运行 / 打开配置窗口三条路共用）灌值时**跳过已连线的端口**，
  所以存盘常量不会覆盖上游实时值。
- 点「确定」时：未连线端口的手填值写回存盘字典；**已连线的端口会把常量键移除**，避免残留脏数据。

## 跨类型连线会发生什么

上游输出类型和本端口声明的 `double` 不一样时，走统一的宽容转换（`ValueConverter`）：

| 上游给的东西 | 接到 `A`（`double`）上 | 接到 `Type`（枚举）上 |
| --- | --- | --- |
| `int` / `long` / `float` / `decimal` 数值 | 按数值转，正常生效 | **编译期就拦**（枚举不参与"数值族互转"这条白名单，报 `[连线类型不匹配]`） |
| 文本 `"12.5"` | 解析成 `12.5` | 按**成员名**解析（`"GreaterThan"` 可以，`"大于"` 不行） |
| 文本 `"abc"` | 转换抛异常 → 编译期连线检查直接拦下，运行期看不到 | 编译期放行（字符串→枚举在白名单里），运行期取值才抛 |
| 存盘回读的 JSON 数字（枚举那一列） | — | 枚举按 JSON **数字**落盘，回读有专门一条"数字 → 枚举"的解析路（见下） |
| `bool` | 转换规则之外的组合按连线检查拦下 | — |

**枚举端口这条要说清**：编译期的连线白名单只放"同类型/派生/枚举 + 字符串源/数值族互转/字符串⇄数值布尔"，
枚举**不算**数值族，所以上游是 `int` 时连线在编译期就被拦（报错文案里期望类型显示的是枚举名）。
运行时转换器其实认"数字 → 枚举"，但那条能力留给存盘回读用，不给你连线用——
想按数字驱动判据，请上游输出成员名字符串，或者用条件分支而不是连线。

最后一行那条历史坑值得记：JSON 里枚举是数字，早先的转换实现不认"数字 → 枚举"，异常被灌值的宽容
`catch` 吞掉，症状是**方案重开后枚举配置静默回到默认值**（所有插件的枚举配置一起中招），
现在这条已在转换器里显式处理（拆包后的枚举目标按名字/数字串解析，非 JSON 来源的整数按枚举底层类型取值）。
所以"我存的 `GreaterThanOrEqual` 打开又变回 `Equal`"这类现象，
先确认插件 DLL 版本，不要怀疑自己的操作。

## 存盘键（`.vms` 里长什么样）

本插件**没有任何 `[StepConfig]` 配置属性**——四个参数全是端口，因此存盘字典的键就是端口名：

```
"InputValues": {
  "A":         12.5,
  "B":         12.0,
  "Type":      4,            // 枚举落盘是数字：Equal=0 … LessThanOrEqual=5
  "Tolerance": 0.001
}
```

- 键名 = 端口名（`A`/`B`/`Type`/`Tolerance`），没有额外映射层。
- 已连线的端口不会出现在这里（确认时被移除）。
- 手改 `.vms` 里的 `Type` 数字是可行的（`0`~`5`，顺序见下），但**推荐在界面里选**。

## 界面为什么是英文成员名

`Type` 这一行的下拉候选来自端口的预设选项，而预设选项就是**枚举成员名原样列出**
（`Equal` / `NotEqual` / `GreaterThan` / `LessThan` / `GreaterThanOrEqual` / `LessThanOrEqual`，
按声明顺序，编号 0~5）。这一族工具插件的运算类型枚举还没配中文显示名（已知待办），
**界面上显示的就是英文成员名，不会显示中文**。含义对照见「概览」里的成员表。

其余三行是数字输入框（`double`），没有下拉。

## 没有的东西（避免按别的插件找）

| 你会找 | 实际情况 |
| --- | --- |
| 配置项页签 / 专属配置界面 | 无。本插件不实现自定义视图接口，走宿主自动生成的参数面板，按端口排序显示四行 |
| 显示窗口 / 结果图 | 无。本插件不产出图像，也不往主界面视图窗口投东西 |
| 动态端口 | 无。端口恒为四个输入 + 一个输出 |
| 容差开关 | 没有开关。六个比较**全部**带容差参与判定，改不了"带不带容差"，只能把 `Tolerance` 填 `0` |
