# 逻辑运算 · 排障

> 分类：逻辑判断 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `LogicOperationPlugin`）

按"看到什么现象"来查。本插件的算法体就是一次 `switch`：**不打日志、不判失败、不 try/catch**，
所以"日志里干干净净但结果不对"是它的常态形态。下面每条给原因和改法。

## 一、编译/运行前就被拦的

| 现象（原文） | 为什么 | 怎么改 |
| --- | --- | --- |
| `[参数缺失] '步骤名' 的必填参数 'A' 未配置！` | `A` 既没连线、手填值也是空的（判据三条同时成立，见「端口与参数」） | 填 `True`/`False`，或把上游布尔输出连过来 |
| 同上，参数名是 `B` / `Operation` | 同上，换了个端口 | 同上 |
| 节点上亮黄色叹号角标 | 同一条判据的画布投影（与编译器逐字对齐） | 悬停看它列出哪几个端口名，逐个补 |
| `[连线类型不匹配] '步骤名' 的输入端口 'A' 期望 Boolean，但上游 'XXX' 提供的是 Int32。请在变量绑定处改选类型兼容的输出，或调整上游算子的输出类型。` | **bool 不算数值族**，"非零即真"在这里不成立 | 上游先接一个「数值比较」（如 `NotEqual`、`B=0`）出布尔，再连进 `A` |
| 同上，端口是 `Operation`，上游给数字 | 枚举也不参与数值族互转白名单（运行时转换器认数字→枚举，但编译期连线检查不认） | 改连**成员名字符串**输出，或直接在面板下拉里选 |

## 二、跑通了、但结果不是想要的

**现象：填了常量，结果不跟着变。**
先分清两种完全不同的原因：
① 这一行**已经连了上游**——连线值优先于手填值，手填槽位不参与生效。要用手填值就点 ✕ 断线。
② 填的文本**不是** `True` / `False`（比如打了 `1`、`0`、`是`、`yes`）。文本转 `bool` 走
`Convert.ChangeType`，它只认这两个词；转换抛异常后被静默吞掉、**保留原值，不弹任何错**。
界面上看着"我填过了"，实际还是旧值——这是本插件最容易白费时间的一条。

**现象：`And` 永远是 `false`。**
两路里有一路没连、也没填，`bool` 端口没值时取声明的默认值 `false`（不是"空"、也不报错）。
`And` 遇到一个 `false` 就恒假。用不上的那一行请显式填 `True`（对 `And` 是中立项）。

**现象：`Or` 永远是 `true`，明明条件都不满足。**
同一枚硬币的反面：默认 `false` 不影响 `Or`，但如果你把某一行填成了 `True` 当占位忘了改回来，
`Or` 就恒真。取反类运算（`Not` / `Nand` / `Nor`）尤其容易被默认值骗到——两行都留空时
`Nand` / `Nor` 输出的是 `true`，看起来像"莫名成功"。

**现象：接了 `Not`，输出跟上游一模一样。**
`Not` **只取 `A` 取反**，`B` 完全不参与。多半是把上游连到了 `B` 上。
（`A` 留空时 `Not` 恒为 `true`，那是另一种表现。）

**现象：`Xor` 看着像 `Or`。**
`Xor` 只在"两个不同"时为真，两个都真时是 `false`。多条件里如果常有"同时为真"的情形，
`Xor` 和 `Or` 的结果会大面积一致，只在"两个都真"那格分开。确认你要的语义是"恰好一个"还是"至少一个"。

**现象：想判三个条件，接了两个节点，第二个结果不对。**
链式接法要把**第一个节点的 `Result` 连到第二个节点的 `A`**，第三个条件连 `B`。
接到两个都连 `A` 之类的错法，第二个条件会被直接覆盖掉。

**现象：重开方案后运算类型变回了 `And`。**
枚举是以数字落盘的（`And=0 … Nor=5`），"回读后静默还原成默认值"是历史 bug，
已在统一转换器里修掉。现在再出现这个现象，先确认 `Modules\Plugin.Util.dll` 是本次构建产物，
不要怀疑自己的操作。手改 `.vms` 时把 `Operation` 写成成员名以外的字符串同样会静默回默认值。

**现象：节点是绿的，但产品明明是 NG。**
本节点恒判成功，`Result=false` 只是数据、不是失败。
NG 语义要由下游条件分支 / 判定步骤产生，别指望这个节点变红。

**现象：换了工位 / 换了配方，结果整体反了。**
看上游是不是**恒为假**（传感器常开、判定节点没跑）或**恒为真**（默认值当占位没清）。
先单独试运行上游那一步，再回来看组合。

## 三、想表达的东西它表达不了

| 想表达 | 用什么 |
| --- | --- |
| 数值条件（尺寸超限、计数 > 0） | 先「数值比较」出布尔，再进这里组合 |
| 三个及以上条件 | 本节点两个操作数封顶，链式串多个「逻辑运算」；复杂条件改用脚本类节点一次写清 |
| 短路求值（前一条件为假就不执行后一步） | 这里做不到：`A` / `B` 是**数据端口**，上游步骤已经各自跑完了才轮到这里。要短路请用条件分支容器把后一步包起来 |
| 带优先级的复合条件（`(a and b) or (c and d)`） | 两两组合 + 一次 `Or`；层级深就用条件分支或脚本 |
| 位运算、多个布尔打包成一个整数 | 本节点只处理两个布尔；用脚本类节点 |
| 触发沿（上升沿才动作） | 本节点是纯组合逻辑，没有状态、没有沿检测 |

## 四、快速自检（换工位 / 改配方之后）

1. 打开参数面板，三行的**标签**是「输入A」「输入B」「逻辑运算类型」，逐个确认值而不是看有没有填过。
2. 每行左侧的连接状态：连了上游的行，框里的值不生效，要改的是连线不是文本。
3. `Operation` 是英文成员名，逐字看清 `Nand` 与 `Nor`、`Or` 与 `Xor` 这类后缀差异。
4. 用不到的那一行按运算类型填**中性值**：`And`/`Nand` 用 `True`，`Or`/`Nor` 用 `False`，`Not` 时 `B` 随意。
5. 拿两个已知组合（都真 / 一真一假）各跑一次，看 `Result` 而不是看节点颜色。
