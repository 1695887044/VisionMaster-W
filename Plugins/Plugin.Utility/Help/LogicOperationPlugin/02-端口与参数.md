# 逻辑运算 · 端口与参数

> 分类：逻辑判断 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `LogicOperationPlugin`）

本页是字典：三个输入、一个输出，逐个写清**声明类型、默认值、必填性、界面这一行长成什么样、
不接线的后果**。"该用哪个运算"在「概览」的真值表里，按现象找原因在「排障」。

## 端口声明对照（逐字取自源码）

| C# 成员 | 端口名（界面上看到的） | 声明类型 | 默认值 | 端口描述 | 必填 |
| --- | --- | --- | --- | --- | --- |
| `InputA` | `A` | `InputPort` 装 `bool` | `false` | 输入A | 是 |
| `InputB` | `B` | `InputPort` 装 `bool` | `false` | 输入B | 是 |
| `Operation` | `Operation` | `InputPort` 装 `LogicOperationType` | `And` | 逻辑运算类型 | 是 |
| `Result` | `Result` | `OutputPort` 装 `bool` | — | 运算结果 | 输出端口无此项 |

三行的**必填性来自基类默认**：`InputPort` 的 `IsRequired` 初值就是 `true`，源码里没写
`{ IsRequired = false }`。端口名与 C# 成员名**故意不一致**（`InputA` → `A`），
存盘字典里的键、报错文案里的参数名，用的都是**端口名**那一列。

## 参数面板上这三行

本插件没有自定义配置视图，宿主回退到自动生成的参数面板，规则是：

- **只列输入端口**（`[StepConfig]` 常量在这个面板上没有形态可渲染），本插件正好三个；
- **行序按端口名排序**（忽略大小写），所以界面上是 `A`、`B`、`Operation` 这个顺序，
  不是源码里的声明顺序；
- **行标签用端口描述**（描述为空才退回端口名），所以你看到的是「输入A」「输入B」「逻辑运算类型」，
  不是 `A`/`B`/`Operation` 这三个键名——文档和报错里出现的是键名，界面上出现的是描述，同一行的两张脸。

每行右边是 🔗（连上游）和 ✕（清除连线），可以直接在框里填常量。

| 行 | 输入形态 | 能填什么 |
| --- | --- | --- |
| 输入A | 文本框 | `True` / `False`（大小写随意） |
| 输入B | 文本框 | 同上；选 `Not` 时这一行不参与运算 |
| 逻辑运算类型 | **下拉**（枚举端口） | `And` / `Or` / `Not` / `Xor` / `Nand` / `Nor`，英文成员名 |

**布尔行只认 `True`/`False`**：文本到 `bool` 走的是框架统一转换器的 `Convert.ChangeType`，
它只解析这两个词。在框里打 `1`、`是`、`yes`，转换抛异常后被**静默吞掉、保留原值**——
界面上不会弹错，看起来"我填了 1"，实际存的还是旧值。这是本插件最省时间的一条使用纪律。

**运算类型是下拉而不是输入框**：枚举端口在编辑器里被识别为"只能选"，候选直接把枚举成员名列出来。
`LogicOperationType` 没配中文显示名（已知待办），**界面上就是英文成员名，不会显示"与/或/非"**，
中文含义对照看「概览」的真值表。

## "必填"到底怎么判（三方同一口径）

```
IsRequired 为 true   且   该端口没有上游连线   且   手填值为空
```

- **画布上**：三条同时成立时节点亮黄色叹号角标，悬停列出缺失端口名。
- **编译时**：同一判据报 `[参数缺失] '步骤名' 的必填参数 'A' 未配置！`。
- 手填过常量（哪怕就是 `False`）就不算缺，**"必填"不等于"必须接上游"**。
- 注意 `bool` 端口的"空"和 `double` 不一样：`false` 是一个能正常参与运算的值，
  只有既没连线、存盘字典里又查不到这个键时才算缺。刚拖入的新步骤就是这种状态。

## 一个端口的值从哪来（优先级）

```
上游连线值  >  手填（常量）值
```

- 算法取值用 `GetTypedValue()`：已连线时读缓存的上游值，手填值不参与生效。
- 因此"面板里改了 `A` 但结果不变"多半是这一行**已经连了上游**。
- 灌值（试运行 / 正式运行 / 打开配置窗口共用一条路）时**已连线的端口会被跳过**，
  存盘常量不会覆盖上游实时值。
- 点「确定」时：未连线端口的手填值写回存盘字典；已连线的端口把常量键**移除**，不留脏数据。

## 跨类型连线会发生什么

编译期的连线检查与运行时转换能力逐条对齐，`bool` 端口这一族要注意 **bool 不算数值族**：

| 上游输出类型 | 接到 `A` / `B`（`bool`） | 接到 `Operation`（枚举） |
| --- | --- | --- |
| `bool`（判定、比较类的 `Result`） | 正常，这是本节点的常规接法 | — |
| 数值（`int` / `double`…） | **编译期拦**：`[连线类型不匹配]`，期望 bool、上游给 int | **编译期拦**（枚举不参与数值族互转白名单） |
| `string` | 放行；运行时按 `True`/`False` 解析，别的文本抛异常 | 放行；按**成员名**解析（`"Or"` 可以，`"或"` 不行） |
| 图像 / 自定义对象 | 编译期拦 | 编译期拦 |
| `object`（弱类型上游） | 类型未知，编译期放行，运行期到了值才知道 | 同左 |

也就是说：**"非零即真"这种写法在这里不成立**。想把数值判成布尔，先接一个「数值比较」
（例如 `Type=NotEqual`、`B=0`），再把它的结果连进 `A`。

## 存盘键（`.vms` 里长什么样）

本插件**没有任何 `[StepConfig]` 配置属性**——三个参数全是端口，因此键就是端口名：

```
"InputValues": {
  "A":         true,
  "B":         false,
  "Operation": 4            // 枚举落盘是数字：And=0 Or=1 Not=2 Xor=3 Nand=4 Nor=5
}
```

- 已连线的端口不会出现在这里（确认时被移除）。
- 手改 `.vms` 里的数字是可行的（0~5），但**推荐在界面里选**；改成员名会让按名字解析的来源失配。

## 没有的东西（避免按别的插件找）

| 你会找 | 实际情况 |
| --- | --- |
| 配置项页签 / 专属配置界面 | 无。走宿主自动生成的参数面板，三行 |
| 动态端口 / 多操作数 | 无。端口恒为三个输入 + 一个输出，两个操作数封顶 |
| 失败路径 / 日志 | 无。算法里没有异常分支也不显式判失败，跑完就是绿的 |
| `B` 的显隐控制 | 没有。选 `Not` 时 `B` 仍显示、仍可填，只是不参与运算 |
