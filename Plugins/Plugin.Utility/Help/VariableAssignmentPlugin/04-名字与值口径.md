# 变量赋值 · 名字与值口径

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

这一页把界面上最容易踩的三件事一次讲清：**「变量名」这一行怎么用**、
**「值」按什么口径解析**、**切作用域时名字会不会被清掉**。
三条都是真机上踩过并已在代码里定死的规则，不是推测。

## 规则一：变量名是"名字"，不是值

**名字行没有通用「变量绑定」弹窗入口，也没有链接图标。** 名字与值的语义不同：

| 作用域 | 名字怎么来 | 为什么 |
| --- | --- | --- |
| 全局变量 | **只能从变量管理里选**（可搜索） | 变量管理是权威注册表；手填一个不存在的名字，运行期只能报错 |
| 运行时变量 | **候选 + 允许手填** | 脚本 `SetVar` / 动态创建的名字不在快照里；只给下拉会漏掉合法变量 |

**全局行**：名字单元格是「选择全局变量」按钮，点开是搜索 + 候选浮层。当前名字不在快照里时，
浮层首项是只读的「失效」项（`IsEnabled=False`），**不会自动替换、也不会静默清空**；
运行期会明确报「找不到全局变量」，错误消息里点名原来的名字。

**运行时行**：可编辑下拉，候选来自上游「变量定义」；手填给「手填」徽标，并按四档提示：

| 情况 | 级别 | 提示要点 |
| --- | --- | --- |
| 命中上游变量定义 | 信息（蓝） | 写入运行时变量「X」（类型）· 说明 |
| 未命中 + 未勾自动创建 | 警告（琥珀） | 运行期会报「本地变量 X 不存在」；请声明或勾选「自动创建」 |
| 未命中 + 已勾自动创建 | 信息（蓝） | 运行期会新建「X」（类型由值决定）；名字由你负责，拼错会新建另一个 |
| 同名但在全局 | 警告（琥珀） | 「X」是全局变量；要写它请把作用域改成「全局变量」 |
| 全局行名字失效 | 错误（红） | 变量管理里没有「X」：运行期明确报错，不会静默新建 |

**为什么名字行不能挂通用绑定弹窗**：语义是**值**的端口才配绑定弹窗/行尾链接图标；语义是**名字**的
（变量名、步骤名、卡地址、端口名）挂绑定弹窗只会落一条"该端口的值由对方提供"的连线。
在弹窗里选中全局变量 `OKCount`，落下来的不是"名字 = OKCount"，而是一条运行期把 `OKCount` 的
**当前值**喂进这个名字端口的连线。后果两种，都很难看：

| 后果 | 现场表现 |
| --- | --- |
| 编译期类型不匹配 | 上游给的值类型和名字端口的 `String` 不符，编译报 `[连线类型不匹配] … 的 'Name' 期望 String，但上游 '…' 提供的是 …` |
| 运行期**拿值当名字** | 变量恰好是数值型 → 名字变成 `"0"`，于是"给 OKCount 赋值"变成了"给一个叫 0 的变量赋值"：步骤可能照常绿，值却写去了别处（静默故障） |

**老方案里已经挂过这种连线的怎么办**：迁移行下方会显示
`该行原由上游提供（{上游地址}）—— 在本行选/输一个变量名，即可改为手填。`
你在这行**真的动手**时，插件才把那条旧连线解除；只是打开看一眼、点取消，连线不会被碰。
确认时 `RemoveLegacyNameLink` 也会统一解除旧 `Name` 连线（名字类端口不该保留连线）。

"真的动手"的判据是**真实输入事件**：键入字符、退格/删除、`Ctrl+X`、粘贴、右键菜单里的「剪切 / 删除」、
拖拽落文，以及从下拉里选进来一项（`SelectionChanged` 且**有新增项**）。程序灌值（试运行桥接、
候选回填、配置加载）一条都不走这里。新视图按行上报 `NotifyRowNameEditedByUser(rowId)`。

另外运行时名字行关掉了"输入即补全"（`IsTextSearchEnabled=False`）：否则刚敲 `OK` 会被补成
`OKCount` —— 正是这一类"静默写错变量"要消灭的对象。候选照常从下拉里选。

## 规则二：手填的「值」是文本，按目标类型解析一次

界面上的值框**只能产出文本**（端口是 `object`，常量落进 JSON 快照也是文本），所以"给 `Int32` 变量填 `21`"
必须有写入侧的一次解析，否则这类最普通的用法永远不可能成功。口径是**宽进严出**：

| 给进去的东西 | 怎么处理 |
| --- | --- |
| **文本**（手填的常量） | 按目标变量的声明类型解析一次；能解析就写，解析不了明确报错，**错误消息里带上被拒的原值** |
| **类型化的值**（链接图标连上游给的 `double` / `HImage` …） | 仍按原样报类型不匹配。那是上游接线错了，静默截断/转换只会把错因推到很远的地方 |

数值文本另外两条硬口径：

- **不变区域性（InvariantCulture）**：显式写死，换机器/换区域设置时同一个方案解析出同一个数。
- **拒绝千分位分隔符**：默认解析会把 `2,5` 读成 `25`。这是"应当报错却改了值"，宁可拒收，
  让你把 `1,500` 重打成 `1500`。所以带逗号的数字一律失败，**不会被当成 1500**。
- 另外两条细节：**先裁掉首尾空格**再解析；**空文本不算解析成功**（直接按类型不匹配报出去）。
- 目标类型是 `Nullable` 时先剥掉包装（否则 `Nullable<int>` 会让解析直接抛）。

**数组 / 枚举 / HImage 这类声明类型的变量，填文本是解析不了的**（必然报"无法写入 String"）——
这种值只能用行尾链接图标引用上游输出端口。**值行不提供手输变量名**：手输的是字面量，不是引用；
要取某个变量的当前值，请用 `LinkableValueEditor` 的链接（`RuntimeVariable` / `GlobalVariable` 连线）。

运行时变量那条路（作用域=Runtime）保持同一口径：值类型与池里既有类型不一致时**能转就转**
（会写一条警告日志 `… 值类型已按变量既有类型 {类型} 自动转换`），转不了就显式失败并带上值。

**为什么运行时也要挡类型**：变量池的类型是条件表达式的"契约"——`double` 变量被塞进 `string` 之后，
If/While 每次求值都抛异常、所有分支集体不走而流程照常往下跑，是最难排查的静默故障形态。

## 规则三：切作用域不再清空名字

v1 的现象：选中/输入一个名字，把作用域从"运行时变量"切到"全局变量"（或反向），
名字行**自己变空**；点确定后落盘成空名，运行时报 `变量名称不能为空`。

原因（WPF 实测行为）：候选列表按作用域整批重算，重算要清空再填；而可编辑 `ComboBox` 在**当前有选中项**时
清空 `ItemsSource`，会连带把 `Text` 置空，并沿双向绑定把空串**推回端口**。端口才是这一行的真值来源。

v3 已处理三件事：

1. `RefreshCandidates` **重算前先记住行里的名字，重算后顶回去**；候选集合用会通知界面的类型。
2. `AssignmentRow.Scope` 的 setter **忽略空值**（不是回落 `Runtime`）。作用域 `ComboBox` 在容器生成/回收时
   会把 `SelectedValue` 推成 `null`，回落 `Runtime` 会让一条「全局」行静默变成「运行时」行。
3. 作用域切换时通知 `IsGlobal` / `IsRuntime` / `ScopeText` / `CanCreate` / `ShowLock`，
   名字单元格、右侧徽标、自动创建列会**立即换模板**，不会出现"作用域显示运行、名字列还是全局模板"的半旧状态。

切到全局会自动把该行 `CreateIfNotExists` 置 `false`（全局不能自动创建）；切回运行时**不会自动勾回来**，
需要的话手动勾一次——这是刻意的，避免把"全局禁用"的意图带回来。

## 操作顺序（照做即可）

```
1 添加一行        需要几个变量就加几行（上限 32）
2 选作用域        每行独立；先定这个，候选列表才准
3 定名字          全局：点「选择全局变量」搜索/选；运行时：候选或手填
4 看那行小字      命中候选会说清声明类型；没命中会说清运行期怎么失败
5 填值            常量直接敲（纯数字，不带逗号）；要上游结果就点值行行尾的链接图标
6 自动创建        只在作用域=运行时变量时有意义
7 重复 1-6        行顺序即执行顺序；复制行会清空目标名
```

## 常见问题

**Q：名字行的提示说"变量管理里没有「X」：运行期会明确报「找不到全局变量」，不会静默新建"，是错误吗？**
A：不是错误，是提前告诉你会怎么失败。要么改选一个全局变量，要么先去变量管理建。

**Q：提示说"「X」是运行时变量（Double），不在变量管理里 —— 全局作用域写不了它"？**
A：同名但作用域选错。这正是"必须有作用域选择"的原因：两个池子里的同名变量是两个东西。

**Q：为什么"给 Int32 变量填 `21`"能成，但"填 `21.5`"失败？**
A：`21` 能解析成 `Int32`；`21.5` 按 `Int32` 解析会抛，且只放宽文本一次，不会帮你四舍五入。
先想清楚目标变量的声明类型（提示行里就写着）。

**Q：`1,500` 到底会写成什么？**
A：**什么都写不进去**——千分位被拒，直接报类型不匹配（原值会出现在错误消息里）。
这是有意为之，好过把 `2,5` 静默变成 `25`。

**Q：我在这行敲了字，画布上原来那根线怎么没了？**
A：那是规则一的处置：那条线是"值当名字"的旧连线，你动手编辑名字就解除它。
如果不想解除，就别改这一行（只打开看一眼、点取消，线会留着）。

**Q：勾了「自动创建」，全局变量还是报找不到？**
A：自动创建只对运行时变量有效。全局量表是设计期资产，运行期只写不增；全局行的「自动创建」是锁。

**Q：全局变量失效了，为什么界面不帮我清空/换一个？**
A：清空会把错误变成"变量名不能为空"，丢掉原名字；自动换一个会静默改目标。
保留原名、标「失效」、由运行期点名，是 v3 明确选择的策略。

**Q：复制行为什么名字是空的？**
A：复制的是作用域/自动创建/值（含链接），**目标名故意清空**——两行写同一个变量通常是误操作。
复制后请重新选/填目标。

**Q：试运行和正式运行表现不一样？**
A：留意试运行会把上游实际值灌进配置实例的端口。插件已经区分"程序灌值"与"用户编辑"，
所以试运行不会误解除你什么都没动的旧连线；但你在试运行里改的名字可能与保存的方案不同，
确认后要回配置窗口重填一次。

**Q：为什么同一个程序集里「数学计算」的运算是英文，这个节点的界面却是中文？**
A：作用域/提示文案是写死在本节点视图与插件里的；而「数学计算 / 数值比较 / 逻辑运算 / 类型转换」
四个插件的运算枚举**成员目前没标中文显示名**，下拉就是 `Add` / `Equal` / `And` / `Int32` 这类成员名。
这是框架那条"枚举上屏走中文显示名"纪律的**未清欠账**，不是本节点的问题。
