# 变量赋值：不变量与移植清单

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）｜ 读者：开发

两组：**A 组**违反就编译红/闸门红，**B 组**违反不报错、只出诡异现象。每条一律写成
`症状 → 机理 → 守门断言名`。

本条目的断言密度在工具类插件里是最高的：`FlowCanvasChecks\VariableAssignmentCheck.cs`（按 `[A2]`/`[A3]`/`[A4]`
三段组织，反射构造插件与设端口）+ `FlowCanvasChecks\GlobalVariableChecks.cs`（41 条，主要覆盖变量管理侧的
数组子行/列宽/当前值提交）。**下面写的是从这两个文件里逐个抄出来的真实断言名**；查不到断言的条目
明写"无断言，靠人工核对"，不当已验证。

## 一、A 组：违反就编译红 / 闸门红

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| 老流程一编译就报"必填参数未配置" | 四个端口必须显式 `IsRequired = false`；`InputPort.IsRequired` 默认 `true`，而编译期必填判据只看有没有连线来源 | `【运行时】变量不存在 + 没勾自动创建 → 明确报「不存在」` 所在的 `[A2]` 段整体会红（该段每个用例都靠"没连线、只填常量"跑通）——真正的静态口径写在插件源码注释里，改动后由 `VariableAssignmentCheck` 的 `[A2]`/`[A4]` 三段集体反证 |

| 作用域切换后候选/提示没跟着换 | 候选按作用域过滤，且只订了 `Scope.ValueChanged`；订错对象或漏订都会红 | `【插件】作用域=全局 → 候选只剩全局变量`、`【插件】作用域切到运行时 → 候选换成上游变量定义声明的名字`、`【插件】切作用域后提示跟着换（名字不在运行时候选里时会说清后果）` |

## 二、B 组：不报错，只出诡异现象

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| 失败原因在引擎日志里消失 | 某条失败分支**没 `return`**，落到下一行把 `ErrorMessage` 洗成空（历史上真犯过，两处） | 无断言逐条钉这两行，靠人工核对 + `【运行时】变量不存在 + 没勾自动创建 → 明确报「不存在」` 的返回值反证 |
| `Scope` 改成枚举后方案一打开就炸 | `InputValues` 把枚举存成 int，读回赋端口时抛 `InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'` | 无断言；`【全局】名字行挂…连线` 那一组间接要求端口是 `string`，改动前先看这条 |
| 步骤永远红、错误日志永远为空 | 自声明 `Success`/`ErrorMessage` 同名属性**影子隐藏**基类成员：插件写派生口、引擎读基类口（CS0108） | 无断言，靠人工核对（插件里那段注释是唯一的说明） |
| 换作用域后下拉还是旧内容 | 候选集合用了不通知界面的普通 `List` | 无断言（重算本身由 `【插件】作用域切到运行时 → 候选换成…` 覆盖，"通知"这半边只能现场看） |
| 订阅翻倍、提示与候选互相打架 | `Initialize` 会被多次调用（开配置窗、试运行），订阅没判重 | 无断言，靠 `_configEventsHooked` 那段守卫 + 人工核对 |
| 名字被"输入即补全"改写成另一个变量 | 可编辑 `ComboBox` 默认 `IsTextSearchEnabled=true`，敲 `OK` 补成 `OKCount` → 静默写错变量 | 无断言（静态扫描只查"不是通用绑定控件"这一半） |
| 网络变量的设备侧原因被吞掉，只剩一句泛泛失败 | 写入器把 `IWritableVariable.TryWrite` 的 `writeError` **原样透出**是刻意的；空串才回落通用文案 | `【当前值】网络变量写入失败如实报错（未绑定管理器）、镜像值不变`（`FlowCanvasChecks\GlobalVariableChecks.cs`，同一口径的变量管理侧） |
| 布尔类网络变量写不进、或写进去的是错的 | 设备侧按 PLC 约定解析（`1`=真 / `off`=假），不走 `ChangeType` 的英文异常口径 | `【当前值】布尔按 PLC 约定解析（1=真 / off=假），不是 ChangeType 的英文异常` |
| 手动写值把"基准"冲掉 | 写当前值不动初始值，是变量管理侧的同一套纪律（本节点写全局变量走的是同一个可写契约） | `★【当前值】提交写入当前值、初始值（基准）分毫不动`、`★【当前值】元素行提交只写 Value[i]、基准数组分毫不动` |
| 并行分支写同一个全局变量，结果时对时错 | `[ParallelSafe]` 只声明"本插件实例无共享可变状态"，**不等于同变量并发写安全** | 无断言，靠流程设计（用户页已明写这条边界） |

## 三、改这个文件必须连带的动作

| 改了什么 | 必须同步 |
| --- | --- |
| 端口名（`Name` / `Value` / `CreateIfNotExists` / `Scope`） | `.vms` 的 `InputValues` 键随之变化、老方案静默回落默认；《端口与参数》页的存盘键表与《名字与值口径》里引用端口名的地方 |
| `Scope` 的字面量 | 必须同时改 `VariableOption.Scope`（宿主快照）与视图里两个 `ComboBoxItem` 的 `Tag`，否则候选永远过滤不出东西；报错文案里的 `Runtime`/`Global` 也要跟着 |
| 名字行的控件形态 | 《名字与值口径》规则一 + 静态扫描类断言（`【视图】…` 两条）；想"顺手统一成通用绑定控件"就是本次事故的回归 |
| 失败消息原文 | 《排障》页四张原文表要求**逐字一致**；改了源码不改表，那张表会把现场排查带偏 |
| 类型解析口径（千分位/区域性/Nullable/Trim） | 《名字与值口径》规则二 + `GlobalVariableWriter.TryCoerceText`（两处口径要一致，插件侧运行时转换与主程序侧文本解析各一份） |
| 快照字段（`VariableOption` 增删字段） | 宿主组装处 `VisionMaster\Helpers\PluginVariableOptions.cs` + 插件提示文案 + `【快照】…` 断言 |
| 插件源码或手册 | **重建 `Plugin.Util` 工程**（`Modules\Plugin.Util.dll` 不由宿主工程带出，只重建宿主跑的是旧 DLL，红线③）；加完手册要核 DLL 里的 `.Help.` 资源名数量（R42，增量构建会静默漏打包） |

## 四、移植清单（把这个节点搬到别的项目时）

1. **能力契约要有**：一个跨程序集的"按名写全局变量"接口，三步顺序固定（查表 → 类型守门 → 落值），
   且**运行期不自动建变量**；失败必须带中文原因并原样透出设备侧消息。
2. **候选要有宿主透传的只读快照**（名字 / 作用域 / 声明类型 / 说明），不要让插件持有方案的活对象。
3. **名字类端口一律"手填 + 候选"**，且关掉输入即补全；绑定弹窗只留给语义是"值"的端口。
4. **用户意图要接真实输入事件**（六类：键入、退格/删除、`Ctrl+X`、粘贴、命令预览的剪切/删除、拖拽落文，
   外加下拉选中新增项），不要从"值变了"倒推。
5. **候选重算要保住端口里的值**（先记住、重算后顶回去），且用会通知界面的集合类型。
6. 四个端口全部 `IsRequired = false`；`Scope` 用字符串 + 白名单校验。
