# 变量赋值 · 排障

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

下表第一列是**错误信息/日志原文**（取自插件与主程序侧写入器源码）。
本节点的原则是"赋不进去一律显式失败并说清原因"，所以**这一步红了就一定有消息**；
多行模式下消息带行号，真遇到空消息，看第七节的兜底分支。

## 一、插件侧（逐行执行）

`RunRows` 对每一行独立执行，失败行不阻断后续行。行标签是 `第{index}行「{name}」`；
名字为空时标签退化成 `第{index}行`。整节点失败时 `ErrorMessage` 汇总：

```
{N}/{M} 行失败：第1行「A」…；第3行「B」…（最多前 3 条，其余写「等 N 行」）
```

每行另有一条 Error 日志：`{实例名} 第 N 行「X」赋值失败：{原因}`。

| 报错原文（单行原因） | 触发条件 | 处置 |
| --- | --- | --- |
| `变量名称不能为空` | 该行名字是空串或全空白 | 在名字行选/填一个名字；空行会一直红 |
| `作用域取值无法识别：「{你填的}」（应为 Runtime 或 Global）` | 该行作用域不在白名单里（多半是旧方案/脚本塞进来的字符串） | 用界面下拉选；**不会**把它"当成 Runtime"跑过去——拼错一个字母会把值静默写到另一个池子里 |

## 二、作用域=全局变量：写入器侧（按守门顺序，先命中谁就是谁）

| 报错原文 | 含义 | 处理 |
| --- | --- | --- |
| `目标全局变量名不能为空` | 名字被清成空串（或全是空格） | 重新选一个全局变量 |
| `当前执行环境没有绑定工作区，无法写入全局变量` | 在脱离工作区的执行环境里跑（容器/独立调用） | 只能在完整流程里写全局变量 |
| `当前执行环境不支持写全局变量` | 执行环境压根没有写入能力（连工作区都没有注入） | 同上；确认跑的是正式流程而不是脚本化调用 |
| `找不到全局变量「X」，请先在变量管理里新建同名变量` | 名字写对了但量表里没这个变量；**运行期不会自动建** | 去变量管理建同名变量，或改选已有名字 |
| `全局变量「X」的类型是 Int32，无法写入 String（值 [abc]）` | 文本按声明类型解析不出来（**被拒的原值已写在括号里**） | 按类型填正确的文本，或用链接图标连上游输出 |
| `全局变量「X」不支持写入（该变量类型未实现可写契约）` | 该变量源不接受显式写 | 换个变量或改流程设计 |
| `全局变量「X」写入失败` | 变量侧写失败但没给具体原因 | 看日志同实例名的 Error 行 |
| `写全局变量 X 失败` | 写入器返回失败但错误串为空（理论分支） | 同上，按日志定位 |

## 三、作用域=运行时变量

| 报错/日志原文 | 含义 |
| --- | --- |
| `本地变量 {名字} 不存在` | 变量池里没有这个名字，且没勾「自动创建」。运行时变量通常由上游「变量定义」节点声明 |
| `{实例名} 第 N 行：本地变量 {名字} 已创建并赋值` | 勾了自动创建、本轮新建成功（INFO，正常） |
| `{实例名} 第 N 行：本地变量 {名字} 已赋值` | 覆盖已有变量成功（INFO） |
| `{实例名} 第 N 行：全局变量 {名字} 已赋值` | 全局写入成功（INFO） |
| `变量 {名字} 类型为 {类型}，值 [{值}] 无法转换：{原因}` | 类型不符且转不动（**显式失败**）。为什么不静默通过：变量池的类型是条件表达式的契约，塞错类型会让 If/While 每次求值都抛、所有分支集体不走而流程照常往下跑 |
| `{实例名} 赋值 {名字}：值类型已按变量既有类型 {类型} 自动转换` | 成功，但值被按池里既有类型转过一次（WARN）。这是设计好的行为，不是异常 |

## 四、网络变量（PLC/SCADA 那批）的失败原因会原样透传

作用域=全局变量、而那个变量是网络变量时，失败原因是**设备侧给的**，会穿过写入器进到该行的错误信息里：

| 透传原文 | 处理 |
| --- | --- |
| `变量 [X] 未配置设备地址，无法写入` | 在变量管理里补地址 |
| `变量 [X] 未绑定通信管理器（连接可能已删除，请在变量管理中重新挂接）` | 重新挂连接 |
| `变量 [X] 缺少连接名，无法定位设备` | 补连接名 |
| `连接 [Y] 离线，变量 [X] 未写入设备` | 先让连接上线；离线时不会假装成功 |

## 五、编译期就被拦下的三类（不是运行期）

| 消息原文 | 为什么 | 处置 |
| --- | --- | --- |
| `[参数缺失] '{步骤名}' 的必填参数 'Name' 未配置！`（或 `'Value'`、`'CreateIfNotExists'`、`'Scope'`、`'Value_xxx'`） | 这些端口本应显式 `IsRequired = false`；被改回默认 `true` 就会出现"正常用法编不过"（必填判据只看有没有来源） | 别改这些 `IsRequired`；如果看到这条，先确认插件 DLL 是不是旧版（改了源码必须重建插件工程） |
| `[连线类型不匹配] … 的 'Name' 期望 String，但上游 '…' 提供的是 …` | 有人把**名字**这一行接成了"值由上游提供"的连线，而上游是图像/数组这类塞不进 `String` 的类型 | 名字行不许接通用绑定弹窗（见《名字与值口径》规则一）；在名字行动手编辑一次会自动解除旧连线 |
| `[并行写冲突] …`（编译器 `CollectAssignmentWrite`） | 同一并行分支里两个节点写同一个运行时/全局变量 | 把写同一变量的节点串到一个分支，或改成不同变量；同一节点多行写同一变量不会误报 |

## 六、三条现场排查链

**链一：给全局变量赋值，说"找不到全局变量"**

```
1 名字是不是选错了？看名字行下方提示——它会说"变量管理里没有「X」"
2 是不是同名但作用域选错了？提示会说「X」是运行时变量（类型），不在变量管理里
3 变量管理里真没有 → 建同名变量（运行期绝不自动建，勾了「自动创建」也没用）
```

**链二：值填了却报类型不匹配**

```
1 看消息括号里的「值 [原值]」——被拒的就是它
2 目标声明类型看提示行（如 Int32）：填 21 能过，21.5 / 1,500 / abc 都过不了
3 数组 / 枚举 / HImage 这类变量：文本压根解析不了，必须用「值」行行尾的链接图标连上游输出
```

**链三：什么都没动，画布上那根线却没了 / 或者敲了名字却不生效**

```
1 线没了：那是规则一的处置（你在名字行动过手，或点了确认——确认会统一解除旧 Name 连线）
2 敲了不生效：那一行还挂着旧连线，运行期"以连线为准"。在名字行选/输一次名字把它解除
3 只是打开看了一眼就点取消：连线应当保持原样——若被解除，那是回归（有断言钉着，见开发章节）
```

## 七、"这一步红了但界面上没有原因"

理论上不会发生（每条失败分支都写 `ErrorMessage` 且**都带 `return` 短路**——
历史上有一条没 return，直接落到下一行把 `ErrorMessage` 洗成空，引擎日志里就丢了失败原因）。
多行模式下真遇到空消息，按下面顺序看：

1. `ErrorMessage` 是否有 `N/M 行失败：…` 汇总（有就说明至少一行报了原因，按行号去界面定位）；
2. 流程日志里搜 `第 N 行「X」赋值失败：`（每行失败都有一条 Error）；
3. 搜 `{实例名} 变量赋值失败: {消息}`（兜底分支）或 `{实例名} {ErrorMessage}`（整节点汇总）；
4. 若一行都没执行（`Rows` 为空），会走旧版单值回退，消息是不带行号的老文案。

## 八、常见问题

**Q：变量明明建好了，为什么还是"本地变量 X 不存在"？**
A：作用域选错了。名字行下方的提示会点破这件事："`{名字}` 是全局变量（Int32），
不是上游声明的运行时变量 —— 要写它请把作用域改成「全局变量」。"
运行时变量通常由上游「变量定义」节点声明。

**Q：运行时变量的值能带到下一轮吗？**
A：不能，本轮跑完即弃。要跨轮/跨流程请用作用域=全局变量。

**Q：选中一个名字后切作用域，名字自己变空了？**
A：v3 已处理（重算候选前先记住值、重算后顶回去；作用域 setter 忽略空值）。若你用的是旧版插件 dll
且仍偶发清空：切作用域前先确认名字已填对，清空后运行会报 `变量名称不能为空`——重打即可。

**Q：两行写同一个变量会怎样？**
A：不会拦（同一节点内允许，按行顺序执行，后一行覆盖前一行）。但通常是误操作；
复制行会清空目标名就是为了避免这种"看起来复制了、其实双写"的情况。

**Q：删了一行，运行期还报那一行？**
A：确认删行时插件会 `RemoveDynamicInput` 并清掉该行的常量/链接键；如果用的是旧 DLL 或方案没保存，
旧 `Rows` 还在。删完点「确认」再跑；必要时重新打开配置窗口看一眼行数。

**Q：同一个全局变量被两个并行分支同时写？**
A：插件本身标了并行安全（运行时写走执行上下文的记账字典），但**同一个全局变量的两次写仍是竞态**，
结果取决于调度顺序。要累加就串到一个流程分支里，或用「数学计算」读改写成一串。
