# 变量赋值

> 分类：变量操作 ｜ 来源：插件 Plugin.Utility（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

把「值」写进一个**已经存在的变量**：作用域=运行时变量写本轮执行期的变量池，作用域=全局变量写
变量管理里那些随方案存盘的变量。六个工具里只有它有专属配置界面。

## 为什么需要它 / 原理

流程跑出来的结果默认只活在"某步骤的输出端口"上：连线到显示/上报就够，但**分支条件、循环计数、
跨步骤汇总、停机留档**需要有个地方落值。变量就是那个地方，而它有两套完全不同的语义：

| 作用域 | 写的是哪里 | 活多久 | 谁在读 |
| --- | --- | --- | --- |
| `Runtime`（界面显示"运行时变量"） | 本轮执行的变量池（`IExecutionContext.LocalVariables`） | **本轮跑完即弃** | 条件分支 If/While、循环计数、下游需要读变量的节点 |
| `Global`（"全局变量"） | 变量管理里注册的那个变量 | **跨流程、随方案存盘** | 组态画面、SCADA/PLC 上报、其它流程 |

写全局变量的三步守门在主程序侧（插件物理上够不到变量管理所在的程序集，通过执行上下文给出的
写入能力契约调用）：**① 按名查注册表 → ② 类型守门（唯一的放宽是"文本按声明类型解析一次"）→
③ 交给变量的可写契约真正落值**。顺序不能换，且**运行期绝不新建变量**——
变量是设计期资产，让插件在运行期悄悄改量表会让方案结构随运行结果漂移（跑一次多一个变量），
而组态画面绑的是设计期那批名字，问题极难复现。

为什么要有「作用域」选择而不是"先找运行时、再找全局"自动路由：同名时两者是**两个不同的东西**，
自动路由要么产生歧义、要么用户看不出写去了哪。显式选一次，语义就定死了。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Name` | 否（`IsRequired=false`） | 目标变量名称（`string`，默认空） |
| `Value` | 否 | 要赋的值（`object`，默认 `null`） |
| `CreateIfNotExists` | 否 | 变量不存在时是否自动创建（`bool`，默认 `false`，**仅作用域=Runtime 有效**） |
| `Scope` | 否 | 写到哪里：`Runtime`（默认）/ `Global`；界面用中文下拉，落盘是这两个英文串 |

四个端口**全部显式 `IsRequired = false`**。这条是本工程最硬的纪律：`InputPort.IsRequired` 默认是
`true`，而"必填"的判据看的是**有没有来源**（连线或面板里亲手填过常量）——
这几个参数天生就是给人手填的，留着默认值会让正常用法在流程编译时报
`[参数缺失] '<步骤名>' 的必填参数 'Name' 未配置！`。

`Scope` 之所以是 `string` 而不是枚举：枚举经 `InputValues` 存盘会序列化成 int，
读回来赋给端口时曾直接抛 `InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'`
（方案一打开就炸）。`string` 两端无损往返，取值再做白名单校验。

本插件实现了自定义配置视图（`IPluginCustomViewProvider`），所以你看到的**不是**通用「变量绑定」窗口，
而是三行表单 + 一个作用域下拉：

| 界面行 | 控件 | 说明 |
| --- | --- | --- |
| 作用域 | 下拉：运行时变量 / 全局变量 | 决定名字行的候选来自哪 |
| 变量名 | **可手填、可点右侧箭头选候选**的编辑框 | **这一行没有链接图标按钮**，且关掉"输入即补全"（见第 2 页） |
| （名字行下方小字） | 提示文本 | 随作用域与当前名字变化：命中候选时说清**声明类型**，没命中时说清**运行期会怎么报错** |
| 值 | 手填常量 + 行尾链接图标（要引用上游结果才点它） | 只有这一行的语义是"值" |
| 勾选框 | 变量不存在时自动创建（仅运行时变量） | 对应 `CreateIfNotExists` |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| （无） | 本节点不产出端口。它的"结果"落在变量上，下游用条件分支/其它节点的绑定去读那个变量 |

想"看得见写没写进去"，用流程日志（成功会写一行 `{实例名} 本地变量 X 已赋值` /
`{实例名} 全局变量 X 已赋值`）或组态画面/变量监视。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（端口名 / 界面标签） | 默认 | 说明 |
| --- | --- | --- |
| `Scope`（作用域） | `Runtime` | `Runtime`=运行时变量、`Global`=全局变量；其它取值运行期直接报错，不会被"当成 Runtime" |
| `Name`（变量名） | 空 | 要写入的变量**名字**。候选=按作用域过滤后的变量名（全局→变量管理，运行时→上游「变量定义」声明的） |
| `Value`（值） | `null` | 常量文本，或用行尾链接图标引用上游步骤的输出 |
| `CreateIfNotExists`（自动创建） | `false` | 只在作用域=Runtime 起作用；为 `true` 时变量不存在就按当前值的类型新建 |

## 口径与失败策略

**先记住一条大原则：赋不进去一律显式判失败并把原因写进错误信息，绝不静默。**

| 情形 | 结果与错误信息原文 |
| --- | --- |
| 名字空/全空白 | `变量名称不能为空` |
| 作用域串不认识 | `作用域取值无法识别：「{你填的}」（应为 Runtime 或 Global）` |
| 执行环境没有全局变量写入能力 | `当前执行环境不支持写全局变量` |
| 全局：注册表里没有这个名字 | `找不到全局变量「{名字}」，请先在变量管理里新建同名变量` |
| 全局：类型解析不了 | `全局变量「{名字}」的类型是 {声明类型}，无法写入 {值的类型}（值 [{原值}]）` |
| 全局：变量本身不可写 | `全局变量「{名字}」不支持写入（该变量类型未实现可写契约）` |
| 运行时：类型不符且转不动 | `变量 {名字} 类型为 {类型}，值 [{值}] 无法转换：{原因}` |
| 运行时：类型不符但能转 | **成功**，日志警告 `{实例名} 赋值 {名字}：值类型已按变量既有类型 {类型} 自动转换` |
| 运行时：变量不存在且没勾自动创建 | `本地变量 {名字} 不存在` |
| 运行时：变量不存在但勾了自动创建 | 成功，日志 `{实例名} 本地变量 {名字} 已创建并赋值` |

失败分支**都带 `return` 短路**——历史上有一条没 return，直接落到下一行把 `ErrorMessage` 洗成空，
引擎日志里就丢了失败原因。

其它口径：

- **`Value` 给 `null`（没连线也没填）时**：类型守门只针对非空值，`null` 会**原样下发**给变量自己处理
  （本地变量是内存赋 `null`，恒成功；网络变量要把 `null` 转成设备原始值，多半在这一步失败并给出原因）。
  运行时路径则把 `null` 写进变量池，会污染下游条件求值。两种作用域都不建议留空。
- **并行安全**：运行时写走的是执行上下文的记账字典；全局写靠配置界面（编辑器）把关。
  同一条并行链上多个实例写**同一个全局变量**仍然是竞态，别这么用。
- **不做类型自动"降级"**：`double` 值写进 `Int32` 全局变量仍按原样报错（那是上游接线错了），
  只有**文本**会被解析一次。细则见第 2 页。

## 典型用法 / 接线

```
Blob 分析.Area ──▶（画布连线到本步骤）
                    变量赋值.作用域 = 运行时变量
                    变量赋值.变量名 = ResultArea          ← 手填或从候选里选
                    变量赋值.值     = 用链接图标取 Blob 分析.Area
                    变量赋值.自动创建 = 勾上（第一次跑）

条件分支 If.条件  ◀── 读运行时变量 ResultArea
变量管理.OKCount  ◀── 变量赋值：作用域=全局变量，名字=OKCount，值=链接图标 Blob 数量
```

计数累计（本轮内）：作用域=运行时、名字=`Count`、勾「自动创建」，值用上游计数或
先读后加（需要加法就用「数学计算」把变量值加 1 再赋回去）。
跨流程留档：作用域=全局变量，名字必须已在变量管理里建好（`Int32` 类型就填 `21` 这种纯数字文本）。

## 常见问题

**Q：变量名那一行为什么没有链接图标链接按钮？**
A：那一行的语义是**名字**，不是值。通用绑定弹窗只会落一条"值由对方提供"的连线，
后果是运行期**拿值当名字**——"给 OKCount 赋值"变成"给一个叫 0 的变量赋值"。
名字的正解是手填或从候选下拉选。详见第 2 页。

**Q：给全局变量填 21，为什么写不进去？**
A：先看错误信息里有没有"类型是 Int32，无法写入 String"。界面只能产出文本，
21 会按变量声明类型解析一次（`Int32`→整数）；如果那个变量声明的是数组/枚举/HImage，
文本解析不了就按原样报错——那种值必须靠链接图标连上游输出。

**Q：填 `1,500` 想表达 1500，结果报类型不匹配？**
A：数值文本**拒绝千分位分隔符**（默认解析会把 `2,5` 读成 `25`，属于"该报错却改了值"）。
重打成 `1500`。

**Q：选中一个名字后切作用域，名字自己变空了？**
A：这是插件已经处理的行为（重算候选时先记住值、重算后顶回去）。
若你用的是旧版插件 dll 且仍偶发清空：切作用域前先确认名字已填对，清空后运行会报
`变量名称不能为空`——重打即可。恢复细节见第 2 页。

**Q：勾了「自动创建」但全局变量还是报找不到？**
A：自动创建**只对运行时变量生效**。全局变量必须先在变量管理里建好，运行期绝不新建。

**Q：变量明明建好了，为什么还是"本地变量 X 不存在"？**
A：作用域选错了。名字行下方的提示会点破这件事："`{名字}` 是全局变量（Int32），
不是上游声明的运行时变量 —— 要写它请把作用域改成「全局变量」。"
运行时变量通常由上游「变量定义」节点声明。

**Q：这一步红了，但界面上没有原因？**
A：错误信息理论上都有（见上表）。若确为空，看流程日志里同实例名的 Error 行——
`{实例名} 变量赋值失败: {消息}` 是兜底分支写的。

**Q：运行一次之后运行时变量的值还在，能带到下一轮吗？**
A：不能。运行时变量本轮跑完即弃；要跨轮/跨流程请用作用域=全局变量。
