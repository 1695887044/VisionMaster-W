# 变量赋值

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

把「值」写进一个**已经存在的变量**：作用域=运行时变量写本轮执行期的变量池，作用域=全局变量写
变量管理里那些随方案存盘的变量。工具箱里的实名是「**变量赋值**」，分组「变量操作」；
六个工具插件里只有它有专属配置界面。

## 一、为什么需要它

流程跑出来的结果默认只活在"某步骤的输出端口"上：连线到显示/上报就够，但**分支条件、循环计数、
跨步骤汇总、停机留档**需要有个地方落值。变量就是那个地方，而它有两套完全不同的语义：

| 作用域 | 写的是哪里 | 活多久 | 谁在读 |
| --- | --- | --- | --- |
| `Runtime`（界面显示"运行时变量"） | 本轮执行的变量池 | **本轮跑完即弃** | 条件分支 If/While、循环计数、下游需要读变量的节点 |
| `Global`（界面显示"全局变量"） | 变量管理里注册的那个变量 | **跨流程、随方案存盘** | 组态画面、SCADA/PLC 上报、其它流程 |

为什么要有「作用域」选择，而不是"先找运行时、再找全局"自动路由：**同名时两者是两个不同的东西**，
自动路由要么产生歧义、要么用户根本看不出写去了哪。显式选一次，语义就定死了。

## 二、第一次赋值（照做即可）

```
1 选作用域        运行时变量 / 全局变量          ← 先定这个，候选列表才准
2 定名字          手填，或点右侧箭头从候选里选    ← 这一行没有链接图标，别去找绑定弹窗
3 看那行小字      "写入全局变量「OKCount」（Int32）——「值」按它的类型解析（如 Int32 填 21）"
4 填值            常量直接敲（纯数字，不带逗号）；要上游结果就点值行行尾的链接图标
5 自动创建        只在作用域=运行时变量时有意义
```

跑通后应该看到：本步骤变绿，流程日志里一行
`{实例名} 本地变量 X 已赋值`（运行时）或 `{实例名} 全局变量 X 已赋值`（全局）；
作用域=运行时且变量原本不存在时是 `… 已创建并赋值`。这个节点**不产出端口**，
想"看得见写没写进去"就靠日志、变量监视或组态画面。

## 三、配置界面（五行，一眼看完）

| 界面行 | 控件 | 要点 |
| --- | --- | --- |
| 作用域 | 下拉：运行时变量 / 全局变量 | 决定名字行的候选来自哪、写进哪个池 |
| 变量名 | **可手填、可点右侧箭头选候选**的编辑框 | **这一行没有链接图标按钮**，且关掉了"输入即补全"（原因见《名字与值口径》页） |
| （名字行下方小字） | 提示文本 | 随作用域与当前名字变化：命中候选时说清**声明类型**，没命中时说清**运行期会怎么报错** |
| 值 | 手填常量 + 行尾链接图标 | 只有这一行的语义是"值"，所以要引用上游结果就点它 |
| 勾选框 | 变量不存在时自动创建（仅运行时变量） | 对应 `CreateIfNotExists` |

## 四、典型接线

```
Blob 分析.Area ──▶（画布连线到本步骤的「值」行）
                    变量赋值.作用域 = 运行时变量
                    变量赋值.变量名 = ResultArea          ← 手填或从候选里选
                    变量赋值.值     = 用链接图标取 Blob 分析.Area
                    变量赋值.自动创建 = 勾上（第一次跑）

条件分支 If.条件  ◀── 读运行时变量 ResultArea
变量管理.OKCount  ◀── 变量赋值：作用域=全局变量，名字=OKCount，值=链接图标 Blob 数量
```

- **本轮内计数累计**：作用域=运行时、名字=`Count`、勾「自动创建」，值用上游计数，
  或先读后加（需要加法就用「数学计算」把变量值加 1 再赋回来）。
- **跨流程留档**：作用域=全局变量，名字必须已在变量管理里建好（`Int32` 类型就填 `21` 这种纯数字文本）。

## 五、写全局变量时的三步守门（发生在主程序侧）

插件物理上够不到"变量管理"所在的程序集，所以走执行上下文给出的写入能力契约，顺序不能换：

```
① 按名查注册表   →  ② 类型守门（唯一的放宽：文本按声明类型解析一次）  →  ③ 交给变量的可写契约真正落值
```

**运行期绝不新建变量**（作用域=全局）：让插件在运行期悄悄改量表会让方案结构随运行结果漂移
（跑一次多一个变量），而组态画面绑的是设计期那批名字，问题极难复现。
所以勾了「自动创建」也只对运行时变量有效。

## 六、一条大原则

**赋不进去一律显式判失败并把原因写进错误信息，绝不静默。** 全部消息原文见《排障》页；
"名字"与"值"这两行各自要什么、按什么口径解析，见《名字与值口径》页——那三条都是真机上踩过并已在代码里定死的规则。

## 七、边界速览

| 你会问 | 实际 |
| --- | --- |
| 这个节点有输出端口吗 | 没有。结果落在变量上，下游用条件分支/其它节点的绑定去读那个变量 |
| 能新建变量吗 | 运行时变量能（勾「自动创建」）；**全局变量不能**，必须先在变量管理里建好 |
| 值能填数组/图像吗 | 填文本填不进去（必然报类型不匹配）——这种值只能用行尾链接图标引用上游输出端口 |
| 运行时变量的值能带到下一轮吗 | 不能，本轮跑完即弃；要跨轮/跨流程用作用域=全局变量 |
| 能并行吗 | 插件标了并行安全（运行时写走执行上下文的记账字典）。但同一条并行链上多个实例写**同一个全局变量**仍是竞态，别这么用 |
