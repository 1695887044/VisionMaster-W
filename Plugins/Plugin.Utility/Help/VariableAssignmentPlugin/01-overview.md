# 变量赋值

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

一个节点可以写**多个变量**：每行一个作用域、一个变量名、一个值；**行顺序就是执行顺序**。
旧版单条配置第一次打开时自动迁移成第 1 行，旧「值」连线保留。工具箱里的实名是「**变量赋值**」，
分组「变量操作」；六个工具插件里只有它有专属配置界面。

## 一、为什么需要它

流程跑出来的结果默认只活在"某步骤的输出端口"上：连线到显示/上报就够，但**分支条件、循环计数、
跨步骤汇总、停机留档**需要有个地方落值。变量就是那个地方，而它有两套完全不同的语义：

| 作用域 | 写的是哪里 | 活多久 | 谁在读 |
| --- | --- | --- | --- |
| `Runtime`（界面显示"运行时变量"） | 本轮执行的变量池 | **本轮跑完即弃** | 条件分支 If/While、循环计数、下游需要读变量的节点 |
| `Global`（界面显示"全局变量"） | 变量管理里注册的那个变量 | **跨流程、随方案存盘** | 组态画面、SCADA/PLC 上报、其它流程 |

为什么每行都要选一次作用域，而不是"先找运行时、再找全局"自动路由：**同名时两者是两个不同的东西**，
自动路由要么产生歧义、要么用户根本看不出写去了哪。显式选一次，语义就定死了。

## 二、第一次赋值（照做即可）

```
1 添加一行        「+ 添加一行」；需要几个变量就加几行（上限 32 行）
2 选作用域        每行独立：运行时变量 / 全局变量
3 定名字          全局：只能从变量管理里选（可搜索）
                  运行时：候选来自上游「变量定义」，也可以手填
4 看那行小字      命中候选会说清声明类型；没命中说清运行期会怎么失败
5 填值            常量直接敲（纯数字，不带逗号）；要上游结果就点值行行尾的链接图标
6 自动创建        只在作用域=运行时变量时有意义
```

跑通后应该看到：本步骤变绿，流程日志里**每行一条**：
`{实例名} 第 1 行：本地变量 X 已赋值`（运行时）或 `{实例名} 第 2 行：全局变量 Y 已赋值`（全局）；
作用域=运行时且变量原本不存在时是 `… 已创建并赋值`。这个节点**不产出业务端口**，
想"看得见写没写进去"就靠日志、变量监视或组态画面。

## 三、配置界面（行列表 + 右侧详情）

宽档（约 960×680）是"左边行列表、右边当前行详情 + 作用域规则"；窗口宽度小于 700 时行模板自动切成
**两行式**（作用域 + 名字 + 操作在第一行，值 + 自动创建在第二行），不是把两栏堆叠。

| 位置 | 控件 | 要点 |
| --- | --- | --- |
| 顶部 | 「+ 添加一行」+ 行数胶囊 | 到 32 行后添加/复制禁用，底部显示「已满 32 行」 |
| 行列表 | 每行一套：作用域 / 变量名 / 值 / 自动创建 / 操作 | 点行选中；错误行红边、警告行琥珀边；行内展开一句说明 |
| 作用域 | 下拉：运行 / 全局 | 每行独立；切到全局会自动取消该行的「自动创建」 |
| 变量名（全局） | 「选择全局变量」按钮 + 搜索浮层 | **只能选，不能手填**；失效项只读保留，不自动替换/清空 |
| 变量名（运行时） | 可编辑下拉（候选 + 手填） | 候选来自上游「变量定义」；手填给「手填」徽标；关掉"输入即补全" |
| 值 | `LinkableValueEditor`（常量 + 行尾链接图标） | **只有这一行允许连线**；变量引用必须用链接，不提供手输变量名 |
| 自动创建 | 运行时=勾选框；全局=锁图标 | 全局变量必须先在变量管理里存在 |
| 操作 | 上移 / 下移 / 复制 / 删除 | 复制会**清空目标名**（避免两行写同一变量）；删除有值链接的行会先确认 |
| 右栏 | 当前行卡 + 作用域规则卡 | 第 N 行 / 共 M 行、作用域徽标、声明类型、候选数、值来源、行内提示 |
| 错误横幅 | 「有 N 行配置有问题」+ 定位 | 点「定位」跳到第一条错误行；**不阻断确认**（运行期会明确失败） |

## 四、典型接线

```
Blob 分析.Area ──▶（画布连线到本步骤第 1 行的「值」）
                    第 1 行：作用域=运行时变量，名字=ResultArea，值=链接图标取 Blob 分析.Area
                    第 2 行：作用域=全局变量，名字=OKCount，值=链接图标取 Blob 数量

条件分支 If.条件  ◀── 读运行时变量 ResultArea
变量管理.OKCount  ◀── 第 2 行写入（名字只能从变量管理里选）
```

- **本轮内多个结果**：一行一个变量，行顺序即执行顺序；某行失败不阻断后续行，最后整节点报失败。
- **跨流程留档**：作用域=全局变量，名字必须已在变量管理里建好（`Int32` 类型就填 `21` 这种纯数字文本，
  或者用链接取上游数值）。
- **旧方案迁移**：旧版只有一个 `Name/Value/Scope/CreateIfNotExists` 的配置，打开窗口时会变成第 1 行，
  旧「值」连线保留；旧「名字」连线只用于提示，确认时解除（名字类端口不该挂连线）。

## 五、写全局变量时的三步守门（发生在主程序侧）

插件物理上够不到"变量管理"所在的程序集，所以走执行上下文给出的写入能力契约，顺序不能换：

```
① 按名查注册表   →  ② 类型守门（唯一的放宽：文本按声明类型解析一次）  →  ③ 交给变量的可写契约真正落值
```

**运行期绝不新建全局变量**：让插件在运行期悄悄改量表会让方案结构随运行结果漂移
（跑一次多一个变量），而组态画面绑的是设计期那批名字，问题极难复现。
所以勾了「自动创建」也只对运行时变量有效；全局行的「自动创建」是锁图标。

## 六、一条大原则

**赋不进去一律显式判失败并把原因写进错误信息，绝不静默。** 多行模式下：

- 每行独立执行，失败行不阻断后续行；
- 只要有一行失败，整节点 `Success=false`，`ErrorMessage` 形如
  `2/3 行失败：第1行「A」…；第3行「B」…`（最多列前 3 条，其余写「等 N 行」）；
- 每行另有一条 Error 日志：`{实例名} 第 N 行「X」赋值失败：…`；
- 界面上每行都有提示，错误行可以点顶部「定位」跳过去。

全部消息原文见《排障》页；"名字"与"值"这两行各自要什么、按什么口径解析，见《名字与值口径》页。

## 七、边界速览

| 你会问 | 实际 |
| --- | --- |
| 这个节点有输出端口吗 | 没有业务输出端口。结果落在变量上，下游用条件分支/其它节点的绑定去读那个变量 |
| 能写几个变量 | 每行一个，最多 32 行；行顺序即执行顺序 |
| 能新建变量吗 | 运行时变量能（勾「自动创建」）；**全局变量不能**，必须先在变量管理里建好 |
| 值能填数组/图像吗 | 填文本填不进去（必然报类型不匹配）——这种值只能用行尾链接图标引用上游输出端口 |
| 运行时变量的值能带到下一轮吗 | 不能，本轮跑完即弃；要跨轮/跨流程用作用域=全局变量 |
| 能并行吗 | 插件标了并行安全（运行时写走执行上下文的记账字典）。但同一条并行链上多个实例写**同一个全局变量**仍是竞态，别这么用 |
| 旧方案会坏吗 | 旧四键与旧「值」连线保留；旧「名字」连线在确认时解除并提示；旧配置自动变成第 1 行 |
