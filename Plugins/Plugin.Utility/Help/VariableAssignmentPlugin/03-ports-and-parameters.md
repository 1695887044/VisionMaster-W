# 变量赋值 · 端口与参数

> 分类：变量操作 ｜ 来源：插件 Plugin.Util（工程 `Plugin.Util.csproj`，C# 类 `VariableAssignmentPlugin`）

这页逐条列**端口**与**界面控件**：类型、默认值、必填性、接不上会怎样，以及存盘键。
名字与默认值都照插件源码抄。

## 一、输入端口（四个）

| 端口（源码属性名） | 端口名（存盘键） | 界面行 | 类型 | 默认 | 必填 | 接不上/不填会怎样 |
| --- | --- | --- | --- | --- | --- | --- |
| `VariableName` | `Name` | 变量名 | `InputPort<string>` | `""`（空） | 否（显式 `IsRequired = false`） | 运行期报 `变量名称不能为空`（全空白同样算空） |
| `Value` | `Value` | 值 | `InputPort<object>` | `null` | 否 | `null` 会**原样下发**给变量自己处理（见第四节） |
| `CreateIfNotExists` | `CreateIfNotExists` | 变量不存在时自动创建（仅运行时变量） | `InputPort<bool>` | `false` | 否 | 只影响作用域=运行时；不勾时变量不存在就显式失败 |
| `Scope` | `Scope` | 作用域 | `InputPort<string>` | `Runtime` | 否 | 认不出来的取值直接报错，**不会被"当成 Runtime"** |

### 四条端口纪律（都是踩过之后定死的）

1. **四个口全部显式 `IsRequired = false`**。`InputPort.IsRequired` 默认是 `true`，而编译期的必填判据只看
   "有没有来源"（连线，或面板里亲手填过常量）——这几个参数天生就是给人手填的，留着默认值会让正常用法
   在流程编译时报 `[参数缺失] '步骤名' 的必填参数 'Name' 未配置！`，这个节点等于用不了。
2. **`Scope` 是 `string` 而不是枚举**。枚举经 `InputValues` 存盘会序列化成 int，读回来赋给端口时
   曾直接抛 `InvalidCastException: Invalid cast from 'System.Int32' to '枚举类型'`（方案一打开就炸）。
   `string` 两端无损往返，取值再做白名单校验（只认 `Runtime` / `Global`，忽略大小写）。
3. **为什么不自动路由**：同名时"运行时变量"与"全局变量"是两个不同的东西，自动路由要么产生歧义、
   要么用户看不出写去了哪。显式选一次，语义就定死。
4. **`Success` / `ErrorMessage` 复用基类端口，本类不自声明同名属性**。曾经自声明过，结果"影子隐藏"基类成员：
   插件写派生端口、引擎读基类端口，于是**永远报失败且错误日志为空**（CS0108 教训）。

## 二、输出端口

| 端口 | 说明 |
| --- | --- |
| （无） | 本节点不产出端口。它的"结果"落在变量上，下游用条件分支/其它节点的绑定去读那个变量 |
| `Success` / `ErrorMessage` | 基类契约端口。赋不进去时 `Success=false` + 中文原因；**没有"失败不阻断"开关**——这个节点的失败是真失败 |

想"看得见写没写进去"：看流程日志（`{实例名} 本地变量 X 已赋值` / `{实例名} 全局变量 X 已赋值`）、
变量监视或组态画面。

## 三、配置界面的控件与它们绑的端口

| 界面行 | 控件（源码） | 绑定 | 行为要点 |
| --- | --- | --- | --- |
| 顶部说明 | 两行文本 | 写死在视图里 | "给一个运行时变量赋值" + 一句作用域科普（运行时本轮即弃 / 全局可跨流程随方案存盘） |
| 作用域 | 两张 `RadioButton` 卡片（运行时变量 / 全局变量） | `IsChecked` ←→ `Scope.Value`，经 `ScopeEqualsConverter` 写回字符串 | 选中态 = 主色描边 + 浅底 + 对勾；改它触发候选与提示重算。取值不在 Runtime/Global 白名单时两张卡片都不选中，提示会写「作用域取值无法识别」 |
| 变量名 | 可编辑 `ComboBox`（候选 + 手填） | `Text` ←→ `VariableName.Value`（`UpdateSourceTrigger=PropertyChanged`），`ItemsSource` ←→ `NameCandidates`；候选行经 `NameCandidateItems` 显示「名字 + 声明类型」 | `IsTextSearchEnabled="False"`（关掉"输入即补全"，否则刚敲 `OK` 被补成 `OKCount`）；**没有链接图标**；选择落下的仍是名字常量 |
| （名字行下方小字） | `TextBlock` | ←→ `NameHint` | 随作用域与当前名字变化，四类文案见第五节 |
| 值 | `LinkableValueEditor`（宿主通用控件） | `Port` ←→ `Value`，`StepData` ←→ `StepData` | 手填常量 + 行尾链接图标二合一；**只有这一行允许连线** |
| 变量不存在时自动创建 | `CheckBox` | ←→ `CreateIfNotExists.Value` | 布尔用勾选框比在文本框里敲 `true` 直观 |

界面底部还有一段固定说明文字，把"名字行怎么选、值按类型解析、全局变量必须先在变量管理里建好"三件事
重申了一遍——现场不看手册时读的就是那段。

## 四、默认值与取值范围

| 项 | 默认 | 取值范围 | 改了影响什么 |
| --- | --- | --- | --- |
| `Scope` | `Runtime` | `Runtime` / `Global`（字符串，忽略大小写） | 决定写哪个池、候选来自哪、失败消息长什么样 |
| `Name` | 空 | 任意非空变量名 | 目标变量；候选按作用域过滤（全局→变量管理，运行时→上游「变量定义」声明的） |
| `Value` | `null` | 常量文本，或连线取上游输出 | 类型要和目标变量的**声明类型**对得上（文本会被解析一次，类型化的值不会） |
| `CreateIfNotExists` | `false` | `true` / `false` | 仅作用域=Runtime 起作用；为 `true` 且变量不存在时**按当前值的类型新建** |

`Value` 给 `null`（没连线也没填）时：类型守门只针对非空值，`null` 会**原样下发**——
本地变量是内存赋 `null`、恒成功（但会污染下游条件求值）；网络变量要把 `null` 转成设备原始值，
多半在这一步失败并给出原因。两种作用域都不建议留空。

## 五、名字行下方的提示（四类文案原文）

提示不是装饰：这条链上失败的两种方式（名字打错、值类型不符）在界面上都看不出原因，
所以把**声明类型**与**会怎么失败**当场说出来。

| 情形 | 文案原文（`{}` 里是实际值） |
| --- | --- |
| 还没填名字（全局） | `还没填名字。作用域=全局变量时，名字要来自变量管理（点右侧箭头选）。` |
| 还没填名字（运行时） | `还没填名字。作用域=运行时变量时，名字通常来自上游「变量定义」节点。` |
| 命中候选（全局） | `写入全局变量「{名字}」（{声明类型}）——「值」按它的类型解析（如 Int32 填 21）。` |
| 命中候选（运行时） | `写入运行时变量「{名字}」（{声明类型}）· {说明}。` |
| 同名但在另一个作用域 | `「{名字}」是运行时变量（{类型}），不在变量管理里 —— 要写它请把作用域改成「运行时变量」。`（反向同理） |
| 候选里找不到（全局） | `变量管理里没有「{名字}」：运行期会明确报「找不到全局变量」，不会静默新建。` |
| 候选里找不到（运行时） | `「{名字}」不在上游的变量定义里：需要它运行时已存在，或勾上「不存在时自动创建」。` |
| 这一行有旧连线（老方案） | `该行原由上游提供（{上游地址}）—— 在本行选/输一个变量名，即可改为手填。` |

最后一行**会拼在其它文案前面**：先说旧连线这件事，再说当前名字的状态。

## 六、存盘键与并行

- `.vms` 里的键 = **端口名**：`Name` / `Value` / `CreateIfNotExists` / `Scope`。
  改端口名 = 老方案这几项静默回落默认值（用户只看到"配置怎么自己变了"）。
- 有连线的端口在确认时**移除固定值键**（运行时以连线为准），不会留下脏数据。
- 本插件标注了并行安全：运行时写走执行上下文的记账字典，全局写由配置界面把关。
  但**同一条并行链上多个实例写同一个全局变量**仍然是竞态，流程侧不该这么写。
- 同程序集里另外四个工具插件（数学计算 / 数值比较 / 逻辑运算 / 类型转换）的运算枚举**成员目前没有标
  `[Display(Name=…)]`**，界面下拉是英文成员名（`Add` / `Equal` / `And` / `Int32` …）。
  本节点的「作用域」下拉不受影响——它的两项中文是写死在视图里的。
