# 变量赋值 · 名字与值

> 分类：变量操作 ｜ 来源：插件 Plugin.Utility（C# 类 `VariableAssignmentPlugin`）

这一页把界面上最容易踩的三件事一次讲清：**「变量名」那一行怎么用**、
**「值」按什么口径解析**、**切作用域时名字为什么有时会被清掉**。
三条都是真机上踩过并已在代码里定死的规则，不是推测。

## 规则一：「变量名」要的是名字，不是值

**这一行只能手填，或点右侧箭头从候选里选。不要、也没有通用的「变量绑定」弹窗入口。**

为什么：端口的语义决定了它能挂什么控件。语义是**值**的（要接上游结果）才配绑定弹窗 /
行尾链接图标；语义是**名字**的（变量名、步骤名、卡地址、端口名）挂绑定弹窗只会落一条
"该端口的值由对方提供"的连线。在弹窗里选中全局变量 `OKCount`，落下来的不是"名字 = OKCount"，
而是一条运行期把 `OKCount` 的**当前值**喂进这个名字端口的连线。后果两种，都很难看：

| 后果 | 现场表现 |
| --- | --- |
| 编译期类型不匹配 | 上游给的值类型和端口声明的 `String` 不符，编译报 `[连线类型不匹配] … 的 'Name' 期望 String，但上游 '…' 提供的是 …` |
| 运行期**拿值当名字** | 变量恰好是数值型 → 名字变成 `"0"`，于是"给 OKCount 赋值"变成了"给一个叫 0 的变量赋值"：步骤可能照常绿，值却写去了别处（静默故障） |

候选下拉给的是**名字**，选中后落成**常量**，语义就对了：

| 作用域 | 候选来自 |
| --- | --- |
| 全局变量 | 变量管理里那些变量名（宿主按作用域过滤后透传给插件） |
| 运行时变量 | 上游「变量定义」节点声明的变量名 |

**老方案里已经挂过这种连线的怎么办**：打开配置窗口时，名字行下方会显示
`该行原由上游提供（{上游地址}）—— 在本行选/输一个变量名，即可改为手填。`
你在这行**真的动手**（键入、删字符、从下拉里选）时，插件才把那条旧连线解除；
只是打开看一眼、点取消，连线不会被碰。这条纪律已被回归断言钉住
（`FlowCanvasChecks\VariableAssignmentCheck.cs` 的 `[A4]`，含"名字行不许再接回通用绑定弹窗"的静态扫描）。

另外这一行关掉了"输入即补全"（`IsTextSearchEnabled=False`）：
否则你刚敲 `OK`，控件会把它补成候选里的 `OKCount` —— 正是这一类"静默写错变量"要消灭的对象。
候选照常从下拉里选。

## 规则二：手填的「值」是文本，按目标类型解析一次

界面上的值框**只能产出文本**（端口是 `object`，JSON 快照也是文本），所以"给 `Int32` 变量填 `21`"
必须有写入侧的一次解析，否则这类最普通的用法永远不可能成功。口径是**宽进严出**：

| 给进去的东西 | 怎么处理 |
| --- | --- |
| **文本**（手填的常量） | 按目标变量的声明类型解析一次；能解析就写，解析不了明确报错，**错误消息里带上被拒的原值** |
| **类型化的值**（链接图标 连上游给的 `double` / `HImage` …） | 仍按原样报类型不匹配。那是上游接线错了，静默截断/转换只会把错因推到很远的地方 |

数值文本另外两条硬口径：

- **不变区域性（InvariantCulture）**：显式写死，换机器/换区域设置时同一个方案解析出同一个数。
- **拒绝千分位分隔符**：默认解析会把 `2,5` 读成 `25`。这是"应当报错却改了值"，宁可拒收，
  让你把 `1,500` 重打成 `1500`。所以带逗号的数字一律失败，**不会被当成 1500**。

运行时变量那条路（作用域=Runtime）保持同一口径：值类型与池里既有类型不一致时**能转就转**
（会写一条警告日志"值类型已按变量既有类型 X 自动转换"），转不了就显式失败。

**数组 / 枚举 / HImage 这类声明类型的变量，填文本是解析不了的**（必然报"无法写入 String"）——
这种值只能用行尾链接图标引用上游输出端口。

## 规则三：切作用域时名字被清空——原因与恢复

现象：选中/输入一个名字，把作用域从"运行时变量"切到"全局变量"（或反向），
名字行**自己变空**；点确定后落盘成空名，运行时报 `变量名称不能为空`。

原因（WPF 实测行为）：候选列表按作用域整批重算，重算要 `Clear()` 再填；
而可编辑 `ComboBox` 在**当前有选中项**时清空 `ItemsSource`，会连带把 `Text` 置空，
并沿 TwoWay 绑定把空串**推回端口**。端口才是这一行的真值来源。

现在的实现已经处理：重算候选**前先记住端口里的名字，重算后顶回去**，
并且"用户编辑"只由真实输入事件判定（键入/删字符/下拉选择），
程序灌值（试运行桥接、候选回填、配置加载）不会被误当成用户动作。

如果你仍遇到清空（例如用的是旧版插件 dll）：

1. 重新在名字行填/选一次名字，**先别急着点确定**；
2. 检查行下方提示是否显示"写入全局变量「X」（类型）"——显示出来了说明值确实写进了端口；
3. 想要彻底避免：先定作用域，再定名字（切一次作用域就把名字重打一遍）。

## 报错原文对照（作用域=全局变量）

按守门顺序，先命中谁就是谁：

| 报错原文 | 含义 | 处理 |
| --- | --- | --- |
| `目标全局变量名不能为空` | 名字被清成空串（或全是空格） | 见规则三，重填名字 |
| `当前执行环境没有绑定工作区，无法写入全局变量` | 在脱离工作区的执行环境里跑（容器/独立调用） | 只能在完整流程里写全局变量 |
| `找不到全局变量「X」，请先在变量管理里新建同名变量` | 名字写对了但量表里没这个变量；**运行期不会自动建** | 去变量管理建同名变量，或改回已有名字 |
| `全局变量「X」的类型是 Int32，无法写入 String（值 [abc]）` | 文本解析不出该类型（原值已写在括号里） | 按类型填正确的文本，或用链接图标连上游 |
| `全局变量「X」不支持写入（该变量类型未实现可写契约）` | 该变量源不接受显式写 | 换个变量或改流程设计 |
| `全局变量「X」写入失败` | 变量侧写失败但没给具体原因 | 看日志同实例名的 Error 行 |

**网络变量（PLC/SCADA 那批）的失败原因是设备侧给的，会原样透传到本步骤的错误信息**：

| 透传原文 | 处理 |
| --- | --- |
| `变量 [X] 未配置设备地址，无法写入` | 在变量管理里补地址 |
| `变量 [X] 未绑定通信管理器（连接可能已删除，请在变量管理中重新挂接）` | 重新挂连接 |
| `变量 [X] 缺少连接名，无法定位设备` | 补连接名 |
| `连接 [Y] 离线，变量 [X] 未写入设备` | 先让连接上线；离线时不会假装成功 |

## 操作顺序（照做即可）

```
1 选作用域        运行时变量 / 全局变量          ← 先定这个，候选列表才准
2 定名字          手填，或点右侧箭头从候选里选    ← 这一行没有链接图标，别去找绑定弹窗
3 看那行小字      "写入全局变量「OKCount」（Int32）——「值」按它的类型解析（如 Int32 填 21）"
4 填值            常量直接敲（纯数字，不带逗号）；要上游结果就点值行行尾的链接图标
5 自动创建        只在作用域=运行时变量时有意义
```

## 常见问题

**Q：名字行的提示说"变量管理里没有「X」：运行期会明确报「找不到全局变量」，不会静默新建"，
是错误吗？**
A：不是错误，是提前告诉你会怎么失败。要么改名，要么先去变量管理建。

**Q：提示说"`{名字}` 是运行时变量（Double），不在变量管理里 —— 要写它请把作用域改成「运行时变量」"？**
A：同名但作用域选错。这正是"必须有作用域下拉"的原因：两个池子里的同名变量是两个东西。

**Q：为什么"给 Int32 变量填 `21`"能成，但"填 `21.5`"失败？**
A：`21` 能解析成 `Int32`；`21.5` 按 `Int32` 解析会抛，且只放宽文本一次，不会帮你四舍五入。
先想清楚目标变量的声明类型（提示行里就写着）。

**Q：勾了「自动创建」，全局变量还是报找不到？**
A：自动创建只对运行时变量有效。全局量表是设计期资产，运行期只写不增。

**Q：`1,500` 到底会写成什么？**
A：**什么都写不进去**——千分位被拒，直接报类型不匹配（原值会出现在错误消息里）。
这是有意为之，好过把 `2,5` 静默变成 `25`。

**Q：我在这行敲了字，画布上原来那根线怎么没了？**
A：那是规则一的处置：那条线是"值当名字"的旧连线，你动手编辑名字就解除它。
如果不想解除，就别改这一行（只打开看一眼、点取消，线会留着）。

**Q：试运行和正式运行表现不一样？**
A：留意试运行会把上游实际值灌进配置实例的端口。插件已经区分"程序灌值"与"用户编辑"，
所以试运行不会误解除你什么都没动的旧连线；但你在试运行里改的名字可能与保存的方案不同，
确认后要回配置窗口重填一次。
