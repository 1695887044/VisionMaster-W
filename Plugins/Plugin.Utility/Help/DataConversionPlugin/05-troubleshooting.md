# 类型转换 · 排障

> 分类：数据处理 ｜ 来源：插件 Plugin.Utility

按"看到什么现象"查。文案原文逐字取自 `DataConversionPlugin.cs` 与编译器（`FlowCompiler`），
括号里标级别。本插件的错误分两类：**日志里有话、界面不一定有话**——它的失败路径
只写 `Success=false`，没写错误信息文本。

## 一、编译/启动前就被拦的

| 现象原文 | 为什么 | 怎么改 |
| --- | --- | --- |
| `[参数缺失] '步骤名' 的必填参数 'Input' 未配置！` | 三个输入都是必填（基类默认），而 `Input` 的默认值是 `null`——判据要求存盘字典里这个键的值非空 | 连上游，或在「输入值」框里填一个常量并确认 |
| 同上，参数名是 `Target` 或 `Format` | 同一判据换了端口 | 打开一次参数面板确认即可（这两行都有非空默认值） |
| 节点亮黄色叹号角标，悬停 `必填参数未配置（编译会报参数缺失）：` + `· Input` | 上面那条编译判据的画布投影 | 同上 |
| `[连线类型不匹配] '步骤名' 的输入端口 'Target' 期望 TargetDataType，但上游 '…' 提供的是 Int32。请在变量绑定处改选类型兼容的输出，或调整上游算子的输出类型。` | 枚举目标只接受字符串名或 object 来源，**数值 → 枚举编译期不放行** | 在面板下拉里直接选；确实要上游决定，改连**成员名字符串** |
| `[并行不安全] 分支内步骤 '…'（算子 DataConversionPlugin）未声明 [ParallelSafe]，…` | 本插件已标；出现这条说明 `Modules\` 下是旧 DLL | 重建插件工程 |

报错里的类型名走 `Type.Name`（`Double` / `Boolean` / `Int32` / `TargetDataType` 这种 CLR 写法，不是 C# 关键字）。
枚举端口显示的是**枚举类型名**、不是某个成员名——别把 `TargetDataType` 读成"这个端口要的是数值"，它要的是成员。

## 二、跑通了、但结果不是想要的

**现象：`Result` 是 `null`，步骤是红的。**
转换失败。日志里那行是 `{实例名} 类型转换失败: {异常消息}`（Error）。
**步骤上的错误信息很可能是空的**（本插件的 catch 只写日志 + `Success=false`，
不调用语义化的失败方法），所以只能看日志，别在界面上猜。
常见原因按目标类型分：

| `Target` | 典型失败原因 |
| --- | --- |
| `Int32` | 文本里有非数字字符、千分位、区域小数点；或上游给的是图像/区域这类根本转不了数的对象 |
| `Double` | 文本小数点符号与**当前区域设置**不一致（`12,3` 在用 `.` 的机器上失败） |
| `Boolean` | 文本不是 `true`/`false`（`1`/`0`/`是`/`OK` 都会抛） |
| `String` | 基本不会失败（`ToString()`） |
| `DateTime` | `Format` 与文本没逐字符对上 |

**现象：`2.5` 转成 `Int32` 得 2。**
`Convert.ToInt32` 对浮点用**银行家舍入**（`3.5 → 4`）。这是 CLR 语义，不是这个节点的开关。
要"半进位"就先在「数学计算」里加 0.5 再 `Floor`。

**现象：`12,3` 转 `Double` 失败，换台机器又好了。**
区域设置问题。`Convert.ToDouble` 用当前区域的小数点符号。
跨机器部署时这是最常见的一类"换了电脑就坏"。
（口径对照：「变量赋值」写全局变量时是**显式锁不变区域性并拒绝千分位**的，
这边用的是 `Convert` 默认行为——两个节点不是一套规则，别照着对方的结论套。）

**现象：`Target=DateTime` 一直失败。**
`ParseExact` 是逐字符严格匹配：

```
2026/10/14        对 yyyy-MM-dd          失败（分隔符不符）
2026-10-14        对 yyyy-MM-dd HH:mm:ss 失败（缺时间部分）
2026-10-14 9:30:00 对 HH                  失败（HH 要求两位，这里要用 H）
2026-10-14 09:30  对 HH:mm:ss             失败（缺秒）
```

先确认上游文本长什么样（把它连到上报/显示通道看一眼），再照着它写 `Format`。

**现象：把 `Format` 清空了，结果还是按默认格式解析。**
代码里写了 `?? "yyyy-MM-dd HH:mm:ss"`——端口值为空时**自动回落默认格式**。
"清空"不等于"不格式化"，想换格式必须填上新的。

**现象：`Input` 空着（没连线也没填），这一步却是绿的。**
两个可能：① 值是 `null` 的分支显式判"成功"（`Result=null`、置成功、直接返回），
这是设计口径——别指望它帮你发现漏接；② 根本没跑到这一步（被上游分支跳过）。
**如果连"没配置"这一关都过了还全绿**，那是①。希望缺数据就停流程，请在下游加判定
（接「数值比较」或脚本节点），而不是指望这里变红。

**现象：目标类型没选错，但输出到下游就报类型不对。**
`Result` 是 `object` 端口，编译期连线一律放行（object 双向放行），
**错配要到运行期才暴露**。核对下游端口声明的类型与这里转出来的 CLR 类型是否一致——
例如这里转成 `Int32`，下游若是 `double` 端口可以（数值互转），若是 `bool` 就不行。

**现象：转出来的字符串看着很怪（比如 `True`、`12.34`）。**
`String` 那一路就是 `input.ToString()`，用当前区域格式化、**不做位数控制**。
要格式化请走「数学计算」先取整，或用脚本节点。

## 三、改了没反应

**现象：改了源码，界面上行为一点没变。**
`Modules\` 下的插件 DLL 不由宿主工程带出，只重建宿主跑的仍是旧 DLL。
必须重建插件工程；增量构建还可能静默漏打包内嵌手册（收尾那次全量重建用 `--no-incremental`）。

**现象：给 `TargetDataType` 补了中文 `[Display]`，下拉还是英文。**
两处候选生成点（自动参数面板 + 绑定窗口）都走 `StepConfigOption.ForEnum`，
读的就是成员上那个特性。界面没变基本就是**插件工程没重建**，先核 DLL 时间戳。

**现象：改了成员顺序，历史方案的目标类型全乱了。**
枚举落 JSON 是序号。这是不可逆的破坏性改动——**只能在末尾追加**。

## 四、快速自查清单

```
① 步骤红 → 直接搜日志"{实例名} 类型转换失败"，界面上的错误信息可能没有内容
② 反复失败 → 把 Input 的原文本先显示出来，再照着它写 Target 与 Format
③ 全绿但 Result 是 null → 十有八九是输入没接（null 分支判成功）
④ 只有 DateTime 需要 Format，其它目标类型填了也不起作用
⑤ 跨机器坏 → 怀疑区域设置（小数点符号、日期格式），不是本节点的开关
```
