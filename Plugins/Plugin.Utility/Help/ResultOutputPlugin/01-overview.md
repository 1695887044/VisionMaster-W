# 结果输出

> 分类：流程控制 ｜ 来源：插件 Plugin.Utility

把本轮业务判定（OK/NG）显式声明给宿主，供 SCADA 系统变量、轮次记录/下钻、结果上报与报表使用。
每条生产流程应**恰好一个**，放在主路径末尾、所有 `Return` 之前。

## 什么时候用它

SCADA 要显示工位良率、报表要统计班次产出、轮次记录要落 OK/NG，都绕不开同一个问题：
**这一轮到底算 OK 还是 NG？** 不能靠"有步骤失败"反推——

- 判定表 NG 时会 `Fail()`，步骤变 Failed；
- 卡尺/斑点 NG 时 `Success` 仍为 true，只在 `IsOk` 端口写 false。

同一个"步骤 Failed"在不同插件里既可能是产品不良、也可能是技术故障。所以判定必须由流程
显式声明：把上游判定（判定表 `IsOk`、逻辑运算 `Result`、脚本写出的布尔变量）接到本步骤的
`IsOk` 端口，宿主在轮末读取。

## 三步上手

```
① 工具箱（分组「流程控制」）拖出「结果输出」，放在主路径最后一步。
② 把判定接到 IsOk：判定表的 IsOk、逻辑运算的 Result，或脚本写出的布尔变量。
   可选：把 NG 原因接到 Reason，轮次记录/下钻会显示它。
③ 运行一轮，System.Flow.<流程名>.* 开始计数（底栏已不显示 KPI，在「N 条在跑」浮窗里看）。
```

## 它不做什么

- **不计算节拍**：插件在轮内执行，本轮还没结束，拿不到最终耗时；节拍由宿主按
  `FlowRunStarted → FlowRunCompleted` 统计。
- **不统计计数**：OK/NG/未判定由宿主累计。
- **不写变量**：系统变量是只读派生量；写全局变量会退回用户变量改名/删除/复制/迁移的
  生命周期问题。本步骤只声明判定，宿主负责记录与投影。

## 关键语义

**NG 时本步骤仍然 Success。** 判定是正常结果；步骤失败只表示"没拿到判定"。
否则父流程和「调用流程」会把产品 NG 当成调用故障（判定表 NG 恰好会 `Fail()`）。

**一条流程只允许一个。** 本轮执行到两个及以上 → 记**未判定**（判定源歧义），
不再"取最后执行"——那在循环里会变成"最后一个对象说了算"，在顺序两步里会变成"后一步覆盖前一步"。

- 分支逻辑各写一个（If/Else 各一个）可以，因为一轮只走一条路径；
- **循环里不要放**：循环里只做检测、把结果累积到变量或判定表，循环外放一个做整批结论
  （典型是"任一 NG 即 NG"）；
- 真要"以某一步的端口为准"，用结果源配置的「步骤端口」模式，它按步骤 Id 钉死。
