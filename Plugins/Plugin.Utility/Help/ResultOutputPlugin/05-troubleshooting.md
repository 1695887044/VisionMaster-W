# 排障

## 编译报 `[参数缺失] … 'IsOk' 未配置`

原因：`IsOk` 是必填端口，既没有上游连线，也没有手填常量。

处理：把上游判定接到 `IsOk`（判定表 `IsOk`、逻辑运算 `Result`、脚本布尔变量），
或先手填一个常量做测试。固定值运行时会在日志里留一条 Warn。

## 底栏一直显示「未判定」

按顺序查：

1. 流程里有没有「结果输出」步骤？旧方案没有时宿主会尝试 `<流程名>_Result` 变量。
2. 本步骤本轮执行了吗？被 `If` 分支跳过、被 `Return` 提前返回、或放在循环里一次没进，
   都会导致宿主读不到判定 → 记「未判定」。
3. 步骤状态是不是 `Success`？本步骤正常执行时始终 Success；如果它 Failed，
   说明 `RunAlgorithm` 抛异常（例如日志服务异常），看运行日志。
4. 多个「结果输出」步骤？宿主取最后执行的一个；如果最后执行的那个没拿到值，
   本轮就是未判定。建议每条流程只放一个。

## 明明 NG，底栏却记 OK

检查 `IsOk` 接的是不是**本轮**的判定：

- 接的是上一轮的结果变量（变量没每轮写）；
- 接的是另一个工位/另一条规则的输出；
- 判定表 NG 但 `IsOk` 端口接的是 `FailedCount == 0` 之类的派生值，口径不一致。

结果输出只负责"声明"，判定逻辑本身要对。建议在轮次下钻里看失败步骤与原因。

## 步骤 Failed 了，底栏却没记 NG

这是**预期行为**：步骤 Failed 表示技术故障/异常，不是产品不良。本步骤正常执行时始终 Success，
所以它 Failed 只可能是自身异常。产品 NG 应通过 `IsOk=false` 表达，步骤保持 Success。

## 流程改名后 SCADA 绑定断了

系统变量按 `FlowId` 生成确定性 Id，改名只改显示名；按 Id 绑定的画面不应断。
如果画面是按**名字**手填绑定的，改名后需要重新选择（与用户变量同一口径）。

## 旧方案没有这个步骤

不自动插入（静默改用户流程图是红线级行为）。两种做法：

- 在流程末尾手动拖一个「结果输出」，接上判定；
- 继续用约定变量 `<流程名>_Result`，宿主会读它；读不到记「未判定」。
