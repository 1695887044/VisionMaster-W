# 数学计算 · 端口与参数

> 分类：数据处理 ｜ 来源：插件 Plugin.Utility

本页是字典：三个输入、一个输出，逐个写清**端口名、声明类型、默认值、必填性、
界面上这一行长什么样、不接线的后果**。内容逐字取自 `MathCalculationPlugin.cs`，
"该选哪个运算"在「概览」的算式表里，按现象找原因在「排障」。

## 端口声明对照

| C# 成员 | 端口名 | 声明类型 | 默认值 | 端口描述 | 必填 |
| --- | --- | --- | --- | --- | --- |
| `Operation` | `Operation` | `InputPort` 装 `MathOperationType` | `Add` | 运算类型 | 是 |
| `ValueA` | `A` | `InputPort` 装 `double` | `0.0` | 操作数A | 是 |
| `ValueB` | `B` | `InputPort` 装 `double` | `0.0` | 操作数B | 是 |
| `Result` | `Result` | `OutputPort` 装 `double` | — | 运算结果 | 输出端口无此项 |

三行输入的必填性**来自基类默认**：`InputPort` 的 `IsRequired` 初值就是 `true`，
源码里没有写 `{ IsRequired = false }`（只有「延时」那个插件显式重复了一次 `true`）。
端口名与 C# 成员名**故意不一致**（`ValueA` → `A`、`ValueB` → `B`）：
存盘字典里的键、编译报错里出现的参数名，用的都是**端口名**那一列。

## 本插件没有 `[StepConfig]` 配置属性

四个参数全部以**输入端口**形态存在（源码里没有任何 `[StepConfig]` 标注）。
后果是可以在参数面板上直接说的三件事：

- 每个参数都能连线（`[StepConfig]` 属性只能手填常量），"操作数"本来就是上游给的；
- 存盘时三个参数共用同一个 `InputValues` 字典，不另开一套键；
- 界面回退到宿主自动生成的参数面板——本插件不实现自定义视图接口。

## 参数面板上这三行

宿主自动生成参数面板，规则是：

- **只列输入端口**，本插件正好三个；
- **行序按端口名排序**（忽略大小写），所以界面上是 `A`、`B`、`Operation`，
  不是源码里的声明顺序（`Operation` 声明在最前面）；
- **行标签用端口描述**（描述为空才退回端口名），所以看到的是「操作数A」「操作数B」「运算类型」
  三个中文标签。文档与报错里出现的是端口名，界面上出现的是描述，同一行的两张脸。

`Operation` 那一行的形态与其它两行不同——枚举端口被识别为"只能选"：

| 项目 | `A` / `B` | `Operation` |
| --- | --- | --- |
| 控件 | 可编辑文本框 + 🔗 链接 + ✕ 清除 | **只有下拉** |
| 候选 | 无 | 按端口类型现场取 `Enum.GetNames`，顺序即声明顺序 |
| 链接按钮 | 有 | **不提供**（枚举是封闭集合，上游值未必是合法枚举值） |
| 清除按钮 | 有 | **不提供**（清掉之后没有任何"空枚举"可以表示） |
| 显示文字 | 原样文本 | 英文成员名——`MathOperationType` 未配中文 `[Display]` |

**下拉里是英文不是中文**：`Add` / `Subtract` / … 直接就是成员名。这是已知欠账，
机制（`StepConfigOption.ForEnum`）已经修好，只差给这 17 个成员补
`[Display(Name="加法")]` 这样的特性。补了不改存盘值：流程与 `.vms` 里存的永远是成员名。

## 逐个端口的"不接线会怎样"

**`A`（操作数A，默认 `0.0`）**
没连线也没在面板里填过 → 编译报 `[参数缺失] '步骤名' 的必填参数 'A' 未配置！`
（必填性来自基类默认，见上文）。判过之后取的是**实际生效值**：连线值优先于手填值。

**`B`（操作数B，默认 `0.0`）**
同上，端口名换成 `B`。选一元运算时它的值根本不参与生效——但**必填性照样在**，
该填还是要填（约定做法：填 `0` 或 `1` 占位，别留空）。

**`Operation`（运算类型，默认 `Add`）**
同上，端口名换成 `Operation`。因为面板上只有下拉、没有清除按钮，
这一行一旦确认过就不会为空；真正的风险是**存进去的数字**：
枚举在 JSON 里落的是成员对应的序号（`Add=0` … `Ceiling=16`），
所以调整成员顺序会静默改变历史方案选的运算。要加运算类型只能**在末尾追加**。

**`Result`（运算结果，`double`）**
输出端口，不参与必填检查。下游按 `double` 端口取值；连到 `bool` 端口
（例如「逻辑运算」的 `A`）会在编译期被拦——`bool` 不属于数值族。

## 连线兼容性速查（按编译期判据）

| 上游输出类型 | 能否连进 `A` / `B`（期望 `double`） | 能否连进 `Operation`（期望枚举） |
| --- | --- | --- |
| `double` / `int` / 数值族 | 可（数值拓宽） | 否 |
| `string` | 可 | 可（运行期 `Enum.Parse` 按成员名解析） |
| `object`（全局变量默认类型） | 可（类型待定，交给运行期） | 可（同为 object 放行） |
| `bool` | 否 | 否 |
| `HImage` / `HRegion` | 否 | 否 |

**数值 → 枚举不通是有意的不对称**：运行期转换器认"数字 → 枚举"，编译期连线检查不认。
别把它当 bug 顺手补上——连线语义要显式。

## 改端口名 / 改默认值的代价

- **改端口名 = 改存盘键**。老方案 `InputValues` 里存的还是 `A`，
  新键查不到值，该端口静默回到声明的默认值，症状是"换了版本参数全没了"。
- **改默认值 = 改所有"从没填过这一行"的历史方案的行为**。默认值就写在源码的构造调用里，
  `0.0` / `0.0` / `Add` 三个数动之前先想清楚有没有方案靠的是默认值。
- **改成员顺序 = 改存盘数字**，见上面 `Operation` 那一条。
