# 数学计算

> 分类：数据处理 ｜ 来源：插件 Plugin.Utility（工程 `Plugin.Util.csproj`，C# 类 `MathCalculationPlugin`）

对两个数做一步运算，把结果作为 `Result` 输出给下游。工具箱里最省事的"算一下"节点。

## 为什么需要它 / 原理

流程里经常要算一个补偿量、一个差值、一个半径（面积反推）或把像素当量换算成毫米。
用算子拼这些要么得引入额外的中间步骤，要么根本表达不了（比如 `a^b`、`log`）。
本节点把这 17 个一元/二元运算收成"选类型 + 填两个数"三行参数，纯计算、无外部依赖，
标了 `[ParallelSafe]`，可与其它纯计算步骤并行执行。

原理就是一次 `switch`：读三个输入端口的**实际生效值**（连线值优先于手填值），
按运算类型算出一个 `double` 写进 `Result`。**没有动态端口**——端口固定四个，
不会因为改参数而增减，也不会因为改名而断线（名字是写死的 `Operation`/`A`/`B`/`Result`）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `A` | 否 | 操作数 A（`double`，默认 `0.0`）。一元运算只用它 |
| `B` | 否 | 操作数 B（`double`，默认 `0.0`）。一元运算忽略它 |
| `Operation` | 否 | 运算类型（枚举 `MathOperationType`，默认 `Add`） |

本插件**没有自定义配置视图**，宿主自动生成参数面板：按端口名排序列出上面三行
（显示为 `A` / `B` / `运算类型` 之类的描述标签），每行一个值输入框 + 链接图标（连线）+ ✕（清除）。
连线了就以连线值为准，没连线就用框里填的常量。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Result` | 运算结果（`double`，"运算结果"） |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（端口名） | 默认 | 说明 |
| --- | --- | --- |
| `Operation` | `Add` | 运算类型。当前显示英文成员名（该枚举未配中文 `[Display]`），含义见下表 |
| `A`（面板标签"操作数A"） | `0.0` | 第一操作数 |
| `B`（面板标签"操作数B"） | `0.0` | 第二操作数 |

`Operation` 的 17 个成员（界面上的英文成员名 → 实际算式）：

| 成员名 | 算式 | 用到哪些输入 |
| --- | --- | --- |
| `Add` | a + b | A、B |
| `Subtract` | a − b | A、B |
| `Multiply` | a × b | A、B |
| `Divide` | a ÷ b；**b=0 时结果为 `NaN`**（不报错） | A、B |
| `Power` | a 的 b 次方（`Math.Pow(a,b)`） | A、B |
| `Sqrt` | √a；a<0 时为 `NaN` | A |
| `Abs` | \|a\| | A |
| `Sin` | sin(a)，**a 为弧度** | A |
| `Cos` | cos(a)，弧度 | A |
| `Tan` | tan(a)，弧度 | A |
| `Atan` | 反正切，**结果是弧度**（要角度请 ×180/π） | A |
| `Log` | 自然对数 ln(a)；a≤0 时为 `NaN` | A |
| `Log10` | 常用对数 log10(a) | A |
| `Exp` | e 的 a 次方 | A |
| `Round` | 四舍五入取整（.NET `Math.Round`，**银行家舍入**：`2.5 → 2`、`3.5 → 4`） | A |
| `Floor` | 向下取整 | A |
| `Ceiling` | 向上取整 | A |

## 口径与失败策略

- **正常路径不改 `Success`**：框架契约是"默认成功、显式失败"，所以只要算式跑完这一步就是绿的——
  哪怕结果是 `NaN`（除零、负数开方、对负数取对数都只给 `NaN`，**不判失败**）。
  要拦 `NaN` 请在下游接一个「数值比较」或自己做判定。
- **抛异常才失败**：走到 `catch` 时记日志 `{实例名} 运算失败: {消息}`，
  同时 `Result` 置 `NaN`、`Success=false`、`ErrorMessage` = 异常消息。
- **上游值类型不符**：端口是 `double`，上游给的是字符串/布尔会由框架统一转换；
  转不动时是**连线类型不匹配**在取值阶段抛错（不是本插件的算法问题）。
- 没有超时、没有循环、没有外部资源，可安全并行。

## 典型用法 / 接线

```
标定助手.MmPerPixel ──▶ 数学计算.B          （除法 divisor，注意非 0）
像素测量.Value      ──▶ 数学计算.A
                       数学计算.Operation = Divide（b 不为 0）
                       数学计算.Result   ──▶ 数值比较.A  （阈值判定）
                       数学计算.Result   ──▶ 类型转换.Input（Target=String 后上报）
```

算偏心量的接法：`Subtract`（圆心 X 实测 − 名义）与 `Subtract`（Y 同）→ 两个差进 `Power`（2 次方）→
`Add` → `Sqrt`。三步都是同一个节点，只改 `Operation`。

## 常见问题

**Q：除数是 0，为什么不报错反而往下跑？**
A：设计上除零给 `double.NaN` 且不判失败（`Divide` 里显式判了 `b == 0`）。
想让它红，`Result` 后面接一个数值比较或判定步骤。

**Q：`Round` 为什么把 2.5 变成 2？**
A：用的是 .NET `Math.Round`，默认银行家舍入（四舍六入五成双）。要传统的"半进位"就先加 0.5 再 `Floor`。

**Q：`Sin` / `Cos` / `Atan` 的结果看着不对。**
A：参数与返回值都是**弧度**。角度先乘 π/180 再送入；`Atan` 出来要乘 180/π 才是角度。
（需要 atan2(y,x) 那种象限判别的角度，本节点没有，走「图像脚本」或「C#脚本」。）

**Q：`B` 明明填了值却没生效。**
A：两种原因：① 选了一元运算（`Sqrt`/`Abs`/三角/对数/取整/`Exp`），这些**只看 A**；
② `B` 已经连了上游——连线值优先于手填常量，面板里的数字不参与生效。

**Q：结果是 `NaN`，界面却一片绿，怎么定位是哪一步坏的？**
A：`NaN` 会顺着连线继续传染（任何含 `NaN` 的算式都得 `NaN`）。
从最上游往下游逐个看 `Result`，第一个变成 `NaN` 的那步就是病根（多半是除零或负数开方/对数）。

**Q：想要整数运算 / 想要保留两位小数？**
A：本节点全程 `double`。整数就 `Floor`/`Round` 后由下游按 int 端口取值；
保留小数没有直接档位（`Round` 不带位数参数），需要格式化时用「类型转换」转 String，
或在脚本类节点里做。

**Q：`Operation` 下拉里为什么是英文？**
A：这四个工具插件的运算类型枚举还没配中文 `[Display]`（属已知待办），
所以界面显示的是成员名本身（`Add`/`Divide`/…），含义见上面的算式表。
