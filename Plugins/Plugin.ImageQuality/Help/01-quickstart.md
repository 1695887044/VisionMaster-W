# 图像质量检查 · 快速上手

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageQuality

采集之后、算法之前，先回答一句：**这张图能不能用**。

散焦、过曝、欠曝、对比度太低、彩色图饱和度异常时，Blob / 匹配 / 读码 / OCR 仍会给出
“看起来合法”的结果：分数偏低但过阈值、码读不出、字符拒识、缺陷数异常。本插件把
“成像质量”拆成四个可复算的物理量——对焦、曝光、对比度、饱和度——输出原始值、0~1 归一化分和明细，
让“图不能用”在算法之前就被看见，而不是事后解释“为什么这一张 NG”。

工具库里的名字是「图像质量检查」，分组在**图像处理**。

## 一轮检查产出什么

```
输入：图像（Image，必接）
      检查区（Roi，可选；不接则全图）

      │
      ├─▶ FocusRaw / FocusScore          对焦：梯度能量（sobel_amp sum_abs 均值）
      ├─▶ ExposureRaw / ExposureScore    曝光：0/满量程截断像素占比
      ├─▶ ContrastRaw / ContrastScore    对比度：P95 − P5 展宽
      ├─▶ SaturationRaw / SaturationScore 饱和度：HSV S 均值（灰度图为 NaN / 0）
      ├─▶ HasColor                       是否彩色图
      ├─▶ IsUsable / Reason              可选阈值判定的结论与原因（默认 metrics-only）
      ├─▶ Details                        逐项明细：原始值、分数、P5/P95、截断比例、跳过原因
      └─▶ Success / ErrorMessage         执行成功与否；只有输入/算法错误才 false
```

## 五步配出第一次检查

### 第一步：接图

把「采图」或「读图」步骤的图像输出接到本步骤的 `Image` 端口。图像必须是 **byte 或 uint2**，
通道数 1 / 3 / 4；其它位深（real / int4）v1 不支持，会明确失败，请先在上游「预处理」转成 byte。

### 第二步：圈检查区（可选）

产品只占画面一小块时，接一个 `Roi`（`HRegion`，通常来自「创建 ROI」），指标只在 ROI 内算。
不接则用图像自带域（全图）。ROI 有效像素低于 `MinRoiPixels`（默认 16）会直接失败，
避免用几个像素算出“看起来很稳”的假分数。

### 第三步：标定三个参考值

四个分数都是“原始值 ÷ 参考值”夹到 0~1。参考值不是万能常数，必须按**配方/产品**标定：

| 参数 | 默认 | 怎么标 |
| --- | --- | --- |
| `FocusRef` | 200 | 取一批良品，看 `FocusRaw` 的 P5（偏低那端），把参考值设在它附近或略低 |
| `ContrastRef` | 128 | 取良品 `ContrastRaw` 的 P5，参考值设在它附近 |
| `SaturationRef` | 128 | 彩色产品取良品 `SaturationRaw` 的 P5；灰度产品不用管 |
| `MaxTruncationPercent` | 5 | 良品截断占比的 P95 再留一点余量；超过它曝光分记 0 |

先看 `Details` 里的原始值，再定参考值。**不要**直接抄默认值上产线。

### 第四步：看原始值与明细

- `Details` 每行一项：`对焦: raw=... score=...`、`曝光: raw=...% ...`、`对比度: raw=...`、`饱和度: ...`。
- 灰度图的饱和度会写“跳过”，`SaturationRaw` 是 NaN、`SaturationScore` 是 0——这是预期行为，不是故障。
- `ExposureRaw` 是**截断占比**，不是平均亮度。画面整体偏暗但没有像素压到 0 时，它仍可能是 0；
  平均灰度在 `Details` 里，两者要一起看。

### 第五步：需要拦截时再启用阈值

默认 `EnableThreshold=false`：只出指标，`IsUsable` 恒 true。需要前置拦截时：

1. 打开 `EnableThreshold`；
2. 给对应对焦/曝光/对比度/饱和度填 `Min` / `Max`（都是 0~1 的**分数**，不是原始值）；
3. 把 `IsUsable` 接到「逻辑判断」或流程分支；`Reason` 写清哪一项越界。

**质量不达标不会让 `Success=false`**。这是刻意的：图不好是“测量结论”，不是“算法执行失败”；
如果直接 Fail，流程会在最需要看后续数据的时候中断。

## 接线图

```
[采图] ──Image──▶ [图像质量检查].Image
[创建 ROI] ──Roi──▶ [图像质量检查].Roi（可选）
                        │
                        ├──IsUsable──▶ [逻辑判断]（启用阈值时才用）
                        ├──FocusScore / ExposureScore / ... ──▶ [数据记录]
                        └──Details──▶ [结果展示] / [数据记录]
```

## 这个插件不做什么

- **不修改图像**。不做增强、滤波、裁剪、对齐；它只测量。
- **不做脏污检测**。v1 不含脏污；`BlobDetect` / `DlAnomaly` / `DlSegment` / `DlClassify` / `ImageDiff`
  已经覆盖“检脏污”，本插件与它们不重复。v1.1 再评估“有参考图时的差分前置分”。
- **不判 OK/NG**。默认 metrics-only；启用阈值也只输出 `IsUsable`，不调 `Fail`。
- **不写全局变量**。结果只走端口/运行时变量；要全局由下游「变量赋值」映射。
- **不支持 real / int4**。相机原始位深 byte / uint2 是 v1 的范围；其它类型先转 byte。

## 常见误用

| 写法 | 后果 | 正确做法 |
| --- | --- | --- |
| 参考值保持默认 200/128 就上产线 | 分数长期顶在 1 或长期 0.2，阈值没有区分度 | 按良品批次 P5 标定三个参考值 |
| 用 `ExposureRaw` 当“平均亮度” | 整体偏暗但没截断时读到 0，误判为曝光正常 | 同时看 `Details` 里的均值/范围 |
| 灰度图等 `SaturationScore` 有值 | 恒为 0，误判为“饱和度极低” | 先看 `HasColor`；灰度图饱和度无意义 |
| ROI 框进大量背景 | 指标被背景稀释，缺陷区变化不明显 | ROI 只框产品；或先用「创建 ROI」做掩膜 |
| 拿 `pcb_focus` 121 张当“单调散焦序列” | 061 附近最清晰、两端都散焦，单调判据必红 | 以 061 为锚，按 `\|i-61\|` 看趋势（见 04 页） |
