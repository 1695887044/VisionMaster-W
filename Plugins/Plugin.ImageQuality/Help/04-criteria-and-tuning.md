# 图像质量检查 · 口径与调参

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageQuality

这一页讲四个指标**到底在算什么**、为什么这么选、以及怎么按产品标定。
不要把它当“万能阈值表”——本插件没有通用分数，参考值必须按配方/光源/镜头标定。

## 对焦：梯度能量，不是“看起来清楚”

**口径**：`sobel_amp(gray→real, 'sum_abs', 3)` 的均值，uint2 图按 `255/65535` 归一化到 8bit 等效梯度。

为什么用 Sobel 而不是 Laplacian 方差：

- 本仓 `pcb_focus` 121 张实测：Tenengrad（Sobel 梯度能量）从 001 的 30.9 平滑升到 061 的 391.7，
  再平滑降到 121 的 11.2；
- 同一序列的 Laplacian 方差在 001~041 几乎持平（31.4→31.4），051/061 才跳变（70.0/160.3），
  071 又回落到 28.9——对“接近焦点的散焦”分辨力差，容易把不同散焦程度判成同一档。

所以 v1 主指标用 Sobel；Laplacian 只作为对拍/辅助项，不进默认输出。

### `pcb_focus` 不是单调散焦序列

**这是本仓最容易误判的一条**。121 张是“过焦点扫描”：061 附近最清晰，两端都散焦。
按文件名序号做“全序列单调下降”的断言必红，而且不是算法错。

正确用法：

- 以 061 为锚，看 `FocusScore` 与 `|i − 61|` 的 Spearman 相关（期望 ≤ −0.95）；
- 或分段：001→061 单调上升、061→121 单调下降；
- 不要拿这套图验证曝光：平均灰度随焦点从 95.7 漂到 80.4，对焦与曝光是耦合的。

### 标定 `FocusRef`

1. 取一批**良品**（同产品、同光源、同曝光），逐张跑本插件，记录 `FocusRaw`；
2. 取 P5（偏低那端）作为 `FocusRef`；
3. 散焦/模糊的坏图应显著低于 P5；如果良品与坏图分布重叠，说明这个工位靠“对焦分”分不开，
   要换指标（例如先看对比度）或改光学方案。

## 曝光：只看两端截断，不看“整体亮不亮”

**口径**：`ExposureRaw = (直方图 0 箱 + 满量程箱) / 总像素 × 100`（百分比）。

为什么不是平均灰度：

- 平均灰度低不一定是坏图（深色产品、暗背景是正常的）；
- 真正不可逆的是**截断**：像素压到 0 或满量程后，细节永久丢失，算法再调也救不回来。

所以 `ExposureRaw` 只数“压死”的像素。平均灰度、最小/最大灰度放在 `Details` 里供参考，
不参与分数。

### 标定 `MaxTruncationPercent`

1. 良品批次的 `ExposureRaw` 取 P95；
2. `MaxTruncationPercent` 设在 P95 之上留一点余量（默认 5% 只是起点，不是标准）；
3. 过曝/欠曝的坏图应显著高于它。

注意：良品本身有高光（金属反光、LED 灯珠）时，截断占比可能天然有几个百分点；
不要为了“看起来干净”把阈值压到 0，否则每张良品都会被判不可用。

## 对比度：P5~P95 展宽，不是 min~max

**口径**：灰度直方图累计分布取 P5 与 P95，`ContrastRaw = P95 − P5`（0~255 尺度）。

为什么不用 min~max：单个坏点/噪点就能把 min 拉到 0、max 拉到 255，
“对比度”看起来很高，实际画面可能一片灰。P5/P95 忽略两端各 5% 的极值，更稳。

`Details` 里同时给标准差（`Intensity` 的 deviation），供排查“展宽够但分布怪”的情况。

### 标定 `ContrastRef`

1. 良品 `ContrastRaw` 取 P5；
2. `ContrastRef` 设在 P5 附近；
3. 低对比（雾状、光源衰减、镜头脏污导致整体发灰）的坏图应显著低于 P5。

### 对焦与对比度会互相影响

低对比良品的梯度天然低，`FocusScore` 也会低。判断“是散焦还是低对比”时：

- `FocusScore` 低 + `ContrastScore` 正常 → 更像散焦/运动模糊；
- `FocusScore` 低 + `ContrastScore` 也低 → 更像低对比/光源问题；
- 两者都正常但下游仍不稳 → 看 `ExposureRaw` 和 `Details` 的均值/范围。

不要只看一个指标就下结论。

## 饱和度：只对彩色图有意义

**口径**：`decompose3` → `trans_from_rgb(..., 'hsv')` → S 通道 `Intensity` 均值（0~255）。

- 灰度图：`HasColor=false`，`SaturationRaw=NaN`，`SaturationScore=0`，`Details` 写“跳过”。
  这是**预期行为**，不是故障；不要拿 0 当“饱和度极低”。
- 彩色图：`SaturationRaw` 是 S 通道均值；`SaturationRef` 按良品 P5 标定。
- uint2 彩色：先按 `255/65535` 线性缩放到 byte 再转 HSV（不截顶），指标仍是 0~255 尺度。

饱和度异常通常对应：光源色温漂移、滤镜/白平衡变化、相机色彩增益被改。
它不是“颜色对不对”的判定——颜色判定用「颜色检查」/「区域颜色」。

## 四类典型配方

### 配方 A：散焦 PCB（`pcb_focus`）

- 目标：在算法前拦掉明显散焦的图；
- 指标：`FocusScore` 为主，`ContrastScore` 为辅；
- 标定：清晰段（约 041~081）良品 `FocusRaw` 的 P5 作 `FocusRef`；
- 验证：061 为锚，`FocusScore` 与 `|i−61|` 的 Spearman ≤ −0.95；
- 注意：不要用全序列单调判据；不要用这套图验证曝光。

### 配方 B：标签曝光（`label`）

- 目标：拦过曝/欠曝的标签图；
- 指标：`ExposureScore` 为主，`ContrastScore` 为辅；
- 标定：良品 `ExposureRaw` P95 定 `MaxTruncationPercent`；良品 `ContrastRaw` P5 定 `ContrastRef`；
- 注意：`label` 真图没有绝对曝光真值，只能验证方向与重复性；绝对真值用合成图。

### 配方 C：SMD 对比度（`smd`）

- 目标：拦低对比/雾状图；
- 指标：`ContrastScore` 为主；
- 标定：良品 `ContrastRaw` P5 定 `ContrastRef`；
- 注意：SMD 不同芯片的纹理差异大，按产品分批标定，不要跨产品共用参考值。

### 配方 D：彩色产品饱和度

- 目标：拦光源色温/白平衡漂移；
- 指标：`SaturationScore`；
- 标定：良品 `SaturationRaw` P5 定 `SaturationRef`；
- 注意：先看 `HasColor`；灰度图跳过。

## 阈值标定的通用流程

1. **先 metrics-only 跑一批**（`EnableThreshold=false`），记录四个原始值；
2. 取良品分布的 P5/P95，定三个参考值与 `MaxTruncationPercent`；
3. 把参考值写进参数，再跑同一批，确认 `FocusScore`/`ExposureScore`/`ContrastScore` 在良品上分布合理；
4. 拿已知坏图（散焦/过曝/低对比）跑，确认分数显著低；
5. 打开 `EnableThreshold`，填 Min/Max，接 `IsUsable` 到「逻辑判断」；
6. 换镜头/光源/曝光时间/产品 → **重新标定**，不要沿用旧参考值。

## 常见调参错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 良品分数长期 1.0 | `FocusRef` 太低，`FocusRaw` 一直超过它 | 把参考值抬到良品 P50 附近，留出区分度 |
| 良品分数长期 0.2 | 参考值太高 | 按良品 P5 重标 |
| 曝光分恒 1.0，但图明显偏暗 | 没有截断；`ExposureRaw` 只数两端压死像素 | 看 `Details` 均值/范围，必要时加“均值区间”下游判断 |
| 灰度图饱和度 0 被当异常 | 灰度图没有饱和度 | 先看 `HasColor`；灰度图跳过 |
| ROI 改小后分数大涨 | 原来 ROI 含大量背景，指标被稀释 | ROI 只框产品；或接受“全图质量”口径 |
| uint2 图分数和 byte 图差很多 | 位深不同但参考值没重标 | 本插件已归一化到 0~255；仍建议按位深重标参考值 |
