# 排障

## 先确认三件事

1. 数据库页：profile 启用、文件路径正确、「测试连接」通过；
2. 语句：类型是「写一行」、SQL 是 `INSERT`、参数表与占位符对齐、「测试语句」通过；
3. 步骤：选中的是那条语句、必填参数已填/已链接。

## 常见错误

### 『写一行』只允许 INSERT

语句类型选错了。更新用「数据库执行」，查询用「数据库查询」。

### 该语句是『查询』类型，不能用于写步骤

步骤与语句类型不匹配。到数据库页把语句类型改成「写一行」，
或换一条正确的语句。

### 只读数据库不允许写操作

profile 是只读档。写步骤必须用读写档 profile。

### 缺少必填参数 @lot

参数必填且没有默认值。填常量或链接上游；若业务允许空，把参数改成非必填
或给一个默认值。

### 参数 @ok 期望布尔值（true/false/1/0）

上游给的是别的文本（例如 "OK"/"NG"）。两种修法：

- 上游先用「比较」转成布尔；
- 把语句参数类型改成 Text，并在 SQL 里按文本存。

### 约束冲突（UNIQUE constraint failed）

同一主键/唯一键已有行。选择：

- 改成 UPSERT：`INSERT ... ON CONFLICT(...) DO UPDATE SET ...`；
- 或在写之前先查（多一次往返，且仍有竞态）；
- 或检查批号/序列号是不是重复取了。

### 影响行数 1 超过上限 0

不会发生——上限 0 表示不限制。若你设了上限（例如 1），
UPSERT 更新已有行也算 1 行，属正常；只有真的超过才回滚。

### 写成功但查不到

- 写到了另一个数据库文件：核对 profile 的路径；
- 事务没提交：本步骤是自动提交的，失败会明确报错，不会"半成功"；
- 查询用了不同的过滤条件（大小写、前后空格）。

## 停线了怎么办

`FailFast = true` 时写失败会中断当轮。现场处理顺序：

1. 看日志 `[数据库] op=Execute ... error=...`，错误类别在文案开头；
2. 修数据库（文件被占用、磁盘满、约束冲突）；
3. 恢复运行；**不要**把 FailFast 关掉来"先跑起来"——
   那会让丢失的行再也补不回来。

## 测试与真写的区别

- 配置窗口「测试语句」：事务内执行后回滚，banner 写「已回滚（未写入数据）」；
- 数据库页「测试语句」：同样默认回滚；
- 正式运行：真写。

看到"测试通过"不等于数据已经进库，这是刻意的。

## MySQL / MariaDB 专有情况

- **Duplicate entry（1062）**：唯一键已存在。改成
  `INSERT ... ON DUPLICATE KEY UPDATE ...`，或先查再写；
- **Data too long（1406）**：参数比列定义长。改列长度，或在步骤里截断/校验；
- **Incorrect string value（1366）**：字符集不匹配（常见于 emoji/生僻字）。
  库表用 `utf8mb4`；MySqlConnector 默认按 `utf8mb4` 通信；
- **MyISAM 表不支持事务**：写失败不会回滚，务必用 InnoDB；
- **Access denied（1142/1045）**：账号没有 `INSERT` 权限或密码不对；
  密码在数据库页重新输入（保存时 DPAPI 加密）；
- **密码无法解密**：`databases.json` 来自另一台机器/另一个 Windows 账号，重新输入即可。
