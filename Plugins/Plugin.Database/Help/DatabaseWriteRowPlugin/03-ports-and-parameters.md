# 端口与参数

## 输入（由语句定义动态生成）

选中「写一行」语句后，按参数表逐行生成输入端口。每行可填常量或链接上游。

常见映射：

| 参数 | 来源 |
| --- | --- |
| lot | 上游「读码」结果 / 工单变量 |
| product_code | 配方变量 |
| score | 视觉检测的分数输出 |
| ok | 判定结果（布尔） |
| created_at | 系统时间变量，或留空由数据库默认值填充 |

## 参数规则

- 名字 = SQL 里的 `@name`（不含 `@`）；
- 必填且无默认值 → 未填/未链接时确认被拒，点名缺哪个参数；
- 类型按参数表校验：
  - Text：原样绑定；
  - Integer：整数，拒绝小数/千分位；
  - Real：数值，不变区域性；
  - Boolean：`true/false/1/0`，落库 1/0；
  - DateTime：日期时间文本按不变区域性解析；
  - Blob：Base64 文本或字节数组；
- 多余参数被拒（"语句没有定义这些参数"）。

## 输出

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| Accepted | 布尔 | 语句是否执行成功 |
| AffectedRows | 整数 | 实际影响行数；UPSERT 命中已有行可能为 0 |
| ElapsedMs | 数值 | 本次执行耗时（毫秒） |

## 默认值怎么用

参数表里的「默认值」在两种情况下生效：

- 步骤里该参数留空（常量框为空且没有链接）；
- 参数非必填且上游没给值。

必填参数可以靠默认值满足——此时步骤里留空是合法的。

## 事务与上限

- 一次调用 = 一个事务；
- 语句「最大影响行数」非 0 时，超限回滚并失败（单行写入一般是 1，用作兜底）；
- 超时取 profile / 语句 / 步骤三处非零值的最小值。

## 与「数据库执行」的参数差异

两者参数机制完全相同（都按语句参数表生成端口），区别只在 SQL 类型与输出：

- 写行：`INSERT`，输出 `Accepted`；
- 执行：`UPDATE/DELETE`（必须带 WHERE），输出 `AffectedRows`。

## 例子：每件写一行

语句 `WriteResult`：

```sql
INSERT INTO result(lot, product_code, score, ok)
VALUES (@lot, @code, @score, @ok)
```

参数：

| 参数 | 值 |
| --- | --- |
| lot | 链接「读码_0.Text」 |
| code | 常量 `A-1001` |
| score | 链接「模板匹配_0.Score」 |
| ok | 链接「比较_0.Result」 |

下游用 `AffectedRows > 0` 判断是否真的新增，用 `Accepted` 判断调用是否成功。
