# 排障

## 先看这四处

1. 硬件管理 → 数据库：profile 是否启用、文件路径是否存在；
2. 命名语句：类型是不是「查询」、SQL 能不能在数据库页「测试语句」跑通；
3. 步骤配置：数据库/语句是否选中、必填参数是否填了或链接了；
4. 日志：每次执行都有一行 `[数据库] op=Query profile="…" statement="…"`，
   失败时带 `error=`，里面是可直接上屏的原因。

## 常见错误

### 还没有数据库配置

配置窗口左栏为空。去「硬件管理 → 数据库」添加 profile。
v1 支持 SQLite 与 MySQL/MariaDB。SQLite 文件后缀必须是 `.db` / `.sqlite` / `.sqlite3`；
MySQL 需要填服务器、端口、库名、用户与密码。

### 该数据库还没有命名语句

profile 建了但没有语句。去数据库页「新建语句」，类型选「查询」。
插件里不能写 SQL —— 这是刻意的：SQL 必须集中维护、集中测试、集中审计。

### 该步骤需要「查询」语句，当前语句是「写一行」

语句类型与步骤不匹配。要么换一条查询语句，要么改用「数据库写行」步骤。

### 只读数据库不允许写操作

profile 以「只读」打开。查询步骤不受影响；写步骤要换成读写档的 profile。

### 缺少必填参数 @xxx

参数表里该参数是必填且没有默认值。两种修法：

- 在步骤里填常量；
- 点 🔗 链接上游输出。

「语句没有定义这些参数」则相反：步骤里多了参数，通常是语句改过参数表，
重新打开配置窗口让参数行按新定义重建。

### 参数 @x 期望整数/数值，实际是 'abc'

类型不匹配。检查上游给的是不是文本，或把语句参数类型改成 Text。
数值文本不接受千分位（`1,234` 会被拒）。

### 超时 / 数据库正忙

- 提高 profile 或语句的超时；
- SQLite 同一时刻只有一个写者：别的进程正在写时会短暂 `BUSY`，
  服务已设置 `busy_timeout` 等待，仍然超时才报错；
- 不要用查询语句做全表扫描。

### 找不到表/列（no such table / no such column）

数据库文件路径选错了，或表还没建。用数据库页的「测试连接」确认版本与文件，
再用「测试语句」确认 SQL 能跑。

### 结果被截断（Truncated = true）

达到最大行数上限。确认是不是真的要全量：多数场景应该加 `WHERE` 或 `LIMIT`，
而不是把上限调大。

## 试运行与正式运行的区别

配置窗口里的「测试语句」：**事务内执行后回滚**，只预览结果，不写数据。
正式运行：按语句类型执行；查询本身就是只读的，不存在回滚问题。

## 查询结果为空

`RowCount = 0`、`Scalar = null`、`RowsJson = []`，步骤仍然是成功。
下游用 `If` 判 `RowCount > 0` 或 `Scalar != null` 即可。

## MySQL / MariaDB 专有错误

### Access denied for user（1045 / 1044 / 1142）

账号或密码不对，或该账号没有这张表的权限。到数据库页重新输入密码（保存时会 DPAPI 加密），
并让 DBA 确认 `GRANT SELECT`。

### Unknown database / Table doesn't exist（1049 / 1146 / 1054）

库名、表名或列名写错，或连到了另一台服务器。核对 profile 的「服务器/端口/数据库」，
再看 SQL 里的表名大小写（Linux 上的 MySQL 默认区分表名大小写）。

### PRAGMA 是 SQLite 专有语法

当前 profile 是 MySQL。把 `PRAGMA table_info(t)` 换成
`SELECT * FROM information_schema.columns WHERE table_schema = DATABASE() AND table_name = 't'`。

### 查询步骤不允许锁定读（FOR UPDATE / LOCK IN SHARE MODE）

查询步骤只做只读查询。需要锁行请走「数据库执行」的 `UPDATE`，
或在业务侧接受"读到旧值"的代价。

### 数据库密码无法解密

`databases.json` 是从另一台机器/另一个 Windows 账号拷过来的。DPAPI 密文与本机绑定，
到数据库页重新输入一次密码即可。

### 连接超时 / 服务器不可达（2002 / 2003）

检查服务器地址、端口（默认 3306）、防火墙与 MySQL 的 `bind-address`。
容器环境注意端口映射。
