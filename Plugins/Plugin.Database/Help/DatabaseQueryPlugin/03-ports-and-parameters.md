# 端口与参数

## 输入（由语句定义动态生成）

配置窗口选中命名语句后，按语句的参数表**逐行生成输入端口**：

| 端口名 | 类型 | 说明 |
| --- | --- | --- |
| 语句里定义的每个参数 | 任意 | 名字就是 SQL 里的 `@name`（不含 `@`） |

每一行可以：

- 填**常量**（在输入框里直接写）；
- 点 🔗 **链接上游**（变量、上一步的输出、系统变量）。

已链接的行以连线值为准；未链接的行用常量值。
必填且没有默认值的参数，未填/未链接时确认会被拒绝，并点名缺的是哪个 `@参数`。

### 参数类型

| 类型 | 接受的值 | 说明 |
| --- | --- | --- |
| Text | 任意文本 | 原样绑定，不做拼接 |
| Integer | 整数文本 / 整数 | 拒绝小数与千分位 |
| Real | 数值文本 / 数值 | 使用不变区域性；拒绝 `1,234` |
| Boolean | `true`/`false`/`1`/`0`/布尔 | 落库为 1/0 |
| DateTime | 日期时间文本 / DateTime | 按不变区域性解析 |
| Blob | Base64 文本 / 字节数组 | 文本必须是合法 Base64 |

类型不匹配会在执行前被拒，错误文案点名参数与原始值。

## 输出

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| Scalar | 任意 | 第一行第一列；无行时 `null` |
| RowsJson | 文本 | `[{"列名": 值}]`；数值仍是数值，`null` 仍是 `null`，字节转 Base64 |
| RowCount | 整数 | 返回行数（0 不算失败） |
| Columns | 文本 | 列名逗号分隔，保持查询顺序 |
| Truncated | 布尔 | true = 只拿到前 N 行（受最大行数限制） |
| ElapsedMs | 数值 | 本次查询耗时（毫秒） |

## 最大行数

- 数据库 profile 上有默认最大行数（默认 1000）；
- 语句上可以再设一个（0 = 用 profile 的）；
- 步骤配置里的超时也可以再设（0 = 用前两级）。

实际生效的是**三者中非零的最小值**。达到上限时 `Truncated = true`，
只返回前 N 行，不会把整表拉进内存。

## 例子

命名语句 `ReadRecipe`：

```sql
SELECT param_name, param_value
FROM recipe
WHERE product_code = @code AND enabled = 1
```

步骤参数：

| 参数 | 值 |
| --- | --- |
| code | 链接「视觉检测_0.Result」或常量 `A-1001` |

下游用法：

- `RowCount > 0` → 配方存在；
- `RowsJson` 交给 C# 脚本解析；
- `Scalar` 取第一行第一列（本例是 `param_name`，通常配合 `ORDER BY` 使用）。
