# 数据库查询

## 这个步骤做什么

按硬件管理里封装好的**命名语句**查询数据库，把结果交给下游：

- `Scalar`：第一行第一列（没有行时是 `null`）；
- `RowsJson`：结果行 JSON 数组（列名做键）；
- `RowCount`：返回行数；
- `Columns`：列名（逗号分隔，保持查询顺序）；
- `Truncated`：是否被最大行数截断；
- `ElapsedMs`：本次查询耗时。

典型用途：读配方、读工单、读上一道工序的结果、统计当班产量。

## 支持的数据库

| 类型 | 连接方式 | 说明 |
| --- | --- | --- |
| SQLite | 本地文件（`.db` / `.sqlite` / `.sqlite3`） | 单机追溯、离线场景 |
| MySQL·MariaDB | 服务器 + 端口 + 数据库 + 用户 + 密码 | 中央库/MES；密码由宿主用 DPAPI 加密保存 |

两种数据库的插件步骤完全一样：只选 `数据库 + 语句 + 参数`，SQL 与连接串都不进 `.vms`。

## 前提：先有数据库与语句

插件本身**不写 SQL、不碰连接串**。使用前必须先在
「硬件管理 → 数据库」完成两件事：

1. 添加一个数据库（选类型：SQLite 填文件路径；MySQL 填服务器/端口/库名/用户/密码）；
2. 在「命名语句」里新建一条**查询**语句（`SELECT` / `WITH`；SQLite 另允许只读 `PRAGMA`），
   并把参数表与 SQL 里的 `@name` 占位符一一对齐。

配置窗口左侧会列出可选的数据库与语句；SQL 只读预览，编辑请回数据库页。

## 什么时候用 / 不用

**用**：结果集小、需要拿到具体值（配方号、阈值、工单数量）。
**不用**：每件都要写一行（用「数据库写行」）；整表更新（用「数据库执行」）。

## 失败语义

默认 `FailFast = false`：查询失败只让本步骤变红，流程继续。

原因：读库失败通常应该由下游 `If` 判空来处理（读不到配方就走默认参数），
不该因为一次读库失败把整条线停掉。需要停线的现场把 `FailFast` 打开。

**`RowCount = 0` 不是失败**：`Success = true`、`Scalar = null`、`RowsJson = []`。

## 只读数据库

数据库以「只读」方式打开时，查询照常可用；写步骤会被直接拒绝。

- **SQLite**：连接串以 `Mode=ReadOnly` 打开，是数据库层的硬保证；
- **MySQL/MariaDB**：MySQL 没有"连接级只读"开关，只读靠应用层拦（只允许查询语句）。
  要真正的硬保证，请给该账号只授 `SELECT` 权限——数据库的 GRANT 才是最终边界。

只读档允许的语句：`SELECT`、`WITH`；SQLite 另允许只读 `PRAGMA` 白名单
（`table_info` / `table_xinfo` / `table_list` / `index_list` / `index_info` /
`foreign_key_list` / `database_list` / `compile_options`）。

## 与其它数据出口的分工

| 出口 | 职责 |
| --- | --- |
| CSV 记录 | 本地追加账本，不查不改 |
| Excel 导出 | 人看报表 |
| 结果上报 | HTTP/MES 上报 |
| **数据库查询** | 从中央库读配置/工单/统计 |

四者互不替代：查询是"读"，写行/执行才是"写"。
