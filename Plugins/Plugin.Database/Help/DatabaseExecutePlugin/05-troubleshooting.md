# 排障

## 常见错误

### UPDATE / DELETE 必须带 WHERE

保存语句时被拒。补 `WHERE`；确需整表操作写 `WHERE 1 = 1`（显式，可追溯）。

### 『执行』只允许 UPDATE / DELETE；INSERT 请用『写一行』

语句类型选错了。插入/插入或更新用「写一行」步骤与「写一行」类型语句。

### 只读数据库只允许保存『查询』语句

profile 是只读档。执行步骤必须用读写档 profile。

### 影响行数 N 超过上限 M，已回滚

语句上设了「最大影响行数」，本次命中的行数超了。
两种处理：

- 收窄 `WHERE`（多数情况是对的）；
- 确认业务确实要改这么多，再调高上限。

回滚是整条语句回滚，不会留下"改了一半"的状态。

### 缺少必填参数 @xxx

参数是必填且没有默认值。填常量或链接上游。

### 参数 @x 期望布尔值（true/false/1/0）

上游给的是别的文本。检查上游输出类型，或在语句里把参数类型改成 Text。

### 语句『xxx』已被禁用

数据库页把语句或 profile 的「启用」取消了。恢复启用，或换一条。

### 找不到该命名语句（可能已被删除）

`.vms` 里的 StatementId 在数据库中已不存在。到数据库页确认；
有流程引用时删除本应被禁止，出现这条说明配置被外部改动过（手工改 json / 换机器）。

## 调试顺序

1. 数据库页 →「测试连接」：文件在不在、版本、耗时；
2. 数据库页 → 选中语句 →「测试语句」：SQL 与参数能不能跑（默认回滚）；
3. 步骤配置 →「测试语句」：参数映射对不对（默认回滚）；
4. 正式运行 → 看日志 `[数据库] op=Execute ...` 一行。

## 回滚了但我以为写进去了

配置窗口与数据库页的「测试语句」**默认回滚**，banner 会写「已回滚（未写入数据）」。
要真写只能走正式运行；测试区取消勾选回滚需要二次确认（宿主页）。

## 事务与并发

- 一次调用一个事务；失败整条回滚；
- SQLite 同一时刻一个写者：别的进程在写时可能短暂 `BUSY`，
  服务已设 `busy_timeout` 等待；
- 不要在两个步骤里"先删后插"假装一个事务——那跨了两个事务，中间失败会留下半套数据。

## MySQL / MariaDB 专有情况

- **MyISAM 表不支持事务**：回滚不会生效。要"全有全无"必须用 InnoDB；
- **锁等待超时（1205）/ 死锁（1213）**：事务被数据库回滚，日志会标「死锁」；
  收窄 `WHERE`（走索引）或缩短事务再重试；
- **Access denied（1142）**：账号没有该表的 `UPDATE`/`DELETE` 权限；
- **Safe update mode**：部分客户端默认开启 `sql_safe_updates`，无键更新的 `UPDATE` 会被拒；
  本软件直连不受该客户端设置影响，但 DBA 可能在服务端启用等价策略。
