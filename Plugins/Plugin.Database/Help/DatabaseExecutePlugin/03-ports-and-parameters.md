# 端口与参数

## 输入（由语句定义动态生成）

选中命名语句后，按语句参数表逐行生成输入端口。每行可填常量或点 🔗 链接上游。

例子：把某批号的结果标记为 NG。

```sql
UPDATE result
SET ok = @ok, remark = @remark
WHERE lot = @lot
```

参数表：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| lot | Text | 是 | 批号 |
| ok | Boolean | 是 | 0 = NG |
| remark | Text | 否 | 备注 |

步骤里：`lot` 链接上游变量，`ok` 填常量 `false`，`remark` 留空。

## 参数规则

- 名字就是 SQL 里的 `@name`（不含 `@`），必须是字母/数字/下划线且不以数字开头；
- 必填且无默认值的参数，未填/未链接时**确认被拒绝**；
- 类型按参数表校验（Text/Integer/Real/Boolean/DateTime/Blob）；
- 多余参数会被拒（"语句没有定义这些参数"）——静默忽略会让人以为值生效了。

## 输出

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| AffectedRows | 整数 | 实际影响行数；0 是合法结果 |
| ElapsedMs | 数值 | 本次执行耗时（毫秒） |

`AffectedRows = 0` 表示条件没有命中任何行，步骤仍然是成功。
下游若要"必须改到至少一行"，用 `If` 判 `AffectedRows > 0`。

## 上限与超时

- 语句「最大影响行数」：0 = 不限制；非 0 时超限回滚并失败；
- 语句「超时」：0 = 用 profile 的；
- profile「超时」：兜底值（默认 30 秒）。

实际生效的是**非零值里的最小值**。执行在事务里，超时会回滚。

## 批量执行（接口预留）

宿主服务提供 `TryExecuteBatch`（同一语句、多组参数、一个事务、全有或全无），
v1 的界面只暴露单次执行。需要在一条流程里批量写时，用多个「数据库写行」步骤，
或后续版本接入批量界面。

## 事务边界

一次调用 = 一个事务。**不存在跨步骤事务**：上一步的 COMMIT 不会被下一步回滚。
需要"要么全做要么全不做"的多条语句，请把它们合并成一条 SQL，
或使用批量接口。
