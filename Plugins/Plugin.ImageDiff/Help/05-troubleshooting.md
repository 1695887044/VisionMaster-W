# 图像差分 · 排错

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageDiff

按 **`ErrorMessage` 原文**查这一页。每一条都在代码里有对应分支，搜原文就能定位到行。

## 一、直接失败（`Success=false`，`ErrorMessage` 有原文）

### `基准图未连接（Reference 端口为空）。差分必须有一个基准：请先接「采图」或「读图」步骤的图，或接基准库步骤。`

原因：`Reference` 端口的 `ActualValue` 是 null。

排查顺序：
1. 看端口上有没有连线。没连线就接一条。
2. 有线但上游这一步本轮没出图（上游失败了）。**先修上游**——上游 `Success=false` 时下游拿到的就是空。
3. 上游是「读图」步骤但文件路径变了/文件被移走了。

### `被测图未连接（Test 端口为空）。`

同上，检查 `Test` 端口。

### `两图尺寸不一致：基准 {w1}×{h1}，被测 {w2}×{h2}。差分是逐像元运算，尺寸不一致必须先在前面把图对齐（用「模板匹配」做位姿对齐，或「标定」做几何校正）；本步骤不会替你静默缩放。`

这是**刻意的硬失败**，不是 bug。

差分对不上尺寸时，可选的坏做法有两种：静默把被测图缩放到基准尺寸（插值让边缘变软，细缺陷的差异强度被削掉、
而统计口径没人知道变了），或者静默裁到公共区域（丢掉的部分永远检不到）。
两者都会得到"看着有数、其实错"的结果，所以默认拒绝。

修法三条：
1. **尺寸本来就该一样**：查上游是不是有一步顺手改了尺寸（裁剪、缩放、镜像）。找出来去掉。
2. **两路相机分辨率不同**：换成同分辨率的相机，或在前级做一次标定重采样（`SizeMismatch` 保持 `Fail`）。
3. **确实只差整体缩放**：临时把 `SizeMismatch` 改成 `缩放被测图到参考图尺寸`，日志会 Warn 一句。
   这时插值误差已经进入测量，阈值要重新定。

### `两图尺寸不一致：…，公共区域只有 {w}×{h}，太小无法比较。`

`SizeMismatch = 裁到公共区域` 且公共区域小于 8×8。基本只有"其中一路图几乎全被裁光"才会出现——
回去查那一路的裁剪参数。

### `两图通道数不一致：基准 {c1} 通道，被测 {c2} 通道`

尺寸相同但通道数不同，且不是"1 通道 + ≥3 通道"这一对可灰度化的组合。

放行规则：`1 通道 ↔ ≥3 通道`（都转灰度后同域）。
其它组合（2 通道、4 通道对 1 通道等）不猜，直接拒绝——猜错的代价是静默错数。

修法：在前面用「预处理」把两边都统一成 1 或 3 通道。

### `图像差分判定 NG：{原因1}；{原因2}…`

判定 NG，不是执行失败。`Success` 会置 false，但差异图、面积、片数都**已经正常输出**。
原因串会列出所有超限项，例如：

```
图像差分判定 NG：总面积 1520 > 上限 1000；最大单片 800 > 上限 500
```

按列出的项逐条调：要么放宽上限，要么改善检测（见 04 页四段判读法）。

> 想**只测量不判定**：把 `MaxTotalArea`、`MaxComponentArea`、`MaxValueLimit` 三行都填 0。
> 这时永不 NG，判定交给下游「逻辑判断」。

## 二、不报错但结果不对（最难的一类）

这些情况下 `Success=true`、日志干净，但数不可信。按症状查：

| 症状 | 最可能的原因 | 确认方法 | 修法 |
| --- | --- | --- | --- |
| **永远 OK，差异恒为 0** | 两边接的是同一张图（基准与被测走了同一路） | 人为改一下工件再拍，看 `DiffArea` 变不变 | 检查 `Reference`/`Test` 的连线来源 |
| **整幅都 NG，图上差异区是轮廓重影** | 两张图没对齐（工件位置/角度变了） | 看 `OverlayImage`：差异是不是沿着工件轮廓走一圈 | 前面加「模板匹配」+ 仿射对齐 |
| **整幅偏亮/偏暗，差异均匀分布** | 两台相机曝光/增益不同，或换了光源 | 看 `DiffImage` 是不是一片均匀灰 | 基准图与被测图用同一套相机参数重采 |
| **片数几百上千，面积很小** | 阈值太低，把传感器噪声当差异 | `Threshold` 调到 60 看片数是否骤降 | 抬阈值；或前面加「中值滤波」 |
| **该抓的小瑕疵漏检** | 面积下限太大 | `MinArea` 设 1 看是否出现 | 降 `MinArea`；小件设 1~5 |
| **明显缺陷却报 OK** | 极性反了（缺陷方向被单向极性筛掉） | 把极性改回「双侧」再看 | 按缺陷方向选对极性 |
| **`MaxDiffValue` 老是顶到 200+，但面积是 0** | 它在测噪声（不受阈值影响），且 `MinArea` 把噪声片丢掉了 | 把 `MinArea` 设 1、`Threshold` 设 0，看最大单片面积 | `MaxValueLimit` 不要设太紧；或改用 `MaxComponentArea` 判 |
| **相对差下画面全白** | `AmbientFloor` 太小，暗区分母趋近 0 把噪声放大 | 看 `DiffImage` 是不是暗区最亮 | `AmbientFloor` 抬到 30~50 |
| **相对差下几乎无差异** | 从绝对差抄来的阈值（30 在相对差域＝30%） | 算一下：200 灰度处差 60 才命中 | 阈值降到 8~15 重新定 |
| **有符号差下差异全是"变亮"** | `SignedDisplay` 被调离 128 太远 | 看 `DyeImage` 中灰位置 | 恢复 128，单选极性用「极性」那行 |
| **改了基准图但结果没变** | 基准图存在上游步骤里，不是本步骤 | 看上游「读图」/基准库那一步存的路径 | 换上游的图；本步骤不存图 |
| **工件边缘一圈全被算成差异** | 边缘本就有亚像素抖动 | 看差异区是否贴着边缘 | 提 `MinArea`；或用 `MaskRegion` 把边缘外扩几像素屏蔽掉 |
| **同一配方换了工位就不灵** | 阈值/面积是跟着光照和分辨率定的 | 新工位重跑一遍四段判读法 | 不要跨工位复制参数 |

## 三、上屏相关的现象

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 窗口 1 上没有图 | `DisplayViewIndex = 0` | 设成 1~9 |
| 窗口 1 上是原图，没有青色区 | 本轮 `HasDiff=false` 且确实无差异（正常）；或所有差异被 `MinArea` 丢掉了 | 先把 `MinArea` 设 1 确认 |
| 图上有青色区但看不清细节 | 涂色盖住了缺陷明暗 | 看 `DiffImage`（差异强度图）而不是叠加图；叠加图只画 B 通道就是为了少糊细节，但深色缺陷仍会偏色 |
| 标题上的 NG/OK 与流程分支不一致 | 流程分支接的是 `Success`，而 `Success` 在执行异常时也是 false | 分支判定接 `HasDiff` 端口，语义更准 |

## 四、性能现象

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 单轮 100ms 以上 | 大图 + 上屏 | `DisplayViewIndex = 0`；下游不接 `OverlayImage` |
| 秒级 | 差异片数上千（连通域统计慢） | 提 `Threshold` / `MinArea` 把噪声片去掉 |
| 偶发卡顿 | 标注图生成（底图拷贝 + 涂色 + 合成） | 同上，关掉上屏 |

## 五、修改代码时容易踩的三个坑

写在这里是因为它们都在本插件的实现里踩过，改代码时别踩回去：

1. **不要在 byte 域做减法**。`SubImage` 在 byte 域会饱和截断（`0 − 30 = 0`），
   表现是"变暗的差异全没了，画面看着正常"。必须先 `convert_image_type` 到 `real`。
2. **不要用 `abs_diff_image` 的 5 参写法**。托管 API `HOperatorSet.AbsDiffImage` 只有
   **4 参重载** `(image1, image2, out result, mult)`，**没有 `add`**，与 `sub_image` 的 5 参不对称。
   写成 5 参会 `CS1501`。
3. **不要用形态学开运算代替面积筛选**。`opening` 用圆盘结构元会把细长划痕整条腐蚀掉，
   而划痕正是差分最常见的缺陷。本插件用的是 `select_shape('area','and',MinArea,∞)`。

另有两个契约细节：
- `InputPort<T>.Value` 是 `object?`（手动值弱类型入口），业务代码一律用 **`ActualValue`**。
- `DiffImage` 已交给输出端口，**不要在该轮 `finally` 里 Dispose**，下一轮的
  `AutoDisposeRoundOutputs` 会释放；提前释放会让端口上的图变野指针。
