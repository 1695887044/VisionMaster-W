# 图像差分 · 差分口径与调参

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageDiff

这一页回答三个问题：**"差异"到底怎么算的**、**阈值怎么定**、**现场最常见的四种检法怎么配**。

## 1. 三种算法的算式

设基准图灰度为 `R`，被测图灰度为 `T`（都先转成单通道）。

| 算法 | 算式 | 值域 | "一样"对应 |
| --- | --- | --- | --- |
| 绝对差 `Absolute` | `D = |T − R|` | 0~255 | `D = 0` |
| 有符号差 `Signed` | `D = T − R + SignedDisplay`，再夹到 0~255 | 0~255 | `D = SignedDisplay`（默认 128） |
| 相对差 `Relative` | `D = (T − R) / max(R, AmbientFloor) × 100` | 0~255（超出饱和） | `D = 0` |

**三者的计算都在 real 域做，最后才转回 byte。** 这一点是硬性的：
byte 域直接相减会饱和截断——`0 − 30` 在 byte 域得 0 而不是 −30，
结果是"变暗的差异全被吃掉"，画面看起来正常、数据全错。这是本插件实现里最要紧的一条不变量。

### 极性与算法的组合

极性先在**两个方向的分量**上生效，再进算式：

```
pos = T − R（变亮分量，real 域，负值保留）
neg = R − T（变暗分量，real 域，负值保留）

Polarity = Both     → 取 max(pos, neg)     （等效 |T − R|）
Polarity = Brighter → 取 pos               （只留变亮，变暗处得 0）
Polarity = Darker   → 取 neg               （只留变暗，变亮处得 0）
```

然后：
- `Absolute`：把上面选出的分量直接转 byte。
- `Relative`：把上面选出的分量 ÷ `max(R, floor)` × 100 再转 byte。
- `Signed`：**极性照样生效**，然后 `pos − neg + 零点`。也就是说 `Signed + Both` 是真正的双向有符号差
  （变亮在中灰以上、变暗在中灰以下）；`Signed + Brighter` 会得到"只有中灰以上的部分"，
  `Signed + Darker` 会得到"只有中灰以下的部分"（变暗量取负号，不是把幅度加到中灰上方）。

> 一开始别碰 `Signed + Brighter` 这种组合。要么用 `Absolute` 配极性，要么用 `Signed` 配 `Both` 看双向。

## 2. 阈值怎么定：四段判读法

不要凭感觉填。按这四步走，每一步都有可见的数：

### 第一段：良品 vs 良品（噪声地板）

拿两张**不同良品**的图做差分，`Threshold` 先设 0，看 `MaxDiffValue` 和 `DiffCount`。
记下良品之间的最大差异强度 `N`（噪声地板）和片数。

### 第二段：良品 vs 典型不良（信号峰）

拿良品 vs 一个**典型的、最轻微的不良品**做差分，记下 `MaxDiffValue`（信号峰 `S`）。
如果 `S < N`，说明这个算法/极性根本分不开它们——**换算法**，别调阈值。

### 第三段：定阈值

`Threshold = N + (S − N) × 0.4`，然后回良品集上验 30 件：
要求良品全部 `HasDiff = false`（在判定上限都填好的前提下）。

判据：**信号峰 / 噪声地板 ≥ 2** 才值得继续调；低于 2 的项目，靠阈值调出来的一定会漏检或误报。

### 第四段：定面积下限

`MinArea` 从 1 起，逐步抬高，直到良品集上的 `DiffCount` 稳定在 0~1 片。
这时 `MinArea` 就是"噪声片的最小面积 × 2"。

> 为什么不用固定值：不同视野、不同噪声水平差一个量级。20 只是给个能跑起来的默认。

## 3. 耗时：只有面积和层数，没有超时参数

单轮耗时近似正比于 **像素总数 × 常数**：

```
t ≈ W × H × (转灰度 + 一次减法 + 阈值 + 连通域 + 面积统计)
```

- 转灰度：3 通道图才有，约占总耗时 15%。
- 连通域 `connection` + `select_shape`：**差异片数越多越慢**，几百片以上会明显起来。
- 上屏：`DisplayViewIndex = 0` 可省掉整张标注图的生成（底图拷贝 + 涂色 + 合成），
  500 万像素以上建议生产时设 0。

没有可调的"速度参数"——想快只有三条路：减小输入图尺寸（先裁剪到工件区域）、关掉 `OverlayImage`
的消费（下游不接就省一次 `Compose3` 以外的拷贝）、把 `DisplayViewIndex` 设 0。

## 4. 四个配方

### 配方 A：丝印漏印（白底黑字，缺字/漏笔画）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 算法 | 绝对差 | 漏印处变亮，缺笔画处也变亮，但可能有墨点变暗，双侧更稳 |
| 极性 | 双侧 | 墨点脏污计入，交给面积上限判 |
| 聚合方式 | 连通域 | 要数"漏了几处" |
| 阈值 | 40~60 | 黑白对比强，可以设得比较高 |
| 面积下限 | 30~80 | 一个笔画断点通常几百像素，噪点几十 |
| 单片面积上限 | 300~800 | 断一笔就 NG |

要点：**先做几何对齐**。丝印件位置差 1 px，整条笔画轮廓都会"差"，差异区呈毛笔描边状。
不对齐的话，靠抬阈值压掉描边，会把真漏笔画的信号也一起压掉。

### 配方 B：装配缺件（治具里少了垫片/少装一个螺丝）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 算法 | 绝对差 | 缺件处露出背景，明暗差大 |
| 极性 | 只算变暗 | 缺件＝原来该亮的金属位变暗；反过来"多装"才是变亮，通常另有工序 |
| 聚合方式 | 连通域 | 数"缺了几件" |
| 阈值 | 30~50 | 金属反光不稳的话要往下压并配合相对差 |
| 面积下限 | 200 | 缺件是大块，噪点不会到这个量级 |
| 单片面积上限 | 0（不判） | 由片数判，不靠面积 |

要点：**多装要单独配一个步骤**。缺件和多余件方向相反，一个单极性的步骤只能抓一边；
要两边都抓就用「双侧」+ 两个不同的面积上限（本步骤只支持一组上限，另一组放到下游逻辑里判）。

### 配方 C：脏污/异物（不允许出现任何新增）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 算法 | 绝对差 | 脏污可能是亮的（白屑）也可能是暗的（黑点） |
| 极性 | 双侧 | 同上 |
| 聚合方式 | 连通域 | 数"有几处" |
| 阈值 | 25~40 | 要抓细小的 |
| 面积下限 | 5~15 | 小到 5 像素的异物也要抓 |
| 总面积上限 | 按工艺填 | 累计脏污有规格时 |
| 最大强度上限 | **0（不判）** | `MinArea` 很小时 `MaxDiffValue` 基本在测噪声，见 03 页 |

要点：这一档最容易误报。务必先用**良品集 50 件以上**验误报率，再定 `MinArea`；
靠"阈值往上抬"压误报会先漏掉半透明的脏污。

### 配方 D：包装缺件/漏放（整盒里面少了说明书/多了一个）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 算法 | 相对差 | 不同盒之间底色可能有差，相对差抗整体漂移 |
| 环境亮度下限 | 30 | 盒内阴影区亮度低，分母下限必须抬，否则噪声被放大 |
| 极性 | 双侧 | 少了是变亮（露出白盒底）、多了是变暗 |
| 聚合方式 | 总面积 | 关心"整盒累计变了多少" |
| 阈值 | 20~30 | 相对差域下 30 表示 30%，已经很高 |
| 面积下限 | 100 | 说明书是整块 |
| 总面积上限 | 2000~5000 | 按规格定 |

要点：相对差下阈值语义完全变了，**从配方 C 抄过来的 30 不能直接用**——算一下：
`30%` 的相对差意味着一个 200 灰度的位置要差 60 个灰度才算数。

## 5. 什么时候不该用差分

差分是"有基准就能比"的暴力办法，但下面这些情况它会失效，硬上只会得到难维护的方案：

| 情况 | 为什么失效 | 替代 |
| --- | --- | --- |
| 工件位置/角度每次都变，且没有可靠特征做对齐 | 两张图错位，差异＝轮廓重影 | 先上「模板匹配」出位姿，仿射变换后再差分；或者直接在匹配里判分 |
| 基准件本身有正常变异（织物纹理、天然材质） | 良品之间差异就很大，信号被噪声淹没 | 用「Blob」按形状/灰度筛，或改用深度学习分类/分割 |
| 缺陷是"形变"而不是"明暗变化"（弯曲、缩水） | 形变会让整片轮廓变，方向性强 | 用「卡尺」量尺寸 + 公差判定 |
| 需要识别"是什么缺陷"而不只是"有没有" | 差分只给"不一样"，不给类别 | 用「分类」插件，或裁出差异区再送分类 |
| 光源会整体变化且变化不均匀（有方向性暗角） | 相对差只能抵整体乘性漂移 | 先做一次平场校正（「预处理」的算术运算 ÷ 参考白片），再差分 |

## 6. 与「预处理」算术算子组的分工

现场常问"这两个不是一回事吗"。分工只有一句：

- **差分要两张图**（基准 + 被测），输出"哪里不一样"——**就是本插件**。
- **算术算子要一张图 + 一个常数**（加/减/乘增益/转 real/归一化），输出"这张图变亮/变暗/拉伸后长什么样"
  ——在「图像预处理」的**算术运算**算子组里。

为什么不能把差分做成预处理的算子：预处理的链内算子（`OperatorStepItem`）只有
`OperatorKey` + `Enabled` + 字符串参数字典，**结构上拿不到第二张图**。
所以凡是"图 × 图"的运算只能做成独立步骤，本插件就是为此而生的。

反过来，如果只是"整幅图减去 30 再做阈值"，用「预处理」的「灰度减常数」更轻——不需要基准图。
