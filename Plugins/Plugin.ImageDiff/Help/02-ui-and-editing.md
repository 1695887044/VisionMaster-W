# 图像差分 · 界面与操作

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageDiff

本插件**没有专属配置视图**，全部参数走宿主的通用属性面板（`FlatPropertyGrid`）。
属性按 `[StepConfig]` 声明顺序排列，中文名与说明取自属性上的 `[Display]`。
所以"界面"这一页讲的其实是**属性面板每一行是什么、改了会怎样、改完怎么确认**。

## 参数分组一览

属性面板里从上到下 12 行，按作用分四组看：

| 组 | 行 | 作用 |
| --- | --- | --- |
| 算法口径 | 算法、极性、聚合方式、尺寸不一致处理 | 决定"差异"怎么定义 |
| 灵敏度 | 差异阈值、面积下限、环境亮度下限、有符号显示零点 | 决定"多小算不一样" |
| 判定上限 | 总面积上限、单片面积上限、最大强度上限 | 决定"多少算 NG" |
| 显示 | 结果上屏窗口 | 决定推不推图、推到哪 |

前两组改任何一项都会改变测量值，**改完必须回看一遍 DiffArea/MaxDiffValue 的数**；
后两组只影响判定与显示，不改测量。

## 算法口径四行

### 算法

下拉三选一：`绝对差（|被测 − 基准|）` / `有符号差（被测 − 基准）` / `相对差（按参考图亮度归一化）`。

- 从绝对差换到有符号差：**0 点从"完全一样"变成"128 中灰"**。原来的阈值 30 现在表示"偏离中灰 30"，
  语义完全不同，必须重调。
- 从绝对差换到相对差：数值域变成百分比，阈值 30 现在表示"差 30%"——对高对比区极敏感、对阴影区极迟钝。
  同样必须重调。
- 日志里会写明当前算法，PublishPreview 的信息栏也有「算法」一行，对不上就是选错了。

### 极性

下拉三选一：`双侧（变亮变暗都算）` / `只算变亮（被测比参考亮）` / `只算变暗（被测比参考暗）`。

- 双侧是默认，对应"有没有脏污/有没有缺件"这类不分方向的检测。
- **只算变亮**典型场景：白底的黑字丝印**漏印**（该黑的地方变白＝变亮）。
- **只算变暗**典型场景：金属表面**新增暗斑/氧化/凹坑**。
- 极性单向时，反方向的差异会被整片丢弃——如果明明有缺陷却报 OK，先查这一行。

### 聚合方式

- `连通域（按片统计）`（默认）：差异区按 8 连通拆成一片片，`DiffCount` 是片数，`MaxDiffComponentArea` 是最大那片。
- `总面积（不分片）`：不拆，只给总面积，`DiffCount` 退化成 0 或 1。

**要数"有几处"就必须用连通域口径**。反之，如果关心的是"整幅累计脏了多少"而不关心分成几块
（比如全屏灰尘），总面积口径更稳——不会因为两片脏污挨在一起就少算一次。

### 尺寸不一致处理

两图尺寸不同时的策略，三选一：`硬失败（推荐）` / `缩放被测图到参考图尺寸` / `裁到公共区域`。

- **硬失败是默认，也是唯一不产生静默错数的选项**。它会在 `ErrorMessage` 里写清两边的尺寸，并提示先用
  「模板匹配」做位姿对齐或「标定」做几何校正。
- 缩放：用 `zoom_image_size` + 双线性插值，只适用于"两图只差整体缩放"的场合，日志会 Warn 一句。
  插值会让边缘变软，细线缺陷的差异强度会被削掉一部分。
- 裁到公共区域：取 `min(宽) × min(高)` 的左上角区域，不做插值。只适用于"两张图都是同一相机的整幅输出，
  只是某一路被裁过"的场合；公共区域小于 8×8 会直接失败。

> 通道数不同但尺寸相同时：`1 通道 + ≥3 通道` 这一对是放行的（都转灰度后同域），
> 其它组合（如 2 通道）会在转灰度时直接失败并说明原因。

## 灵敏度四行

### 差异阈值（0~255，默认 30）

`Threshold` 之后的像元才算"不一样"。它是**唯一的灵敏度总闸**。

调法见 04 页「四段判读法」。改这一行时注意：阈值下降会同时抬高片数、总面积、最大单片三个数，
所以调完要一起看；只看总面积容易误判"变好了"。

### 面积下限（像素，默认 20）

单片差异小于它就被整片丢弃。等价于 `select_shape('area', 'and', MinArea, +∞)`——
用的是**按面积筛连通域**，不是形态学开运算，所以**细长划痕不会被腐蚀掉**（这是刻意选的：
划痕恰好是差分最常见的缺陷形态）。

- 小件（视野内工件 < 200×200 px）：设 1~5。
- 大件（全视野 2000 万像素）：设 20~100，否则噪声片数上百。

### 环境亮度下限（默认 8.0，仅相对差生效）

相对差的分母是 `max(基准图灰度, AmbientFloor)`。参考图接近全黑的地方，若不加下限，
分母趋近 0 会把传感器噪声放大成满幅 255，画面全是"差异"。

- 光照良好的场合：8~15 就够。
- 暗场/红外/低照度：抬到 30~50。
- **别的算法下这一行完全无效**，改了不会有任何变化——别在这里找问题。

### 有符号显示零点（0~255，默认 128，仅有符号差生效）

有符号差是 `被测 − 基准 + SignedDisplay` 再转 byte。默认 128 表示"一样"落在中灰。
把它调到 200，就等于只保留"变暗"的差异（变亮部分被压到 255 以上饱和），是一种偷懒的单向化；
正式做法还是用「极性」那一行。

## 判定上限三行

| 行 | 默认 | 语义 | 提示 |
| --- | --- | --- | --- |
| 总面积上限 | 0 | `DiffArea > 上限` → NG | 0 = 不判 |
| 单片面积上限 | 0 | `MaxDiffComponentArea > 上限` → NG | 0 = 不判；最常用的一项 |
| 最大强度上限 | 0 | `MaxDiffValue > 上限` → NG | 0 = 不判；对"深划痕"敏感 |

三项**全部是严格大于**才 NG（等于上限算合格）。
任一超限即 `HasDiff=true` 并 `Fail`，`ErrorMessage` 里会把所有超限项用「；」拼在一起，例如：

```
图像差分判定 NG：总面积 1520 > 上限 1000；最大单片 800 > 上限 500
```

**三行都填 0 时永不判 NG**——`Success` 保持 true，判定交给下游「逻辑判断」。

## 显示行

### 结果上屏窗口（0~9，默认 1）

- `1~9`：把标注图推到对应序号的图像窗口。
- `0`：不推。跑批/生产时建议设 0 省渲染开销；调试时保持 1。

上屏用 `PublishPreview(image, viewIndex, title, info, null)`，标题是 `OK/NG 差异 {面积} px / {片数} 片`，
信息栏六行：算法、阈值、差异片数、差异总面积、最大单片、最大强度。

## 怎么确认改对了

改参数后按这个顺序确认，全部在属性面板与上屏图上完成，不用写脚本：

1. **先看 `Success`**：红了先看 `ErrorMessage` 原文，按 05 页对照。
2. **再看差异图是不是"该亮的亮"**：窗口 1 上蓝色区应该正好盖住缺陷，不该有整幅的轮廓重影
   （有重影 = 两图没对齐）或满屏细碎点（= 阈值太低）。
3. **最后看三个数**：`DiffCount`、`DiffArea`、`MaxDiffValue` 与上一版配置比，
   只允许"往期望方向动"；同时动方向不对，说明改的不是你以为的那一项。

> 有一条容易踩：改「算法」「极性」「聚合方式」这三行**都不需要重新学习任何东西**，
> 但会让历史数据不可比。同一个配方在产线上跑过之后，这三行改了就等于换了个检测项，
> 要重新出新旧对照，不能只看"这次的数比上次小"就认为改进有效。
