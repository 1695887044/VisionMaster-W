# 图像差分 · 快速上手

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageDiff

把「被测图」和「基准图」逐像元相减，按阈值把**不一样的像素**挑出来，拆成一片片连通域 →
数片数、量总面积、取最大单片和最大差异强度 → 与上限比对给出 **OK/NG**，同时叠一张青色标注图。
它回答的是"**这张图和标准件比，哪里不一样、差多少、超没超限**"——
丝印偏移、漏印、脏污新增、装配有无、包装缺件这类"有/没有、多/少、偏/正"的检测，一次差分就出结论。

工具库里的名字是「图像差分」，分组在**图像处理**。

## 一轮差分产出什么

```
输入：基准图（Reference，必接）
      被测图（Test，必接）
      屏蔽区（MaskRegion，可选）

      │
      ├─▶ DiffImage            差异强度图（单通道 byte）：0 = 一样，越大越不一样
      ├─▶ OverlayImage         标注图：基准图 + 差异区青色涂色
      ├─▶ DiffCount            差异片数（连通域个数；总面积口径下是 0 或 1）
      ├─▶ DiffArea             差异总面积（像素）
      ├─▶ MaxDiffComponentArea 最大单片差异面积（像素）
      ├─▶ MaxDiffValue         最大差异强度（0~255）
      ├─▶ HasDiff              是否判定为有差异（NG）
      └─▶ Success / ErrorMessage  执行成功与否；NG 时原因写在 ErrorMessage
```

## 五步配出第一张图

### 第一步：接两张图

- **Reference（基准图）**：接「标准件那张图」。三种常见来源：
  1. 「采图」步骤拍下的**良品图**，存到「数据记录」或直接串一个「读图」步骤；
  2. 上一个「预处理」步骤的输出（先做一次几何对齐、转灰度都行）；
  3. 基准库步骤（若有）读出的基准图。
- **Test（被测图）**：接当前这一拍的实拍图，一般就是相机直出。

> **两张图必须尺寸一致**。尺寸不一致默认直接失败——这是刻意的，见第五节。

### 第二步：确认尺寸与对齐

差分是**逐像元运算**：第 (r, c) 个像素只和第 (r, c) 个像素比。
所以两张图不但要同尺寸，还要**同一个物理位置对齐到同一像素**。如果工件会晃、会被夹具顶偏，
在差分**前面**插一个「模板匹配」，用匹配出的位姿把被测图仿射变换到基准件的位置上，再喂给本步骤。

不做的后果：整幅图都"有差异"，NG 满屏，但看图能看出是错位而不是缺陷。

### 第三步：选算法

| 算法 | 什么时候用 | 一句话 |
| --- | --- | --- |
| **绝对差**（默认） | 99% 的场合 | `|被测 − 基准|`，只关心"差多少"，不关心谁亮谁暗 |
| 有符号差 | 需要区分"变亮"还是"变暗" | `被测 − 基准`，中灰 128 为 0，上方是变亮、下方是变暗 |
| 相对差 | 同一批件整体亮度会漂（光源老化、反光变化） | `(被测 − 基准) / max(基准, AmbientFloor) × 100`，按亮度百分比算，抗整体漂移 |

**先用绝对差**。只有当"良品之间本身灰度就差得多"（比如磨砂表面、织纹）时才换相对差；
只有当"变亮和变暗的严重程度不能一视同仁"时才用有符号差。

### 第四步：调阈值

`Threshold` 默认 30（0~255 尺度，即只看超过 12% 灰度差的变化）。
调法：把良品图当被测图跑一遍（左右都是良品），差异强度应该全是噪声——
如果噪声峰值到 40，就把阈值设到 50；再看真缺陷的差异强度，要留出 2 倍以上余量。

`MinArea` 默认 20 像素：单片小于 20 像素的差异当噪点丢掉。小件检测要把这个降下来（甚至设 1），
大件检测要往上抬。

### 第五步：设判定上限（可选）

三项上限**互相独立**，任一超限即 NG；填 0 表示该项不参与判定：

| 参数 | 默认 | 什么时候填 |
| --- | --- | --- |
| `MaxTotalArea` | 0（不判） | "整幅图累计脏了多少像素"有规格时 |
| `MaxComponentArea` | 0（不判） | "单块脏污不能超过多大"有规格时（最常用） |
| `MaxValueLimit` | 0（不判） | "最深的那一下不能超过多少灰度"有规格时 |

三项都填 0 时，本步骤只输出测量值（DiffArea / MaxDiffValue 等）**永不判 NG**——
判定交给下游的「逻辑判断」步骤。这是推荐的第一版做法：先只看数，跑够 50 件再定上限。

## 接线图

```
[采图] ──Image──▶ [图像差分].Test ──OverlayImage──▶ [结果展示]
[读图/基准] ─────▶ [图像差分].Reference
[预处理/裁剪] ───▶ [图像差分].MaskRegion（可选）
                        │
                        ├──HasDiff──▶ [逻辑判断]（或直接接流程分支）
                        ├──DiffArea──▶ [结果上传]
                        └──MaxDiffValue──▶ [数据记录]
```

## 上屏图怎么看

`DisplayViewIndex` 默认 1，即把标注图推到窗口 1。图上是**基准图打底**，差异区涂成**青色**
（B 通道拉满，红绿不动）——不压红绿是为了不把缺陷本身的明暗细节糊掉。
标题横幅写 `OK/NG 差异 {总面积} px / {片数} 片`，右上角信息栏带算法、阈值、片数、总面积、最大单片、最大强度。
设 0 则不上屏（跑批时省渲染开销）。

## 这个插件不做什么

- **不做图像对齐**。两张图错位时它只会告诉你"整幅都不一样"，不会自己找位姿——那是「模板匹配」的活。
- **不做几何校正/去畸变**。基准和被测都得是同一坐标系下的原始像素图；标定域的事在「标定」和「预处理」里做。
- **不做"图像 ÷ 图像"这类逐像元乘法除法**。逐像元的常数算术（加/减/乘增益/归一化）在「图像预处理」的
  算术运算算子组里；本插件只做减法意义下的差异。

## 常见误用

| 写法 | 后果 | 正确做法 |
| --- | --- | --- |
| 基准图和被测图来自不同曝光/不同增益的相机设置 | 整幅偏亮偏暗，全是差异 | 基准图和被测图用同一套相机参数采集 |
| 工件第一张图当基准，工件位置每次都偏一点 | 每片都 NG，且差异区呈"轮廓重影" | 前面加模板匹配对齐，或接受"位置也纳入检测"（换用相对差 + 大阈值） |
| 拿基准图和自己比（同一张图接两路） | 差异恒为 0，永远 OK，看着很稳 | 这是自检手段，不能当产线配置 |
| 阈值设到 5 以下 | 传感器噪声全部命中，片数几百上千 | 阈值下限从 15 起调；噪声大的场合先做一次「中值滤波」 |
