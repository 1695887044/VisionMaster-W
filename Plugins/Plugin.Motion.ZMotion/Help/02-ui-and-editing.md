# 界面与编辑：卡配置、轴映射与调试读观

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.ZMotion

参数**填什么**在《卡参数与轴参数》那一页；这一页只讲**在哪个控件上填、点了会怎样、
界面上那行字是谁写的**。界面本体在宿主侧（`VisionMaster\Views\DialogViews\MotionBoardView.xaml`
及其 设置/调试 两个页签），本插件不提供任何自定义视图 —— 它只提供一个 `IMotionDevice` 实现。

## 窗口的骨架

| 区 | 内容 | 数据来源 |
| --- | --- | --- |
| 左侧卡列表 | 方案里的每一张卡一行 | `SolutionModel.MotionCards`（即 `MotionDescriptor` 列表） |
| 页签 | 设置 / 调试 / 凸轮 | 三个页签各自的 ViewModel |
| 未选卡时 | 「请在左侧选择一张运动卡」 | 视图占位文字 |
| 窗口最小高 | 680 | 刻意钉住的值（默认尺寸下页签内容会显示不全） |

顶部一行摘要：卡标题、连接状态文字（`已连接` / `未连接`）、驱动名、机型、状态说明。
卡标题的回退顺序是 **显示名 → 地址 → `(未命名运动卡)`**（`MotionDescriptor.Caption`），
所以卡名为空时界面显示的是 IP，但**流程里按卡名寻址用的还是本体**（空的还是空的）。
状态说明那一行来自驱动的 `StateDetail`，是自由文本 —— 排障时它是第一现场，见《排障》。

## 设置页签

### 顶部四个动作

| 按钮 | 做什么 | 注意 |
| --- | --- | --- |
| 属性 | 改设备标识（卡名 / 地址 / 机型 / 备注） | 老问题"新增时能填、加完就没入口"已补，改名走这里 |
| 清除报警 | 立即下一条 `ClearAlarm` 命令 | 报警态下这是唯一该放行的动作；成功后卡回「在线」，**不会自动使能** |
| 连接 / 断开 | 按钮文字随状态翻转 | 连接是幂等的：状态不是"未连接"时点连接不会真的重连，所以恢复动作一律先断开再连接 |
| 删除 | 删掉这张卡的配置 | 走外壳的模态确认遮罩 |

### 设备标识区

一行提示写着「设备名可留空：留空则显示地址」。卡名参与流程寻址，建议**非空、无首尾空格、全方案唯一**：
两张卡同名时，IO 这类卡级步骤按卡名只命中其中一张，启动体检会把"卡名重复"写进日志点名。

### 运动参数区（标注"影响本卡所有轴"）

逐项输入框：默认速度 (mm/s)、默认加速度 (mm/s²)、命令超时 (ms)、状态轮询周期 (ms)、看门狗超时 (ms)，
下面一条「随方案启动自动连接」勾选框，再下面一行说明：
轮询周期决定报警/限位多久被发现（越小越灵敏，但网口卡通信压力越大）；看门狗超时后卡会被判定失联并安全停机。

改完**不会自动生效**，要按页面底部那条提示点「应用参数与轴映射」
（原文：改完参数或轴映射后，点这里统一保存并生效）。

### 轴映射表

表头标注：流程按「逻辑名」引用轴 · 脉冲当量与软限位按机械标定填写。行内六列：

| 列 | 提交时机 | 备注 |
| --- | --- | --- |
| 逻辑名 | 失焦 | 最长 32 字符；不允许包含凸轮分隔符 |
| 物理轴号 | 失焦 | 0 基；同一张卡内不许重复 |
| 脉冲当量/毫米 | 输入即提交 | 连接时下发给 `SetUnits`，**改完要重连** |
| 软限位下限(mm) / 上限(mm) | 输入即提交 | 只校验绝对运动 |
| 启用 | 勾选 | 关掉 = 不进流程下拉候选、不被轮询、不被"停全部轴/清报警"遍历 |

没连卡时表里也会先铺 4 行（`MotionAxisValidator.MinimumAxisRows`），
否则用户在连接之前根本找不到"脉冲当量填在哪儿"；连上之后按机型能力补齐到实际轴数。
表为空时提示原文：还没有轴映射，点下方「添加轴」。

行内校验的文案会直接弹在界面上（原因来自 `MotionAxisValidator`，逐字）：

- `逻辑轴名不能为空（流程与点位表都按它引用）`
- `逻辑轴名不能超过 32 个字符`
- `逻辑轴名不能包含「·」（凸轮轴标签用它做分隔）`
- `逻辑轴名「X」在本卡已存在（重名会让流程按名寻址变成随机命中）`
- `物理轴号不能为负（卡内轴号是 0 基）`
- `物理轴号 0 已被轴「X」占用（两根轴指向同一个物理轴会互相打架）`

改逻辑轴名必须走界面上的重命名入口：点位表以轴名为外键，直接改字符串会让该轴已教好的点位变成孤儿。

### 轴配置弹窗（低频七个字段）

编码器类型、每毫米脉冲数、驱动器型号、额定电流、跟随误差上/下限、轴备注。
**这一组只随方案存档，驱动不下发到卡**，界面上的空值回退口径（增量编码器 / 1000 / 候选第一项 / 5 / ±5000）
只是显示用。别以为在这里填了跟随误差上限，驱动器就会按它报警。

## 调试页签（读观与手动操作）

轴列表按轴逐行列出（位置与状态并排），不是一张卡的整体状态。每行的状态标签取值只有这几种：
`映射停用` / `报警` / `限位` / `正在{模式}运行中`（呼吸动画）/ `已使能·已回零` / `已使能` / `未使能` / `未连接`。
连接着但还没回零时，顶部那条橙色提示常显。

| 区 | 控件 | 行为 |
| --- | --- | --- |
| 控制 | 使能 / 失能 / 停止全部 | 与流程步骤走同一条命令队列 |
| 定位 | 目标输入 + 取当前位置 + 定位 / 定位并等待 | 「取当前位置」是对位时最常用的起点 |
| 点动 | 正 / 负 两个按钮，**按住才动、松手即停** | 三条路径都收：按下、松开、失焦；另有 500 ms 心跳兜底 |
| 回零 | 方式下拉 + 开始回零（执行中显示「回零中…」） | 未连接时列契约全集 8 种，连接后按能力收窄；下拉显示中文 |
| IO | IN 只读监视、OUT 点击翻转 | 未连接时按 8 路铺出占位，免得界面空白 |
| 急停 | 独立红色按钮 | 不藏在子菜单里；清空待执行队列 + 插队立即停全部轴 |

点动速度填 0 = 使用卡内默认速度。关窗时页签会停掉点动、并撤掉本面板发起且尚未结束的命令
（回零最长能跑 120 秒，窗口关了命令还在队列里执行是不能接受的）。

手动路径上的闸门在页签层先判一遍，文案与流程侧同源：
`运动卡未连接`、`请先在左侧选择一根轴`、`目标坐标不是有效数字`、
`X 目标 N mm 超出软限位（min ~ max mm）`、`X 未使能，请先伺服使能`、`X 需要回零后才能运动`、
`X 正在{模式}，请等待完成`、`该卡未上报点动能力，请改用「定位」逐点对位`。
点动时若轴正在运动，是**静默忽略**（按住期间界面会重复脉冲，弹提示会刷屏）。

## 常见问题

**Q：轴名改了，流程里那个下拉还是旧的。**
候选项每次打开属性面板时现取，取值来自**全局轴注册表**而不是各卡映射表的并集；
被重名影子化的那些轴刻意不列出来（列了就是递给用户一个"选了必然失败"的选项）。
启动日志里的轴映射体检会点名是谁和谁冲突。

**Q：点位表在哪里？**
在「运动卡设置」里按轴展开，每轴固定 16 行 P0–P15，不可增删 ——
固定行数是为了让"第 3 个点位"在现场口头沟通里有稳定指代。

**Q：凸轮页签在这张卡上能用吗？**
凸轮表是**全局实体**（不挂卡、删卡不动它），随方案单独落盘；
本驱动上报的能力是**不支持直线/圆弧插补**，运动命令契约里也没有凸轮命令，
所以正运动这边没有对应的下发出口。节拍要求高的同步场合要改用卡内联动或硬件同步。
