# 正运动 ZMotion 运动卡

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.ZMotion

正运动控制器（**网口 Ether 直连**）的真机驱动：把统一的运动命令契约翻成 `ZAux_*` API，
把卡上的状态字翻成统一的轴状态快照。它不是流程里的算子 —— 它出现在「系统 → 运动卡设置」的驱动列表里，
流程中的七个运动步骤（轴使能 / 轴回零 / 轴运动 / 等待到位 / 读轴状态 / 轴卡 IO / 轴停止）按原名在它上面跑。

本页讲**卡参数与轴参数**：每一项配什么、下发到什么、哪几项其实还没被驱动吃进去。
连接不上怎么排查见「连接与排障」，与流程步骤怎么配合见「与步骤算子的配合」。

## 为什么需要它 / 原理

- **连接做四件事**（顺序固定，都在锁外执行，因为建链可能要几百毫秒到几秒）：
  ① `ZAux_OpenEth(地址)` 建句柄；② `ZAux_GetControllerInfo` 读机型与固件版本、据此定能力表；
  ③ **逐启用轴下发 `SetUnits`（脉冲当量）**；④ 上报能力表（轴数 / IO 点数 / 支持的 IO 与回零方式）并把
  "已连接 机型 @ IP（固件 …）｜N 轴｜IO X 入 / Y 出"写进状态说明。
- **状态轮询**（一条独立线程，节拍 = 卡级 `PollIntervalMs`）：逐个**已启用**轴读
  `GetAxisStatus`（状态位域）、`GetIfIdle`（忙/闲）、`GetMpos`（指令位置）、`GetAxisEnable`（使能），
  再用 `GetInMulti(0, 点数-1)` **一次批量读全部数字输入**。
  批量读的理由：10 ms 周期下逐点问 24 个点 = 每周期 24 次往返，网口卡会被自己打满。
- **命令执行**（一条独立线程，逐条按队列执行）：使能/失能、绝对/相对定位、点动、回零、停止、写输出、清报警，
  各自的 API 映射见下面的对照表。
- **读不到状态就抛异常**，交给基类累计"轮询失败次数"；连续失败或超过看门狗时长即判失联并安全停机。
  把异常吞掉会变成"轴状态一直不变"，那是最危险的静默故障。
- **只遍历"已启用"的轴**：所有对轴的遍历（轮询、清报警、停全部轴）都过滤 `Enabled`，
  避免"操作到用户明确关掉的轴"。

## 在「系统 → 运动卡设置」里怎么配

| 项 | 必填 | 说明 |
| --- | --- | --- |
| 驱动类型 | 是 | 选「正运动 ZMotion 运动卡」。列表来自宿主扫描 `Modules\` 里实现 `IMotionDevice` 且带 `[Display]` 的类型 |
| 卡名 | 是 | 流程里**卡级操作**（「轴卡 IO」的 `Card` 端口）按卡名寻址；同一方案里请唯一 |
| 地址（IP） | **是** | 控制器的 IP，如 `192.168.0.11`。留空直接连不上：状态说明给 `未填写控制器 IP 地址`。**这是全流程里唯一出现 IP 的地方** —— 步骤只填轴名/卡名，换网段只改这里 |
| 机型 | 建议填 | 如 `ECI3428` / `ECI3828` / `ZMC408SCAN` / `VPLC532R`。留空时用控制器自报的 SoftType 识别；**都认不出时按兜底值处理并写告警**，见下表 |
| 显示名 / 备注 | 否 | 只给人看，不参与寻址 |
| 自动连接 | 否 | 勾选后宿主在方案加载/启动时自动连接本卡 |
| 轴映射 | 是 | 见下面「轴映射参数」 |
| 卡级参数 | 否 | 见「卡级参数」 |

## 机型与能力（决定能操作几根轴、几个点）

机型名**按前缀匹配**（控制器自报的 SoftType 可能带后缀，如 `ECI3428_V2` 也能命中 `ECI3428`），
配置里填的机型**优先于**控制器上报的：

| 机型 | 轴数 | 输入 | 输出 | 类型 | IO 点数是否核实 |
| --- | --- | --- | --- | --- | --- |
| `ECI3428` | 4 | 24 | 16 | EtherCAT 总线型 | 已核实 |
| `ECI3828` | 8 | 24 | 20 | EtherCAT 总线型 | 已核实 |
| `ZMC408SCAN` | 4 | 24 | 20 | EtherCAT 总线型 | 已核实 |
| `VPLC532R`（虚拟 PLC，RTSys 仿真器同属此类） | 32 | 24 | 16 | 总线型 | **未核实**（虚 PLC 的点位取决于组态） |
| 认不出（含留空且自报名不匹配） | **4** | **24** | **16** | 按总线型 | 未核实（兜底值就是猜的，如实标记） |

- **兜底刻意取"常见的最小配置"（4 轴）**：能力报小的后果是"某些轴不能操作"（可见、可改），
  报大的后果是"对着不存在的轴下发命令"（不可见，真机上表现为莫名其妙的失败）。
- **未识别机型会在日志里明说**：`未识别机型「…」，本次按 4 轴 / 24 入 / 16 出 处理。请在「运动卡设置」的机型栏填写准确型号…`。
  买了 8 轴卡却看到这条，就把机型栏填准，否则第 5~8 根轴配了也用不了。
- **IO 点数标为"未核实"时，状态说明里会带着这句话**（`…｜IO 24 入 / 16 出（点数未核实，按显示上限列出）`）：
  列多了只是"点一下会失败"，列少了会让用户以为某个输出坏了 —— 所以界面选择说实话，实物点数以接线为准。
- **总线型 / 脉冲型的差别只在回零**：总线型走 `ZAux_BusCmd_Datum` + `GetHomeStatus==1` 判完成，支持**全部 8 种**回零方式；
  脉冲型走 `ZAux_Direct_Single_Datum` + "轴空闲"判完成，只上报 3 种（负限位+Index / 正限位+Index / 原点开关），
  且寻零参数（速度、偏移）在控制器内设定。
- **上报的能力**：硬限位支持（限位接在控制器上、由控制器直接封锁运动）、点动支持、
  **直线/圆弧插补不支持**（本驱动不做插补）。

## 轴映射参数

行内表格编辑这 5 个核心字段，其余 7 项收在「轴配置」弹窗里，全部随方案 JSON 落盘：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 逻辑轴名 `LogicalName` | —— | **流程的唯一寻址键**，必须全局唯一（跨卡也不能重名）。步骤里填的就是它；改名要同步改流程 |
| 物理轴号 `PhysicalIndex` | —— | **0 基**：卡上的第 1 根轴填 `0`。超出机型轴数会被门禁挡下（`轴号 5 超出范围（本卡 4 轴）`） |
| 是否启用 `Enabled` | `true` | 关掉的轴不进下拉候选、不被轮询、不被"停全部轴/清报警"遍历 —— 这是"这根轴这台机器暂时不用"的正确做法 |
| 脉冲当量 `UnitsPerMm` | `1000` | **每毫米多少个单位**，连接时下发给 `SetUnits`（下限取 `0.0001`）。由标定得出；配错的后果是行程按错误倍率放大/缩小，**且看起来能跑**，最难在现场发现 |
| 软限位下/上（mm） | `-1000000` / `1000000` | 软件层最后一道防线，**只在绝对运动时校验**。保持默认等于"这道防线是空的"（界面会据此提示 `IsSoftLimitDisabled`），请按机构真实行程填写 |

「轴配置」弹窗里的低频字段（当前**只随方案存档，驱动不下发到卡**）：

| 参数 | 空/0 的含义 | 说明 |
| --- | --- | --- |
| 轴备注 `AxisRemark` | 空 = 未填 | 如"Z 轴升降"，纯给人看 |
| 编码器类型 `EncoderType` | 空 = 界面按"增量编码器"回退展示 | 无 / 增量 / 绝对值 / 光栅尺，记录用 |
| 每毫米脉冲数 `EncoderPpu` | 0 = 界面按 1000 回退展示 | 位置反馈换算参考值，**本驱动不用它**（用的是 `UnitsPerMm`） |
| 驱动器型号 `MotorDriver` | 空 = 界面回退候选第一项 | 示教与报警码解析的记录位 |
| 额定电流（A）`MotorRatedCurrentA` | 0 = 界面按 5 回退展示 | 过载估算的记录位 |
| 跟随误差上/下限（pulse） | 0 = 界面按 ±5000 回退展示 | **不下发给驱动器**：真实的跟随误差窗口要在伺服/驱动器参数里设 |

> 这一组是"先记录、后接入"的字段：现场把它们当**接线/参数备忘**用，
> 不要以为在软件里填了跟随误差上限，驱动器就会按它报警。

## 卡级参数

| 参数 | 默认 | 在正运动卡上的真实作用 |
| --- | --- | --- |
| 默认速度 `DefaultVelocityMmPerS` | `50` | **不影响步骤运动命令**：步骤速度填 0 时驱动"不覆盖"，沿用控制器内该轴当前 SPEED。它是点位表与调试面板的默认值来源 |
| 默认加减速度 `DefaultAccelMmPerS2` | `500` | 同上：点位表的默认加减速来源。步骤命令的加速度恒为"不覆盖"（`Accel ≤ 0` 时不写 `SetAccel/SetDecel`） |
| 轮询周期 `PollIntervalMs` | `10` | 决定"报警/限位多久被发现"（工业常见 5~20 ms）。太小占满网口带宽，太大安全响应迟钝 |
| 命令超时 `CommandTimeoutMs` | `30000` | 单条命令的默认超时；「轴运动」「轴卡 IO」「轴停止」的下发超时就是它；回零命令没给超时的兜底也是它（下限 1000 ms） |
| 看门狗超时 `WatchdogTimeoutMs` | `3000` | 连续 3 次轮询失败**或**超过这个时长没有成功轮询 → 判失联、清队、安全停机 |
| 自动重连 `AutoReconnect` | `true` | **当前只是配置项**：运动卡这一层没有实现自动重连逻辑，掉线后要人工在「运动卡设置」里**先断开再连接**（详见「连接与排障」）。重新连接时驱动会重新读机型、重发 `SetUnits` 并重建能力表 |
| 队列深度 `MaxQueueDepth` | `256` | 超过即 `被拒绝：命令队列已满（上限 256 条）` |

## 命令 → 正运动 API 对照（现场对厂商手册时用这张表）

| 统一命令 | 正运动 API | 完成判定 | 备注 |
| --- | --- | --- | --- |
| 使能 | `ZAux_Direct_SetAxisEnable(轴, 1)` | 返回 0 即完成 | 使能状态由下一次轮询的 `GetAxisEnable` 回报 |
| 失能 | 先 `Single_Cancel(轴, 2)` 再 `SetAxisEnable(轴, 0)` | 返回 0 | 失能即停：撤掉当前运动再断电 |
| 绝对定位 | `SetSpeed`(速度>0 时) → `SetAccel/SetDecel`(加减速>0 时) → `SetSramp` → `Single_MoveAbs(轴, 目标mm)` | **下发即返回** | 不等到位；等到位是「等待到位」步骤的事 |
| 相对定位 | 同上 → `Single_Move(轴, 增量mm)` | 下发即返回 | 增量可为负 |
| 点动 | 同上 → `Single_Vmove(轴, ±1)` | 下发即返回 | 速度模式持续走，直到收到停止；调试面板负责"松手即停" |
| 回零 | 总线型 `BusCmd_Datum(轴, 模式码)`；脉冲型 `Single_Datum(轴, 模式码)` | 总线型 `GetHomeStatus==1`；脉冲型 `GetIfIdle≠0` | 超时**先停轴**（`Single_Cancel(轴,2)`）再报失败；回零速度/偏移沿用控制器内设置 |
| 停止 | `Single_Cancel(轴, 模式)`；轴号 -1 时**逐启用轴**逐个取消 | 返回 0 | 模式 2=减速停、3=立即停（与枚举值一致）；≤0 归为 2 |
| 写输出 | `ZAux_Direct_SetOp(点号, 1/0)` | 返回 0 | 点号 **0 基** |
| 清报警 | `ZAux_BusCmd_DriveClear(轴, 0)`，**逐启用轴** | 全部返回 0 | **不自动重新使能**（使能有机械后果，须人工明确点） |
| 读输入 | `GetInMulti(0, 点数-1)`（轮询里批量） | —— | 「轴卡 IO」读的是这份快照 |

回零方式码（`homemode`）**只能来自手册**，本表取自已投产的参考工程：
`NegativeLimitIndex=1`、`PositiveLimitIndex=2`、`NegativeLimit=17`、`PositiveLimit=18`、`Origin=19`、
`PositiveLimitOrigin=23`、`NegativeLimitOrigin=27`、`PresetZero=37`。填错一个数字，轴会按完全不同的寻零路径走。

## 口径与失败策略

- **单位一律 mm**：`SetUnits` 之后本卡所有位置/速度 API 都以"用户单位"（mm）计，
  **代码里绝不再除一次当量** —— 除一次会让所有位置缩到 1/当量，而目标也同步缩小，表现为"能跑但行程全错"。
- **位置读的是 `GetMpos`（指令位置）**，不是编码器实际位置；速度**当前不回读**，所以「读轴状态」的 `Velocity` 在这张卡上恒为 0。
- **轴状态位域**（`GetAxisStatus`）：bit3 伺服报警、bit4 正限位、bit5 负限位、bit11 到位、bit12 急停输入。
  解析集中在一个纯函数里，因为**位写错的后果不是"少亮一个灯"，而是把报警读成到位**（安全停机就不会触发）。
  报警时快照的报警说明固定为"伺服报警"（SDK 状态字只给位，不给报警原因）。
- **不做逐码翻译**：SDK 全系列只返回一个 int，且**没有码→文案的接口**（zauxdll 无 `GetErrMsg` 一类导出）。
  凭记忆编一张对照表看着专业，但现场按错误方向排查的损失比"没翻译"大得多。所以每条故障只给三层有把握的东西：
  ① 原始码（`正运动错误码 N`，可对厂商手册或报给厂商）；② 出错的操作上下文（"回零时"还是"读状态时"，这本身能定位大半）；
  ③ 按操作类别的**分级与处置建议**。
- **故障分级（决定能不能自动恢复）**：
  | 操作 | 分级 | 现场含义 |
  | --- | --- | --- |
  | 连接控制器 | 需检修 | 网线/IP/供电/被占用，重试不会自己好，要人去看 |
  | 回零 | 需复位 | 失败时轴可能正卡在原点开关上，必须人工确认后重来 |
  | 使能 / 失能 / 绝对 / 相对 / 停止 / 点动 | 需复位 | 卡侧状态不对（未使能、报警、撞限位），要人处理 |
  | 读状态 / IO 等 | 可恢复 | 单次失败不判失联，连续失败由看门狗兜 |
- **命令执行失败或超时的后果**：基类清空待执行队列、把卡打进「已安全停机」，并逐启用轴下发**减速停**（`Single_Cancel(轴,2)`）。
  这里是"收尾"不是"急停"，所以用减速停；真正的急停是 `StopMode=3` 且走紧急通道。
- **硬信号自动急停**：轮询发现报警 / 限位 / 急停输入 → 立刻 `EmergencyStop()`（清队 + 插队立即停全部轴）并进入「报警」。
- **被打断不记故障**：急停或停止导致的"命令被取消"是预期行为，不记成设备故障、也不因此进安全停机。

## 典型用法 / 接线

```
① 系统 → 运动卡设置：新增卡
   驱动 = 正运动 ZMotion 运动卡
   卡名 = 运动卡1     地址 = 192.168.0.11     机型 = ECI3428     勾 自动连接
② 轴映射：X→轴号 0、Y→轴号 1（0 基！），填当量、按真实行程收紧软限位
③ 流程（与仿真时同一套，一字不改）：
   轴使能(X) ──▶ 轴回零(X) ──▶ 轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=ON)
                                                        └──▶ 轴卡 IO(读 IN0) ──▶ 轴停止(X)
```

上电标准顺序建议：连接（或自动连接）→ 清报警（如处于报警）→ 使能 → 回零 → 运动。
清报警**不会**自动使能，所以"清报警 → 轴使能 → 轴回零"这三步要连着放。

## 常见问题

**Q：连接成功但第 5~8 根轴用不了（8 轴卡）？**
机型没被认出来，能力按 4 轴兜底给的。日志里会有"未识别机型…"。把「运动卡设置」的机型栏填成
`ECI3828`（8 轴 / 24 入 / 20 出）再重连；确认状态说明里的轴数变了。

**Q：轴能走，但走 10 mm 实际走了 10000 mm（或反过来）？**
当量口径问题：`UnitsPerMm` 是**每毫米多少个单位**，连接时下发 `SetUnits`。
两种错法：把"每单位多少毫米"（倒数）填进去了；或者驱动器侧电子齿轮比改过而软件没同步。
按标定重算，重连（`SetUnits` 只在连接时下发）。日志里若有"设置脉冲当量失败——位置与目标将按控制器原单位解释"，
说明这一步根本没下发成功，位置口径直接是控制器原单位。

**Q：流程里速度给了 50，真机跑得明显不是 50？**
看两处：① 本驱动在 `SetSpeed` 失败时只告警不中断（"本次将沿用控制器内的既有速度"），所以先看日志有没有这句；
② 速度填的是 0（0 = 不覆盖，沿用控制器内 SPEED）。把速度显式写成非零值再试。

**Q：想要 S 曲线，但用流程步骤运动时总是梯形？**
正常：每次定位前驱动都会写 `SetSramp` —— 梯形=0、S 曲线=200 ms，且**刻意每次都设**（避免上一条命令的残留）。
流程步骤的命令曲线固定为梯形，所以会把之前设过的 S 清掉。要 S 曲线请走点位运动（调试面板 / 点位表），
那里能选曲线形状；平滑时长固定 200 ms，不可调（参数面越小越不容易配坏）。

**Q：软限位设了却撞机？**
软限位**只校验绝对运动**（`MoveAbsolute`）。相对运动、点动不受它拦 —— 那两条靠卡上的硬限位与驱动器保护。
另外保持默认 ±1000000 mm 等于没设（界面会提示这道防线是空的）。

**Q：状态说明里"IO 点数未核实"是什么意思？**
这张机型表给的是常见的显示上限（虚拟 PLC 与未识别机型尤其如此）。以实物接线与厂商手册为准；
流程里点到不存在的点会被门禁挡下（`输出点 N 超出范围（本卡 16 点）` / `输入点 N 无效（本卡输入点范围 0~23）`）。
