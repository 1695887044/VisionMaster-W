# 坐标系与单位口径

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.ZMotion

这一页讲"这张卡报出来的数是什么口径"。参数怎么填见《卡参数与轴参数》，
现象怎么反查见《排障》；下面每一条都对应驱动实现里的一处具体决定，不是通用运动控制常识。

## 一、位置单位：全程 mm，换算只发生一次

正运动 SDK 的位置寄存器是"单位"而不是毫米。驱动在**连接时**对每一根已启用轴下发
`SetUnits(轴, max(0.0001, UnitsPerMm))`，之后本卡所有位置/速度 API 收发都是**用户单位（mm）**。

由此推出两条纪律：

- **代码里绝不再除一次当量**。除一次会让所有位置缩到 1/当量，而目标位置也同步缩小，
  表现是"看起来能跑、只是行程全错"—— 这类错误在现场几乎发现不了。
- **当量只在连接时下发**。改了 `UnitsPerMm` 必须重连才生效；
  `SetUnits` 返回非 0 时驱动只写一条 Warn（`设置脉冲当量失败（码 N）——位置与目标将按控制器原单位解释，请核对`），
  连接本身不失败 —— 所以日志里那句话要看，别看一眼"已连接"就过去。

## 二、坐标原点：由回零建立，软件不强制

- 绝对坐标以回零建立的零点为基准；`Home` 命令成功后基类把"已回零"标记置 true。
- 连接末尾驱动**无条件**把该标记置 false（本驱动按增量式对待：多回一次零，好过在位置不可信时按错误坐标运动）。
- **已知口径不一致（如实记录，不是缺陷报告里的猜测）**：能力表里 `SupportsAbsoluteEncoder` 上报 true，
  而基类在连接成功末尾会按能力位把"已回零"重算成 true —— 于是"每次连接后都要回零"的意图
  与"连上就算已回零"的实际结果对不上。代码注释里取 false 的理由（伺服是否绝对式取决于所配伺服、
  SDK 没有统一查询接口）与最终上报值方向相反。**结论很实际：不要指望软件替你强制回零**，
  流程首步显式放`轴回零`；现场确认是绝对值编码器且机构允许免回零时，由人决定省略。
- `零位置预设（不找开关）`（模式码 37）不找开关、直接把当前位置置零，适合已经在对位位置的场合。

## 三、位置读的是什么：指令位置

轮询里位置来自 `ZAux_Direct_GetMpos` —— 这是**指令位置**，不是编码器实际位置。
所以：外力推动、丢步、跟随误差都**不会**反映在`读轴状态`的 `Position` 上。
要核对真实位置看驱动器侧。

## 四、速度不回报

本驱动的轮询读四样：状态位域、忙/闲、指令位置、使能位，**没有读速度寄存器**。
于是`读轴状态`的 `Velocity` 在这张卡上恒为 0。那是"缺数据"，不是"静止"：
判"动没动"一律用 `Moving`（来自 `GetIfIdle`，0 = 运动中）。

## 五、轴状态位域的语义（读错的后果不是"少亮一个灯"）

`ZAux_Direct_GetAxisStatus` 返回一个状态字，解析集中在一个纯函数里：

| 位 | 含义 | 快照字段 |
| --- | --- | --- |
| bit3 | 伺服报警 | `Alarm`（附说明，固定为"伺服报警"） |
| bit4 | 正限位触发 | `PositiveLimit` |
| bit5 | 负限位触发 | `NegativeLimit` |
| bit11 | 到位 | `InPosition` |
| bit12 | 急停输入触发 | `EmergencyStop` |

位写错的后果是**把报警读成到位**（安全停机就不会触发）或把限位读成正常（继续往限位方向走）。
报警时说明文案固定"伺服报警" —— SDK 的状态字只给位，不给报警原因，真实原因要在驱动器侧看。

## 六、编号基准：轴号与 IO 点号都是 0 基

- 物理轴号 `PhysicalIndex` 从 0 开始，卡上第 1 根轴填 0；上界是机型轴数。
- IO 点号同样从 0 开始：界面上的 `IN0` / `OUT0` 就是点号 0，批量读区间是 `0 ~ 点数-1`。
- 停止命令里 **轴号 -1 是约定值，表示全部轴**（正运动没有"停所有轴"的单一调用，实现是逐启用轴取消）。

## 七、速度 / 加减速 / 曲线的"不给就沿用"口径

一句话原则：**流程管"去哪、多快、等多久"，控制器管"怎么动、怎么找零、到位怎么判"**。

| 量 | 填 0 / ≤0 时的行为 | 说明 |
| --- | --- | --- |
| 速度 | **不覆盖**，沿用控制器内该轴当前 SPEED | 仿真填 0 会用卡级默认 50，真卡填 0 是"沿用控制器里那个值"，可能是 5 mm/s |
| 加减速 | **不覆盖**（不写 `SetAccel`/`SetDecel`） | 现场在卡内调好的加减速不该被软件擅自改写 |
| 曲线 | 每次定位前**都写** `SetSramp`：梯形 = 0、S 曲线 = 200 ms | 刻意每次都设，避免上一条命令的残留；流程步骤恒梯形，会清掉之前设过的 S |
| 回零速度 / 偏移 | **完全不动**，沿用控制器内既有设置 | 驱动擅自改会破坏已经调好的机构行为 |
| 到位判断窗口 | 由驱动器/控制器内参数决定 | `等待到位` 读的是卡给的到位位；判得过严会"看着到了却不报到位" |

`SetSpeed` / `SetAccel` / `SetSramp` 失败都只写 Warn 不中断（本次沿用控制器内既有参数）——
宁可慢一点，也别把一次定位变成故障停机。

## 八、软限位只拦绝对运动

软限位是软件层的最后一道防线，实现只在校验`绝对定位`时读 `AxisMapping` 的上下限：

- 相对运动、点动**不查**软限位，靠卡上的硬限位（能力位上报支持，限位接在控制器上、由控制器直接封锁运动）与驱动器保护。
- 保持默认 ±1000000 mm 等于这道防线是空的（界面会按 `IsSoftLimitDisabled` 提示）。
- 拒绝时是"命令被拒绝"，级别为提示（Notice），不会把卡打进安全停机 —— 目标本身不合法属于业务正常。
- 手动路径（调试页签）另有同一份文案的闸门：`目标坐标不是有效数字` 与超出软限位那条。

## 九、下发 ≠ 到位；同卡命令是排队的

- `Single_MoveAbs` / `Single_Move` 返回 0 只代表命令进了控制器。日志会明确写"已下发…（未等到位；如需等待请在其后加「等待到位」步骤）"。
- 命令执行是**一条线程、FIFO**。"轴运动(X) → 轴运动(Y)"两条会先后下发；
  要真并行需要不同卡，或者接受"下发快、执行排队"。
- 急停走插队通道：清空普通队列 + 专用槽位 + 打断正在执行的那条命令。
  停止与失能属于"打断性命令"，入队时会取消当前那条长命令（否则"停止"要等回零跑完，毫无意义）。
- 队列上限默认 256 条，超过即拒绝（`被拒绝：命令队列已满（上限 256 条）`）。

## 十、错误码不做逐码翻译

SDK 全系列只返回一个 int，且**没有码→文案的接口**（zauxdll 无 `GetErrMsg` 一类导出）。
凭记忆编一张"12 = 参数错误、34 = 通信超时"的对照表看着专业，但现场按错误方向排查
（把"轴未使能"当成"网线坏了"）的损失比"没翻译"大得多。所以每条故障只给三层有把握的东西：

1. **原始码**：文案里的"正运动错误码 N"，可对厂商手册或报给厂商；
2. **出错的操作上下文**：是"回零时"还是"读状态时"，这本身能定位大半；
3. **按操作类别的分级与处置建议**：决定"能不能自动恢复 / 要不要叫维修"。

| 操作类别 | 分级 | 现场含义 |
| --- | --- | --- |
| 连接控制器 | 需检修 | 网线/IP/供电/被占用，重试不会自己好 |
| 回零 | 需复位 | 失败时轴可能正卡在原点开关上，必须人工确认后重来 |
| 使能 / 失能 / 绝对 / 相对 / 停止 / 点动 | 需复位 | 卡侧状态不对（未使能、报警、撞限位） |
| 读状态 / IO 等其余 | 可恢复 | 单次失败不判失联，连续失败由看门狗兜 |

## 常见问题

**Q：同一份流程，仿真跑得对，真机行程差一个固定倍数。**
`UnitsPerMm` 的倒数填进去了，或驱动器侧电子齿轮比改过而软件没同步。按标定重算后**重连**（当量只在连接时下发）。

**Q：为什么`等待到位`的判据不是"位置等于目标"？**
到位是卡侧信号（bit11）与忙/闲的合成，判据在控制器/驱动器侧（跟随误差窗口、到位带宽）。
软件层再叠一个位置容差，会出现"卡认为到了、软件认为没到"的假超时。

**Q：轴明明被外力推走了，位置读数怎么不变？**
不变是对的 —— 那是指令位置。要发现丢步只能看驱动器实际位置/跟随误差。
