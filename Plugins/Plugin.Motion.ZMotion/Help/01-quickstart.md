# 快速上手与连接

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.ZMotion

这一页解决"第一次把这张真卡跑通"。它是**设备驱动插件**，不是流程里的算子：
工具箱里找不到它，它出现在「系统 → 运动卡设置」的驱动下拉里；流程中那七个运动步骤
（轴使能 / 轴回零 / 轴运动 / 等待到位 / 读轴状态 / 轴卡 IO / 轴停止）按原名在它上面跑。

插件类与工具箱身份（取自 `[Display]`，逐字）：`Name = 正运动运动控制卡`、
`GroupName = 运动卡`、`Description = 正运动（ZMotion）ECI/ZMC 系列网口控制器：点位运动 / 回零 / 点动 / IO / 急停`。

## 跑通一次的六个动作

```
① 落 DLL：Plugin.Motion.ZMotion.dll 必须在 Modules\（宿主扫描那里，别的目录加载不到）
② 落 native：zauxdll.dll 与 zmotion.dll（都是 64 位）放在 VisionMaster.exe 同级目录
   —— 放 Modules\ 里加载不到，P/Invoke 只搜 exe 目录、系统目录与 PATH
③ 系统 → 运动卡设置 → 添加运动卡：驱动选「正运动运动控制卡」，
   填 卡名（如 运动卡1）、连接地址（如 192.168.0.11）、机型（如 ECI3428）
④ 轴映射：逻辑名 X / Y（全局唯一）、物理轴号 0 基（第 1 根轴填 0）、
   脉冲当量 UnitsPerMm（标定得出）、按真实行程收紧软限位，不用的轴取消勾选
⑤ 点「应用参数与轴映射」→ 点「连接」，读状态说明那一行
⑥ 调试页签：使能 → 回零 → 给一个 1~2 mm 的绝对定位 → 等待到位
```

第 ⑤ 步连上之后，状态说明不是干巴巴一句"已连接"，而是驱动自己写的那一行：

```
已连接 ECI3428 @ 192.168.0.11（固件 x.x.x）｜4 轴｜IO 24 入 / 16 出
```

**这行是排障第一现场**：机型对不对、轴数对不对、IO 点数后有没有"（点数未核实，按显示上限列出）"，全在里面。
看到"未识别机型"或轴数不符，先回第 ③ 步把机型栏填准再重连，别急着调流程。

## 五种状态，命令能不能发全看它

| 状态 | 界面文字 | 放行什么 | 怎么走到下一步 |
| --- | --- | --- | --- |
| 未连接 | 未连接 | 什么都不放（`运动卡未连接`） | 点「连接」，或勾「随方案启动自动连接」 |
| 连接中 | 正在连接运动卡… / 正在断开… | 全挡（`运动卡正在连接/断开，请稍候`） | 等它结束（网口建链几百毫秒到几秒属正常） |
| 在线 | 在线 | 全部命令 | —— |
| 报警 | 报警 | 只放行**清报警**与**急停** | 排除原因 → 清除报警 → **还要重新使能** |
| 已安全停机 | 已安全停机 | 全挡（`运动卡已安全停机，请重新连接后再操作`） | **先「断开」再「连接」**（连接对非"未连接"状态是幂等的） |

## 首次上电的最小验证顺序（新设备接真卡）

每步只验一件事，出错能立刻定位：

```
① 连接：状态说明里机型、轴数、IO 点数都对得上，无"未识别机型"/"未核实"
② 读轴状态：位置有读数、Enabled=false、无报警/限位
③ 轴使能：使能后再读状态，Enabled=true（伺服上电、抱闸打开，先确认机构安全）
④ 轴回零：默认「负限位 + Index」；轴先离开开关再试；确认零点方向与坐标符合预期
⑤ 小行程绝对定位：1~2 mm 目标 + 明确速度 → 等待到位 → 读位置
   （这一步专验当量与方向：走出的距离对不对、正负号对不对）
⑥ 相对定位：+1 mm、−1 mm 各一次（相对运动不查软限位，靠硬限位兜）
⑦ 读输入：逐个读关键传感器，确认点号与实物接线一致（0 基）
⑧ 写输出：逐个写气缸/阀，确认点号与动作对应
⑨ 停止：减速停与立即停各试一次；再试一次急停，确认队列被清、轴停下
```

每一步看两处：调试页签上的状态标签，以及日志里 `[ZMotion:卡名] …` 那些中文行
（下发原文、拒绝原因、看门狗都写在那里）。

## 流程里的标准起手式

```
轴使能(X) ─▶ 轴回零(X) ─▶ 轴运动(X) ─▶ 等待到位(X) ─▶ 轴卡 IO(OUT0=ON)
                                            └─▶ 轴卡 IO(读 IN0) ─▶ 轴停止(X)
```

三条从仿真搬过来最容易翻车的规矩：

- **回零要显式放在流程首步**：本驱动按增量式对待，连接末尾把"已回零"标记置 false，
  但软件层不会强制拦你（详见《坐标系与单位口径》那条口径不一致的记录）。
- **一条定位命令不等到位**：`轴运动` 返回成功只代表命令进了控制器，必须跟一个`等待到位`。
- **清报警不会自动使能**：所以"清报警 → 轴使能 → 轴回零"要连着放。

## 常见问题

**Q：驱动下拉里没有「正运动运动控制卡」。**
`Modules\` 里没有这个 DLL（或 DLL 陈旧）。插件工程必须建在 `Plugins\` 下、产物投递到 `Modules\`；
只重建宿主不会带出插件 DLL。

**Q：能选到驱动，点「连接」却报找不到模块。**
九成是 native 依赖不齐。`zauxdll.dll`（辅助层）自己还要 `zmotion.dll`（核心层），
少任何一个，Windows 只说"Unable to load DLL 'zauxdll.dll' or one of its dependencies"，
不告诉你缺的是哪一个。本驱动会自己去查并点名（见《排障》那一页的报错原文对照）。

**Q：厂商调试软件（RTSys）能连，本程序连不上。**
正运动的网口连接是独占的，后连的一方失败。先断开厂商软件、关掉多余的本程序实例再连。

**Q：勾了「随方案启动自动连接」，启动后没连上。**
自动连接只在方案加载时对勾了这项的卡**发起一次**，一台失败不影响其它台，失败原因就写在状态说明里
（多半是控制器还没上电、或 DLL 缺失）。控制器先上电，然后手工点一次连接即可。

**Q：`自动重连` 勾了，掉线却没自己接上。**
这一项目前只是配置项：运动卡这一层没有实现自动重连逻辑，掉线后要人工「断开 → 连接」。
界面措辞不要当承诺用。
