# 不变量与断言对照：哪些有闸门钉着、哪些只能靠人

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.ZMotion ｜ 读者：开发

断言全部落在 `FlowCanvasChecks\MotionZMotionChecks.cs`（运动驱动与调试面板这一组，
含契约扫描与真机无关的纯函数断言）。本页每条**照抄断言名**，可在闸门输出里逐字搜到；
搜不到的就是"无断言，靠人工核对"，不要以为有兜底。

## A 组：违反就红（闸门会拦，改完必须跑一遍）

### 回零模式码（厂商码不能猜）

| 不变量 | 断言名 |
| --- | --- |
| 八个回零方式逐个映射到正运动手册里的模式码（1/2/19/27/23/17/18/37） | `回零方式「{name}」→ {code}`（逐值一条） |
| 契约新增枚举值时必须补映射，不许漏 | `契约里定义的回零方式全部有映射（没有漏网的枚举值）` |
| 预设零点不算"找开关"，界面据此提示 | `零位置预设被标记为「不需要找开关」（界面据此提示）` |

⚠ C# 枚举值 0~7 与正运动模式码不是同一套数，改代码时按 `ZMotionHomeModes.ToSdk` 的 `switch` 逐字抄，
不要按枚举值推算。

### 故障分级与文案

| 不变量 | 断言名 |
| --- | --- |
| 回零失败需人工复位（不自动重试） | `回零失败 → 需人工复位（可能正卡在原点开关上，不能自动重试）` |
| 保留原始码、带操作上下文、带建议、带轴名 | `故障里带**原始错误码**（现场据此对厂商手册）`、`故障里带出错的操作上下文（「回零」比「操作失败」有用得多）`、`有处置建议（现场少打一次电话）`、`带上出错轴名` |
| 连接类判需现场处理 | `连接失败 → 需现场处理（检查 IP / 网线 / 供电 / 占用），并给出对应建议` |
| 单次读状态失败只算可恢复 | `读状态失败 → 可恢复级（单次通信抖动不该把设备判死，看门狗会兜连续失败）` |
| 运动被拒需人工复位 | `运动被拒 → 需人工复位（卡侧状态不对：未使能/报警/限位）` |
| 不许编造逐码文案 | `★不逐码编造文案：说明里保留原始码而不是伪装成已知含义` |

### 点动（按住才动）

| 不变量 | 断言名 |
| --- | --- |
| 点动持续运动直到被叫停；停止能终止 | `点动命令被接受`、`★点动下发后轴**持续**运动（没有终点，直到被叫停）`、`★停止命令能终止点动（位置不再变化）` |
| 心跳阈值与临界 | `阈值取 500ms：按住期间 UI 每 150ms 一次脉冲，留 3 倍余量`、`心跳新鲜（100ms 前刚按过）→ 不干预点动`、`★心跳超时（900ms 没脉冲）→ 判定必须停`、`从未点动过（MinValue）不触发停止（否则一开面板就会去停设备）`、`刚好等于阈值时不判超时（避免临界抖动导致按住时反复起停）` |
| 界面上的按住/急停形态 | `★点动用「按住才动」行为（HoldCommand 与 ReleaseCommand 成对，不是普通 Click）`、`★有独立的急停入口（DialogDangerButton，实心红、不藏在子菜单里）` |

| 不变量 | 断言名 |

| Provider 同步不递归、通知顺序正确 | `★{label} Provider 的 EnsureSynced 有重入闸（同步期间再进来直接返回）`、`★{label} Provider 先记同步状态、再广播 DevicesChanged…` |

## B 组：违反静默（闸门不管，只能靠人）

以下每一条都有代码依据，但**当前没有对应断言**，写错了程序照样跑，代价由现场承担。

| # | 不变量 / 事实 | 破坏后的静默表现 | 核对方式 |
| --- | --- | --- | --- |
| B1 | `SetUnits` 之后所有位置/速度 API 一律是用户单位（mm），**绝不能再除脉冲当量** | 无断言，靠人工核对。位置和目标同比例缩小，"看起来能跑，只是行程全错" | 走一次已知距离的定位，量实际位移 |
| B2 | 脉冲当量下限取 `max(0.0001, UnitsPerMm)`，且只在连接时下发 | 无断言，靠人工核对。填 0 或负数会被静默抬到下限；改完不重连不生效 | 改值后必须断开重连 |
| B3 | `SetUnits` 失败只写 `Warn`，命令照发 | 无断言，靠人工核对。位置将按控制器原单位解释 | 每次连接后 grep 日志 `设置脉冲当量失败` |
| B4 | 回零判据只认 `GetHomeStatus == 1`，其它值继续等 | 无断言，靠人工核对。把"失败"当"进行中"会一直等到超时 | 断开会触发超时文案，看时长是否符合预期 |
| B5 | 回零速度/偏移**沿用控制器内设置**，软件不覆盖 | 无断言，靠人工核对。在软件里改这些值不会有任何效果 | 参数面里没有这两个值即为设计意图 |
| B6 | 速度不参与轮询，`AxisStatus.Velocity` 恒 0 | 无断言，靠人工核对。任何按速度做的判断永远为假 | 「读轴状态」的输出恒 0 |
| B7 | `SafeStopCore` 与清报警只遍历 **`Enabled == true`** 的轴 | 无断言，靠人工核对。把某根轴的映射取消勾选后，安全停止与清报警都不再覆盖它 | 停用的轴要在界面上留痕；物理安全不能只靠软件 |
| B8 | 清报警**不自动重新使能** | 无断言，靠人工核对。期望"清完就能走"的流程会卡在未使能 | 流程里显式接「使能」步骤 |
| B9 | `SafeStopCore` 用减速停（模式 2），急停用立即停（模式 3）；`StopMode <= 0` 兜底为 2 | 无断言，靠人工核对。写反会让收尾变成冲击性停止 | 代码审阅 + 听声辨停 |
| B10 | 绝对运动才校验软限位（相对运动不校验） | 无断言（门禁本身也无独立断言），靠人工核对。相对走多了照样出行程 | 靠硬限位与点位管理 |
| B11 | 未识别机型 `Warn` 一次，能力按 4 轴兜底，界面继续可用 | 无断言覆盖 Warn 文案。真接了 8 轴的卡而机型不认识时，后 4 根轴会被判"轴号超出范围" | 状态行有"按显示上限列出"或日志里的未识别提示 |
| B12 | `SupportsAbsoluteEncoder` 的代码值为 `true`，与紧邻注释表达的"保守取 false"不一致 | 无断言，靠人工核对。基类据此在连接后置 `IsHomed = true`，等于**不强制回零就能走绝对坐标** | 需要强制回零的流程自己放「回零」步骤；改这个位会改变界面是否要求回零 |
| B13 | 连接失败时状态行统一显示「连接失败：设备未给出原因」，具体原因在故障与日志里 | 无断言，靠人工核对。只盯状态行会查不到原因 | 故障提示 + 日志同行 |

## 改动前的自检顺序

1. 动 `ZMotionModels.cs`（位、模式码、机型、分级）→ 跑本组断言，红了就照断言名回查手册。
2. 动 `ZMotionCard.cs` 的下发/轮询 → 先看它有没有把"安全"往驱动里搬（安全属于基类）。
3. 动端口/候选/落盘 → 跨插件契约，A 组「参数面板与寻址」那一节会整片红。
4. 动 `csproj`/部署 → A 组「部署与 SDK」那一节 + 手动确认 exe 同级两个 dll 都在。
5. 动手册 → 重建本插件工程，让 `HelpCatalogService` 读到新资源。
