# 几何计算 · 端口与参数

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryRelation

本插件**没有自定义配置界面**，也没有 `[StepConfig]` 常量：双击步骤（或右键「模块参数」）打开的是**输入端口清单**，
每行 = 参数名 + 值输入框 + 🔗（连上游）+ ✕（清除连线）——参数与连线是同一张表。
枚举型端口（`Op` / `RelationKind` / `ConstructMode`）在界面上下拉显示中文名，流程文件里存的是它的数值（如 `2` = 求交）。

## 输入端口

| 端口 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `Op` | `GeometryOp` | 是 | 距离 | 关系模式：距离 / 夹角 / 求交 / 垂足 / 平行垂直 / 圆关系 / 构造。**这一个端口决定其余参数谁生效** |
| `A` | `GeometryParam` | 是 | 无 | 几何 A（点/线/圆/椭圆）。为空即失败：`几何计算：输入 A 为空（请接上游几何基元：几何查找 / 卡尺 FittedGeometry）` |
| `B` | `GeometryParam` | 否 | 无 | 几何 B。除"构造-过两点构线"外的模式都要它，没接会明确报"××模式需要输入 B" |
| `C` | `GeometryParam` | 否 | 无 | 几何 C。**只有"构造 + 三点构圆"用**，其余模式完全不看它 |
| `MmPerPixel` | `double` | 否 | 0 | 像素当量（mm/px），接「标定」的 `MmPerPixel`。**未接且手填 ≤ 0 = 数值直接输出像素**（不假装是 mm） |
| `StandardValue` | `double` | 否 | 0 | 标准值（判定用） |
| `UpperTolerance` | `double` | 否 | 0 | 上公差（默认 0 = 零容忍） |
| `LowerTolerance` | `double` | 否 | 0 | 下公差（默认 0 = 零容忍；按**幅度填正数**，判定式是"值 ≥ 标准值 − 下公差"） |
| `AngleTolerance` | `double` | 否 | 0.1 | 角度容差（度）。"平行/垂直"用它判；"距离 + 两条线"也用它先验平行（填 ≤ 0 时按 0.1 兜） |
| `RelationKind` | `LineRelationKind` | 否 | 平行 | 平行 / 垂直。**只有"平行/垂直"模式看它** |
| `ConstructMode` | `ConstructKind` | 否 | 过两点构线 | 过两点构线 / 三点构圆。**只有"构造"模式看它** |
| `SrcImage` | `HImage` | 否 | 无 | 叠加显示用的图像：接上游图像源，把输入与结果画在它上面。**不接 = 不显示**（算法照跑） |
| `DisplayViewIndex` | `int` | 否 | 1 | 显示窗口：`0` = 不显示，`1~9` = 主界面第几个图像窗口（填大于 9 按 9 处理） |
| `Success` / `ErrorMessage` | `bool` / `string` | — | — | 基类自带：本步骤是否跑通、失败时的中文原因 |

> 「必填」= 端口自己声明的 `IsRequired`：既没连线、步骤数据里又没有常量值时，编译报参数缺失；
> 打开一次「模块参数」点确定，默认值就存成常量，之后不连线也能跑。
> 本插件**只有 `Op` 与 `A` 是必填**，其余端口全部声明为非必填。

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Value` | `double` | 数值结果：距离 / 圆心距 / 垂距（像素，接当量后 mm）、夹角或平行垂直的实测夹角（**度**，[0,90]）。不做数值输出的模式为 0 |
| `Geometry` | `GeometryParam` | 基元结果：求交的**交点**、垂足的**垂足点**、构造出的**线或圆**。其余模式为 null。可继续喂给下一个「几何计算」 |
| `IsOk` | `bool` | 判定结果（true = OK）。**只有距离 / 夹角 / 圆关系 / 平行垂直四种模式会写它**；求交、垂足、构造恒为 false |

**每轮开头一律清零**：`Value` = 0、`Geometry` = null、`IsOk` = false。
所以失败轮下游读到的是空值，不会拿到上一轮的残留——但也别指望"`IsOk` 是 false"意味着本轮失败，它只意味着"本轮没判出 OK"。

## 七种模式各要什么、出什么

| 模式 | 要什么样的输入 | 出什么 | 用哪些参数 | 备注 |
| --- | --- | --- | --- | --- |
| 距离 | 点+点 / 点+线（顺序随意）/ 线+线（必须接近平行） | `Value`（长度）+ `IsOk` | `MmPerPixel`、规格三项、`AngleTolerance`（线线时验平行） | 线-线量的是**从 B 的锚点到线 A 的垂距**；两线不平行直接失败 |
| 夹角 | 两条线 | `Value`（度，[0,90]）+ `IsOk` | 规格三项（**不乘当量**） | 无向夹角：0° 与 170° 的两线报 10° |
| 求交 | 线+线 / 线+圆 / 圆+圆（顺序随意） | `Geometry`（一个交点） | 无 | 近平行 / 不相交 / 同心内含都明确失败；两解时只给**一个固定解**，交点个数不外露 |
| 垂足 | 点+线（顺序随意） | `Geometry`（垂足点）+ `Value`（垂距） | `MmPerPixel` | **不做判定**（`IsOk` 恒 false）；垂足是"到无限直线"的投影，落在线段延长线上照样给 |
| 平行/垂直 | 两条线 | `IsOk` + `Value`（实测夹角） | `AngleTolerance`、`RelationKind` | **不看标准值与上下公差**；平行 = 夹角 ≤ 容差，垂直 = 夹角与 90° 的差 ≤ 容差 |
| 圆关系 | 两个圆 | `Value`（圆心距）+ `IsOk` | `MmPerPixel`、规格三项 | 同心怎么判：`StandardValue` 留 0 + 上下公差填允许的圆心偏量 |
| 构造 | 两点（构线）/ 三点（构圆） | `Geometry`（线或圆） | `ConstructMode` | 构线的锚点 = 两点中点、方向 = 两点连线；三点共线直接失败；**不做判定**、不乘当量 |

## 参数怎么调

| 参数（端口） | 默认 | 调大 / 调小分别会怎样 |
| --- | --- | --- |
| `MmPerPixel` | 0（= 不换算） | 没接线时它是**手填的当量**：填 0 或负数 → 输出像素；填准 mm/px → 输出 mm。接了上游（「标定」）就**以上游为权威**：上游值 ≤0 / NaN / Inf 时本步骤直接失败，**不会悄悄退回手填值**（那是标定本轮真失败了，必须让线停下来） |
| `StandardValue` | 0 | 用图纸名义值。填 0 又不动公差 = 零容忍，**默认全 NG 是有意的**（平台不假装知道你产品的规格） |
| `UpperTolerance` | 0 | 调大 → 向上允更多偏差；填 0 就是"不许偏上"。与标准值同单位（接当量后是 mm） |
| `LowerTolerance` | 0 | 调大 → 向下允更多偏差；**按幅度填正数**（判定式 `值 ≥ 标准值 − 下公差`），填负数等于把下限往上抬 |
| `AngleTolerance` | 0.1 度 | 调大 → 平行/垂直更容易判 OK（"距离 + 两线"的平行预检也跟着放宽）；调小 → 严。填 0 或负数按 0.1 兜住 |
| `RelationKind` | 平行 | 只影响"平行/垂直"模式：选垂直就按离 90° 有多近来判 |
| `ConstructMode` | 过两点构线 | 三点构圆会去读 `C`，其他模式不读 `C` |
| `SrcImage` / `DisplayViewIndex` | 未接 / 1 | 不接图像就一行都不显示（不影响 `Value` / `Geometry` / `IsOk`）；窗口填 0 同理 |

## 图上看什么

**只有本步骤成功的轮次才推图**。输入基元画**绿色**、结果基元画**红色**；左上角一行文字是 `模式 = 数值`
（`IsOk` 为 true 时绿字、否则黄字），信息栏三行：模式 / 结果 / 判定。
点画"点"标注固定带字母 `P`；线的标注是按示意长度画的（见上文"基元的线是无限直线"）。
