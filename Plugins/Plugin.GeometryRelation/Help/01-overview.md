# 几何计算

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryRelation

吃上游的**几何基元**（点 / 线 / 圆），算它们之间的**关系**：距离、夹角、求交、垂足、平行垂直、圆关系、构造（连线构圆）。
输出要么是**数值**（`Value`，可判定 OK/NG），要么是**新基元**（`Geometry`，可以接着喂给下一个「几何计算」，串成表达式树）。
它**不找边**（那是「几何查找」）、**不碰图像像素**（纯数学，图像只是拿来叠一层标注给人看）。

## 为什么需要它

现场要的是"这条边到那个圆心多少毫米""两条边是不是垂直"，而单个算子只会报自己那一个量。
把基元当数据传下去、用一个算子算关系，好处有三：**不用为每一种组合新增算子**（七种模式覆盖常见关系）、
**中间结果能复用**（求出的交点可以接着量距离）、**换产品只改连线不改流程结构**。

**为什么是纯托管数学而不是调视觉库**：这些关系都有闭式解，写成托管代码能逐条被断言钉死
（合成已知量对解析解，误差控到 1e-9），而调库的结果没法逐值验证。附带两个好处：跑得快、结果与平台版本无关。
代价是**不与「卡尺测量」的角度逐值一致**——卡尺的角度依赖"点分布取向"（射线口径 0~180°），
本算子的基元只带 (行, 列, 方向角) 没有那个取向，所以夹角一律给**无向夹角 [0,90]**（见下面的口径）。

## 原理（一次运算的骨架）

```
A（必接基元） [+ B / C]
   ↓ 按 Op 选模式 → 校验类型（Kind 不对就明确失败，不硬算）
   ↓ 纯几何公式（方向单位向量 = (sin φ, cos φ)，φ 为线的方向角、度）
   ↓ 长度类结果 × 像素当量（角度类不乘）
   ↓ 有规格的模式做判定：值 ∈ [标准值 − 下公差, 标准值 + 上公差]
Value / Geometry / IsOk（成功时把输入与结果叠到 SrcImage 上推视图窗口）
```

基元是**不可变**的：本算子只做换算、产新对象，绝不就地改上游那个基元
（否则两个下游共享同一对象时，一个改动会把另一个的结果悄悄改掉）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Op` | 是 | 关系模式：距离 / 夹角 / 求交 / 垂足 / 平行垂直 / 圆关系 / 构造（默认**距离**）。界面上是中文，流程里存成员名 `Distance` / `Angle` / … |
| `A` | 是 | 几何 A（`GeometryParam`，点/线/圆）。为空即失败：`几何计算：输入 A 为空（请接上游几何基元：几何查找 / 卡尺 FittedGeometry）` |
| `B` | 否 | 几何 B。除"构造-过两点构线/三点构圆"外的所有模式都要它，没接会明确报"××模式需要输入 B" |
| `C` | 否 | 几何 C。**只有"构造 + 三点构圆"用**，其余模式完全不看它 |
| `MmPerPixel` | 否 | 像素当量（mm/px），接「标定」的 `MmPerPixel`。**未接且手填 ≤ 0 = 数值直接输出像素**（不假装是 mm） |
| `StandardValue` | 否 | 标准值（判定用，默认 0） |
| `UpperTolerance` | 否 | 上公差（默认 0 = 零容忍） |
| `LowerTolerance` | 否 | 下公差（默认 0 = 零容忍；按**幅度填正数**，判定式是"值 ≥ 标准值 − 下公差"） |
| `AngleTolerance` | 否 | 角度容差（度，默认 0.1）。"平行/垂直"用它判；"距离 + 两条线"也用它先验平行（填 ≤ 0 时按 0.1 兜） |
| `RelationKind` | 否 | 平行 / 垂直（默认**平行**）。**只有"平行/垂直"模式看它** |
| `ConstructMode` | 否 | 构造方式：过两点构线 / 三点构圆（默认**过两点构线**）。**只有"构造"模式看它** |
| `SrcImage` | 否 | 叠加显示用的图像：接上游图像源，把输入与结果画在它上面。**不接 = 不显示**（算法照跑） |
| `DisplayViewIndex` | 否 | 显示窗口：`0` = 不显示，`1~9` = 主界面第几个图像窗口（默认 1，填大于 9 按 9 处理） |
| `Success` / `ErrorMessage` | — | 基类自带：本步骤是否跑通、失败时的中文原因 |

> 「必填」= 端口自己声明的 `IsRequired`：既没连线、步骤数据里又没有常量值时，编译报 `[参数缺失] '<端口>' 未配置`；打开一次「模块参数」点确定，默认值就存成常量，之后不连线也能跑。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Value` | 数值结果：距离/圆心距（像素，接当量后 mm）、夹角/平行垂直的实测夹角（**度**，[0,90]）、垂足模式的垂距。不做数值输出的模式为 0 |
| `Geometry` | 基元结果：求交的**交点**、垂足的**垂足点**、构造出的**线或圆**。其余模式为 null。可继续喂给下一个「几何计算」 |
| `IsOk` | 判定结果（true = OK）。**只有距离 / 夹角 / 圆关系 / 平行垂直四种模式会写它**；求交、垂足、构造恒为 false |

## 模式清单（`Op` 决定一切）

| 模式 | 要什么样的输入 | 出什么 | 用哪些参数 | 备注 |
| --- | --- | --- | --- | --- |
| 距离 `Distance` | 点+点 / 点+线（顺序随意）/ 线+线（必须接近平行） | `Value`（长度）+ `IsOk` | `MmPerPixel`、规格三项、`AngleTolerance`（线线时验平行） | 线-线量的是**从 B 的锚点到线 A 的垂距**；两线不平行直接失败 |
| 夹角 `Angle` | 两条线 | `Value`（度，[0,90]）+ `IsOk` | 规格三项（**不乘当量**） | 无向夹角：0° 与 170° 的两线报 10° |
| 求交 `Intersect` | 线+线 / 线+圆 / 圆+圆（顺序随意） | `Geometry`（一个交点） | 无 | 近平行 / 不相交 / 同心内含都明确失败；两解时只给**一个固定解**，交点个数不外露 |
| 垂足 `PerpendicularFoot` | 点+线（顺序随意） | `Geometry`（垂足点）+ `Value`（垂距） | `MmPerPixel` | **不做判定**（`IsOk` 恒 false）；垂足是"到无限直线"的投影，落在线段延长线上照样给 |
| 平行/垂直 `LineRelation` | 两条线 | `IsOk` + `Value`（实测夹角） | `AngleTolerance`、`RelationKind` | **不看标准值与上下公差**；平行 = 夹角 ≤ 容差，垂直 = 夹角与 90° 的差 ≤ 容差 |
| 圆关系 `CircleRelation` | 两个圆 | `Value`（圆心距）+ `IsOk` | `MmPerPixel`、规格三项 | 同心怎么判：`StandardValue` 留 0 + 上下公差填允许的圆心偏量 |
| 构造 `Construct` | 两点（构线）/ 三点（构圆） | `Geometry`（线或圆） | `ConstructMode` | 构线的锚点 = 两点中点、方向 = 两点连线；三点共线直接失败；**不做判定** |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（端口） | 默认 | 调大 / 调小分别会怎样 |
| --- | --- | --- |
| `MmPerPixel` | 0（= 不换算） | 没接线时它是**手填的当量**：填 0 或负数 → 输出像素；填准 mm/px → 输出 mm。接了上游（「标定」）就**以上游为权威**：上游值 ≤0/NaN/Inf 时本步骤直接失败，**不会悄悄退回手填值**（那是标定本轮真失败了，必须让线停下来） |
| `StandardValue` | 0 | 用图纸名义值。填 0 又不动公差 = 零容忍，**默认全 NG 是有意的**（平台不假装知道你产品的规格） |
| `UpperTolerance` | 0 | 调大 → 向上允更多偏差；填 0 就是"不许偏上"。与标准值同单位（接当量后是 mm） |
| `LowerTolerance` | 0 | 调大 → 向下允更多偏差；**按幅度填正数**（判定式 `值 ≥ 标准值 − 下公差`），填负数等于把下限往上抬 |
| `AngleTolerance` | 0.1 度 | 调大 → 平行/垂直更容易判 OK（"距离 + 两线"的平行预检也跟着放宽）；调小 → 严。填 0 或负数按 0.1 兜住 |
| `RelationKind` | 平行 | 只影响"平行/垂直"模式：选垂直就按离 90° 有多近来判 |
| `ConstructMode` | 过两点构线 | 三点构圆会去读 `C`，其他模式不读 |
| `SrcImage` / `DisplayViewIndex` | 未接 / 1 | 不接图像就一行都不显示（不影响 `Value`/`Geometry`/`IsOk`）；窗口填 0 同理 |

本插件**没有自定义配置界面**，也没有 `[StepConfig]` 常量：双击步骤（或右键「模块参数」）打开的是**输入端口清单**，
每行 = 参数名 + 值输入框 + 🔗（连上游）+ ✕（清除连线）——参数与连线是同一张表。

## 现场现象 → 先查什么

| 现场现象 | 先查这里 |
| --- | --- |
| `输入 A 为空` | ① `A` 到底连了谁（能喂的是「几何查找」的 `Geometry` 或本算子自己的 `Geometry`）；② 上游那一步本轮是否失败——失败步骤的输出是空的 |
| `××模式需要输入 B` | 该模式确实要两个特征：把第二个「几何查找」的 `Geometry` 连到 `B` |
| 报"距离模式不支持 Circle 与 Line 的组合" | 这是当前实现的边界：**距离 / 垂足只认点与线**，圆基元只能进「圆关系」和「求交」。要"圆心到边的垂距"就用「卡尺测量」的点到线距类型，或在脚本类算子里拿「几何查找」的 `Row`/`Col` 数值自己算 |
| 距离模式的两条线不平行 | 两线夹角超出 `AngleTolerance`（默认 0.1°，很严）。先确认现场是不是"两条平行边"；本来就要求非平行关系就改用「求交」；确属平行但上游抖动大就放宽 `AngleTolerance` |
| 报"两线近平行，交点数值不可信" | 正常保护：交点会跑到很远。把两条边取得更长/更斜，或改测距离 |
| 报"直线与圆不相交 / 两圆不相交或同心内含" | 真不相交就是真不相交：核对上游基元摆对了吗（圆找成了弧、线偏出目标），别放宽阈值 |
| 报"三点共线，无法确定外接圆" | 三个点近似在一条直线上：换三个分布开的点（尽量靠近圆周而非同一侧） |
| 数值整体大/小一个倍数 | 当量：`MmPerPixel` 接的是哪一步、本轮标定是否成功；没接线时输出的是**像素**，别当 mm 用 |
| 接了当量却报"上游像素当量无效" | 上游「标定」本轮失败或值为 0/NaN。二选一：查标定；或断开 `MmPerPixel` 连线、改成手填 |
| 夹角跟我量的差 90°／是补角 | 本算子给**无向夹角 [0,90]**（两条直线的真实夹角）。要"射线口径 0~180"请用卡尺的角度类型，别在这里放宽容差 |
| 判定一直 NG | 规格三项还是默认 0/0/0；另外注意**求交 / 垂足 / 构造根本不做判定**（`IsOk` 恒 false），别拿它们分流 |
| "平行/垂直"填了标准值不生效 | 该模式只看 `AngleTolerance`，标准值/上下公差对它无用 |
| 图上看不到标注 | ① `SrcImage` 没接（本算子不像「几何查找」有原图可推）；② 窗口填 0；③ 本轮步骤失败——**只有成功的轮次才推图**。注意本算子的显示异常**不留日志**，查不出来就按这三条自查 |
| 构造出的线在图上长得离谱 | 基元只带"一点 + 方向角"、没有端点，显示时按示意线画（长度取图对角线的 1/4）。**长度不是测量值**，别看图上那根线估尺寸 |

## 口径与失败策略

- **坐标系**：图像像素系 `(Row, Col)`；角度单位**度**，线方向角 [0,180)（与「几何查找」同一口径）。
- **单位**：长度类 = 像素 × 像素当量；**未标定就是像素**（不假装是 mm）。**夹角/平行垂直永远是度**，与当量无关。
- **判定式**：`标准值 − 下公差 ≤ 值 ≤ 标准值 + 上公差`（含边界，容 1e-9 的浮点余量）。
- **NG 不是失败**：超限只是正常结果，`Success` 仍为 true、流程继续。**分流看 `IsOk`，别看步骤红绿**。
- **失败就是失败**：类型不匹配、缺输入、几何退化（近平行 / 不相交 / 同心内含 / 三点共线）、上游当量无效，一律**明确失败并给中文原因**，绝不返回"看着合理"的兜底值。
- **每轮开头清零**：`Value` = 0、`Geometry` = null、`IsOk` = false。失败轮下游读到的是空值，不是上一轮的残留。
- **推图时机**：仅在本步骤成功时；`SrcImage` 未接或窗口 0 则跳过。输入基元画**绿色**、结果基元画**红色**，左上角一行 `模式 = 数值`（`IsOk` 为 true 绿字、否则黄字），信息栏三行：模式 / 结果 / 判定。
- **显示层不拖垮流程**：渲染异常一律忽略（与「几何查找」不同，这里不写 Warn 日志）。
- **并行安全**：纯托管计算、不写全局变量，可放进并行分支。

## 典型用法 / 接线

```
图像采集.OutputImage ──▶ 几何计算.SrcImage        （只为叠加显示；不接就不显示）
几何查找#1.Geometry  ──▶ 几何计算.A
几何查找#2.Geometry  ──▶ 几何计算.B
标定.MmPerPixel      ──▶ 几何计算.MmPerPixel      （推荐：当量跟着标定走，忘重标当场失败）
几何计算.Geometry    ──▶ 几何计算#2.A              （表达式树：交点接着量距离）
几何计算.Value       ──▶ CSV记录 / 结果显示.r1     （格式 F3，单位 mm）
几何计算.IsOk        ──▶ 结果上报.判定字段
量"两条平行边之间的间距"：
几何查找(边1).Geometry ──▶ 几何计算.A
几何查找(边2).Geometry ──▶ 几何计算.B              Op=距离 → Value（两线先过平行预检，不平行直接失败）
量"两个圆的圆心距"：同样两条线改 Op=圆关系 → Value + IsOk
```

## 常见问题

**Q：卡尺的 `FittedGeometry` 能直接连到 `A` 吗？**
不能——那是 XLD 轮廓（一堆点），`A` 要的是基元（`GeometryParam`），类型对不上。
（失败文案里提到它属于历史口径，别照着找。）能喂 `A` 的是「几何查找」的 `Geometry` 和本算子自己的 `Geometry`。

**Q：想量两个圆的圆心距，用"距离"模式？**
不行，"距离"只认 点-点 / 点-线 / 平行线。两个圆请用**圆关系**模式（它就是圆心距 + 判定）。

**Q：点到线的距离，垂足落在线段外面还算吗？**
算。基元的线是**无限直线**（一点 + 方向角，没有端点），量的是垂直距离，不是"到最近端点"。
要端点关系就先在「几何查找」里把范围收到那一段，或用垂足/求交拿到点再量点-点。

**Q：求交给出的是哪一个交点？**
线-圆 / 圆-圆 有两个解时只输出**一个固定解**（取点的分支在公式里写死了，没有"取第几个解"的参数，交点个数也不外露）。圆-圆想拿另一个解可以把 `A` / `B` 两个圆**对调**（对调翻掉垂直偏移的方向，正好取到另一侧）；线-圆没有这种开关（线的方向角已归一化到 [0,180)，"反向"就是同一条线）。上线前务必用标注图（结果基元画红）确认取到了哪一侧。

**Q：不接当量，`Value` 是什么单位？**
像素。所以同一流程里"接没接标定"会让数值差几十倍——上线前把当量来源固定成连线（`标定.MmPerPixel`），
别靠手填，手填值换相机就没人提醒你了。

**Q：夹角 8° 的两条线判平行 NG？**
正常，`AngleTolerance` 默认 0.1°。现场"平行"的允差是多少就填多少（比如 2°），别改标准值——那个参数对它不起作用。

**Q：为什么"求交 / 构造"这轮的 `IsOk` 是 false，流程却当它 NG 了？**
这两个模式不做判定，`IsOk` 恒 false。它们的成败看 `Success`（失败就是拿不到交点/构不出圆），
分流别接 `IsOk`。

**Q：能把这些值当"点胶路径"喂给运动控制吗？**
基元是**像素系**的，机械手要的是物理坐标。先经当量/位姿换算，并且**角度口径要确认**（本算子的方向角是"沿线方向"，
与卡尺搜索区的"扫描方向"差 90°）。这一步没做对，表现是"每颗胶都偏一个固定距离/固定转角"。
