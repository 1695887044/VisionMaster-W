# 几何计算 · 口径与判定

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryRelation

这页把"数字到底是什么意思"一次讲清：单位从哪来、判定式怎么算、哪几种模式压根不判定、
以及所有失败文案的原文（现场报错时对着查）。

## 坐标系与单位

- **坐标系**：图像像素系 `(Row, Col)`，Row 向下、Col 向右；角度单位**度**，线方向角归一化到 [0,180)。
- **方向口径**：直线的方向单位向量是 `(sin φ, cos φ)`，所以 **φ=0 → 沿 +Col（水平向右）**、**φ=90 → 沿 +Row（竖直向下）**。
  这与「几何查找」同一口径；与「卡尺测量」的角度（扫描方向）**差 90°**，不是 bug，是两套定义。
- **长度类** = 像素 × 像素当量；**未标定就是像素**（不假装是 mm）。
- **角度类（夹角、平行/垂直的实测夹角）永远是度**，与当量无关，也不受当量端口影响。
- **构造模式不乘当量**：它输出的是基元，坐标仍是像素系。

## 判定式（谁判、谁不判）

判定式：**`标准值 − 下公差 − 1e-9 ≤ 值 ≤ 标准值 + 上公差 + 1e-9`**（含边界，留 1e-9 浮点余量）。
三个参数默认都是 0，即**零容忍**：不填规格就一定 NG，这是有意的——平台不假装知道你产品的规格。

| 模式 | 写不写 `IsOk` | 判的是哪个值 |
| --- | --- | --- |
| 距离 | 判 | `Value`（乘过当量的长度） |
| 夹角 | 判 | `Value`（度，[0,90]） |
| 圆关系 | 判 | `Value`（圆心距） |
| 平行/垂直 | 判，但**不看规格三项** | 直接按 `AngleTolerance` 与 `RelationKind` 算出布尔值；`Value` 只是顺手给出的实测夹角 |
| 求交 | **不判** | `IsOk` 恒 false |
| 垂足 | **不判** | `IsOk` 恒 false |
| 构造 | **不判** | `IsOk` 恒 false |

**这三类"不判"是现状，不是漏配**：它们的成功含义是"拿到了交点 / 垂足 / 新基元"，属于失败域而非合格域。
副作用在显示层很直观——左上角那行字按 `IsOk` 上色，所以**求交、垂足、构造跑成功了一轮也显示黄字**
（求交模式 `Value` 不做数值输出、恒 0，于是图上会出现一行 `求交 = 0` 的黄字）。
**分流请看 `Success` 或 `Geometry` 是否为空，别接这三类的 `IsOk`。**

## 三条"要么不出现、要么就是真有问题"

- **NG 不是失败**：超差只把 `IsOk` 置 false，`Success` 仍为 true、流程继续、照样推图。
- **失败就是失败**：类型不匹配、缺输入、几何退化（近平行 / 不相交 / 同心内含 / 三点共线）、上游当量无效，
  一律明确失败并给中文原因，绝不返回"看着合理"的兜底值，也绝不悄悄退回手填当量。
- **每轮开头清零**：`Value` = 0、`Geometry` = null、`IsOk` = false。
  所以"本轮读到 0"要么是真的 0，要么是本轮失败/未判定，不会是你没看见的上一轮残值。

## 几何退化：为什么不"硬算下去"

| 情况 | 代码怎么做 | 为什么这样 |
| --- | --- | --- |
| 两线近平行求交 | 只有方向完全共线（\|det\| < 1e-15）才失败；近平行按 HALCON 返回远交点 | 真平行时交点不存在；"很远的交点"是数学事实，交给人看标注图判断 |
| 两线不平行却量距离 | 先按 `AngleTolerance` 验平行，不过就失败 | "非平行线的间距"没有单一答案 |
| 线与圆 / 两圆不相交 | 判别式为负 / 圆心距与半径和差的关系越界 → 失败 | 真不相交就是真不相交，不该放宽阈值 |
| 两圆同心或内含 | 直接失败 | 无交点或无穷多交点 |
| 三点共线构圆 | 分母绝对值小于 1e-9 → 失败 | 外接圆半径无穷大 |
| 两解的求交（线-圆 / 圆-圆） | 只输出**一个固定解**，交点个数不外露 | 圆-圆可把 `A`/`B` **对调**取到另一侧；线-圆没有这个开关（方向角已归一到 [0,180)，"反向"就是同一条线）。上线前用标注图（结果基元画红）确认取到哪一侧 |
| 点-线距 / 垂足 | 按**无限直线**算 | 基元只有"一点 + 方向角"，没有端点；垂足落在线段延长线上照样给 |

## 失败文案原文（逐条抄自源码）

| 文案 | 触发条件 |
| --- | --- |
| `几何计算：输入 A 为空（请接上游几何基元：几何查找 / 卡尺 FittedGeometry）` | `A` 为空 |
| `几何计算：上游像素当量无效（≤0 / NaN / Inf），标定步骤本轮可能失败——请检查「标定」接线` | `MmPerPixel` **已连线**且上游值无效 |
| `几何计算：未知模式 <Op>` | `Op` 落到未定义的枚举成员上 |
| `几何计算：距离模式需要输入 B` / `夹角模式需要输入 B` / `求交模式需要输入 B` / `垂足模式需要输入 B` / `平行/垂直判定需要输入 B` / `圆关系需要输入 B` | 对应模式下 `B` 为空 |
| `几何计算：距离模式的两条线不平行（平行线距才有意义）；如需非平行线关系请用「求交」` | 距离 + 两线，且夹角超 `AngleTolerance` |
| `几何计算：距离模式不支持 X 与 Y 的组合（支持 点-点 / 点-线 / 平行线）` | 距离模式收到圆或椭圆 |
| `几何计算：夹角模式需要两条线，实际收到 X 与 Y` | 夹角模式收到非线 |
| `几何计算：两线平行（方向共线），没有唯一交点` | 求交 + 两线方向完全共线（\|det\| < 1e-15）；近平行仍会给出远交点 |
| `几何计算：直线与圆不相交` / `几何计算：圆与直线不相交` | 线-圆（两种接法各一条）无实交点 |
| `几何计算：两圆不相交或同心/内含` | 圆-圆无交点 |
| `几何计算：求交模式不支持 X 与 Y（支持 线-线 / 线-圆 / 圆-圆）` | 求交收到点或椭圆 |
| `几何计算：垂足模式需要 点+线，实际收到 X 与 Y` | 垂足模式的两个输入不是点+线 |
| `几何计算：平行/垂直判定需要两条线，实际收到 X 与 Y` | 平行/垂直收到非两线 |
| `几何计算：圆关系需要两个圆，实际收到 X 与 Y` | 圆关系收到非两圆 |
| `几何计算：过两点构线需要 A、B 都是点` / `几何计算：三点构圆需要 A、B、C 都是点` / `几何计算：三点共线，无法确定外接圆` | 构造模式的输入不合规 |

上面 X / Y 位置显示的是基元类型（`Point` / `Line` / `Circle` / `Ellipse` / `Contour`），
`平行/垂直判定` 这类名字里的斜杠是固定文案，不是分隔符。

## 显示层

- **只有成功轮次才推图**；`SrcImage` 未接、未初始化或窗口 ≤ 0 就一行都不显示。
- 输入 `A`、`B` 画**绿色**，结果 `Geometry` 画**红色**；左上角文字 `模式 = 数值` 按 `IsOk` 上绿/黄。
- 窗口号 > 9 按 9 处理。
- **本算子的显示异常一律忽略且不留日志**（与「几何查找」不同，那里会写一句 Warn）。
  所以"图上没标注"不是错误信号：按 `SrcImage` 没接 / 窗口填 0 / 本轮步骤失败这三条自查。
