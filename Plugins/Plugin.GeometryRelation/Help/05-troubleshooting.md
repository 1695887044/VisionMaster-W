# 几何计算 · 排错与常见问题

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryRelation

## 现场现象 → 先查什么

| 现场现象 | 先查这里 |
| --- | --- |
| `输入 A 为空` | ① `A` 到底连了谁（能喂的只有「几何查找」的 `Geometry` 或本算子自己的 `Geometry`，见下面 Q1）；② 上游那一步本轮是否失败——失败步骤的输出是空的 |
| `××模式需要输入 B` | 该模式确实要两个特征：把第二个「几何查找」的 `Geometry` 连到 `B` |
| 报"距离模式不支持 Circle 与 Line 的组合" | 这是当前实现的边界：**距离 / 垂足只认点与线**，圆基元只能进「圆关系」和「求交」。要"圆心到边的垂距"就换用卡尺的点到线距类型，或在脚本类算子里拿「几何查找」的 `Row` / `Col` 数值自己算 |
| 距离模式的两条线不平行 | 两线夹角超出 `AngleTolerance`（默认 0.1°，很严）。先确认现场是不是"两条平行边"；本来就要求非平行关系就改用「求交」；确属平行但上游抖动大就放宽 `AngleTolerance` |
| 报"两线近平行，交点数值不可信" | 正常保护：交点会跑到很远。把两条边取得更长/更斜，或改测距离 |
| 报"直线与圆不相交 / 两圆不相交或同心内含" | 真不相交就是真不相交：核对上游基元摆对了吗（圆找成了弧、线偏出目标），别放宽阈值 |
| 报"三点共线，无法确定外接圆" | 三个点近似在一条直线上：换三个分布开的点（尽量靠近圆周而非同一侧） |
| 接了当量却报"上游像素当量无效" | 上游「标定」本轮失败或值为 0/NaN。二选一：查标定；或断开 `MmPerPixel` 连线、改成手填 |
| 数值整体大/小一个倍数 | 当量：`MmPerPixel` 接的是哪一步、本轮标定是否成功；没接线时输出的是**像素**，别当 mm 用 |
| 夹角跟我量的差 90° 或是补角 | 本算子给**无向夹角 [0,90]**（两条直线的真实夹角）。要"射线口径 0~180"请用卡尺的角度类型，别在这里放宽容差 |
| 判定一直 NG | 规格三项还是默认 0/0/0；另外注意**求交 / 垂足 / 构造根本不做判定**（`IsOk` 恒 false），别拿它们分流 |
| 步骤是绿的但 `IsOk` 是 false | 上面那条的镜像：不判定的三种模式成功时 `IsOk` 也 false，图上的字也是黄的（如 `求交 = 0`）。看 `Geometry` 有没有值来判断有没有成 |
| "平行/垂直"填了标准值不生效 | 该模式只看 `AngleTolerance`，标准值与上下公差对它无用 |
| 图上看不到标注 | ① `SrcImage` 没接（本算子不像「几何查找」自带原图可推）；② 窗口填 0；③ 本轮步骤失败——**只有成功的轮次才推图**。注意本算子的显示异常**不留日志**，查不出来就按这三条自查 |
| 构造出的线在图上长得离谱 | 基元只带"一点 + 方向角"、没有端点，显示时按示意线画（长度取图对角线的 1/4）。**长度不是测量值**，别看图上那根线估尺寸 |
| 交点取到另一侧去了 | 线-圆 / 圆-圆有两个解，本算子只给一个固定解。圆-圆可把 `A` / `B` 对调翻到另一侧；线-圆没有开关。用标注图（结果基元画红）核对 |

## 常见问题

**Q1：卡尺的 `FittedGeometry` 能直接连到 `A` 吗？**
不能。`FittedGeometry` 是 XLD 轮廓（一堆点，`HXLD` 类型），`A` 要的是基元（`GeometryParam`），
连线类型对不上、编译就接不了。
**注意**：`A` 为空时的那句失败文案里写着"请接上游几何基元：几何查找 / 卡尺 FittedGeometry"，
后半句是**历史口径、照着找会白跑一趟**——照前半句接「几何查找」的 `Geometry`，或接本算子自己的 `Geometry`。

**Q2：想量两个圆的圆心距，用"距离"模式？**
不行，"距离"只认 点-点 / 点-线 / 平行线。两个圆请用**圆关系**模式（它就是圆心距 + 判定）。

**Q3：点到线的距离，垂足落在线段外面还算吗？**
算。基元的线是**无限直线**（一点 + 方向角，没有端点），量的是垂直距离，不是"到最近端点"。
要端点关系就先在「几何查找」里把范围收到那一段，或用垂足/求交拿到点再量点-点。

**Q4：不接当量，`Value` 是什么单位？**
像素。所以同一流程里"接没接标定"会让数值差几十倍——上线前把当量来源固定成连线（`标定.MmPerPixel`），
别靠手填，手填值换相机就没人提醒你了。

**Q5：夹角 8° 的两条线判平行 NG？**
正常，`AngleTolerance` 默认 0.1°。现场"平行"的允差是多少就填多少（比如 2°），别改标准值——那个参数对它不起作用。

**Q6：为什么"求交 / 垂足 / 构造"这轮的 `IsOk` 是 false，流程却当它 NG 了？**
这三种模式不做判定，`IsOk` 恒 false。它们的成败看 `Success`（失败就是拿不到交点 / 构不出圆），分流别接 `IsOk`。

**Q7：`Op` 换了模式，其它参数要不要跟着改？**
要。`MmPerPixel` / 规格三项 / `AngleTolerance` / `RelationKind` / `ConstructMode` 各有各的模式归属
（见「端口与参数」的模式表）。最常见的错是留着上一个模式的规格值当新模式的判定标准。

**Q8：`C` 端口平时要不要连？**
不连。只有"构造 + 三点构圆"会读它，其余模式完全不看它。

**Q9：能把这些值当"点胶路径"喂给运动控制吗？**
基元是**像素系**的，机械手要的是物理坐标。先经当量/位姿换算，并且**角度口径要确认**
（本算子的方向角是"沿线方向"，与卡尺搜索区的"扫描方向"差 90°）。这一步没做对，表现是"每颗胶都偏一个固定距离/固定转角"。

**Q10：同一份基元能不能喂给两个下游？**
能。基元不可变、本算子只产新对象，就地改上游那种写法在这里不存在，
所以"求出的交点既量距离又量夹角"这种接法是安全的。
