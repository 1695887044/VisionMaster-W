# 几何计算 · 开发：不变量与陷阱清单

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryRelation ｜ 读者：开发

**改这个插件前逐条对照**：每条都是"必须成立的事实 + 不成立时的症状 + 现在由谁守"。
A 类违反会当场红或抛，B 类违反后**静默**出错（难查得多）。

守门断言的真实分布（逐条回源码抄，没有的直说）：

- `FlowCanvasChecks\GeometryChecks.cs` —— 分节 `[GEO] 几何工具：GeometryMath 纯函数 + GeometryParam 契约`，**22 条**
  `Check(...)`：公式层 14 条 + `GeometryParam` 契约 4 条 + 枚举端口回写链路 3 条 + 轮廓 JSON 1 条。
  它**只测托管数学与契约**，头注写明"HALCON 找边/拟合（GeometryFinder 的算子层）不在此断言——它依赖真算子，另由现场/探针验"。
- `FlowCanvasChecks\GeoDemoCheck.cs` —— 分节 `[GEODEMO] 演示方案：加载 → 编译 → 执行（几何查找 + 几何计算）`，**13 条**，
  跑 `解决方案\几何工具演示.vms`（9 步：采集 / 两个 ROI / 两个几何查找 / **几何计算_夹角** / **几何计算_交点** / 采集圆图 / 查找圆），
  末尾另有三条"直接调插件"的数值断言。
- `FlowCanvasChecks\ParallelExecutionChecks.cs:266` —— `标注 [ParallelSafe] 的 18 个插件 DLL 全部含特性元数据（漏重建=门禁误报）`，清单含 `Plugin.GeometryRelation.dll`。
- **本插件的七个分派分支里，只有夹角、求交被端到端跑过**；距离 / 垂足 / 平行垂直 / 圆关系 / 构造五种模式的
  校验分支与失败文案**无断言，靠人工核对**（公式本身有 22 条覆盖，缺的是"模式接线与文案"这一层）。

## A 组：违反会当场红或抛

**A1 公式方向口径只有一份**
`Direction(phiDeg) = (sin φ, cos φ)`（`GeometryMath.cs:20-24`）：φ=0 沿 **+Col**、φ=90 沿 +Row。
所有距离/垂足/求交/示意线都从它派生。
症状：写成 `(cos, sin)` → 数值仍然"看着合理"，但**垂足与交点全在镜像位置**，且角度类断言立刻红。
守门：`点-线距 点(5,0) 到 row=0 水平线 = 5`、`垂足 点(5,0) → row=0 线上 = (0,0)`、`线-线求交 row=5 与 col=3 → (5,3)`、
`过两点构线 (0,0)-(0,4) → 中点(0,2) phi=0`。

**A2 夹角必须落在 [0,90]**
`AngleBetweenLines` = `|φ1−φ2| % 180`，大于 90 折成 `180 − d`（:48-52）。
症状：忘了折角 → 0° 与 170° 报 170，`AreParallel` 判不出平行，"距离 + 两线"整批失败。
守门：`夹角 0° 与 90° = 90`、`夹角 0° 与 10° = 10`、`夹角 0° 与 170° = 10（补角归一，不是 170）`、`夹角恒在 [0,90]`。

**A3 几何退化必须"明确 false"，不许硬算**
线-线只有方向完全共线 `|det| < 1e-15`（:68）才 false（近平行按 HALCON 给远交点）、线-圆 `disc < 0`（:92）、
圆-圆 同心/相离/内含（:113-116，相离/内含的容差是 `1e-12`）、三点共线 `|d| < 1e-9`（:154）。
症状：把这些改成"返回最近点"→ 交点跑到图外、数值巨大但流程全绿，是最贵的一类静默错。
守门：`平行线求交 → false（明确失败）`、`同心圆求交 → false`、`三点共线构圆 → false（明确失败）`、
`线-圆求交 圆心(0,0) R=5 与 col=0 线 → 交点在圆上`、`圆-圆求交 两 R=5 圆心距 8 → 交点在两圆上`、`三点构圆 直角三角 → 圆心(2,2) r=√8`。

**A3b 残差是"像素距离"，椭圆用最短欧氏距**
`PointResidual`（:160）：线=点到无限直线、圆=`|点到圆心 − R|`、椭圆=法向 Newton 求最短欧氏距（`EllipseDistance`，:206）。
症状：用"归一化残差 × 短半轴"近似 → 长轴方向按扁率低估（100×50 椭圆外移 10px 算成 5px），与 HALCON `distance_pc` 对不上。
守门：`轴外点(5,12) = 4.1177`、`长轴外溢点(0,12) = 2`（旧近似给 2.81 / 1）。

**A4 枚举端口的还原链路（三段，各有断言）**
`.vms` 存数值 → `ApplyConfigValues` → `port.Value = object` → `ValueConverter.Convert` → 枚举。
症状：转换器少认一种形态 → 下拉改了没效果，或**重开方案后模式跳回默认**（试运行对、重启错）。
守门：`ValueConverter 字符串→枚举（参数面板下拉回写路径）`、`ValueConverter 数值→枚举（JSON 加载路径，Int64→枚举）`、
`枚举端口接受下拉回写的值（Kind → 圆）`（第三条实例化的是姊妹插件「几何查找」，同一条链路）。

**A5 基元必须能 JSON 往返**
`GeometryParam` 有公共无参构造 + `Points` 数组，跨插件/全局变量/方案文件都要序列化。
症状：换成 struct 或去掉无参构造 → 方案存不下基元，`A`/`B` 连线还原成 null。
守门：`GeometryParam JSON 往返一致（Newtonsoft）`、`GeometryParam 轮廓 JSON 往返（Points 数组）`、
`工厂构造：Line 的 Phi 已被归一化（200→20）`、`Phi 归一化 [0,180)：-10→170, 190→10, 180→0`。

**A6 真链路编译必须过**
端口名与连线类型是 `.vms` 最容易翻车的两处（`GeoDemoCheck` 头注列了四点：`$type` 白名单、端口名对不上、
连线类型不匹配、动态端口重建时机）。
症状：改端口名（属性名即端口名）后编译报端口不存在，或连线上 `GeometryParam` 对不上。
守门：`流程编译通过（端口存在、连线类型匹配）`、`流程步骤依次与预期一致（9 步）`、
`几何计算_夹角 的 A/B 连到两个几何查找的 Geometry 输出`、`全部 9 步执行成功（无失败/未执行）`、
`采集 / ROI / 几何查找 / 几何计算 四个插件程序集可装载`、`生产加载器能打开这份方案`、`方案里能找到目标流程「几何工具演示」`、
`演示方案文件存在`、`流程执行无异常`。

## B 组：违反后**静默**出错（认知类与现状类）

**B1 `IsOk` 只有四种模式会写**
`Judge` 只在 :176 / :189 / :268 被调；`DoLineRelation` 另走容差直接写 `IsOk`（:253）；
求交 / 垂足 / 构造三条分支从不碰 `IsOk`，它在轮首被置 false（:107）后就留在那儿。
症状（**现场已经出现过**）：拿 `IsOk` 做分流 → 求交成功的轮次被判成 NG；显示层同样按 `IsOk` 上色，
所以图上出现 `求交 = 0` 的**黄字**（`Value` 根本没被写过，恒 0）。
守门：**无断言，靠人工核对**——这条要改就得先定义"这三类模式的成功语义是否等于 OK"。

**B2 三个输出的清零只有 :105-107 三行**
`double` / `GeometryParam` / `bool` 都不是 `IDisposable`，基类轮首回收（`DisposePreviousRoundOutputs`，
`VisionPluginBase.cs:150-157` 只收 `port.Value is IDisposable`）管不到它们；本插件 `Dispose()`（:143）是**空重写**
且不调 `base.Dispose()`——因为没有可回收的端口值，所以**不产生泄漏**，但也不能指望基类兜底。
症状：新增输出端口忘了补清零 → 跨轮残值，数值"时对时错"，最难查的一类。
守门：**无断言，靠人工核对**（`全部 9 步执行成功` 只走成功路径，不验残值）。

**B3 当量的"连线就以上游为权威"**
`TryResolveScale`（:319-340）：`LinkedSource != null` 且上游值 ≤0/NaN/Inf → **明确失败**，
绝不静默回退手填值；未连线时 ≤0/NaN 才按"未标定 = 输出像素"。
症状：把这条改成"上游无效就用手填" → 标定本轮失败却照旧出数，产线拿着像素当毫米用，偏差是几十倍不是百分之几。
守门：**无断言，靠人工核对**（演示方案没接标定步骤，走的是"未连线"分支）。

**B4 距离模式的线-线只量"B 锚点到线 A 的垂距"**
:166 `DistancePointLine(GeometryParam.Point(b.Row, b.Col), a)`——两条线在基元里只有"一点 + 方向角"，
没有"两条平行线之间的距离"这一独立公式，靠锚点承载。
症状：上游换了拟合方式、锚点从"中点"变成别的，同一个物理间距会给出不同数值。
守门：线-线组合本身**无断言，靠人工核对**（`点-线距` 那条守的是公式，不是这条口径）。

**B5 圆-圆 / 线-圆求交只给一个固定解**
`TryIntersectCircles` 取 `+h·perp`（:123-124）、`TryIntersectLineCircle` 取较小 t（:95），
`count` 算出来但**不回传任何输出端口**。
症状：现场要"另一个交点"时没有参数可填，只能把 `A`/`B` 对调（圆-圆有效，线-圆无效）。
看起来"随机取一侧"，其实是写死的分支。守门：`圆-圆求交 两 R=5 圆心距 8 → 交点在两圆上`
只断言"在两个圆上"，**不钉死是哪一侧**——所以这一条属于无断言、靠人工核对（对调即可翻侧要记在用户页）。

**B6 显示层的三处静默**
① `if (Success.Value is true) Publish(...)`：失败轮一行都不推（不是 bug，但会让人以为"没图 = 插件坏了"）。
② `try { PublishPreview(...) } catch { }`（:373-374）**不留日志**——姊妹插件「几何查找」的 `Publish` 是写了 Warn 的。
③ 线的标注长度取 `sqrt(w²+h²)/4`（:390）是**示意**，图上线的长短不是测量值。
症状：查"图上没标注"时日志里没有任何线索。守门：**无断言，靠人工核对**。

**B7 `Op` 加了成员必须末尾追加 + 补 switch**
`.vms` 存的是枚举**数值**：在中间插成员会让旧方案的所有模式集体错位（编译、运行都不报错，只是全跑成别的模式）。
忘了补 `case` 则命中 :135 `Fail("几何计算：未知模式 <Op>")`。
守门：**无断言，靠人工核对**（改枚举后跑 `gate` 也抓不到，必须重开演示方案对照步骤名）。

**B8 与「几何查找」的两处口径差，别在文档里写反**
① 本插件的 `Phi` 是"沿线方向、[0,180)"，`GeometryParam.Line` 工厂已归一化；卡尺的角度是另一套（射线口径）。
② 本插件**不乘当量的是角度与构造**，乘当量的是距离 / 垂距 / 圆心距。
症状：手册写反后，现场按 mm 读角度、或按像素读长度，偏差方向完全相反。
守门：`直接调用：两线夹角 = 90°（实测 …°）`（角度路径，不受当量影响）。

**B9 断言直接调 `RunAlgorithm(null)`，绕过了基类外壳**
`GeoDemoCheck` 里 `rel.RunAlgorithm(null)` 不经 `Execute`：
`Success` 预置、轮首回收、异常转 `Fail` 这三件事在那三条断言里**没有被走到**。
症状：给 `RunAlgorithm` 加了依赖 `context` 的代码（如 `context.Logger`）→ 断言里 NRE，
或反过来"测试全绿、真流程抛"。守门：**无断言覆盖这条**；改完要么补走 `Execute` 的用例，要么保证 `context` 可空。

## 并行安全声明的依据（`[ParallelSafe]`）

纯托管算术、无 static 可变字段（`GeometryMath` 全是无状态 `static` 方法）、不碰进程级独占资源、
不写全局共享状态；耗时微秒级，无需分段检查 `context.CancellationToken`。
**代价**：本插件读 `A`/`B`/`C` 拿到的 `GeometryParam` 与上游是同一引用——不可变性（`init` 属性）是它敢并行的前提。
任何一方将来改成可变（例如加 `TranslateSelf()`），这条声明立刻不成立，且并行下表现为偶发错值。
