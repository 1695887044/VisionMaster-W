# 结果上报 · 排障

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload

下面每条文案都是从源码抄下来的**原文**（`…` 处是变量内容），界面/日志里能逐字搜到。
先看级别：WARN/ERROR 由后台线程产生，**会暂存到下一次本步骤执行时转交宿主日志**——
所以软件刚启动、流程还没跑到这一步时看不到后台日志，属正常现象，不是丢了。
后台转交队列最多暂存 500 条（超出丢最老的）；配置面板底部的「最近上报日志」是另一份独立账本，
只留最近 50 条，日志已经转交宿主之后它仍然看得到。

## 一、日志原文 → 查哪一项

| 原文 | 级别 | 处置 |
| --- | --- | --- |
| `结果上报：未配置目标 URL，跳过本次上报` | WARN | `目标 URL` 空。勾了「上报失败阻断流程」时这条会变成步骤失败，消息为 `结果上报：未配置目标 URL` |
| `结果上报：字段表没有启用的字段，至少要有一个字段才有东西可上报` | WARN/失败 | 字段表全没勾「启用」或字段名全空白。至少留一行启用字段 |
| `结果上报：原始 JSON 模板为空` | WARN/失败 | 预设选了 `原始JSON` 但模板没填 |
| `结果上报：未知报文预设：<成员名>` | WARN/失败 | 报文预设存了代码里已经不认的值（老方案/手改 `.vms`）。重选一次预设 |
| `结果上报：组报文异常：…` | WARN/失败 | 模板/值内容异常，看后面的异常消息；先用面板「实际发出 →」预览复现 |
| `结果上报：发送队列已满，上报被拒（检查服务器是否长期不通）` | 步骤失败 | 只在**异步 + 勾了阻断**时出现。说明服务器长期不通，件已经塞满 1000 条 |
| `结果上报：发送队列正在关停，不再接收` | 步骤失败 | 正在关软件/停服务，属正常收尾 |
| `结果上报：…`（同步模式失败，内容是响应体或错误描述；空则为 `未知错误`） | WARN/失败 | 同步模式下失败原因直接进这条；勾了阻断则本步骤失败 |
| `[结果上报] 队列已满（1000 条），『…』一条上报被拒——请检查服务器是否长期不通` | WARN | 未勾阻断时的同一现象：件被丢弃（**不会落 spool**，因为压根没进队列）。这是真的丢数据，必须处理服务器不通 |
| `[结果上报]『…』上报失败（已重试 N 次）：超时（3000ms 无响应）` | WARN | 服务器不响应：查 MES 服务/防火墙/URL 端口；`状态码` 会是 `0` |
| 同上，原因为 `HTTP 404 NotFound` / `HTTP 500 InternalServerError` | WARN | 状态码 + 状态名，服务端问题。非 2xx 一律算失败并重试 |
| 同上，原因为异常消息（如"无法连接到远程服务器"、"不知道这样的主机"） | WARN | 网络/DNS/URL 拼写。`状态码` `0` |
| `[结果上报]『…』已存入断网续传队列（…），网络恢复后自动补传` | WARN | 正常兜底动作，等网络恢复会自动补 |
| `[结果上报]『…』断网续传落盘失败：…` | ERROR | 程序目录没写权限/磁盘满/spool 文件被占用。spool 目录下的文件被编辑器独占也会这样 |
| `[结果上报] 断网续传读取失败：…` | ERROR | spool 文件读不了（损坏、被删、被占）。坏行会被跳过，整文件读失败才会出这条 |
| `[结果上报]『…』补传累计失败 50 次已放弃并删除，请检查该步骤的 URL/协议：…` | ERROR | 这条的报文**已永久丢弃**。去对应步骤查 URL/报文预设/鉴权 |
| `[结果上报] 补传连续失败，本轮中止（网络可能仍未恢复，下轮空闲再试）` | WARN | 网络还没恢复，无需干预 |
| `[结果上报] 断网续传补传成功 N 条` | INFO | 正常，欠账清了一部分 |
| `[结果上报] 断网续传账本清理失败（成功件下轮会凭幂等 ID 重发，由 MES 去重）：…` | ERROR | 补传成功但删行失败（文件被占）。下一轮会**重发**这些件，靠 MES 按 `X-Upload-Id` 去重；尽快释放文件占用 |
| `[结果上报] 断网续传积压已达上限 100000 条，丢弃最老的 N 条（保新弃旧）` | WARN | 长期不通的极端积压，最老件已丢。先修网络，再评估 MES 端如何补账 |
| `[结果上报]『…』上报线程异常：…` | ERROR | 后台线程被意外打断（罕见，发送与重试内部已兜底）。若反复出现，收集消息内容报修 |

## 二、面板「立即发送」的结果行（只写在界面，不是日志）

| 界面显示 | 含义 |
| --- | --- |
| `✘ 请先填目标 URL` | URL 空。此时不会发出任何东西 |
| `正在发送…` | 后台线程执行中，按钮置灰防重复点 |
| `✔ HTTP <码>（业务成功）` | 2xx 且命中关键字（没填关键字时 2xx 即算） |
| `✘ HTTP <码>，但响应未命中成功关键字『…』` | 连上了、MES 却回业务失败。**这是最常见的"200 但 MES 查不到记录"** |
| `✘ HTTP <码> <响应/错误>` | 非 2xx，或 `HTTP 0` 表示没连上 |
| `✘ <组包错误>` | 模板/字段表本身有问题（如 `字段表没有启用的字段…`、`原始 JSON 模板为空`、`组报文异常：…`） |
| `✘ 测试异常：…` | 发送过程抛出意外异常 |

结果行下面还会带一行 `→ <报文>`（实际发出内容）和一行 `← <响应>`（服务器返回），长文本截断到 300 字符。

## 三、现象 → 先查这里

| 现象 | 先查 |
| --- | --- |
| `状态码` 一直是 0 | 0 = **压根没拿到 HTTP 响应**：URL 写错/域名解析不了/防火墙拦了/MES 没起/超时。`响应` 里带具体原因。先用「立即发送」在同一台机器上验一次 |
| 字段值全是 `null` 或空 | ① 来源=端口 但**没连线**（预览里 `(空)` 就是没连上）；② 上游算子本轮失败（失败步骤的输出端口通常是空的）；③ 来源=变量 但**变量名打错**（区分大小写、只在本轮有效）；④ 字段名两边不一致（端口与键取 Trim 后的名字） |
| MES 说数值字段类型不对（收到的是字符串） | 看上游端口给的是什么类型：`double` 会写成 `12.3`（数值），文本会写成 `"12.3"`。要么上游保持数值类型，要么用 `原始JSON` 的 `{#名}` 原样注入 |
| 钉钉群里中文变成 `\u4EF6` | 本版本已修（中文不转义）。如果还看到，先确认**重建过插件工程**（改了插件源码只重建宿主，跑的还是旧 DLL） |
| 时间戳差 8 小时 | 勾「时间戳用 UTC」，或把时间格式改成带时区的格式（如 `yyyy-MM-ddTHH:mm:ss.fffZ`）。开启后**内置时间戳和值池里的时间**一起走 UTC，不会只转一半 |
| 该发的没发、不该发的照发 | 「仅NG上报」的两处要对上：`判定字段名` 必须是字段表里存在的字段名；`NG 判定值` 要等于该字段**本轮实际值**。若判定列接的是布尔端口（`True`/`False`）而 NG 值填 `NG`，就永远不相等。数值/布尔/文本三级比对见 04 页第八节 |
| 一条都不发（时机=触发端口） | 上游没给 `true`；或 `上报时机` 其实不是 `触发端口`。注意端口名是 `上报触发`，面板③里的"触发信号"就是它的连线入口 |
| 补传会不会让 MES 记重 | 不会重复**产生新单**：每条一个 GUID 作 `X-Upload-Id`，补传沿用原 ID。但**去重是 MES 端的责任**——上线前和 MES 侧确认它是否读这个头 |
| 节拍被拖长 | 检查是否取消了「异步队列」。同步模式最坏耗时 = `(重试+1) × 超时 + 退避之和`（默认约 15 秒）。另外勾了「上报失败阻断流程」时队列满也会让步骤失败 |
| 改了报文预设后模板内容没了 | 预设之间**不迁移**内容：钉钉切回 `MES字段表` 要自己重填。这是已知行为，不是丢数据 |
| 上报出去步骤名是 `未赋值` | 配置期引擎还没注入实例名，预览与测试发送会退回步骤名。真实执行时是 `流程名.步骤名` |

## 四、上线前自检

1. 报文预设、URL、超时、重试、异步/同步、阻断 六项按**本工位 MES 接口文档**核对一遍。
2. 面板「实际发出 →」结构对不对：键名与 MES 字段表**逐字一致**（大小写、下划线）。
3. 预览里凡是 `(空)` 的字段，都是"字段建了但值来路不通"——线没连 / 变量名不对 / 上游本轮失败。
4. 用「立即发送」在**这台机器**上真发一次（注意别打生产 MES，或先发测试接口），确认响应内容；
   留意它会把 `响应`/`状态码`/`已上报` 写成这次测试的结果。
5. MES 侧确认：非 2xx 的重试是否会产生重单，`X-Upload-Id` 是否被读取去重。
6. 「仅NG上报」工位：拿一件已知 NG / 已知 OK 各跑一次，确认发/不发的边界。
7. 程序目录 `ResultUploadSpool\` 是否存在、可写；把该目录纳入磁盘清理白名单。
8. 若用了同步模式：按 `(重试+1) × 超时 + 退避` 重估节拍，确认最坏情况仍在产线 CT 之内。
9. 请求头里的 token 与 spool 内容都是**明文**：方案文件与程序目录的访问权限按保密要求管。
