# 结果上报 · 字段映射与上报口径

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload

本页专管四件事：**字段值从哪来**、**报文怎么拼**、**发不出去怎么办**、**时间与编码口径**。
所有数值与判据都取自插件源码，与界面行为一致。

## 一、一个"字段名"到底管几件事

字段表里那一列**字段名**（源码 `UploadFieldDef.Name`，用作端口与 JSON 键时会 `Trim()` 掉两侧空格）同时决定三件事：

| 由字段名决定 | 具体表现 | 取值口径 |
| --- | --- | --- |
| JSON 里的键名 | 报文预设 = `MES字段表` 时，报文就是「字段名: 值」的平铺对象 | 写进 JSON 时**区分大小写**（`sn` 和 `SN` 会各出一个键） |
| 输入端口名 | 来源=`端口` 且勾了「启用」的字段，自动长出一个同名输入端口 | 建端口时**不区分大小写去重**，重名只建一个 |
| 占位符名 | 通知模板 / 原始 JSON 模板里的 `{字段名}` `{#字段名}` | 查值**忽略大小写**（`{SN}` 能命中字段 `sn`） |

**改动字段名的连锁反应**：字段名一变，端口名跟着变，**原来的连线会断**（连线认端口名）。
所以字段名一旦和 MES 字段表对上就别再动；必须动时，改完去连线界面重连一次。

**别用的大小写花样**：同一张字段表里写 `sn` 与 `SN` 两行，报文会出现两个键，
但它们的值取自同一份值池（忽略大小写），**永远是一样的值**——想区分两个字段请起真正不同的名字。

**别用配置项的名字当字段名**：`Url`、`Fields`、`TimeoutMs`、`SendTiming` 这些都是配置属性名，
同时会被当成端口键写进方案；字段名撞上它们时，灌值会先命中端口那一路，配置项拿不到值。
给字段起名请用业务语义（`sn` / `result` / `measure` / `条码`）。

## 二、字段值从哪来（三路取值的准确口径）

| 来源 | 值从哪取 | 取不到时 | 现场要点 |
| --- | --- | --- | --- |
| `端口` | 本算子上**同名输入端口**的当前值 | JSON 键存在、值为 `null`（通知/原始JSON 文本里是空串） | 最常见的是"字段建了、线没连"。预览里显示 `(空)` 占位就是没连上 |
| `变量` | 运行期**本轮局部变量** `LocalVariables[变量名]` | 该键为 `null` | 变量名**区分大小写**、必须是「变量定义 / 变量赋值 / 脚本 SetVar」写入的**键名**、**只在当前这一轮执行里有效**（跨轮要传的东西改用端口连线）。取不到**不报错**，是"填了名字却是空"的头号原因 |
| `内置` | 两项：`时间戳`（本轮组包那一刻的时间，走时间格式 + UTC 开关）、`步骤名` | 不会取不到 | `步骤名` 用的是 `流程名.步骤名`（见下） |

**变量名那一列要的是名字，不是值**：填的必须是变量名（如 `CurrentSN`），
不是 `变量:CurrentSN`、不是 `{CurrentSN}`、更不是那个变量的值。这一行是**手打文本框**、没有候选下拉，
只能照抄「变量管理」/脚本里写过的那个键名。

### `{步骤名}` / 内置"步骤名"显示成什么

| 场合 | 显示 |
| --- | --- |
| 流程里真实执行 | `流程名.步骤名`（编译时由宿主注入） |
| 配置面板预览 / 立即发送 | 注入还没发生时退回步骤自身的名字；新建未保存的步骤可能是 `未赋值` |

MES 侧如果按步骤名分单，注意**步骤改名 = 上报内容改名**。

## 三、四种报文预设各自拼出什么

| 预设 | 报文结构 | 要点 |
| --- | --- | --- |
| `MES字段表` | 启用的字段逐个平铺成 `{"字段名": 值}` | 字段表**就是**载荷本身；类型保真（见第五节）；一个启用字段都没有 → 组报文失败 |
| `钉钉文本` / `企业微信文本` | `{"msgtype":"text","text":{"content":"展开后的通知内容"}}` | 两者同构；`content` 由「通知内容模板」展开 |
| `原始JSON` | 模板展开后的**整段文本**原样发出 | 对接奇葩协议的兜底；模板留空 → 组报文失败；用户自己负责内容是合法 JSON |

## 四、占位符语法（通知模板 / 原始 JSON 模板）

| 写法 | 展开成 | 找不到时 |
| --- | --- | --- |
| `{字段名}` | 值转成**文本**后注入（数值一律不变区域性 `ToString`，不会把小数点写成逗号）。在原始 JSON 里额外做 JSON 字符串转义并**带引号** | **原样保留** `{字段名}` 这几个字符——这是故意的，让你一眼看出名写错了 |
| `{#字段名}` | **原样注入**（不带引号）：数字写成 `12.3`、布尔写成 `true`、JSON 片段整块塞进去 | 同上，原样保留 |
| `{时间}` / `{时间戳}` | 按「时间格式」+「时间戳用 UTC」格式化 | 内置项，永远命中 |
| `{日期}` | 固定 `yyyy-MM-dd` | 内置项 |
| `{步骤名}` / `{StepName}` | 步骤名（口径见第二节） | 内置项 |

- 占位符名两侧的空格会被忽略：`{ sn }` 与 `{sn}` 等价。
- 模板里出现**花括号但不是占位符**（如 JSON 对象本身 `{"a":1}`）不会被误伤——匹配规则只吃"单层、非 `#` 开头"的内容；
  但嵌套花括号 `{a{b}}` 属于未定义行为，别这么写。
- 原始 JSON 里 `{#名}` 先展开、`{名}` 后展开，所以带 `#` 的写法不会被误当普通占位符。

## 五、类型保真对照（MES 数值字段校验的根据）

| 上游端口给的值 | `MES字段表` 报文里的样子 |
| --- | --- |
| `double` / `float` / `decimal` / `int` / `long` / `short` / `byte` 等数值 | `12.3`（**不带引号**，数值型） |
| `bool` | `true` / `false` |
| `string` | `"12.3"`（带引号，字符串型） |
| `DateTime` | 按「时间格式」格式化后的字符串（并遵循 UTC 开关） |
| 认不出的类型（如图像 `HImage`） | 该类型的 `ToString()` 文本占位（不会炸，但不是你要的内容） |
| `null` | `null`（键仍保留） |

**要数值就给数值**：如果上游做过格式化（把 `double` 拼成字符串），JSON 里就是带引号的串，MES 数值字段校验会拒绝。
补救两条路：上游保持数值类型；或改用 `原始JSON` + `{#字段名}` 原样注入（自己保证内容是合法 JSON 值）。

## 六、编码、请求体与幂等口径

- **只做 HTTP POST**：没有 MES 私有协议、没有 Modbus、没有数据库写入。别的协议请用 `原始JSON` + 中转服务，或走 C#脚本。
- **请求体**固定 `application/json; charset=utf-8`，UTF-8；中文**不转义**（不会变成 `\u4EF6`）。
  四种预设都是 POST，没有 GET/PUT。
- **幂等头 `X-Upload-Id`**：每条上报一个 GUID；首发、重试、断网补传**沿用同一个**。
  你自己填了同名请求头则**以你的为准**（不覆盖）。**去重最终由 MES 端落实**——MES 不读这个头，照样会记两次。
- **不满足时机就静默通过**：`仅NG` 没命中、`触发端口` 没给 `true` → 直接返回、**连日志都不写**。

## 七、超时、重试、退避的具体数值

| 项目 | 数值 | 口径 |
| --- | --- | --- |
| 单次请求超时 | `TimeoutMs`，默认 `3000` ms；填 0 或负数**回落 3000** | 每请求一个取消令牌控制；HTTP 客户端总超时置为无限，不会打断别的件 |
| 重试次数 | `RetryCount`，默认 `3`，**限 0~10**（超范围自动夹紧） | 总尝试次数 = 重试次数 + 1 |
| 退避间隔 | 第 2 次起等待 `min(500ms × (第几次-1), 3000ms)`：0.5s / 1s / 1.5s / 2s / 2.5s… **封顶 3s** | 每次重试都**重新加签**（防旧时间戳被判过期） |
| 一次上报最坏耗时 | `(重试次数+1) × 超时 + 退避之和`。默认配置 = `4×3000 + (0.5+1+1.5)s` = **约 15 秒** | 异步模式**不占节拍**（后台线程）；同步模式**全占节拍** |
| 队列容量 | `1000` 条 | 满了新件被拒：勾了阻断时报错，异步且未勾阻断时只写 WARN 日志 |
| 失败判定 | 非 2xx、超时、连接/异常类错误都算失败并重试；2xx 立即成功返回 | 2xx 之后是否"业务成功"另由「业务成功关键字」决定 |

## 八、「仅NG上报」的比对口径

判定字段的值与 `NG 判定值` **三级智能比对**：

1. 两边都能解析成数值 → 按数值比（`12.0` 对得上 `12`）；
2. 否则两边都能解析成布尔 → 按布尔比（`True` 对得上 `true`）；
3. 都不行才按文本比，**忽略大小写**。

数值/布尔的文本解析一律用**不变区域性**（不让区域设置改结果）。
注意布尔值不算数值（`true` 不会被当成 `1` 去和 `"1"` 比）。

## 九、断网续传（spool）的落点与规则

| 项目 | 内容 |
| --- | --- |
| 文件位置 | **程序目录**（宿主 exe 所在目录，非流程工作目录）`\ResultUploadSpool\spool.jsonl` |
| 格式 | JSONL，**一行一件**，字段含幂等 ID、步骤名、URL、超时、重试次数、请求头、报文、加签密钥、是否跳过证书、落盘时刻 |
| 写入时机 | **重试穷尽仍失败**才写；补传成功即删行 |
| 开关 | `SpoolEnabled`，默认开；测试发送（面板立即发送）**永不**落 spool |
| 补传触发 | 后台线程启动即扫一次；此后**空闲** 30 秒没实时件才扫一轮；处理完一批实时件（队列清空）也顺带补一轮 |
| 每轮条数 | 最多 `20` 条（实时件优先，补传不插队） |
| 中止条件 | 一轮里**连续失败 2 条** → 本轮中止（判定网络还没恢复，下轮再试） |
| 放弃条件 | 单条累计补传失败**超过 `50` 次**（源码判据写作 `> 50`，即第 51 次）→ 放弃并**删行**：URL/协议写错的毒记录不该永远压着后面的件 |
| 积压上限 | `100000` 行；超了**丢最老的 1/10**（保新弃旧） |
| 泄密提醒 | spool 里存的是**完整请求头（含 token）、加签密钥与报文**，程序目录按此权限管理 |

补传件在日志里的步骤名前带 `[补传]`，例如 `[结果上报]『[补传]主流程.结果上报』…`，便于区分现场实时件与欠账件。

## 十、鉴权与证书

| 项目 | 口径 |
| --- | --- |
| 请求头 | Key 为空白的行**跳过**；同名 Key **只有第一个生效**（大小写不敏感） |
| Header 值的持久化 | 界面是打码框（看着像密码），**写进方案文件是明文**。这是"只打码不加密"的刻意取舍——别把生产 token 放进会外发的方案包 |
| 钉钉加签 | 填 `SEC` 开头的串；非空则每次尝试自动给 URL 追加 `timestamp` + `sign`，算法是 `sign = UrlEncode(Base64(HMAC-SHA256(secret, "时间戳\nsecret")))`。**每次重试重签** |
| 时间偏差 | 加签的 `timestamp` 取**本机当前时间**（毫秒）。工控机时钟漂移会被钉钉服务端判为过期而拒收，对时是前置条件 |
| 跳过 HTTPS 证书校验 | 只对 `https` 有意义（自签证书内网调试，界面上默认关闭并带红字警告）。**有中间人风险**，正式环境关掉。进程内常驻**两个** HTTP 客户端实例（普通 / 跳过证书），按每条上报的这个标志二选一——客户端的 TLS 选项首次请求后不可再改，不能运行期改同一个。连接池里的连接每 10 分钟换一次，防 DNS/路由变更后僵死 |

## 十一、三个结果端口该怎么读

| 端口 | 异步模式（默认） | 同步模式（取消「异步队列」） |
| --- | --- | --- |
| `响应` | **最近一次**完成的上报响应体（可能是上一轮的件、可能是补传件），只适合事后看 | 就是本轮这条的响应，下一步骤可立即用 |
| `状态码` | 同上；`0` = 没拿到 HTTP 响应（超时/连不上/DNS/URL 非法） | 同上 |
| `已上报` | 最近一次是否业务成功（2xx 且命中关键字；没填关键字时 2xx 即成功） | 本轮结果 |

**异步模式的时序不是本轮的**：入队后流程线程就返回了，回写发生在后台线程完成那一刻。
要"用上报结果卡下一步"必须切同步模式，代价见第七节超时公式。
