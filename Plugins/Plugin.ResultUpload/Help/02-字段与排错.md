# 结果上报 · 字段与排错

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload
> 本页是 `01-overview` 的下半部分：字段名对应链、占位符语法、超时/重试/spool 的具体数值、
> 日志原文逐条对应处置。现场排错先看本页。

## 一个"字段名"到底管几件事

字段表里那一列**字段名**（源码 `UploadFieldDef.Name`，读写都会 `Trim()` 掉两侧空格）同时决定三件事：

| 由字段名决定 | 具体表现 | 取值口径 |
| --- | --- | --- |
| JSON 里的键名 | 报文预设 = `MES字段表` 时，报文就是「字段名: 值」的平铺对象 | 写进 JSON 时**区分大小写**（`sn` 和 `SN` 会各出一个键） |
| 输入端口名 | 来源=`端口` 且勾了「启用」的字段，自动长出一个同名输入端口 | 建端口时**不区分大小写去重**，重名只建一个 |
| 占位符名 | `通知内容模板` / `原始 JSON 模板` 里的 `{字段名}` `{#字段名}` | 查值**忽略大小写**（`{SN}` 能命中字段 `sn`） |

**改动字段名的连锁反应**：字段名一变，端口名跟着变，**原来的连线会断**（连线认端口名）。
所以字段名一旦和 MES 字段表对上了就别再动；必须动时，改完去连线界面重连一次。

**别用的大小写花样**：同一张字段表里写 `sn` 与 `SN` 两行，报文会出现两个键，
但它们的值取自同一份值池（忽略大小写），**永远是一样的值**——想区分两个字段请起真正不同的名字。

## 字段值从哪来（三路取值的准确口径）

| 来源 | 值从哪取 | 取不到时 | 现场要点 |
| --- | --- | --- | --- |
| `端口` | 本算子上**同名输入端口**的当前值 | JSON 键存在、值为 `null`（通知/原始JSON 文本里是空串） | 最常见的是"字段建了、线没连"。预览里显示 `(空)` 占位就是没连上 |
| `变量` | 运行期**本轮局部变量** `LocalVariables[变量名]` | 该键为 `null` | 变量名**区分大小写**、必须是脚本 `SetVar`/变量定义写入的**键名**、**只在当前这一轮执行里有效**。这一条是"填了名字却是空"的头号原因，见下节 |
| `内置` | 只有两项：`时间戳`（本轮开始组包那一刻的时间，走 `TimestampFormat` + UTC 开关）、`步骤名` | 不会取不到 | `步骤名` 用的是 `流程名.步骤名`（见下） |

### 为什么"变量名填了却取不到"（本仓 R33/R34 纪律）

- 这一列的语义是**名字**，不是值：填的必须是**变量的名字**（例如 `CurrentSN`），不是 `变量:CurrentSN`、不是 `{CurrentSN}`、不是变量的值。
- 界面上它是**手打的文本框**，本插件没有实现宿主配置上下文接口，因此**没有候选下拉**——只能照抄「变量管理」/脚本里写过的那个键名。
- 查找区分大小写：`currentsn` 取不到 `CurrentSN`。
- 只在**本轮**有效：局部变量每轮执行重新建，上一轮写的值这一轮读不到。跨轮要传的东西请改用端口连线，或由本轮内的脚本步骤先写。
- 取不到**不报错**：该字段静默变成 `null`/空串。MES 那边看到空字段，先怀疑这一条。

同样"名字类"的还有 `判定字段名`（`JudgeFieldName`）：填**字段表里存在**的字段名。
它有候选下拉（来源=「启用」的字段名，可手填），填了不存在的名字 → 「仅NG上报」永远判定"不是 NG"，**一条都不发**。

### `{步骤名}` / 内置"步骤名"显示成什么

| 场合 | 显示 |
| --- | --- |
| 流程里真实执行 | `流程名.步骤名`（编译时由宿主注入） |
| 配置面板预览 / 「立即发送」 | 注入还没发生时退回步骤自身的名字；新建未保存的步骤可能是 `未赋值` |

MES 侧如果按步骤名分单，注意**步骤改名 = 上报内容改名**。

## 占位符语法（通知模板 / 原始 JSON 模板）

| 写法 | 展开成 | 找不到时 |
| --- | --- | --- |
| `{字段名}` | 值转成**文本**后注入（数值一律不变区域性 `ToString`，不会把小数点写成逗号）。在原始 JSON 里额外做 JSON 字符串转义并**带引号** | **原样保留** `{字段名}` 这几个字符——这是故意的，让你一眼看出名写错了 |
| `{#字段名}` | **原样注入**（不带引号）：数字写成 `12.3`、布尔写成 `true`、JSON 片段整块塞进去 | 同上，原样保留 |
| `{时间}` / `{时间戳}` | 按 `时间格式` + 「时间戳用 UTC」格式化 | 内置项，永远命中 |
| `{日期}` | 固定 `yyyy-MM-dd` | 内置项 |
| `{步骤名}` / `{StepName}` | 步骤名（口径见上表） | 内置项 |

- 占位符名两侧的空格会被忽略：`{ sn }` 与 `{sn}` 等价。
- 模板里出现**花括号但不是占位符**（如 JSON 对象本身 `{"a":1}`）不会被误伤——正则只吃"单层、非 `#` 开头"的内容；但嵌套花括号 `{a{b}}` 属于未定义行为，别这么写。
- 「立即发送」和真实上报用的是**同一个组包器**，预览看到什么就发什么；预览显示`（无法预览：…）`说明模板本身有问题，真发也会失败。

## 类型保真对照（MES 数值字段校验的根据）

| 上游端口给的值 | MES字段表 报文里的样子 |
| --- | --- |
| `double` / `float` / `decimal` / `int` / `long` 等数值 | `12.3`（**不带引号**，数值型） |
| `bool` | `true` / `false` |
| `string` | `"12.3"`（带引号，字符串型） |
| `DateTime` | 按 `时间格式` 格式化后的字符串 |
| 认不出的类型（如图像 `HImage`） | 该类型的 `ToString()` 文本占位（不会炸，但不是你要的内容） |

**要数值就给数值**：如果上游做过格式化（把 `double` 拼成字符串），JSON 里就是带引号的串，MES 数值字段校验会拒绝。
补救两条路：上游保持数值类型；或改用「原始JSON」+ `{#字段名}` 原样注入（自己保证内容是合法 JSON 值）。

## 三个结果端口该怎么读

| 端口 | 异步模式（默认） | 同步模式（取消「异步队列」） |
| --- | --- | --- |
| `响应` | **最近一次**完成的上报响应体（可能是上一轮的件、可能是补传件），只适合事后看 | 就是本轮这条的响应，下一步骤可立即用 |
| `状态码` | 同上；`0` = 没拿到 HTTP 响应（超时/连不上/DNS/URL 非法） | 同上 |
| `已上报` | 最近一次是否业务成功（2xx 且命中「业务成功关键字」；没填关键字时 2xx 即成功） | 本轮结果 |

**异步模式的时序不是本轮的**：入队后流程线程就返回了，回写发生在后台线程完成那一刻。
要"用上报结果卡下一步"，必须切同步模式；同步模式的代价见下面超时公式。

## 超时、重试、退避的具体数值

| 项目 | 数值 | 出处口径 |
| --- | --- | --- |
| 单次请求超时 | `超时(TimeoutMs)`，默认 `3000` ms；填 0 或负数**回落到 3000** | 每请求 `CancellationTokenSource` 控制；`HttpClient` 总超时置为无限，不会打断别的件 |
| 重试次数 | `失败重试次数(RetryCount)`，默认 `3`，**限 0~10**（超范围自动夹紧） | 总尝试次数 = 重试次数 + 1 |
| 退避间隔 | 第 2 次起等待 `min(500ms × (第几次-1), 3000ms)`：0.5s / 1s / 1.5s / 2s / 2.5s… **封顶 3s** | 每次重试都**重新加签**（防旧时间戳被判过期） |
| 一次上报最坏耗时 | `(重试次数+1) × 超时 + 退避之和`。默认配置 = `4×3000 + (0.5+1+1.5)s` = **15 秒** | 异步模式**不占节拍**（后台线程）；同步模式**全占节拍** |
| 队列容量 | `1000` 条 | 满了新件被拒：同步/阻断时报错，异步不阻断时只写 WARN 日志 |
| 幂等头 | `X-Upload-Id`，每条一个 GUID；首发/重试/补传**沿用同一个** | 你自己在请求头里填了同名 Key 则**不覆盖你的** |
| 请求体 | `application/json; charset=utf-8`，UTF-8；中文**不转义**（不会变成 `\u4EF6`） | 四种预设都是 POST，没有 GET/PUT |

## 断网续传（spool）的落点与规则

| 项目 | 内容 |
| --- | --- |
| 文件位置 | **程序目录**（宿主 exe 所在目录，非流程工作目录）`\ResultUploadSpool\spool.jsonl` |
| 格式 | JSONL，**一行一件**，字段含幂等 ID、步骤名、URL、超时、重试次数、请求头、报文 |
| 写入时机 | **重试穷尽仍失败**才写；补传成功即删行 |
| 开关 | `断网续传(SpoolEnabled)`，默认开；测试发送（面板「立即发送」）**永不落 spool** |
| 补传触发 | 服务启动即扫一次；此后**空闲** 30 秒没实时件才扫一轮；处理完一批实时件也顺带补一轮 |
| 每轮条数 | 最多 `20` 条（实时件优先，补传不插队） |
| 中止条件 | 一轮里**连续失败 2 条** → 本轮中止（判定网络还没恢复，下轮再试） |
| 放弃条件 | 单条累计补传失败 `50` 次 → 放弃并**删行**（URL/协议写错的毒记录不该永远压着后面的件） |
| 积压上限 | `100000` 行；超了**丢最老的 1/10**（保新弃旧） |
| 泄密提醒 | spool 里存的是**完整请求头（含 token）与报文**，程序目录按此权限管理 |

补传件在日志里的步骤名前带 `[补传]`，例如 `[结果上报]『[补传]主流程.结果上报』…`，便于区分现场实时件与欠账件。

## 日志原文 → 查哪一项

日志（含 WARN/ERROR）都会**暂存到下一次本步骤执行时转交宿主日志**，所以软件刚启动、
流程还没跑到这一步时看不到后台日志，属正常现象，不是丢了。
后台转交队列最多暂存 500 条（超出丢最老的）；配置面板底部的「日志回看」是另一份独立账本，
只留最近 50 条，日志已经转交宿主之后它仍然看得到。

| 原文（部分为模板，`…` 处是变量内容） | 级别 | 处置 |
| --- | --- | --- |
| `结果上报：未配置目标 URL，跳过本次上报` | WARN | `目标 URL` 空。勾了「上报失败阻断流程」时这条会变成步骤失败，消息为 `结果上报：未配置目标 URL` |
| `结果上报：字段表没有启用的字段，至少要有一个字段才有东西可上报` | WARN/失败 | 字段表全没勾「启用」或全为空。至少留一行启用字段 |
| `结果上报：原始 JSON 模板为空` | WARN/失败 | 预设选了 `原始JSON` 但模板没填 |
| `结果上报：组报文异常：…` | WARN/失败 | 模板/值内容异常，看后面的异常消息；先用面板预览复现 |
| `结果上报：发送队列已满，上报被拒（检查服务器是否长期不通）` | 步骤失败 | 只在**异步 + 勾了阻断**时出现。说明服务器长期不通，件已经塞满 1000 条 |
| `结果上报：发送队列正在关停，不再接收` | 步骤失败 | 正在关软件/停服务，属正常收尾 |
| `结果上报：…`（同步模式失败，内容为响应体或错误描述；空则为 `未知错误`） | WARN/失败 | 同步模式下失败原因直接进这条 |
| `[结果上报] 队列已满（1000 条），『…』一条上报被拒——请检查服务器是否长期不通` | WARN | 未勾阻断时的同一现象：件被丢弃（**不会落 spool**，因为压根没进队列）。这是真的丢数据，必须处理服务器不通 |
| `[结果上报]『…』上报失败（已重试 N 次）：超时（3000ms 无响应）` | WARN | 服务器不响应：查 MES 服务/防火墙/URL 端口；`状态码` 会是 `0` |
| 同上，原因为 `HTTP 404 NotFound` / `HTTP 500 InternalServerError` | WARN | 状态码 + 状态名，服务端问题。非 2xx 一律算失败并重试 |
| 同上，原因为异常消息（如"无法连接到远程服务器"、"不知道这样的主机"） | WARN | 网络/DNS/URL 拼写。`状态码` `0` |
| `[结果上报]『…』已存入断网续传队列（…），网络恢复后自动补传` | WARN | 正常兜底动作，等网络恢复会自动补 |
| `[结果上报]『…』断网续传落盘失败：…` | ERROR | 程序目录没写权限/磁盘满/spool 文件被占用。spool 目录下的文件被编辑器独占也会这样 |
| `[结果上报] 断网续传读取失败：…` | ERROR | spool 文件读不了（损坏、被删、被占）。坏行会被跳过，整文件读失败才会出这条 |
| `[结果上报]『…』补传累计失败 50 次已放弃并删除，请检查该步骤的 URL/协议：…` | ERROR | 这条件的报文**已永久丢弃**。去对应步骤查 URL/报文预设/鉴权 |
| `[结果上报] 补传连续失败，本轮中止（网络可能仍未恢复，下轮空闲再试）` | WARN | 网络还没恢复，无需干预 |
| `[结果上报] 断网续传补传成功 N 条` | INFO | 正常，欠账清了一部分 |
| `[结果上报] 断网续传账本清理失败（成功件下轮会凭幂等 ID 重发，由 MES 去重）：…` | ERROR | 补传成功但删行失败（文件被占）。下一轮会**重发**这些件，靠 MES 按 `X-Upload-Id` 去重；尽快释放文件占用 |
| `[结果上报] 断网续传积压已达上限 100000 条，丢弃最老的 N 条（保新弃旧）` | WARN | 长期不通的极端积压，最老件已丢。先修网络，再评估 MES 端如何补账 |
| `[结果上报]『…』上报线程异常：…` | ERROR | 后台线程被异常打断（罕见）。若反复出现，收集消息内容报修 |

面板「立即发送」的结果区文本（不是日志，只写在界面上）：

| 界面显示 | 含义 |
| --- | --- |
| `请先填目标 URL` | URL 空 |
| `HTTP <码>（业务成功）` | 2xx 且命中关键字（没填关键字时 2xx 即算） |
| `HTTP <码>，但响应未命中成功关键字『…』` | 连上了、MES 却回业务失败。**这是最常见的"200 但 MES 查不到记录"** |
| `HTTP <码> <响应/错误>` | 非 2xx，或 `HTTP 0` 表示没连上 |
| `测试异常：…` | 组包或发送抛异常 |

## 鉴权与证书

| 项目 | 口径 |
| --- | --- |
| 请求头 `Headers` | Key 为空白的行**跳过**；同名 Key **只有第一个生效**（大小写不敏感）。请求体会固定以 `application/json; charset=utf-8` 发出，在这里写 `Content-Type` 改不动它 |
| Header 值的持久化 | 界面是打码框（看着像密码），**写进方案文件是明文**。生产 token 别放进会外发的方案包 |
| 钉钉加签 `SignSecret` | 填机器人安全设置里 `SEC` 开头的串；非空则每次尝试自动给 URL 追加 `timestamp` + `sign`（`sign = UrlEncode(Base64(HMAC-SHA256(secret, "时间戳\nsecret")))`）。**每次重试重签**，长重试不会被判时间戳过期 |
| 时间偏差 | 加签的 `timestamp` 取**本机当前时间**（毫秒）。工控机时钟漂移会被钉钉服务端判为过期而拒收，对时是前置条件 |
| `跳过HTTPS证书校验` | 只对 `https` 有意义（自签证书内网调试，界面上默认关闭并带红字警告）。**有中间人风险**，正式环境关掉。进程内常驻**两个** HTTP 客户端实例（普通 / 跳过证书），按每条上报的这个标志二选一——因为客户端的 TLS 选项首次请求后不可再改，不能运行期改同一个。连接池里的连接每 10 分钟换一次，防 DNS/路由变更后僵死 |

## 上线前自检

1. 报文预设、URL、超时、重试、异步/同步、阻断 六项按**本工位 MES 接口文档**核对一遍。
2. 面板「报文预览」结构对不对：键名与 MES 字段表**逐字一致**（大小写、下划线）。
3. 预览里凡是 `(空)` 的字段，都是"字段建了但值来路不通"——线没连 / 变量名不对 / 上游本轮失败。
4. 用「立即发送」在**这台机器**上真发一次（注意别打生产 MES，或先发测试接口），确认 `响应` 内容。
5. MES 侧确认：非 2xx 的重试是否会产生重单，`X-Upload-Id` 是否被读取去重。
6. 「仅NG上报」工位：拿一件已知 NG / 已知 OK 各跑一次，确认发/不发的边界（判定字段名与 NG 判定值）。
7. 程序目录 `ResultUploadSpool\` 是否存在、可写；把该目录纳入磁盘清理白名单。
8. 若用了同步模式：按 `(重试+1)×超时+退避` 重估节拍，确认最坏情况仍在产线 CT 之内。
