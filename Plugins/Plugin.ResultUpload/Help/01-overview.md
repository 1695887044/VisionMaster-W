# 结果上报

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload

流程每测完一件，把「条码 + 结果 + 检测值」组一条 **JSON**，`POST` 到一个 URL。
MES 上传、钉钉/企业微信群通知、自定义协议——底层都是同一件事：**往一个 URL POST JSON**，
所以四种形态共用一套界面、一个学习成本。

## 为什么需要它 / 原理

产线的两个硬要求：**不能拖节拍**、**不能丢件**。本算子的做法和「CSV记录」同范式（生产者-消费者）：

```
① 取值   字段表三路取值（端口 / 运行期变量 / 内置）
② 判时机 每次执行 / 仅NG / 触发端口 —— 不该发就直接静默通过
③ 组包   按报文预设生成 JSON（纯内存；与面板"报文预览"同一套代码）
④ 入队   微秒级塞进有界队列（默认 1000 条），流程线程到此为止
⑤ 发送   后台线程 HTTP POST + 退避重试；重试穷尽 → 落盘（断网续传）
⑥ 回写   回调把 状态码 / 响应 / 已上报 写回输出端口
```

- **MES 挂了、网线拔了都拖不垮检测**：网络 IO 全在后台线程（默认异步模式）。
- **预览即所发**：配置面板底部的"实际发出 →"和服务器收到的报文由同一个组包器产出，不会出现"看着对、发出去错"。
- **字段表 = 动态端口**：来源=端口 的字段，字段名同时就是输入端口名；
  在通知/原始JSON 模式下字段表退化成"占位符值池"，`{字段名}` 从这里取值——界面只有一套心智。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `<字段名>`（如 `sn`、`result`、`measure`） | 否 | 字段表里 来源=端口 且勾了「启用」的每一项，自动长出一个**同名**输入端口（类型 `object`，任意上游输出都接得进来）。未连线不算「参数缺失」，报文里该键为 `null` |
| `上报触发` | 否 | 布尔。只有「上报时机」= `触发端口` 时生效：为 `true` 的那一次执行才上报 |

> 端口名就是 JSON 里的键名（MES 字段表模式）/ 占位符名（通知与原始JSON 模式）。
> **只有动态输入，没有动态输出**：上报产生的结果只从下面三个固定端口出来。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `响应` | 服务器响应体；失败时是错误描述（如"超时（3000ms 无响应）"）。**异步模式下这是"最近一次"的结果**，不是本轮的 |
| `状态码` | HTTP 状态码；**超时/网络错误为 `0`**（0 不是 HTTP 码，是"根本没连上/没响应"） |
| `已上报` | 最近一次是否**业务成功**：HTTP 2xx 且命中「业务成功关键字」（没填关键字时 2xx 即成功） |
| `Success` / `ErrorMessage` | 基类契约。默认 `BlockOnFailure=false`，上报失败本步骤仍算成功 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 报文预设 `PayloadKind` | `MES字段表` | 四选一：`MES字段表` / `钉钉文本` / `企业微信文本` / `原始JSON`。**切换时模板不迁移**（钉钉切回 MES 要自己重填模板） |
| 目标 URL `Url` | `""` | MES 接口或钉钉/企微 webhook。空 = 本次不上报（WARN；勾了阻断则步骤失败） |
| 超时 `TimeoutMs` | `3000` | **单次请求**超时（毫秒），填 0 或负数回落到 3000。总耗时还要加重试与退避，见"口径"节 |
| 请求头 `Headers` | 空 | Key-Value 列表（MES 常要 `Authorization`）。Key 空白跳过；同名 Key 只**第一个**生效。值在界面用打码框显示，但**存进方案是明文** |
| 字段表 `Fields` | `sn`(端口) / `result`(端口) / `time`(内置:时间戳) | 上报内容定义，同时是动态端口的源头。出厂三条即一单最小可用的 MES 上报 |
| 通知内容模板 `MessageTemplate` | `件{sn}判定{result}` | 钉钉/企微的 `text.content`。占位符：`{字段名}` `{时间}` `{日期}` `{步骤名}` |
| 原始 JSON 模板 `RawJsonTemplate` | `{"sn":"{sn}","result":"{result}"}`（带换行缩进） | 对接奇葩协议的兜底。`{名}` = 转义成 JSON 字符串注入；`{#名}` = **原样注入**（数字/布尔/JSON 片段不带引号） |
| 上报时机 `SendTiming` | `每次执行` | `每次执行` / `仅NG上报` / `触发端口` |
| 判定字段名 `JudgeFieldName` | `result` | "仅NG"看**这一个字段**的值。候选下拉来自"启用的字段名"，也可手填 |
| NG 判定值 `NgValue` | `NG` | 判定字段的值等于它即视为 NG。填空串 = **永远不算 NG**（一条都不发） |
| 异步队列 `AsyncMode` | `true` | 勾选 = 入队即返回（推荐）。取消 = **同步等响应**，`响应`/`状态码`/`已上报` 下一步就能读到，代价是超时会拖节拍 |
| 失败重试次数 `RetryCount` | `3` | 首发失败再试 N 次（总尝试 = N+1），限 0~10。退避 0.5s / 1s / 1.5s… **封顶 3s** |
| 上报失败阻断流程 `BlockOnFailure` | `false` | **默认不阻断**（宁漏报不停线）。要"MES 没收到就停线"才勾 |
| 业务成功关键字 `SuccessKeyword` | `""` | 非空时：2xx **且**响应体包含它才算成功（如钉钉的 `errcode`）。MES 常返回 200 但业务失败，靠这个抓 |
| 钉钉加签密钥 `SignSecret` | `""` | 机器人安全设置选"加签"时那个 `SEC` 开头的串。非空则每次尝试自动给 URL 拼 `timestamp` + `sign` |
| 跳过 HTTPS 证书校验 `SkipCertValidation` | `false` | 自签证书内网调试用，**有中间人风险**，只对 https 有意义；正式环境不要开 |
| 断网续传 `SpoolEnabled` | `true` | 重试穷尽仍失败的件**落盘**，网络恢复后自动补传（幂等 ID 防 MES 记重） |
| 时间格式 `TimestampFormat` | `yyyy-MM-dd HH:mm:ss.fff` | 内置"时间戳"字段与 `{时间}`/`{时间戳}` 的输出格式；留空用这个默认 |
| 时间戳用 UTC `TimestampUtc` | `false` | 对接跨时区 MES 时勾。开启后**内置时间戳与值池里的时间**遵循同一时区纪律 |

**字段表的每一行**：`启用` / `字段名`（JSON 键 = 端口名 = 占位符名） / `来源`（`端口`/`变量`/`内置`） /
`变量名`（来源=变量时手打） / `内置项`（只有 `时间戳`、`步骤名` 两种）。

## 口径与失败策略

- **只做 HTTP POST**：没有 MES 私有协议、没有 Modbus、没有数据库写入。别的协议请用「原始JSON」+ 中转服务，或走 C#脚本。
- **类型保真（很关键）**：端口值是 `double` 就写 `12.3`，**不是** `"12.3"`——MES 数值型字段的校验靠它。
  认不出的类型（如 `HImage`）用字符串占位（好过炸）。
- **中文不转义**：用宽松编码器，`件A判定OK` 不会变成 `件A\u5224\u5B9AOK`（钉钉/企微看得懂，很多 MES 还按原文匹配）。
  请求体固定 `application/json; charset=utf-8`。
- **不满足时机就静默通过**：`仅NG` 没命中、`触发端口` 没给 true——直接返回、**连日志都不写**（高频流程里刷日志会淹没真正的问题）。
- **超时口径**：`TimeoutMs` 管的是**单次请求**；一次上报的最坏耗时 ≈ `(重试次数+1)×超时 + 退避之和`
  （重试 3 次时退避合计 0.5+1+1.5 = 3 秒）。异步模式这些都不占节拍；**同步模式全占节拍**。
- **重试是"同一件重发"**，幂等 ID（`X-Upload-Id`，每条上报一个 GUID）在首发、重试、断网补传之间**沿用同一个**，
  MES 端据此去重；你自己填了同名请求头则以你的为准（不覆盖）。**去重最终由 MES 端落实**。
- **断网续传**：落盘在**程序目录** `ResultUploadSpool\spool.jsonl`（一行一件、JSONL）。
  补传只在**空闲**进行（实时件永远优先、补传不插队）：每轮最多 20 条，连续失败 2 条本轮中止（网络还没恢复），
  单条累计失败 50 次判为"毒记录"直接放弃删行（URL 写错永远发不通，别挡住后面的件），
  积压到 10 万行则**丢最老的 10%**（保新弃旧）。
- **"仅NG"的比对口径**：两边都能解析成数值就按数值比（`12.0` 对得上 `12`）；
  都能解析成布尔就按布尔比（`True` 对得上 `true`）；都不行才按文本忽略大小写比。数值/布尔文本解析用**不变区域性**。
- **图片不上传**：本算子只发文本。要留证就让「CSV记录」存图，把它的**路径**作为一个字段上报。
- **测试发送不落断网账本**：面板「立即发送」的失败不会污染真实 spool（但它会真发一条到服务器，注意别打到生产 MES）。

## 典型用法 / 接线

```
① MES 逐件上报（最常用）
码读取.Text ──▶ 结果上报.sn
Blob.IsOk ───▶ 结果上报.result
               结果上报.time   （内置:时间戳，无需连线）
               报文预设=MES字段表  时机=每次执行  异步=开
                          └──POST──▶ http://mes/api/inspect

② 只报 NG + 钉钉通知
Blob.IsOk ───▶ 结果上报.result      报文预设=钉钉文本
               SignSecret=SECxxxx（自动加签）
               MessageTemplate=件{sn}判定{result}
               时机=仅NG上报  判定字段名=result  NG判定值=NG
                          └──POST──▶ https://oapi.dingtalk.com/robot/send?access_token=…

③ 尺寸上报 + 数值型字段
卡尺.MeasureValue ──▶ 结果上报.measure   （double → JSON 里是 12.3，不带引号）

④ 自定义协议（原始JSON）
RawJsonTemplate = {"BarCode":"{sn}","Judge":"{result}","Val":{#measure},"Ts":"{时间}"}
                  {#measure} 原样注入 → "Val": 12.3；{时间} 走时间格式 + UTC 开关

⑤ 拿服务器响应给下游（同步模式）
异步队列 = 取消 → 本次阻塞等响应 → 下一步读 响应/状态码/已上报（注意：超时会拖节拍）

⑥ 与本地存档并列
检测结果 ──▶ 结果上报（MES 看） ──▶ CSV记录（本地存档） ──▶ Excel报表（人看）
```

**位置原则**：放在**流程末端**（判定之后）。它只"告诉别人"，不参与判定。

## 常见问题

**Q：会影响产线节拍吗？**
默认几乎不会（异步，流程线程只到"入队"）。**只有取消异步队列（同步模式）时才会**——那时最坏节拍
= `(重试+1)×超时 + 退避`，网络不通时这几秒全算在流程头上。

**Q：MES 挂了会停线吗？**
默认**不停**（`BlockOnFailure=false`，宁漏报不停线）。后台退避重试，重试穷尽落盘 spool，网络恢复自动补传。
要"MES 没收到就停线"才勾阻断——注意勾了之后**超时/队列满（1000 条）**都会让步骤失败。

**Q：HTTP 返回 200，为什么 MES 里查不到记录？**
200 只代表"连上了"。两种处理：① 填「业务成功关键字」（MES 返回体里的成功标识），让 `已上报` 反映业务结果；
② 看 `响应` 端口的内容确认 MES 到底回什么。面板日志里"业务成功/未命中关键字"也是这么判的。

**Q：`状态码` 一直是 0？**
0 = **压根没拿到 HTTP 响应**：URL 写错/域名解析不了/防火墙拦了/MES 没起/超时。
`响应` 里会带具体原因（"超时（3000ms 无响应）"或异常消息）。先用面板「立即发送」在同一台机器上验一次。

**Q：字段值全是 `null` 或空？**
按这条链查：① 该字段来源=端口 但**没连线**（预览里显示 `(空)` 占位就是没连上）；
② 上游算子本轮失败（失败步骤的输出端口通常是空的）；③ 来源=变量 但**变量名打错**（区分大小写，取不到就是空）；
④ 字段名有前后空格被两边不一致。

**Q：MES 说数值字段类型不对（收到的是字符串）？**
看上游端口给的是什么类型。`double` 会被写成 `12.3`（数值）；如果上游给的是**文本**（比如格式化过的字符串），
JSON 里就是带引号的串。要数值就在上游把值保持为数值类型，或用「原始JSON」的 `{#名}` 原样注入。

**Q：补传会不会让 MES 记重？**
不会重复**产生新单**：每条上报一个 GUID 作 `X-Upload-Id`，补传沿用原 ID。
但**去重是 MES 端的责任**——MES 不读这个头，照样会记两次。上线前和 MES 侧确认。

**Q：钉钉群里中文变成了 `\u4EF6`？**
本版本已修（中文不转义）。如果还看到，先确认重建过插件工程（改了插件源码只重建宿主，跑的还是旧 DLL）。

**Q：时间戳差 8 小时？**
勾「时间戳用 UTC」，或把 `TimestampFormat` 改成带时区的格式（如 `yyyy-MM-ddTHH:mm:ss.fffZ`）。
注意开启后**内置时间戳和值池里的时间**一起走 UTC，不会只转一半。

**Q：只想报 NG，为什么 OK 件也发出去了？**
`判定字段名` 要填**字段表里存在**的字段名（可从下拉选）；`NG 判定值` 要等于该字段**实际的值**。
判定字段找不到、或 NG 判定值填空 → 一律"不算 NG"（不发）；反过来如果那列实际值是 `False` 而 NG 值填 `NG`，
就会走"文本比"而不等，出现"该发的没发"。

**Q：请求头里的 token 安全吗？**
界面是 `PasswordBox` **打码显示**，但**持久化到方案文件仍是明文**。这是"只打码不加密"的刻意取舍——
别把生产 token 放进会外发的方案包。
