# 结果上报 · 定位与快速上手

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload

工具箱里的这一条叫**「结果上报」**（分组：数据处理）。它只做一件事：流程每测完一件，
把「条码 + 判定 + 检测值」组一条 **JSON**，`POST` 到一个 URL。
MES 上传、钉钉/企业微信群通知、自定义协议——底层都是"往一个 URL POST JSON"，
所以四种形态共用一套界面、一个学习成本。

检测类算子负责"判"，本算子负责"告诉别人"；它不参与判定，放在**流程末端**。

## 一、跑通第一次：五步

1. 从工具箱把「结果上报」拖进流程，放在判定之后（最后一个或倒数第二个节点）。
2. 双击卡片打开配置面板，卡片①**报文预设**选 `MES字段表`，`目标 URL` 填 MES 接口地址
   （钉钉机器人填 `https://oapi.dingtalk.com/robot/send?access_token=…`，企业微信填 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…`）。
3. 卡片②**上传内容（字段表）**出厂给了三行：`sn`（来源=端口）、`result`（来源=端口）、`time`（来源=内置:时间戳）。
   `time` 不用连线；`sn` / `result` 会自动长成两个**同名输入端口**。连法是点该行右侧的 **🔗**（链路图标，
   公共控件 `LinkableValueEditor` 自带，旁边的 ✕ 解绑），在弹出的变量绑定窗口里选上游输出（或全局变量）。
   画布上的连线只表达"两个步骤有数据依赖"，具体连哪个字段一律在这个窗口里定——画布上**没有**按字段拆开的端口锚点。
4. 看卡片②底部的**「实际发出 →」预览**：键名要和 MES 字段表逐字一致；
   预览里显示 `(空)` 的字段就是"字段建了但值来路不通"（线没连 / 变量名不对 / 上游本轮失败）。
5. 卡片④按**立即发送**，在同一台机器上真发一条，看结果行的 `HTTP` 码与响应体。
   跑通之后，界面结果区出现 `✔ HTTP 200（业务成功）`（绿字），画布上这一步是成功态。

**跑通后该看到什么**：MES/群里收到一条 JSON；本步骤输出端口 `已上报` 为 `true`、`状态码` 为 2xx；
面板「最近上报日志」列表（最多 50 条）里有后台线程写出的记录。

## 三、本算子的六条口径（先看这个，细节在另三页）

- **不拖节拍**：默认异步——流程线程只做"取值 + 组 JSON + 入队"（微秒级），HTTP 与退避重试都在后台线程；
  MES 挂了、网线拔了都拖不垮检测。
- **不丢件**：重试穷尽仍失败的件落盘 `程序目录\ResultUploadSpool\spool.jsonl`，网络恢复后自动补传，
  每条一个幂等 ID（`X-Upload-Id`），首发/重试/补传沿用同一个。
- **不停线**：默认 `上报失败阻断流程 = 不勾`，上报失败只写 WARN，本步骤仍算成功（宁漏报不停线）。
- **类型保真**：上游给 `double` 就写 `12.3` 而不是 `"12.3"`——MES 数值型字段的校验靠它。
- **中文不转义**：`件A判定OK` 不会被打成 `件A\u5224\u5B9AOK`；请求体固定 `application/json; charset=utf-8`。
- **只发文本**：不上传图片。要留证就让「CSV记录」存图，把它的**路径**作为一个字段上报。

## 五、常见疑问（上手阶段）

**Q：会影响产线节拍吗？**
默认几乎不会（异步，流程线程只到"入队"）。**只有取消「异步队列」（同步模式）时才会**——
那时最坏节拍 = `(失败重试次数+1) × 超时 + 退避之和`，网络不通时这几秒全算在流程头上。

**Q：MES 挂了会停线吗？**
默认**不停**。后台退避重试，重试穷尽落盘 spool，网络恢复自动补传。
要"MES 没收到就停线"才勾阻断——注意勾了之后**超时、队列已满（1000 条）**都会让步骤失败。

**Q：HTTP 返回 200，为什么 MES 里查不到记录？**
200 只代表"连上了"。填「业务成功关键字」（MES 返回体里的成功标识），
`已上报` 才会反映业务结果；面板与日志里的"业务成功/未命中关键字"就是按这条判的。

**Q：配置面板的下拉是中文，方案文件里为什么是英文？**
界面上的中文由本插件视图里的枚举标签转换器给出（`FieldTable` → `MES字段表`、`OnlyNG` → `仅NG上报`），
而**存进 `.vms` 的一律是英文成员名**——流程与历史方案都按成员名解析，改显示名不会打断已配好的流程。
这几个枚举成员上目前**还没有** `[Display]` 中文标注（本仓 R40 的欠账清单里就列着本工程），
所以只有在这套自带配置面板里是中文；若哪天改用宿主通用面板渲染，界面就会退回英文成员名。

**Q：只想报 NG，为什么 OK 件也发出去了 / 一条都不发？**
`上报时机 = 仅NG上报` 时看**一个字段**：`判定字段名` 要填字段表里存在的字段名（有候选下拉），
`NG 判定值` 要等于该字段本轮的实际值。判定字段找不到、或 NG 判定值填空 → 一律"不算 NG"，一条都不发。
详细比对规则（数值/布尔/文本三级）见 `04-字段映射与上报口径`。
