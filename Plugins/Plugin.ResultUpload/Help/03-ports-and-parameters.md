# 结果上报 · 端口与参数

> 分类：数据处理 ｜ 来源：插件 Plugin.ResultUpload

本页逐项对照源码：端口名与类型取自 `ResultUploadPlugin.cs` 的端口声明，
配置项取自同一文件里带 `[StepConfig]` 的属性（**属性名就是 `.vms` 里的存盘键**），默认值取自 `[DefaultValue]`。

## 一、输入端口

| 端口 | 类型 | 必填 | 说明 | 接不上/没连线会怎样 |
| --- | --- | --- | --- | --- |
| `<字段名>`（如 `sn`、`result`、`measure`） | `object` | 否 | 字段表里 **来源=端口** 且勾了「启用」的每一行，自动长出一个**同名**输入端口 | 不算「参数缺失」；`object` 类型不做静态连线校验，任意上游输出都接得进来。未连线时 JSON 里**键仍在、值为 `null`**；通知/原始JSON 的文本里是空串 |
| `上报触发` | `bool` | 否 | 只有「上报时机」= `触发端口` 时生效：为 `true` 的那一次执行才上报 | 没连线视为"不触发"，本轮静默通过（不发、也不写日志） |

**只有动态输入、没有动态输出**：上报产生的结果只从下面三个固定端口出来。
字段表一行同时决定"端口名 + JSON 键名 + 占位符名"，改名的连锁反应见 `04-字段映射与上报口径`。

**字段端口怎么接上线**：字段行右侧的 **🔗**（公共控件 `LinkableValueEditor` 的链接按钮）→ 变量绑定窗口
（单绑定模式）→ 选上游输出或全局变量；旁边的 **✕** 解绑（已绑定时显示为"解除"，未绑定时是"清空固定值"）。
不要指望在画布上找这些端口：画布每个节点只有一根流程连接脚（模块级数据依赖），端口选择一律在绑定窗口里做。

## 二、输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `响应` | `string` | 服务器响应体；失败时是错误描述（如 `超时（3000ms 无响应）`）。**异步模式下这是"最近一次"的结果**，可能是上一轮的件、也可能是补传件 |
| `状态码` | `int` | HTTP 状态码；**超时/连不上/DNS 失败/URL 非法一律为 `0`**（0 不是 HTTP 码，是"根本没拿到响应"） |
| `已上报` | `bool` | 最近一次是否**业务成功**：HTTP 2xx **且**命中「业务成功关键字」（关键字留空时 2xx 即算成功） |
| `Success` | `bool` | 基类契约。默认 `上报失败阻断流程 = 不勾`，所以**上报失败本步骤仍算成功** |
| `ErrorMessage` | `string` | 基类契约，只在被判为失败的出口写入（未配 URL / 组报文失败 / 入队被拒且勾了阻断 / 同步模式失败且勾了阻断） |

异步模式下这三个口由**后台线程**回写；要"用上报结果卡下一步"必须切同步模式。

## 三、配置项（`[StepConfig]`，共 19 项；属性名 = 存盘键）

| 界面标签 | 存盘键 | 默认值 | 取值范围 / 守门 | 改了影响什么 |
| --- | --- | --- | --- | --- |
| 报文格式 | `PayloadKind` | `FieldTable`（界面显示 `MES字段表`） | `FieldTable` / `DingTalkText` / `WeComText` / `RawJson` | 决定"字段表"与"模板"怎么变成一条 JSON。**切换不迁移模板内容**（钉钉切回 MES 要自己重填模板） |
| 目标 URL | `Url` | `""` | 空串会被当作"未配置"；前后空格在取值时被裁掉 | 空 = 本次不上报（WARN）；勾了阻断则步骤失败 |
| 超时 ms | `TimeoutMs` | `3000` | 填 `0` 或负数**自动回落 3000** | 只管**单次请求**。总耗时还要加重试与退避（见 04 页公式） |
| 请求头 | `Headers` | 空列表 | 每行 `Key` + `Value`；Key 空白的行**跳过**，同名 Key **只有第一个生效**（不区分大小写） | 请求体会固定以 `application/json; charset=utf-8` 发出，在这里写 `Content-Type` 改不动它。值界面打码、**存进方案是明文** |
| 字段表 | `Fields` | 三行：`sn`(端口) / `result`(端口) / `time`(内置:时间戳) | 见下方"字段表的每一行" | 同时是动态端口的源头；全不启用 = 组报文失败 |
| 通知内容 | `MessageTemplate` | `件{sn}判定{result}` | 占位符 `{字段名}` `{时间}` `{日期}` `{步骤名}` | 只在 `钉钉文本` / `企业微信文本` 下出现，展开进 `text.content` |
| JSON 模板 | `RawJsonTemplate` | 带换行缩进的 `{"sn":"{sn}","result":"{result}"}` | `{名}` = 转义成 JSON 字符串注入；`{#名}` = **原样注入**（数字/布尔/JSON 片段不带引号） | 只在 `原始JSON` 下使用；留空 = 组报文失败（`原始 JSON 模板为空`） |
| 上报时机 | `SendTiming` | `EachRun`（`每次执行`） | `EachRun` / `OnlyNG` / `OnTrigger` | 不满足时机 = **静默通过，连日志都不写**（高频流程里刷日志会淹没真正的问题） |
| 判定字段 | `JudgeFieldName` | `result` | 候选来自"启用的字段名"，**也可手填**；查找忽略大小写 | "仅NG上报"只看这一个字段的值。填了不存在的名字 → 永远"不算 NG"，一条都不发 |
| NG 判定值 | `NgValue` | `NG` | 填空串 = **永远不算 NG**（一条都不发） | 比对三级规则见 04 页 |
| 异步队列 | `AsyncMode` | `true`（勾选） | 取消 = 同步等响应 | 同步模式下 `响应`/`状态码`/`已上报` 下一步就能读到，代价是超时把节拍拖走 |
| 失败重试 | `RetryCount` | `3` | **限 0~10**，超范围自动夹紧 | 总尝试次数 = 重试次数 + 1；退避 `0.5s / 1s / 1.5s…` 封顶 3s |
| 成功关键字 | `SuccessKeyword` | `""` | 非空时：2xx **且**响应体包含它才算成功 | 决定 `已上报` 与"仅NG之外的业务判据"。MES 常返回 200 但业务失败，靠这个抓 |
| 上报失败阻断流程 | `BlockOnFailure` | `false`（不勾） | — | 勾上 = "MES 没收到就停线"：未配 URL / 组报文失败 / 队列满 / 同步发送失败 都会让本步骤失败 |
| 加签密钥 | `SignSecret` | `""` | 钉钉机器人安全设置里 `SEC` 开头的串（自动 Trim） | 非空则每次**尝试**都给 URL 追加 `timestamp` + `sign`（重试会重签，防旧时间戳被判过期） |
| 跳过 HTTPS 证书校验 | `SkipCertValidation` | `false` | 界面上勾选时出现红字警告 | 只对 `https` 有意义，自签证书内网调试用，**有中间人风险**，正式环境关掉 |
| 断网续传 | `SpoolEnabled` | `true` | — | 关 = 重试穷尽即丢件（不再落盘、不再补传）。测试发送**永不**落 spool |
| 时间格式 | `TimestampFormat` | `yyyy-MM-dd HH:mm:ss.fff` | .NET 格式串；留空回落到这个默认 | 内置"时间戳"字段与 `{时间}` / `{时间戳}` 占位符的输出格式 |
| UTC | `TimestampUtc` | `false`（本机时间） | — | 开启后**内置时间戳与值池里的时间**一起走 UTC，不会只转一半 |

## 四、字段表的每一行（`Fields`，存盘键随 `Fields` 一起走 JSON 往返）

| 列 | 源码字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用 | `Enabled` | 勾选 | 临时停用某字段不必删除；不启用就不建端口、不进 JSON |
| 字段名 | `Name` | `""` | **JSON 键 = 端口名 = 占位符名**；端口与键取的是 Trim 之后的名字。新增按钮会自动起 `field`、`field2`… 这种不重名（不区分大小写）的名字 |
| 来源 | `Source` | `Port`（`端口`） | `端口` / `变量` / `内置` 三选一 |
| 变量名 | `VariableName` | `""` | 来源=变量时**手打**的键名（区分大小写，只在本轮执行有效）。这一列要的是**名字**不是值，所以没有连线入口 |
| 内置项 | `BuiltIn` | `Timestamp`（`时间戳`） | 只有 `时间戳`、`步骤名` 两种 |

**为什么"变量名填了却取不到"**：它查的是本轮运行期变量池 `context.LocalVariables`，
键名区分大小写、**只在当前这一轮执行里有效**；取不到不报错，该字段静默变成 `null`。
详见 04 页"三路取值的准确口径"。

## 五、其它界面元素

- **实际发出 →（报文预览）**：与真实发送用**同一个组包器**，"看着对、发出去错"不可能发生；
  预览显示 `（无法预览：…）` 说明模板本身有问题，真发也会失败。预览里的时间戳每次刷新都重取当前时刻。
- **立即发送**：按当前配置真发一条（后台线程，不卡界面），结果行绿/红着色，失败**不**落断网账本；
  但它**会**把 `响应`/`状态码`/`已上报` 写成这次测试的结果。
- **最近上报日志 + 刷新**：后台线程持续产生的最近 50 条（含断网续传动态），ERROR 红 / WARN 橙 / INFO 灰。
