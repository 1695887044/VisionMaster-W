# C#脚本 · 可用类型与引用白名单

> 分类：逻辑控制 ｜ 来源：插件 Plugin.CSharpScript

这一页回答一个问题：**脚本里 `using` 什么能用、什么会被拒、被拒时日志长什么样。**

## 三档可用范围

| 档 | 内容 | 在脚本里怎么写 |
| --- | --- | --- |
| ① 默认 imports | `System`、`System.Collections.Generic`、`System.Linq`、`System.Text`、`System.Math`、`HalconDotNet` | 不用写 `using`，直接 `List<int>`、`HImage`、`Math.Sqrt(...)`、`DateTime.Now` |
| ② 宿主运行目录里的托管 dll | 引用集扫描时自动收（HslCommunication、Newtonsoft.Json、AvalonEdit、插件自身 dll…） | 自己写 `using` 或全限定名：`using HslCommunication;` / `Newtonsoft.Json.JsonConvert…` |
| ③ `ExternalLibs\` 扩展 dll | **默认拒绝**，只有登记进 `whitelist.json` 且 SHA256 一致才加入引用集 | 通过后与②一样写 `using` |

**不能**在脚本里引 NuGet 新包，也不能 `#r "…"` 动态加载——只有这三档。
`Context` 门面不属于任何档：它是宿主注入的全局对象（`globalsType = ScriptContext`），始终可用。

## 引用集是怎么攒出来的

Roslyn 编译要知道"哪些程序集可以引用"。本插件按四级来源合并、按路径去重：

| 顺序 | 来源 | 为什么需要 |
| --- | --- | --- |
| 1 | 运行期可信平台程序集清单（TPA，`TRUSTED_PLATFORM_ASSEMBLIES`） | BCL + 已登记依赖，最完整 |
| 2 | 当前已加载程序集的物理位置 | 补 TPA 没列的私有依赖 |
| 3 | **宿主根目录整目录扫描 `*.dll`** | 关键一级：`halcondotnet` 在 `deps.json` 里是 `"type": "reference"`，**不进 TPA**，只靠 1)2) 会变成"编译那一刻恰好加载过才认"——现场表现就是同一份脚本无界面宿主里编得过、主程序里报 `The type or namespace name 'HImage' could not be found` |
| 4 | `ExternalLibs\` 白名单通过项 | 见下一节 |

扫描时对每个 dll 先判"**是不是托管程序集**"（用 `AssemblyName.GetAssemblyName`，原生 dll 会抛
`BadImageFormatException` 就地丢弃）。这一步是硬要求：`MetadataReference.CreateFromFile` 对原生 dll
**不抛异常**，问题会推迟到脚本编译，整份脚本报
`CS0009 Metadata file '…onnxruntime_providers_shared.dll' could not be opened`——
文案与业务毫不相干（典型的"某个 AI 插件把 onnxruntime 拷进了宿主目录"事故）。
所以：**`halcon.dll`、`hcanvas.dll` 这类原生库永远不会进引用集，也不需要进**，
脚本要用的是它们的托管包装 `HalconDotNet.dll`。

引用集与脚本编译缓存都是**进程级静态终身缓存**（缓存超 64 条整体清空，引用集本身不淘汰）。
**新增 dll、改白名单都要重启宿主。**

## 扩展库白名单（fail-closed）

目录固定为**宿主运行目录**下的 `ExternalLibs\`（`AppContext.BaseDirectory`），清单为
`ExternalLibs\whitelist.json`。判定顺序与对应的审计日志原文：

| 情形 | 结果 | 日志原文（级别） |
| --- | --- | --- |
| `ExternalLibs\` 目录不存在 | 静默跳过，视为未启用该功能 | 无 |
| 目录存在但**没有** `whitelist.json` | 拒绝加载任何扩展 dll | `[扩展库白名单] ExternalLibs 目录存在但缺少 whitelist.json：拒绝加载任何扩展 dll（默认拒绝）。`（Error） |
| 清单 JSON 解析失败 | 拒绝加载任何扩展 dll | `[扩展库白名单] whitelist.json 解析失败(<原因>)：拒绝加载任何扩展 dll（默认拒绝）。`（Error） |
| `enabled` 不是显式 `true`（缺省、写成字符串/数字都算关闭） | 全部不加载 | `[扩展库白名单] 开关 enabled 非 true：扩展库加载已被手动关闭。`（Info） |
| dll **未登记**进清单 | 忽略该 dll，但把真实哈希打出来方便一键登记 | `[扩展库白名单] 发现未登记 dll，已忽略：<名字>.dll（实际 SHA256=<64位哈希>，如确需使用请登记进 whitelist.json）`（Warning） |
| 登记的 dll 与宿主已有程序集**同名** | 跳过扩展副本（防影子替换，以宿主版本为准） | `[扩展库白名单] <名字>.dll 与宿主已有程序集同名：以宿主版本为准，跳过扩展副本。`（Info） |
| 清单里的 `sha256` 缺失或与文件实际值不一致 | 拒载（疑似被篡改） | `[扩展库白名单] 哈希不符，疑似被篡改，拒绝加载：<名字>.dll（清单=<登记值> 实际=<实际值>）`（Error） |
| 处理该 dll 时抛异常 | 跳过该项，其余继续 | `[扩展库白名单] 处理 <名字>.dll 异常：<消息>`（Error） |
| 全部通过 | 加编译引用 + 登记运行期路径 | `[扩展库白名单] 校验通过，已加入脚本引用：<名字>.dll（批准人：<approvedBy>，哈希：<前12位>…）`（Info） |

被拒的 dll **连运行期搭便车的机会都没有**：运行期兜底加载（`AssemblyLoadContext.Default.Resolving`）
只对白名单通过项挂载。所以"哈希不符"的后果是**引用其类型的脚本一定编译失败**，
而不是"编译过了但跑不起来"。

### whitelist.json 格式

```json
{
  "enabled": true,
  "remark": "总开关；false 或缺省 = 全部扩展库不加载",
  "libraries": [
    {
      "file": "SomeLib.dll",
      "sha256": "64位十六进制小写，必须与文件实际内容一致",
      "approvedBy": "批准人/部门",
      "purpose": "用途说明，出问题时回溯用"
    }
  ]
}
```

`file` 字段只认**文件名**（经 `Path.GetFileName` 归一），写 `..\xx\SomeLib.dll` 不会指到目录外。

### 登记三步

1. 把 dll 放进宿主目录下的 `ExternalLibs\`；
2. 跑一次任意 C# 脚本，日志里 WARN 会带出该 dll 的**真实 SHA256**，复制；
3. 粘进 `whitelist.json`（连同 `approvedBy` / `purpose`），把 `enabled` 写成 `true`，**重启宿主**；
   日志转 INFO「校验通过」后脚本里就能 `using` 了。

> 当前仓库里**既没有** `ExternalLibs` 目录**也没有** `whitelist.json`，此功能默认处于"未启用"状态。

## 哪些 `using` 会失败、报什么

| 你写的 | 结果 | 报错/日志 |
| --- | --- | --- |
| `using System;`（及五档默认 imports 里任一个） | 可省不写，写了也不报错 | — |
| `using HalconDotNet;` | 可用（默认 import 已含，整目录扫描保证它在引用集里） | — |
| `using Newtonsoft.Json;`、`using HslCommunication;` 等宿主目录里存在的托管 dll | 可用 | — |
| `using SomeLib;`，dll 只在 `ExternalLibs\` 未登记 | **不可用** | 编译期：`第 N 行 第 M 列: The type or namespace name 'SomeLib' does not exist…`；日志：未登记 WARN |
| 同上，已登记但哈希不符 | **不可用** | 同上编译错误；日志：哈希不符 ERROR |
| 同上，`enabled` 写成 `false` | 已登记的也**全部不可用** | 日志：手动关闭 INFO |
| `using System.Windows.Forms;` 之类运行环境里没有的程序集 | **不可用** | 与上面同款 `does not exist` 编译错误 |
| 想引 NuGet 包 / 写 `#r` | **不支持** | 无该机制 |
| 直接 `using` 原生库（如 halcon 本体） | 不适用：原生 dll 不进引用集，也**不该**进 | — |

## 常见问题

**Q：脚本报 `The type or namespace name 'HImage' could not be found`，是不是要写 `using HalconDotNet;`？**
A：不用（它已是默认 import）。这个报错的历史根因是**引用集依赖加载顺序**，现已由"宿主根目录整目录扫描"修掉。
若现场仍出现，先确认宿主目录里有 `HalconDotNet.dll`。

**Q：报 `CS0009 Metadata file '…' could not be opened`，脚本一行都没跑？**
A：说明引用集里混进了**原生 dll**。当前实现已按托管性过滤；若你用的是旧版插件 dll，先更新插件。
常见来源是某个 AI/推理插件把 `onnxruntime*.dll` 拷进了宿主输出目录。

**Q：日志里出现「发现未登记 dll」的 WARN，是不是出问题了？**
A：不是错误，是纪律：目录里有清单没登记的 dll，已被忽略。确需使用就照它的哈希登记；不需要就把文件挪走，
WARN 自然消失。

**Q：登记好了、`enabled: true` 也写了，重启后 INFO 变成「校验通过」，脚本还报错？**
A：分清两件事——重启的是**宿主**还是只是重开了配置窗口？引用集进程级只建一次。
另外确认脚本里的命名空间名与 dll 导出的命名空间一致（`SomeLib.dll` 里的名字未必是 `SomeLib`）。

**Q：扩展库自己还依赖别的 dll，要不要一起登记？**
A：要，**逐个登记**。运行期兜底只认白名单路径表，依赖闭包不会自动跟进；这是纪律不是 bug。

**Q：白名单能不能挡住脚本里 `Process.Start` / 删文件？**
A：挡不住。白名单**只管能引用哪些 dll**，管不住脚本正文（无沙箱，MVP 明确不做）。
正文纪律靠"方案文件进版本管理 + 评审"兜底。

**Q：扩展库的审计日志我只见过一次，后面就没了？**
A：设计如此。引用集只扫一遍，审计记录暂存后在**首次脚本执行**时投递进日志并清空；
要查历史看落盘日志文件。

**Q：更新插件时 PostBuild 报 `MSB3073`？**
A：主程序还在运行、占住了 `Microsoft.CodeAnalysis*.dll`，投递中断。
关程序 → 重新生成 → 核对 `Modules\Plugin.CSharpScript.dll` 时间戳 → 再启动。
