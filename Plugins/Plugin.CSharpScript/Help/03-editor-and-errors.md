# C#脚本 · 编辑器与报错

> 分类：逻辑控制 ｜ 来源：插件 Plugin.CSharpScript

这一页讲**配置界面怎么用**：编辑器有什么智能提示、"校验脚本"看什么、报错原文怎么读、
以及一个明确的坏消息——**这个脚本没有断点，也没有调试器**。

## 界面布局

| 区域 | 内容 |

| 左列第三卡片 | **共享变量**（表头提示"脚本里 `Context.GetGlobal`"）+「+ 新增」；行 = 变量选择 + 别名（留空则选定/确认时固化为当时的变量名）+ 方向（系统变量恒只读）+ 备注 +「✕」；不生成输入端口 |
| 左列第四卡片 | **Context 自定义函数速查**：现场不用翻文档的成员清单 |

本视图**没有"执行"按钮**——试运行由主程序外壳提供。

## 编辑器能力

| 触发 | 行为 |
| --- | --- |
| 打字（字母/数字/下划线） | 按前缀弹补全：接口变量（带"输入/输出 + 声明类型"）+ `Context` 成员 + 常用关键字三类 |
| 输入 `Context.` | 只弹 `Context` 的成员列表（判定"点号左侧确实是 `Context`"才切成员模式） |
| `Ctrl+Space` | 强制弹全量补全 |
| 选中某成员插入 | 插入**调用模板**，参数位置为 Tab 占位符，按 `Tab` 逐个步进，最后一个参数后 `Tab` 退出模板 |
| 输入 `(` | 弹参数签名提示（`Esc` 关闭） |
| 鼠标悬停标识符 | 悬浮卡：API 成员显示名称/签名/说明；接口变量显示名称/方向/类型 |
| 语法高亮 | 自定义 C# 高亮（`Context` API 棕黄 / 类型青色 / 控制流关键字紫色）；**变量表里的名字不参与着色**——脚本里必须走 `Context.GetInput` / `SetOutput`，裸名不可用 |
| `Ctrl+/` | 给当前行/选区加 `//` 注释（右键菜单里也有「注释」「取消注释」） |
| 其它编辑行为 | 撤销、自动缩进、括号配对、当前行高亮、查找替换、字号缩放 |
| 右键「插入代码片段」 | 按分类插整段示例，落在光标行**下方**，可一次 `Ctrl+Z` 撤回 |

内置代码片段 8 个，分三类：

| 分类 | 片段 |
| --- | --- |
| 输入输出 | 取输入并写输出（基本骨架） / 弱类型取输入（手动转换） / 运行期变量计数（GetVar/SetVar） |
| 流程控制 | 判定 NG（Fail + return） / try-catch 保护 |
| Halcon 图像 | 阈值分割 + 面积统计 / 灰度统计（均值/标准差） / 显示图像到视图窗口 |

**已知缺口**：补全表（`CSharpApiDoc`，与 `ScriptContext` 手工同步）**没有** `MarkLine`、`MarkText`、
`NewMarks` 与非泛型 `GetVar` 这几项——敲的时候不会自动弹出来，但**直接写是能用的**。
它们的签名在左列「Context 自定义函数速查」卡片和"Halcon 图像"类片段里有现成写法，照抄即可。

## 校验脚本

工具栏「校验脚本」（右键菜单里叫「校验脚本（编译检查）」）做的事：
把编辑器当前文本固化进配置 → **强制重编译**（不执行）→ 结果显示在编辑器下方。

| 显示 | 含义 |
| --- | --- |
| `✔ 脚本校验通过（编译无误）`（绿色） | 编译零 error。**不代表结果正确**——没执行过，端口有没有值、逻辑对不对都要跑一遍才知道 |
| `✘ 第 N 行 第 M 列: <消息>`（红色） | 取第一条编译错误；**该错误行**在编辑器里标红并把光标跳到该行。其余错误需修完再点一次校验 |

行号可信：Roslyn 诊断的行号就是编辑器真实行号，**不需要换算**（与图像脚本那套"第 N 个非空行"不同，
这里没有跳过空行的坑）。

## 报错原文怎么读

| 报错 | 阶段 | 处理 |
| --- | --- | --- |
| `第 N 行 第 M 列: CS…: <消息>` | 编译 | 按列定位；`The type or namespace name 'X' does not exist` 类问题查第 2 页的引用集/白名单 |
| `脚本编译错误: <消息>` | 运行期才冒出的延迟诊断 | 少见；同样是编译问题，重新校验一遍即可定位 |
| `脚本创建失败: <消息>` | 引擎创建脚本对象时抛异常 | 一般是脚本正文异常（极端编码/内容）；先清空正文再恢复 |
| `脚本运行异常: <消息>` | 执行 | 脚本里抛出的异常，已剥掉 `AggregateException`/`TargetInvocationException` 外壳。消息里没有行号——用 try/catch 自己包一层，`Context.Error(...)` 记下现场 |
| `写输出端口[X]失败：<消息>` | 执行 | `SetOutput` 时 CLR 类型不符。把输出行的「类型」改成脚本真正产出的类型，或在脚本里先转 |
| `脚本编译失败` | 兜底 | 编译没通过但没带回详情；点「校验脚本」拿具体行列 |

失败契约（决定步骤红/绿）：

- 编译失败 → 失败；
- 运行期抛异常 → 失败；
- 取消（停止/急停）→ **不算失败**：节点记为已取消（灰行），不是红行；长循环请定期调用 `Context.ThrowIfCancellationRequested()`（已请求停止时抛 `OperationCanceledException`）；
- `Context.Fail("原因")` → 失败，错误信息=原因（**不会中断执行，必须紧跟 `return`**）；
- 脚本正常返回 → **成功**（返回值不参与判定，`Context` 的布尔返回值也不是状态）。

## 断点与调试

明确说明：**本插件没有断点、单步、 watches 任何调试功能**，编辑器里也不提供"运行到某行"。
可用的排查手段只有这几条：

1. **「校验脚本」**先把编译错误清干净（含类型/名字错误，成本最低）；
2. **日志**：`Context.Info/Warn/Error/Success` 都会自动带 `[实例名]` 前缀写进流程日志，
   在日志窗口按实例名过滤即可看这段脚本的执行轨迹；
3. **随图信息**：`Context.ShowImage(img, 1, "标题", ("缺陷数", 51), ("判定", "NG"))`
   把中间量直接标在画布图片列表上，比翻日志快；
4. **输出端口**：把可疑的中间值临时 `SetOutput` 成一个输出，下游连个显示/记录步骤看一眼；
5. **try/catch 自保**：模板"流程控制 → try-catch 保护"就是给这段脚本加人肉断点，
   `catch (Exception ex) { Context.Error("崩在 X 之前：" + ex.Message); Context.Fail(ex.Message); }`。

## 常见问题

**Q：敲 `MarkLine` 时补全不弹，是不是不支持？**
A：支持，只是补全表没覆盖标注三件套（`NewMarks`/`MarkLine`/`MarkText`）和非泛型 `GetVar`。
直接写完整、或从"Halcon 图像"类片段里抄。

**Q：`Context.` 后面什么都不弹？**
A：成员列表只在"点号左侧确实是 `Context`"时弹。如果你写成 `ctx.`（自己 `var ctx = Context;`）
就没有成员补全，但代码照样能跑。

**Q：校验时行号是对的，运行时报"脚本运行异常"却没有位置，怎么找？**
A：按上面第 5 条加 try/catch 定位；或分段注释掉正文做二分。异常消息本身（如空指针、除零、
`Convert.ChangeType` 失败）通常已足够指认那一行的哪个变量。

**Q：为什么我改了脚本，运行结果没变？**
A：编译按正文内容 SHA256 指纹缓存，真改了内容不会命中旧缓存。若确实没变，检查是否改在了别的步骤实例上，
或流程跑的是另一个分支。

**Q：编辑器里 `List` / `Dictionary` 补全出来的是关键字，不能用泛型？**
A：补全列表里的 `List`、`Dictionary` 属于"常用关键字/类型"低优先级区，只是文本提示；
真正写 `List<int>` 完全可用（`System.Collections.Generic` 是默认 import）。

**Q：能不能不写 `using` 就用 LINQ？**
A：可以，`System.Linq` 已是默认 import，直接 `.Where(...)` / `.Select(...)` / `.ToList()`。

**Q：插入的代码片段能把现在的正文替换掉吗？**
A：不能，片段只**插入**到光标行下方。要清空正文直接全选删除；误插了一次 `Ctrl+Z` 撤回整段。

**Q：变量表改了名，脚本里的字符串没跟着变？**
A：脚本里的名字是**字符串字面量**，插件不会联动改名。改完变量表要自己核对
`GetInput("…")` / `SetOutput("…")` 的每个字符串；名字对不上时 `GetInput` 返回 `null`/`default`、
`SetOutput` 不写入，两者都会在流程日志里 Warn 一次（同一轮同一名字只提醒一次）。
这是最容易埋 bug 的地方，建议插入片段里的骨架 + 一次校验 + 一次试运行确认。

**Q：两行变量写成同一个名字会怎样？**
A：点「确定」或试运行会被拒绝，状态栏给出冲突的两行行号（输入表、输出表各自查重，输入与输出允许同名）。
重名时端口只会建一个，另一行的连线会被当成孤儿删掉——所以这里选择"直接不许保存"；
把名字改成不冲突的值后，原连线会自动迁过去。空名字行同样会被拒绝（没有再点「取消」即可放弃改动）。
