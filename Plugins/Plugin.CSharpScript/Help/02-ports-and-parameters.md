# C#脚本 · 端口与参数

> 分类：逻辑控制 ｜ 来源：插件 Plugin.CSharpScript

## 输入端口

输入端口由「输入变量」表逐行驱动（初始为空表，点「+ 新增」加行，默认名 `in` / `in2` / `in3` …）。

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| 变量表每行一个同名端口 | 否（行本身不强制连线） | 连线时取上游值；未连线时按类型在行内编辑框手填 |

行内「类型」下拉决定端口承载的 CLR 类型（界面显示中文，存的是枚举成员名）：

| 声明类型（界面显示 / 成员名） | 端口 CLR 类型 | 用途 |
| --- | --- | --- |
| 任意对象（`Object`） | `object` | 不确定类型、原样转发（默认值） |
| 整数（`Int`） | `int` | 整数 |
| 浮点数（`Double`） | `double` | 浮点数 |
| 布尔（`Bool`） | `bool` | 真假 |
| 字符串（`String`） | `string` | 文本 |
| Halcon 元组（`HTuple`） | `HTuple` | HALCON 元组（多值数组） |
| Halcon 图像（`HImage`） | `HImage` | 图像 |
| Halcon 区域（`HRegion`） | `HRegion` | 区域 |
| Halcon 轮廓（`HXld`） | `HXLDCont` | 轮廓 / XLD（注意枚举名与 CLR 类型名不一致） |
| Halcon 图形对象（`HObject`） | `HObject` | HALCON 图形对象基类 |

图形类（`HImage`/`HRegion`/`HXld`/`HObject`）必须连线拿到真实对象，不能靠手填文本凑出来。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| 变量表每行一个同名端口 | 脚本里 `Context.SetOutput("名字", 值)` 写入；名字不存在于表中会被**静默忽略** |
| （同名端口的默认值） | 类型由「类型」下拉决定；写不进该类型时抛错并被包成 `写输出端口[X]失败：…` |

**读写全局/系统变量：走「共享变量」表（推荐）**。左侧「共享变量」表按变量 **Id** 声明要读/写的变量：

- 方向 = 只读 → 脚本里 `Context.GetGlobal<T>("别名")`；
- 方向 = 读写 → 再可 `Context.SetGlobal("别名", 值)` / `TrySetGlobal(...)`；
- **系统变量恒只读**（方向下拉锁定；它由运动轴状态投影而来，不实现可写契约）。

声明表是**编译期可见的写集合**：并行分组的多条分支同时写同一个全局变量，编译器会报
`[并行全局变量写冲突]`（与「变量赋值」同一条闸门）。变量在变量管理里改名不影响声明（按 Id 寻址），
脚本里的别名也不用动。

**备选（脚本不需要读值、只把上游结果落全局）**：把值写到输出行，再在下游接「变量赋值」
（作用域=全局变量）把它的「值」连到该输出端口——这条路是纯数据流，不占声明表。

**输入端口只接上游数据流**：C#脚本的输入行不再提供"绑定全局变量"（绑定弹窗里没有全局节点）。
旧方案里已经绑在输入上的全局变量仍可读（连线还在），建议迁到「共享变量」表。
运行期的临时变量走 `Context.SetVar` / `Context.GetVar`（本次流程运行内共享，不跨运行持久）。

**变量改名 / 删行会自动收尾**：改输入变量名时，本步骤挂在该名字上的连线与手填值会一起迁到新名字，
端口也按新名字重建；删行时对应的连线键一并清除。改**输出**变量名只会重建本步骤的端口，
下游选过旧端口名的连线需要重选（下游存的是端口名，插件改不到别的步骤）。

以上收尾在编辑期即时生效（行内链接显示才跟得上新名字），但点「取消」会把变量表 / 连线 / 手填值
还原成打开配置前的样子；点「确定」才落盘。历史方案里已经存在的孤儿键（旧版本改名/删行留下的，
表现为编译报「没有名为 X 的输入端口」）：打开本步骤配置点一次「确定」即可清掉。

图形输出（`HImage` 等）在该行把「显示窗口」选成 窗口1~9，执行完会自动推预览到对应视图；选「不显示」则不推。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ScriptText` | 内置模板（见下方"典型用法"） | 脚本正文（顶层语句）。随配置内嵌进 `.vms`；正文为空时按空串处理 |
| `InputVars` | 空集合 | 输入变量表；每项一个动态输入端口 |
| `OutputVars` | 空集合 | 输出变量表；每项一个动态输出端口，并写进步骤的输出端口快照供下游选择 |
| `SharedVars` | 空集合 | 共享变量声明（全局/系统）；按变量 Id 寻址，不生成端口。方向=只读/读写，系统变量恒只读 |
| 行内 `Name` | `in` / `out`（重名自动加序号） | 变量名 = 端口名 = 脚本里的取存键；建议字母开头、不含空格 |
| 行内 `Type` | `Object` | 声明类型；**改类型会重建端口**，原连线可能需要重连 |
| 行内 `Remark` | 空 | 备注；输出行会用它作为下游端口说明与推图标题来源 |
| 行内 `DisplayWindow` | `0`（不显示） | 仅图形类输出可见：`0`=不显示，`1`~`9`=主界面第几号视图窗口 |

## 口径与失败策略

- **编译失败**：步骤直接 `Success=false`，错误信息形如 `第 N 行 第 M 列: CS…: …`。
  Roslyn 的行号就是编辑器真实行号，不用换算。
- **运行期异常**：剥掉 `AggregateException` / `TargetInvocationException` 外壳后写成
  `脚本运行异常: <消息>`，判失败。
- **`Context.Fail("原因")`**：脚本正常跑完后宿主置失败，错误信息就是那句原因。
  `Fail` **不会中断脚本**，务必紧跟 `return`。
- **输出端口不存在**：`SetOutput` 忽略，不报错（想确认就看下游有没有值）。
- **输出类型不符**：抛错并包成 `写输出端口[名字]失败：<原始消息>`，判失败。
- **无超时、无取消配置项**：只把流程的 `CancellationToken` 透传给脚本；死循环会卡住整条流程，
  需要自己在脚本里判断/加限时。
- **无沙箱**：白名单只约束"能引用哪些扩展 dll"，管不住脚本正文（仍可读写文件、起进程）。
- **编译缓存**：按脚本正文 SHA256 指纹缓存已编译委托，内容不变零成本复用；超过 64 条整体清空。
  引用集（能 `using` 的程序集清单）是**进程级一次性构建**，改白名单或补 dll 必须重启宿主。
