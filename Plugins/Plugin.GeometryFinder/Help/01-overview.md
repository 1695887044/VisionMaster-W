# 几何查找

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryFinder

在圈定的范围里做**亚像素找边**，把找到的边**拟合成直线 / 圆 / 椭圆**，输出一份可复用的**几何基元**给下游算关系用。
它只回答"这条边（这个圆）在图里的哪个位置、朝哪个方向、有多大"这三件事：
**不测两个特征之间的距离与夹角**（那是「几何计算」）、**不做 OK/NG 判定**、**不乘像素当量**（输出永远是像素）。

## 为什么需要它

平台原本只有"出图、出区域"的算子：边找出来了只落在画面上，下游拿不到"一条直线的方程、一个圆的圆心和半径"，
只能回到 C# 脚本里手算。本算子把边**升级成一等数据**（几何基元），于是"找特征 + 算关系"能在流程图上直接搭出来。

**为什么要亚像素边而不是二值化找边**：二值化 + 连通域给出的边缘点只能落在整数像素格上，
一条 3° 倾角的边每个像素只能"跳一格"，拟合出来的角度天然带量化误差；而且阈值一动，边缘就整体胖瘦一圈。
亚像素边缘提取先把灰度沿梯度方向插值成连续曲线、再取变化最大处，位置能落到小数像素上——
这正是"同一个件重复测量数值稳不稳"的关键：量化台阶没了，抖动就只剩真实的散布。

## 原理（四步，一次跑完）

```
取域（接了区域就在区域内找，没接就整图）
   ↓ 亚像素边缘提取（'canny'，平滑 Sigma + 低/高滞后阈值）
一堆轮廓（长短不一，视野里每一条对比度跳变都出一条）
   ↓ 按长度筛：只保留长度 ≥ 下限的那些
   ↓ 取其中**最长的一条**（其余全部丢弃，不参与拟合）
拟合（直线 / 圆 / 椭圆，按「查找类型」选一种）
   ↓
基元 Geometry + 便捷数值 Row / Col / Phi / Radius + 那条轮廓 Contours
```

- **只拟合最长的一条轮廓**是本算子的核心口径：同一视野里有五条边时，它挑最长的去拟合，**不会**同时给出五条。
  要多个特征就放多个本算子，各自圈范围（用 `MaskRegion` 把视野收窄是最直接的办法）。
- **拟合抗毛刺**靠鲁棒算法：最小二乘把所有点一视同仁，一个毛刺点就能把线拽歪；
  Tukey 把离群点的权重压到近零（离群点等于没投进去），是工业场合的默认选择。
  直线与圆走各自的鲁棒实现（圆的几何版按"点到圆的距离"计残差，比按纵向偏差更合理）。
- **椭圆是另一条路**：走的是固定算法（`fit_ellipse_contour_xld` 的 fitzgibbon），
  不吃「拟合算法」这一项——改那一项对椭圆没有影响，这不是 bug。
- 圆与椭圆拟合前会把轮廓**闭合**（首点补到末尾），所以要求点数够（圆 ≥ 3、椭圆 ≥ 5），点太少直接判拟合失败。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 是 | 待查找图像（`HImage`）。为空或未初始化直接失败：`几何查找：未接入图像（SrcImage 为空）` |
| `MaskRegion` | 否 | 查找区域（`HRegion`）：接「ROI」算子的 `MaskRegion`（合并有效区域）。只在区域内找，**未接 = 整图**；坐标不因它改变 |
| `Kind` | 是 | 查找类型：直线 / 圆 / 椭圆（默认**直线**）。界面上是中文，流程里存的是成员名 `Line` / `Circle` / `Ellipse` |
| `Sigma` | 否 | 边缘提取的平滑量（默认 1.0）。越大越抗噪，但边会发"糊"、定位变钝 |
| `LowThreshold` | 否 | 边缘低阈值（默认 20）。低于它的对比度直接不算边 |
| `HighThreshold` | 否 | 边缘高阈值（默认 40）。强弱分界：只有强于它的才算"确定的边" |
| `MinContourLength` | 否 | 参与候选的轮廓长度下限，像素（默认 30）。短于它的轮廓一律不参与"取最长" |
| `FitAlgorithm` | 否 | 拟合鲁棒算法（默认 **Tukey 抗离群（推荐）**）：最小二乘 / Huber 抗离群 / Tukey 抗离群。只对直线、圆生效 |
| `FailOnNotFound` | 否 | 找不到是否判本步骤失败（默认 **是**）。设为否 → 步骤算成功，只把 `IsFound` 置 false |
| `DisplayViewIndex` | 否 | 显示窗口：`0` = 不显示，`1~9` = 主界面第几个图像窗口（默认 1，填大于 9 按 9 处理） |

> 「必填」= 端口自己声明的 `IsRequired`：既没连线、步骤数据里又没有常量值时，编译报 `[参数缺失] '<端口>' 未配置`。
> 打开一次「模块参数」点确定，默认值就存成常量，之后不连线也能跑。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Geometry` | **主输出**：类型化几何基元（`GeometryParam`）。类型由 `Kind` 决定，可直接喂给「几何计算」的 `A` / `B` |
| `Contours` | 参与拟合的**那一条**最长轮廓（XLD）。复核"拟合用的是哪条边"就看它；也能直接给「结果显示」描边 |
| `IsFound` | 本轮是否真的拟合成功（失败轮为 false） |
| `Row` / `Col` | 基准点：直线 = 拟合线段中点，圆 = 圆心，椭圆 = 中心（像素） |
| `Phi` | 方向角（**度**，[0,180)）：直线 = 沿线方向，椭圆 = 长轴方向。圆不用这一项，值为 0 |
| `Radius` | 圆 = 半径，椭圆 = **长半轴**（像素）。直线不用这一项，值为 0 |
| `Success` / `ErrorMessage` | 基类自带：本步骤是否跑通、失败时的中文原因 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（端口） | 默认 | 调大 / 调小分别会怎样 |
| --- | --- | --- |
| `Sigma` | 1.0 | 调大（1.5~3）→ 噪声纹、脏污被抹平，边变粗变"钝"；调小（下限按 0.4 兜住）→ 边更锐利，但纹理/毛刺也会各出一条边，"取最长"更容易挑错 |
| `LowThreshold` | 20 | 调小（10~15）→ 弱对比的边也能出来，同时视野里的纹理也算边；调大 → 只剩明显边，找不到就报"未找到足够长的轮廓"。低于 1 按 1 处理 |
| `HighThreshold` | 40 | 与低阈值是**滞后对**：高阈值定"确定的边"、低阈值把它们的延伸段捡回来。差距调大 → 边更长更连续（更容易把相邻轮廓串成一条）；差距调小 → 边断成多段、每段都变短。高阈值不足"低阈值 + 1"时会被自动抬到"低 + 1" |
| `MinContourLength` | 30 | 调大 → 滤掉碎边、杂边（**挑错边时第一根要动的旋钮**）；调小 → 短弧、短段也能进候选，但更容易选中一条噪声。下限按 1 兜住 |
| `FitAlgorithm` | Tukey | 最小二乘最脆（一个毛刺点就能把线拽歪）；Huber 折中（离群点降权但不清零）；Tukey 最抗离群（离群点近乎不参与拟合）。**先看现场有没有毛刺再决定往哪调**，别一上来就换最小二乘；点数本来就少时鲁棒算法也没有冗余可用 |
| `FailOnNotFound` | true | 计量场景保持 true（"找不到边"就是异常，必须让线停下来）；探测/遍历场景设 false，配合 `IsFound` 走分支 |
| `DisplayViewIndex` | 1 | `0` 关掉推图（不影响算法与输出端口）；多相机/多窗口时把它对准要看的那一格 |

本插件**没有自定义配置界面**，也没有 `[StepConfig]` 常量：双击步骤（或右键「模块参数」）打开的是**输入端口清单**，
每行 = 参数名 + 值输入框 + 🔗（连上游）+ ✕（清除连线）。所以"参数"和"连线"是同一张表：
数值想让它跟着上游走就点 🔗，想固定就直接在框里填。

## 现场现象 → 先查什么

| 现场现象 | 先查这里 |
| --- | --- |
| 报"未找到足够长的轮廓（长度下限 X px）" | ① `MaskRegion` 是否罩住了目标边（最常见）；② 阈值太高（`LowThreshold` 先降到 10~15）；③ `MinContourLength` 比目标边本身还长；④ 视野里本来就没什么对比度 |
| 找到了，但拟合的是隔壁那条边 | "最长"选错了：`MaskRegion` 把视野收到只剩目标，或把 `MinContourLength` 提上去把干扰段筛掉 |
| 拟合出的**圆半径明显偏大** | 只拟到一小段弧（弧越长越能定住圆）。处置：把区域扩到能吃到**大半个圆周**、`LowThreshold` 降一点让轮廓连起来、`Sigma` 略增。点太少（<3）时会直接报拟合失败 |
| 直线方向角跟现场量到的**差 90°** | 口径不同不是错：本算子的 `Phi` 是**沿着边**的方向（0° = 沿列方向即水平边，90° = 沿行方向即竖直边）；卡尺搜索区的角度是**扫描方向**（垂直于边）。要么两边统一加/减 90°，要么下游一律按本算子口径判 |
| 方向角"突然从 5° 跳到 175°" | `Phi` 归一化在 [0,180)，0 与 180 同义。做趋势/报警前先取"离当前值近的补角"，别直接比大小 |
| 数值来回抖 | ① `Sigma` 略增；② 确认 `FitAlgorithm` 是 Tukey；③ `MaskRegion` 挪开毛刺、倒角、隔壁件的边缘；④ 让被拟合的边更长（长边平均掉局部噪声） |
| 边断成好几段、每段都短 | 高低阈值差距太小 → 拉大 `HighThreshold` 与 `LowThreshold` 的间距；或 `Sigma` 略增让剖面连续 |
| 改了 `FitAlgorithm` 一点反应没有 | 查找类型是**椭圆**：椭圆走固定算法，不吃这一项 |
| 圆/椭圆一直报"轮廓存在但拟合失败" | 点集退化（选中了近乎直线的弧、或轮廓太短）或目标本来不是这个形状：先加 `MaskRegion` 套住目标，再放大 `Sigma` 或 `MinContourLength`（文案里就是这么建议的） |
| 图上只有原图、没有绿色标注 | 推图失败只写日志不影响结果——去日志找"预览发布失败（视图 N），算法结果不受影响"，按提示查窗口号与宿主 |
| 什么都没显示 | `DisplayViewIndex` 填了 0，或上游本轮失败没给图 |

## 口径与失败策略

- **坐标系**：全部**图像像素系 (Row, Col)**，Row 向下、Col 向右；角度单位**度**，`Phi` 归一化 **[0,180)**。
- **不乘像素当量**：基元是"位置"的载体，乘了当量就不能继续参与求交/构造（下游要求同一坐标系）。
  长度换算只在「几何计算」的**数值**输出口做——当量接那里，别接这里。
- **接了 `MaskRegion` 也不搬坐标系**：它只是把处理范围剪纸（取域），输出的行列仍是整图坐标。
  这就是它比"先裁剪再找"省事的地方——**下游一个都不用换算**。
- **失败即明确失败**（默认）：不返回"上一个能用的值"糊弄过去。三种失败文案各自带处置方向：
  未接图像 / 未找到足够长的轮廓 / 轮廓存在但拟合失败。
- **`FailOnNotFound = false` 时**：找不到边不再判失败，步骤 `Success` 仍为 true，只把 `IsFound` 置 false，流程继续；
  此时其余输出是本轮的**空值**（`Geometry` 为 null、`Row`/`Col`/`Phi`/`Radius` 为 0），不是上一轮的残留。
- **每轮开头清零**：`Geometry`/`IsFound`/`Row`/`Col`/`Phi`/`Radius` 一律先重置，
  `Contours`（非托管）由框架在轮首自动回收。失败轮下游读到的是空值，**不是脏值**。
- **显示是给人看的，不参与判定**：找不到时也会推一张带红字"未找到轮廓"的图（拟合失败推"未拟合到目标"），
  成功时推**绿色**的拟合线/圆/椭圆 + 结果文字（`φ=` / `r=` / `长×短`）；推的是**源图**，不带区域裁剪。
- **并行安全**：纯视觉计算、不写全局变量，可以放进并行分支，不会被编译期标为并行不安全。

## 典型用法 / 接线

```
图像采集.OutputImage ──▶ 几何查找.SrcImage
ROI.MaskRegion       ──▶ 几何查找.MaskRegion     （区域口；Domain_名字 是图像，类型对不上）
几何查找.Geometry    ──▶ 几何计算.A
几何查找#2.Geometry  ──▶ 几何计算.B               （两个特征 → 距离/夹角/求交）
几何查找.Row         ──▶ 变量赋值 / CSV记录
几何查找.Phi         ──▶ 结果显示.r1              （格式 0.##，单位 °）
几何查找.Contours    ──▶ 结果显示.r2              （青色描边，复核拟合用的是哪条边）
标定.MmPerPixel      ──▶ 几何计算.MmPerPixel     （当量只在计算侧乘，不接这里）
```

**摆一个"找竖直边"的最小例子**：① 采集图连 `SrcImage`；② 「ROI」算子画一条**压住那竖直边**的框，
它的 `MaskRegion` 连本算子；③ `Kind` 选直线，其余先默认；④ 跑一遍看视图窗口里绿线是否贴住边——
贴上再谈阈值，没贴上先查区域。

## 常见问题

**Q：查找类型里没有"点"，我要一个点怎么办？**
本算子只出直线/圆/椭圆三种。要圆心就用"圆"（`Row`/`Col` 就是圆心，`Radius` 就是半径）；
要角点、交点这类"点"，找两条边再让「几何计算」求交，或先求交拿到一个点、再拿它跟某条边求垂足——比直接描点稳得多。

**Q：为什么不用「卡尺测量」？它也能找边。**
卡尺是"量一个已知量"（要选测量类型、摆搜索区、填标准值），本算子是"把结构摸出来"（出基元，不出判定）。
需要重复精度、直接出 mm 与 OK/NG → 卡尺；需要把边/圆当数据继续算关系 → 本算子 + 几何计算。
注意两者**角度口径差 90°**（见上面的现象表）。

**Q：同一个视野里有三条边，能不能一次都找出来？**
不能，一轮只拟合最长的一条。要三个特征就放三个本算子，各配一个 `MaskRegion`。

**Q：`FailOnNotFound` 到底该不该关？**
只有"找不到是正常分支"的场合才关（遍历料盒、判断有没有件）。
一旦关掉，下游就必须看 `IsFound` 分流；只看 `Success` 的话，失败轮会被当成"跑通了但值是 0"。

**Q：低阈值 / 高阈值怎么填？**
先按默认（20 / 40）跑一遍；报"未找到"就降 `LowThreshold`（一次降 5），
到处乱出边就升 `LowThreshold`；边连续不上、被切断就拉大两者间距。填反了不用纠——高阈值不足"低 + 1"时会被自动抬上去。

**Q：接了 `MaskRegion`，输出的坐标要加偏移吗？**
不用。区域只是限定处理范围，图没被裁剪，行列仍是整图坐标。
只有上游用了 `Crop_名字`（真裁剪图）才需要加 `OffsetRow_` / `OffsetCol_`。

**Q：能不能把它当"定位"用，输出给机械手？**
它输出的就是像素系的基元，可以做定位源，但**记得换算与标定**：机械手要的是物理坐标，
像素 → 毫米要么走「几何计算」的数值口（接当量），要么接位姿/坐标变换那一类算子；直接拿像素当毫米是最贵的错。
