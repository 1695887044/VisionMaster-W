# 几何查找 · 排错与常见问题

> 分类：几何工具 ｜ 来源：插件 Plugin.GeometryFinder

## 现场现象 → 先查什么

| 现场现象 | 先查这里 |
| --- | --- |
| 报"未找到足够长的轮廓（长度下限 X px）" | ① `MaskRegion` 是否罩住了目标边（最常见）；② 阈值太高（`LowThreshold` 先降到 10~15）；③ `MinContourLength` 比目标边本身还长；④ 视野里本来就没什么对比度 |
| 找到了，但拟合的是隔壁那条边 | "最长"选错了：`MaskRegion` 把视野收到只剩目标，或把 `MinContourLength` 提上去把干扰段筛掉 |
| 拟合出的**圆半径明显偏大** | 只拟到一小段弧（弧越长越能定住圆）。处置：把区域扩到能吃到**大半个圆周**、`LowThreshold` 降一点让轮廓连起来、`Sigma` 略增。点太少（< 3）时会直接报拟合失败 |
| 直线方向角跟现场量到的**差 90°** | 口径不同不是错：本算子的 `Phi` 是**沿着边**的方向（0° = 沿列方向即水平边，90° = 沿行方向即竖直边）；卡尺搜索区的角度是**扫描方向**（垂直于边）。要么两边统一加/减 90°，要么下游一律按本算子口径判 |
| 方向角"突然从 5° 跳到 175°" | `Phi` 归一化在 [0,180)，0 与 180 同义。做趋势/报警前先取"离当前值近的补角"，别直接比大小 |
| 数值来回抖 | ① `Sigma` 略增；② 确认 `FitAlgorithm` 是 Tukey；③ `MaskRegion` 挪开毛刺、倒角、隔壁件的边缘；④ 让被拟合的边更长（长边平均掉局部噪声） |
| 边断成好几段、每段都短 | 高低阈值差距太小 → 拉大 `HighThreshold` 与 `LowThreshold` 的间距；或 `Sigma` 略增让剖面连续 |
| 改了 `FitAlgorithm` 一点反应没有 | 查找类型是**椭圆**：椭圆走固定算法（`fitzgibbon`），不吃这一项。直线与圆才按这一项换鲁棒实现 |
| 圆/椭圆一直报"轮廓存在但拟合失败" | 点集退化（选中了近乎直线的弧、或轮廓太短）或目标本来不是这个形状：先加 `MaskRegion` 套住目标，再放大 `Sigma` 或 `MinContourLength`（文案里就是这么建议的） |
| 图上只有原图、没有绿色标注 | 推图失败只写日志不影响结果——去日志找"预览发布失败（视图 N），算法结果不受影响"，按提示查窗口号与宿主 |
| 什么都没显示 | `DisplayViewIndex` 填了 0，或上游本轮失败没给图 |
| 下游「几何计算」报"输入 A 为空" | 本算子本轮没成功（失败轮 `Geometry` 是 null）。先修本算子，别去改下游 |

## 常见问题

**Q：查找类型里没有"点"，我要一个点怎么办？**
本算子只出直线/圆/椭圆三种。要圆心就用"圆"（`Row`/`Col` 就是圆心，`Radius` 就是半径）；
要角点、交点这类"点"，找两条边再让「几何计算」求交，或先求交拿到一个点、再拿它跟某条边求垂足——比直接描点稳得多。

**Q：为什么不用「卡尺测量」？它也能找边。**
卡尺是"量一个已知量"（要选测量类型、摆搜索区、填标准值），本算子是"把结构摸出来"（出基元，不出判定）。
需要重复精度、直接出 mm 与 OK/NG → 卡尺；需要把边/圆当数据继续算关系 → 本算子 + 几何计算。
注意两者**角度口径差 90°**（见上面的现象表）。

**Q：同一个视野里有三条边，能不能一次都找出来？**
不能，一轮只拟合最长的一条。要三个特征就放三个本算子，各配一个 `MaskRegion`。

**Q：`FailOnNotFound` 到底该不该关？**
只有"找不到是正常分支"的场合才关（遍历料盒、判断有没有件）。
一旦关掉，下游就必须看 `IsFound` 分流；只看 `Success` 的话，失败轮会被当成"跑通了但值是 0"。

**Q：低阈值 / 高阈值怎么填？**
先按默认（20 / 40）跑一遍；报"未找到"就降 `LowThreshold`（一次降 5），
到处乱出边就升 `LowThreshold`；边连续不上、被切断就拉大两者间距。填反了不用纠——高阈值不足"低 + 1"时会被自动抬上去。

**Q：接了 `MaskRegion`，输出的坐标要加偏移吗？**
不用。区域只是限定处理范围，图没被裁剪，行列仍是整图坐标。
只有上游用了 `Crop_名字`（真裁剪图）才需要加 `OffsetRow_` / `OffsetCol_`。

**Q：能不能把它当"定位"用，输出给机械手？**
它输出的就是像素系的基元，可以做定位源，但**记得换算与标定**：机械手要的是物理坐标，
像素 → 毫米要么走「几何计算」的数值口（接当量），要么接位姿/坐标变换那一类算子；直接拿像素当毫米是最贵的错。

**Q：界面上的下拉为什么显示中文？**
`Kind` 与 `FitAlgorithm` 两个枚举端口都逐个成员标了中文名（直线 / 圆 / 椭圆；
最小二乘 / Huber 抗离群 / Tukey 抗离群（推荐）），绑定与「模块参数」界面读的就是这份标注。
**存盘写的是枚举的数值**（流程文件里能看到 `"Kind": 1` 这种，不是成员名也不是中文标签），
所以改中文标签不会打断已经配好的流程；反过来说，手改流程文件时要把数值改对。
`Huber` / `Tukey` 是人名、无通用译名，保留原字。

**Q：`Sigma` / 阈值填了 0 或负数会怎样？**
不会报错，也不会喂给底层算子：`Sigma` 低于 0.4 按 0.4、低阈值低于 1 按 1、
高阈值不足"低 + 1"抬到"低 + 1"、长度下限低于 1 按 1。以实际生效值判断现象，别按你填的数判断。
