# 虚拟运动卡（仿真）：配置项与参数

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.Virtual

这一页回答：**「运动卡设置」里哪些字段对仿真真实生效、哪些只是存着**，
以及仿真专用开关（界面上没有入口的那一组）各自管什么。
时间口径与仿真深度见《仿真相位差与延时口径》，报错原文见《排障》。

## 一、「系统 → 运动卡设置」字段逐个

| 字段（对应配置对象属性名） | 必填 | 仿真是否消费 | 说明 |
| --- | --- | --- | --- |
| 驱动类型 `DriverTypeKey` | 是 | 是 | 选「虚拟运动卡（仿真）」。列表来自宿主扫描运行目录 `Modules\` 下实现运动设备接口的类型——DLL 没投递就选不到 |
| 内部身份 `Id`（Guid） | —— | 是 | 界面不展示。**所有内部引用一律用它，不用显示名**——显示名用户可以随便改 |
| 显示名 `DisplayName` | 是 | 只用于展示 | 界面上的一行标题按"显示名 → 地址 → (未命名运动卡)"回退；改它不断流程（流程引用的是轴名，不是卡名） |
| 地址 `Address` | **不用** | **否** | 本驱动的连接流程**完全不读地址**：留空、乱填都能连。地址只在真卡（如正运动）那侧有意义 |
| 机型 `CardModel` | **不用** | **否** | 机型不影响仿真轴数与 IO 数（那些是下面的固定开关值） |
| 自动连接 `AutoConnect` | 否 | 是 | 勾选后宿主在方案加载/启动时自动连接本卡 |
| 备注 `Remarks` | 否 | 只用于展示 | 纯给人看 |
| 轴映射 `Axes` | 是 | **部分**（见第三节） | 每行：逻辑轴名（**全局唯一**，流程用它寻址）、物理轴号（**0 基**，仿真可用 `0~2`）、是否启用、软限位 |

## 二、卡级运动参数（`Params`，与真卡同一套字段）

界面上可配、但对仿真**真实生效**的：

| 参数 | 默认 | 仿真里的作用 |
| --- | --- | --- |
| `DefaultVelocityMmPerS` | `50` | 运动命令速度填 0 时，仿真用它推进（真卡口径不同：不覆盖控制器内速度。见《相位差》页） |
| `PollIntervalMs` | `10` | **轮询与位置推进的节拍**：仿真内部再夹到 `1~1000` ms。它直接决定"每拍走多远" = 速度 × 该间隔，也决定使能/报警等状态多久被快照反映 |
| `CommandTimeoutMs` | `30000` | 单条命令默认超时；回零命令若未带超时也用它兜底（回零**步骤**会在此基础上再加 1000 ms 等结果） |
| `WatchdogTimeoutMs` | `3000` | 看门狗：连续轮询失败、超过该时长没有成功轮询 → 判失联并安全停机（与真卡同一套规则，实际取值下限 200 ms） |
| `MaxQueueDepth` | `256` | 命令队列上限，满了报"命令队列已满" |

界面上可配、但仿真**不消费**的（只是存着，随方案落盘）：

| 参数 | 默认 | 为什么没作用 |
| --- | --- | --- |
| `DefaultAccelMmPerS2` | `500` | 仿真**匀速逐拍推进、不做加减速**——改它看不出任何差别 |
| `AutoReconnect` | `true` | **运动卡这一层没有自动重连逻辑**：掉线后卡进「已安全停机」，需要在「运动卡设置」里**先断开再连接**才会重建（真卡同口径，这个字段当前是纯配置项） |

## 三、轴映射字段的生效矩阵

| 轴映射字段 | 默认 | 仿真是否消费 | 说明 |
| --- | --- | --- | --- |
| `LogicalName` | 自动补 `A{序号}`（全局不重名） | 是 | 流程寻址键；改名会级联教学点位（走注册表的改名入口，别直接改字段） |
| `PhysicalIndex` | —— | 是 | 必须落在 **0~2**，超出报 `轴号 … 超出仿真范围（0~2）` |
| `Enabled` | `true` | 是 | 未启用的轴流程解析时被拒（"处于停用状态"）；仿真模拟限位时也跳过未启用的轴 |
| `SoftLimitMinMm` / `SoftLimitMaxMm` | ±1000000 | 是 | **两重作用**：目标越界时命令在入队就被拒（基类门禁）；运动途中位置越过软限位线，仿真会置正/负限位状态位（用来验证硬信号 → 急停 → 报警链路）。默认值等于不设防，建议改成真实行程 |
| `UnitsPerMm`（脉冲当量） | `1000` | **否** | 仿真内部就用 mm 记账，不做脉冲换算——"改当量"这类验证只能在真机做 |
| 轴配置弹窗 7 个低频字段（编码器类型/PPU、驱动器、额定电流、跟随误差上下限、备注） | 各有回退显示值 | **否** | 只是存着，不参与任何仿真行为 |

## 四、仿真专用参数与故障注入开关（**界面上没有编辑入口**）

这一组不是方案配置，**不随 `.vms` 落盘**；只有自动化冒烟测试与代码会直接设置它们，现场不要指望能调到。

| 开关 / 方法 | 默认 | 用途 |
| --- | --- | --- |
| `SimulatedAxisCount` | `3` | 仿真轴数（**连接时**生效，改完要重连；下限 1） |
| `SimulatedInputCount` / `SimulatedOutputCount` | `8` / `8` | 仿真 IO 点数（连接时生效，下限 1） |
| `SimulatedAbsoluteEncoder` | `true` | 声明为绝对式（连接后位置即可信，无需回零）或增量式（连接后"已回零"为假，必须先回零；失联后强制归假——专门用来验证这条恢复规则） |
| `SimulatedHomeDurationMs` | `200` | 回零耗时（ms）：仿真不看开关、不找 Index，固定这么久之后把位置写成 0（下限 1） |
| `SimulateAlarm` | `false` | 让**所有轴**报 `模拟：伺服报警`，验证报警门禁、硬信号打断与清报警。**清报警命令会把这个开关一起复位**（否则"清完立刻又报"） |
| `SimulatePollException` | `false` | 让轮询抛 `模拟：与运动卡的通信中断`，验证看门狗 → 安全停机 |
| `SimulateCommandFailure` | `false` | 让**绝对运动 / 相对运动 / 回零**三类命令强制失败（`模拟：运动命令执行失败`），验证失败分级与"失败即清队 + 安全停机"。注意它**不拦点动与停止**（见《相位差》页的命令深度表） |
| `SetInput(点号, 值)` | —— | 把某个仿真输入点置位（模拟传感器/限位信号），供自动化脚本造条件 |
| `SetSimulatedPosition(轴, mm)` / `GetSimulatedPosition(轴)` | —— | 直接把轴摆到某位置 / 读仿真位置，造初始条件用，**不走命令通道** |

## 五、对外声明的能力（连接时写死）

| 能力项 | 仿真值 | 与真卡（正运动）的差别 |
| --- | --- | --- |
| 轴数 | `3`（物理轴号 0~2） | 正运动按机型：ECI3428=4、ECI3828/ZMC408SCAN=8、VPLC532R=32 |
| 数字输入 / 输出 | `8` / `8`，点号 **0 基** | 正运动典型 24 入 / 16~20 出（未核实机型按显示上限标出） |
| 硬限位 | 支持 | 仿真实为"位置越过**软限位**就算撞限位"；真卡是控制器上的限位输入 |
| 绝对值编码器 | 由 `SimulatedAbsoluteEncoder` 决定（默认支持） | 真卡也声明支持但文档口径保守；两边都请按"上电先回零"写流程 |
| 点动 Jog | 支持 | 一致 |
| 直线 / 圆弧插补 | **不支持** | 正运动同样未上报插补能力 |
| 回零方式 | **只有 3 种**：`NegativeLimitIndex`（负限位 + Index）、`Origin`（原点开关）、`PresetZero`（零位置预设） | 正运动总线型支持全部 8 种、脉冲型 3 种（且第 2 种是正限位+Index，与仿真不同）。仿真里选这 3 种之外的方式，**入队时**就被拒（`Rejected_NotSupported`）；且这 3 种在仿真里执行完全一样——见《相位差》页 |

## 六、这些配置存在哪儿

- 「运动卡设置」的全部字段（含轴映射与卡级参数）是**纯配置对象**，随方案 JSON 落盘（`.vms`）。
  运行态的句柄、状态、队列计数一律不落盘——配置与"这一秒卡在什么状态"彻底分开。
- 第四节的仿真开关**不在配置对象里**，不随方案保存，重启回到代码默认值。
- 换卡型（仿真 ↔ 正运动）只换驱动类型与地址/机型字段，轴映射与流程不用动——前提是物理轴号在新卡范围内。
