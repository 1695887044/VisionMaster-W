# 虚拟运动卡（仿真）：仿真相位差与延时口径

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.Virtual

这一页专讲**时间**：仿真里的每一步延迟从哪来、和正运动真卡差在哪、
以及"哪些指令真仿真了状态机、哪些只是即时记账"。判断"仿真到底验了什么"，照着这张表来。

## 一、时间模型：一切由轮询节拍驱动

仿真的世界只有一条时间轴——**卡级轮询** `PollIntervalMs`（默认 10 ms，仿真内部夹到 `1~1000` ms）：

- 每一拍，仿真把每根轴朝目标推进 `速度 × 拍长` 毫米（匀速，无加减速）；走完剩余距离就直接落在目标上。
- 速度取运动命令带的值；**带 0 时用卡级默认速度**（默认 50 mm/s）。
  正运动口径不同：速度 0 表示"不覆盖控制器内当前 SPEED"——所以**仿真节拍 ≠ 真机节拍**，节拍敏感流程必须显式给速度。
- 位置、到位位、运动位、报警位、限位位、IO 输入，全部只在**这一拍结束时**写进状态快照。
  命令线程与步骤读到的永远是"上一拍的自己洽结果"。

**推演示例**：目标 20 mm、速度 200 mm/s、拍长 10 ms → 一拍走 2 mm，约 10 拍（≈100 ms）后
某拍同时置"到位且静止"。「等待到位」步骤（自身查看间隔默认 20 ms）大约再多等半拍到一拍发现。
把拍长改成 100 ms，同样的行程就是 1 拍走完——仿真耗时随拍长**线性变化**，这不是 bug，是它的节拍本质。

## 二、整条链路的相位差（谁比谁晚一拍）

| 事件 | 命令返回时刻 | 快照反映时刻 | 与真机的差别 |
| --- | --- | --- | --- |
| 运动下发（绝对/相对） | **立即 Done**（只写目标与速度，不等走完） | 走完才置 `InPosition` | 一致：真卡也是"下发即返回、到位另行报"（守门断言 `★Move 下发成功 ≠ 已到位（命令已 Done，但轴仍在途中）`） |
| 使能 / 失能 | 立即 Done（直接改仿真状态） | **下一拍**才在快照看到 `Enabled` | 真机驱动器上电有实际延时；仿真的"晚一拍"是纯节拍效应——命令完成与快照刷新是两件事（断言 `轴使能命令完成，且设备回报已使能` 特意分别等待两者） |
| 报警注入（开关打开） | 无命令参与 | **下一拍**所有轴带报警；基类随后把卡转「报警」 | 真机是伺服真实状态位；仿真只有"被开关造出来"的报警，**报警含义本身验不了**（断言 `★轮询到伺服报警 → 状态转 Alarm` 钉的是发现链路，不是报警成因） |
| 清报警 | 立即 Done，且把所有轴报警与注入开关一起复位 | 下一拍恢复干净 | 真卡清完不会自动使能——这条恢复顺序（清报警 → 轴使能 → 回零）仿真照样能验 |
| 回零 | **唯一会等的命令**：命令线程阻塞到 `SimulatedHomeDurationMs`（默认 200 ms）期满，位置写成 0 | 期满那一拍置到位 | 真机是撞开关 + 找 Index，几十秒常态；**超时值不要照抄仿真的观感调小**（「轴回零」步骤会等 卡级超时 + 1000 ms） |
| 点动 Jog | 立即 Done，目标设为当前位置 ±1000000 mm | 每拍推进直到被停止 | "没有终点"的语义是真的；但推进匀速、无阻尼，撞到软限位线才停 |
| 通信故障注入 | 无命令参与 | 该拍轮询抛异常；基类累计连续失败，超过约 `WatchdogTimeoutMs`（实际下限 200 ms）判失联 → **安全停机** | 看门狗与安全停机路径**与真机同一实现**（可信）；网络时序、丢包不可验 |
| 急停 | 立即返回：清空待执行队列 + 打断当前命令 + 停全部轴 | 下一拍快照干净 | 队列与打断是基类同一实现（可信）。注意回零被打断在仿真里表现为：循环检测到取消后**抛"已取消"异常**（按契约），基类据此把"被急停打断"与"真的回零失败"分开——不记故障（断言 `急停是预期操作：不记成设备故障、也不进安全停机`） |

## 三、命令逐条仿真深度（状态机 / 即时记账 / 真等待）

仿真对九类命令的处理**深浅不一**，逐条对着实现写（"真卡"列为正运动驱动的口径）：

| 命令 | 仿真怎么处理 | 有没有时间演化 | 真卡（正运动）对应动作 |
| --- | --- | --- | --- |
| 使能 | 直接置内部标志，立即 Done | 无（即时记账） | 驱动器上电，正运动失能前还会先补一次减速取消 |
| 失能 | 清标志 + **把目标撤回当前位置**（失能即停） | 无 | 先取消运动再断电 |
| 绝对运动 | 校验未使能/报警 → 写目标与速度 → **立即返回 Done** | **有**：位置由轮询线程逐拍推进 | 下发定位命令即返回；速度 0 不覆盖控制器内 SPEED；每次定位前按曲线类型写 S 段参数（梯形=0、S 曲线=200 ms） |
| 相对运动 | 同上，目标 = 当前位置 + 增量 | 有 | 同上 |
| 点动 | 校验后把目标设成 ±1000000 mm 即返回 | 有（直到被停止/越线） | 真实连续速度模式，按住/松开 + 心跳兜底 |
| 回零 | **唯一真正等待的命令**：置回零中 + 截止时间，循环等轮询线程把它翻完；支持取消（抛"已取消"）与超时（报 `回零超时（>…ms）`）；期满位置 = 0 | 有（固定时长） | 真实寻零：总线型走datum + 完成判据（回零状态=1），脉冲型走另一条 + 空闲判据；**模式支持与否、耗时、方向全由机构决定** |
| 停止 | 目标撤回当前位置（-1 = 全部轴逐根撤），立即 Done | 无 | 逐轴下发取消（减速/立即按模式号 2/3） |
| 写输出 | 越界校验后直接改仿真输出数组 | 无 | 写真卡的输出口 |
| 清报警 | 所有轴报警位清除 + 复位注入开关 | 无 | 向厂商接口发清除请求 |
| 其余未来新增命令 | 兜底返回"不支持"：`虚拟卡不支持命令：…` | —— | 逐驱动实现 |

三条"别误会"：
- **回零方式在仿真里不分模式**：声明支持的 3 种（负限位+Index / 原点开关 / 零位置预设）执行完全相同——
  都是等 `SimulatedHomeDurationMs` 然后置零。仿真验的是"回零步骤会等待、会超时、会归零坐标系"，
  不是任何寻零路径。
- **未使能/报警拦截有两层**：驱动层命令入口也查这两条（所以 `SimulateCommandFailure` 之外还有这些即时拒绝），
  但真正常见的是**基类门禁先拦**——卡进「报警」后运动命令根本入不了队。两层原因文案不同，别混。
- **`SimulateCommandFailure` 只拦绝对/相对/回零**：点动、停止、使能、IO 不受它影响——
  想验"点动中途失败"这条链，仿真给不了，别把它当全覆盖的故障注入。

## 四、HomeMode 对照（C# 值 ≠ 正运动模式码，别当同一个数用）

流程与界面存的是**成员名**；下表"本仓值"是契约枚举的数值，"正运动模式码"是驱动映射给厂商的数
（照驱动映射表逐条抄，**两边根本不是同一套编号**）：

| 成员名 | 本仓值 | 中文显示名（契约层字典） | 正运动模式码 | 虚拟卡声明支持 |
| --- | --- | --- | --- | --- |
| `NegativeLimitIndex` | 0 | 负限位 + Index | 1 | 是 |
| `PositiveLimitIndex` | 1 | 正限位 + Index | 2 | 否 |
| `Origin` | 2 | 原点开关 | 19 | 是 |
| `NegativeLimitOrigin` | 3 | 负限位 + 原点 | 27 | 否 |
| `PositiveLimitOrigin` | 4 | 正限位 + 原点 | 23 | 否 |
| `PresetZero` | 5 | 零位置预设（不找开关） | 37 | 是 |
| `NegativeLimit` | 6 | 负限位（不回原点） | 17 | 否 |
| `PositiveLimit` | 7 | 正限位（不回原点） | 18 | 否 |

- 中文不写在枚举成员上、也不写 `[Display]`：显示词表在契约层（驱动写日志、界面上拉、故障提示三处共用同一个说法），
  且那里用穷尽 switch——漏一个成员编译器直接报错，成员名保持与厂商手册一致方便对照。
- 正运动总线型支持全部 8 种、脉冲型只报 3 种（`NegativeLimitIndex` / `PositiveLimitIndex` / `Origin`）；
  虚拟卡报的是另一组 3 种（见"声明支持"列）。**同名的回零方式，三张表里支持的集合互不相同**——
  仿真里能过不代表真机能过，选方式前先想清楚目标卡型。
- 手写数值 = 灾难：把 1 当"负限位+Index"写进存档，本仓值是 `PositiveLimitIndex`；一切引用请写成员名。

## 五、仿真验得到 / 验不到（照着判断 CI 绿了什么）

**验得到**：流程结构（使能→回零→运动→等待→读状态→停止 的顺序与分支）、"下发 ≠ 到位"有没有配等待、
轴名/卡名解析、软限位越界被拒、超时判失败、急停清队与打断、报警/限位进安全停机、
重连后的状态恢复、错误文案与分支处置。

**验不到（必须真机联调）**：脉冲当量与方向、真实节拍与加减速/S 曲线、回零路径与开关极性、
编码器实际位置与指令位置之差、IO 点号与实物接线对应关系、伺服报警含义、网口通信时序与丢包、
多轴同时运动的真实并行性、以及任何与力/惯量相关的机械行为。
