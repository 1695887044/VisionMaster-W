# 虚拟运动卡（仿真）：快速上手

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.Virtual

**没有硬件时的替身运动卡**：3 根仿真轴 + 8 个数字输入 + 8 个数字输出，把"命令排队、异步运动、
急停插队、看门狗安全停机、报警门禁"整套行为在软件里演出来。它不是流程里的算子——
它出现在「系统 → 运动卡设置」的驱动列表里；流程中的七个运动步骤（轴使能 / 轴回零 / 轴运动 /
等待到位 / 读轴状态 / 轴卡 IO / 轴停止）按原名在它上面跑，一个字节都不用改。

## 跑通第一次：5 步

1. 「系统 → 运动卡设置」新增卡：驱动选「虚拟运动卡（仿真）」，卡名如 `运动卡1`，勾「随方案启动自动连接」。
   **地址与机型都不用填**——本驱动的连接流程完全不读它们（见《端口与参数》页的生效矩阵）。
2. 轴映射：`X→0`、`Y→1`、`Z→2`（物理轴号 **0 基**，仿真只有 0~2），按机构把软限位改成真实行程
   （默认 ±1000000 mm 等于不设防）。
3. 连接。状态说明应显示：`已连接虚拟卡（3 轴，绝对编码器，位置可信）`。
4. 流程照真卡写法排：
   `轴使能(X) ──▶ 轴回零(X) ──▶ 轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(OUT0=ON) ──▶ 轴停止(X)`
5. 跑一次：`等待到位` 的 `Elapsed` 应能看出"运动真的花了几拍"而不是 0——若秒过且位置没变，
   多半是"少放了等待"或"运动步骤其实失败了"，正好用仿真抓这类结构错误。

## 它存在的两个理由

- **没有硬件也能开发与回归**。运动控制的多数逻辑（排队、异步语义、急停打断、看门狗、报警门禁、
  软限位）发生在基类与宿主这一层，与具体板卡无关——仿真与真卡**共用同一副骨架**，
  仿真验过的流程结构上可以直接搬。
- **故障注入**。真卡上不能随便制造"掉线""伺服报警""轮询超时"，而这些恰恰最需要验证
  （安全停机、错误分级、重连后的零点处理）。仿真把它们做成了开关（见《端口与参数》页第二组）。

## 一条必须先建立的认知：下发 ≠ 到位

仿真刻意模拟"真实异步运动"而不是"瞬间到位"：运动命令**立即返回**，位置由轮询线程按速度
**逐拍推进**，走完才置 `InPosition`。这样才能测出这条最容易写错的语义——
若仿真是瞬间到位，一切流程看起来都对，真机上却会出现"两条轴同时下发、实际串行"。
推进的节奏、延时与相位从哪来、和真机差在哪，专页讲清：《仿真相位差与延时口径》。

## 该看到什么 / 不该期待什么

| 期待 | 仿真里实际是 |
| --- | --- |
| 流程顺序与分支跑通 | **可信**——与真卡同一套队列、门禁、状态机 |
| 报错文案与失败分流 | **可信**——"轴未使能""软限位拒绝""报警态被拒"都是同一来源 |
| 节拍（`Elapsed` 的数值） | **不可信**——仿真匀速推进、回零固定约 200 ms，节拍数量级与真机不同 |
| 脉冲当量 / 方向 / 编码器实际位置 | **验不到**——仿真内部就用 mm 记账，没有脉冲概念 |
| IO 点号与实物接线对应关系 | **验不到**——仿真固定 8 入 8 出 |

## 典型用法

```
① 离线开发：按上面 5 步配一张卡，产线流程在它上面排结构、对文案。
② 专验异常路径（仿真的真正价值）：
   - 忘记放「轴使能」→ 应看到 `轴未使能（请先执行「轴使能」步骤）`，然后补步骤
   - 「轴运动」后不放「等待到位」→ 夹紧步骤立刻跑、位置还没到 → 说明少了等待
   - 绝对目标写到软限位之外 → 应看到被拒绝（参数无效）+ 软限位原因
   - 把「等待到位」超时给得很小 → 制造超时分支，核对报错里带的位置读数
③ 保留一张虚拟卡专跑调试流程，产线流程跑真卡（注意「轴停止」留空 = 停**所有卡**的全部轴，
   混用时仿真卡也会被一起停——它本来就停着，无副作用，但要知道有这件事）。
```

## 切到真卡时要检查什么

仿真→真机只动配置、不动流程（这正是按轴名寻址的目的）。逐项核对：
① 轴映射的物理轴号与真卡机型匹配；② 每轴脉冲当量与软限位改成真实值；③ 地址（IP）与机型填写；
④ native DLL 齐（正运动要 `zauxdll.dll` 与 `zmotion.dll`，见该驱动帮助页）；
⑤ 仿真里"回零很快"掩盖的顺序问题；⑥ IO 点号范围变化。
差异逐条在《仿真相位差与延时口径》页的对照表里。

**Q：驱动列表里没有「虚拟运动卡（仿真）」？**
宿主扫描的是运行目录 `Modules\` 里带显示特性的驱动类型——`Plugin.Motion.Virtual.dll` 没投递到 `Modules\`
就选不到（改了源码必须重建插件工程，产物陈旧是这里最常见的坑）。
