# 虚拟运动卡（仿真）· 开发：不变量与陷阱清单

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.Virtual ｜ 读者：开发

两组：A 组"违反就闸门红 / 断言红"，B 组"违反不报错、只出诡异现象"。每条一律写成
**症状 → 机理 → 守门断言名**。断言名逐字取自 `FlowCanvasChecks\MotionChecks.cs`
（30 条，段名 `[M] 运动控制内核：门禁 / 异步语义 / 软限位 / 急停打断 / 看门狗 / 报警 / 回零`、
`[M] 命令门禁与异步语义（下发 ≠ 到位）`、`[M] 软限位门禁`、`[M] 急停：清空队列 + 打断正在执行的命令`、
`[M] 看门狗：轮询失联 → 安全停机 + 位置失效`、`[M] 报警：状态门禁 → 清报警恢复`、
`[M] 回零：完成即归零 / 不支持的方式当场拦住`），手册侧断言取自 `FlowCanvasChecks\HelpManualCheck.cs`。
**查不到对应断言的条目已标明"无断言，靠人工核对"，不许当成已守。** 这套断言全部跑在虚拟卡上，
所以虚拟卡被改坏时它是唯一会红的地方——也正因为它只跑虚拟卡，"真卡独有的行为"不在它的守门范围内。

## A 组：违反就断言红

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| 没连接也能"发命令"，界面上看不出任何拒绝 | 基类状态门禁被绕过（驱动自己起了线程或直接改轴表） | `未连接时命令被拒绝（不会静默排队等着）`、`连接成功且状态为在线` |
| 界面显示不出这台卡有几轴几 IO，配置写错也没人拦 | `ConnectCore` 没调 `SetCapabilities`，能力位停在未知，轴号/输出点校验随之失去依据 | `连接后能力已回填（3 轴 / 8 输入 / 8 输出 / 有硬限位）` |
| 绝对式改成增量式后重连仍然"位置可信"，流程跳过回零直接跑 | `MarkHomed` 与 `SupportsAbsoluteEncoder` 两处口径不一致 | `绝对式编码器：连接后位置即可信（IsHomed=true）`、`增量式编码器：连接后位置不可信（IsHomed=false）`、`回零后 IsHomed=true` |
| 使能命令显示完成，但下一步 Move 一直报"轴未使能" | `Enabled` 没通过轮询快照回填（命令 Done 不等于快照已刷新） | `轴使能命令完成，且设备回报已使能` |
| 流程看起来并行、实际串行被仿真掩盖；或反过来所有等待步骤全部超时 | 把 Move/Jog 改成同步等待到位（最大失真），或把"立即返回"改成永远不推进 | `★Move 下发成功 ≠ 已到位（命令已 Done，但轴仍在途中）`、`轮询推进后轴真的走到目标（位置 ≈ 20mm 且到位）` |
| "配了 3 号轴但卡只有 2 根"这类配置错误静默进队列 | 轴号校验从基类挪走了，或能力位谎报轴数 | `轴号越界被拒绝（能力已知时按能力校验）` |
| 轴直接走到软限位之外 | 软限位门禁被绕过（`ExecuteCommandCore` 里自己判、或改了 mapping 让 `IsWithinSoftLimit` 恒真） | `目标超出软限位时被拒绝（不让轴往限位方向走）` |
| 一次正常的软限位拒绝在界面上显示成设备故障 | 拒绝的分级被改动：含"软限位"的 InvalidArgument 必须是 Notice | `软限位拒绝记为 Notice 级（业务上正常，不该当成设备故障）`、`被软限位拒绝后设备仍是可用的（不进报警/安全停机）` |
| 回零期间后续命令被立刻执行掉，"排队"这条语义没了 | 命令线程不再逐条串行执行，或 Stop/Jog 的抢占逻辑被扩大成"插队一切" | `回零执行期间，后续命令在排队等待` |
| 急停点了没反应，要等回零自己跑完 | Stop/Disable 不再属于打断性命令，或 `_emergencyCts` 的取消链没接到驱动 | `急停被接受`、`★急停能打断正在执行的命令（回零立刻结束，而不是等它跑完）` |
| 急停之后，之前排队的 Move 还是执行了 | 急停路径没清空队列（只打断了当前那条） | `★急停清空待执行队列（排队的 Move 全部被取消）` |
| 人工按急停被记成一次设备故障，甚至进了安全停机 | Home 的等待循环发现取消后返回 Failed 而不是抛取消异常 | `急停是预期操作：不记成设备故障、也不进安全停机` |
| 轮询抖动一次就把设备判成掉线（现场表现为偶发停机） | 基类要求连续 3 次失败才判失联；驱动改成"抛一次就 `NotifyDeviceLost`"会绕过这个阈值 | `★轮询连续失败后进入安全停机（看门狗）`、`安全停机后不再接受运动命令（不会在不知道轴在哪的情况下继续走）` |
| 通信失联被升级成"需人工复位"，操作员对着网线无从下手 | 两条失联路径的分级不同：轮询连续失败是 Recoverable，看门狗超时是 RequiresReset | `通信类失联记为可恢复级（而不是需人工复位）`、`★增量编码器失联后 IsHomed 归 false（位置不可信，必须重新回零）` |
| 伺服报警后界面状态还是 Online | 快照的 `Alarm` 位没填（轴级 Alarm 与全局注入开关取或的那一处被改坏） | `★轮询到伺服报警 → 状态转 Alarm`、`报警故障为需人工复位级（必须人工确认，不能自动恢复）` |
| 报警中能下发 Move | 报警态门禁被放宽（"清报警以外的命令也允许在 Alarm 态入队"） | `★报警态拒绝运动命令（不会对着报警中的轴下发 Move）` |
| 清完报警立刻又报，只能重启软件 | `ClearAlarm` 分支只清了轴级 `Alarm`，没把注入开关 `SimulateAlarm` 一起复位 | `★清除报警后回到可运动状态（不必重启软件）`、`清报警后运动命令恢复正常` |
| 回零完成但位置不在零点，坐标系没重建 | Home 收尾时漏了把位置与目标同时归零 | `回零命令完成`、`回零后位置归零（坐标系重建）` |
| 不支持的回零方式跑到一半才失败 | `SupportedHomeModes` 与实际实现不一致（声明少了、或实现里其实支持） | `★不支持的回零方式在入队时就被拒绝（而不是运行到一半才失败）` |
| 手册被自动生成页顶掉 / 用户看到的不是这份 / 中文乱码 | 本程序集只有一个设备类，手册**必须扁平**放在 `Help\`；反过来运动步骤那侧必须一进一个子目录。层级放错 + `Help\**\*` 没进 `EmbeddedResource` + 编码带 BOM 或正文太短，是同一组症状的四个成因 | `HM2 多插件程序集不许放扁平手册（防串页）`、`HM3 Help 子目录名逐字等于插件类名（分册能被认出）`、`HM4 有 Help/*.md 的工程都带 EmbeddedResource（手册进得了 DLL）`、`HM7 手册都是无 BOM 的合法 UTF-8 且含中文（编码纪律）`、`HM8 每个插件的手册正文 ≥ 70 行（不是占位页）` |
| 开发章节混进用户册，显示分层失效 | 开发页文件名没有 `dev-` 段，或被塞进子目录 | `HM12 开发页文件名是 NN-dev-xxx.md（宿主认得出这是开发章节）`、`HM12b 手册最多一层目录（开发页另立子目录会挤掉用户页）` |

## B 组：不报错，只出诡异现象

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| 急停响应从毫秒级退化成一个等待步长 | Home 的等待循环里把 `ct.WaitHandle.WaitOne(5)` 换成 `Thread.Sleep`：取消仍会被处理，但要等睡完 | 无断言，靠人工核对（断言只等"回零立刻结束"的整体时限，睡 5 ms 与睡 500 ms 都能过） |
| 把 `PollIntervalMs` 夹到某个下限后，仿真速度莫名变快 | 推进用的 `dtSec` 与基类节拍是**两处同值的 clamp**；只改一边就等于改了速度倍率 | 无断言，靠人工核对 |
| 命令没给速度时轴"慢慢走"而不是不动 | 速度不大于 0 时回退 `DefaultVelocityMmPerS`，步长过小时再兜一次同样的默认速度 | 无断言，靠人工核对 |
| 到位判定抖动、或提前一拍报 InPosition | 推进与判停共用 1e-9 这个容差；换成毫米级常量后"剩余距离"会在一拍内被误判成 0 | 无断言（终态断言只看最后是否 ≈20 mm 且到位，不看判据本身） |
| 限位信号一次也不出现，点动撞出软限位也照样走 | 限位位**借的是软限位**，且要求该轴映射 `Enabled`；映射关掉或软限位留空，基类的入队门禁与执行侧限位会一起失效 | 无断言，靠人工核对（`目标超出软限位时被拒绝` 只覆盖入队那一侧） |
| 一个输入脉冲整批丢 | `SetInput` 只写数组，轮询每拍全量刷新；脉冲窄于一个节拍就没人见过它 | 无断言，靠人工核对 |
| 失能后轴还在按最后一拍的目标继续走 | Disable 分支少了"把目标拉回当前位置"那一行（真机也如此，仿真必须同形） | 无断言，靠人工核对 |
| 想测"点动失败"却注不进去 | `SimulateCommandFailure` 只卡 MoveAbsolute / MoveRelative / Home 三类，Jog / Stop / Enable 不在门禁里 | 无断言，靠人工核对（仿真覆盖面盲区，别当成"注入开关坏了"） |
| 删掉 `ClassifyOutcome` 的覆写后现场没提示"先使能" | 覆写只影响建议文案（Failed 默认已是可恢复级），级别不会红，手册里的建议行会失真 | 无断言，靠人工核对（`05-troubleshooting.md` 的原文对照表是它唯一的守门） |
| 未使能的失败被升级成 RequiresReset | 分级判据是错误文案里的"未使能"子串；文案改字（比如改成"伺服未使能"以外写法）就命中不到 | 无断言，靠人工核对（文案与子串互为契约） |
| 新增命令种类失败后队列照常跑，界面也不停机 | 落到 default 的 NotSupported 在基类里映射为命令 Failed，但**不触发**失败后的安全停机分支 | 无断言，靠人工核对 |
| 断言里换编码器类型没生效 | 断言的 `NewDescriptor(absoluteEncoder)` 形参其实没被使用，真开关是 `card.SimulatedAbsoluteEncoder` | 无断言，靠人工核对 |
| 换台机器/重启后仿真行为变了 | 所有 `Simulated*` 与 `Simulate*` 开关都不是描述符字段，不进 `.vms`，每次都是代码默认值 | 无断言，靠人工核对 |
| 报警原因在界面只剩"轴报警" | `AlarmMessage` 留空时基类用兜底文案；快照那句"模拟：伺服报警"是定位注入开关是否开着的关键线索 | 无断言，靠人工核对 |
| 驱动自己 `ReportFault` 之后日志刷成两遍 | 报警/限位的上报与安全停机是基类 `DetectCriticalSignals` 的职责，驱动只填快照；重复上报还会打乱"同一轴同一原因只报一次"的去重 | 无断言，靠人工核对 |
| 断开后仿真轴还"活着"，重连位置从旧值继续 | `DisconnectCore` 不清 `_axes` 就会残留；`SafeStopCore` 被删则失联时仿真世界仍按最后一条命令推进 | 无断言，靠人工核对（`★轮询连续失败后进入安全停机` 只判状态，不判位置是否真的停住） |

## 改这个文件时必须一起动的东西

| 改了什么 | 必须同步 |
| --- | --- |
| `SupportedHomeModes` 里的成员集合 | `MotionChecks` 那条"不支持的回零方式在入队时就被拒绝"用的反例成员（当前用 `PositiveLimitIndex`，即卡未声明的那个），以及用户册《仿真相位差与延时口径》的 HomeMode 对照表 |
| 任何错误文案 | 用户册《排障》的逐字对照表 + `ClassifyOutcome` 的"未使能"子串判据 |
| `Simulated*` / `Simulate*` 的默认值 | 用户册《配置项与参数》的仿真开关表（这些开关界面上没有编辑入口，默认值只能靠手册交代） |
| 快照里新增的位（限位、急停、报警、到位） | 基类 `DetectCriticalSignals` 的判据与 `MotionReadStatusPlugin` 的输出端口口径 |
| 仿真推进模型（速度、节拍、容差） | 用户册《仿真相位差与延时口径》的时间模型一节 + `MotionChecks` 里所有依赖"等一两拍"的 `WaitFor` 时长 |
| 断言本身 | 跑一次 `MotionChecks` 并确认 30 条都执行到（段名对得上），改完虚拟卡不许靠"跳过某条"变绿 |
