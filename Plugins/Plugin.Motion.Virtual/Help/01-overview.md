# 虚拟运动卡（仿真）

> 分类：运动卡 ｜ 来源：插件 Plugin.Motion.Virtual

**没有硬件时的替身运动卡**：3 根仿真轴 + 8 个数字输入 + 8 个数字输出，
把"命令排队、异步运动、急停插队、看门狗安全停机、报警门禁"这一整套行为在软件里演出来。
它不是流程里的算子 —— 它出现在「系统 → 运动卡设置」的驱动列表里，
流程中的七个运动步骤（轴使能 / 轴回零 / 轴运动 / 等待到位 / 读轴状态 / 轴卡 IO / 轴停止）按原名在它上面跑。

## 为什么需要它 / 原理

- **多数运动逻辑与板卡无关**。命令排队、打断式停止、超时判失败、状态机（未连接 → 连接中 → 在线 → 报警 / 已安全停机）、
  软限位与能力门禁都在基类与宿主这一层。没有虚拟卡，这些逻辑只能等真卡到位才能验证。
- **它刻意模拟"真实异步运动"，而不是瞬间到位**：运动命令**立即返回**，位置由轮询线程按速度**逐拍推进**，
  走完才置 `InPosition`。这样才能测出"下发 ≠ 到位"这条最容易写错的语义 ——
  如果仿真是一步到位，流程看起来全对，上真机就会出现"两条轴同时下发、实际串行"式的偏差。
- **故障注入是它存在的第二个理由**。真卡上不能随便制造"掉线""伺服报警""轮询超时"，
  而这些恰恰是最需要验证的路径（看门狗 → 安全停机、错误分级、重连后的零点处理）。
- **与真卡共用同一副骨架**：本实现只写"仿真与真卡不一样的那几处"，
  其余（队列、门禁、看门狗、状态回写）全部来自同一个基类，所以仿真验过的流程结构上可以直接搬。

## 在「系统 → 运动卡设置」里怎么配

| 项 | 必填 | 说明 |
| --- | --- | --- |
| 驱动类型 | 是 | 选「虚拟运动卡（仿真）」。列表来自宿主扫描 `Modules\` 里实现 `IMotionDevice` 且带 `[Display]` 的类型——DLL 没投递到 `Modules\` 就选不到 |
| 卡名 | 是 | **卡级操作的寻址键**。「轴卡 IO」步骤的 `Card` 端口、急停/停全部轴的的目标集合都按卡名/卡实例走；同一方案里建议起唯一名 |
| 显示名 / 备注 | 否 | 只给人看；改它不断流程（流程里引用的是轴名与卡名） |
| 地址（IP） | **不用** | 本驱动的 `ConnectCore` **完全不读地址**：留空、乱填都能连。地址只在真卡（如正运动）那侧有意义 |
| 机型 | **不用** | 同上，机型不影响仿真轴数与 IO 数（那些是固定值，见下） |
| 自动连接 | 否 | 勾选后宿主在方案加载/启动时自动连接本卡 |
| 轴映射 | 是 | 每行：逻辑轴名（**全局唯一**，流程用它寻址）、物理轴号（**0 基**，仿真可用 `0~2`）、是否启用、正/负软限位（mm） |
| 卡级参数 | 否 | 默认速度 / 默认加减速度 / 轮询间隔 / 命令超时 / 看门狗超时 / 自动重连 / 队列深度，与真卡同一套字段（生效范围见下） |

**脉冲当量（`UnitsPerMm`）在仿真里不起作用**：虚拟卡内部本来就用 mm 记账，不做脉冲换算。
所以"改当量"这类验证只能在真机做 —— 仿真验不了它，也不该用它来对当量。
同理，轴参数弹窗里的那些厂商字段（编码器类型与 PPU、驱动器额定电流、跟随误差上下限、轴备注）
在仿真侧只是存着，不参与任何行为。

## 它对外声明的能力

| 能力项 | 仿真值 | 与真卡（正运动）的差别 |
| --- | --- | --- |
| 轴数 | `3`（物理轴号 0~2） | 正运动按机型：ECI3428=4、ECI3828/ZMC408SCAN=8、VPLC532R=32 |
| 数字输入 / 输出 | `8` / `8`，点号 **0 基** | 正运动典型 24 入 / 16~20 出 |
| 硬限位 | 支持 | 但仿真是"位置越过软限位就算撞限位"，真卡是控制器上的限位输入 |
| 绝对值编码器 | 默认**按绝对式**声明 | 正运动也声明为支持绝对式，但注释与文档口径偏保守；两边都请按"上电先回零"写流程 |
| 点动 Jog | 支持 | 一致 |
| 直线 / 圆弧插补 | **不支持** | 正运动同样未上报插补能力 |
| 回零方式 | **只有 3 种**：`NegativeLimitIndex`（负限位 + Index）、`Origin`（原点开关）、`PresetZero`（零位置预设） | 正运动总线型支持全部 8 种、脉冲型 3 种。流程若在仿真里选了"原点开关"以外的方式，仿真可能直接报"不支持" |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。
> （运动卡的这些项在「系统 → 运动卡设置」里维护、随方案落盘；下面**第一组是界面上能改的**，
> **第二组是仿真专用开关，界面上没有入口**，只有自动化冒烟测试会直接设它们。）

界面上可配、且对仿真真实生效的卡级参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `DefaultVelocityMmPerS` | `50` | 默认速度（mm/s）。**运动命令速度填 0 时仿真就用它**（真卡口径不同，见下表） |
| `DefaultAccelMmPerS2` | `500` | 默认加减速度（mm/s²）。仿真**匀速推进、不做加减速**，所以这个值只是配置项，仿真里改它看不出差别 |
| `PollIntervalMs` | `10` | 轮询与位置推进的节拍（仿真内部再夹到 `1~1000` ms）。它直接决定仿真里"每拍走多远" = 速度 × 该间隔 |
| `CommandTimeoutMs` | `30000` | 单条命令的超时；回零步骤会在此基础上再加 1000 ms 等结果 |
| `WatchdogTimeoutMs` | `3000` | 看门狗：连续 3 次轮询失败或超过这个时长没有成功轮询 → 判失联并安全停机（与真卡同一套规则） |
| `AutoReconnect` | `true` | **当前只是配置项**：运动卡这一层没有自动重连逻辑。掉线后卡进「已安全停机」，需要在「运动卡设置」里**先断开再连接**才会重建 |
| `MaxQueueDepth` | `256` | 命令队列深度上限，满了报"命令队列已满" |

仿真专用参数与故障注入开关（**界面上没有编辑入口**，现场不要指望能调到）：

| 开关 / 参数 | 默认 | 用途 |
| --- | --- | --- |
| `SimulatedAxisCount` | `3` | 仿真轴数（连接时生效，改完要重连） |
| `SimulatedInputCount` / `SimulatedOutputCount` | `8` / `8` | 仿真 IO 点数（连接时生效） |
| `SimulatedAbsoluteEncoder` | `true` | 声明为绝对式（true）或增量式（false）。false 时连接后的说明会变成"增量编码器，需先回零" |
| `SimulatedHomeDurationMs` | `200` | 回零耗时（ms）：仿真不看开关、不找 Index，固定这么久之后把位置写成 0 |
| `SimulateAlarm` | `false` | 让**所有轴**都报"伺服报警"，用来验证报警门禁、硬信号打断与清报警（清报警会把这个开关一起复位，否则"清完立刻又报"） |
| `SimulatePollException` | `false` | 让轮询抛异常（`模拟：与运动卡的通信中断`），用来验证看门狗 → 安全停机 |
| `SimulateCommandFailure` | `false` | 让运动/回零类命令强制失败（`模拟：运动命令执行失败`），用来验证失败分级与"失败即清队 + 安全停机" |
| `SetInput(点号, 值)` | —— | 把某个仿真输入点置位（模拟传感器/限位信号），供自动化脚本造条件 |
| `SetSimulatedPosition(轴, mm)` / `GetSimulatedPosition(轴)` | —— | 直接把轴摆到某个位置 / 读仿真位置，造初始条件用，不走命令通道 |

## 与真机的行为差异（照着这张表判断"仿真验了什么"）

| 项目 | 仿真 | 正运动真卡 | 影响 |
| --- | --- | --- | --- |
| 速度填 0 | 用卡级默认速度（默认 50 mm/s） | **不覆盖**，沿用控制器内该轴当前 SPEED | 仿真节拍 ≠ 真机节拍；节拍敏感流程请显式给速度 |
| 加减速度 | 不参与，匀速逐拍推进 | 命令给正值才覆盖 `SetAccel/SetDecel`，否则沿用控制器 | 仿真测不出加减速导致的到位时间差 |
| S 曲线 / 平滑 | 无 | 每次定位前按曲线类型写 `SetSramp`（梯形=0、S 曲线=200 ms） | 平滑行为只能真机验 |
| 位置口径 | 仿真位置（mm），无脉冲概念 | `SetUnits` 后 `GetMpos` 即 mm；**指令位置**不是编码器实际位置 | 当量、丢步、跟随误差这些仿真验不到 |
| 速度回报 | 运动中给当前速度，静止 0 | 当前轮询**不读速度**，`Velocity` 恒为 0 | 用仿真验 `Velocity` 字段会得到"看起来能用"的假象 |
| 回零 | 固定 200 ms 后位置 = 0 | 真实寻零（撞开关、找 Index），耗时由机构决定；回零速度/偏移沿用控制器内参数 | 回零耗时、方向、开关接线只能真机验 |
| 限位 | 位置越过该轴**软限位**就置正/负限位位 | 控制器上的限位输入触发 | 仿真的限位行为实际在验"越界之后的处理链"，不是验开关接线 |
| IO 点数 | 8 入 / 8 出 | 按机型（部分机型上报的是显示上限） | 仿真里点号 8~23 能过、真机可能报超范围；反过来真机点号在仿真里会超范围 |
| 报警成因 | 开关注入 | 伺服报警 / 跟随误差超限等真实状态位 | 报警清除流程可验，报警含义本身不可验 |
| 通信失败 | 抛异常注入 | 真实网口超时/断链；SDK 原生依赖缺失另有专门报错 | 看门狗与安全停机路径可验，网络问题不可验 |
| 命令排队 | 与真卡同一套队列与门禁 | 同 | **可信**：这部分就是共用实现 |

**仿真验得到的**：流程结构（使能→回零→运动→等待→读状态→停止 的顺序与分支）、
"下发 ≠ 到位"有没有配等待、轴名/卡名解析对不对、软限位越界被拒、超时判失败、
急停清队与打断、报警/限位进安全停机、重连后的状态恢复、错误文案与分支处置。

**仿真验不到的**（必须真机联调）：脉冲当量与方向、真实节拍与加减速/S 曲线、回零路径与开关极性、
编码器实际位置与指令位置的差、IO 点号与实物接线对应关系、伺服报警含义、网口通信时序与丢包、
多轴同时运动的真实并行性、以及任何与力/惯量相关的机械行为。

## 口径与失败策略

- **单位一律 mm / mm/s**，与真卡一致；仿真不做当量换算。
- **轴号必须落在 0~2**：超出报 `轴号 5 超出仿真范围（0~2）`，把映射里的物理轴号改对即可（**0 基**）。
- **未使能不能运动**：仿真与真卡同口径 —— 运动报 `轴未使能（请先执行「轴使能」步骤）`，
  回零报 `轴未使能（回零前需先使能）`；这条失败的分级是"可恢复"，建议原文是
  `在流程里把「轴使能」步骤放在运动步骤之前`。所以流程**必须**显式放使能步骤，仿真不会替你省。
- **轴处于报警状态时不能运动**：`轴处于报警状态，无法运动`（`SimulateAlarm` 打开时全部运动/点动都会被这条挡下）。
- **失能即停**：失能把目标撤回当前位置（真卡也如此，正运动侧是先取消运动再断电）。
- **停止/急停**：普通停止把目标撤回当前值；物理轴号 -1（停全部轴）逐轴撤目标并中断回零。
  与真卡一样：命令门禁要求「在线」，急停通道允许「在线」与「报警」。
- **清报警**：仿真把所有轴的报警与注入开关一起复位；真卡清报警后**不会自动使能**，
  所以"清报警 → 轴使能 → 回零"这条恢复顺序在仿真里也能照样验出来。
- **卡状态机与安全停机是共用的**：报警/限位等硬信号会自动触发一次急停并进入「报警」；
  看门狗判失联会进入「已安全停机」，此时所有命令都会被
  `运动卡已安全停机，请重新连接后再操作` 挡下 —— 必须人工重连，仿真不给你开后门。

## 典型用法 / 接线

```
离线开发一台三轴设备（不需要任何硬件）：
① 系统 → 运动卡设置：新增卡，驱动=虚拟运动卡（仿真），卡名=运动卡1，勾自动连接
② 轴映射：X→0、Y→1、Z→2（都启用），按机构填软限位（默认 ±1000000 mm，建议改成真实行程）
③ 流程：
   轴使能(X) ──▶ 轴回零(X) ──▶ 轴运动(X) ──▶ 等待到位(X) ──▶ 轴卡 IO(写 OUT0=ON)
                                                        └──▶ 轴卡 IO(读 IN0 夹紧反馈) ──▶ 轴停止(X)

用它专门验"异常路径"（这才是仿真的价值）：
- 忘记放「轴使能」→ 应看到 `轴未使能（请先执行「轴使能」步骤）`，然后补步骤
- 「轴运动」后面不放「等待到位」→ 夹紧步骤会立刻跑，位置还没到 → 说明少了等待
- 绝对目标超出软限位 → 应看到被拒绝（参数无效）+ 软限位原因
- 超时给得过小 → 看到等待超时文案里带当前位置，据此定真机超时值

真机切换只动配置，不动流程：
  把这张卡的驱动换成「正运动 ZMotion 运动卡」+ 填 IP + 填机型 + 核对轴号与当量
  → 流程里所有轴名、步骤、连线都不用改（这正是按轴名寻址的目的）
```

## 常见问题

**Q：仿真里一切正常，上真机出现节拍慢一倍 / 轴串行？**
看两处：① 「轴运动」与「等待到位」有没有按"先都下发、再各自等待"排；
② 同一张卡上的命令是**排队执行**的，两轴真并行需要不同卡。仿真推进快（200 ms 级回零、匀速运动），
很容易把"少放了等待"这件事掩盖过去 —— 所以先按上面的排法复核流程结构。

**Q：仿真里速度填 0 跑出 50 mm/s，真机上却是别的值？**
这是两套口径：仿真 0 → 用卡级默认速度；真卡 0 → 不覆盖控制器内 SPEED（可能是厂商调试软件里设的）。
要么流程显式给速度，要么把卡级默认速度当真，不要指望两边一致。

**Q：仿真里改了脉冲当量，位置没变化？**
正常。仿真不做当量换算，`UnitsPerMm` 对它无效。当量必须在真机上验：
现象通常是"走 10 mm 实际走了 10000 个单位"这类整体倍数错，改轴映射里的当量与驱动器电子齿轮比。

**Q：仿真怎么触发报警 / 掉线来验异常分支？**
`SimulateAlarm` / `SimulatePollException` / `SimulateCommandFailure` 这三个开关**界面上没有入口**，
由自动化冒烟测试直接设置。人工要模拟异常，现场可行的两条替代路径：
① 把绝对目标写到软限位之外，让仿真"越界即撞限位"，据此观察硬信号 → 急停 → 报警态这条链；
② 把「等待到位」超时给得很小，制造超时分支。

**Q：仿真里回零只用 200 ms，是不是说明流程不用等回零？**
不是。「轴回零」步骤**会等待**（默认最多 120 秒 + 1 秒），仿真只是做得快。
真机上回零要走完寻零路径，几十秒是常态；超时值不要照抄仿真的观感去调小。

**Q：仿真能连几张、能不能和真卡混着用？**
可以同时配多张卡（虚拟与真卡混着都行），每张卡独立队列与线程。
常见实用法：**保留一张虚拟卡专跑调试流程**，产线流程跑在真卡上 ——
注意「轴停止」留空是"停所有卡的全部轴"，混用时会连仿真卡一起停（仿真卡本来就停着，无副作用，但要知道有这件事）。

**Q：仿真里 `读轴状态` 的 `Velocity` 有数，真机上全是 0？**
两边实现不同：仿真会填当前推进速度，正运动轮询目前不读速度寄存器，所以真机上恒 0。
判"动没动"一律用 `Moving`，不要用 `Velocity`。

**Q：把仿真卡的驱动换成真卡后，流程里哪些地方要跟着检查？**
① 轴映射的物理轴号（0 基）与真卡机型是否匹配；② 每轴脉冲当量与软限位改成真实行程；
③ 地址（IP）与机型填写；④ native DLL 是否齐（正运动要 `zauxdll.dll` **和** `zmotion.dll`，见该驱动帮助页）；
⑤ 仿真里"回零很快"掩盖的顺序问题；⑥ IO 点号范围变化。逐项对照本程序集帮助页「与步骤算子的配合」那一页的清单。
