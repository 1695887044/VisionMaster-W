# 深度学习分割 · 界面与操作

> 分类：图像处理 ｜ 来源：插件 Plugin.DlSegment ｜ 视图：SegmentView

本插件的配置界面是两栏：**左栏配参数**（图像输入 → 模型 → 预处理参数 → 试算），**右栏看结果**（只读预览 + 状态栏）。所有改动都是"改完立即生效"，不需要点保存；确认按钮只负责把值写回步骤配置，写回规则见 11-dev-host-contracts.md。

## 一、图像输入

| 元素 | 说明 |
|---|---|
| 端口行 `Image` | 点右侧的 🔗 可以从上游选一个图像输出接进来；也可以直接手填一个上游步骤名（宿主会转成连线） |
| 灰字提示 | 「本节点检测整幅图，不吃 ROI；要只看某个区域，请上游先用「创建ROI」裁好。」 |
| 必填性 | `Image` **不是必填端口**（允许空着建节点），但执行时会明确失败并给出文案 |

`Image` 为空时执行报的原文是：

> 上游没有图像：请把图像节点的输出连到本节点的 Image。整幅图分割需要一个输入。

**为什么不做成必填**：现场常见"先把节点摆好、后面再接图"的搭流程顺序。必填会让流程在搭建阶段就红一片，掩盖真正的错误。空着时给一条明确的运行期失败，比在画布上标红更方便排查。

## 二、异常/分割模型（.onnx）

| 元素 | 说明 |
|---|---|
| 路径框 | 直接填绝对路径，或填相对路径（相对宿主 exe 目录解析）。`UpdateSourceTrigger=PropertyChanged`，打字过程中就会去读模型元数据 |
| 「浏览」按钮 | 打开文件对话框，过滤器 `ONNX 模型|*.onnx|所有文件|*.*`，只列已存在的文件 |
| 模型信息卡 | 三态：**未选择**（灰） / **就绪**（正常底色，显示输入尺寸、输出形状、类别名） / **失败**（红底红边红字，显示失败原因） |

模型卡里"就绪"时你会看到形如：

```
输入 image  [1,3,512,512]
输出 logits [1,3,512,512]   C=3 名=background,scratch,dent
```

"失败"时最有用的一条是**把你模型的真实形状原样列出来**，例如：

```
读到的输出：output0（秩 3，形状 [1,84,8400]）
本插件只认 4 维 [1,C,H,W] 且 C ≥ 2 的语义分割输出（C=1 是单类掩膜，用「阈值」或「Blob」更合适）。
换模型或换插件，不会替你猜。
```

**看到这条不要试图改配置绕过**——形状不对就是模型类型不对，改缩放/尺寸都无济于事。

## 三、预处理参数

| 参数 | 控件 | 默认 | 范围 | 说明 |
|---|---|---|---|---|
| 缩放模式 | 下拉 | `Letterbox · 等比补边（推荐）` | Letterbox / Stretch | Letterbox 保持长宽比、四周补 114 灰；Stretch 直接拉伸 |
| 输入尺寸 | 数字框 | 0 | 0 ~ 4096 | **0 = 用模型静态尺寸**；模型是动态输入时必须填训练尺寸 |
| 插值 | 下拉 | `Nearest · 最近邻（推荐）` | Nearest / Bilinear | 只影响**结果缩回原图**这一步，不影响推理 |
| 类别口径 | 下拉 | `全部前景（所有非背景类合并）` | AllClasses / SingleClass | 决定 `RegionMask` / `Region` / `ForegroundRatio` 怎么取 |
| 类别序号 | 数字框 | 1 | 0 ~ 255 | 只在"只取指定类别"时生效；指到不存在的类会明确失败 |
| 预览窗口 | 数字框 | 1 | 0 ~ 9 | 0 = 不发布预览 |

「高级参数」折叠区里放的是输入尺寸、插值、类别序号、预览窗口——**多数场景不用动**。展开与否不影响取值。

### 三个下拉到底在选什么

- **缩放模式**：图形被压到模型输入尺寸时的做法。`Letterbox` 会把图等比缩到能放进 `W×H` 的最大尺寸，再在四周补一圈 114 的灰（模型训练时常见做法，黑边则常常是模型没见过的强边缘）。`Stretch` 直接拉伸到 `W×H`，长宽比会变——**量面积时不要用它**。
- **插值**：把"模型尺度下的类别图"放回原图尺寸时的算法。`Nearest` 不会制造新的类别值；`Bilinear` 会对类别序号取平均，产生 1.5 这种"不存在的类"。除非原图比模型输入大很多且边缘锯齿明显，否则保持 Nearest。
- **类别口径**：`全部前景` 把所有非 0 类当一块前景（做"有没有缺陷"最直观）；`只取指定类别` 只把某一类当前景（做"划痕面积"这类具体指标时必须选它）。

## 四、试算

点「试算一下」会用当前参数对**上游图**跑一次完整的推理 + 后处理，把结果摘要写进下方结果卡，并把类别图灌到右栏预览。它与正式执行共用同一个 `TrySegment` 实现——**界面上看到的和流程里跑的是同一段代码**，这是刻意设计：两套代码必然分叉，而分叉的表现是"界面看着对、跑起来不对"，最难查。

试算不动输出端口，只写预览与摘要。

## 五、右栏预览

| 元素 | 说明 |
|---|---|
| 标题「图像预览」+ 副标题「只读 · 整幅图」 | 提示这里不能编辑 |
| 「适应窗口」工具条按钮 | 把图缩到刚好铺满预览区 |
| 「1:1」工具条按钮 | 原始像素大小（大图会出滚动条） |
| 画布 | `ContentTemplate` 绑定 `DisplayImage`，用只读的 `ImageReadOnly` 控件 |
| 空态 | 没有图时显示「还没有图像」+ 引导（点 🔗 绑定上游，或点执行把这个节点的图带进来） |
| 错误态 | 模型加载失败时显示红块「模型加载失败」，下面跟着失败原因 |

预览是**只读**的：分割不做标注回写，所以没有任何框选、涂抹、双击编辑的交互。

## 六、完整配置七步

1. 上游连一张图到 `Image`（或先点执行把图带进预览）。
2. 点「浏览」选 `.onnx`。
3. 看模型信息卡：绿字就绪 → 继续；红字 → 按文案换模型。
4. 缩放模式留 `Letterbox`；输入尺寸留 0（静态模型）或填训练尺寸（动态模型）。
5. 类别口径先选 `全部前景`。
6. 点「试算一下」，看结果卡里的 `前景占比`、`主导类别`、`片数` 是否符合肉眼直觉。
7. 点「确定」把参数写回步骤配置。

## 七、改了什么怎么确认

| 你改了 | 去哪里看生效 |
|---|---|
| 模型路径 | 模型信息卡（应在 1 秒内由灰变绿或变红） |
| 缩放模式 / 输入尺寸 | 试算结果的 `FeatureWidth/FeatureHeight`（摘要里体现为热力图尺度），面积是否稳定 |
| 插值 | 类别图边缘是否出现"中间序号"（Nearest 不会） |
| 类别口径 / 类别序号 | 结果卡的 `前景占比`、`片数` 是否跟着变 |
| 预览窗口 | 执行后右栏/流程里对应窗口是否有图；改成 0 后不再出图 |

## 八、不做的事

- 不在界面上显示"这个像素是什么类"的交互式查询（要查请把 `ClassMap` 接到预处理做灰度切片）。
- 不提供类别调色板编辑：灰度即序号，配色由「结果显示」或组态负责。
- 不提供模型健康检查以外的诊断（比如按类统计召回率），那是训练侧的事。
- 不在试算时自动换阈值——分割没有阈值可调，类别由模型给。
