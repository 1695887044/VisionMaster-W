# 深度学习分割 · 判据与调参

> 分类：图像处理 ｜ 来源：插件 Plugin.DlSegment

分割没有"阈值"可调——每个像素归哪一类完全由模型决定。这一篇讲的是**怎么判断分得准不准、怎么把结果变成可用的判定**，以及现场最常见的六个配方。

## 一、先看懂结果长什么样

一轮分割给你三样东西：一张**类别图**（`ClassMap`）、一份**占比表**（`ClassRatios`）、一块**前景**（`Region`）。

判读顺序固定：

1. **看主导类**：`DominantClassName` 应该与肉眼直觉一致。不一致说明模型没训好、或图根本没送对。
2. **看占比量级**：`ClassRatios` 各项加起来必须等于 1（浮点误差 1e-6 内）。加不起来说明模型输出不是每像素一个类（比如输出是 sigmoid 而非 softmax 的多标签模型）——这类模型不适合本插件。
3. **看片数**：`RegionCount` 是前景连通片数。1 个缺陷块就是 1；背景里有零星噪声会变成几十，这时该在上游做滤波或在下游按面积筛。
4. **最后才看形状**：把 `Region` 接到形状测量，看长宽比、圆度、面积分布。

## 二、面积与像素当量

`ClassAreas[i]` 是**像素数**。要换成 mm²，两条路：

| 做法 | 适用 |
|---|---|
| `ClassAreas[i] × mmPerPixel²` | 快，适合趋势监控；像素当量必须来自标定 |
| `Region` 接「面积测量」并喂 `MmPerPixel` | 准，能同时给出凸包、外接框、质心 |

**判据**：同一工件重复 10 次，面积标准差 / 均值 应 < 2%；超过 5% 说明分割在边界上抖动（模型不稳或图对比度不够），这时不要拿面积做 OK/NG 的唯一依据。

## 三、定判定线（四段法）

分割本身不出 OK/NG，判定线要你在下游定。四段：

1. **良品基线**：≥ 30 张良品图，记录每张的目标类占比 `r_i` 与片数 `n_i`。
2. **不良下界**：≥ 10 张最轻微的不良图，同样记录。
3. **可分辨性**：良品占比上界 `R_hi = p99(r_i)`，不良占比下界 `L_lo = min(r_i)`。判据 **`L_lo / R_hi ≥ 2`**（量级差两倍以上才好定线）；若占比可能为 0，改用极差式 `(L_lo − median_良品) / (R_hi − median_良品) ≥ 2`。
4. **定线**：`Threshold = R_hi + (L_lo − R_hi) × 0.4`。误报代价大（停线）调到 0.7，漏检代价大（流出）调到 0.2。

不可分辨时**不要靠调阈值硬凑**，先查三件事：预处理是否与训练一致、视野是否把目标压在边缘、模型训练集里有没有这种缺陷。

## 四、缩放模式对判据的影响

| 模式 | 何时用 | 对面积的影响 |
|---|---|---|
| `Letterbox` | 默认；长宽比与模型输入不一致时 | 各方向等比缩放，面积比例关系保持 |
| `Stretch` | 图像长宽比与训练时完全一致 | 非等比拉伸会让面积系统性偏大或偏小 |

**判据**：把同一张图分别用两种模式跑一遍，若 `ForegroundRatio` 差异 > 3%，说明原图长宽比与模型输入差得远，**必须用 Letterbox**。

## 五、耗时构成

```
总耗时 ≈ 缩放到模型输入(毫秒级) + 推理(模型的) + 逐像素 argmax + 缩回原图 + 区域化
```

| 环节 | 量级 | 能省吗 |
|---|---|---|
| 缩放 + 建画布 | 1~5 ms | 不能省，但可用较小 `InputSize` 缩短上游 |
| 推理 | 10~200 ms（DeepLab-MobileNet ~20ms，DeepLab-ResNet50 ~100ms，SAM 类数百 ms） | 换小模型；`DisplayViewIndex=0` 不影响这一项 |
| argmax | 像素数 × C 的一次扫描，512×512×3 ≈ 0.8M 次比较，几毫秒 | 减少 C 或输入尺寸 |
| 缩回原图 | 与原图像素数成正比 | — |
| 区域化（`connection`） | 与前景片数相关，碎片多时明显 | 上游降噪 |

**判据**：连续 20 轮若 P95 耗时 > 2 × 中位数，先查是不是某几轮背景噪声生成了上千个碎片（`RegionCount` 飙高）。

## 六、六个现场配方

### 配方 A：划痕面积

| 项 | 值 |
|---|---|
| `RegionMode` | 只取指定类别，`ClassIndex` = 划痕类 |
| 判定 | `ClassAreas[划痕] × mmPerPixel² > 0.5 mm²` 判 NG |
| 注意 | 划痕常断续，`RegionCount` 会 > 1；要"总长度"就接骨架分析节点 |

### 配方 B：缺料 / 缺件（有无判断）

| 项 | 值 |
|---|---|
| `RegionMode` | 全部前景 |
| 判定 | `ForegroundRatio < 0.02` 判"没有件" |
| 注意 | 先确认相机视野固定；视野一改，占比基线全废 |

### 配方 C：多品种混线

| 项 | 值 |
|---|---|
| 模型 | 一个模型出 N 类：背景 + N-1 种品种 |
| 判定 | `DominantClassName` 与工单期望品种比对 |
| 注意 | 品种相似度高时容易互串，必须在 04 的"可分辨性"上验收过 |

### 配方 D：异色 / 脏污

| 项 | 值 |
|---|---|
| `RegionMode` | 只取指定类别 |
| 判定 | `ClassAreas[脏污] > 2000 px` 判 NG（先用良品定噪声地板） |
| 注意 | 反光造成的假脏污很常见，光源不稳就要先稳定光源 |

### 配方 E：背景剔除（只留产品）

| 项 | 值 |
|---|---|
| `RegionMode` | 全部前景 |
| 用法 | 把 `Region` 接到后续测量节点，做"只在产品上测量" |
| 注意 | 本插件不吃 ROI 端口，但可以用分割结果反哺 ROI——上游裁图是另一条路 |

### 配方 F：批次趋势

| 项 | 值 |
|---|---|
| 输出 | `ClassRatios` → 全局变量（数组）→ SCADA 趋势 |
| 注意 | 数组上屏需要「结果显示」的数组分支（A3 已支持）；变量写入只支持标量时，改用 `Summary` 或逐类拆成标量变量 |

## 七、什么时候不该用分割

| 场景 | 更合适的做法 |
|---|---|
| 只要一个"这张图是什么" | 「深度学习分类」（更快、更省） |
| 只要"有没有异常"且只有良品样本 | 「深度学习异常检测」 |
| 目标边界规整、对比度高 | 阈值 + Blob，毫秒级且无需训练 |
| 要数"有几个独立目标" | 「YOLO」检测 |
| 要"每个目标的独立掩膜" | 实例分割（YOLOv8-seg），本插件不做 |
| 缺陷形态千变万化、无标注 | 异常检测，不是分割 |

## 八、与相邻节点的分工

| 节点 | 边界 |
|---|---|
| 深度学习分类 | 整图给一个标签；不输出像素级结果 |
| 深度学习异常检测 | 输出分数与热力图；不输出类别 |
| 深度学习分割（本插件） | 输出像素级类别图与区域；不给分数 |
| YOLO | 给框与类别；不保证像素级边界 |
| 结果显示 | 把类别图/区域画到图上；本插件只出数据 |

## 九、判定线写在哪

**不要写在本插件里**。判定线属于工艺参数，会随批次/材料/客户要求变，写进方案就会导致"改了个阈值要重新发方案"。

推荐做法：把 `ForegroundRatio` / `ClassRatios[i]` / `RegionCount` 接到「逻辑判断」节点的比较端口，阈值写在判断节点上——那里改阈值不碰模型配置，也便于审计留痕。
