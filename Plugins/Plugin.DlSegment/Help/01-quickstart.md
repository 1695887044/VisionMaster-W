# 深度学习分割 · 快速上手

> 分类：图像处理 ｜ 来源：插件 Plugin.DlSegment

深度学习分割把图像里的**每一个像素**判成某一类，输出一张"类别图"和"每类有多大"。分类只回答"这张图是什么"，分割回答"这块像素是什么"——要量面积、要抠缺陷轮廓、要区分背景与前景，都是分割的活。

## 一轮分割产出什么

```
Input  Image : HImage ──┐
                        ├─→ ClassMap        : HImage   类别图（byte，像素值 = 类别序号）
                        ├─→ RegionMask      : HImage   前景掩膜（前景 255，背景 0）
                        ├─→ Region          : HObject  前景区域（可接面积/形状测量）
                        ├─→ RegionCount     : int      前景连通片数
                        ├─→ ForegroundRatio : double   前景像素占比 0~1
                        ├─→ ClassAreas      : double[] 各类像素数，下标 = 类别序号
                        ├─→ ClassRatios     : double[] 各类占比 0~1
                        ├─→ DominantClassIndex / DominantClassName   面积最大的类
                        ├─→ Summary         : string   人读摘要
                        └─→ Success / ErrorMessage     （基类提供）
```

**类别序号 0 一律当背景**：`RegionMask` / `Region` / `ForegroundRatio` 都按"非 0 即前景"取。类别名默认 `class_0`、`class_1`……，模型元数据里带 `names` 时会用它（逗号或分号分隔，个数要与 C 一致，否则回落 `class_N`）。

## 为什么单独一个插件而不是扩展分类

分类与分割的**输入预处理一样、输出契约完全不同**：

- 分类输出 `[1,C]`，C 个概率，取 TopK 就完事；
- 分割输出 `[1,C,H,W]`，每个像素一组通道，要逐像素 argmax，还要把结果**还原回原图尺寸**，再从类别图抠区域、算面积。

把两条路塞进一个插件，会让"这个插件到底在干什么"变成一个要靠配置才能回答的问题。所以拆开，各管一摊。

## 三步跑通

1. **接图**：把上游（采图 / 读图 / 裁好的 ROI 图）连到本节点的 `Image` 端口。
2. **选模型**：点「浏览」，选一个 `.onnx` 语义分割模型。模型卡立刻显示三件事：输入尺寸、输出形状、类别名。**形状不认识就当场拒绝**，并在卡里把你模型的真实形状原样列出来（见下节）。
3. **执行**：点「执行」（或点「试算一下」先看效果）。右栏出现类别图，`Summary` 里是各类面积。

## 输出契约：只认一种形状，不认识的直接拒绝

本插件只接受**语义分割**的 ONNX 输出：

| 形状 | 判定 |
|---|---|
| 秩 4、`[1, C, H, W]`、`C ≥ 2`、`H/W` 在 1~8192 | **接受**，这就是语义分割 logits / 概率 |
| 其它任何形状 | **拒绝**，错误里带「读到的输出：{名字}（秩 n，形状 [...]）」+ 本插件的接受条件 |

为什么这么严：一张 `[1,84,8400]` 的 YOLOv8 检测输出如果被硬当成分割图去 argmax，会得到一张**看起来有模有样但完全没意义**的图，而且不报错。宁可在加载期明确失败，也不要在运行期产生假结果。**插件不会替你猜。**

C 的取值表（常见）：

| C | 含义 |
|---|---|
| 2 | 背景 + 前景（最常见的二类分割） |
| 3 | 背景 + 2 类缺陷，或 RGB 三段式 |
| 5~20 | 多类缺陷 / 多工位 / 零件多品种 |

## 类别图长什么样

`ClassMap` 是 **byte 单通道**，像素值就是类别序号，已经缩回原图尺寸。注意：

- 它是**序号图**，不是伪彩色图。直接看会是一片很暗的灰（0/1/2），要看清结构得接「结果显示」或预处理做一次灰度拉伸；
- 序号上限 255（byte 装得下 256 类）；C > 255 的模型在推理前就会被拒绝，不会给你一张被截断的图；
- 缩回原图用的是 `Nearest`（最近邻）插值，**不插值类别值**——双线性会把 1 和 2 混成 1.5，那是没有意义的类。

## 五步配第一个分割

1. 模型文件放本地（不要放网络盘，加载慢且断网就崩）。
2. 点「浏览」选它，确认模型卡是绿字（就绪）而不是红字（失败）。
3. 输入尺寸留 0（= 用模型自带静态尺寸）；模型是动态输入时这里必须填，填模型训练时用的那个（常见 512 / 640）。
4. 缩放模式先用 `Letterbox`（等比补边）。`Stretch` 会把图拉变形，量面积会系统性偏大或偏小。
5. `RegionMode` 先用 `全部前景`，看 `ForegroundRatio` 与 `Summary` 是否符合肉眼直觉，再决定要不要改成 `只取指定类别`。

## 接线图

```
[采图] ──Image──> [深度学习分割] ──Region──────> [面积测量 / 形状测量]
                       ├──ClassMap──> [结果显示]（看类别结构）
                       ├──Summary ──> [数据记录 / 结果上传]
                       └──RegionCount / ForegroundRatio ──> [逻辑判断]
```

## 上屏图怎么看

- 右栏预览显示的是 `ClassMap` 放大后的样子，**灰度层次即类别**：最暗 = 背景类，越亮序号越大。
- 预览是只读的，不能在这里框选或涂抹；要只看某个区域，请上游先用「创建ROI」裁图再进来。
- `DisplayViewIndex = 0` 表示不发布预览，只算输出（批量跑、追求速度时用）。

## 不做什么

| 不做 | 为什么 / 该用什么 |
|---|---|
| 不做 OK/NG 判定 | 判定归下游「逻辑判断」；本插件只给面积/占比/片数 |
| 不支持实例分割（YOLOv8-seg） | 那套输出是 `[1,4+C+32,N]` + 原型掩膜，解码路径完全不同，需要另一个插件 |
| 不做多模型级联 | 一个节点一个模型；要级联就串两个节点 |
| 不自动裁剪或对齐 | 分割只认"喂进来的图"，要不要对齐是上游的事 |
| 不在图上画框 | 本插件只输出类别图；要画标注请接「结果显示」 |

## 常见误用

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 模型卡红字「读到的输出：...（秩 n，形状 [...])」 | 模型不是语义分割（分类/检测/异常） | 换模型，或换对应插件（DlClassify / Yolo / DlAnomaly） |
| 选了模型但执行报「尚未选择模型」 | `.vms` 里存的是相对路径，换了机器就找不到 | 重新浏览选一次，或把模型放在同一个相对位置 |
| 面积数出来明显偏小 | 用了 `Stretch` 且原图长宽比与模型输入差很多 | 改回 `Letterbox` |
| 图上几乎全是一个类 | 模型没训好 / 归一化不对 / 图太暗 | 先在训练侧确认模型本身可用 |
| 界面正常、跑起来报 `onnxruntime.dll` 找不到 | 原生库没投递到宿主目录 | 见 05-troubleshooting.md「原生库」一节 |
