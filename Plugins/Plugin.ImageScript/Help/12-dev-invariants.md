# 图像脚本 · 开发章节：不变量与守门现状

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageScript ｜ 读者：开发

**守门现状先说清**：`FlowCanvasChecks\` 目录里**没有 ImageScript 专属的断言文件**（`ImageScriptChecks.cs` 不存在）。
所以下面每条不变量的"守门断言名"要么指向别的检查项，要么只能写"无断言，靠人工核对"。
不许把它当成"已经有人管了"。

## A 组：违反就当场报错（症状是响的）

1. **症状** 运行直接失败，原因写 `未选择要运行的脚本过程`。
   **机理** `SelectedProcedure` 为空或指向不存在的过程名；`RunProcedureNameList` 里 `main` 被排除，所以"跑 main"这个想法本身不成立。
   **守门断言名** 无断言，靠人工核对（跑一次不带选择过程的节点，看是否只报失败不抛异常）。

2. **症状** `未找到过程 [X]`。
   **机理** `Procedures` XML 里没有这个名字；用户改过过程名或从别的工程粘了过程清单。
   **守门断言名** 无断言，靠人工核对。

3. **症状** `脚本有问题: …` 或 `脚本编译异常: …`，脚本一行不跑。
   **机理** `PrecheckBody` 的三条自查命中：中文全角标点、单引号没闭合、括号不配对。
   这三条是给 HDevelop 的"算子必须写在一行"这一硬规则兜底的——引擎报的行号是"第几个非空行"，不是编辑器行号。
   **守门断言名** 无断言，靠人工核对（故意写一句 `read_image (Image，'x')` 看提示是否落在正确编辑器行）。

4. **症状** `输入变量[Image]未链接或图像为空` 并返回。
   **机理** 图形输入没有值；这是设计上的短路，避免把空对象塞进 `SetInputIconicParamObject` 后得到 #1305 之类的底层错。
   **守门断言名** 无断言，靠人工核对。

5. **症状** `输出[X]类型不符：脚本实际产出的是…` 并失败。
   **机理** 声明类型和 `GetObjClass()` 的真实类别不一致。提示里给出该改成什么，是因为让用户猜 HALCON 类名猜不出。
   **守门断言名** 无断言，靠人工核对。

6. **症状** `效果图绘制失败（dev_display）：…`（`DisplayOpException`）。
   **机理** 画图环节本身出错（颜色名不认、行列坐标非法），与脚本算子错误分开报，
   这样"结果是对的只是画不出来"和"结果根本没算出来"在提示上能分开。
   **守门断言名** 无断言，靠人工核对；`ResultDisplayCheck` 的画布与窗口静态扫描会盯"插件里不许自己开窗口"这一条。

7. **症状** 老式 `disp_rectangle1 (…)` 报"改成两行：gen_rectangle1 … 然后 dev_display"。
   **机理** `LegacyDisplayShim` 对无法垫片的老算子直接报错引导，而不是让它静默画到看不见的地方。
   **守门断言名** 无断言，靠人工核对。

## B 组：违反不报错，只是结果静默变坏（症状是哑的）

8. **症状** 改完变量表没点「同步接口变量」，运行时报引擎侧的"未知变量"。
   **机理** 过程接口四类参数与变量表脱钩；引擎按接口取参，接口里没有就是没有。
   **守门断言名** 无断言，靠人工核对（表里加一行、不同步、跑一次）。

9. **症状** 画布上什么都没有，但流程成功。
   **机理** 脚本里写了原生窗口算子（`open_window`、`set_color`、`disp_*`）。它们**能编译通过**，
   因为 HALCON 不认识 `dev_*` 之外的窗口调用是合法的；画到的是引擎自己的窗口，宿主回读不到。
   这正是显示后端必须注册、老算子必须改写或报错的原因。
   **守门断言名** 无断言，靠人工核对；静态口径见 AGENTS.md R36（全仓只有 `AnnotationBaker` 允许 `OpenWindow`，
   `HDevDisplayBackend` 是永久豁免）。

10. **症状** 第一次运行明显比后续慢。
    **机理** JIT 预编译属性只对已走过的过程生效；`PreWarmEngine` 只预热引擎本身，不预热每个新写的脚本。
    **守门断言名** 无断言，靠人工核对。

11. **症状** 反复改脚本后内存涨一截。
    **机理** `CallCache` 是指纹到已编译程序的映射，只在条目数超过 64 时整体清空，不做逐条淘汰。
    **守门断言名** 无断言，靠人工核对。

12. **症状** 输出端口在流程面板上消失了。
    **机理** `RebuildDynamicOutputs` 里 `if (StepData != null)` 是保护，但 `ApplyConfigValues` 的顺序若被改成"先连线后建端口"，
    按名恢复的连线就接不上。顺序是硬约束，别在 `override` 里调换。
    **守门断言名** 无断言，靠人工核对。

13. **症状** 随图信息里少了某个数值输出。
    **机理** `BuildInfoRows` 读端口值时**吞掉异常**（读不到就跳过这一条），标签优先用「备注」。
    数值输出是在所有输出取完之后才汇进随图信息的（`pending` 表），不要改成边取边发。
    **守门断言名** 无断言，靠人工核对。

14. **症状** 区域输出显示成一张全黑图。
    **机理** `ComposeIconicToImage` 任一环节抛异常时返回 `null`（宁可不显示也不失败）；
    或 `GenBlankCanvas` 的尺寸被夹到 64~4096 之外。
    **守门断言名** 无断言，靠人工核对。

15. **症状** 同一次运行里两个同名变量只有一个生效。
    **机理** `MergeVars` 用字典索引器赋值，**故意容忍重名**（后写的覆盖先写的），
    因为 `ToDictionary` 遇到重名会抛 `ArgumentException` 把整个节点崩掉。别"顺手优化"成 `ToDictionary`。
    **守门断言名** 无断言，靠人工核对。

## 并行安全声明

本插件不带 `[ParallelSafe]`（基类与调度器按 FullName 字符串匹配该特性），
因为显示后端用**进程级静态窗口态**（`Begin` / `HasDrawing` / `Capture` / `Release`）。
若哪天要真并行，先把显示后端改成实例态或加运行级串行锁，光删注释不算。
