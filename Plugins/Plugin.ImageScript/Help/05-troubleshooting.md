# 图像脚本 · 排错

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageScript

这一页按**现象/报错原文**查病根。插件把 HDevelop 引擎的天书报错翻译成了带行号的中文，
所以第一步永远是：**把状态栏红字（或步骤上的错误信息）完整读一遍**，再对照下面的表。

## 报错原文速查

| 报错原文（节选） | 病根 | 怎么处理 |
| --- | --- | --- |
| `未选择要运行的脚本过程` | 「运行过程」下拉为空（新建步骤还没选，或过程被删掉了） | 在步骤界面顶部选一个过程；一个过程都没有就点「新建过程」 |
| `未找到过程 [xxx]` | 下拉记住的过程名在过程表里已经不存在（改名/删除后残留） | 重新选一次过程；导入外部 `.hdev` 后尤其容易撞上 |
| `输入变量[Image]未链接或图像为空` | 图形类（iconic）输入**没有连线**，或上游这一步压根没产出图像 | 到流程里把上游图像连到该输入；图形类变量不能靠手填初值，必须连线 |
| `输出[Region]类型不符：脚本实际产出的是区域(HRegion)，但输出变量表里声明为 HImage —— 请把该变量的“类型”下拉改成区域(HRegion)` | 输出变量表里声明的类型和脚本真正算出来的对象类型不一致（HALCON 原文只有一句 `Output object type mismatch`，插件已翻译成这句话） | 照句子改「类型」下拉即可：区域(HRegion) / 轮廓(HXld) / 图像(HImage) / 通用对象(HObject) |
| `输出参数[Result]在脚本中未被赋值（接口声明了它，但脚本没有写入）` | 输出表里加了变量，脚本正文没写它（名字大小写不一致也算没写） | 在脚本里补 `Result := ...`，或把该输出行删掉 |
| `脚本编译失败: invalid program line: N`（后面跟着【第 N 行】和原因清单） | 引擎只报行号不报原因，插件把 N 换算成编辑器真实行号并列了四类嫌疑 | 见下一节 |
| `脚本编译失败: unresolved procedure call: N` | 第 N 行调用了引擎里不存在的算子/过程 | 见「算子/过程找不到」 |
| `脚本有问题: 【第 3 行】含有中文全角标点“，”——请改成英文半角符号（输入法切到 English 重新输入）` | 从聊天窗口/文档粘贴代码带进来的全角标点、智能引号、不间断空格 | 插件已在编译前精确指出行与字符，按提示替换该行标点 |
| `【第 3 行】单引号 ' 没有闭合——Halcon 算子必须写在一行内，请检查` | 引号漏配，或把算子拆成了两行 | 补引号；把该算子合并回一行 |
| `【第 3 行】括号不配对——若算子被拆成了多行，请合并为一行（引擎不支持续行写法）` | 括号不成对 / 续行 | 同上 |
| `效果图绘制失败（dev_disp_text）：<HALCON 原文>` + `提示：检查颜色名是否为 Halcon 认得的写法（如 'red'/'green'/'cyan'），以及行/列坐标是否为有效数值` | 画图环节（离屏窗口、显示算子）出错，与算法错误分开报 | 检查颜色名拼写、坐标是否被赋成了字符串或空元组 |
| `Halcon 脚本异常: <消息>` | 脚本正文里某个算子在运行期抛了 HALCON 异常（阈值取空、对象集为空、参数越界等） | 看消息里的算子名与错误码，对照下面「HALCON 常见错误码」 |
| `脚本执行异常: <消息>` / `脚本编译异常: <消息>` | 非 HALCON 的意外异常（如内存不足、对象已被释放） | 先重试；持续复现就贴出消息找宿主侧排查 |

## 编译类错误：先看插件标出的行

引擎报的 `invalid program line: N` 里的 **N 是"第 N 个非空行"**（数行时跳过空行），
不是编辑器行号。插件已经做了两件事帮你定位：

- **编译前静态体检**：全角标点、引号不闭合、括号不配对这几类问题在编译前就用**编辑器真实行号**报出来，
  并附上该行原文；
- **报错翻译**：引擎的报错按非空行反查回真实行号，输出 `【第 N 行】<该行代码>` + 原因清单。

翻译给出的四类原因，按现场出现频率排：

1. **该行用到的变量没在上方「输入/输出变量」表中声明**（最常见）——脚本里用到的图像/数值变量
   都要加进表，并连线或给初值；纯数值也可以先 `X := 0` 自己赋值再用。
2. **行尾拖了注释**——HDevelop 要求注释独占一行并以 `*` 开头。
   插件会尽力自动剥离行尾注释，但只在能确定是注释时才剥（含 `:=` 的赋值行里 `*` 一律当乘号），
   残余写法仍会报错。
3. **括号或引号不成对，或算子被拆成了多行**（每个算子必须写在一行内）。
4. **混入中文全角标点**。

### 「校验脚本」与「运行」的区别

- 工具栏**校验脚本**（右键菜单里叫「编译（校验脚本）」）：强制重编译全部过程，**不执行**。
  结果写在编辑器底部：通过显示 `✔ 脚本校验通过（编译无误）`，失败显示 `✘ <带行号的错误>` 并把错误行标红。
- **运行过程**才会真正灌输入、跑脚本、收输出。校验通过 ≠ 结果正确，只保证编译得过。

### 改了脚本却像没生效

编译结果按**脚本内容指纹（SHA256）**缓存，内容变了自动重编；缓存超过 64 条整体清空。
所以"改了没生效"一般是这两类：

- 改的是**编辑器屏幕上的文本但没固化**——校验和运行前插件会把编辑器文本写回过程体，
  若过程下拉/编辑下拉指向的不是同一个过程，你改的就不是要跑的那个；
- 改的是**变量表**：变量表是接口的唯一真源，每次编译前会反向同步进过程接口，
  但要确认改的是当前选中过程的表。

## 输入输出与连线

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 一运行就失败，脚本一行都没执行 | 图形类输入 `Image` 未连线或上游图像为空（`输入变量[Image]未链接或图像为空`） | 先把上游接上；无上游就换一个有图的步骤连线 |
| 数值输入取到 0 / 空串 | 控制类输入（Int/Double/String/HTuple）可以手填初值，初值列空着时按类型退化 | 在变量行的初值里填上，或连线 |
| 下游拿不到输出 | 输出行没加、名字与脚本里的写法不一致、或声明类型不对 | 看上面两条报错原文；名字大小写敏感 |
| 输出 `Result` 类型莫名变成 Double | 新增变量时按名字猜类型（`i` 开头→Int，`s` 开头→String，其余→Double）。所以字符串结果 `Result` **必须手工把类型改成 String** | 改「类型」下拉，别指望猜 |
| 加完变量连线断了 | 变量表驱动的端口名就是变量名，改名等于新建端口，原连线锚不到 | 改回原名，或重新连线 |
| 手动「添加变量」后编译报 `invalid program line` | 变量表没同步进接口 | 正常路径每次编译都会同步；若仍报错，点「同步接口变量」再校验 |

## 效果图 / 显示类问题（不报错但没图）

这类最难查，因为**显示失败不会让步骤失败**，算法结果照样是好的。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 视图里完全没有效果图，但数值输出正常 | 脚本用了 `disp_image` / `open_window` / `set_color` / `disp_text` 等**原生显示算子**：注册显示后端后它们**不报编译错**，只是画在另一张窗口上，于是画布静默空白 | 改用 `dev_display` / `dev_disp_text` / `dev_set_color` 等 `dev_*` 系列。常见老写法插件会自动改写回 `dev_*`（一行改一行），但 `disp_rectangle1`、`disp_circle`、`disp_line`、`disp_arrow`、`disp_cross`、`disp_polygon`、`write_string`、`get_window_extents`、`set_window_extents` 不自动改写，需要自己换成 `gen_*_contour_xld` + `dev_display` |
| 区域/轮廓看不到 | 输出行没选「窗口 N」 | 在输出变量行把「显示窗口」设为窗口 1~9；区域/轮廓会叠加在第一路图像输入上 |
| 效果图与原图错位 | 显示尺寸以底图为准（尺寸一旦锁定，脚本自报的宽高会被忽略，保证 1:1 对齐）；底图缺失时才用脚本给的宽高 | 保证有图像输入并连线 |
| 文字太大/太小，而且串到了后面别的脚本节点 | 字体状态由宿主每轮自动复位（`Begin()` 还原字体），但历史上脚本半路抛异常会漏还原 | 升级到当前实现即可；仍异常就重启（每个脚本节点各自复位一次） |
| `dev_disp_text` 编译不过 | 参数不足，**必须 7 参完整形式** | 补成 `dev_disp_text (Text, 'window', Row, Column, 'black', [], [])` |
| 想设字号用了 `['font']` / `['size']`，算子直接失败 | 这两个 GenParam 在实测中就是让算子失败；`['shadow']` 无效；`Size := -1` 也不是还原默认 | 字号只走 `dev_disp_text` 的第三/第四个参数与 `set_display_font`；`dev_set_window` 之后再设 |
| 只想把中间图送到某个视图 | `publish_preview (Image, 2)`（进视图 2，不进效果图画布、不参与叠加） | 只能送**图像**，区域/轮廓会被静默丢弃 |
| 写了 `publish_preview` 报 `unresolved procedure call` | 该算子是自定义过程，靠部署目录 `ScriptAssets\procedures\publish_preview.hdvp` 提供；漏拷就没兜底 | 确认程序目录下 `ScriptAssets\procedures\publish_preview.hdvp` 存在（见下一节） |

## 算子 / 过程找不到

`脚本编译失败: unresolved procedure call: N` 的行文里会附带一句提示。注意那句提示沿用了早期措辞
（" `dev_display`、`dev_set_window` 等 `dev_*` 系列是 HDevelop 开发环境专用，粘贴脚本时请删掉这些行"）——
当前版本这一条已经过时：宿主注册了显示后端，所以 `dev_*` 是可用的。真遇到这条报错时更可能是：

- 算子名拼错（多一个下划线、少一个字母），或用了本仓库 HALCON 23.05 没有的新算子；
- 自定义过程缺失：`ScriptAssets\procedures\` 下没有对应 `.hdvp`；
- 从外部 HDevelop 工程粘贴了引用**私有过程**的代码行，而那个 `.hdvp` 没跟着部署。

排查顺序：先看被标出的那一行原文 → 用编辑器输入 `op` 后的候选列表核对算子名（不确定就查文档同名算子）→
确认 `ScriptAssets` 目录已随插件部署（`images` 32 张图、`ocr\Industrial_0-9A-Z_Rej.omc`、`procedures\publish_preview.hdvp`）。

## 资源短名与模板里的 `{A}`

- `read_image (Img, 'marks')`、`read_ocr_class_mlp ('Industrial_0-9A-Z_Rej', ...)` 里的**短名**
  在编译前会被解析成程序目录下 `ScriptAssets` 里的全路径；已是路径（含 `/`、`\`、`:`）或找不到文件的**原样保留**，
  装了 Halcon 时官方图像名（如 `'fabrik'`）仍由 Halcon 自己的搜索路径兜底。
  所以"图片读不到"先确认 `ScriptAssets\images\` 里有没有同名文件，而不是改脚本。
- 模板里的 `{A}` 在插入时会替换成 `ScriptAssets` 的绝对路径（正斜杠），并顺手创建
  `models`（模型存盘）和 `ng_records`（NG 留档）两个子目录。
  **如果直接手打 `{A}` 而不通过右键「插入示例代码」，占位符不会被替换**，路径就是字面的 `{A}`。

## HALCON 常见错误码

运行期异常都以 `Halcon 脚本异常: <消息>` 形式出现，下表是本项目实测过的几个。

| 错误码/消息 | 触发 | 正确做法 |
| --- | --- | --- |
| `#1305` | `open_window` 的 mode 只接受 `'buffer'`，写 `'invisible'`/`'visible'`/`'pixmap'` 一律报 | 用 `dev_open_window`（宿主自己开离屏 buffer 窗口） |
| `#9302`（表现为卡死） | 反复 `open_window` / `close_window` | 不要自己开关窗口；`dev_close_window` 只清屏，句柄常驻复用 |
| `#2453` handle is NULL、`#2455` | 把窗口句柄本体交给引擎 / 用 `HTuple.Clone()`、`Append()` 动了句柄容器 | 脚本里不要自管句柄，交给 `dev_get_window` / `dev_set_window` |
| `#3101` Unknown feature | `select_shape (..., 'elongation', ...)`——本仓库 HALCON 23.05 不认识 `'elongation'` | 改用 `smallest_rectangle1` 取宽高自算长宽比 |
| `Index out of range` / `IndexOutOfRange` | 对**空对象集**取元素或取类型（`count_obj` 为 0 时仍 `select_obj`） | 取之前先 `count_obj (Obj, Count)` 判 `Count > 0` |
| `Output object type mismatch (excepted image, got region)` | 输出类型选错 | 插件已翻译成"改哪个下拉"的中文，照做即可 |

## 导入 / 导出 / 恢复默认

| 现象 | 说明 | 处理 |
| --- | --- | --- |
| `导入失败：文件为空或不是有效的 .hdev。` | 解析不出过程 | 确认是 HDevelop 工程文件；外部工程若用了私有过程，需一并部署 `.hdvp` |
| `导入出错：<消息>` | 读取异常 | 看消息；仍不行就在 HDevelop 里另存一份纯净 .hdev |
| `导出出错：<消息>` / `当前没有可导出的脚本过程。` | 没有过程，或写文件失败 | 先建过程；检查目标目录权限 |
| 导入后「运行过程」下拉指向不对 | 导入时会优先把编辑视图指到 `main`（若存在） | 手工在「运行过程」里选你要跑的那个；本插件自带默认过程名是 `script` |
| 想看回出厂演示脚本 | 工具栏「恢复默认脚本」**不可撤销**（整表替换） | 方案还没保存时关闭配置窗口即可放弃；已保存就先导出备份再恢复 |

## 常见问题

**Q：状态栏只写"脚本编译失败: invalid program line: 1"，我的第一行是注释啊？**
A：引擎数的是**非空行**，第 1 个非空行才是它说的行；插件会换算成真实行号并把该行原文贴给你。
如果你的报错里没有【第 N 行】，说明是过程级/接口级错误，重点检查变量表和过程名是否一致。

**Q：`threshold` 明明写对了，为什么还说变量没声明？**
A：`threshold` 的输入图像名（如 `GrayImage`）必须是**接口里的变量**或脚本中先前 `:=`/算子产出过的中间量。
只有出现在脚本正文、但既不是输入输出表成员又不是任何算子输出的名字，引擎会当"未定义"。
注意中间量不需要进表，但**进出流程的必须进表**。

**Q：为什么步骤失败但我上游看到的图还是好的？**
A：显示环节与算法环节是两条路：`效果图绘制失败（…）` 只说明画图崩了。
反过来说，画图失败会让步骤失败（错误信息就是那句带颜色提示的话），
但"没有效果图"本身不会失败——所以视图空、步骤绿，就往显示算子上查。

**Q：同一份脚本在 HDevelop 里能跑，在这里报 `unresolved procedure call`？**
A：这里是 **HDevEngine 运行引擎**，可用算子集与完整 HDevelop 有差别；另外它没有你 HDevelop 工程的搜索路径，
自定义过程只从 `ScriptAssets\procedures` 和临时目录找。把依赖的 `.hdvp` 放进前者。

**Q：输出区域能显示，为什么叠加的底图是黑的？**
A：区域/轮廓是叠在**第一路已连线的图像输入**上合成的；没有图像输入时退化为在黑色画布上填充绘制
（画布尺寸按 64~4096 夹紧）。想让区域叠在原图上，就把原图作为图形输入连进来。

**Q：`Result := 'OK'` 之后下游拿到的是 0 或空？**
A：输出变量的「类型」列决定怎么读元组。字符串结果类型要是 String；被猜成 Double 时会读不出内容，
进而报 `输出参数[Result]在脚本中未被赋值…`。把类型显式改成 String。

**Q：改了脚本内容，运行结果一点没变？**
A：确认你编辑的过程和「运行过程」下拉选中的是**同一个过程**。多过程工程里，运行只跑下拉里那一个，
其余过程只是被调用。编译缓存按内容指纹走，内容真变了不会命中旧缓存。

**Q：怎么让现场同事一眼看懂这个脚本步骤在做什么？**
A：输出变量行的「备注」会作为推送图像的标题显示在视图上；正文里用 `*` 注释解释阈值来历；
阈值这类参数目前写死在脚本里（默认脚本没把它们做成输入端口），要改就改正文。
