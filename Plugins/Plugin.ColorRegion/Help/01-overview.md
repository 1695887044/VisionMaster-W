# 区域颜色检查

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorRegion

## 它回答什么问题

**这一块区域是什么颜色、是不是我要的那个颜色、纯不纯。**

在采样区（矩形 / 圆 / 椭圆）里**逐点分类成颜色词再投票**，取票数最多的**主色**和它的**占比**，
再与期望颜色比对。产出主色 `Color`、占比 `Share`、区域中位色 `Rgb`、各色占比明细 `Table`、
判定 `Result`、结论全文 `Verdict`，并把「采样区轮廓 + 主色标签 + 结论行」投到主界面的视图窗口。

典型场景：**指示灯什么颜色、色标对不对、这块区域颜色纯不纯、某颜色占比够不够**。

## 一句话原理：投票，不是取中位色

```
采样区 ROI（矩形 / 圆 / 椭圆）
   ↓ ① 展开成区域内的逐像素点集（点太多按固定步长均匀抽稀）
   ↓ ② 一次取回整批点的 R/G/B
   ↓ ②.5 高位深图自动等比压回 8 位（判据按 8 位标定）
   ↓ ③ 每个点归成一个"颜色词"，累计票数
{ 灰: 63, 蓝: 22, 白: 10, 绿: 5 }
   ↓ ④ 票数降序 → 主色 = 灰，占比 = 63%
   ↓ ⑤ 判定：主色在期望词表里？且 占比 ≥ 最小占比？
合格 / 不合格（并给出结论全文）
```

为什么非要投票：区域里若一半红一半蓝，中位色可能是个"谁都不像"的颜色，却还是会被报出一个词——
现场看不出它其实没把握。逐点投票会直接告诉你"主色红只占 41%"，这是"**不纯**"，不是"红"。

采样用 HALCON 区域当掩膜，所以**用方框框圆形指示灯时四个角的背景不会被采到**；
反过来说，形状选得对不对直接决定投票质量——圆形指示灯请用「新建圆形」。
判色的完整口径（颜色空间、11 个颜色词、13 项阈值各管什么）在《颜色区域与判色阈值口径》那一页。

## 快速上手：第一次用的 4 步

1. **接图**：左栏「图像输入」点 🔗 绑上游图像，或在画布上从上游算子拖一条线到本节点的 `Image`。
2. **出图**：点「执行」——上游图会自动显示在配置界面右侧画布。
   第一次会报"尚未框选采样区"，**这是对的**，说明图进来了、只差框。
3. **框采样区**：在图上**右键 → 新建矩形 / 新建圆形 / 新建椭圆**，框住要检的那块（圆形指示灯用圆形）。
4. **示教**：点「试算一下」看主色、占比、明细与中位色，再点「把主色填成期望颜色」一键把期望填上。

> **试算不要求先填期望颜色**：现场顺序是"先试算出主色 → 再一键填成期望"，
> 若试算就强制填期望，那个入口永远用不上（顺序死锁）。**判定在运行期做，而且必须做**。
> 「把主色填成期望颜色」这个按钮存在的理由：手打颜色词必须**正好**落在词表里，写成"深红"永远匹配不上。

跑通之后应该看到：视图窗口里采样区轮廓（合格绿、不合格红）+ 主色标签 + 结论行；
输出端口 `Color` / `Share` / `Result` 有值；日志里有"区域颜色检查：主色 …（占 …%）"三行。

## 接哪儿去

```
图像采集.OutputImage ─────▶ 区域颜色检查.Image
（可选）ROI.Domain_指示灯区 ─▶ 区域颜色检查.Image    （先定位/先裁剪再看）
（可选）模板匹配.AlignedImage ───▶ 区域颜色检查.Image     （每帧位置会变时先对齐）

区域颜色检查.Result  ─▶ If（逻辑控制） / 结果上报.判定
区域颜色检查.Color   ─▶ 结果显示.r1 / CSV记录
区域颜色检查.Share   ─▶ 数值比较 / 数学计算（占比趋势、报警口径）
区域颜色检查.Verdict ─▶ 结果显示.r2 / 结果上报.备注
```

**判定不合格 ≠ 本步骤失败**：颜色错或不纯时 `Result=false`、`Verdict` 说清原因，步骤照常跑通，
下游按 `Result` 分流；只有跑不动（没图、没框、灰度图、期望没配）才 `Success=false`。
