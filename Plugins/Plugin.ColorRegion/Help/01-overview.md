# 区域颜色检查

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorRegion

回答"**这一块区域是什么颜色、是不是我要的那个颜色、纯不纯**"。
在采样区（矩形 / 圆 / 椭圆）里**逐点分类成颜色词再投票**，取票数最多的**主色**和它的**占比**，
再与期望颜色比对。产出主色 `Color`、占比 `Share`、区域中位色 `Rgb`、各色占比明细 `Table`、
判定 `Result`、结论全文 `Verdict`，并可把「采样区轮廓 + 主色标签 + 结论行」投到主界面的视图窗口。

典型场景：**指示灯什么颜色、色标对不对、这块区域颜色纯不纯、某颜色占比够不够**。

## 为什么需要它 / 原理

**逐点分类 → 投票 → 主色 + 占比**，而不是"取区域中位色分类一次"：

```
采样区 ROI（矩形 / 圆 / 椭圆）
   ↓ ① 展开成区域内的逐像素点集（点太多按固定步长均匀抽稀）
   ↓ ② 一次取回整批点的 R/G/B
   ↓ ②.5 高位深图自动等比压回 8 位（判据按 8 位标定）
   ↓ ③ 每个点归成一个"颜色词"，累计票数
{ 灰: 63, 蓝: 22, 白: 10, 绿: 5 }
   ↓ ④ 票数降序 → 主色 = 灰，占比 = 63%
   ↓ ⑤ 判定：主色在期望词表里？且 占比 ≥ 最小占比？
合格 / 不合格（并给出结论全文）
```

- **为什么非要投票**：区域里若一半红一半蓝，中位色可能是个"谁都不像"的颜色，
  却还是会被报出一个词——现场看不出它其实没把握。逐点投票会直接告诉你"主色红只占 41%"，
  这是"**不纯**"，不是"红"。
- **为什么用 HALCON 区域当掩膜**（本算子最核心的一点）：**用方框框圆形指示灯时，方框的四个角是背景**。
  不作掩膜，背景像素会参与投票，主色可能直接变成"背景色"，而且因为背景占比高，它还会"看起来很有把握"。
  用**圆形**采样区就只剩灯上的像素。→ 圆形指示灯请用「新建圆形」，不要用方框。
- **抽稀是均匀的**：超过「采样点数上限」时按固定步长跳点，投票不会被偏向某一侧，所以区域很大时**不必调大上限**。
- **越界自动裁**：采样区超出图像的部分被裁掉（不报错——框松一点是常事）；
  但如果**完全没交集**会直接报错。
- **票数打平时按词表顺序定序**（黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫），保证同一块区域每次跑出来的主色都一样。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | 运行期必需 | 待检查的图像（`HImage`）。端口本身不强制（编译期不报），运行期没有图直接失败。**必须三通道彩色图**（通道数 < 3 会报错停下）；12/16 位高位深图自动等比压回 8 位再判色 |

> 采样区**不接上游 ROI**：它是本算子内部画的 ROI（`RoiShape` + `RoiParams`），上游只进 `Image`。
> 想先圈定再看，就把「ROI」的 `Domain_名字` 接到 `Image`——坐标系不变，本算子照常在自己的采样区里取点。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Color` | 主色（票数最多的颜色词，11 词之一） |
| `Share` | 主色占比（`0~1` 的小数，不是百分数）。界面上显示的百分比就是它 ×100 |
| `Rgb` | 区域**中位色**，字符串 `R, G, B`（排查与示教用）。高位深图归一发生过时，这里是**归一后**的值 |
| `Table` | 各颜色词的占比明细，如 `红:96%、灰:4%` |
| `Result` | 判定结论：`true` = 合格 / `false` = 不合格（不合格时本步骤仍算执行成功） |
| `Verdict` | 结论全文，写给人看的那一句（日志、画面标注、下游上报共用同一句） |
| `Success` / `ErrorMessage` | 基类自带：本步骤是否跑通、失败时的中文原因 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

**采样区与判据**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `RoiShape` | `Rectangle` | 采样区形状：`Rectangle` / `Circle` / `Ellipse`。**不用手填**——你在图上右键画的是哪种就是哪种（新建矩形 / 圆形 / 椭圆） |
| `RoiParams` | 空（未框选） | 采样区参数，**固定 5 个数**：矩形 `[中心行, 中心列, 角度(弧度), 半长, 半宽]`；圆 `[中心行, 中心列, 半径, 0, 0]`；椭圆 `[中心行, 中心列, 角度(弧度), 半径1, 半径2]`。统一 5 槽是为了让存取只有一条路径（圆的第 4/5 个是占位 0，不用） |
| `ExpectedColors` | 空 | 期望颜色，逗号分隔（中英文逗号、顿号都认），**命中任一即可**，如 `红,玫红`。写 `*` = **只报颜色不判定**。**留空会在运行期报错**（配置问题不静默通过）。词表只有 `黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫` |
| `MinShare` | `0.60` | 主色最少要占多少才算合格（0~1）。越界值会被**夹回 0~1**（填 1.5 会"永远不纯"、填 -0.2 会"永远合格"，都是配置错误在悄悄改判定，所以夹住）。区域里有反光/边界过渡时适当调低 |
| `SamplePoints` | `400` | 区域内最多取多少个采样点（超了按步长均匀抽稀；下限 8）。区域很大时不必调大 |
| `DisplayViewIndex` | `1` | 结果投射到主界面第几个视图窗口（1~9）；`0` = 不投射 |

**颜色判据阈值（13 项）**：把实测颜色归到哪个颜色词用的阈值，与「颜色序列检查」同一套词、同一套默认值。
这里是**本步骤自己带的一份可调副本**（随方案落盘，改它不影响别的工位/算子）。

| 参数 | 默认 | 一句话 |
| --- | --- | --- |
| `ColorlessSaturation` | `0.45` | 无彩/有彩分界（饱和度） |
| `BlackValue` | `80` | 无彩且明度低于它 → 黑 |
| `WhiteSaturation` | `0.15` | 白还要求饱和度低于它 |
| `WhiteValue` | `195` | 无彩且明度高于它 → 白 |
| `BrownWarmth` | `12` | 无彩但偏暖（R 比 G、B 都高出这么多）→ 棕 |
| `BrownValue` | `175` | 棕的明度上限（比它亮就归灰） |
| `RoseHueFrom` | `330` | 玫红起点（色相，度） |
| `RedHueFrom` | `350` | 红起点 |
| `RedHueTo` | `20` | 红止点（红跨 0 度） |
| `OrangeHueTo` | `45` | 橙止点 |
| `YellowHueTo` | `70` | 黄止点 |
| `GreenHueTo` | `160` | 绿止点 |
| `BlueHueTo` | `230` | 蓝止点（比它高就是紫） |

逐项怎么调、往哪个方向调，见《区域颜色检查 · 调参与判据》。

## 口径与失败策略

- **"判定不合格" ≠ "本步骤失败"**。颜色错或不纯时 `Result=false`、`Verdict` 说清原因，步骤照常跑通；
  下游按 `Result` 分流。只有跑不动才 `Success=false`。
- **判定口径**（逐条）：

| 情况 | 行为 |
| --- | --- |
| 主色在期望词表里 **且** 占比 ≥ `MinShare` | 合格：`颜色正确：红（占 96%，期望 红,绿）` |
| 主色对、占比不足 | 不合格：`颜色不纯：主色 X 只占 N%（要求 ≥ M%），明细 …` |
| 主色不在期望词表 | 不合格：`颜色错误：实测 X（占 N%），期望 Y；明细 …` |
| 期望为空 | **运行期报错**（不是默认通过，也不判产品不良）——没配期望是工程配置问题 |
| 期望写 `*` | 合格：`只报颜色不判定：X（占 N%，中位色 R,G,B）`（这是你显式写的"我要不检"） |
| 期望里有词表外的词 | **报错**并列出 11 个可用词。比对按字面做，词表外的词永远匹配不上 |

- **会失败（本步骤报错停下）的情形**：上游没有图像／图像未初始化；尚未框选采样区（`RoiParams` 不是 5 个数）；
  图像通道数 < 3；形状名认不出（应为 `Rectangle` / `Circle` / `Ellipse`）；参数不足 5 个；
  矩形半长/半宽 ≤ 0；圆的半径 ≤ 0；椭圆的两个半径 ≤ 0；采样区与图像**没有交集**；采样区里取不到点；
  采样点超出图像范围；区域里取不到采样点；期望为空；期望词不认。提示语一律写清"怎么补"。
- **只是告警、不中断**：主色占比低于 60% 时提一条"区域颜色不纯：主色 X 只占 N%…确认采样区是否框到了背景或多种颜色"
  （这是**提醒**，和 `MinShare` 的判定阈值无关）；高位深归一发生时带一条说明。都进日志 Warn。
- **投图是锦上添花**：推图失败绝不把一次成功的检测判成失败（异常被吞掉，端口与判定照写）。`DisplayViewIndex=0` 完全不推。
- **画面标注口径**：采样区轮廓按**折线**画（圆/椭圆不画成方框，否则看不出采的是哪一块），
  中心右侧贴 `主色 占比%`，结论行优先贴采样区上方、贴不下改贴下方、再越界夹回画面内。合格绿、不合格红。
- **坐标与单位口径**：全部图像像素系 `(Row, Col)`；角度存盘是**弧度**（界面摘要显示成度）；
  `Share` 是 0~1 的小数；`Rgb` 是 8 位口径（0~255）。

## 典型用法 / 接线

```
图像采集.OutputImage ─────▶ 区域颜色检查.Image
（可选）ROI.Domain_指示灯区 ─▶ 区域颜色检查.Image    （先定位/先裁剪再看）
（可选）模板匹配.AlignedImage ───▶ 区域颜色检查.Image     （每帧位置会变时先对齐）

区域颜色检查.Result  ─▶ If（逻辑控制） / 结果上报.判定
区域颜色检查.Color   ─▶ 结果显示.r1 / CSV记录
区域颜色检查.Share   ─▶ 数值比较 / 数学计算（占比趋势、报警阈值）
区域颜色检查.Verdict ─▶ 结果显示.r2 / 结果上报.备注
```

**第一次用的 4 步**：
① 左栏「图像输入」点 🔗 绑上游图像（或画布上拖一条线）；
② 点「执行」——上游图会自动显示在右侧画布（第一次会报"尚未框选采样区"，那是对的）；
③ 在图上**右键 → 新建矩形 / 新建圆形 / 新建椭圆**，框住要检的那块（圆形指示灯用圆形）；
④ 点「试算一下」看主色与占比，再点「把主色填成期望颜色」一键把期望填上。

> **试算不要求先填期望颜色**：现场通常是"先试算出主色 → 再一键填成期望"，
> 若试算就强制要求填期望，那个入口永远用不上（顺序死锁）。**判定在运行期做，而且必须做**。

## 常见问题

**Q：主色怎么判成背景色了？**
多半是**采样区太大或形状不对**。用方框框圆形灯，四个角的背景会参与投票——改用「新建圆形」贴合目标。
其次看试算结果的「明细」行：若主色占比只有 40%~60%，就是框里混进了别的东西。

**Q：报"颜色不纯：主色只占 N%"，但颜色明明是对的？**
两种可能：① 采样区框到了背景或多种颜色（收窄它）；② `MinShare` 要求太高（默认 0.60）。
指示灯边缘的反光、色标与基材的过渡带都会摊薄占比——适当调低 `MinShare` 是正解，
但别调到 0 以下或 1 以上（越界值会被夹回 0~1）。

**Q：期望颜色为空会怎样？**
**运行期报错**："尚未配置期望颜色"。不静默通过、也不判成产品不良。要"只报颜色不判定"请显式写 `*`。

**Q：手打"深红"为什么匹配不上？**
颜色词只有 **黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫** 十一个，比对按字面做。
用「把主色填成期望颜色」一键填，从根上避开打错词。

**Q：能接上游的 ROI 吗？（比如「ROI」算子的 `MaskRegion`）**
**不能**。本算子的采样区是插件内部画的 5 槽参数，上游只进 `Image`。
想限定范围就把 `Domain_名字` 接到 `Image`（坐标系仍是全局的）。

**Q：有 RGB / HSV / Lab 切换吗？能算 ΔE 颜色距离吗？**
都没有。判据固定用 **HSV 式**（`s=(max−min)/max`、`v=max`、色相角），要微调的是 13 项色卡阈值；
判定是"投票 + 占比"，**没有距离度量、没有容差半径**。详见《区域颜色检查 · 调参与判据》。

**Q：`Share` 是百分数还是小数？**
小数（0~1）。要看百分数就用 `Table`（文本明细，如 `红:96%、灰:4%`）或 `Verdict`，
或在下游自己乘 100。

**Q：换了 12 位相机，中位色的 R,G,B 变小了，是不是坏了？**
不是。判据按 8 位标定，高位深图会**按实测最大灰度等比压回 0~255** 再判色，日志会留一条说明；
`Rgb` 给的是**归一后**的值。色相与饱和度是比值，等比缩放不动它们，所以**颜色词的答案不变**。

**Q：结果图投到哪去了？画面上一片黑？**
投递窗口由 `DisplayViewIndex`（1~9）决定，`0` 表示不投射。
合格绿字、不合格红字；推图失败只会没有标注，不影响判定结果。
