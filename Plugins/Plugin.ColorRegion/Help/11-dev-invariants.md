# 区域颜色检查 · 不变量与移植清单

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorRegion ｜ 读者：开发

每条一律 **症状 → 机理 → 守门断言名**。A 组违反就编译期/闸门红；B 组违反不报错、只出诡异现象
（B 组才是接手合并时真正要读的部分）。断言名逐字抄自 `FlowCanvasChecks\ColorRegionCheck.cs`
与 `FlowCanvasChecks\ColorSyntheticChecks.cs`，改代码前先按名字找到那条断言。

## A 组：改了就红

**1. `RoiShape` 存成枚举**
症状：`.vms` 回填或步骤 `InputValues` 往返时抛 `InvalidCastException`，表现为"方案一打开就报错/配置丢一半"。
机理：形状走 `RoiShapeNames` 字符串常量集（`Rectangle` / `Circle` / `Ellipse`），
字符串在 `InputValues` 里往返无损，枚举经那条链会被按底层类型强转。
守门：`ColorRegionCheck` 的「参数能随方案落盘并回填（形状 / 采样区 / 期望颜色 / 最小占比 / 采样点数 / 投射窗口 / 颜色阈值）」
——它做的是"存一遍、读一遍、逐字段比"的往返断言，改成枚举当场红。

**2. `RoiParams` 不是固定 5 槽**
症状：画完框、点执行报"尚未框选采样区"；或圆和椭圆互相错位。
机理：三种形状统一存 5 个数（圆的第 4/5 位是占位 0），存取/回填/断言因此只有一条路径；
按形状分长度会让"参数长度校验"变成三套，且旧方案在新版本读不回来。
守门：同上一条落盘断言 + 三条形状各自的判定断言「【矩形】框住灰线 → 主色 灰、占比高、判合格」
「【圆形】圆框住灰线 → 主色 灰（圆掩膜生效，不是方框四角）」「【椭圆】椭圆框住灰线 → 主色 灰」。

**3. 13 个阈值属性名与 `ColorThresholdEditor` 的绑定名不一致**
症状：**不红、界面上也看不出**——改了阈值没生效（这是最坏的一类，所以它其实在 B 组门口；放这里是因为改名这一步有闸门）。
机理：WPF 绑定失败是静默的；控件是「颜色序列检查」与本算子**共用**的，它按属性名绑。
守门：`ColorRegionCheck` 的「插件程序集可装载（含 WPF 视图与共用阈值编辑器）」是装载级兜底；
真正的口径是"改名要同时改两处"，改完必须跑「参数能随方案落盘并回填…」确认那 13 项真的进了快照。

**4. 新增工具箱条目/改手册却破坏打包约定**
症状：宿主静默退回"自动生成页"（一张干巴巴的端口清单），不报错也不提示。
机理：手册必须 `Help\` 扁平、`NN-` 前缀、首行 `# 一级标题`、无 BOM UTF-8、正文合计达标、不许出现占位词。
守门：手册闸门 `FlowCanvasChecks\HelpManualCheck.cs` 的 HM0~HM11（进常规 gate 基线）。
另一头是构建期：加完手册要给该工程 `--no-incremental` 重建并核 DLL 里的 `.Help.` 资源名数（AGENTS.md R42）。

## B 组：违反不报错，只出诡异现象

**5. 不用区域掩膜、直接按外接矩形取点**
症状：用方框框圆形指示灯时，主色报成**背景色**，而且因为背景占比高、它"看起来很有把握"；
`Result` 还会判合格（如果背景恰好是期望词之一）。
机理：形状由 HALCON 区域当掩膜保证，落在区域外的点不参与投票。省掉掩膜 = 投票样本混入四角背景。
守门：「【圆形】圆框住灰线 → 主色 灰（圆掩膜生效，不是方框四角）」——这条就是为这个坑写的反证。

**6. 取中位色分类一次，代替逐点投票**
症状：区域里两色混杂时仍报出一个干净的颜色词，现场以为很有把握；"混料/贴错色标"漏检。
机理：中位色可能是"谁都不像"的颜色，但它照样会被归成一个词。投票的价值是说"主色只占 41%"。
守门：「【判定·混合】框住两根线+缝 → 明细里出现多种颜色，主色占比明显低于单根线」
+「【判定·占比不足】期望对但要求 ≥90%（实测只有 67%）→ 判「颜色不纯」」。

**7. 票数打平时靠字典/遍历顺序定序**
症状：同一块区域、同一张图，两次跑出来的主色不一样（或在两台机器上不一样）。
机理：打平必须按词表顺序（黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫）定序，保证可复现。
守门：`ColorRegionCheck` 各形状与判定的确定性断言（同一夹具重跑必须同结果）；
跨算子一致性由「采集 / 颜色序列 / 区域颜色 三个插件程序集可装载」起步的 `ColorSyntheticChecks` 流程链兜住。

**8. 不做高位深归一就直接判色**
症状：换 12/16 位相机后"黑"永远判不出、"白"满天飞、灰/棕大面积误判；
`Rgb` 中位色数值变小会被当成"坏了"。
机理：明度阈值（80 / 195 / 175）按 8 位标定。归一是**按实测最大通道值等比压回 0~255**，
色相与饱和度是比值量所以颜色词答案不变——但**必须留一条 Warn** 说明 `Rgb` 是归一后的值。
守门：「【5 芯图】框住红线 → 主色 红（同一算子换图不用改配置）」验证换图不漂移；
日志留痕是人工复核项（文案：图像是高位深…已等比压到 8 位再判色…）。

**9. 期望为空时"默认通过"**
症状：现场漏配期望颜色 → 全线一路绿灯，且没有任何地方报错；不良流出。
机理：期望为空是**配置问题**，必须运行期挡下来；"不判定"只有显式写 `*` 这一条路。
守门：「没填期望颜色 → 明确报错（配置问题不静默通过、也不判成不良）」。

**10. 期望词做模糊匹配 / 容错映射**
症状：填"深红"看似生效，实际永远匹配不上 → 恒定"颜色错误"，排查半天。
机理：比对按字面做；词表外的词必须**当场报错并列出 11 个可用词**，把静默故障前移成配置期报错。
守门：「期望颜色写了词表外的词（深红）→ 明确报错并列出可用词」。

**11. 灰度图复制成三通道硬撑**
症状：黑白产品上判出随机颜色词，判定看似正常。
机理：本算子的语义建立在彩色通道上，通道数小于 3 必须停下报错而不是猜。
守门：「灰度图 → 明确报「要彩色图」」。

**12. 采样区完全越界时静默返回空结果**
症状：`Result=true`、`Color` 为空或上轮的旧值——最阴的一种（旧值会伪装成"这次也合格"）。
机理：部分越界裁掉（框松是常事），完全没交集必须报错；取不到投票点同理。
守门：「采样区整个落在图像外 → 报「没有交集」」+「没框采样区 → 明确报错并说清怎么补」。

**13. 投图失败把检测判成失败**
症状：一次成功的检测因为界面窗口没就绪被记成 `Success=false`，整条线停。
机理：投射是锦上添花，异常必须被吞掉、端口与判定照写。
守门：「【投射】只投一帧、投到 1 号视图窗口」「【投射】矩形轮廓 = 4 条线 + 主色标签 + 结论行（共 6 条标注）」
「【投射·合格】结论与主色标签都是绿字」「【投射·不合格】结论是红字」
「【投射·圆形】轮廓按 32 段折线画（圆要像圆，不能画成方框）」——这组同时钉住"形状按折线"和"颜色按结论"。

**14. 画布直接引用上游 `HImage` 句柄**
症状：上游释放或换图后画布变空/变黑，或反过来"打开配置读了一张已经失效的示意图路径"。
机理：视图必须**自己拷一份**，并优先用上游图而不是示意图路径；换产品时画布要跟着换。
守门：「【上游图】上游图灌进 Image 端口后，自动显示到配置界面的画布上」「【上游图】画布上显示的就是上游那张图（尺寸一致）」
「【上游图】显示的是自己拷的一份：上游句柄释放后画布仍然可用（不会变成空句柄）」「【上游图】上游换成另一张图（换产品）→ 画布跟着换」
「【上游图】打开配置时优先用上游图，不去读（可能失效的）示意图路径」。

**15. 试算入口加上"必须先填期望颜色"**
症状：示教按钮「把主色填成期望颜色」永远点不动（顺序死锁），现场改成手打颜色词 → 撞上第 10 条。
机理：试算只做颜色分析，判定在运行期做且必须做。
守门：「【试算】给出主色、占比、中位色与明细（现场据此判断框得对不对）」
+「【示教】「把主色填成期望颜色」一键成配方（省得手打颜色词打错）」。

**16. 在本算子里"改玫红的定义"**
症状：改 13 项阈值看起来生效，但另一个工位/另一个颜色算子里的答案不一样，或全仓颜色语义漂移。
机理：阈值数值是**每算子一份副本**（可以各调各的），**颜色词表与分类层次在内核 `Core.Halcon.Color`**（共用，改它影响所有颜色算子）。
守门：`ColorSyntheticChecks` 的流程链（颜色序列检查与两个区域颜色检查步骤并存，验"各带副本、共用词表"这条边界）；
要动词表属于改公共契约，按 AGENTS.md R12 走架构评审。

## 移植 / 扩展清单

- **加第 12 个颜色词**：只动内核词表 = 影响所有颜色算子 + 打断既有方案里存成文本的期望颜色。必须先评审。
- **加形状（如多边形）**：三处同时改——`RoiShapeNames`、`RoiParams` 的 5 槽约定（多边形装不进 5 个数，
  这条约定本身要重设计）、`ProjectResult` 的折线投射；再加 `ColorRegionCheck` 的新形状断言。
- **要 ΔE / 颜色距离**：不要在投票链上打补丁。连续量用 `Rgb` 端口 + 「C#脚本」，或走带阈值分割的预处理算子。
- **要接上游 ROI 当采样区**：与第 5 条的掩膜口径耦合（上游区域 + 内部形状两套语义），
  先想清"谁裁谁"，否则又是一份"看起来很有把握的背景色"。
