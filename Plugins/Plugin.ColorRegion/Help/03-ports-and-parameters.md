# 区域颜色检查 · 端口与参数

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorRegion

端口名与配置项名逐字对源码；默认值与夹取行为以工程 `RegionColorPlugin.cs` 为准。

## 输入端口

| 端口 | 类型 | 必填 | 接不上会怎样 |
| --- | --- | --- | --- |
| `Image` | `HImage` | 运行期必需 | 端口本身不强制（编译期不报红），运行期没有图直接失败并提示怎么连。**必须三通道彩色图**（通道数小于 3 会报错停下）；12/16 位高位深图自动等比压回 8 位再判色 |

> 采样区**不接上游 ROI**：它是本算子内部画的 ROI（`RoiShape` + `RoiParams`），上游只进 `Image`。
> 想先圈定再看，就把「ROI」算子的 `Domain_名字` 接到 `Image`——坐标系不变，本算子照常在自己的采样区里取点。
> 位置每帧会变（工件在传送带上浮动）时，上游先接「模板匹配」的对齐图。

## 输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `Color` | `string` | 主色（票数最多的颜色词，11 词之一） |
| `Share` | `double` | 主色占比（`0~1` 的小数，**不是百分数**）。界面上的百分比就是它乘 100 |
| `Rgb` | `string` | 区域**中位色**，字符串 `R, G, B`（排查与示教用）。高位深图归一发生过时，这里是**归一后**的值 |
| `Table` | `string` | 各颜色词的占比明细，如 `红:96%、灰:4%` |
| `Result` | `bool` | 判定结论：`true` 合格 / `false` 不合格（不合格时本步骤仍算执行成功） |
| `Verdict` | `string` | 结论全文，写给人看的那一句（日志、画面标注、下游上报共用同一句） |
| `Success` / `ErrorMessage` | 基类自带 | 本步骤是否跑通、失败时的中文原因 |

## 配置项：采样区与判据

| 配置项 | 默认 | 取值范围 | 改了影响什么 |
| --- | --- | --- | --- |
| `RoiShape` | `Rectangle` | `Rectangle` / `Circle` / `Ellipse` | **不用手填**——你在图上右键画的是哪种就是哪种（新建矩形 / 圆形 / 椭圆）。存的是字符串而不是枚举：枚举值经步骤的 `InputValues` 往返会抛 `InvalidCastException` |
| `RoiParams` | 空（未框选） | 固定 5 个数 | 采样区几何。矩形 `[中心行, 中心列, 角度(弧度), 半长, 半宽]`；圆 `[中心行, 中心列, 半径, 0, 0]`；椭圆 `[中心行, 中心列, 角度(弧度), 半径1, 半径2]`。统一 5 槽是为了让存取、回填、断言只有一条路径（圆的第 4/5 个是占位 0，不用） |
| `ExpectedColors` | 空 | 11 个颜色词，逗号分隔；或 `*` | 期望颜色，**命中任一即可**，如 `红,玫红`（中英文逗号、顿号都认）。`*` = **只报颜色不判定**。**留空会在运行期报错**（配置问题不静默通过） |
| `MinShare` | `0.60` | `0~1`，越界夹回 | 主色最少要占多少才算合格。填 1.5 会"永远不纯"、填 -0.2 会"永远合格"，都是配置错误在悄悄改判定，所以界面夹住。怎么定见口径页 |
| `SamplePoints` | `400` | 上限，下限 8 | 区域内最多取多少个采样点，超了按固定步长**均匀**抽稀。均匀抽稀不会让投票偏向某一侧，所以区域很大时**不必调大**它；只有"区域很小但想全点都采"时才用得上 |
| `DisplayViewIndex` | `1` | `1~9`；`0` = 不投射 | 结果投到主界面第几个视图窗口 |

## 配置项：颜色判据阈值（13 项）

把实测颜色归到哪个颜色词用的阈值，与「颜色序列检查」**同一套词、同一套默认值**。
这里是**本步骤自己带的一份可调副本**（随方案落盘，改它不影响别的工位/算子）。
配置路径：节点配置 → 检查参数 → **高级参数** → **颜色判据阈值**。

| 配置项 | 默认 | 一句话 |
| --- | --- | --- |
| `ColorlessSaturation` | `0.45` | 无彩/有彩分界（饱和度） |
| `BlackValue` | `80` | 无彩且明度低于它 → 黑 |
| `WhiteSaturation` | `0.15` | 白还要求饱和度低于它 |
| `WhiteValue` | `195` | 无彩且明度高于它 → 白 |
| `BrownWarmth` | `12` | 无彩但偏暖（R 比 G、B 都高出这么多）→ 棕 |
| `BrownValue` | `175` | 棕的明度上限（比它亮就归灰） |
| `RoseHueFrom` | `330` | 玫红起点（色相，度） |
| `RedHueFrom` | `350` | 红起点 |
| `RedHueTo` | `20` | 红止点（红跨 0 度） |
| `OrangeHueTo` | `45` | 橙止点 |
| `YellowHueTo` | `70` | 黄止点 |
| `GreenHueTo` | `160` | 绿止点 |
| `BlueHueTo` | `230` | 蓝止点（比它高就是紫） |

逐项往哪个方向调、调错会是什么现象，见《颜色区域与判色阈值口径》。

> 这 13 个属性名必须与共用控件 `ColorThresholdEditor` 里绑的名字**逐字一致**——
> WPF 绑定失败是静默的（界面上看着有那一项、改了却没进配置）。

## 界面操作件

| 界面元素 | 干什么 | 注意 |
| --- | --- | --- |
| 右侧画布 | 显示上游灌进来的图（打开配置时优先用上游图，不去读可能失效的示意图路径） | 画布显示的是**自己拷的一份**：上游句柄释放后画布仍可用 |
| 右键 → 新建矩形/圆形/椭圆 | 画采样区，同时写回 `RoiShape` + `RoiParams` | 形状不用手填，画什么就是什么 |
| 「试算一下」 | 只做颜色分析、**不做判定**（填了期望也会把判定一起显示出来） | 没有试算结果时提示"还没有试算结果" |
| 「把主色填成期望颜色」 | 把上一次试算的主色写进 `ExpectedColors` | 没有试算结果时点它只会给提示，不会填空值 |

## 落盘

全部配置项（形状 / 采样区 / 期望颜色 / 最小占比 / 采样点数 / 投射窗口 / 13 项颜色阈值）随步骤的
`[StepConfig]` 快照写进 `.vms`，回填走同一份快照；断言 `参数能随方案落盘并回填（形状 / 采样区 / 期望颜色 /
最小占比 / 采样点数 / 投射窗口 / 颜色阈值）` 逐字段核对往返一致。
