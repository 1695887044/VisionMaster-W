# 区域颜色检查 · 排障

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorRegion

下面的**报错文案逐字抄自源码**（`RegionColorPlugin.cs` 与内核 `RegionColorAnalyzer.cs`），
可以直接拿界面上看到的句子在这里查。

## 本步骤报错停下（`Success=false`，`ErrorMessage` 就是这句）

**「上游没有图像：请先在流程里把本节点的 Image 连到上游（画布上从上游拖一条线过来，或右键 → 变量绑定选上游的 Image 输出）。只想先框采样区的话，点「执行」一次，上游图像会自动显示在配置界面右侧」**
`Image` 端口取不到图或图未初始化。按提示连线；这条文案刻意把"只想先框采样区"这条路也写出来，
因为初次配置时所有人都卡在这一步。

**「尚未框选采样区：请在节点配置里于图像上右键 → 新建矩形/圆形/椭圆，框住要检的那块」**
`RoiParams` 不是 5 个数（从没画过、或画的过程被打断）。去画布上重画一个即可，不需要手填参数。

**「区域颜色检查要彩色图，当前图像只有 N 个通道」**
灰度图（含单通道被误当彩色的采集通道设置）。换彩色输出，或把这一路判色改成灰度判据的算子；
内核里同一条判据的文案是「区域颜色检查要彩色图，当前只有 N 个通道」，两句同义、出现在不同层，日志里都可能见到。

**「采样区与图像没有交集」**
采样区整个框到画面外。往图里挪；只是**部分**越界不会报错（超出部分自动裁掉）。

**「区域里取不到采样点：请重新画一个框」**
区域存在但取不到可投票的点（框得过小、或被裁到只剩边缘）。把框放大一点重画。

**「尚未配置期望颜色：请在节点配置里填「期望颜色」（多个用逗号分隔，写 * 表示只报颜色不判定）」**
期望为空时**运行期报错**：不静默通过、也不判成产品不良——没配期望是工程配置问题，不是产品问题。
要"只报颜色不判定"请显式写 `*`。

**「期望颜色里有认不出的词：X；…」并列出可用词**
颜色词只有 **黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫** 十一个，比对按字面做，词表外的词永远匹配不上。
用「把主色填成期望颜色」一键填，从根上避开打错词。

形状名认不出、参数不足 5 个、矩形半长/半宽 小于等于 0、圆的半径 小于等于 0、椭圆的两个半径 小于等于 0、
采样点超出图像范围——这几条同样从"采样区几何"这个口子出来，一律提示怎么补；
绝大多数是画框时把句柄拖反了，重画最快。

## 步骤跑通了，但判定不合格（`Result=false`）

这**不是**故障：`Verdict` 会说清原因，步骤照常执行成功，下游按 `Result` 分流。三种结论全文——

| 界面上看到的 `Verdict` | 含义 | 先改什么 |
| --- | --- | --- |
| `颜色正确：红（占 96%，期望 红,绿）` | 主色命中期望且占比达标 | — |
| `颜色不纯：主色 X 只占 N%（要求 ≥ M%），明细 …` | 主色对、纯度不够 | ① 采样区混进背景或第二种颜色（收窄它）；② `MinShare` 定太高 |
| `颜色错误：实测 X（占 N%），期望 Y；明细 …` | 主色不在期望词表 | 先看是不是判成了背景色（形状/大小），再考虑动色卡 |
| `只报颜色不判定：X（占 N%，中位色 R,G,B）` | 期望写了 `*` | 正常，这是显式配置的"不检" |

**主色怎么判成背景色了？** 多半是**采样区太大或形状不对**。用方框框圆形灯，四个角的背景会参与投票——
改用「新建圆形」贴合目标。其次看试算结果的「明细」行：若主色占比只有 40%~60%，就是框里混进了别的东西。

## 日志里的告警（不中断）

**「图像是高位深（实测最大灰度 N），已等比压到 8 位再判色；颜色词不受影响，中位色 R,G,B 为归一后的值」**
换了 12/16 位相机、接手后发现中位色的 R/G/B 变小了——**不是坏了**。判据按 8 位标定，
图会按实测最大灰度等比压回 0~255 再判色；色相与饱和度是比值，等比缩放不动它们，所以**颜色词的答案不变**。

**「区域颜色不纯：主色 X 只占 N%…确认采样区是否框到了背景或多种颜色」**
占比低于 60% 时的**提醒**，和 `MinShare` 的判定阈值无关（它是固定提示线）。进日志 Warn，不影响判定。

正常跑通时日志有三行：`区域颜色检查：主色 …（占 …%），中位色 R… G… B…，采样 … 点`、
`区域颜色检查：明细 …`、`区域颜色检查·判定：…`。排查现场问题时这三行是最快的入口。

## 配置界面的两条提示语

- 点「把主色填成期望颜色」时提示**「还没有试算结果：先框好采样区并点「试算一下」，再把主色填成期望颜色」**：
  顺序是先试算、再一键填，不是按钮坏了。
- 试算结果区里出现**「尚未配置期望颜色（点下面那个按钮即可把主色填进去）」**：
  这是**试算**路径，试算不要求先填期望（现场顺序是"先试算出主色 → 一键填成期望"，
  若试算就强制填期望，那个入口永远用不上）。**运行期**才会因期望为空报错。
- 试算失败时摘要行写成 `试算失败：…`、判定行写成 `无法判定：…`，后面跟的就是上面那几条真实文案。

## 现象 → 先查这一项

| 现象 | 先查这一项 |
| --- | --- |
| 主色判成背景色 | 形状/大小（圆灯用了方框）→ 改「新建圆形」 |
| 「颜色不纯：主色只占 N%」 | ① 采样区混进背景或第二种颜色；② `MinShare` 定太高 |
| 绿灯读成蓝 | `GreenHueTo`（默认 160）调高；青色 LED 的色相常落在 170~190 |
| 红灯与玫红乱跳 | 只动 `RoseHueFrom` / `RedHueFrom`（330 / 350）这一对 |
| 白标签读成黄/灰 | 白的两条附加条件：`WhiteSaturation`（0.15）与 `WhiteValue`（195）——暖光下先放宽饱和度、再压低明度 |
| 12/16 位相机接手后黑白灰棕大面积错 | 不用改参数：已自动等比压回 8 位，日志有说明；`Rgb` 是归一后的值 |
| 换工位/换产品就要重配 | 正常——阈值是**每个算子各带一份副本**，随各自方案落盘，这正是设计意图 |
| 结果图上找不到标注 | `DisplayViewIndex`（1~9，0 = 不投射）；轮廓按折线画，圆/椭圆不会画成方框 |
| 画布上图是黑的/空的 | 打开配置时优先用上游图；上游本轮失败则端口为空，先跑通上游 |

## 光照漂移与换型：按这个顺序重调

1. **先看主色对不对**：点「试算一下」读「主色」和「明细」。
   主色就对、占比偏低 → 是**采样区/`MinShare`** 的问题，不要动色卡。
2. **主色就不对** → 动 13 项阈值；先分清落在**无彩区**（黑白灰棕）还是**有彩区**（色相），只动对应那一组。
3. **换了灯/加了遮光罩，全批漂移** → 先看 `Rgb` 中位色的绝对值漂了多少：
   明度类阈值（`BlackValue` `WhiteValue` `BrownValue`）跟着打光方向调；
   饱和度分界 `ColorlessSaturation` 是唯一一个"比例型"的稳剂量，通常**不用改**。
4. **位置每帧会变**（工件在传送带上浮动）→ 上游先接「模板匹配」的对齐图或「ROI」的 `Domain_`；
   本算子的采样区坐标始终是**图像像素系**，不会因为上游裁图而自动跟着走。
5. **灯灭态**（要区分"灭"和"绿"）→ 灭态通常读成 `黑` 或 `灰`，把期望写成多候选即可
   （如 `红,绿` 允许两态）；灭态另用别的判定链路，或期望填 `*` 只报颜色、由下游用 `Color`/`Share` 自己判。

## 常见问法

**Q：多个颜色都算合格怎么配？** 「期望颜色」用逗号分隔多候选，**命中任一即可**：`红,玫红`。中英文逗号、顿号都认。

**Q：怎么只让它"报颜色"、不参与流程判定？** 在「期望颜色」里写 `*`（它是配置项，不在输入端口上）。
此时 `Result` 恒为 `true`，`Verdict` 是"只报颜色不判定：X（占 N%，中位色 R,G,B）"，
下游想怎么用 `Color` / `Share` 都行。

**Q：想让某个颜色占比达到多少才算亮灯？** 用 `Share` 端口：期望填 `*` 让它只报颜色，
下游用「数值比较」/「数学计算」判断 `Share` 不小于阈值，或直接接「If」（逻辑控制）。
这样"颜色对不对"和"亮度够不够"两条判定各管各的。

**Q：能接上游的 ROI 吗（比如「ROI」算子的 `MaskRegion`）？** **不能**。
采样区是插件内部的 5 槽参数，上游只进 `Image`。想限定范围就把 `Domain_名字` 接到 `Image`（坐标系仍是全局的）。

**Q：有 RGB / HSV / Lab 切换吗？能算 ΔE 颜色距离吗？** 都没有。
判据固定用 **HSV 式**，要微调的是 13 项色卡阈值；判定是"投票 + 占比"，没有距离度量、没有容差半径。

**Q：`Share` 是百分数还是小数？** 小数（0~1）。要百分数就用 `Table`（如 `红:96%、灰:4%`）或 `Verdict`，
或在下游自己乘 100。
