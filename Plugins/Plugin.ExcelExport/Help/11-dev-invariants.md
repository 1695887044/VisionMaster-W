# Excel报表：不变量与移植清单

> 分类：数据处理 ｜ 来源：插件 Plugin.ExcelExport ｜ 读者：开发

两组：**A 组**违反就编译红/闸门红，**B 组**违反不报错、只出诡异现象。每条一律写成
`症状 → 机理 → 守门断言名`。

**先说清一件事**（决定了本页 B 组的分量）：`FlowCanvasChecks\` 里**没有任何针对 ExcelExport 业务逻辑的断言**
——全目录检索 `ExcelExport` 只命中 `HelpManualCheck.cs` 的档位表登记（`["ExcelExportPlugin"] = ManualTier.M`）。
所以 B 组那批 OOXML/CSV 细节**目前全部靠人工核对 + 真机抽点链接**，合并/移植时这一页就是唯一的网。
要补断言时，优先把 B1/B3/B4 那三条（漏写回 sheet、rels 的 Type、克隆错样式）做成"打开包看 XML"的静态断言。

## 一、A 组：违反就编译红 / 闸门红

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| 手册被"自动生成页"顶掉，用户看到的不是我们写的那份 | `Help\` 下没有 .md，或 csproj 没挂 `<EmbeddedResource Include="Help\**\*" />`（**没有全局 props 规则**，每个工程自己挂）；宿主 `HelpCatalogService` 按 `"<程序集名>.Help."` 前缀找资源，找不到就回退自动生成 | `HM1 每个插件类都有自带手册（无兜底自动生成页）`、`HM4 有 Help/*.md 的工程都带 EmbeddedResource（手册进得了 DLL）`（`FlowCanvasChecks\HelpManualCheck.cs`） |
| 手册进了仓库但 DLL 里没有资源，真机仍显示自动生成页 | MSBuild 增量判定不把"新挂上的内嵌资源项"当脏（R42）；构建报 0 错误也不代表打包成功 | 闸门只有静态一条（`HM4`）；**产物对账靠人工**：`tr '\0' '\n' < Modules\Plugin.ExcelExport.dll` 数 `.Help.` 资源名，必须等于 `Help\` 下 .md 数；稳妥做法收尾一次 `--no-incremental` |
| 页序乱、页名取不到 | 文件名不是 `NN-` 前缀（页序 = 资源名 Ordinal 序），或第一行不是 `# ` 一级标题（页标题就取它） | `HM6 手册文件名是 NN-xxx.md（页序确定）`、`HM5 每页第一行内容就是 \`#\` 一级标题（页名取得到）` |
| 开发章节混进用户册 / 用户页被整批挤掉 | 开发页判据是**文件名里的 `dev-` 段**（去掉 `NN-` 后以 `dev-` 起头）；另立 `Help\dev\` 子目录会把同插件的用户页挤掉 | `HM12 开发页文件名是 NN-dev-xxx.md（宿主认得出这是开发章节）`、`HM12b 手册最多一层目录（开发页另立子目录会挤掉用户页）`、`HM14 开发章节显隐链路四处齐全（标记→节点→裁树→开关→配置）` |
| 开发章节被当成随笔放行 | 本条目登记为 **M 档**，开发页合计行数下限 150；`HM13` 只在"已交开发页"时生效——交了就受约束 | `HM13 已交的开发章节达到所在档位的行数下限（L300/M150/S100，交了就不是随笔）`、`HM16 档位表与插件类一一对应（无未登记、无过期条目）` |
| 手册被当成占位页/编码坏 | 正文合计不足 70 行、带 BOM、非法 UTF-8、无中文，或出现 `HelpManualCheck.PlaceholderMarks` 里那批占位字样（未完成标记、"待…"类标记、省略式括注） | `HM8 每个插件的手册正文 ≥ 70 行（不是占位页）`、`HM7 手册都是无 BOM 的合法 UTF-8 且含中文（编码纪律）`、`HM9 手册里不许有占位标记（禁用字样清单见 HelpManualCheck.PlaceholderMarks）` |
| `[StepConfig]` 属性写成后备字段 + 手写 setter，或 partial 属性所在类没写 `partial` | 源生成器（`Shard\Core.PluginGenerators`）按约定生成实现与钩子声明，不满足约定报编译 Error **CPG0001~CPG0005**，不静默跳过 | 编译器诊断（无 gate 断言）；钩子**只写实现、不写声明**（声明由生成器产出），见 R18 |
| 生成器改动后运行的是旧插件 DLL | 生成物在插件 DLL 里编译期展开（R16）；与红线③"产物陈旧"同族 | 无断言，靠构建纪律（改 `Core.PluginGenerators` 必须重建全部插件工程） |

## 二、B 组：不报错，只出诡异现象

| 症状 | 机理 | 守门断言名 |
| --- | --- | --- |
| Excel 打开报表报"需要修复" | 改 zip 的三处（`sheet1.xml` / `sheet1.xml.rels` / `styles.xml`）**缺一处或顺序错**就坏包：`<hyperlinks>` 位置不合 schema、rels 的 `Type` 被写成 Clark 记法、CT_Font 子元素顺序错 | 无断言，靠人工核对（见第十节 10-dev-architecture 第五节的三条纪律） |
| 链接格显示成时间格式 | `cellXfs` 克隆错了对象——MiniExcel 默认**末位** cellXfs 是时间格式（`numFmtId=21`），必须克隆"数据格样式"（默认 `s="2"`，代码还会从该列实际数据格探一次） | 无断言，靠人工核对 |
| 关系建好了、单元格没变（点开不是图片） | 改过的 sheet 忘了写回条目表（`doc[sheetName] = …`），最后写包时用的还是旧 XML | 无断言，靠人工核对 |
| 显示名看不出是 png 还是 jpg | 用了 `GetFileNameWithoutExtension`；现在固定 `Path.GetFileName`（带扩展名） | 无断言，靠人工核对 |
| 整本报表是空的 / "只有表头？" | `MiniExcel.Query` 未显式给 `excelType: ExcelType.CSV`（默认按 xlsx 解析，CSV 会抛并被收成"导出异常"），或 `useHeaderRow` 漏了 | 无断言，靠人工核对 |
| 勾了「只导有图的行」但没过滤 | `OnlyRowsWithImage` 只在 `hasLinkColumn` 成立时生效，而该判定**只看第一条数据行的键集**；列名对不上时静默导出全量 | 无断言，靠人工核对（面板文本会提示"未找到列"，是唯一的线索） |
| 报表里链接数 M 远小于行数 | 单元格值不满足三条判据（非空 / 无非法路径字符 / `Path.IsPathRooted`），相对路径一律不建链接 | 无断言，靠人工核对 |
| 路径预览出现"未赋值" | `InstanceName` 由引擎注入、构造视图时还没有；`EffectiveStepName` 退回 `StepData.StepName`，并在视图 `Loaded` 时 `RefreshPreview()` 一次。少了这个回退，预览目录名就会带"未赋值"，而真跑又是另一条路径 | 无断言，靠人工核对 |
| 日期目录层级错位（`{yyyy-MM}` 被写成"2026-09-16"） | 占位符替换必须**长 token 优先**；顺序写反就出现截胡 | 无断言，靠人工核对 |
| 目录里残留 `.tmp` | 原子替换在 `File.Delete` + `File.Move` 之间被中断（磁盘/占用）；正常失败路径会删临时件 | 无断言，靠人工核对 |
| 报表"写不进但也没产出第二个文件" | 与「CSV记录」**故意不同**：那边被占用会旁路写 `_conflictN.csv` 保数据，这边占用即失败并提示"请先关闭"。别把它当 bug"顺手统一" | 无断言，靠人工核对（口径写在 04 第六节） |
| 产线莫名停了 | `BlockOnFailure` 默认 `false`；有人勾上后报表导不出就拦整条流程 | 无断言；配置口径见 01/03 页 |
| 流程日志里这一步什么都没留 | "不导出"分支静默 `return`，**连日志都不写**（刻意）。排查时先看导出方式档，别看日志有无 | 无断言，靠人工核对 |
| 界面卡在"正在导出…" | 手动导出在 `Task.Run` 里跑；`IsExporting` 是重入保护而非进度，长账本确实要几秒。若**永远**停在这句：先看结果文本有没有变成 `✘ 导出异常：…`（外层 catch 在，2026-10-20 起调度失败也会落终态）；两层 `catch` 都被删掉时才会出现"文本不动 + 按钮永久置灰" | `FlowEngineFixChecks` 的 `[EE4]` 五条静态断言（Task.Run 在外层 try 内 / 外层 catch 写 LastResult + 复位 IsExporting / 文案带类型名 / 内层 finally 仍在） |
| 跨线程改集合属性把界面搞崩 | 绑定引擎只把**标量**属性变更调度回 UI 线程；`ExportNow` 只发 `IsExporting`/`LastResult` 两个标量通知。以后加"已导出的行"这类集合属性要自己 marshal | 无断言，靠人工核对 |
| 导出成功但交付机报缺 `MiniExcel.dll` | 私有依赖靠 csproj 的 `CopyLocalLockFileAssemblies=true` + `PostBuild` 拷进 `$(ModulesDir)`；只拷插件 DLL 不拷依赖 = 运行期才炸 | 无断言；交付对账看 `Modules\MiniExcel.dll` 是否存在 |
| 报表样式改了颜色/字号 | 样式常量（`FF0563C1`、Calibri、11）写死在注入器里，界面**没有开关**；要改就改源码并接受"用户手册里那句'样式固定'要同步" | 无断言，靠人工核对 |

## 三、改这个工程必须连带的动作

| 改了什么 | 必须同步 |
| --- | --- |
| 端口名（`导出触发`）或 `[StepConfig]` 属性名 | `.vms` 的 `InputValues` 键随之变化，**老方案该项静默回落默认值**；同步《端口与参数》页的"界面标签 ↔ 属性名"表与《架构》页第七节的存盘键表 |
| 失败/成功消息文案 | 《排障》页的原文对照表要求**逐字一致**；改了源码不改表 = 那张表失效（现场照表排查会走偏） |
| 占位符集合 | 《端口与参数》第四节 + 《列映射与写入口径》第一节的默认路径示例 |
| 「导出方式」档位语义 | 《端口与参数》第五节 + 《列映射与写入口径》第七节的节拍结论 |
| `XlsxHyperlinkInjector` 的任一处 XML 结构 | 《列映射与写入口径》第五节 + 本页第二节；这类改动**必须真机打开一次报表**并抽点链接（无断言可依赖） |
| csproj 的依赖投递 | 交付清单（`Modules\MiniExcel.dll`）+ 本页 A 组的产物对账口径 |
| 插件源码或手册 | **重建插件工程**（`Modules\` 不由宿主工程带出，只重建宿主跑的是旧 DLL，红线③）；改过 `Core.PluginGenerators` 则重建全部插件工程（R16） |
| 大改动（公共契约/多模块） | 按 R12 闭环：评审 → 实现 → reviewer 审查 → `docs\code-changes\` 落记录；并按 R28 重建 CodeGraph 索引 |

## 四、移植清单（把这个算子搬到别的项目时）

1. **依赖**：MiniExcel 1.46.0（读 CSV **必须显式 `excelType`**；`EnableAutoWidth` 会抛、不支持公式与超链接）
   + 插件私有依赖投递方式（`CopyLocalLockFileAssemblies` + 拷到插件扫描目录）。
2. **上游约定**：CSV 表头行、UTF-8、RFC 4180 引号转义、图片列写**绝对路径**。链接列的判定只看首条数据行。
3. **样式索引假设**：注入器假设"表头 `s="1"`、数据格 `s="2"`"作为兜底值，但会先从该列实际数据格探一次 `s`；
   换 MiniExcel 版本或换写表库时要重新验证这两处（默认值、`cellXfs` 末位是时间格式）。
4. **OOXML 三条硬规矩**：rels 的 `Type` 纯 URI 字符串、CT_Font 子元素顺序、`<hyperlinks>` 的插入位置。
5. **失败契约**：报表是附属产物 → 默认不阻断生产；占用不旁路改名；改这两条要先改用户手册的口径句。
