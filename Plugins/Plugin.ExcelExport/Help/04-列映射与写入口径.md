# Excel报表 · 列映射与写入口径

> 分类：数据处理 ｜ 来源：插件 Plugin.ExcelExport

这页管四件事：**报表落在哪里**、**报表的列从哪来**、**图片列按什么口径变成链接**、**读写各自的口径**。
判据全部取自插件源码，界面与日志里的消息原文见《排障》页。

## 一、落点与轮转

| 东西 | 落在哪 | 备注 |
| --- | --- | --- |
| 读：源账本 | `账本路径` 模板展开后的绝对路径，默认 `D:\Records\{源步骤}\{yyyy-MM}\{yyyy-MM-dd}.csv` | **只读**，不动它；目录不存在/文件不存在都不创建 |
| 写：报表 | `输出目录` + `报表文件名`，默认 `D:\Records\{StepName}\{yyyy-MM}\报表\{yyyy-MM-dd}_报表.xlsx` | 输出目录自动创建；文件名没写 `.xlsx` 会自动补 |
| 临时件 | 同目录 `.tmp`，成功即原子替换、失败即删除 | 正常情况**看不到**残留 `.tmp`；看到残留说明改包环节被中断过 |
| 历史报表 | 默认按天一个文件名 → 自然形成"每天一份快照" | 同一天重复导 = **覆盖**，不是追加 |

**快照语义**：报表是"导出那一刻的账"。账本后来又长了行，老报表不会自己变——要新的就再导一次
（同名会覆盖当天那份）。要留历史就别在同一天重复导，或把文件名模板改成带时分秒。

## 二、报表列的来龙去脉（字段名对应关系）

报表**不做列映射、不改名、不排序**，列就是账本的列：

```
算子的输出端口名        CSV 的列名（= 表头）        报表的列名
Blob.IsOk        ──▶   「结果」(来源=端口)    ──▶   结果
卡尺.MeasureValue ─▶    「宽度」(格式 F3)     ──▶   宽度
内置:图片路径      ──▶   「图片路径」          ──▶   图片路径（变成可点击的短文件名）
内置:时间戳        ──▶   「时间」              ──▶   时间
```

三条口径：

- **列名要逐字对上**。报表里想要哪一列叫什么，就去「CSV记录」把那一列的**列名**改成什么；
  「图片走这里」填的也是**列名**（不是列号、不是别名列标题），默认 `图片路径`，区分大小写。
- **值的长相由上游决定**。账本里是文本，报表就照抄文本；数值列的位数在「CSV记录」的「格式」里定（如 `F3`），
  本算子不重新格式化、不做单位换算。
- **列序 = 账本表头序**。写 xlsx 时的列顺序由读到的字典键序决定，而键序就是 CSV 表头顺序；
  想调报表列顺序，去调「CSV记录」里列的上下顺序。

## 三、"列存在不存在"是怎么判的

一个容易忽略的口径：**是否有链接列，只看账本的第一条数据行**。

```
有链接列 = 『图片走这里』非空 且 第一条数据行里含这个键名
```

后果：

- 列名打错一个字母 → 判为"没有该列" → 报表正常导出成纯表格（不报错），结果文本会告诉你"未找到列"。
- 「只导有图的行」**依赖这一列被判定存在**；判定不成立时过滤整条跳过，导出全量。
- 账本中途改过列定义（加列/删列）会让行与表头对不齐——那是上游的问题，本算子照表头读，
  多余的列丢、缺的列读成空。改列定义后建议归档旧账本（见「CSV记录」的说明）。

## 四、读账本的口径

- 按 **CSV** 解析（不是 xlsx），**第一行当表头**；只有表头没有数据行 → 直接失败并说明"只有表头？"。
- 认「CSV记录」的整套约定：UTF-8、逗号分隔、**RFC 4180 引号转义**（含逗号/空格/引号的路径能正确读出来，
  链接里会被百分号编码成合法的 `file:///`）。
- **账本被 Excel 独占打开着也能读**（读的是账本，写的是报表）；被独占的是**报表**时写不进去，报"请先关闭"。
- 读出来的每行是"列名 → 值"的字典，值一律是文本形态进入报表，本算子不做二次解析。

## 五、图片列变链接的口径

链接不是"看图嵌图"，而是把单元格文本换成一个指向磁盘原图的外部超链接：

| 环节 | 口径 |
| --- | --- |
| 哪些单元格会被改 | 只有「图片走这里」那一列的数据格（表头格不动） |
| 什么样的值才算 | 去空格后**非空**、**不含非法路径字符**、**是绝对路径**（`Path.IsPathRooted`）三者同时满足 |
| 不算的怎么办 | 保持原文（一长串路径），不挂链接样式、不建关系；这种行在勾了「只导有图的行」时会被整行过滤掉 |
| 链接目标 | 绝对路径转成 `file:///` URI；转不成 URI（例如相对路径）就跳过该行 |
| 单元格显示什么 | **文件名（带扩展名）**，如 `12_NG.png`——完整路径藏在链接目标里，报表才紧凑；保留扩展名是为了分得出 png 还是 jpg |
| 外观 | 蓝色下划线、Calibri、字号 11；样式是**克隆本列数据格原样式**再换字体，所以链接格和普通格观感一致 |
| 处理范围 | **只处理第一个工作表**（sheet1），多 sheet 报表不支持 |

**为什么有的单元格还是长长一串路径**：那格的路径被判为"不能作链接目标"（空、相对路径、含非法字符），
于是保持原文。这是刻意行为——宁可不建链接，也不产出一个点开是"找不到文件"的假链接。

## 六、写文件的口径

| 口径 | 具体行为 |
| --- | --- |
| 覆盖语义 | 目标存在就整份重写（不是追加行）；所以同一天重复导 = 覆盖当天那份快照 |
| 原子替换 | 注入链接时先写同目录 `.tmp`，整包成功才删旧件并改名；任何一步失败都删掉临时文件，**不留半个损坏的报表** |
| 失败不旁路改名 | 这点和「CSV记录」不同——那边被占用会写 `_conflictN.csv` 保数据，这边写不进（报表正被 Excel 打开）就直接失败并提示"请先关闭"，**不会**给你产出第二个文件 |
| 不写包的情况 | 一行的可用链接都没有时，直接返回 0 且不重写压缩包——报表保持刚写出来的样子（不会出现"有蓝色字体但没有链接"的中间态） |
| 打开报表 | 「导出后打开报表」用系统默认程序打开，打开失败**不影响导出结果**，只另写一条 WARN |

## 七、性能与节拍

| 场景 | 表现 |
| --- | --- |
| 仅手动导出 | 不占产线节拍（在配置面板点，后台线程跑，几万行也不卡界面） |
| 触发端口 / 每次执行 | **在流程线程里同步完成**读账本 + 写报表 + 改包：几万行的账本会明显拖这一拍的节拍 |
| 高频循环流程 | 「每次执行都导」= 每次都重写整本报表，慎用；要挂在流程里请用「触发端口」（收工信号） |

结论：**要节拍就只在收工时导一次**；要历史快照就按天留文件，不要按件导。
