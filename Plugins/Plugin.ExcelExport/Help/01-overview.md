# Excel报表

> 分类：数据处理 ｜ 来源：插件 Plugin.ExcelExport

把「CSV记录」写出的**流水账**加工成**给人看的 xlsx 报表**：首行冻结、能筛选排序，
最关键的是——图片那一列不再是一长串路径，而是蓝色下划线的**短文件名**（如 `12_NG.png`），
点一下就用系统看图软件打开磁盘上的高清原图。

## 为什么需要它 / 原理

CSV 账本机器读得懂、人看着累；而产线上**边测边写 xlsx 是错的**：写 Excel 要整份重写、还得防 Excel 占用，
代价高且没意义（机器不看报表）。所以本算子是**事后导出**——人要看的时候再导，报表就是"当时那份账"的快照。

```
CSV 账本（D:\Records\流程1.CSV记录\2026-09\2026-09-16.csv）
   ↓ ① 读账本（MiniExcel，必须按 CSV 解析、表头行当列名）
   ↓ ② 可选过滤：只保留"图片列有有效绝对路径"的行
   ↓ ③ 写数据 xlsx（列序 = CSV 表头序；冻结首行 + 自动筛选；先写 .tmp 再原子替换）
   ↓ ④ 改写 xlsx 内部的 zip 三处，把图片路径列变成可点击超链接
报表（D:\Records\流程1.Excel报表\2026-09\报表\2026-09-16_报表.xlsx）
```

三条要记住的取舍：

- **报表里没有图片二进制**，只有指向磁盘原图的 `file:///` 链接。好处是文件小、能筛选排序；代价是**原图被删/挪走链接就断**。
- **上游是"文件"不是"连线"**：本算子不接端口数据流，它读 CSV。所以它的上游是「CSV记录」的**产物**。
- **缺列就降级**：找不到「图片走这里」指定的列，不报错，导出成纯表格（报表照样可用）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `导出触发` | 否 | 布尔。只有「导出方式」= `触发端口` 时生效：为 `true` 的那一次执行才导出。不连线不算「参数缺失」 |

本算子**没有动态端口**（它读文件，不像「CSV记录」按列长端口）。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `报表路径` | 本次导出的 xlsx 完整绝对路径；失败时为空串 |
| `导出行数` | 本次写进报表的**数据行数**（不含表头）；被"只导出有图行"过滤过的就是过滤后的数 |
| `Success` / `ErrorMessage` | 基类契约（默认 `BlockOnFailure=false`，导出失败时本步骤仍然算成功） |

> 面板上点「立即导出」（手动导出）也会回写这两个端口，方便你在下游或日志里看到最近一次报表路径。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 源账本路径模板 `SourcePathTemplate` | `D:\Records\{源步骤}\{yyyy-MM}\{yyyy-MM-dd}.csv` | 与「CSV记录」的默认目录/文件名严格对齐，**开箱就能命中账本**。占位符见下表 |
| 源步骤名 `SourceStepName` | `""`（空） | `{源步骤}` 展开成它。**填的是上游 CSV 记录步骤的名字**；留空则退回用本步骤自己的名字 |
| 报表输出目录模板 `OutputDirectoryTemplate` | `D:\Records\{StepName}\{yyyy-MM}\报表\` | 默认单独放 `报表\` 子目录，避免污染账本目录。`{StepName}` 是**本步骤**的名字 |
| 报表文件名模板 `ReportFileNamePattern` | `{yyyy-MM-dd}_报表.xlsx` | 没写 `.xlsx` 会自动补上；留空回落到 `{今天}_报表.xlsx` |
| 图片走这里 `LinkColumn` | `图片路径` | 要做成超链接的**列名**（名字，不是位置）。与「CSV记录」的内置字段列同名，所以开箱即用 |
| 冻结首行 `FreezeHeader` | `true` | 滚动时表头不跑 |
| 自动筛选 `AutoFilter` | `true` | 首行下拉筛选（按结果/日期筛 NG） |
| 只导出有图行 `OnlyRowsWithImage` | `false` | 只保留「图片走这里」那列是**有效绝对路径**的行（抽检看 NG 图时用） |
| 导出方式 `ExportPolicy` | `仅手动（点按钮才导）` | 三选一：`仅手动` / `触发端口（收到信号才导）` / `每次执行都导` |
| 导出后打开报表 `OpenAfterExport` | `false` | 用系统默认程序打开。仅手动导出时建议勾；自动导出时勾了会让 Excel 占住文件，反过来影响下次导出 |
| 导出失败阻断流程 `BlockOnFailure` | `false` | **默认不阻断**（宁漏报表不停线）。要"报表出不了就停线"才勾 |

**占位符（这两个最容易搞混）**

| 占位符 | 展开成 |
| --- | --- |
| `{源步骤}` | **上游「CSV记录」步骤**的名字（来自 `SourceStepName`，留空时等于本步骤名） |
| `{StepName}` | **本 Excel 报表步骤自己**的名字 |
| `{yyyy}` `{yyyy-MM}` `{yyyy-MM-dd}` `{MM}` `{dd}` `{yyyy-MM-dd HH-mm-ss}` | 导出**那一刻**的日期。只有"今天那份账"，没有"时间范围"参数 |

> 步骤名的口径：运行期取引擎注入的实例名（`流程名.步骤名`，如 `流程1.CSV记录`）；在配置面板里预览时还没注入，
> 会退回步骤名本身——所以面板显示的路径和真跑时可能差一个"流程名."前缀，以真跑为准。

## 口径与失败策略

- **不导出时静默通过**：导出方式=仅手动/触发端口而本次不该导，`RunAlgorithm` 直接返回、**连日志都不写**（高频流程里刷日志会淹没真正的问题）。
- **默认不阻断生产**：报表是给人看的附属产物，失败只写 WARN；勾了 `BlockOnFailure` 才让本步骤失败。
- **失败不旁路改名**：这点和「CSV记录」不同——那边被占用会写 `_conflictN.csv` 保数据，
  这边写不进（报表正被 Excel 打开）就直接失败并提示"请先关闭"，**不会**给你产出第二个文件。
- **原子替换**：先写 `.tmp`，全部成功才替换正式文件；任何一步失败都删掉临时文件，**不留半个损坏的报表**。
- **链接只认绝对路径**：单元格里是相对路径、空串、含非法路径字符的，一律跳过（保持原文，不做链接）。
  「CSV记录」写进去的是绝对路径，正常链路没问题。
- **列序 = 账本表头序**：不做列映射，也不排序；想改报表列序就去改「CSV记录」的列定义顺序。
- **只处理第一个工作表**（sheet1）；报表样式固定（超链接字体 Calibri、字号 11、蓝色下划线，不可配）。
- **手动导出在后台线程跑**：几万行也不卡界面；有重入保护（上一次没结束前再点按钮不响应）。

## 典型用法 / 接线

```
① 标准链路（事后导出，推荐）
采集 ──▶ 检测 ──▶ CSV记录（写账本，含「图片路径」列）
                        ↓ 收工时
                    Excel报表（导出方式=仅手动 → 面板点「立即导出」）
                        └─▶ 报表路径 ──▶ 日志/下游可读

② 收工自动出报表
CSV记录 ─▶ Excel报表（导出方式=触发端口，收工信号 ─▶ 导出触发.端口）

③ 只看 NG 图（抽检）
Excel报表：只导出有图行 = 勾选，图片走这里 = 图片路径
        → 账本里图片列为空的行（合格件）不进报表

④ 与结果上报并列
CSV记录 ──▶ Excel报表（人看）
        └─▶ 结果上报（MES 看）
```

**源步骤名怎么填**：去「CSV记录」那一步看它的步骤名（或看它的默认账本路径里的目录名），
逐字抄进「源步骤名」。面板上会**实时显示"实际读取 → 路径"和"账本已找到 / 账本不存在"**，填错当场就能发现。

## 常见问题

**Q：报表里真的有图片吗？**
没有。只有指向磁盘原图的超链接，单元格显示短文件名。这是刻意取舍——嵌图会让报表体积暴涨且没法筛选排序。

**Q：点链接打不开？**
① 原图被删除或挪走了（`KeepDays` 清理过、或手工搬过相册）；② 账本里那格是**相对路径**（会被跳过，压根不会生成链接）；
③ 链接是在别的机器上生成的。

**Q：图片列没变成蓝色链接？**
按这条链查：账本里**有没有一列的名字逐字等于**「图片走这里」（默认 `图片路径`，区分大小写）；
「CSV记录」是不是真的存了图（不存图时那列是空串）；那一格是不是绝对路径。
导出结果文本会告诉你结论：`未找到列『图片路径』，导出为纯表格` / `没有可用的绝对图片路径，未生成链接`。

**Q：`只导出有图行` 勾了却没过滤？**
过滤依赖「图片走这里」那一列**存在**。列不存在时过滤不生效（导出全量），并提示未找到列。先把列名对上。

**Q：账本找不到？**
面板会红字提示「账本不存在（检查『源步骤名』是否与 CSV 记录步骤一致）」。三种原因：`源步骤名` 填错（最常见）、那一天还没产生账本、
上游把 `记录目录模板` 改过（比如去掉了 `{yyyy-MM}` 层）。改完看面板的"实际读取"预览行确认。

**Q：Excel 打开报表说"需要修复"？**
报表是改写 xlsx 内部 zip 生成的，出现这句说明包结构被改坏了：
① 用的是不是本插件产出的文件（别拿别的工具二次另存过的）；② 是否只重建了宿主没重建插件工程（跑的是旧 DLL）。

**Q：能导出昨天/上周/指定时间范围吗？**
不能。日期占位符只按**导出那一刻**展开，即"今天那份账"。要历史报表，就把 `源账本路径模板` 里的
`{yyyy-MM-dd}` 换成具体日期导一次（或者上游按天留着的文件本身就在，直接打开 CSV）。

**Q：每次执行都导会怎样？**
每次都**重写整本报表**（读全账本 + 写 + 改包）。只适合"一个班次只跑一次"的报表流程；高频循环流程慎用。
真要挂在流程里，用「触发端口」。

**Q：报表出错了，产线会停吗？**
默认**不会**（`BlockOnFailure=false`，宁漏报表不停线），只留一条 WARN。要停线自己勾上。
