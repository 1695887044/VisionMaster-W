# 坐标变换 · 快速上手

> 分类：定位 ｜ 来源：插件 Plugin.PoseTransform

一句话：这个算子把**定位结果**变成**下游能用的东西**——要么把"画在模板图上的 ROI"跟着工件搬到当前图上，
要么把图像坐标（+角度）经标定换算成机械坐标（mm、度）。它补的是"定位 → 测量"和"定位 → 执行"之间的最后一公里。

> 本页只管跑通第一次。界面每个区做什么见《界面与操作》；端口与参数逐个说明见《端口与参数》；
> 为什么这样算、四类失配怎么设计的见《变换口径与标定消费》；出问题照《常见问题与排障》逐条对。

## 先选模式

| 你的下游要什么 | 选哪个模式 | 界面显示 | 流程里存的值 |
| --- | --- | --- | --- |
| 一个"现在该看哪"的检测区域（给 Blob 缺陷检测、多特征测量） | 位姿跟随 | `位姿跟随` | `FollowRoi` |
| 一组毫米坐标（给运动节点、CSV 记录、结果上报、机器人抓取） | 像素→机械 | `像素→机械` | `ToMechanical` |

两个模式**共用同一个算子实例、互不干扰**：切换只影响界面与执行分支，不会清掉另一种模式已填的参数。
所以可以先把两边都配好，来回切着对比。

## 路线 A：位姿跟随（把 ROI 搬到当前图）

**需要的上游**：一个「ROI」算子（在模板图上画的框）+ 一个「模板匹配」算子（给当前位姿）。

1. **在模板图上画基准 ROI**：用「ROI」算子在**模板图 / 学习图**上框好要检测的区域。
   ⚠ 这是全流程最容易错的一步——基准 ROI 的坐标属于**模板坐标系**，画在别的图上基准本身就偏了，
   跟随结果会**系统性偏移**（每次偏一样的量，看着像"算法不准"）。
2. 把「坐标变换」拖进流程，模式选**位姿跟随**。
3. 接三个位姿输入：`PoseRow` / `PoseCol` / `PoseAngle` ← 「模板匹配」的 `Row` / `Column` / `Angle`。
   **角度单位是度**，匹配插件给的也是度，直接接，不要自己换算弧度。
4. 接区域输入：`BaseRegion` ← 「ROI」算子的 `MaskRegion`。
5. 模板参考点：**保持默认**（`模板参考点由基准 ROI 中心派生` 勾着）就行。
   只有当"基准 ROI 的中心并不是位姿原点"时才动它——例如 ROI 偏在一角、真正的原点吸盘中心：
   取消勾选，点**取基准 ROI 中心**一键填，或手工填 `TemplateRefRow` / `TemplateRefCol`。
6. 打开这个步骤的配置对话框，在「⑥ 预览图」卡片里点**浏览**选一张模板图。
   画布出现**绿色基准轮廓**和**黄色参考点十字**。
7. **试运行一次，做一次自检**：喂一组"模板态"位姿（位姿 = 模板参考点、角度 = 0），
   画布上的**橙色跟随轮廓必须与绿框完全重合**。
   不重合就说明第 1 步或第 5 步错了，先别往下接线。
8. 看信息栏下面那行面积提示：形如 `跟随面积 3120px²（相对基准 +0.02%）`。
   刚体变换不缩放，正视平面下这个百分比应当**接近 0**；偏差明显说明位姿来源可疑
   （接错上游、或上游匹配到了另一件工件）。
9. 接下游：`FollowedRegion` → 「Blob 缺陷检测」的 `MaskRegion`（或任何吃 `HRegion` 的下游）。

**跑通后该看到**：`Success` 为真、`ErrorMessage` 为空；画布上橙框跟着工件走；
日志一行 `位姿跟随：基准面积 …px² → 跟随面积 …px²（±X%）`。

### 可选：输出对齐图

需要"把当前图搬回标准位姿"时（下游算子的 ROI 是内部固定的），勾**输出对齐图**并把 `SrcImage` 接上图像源。

- 不接 `SrcImage` 时**不算失败**：只记一条 `未接 SrcImage：跳过输出对齐图` 的日志，跟随 ROI 照常给。
- 有了「模板匹配」的 `AlignedImage` 就**不必**在这里再开对齐图——两者等价，这里多一次重采样而已
  （选型表见《变换口径与标定消费》）。

## 路线 B：像素→机械（换算成毫米）

**需要的上游**：一个「标定」算子（`Transform` 输出）+ 一个给像素点的定位算子。

1. 模式选**像素→机械**。
2. `Transform` ← 「标定」插件的 `Transform` 输出。
   **只能这样来**：界面不提供手填矩阵的入口，标定数据必须有单一事实源。
   九点 / 透视 / 网格三种标定都支持，**各自还有"已去畸变"版本**（标定数据带相机内参时）；
   **只有像素当量的标定不行**（它不含机械坐标系）。
3. `PixelPointRow` / `PixelPointCol` ← 「模板匹配」的 `Row` / `Column`（要换算的那个点，通常是目标中心）。
4. 需要机械角时才接 `PixelAngle` ← 「模板匹配」的 `Angle`：**接了才会输出 `MechanicalAngle`**，
   没接时那个端口保持 0（是"没给"，不是"算出来是 0"）。
5. **建议**把 `SrcImage` 接上图像源：让"换了分辨率忘了重新标定"当场失败，
   而不是算出一个看着挺合理的错坐标。
6. 多相机时接 `SourceSerial` ← 「图像采集」的 `SourceSerial`，并确认标定步骤里填的是同一台相机的序列号。
7. 看「⑤ 标定信息」只读块：类型 / 来源 / 相机序列号 / 标定图尺寸 / 创建时间 / 残差；
   **标定带内参时这一行末尾还会多出"内参：模型 / 系数 / 重投影 RMS / 图数 ｜ 去畸变已启用"**
   （看到它就知道当前像素已经换算到理想针孔坐标系了）。
   **红字 = 已经失配**（这份标定和当前预览图尺寸对不上），橙字 = 残差偏大（超过 1 像素）。
8. 试运行：读 `MechanicalX` / `MechanicalY`（接了角度时还有 `MechanicalAngle`），
   以及 `PixelEchoRow` / `PixelEchoCol` 两个回显端口。

**跑通后该看到**：日志一行形如 `像素 (512.4, 780.1) → 机械 (405.123, 307.884)mm，机械角 29.996°`
（透视/网格会标注类型，"已去畸变"的标定会标注成"九点标定（已去畸变）"等）；
`PixelEchoRow` / `PixelEchoCol` **应当几乎等于你接进去的 `PixelPointRow` / `PixelPointCol`**
——插件内部已经把它们比对过，偏差超过容差就直接判失败，不会把对不上的结果交给你
（不带内参的标定与 `division` 模型是 `0.000001px`，`polynomial` 模型是 `0.001px`，理由见排障页）。

## 接线图（两条路线一起看）

```
── 位姿跟随（保留原图坐标，只搬 ROI/点）
ROI.MaskRegion（画在模板图上）────────▶ 坐标变换.BaseRegion
模板匹配.Row / Column / Angle ───────▶ 坐标变换.PoseRow / PoseCol / PoseAngle
坐标变换.FollowedRegion ─────────────▶ Blob 缺陷检测.MaskRegion

── 像素→机械（机器人抓取 / 贴合 / 记录）
标定.Transform ─────────────────────▶ 坐标变换.Transform
模板匹配.Row / Column ──────────────▶ 坐标变换.PixelPointRow / PixelPointCol
模板匹配.Angle ─────────────────────▶ 坐标变换.PixelAngle        （需要机械角才接）
图像采集.OutputImage ────────────────▶ 坐标变换.SrcImage          （建议接：换分辨率当场失败）
图像采集.SourceSerial ──────────────▶ 坐标变换.SourceSerial      （多相机才必接）
坐标变换.MechanicalX / Y / MechanicalAngle ─▶ 运动控制 / CSV记录 / 结果上报
```

## 上线前建议做的四项验收

- **模板态自洽**：位姿 = 参考点、角度 0 时跟随 ROI 与基准 ROI 重合（面积相对差为 0）；
- **面积保持**：跟随前后 ROI 面积差接近 0%（正视平面）；
- **人为旋转验证**：拿一张图人为转 30°（或用工装转 30°），确认跟随 ROI 的角度与位置都对；
- **回算比对示教器**：取 3 个已知机械位置的特征点，经本插件换出 X/Y，与示教器读数比对
  （口径建议 **±0.5mm 或 ±1 像素当量，取大者**）。

再加一条**失败面验证**（很重要）：故意断开 `Transform`、故意换一张不同分辨率的图，
确认流程是**明确失败**而不是给出错值——此时下游读到的是每轮开头清零的值（0），
而不是上一轮的好值。这一条能同时验掉"失配有没有被糊过去"和"清零有没有做"。
