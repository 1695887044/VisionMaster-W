# 坐标变换 · 端口与参数

> 分类：定位 ｜ 来源：插件 Plugin.PoseTransform

本页逐个列出口与配置项：**名字、类型、必填性、接不上会怎样**。
"必填"这一列有个统一前提——**所有端口的必填性都按模式判定**，所以端口声明一律是"非必填"，
真正的把关在运行时（见下面的说明）。

## 一、为什么界面上"一个都不标红星"

本插件有两种模式，两种模式各用一批端口。若把 `BaseRegion` 声明成必填，
那么"像素→机械"流程会因为没接跟随用的 ROI 而**编译不过**——这显然不对。
所以 12 个输入端口在声明处**全部为 `IsRequired = false`**，必填性交给运行时的模式分支把关：

| 模式 | 真正必须的输入 | 缺失时的失败文案 |
| --- | --- | --- |
| 位姿跟随 | `BaseRegion` + 位姿三项（有效值） | `基准 ROI 为空：请把 ROI 插件的 MaskRegion 接过来（并在模板图上画好基准）` |
| 像素→机械 | `Transform` + `PixelPointRow` / `PixelPointCol` | `未接标定：请把「标定」插件的 Transform 输出接到本步骤` |

**后果要知道**：接错模式（比如选了位姿跟随却没接 `BaseRegion`）**在编译流程时不会提醒你**，
要跑到那一步才失败。判断更早的办法是看配置界面的信息栏——它是同一批判据，开着对话框就会立刻提示"还差什么"。

## 二、输入端口

| 端口 | 类型 | 用在哪 | 默认 | 接不上 / 不接会怎样 |
| --- | --- | --- | --- | --- |
| `SrcImage` | `HImage` | 两个模式（用途不同） | 无 | **不接也能工作**。位姿跟随：勾了「输出对齐图」却没接 → 只记一条 `未接 SrcImage：跳过输出对齐图`，跟随 ROI 照常给；像素→机械：不接就**跳过图像尺寸失配校验**（换分辨率不会当场失败） |
| `BaseRegion` | `HRegion` | 位姿跟随 | 无 | 位姿跟随下不接 → 失败：`基准 ROI 为空…`。接的必须是**画在模板图上**的那个框（接 `MaskRegion`） |
| `TemplateRefRow` | `double` | 位姿跟随 | `0` | 只在**取消勾选**「模板参考点由基准 ROI 中心派生」时才被读；勾选状态下填什么都不生效 |
| `TemplateRefCol` | `double` | 位姿跟随 | `0` | 同上。两项都是 `NaN`/`Inf` → `模板参考点无效（NaN/Inf）：请点「取基准 ROI 中心」或手工填写`；两项**同时为 0** → `模板参考点为 (0,0)：…` |
| `PoseRow` | `double` | 位姿跟随 | `0` | ← 「模板匹配」的 `Row`。与下面两项**全为 0** 判无效：`位姿为 (0,0,0)：多半是模板匹配失败或位姿未接——请检查上游位姿来源` |
| `PoseCol` | `double` | 位姿跟随 | `0` | ← 「模板匹配」的 `Column` |
| `PoseAngle` | `double` | 位姿跟随 | `0` | ← 「模板匹配」的 `Angle`（**单位度**，匹配插件给的也是度）。角度本身允许 0（正对时就是 0），但三项同时为 0 会被判无效 |
| `Transform` | `CalibrationTransform` | 像素→机械 | `null` | ← **「标定」插件的 `Transform` 输出**。不接受手填矩阵（单一事实源）。支持九点/透视/网格三类，**只有像素当量的标定不行** |
| `SourceSerial` | `string` | 像素→机械 | 空串 | ← 「图像采集」的 `SourceSerial`。**与标定记录的非空序列号都填且不匹配**才判失败；任一端为空则不检查 |
| `PixelPointRow` | `double` | 像素→机械 | `0` | ← 「模板匹配」的 `Row`（要换算的那个点）。`NaN`/`Inf` → `待换算的像素坐标无效（NaN/Inf）——请检查上游（模板匹配是否成功）`；与 `PixelPointCol` **同时为 0** → `待换算的像素点为 (0,0)：…` |
| `PixelPointCol` | `double` | 像素→机械 | `0` | ← 「模板匹配」的 `Column` |
| `PixelAngle` | `double` | 像素→机械 | `0` | ← 「模板匹配」的 `Angle`（度）。**接了（或有非零值）才换算并输出 `MechanicalAngle`**；没接时那个端口是 0，含义是"没给"而不是"结果是 0°" |

所有输入端口值类型是 `double` 的，都**不接受 `NaN` / `Inf`**，也不接受"全零"这种默认值形态
——理由见《变换口径与标定消费》第四节。

## 三、输出端口

| 端口 | 类型 | 什么时候有值 | 典型下游 |
| --- | --- | --- | --- |
| `FollowedRegion` | `HRegion` | 位姿跟随成功时 | 「Blob 缺陷检测」的 `MaskRegion`、任何吃区域的下游 |
| `FollowedImage` | `HImage` | 位姿跟随 + 勾了 `EmitFollowedImage` + 接了 `SrcImage`，三者齐了才有 | 内部 ROI 固定的算子（卡尺/颜色/OCR） |
| `MechanicalX` | `double` | 像素→机械成功时 | 运动控制节点 / CSV 记录 / 结果上报 |
| `MechanicalY` | `double` | 同上 | 同上 |
| `MechanicalAngle` | `double` | 像素→机械成功**且**给了像素角度时；归一化到 `(−180, 180]` | 抓取、贴合、姿态补偿 |
| `PixelEchoRow` | `double` | 像素→机械成功时 | **自校验用**：应当几乎等于你接进 `PixelPointRow` 的值 |
| `PixelEchoCol` | `double` | 同上 | 同上 |

另有基类提供的两个通用输出：`Success`（`bool`）与 `ErrorMessage`（`string`）——
**任何失败都必须同时把这两个摆正**，下游"取分支/记录错误"靠的就是它们。

### 失败时输出端口是什么状态（重要）

本步骤失败时，**不会留上轮的残留值**：

- 五个 `double` 输出（`MechanicalX` / `MechanicalY` / `MechanicalAngle` / `PixelEchoRow` / `PixelEchoCol`）
  在每轮**开头**就被清零，失败轮下游读到的是 `0`；
- 跟随的两个产物**必须全部算成功才写端口**：中途异常时已算出的区域/图像会被就地释放，
  `FollowedRegion` / `FollowedImage` 保持未输出状态。
  ——不会出现"图是 A 位姿、ROI 是 B 位姿"这种看不出来的组合。

所以**看到下游拿到 0 或空，先回来看本步骤的 `ErrorMessage`**，别怀疑下游。

## 四、配置项（随步骤存盘）

| 配置 | 界面 | 类型 | 默认 | 改了影响什么 |
| --- | --- | --- | --- | --- |
| `Mode` | 卡片 ① 的二选一（`位姿跟随` / `像素→机械`） | 枚举 `TransformMode` | `FollowRoi` | 切界面 + 切执行分支。**不清空另一种模式已填的参数**。存的是成员名 `FollowRoi` / `ToMechanical`，界面显示中文 |
| `EmitFollowedImage` | `输出对齐图（把当前图重采样回模板参考位姿）` | `bool` | `false` | 开 → 每轮多一次图像重采样 + 一次内存拷贝，产出 `FollowedImage`。只要跟随 ROI 时保持关 |
| `TemplateRefFromRegionCenter` | `模板参考点由基准 ROI 中心派生` | `bool` | `true` | 开 → 参考点直接取基准 ROI 中心（`AreaCenter`），**不用手填两个数**；关 → 用 `TemplateRefRow` / `TemplateRefCol` 的值，并对 `(0,0)` / `NaN` 把关 |
| `PreviewImagePath` | 「⑥ 预览图」的路径框（或**浏览**） | `string` | 空 | **完全不参与运行**，只影响配置界面的叠加底图。存的是绝对路径，换机器后失效属预期（会提示"预览图不存在"） |

### 界面状态（不存盘）

这几个是配置界面用的，关掉对话框就没了，也不进流程：
`DisplayImage`（叠加预览图）、`StatusMessage` + `StatusLevel`（信息栏一行与颜色）、
`CalibrationInfoText` + `CalibrationInfoLevel`（标定信息块与颜色）、`FollowedInfoText`（跟随面积一行）。

## 五、类型口径速查

| 口径 | 值 |
| --- | --- |
| 角度单位 | **度**（端口、界面、存盘全是度；只在调 HALCON 时内部转弧度） |
| 长度单位 | 像素（图像侧）/ **毫米 mm**（机械侧） |
| 机械角范围 | 归一化到 **`(−180, 180]`**（左开右闭：`−180` 会显示成 `+180`） |
| 回显自校验阈值 | `1e-6` 像素（不带内参的标定）；带内参时**按畸变模型分档**：`area_scan_division` → `1e-6`、`area_scan_polynomial` → `1e-3` |
| 残差提醒阈值（仅界面橙字） | `1.0` 像素 |
| 相机序列号比对 | 忽略大小写，两端都非空才比 |
| 图像尺寸比对 | 标定没记尺寸（两个 0）时放行 |
| 坐标轴习惯 | HALCON 系：**先 Row（垂直）后 Col（水平）**；机械侧 `X` / `Y` 由标定矩阵决定谁对应谁 |
