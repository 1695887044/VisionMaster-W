# 坐标变换

> 分类：定位 ｜ 来源：插件 Plugin.PoseTransform

两个模式共用一套纪律：**位姿跟随**把"画在模板图上的 ROI"跟着当前位姿搬到当前图上；
**像素→机械**把图像坐标（+角度）经标定变换换成机器人/运动轴能用的机械坐标（mm、度）。
它补的是"定位 → 测量 / 定位 → 执行"之间的最后一公里。

## 为什么需要它

模板匹配给的是**当前图里**的目标位姿，但检测区域是**在模板图上画的**，下游算子（Blob、引导、机械手）
要的是"现在该看哪"和"现在在第几毫米"。这一步不做的话，只有两种坏结果：
ROI 固定在模板位置（工件一动就漏检），或者拿像素当毫米用（换镜头/换工作距离就整体错）。

## 原理

1. **位姿跟随**（刚体变换作用在区域上）
   ```
   vector_angle_to_rigid(模板参考点, 0° → 当前位姿, θ) → HomMat2D   // 模板坐标系 → 当前坐标系
   affine_trans_region(基准 ROI, HomMat2D, "nearest_neighbor")      → 当前坐标系下的 ROI
   ```
   基准 ROI 的坐标属于**模板坐标系**（跟随公式从"模板参考位姿"出发），所以它必须画在模板/学习图上。
   自检口径：当位姿 = 模板参考点且角度 0（目标就在学习时的位置）时，变换是恒等的，
   跟随 ROI 必须与基准 ROI **完全重合**。
2. **可选的对齐图**（`EmitFollowedImage`）：把**当前图**反向重采样回模板参考位姿
   （`vector_angle_to_rigid(位姿,θ → 参考点,0)` + `affine_trans_image(..., "bilinear", "false")`）：
   目标回到"学习时的位置"、画幅不变、出界填黑。注意图像走的是**逆变换**，与 ROI 的方向相反。
3. **像素 → 机械**：按 `Transform.Kind` 分派——
   九点（仿射 6 元）`X = a11·Row + a12·Col + a31`、`Y = a21·Row + a22·Col + a32`；
   透视（投影 9 元，做透视除法，w≈0 明确失败）；网格（三角化定位 + 重心插值，**只在 N×N 覆盖范围内有效、不外推**）。
4. **反向回显自校验**：换算出机械坐标后，立刻把它**反算回像素**并与输入比较，
   偏差 > 1e-6px 直接失败。矩阵损坏或实现写错会当场露馅，而不是等机器人抓偏了才发现。
5. **角度**（像素角 → 机械角）：不手推三角函数，用"方向向量作差"——
   图像 x 轴方向经矩阵线性部分映射得基准方向 φ0，目标转 θ 后的方向向量映射得 φ(θ)，
   机械角 = φ(θ) − φ0，归一化到 (−180, 180]（目标没转时严格为 0）。
   透视/网格用**该点处的局部雅可比**（网格取所在三角形的仿射雅可比）。
   **单位口径**：插件侧一律"度"，只在调 HALCON 时转弧度；机械角与像素角的符号可以不同（含镜像/轴交换的标定属手性翻转，由矩阵自然吸收，**不做任何额外"校正"**）。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 否 | 参考图：①像素→机械时的**图像尺寸失配校验** ②位姿跟随的**输出对齐图**底图。不接也能工作 |
| `BaseRegion` | 位姿跟随必填 | 基准 ROI：接「ROI」的 `MaskRegion`，**必须画在模板图上** |
| `TemplateRefRow` / `TemplateRefCol` | 否 | 模板参考点（模板坐标系里的"位姿原点"）。默认由基准 ROI 中心派生，不用手填 |
| `PoseRow` / `PoseCol` | 位姿跟随必填 | 当前位姿：接「模板匹配」的 `Row` / `Column` |
| `PoseAngle` | 位姿跟随（可填 0） | 当前位姿角度（**度**）：接「模板匹配」的 `Angle`。角度本身允许 0，但位姿三项**全为 0** 会被判无效 |
| `Transform` | 像素→机械必填 | 接「标定」插件的 `Transform` 输出（**不允许手填矩阵**——单一事实源）。支持九点/透视/网格三类 |
| `SourceSerial` | 否 | 当前图像的相机序列号：接「图像采集」的 `SourceSerial`。与标定记录的非空序列号都填且不匹配 → 明确失败 |
| `PixelPointRow` / `PixelPointCol` | 像素→机械必填 | 待换算的像素点（接「模板匹配」的 `Row` / `Column`，即目标中心） |
| `PixelAngle` | 否 | 像素系角度（度）：**接了（或有非零值）才输出 `MechanicalAngle`** |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `FollowedRegion` | 跟随后的 ROI（当前坐标系）：接「Blob 缺陷检测」的 `MaskRegion` 等吃 `HRegion` 的下游 |
| `FollowedImage` | 可选：按位姿对齐回模板参考位姿的图。只在 `EmitFollowedImage = true` 且接了 `SrcImage` 时输出 |
| `MechanicalX` / `MechanicalY` | 机械坐标（mm）：接运动节点 / CSV记录 / 结果上报 |
| `MechanicalAngle` | 机械系角度（度），归一化到 (−180, 180]：抓取、贴合需要它 |
| `PixelEchoRow` / `PixelEchoCol` | 反向回显（自校验）：机械坐标再算回像素的结果，正常应与输入像素点重合（偏差 < 1e-6px） |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Mode` | `FollowRoi` | `FollowRoi` 位姿跟随 / `ToMechanical` 像素→机械。切换只影响界面与执行分支，不会清掉另一种模式已填的参数 |
| `EmitFollowedImage` | false | 是否输出对齐图。**默认关**：少一次重采样、少一次内存拷贝；只跟随 ROI 时保持关 |
| `TemplateRefFromRegionCenter` | true | true = 模板参考点由基准 ROI 中心自动派生（避免手填两张数）；false = 用 `TemplateRefRow/Col` 端口值 |
| `PreviewImagePath` | 空 | 配置态叠加预览的底图路径，**不参与运行**（运行只用端口值）。界面另有「取基准 ROI 中心」一键填参考点 |

> 枚举**界面显示中文、流程里存的是成员名**（`FollowRoi` / `ToMechanical`）。

## 口径与失败策略

- **四类失配必须明确失败**，绝不拿旧标定或恒等变换糊过去：
  ① 未接标定 → "未接标定：请把「标定」插件的 Transform 输出接到本步骤"；
  ② 标定只有像素当量 → "当前标定只有像素当量、不含机械坐标：坐标换算请用九点标定 / 透视标定 / 网格标定"；
  ③ 图像尺寸不符（接了 `SrcImage` 才校验）→ "标定与当前图像尺寸不符（标定时 …，当前 …）——换分辨率/换相机后需重新标定"；
  ④ 相机身份不符（两端序列号都非空才校验）→ 提示换用该相机的标定文件或查 `SourceSerial` 接线。
- **位姿/点位守卫**：NaN/Inf 与 (0,0,0) 都按无效失败——匹配失败时下游常拿到 0 或 NaN，
  静默变换会产出"看起来正常"的错 ROI / 错坐标，而 (0,0) 在图像角上、正常目标不可能在那。
- **标定数据损坏**：矩阵/投影/网格缺失或退化（det 近零、三角形退化）→ 明确失败并提示重新运行「标定」步骤；未知 `Kind` 也直接拒绝。
- **网格不外推**：像素点或机械点落在 N×N 节点构成的区域外 → 失败并提示"移入标定范围或扩大取点覆盖"。
- **回显不一致即失败**：偏差 > 1e-6px 判"标定矩阵可能已损坏"。
- **失败不留半成品**：跟随 ROI 与对齐图**全部算成功才写端口**；`MechanicalX/Y`、`MechanicalAngle`、
  `PixelEchoRow/Col` 每轮开头清零（基类只自动回收 `HRegion`/`HImage`，不清 double），失败轮下游读不到上一轮残留。
- **不做方向校正**：机械轴方向、镜像、旋转全部由标定矩阵吸收；插件只做"矩阵作用 + 失配检测"。
- **幂等、无阻塞**：同一输入同一输出，没有取消分支。配置态叠加预览（基准绿 / 跟随橙 / 参考点黄）只在配置窗口开着时刷新。

## 典型用法 / 接线

```
── 引导链路（保留原图坐标，只搬 ROI）
ROI.MaskRegion（画在模板图上）───────▶ 坐标变换.BaseRegion
模板匹配.Row / Column / Angle ───────▶ 坐标变换.PoseRow / PoseCol / PoseAngle
坐标变换.FollowedRegion ─────────────▶ Blob 缺陷检测.MaskRegion

── 机械坐标链路（机器人抓取/贴合）
标定.Transform ─────────────────────▶ 坐标变换.Transform
模板匹配.Row / Column ──────────────▶ 坐标变换.PixelPointRow / PixelPointCol
模板匹配.Angle ─────────────────────▶ 坐标变换.PixelAngle        （需要机械角才接）
图像采集.OutputImage ────────────────▶ 坐标变换.SrcImage          （建议接：换分辨率当场失败）
图像采集.SourceSerial ──────────────▶ 坐标变换.SourceSerial      （多相机才必接）
坐标变换.MechanicalX / Y / MechanicalAngle ─▶ 运动控制 / CSV记录 / 结果上报
```

## 常见问题

**Q：我的卡尺 / 颜色 / OCR 为什么不跟着工件走？**
本插件的跟随只搬 **ROI/点位**（给 `Blob 缺陷检测.MaskRegion`、机器人引导、多特征测量用）。
卡尺、颜色、OCR 的检测区域是插件内部配置，一期不能被位姿驱动——这类算子请接「模板匹配」的 `AlignedImage`
（它把目标**重采样**成标准位姿的新图）。选型口诀：要原图坐标/引导 → 本插件；要固定 ROI 的算子 → AlignedImage。

**Q：跟随后 ROI 明显偏？**
三查：① 基准 ROI 是不是画在**模板图**上（画在别的图上会系统性偏移）；② 模板参考点对不对
（默认用基准 ROI 中心，中心不是位姿原点就关掉派生、手工填或点「取基准 ROI 中心」）；
③ 位姿来源与基准 ROI 是否同一坐标系。自检法：给一组"模板态"位姿（位姿=参考点、角度 0），跟随框必须与绿框重合。

**Q：信息栏报"失败：位姿为 (0,0,0)"？**
多半是模板匹配失败或位姿端口没接。先查匹配分数/模板是否学过，别在这里补 0。

**Q：像素 30° 怎么机械角成了 −30°？**
标定里含镜像或轴交换（手性翻转）时转角符号取反，这是数学事实、由矩阵自然吸收。
**不要**在配置里"再校正一次"（负负得正是最难查的一族错误）；要验证就用回算比对示教器。

**Q：运行报"标定与当前图像尺寸不符"，但结果其实看着挺准？**
这正是它该失败的时候：换了分辨率/相机而流程还在用旧标定，是静默错位的经典来源。重新标定（或在标定步骤里改用当前相机的那份）。

**Q：`MechanicalAngle` 一直是 0？**
只有接了 `PixelAngle`（或有非零值）才会换算输出机械角；本步骤失败时该端口是开轮清零值 0，先查 `Success`。

**Q：要对多个目标怎么办？**
一期只做单目标 `double`（端口类型与上游严格一致；硬凑 HTuple 会运行期静默拿不到值）。
多目标就放多个本步骤，各自接一对像素点。
