# 坐标变换 · 界面与操作

> 分类：定位 ｜ 来源：插件 Plugin.PoseTransform

双击流程里的「坐标变换」步骤（或右键 →「模块参数」）打开配置对话框。
整个界面按**模式**收敛：选「位姿跟随」只出现跟随相关的卡片，选「像素→机械」只出现换算相关的卡片，
**不会同时摆出十几个框**让你自己分辨哪几个有用。

## 一、卡片布局

| 卡片 | 标题 | 什么时候出现 | 里面有什么 |
| --- | --- | --- | --- |
| ① | **模式与选项** | 始终 | 模式二选一（`位姿跟随` / `像素→机械`）+ 下面几项开关，开关随模式换 |
| ② | **参考图（可选）** | 始终 | `SrcImage` 那一行；说明文案写明它在两个模式里各自干什么 |
| ③ | **位姿跟随输入** | 只在「位姿跟随」 | `BaseRegion` / 模板参考点两项 / 位姿三项，外加「取基准 ROI 中心」按钮与一条硬约束提示 |
| ④ | **像素→机械输入** | 只在「像素→机械」 | `Transform` / `PixelPointRow` / `PixelPointCol` / `PixelAngle`，附"只接标定插件输出、不允许手填矩阵"的提示 |
| ⑤ | **标定信息** | 只在「像素→机械」 | 一块**只读**文本（类型/来源/相机/尺寸/时间/残差），颜色由状态级别驱动 |
| ⑥ | **预览图（配置态叠加用）** | 始终 | 预览图路径 + **浏览** 按钮 + 一段配色说明（绿/橙/黄各是什么） |
| — | **画布** | 始终 | 叠加预览区（`ImageEdit`），下方两行文本：状态栏一行 + 跟随面积一行 |

### ① 模式与选项里的三个开关

| 界面文案 | 对应配置 | 默认 | 勾/取消的影响 |
| --- | --- | --- | --- |
| `输出对齐图（把当前图重采样回模板参考位姿）` | `EmitFollowedImage` | **关** | 勾上才输出 `FollowedImage`（要同时接 `SrcImage`）。默认关是刻意的：少一次重采样、少一次内存拷贝 |
| `模板参考点由基准 ROI 中心派生` | `TemplateRefFromRegionCenter` | **开** | 开着时 `TemplateRefRow` / `TemplateRefCol` 填什么都不生效（参考点直接从基准 ROI 中心算）；取消才用端口值 |
| 模式二选一 | `Mode` | `位姿跟随` | 只切换界面与执行分支，**不清空另一种模式已填的值** |

卡片 ① 里还有一段常驻说明，写的是本插件与「模板匹配」对齐图的分工：
"那边把目标重采样成标准位姿（适合内部 ROI 固定的算子）；本插件跟随保留原图坐标、只跟随 ROI/点位
（MaskRegion、机器人引导用这个）"——纠结要不要开对齐图时看这段。

## 二、画布上的三种颜色

叠加预览只在**配置对话框开着**的时候刷新（对话框关了就不再为"没人看的图"做重采样与绘制）。

| 颜色 | 画的是什么 | 什么时候出现 |
| --- | --- | --- |
| **绿色轮廓** | 基准 ROI（模板坐标系里的那个框） | 接上了 `BaseRegion` 且它不是空区域 |
| **橙色轮廓** | 跟随 ROI（按当前位姿搬完之后的框） | 参考点有效 **且** 位姿三项通过有效性判定 |
| **黄色十字** | 模板参考点（位姿原点） | 参考点有效 |

底图按这个顺序挑：**优先用「⑥ 预览图」里载入的图**；没有载入预览图时，若已接 `SrcImage` 且它有值，
就直接拿它当底图；两个都没有 → 画布空着、`跟随面积` 那行清空。

几条实际会碰到的行为：

- **只有绿框、没有橙框**：位姿还没就绪。给 `PoseRow` / `PoseCol` / `PoseAngle` 填一组有效值，
  或先试运行一次。此时画布下方那行会明确写"跟随 ROI 未画：位姿未就绪（给 PosRow/Col/Angle 一个有效值或试运行一次）"。
- **只有底图、连绿框都没有**：`BaseRegion` 还没接进来。信息栏会提示"预览已载入，但基准 ROI 未接：叠加图只有底图"。
- **画布永远不会把标注画进你的真实图像**：预览是底图的一份 RGB 副本，绘制全部画在副本上，
  上游 `SrcImage` 端口的图**不受影响**（下游拿到的还是干净图）。
- **黄色十字画在最上层**，所以它和绿框重叠时也看得见——用来确认"参考点是不是你以为的那个位置"。

## 三、两个按钮

| 按钮 | 做什么 | 没接基准 ROI 时会怎样 |
| --- | --- | --- |
| **浏览** | 弹文件选择框（`bmp / jpg / jpeg / png / tif / tiff`），选中后把路径写进「⑥ 预览图」 | — |
| **取基准 ROI 中心** | 读当前 `BaseRegion` 的面积与中心，把中心坐标填进 `TemplateRefRow` / `TemplateRefCol`，并在信息栏回一行"已取基准 ROI 中心（行, 列）填入模板参考点" | 信息栏变橙："基准 ROI 还没接（或为空）：先在流程里把 ROI 插件的 MaskRegion 接到本步骤"，**不动任何值** |

「取基准 ROI 中心」是**手工填参考点**那条路的加速器：关掉派生之后，先接好 ROI、点一下这个按钮，
再把十字往真正的位姿原点上微调，比从零打两个数快得多。

## 四、预览图的行为细节

- 路径**可以手打**（输入框是即时提交的），不必非走浏览按钮；手打进一个不存在的文件，
  信息栏会报红"预览图不存在: ……（完整路径）"，画布清空。
- 同一个路径不会重复读盘（内部记着已载入的是哪张）；把路径**清空**会立刻清掉预览与叠加图。
- 换图时旧图被释放、新图在后台读盘。若在载入途中又换了一次，**过期结果直接丢弃**（不会出现"旧图复活"）。
- 「⑥ 预览图」只影响**配置界面的观感**，**完全不参与运行**：运行只吃端口的值。
  它也不会被当成图像源给下游——存进方案里的只是那个路径字符串。

## 五、「⑤ 标定信息」只读块怎么读

只在像素→机械模式下出现。一行内容形如：

```
类型 九点 ｜ 来源 工位A-上相机 ｜ 相机 0012345678 ｜ 标定图 2448×2048 ｜ 创建 2026-10-11 14:32 ｜ 残差 RMS 0.31px / 最大 0.9px
```

| 颜色 | 含义 | 依据 |
| --- | --- | --- |
| 绿（正常） | 标定可用且残差在 1px 内 | 残差 RMS ≤ 1.0 |
| **橙** | 标定可用，但**残差偏大**，还能用、需要留意 | 残差 RMS > 1.0（阈值本身由「标定」插件把关，这里只提醒） |
| **红** | 已经失配：未接标定 / 类型不可用 / 数据损坏 / 与预览图尺寸不符 | 尺寸不符时行首会多一句"当前图 W×H ≠ 标定图 W×H——换分辨率/换相机后需重新标定" |

两个容易误读的点：

- **"（未填）"不是错误**：来源与相机序列号没填就显示 `（未填）`；标定图尺寸没记就显示 `未记录`。
  这两项都会让对应的失配检查**自动放行**（详见《常见问题与排障》Q9、Q10）。
- **红字里的尺寸比对用的是预览图**，运行期比对用的是 `SrcImage`。所以"界面上红、试运行却成功"或反过来，
  通常是这两处接了不同的图。

## 六、信息栏（状态栏）那一行

底部一行文字 + 一种颜色（绿 / 橙 / 红），内容是"**当前模式还差什么 / 已经就绪**"。

| 模式 | 就绪时 | 未就绪时（橙） |
| --- | --- | --- |
| 像素→机械 | `就绪：标定已接入（九点），运行输出机械坐标（含反向回显自校验）` | `未接标定：请把「标定」插件的 Transform 输出接到本步骤` / 或具体的标定问题文案 |
| 位姿跟随 | `就绪：跟随参数完整（试运行可看叠加效果）` | `基准 ROI 未接：请把 ROI 插件的 MaskRegion 接过来（画在模板图上）` / `位姿未就绪：……` |

**信息栏绿了不等于试运行一定成功**——它查的是"配置齐不齐"，运行期还会额外查图像尺寸与相机身份
（这两项必须有真实的 `SrcImage` / 序列号才能比）。反过来，**信息栏红/橙的时候基本可以先修再试**，
省一轮试运行。

## 七、这个界面**没有**的东西（避免找）

- **没有手填标定矩阵的入口**：标定只能从上游「标定」插件接进来（单一事实源）。
- **没有"目标列表 / 多目标"界面**：一期只做单目标，多目标请放多个本步骤，各自接一对像素点。
- **没有跟随 ROI 的绘制工具**：框只能在「ROI」算子里画，这里只显示、不编辑。
- **没有"方向校正 / 符号修正"开关**：镜像、轴交换、旋转全部由标定矩阵自然吸收，
  刻意不提供这个入口（"再手动校正一次"是这类系统里最难查的错误来源）。
- **没有单独的"参数页/端口页"分页**：端口值就在各卡片里直接填，配置开关在卡片 ①。
