# 坐标变换 · 上手与现场验收

这一页讲两个模式各自怎么配、怎么自检、以及和「模板匹配」的对齐图怎么选型。端口与参数含义见上一页。

## 一、位姿跟随（8 步）

1. **在模板图上画基准 ROI**：用「ROI」在**模板图 / 学习图**上框好检测区域。
   这一步最容易错——基准 ROI 的坐标属于模板坐标系，画在别的图上基准本身就偏了，跟随结果会系统性偏移；
2. 「坐标变换」模式选**位姿跟随**；
3. 接输入：`BaseRegion` ← 「ROI」的 `MaskRegion`；`PoseRow` / `PoseCol` / `PoseAngle` ← 「模板匹配」的
   `Row` / `Column` / `Angle`（角度单位是**度**，匹配插件给的也是度，直接接，不要自己换算弧度）；
4. 模板参考点：保持 `TemplateRefFromRegionCenter = true`（由基准 ROI 中心派生）。
   如果基准 ROI 的中心并不是"位姿原点"（例如 ROI 偏在一角、原点在吸盘中心），
   关掉派生，点「取基准 ROI 中心」或手工填 `TemplateRefRow` / `TemplateRefCol`；
5. （可选）在预览卡片「浏览」选一张模板图——画布出现**绿色基准轮廓**与**黄色参考点十字**；
6. 试运行给一组有效位姿：画布出现**橙色跟随轮廓**。
   **自检**：喂"模板态"位姿（位姿 = 参考点、角度 0），橙框必须与绿框**完全重合**；不重合就说明第 1 步或第 4 步错了；
7. 看信息栏的面积一行：`基准面积 …px² → 跟随面积 …px²（±X%）`。
   刚体变换下正视平面应当**接近 0%**（`affine_trans_region` 用 nearest_neighbor，只有栅化取整的微小差异）；
   偏差明显 → 位姿来源可疑（多半是接错了上游、或上游匹配到了另一件工件）；
8. 下游接线：`FollowedRegion` → 「Blob 缺陷检测」的 `MaskRegion`。
   需要"标准位姿图"喂给内部 ROI 固定的算子时，勾 `EmitFollowedImage` 并把 `SrcImage` 接上图像源
   （不接 SrcImage 时只记一条 Info 日志、对齐图输出 null，跟随 ROI 照常给）。

## 二、像素 → 机械（7 步）

1. 模式选**像素→机械**；
2. `Transform` ← 「标定」插件的 `Transform` 输出（**只能这样来**，界面不提供手填矩阵——单一事实源）；
3. `PixelPointRow` / `PixelPointCol` ← 「模板匹配」的 `Row` / `Column`；需要机械角时 `PixelAngle` ← 「模板匹配」的 `Angle`；
4. **建议**把 `SrcImage` 接上图像源：让"换分辨率忘了重标"当场失败，而不是算出一个看着合理的错坐标；
5. 多相机就接 `SourceSerial`（←「图像采集」的 `SourceSerial`），并确认标定步骤里填了同一台相机的序列号；
6. 看界面「标定信息」只读块：来源 / 相机序列号 / 标定图尺寸 / 创建时间 / 残差是否与当前相机对得上
   （红字 = 已失配）；
7. 试运行：读 `MechanicalX` / `MechanicalY`（接了角度时还有 `MechanicalAngle`）与 `PixelEchoRow` / `PixelEchoCol`。
   **回显必须回到原点**（插件内部已把关，偏差 > 1e-6px 直接失败），日志一行形如
   `像素 (r, c) → 机械 (x, y)mm，机械角 θ°`（透视/网格会标注类型）。

## 三、和「模板匹配」对齐图的分工（选型表）

| 维度 | 「模板匹配」的 `AlignedImage` | 本插件「位姿跟随」 |
| --- | --- | --- |
| 做什么 | 把目标**重采样**成标准位姿的**新图** | **保留原图坐标**，只变换 ROI / 点 |
| 代价 | 每帧一次图像重采样（插值损失 + 内存拷贝） | 只变换区域（轻） |
| 适合 | 内部 ROI 固定的算子：卡尺 / 颜色 / OCR | `Blob 缺陷检测.MaskRegion`、机器人引导、多特征测量 |
| 不适合 | 引导场景（重采样丢了原图坐标映射） | 卡尺 / 颜色 / OCR（它们的内部 ROI 一期不可被位姿驱动） |

> 已有「模板匹配」的 `AlignedImage` 时**不必**在这里再开对齐图——两者等价，多一次重采样而已。

## 四、症状 → 查哪里

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| 失败"未接标定…" | `Transform` 没接 | 接「标定」的 `Transform` 输出 |
| 失败"当前标定只有像素当量…" | 用了像素当量模式做机械换算 | 回标定步骤改用九点 / 透视 / 网格重标一份 |
| 失败"标定与当前图像尺寸不符" | 换分辨率 / 换相机没重标 | 重新标定（这是它**应该**失败的时候） |
| 失败"相机身份不符" | 拿错相机的标定，或 `SourceSerial` 接错 | 换该相机那份标定文件；核对接线 |
| 失败"位姿无效（NaN/Inf）" | 上游匹配失败或位姿没接 | 查匹配分数 / 模板是否学过 |
| 失败"位姿为 (0,0,0)" | 匹配失败的默认值漏到下游 | 同上；不要用补 0 绕过 |
| 失败"待换算的像素点为 (0,0)" | 目标中心端口没接 | 接「模板匹配」的 `Row` / `Column` |
| 失败"…不在网格覆盖范围内" | 网格标定只在 N×N 节点围成的区域内有效（不外推） | 把点移入标定范围，或扩大取点覆盖（加密 / 扩边） |
| 失败"标定数据损坏（矩阵/投影/网格缺失或退化）" | 上游标定本轮没算好 | 重新运行「标定」步骤 |
| 失败"反向回显不一致" | 矩阵在传输/存盘过程中损坏 | 重新标定 |
| 画布只有绿框没有橙框 | 位姿未就绪 | 给一组有效位姿或试运行一次 |
| 跟随后 ROI 整体偏 | 基准 ROI 画在非模板图上 / 参考点不对 / 位姿不同源 | 回第一节第 1、4 步，用"模板态自洽"自检 |
| 「Blob 缺陷检测」检出尺寸对但位置不对 | 基准 ROI 与模板学习坐标不一致 | 在模板图上重画基准再跟随 |

## 五、上线前验收

- **模板态自洽**：位姿 = 参考点、角度 0 时跟随 ROI 与基准 ROI 重合（面积相对差 0）；
- **合成旋转**：拿一张图人为转 30°（或用工装转 30°），确认跟随 ROI 的角度与位置都对；
- **面积保持**：跟随前后 ROI 面积差接近 0%（正视平面）；
- **回算比对示教器**：取 3 个已知机械位置的特征点，经本插件换出 X/Y，与示教器读数比对
  （**±0.5mm 或 ±1 像素当量，取大者**）；
- **端到端一条线**：`图像采集 → 模板匹配 → 坐标变换 → CSV记录`，记录里的机械坐标与现场实测一致；
- **失败面验证**：故意断开 `Transform`、故意换一张不同分辨率的图，确认流程是**明确失败**而不是给出错值
  （下游此时读到的是开轮清零值 0，不会读到上一轮的好值）。
