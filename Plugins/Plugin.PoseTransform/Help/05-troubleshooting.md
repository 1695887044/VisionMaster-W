# 坐标变换 · 常见问题与排障

> 分类：定位 ｜ 来源：插件 Plugin.PoseTransform

"失败文案"那一列**逐字来自程序**，可以直接和界面里看到的对上。
先看第一节的现象对照表，找不到就在第二节按文案搜，最后有第三节的通用排查顺序。

## 一、现象 → 查哪里（不用看错误文案的那种）

| 现象 | 最可能的原因 | 处置 |
| --- | --- | --- |
| 跟随后 ROI 整体偏，每次偏一样的量 | 基准 ROI 画在了**非模板图**上 | 回「ROI」算子，在模板/学习图上重画基准。用"模板态自洽"自检确认（位姿=参考点、角度 0 → 橙框与绿框重合） |
| 跟随后 ROI 偏，但偏量随位置变 | 模板参考点不是真正的位姿原点 | 取消「模板参考点由基准 ROI 中心派生」，点**取基准 ROI 中心**再按实际原点微调 |
| 画布只有绿框、没有橙框 | 位姿三项还没有效值 | 给 `PoseRow`/`PoseCol`/`PoseAngle` 一组有效值，或先试运行一次 |
| 画布只有底图 | `BaseRegion` 没接进来 | 接「ROI」的 `MaskRegion`（信息栏也会写"基准 ROI 未接：叠加图只有底图"） |
| `MechanicalAngle` 一直是 0 | 要么没接 `PixelAngle`（含义是"没给"），要么本步骤失败被清零 | 先查 `Success`；确实在跑就检查 `PixelAngle` 有没有连线 |
| `MechanicalX` / `Y` 是 0 | 本轮失败（五个标量输出每轮开头清零） | 看 `ErrorMessage`，别怀疑下游 |
| 跟随前后面积差明显（不是接近 0%） | 位姿来源可疑：接错上游、或匹配到了另一件工件 | 核对位姿三项的连线；刚体变换不缩放，面积必须守恒 |
| 像素 30°，机械角变成 −30° | 标定里含**镜像或轴交换**（手性翻转），转角取反是数学事实 | **不要**"再校正一次"。要验证就回算比对示教器 |
| 透视标定下，同样的像素角在画面左右算出不同机械角 | 透视的角度与位置相关（用该点局部雅可比），这是正确行为 | 九点标定没有这个现象；需要"角与位置无关"就用九点 |
| 试运行报"标定与当前图像尺寸不符"，但结果看着挺准 | 这正是它**该**失败的时候：换了分辨率/相机而流程还在用旧标定 | 重新标定（或在标定步骤里改用当前相机那份）。不要靠"看着准"放行 |
| 界面上标定信息是红的，试运行却成功（或反过来） | 界面比对用**预览图**尺寸，运行比对用 `SrcImage` | 两处接同一张图，或以运行期为准 |
| 网格标定下远处的点越来越偏 | 点落在 `N×N` 节点覆盖范围外（不外推是对的，外推才危险） | 把点移入标定范围，或扩大取点覆盖（加密 / 扩边）重标一份 |
| 机器人抓偏了，但流程一路"成功" | 检查下游有没有读 `Success`；本插件失败时输出是清零值 | 让运动节点/上报节点先判 `Success`，别直接读数值 |
| 工具箱里找不到这个算子 | 插件的分组元数据缺失（异常改动导致） | 确认 DLL 是 `Modules\` 里的最新版；正常安装下它应该在**「定位」**分组，实名「坐标变换」 |

## 二、按失败文案查（逐字对得上界面）

### 「未接标定：请把「标定」插件的 Transform 输出接到本步骤」
像素→机械模式下 `Transform` 为空。只能接「标定」插件的 `Transform` 输出——**界面不提供手填矩阵**（单一事实源）。

### 「当前标定只有像素当量、不含机械坐标：坐标换算请用九点标定 / 透视标定 / 网格标定（像素当量模式只给 mm/px）」
用了**像素当量**模式的标定去做机械换算。像素当量根本没有机械坐标系，给不出 X/Y。
回「标定」步骤改用九点 / 透视 / 网格重标一份。

### 「标定数据损坏（矩阵缺失或退化）：请重新运行「标定」步骤」
### 「标定数据损坏（投影矩阵缺失或退化）：请重新运行「标定」步骤」
### 「标定数据损坏（网格缺失或退化）：请重新运行「标定」步骤」
### 「网格规模非法（MeshSize=…，至少 2）：标定数据可能已损坏，请重新运行「标定」步骤（网格标定模式）」
### 「网格节点数与规模不符（MeshSize=… 要求 … 个数，实际 …）：…」
矩阵行列式近零、投影矩阵长度不足或含非有限值、网格节点数与规模不匹配。
**通常是上游「标定」这一轮没算好**（或标定数据在存盘/传输中被改坏）。先重跑标定步骤；
若反复出现且矩阵是九点类型，顺带检查标定现场的点位是否有三点共线这类退化布置。

### 「不支持的标定类型（xxx）：请升级软件或重新标定」
标定数据里的类型不在本软件认识的范围（新类型 / 数据被损坏成非法值）。
这是**刻意的拒绝**——不认的类型绝不按旧逻辑静默算。按提示升级或重标。

### 「相机内参缺失：这份标定声明了「去畸变像素」语义，但没有携带内参数据——请重新运行「标定」步骤的内参标定」
### 「相机内参的模型类型无法识别（「xxx」）：只支持 area_scan_division / area_scan_polynomial——…」
### 「相机内参损坏（area_scan_polynomial 需要 5 个畸变系数，实际 …）：…」
### 「相机内参非法（焦距/像元尺寸/主点/kappa/标定图尺寸 …）：请重新运行内参标定」
接进来的标定是**"已去畸变"版本**（`NinePointUndistorted` 等），但内参那一半坏了或没带过来。
这几条的文案都由**契约层**给出（`CameraIntrinsics.IsUsable`），消费端与生产端共用同一份判据，
所以界面上看到的说法与「标定」插件里是一致的。按提示回「标定」重跑内参标定。

### 「标定与内参的图像尺寸不一致（标定 W×H，内参 W×H）：两者不是同一次拍摄的产物——…」
### 「标定与内参的相机身份不一致（标定属于「A」，内参属于「B」）：…」
**内参自证**：平面标定的那份数据与相机内参不是同一台相机/同一次拍摄的产物。
**只记一边就放行**（历史数据与离线场景的常态），所以看到这条说明两边都记了且真的对不上。

### 「标定数据自相矛盾（类型 Xxx 不带内参语义，却携带了相机内参）：数据来源可能被混用——…」
反向自证：标定类型说"像素是原始像素"，数据里却塞着相机内参。
放行它就等于"矩阵按原始像素用、界面却可能显示已去畸变"，是纯静默错位。回「标定」重跑一份。

### 「当前图像尺寸与内参标定尺寸不符（内参标定 W×H，当前 W×H）——换分辨率/换相机后需重新运行内参标定（畸变系数是像素帧相关的量）」
失配③的另一条支路（与上面那条"标定与当前图像尺寸不符"**并列**，不是替代）：
标定快照尺寸对得上、但内参记的尺寸对不上。畸变系数是**像素帧相关**的量，
跨分辨率使用会把点挪到"看起来合理"的错误位置。

### 「标定与当前图像尺寸不符（标定时 W×H，当前 W×H）——换分辨率/换相机后需重新标定」
失配③。文案里的**两个尺寸都故意写出来**：左边是标定当时的、右边是现在这张图的，直接能判断是哪一侧变了。
只有**接了 `SrcImage`** 才会做这项检查；标定文件没记录尺寸时放行（无从比对）。

### 「相机身份不符：这份标定属于「A」，但当前图像来自「B」；请换用该相机的标定文件（或检查 SourceSerial 接线）」
失配④。要么真的拿错了相机那份标定，要么 `SourceSerial` 接错线（接成了另一路采集）。
比对忽略大小写。两端序列号**都非空**才检查——所以离线调试（`SourceSerial` 为空）不会报这条。

### 「位姿无效（NaN/Inf）——请检查模板匹配是否成功（或上游位姿来源）」
### 「待换算的像素坐标无效（NaN/Inf）——请检查上游（模板匹配是否成功）」
上游给了非数。常见于匹配算子在异常分支上输出 `NaN`，或端口类型不匹配。查匹配那一层的日志。

### 「位姿为 (0,0,0)：多半是模板匹配失败或位姿未接——请检查上游位姿来源」
### 「待换算的像素点为 (0,0)：多半是模板匹配失败或未接——请检查上游位姿来源」
三项/两项同时为 0 是"没值"的典型形态（`(0,0)` 在图像左上角，正常目标不可能在那）。
**先查匹配分数 / 模板是否学过 / 端口有没有连线，别在这里补 0 绕过**——补 0 会得到一个"看起来正常"的错结果。

### 「基准 ROI 为空：请把 ROI 插件的 MaskRegion 接过来（并在模板图上画好基准）」
位姿跟随下 `BaseRegion` 没接或接进来是空图。

### 「基准 ROI 是空区域（面积为 0）：请检查基准 ROI 的绘制（要画在模板图上）」
接上了但那个框里一个像素都没有。常见于 ROI 画在了另一张尺寸/位置不同的图上，或框被拖到画外。

### 「模板参考点无效（NaN/Inf）：请点「取基准 ROI 中心」或手工填写」
### 「模板参考点为 (0,0)：请点「取基准 ROI 中心」或手工填写实际参考点」
只在**取消了派生勾选**时才会遇到（派生状态下参考点直接从 ROI 中心算）。点**取基准 ROI 中心**一键填，或手工填实际位姿原点。

### 「位姿跟随失败：……（请检查基准 ROI、SrcImage 与位姿是否有效）」
HALCON 变换调用本身抛异常。括号前的那段是原始异常信息，通常会点明是区域还是图像的问题。
**此时两个输出都没有写**（已算出的中间产物被就地释放），下游读到的是空值而不是半成品。

### 「读取图像尺寸失败：……（SrcImage 是否有效？）」
`SrcImage` 接到了一个"非空但读不出尺寸"的图像对象。换一张正常的图或检查上游采集。

### 「反向回显不一致（偏差 Npx，容差 Tpx）：标定矩阵可能已损坏，请重新标定」
正算到机械、再反算回像素，回不到原点。这是**自洽性**判据，不是精度判据——标定残差再大也不会触发它。
触发说明矩阵数据本身坏了（存盘/传输被改），重新标定。

容差按标定类型分档，看消息里那个 `T` 就知道是哪一档：

| 标定类型 | 容差 | 为什么 |
| --- | --- | --- |
| 九点 / 透视 / 网格（不带内参） | `1e-6` px | 纯矩阵往返，可以要求到双精度极限 |
| `area_scan_division`（已去畸变） | `1e-6` px | 畸变可**解析求逆**（实测往返 2.7e-13px） |
| `area_scan_polynomial`（已去畸变） | `1e-3` px | 畸变**只能迭代反解**（实测最坏 1.1e-4px）。**这一档不是数据坏了**——若按 `1e-6` 判会假红，而且重标定解决不了 |

看到 polynomial 档报错先别急着重标：偏差在 `1e-4` 量级属正常反解误差；**只有远超 `1e-3`** 才是数据问题。

### 「未知模式：xxx（请重新选择模式）」
步骤里存的模式值在当前版本不认识（方案来自别的版本 / 手工改过存盘文件）。
在界面里重新选一次模式即可。

### 「预览图不存在: ……（路径）」
### 「加载预览图失败: ……（原因）」
只影响配置界面的底图，**不影响运行**。路径是绝对路径，换机器/挪方案目录后会失效——重新选一张就行。

### 「叠加预览失败：……」「跟随预览失败：……」
只影响画布叠加显示，把信息栏染成橙色，**不影响运行结果**。运行成功与否看 `Success`。

## 三、日志里的正常行（用来确认"它真的在算"）

| 日志 | 含义 |
| --- | --- |
| `位姿跟随：基准面积 3120px² → 跟随面积 3119px²（−0.03%）` | 跟随成功；百分比就是面积守恒检查，正视平面应接近 0 |
| `像素 (512.4, 780.1) → 机械 (405.123, 307.884)mm，机械角 29.996°` | 换算成功；接了角度才有后半段 |
| `…… （透视）` / `…… （网格（分段仿射））` / `…… （九点标定（已去畸变））` 结尾 | 标注所用标定类型（不带内参的九点不标；三个"已去畸变"类型都标） |
| `未接 SrcImage：跳过输出对齐图` | 勾了对齐图但没接图，**这不是失败**，跟随 ROI 照常给 |

## 四、通用排查顺序（两分钟走完）

1. **模式选对了吗**？两种模式的端口几乎不重叠，选错了就是"该接的接不上、接了的没用"。
2. **信息栏绿了吗**？配置对话框开着时它就是同一批判据的预演；没绿先按它的提示补齐。
3. **`Success` 与 `ErrorMessage`**：本步骤失败时标量输出全是清零值，
   下游拿到的 0 不是"算出来的 0"。先确认失败发生在哪一层。
4. **跟随线做模板态自检**：位姿 = 参考点、角度 0 → 橙框必须压住绿框。不重合就是基准或参考点错了。
5. **换算线做回算比对**：取 3 个已知机械位置的特征点，换出的 X/Y 与示教器读数比
   （建议 ±0.5mm 或 ±1 像素当量，取大者）。
6. **故意制造一次失败**：断开 `Transform`、或换一张不同分辨率的图，确认流程**明确报错**而不是给错值。
   这一条同时验掉"失配有没有被糊过去"和"输出有没有清零"。

## 五、其它常见疑问

**Q：标定接了"已去畸变"的那种，算出来的坐标和以前不一样了？**
像素定义域变了：带内参的标定里，矩阵吃的是**去畸变后**的像素，插件会自动"先去畸变、最后加畸变"。
拿同一份矩阵在"不带内参"时的期望值去对，就会差出"去畸变量 × 当量"（kappa=-1500 时约 0.37mm）。
看「⑤ 标定信息」有没有"去畸变已启用"那一段就能确认当前是哪个域。

**Q：`area_scan_polynomial` 的回显容差为什么是 0.001 而不是 0.000001？**
因为该模型的**逆向畸变只能迭代反解**，HALCON 自己的往返误差最坏就到 `1e-4` 量级。
按 `1e-6` 判会**假红**，而且失败文案会指向"矩阵损坏、请重新标定"——现场重标定根本解决不了（是容差错，不是数据错）。
`area_scan_division` 可解析求逆（实测往返 2.7e-13px），所以仍是 `1e-6`。

**Q：我的卡尺 / 颜色 / OCR 为什么不跟着工件走？**
本插件的跟随只搬 **ROI 与点位**（给 `MaskRegion`、机器人引导、多特征测量用）。
卡尺、颜色、OCR 的检测区域是它们各自内部配置的，目前不能被位姿驱动——这类算子请接
「模板匹配」的 `AlignedImage`（把目标重采样成标准位姿的新图）。选型口诀见《变换口径与标定消费》第三节。

**Q：能不能手填标定矩阵 / 直接给六个数？**
不能。`Transform` 只接受「标定」插件的输出。手填矩阵等于制造第二个事实源，
标定改了、手填的没改，出来的坐标错得毫无征兆。要改标定请回到标定步骤改。

**Q：「模板参考点由基准 ROI 中心派生」一直勾着行不行？**
行，而且这是默认推荐。只有当基准 ROI 的**几何中心不是位姿原点**时才需要取消——
典型是 ROI 只框住工件一侧、而原点定义在吸盘/夹爪中心。

**Q：对齐图和跟随 ROI 能同时输出吗？**
能，勾 `EmitFollowedImage` + 接 `SrcImage` 就同时有两个输出。
但注意两者方向是**互逆**的：ROI 是"从模板搬到当前"，图是"从当前搬回模板"，
所以对齐图上的标准位置 ≠ 跟随 ROI 的当前位置，别把它们叠在一起看。

**Q：为什么 `PixelAngle` 没接的时候 `MechanicalAngle` 是 0 而不是空？**
`double` 输出没有"空"这个状态，所以约定是"未接/失败时保持每轮开头的清零值 0"。
判"有没有算过"看 `Success`，不要看那个 0。

**Q：多目标怎么办？**
放多个本步骤，各自接一对像素点（或一组位姿）。端口类型与上游严格一致，
硬凑数组类型会在运行期静默取不到值，比多放几步贵得多。

**Q：这个步骤很慢 / 能不能并行跑？**
它声明为可并行（纯视觉计算，无设备占用）。真正贵的是勾了 `EmitFollowedImage` 之后的那次
图像重采样——只要跟随 ROI 就把对齐图关掉，默认就是关的。

**Q：`PreviewImagePath` 会不会影响运行结果？**
不会。它只是配置界面的叠加底图，运行只吃端口值。
但它存的是**绝对路径**，方案换机器后会提示"预览图不存在"——重新选一张即可。

**Q：改了插件源码后真机没变化？**
`Modules\Plugin.PoseTransform.dll` 不由宿主工程带出来，**必须重建插件工程**；
打包走 Release 产物，只重建 Debug 真机仍跑旧 DLL。
