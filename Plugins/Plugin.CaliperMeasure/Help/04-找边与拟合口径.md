# 卡尺测量 · 找边与拟合口径

> 分类：测量 ｜ 来源：插件 Plugin.CaliperMeasure

这一页讲**为什么这样算**：剖面怎么找边、N 把卡尺怎么排、拟合的内部固定参数、
哪些失败是"宁可不给数"、判定与单位口径从哪来。调参前的判据、界面操作在另几页。

## 一、一把卡尺 = 一条会读数的尺子

一把卡尺是一个可旋转的小矩形，参数 `[中心行, 中心列, 角度 Phi, 半长 L1, 半宽 L2]`。
它**沿 L1 方向**从一侧推到另一侧，一路上把灰度记成一条曲线；
**垂直于扫描方向的 L2 那一段被平均掉**（投影）——这就是"卡尺半宽"的作用：
窗口太窄只剩单个像素的噪声，太宽会混进旁边不相干的特征。圆周卡尺的默认半宽取 3px 就是这个道理。

找边 = 在剖面上找"最陡"，再过两道闸：

- 算子先对剖面做高斯平滑（「平滑 Sigma」）再求导找极值，**不是"像素值差一下就算"**；
- **边缘阈值**：相邻像素的最小灰度差。低于它的起伏只当纹理，不算边；
- **极性**：沿扫描方向只允许哪种明暗跳变（暗→亮 / 亮→暗 / 全部）。

过了闸的点，按「插值方式」给出**亚像素**位置（双线性/双三次能在两个像素之间定位，最近邻只能落在整像素上）。

界面中文与算子参数的对应（**这层映射由插件按成员名 switch 生成，与界面显示名无关**，改显示名不会改到参数）：

```
极性      暗→亮 / 亮→暗 / 全部        → transition  positive / negative / all
选择      第一条 / 最后一条 / 全部     → select      first / last / all
插值      最近邻 / 双线性 / 双三次     → interpolation nearest_neighbor / bilinear / bicubic
拟合(直线) 最小二乘 / Huber / Tukey   → algorithm   regression / huber / tukey
拟合(圆)   最小二乘 / Huber / Tukey   → algorithm   geometric / geohuber / geotukey
```

圆与直线的拟合算法值集**不是同一族**（把直线的三个值喂给拟合圆会直接报参数错），
所以界面上一个「拟合方式」下拉在两种类型下会各自映射到对应族——操作员不用管，这里写出来是为了移植时不踩。

## 二、N 把卡尺怎么排：矩形要「横跨」被测特征（硬事实）

| 方向 | 半轴 | 是什么 | 摆错了会怎样 |
| --- | --- | --- | --- |
| **L1（Phi 轴）** | 半长 | **扫描方向**——每把卡尺沿它推过去，检出的边**垂直于**它 | 扫不到边，直接报"未检出" |
| **L2（垂直 Phi）** | 半宽 | **阵列排布方向**——N 把卡尺沿它等分铺开，每把保留完整 L1 扫描长度 | 卡尺顺着扫描方向散开、各自扫到不同位置，平均出来的数没有意义 |

这条是拿真实 HALCON 实证过的：Phi=0 时 L1 沿水平，把 L1=100/L2=10 的矩形压在竖直亮带上能量出宽度；
把 L1 缩到 10（扫描线够不到边）或把 Phi 转 90°（扫描方向变竖直），都检不到边。

**矩形均布的算术**（把整段 L2 宽度等分成 N 份）：

```
间距 spacing   = 2 × L2 / N
每把半宽       = max(spacing / 2, 0.5)          // 下限 0.5px，防止被均分成 0
第 i 把的偏移  t = -L2 + spacing × (i + 0.5)     // i 从 0 起
第 i 把的中心  row = R + t × cos(Phi)
              col = C + t × sin(Phi)
每把的 Phi、L1 = 与搜索区相同                    // 只挪中心、只改半宽
N = 1           → 整块搜索区就是那把卡尺
```

所以**卡尺堆得再密也不会互相污染**，但也**不会因为更密而更准**——够用就停。
画布上显示的黄框就是这 N 个小矩形本身（与测量用的参数同源，所见即所测）。

**圆形搜索区不一样**：N 把卡尺沿**圆周**均布，每把的扫描方向取该点的**径向**（圆周正好垂直于半径），
沿半径 ±环宽/2 内扫——圆心/半径手摆不准时，真实圆边只要落在环内照样扫得到。

```
弧间距 spacing  = 2π × 半径 / N
半长（径向）    = max(环宽 / 2, 1)
半宽（平均窗）  = min(3.0, max(spacing / 2, 0.5))   // 默认 3px 窗口，间距更小时让位给间距
第 i 把角度     a = 2π × i / N
第 i 把中心     row = 圆心行 + 半径 × sin(a)
               col = 圆心列 + 半径 × cos(a)
卡尺 Phi        = −a                              // 该约定下矩形的长轴正好落在径向
```

## 三、"全部"这个选择到底取哪个点（最容易被误解的口径）

一条卡尺上有多条边时，界面上的「选择」确实会传给算子，但**本插件对结果的取法是固定的**：

- 每把卡尺**统一取第一个检出点**（宽度类型取**第一对边**）；
- 「选择」= 第一条 与 = 全部 → **拿到的是同一个点**；
- 只有「选择」= 最后一条 会换到扫描方向的另一头。

所以"全部"并不会把多条边都算进来，**别指望选"全部"能取到最外侧那条边**，那是"最后一条"的活。
界面上「选择」的提示写的是"宽度/间隙取第一条配对，两点距取每个搜索区的第一条"，与此一致。

## 四、必须全检 + 最多 4 次重试

- **必须全检**：只要有**一把**卡尺找不到边就整轮失败。用检到的那几把平均出一个"看似合理"的数，
  是计量最危险的错法（错了但不报错），所以这里选择宁可失败。
- **找边最多试 4 遍**：HALCON 的 measure 算子同参首跑偶尔返回 0 条边（实测同参连跑三遍是 0/1/1 条），
  插件对每把卡尺重试到 4 次。真的没边时第 4 次仍然空、照样失败——
  它只兜"偶发首跑空"，**不改判定口径**，也不会把"确实没边"变成"有边"。
- **越界参数静默夹取**，NaN/Infinity 一律按最小值处理：坏配置最多让结果不对，绝不能把流程崩掉。
  （Sigma 填 0 会让算子抛参数错、中心在图外会抛越界错，这些英文错误码不该出现在现场，
  所以下限按算子要求抬到 0.4，中心越界提前用中文拦下并指名是哪个区。）

## 五、为什么要拟合：边点是散点，规格要的是"一条边"

两点距之后的三种量（点到线距、圆直径、角度）的规格对象是**几何**，不是某个像素点。
所以先把 N 个边缘点连成轮廓，再拟合成直线/圆，最后在这个几何上取数。好处有两个：

- **抗噪**：一个毛刺点被鲁棒算法降权，拽不歪整条线；
- **口径正确**：点到线距量的是"点到**无限直线**的垂距"，不是"到那条线段最近点的距离"——
  垂足落在线段延长线外面照样算，这才是形位公差里的位置度/垂直度算法。

拟合算子的**内部固定参数**（界面上不开放，写在这里是为了遇到退化时报错能看懂）：

```
直线：maxNumPoints = -1（全部点参与）、clipEndPoints = 0、iterations = 5、clippingFactor = 2.0
圆  ：maxNumPoints = -1、maxClosureDeviation = 0（要求闭合轮廓）、clippingEndPoints = 0、
      iterations = 5、clippingFactor = 2.0
```

- **残差口径是"中位数"不是"最大值"**：算的是所有边缘点到拟合几何距离的**中位数**，
  超过「最大残差(px)」才判失败。按最大值检查的话，一个毛刺离群点就会把鲁棒算法已经正确拟合的结果判死，
  抗离群就没有意义了；中位数与 Tukey 的容错哲学一致（少数离群点拉不动中位数）。
- 直线轮廓按卡尺排列顺序连成**开放**折线；圆连成**闭合**折线（首点复制到末尾）。
- **`FittedGeometry` 端口的语义按类型分**：拟合类给真正的拟合几何（拟合直线 / 整圆轮廓 / 角度的两条拟合线）；
  宽度与两点距没有拟合，沿用"测量连线"（历史语义保持不变，别指望它一定是拟合结果）。
- 圆的显示轮廓用 `gen_circle_contour_xld` 另生成整圆（点间距取半径的 1% 左右、夹在 0.05~5px），
  与离散边缘点无关，所以品红圆看着平滑不代表点密。

## 六、圆退化怎么拦（三条几何判据）

鲁棒拟合算法遇到共线/过扁的点集**不会报错**，而是收敛到一个"贴住少数点的小圆"——
半径有限、残差中位数也可能因降权而达标。所以除了"算子抛异常"这条，插件再加三条几何判据：

| 判据 | 拦截的是什么 |
| --- | --- |
| 半径必须有限、为正，且不超过图像对角线的 10 倍 | 点近共线时算子给出的天文数字半径（"任何大圆都能贴住它"） |
| 边缘点两两最大跨度 < 2px | 所有点挤成一坨（圆画得极小，或把直线边当成圆） |
| 拟合圆直径 < 点集跨度的 60% | 小圆包不住点集，必是退化解（真实圆周上均布的点，最大跨度约等于直径；3 点 120° 均布也有 1.73 倍半径） |

三条都是**明确失败**而不是给一个可疑直径。处置方向都一样：让圆套住**整个**圆周、加大「卡尺数」，
被测是弧/椭圆时本类型不适用。加大「环宽」救不了这条（问题不是扫不到边，而是扫到的边太少太扁）。

## 七、角度：为什么落在 0~180°

两条拟合线求交点后，把两条线**归一化成"从交点指向点分布远端"的射线**（比较两端点到交点的距离，取远的那一端），
再取夹角绝对值并换算成度。

```
叉积判平行：|cross| < 0.0017 × |u1| × |u2|  → 夹角小于约 0.1°，交点数值上跑无限远
                                              → 明确报"两条拟合直线接近平行"，不硬算
归一化取向：每条线取离交点更远的那个端点作为射线方向
最终值     = |angle_ll| × 180 / π   ∈ [0°, 180°]
```

不做这层归一化时，结果依赖拟合线段端点的输出顺序，会把 150° 的楔角报成 −30°。
样图实测 30°/90°/150° 三种楔角得 29.91°/90°/150.1°。
**角度不乘像素当量**（量纲无关量）——这也是"结果整体偏一个倍数时，用角度对不对来反推只有当量错了"的依据。

## 八、物理值、偏差与判定

```
像素测量值 MeasureValuePx   （由类型决定：宽度=第一对边的对内间距取 N 把平均；两点距=distance_pp；
                             点线距=distance_pl 垂距；圆直径=2×拟合半径；角度=归一化夹角）
物理值     MeasureValue     = 角度 ? MeasureValuePx : MeasureValuePx × 生效像素当量
偏差       Deviation        = MeasureValue − 标准值
判定       IsOk             = 下公差 − 容差 ≤ Deviation ≤ 上公差 + 容差   （容差 1e-9，正好等于边界算 OK）
```

- **NG 不是失败**：超限只是正常结果，`Success` 保持 true，原因写进 `ErrorMessage`。分流请判 `IsOk`，
  **不要用步骤的红绿**。
- **样图实测当量口径**：当量从 1.0 改成 0.5 时，点到线距 196.5→98.25、圆直径 199.917→99.958，而角度仍是 29.91°。
- **像素当量以连线为权威**：接了 `MmPerPixel` 就用上游值；上游 ≤0/NaN 时明确失败并给两条处置
  （查上游标定本轮是否成功 / 断开连线改手填）。拿错当量 = 所有长度值整体缩放错，所以这里**不静默回退**——
  与「标定」插件"失配必须报"的纪律一致。

## 九、显示层与判定层分工

- 标注图只是给人看的：渲染失败只丢 `MeasureImage` 并记一条 Warn，**一次成功的测量仍然算成功**；
- 反过来测量失败时预览直接清空，画布上没有底图（算法失败就没有"对的结果"可画）；
- 底图的通道数/位深归一化（多通道丢 alpha、非 byte 按实际灰度范围拉伸）由**全仓库共享的渲染烘焙件**负责，
  本插件只声明"画哪几层、什么颜色、文字写什么"，不自己开窗——所以这里出现的颜色与图层顺序就是产物上的最终顺序。

## 十、没有的开关与节拍口径

- **本算子没有"禁用某把卡尺""透传""超时"这类开关**：可调的就是第 3 页那 16 个字段加画布上的搜索区。
  要"跳过这一步"，在流程里停用它或删掉步骤，不要指望参数置 0；
- **耗时 ≈ 卡尺数 × 每把的剖面计算 + （拟合类）一次拟合 + 一次离屏渲染**：
  所以砍节拍按顺序砍——`卡尺数 N`（最直接，每把一次测量）→ `插值方式` 降到最近邻（丢亚像素）→ 缩小搜索区。
  **不要砍 `最大残差` 或公差**来"提速"：那不省时间，只是把质量闸门拆了；
- **可并行**：本算子声明为线程安全（纯视觉计算、无共享状态），多步骤并行执行时各自跑各自的实例；
- **配置态预览**与产线运行共用同一段算法核心（`ExecuteMeasureCore`），所以"界面里看到的"与"跑出来的"口径一致，
  但预览只在配置实例上跑，产线每帧不会多算一遍。
