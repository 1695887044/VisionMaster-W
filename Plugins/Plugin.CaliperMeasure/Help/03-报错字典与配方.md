# 卡尺测量 · 报错字典与现场配方

这一页是给"现场站着、屏幕上报错、手上没有源码"的人用的：
先用第一节症状表定方向，再用第二节报错字典按原文查那一条，最后按第三节配方库成套调参。

**字典口径**：加粗引号里的文字是插件写到信息栏/`ErrorMessage`/日志里的**原文**（逐字照抄源码），
其中 `{…}` 是运行时填进去的实际数字或名字，其余文字一字不改。
`{步骤名}` 就是流程栏里这个步骤显示的名字。

## 一、现场现象 → 先查什么

| 看到什么 | 先查哪一项 | 为什么是它 |
| --- | --- | --- |
| 一打开就报"输入图像为空或未初始化" | 「输入图像」行有没有连线/没有指定图片；上游步骤本轮是否失败 | 端口拿到的是空对象或未初始化的图，算法一行都没跑 |
| 报"第 N 把卡尺未检出成对边缘/未检出边缘" | 先看**方向**：黄框的 L1 有没有横跨被测边（Phi 对不对），再看阈值、极性 | 方向错时降阈值、改极性都救不回来，而文案给的三个候选里方向是第一个 |
| 报"…中心 (行, 列) 超出图像范围（宽×高）" | 搜索区中心坐标；图是不是被上游换了尺寸 | 中心在图外时算子会抛英文错误码，插件提前拦下并指名道姓；上游裁剪/缩放改过坐标系就会整体错位 |
| 报"当前测量类型需要 N 个…搜索区，实际只有 M 个" | 「搜索区列表」的行数与顺序（**只取前 N 个**） | 区被删过、或多余的区排在前面把位置占了 |
| 报"…不是圆形 / 不是矩形" | 该区在画布上的形状 | 圆直径只收圆形区，其余四种只收矩形；别的形状是右键误建 |
| 报"半径过小 / 尺寸过小（半长 L1、半宽 L2）" | `参数微调` 里 L1/L2/半径 的值 | 小于 1px 是退化几何，喂给算子只会得到无意义结果 |
| 报"像素当量来自上游连线但无效（0）" | 上游「标定」步骤本轮有没有成功、链接的变量有没有值 | 接了线就以连线为权威，插件**不会**拿手填旧值硬算——这是防"整批尺寸缩放错" |
| 报"不支持的图像通道数：4" | 上游给的什么图（带 alpha 的合成分辨率图、四通道特殊图） | 只吃 1 通道灰度和 3 通道彩色；先在前面转成灰度 |
| 报"拟合残差过大（主体点残差 …）" | 边缘点里有没有杂边；特征本身弯不弯；`拟合方式` 是不是被改成最小二乘 | 口径是**中位数**——半数以上的点离拟合几何超过 1px，说明点集本身有问题，不是阈值紧 |
| 报"只收集到 N 个边缘点，少于最少点数" | `卡尺数 N` 与 `最少点数` 的大小关系 | 可用点数 ≤ 卡尺数；`N` 比 `最少点数` 小就一定报 |
| 报"拟合圆退化…" | 圆形区有没有套住**整个**圆周、卡尺数够不够 | 只扫到一小段弧 → 点近共线 → 鲁棒算法会收敛到一个贴住少数点的小圆，插件用几何判据拦下来 |
| 报"两条拟合直线接近平行" | 两个区压的是不是**两条相交**的边 | 夹角小于约 0.1° 时交点跑到很远，角度数值上不可信，硬算出来的是垃圾 |
| 判定一直 NG | `标准值` / `上公差` / `下公差` 是不是还在默认的 0/0/0 | 出厂就是零容忍；`Success` 是绿的、只有判定红，说明测量没问题、规格没填 |
| 数值整体偏大或偏小一个倍数 | `MmPerPixel` 连的是哪一步、手填「像素当量」是多少 | 当量错了所有长度类同比例错；**角度不受影响**，可以用角度对不对来反推"只有当量错了" |
| 数值来回抖 | `卡尺数 N`、`平滑 Sigma`、绿十字有没有落在毛刺上 | 多点平均是这里最主要的抗噪手段；十字位置肉眼乱跳就不是参数问题，是摆位问题 |
| 预览区一片空白、信息栏红字 | 信息栏那句失败原因（预览失败时**不画标注图**、底图也会清空） | 预览和运行共用同一段算法核心：算法失败就没有图。先按红字修配置，不是界面坏了 |
| 改了数值预览不动 | 「参数微调」的文本框要**失去焦点**才写回；别的框是即时（约 200ms 防抖） | 微调行绑定的是失焦提交；按 Tab 或点一下画布就刷新 |
| 量到的数"很稳定地错" | `极性` 与 `选择`：是不是锁在了隔壁那条边上 | 稳定 ≠ 正确。看青色连线连的到底是哪两点就能识破 |

## 二、报错字典（全量）

### A. 输入与配置类（14 条）

**1. 「输入图像为空：请为上方「输入图像」指定图片，或连接上游图像端口」**（橙字，只在配置界面出现）
- 触发：预览路径上 `SrcImage` 端口为空或图像未初始化。
- 现场通常：刚把步骤拖进来还没接线；或者接了上游但还没运行过、上游本轮没出图。
- 处置：在「输入图像」行指定一张图，或连上上游图像输出后试运行一次。

**2. 「输入图像为空或未初始化」**
- 触发：运行路径（`RunAlgorithm`）上 `SrcImage` 为空或未初始化，本步骤直接判失败。
- 现场通常：上游采集失败、连到了别的步骤的端口、或连的是**变量**而变量本轮没图。
- 处置：先让上游出图；确认连的是图像端口而不是数值端口。失败轮 `MeasureValue=0`、`IsOk=false`，下游不会拿到上一件的数。

**3. 「卡尺测量失败：{异常信息}」**
- 触发：算法核心抛出异常被兜住（不是上面任何一条已写明的失败路径），本步骤判失败。
- 现场通常：HALCON 原生库异常、极端脏配置（如搜索区参数是 NaN 之外的怪异值）、内存不足。
- 处置：把花括号里的原文抄下来查；先按第 2 页第三节把参数逐项回默认，再换一张图复现。能稳定复现的话记下"类型 + 图 + 参数"。

**4. 「预览失败：{异常信息}」**（红字，只在配置界面出现）
- 触发：预览路径捕获到异常（同上，但走的是界面而不是流程）。
- 现场通常：同 3；预览**不弹框、不抛异常**，只把原因写在信息栏。
- 处置：改参数重试即可；不要把它当成"界面坏了"，它是把算法异常原样转给你看。

**5. 「不支持的图像通道数：{n}（仅支持 1 通道灰度或 3 通道彩色）」**
- 触发：`count_channels` 返回不是 1 也不是 3（例如带 alpha 的 4 通道图）。
- 现场通常：上游是合成分辨率图/模拟器出的 RGBA 图；或某一步改过通道数。
- 处置：在卡尺前面插一个转灰度的步骤（预处理族），或改接原始灰度源。这里**不猜**你要哪个通道。

**6. 「像素当量来自上游连线但无效（{值}）：请检查上游（「标定」步骤本轮是否成功 / 链接的变量是否有值），或改用手填像素当量并断开该连线」**
- 触发：`MmPerPixel` **有连线**，但取到的值 ≤0、NaN 或 Infinity。
- 现场通常：标定本轮失配失败（输出端口归 0）、链接的运行时变量没赋过值、连到了别的 double 端口。
- 处置：二选一——① 让上游标定先跑成功；② 断开这条连线，用「⑤ 判定与标定」的手填「像素当量」。**不会静默回退**，因为拿错当量 = 所有长度值整体缩放错。

**7. 「当前测量类型需要 {需要数} 个{圆形/矩形}搜索区，实际只有 {实际数} 个：请在画布上右键新建，或点「重置搜索区」」**
- 触发：列表里的区数量不够（宽度/圆直径要 1 个，两点距/点到线距/角度要 2 个）。
- 现场通常：手工删过搜索区；切换类型后没补；方案是从别的类型改过来的。
- 处置：画布右键新建，或点「重置搜索区」（注意它会**清掉现有区域**重建默认位置，摆好的区要重新拖）。

**8. 「搜索区「{区名}」不是圆形：圆直径测量需要圆形搜索区（请删除该搜索区后，在画布右键 → 区域 → 新建圆形）」**
- 触发：类型=圆直径，但取到的第一个区形状不是圆形。
- 现场通常：先用矩形摆好了位置再切到圆直径——切类型只补数量、不改形状（有意不改，绝不擅动你摆的区）。
- 处置：删掉那个矩形区，右键新建圆形，套住真实圆周。

**9. 「搜索区「{区名}」参数不完整（需要 圆心行/圆心列/半径 三项）」**
- 触发：圆形区的参数数组少于 3 个数。
- 现场通常：手改过方案文件；或旧版本方案里的区形状与参数对不上。
- 处置：删掉该区重建；别去手补 JSON。

**10. 「搜索区「{区名}」半径过小（{半径}，需 ≥ 1）：请拖大圆形搜索区或在参数微调里改大」**
- 触发：圆形区半径（取绝对值后）< 1px。
- 现场通常：区缩成一个点（误拖手柄）。
- 处置：拖大或在 `参数微调` 的「半径(Radius)」填一个真实像素半径；半径也决定圆周卡尺的分布位置。

**11. 「搜索区「{区名}」不是矩形：{点到线距/角度/卡尺测量}只支持矩形搜索区（请删除该形状后新建矩形）」**
- 触发：非圆直径类型下取到的区不是矩形（中间那一项按类型换成"点到线距""角度"，其余情况写"卡尺测量"）。
- 现场通常：右键误建了圆形/椭圆区。
- 处置：删掉该区，新建矩形。椭圆也不收——卡尺阵列只在矩形/圆周上均布。

**12. 「搜索区「{区名}」参数不完整（需要 中心行/中心列/角度/半长/半宽 五项）」**
- 触发：矩形区参数数组少于 5 个数。
- 现场通常：手改过方案文件、跨版本残留。
- 处置：删掉重建。

**13. 「搜索区「{区名}」尺寸过小（半长 L1={值}、半宽 L2={值}，两者都需 ≥ 1）：请拖大搜索区或在参数微调里改大」**
- 触发：|L1| 或 |L2| < 1px（两者取绝对值判断）。
- 现场通常：区被拖成一条线/一个点。
- 处置：拖大。**注意**：L1 是扫描方向、L2 是阵列方向，只拖大"错的那一维"才有意义（L1 短=扫不到边，L2 短=阵列挤在一起）。

**14. 「搜索区「{区名}」中心 ({行}, {列}) 超出图像范围（{宽}×{高}）：请把搜索区拖到图像内」**
- 触发：矩形区中心行 <0 或 ≥ 图高，或中心列 <0 或 ≥ 图宽。
- 现场通常：把区拖出画面；或上游换了图像尺寸（裁剪/缩放后坐标系变了）。
- 处置：拖回图内；若上游改过尺寸，重新对一遍所有区的位置。插件**不静默截半**——中心在图外时算子会抛英文码 `#3022`，这里提前用中文说清是哪个区、中心在哪、图多大。

### B. 边缘提取类（5 条）

**15. 「第 {序号} 把卡尺未检出成对边缘（共 {N} 把）：请降低边缘阈值、放宽极性，或调整/放大搜索区」**
- 触发：类型=宽度/间隙，第 序号 把卡尺的 `measure_pairs` 重试到第 4 遍仍然 0 对边（共 N 把）。
- 现场通常：① 矩形没**横跨**边（Phi 转了 90°，或 L1 短到穿不过去）——最常见；② 阈值太大（弱边）；③ 极性单方向选反；④ 那个位置本来没有成对特征（缝的一侧被裁掉了）。
- 处置：按顺序自查：黄框朝向 → `边缘阈值` 降到 10~15 → `极性` 回"全部"跑一遍 → 加长 L1 或整体放大搜索区。**只要有一把检不到就整轮失败**，这是有意的（不"部分平均"）。

**16. 「第 {区序} 个搜索区的第 {序号} 把卡尺未检出边缘（共 {N} 把）：请降低边缘阈值、放宽极性，或调整/放大搜索区」**
- 触发：两点距/点到线距/角度下，某个矩形区的第 序号 把卡尺 `measure_pos` 重试 4 遍仍 0 点。
- 现场通常：同 15；另外常见"第 2 个区"根本没压在特征上（区1 当点、区2 当线，摆串了）。
- 处置：文案里的"第几个搜索区"就按 `搜索区列表` 的顺序数；先把那个区挪到真实特征上，再动阈值。

**17. 「搜索区「{区名}」圆心 ({行}, {列}) 超出图像范围（{宽}×{高}）：请把圆搜索区拖到图像内」**
- 触发：圆直径类型下圆心落在图像外。
- 现场通常：把圆拖出画面；或图被上游换尺寸。
- 处置：拖回图内。注意这里只判**圆心**——圆周卡尺中心越界另有专门文案（第 19 条）。

**18. 「第 {序号} 把圆周卡尺中心 ({行}, {列}) 超出图像范围（{宽}×{高}）：请把圆搜索区拖离图像边缘、缩小半径或减小环宽」**
- 触发：圆心在图内，但沿圆周均布的某把卡尺中心跑到图外（圆太大、贴边）。
- 现场通常：圆压着图像边缘；半径 + 位置把某个角的卡尺推出画面。
- 处置：三选一——把圆拖离边缘 / 缩小半径 / 减小「环宽(px)」。真件就在边缘装不下时，改用矩形区分段量弧，或上游先裁剪出局部视野再量。

**19. 「第 {序号} 把圆周卡尺未检出边缘（共 {N} 把）：请降低边缘阈值、放宽极性，或增大环宽（真实圆边可能在环外）」**
- 触发：某把径向卡尺在 ±环宽/2 的扫描范围内检不到边。
- 现场通常：手画的圆半径/圆心偏得多于环宽一半（默认 30 → ±15px 容差）；孔边对比太弱；圆周上某段被脏污/遮挡。
- 处置：先加大「环宽(px)」把真实圆边纳进扫描带（别加太狠，会扫进隔壁特征）；再降阈值；某段确实没有边就重新套圆或避开缺陷段。

### C. 拟合类（12 条）

**20. 「搜索区「{区名}」只收集到 {点数} 个边缘点，少于最少点数 {最少点数}：请增大卡尺数，或降低「最少点数」」**
- 触发：点到线距/角度中，**该命名区**（直线那条）可用点数 < `最少点数`。
- 现场通常：`卡尺数 N` 比 `最少点数` 小（例如 N=3、最少点数=5）；或该区某把检不到（那就先报第 16 条）。
- 处置：优先增大 `卡尺数`（多点多冗余才是拟合的本意）；`最少点数` 调小是降质量闸门，只在点确实稀缺时用。

**21. 「拟合直线失败（搜索区「{区名}」）：边缘点可能全部重合或分布退化——请检查搜索区是否压在一条干净、连续的特征边上（原始算子信息：{算子原文}）」**
- 触发：`fit_line_contour_xld` 抛异常（点全部重合、分布退化）。
- 现场通常：所有卡尺扫到同一个位置（N 把挤成一堆、L2 太小）；区太小；特征不是一条直线。
- 处置：把区沿边方向（L2）拉长、放大 L1；确认这段是真的直线边。花括号里的算子原文照抄进问题记录即可，不影响处置方向。

**22. 「拟合直线失败（搜索区「{区名}」）：拟合结果是一条零长度线段（边缘点全部重合）——请检查搜索区位置」**
- 触发：拟合出的线段两端点距离 < 1e-9（点全重合）。
- 现场通常：所有卡尺检到同一个点（例如区压在**一个**小特征上，而不是压在**一条**边上）。
- 处置：把区拉开、让它沿边方向覆盖一段真实长度；两点距场景别用"点当线"。

**23. 「搜索区「{区名}」拟合残差过大（主体点残差 {中位数} px > 允许 {最大残差} px）：边缘点可能混入毛刺/杂边，或特征本身弯曲——请增大卡尺数、增大平滑 Sigma，或把搜索区挪到更直的边缘上」**
- 触发：边缘点到拟合直线的距离**中位数** > `最大残差`。
- 现场通常：搜索区里有杂边/毛刺；被测边本来就是弧/弯的；`拟合方式` 被换成最小二乘（一个坏点就能把线拽歪，残差随之爆）。
- 处置：先把 `拟合方式` 确认在 Tukey；加大 `卡尺数`、加大 `Sigma`；**把区挪到更直的段落**（最有效）；只有确认现场确实允许这么大残差才放大 `最大残差`，不要顺手填 10。

**24. 「拟合圆至少需要 3 个边缘点（当前 {点数} 个）：请增大卡尺数」**
- 触发：圆直径下点数 < 3（数学下限，3 点才定圆）。
- 现场通常：`卡尺数` 被填成 2 或 1。
- 处置：`卡尺数` 至少 3；圆直径实际建议 16 上下（点少必共线 → 报第 27~29 条的退化）。

**25. 「只收集到 {点数} 个边缘点，少于最少点数 {最少点数}：请增大卡尺数，或降低「最少点数」」**
- 触发：圆直径下点数 < `最少点数`（文案与第 20 条同族，但不带区名——圆只有一个区）。
- 现场通常：`最少点数` 填得比 `卡尺数` 大。
- 处置：加大 `卡尺数`；或把 `最少点数` 降到不超过可用点数（注意圆还额外受 3 点数学下限约束）。

**26. 「拟合圆失败：边缘点可能接近共线或全部重合（圆退化）——请检查圆搜索区是否套住圆周特征、并增大卡尺数（原始算子信息：{算子原文}）」**
- 触发：`fit_circle_contour_xld` 抛异常。
- 现场通常：只扫到圆周的一小段弧；点全落在同一条边上（被测根本不是圆）。
- 处置：让圆套住**整个**圆周（画在真实圆周边上），`卡尺数` 加到 16 上下。

**27. 「拟合圆退化：边缘点接近共线或分布过扁，无法确定合理的圆（估算半径 {半径}）——请让圆搜索区套住整个圆周特征、增大卡尺数，并确认被测特征确实是圆」**
- 触发：算子给了半径但不成话——非有限值 / ≤0 / 大于图像对角线的 10 倍。
- 现场通常：点近共线（只扫到一小段弧），数学上"任何大圆都能贴住它"。
- 处置：加大 `环宽` 没用（问题不是扫不到边而是扫到的边太少太扁）；重画圆、加卡尺数、必要时换测量类型。

**28. 「拟合圆退化：{点数} 个边缘点几乎重合（跨度仅 {跨度} px，特征可能是直线边缘而非圆周）——请确认被测特征是圆、并让圆搜索区套住整个圆周」**
- 触发：所有边缘点两两最大距离 < 2px（点挤成一坨）。
- 现场通常：圆画得极小；或圆周上全是同一处反光点。
- 处置：把圆画到真实孔径/轴径尺度；检查是不是把直线边当成了圆。

**29. 「拟合圆退化：边缘点接近共线或分布过扁，拟合出的圆（直径 {直径} px）远小于点集跨度（{跨度} px）——请让圆搜索区套住整个圆周特征、增大卡尺数，并确认被测特征确实是圆」**
- 触发：拟合圆直径 < 点集跨度的 60%。真实圆周上均布的点，最大跨度约等于直径（3 点 120° 均布也有 1.73 倍半径），"圆包不住点"必是退化解。
- 现场通常：**鲁棒算法（geotukey/geohuber）遇到共线点不报错，而是收敛到一个贴住少数点的小圆**——半径有限、残差也可能达标，前两条拦不住，靠这条几何判据拦。
- 处置：把圆形搜索区重新套在整个圆周上（不是套在半边）、加大 `卡尺数`；被测是弧/椭圆的话本类型不适用。

**30. 「拟合残差过大（主体点残差 {中位数} px > 允许 {最大残差} px）：边缘点可能混入毛刺/杂边，或被测特征不是圆——请增大卡尺数、增大平滑 Sigma，或检查特征」**
- 触发：圆直径下点到拟合圆的距离中位数 > `最大残差`（文案与第 23 条同族，圆没有区名）。
- 现场通常：孔边有缺口/毛刺；圆周某段被脏污盖住；被测是椭圆或带倒角；`环宽` 太大扫进隔壁特征。
- 处置：先减小 `环宽` 排除扫错边；再加 `卡尺数`、加 `Sigma`；确认特征真是圆；最后才适度放宽 `最大残差`。

**31. 「两条拟合直线接近平行，无法确定夹角：请让两个搜索区分别压在两条相交的特征边上」**
- 触发：两条拟合线方向向量的叉积模小于约 0.0017 倍（夹角 < ~0.1°），交点在数值上跑无限远。
- 现场通常：两个区压在同一条边的两段上；测的其实是两条平行边（那不该用角度类型）。
- 处置：让两个区压在**真正相交**的两条边上（V 形槽两侧、直角两边）。要量平行边间距就换「宽度/间隙」或「两点距」。

### D. 判定类（2 条）

这两条**不是执行失败**：`Success` 仍为 true，步骤不标红；文字写进 `ErrorMessage`，摘要行里带"（…）"，信息栏红字。分流请用 `IsOk`。

**32. 「偏差 {带符号偏差} 超出上公差（上公差 {上公差}）」**
- 触发：`Deviation` > `上公差`（判定加了 1e-9 容差，正好等于边界算 OK）。偏差格式带符号显示（测大为正）。
- 现场通常：`标准值` 还是默认 0（任何正的测量值都会"超上公差"）；或工件确实偏大。
- 处置：先确认规格填了（`标准值` + 上下公差，单位与测量值一致）；规格没错就当真超差，接报警/分拣。

**33. 「偏差 {带符号偏差} 超出下公差（下公差 {下公差}）」**
- 触发：`Deviation` < `下公差`。
- 现场通常：`下公差` 忘了填负数（非对称公差要填负，例如 +0.05 / −0.02）；或当量偏小导致读数系统性偏小。
- 处置：核对公差方向；用第 11 步的"当量翻倍、测量值应翻倍"验一次当量。

### E. 显示类（1 条）

**34. 「{步骤名} 标注图渲染失败，MeasureImage 将为空：{异常信息}」**（Warn 日志，只在流程日志里）
- 触发：测量已经成功，但离屏渲染标注图时抛异常。
- 现场通常：显示/内存资源紧张、极端图像尺寸。
- 处置：**不用管测量结论**——`MeasureValue`/`Deviation`/`IsOk` 全有效，只是 `MeasureImage` 这轮为空。
  要图就先修渲染侧条件（换窗口、减小图、重启宿主）；判定与 CSV 记录不受它影响。这是"显示层不能把成功的测量判成失败"的分工。

## 三、分场景配方库

配方是**成套起步值**，不是现场保证；每个都写"先调哪一格"。
所有取值都在合法区间内，超出会被静默夹取（区间见第 2 页第二节）。

### 配方 1｜高反光金属件的边（局部饱和、镜面亮带）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 按尺寸选（多数是「宽度/间隙」或「点到线距」） |
| 卡尺数 N | 8~16 |
| 平滑 Sigma | 1.5~2.0 |
| 边缘阈值 | 30~60（**抬高**，让反光纹理不算边） |
| 极性 | 单方向（按扫描方向定：暗区→亮件选"暗→亮"，反之选"亮→暗"） |
| 选择 | 第一条（或"最后一条"，取决于哪一侧是真实边） |
| 插值方式 | 双线性 |
| 拟合方式 | Tukey |
| 最大残差 | 1.0（不要放宽） |

- 为什么这么配：反光在剖面上表现为"小幅高频起伏"，用**高阈值 + 强平滑**把它压到阈值以下，只留真实的那一次大跳变；极性收紧直接把另一半候选挡掉。
- 预期：绿十字全部落在同一条边上、不随反光斑移动；重复跑 20 次的极差明显小于放宽阈值的版本。
- 现场先调哪一格：**`边缘阈值`**。先往上抬到"检不到边"，再退回上一档——那个位置就是真实边与反光的分离点。

### 配方 2｜低对比印刷字符边 / 浅色打标（弱边）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 「宽度/间隙」（笔画宽）或「两点距」（字间距） |
| 卡尺数 N | 3~5（字符小，区也小，别堆太多把相邻笔画扫进来） |
| 平滑 Sigma | 1.0~1.5 |
| 边缘阈值 | 8~15（**降**） |
| 极性 | 单方向（字符比底色暗：扫过去是"亮→暗"） |
| 插值方式 | 双三次 |
| L1（半长） | 刚好跨过笔画 + 两侧各几像素余量 |

- 为什么这么配：弱边的导数峰值本来就低，阈值必须降；降阈值带来的噪声用"单方向极性 + 平滑"补回去；双三次在弱过渡上给出的亚像素位置更连续。
- 预期：某一把卡尺报"未检出"时，先降阈值就能出边；出边后绿十字位置肉眼贴笔画。
- 现场先调哪一格：**`边缘阈值`**（降），紧接着检查 `极性` 有没有反（反了会整条检不到）。

### 配方 3｜细窄透明件（玻璃/膜片边缘，过渡很薄）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 「宽度/间隙」或「点到线距」 |
| 卡尺数 N | 5~10 |
| 平滑 Sigma | **0.4~0.8**（下限附近，别糊掉薄过渡） |
| 边缘阈值 | 5~12 |
| 极性 | 单方向（透明边常只在"暗→亮"一侧有干净跳变，另一侧是缓变） |
| 选择 | 第一条 |
| 插值方式 | 双三次 |
| 像素当量 | 建议接标定；薄件对当量误差最敏感 |

- 为什么这么配：透明件的边是**很窄的过渡带**，Sigma 一大就被抹平（这里下限 0.4，填 0 会被夹到 0.4，不是"关掉平滑"）；靠单方向极性只取那一侧的锐利跳变。
- 预期：检出点稳定在同一侧；若数值随光照漂，多半是取到了另一侧的缓变过渡。
- 现场先调哪一格：**`极性`（收成单方向）**，然后 `选择`（第一条/最后一条）换一侧对照，看哪一侧的重复性好。

### 配方 4｜深色橡胶弱边（黑件、边缘发虚、低灰度差）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 「宽度/间隙」/「圆直径」按对象 |
| 卡尺数 N | 10~16（黑件噪声大，靠多点平均救） |
| 平滑 Sigma | 2.0~3.0 |
| 边缘阈值 | 6~12 |
| 极性 | 单方向（暗件→亮背景：由内向外扫是"暗→亮"） |
| 插值方式 | 双三次 |
| 拟合方式 | Tukey（毛刺/飞边多，必须鲁棒） |
| 最大残差 | 1.0~2.0（发虚边允许略大） |
| 环宽（若圆） | 20~40 |

- 为什么这么配：橡胶边本身对比弱 + 常有飞边毛刺，所以"低阈值取到边 + 强平滑压噪 + 鲁棒拟合挡飞边"三件一起上，单靠一个参数都会失衡。
- 预期：`EdgePoints` 的十字贴住可见轮廓；偶发轮次报"未检出"时说明该处真的没边（脏污/重叠），不是参数问题。
- 现场先调哪一格：**`Sigma` 与 `边缘阈值` 一起**（Sigma 加大后导数峰值变小，阈值要同步往下调，不然会突然检不到边）。

### 配方 5｜双边测宽（胶条宽度 / 针脚间距 / 缝宽）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 「宽度/间隙」（`measure_pairs`，一次给出成对边） |
| 卡尺数 N | 5~8（胶条沿长度方向铺，L2 沿胶条方向） |
| L1（半长） | 缝宽的一半 + 两侧各 5~15px 余量（**必须穿得过两条边**） |
| L2（半宽） | 覆盖胶条长度方向的稳定段 |
| 平滑 Sigma | 1.0 |
| 边缘阈值 | 20~40（胶条对比通常够） |
| 极性 | 全部（宽度类型取第一对边；若第一对边不是胶条，改收紧） |
| 选择 | 全部（取第一对边）或第一条 |
| 标准值 | 图纸胶宽；上/下公差按允许宽窄波动 |

- 为什么这么配：宽度类型不需要拟合，`measure_pairs` 直接把"成对边"给你，第一对的 `IntraDistance` 就是宽度；所以 L1 的长度决定成败——它必须从一侧穿到另一侧。
- 预期：每个黄框里能看到**两条**绿十字、青线连在这两十字之间。
- 现场先调哪一格：**L1（半长）**。"未检出成对边缘"九成是 L1 短到只穿过一条边；其次才降阈值。
- 补一句：胶条宽度波动大就用「两点距」/「点到线距」分开量两条边，不要指望"全部"极性帮你挑对那一对。

### 配方 6｜圆孔定心与直径（孔径 / 轴径）

| 项 | 起步值 |
| --- | --- |
| 测量类型 | 「圆直径」（**只收圆形搜索区**） |
| 圆形区摆位 | 画在**真实圆周**上（不是套住圆心的一小块） |
| 卡尺数 N | **16~32**（点少必共线 → 圆退化） |
| 环宽(px) | 30（±15px 容差）；手摆误差大先 40~60，稳定后收回 |
| 平滑 Sigma | 1.0~1.5 |
| 边缘阈值 | 20~40 |
| 极性 | 由内向外扫：孔（内暗外亮）选"暗→亮"；实心轴选"亮→暗" |
| 拟合方式 | Tukey（走 geo 系列的 geotukey，界面不用你管） |
| 最少点数 | 3~8 |
| 最大残差 | 1.0（孔有缺口时先看残差再谈放宽） |

- 为什么这么配：直径 = 2×拟合半径，所以全部误差来自"拟合圆可不可信"。卡尺数与"套住整个圆周"决定点分布，环宽决定手摆误差能不能被容下；
  共线/过扁的点集会触发第 27~29 条的退化拦截，宁可不给数也不给一个假直径。
- 预期：品红整圆轮廓贴住孔边、青线是过圆心的直径线；`MeasureValue` 与量具读数同量级。
- 现场先调哪一格：**圆形区的半径/圆心摆位**。报"圆周卡尺未检出"才动 `环宽`；报"拟合圆退化"就是点分布问题，加 `卡尺数` 并重新套圆。
- 想要**圆心**坐标：本算子的输出是直径数值与几何 XLD（`FittedGeometry` 给的是整圆轮廓），
  要拿圆心坐标去驱动的，就把这条拟合圆轮廓交给下游的几何类算子处理。

## 四、常见问题

**Q：NG 会让流程变红、让后续不执行吗？**
不会。NG 是正常结果，`Success` 保持 true，只在 `ErrorMessage` 写"偏差…超出上/下公差…"。
分流请判 `IsOk`；用步骤红绿分流会把 NG 件当"步骤坏了"处理。

**Q：默认跑起来全是 NG，是不是坏了？**
不是。`标准值/上公差/下公差` 出厂 0/0/0 是**有意的零容忍**——通用算子不假装知道你产品的规格。
填法：标准值用图纸名义值（单位与测量值一致，角度类填度），上下公差填允许偏差幅度（下公差填负数）。

**Q：预览区一片空白，什么也看不见？**
先看信息栏那句话。预览与流程跑的是**同一个算法核心**，算法失败时不产标注图、底图也会清空——
所以"没图"通常是"没测成"，按红字那条查第二节。

**Q：改了 `参数微调` 里的数字，画布上的框不动？**
那一行的文本框是**失去焦点才写回**。按 Tab、或点一下画布别处就刷新。
其余数值框与下拉是即时生效（约 200ms 防抖后重算预览）。

**Q：按 Del 键删不掉搜索区？**
焦点在文本框里时 Del 被当成编辑键，删除命令被有意挡住（防误删）。先点一下列表里的区或画布空白处再按。

**Q：卡尺数从 5 加到 50，精度没怎么提升？**
正常。相邻卡尺间距 = 2×L2/N，半宽会被夹到"间距的一半"（下限 0.5px），
N 密到一定程度每把的取样窗口已经很小、再密也不会更准，只是更慢。够用就停（默认 5，圆直径 16 上下）。

**Q：`选择` 选了"全部"，为什么和"第一条"结果一样？**
本算子对"全部"的取值口径就是**每把卡尺的第一个检出点**（宽度取第一对边），不会把多条边都算进来。
要取另一头请明确选"最后一条"。

**Q：切换测量类型后，原来摆的区还在吗？**
在。切换**只补足缺的数量，绝不删**你摆好的区，也绝不改形状（形状不对会在运行时明确报第 8/11 条）。
注意运算**只取列表前 N 个**，多余的区请删掉以免占位。

**Q：角度为什么是 150 而不是 −30？会不会报成补角？**
两条拟合线被归一化成"从交点指向点分布远端"的射线后取绝对值，结果固定落在 0~180°（度）。
样图实测 30°/90°/150° 三种楔角得 29.91°/90°/150.1°。角度也不乘像素当量——量纲无关。

**Q：能不能一个步骤里量两个尺寸？**
不能，界面就写着"一个步骤只测一个尺寸"。加第二个卡尺测量步骤即可，
端口数量固定（不随卡尺数变），多步之间互不影响连线。

**Q：彩色图能直接测吗？4 通道呢？**
3 通道自动转灰度再测；1 通道直接用；其它通道数报第 5 条。要指定用哪个通道，请在前面用图像类算子先转好。

**Q：试运行的数和正式运行的数不一样？**
先看当量：试运行会把上游的当量值**桥接**进 `MmPerPixel` 端口，端口值优先于手填；
正式运行按连线走（接了就用上游、上游无效就判失败）。两边口径不同的话，多半是手填值与标定值不一致。

**Q：节拍太紧，能砍什么？**
按顺序砍：`卡尺数 N`（最直接，每把一次测量）→ `插值方式` 降到最近邻（丢亚像素）→ 缩小搜索区。
**不要砍 `最大残差` 或公差**来"提速"，那不省时间，只是把质量闸门拆了。
