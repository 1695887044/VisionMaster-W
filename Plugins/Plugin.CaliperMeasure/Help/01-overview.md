# 卡尺测量

> 分类：测量 ｜ 来源：插件 Plugin.CaliperMeasure

阵列式卡尺：在你摆的一个**搜索区**里自动均布 N 把卡尺做**亚像素找边**，支持**宽度/间隙、两点距、点到线距、圆直径、角度**五类量，
输出**物理值 + 与标准值的偏差 + OK/NG**，并给出标注图、拟合几何与原始边缘点。
**一个步骤只测一个尺寸**——界面上写得很明白，要测多个尺寸就加多个卡尺测量步骤。

## 一、定位：做什么、不做什么

| 它做 | 它不做（该找谁） |
| --- | --- |
| 量一个几何尺寸的**数值**并判 OK/NG | 定位目标在哪 → 「模板匹配」；匹配完的坐标可以拿来推着卡尺搜索区走 |
| 亚像素找边（边在两个像素之间也能给位置） | 有没有缺陷、缺陷多少 → 「Blob 缺陷检测」 |
| 把像素值乘标定当量换成 mm（角度除外） | 自己算当量 → 「标定」插件出 `MmPerPixel`，本算子只是接过来用 |
| 叠一张自带判定文字的标注图（`MeasureImage`） | 把**别的算子**的结果烧进图 → 「结果显示」；本算子只烧自己的四图层 |
| 输出一条线/一个圆/两个点这些几何（`FittedGeometry`、`EdgePoints`） | 裁剪、屏蔽、洗图 → 「ROI」「图像预处理」（它们改图，本算子只读图） |

## 二、为什么需要它

手工在图上画条线量距离，只量到**一个位置**：光照一变、毛刺一来，读数就漂。
卡尺的做法是把"在哪找边"这件事交给**灰度剖面**——沿扫描方向把灰度排成一条曲线，
曲线的**变化最陡处**就是边；再用多个位置上的边一起出结果，单个坏点的影响被摊薄。
这就是"阵列式"三个字的价值：**同一件东西量 N 次，而不是量 1 次赌运气。**

## 三、原理：卡尺怎么找边，为什么要投影与拟合

### 3.1 一把卡尺 = 一条会读数的尺子

一把卡尺就是一个可旋转的小矩形，参数是 `[中心行, 中心列, 角度 Phi, 半长 L1, 半宽 L2]`。
它**沿 L1 方向**从一侧推到另一侧，一路上把灰度记成一条曲线；
**垂直于扫描方向的 L2 那一段被平均掉**（投影）——这就是"卡尺半宽"的作用：
窗口太窄只剩单个像素的噪声，太宽会混进旁边不相干的特征。圆周卡尺的默认半宽取 3px 就是这个道理。

### 3.2 找边 = 在剖面上找"最陡"，再过两道闸

剖面上灰度变化最大的位置就是边（算子内部对剖面做高斯平滑 `Sigma` 后求导找极值，不是"像素值差一下就算"）。
极值还要过两道闸才作数：

- **边缘阈值**：相邻像素的最小灰度差。低于它的起伏只当纹理，不算边；
- **极性**：沿扫描方向只允许哪种明暗跳变（暗→亮 / 亮→暗 / 全部）。

过了闸的点，按 `插值方式` 给出**亚像素**位置（双线性/双三次能在两个像素之间定位，最近邻只能落在整像素上）。

### 3.3 N 把卡尺怎么排：矩形要「横跨」被测特征（硬事实）

| 方向 | 半轴 | 是什么 | 摆错了会怎样 |
| --- | --- | --- | --- |
| **L1（Phi 轴）** | 半长 | **扫描方向**——每把卡尺沿它推过去，检出的边**垂直于**它 | 扫不到边，直接报"未检出" |
| **L2（垂直 Phi）** | 半宽 | **阵列排布方向**——N 把卡尺沿它等分铺开，每把保留完整 L1 扫描长度 | 卡尺顺着扫描方向散开、各自扫到不同位置，平均出来的数没有意义 |

所以口诀是**矩形要"横跨"被测的边/缝**：测一条竖直边，L1 得指向水平方向，卡尺沿边本身的方向（L2）排开。
这条是拿真实 HALCON 实证过的：`Phi=0` 时 L1 沿水平，把 `L1=100/L2=10` 的矩形压在竖直亮带上能量出宽度；
把 L1 缩到 10（扫描线够不到边）或把 Phi 转 90°（扫描方向变竖直），都检不到边。

均布的算术口径：矩形把整段 L2 宽度等分成 N 份，相邻间距 = `2×L2/N`，每把的半宽 = 间距的一半（最小 0.5px），
所以**卡尺堆得再密也不会互相污染**，但也**不会因为更密而更准**——够用就停；`N=1` 时整块搜索区就是那把卡尺。
圆形搜索区不一样：N 把卡尺沿**圆周**均布，每把的扫描方向取该点的**径向**（圆周正好垂直于半径），
沿半径 ±环宽/2 内扫——圆心/半径手摆不准时，真实圆边只要落在环内照样扫得到。

### 3.4 为什么要拟合：边点是散点，规格要的是"一条边"

两点距之后那些量（点到线距、圆直径、角度）的规格对象是**几何**，不是某个像素点。
所以先把 N 个边缘点连成轮廓，再拟合成直线/圆（`fit_line_contour_xld`、`fit_circle_contour_xld`），
最后在这个几何上取数。好处有两个：

- **抗噪**：一个毛刺点被鲁棒算法降权，拽不歪整条线；
- **口径正确**：点到线距量的是"点到**无限直线**的垂距"，不是"到那条线段最近点的距离"——
  垂足落在线段延长线外面照样算，这才是形位公差里的位置度/垂直度算法。

拟合的固定内部参数（界面上不开放，写在这里是为了你遇到退化时报错能看懂）：
`maxNumPoints=-1`（全部点参与）、`iterations=5`、`clippingFactor=2.0`、直线 `clipEndPoints=0`、圆要求闭合轮廓。

### 3.5 像素 → 物理

长度类 = 像素测量值 × **生效像素当量**（mm/px）；**角度不乘当量**——它是量纲无关量，永远是度。
样图实测这条是硬的：当量从 1.0 改成 0.5 时，点到线距 196.5→98.25、圆直径 199.917→99.958，而角度仍是 29.91°。

## 四、五种测量类型怎么算出来的

| 类型（界面中文） | 搜索区 | 算法链 | 测量值口径 |
| --- | --- | --- | --- |
| 宽度/间隙（`Width`） | 1 个矩形 | `measure_pairs` | 一次给出**成对边**，取第一对边的对内间距（`IntraDistance`）为这把卡尺的宽度；N 把取**平均** |
| 两点距（`PointToPoint`） | 2 个矩形 | `measure_pos` + `distance_pp` | 每个区把各自 N 个边点**平均成一个代表点**，再量两点的欧氏距离 |
| 点到线距（`PointToLineDistance`） | 区1 点 + 区2 线（都是矩形） | `measure_pos` + `fit_line_contour_xld` + `distance_pl` | 区1 出代表点，区2 的 N 点拟合直线，取**点到无限直线的垂距** |
| 圆直径（`CircleDiameter`） | 1 个**圆形** | 径向 `measure_pos` + `fit_circle_contour_xld` | 直径 = 2 × 拟合半径 |
| 角度（`Angle`） | 2 个矩形 | 两条拟合线 + `angle_ll` | 两条线先归一化成"从交点指向点分布远端"的射线，取绝对值 → **0~180°**，单位是度 |

界面上切换类型时，**只补足缺的搜索区，绝不删你已经摆好的**；下面的灰字会实时提示
"当前测量类型需要 N 个（圆形/矩形）搜索区，已配置 M 个"，缺了运行就报错。
「④ 拟合参数」分区只在三种拟合类出现，「环宽」只在圆直径出现——看不到不是坏了。

## 五、输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SrcImage` | 是 | 待测量的输入图像。1 通道灰度直接用；3 通道彩色自动转灰度；**其它通道数直接报错**（不猜） |
| `MmPerPixel` | 否 | 像素当量（mm/px），接「标定」插件的同名输出，也可链接运行时变量。**接了以上游为权威**；上游值无效（≤0/NaN）直接判失败，绝不静默回退到手填值。没接线时用手填的「像素当量(mm/px)」；配置界面试运行把上游值桥接进端口时，端口值优先于手填 |

## 六、输出端口

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `MeasureValue` | double | 测量值。长度类已乘当量（mm），角度类是度 |
| `Deviation` | double | 偏差 = 测量值 − 标准值（带符号：测大为正、测小为负），与测量值同单位 |
| `IsOk` | bool | 判定结果（true = 合格）。**NG 不算执行失败**，`Success` 仍是 true |
| `MeasureImage` | HImage | 标注图（见第八节图层表）。渲染失败时它是**空**，测量结果照样有效 |
| `FittedGeometry` | HXLD | 拟合类 = 真正的拟合几何（拟合直线 / 整圆轮廓 / 角度的两条拟合线）；宽度与两点距 = 测量连线 |
| `EdgePoints` | HXLD | 检出的原始边缘点（十字 XLD，臂长 12px、45° 斜放），给下游复核或存档 |

另有基类的 `Success`（本步跑没跑通）与 `ErrorMessage`（失败原因 / NG 原因）。
**N 把卡尺不生成 N 个端口**：全部卡尺矩形合成一个 XLD 对象集，改卡尺数不会把下游的线弄断。

## 七、口径与失败策略

- **NG 不是失败**。超限只是正常结果：`Success` 保持 true，原因写进 `ErrorMessage`（例如偏差超上公差）。
  分流请判 `IsOk`，**不要用步骤的红绿**。
- **必须全检**：只要有**一把**卡尺找不到边就整轮失败。用检到的那几把平均出一个"看似合理"的数，
  是计量最危险的错法（错了但不报错），所以这里选择宁可失败。
- **找边最多试 4 遍**：HALCON 的 measure 算子同参首跑偶尔返回 0 条边，插件对每把卡尺重试到 4 次；
  真的没边时第 4 次仍然空、照样失败。它只兜"偶发首跑空"，不改判定口径。
- **越界参数静默夹取**，NaN/Infinity 一律按最小值处理：坏配置最多让结果不对，绝不能把流程崩掉
  （`Sigma=0` 会让算子抛 `#1302`、中心在图外会抛 `#3022`，这些英文错误不该出现在现场）。
- **搜索区问题指名道姓**：数量不足、形状不对（圆直径要圆形、其余只收矩形）、半长/半宽 < 1px、
  半径过小、中心/圆心超出图像范围，都会报出**是哪个区、当前值、图多大**，并给下一步动作。
- **像素当量以连线为权威**：接了 `MmPerPixel` 就用上游值；上游 ≤0/NaN 时明确失败并给两条处置
  （查上游标定本轮是否成功 / 断开连线改手填）。
- **轮首归零**：`MeasureValue`、`Deviation` 置 0，`IsOk` 置 false（基类只自动回收图像与 XLD 类端口，
  double/bool 会原样留着上一轮的值）。所以失败轮下游读到的是 0/false，不是上一件的脏数。
- **显示层与判定层分工**：标注图只是给人看的。渲染失败只丢 `MeasureImage` 并记一条 Warn，
  一次成功的测量**仍然算成功**；反过来测量失败时预览直接清空，画布上没有底图。
- **本算子没有"禁用某把卡尺/透传"这类开关**：可调的就是第九节那 12 个参数加画布上的搜索区。
  要"跳过这一步"，在流程里停用它或删掉步骤，不要指望参数置 0。
- **坐标系**：全部图像像素系 `(Row, Col)`；画布上的**角度(Phi) 存的是弧度**；
  输出的角度是**度**且固定落在 0~180°（归一化过，不会把 150° 的楔角报成 −30°）。
- **配置态与运行态分开**：预览只在配置界面的实例上跑（改参数约 200ms 后自动刷新一次），
  产线每帧不会白烧一遍完整测量。

## 八、显示与坐标系（标注图上有什么）

`MeasureImage` 与配置界面右侧的预览用的是同一套渲染，图层从下到上固定这个顺序：

| 图层 | 样式 | 是什么 | 该看它判断什么 |
| --- | --- | --- | --- |
| 底图 | 原图 | 送进来测量的那张图（通道/位深由渲染件归一化后显示） | 搜索区有没有压在真实特征上 |
| 卡尺小矩形 | 黄，1px | N 把卡尺各自的位置与朝向 | 黄框是不是**横跨**特征、朝向是不是垂直于边 |
| 测量连线 | 青，2px | 量的到底是哪一段：宽度=每对边之间、两点距=两代表点之间、点线距=垂线段、圆直径=过圆心的直径线、角度=夹角弧 | 连线连的是不是你想量的两点 |
| 拟合几何 | 品红，2px | 拟合出的直线 / 整圆 / 两条线（宽度与两点距没有这一层） | 拟合几何贴不贴真实边 |
| 边缘点 | 绿十字，2px | 每把卡尺检出的那个亚像素点 | 十字有没有落在毛刺/杂边上 |
| 左上角文字 | 白底框，OK 绿字 / NG 红字 | 三行：判定、测量值（带单位）、偏差 | 一眼确认这轮的结果与单位 |

配置界面右侧那块**既是预览也是画布**：可以右键新建矩形/圆形搜索区、拖句柄粗调，
左下角信息栏三色（绿=正常、橙=还能继续、红=失败），改参数约 200ms 后自动重算一遍。

## 九、典型接线

```
图像采集.OutputImage ──▶ 卡尺测量.SrcImage          （或 ROI.Domain_测量区 ──▶ SrcImage：坐标不变，最省事）
预处理.Image         ──▶ 卡尺测量.SrcImage          （边缘更清晰，卡尺更稳）
标定.MmPerPixel      ─────▶ 卡尺测量.MmPerPixel     （推荐：当量跟着标定走，标定本轮失败当场判失败）

卡尺测量.MeasureValue ──▶ CSV记录.<列名>            （动态端口，端口名 = 你起的列名；格式给 F3、单位 mm）
卡尺测量.Deviation    ──▶ CSV记录.<列名>            （格式 +0.###）
卡尺测量.IsOk         ──▶ 结果上报.<字段名>          （上报字段同样是动态端口）
卡尺测量.MeasureImage ──▶ 结果显示.SrcImage          （要再叠别的结果时用它当底图；它已自带四层标注）
卡尺测量.EdgePoints   ──▶ 结果显示.r1 / 存档         （复核边缘到底落在哪）
```

> **搜索区不吃「ROI」插件的输出**：卡尺的搜索区存在本步骤自己的画布里（随方案存盘），
> ROI 插件的框是用来限定"看哪里"的另一套东西。两者形状参数写法相同（矩形/圆），但不共用、不互相引用。

## 十、从哪开始读

- 第一次接这个算子：翻第二页「配置走查与参数」，按 13 步从零走到下游拿到稳定数值，再看逐参数对照表；
- 现场出问题了：翻第三页「报错字典与现场配方」，先用症状表定位方向，再按界面里的原文查那一条，
  最后照配方库成套调参。
