# 卡尺测量 · 配置走查与参数

这一页给"第一次接这个算子的人"：先按第一节的 13 步从零走到下游拿到稳定数值（每步都给了判据），
再查第二节的逐参数对照表（默认值、区间、调大调小各看到什么、和谁互相牵制）。
参数含义与原理在上一页，这里不重复。

## 〇、界面地图（走查里说的"哪一格"就是这里）

左右两列。左列是可滚动的参数卡，从上到下六张：

| 卡片 | 控件 | 作用 |
| --- | --- | --- |
| 图像输入 | 「输入图像」链接框、`重置搜索区` 按钮 | 绑 `SrcImage`；按钮按当前类型重建默认搜索区（**会清掉现有区域**） |
| ① 测量类型 | 下拉「测量类型」+ 一行灰字提示 | 五类量选一；灰字实时写"需要 N 个（圆形/矩形）搜索区，已配置 M 个" |
| ② 搜索区与卡尺 | 数值框「卡尺数 N」、`搜索区列表`、`删除` / `重置` 按钮、`参数微调` 数值行 | 摆区的唯一入口；列表行显示 `名字 [形状]`，选中后下面出参数微调行 |
| ③ 找边参数 | 「平滑 Sigma」「边缘阈值」「极性」「选择」「插值方式」 | 剖面与找边闸门 |
| ④ 拟合参数 | 「拟合方式」「最大残差(px)」「最少点数」，圆直径多一行「环宽(px)」 | **只在三种拟合类出现**（点到线距/圆直径/角度） |
| ⑤ 判定与标定 | 「标准值」「上公差」「下公差」「像素当量(mm/px)」+ 两行说明 | 规格与当量 |

右列一块：`标注图预览（可拖拽搜索区）`——上面是图，下面是三色信息栏（绿=正常、橙=还能继续、红=失败）。

几条交互口径，走查里会反复用到：

- **改数值框/下拉 = 约 200ms 后自动重算预览**（不用点按钮）；但 `参数微调` 里的文本框是**失去焦点才写回**，
  打完成绩要按 Tab 或点一下别处，不然画布不动；
- 画布上**右键 → 区域 → 新建矩形 / 新建圆形**；拖句柄粗调，`参数微调` 精调，两边实时同步；
- 选中搜索区后按 **Del** 删除（焦点在文本框里时不会误删）；`删除` / `重置` 按钮同样的事；
- 切换测量类型**只补缺的搜索区，绝不删你摆好的**；
- 搜索区的形状参数（随方案存盘，运行期不变）：

| 形状 | 参数微调里的名字 | 口径 |
| --- | --- | --- |
| 矩形 | 中心行(R)、中心列(C)、角度(Phi)、半长(L1)、半宽(L2) | Phi 是**弧度**；L1/L2 取绝对值用，都不得小于 1px |
| 圆形 | 圆心行(R)、圆心列(C)、半径(Radius) | 半径取绝对值，不得小于 1px |

> 工件位置飘出搜索区时，卡尺**不会跟着走**——搜索区是配置期固定的。表现就是"某把卡尺未检出边缘"。
> 来料定位差就得先定位（模板匹配）再想办法把工件请回搜索区，别指望这里自己追。

## 一、第一次接这个算子：13 步走查

### 第 1 步｜把图接进来

在左列「图像输入」卡的「输入图像」行点链接按钮，选上游的图像输出（采集的 `OutputImage`、
预处理的 `Image`，或 ROI 的 `Domain_名字`——推荐 `Domain_`，坐标系不动）。
**期望**：信息栏不再写"输入图像为空：请为上方「输入图像」指定图片，或连接上游图像端口"。
**没做对**：接的是别的步骤的**裁剪图**（`Crop_名字`）也能跑，但坐标系搬走了，你对着原图想的搜索区位置会整体偏。
**判据**：右侧画布出现底图，信息栏变绿或变红都不算这一步的错（红是"还没配好"，不是"没接上"）。

### 第 2 步｜让画布上有真实的那张图

流程没跑起来时，在「输入图像」行直接指定一张图；已经接了上游就**试运行一次**，上游的图会自动进来。
**期望**：画布上出现**未标注的原图或上一轮的标注图**，搜索区压在图上看得见。
**没做对**：拿一张不相干的图调参 → 阈值、极性全调歪，换真图又要重来。
**判据**：把搜索区拖到某个特征上，那个特征在图上肉眼可见（不然下面没法判断边找得对不对）。

### 第 3 步｜选测量类型

在「① 测量类型」的下拉里选。
**期望**：下面灰字变成"当前测量类型需要 1（或 2）个矩形/圆形搜索区，已配置 …"；
选到点到线距/圆直径/角度时，「④ 拟合参数」卡**冒出来**；选圆直径时再多了「环宽(px)」。
**没做对**：类型和实际要量的东西不匹配——例如缝隙用"两点距"量，得到的是两个平均代表点之间的距离，
不是缝宽；圆直径选了矩形区，运行直接报"不是圆形"。
**判据**：灰字里"已配置"的数字 ≥ "需要"的数字，且形状对（圆直径那行写的是"圆形"）。

### 第 4 步｜摆搜索区：数量与形状

画布右键 → 区域 → 新建矩形（圆直径选新建圆形）。第一个默认叫 `搜索区1`，第二个 `搜索区2`。
两类量的区（点到线距/角度/两点距）要分清**谁当点谁当线**：列表里排第 1 的是"点"（或第一个搜索区），
排第 2 的是"线"。角度报错文案里说的是"第 1/第 2 个搜索区"，就是按这个顺序。
**期望**：`搜索区列表` 出现对应行数，右侧画布出现黄/橙的手柄框。
**没做对**：多余的区域留在列表里但排在前面——**运算只取前 N 个**，你以为在用第 3 个区，其实用的是第 1 个。
**判据**：把不用的区选中后按 Del 删掉，让列表数量正好等于需要数量。

### 第 5 步｜定"投影方向"：让矩形横跨被测特征（决定成败）

选中搜索区，在 `参数微调` 里改 角度(Phi)/半长(L1)/半宽(L2)（改完按 Tab 写回），或直接拖画布句柄。
规则只有一条：**L1 方向 = 每把卡尺的扫描方向，被测边要垂直于它**；L2 方向 = 卡尺阵列铺开方向，**沿着边本身**。
测竖直边 → Phi 让 L1 指向水平（Phi=0 就是）；测水平边 → Phi 转 90°（≈1.5708 弧度）。
半长 L1 要**长过特征**：至少覆盖"缝宽 + 两边各一点余量"，扫描线从一侧穿到另一侧才叫扫得到。
**期望**：预览里出现**一排黄框**横跨那条边，N 个（默认 5 个），它们并排沿 L2 方向排开。
**没做对**：把 Phi 转 90° 或 L1 太短 → 直接报"第 … 把卡尺未检出…（请降低边缘阈值、放宽极性，或调整/放大搜索区）"；
文案里给了三个候选，**方向错才是第一个**，别一上来就降阈值。
**判据**：数一下黄框个数 = 「卡尺数 N」；每个黄框的**长轴都穿过**那条边，而不是**贴着**那条边走。

### 第 6 步｜设卡尺数 N

「② 搜索区与卡尺」的数值框（默认 5，整数 1~1000）。
**期望**：黄框个数立刻跟着变；预览重算后数值更平稳（多把取平均是这里最主要的抗噪手段）。
**没做对**：N 太大 → 每把的半宽被夹到"相邻间距的一半"（下限 0.5px），黄框挤成一条线，
**不会更准，只会更慢**；圆直径的 N 太小（例如 3~5）→ 点近共线，报"拟合圆退化"。
**判据**：跑 10 次手算一下极差（最大值减最小值），比改之前小就留着；圆直径起步按 16 把上下试。

### 第 7 步｜第一轮找边验证：先放宽、再收紧

第一次跑请**故意用宽容配置**：「极性」= 全部、「边缘阈值」先降到 10~15、「平滑 Sigma」保持 1.0、
「插值方式」= 双线性（亚像素）。
**期望**：信息栏出绿字（形如 `宽度/间隙：测量值=…（像素=…×当量） 标准=… 偏差=… 判定=… 卡尺=5`），
画布上出现**绿十字贴在真实边上**、**青线连在想量的那两点**之间。
**没做对**：用默认阈值 30 跑弱对比边 → "未检出边缘"；这一步的意义是先让边"出来"，再谈选哪条。
**判据**：绿十字的位置肉眼就在边上（差半个像素以内）；如果十字落在噪声上，说明阈值还得往回抬。

### 第 8 步｜收紧极性与选择，锁定要的那条边

看清图上的明暗方向：沿扫描方向是"暗→亮"还是"亮→暗"，把「极性」从"全部"改成那个**单方向**；
再用「选择」决定一条卡尺上有好几条边时取哪条。
**取值口径（容易误解，看清）**：本算子对"第一条"和"全部"**取的是同一个点**——都拿每把卡尺的第一个检出点
（宽度类型拿第一对边）；只有"最后一条"会换到另一头。所以"全部"并不会把多条边都算进来，
别指望选"全部"能取到最外侧那条边，那是"最后一条"的活。
**期望**：绿十字只出现在你要的那条边上，测量值不再随隔壁的对比度乱跳。
**没做对**：留着"全部" + "全部" → 测缝隙量到隔壁那条边，数值"很稳定地错"。
**判据**：把「边缘阈值」往上抬一档再降回来，若检出点不变 = 锁住了；一变就说明还有第二条候选在竞争。

### 第 9 步｜单次运行，逐层看边线与连线

停下来只看这张预览，四层逐个确认（颜色含义见上一页第八节）。
**期望**：黄框横跨 / 绿十字贴边 / 青线连对的那一段 / 品红拟合几何（若有）贴着真实边或圆周。
**没做对**：
- 青线连的不是那两个点 → 回到第 8 步；
- 品红线明显斜于真实边 → 有杂边把拟合拽歪（挪搜索区、加大「卡尺数」，或检查「拟合方式」别是最小二乘）；
- 圆直径的青线（直径线）比真实圆小一圈 → 只扫到一小段弧，回第 11 步加大环宽或重新套圆。
**判据**：**看着不对就别信数值**——这一步是所有后续调参的前提，图上确认过再谈精度。

### 第 10 步｜"建参考"：定标准值与上下公差

本算子没有模板学习那种动作，"建参考"就是**把这个尺寸的规格钉下来**，两种来源按顺序选：
① **有图纸**：「标准值」填名义值，「上公差」「下公差」填允许偏差（下公差填**负数**做非对称，例如 +0.05 / −0.02）；
② **没图纸**：拿一件确认合格的良品连跑 5~10 次，看 `MeasureValue` 的平均值，把它当标准值的**草稿**，
公差先用"分散度的一半再放大一档"起步，量块/仪表对数后再改。
**注意单位**：标准值/公差的单位必须与测量值一致（长度类是 mm 或你手填当量后的单位，**角度类填的是度**）。
**期望**：判定从默认全 NG 变成 OK（良品），信息栏的"判定=OK"。
**没做对**：出厂 标准值/上公差/下公差 = 0/0/0 是**有意的零容忍**（通用算子不假装知道你产品规格）。
不改它们就永远 NG——这是提醒你去填，不是坏了。
**判据**：`Deviation` = `MeasureValue` − 标准值 手算能对上；判定规则是 下公差 ≤ 偏差 ≤ 上公差
（正好等于边界算 OK，容差 1e-9 防浮点抖动）。

### 第 11 步｜定像素当量（长度类的命门）

优先在流程里把「标定」步骤的 `MmPerPixel` 输出连到本步骤的 `MmPerPixel` **输入端口**；
没有标定步骤再手填「⑤ 判定与标定」里的「像素当量(mm/px)」（默认 1.0 = 直接输出像素值）。
手填算法：拿已知尺寸的标准件，`当量 = 实际尺寸(mm) ÷ 量到的像素数`。
**期望**：`MeasureValue` 与量具读数同量级；信息栏括号里的 `像素=…×当量` 能手算复核。
**没做对**：
- 接了上游但上游本轮失败/值为 0 或 NaN → **步骤直接判失败**，文案写明"像素当量来自上游连线但无效…"，
  并给两条处置（查标定本轮 / 断开连线改手填）。这是设计：**不会拿旧值硬算**；
- 没接线时手填值忘了改 → 结果整体偏一个倍数（默认 1.0 就是纯像素值）。
**判据**：把当量改成 2 倍，测量值应当**正好翻倍**（角度类除外，角度永远不变）。
另外配置界面的试运行会把上游的当量**桥接进端口**，此时端口值优先于手填——"试运行所见 = 运行所得"。

### 第 12 步｜连续运行压噪声，验证重复性

连着跑 20~50 轮（同一种件），看 `MeasureValue` 的分散度与平均值。
**期望**：极差落在现场允许值内；`EdgePoints` 的十字位置肉眼稳定。
**没做对**：
- 数值来回抖 → 先加大「卡尺数 N」（多点平均是主要手段），再适当加大「平滑 Sigma」；
  仍抖就看绿十字是不是有某把压在毛刺/倒角/杂边上，把那个位置的搜索区挪开；
- 偶发"未检出"而大多数轮正常 → 极性还没收紧、或某把卡尺压到反光带（挪区/降阈值/加 Sigma）；
- 平均值系统性偏 → 先查当量，再查摆位，**最后才怀疑公差**。
**判据**：故意拿一个带毛刺/脏污的样本跑一遍，看结果还贴不贴真值。
样图实测的口径：12px 毛刺下点到线距真值 196.5，`Tukey` 得 196.5、`最小二乘` 被拽到 191.092——
要换最小二乘，先确认自己有没有这个耐受度。

### 第 13 步｜接下游（CSV / 上报 / 结果显示）

- **存档追溯（SPC）**：「CSV记录」里加列，把列的端口连 `MeasureValue`（格式 `F3`）、`Deviation`（格式 `+0.###`）、
  `IsOk`；要留证据图就连 `MeasureImage` 到那个插件的「图片」列端口；
- **报 MES**：「结果上报」的字段端口连 `IsOk` / `MeasureValue`；上报时机可以用「上报触发」端口控制；
- **上屏/叠别的结果**：`MeasureImage` 已经自带四层标注与判定文字，直接发布即可；
  还要叠别的结果就拿它当「结果显示」的 `SrcImage` 底图；
- **做补偿/分拣**：`MeasureValue`、`Deviation` 连「C#脚本」算补偿量。
  **分流请用 `IsOk`，不要用步骤的红绿**——NG 时 `Success` 仍是 true。
**判据**：跑一轮后 CSV 里那行的数值、正负号、位数与界面信息栏完全一致；
NG 样本回放时 `Deviation` 的方向与幅度确实和缺陷一致，再接报警。

## 二、逐参数对照表

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（默认值） | 合法区间与越界怎么处理 | 调大会看到什么 | 调小会看到什么 | 什么症状说明它错了 | 和哪些参数互相牵制 |
| --- | --- | --- | --- | --- | --- |
| 测量类型（宽度/间隙） | 五项选一。流程里存成员名（`Width`/`PointToPoint`/`PointToLineDistance`/`CircleDiameter`/`Angle`），导出或手改方案按成员名填 | 不适用（换的是口径不是幅度）：切到拟合类会多出「④ 拟合参数」卡，切到圆直径多「环宽(px)」 | 不适用：切回宽度/两点距时拟合参数卡**收起**（不是删了你的值） | 类型与要量的东西对不上：缝用量成两点距得到"两个平均点距"；圆直径用矩形区直接报"不是圆形" | 搜索区数量与形状、`环宽`只在圆直径生效、`FittedGeometry` 端口的语义 |
| 卡尺数 N（5） | 1~1000，界面只收整数；越界静默夹取，NaN 按 1 | 更稳（多点平均）、更慢；黄框更密，每把半宽被夹到"相邻间距一半"（下限 0.5px），**过密不再提精度** | 更快，但单点噪声权重变大；圆直径的 N 太小会点近共线 → "拟合圆退化" | 数值来回抖（太小）；节拍顶不住（太大）；拟合类报点数不足 | `半宽(L2)`（间距=2·L2/N）、`最少点数`（点数 ≤ N）、圆直径的弧间距与 `环宽` |
| 平滑 Sigma（1.0） | 0.4~100；填 0/负数夹到 0.4（`Sigma=0` 会让算子抛 `#1302`） | 剖面更圆滑、抗噪更强，但边"发糊"、过渡带中心的定位变钝，弱边可能被抹掉 | 高频起伏被当成边，十字乱跳（配合过低的阈值尤其明显） | 十字落在噪声上（太小）；弱边检不到、边位置系统性偏移（太大） | `边缘阈值`（Sigma 大 → 导数峰值小 → 需要更低阈值）、`插值方式` |
| 边缘阈值（30） | 1~255 | 只承认强对比；弱边/低对比直接"未检出边缘" | 噪声、纹理、脏污都被当边，检出点跳、数值抖 | 报"未检出"（太大）；数值抖、十字不在边上（太小） | `极性`（单方向能挡掉一半假候选）、`Sigma`、光源强度 |
| 极性（全部） | 暗→亮 / 亮→暗 / 全部 | 不适用；"全部"最宽容、也最容易跳到隔壁对比度上 | 单方向更严，选反了就**整条检不到** | 量到隔壁那条边、数值"稳定地错"（该收紧）；整把未检出（选反了） | `选择`、`边缘阈值`、宽度类型的"第一对边" |
| 选择（全部） | 第一条 / 最后一条 / 全部 | 不适用。注意口径：**"全部"与"第一条"取同一个点**（都拿每把卡尺第一个检出点，宽度取第一对边） | 不适用；只有"最后一条"会换到扫描方向的另一头 | 想锁最外侧那条边却选了"全部" → 一直量到最内侧 | `极性`（两者一起决定"锁定哪条边"） |
| 插值方式（双线性） | 最近邻（整像素）/ 双线性（亚像素，默认）/ 双三次（亚像素） | 双三次：过渡更平滑、最慢 | 最近邻：最快，但只能落在整像素上，台阶位置有半个像素量级的系统性量化误差 | 精度要求亚像素却用了最近邻；节拍极紧且只要求 ±1px 可以降它 | `Sigma`、图像分辨率、节拍 |
| 拟合方式（Tukey 抗离群（推荐）） | 最小二乘 / Huber / Tukey。仅拟合类生效（直线走 regression/huber/tukey，圆走同族 geometric/geohuber/geotukey，界面不用你管） | 抗离群更强：毛刺点几乎不参与拟合 | 最小二乘等权，**一个坏点能拽歪整条线/圆**（实测 12px 毛刺：Tukey 196.5、最小二乘 191.092） | 换个毛刺位置数值就跳（该用鲁棒档）；边本来就干净、还嫌慢可以降 Huber | `最大残差`（中位数口径与鲁棒档配套）、搜索区摆位 |
| 最大残差(px)（1.0） | 0.05~1e6。**口径是"边缘点到拟合几何距离的中位数"上限**，不是单点最大值 | 容忍弯边/杂边，但错得更远才报（等于放宽质量闸门） | 稍微有点弯就报"拟合残差过大（主体点残差 … px > 允许 … px）" | 拟合类反复报残差过大：先确认特征直不直、区摆得对不对，**不要顺手放到 10** | `拟合方式`、`卡尺数`、`半长/半宽` 摆位 |
| 最少点数（3） | 2~1000，界面只收整数（直线 2 点定线、圆 3 点定圆，取 3 = 直线有 1 点冗余、圆刚好达下限） | 数据不够就报"只收集到 N 个边缘点，少于最少点数 …" | 两点拟出的线毫无冗余，噪声直接进结果 | 拟合类报点数不足；或数值抖且线明显歪 | `卡尺数`（可用点数 ≤ N）、`拟合方式` |
| 环宽(px)（30，仅圆直径） | 2~1e5；每把径向卡尺的扫描总宽 = 环宽，实际按 ±环宽/2 扫（默认 ±15px） | 容得下更大的圆心/半径手摆误差，但更容易扫进相邻特征（隔壁孔边、反光带） | 圆摆稍不准就"第 i 把圆周卡尺未检出边缘…或增大环宽" | 圆周卡尺未检出（太小）；检出点在隔壁特征上、圆拟歪（太大） | 半径、`卡尺数`（弧间距小 → 卡尺半宽夹到间距一半）、圆周卡尺中心越界 |
| 标准值（0） | ±1e9；与测量值同单位（角度类填**度**） | 不适用（它是名义值不是闸门） | 不适用 | 默认 0 = 零容忍，一跑就 NG；单位填错（mm 与 px 混）时偏差量级离谱 | `上公差`/`下公差`、`像素当量`（改了当量要重填标准值） |
| 上公差（0） | ±1e9；判定用 `偏差 ≤ 上公差 + 1e-9` | 越宽松，NG 越少（别拿它当"消除报警"的手段） | 越严；填 0 且下公差 0 = 零容忍（出厂默认） | 良品反复 NG 且 `Deviation` 很小 → 公差比现场要求紧 | `标准值`、`下公差`、`MeasureValue` 的重复性（第 12 步） |
| 下公差（0） | ±1e9，**允许填负**做非对称公差（例如 +0.05 / −0.02） | 填正数会把"偏小也算合格"的范围推大（一般不是你要的） | 填大负数 = 允许测小；判定用 `偏差 ≥ 下公差 − 1e-9` | 只报"超出下公差"或只报"超出上公差"时，说明公差带不对称方向填错了 | `标准值`、`上公差` |
| 像素当量(mm/px)（1.0） | 界面 1e-6~1e6；运行期夹取 1e-9~1e6（手填与上游连线值走同一夹取）。1.0 = 直接输出像素值 | 测量值整体按比例放大（**角度不受影响**） | 整体按比例缩小 | 结果整体偏大/偏小一个倍数 | `MmPerPixel` 端口（接线就盖过它）、`标准值`/公差（单位跟着变） |
| `MmPerPixel` 输入端口（未接=0） | 可选端口。已连线：上游值权威（照常夹取）；上游 ≤0/NaN → **明确失败**并指两条处置。未接线但端口值>0（试运行桥接）：用端口值。都没接：用手填值 | — | — | 报"像素当量来自上游连线但无效（…）" → 上游标定本轮失败或变量没值 | 「标定」插件的 `MmPerPixel` 输出（类型 double，吻合）、手填「像素当量」 |

## 三、什么时候该动哪个（速查）

| 现象 | 先动 | 再动 | 最后才考虑 |
| --- | --- | --- | --- |
| 报"未检出边缘" | 搜索区方向（Phi/L1，第 5 步） | `边缘阈值` 降、`极性` 放宽到全部 | `Sigma`（别用它救找不到边） |
| 找到边但数值跳 | `卡尺数 N` 加大 | `Sigma` 加大 | 挪搜索区避开毛刺 |
| 量到隔壁那条边 | `极性` 收成单方向 | `选择` = 第一条/最后一条 | 缩短 L1 让它扫不到隔壁 |
| 拟合反复失败 | `卡尺数 N` 加大 | `最少点数` 调小（点数不足那条） | `最大残差` 适度放大（残差那条） |
| 圆测成小圆/半径离谱 | 圆形区套住整个圆周 | `卡尺数 N` 加到 16 上下 | `环宽` 调整（别拿它遮摆位错） |
| 结果整体偏一个倍数 | `MmPerPixel` 连线来源 | 手填「像素当量」 | 上游标定本轮是否成功 |
| 判定一直 NG | `标准值` | `上/下公差` | 是不是该判 NG（真超差了） |
