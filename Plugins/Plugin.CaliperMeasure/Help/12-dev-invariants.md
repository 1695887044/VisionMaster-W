# 卡尺测量 · 不变量与守门

> 分类：测量 ｜ 来源：插件 Plugin.CaliperMeasure ｜ 读者：开发

分两组：**A 组 = 违反了会有动静**（闸门红、步骤判失败、反序列化当场抛）；**B 组 = 违反了没动静**
（流程照跑、数值照出，只是错）。B 组才是真正要人盯的部分。
每条给 `症状 → 机理 → 守门`。**守门只写真实存在的断言名**（`[CALM]` 16 条在
`FlowCanvasChecks\CaliperMeasureChecks.cs`；烘焙件 B1~B8 在 `FlowCanvasChecks\AnnotationBakerChecks.cs`；
静态扫描在 `FlowCanvasChecks\ResultDisplayCheck.cs`；ROI 手势在 `FlowCanvasChecks\RoiInteractionChecks.cs`；
产物守门在 `FlowCanvasChecks\ParallelExecutionChecks.cs`；手册结构在 `FlowCanvasChecks\HelpManualCheck.cs`），
没有闸门覆盖的写"无断言，靠人工核对"。

## A 组：违反即有动静

**A1 输入端口 `MmPerPixel` 的名字、类型、可选性**
症状：接不上「标定」的输出，或宿主把它当必填端口卡住编译。
机理：端口靠反射发现，`InputPort<double>` + 构造里的 `description` 是宿主唯一的元数据来源；
改名或改类型，标定侧的连线就断了。
守门：`[CALM] 输入端口 MmPerPixel 存在、可选、类型 double（可直接接标定输出）`、
`[CALM] 标定插件 MmPerPixel 输出类型 = double（与卡尺输入端口类型吻合）`。

**A2 像素当量三分支取值口径**
症状：接了标定却用手填值算，或试运行的数与产线的数对不上。
机理：`GetEffectivePixelSizeMm(out error)` 按"已连线 → 上游权威；未连线但端口值 > 0 → 端口值（试运行桥接）；
否则 → 手填"三分支取值，三条各自对应一条断言。
守门：`[CALM] 未接上游 → 用手填值（0.03）`、`[CALM] 已接上游 → 以连线为准（0.02，手填被打断点）`、
`[CALM] 试运行桥接：无链接但端口值>0 → 以端口值为准（试运行所见=运行所得）`。

**A3 上游当量无效必须判失败（不静默回退）**
症状：标定本轮失败，卡尺却给了一个"看起来正常"的 mm 值。
机理：拿错当量 = 所有长度值整体缩放错，危害远大于一次失败；所以 ≤0/NaN/Infinity 一律走
`p.ValidationError` → 整步 `Fail`，并明确给两条处置。
守门：`[CALM] 上游=0 → 报错并指「标定」（不静默回退）`、`[CALM] 上游=NaN → 同样报错（NaN 不得溜进任何计算）`、
`[CALM] 上游当量=0 → 步骤失败并指「标定」（不给旧值硬算的机会）`、
`[CALM] 标定失败传导：当量口归 0 → 卡尺明确失败（不拿旧标定硬算）`。

**A4 长度类数值真的乘上当量（端到端）**
症状：改了当量数值不动，或倍数不对。
机理：`MeasureValueMm = MeasureValuePx × 生效当量`（角度分支除外）。
守门：`[CALM] 未接上游：手填当量跑通（亮带 ≈240px × 0.5 ≈ 120mm）`、
`[CALM] 已接上游：以连线为准（同一亮带，2.0/0.5 应放大 4 倍）`、
`[CALM] 标定插件先产出一份当量 0.02 的标定（链路源头）`、
`[CALM] 真实链路：卡尺以标定当量为准（≈240px × 0.02 ≈ 4.8mm）`。

**A5 失败轮端口归零**
症状：某轮失败后下游 CSV 记上一个工件的数值，或 `IsOk` 停在上一轮的 true。
机理：基类 `AutoDisposeRoundOutputs` 只回收 `IDisposable`，double/bool 端口留着上一轮值；
`RunAlgorithm` 头三行显式归零补上这个洞。
守门：`[CALM] 当量失效的失败轮：输出端口清零（无上一轮脏值）`。

**A6 标注底图逐点保真（不许塌成窗口底色、不许缩进左上角）**
症状：预览/`MeasureImage` 里底图整片黑或整片压到左上角，只剩标注。
机理：`AnnotationBaker` 的六条窗口纪律里，`SetPart` 是无条件项；漏掉它（本插件 2026-10-13 之前的真实状态）
就会把窗口可视区当成比底图大的范围，底图外全是窗口底色。
守门：`[CALM] 标注底图逐点保真（亮带内 255 / 亮带外 0，底图没被缩进左上角）`、
`B1【纪律3 SetPart】四角像素 == 底图灰度 100（不是窗口黑底、底图没缩进左上角）`。

**A7 文字白底框必须显式给 `box: true`**
症状：左上角三行文字在复杂背景上读不出来，或只给了 `box_color` 却画不出框。
机理：HALCON 只给 `box_color` 不画框，必须同时给 `box,true`；烘焙件不透传"默认带框"。
守门：`B2【纪律5 box】显式 Box:true → 文字周围采到接近白的底色框像素（max ≥240）`、
`B2【纪律5 box】显式 Box:false → 同一带内没有白框（max ≤130，只有黑字与灰底）`。

**A8 窗口按尺寸复用、轮间不残留**
症状：连续跑几轮后标注越叠越多，或每轮都重开窗口导致耗时抖动。
机理：烘焙件按窗口号复用、每轮无条件 `SetPart` + 清屏；插件侧唯一责任是别自己攒窗口、别把上一轮的
XLD 对象继续持有（本插件中间对象全进 `temp`，finally 释放）。
守门：`B3【纪律2 窗口复用】同尺寸连烘 3 轮都成功（没有反复开关窗口）`、
`B3【纪律3 串轮污染】第 1 轮的线没有残留（行20 附近 max ≤130）`、
`B3【纪律3 串轮污染】第 2 轮的线没有残留（行50 附近 max ≤130）`。

**A9 非 byte 底图不许整片死白**
症状：12/16 位相机接进来，标注图白花花一片，看不出特征。
机理：位深归一化在烘焙件里做（按**实际灰度范围**线性拉伸），插件侧不许先 `convert_image_type`；
本插件历史版本缺这一步，所以迁移后才有这条绿灯。
守门：`B4【死白陷阱】产物有灰度层次（全图 range >100，不是整片 255）`、
`B4 两块灰度可区分（1000 的那块明显暗于 2000 的那块）`。

**A10 多通道底图不许触发降级告警**
症状：4 通道图进来后 `MeasureImage` 为空，日志刷"对象元素未初始化"。
机理：烘焙件负责丢 alpha；插件侧的 `AddLayer` 还要挡住 null/未初始化的**图层**（空对象集合法，不初始化对象非法）。
守门：`B5 4 通道底图烘焙不抛异常`、`B5 4 通道底图仍能产出标注图（尺寸不变）`、
`B5 4 通道没有触发任何降级告警`、`B6 非法色名 / NaN / 负半径 / 参数个数错 / 空对象 全都不抛异常`、
`B6 仍然产出标注图（坏元素只丢自己，不丢整张）`。

**A11 渲染件生命周期**
症状：关掉配置界面后仍有窗口挂着，或再次打开时 `Bake` 返回 null。
机理：`AnnotationRenderer.Dispose` 必须转交 `_baker.Dispose()`，本插件的 `Dispose` 里已排在这条上；
baker 释放后再 `Bake` 是"返回 null + 一条 Warn"，不是抛。
守门：`B7 Dispose 后再 Bake：返回 null、不抛、且有告警留痕`、`B7 Dispose 幂等（连调两次不抛）`、
`B7 500 轮里没有触发任何降级告警`。

**A12 不许出现第二处开窗（R36 全仓纪律）**
症状：多窗口互相抢句柄、无头环境跑不动、产物体积莫名变大。
机理：全仓 `OpenWindow` 只许在 `Services\Core.Halcon\Helpers\AnnotationBaker.cs`（外加一份永久豁免
`Plugin.ImageScript\HDevDisplayBackend.cs`，它不是烘焙件）。本插件 2026-10-13 从 175 行渲染体瘦到 62 行就是这次迁移。
守门：`扫描④【D9】全仓 OpenWindow 只出现在 AnnotationBaker.cs + N 份豁免里（清单只许变短）`、
`扫描④c Plugin.ResultDisplay 自己**零**开窗/dump/SetPart（那属于共享件的职责）`。
人工判据：`grep -rn "OpenWindow" Plugins\Plugin.CaliperMeasure` 必须为空。

**A13 文字对齐语义不许被改动带偏（R39）**
症状：改烘焙件后左上角三行文字整体偏移或丢字。
机理：本插件调用 `AddTextBlock(lines, textColor, 12, 12, 20, box: true)`，**不写 `HAlign`** = 走默认 Left = 历史行为；
字宽只能由烘焙件量（`GetStringExtents`，且必须排在 `SetFont` 之后）。
守门：`B8【零行为变化】不写 HAlign 与显式 Left 的墨迹包围盒一致（±4px）——四份已迁插件不受影响`、
`B8【Left】墨迹左缘 == 给定列 20（±10px）`、`B8 垂直不受对齐影响（三种对齐墨迹上缘同行带，±6px）`。

**A14 `[ParallelSafe]` 标注与产物同步**
症状：宿主门禁把"已标注算子"误报成不安全，并行分组里被踢出去串行跑。
机理：标注在源码上，但**门禁读的是 DLL 元数据**；只改源码不重建 = 产物里没有 `ParallelSafeAttribute`。
卡尺是纯视觉计算（不开窗、不碰 UI 状态、无跨步骤共享对象），所以这个声明成立。
守门：`标注 [ParallelSafe] 的 18 个插件 DLL 全部含特性元数据（漏重建=门禁误报）`（P31 产物守门）。
动作：改完必须 `dotnet build VisionMaster.sln`（只 build 宿主看不到）。

**A15 `CaliperParamEntry` 的 `[JsonIgnore]` 不能删**
症状：打开含卡尺步骤的老方案直接抛 `Unable to find a constructor to use for type CaliperParamEntry`。
机理：`ParamEntries` 是 get-only 集合属性，Newtonsoft 默认会尝试填充；该项无无参构造且持有 owner 引用（纯 UI 包装）。
守门：无断言，靠人工核对（保存 → 重开方案一次）。同族：`DisplayText`、`ParamNames` 也必须保持 `[JsonIgnore]`。

**A16 画布手势不许在插件里重实现**
症状：第一下拖不动句柄、点空白取消不了选中、瞄偏一点就丢选中。
机理：手势全在 `HalconBase`/`ImageEdit`（R51~R53），插件只做绑定与回传；
插件里加"先激活再拖"的补丁会与控件的回放逻辑相互抵消。
守门：`[ROI] ② 冷启动一次手势直接拖角点即可改大小（本次修复目标）`、
`[ROI] ④ 点空白结束编辑（既有语义回归）`、`[ROI] ⑥ 多 ROI 下冷启动一次手势拖第二个的角点（切换 + 改大小）`、
`[ROI] ⑦ 起手点偏出手柄 ~11px 时不摘除选中（容差放宽）`、`[ROI] ⑧ 冷启动从内部拖 = 移动（补发 down 带来的行为变更，钉住）`。
注意：这批断言要求**有可见窗口的真机环境**，无头时整组以"跳过"形式绿灯（`[ROI] 画布交互断言（跳过：本机无 HALCON 引擎）`），
所以它们绿不代表手势验过。

**A17 手册结构四条约定**
症状：宿主悄悄退回自动生成页，或开发章节挤掉用户页。
机理：`Help\` 扁平（本程序集只有一个插件类，**不许建子目录**）、文件名 `NN-` 前缀、首行 `# 一级标题`、
无 BOM 合法 UTF-8 含中文、正文 ≥70 行、无占位标记、开发页 `NN-dev-xxx.md` 且合计达 L 档 300 行下限。
守门：`HM5 每页第一行内容就是 \`# \` 一级标题（页名取得到）`、`HM6 手册文件名是 \`NN-xxx.md\`（页序确定）`、
`HM7 手册都是无 BOM 的合法 UTF-8 且含中文（编码纪律）`、`HM8 每个插件的手册正文 ≥ 70 行（不是占位页）`、
`HM9`（占位标记闸门；它的断言名里就带着那几个禁词本身，所以本页不逐字照抄，避免自己踩中自己）、`HM12 开发页文件名是 \`NN-dev-xxx.md\`（宿主认得出这是开发章节）`、
`HM12b 手册最多一层目录（开发页另立子目录会挤掉用户页）`、
`HM13 已交的开发章节达到所在档位的行数下限（L300/M150/S100，交了就不是随笔）`、
`HM4 有 Help/*.md 的工程都带 EmbeddedResource（手册进得了 DLL）`。

## B 组：违反即静默（数值照出、流程照跑，只是错）

**B1 阵列必须沿 L2 轴排，不能沿 L1**
症状：数值"稳但偏"，或多把卡尺的绿十字排成一条斜线穿过特征。
机理：`gen_measure_rectangle2` 沿 L1(Phi) 轴扫描、检出边垂直于 L1；沿 L1 均布会让每把扫到不同位置，
平均出来的数没有意义。L2 轴单位向量在这里是 `(cosφ, sinφ)`（**不是** `(cosφ, −sinφ)`，后者只在 φ=0 时碰巧垂直）。
守门：无断言，靠人工核对（预览里黄框应沿边方向并排、每个都横跨特征）。

**B2 圆周卡尺的 `phi = −a` 与径向取向**
症状：圆直径读数偏、或只有一侧几把卡尺检出。
机理：圆周上角 a 处的点为 `(圆心行 + R·sin a, 圆心列 + R·cos a)`，其径向单位向量 `(sin a, cos a)`
在"长轴 = (−sinφ, cosφ)"的约定下要求 φ = −a。写反符号等于把每把卡尺转了 2a。
守门：无断言，靠人工核对（品红整圆贴孔边、黄框长轴指向圆心）。

**B3 半宽夹取下限 0.5px**
症状：卡尺数调大后偶发"第 i 把未检出"。
机理：`halfWidth = max(spacing/2, 0.5)`；把它改成"允许 0"会造出退化测量对象（算子返回空或不稳），
错误表现却像"边太弱"，会把人一路引向降阈值。
守门：无断言，靠人工核对（N=1000 时预览仍出图）。

**B4 "全部"与"第一条"取同一个点**
症状：数值稳定但一直量在最内侧那条边上。
机理：`CollectRegionEdgePoints` 统一取 `rowEdge[0]`；`Select='all'` 只是让算子多返回几个点，插件不铺开用。
这是**有意的口径**（写进用户文档"选择"一节），改动它等于改变所有已配好方案的含义。
守门：无断言，靠人工核对（把「选择」在"第一条/全部"间切换，测量值必须一模一样）。

**B5 "必须全检"被改成"部分平均"**
症状：一批次里偶尔缺边的工件读数仍在公差内，缺陷漏检。
机理：任一把卡尺检不到就整轮 `Failed`；若改成跳过缺失的那把，错误就不再出声（计量最危险的失败模式）。
守门：无断言，靠人工核对（把某把卡尺拖到空白处必须报"第 i 把…未检出"）。

**B6 重试次数只兜"偶发首跑空"**
症状：现场"偶发未检出"消失后，把重试次数当成灵敏度旋钮调大。
机理：4 次重试针对的是同参首跑偶尔 0 边（实测 0/1/1）；真没边时第 4 次仍空、照样失败。
若把它改成"重试到出边为止"，就会把"确实没有边"的工件平均出一个可疑值。
守门：无断言，靠人工核对（空白图上跑必须仍失败）。

**B7 残差口径是中位数，不是最大值**
症状：毛刺工件上 Tukey 明明拟合对了，却被判"拟合残差过大"。
机理：`Median(residuals) > FitMaxError` 才失败；换成 `Max` 就等于关掉抗离群。
守门：无断言，靠人工核对（样图实测 12px 毛刺下点到线距：Tukey 196.5 / 最小二乘 191.092，前者不得报残差过大）。

**B8 圆退化三条几何判据**
症状：给一个"贴着少数点的小圆"直径，数值看着合理却完全错。
机理：鲁棒算法（geo 系列）遇到共线点**不抛异常**，半径有限、残差中位数也可能达标；
只有"半径 vs 图像对角线 10 倍""点集跨度 < 2px""直径 < 跨度 60%"这三条几何判据能拦住。
守门：无断言，靠人工核对（三个共线点必须报退化，而不是给半径）。

**B9 角度射线的取向归一化**
症状：150° 的楔角报成 −30°，或同一工件正反装读数互补。
机理：`fit_line_contour_xld` 输出的端点顺序决定 `angle_ll` 的取向，必须先把每条线换成
"离交点更远的那个端点"，再取绝对值 × 180/π。
守门：无断言，靠人工核对（样图 30°/90°/150° 三种楔角应得 29.91°/90°/150.1°）。
⚠ 同族口径 `[GEO] 夹角 0° 与 170° = 10（补角归一，不是 170）` 守的是 GeometryTool 的 `GeometryMath`，
**改卡尺这段它不会红**——别把它当本条的守门人。

**B10 判平行的阈值**
症状：两条近平行边测出一个巨大的角度或随机角度。
机理：`|cross| < 0.0017 × norm` 时报错而不是硬算；调小它会让"交点跑到无限远"的样本进结果。
守门：无断言，靠人工核对。

**B11 角度不乘像素当量**
症状：改当量后角度跟着变（现场表现为"标定一改，角度全错"）。
机理：物理值组装处有 `Kind == Angle` 单独分支（量纲无关）。写成统一乘当量是最顺手也最难发现的错。
守门：无断言（`[CALM]` 的四条端到端当量断言都跑长度类，不覆盖角度），靠人工核对
（当量 1.0 → 0.5：点到线距应减半，角度必须一字不变）。

**B12 渲染失败不得污染 `Success`**
症状：内存紧张时批量误判 NG/误报失败，但测量本身是对的。
机理：渲染 try/catch 只置 `MeasureImage = null` + 一条 Warn。若把异常往外抛，外层 `catch` 会 `Fail("卡尺测量失败：…")`。
守门：无断言，靠人工核对（临时让渲染抛异常后，`MeasureValue`/`IsOk` 仍应有值、`Success` 仍应 true）。

**B13 端口"非空才赋值"**
症状：渲染失败轮下游拿到一个已释放的 HImage，偶现花图或崩溃。
机理：`if (result.MeasureImage != null) MeasureImage.TypedValue = ...`；无条件赋值会把 null 覆盖掉轮首状态，
或把被 finally 释放的源对象交给端口。
守门：无断言，靠人工核对（配合 B12 一起验）。

**B14 NG 不得写 `Success=false`**
症状：NG 件把流程当"步骤失败"处理（下游分支走错、报警当成设备故障）。
机理：NG 只写 `ErrorMessage`，`Success` 保持基类预置的 true。基类 `Fail()` 一行就同时改两个，
所以**误用 `Fail` 表达 NG** 是最容易写错的一处。
守门：无断言，靠人工核对（超差样本必须 `Success=true`、`IsOk=false`）。

**B15 `FittedGeometry` 对宽度/两点距给的是测量连线**
症状：下游按"拟合几何"消费这个端口，宽度类型拿到的是每对边之间的短连线。
机理：`fittedXld ?? measureXld` 的回退是第一批留下的语义，端口描述里已明写。
改这个回退 = 静默改契约，必须同时改用户页第 3 页端口表与下游配置。
守门：无断言，靠人工核对。

**B16 搜索区只取列表前 N 个**
症状：明明画了第 3 个区，结果与它无关。
机理：`CaliperRegions.Take(required)`；多余的区不参与运算但会占位（顺序即身份）。
界面上没有"排序"入口，所以顺序只能靠删/建来控。
守门：无断言，靠人工核对。

**B17 切类型只补数量、不改形状不删区**
症状：切一次类型，摆好的区全没了（若真删了）；或切到圆直径后区还是矩形。
机理：`EnsureRequiredRegions` 只在 `Count < Required` 时 `AddDefaultRegions`；形状纠正**故意交给运行期中文报错**。
守门：无断言，靠人工核对（切类型前后 `搜索区列表` 的行数只增不减）。

**B18 播种默认区的尺寸基准来自"当前图"**
症状：没接图时播种的区落在 640×480 的位置，接上 500 万像素图后区挤在左上角。
机理：`CurrentImageSizeOrFallback()` 取不到图就回退 640×480；`OnSourceImageChanged` 只对**缺数量**的区补播，
不会重排已有区。
守门：无断言，靠人工核对（先接图再重置）。

**B19 界面区间与运行期夹取两份数字必须同步**
症状：界面允许 Sigma=0.2，运行时被夹回 0.4，用户看不出为什么。
机理：XAML 的 `Minimum/Maximum` 与 `ClampFinite` 的常量各自一份（虽然都引用同一批 `private const`，
但 XAML 里的数字是**字面量**）。
守门：无断言，靠人工核对（改任一常量时两页文档三处都要跟）。

**B20 `partial` 与生成器**
症状：改了 `[StepConfig]` 声明但界面/灌值不生效，或编译报"OnSigmaChanged 未定义"。
机理：属性实现与 `partial void OnXxxChanged` 由 `Core.PluginGenerators` 生成；
只重编宿主看不到生成器变化（R18）。
守门：无断言，靠人工核对（改生成器后 `dotnet build VisionMaster.sln`）。

## 并行安全的声明依据

`[ParallelSafe]` 成立的前提，本插件逐条满足：
① 不持有全仓共享的非托管窗口（渲染只攒 plan，窗口在烘焙件里按实例私有）；
② 不写 UI（`SchedulePreview` 在运行实例上第一行就 return，非 UI 线程调用只做投递）；
③ 无跨步骤/跨实例共享可变对象（`MeasureParams` 每轮新建，中间 HALCON 对象全进方法内 `temp`）；
④ 端口值只写自己的输出端口。
**破坏条件**：若将来要缓存 measure 句柄、或把 `_renderer` 换成进程级单例，本声明必须撤掉并重跑并行闸门。
