# 图像赋值 · 端口与参数

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageAssign

本页给全：两个输入端口的类型与必填性、能连什么不能连什么、参数面板为什么长这样、
`.vms` 里实际落盘的键名，以及"接不上会怎样"的具体表现。

## 输入端口

| 端口 | 类型 | 必填 | 默认 | 面板标签 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `InputImage` | `HImage` | 是 | `null` | 要写入的图像 | **只能连上游**——界面上没有"手填一张图"这回事（图像只能由视觉流程产生） |
| `VariableName` | `string` | 是 | 空串 | 目标全局图像变量名 | 手打变量名，或由上游连一个**产出名字字符串**的文本输出 |

> **端口名与代码里的属性名不一致**：`VariableName` 这一行的 C# 属性叫 `TargetVariableName`。
> **连线、存档、日志用的键都是端口名 `VariableName`**，按属性名去找会对不上。

## `InputImage` 能接什么

类型兼容判据由宿主 `TypeHelper.CanBindTo` 决定，本算子的口是 `HImage`，所以：

| 上游输出 | 能不能连 | 原因 |
| --- | --- | --- |
| `HImage`（采集 / 预处理 / 结果显示的图像输出） | 可 | 同类型 |
| `HObject` 家族里能作为图像的那个输出 | 视声明类型 | 派生 → 基类可绑，反向不行 |
| `HRegion`（ROI 域） | **不可** | 区域不是图像，编译期即报连线类型不匹配 |
| 数值 / 文本 / 布尔输出 | **不可** | 图像端口不吃标量 |

**接不上会怎样**：编译期报连线类型不匹配，流程无法进入运行。
**连了但上游本轮没产出图**：运行期本步骤失败，`ErrorMessage` 为 `输入图像为空或未初始化`
（上游算子失败时它的输出端口通常是空的，所以这一条常常是"上游才是病根"）。

## `VariableName` 这一行的语义是"名字"

这条最容易踩，单独说清（与 AGENTS.md 里"名字不等于值"的同一条纪律一致）：

- 该端口要的是**变量名本身**（一段字符串，例如 `Img`）。
- **不要**用通用的「变量绑定」弹窗去选一个全局变量接进来——那条连线的语义是"运行期由那个变量提供值"，
  于是这一行拿到的是**那个变量的当前值**，写的时候就是"拿值当名字"，报 `找不到全局变量「1485」` 这类莫名错误。
- 正确姿势：**手打名字**；或让上游产出一个内容正好是名字的文本（例如配方/工单里的字段），
  连进来时那个文本的值必须逐字等于变量名。
- 匹配口径：按名查、大小写不敏感，同名以靠前者为准。名字里的空格会被 `Trim`，两端之外不算。

## 输出端口

| 端口 | 来源 | 说明 |
| --- | --- | --- |
| `Success` | 基类自带 | 本步骤是否跑通。基类在每次执行开头预置 `true`，失败时由 `Fail` 置 `false` |
| `ErrorMessage` | 基类自带 | 失败时的中文原因，可直接连去报警 / 记录 |

**没有图像输出端口，也没有别的输出。** 图写进变量之后上游那条链照常继续用这张图。

派生类插件**不要再声明一份同名的 `Success` / `ErrorMessage`**：重复声明会影子隐藏基类成员，
结果是"插件写自己那份端口、引擎读基类那份端口"，表现为**永远报失败且错误信息为空**。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

**本算子没有任何 `[StepConfig]` 配置项**。所谓"配置"就是上面两个输入端口的手填值，
由基类默认生命周期写进步骤的 `InputValues`：

| 存档键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `VariableName` | string | 空 | 目标全局图像变量名。填上后即可通过编译 |
| `InputImage` | `HImage` | 无 | 只能由链接提供。**没连上游时编译期报** `[参数缺失] … 的必填参数 'InputImage' 未配置` |

参数面板是宿主的**自动端口面板**（本插件不实现自定义视图接口）：
界面上显示的是端口的**描述文字**（"要写入的图像" / "目标全局图像变量名"），不是端口名；
每行 = 标签 + 值 + 链接按钮 + 清除。

## 取值优先级与"改了什么影响什么"

- 端口生效值优先级：**上游链接值 高于 界面手填值 高于 端口默认值**。
- 一次执行内取值只在开头做一次（源码里就是两次 `GetTypedValue()`），整步用同一个值——
  不会出现"名字按新的、图按旧的"这种半截状态。
- 改 `VariableName` 只影响写入目标；改 `InputImage` 的连线只影响写入内容。
  两者都不产生任何图像处理，所以**不存在"改了参数要重新训练/重新标定"这类连锁**。
- 想显示**带标注**的图：把上游换成「结果显示」的 `AnnotatedImage`，而不是原始图像。

## 与显示端的职责边界

本算子**不做像素转换**。真正的"Halcon 像素 → WPF 位图"发生在显示端（组态取值出口那一处统一转换），
本算子只搬引用。所以画面卡顿、颜色失真这类问题不归它，见《排错》的分诊表。
