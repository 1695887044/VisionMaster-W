# 图像赋值

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageAssign

把**流程里的一张图"写进"一个全局图像变量**，让组态画面（SCADA）上的「图像显示」图元能实时看到流程在拍什么。
它是"**视觉流程 → 全局变量 → 组态画面**"这条链路里**唯一的写入口**：
流程每跑一张图，画面上的图元就刷新一次。

**它不做任何图像处理**（零 HALCON 算子），**也没有任何图像输出端口**——
它不"从一个口搬到另一个口"、不转发图像，只负责把上游那张图的**引用**交给变量。

## 为什么需要它

在它有之前，**写全局变量在代码里根本没有通路**：连线方向只有"读全局变量"，插件拿不到任何写入的正门。
照着注释自己写的插件会"**编译通过、运行静默失败**"。
所以本算子的价值不在算法，而在**打通写回通路**——能力契约 `IGlobalVariableWriter` 由宿主实现、
通过执行上下文交给插件，插件物理上够不到"变量管理"所在的程序集。

## 它和「变量赋值」、和"图像流"的分工

| | 图像赋值（本算子） | 变量赋值 |
| --- | --- | --- |
| 写什么 | **只写图像**（`HImage`） | 任意值（数值 / 文本 / 布尔…） |
| 作用域 | 天生只写**全局**变量 | 可选 `Runtime`（运行时）/ `Global`（全局） |
| 输入 | `InputImage` + `VariableName` 两个端口 | `Name` / `Value` / `Scope` / `CreateIfNotExists` |
| 变量不存在 | **报错，不自动建** | 运行时作用域可 `CreateIfNotExists` 自动建 |
| 界面 | 宿主的自动端口面板（没有自定义视图） | 自带配置界面 |

**和"图像流"的分工**（同一张图要送去处，三条路各有各的口）：

| 你想要 | 该用哪个算子 |
| --- | --- |
| 组态画面上实时显示这张图 | **图像赋值** → 画面上的「图像显示」图元绑定该全局图像变量 |
| 在主界面的**视图窗口**（1~9）里看，还要带数值/几何标注 | 「结果显示」（`AnnotatedImage` + `DisplayViewIndex`），或各检测算子自带的 `DisplayViewIndex` |
| 把图**存成文件**留档 | 「CSV记录」的「图片」端口（连 `HImage` 就存一份图片副本） |
| 把图**发出去**（网络/PLC） | 上报类算子（结果上报等），不要用图像赋值 |

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `InputImage` | 是 | 要写入的图像（`HImage`）。**只能连上游**——界面上没有"手填一张图"这回事（图像只能由视觉流程产生）。未连上游则运行失败并提示 |
| `VariableName` | 是 | 目标全局**图像**变量名（文本端口）。既能在面板里**手打变量名**，也能由上游连线驱动（例如由上游节点决定"这一轮写哪个变量"） |

> **端口名与代码里的属性名不一致**：属性叫 `TargetVariableName`，但**连线和落盘用的键是 `VariableName`**。
> 按属性名去找会对不上。
> **变量名那一行不要挂"变量绑定"弹窗去选变量**：这行的语义是**名字**，通用绑定弹窗给的是"值"
> ——接上去会变成"运行期由那个变量提供值"，写进去的就是那个变量的当前值，而不是它的名字。
> 直接手打名字（或让上游产出**名字字符串**）。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Success` | 基类自带：本步骤是否跑通（默认预置 `true`，失败时 `false`） |
| `ErrorMessage` | 基类自带：失败时的中文原因，可直接展示给操作员 |

**没有图像输出端口，也没有别的输出**。上游那张图写进变量之后**仍然照旧可用**——
本算子不 new、不 copy、不 Dispose 任何 `HImage`，所有权仍归生产者。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

**本算子没有任何 `[StepConfig]` 配置项**。所谓"配置"就是上面两个输入端口的手填值，
由基类默认生命周期存进步骤的 `InputValues`：

| 存储键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `VariableName` | string | 空 | 目标全局图像变量名。**手填后即可通过编译** |
| `InputImage` | `HImage` | `null` | 只能由上游链接提供。**没连上游会在编译期报** `[参数缺失] … 必填参数 'InputImage' 未配置` |

配置界面是宿主的**自动端口面板**（本插件没有自定义视图），界面上显示的是端口的描述文字
（"要写入的图像" / "目标全局图像变量名"），不是端口名。

## 口径与失败策略

- **一次搬运，三步守门**：① **查名**（大小写不敏感，同名以靠前者为准）→ ② **类型守门**
  （写入值的类型必须 ⊆ 变量的声明类型）→ ③ **落值**。
- **失败必须说话**：空图、空变量名、环境不支持、变量不存在、类型不符——每一种都给出
  **可以直接展示给操作员的中文原因**，禁止静默失败；写入结果按 `TryWrite` 的真实返回值如实反馈，
  **不做"无条件报成功"**。会失败的情形（原文）：

| 失败原因（界面上能看到的那句） | 怎么补 |
| --- | --- |
| `输入图像为空或未初始化` | 上游没连图，或上游本轮产出的图是空的 |
| `目标变量名不能为空` | 变量名那一格没填 |
| `当前执行环境不支持写入全局变量` | 简化构造（如离线断言容器）没有工作区绑定，**这是设计内行为、不是缺陷** |
| `找不到全局变量「X」，请先在变量管理里新建同名变量` | 变量没建 |
| `全局变量「X」的类型是 Y，无法写入 HImage（值 […]）` | 变量声明类型必须是 `HImage`（或 `object`） |
| `全局变量「X」不支持写入（该变量类型未实现可写契约）` | 该变量类型不可写 |

- **变量是设计期资产：运行期只能写、不能增**。刻意**不做**"变量不存在就自动创建"——
  插件在运行期悄悄改变量表会让方案结构随运行结果漂移（跑一次多一个变量），
  而组态画面绑的是设计期那批名字，问题极难复现。
- **类型守门是严格匹配**，不做隐式数值转换：静默的数值拓宽/收窄在工业现场比"报错"危险得多。
  （写入器会把**文本**值按变量声明类型解析一次，那是给"手填界面只能产出文本"用的；
  图像不是文本，照旧直接报错。）
- **写进去的是引用，不是快照**。变量持有的是**同一个 `HImage` 对象引用**：
  零拷贝、零额外显存；副作用是上游若**原地修改**同一个实例，变量里看到的值也会跟着变。
  要"冻结某一帧"，应由**上游产出新实例**（而不是在本算子里想办法）。
- **所有权不动**：本算子不 `Dispose` 任何图，也不接走图。基类的"轮首自动回收"只针对**输出端口**，
  而且对"与上游链接同引用"的值会跳过释放——所以图写进变量后，上游那条链照常继续用这张图。
- **图像变量的值不落盘**：`HImage` 无法 JSON 序列化，**当前值不随方案保存 → 重启后画面无图**（回落"无图像"），
  跑一轮流程才有图。这是设计口径，不是丢数据。
- **不做像素转换**：真正的"Halcon 像素 → WPF 位图"发生在**显示端**
  （组态取值出口那一处统一转换），本算子只搬引用。

## 典型用法 / 接线

```
图像采集.OutputImage ──▶ 图像赋值.InputImage
                        图像赋值.VariableName ◀── 手打 Img（或上游字符串端口喂进来）

变量管理：新建全局变量 Img，类型 HImage（必须事先建好）
组态画面：放「图像显示」图元 → 绑定 Img
运行：流程每跑一帧，画面刷新一次
```

**第一次使用（6 步）**：
① 先在「变量管理」里建一个类型为 `HImage` 的**全局**变量（例如 `Img`）——不建则运行必失败；
② 工具箱「图像处理」里拖入「图像赋值」；
③ 双击打开参数面板，第 1 行「要写入的图像」点 🔗 连上游节点的图像输出；
④ 第 2 行「目标全局图像变量名」**直接手打**变量名（如 `Img`）；
⑤ 点「确定」保存（存进 `InputValues`）；
⑥ 组态画面放「图像显示」图元并绑定该变量。

> **想显示带标注的图**：把上游换成「结果显示」的 `AnnotatedImage`，
> 而不是原始图像——存图/上画面都自带标注。

## 常见问题

**Q：会不会把图复制一份、白占内存？**
不会。变量拿的是**同一个 `HImage` 引用**，零拷贝。副作用请记牢：上游若对同一实例做**原地修改**，
变量里看到的也会变。需要"冻结某一帧"应由上游产出新实例。

**Q：图像赋值节点后面，上游那张图还能继续用吗？**
能。本算子不 new、不 copy、不 Dispose 任何图，所有权仍归生产者。

**Q：重启软件后画面还有图吗？**
没有。图像变量的**当前值不落盘**（`HImage` 无法序列化），重启后为空，画面回落"无图像"；
流程跑起来才有图。

**Q：变量不存在会自动建吗？**
不会，必须先在「变量管理」里建好同名的 `HImage` 全局变量。运行期只能写、不能增。

**Q：变量名写错了会怎样？**
按名查（大小写不敏感）。写成一个**已存在的别的变量**时：类型不符就报错；
若那个变量恰好是 `object` 类型，**会真的写进去**——本算子不校验"目标是不是图像变量"，
守门只保证"写入值类型 ⊆ 变量声明类型"。所以名字请从变量管理里核对一遍再填。

**Q：为什么变量名是文本框而不是下拉？**
文本端口既能手填，也能被上游连线驱动（由上游决定"这一轮写哪个变量"），与「变量赋值」保持同一手感。
但注意语义是**名字**：那一条不要接"提供值"的通用变量绑定。

**Q：画面上的图不刷新，先查什么？**
① 本步骤 `Success` 是否为 `true`、`ErrorMessage` 有没有内容；
② 图元绑定的变量名和这里填的是不是**同一个**（大小写不敏感，但拼写要对）；
③ 变量类型是不是 `HImage`（或 `object`）；
④ 流程是不是真的产出了图（上游失败时输出端口通常是空的 → 这里会报"输入图像为空或未初始化"）。

**Q：它和「结果显示」都能让画面看到图，用哪个？**
看画面是哪种：**主界面的视图窗口**（1~9）用「结果显示」/各算子的 `DisplayViewIndex`；
**组态画面上的图像显示图元**必须走本算子（图元绑的是全局变量，视图窗口它看不到）。

**Q：能不能一次写多个变量（多路画面）？**
一个本算子实例只写一个变量。要多路就放多个「图像赋值」，各自连同一批上游图像输出、填各自的变量名。
