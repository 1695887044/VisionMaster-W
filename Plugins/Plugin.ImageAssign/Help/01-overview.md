# 图像赋值

> 分类：图像处理 ｜ 来源：插件 Plugin.ImageAssign

把**流程里的一张图写进一个全局图像变量**，让组态画面（SCADA）上的「图像显示」图元实时看到流程在拍什么。
它是「视觉流程 → 全局变量 → 组态画面」这条链路最直接的写入口（「变量赋值」节点与 C# 脚本的共享变量
写入也能写，三条路汇到同一个 `IWritableVariable.TryWrite` 收口）：流程每跑一张图，画面就刷新一次。

**它不做任何图像处理**（一个 HALCON 算子都不调），**也没有任何图像输出端口**——
它不把图"从一个口搬到另一个口"、不转发、不复制，只把上游那张图的引用交给变量；
**变量侧在落值时拷一份**（写入即拷贝），所以画面拿到的是稳定快照，不会被上游下一轮的回收带走。

## 为什么需要它

在它出现之前，**图像**写全局变量没有专门通路：「变量赋值」节点要手填一个值（图像填不进去），
C# 脚本要先自己把图取到手里；"画面上跟着流程刷图"这件事没有正门。
所以本算子的价值不在算法，而在**把这条链一次接通**——能力契约 `IGlobalVariableWriter` 由宿主实现，
通过执行上下文 `IExecutionContext.GlobalVariables` 递送给插件；插件物理上够不到「变量管理」所在的程序集。

## 它和「变量赋值」的分工

| | 图像赋值（本算子） | 变量赋值 |
| --- | --- | --- |
| 写什么 | **只写图像**（`HImage`） | 任意值（数值 / 文本 / 布尔…） |
| 作用域 | 天生只写**全局**变量 | 可选 `Runtime`（运行时）/ `Global`（全局） |
| 输入 | `InputImage` + `VariableName` 两个端口 | `Name` / `Value` / `Scope` / `CreateIfNotExists` |
| 变量不存在 | **报错，不自动建** | 运行时作用域可自动建 |
| 界面 | 宿主的自动端口面板（没有自定义视图） | 自带配置界面 |

## 同一张图要送去处，三条路各有各的口

| 你想要 | 该用哪个算子 |
| --- | --- |
| 组态画面上实时显示这张图 | **图像赋值**，画面上放「图像显示」图元并绑定该全局图像变量 |
| 主界面**视图窗口**（1~9）里看，还要带数值/几何标注 | 「结果显示」（`AnnotatedImage` + `DisplayViewIndex`），或各检测算子自带的 `DisplayViewIndex` |
| 把图**存成文件**留档 | 「CSV记录」的图片端口（连 `HImage` 就存一份图片副本） |
| 把图**发出去**（网络 / PLC） | 上报类算子（结果上报等），不要用图像赋值 |

## 快速上手（6 步跑通第一次）

① 先在「变量管理」里新建一个类型为 `HImage` 的**全局**变量（例如 `Img`）——不建则运行必失败；
② 工具箱「图像处理」分组里拖入「图像赋值」；
③ 双击步骤打开参数面板，第 1 行「要写入的图像」点链接按钮，连上游节点的图像输出（如 `图像采集.OutputImage`）；
④ 第 2 行「目标全局图像变量名」**直接手打**变量名（如 `Img`），不要用它去连"提供值"的通用变量绑定；
⑤ 点「确定」保存（两个值落进步骤的输入常量）；
⑥ 到组态画面放「图像显示」图元，数据源绑定同一个变量名。

接线示意：

```
图像采集.OutputImage ──链接──▶ 图像赋值.InputImage
变量管理里的全局变量 Img（类型 HImage，事先建好）
图像赋值.VariableName ◀──手打── Img
组态画面「图像显示」图元 ──绑定── Img
流程每跑一帧 ──▶ 画面刷新一次
```

## 跑通之后该看到什么

- 步骤输出 `Success` 为 `true`、`ErrorMessage` 为空；
- 运行日志里有一行 `图像赋值 已把图像写入全局变量 Img`（前缀是该步骤的实例名）；
- 「变量管理」里 `Img` 的当前值变成刚写入的图（重启软件后这一格会回落为空，见下）；
- 组态画面的图像随每一轮流程刷新。

## 需要知道的三条口径

- **写进去的是引用，不是快照**：变量拿的是同一个 `HImage` 对象引用，零拷贝、零额外显存。
  副作用是上游若对同一实例做**原地修改**，画面里看到的也会跟着变。要"冻结某一帧"应由上游产出新实例。
- **变量是设计期资产，运行期只能写、不能增**：刻意不做"变量不存在就自动创建"——
  插件在运行期悄悄改变量表会让方案结构随运行结果漂移，而组态画面绑的是设计期那批名字。
- **图像变量的当前值不落盘**：`HImage` 无法 JSON 序列化，当前值不随方案保存，**重启后画面无图**，
  跑一轮流程才有图。这是设计口径，不是丢数据。

## 常见问题（速答）

**Q：会不会把图复制一份、白占内存？**
会复制**一次**，但复制发生在变量侧（`LocalVariableModel.TryWrite` 的 HImage 分支），不是本算子。
这次拷贝是必须的：上游下一轮开始就会释放端口上那张图，不拷就等于画面拿着一根死句柄
（表现为 Web 运行态图像周期性 404）。代价是每轮一张全图（500 万彩图 ≈ 15MB）。

**Q：这个节点后面，上游那张图还能继续用吗？**
能。本算子不 new、不 copy、不 Dispose 任何图；变量存的是自己拷的副本，与上游那张互相独立。

**Q：变量名写错了会怎样？**
按名查（大小写不敏感）。若恰好写成一个已存在的 `object` 类型变量，会真的写进去——
本算子不校验"目标是不是图像变量"，守门只保证"写入值的类型 ⊆ 变量声明类型"。名字请核对后再填。

**Q：为什么变量名是文本框而不是下拉？**
文本端口既能手填，也能被上游连线驱动（由上游决定"这一轮写哪个变量"），与「变量赋值」保持同一手感。
但这一行的语义是**名字**，不要接"由上游提供值"的通用变量绑定（后果见《排错》）。

**Q：能不能一次写多个变量（多路画面）？**
一个实例只写一个变量。要多路就放多个「图像赋值」，各自连同一批上游图像输出、填各自的变量名。
