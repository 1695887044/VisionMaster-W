# 颜色序列检查 · 界面与操作

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorCheck

配置窗口是**左参数、右图像**两栏（左栏定宽 330 像素、内容超长自动出滚动条；右栏吃掉剩余宽度）。
右侧的图像编辑能力**全部来自共享控件 `ImageEdit`**（`Core.Halcon`），本算子只做绑定，没有自己造图像控件。
视图里没有任何业务算法：三个按钮只是转发到插件实例，框选与形状参数的双向同步都在插件侧。

## 左栏卡片一览（自上而下）

| 卡片 | 里面有什么 | 干什么用 |
| --- | --- | --- |
| **图像输入** | 一行 `LinkableValueEditor`（标签「输入图像」，带 🔗 绑定入口） | 把 `Image` 端口链到上游输出或变量。**这是图像的唯一来源** |
| **采样区** | 一行说明文本、「当前采样区」摘要、**清空采样区**按钮 | 摘要实时显示 `中心 (行, 列) 角度 X 度 半长 X 半宽 X`；未框时显示"尚未框选采样区" |
| **检查参数** | 序列反向（勾选）、线数（0 = 自动反推）、等间距规整化（勾选）、**试算一下**按钮、结果摘要框、**高级参数**折叠区 | 日常只需要「线数」与「规整化」两个旋钮，其余全收在折叠区里 |
| **配方** | 格式说明、多行文本框（96 高、接受回车）、**把试算结果存成配方**按钮、口径说明 | 配方正文随方案落盘 |
| **怎么用** | 四步操作说明 | 现场忘了顺序时看这里 |
| **本轮范围** | 能力边界说明 | — |
| 底部一行提示 | 插件的 `Hint` 文本 | 载入图像、存配方、报错原因都写在这一行 |

> 「怎么用」与「本轮范围」两张卡片里有**两句已经过时的话**（提到"填示意图路径并点载入"、提到"阈值暂写死"）。

## 高级参数折叠区（7 项 + 1 组阈值）

| 界面标签 | 对应参数 | ToolTip 口径 |
| --- | --- | --- |
| 暗线判据幅度 | `DarkSpanRatio` | 判定线 = 剖面众数亮度 − 该百分比 ×（众数亮度 − 最暗像素） |
| 白线百分位 | `BrightPercentile` | 亮度高于这条百分位的行算「白线」 |
| 最小段长 | `MinRun` | 连续多少行都可靠才算一根线，用来滤噪点 |
| 最大段长比例 | `MaxRunRatio` | 长过剖面长度这个比例的可靠段按背景丢弃；填 0 = 不做这个保护 |
| 补色窗口比例 | `RuleWindowRatio` | 给「补出来」的那几根取色时的窗口半宽，单位是线距的比例 |
| 投射视图窗口 | `DisplayViewIndex` | 结果画到主界面哪个视图窗口（1~9）；填 0 = 不投射 |
| 端点外推 | `ExtendEnds` | 允许在检出范围两端各多探一根（靠「那一格有没有起伏」判断） |
| 颜色判据阈值 | 13 项，共用控件 `ColorThresholdEditor` | 无彩饱和度 / 黑明度 / 白饱和度 / 白明度 / 棕暖度 / 棕明度 / 玫红起点 / 红起点 / 红止点 / 橙止点 / 黄止点 / 绿止点 / 蓝止点 |

⚠ **「白线百分位」的调向，界面上有两处口径相反的说法**：控件 ToolTip 写"日志出现丢弃过长可靠区间时把它调小"，
而算法发出的那条告警原文写"把「白线百分位」调高或把采样区收紧些"。**以告警那条为准**：
阈值线取自亮度的高位百分位，**调高**才会让"又长又平的浅色背景"落到阈值线下、不再被收成一段。
调低的正确用途是**白线检不到**（阈值压低，白线才够得着）。这条矛盾已列入未决问题。

## 画布上的操作（全部由 `ImageEdit` 控件提供）

| 动作 | 怎么做 | 结果 |
| --- | --- | --- |
| 新建采样区 | 图上**右键 → 新建矩形**，拖出一个框 | 左栏摘要立刻更新，形状参数落进 `RoiParams` |
| 改形状 | 拖角点手柄改大小、拖边改位置、拖中心移动 | 松手即回写，摘要跟着变 |
| **第一次点某个框就能拖** | 直接在**未选中**的框上按下并拖 | 会**换绑并立即开始拖**（共享控件里"换绑后补发一次按下"的行为）。未选中框上**只点不拖**则只是选中，尺寸不变 |
| 命中容差 | 起笔点偏出手柄约 11 像素以内 | **不会**把当前选中的框摘掉（容差与手柄同宽，瞄偏一点不丢选中） |
| 删除 | 右键框 → 删除 | 摘要回到"尚未框选采样区" |
| 一次清干净 | 左栏**清空采样区**按钮 | 集合清空，`RoiParams` 置空 |

**本算子只用一个框**：画了多个时，**取集合里最后一个**为准（拖拽回写也只认最后一个）。
多画的框不会参与计算，要收拾就点「清空采样区」重画一个。

## 关于"取色"：界面上没有吸管

**没有**取色器/吸管/参考色示教这类控件，也**不能**在图上点一个像素看它的颜色词。
颜色是**算法自己取的**：沿采样区短边逐点取样，每个短轴位置在长轴方向取 **5 条邻近采样线**（偏移 -4 / -2 / 0 / 2 / 4 像素），
同一位置这 5 个点按通道**取中位**合成**一条中位剖面**——这是抗反光和脏点的手段，也是"为什么框要贴着线束"的原因。

想知道某一根被判成了什么颜色，用**试算一下**结果框里的「来源」行（`1黑检,2白补,…`）；
想看这一幅图的分色判据落在哪，看结果框的「阈值」行。这两行是调参时**唯一的仪表**。

## 试算与「存成配方」

- **试算一下**：拿当前显示在画布上的那张图（也就是 `Image` 端口带进来的那份）走**和生产完全相同**的
  采样 + 分析 + 判定链路，把结论写进结果摘要框。**不写任何输出端口**，也不投到视图窗口。
- 画布上没图时点它会提示"先点「载入」把示意图读进来再试算"——**这句话里的按钮并不存在**，
  正确做法是回到「图像输入」把端口链上、点一次「执行」把上游图带进来。
- **把试算结果存成配方**：把上一次试算的颜色序列按 `N 芯 = 颜色1,颜色2,…` 追加到配方文本末尾。
  已经在配方里出现过**同一行**时不重复追加，只在底部提示一行。没有试算结果时提示先框好采样区并点「试算一下」。
- 追加的新行排在**末尾**：若配方表里已经有同芯数的另一条，运行期**取的是第一条**（也就是先写的那条），
  并留一条告警。要钉死比哪条就走 `ExpectedSequence` 端口。

## 结果摘要六行怎么读

```
找到 10 根：黑,白,灰,紫,蓝,绿,黄,红,玫红,棕
线距 21.5 像素（分段估 21.0 / 自相关 22.0）
阈值：暗 < 114　彩 > 47　亮 > 236
来源：1黑检,2白补,3灰检,4紫检,…
期望：黑,白,灰,紫,蓝,绿,黄,红,玫红,棕（配方「10 芯」）
判定：合格　线序正确，10 芯：…（配方「10 芯」）
```

| 行 | 看什么 |
| --- | --- |
| 根数与序列 | 和实物对不对。根数不对是"找线"环节的问题，不是判色问题 |
| 线距 | 两个估计值是否接近；差得远就去看日志里哪条仲裁规则生效了 |
| 三个阈值 | 调参主表：暗线阈值应落在"线间缝"与"暗线"之间 |
| 来源（检/补） | `检` = 真的看到；`补` = 按线距推出来的。补得多说明直接抓到的段太少 |
| 期望与配方名 | 确认比的是哪条配方 |
| 判定 | 与 `Verdict` 端口、画面标注、日志**同一句** |
