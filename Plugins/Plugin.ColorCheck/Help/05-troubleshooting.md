# 颜色序列检查 · 排障

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorCheck

按**界面上/日志里真正会出现的原话**逐条对。文案取自源码，检索时可以直接粘原文去搜。

## 一、本步骤直接失败（`Success=false`，`ErrorMessage` 就是原文）

| 原文（节选） | 为什么 | 怎么改 |
| --- | --- | --- |
| `上游没有图像：请先在流程里把本节点的 Image 连到上游…` | `Image` 端口没值或图未初始化。端口 `IsRequired=false`，所以**编译期不拦**，运行期才报 | 画布上从上游拖一条线过来，或右键 → 变量绑定选上游的图像输出；确认上游那一步自己跑成功了 |
| `尚未框选采样区：请在节点配置里于图像上右键 → 新建矩形，框住线束` | `RoiParams` 不是 5 个数（没画、被清空、或点了「清空采样区」） | 打开配置，右键新建矩形。**第一次点执行报这条是正常的**——此时图刚上屏，框完再执行一次 |
| `颜色序列检查要彩色图，当前图像只有 N 个通道` | 灰度图/单通道图进不来（先查 `CountChannels`，再查取色返回的通道数） | 上游换成彩色输出；若采集设了灰度模式请改回。要预处理就放在本算子**之前** |
| `采样区的半长/半宽必须大于 0：请重新画一个框` | 形状参数退化（拖成一条线/一个点，或旧方案里存了坏值） | 重新画一个有面积的框 |
| `采样区的短边只有 N 个像素，太窄了：把框沿线束方向之外的那一边拉宽些` | 短边采样点不足 8 个 | 沿**垂直于线束走向**的那一边把框拉宽 |
| `采样区超出图像范围（图像 WxH，采样点取到 (r, c)）：请把框画在图像内` | 采样点落到图外（框画到边缘外、或换了更小的图） | 把框整个挪回图内 |
| `采样区太窄：沿线束方向只有 N 个采样点，至少要 8 个（把框画宽一点）` | 剖面长度不足（与上面那条同源，发生在分析阶段） | 同上，拉宽短边 |
| `采样区里几乎没有明暗变化（亮度极差只有 N 级）：多半框到空白背景上了，请把采样区移到线束上` | 亮度极差 < 25 级，说明这里没有图像结构，任何判据只会把噪声当线 | 把框移到真正的线束上；确认打光没有把暗缝"洗平" |
| `采样区里只找到 N 段可靠线，凑不出线距（确认采样区框住了整条线束；若线束颜色都很浅，把「暗线判据幅度」调小一点）` | 可靠段 < 2 段 | 先确认框住整束；线色普遍偏浅就按原文把 `DarkSpanRatio` **调小**——判定线 = 众数亮度 − 百分比 × 跨度，百分比越小判定线越**高**、算"暗"的像素越多、抓到的段也就越多。调反方向只会更少 |
| `线距估计异常（X 像素，剖面长 N）：确认采样区的短边方向与线束走向垂直` | 线距 < 2 或 > 剖面长的一半 | **参数救不了**，重画框：短边要垂直于线束走向 |
| `线距与各段中心对不上，无法定位每根线：确认采样区的短边方向与线束走向垂直` | 最小二乘回归定锚失败 | 同上，重画框；确认线束大致等间距 |
| `配方表第 N 行「…」里没有颜色：格式是「产品名 = 颜色1,颜色2,...」` | 某一行只有产品名、等号后面空了 | 补上颜色，或把该行删掉/改成 `#` 注释 |
| `未知产品：N 芯没有对应配方（配方表是空的 / 配方表里有 X（M 芯）、…）：请补一条配方，或用「期望序列」输入端口直接把期望序列给进来` | 实测根数对不上任何一条配方。**有意按配置问题报错停流程，不判 NG** | 补一条长度为 N 的配方；或让上游把期望序列喂进 `ExpectedSequence` |

## 二、只是告警（判定照常出，进日志 Warn）

| 原文（节选） | 含义 | 要不要动 |
| --- | --- | --- |
| `丢弃了 N 段过长的可靠区间（疑似浅色背景被算成了线）：把「白线百分位」调高或把采样区收紧些` | 长过 `MaxRunRatio` 的段被当背景扔掉 | **调高** `BrightPercentile`（阈值抬高，长平背景就落下去了）或收紧框。⚠ 控件 ToolTip 写的是"调小"，与本条告警相反，**以本条为准** |
| `分段线距 A 正好是自相关线距 B 的 R 倍，按自相关走（中间漏检的线被补回来）` | 仲裁判成"漏检一半" | 通常不用动；若实物本来就稀疏，检查是否把两相邻线当成一根 |
| `自相关给出的线距 A 与分段线距 B 差得较多，以分段线距为准（自相关在边缘信号上容易被线宽变化带偏）` | 仲裁站在分段一边 | 不用动；根数错再按调参页走 |
| `线数按手动指定的 N 根展开（自动估出的是 M 根），以检出范围的中点为基准` | `WireCount` 生效 | 芯数固定时这是正常状态；不想被钉死就把 `WireCount` 改回 0 |
| `配方表里有 N 条都是 K 芯（…），本次取第一条「X」；要明确指定请用「期望序列」输入端口` | 同芯数撞车，**取排在最前的一条** | 删掉多余配方，或走端口。注意「把试算结果存成配方」是**追加到末尾**的，旧那条仍会赢 |
| `图像是高位深（实测最大灰度 N），已等比压到 8 位再判色；颜色词不受影响` | 12/16 位图自动归一 | **不用动**，看到这条就不必怀疑判据 |

## 三、界面提示行（`Hint` / 结果摘要）里的话

| 原文 | 场景 | 处理 |
| --- | --- | --- |
| `还没有图像：请先在「图像输入」里绑定上游端口或变量，或点「执行」把上游图载入画布；也可以在画面上右键 → 打开图片，再试算（只影响试算，不改上游图像来源）` | 画布上没图就点「试算一下」 | 两条路任选：①「图像输入」把端口链上、点一次「执行」把上游图带进画布；②**直接在画面上右键 → 打开图片**，选一张本地图框好采样区就能试算（只影响试算，不改上游图像来源、不落盘） |
| `试算失败：` + 上面任意一条失败原文 | 试算走的是与生产相同的链路 | 按对应那条处理 |
| `已显示上游图像（试运行带进来的）：可以直接在图上右键框采样区` | 端口拿到图 | 正常，接着框 |
| `上游图像显示失败：` + 异常消息 | 拷贝上游图时抛异常 | 看消息本身；通常是图已被系统回收（上游那轮没跑成功） |
| `还没有试算结果：先框好采样区并点「试算一下」，再把结果存成配方` | 空按「存成配方」 | 先试算 |
| `配方表里已经有这一条了：N 芯 = …` | 追加的是**完全相同的一行** | 不用管（去重生效） |
| `已存成配方：N 芯 = …` | 追加成功 | 记得点确认，否则不落盘 |

## 四、现象类问答

**Q：看得见 10 根只报 8 根？** 白线与浅背景颜色上不可分，直接"找线"抓不到。
确认勾着「等间距规整化」（默认开）、开着「端点外推」；看结果框「来源」行，`检`/`补` 一比就知道差在哪。

**Q：根数多了、检到不该检的东西？** 先关掉「等间距规整化」做对照组；再把「最小段长」调大滤噪点；
浅色背景被算成线就把「最大段长比例」调小或收紧框。
**连接器上一排金属触点本身就是等间距的暗块，算法会理所当然当"线"报出来——那不是 bug，是采样区画错了地方。**

**Q：序列整体错位一格？** 回归定锚之后端部漏检只少一根、不该整体错位。还错就：① 看线距是否明显不对；
② 确认短轴方向真的垂直于线束走向；③ 方向和实物反了就勾「序列反向」（注意反向发生在判定之前，配方也得按反过来的顺序写）。

**Q：`BadIndex` 一直是 0 但 `Result=false`？** `0` = 没有"第几位"可报，要么全对要么**根数不符**。看 `Verdict`。

**Q：画面上有几根是橙字？** 橙 = 规整补出来的（`Detail` 里的"补"）；红 = 不符的那根；绿 = 检出且合格。
采样线与结论行本身随判定变色（合格绿/不合格红）。

**Q：结果没投到视图窗口？** 依次查：`DisplayViewIndex` 是否为 0；该窗口号是否真的存在（1~9，窗口号**原样直传**）；
投图整体包在 `catch` 里——**推图失败静默不报**，判定与端口照写，所以"图上没东西"不等于"没跑成功"。

**Q：配置界面右侧一直是空画布？** 图像只有「图像输入」端口一个来源，链接上游后点一次「执行」图会自动进画布。

**Q：改了配置现场还跑老结果？** 重新点「执行」/重新试运行。若连插件 DLL 都是刚重建的，
注意 `Modules\` 里的产物必须跟着更新（只重建宿主工程，运行的还是旧 DLL）。

## 五、换灯 / 换型之后：按这个顺序重调

1. **先重画采样区**——绝大多数框歪的问题到这一步就解决了：短轴方向与线束走向垂直、贴住线束、
   不把大片浅色背景或连接器金属触点圈进来。长轴自动判走向，**竖着画也能用**。
2. 点「试算一下」，读结果框第 2 行的**线距**（两个估计值差多少）与第 3 行的**三个阈值**（落在什么位置）。
3. **根数错** → 动 `Regularize`（先关掉做对照组，看直接可见几根）、`MinRun`、`MaxRunRatio`、`ExtendEnds`。
4. **颜色错**（根数对、词不对）→ 动 13 项色卡阈值，方向表见《颜色序列检查 · 颜色口径与判定》。
   先用「关掉规整化」的那份序列做参照：如果关规整化时检出的那几根颜色都对、只有"补"出来的那几根错，
   那是 `RuleWindowRatio` 的事，**不是色卡的事**。
5. **顺序/整体错位** → 先看线距是否异常，再看 `ReverseSequence`（注意反向发生在判定之前，配方也得按反过来的顺序写）。
6. 调完拿良品图点「把试算结果存成配方」更新配方，**别手打颜色词**。

| 现象 | 先查这一项 |
| --- | --- |
| 换了灯/换了曝光，整批颜色词都漂 | 试算第 3 行的阈值位置。三个阈值都按本幅图现算、通常跟着变；真不稳先查打光是否把暗缝"洗平"了（亮度极差 < 25 级会直接报"框到空白背景"） |
| 12/16 位相机接手后黑白灰棕全错 | **不用改参数**：算法按实测最大灰度等比压回 8 位（日志有"已等比压到 8 位再判色"的告警）。看到那条 Warn 就不必怀疑判据 |
| 白线死活检不到 | `BrightPercentile` 92 → 85；仍不行就确认白线是不是被 `MaxRunRatio` 当背景丢弃了（日志有"丢弃了 N 段过长的可靠区间"，那时要的是**调高**百分位或收紧框） |
| 玫红与红分不清 | 只动 `RoseHueFrom` / `RedHueFrom` 这一对（默认 330 / 350），两者只差十几度 |
| 换产品（芯数不同）就报错停线 | 配方缺失按配置问题报错是有意的，不是产品不良。补配方，或让上游把期望序列喂进 `ExpectedSequence` |
| 同芯数两条配方，比对了错的那条 | 算法取排在最前的一条并留告警。要明确指定就走 `ExpectedSequence` 端口；另外「把试算结果存成配方」是**追加到末尾**的，旧那条仍会赢 |
| 采样区太窄报错 | 短边至少 8 个采样点。报错原文写着"短边只有 N 个像素"，按它把框沿垂直于线束走向的那一边拉宽 |

**Q：调了半天根数还是不对，怎么分清是参数问题还是现场问题？** 两步：
① 关掉「等间距规整化」再试算——它只报"直接看得见"的线，拿这份和实物的可见段对比；
② 看试算第 3 行的暗线阈值——若它落在缝电平附近**甚至更高**，说明打光把暗缝洗平了，
这是光路问题（换射角 / 加遮光），**参数救不回来**。
