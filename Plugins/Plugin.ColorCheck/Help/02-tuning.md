# 颜色序列检查 · 调参与判据

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorCheck

这一页专讲**判色的口径与怎么调**：颜色空间到底用的哪一个、13 个色卡阈值各管什么、
自适应阈值的安全窗口在哪、光照/换型之后按什么顺序重调。
基础用法（端口、配方、接线）见《颜色序列检查》。

## 判据到底是什么颜色空间：固定 HSV 式，没有开关

**界面上没有"RGB / HSV / Lab"颜色空间下拉，也没有 ΔE / 颜色距离 / 容差半径。**
这不是缺功能，是刻意的：判定走的是"把像素归成一个**颜色词**"，
用连续距离度量做线序判定会被灰阶漂移牵着走（白线和浅背景本来就分不开）。

分类用的量固定是这样算的（三个量都从 R/G/B 现场推，不需要转换库）：

| 量 | 算法 | 用途 |
| --- | --- | --- |
| 明度 `v` | `max(R, G, B)` | 判黑（<80）、判白（>195）、判棕上限（<175） |
| 饱和度 `s` | `(max − min) / max`（`max<=0` 时记 0） | 无彩/有彩分界（<0.45 走黑白灰棕）、白的附加条件（<0.15） |
| 色相 `h` | 标准 HSV 色相角，0~360 度 | 有彩区按角度分色系 |

**先判"有没有颜色"，再按色相分色系**：

```
s < ColorlessSaturation(0.45)  →  无彩区
    v < BlackValue(80)                          → 黑
    s < WhiteSaturation(0.15) 且 v > WhiteValue(195) → 白
    (R-G) ≥ BrownWarmth(12) 且 (R-B) ≥ 12 且 v < BrownValue(175) → 棕
    其余                                        → 灰
s ≥ 0.45  →  有彩区，按色相角 h：
    [330,350) → 玫红      ≥350 或 <20 → 红（红跨 0 度）
    [20,45)   → 橙        [45,70)     → 黄
    [70,160)  → 绿        [160,230)   → 蓝
    [230,330) → 紫
```

**颜色词只有 11 个**：`黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫`（外加通配符 `*` 表示"这一位不检"）。
配方/期望序列必须**正好**打这些词，"深红""天蓝""magenta" 一律认不出来。
最稳的做法是拿一张已知良品点「试算一下」，再点「把试算结果存成配方」。

**想比较"两个色差多远"怎么办**：本算子给不了 ΔE。要连续量判色，请用别的路线
（例如「区域颜色检查」的 `Rgb` 中位色端口配合「C#脚本」自己算距离，
或用图像处理类插件先做通道分离/阈值分割）。线序这类"离散颜色词"场景，用本算子就够。

## 13 项色卡阈值：改哪个动到什么

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

配置路径：节点配置 → 检查参数 → **高级参数** → **颜色判据阈值**。
这 13 项是**本步骤自己带的一份副本**（默认值取自内核），改了随方案落盘，
**不影响别的工位、别的颜色算子**——不同工位的打光与材质本来就不同，全局一份色卡会变成束缚。

| 参数 | 默认 | 管到哪 | 往哪调 |
| --- | --- | --- | --- |
| `ColorlessSaturation` | `0.45` | 无彩/有彩的分界线，**黑/白/灰/棕全住在这条线以下** | 调低 → 更多像素被判成有彩（灰线容易被读成彩线）；调高 → 彩线容易掉进灰/白 |
| `BlackValue` | `80` | 明度低于它才叫黑 | 黑线偏灰（打光强）就调高；暗背景被误判成黑线就调低 |
| `WhiteSaturation` | `0.15` | 白的附加条件：饱和度必须低于它 | 白线偏色（灯光偏黄）时调高一点，否则白会被读成黄 |
| `WhiteValue` | `195` | 明度高于它才叫白 | 白线判不出来就调低；反光高光斑被判白就调高 |
| `BrownWarmth` | `12` | 偏暖判据：R 比 G、B **都**高出这么多才算棕 | 棕色线被读成灰 → 调小；灰色线被读成棕 → 调大 |
| `BrownValue` | `175` | 棕的明度上限（比它亮就归灰） | 浅棕/米色该算棕时适当调高（但越接近白值越容易抢白的字） |
| `RoseHueFrom` | `330` | 玫红起点 | 玫红被读成紫 → 调小；紫被读成玫红 → 调大 |
| `RedHueFrom` | `350` | 红起点（玫红/红分界） | **红与玫红只差十几度**，分不清就只调这一对（见下面的口诀） |
| `RedHueTo` | `20` | 红止点（红跨 0 度：`≥350` 或 `<20` 都是红） | 橙红被读成红 → 调小；红被读成橙 → 调大 |
| `OrangeHueTo` | `45` | 橙止点 | 橙黄之间分不清时调它 |
| `YellowHueTo` | `70` | 黄止点 | 黄绿之间分不清时调它 |
| `GreenHueTo` | `160` | 绿止点 | 青绿被读成蓝 → 调大；青绿被读成绿 → 调小 |
| `BlueHueTo` | `230` | 蓝止点（比它高就是紫） | 蓝紫分不清时调它 |

**改色相阈值只影响"有彩区"**——也就是只有 `s ≥ ColorlessSaturation` 的像素才轮到色相说话。
"黑线读成灰线""白线读成灰线"这类问题，**动色相阈值一点用都没有**，要动的是上面那四项无彩条件。

## 自适应三阈值与线距：谁说了算、区间在哪

「高级参数」里那几项（`DarkSpanRatio` `BrightPercentile` `MinRun` `MaxRunRatio` `RuleWindowRatio` `ExtendEnds`）
**全是无量纲的比例或百分位，不是绝对灰阶值**——这正是"自适应"的意义：换灯、换工装改的是尺度，比例大体不变。

| 旋钮 | 默认 | 口径 | 现场区间与调向 |
| --- | --- | --- | --- |
| `DarkSpanRatio` 暗线判据幅度 | `35` | 判定线 = 众数亮度 − 百分比 ×（众数 − 2% 分位亮度） | 两张样本图上的**安全阈值窗口是 100~160**：默认 35 给出 154 与 114，都在窗口里。线束整体偏浅、暗缝不明显 → 调大（判定线压低）；暗线漏检 → 调小。**别写死绝对灰阶**——脚本版写死 150 只是碰巧落在窗口里，换一盏灯就要重调 |
| `BrightPercentile` 白线百分位 | `92` | 亮度高于这条百分位的算可靠线像素 | 白线检不到 → 降到 85 左右；浅色背景被误收成长段 → 调高 |
| 彩度阈值 | 自动（Otsu） | 剖面的通道极差走大津法，界面上不给调 | 实测对结果极不敏感（20~110 都给出同一个根数），所以让人别管它 |
| `MinRun` 最小段长 | `4` | 连续这么多行都可靠才算一根线 | 噪点多 → 调大；线很细（一根只有几行）→ 调小 |
| `MaxRunRatio` 最大段长比例 | `0.33` | 长过剖面长度这个比例的可靠段**按背景丢弃** | 一"根"线不可能占掉剖面一大截；日志出现"丢弃了 N 段过长的可靠区间"就是它在防浅色背景。填 `0` = 关掉保护（不推荐） |
| `RuleWindowRatio` 补色窗口比例 | `0.30` | 给"补出来"的那几根取色时的窗口半宽（线距的比例） | 相邻两根颜色互相污染 → 调小；补出来的颜色太随机/偏暗 → 调大 |
| `ExtendEnds` 端点外推 | `true` | 两端各多探一根，判据是"那一格里有明暗起伏"（≥ 全局起伏的 20%），不要求认得出颜色 | 端部总少一根就开着；末端把线束外的边缘结构多报一根就关掉 |
| `WireCount` 线数 | `0` = 自动 | 强制按指定根数，**以检出范围的中点为基准**向两边展开 | 芯数固定、算法偶尔多一根少一根时可以钉死。日志会留一条"按手动指定展开"的说明 |

**线距（pitch）谁说了算**（算法内部仲裁，理解它有助于看懂日志）：

| 情况 | 听谁的 |
| --- | --- |
| 自相关与分段线距相差 25% 以内 | 取平均，互相消噪 |
| 分段线距正好是自相关的整数倍（≥1.6 倍） | **信自相关**——那正是"漏检一半致使中位间距变成两倍"的典型情形，线会被补回来 |
| 其余不一致 | **信分段线距**（自相关在边缘信号上容易被线宽变化带偏，实测会给出 16 而真值 21.5） |

线距估出后，还会夹一道硬闸：`< 2` 像素或 `> 剖面长的一半` 直接报错——
那说明**采样区的短边方向根本没和线束走向垂直**，调参数没用，重新画框。

## 试算结果那几行怎么读

点「试算一下」，结果框输出六行，这是调参时**唯一的仪表**：

```
找到 10 根：黑,白,灰,紫,蓝,绿,黄,红,玫红,棕
线距 21.5 像素（分段估 21.0 / 自相关 22.0）
阈值：暗 < 114　彩 > 47　亮 > 236
来源：1黑检,2白补,3灰检,4紫检,5蓝检,6绿检,7黄检,8红检,9玫红检,10棕检
期望：黑,白,灰,紫,蓝,绿,黄,红,玫红,棕（配方「10 芯」）
判定：合格　线序正确，10 芯：…（配方「10 芯」）
```

| 行 | 看什么 |
| --- | --- |
| 第 1 行 根数与序列 | 和实物对不对。根数不对就是"找线"环节的问题，不是判色问题 |
| 第 2 行 线距 | 两个估计值是否接近。差得远 → 看日志里是哪一条仲裁规则生效了；线距明显不对 → 框的方向或位置有问题 |
| 第 3 行 三个阈值 | **调参主表**。暗线阈值该落在"缝"和"暗线"之间（实测安全窗口 100~160）；亮阈值贴住白线；彩度阈值不用管 |
| 第 4 行 来源（检/补） | 哪几根是靠线距推出来的。补得多说明直接抓到的段太少，先想怎么让暗/彩/极亮三条抓得更全 |
| 第 5 行 期望与配方名 | **确认比的是哪条配方**（同芯数多条时会取第一条）。想钉死就走 `ExpectedSequence` 端口 |
| 第 6 行 判定 | 结论全文，和 `Verdict` 端口、画面标注、日志是同一句 |

## 光照漂移与换型：按这个顺序重调

1. **先重画采样区**（80% 的问题在这一步就解决了）：短轴方向与线束走向垂直、贴住线束、
   不把大片背景或连接器金属触点圈进来。长轴自动判走向，竖着画也能用。
2. 点「试算一下」，读第 3 行的三个阈值和第 2 行的线距。
3. **根数错** → 动 `Regularize`（先关掉做对照组，看直接可见几根）、`MinRun`、`MaxRunRatio`、`ExtendEnds`。
4. **颜色错**（根数对、词不对）→ 动 13 项色卡阈值。先用「关掉规整化」的那份序列做参照：
   如果关规整化时检出的那几根颜色都对，只有"补"出来的那几根错，那是 `RuleWindowRatio` 的事，不是色卡的事。
5. **顺序/整体错位** → 看线距是否异常，再看 `ReverseSequence`。
6. 调完拿良品图点「把试算结果存成配方」更新配方，别手打。

| 现象 | 先查这一项 |
| --- | --- |
| 换了灯/换了曝光，整批颜色词都漂 | 试算第 3 行的阈值位置。自适应阈值是按本幅图现算的，通常跟着变；真不稳先查打光是否把暗缝"洗平"了（亮度极差 < 25 级会直接报"框到空白背景"） |
| 12/16 位相机接手后黑白灰棕全错 | 不用改参数：算法已按实测最大灰度等比压回 8 位（日志有"已等比压到 8 位再判色"的说明）。看到这条 Warn 就不必怀疑判据 |
| 换产品（芯数不同）就报错停线 | 配方缺失按配置问题报错是有意的。补配方，或让上游把期望序列喂进 `ExpectedSequence` |
| 同芯数两条配方，比对了错的那条 | 算法取第一条并留 Warn。明确指定走 `ExpectedSequence` 端口 |
| 白线死活检不到 | `BrightPercentile` 92 → 85；仍不行就确认白线是不是被 `MaxRunRatio` 当背景丢弃了（日志有"丢弃了 N 段过长"） |
| 玫红与红分不清 | 只动 `RoseHueFrom` / `RedHueFrom` 这一对（默认 330 / 350），两者只差十几度 |
| 采样区太窄报错 | 短边至少 8 个采样点。报错原文会写"短边只有 N 个像素"，按它把框拉宽 |

## 常见问题

**Q：这些阈值改了会不会影响别的算子/别的工位？**
不会。每个颜色算子各带一份可覆盖的副本，随本方案落盘。
共用的是**颜色词表**（11 个词）与**分类的层次**（先无彩后有彩），不是阈值数值。

**Q：能不能把色卡调成"全局统一"？**
刻意不做。不同工位、不同产品的打光与材质不一样，"玫红从哪里算起"本来就可能不同；
全局一份要么大家互相迁就，要么再多支持几份、复杂度又上一层。

**Q：为什么"彩 >"这个阈值界面上不能调？**
它由大津法从本幅图的彩度直方图现算。实测极不敏感（20~110 都给出同一个根数），
给人调反而多一个会调错旋钮，所以留自动。

**Q：调了半天根数还是不对，怎么判断是参数问题还是现场问题？**
两步：① 关掉「等间距规整化」再试算——它只报"直接看得见"的线，和实物的可见段对比；
② 看试算第 3 行的暗线阈值——若它落在缝电平附近甚至更高，说明打光把暗缝洗平了，
这是光路问题（换射角/加遮光），参数救不回来。

**Q：能不能让某一位不检（比如第 3 根有时缺件是正常的）？**
能。配方里那一位写 `*`（例如 `黑,白,*,紫,蓝`），该位不参与比对，其余照检。

**Q：手动能不能指定"这一轮比哪条配方"？**
能，走 `ExpectedSequence` 输入端口：填了就**完全绕过配方表**（工单/数据库下发就是这个用法）。

**Q：改了配置但现场跑的仍是老结果？**
改完要**重新点「执行」/重新试运行**；如果连插件 DLL 都是刚重建的，注意 `Modules\` 里的产物必须跟着更新
（改了插件源码只重build宿主工程，运行的还是旧 DLL）。
