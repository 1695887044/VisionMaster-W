# 颜色序列检查

> 分类：图像处理 ｜ 来源：插件 Plugin.ColorCheck

沿一条**采样带**扫出一串**颜色词**（黑 / 白 / 灰 / 棕 / 红 / 玫红 / 橙 / 黄 / 绿 / 蓝 / 紫），
再与**配方**逐位比对，回答两件事：**根数对不对、顺序对不对**。
产出判定结论 `Result`、第一位不符的位置 `BadIndex`、写给人看的结论全文 `Verdict`、
本次比对用的期望序列 `Expected`、根数 `Count`、实测序列 `Sequence`、
逐根明细 `Detail`（每根标出是"检"到的还是"补"出来的）、每根中心的图像行号 `Rows`，
并可把「采样线 + 逐根标签 + 结论行」投到主界面的视图窗口。

用在**线序、排线、色带、色块标签**这类"一串颜色的顺序对不对"的场合。
插件不认识"线"这个字，它只认"一串颜色"——所以同一个节点既能检 10 芯线束，也能检印刷色带。

## 为什么需要它 / 原理

**为什么不直接用"找边界"的思路**：白线（明度约 240）和浅色背景（约 235）只差几个灰阶，
颜色上根本不可分。任何阈值分割、边缘检测、变化点检测走到白线这里都会断。
所以骨架必须是：**先抓抓得到的（暗 / 彩 / 极亮），由它们的间距估出线距，再把整条链按等间距铺开**——
抓不到的那根被"补"回来。

```
采样区矩形（框住整条线束）
   ↓ ① 沿短轴取一条中位剖面（5 条邻近采样线逐点取中位，抗反光与脏点）
   ↓ ② 从这一幅图现算三个阈值：暗线 / 白线 / 彩度
   ↓ ③ 找"可靠像素"的连续段（暗 / 彩 / 极亮，够长才算一根）
   ↓ ④ 由段间距 + 自相关交叉验证估出「线距」
   ↓ ⑤ 最小二乘回归定锚点（相位与端点）
   ↓ ⑥ 按等间距铺满整束，逐根取中位色 → 归成颜色词
黑,白,灰,紫,蓝,绿,黄,红,玫红,棕
   ↓ ⑦ 与期望序列逐位比对（`*` 位跳过）
合格 / 第 N 根不符 / 根数不符
```

三处"自适应"（都是**从本幅图现算**，不是写死的经验值，这是换灯换相机不用重调的底气）：

| 环节 | 现在怎么做 | 为什么 |
| --- | --- | --- |
| 暗线阈值 | 剖面**众数亮度** 减 `暗线判据幅度` × （众数 − 2% 分位亮度） | 众数就是线间缝/背景的电平；用 2% 分位而不用最小值，一个坏点拉不跑尺度 |
| 彩度阈值 | **大津法**（Otsu）自动求 | 实测极不敏感（阈值 20~110 都给出同一个根数），人不用管 |
| 白线阈值 | 亮度的 `白线百分位` | 高位百分位只收"极亮"，浅色背景收不进来 |
| 线距 | 自相关 × 分段中位间距**交叉验证** | 自相关单独用会给出 16 而真值 21.5；分段单独用会在"漏检一半"时变成两倍 |
| 相位/端点 | 对可靠段中心做**最小二乘回归**定锚 | 拿"第一个可靠段"当起点时，端部漏检会让**整条序列错位一格**；回归定锚后端部漏检只少一根 |

**采样几何约定（务必先读）**：

| 方向 | 是什么 |
| --- | --- |
| 长轴（半长大的那条轴） | **线束走向**（沿着线排开的方向） |
| 短轴 | **采样剖面方向**（扫过每一根线的方向） |

- 长轴由算法自动判：**把框竖着画也能用**，不需要按某个固定方向画。
- 5 条采样线只在长轴方向偏移几个像素（-4 / -2 / 0 / 2 / 4），**不沿长轴摊开**。
  实测线束是扇形散开的（连接器在一端），摊开后按行号合并会把只在个别列上明显的边界线洗成背景，
  实测就是这样丢了线、根数少两根。
- 序列索引 0 是**坐标较小的那一端**；方向反了就勾「序列反向」。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | 运行期必需 | 待检查的图像（`HImage`）。端口本身不强制（编译期不报），但运行期没有图直接失败。**必须三通道彩色图**（通道数 < 3 会报错停下）；12/16 位高位深图自动等比压回 8 位再判色 |
| `ExpectedSequence` | 否 | 期望序列（`string`，逗号分隔的颜色词）。**填了就以端口为准，不再查配方表**——留给"配方从数据库/工单取"的场景；留空才按实测根数去配方表里挑 |

> 采样区**不接上游 ROI**：它是本算子内部在图上框出来的矩形参数（`RoiParams`），上游只进 `Image`。
> 想让上游裁好再送过来，就把「ROI」的 `Domain_名字` 接到 `Image`。

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Result` | 判定结论：`true` = 合格 / `false` = 不合格（不合格时本步骤仍然算执行成功） |
| `BadIndex` | 第一位不符的序号（**从 1 起**）；`0` = 全对，或者**根数就不对**（长度不符时无从谈"第几位"） |
| `Verdict` | 结论全文，写给人看的那一句（日志、画面标注、下游上报共用同一句） |
| `Expected` | 本次比对用的期望序列（回显，用来排查"到底比的哪条配方"） |
| `Count` | 根数 |
| `Sequence` | 颜色序列（逗号分隔） |
| `Detail` | 逐根明细：`1黑检,2白补,...`——`检` = 命中可靠段（真的看到）；`补` = 按等间距规整补出来的 |
| `Rows` | 每根线中心的**图像行号**（逗号分隔，由剖面坐标线性插值换算回来） |
| `Success` / `ErrorMessage` | 基类自带：本步骤是否跑通、失败时的中文原因 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

**采样区与主旋钮**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `RoiParams` | 空（未框选） | 采样区矩形，5 个数：`[中心行, 中心列, 角度(弧度), 半长, 半宽]`（Halcon Rectangle 约定）。**在配置界面的图上右键 → 新建矩形**画出来，不要手打 |
| `ReverseSequence` | `false` | 序列反向：把剖面的首尾对调。线束摆放方向和上次相反时勾上 |
| `WireCount` | `0` | 手动指定线数；`0` 或负数 = 由算法自动反推。填了且与自动估出的不一样时，**以检出范围的中点为基准**向两边展开，并在日志留一条说明 |
| `Regularize` | `true` | 等间距规整化：开 = 按估出的线距铺满整束（**能补出看不见的白线**）；关 = 只报看得见的线（调参时的对照组） |

**高级参数（自适应找线）**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `DarkSpanRatio` | `35` | 暗线判据幅度（界面上叫「暗线判据幅度」，百分比）。判定线 = 众数亮度 − 该百分比 ×（众数 − 最暗）。实测两张样本图的安全阈值窗口是 **100~160**，默认 35 给出 154 与 114 |
| `BrightPercentile` | `92` | 白线百分位：亮度高于这条百分位的算可靠线像素。检不到白线就调低（如 85） |
| `MinRun` | `4` | 最小段长：连续这么多行都可靠才算一根线（滤噪点） |
| `MaxRunRatio` | `0.33` | 最大段长比例：长过剖面长度这个比例的可靠段**按背景丢弃**（防浅色背景被当成线）。填 `0` = 不做这条保护 |
| `RuleWindowRatio` | `0.30` | 补色窗口半宽（线距的比例）：给"补出来"的那几根取色时的窗口大小 |
| `ExtendEnds` | `true` | 端点外推：允许在检出范围两端**各多探一根**（那一格里有明暗起伏就认，不要求认得出颜色） |

**颜色判据阈值（13 项）**：把实测颜色归到哪个颜色词用的阈值。所有颜色算子共用同一套颜色词，
这里只是**本步骤的一份可调副本**（随方案落盘，改它不影响别的工位/别的算子）。
逐项含义与调法见《颜色序列检查 · 调参与判据》。

| 参数 | 默认 | 一句话 |
| --- | --- | --- |
| `ColorlessSaturation` | `0.45` | 无彩/有彩分界（饱和度） |
| `BlackValue` | `80` | 无彩且明度低于它 → 黑 |
| `WhiteSaturation` | `0.15` | 白还要求饱和度低于它 |
| `WhiteValue` | `195` | 无彩且明度高于它 → 白 |
| `BrownWarmth` | `12` | 无彩但偏暖（R 比 G、B 都高出这么多）→ 棕 |
| `BrownValue` | `175` | 棕的明度上限（比它亮就归灰） |
| `RoseHueFrom` | `330` | 玫红起点（色相，度） |
| `RedHueFrom` | `350` | 红起点 |
| `RedHueTo` | `20` | 红止点（红跨 0 度） |
| `OrangeHueTo` | `45` | 橙止点 |
| `YellowHueTo` | `70` | 黄止点 |
| `GreenHueTo` | `160` | 绿止点 |
| `BlueHueTo` | `230` | 蓝止点（比它高就是紫） |

**配方与显示**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `RecipeText` | 空 | 配方表，一行一条：`产品名 = 颜色1,颜色2,...`；`#` 开头是注释，空行忽略；不带等号的行按"整行就是颜色序列"处理，产品名自动取「N 芯」。某一位写 `*` 表示这一位不检。**运行期按实测根数匹配**（期望序列的长度就是这条配方要求几根） |
| `DisplayViewIndex` | `1` | 结果投射到主界面第几个视图窗口（1~9）；`0` = 不投射 |

## 口径与失败策略

- **"判定不合格" ≠ "本步骤失败"**。`Result=false`（线序错、根数不符）时步骤照常跑通、输出照常齐全，
  下游用 `Result` / `BadIndex` / `Verdict` 分流即可。只有**跑不动**才失败（走 `Success=false`）。
- **配置问题按配置问题报，不判成 NG**：
  - 根数对不上任何一条配方 → **报错让流程停住**（"未知产品：N 芯没有对应配方"），不判 NG。
    配方没配是工程配置问题；判成 NG 会让一条配错的线永远把良品报成不良，现场只会以为"这批产品有问题"。
  - 期望序列里写了词表外的词（"深红"这种）→ **报错**并列出可用词。比对按字面做，
    词表外的词永远匹配不上，只会默默把那一位判 NG——那才是最难查的。
- **期望序列端口优先**：端口填了就不查配方表（同芯数多条配方的撞车问题也随之绕开）。
- **会失败（本步骤报错停下）的情形**：上游没有图像／图像未初始化；尚未框选采样区（`RoiParams` 不是 5 个数）；
  图像通道数 < 3（灰度图）；矩形半长/半宽 ≤ 0；采样区短边不足 8 个像素；采样点超出图像范围；
  剖面几乎没有明暗变化（亮度极差 < 25 级，多半框到空白背景）；可靠段少于 2 段（凑不出线距）；
  线距估计异常（< 2 像素或 > 剖面长的一半）；回归定锚失败；配方缺失；期望词不认。
  提示语一律写清"怎么补"。
- **只是告警、不中断**：丢弃了过长段（疑似浅色背景被算成线）、自相关与分段线距打架、
  线数按手动指定展开、多条同芯数配方（取第一条）、高位深已归一。都进日志的 Warn。
- **投图是锦上添花**：投递失败绝不能把一次成功的检测判成失败——整体推图失败只吞掉异常，判定与端口照写。
  `DisplayViewIndex=0` 时完全不推。
- **坐标与单位口径**：全部图像像素系 `(Row, Col)`；角度在**存盘里是弧度**（界面摘要显示成度）；
  序列索引 0 = 坐标较小的一端；`Rows` 给的是图像行号（剖面坐标经换算表线性插值译回图像）。

## 典型用法 / 接线

```
图像采集.OutputImage ──────▶ 颜色序列检查.Image
（可选）ROI.Domain_线束区 ───▶ 颜色序列检查.Image     （先圈定再看，搜索更快更稳）
（可选）工单/数据库.线序 ─────▶ 颜色序列检查.ExpectedSequence （填了就绕过配方表）

颜色序列检查.Result  ─▶ If（逻辑控制） / 结果上报.判定
颜色序列检查.Verdict ─▶ 结果显示.r1 / CSV记录 / 结果上报.备注
颜色序列检查.Count   ─▶ 数学计算 / CSV记录（根数列）
```

**配方表写法**（一行一条，`#` 注释）：

```
# 十芯主线束
10芯 = 黑,白,灰,紫,蓝,绿,黄,红,玫红,棕
5芯  = 棕,红,黄,绿,蓝
测试件第3位不检 = 黑,白,*,紫,蓝
```

**第一次用的 4 步**：
① 左栏「图像输入」点 🔗 绑上游图像（或在画布上拖一条线）；
② 点「执行」——上游图会自动显示在右侧画布上（第一次会报"尚未框选采样区"，那是对的）；
③ 在图上**右键 → 新建矩形**，框住整条线束（贴住线束，别把大片背景圈进来）；
④ 点「试算一下」核对根数与序列，再点「把试算结果存成配方」一键生成配方。

## 常见问题

**Q：明明看得见 10 根，为什么只报 8 根？**
白线与浅背景颜色上不可分，直接"找线"抓不到它。确认勾上了「等间距规整化」（默认是开的），
必要时开「端点外推」。看试算结果里的「来源」行：`检` 是真看到的、`补` 是按线距推出来的。

**Q：根数多了，检到不该检的东西？**
先关「等间距规整化」做对照（只报看得见的线，看清楚到底有几段）；
再把「最小段长」调大滤掉噪点；浅色背景被算成线时把「最大段长比例」调小，或把采样区收紧。
连接器上一排金属触点本身就是等间距的暗块，算法会理所当然地当"线"报出来——**那不是 bug，是采样区画错了地方**。

**Q：序列整体错位一格（第一位就对不上）？**
以前端部靠"第一个可靠段"当起点会整体错位，现在改成回归定锚，端部漏检只少一根。
如果还错位：① 看「线距」是不是明显不对（对照日志里的分段估 / 自相关两个数）；
② 检查采样区短轴方向是否真的与线束走向垂直；③ 方向和实物反了就勾「序列反向」。

**Q：报「未知产品：N 芯没有对应配方」，是产品不良吗？**
不是，这是**工程配置缺失**（有意按配置问题报错停流程，不判 NG）。补一条长度为 N 的配方，
或者用 `ExpectedSequence` 输入端口把期望序列直接给进来。
若配方表里同芯数有多条，会取第一条并在日志留一条提示——要明确指定就走端口。

**Q：填了配方但一直报"应为 深红、实测 红"这种怪结论？**
颜色词只有 **黑 白 灰 棕 红 玫红 橙 黄 绿 蓝 紫** 十一个，比对按字面做，词表外的词永远匹配不上。
现在这种情况会直接报错列出可用词。正解是拿一张已知良品的图点「试算一下」，
再点「把试算结果存成配方」——一键生成，不会打错词。

**Q：换了灯/换了相机，判色就不对了？**
先点「试算一下」看「阈值」那一行（暗 < X、彩 > X、亮 > X）落在什么位置，再对照调参页的表。
自适应的三个阈值都是从本幅图现算的，多数情况下不用改；
真正常改的是**采样区的位置和大小**。12/16 位相机的图会自动压回 8 位（日志会留说明），
不需要手工处理。详细顺序见《颜色序列检查 · 调参与判据》。

**Q：`BadIndex` 一直是 0，但 `Result` 是 false？**
`0` 的意思是"没有'第几位'可报"——要么全对，要么**根数本身就不符**（长度对不上时无从谈第几位）。
看 `Verdict` 那一句，根数不符时它写的是"根数不符：实测 N 根，配方要求 M 根"。

**Q：画面上为什么有几根是橙字？**
橙字 = 这一根是**规整补出来的**（`Detail` 里标"补"），不是看到的；红字 = 不符的那一根；绿字 = 检出且合格。
结论行与采样线本身随判定变色（合格绿 / 不合格红）。

**Q：配置界面右侧一直是空画布？**
图像只有**一个来源**：「图像输入」端口连上游。链接好上游后点「执行」跑一遍，图会自动带进画布
（本算子没有"填本地路径读图"的旁路）。
