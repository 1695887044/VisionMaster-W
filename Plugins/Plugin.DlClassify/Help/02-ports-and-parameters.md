# 深度学习分类 · 端口与参数

> 分类：图像处理 ｜ 来源：插件 Plugin.DlClassify

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | **必须连**（端口标记上写的是可空，但没图这一步直接失败） | 待分类图像（`HImage`）。支持 **1 通道（灰度，自动补成 3 通道）** 与 **3 通道（RGB）**，其它通道数明确报错。**整图分类**——想只看某个区域，请在**上游**把它裁成一张图再连进来 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `PredictedClassId` | 概率最高的类别**索引**（0 基）。判 OK/NG 时更常用的是下面那个名字 |
| `PredictedClassName` | 概率最高的类别名（模型没带名字时是 `class_N` 占位）。下游比较节点直接比它（如 `== "OK"`） |
| `Confidence` | 最高类别的概率（0~1）。**偏低时结果不可信**，请务必做阈值门禁（见"口径与失败策略"） |
| `Scores` | **全部类别**的概率数组（`double[]`，与 `ClassNames` **同序**，和 = 1）。供下游做多标签/阈值判定 |
| `ClassNames` | 全部类别名数组（`string[]`，与 `Scores` 同序，长度 = 类别数）。模型没带名字时逐项 `class_N` |
| `TopKText` | 前 K 类的文本摘要，分号分隔，形如 `OK:0.980;NG:0.010`。给**记录/上传/比较**这类只吃标量的下游用 |

> 另有基类隐式端口 `Success` 与 `ErrorMessage`。
> ⚠ 数组端口只能整体连给 object 输入口，所以额外给了 `TopKText` 这个标量口；`ClassNames[i]` 与 `Scores[i]` 严格同序（全量生成，不会因为只取前 K 类而错填名字）。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（界面名） | 默认 | 说明 |
| --- | --- | --- |
| `ModelPath`（模型路径） | 空 | ONNX 分类模型文件路径，可点「浏览」选。支持**绝对路径**与**相对宿主程序目录**的路径（换机器部署不用改配置）。找不到文件 = 明确报错，**不静默退回任何默认模型** |
| `ResizeMode`（缩放模式） | `Letterbox` | `Letterbox` = 等比缩放 + 居中补 114 灰边（不改变长宽比，**默认、出错面最小**）；`Stretch` = 直接拉伸到目标尺寸（改变长宽比，部分自训练/老导出用这种）。**按训练侧的做法选**，选错只会让精度静默下降 |
| `InputSize`（输入尺寸，0 = 用模型自带的） | 0 | 模型输入边长（像素），手填时按**正方形**取。0 = 用模型元数据里的静态尺寸（推荐，支持非方形）。分类模型常见 **224** |
| `TopK`（结果保留前 K 类） | 3 | 只影响 `TopKText` 里列几类，以及信息栏/日志的展示；`Scores` / `ClassNames` **永远是全量**。K 会被夹到 `[1, 类别数]` |

> **没有"类别名文件"配置项**：类别名只来自模型元数据 `names`。**没有 OK/NG 判定阈值配置项**（判定归下游）。**没有置信度门禁配置项**：低置信度提醒用固定阈值 0.6（只写 Warn，不参与判定）。**没有 GPU/设备开关**：当前只带 CPU 版。

## 口径与失败策略

- **判定不归本插件**：只输出"最可能是哪一类、把握多大"，**不给 OK/NG**。判定交给下游比较/逻辑节点（如 `PredictedClassName == "OK"`）。沿用「颜色检查」「OCR」「YOLO」立的同一条规矩。
- **预测成 NG 类也算执行成功**：分类结果是业务结论，不是程序状态（`Success` 仍为 true）。分流请用 `PredictedClassName` / `Confidence`，不要用执行状态。
- **低置信度只告警不放行也不拦截**：最高概率 **低于 0.6** 时插件主动写一条 Warn 日志（列出前 K 类），提示"本次结果不可信，请勿直接用于放行"。**它不判失败、也不改输出**——是否拦停由你在下游做阈值门禁（推荐做法：`Confidence < 门限` → 报警/复判，而不是直接当那个类别）。
- **执行失败（`Success` = false）的情形**：起手收到取消请求（流程被停止）→ `执行已取消`；上游没有图像；未选模型 / 模型文件不存在；模型任务不是 `classify`；输出形状不是分类布局或类别数 < 2；张量长度与类别数不一致；图像通道数不是 1 或 3；`输入尺寸` = 0 且模型是动态形状；加载 ONNX 失败（文件不合法 / 原生库缺失 / 32 位进程）。
- **没有推理超时**：一次分类是**阻塞推理**，插件不设超时；只在**起手**检查一次取消令牌（所以点停止能拦住的是一轮开始之前，不是中途）。节拍吃紧就降`输入尺寸`、换更小的模型、或在上游把 ROI 裁小再送进来。
- **图像位深**：非 `byte` 图（12/16 位 uint2、real 浮点）会先调 HALCON 的类型转换统一成 byte——**只是类型转换，不按灰度范围重新标定**。高位深相机请在**上游预处理**里先做灰度拉伸/归一化，否则模型看到的输入和训练时不是一个量级。
- **通道顺序**：HALCON 的 3 通道按 R、G、B 存放，与 Ultralytics 期望的 RGB 一致，所以直接映射。**上游若给的是 BGR 顺序的图，颜色类判定可能受影响**（分类任务对颜色敏感时请在上游统一成 RGB）。
- **确定性与耗时**：CPU、单线程（`IntraOp/InterOp` 固定为 1）——工业现场更在意"同一张图给同样的结果"。耗时随`输入尺寸`与模型大小增长（224 输入的分类模型通常比 640 的检测模型快得多）。
- **部署依赖**：`onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`System.Numerics.Tensors.dll` 必须在**宿主 exe 目录**；必须 **64 位进程**。漏带的表现是运行期 `DllNotFoundException` / `FileNotFoundException`，**编译期完全看不出问题**。
