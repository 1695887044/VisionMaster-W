# 深度学习分类

> 分类：图像处理 ｜ 来源：插件 Plugin.DlClassify

把一张图（或上游裁好的 ROI）送进 **ONNX 分类模型**，输出"**最可能属于哪一类 + 把握多大 + 各类概率**"。
工业上最大的用途是 **OK/NG 二分类**：划痕、脏污、色差、装配到位与否这类"**说不清规则、人一眼却认得**"的外观判定。

## 为什么需要它 / 原理

传统算子（Blob / 模板匹配 / 卡尺）靠**规则**判定——你得能说清"灰度低于多少、面积大于多少算 NG"。当缺陷形态多变、背景复杂、规则怎么写都会误判时，改成让模型从标注样本里学规则：训练侧标注"OK/NG"两类，导出的 ONNX 交给本节点用。

| 想解决的问题 | 该用哪个 |
| --- | --- |
| 有明确灰度/面积/形状规则 | Blob 缺陷检测 |
| 要把目标框出来、还要位置 | YOLO 目标检测 |
| **只要一个整体结论（这张图属于哪一类）** | **深度学习分类（本节点）** |

### 推理链路

```
① 取原图尺寸
② 算缩放几何（Letterbox 等比 + 居中补 114 灰　或　Stretch 直接拉成方形）
③ 构造输入画布（非 byte 图先转 byte；单通道自动补成 3 通道）
④ 转 NCHW float 张量（直接取底层缓冲整块拷贝，像素 /255 归一到 0~1）
⑤ ONNX Runtime 推理（CPU、单线程）
⑥ 后处理：输出布局校验 → 概率归一化 → 取前 K 类
```

### 三个"做错了不报错、只是精度静默变差"的点

| 环节 | 口径 | 做错的表现 |
| --- | --- | --- |
| **缩放模式要与训练一致** | 默认 `Letterbox`（等比补边，不破坏长宽比）；部分自训练/老导出用 `Stretch`（拉成方形） | 选错 = **精度静默下降**：不报错、不崩溃，只是置信度偏低或偶发错分。非方形图上两者结果不同 |
| **补边灰度 = 114** | Ultralytics 训练时的默认填充值 | 填黑边会引入模型没见过的强边缘，结果系统性偏移 |
| **归一化 /255** | 训练时像素归一到 0~1 | 少除/多除模型照样跑，只是精度静默劣化 |

### 概率归一化：logits 还是已 softmax，插件自己判

Ultralytics 导出的分类模型输出是**原始 logits**（softmax 在预测器里做、不在图里）；但也有部分导出/第三方模型已经把 softmax 做进了图里。**对已经 softmax 过的输出再做一次 softmax 会把分布压平**（原本 0.9 变 0.5 上下），表现是"能跑、但置信度毫无区分度"。

判据：所有值都落在 `[0,1]` **且** 和约等于 1 → 视为概率原样使用；否则视为 logits 做数值稳定的 softmax（先减最大值再取指数）。

### 模型校验：格式不对就明确拒绝，不硬算

- **任务校验**：模型元数据 `task` 不是 `classify`（detect / segment / pose / obb / semantic / depth）的**明确拒绝**——按分类解读会得到错误结果却不报错。
- **输出布局校验**：只接受分类形状 `[1, C]`（也接受被导出成 `[1, 1, C]` 的），且类别数至少 2。检测的 `[1, 4+C, N]`、分割的 `[1, C, H, W]` 一律拒绝并提示改用对应节点。
- **类别名**：读模型元数据 `names`；读不到用 `class_0` `class_1` 占位，**绝不编造**（按 ImageNet/COCO 顺序硬套会让你以为识别对了）。
- **输入尺寸**：`输入尺寸`填 0 时用模型元数据里的静态形状（可以是**非方形**）；手填时按**正方形**用（填 224 就是 224×224）。模型是动态形状又没填 → 明确报错，**不猜**。

### 模型会话：进程级共享 + 引用计数

同一个模型被多个流程引用只加载 **1 份**（按模型文件全路径缓存，归零才真正卸载）。**改了`模型路径`会自动换会话**，不用重启软件——不会出现"界面显示新模型、跑的还是旧模型"。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `Image` | **必须连**（端口标记上写的是可空，但没图这一步直接失败） | 待分类图像（`HImage`）。支持 **1 通道（灰度，自动补成 3 通道）** 与 **3 通道（RGB）**，其它通道数明确报错。**整图分类**——想只看某个区域，请在**上游**把它裁成一张图再连进来 |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `PredictedClassId` | 概率最高的类别**索引**（0 基）。判 OK/NG 时更常用的是下面那个名字 |
| `PredictedClassName` | 概率最高的类别名（模型没带名字时是 `class_N` 占位）。下游比较节点直接比它（如 `== "OK"`） |
| `Confidence` | 最高类别的概率（0~1）。**偏低时结果不可信**，请务必做阈值门禁（见"口径与失败策略"） |
| `Scores` | **全部类别**的概率数组（`double[]`，与 `ClassNames` **同序**，和 = 1）。供下游做多标签/阈值判定 |
| `ClassNames` | 全部类别名数组（`string[]`，与 `Scores` 同序，长度 = 类别数）。模型没带名字时逐项 `class_N` |
| `TopKText` | 前 K 类的文本摘要，分号分隔，形如 `OK:0.980;NG:0.010`。给**记录/上传/比较**这类只吃标量的下游用 |

> 另有基类隐式端口 `Success` 与 `ErrorMessage`。
> ⚠ 数组端口只能整体连给 object 输入口，所以额外给了 `TopKText` 这个标量口；`ClassNames[i]` 与 `Scores[i]` 严格同序（全量生成，不会因为只取前 K 类而错填名字）。

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数（界面名） | 默认 | 说明 |
| --- | --- | --- |
| `ModelPath`（模型路径） | 空 | ONNX 分类模型文件路径，可点「浏览」选。支持**绝对路径**与**相对宿主程序目录**的路径（换机器部署不用改配置）。找不到文件 = 明确报错，**不静默退回任何默认模型** |
| `ResizeMode`（缩放模式） | `Letterbox` | `Letterbox` = 等比缩放 + 居中补 114 灰边（不改变长宽比，**默认、出错面最小**）；`Stretch` = 直接拉伸到目标尺寸（改变长宽比，部分自训练/老导出用这种）。**按训练侧的做法选**，选错只会让精度静默下降 |
| `InputSize`（输入尺寸，0 = 用模型自带的） | 0 | 模型输入边长（像素），手填时按**正方形**取。0 = 用模型元数据里的静态尺寸（推荐，支持非方形）。分类模型常见 **224** |
| `TopK`（结果保留前 K 类） | 3 | 只影响 `TopKText` 里列几类，以及信息栏/日志的展示；`Scores` / `ClassNames` **永远是全量**。K 会被夹到 `[1, 类别数]` |

> **没有"类别名文件"配置项**：类别名只来自模型元数据 `names`。**没有 OK/NG 判定阈值配置项**（判定归下游）。**没有置信度门禁配置项**：低置信度提醒用固定阈值 0.6（只写 Warn，不参与判定）。**没有 GPU/设备开关**：当前只带 CPU 版。

## 口径与失败策略

- **判定不归本插件**：只输出"最可能是哪一类、把握多大"，**不给 OK/NG**。判定交给下游比较/逻辑节点（如 `PredictedClassName == "OK"`）。沿用「颜色检查」「OCR」「YOLO」立的同一条规矩。
- **预测成 NG 类也算执行成功**：分类结果是业务结论，不是程序状态（`Success` 仍为 true）。分流请用 `PredictedClassName` / `Confidence`，不要用执行状态。
- **低置信度只告警不放行也不拦截**：最高概率 **低于 0.6** 时插件主动写一条 Warn 日志（列出前 K 类），提示"本次结果不可信，请勿直接用于放行"。**它不判失败、也不改输出**——是否拦停由你在下游做阈值门禁（推荐做法：`Confidence < 门限` → 报警/复判，而不是直接当那个类别）。
- **执行失败（`Success` = false）的情形**：起手收到取消请求（流程被停止）→ `执行已取消`；上游没有图像；未选模型 / 模型文件不存在；模型任务不是 `classify`；输出形状不是分类布局或类别数 < 2；张量长度与类别数不一致；图像通道数不是 1 或 3；`输入尺寸` = 0 且模型是动态形状；加载 ONNX 失败（文件不合法 / 原生库缺失 / 32 位进程）。
- **没有推理超时**：一次分类是**阻塞推理**，插件不设超时；只在**起手**检查一次取消令牌（所以点停止能拦住的是一轮开始之前，不是中途）。节拍吃紧就降`输入尺寸`、换更小的模型、或在上游把 ROI 裁小再送进来。
- **图像位深**：非 `byte` 图（12/16 位 uint2、real 浮点）会先调 HALCON 的类型转换统一成 byte——**只是类型转换，不按灰度范围重新标定**。高位深相机请在**上游预处理**里先做灰度拉伸/归一化，否则模型看到的输入和训练时不是一个量级。
- **通道顺序**：HALCON 的 3 通道按 R、G、B 存放，与 Ultralytics 期望的 RGB 一致，所以直接映射。**上游若给的是 BGR 顺序的图，颜色类判定可能受影响**（分类任务对颜色敏感时请在上游统一成 RGB）。
- **确定性与耗时**：CPU、单线程（`IntraOp/InterOp` 固定为 1）——工业现场更在意"同一张图给同样的结果"。耗时随`输入尺寸`与模型大小增长（224 输入的分类模型通常比 640 的检测模型快得多）。
- **部署依赖**：`onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`System.Numerics.Tensors.dll` 必须在**宿主 exe 目录**；必须 **64 位进程**。漏带的表现是运行期 `DllNotFoundException` / `FileNotFoundException`，**编译期完全看不出问题**。

## 典型用法 / 接线

```
① 最常见的 OK/NG 外观判定
图像采集.OutputImage ──▶ 分类.Image
分类.PredictedClassName ─▶ 比较节点（== "OK"）──▶ 条件分支（OK 放行 / NG 报警）
分类.Confidence ─────────▶ 比较节点（>= 0.90）──▶ 与门（把握不足 → 复判/报警，不直接放行）
分类.TopKText ───────────▶ 数据记录 / 结果上报（存档每类的概率）

② 只看某个区域：先裁再分类
创建ROI ──▶ 裁剪/预处理 ──▶ 分类.Image      （本节点不吃 ROI 区域，必须先裁成一张图）

③ 多类别分拣（OK / 脏污 / 划伤 / 缺料）
分类.PredictedClassId ──▶ C#脚本 / 条件分支按类别分流
分类.Scores ────────────▶ C#脚本（多标签阈值：任一类 > 0.7 才算该类）

④ 与 YOLO 接力：先检出再逐目标分类
YOLO.BestCrop ──────────▶ 分类.Image        （粗定位 → 对该目标定性）
```

## 常见问题

**Q1：置信度一直很低（比如全在 0.4~0.55），是不是模型不行？**
先按顺序查三件事：① `缩放模式`是否和训练侧一致（选错最典型的表现就是"能跑但置信度没区分度"）；② 输入尺寸/预处理与训练是否一致；③ 图像本身是否偏离训练分布（打光、分辨率、颜色顺序）。界面上「试算一下」能直接看到前 K 类概率，比看日志快。

**Q2：所有类别概率都差不多、完全分不出来？**
除了缩放模式，还要怀疑**输出被做了两次 softmax**。插件已按"全在 0~1 且和≈1 就当概率、否则做 softmax"判据处理，但这个判据有极小概率误判（logits 恰好全在 0~1 且和≈1）。如果确认模型输出的是概率却仍被压平，请把模型名与试算出的各类概率记下来反馈给开发（判据本身还在用真实模型补验）。

**Q3：类别名显示成 `class_0` `class_1`，能判定吗？**
能用，但下游只能按**索引**判（`PredictedClassId == 0`）。这说明模型元数据里没带 `names`（插件不编造名字）。想让界面和记录里出现真名，请在导出时把类别名写进模型元数据。

**Q4：置信度低的时候会不会自动拦住？**
不会，插件**不判定**。它只在最高概率低于 0.6 时写一条 Warn 日志提醒"结果不可信"。真正的门禁要在下游搭：`Confidence >= 门限` 与 `PredictedClassName == "OK"` 两个条件一起判，否则"报了 OK 但其实只有 0.52 把握"会被当成合格放行。

**Q5：判定 NG 会不会让流程走异常分支？**
不会。分类结果是正常输出（`Success` = true）。分流请用 `PredictedClassName` / `Confidence`，**不要用执行状态**——否则模型正常判了个 NG 会被当成程序故障处理。

**Q6：能不能用 GPU？**
当前只有 CPU 版，界面上**没有设备开关**（CPU-only 阶段加开关是个什么都不做的旋钮）。接 GPU 是"换 ExecutionProvider + 多带原生库"，端口契约不变。

**Q7：`TopK` 填了 5，但 `Scores` 里明明有 8 类。**
正常。`TopK` 只管 `TopKText`（和信息栏/日志）列几类，`Scores` / `ClassNames` **永远是全量**，顺序按类别索引。

**Q8：动态形状模型报"无法确定模型输入尺寸"？**
手填`输入尺寸`（分类模型常见 224）。填了就是正方形画布；留 0 且模型元数据里也读不到 → 明确报错，插件不猜。

**Q9：`Scores` 怎么和别的端口对上号？**
`Scores[i]` 与 `ClassNames[i]` **同序**，下标就是类别索引（0 基），与 `PredictedClassId` 同一套编号。这是本节点唯一的对齐口径。

**Q10：想同时输出"这一类的概率是否达标"给 MES？**
接「变量运算」/「比较」节点：从 `Scores` 按下标取那一类，或直接比 `Confidence` 与门限；文本形态的结果用 `TopKText` 直接记录。
