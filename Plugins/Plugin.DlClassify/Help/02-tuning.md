# 深度学习分类 · 调参与排错

这一页管四件事：**模型怎么准备**、**第一次分类怎么跑起来**、**缩放模式与输入尺寸怎么选**、**置信度门禁怎么搭**。
配置界面左列有「模型摘要」（输入输出形状 / `task` / 类别名）和「试算」两块——**选错模型时摘要区是唯一线索**，试算结果会列出前 K 类的概率。

## 一、模型准备

模型是**客户资产，插件不内置**。训练侧完成图片标注、训完导出 ONNX，插件只负责"用"它。

1. **必须是分类任务（classify）**。检测 / 分割 / 姿态 / 旋转框模型的输出格式完全不同，按分类解读会得到错误结果**却不报错**，所以插件会明确拒绝。导出：
   ```
   yolo export model=你的模型.pt format=onnx task=classify
   ```
2. **类别数至少 2**（OK/NG 就是两类）。单类模型会被拒（"输出类别数不合理"）。
3. **类别顺序 = 索引顺序**。`PredictedClassId` 是 0 基索引，与训练时的类别编号一一对应；模型元数据里的 `names` 决定 `PredictedClassName` / `ClassNames` 显示什么。**读不到名字就用 `class_0` `class_1` 占位，插件不编造**。
4. **缩放方式要与训练一致**（这是分类插件最容易调错的一项，见第三节）。
5. **放置路径**：绝对路径，或**相对宿主程序目录**的路径（换机器部署不用改配置）。相对路径按 exe 所在目录解析。
6. **部署依赖**：`onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`System.Numerics.Tensors.dll` 必须在**宿主 exe 目录**；必须 **64 位进程**。

## 二、第一次分类（五步）

1. **选模型**：填`模型路径`或点「浏览」。摘要区应显示 `task=classify`、输入形状、类别名。
2. **接图**：在「图像输入」里链接上游端口（或画布上拖线）。点「执行」试运行，上游图会自动显示到右列。
3. **定预处理**：`缩放模式` 按训练侧做法选（默认 `Letterbox`）；`输入尺寸` 一般留 0（用模型自带的），动态形状模型才手填（分类常见 224）。
4. **试算**：点「试算一下」，结果形如：
   ```
   预测：OK（置信度 0.981，耗时 12 ms）
     OK  0.981
     NG  0.019
   ```
   **试算与运行期共用同一套分类代码**，所以"界面看着对、跑起来不对"不会发生。
5. **接下游判定**：`PredictedClassName` 接比较节点、`Confidence` 接阈值门禁、`TopKText` 接记录/上传。

> **判定不归本节点**：它只说"最可能是哪一类、把握多大"，不给 OK/NG。别把"预测成 NG"当成执行失败——分流用 `PredictedClassName` / `Confidence`，不要用 `Success`。

## 三、缩放模式与输入尺寸：精度静默下降的两个来源

| 项 | 默认 | 选错的表现 | 怎么定 |
| --- | --- | --- | --- |
| `缩放模式` | `Letterbox` | **不报错、不崩溃，只是置信度偏低或偶发错分** | 问训练侧：Ultralytics 标准预处理是等比补边（letterbox），选 `Letterbox`；若对方是"直接 resize 成 224×224"这类自写训练脚本，选 `Stretch`。拿不准就**两种各试算一次**，看哪个置信度明显更高——差得多的那个才是对的 |
| `输入尺寸` | 0（用模型自带） | 填了和训练不一样的边长 → 同上，静默劣化 | 保持 0。只有模型是**动态形状**（元数据读不到边长）才手填，且填成训练时用的那个边长（分类常见 224）。手填时按**正方形**取 |
| 图像位深 | 自动转成 byte | 12/16 位图（uint2）只是做类型转换，**不会按灰度范围重新标定** | 高位深相机在**上游预处理**里先做灰度拉伸/归一化，再连进来 |
| 颜色顺序 | RGB 直通 | 上游给 BGR 时，对颜色敏感的判定（色差、有无涂料）会受影响 | 在上游统一成 RGB |

> 补边灰度固定 **114**（与训练一致）、像素归一化固定 **/255**，这两项不提供旋钮——它们改错的后果是"能跑但精度静默劣化"，所以钉死在插件里。

## 四、置信度门禁怎么搭（现场最该补的一环）

模型不可能 100% 可靠。**"最高类别"在低置信度时基本是掷骰子**，所以必须有一道门禁：

```
分类.PredictedClassName ──▶ 比较A（== "OK"）
分类.Confidence ──────────▶ 比较B（>= 门限，如 0.90）
比较A + 比较B ────────────▶ 与门 ──▶ 条件分支：三条出口
                                     ├ 放行（A 成立且 B 成立）
                                     ├ 报警/NG（A 不成立）
                                     └ 复判/拦截（A 成立但 B 不成立 → 把握不足，不许直接放行）
```

- **门限怎么定**：拿一批已知样本跑一遍，把 `Confidence` 按"人工判定对/错"分成两组，取"错的那组的最大值"作为门限起点，再往上留余量。经验上二分类取 **0.90~0.98**；**产线宁可多拦、不可漏放**。
- 插件内置一个**固定 0.6 的低置信度提醒**（只写 Warn 日志、不改输出、不判失败）。它是给人看日志用的，**不能当门禁**——门禁必须在下游搭。
- 想让"不确定"变成第三种结果：读 `Scores` 数组在下游脚本里判（如最大与次差值过小 → 复判）。

## 五、参数调节速查

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 现象 | 调哪里 / 查哪里 |
| --- | --- |
| 置信度整体偏低、分不开 | ① `缩放模式`与训练不一致（最常见）；② `输入尺寸`与训练不一致；③ 图像偏离训练分布（打光/分辨率/颜色）；④ 模型本身训练不足 |
| 各概率都差不多（0.5/0.5） | 怀疑输出被做了两次 softmax。先确认 `缩放模式`，再把模型名 + 试算概率记下来反馈（判据是"全在 0~1 且和≈1 就当概率，否则做 softmax"，极小概率误判） |
| 类别名全是 `class_N` | 模型元数据没带 `names`，属正常。下游改用 `PredictedClassId` 判定，或在导出时把名字写进元数据 |
| 某类总被误判成另一类 | 训练侧的样本不均衡/标注不一致；先确认预处理一致，再回训练侧加样本。本节点没有可改的判定阈值 |
| 想多列几类 | `结果保留前 K 类`（只影响 `TopKText` 展示；`Scores`/`ClassNames` 永远全量，K 会被夹到类别数） |
| 耗时超出节拍 | `输入尺寸`降一档（模型需支持）、换更小的模型、在上游把 ROI 裁成一张小图再分类 |
| 只想判某个区域的类别 | 本节点吃整幅图：在上游用 ROI + 裁剪先把那块裁成一张图，再连 `Image` |

## 六、现场排障（报错原文 → 查什么）

| 报错 / 现象 | 排查 |
| --- | --- |
| `尚未选择模型：请在节点配置里选择一个 .onnx 分类模型` | 没填路径 |
| `模型文件不存在：<路径>` | 路径填错 / 模型没部署；相对路径以**宿主程序目录**为基准核对 |
| `这个模型的任务类型是「目标检测/实例分割/…」（元数据 task=…）` | 用 classify 任务重新导出（见第一节命令） |
| `无法识别的输出形状 […]：期望分类模型的 [1, C]` | 这不是分类模型（检测 `[1,4+C,N]` / 分割 `[1,C,H,W]`），改用对应节点 |
| `输出类别数 1 不合理（分类模型至少 2 类）` | 导出异常或模型不是分类头 |
| `输出张量长度 N 小于类别数 C，模型输出与元数据不一致` | 模型被裁剪过/导出损坏，重新导出 |
| `图像通道数为 N，只支持 1 通道（自动补成 3）或 3 通道` | 上游先转成灰度或 RGB（常见于 4 通道 RGBA） |
| `无法确定模型输入尺寸：模型是动态形状…` | 手填`输入尺寸`（分类常见 224）。留 0 会明确报错，**不猜** |
| `加载 ONNX 模型失败：…` | ① 文件不是合法 `.onnx`；② `onnxruntime.dll` 没投递到宿主 exe 目录；③ 32 位进程（必须 x64） |
| 运行期 `DllNotFoundException: onnxruntime` | 原生库不在 exe 旁边（Windows 不递归搜 `Modules\`） |
| 运行期 `FileNotFoundException`（Tensors） | `System.Numerics.Tensors` 没随插件带，它**不在** .NET 9 共享框架里 |
| 日志出现"置信度偏低…请勿直接用于放行" | 这是提醒（阈值 0.6），不是故障。检查预处理是否一致，并确认下游门禁已搭好 |
| 步骤报 `执行已取消` | 流程被停止（本算子起手检查一次取消令牌）。属正常中断 |
| 换了模型路径但结果像旧模型 | 不该发生（会话按路径判变）。确认改的是**本步骤**的路径，且界面摘要已显示新文件名 |

## 七、上线前检查清单

- [ ] 模型摘要 `task = classify`、输出形状 `[1, C]`、类别数与现场类别一致；
- [ ] `缩放模式` / `输入尺寸`与训练侧确认过（拿一批样本两种模式各试算，比较置信度）；
- [ ] 用**已知 OK / NG / 边界样**各跑一批，统计漏判与误判，据此定 `Confidence` 门限；
- [ ] 下游三出口（放行 / NG / 把握不足复判）已接好，**没有"只看类别不看把握度"的裸判定**；
- [ ] `TopKText` 或 `Scores` 进了数据记录，便于事后复盘模型误判样本；
- [ ] 部署包里模型与 `onnxruntime*.dll`、`System.Numerics.Tensors.dll` 都在该在的位置（换机部署最容易漏）；
- [ ] 把误判样本回流给训练侧迭代——分类模型是**持续资产**，插件只负责用它。
