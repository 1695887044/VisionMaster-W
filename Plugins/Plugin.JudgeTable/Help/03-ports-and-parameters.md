# 判定表 · 端口与参数

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable

本页是接线与配参的字典：每个端口叫什么、什么类型、什么时候存在，
以及**结果怎么对外**（运行时变量 → 下游「变量赋值」→ 全局变量）。

## 固定输出端口（表级，永远存在）

| 端口 | 类型 | 含义 | 典型用途 |
| --- | --- | --- | --- |
| `Success` | bool | 本步骤是否执行成功（基类端口） | 流程失败上浮 |
| `ErrorMessage` | string | 失败原因（基类端口；NG 时等于 `Reason`） | 状态栏 / 日志 |
| `IsOk` | bool | **所有启用规则都通过**。没有启用任何规则时为 false | If 容器条件、结果显示 |
| `FailedCount` | int | 未通过的启用规则数 | 结果上报、报表 |
| `Reason` | string | 一句话判定说明，如 `NG：2/3 条规则未通过（外径、主码）` | 结果显示、日志 |
| `Details` | string[] | 逐规则明细：`规则名: 期望 … / 实际 … / 原因 …` | 结果显示、C#脚本逐行打印 |
| `Results` | bool[] | 逐规则结果，**与启用规则顺序对齐**（停用行不占位） | 批量取用，见下面「数组下标」 |

> `Results` 的下标是"启用规则里的第几条"，不是"表格里的第几行"。
> 停用一条规则会让它后面的所有下标前移一位 —— 需要稳定下标时，用每条规则的独立结果端口。

## 动态输入端口（随规则生成）

| 端口名 | 类型 | 生成条件 | 说明 |
| --- | --- | --- | --- |
| `实际_{规则名}` | object | **每条规则都生成**（含停用行） | 规则的实际值；未连线即该规则不通过 |

- **怎么接**：展开该行 → 「数据源」右侧点 **🔗** → 在变量绑定窗口里选上游输出 / 全局变量 / 常量
  （窗口以**单绑定模式**打开，目标端口已锁定为本行的 `实际_{规则名}`，不用再挑端口）。
  选完立刻回显在「数据源」里，点「确定」后随方案落盘；点 **✕** 解绑并回到手填态。
- **也可以直接填常量**：未连线时「数据源」就是一个可编辑框，填的值按当前模式解析
  （数值 `12.5` / 集合 `A, B` / 正则 …），用于上游还没就绪时先验证判定口径。
  常量随「确定」写进 `InputValues`；一旦该端口有连线，运行期以连线为准（常量保留但不生效）。
- **取消配置会回滚连线**：连线是立即写回步骤的（🔗 选完即生效），规则改动却要「确定」才保存；
  点「取消」时插件把连线恢复成打开时的样子，会话内新加的规则上绑的线一并撤掉
  （否则会留下"规则没保存、线还在"的孤儿键）。
- **绑到图像 / 区域会被拦**：判定表只判数值与文本。把 `实际_{规则名}` 绑到图像类输出
  （`HImage` / `HRegion` 等 HALCON 对象）时，该规则判 NG，原因写明
  「数据源类型不支持：绑定的是图像/区域（HImage），本规则需要数值或文本」——
  要判尺寸就绑上游量出来的数值端口，不要绑图像本身。
- 名字里的 `{规则名}` 会清洗：空白、方括号、逗号等一律变下划线（端口名要能被编译器按
  `端口名[下标]` 解析，带 `[` 会整条失配）。
- **两条规则重名**时，后一条的端口自动加后缀 `_2` / `_3`（去重集合覆盖全部规则，
  所以"停用/启用"不会改变其它行的端口名）。
- 停用行**也建端口**：否则它的连线键会变成"没有同名端口"的孤儿键，整条流程编译失败。
- 这些端口都是 `IsRequired = false`：未连线**不是**编译期"参数缺失"，而是运行期"该规则不通过"
  （原因写进 `Details`）。

## 动态输出端口 / 运行时变量（每条规则一个）

| 名字 | 类型 | 生成条件 |
| --- | --- | --- |
| `{表名}.{规则名}.结果` | bool | `Enabled && GenerateResult`（默认都开） |

- `{表名}` = **步骤名**清洗后（不是运行期 `InstanceName`，原因见「开发·宿主契约」）。
- 生成的是**两样东西**，名字完全相同：
  1. **动态输出端口**：下游可以在画布上连线取 bool；
  2. **运行时变量**：执行期写 `context.LocalVariables[同名] = IsOk`，
     下游「变量赋值」Scope=Runtime 可读、`If`/`While` 条件可用同名变量引用。
- 每轮**覆盖写**。放在 `For` 循环里时，循环结束后留下的是**最后一圈**的值；
  要看历史请用 `Results` 或每轮自己落记录。

## 结果怎么对外：只走「变量赋值」，不写全局

判定表**绝不写全局变量**（不调用 `IGlobalVariableWriter`，也不碰变量管理）。
要对外时在下游加一个「变量赋值」节点：

```
判定表.工位A.外径.结果（运行时变量） ──▶ 变量赋值.Scope=Runtime  → 局部变量
判定表.工位A.外径.结果（运行时变量） ──▶ 变量赋值.Scope=Global   → 变量管理里的全局变量
```

| 目标 | 做法 |
| --- | --- |
| 同一条流程里后续步骤用 | 直接把结果端口连到下游输入，或 Scope=Runtime 写局部变量 |
| 跨流程 / SCADA / 上位机 | 「变量赋值」Scope=Global，名字填变量管理里已有的全局变量 |
| 批量结果 | 连 `Results`（bool[]），或逐条规则的端口分别映射 |
| 逐条原因 | 连 `Details`（string[]）给结果显示 / 数据记录 |

**为什么不直接写全局**：
① 全局变量是方案级共享状态，判定表每轮写 N 个会让"谁改了这个变量"无法追溯；
② 全局写需要宿主能力面（插件物理上够不到变量管理），把它塞进判定表等于让一个纯判定算子
   依赖写权限；
③ 现场的常见需求是"只把某几条结果对外"，用「变量赋值」能显式选，不多写一个字节。

## 数组下标口径

`Results` / `Details` 是数组端口，下游取元素有两种写法：

| 写法 | 谁支持 | 说明 |
| --- | --- | --- |
| `Results[0]` / `Details[1]` | 端口名解析（编译器 `^端口名(\[下标\])?$`） | 连线时把下标写进端口名即可，下标必须是**常量非负整数** |
| `IArrayElementWritable.TryWriteElement(i, v, out err)` | 变量侧（宿主实现） | 写数组变量的某个元素；判定表本身不写变量，这里只说明下游口径 |

- 下标**越界不会自动扩容**：`Results` 的长度等于启用规则数，多取一位在下游读到的是默认值。
- 需要"按规则名取"而不是"按下标取"时，用每条规则的独立结果端口（名字里带规则名）。

## 配置参数（随方案落盘）

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `Rules` | 规则集合 | 空 | 每条规则的完整配置（见下表） |

### 单条规则（`JudgeRule`）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `RuleId` | string | 新建 Guid | 稳定身份，改名不断链；界面不显示 |
| `Name` | string | `规则` | 显示名，同时是端口名的一部分 |
| `Enabled` | bool | true | 停用后不判定、不生成端口、不写变量 |
| `GenerateResult` | bool | true | 是否生成结果端口 / 写运行时变量 |
| `Mode` | 枚举 | 数值 | 数值 / 文本 / 集合 / 正则 / 布尔 / 计数 / 非空 |
| `Expected` | string | 空 | 期望值，按模式解析 |
| `Tolerance` | double | 0 | 数值容差，期望里写了 `± b` 时以写明的为准 |
| `IgnoreCase` | bool | false | 文本 / 集合 |
| `IgnoreWhitespace` | bool | false | 文本 |
| `MaxEditDistance` | int | 0 | 文本；0 = 必须完全一致 |
| `Confusables` | string | 空 | 文本；易混字符组，如 `0O,1I,5S` |
| `SetSemantics` | 枚举 | 全部期望都在 | 集合语义 |

**运行期状态不落盘**：`LastActual` / `LastOk` / `LastReason` / `LastFormula`
只活在配置实例上，关掉窗口就清空（配置态没有"上次结果"，留着旧数字会误导）。

## 改名 / 删除对连线的影响

| 动作 | 输入侧（`实际_{规则名}`） | 输出侧（`{表名}.{规则名}.结果`） |
| --- | --- | --- |
| 改名 | 本插件**自动迁移**连线到新名字（新名字已被占用时移除旧连线并提示） | **旧端口消失**：下游接到旧名字的线会在编译期报"不存在输出"，需重连 |
| 停用 | 端口保留，连线保留（不判定） | 端口消失 → 下游连线报错；重新启用即恢复 |
| 关闭结果输出 | 端口保留，连线保留（照常判定） | 端口消失 → 下游连线报错 |
| 删除 | 该行的连线键被清掉并提示 | 端口消失 → 下游连线报错 |
| 改步骤名 | 表名前缀变化 → **所有**结果端口名变化 | 下游全部需要重连（编译期明确报错，不会静默） |

**为什么改名能自动迁移输入连线**：`StepData.LinkedSources` 的键是端口名，
改名后旧键没有同名端口就是孤儿键，编译器对孤儿键是**报错**（一条就能让整条流程编译失败）。
本插件在配置态（打开窗口 / 点确定）按"上一次的端口名"做锚点迁移，迁移不了就删掉并写状态消息。
