# 判定表 · 快速上手

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable

判定表是"**把好几条 OK/NG 判据写在一张表里**"的算子：每条规则接一个上游值，
按规则自己的口径（数值 / 文本 / 集合 / 正则 / 布尔 / 计数 / 非空）判一次，
然后回答两件事：

1. **整表过没过**（固定输出端口 `IsOk` / `FailedCount` / `Reason` / `Details` / `Results`）；
2. **每条规则各自过没过**（每条规则一个 bool 动态输出端口 + 一个同名**运行时变量**）。

它替代的是"接一串「逻辑判断」节点 + 手写条件表达式"的老做法：
判据集中在一张表里、每行一个期望值、失败原因逐行写清，现场改规格不用重画流程。

## 一分钟理解它产出什么

```
上游值 A ──▶ 判定表.实际_外径    规则「外径」  期望 12.00 ± 0.05
上游值 B ──▶ 判定表.实际_高度    规则「高度」  期望 8.00 ± 0.10
上游值 C ──▶ 判定表.实际_主码    规则「主码」  期望 CODE-A, CODE-B
                        │
                        ├── 表级固定端口
                        │     IsOk        所有启用规则都通过（bool）
                        │     FailedCount 未通过的启用规则数（int）
                        │     Reason      一句话判定说明（string）
                        │     Details     逐规则"期望/实际/原因"（string[]）
                        │     Results     逐规则结果，与启用规则顺序对齐（bool[]）
                        │
                        └── 每条启用且开启"结果输出"的规则
                              {表名}.{规则名}.结果    bool 动态输出端口
                              {表名}.{规则名}.结果    同名运行时变量（执行期写入）
```

**记住一句话**：判定表只写**运行时变量**，**绝不写全局变量**。
要对外（给别的流程、给 SCADA、给上位机）就在下游接一个「变量赋值」节点，
作用域选 `Global`，从运行时变量映射过去。

## 第一次配判定表（7 步）

1. **连上游**：把要判的值连到本步骤的输入端口 `实际_{规则名}`（端口随规则自动出现）。
2. **新增规则**：点工具条「＋ 新增规则」，默认名 `规则1` / `规则2`…
3. **改名**：直接在表格「规则」列改名字。名字同时是端口名的一部分（见下面第 6 步）。
4. **选模式 + 填期望**：展开这一行（点左侧箭头或双击行），选模式、填期望值。
5. **接线**：名字改完后输入端口名会变（`实际_{新名字}`），回画布把上游输出连到新端口。
6. **定结果输出**：展开行右侧「结果输出」开关默认开 —— 关掉这一行就不生成端口、不写变量，
   但仍然参与总判定。
7. **确认保存**：点「确定」。端口定义快照随步骤存进方案，编译器据此供下游接线。

## 典型接线

```
卡尺测量.Value      ──▶ 判定表.实际_外径
卡尺测量.Value      ──▶ 判定表.实际_高度
码读取.Codes        ──▶ 判定表.实际_主码
Blob缺陷检测.Count  ──▶ 判定表.实际_缺陷数

【只看总判定】
判定表.IsOk          ──▶ If 容器条件 / 结果显示 / 结果上报
判定表.FailedCount   ──▶ 结果上报（数值字段）
判定表.Details       ──▶ 结果显示 / C#脚本（逐行打印原因）

【按规则取单条结果】
判定表.工位A.外径.结果 ──▶ 下游任意 bool 输入（或先经「变量赋值」写全局）

【批量取所有规则结果】
判定表.Results        ──▶ 下游用 Results[0] / Results[1] 取（数组下标见「端口与参数」）
```

## 三个最容易踩的点

1. **改名 = 改端口名**。规则名是输入端口 `实际_{名字}` 与结果端口 `{表名}.{名字}.结果` 的一部分，
   改名后旧端口消失、新端口出现；本插件会把**输入连线**自动迁到新名字，但
   **下游接到旧结果端口的那条线会断**，需要在画布上重连（编译期会明确报"不存在输出"）。
2. **没有连线不是"跳过"，而是"该规则不通过"**。`Details` 里会写
   `规则 X 没有接入实际值（端口 实际_X 未连线）`，整表判 NG。
3. **一条规则都没启用时整表判 NG**（`Reason` 写"没有启用任何规则"）。
   空表静默通过会让"配置漏了"表现成"产品全 OK"，比报错危险得多。

## 什么情况下该用它 / 不该用它

| 场景 | 用什么 |
| --- | --- |
| 一个工位有多条尺寸/字符/数量判据，要一张表看全部 | **本算子** |
| 只有一条判据、一个阈值 | 「逻辑判断」或「比较」算子更轻 |
| 判据之间要做复杂布尔组合（A 且 (B 或 C)） | 用 If 容器 + 本算子的 `Results[i]` 组合，或 C#脚本 |
| 判完要驱动运动/IO | 本算子只出结果，动作交「运动」「IO」等步骤；用 If 容器按 `IsOk` 分支 |
| 要把结果写进变量管理里的全局变量 | 下游加「变量赋值」Scope=Global，从运行时变量映射 |
