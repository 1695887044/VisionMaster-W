# 判定表 · 常见问题与排障

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable

按**现象**找原因。每一条都写清"看到什么 → 为什么 → 怎么改"。
带「静默」标记的是不报错但结果不对的那一类，最费时间。

## 整表结果不对

### 现象：整表一直 NG，但每一行看着都对

| 可能原因 | 判据 | 处理 |
| --- | --- | --- |
| 有一条规则没接线 | 展开该行，「数据源」显示「未连线」；`Details` 里写 `没有接入实际值（端口 实际_X 未连线）` | 展开该行点「数据源」右侧 🔗 选上游输出（或直接填常量） |
| 规则改名后没重连 | 「数据源」仍是「未连线」，端口名与你以为的不一样 | 按新端口名重连（悬停「数据源」可看端口名，或点「复制端口名」） |
| 上游值为 null | `Details` 写 `上游值为空（端口 实际_X 已连线但值为 null）` | 查上游为什么没出值（采集失败 / 前一步失败但流程继续） |
| 期望写错模式 | 「原因」列写"无法解析为数字"或"编辑距离 N > 允许 0" | 按「判定口径」页改模式或改期望 |
| 一条规则都没启用 | `Reason` 写"没有启用任何规则" | 至少启用一条 |

### 现象：整表一直 OK，但明显有不良品

| 可能原因 | 判据 | 处理 |
| --- | --- | --- |
| 判据写得太松 | 逐行看「Actual」与「期望」 | 收紧期望或加容差为 0 |
| 期望是空串 | 该行「原因」写"没有填写期望值"，但该行**停用**了 | 停用行不判定；确认它该启用 |
| 接错了上游值 | 「数据源」地址指向别的步骤 | 重新接线 |
| 数值被字符串吞了单位 | 实际值显示 `12.3mm` 这类 | 用「数据转换」或 C#脚本先取纯数字 |

## 端口与接线

### 现象：NG 原因写「数据源类型不支持：绑定的是图像/区域（HImage）」

**这是绑错了端口**：判定表只判数值与文本，`实际_{规则名}` 应该接上游**算出来的数值/文本输出**
（如匹配分数、测量结果、OCR 文本），不是图像本身。要判尺寸就先用量测插件出数值，再绑那个数值端口。
把图像绑进来时，判定内核只会把对象转成类型名去比较，得到的是"看不懂的 NG"——所以插件在取值处直接拦下并说明原因。

### 现象：点了「取消」，数据源还是刚才绑的那个

**正常情况下不该发生**：连线是立即写回步骤的，规则改动却要「确定」才保存，
所以插件在取消时会把连线回滚到打开配置时的快照（新增规则上绑的线一并撤掉）。

若确实看到"取消后线还在"，说明跑的是旧版插件（没有回滚逻辑）：重建 `Plugin.JudgeTable` 后再试。
另一种情况是「试运行」——它为了"所见即所试"会先同步一次参数（等同于确认），此后取消不再回滚。

### 现象：变量绑定窗口里找不到 `实际_X`（左侧一条端口都没有）

**这是预期行为**：完整变量绑定窗口的端口表来自插件**扫描期快照**（宿主用空配置实例拍的那一份，
那时还没有任何规则），动态输入端口不在里面。

正确做法：展开该行 → 「数据源」右侧点 **🔗**。控件用**单绑定模式**打开同一个窗口，
目标端口由它直接指定，不查那张表。同理，流程栏/画布右键「编辑绑定…」也列不出这些端口。

### 现象：点 🔗 没反应 / 窗口里没有候选

| 可能原因 | 判据 | 处理 |
| --- | --- | --- |
| 没有可绑的上游 | 窗口打开但候选树为空 | 确认方案里该步骤**之前**有产生输出的步骤（上游只看它前面的步骤） |
| 宿主未运行（纯脚本/断言环境） | 点了完全无提示 | 🔗 依赖宿主 `ProcessViewModel` 订阅事件；只在真 exe 里可用 |
| 规则刚改名、界面没刷新 | 「数据源」悬停的端口名与实际端口不一致 | 关掉配置窗口重开（端口与行绑定在重建时刷新） |

### 现象：手填的常量关了窗口就没了

| 可能原因 | 判据 | 处理 |
| --- | --- | --- |
| 没点「确定」 | 配置窗口只有确认才把端口值写回 `InputValues` | 点确定 |
| 该端口同时有连线 | 有连线时运行期以连线为准，但常量本身仍会落盘 | 点 ✕ 解绑后才以常量参与判定 |

### 现象：下游连不上 `{表名}.{规则名}.结果`

| 可能原因 | 判据 | 处理 |
| --- | --- | --- |
| 该行停用了 | 表格「启用」列未勾 | 勾上启用（端口立刻重新生成） |
| 该行关了结果输出 | 展开行开关是关的，折叠行小标签显示「未生成」 | 打开开关 |
| 规则刚改名 | 端口名跟着改名了 | 按新名字重连 |
| 步骤刚改名 | 表名前缀变了，所有结果端口名都变了 | 重连（编译期会明确报"不存在输出"） |
| 还没打开过配置窗口 | 端口快照没建过（新建步骤直接跑） | 打开一次配置窗口点确定，端口定义随方案落盘 |

### 现象：编译报"没有名为 实际_X 的输入端口"

说明 `StepData.LinkedSources` 里有一个**没有同名端口**的键（孤儿键）。
本插件在打开配置窗口 / 点确定时会自动清理并提示，所以：

1. 打开本步骤的配置窗口 → 点确定；
2. 再看编译是否通过；
3. 若仍报，说明该键是手改模型或旧版本留下的，重新接线一次即可。

### 现象：改完规则名，下游那条线还在画布上但流程报错

这是**预期行为**：下游记录的是旧端口名，旧端口已经不存在。
编译期会明确报"上游不存在输出 '旧名字'"（不会静默失效）。重新连一次即可。

## 运行时变量

### 现象：下游「变量赋值」Scope=Runtime 报"变量不存在"

| 可能原因 | 处理 |
| --- | --- |
| 名字拼错 | 用「复制端口名」把全名复制过去，别手打 |
| 本行关了结果输出 | 打开开关（关掉时**不写**运行时变量） |
| 本行停用 | 启用该行 |
| 判定表还没跑过 | 运行时变量在**执行期**才创建；先跑一轮 |
| 变量名带了步骤名的旧值 | 步骤改名后前缀变了，按新名字重取 |

### 现象：循环里每轮结果都变成最后一圈的值

**设计如此**：运行时变量每轮覆盖写。要看历史请：

- 用 `Results`（bool[]）批量取；或
- 每轮在下游「数据记录」/ C#脚本里落一行；或
- 把判定表放进子流程，由调用方每轮取一次。

## 界面与保存

### 现象：改了期望，跑起来还是旧值

| 可能原因 | 处理 |
| --- | --- |
| 没点「确定」 | 配置窗口的确认才会把规则写回 `InputValues` |
| 改的是**试运行**的实例 | 试运行读已保存的配置；先确定再跑 |
| 方案没保存 | 确认后还要保存方案（`.vms`） |

### 现象：规则名打不出某些字符

端口名会清洗：空白、方括号、逗号等变成下划线。
规则名本身可以随便写（中文、空格都行），只是**端口名**里那些字符会变 `_`。

### 现象：两条规则同名

允许。后一条的端口自动加后缀 `_2` / `_3`（输入与输出各一套）。
但强烈建议改名：同名规则在 `Details` 里也难区分（明细只写规则名）。

### 现象：摘要的"结果输出 N 条"和我数的行数不一致

摘要只数 `启用 && 结果输出开` 的行。停用行、关掉输出的行都不计入。

## 日志与取证

| 想知道 | 去哪看 |
| --- | --- |
| 这一行为什么 NG | 表格「原因」列 / `Details` 端口 / 运行日志（每条 NG 规则一行 Warn） |
| 判定算式 | 展开行的算式框（如 `编辑距离 1 > 允许 0 → NG`） |
| 端口到底叫什么 | 展开行「结果输出」卡片里的只读全名，或「复制端口名」 |
| 输入端口叫什么 | 「数据源」的悬停提示，或该行的「复制端口名」 |
| 连线迁移/移除发生过什么 | 底栏状态消息（一次性提示，重新打开窗口后清空） |

## 不要这样做

| 做法 | 后果 |
| --- | --- |
| 指望判定表写全局变量 | 本插件不写全局（设计如此）；用下游「变量赋值」Scope=Global |
| 把期望写成"从上游连进来" | v1 期望是**常量文本**；动态期望请用 C#脚本 |
| 用停用行当"暂时不看这条" | 停用会**删掉**它的结果端口，下游连线报错；只想不看结果请关「结果输出」（端口同样消失），要保留端口就别动它 |
| 在 `For` 里指望运行时变量累积 | 每轮覆盖；累积请自己落记录 |
