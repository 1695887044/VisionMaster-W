# 判定表 · 界面与编辑

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable

配置界面是一张**全宽表格 + 可展开行**。折叠状态下一屏能看到所有规则的
"数据源 / 模式 / 期望 / 上次结果 / 原因"；展开某一行才显示它的完整编辑区
（判定规则 + 结果输出）。设计基线见 `docs/UI设计基线/判定表/design.html`。

## 界面分区（自上而下）

| 区 | 内容 | 说明 |
| --- | --- | --- |
| 标题 | 「判定表」+ 一行口径提示 | 提示里写明"不写全局变量" |
| 摘要 | 整体徽标（OK/NG/—）、通过 N / M、失败 N、停用 N、结果输出 N 条、表级端口 | 随开关与上次运行结果实时更新 |
| 工具条 | ＋新增规则 / 上移 / 下移 / 删除 / 展开全部 / 收起全部 | 上移/下移/删除作用于**当前选中行** |
| 规则表 | 10 列，见下表 | 全宽，行可展开 |
| 底栏 | 操作提示 + 最近一次状态消息 | 改名迁移、连线移除等一次性反馈在这里 |

## 表格列

| 列 | 内容 | 可编辑 | 备注 |
| --- | --- | --- | --- |
| 展开 | 箭头 `▸` / `▾` | 点箭头或双击行 | 纯界面状态，不落盘 |
| 启用 | 复选框 | 是 | 停用行灰显、不判定、不生成端口 |
| 规则 | 规则名 | **是（就地改名）** | 名字是端口名的一部分，改名会重建端口 |
| 数据源 | 上游连线的显示地址，或「未连线」 | 否 | 悬停显示输入端口名；展开行里用 🔗 接线 |
| 模式 | 数值 / 文本 / 集合 / 正则 / 布尔 / 计数 / 非空 | 展开行里改 | 折叠行只显示中文模式名 |
| 期望 / 规格 | 期望值原文（数值容差会补成 `a ± b`） | 展开行里改 | 太长会截断，悬停看全文 |
| Actual | 上一次运行的实际值 | 否 | 没跑过显示 `—（运行时）` |
| 结果 | `OK` / `NG` / `跳过` 徽标 + `→ 规则名.结果` 小标签 | 否 | 停用或关闭生成时小标签显示「未生成」 |
| 原因 | 上一次运行的原因 | 否 | NG 时标红；没跑过显示 `—（运行时）` |
| 操作 | ↑ / ↓ / ✕ | 是 | 行内快速调整，不依赖选中态 |

## 展开行：左「判定规则」

| 字段 | 说明 |
| --- | --- |
| 数据源 | 全仓通用的可链接编辑器（固定值 / 上游链接二合一）。未连线时**直接在框里填常量**（按模式解析，可试运行）；点 🔗 选上游输出（单绑定模式，目标端口已锁定为本行的 `实际_{规则名}`）；点 ✕ 解绑。右侧「复制端口名」把端口名复制到剪贴板 |
| 模式 | 下拉，改模式后下方选项组随之切换 |
| 期望 / 规格 | 文本输入，按模式解析（语法见「判定口径与期望写法」） |
| 容差 ± | **数值 / 计数**模式可见。只在期望里没写 `± b` 时生效 |
| 忽略大小写 / 忽略空白 | **文本**模式可见 |
| 编辑距离 | **文本**模式可见，0 = 必须完全一致 |
| 易混字符组 | **文本**模式可见，如 `0O,1I,5S`；右侧输入框的提示文字就是示例 |
| 集合语义 | **集合**模式可见：全部期望都在 / 完全一致 / 不许多余 |
| Actual | 只读，上次运行的实际值 |
| 判定算式 / 原因 | 上次运行的算式与原因（没跑过显示引导文案） |

> **数据源这一行为什么必须用单绑定通道**：本插件的输入端口随规则动态生成，
> 而宿主「变量绑定」窗口的左侧端口表来自**插件扫描期快照**（那一刻还没有任何规则），
> 里面列不出 `实际_{规则名}`。本行用的是全仓通用的 `LinkableValueEditor`（固定值 / 链接二合一），
> 它点 🔗 时发 `LinkPathEvent` 以**单绑定模式**打开同一个变量绑定窗口，目标端口由控件直接指定，
> 不查那张表。选完上游输出后连线写回本步骤并立刻回显；点 ✕ 则解绑、回到手填常量态。
>
> **取消会回滚连线**：连线是立即写回步骤的（🔗 选完即生效），而规则改动要「确定」才保存 ——
> 两者口径不一致会留下"规则没保存、线却还在"。所以点「取消」时插件把连线恢复成打开配置时的样子，
> 会话内新增规则上绑的线一并撤掉。
>
> **端口对象会重建**：改名 / 启停 / 增删 / 改结果开关都会换一个新的输入端口对象。
> 那一行用 `MultiBinding`（端口名 + 插件 + `PortsVersion`）经 `InputPortConverter` 按名现取，
> 每次重建后自动指向新对象（R189 的强制范式）—— 少了这一路，编辑器会一直连着已释放的旧端口，
> 表现为"常量填了不落盘、🔗 绑了报没有该输入端口"。

## 展开行：右「结果输出」

| 元素 | 说明 |
| --- | --- |
| 开关 | 开 = 生成 bool 动态输出端口 + 每轮写同名运行时变量；关 = 都不生成，但仍参与总判定 |
| 运行时变量 / 输出端口 | 只读全名 `{表名}.{规则名}.结果`；关掉时显示 `—（未生成）` |
| 类型 | 固定 `bool` |
| 复制端口名 | 复制上面的全名（关掉时复制的是空串，按钮点了也不会写入脏值） |
| 提示 | 「每轮写运行时变量；要全局用下游「变量赋值」Scope=Global 映射；判定表不写全局变量。」 |
| 写入预览 | `{全名} = true / false`（跑过就显示上次的值，没跑过显示 `true / false`） |

**停用行的开关是灰的**：停用行既不生成也不写入，但开关的取值**保留**——
重新启用时自动恢复原来的选择，不用重配。

## 工具条动作

| 按钮 | 行为 |
| --- | --- |
| ＋ 新增规则 | 追加一行，默认名 `规则N`（取最小可用序号），并自动展开 |
| 上移 / 下移 | 移动选中行；顺序决定 `Results[i]` 的下标与端口生成顺序 |
| 删除 | 删除选中行；该行的输入连线键会一并清掉，并提示检查下游连线 |
| 展开全部 / 收起全部 | 只改展开态，**不改变任何一行的结果输出开关** |

## 摘要怎么算

| 显示 | 口径 |
| --- | --- |
| 整体徽标 | 有失败 → `NG`；全部启用规则都通过 → `OK`；还没跑过或没有启用规则 → `—` |
| 通过 N / M | N = 启用规则里上次判定 OK 的条数；M = 启用规则总数 |
| 失败 N | 启用规则里上次判定 NG 的条数 |
| 停用 N | `Enabled=false` 的条数 |
| 结果输出 N 条 | `Enabled && GenerateResult` 的条数（停用行不计入） |
| 表级端口 | 固定写 `IsOk（判定） · FailedCount（失败数） · Results（结果集）` |

## 键盘与鼠标

- **双击行**：展开 / 收起该行（点在按钮、输入框、下拉上时不触发，避免误折叠）。
- **点箭头**：同上。
- **改名**：在「规则」列直接键入，每次按键都会重建端口并把输入连线迁到新名字。
  连续改名不会丢连线（每次迁移都以"上一次的端口名"为锚点）。

## 已知偏差（相对设计稿）

| 偏差 | 原因 | 影响 |
| --- | --- | --- |
| 「数据源」用通用 `LinkableValueEditor`（设计稿是只读展示位） | 该控件是全仓值端口的既有交互（🔗 选上游 / ✕ 解绑 / 未连线手填常量），动态输入端口在完整变量绑定窗口里列不出来，只能走它的单绑定通道（平台约束，非设计变更） | 多出"手填常量"与"解绑"两项能力；折叠列仍显示地址或「未连线」 |
| 行高比设计稿略高 | WPF 输入框最小可点击高度 + 字体度量 | 观感差异，不影响操作 |
| 单行展开动效为瞬时 | 未引入 150ms 动画 | 观感差异 |
| 「从流程导入」「导出 CSV」未实现 | v1 范围只做判定与结果输出 | 需要批量导入时用 C#脚本或 Excel 步骤 |
| 首条失败行不自动展开 | 配置态没有"上次运行"，跑完才谈得上失败 | 运行后在结果列看 NG 行 |
