# 判定表 · 判定口径与期望写法

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable

七种模式各有一套期望语法。**期望写错不会静默通过**：解析不了就判该规则不通过，
原因写进 `Details` 与「原因」列。本页给每种模式的写法、通过条件与失败文案。

## 通用口径（所有模式）

| 情况 | 结果 | 原因文案（写进 Details） |
| --- | --- | --- |
| 规则停用 | 不判定 | 不进 `Results` / `Details` |
| 端口未连线 | **不通过** | `规则 X 没有接入实际值（端口 实际_X 未连线）` |
| 已连线但值为 null | **不通过** | `规则 X 的上游值为空（端口 实际_X 已连线但值为 null）` |
| 期望为空 | **不通过** | `没有填写期望值` |
| 判定过程抛异常 | **不通过** | `判定异常：<类型>: <消息>`（只影响该条，整表继续） |

## 1. 数值（Numeric）

期望支持五种写法：

| 写法 | 含义 | 通过条件 |
| --- | --- | --- |
| `12` | 精确值，容差取「容差 ±」字段 | `abs(实际 − 12) ≤ 容差` |
| `12.00 ± 0.05` | 中心值 ± 容差（也接受 `12.00 +- 0.05`） | `abs(实际 − 12) ≤ 0.05` |
| `18 ~ 24` | 闭区间（也接受全角 `18 ～ 24`；写反了按区间理解） | `18 ≤ 实际 ≤ 24` |
| `≥ 2.5` / `> 2.5` | 下限（也接受 `>=`） | `实际 ≥ 2.5` / `实际 > 2.5` |
| `≤ 2.5` / `< 2.5` | 上限（也接受 `<=`） | `实际 ≤ 2.5` / `实际 < 2.5` |

- **实际值**：数值类型直接取；字符串按"不变区域性 + 不带千分位"解析
  （`1.5` 认、`1,5` 不认 —— 后者在部分区域里会被读成 15，静默改值比报错难查）。
- **NaN / Inf 一律不通过**，原因 `实际值不是有限数字（NaN / Inf）`。
- 判定算式会写进「判定算式」框，如 `|12.07 − 12.00| = 0.07 > 0.05 → NG`。

## 2. 文本（Text）

期望就是一段文本。四个选项可组合：

| 选项 | 作用 | 例子 |
| --- | --- | --- |
| 忽略大小写 | 两边都转大写后比较 | `LOT-a` 与 `lot-A` 视为一致 |
| 忽略空白 | 去掉所有空白（含中间） | `A B C` 与 `ABC` 视为一致 |
| 编辑距离 | 允许的最多字符差异，0 = 必须完全一致 | 允许 1 时 `1O27` 与 `1027` 差 1 → 通过 |
| 易混字符组 | 比较前把组内字符归一成组内第一个字符 | `0O,1I,5S` 让 `O`≡`0`、`I`≡`1`、`S`≡`5` |

- **编辑距离按 Unicode 码点计算**，不按 `char`：一个汉字算一个字符，
  不会被拆成两个字节导致"距离比预期大 1"。
- 归一顺序固定：易混字符 → 去空白 → 转大写 → 算距离。三个选项叠加时按这个顺序生效。
- 空期望不算"期望空串"，而是"没填期望"（判不通过）。要判空用「非空」模式，
  或用正则 `^$`。

## 3. 集合（Set）

期望是多项，用**英文逗号 / 中文逗号 / 顿号 / 分号**分隔；实际值同样按这些分隔符切
（数组 / 列表类实际值逐元素取）。三种语义：

| 语义 | 通过条件 | 失败文案 |
| --- | --- | --- |
| 全部期望都在 | 期望里每一项都能在实际里找到（实际可以更多） | `缺少 CODE-C` |
| 完全一致 | 双向都不缺、不多（按集合比，不看顺序） | `缺少 …` 或 `多出 …` |
| 不许多余 | 实际里每一项都在期望里（期望可以有多余项） | `多出 CODE-D` |

- 勾「忽略大小写」时两侧都按不区分大小写比较。
- 重复项按集合去重（`A,A,B` 与 `A,B` 视为同一个集合）。
- 判定算式会写 `期望 N 项 / 实测 M 项 / 命中 K 项`。

## 4. 正则（Regex）

期望是一条 .NET 正则，实际值按文本匹配（`IsMatch`，**不加锚点**——要整串匹配请自己写 `^...$`）。

| 情况 | 结果 | 原因 |
| --- | --- | --- |
| 匹配 | 通过 | `正则匹配` |
| 不匹配 | 不通过 | `不匹配正则 <模式>` |
| 模式非法 | 不通过 | `正则非法：<编译器原文>` |
| 匹配超时（1 秒） | 不通过 | `正则匹配超时（模式可能有灾难性回溯）：<模式>` |

> 超时是硬保护：`(a+)+$` 这类模式在长文本上会吃掉整条流程的时间片，宁可判 NG 也不卡死。

## 5. 布尔（Boolean）

期望 `true` / `false`（大小写不敏感，也接受 `1` / `0`）。
实际值可以是 bool、文本（同上）、或数值（非 0 = true）。

| 情况 | 结果 | 原因 |
| --- | --- | --- |
| 一致 | 通过 | `布尔一致（true）` |
| 不一致 | 不通过 | `期望 true，实际 false` |
| 期望解析不了 | 不通过 | `期望值无法解析为布尔（应填 true / false）：…` |

## 6. 计数（Count）

先算"实际值有几个"，再按数值口径比较：

| 实际值类型 | 计数口径 |
| --- | --- |
| 数值 | 数值本身（可写 `18 ~ 24`、`≥ 3`、`= 5` 这类期望） |
| 字符串 | 按分隔符切项后的**项数**（空串 = 0，无分隔符 = 1） |
| 数组 / 列表 | 元素个数 |
| 其它对象 | 1 |

期望语法与数值模式完全一致（区间 / 比较符 / 精确值）。
判定算式形如 `21 ∈ [18, 24] → OK`。

## 7. 非空（NotEmpty）

| 实际值 | 通过条件 | 失败文案 |
| --- | --- | --- |
| null | 不通过 | `实际值为空（null）` |
| 字符串 | 非空白（`IsNullOrWhiteSpace` 为 false） | `实际值为空白文本` |
| 数组 / 列表 | 至少一个元素 | `实际值为空集合` |
| 其它对象 | 通过 | — |

非空模式**不需要填期望**（填了也忽略）。

## 一个模式选不对会怎样

| 现象 | 真实原因 |
| --- | --- |
| 期望 `12.00 ± 0.05` 在文本模式下判 NG | 文本模式比的是"字符串相等"，不是数值范围 —— 改模式 |
| 集合模式里"少了一个"但实际值看着一样 | 分隔符是英文/中文逗号、顿号、分号；其它符号（如 `|`）不切项 |
| 数值模式报"无法解析为数字" | 实际值里混了单位或非数字字符（如 `12.3mm`）；先用「数据转换」或 C#脚本取数 |
| 正则模式从不通过 | 模式里带了 `^`/`$` 而实际值有多余空格；先开「文本」模式确认实际值长什么样 |

## v1 的范围边界

| 能力 | v1 状态 |
| --- | --- |
| 逐字符置信度（OCR 每字符可信度）参与判定 | **v1 不支持**：置信度门请在 OCR 步骤或 C#脚本里做；v2 评估接入 |
| 数组下标来自变量（如 `For.Index`） | v1 只支持常量下标；动态下标 v2 评估（需运行期求值 + 越界策略） |
| 判据之间的布尔组合 | 用 If 容器 + `Results[i]`，或 C#脚本 |
| 判据按配方切换 | 用多张判定表 + If 分支，或由上游把期望值连进来（v1 期望是常量文本） |
