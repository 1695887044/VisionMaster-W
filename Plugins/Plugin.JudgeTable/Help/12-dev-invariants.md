# 判定表 · 开发：不变量与断言

> 分类：逻辑判断 ｜ 来源：插件 Plugin.JudgeTable ｜ 读者：改这个插件、review 这个插件的人

本页是"改坏了会静默出错"的清单：每条不变量写清**判据**、**违反的后果**、**谁在守**。
断言全部在 `FlowCanvasChecks/JudgeTableChecks.cs`（`[JT1]`~`[JT45]`），随
`dotnet build FlowCanvasChecks` + 运行断言宿主一起跑。

## 一、端口生成类

| # | 不变量 | 违反的后果 | 守门 |
| --- | --- | --- | --- |
| I1 | 每条规则都建动态输入端口 `实际_{名}`（**含停用行**） | 停用行的连线键变成孤儿键 → 整条流程编译失败 | `[JT1]` `[JT6]` `[JT7]` |
| I2 | 只有 `Enabled && GenerateResult` 的行建输出端口 | 停用行仍在写结果端口 → 下游拿到不该有的值 | `[JT6]` `[JT7]` `[JT16]` |
| I3 | 端口名 = 快照名 = 运行时变量名（三者同源） | 下游按快照连上、运行期找不到端口 | `[JT2]` `[JT9]` `[JT10]` |
| I4 | 快照的 `DataTypeName` 是 `bool` 的程序集限定名 | 绑定界面按 `object` 处理，类型检查失效 | `[JT2]` `[JT39]` |
| I5 | 重名规则自动加 `_2` / `_3` 后缀，且去重覆盖全部规则 | 端口折叠（先到先得）→ 后一行的连线被当孤儿删掉 | `[JT5]` |
| I6 | 改名后输入端口与输出端口**同步**改名，旧名字不再存在 | 旧端口残留 → 两条规则抢同一个名字 | `[JT4]` |
| I7 | 端口名不含 `[` / `]` / 空白（`Sanitize`） | 编译器拆数组下标的正则整条失配 → 连线静默失效 | `[JT4]`（中文名）+ 人工评审 |

## 二、连线类

| # | 不变量 | 违反的后果 | 守门 |
| --- | --- | --- | --- |
| I8 | 改名时把输入连线键迁到新名字 | 孤儿键 → `没有名为 X 的输入端口`，整条流程编译失败 | `SyncInputLinks` + 人工评审（见下"未自动守"） |
| I9 | 删除规则时清掉它的连线键 | 同上 | 同上 |
| I10 | `StepData == null`（编译态）时**不做**任何连线迁移 | 编译期改活模型 → 同一轮编译内端口/键错位 | 代码结构（`SyncInputLinks` 首行 return）+ 人工评审 |
| I11 | `RunAlgorithm` 里**不重建端口** | 编译期挂好的上游输出被换掉 → 下游永远读默认值 | 人工评审（`[JT9]`~`[JT16]` 会因端口被换而红） |

## 三、执行与变量类

| # | 不变量 | 违反的后果 | 守门 |
| --- | --- | --- | --- |
| I12 | 每条启用且生成的行写 `LocalVariables[全名] = IsOk` | 下游「变量赋值」Scope=Runtime 取不到值 | `[JT10]` |
| I13 | 运行时变量的值必须等于端口值（NG 时是 false，不是缺键/true） | 下游看到的值与界面不一致 | `[JT15]` |
| I14 | **绝不写全局变量** | 判定表变成隐式全局写入者，现场无法追溯 | `[JT13]`（执行前后 `GlobalVariables` 逐项不变） |
| I15 | `Results` 与启用规则顺序对齐（停用行不占位） | 下游按下标取错规则 | `[JT11]` `[JT16]` |
| I16 | `Details` 逐规则一行，含规则名 / 期望 / 实际 / 原因 | 现场无法定位是哪条判据 NG | `[JT11]` `[JT42]` |
| I17 | 未接线 / 上游空 / 端口不存在 **三种原因分开写** | 现场只看到"没有实际值"，不知道是没接还是上游没出值 | `[JT42]` `[JT43]` |
| I18 | 一条规则都没启用 → 整表 NG 并写明原因 | 空表静默通过 = 配置漏了也判 OK | `[JT17]` |
| I19 | 单条规则异常只判该条失败，整表继续 | 一条坏规则让整表不产出 | `JudgeEngine.Evaluate` 的 catch + 人工评审 |
| I20 | 写运行时变量失败只记 Warn，不改判定 | 变量池异常被当成判定 NG | 代码结构 + 人工评审 |

## 四、判定口径类

| # | 不变量 | 违反的后果 | 守门 |
| --- | --- | --- | --- |
| I21 | 数值：`a` / `a ± b` / `a ~ b` / `≥` / `≤` 全部可用；`±` 优先于容差字段 | 现场写 `±` 却被容差字段覆盖 | `[JT19]`~`[JT22]` |
| I22 | NaN / Inf / 非数字文本一律 NG | NaN 参与比较永远 false，看起来像"配置没生效" | `[JT22]` |
| I23 | 数值文本解析拒绝千分位（`1,000` 不认） | `2,5` 被读成 25，静默改值 | `[JT23]` |
| I24 | 文本编辑距离按**码点**算 | 中文被拆成两字节 → 距离比预期大 1 | `[JT28]` |
| I25 | 文本归一顺序：易混字符 → 去空白 → 转大写 → 算距离 | 选项叠加时结果随顺序漂移 | `[JT24]`~`[JT27]` |
| I26 | 集合三种语义（全部期望都在 / 完全一致 / 不许多余） | 三选一语义混淆 → 松/紧判反 | `[JT29]`~`[JT32]` |
| I27 | 正则非法 / 超时明确失败 | 非法模式抛异常打断整表 | `[JT33]` |
| I28 | 布尔接受 `true/false/1/0`（大小写不敏感），其它明确失败 | 写"是"静默变成 false | `[JT34]` |
| I29 | 计数：数值取自身 / 字符串按项数 / 数组按元素数 | 字符串被当长度算 | `[JT35]` |
| I30 | 非空：null / 空白 / 空集合都失败 | "空字符串算通过" | `[JT36]` |
| I31 | 期望为空 → NG 并写原因（不静默通过） | 忘填期望的产品全 OK | `[JT37]` |

## 五、持久化与界面类

| # | 不变量 | 违反的后果 | 守门 |
| --- | --- | --- | --- |
| I32 | `Rules` 随 `.vms` 往返（名字/顺序/模式/期望/选项） | 方案重开后规则丢失或变默认 | `[JT38]` |
| I33 | `OutputPortDefinitions` 随 `.vms` 往返 | 重开方案后下游连线全断 | `[JT39]` |
| I34 | 运行期回显（`LastActual`/`LastOk`/`LastReason`/`LastFormula`）**不落盘** | 旧结果跟着方案进产线，看起来像"刚跑过" | `[JT40]` |
| I35 | 重新 `Initialize` 后端口按规则重建 | 打开配置窗口看不到端口 | `[JT41]` |
| I36 | 视图：`GridListViewStyle` + `ItemContainerStyle`（含 `GridViewRowPresenter`）+ 就地合并 `GridView.xaml` | 列头消失 / 行塌成类型全名 | `[JT45]` + `UIThemeSmokeTest` 静态扫描 |
| I37 | 视图零硬编码颜色（只用令牌） | 换肤时这一页不变 | `[JT45]` + `UIThemeSmokeTest` 颜色闸门 |
| I38 | 视图实例化 + 布局不抛（资源键/模板/绑定全可解析） | 打开参数窗口直接崩/空白 | `[JT44]` |

## 未自动守住的（人工评审清单）

| 项 | 怎么审 |
| --- | --- |
| I8 / I9 连线迁移与清理 | 在配置界面改名 → 看底栏状态消息 + 回画布确认连线还在；删除一行 → 确认没有"没有名为 X 的输入端口" |
| I10 编译态不迁移 | 检查 `SyncInputLinks` 首行仍是 `if (step == null) return;` |
| I11 运行期不重建 | 检查 `RunAlgorithm` 里没有 `Rebuild*` 调用 |
| I19 单条异常不扩散 | 把某条规则写成非法正则 + 另一条正常，跑一轮看整表仍出结果 |
| I20 变量写入失败不致命 | 用一个只读/抛异常的 `LocalVariables` 实现跑一轮（或代码评审 `WriteRuntimeVariable` 的 try/catch） |
| I7 端口名清洗 | 规则名写 `A[0]` / `A B`，确认端口名变成 `A_0_` / `A_B` 形态且能编译 |

## 改这个插件时的最小回归步骤

1. `dotnet build "Plugins\Plugin.JudgeTable\Plugin.JudgeTable.csproj" -m:1 -nodeReuse:false --nologo`
   → 判据 `0 个错误` 且退出码 0（本机默认多进程会静默失败）。
2. `dotnet build "FlowCanvasChecks\FlowCanvasChecks.csproj" -m:1 -nodeReuse:false` → 再跑断言宿主
   （`--no-build` 会拿旧 exe，改了断言必须重建）。
3. 看 `[JT*]` 全部通过；有任何红，先读该条断言的 detail（它把实际值/原因都打出来了）。
4. 改了 `Help\*.md` 也要重建插件工程（手册是内嵌资源），并核对 DLL 里的资源数 = 磁盘 .md 数。
5. 收尾统一走 `tools\run_gates.ps1`（唯一入口，含根目录/产物/帮助手册/主题/断言六个宿主）。
