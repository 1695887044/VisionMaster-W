# 网络相机（虚拟）· 排错

本页只讲"现场遇到什么现象 → 查哪一项"。协议与参数含义见上一页。
引用的错误文案与插件/宿主源码逐字一致，照抄搜索最快。

## 一、五分钟把链路跑通（无硬件）

1. 启动主软件，确认宿主相机收图服务在监听：「系统 → 相机设置」里网络相机的接入地址那两行能显示出完整 URL。
   若提示"收图服务未启动，网络相机会永远等不到图"，查 `AppConfig.json → NetworkCameraServer.Enabled`
   与端口是否被占用（默认 `19100`；`0.0.0.0` = 听所有网卡）。
2. 「系统 → 相机设置」添加一台相机：驱动类型选「网络相机（虚拟）」，**序列号手填**（例如 `V-CAM-01`，只用字母数字与短横线）。
3. 点「连接」：状态应为 `Connecting`，说明"等待客户端接入（序列号 V-CAM-01）"。
   这一刻还没有客户端，**这是正确状态**，不是失败。
4. 启动 `Tools\VirtualCameraClient`：主机 `127.0.0.1`、端口 `19100`、令牌 `visionmaster`（与服务端一致）、序列号 `V-CAM-01`，
   选一个图片文件夹，勾上心跳（默认独立循环，每秒一次），点"开始推图"。
5. 回相机设置：状态先跳 `Online`（收到心跳）或直接 `Streaming`（首帧到达即视为进入采流）。
6. 流程里拖「图像采集」→「相机采集」页选这台，点窗口底部「执行」试运行；
   成功文案形如 `已从相机取图: 宽x高x通道（第 N 帧，来源 文件名）`。

## 二、现象 → 查哪一项

| 现象 | 第一判据 | 处置 |
| --- | --- | --- |
| 状态长期 `Connecting`，文案"等待客户端接入（序列号 X）" | 客户端返回码 | 401 → 令牌不一致；404 → 序列号不一致（404 消息里会列出"当前已配置：…"）；连接被拒 → 主机/端口错、服务没监听、跨机被防火墙挡 |
| 客户端返回 400"请求体为空：请把图片文件的字节作为 body 发送" | 客户端发了空 body | 推帧必须带图片字节；心跳才允许无 body |
| 客户端返回 400"URL 缺少序列号：应为 /camera/{序列号}/frame" | 路径写错 | 检查是不是写成了 `/flow/{流程名}`（那是网络推送通道，端口 `19000`） |
| 客户端返回 400"图片解码失败：…" | body 不是有效图片字节 | 发**文件字节**（jpg/png/bmp/tif），不要发 base64、不要发 multipart、不要发 raw 像素 |
| 客户端返回 401 | 令牌 | 两边统一改 `AppConfig.json → NetworkCameraServer.Token`，头必须是 `Authorization: Bearer {令牌}` |
| 客户端返回 404 | 序列号不在方案里 | 添加该相机或改客户端；中文/空格序列号需 URL 转义，建议改字母数字 |
| 客户端返回 409"相机未打开，请先在「系统 → 相机设置」连接该相机" | 帧到了但没连接 | 点「连接」；勾「自动连接」的记得保存方案 |
| 客户端返回 409"相机已停止采流，帧被拒绝" | 停止采流后闸门是关的 | 点「开始采流」；这是刻意的：停止后残留旧图已无意义 |
| 客户端返回 409 且原因写"帧数据无效（宽x高x通道，像素 N 字节）" | 宽高与字节数不自洽 | 多半是解码尺寸/通道不符，先换一张标准 jpg/png 验 |
| 客户端返回 409"相机设备已释放" | 该相机已被删除/方案已关闭 | 重新添加并连接 |
| 界面"采流中"但客户端早没了 | 心跳 | 默认 3000 ms 无心跳即判掉线（检查间隔取值的 1/3、夹在 200~1000 ms）。没判掉线就查 `HeartbeatTimeoutMs` 是否过大、客户端是否在暂停推图时把心跳也停了（**必须照发**）、序列号是否与另一台重复 |
| 状态 `Online`（在线）但没有图 | 这是"客户端活着、此刻没送帧" | 不是故障：客户端暂停、图片放完、只在触发时推图都会停在这里。该查客户端，不要主软件里找毛病 |
| 采集步骤"等待相机「X」出图超时（N ms）；相机状态：…，待消费 N 帧，累计收帧 N，溢出丢帧 N" | 见下面「三」 | — |
| 采集步骤"找不到序列号为「X」的相机…" | 采集步骤引用的相机不在当前方案 | 相机设置确认，或回「相机采集」页重选 |
| 采集步骤"相机「X」未连接（…）" | 状态 `Closed` | 连接（并考虑勾「自动连接」） |
| 采集步骤"相机返回的帧数据无效（宽高与像素字节数不自洽）" | 队列里那帧字节数不够 | 换标准图片；若是自研客户端，核对发送的是文件字节而非裁剪后的 raw |
| 日志"已 X.Xs 未收到心跳…（已清空 N 帧陈旧图像）" | 掉线并清队列 | 正常保护动作；恢复后会自动回到在线/采流，无需人工 |
| 日志"帧队列溢出：处理速度跟不上相机出图速度，已丢弃 N 帧最旧图像（队列上限 C）…" | 流程产能 < 推送间隔 | 降客户端推送频率或缩短处理链；**别只靠加大队列容量掩盖** |
| 反复出现同一句拒绝却只看到一条日志 | 服务端只在**原因变化**时记一条 | 看那条最早的拒绝原因，它就是根因 |
| 推图成功但主界面没图 | 「图像采集」的「显示窗体」是否为 0（不显示）；画布采集开关 | 采集本身成功与否看 `Success` 与日志；显示是"锦上添花"，投递失败只告警不影响判定 |
| 采集步骤彩色图红蓝互换 | 通道约定 | 全仓只有一处解码与一处"像素 → HImage"（灰度 1 通道、彩色 BGR 交错）。查是否有绕过它们的新路径 |

## 三、超时文案怎么读（四个数字定位根因）

| 计数表现 | 结论 | 下一步 |
| --- | --- | --- |
| 累计收帧不涨、待消费 0 | 帧根本没进队 | 查客户端返回码（401/404/409 都在第二节） |
| 累计收帧涨、待消费为 0，偶发超时 | 帧被别的消费者抢走，或流程节奏刚好错过 | 检查是否两个采集步骤选了同一台（帧不广播，每帧只被取一次） |
| 待消费长期 = 队列上限，溢出在涨 | **处理不过来**（产能不匹配） | 缩短处理链 / 降推送频率；每丢一帧 = 一个未检测工件 |
| 待消费有货、超时却发生在另一轮 | `FrameTimeoutMs` 填得过小（采集步骤端口填 0 = 用相机配置） | 按产品节拍放宽，或让上游变量控制这个端口 |

## 四、跨机部署与端口

- **两条 HTTP 通道两个端口，不要混**：相机通道 `19100`（`NetworkCameraServer`）；网络推送通道 `19000`（`HttpImageServer`）。
- `Host = 0.0.0.0` 是"听所有网卡"，**不能填进客户端**；客户端填这台工控机的实际 IP。本机有双网卡（视觉网 + 办公网）
  而只想让视觉网那侧能推时，把 `Host` 改成该网卡的实际 IP。
- 令牌默认值 `visionmaster` 是写在源码与文档里的占位值，只防误连、**不是安全防线**；投用前改掉（服务启动时会记一条 Warn 提醒）。
- 改了端口/令牌要重启软件让服务重新监听；现场联调通过后不要再动端口（客户端 URL 要跟着改）。

## 五、"改了没生效"先查这三条（仓库红线）

1. 插件工程必须在 `Plugins\` 下构建——构建约定按目录把 DLL 投到 `Modules\`，放别处加载不到。
2. 改了插件源码必须**重建插件工程**：`Modules\` 不由宿主工程带出，只重建宿主跑的还是旧 DLL。
3. `Modules\` 只放插件 DLL（本驱动是 `Plugin.Camera.Network.dll`）；**公共契约程序集
   `Core.Interfaces.dll` / `Core.Controls.dll` 一律不许拷进去**，否则静态状态出现两份。
