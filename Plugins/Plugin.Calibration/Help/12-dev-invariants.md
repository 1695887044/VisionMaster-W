# 标定 · 开发：不变量与陷阱清单

> 分类：标定 ｜ 来源：插件 Plugin.Calibration ｜ 读者：开发

**改这个插件前逐条对照**：每条都是"必须成立的事实 + 不成立时的症状 + 现在由谁守"。
分两类：**A 类违反后立刻报错**（好查），**B 类违反后静默出错**（难查，历史上真踩过）。

守门断言在 `FlowCanvasChecks\CalibrationChecks.cs`（标题行 `[CAL] 标定插件：仿射/透视求解 / 正反变换 /
质量闸门 / 端口面`，含求解、插件级、JSON 往返、闸门、网格规模 UI、旧方案迁移、残差口径、径向带、时间戳、
取点/锁定、透视族、导出导入、实时图、预填、序列号、粘贴解析、网格族）与消费侧
`FlowCanvasChecks\PoseTransformChecks.cs`（标题行 `[PT] 坐标变换插件：正反变换 / 角度 / 四类失配 / 位姿跟随 /
透视联动 / 网格联动 / 端口面`）。

**下面每条给的断言名都是这两个文件里的原话**；没有断言覆盖的条目已注明"无断言，靠人工核对"。

## A 类：违反就当场报错（好查，但报错文案必须仍然可执行）

### A1 求解只在数学层，坐标语义只在契约层

`TrySolveAffine` / `TrySolveProjective` 无 HALCON 依赖，映射方向固定 `(Row, Col) → (X, Y)`。
把 Row/Col 或 X/Y 传反，编译过、单测照绿、现场坐标轴互换。
守门：`[CAL] 正变换与手算一致（< 1e-9）`、`[CAL] 正反变换互逆（< 1e-9）`、
`[PT] 轴交换/符号不错位（(100,200) → (405,307)，手算常量）`。

### A2 6 元矩阵排布与 HALCON 不同，必须重排

契约 6 元是 `[a11 a12 a21 a22 a31 a32]`，`vector_to_hom_mat2d` 是行主序 `[h11 h12 h13 h21 h22 h23]`；
9 元与 6 元的换算把 `a31/a32` 插在索引 2/5。
守门：`[CAL] 透视跨模型一致：仿射数据上 与 TrySolveAffine 输出重排后逐位 < 1e-9`、
`[CAL] 透视 HALCON 对拍（vector_to_proj_hom_mat2d / normalized_dlt）：h33 归一后逐元 < 1e-6`。

### A3 退化构型必须在求解前拦住

共线判据 `det ≤ 1e-4·trace³`、点全部重合（归一化尺度为 0）、透视的 AᵀA 次小/最大特征值比、
`|h33| < 1e-9`、折返（标定点处 `w` 符号不一致）。
守门：`[CAL] 共线点必须失败且文案含「共线」`、`[CAL] 3 个非共线点恰好可解（残差≈0）`、
`[CAL] 两点重合 → 失败并给出下一步（提示去拖动标记）`、
`[CAL] 透视：3 点失败（至少需要 4 组）/ 近共线 4 点、重复 4 点失败（退化）`、
`[CAL] 透视守卫余项：h33≈0 拒绝 / 映射折返拒绝 / 退化线点拒绝`、
`[PT] 透视分母≈0 的像素点 → 明确失败（w=0 线上拒绝；线外点照常映射）`。

### A4 点数下限按模式分叉

九点 3 组起、透视 4 组起、网格必须 N² 且**每行都填**。
守门：`[CAL] 透视：3 点失败（至少需要 4 组）/ 近共线 4 点、重复 4 点失败（退化）`、
`[CAL] 网格缺节点 → 明确失败并指到行（缺一个节点整格不可用）`。

### A5 半填行与 NaN 必须指名到行

数学层只知道"第几个点"（空行剔除后与行名对不上），所以按行名报错只能发生在插件侧。
守门：`[CAL] 半填行 → 失败且指到行名（P3）`、`[CAL] NaN 指名到行（P2），不再报「第 N 组点」`。

### A6 质量闸门 = 业务失败，不是警告

`rms > ResidualThresholdPx` 判失败并**不发布端口**；护栏越界同判失败。
守门：`[CAL] 残差超阈值 → 失败且文案带残差与检查清单`、
`[CAL] 像素当量取齐 A/B 后成功，且 Kind=PixelScale`（反证：没取全时不得成功）。

### A7 网格不做残差闸门，当量护栏照做

网格节点处精确通过 → 基线残差在畸变场景下必然超阈值，若照闸门拦就自相矛盾。
守门：`[CAL] 网格标定：基线残差超阈值仍判成功，且报告值 = 基线 RMS（质量口径一致）`、
`[CAL] 网格标定：求解成功、Kind=Mesh / 3×3 / 36 个数、Matrix 保持零（未升级消费方必须失败）`。

### A8 身份/尺寸自证只在"两端都有值"时才生效

序列号：本步骤 `CameraSerial` 与上游 `SourceSerial` 都非空才比对（`OrdinalIgnoreCase`）；
尺寸：`SourceImageWidth/Height` 有值才比对。放行分支不能改成报错，否则单相机/离线/旧方案全线红。
守门：`[CAL] 相机身份不符 → 明确失败（标定属于 A、图像来自 B）`、
`[CAL] 序列号一致（忽略大小写）→ 正常成功`、`[CAL] 上游未提供序列号 → 不校验（单相机/未接线零影响）`、
`[PT] 尺寸相符→通过；标定未记录尺寸→放行（无从比对，不误报）`、
`[PT] 失配④相机身份不符 → 失败、两台相机都在文案里`、`[PT] 标定未记录序列号 → 放行（旧标定文件不误拦）`。

### A9 未知 `Kind` 绝不静默按旧逻辑放行

消费端 `switch` 必须留 `default` 明确拒绝（生产端加新模式时忘了改消费端就撞这条）。
守门：`[PT] 未知 Kind=(CalibrationKind)7 → 拒绝（防「忘记分支」静默按旧逻辑放行）`、
`[PT] 网格损坏（长度不符 / 缺失）→ 明确失败、文案含「网格」与「重新运行「标定」步骤」`、
`[PT] 透视矩阵缺失/退化/长度不足 → 拒绝且文案含「损坏/重新运行标定」`。

### A10 网格是插值，凸包外必须失败（正反两向）

外推 = 在没标过的地方编造坐标。
守门：`[CAL] 网格外不插值（正/反两向）→ 明确失败（文案含「不在网格覆盖范围内」）`、
`[PT] 网格外（正向像素 / 反向机械）→ 明确失败（不外推）`。

### A11 导入的拒绝面必须早于任何写操作

版本、模式范围、缺表、表内 null 行、阈值/护栏非有限或负数——全部查完才允许动本机数据。
守门：`[CAL] 导入拒绝面：空内容 / 非法 JSON / 更高版本 / 锁定态`、
`[CAL] 导入拒绝面 2：空行不抛异常（中文原因）、NaN/Inf 阈值与护栏必须拒绝、模式越界拒绝`。

### A12 锁定态的每个编辑入口都要拒（不是只在界面上禁用）

`RebuildGrid` / `PasteRows` / `ClearRows` / `PushMarkers` / `ArmPick` / `ApplyPickedPoint` /
`ImportCalibrationJson` 各自显式判 `IsEditable`。
守门：`[CAL] 锁定后 IsEditable=false`、`[CAL] 锁定态取点被拒（文案含「锁定」）`、
`[CAL] 锁定态清空表格被拒（数据原样保留）`。

### A13 端口面与 `[Display]` 是"能不能用"级别的事实

5 入 4 出（+基类 `Success` / `ErrorMessage`），`Transform` 端口类型必须是 `CalibrationTransform`；
`GroupName` 必须是「标定」，否则工具箱里分组错/拖不出来。
守门：`[CAL] 输出端口齐全（Transform / MmPerPixel / ResidualRmsPx / ResidualMaxPx）`、
`[CAL] Transform 端口类型 = CalibrationTransform（下游按类型接）`、
`[CAL] 输入端口 SourceImagePath 存在（配置态取点/预览入口）`、
`[CAL] 插件带 [Display]（GroupName=标定，否则工具箱里拖不出来）`、
`[CAL] 透视 UI 面：ShowPointTable 真值表（含通知）、状态含「透视」、端口面 5 入 4 出（+基类 2 输出）不变`、
`[PT] 输入端口面齐全（绑定用）`、`[PT] 输出端口面齐全`。

## B 类：违反后静默出错（难查，历史真踩过）

### B1 残差单位：mm 偏差必须除以当量换成 px

求解器与表格回写都是像素口径（阈值默认 1px、带诊断 0.5px）。2026-10-04 曾漏掉这一步：
0.5mm 的错点在当量 0.02 时 ≈25px，被写成"0.5px"→ 与聚合残差对不上、还骗过人眼。
症状：表格说很好、RMS 说超阈值（或反过来）。
守门：`[CAL] 表格残差列按像素口径（0.5mm ≈ 22px，不是 0.5）`、
`[CAL] 透视单位反证：该行残差（px）= mm ÷ 局部当量（≠ 中心当量，差 >2.5%）`。

### B2 透视逐点残差要用**局部当量**，不是中心当量

近大远小场景下边缘点的 mm/px 与中心不同，用全局值会在边缘悄悄放行放大误差。
守门：`[CAL] 透视单位反证：该行残差（px）= mm ÷ 局部当量（≠ 中心当量，差 >2.5%）`、
`[CAL] 透视局部当量：中心值=中心差分独立算值（<1e-8）、各向异性可识别（>5%）、退化护栏>0`、
`[CAL] 透视插件全链路：Success/Kind/端口/相机与尺寸透传/当量=中心局部/表格残差=局部口径`。

### B3 径向带：空带记 0，判读前先看计数

写 NaN 会让 JSON 出现非标准的 `"NaN"`（跨语言消费有风险）；不写计数则无法区分"残差真是 0"与"这个带没点"。
症状：3 点标定被误报"疑似镜头畸变"。
守门：`[CAL] 径向带无 NaN（无点带=0 + 计数表达，JSON 才跨语言安全）`、
`[CAL] 空带不误报畸变（计数为 0 的带不参与形态判读）`、`[CAL] 有计数时照常提示畸变`、
`[CAL] 提示门限随残差阈值放宽（阈值 3px → 0.6px 边缘不再提示）`、
`[CAL] CalibrationTransform JSON 往返字段不丢`、
`[CAL] 透视 JSON：ProjectiveMatrix 往返逐位一致、h33=1、无 NaN/Inf；旧 JSON 读入行为不变`。

### B4 时间戳由输入签名驱动，不是"运行时刻"

运行实例只走 `ApplyConfigValues`、不经 `Initialize` ⇒ 首轮若推进时间戳，每次运行的首个
`RunAlgorithm` 都会把方案里的标定时间刷成"刚刚"，下游"标定多久没更新"永远读不到真值。
签名里必须包含 `null` 与 0 的可区分表达（`?.ToString("R") ?? "-"`）以及 `SourceTag` 与尺寸。
守门：`[CAL] 连续两次运行 CreatedAtUtc 稳定（签名不变不推进）`、
`[CAL] 修改标定数据后 CreatedAtUtc 前进`、`[CAL] 载入的标定时间在运行首轮保持不变（首轮只记签名）`、
`[CAL] 透视签名/时间戳：切换 NinePoint↔Perspective 推进；同数据重复运行不推进`、
`[CAL] 导入后：按文件数据求解成功、时间戳以文件为准（首轮不推进）`。

### B5 `null` 与 `0` 的区分是标定数据的语义底座

四个 A/B 字段与表格四值一律 `double?`：`null` = 未填，`0` = 合法坐标（回零位、工件原点、图像边缘都会取 0）。
旧实现拿 0 当哨兵 → 合法点被误判半填、或与图像 0 一起被当空行**静默剔除**。
症状：四格都填了却被告知漏填；或某个点根本没参与求解却看不出来。
守门：`[CAL] 机械坐标 0 是合法值（不再被判半填/空行，正常求解）`、
`[CAL] 含 0 坐标的解不含该点被剔除的痕迹（9 点全参与）`、
`[CAL] 导出/导入往返：0 与 null 的区分不丢、序列号逐项一致`、
`[CAL] 粘贴解析：空单元格=null、行首空格子保留、全空行跳过`、
`[CAL] 配置面新增键存在（CalibrationStampUtc / IsCalibrationLocked / 可空 A/B）`。

### B6 旧方案迁移只能在配置态 `Initialize` 做，且不污染 `ValueConverter`

"四值全 0 → 空行"是标定专属语义。运行实例不经 `Initialize`，所以旧格式数据在运行期被当**有效点**——
这条差异必须知道，别在运行期"顺手补迁移"。
守门：`[CAL] 旧方案迁移：四值全 0 → 空行（旧版本就把这种行当空行）`、
`[CAL] 旧方案迁移：含非 0 值的行不被碰（0 坐标照常保留为有效点）`、
`[CAL] 旧方案迁移：已经是 null 的行是空操作（幂等）`。

### B7 Tab 粘贴必须保留空单元格

`RemoveEmptyEntries` 会吞掉 Excel 的空白格，把后面的列顶到前面 → 整行错位（机械 X 进了图像 Row）。
只修剪**行尾**空格子，**行首空列保留**。
守门：`[CAL] 粘贴解析：空单元格=null、行首空格子保留、全空行跳过`、
`[CAL] 粘贴解析：5 列带序号 → 首列丢弃、四值就位`、`[CAL] 粘贴解析：列数不对 → 报错并说明应为 4/5 列`。

### B8 表格订阅两条隐蔽路径，缺一条就"改值不刷新"

字段初始化的默认集合**不走 setter**，`CollectionChanged` 必须在构造函数补挂；
反序列化进来的行没有 `Add` 事件，setter 里必须 `RebindPointRowSubscriptions()` 先摘后挂。
症状：某些实例上"改一格即时重算"静默失效（界面还留着上一次的质量数字）。
守门：`[CAL] 表格改一格 → 质量区立即重算（连续两次改动的读数不同）`。

### B9 回写残差不能触发第二轮求解

`OnPointRowChanged` 只认 `MachineX` / `MachineY` / `ImageRow` / `ImageCol` 四个属性名；
`ResidualPx` 的回写与派生属性变更必须不再进 `RefreshStatus`，否则"求解 → 回写 → 再求解"自激。
双向同步（拖标记 ↔ 改表格）另靠 `_syncingMarkers` 闸门，`finally` 里复位。
守门：`[CAL] 配置态残差回写表格（不用跑一次流程才填）`（它同时是"回写不炸"的回归位）；
**`_syncingMarkers` 的防自激本身无断言，靠人工核对**（改这条路径时手工做"拖一次标记、
状态栏只算一轮"的验证，或补一条计数型断言）。

### B10 图像尺寸元信息的两条相反规则

- 底图换人（文件 ↔ 实时图）时 `RefreshCanvasImageState` **只增不清**："图片暂时不在场"不等于
  "标定快照作废"；
- 用户**显式清空路径**且此前确有文件预览、且没有实时图时才清成 0——"你主动把图标废了"。
症状：打开一份"手动填点"的标定就丢尺寸，下游尺寸自证从此放行。
守门：`[CAL] 实时图断开：画布回落但尺寸记录保留（快照不被误清）`、
`[CAL] 空路径且从未载过图：尺寸记录保留（修复“打开即清尺寸”）`、
`[CAL] 实时图接入：画布底图切换为实时图且尺寸记录更新`。

### B11 异步读图的两个守卫 + "同一张不重读"

`_previewLoadId` 丢弃过期结果、`_disposed` 拒绝写已关闭窗口；路径与 `PreviewImagePath`
OrdinalIgnoreCase 相同直接返回。缺一条的症状：换路径后旧图"复活"、或每次刷新都读盘。
守门：`[CAL] 清空路径后，在途读图不把预览'复活'（DisplayImage 保持空）`。

### B12 构造期不碰 HALCON 原生库

属性初始化只建 `ObservableCollection`/命令，`DisplayImage` 保持 null；载入图像只在
`Initialize`/`EnsurePreviewLoaded` 里做（否则工具箱/编译期枚举插件类型时就可能触发原生调用）。
守门：`[CAL] 构造后 DisplayImage 为 null（构造期不碰 HALCON 原生库）`、
`[PT] 构造后 DisplayImage 为 null（构造期不碰 HALCON 原生库）`。

### B13 借入的图像不 Dispose、自有图像换人即弃

`OnlineImage` 只断引用；`DisplayImage` 的 setter 在 `SetProperty` 成功后释放被换下的旧图；
标记的原生句柄靠 `OnCanvasMarkersChanged` 对 `OldItems` 逐个 `Dispose`。
症状：非托管内存随"每换一次图/每重建一次表"稳定上涨。
守门：**句柄释放路径无专门断言，靠人工核对**（`CalibrationChecks` 只在插件级查 Success/端口，
`[CAL] 插件级九点成功：Success=true 且 Transform 端口有值` 一类；改所有权时按 R42 重建后
用长时运行/任务管理器看原生内存曲线）。

### B14 配置态与运行期必须共用一份计算

`RefreshStatus` 与 `RunAlgorithm` 都调 `ComputeCalibration`。另写"界面用的简化求解"=
"界面绿、运行红"，而且只有现场能发现。同理 `BuildCalibrationExportJson` 也先跑它，
以便时间戳按签名落定 + 拿质量快照。
守门：`[CAL] 闸门未过时质量数字保留（红字显示差多少，不再清空）`、
`[CAL] 导出：可解配置带质量快照（Snapshot）与版本号`。

### B15 `GridSize` 的 clamp 范围与界面可选值必须一致

`OnGridSizeChanging` 夹 2~10，`GridSizeOptions = Enumerable.Range(2, 9)`（即 2~10 九个值）。
只改一处的症状：从旧方案载入 6×6 时下拉框空白、或界面能选到 clamp 拦不住的值。
守门：`[CAL] 网格规模可选值覆盖 2~10（与 OnGridSizeChanging 的 clamp 一致）`、
`[CAL] 导入元信息：文件尺寸 0 不清本机尺寸；12 行 vs 网格 5 → 归一 4×4`。

### B16 拒绝缩小网格时必须"先扫描再删"

边删边判会留下既不是旧尺寸也不是新尺寸的表，且提示里的行号对不上。
建议值用 `Ceiling(Sqrt(count))`（`Round` 会给装不下全部行的 N：12 行 → 3×3 仍被拒）。
守门：`[CAL] 网格缩小遇非空行 → 不删任何行（表保持 9 行原样）`、
`[CAL] 拒绝缩小时给出可操作提示（含能容纳全部行的 3×3 建议）`、
`[CAL] 非平方行数被拒缩时建议向上取整（12 行 → 4×4 而非 3×3）`。

### B17 取点是 opt-in 通道，不许改变其他插件行为

`HalconBase.IsPickMode` 默认 false，只有本插件待命时开启；视图 `Unloaded` 与 Esc 都要 `CancelPick()`。
漏一条的症状：别的插件画布开始吃点击、或待命态悬着把下一次点击写进"孤儿行"（重建后已换掉的行对象）。
守门：`[CAL] HalconBase.IsPickMode 默认 false（加法不改变其他插件行为）`、
`[CAL] HalconBase.ImagePicked 事件存在（一次性取点通道）`、
`[CAL] 未锁定但无标定图 → 取点提示先载图`、
`[CAL] A/B 未取全 → 明确失败并给下一步（不再误用 (0,0)）`。

### B18 预填失败不许动行数据

上游 `SourcePointRow` / `SourcePointCol` 任一为空 → 只报状态、不写半格（写半格会立刻触发"半填行"失败，
用户看不出是谁干的）。
守门：`[CAL] 预填：从上游定位点端口（Row/Col）回填该行`、
`[CAL] 预填：上游为空 → 明确拒绝且不动行数据`。

### B19 消费端文案与生产端文案不能互相依赖

同一批事实有**两套文案**（标定侧 `[CAL] 相机身份不符 → 明确失败（标定属于 A、图像来自 B）` 与
坐标变换侧 `[PT] 失配④相机身份不符 → 失败、两台相机都在文案里`）；断言里锁的是关键词
（如「九点」「透视」「损坏」「重新运行「标定」步骤」「不在网格覆盖范围内」）。
改文案时保持关键词，否则断言红在别人的用例上：
`[PT] 失配②文案同时含「九点」与「透视」（旧断言依赖「九点」不丢）`、
`[PT] 失配①未接标定 → 失败并指到「标定」插件`、
`[PT] 失配②当量标定当九点用 → 失败并指到「九点标定」`、
`[PT] 矩阵缺失/退化 → 失败并指到「重新运行标定」`、
`[PT] 失配③图像尺寸不符 → 失败、两个尺寸都在文案里`。

### B20 网格的三角化/插值不许在两端各写一份

`CalibrationMesh` 在契约程序集，生产端（填 `MeshNodes`、算平均当量）与消费端（映射、局部仿射）共用。
分叉的症状是同一份标定在两个步骤里给出不同坐标，且只在视野中间以外暴露。
守门：`[CAL] 网格标定：节点处精确通过（最大偏差 < 1e-9）`、
`[CAL] 网格标定：格内点误差 ＜ 全局仿射基线的一半（畸变被分段吸收）`、
`[CAL] 网格标定：正反互逆（像素 → 机械 → 像素 误差 < 1e-9）`、
`[CAL] 网格标定导出/导入往返：Kind/N/节点逐项一致且可用`、
`[CAL] 网格退化（节点重合/共线）→ 明确失败且说清是哪一格`、
`[PT] 网格（节点取自同一仿射）：映射与仿射处处一致（< 1e-9，含节点与格内点）`、
`[PT] 畸变网格：格内点误差 ＜ 全局仿射的一半（消费侧确实在吸收畸变）`、
`[PT] 网格角度：与九点角度换算一致（局部雅可比口径正确）`。

### B21 手册本身的打包与分层

页序按文件名 `NN-` Ordinal 排；开发页判据是文件名里的 `dev-` 段；`Help\` 下**不许再分子目录**
（本程序集只有一个插件类，走扁平页；一旦多出子目录，宿主"本类型子目录有页就只收子目录"的规则
会把全部用户页静默挤掉）。
守门：`[HM]` 一族——HM5 首行 `# `、HM6 文件名前缀、HM7 无 BOM 严格 UTF-8 且含中文、
HM8 每册正文 ≥70 行、HM9 无占位标记、HM12 `NN-dev-xxx.md`、HM12b 最多一层目录、
HM13 已交开发章节达档位下限（本条 L 档 300 行）。
