# 标定

> 分类：标定 ｜ 来源：插件 Plugin.Calibration

产出"**像素 → 毫米 / 机械坐标**"的变换。四种模式（像素当量 / 九点标定 / 透视标定 / 网格标定）都输出同一个
`Transform` 契约对象，供下游「坐标变换」换算机械坐标、或直接把 `MmPerPixel` 接给测量类算子做毫米换算。

## 为什么需要它

视觉算子天生只会算像素：像素是"照片上的距离"，不是"工件上的距离"。当量随镜头焦距、工作距离、传感器尺寸、
分辨率而变，而且**各向异性**（横竖当量不一定相同）、**视野内不一定均匀**（畸变、相机斜置）。
标定这一步做的事，就是把"图像坐标"和"机械坐标"绑成一个可核验的映射，并给出**质量数字**（残差）——
让"这份标定能不能用"变成一个看得见、卡得住的条件，而不是靠运气。

## 原理

1. **像素当量**：量一段已知长度（`KnownLengthMm`）在图上的像素距离（A、B 两点），
   当量 = 已知长度 ÷ 像素距离。只得到一个数，**不含机械坐标**，因此不能用来做坐标换算。
2. **九点标定（2D 仿射）**：N×N 组"图像点 (Row, Col) ↔ 机械坐标 (X, Y)"，最小二乘求 6 元矩阵：
   `X = a11·Row + a12·Col + a31`、`Y = a21·Row + a22·Col + a32`（行主序，单位 mm）。
   仿射只有 6 个自由度，**3 点即唯一解**——所以"9 点"只是行业叫法，点数是**采样密度**、不是模型：
   加密点能提高抗噪余量、让残差更能暴露畸变，但**不会把畸变拟合掉**。
3. **透视标定（3×3 投影）**：相机斜置/大视场存在"近大远小"时，仿射吸不住，改用 8 自由度的投影矩阵（**至少 4 点**，推荐 3×3/4×4）。
4. **网格标定（分段仿射）**：镜头畸变的工程近似——把 N×N 节点三角化后**逐格仿射**、重心插值（要求 N×N **每行都取点**，缺一个节点它周围四格都不可用）。
   三角化/插值规则在契约程序集里（生产端与消费端共用同一份实现，避免两端算出两套坐标）。
5. **每轮重算**：运行期不"存矩阵直接用"，而是用存下的标定点**每轮重算**（微秒级）。
   好处：改了标定表却忘了重新标定这种不一致，在结构上不可能发生；配置态预览与运行期走**同一段计算**，
   界面上看到的质量就是运行时的质量。

## 输入端口

| 端口 | 必填 | 说明 |
| --- | --- | --- |
| `SourceImagePath` | 否 | 标定图路径（**配置态取点/预览用，运行期不读盘**）。可浏览也可链接变量 |
| `SourceImage` | 否 | 实时图：配置态**优先级高于文件路径**（有它就直接在它上面取点）；运行期不参与计算 |
| `SourceSerial` | 否 | 上游相机序列号（接「图像采集」的 `SourceSerial`）：与本步骤「相机序列号」都非空且不一致 → **明确失败** |
| `SourcePointRow` | 否 | 上游定位点 Row（接「模板匹配」的 Row / 「几何查找」的 Row（圆心行）），配合行上的「预填」按钮 |
| `SourcePointCol` | 否 | 同上，Col |

## 输出端口

| 端口 | 说明 |
| --- | --- |
| `Transform` | 标定结果（`CalibrationTransform`）：模式种类、当量、6 元仿射矩阵 / 9 元投影矩阵 / 网格节点、标定图尺寸、相机序列号、创建时间、残差指标。下游接「坐标变换」的 `Transform` |
| `MmPerPixel` | 像素当量（mm/px）便利口：直接接给卡尺测量等算子的 `MmPerPixel` 输入 |
| `ResidualRmsPx` | 标定残差均方根（像素）——质量主指标，可接「CSV记录」做标定档案 |
| `ResidualMaxPx` | 最大单点残差（像素）：哪个点没取好，看表格的"残差px"列指到哪一行 |

## 关键参数

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `Mode` | `PixelScale`（像素当量） | 四选一：`PixelScale` / `NinePoint` / `Perspective` / `Mesh`（界面显示中文、流程存成员名）。切换只影响界面与执行分支，**不会清掉另一种模式已填的数据** |
| `GridSize` | 3 | 网格边长 N（**夹取 2~10**，界面下拉可选 2~10），标定表行数 = N²。点数只是采样密度：3×3 覆盖四角+中心是常规规模，4~5 加密抗噪，2（4 点）是最小覆盖 |
| `KnownLengthMm` | 100 | 像素当量模式：标定物的已知长度（mm）。**填错 = 当量整体缩放错**；必须为正数 |
| `ScaleARow` / `ScaleACol` | 空 | 像素当量模式的 A 点。**空 = 未取点，0 是合法坐标**（标定物一端可能正好落在图像边缘） |
| `ScaleBRow` / `ScaleBCol` | 空 | B 点，含义同 A。当量 = 已知长度 ÷ A–B 像素距离 |
| `PointRows` | 空 | 标定表（九点/透视/网格共用），每行 `{ 机械X, 机械Y, 图像Row, 图像Col, 残差px }`，JSON 快照随步骤存盘。**整行留空 = 空行**（不参与计算）；**半填 = 报错并指名行名**；旧方案"四值全 0"的行载入时自动还原为空行 |
| `ResidualThresholdPx` | 1.0 | 质量闸门（px）：残差 RMS 超过它判**业务失败**（不是警告）。经验：≤0.2px 很漂亮，0.2~1px 正常 |
| `MmPerPixelMin` / `MmPerPixelMax` | 0.001 / 1.0 | 当量合理性护栏：防"µm 当 mm 填"、防标定物长度量错一个数量级。填反了对称使用，不报错 |
| `CameraSerial` | 空 | 这份标定属于哪台相机（与「系统 → 相机设置」的序列号一致）。多相机**必填**，失配核对要用 |
| `IsCalibrationLocked` | false | 锁定防误改：锁定后表格 / 取点 / 粘贴 / 重建 / 清空 / 拖标记都被拒。**只锁输入不锁输出**——照常重算与输出，下游不受影响 |
| `SourceImageWidth` / `SourceImageHeight` | 0 | **载图时自动记录**并随步骤存盘：下游据此做"换分辨率就失效"的自证 |
| `CalibrationStampUtc` | 空 | 标定配置的最后改动时间（UTC），按"输入签名"推进——**运行期每轮重算不会把它刷成"刚刚"**，下游拿它判断"标定多久没更新"才有意义 |

## 口径与失败策略

- **失配必须失败**：相机身份不符、A/B 未取全、两点重合、有效点不足、半填行、含 NaN/Inf、点近似共线、
  点全部重合、当量非正或越界、残差超阈值——全部明确失败并写清**下一步做什么**，绝不"先用着旧矩阵"。
- **共线守卫**：法方程 `det ≤ 1e-4·trace³` 直接判"近似共线"失败（不去解病态方程）。
  常见成因是只沿一条输送带走点——把点铺开成 N×N 网格覆盖四角与中心。
- **残差单位口径**：机械系偏差（mm）会**按当量换算成像素**后再统计与比较；表格"残差px"列同一口径回写。
- **透视与网格故意把 6 元 `Matrix` 留成零**：未升级的消费者拿它会因 `det=0` 明确失败——
  绝不允许把"透视/网格"静默近似成"仿射"（边缘区域会整体错位）。
- **网格模式不做残差闸门**：网格在节点处**精确通过**，节点残差恒 0、没有信息量。
  质量区显示的 RMS / 最大 / 径向带是"**同一批点上全局仿射基线**"的拟合质量，用来判读畸变有多大
  （它偏大是**正常**的，正是你选网格的理由）。当量护栏照常生效。
- **超阈值时质量区照常红字显示残差数字**（看得到差多少），运行期照旧失败不输出。
- **开轮清零**：`Transform` 置 null、三个 `double` 输出置 0（失败轮下游读不到上一轮脏值）。
- **锁定只锁编辑、不锁运行**；无阻塞操作（没有取消分支），同一组输入永远得到同一矩阵（幂等）。

## 典型用法 / 接线

```
图像采集.SourceSerial ─▶ 标定.SourceSerial        （多相机建议接）
图像采集.OutputImage ──▶ 标定.SourceImage         （配置态在线取点用）
标定.Transform ───────▶ 坐标变换.Transform         （需要机械坐标时必接）
标定.MmPerPixel ──────▶ 卡尺测量.MmPerPixel       （只要毫米换算时接这个）
标定.ResidualRmsPx ───▶ CSV记录.对应列            （留标定档案 / 漂移报警）
```

## 常见问题

**Q：下游「坐标变换」报"当前标定只有像素当量、不含机械坐标"？**
用了 `PixelScale` 模式去做坐标换算。像素当量只给 mm/px、不知道机械系在哪，
要机械坐标就重新用「九点标定」（或透视/网格）标一份。

**Q：残差报"超过阈值 1px"，先改什么？**
口诀：**先查点、再查单位、最后才动阈值**。
① 表格逐行看"残差px"列指到哪一行（多半是那一行的图像点没取在同一物理位置，或机械坐标与图像点串了行）；
② 看径向带提示：中心小、边缘大 → 疑似镜头畸变，仿射吸不住，转「网格标定」或做镜头内参；单方向偏/梯形 → 相机斜置，转「透视标定」；
③ 都排除了再考虑放宽 `ResidualThresholdPx`（大画幅/弱镜头现场常见），但要明白这是在容忍误差。

**Q：当量算出来是 0.00002 这种量级？**
单位填错一个数量级（把 µm 当 mm）或标定物长度写少一位。护栏 [0.001, 1] 会直接报越界；
先核 `KnownLengthMm` 与标定物实际标注单位。

**Q：报"第「P3」行只填了一部分"？**
标定表四个值（机械X / 机械Y / 图像Row / 图像Col）必须齐全。**没填就留空**，别写 0——
0 是合法坐标（机械回零位、工件原点、图像边缘都会取到 0）。整行留空 = 空行不参与计算；半填会被当成漏填而明确报错。

**Q：A/B 点把 Row 填成 0 就"没反应"？**
不会。这四个字段是可空语义：`null` = 未取点，`0` = 合法坐标（旧版本拿 0 当"没填"，已修）。

**Q：各向异性 2% 要不要紧？**
通常是标定物没有正对镜头（或像素本身非方形）。它是**提示不是失败**；
但如果测量方向正好落在当量大的那一向，误差会被放大——介意就摆正标定物重标。

**Q：换相机 / 换分辨率后旧标定还在用？**
填好 `CameraSerial` 并接上游 `SourceSerial`（两端都非空才校验，大小写不敏感，单相机/离线不打扰）；
图像尺寸在载图时自动记录，下游「坐标变换」接了 `SrcImage` 就会做尺寸失配校验。
标定时间戳 `CalibrationStampUtc` 只在标定数据真改动时推进，可用来盯"标定多久没更新"。

**Q：怕现场有人误改标定？**
勾「锁定标定（防误改）」。锁定后所有编辑入口禁用，运行照常输出；解锁后才能继续改。
