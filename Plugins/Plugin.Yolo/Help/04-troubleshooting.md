# YOLO 目标检测 · 排错

> 分类：图像处理 ｜ 来源：插件 Plugin.Yolo

## 五、现场排障（报错原文 → 查什么）

| 报错 / 现象 | 排查 |
| --- | --- |
| `尚未选择模型：请在节点配置里选择一个 .onnx 检测模型` | 没填路径 |
| `模型文件不存在：<路径>` | 路径填错、模型没部署到那台机器；相对路径请以**宿主程序目录**为基准核对 |
| `这个模型的任务类型是「实例分割/姿态/…」（元数据 task=…）` | 模型不是 detect 任务，按第一节重新导出 |
| `输出形状 [..] 看起来是 YOLOv5 风格的 [N, 5+C]（通道在后、带 objectness）` | 用 v8/v11 重新导出，或联系开发补支持 |
| `无法识别的输出形状 […]：期望 [1, 4+C, N]` | 不是检测模型，或导出时裁剪过输出。报错会带上模型路径与实际输出形状，可整句贴回来定位 |
| `输出通道数 N 不合理（应大于 4）` | 不是检测模型，或导出异常 |
| `图像通道数为 N，只支持 1 通道（自动补成 3）或 3 通道` | 上游先转成灰度或 RGB（常见于 4 通道 RGBA 输入） |
| `无法确定模型输入尺寸：模型是动态形状…` | 手填`输入尺寸` |
| `类别过滤里有一项不是合法的类别索引` | 只接受非负整数、逗号分隔（如 `0,2`），留空 = 不过滤 |
| `加载 ONNX 模型失败：…` | ① 文件不是合法 `.onnx`；② `onnxruntime.dll` 没随插件投递到宿主 exe 目录；③ 宿主是 32 位进程（必须 x64） |
| `当前进程是 32 位，而 ONNX Runtime 原生库只有 x64 版本` | 把宿主改为 64 位（x64） |
| 运行期 `DllNotFoundException: onnxruntime` | 原生库不在 exe 旁边（Windows 不递归搜 `Modules\`） |
| 运行期 `FileNotFoundException`（Tensors） | `System.Numerics.Tensors` 没随插件带——它**不在** .NET 9 共享框架里 |
| 一个都没检测到（步骤仍算成功） | 看 Info 日志（含阈值与模型名）。① 置信度阈值设得太高；② 模型与当前产品不匹配；③ 图像需要预处理（亮度/对比度） |
| 日志被 ORT 内部消息淹没 | 已把 ONNX Runtime 日志压到 ERROR 级别（那些 `Initializer … appears in graph inputs` 是模型导出质量的提醒，与用法无关） |
| 换了模型路径但结果像旧模型 | 不该发生（会话按路径判变）。确认改的是**本步骤**的模型路径，且界面摘要已变成新文件名 |
