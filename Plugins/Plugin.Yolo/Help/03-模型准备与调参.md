# YOLO 目标检测 · 模型准备与调参

> 分类：图像处理 ｜ 来源：插件 Plugin.Yolo

配置界面右列是只读图像显示（不能框选，本节点不吃 ROI、检测整幅图），左列刻意显示两处排障信息：**模型摘要**（输入输出形状 / task / 类别名）和**试算结果里的 letterbox 参数**——它们不是装饰，出问题先看这两处。

## 一、模型准备（现场最容易卡的一步）

模型是**客户资产，插件不内置**。YOLO 模型由训练侧导出，插件只负责"用"它。

1. **必须是检测任务（detect）**。分割 / 姿态 / 旋转框 / 分类模型的输出格式与检测完全不同，**按检测解读会得到错误结果却不报错**，所以插件会明确拒绝。导出：
   ```
   yolo export model=你的模型.pt format=onnx
   ```
2. **必须是 YOLOv8 / v11 系列**。v5 的输出布局是 `[1, N, 5+C]`（带 objectness、维度顺序恰好相反），第一期不支持，会拒绝并提示重新导出。
3. **类别名建议写进模型元数据**。Ultralytics 导出会把 `names` 与 `task` 写进去；读不到 `names` 时插件用 `class_0` `class_1` 占位（**不编造名字**）。界面上的模型摘要会写明"模型未写类别名"。
4. **类别索引从 0 起、顺序按模型**。下游做判定、`类别过滤`、按类统计时一律以**索引**为准（显示名可能改，索引才和模型一致）。
5. **放置位置**：填绝对路径，或**相对宿主程序目录**的路径（换机器部署不用改配置）。相对路径按 exe 所在目录解析，路径里有非法字符会被当作"找不到"处理。
6. **部署依赖**：`onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`System.Numerics.Tensors.dll` 必须在**宿主 exe 目录**。Windows 加载原生 DLL 不会递归搜 `Modules\`，放错位置编译期一切正常、运行期才炸。

## 二、第一次检测（五步）

1. **选模型**：填`模型路径`或点「浏览」。摘要区立刻显示输入/输出形状、`task`、类别名——**这一眼能挡掉 90% 的"模型选错了"**。
2. **接图**：在「图像输入」里链接上游端口（或画布上拖线）。点「执行」试运行，上游图会自动显示到右列。
3. **调参**：`置信度阈值` / `NMS 重叠阈值` / `最多保留目标数`；高级里有`输入尺寸` / `类别过滤` / `裁剪边距`。
4. **试算**：点「试算一下」，结果形如：
   ```
   检测到 2 个目标（耗时 63 ms）
   letterbox: 缩放 0.500　补边 (0,25)
     划伤  0.90  [80,30,120,70]
     缺陷  0.70  [8,62,54,96]
   ```
   **试算与运行期共用同一套检测代码**，所以"界面看着对、跑起来不对"不会发生。
5. **接下游**：`Count` / `ClassNames` 接比较节点做 OK/NG；`BoxesText` 接记录/上传；`BestCrop` 接精测算子。

## 三、letterbox 与坐标：为什么框会偏

```
scale    = min(目标边长/原图宽, 目标边长/原图高)      ← 取小者，等比，保证不拉伸
缩放后   = round(原图宽 × scale) × round(原图高 × scale)
补边     = ((目标边长 − 缩放后宽)/2, (目标边长 − 缩放后高)/2)   ← 整数整除，居中
填充值   = 114 灰（不是黑）
原图坐标 = (letterbox 坐标 − 补边) ÷ scale，再夹进 [0, 宽−1] × [0, 高−1]
```

**算例**（200×100 的宽图送进 100×100）：`scale = 0.5`，缩放后 `100×50`，补边 `(0, 25)`。
模型给的回信框 `(40,40,60,60)` → 原图 = `((40−0)/0.5, (40−25)/0.5, (60−0)/0.5, (60−25)/0.5)` = **`(80,30,120,70)`**。

| 症状 | 十有八九是这里 |
| --- | --- |
| 框整体往一个方向偏 | 补边算错 / 有人把填充值改成黑（0）——黑边会被模型当成强边缘 |
| 贴边的目标框偏得厉害 | 同上，114 灰是训练时的填充值，必须一致 |
| 框尺寸对、位置按比例偏 | 有人直接拉伸成方形（没等比缩放），长宽比被改变 |
| 框略微超出图像边界 | 正常，插件已夹回图内；若`BestCrop`日志出现"已夹取"说明框越界，需查模型或输入尺寸 |

## 四、参数调节速查

> 完整参数与取值范围以流程中该步骤的「模块参数」界面为准，这里只解释含义。

| 现象 | 调哪里 |
| --- | --- |
| 漏检（该检出的目标没框出来） | 调低`置信度阈值`（默认 0.25）。先降到 0.15 看看有没有候选——完全没有就怀疑模型/预处理，而不是继续降阈值 |
| 误检多 | 调高`置信度阈值` |
| 同一个目标出一堆框 | 调低`NMS 重叠阈值`（0.45 → 0.3 左右压制更强） |
| 不同类别被互相压制 | 不会发生——NMS **按类别分组**做，跨类不互压 |
| 只想看某几个类别 | `类别过滤`填索引（如 `0,2`）。非法值明确报错，不会静默当成不过滤 |
| 目标太密、下游数据量或耗时大 | `最多保留目标数`（按置信度截断）；`类别过滤`；上游裁 ROI；`输入尺寸`降一档 |
| 动态形状模型报"无法确定输入尺寸" | 手填`输入尺寸`（常见 640）。**留 0 会明确报错，不猜** |
| `BestCrop` 边缘被切掉 | `裁剪边距`给几像素余量 |
| `BestCrop` 内容错位 | 看日志有没有"检测框超出图像范围，已夹取"——那是模型/输入尺寸不对的第一个信号 |
| 节拍吃紧（耗时长） | `输入尺寸`调小、换更小的模型（n < s < m）、`最多保留目标数`收紧、上游裁小检测区域 |

> **阈值与 NMS 的调法建议按顺序**：先用极低置信度（0.1）跑一遍看"模型到底有没有看见"，确认候选存在 → 再逐档升到误检可接受的阈值 → 最后用 NMS 收拾重复框。反过来调容易把"模型根本没学到"误诊成"阈值太高"。

## 六、判定与下游怎么接

本节点**不做 OK/NG、不做结果投射**（规矩与「颜色检查」「OCR」一致）：

```
YOLO.Count ──────────▶ 比较节点（> 0 判 NG）──▶ 条件分支 / 结果上报
YOLO.ClassNames ─────▶ C#脚本（按类统计、分拣）
YOLO.BoxesText ──────▶ 数据记录 / 结果上报（标量，直接接得上）
YOLO.BestCrop ───────▶ 卡尺测量 / 几何查找（粗定位 → 精测）
```

- **按类别计数/存在性判定**：`ClassNames` 是数组，简单场景用 `Count`，需要"某一类才算 NG"时在下游脚本里遍历 `ClassIds`。
- **要物理尺寸**：`Boxes` 是像素。请在上/下游接「标定」做坐标变换，或乘像素当量——本插件不做换算。
- **要带框的存档图**：本节点不输出标注图，用「结果显示」把几何项烧进像素。

## 七、上线前检查清单

- [ ] 模型摘要里 `task = detect`、形状是 `[1, 4+C, N]`，类别名与现场一致（不是 `class_N` 也能用，但下游要自己映射）；
- [ ] 用**已知 NG 样**验一遍：漏检率能接受才算阈值定下来；
- [ ] `模型路径`用相对路径时，确认部署包里模型与 exe 的相对位置和开发机一致；
- [ ] `onnxruntime*.dll` 与 `System.Numerics.Tensors.dll` 在宿主 exe 目录（换机部署最容易漏）；
- [ ] 耗时满足节拍（看试算里的 ms 数）；不满足就降`输入尺寸`或换小模型；
- [ ] 判定逻辑与"检出 0 个算正常"这条口径已和现场 MES/报警约定清楚，别把良品当异常。
