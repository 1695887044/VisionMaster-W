# YOLO 目标检测 · 快速上手

> 分类：图像处理 ｜ 来源：插件 Plugin.Yolo

把一张图送进 **ONNX 格式的 YOLO 检测模型**，输出"检到了几个、各是什么类别、把握多大、框在哪"，并可把置信度最高的那个目标**直接裁好**给下游精测算子用。
它靠**学过的经验**找目标，适合"规则说不清、但人一眼就能认出来"的场景：缺陷种类多、形态多变、背景复杂。

## 为什么需要它 / 原理

传统算子靠规则找目标——Blob 按灰度找异常、模板匹配按长相找目标、卡尺按边缘找位置。缺陷形态一变就得重调参数时，就换成"让模型自己认"。

### 六步推理链路

```
① 读原图尺寸        取宽高
② 算 letterbox 参数  scale = min(目标边长/宽, 目标边长/高)，补边 = 居中取整除
③ 构造 letterbox 图  等比缩放 + 居中贴到 **114 灰**画布（不是黑边）
④ 转 NCHW 张量      3×边长×边长 的 float，像素 **/255** 归一到 0~1
⑤ ONNX Runtime 推理 CPU 版、单线程
⑥ 后处理           任务校验 → 布局嗅探 → 解码 → 坐标反算 → 按类别 NMS → 类别过滤 → 数量截断
```

### 四个"做错了不报错、只是结果静默变差"的点

| 环节 | 为什么必须这样做 | 做错的表现 |
| --- | --- | --- |
| **letterbox，不能直接拉伸** | 模型是在"等比缩放 + 补边"的图上训练的 | 长宽比被改变 → **精度静默下降**：不报错、不崩溃，只是漏检变多、框变歪 |
| **补边灰度 = 114** | YOLO 训练时的默认填充值 | 填 0（黑边）会让模型把边界当成强边缘 → **贴边目标的框系统性偏移** |
| **归一化 /255** | 训练时像素归一到 0~1 | 少除/多除模型照样跑、不报错，只是精度静默劣化 |
| **坐标反算 + 夹取** | 模型输出的是 letterbox 图上的像素坐标 | 当成原图坐标直接用 → 整体偏移一个补边宽度并带缩放误差 |

```
原图坐标 = (letterbox 坐标 − 补边) ÷ 缩放系数，然后夹进 [0, 宽−1] × [0, 高−1]
```

> 夹取是必需的：模型会给略微越界的框（尤其贴边目标），不夹就会导致下游裁剪出错。

### 模型自描述：能读的不让你填

Ultralytics 导出的 ONNX 会把**类别名（`names`）、任务类型（`task`）、输入尺寸**写进模型元数据，插件加载时读一次：

- **类别名**：元数据里有就用；**读不到就用 `class_0` `class_1` 这样的占位名，绝不编造**（按 COCO 顺序硬套会让你以为识别对了，而模型的类别体系可能完全不同）。
- **任务校验**：`task` 不是 `detect`（segment / pose / obb / classify / semantic / depth）的模型**明确拒绝**——不同任务的输出格式完全不同，按检测解读会得到错误结果却不报错。
- **布局嗅探**：只支持 **YOLOv8 / v11 检测**的输出布局 `[1, 4+C, N]`（通道在前、无 objectness）。YOLOv5 是 `[1, N, 5+C]`（带 objectness，维度顺序恰好相反），会被拒绝并提示重新导出。判据是"哪个维度小"——通道数（几十~几百）必然远小于锚点数（几千~几万）。
- **输入尺寸**：`输入尺寸`填 0 时用模型元数据里的静态形状；模型是**动态形状**又没填 → 明确报错要求手填（常见 640），**不猜**。

### NMS 按类别分别做

同类别的重叠框才互相压制（保留置信度高的），不同类别不会——"人"和"自行车"框高度重叠是正常的（人骑着车），不该互相吃掉。最后所有目标按置信度**降序**输出。

### 模型会话：进程级共享 + 引用计数

同一个模型被 5 个流程引用只加载 **1 份**（按模型文件全路径缓存，谁用谁计数、归零才真正卸载）。配置里**换了模型路径会自动换会话**，不用重启软件——不会出现"界面显示新模型、跑的还是旧模型"这种最难查的问题。

## 典型用法 / 接线

```
① 基本检测 + 存档
图像采集.OutputImage ──▶ YOLO.Image
YOLO.BoxesText ────────▶ 数据记录 / 结果上报      （标量，直接接得上）
YOLO.Count ────────────▶ C#脚本 / 比较节点        （判 OK/NG、分支）

② YOLO 定位 → 传统算子精测（最有价值的接力）
图像采集.OutputImage ──▶ YOLO.Image
YOLO.BestCrop ─────────▶ 卡尺测量.SrcImage        （粗定位后精测，不用写脚本）
YOLO.Count ────────────▶ 条件分支

③ 先定位再检测（目标位置不固定 / 工件会飘）
模板匹配.AlignedImage ──▶ YOLO.Image

④ 只关心缺陷那一类
YOLO.类别过滤 = "2"（缺陷在模型里的类别索引），下游数据量立刻小一截
```

## 常见问题

**Q1：支持哪些 YOLO 版本？**
**YOLOv8 / v11 的检测模型**（输出 `[1, 4+C, N]`）。YOLOv5 **明确不支持**（输出 `[1, N, 5+C]` 带 objectness，会被拒绝并提示重新导出）；分割 / 姿态 / 旋转框 / 分类模型也**明确拒绝**，拒绝文案里带中文任务名和导出命令。

**Q2：为什么"没检测到目标"不算失败？**
可能本来就是良品。判 Failed 会把良率搞脏。看 Info 日志（里面写了当前的置信度阈值与模型名），先自查"阈值是否过高 / 模型是否匹配当前产品 / 图像是否需要预处理"。

**Q3：能不能用 GPU？**
当前只有 CPU 版，界面上**没有设备开关**（CPU-only 阶段加个开关是个什么都不做的旋钮）。将来接 GPU 是"换 ExecutionProvider + 多带原生库"，端口契约不变。

**Q4：类别名显示成 `class_0` `class_1`，是不是坏了？**
正常。这说明模型元数据里没带 `names`（插件不编造名字）。想要真名，导出时把类别名写进模型，或在下游按`ClassIds`自己映射。

**Q5：框整体偏移，或贴边的目标框偏？**
先看配置界面「试算」结果里的 **letterbox 缩放与补边**（这是排障用的，不是装饰）：`scale` 与补边算错，框就会整体偏。贴边目标偏移请确认预处理没有被改成黑边填充（插件固定 114 灰）。

**Q6：`Boxes` 怎么解析成一个个框？**
扁平数组，**每 4 个一组**：`x1,y1,x2,y2`（原图像素）。第 i 个目标 = `Boxes[4i] … Boxes[4i+3]`，与 `ClassIds` / `ClassNames` / `Confidences` **同序**。要标量就用 `BoxesText`。

**Q7：换一个模型要重启软件吗？**
不用。会话按**模型路径**判变——路径改了会自动先释放旧会话、再加载新的。改完`ModelPath`后配置界面的**模型摘要**会刷新（输入输出形状 / task / 类别名），那里是"模型选错"时唯一的线索。

**Q8：报"无法确定模型输入尺寸"？**
模型是动态形状（元数据里读不到边长），必须手填`输入尺寸`（检测模型常见 640）。留 0 会明确报错——插件不猜尺寸，猜了会得到偏移的框。

**Q9：同一个目标出一堆重复框？**
调低`NMS 重叠阈值`（0.45 → 0.3 左右压制更强）。不同类别之间不会互相压制（NMS 按类别分组做），所以"人和车重叠"不会被吃掉。

**Q10：目标很多时很慢 / 下游数据太大？**
填小`最多保留目标数`（按置信度截断），或用`类别过滤`只留关心的类，或在上游用 ROI 把图裁小、降`输入尺寸`。
