# 深度学习异常检测 · 判据与调参

> 分类：图像处理 ｜ 来源：插件 Plugin.DlAnomaly

本页解决三件事：**分数怎么读**、**阈值怎么定**、**热力图怎么用**。以及最后一节：**什么时候不该用异常检测**。

## 一、分数怎么读

异常检测模型的分数是"不像良品的程度"，**不是概率、没有上限、不同模型不可互比**。同一模型同一台相机的分数可比；换模型、换光照、换曝光、换镜头之后，旧阈值一律作废。

读分数只有一种正确姿势：**看分布，不看单点**。

## 二、定阈值：良品分布 + 不良样本的四段法

### 第 1 步：量良品的噪声地板 N

拿 **≥30 张**确认良品（覆盖不同时间、不同批次、不同工位灯位），逐张试算记下 `Score`。

- `N_hi` = 良品分数的第 99 百分位（不是最大值：最大值会被一张异常亮/暗的良品带飞）
- `N_lo` = 良品分数的第 1 百分位（用于判断方向，见下）

### 第 2 步：量不良的信号峰 S

拿手上**每一张**确认的不良（哪怕只有 1~2 张）试算，取其中**最小**的那个分数作为 `S_lo`。

### 第 3 步：判"可不可分"

**判据：`S_lo / N_hi ≥ 2`**（若分数可能为 0 或负，改用极差：`(S_lo − median_良品) / (N_hi − median_良品) ≥ 2`）。

- **≥ 2**：可分，继续第 4 步。
- **< 2**：不可分。不要硬调阈值——先做下面三选一：
  1. 检查预处理是否与训练一致（`ResizeMode`、`InputSize`）；
  2. 缩小视野（上游「创建ROI」只留缺陷可能出现的区域），背景差异变小、信噪比通常显著提升；
  3. 回训练侧补数据/换模型（PatchCore 类方法对"缺陷面积占比极小"的场景有帮助）。

### 第 4 步：把阈值放在两者之间

```
Threshold = N_hi + (S_lo − N_hi) × 0.4
```

取 0.4 而不是 0.5 的理由：良品偶发离群（灯光闪一下、粉尘）比不良漏检的代价更小——**宁误报勿漏检**是工业外观检测的默认取向。若你的场景相反（误报会导致停线损失更大），把系数改到 0.7。

阈值**不写在本节点**：把 `Score` 接到「结果比较」或「判断」节点，按上式填。

### 反向模型的处置

如果良品分数**偏高**、不良分数**偏低**（第 1 步里发现 `N_lo` 明显大于 0 且不良比良品还低），说明这个模型输出的是"相似度"而不是"异常度"。两种办法：

1. 下游用"小于阈值"比较；
2. 回训练侧换导出方式。**不要**在本节点外面接一个取负的数学节点——那会让方案里出现两份口径，日后没人说得清哪个对。

## 三、热力图怎么用

| 用法 | 做法 | 注意 |
| --- | --- | --- |
| 只看缺陷在哪 | `DisplayViewIndex` 设非 0，直接上屏 | 热力图分辨率通常远低于原图，**位置是区域性估计** |
| 存档留证 | `HeatmapImage` 接「结果显示」或「数据记录」的图输入 | 单通道 `byte`，不是彩色图 |
| 精定位 | 用 `HeatmapMaxRow/Col` + 「创建ROI」在热点附近开窗，再卡尺/Blob | 热点坐标是**热力图坐标系**，不是原图坐标，换算按 `原图宽 / 热力图宽` |
| 跨批次比趋势 | `HeatmapMax` 设**固定上限** | 自适应上限下，两次的"最亮"恒为 255，趋势不可比 |

**热力图上限的两档口径**（这是最容易把结论做错的开关）：

- `HeatmapMax = 0`（默认，自适应）：本轮最大值映射到 255。看"在哪"很清楚，**但两次采集不可比**。
- `HeatmapMax = X`（固定）：超过 X 的都截到 255。适合"同一个上限下看异常强度有没有变大"。X 取训练侧的热力图归一化上限，或取良品热力图最大值。

## 四、耗时与吞吐

单张耗时 ≈ **预处理 + 一次前向**：

```
预处理 ≈ 0.3 ~ 1 ms（缩放 + 通道补齐 + float 转换，与输入尺寸成正比）
前向   ≈ 见下表的量级（CPU 单线程，实际取决于模型）
```

| 模型类型 | 输入 | CPU 单线程量级 |
| --- | --- | --- |
| 轻量自编码 / 小型 CNN | 224×224 | 10 ~ 40 ms |
| ResNet18 骨干的 PatchCore 特征提取 | 224×224 | 40 ~ 120 ms |
| 大骨干 / 高分辨率 | 512 以上 | 数百 ms |

**ONNX Runtime 会话是进程级共享的**（按模型路径缓存 + 引用计数），所以"同一模型被多个步骤用"不会重复加载，第二个及以后只付推理成本。首次加载会有一次性的模型解析开销（几十到几百 ms）。

## 五、什么时候不该用异常检测

| 场景 | 为什么不适合 | 该用什么 |
| --- | --- | --- |
| 缺陷有明确几何/灰度规则 | 规则简单可靠，模型只是增加不确定性 | Blob / 卡尺 / 模板匹配 |
| 缺陷类别稳定、每类都有样本 | 分类能给出"是哪一类"，信息更多 | 深度学习分类 |
| 要输出逐像素的类别区域 | 异常检测只给"像不像良品" | 深度学习分割 |
| 背景本身变化剧烈（工位移动、视野里有运动物体） | 背景变化会被当成异常，误报率极高 | 先做位姿对齐（模板匹配），或固定视野 |
| 训练集混入了没被发现的坏样本 | 模型学会把缺陷当"良品"，漏检且不可见 | 训练侧数据清洗；这是异常检测最危险的失效模式 |
| 一张不良样本都没有、也没法造 | 阈值无法定量，只能靠猜 | 先靠人工规则过渡，同时攒样本 |

## 六、四个现场配方

### 配方 A：新机种上线首周的漏印/缺胶

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 视野 | 上游 ROI 只留印刷区 | 背景占比越小信噪比越高 |
| `ResizeMode` | Letterbox | 与训练一致 |
| `HeatmapMax` | 0（自适应） | 首周主要看"有没有、在哪" |
| 阈值 | 按本页四段法定 | 不良只有几张，靠 `S_lo/N_hi ≥ 2` 判可不可分 |

### 配方 B：装配到位与否

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 视野 | 整幅（装配位置固定） | 位置信息本身是判据 |
| `HeatmapMax` | 固定上限 | 要知道"差多少"，不只是"有差异" |
| 判据 | `Score` + `HeatmapMaxValue` 双判 | 单看分数时，小面积强异常与大面积弱异常会混在一起 |

### 配方 C：异物/脏污（面积极小）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 输入尺寸 | 尽量大（512 或模型支持的上限） | 小目标在 224 上会被缩没 |
| 判据 | 主要看 `HeatmapMaxValue` | 整图平均化会稀释极小面积异常 |
| 兜底 | 并联一路 Blob 高对比检测 | 极亮/极暗异物用规则更快更稳 |

### 配方 D：表面低对比度纹理（织物/喷砂）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| `ResizeMode` | 与训练严格一致 | 纹理对重采样极敏感 |
| `HeatmapInterpolation` | Bilinear | 显示更平滑，便于人工判读（不影响分数） |
| 阈值 | 宁可略低 | 这类缺陷人眼也难判，先保证不漏 |

## 七、与相邻节点的分工

| 节点 | 分工 |
| --- | --- |
| 「图像预处理」 | 调亮度/对比度/滤波。**只在训练侧做过同样预处理时才加**，否则等于喂了模型没见过的图 |
| 「创建ROI」 | 缩视野、聚焦区域。**优先用它而不是在训练侧裁图**，现场改视野不用重训 |
| 「深度学习分类」 | 有类别样本、要"是哪一类" |
| 「深度学习分割」 | 要逐像素类别图 |
| 本节点 | 只有良品样本、要"有多异常 + 在哪" |
