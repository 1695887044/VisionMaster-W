# 深度学习异常检测 · 界面与操作

> 分类：图像处理 ｜ 来源：插件 Plugin.DlAnomaly ｜ 视图：AnomalyView

本节点有**专属配置视图**（不是通用属性网格）。整块分成左右两栏：左边是"参数"，右边是"看图"。本文按界面从上到下逐段讲。

## 一、左栏①：图像输入

| 元素 | 作用 |
| --- | --- |
| 端口行 `Image` | 图源入口。点行尾的 🔗 选上游端口，或点绑定按钮挂到全局变量 |
| 灰字提示 | 「本节点检测整幅图，不吃 ROI；要只看某个区域，请上游先用「创建ROI」裁好。」 |

要点：

- `Image` **不是必填**。不接也能保存方案、能打开窗口；但执行时会明确失败并写「上游没有图像：请把图像节点的输出连到本节点的 Image」。
- 视图里看到的预览图来自**上游最新一次执行留下**的图（"点「执行」试运行带进来的"）。第一次打开窗口、上游还没跑过时预览是空的，这是正常的。

## 二、左栏②：异常检测模型（.onnx）

| 元素 | 作用 |
| --- | --- |
| 路径输入框 | 显示当前模型路径。可以直接粘贴路径，也可以手改（`UpdateSourceTrigger=PropertyChanged`，边打边生效） |
| 「浏览」按钮 | 打开文件对话框，过滤器 `ONNX 模型|*.onnx|所有文件|*.*`；选中后立刻解析模型 |
| 模型信息卡 | 显示解析结果：输入名与输入尺寸、输出名与各自形状、识别出的契约（分数 / 热力图 / 两者都有）、以及 `task` 元数据 |
| 卡片下方说明 | 按秩契约的档位表（见「快速上手」页）；形状不认识时这里是看真实形状的地方 |

模型卡的状态有三种，颜色不同：

| 状态 | 卡片外观 | 含义与处置 |
| --- | --- | --- |
| 未选择 | 普通底色 | 还没填路径。填了或点了「浏览」就会重新解析 |
| 就绪 | 普通底色 | 解析成功，契约已认出。可以试算/执行 |
| 失败 | **红色底 + 红边框 + 红字** | 路径不存在 / 不是 ONNX / 输出形状不被接受 / 32 位进程。卡片里的文字就是原因，逐字读，不要凭猜 |

**改了路径一定会重新解析**：`ModelPath` 变更触发 `RefreshModelState()`，不需要关窗口重开。这是刻意做的——"换了模型界面显示新路径、跑起来还是旧模型"这类问题极难排查。

## 三、左栏③：预处理参数

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| 缩放模式 | Letterbox | Letterbox / Stretch | 与训练一致最重要。非方形图上两者结果不同，选错 = 分数静默偏移 |
| 高级 → 输入尺寸 | 0 | 0~4096 | **0 = 用模型静态尺寸**（推荐）。只有动态形状模型才手填，异常模型常见 224 / 256 |
| 高级 → 热力图上限 | 0 | 0~1000000，4 位小数 | **0 = 用本轮热力图自身最大值**（自适应，适合"只看在哪"）；>0 固定上限（跨批次比趋势才有意义） |
| 高级 → 热力图插值 | Nearest | Nearest / Bilinear | **只影响显示，不影响分数** |
| 高级 → 预览窗口 | 1 | 0~9 | 0 = 不发布（只算输出端口） |

「高级参数」收在 Expander 里，多数场景不用动。三处数值框都是 `NumericBox`：非法输入会被直接拒绝（框边变红），不会把脏值写进参数。

## 四、左栏④：试算

| 元素 | 作用 |
| --- | --- |
| 「试算一下」按钮 | 用当前预览图跑一遍完整检测（与运行期**共用** `TryDetect`） |
| 提示条 | 一句话状态：显示的是哪张图、当前卡在哪一步 |
| 结果卡 | 分数 + 热力图摘要。失败时第一行是「试算失败：…」并带原始原因 |

试算的价值在于**在保存方案之前就知道模型与参数配不配**：界面看着对、跑起来不对，是这类模型节点最容易出的问题，试算就是为了提前暴露它。

## 五、右栏：图像预览

- 标题「图像预览」+ 徽标「只读 · 整幅图」。
- 工具条两个按钮：「适应窗口」（把整图缩放到窗口里）、「1:1」（按原始像素显示）。
- 预览区是只读的 `ImageReadOnly`：**不能在本节点画 ROI**，要画框去上游「创建ROI」。
- 三种状态：有图 → 显示图；无图且模型正常 → 空态提示（引导点 🔗 绑定或点执行）；无图且模型失败 → 红色"模型加载失败"态。
- 底部状态栏显示当前提示（与左栏提示条同一来源）。

## 六、一次完整的配置过程

1. 接好 `Image`（点 🔗 选上游端口）。
2. 点「执行」让上游先跑一次，把图带进预览。
3. 点「浏览」选模型，读模型卡里的契约（有没有热力图、多大）。
4. 点「试算一下」，看结果卡。
5. 拿 3~5 张**确认的良品**与 1~2 张**确认的不良**分别试算，记下分数分布（这一步决定阈值，见「差分口径与调参」页）。
6. 把 `Score` 接到下游比较/判断节点，定阈值。
7. 需要看缺陷位置时，把 `HeatmapImage` 接到「结果显示」，或在「预览窗口」里直接看。

## 七、怎么确认改对了

| 你改了什么 | 怎么确认生效 |
| --- | --- |
| 换了模型 | 模型卡的第一行输出名/形状变了吗？没变说明路径没真正改到 |
| 改了缩放模式 | 拿同一张图试算两次，分数应当变化（**方形图上可能完全一样**，因为两种模式在方形图上等价） |
| 改了输入尺寸 | 试算不报「无法确定模型输入尺寸」即为生效 |
| 改了热力图上限 | 预览里的热力图片亮度会变，**`Score` 不应变**（上限只影响显示） |
| 改了预览窗口号 | 执行后对应窗口出现热力图；0 时不出图，这是设计 |

## 八、不做的事

- 视图里**不提供训练**、不提供模型转换：拿到的必须是已经导出好的 `.onnx`。
- 视图里**不提供阈值**：阈值属于下游判定节点，放这里会让"同一阈值在多处各写一份"。
- 视图里**不提供逐像素标注/编辑**：它是只读预览。
