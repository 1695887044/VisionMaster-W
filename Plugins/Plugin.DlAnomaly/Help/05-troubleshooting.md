# 深度学习异常检测 · 排错

> 分类：图像处理 ｜ 来源：插件 Plugin.DlAnomaly

## 一、按报错原文逐条对

下表左列是**运行时 `ErrorMessage` 的真实文案**（可直接拿去 grep 源码），右列是处置。

| 报错（节选关键字） | 什么情况 | 处置 |
| --- | --- | --- |
| `执行已取消` | 流程被停止/暂停，起手就查到了取消令牌 | 正常现象。`[ParallelSafe]` 要求长阻塞可分步检查，取消不算失败 |
| `上游没有图像：请把图像节点的输出连到本节点的 Image` | `Image` 端口没接，或上游本轮没出图 | 检查连线；上游若也失败，先修上游 |
| `尚未选择模型：请在节点配置里选择一个 .onnx 异常检测模型` | `ModelPath` 为空 | 点「浏览」选模型 |
| `模型文件不存在：{path}。请重新选择，或把模型放到该路径` | 路径写错 / 方案拷到别的机器但模型没拷 | 用绝对路径重选，或把模型放到宿主程序目录下改用相对路径 |
| `当前进程是 32 位，而 ONNX Runtime 原生库只有 x64 版本` | 宿主被编译/发布成 x86 | 换 x64 宿主；本节点的推理链路没有 32 位路径 |
| `无法确定模型输入尺寸` | 模型是动态形状，且 `InputSize` 填了 0 | 手工填 `InputSize`（异常检测模型常见 224 / 256） |
| `读到的输出：{name}（秩 n，形状 [...]）…不会替你猜` | 模型输出形状不落三格（秩 2 `[1,1]` / 秩 4 `[1,1,H,W]` / 秩 3 `[1,H,W]`） | 这是**拒绝而不是 bug**。确认导出的是异常检测头而不是分类头/检测头；确实需要新形状，得改代码并补断言 |
| `热力图…平坦长度与 …×… 不一致` | 模型声明的形状与实际输出张量不符（少见，多见于手改过 ONNX） | 换原始导出的模型 |
| `热力图输出为空张量。` | 模型热力图尺寸为 0 | 换模型 |
| `图像通道数为 N，只支持 1 通道（自动补成 3）或 3 通道` | 上游送来了 2/4 通道图（多通道相机/合并图） | 上游先「图像预处理」拆通道或转灰度 |
| `难以…图像为空` / `图像未初始化` | 端口上挂着一个已释放/空的句柄 | 检查上游是否提前释放了图；不要把输出图手动 `Dispose` |

**排错第一原则**：先读完整原文（不要只看"模型加载失败"这种卡片摘要），原文里已包含真实形状、真实路径、真实通道数。

## 二、"不报错但结果不对"症状表

这一类占现场问题的绝大多数，因为异常检测的失效**几乎全是静默的**。

| 症状 | 最可能的原因 | 怎么确认 |
| --- | --- | --- |
| 所有图分数都几乎一样、看不出区分度 | 归一化或缩放模式与训练不一致；或模型没真正加载（用了别的模型） | 拿同一张良品，改 `ResizeMode` 再试算一次，分数应当变化（方形图上可能不变化） |
| 良品大量判 NG | 阈值定得太紧；或视野里有变化背景 | 按「判据与调参」四段法重量分布；缩视野后再看 |
| 不良全部判 OK | 训练集混入了不良样本；或分数方向搞反了 | 拿最明显的不良试算，看分数是不是**低于**良品 |
| 分数剧烈跳动、同一件重测差很多 | 光照/曝光不稳；或上下游在动 | 固定光源；确认相机是否在连续触发里自动调参 |
| 热力图永远是全黑 | 模型没热力图输出（只有分数）；或 `HeatmapMax` 设得过大 | 看模型卡有没有热力图；把 `HeatmapMax` 设 0 试 |
| 热力图永远全亮/全 255 | `HeatmapMax` 设得过小，所有像素都超过上限 | 设 0，或按良品最大值定 |
| 热点位置总在同一个角落 | padding 被当成异常（送进来的图与训练时填充策略不一致） | 确认 `ResizeMode`；确认上游没有先做缩放 |
| 换模型后没变化 | 路径没真正改（手改了但没回车/没触发） | 卡片第一行的输出名/形状变了吗 |
| 首张特别慢，之后快 | 正常：首个会话加载开销一次性 | 无需处理 |
| 多工位同时跑时变慢 | 会话共享是进程级 + 引用计数，单线程推理 | 多进程部署，或减少同时调用 |

## 三、上屏与预览问题

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 预览区空、提示"还没有图像" | 上游还没执行过，本节点没有可显示的图 | 先点「执行」让上游流出图 |
| 预览是灰的/尺寸很小 | 上游送的就是小图 | 检查上游 ROI 与缩放 |
| 执行后没出现预览窗口 | `DisplayViewIndex = 0`；或模型没有热力图输出 | 改成 1~9；确认契约含热力图 |
| 「适应窗口」「1:1」点了没反应 | 还没有图（按钮内部找不到预览控件时会静默返回） | 先让预览有图 |
| 窗口里显示"模型加载失败"红框 | 模型态是 `Failed` | 读卡片里的原因（路径/形状/位数） |

## 四、修改源码时最容易踩的三个坑

下面三条都是**改了不报错、只是行为不对**的类型，改动这两处之前必须先看。

### 坑 1：把 `session.Run` 的 out 参数写成 `NamedOnnxValue?`

`Run(...)` 返回 `IDisposableReadOnlyCollection<DisposableNamedOnnxValue>`，所以

```csharp
if (!byName.TryGetValue(name, out DisposableNamedOnnxValue? value))  // ← 必须是 DisposableNamedOnnxValue
```

写成 `NamedOnnxValue?` 编译报 `CS1503`（无法从 `out NamedOnnxValue` 转换）。

### 坑 2：只传 `OutputMetadata.Values` 而丢掉 Key

`NodeMetadata` **没有 `Name` 属性**（只有 `Dimensions` / `SymbolicDimensions` / `ElementType` 等）。输出名只能取 `OutputMetadata` 字典的 Key。丢了 Key 只能自己编名字，加载期认出的契约名和 `Run()` 返回的名字就对不上，**运行期静默取不到值**。

### 坑 3：把补边灰度改成 0

`ResizePlan.PadGrayValue = 114`。改成 0 会让模型看到训练时从未见过的强边缘，异常分数整体抬高——**不报错**，只是所有判定都开始偏向 NG。

## 五、契约提醒（改断言/写迁移脚本时）

- `OutputPort<double>.Value` 的默认是 **`0.0` 不是 `null`**。判"没算出来"要用 `HeatmapMaxRow` 是否为 `-1`，或 `Score` 是否为 `NaN`。
- 断言里要跑完整逻辑必须调 `plugin.Execute(context)`，**不是** `plugin.RunAlgorithm(context)`——`Success.Value = true` 只在 `Execute` 开头预置，跳过它会让"正常返回"的用例全假红且 `ErrorMessage` 为空。
- 输入端口赋值用 `plugin.Image.Value = image;`（`Value` 是 `object?` 弱类型入口），插件内部读用 `Image.GetTypedValue()` / `ActualValue`。
